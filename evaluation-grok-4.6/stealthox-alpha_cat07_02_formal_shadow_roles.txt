## Section 5 code would not execute as written

Illustrative code is allowed; incoherent object use is not.

- PM4Py `Role` objects expose `activities` and `originator_importance`, not `role_name`, `resources`, or `origin_ev`.
- `discover_activity_based_resource_similarity` returns a graph, not a DataFrame with `weight`. `sim[sim["weight"] >= 0.85]` does not follow.
- `measure="cosine"` and `aggregate_measure="median"` are not the usual PM4Py parameter names (`aggregation` is).
- `format_dataframe(..., resource_key=...)` is not a standard signature for that helper.
- `filter_event_attribute_values(..., level="events")` is the wrong level token if the API expects `"event"` / `"case"`.
- `cluster_log` is unpacked as `(clustered_logs, _)` and then ignored; role mining runs on the full log. The “segment first so rare specialists are not diluted” comment is not implemented.
- `insert_case_service_waiting_time` then `get_service_time` is sketched without start timestamps, which that pipeline requires.

The *intent* of the code (A9-only handover as hierarchy, service-time gap under substitution, betweenness for Mateo, anti-frequency checklist) is the right intent. Intent does not make the snippet coherent.
