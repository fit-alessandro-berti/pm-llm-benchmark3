**7.4**

The analysis in sections 1–6 is unusually careful: it separates form from objective, timing from occurrence, coverage from a clean AV-2 pass, and an alert from proof. That is the right evaluation frame. It is not nearly flawless. Under a strict reading, several classification, consistency, and executability defects are material.

**What is strong.** FEP-1 is decomposed into real threat scenarios (unilateral authorization, payee/bank substitution, fabricated commercial support, credential misuse, collusion/rubber-stamping, emergency-as-bypass, irreversibility) rather than restated as “two names.” ED-1 is correctly treated as a conjunctive permission, not a fourth additive safeguard. The sufficiency test uses timing, independence, coverage, overrideability, recoverability, evidence quality, and collusion resistance, and correctly rejects “same expected loss” as the sole standard. Case handling does not collapse to amount or raw four-eyes: AP-204 fails despite distinct users because of a fabricated receipt; AP-203/AP-207 are not auto-failed for same-user handling; AP-205 is excluded from completed-payment FEP-1; AP-206 is left open because token provenance is unresolved; AP-209 is not convicted by pairing alone. Pre-settlement, post-release manager action is correctly described as hybrid and contingent on stop power. Monitoring rules distinguish investigation triggers from misconduct.

**Classification is too generous where the author’s own test forbids it.** The write-up states that no manager level is supplied, so MG-4/ED-1 authorization “cannot be conclusively certified even in the strongest cases,” then still marks AP-203 and AP-207 `OBJECTIVE_MET`. That is internally inconsistent. Missing L3+ authority is a required ED-1/MG-4 element, not a footnote. For AP-207, stop-power at the settlement gate is also unverified; `OBJECTIVE_MET` plus “conditional / provisional” is a hedged pass, not a coherent verdict. Both belong in `OBJECTIVE_PARTIALLY_MET` or `INDETERMINATE` under the author’s own rules. AP-201’s rationale calls a convenience same-user path a “documented exception” while listing accountable acceptance as missing evidence—“documented” overstates what the log shows.

**Equivalence labels are defined and then abandoned.** Section 2’s fully / partially / merely mitigating / ineffective scale is the required sufficiency test, but section 3 never applies it case by case. `OBJECTIVE_*` is related, not a substitute. The reader cannot see whether AP-201 is partial equivalence or mere mitigation, or whether AP-208 is ineffective versus failed-and-lucky.

**Section 7 is not reliably executable as specified.** `pm4py.filter_four_eyes_principle` in public APIs keeps cases that *satisfy* four-eyes (different resources). Violations are the complement of that set among completed payments. The code instead treats the return value as the violation set, then retries an undocumented `keep_violations=True`. On a normal install that parameter raises `TypeError`, and the block aborts with `RuntimeError` rather than computing `completed_ids - conforming_ids`. Defensive version notes do not make the required artifact run. That is a direct miss on “one executable Python code block” that obtains nominal violating completed cases via the named API.

Smaller code/evidence nits: m09’s performance-rating relationship is coded as unknown independence rather than an unresolved MG-4 conflict (the narrative still fails AP-202, so the verdict is saved by other facts). RA-7’s one-business-day rule is written for emergency same-user payments but is leaned on for AP-201, which had no token. Business-day and 24-hour screens are properly labeled as proxies, which is good; they still cannot rescue a filter that never returns.

**Net.** Control-objective reasoning is well above a routine checklist review. Strict grading cannot ignore the `OBJECTIVE_MET` contradiction, the unused equivalence test, and a PM4Py path that likely never emits the promised evidence table. Those keep the score well short of the near-flawless band.
