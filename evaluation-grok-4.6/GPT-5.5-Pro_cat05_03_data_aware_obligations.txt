## Material defects

**1. “Material data change” is never defined, and the code does not implement the prose.**

R1 requires an enhanced review *after the latest material data change*. Section 2 talks about amount *and jurisdiction* changes. The executable rule is narrower: `>20%` after the last ER, plus `r1_activated_after_er`. A same-bucket foreign jurisdiction change (US→FR) after ER would still yield `r1_enhanced_ok`. `latest_material` is computed from any `state_changed` flag (including create and the TX-308 decrease) and then **not used** in the R1 decision. If it had been, TX-308 would be auto-failed. That is a real spec/implementation split, not a comment-level nit.

**2. R3 is incomplete.**

The formalization assumes a prior `Sanctions_Screen` exists. A list add with no prior screen is undefined. “Cannot safely clear” is not the same as a defined INDETERMINATE/NONCOMPLIANT result. No case tests the hole, but the predicate is still open.

**3. R2 “relevant enhanced review” is only half-formalized.**

The prose correctly refuses a standard-packet approve. The code only checks `ER < CA < release` and that ER is after the last risk/customer-type change. Packet lineage is narrative-only. Fine as a coarse flag if stated as such; the §2 table overclaims (“evidence that approval reviewed the enhanced packet”) relative to what is checked.

**4. Exemption judgment is partly hardcoded.**

`evidence_strength: "strong" | "weak_or_conflicted"` encodes the EX-77 / EX-88 conclusion in the register. The task forbids a case-level classification lookup; this is the same move one level up. Deriving strength from signature time, certificate time, and witness role would have been the honest check. They *also* compare `signature_ts` to release, so the field is partly redundant and partly a smuggled verdict.

**5. PM4Py is decorative.**

The required `format_dataframe` call writes `pm4py_log` and never reads it. Same-timestamp order is preserved only in the pandas path. There is no DECLARE model, no pm4py conformance API, and the “control-flow screen” is `activity in acts[:release_pos]`. That meets the letter of “call format_dataframe” and the optional trace-order bullet; it does not show that a process-mining library was used to *check* anything. The ImportError fallback is fine; the unused formatted log is not.

**6. Small conceptual slippages in the findings table.**

- TX-302 puts EX-77 under “Satisfied obligations.” A waiver is not an obligation satisfaction; that is what the exemption column is for.
- TX-308’s ER “covers prior EUR 140,000 state” — that was the *then-current* state, not a prior one.
- R4 is listed as a “triggered rule” as if it were an activity obligation like R1–R3. It is an invalidation predicate. Harmless if you already know the policy; sloppy in a normalized rule table.
- Severity (None / High / Critical / “Potentially high”) is undefined. TX-304 as Critical is a judgment, not a derived field.

**7. TX-302 / TX-310 / code label mismatch is not reconciled.**

Narrative: TX-302 COMPLIANT, TX-310 NONCOMPLIANT. Code: `NO_ISSUE_COARSE` vs `REVIEW_REQUIRED`. The prompt allows `REVIEW_REQUIRED` for evidential cases, but the write-up never maps those three coarse labels onto the four allowed classifications. A judge using the code output cannot recover the §3 table.

**8. A few formal edges are left in English.**

R1’s pseudo-logic mentions unknown amount given non-DE jurisdiction, but not the symmetric “high amount, unknown jurisdiction” case that the table does mention. R5 uses `release_time < expires` while the policy talks about the *obligation trigger*; they coincide here only because R1/R2/R3 are all evaluated at release. `before` is well-defined; several side conditions are not.

## What does *not* deserve a dock

Choosing COMPLIANT over JUSTIFIED_EXCEPTION on TX-302 is correct: the enhanced review already satisfies R1. Refusing to treat the TX-308 decrease as a re-review trigger is required by R4. Short-circuiting R1 to False when jurisdiction is DE even if amount is unknown is the right three-valued rule. Not using the next-day 150000 on TX-305 is required by the additional facts.

The temporal story and the case calls are good enough that a lenient grader would be in the mid-9s. A strict one has to charge for an underspecified material-change predicate, a checker that does not implement the author’s own R1 text, hardcoded exemption strength, unused PM4Py, and several table-level category errors. That is why this is **8.1** and not 9+.
