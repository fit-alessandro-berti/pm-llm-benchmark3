**7.8**

This is a strong investigation write-up with unusually careful event-time reasoning. It is not nearly flawless. Several technical and logical defects are material enough that a strict reading cannot sit in the 9–10 band.

**What is actually good.** Event-time roles are not read off the current master: Eva is an Independent Verifier on 2026-08-09 and still not QM on 2026-08-15. Alias collapse is applied before SoD, so CHG-508 is correctly treated as self-approval. Service-account handling is conceptually right: `svc_qms` is never a human by default, CHG-503 is weak/unproven, CHG-509 is strong enough for SoD but still a shared-account control defect. Delegation is applied as a conjunction of interval, scope, activity, absence, and chain validity. D-QM-01 is not stretched to cooling-system retrospective review; D-IC-04 is void both as prohibited subdelegation and as email-only. Leave is treated as availability, not role loss. RR6 is respected: repeated Clara–Ben pairing and reciprocity stay indicators. Case classifications are mostly the right primary labels, with confidence and missing evidence that match the ambiguity.

**PM4Py polarity is very likely wrong.** `pm4py.filter_four_eyes_principle` in current public APIs keeps cases that *satisfy* four-eyes (different resources). The code prints that result as “RR1/RR2 violations.” If that is the installed semantics, the printed set is inverted: CHG-502, CHG-508, and CHG-510 would be omitted, and conforming cases would be flagged. The raw-vs-normalized contrast that is supposed to prove the alias defect would also flip. The write-up wraps `filter_activity_done_different_resources` in `try/except` but does not pin a version, check polarity, or recompute four-eyes in pandas as an independent ground truth. For a required executable checker, that is a first-order defect, not a nit.

**The network block is not robustly executable.** `discover_handover_of_work_network` / `discover_working_together_network` return a NetworkX graph in modern PM4Py, not an object with `.connections`. `getattr(net, "connections", net)` then calls `.items()` on a DiGraph and will throw. Reciprocal-edge extraction has the same problem. Section 4’s network interpretation is qualitatively fine and correctly non-accusatory, but the mandated network evidence may never print.

**Delegation logic in code is narrower than the rules, and looser than the prose.** Emergency approvals are coded as needing IC only (`needed = "IC" if emerg and act == "Approve_Change"`). RR4 is an extra path, not an exclusive one; a QM approval of an emergency change is valid under RR3. It does not change this log, but it is a formal error. Conversely, D-IC-03 is coded as any `cooling_system` approval. The instrument is “CI-44 only.” The narrative admits the linkage is missing; the checker silently grants it. That is how CHG-505’s approval becomes VALID_SUBSTITUTION while the evidence only shows a cooling emergency in the same window.

**CHG-505 is over-resolved.** Treating the approval leg as a valid IC substitution assumes CI-44 and a credible safety rationale that are not in the log. The package-deal reading (failed retrospective voids the RR4 exception) is defensible, and the scope/lateness critique of Ben’s review is correct. Calling the approval valid while listing the incident link as missing evidence is an unresolved tension. INDETERMINATE on the approval leg, UNAUTHORIZED on the review, would have been tighter.

**Smaller accuracy problems.** The executive summary says “four” genuine authority/four-eyes failures and then lists five (507, 510, 505 retrospective, 502, 508), while also counting 505 among the “clean or defensible” three. RR5 is slightly overstated for CHG-509: reliable mapping *can* support conformance; calling the strongly attributed service-account verify an RR5 failure is a control opinion, not the rule as written. The CHG-510 secondary label “void paper trail was constructed to look like authority” implies purpose; the later good-faith alternative walks that back, but the label still overclaims. Absence contradiction is applied only to the 25-minute VPN window. That reading is disclosed, but a day-level reading would weaken every 13 August delegate act, including CHG-506, and the code hard-codes the narrower view.

**What keeps it well above mediocre.** The actor–role matrix, the ALCOA+ treatment of the late D-QM-01 database row versus the earlier signed PDF, the personal-not-credential nature of D-QM-01 on CHG-506, the weekend/absence hole on CHG-509, the technical-versus-objective split, and the investigation priorities are all at a high professional standard. The errors are concentrated in executable semantics, one over-identified emergency approval, and sloppy closing arithmetic—not in the main SoD or event-time role story.

A nearly flawless answer would have pandas-native four-eyes as the source of truth, version-safe SNA extraction, IC *or* QM on emergency approval, CI-44 as an explicit unchecked predicate, and an executive count that matches the table. This does not.
