**7.6**

The write-up is unusually complete: event-time roles, alias normalization, delegation scope, RR4 business-day logic, service-account attribution, and SoD are all handled with the right vocabulary, and the required headings and allowed labels are used. Most case calls are defensible. It is not nearly flawless.

**Material classification error (CHG-509).** D-QM-02 is valid only if the principal is absent. Asha’s recorded leave ends 2026-08-14. 15 Aug is a weekend, but the plant processed a HIGH-risk change that day, so “weekend” is not formal unavailability. Primary `VALID_SUBSTITUTION` overstates the rule. The supporting text and the code (`VALID_CONDITIONAL_ON_ABSENCE`) are more careful than the table label; the table is what the spec asked to classify. `INDETERMINATE` (or `UNAUTHORIZED` if absence is treated as unmet) is the stricter, better primary.

**Softer but real overclaim (CHG-504).** Event-time QM authority is correctly identified, and the VPN/leave/credential-sharing conflict is described. Primary `AUTHORIZED` still treats an unresolved identity dispute as a pass. `INDETERMINATE` with the same secondary would match the prompt’s instruction that ambiguous identity evidence has no canonical answer. Medium confidence and the secondary label mitigate this, but the primary is still too clean.

**Rule/role creep.** Independent Verifier expiry after 2026-08-11 is repeatedly treated as a verification defect. RR2 only requires implementer ≠ verifier. Flagging a missing activity–role matrix is fair; encoding `verification_role_issue` for Eva/Grace as if it were a stated resource rule is not.

**Network interpretation is thin.** Section 4 restates the supplied pair/reciprocal/workstation facts well and correctly refuses to infer collusion. It does not interpret actual PM4Py handover or working-together output (weights, concentrated edges, direction). The code would print top edges; the analysis never uses them.

**Code quality vs. spec nits.** The pandas reconstruction, alias map, interval checks, RR4 clock, and refusal to auto-declare collusion are strong, and keeping `svc_qms` out of `org:resource` is the right RR5 design. Weaker points: `filter_four_eyes_principle` is only reported as `len(...)` (and in many PM4Py versions that filter *keeps* conforming cases, so the number is easy to misread); `filter_activity_done_different_resources` is applied to Approve vs Retrospective, not repeated approval-like activities; `numpy` is unused. Manual flags correctly override PM4Py for service accounts (CHG-503 would otherwise look like a four-eyes pass).

**Small consistency/format issues.** CHG-505 confidence is split instead of one cell; executive “40–50% / 30–40%” buckets overlap and are not a control total; weekend-as-absence is never reconciled with Saturday production. None of these sink the argument.

**What is actually good.** CHG-501 as `VALID_SUBSTITUTION` (PDF vs late QMS row), CHG-502/508 RR1 after alias normalization, CHG-503 as identity/shared-terminal not proof, CHG-505/510 cooling vs `production_equipment` scope on D-QM-01, D-IC-04 as prohibited subdelegation, CHG-506 as disputed identity rather than a clean SoD fail, CHG-507 Eva-as-QM rejected at event time, and the benign/adverse/discriminating table for RR6 are all on target. The three investigations (510, 506, 503 cluster) are the right priorities.

Net: expert-level structure and mostly correct rule application, pulled down by a designed miss on D-QM-02 absence, a too-clean CHG-504 primary, and several hypercritical but real gaps in network use and role-matrix discipline.
