## Process-structure errors

Site B is **not** a sequential `Register → Identity → Originals → Document` machine. The rules and the DFG both say Identity Check **and** Originals Receipt may start after Register. Frequencies (`Register → Identity Check` 2,050; `Register → Originals Receipt` 1,860; `Identity Check → Originals Receipt` 1,020) show that overlap of identity work with the originals wait is already structurally available. Calling Site B “sequential” and treating “create both checks after Register” as the only interesting contrast misses the actual residual treatment: Document Check is gated by originals when legally required; Identity is not.

Other structural slips:

- Site A **after** is listed as having “no explicit” queue discipline, despite daily huddles being a named co-intervention.
- Site A after case-mix is listed as “Same” immediately after the table that shows 48% → 40%.
- “Loops” are collapsed into a rework percentage. Site B’s legally distinctive loop is `Legal Review → Request Supplement → Document Check` (and then re-assessment), which is a different mechanism from ordinary verification rework.
- Legal review is marked **low** transport relevance. As an effect modifier and bottleneck it is high; it is only “low” as a copyable Site A feature.
- Concurrency at A is described as legally unproblematic, which is true, but the table then implies Site A’s parallelism is the thing to preserve rather than Site B’s **asymmetric** prerequisites (identity free after register; document not).

The comparison table is therefore a checklist of labels, not a faithful mapping of partial orders.

## Quantitative scenarios

The scenario table is the weakest analytical section after the code.

- Optimistic and digital-only both apply an ~8–9h **overall** median drop to a 38% eligible share. If 38% of cases save ~8h and 62% save ~0, the population median does not fall by 8h unless the 38% were the median-setting cases and their entire distribution shifted. That reasoning is not shown.
- Three of five scenarios worsen both median and p90. None improve the center while fattening the tail. That was the one quantitative stress test the prompt required, and it is the realistic Site B risk: verification wait falls for digital/simple cases while specialized document/legal/assessment queues saturate and p90 rises.
- IT-lock “+20h / +50h” is not a default. If the lock simply prevents overlap, the ITT effect is near zero, not a large harm. Harm requires a specific interference story (duplicate reopenings, late back-entry, abandoned workarounds). That story is not written.
- Bottleneck-shift “+5h median” from parallelization is unexplained. Parallelizing enabled work does not by itself add five hours unless WIP explodes or legal/supplement loops intensify.
- Site B baselines that should have been used as bounds—18h originals delay, 20h wait before assessment, 8.1h document service, 3.4h identity service, 40% legal, 360/1360 supplement after legal—are almost unused. Identity already fits inside the originals wait for many cases, so the **upper bound** on cycle-time gain for the 62% originals-required stratum is small even under perfect overlap.

## Intervention and POWL

Restricting first-wave concurrency to cases that do not need originals is the correct statutory move. The specification then blurs it:

- It allows Document Check “after Register and before Originals Receipt (if applicable),” which is the illegal ordering for the 62%.
- Resource mapping assigns Register to identity reviewers.
- WIP “3” is invented with no link to Site A’s six-open-task rule or B’s pool sizes (4 / 7 / 3 / 2).
- The textual POWL is sequential (`Identity → Originals → Document`) plus illegal `is_parallel` keywords. Assessment is not encoded as the join of two unordered predecessors. The legal/supplement loop is described in prose and omitted from the order. This is exactly the “purely sequential Site B model” the prompt said not to substitute.

A faithful candidate is a **choice on originals-required**:  
`Register` then `{Identity ∥ Originals}` and `Document` only after Originals when required;  
`Register` then `{Identity ∥ Document}` when not required;  
join before `Assessment`;  
XOR skip vs `Legal Review`;  
loop `Legal Review` with `Request Supplement → Document Check → Assessment`.

That object is not in the answer.

## Pilot

The design table is populated and then conceptually broken. **Case type cannot be the unit of assignment.** Digital vs physical is a covariate, not a treatment. “Randomize digital/physical assignment” is not an experiment Site B can run.

A transport-learning pilot needs:

- assignment unit that can receive the control-flow change (case or team/queue, with interference handled because pools are shared);
- treatment versions that never create Document Check before Originals when originals are required;
- fidelity metrics (task-creation time, true interval overlap, lock-workaround rate), not just cycle time;
- a plan to distinguish “Document was never enabled, so no effect” (mechanism) from “Document was enabled but the lock/WIP/specialization prevented overlap” (implementation).

The write-up claims stratification does this. It does not. Fixed pools without clustered assignment also let treated cases steal document/legal capacity from controls, so any contrast is contaminated. Powering on a 10h median move copies Site A’s confounded contrast. Stop rules mix a success threshold with a harm threshold in one line.

## PM4Py code

This section is not an imperfect implementation; it is a different, non-existent API.

- `pm4py.algo.discovery.time_tree` / `time_tree.apply([...])` is not how the prompt asked to build Site A. Site A trees were already given; the required call is `pm4py.parse_process_tree(...)` on those strings, including the `X('Approve','Reject')` choice.
- `pm4py.convert_to_petri_net(...).show()` ignores the usual `(net, im, fm)` return.
- `PartialOrder`, `Place`, `Edge(..., is_parallel=True)` are not the POWL objects (`StrictPartialOrder`, `OperatorPOWL`, `Transition`, `SilentTransition`, `order.add_edge`).
- There is no XOR legal branch and no LOOP on supplement.
- `play_out(b_net, sample_trace)` is not a valid use.
- Comments mention capacity and data-dependent legal rules, which is the only salvageable part, and then invent `convert_to_petri_net_with_durations`.

Model fidelity—the dimension the rubric named—is therefore near floor.

The surrounding essay still over-transfers: 8–10h for digital claims, “no rework increase because Site A was stable” (A’s rework rose 11.8 → 12.4; B starts at 17% with a supplement loop), and “transfer huddles” (a co-intervention that would confound the next test). Those are not small bookkeeping errors; they are the assumptions the quantitative story depends on.
