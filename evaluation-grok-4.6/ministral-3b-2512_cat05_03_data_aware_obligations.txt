## Temporal semantics are internally inconsistent

Section 1 names event / effective / record / evidence time, which is the right vocabulary, then contradicts itself.

- Blanks are first treated as “keep the last known value,” then “a blank at `Release_Funds` means no prior update occurred.” The second reading would erase carried-forward state and is exactly what produced the TX-301 80k error.
- “The value at `Release_Funds` is authoritative unless overridden by a later event” collapses record time into event time. A later `Record_Exemption` is evidence about an earlier approval, not a mutation of the release snapshot.
- Material change is reduced to amount only. R1’s “latest material data change” is broader than R4, and the text never says how jurisdiction, risk, or customer-type updates interact with review validity.
- Same-timestamp ordering is mentioned, but not the consequence: the snapshot after `event_index` *n* is not the snapshot after *n+1*.

This is glossary-level coverage, not a usable reconstruction procedure.

This was a detailed, eight-point implementation requirement. The submitted block fails almost all of them.

2. The header is wrong (`case` plus a duplicated `concept:name`), and rows are inconsistent with that header.

6. R3 tests for any screen before release, not a screen **after** the list update.

10. Several paths unconditionally emit `INDETERMINATE`, which hides the distinction the narrative also failed to make.

“Executable checker” is not satisfied by a non-running stub over one malformed case.

## Section 6 explains the right headings with the wrong mechanisms

The six required failure modes are named, which is cheap. The explanations often invert the process-mining point.

- **Final-state leakage** is using end-of-case attributes when judging an earlier event. The answer says control-flow traces “only capture events up to release” and therefore miss post-release exemptions. Post-release events **are** in the trace. The bug is data semantics, not a missing event.
- **Post-hoc exemptions** are not ignored by control-flow; they appear as extra events. The problem is deciding whether a later record is evidence of earlier approval.
- Conditional activation, missing data, and same-timestamp order are directionally right but stay slogan-level.

This section reads as a paraphrase of the prompt, not an analysis grounded in the log.
