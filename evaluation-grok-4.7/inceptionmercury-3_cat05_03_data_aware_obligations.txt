7.3

The case conclusions are largely right, but the formalization is not sound and the required checker does not run.

Case results hold up under event-time state. TX-301, TX-303, TX-304, TX-307, and TX-309 are properly NONCOMPLIANT. TX-306 and TX-308 correctly treat a sub-20% increase and a decrease as non-invalidating, and 100,000 meets R1’s threshold. TX-302 is COMPLIANT on the Enhanced_Review even if EX-77 is set aside, and EX-77 is still well supported. TX-310 correctly refuses EX-88: a backdated display plus an interested witness does not meet R5. TX-305 stays INDETERMINATE and does not copy the settlement amount backward. TX-311 correctly uses `event_index` and finds R1 off because release jurisdiction is DE. Section 4 covers the required cases, and sections 6 and 7 hit the requested failure modes and logging controls.

Formalization problems are real. In R3, `x` is free in `ok3` after being bound only inside `req3`, so the screen-after-update obligation is not well-formed. R4 uses an unbound `release`. `ValidExemption(r)` does not match `ValidExemption(x, r)`. R2 is only “some Enhanced_Review before some Compliance_Approve.” It does not require the review to postdate the HIGH/PEP change, nor does it encode the standard-packet limit that the TX-307 prose itself relies on. “Material change” also folds in every risk and customer-type update for R1, which is broader than R4’s amount-dependent invalidation rule. The TX-305 alternative is too quick: a later 150,000 payload would not automatically make an amount-less Enhanced_Review satisfy R1.

The code’s state machine, if it ran, would mostly match those flags: forward fill does not run backward, settlement amount is not treated as release amount, `event_index` orders TX-311, and EX-88 stays `REVIEW_REQUIRED` rather than a hardcoded narrative label. As written it is not executable. `CSV_TEXT` has no header, while `read_csv` treats the first event as column names, so `event_index` and `case:concept:name` raise `KeyError` and TX-301’s create row is dropped. `case_id` is not a parameter of `evaluate_case`. The `state_*` forward fill is never used. `latest_standard` and exemption signature/record times never appear in the diagnostics frame.
