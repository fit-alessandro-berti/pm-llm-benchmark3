The design correctly refuses to code rejects, withdrawals, and open cases as non-defaults, balances all 48,000 applications, and states a conditional-on-activation estimand with real alternatives. That framing is then undermined by estimator, cohort, validation, and code errors that would still distort the 90-day risk.

The primary censoring rule is wrong for the claim it is meant to protect. Section 3 sets censoring time to `min(90 days, extraction − activation, last known event-free time)` and then, in code, writes a completed horizon with a missing feed as `surv_time = 90`, `surv_event = 0`. In a survival likelihood that is a recorded non-default. The same branch is used for permanently missing partner feeds, which the text says must not be treated as non-defaults. Known `default_90d = 1` outcomes are counted only when a `Default Recorded` event falls inside the horizon; otherwise a mature positive label falls through to that same event-free censoring path. IPCW is named as the primary fix but never specified, and it is not identified for partner-originated accounts if that stratum is almost entirely missing. Pattern-mixture sensitivities do not repair a primary label that has already been filled in.

The estimand does not match the cohort or the split. \(T_{\text{activation}} < \infty\) is eventual activation, while the table keeps only activation observed by the cutoff, so recent starts are selected for fast activation. “Unless linked” transfers sit outside the 25,200 and break the partition. The displayed estimand conditions on policy period, but the only training window is pre-1 July 2025, so the post-policy coefficient is not estimable. Test cases start on or after 15 October 2025, where policy change, activity renaming, and immature 90-day labels are tied together. A 31 December 2025 backtest cannot observe a 90-day outcome plus a 7–35 day feed by 15 February 2026. Binary AUC on the mature subset reselects complete feeds, and a missing-label subgroup has no observed default on which to score.

Prefix rules disagree. Section 1 uses the earlier of the third event and day 5; section 4’s fixed-length prefix does not; the code calls `get_prefixes_from_log(..., length=3)` and never applies the day-5 cap. “Third event after Application Started” is also off-by-one relative to a length-3 prefix. Deduplication runs on the raw activity name before the migration map, so old-name/new-name duplicates remain. Single timestamps cannot identify service or sojourn time. DFG, variants, and queue time are fit on the full log, so later cases enter earlier features. `documents_total` is still taken from the prefix snapshot the audit said to repair. `temporal_features` are merged without case-level aggregation, and the lifelines index uses `primary_train[CASE_ID].index` rather than case ids. The skeleton is roughly twice the requested 80–160 lines and does not implement the stated as-of rule.

The leakage table and the deployment caveats are the most reliable parts. As an analysis specification, the outcome construction and the backtest calendar are not yet statistically safe to run.
