5.5

The case analysis is detailed and mostly well-traced, but the final judgment contradicts its own authority standard, and the required POWL does not implement the control flow it claims to encode.

Section 5 classifies SUP-705 as MIXED with dominant JUSTIFIED_EXCEPTION because the flood “factually” continued. That directly contradicts the stated burden of proof (a contemporaneous written authority is required; factual persistence is not) and the same section’s rejection of treating the post-expiry emergency as authority. FD-7 ended on 2026-07-12; SUP-705 is 2026-07-13 with no extension. The “what would reverse” cell (a written extension) also fits a noncompliance finding, not a justified exception. The rejection paragraph then assigns the flood-extension argument to the prosecution, which argued the opposite. MIXED is being used to split the one case where authority had clearly lapsed.

The model fails several minimum requirements it asserts are met. `checks` (both sanctions and quality) is ordered before `decision`, so quality is forced before activation on every route. The auto branch therefore cannot express PD-3’s post-activation quality review, despite a comment promising a partial order that is never built. The emergency branch both reuses that same `quality` node and places it after `activate`, which composes a cycle and still does not allow provisional activation before quality. `Request_More_Info` is the redo of a loop whose body already contains the approval decision, so info requests occur only after activation and the body can activate repeatedly; SUP-707’s pre-decision repeats are not in the language. `silent_exit` is unused. Rejection is not an XOR alternative to approval: the decision contains only activating branches, and reject/withdraw run afterward, so a rejected case has already activated. The same `Transition` objects (`activate`, `quality`, `notify`, `close`, `standard_branch`) are shared across exclusive parents, so the POWL is not a well-formed tree. The first `M1`, with terminal paths concurrent rather than exclusive, is discarded leftover.

Other final-conclusion problems: SUP-708’s order is given as observed, so “pending” and low confidence on a speculative start-versus-complete theory are under-supported; the CS-9 overlay predicate is vacuous and invents “CS-9 amount rules”; PD-3 master-data validation, the two-business-day quality deadline, and daily monitoring are missing from the enforceable checks; and the proposed CoI rule bans same-line relationships when the stated policy only requires disclosure. Schema design and the SUP-701/702/703/704/711/712/714 classifications are the parts that hold.
