6.5

The design correctly refuses to code rejects, withdrawals, and open cases as non-defaults, reconciles all 48,000 starts, and separates joint activation-and-default risk from conditional default, survival, and counterfactual targets. The leakage table and the deployment feedback points are the strongest parts. The write-up is not reliable enough to implement as specified.

The primary estimand is misstated. \(F(h)\) is called a cumulative incidence, but the right-hand side never uses \(h\), leaves \(T_{\max}\) undefined, and mixes the scientific 90-day post-activation window with the 7–35 day feed lag. “Policy \(\_obs\)” is broken notation carried into the limitations section. Prediction time in §1 is the earlier of event 3 and first Credit Review, and must precede any terminal activity. §4 and the code switch to a raw \(k=3\) or 72-hour cut and never enforce that constraint, so Rejected, Account Activated, or Default Recorded can sit inside the prefix.

Cohort arithmetic adds to 48,000, but the maturity claim does not. “~39,300 mature-eligible” treats unlinked transfers as observed and folds permanently missing partner feeds into the 3,600 “not yet matured” row. The factor ~2.2 uses 2,700/48,000 as if it were the true joint risk, which counts immature activated accounts and still-open cases as non-events. That is the naive denominator the censoring section argues against.

Censoring categories are the right ones, then the strategy blurs them. The primary analysis both restricts to a maturity-eligible cohort and applies administrative censoring weights. Inverse-probability-of-activation covariates are called “instruments,” including policy era, which also shifts the outcome relationship, so it fails the exclusion restriction. Overlap is treated as a partial test of selection on observables; it only speaks to positivity. In validation, censored cases are a multiclass label, so the model can score well by predicting administrative non-maturity from start date.

The temporal split names the right eras and correctly rejects a random split, but it does not close the maturity arithmetic. With a 60+90+35 day embargo and an extract on 15 February 2026, guaranteed outcome follow-up ends around mid-August 2025. Most of Test-1 and essentially all of post-migration Test-2 cannot support a default metric. The text flags Test-2 as maturity-limited and states an embargo, without saying that post-migration outcome performance is unidentified in this extract.

The skeleton contradicts the paper. `mature` requires a non-missing `label_available_at`, so rejected, withdrawn, transferred, and open cases are all immature, and the modeling hook `X[mature]` returns the selective activated cohort. The leakage assert misses that outcome, which is merged back in as `label`. `GroupBy.nth` keeps the row index, so `t_pred.loc[case]` does not align, and short cases raise `KeyError` instead of being counted as uncovered. `era` compares a timestamp with the string `"2025-01-01"`. Dedup is exact-timestamp equality, not the stated 5-minute rule. The 72-hour log, DFG, and variants are built from full traces that still contain post-outcome activities, and the prefix log is never the feature source.
