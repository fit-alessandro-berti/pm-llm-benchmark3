6.5

The settled conclusions are right on the actual equivalence question, and wrong on the exact bounded counts that the same conclusions treat as derived facts.

The verdicts hold. After hiding `tau`, neither visible language contains the other: Model A ties `Check Revision` to each loop iteration, so `occ(Check) = occ(Analyze) = n ≥ 1`, while Model B has a single `Check Revision` beside the loop, so `occ(Check) = 1`. The four shared traces are exactly the one-iteration cases `AC`, `CA`, `AC·Approve`, and `CA·Approve`. `Open · A · Approve · Check · Close` and `Open · A · Rework · A · Check · Close` are genuine B-only traces; two-check traces such as `Open · A · C · Rework · A · C · Close` are genuine A-only traces. P1 is therefore not equivalent, P3 is not equivalent, and P2 is equivalent only after collapsing repeated checks to a Boolean and dropping approvals and `tau`. The optional approval changes placement, not the check-count split. The simplified tree that sequences `Analyze` then `Check` then optional `Approve` inside the same loop is a fair P1 target: it keeps one check per analysis, optional approval after that pair, and rework as a separator, and it does not preserve the bounded visible language.

The exact P3 cardinalities do not. For three iterations with an approval in every block, Model A has length `1 + 3·3 + 2 Rework + 1 = 13`, so those 8 traces fall outside “at most 12 visible events.” The bounded set is 76 traces, not 84; A-only is 72, not 80. The same omission makes the simplified model’s bounded size 7, not 14. Model B’s 85 is right, and the total-variation figure `81/85` happens to survive, but the write-up asserts `84 / 85 / 4` and would fail its own check. That is a final quantitative error, not an abandoned aside.
