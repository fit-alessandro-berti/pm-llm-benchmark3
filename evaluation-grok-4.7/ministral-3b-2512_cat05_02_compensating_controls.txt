3.4

The write-up has the required seven-part shape and a few defensible calls (AP-202 failed, AP-205 stopped before completion, AP-208’s package failed). It is not a usable conformance assessment. Case facts are swapped or invented, the control objective is misstated, required reasoning is missing, and the code cannot run.

**Control objective.** FEP-1 exists to stop one person from both initiating and authorizing an erroneous or fraudulent transfer. Collusion between two people defeats four-eyes; it is not an objective four-eyes achieves. AV-2 is treated as if it prevents fake invoices, collusion, and compromised-operator fraud, which the control definition expressly excludes. “Late manager approval” is a compensating-control failure mode, not an FEP-1 threat. Several rows say the threat has no detective or corrective response while also assigning RA-7 that role, and they never state which controls simply fail to address the threat.

**Sufficiency test.** Fully equivalent is defined as “AV-2 blocks release,” which is non-completion, not an equivalent package for a completed payment. The partial/mitigating boundary is an loose OR that can bless a post-settlement ratification. Rubber-stamp versus substantive review, coverage gaps, and emergency necessity are not operationalized. The required explanation of why equal expected loss is not a sufficient standard is absent. Two criteria sentences are garbled (“Warning/block approval”; “AV-2 pass goods receipt”).

**Case findings (core failure).**
- AP-203 settled at 12:00 with the ED-1 conditions largely met, yet it is labeled `LOSS_PREVENTED_BEFORE_COMPLETION`. That label is for a payment that never completed.
- AP-204’s audit found a fabricated receipt, there is no manager event, and the audit was days later. The table says MG-4 occurred and RA-7 found “no defect,” then calls a EUR 220k confirmed defect only partially met with medium residual risk.
- AP-206 had no bank-account change, a full AV-2 pass, independent approval before release, and next-morning audit inside a one-business-day window. The only real issue is whether the emergency token preceded preparation. The answer imports AP-208’s bank-ownership failure and marks the objective failed.
- AP-201’s independent ratification was before the 10:00 settlement on a correct EUR 1,800 payment. Residual risk “High (no recall)” and “MG-4 too late” contradict the timeline and the exposure.
- AP-207 meets a plausible ED-1 pattern (substantive independent review before settlement, timely audit). Section 3 says residual risk is none; section 5 says there were no compensating controls and the review was weak.
- AP-209 has no manager event. Both the table and the code assign a timely pre-settlement MG-4.
- `INDETERMINATE` is never used where the record is actually ambiguous (token timestamp, u12/u13 cell versus collusion).
- Failed or bypassed activities (overridden warning, unavailable AV-2, post-settlement ratification) are listed as if they were preventive controls that operated.

**Timing semantics.** The comparison labels a post-release, pre-settlement manager action preventive, hybrid, detective, and corrective in successive sentences, and then says that review “misses fraud.” A substantive review at that point can still stop irrevocable settlement. ED-1 is described as a preventive control; it is a conditional permission. The audit row does not separate recall-window audits from audits that are only detective.

**Counterfactuals.** “Control break” is used for controls that failed rather than controls that interrupt the loss path. AP-201 and AP-207 are described as having no compensating controls. AP-204 misses the actual break: AV-2 cannot see a fabricated receipt, the nominal second person was not independent, and the audit was too late to recover. No qualitative ranges are given. AP-205’s loss mechanism is stated as the control that stopped it.

**Monitoring.** The audit “alert” is the compliant condition (audit within 24 hours), not the breach. Credential sharing in AP-202 is called proof; the facts say it is unresolved. The same-user example “3/60” is not this population. Thresholds are arbitrary and do not separate justified ED-1 use from convenience same-user release.

**Code.** Not executable and not the requested check. The CSV is truncated to two cases, the case column is renamed, and the text is passed to an XES importer rather than read with pandas. UTC timestamps are never parsed, and `format_dataframe` is applied to the wrong object via a wrong import. The four-eyes call does not use `pm4py.filter_four_eyes_principle`, does not discuss the version-dependent positive filter (compliant cases versus violations), and labels the result a violation anyway. AP-205 is absent from the log being filtered. The case-facts frame repeats the false manager and audit findings and flags a bank change on AP-206. The `av_covered` expression is an operator-precedence error. The merge of event-level and case-level frames is incoherent. Flags are string matches, not timestamp comparisons, and the audit match is case-sensitive against capitalized text, so it would not mark the timely audits even if the frame survived. The closing note treats `nominal_four_eyes` as a placeholder.

Heading level also departs from the required top-level headings. The recurring defect is treating a named activity as a sufficient control and then overwriting the event record when the classification needs it.
