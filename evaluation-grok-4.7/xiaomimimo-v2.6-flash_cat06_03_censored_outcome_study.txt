6.8

The design correctly refuses to code rejected, withdrawn, transferred, or open cases as non-defaults, and it centers activation as selective observation rather than a silent filter. The competing-outcome estimand, as-of prefix rule, leakage table, and temporal split are the right skeleton. The score is held down by identifiability overclaims, an inconsistent time scale, a maturity error in validation, and a skeleton that does not implement the target it describes.

The primary estimand is only partly specified. Cause 1 (activated and default within 90 days) and cause 2 (activated and no default) do not occur on the same clock: a default can be known during the 90 days, while “no default” is known only at activation plus 90 days. Section 1 never defines those event times, then still claims the CIF is identified from independent administrative censoring alone. That is too strong. Permanently missing partner feeds are not administrative censoring, and a case started in 2024 that is still open in February 2026 is not censored independently of outcome merely because the extract date is fixed. Open cases are also listed as both a competing cause and a censored state.

Cohort arithmetic is correct (48,000; 1,740/1,160; 25,200 activated; 12.5% among matured activations). The flow table then adds a “TBD” permanently missing stratum without saying it overlaps rows 5–7, so the partition is not clean. Global 60-second deduplication is applied to the whole history, not only post-migration duplicates.

Validation overstates maturity. Train through 31 March 2025 and validation through 30 June 2025 are called fully mature, but slow activations from those starts are still inside the 5,100 open and 3,600 immature counts. The rolling-origin rule keeps only cases with `label_available_at` at or before the origin. That drops right-censored cases instead of including them with a censoring indicator, which conflicts with the competing-risk model in Section 3 and biases training toward cases that resolve quickly.

The code would not run as written: the channel audit groups `case` by `case:channel`, which was never aggregated onto that frame. Label construction uses any `Default Recorded` event, not `default_90d` within 90 days of activation, and an observed default before the 125-day deadline is still marked immature. The survival hook sets exit time to the first stop event, which for booked accounts is activation, not default or horizon completion. The feature frame carries `stratum`, `outcome_time`, and `label_ready_at` while the leakage assertion only checks a forbidden-name set, and `t_pred` is the max timestamp of the same rows being checked, so the future-event count is vacuously zero. Coverage includes prefixes shorter than K even though the text says those cases are unscored.
