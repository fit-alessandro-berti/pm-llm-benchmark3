The write-up is structured correctly and gets several hard ideas right: time origin at `Submit`, horizon 72h, estimands stated before estimators, withdrawal/transfer not treated as ordinary independent censoring, and `Escalate` correctly barred as a baseline covariate because of immortal time. The S09 point is also right: an open case aged 92h is a known non-resolution at 72h for a fixed-horizon “resolved by 72” indicator, while it is right-censored at 92h for a time-to-resolution curve. Those strengths are undercut by contradictions and required misses.

The central encoding is wrong in two incompatible ways. The status table codes open cases younger than 72h as estimand-1 successes (`0`). The code codes every non-early-resolution, including those same open cases (S10, S15, S24, S29, S31), as breaches (`1`). Neither is censoring. For \(P(T_{\text{resolve}}>72)\), age \(<72\) and still open is unresolved, not a success and not a failure. Printing cohort breach rates from that indicator does not estimate either stated estimand. The “optimistic transfer” sensitivity then sets transferred cases to `0`, which imputes success. It does not censor them. Complete-case analysis is named and never built. Estimand 2 never becomes a competing-risk code or a risk set.

Other concrete problems: Kaplan–Meier “overestimates breach risk” by censoring withdrawals is the wrong direction for their own estimand 1, where withdrawal is already a non-resolution; the cause-specific hazard is described as conditioning only on no withdrawal. Restricted mean time is never compared, despite being required. Section 3 never separates open cases below 72h (still censored for the SLA indicator) from open cases above 72h (already observed non-resolutions); S03/S13/S20/S28 are observed late resolutions that a resolved-only analysis would still include, so “completed cases look artificially low” is an untested direction. A multi-state model is recommended as primary even though sojourn times are absent, and the 24h/48h landmark states are not identifiable from prefixes. The Mermaid diagram drops observed transitions (`AutoCheck→Resolve`, `Screen→Reject`, `Screen→Escalate`, `Screen→Withdraw`, `AutoCheck→Escalate`, `Rework→Resolve`). `autocheck_order` is called baseline even though it is realized path order, and `last_event_gap_h` is used as a feature without noting that it is defined by the same endpoint as the outcome. The 85% alert is not computed from the table. The code fabricates hourly timestamps after claiming not to, and it depends on a removed PM4Py import path (`pm4py.objects.log.log`). Section 9 omits start time relative to the freeze date, which is what would show whether cohort B simply had less follow-up.
