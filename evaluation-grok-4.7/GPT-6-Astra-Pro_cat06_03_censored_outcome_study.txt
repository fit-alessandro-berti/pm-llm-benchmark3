7.8

The design is statistically serious and avoids the central failure modes: it does not train on the 21,600 labeled rows alone, does not code rejects or withdrawals as non-default, separates prediction time from label time, and keeps validation temporal. Cohort arithmetic (48,000; 25,200 activated; 12.5%; 10.7–25% ignorance bounds) and the 215-day maturity dates check out. The estimand, competing-risk warning, pattern-mixture sensitivity, leakage table, and refusal to treat inter-event gaps as service time are all defensible.

The implementation then contradicts that care. For validation, `tau < 2024-11-01` keeps an October start only when the third event also falls in October. Late-October and slow-to-landmark cases drop out, so the calibration sample is selected on speed—the bias the maturity rule was built to prevent. The same rule is not applied to test, so the two sets are not comparable. Vintage-dependent inclusion of exact-`k` prefixes (a September start enters training at `k=3` only if event 3 occurs before 1 October) is never identified, even though it confounds fast-path features with calendar time.

Other gaps are smaller but real. Section 1 says the six state probabilities sum to one, while activation with a still-missing default feed is outside that observable partition; section 3 repairs this, but the primary estimand is stated too cleanly. The stated primary fit is inverse-observation weighting plus joint exit probabilities; the skeleton only flags complete cases and defers both pieces to comments. Data-quality failures abort by `assert` instead of the promised quarantine counts. `idle_hours` is identically zero on the executed event-count path. Migration duplicates that are not exact timestamp ties are not diagnosed. The script is also a bit past the requested length, and empty `ALIASES` will silently miss renamed exits until someone notices the printout.
