7.5

The case analysis is strong and usually precise, but the required case table is broken on two high-risk rows and the required checking code is not reliably executable. Those are material failures against an answer that otherwise handles a difficult record well.

Event-time authority is mostly right. Aliases are normalized so `b.koch` and `u_bk` are Ben, and that correctly turns CHG-508 into a real drafter/approver breach. CHG-502 and CHG-510 are likewise clean RR1 failures. Eva is never treated as QM from a later job title; CHG-507 is unauthorized; D-IC-04 is invalid because D-IC-03 forbids subdelegation. D-QM-01 is applied from the 2026-08-09 signed PDF, with the 2026-08-12 migration row kept in its place, so CHG-501 can be a valid substitution while CHG-503’s approval is separately supportable. Service-account evidence is split correctly: CHG-503 stays unattributed, CHG-509 is strongly attributable to Eva. Sick-leave timing is case-specific: CHG-506 and the CHG-505 review fall inside it; CHG-510’s review does not. Weekend status is not treated as Asha’s absence. The two-business-day clock is explicit and internally consistent: CHG-505’s Friday review is late, CHG-510’s Wednesday review is timely, and Ben’s cooling-system reviews still lack D-QM-01 scope.

The findings table does not match its own header for CHG-505 and CHG-506. Confidence is missing; the alternative explanation sits in the confidence column and the missing-evidence text sits in the alternative column. CHG-505’s sentence “the logged event time controls absent correction evidence” is unclear. CHG-504 is labeled AUTHORIZED while the account user is still unresolved, and CHG-509 is labeled UNAUTHORIZED where the missing fact is Asha’s availability; both are argued, but the primary labels are sharper than the ambiguous record. The technical result that Eva can approve and verify CHG-509 under RR1/RR2 is stated without separating that from the weaker independence objective.

Section 4 does the required work: each concentration, reciprocal pair, shared session, leave conflict, and prohibited subdelegation has a benign explanation, an adverse explanation, and a discriminator, without treating repetition as collusion. Section 6 covers the requested controls with case-specific content. Section 7 names real SoD failures, identity limits, and pattern risk, and its three investigations are the right ones. It still folds CHG-503 into “supportable substitutions” closely enough that the unresolved verifier can be missed, and it calls CHG-509 a genuine control failure while absence is unproven.

The code embeds the log, parses timestamps, calls `format_dataframe`, normalizes aliases, and its pandas pair flags correctly emit `UNKNOWN_ACTOR` for CHG-503. That is the right SoD behavior. The PM4Py four-eyes calls still see `UNATTRIBUTED:svc_qms` as a different resource, so they can report a false pass; the text admits this, but the printed case IDs are easy to read as the verdict. `astype(bool)` is unsafe if `true`/`false` arrive as strings, because every non-empty string becomes True. Retrospective review interval, scope, and business-day lateness are absent from the checker, and the contested CHG-505 flag is never printed. Both network calls pass `activity_key`, which the usual top-level `discover_handover_of_work_network` and `discover_working_together_network` signatures do not accept, so the script is likely to raise `TypeError` before producing network evidence. The optional different-resource filter is omitted.
