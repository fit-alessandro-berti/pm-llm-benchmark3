3.5

The write-up has the right section structure and states the offset identity, SLA limits, and zeta=1 bands correctly, but the intervals, durations, and classifications are not trustworthy. Several rows contradict themselves, and more than one material label is the opposite of what the stated numbers imply.

**Self-contradictory classifications.** T-401 S1 lists duration [780, 1080] against a 900 s cap and then calls it a certain violation because the “entire interval” is above 900. It is not: 780 is already inside the pass region, so that row is a possible violation on the answer’s own figures. T-409 S2 lists [480, 2100] against a 2700 s cap and calls it a possible violation for “overlapping 2700”; the interval is wholly inside the pass region. T-404’s investigation-to-containment profile interval [1680, 2700] sits inside [1500, 2700] and is still marked a possible violation. Boundary contact is treated as a violation in some rows and ignored in others.

**Wrong event times and time zones.** T-403’s vendor stamp is 04:00 EDT, which is 08:00 UTC, not a [12:00, 13:00] window. The code repeats the error by storing 09:00. The resulting S1 duration [-300, 300] and the “negative durations” rationale do not describe this case. T-402 containment is 10:02:00, not 10:00:00. That two-minute shift is exactly what moves investigation-to-containment from a clear pass to a boundary-straddling possible violation; the answer reports a certain pass on the wrong instant.

**Resolution and clock offset are not actually composed.** The stated rule is resolution first, then `true = recorded − offset`. HUB’s ±0.5 s measurement uncertainty never enters the intervals. OPS-BER 10:14 CEST should be about [08:12:00, 08:16:30] UTC after the minute floor and offset [-90, +120]; the table gives [08:13:00, 08:16:00]. SENSOR keeps only one ±5 s layer. Those narrowed windows are why T-401 S1 is called a certain violation when the feasible gap still reaches under 15 minutes.

**DST order is reversed.** On 2025-10-26, ingestion order plus the labels 02:50, then 02:05, then 02:42 leaves only one combination: alert on the first fold, investigation and containment on the second. The answer keeps both investigation folds, puts containment near 00:41 UTC while calling it the second fold, and reports S1 unions that do not match the section 2 intervals. T-404 is similarly inconsistent: the start upper bound is 10:17 in the duration math and 10:27 in the event table, so S1 and S2 are computed from different starts.

**Sensitivity math fails on the answer’s own intervals.** With T-401 duration [780, 1080], a 5-minute SLA cushion (threshold 1200) makes every value a pass, not a possible violation. T-406’s upper bound of 1140 still exceeds a 2-minute cushion (1020), so that cell is not a certain pass. Zeta=3 for the T-401 alert-to-investigation profile swallows [780, 1080] and should be a certain pass. The prose also treats tolerance as if it moved the duration bound rather than the acceptance threshold.

**Missing required tests.** Every testable Alert_Received → Containment_Complete profile is absent. That pair does not need inferred starts, and for T-402 it is a certain profile violation near 62 minutes. T-409’s replacement of the NTP bound by a weak ±12 min estimate is never stated in the assumptions, and the printed interval [16:02, 16:26] is not that bound (the date is also truncated).

**Mobile delay and T-407.** The entry-delay paragraph says the delay shifts the record and not the occurrence time, then defines occurrence as recorded time minus the delay. The numeric window [12:13, 12:19] does not apply rounding, the ±300 s clock bound, and a [0, 300] s delay together. T-407 adopts the unlogged “receipt not after investigation start” constraint as fact and drops joint HUB uncertainty.

**Code would not support the claims.** Naive datetimes are converted with `astimezone`, so the source zone is not the zone of the stamp. The T-404 and T-407 branches never run because those activities are not in the input rows. Legacy folds are not reduced by ingestion order. Interval classification uses the leftover `zeta` after the loop and only the first segment of a union. `conformance_temporal_profile` is indexed as a frame with `fitting` columns, with no version isolation, and midpoint results are not compared with the interval conclusions. The hand table and the code also implement different bounds.

**Sections 6 and 7.** Sufficiency is grouped by case, not by each possible or indeterminate result, and it does not separate synchronization, missing-activity, duration, and semantic evidence. Governance names the requested controls, but the enforcement rule treats any overlap with the pass region as an SLA pass, so the widest uncertainty almost automatically complies.
