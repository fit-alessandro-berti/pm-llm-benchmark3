4.2

The write-up has the required nine sections and a sensible narrative preference for a hybrid rule with a pooling fallback, but the quantitative core is not auditable and several final claims contradict the model that is supposed to support them.

Offered load treats parallel ME/ES work as the critical-path maximum. Parallel branches still consume two resources, so resource-minutes are the sum of the branch times; only elapsed case time uses the max. Complex-tail probabilities are also dropped, so ordinary midpoints understate Electrical and Software. Intake, diagnostic, and validation minutes are then combined inconsistently (the stated total does not match the listed components). The result is a base utilization near 90% that is too low and not comparable with the later delay and utilization figures. There is no time-block by skill account of shift overlap, breaks, or the evening cliff when only Emil remains, despite that being the requested capacity analysis. U1–U5 effects stay qualitative: Chen’s absence is described only as a software cut, not as the loss of the fastest electrical resource and of the only morning software person in the reserved P1 pool.

The comparison is one row per policy, not a policy-by-scenario table. The ranges are presented as 100-repetition simulation bounds. The code runs one seed, hardcodes resilience and failure mode, and never produces those ranges. That is invented evidence. Mean delays of roughly 125–160 minutes and hybrid max utilization of 85–92% cannot sit beside a system already estimated at about 90–106% load before handover, setup, coordination, and multipliers. The P1 pool (Ada, Chen, Deepa) cannot cover every skill: Ada and Deepa have no Software, Chen has no Mechanical, and under U3 the reserved Software set is empty. The recommendation still says this policy is robust across U1–U5.

The Python scaffold does not implement the stated mechanisms. U1/U5 priority probabilities sum above 1. U2’s extra demand is not created. U3 and the intake outage are absent. Skill multipliers are never applied because case types are not the skill column names. Handover and setup are added and then overwritten. The preemption penalty is charged to the P1 case itself rather than to the interrupted activity’s remaining time. Defined shift and break checks are unused, arrivals ignore blocks, and recorded “delay” is service time only, so the SLA clock is not an elapsed-time clock. Event timestamps collapse to whole hours and can be invalid. PM4Py is called, but case sojourn is not separated from stage service and queue wait, which the required post-analysis needed. Omitted mechanisms are not identified, so the scaffold exception does not apply.

The rollout rule says to proceed if the pilot shows a 10% P1 SLA degradation and a 5% delay increase. That approves a worse system. Trigger inequalities are also missing or unreadable, so the mode switch is not operational.

Sections on dispatch rules, secondary risks, and event attributes show real process awareness. They do not repair the load identity error, the unsupported scenario table, the non-running experiment, or the inverted go-live test.
