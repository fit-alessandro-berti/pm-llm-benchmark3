The score stops there because several analysis claims are not accurate.

Dropping the extension rows does more than the object-centric Petri-net paragraph says. Orders lose e08 as well as e09, e10, e13, and e14, so the order net loses the repeated Pack and Confirm, not only Dispatch. Package and item nets lose Confirm, and item nets lose Dispatch, only because those rows were added. Changing the inductive-miner variant or the noise threshold does not delete Confirm from package traces in which every trace contains it once. The sentence treats those three changes as the same effect.

“One-hop” and “one-step logistics walk” are also looser than the graph they describe. From D1, `carries` reaches only P1; I1/I3 are two steps away and O100/O200 three. The implemented policy is a hand-expanded logistics chain, and the code matches that broader policy, but the distance language is wrong.

Qualifier design undercuts the otherwise strict provenance split. `fulfilled` covers pack, dispatch, and confirm, so the order role no longer identifies the lifecycle stage. E2O `settles` is easy to read as completion, which is exactly the reading the O2O vocabulary refuses by keeping both M1 and M2 on `partially_settles`. The check that pairs oid `{M1, M2}` with type `order` can never catch an order allocation; only the later eid check does.

Smaller slips sit in the same band: O100’s lane split is e07 plus e08, not one step; Add Item → Add Item is not the P1/P2 split; and the OTG paragraph blends O2O edges with event co-occurrence without fixing which graph `discover_otg` returns. The core tables survive a manual audit. The discovery commentary does not, at the standard of a nearly exact account.
