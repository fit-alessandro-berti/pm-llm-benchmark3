6.5

The design correctly refuses to code rejected, withdrawn, transferred, or open cases as non-default, and it separates selection, administrative censoring, feed lag, transfer, and permanently missing feeds. That core is sound. It is not statistically coherent enough to implement as written, and the skeleton does not enforce the as-of rules the prose states.

The primary estimand is misspecified. \(CIF_j(t_0)=P(State=j\mid\mathcal{H}(t_0))\) is a static state probability, not a cumulative incidence, and no time horizon \(\tau\) is fixed. Censoring is listed as a cause and then, in §3, handled with IPCW instead. Those are incompatible. “No default by 90 days after activation” is not a competing event on the same clock as rejection or withdrawal; the nested time origins are never defined. The risk set is also unstable: §1 predicts only if the case is still open and treats Accepted as terminal, while §2 and the code omit Accepted and describe the population as all 48,000 applications. The displayed estimand does not condition on still being at risk at the landmark.

Alternative 1 asks for the descriptive quantity \(P(default\mid activated,\mathcal{H}(t_0))\), which is fit on activated cases. It does not require IPW or Heckman; those change the estimand. The claim that an activated-only model necessarily overestimates population default risk is unsupported. Rejected applicants are likely higher risk, so the activated rate can understate the counterfactual rate. Missing transfer linkage is also treated as interference; it is a follow-up problem.

Cohort arithmetic matches 48,000, and the prohibited 5.6% rate is right. Withdrawal is called both a competing outcome and informative censoring. Permanently missing partner feeds are not separated from the 3,600 immature activations, so the table’s “right censoring” role is too coarse. No landmark risk-set count is given.

Prefix rules conflict with the code. Prose says not to predict once a terminal event has occurred and not to pad short cases, but `time_prefix` keeps every event with `timestamp <= start+h`, including Rejected, Accepted, or Activated inside the window. A \(k\)-prefix whose \(k\)th event is terminal is likewise kept by `get_prefixes_from_log`. `last_activity` then leaks the outcome. “Contributes at its terminal time” is not a valid prediction time, because the outcome is already known. `documents_total` is “repaired” by counting `Request Documents`, which is a lender activity, not an as-of count of uploads. Service-versus-waiting time is not identified: the log has no lifecycle start/complete column.

Validation cannot be run as specified. Validation and TEST-1 are the same start window, 2025-04-01 to 2025-06-30. TRAIN requires labels mature by 2025-06-30, which selects fast activations and drops censored cases, contradicting IPCW. The “~60%” figure is invented. A start on 2025-03-31 is mature by 2025-06-30 only if activation and the feed both occur implausibly fast. TEST-3 starts cannot have mature 90-day outcomes by 2026-02-15. A 3-month walk-forward ignores the 90+7–35 day maturity gap. “Brier at 90d” never says whether the clock starts at \(t_0\) or at activation. Conditional AUC among those eventually activated uses the future selection result to define the test cohort.

The code does not implement that design. `case_tbl_train_cutoff` is unused. The split is taken from the 2026-02-15 extract, and backfilled `default_90d` on early events is never nulled when `label_available_at` is after the cutoff. `censored` is only “no terminal event,” so immature activated accounts are omitted. The leakage `assert` passes whenever the forbidden columns are absent, and fails in this pipeline because those columns remain on the frame and are not all null. Prefixes of length 3 are computed and never used. `discover_dfg` on time-truncated prefixes is not a map of the real process.

§8 is the cleanest part: association versus selection versus counterfactual is explicit, and the three feedback loops are real deployment risks. The study still needs one clock, one risk set, censoring kept out of the cause set, and a skeleton that blanks future labels and terminal events before features are built.
