The headline verdicts are right: A and B are not visibly trace-equivalent, not equivalent under P1 or P3, and they do match under the stated P2 abstraction, because A has one `Check Revision` per analysis while B has exactly one check beside the loop. A1/A2 separate A from B, and B1/B2 separate B from A, so incomparability is real. That core is not enough to carry the write-up.

`+` is treated as two different operators. In B it is correctly called concurrency; in A the same operator is called fully sequential and is claimed to force `Analyze Revision` before `Check Revision`. That is false. A admits `Open Case, Check Revision, Analyze Revision, Close Case`. The “decisive difference” cells for B1 and B2 are therefore wrong: B1 fails in A because the second iteration never gets a check, and B2 fails because `Approve Revision` is taken before that iteration’s parallel block has finished. A check immediately after `Rework Case` is legal in A.

The cited 3-analysis P3 witness has 13 visible events, so it sits outside the bound of 12. Non-equivalence under P3 is still true (A1 is inside the bound), but that witness does not show it. Section 9 then says this bound cannot detect the divergence, which contradicts A1.

The bounded explorer does not fire a Petri net: it walks only `out_arcs`, never consumes input tokens, and treats silence as the label `"tau"` rather than `None`. It is not an exhaustive P3 check. `play_out` is also misdescribed as one trace. Node count is stated as an exact 10; both trees have 12 nodes. The P2 simplification does not preserve P2. A one-child loop whose body is `Analyze Revision` then `Rework Case` forces a rework on every iteration, including the last, so the no-rework dashboard tuple is missing. The listed regression traces are not admitted by that tree, and `Open, Analyze, Rework, Analyze, Check, Close` is not admitted by A either. The preservation table’s “exact” dashboard row is false, and the recommendation to replace either original with this model for the dashboard does not hold.
