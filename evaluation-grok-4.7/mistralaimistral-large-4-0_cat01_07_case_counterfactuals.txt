6.5

The write-up matches the required format and gets the main policy point right: K-337 changes the decision rule, while the other three mostly change timing, routing, or task creation. Four-eyes review, originals-before-document-check, and final compliance after the latest assessment are preserved. The 100-case discussion correctly treats C1 reservation as zero-sum, D1/D2 substitution as rework-sensitive, and earlier verification as a possible move of congestion into assessment. Those strengths do not offset several load-bearing timing and calibration errors.

K-411’s “base” path is the optimistic extreme. Document check ends Tue 16:30 and assessment starts at 16:30, with M1 signing that evening, for an 18.5 h saving that is then repeated as the base benefit in the ranking. The same-day record does not support an idle A2 at 16:30. Tuesday’s snapshot already shows about 6 h of A2 work, one assessor is in training, and a case ready at Tue 13:30 is not assessed until 20:00. Held fixed, that earlier case occupies A2 through 22:30. A zero-wait 16:30 start is a best case. The plausible base is an overnight wait and a much smaller, possibly near-zero, cycle-time change. The answer states a 0 h scenario and then still labels 18.5 h as base.

K-337’s headline saving has the same problem. Thu 08:00’s 5 h C1 forecast is treated as evidence that C1 can start Fri 11:00. That backlog would clear Thursday afternoon only if no further work arrived, which is incompatible with the week’s compliance load. The numeric band, about 101–105 h versus 214 h, is only a narrow Friday-completion slice. Slippage to Monday, a longer review because the discrepancy is still open, and appeal time are acknowledged in prose but excluded from the range that carries the conclusion.

K-219 misuses the Mon 16:00 D2 snapshot. A 5 h queue at 16:00 is remaining work at 16:00, so it should be about 3.5 h by the 17:30 originals arrival, not a fresh 5 h wait until 22:30. Within a 4–8 h D2 service, the case is still ready before the assessment queue clears, so best and base correctly land on the same 15.5 h saving without stating why further document speed has no cycle-time value. The rework interval of 32–71 h is internally inconsistent: 32 h leaves no room for the stated minimum external response of 8 h plus a second document check and assessment. Same-evening M1 signing is also doing too much work. If M1 still batches next morning, earlier document completion and an earlier Tuesday assessment need not move Notify at all.

K-104 is more careful upstream, but the base path reserves the same Wed 13:10 C1 start that happened factually, so the reservation does not change scheduling. The entire 1–2 h gain is a shorter final review. The path never shows C1’s preliminary work, yet it spends scarce C1 time as if S1’s early packet were that work. The post-assessment S1 shortening is off the critical path because final review still waits until Wednesday.

Smaller defects add up. The partial order uses `Esc/Prelim > Tri` against a `<` means “precedes” convention. The K-104 pilot excludes materially incomplete packets, which removes the main failure mode the pilot should measure. Assumption 5 is labeled quality while its first claim is a service-time effect. The ranking is defensible on reversibility and compliance, but its benefit column repeats the overstated K-411 base and therefore overstates how robust that intervention is in realized cycle time.
