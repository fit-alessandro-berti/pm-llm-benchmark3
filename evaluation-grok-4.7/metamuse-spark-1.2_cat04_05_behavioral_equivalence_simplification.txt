The central comparison is right: A places one `Check Revision` inside every loop iteration, B places exactly one `Check Revision` in parallel with the whole loop, the visible languages are incomparable, P1 and the P3 bound therefore fail, and P2 holds only after the stated collapse. The four table traces really do separate the languages, and the bounded-vs-unbounded warning is the right one. The write-up is not reliable beyond that.

The P1 predicate is misstated. The task only requires each analysis to have its own check before the next `Rework Case` or `Close Case`. Model A’s `+` also allows `Check` before `Analyze`. Requiring `Analyze_i < Check_j` rejects compliant A traces. The B1 gloss is false on its own trace: `Check` sits before `Rework`, so the first analysis is not the uncovered one; the single check cannot cover the second analysis before `Close`. The later claim that keeping `Approve Revision` is necessary to witness the difference contradicts A2 and the approval-free form of B2. The projected pattern is also described as feasible in A when that projection still has two analyses and one check.

N2 is a valid negative trace for the simplification, but the reason is wrong. `*(body, redo)` executes `body` once, and `+` does not make the loop optional, so B cannot emit `Open Case, Check Revision, Close Case`.

Section 7 reports a “direct run” that was not performed. Both trees have 12 nodes (5 operators and 7 leaves), 6 visible leaves and 1 `tau`. Root-to-leaf node depth is 5 for A and 6 for B, because B’s `+` wraps the loop. The stated 11/10 nodes, equal depth 5, “≈10–12 places”, and simplicity scores 0.66, 0.68, and 0.75 are invented. For exactly two iterations the bounded visible languages have 16 traces in A (4 bodies × 4 bodies) and 20 in B (4+5+5+6 check slots), not 8 and 12. A2 has length 7, not 6. The “more minimal” tree is the same tree as `S`, and `S` has 11 nodes and the same depth as A, so the simplicity comparison does not match the models.

The BFS is not exhaustive as written. Keying markings by `p.name` merges the unnamed places that tree-to-net conversion produces, so distinct markings collide. The fallback enablement test treats arcs as places. Footprints are correctly called insufficient, but `+(a,b)` and `X(->(a,b),->(b,a))` have the same language, so that pair does not show equal footprints hiding different languages. Infinite loop languages are ignored for the stochastic API.

`S` is a sound P1-oriented compromise and a subset of A, and the preservation table does admit the lost interleavings. Calling that “exact P1” and assigning it fabricated simplicity scores overstates what was shown. Notation is repeatedly stripped to empty backticks, including the language-inclusion claims.
