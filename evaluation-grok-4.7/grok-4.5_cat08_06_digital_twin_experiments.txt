7.3

The design covers every required section and respects the hard constraints: non-stationary arrivals, shared calendars, endogenous resource coupling, a service/wait split, latent rather than fake objections, and no optimality claim. PM4Py use is on the right side of the API (`pandas` I/O, `format_dataframe`, `parse_process_tree`, variants, DFG, performance DFG). The gaps below are why this is not a high score.

**Estimation and internal consistency.** Month multipliers average about 1.35 and hour multipliers about 0.74, with “normalize later” never applied. If `base_rate` is the log’s overall mean, volume is wrong as soon as either factor is corrected. Complex-variance public notice is required by the problem statement but coded as 0.90. Variant shares partition to 100% and account for all simple renovations in the clean and missing-docs groups, so a uniform inspection-rework probability of 0.09 contradicts the simple-case rows. Zipf(α=1.2) is not shown to reproduce the top-20 architects’ 31% share. Routing numbers are labeled as estimates and then hardcoded.

**Waiting time and long-run measurement.** Municipal delay is described as queueing delay, but the parameter object still allows “wait residuals” as inputs. That double-counts congestion and makes interventions look weaker than a pure DES. Cycle-time KPIs use only cases that finish before an unsized truncation buffer. Complex cases have a p90 of about 260 days, so an 18-month horizon with a buffer long enough to protect that tail leaves a short, seasonally unbalanced sample, and no censoring estimator is specified. The simulation clock is a float hour index; council weeks, holidays, and month effects need an absolute calendar origin that is never defined.

**Decision rules.** SLA cutoffs (30/90/120/180 days) are not checked against the empirical medians and p90s. Simple renovations with missing documents already have a p90 of 45 days, so a 90% within-30-days rule may be infeasible at baseline and would reject every policy. The cost rule still contains an undefined “X.” `norm()` in the composite score is undefined, so the weights are not on a common scale. “Interaction gain ≥ 50% of the sum of standalone gains” is ambiguous and, read as synergy, is an extreme bar that would almost never select D10. Pairwise CIs versus baseline ignore multiplicity across D1–D10 and several KPIs.

**Experiment and validation design.** As-is geographic grouping is a stated process fact, but baseline batching is off and only D3 turns it on, so D3’s incremental value is inflated. Common random numbers are not reconciled with D1 and D7, which change the arrival process itself. A 12/6 month holdout is not checked against which peak seasons fall in the test window. D8 never says whether triage means a shorter service time, a priority queue, or a skip. Planning and legal rework have probabilities but no return state, so the control flow past the tree is incomplete.

**Skeleton.** The excerpt is reduced to one event, so variants, the DFG, and the arrival rate are vacuous. `is_on_shift` returns true, which contradicts the calendar design. Simple-only planners, the Monday portal clerk, holiday closures, and the peak-month inspector never affect capacity. D4–D8 are flags only. `apply_d2_policy` is never called, and the decision-join note omits “results that apply,” which deadlocks skipped inspections if implemented literally. Public notice is stored as a service duration. Stress rows S1–S5 and the steady-state control are absent from the experiment grid. Dead imports and bare `except` hide API failures.

The architecture is the right kind of twin. The parameter logic, decision thresholds, and skeleton do not yet implement that architecture consistently enough to rank these policies.
