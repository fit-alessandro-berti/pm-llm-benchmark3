The case-level judgments are largely correct and carefully hedged: aliases are normalized before SoD, Eva’s later title is not backdated onto CHG-507, weekend status is not treated as Asha’s absence, D-IC-04 is rejected as prohibited subdelegation, CI-44 and the safety rationale are not inferred from a cooling-system flag, service accounts are attributed differently, and repeated Clara–Ben work is not called collusion. The checking code is not at the same standard. `filter_four_eyes_principle` is called without stating that the default keeps compliant cases, and CHG-503 is a different resource token, so that filter reports independence where the narrative correctly says unknown. Handover and working-together results are printed as graph objects, so the required network evidence is not actually shown. Emergency approval logic can only see IC authority, would pass a standing IC without the safety-rationale test the prose requires, and relies on hardcoded case IDs. `prohibited_subdelegation` means “this row is an invalid onward delegation,” which the name does not say. CHG-506 is treated as substantively valid if Ben acted, without weighing Asha’s same-morning VPN session against D-QM-01’s absence condition. CHG-501 is both “high confidence” and still dependent on an unauthenticated PDF. The conclusion enumerates buckets but does not directly answer how much of the pattern is authority failure versus identity or organizational risk.
