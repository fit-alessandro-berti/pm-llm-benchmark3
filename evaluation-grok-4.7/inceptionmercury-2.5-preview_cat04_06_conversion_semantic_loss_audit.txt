3.5

The write-up has the right document skeleton and a few sound high-level choices, but it misstates source behavior, ships conversion and trace-exploration code that does not implement the stated PM4Py interface, and then labels unchecked expectations as validated. Those are core failures for an invariant and round-trip audit, not polish issues.

**Baseline.** The invariant table is incomplete and, in places, semantically wrong. Assess Risk then Prepare Evidence is legal, yet the join row’s negative witness is only the telegraphic phrase “Trace after Ass before Prep,” which does not exhibit verification starting before both predecessors. The silent XOR branch is a required positive behavior; listing `[..., Ass, skip, ...]` as a negative witness inverts optionality. Unordered Assess/Prepare is given only one order and “N/A” as the negative witness. Absent entirely are the causal facts that decide whether a process tree can exist: no order between Prepare Evidence and the legal XOR, no order between that XOR and the verification loop, Configure Trial before Inspect Trial on every iteration, Correct Defect only as the redo separator, at least one trial body, and Archive Change as the unique visible end. “Observable after hiding tau? Yes (as skip)” treats a hidden transition as if it remained visible.

**Pipelines.** POWL → accepting Petri net → BPMN as primary, with process-tree conversion allowed to fail, is the right pair. The primary failure condition is still wrong: “None if net is workflow sound” equates soundness with semantic fidelity, which this task explicitly rejects. The secondary risk is only “lacks hierarchy,” without naming the asymmetric partial order (verification waits for Assess and Prepare; legal waits only for Assess; release waits for both).

**Conversion code.** `convert_to_petri_net` is required to produce `net_from_powl`, `im_from_powl`, and `fm_from_powl`. The code instead stores one return value and looks for `.initial_marking` / `.final_marking`. Markings are then passed through as `None`. The tree-to-BPMN call passes those Petri markings into `convert_to_bpmn` after the code itself notes that this signature is uncertain. Only one BPMN model is converted back. Workflow-net and soundness checks do not cover every accepting net, ignore `None` markings, and ignore the Boolean results. Saves omit the source POWL view and the round-trip nets, and use `.bpmn` / `.xml` paths on visualization helpers. The process-tree exception is printed as “expected” without an interpretation.

**Audit.** Several cells say `validated preserved` although nothing was executed. The same tree step is both `lost` and `conversion failed`. Silent optionality is marked `lost (merged)` in BPMN with no evidence, conflating hidden routing with a changed language. Allowed terms are also replaced by `N/A` and parentheticals. Label uniqueness, binary loop shape `trial_body (correct_defect, trial_body)*`, initial/final marking equality, and the missing legal–verification edge are not actually audited. The prose claim that a BPMN loop may admit zero iterations unless “flags” are set is unsupported.

**Round-trip code.** The explorer cannot fire a transition: `net.input_places` is not a PM4Py Petri-net API. A visited set of markings, even if markings were hashable (`Marking` is a `Counter` and is not), deletes every later path to the same marking, so Assess∥Prepare and legal∥verification interleavings are dropped. The bound counts silent steps, not visible length or loop iterations, and the write-up never says whether the bounded comparison is exhaustive. Footprints are computed and never compared. Reachability graphs, positive and negative witness traces, and playout are omitted. A mismatch is mislabeled “not exhaustive equivalence.”

**Visual review and rejection.** Some layout warnings are real, but the gateway discussion reverses the model: the XOR is explicit choice, and the release and verification joins are real synchronizations. Annotations are two vague notes. Rejection item 5 is false for this loop: a faithful footprint must allow a later Configure Trial after an earlier Inspect Trial once Correct Defect has occurred. That rule would quarantine a correct net. Loss of a required interleaving is not a rejection condition.

**Canonical form and residuals.** POWL as the editable source, with Petri and BPMN as regenerated derivatives and the process tree barred from authority, is the best section. It still omits version pinning, witness archives, and a rule that a tree picture of a subgraph must not stand in for the whole model. The residual list cites time, data, and readability. It does not include the limits that remain even after these tests pass: bounded search versus unbounded redo, visible-trace equality versus true concurrency, tau-hiding versus distinct silent routings, or soundness versus language equivalence.
