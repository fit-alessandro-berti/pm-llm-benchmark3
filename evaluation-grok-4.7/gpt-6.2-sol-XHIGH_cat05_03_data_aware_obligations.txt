8.4

The case dispositions are the right ones, and the temporal model is unusually careful. All eleven release states are reconstructed correctly. R1 is applied only on non-DE amounts of at least 100,000, with equality included (TX-308). Increases are measured against the latest review baseline and only above 20 percent (TX-301 56.25 percent, TX-309 24.21 percent then 22.88 percent, TX-306 about 4.55 percent). Decreases do not invalidate (TX-308). TX-305 refuses to copy the next-day 150,000 settlement backward. TX-307 correctly rejects a standard-packet approval as a substitute for Enhanced_Review. EX-77 is separated from EX-88 by signature time versus certificate-creation time and an interested witness. TX-311 uses `(timestamp, event_index)` and correctly notes that reversing the two 16:20 events would not change the release result, because the release jurisdiction would still be DE. Sections 4, 6, and 7 are specific, and the code forward-fills, re-sorts on `event_index`, keeps settlement and late exemption rows out of the release snapshot, and emits `REVIEW_REQUIRED` instead of a classification lookup.

The required findings table is broken for two cases. TX-303 and TX-304 each have nine populated cells: the confidence value is missing, the decisive-evidence text sits in Confidence, and Decisive evidence is empty. That is a required-column failure, not a styling quibble.

Materiality is wider than the rules. R4 defines amount invalidation. The write-up also treats every known change of risk or customer type as a material change that stales an R1 review. That can false-fail an otherwise current foreign high-value review. It does not flip any of these eleven cases, and it is disclosed, but the code implements the broad version through `last_material`.

The R4 diagnostic does not match the stated invariant. The prose says a later Standard_Review must not refresh an earlier Enhanced_Review. `r1_review` preserves that, because it compares the enhanced review with `last_material`. The `r4` flag compares `last_material_amount` with `last_review`, which includes a later Standard_Review, so it can report `NO_INVALIDATION` while R1 is still stale. No supplied trace hits that path.

Smaller defects: TX-304 lists the pre-addition screen as a satisfied obligation when it is only the premise of the rescreen duty; R4 is sometimes written into “Triggered rules” as commentary; and the optional trace-order check is absent, with the control-flow argument left entirely to section 6. The unproven-waiver path also turns a missing Enhanced_Review into `UNKNOWN` whenever `verified_approval` is empty. That matches the chosen INDETERMINATE reading of TX-310, but it is softer than R5’s “effective only if” test and is not distinguished in the code from a merely missing record.
