# 1. Assumptions and notation

**Notation.** For case *i*: `a_i` = external arrival at S1; `b1_i`, `e1_i` = S1 start/end; `b2_i`, `e2_i` = S2 start/end. Queue entry to S2 is `e1_i` (given by the scenario). Definitions used throughout:

- S1 wait `W1_i = b1_i − a_i`; S1 active service `S1_i = e1_i − b1_i`; S1 sojourn `T1_i = e1_i − a_i = W1_i + S1_i`.
- S2 wait `W2_i = b2_i − e1_i`; S2 active service `S2_i = e2_i − b2_i`; S2 sojourn `T2_i = e2_i − e1_i`.
- Case total sojourn `T_i = e2_i − a_i = T1_i + T2_i`.
- Horizon `H = [08:00, 14:00]`, length 360 min. Censoring time `τ = 14:00`.

**Assumptions.**

- **A1 (rounding model).** Every reported timestamp `t` is the rounding-to-5-min of an unobserved true time in `[t−2.5, t+2.5]`. Rounding errors of distinct timestamps are treated as independent and uniform. Consequence: any *duration* computed as a difference of two reported timestamps carries an additive error in `[−5, +5]` min (worst case), with s.d. ≈ 2.04 min if independent-uniform. I therefore report durations to the nearest 5 min and never claim resolution finer than ±5 min on a single duration. Errors partially cancel in aggregates (mean of *n* durations has s.d. ≈ 2.04/√n).
- **A2 (event-order convention at ties).** When two reported times coincide, the logical order is: *service completion* → *queue entry at the next station* → *service start* → *external arrival*. That is, at a tied instant a departure is counted **before** an arrival ("departure-first"). Under A2 a case that ends S1 at *t* and would start S2 at *t* is never counted twice. Because ties are an artefact of rounding, I also report the opposite ("arrival-first") convention wherever it changes an integer count; it moves peak WIP by at most 1.
- **A3 (capacity).** S1 has exactly 2 single-task servers (I1, I2), S2 exactly 2 (C1, C2). C2's capacity is 0 during [10:55, 11:10] (15 min). No hidden third server is assumed unless the log forces one (it does not: no resource ever shows overlapping intervals once imputations respect A5).
- **A4 (work conservation, *assumed, testable*).** A server that is idle and has a non-empty queue starts the next case "immediately", where immediately means *after a ~5-minute changeover*. Evidence: in every fully observed case where the same resource works back-to-back, the next start equals the previous end **+5 min** (I1: 08:25→08:30, 08:55→09:00; I2: 08:35→08:40, 09:10→09:15, 09:45→09:50, 10:20→10:25, 10:55→11:00, 11:30→11:35, 12:35→12:40 …; C1: 09:00→09:05, 11:40→11:45, 12:10→12:15, 13:00→13:05; C2: 10:05→10:10, 12:00 → next start 12:15 (10), 12:25→12:30). So effective per-server cycle = service + 5 min changeover. This assumption is used only for *central* imputations, never for bounds.
- **A5 (MISSING start).** MISSING means the activity happened; its start is unobserved. Hard feasibility bounds for a missing start `b`:
  `b ≥ max(queue-entry time, last end of the same resource + 0)` and `b ≤ reported end` (nonnegative service), and `b ≤` next start of the same resource. Central estimate = earliest feasible start **+5 min** changeover if that is the binding constraint (A4), otherwise the queue-entry time; I additionally report the interval midpoint as an alternative central value. No missing start is silently replaced by one number.
- **A6 (OPEN activity).** OPEN = started, not finished by τ. Only *elapsed* service `τ − b` is observed; it is a **lower bound** on final service time. Final service is estimated by residual-life reasoning against the empirical service distribution of the same station, and such cases are excluded from any "mean completed service time".
- **A7 (blank = still queueing).** A blank S2 pair with a completed S1 means the case was in the S2 queue at τ: its S2 wait is right-censored at `τ − e1`. Blank S1 (P22) means the S1 wait is right-censored at `τ − a`.
- **A8 (no bypass, no rework).** Every case must traverse S1 then S2 exactly once; a case is "in system" from `a_i` until `e2_i` (or until τ if not finished).
- **A9 (arrival process).** The 22 external arrivals are the complete arrival stream in the window. Arrivals stop at 12:10; I treat the absence of arrivals after 12:10 as real (not truncation), while flagging that it could equally be an extraction artefact — this materially affects the "S1 drains" conclusion.
- **A10 (FIFO is *not* assumed).** The log contains at least one order inversion at S2 (P17, S1-end 12:50, starts S2 at 13:55 while P16, S1-end 12:35, is still waiting). Queue discipline is therefore treated as "approximately FIFO with exceptions", and waiting-time bounds are derived from resource availability, not from an assumed order.
- **A11 (utilization denominator).** Utilization is computed over each server's *exposure window* (from its first observed start to τ, minus documented outage), and separately over the full 6 h horizon. Both are reported because the choice changes the number by ~5–10 pp.

# 2. Reconstruction method and formulas

**Waiting / service / sojourn.** As defined in §1. For a MISSING start the pair (wait, service) is reported as an *interval* `[W_lo, W_hi]` / `[S_lo, S_hi]` linked by the identity `W + S = T` where `T` (the sojourn) is **fully observed** (both endpoints are recorded). This is the key structural fact of this data set: *missing starts destroy the wait/service split but not the sojourn.* Consequently every sojourn-based quantity (station sojourn, case total sojourn, WIP, Little's Law) is imputation-invariant; only wait-vs-service decompositions and busy-time/utilization are imputation-sensitive.

**Bound construction for a MISSING start `b` of case *i* on resource *r*:**
```
b_lo = max( queue_entry_i , last_end_of_r_before(e_i) )      # no overlap, no start before eligibility
b_hi = min( e_i , next_start_of_r_after(e_i) )               # nonnegative service, no overlap
b_central = b_lo + 5   (changeover, A4)   [alt: (b_lo+b_hi)/2]
```
Rounding (A1) widens each bound by 2.5 min on each side; I quote the ±5 min on derived durations rather than re-quoting every bound.

**Right censoring.** For OPEN service: elapsed `= τ − b`, final `≥ τ − b`. For queue-blocked cases: wait `≥ τ − e1`. Aggregates over censored quantities are reported as **lower bounds** (naïve mean) plus a **Kaplan–Meier-style / residual-life corrected** upper commentary; I do not mix censored and complete observations into a single "mean" without flagging it.

**WIP and queue length.** Step functions built from signed events under A2:
- `WIP_system(t) = #{i : a_i ≤ t} − #{i : e2_i ≤ t}`
- `Q1(t) = #{i : a_i ≤ t} − #{i : b1_i ≤ t}` (waiting for S1, excludes in-service)
- `L1(t) = Q1(t) + #in service at S1`; analogously `Q2`, `L2` with queue entry `e1_i`.
Time averages are areas divided by interval length.

**Throughput / rates.** `arrival rate = #arrivals / duration`; `departure (throughput) rate` per station = completions of that station per duration, computed on hourly bins `[h, h+1)`.

**Busy time / utilization.** `busy_r = Σ (end − start)` over that resource's activities, with OPEN counted as elapsed-to-τ (a lower bound on eventual busy time but the correct value for *busy time within the window*). `ρ_r = busy_r / available_r`. Station utilization = `Σ_r busy_r / Σ_r available_r`. Changeover time is *not* counted as busy (it is reported separately as a 5-min-per-service overhead, i.e. an effective-capacity reduction).

**Little's Law.** Used in the finite-horizon *area identity* form
`L̄ · Δ = Σ_i (time case i spends in the subsystem during Δ) = λ̄ · Δ · W̄`,
i.e. `L̄ = λ̄ W̄` holds exactly when (a) all in-window time is counted, including partial (censored) time for cases still present at τ, and (b) `W̄` is the mean *in-window* time per case counted, not the mean completed sojourn. I apply it only in that form, and only to S1 over the full window and to S2 over [08:25, 14:00] (from the first S2 queue entry). I explicitly do **not** claim a steady-state Little's Law: the system is transient (queues grow monotonically), so the classical `L = λW` with completed-case means would be biased downward by censoring.

**Estimate tiers.** *Lower* = every unknown pushed to its most favourable feasible value (shortest waits, shortest services, earliest starts); *Central* = A4 work-conserving + 5-min changeover, OPEN services extended by the station's median service; *Upper* = every unknown pushed to its least favourable feasible value.

# 5. Bottleneck and temporal interpretation

**Observation (not hypothesis) — capacity arithmetic.**
- S1: 2 servers × (28 min service + 5 min changeover) ⇒ effective capacity ≈ **3.6 cases/h**. Realised S1 throughput 3.3/h.
- S2: 2 servers × (40 min service + 5 min changeover) ⇒ effective capacity ≈ **2.7 cases/h** (≈2.6/h once the 15-min outage is amortised over the window). Realised S2 throughput 2.8/h over 09:00–14:00.
- Arrivals during the loaded period 08:00–12:10 ≈ **5.3/h**.

So `λ(5.3) > μ_S1(3.6) > μ_S2(2.7)`. **Both stations are overloaded during the arrival burst; S2 is the structurally tighter constraint.**

**Observation — queue evidence over time.**
- 08:00–09:30: S1 waits grow 5 → 40 min while S2 waits stay 5–15 min. In this phase the *only* visible constraint is S1: S2 is starved-then-fed and never accumulates a queue. **Apparent bottleneck: S1.**
- 09:30–11:30: S1 waits grow to ~75; S2 waits jump from ~25 to 50–55. Both queues grow. The C2 outage (10:55–11:10) lands exactly here and adds a discrete step (P08 alone loses ~20–25 min; P09/P10 inherit shifted C1 starts).
- 11:30–14:00: arrivals stop at 12:10. S1 drains: its queue falls from ~7 to 1 and its waits plateau at ~100 rather than continuing to grow. S2 does **not** drain: its queue is 4 and rising at τ, with 2 more cases in service and 0 completions expected before ~14:15. **Bottleneck: unambiguously S2.**

**Interpretation.** The evidence is most consistent with a **time-varying bottleneck whose long-run identity is S2**:
1. Early, S1 is the *gating* station simply because it is first — it is the only station that has seen the arrival burst. This is a *positional* effect, not a capacity verdict, and is the classic trap of reading "which queue is longest right now".
2. The capacity numbers, the persistent divergence of cumulative counts (20 S1 completions vs 14 S2 completions ⇒ **6 cases permanently accumulated between the stations**), and the fact that S2's queue keeps growing after arrivals stop are three independent lines of evidence that S2 is the true constraint. The inter-station buffer growing monotonically is the decisive signature.
3. S1's high measured waits (up to 105 min) are therefore *demand-driven and transient*: with arrivals halted, S1 would clear its backlog in ~30 min, whereas S2 needs ≈(4 queued + 2 in service) × 45/2 ≈ 2¼ more hours.

**The maintenance interval — evidence vs hypothesis.**
- *Evidence*: C2 has no activity spanning 10:55–11:10; P06 ended at 10:50 and C2's next start is 11:15 (= outage end + 5 changeover); P08 waited 55 min, the first large S2 wait; C1's queue was simultaneously non-empty, forcing P09 ahead of P08.
- *Bounded impact*: the outage removes 15 server-minutes ≈ 0.33 of a service ⇒ at most **~1 lost S2 completion**, and directly ~20–25 min of extra wait for P08 plus ~5–10 min knock-on for P09–P11.
- *Hypothesis (not proven)*: the outage is **not** the cause of the S2 backlog. Even with C2 fully available, S2 capacity (2.7/h) would still have been below S1's delivery rate (3.3/h); the backlog would be ~5 instead of ~6 cases. Counterfactual: removing the outage advances the final S2 completions by roughly 15–20 min, which does not change any qualitative conclusion.

**Secondary evidence — discipline anomalies.** Two order inversions (P09 before P08; P17 before P16) and one work-conservation violation (I2 idle 13:45–14:00 with P22 waiting). Hypotheses, in decreasing plausibility: resource-case affinity/fixture compatibility; logging latency at the extraction boundary; ad-hoc prioritisation. These affect individual case waits by tens of minutes but not station-level throughput conclusions.

**Little's Law consistency check (applied only where defensible).** I use the finite-horizon area identity, which requires no stationarity — only complete accounting of in-window time including censored cases.
- **S1, 08:00–14:00**: total in-station time = 2085 case-min ⇒ `L̄ = 5.79`; `λ̄ = 22/360 = 0.0611/min`; `W̄ = 2085/22 = 94.8 min`; `λ̄W̄ = 5.79`. ✔ (exact, since sojourns use only observed endpoints — **this check is completely invariant to the P07/P15 start imputations**).
- **S2, 08:25–14:00**: total in-station time = 1340 case-min over 335 min ⇒ `L̄ = 4.00`; `λ̄ = 20/320 = 0.0625/min` (queue entries 08:25–13:45); `W̄ = 1340/20 = 67.0 min`; `λ̄W̄ = 4.19`. Agreement to **5%**, the residual being the boundary effect (the last queue entry is 15 min before τ). ✔
- **Where I refuse to apply it**: any steady-state `L = λW` using *completed-case* mean sojourns. With 6 of 20 S2 sojourns censored and queues monotonically increasing, that form would report `W̄ = 70` (completed only) against a true in-window mean and would misstate `L` by ~15–20%. Also not applied per-hour, where boundary flows dominate.

# 6. Missingness, censoring, and sensitivity analysis

**What is missing/censored.** 3 MISSING starts (P07 at S1; P05, P11 at S2), 3 OPEN services (P21 at S1; P15, P17 at S2), 1 MISSING start *combined with* an OPEN downstream service (P15), 5 never-started activities (P16, P18–P20 at S2; P22 at S1), and universal ±2.5 min rounding.

**Scenario definitions.**
- **Optimistic (O)** — every missing start as *late* as feasible (short services, long waits already counted elsewhere is minimised): P07 `b1=10:00` (svc 0), P05 `b2=10:15` (svc 0), P11 `b2=12:25` (svc 0); OPEN services assumed to end immediately after τ; rounding pushed to shorten all durations by 5 min.
- **Central (C)** — A4 work-conserving with 5-min changeover: P07 `b1=09:30` (svc 30, wait 45), P05 `b2=09:45–09:50` (svc 25–30, wait 20–25), P11 `b2=12:00–12:05` (svc 20–25, wait 55–60), P15 `b1=11:45` (svc 30, wait 95); OPEN services completed at the station median (S1 30, S2 40) from their start.
- **Pessimistic (P)** — every missing start as *early* as feasible (long services): P07 `b1=09:25` (svc 35), P05 `b2=09:45` (svc 30), P11 `b2=12:00` (svc 25), P15 `b1=11:40` (svc 35); OPEN services take the station 90th percentile (S1 35, S2 50); rounding lengthens all durations by 5 min.

| I2 utilization (6 h) | 0.74 | 0.81 | 0.89 | Stable (no MISSING on I2) |
| C1 utilization (exposure) | 0.73 | 0.88 | 0.94 | Moderately stable |
| C2 utilization (exposure) | 0.72 | 0.85 | 0.95 | Moderately stable |
| S1 mean wait (min) | 76 | 71 | 69 | Stable |
| S2 mean wait, completed only (min) | 44 | 39 | 37 | Stable but **censoring-biased low** in all scenarios |
| S2 mean wait, censoring-adjusted | ≥48 | 55–65 | ≥75 | Level uncertain, **sign of trend stable** |
| Mean system WIP | 9.5 | 9.5 | 9.5 | **Invariant** (depends only on arrivals and S2 ends) |
| Peak WIP | 12 | 12–13 | 13 | Invariant ±1 (tie convention only) |
| S1 throughput (/h) | 3.3 | 3.3 | 3.3 | **Invariant** |
| S2 throughput (/h) | 2.8 | 2.8 | 2.8 | **Invariant** |
| μ_S1 − μ_S2 (capacity gap) | +0.6/h | +0.9/h | +1.1/h | **Sign invariant** |
| Bottleneck verdict | S2 | S2 | S2 | **Invariant** |

**Conclusions that are stable under every scenario:**
1. S2 is the structural bottleneck; the inter-station buffer grows monotonically (6 cases accumulated) and never recovers within the window. This follows from counts alone (20 vs 14 completions) and cannot be altered by any imputation.
2. Both stations run at high utilization (≥0.7 in the most optimistic case) — the system has essentially no slack, so waiting times are extremely sensitive to any further disruption.
3. Waiting times, not service times, dominate sojourn: at S2 the mean wait (39–65) is comparable to or larger than the mean service (40), and at S1 wait is ~2.5× service.
4. The system is **transient, not in steady state**; reporting "average waiting time" without a time axis is misleading.
5. The C2 outage is a second-order effect (≤1 lost completion).

**Conclusions that are NOT stable / must be hedged:**
1. **I1's utilization** (0.61–0.83): two of its ten activities have unknown starts. Any claim that "I1 is less loaded than I2" is imputation-dependent and should not be used for staffing decisions.
2. **The true mean S2 waiting time**: censoring is heavy (30% of S2 sojourns incomplete) and, crucially, *informative* — the censored cases are exactly the ones with the longest waits. Any completed-case mean is a lower bound. I would report "≥44 min, plausibly 55–65 min" rather than a point value.
3. **Whether P05's and P11's S2 services were genuinely short** or whether the servers idled first. The service-distribution argument (0–15 min services would be unprecedented) favours the early-start/long-service reading, but this is inference, not observation.
4. **P22's status** — whether S1 truly violated work conservation, or the log was extracted mid-transaction. This changes P22's wait by ~10 min and I2's utilization by ~4 pp; it does not change any station conclusion, but it does change whether one should investigate a scheduling defect.
5. **Anything after 14:00.** Projected completion of the 8 in-flight cases (~2¼ h to clear S2 at 2.7/h) assumes no further arrivals — assumption A9, which is itself unverifiable from this extract.

**Rounding-specific sensitivity.** Because all timestamps are 5-min-rounded, individual durations carry ±5 min worst-case error — i.e. a reported 5-min wait is consistent with 0, and a reported 25-min service with 20 or 30. This makes *per-case* claims weak but *aggregate* claims strong: the mean of the 20 S1 services has a rounding s.d. of ≈0.5 min, negligible against the 4-min sample s.d. Rounding also manufactures ties (e.g. the P07-end / P09-queue-entry alignment), which is why the tie convention A2 is stated explicitly and why peak-WIP is reported as a 12–13 range rather than a single integer.

# ---------------------------------------------------------------- 2. status-aware parsing
# Three distinct non-times must NOT collapse to NaT-with-the-same-meaning:
#   MISSING -> event happened, timestamp unrecorded  (imputable within bounds)
#   OPEN    -> event started, not yet finished at TAU (right-censored)
#   ""      -> event never happened by TAU            (right-censored in queue)
def parse(v):
    """returns (timestamp_or_NaT, status) with status in {OBS, MISSING, OPEN, NONE}"""
    if v == "":
        return pd.NaT, "NONE"
    if v == "MISSING":
        return pd.NaT, "MISSING"
    if v == "OPEN":
        return pd.NaT, "OPEN"
    return pd.Timestamp(DAY + v), "OBS"

for col in ["arrival_s1", "s1_start", "s1_end", "s2_start", "s2_end"]:
    parsed = df[col].map(parse)
    df[col + "_ts"] = [p[0] for p in parsed]
    df[col + "_st"] = [p[1] for p in parsed]

print("=== status matrix (counts) ===")
print(pd.DataFrame({c: df[c + "_st"].value_counts()
                    for c in ["arrival_s1", "s1_start", "s1_end", "s2_start", "s2_end"]}
                   ).fillna(0).astype(int))

M = lambda td: td / pd.Timedelta(minutes=1)   # timedelta -> minutes

# ---------------------------------------------------------------- MISSING-start bounds (A5)
def missing_start_bounds(case, station):
    """Feasibility interval for an unrecorded start, from resource + queue constraints."""
    r = df.set_index("case").loc[case]
    res = r[f"{station}_resource"]
    end = r[f"{station}_end_ts"]
    entry = r["arrival_s1_ts"] if station == "s1" else r["s1_end_ts"]
    # last completion of the same resource strictly before this activity's end
    same = df[(df[f"{station}_resource"] == res) & (df["case"] != case)]
    prev_ends = same.loc[same[f"{station}_end_ts"] < end, f"{station}_end_ts"].dropna()
    next_starts = same.loc[same[f"{station}_start_ts"] > end, f"{station}_start_ts"].dropna()
    lo = max([entry] + ([prev_ends.max()] if len(prev_ends) else []))
    hi = min([end] + ([next_starts.min()] if len(next_starts) else []))
    central = min(lo + pd.Timedelta(minutes=5), hi)   # A4: 5-min changeover
    return lo, central, hi

MISSING_STARTS = [("P07", "s1"), ("P15", "s1"), ("P05", "s2"), ("P11", "s2")]
bounds = []
for case, st in MISSING_STARTS:
    lo, ce, hi = missing_start_bounds(case, st)
    end = df.set_index("case").loc[case, f"{st}_end_ts"]
    bounds.append(dict(case=case, station=st.upper(),
                       start_lo=lo.time(), start_central=ce.time(), start_hi=hi.time(),
                       svc_min=M(end - hi), svc_central=M(end - ce), svc_max=M(end - lo)))
bnd = pd.DataFrame(bounds)
print("\n=== MISSING-start feasibility intervals (minutes of service) ===")
print(bnd.to_string(index=False))
BND = bnd.set_index(["case", "station"])

# ---------------------------------------------------------------- 3./4. PM4Py interval log
# Only *usable* observations: an interval event needs both endpoints. We take the
# CENTRAL imputation for MISSING starts and clip OPEN ends at TAU, and we tag each
# row so nothing pretends to be fully observed.
rows = []
for _, r in df.iterrows():
    for st, act in [("s1", "Incoming Inspection"), ("s2", "Calibration")]:
        s_st, e_st = r[f"{st}_start_st"], r[f"{st}_end_st"]
        if s_st == "NONE" and e_st == "NONE":
            continue                                   # never happened -> no event
        s = r[f"{st}_start_ts"]
        if s_st == "MISSING":
            s = pd.Timestamp(DAY + "00:00") + pd.Timedelta(0)  # placeholder, set below
            lo, ce, hi = missing_start_bounds(r["case"], st)
            s = ce
        e = r[f"{st}_end_ts"] if e_st == "OBS" else TAU        # OPEN -> clipped at TAU
        rows.append(dict(**{"case:concept:name": r["case"], "concept:name": act,
                            "start_timestamp": s, "time:timestamp": e,
                            "org:resource": r[f"{st}_resource"]},
                         quality=("observed" if s_st == "OBS" and e_st == "OBS"
                                  else ("imputed_start" if s_st == "MISSING" else "right_censored"))))
ev = pd.DataFrame(rows)
log = pm4py.format_dataframe(ev, case_id="case:concept:name", activity_key="concept:name",
                             timestamp_key="time:timestamp", start_timestamp_key="start_timestamp")
print("\n=== PM4Py interval log: %d events, quality mix ===" % len(log))
print(log["quality"].value_counts().to_string())

# ---------------------------------------------------------------- 5. station quantities
rec = []
for _, r in df.iterrows():
    c = r["case"]
    row = dict(case=c)
    # ---- S1
    if r["s1_end_st"] == "OBS":
        row["S1_sojourn"] = M(r["s1_end_ts"] - r["arrival_s1_ts"])
    if r["s1_start_st"] == "OBS":
        row["S1_wait_lo"] = row["S1_wait_hi"] = M(r["s1_start_ts"] - r["arrival_s1_ts"])
        end = r["s1_end_ts"] if r["s1_end_st"] == "OBS" else TAU
        row["S1_svc_lo"] = M(end - r["s1_start_ts"])
        row["S1_svc_hi"] = row["S1_svc_lo"] if r["s1_end_st"] == "OBS" else np.nan
    elif r["s1_start_st"] == "MISSING":
        b = BND.loc[(c, "S1")]
        row["S1_wait_lo"] = M(pd.Timestamp(DAY + str(b.start_lo)) - r["arrival_s1_ts"])
        row["S1_wait_hi"] = M(pd.Timestamp(DAY + str(b.start_hi)) - r["arrival_s1_ts"])
        row["S1_svc_lo"], row["S1_svc_hi"] = b.svc_min, b.svc_max
    else:                                              # P22: never started
        row["S1_wait_lo"] = M(TAU - r["arrival_s1_ts"]); row["S1_wait_hi"] = np.inf
    # ---- S2
    if r["s1_end_st"] == "OBS":
        entry = r["s1_end_ts"]
        if r["s2_start_st"] == "OBS":
            row["S2_wait_lo"] = row["S2_wait_hi"] = M(r["s2_start_ts"] - entry)
            end = r["s2_end_ts"] if r["s2_end_st"] == "OBS" else TAU
            row["S2_svc_lo"] = M(end - r["s2_start_ts"])
            row["S2_svc_hi"] = row["S2_svc_lo"] if r["s2_end_st"] == "OBS" else np.inf
        elif r["s2_start_st"] == "MISSING":
            b = BND.loc[(c, "S2")]
            row["S2_wait_lo"] = M(pd.Timestamp(DAY + str(b.start_lo)) - entry)
            row["S2_wait_hi"] = M(pd.Timestamp(DAY + str(b.start_hi)) - entry)
            row["S2_svc_lo"], row["S2_svc_hi"] = b.svc_min, b.svc_max
        else:

        if r["s2_end_st"] == "OBS":

    rec.append(row)

    [df.set_index("case")["state"].str.contains("MISSING").values,

    ["missing_start", "open_service", "queue_censored"], "complete")

d = df.set_index("case")
wip = []

    b1   = count(d["s1_start_ts"], t)          # NOTE: MISSING starts excluded -> Q1 upper bound

# ---------------------------------------------------------------- busy time & utilization
util = []
for st, servers, outage in [("s1", ["I1", "I2"], {}), ("s2", ["C1", "C2"], {"C2": 15.0})]:
    for res in servers:

        busy_c = busy_lo = 0.0
        for _, r in sub.iterrows():
            end = r[f"{st}_end_ts"] if r[f"{st}_end_st"] == "OBS" else TAU
            if r[f"{st}_start_st"] == "OBS":

print(U.round(2).to_string(index=False))

# ---------------------------------------------------------------- rates by subperiod
bins = pd.date_range(T0, TAU, freq="1h")
rate = pd.DataFrame({
    "arrivals": pd.cut(d["arrival_s1_ts"], bins, right=False).value_counts().sort_index(),
    "S1_completions": pd.cut(d["s1_end_ts"], bins, right=False).value_counts().sort_index(),
    "S2_completions": pd.cut(d["s2_end_ts"], bins, right=False).value_counts().sort_index()})

print(rate.to_string())

# ---------------------------------------------------------------- Little's Law (area identity)
def little(entry, exit_, t_start, t_end, label):
    ent = entry.dropna(); ent = ent[(ent >= t_start) & (ent <= t_end)]
    area = 0.0
    for c, e in ent.items():
        x = exit_.get(c, pd.NaT)
        x = min(x, t_end) if pd.notna(x) else t_end        # censored: count time up to TAU
        area += M(x - e)
    span = M(t_end - t_start); n = len(ent)
    L, lam, W_ = area / span, n / span, area / n
    print(f"{label}: L={L:.2f}  lambda={lam*60:.2f}/h  W={W_:.1f}min  lambda*W={lam*W_:.2f}")
print("\n=== Little's Law, finite-horizon area identity (no stationarity assumed) ===")
little(d["arrival_s1_ts"], d["s2_end_ts"], T0, TAU, "SYSTEM 08:00-14:00")
little(d["arrival_s1_ts"], d["s1_end_ts"], T0, TAU, "S1     08:00-14:00")
little(d["s1_end_ts"],     d["s2_end_ts"], pd.Timestamp(DAY+"08:25"), TAU, "S2     08:25-14:00")
# NOT applied per-hour or with completed-case means: queues grow monotonically and
# 30% of S2 sojourns are right-censored, so a steady-state L=lambda*W would be biased.

# ---------------------------------------------------------------- 6. sensitivity scenarios
scen = {}
for name, pick in [("optimistic", "hi"), ("central", "ce"), ("pessimistic", "lo")]:
    s1, s2 = [], []
    for case, st in MISSING_STARTS:
        b = BND.loc[(case, st.upper())]
        v = {"hi": b.svc_min, "ce": b.svc_central, "lo": b.svc_max}[pick]
        (s1 if st == "s1" else s2).append(v)
    obs1 = [M(r["s1_end_ts"] - r["s1_start_ts"]) for _, r in df.iterrows()
            if r["s1_start_st"] == "OBS" and r["s1_end_st"] == "OBS"]
    obs2 = [M(r["s2_end_ts"] - r["s2_start_ts"]) for _, r in df.iterrows()
            if r["s2_start_st"] == "OBS" and r["s2_end_st"] == "OBS"]
    adj = {"optimistic": -5, "central": 0, "pessimistic": +5}[name]   # rounding worst case
    scen[name] = dict(mean_S1_service=np.mean(obs1 + s1) + adj,
                      mean_S2_service=np.mean(obs2 + s2) + adj,
                      eff_cap_S1_per_h=2 * 60 / (np.mean(obs1 + s1) + adj + 5),
                      eff_cap_S2_per_h=2 * 60 / (np.mean(obs2 + s2) + adj + 5))
S = pd.DataFrame(scen).T
S["bottleneck"] = np.where(S.eff_cap_S2_per_h < S.eff_cap_S1_per_h, "S2", "S1")
print("\n=== scenario sensitivity (effective capacity includes 5-min changeover) ===")
print(S.round(2).to_string())

# VALID PROJECTION ONLY: cases that fully completed BOTH stations with observed
# starts. On this projection pm4py's case-level semantics (case service time =
# sum of activity durations; case waiting time = case duration - service time)
# are exactly what we want. They are CASE-LEVEL, *not* station-level: they cannot
# tell us S1-queue vs S2-queue waiting, which is why the pandas work above exists.
ok = [c for c in d.index if d.loc[c, "s2_end_st"] == "OBS"
      and d.loc[c, "s1_start_st"] == "OBS" and d.loc[c, "s2_start_st"] == "OBS"]
proj = pm4py.format_dataframe(ev[ev["case:concept:name"].isin(ok)].copy(),
                              case_id="case:concept:name", activity_key="concept:name",
                              timestamp_key="time:timestamp", start_timestamp_key="start_timestamp")
proj = pm4py.insert_case_service_waiting_time(proj, start_timestamp_key="start_timestamp")
proj = pm4py.insert_case_arrival_finish_rate(proj, start_timestamp_key="start_timestamp")
kpi = (proj.groupby("case:concept:name")[["@@service_time", "@@waiting_time",
                                          "@@arrival_rate", "@@finish_rate"]].first() / 60.0)
kpi.columns = ["case_service_min", "case_waiting_min", "arrival_gap_min", "finish_gap_min"]
print("\n=== PM4Py CASE-LEVEL KPIs (projection of %d fully observed cases) ===" % len(ok))
print("   [case-level, NOT station-level: waiting here is total inter-activity idle time]")
print(kpi.round(1).to_string())
print(kpi.mean().round(1).to_dict())

# ---------------------------------------------------------------- 7. convert_log_to_time_intervals
# We DO call it, but only for the coarse system-level picture:
try:
    iv = pm4py.convert_log_to_time_intervals(proj, start_timestamp_key="start_timestamp")
    print("\n=== convert_log_to_time_intervals: inter-activity gaps (S1end -> S2start) ===")
    print(iv.head(5).to_string())
except Exception as e:                                    # keep the script runnable
    print("\nconvert_log_to_time_intervals unavailable:", e)
# WHY the station-specific pandas computation above is the primary instrument:
#  (1) convert_log_to_time_intervals works on the *projected* log, i.e. it silently
#      drops the MISSING/OPEN/never-started activities -- exactly the cases that
#      carry the information about the S2 backlog. Using it alone would infer
#      utilization and waiting from completed cases only (the survivorship trap).
#  (2) It has no notion of a censoring horizon: a case still queueing at 14:00
#      contributes no interval at all, rather than a lower bound.
#  (3) It cannot express interval-valued (lo, hi) durations for imputed starts.
#  (4) Resource availability constraints (C2's 10:55-11:10 outage, no-overlap per
#      server) are outside its model, yet they are what bounds the missing starts.
