## 1. Normalization Assumptions

### True-Time Interpretation and Clock-Offset Model
Let the true physical occurrence time of an event in UTC be $t^* \in \mathbb{R}$. When an event is recorded by source system $S$, the source system emits a displayed or stored timestamp $R_{\text{disp}}$. 

1. **Resolution and Display Uncertainty Interval**: Due to clock quantization, display truncation, or sensor sampling, the internal source clock reading $R_{\text{clock}}$ at the moment of capture lies in a discretization interval:
   $$R_{\text{clock}} \in [R_{\text{low}}, R_{\text{high}}]$$
2. **Clock Offset Correction**: Source clock offset is defined as $\delta = R_{\text{clock}} - t_{\text{local}}^*$, where $t_{\text{local}}^*$ is the true local wall-clock time. If system diagnostics bound the offset such that $\delta \in [a, b]$, the true local event time is obtained by subtracting the offset:
   $$t_{\text{local}}^* = R_{\text{clock}} - \delta \implies t_{\text{local}}^* \in [R_{\text{low}} - b, R_{\text{high}} - a]$$
3. **Time-Zone and UTC Transformation**: If the source operates in a local time zone with UTC offset $\Delta_{\text{TZ}}$ (taking daylight saving time rules and active folds into account), true UTC time is:
   $$t^* = t_{\text{local}}^* - \Delta_{\text{TZ}} \implies t^* \in [R_{\text{low}} - b - \Delta_{\text{TZ}}, R_{\text{high}} - a - \Delta_{\text{TZ}}]$$
   As mandated, timestamp-resolution uncertainty is applied prior to clock-offset correction.

## 3. Certain/Possible/Indeterminate Findings

### Classification Criteria
- **SLA Rule Evaluation**: For a maximum duration $S_{\max}$, an interval $[D_{\min}, D_{\max}]$ is:
  - `CERTAIN_PASS` if $D_{\max} \le S_{\max}$;
  - `CERTAIN_VIOLATION` if $D_{\min} > S_{\max}$;
  - `POSSIBLE_VIOLATION` if $D_{\min} \le S_{\max} < D_{\max}$.
- **Temporal Profile Evaluation**: For a two-sided tolerance band $[L_\zeta, U_\zeta] = [\mu - \zeta\sigma, \mu + \zeta\sigma]$:
  - `CERTAIN_PASS` if $D_{\min} \ge L_\zeta$ and $D_{\max} \le U_\zeta$ (wholly inside);
  - `CERTAIN_VIOLATION` if $D_{\max} < L_\zeta$ or $D_{\min} > U_\zeta$ (wholly outside);
  - `POSSIBLE_VIOLATION` if the interval partially overlaps the boundaries.
- **Baseline Acceptance Regions**:
  - **S1**: $\le 900\,\text{s}$ ($15\,\text{min}$)
  - **S2**: $\le 2700\,\text{s}$ ($45\,\text{min}$)
  - **S3**: $\le 129600\,\text{s}$ ($36\,\text{h}$)

  - **TP2 (IS $\to$ CC)**: $[1500, 2700]\,\text{s}$ ($\zeta=1$)
  - **TP3 (AR $\to$ CC)**: $[1980, 3420]\,\text{s}$ ($\zeta=1$)

## 7. Governance Recommendation

To ensure auditability, regulatory compliance, and legally defensible SLA enforcement across distributed IT/OT architectures, the organization must implement the following governance controls:

```
===================================================================================
                       INCIDENT RESPONSE TEMPORAL GOVERNANCE
===================================================================================
1. DATA ARCHITECTURE      UTC Only | ISO 8601:2019 / RFC 3339 | Millisecond Precision
2. CLOCK SYNCHRONIZATION  NTP/PTP Stratum 1/2 | Max Drift < 100ms | Continuous Offsets
3. AUDIT ENVELOPE         Raw String + Source Timezone + Fold Flag + Clock Uncertainty
4. LIFECYCLE MODEL        Mandatory Start & Complete Events | W3C Distributed Tracing
5. ENFORCEMENT POLICY     Conservative Enforcement (Certain Violations Only for Penalty)
===================================================================================
```

---

### Governance Policies and Technical Specifications

1. **Mandatory Storage and Serialization Standards**:
   - All persistence layers, event buses (Kafka, RabbitMQ), and data warehouses must serialize timestamps exclusively in **UTC ISO 8601:2019 / RFC 3339 format** with explicit fractional seconds and `Z` suffix:
     $$\text{Example: } \texttt{2026-06-01T08:14:15.123Z}$$
   - Direct storage of local wall-clock time without an explicit offset or fold indicator is prohibited across all production systems.

2. **Immutable Raw Payload and Provenance Retention**:
   - To guard against clock misconfigurations and daylight saving discrepancies, ingestion pipelines must retain an immutable **Temporal Provenance Envelope** alongside the normalized UTC timestamp:
     ```json
     {
       "event_id": "evt-8839102",
       "activity": "Investigation_Start",
       "normalized_utc_interval": {
         "start": "2026-06-01T08:12:00.000Z",
         "end": "2026-06-01T08:16:30.000Z"
       },
       "provenance": {
         "source_system": "OPS-BER",
         "raw_recorded_string": "2026-06-01 10:14",
         "source_timezone": "Europe/Berlin",
         "tz_offset_minutes": 120,
         "dst_fold": 0,
         "resolution_semantics": "floor_to_minute",
         "clock_sync": {
           "protocol": "NTP",
           "last_sync_utc": "2026-06-01T07:45:00Z",
           "offset_bound_ms": [-90000, 120000],
           "stratum": 2
         }
       }
     }
     ```

3. **Clock Synchronization and Telemetry Controls**:
   - All on-premise and cloud servers must synchronize against redundant Stratum 1/2 NTP/PTP servers with maximum polling intervals $\le 64\,\text{s}$.
   - System daemons (`chrony`/`systemd-timesyncd`) must emit continuous drift and dispersion metrics into the central observability platform. Any system exceeding $\pm 100\,\text{ms}$ clock drift must raise an automated operational alert.
   - For external vendors and mobile devices where continuous synchronization cannot be enforced, ingestion gateways must append server-side arrival timestamps and round-trip ping telemetry to bound transit latency.

4. **Lifecycle and Event State-Machine Standards**:
   - Operational procedures must forbid inferring task initiation from completion timestamps. All operational activities spanning $> 1\,\text{minute}$ must explicitly emit discrete lifecycle transitions:
     $$\texttt{ASSIGNED} \longrightarrow \texttt{STARTED} \longrightarrow \texttt{CONTAINED} \longrightarrow \texttt{CLOSED}$$
   - Mobile and web incident management interfaces must capture user event times via system-level monotonic timers (`clock_gettime(CLOCK_MONOTONIC)`) at the moment of button press, recording both `event_timestamp` and `transmission_timestamp` to decouple user latency from occurrence time.

5. **Causal Tracking and Distributed Tracing**:
   - Implement **W3C Trace Context** (`traceparent`, `tracestate`) across all alert notifications and incident ticketing systems.
   - Alerts transmitted across networks must mandate bidirectional handshakes: an `Alert_Sent` event must be paired with an authenticated `Alert_Acknowledged` event containing the correlated `trace_id`.

6. **Contractual and Legal SLA Enforcement Policy**:
   - **Strict Conformance Principle**: Contractual penalties, regulatory breach reporting, and vendor chargebacks must be legally enforceable only upon **`CERTAIN_VIOLATION`** findings ($D_{\min} > \text{SLA}_{\max}$).
   - **Evidential Escalation for Possible Violations**: Any case classified as `POSSIBLE_VIOLATION` ($D_{\min} \le \text{SLA}_{\max} < D_{\max}$) must trigger an automated **Evidential Discovery Workflow** to retrieve supplementary forensic logs (NTP logs, network packet captures, database commit logs) prior to final compliance sign-off.
   - **Prohibition of Point-Estimate Approximations**: Internal audits must formally ban replacing uncertain timestamp intervals with midpoints or arbitrary floor/ceiling values, ensuring all compliance reporting transparently reflects measurement bounds.
