  * An Object-Centric Petri Net (OCPN) is a **type-level** model discovered from flattened projections per object type, where places are typed by object types and arcs are normal or variable (double-headed) arcs connecting places to activity transitions. **Individual object instances (`V1`, `O100`, `O200`, `M1`, `M2`) are tokens, not nodes/places in the Petri net.** Furthermore, places do not connect directly to other object instances; transitions (`Issue Invoice`, `Record Payment`) sit between typed places.
* **OTG Misconception:** You describe the OTG (Object Type Graph) as having transitions like `Order -> Item (via Add Item, Reserve Stock, Pack Package)`. While ET-OT links event types to object types, an OTG connects object types based on object interactions/relations. Because `Confirm Delivery` only touches `Delivery`, it doesn't create an edge in the OTG at all.
