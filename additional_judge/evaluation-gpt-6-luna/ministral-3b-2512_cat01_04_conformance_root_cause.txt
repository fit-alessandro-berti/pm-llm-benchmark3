The June–July conformance collapse has a strong measurement explanation. The UI renamed `Classify`, the gateway added `Queue Routed`, and ETL switched `Decision` and `Notify` to ingestion timestamps. The staged alignment results isolate these mechanisms: label mapping, event removal, and source ordering each improve fit. These corrections do not explain everything. `Manual Override` remains, and some enhanced-review traces lack a recorded compliance check.

August–September adds a separate model and behavior question. The sign-off policy changed the required process for claims above EUR 50,000, but the model stayed unchanged. The candidate model’s improved fit supports model obsolescence, though optional sign-off alone cannot represent the threshold rule. The 30 enhanced-review traces without a check remain unresolved.

Stable cycle time, approvals, and appeals weaken the case for a large system-wide operational disruption, but they do not establish that the process was compliant. Case mix may differ, appeals are an imperfect proxy, and incident detection is incomplete. Conversely, a missing event in a trace does not establish a bypass. Distinguishing operational concern from conformance measurement requires case-level policy applicability, source-event provenance, and an audit of whether the required action actually occurred.

## 6. PM4Py reproduction and model-comparison code

```python
from collections import Counter
import pandas as pd
import pm4py
from pm4py.objects.conversion.process_tree import converter as pt_converter
from pm4py.objects.conversion.log import converter as log_converter
from pm4py.objects.process_tree.utils import generic as tree_generic
from pm4py.objects.petri_net.utils import alignments
from pm4py.objects.petri_net.utils import petri_utils

# The supplied normative tree:
# Receive, Classify, then either:
#   (a) Standard Review with zero or more Request Info loops, or
#   (b) Enhanced Review followed by Compliance Check,
# then Decision, Notify.
normative_tree = pm4py.parse_process_tree(
    "->( 'Receive', 'Classify', "
    "X( *( 'Standard Review', 'Request Info' ), "
    "->( 'Enhanced Review', 'Compliance Check' ) ), "
    "'Decision', 'Notify' )"
)
normative_net, normative_im, normative_fm = pt_converter.apply(normative_tree)

# A control-flow candidate with optional sign-off after the existing process.
# This is only an aggregate comparison model. It does not encode the EUR 50,000
# threshold; that requires case-attribute stratification or a data-aware model.
candidate_tree = pm4py.parse_process_tree(
    "->( 'Receive', 'Classify', "
    "X( *( 'Standard Review', 'Request Info' ), "
    "->( 'Enhanced Review', 'Compliance Check' ) ), "
    "'Decision', 'Notify', *( 'Supervisor Sign-off' ) )"
)
candidate_net, candidate_im, candidate_fm = pt_converter.apply(candidate_tree)

# Input CSV must contain case_id, activity, timestamp, source_sequence, and any
# available case attributes (for example claim_amount and high_value).
df = pd.read_csv("events.csv")
df["timestamp"] = pd.to_datetime(df["timestamp"], utc=True)

def to_event_log(frame):
    event_df = frame.rename(columns={
        "case_id": "case:concept:name",
        "activity": "concept:name",
        "timestamp": "time:timestamp",
    }).copy()
    return pm4py.convert_to_event_log(event_df)

def normalize(frame, order_by_sequence=True, remove_queue=True):
    out = frame.copy()
    out["activity"] = out["activity"].replace({"Risk Screen": "Classify"})
    if remove_queue:
        # Apply only after provenance confirms Queue Routed is technical.
        out = out[out["activity"] != "Queue Routed"]
    if order_by_sequence:
        # Preserve source sequence as the authoritative ordering field.
        out = out.sort_values(["case_id", "source_sequence"], kind="stable")
    else:
        out = out.sort_values(["case_id", "timestamp"], kind="stable")
    return out

corrected = normalize(df)
log = to_event_log(corrected)

# Inspect variant frequencies and a frequency DFG.
variants = pm4py.get_variants(log)
variant_counts = Counter(
    tuple(event["concept:name"] for event in trace)
    for trace in log
)
print("Variants:", variant_counts.most_common(30))

dfg, starts, ends = pm4py.discover_dfg(log)
print("Frequency DFG:", dfg)

def alignment_summary(event_log, net, im, fm):
    aligned = pm4py.conformance_diagnostics_alignments(
        event_log, net, im, fm
    )
    costs = [item["cost"] for item in aligned if item is not None]
    fitting = sum(cost == 0 for cost in costs)
    return {
        "traces": len(costs),
        "fitting_percent": 100 * fitting / len(costs) if costs else float("nan"),
        "mean_cost": sum(costs) / len(costs) if costs else float("nan"),
        "alignments": aligned,
    }

normative_result = alignment_summary(
    log, normative_net, normative_im, normative_fm
)
candidate_result = alignment_summary(
    log, candidate_net, candidate_im, candidate_fm
)
print("Normative:", {k: v for k, v in normative_result.items() if k != "alignments"})
print("Candidate:", {k: v for k, v in candidate_result.items() if k != "alignments"})

# Fitness and precision; report separately by period and high-value stratum.
net, im, fm = normative_net, normative_im, normative_fm
print("Token replay fitness:", pm4py.fitness_token_based_replay(log, net, im, fm))
print("Precision:", pm4py.precision_token_based_replay(log, net, im, fm))

if "high_value" in corrected.columns:
    for value, group in corrected.groupby("high_value", dropna=False):
        stratum_log = to_event_log(group)
        print("High-value stratum:", value)
        print("Normative:", alignment_summary(
            stratum_log, normative_net, normative_im, normative_fm
        )["fitting_percent"])
        print("Candidate:", alignment_summary(
            stratum_log, candidate_net, candidate_im, candidate_fm
        )["fitting_percent"])

# Do not discard Manual Override without auditing its source and user meaning.
# Reconcile apparent missing Compliance Check events and sign-offs to source
# records before interpreting residual alignment moves as employee violations.
```

## 7. Provisional conclusion

The conformance drop is best explained by multiple measurement changes: the UI label replacement, the added `Queue Routed` event, and unreliable ordering after ETL began using ingestion timestamps. The supplied staged comparisons strongly support these explanations. They do not establish that all remaining deviations are harmless.

The August policy made the normative model incomplete for eligible high-value claims. Aggregate alignment cannot determine which cases required sign-off, and an optional sign-off model is only a rough control-flow approximation. Missing compliance checks and `Manual Override` actions remain operational questions, not proven violations. Stable business outcomes limit claims of broad deterioration but cannot rule out localized noncompliance, especially given incomplete incident detection.

## 8. Model-governance recommendation

Version normative models alongside policy changes, including threshold-dependent requirements where the mining method supports them. Preserve source timestamps and sequence numbers through ETL, and document event semantics and provenance for UI labels, gateway events, and user actions. Treat label mappings and event removal as governed transformations with validation evidence. Monitor fitness and precision by policy-relevant case strata, and audit residual deviations against source records before assigning responsibility to employees.
