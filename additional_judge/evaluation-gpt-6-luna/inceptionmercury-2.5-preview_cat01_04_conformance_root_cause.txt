## 3. Causal diagnosis

The apparent conformance collapse is best explained by several changes acting together. The UI label change creates a direct model-to-log mismatch, while `Queue Routed` adds a likely technical event. The ETL switch to warehouse-ingestion time can invert event order, and the source-sequence comparison supports that explanation. These are strong explanations for the June–July fitness decline, although the remaining deviations show they do not account for everything.

From August, the policy change makes the normative model incomplete. The improvement from 66% to 86% when optional sign-off is allowed is evidence that the model needs updating, but that candidate is only a control-flow approximation: the actual requirement depends on claim value. A model that allows sign-off everywhere could fit better while misrepresenting the policy.

There may also be real behavioral changes or noncompliance. Enhanced-review cases without a recorded compliance check and the use of `Manual Override` need investigation, but neither proves bypass. Stable approval and appeal rates modestly weaken the case for a widespread harmful change; they cannot rule it out because incident detection is incomplete and aggregates can conceal a high-risk subgroup.

The rankings are provisional. Confidence is highest in the existence of label, technical-event, and timestamp problems; moderate in model obsolescence; and lower in the extent of actual process change or employee noncompliance.

## 6. PM4Py reproduction and model-comparison code

```python
import pandas as pd
import pm4py
from pm4py.objects.process_tree.obj import ProcessTree
from pm4py.objects.process_tree import semantics
from pm4py.algo.conformance.alignments.petri_net import algorithm as alignments

# Define the normative tree structurally:
# ->(Receive, Classify, X(
#     *(Standard Review, Request Info),
#     ->(Enhanced Review, Compliance Check)
#   ), Decision, Notify)
def activity(name):
    return ProcessTree(label=name)

def node(operator, children):
    tree = ProcessTree(operator=operator)
    tree.children = children
    for child in children:
        child.parent = tree
    return tree

standard_loop = node(
    semantics.Operator.LOOP,
    [activity("Standard Review"), activity("Request Info")]
)
enhanced = node(
    semantics.Operator.SEQUENCE,
    [activity("Enhanced Review"), activity("Compliance Check")]
)
review_choice = node(semantics.Operator.XOR, [standard_loop, enhanced])
normative_tree = node(
    semantics.Operator.SEQUENCE,
    [
        activity("Receive"),
        activity("Classify"),
        review_choice,
        activity("Decision"),
        activity("Notify"),
    ],
)
net, initial_marking, final_marking = pm4py.convert_to_petri_net(normative_tree)

# Input CSV must contain case_id, activity, timestamp, and source_sequence.
# Preserve raw events; create a separate normalized copy for sensitivity analysis.
events = pd.read_csv("events.csv")
events["timestamp"] = pd.to_datetime(events["timestamp"])

def prepare_log(frame, map_label=False, drop_gateway=False, source_order=False):
    frame = frame.copy()
    if map_label:
        frame["activity"] = frame["activity"].replace({"Risk Screen": "Classify"})
    if drop_gateway:
        frame = frame[frame["activity"] != "Queue Routed"]
    if source_order:
        # Use the validated source sequence to establish within-case event order.
        frame = frame.sort_values(["case_id", "source_sequence"])
    else:
        frame = frame.sort_values(["case_id", "timestamp"])
    return pm4py.format_dataframe(
        frame,
        case_id="case_id",
        activity_key="activity",
        timestamp_key="timestamp",
    )

def compare(frame):
    log = prepare_log(frame)
    dfg, starts, ends = pm4py.discover_dfg(log)
    aligned = alignments.apply_log(
        log, net, initial_marking, final_marking
    )
    fitting = sum(result["fitness"] == 1 for result in aligned) / len(aligned)
    mean_cost = sum(result["cost"] for result in aligned) / len(aligned)
    return dfg, fitting, mean_cost

# Run each period separately and compare raw, mapped, filtered, and source-ordered
# variants. Keep the resulting logs and case-level alignments for audit.
for period, period_events in events.groupby("period"):
    print(period, compare(period_events))
```

## 7. Provisional conclusion

The strongest explanation for the initial collapse in measured conformance is the combined effect of changed activity labels, a newly recorded technical event, and unreliable event ordering. Each correction materially improves alignment, and the manual audit supports the label interpretation. The data do not support treating raw fitness as evidence of a sudden operational failure.

The normative model also became obsolete when the sign-off requirement took effect. The supplied tree cannot express its value threshold, so aggregate fitting against an optional-sign-off candidate is insufficient to establish policy compliance.

A genuine compliance problem remains possible. Missing recorded checks on enhanced reviews and override usage warrant targeted validation, but neither the traces nor the stable outcome summaries establish intentional bypass. The next conclusion should be based on case-level source records and a representative audit.

## 8. Model-governance recommendation

1. Version models alongside policy effective dates and UI releases.
2. Maintain a semantic contract distinguishing business activities, technical events, and display labels.
3. Preserve source timestamps and sequence identifiers; document event ordering and provenance in each conformance run.
4. Retain raw and normalized logs so mappings and exclusions are traceable and reproducible.
5. Report conformance by relevant case attributes, including policy thresholds, rather than relying only on aggregate control-flow fitness.
6. Validate audit-event completeness and resource attribution before interpreting deviations as employee behavior.
7. Compare candidate models on both fit and policy meaning; an optional branch must not substitute for an attribute-dependent rule.
