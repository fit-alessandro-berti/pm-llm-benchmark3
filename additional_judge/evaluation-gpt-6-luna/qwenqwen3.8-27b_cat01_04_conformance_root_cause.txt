The leading explanations for the measured conformance drop are recording and ordering changes. The remaining missing-check and override cases are separate operational concerns; the aggregates do not establish employee noncompliance.

The observed collapse is best read as a layered provenance problem, not a single behavioral failure. The UI release changed the recorded label from `Classify` to `Risk Screen`, so the model saw an unknown activity even though the business step may be unchanged. The gateway then inserted `Queue Routed`, a technical event that has no counterpart in the normative tree, increasing moves on log and event counts. The ETL switch to warehouse-ingestion time for `Decision` and `Notify` made some `Notify` events appear before `Decision`, producing reversed directly-follows edges and alignment penalties. When the label is mapped and the technical event is removed, fitness recovers substantially; when source sequence is used, it recovers further. This staged recovery is strong evidence that much of the measured deterioration is an artifact of recorded labels and recorded order.

At the same time, the August policy introduced `Supervisor Sign-off` for high-value claims while the model remained unchanged. The candidate optional sign-off model improves August–September fitness, showing that part of the remaining deviation is model obsolescence. `Manual Override` and enhanced reviews without a recorded compliance check may be real control-flow deviations, missing source events, or extraction defects. Stable approval rates, appeal rates, and reported incidents argue against a broad compliance collapse, but incomplete incident detection means they cannot prove that no reviewer bypassed checks. Therefore, unchanged business outcomes neither validate the data pipeline nor exonerate employees; they only reduce the prior probability of a widespread behavioral change.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py

NORMATIVE_PT_STRING = (
    "->('Receive','Classify',"
    "X(*('Standard Review','Request Info'),"
    "->('Enhanced Review','Compliance Check')),"
    "'Decision','Notify')"
)

# Allows zero or more sign-offs after either review branch and before Decision.
# This is a control-flow comparison model, not a policy-aware model.
CANDIDATE_PT_STRING = (
    "->('Receive','Classify',"
    "X(*('Standard Review','Request Info'),"
    "->('Enhanced Review','Compliance Check')),"
    "*('Supervisor Sign-off'),"
    "'Decision','Notify')"
)

LABEL_MAP = {"Risk Screen": "Classify"}
TECHNICAL_EVENTS = {"Queue Routed"}

APR_MAY = {
    "Receive,Classify,Standard Review,Decision,Notify": 380,
    "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,
    "Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify": 40,
}

JUN_JUL = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 270,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 145,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,
    "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
    "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 20,
}

AUG_SEP = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 210,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify": 150,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 90,
    "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify": 60,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 45,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 35,
}


def make_xes(variants):
    """Expand variant counts into a small XES string.

    For traces with Notify before Decision in the supplied order, the synthetic
    source sequence places Decision first. This represents the stated ordering
    issue for demonstration; it is not a substitute for the actual source data.
    """
    traces = []
    case_no = 0

    for trace, count in variants.items():
        events = [event.strip() for event in trace.split(",")]

        for _ in range(count):
            case_no += 1
            case_id = f"case_{case_no:06d}"
            event_xml = []

            for i, activity in enumerate(events):
                source_seq = i + 1
                if (
                    activity == "Notify"
                    and i + 1 < len(events)
                    and events[i + 1] == "Decision"
                ):
                    source_seq = i + 2
                if (
                    activity == "Decision"
                    and i > 0
                    and events[i - 1] == "Notify"
                ):
                    source_seq = i

                event_xml.append(
                    "<event>"
                    f"<key>concept:name</key><string>{activity}</string>"
                    "<key>lifecycle:transition</key><string>complete</string>"
                    f"<key>source:seq</key><int>{source_seq}</int>"
                    "</event>"
                )

            traces.append(
                "<trace>"
                f"<key>case:concept</key><string>{case_id}</string>"
                + "".join(event_xml)
                + "</trace>"
            )

    return "<log>" + "".join(traces) + "</log>"


def parse_log_string(xes_string):
    # Use the requested string parser; fall back to the XES parser on versions
    # where parse_event_log_string does not accept XES strings.
    try:
        return pm4py.parse_event_log_string(xes_string)
    except Exception:
        import io
        return pm4py.parse_xes(io.StringIO(xes_string))


def get_attr(obj, key, default=None):
    try:
        return obj.get(key, default)
    except Exception:
        try:
            return obj[key]
        except Exception:
            return default


def normalize_log(log, map_labels=True, remove_technical=True, source_order=False):
    """Apply explicit label, technical-event, and optional ordering rules."""
    traces = []

    for case in log:
        case_id = get_attr(case, "case:concept", "case")
        events = []

        for original_order, event in enumerate(case):
            activity = get_attr(event, "concept:name")
            if remove_technical and activity in TECHNICAL_EVENTS:
                continue
            if map_labels and activity in LABEL_MAP:
                activity = LABEL_MAP[activity]

            seq = get_attr(event, "source:seq", original_order + 1)
            events.append((original_order, seq, activity))

        if source_order:
            events.sort(key=lambda item: (item[1], item[0]))

        event_xml = []
        for i, (_, _, activity) in enumerate(events):
            event_xml.append(
                "<event>"
                f"<key>concept:name</key><string>{activity}</string>"
                "<key>lifecycle:transition</key><string>complete</string>"
                f"<key>source:seq</key><int>{i + 1}</int>"
                "</event>"
            )

        traces.append(
            "<trace>"
            f"<key>case:concept</key><string>{case_id}</string>"
            + "".join(event_xml)
            + "</trace>"
        )

    return parse_log_string("<log>" + "".join(traces) + "</log>")


def top_dfg_relations(log, limit=5):
    dfg_result = pm4py.discover_dfg(log, parameters={"variant": "frequency"})
    relations = getattr(dfg_result, "dfg", dfg_result)
    items = []

    for key, count in relations.items():
        if isinstance(key, tuple) and len(key) == 2:
            source, target = key
        else:
            source, target = str(key).split(" -> ", 1)

        if source in ("__start__", "__end__") or target in ("__start__", "__end__"):
            continue
        items.append(((source, target), count))

    return sorted(items, key=lambda item: item[1], reverse=True)[:limit]


def sample_log(log, sample_size=180):
    cases = list(log)
    if len(cases) <= sample_size:
        return log

    step = max(1, len(cases) // sample_size)
    sampled = cases[::step][:sample_size]
    try:
        return pm4py.EventLog(sampled)
    except Exception:
        return sampled


def alignment_metrics(log, model, sample_size=180):
    log_sample = sample_log(log, sample_size)

    try:
        alignments = pm4py.alignments.alignments(
            log_sample, model, parameters={"cost": 1.0}
        )
        fitness = pm4py.alignments.alignments_fitness(alignments)
        try:
            diagnostics = pm4py.alignments.alignments_diagnostics(alignments)
        except Exception:
            diagnostics = {}
        return fitness, diagnostics, len(log_sample)
    except Exception as exc:
        try:
            fitness = pm4py.fitness(log_sample, model)
        except Exception:
            fitness = None
        return fitness, {"alignment_error": str(exc)}, len(log_sample)


def precision_metric(log, model, sample_size=180):
    log_sample = sample_log(log, sample_size)

    try:
        try:
            precision_function = pm4py.precision.precision
        except AttributeError:
            precision_function = pm4py.precision

        try:
            return precision_function(
                log_sample, model, parameters={"variant": "replay"}
            )
        except Exception:
            return precision_function(log_sample, model)
    except Exception as exc:
        return f"precision_unavailable: {exc}"


normative_tree = pm4py.parse_process_tree(NORMATIVE_PT_STRING)
normative_net, initial_marking, final_marking = pm4py.convert_to_petri_net(
    normative_tree
)

candidate_tree = pm4py.parse_process_tree(CANDIDATE_PT_STRING)
candidate_net, candidate_initial_marking, candidate_final_marking = (
    pm4py.convert_to_petri_net(candidate_tree)
)

periods = [
    ("Apr-May", APR_MAY),
    ("Jun-Jul", JUN_JUL),
    ("Aug-Sep", AUG_SEP),
]

print("Period | condition | alignment fitness | top frequency DFG relations")
for period, variants in periods:
    raw_log = parse_log_string(make_xes(variants))
    mapped_log = normalize_log(
        raw_log, map_labels=True, remove_technical=True, source_order=False
    )
    ordered_log = normalize_log(
        raw_log, map_labels=True, remove_technical=True, source_order=True
    )

    raw_fitness, raw_diagnostics, raw_n = alignment_metrics(raw_log, normative_net)
    mapped_fitness, mapped_diagnostics, mapped_n = alignment_metrics(
        mapped_log, normative_net
    )
    ordered_fitness, ordered_diagnostics, ordered_n = alignment_metrics(
        ordered_log, normative_net
    )

    print(f"{period} raw, n={raw_n}: fitness={raw_fitness}")
    print(f"  DFG: {top_dfg_relations(raw_log)}")
    print(f"{period} mapped+technical removed, n={mapped_n}: fitness={mapped_fitness}")
    print(f"  DFG: {top_dfg_relations(mapped_log)}")
    print(
        f"{period} mapped+technical removed+source order, n={ordered_n}: "
        f"fitness={ordered_fitness}"
    )
    print(f"  DFG: {top_dfg_relations(ordered_log)}")
    print(f"  Raw alignment diagnostics: {raw_diagnostics}")
    print(f"  Mapped alignment diagnostics: {mapped_diagnostics}")
    print(f"  Ordered alignment diagnostics: {ordered_diagnostics}")

aug_log = parse_log_string(make_xes(AUG_SEP))
aug_normalized = normalize_log(
    aug_log, map_labels=True, remove_technical=True, source_order=True
)

norm_fitness, norm_diagnostics, _ = alignment_metrics(
    aug_normalized, normative_net
)
candidate_fitness, candidate_diagnostics, _ = alignment_metrics(
    aug_normalized, candidate_net
)
norm_precision = precision_metric(aug_normalized, normative_net)
candidate_precision = precision_metric(aug_normalized, candidate_net)

print("Aug-Sep model comparison")
print(
    f"Normative: fitness={norm_fitness}, precision={norm_precision}, "
    f"diagnostics={norm_diagnostics}"
)
print(
    f"Candidate optional-sign-off model: fitness={candidate_fitness}, "
    f"precision={candidate_precision}, diagnostics={candidate_diagnostics}"
)
print(
    "Caveats: the optional sign-off model is control-flow only. It cannot "
    "enforce the EUR 50,000 high-value condition or resource authorizations, "
    "and it may overgeneralize by allowing sign-off where policy does not require it."
)
```

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a confluence of logging and data-provenance defects, not a sudden organization-wide behavioral change. From June, the UI label `Classify` became `Risk Screen`, and the gateway added `Queue Routed`. The normative model did not know these labels, so raw alignment fell sharply. Mapping `Risk Screen` to `Classify` and removing `Queue Routed` recovered most of the lost fitness. The ETL change to warehouse-ingestion time for `Decision` and `Notify` created apparent `Notify`-before-`Decision` reversals; using the source sequence number recovered further. These staged improvements are the strongest diagnostic signal: the initial conformance drop is largely an artifact of recorded labels, technical events, and unreliable ordering.

A separate real compliance concern remains, but it is narrower and less certain. The August policy added `Supervisor Sign-off` for claims above EUR 50,000, while the model was not updated. The candidate optional sign-off model improves August–September fitness, indicating model obsolescence. However, an optional control-flow model cannot enforce the high-value condition, so it may overgeneralize. More importantly, 25 June–July and 30 August–September enhanced-review traces lack a recorded `Compliance Check`, and `Manual Override` appears in nontrivial counts. These may be true bypasses, missing source events, or extraction defects. Stable approval rates, appeal rates, and reported incidents argue against a broad noncompliance event, but incomplete incident detection prevents a clean exoneration.

Confidence is high, about 85%, that data, logging, and model obsolescence explain most of the measured drop; confidence is moderate, about 45–55%, that a real compliance issue exists in missing checks or overrides, pending source audit. IT should restore source-sequence ordering, add event-semantic mappings, classify verified `Queue Routed` events as technical, and audit resource and event provenance. Process owners should version the model against the policy date and stratify conformance by high-value status. Compliance should audit the missing-check and override cases against source files and monitor high-value claims. We must not yet claim that employees are noncompliant, that the process is safe, or that the current model is adequate. Nor should we claim the pipeline is reliable until source provenance is verified.

## 8. Model-governance recommendation

1. Version every normative model with an owner, policy reference, and effective date. Each conformance job must identify the model version applicable to its cases.
2. Maintain event-semantic contracts that define canonical activity, source system, lifecycle meaning, and semantic owner. Map UI and warehouse labels through those contracts.
3. Classify technical events explicitly. Exclude verified technical events from control-flow conformance or model them deliberately, with their status preserved in the event data.
4. Preserve source timestamps and sequence numbers end to end. Declare the ordering field used by conformance jobs; do not use warehouse-ingestion time as event order by default.
5. Evaluate attribute- and resource-dependent rules with data-aware constraints or stratified conformance. Do not present a control-flow-only model as enforcing claim-value or authorization requirements.
6. After UI, gateway, ETL, or policy releases, validate the pipeline and model against historical and new logs. Compare variants, DFGs, fitness, precision, and audited event provenance before updating the reporting baseline.
