# Bounded visible-trace exploration. Silent transitions (label=None) are hidden.
# A trace is complete only when the marking equals fm exactly.
def bounded_visible_traces(net, im, fm, max_visible_len=9, max_loop_iters=3):
    if im is None or fm is None:
        raise ValueError("Initial and final markings are required")
    visible_labels = {
        t.label for t in net.transitions if t.label is not None
    }
    results = set()
    seen_states = set()

    def enabled(marking):
        # PM4Py's public helper is used where supported.
        return pm4py.get_enabled_transitions(net, marking)

    def visit(marking, trace, loop_counts, silent_seen):
        state = (tuple(sorted((id(p), n) for p, n in marking.items())),
                 trace, tuple(sorted(loop_counts.items())))
        if marking == fm:
            results.add(tuple(trace))
            return
        if len(trace) >= max_visible_len:
            return

        # Prevent infinite silent cycling at a fixed visible prefix.
        silent_key = (tuple(sorted((id(p), n) for p, n in marking.items())),
                      tuple(trace), tuple(sorted(loop_counts.items())))
        if silent_key in silent_seen:
            return
        next_silent_seen = silent_seen | {silent_key}

        for t in enabled(marking):
            label = t.label
            next_trace = trace if label is None else trace + [label]
            if label is not None and label not in visible_labels:
                continue
            # Conservative loop bound: cap repeated visible activity labels.
            counts = dict(loop_counts)
            if label is not None:
                counts[label] = counts.get(label, 0) + 1
                if counts[label] > max_loop_iters:
                    continue
            new_marking = marking.copy()
            for arc in net.in_arcs:
                pass
            # Fire via PM4Py's transition execution helper when available.
            try:
                new_marking = pm4py.execute_transition(net, marking, t)
            except Exception:
                # Fallback to the Petri-net arc semantics.
                from pm4py.objects.petri_net.obj import Marking
                new_marking = Marking(marking)
                for arc in t.in_arcs:
                    new_marking[arc.source] -= arc.weight
                    if new_marking[arc.source] == 0:
                        del new_marking[arc.source]
                for arc in t.out_arcs:
                    new_marking[arc.target] += arc.weight
            visit(new_marking, next_trace, counts, next_silent_seen)

    visit(im, [], {}, set())
    return results

The code in Section 3 includes bounded visible-trace exploration and witness checks. It hides transitions labeled `None`, avoids silent cycles by tracking markings at each visible prefix, requires exact equality with the final marking, and caps visible trace length and repeated visible labels. This is a bounded approximation of loop iteration count, not a proof of an exact loop bound. Enumeration is exhaustive only within its stated visible-length and repeated-label bounds, and only if the PM4Py transition-execution helper behaves as assumed.

For stronger comparison, compute footprints for the source-derived and each round-tripped net, and compare relations over visible labels. Also compare the bounded trace sets directly. # 6. Visual-Semantics Review

Parallel gateways may appear to promise simultaneous work, while Petri-net traces expose sequential interleavings. An exclusive gateway may represent the optional Legal Review choice, but its silent path may render as an unlabeled routing node or disappear. The binary loop may be drawn as a loop around activities in a way that obscures that each iteration runs Configure Trial before Inspect Trial and that Correct Defect separates repeats.

Layout can make unordered branches look sequential: left-to-right placement and edge routing are visual choices, not source ordering. The synchronization before Release should be shown and explained as a join that waits for both the optional branch and the verification loop. Add a legend for parallel and exclusive gateways, label the empty legal path “skip legal review,” annotate “at least one verification iteration,” and state that layout does not imply order where no control-flow edge exists.

# 7. Rejection Criteria

Quarantine a conversion result if any of these occurs:

1. Workflow-net or soundness diagnostics fail, or cannot be run on a net with valid markings.
2. Initial or final marking is null, malformed, unreachable, or permits completion before Archive Change.
3. A positive interleaving witness is rejected, including either Assess/Prepare order or either Legal/verification order.
4. A forbidden trace is accepted: zero verification iterations, Inspect before Configure, Legal before Assess, or Archive before Release.
5. Release can occur before both the legal branch has resolved and the verification loop has completed.
6. Optional Legal Review is made mandatory, prohibited, or repeatable.
7. Activity labels are duplicated or remapped such that witness traces become ambiguous.
8. A bounded trace or footprint comparison finds divergence within its stated bounds.
9. Process-tree conversion throws an exception, or succeeds but its derived BPMN fails the invariant checks.
10. A BPMN rendering’s gateways or routing nodes cannot be interpreted well enough for stakeholder use.

# 8. Canonical Representation Recommendation

Keep the source POWL as the authoritative editable representation. Store the accepting Petri net with its initial and final markings as a validated executable derivative, linked to the source version. Use the BPMN from Pipeline A as a stakeholder visualization derivative; label it as generated and include its conversion and validation evidence.

A process tree should not be canonical. It may be retained as an exploratory derivative only if conversion succeeds and it passes the same invariant audit; a successful conversion alone is insufficient. Future edits should be made to POWL, then regenerate the Petri net and BPMN and rerun validation. Avoid editing a derivative and feeding it back as the new source without an explicit review, since that can introduce round-trip drift.

Each derivative should carry conversion logs, marking checks, workflow-net and soundness results, footprint comparisons, bounded trace and witness results, and the bounds and limitations of those checks.

# 9. Residual Uncertainty

1. Bounded trace comparison cannot prove equivalence for arbitrarily many loop iterations or unbounded visible trace lengths.
2. Visible interleaving traces cannot establish true concurrency or partial-order equivalence.
3. Tests on a Petri net reconstructed from BPMN do not prove every BPMN engine will interpret gateways, joins, or loops identically.
4. Hiding tau cannot establish that internal routing is identical or free of all possible silent divergence.
5. Structural and behavioral checks cannot validate stakeholder understanding of the rendered diagram or business rules absent from the source control-flow model.
