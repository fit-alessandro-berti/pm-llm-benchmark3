## 3. Causal and measurement decomposition

The 93% to 32% June–July fitness decline is a change in the measured log-to-model relationship; it does not establish that actual process conformance fell by the same amount. The evidence supports several overlapping measurement and governance effects.

- **Label mismatch:** `Classify` changed to `Risk Screen`; mapping the label raises fitting traces from 32% to 58%. The UI audit supports semantic continuity.
- **Technical-event inflation:** removing `Queue Routed` raises fitness from 58% to 81%. Its introduction by the event gateway and uneven presence make its inclusion in control-flow checking questionable.
- **Ordering distortion:** source-sequence ordering raises fitness from 81% to 89%. The ETL began using ingestion time for `Decision` and `Notify`, and screenshots support true decision-before-notification ordering in at least 11 cases.
- **Residual deviations:** after these corrections, `Manual Override` and enhanced-review traces without recorded checks remain. These could indicate real behavior, missing events, or additional semantic issues; the aggregate evidence does not discriminate among them.
- **Model obsolescence:** from August 1, sign-off became policy-required for high-value claims, but the model stayed unchanged. Allowing optional sign-off improves fitness from 66% to 86%, but this is not a valid compliance test because the model lacks the EUR 50,000 condition.
- **Outcome measures:** stable approval, appeal, and cycle-time aggregates modestly weaken a broad deterioration hypothesis, but they cannot rule out targeted or underdetected compliance gaps. The rise in missing resource data further limits attribution to employees.

## 4. What can and cannot be inferred

**Can be inferred:** The supplied evidence strongly supports that label, event-capture, and timestamp changes account for most of the June–July measured conformance drop. The August–September model omits a known policy step. Some enhanced-review traces lack a recorded check after the available preprocessing, and overrides occur.

**Cannot be inferred:** The logs do not establish whether those checks were actually skipped, whether override use was authorized, or whether the new sign-off policy was followed by the claims to which it applied. Aggregate stability does not demonstrate compliance or safety. Nor does improved fitness under an optional-sign-off model establish policy conformance: it permits sign-off regardless of claim value. No supplied evidence supports calling employee noncompliance systemic.

## 5. Diagnostic plan

1. **Reconstruct event provenance and order.** For a representative sample, join source-system events, gateway records, warehouse rows, and conformance input. Compare source timestamps, ingestion times, and sequence numbers; verify the `Risk Screen` mapping and `Queue Routed` semantics. Preserve the original records.
2. **Audit missing compliance checks.** Review all 25 June–July and 30 August–September enhanced-review traces, if feasible, against independent check records, user-interface histories, and source-system artifacts. Record whether the check occurred, whether its event was captured, and the case value and reviewer.
3. **Test policy applicability.** Join case value and policy effective date to sign-off events. Measure required sign-off completion among claims above EUR 50,000, and investigate sign-offs below the threshold rather than treating them as automatically valid or invalid.
4. **Review `Manual Override`.** Examine its source event, actor, authorization, reason, and routing outcome. Separate logging changes from actual user actions and compare use across reviewers and periods.
5. **Recompute conformance transparently.** Report raw and corrected results side by side, with each transformation documented. Stratify by period, case value, route, reviewer, and event-source completeness; compare the normative and candidate models without treating higher fitness alone as proof of compliance.
6. **Validate outcomes and sampling.** Check whether appeal and incident detection changed, and examine cycle time and approval by the same case strata. Use a representative audit design so that absence of detected incidents is not mistaken for proof of absence.

def to_log_string(variants):
    lines = []
    c = 0
    for tr, cnt in variants.items():
        acts = [a.strip() for a in tr.split(",")]
        for _ in range(cnt):
            c += 1
            lines.append(f"case:{c}:" + ",".join(acts))
    return "\n".join(lines)

logs = {
    period: pm4py.parse_event_log_string(to_log_string(variants))
    for period, variants in variant_tables.items()
}

# Diagnose DFGs
for period, log in logs.items():
    dfg, start_activities, end_activities = pm4py.discover_dfg(log)
    print(period, "DFG edges:", len(dfg))

def evaluate(log, net, im, fm):
    aligned = align_algo.apply(log, net, im, fm)
    return fitness_evaluator.evaluate(aligned, log, net, im, fm)

print("Raw Jun-Jul fitness:", evaluate(logs["Jun_Jul"], net, im, fm))

# Apply transparent label mapping and technical-event filtering.
def normalize(log, remove_queue=True):
    for trace in log:
        i = 0
        while i < len(trace):
            activity = trace[i]["concept:name"]
            if activity == "Risk Screen":
                trace[i]["concept:name"] = "Classify"
            if remove_queue and activity == "Queue Routed":
                del trace[i]
                continue
            i += 1
    return log

norm_jun = normalize(logs["Jun_Jul"], remove_queue=True)
print("Normalized Jun-Jul fitness:", evaluate(norm_jun, net, im, fm))

prec_cand = precision_algo.apply(aug_log, cand_net, cand_im, cand_fm)
print("Aug-Sep candidate fitness:", fit_cand, "precision:", prec_cand)

The evidence strongly indicates that logging, label, and timestamp changes caused most of the June–July measured conformance collapse. Sequential normalization raises fitness from 32% to 89%, while the UI audit and source screenshots support the proposed label and order corrections. The August–September model also became obsolete when sign-off was required for high-value claims; an optional-sign-off candidate improves fitness, but cannot assess whether the threshold rule was followed.

A compliance gap remains possible. The traces without recorded checks and the override events require case-level investigation. Stable aggregate outcomes reduce concern about broad deterioration but cannot rule out targeted noncompliance or incomplete incident detection.

## 8. Model-governance recommendation

1. Version normative models with effective dates, and update them when policy changes.
2. Define and version event semantics, including whether each event is a business action or a technical event.
3. Preserve source timestamps and sequence numbers; store warehouse-ingestion time separately.
4. Report conformance by relevant case attributes, including claim value, route, and event-source completeness.
5. Document and version every preprocessing rule, and retain raw-to-normalized trace mappings.
6. Audit persistent deviations against independent records before making claims about staff compliance or process safety.
