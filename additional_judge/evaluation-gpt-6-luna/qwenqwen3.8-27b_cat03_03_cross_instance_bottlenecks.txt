## 4. What flattening misses

- **Job viewpoint:** Makes each job’s activity sequence and aggregate durations visible. It can hide delays when events are linked only to a lot, tool, batch, or shipment; it may also duplicate a shared event across several jobs. A misleading conclusion is that jobs follow a broadly normal path and none is an outlier, so there is no meaningful waiting problem. The missing L7 events illustrate the risk.
- **Machine viewpoint:** Shows machine use, utilization, sequence, and gaps. It hides the job’s wait for a non-machine resource, batch partner, lot release, or shipment partner. A misleading conclusion is that moderate utilization and a 48-minute maximum CNC-2 gap rule out a serious constraint.
- **Batch viewpoint:** Shows the single cure as one event and its related jobs, machine, rack, and components. Flattening to one anchor type can obscure which partner’s readiness delayed the group, or repeat the shared event when projecting it onto several jobs. A misleading conclusion is that batch starts are timely because there are few batch events or the oven is not highly utilized.
- **Tool viewpoint:** Makes acquisition, release, cleaning, or calibration intervals visible if recorded. It can hide the job’s wait if there is no explicit wait event and can duplicate a shared hold when viewed through jobs. A misleading conclusion is that FIX-A or CAL-3 is not constraining because no `Wait for Tool` activity appears.
- **ComponentLot viewpoint:** Shows quarantine and release lifecycle events and linked components. It can hide which jobs are blocked if event-to-job relations are missing or inconsistently propagated. A misleading conclusion is that lot release is unrelated to job flow because it is absent from the Job flattening.
- **Shipment viewpoint:** Shows shipment creation, loading, and dispatch sequence. It hides the time an already packed job spends waiting for another consolidated job, especially when only shipment events are measured. A misleading conclusion is that shipment handling is fast because Create–Load–Dispatch takes a median 1.1 hours.

Low machine utilization can coexist with long job waiting when a job needs a shared tool, a released component lot, a batch partner, or a shipment partner. The machine may be free while the job is not eligible to use it.

## 8. Falsification and additional data

The leading batch/rack explanation would weaken if:

1. J1/J2 ready timestamps are placeholders or do not mean batch eligibility.
2. OVEN-1 was unavailable before 12:05 due to ramping, maintenance, or a scheduled window.
3. RACK-7 was unavailable for B1 until 12:05, making rack availability rather than partner synchronization the binding constraint.
4. B1 policy requires all three jobs, while J3’s late readiness arose from an upstream hold; the barrier may be real but not the root cause.
5. Components C1 or C3 had inspection or lot holds that prevented B1 from starting.
6. An earlier B1 start would simply transfer waiting to a downstream constraint, such as testing or shipment consolidation.
7. B1’s start time was fixed by a shift, recipe, or production schedule.

Useful additional data include validated definitions and sources for “ready” timestamps; oven and rack state timelines; batch capacity, recipes, and partial-batch policies; explicit wait-for-tool, wait-for-lot, wait-for-batch-partner, and wait-for-shipment-partner events; lot release reasons and override audits; test-tool states and calibration requirements; shipment windows and split-shipment rules; and job due dates, priorities, and quality outcomes.
