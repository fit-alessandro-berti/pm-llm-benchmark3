### Material flaws (why this cannot score high under hypercritical review)

**1. Section 9 contradicts Section 3 on the primary analysis (major)**  
Prose primary strategy: staged multi-state + treat missing outcome feeds as missing + IPCW / weighted likelihood under MAR-ish assumptions.  
Code reality:
```python
observed_targets = {..., "PENDING_90D"}  # excludes MISSING_OUTCOME_FEED
analysis_frame = model_frame.loc[model_frame["target"].isin(observed_targets)]
```
Missing-feed activated cases are **dropped**, i.e. complete-case analysis—the approach Sec. 3 spent pages rejecting. The final comment gestures at IPCW but nothing in the frame, weights, or split supports it. For a required “concrete enough to implement” skeleton, this is a core integrity failure, not a nit.

**2. Staged estimand vs single multiclass label (major design/code gap)**  
Sec. 1–3 sell  
\(P(\texttt{DEFAULT\_90D}\mid H_l)=P(A_{90}=1\mid H_l)\times P(D_{90}=1\mid A_{90}=1,H_l)\)  
and a two-stage competing-route then activated-default analysis.  
Sec. 9 only materializes one flat `target` string for what reads as multiclass supervised learning. No structure for:
- competing terminal process model,
- activated-only default model,
- recombination,
- separate censoring model on the activated branch.

The estimand in prose and the object in code are not the same object.

**3. Prefix / population mismatch (moderate–major)**  
Design: baseline score after `Application Started` for **all** valid applications; later \(K=1,2,3\) conditional on survival to that prefix.  
Code: only cases with \(\ge 3\) pre-barrier events enter `features` / `analysis_frame`. Short rejects/withdrawals—the bulk of non-activated mass—are structurally excluded from the only fitted table. That silently reintroduces selection related to “reached 3 events,” which the text warned against.

**4. Operational realism of the 90-day-from-landmark activation gate (moderate)**  
`DEFAULT_90D` requires activation **within 90 days after landmark \(l\)**, then 90-day performance. For early landmarks (especially \(K=1\) at start), if underwriting + fulfillment often exceeds 90 days, the positive pathway becomes extremely rare and many eventually-bad activated accounts are labeled `PENDING_90D`. Horizon sensitivity is mentioned, but there is no confrontation of whether the primary business quantity remains useful under realistic cycle times, nor any diagnostic plan for activation-time distribution vs landmark.

**5. Skeleton is thin where the design is ambitious (moderate)**  
Sec. 5 promises control-flow, queue/workload, rework loops, business-hour waits, historically referenced medians, etc.  
Code features are essentially: a few static fields, event count, distinct activities, document-request count, elapsed hours, last risk score.  
`get_prefixes_from_log` / `discover_dfg` are QA ornaments, not feature generators. No as-of queue load, no loop-duration features, no training-only variant encodings, no repaired resource experience. Acceptable only if sold as a stub; relative to the claimed pipeline it over-promises.

**6. Temporal validation: prose A, code B (moderate)**  
Sec. 7 specifies forward-chaining, freeze-at-backtest-date, `label_available_at` gating, policy-transition stress set, migration as diagnostics-only until later extract.  
Code: one crude split on `case_start` (train &lt; 2025-01-01, val Jan–Apr 2025, else test), no backtest freeze loop, no migration quarantine, no explicit “no mature primary claims post-15 Oct 2025” enforcement beyond `ADMIN_CENSORED`. Late calendar mass collapses into a junk “test” bucket.

**7. Label construction edges (moderate)**  
- Case-level `observed_label` is last available `default_90d` with `label_available_at  CUTOFF`, not clearly tied to **that** activation’s 90-day window and feed rules.  
- `classify_pathway` does not use `label_seen_at` inside the activated branch; maturity is only via the blunt landmark \(+215\) day rule.  
- Permanent missing feed vs not-yet-mature vs true non-default are collapsed into coarse strings; the ascertainment model covariates promised in Sec. 3 are never built.  
- Ambiguous same-timestamp routes get a label (`AMBIGUOUS_ROUTE_TIME`) then are excluded only via `tie_ambiguous` on landmark ties—not fully aligned.

**8. Smaller but real issues**  
- `data_extract_time` is assumed usable as record availability with a comment; Sec. 4 correctly says file-level extract time is often useless—code still filters on it.  
- Dedup on `[CASE, ACT, TS, resource, source_system]` can drop legitimate same-second distinct events if resource/source match.  
- `PENDING_90D` is treated as a fully observed multiclass outcome; for decision metrics this needs explicit justification vs censoring of the activation clock.  
- No clustered-by-case evaluation path despite multi-landmark unit of analysis.  
- Post-policy mature sample frailty is noted qualitatively; no quantitative feasibility check (expected `# DEFAULT_90D` in the Jul 2025 stress window).  
- Line count and scope drift above the “80–160 lines, skeleton” brief while still omitting the hard parts (weights, stage-2 survival/classification hook data structures).
