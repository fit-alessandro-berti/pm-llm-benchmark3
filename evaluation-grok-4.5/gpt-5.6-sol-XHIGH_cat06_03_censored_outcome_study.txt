**8.6**

## Grading rationale (strict)

This is a strong, process-aware design that correctly refuses the usual failure modes (treating the 21,600 as the population, coding rejects/withdrawals/open as non-default, random splits across policy/migration, and raw use of post-decision fields). Sections 1–8 are coherent, and the estimand honesty is well above typical benchmark-chasing writeups. It is not near-flawless under a hypercritical bar.

### What is genuinely strong
- **Target (§1):** Activation-conditional \(P(Y\mid H(t_p), A=1, G=g)\) is the right primary choice given observed outcomes; counterfactual all-applicant default is correctly quarantined. Multi-state alternative is a real different question, not a relabeling trick.
- **Cohort (§2):** Full 48,000 accounting; pending 3,600 not invented into fake cells; rejects/withdrawals/transfers/open kept as competing or undefined, not \(Y=0\).
- **Missingness (§3):** Clean separation of right censoring, feed delay, activation selection, transfer, permanent feed loss; IPW only for observation among activated (not pseudo-counterfactual activation weights); testability table is appropriate.
- **Leakage (§6):** Table hits every mandated element with sound drop/repair rules, especially `collection_status`, `final_limit`, `decision_reason`, extraction-time resource experience, and `label_available_at`.
- **Validation (§7):** Temporal structure, policy/migration cuts, and the hard maturity point that post-migration activations cannot yet support confirmatory 90-day evaluation are exactly the kind of detail most answers miss.
- **Limitations (§8):** Selection vs association vs counterfactual is explicit; deployment feedback list is operationally real.

### Deductions (why not 9+)

**Design / statistical nits**
1. **Primary code path vs stated temporal discipline:** Text correctly demands rolling-origin and `label_available_at` cutoffs; the skeleton builds `mature_binary` / `model_ready` almost entirely against a single global `CUTOFF` (2026-02-15). That quietly lets hindsight label maturity define who sits in train/val/test, which undercuts §7’s own standard. This is more than cosmetic for a study whose credibility rests on as-of semantics.
2. **IPW is the stated primary analysis but is only a comment.** For a skeleton that is supposed to make the data-engineering audit concrete, omitting even a minimal observation-model / weight column / positivity check is a gap between §3 and §9.
3. **Transfer handling is underspecified in the implementable path.** §2–3 treat linkage, competing exit, and informative missingness seriously; the code is a one-line “would occur here.” Given 2,900 transfers and ~40% unlinkable, that is a material cohort hole, not a polish item.
4. **Landmark definition is slightly double-jointed.** “Third canonical event, expected to be first Credit Review” plus a hard filter that the prefix end activity *is* `Credit Review` is fine operationally, but eligibility, coverage, and estimand language could be tighter about cases whose third event is something else or whose first review occurs after rework under a different \(K\).
5. **Metrics:** “Weighted AUROC” under feed-IPW is asserted without defining the target population or weighting scheme for ranking metrics; workable, but looser than the rest of the censoring discussion.
6. **Minor estimand/operations tension left softer than ideal:** Showing an \(A=1\)-conditional score on all applications is acknowledged, yet the business ask is “every credit application.” The multi-state path is described well but not given enough force as the deployment-facing output when activation is still undecided at \(t_p\).

**Implementation skeleton defects**
7. **Label extraction order risk:** Events are filtered with `TS <= EVENT_END` *before* labels are harvested from the same frame. If `default_90d` / `label_available_at` are only materialised on later-timestamped rows (plausible with delayed feeds through 15 Feb 2026), mature labels can be dropped. A case-level label extract (or allowing label fields through `CUTOFF` independent of process-event window) is the safer pattern; the code does not do it.
8. **Elapsed-time prefixes:** Required in §4, absent in code (only fixed \(K\) via `get_prefixes_from_log`).
9. **Process-reference features:** §5 promises fold-wise variant/DFG/rarity/workload features; code only prints a train DFG edge count—no join-back, no leakage-safe frequency features, no workload-as-of.
10. **Migration map is empty (`ACTIVITY_MAP = {}`)** while §4 depends on a dated canonical map; near-duplicate handling is flag-only with no sensitivity path coded.
11. **Small robustness smells:** `outcome_state` initialised as `"not_activated/" + terminal_state` (including the oxymoron `not_activated/activated`) before overwrite; edge activated states can fall through; `elapsed_hours` is prefix span (OK if first event is always start, fragile otherwise); resource-experience repair from §5–6 never appears; `documents_total` is only dropped, not version-repaired as §6 allows.
12. **Assertions are narrow.** Column-name disjointness and `prefix_max <= prediction_time` are good but do not catch same-timestamp batching, backfilled case attributes, or label-on-event leakage paths.

**Clarity / completeness**
13. Cohort-flow table correctly refuses to fabricate the 3,600 split, but never gives even symbolic sub-flows (landmark-eligible × mature × feed-complete), so “publish counts later” does a lot of work that the design section could have structured.
14. Partner-origin permanent feed missingness is in sensitivities but barely visible in the primary estimand’s identification narrative.

### Score calibration under the stated rubric
- Weak answers (train 21.6k only, rejectnon-default, random split, leaky fields): ~2–4.
- Solid competent design with a few process mistakes: ~6–7.5.
- This answer: excellent threat model and mostly right estimand/cohort/leakage/validation story; several real as-of and implementability cracks under strict reading  **8.6**, not 9.5+.

A 9.5+ would need fold-specific as-of labels in the main pipeline, a coded observation-weight path, safer label/event separation, elapsed-time prefixes, and transfer/linkage made concrete—not merely discussed.
