## Section-by-section

### 1. Decision rule — good design, uneven formalization

**Strengths:** Hard stage gate; repeat-alert material-change gate; imputation “verify first”; segment calibration notes that correctly refuse to treat observational `p` as interventional effect; spillover in the objective; reserve as preference with override conditions; ARR ranges treated as uncertain, not known CATEs.

**Flaws:**
- Core formulas are missing operators (`Net_portfolio  (ARR × Value)`, `Spillover_harm  (slots_used)`), which hurts “deployable rule” claims.
- **Step 1 robust gate ignores spillover; Step 3 then imposes a spillover hurdle (~€1,500–2,500).** That split is workable only if applied consistently later — it is not (see §2).
- “Diagnosis Started > Triage ceteris paribus” is asserted without reconciling cases where Triage + long SLA + high ARR dominates short-horizon Diagnosis Started.
- Calibration offsets are described carefully for `p`, then the text still leans on adjusted `p` for Strategic prioritization while insisting ARR is untouched — conceptually fine, but it sets up prose/number mismatches in §2.

### 2. Capacity allocation — right exclusions, broken consistency

**Strengths:**
- I-03 ineligible for mechanistic reasons, not low priority.
- I-05 suppressed as refresh artefact; I-07 re-eligible on new log.
- I-06 held for imputation risk.
- I-08 not auto-selected despite €100k stake when ARR_low net is negative — correct robust instinct.
- 3 deploy + 1 reserve is operationally realistic given congestion and the regulatory option value.
- Most `Robust_Benefit = ARR_low × Value − 450 − FA` figures check out (I-01 €920, I-04 €3,550, I-08 −€450, I-09 €2,350, etc.).

**Major coherence failure:**  
Step 3 says defer when `Robust_Benefit < ~€1,500–2,500` marginal spillover. **I-01’s stated robust benefit is €920**, below that band, yet I-01 is **Tier 1 / INTERVENE / Slot 1**. By the author’s own rule, I-01 should not clear the portfolio filter. That is not a nit; it is a direct contradiction between stated policy and named portfolio.

**Other issues:**
- I-09 is Tier 1 intervene while the same answer flags NNL calibration **and** ARR as sparse/uncertain. Using undisccounted `ARR_low = 0.18` as if it were already “robust” undercuts the uncertainty doctrine in §1 and §5. Portfolio **I-01, I-04, I-09** is plausible as a value/ARR story, but **not** as an application of the rule written in §1. That gap is the single largest grade penalty.

### 3. Expected-impact table — right qualitative shape, weak audit trail

**Strengths:** Three required scenarios; spillover large enough to flip Adverse net negative; shows that a 4th slot is unattractive; Base net arithmetic `18,585 − 1,350 − 3,250 − 6,480 = 7,505` is internally consistent; useful observation that Adverse may be breach-count neutral while economically negative.

**Flaws (strict):**
- Optimistic components are sloppy: labels `0.31 / 0.24 / 0.27` do not match the euro pieces `2,763 / 14,100 / 5,400` without silent alternate ARRs (`2,763/9,000 ≈ 0.307`, `14,100/60,000 = 0.235`). “Show enough arithmetic to make the table auditable” is only partly met.
- False-alarm burden is folded into “Intervention cost” while the column header still reads like cash labor cost — workable if defined once, but easy to misread against the suggested `ARR × Value − swarm − FA` template.
- Adverse row is hand-wavy (“illustrative,” mixed inclusion of burden, optional zero on I-09) and does not cleanly separate (a) lower-bound ARR on all three, (b) one null effect, (c) extra congestion breaches. Confidence labels (“Low / Moderate / Moderate-High”) are asserted, not tied to identification assumptions.
- Spillover valuation at €18k average for six unnamed diagnosis-stage cases is fine as a sensitivity anchor, but dependence on congestion (emphasized in the prompt) is mostly collapsed into a single 0.01/0.02/0.03 knob.
- “Direct breaches plausibly avoided = Σ ARR” is an expectation, not a count of plausible avoided breaches; wording overclaims precision.

Qualitative conclusion (2–3 slots, not 4; Adverse can go negative) is sound; execution is not tight enough for a high score.
