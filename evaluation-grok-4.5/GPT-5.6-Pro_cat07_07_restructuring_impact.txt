### Hypercritical deductions (why not 9.5–10)

1. **Exposure index over-sold as diagnostic clarity**  
   Summing both legs of round-trips is fine as a directional stress score, but the write-up only partly disciplines interpretation. Readers can still blur “exposure index +23%” with “waiting burden +23%” despite the non-additivity caveat. A one-line normalization (e.g., per-case expected edge exposure, or separating outbound vs return legs) would have made this tighter. Minor conceptual looseness: **0.25**.

2. **Scenario quantiles are loosely tethered to the mechanism math**  
   Ranges are labeled “planning hypotheses,” which is honest, but §2 does not show even a rough bridge from the §1 edge frequencies/waits (or utilization slack) into the 6.9–7.3d / 7.2–7.9d / 8.2–9.5d bands. The central scenario largely restates management medians; adverse waits (“>6h,” “>14h”) are plausible but free-floating. For a forecast brief, that is a real rigor gap: **0.30**.

3. **Handover edge p90 methodology in code is awkward**  
   In `direct_handover_edges`, p90 is taken over *per-case median* inter-event times, not over the transition population (and not a case-weighted transition quantile). As a sketch this is acceptable; as analytics guidance it can misrank tail risk on busy edges. **0.20**.

4. **PM4Py API surface is asserted more confidently than a sketch warrants**  
   The prompt allows pseudocode, and version drift is acknowledged—but the answer presents long, callable-looking signatures (`filter_event_attribute_values` kwargs, `insert_case_service_waiting_time` column names, `discover_subcontracting_network(n=2)`, etc.) as if production-ready. Several of these are version-sensitive; a stricter sketch would mark optional/approx APIs and keep a thinner verified core. **0.20**.

5. **Service/waiting enrichment still executed when unidentified**  
   The timing warning is excellent, yet `get_service_time` / `insert_case_service_waiting_time` still run with `start_key == TIMESTAMP`. That can silently produce misleading artifacts downstream if a reader prints them without heeding the warning. Better: hard-gate those calls. **0.15**.

6. **Optimistic path quietly imports design changes not in the base proposal**  
   e.g., Legal/Risk waiting “at or below current” because “triage is separated from substantive work,” and protected specialty capacity. §2 optimistic header says the scenario *requires* those conditions—good—but a careless reader may treat them as outcomes of the stated restructure rather than *modifications*. §6 later makes the modifications explicit; §2 could cross-link more sharply. **0.10**.

7. **Guardrail thresholds are crisp but under-justified**  
   “88% / 92% utilization,” “+1 pp rework,” “p90 +10%,” “handovers +10% vs 343” are operationally useful and marked for recalibration, yet several are not tied back to baseline variance or sample-size logic. Acceptable for a design, slightly soft for “utmost strictness.” **0.10**.

8. **Presentational density in §1**  
   The mechanism map proper is preceded by a long index calculation. Not wrong, but it slightly blurs the required “mechanism map” artifact versus a pre-analysis. Negligible substance impact: **0.05**.
