# Uncertainty-Aware Predictive Process Monitoring for Early Credit Default Warning

---

## 1. Target definition

**Primary formulation: cause-specific cumulative incidence of "activated-and-defaults-within-90-days" over *all* applications, from a fixed elapsed-time prediction point, with rejection / withdrawal / transfer / survival as competing absorbing states.**

| Element | Specification |
|---|---|
| **Unit of analysis** | One credit application (one `case:concept:name`), exactly one prediction per application. Transfer-linked duplicate identities are *grouped*, never split across folds. |
| **Prediction time ** | `t_pred = Application Started + 72h` (elapsed-time prefix). Secondary, event-indexed view: first `k  {1,2,3,5}` events, used only for stratified reporting, not as the primary cohort definition. |
| **Population / risk set** | Applications started in the observation window that are **still in flight at ** (no absorbing event before ). Cases already Rejected / Withdrawn / Transferred before 72h are *resolved at prediction time* and reported separately, not scored. |
| **State space** | `0 In review`  `1 Activated (in 90-day window)`  `2 Default90d` (target) or `3 Survived 90d`; from `0`: `4 Rejected`, `5 Withdrawn`, `6 Transferred out`. |
| **Horizon H** | Primary landmark `H = 180 days` after ; endpoint = activation within 90 days of  **and** default within 90 days of that activation. Secondary landmarks 30/60/90 days and an extended 270-day landmark. |
| **Estimand** | `F(+H | X_, alive at , era e)` — the cause-specific cumulative incidence of state 2 under the **observed** credit policy regime `e` (pre/post 1 Jul 2025), estimated by Aalen–Johansen from cause-specific hazard models. The full vector `(F,F,F,F,F)` is reported, not `F` alone. |

**Why this is defensible.** (i) It keeps all 48,000 applications in the risk set — nothing is silently relabelled "non-default". (ii) "Default" is only ever asserted for cases that were actually activated and actually observed for 90 days plus the feed lag; every other case contributes *person-time and a competing event*, which is exactly what the data support. (iii) It answers the operational question the lender can act on at hour 72: *"of applications that look like this one, what share will become a 90-day default account within six months, and what share will be rejected, withdrawn, or handed to a partner?"* — a triage / capacity / review-routing quantity. (iv) Its policy-dependence is explicit in the estimand rather than hidden in a cohort filter.

**Honest headline caveat:** `F` is **not** "probability this applicant would default if lent to". It is a policy-conditional mixture of the lender's own selection behaviour and post-activation risk.

**Credible alternatives (different questions):**

- **(A) Conditional PD: `P(default  90d | activated, X_)`.** This is the classical credit-risk PD. It is defined on a set membership determined *after*  (activation), so it cannot be read as a per-application risk; it is legitimate only as a *component* model, reported as `F/(F+F)` among resolved activations, with the selection mechanism named. Using it alone re-creates the 21,600-row bias.
- **(B) Time-to-default after activation with right censoring** (cause-specific Cox / flexible parametric survival on activated accounts). Answers *"when will defaults arrive"* for provisioning and collections staffing; still conditioned on activation, but uses the 3,600 immature activations as censored observations instead of discarding them.
- **(C) Policy-specific counterfactual `P(default  90d | do(activate), X_)` for every applicant, including rejected ones.** Requires consistency, no unmeasured confounding of activation, and **positivity — which is structurally violated** (rejected applicants have zero activation probability under the logged policy). Not identified from these data. A plausible *partial* identification route is a regression-discontinuity / instrument around the 1 Jul 2025 threshold change, plus Manski-type bounds; this must be labelled a separate, assumption-heavy study, never the headline model.

## 2. Cohort construction

**As-of rules (applied in this order):**

- **R1 (event admissibility):** an event enters any feature computation iff `time:timestamp  min(t_pred, replay_cutoff)`.
- **R2 (label admissibility):** a 90-day label is usable iff `Account Activated + 90d + feed_lag  replay_cutoff` **and** `label_available_at  replay_cutoff`. Worst-case `feed_lag = 35d`; optimistic sensitivity `= 7d`.
- **R3 (reference statistics):** DFG, variant frequencies, target encodings, resource histories are fitted only on training-era data that already satisfy R1–R2 at the training replay cutoff.
- **R4 (static attributes):** `case:channel`, `case:region`, `case:requested_amount` taken from their **first** event; later revisions ignored.
- **R5 (linkage):** the transfer linkage table has no stated availability timestamp  assumed **not available at prediction time**; used only for outcome ascertainment in sensitivity analyses.
- **R6 (grouping):** linked transfer identities form one group ID for splitting and for cluster bootstrap.

**Derived maturity boundaries at extraction 15 Feb 2026:**

| Rule | Boundary |
|---|---|
| Activation mature, worst-case 35d feed | activation  **13 Oct 2025** |
| Activation mature, optimistic 7d feed | activation  **10 Nov 2025** |

## 3. Censoring and missing-label strategy

| Mechanism | What it is here | Primary handling | Assumption | Testability |
|---|---|---|---|---|
| **Ordinary right censoring** | 5,100 open cases; administrative end of follow-up | Censor at replay cutoff; Aalen–Johansen / IPCW | Censoring independent of latent event time given start date, era, covariates | **Partially testable**: model the censoring hazard on covariates; compare censored vs. followed covariate distributions |
| **Delayed labels (7–35d)** | 3,600 immature activations; feed lag on all labels | Maturity-aware administrative censoring at `cutoff  35d` for the default cause; other causes censored at `cutoff` | Lag distribution stable and independent of default given covariates | **Largely testable/estimable**: `label_available_at  (activation + 90d)` gives the empirical lag distribution; the independence of the *tail* is not testable |
| **Selection through activation** | 14,800 rejected/withdrawn never exposed to credit | **Not censoring.** Modelled as competing absorbing states; conditional PD reported only as `F/(F+F)` | Consistency of the observed policy; no claim about `do(activate)` | **Fundamentally untestable** counterfactual; positivity structurally violated |
| **Transfer** | 2,900 cases; ~60% linkage | Competing event in primary; sensitivity re-enters linked cases as continued follow-up under a new ID | Transfer independent of latent default given covariates (primary); MAR given observables (sensitivity) | **Partially testable**: linked vs. unlinked covariate balance, linkage-rate drift by era/channel; residual MNAR untestable |
| **Permanently missing feeds** | Elevated for partner-originated activations | Treated as censoring at last confirmed contact in primary (declared as an optimistic assumption) | MAR given source, channel, era, prefix | **Untestable** in the MNAR direction; missingness *rate* is testable, missing *outcomes* are not |

**Primary analysis strategy.** Cause-specific hazard models (gradient-boosted or flexible-parametric cause-specific Cox, one per transition, era-stratified) combined via **Aalen–Johansen** into CIFs; maturity-aware administrative censoring as above; cluster-robust / group-bootstrap intervals with clusters = linked applicant identities. Every reported CIF is accompanied by the at-risk count and the censoring fraction at that landmark.

**Sensitivity analyses (pre-registered, reported side-by-side):**

1. **Feed-lag bracket:** re-run with 7-day vs. 35-day lag  shifts the maturity boundary from 13 Oct to 10 Nov 2025 and changes the evaluable post-policy sample.
2. **Pattern-mixture -shift for permanent feed loss:** assume default risk among permanently-missing feeds = ` ×` observed risk for the same source/channel stratum, `  {1, 1.25, 1.5, 2, 3}`; report the **tipping point**  at which the triage decision reverses.
3. **Manski-type worst/best-case bounds** over the missing-feed and unlinkable-transfer fractions (all missing = default vs. none = default). These are wide; their width *is* the honest uncertainty statement.
4. **IPCW for feed missingness** under MAR, with weights fitted on observables; compare to unweighted primary.
5. **Transfer reclassification:** linked transfers merged into follow-up (state 1/2/3) vs. kept as competing state 6.

What cannot be fixed by any of this: the counterfactual default risk of a rejected applicant, and the outcome distribution of permanently unobserved feeds. Those are reported as **bounds or explicitly assumption-labelled scenarios**, never as point predictions.

## 4. Prefix extraction

1. **Harmonise first, truncate second.** Apply a *versioned, effective-dated* activity rename map for the 15 Oct 2025 migration; retain `act_raw` and a `post_migration` flag. Then de-duplicate: exact repeats on (case, activity, timestamp, resource, source_system), plus same-activity repeats within 60 s. Log removal counts per era; a spike confined to the migration period is expected, a spike elsewhere invalidates the rule.
2. **Order deterministically:** sort by timestamp, stable tie-break on original row order; record tie counts (ties are common after migration and silently change "the third event").
3. **Truncate the log at  before anything else.** Build `pre = events[ts  t_pred]`, drop label/post-decision columns, *then* convert to a PM4Py log. All features, DFGs, variants and temporal statistics are computed on this truncated object.
4. **Elapsed-time prefixes (primary):** every application gets exactly one prefix at start + 72h, including cases with only one or two events. Short prefixes are kept and flagged (`prefix_len`, `prefix_is_short`) — dropping them would create length bias that correlates with both risk and rejection.
5. **Fixed-event-count prefixes (secondary):** `pm4py.get_prefixes_from_log(pre_log, k)` on the already-truncated log; retain traces of length exactly `k` for the event-indexed stratum, and report the *composition* of that stratum (it over-represents fast, simple, often low-risk cases). Never compare k=3 metrics to the -metrics without this caveat.
6. **Document loops:** preserved verbatim in the event sequence (loop counts are signal). For variant-frequency reference features only, use a **consecutive-duplicate-collapsed abstraction** so `Credit Review  Request Documents  Credit Review  …` does not explode the variant space; the collapse map is fitted on training data.
7. **Resolved-before- cases:** excluded from the scored risk set, counted and reported separately (their outcome is already known — scoring them would inflate every metric).
8. **Snapshot settling lag:** any field sourced from a nightly batch is either event-sourced with its own ingestion timestamp or excluded (see §6); a same-calendar-day tolerance is *not* sufficient.

## 5. Process-aware features

**Static case attributes (value at first event):** `case:channel`, `case:region`, `case:requested_amount` (and log-amount), applicant-side attributes if present, `source_system` (kept but monitored — it doubles as an era proxy and can hurt transportability).

**Prefix-derived (computable from truncated log alone):**
- *Control-flow:* prefix length, distinct activities, last canonical activity, KYC-pass/rework flag, whether Credit Review has been entered, collapsed-variant ID, activity bag counts.
- *Rework:* number of `Request Documents` events, number of Credit Review re-entries, max/mean loop length, document-request-to-return latency.
- *Timing:* elapsed time since start, inter-event time mean/max/last, time in current activity, idle gap since last event, night/weekend/holiday flags, hour-of-day of last event.
- *Resource / queue:* distinct resources, handover count, whether the case has been re-assigned, **queue backlog at ** = number of other cases with an open event and no terminal event as of  (computed from prefix-truncated data across cases — legitimate because it uses only past events of *other* cases).
- *Risk-score trajectory:* last non-null `risk_score` with `ts  `, its **age/staleness**, delta and slope over the prefix, missingness indicator.
- *Prefix quality:* `prefix_is_short`, `n_duplicate_events_removed`, `post_migration`, tie count.

**Features requiring historical reference data (fit on training era only, as-of joined):**
- Reference DFG transition probabilities from the last prefix activity (`pm4py.discover_dfg` on the training prefix log).
- Collapsed-variant frequency in a trailing 90-day window (`pm4py.get_variants`), with an explicit `unseen_variant` flag.
- **Resource experience reconstructed as-of ** from the event log (count of prior cases the resource touched before ), replacing the extraction-time snapshot.
- Rolling mature-outcome rates by channel/region — **gated on `label_available_at  `**, not on event time. Any target encoding that ignores the 7–35-day feed lag is leakage.
- Case-service / waiting-time decompositions (`pm4py.insert_case_service_waiting_time`) **only under the stated assumption** that timestamps are activity *completion* times and handling is broadly sequential; otherwise the service/waiting split is not interpretable and the feature is dropped.

## 6. Leakage audit

| Feature or data element | Leakage or bias risk | Valid availability rule | Keep/repair/drop | Rationale |
|---|---|---|---|---|
| `final_limit` | Populated only after the final credit decision — encodes the decision and thus activation selection | Never at  for in-flight cases | **Drop** | Pure post-outcome field; its non-nullness alone predicts activation |
| `decision_reason` | Populated at/after Accept/Reject | Only if a decision event occurred strictly before  (rare) | **Drop** (primary) | Near-perfect proxy for the competing event; any "keep" variant must be audited per era |
| `collection_status` | Updated after activation; directly reveals default | Never a feature | **Drop as feature**; may be used only in label ascertainment with as-of rules | Target leakage in its most literal form |
| Future events (`Contract Signed`, `Account Activated`, `Collections Contact`, `Default Recorded`) | Post- control flow | `ts  min(t_pred, replay_cutoff)` | **Drop via truncation** | Truncate the log *before* feature computation, not the feature table afterwards |
| `documents_total` (nightly snapshot) | Same-day uploads after the nominal prediction time | Only event-sourced doc counts with ingestion `ts    settling_lag` | **Repair  else drop** | Calendar-day granularity cannot guarantee as-of correctness |
| `risk_score` (updated at several events) | Using the latest stored value imports post- revisions; backfills overwrite history | Last non-null value with event `ts  `, plus staleness | **Repair** (drop if event-sourced history is unverifiable) | Score revisions after review are decision-contaminated |
| Resource experience at extraction | Future information; correlates with tenure/era and with outcomes | Replace with log-derived count of prior cases handled before  | **Drop raw / repair derived** | Snapshot-at-extraction is a classic silent leak |
| `default_90d` repeated on events | Forward/backward fill spreads the label across the whole trace | Label pipeline only; stripped before log conversion | **Drop from features** | Repeated labels make naive groupby aggregations leak |
| `label_available_at` | Encodes maturity, which correlates with era and outcome | Cohort/maturity logic and target-encoding gating only | **Drop from features** | Also the key to preventing training/test label leakage |
| `data_extract_time` | Constant; encodes extraction vintage | Audit metadata | **Drop from features** | No signal, invites vintage artefacts |
| `source_system` | Changes at migration  era proxy | Value at first event | **Keep + drift monitor** | Useful but a transportability hazard; test with/without |
| `org:resource` (raw ID) | High cardinality; encodes era and routing policy | Only as-of derived aggregates | **Repair** | Raw-ID target encoding leaks future outcome rates |
| Migration duplicate events | Inflate counts, loops, and variant frequencies | Dedup rules of §4, applied per era with counts logged | **Repair** | Otherwise the model learns a migration artefact |
| Transfer linkage table | Created after transfer; unknown availability | Not available at ; sensitivity-only outcome ascertainment | **Drop from features** | Also a grouping key for splitting, not a predictor |
| Timestamp ties / ordering | Non-deterministic "k-th event" | Stable sort + documented tie-break | **Repair** | Reproducibility and prefix-definition stability |

## 7. Validation design

**Temporal blocks by case start (never a random case split):**

| Block | Case-start window | Purpose | Expected limitation |
|---|---|---|---|
| Train | 2024-01-01  2025-03-31 | Fit, **replayed as of 2025-03-31** (all follow-up censored there) | Pre-policy only |
| Validation / calibration | 2025-04-01  2025-06-30 | Hyperparameters, conformal calibration, threshold choice | Pre-policy, late |
| Test A — policy shift | 2025-07-01  2025-09-30 | Main honest performance under the new thresholds | Partial follow-up; short landmarks dominate |
| Test B — migration + immaturity | 2025-10-15  2025-12-31 | Robustness / drift stress test | Heavy censoring; **270-day and most 180-day endpoints not evaluable**; report 30/60/90-day landmarks only |
| Gap | 2025-10-01  2025-10-14 | Embargo around migration | Avoids straddling artefacts |

**Label-availability purge.** Training uses only labels with `label_available_at  train_cutoff`; recent training cases enter as censored observations, not as "non-default". Because maturity extends up to 125 days past activation, an event-time-only split leaks future outcomes into training target encodings. Group IDs from the linkage table are kept within a single block.

**Rolling-origin backtest.** Monthly origins from 2025-01 onward: refit on the expanding window replayed as of the origin, predict the next cohort, evaluate only at landmarks whose ascertainment window has closed at that origin. This reproduces the actual information set at deployment and yields a time series of performance with honest degradation curves.

**Metrics (matched to competing risks + censoring):**
- **Aalen–Johansen calibration curves** for state 2 at 30/60/90/180 days: predicted vs. observed CIF by decile, with at-risk counts.
- **IPCW Brier score** (cause-specific, Graf-type) and integrated Brier; **Uno's time-dependent AUC** and cause-specific C-index.
- **Calibration-in-the-large and slope** at each landmark (complementary log-log / pseudo-observation regression).
- **Full outcome-mix calibration**, not just the default cause — a model that predicts defaults well but mis-predicts rejection is operationally useless for triage.
- **Decision-curve / net-benefit** at review-capacity thresholds; **precision@k and alert-rate curves** given ~5.6% target-cause incidence.
- **Uncertainty:** group bootstrap CIs for CIFs; split-conformal intervals calibrated on the validation block, with **weighted conformal** under covariate shift; report empirical coverage per block and an **abstain/defer rate** for short prefixes and unseen variants.
- **Subgroups:** channel, region, amount band, partner vs. direct, pre/post policy, pre/post migration, prefix-length band, queue-load band — each with its censoring fraction and effective event count, so readers can see where intervals are uninformative.
- **Drift monitoring:** PSI/KS on features, canonical-activity distribution checks across the migration, DFG edge-frequency divergence, linkage rate, feed-lag distribution, maturity-corrected label-rate monitoring.

**Why a random split misleads:** it mixes policy eras (same prefix, different selection and outcome relation), places linked transfer identities and migration duplicates on both sides, ignores that label maturity varies systematically with start date (so test labels are implicitly "more mature" than deployment labels would be), and produces calibration that cannot survive the July threshold change. It would report a stable, confident model for a process that is demonstrably non-stationary.

## 8. Limitations and decision-use boundary

**Can claim:** policy-conditional, prefix-conditional *associations* — cumulative incidence of activated-and-default within a stated horizon, alongside competing outcomes, for applications in flight at hour 72, with censoring-aware uncertainty and stated era validity.

**Cannot claim:** (i) the default risk of a rejected or withdrawn applicant had they been activated (positivity fails); (ii) any causal effect of approving, of limits, or of document requests; (iii) unbiased absolute risk for partner-originated cases with permanent feed loss — only bounds and -scenarios; (iv) validated post-migration outcome performance at this extraction; (v) that `F` is a per-applicant probability of default. `F` mixes the lender's selection policy with post-activation hazard, and it moves when the policy moves even if applicant behaviour is unchanged.

**Deployment will change the data-generating process (performativity):**
1. **Alert-driven review behaviour:** flagged cases get extra document requests or rejection  activation selection changes  future labels are generated under a *different* policy than the training estimand.
2. **Risk-based limits/pricing:** acting on predictions changes `final_limit` and repayment burden, altering the default hazard itself.
3. **Routing shifts:** sending flagged cases to partners increases transfers and permanently missing feeds, worsening identifiability exactly where the model is most used.
4. **Queue and staffing feedback:** triage reallocates reviewer capacity, changing waiting times — a model input — and thus the prefix distribution.
5. **Applicant/agent adaptation:** gaming of document timing or channel choice.

**Boundary of use:** decision *support* for review prioritisation and capacity planning, with human adjudication, logged interventions (action, timestamp, actor) to enable future off-policy evaluation, monitored abstention, and scheduled re-estimation with maturity-aware refresh. Not for automated rejection, not for pricing, and not as a claim about any individual's creditworthiness.

## 9. PM4Py-oriented Python implementation skeleton

```python
"""As-of cohort + prefix pipeline for competing-risk early default warning (PM4Py).
PM4Py is used ONLY for log handling / process features. It has no survival API:
cause-specific hazards + Aalen-Johansen are connected later (scikit-survival/lifelines).
ASSUMPTION comments mark places where the design's assumptions enter the code."""
import numpy as np, pandas as pd, pm4py

CASE, ACT, TS = "case:concept:name", "concept:name", "time:timestamp"
EXTRACT   = pd.Timestamp("2026-02-15", tz="UTC")
FEED_LAG  = pd.Timedelta(days=35)          # worst case; sensitivity: 7 days
DEF_WIN   = pd.Timedelta(days=90)
TAU       = pd.Timedelta(hours=72)         # primary elapsed-time prediction point
K         = 3                              # secondary fixed-event-count prefix
POLICY    = pd.Timestamp("2025-07-01", tz="UTC")
MIGRATION = pd.Timestamp("2025-10-15", tz="UTC")
TRAIN_END = pd.Timestamp("2025-03-31", tz="UTC")
VAL_END   = pd.Timestamp("2025-06-30", tz="UTC")
TESTA_END = pd.Timestamp("2025-09-30", tz="UTC")
RENAME = {"KYC_Check_v2": "Identity/KYC Check", "Credit_Review_v2": "Credit Review",
          "Doc_Request_v2": "Request Documents", "Acct_Activated": "Account Activated"}
TERMINAL   = {"Rejected", "Withdrawn", "Transferred"}
POST_POINT = {"Contract Signed", "Account Activated", "Collections Contact", "Default Recorded"}
BANNED = ["final_limit", "decision_reason", "collection_status", "default_90d",
          "label_available_at", "data_extract_time", "documents_total"]

# ---------------------------------------------------------------- load & harmonise
df = pd.read_csv("applications_events.csv",
                 parse_dates=[TS, "label_available_at", "data_extract_time"])
df[TS] = df[TS].dt.tz_localize("UTC", ambiguous="NaT", nonexistent="shift_forward")
df = pm4py.format_dataframe(df, case_id=CASE, activity_key=ACT, timestamp_key=TS)
df["act_raw"] = df[ACT]
df[ACT] = df[ACT].replace(RENAME)          # versioned migration map (effective-dated in prod)
df = df.sort_values([CASE, TS], kind="mergesort").reset_index(drop=True)
dup_exact = df.duplicated([CASE, ACT, TS, "org:resource", "source_system"])
p_ts, p_act = df.groupby(CASE)[TS].shift(), df.groupby(CASE)[ACT].shift()
dup_near = (df[ACT] == p_act) & ((df[TS] - p_ts) <= pd.Timedelta(seconds=60))
print("dup exact/near removed:", int(dup_exact.sum()), int((dup_near & ~dup_exact).sum()))
df = df[~(dup_exact | dup_near)].copy()

# ---------------------------------------------------------------- as-of case table
def build_cases(ev, cutoff):
    """Rebuild the cohort as it would have looked at `cutoff` (no future information)."""
    g = ev.groupby(CASE)
    c = pd.DataFrame({
        "start": g[TS].min(),
        "activated": ev[ev[ACT].eq("Account Activated")].groupby(CASE)[TS].min(),
        "term_ts": ev[ev[ACT].isin(TERMINAL)].groupby(CASE)[TS].min(),
        "term_act": ev[ev[ACT].isin(TERMINAL)].groupby(CASE)[ACT].first(),
        "label": g["default_90d"].max(), "label_at": g["label_available_at"].min(),
        "channel": g["case:channel"].first(), "region": g["case:region"].first()}).reset_index()
    c["t_pred"] = c["start"] + TAU
    # ASSUMPTION: label trusted only after 90d window + worst-case feed lag AND feed arrival
    c["mature"] = (c["activated"].notna()
                   & (c["activated"] + DEF_WIN + FEED_LAG <= cutoff)
                   & (c["label_at"].notna() & (c["label_at"] <= cutoff)))
    c["state"] = np.select(
        [c.term_act.eq("Rejected"), c.term_act.eq("Withdrawn"), c.term_act.eq("Transferred"),
         c.mature & c.label.eq(1), c.mature & c.label.eq(0), c.activated.notna() & ~c.mature],
        ["rejected", "withdrawn", "transferred", "default_90d", "survived_90d", "activated_immature"],
        default="open_censored")
    c["mnar_suspect"] = c.activated.notna() & (c.activated + DEF_WIN + FEED_LAG <= cutoff) & c.label.isna()
    c["in_risk_set"] = c.term_ts.isna() | (c.term_ts > c.t_pred)   # resolved-before-tau excluded
    # survival hookup: observed time + cause indicator, administratively censored
    asc = cutoff - FEED_LAG                                       # default-cause reporting cutoff
    end = c[["term_ts"]].min(axis=1)
    end = end.fillna(pd.NaT).where(~c.activated.notna(), c["activated"].where(~c.mature, asc))
    c["obs_days"] = ((end.fillna(asc) - c["t_pred"]).dt.total_seconds() / 86400).clip(lower=0)
    return c

cases = build_cases(df, EXTRACT)
print("COHORT FLOW (n=%d):\n" % len(cases), cases["state"].value_counts())
print("MNAR suspects (mature, no feed):", int(cases.mnar_suspect.sum()),
      "| resolved before tau:", int((~cases.in_risk_set).sum()))

# ---------------------------------------------------------------- temporal split
cases["split"] = np.select(
    [cases.start <= TRAIN_END, cases.start <= VAL_END, cases.start <= TESTA_END,
     cases.start >= MIGRATION], ["train", "val", "test_policy", "test_migration"], default="gap")
train_ids = set(cases.loc[cases.split.eq("train"), CASE])
# label-availability purge: training labels must already have existed at TRAIN_END
assert cases.loc[cases.split.eq("train"), "label_at"].dropna().max() <= TRAIN_END

# ---------------------------------------------------------------- prefix truncation
ev = df.merge(cases[[CASE, "t_pred"]], on=CASE, how="left")
pre = ev[ev[TS] <= ev["t_pred"]].drop(columns=BANNED, errors="ignore").copy()
pre = pre[pre[CASE].isin(set(cases.loc[cases.in_risk_set, CASE]))]
pre_log = pm4py.convert_to_event_log(pre)                 # truncated BEFORE any feature code
pref_k = pm4py.get_prefixes_from_log(pre_log, K)          # traces capped at K events (secondary)
print("fixed-k stratum size:", sum(len(t) == K for t in pref_k))

g = pre.groupby(CASE)
feat = pd.DataFrame({
    "n_events": g.size(), "n_acts": g[ACT].nunique(), "last_act": g[ACT].last(),
    "doc_loops": g[ACT].apply(lambda s: int(s.eq("Request Documents").sum())),
    "n_resources": g["org:resource"].nunique(),
    "elapsed_h": (g[TS].max() - g[TS].min()).dt.total_seconds() / 3600,
    "amount": g["case:requested_amount"].first(), "channel": g["case:channel"].first(),
    "risk_last": g["risk_score"].last(),                   # ASSUMPTION: event-sourced, not backfilled
    "risk_age_h": (g[TS].max() - pre[pre.risk_score.notna()].groupby(CASE)[TS].max()
                   ).dt.total_seconds() / 3600}).reset_index()
feat["prefix_is_short"] = feat.n_events < K
# temporal features are justified only because pre_log contains no post-tau events
tf = pm4py.extract_temporal_features_dataframe(pre_log).add_prefix("tf_").reset_index()
feat = feat.merge(tf.rename(columns={tf.columns[0]: CASE}), on=CASE, how="left")
# OPTIONAL: pm4py.insert_case_service_waiting_time(pre_log) -- only if timestamps are
# completion times and handling is sequential; otherwise service/waiting split is not interpretable.

# ------------------------------------------- reference features: TRAIN-ERA ONLY, as-of
ref = pre[pre[CASE].isin(train_ids) & pre[TS].le(TRAIN_END)]
ref_log = pm4py.convert_to_event_log(ref)
dfg, sa, ea = pm4py.discover_dfg(ref_log)                 # reference transition structure
out = {}
for (a, b), v in dfg.items(): out[a] = out.get(a, 0) + v
feat["ref_outdeg_last"] = feat.last_act.map(out).fillna(0)          # unseen activity -> 0 + flag
collapse = lambda s: tuple(a for i, a in enumerate(s) if i == 0 or a != s[i-1])
var = pre.groupby(CASE)[ACT].apply(lambda s: collapse(tuple(s)))
vfreq = var[var.index.isin(train_ids)].value_counts(normalize=True)  # pm4py.get_variants equivalent
feat["variant_freq_ref"] = feat[CASE].map(var).map(vfreq).fillna(0.0)
feat["unseen_variant"] = feat.variant_freq_ref.eq(0)
# resource experience AS-OF tau, replacing the extraction-time snapshot
prior = df[df[TS] <= TRAIN_END].groupby("org:resource")[CASE].nunique()
feat["ref_resource_prior_cases"] = g["org:resource"].first().map(prior).fillna(0).values

# ---------------------------------------------------------------- leakage audit
assert not (set(BANNED) & set(feat.columns)), "banned column survived into features"
assert pre[TS].le(pre["t_pred"]).all(), "post-prediction event in prefix"
first_post = df[df[ACT].isin(POST_POINT)].groupby(CASE)[TS].min().rename("first_post")
chk = pre[pre[ACT].isin(POST_POINT)].merge(first_post, on=CASE)
assert chk[TS].le(chk["t_pred"]).all(), "post-point activity leaked"
naive = df.groupby(CASE)["final_limit"].max().notna().mean()
print(f"LEAKAGE AUDIT OK | final_limit non-null: full log {naive:.1%} vs prefix 0%")
print(feat.groupby("prefix_is_short").size(), "\nsplit sizes:\n", cases.split.value_counts())

# NEXT (not PM4Py): fit cause-specific hazards on (obs_days, state) per era with IPCW for
# feed missingness; combine via Aalen-Johansen to CIF_2(180d); delta-shift/bounds sensitivity;
# conformal intervals calibrated on the val block; evaluate on test_policy / test_migration.
```
