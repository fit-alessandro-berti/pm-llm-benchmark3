# 1. Executive Verdict
- **Workflow net?** Yes. Unique source `source` and sink `sink`, and every node lies on a source-to-sink path.
- **Expected sound?** No. It should be classified as unsound due to improper completion and no option to complete correctly on the waiver branch.
- **Principal defect:** `t_join_waived` has only input `p_waived`. It does not synchronize with `p_analysis_done`, unlike `t_join_normal`.
- **Business consequence:** On waiver, `t_authorize` can fire before `Perform Analysis` finishes or without consuming the analysis token, leaving a stray token while `sink` is marked. Authorization is therefore not gated by analysis, violating mandatory analysis and clean completion.

# 2. Structural Diagnosis
| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_split`: `p_ready` -> `p_analysis` + `p_review` | AND-split to start analysis and review in parallel | Correct 1-to-2 parallel creation | None; creates both branch tokens |
| `p_review` -> `t_standard_review` / `t_waive_review` | XOR-choice: standard review or recorded waiver | Correct free choice, consumes `p_review`, produces mutually exclusive `p_review_done` vs `p_waived` | None structurally; choice is correct |
| `t_standard_review` -> `p_review_done` | Record standard completion | Produces token synchronized later | Normal path can complete |
| `t_waive_review` -> `p_waived` | Record waiver completion | Produces `p_waived` isolated from analysis branch | Waiver token never joined with analysis |
| `t_join_normal`: `p_analysis_done` + `p_review_done` -> `p_decision` | AND-join for normal path | Correct 2-input synchronization | Only usable when standard review chosen |
| `t_join_waived`: `p_waived` -> `p_decision` | Intended AND-join for waiver path | Implemented as 1-input sequence, not a join; enabled by waiver alone | Early `t_authorize`; leftover analysis token; improper completion |
| `im=[source]`, `fm=[sink]` | Workflow start/end | Correct single-token initial/final markings | Defect is not marking choice but net structure |
| Source-to-sink path condition | All nodes should be on some source-sink path | Holds: e.g. `source-...-p_waived-t_join_waived-p_decision-...-sink` exists | Net passes `check_is_workflow_net`; structural validity does not imply soundness |

# 3. Marking-Based Counterexample
Legal sequence exposing early authorization before analysis, using transition names:

`t_register, t_split, t_waive_review, t_join_waived, t_authorize` — then optionally `t_analyze` on leftover.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `source:1` | `t_register` | `im` |
| 1 | `t_register` | `p_ready:1` | `t_split` | case registered |
| 2 | `t_split` | `p_analysis:1, p_review:1` | `t_analyze, t_standard_review, t_waive_review` | both parallel tokens created |
| 3 | `t_waive_review` | `p_analysis:1, p_waived:1` | `t_analyze, t_join_waived` | waiver route chosen; analysis still untouched |
| 4 | `t_join_waived` | `p_analysis:1, p_decision:1` | `t_analyze, t_authorize` | waiver join fired **without** `p_analysis_done`; defect: single precondition |
| 5 | `t_authorize` | `p_analysis:1, sink:1` | `t_analyze` | **sink has token but `fm=[sink:1]` not reached** — extra token remains. `t_authorize` occurred **before** `t_analyze`. |
| 6 | `t_analyze` | `p_analysis_done:1, sink:1` | *none* | leftover moved but cannot be consumed: `t_join_normal` needs `p_review_done` which will never arrive because `p_review` was consumed by waiver. Dead, improperly completed. |

Why leftover cannot be consumed: Petri firing only removes its input tokens. `p_analysis`/`p_analysis_done` are only inputs to `t_analyze`/`t_join_normal`/`t_join_waived` in original net. After step 5, `p_decision` is gone, so `t_authorize` cannot fire again to flush. `t_join_normal` is dead without `p_review_done`. No transition consumes `p_analysis_done` alone.

Second counterexample — analysis done but still improper, proving ordering does not save the net:

`t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`

Resulting markings: after `t_analyze`: `p_analysis_done:1, p_review:1`; after `t_waive_review`: `p_analysis_done:1, p_waived:1`; after `t_join_waived`: `p_analysis_done:1, p_decision:1`; after `t_authorize`: `p_analysis_done:1, sink:1` != `fm`. Again dead, no enabled transition. Even when `t_analyze` precedes `t_authorize`, exact final marking is unreachable on waiver branch. Standard path `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize` does reach `sink:1` exactly, confirming defect is waiver-specific.

# 4. Minimal-Repair Alternatives
Edit-cost model: `cost = 1×(#arc adds + #arc removes) + 2×(#place adds + #place removes) + 3×(#transition adds + #transition removes)`. Incident arcs counted separately.Cleanup of now-isolated nodes is mandatory to remain a workflow net and is included.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R-A Convergent join (merge)** | Remove `t_waive_review->p_waived`, `p_waived->t_join_waived`, `t_join_waived->p_decision`; Add `t_waive_review->p_review_done`; Delete place `p_waived`, transition `t_join_waived` | 4 arcs×1 +1 place×2 +1 trans×3 = **9** | Mandatory analysis on both paths; single AND-join `t_join_normal` gates `t_authorize` | Waiver and standard converge to same `p_review_done`; visible labels still differ, downstream place identity lost | Loses audit distinguishability downstream; silent variation removed |
| **R-B Separate AND-join (preserve identity)** | Add `p_analysis_done -> t_join_waived` only; `t_join_waived` becomes 2-input: `p_waived` + `p_analysis_done` -> `p_decision` | 1 arc×1 = **1** | Mandatory analysis on waiver path; `p_waived` vs `p_review_done` retained; parallel + choice structure unchanged | `t_join_waived` no longer fireable before analysis; both joins share input `p_analysis_done` but are mutually exclusive via review choice | Introduces non-free-choice sharing of `p_analysis_done` between two silent joins; potential confusion / duplicate silent enabling logic |
| **R-C Optional analysis (explicit policy change)** | R-A edits + Add silent `t_skip_analysis`: `p_analysis -> p_analysis_done` (1 trans +2 arcs) | 9 +2 arcs×1 +1 trans×3 = **14** | Parallel start preserved; clean completion preserved | **Policy change:** analysis becomes skippable on any path: trace `Register, Waiver, Authorize` without `Analyze` now accepted | Accidentally bypasses mandatory analysis; violates original business rule unless waiver-is-exemption is explicitly approved |

Minimality justification: The defect is exactly one missing synchronization precondition. Therefore lower bound for a mandatory-analysis fix is 1 arc-add, achieved by R-B, which is globally minimal and cannot be beaten without zero edits (zero edits leaves defect). R-A is minimal within the convergent family: to converge you must redirect the waiver output (1 remove +1 add) and you cannot leave `p_waived` and `t_join_waived` dangling in a workflow net, so their incident arcs and nodes must be removed. Any convergent net without dangling nodes costs at least that. R-C is minimal for the optional-analysis policy because optionality needs an additional silent bypass path; it necessarily costs more than R-A/R-B. R-A and R-B tie on visible language but differ structurally in silent branching and place identity, so they are distinct repairs, while R-C differs semantically in accepted visible traces.

# 6. Diagnostic and Reachability Code
```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

# Assumes original: net, im, fm and repaired: repaired_net, repaired_im, repaired_fm exist

def fire_and_print(net, marking, trans_name):
    """Fire transition by name if enabled, print marking. Checks enabledness."""
    trans_by_name = {t.name: t for t in net.transitions}
    t = trans_by_name.get(trans_name)
    if t is None:
        print(f"transition {trans_name} not found")
        return marking
    enabled = pm4py.get_enabled_transitions(net, marking)
    if t not in enabled:
        print(f"NOT ENABLED: {trans_name} in {marking} | enabled: {[x.name for x in enabled]}")
        return marking
    # fire manually to stay version-independent
    new_marking = Marking(marking)
    for a in t.in_arcs:
        new_marking[a.source] -= 1
        if new_marking[a.source] == 0:
            del new_marking[a.source]
    for a in t.out_arcs:
        new_marking[a.target] = new_marking.get(a.target, 0) + 1
    print(f"fired {trans_name} -> {dict((p.name, c) for p, c in new_marking.items())}")
    return new_marking

def diagnose(label, n, i, f):
    print(f"\n=== {label} ===")
    print("is_workflow_net:", pm4py.check_is_workflow_net(n))
    print("soundness:")
    print(pm4py.check_soundness(n, i, f, print_diagnostics=True))
    print("enabled in initial:", [t.name for t in pm4py.get_enabled_transitions(n, i)])
    rg = pm4py.convert_to_reachability_graph(n, i, f)
    print(f"reachability graph: {len(rg.states)} states, {len(rg.transitions)} arcs")
    return rg

rg_orig = diagnose("ORIGINAL", net, im, fm)
rg_rep = diagnose("REPAIRED", repaired_net, repaired_im, repaired_fm)

# Counterexample replay on original (early authorize)
print("\n--- replay waiver-early on ORIGINAL ---")
m = Marking(im)
for name in ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize"]:
    m = fire_and_print(net, m, name)
print("exact fm reached?", m == fm, "sink marked?", m.get(list(net.places)[0], 0))

# Same prefix on repaired: join_waived should NOT be enabled before analyze
print("\n--- replay waiver-early on REPAIRED (should block) ---")
m2 = Marking(repaired_im)
for name in ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_analyze", "t_join_waived", "t_authorize"]:
    m2 = fire_and_print(repaired_net, m2, name)
print("exact fm reached?", m2 == repaired_fm)

Original `check_soundness` reports unsound — option to complete / proper completion violated on waiver branch, leftover token, diagnostics flag improper completion. Repaired `check_soundness` reports sound. `get_enabled_transitions` after `t_waive_review` includes `t_join_waived` in original but not in repaired until `t_analyze` fires. Reachability of original contains dead markings with `sink+leftover`; repaired does not. No numeric sizes are claimed here beyond what the code prints at runtime.

# 7. Repair Trade-Offs and Residual Risks
- **Distinguishability:** R-B retains `p_waived` vs `p_review_done` and separate silent joins, so audit can distinguish waiver from standard downstream. R-A merges to `p_review_done`; only transition labels in the log distinguish them, process state loses the distinction. If waiver must be formally recorded for compliance, R-A is weaker.
- **Duplicate behavior / confusion via silent transitions:** R-B shares `p_analysis_done` between `t_join_normal` and `t_join_waived`. This is non-free-choice confusion: enabledness of one silent join depends on which review token exists. It is deterministic here because `p_review_done`/`p_waived` are exclusive, but discovery or analysis tools may report confusion or duplicate silent behavior. R-A has a single silent join and avoids this.
- **Soundness vs alignment:** Soundness only guarantees option to complete, proper completion, and no dead transitions. Both R-A and R-B can be sound yet still misalign if e.g. analysis were accidentally skippable. Soundness does not prove authorization is gated by both branches or that waiver semantics are correct.
- **Regression traces:** Positive: `Register, AnalyzeStandardReview, Authorize` in both orders; `Register, AnalyzeWaiver, Authorize` in both orders — all must reach exact `fm`. Negative: `Register, Waiver, JoinWaived, Authorize` without `Analyze` must be impossible; any trace reaching `sink` with leftover `p_analysis(_done)` must be impossible; `Authorize` never before both `Analyze` and review outcome.
- **Detecting accidental bypass:** Assert `t_authorize` is never enabled when `p_analysis_done` is unmarked; mine event logs for `Authorize` without preceding `Analyze`; add place invariant check that waiver path still consumes `p_analysis_done`; test R-C style skip trace is rejected. Monitor for new silent transitions that produce `p_analysis_done` or `p_decision` without visible predecessors.

# 8. Final Recommendation
**Deploy R-B (separate AND-join, one added arc `p_analysis_done->t_join_waived`).** It is the only minimal fix that retains mandatory analysis, preserves the formally recorded waiver state for audit, and changes no visible labels. Cost 1 versus 9 for merging makes review and rollback trivial.

**Fallback R-A (convergent join).** If confusion analysis or mining tools penalize shared-input silent joins, or if downstream logic should not branch on waiver identity, deploy the merged join. Accept loss of place-level distinguishability in exchange for a single synchronization point and simpler mental model. Explicitly reject silent skipping of analysis unless business approves the R-C policy change.
