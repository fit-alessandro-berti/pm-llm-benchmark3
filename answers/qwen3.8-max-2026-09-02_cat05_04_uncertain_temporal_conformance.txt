import datetime as dt
import itertools
from zoneinfo import ZoneInfo
import pandas as pd
try:
    import pm4py
except Exception:
    pm4py = None

UTC = dt.timezone.utc

def sec(x): return pd.Timedelta(seconds=x)

def parse_utc(s): return pd.Timestamp(s, tz='UTC')

def parse_local(s): return dt.datetime.fromisoformat(s.replace(' ', 'T'))

def convert_local_interval(start_dt, end_dt, tz_name, fold=0):
    tz = ZoneInfo(tz_name)
    s = start_dt.replace(tzinfo=tz, fold=fold).astimezone(UTC)
    e = end_dt.replace(tzinfo=tz, fold=fold).astimezone(UTC)
    return pd.Timestamp(s), pd.Timestamp(e)

def apply_offset(rec_utc, offset_bounds):
    lo, hi = rec_utc
    a,b = offset_bounds
    return (lo - sec(b), hi - sec(a))

def hub_interval(recorded):
    t=parse_utc(recorded)
    return [(t-sec(1.5), t+sec(1.5))]

def sensor_interval(recorded):
    t=parse_utc(recorded)
    rec=(t-sec(5), t+sec(5))
    return [apply_offset(rec, (-5,5))]

def floor_minute_local(recorded, tz_name, offset_bounds, fold=0):
    start=parse_local(recorded)
    start=start.replace(second=0, microsecond=0)
    end=start+dt.timedelta(minutes=1)
    utc=convert_local_interval(start,end,tz_name,fold)
    return apply_offset(utc, offset_bounds)

def nearest_local(recorded, tz_name, half_sec, offset_bounds, fold=0, entry_delay=(0,0)):
    center=parse_local(recorded)
    start=center-dt.timedelta(seconds=half_sec)
    end=center+dt.timedelta(seconds=half_sec)
    utc=convert_local_interval(start,end,tz_name,fold)
    rec=apply_offset(utc, offset_bounds)
    d0,d1=entry_delay
    return [(rec[0]-sec(d1), rec[1]-sec(d0))]

def legacy_ber_floor(recorded):
    return [floor_minute_local(recorded,'Europe/Berlin',(-60,60),fold=f) for f in (0,1)]

## 1. Normalization Assumptions

I use conservative, closed UTC feasibility intervals unless explicitly stated otherwise. A point timestamp is treated as a display artifact, not as the true event time.

**Clock-offset direction.** For a source clock, `clock_offset = recorded_clock - true_clock`. If the offset bound is `[a, b]`, then for a recorded-clock interval `[R_low, R_high]` the true-time interval is:

`[R_low - b, R_high - a]`.

**Order of uncertainty propagation.** Timestamp-resolution / rounding uncertainty is applied first, producing a recorded-clock interval. Clock-offset uncertainty is applied second.

**Rounding / display semantics.**

- **HUB:** displayed second with ±0.5 s measurement uncertainty, then offset ±1 s. Result: `[R - 1.5 s, R + 1.5 s]`.
- **OPS-BER:** floor to minute. Displayed `HH:MM` means local clock time in `[HH:MM:00, HH:MM:59.999]`. I conservatively use `[HH:MM:00, HH:MM+1:00]` before offset correction.
- **SENSOR:** round to nearest 10 s. Recorded `T` means source-clock interval `[T - 5 s, T + 5 s]`, then offset ±5 s.
- **VENDOR-NY:** floor to minute, then offset ±180 s.
- **LEGACY-BER:** floor to minute, then offset ±60 s. DST fold handled as alternative intervals.
- **MOBILE-LON:** round to nearest minute, i.e. `[T - 30 s, T + 30 s]`, then offset ±300 s. User-entry delay is treated separately below.

**Time-zone conversion.** Local wall-clock intervals are converted to UTC using the appropriate IANA zone:

- `Europe/Berlin` on 2026-06-01: CEST, UTC+2.
- `America/New_York` on 2026-06-01: EDT, UTC4.
- `Europe/London` on 2026-06-01: BST, UTC+1.
- `Europe/Berlin` on 2025-10-26: DST fold. Local times 02:00–02:59 may be CEST UTC+2, first fold, or CET UTC+1, second fold.

**DST fold semantics for T-405.** Because the fold was not logged, each LEGACY-BER event in the ambiguous hour initially produces a union of two disjoint UTC intervals. Ingestion order is then used as a semantic constraint: `Alert_Received` precedes `Investigation_Start`, which precedes `Containment_Complete`. This eliminates some fold combinations but does not make surviving timestamps exact.

**Inferred starts.**

- **T-404:** `Investigation_Start` is inferred as `Investigation_Complete - investigation_duration`, with signed duration `[18, 25]` minutes. All HUB uncertainty is retained.
- **T-407:** `Alert_Received` is inferred from `Alert_Sent + delivery_latency`, with latency `[0, 20]` minutes. `Alert_Sent` is not treated as identical to `Alert_Received`.

**Causal / ordering constraints.** For lifecycle pairs, I enforce nonnegative feasible durations: later activity must not precede earlier activity. If two intervals overlap, the minimum feasible duration is 0 s unless other evidence imposes a stricter lower bound. For T-407, I use the plausible but explicit assumption that receipt cannot be after `Investigation_Start`. If that assumption is rejected, T-407 S1 becomes less testable; this is noted in evidential sufficiency.

**Mobile entry delay for T-406.** I assume the up-to-five-minute entry delay is **occurrence-to-record latency**, not merely a record-creation artifact. Therefore the actual `Investigation_Start` may be up to 300 s earlier than the corrected mobile record time. This materially widens the interval earlier. If instead the delay were treated as only a record-creation delay and the user-entered time were assumed to represent occurrence, the T-406 investigation-start interval would be `[12:08:30Z, 12:19:30Z]` instead of `[12:03:30Z, 12:19:30Z]`.

**Baseline conformance parameters.** Baseline SLA tolerance is 0 additional minutes. Baseline temporal-profile zeta is `zeta = 1`. Sensitivity analyses vary SLA tolerance and zeta.

**Material assumptions.** The conclusions most sensitive to assumptions are:

- T-404: inferred start from signed duration.
- T-405: DST fold resolution by ingestion order.
- T-406: mobile entry delay treated as occurrence uncertainty.
- T-407: inferred receipt and receipt-before-start assumption.
- T-409: weak ±12-minute OPS-BER offset estimate.

```python
# Executable Python 3.11+
# Requires pandas. PM4Py is optional at runtime; if unavailable, interval analysis still runs.
# This code does not read external files.

import datetime as dt
import itertools
from zoneinfo import ZoneInfo

import pandas as pd

try:
    import pm4py
except Exception:
    pm4py = None

UTC = dt.timezone.utc
EPS = 1e-6


def sec(x: float) -> pd.Timedelta:
    return pd.Timedelta(seconds=x)


def parse_utc(s: str) -> pd.Timestamp:
    return pd.Timestamp(s, tz="UTC")


def parse_local(s: str) -> dt.datetime:
    return dt.datetime.fromisoformat(s.replace(" ", "T"))


def convert_local_interval(
    start_dt: dt.datetime,
    end_dt: dt.datetime,
    tz_name: str,
    fold: int = 0,
) -> tuple[pd.Timestamp, pd.Timestamp]:
    """Convert a naive local interval to UTC, honoring fold for ambiguous times."""
    tz = ZoneInfo(tz_name)
    s = start_dt.replace(tzinfo=tz, fold=fold).astimezone(UTC)
    e = end_dt.replace(tzinfo=tz, fold=fold).astimezone(UTC)
    return pd.Timestamp(s), pd.Timestamp(e)


def apply_clock_offset(
    rec_utc: tuple[pd.Timestamp, pd.Timestamp],
    offset_bounds: tuple[float, float],
) -> tuple[pd.Timestamp, pd.Timestamp]:
    """
    clock_offset = recorded - true.
    If offset in [a, b], true = recorded - offset => [rec_low - b, rec_high - a].
    """
    lo, hi = rec_utc
    a, b = offset_bounds
    return (lo - sec(b), hi - sec(a))


def hub_interval(recorded_utc: str) -> list[tuple[pd.Timestamp, pd.Timestamp]]:
    """HUB exact displayed second +/-0.5s, then +/-1s clock offset."""
    t = parse_utc(recorded_utc)
    return [(t - sec(1.5), t + sec(1.5))]


def sensor_interval(recorded_utc: str) -> list[tuple[pd.Timestamp, pd.Timestamp]]:
    """SENSOR nearest 10s: +/-5s rounding, then +/-5s offset."""
    t = parse_utc(recorded_utc)
    rec = (t - sec(5), t + sec(5))
    return [apply_clock_offset(rec, (-5, 5))]


def floor_minute_local(
    recorded_local: str,
    tz_name: str,
    offset_bounds: tuple[float, float],
    fold: int = 0,
) -> tuple[pd.Timestamp, pd.Timestamp]:
    """Floor-to-minute local display, converted to UTC, then clock offset."""
    start = parse_local(recorded_local)
    start = start.replace(second=0, microsecond=0)
    end = start + dt.timedelta(minutes=1)
    utc = convert_local_interval(start, end, tz_name, fold=fold)
    return apply_clock_offset(utc, offset_bounds)


def nearest_local(
    recorded_local: str,
    tz_name: str,
    half_seconds: float,
    offset_bounds: tuple[float, float],
    fold: int = 0,
    entry_delay: tuple[float, float] = (0, 0),
) -> list[tuple[pd.Timestamp, pd.Timestamp]]:
    """
    Nearest rounding in local time, UTC conversion, clock offset, then optional entry delay.
    entry_delay=(d0,d1) means occurrence = record_true_time - delay, delay in [d0,d1].
    """
    center = parse_local(recorded_local)
    start = center - dt.timedelta(seconds=half_seconds)
    end = center + dt.timedelta(seconds=half_seconds)
    utc = convert_local_interval(start, end, tz_name, fold=fold)
    rec = apply_clock_offset(utc, offset_bounds)
    d0, d1 = entry_delay
    return [(rec[0] - sec(d1), rec[1] - sec(d0))]


def legacy_ber_floor(recorded_local: str) -> list[tuple[pd.Timestamp, pd.Timestamp]]:
    """LEGACY-BER ambiguous DST fold: return both fold alternatives."""
    return [
        floor_minute_local(recorded_local, "Europe/Berlin", (-60, 60), fold=f)
        for f in (0, 1)
    ]


def ordered_duration_interval_pair(
    a: tuple[pd.Timestamp, pd.Timestamp],
    b: tuple[pd.Timestamp, pd.Timestamp],
) -> tuple[float, float] | None:
    """
    Feasible durations b-a for a in A, b in B, constrained b >= a.
    Returns seconds interval or None if no ordered pair exists.
    """
    a0, a1 = a
    b0, b1 = b

    # No feasible ordered pair if latest B is before earliest A.
    if b1 < a0:
        return None

    # If all B is strictly after all A, all ordered pairs are feasible.
    if b0 > a1:
        return ((b0 - a1).total_seconds(), (b1 - a0).total_seconds())

    # Intervals overlap or touch: minimum feasible duration is 0.
    return (0.0, (b1 - a0).total_seconds())


def merge_intervals(
    intervals: list[tuple[float, float]],
) -> list[tuple[float, float]]:
    """Merge overlapping/adjacent duration intervals."""
    if not intervals:
        return []
    xs = sorted(intervals)
    merged = [list(xs[0])]
    for s, e in xs[1:]:
        if s <= merged[-1][1] + EPS:
            merged[-1][1] = max(merged[-1][1], e)
        else:
            merged.append([s, e])
    return [(s, e) for s, e in merged]


def ordered_duration_intervals(
    A: list[tuple[pd.Timestamp, pd.Timestamp]],
    B: list[tuple[pd.Timestamp, pd.Timestamp]],
) -> list[tuple[float, float]]:
    """Duration interval union for two event-time interval unions."""
    out = []
    for a in A:
        for b in B:
            d = ordered_duration_interval_pair(a, b)
            if d is not None:
                out.append(d)
    return merge_intervals(out)


def joint_feasible(
    a: tuple[pd.Timestamp, pd.Timestamp],
    b: tuple[pd.Timestamp, pd.Timestamp],
    c: tuple[pd.Timestamp, pd.Timestamp],
) -> bool:
    """Exists a_time <= b_time <= c_time for three intervals."""
    lo = max(a[0], b[0])
    hi = min(b[1], c[1])
    return lo <= hi and a[0] <= c[1]


def classify_sla(
    durs: list[tuple[float, float]],
    limit_sec: float,
) -> str:
    if not durs:
        return "INDETERMINATE"
    if all(e <= limit_sec + EPS for _, e in durs):
        return "CERTAIN_PASS"
    if all(s > limit_sec + EPS for s, _ in durs):
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"


def classify_profile(
    durs: list[tuple[float, float]],
    mean: float,
    sd: float,
    zeta: float,
) -> str:
    if not durs:
        return "INDETERMINATE"
    low = mean - zeta * sd
    high = mean + zeta * sd

    if all(s >= low - EPS and e <= high + EPS for s, e in durs):
        return "CERTAIN_PASS"

    # Every duration interval wholly outside the band, whether below or above.
    if all((s > high + EPS) or (e < low - EPS) for s, e in durs):
        return "CERTAIN_VIOLATION"

    return "POSSIBLE_VIOLATION"
```

## 6. Evidential Sufficiency

This section identifies the minimum additional evidence needed to convert INDETERMINATE or POSSIBLE_VIOLATION results into certain conclusions. Evidence types are:

- **Synchronization evidence:** tighter clock-offset bounds, NTP telemetry, PTP, signed clock-sync reports.
- **Missing activity evidence:** an actual missing start, receipt, or close event record.
- **Duration evidence:** signed or system-generated durations independent of endpoint timestamps.
- **Semantic evidence:** definitions of event meaning, causal order, entry delay, or receipt acknowledgment.

## 7. Governance Recommendation

**1. Store canonical UTC timestamps.** Store all event times in UTC as the system of record. Preserve the original local wall-clock value, time-zone identifier, and DST fold indicator as separate provenance fields.

**2. Retain raw timestamps and rounding metadata.** Do not overwrite raw values with normalized values. For each record, retain:

- Raw displayed value.
- Display resolution: exact second, floor minute, nearest 10 s, nearest minute, etc.
- Rounding semantics: floor, ceiling, nearest, unknown.
- Source system and ingestion timestamp.

**3. Record clock-offset telemetry at event time.** Daily NTP diagnostics are insufficient for high-stakes SLA decisions near boundaries. Systems should record per-event or near-event offset estimates, or at least the active offset bound at the time of the event.

**4. Preserve uncertainty intervals in analytics.** Compliance engines should support intervals or unions of intervals. A point timestamp should be treated as a derived approximation, not as ground truth.

**5. Explicitly model DST folds.** For ambiguous local times, require an explicit fold field: first fold, second fold, or unknown. If unknown, preserve both alternatives and use ordering constraints only when semantically justified.

**6. Distinguish event semantics.** Define whether timestamps represent:

- Activity start.
- Activity completion.
- Record creation.
- User entry.
- Message sent.
- Message received.
- Acknowledgment.

`Alert_Sent` should not be treated as `Alert_Received` without delivery evidence. `Investigation_Complete` should not be treated as `Investigation_Start` without duration or start evidence.

**7. Capture causal identifiers.** Each incident should carry causal identifiers linking alert, receipt acknowledgment, investigation start, containment completion, and closure. Where receipt acknowledgment is absent, delivery-latency bounds should be recorded as evidence, not silently collapsed.

**8. Handle user-entered timestamps separately.** Mobile or manual timestamps should carry an entry-delay field or confidence score. Governance should state whether entry delay is treated as record-creation uncertainty or occurrence uncertainty. For enforcement, occurrence uncertainty is usually the safer interpretation.

**9. Define enforcement policy for intervals.** The organization should decide when interval overlap is sufficient for enforcement:

- **Strict enforcement:** only `CERTAIN_VIOLATION` results count as violations.
- **Risk-based enforcement:** `POSSIBLE_VIOLATION` triggers evidence collection or review.
- **Tolerance-based enforcement:** predefined SLA grace periods convert some possible violations into passes, but the tolerance must be legally and operationally approved.
- **Statistical profile enforcement:** temporal-profile deviations should not be treated as SLA violations unless policy explicitly combines statistical expectations with contractual SLAs.

**10. Avoid midpoint-only decisions for enforcement.** Midpoint logs are useful for diagnostics and tool compatibility, including PM4Py, but they are lossy. They should never be the sole basis for a certain SLA violation when interval evidence shows feasible pass or feasible violation outcomes.
