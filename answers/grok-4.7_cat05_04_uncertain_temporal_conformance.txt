## 1. Normalization Assumptions

True time is obtained from the recorded clock by `true = recorded − offset`, with `offset` inside the stated closed bound. Resolution is expanded first, then the offset bound is applied. For recorded clock `R ∈ [Rlo, Rhi]` and offset `∈ [a, b]`, true time is `[Rlo − b, Rhi − a]`. Uncertainties on different events are treated as independent, so a duration interval is `[Blo − Ahi, Bhi − Alo]`. A shared HUB clock bias that cancelled across two HUB events would shrink only the sub-second fringe cases in §4; it does not change any primary label below.

Resolution rules used:

- HUB, exact to the displayed second with measurement `±0.5 s`, plus clock offset `[-1 s, +1 s]`. Feasible true time is the displayed instant `±1.5 s`.
- Floor-to-minute (OPS-BER, VENDOR-NY, LEGACY-BER): displayed `hh:mm` means recorded clock `[hh:mm:00.000, hh:mm:59.999]`. That is the inclusive stand-in for `[hh:mm:00, hh:mm+1:00)`. The `0.001 s` gap does not cross any threshold used below.
- SENSOR, round to nearest 10 s: preimage `[displayed − 5 s, displayed + 5 s]` (tie endpoints included), then offset `[-5 s, +5 s]`, giving displayed `±10 s`. The `08:51:10` event is already a completion event, so it is not shifted again.
- MOBILE-LON, round to nearest minute: preimage `[displayed − 30 s, displayed + 30 s]`, then offset `[-300 s, +300 s]`.

Time zones on the case dates: 2026-06-01 is CEST (`Europe/Berlin`, UTC+2), BST (`Europe/London`, UTC+1), and EDT (`America/New_York`, UTC−4). 2025-10-26 is the EU fall-back day. Local `02:00`–`02:59` in `Europe/Berlin` is the union of CEST (UTC+2, earlier instant; fold E) and CET (UTC+1, later instant; fold L), each then widened by the legacy offset `[-60 s, +60 s]`.

DST order constraint for T-405: ingestion order is a constraint on true time (`Alert_Received`, then `Investigation_Start`, then `Containment_Complete`). Of the eight fold triples, only Alert=E, Investigation=L, Containment=L has any ordered realization, and every point in those three intervals is ordered. The other seven triples are impossible even at the extreme offsets. The surviving times stay intervals.

SLA rules are one-sided lateness caps: pass when duration `≤ 900 s` (S1), `≤ 2700 s` (S2), or `≤ 129600 s` (S3). A negative duration satisfies that inequality. It is also reported as a feasible lifecycle reversal. The temporal profile is two-sided and, unless a row says otherwise, is judged at zeta `1`. Acceptance is closed: average `± zeta × sd`. Primary SLA tolerance is `0`. A label is certain only relative to the feasible set defined here. Confidence is trust in that set.

T-404: `Investigation_Start = Investigation_Complete − D` with `D ∈ [18, 25]` minutes from the signed work record, composed with HUB uncertainty on the completion timestamp. The work-record range is not given a further clock offset.

T-406 entry delay, primary semantics (stale observation): the user-entered reading can denote an instant up to 5 minutes after occurrence, in addition to the mobile clock bound. Occurrence is the clock-corrected interval shifted earlier by `δ ∈ [0, 300 s]`. Upper endpoint is unchanged because `δ` may be `0`. Alternative semantics (recording lag), used only in §4: the entered value is already the user’s occurrence statement, and the five minutes only delay when the row was written, so they do not move occurrence.

T-407: `Alert_Sent` is not used as `Alert_Received`. The `[0, 20]` minute latency bound is conditional on delivery. With no acknowledgement, receipt is not established, so every pair that needs `Alert_Received` is indeterminate. A conditional interval is shown and is not classified as primary.

T-409: the daily OPS-BER bound `[-90 s, +120 s]` is not applied, because NTP diagnostics for that hour are missing. The weak engineering estimate `[-12 min, +12 min]` is the operative offset. Pairs that depend on it are low confidence. Discarding that estimate would make those pairs indeterminate; that alternative is stated on the affected rows.

## 5. PM4Py Temporal-Conformance Code

The block reconstructs the evidence, normalizes intervals with `zoneinfo`, keeps the DST fold as two candidates until the order filter, classifies interval durations, then builds a separate midpoint log explicitly marked lossy. Midpoints are centers of the feasible intervals in §2, not a substitute analysis. `pm4py.format_dataframe` and `pm4py.conformance_temporal_profile` run on that lossy log only. The script assumes a deviation element is a tuple `(activity_1, activity_2, observed_seconds, ...)` when it has that shape; the raw object is always printed because PM4Py versions differ on tuple width and on whether they test directly-follows pairs or every eventually-follows pair named in the profile. Boundary handling assumed for the script’s own midpoint column is inclusive (`within` fails only when `diff < mean − zeta·sd` or `diff > mean + zeta·sd`). PM4Py is not treated as a solver of timestamp uncertainty.

```python
#!/usr/bin/env python3
"""Interval SLA / temporal-profile conformance, plus a lossy midpoint PM4Py check.

The midpoint log is a lossy approximation. It is not the conformance result.
"""

from __future__ import annotations

from datetime import datetime, timedelta
from zoneinfo import ZoneInfo

import pandas as pd

UTC = ZoneInfo("UTC")
BERLIN = ZoneInfo("Europe/Berlin")
LONDON = ZoneInfo("Europe/London")
NEW_YORK = ZoneInfo("America/New_York")

PROFILE = {
    ("Alert_Received", "Investigation_Start"): (600.0, 180.0),
    ("Investigation_Start", "Containment_Complete"): (2100.0, 600.0),
    ("Alert_Received", "Containment_Complete"): (2700.0, 720.0),
    ("Containment_Complete", "Close_Incident"): (86400.0, 21600.0),
}
SLA = {
    "S1 Alert_Received->Investigation_Start": 900.0,
    "S2 Investigation_Start->Containment_Complete": 2700.0,
    "S3 Containment_Complete->Close_Incident": 129600.0,
}
PAIRS = [
    ("S1", "Alert_Received", "Investigation_Start", 900.0, None),
    ("S2", "Investigation_Start", "Containment_Complete", 2700.0, None),
    ("S3", "Containment_Complete", "Close_Incident", 129600.0, None),
    ("P Alert->Start", "Alert_Received", "Investigation_Start", None,
     ("Alert_Received", "Investigation_Start")),
    ("P Start->Containment", "Investigation_Start", "Containment_Complete", None,
     ("Investigation_Start", "Containment_Complete")),
    ("P Alert->Containment", "Alert_Received", "Containment_Complete", None,
     ("Alert_Received", "Containment_Complete")),
    ("P Containment->Close", "Containment_Complete", "Close_Incident", None,
     ("Containment_Complete", "Close_Incident")),
]


def utc(y, mo, d, h, mi, s=0, ms=0) -> datetime:
    return datetime(y, mo, d, h, mi, s, ms * 1000, tzinfo=UTC)


def shift(lo: datetime, hi: datetime, off_lo: timedelta, off_hi: timedelta):
    """true = recorded - offset, offset in [off_lo, off_hi]."""
    return lo - off_hi, hi - off_lo


def hub(ts: datetime):
    half = timedelta(milliseconds=500)
    off = timedelta(seconds=1)
    return shift(ts - half, ts + half, -off, off)


def floor_minute(local_naive: datetime, zone: ZoneInfo, off_lo_s: float, off_hi_s: float, fold: int | None):
    kwargs = {"tzinfo": zone}
    if fold is not None:
        kwargs["fold"] = fold
    start = local_naive.replace(**kwargs)
    # Inclusive stand-in for [minute, next minute): 59.999 s.
    end = start + timedelta(milliseconds=59999)
    rlo = start.astimezone(UTC)
    rhi = end.astimezone(UTC)
    return shift(rlo, rhi, timedelta(seconds=off_lo_s), timedelta(seconds=off_hi_s))


def round_window(local_naive: datetime, zone: ZoneInfo, half_width: timedelta, off_s: float):
    center = local_naive.replace(tzinfo=zone).astimezone(UTC)
    rlo, rhi = center - half_width, center + half_width
    off = timedelta(seconds=off_s)
    return shift(rlo, rhi, -off, off)


def dur(a, b):
    alo, ahi = a
    blo, bhi = b
    return (blo - ahi).total_seconds(), (bhi - alo).total_seconds()


def classify_upper(lo, hi, limit) -> str:
    if hi <= limit + 1e-6:
        return "CERTAIN_PASS"
    if lo > limit + 1e-6:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"


def classify_band(lo, hi, mean, sd, zeta) -> str:
    blo, bhi = mean - zeta * sd, mean + zeta * sd
    if lo >= blo - 1e-6 and hi <= bhi + 1e-6:
        return "CERTAIN_PASS"
    if hi < blo - 1e-6 or lo > bhi + 1e-6:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"


def build_intervals():
    """Return case -> activity -> (lo, hi) under the primary semantics."""
    ev = {}

    def put(case, activity, interval):
        ev.setdefault(case, {})[activity] = interval

    put("T-401", "Alert_Received", hub(utc(2026, 6, 1, 8, 0, 0)))
    put("T-401", "Investigation_Start", floor_minute(
        datetime(2026, 6, 1, 10, 14), BERLIN, -90, 120, None))
    put("T-401", "Containment_Complete", round_window(
        datetime(2026, 6, 1, 8, 51, 10), UTC, timedelta(seconds=5), 5))
    put("T-401", "Close_Incident", hub(utc(2026, 6, 2, 9, 0, 0)))

    put("T-402", "Alert_Received", hub(utc(2026, 6, 1, 9, 0, 0)))
    put("T-402", "Investigation_Start", floor_minute(
        datetime(2026, 6, 1, 11, 18), BERLIN, -90, 120, None))
    put("T-402", "Containment_Complete", hub(utc(2026, 6, 1, 10, 2, 0)))

    put("T-403", "Alert_Received", floor_minute(
        datetime(2026, 6, 1, 4, 0), NEW_YORK, -180, 180, None))
    put("T-403", "Investigation_Start", hub(utc(2026, 6, 1, 8, 16, 0)))
    put("T-403", "Containment_Complete", hub(utc(2026, 6, 1, 8, 58, 0)))

    complete = hub(utc(2026, 6, 1, 10, 35, 0))
    put("T-404", "Alert_Received", hub(utc(2026, 6, 1, 10, 0, 0)))
    put("T-404", "Investigation_Complete", complete)
    # start = complete - duration, duration in [18, 25] minutes.
    put("T-404", "Investigation_Start", (
        complete[0] - timedelta(minutes=25),
        complete[1] - timedelta(minutes=18),
    ))
    put("T-404", "Containment_Complete", hub(utc(2026, 6, 1, 10, 55, 0)))

    # T-405: both DST folds, then keep the only order-feasible triple.
    folds = {}
    for name, hh, mm in (
        ("Alert_Received", 2, 50),
        ("Investigation_Start", 2, 5),
        ("Containment_Complete", 2, 42),
    ):
        folds[name] = {
            "E": floor_minute(datetime(2025, 10, 26, hh, mm), BERLIN, -60, 60, fold=0),
            "L": floor_minute(datetime(2025, 10, 26, hh, mm), BERLIN, -60, 60, fold=1),
        }
    surviving = []
    for fa in ("E", "L"):
        for fi in ("E", "L"):
            for fc in ("E", "L"):
                a, i, c = folds["Alert_Received"][fa], folds["Investigation_Start"][fi], folds["Containment_Complete"][fc]
                # Existence of an ordered triple (non-strict; surviving gaps are strict).
                ordered = a[0] <= i[1] and i[0] <= c[1] and a[0] <= c[1] and not (a[0] > i[1] or i[0] > c[1])
                # Reject a triple whose intervals are wholly in the wrong order.
                wholly_bad = a[0] >= i[1] or i[0] >= c[1]
                if not wholly_bad and a[0] < i[1] and i[0] < c[1]:
                    surviving.append((fa, fi, fc, a, i, c))
    if len(surviving) != 1:
        raise RuntimeError(f"expected one DST triple, found {len(surviving)}: {[(s[0], s[1], s[2]) for s in surviving]}")
    fa, fi, fc, a, i, c = surviving[0]
    if (fa, fi, fc) != ("E", "L", "L"):
        raise RuntimeError(f"unexpected surviving folds {(fa, fi, fc)}")
    put("T-405", "Alert_Received", a)
    put("T-405", "Investigation_Start", i)
    put("T-405", "Containment_Complete", c)

    put("T-406", "Alert_Received", hub(utc(2026, 6, 1, 12, 0, 0)))
    reading = round_window(datetime(2026, 6, 1, 13, 14), LONDON, timedelta(seconds=30), 300)
    # Stale observation: occurrence = denoted instant minus delta, delta in [0, 300 s].
    put("T-406", "Investigation_Start", (reading[0] - timedelta(minutes=5), reading[1]))
    put("T-406", "Containment_Complete", hub(utc(2026, 6, 1, 12, 52, 0)))
    # Recording-lag alternative kept beside the primary map.
    ev["T-406-recording-lag"] = {
        "Alert_Received": ev["T-406"]["Alert_Received"],
        "Investigation_Start": reading,
        "Containment_Complete": ev["T-406"]["Containment_Complete"],
    }

    put("T-407", "Alert_Sent", hub(utc(2026, 6, 1, 14, 0, 0)))
    put("T-407", "Investigation_Start", hub(utc(2026, 6, 1, 14, 17, 0)))
    put("T-407", "Containment_Complete", hub(utc(2026, 6, 1, 14, 55, 0)))
    sent = ev["T-407"]["Alert_Sent"]
    ev["T-407-conditional-receipt"] = {
        "Alert_Received": (sent[0], sent[1] + timedelta(minutes=20)),
        "Investigation_Start": ev["T-407"]["Investigation_Start"],
        "Containment_Complete": ev["T-407"]["Containment_Complete"],
    }

    put("T-408", "Alert_Received", hub(utc(2026, 6, 1, 15, 0, 0)))
    put("T-408", "Investigation_Start", hub(utc(2026, 6, 1, 15, 10, 0)))
    put("T-408", "Containment_Complete", hub(utc(2026, 6, 1, 16, 5, 0)))
    put("T-408", "Close_Incident", hub(utc(2026, 6, 3, 6, 30, 0)))

    put("T-409", "Alert_Received", hub(utc(2026, 6, 1, 16, 0, 0)))
    put("T-409", "Investigation_Start", floor_minute(
        datetime(2026, 6, 1, 18, 4), BERLIN, -720, 720, None))
    put("T-409", "Containment_Complete", hub(utc(2026, 6, 1, 16, 35, 0)))
    return ev


def evidence_frame(ev) -> pd.DataFrame:
    rows = []
    for case, acts in ev.items():
        if case.endswith("-recording-lag") or case.endswith("-conditional-receipt"):
            continue
        for activity, (lo, hi) in acts.items():
            rows.append({
                "case_id": case,
                "activity": activity,
                "utc_lo": lo,
                "utc_hi": hi,
                "adopted_for_primary": activity != "Alert_Sent",
            })
    return pd.DataFrame(rows)


def classify_cases(ev):
    rows = []
    for case, acts in ev.items():
        for label, src, dst, sla_limit, profile_key in PAIRS:
            if src not in acts or dst not in acts:
                rows.append({
                    "case": case, "rule": label, "lo": None, "hi": None,
                    "zeta1": "INDETERMINATE", "zeta2": "INDETERMINATE", "zeta3": "INDETERMINATE",
                    "sla0": "INDETERMINATE", "sla2": "INDETERMINATE", "sla5": "INDETERMINATE",
                })
                continue
            lo, hi = dur(acts[src], acts[dst])
            row = {"case": case, "rule": label, "lo": round(lo, 3), "hi": round(hi, 3)}
            if profile_key is not None:
                mean, sd = PROFILE[profile_key]
                for zeta, col in ((1, "zeta1"), (2, "zeta2"), (3, "zeta3")):
                    row[col] = classify_band(lo, hi, mean, sd, zeta)
                row["sla0"] = row["sla2"] = row["sla5"] = ""
            else:
                row["zeta1"] = row["zeta2"] = row["zeta3"] = ""
                for extra, col in ((0, "sla0"), (120, "sla2"), (300, "sla5")):
                    row[col] = classify_upper(lo, hi, sla_limit + extra)
            rows.append(row)
    return pd.DataFrame(rows)


def midpoint(interval) -> datetime:
    lo, hi = interval
    return lo + (hi - lo) / 2


def midpoint_frame(ev) -> pd.DataFrame:
    """Lossy one-point approximation. Not valid for enforcement."""
    rows = []
    lifecycle = [
        "Alert_Received", "Investigation_Start", "Containment_Complete", "Close_Incident",
    ]
    for case, acts in ev.items():
        if not case.startswith("T-") or "-" in case[2:]:
            # Primary case ids only. Alternatives are interval-side comparisons.
            if case[:5] not in {f"T-{n}" for n in range(401, 410)} or "-" in case:
                continue
        for activity in lifecycle:
            if activity not in acts:
                continue
            rows.append({
                "case_id": case,
                "activity": activity,
                "timestamp_utc": midpoint(acts[activity]),
                "timestamp_semantics": "lossy_midpoint_approximation",
            })
    # T-404 keeps the inferred start midpoint and does not feed Investigation_Complete
    # into the profile log. T-407 has no Alert_Received midpoint.
    return pd.DataFrame(rows).sort_values(["case_id", "timestamp_utc"]).reset_index(drop=True)


def midpoint_classes(mid: pd.DataFrame) -> pd.DataFrame:
    rows = []
    for case, g in mid.groupby("case_id"):
        times = dict(zip(g["activity"], g["timestamp_utc"]))
        for label, src, dst, sla_limit, profile_key in PAIRS:
            if src not in times or dst not in times:
                continue
            diff = (times[dst] - times[src]).total_seconds()
            if profile_key is not None:
                mean, sd = PROFILE[profile_key]
                for zeta in (1, 2, 3):
                    blo, bhi = mean - zeta * sd, mean + zeta * sd
                    status = "MIDPOINT_PASS" if blo <= diff <= bhi else "MIDPOINT_FAIL"
                    rows.append({"case": case, "rule": label, "zeta_or_tol": f"zeta{zeta}",
                                 "midpoint_seconds": round(diff, 3), "midpoint_status": status})
            else:
                for extra, name in ((0, "tol0"), (120, "tol2"), (300, "tol5")):
                    status = "MIDPOINT_PASS" if diff <= sla_limit + extra else "MIDPOINT_FAIL"
                    rows.append({"case": case, "rule": label, "zeta_or_tol": name,
                                 "midpoint_seconds": round(diff, 3), "midpoint_status": status})
    return pd.DataFrame(rows)


def run_pm4py(mid: pd.DataFrame):
    """Invoke PM4Py on the lossy log. Return shape is version-dependent."""
    import pm4py

    formatted = pm4py.format_dataframe(
        mid.copy(),
        case_id="case_id",
        activity_key="activity",
        timestamp_key="timestamp_utc",
    )
    diagnostics = {}
    for zeta in (1, 2, 3):
        try:
            diagnostics[zeta] = pm4py.conformance_temporal_profile(
                formatted, PROFILE, parameters={"zeta": float(zeta)}
            )
        except TypeError:
            diagnostics[zeta] = pm4py.conformance_temporal_profile(
                formatted, PROFILE, zeta=float(zeta)
            )
    return formatted, diagnostics


def describe_pm4py(diagnostics, case_order) -> None:
    """Assumption: each trace yields a list of deviations.

    If an item is a tuple whose first two fields are activity names and a later
    field is a number, that number is read as the midpoint duration in seconds.
    Any other shape is printed raw and left unparsed.
    """
    print("\n=== PM4Py raw diagnostics on the LOSSY midpoint log ===")
    for zeta, diag in diagnostics.items():
        print(f"\nzeta={zeta} type={type(diag).__name__}")
        if not isinstance(diag, (list, tuple)):
            print(repr(diag))
            continue
        for idx, item in enumerate(diag):
            case = case_order[idx] if idx < len(case_order) else f"trace[{idx}]"
            print(f"  {case}: {item!r}")


def main() -> None:
    # Offset sanity checks for the case dates (fails closed on bad tzdata).
    assert datetime(2026, 6, 1, 12, 0, tzinfo=BERLIN).utcoffset() == timedelta(hours=2)
    assert datetime(2026, 6, 1, 12, 0, tzinfo=LONDON).utcoffset() == timedelta(hours=1)
    assert datetime(2026, 6, 1, 12, 0, tzinfo=NEW_YORK).utcoffset() == timedelta(hours=-4)
    e = datetime(2025, 10, 26, 2, 50, tzinfo=BERLIN, fold=0).astimezone(UTC)
    l = datetime(2025, 10, 26, 2, 50, tzinfo=BERLIN, fold=1).astimezone(UTC)
    assert e.hour == 0 and l.hour == 1

    ev = build_intervals()
    evidence = evidence_frame(ev)
    print("=== Normalized evidence (primary). Endpoints are feasible true times. ===")
    print(evidence.to_string(index=False))

    classes = classify_cases(ev)
    print("\n=== Interval classifications, including labeled alternatives ===")
    print(classes.to_string(index=False))

    mid = midpoint_frame(ev)
    print("\n=== LOSSY MIDPOINT LOG (approximation only; not the analysis) ===")
    print(mid.to_string(index=False))

    mid_cls = midpoint_classes(mid)
    print("\n=== Midpoint-only pass/fail, for disagreement hunting ===")
    print(mid_cls.to_string(index=False))

    print(
        "\nInterval-vs-midpoint disagreements that matter at the primary setting "
        "(SLA tolerance 0, profile zeta 1), using the script's own midpoint column:"
    )
    primary_cases = [f"T-{n}" for n in range(401, 410)]
    interval_primary = classes[classes["case"].isin(primary_cases)]
    for _, r in interval_primary.iterrows():
        if r["lo"] is None:
            continue
        rule = r["rule"]
```

## 7. Governance Recommendation

Store every event as a UTC instant, and retain the original local reading, the IANA zone, and the numeric offset that was applied. Keep the pre-rounding timestamp and a resolution code (exact second, floor minute, nearest 10 seconds, nearest minute). Attach clock-offset telemetry sampled at event time, with its validity window and a measured-versus-estimated flag. A missing NTP sample stays null. It is not replaced in the enforced record by a standing daily bound or by an engineering estimate; those may be stored beside the decision as explicitly weak bounds, which is the T-409 situation.

Model start and completion as different timestamps. Device feeds that emit completion events are mapped only to completion activities. On a DST fold, persist the fold bit or the UTC offset. A local time in `02:00`–`02:59` on a fall-back day without that bit remains a two-interval union until a causal rule, as in T-405, selects one side. Do not collapse the union to its midpoint for storage.

Give `Alert_Sent`, transport latency, and `Alert_Received` separate identities linked by a message id and a receipt ack. Do not score S1 from a send timestamp. For mobile entry, store device UTC, the user-typed value, and an explicit entry-lag field. The lag’s meaning — submission delay, or a stale reading of occurrence — is a controlled semantic flag. T-406 shows that the flag changes S2.

Keep the legal SLA and the statistical profile as separate decisions. Report the feasible duration interval with the label. Enforcement of a maximum uses the whole interval: a certain violation (every feasible duration above the cap) is the enforceable breach; a certain pass (every feasible duration within the cap) is clearance; overlap is a review trigger and is not sufficient for a penalty or for automatic closure; an indeterminate case is quarantined and is not scored. Minute-level tolerance and zeta are policy parameters and are applied to the interval, not to a reconstructed point. The midpoint log and `pm4py.conformance_temporal_profile` remain diagnostic reproductions. They are not the system of record, because a point inside the interval can pass while a feasible tail violates, and a point can fail while another feasible value passes.
