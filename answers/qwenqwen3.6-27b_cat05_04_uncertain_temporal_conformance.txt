## 1. Normalization Assumptions

1. **Clock-Offset Direction**: `true_clock = recorded_clock - clock_offset`. For a bound `[o_min, o_max]`, true time lies in `[recorded - o_max, recorded - o_min]`.
2. **Resolution Uncertainty**: Applied before offset correction. Floor-to-minute implies `[0, +59.999]` s relative to displayed time. Round-to-nearest-10s implies `[-5, +5]` s. Round-to-nearest-minute implies `[-30, +30]` s. HUB exact-to-second implies `[-0.5, +0.5]` s.
3. **Time-Zone Conversion**: Applied to the displayed time before offset adjustment. CEST = UTC+2, CET = UTC+1, EDT = UTC-4, BST = UTC+1.
4. **DST Folds (T-405)**: The 2025-10-26 02:00–02:59 local window occurs twice. Ingestion order `Alert(02:50) < Start(02:05) < Contain(02:42)` is only chronologically valid if `Alert` belongs to the first occurrence (CEST, UTC+2) and `Start`/`Contain` belong to the second occurrence (CET, UTC+1). This assumption is required to avoid negative durations and is explicitly preserved.
5. **Inferred Starts (T-404)**: `Investigation_Start` is derived as `Investigation_Complete - Duration`. Duration bounds `[1080, 1500]` s are subtracted interval-wise: `[Complete_max - Duration_max, Complete_min - Duration_min]`.
6. **Causal Constraints (T-407)**: `Alert_Received` is bounded by network latency `[0, 1200]` s after `Alert_Sent`, but causally cannot exceed `Investigation_Start`. The upper bound is clipped to `Start_min`.
7. **Mobile Entry Delay (T-406)**: Treated as uncertainty about the *occurrence time*, not merely recording latency. The feasible interval is shifted earlier by `[0, 300]` s, widening the lower bound. This reflects that a late entry implies the event happened earlier.
8. **Duration Arithmetic**: `Duration  [End_min - Start_max, End_max - Start_min]`. Negative lower bounds are clamped to `0` where causality dictates, but the full mathematical interval is retained for SLA/profile testing.
9. **Temporal Profile Acceptance**: Defined as `[avg - zeta*std, avg + zeta*std]`. Default `zeta=2` is used for primary classification; sensitivity analysis covers `zeta  {1, 2, 3}`.

## 7. Governance Recommendation

1. **UTC Storage & Raw Retention**: All systems must store events in UTC with raw, unrounded timestamps. Display formatting should occur only at the presentation layer.
2. **Clock Offset Telemetry**: Implement continuous NTP/PTP monitoring with automated telemetry publishing. Bound offsets dynamically; flag systems exceeding ±30s for remediation.
3. **Resolution Metadata**: Log timestamp resolution (e.g., `resolution: 1s`, `rounding: floor_minute`) alongside each event to enable precise interval reconstruction.
4. **Start/Complete Semantics**: Enforce explicit `*_Start` and `*_Complete` event types. Prohibit inferring starts from completions without documented duration bounds and uncertainty propagation.
5. **DST Fold Handling**: Systems in DST zones must log the specific offset (e.g., `UTC+2` vs `UTC+1`) or use non-ambiguous UTC internally. Ingestion pipelines must validate chronological order against fold-aware UTC conversion.
6. **Causal Identifiers**: Link related events (e.g., `Alert_Sent`  `Alert_Received`) with correlation IDs and delivery latency bounds to avoid missing-event indeterminate states.
7. **Interval Overlap Enforcement Policy**: 
   - **CERTAIN_PASS**: Auto-approve compliance.
   - **CERTAIN_VIOLATION**: Trigger immediate remediation and audit.
   - **POSSIBLE_VIOLATION**: Require manual review, treat as compliant for SLA reporting only if supporting provenance exists, but flag for statistical profile monitoring.
   - **INDETERMINATE**: Exclude from automated scoring; require evidence collection before adjudication.
   This policy prevents false positives from clock noise while ensuring genuine violations are not masked by uncertainty.
