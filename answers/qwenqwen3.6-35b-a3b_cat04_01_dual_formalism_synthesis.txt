This is documented as an admitted semantic loss.
4. **Duplicate visible labels**: Not permitted. Each activity retains a unique label to preserve traceability and avoid ambiguity in conformance checking or process mining.
5. **Approximation policy for the process tree**: A **permissive over-approximation** is used for cross-branch dependencies. The process tree's block-structured nature cannot natively express that `Execute Trial` must wait for both `Plan Verification` and `Design Corrective Action` while approvals run in parallel. The tree allows the trial cycle to start concurrently with planning and approvals, with `Release Material` acting as the hard synchronization point. This admits early trial starts but guarantees all obligations are met before release.
6. **"May overlap" interpretation**: Interpreted as the absence of a precedence constraint (logical concurrency in the model), not true physical concurrency. Activities may interleave arbitrarily as long as explicit order edges are respected.

# 3. PM4Py Process-Tree Model

**Compact Process-Tree Expression**
```text
SEQ(
  Register Deviation,
  PAR(
    SEQ(Contain Material, Plan Verification),
    SEQ(
      Analyze Root Cause,
      PAR(
        Design Corrective Action,
        XOR(Supervisor Review, PAR(Quality Review, Regulatory Review)),
        XOR(Consult Supplier, SilentTransition("Skip Supplier"))
      ),
      LOOP(Execute Trial, Inspect Trial)
    )
  ),
  Release Material,
  Archive Case
)
```

**Python Code**
```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator
from pm4py.objects.process_tree.operator import SilentTransition

def build_process_tree():
    # Leaf nodes
    reg = ProcessTree(Operator.LEAF, label="Register Deviation")
    cont = ProcessTree(Operator.LEAF, label="Contain Material")
    anal = ProcessTree(Operator.LEAF, label="Analyze Root Cause")
    plan = ProcessTree(Operator.LEAF, label="Plan Verification")
    desi = ProcessTree(Operator.LEAF, label="Design Corrective Action")
    supp = ProcessTree(Operator.LEAF, label="Supervisor Review")
    qual = ProcessTree(Operator.LEAF, label="Quality Review")
    regu = ProcessTree(Operator.LEAF, label="Regulatory Review")
    cons = ProcessTree(Operator.LEAF, label="Consult Supplier")
    skip = SilentTransition("Skip Supplier")
    exec_t = ProcessTree(Operator.LEAF, label="Execute Trial")
    insp = ProcessTree(Operator.LEAF, label="Inspect Trial")
    rel = ProcessTree(Operator.LEAF, label="Release Material")
    arch = ProcessTree(Operator.LEAF, label="Archive Case")

    # Subtrees
    seq_plan = ProcessTree(Operator.SEQUENCE, label=None)
    seq_plan.children = [cont, plan]
    cont.parent = seq_plan; plan.parent = seq_plan

    xor_risk = ProcessTree(Operator.XOR, label=None)
    xor_risk.children = [supp, ProcessTree(Operator.PARALLEL, label=None)]
    supp.parent = xor_risk
    qual.parent = xor_risk.children[1]; regu.parent = xor_risk.children[1]

    xor_supplier = ProcessTree(Operator.XOR, label=None)
    xor_supplier.children = [cons, skip]
    cons.parent = xor_supplier; skip.parent = xor_supplier

    par_analyze = ProcessTree(Operator.PARALLEL, label=None)
    par_analyze.children = [desi, xor_risk, xor_supplier]
    desi.parent = par_analyze; xor_risk.parent = par_analyze; xor_supplier.parent = par_analyze

    seq_analyze = ProcessTree(Operator.SEQUENCE, label=None)
    seq_analyze.children = [anal, par_analyze]
    anal.parent = seq_analyze; par_analyze.parent = seq_analyze

    loop_trial = ProcessTree(Operator.LOOP, label=None)
    loop_trial.children = [exec_t, insp]
    exec_t.parent = loop_trial; insp.parent = loop_trial

    # Insert loop into analyze sequence
    seq_analyze.children.append(loop_trial)
    loop_trial.parent = seq_analyze

    par_main = ProcessTree(Operator.PARALLEL, label=None)
    par_main.children = [seq_plan, seq_analyze]
    seq_plan.parent = par_main; seq_analyze.parent = par_main

    # Root sequence
    tree = ProcessTree(Operator.SEQUENCE, label=None)
    tree.children = [reg, par_main, rel, arch]
    reg.parent = tree; par_main.parent = tree; rel.parent = tree; arch.parent = tree

    return tree

tree = build_process_tree()
```

**Approximation Identification**
The process tree cannot represent the exact cross-branch dependency that `Execute Trial` waits for both `Plan Verification` and `Design Corrective Action`. Because process trees are strictly hierarchical, the trial loop is placed inside the `Analyze Root Cause` branch, making it run concurrently with `Plan Verification`. This is a **permissive over-approximation**: the tree admits traces where the trial starts before planning is complete. However, `Release Material` synchronizes all branches, ensuring business rules are ultimately satisfied. The model also admits early loop exit after any inspection, abstracting the data-driven pass/fail condition.

# 4. PM4Py POWL Model

**Compact POWL Description**
A partial-order DAG where `Register Deviation` fans out to `Contain Material` and `Analyze Root Cause`. `Contain Material` precedes `Plan Verification`. `Analyze Root Cause` precedes `Design Corrective Action`, the risk route (`Supervisor Review` XOR `Quality Review` + `Regulatory Review`), and `Consult Supplier`. `Plan Verification` and `Design Corrective Action` both precede `Execute Trial`. `Execute Trial` precedes `Inspect Trial`, which loops back via `Adjust Parameters`. `Release Material` has explicit precedence edges from `Plan Verification`, `Design Corrective Action`, all risk nodes, `Consult Supplier`, and `Inspect Trial`. `Release Material` precedes `Archive Case`.

**Python Code**
```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition, POWLModel
from pm4py.objects.process_tree.obj import Operator

def build_powl_model():
    powl = POWLModel()
    
    # Create transitions
    nodes = {
        "Register Deviation": Transition("Register Deviation"),
        "Contain Material": Transition("Contain Material"),
        "Analyze Root Cause": Transition("Analyze Root Cause"),
        "Plan Verification": Transition("Plan Verification"),
        "Design Corrective Action": Transition("Design Corrective Action"),
        "Supervisor Review": Transition("Supervisor Review"),
        "Quality Review": Transition("Quality Review"),
        "Regulatory Review": Transition("Regulatory Review"),
        "Consult Supplier": Transition("Consult Supplier"),
        "Execute Trial": Transition("Execute Trial"),
        "Inspect Trial": Transition("Inspect Trial"),
        "Adjust Parameters": Transition("Adjust Parameters"),
        "Release Material": Transition("Release Material"),
        "Archive Case": Transition("Archive Case")
    }
    skip_supplier = SilentTransition("Skip Supplier")
    
    for n in nodes.values(): powl.nodes.add(n)
    powl.nodes.add(skip_supplier)
    
    # Partial order
    order = StrictPartialOrder(powl)
    powl.order = order
    
    # Precedence edges
    edges = [
        ("Register Deviation", "Contain Material"),
        ("Register Deviation", "Analyze Root Cause"),
        ("Contain Material", "Plan Verification"),
        ("Analyze Root Cause", "Design Corrective Action"),
        ("Analyze Root Cause", "Supervisor Review"),
        ("Analyze Root Cause", "Quality Review"),
        ("Analyze Root Cause", "Regulatory Review"),
        ("Analyze Root Cause", "Consult Supplier"),
        ("Analyze Root Cause", skip_supplier),
        ("Plan Verification", "Execute Trial"),
        ("Design Corrective Action", "Execute Trial"),
        ("Execute Trial", "Inspect Trial"),
        ("Inspect Trial", "Adjust Parameters"),
        ("Adjust Parameters", "Execute Trial"),
        ("Plan Verification", "Release Material"),
        ("Design Corrective Action", "Release Material"),
        ("Supervisor Review", "Release Material"),
        ("Quality Review", "Release Material"),
        ("Regulatory Review", "Release Material"),
        ("Consult Supplier", "Release Material"),
        ("Inspect Trial", "Release Material"),
        ("Release Material", "Archive Case")
    ]
    
    for src, tgt in edges:
        order.add_edge(nodes[src], tgt if isinstance(tgt, str) else tgt)
        
    # Operators
    powl.operators.add(OperatorPOWL(Operator.XOR, [nodes["Supervisor Review"], nodes["Quality Review"], nodes["Regulatory Review"]], name="RiskRoute"))
    powl.operators.add(OperatorPOWL(Operator.XOR, [nodes["Consult Supplier"], skip_supplier], name="SupplierChoice"))
    powl.operators.add(OperatorPOWL(Operator.LOOP, [nodes["Execute Trial"], nodes["Inspect Trial"], nodes["Adjust Parameters"]], name="TrialCycle"))
    
    return powl

powl = build_powl_model()
```

**Concurrency Explanation**
Nodes intentionally left without order edges may execute concurrently because POWL semantics treat the partial order as a maximal concurrency constraint. For example, `Supervisor Review`, `Quality Review`, and `Regulatory Review` lack explicit edges between them (grouped under `RiskRoute`), so any interleaving is permitted. `Consult Supplier` and `Execute Trial` have no direct edge, allowing them to overlap. `Release Material` waits only for explicit incoming edges; all other nodes are free to proceed in parallel once their predecessors complete.

# 7. Preferred Representation and Validation Plan

**Canonical Representation**: POWL. Its native support for arbitrary partial orders, explicit cross-branch synchronization, and operator grouping makes it semantically faithful to the non-block-structured dependencies without requiring duplication or artificial sequencing.

**Validation Plan**:
1. **Conversion to Petri Net**: Use `pm4py.convert_to_petri_net(powl)` to generate an accepting Petri net. Verify that silent transitions are properly handled as internal places/transitions.
2. **Soundness Checking**: Run `pm4py.check_soundness(net, im, fm, print_diagnostics=True)` to ensure every reachable marking can reach the final marking and no deadlocks/livelocks exist.
3. **Bounded/Sampled Playout**: Use `pm4py.play_out(net, ...)` with a depth limit (e.g., 20 transitions) to generate stochastic traces. Collect 1000 samples to verify distribution aligns with expected concurrency patterns.
4. **Positive/Negative Trace Tests**: Feed the 8 witness traces (and 10 additional synthetic ones) through `pm4py.conformance_diagnostics_heuristic_alignments(trace, net, im, fm)` to confirm acceptance/rejection matches the table.
5. **Silent/Duplicate Label Check**: Extract the Petri net's transition labels. Assert `len(set(labels)) == len(labels)` to guarantee no label duplication. Simulate silent firing sequences to ensure they do not create spurious reachable markings that bypass synchronization points.
6. **Limitations**: Bounded playout cannot guarantee coverage of unbounded loop iterations; silent transitions may introduce non-determinism in playout engines; POWL-to-Petri conversion may flatten some operator semantics into implicit places, potentially obscuring the original XOR/LOOP intent in the net structure.

# 8. Final Self-Critique

1. **Semantic approximation of loop guard**: The `LOOP` operator abstracts away the data-driven pass/fail condition. Both models permit exiting the trial cycle after a failed inspection or looping indefinitely, which could mislead conformance checkers into accepting non-compliant cases if external data validation is not enforced.
2. **Process-tree concurrency loss**: The permissive over-approximation allows `Execute Trial` to start before `Plan Verification` completes. While `Release Material` synchronizes everything, performance or resource planning based on the process tree would underestimate early-stage parallelism and misrepresent actual throughput.
3. **POWL operator grouping vs. DAG semantics**: The `OperatorPOWL` definitions are metadata annotations in PM4Py and do not structurally constrain execution beyond the edges. If the model is exported to a tool that strictly enforces operator semantics as execution constraints, the XOR and LOOP groupings might be interpreted differently than intended, requiring careful exporter validation.
