## 1. Normalization Assumptions

### Clock-offset direction and timestamp resolution
- `clock_offset = recorded_clock - true_clock` (as defined). True time = recorded time - offset.
- Apply timestamp-resolution uncertainty **before** clock correction. For example:
  - OPS-BER "floor to minute" means recorded time is in [10:14:00, 10:14:59.999]. True time is then in [recorded_time - 120s, recorded_time - (-90s)] = [recorded_time - 120s, recorded_time + 90s] after applying clock offset bounds.

### Time-zone conversion and DST handling
- Use IANA time zones (e.g., `Europe/Berlin`, `America/New_York`).
- For **LEGACY-BER on 2025-10-26**, the DST fold ambiguity (02:00–02:59) is preserved as two possible UTC intervals:
  - **Standard time (CET)**: UTC+1  02:00 CET = 01:00 UTC
  - **Daylight time (CEST)**: UTC+2  02:00 CEST = 00:00 UTC
  - Thus, any local time in [02:00, 02:59] maps to a union of two UTC intervals:
    - [01:00, 01:59] UTC (CET)
    - [00:00, 00:59] UTC (CEST)
  - Ingestion order (Alert_Received < Investigation_Start < Containment_Complete) rules out some combinations but not all.

### Mobile entry delay (T-406)
- User may have entered the displayed time **up to 5 minutes late** in addition to clock offset.
- This is treated as a **shift in the recorded time**, not the true occurrence time. The feasible true time interval is derived from the **shifted recorded time** minus clock offset bounds.
- Example: Recorded time = 13:14 BST (UTC+1). Entry delay shifts recorded time to [13:14:00, 13:19:00] BST. True time is then in [recorded_time - 300s, recorded_time + 300s] after clock offset correction.

### Inferred starts (T-404)
- Investigation_Start is missing. A signed work record states investigation duration was between 18 and 25 minutes.
- We infer Investigation_Start  [Containment_Complete - 25 minutes, Containment_Complete - 18 minutes].
- This is treated as a **feasible interval**, not a point estimate.

### Causal constraints (T-407)
- Alert_Sent is not Alert_Received. Network evidence bounds delivery latency to [0, 20] minutes.
- We assume Alert_Received  [Alert_Sent, Alert_Sent + 20 minutes].
- Causal assumption: Alert_Received  Investigation_Start (plausible but not logged).

### Rounding semantics
- **Round to nearest**: ±50% of the rounding unit (e.g., ±5s for 10s rounding).
- **Floor to minute**: [0, 59.999] seconds added to the minute.
- **Round to nearest minute**: ±30 seconds added to the minute.

### SLA vs. temporal profile
- SLA is a **hard maximum**; temporal profile is a **statistical expectation** with mean ± zeta * std.
- A case can satisfy SLA but violate the temporal profile (or vice versa).

## 5. PM4Py Temporal-Conformance Code

```python
import pandas as pd
from datetime import datetime, timedelta
import pytz
from typing import List, Tuple, Union

# --- Helper: Convert local time to UTC interval ---
def local_to_utc_interval(
    local_dt: datetime,
    tz: str,
    rounding: str,
    clock_offset_bounds: Tuple[int, int],
    dst_ambiguity: bool = False,
    entry_delay_bounds: Tuple[int, int] = (0, 0)
) -> List[Tuple[datetime, datetime]]:
    """
    Convert a local recorded time to a list of possible UTC intervals.
    - rounding: 'floor_minute', 'round_minute', 'round_10s', 'exact'
    - clock_offset_bounds: (min_offset_seconds, max_offset_seconds)
    - dst_ambiguity: if True, handle DST fold for Europe/Berlin on 2025-10-26
    - entry_delay_bounds: (min_delay, max_delay) in seconds (for mobile entry delay)
    """
    # Apply entry delay shift to recorded time (shifts the recorded time, not true time)
    if entry_delay_bounds != (0, 0):
        min_delay, max_delay = entry_delay_bounds
        recorded_min = local_dt - timedelta(seconds=max_delay)
        recorded_max = local_dt + timedelta(seconds=max_delay)
    else:
        recorded_min = recorded_max = local_dt

    # Apply rounding semantics
    if rounding == 'floor_minute':
        # Floor to minute: [0, 59.999] seconds added
        recorded_min = recorded_min.replace(second=0, microsecond=0)
        recorded_max = recorded_max.replace(second=59, microsecond=999999)
    elif rounding == 'round_minute':
        # Round to nearest minute: ±30 seconds
        recorded_min = recorded_min - timedelta(seconds=30)
        recorded_max = recorded_max + timedelta(seconds=30)
    elif rounding == 'round_10s':
        # Round to nearest 10 seconds: ±5 seconds
        recorded_min = recorded_min - timedelta(seconds=5)
        recorded_max = recorded_max + timedelta(seconds=5)
    elif rounding == 'exact':
        pass
    else:
        raise ValueError(f"Unknown rounding: {rounding}")

    # Handle DST ambiguity for LEGACY-BER on 2025-10-26
    if dst_ambiguity:
        # Europe/Berlin: 2025-10-26 02:00–02:59 ambiguous
        # We return two possible UTC intervals for each local time in [02:00, 02:59]
        if local_dt.date() == datetime(2025, 10, 26).date() and 2 <= local_dt.hour <= 2:
            # Split into two possible UTC intervals
            # CET: UTC+1  02:00 CET = 01:00 UTC
            # CEST: UTC+2  02:00 CEST = 00:00 UTC
            utc_intervals = []
            for base in [recorded_min, recorded_max]:
                # CET interval
                cet_min = base.replace(hour=base.hour-1)  # UTC+1
                cet_max = base.replace(hour=base.hour-1, second=59, microsecond=999999)
                # CEST interval
                cest_min = base.replace(hour=base.hour-2)  # UTC+2
                cest_max = base.replace(hour=base.hour-2, second=59, microsecond=999999)
                utc_intervals.append((cet_min, cet_max))
                utc_intervals.append((cest_min, cest_max))
            return utc_intervals
        else:
            # Not in DST fold; convert normally
            pass

    # Convert to UTC using timezone
    tz_obj = pytz.timezone(tz)
    utc_min = tz_obj.localize(recorded_min).astimezone(pytz.UTC).replace(tzinfo=None)
    utc_max = tz_obj.localize(recorded_max).astimezone(pytz.UTC).replace(tzinfo=None)

    # Apply clock offset bounds: true_time = recorded_time - offset
    # offset in [a,b]  true_time in [recorded_time - b, recorded_time - a]
    a, b = clock_offset_bounds
    true_min = utc_min - timedelta(seconds=b)
    true_max = utc_max - timedelta(seconds=a)

    return [(true_min, true_max)]

# --- Build event log with intervals ---
def build_event_log() -> pd.DataFrame:
    data = []

# --- Derive feasible duration intervals ---
def derive_duration_intervals(df: pd.DataFrame) -> pd.DataFrame:
    # For each case, compute feasible duration intervals for each activity pair
    results = []
    for case, group in df.groupby('case'):
        # Sort by start time
        group = group.sort_values('start')
        activities = group['activity'].tolist()
        for i in range(len(activities)-1):
            act1, act2 = activities[i], activities[i+1]
            # Get feasible intervals for both activities
            row1 = group[group['activity'] == act1].iloc[0]
            row2 = group[group['activity'] == act2].iloc[0]
            intervals1 = local_to_utc_interval(
                row1['start'], row1['system'], row1['rounding'],
                row1['clock_offset'], row1['dst_ambiguity'], row1['entry_delay']
            )
            intervals2 = local_to_utc_interval(
                row2['start'], row2['system'], row2['rounding'],
                row2['clock_offset'], row2['dst_ambiguity'], row2['entry_delay']
            )
            # Compute duration intervals: end - start
            duration_intervals = []
            for (s1, e1) in intervals1:
                for (s2, e2) in intervals2:
                    # Ensure s2 >= e1 (causal constraint)
                    if s2 < e1:
                        s2 = e1
                    if s2 > e2:
                        continue
                    duration_intervals.append((s2 - e1, e2 - s1))
            # Flatten intervals
            if not duration_intervals:
                min_dur, max_dur = None, None
            else:
                min_dur = min([d[0].total_seconds() for d in duration_intervals])
                max_dur = max([d[1].total_seconds() for d in duration_intervals])
            results.append({
                'case': case,
                'activity1': act1,
                'activity2': act2,
                'min_duration': min_dur,
                'max_duration': max_dur,
                'duration_intervals': duration_intervals
            })
    return pd.DataFrame(results)

# --- Temporal profile conformance ---
def classify_temporal_profile(duration_interval: Tuple[float, float], profile: Tuple[float, float], zeta: float) -> str:
    mean, std = profile
    lower = mean - zeta * std
    upper = mean + zeta * std
    if duration_interval[1] < lower:
        return "CERTAIN_VIOLATION"
    elif duration_interval[0] > upper:
        return "CERTAIN_VIOLATION"
    elif duration_interval[0] >= lower and duration_interval[1] <= upper:
        return "CERTAIN_PASS"
    else:
        return "POSSIBLE_VIOLATION"

if __name__ == "__main__":

        ('Alert_Received', 'Investigation_Start'): (600, 180),

        ('Alert_Received', 'Containment_Complete'): (2700, 720),

    }
    # Classify for zeta=1,2,3
```

## 7. Governance Recommendation

### **Timestamp and Clock Controls**
- **Store raw timestamps** in UTC with full precision (microseconds) and timezone.
- **Retain clock offset telemetry** (min/max offset) for each system at event time.
- **Log DST fold events** explicitly (e.g., `is_dst=True/False`).
- **Enforce UTC storage** for all lifecycle timestamps; avoid local time in logs.

### **Resolution and Rounding Metadata**
- Record rounding semantics (floor, round, exact) and unit (second, minute, 10s).
- Store timestamp resolution in metadata (e.g., `resolution="1s"`).

### **Lifecycle Semantics**
- Define `start` and `complete` semantics per system:
  - **Completion events** (e.g., SENSOR) should be treated as end-of-activity.
  - **Floor to minute** implies activity occurred **at or after** the displayed time.
- Require **causal identifiers** linking `Alert_Sent`  `Alert_Received` where applicable.

### **DST and Time-Zone Handling**
- Use IANA time zones and log DST transitions.
- For ambiguous folds, preserve **both possible UTC intervals** and require manual review or additional evidence.

### **Enforcement Policy**
- **Interval overlap is sufficient for enforcement**: If any feasible duration satisfies the SLA, the case is not in violation.
- **Midpoint-only logs are lossy**: Use only for approximate diagnostics; interval-based analysis is authoritative.
- **SLA tolerance should be explicit**: Add a configurable tolerance (e.g., 2 minutes) to account for rounding and clock drift.

### **Provenance and Synchronization**
- Require **event-level synchronization evidence** (e.g., NTP diagnostics, acknowledgments) for external systems.
- For mobile timestamps, log **user entry delay** separately and treat as recorded-time shift.

### **Temporal Profile Usage**
- Use interval-based conformance for regulatory reporting.
- Reserve midpoint-only analysis for internal dashboards.
- Document zeta choice and SLA tolerance in compliance reports.
