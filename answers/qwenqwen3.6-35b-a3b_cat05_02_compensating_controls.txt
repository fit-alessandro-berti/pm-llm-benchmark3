## 1. Control-Objective Decomposition

FEP-1's nominal requirement (Prepare  Release) serves the broader control objective: **Ensure that no single human actor can unilaterally execute a payment transfer that contains an error or fraud, thereby protecting assets and ensuring transaction integrity.** This decomposes into five distinct threat scenarios, each addressed by the compensating controls with varying efficacy:

1.  **Unauthorized Initiation / Fraudulent Transfer:** A malicious actor creates a fake payment to a controlled account.
    *   *AV-2:* Prevents via sanctions checks, bank-account ownership validation, and bank-account change detection. Fails if collusion exists or account ownership is spoofed convincingly.
    *   *MG-4:* Prevents if manager reviews vendor master data and commercial rationale. Fails if manager is compromised, has conflict of interest, or rubber-stamps.
    *   *RA-7:* Detects post-fact. Corrective only if recall window holds.
    *   *ED-1:* Does not prevent; relies on AV-2/MG-4/RA-7 even in emergency mode.

2.  **Erroneous Data Entry:** A legitimate actor inputs wrong amount, vendor, or duplicate invoice.
    *   *AV-2:* Prevents via duplicate invoice check, amount limits, and PO match. Fails on manual data entry errors outside automated checks.
    *   *MG-4:* Prevents if manager verifies invoice/receipt. Fails if manager does not review details.
    *   *RA-7:* Detects errors. Corrective via recall.
    *   *ED-1:* Allows single operator only if AV-2 passes and MG-4 approves; reduces risk but does not eliminate entry error risk.

3.  **Collusion / Evasion of Separation:** Two or more actors cooperate to bypass checks (e.g., shared workstation, fabricated receipts, credential sharing).
    *   *AV-2:* Fails completely; automated checks cannot detect human agreement to defraud.
    *   *MG-4:* Fails if manager is part of collusion or if manager relies solely on documents provided by colluders without independent verification.
    *   *RA-7:* Detects patterns over time. Corrective capacity limited by recall window.
    *   *ED-1:* Fails if emergency token/conditions are fabricated by colluders.

4.  **Compromised Account / Session Hijacking:** An attacker gains access to a single user's credentials and executes both steps.
    *   *AV-2:* May detect anomalies if attacker behavior differs, but generally fails if credentials are valid.
    *   *MG-4:* Prevents if manager requires out-of-band verification or reviews context. Fails if manager is tricked by compromised session.
    *   *RA-7:* Detects unusual activity.
    *   *ED-1:* Does not mitigate; single operator with compromised credentials can bypass all separation.

5.  **Emergency Bypass Abuse:** Single-operator permission used outside genuine emergency, or conditions not met, increasing exposure.
    *   *AV-2:* Must be operational and pass; prevents release of clearly invalid data even in emergency.
    *   *MG-4:* Must approve before settlement; prevents irrevocable release of abusive payments.
    *   *RA-7:* 100% audit ensures detection of abuse.
    *   *ED-1:* Defines the boundary; non-conformance to ED-1 conditions indicates abuse risk or control gap.

## 2. Equivalence and Sufficiency Test

A compensating package is evaluated against FEP-1's control objective using a structured test. Equivalence is not binary; it depends on the risk profile and control dynamics.

**Test Criteria:**
*   **Timing & Preventive Nature:** Controls must intervene *before* irrevocable bank settlement. MG-4 after release but before settlement is preventive for settlement but detective for the release action. Controls that only act post-settlement are purely detective/corrective and cannot prevent the error/fraud from occurring.
*   **Independence & Conflict:** The reviewer must be independent of the preparer/releaser. Independence includes organizational hierarchy (no direct reporting), financial interest, and lack of shared resources (e.g., shared workstations enabling collusion). A manager who sets performance ratings for the releaser fails the independence test.
*   **Coverage & Evidence Quality:** AV-2 covers specific data fields but cannot validate commercial substance (receipts, service completion). MG-4 must involve review of supporting evidence, not just a click. "Rubber-stamping" provides negligible coverage.
*   **Overrideability & Robustness:** Controls must not be easily overridden by the same actor. AV-2 overrides must be logged and restricted. ED-1 conditions must be technically enforced, not manually asserted.
*   **Recoverability:** Corrective capacity depends on the bank recall window (typically 24 hours). If a control package allows release with no chance of recall (e.g., post-settlement review), residual risk is high.
*   **Collusion Resistance:** FEP-1 mitigates collusion risk by requiring separation. Compensating controls must address this: AV-2 does not; MG-4 does only if the manager is independent and verifies documents; RA-7 detects patterns but is slow. Repeated pairing of the same users across cases indicates a structural collusion risk that nominal four-eyes cannot detect.
*   **Standard of Sufficiency:** "Same expected loss" is insufficient. The standard must consider:
    *   *Deterrence:* FEP-1 has high deterrence value; removing it requires controls that maintain deterrence (e.g., unpredictable audits, strict penalties).
    *   *Operational Resilience:* Emergency controls must function under stress.
    *   *Risk Appetite:* High-value or high-risk transactions may require preventive controls that detective controls cannot substitute.

**Classification Logic:**
*   *Fully Equivalent:* Preventive, independent, comprehensive coverage, collusion-resistant (or low collusion risk), and within recall window.
*   *Partially Equivalent:* Preventive control present but with timing gaps (e.g., post-release review), or independence issues mitigated by strong detective controls, or high coverage but no collusion resistance in a high-collusion-risk context.
*   *Merely Mitigating:* Detective/Corrective controls only, or preventive controls with significant coverage gaps (e.g., AV-2 pass but no manager review).
*   *Ineffective:* Controls absent, overridden, compromised, or post-settlement where recovery is impossible.

**Manager Timing Semantics:**
A manager action after `Release_Payment` but before `Bank_Settlement` is **hybrid**. It is detective with respect to the `Release_Payment` action (the release has already occurred), but it is preventive with respect to `Bank_Settlement` (the transfer has not yet become irrevocable). In the context of FEP-1, which aims to prevent erroneous/fraudulent transfers, this timing provides **corrective capacity** via recall. If the recall is successful, the control objective is effectively met, though the preventive separation is not. If the bank settles immediately upon release, this MG-4 is purely detective.

## 6. Evidence and Monitoring Recommendations

**Evidence Collection & Monitoring Rules:**
*   **Same-User Rate:** Track percentage of cases where `Prepare_Payment` = `Release_Payment`. Threshold alert if >5%.
*   **Override Rate:** Track `Override_Warning` frequency. Alert if override rate increases or if overrides are frequent for specific users.
*   **Late Manager Approval:** Flag MG-4 events occurring after `Release_Payment` but before `Bank_Settlement` as hybrid; flag after `Bank_Settlement` as ineffective. Alert if >10% of MG-4 are post-release.
*   **Audit-Before-Recall-Window:** Ensure RA-7 audit timestamp is within 24 hours of release. Alert if audit is delayed.
*   **Repeated Resource Pairs:** Detect pairs of users (e.g., u12/u13) appearing together in `Prepare_Payment` and `Release_Payment` across multiple cases. Alert if pair frequency exceeds threshold (e.g., >3 cases/month).
*   **Shared Workstations:** Monitor logs for `org:resource` associated with same workstation ID. Alert on shared workstations for payment actors.
*   **Bank-Change Proximity:** Flag payments where bank account changed within 7 days. Require AV-2 pass and MG-4 review.
*   **Control Outages:** Track `Validation_Service_Unavailable`. Alert if outage exceeds defined SLA; require manual compensating controls.

**Alerts vs. Proof:**
*   *Alert:* Shared workstation or repeated pairing indicates **risk** of collusion but is not proof. It requires investigation into workflow design (e.g., dedicated payment cell) vs. unauthorized cooperation.
*   *Alert:* Override of AV-2 indicates **process exception** but not proof of fraud. It requires review of override justification and manager approval.
*   *Alert:* ED-1 token timing mismatch indicates **procedural non-conformance** but not proof of abuse. It requires verification of emergency status.
*   *Proof:* Audit finding fabricated receipt, vendor linked to relative, or manager conflict of interest is evidence of control failure or misconduct.
