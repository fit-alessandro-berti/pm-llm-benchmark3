# 1. Policy Interpretation and Conflict Resolution

Material assumptions:

- Each test line is one case; hours are timestamps relative to case start.
- Activity labels are the authoritative business event names; no hidden activity labels are introduced.
- A complete valid case ends with `Close Onboarding`.
- “Final outcome” is interpreted as either `Reject Vendor` or `Activate Vendor`; `Close Onboarding` is case closure after the outcome.
- “Applicable approval” means:
  - low-risk accepted route: `Manager Approval`;
  - high-risk accepted route: `Compliance Approval`;
  - rejected route: no approval.
- `Verify Bank Account` may occur again after `Change Bank Details`; the initial and repeated verification share the same activity label.
- `Change Bank Details` after activation is modeled only before `Release First Payment`; changes after first payment or after closure are treated as outside this model.
- Escalation is placed after `Classify Risk` in the procedural model. This is stricter than R7, which only says after `Run Sanctions Screening`; it matches T6/T7 but excludes a possible escalation between screening and classification.
- Resource, emergency, and joint-authorization attributes are not available from activity labels alone. They require an external validation layer.
- Temporal expectations are normative warnings, not hard control-flow violations.

R5/R6 conflict:

- **Resolution A — strict legal precedence:** if `Sanctions Escalation` occurs, `Obtain Legal Opinion` must be before activation. Emergency activation is not accepted. This is the implemented model.
- **Resolution B — controlled emergency exception:** activation before `Obtain Legal Opinion` is allowed only if an external case attribute says the case was an emergency, an external authorization artifact shows joint authorization, and the opinion arrives within 24 hours. This cannot be verified from the event log alone.

Chosen resolution: **Resolution A, strict legal precedence**.

Compliance risk of the choice: it rejects emergency activations that Operations might consider legitimate, but it avoids accepting cases whose legality cannot be proven from the available event data. This is conservative and auditable. R6 is therefore recorded as a conflicting stakeholder requirement, not silently merged into the implemented model.

| R2 | Procedural Petri net, with external consistency check | Low-risk branch contains only `Manager Approval`; high-risk branch contains only `Enhanced Due Diligence` then `Compliance Approval`; rejected branch has neither. # 3. Procedural Backbone

Compact formal description:

```text
Receive Onboarding Request
 (Capture Master Data || Run Sanctions Screening || Verify Bank Account)
 silent AND-join
 (Request Clarification  Receive Clarification)*
 Classify Risk
 (no escalation OR Sanctions Escalation)
 choice:
     Reject Vendor  Close Onboarding
   | Manager Approval  Activate Vendor  [Change Bank Details  Suspend Vendor  Verify Bank Account]*  Release First Payment  Close Onboarding
   | Enhanced Due Diligence  Compliance Approval  Activate Vendor  [Change Bank Details  Suspend Vendor  Verify Bank Account]*  Release First Payment  Close Onboarding

Strict R5 addition:
    if Sanctions Escalation occurred, Obtain Legal Opinion must produce the activation/closure gate before Activate Vendor or rejected Close Onboarding.
```

A(t_receive, p_received)

t_no_escalation = T("tau_no_escalation", None)
A(p_postclass, t_no_escalation)
A(t_no_escalation, p_case_ready)
A(t_no_escalation, p_noesc_flag)

t_legal = T("t_legal_opinion", "Obtain Legal Opinion")

A(t_legal, p_legal_flag)

t_gate_noesc = T("tau_gate_noesc", None)
A(p_noesc_flag, t_gate_noesc)

t_gate_legal = T("tau_gate_legal", None)

# Terminal choice: low-risk

t_low_to_approval = T("tau_low_to_approval", None)

# Terminal choice: high-risk
t_edd = T("t_edd", "Enhanced Due Diligence")

initial_marking = Marking()

procedural_model = (net, initial_marking, final_marking)

Explanation:

- **Concurrency:** after `Receive Onboarding Request`, one token splits into three parallel check flows. The silent AND-join permits the next step only when all three are complete.
- **Clarification loops:** `(Request Clarification  Receive Clarification)*` is modeled before `Classify Risk`. This is a conservative approximation: R3 allows clarification before any final outcome, not necessarily only before classification. DECLARE and the external check provide the more faithful R3 enforcement.
- **Choices:** after classification there is exactly one of rejection, low-risk approval, or high-risk approval. Escalation/no escalation is a separate optional choice.
- **Terminal outcomes:** rejection closes after the legal/no-escalation gate; acceptance requires activation, then payment, then closure.
- **Post-activation behavior:** `Change Bank Details  Suspend Vendor  Verify Bank Account` is included before `Release First Payment`, with unbounded repetition. Changes after payment or closure are deliberately excluded.
- **R5/R6:** the net implements strict R5 only. Emergency activation before legal opinion is not accepted by this procedural model.

Rule explanations:

| Rule | Direction | Semantics used |
|---|---|---|
| `existence(A)` | unary | Activity `A` must occur at least once. |
| `init(Receive Onboarding Request)` | unary | If the rule is satisfied, `Receive Onboarding Request` is first. Combined with `existence`, it starts each case. |
| `precedence(A,B)` | source `A`, target `B` | If `B` occurs, some `A` must have occurred earlier. It is a backward permission rule, not a forward obligation. |
| `altresponse(A,B)` | source `A`, target `B` | After every `A`, a `B` must occur before another `A`. Other activities may occur between them. Used for clarification cycles. |
| `response(A,B)` | source `A`, target `B` | If `A` occurs, `B` must eventually occur after it. It does not require immediate succession. |
| `noncoexistence(A,B)` | symmetric | `A` and `B` must not both occur in the same case. |

Important distinctions:

- `response(A,B) != precedence(A,B)`: response says “A obliges later B”; precedence says “B is allowed only if earlier A happened.”
- `altresponse(A,B)` is not `chainresponse(A,B)`: chain response would require `B` immediately after `A`, which is too strict for clarification cycles with interleaved checks.
- `noncoexistence(A,B)` is not `nonsuccession(A,B)`: noncoexistence forbids both activities in one trace; nonsuccession is an ordering-prohibition pattern. For R1 and R8, mutual exclusion is the intended semantics, so `noncoexistence` is used.
- R5 is not encoded as a global DECLARE rule because a global `precedence(Obtain Legal Opinion, Activate Vendor)` would wrongly reject non-escalated activations. The procedural net is authoritative for R5.

# 5. Log-Skeleton Model

```python
all_labels = [
    "Receive Onboarding Request",
    "Capture Master Data",
    "Run Sanctions Screening",
    "Verify Bank Account",
    "Classify Risk",
    "Request Clarification",
    "Receive Clarification",
    "Sanctions Escalation",
    "Obtain Legal Opinion",
    "Enhanced Due Diligence",
    "Manager Approval",
    "Compliance Approval",
    "Reject Vendor",
    "Activate Vendor",
    "Change Bank Details",
    "Suspend Vendor",
    "Release First Payment",
    "Close Onboarding",
]

always_once = [
    "Receive Onboarding Request",
    "Capture Master Data",
    "Run Sanctions Screening",
    "Classify Risk",
    "Close Onboarding",
]

before_pairs = set()

# Receive starts every case.
for a in all_labels:
    if a != "Receive Onboarding Request":
        before_pairs.add(("Receive Onboarding Request", a))

# Backbone precedence.
before_pairs.update({
    ("Capture Master Data", "Classify Risk"),
    ("Run Sanctions Screening", "Classify Risk"),
    ("Run Sanctions Screening", "Sanctions Escalation"),
    ("Classify Risk", "Sanctions Escalation"),
    ("Classify Risk", "Reject Vendor"),
    ("Classify Risk", "Manager Approval"),
    ("Classify Risk", "Enhanced Due Diligence"),

    ("Enhanced Due Diligence", "Compliance Approval"),
    ("Obtain Legal Opinion", "Activate Vendor"),
    ("Obtain Legal Opinion", "Close Onboarding"),
    ("Manager Approval", "Activate Vendor"),
    ("Compliance Approval", "Activate Vendor"),
    ("Activate Vendor", "Release First Payment"),
    ("Activate Vendor", "Close Onboarding"),
    ("Release First Payment", "Close Onboarding"),
    ("Reject Vendor", "Close Onboarding"),
})

never = {
    ("Reject Vendor", "Activate Vendor"),
    ("Activate Vendor", "Reject Vendor"),
    ("Reject Vendor", "Release First Payment"),
    ("Release First Payment", "Reject Vendor"),
    ("Reject Vendor", "Manager Approval"),
    ("Manager Approval", "Reject Vendor"),
    ("Reject Vendor", "Compliance Approval"),
    ("Compliance Approval", "Reject Vendor"),
    ("Enhanced Due Diligence", "Manager Approval"),
    ("Manager Approval", "Enhanced Due Diligence"),
    ("Compliance Approval", "Manager Approval"),
    ("Manager Approval", "Compliance Approval"),
}

equivalence = {(a, b) for a in always_once for b in always_once if a != b}
equivalence.update({
    ("Activate Vendor", "Release First Payment"),
    ("Release First Payment", "Activate Vendor"),
    ("Enhanced Due Diligence", "Compliance Approval"),
    ("Compliance Approval", "Enhanced Due Diligence"),
    ("Sanctions Escalation", "Obtain Legal Opinion"),
    ("Obtain Legal Opinion", "Sanctions Escalation"),
})

log_skeleton = {
    "equivalence": equivalence,
    "always_before": before_pairs,
    "always_after": {(b, a) for (a, b) in before_pairs},
    "never_together": never,
    "activ_freq": {
        "Receive Onboarding Request": {1},
        "Capture Master Data": {1},
        "Run Sanctions Screening": {1},
        "Classify Risk": {1},
        "Sanctions Escalation": {0, 1},
        "Obtain Legal Opinion": {0, 1},
        "Enhanced Due Diligence": {0, 1},
        "Manager Approval": {0, 1},
        "Compliance Approval": {0, 1},
        "Reject Vendor": {0, 1},
        "Activate Vendor": {0, 1},
        "Release First Payment": {0, 1},
        "Close Onboarding": {1},
    },
    "directly_follows": set(),
}
```

Orientation and defense:

- `always_before (A,B)` means `A` is always before `B`.
- `always_after (A,B)` means `A` is always after `B`; therefore it contains reversed pairs from `always_before`.
- `never_together` is symmetric; both orientations are included for literal safety.
- `equivalence` is symmetric; both orientations are included.

Deliberate omissions:

- No `Request Clarification  Receive Clarification` pair is included because repeated cycles produce `Request, Receive, Request, Receive`, which breaks simple binary “always before” semantics.
- No `Verify Bank Account  Classify Risk` pair is included because post-change re-verification can occur after classification; DECLARE precedence and the procedural net cover the first verification requirement.
- No `Change Bank Details  Suspend Vendor` pair is included because repeated change/reactivate cycles can interleave.
- `directly_follows` is empty because concurrency, clarification, escalation, and rework make direct succession too brittle.

Overlap/disagreement:

- R1/R8 overlap with DECLARE and procedural enforcement.
- `Obtain Legal Opinion  Activate Vendor` reflects the chosen strict R5 policy. Under Resolution B, this pair must be removed or made policy-dependent.
- The Log Skeleton is intentionally weaker than the procedural model for clarification and rework loops.

# 7. Resource- and Data-Aware Checks

Required base event attributes:

- `case_id`
- `activity`
- `timestamp`
- `resource`

If `case_id`, `activity`, or `timestamp` is missing, validation should fail because ordering/identity cannot be established. If `resource` is missing for a SoD-relevant activity, validation should fail closed.

```python
import pandas as pd

FINAL_OUTCOMES = {"Reject Vendor", "Activate Vendor"}
APPROVALS = {"Manager Approval", "Compliance Approval"}


def require_columns(df, cols):
    missing = set(cols) - set(df.columns)
    if missing:
        raise ValueError(f"Missing required columns: {sorted(missing)}")


def finding(case, rule, severity, message, activity=None):
    return {
        "case_id": case,
        "rule": rule,
        "severity": severity,
        "message": message,
        "activity": activity,
    }


def sorted_case_events(df, case, case_col="case_id"):
    return df[df[case_col] == case].sort_values("timestamp")


def first_time(evs, activity):
    sub = evs[evs["activity"] == activity]
    return None if sub.empty else sub.iloc[0]["timestamp"]


def check_terminal_and_approval_consistency(df):
    require_columns(df, {"case_id", "activity", "timestamp"})
    out = []

    for case, evs in df.groupby("case_id"):
        evs = evs.sort_values("timestamp")
        acts = list(evs["activity"])

        for a in ["Activate Vendor", "Reject Vendor", "Release First Payment"]:
            if acts.count(a) > 1:
                out.append(finding(case, "R10", "fail", f"{a} occurs more than once", a))

        if "Activate Vendor" in acts and "Reject Vendor" in acts:
            out.append(finding(case, "R1", "fail", "Reject Vendor and Activate Vendor co-occur"))

        m = "Manager Approval" in acts
        c = "Compliance Approval" in acts
        act = "Activate Vendor" in acts
        rej = "Reject Vendor" in acts

        if m and c:
            out.append(finding(case, "R8", "fail", "Manager Approval and Compliance Approval co-occur"))

        if act and not (m ^ c):
            out.append(finding(case, "R2", "fail", "Accepted case must have exactly one applicable approval"))

        if rej and (m or c):
            out.append(finding(case, "R2", "fail", "Rejected case must have no approval"))

    return out


def check_clarification_closure(df):
    require_columns(df, {"case_id", "activity", "timestamp"})
    out = []

    for case, evs in df.groupby("case_id"):
        pending_since = None

        for row in evs.sort_values("timestamp").itertuples():
            if row.activity == "Request Clarification":
                if pending_since is not None:
                    out.append(finding(
                        case, "R3", "fail",
                        "New Request Clarification before previous Receive Clarification",
                        "Request Clarification",
                    ))
                else:
                    pending_since = row.timestamp

            elif row.activity == "Receive Clarification":
                if pending_since is None:
                    out.append(finding(
                        case, "R3", "warning",
                        "Receive Clarification without a pending request; not forbidden by R3",
                        "Receive Clarification",
                    ))
                pending_since = None

            elif row.activity in FINAL_OUTCOMES and pending_since is not None:
                out.append(finding(
                    case, "R3", "fail",
                    "Final outcome occurred while Request Clarification was unanswered",
                    row.activity,
                ))
                pending_since = None

    return out


def check_four_eyes(df):
    require_columns(df, {"case_id", "activity", "timestamp", "resource"})
    out = []

    for case, evs in df.groupby("case_id"):
        evs = evs.sort_values("timestamp")

        manager = evs[evs["activity"] == "Manager Approval"]
        compliance = evs[evs["activity"] == "Compliance Approval"]
        approvals = pd.concat([manager, compliance])

        verification = evs[evs["activity"] == "Verify Bank Account"]
        capture = evs[evs["activity"] == "Capture Master Data"]
        activation = evs[evs["activity"] == "Activate Vendor"]

        relevant = pd.concat([approvals, verification, capture, activation])
        if relevant["resource"].isna().any():
            out.append(finding(case, "R9", "fail", "Missing resource for SoD-relevant activity"))

        if len(approvals) == 1:
            approval_resource = approvals.iloc[0]["resource"]
            for _, v in verification.iterrows():
                if pd.notna(v["resource"]) and v["resource"] == approval_resource:
                    out.append(finding(
                        case, "R9", "fail",
                        "Verify Bank Account resource equals applicable approval resource",
                        "Verify Bank Account",
                    ))
        elif len(approvals) > 1:
            out.append(finding(case, "R2/R8", "fail", "More than one approval event"))

        for _, a in activation.iterrows():
            for _, c in capture.iterrows():
                if pd.notna(a["resource"]) and pd.notna(c["resource"]) and a["resource"] == c["resource"]:
                    out.append(finding(
                        case, "R9", "fail",
                        "Capture Master Data resource equals Activate Vendor resource",
                        "Activate Vendor",
                    ))

    return out


def check_bank_change_after_activation(df):
    require_columns(df, {"case_id", "activity", "timestamp"})
    out = []

    for case, evs in df.groupby("case_id"):
        evs = evs.sort_values("timestamp")
        act_time = first_time(evs, "Activate Vendor")
        if act_time is None:
            continue

        changes = evs[(evs["activity"] == "Change Bank Details") & (evs["timestamp"] > act_time)]

        for ch in changes.itertuples():
            later = evs[evs["timestamp"] > ch.timestamp]
            susp = later[later["activity"] == "Suspend Vendor"]
            release = later[later["activity"] == "Release First Payment"]
            reverify = later[later["activity"] == "Verify Bank Account"]

            if susp.empty:
                out.append(finding(
                    case, "R11", "fail",
                    "Change Bank Details after activation has no later Suspend Vendor",
                    "Change Bank Details",
                ))

            if not release.empty:
                rel_time = release.iloc[0]["timestamp"]
                if reverify.empty or reverify.iloc[0]["timestamp"] >= rel_time:
                    out.append(finding(
                        case, "R11", "fail",
                        "No Verify Bank Account before later Release First Payment",
                        "Release First Payment",
                    ))

    return out


def check_legal_policy(df, resolution="strict_R5", auth_df=None):
    require_columns(df, {"case_id", "activity", "timestamp"})
    out = []

    for case, evs in df.groupby("case_id"):
        evs = evs.sort_values("timestamp")

        esc_time = first_time(evs, "Sanctions Escalation")
        if esc_time is None:
            continue

        legal_time = first_time(evs, "Obtain Legal Opinion")
        act_time = first_time(evs, "Activate Vendor")
        close_time = first_time(evs, "Close Onboarding")

        if legal_time is None:
            out.append(finding(case, "R4", "fail", "Sanctions Escalation without Obtain Legal Opinion"))
            continue

        if close_time is not None and legal_time > close_time:
            out.append(finding(case, "R4", "fail", "Obtain Legal Opinion occurs after Close Onboarding"))

        if act_time is None:
            continue

        if resolution == "strict_R5":
            if legal_time > act_time:
                out.append(finding(
                    case, "R5", "fail",
                    "Strict R5: Obtain Legal Opinion must precede Activate Vendor",
                    "Activate Vendor",
                ))

        elif resolution == "emergency_R6":
            if legal_time <= act_time:
                continue

            if legal_time > act_time + pd.Timedelta(hours=24):
                out.append(finding(
                    case, "R6", "fail",
                    "Late legal opinion after emergency activation",
                    "Obtain Legal Opinion",
                ))

            if auth_df is None or case not in set(auth_df["case_id"]):
                out.append(finding(case, "R6", "fail", "Missing external emergency authorization record"))
                continue

            auth = auth_df[auth_df["case_id"] == case].iloc[0]
            if not bool(auth.get("emergency", False)):
                out.append(finding(case, "R6", "fail", "Activation before opinion not marked emergency"))

            parties = auth.get("joint_authorization", [])
            if not isinstance(parties,
