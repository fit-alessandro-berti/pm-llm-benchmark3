# 1. Executive Verdict

The net is a workflow net: it has a unique source, a unique sink, and every place and transition lies on a source-to-sink path. It should not be expected to be sound. The principal defect is that silent `t_join_waived` has only `p_waived` as input and never waits for the analysis branch. After a waiver, `t_authorize` can fire while a token remains in `p_analysis` or `p_analysis_done`. A case can therefore be authorized before analysis, and the accepting marking `{sink: 1}` is unreachable on the waiver route because that leftover token cannot be consumed.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
| --- | --- | --- | --- |
| `source` / `t_register` / `p_ready` | Create the case and enable the parallel split | Ordinary prefix; one token reaches `t_split` | None |
| `t_split` | AND-split: start mandatory analysis and a review choice together | Produces one token in `p_analysis` and one in `p_review` | Correctly creates both branches |
| `t_analyze` / `p_analysis_done` | Mandatory analysis; completion must precede authorization | Analysis is a free concurrent branch whose result only feeds `t_join_normal` | On the waiver route the result is never demanded |
| `t_standard_review` / `p_review_done` | One XOR alternative for review | Consumes `p_review` and feeds the two-input join | Standard path can complete properly |
| `t_waive_review` / `p_waived` | Other XOR alternative: recorded waiver instead of standard review | Consumes `p_review` and feeds a one-input join | Waiver is recorded without binding analysis |
| `t_join_normal` | AND-join of analysis and standard review | Enabled only by `p_analysis_done` and `p_review_done` | Dead after a waiver; unused leftover analysis cannot enter it |
| `t_join_waived` | AND-join of analysis and waiver | Enabled by `p_waived` alone; writes `p_decision` immediately | Authorization before analysis; leftover token |
| `t_authorize` / `sink` | Final visible step; unique sink token | Consumes only `p_decision` | Sink can be marked while another place is still marked |
| `im` / `fm` | `{source: 1}` to `{sink: 1}` | `fm` is reachable only via the standard-review route | Waiver traces never match `fm` |
| Source-to-sink coverage | Every node on a path from `source` to `sink` | Holds for all nine places and eight transitions | Workflow-net check can pass while soundness fails |

# 3. Marking-Based Counterexample

Legal sequence that exposes the defect (waiver first, then authorize, then the stranded analysis):

`t_register → t_split → t_waive_review → t_join_waived → t_authorize → t_analyze`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| --- | --- | --- | --- | --- |
| 0 | — | `source:1` | `t_register` | Start from `im` |
| 1 | `t_register` | `p_ready:1` | `t_split` | Case registered |
| 2 | `t_split` | `p_analysis:1`, `p_review:1` | `t_analyze`, `t_standard_review`, `t_waive_review` | Both parallel branches hold a token |
| 3 | `t_waive_review` | `p_analysis:1`, `p_waived:1` | `t_analyze`, `t_join_waived` | XOR review consumed; analysis token still sitting in `p_analysis` |
| 4 | `t_join_waived` | `p_analysis:1`, `p_decision:1` | `t_analyze`, `t_authorize` | One-input join ignores analysis |
| 5 | `t_authorize` | `p_analysis:1`, `sink:1` | `t_analyze` | A token exists in the sink, but the marking is not `fm` |
| 6 | `t_analyze` | `p_analysis_done:1`, `sink:1` | none | Leftover cannot be consumed: `t_join_normal` still needs `p_review_done`, which this XOR branch will never produce |

`t_authorize` occurs *before* `t_analyze`. The sink token is therefore not a proper completion.

A second legal sequence shows the same defect after analysis has already finished:

`t_register → t_split → t_analyze → t_waive_review → t_join_waived → t_authorize`

Nonzero marking is then `p_analysis_done:1`, `sink:1`. Again this is not `fm`. Nothing is enabled: `t_join_normal` waits forever for `p_review_done`. So even when analysis happens to precede authorization, the waiver route still cannot reach the exact final marking.

The standard-review route `t_register → t_split → t_analyze → t_standard_review → t_join_normal → t_authorize` *does* reach `fm`. The failure is specific to the missing second input of `t_join_waived`, not to the XOR at `p_review`.

# 4. Minimal-Repair Alternatives

Edit-cost model: each added or removed place, transition, or arc costs 1. Redirecting an arc is one removal plus one addition (cost 2). Isolated leftovers must be deleted if the result is still required to be a workflow net.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
| --- | --- | --- | --- | --- | --- |
| A. Two-input waiver join | Add arc `p_analysis_done → t_join_waived` | 1 | Yes: analysis remains mandatory on both review outcomes; waiver stays a distinct place/join | `t_join_waived` enabled only after both `t_analyze` and `t_waive_review`; `t_authorize` cannot precede analysis | Two silent joins remain; model is slightly more redundant than a single join |
| B. Rewire waiver into the existing AND-join | Remove arc `t_waive_review → p_waived`; add arc `t_waive_review → p_review_done`; remove arcs `p_waived → t_join_waived` and `t_join_waived → p_decision`; remove place `p_waived`; remove transition `t_join_waived` | 6 | Yes: same visible language as A; analysis still mandatory | Single synchronization (`t_join_normal`); waiver and standard review share `p_review_done` | Structural distinction of the waiver outcome disappears; later rule variants that treat waiver differently need new places |
| C. Waiver cancels pending analysis (policy change) | Add arc `p_analysis → t_waive_review` | 1 | **No.** Analysis is no longer mandatory when a waiver is recorded. Stated policy change: recording a waiver consumes the pending analysis token and authorization proceeds without `Perform Analysis`. Also, after `t_analyze` has fired, `t_waive_review` is no longer enabled | Waiver traces need not contain analysis; leftover token is gone | Quietly drops the stated mandatory-analysis rule; forbids waive-after-analyze |

Repairs A and C tie at cost 1. A is the unique cheapest repair that keeps the stated policy. B is more expensive but is the cheapest way to obtain a single AND-join while remaining a workflow net. Leaving `p_waived` / `t_join_waived` in place after B would disconnect them from the source and fail the workflow-net path condition, so those deletions are part of minimality, not cosmetics.

# 6. Diagnostic and Reachability Code

```python
from pm4py.objects.petri_net.obj import Marking

def format_marking(marking):
    return {p.name: marking[p] for p in marking if marking[p] > 0}

def fire_named(net, marking, trans_name):
    enabled = list(pm4py.get_enabled_transitions(net, marking))
    chosen = next((t for t in enabled if t.name == trans_name), None)
    if chosen is None:
        raise ValueError(
            f"{trans_name!r} is not enabled in {format_marking(marking)}; "
            f"enabled={sorted(t.name for t in enabled)}"
        )
    produced = Marking()
    for p, tokens in marking.items():
        produced[p] = tokens
    for arc in chosen.in_arcs:
        produced[arc.source] -= arc.weight
        if produced[arc.source] <= 0:
            del produced[arc.source]
    for arc in chosen.out_arcs:
        produced[arc.target] += arc.weight
    print(f"FIRED {trans_name} -> {format_marking(produced)}")
    print(f"  enabled now: {sorted(t.name for t in pm4py.get_enabled_transitions(net, produced))}")
    return produced

print("=== ORIGINAL: workflow-net / soundness ===")
print("is_workflow_net:", pm4py.check_is_workflow_net(net))
print("soundness:", pm4py.check_soundness(net, im, fm, print_diagnostics=True))
print("enabled at im:", sorted(t.name for t in pm4py.get_enabled_transitions(net, im)))
original_rg = pm4py.convert_to_reachability_graph(net, im, fm)
print("original reachability graph object:", original_rg)

print("=== ORIGINAL: waiver-then-authorize counterexample ===")
m = Marking(im)
for name in ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize"]:
    m = fire_named(net, m, name)
print("sink marked:", any(p.name == "sink" and m[p] > 0 for p in m))
print("equals fm:", m == fm)

print("=== REPAIRED: workflow-net / soundness ===")
print("is_workflow_net:", pm4py.check_is_workflow_net(repaired_net))
print("soundness:", pm4py.check_soundness(repaired_net, repaired_im, repaired_fm, print_diagnostics=True))
print("enabled at repaired_im:", sorted(t.name for t in pm4py.get_enabled_transitions(repaired_net, repaired_im)))
repaired_rg = pm4py.convert_to_reachability_graph(repaired_net, repaired_im, repaired_fm)
print("repaired reachability graph object:", repaired_rg)

print("=== REPAIRED: same prefix must refuse early waiver join ===")
m = Marking(repaired_im)
m = fire_named(repaired_net, m, "t_register")
m = fire_named(repaired_net, m, "t_split")
m = fire_named(repaired_net, m, "t_waive_review")
try:
    fire_named(repaired_net, m, "t_join_waived")
except ValueError as err:
    print("expected refusal:", err)

print("=== REPAIRED: legal waiver completion ===")
m = Marking(repaired_im)
for name in ["t_register", "t_split", "t_waive_review", "t_analyze", "t_join_waived", "t_authorize"]:
    m = fire_named(repaired_net, m, name)
print("equals repaired_fm:", m == repaired_fm)
```

Expected qualitative difference: both nets should pass the workflow-net check. The original should fail soundness: after a waiver, a marking with a sink token and a leftover analysis token is reachable, and that marking has no continuation to `fm`. The repaired net should pass soundness. Immediately after `t_waive_review`, the original enables `t_join_waived` while analysis is still pending; the repaired net does not. The original reachability graph contains markings that pair `sink` with `p_analysis` or `p_analysis_done`; the repaired graph should not. Do not treat a True soundness flag as proof that every business phrasing is captured.

# 7. Repair Trade-Offs and Residual Risks

Waiver and standard review remain distinguishable in the event log under A and B because the visible labels `Perform Standard Review` and `Record Review Waiver` are unchanged. Repair A also keeps distinct places `p_review_done` and `p_waived`. Repair B collapses those outcomes into one place after the visible step. Repair C keeps the labels but drops analysis from waiver traces, so the *meaning* of a waiver changes.

Repair A retains two silent joins. They are not concurrent duplicates: `p_review` is an XOR place, so at most one join is enabled. They can still confuse a silent-step unfolding or a reachability drawing that looks like two completion corridors. They do not duplicate visible traces.

Soundness only says: from every reachable marking one can reach exactly `fm`, and no transition is dead. A sound net can still implement the wrong policy. Repair C can be made sound while violating “analysis is always mandatory.” Conversely, soundness of A or B does not by itself prove that the labels match the intended documents, only that the control-flow skeleton no longer leaves tokens behind.

Regression-test at least these positive traces (any interleaving of the two parallel visibles):

- `Register Case`, `Perform Analysis`, `Perform Standard Review`, `Authorize Case`
- `Register Case`, `Perform Analysis`, `Record Review Waiver`, `Authorize Case`

and these negative traces:

- `Register Case`, `Record Review Waiver`, `Authorize Case` (analysis missing)
- `Register Case`, `Perform Standard Review`, `Authorize Case` (analysis missing)
- `Register Case`, `Perform Analysis`, `Authorize Case` (no review outcome)
- both review visibles in one case
- a case whose last event is `Authorize Case` while a further visible analysis still occurs

To detect an accidental bypass of mandatory analysis: (i) reject any log trace whose projection onto visible labels lacks `Perform Analysis` before `Authorize Case`; (ii) assert an invariant on the net that `p_decision` becomes marked only by a transition that consumed `p_analysis_done`; (iii) replay the two negative “authorize without analysis” traces and require zero conforming alignments.

# 8. Final Recommendation

Deploy Repair A: add the single arc `p_analysis_done → t_join_waived`. It is the unique cost-1 edit that keeps analysis mandatory on the waiver path, leaves every visible label unchanged, and keeps waiver structurally distinct from standard review. The early-join counterexample disappears: `t_join_waived` is enabled only when both branches have finished, and `t_authorize` can no longer fire while `p_analysis` still holds a token. The standard-review join is untouched, so the already-correct path stays correct.

Use Repair B as the fallback if maintainers want one synchronization and are willing to delete the unused waiver join subnet. B has the same visible language as A but a higher edit cost and a weaker hook for a later rule that treats a recorded waiver differently from a standard review. Do not deploy Repair C unless the business explicitly retracts mandatory analysis; it is cheap and can be sound, and that is exactly why it is dangerous.

After deployment, keep the workflow-net and soundness checks, but treat them as necessary rather than sufficient. Gate release on the positive and negative traces above, especially the refusal of `t_join_waived` after waiver-only and the requirement that every authorized case consumed `p_analysis_done`.
