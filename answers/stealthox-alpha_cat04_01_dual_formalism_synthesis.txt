# 1. Assumptions and Interpretation

1. **Risk route representation.** The lowrisk/highrisk decision is represented as an exclusive choice (*XOR*) between (a) a single `Supervisor Review` and (b) a concurrent pair `Quality Review  Regulatory Review` with no internal order. Exactly one route is taken per case. The data condition "risk class" itself is **not** encoded (Requirement 11); the choice appears as nondeterminism at the controlflow level.
2. **Optional supplier consultation.** `Consult Supplier` is modeled as an *XOR* between the visible activity and a silent step (): `XOR(CS, )`. It is therefore skippable and executable at most once. Whether it is taken is externally guarded (case data), never decided by the model.
3. **Passing inspection abstraction.** Inspection outcomes are not event labels, so "inspection passes" is abstracted as **loop exit**: the trial loop is `LOOP( do = ETIT , redo = AP )`. The *last* `Inspect Trial` before exiting the loop is by definition the passing one; every `Adjust Parameters` is the redo branch taken after a failed inspection. No outcome attribute is encoded.
4. **Duplicate visible labels.** The delivered models use **no duplicated visible labels**: each of the 14 activities corresponds to exactly one tree leaf / POWL transition (except that `Execute Trial`/`Inspect Trial` recur via the loop operator, which reuses the *same* node). A duplicationbased tree variant was designed, evaluated, and rejected (see §3 and §6, row 8) because duplicated labels corrupt alignmentbased conformance and frequency analytics.
5. **Approximation policy for the process tree.** An exact tree is impossible (proof sketch in §3). I adopt a **conservative underapproximation**: the approval route and the optional supplier consultation must *complete before the trial loop starts*. This admits only traces that satisfy every stated dependency (never unsafe behavior) but excludes legal traces in which an approval or the supplier consultation finishes *during* the trial. The excluded set is precisely characterized in §3.
6. **"May overlap" interpretation.** "May overlap" is interpreted as **absence of an order constraint**, realized as *true concurrency* in the model semantics (simultaneously enabled transitions in the underlying net). At the trace level this is observed as arbitrary interleaving. It does **not** mean "must be simultaneous," and no duration or resource assumptions are made.
7. **Cardinalities.** Per case: `RD`, `CM`, `ARC`, `PV`, `DCA`, `RM`, `AC` exactly once; exactly one approval route (`SR` once, or `QR` once and `RR` once); `CS` 0 or 1 times; `ET`/`IT` at least once, alternating starting with `ET`; `AP`  0, only between trial cycles.
8. **Closedworld dependencies.** Only the dependencies in §2 constrain behavior; any pair not related by a (transitive) dependency is free to interleave in any order.
9. **Completiontime recording.** All precedence statements refer to *completion instants* of activities. Zerodelay simultaneity is permitted but never required.

# 3. PM4Py Process-Tree Model

**Compact expression** (notation: `->` = SEQUENCE, `+` = PARALLEL, `X` = XOR, `*(do, redo)` = LOOP, `` = silent):

```text
-> (
  'Register Deviation',
  + (
      -> ('Contain Material', 'Plan Verification'),
      -> ('Analyze Root Cause',
          + ('Design Corrective Action',
             X('Supervisor Review', +('Quality Review', 'Regulatory Review')),
             X('Consult Supplier', )))
    ),
  * ( -> ('Execute Trial', 'Inspect Trial'), 'Adjust Parameters' ),
  'Release Material',
  'Archive Case'
)
```

**Mapping to the narrative:** the outer `->` enforces RD first and `RM  AC` last. The `+` after RD lets the containment stream `->(CM, PV)` and the analysis stream `->(ARC, …)` interleave arbitrarily (C1, D1–D4). Inside the analysis stream, `+(DCA, routeXOR, supplierXOR)` makes design, the selected approval route, and the optional consultation mutually concurrent after ARC (D4–D6, C3 partially). The loop `*(->(ET,IT), AP)` implements the trial cycle with adjustment only on the redo branch (D9). Because the whole initial `+` must complete before the loop, the route and the consultation are forced to finish before the trial — this is the deliberate approximation.

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator


def leaf(label):
    return ProcessTree(label=label)


def sub(operator, children):
    """Create an operator node and wire parent/child pointers explicitly."""
    parent = ProcessTree(operator=operator)
    for child in children:
        child.parent = parent
        parent.children.append(child)
    return parent


tau = ProcessTree(label=None)  # operator=None, label=None  =>  silent transition

rd  = leaf("Register Deviation")
cm  = leaf("Contain Material")
arc = leaf("Analyze Root Cause")
pv  = leaf("Plan Verification")
dca = leaf("Design Corrective Action")
sr  = leaf("Supervisor Review")
qr  = leaf("Quality Review")
rr  = leaf("Regulatory Review")
cs  = leaf("Consult Supplier")
et  = leaf("Execute Trial")
it  = leaf("Inspect Trial")
ap  = leaf("Adjust Parameters")
rm  = leaf("Release Material")
ac  = leaf("Archive Case")

containment_stream = sub(Operator.SEQUENCE, [cm, pv])                 # D3
reviews_high       = sub(Operator.PARALLEL, [qr, rr])                 # C2
approval_route     = sub(Operator.XOR, [sr, reviews_high])            # D5
supplier_optional  = sub(Operator.XOR, [cs, tau])                     # D6
analysis_stream    = sub(Operator.SEQUENCE,
                         [arc, sub(Operator.PARALLEL,
                                   [dca, approval_route, supplier_optional])])  # D4, C3'

trial_cycle = sub(Operator.SEQUENCE, [et, it])                        # D9
trial_loop  = sub(Operator.LOOP, [trial_cycle, ap])                   # D9 (do, redo)

initial_parallel = sub(Operator.PARALLEL, [containment_stream, analysis_stream])  # C1

tree = sub(Operator.SEQUENCE, [rd, initial_parallel, trial_loop, rm, ac])         # D1, D2, D10, D13
```

**What the tree cannot represent exactly (approximation report).**
An exact blockstructured tree does not exist. Proof sketch: `route` must satisfy `ARC < route` yet be unordered w.r.t. the trial loop, while the loop must wait for `DCA` (inside the ARC branch) *and* `PV` (outside it). In a tree, the least common ancestor of the route subtree and the loop subtree would have to be a `PAR` (to permit their interleaving), but `PAR` composes languages by shuffle and cannot transmit the precedence `ARC < route` across branches; nesting the loop inside the ARC branch instead would make the loop wait for `PV`, which lives in the other branch. The only escapes are duplicating `ARC` (breaking the singleoccurrence assumption, since a silent copy would destroy the precedence) or duplicating the route/consultation across XORvariants of the whole process — the latter still misses routes whose execution *spans* the join and duplicates visible labels (`SR`, `QR`, `RR`, `CS`), so it was rejected. Consequently the delivered tree is a **conservative underapproximation**: it excludes exactly those intended traces in which the approval route or the supplier consultation completes *after the first `Execute Trial` starts* (violating intended C3/C4 while satisfying every hard dependency). Everything else — initial overlap, split dependencies, route choice with concurrent highrisk reviews, optionality and single occurrence of the consultation, loop discipline, release order, boundaries — is exact. Practical consequence: fitness against real logs will be systematically understated for cases with late approvals or long consultations; precision is unaffected (no unsafe trace is admitted).

# 4. PM4Py POWL Model

**Compact description:**

```text
root = StrictPartialOrder over nodes:
  RD, CM, ARC, PV, DCA, RM, AC                : Transition (visible)
  RISK  = OperatorPOWL(XOR)[ SR , PO_HIGH ]   where PO_HIGH = StrictPartialOrder{QR, RR},
                                                no internal edges  =>  QR  RR
  SUP   = OperatorPOWL(XOR)[ CS ,  ]          = SilentTransition (skip; optional, <=1)
  TRIAL = OperatorPOWL(LOOP)[ PO_TRIAL , AP ] where PO_TRIAL = StrictPartialOrder{ET -> IT}
                                                (do = ETIT, redo = AP)

root.order edges:
  RDCM, RDARC, CMPV, ARCDCA, ARCRISK, ARCSUP,
  PVTRIAL, DCATRIAL, RISKRM, TRIALRM, SUPRM, RMAC
```

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

# --- visible transitions -------------------------------------------------
rd  = Transition(label="Register Deviation")
cm  = Transition(label="Contain Material")
arc = Transition(label="Analyze Root Cause")
pv  = Transition(label="Plan Verification")
dca = Transition(label="Design Corrective Action")
sr  = Transition(label="Supervisor Review")
qr  = Transition(label="Quality Review")
rr  = Transition(label="Regulatory Review")
cs  = Transition(label="Consult Supplier")
et  = Transition(label="Execute Trial")
it  = Transition(label="Inspect Trial")
ap  = Transition(label="Adjust Parameters")
rm  = Transition(label="Release Material")
ac  = Transition(label="Archive Case")

# --- silent transition for the optional supplier consultation -------------
tau_no_supplier = SilentTransition()

# --- submodels -------------------------------------------------------------
po_high = StrictPartialOrder(nodes=[qr, rr])          # no internal edge => QR  RR (C2)
risk_route = OperatorPOWL(operator=Operator.XOR, children=[sr, po_high])   # D5

supplier_step = OperatorPOWL(operator=Operator.XOR,
                             children=[cs, tau_no_supplier])               # D6, optional

po_trial_cycle = StrictPartialOrder(nodes=[et, it])
po_trial_cycle.order.add_edge(et, it)                 # do-branch: ET before IT (D9)
trial_loop = OperatorPOWL(operator=Operator.LOOP,
                          children=[po_trial_cycle, ap])                   # D9 (do, redo)

# --- top-level strict partial order ---------------------------------------
powl = StrictPartialOrder(
    nodes=[rd, cm, arc, pv, dca, risk_route, supplier_step, trial_loop, rm, ac]
)

powl.order.add_edge(rd, cm)             # D1
powl.order.add_edge(rd, arc)            # D2
powl.order.add_edge(cm, pv)             # D3
powl.order.add_edge(arc, dca)           # D4
powl.order.add_edge(arc, risk_route)    # D5
powl.order.add_edge(arc, supplier_step) # D6
powl.order.add_edge(pv, trial_loop)     # D7 (join input 1)
powl.order.add_edge(dca, trial_loop)    # D8 (join input 2)
powl.order.add_edge(risk_route, rm)     # D11
powl.order.add_edge(trial_loop, rm)     # D10
powl.order.add_edge(supplier_step, rm)  # D12
powl.order.add_edge(rm, ac)             # D13
```

**Why every intentionally unconnected pair may remain concurrent.** In a `StrictPartialOrder`, a node becomes enabled exactly when all its predecessors have completed; if there is no directed path between two nodes in either direction, the model imposes no order and the underlying net exhibits true concurrency. Checking all unordered toplevel pairs: `(CM, ARC)` — Requirement 2; `(ARC, PV)` — planning depends only on containment, analysis may still run; `(PV, DCA)`, `(PV, RISK)`, `(PV, SUP)` — planning is ordered only after `CM`; `(CM, DCA)`, `(CM, RISK)`, `(CM, SUP)` — containment is ordered only before `PV`; `(DCA, RISK)`, `(DCA, SUP)` — both are enabled by `ARC` and mutually unconstrained (Requirements 5–6); `(RISK, SUP)` — consultation may overlap approvals (Requirement 6); `(RISK, TRIAL)` — approvals may overlap the trial cycle (Requirement 7); `(SUP, TRIAL)` — consultation may overlap trial work (Requirement 6). Internally, `(QR, RR)` in `PO_HIGH` carries no edge, giving the required eitherorder completion (Requirement 5). Every ordered pair is justified by a §2 dependency, and no pair that should be ordered is unordered (e.g., `CM` vs `TRIAL` is ordered transitively via `PV`; `ARC` vs `TRIAL` via `DCA`). Thus the POWL language coincides with the linearizations of the intended dependency specification.

# 6. Semantic Comparison

| Requirement | Intended semantics | Process tree | POWL | Overconstraint or underconstraint | Business consequence |
|---|---|---|---|---|---|
| Two initial work streams | `CM  ARC` after RD, free overlap | Exact (`+` of two `->` branches), as a trace language | Exact (no edge `CMARC`) | None | Containment and analysis genuinely proceed in parallel; no artificial waiting. |

# 7. Preferred Representation and Validation Plan

**Preferred representation: the POWL model.** It reproduces the intended dependency specification exactly — every §2 relation is one explicit edge or operator, with no duplication and no excluded legal behavior. The process tree is retained as a conservative, safely deployable simplification (e.g., for tools that only consume blockstructured models), but the POWL model is canonical for conformance and analysis.

**Validation plan (concrete):**

1. **Convert to accepting Petri nets.**
   ```python
   import pm4py
   net_t, im_t, fm_t = pm4py.convert_to_petri_net(tree)   # tree -> net (long supported)
   net_p, im_p, fm_p = pm4py.convert_to_petri_net(powl)   # POWL -> net (recent pm4py)
   ```
2. **Soundness of converted nets.** Run `pm4py.check_soundness(net_p, im_p, fm_p, print_diagnostics=True)` (and analogously for the tree net). Expected: sound — proper completion, no dead transitions, no deadlock markings. Failure here would indicate a construction bug, not a semantics discovery.
3. **Sampled/bounded playout.** Generate e.g. 200 traces via `pm4py.play_out(...)` from each model and assert structural invariants: first activity `RD`, last `AC`; `ET`/`IT` alternate starting with `ET`; every `AP` is immediately preceded by an `IT` and followed by an `ET`; `QR` occurs iff `RR` occurs; `SR` never cooccurs with `QR`/`RR`; `CS` (if present) lies strictly between `ARC` and `RM`. For POWL playouts additionally assert that both `CS`-during-trial and `QR`-before-`RR` and `RR`-before-`QR` positions occur in the sample (coverage of the overlap the tree cannot express).
4. **Explicit positive tests.** Replay W1–W5 (packaged as an event log) with `pm4py.conformance_diagnostics_alignments` against both nets. Expected: fitness 1.0 on the POWL net for all five; on the tree net, W1/W2/W4/W5 fit and **W3 does not** — the deviation localizes exactly at `CS`, empirically confirming the documented approximation.
5. **Explicit negative tests.** Replay F1–F3 against both nets; expect nonempty deviations with the earliest deviation at `PV`/`ET` (F1), at `RM` (F2), and at `AP` (F3), matching the "earliest violated condition" column of §5.
6. **Silentbehavior and duplicatelabel checks.**
   - Label inventory: collect `[t.label for t in net_p.transitions if t.label is not None]` and assert it is exactly the 14 canonical labels, each appearing once (no duplicated labels introduced by conversion).
   - Silence audit: enumerate transitions; expect only the supplierskip  plus a small, inspectable set of operatorplumbing 's. Verify by alignment that (a) the empty trace and an `RD`only trace do **not** fit ( cannot shortcut the mandatory skeleton), and (b) F2 does not fit ( cannot replace a required review). Together these show the silent transition only skips `CS`.
   - Optionally compute `pm4py.precision_alignments` / fitness on a shared sample log for both models to quantify the tree's fitness penalty (expected: lower fitness, comparable or higher precision).
7. **Limitations of the plan.** Soundness is necessary, not sufficient, for semantic fidelity to the narrative; sampled playout cannot prove absence of bad traces; alignment verdicts depend on the chosen cost function; risk class, inspection outcome, and supplier flags are invisible to control flow, so routetodata consistency is untestable here; POWLnet conversion details vary across pm4py versions; and tracebased evidence can never distinguish true concurrency from adversarial sequentialization.

# 8. Final Self-Critique

1. **Semantic weakness — outcome abstraction.** Modeling "passing inspection" as loop exit means any `IT` followed (eventually) by `RM` is *deemed* passing. If a real log records a failed inspection followed by release without `AP` (misrecording or a genuine deviation), both models silently classify it as a normal passing case; symmetrically, the models cannot crosscheck the number of `AP` occurrences against recorded failure flags. The controlflow abstraction is faithful to Requirement 11 but blind to outcome data.
2. **Semantic weakness — unconstrained overlap is maximally permissive.** Interpreting "may overlap" as pure absence of constraints lets the POWL admit degenerate schedules — e.g., `CS` started immediately after `ARC` and left pending until `RM`, or the approval route stretched across the entire trial — with no resource, workload, or servicelevel realism. The model is correct w.r.t. the stated dependencies but offers no guidance on *typical* timing; any contentionaware analysis would need additional (currently unavailable) constraints.
3. **Residual approximation asymmetry.** The tree's underapproximation biases any empirical comparison between the two models: fitness gaps on real logs conflate "process deviates" with "tree is deliberately narrower," and the chosen policy quietly encodes the assumption that consultations and approvals usually finish before trials — if field data contradicts this, the tree (not the process) must be redesigned, likely via the rejected duplication variant, importing the labelduplication problems documented in §6. Additionally, the code targets recent pm4py APIs (nested `StrictPartialOrder` inside `OperatorPOWL`, POWLnet conversion); on older versions the trial cycle may need flattening, so successful execution remains evidence to inspect, not proof of fidelity.
