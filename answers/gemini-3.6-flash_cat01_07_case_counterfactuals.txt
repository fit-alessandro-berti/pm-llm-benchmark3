## 1. Feasibility model

```text
PARTIAL ORDER RELATIONS (PRECEDENCE GRAPH):
Register < Triage
Triage < Identity Check
Triage < Document Check (if originals_required == No)
Triage < Originals Receipt (if originals_required == Yes)
Originals Receipt < Document Check (if originals_required == Yes)
{Identity Check, Document Check} < Assessment
Assessment < Escalation Advice (optional / conditional)
{Assessment, [Escalation Advice]} < Compliance Review (if high_risk == Yes OR high_value == Yes)
Assessment < Decision (if high_risk == No AND high_value == No)
Compliance Review < Decision (if high_risk == Yes OR high_value == Yes)
Assessment < Request More Info (conditional rework trigger)
Compliance Review < Request More Info (conditional rework trigger)
Request More Info < Document Check (rework iteration)
Decision < Notify
```

```text
CONDITIONAL AND DECLARATIVE CONSTRAINTS:
1. Four-Eyes Constraint: Resource(final(Assessment)) != Resource(final(Compliance Review)).
2. Resource Exclusivity: For all resources r and time intervals [s1, e1], [s2, e2], if r performs task1 during [s1, e1] and task2 during [s2, e2], then [s1, e1]  [s2, e2] =  (except advisory S1 overlap).
3. Compliance Requirement: If (high_risk == True OR high_value == True), Compliance Review must be performed after the final Assessment and before Decision.
4. Rework Loop Requirement: Request More Info mandates a subsequent Document Check and Assessment before any Decision or Compliance Review re-evaluation.
5. Original Document Constraint: If originals_required == True, Document Check start timestamp >= Originals Receipt completion timestamp.
```

### Intervention Classification
- **Timing-only alteration:** **K-411** (Parallelize verification tasks via workaround). Modifies task start boundaries and concurrent execution timing without changing the sequence of activities or business logic.
- **Routing & Resource allocation alteration:** **K-104** (Early preliminary escalation and reserved slot) and **K-219** (Resource substitution from D1 to D2). K-104 shifts advisory work to run in parallel with verification tasks. K-219 alters resource dispatch logic based on queue state.
- **Allowed decision policy alteration:** **K-337** (Prohibit second `Request More Info` rework loop). Alters the business rule governing case sufficiency, forcing a terminal decision under uncertainty rather than permitting iterative clarification.

## 3. Counterfactual derivations

### K-104
- `Factual mechanism:` Sequential execution delayed discovery of sanctions ambiguity until A1 Assessment on Tue 19:10. This forced a reactive referral to S1 (Tue 19:20–21:20), followed by C1 queue wait until Wed 13:10 because C1 required full evidence review from scratch.
- `Minimal intervention:` Triage dispatches an early escalation packet to S1 on Mon 08:50 and places a provisional reservation in C1's schedule for Tue afternoon.
- `Temporal propagation:` S1 conducts preliminary analysis concurrently with Identity and Document checks on Mon afternoon. When D1 completes the complex document check on Tue 05:40, A1 starts Assessment on Tue 08:00 with S1’s notes already attached. A1 completes by Tue 11:30. Because C1 received preliminary background context, C1's final review duration drops from 4.5h to 3.0h and starts on Tue 13:00 (utilizing the reserved slot). Case completes Tue 17:00 instead of Wed 18:40.
- `Process-feasibility check:` Complies with Normative Rules 2, 5, 9, and 10. Final Compliance Review occurs after final Assessment. Four-eyes rule holds (A1 Assessment, C1 Compliance).
- `Best/base/worst case:` Best case: -26h cycle time (finish Tue 16:30). Base case: -22h cycle time (finish Tue 20:30). Worst case: -4h cycle time (D1 delay causes C1 reserved slot to be missed, forcing re-queuing).
- `Evidence that would reverse the conclusion:` If the preliminary packet lacks crucial ownership structure details only revealed during D1’s complex document check, S1’s early work becomes redundant, invalidating the time savings.

### K-219
- `Factual mechanism:` Case waited in D1's heavy queue (13h backlog) from Mon 17:30 until Tue 09:30 because Triage routed handwritten documents exclusively to specialist D1.
- `Minimal intervention:` Re-route Document Check to generalist D2 at Mon 17:30 immediately upon Originals Receipt.
- `Temporal propagation:` Mon 17:30 snapshot shows D2 queue at 2–5h compared to D1's 11–13h. D2 picks up the task on Mon 20:00 or Tue 08:00. Assuming standard processing (5.5h service time for D2 on handwriting), Document Check completes Tue 13:30. Assessment A2 starts Tue 14:00 (queue 6h) and completes Tue 16:30. Decision M1 signs Tue 17:30.
- `Process-feasibility check:` Complies with Normative Rules 2 and 4. Originals Receipt precedes Document Check.
- `Best/base/worst case:` Best case: -16h cycle time (completion Tue 17:30 instead of Wed 09:00). Base case: -12h cycle time. Worst case: +24h cycle time (D2 misinterprets handwriting, triggering `Request More Info` and rework).
- `Evidence that would reverse the conclusion:` A historical error log showing D2 has a >40% error/rework rate on handwritten non-standard entries, turning a local queue save into a major rework delay.

### K-337
- `Factual mechanism:` Iterative document request loop (`Request More Info 1` and `2`) caused by persistent supplier total discrepancies, incurring external delays and weekend holdover.
- `Minimal intervention:` Intervene after Assessment 2 (Fri 10:30) to prohibit `Request More Info 2`, forcing an immediate evaluation under existing evidence.
- `Temporal propagation:` Bypassing the second rework loop eliminates `Request More Info 2` (Fri 10:30 to Mon 09:00), `Document Check 3` (Mon 13:00–16:30), and `Assessment 3` (Tue 08:00–10:30). Case moves directly from Assessment 2 to Compliance Review (C1) on Fri 11:00. C1 reviews existing evidence Fri 11:00–15:00. Manager M1 executes conditional decision Fri 16:00. Total cycle time drops from 214.1h to 101h.
- `Process-feasibility check:` Complies with Normative Rules 5, 7, and 9. High-risk/high-value requirement satisfied by C1 review after Assessment 2. Changes the allowed decision policy, replacing full verification with conditional acceptance/rejection.
- `Best/base/worst case:` Best case: -113h cycle time (complete Fri 16:00 before weekend). Base case: -96h cycle time (complete Mon 11:00 if C1 queue delays Fri work). Worst case: -90h cycle time, but decision results in outright rejection, causing customer loss.
- `Evidence that would reverse the conclusion:` Legal or compliance mandate strictly forbidding conditional approvals whenever external supplier totals disagree by more than a zero-tolerance threshold.

### K-411
- `Factual mechanism:` Sequential execution enforced by legacy software lock; Document Check was artificially delayed until Identity Check completed on Tue 13:20.
- `Minimal intervention:` Initiate both Identity Check (I2) and Document Check (D2) concurrently at Triage (Tue 09:35) using a software bypass.
- `Temporal propagation:` I2 starts Identity Check Tue 11:30 (completes Tue 13:20). Concurrently, D2 picks up Document Check Tue 11:30 (D2 queue 4h at Tue 08:00) and completes Tue 16:00 (4.5h service duration). Both verifications complete at Tue 16:00 instead of Tue 19:30. Case enters Assessment queue 3.5h earlier on Tue afternoon.
- `Process-feasibility check:` Complies with Normative Rules 2 and 3. No original documents required; full concurrency is valid.
- `Best/base/worst case:` Best case: -20.5h cycle time (A2 assesses Tue late afternoon 16:30–19:00, M1 decides Tue 19:15). Base case: -3.5h cycle time (case sits in A2 queue overnight, completing Wed 11:00 instead of Wed 14:30). Worst case: 0h change (A2 bottleneck absorbs all upstream gain).
- `Evidence that would reverse the conclusion:` System operational logs showing that A2's queue was completely saturated on Tue evening, forcing all incoming cases to wait until Wed morning regardless of arrival time.

|---|---|---|---|---|---|---|
| K-104 (Early Escalation & C1 Reservation) | +1.5h net (preliminary setup overhead) | Assessment (A1) downstream | Compliance (C1) queue for unreserved cases | High-risk/high-value cases needing C1 on Mon/Tue | Negative (increased congestion) if reservation efficiency < 80% | Reserved capacity is non-refundable; unused slots create permanent capacity loss. |
| K-219 (Resource Shift to D2) | +1.5h to +3.5h (D2 slower service time) | Documents (D1) queue | Documents (D2) queue | Standard document cases assigned to D2 | Positive if D1 is severe bottleneck; Negative if D2 overloads | Non-linear spike in D2 queue wait times once utilization exceeds 85%. |
| K-337 (Suppress Second Rework) | -8.5h service time (eliminates Doc Check 3 & Assessment 3) | Documents (D1) and Assessment (A1) queues | Compliance (C1) queue (earlier arrival) | Subsequent cases waiting for A1/D1 | Positive (capacity freed system-wide) | Step-function saving by cutting entire multi-day external loop. |

### 100-Case Weekly Rollout Analysis

When scaled to 100 similar cases per week, local efficiency gains interact dynamically across shared resource pools. 

Reserving scarce C1 compliance capacity (K-104 intervention) creates severe queue displacement. C1 is a single-resource bottleneck ($C1$). If 30% of high-risk cases reserve provisional C1 slots, minor upstream delays in Document Check (D1) cause C1 to sit idle during reserved slots. System snapshots show C1 backlogs at 18–20 hours; speculative reservations exacerbate this, inflating wait times for non-target urgent cases by up to 40%.

Substituting D2 for D1 on handwritten/complex tasks (K-219 policy) shifts workload from a specialist bottleneck to a generalist pool. While D1 queue drops from 13h to 6h, D2’s longer service times (4–8h vs 3–6h) raise D2 pool utilization. If D2 utilization crosses ~85%, queue build-up becomes non-linear, triggering higher clarification rates and inadvertent rework loops that re-inject cases into D1 or A2.

Suppressing second rework loops (K-337 policy) yields massive capacity recovery. Eliminating redundant Document Check 3 and Assessment 3 runs frees approximately 8.5 service hours per truncated case across D1 and A1 pools. This directly reduces upstream queue build-ups and avoids weekend holdover penalties driven by external supplier delays.

Parallelizing verification tasks (K-411 policy) does not alter total work hours but changes arrival distributions. Simultaneous completion of Identity and Document checks shifts case arrivals at Assessment (A2) from staggered intervals into concentrated batches. On high-arrival days (Mondays), this batching causes temporary queue spikes at Assessment, though total end-to-end flow time improves slightly provided A2 capacity is sufficient.

## 6. Pilot designs

|---|---|---|
| eligibility | All standard, low-risk/low-value cases requiring no original documents (`originals_required == False`). | High-risk/high-value cases reaching Assessment 2 with persistent non-material supplier discrepancies. |

| process-path outcome | Percentage of cases achieving true parallel execution without system timestamp locking errors. | Proportion of cases completing without entering `Request More Info 2`. |
| quality outcome | Rate of downstream assessment rework or data discrepancy findings. | Post-decision audit error rate, default rate, and appeal frequency of conditional decisions. |

## 7. Final synthesis

Intervention K-411 (Parallelizing verification tasks) is the most robust operational policy change. It removes an artificial technical constraint, aligns fully with normative process rules, carries zero cost in additional labor hours, and achieves immediate cycle-time savings without compromising decision quality.

Intervention K-104 (Provisional C1 reservation) is the most dangerous despite its apparent speed. Because C1 is a single-resource bottleneck ($C1$), reserving speculative capacity introduces rigidities. If upstream document checks delay, reserved C1 time is lost permanently, creating severe queue spillovers that delay non-target urgent compliance reviews across the entire system.

A local case counterfactual is least transportable to a system-wide policy in Intervention K-219 (D2 substitution). On a single case, reassigning work to D2 successfully bypasses D1’s long queue. However, scaled system-wide, D2’s slower processing speed on complex handwriting increases total workload demand, quickly causing D2's queue to explode non-linearly and driving higher rework rates that degrade overall operational performance.

To enable high-fidelity operational forecasting, the system requires real-time queue state telemetry (active service vs. queue waiting timestamps) and task-level error/rework transition matrices stratified by document type and resource skill.

## 8. Assumption audit

1. `[structural]` The normative rules represent absolute hard constraints; no activity may bypass specified sequence requirements (e.g., Compliance Review following Assessment for high-risk cases) unless explicitly authorized by policy intervention.
2. `[temporal]` Service times across activities follow bounded stochastic distributions consistent with system guidance rather than fixed deterministic constants.
3. `[resource]` Specialist resource C1 is strictly non-substitutable during the operational window and represents the sole fully certified compliance reviewer.
4. `[behavioral]` Senior advisers (S1) can perform preliminary advisory analysis concurrently with operational verification tasks without requiring locked final verification outputs.
5. `[quality]` Generalist resource D2 exhibits a higher baseline probability of error or clarification requests when processing handwritten non-standard documents compared to specialist D1.
6. `[interference]` Resource capacity is strictly additive and exclusive; individual resources cannot process multiple service tasks simultaneously (excluding passive advisory overlap for S1).
7. `[quality]` Halting iterative rework loops (K-337 intervention) forces decisions under residual uncertainty, inherently shifting the decision distribution toward conditional approvals or rejections.
8. `[interference]` Queue wait times respond non-linearly to aggregate utilization changes, such that shifting tasks to secondary resource pools increases queue times exponentially past 85% capacity utilization.
