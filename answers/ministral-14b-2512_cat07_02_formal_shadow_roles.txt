# 5. PM4Py Role-Discovery and Similarity Code

```python
import pandas as pd
import pm4py
from pm4py.objects.log.util import dataframe_utils
from pm4py.algo.discovery.roles import algorithm as roles_discovery
from pm4py.algo.similarity.activity_based import algorithm as activity_similarity
from pm4py.visualization.workflow_net import visualizer as wf_net_visualizer
from pm4py.objects.log.util import dataframe_utils

# --- Step 1: Load and format the event log ---
# Assume `df` is the PM4Py-compatible dataframe with columns:
# case:concept:name, concept:name, time:timestamp, org:resource, case_complexity, etc.
df = pd.read_csv("event_log.csv")  # Replace with actual loading logic
log = dataframe_utils.convert_to_event_log(df)

# --- Step 2: Discover organizational roles (frequency-based) ---
roles_freq = pm4py.discover_organizational_roles(
    log,
    parameters={
        "variant": roles_discovery.Variants.FREQUENTLY_Together,
        "threshold": 0.1  # Adjust based on expected role granularity
    }
)
print("Frequently together roles:")
print(roles_freq)

# --- Step 3: Activity-based resource similarity ---
similarity_matrix = pm4py.discover_activity_based_resource_similarity(
    log,
    parameters={
        "similarity_function": "cosine",
        "normalization": True
    }
)
print("Top similar resource pairs:")
for pair, score in sorted(similarity_matrix.items(), key=lambda x: -x[1])[:5]:
    print(f"{pair}: {score:.2f}")

# --- Step 4: Handover-of-work and working-together networks ---
# Handover network (who passes work to whom)
handover_net = pm4py.discover_handover_of_work_network(log)
pm4py.visualization.workflow_net.visualize(handover_net)

# Working-together network (collaboration frequency)
working_together_net = pm4py.discover_working_together_network(
    log,
    parameters={
        "threshold": 0.05  # Adjust to filter noise
    }
)
pm4py.visualization.workflow_net.visualize(working_together_net)

# --- Step 5: Join role-discovery with case complexity and substitutions ---
# Filter for high-complexity cases and temporary substitutions
high_complexity_cases = pm4py.filter_event_attribute_values(
    log,
    "case_complexity",
    ["High", "Critical"]
)
substitution_episodes = pm4py.filter_event_attribute_values(
    log,
    "temporary_substitution",
    ["True"]
)

# Discover roles in high-complexity cases
roles_high_complexity = pm4py.discover_organizational_roles(
    high_complexity_cases,
    parameters={"variant": roles_discovery.Variants.FREQUENTLY_Together}
)
print("\nRoles in high-complexity cases:")
print(roles_high_complexity)

# --- Step 6: Avoid over-interpreting frequency as authority ---
# Example: Check if "Supervisor Approval" (A9) is handled by R08_Hana or R13_Mateo
approval_events = pm4py.filter_event_attribute_values(
    log,
    "concept:name",
    ["A9 Supervisor Approval"]
)
approval_roles = pm4py.discover_organizational_roles(
    approval_events,
    parameters={"variant": roles_discovery.Variants.FREQUENTLY_Together}
)
print("\nA9 approval roles:")
print(approval_roles)
# Output shows R08_Hana dominates (138 events) vs. R13_Mateo’s 44 preliminary approvals.
# This highlights that frequency  authority (Mateo lacks final approval power).

# --- Step 7: Cluster log by case attributes (e.g., customer_segment) ---
clustered_logs = pm4py.cluster_log(
    log,
    parameters={
        "attributes": ["customer_segment", "product_line"],
        "algorithm": "kmodes",  # For categorical attributes
        "k": 3  # Adjust based on expected clusters
    }
)
for i, cluster in enumerate(clustered_logs):
    print(f"\nCluster {i+1} (size: {len(cluster)}):")
    print(pm4py.discover_organizational_roles(cluster))
```

# 6. Operational Interpretation

### **Staffing Recommendations**
1. **Specialization**:
   - **Front-Office**: Maintain R01_Amira and R02_Ben as generalists, but train Amira for commercial work (A7/A8) to reduce Giorgio’s shadow load.
   - **Technical**: Pair R03_Chen (high complexity) with R04_Dina (triage) to optimize resource use.
   - **Commercial**: Fatima is irreplaceable; cross-train Giorgio for backup but monitor his efficiency.

2. **Cross-Functional Coordination**:
   - **Escalation Coordinator (Mateo)**: Formalize his role as a "triage lead" with authority to filter low-risk cases for specialists (e.g., Erik). Provide training on security/commercial basics to reduce rework.
   - **Quality Gatekeepers (Ivan/Julia)**: Assign Ivan to complex KB updates and Julia to high-volume quality checks.

3. **Temporary Workforce**:
   - Restrict R11_Kai/R12_Lina to A1/A4/A12 only; avoid A2/A3 to prevent reopened cases. Pair them with a mentor (e.g., Amira) for 2 weeks.

4. **Automation**:
   - Expand R14_Nora’s role to include A4 (Standard Response) for low-complexity cases, but retain human oversight for A2 (Validate Entitlement).

### **Training and Risk Control**
- **Risk 1: Overloading Shadow Roles**
  - *Example*: Giorgio’s commercial shadow work increased durations by 94% during Fatima’s absence.
  - *Mitigation*: Limit Giorgio’s commercial work to <20% of his time; use Mateo to pre-screen complex cases.

- **Risk 2: Ignoring Case Complexity in Staffing**
  - *Example*: Naïve clustering might assign Dina to Chen’s role, but her lower complexity (48% medium/high vs. Chen’s 71%) could lead to underperformance.
  - *Mitigation*: Use `case_complexity` to assign resources (e.g., route high-complexity cases to Chen/Ivan).

### **Resilience Strategies**
1. **Substitution Plans**:
   - For Fatima: Pre-approve Giorgio for A7/A8 up to 30% of her volume.
   - For Erik: Train Mateo to handle 20% of A6 events for low-risk cases (with rechecks).

2. **Process Controls**:
   - Add a "complexity flag" in A2 (Validate Entitlement) to route high-risk cases directly to specialists.
   - Implement automated alerts for >2-day waits in critical cases (e.g., security).

### **Cautions About Staffing Changes**
1. **Avoid Over-Reliance on Shadow Roles**:
   - *Example*: If Fatima is frequently absent, promoting Giorgio to a commercial role may work short-term but could create a bottleneck if he lacks formal authority for A9 (Approval).

2. **Do Not Reduce Specialist Headcount Based on Frequency**:
   - *Example*: Erik’s A6 events are rare (96 in 10 weeks), but his role is critical for compliance. Reducing his capacity could expose the organization to regulatory risks.
   - *Alternative*: Cross-train Mateo for 10% of Erik’s A6 workload, but retain Erik for critical cases.
