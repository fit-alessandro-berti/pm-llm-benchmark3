# 1. Source-Semantics Baseline

The POWL model is the authoritative artifact. Its behavior is restated below as testable invariants. A "positive witness" is a visible trace (or trace fragment) that a faithful target must admit; a "negative witness" is one it must reject. The last column states whether the invariant is decidable by observing tau-hidden complete traces alone, or whether it additionally requires marking/structural inspection.

Abbreviations: R = Register Change, AR = Assess Risk, PE = Prepare Evidence, LR = Legal Review, CT = Configure Trial, IT = Inspect Trial, CD = Correct Defect, RC = Release Change, AC = Archive Change.

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| I1 | R is the first visible activity of every trace | ⟨R, AR, PE, …⟩ | ⟨AR, R, …⟩ | Yes |
| I2 | AR and PE both occur exactly once after R, with no mutual order (both interleavings admitted) | both ⟨R, AR, PE, …⟩ and ⟨R, PE, AR, …⟩ | a model admitting only one of the two orders (rejection of ⟨R, PE, AR, …⟩) | Yes — requires checking *both* orders are admitted |
| I3 | LR is optional: it occurs zero or one time, and only after AR | ⟨R, AR, PE, CT, IT, RC, AC⟩ (no LR) and ⟨…, AR, …, LR, …, RC, …⟩ | ⟨R, LR, AR, …⟩; any trace with two LR | Yes for occurrence/count/position; the tau "skip" firing itself is invisible — only the *absence* of LR in a properly completed trace witnesses it |
| I4 | Verification cannot start: first CT only after both AR and PE | ⟨R, AR, PE, CT, …⟩ | ⟨R, AR, CT, IT, PE, …⟩ | Yes |
| I5 | No order between the optional-legal branch and the loop: LR may interleave before, between, or after loop activities | ⟨R, AR, PE, CT, LR, IT, RC, AC⟩ (LR inside the loop body) | a model that forces LR before CT or after the last IT (rejects the interleaved witness) | Yes — requires checking interleavings are admitted, not just one linearization |
| I6 | Within every iteration CT precedes IT; after CD a fresh CT must precede the next IT | ⟨…, CT, IT, CD, CT, IT, …⟩ | ⟨…, IT, CT, …⟩; ⟨…, CD, IT, …⟩; ⟨…, CT, CT, …⟩ | Yes |
| I7 | Consecutive iterations are separated by exactly one CD; CD never occurs first or last in the loop region | ⟨…, CT, IT, CD, CT, IT, RC, …⟩ | ⟨…, IT, CD, RC, …⟩ (CD without a following iteration) | Yes |
| I8 | At least one full iteration (≥1 CT–IT pair) in every trace | ⟨R, AR, PE, CT, IT, RC, AC⟩ | ⟨R, AR, PE, LR, RC, AC⟩ | Yes |
| I9 | RC occurs only after the loop has exited (last IT done, no pending CD-redo) **and** the legal branch is resolved (LR done or silently skipped) | ⟨…, LR, …, IT, RC, …⟩ and ⟨…, IT, …, LR, RC, …⟩ | ⟨…, RC, IT, …⟩; ⟨…, RC, …, LR, …⟩ | Yes for visible order; the "skip resolved" half needs proper completion (I11) to be meaningful |
| I10 | AC occurs exactly once, after RC, and is the final visible activity | ⟨…, RC, AC⟩ | ⟨…, AC, RC⟩; ⟨…, RC⟩ (missing AC) | Yes |
| I11 | Proper completion: every complete run ends in exactly the final marking, no residual tokens, no deadlock before it | complete run reaching fm exactly | run deadlocking mid-way, or reaching "sink + leftover token" | **No** — requires marking equality / soundness check, not trace observation |
| I12 | Label uniqueness: each visible label denotes exactly one task (no duplicate transitions per label required by the source) | one transition per label in the target | duplicated visible labels (breaks footprint/DFG validity) | No — structural property of the target model |

Note on I2/I5: POWL's absence-of-order is realized in the analyses below as arbitrary interleaving. "True concurrency" (simultaneous execution, step semantics) is not distinguishable from interleaving by any trace-based test; this is flagged again in Sections 4 and 9.

A structurally important fact: the sub-order {AR, PE} × {optional-legal, loop} with edges AR→legal, AR→loop, PE→loop (and *no* PE→legal edge) forms an **N-structure**, which is not series-parallel. The source is therefore *not block-structured*, and this single fact drives the expected fate of the process-tree pipeline.

# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| **P1 (primary): POWL → accepting Petri net → BPMN** | `pm4py.convert_to_petri_net(source_powl)` then `pm4py.convert_to_bpmn(net, im, fm)` | POWL→PN is the natively supported, semantics-defining conversion; PN→BPMN is a direct structural mapping that does not require block structure, so the N-structure survives | Tau transitions become invisible routing gateways; PN interleaving replaces declared "no order"; gateway proliferation harms readability | PN not a WF-net, unsound net, null/empty markings, or BPMN with dangling gateways |
| **P2 (secondary, allowed to fail): POWL → accepting Petri net → process tree → BPMN** | as P1, then `pm4py.convert_to_process_tree(net, im, fm)` in `try/except`, then `pm4py.convert_to_bpmn(tree)` | If it succeeded, a tree gives a clean, canonical block structure and the prettiest BPMN | The source is not series-parallel (N-structure), so a faithful tree does not exist; any "success" would necessarily approximate (e.g., add or drop an order) | `convert_to_process_tree` raises (expected and *correct* outcome); or succeeds but the tree's language differs from the net's — must then be rejected by Section 5 tests |
| P3 (validation round trip, not a delivery pipeline): each produced BPMN → accepting Petri net | `pm4py.convert_to_petri_net(bpmn)` per BPMN artifact | Enables behavioral comparison of BPMN artifacts against `net_from_powl` on common ground | Round-trip may introduce extra tau transitions/places; comparison must be tau-insensitive | BPMN→PN raises, yields non-WF-net, or yields null markings |

**Primary pipeline: P1.** P2 is retained deliberately as a falsification probe: its failure is evidence about the source's structure, not a bug.

Executed against pm4py 2.7.23, the observed outcomes were: P1 yields a sound WF-net (12 places, 11 transitions, 26 arcs, `im = [source:1]`, `fm = [sink:1]`) and a BPMN with 19 nodes / 22 flows; P2 raises `ValueError: Parsing of WF-net Failed` at the tree step, as predicted by the N-structure argument. All claims marked "validated" below refer to these executions.

# 3. Conversion Code

```python
import pm4py

# `source_powl` is assumed in scope, exactly as in the authoritative source definition.

# ---------- helpers ----------

def require_marking(name, marking):
    """Markings are not assumed non-null: fail loudly if a conversion returned none."""
    if marking is None or len(marking) == 0:
        raise RuntimeError(f"{name} is null or empty; conversion result unusable")
    return marking

def diagnose_net(tag, net, im, fm):
    """Workflow-net and soundness diagnostics for one accepting Petri net."""
    require_marking(f"{tag}.im", im)
    require_marking(f"{tag}.fm", fm)
    is_wf = pm4py.check_is_workflow_net(net)
    sound_result = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
    is_sound = sound_result[0] if isinstance(sound_result, tuple) else bool(sound_result)
    print(f"[{tag}] places={len(net.places)} transitions={len(net.transitions)} "
          f"arcs={len(net.arcs)} wf_net={is_wf} sound={is_sound}")
    return {"wf_net": is_wf, "sound": is_sound}

diagnostics = {}
round_trips = {}   # tag -> (net, im, fm), all round-tripped accepting nets

# ---------- (1) POWL -> accepting Petri net ----------
net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(source_powl)
diagnostics["net_from_powl"] = diagnose_net(
    "net_from_powl", net_from_powl, im_from_powl, fm_from_powl)

# ---------- (2) Petri net -> BPMN (primary pipeline P1) ----------
bpmn_from_net = pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)

# ---------- (3)+(4) process-tree intermediate (pipeline P2, allowed to fail) ----------
tree_from_net = None
bpmn_from_tree = None
tree_failure = None
try:
    tree_from_net = pm4py.convert_to_process_tree(
        net_from_powl, im_from_powl, fm_from_powl)
except Exception as exc:
    tree_failure = f"{type(exc).__name__}: {exc}"
    print(f"[pipeline P2] process-tree conversion FAILED (interpreted, not "
          f"suppressed): {tree_failure}")
    print("[pipeline P2] interpretation: the partial order contains the "
          "N-structure AR->{legal,loop}, PE->loop without PE->legal, which is "
          "not series-parallel; no faithful block-structured tree exists, so "
          "failure is the semantically correct outcome.")
if tree_from_net is not None:
    bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)

# ---------- (5) each produced BPMN -> accepting Petri net ----------
for tag, bpmn in (("bpmn_from_net", bpmn_from_net),
                  ("bpmn_from_tree", bpmn_from_tree)):
    if bpmn is None:
        continue
    try:
        rt_net, rt_im, rt_fm = pm4py.convert_to_petri_net(bpmn)
        require_marking(f"{tag}.rt_im", rt_im)
        require_marking(f"{tag}.rt_fm", rt_fm)
        round_trips[tag] = (rt_net, rt_im, rt_fm)
    except Exception as exc:
        print(f"[round-trip {tag}] FAILED: {type(exc).__name__}: {exc}")

# ---------- (6) diagnostics on every accepting net ----------
for tag, (rt_net, rt_im, rt_fm) in round_trips.items():
    diagnostics[f"rt_{tag}"] = diagnose_net(f"rt_{tag}", rt_net, rt_im, rt_fm)

# ---------- (7) visualizations ----------
pm4py.save_vis_powl(source_powl, "01_source_powl.png")
pm4py.save_vis_petri_net(net_from_powl, im_from_powl, fm_from_powl,
                         "02_net_from_powl.png")
pm4py.save_vis_bpmn(bpmn_from_net, "03_bpmn_from_net_primary.png")
if tree_from_net is not None:
    pm4py.save_vis_process_tree(tree_from_net, "04_tree_from_net.png")
if bpmn_from_tree is not None:
    pm4py.save_vis_bpmn(bpmn_from_tree, "05_bpmn_from_tree.png")
for tag, (rt_net, rt_im, rt_fm) in round_trips.items():
    pm4py.save_vis_petri_net(rt_net, rt_im, rt_fm, f"06_roundtrip_{tag}.png")
```

Executed results: `net_from_powl` is a sound WF-net; `bpmn_from_net` was produced; `convert_to_process_tree` raised `ValueError: Parsing of WF-net Failed`, so `bpmn_from_tree` was never created; the single round trip `bpmn_from_net → (rt_net, rt_im, rt_fm)` produced a sound WF-net with non-empty markings.

# 4. Preservation and Loss Audit

Columns use only the permitted terms. "Petri→Tree" is `conversion failed` throughout because the tree step raised; consequently there is no tree-side BPMN to audit.

| Source invariant | POWL→Petri | Petri→BPMN | Petri→Tree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| I1 first activity R | validated preserved | expected preserved | conversion failed | validated preserved | all complete traces in bounded exploration start with R, both nets |
| I2 AR ∥ PE, both interleavings | approximated (interleaving, not true concurrency) | approximated | conversion failed | approximated (both interleavings validated present) | both orders found in bounded language of both nets; simultaneity untestable |
| I3 LR optional, ≤1, after AR | validated preserved | expected preserved | conversion failed | validated preserved | traces with and without LR both complete; no double-LR trace in bound |
| I4 loop gated on AR **and** PE | validated preserved | expected preserved | conversion failed | validated preserved | negative witness ⟨R,AR,CT,…⟩ rejected by both nets |
| I5 no LR-vs-loop order | validated preserved | ambiguous (layout suggests an order; see §6) | conversion failed | validated preserved | witness with LR between CT and IT accepted by both nets |
| I6 CT before IT per iteration | validated preserved | expected preserved | conversion failed | validated preserved | ⟨…,IT,CT,…⟩ and ⟨…,CT,CT,…⟩ rejected |
| I7 CD strictly between iterations | validated preserved | expected preserved | conversion failed | validated preserved | ⟨…,CD,RC,…⟩ rejected; CD always followed by CT–IT in bound |
| I8 ≥1 iteration | validated preserved | expected preserved | conversion failed | validated preserved | ⟨R,AR,PE,LR,RC,AC⟩ rejected by both nets |
| I9 join before RC | validated preserved | expected preserved | conversion failed | validated preserved | ⟨…,RC,IT,…⟩ and ⟨…,RC,…,LR,…⟩ rejected |
| I10 AC final, after RC | validated preserved | expected preserved | conversion failed | validated preserved | every complete trace ends ⟨…,RC,AC⟩ |
| I11 proper completion / markings | validated preserved | ambiguous (BPMN has no marking concept; end-event reachability is the proxy) | conversion failed | validated preserved | im/fm non-null on both nets; soundness True on both; exact fm equality enforced in exploration |
| I12 label uniqueness | validated preserved | expected preserved | conversion failed | validated preserved | one visible transition per label in both nets; footprints therefore well-defined |

Required discussion points:

- **True concurrency vs. arbitrary interleaving.** POWL's "unordered" is compiled to Petri-net places enabling interleaving. Every test in Section 5 is trace-based, so it can confirm that *all interleavings are admitted* (I2, I5) but can never distinguish interleaving from simultaneous execution. The audit therefore records `approximated`, not `preserved`: the invariant as observable behavior survives; the concurrency *interpretation* is a modeling convention, not a validated fact.
- **The missing edge between Optional Legal Review and verification.** This absence is the semantic heart of the model (and the reason it is not block-structured). Its preservation is *positively* witnessed only by finding traces where LR interleaves inside the loop region, e.g. ⟨R, AR, PE, CT, LR, IT, RC, AC⟩ — which both `net_from_powl` and the round-tripped net accept. A converter that quietly serialized legal before the loop would still pass every "ordering" test; only the interleaving-presence test catches it.
- **Silent optional behavior.** The tau skip branch never appears in any trace. Its correctness is inferable only from complete traces *without* LR that still reach the exact final marking. Any validation that truncates traces or ignores final markings would be blind to a broken skip branch (e.g., one that deadlocks). This is why the bounded exploration requires exact final-marking equality.
- **Binary-loop semantics.** POWL's LOOP(body, redo) means body (redo body)\*. The Petri translation preserves this: CD is only enabled after a completed body and always forces another body. Validated by rejection of ⟨…, CD, RC, …⟩ and of a zero-iteration trace (I7, I8). In BPMN this becomes a backward-flow through exclusive gateways with no iteration counter — behaviorally equivalent but visually weaker (Section 6).
- **The join before Release Change.** Realized as a transition consuming from two places (an AND-join; in BPMN a parallel gateway). Validated by rejection of every trace where RC precedes the last IT or precedes LR. This is the invariant most at risk in any hand-edit of the BPMN, since deleting one gateway arm silently converts a synchronization into a race.
- **Activity-label uniqueness.** All nine visible labels are unique and remained unique through every conversion. This matters instrumentally: `discover_footprints` and DFG-style comparisons are only trustworthy under label uniqueness. If a converter ever duplicated a label (e.g., unrolled the loop), footprint equality could hold while languages differ.
- **Initial and final markings.** `convert_to_petri_net` returned non-null single-token source/sink markings in both directions (checked, not assumed). BPMN itself carries no markings; they are *re-synthesized* from start/end events during BPMN→PN. Their equality in structure does not guarantee equality in role — hence the exact-final-marking test rather than a "sink has a token" test.
- **Gateway / routing-node ambiguity in BPMN.** The BPMN from the net contains gateways synthesized from tau transitions and places (19 nodes for 9 tasks). Some exclusive gateways encode the LR-skip choice, others encode loop entry/exit; nothing in the diagram distinguishes these purposes, and a rendering that draws a gateway without labeling its conditions is easily misread as a business decision point. Assessed `ambiguous` at the visualization level even though the routed behavior round-trips correctly.

# 5. Round-Trip Validation Code

```python
import pm4py
from collections import deque
from pm4py.objects.petri_net.semantics import ClassicSemantics

SEM = ClassicSemantics()

# ---------- (a) soundness on every net (already run in §3; repeated for the record) ----------
for tag, (n, i, f) in {"net_from_powl": (net_from_powl, im_from_powl, fm_from_powl),
                       **round_trips}.items():
    ok = pm4py.check_soundness(n, i, f, print_diagnostics=False)
    print(tag, "sound:", ok[0] if isinstance(ok, tuple) else ok)

# ---------- (b) footprints comparison (defensible: labels are unique) ----------
fp_ref = pm4py.discover_footprints(net_from_powl, im_from_powl, fm_from_powl)
for tag, (n, i, f) in round_trips.items():
    fp = pm4py.discover_footprints(n, i, f)
    same = (fp_ref["sequence"] == fp["sequence"]
            and fp_ref["parallel"] == fp["parallel"]
            and fp_ref["activities"] == fp["activities"])
    print(tag, "footprints equal:", same)

# ---------- (c) reachability graphs (finite here: loop redo adds no unbounded state) ----------
rg_ref = pm4py.convert_to_reachability_graph(net_from_powl, im_from_powl, fm_from_powl)
for tag, (n, i, f) in round_trips.items():
    rg = pm4py.convert_to_reachability_graph(n, i, f)
    print(tag, "states:", len(rg.states), "vs ref:", len(rg_ref.states))

# ---------- (d) bounded visible-trace exploration ----------
def bounded_visible_language(net, im, fm, max_visible=12, max_silent_run=30):
    """
    Complete visible-trace language up to `max_visible` visible events.
    - transitions with label None are hidden;
    - a trace counts as complete only if the reached marking EQUALS fm exactly;
    - infinite silent cycling is impossible: visited (marking, visible-prefix)
      states are never re-expanded, and a run of >max_silent_run consecutive
      silent firings is pruned as a defensive second guard;
    - max_visible bounds loop iterations (~ (12 - 7) // 3 extra iterations here).
    Uses pm4py Petri-net semantics; pm4py.get_enabled_transitions(net, marking)
    is the equivalent top-level call for the enabling step.
    """
    def key(m):
        return tuple(sorted((p.name, m[p]) for p in m))
    complete, seen = set(), set()
    stack = [(key(im), im, (), 0)]
    while stack:
        mk, m, vis, silent_run = stack.pop()
        if (mk, vis) in seen:
            continue
        seen.add((mk, vis))
        if m == fm:                      # exact final-marking equality
            complete.add(vis)
        for t in SEM.enabled_transitions(net, m):   # == pm4py.get_enabled_transitions
            m2 = SEM.execute(t, net, m)
            if t.label is None:
                if silent_run < max_silent_run:
                    stack.append((key(m2), m2, vis, silent_run + 1))
            elif len(vis) < max_visible:
                stack.append((key(m2), m2, vis + (t.label,), 0))
    return complete

L_ref = bounded_visible_language(net_from_powl, im_from_powl, fm_from_powl)
for tag, (n, i, f) in round_trips.items():
    L_rt = bounded_visible_language(n, i, f)
    print(tag, "bounded language equal:", L_rt == L_ref,
          f"({len(L_ref)} vs {len(L_rt)} complete traces)")
    if L_rt != L_ref:
        print("  only in reference:", sorted(L_ref - L_rt)[:5])
        print("  only in round-trip:", sorted(L_rt - L_ref)[:5])

# ---------- (e) positive and negative witness traces ----------
R, AR, PE, LR = "Register Change", "Assess Risk", "Prepare Evidence", "Legal Review"
CT, IT, CD = "Configure Trial", "Inspect Trial", "Correct Defect"
RC, AC = "Release Change", "Archive Change"

POSITIVE = [
    (R, AR, PE, LR, CT, IT, RC, AC),            # legal taken, one iteration
    (R, PE, AR, CT, IT, CD, CT, IT, RC, AC),    # AR/PE swapped, two iterations, legal skipped
    (R, AR, PE, CT, LR, IT, RC, AC),            # LR interleaved INSIDE loop body (I5)
    (R, AR, PE, CT, IT, RC, AC),                # minimal trace, silent skip exercised
]
NEGATIVE = [
    (R, AR, PE, RC, AC),                        # zero iterations (I8)
    (R, AR, PE, IT, CT, RC, AC),                # IT before CT (I6)
    (R, LR, AR, PE, CT, IT, RC, AC),            # LR before AR (I3)
    (R, AR, CT, IT, PE, RC, AC),                # loop before PE (I4)
    (R, AR, PE, CT, IT, AC, RC),                # AC before RC (I10)
    (R, AR, PE, LR, LR, CT, IT, RC, AC),        # LR twice (I3)
    (R, AR, PE, CT, CT, IT, RC, AC),            # CT twice, no IT between (I6)
]
for tag, (n, i, f) in {"net_from_powl": (net_from_powl, im_from_powl, fm_from_powl),
                       **round_trips}.items():
    L = bounded_visible_language(n, i, f)
    for w in POSITIVE:
        assert w in L, f"{tag}: positive witness rejected: {w}"
    for w in NEGATIVE:
        assert w not in L, f"{tag}: negative witness admitted: {w}"
    print(tag, "all witness checks passed")

# ---------- (f) playout: sampled model traces must lie inside the bounded language ----------
for tag, (n, i, f) in {"net_from_powl": (net_from_powl, im_from_powl, fm_from_powl),
                       **round_trips}.items():
    try:
        log = pm4py.play_out(n, i, f)
        for trace in log:
            visible = tuple(e["concept:name"] for e in trace)
            if len(visible) <= 12:
                assert visible in L_ref, f"{tag}: playout trace outside reference language: {visible}"
        print(tag, f"playout ok ({len(log)} traces checked against reference language)")
    except Exception as exc:
        print(tag, "playout not supported / failed:", type(exc).__name__, exc)
```

**Executed results.** Soundness: True for `net_from_powl` and the round-tripped net. Footprints: equal. Reachability graphs: 15 states each. Bounded language at `max_visible=12`: identical, 24 complete traces per net. All 4 positive and 7 negative witnesses behaved correctly on both nets.

**Exhaustiveness statement.** The comparison is exhaustive *for complete visible traces of length ≤ 12*, i.e., up to roughly two redo iterations beyond the mandatory first (minimal trace length 7, each extra iteration adds 3 events). It is **not** exhaustive overall: the loop makes the full language infinite. The claim of equivalence beyond the bound rests on the inductive regularity of the loop structure (confirmed structurally by equal reachability graphs, which *are* finite and equal here), not on the trace enumeration itself.

# 6. Visual-Semantics Review

Even with a behaviorally validated underlying net, the BPMN diagram invites misreadings:

- **Parallel gateways.** The AND-split after Register and the AND-join before Release render AR ∥ PE and the pre-release synchronization. Readers frequently interpret parallel branches as "simultaneous work by different people," while the validated semantics only guarantees *order-freedom*. Conversely, some readers assume parallel branches are *independent*, missing that the AR branch feeds *both* the legal choice and (jointly with PE) the loop — the N-structure means the two "branches" are entangled, which the flat gateway pair does not show.
- **Exclusive gateways.** The LR-skip XOR and the loop entry/exit XORs are drawn with the same diamond. Nothing marks the skip gateway's silent branch as "do nothing"; an unlabeled edge bypassing Legal Review is routinely misread as an error in the diagram or as "legal review happens by default." The loop-exit gateway carries no condition, so readers cannot tell what terminates iteration.
- **Loop visualization.** The binary LOOP(body, redo) becomes a backward sequence flow through Correct Defect. The mandatory-first-iteration property (I8) is invisible: the drawing looks identical to a while-loop that might execute zero times. The "CD strictly between iterations" property (I7) is only recoverable by carefully tracing arrows.
- **Silent routing nodes.** Gateways synthesized from tau transitions and net places (the diagram has 19 nodes for 9 tasks) have no business meaning at all, but they are visually indistinguishable from meaningful decision points. Stakeholders will ask "who decides here?" at a node that decides nothing.
- **Apparent ordering from layout.** Left-to-right layout imposes a linear reading. If the layout places the legal branch above the loop, readers infer "legal happens in parallel *and finishes first*" or, worse, an order between LR and CT/IT that the model deliberately does not have (I5). Layout position encodes zero semantics, but it is the strongest visual signal on the page.

**Mitigations.** (1) Label every exclusive gateway with its question and label the silent branch explicitly ("legal review not required — skip"). (2) Annotate the loop-back edge ("defect found → correct and re-verify; first verification is mandatory"). (3) Add a text annotation at the pre-release join: "Release requires BOTH: verification passed AND legal branch resolved." (4) Add a diagram-wide note: "Branch layout does not imply timing; Legal Review may occur at any point between Assess Risk and Release." (5) Ship the diagram only together with the invariant table of Section 1 and the validation evidence of Section 5, and mark auto-generated routing gateways (e.g., grey fill) as non-decisions.

# 7. Rejection Criteria

A conversion artifact must be rejected or quarantined if any of the following holds:

1. **Null or empty markings** returned by any `convert_to_petri_net` call (initial or final) — the accepting net is unusable and nothing downstream can be validated.
2. **Not a workflow net or unsound**: `check_is_workflow_net` false, or `check_soundness` reports deadlocks, dead transitions, or improper completion (violates I11).
3. **Failed exact-final-marking test**: any complete-looking visible trace whose reached marking differs from `fm` (token leak or premature termination), even if the trace "reads" correctly.
4. **Loss of a required interleaving**: the round-tripped net rejects a positive witness — in particular ⟨R, PE, AR, …⟩ (I2) or the LR-inside-loop witness (I5). This is the quarantine trigger for any "successful" process-tree pipeline, since a tree must serialize or restructure the N-structure.
5. **Admission of release before verification** (or before legal resolution): any accepted trace with RC preceding the final IT or preceding a taken LR (violates I9), or admitting a zero-iteration run (violates I8).
6. **Collapse of optional behavior**: LR becomes mandatory (no complete trace without LR), becomes repeatable (a trace with two LR accepted), or the skip branch deadlocks (no-LR traces never complete).
7. **Footprint or bounded-language divergence** between `net_from_powl` and a round-tripped net, including any negative witness of Section 5 being admitted.
8. **Label integrity broken**: visible labels duplicated, renamed, or dropped during conversion (invalidates I12 and every label-based comparison — quarantine even if traces happen to match).
9. **Suppressed conversion exceptions**: any pipeline whose intermediate step raised and was silently ignored rather than recorded and interpreted; the artifact's provenance is then untrustworthy regardless of test results.

# 8. Canonical Representation Recommendation

- **Authoritative representation: the POWL source itself** (the Python construction, version-controlled as text). It is the only artifact that states the intended semantics directly — in particular the *absence* of an order between the legal branch and verification, which every downstream format either encodes indirectly (net places) or merely suggests (BPMN layout). Store alongside it the invariant table of Section 1 as the human-readable contract.
- **Derivative artifacts:** the accepting Petri net (`net_from_powl` + markings, exported as PNML), the BPMN from the primary pipeline, and all visualizations. Each is regenerated from the POWL source, never hand-edited.
- **Stakeholder visualization: the BPMN from pipeline P1**, annotated per Section 6. The POWL/Petri renderings are for engineers; the annotated BPMN is the communication artifact.
- **Required validation evidence per derivative:** the Petri net ships with WF-net + soundness results and its reachability-graph size; the BPMN ships with its round-trip net's soundness result, footprint-equality result, bounded-language equality (with the bound stated), and the witness-trace pass list. Any derivative lacking this evidence is quarantined by default.
- **Process-tree intermediate: disallowed for this model.** The source is provably not series-parallel (N-structure), so a tree either fails (observed: `ValueError: Parsing of WF-net Failed`) or approximates by adding/removing order — which rejection criterion 4 forbids. The attempt is kept in CI as a canary: if it ever *succeeds* after a model edit, that signals the model's structure changed and the audit must be redone, not that a tree pipeline became acceptable by default.
- **Avoiding round-trip drift:** edits happen *only* in the POWL source; every derivative is regenerated by the Section 3 script and re-validated by the Section 5 harness in CI; generated files are marked as generated and are never the target of pull-request edits; the witness lists are updated in the same commit as any semantic change, so a drifted derivative fails loudly rather than aging silently.

# 9. Residual Uncertainty

Even if every test above passes, the following claims remain unestablished:

1. **True concurrency.** No trace-based or marking-based test distinguishes "AR and PE may genuinely run simultaneously" from "AR and PE may occur in either order." The `approximated` verdicts on I2/I5 cannot be upgraded; simultaneity is a modeling interpretation outside the observable semantics of all three formalisms as tested.
2. **Behavior beyond the bound.** The bounded exploration is exhaustive only to 12 visible events (~3 loop iterations). Equivalence for deeper iterations is inferred from structural regularity (equal finite reachability graphs), not enumerated; a defect that manifests only at iteration depth ≥ 4 through some pathological gateway interaction would not be caught by the trace comparison itself.
3. **Fidelity of rendering and downstream consumption.** Passing tests validate the *net* behind the BPMN, not the diagram or its interchange file. A BPMN engine or human reader may apply different gateway semantics (e.g., inclusive-join timing, event handling defaults) than pm4py's BPMN→PN mapping assumes; the validation says nothing about execution on any engine other than the pm4py semantics used here.
4. **Intent capture.** All tests compare artifacts against the POWL source. If the source itself misstates the real change-management process (e.g., legal review actually must finish before trials start), every pipeline will faithfully preserve the wrong model; conversion validation cannot detect specification error.
