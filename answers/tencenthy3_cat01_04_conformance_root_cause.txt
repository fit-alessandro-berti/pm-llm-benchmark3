The conformance collapse is not a single event but a stack of superimposed artifacts. The May UI release changed only the displayed label, so `Risk Screen` is the same control-flow step as `Classify`; this alone created massive log-model moves until labels were remapped. Simultaneously, the gateway injected a technical `Queue Routed` event that never belonged to the normative tree, and the June ETL switch replaced source timestamps with warehouse-ingestion time, reversing `Decision` and `Notify` in some extracted traces. Each defect is visible in the staged alignment gains: label map (3258%), technical-event removal (81%), source-sequence ordering (89%). The August policy added a real, attribute-dependent `Supervisor Sign-off`, but the model was not versioned, so even cleaned logs showed 34% residual deviation until a permissive candidate tree was tried.

Stable cycle times, approval and appeal rates suggest the labeled, timestamped, and technical artifacts caused most of the measured drop rather than a wholesale process breakdown. However, unchanged aggregates neither prove the data are purely erroneous nor exonerate employees. A genuine subset of enhanced reviews without a recorded compliance check could be true bypasses or missing events; detection is admittedly incomplete. Noncompliance that affects only high-value cases may be invisible in portfolio KPIs. Therefore the abductive account must keep both data-quality failures and a smaller real compliance risk open until provenance audit closes the gaps.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py
from pm4py.algo.conformance.alignment import algorithm as align_algo
from pm4py.algo.evaluation.replay_fitness import evaluator as fitness_evaluator
from pm4py.algo.evaluation.precision import algorithm as precision_algo

# 1. Normative process tree
norm_str = "-> ( 'Receive', 'Classify', X ( * ( 'Standard Review', 'Request Info' ), -> ( 'Enhanced Review', 'Compliance Check' ) ), 'Decision', 'Notify' )"
norm_tree = pm4py.parse_process_tree(norm_str)
net, im, fm = pm4py.convert_to_petri_net(norm_tree)

variant_tables = {

        "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,
        "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
        "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,
        "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,
        "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 20,

def to_log_string(variants):
    lines = []
    c = 0
    for tr, cnt in variants.items():
        acts = [a.strip() for a in tr.split(',')]
        for _ in range(cnt):
            c += 1
            lines.append("case:" + str(c) + ":" + ",".join(acts))
    return "\n".join(lines)

logs = {k: pm4py.parse_event_log_string(to_log_string(v)) for k, v in variant_tables.items()}

# 4. Discover DFGs
for k, log in logs.items():
    dfg, sa, ea = pm4py.discover_dfg(log)
    print(k, "DFG edges:", len(dfg))

# 5. Alignment diagnostics and fitness
def evaluate(log, n, i, f):
    aligned = align_algo.apply(log, n, i, f)
    fit = fitness_evaluator.evaluate(aligned, log, n, i, f)
    return fit

print("Raw Jun_Jul fitness:", evaluate(logs["Jun_Jul"], net, im, fm))

# 6. Transparent normalization: map Risk Screen->Classify and remove Queue Routed
def normalize(log, remove_queue=True):
    for trace in log:
        i = 0
        while i < len(trace):
            ev = trace[i]["concept:name"]
            if ev == "Risk Screen":
                trace[i]["concept:name"] = "Classify"
            if remove_queue and ev == "Queue Routed":
                del trace[i]
                continue
            i += 1
    return log

norm_jun = normalize(logs["Jun_Jul"], remove_queue=True)
print("Normalized Jun_Jul fitness:", evaluate(norm_jun, net, im, fm))

# 7. Comparison already shown by raw vs normalized calls above

# 8. Candidate tree permitting optional Supervisor Sign-off (tau = silent skip)
cand_str = "-> ( 'Receive', 'Classify', X ( * ( 'Standard Review', 'Request Info' ), -> ( 'Enhanced Review', 'Compliance Check' ) ), X ( 'Supervisor Sign-off', \u03c4 ), 'Decision', 'Notify' )"
cand_tree = pm4py.parse_process_tree(cand_str)

print("Aug_Sep candidate fitness:", fit_cand, "precision:", prec_cand)
```

## 7. Provisional conclusion

The measured collapse in conformance from 93% to 32% in June–July is primarily a data-capture and model-management artifact, not a sudden breakdown in how claims are handled. Three superimposed logging changes explain most of the drop: (1) the UI relabeled `Classify` to `Risk Screen` without changing function; (2) a technical `Queue Routed` event entered the log; and (3) the ETL began using warehouse-ingestion time, reversing `Decision` and `Notify` in some traces. The staged recovery of fitness after label mapping (58%), technical-event removal (81%), and source-sequence ordering (89%) demonstrates that these defects account for roughly 57 of the 61 lost points. The remaining August–September drop is largely obsolete normative modeling: a new sign-off policy was not reflected in the tree, and high-value attributes were omitted from alignment reporting.

A real compliance problem may nevertheless remain, but its scale is uncertain. The persistent 25–30 enhanced-review traces without a recorded `Compliance Check`, and the undocumented use of `Manual Override`, could reflect true bypasses, missing events, or legitimate corrections. Stable approval, cycle, and appeal rates argue against widespread noncompliance, yet compliance itself warns that detection is incomplete and high-value cases may mask risk.

Confidence: 85% that logging/label/timestamp defects caused the majority of the measured collapse; 55% that a minor real compliance gap exists; 30% that employee noncompliance is systemic.

Immediate actions: IT must revert timestamps to source sequence, flag technical events, and version event schemas. Process owners must update the normative model with the sign-off policy and data conditions. Compliance should commission a provenance audit of enhanced-review-without-check and override cases, stratified by value.

We must not yet claim that employees are noncompliant, that the process is safe, or that the optional-sign-off model validates compliance—the candidate model is overpermissive and blind to the EUR 50,000 threshold.

## 8. Model-governance recommendation

1. **Model versioning** – Maintain an explicit versioned normative model with effective dates; any policy change (e.g., `Supervisor Sign-off`) must trigger a model revision and a migration note before conformance jobs run.
2. **Event-semantic contracts** – Define a signed contract for each event class: business meaning, label, and whether it is a technical vs user action; UI renames must map to the same semantic key before extraction.
3. **Technical-event policy** – Route purely technical events (e.g., `Queue Routed`) to a separate log or tag them; they must never enter control-flow conformance unless explicitly modeled.
4. **Timestamp provenance** – Preserve original source-system timestamps and sequence numbers as immutable attributes; warehouse-ingestion time may be stored separately but never replace event order in conformance.
5. **Data-aware constraints** – Extend control-flow models with attribute conditions (e.g., EUR 50,000 threshold for sign-off) using declarative or data-aware notations; aggregate alignment reports must include stratification by those attributes.
6. **Post-release validation** – After any UI, ETL, or policy release, run a staged diagnostic (label map, technical filter, order reconstruction, model comparison) and a small manual provenance audit before trusting conformance KPIs.
