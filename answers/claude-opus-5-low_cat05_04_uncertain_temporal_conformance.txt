# Uncertain Temporal Conformance Analysis — Incident Response (T-401 … T-409)

## 1. Normalization Assumptions

**A1 — Interval semantics.** Every event is represented as a closed interval of *true UTC occurrence time*, never as a point. Where evidence forces disjunction (DST fold), the representation is a **union of intervals** and is kept disjoint until a constraint eliminates a branch.

**A2 — Order of operations (mandated).** For each event:
1. **Display/resolution expansion** on the *recorded clock reading* (floor-to-minute → `[t, t+59.999s]`; round-to-nearest-10s → `[t−5s, t+5s]`; round-to-nearest-minute → `[t−30s, t+30s]`; HUB exact-second with ±0.5 s measurement → `[t−0.5s, t+0.5s]`).
2. **Time-zone conversion** of the local clock-reading interval to a UTC *clock* interval using the stated zone/offset (CEST = UTC+2, CET = UTC+1, EDT = UTC−4, BST = UTC+1).
3. **Clock-offset correction**, applied last.

**A3 — Offset direction.** `clock_offset = recorded_clock − true_clock` ⇒ `true = recorded − offset`. With `offset ∈ [a,b]` and a recorded-clock interval `[r⁻, r⁺]`, the feasible true-time interval is
`[r⁻ − b, r⁺ − a]`.
Note the inversion: a **positive** offset bound widens the interval **backwards** in time. Example: OPS-BER `[−90 s, +120 s]` on `10:14` CEST → UTC clock `[08:14:00, 08:14:59.999]` → true `[08:12:00.000, 08:16:29.999]`.

**A4 — Duration arithmetic.** For events with feasible intervals `X=[x⁻,x⁺]`, `Y=[y⁻,y⁺]`, the feasible duration is `[y⁻ − x⁺, y⁺ − x⁻]` (interval subtraction), computed **independently per pair** unless a constraint couples them (see A5, A7). Where two events come from the same source with a *common* offset, this is conservative (it double-counts the shared offset); I flag those cases rather than silently assuming offset correlation. All HUB-to-HUB durations below therefore carry a ±3 s envelope (±0.5 s resolution + ±1 s offset, twice); I keep it because HUB offset correlation is not documented.

**A5 — Causal/ordering constraints.** Recorded ingestion order and control-flow logic (`Alert_Received ≤ Investigation_Start ≤ Containment_Complete ≤ Close_Incident`) are used to *prune* infeasible combinations (T-405 folds; T-407 receipt; T-409 negative duration). Pruning is stated explicitly wherever it changes a classification, because it is an assumption, not a log fact.

**A6 — DST fold (T-405, 2025-10-26 Europe/Berlin).** Each `02:mm` local reading is a **union**: fold-1 (CEST, UTC+2) ∪ fold-2 (CET, UTC+1), i.e. two candidate UTC intervals one hour apart. Ingestion order then prunes:
- `Alert 02:50` fold-1 → UTC ≈ 00:49–00:52; fold-2 → 01:49–01:52.
- `IS 02:05` fold-1 → 00:04–00:07; fold-2 → 01:04–01:07.
- `CC 02:42` fold-1 → 00:41–00:44; fold-2 → 01:41–01:44.
If Alert were fold-2 (≥01:49) no later IS candidate exists (max 01:07) → **infeasible**. Hence Alert = fold-1, and IS must be fold-2 (fold-1 IS precedes Alert) and CC fold-2. **Exactly one fold assignment survives**, but the surviving timestamps remain minute-floored and offset-uncertain — pruning removes ambiguity, not imprecision.

**A7 — Inferred start (T-404).** `Investigation_Start = Investigation_Complete − duration`, with `Investigation_Complete ∈ [10:34:58.5, 10:35:01.5]` and `duration ∈ [1080 s, 1500 s]`. All uncertainty is retained: `IS ∈ [10:09:58.5, 10:17:01.5]` (a 7-minute-wide interval). The signed work record is treated as attested but coarse evidence, not a measurement.

**A8 — Missing receipt (T-407).** `Alert_Sent ≠ Alert_Received`. Receipt = send + latency, latency ∈ [0, 1200 s] ⇒ unconstrained receipt ∈ [13:59:58.5, 14:20:01.5]. This interval **extends past** `Investigation_Start` (14:17:00 ±1.5 s), which would imply a negative S1 duration. Two readings:
- **Primary (causal pruning ON):** receipt ≤ IS ⇒ receipt ∈ [13:59:58.5, 14:17:01.5], S1 duration ∈ [0 s, 1023 s] → testable.
- **Alternative (pruning OFF):** the pair is internally inconsistent → **INDETERMINATE**.
I report the primary reading and mark confidence as low because the causal premise is unlogged.

**A9 — Mobile entry delay (T-406) — material assumption.** The 5-minute entry delay is *not* a clock error; it is a gap between occurrence and recording. I state both semantics and adopt (a) as primary:
- **(a) Occurrence-shift semantics (primary):** the user typed a value up to 5 min *after* the event, so the true occurrence may be **up to 300 s earlier** than the normalized record time. `IS ∈ [12:03:30, 12:19:30]`.
- **(b) Record-only semantics:** the delay affects only when the row was written; the typed value still denotes occurrence. `IS ∈ [12:08:30, 12:19:30]`.
This choice **changes the T-406 S2 verdict** (possible violation under (a), certain pass under (b)) and is the single most consequential interpretive decision in this dataset.

**A10 — Degraded synchronization (T-409).** With only an engineering estimate `[−12 min, +12 min]`, OPS-BER `18:04` yields `IS ∈ [15:52:00, 16:16:59.999]`, which starts *before* the HUB alert (16:00:00 ±1.5 s). Unpruned, S1 admits negative durations ⇒ **INDETERMINATE** (internally inconsistent). Under ordering pruning `IS ≥ Alert`, S1 ∈ [0 s, 1021.5 s] → POSSIBLE_VIOLATION. Both reported; INDETERMINATE is the headline because the offset evidence is explicitly non-diagnostic.

**A11 — Rule semantics.** S1–S3 are one-sided maxima (`d ≤ L`); the temporal profile is a two-sided band `[μ − ζσ, μ + ζσ]`. An interval wholly inside the acceptance region = CERTAIN_PASS; wholly outside = CERTAIN_VIOLATION; straddling = POSSIBLE_VIOLATION. SLA compliance and profile conformance are independent verdicts.

**A12 — Midpoints.** Midpoints are never substituted for intervals. They appear only in §5 as an explicitly lossy secondary comparison.

**A13 — Sensor completion semantics.** SENSOR emits *completion* events, which matches `Containment_Complete`; no lifecycle re-anchoring is needed. Had it been used for a start activity, it would be INDETERMINATE.

This is the clearest illustration of the SLA/profile split: statistically the containment time is within three σ of normal, but legally it is out of contract. Do not let a permissive ζ mask an SLA breach.
- **T-408 CC→CI** stays a certain deviation through ζ=2 and only clears at ζ=3 (band `[21600, 151200]` — 6 h to 42 h, so wide it is nearly vacuous). ζ=3 on this pair has almost no discriminating power; I would cap ζ at 2 for CC→CI.
- **T-403 AR→IS** is the sharpest boundary case: at ζ=3 the band ends at 1140 s and the feasible interval ends at 1141.5 s, so it remains POSSIBLE_VIOLATION *by 1.5 seconds* — entirely attributable to VENDOR-NY's ±180 s bound plus minute floor. - **T-401, T-404, T-405 AR→IS** all resolve to CERTAIN_PASS at ζ=3; their ζ=1/2 flags are driven by upper interval tails, not by observed slowness.
- **T-406 AR→IS (a)** and **T-407/T-409 AR→IS** stay POSSIBLE at every ζ because their intervals straddle the band *on both sides* — widening the band cannot resolve a straddle whose lower end is near zero. **No ζ choice can fix these; only better evidence can.** Under semantics (b), T-406 IS→CC is CERTAIN_PASS at all ζ.

**Cross-cutting reading.** Tolerance and ζ move many verdicts, but the *set of certain SLA breaches* shrinks monotonically to `{T-408 S2, T-408 S3}`. Conversely, no tolerance or ζ setting converts any POSSIBLE_VIOLATION into a CERTAIN_VIOLATION. Uncertainty in this log is strictly exculpatory under a "certainty required for enforcement" policy — which is exactly why the governance controls in §7 matter.

## 5. PM4Py Temporal-Conformance Code

```python
"""
Interval-based temporal conformance for incident cases T-401..T-409.

Two independent computations:
  (A) Interval reasoning  -- authoritative. Pure Python/pandas + zoneinfo.
  (B) Midpoint event log  -- LOSSY APPROXIMATION, fed to pm4py.conformance_temporal_profile.

PM4Py does NOT natively model timestamp uncertainty: it consumes one point timestamp
per event. Anything it reports about (B) is a statement about the midpoint collapse,
not about the true event times. (B) exists only as a secondary cross-check on (A).

No external files are read.
"""

from __future__ import annotations

import datetime as dt
from dataclasses import dataclass
from zoneinfo import ZoneInfo

import pandas as pd
import pm4py

UTC = ZoneInfo("UTC")
BERLIN = ZoneInfo("Europe/Berlin")
NEWYORK = ZoneInfo("America/New_York")
LONDON = ZoneInfo("Europe/London")


# ----------------------------------------------------------------------------
# 1. Interval primitives
# ----------------------------------------------------------------------------
@dataclass(frozen=True)
class Iv:
    """Closed interval of true UTC occurrence time."""
    lo: dt.datetime
    hi: dt.datetime

    def shift(self, lo_s: float, hi_s: float) -> "Iv":
        return Iv(self.lo + dt.timedelta(seconds=lo_s),
                  self.hi + dt.timedelta(seconds=hi_s))

    def mid(self) -> dt.datetime:
        return self.lo + (self.hi - self.lo) / 2

    def __repr__(self) -> str:
        return f"[{self.lo.isoformat()}, {self.hi.isoformat()}]"


def dur_interval(a: Iv, b: Iv) -> tuple[float, float]:
    """Feasible duration b - a, in seconds (interval subtraction)."""
    return ((b.lo - a.hi).total_seconds(), (b.hi - a.lo).total_seconds())


def intersect(a: Iv, b: Iv) -> Iv | None:
    lo, hi = max(a.lo, b.lo), min(a.hi, b.hi)
    return Iv(lo, hi) if lo <= hi else None


# ----------------------------------------------------------------------------
# 2. Source metadata -> resolution expansion + clock-offset correction
#    Order (mandated): resolution -> timezone -> offset.
#    true = recorded - offset, offset in [a, b]  =>  [lo - b, hi - a]
# ----------------------------------------------------------------------------
SOURCES = {
    #                 tz,      resolution kind,      offset bound (seconds)
    "HUB":       (UTC,     ("sym", 0.5),             (-1.0, 1.0)),
    "OPS-BER":   (BERLIN,  ("floor_min", None),      (-90.0, 120.0)),
    "SENSOR":    (UTC,     ("sym", 5.0),             (-5.0, 5.0)),   # nearest 10 s
    "VENDOR-NY": (NEWYORK, ("floor_min", None),      (-180.0, 180.0)),
    "LEGACY-BER":(BERLIN,  ("floor_min", None),      (-60.0, 60.0)),
    "MOBILE-LON":(LONDON,  ("sym", 30.0),            (-300.0, 300.0)),  # nearest minute
}


def normalize(local_naive: dt.datetime, system: str,
              fold: int | None = None) -> Iv:
    """Return the feasible true-UTC interval for one recorded reading."""
    tz, (kind, param), (off_lo, off_hi) = SOURCES[system]

    # (1) display / resolution expansion, on the LOCAL CLOCK reading
    if kind == "floor_min":
        lo_local = local_naive.replace(second=0, microsecond=0)
        hi_local = lo_local + dt.timedelta(seconds=59, microseconds=999999)
    else:  # symmetric rounding half-width, in seconds
        lo_local = local_naive - dt.timedelta(seconds=param)
        hi_local = local_naive + dt.timedelta(seconds=param)

    # (2) timezone attach + conversion to UTC. `fold` disambiguates a DST fold:
    #     fold=0 -> first (summer-time) pass, fold=1 -> second (winter-time) pass.
    f = 0 if fold is None else fold
    lo_utc = lo_local.replace(tzinfo=tz, fold=f).astimezone(UTC)
    hi_utc = hi_local.replace(tzinfo=tz, fold=f).astimezone(UTC)

    # (3) clock-offset correction, applied LAST
    return Iv(lo_utc - dt.timedelta(seconds=off_hi),
              hi_utc - dt.timedelta(seconds=off_lo))


def d(s: str) -> dt.datetime:
    return dt.datetime.fromisoformat(s)


# ----------------------------------------------------------------------------
# 3. Raw evidence -> event intervals (DST ambiguity kept as ALTERNATIVES)
# ----------------------------------------------------------------------------

    "Containment_Complete": normalize(d("2026-06-01 08:51:10"), "SENSOR"),
    "Close_Incident":       normalize(d("2026-06-02 09:00:00"), "HUB"),
}
events["T-402"] = {
    "Alert_Received":       normalize(d("2026-06-01 09:00:00"), "HUB"),
    "Investigation_Start":  normalize(d("2026-06-01 11:18:00"), "OPS-BER"),
    "Containment_Complete": normalize(d("2026-06-01 10:02:00"), "HUB"),
}
events["T-403"] = {
    "Alert_Received":       normalize(d("2026-06-01 04:00:00"), "VENDOR-NY"),
    "Investigation_Start":  normalize(d("2026-06-01 08:16:00"), "HUB"),
    "Containment_Complete": normalize(d("2026-06-01 08:58:00"), "HUB"),
}

# T-404: start is INFERRED = Investigation_Complete - duration[18,25] min.
_ic404 = normalize(d("2026-06-01 10:35:00"), "HUB")
events["T-404"] = {
    "Alert_Received":       normalize(d("2026-06-01 10:00:00"), "HUB"),
    "Investigation_Start":  _ic404.shift(-25 * 60, -18 * 60),   # all uncertainty kept
    "Investigation_Complete": _ic404,
    "Containment_Complete": normalize(d("2026-06-01 10:55:00"), "HUB"),

# T-405: fold NOT logged -> each event is a UNION of two candidate intervals.
_alt405 = {
    "Alert_Received":       [normalize(d("2025-10-26 02:50:00"), "LEGACY-BER", fold=f) for f in (0, 1)],
    "Investigation_Start":  [normalize(d("2025-10-26 02:05:00"), "LEGACY-BER", fold=f) for f in (0, 1)],
    "Containment_Complete": [normalize(d("2025-10-26 02:42:00"), "LEGACY-BER", fold=f) for f in (0, 1)],

def prune_folds(alt: dict[str, list[Iv]], order: list[str]) -> dict[str, Iv]:
    """Keep only fold assignments consistent with the ingestion order
    (each event must be able to occur no earlier than its predecessor)."""
    import itertools
    survivors = []
    for combo in itertools.product(*[range(len(alt[a])) for a in order]):
        ivs = [alt[a][i] for a, i in zip(order, combo)]
        if all(ivs[k + 1].hi >= ivs[k].lo for k in range(len(ivs) - 1)):
            survivors.append(combo)
    if len(survivors) != 1:
        raise ValueError(f"fold ambiguity not resolved: {survivors}")
    combo = survivors[0]
    return {a: alt[a][i] for a, i in zip(order, combo)}

events["T-405"] = prune_folds(_alt405, _ORDER405)   # unique surviving assignment

_tz, _res, _ = SOURCES["OPS-BER"]

# 4. Feasible durations + interval classification

SLA = {  # name: (from, to, limit seconds)
    "S1": ("Alert_Received", "Investigation_Start", 900),
    "S2": ("Investigation_Start", "Containment_Complete", 2700),
    "S3": ("Containment_Complete", "Close_Incident", 36 * 3600),
}
PROFILE = {
    ("Alert_Received", "Investigation_Start"):   (600, 180),
    ("Investigation_Start", "Containment_Complete"): (2100, 600),
    ("Alert_Received", "Containment_Complete"): (2700, 720),
    ("Containment_Complete", "Close_Incident"): (86400, 21600),
}


def classify_upper(lo: float, hi: float, limit: float) -> str:
    """One-sided rule d <= limit."""
    if hi <= limit:
        return "CERTAIN_PASS"
    if lo > limit:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"


def classify_band(lo: float, hi: float, band_lo: float, band_hi: float) -> str:
    """Two-sided profile band [band_lo, band_hi]."""
    if lo >= band_lo and hi <= band_hi:
        return "CERTAIN_PASS"
    if hi < band_lo or lo > band_hi:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"


sla_rows, prof_rows = [], []
for case, evs in events.items():
    for rule, (a, b, limit) in SLA.items():
        if a not in evs or b not in evs:
            sla_rows.append(dict(case=case, rule=rule, lo=None, hi=None,
                                 classification="INDETERMINATE",
                                 note="required event missing"))
            continue
        lo, hi = dur_interval(evs[a], evs[b])
        note = ""
        if lo < 0:
            note = "negative lower bound -> internally inconsistent without ordering assumption"
        sla_rows.append(dict(case=case, rule=rule, lo=lo, hi=hi,
                             classification=classify_upper(lo, hi, limit), note=note))
    for (a, b), (mu, sigma) in PROFILE.items():
        if a not in evs or b not in evs:
            continue
        lo, hi = dur_interval(evs[a], evs[b])
        for zeta in (1, 2, 3):
            prof_rows.append(dict(case=case, pair=f"{a}->{b}", zeta=zeta,
                                  lo=lo, hi=hi,
                                  band=f"[{mu - zeta * sigma}, {mu + zeta * sigma}]",
                                  classification=classify_band(
                                      lo, hi, mu - zeta * sigma, mu + zeta * sigma)))

sla_df = pd.DataFrame(sla_rows)
prof_df = pd.DataFrame(prof_rows)

# SLA tolerance sensitivity: +0 / +2 / +5 minutes
tol_rows = []
for r in sla_rows:

        continue

    tol_rows.append({"case": r["case"], "rule": r["rule"],
                     **{f"+{t}min": classify_upper(r["lo"], r["hi"], limit + t * 60)
                        for t in (0, 2, 5)}})
tol_df = pd.DataFrame(tol_rows)

print("=== INTERVAL (authoritative) — SLA ===")

print("\n=== INTERVAL (authoritative) — temporal profile ===")
print(prof_df.to_string(index=False))
print("\n=== SLA tolerance sensitivity ===")
print(tol_df.to_string(index=False))
if T409_INCONSISTENT:

print(f"NOTE T-405: fold pruning left exactly one order-consistent assignment: "

mid_records = []
for case, evs in events.items():

                             activity_key="activity", timestamp_key="timestamp")

temporal_profile = pm4py.discover_temporal_profile(log)
# Override the discovered profile with the SUPPLIED one, so that PM4Py scores
# against the same (mu, sigma) pairs used in the interval analysis above.
supplied_profile = dict(PROFILE)
for key in list(supplied_profile):
    if key not in temporal_profile:

    else:
        temporal_profile[key] = supplied_profile[key]

midpoint_diag = {}
for zeta in (1, 2, 3):
    midpoint_diag[zeta] = pm4py.conformance_temporal_profile(
        log, temporal_profile, zeta=zeta)
    print(f"\n=== MIDPOINT (LOSSY) pm4py temporal-profile diagnostics, zeta={zeta} ===")
    for i, dev in enumerate(midpoint_diag[zeta]):
        print(f"  case {mid_df['case_id'].unique()[i]}: {dev}")

# --- VERSION ASSUMPTION (isolated) -------------------------------------------
# pm4py.conformance_temporal_profile returns, per case, a list of deviation
# tuples. Across versions the tuple shape has been either
#   (source_activity, target_activity, observed_time, num_std_devs)
# or a 5-tuple additionally carrying the zeta/threshold. The reading below only
# assumes elements [0] and [1] are the activity pair and that the LAST element
# is the deviation magnitude in standard deviations; nothing else depends on it.
def summarize_diag(diag, case_ids):
    out = []
    for cid, devs in zip(case_ids, diag):
        for devi in devs:
            try:
                src, tgt, magnitude = devi[0], devi[1], devi[-1]
            except Exception:
                src, tgt, magnitude = str(devi), "?", float("nan")
            out.append({"case": cid, "pair": f"{src}->{tgt}", "n_std": magnitude})

for zeta in (1, 2, 3):

                       iv_sub[iv_sub.classification == "POSSIBLE_VIOLATION"]["pair"]))

    print(f"  interval POSSIBLE    : {sorted(possible)}")
    print(f"  midpoint MISSES (certain but unflagged): {sorted(certain - md_pairs)}")
    print(f"  midpoint OVERSTATES  (flagged but only possible): {sorted(md_pairs & possible)}")
    print("  -> Every midpoint flag is a point verdict on a fabricated timestamp. "

The midpoint run is therefore reported as *approximate triage*, never as evidence.

## 6. Evidential Sufficiency

For each non-certain result, the **minimum** additional evidence that would collapse it to a certain verdict. Evidence classes: **[SYNC]** stronger synchronization, **[MISS]** missing activity, **[DUR]** duration evidence, **[SEM]** semantic/definitional evidence.

| Case · finding | Class | Minimum sufficient evidence |
|---|---|---|
| T-401 S1 & profile AR→IS (PV) | **[SYNC]** | Sub-second timestamp resolution on OPS-BER *or* a per-event NTP offset measurement narrowing [−90,+120] s to ≲±10 s. With the minute floor removed, the 718.5–991.5 s span collapses to ~±11 s around the true value and the 900 s boundary is decided. Resolution alone (seconds instead of minutes) removes 60 s of the 273 s width; both are needed for certainty. |
| T-402 S2 (PV) | **[SYNC]** | Same OPS-BER improvement. The interval overshoots 2700 s by 61.5 s; an offset bound tighter than ±30 s would settle it. |
| T-402 profile IS→CC (PV) | **[SYNC]** | As above. |
| T-403 S1, profile AR→IS, profile AR→CC (PV) | **[SYNC]** | Event-level synchronization with VENDOR-NY: a signed NTP/PTP offset attestation per batch, plus second-resolution timestamps. The ±180 s bound alone contributes 360 s of the 423 s width — this is the single highest-value fix in the dataset. Alternatively **[MISS]**: a HUB-side receipt record for the vendor alert would replace the vendor timestamp entirely. |
| T-404 S1, S2, profile AR→IS, IS→CC (PV) | **[DUR]** | A narrower attested investigation duration (e.g. ±1 min instead of the 7-min [18,25] range), or better **[MISS]**: recover the actual `Investigation_Start` event from a system-of-record (ticket transition log, screen-share start, first analyst command). An observed start makes all four findings certain immediately. |
| T-405 S1, profile AR→IS (PV) | **[SYNC]** | The fold is already resolved by ordering; what remains is minute-floor + ±60 s offset (360 s total width). Second-resolution logging on LEGACY-BER collapses this to ~120 s and decides the 900 s boundary. Independently **[SEM]**: an explicit UTC offset or fold flag per record would make the pruning argument unnecessary rather than assumed. |
| T-405 S3 / CC→CI (IND) | **[MISS]** | A `Close_Incident` event. Absent it, the rule is untestable — not compliant. |
| T-406 S1, S2, profiles (PV) | **[SEM]** first, then **[SYNC]** | The decisive ambiguity is semantic: does the typed value denote occurrence or entry? A device-generated capture timestamp *alongside* the user-entered value settles it and simultaneously removes the ±300 s user-clock bound. This single control flips T-406 S2 from POSSIBLE_VIOLATION to CERTAIN_PASS. Without it, no amount of clock evidence helps, because the 300 s entry delay is not a clock error. |
| T-407 S1, profile AR→IS (PV / IND) | **[MISS]** then **[SEM]** | A delivery/receipt acknowledgment event with its own timestamp makes S1 directly measurable. The causal premise "receipt ≤ start" should be recorded as an explicit modeling rule if relied upon. |
| T-409 S1 (IND) | **[SYNC]** | Restore NTP diagnostics for that hour. The ±12-min estimate is wider than the quantity being measured, which is why the result is INDETERMINATE rather than merely uncertain. Any offset bound narrower than ~±60 s makes S1 decidable. Note that the ordering-pruned reading is an *assumption-driven repair*, not evidence. |
| T-409 profile IS→CC (PV) | **[SYNC]** | As above. |
| All cases except T-401/T-408 · S3 (IND) | **[MISS]** | `Close_Incident` events. Six of nine cases cannot be tested against S3 at all; this is the largest single coverage gap in the log. |

**Priority ranking by findings resolved per control:** (1) OPS-BER second-resolution + per-event offset → resolves 5 findings across T-401, T-402, T-409; (2) `Close_Incident` capture → resolves 6 INDETERMINATEs; (3) mobile device-capture timestamp → resolves 4 T-406 findings; (4) vendor sync attestation → resolves 3 T-403 findings; (5) receipt ACK → resolves 2 T-407 findings.

## 7. Governance Recommendation

**Storage and representation**
1. **Store UTC as the canonical instant**, always with an explicit offset (`2026-06-01T10:14:00+02:00`), never a naive local string. Local time is a *presentation* concern.
2. **Retain the raw timestamp verbatim** alongside the normalized value — original string, original zone identifier, and the ingest-time normalization version. Normalization must be reproducible and re-runnable when offset telemetry is corrected retroactively.
3. **Record resolution metadata per event**: `resolution_unit` (second/10s/minute), `rounding_mode` (floor/nearest/ceiling), and `measurement_uncertainty`. The OPS-BER minute floor alone accounts for most of the T-401/T-402/T-405 ambiguity, and it is invisible without this field.
4. **Persist an uncertainty envelope** (`t_min`, `t_max`) as first-class columns, computed at ingest. Downstream tools that need a point value must opt in explicitly and be labelled lossy.

**Clock and synchronization**
5. **Source offset telemetry as a time series, not a static bound.** Sample NTP/PTP offset per source at least every 5 minutes and join the *contemporaneous* offset to each event rather than a daily worst case. T-409 is INDETERMINATE purely because the telemetry gapped.
6. **Define a synchronization SLO per source** (e.g. |offset| ≤ 1 s for systems feeding SLA rules) and treat breach of the SLO as an incident in its own right. Sources that cannot meet it must not be the sole evidence for a rule with minute-scale limits — VENDOR-NY's ±180 s bound cannot support a 15-minute SLA.
7. **Require signed sync attestations from external sources**; where unavailable, mirror the event at the trust boundary (a HUB-side receipt) and measure against the mirror.

**Time zone and DST**
8. **Log the UTC offset and the DST fold flag explicitly** for every local-time record. `fold` is a single bit that would have eliminated the entire T-405 branch analysis. Prefer storing UTC + zone id over local + zone id.
9. **Forbid ambiguous local times in interchange formats.** Reject at ingest any local timestamp during a fold window that lacks an offset.

**Lifecycle and activity semantics**
10. **Adopt explicit start/complete lifecycle transitions** (`activity` + `lifecycle:transition`) rather than encoding semantics in activity names. SENSOR's "device events are completion events" must be a data field, not documentation.
11. **Never conflate near-synonymous activities.** `Alert_Sent` and `Alert_Received` are distinct events with a latency between them; the SLA must name exactly one as the clock-start, and that event must be logged.
12. **Distinguish occurrence time from recording time** with separate fields (`event_time`, `record_time`, and for manual entry `capture_source ∈ {device, user}`). The T-406 verdict hinges on this distinction alone.

**Provenance and causality**
13. **Emit causal/correlation identifiers**: alert id propagated from send through receipt to investigation, so ordering is *observed* rather than assumed. Ingestion sequence is a weak proxy and should never silently substitute for a causal link.
14. **Version and log every inference rule** (fold pruning, causal pruning, start reconstruction) with its inputs, so that a conformance verdict can be replayed and challenged.

**Enforcement policy — interval overlap is not sufficient**
15. **Enforce only on CERTAIN_VIOLATION.** A POSSIBLE_VIOLATION means the log cannot distinguish a breach from compliant behaviour; acting on it penalizes teams for instrumentation defects they do not own. On this dataset, that means enforcement against **T-408 only**.
16. **Route POSSIBLE_VIOLATION to a data-quality queue**, not a compliance queue, with the specific missing evidence from §6 attached as the remediation ticket. Track the *count* of possible violations as an observability KPI — a rising count is a telemetry failure, not a process failure.
17. **Treat INDETERMINATE as a control failure with an owner.** Six untestable S3 checks is a governance finding in itself; "we could not measure it" must never read as "it passed."
18. **Fix tolerance and ζ in policy before analysis.** §4 shows T-402's only certain breach evaporates at +2 min and T-408's profile deviations evaporate at ζ=3. Choosing thresholds after seeing results is outcome-shopping. Recommended: SLA tolerance = 0 with certainty-based enforcement (the interval already absorbs measurement slack); ζ = 2 for process monitoring, capped at 2 for CC→CI where ζ=3 is near-vacuous.
19. **Report SLA and temporal-profile verdicts separately and never let one mask the other.** T-408 IS→CC is statistically unremarkable at ζ=3 yet is an unambiguous contractual breach.
