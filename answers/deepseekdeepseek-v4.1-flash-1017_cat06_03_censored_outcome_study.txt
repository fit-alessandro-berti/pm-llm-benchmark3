## 1. Target definition

**Primary formulation: multi-state application-to-observed-default risk under the observed credit policy.**  
For each application at a leakage-safe early prediction time \(\tau\), predict the **cause-specific cumulative incidence of an observed activated account defaulting within 90 days after Account Activated**, by an administrative assessment horizon \(H=365\) days after \(\tau\):

\[
F_D(t \mid X,\tau,\text{policy period})
= P(\text{activate, then default within 90d by time }t \mid X,\tau)
\]

with **Rejected, Withdrawn, Transferred, and still-open-at-cutoff treated as competing exits or administrative censoring, not as “non-default.”** Cases that activate but are immature or have permanently missing feeds are right-censored at the last known valid follow-up, not labeled non-default.

- **Prediction time \(\tau\):** after the first up-to-3 allowed pre-decision events, capped at 7 elapsed days from Application Started and strictly before the first final decision/transfer/withdrawal event. If a decision occurs earlier, \(\tau\) is just before that decision and only prior events are used.
- **Horizon:** event/default within 90 days after activation, assessed by \(H=365\) days after \(\tau\) to allow delayed activation; censor at extraction date 2026-02-15.
- **Unit of analysis:** one application case at its primary early prefix.
- **Population:** all 48,000 applications started in the event window 2024-01-01 through 2025-12-31, with a valid Application Started event, after documented data-quality exclusions only. The current 21,600-row labeled export is treated as a **conditional subset**, not representative of all applications.
- **Estimand:** under the observed referral/credit policy, the probability that an application reaches the observed activated-and-default state by the horizon, with non-activation represented as competing outcomes. This is not the counterfactual default risk of rejected/withdrawn applications had they been approved.

**Credible alternative:** default risk **conditional on eventual activation**, i.e. \(P(\text{default within 90d after activation} \mid \text{activated}, X,\tau)\). This answers “if the application is booked, what is its default risk?” but requires either conditioning on a post-prediction selection event or a separate activation/selection model. A multi-state target for all applications is preferred as primary because the business asks for early warning across every application, and it avoids the false statement that non-activated cases are non-defaults.

## 3. Censoring and missing-label strategy

Distinguish the mechanisms:

- **Ordinary right censoring:** still-open cases at extraction and activated cases whose 90-day window is not complete by extraction. Censor at `min(event time, tau+H, extraction, last valid feed)`.
- **Delayed labels:** external outcome feed arrives 7–35 days after the 90-day horizon. Do not use an immature case as `0`; censor at last known feed or wait for label maturity. For backtesting, model maturity using `label_available_at`.
- **Selection through activation:** rejected, withdrawn, transferred, and open cases never enter the activated default outcome. In the primary analysis they are competing exits/censoring, not non-defaults. Conditional-on-activation models are a secondary/sensitivity question.
- **Transfer as competing event or missing follow-up:** primary treats transfer as a competing exit under the lender’s observed-system policy. Sensitivity analyses will incorporate the 60% linkage where defensible, and report bounds for the 40% unlinked.
- **Permanently missing outcome feeds:** especially partner-originated activated accounts. These are not non-defaults. Primary analysis censors at last known valid follow-up under an explicit non-informative-censoring-within-covariate-strata assumption; this is not fully credible. Sensitivity analyses must include best-case/worst-case bounds, inverse-probability weighting for feed availability, and a missing-not-at-random delta-adjustment.

**Primary analysis strategy:** fit a cause-specific competing-risk model for all applications, with causes `default-after-activation`, `rejected`, `withdrawn`, `transferred`, and right-censoring for `still_open`, `activated_immature`, and observed-feed-end. Estimate cumulative incidence, not 1 minus survival from a naive single-event model.

**Sensitivity analyses:**  
1. Include linked transfer outcomes where linkage is accepted and compare against primary.  
2. Worst-case/best-case bounds for unlinked transfers and permanently missing feeds.  
3. IPW or multiple imputation for activation, transfer linkage, and feed availability using only pre-\(\tau\) and process covariates.  
4. Secondary conditional-on-activation default model, clearly labeled as a booked-account risk, not an all-application risk.

**Assumptions:** maturity and censoring dates are testable; covariate associations with missingness are partially testable; conditional exchangeability of censored/unlinked cases and missing-feed missingness at random are not fully testable; counterfactual outcomes for declined applicants are fundamentally untestable from these data.

## 4. Prefix extraction

For each case, sort events by timestamp and define a **decision gate** as the earliest of Accept, Reject, Withdrawn, Transfer/Transferred, Contract Signed, or Account Activated. No prefix may cross the gate.

**Primary prefix**
- Use allowed pre-decision process activities only, e.g. Application Started, Identity/KYC Check, Credit Review, Request Documents and any authorized pre-decision activities.
- \(\tau=\min(\)timestamp of 3rd allowed pre-decision event, Application Started + 7 days, decision gate minus 1 nanosecond, extraction time\()\).
- If fewer than 3 pre-decision events occur before a decision or 7 days, use all available events before \(\tau\). Short cases are retained; missing expected steps become features.
- Repeated document-request loops count as repeated events and also generate rework features such as `document_request_count` and `credit_review_count`.

**Fixed event-count and elapsed-time prefixes**
- Primary: fixed-event up to 3 pre-decision events, capped by 7 elapsed days.
- Robustness/backtesting: 1-event, 2-event, 5-event prefixes and 1-day, 3-day, 7-day elapsed prefixes, always evaluated with the same as-of decision-gate rule.

**Activity renaming and duplicates**
- Apply a versioned activity-name mapping table before prefix extraction; do not learn the mapping from outcomes.
- During the 15 October 2025 migration window, collapse only exact duplicate events on `(case, normalized_activity, timestamp, resource, source_system)`; preserve legitimate repeated document-loop events with distinct timestamps.

| Updated `risk_score` | Several updates may occur after \(\tau\), including final decision score | Use latest value with timestamp \(\le \tau\); never use final value by case | Repair | Valid only as-of \(\tau\) |
| Resource experience | Stored at extraction time, not event time | Use only historical HR/tenure snapshots as of event or \(\tau\); otherwise do not use experience | Drop/repair | Future information leakage |
| `label_available_at`, `default_90d` | Outcome and maturity labels | Used only for labels, censoring, and validation timing | Drop from features | Target leakage |
| `case:concept:name` | IDs may encode time/cohort; repeated prefixes within case are correlated | Use for grouping/splitting only | Drop from model features | Prevent ID and leakage between prefixes |
| `source_system` | May encode migration/extraction version and batch effects | Use only if value is known at event time; otherwise use calendar-period indicators | Repair/drop | Migration/batch leakage risk |
| `org:resource` | Available at event, but may proxy staffing and future workload policies | Keep with subgroup/fairness monitoring; do not attach extraction-time experience | Keep/repair | Operationally valid but potentially biased |
| `requested_amount`, `channel`, `region` | May be corrected later; static attributes may leak post-hoc data | Freeze as of Application Started or before \(\tau\) | Keep/repair | Valid if as-of |
| `data_extract_time` | Constant/future administrative field | Used only for censoring/as-of calculations | Drop from features | Not predictive and can leak snapshot era |

## 7. Validation design

Use **temporal validation and rolling-origin backtesting by application start time**, not a random split. A random split is misleading because it mixes policy regimes, migration duplicates, maturity levels, and correlated prefixes from the same period. It can also leak post-migration activity conventions into earlier periods.

Recommended primary split:
- **Training:** applications started 2024-01-01 through 2025-06-30.
- **Validation/policy-shift period:** started 2025-07-01 through 2025-10-14, after the credit-policy threshold change.
- **Temporal test/migration period:** started 2025-10-15 through 2025-12-31, after activity renaming and duplicate risk.
- Also run rolling monthly/quarterly origins: train on data before origin, validate on next block, test on later block, respecting label maturity and censoring. For late-2025 cases, use censored survival/competing-risk evaluation; for fixed-horizon calibration, restrict to cases whose required follow-up matured by extraction or use IPCW.

Address the known changes:
- **Policy change 2025-07-01:** report performance by period; include policy-period feature or fit/recalibrate models on post-policy data only once enough mature outcomes are available. Test whether the same prefix has different observed outcome relationships pre/post policy.
- **System migration 2025-10-15:** normalize activity names before modelling, apply the same deduplication rule in all periods, evaluate pre/post migration separately, and inspect duplicate rates.
- **Label maturity and delayed feeds:** never evaluate immature cases as non-default. Use time-dependent metrics and calibration with censoring; for business fixed-horizon reports, only report horizons with adequate maturity or apply explicit censoring weights.
- **Calibration and subgroups:** assess time-dependent calibration for cumulative incidence at 90 days post-activation and at 365 days after \(\tau\), overall and by channel, region, requested-amount band, partner/source system, policy period, migration period, and resource groups. Monitor subgroup performance and fairness.
- **Distribution shift:** compare covariate distributions, prefix variants, resource workloads, and calibration over time; maintain a recalibration/monitoring plan.

Metrics appropriate for the primary competing-risk target:
- Cause-specific cumulative incidence curves and time-dependent AUC/concordance.
- IPCW Brier score and fixed-horizon calibration of the default cause; multiclass Brier/log-loss for the competing states at selected horizons.
- Calibration slope/intercept and decision-curve/net-benefit analysis at operationally chosen thresholds.
- Subgroup calibration and discrimination; do not use raw accuracy as the primary metric.

For the conditional-on-activation alternative, use time-to-default-after-activation survival metrics such as c-index, IPCW Brier score, and calibration within the activated cohort.

## 8. Limitations and decision-use boundary

This study can claim **predictive association under the observed application and credit policy**, with explicit competing exits and censoring. It can estimate the probability that an application in the observed system reaches an observed activated-and-defaulted state by a horizon. It can also report a secondary conditional-on-activation risk with clear selection caveats.

It **cannot claim** the counterfactual default risk of rejected, withdrawn, transferred, or still-open applications had they been approved. It cannot infer causal effects of approval, policy changes, or interventions from these observational labels. It cannot fully recover defaults after unlinked transfers or permanently missing partner feeds; those are selective missing outcomes and likely missing-not-at-random.

Deployment could change the data-generating process in at least three ways:
1. **Intervention/feedback loops:** if staff review, reject, request more documents, or adjust limits based on the score, future activation and default labels change.
2. **Process behavior:** resource allocation, workload, document requests, and queue handling may respond to model use, changing both features and outcome relationships.
3. **Selection and label availability:** score-based declines prevent observation of defaults for declined applications, and referral/transfer practice changes which outcomes are linked or permanently missing.

**Decision-use boundary:** use the model as an early-warning triage or monitoring aid under the observed policy, with calibrated risk and human review. Do not present scores as “would-default-if-approved” probabilities. Do not use the model for automated declines or policy optimization without a validation design that addresses selection, fairness, and causal assumptions.

## 9. PM4Py-oriented Python implementation skeleton

```python
import numpy as np
import pandas as pd
import pm4py

CSV = "applications_events.csv"
EXTRACT = pd.Timestamp("2026-02-15")
PRED_EVENTS = 3
PRED_DAYS = 7
HORIZON = pd.Timedelta(days=365)
DEFAULT_WINDOW = pd.Timedelta(days=90)

df = pd.read_csv(
    CSV,
    parse_dates=["time:timestamp", "label_available_at", "data_extract_time"]
)

# Activity mapping must be versioned from change control, not learned from labels.
activity_map = {
    "Old Credit Review": "Credit Review",
    "KYC": "Identity/KYC Check",
    "Requested Docs": "Request Documents",
}
df["activity_norm"] = df["concept:name"].replace(activity_map)
df = df[df["time:timestamp"] <= EXTRACT].copy()
df = df.sort_values(["case:concept:name", "time:timestamp", "activity_norm"])

# Remove only exact migration duplicates; keep genuine repeated document loops.
df = df.drop_duplicates(
    subset=["case:concept:name", "activity_norm", "time:timestamp",
            "org:resource", "source_system"],
    keep="first"
)

decision_acts = {"Accept", "Reject", "Withdrawn", "Transfer", "Transferred to Partner"}
post_decision_acts = {"Contract Signed", "Account Activated",
                      "Collections Contact", "Default Recorded"}
activation_acts = {"Account Activated"}

# Build per-case leakage-safe prediction cutoff tau and truncated prefix events.
case_tau = {}
pred_rows = []
for cid, g in df.groupby("case:concept:name", sort=False):
    g = g.sort_values("time:timestamp")
    start = g["time:timestamp"].min()
    gate = g.loc[g["activity_norm"].isin(decision_acts), "time:timestamp"]
    gate_time = gate.min() if len(gate) else EXTRACT

    pre = g[(g["time:timestamp"] < gate_time) &
            (~g["activity_norm"].isin(post_decision_acts))]
    elapsed_tau = start + pd.Timedelta(days=PRED_DAYS)
    kth_time = (pre.iloc[PRED_EVENTS - 1]["time:timestamp"]
                if len(pre) >= PRED_EVENTS else EXTRACT)
    tau = min(elapsed_tau, kth_time,
              gate_time - pd.Timedelta(nanoseconds=1), EXTRACT)
    case_tau[cid] = tau
    pred_rows.append(
        g[(g["time:timestamp"] <= tau) &
          (~g["activity_norm"].isin(post_decision_acts))]
    )

pred_df = pd.concat(pred_rows, ignore_index=True)

# PM4Py prefix representation. This is used for control-flow/reference features only.
prefix_log_df = pred_df.rename(columns={
    "case:concept:name": "case_id",
    "activity_norm": "activity",
    "time:timestamp": "timestamp",
})
prefix_log = pm4py.format_dataframe(
    prefix_log_df, case_id="case_id", activity_key="activity",
    timestamp_key="timestamp"
)
prefixes = pm4py.get_prefixes_from_log(prefix_log, PRED_EVENTS)

# Historical reference must use training-period prefixes only.
case_start = df.groupby("case:concept:name")["time:timestamp"].min().rename("case_start")
train_cases = set(case_start[case_start < pd.Timestamp("2025-07-01")].index)
prefix_train_df = prefix_log_df[prefix_log_df["case_id"].isin(train_cases)]
prefix_train_log = pm4py.format_dataframe(
    prefix_train_df, case_id="case_id", activity_key="activity",
    timestamp_key="timestamp"
)
train_dfg, train_start_acts, train_end_acts = pm4py.discover_dfg(prefix_train_log)
train_variants = pm4py.get_variants(prefix_train_log)

def first_time(g, acts):
    x = g.loc[g["activity_norm"].isin(acts), "time:timestamp"]
    return x.min() if len(x) else pd.NaT

def case_status(g):
    g = g.sort_values("time:timestamp")
    act_time = first_time(g, activation_acts)
    reject_time = first_time(g, {"Reject"})
    withdraw_time = first_time(g, {"Withdrawn"})
    transfer_time = first_time(g, {"Transfer", "Transferred to Partner"})
    default_event_time = first_time(g, {"Default Recorded"})

    label_rows = g[g["default_90d"].notna() & g["label_available_at"].notna()]
    label_available_at = (label_rows["label_available_at"].min()
                          if len(label_rows) else pd.NaT)
    default_label = label_rows["default_90d"].iloc[-1] if len(label_rows) else np.nan

    matured = (pd.notna(act_time) and pd.notna(label_available_at)
               and label_available_at <= EXTRACT
               and act_time + DEFAULT_WINDOW <= EXTRACT)

    if pd.notna(act_time) and matured and default_label == 1:
        state = "mature_default"
        ev_time = default_event_time if pd.notna(default_event_time) else act_time + DEFAULT_WINDOW
    elif pd.notna(act_time) and matured and default_label == 0:
        state = "mature_nondefault"
        ev_time = act_time + DEFAULT_WINDOW
    elif pd.notna(act_time):
        state = "activated_immature_or_missing_feed"
        ev_time = EXTRACT
    elif pd.notna(reject_time):
        state = "rejected"
        ev_time = reject_time
    elif pd.notna(withdraw_time):
        state = "withdrawn"
        ev_time = withdraw_time
    elif pd.notna(transfer_time):
        state = "transferred"
        ev_time = transfer_time
    else:
        state = "still_open"
        ev_time = EXTRACT

    return pd.Series({
        "act_time": act_time,
        "label_available_at": label_available_at,
        "default_label": default_label,
        "state": state,
        "event_time_raw": ev_time,
    })

case = df.groupby("case:concept:name").agg(start_time=("time:timestamp", "min"))
case = case.join(df.groupby("case:concept:name").apply(case_status))
case["tau"] = case.index.map(case_tau)

admin = pd.Series(EXTRACT, index=case.index)
horizon_end = case["tau"] + HORIZON
event_or_admin = case["event_time_raw"].fillna(EXTRACT)
case["follow_up_end"] = event_or_admin.combine(horizon_end, min).combine(admin, min)
case["event_time_from_tau_days"] = (
    case["follow_up_end"] - case["tau"]
).dt.total_seconds() / 86400.0

# Survival/competing-risk hook: use state and event_time_from_tau_days.
# Primary model would estimate cause-specific hazards for mature_default vs rejected/withdrawn/transferred,
# with right-censoring for still_open and activated_immature_or_missing_feed.

# Temporal split by case start, not random.
case["split"] = "train"
case.loc[case["start_time"] >= pd.Timestamp("2025-07-01"), "split"] = "validation_policy"
case.loc[case["start_time"] >= pd.Timestamp("2025-10-15"), "split"] = "test_migration"

# Prefix features: pred_df is already truncated at tau.
feat = pred_df.groupby("case:concept:name").agg(
    n_prefix_events=("activity_norm", "size"),
    first_activity=("activity_norm", "first"),
    last_activity=("activity_norm", "last"),
    n_unique_activities=("activity_norm", "nunique"),
    elapsed_days=("time:timestamp", lambda s: (s.max() - s.min()).total_seconds() / 86400.0),
    requested_amount=("case:requested_amount", "first"),
    channel=("case:channel", "first"),
    region=("case:region", "first"),
    risk_score_at_tau=("risk_score", "last"),
)
cr = pred_df.assign(is_cr=pred_df["activity_norm"].eq("Credit Review")) \
    .groupby("case:concept:name")["is_cr"].sum()
docs = pred_df.assign(is_doc=pred_df["activity_norm"].eq("Request Documents")) \
    .groupby("case:concept:name")["is_doc"].sum()
feat["credit_review_count"] = cr
feat["document_request_count"] = docs
feat["rework_credit_review"] = (feat["credit_review_count"] > 1).astype(int)
feat = feat.join(case[["split", "state", "event_time_from_tau_days", "default_label"]])

start_by_case = case["start_time"].reindex(feat.index)
feat["policy_period"] = np.where(
    start_by_case >= pd.Timestamp("2025-07-01"), "post_policy", "pre_policy"
)
feat["migration_period"] = np.where(
    start_by_case >= pd.Timestamp("2025-10-15"), "post_migration", "pre_migration"
)

# Leakage audit.
forbidden = {
    "final_limit", "decision_reason", "collection_status", "default_90d",
    "label_available_at", "event_time_raw"
}
leaked = forbidden.intersection(feat.columns)
assert not leaked, f"Leakage columns in features: {leaked}"
assert (pred_df["time:timestamp"] <= pred_df["case:concept:name"].map(case_tau)).all()
assert not pred_df["activity_norm"].isin(decision_acts | post_decision_acts).any()

print("Cohort states as of extraction:")
print(case["state"].value_counts(dropna=False))
print(f"Prefix rows: {len(pred_df)}; cases with features: {len(feat)}")
print("Leakage audit passed.")
```
