## 3. Causal-abductive explanation

```text

alignment_moves -> measured_fitness

```

The June collapse has several causes at different points in the measurement chain. The UI release plausibly renamed the classification event, so an alignment sees a `Risk Screen` move on log and a missing `Classify` move on model even if the underlying task is unchanged. The gateway then inserts `Queue Routed` into many traces; its DFG edges describe logging adjacency, not necessarily a new employee step. From June 15, ingestion-time ordering can place `Notify` before `Decision` although source execution ran the other way. The staged gains after mapping, filtering, and source ordering fit these mechanisms, but their published percentages require population reconciliation with the displayed variants.

August adds a different cause: the value-dependent sign-off policy changes legitimate work while the control-flow tree stays fixed. An optional sign-off branch improves aggregate fitness but may accept forbidden low-value sign-offs and missed high-value sign-offs; precision and case attributes matter. `Manual Override` also deserves separate treatment as a real user action whose recording changed.

Some enhanced reviews still lack a recorded compliance check after the main repairs. Those cases could be bypasses, missing events, or both, and a memo cannot distinguish them. Stable approval and appeal rates modestly weaken a claim of a large disruptive process change. They neither prove a data defect nor rule out localized noncompliance: aggregates mask case mix, appeals are delayed and selective, and incident detection is incomplete.

## 6. PM4Py reproduction and model-comparison code

```python
import copy
import pm4py
from pm4py.objects.log.obj import EventLog, Trace

# Each string is one ordered trace; the integer is its multiplicity.
VARIANTS = {
    "Apr-May": {
        "Receive,Classify,Standard Review,Decision,Notify": 380,
        "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,
        "Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify": 40,
    },
    "Jun-Jul": {
        "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 270,
        "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 145,
        "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,
        "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
        "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,
        "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,
        "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 20,
    },
    "Aug-Sep": {
        "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 210,
        "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify": 150,
        "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 90,
        "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify": 60,
        "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 45,
        "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 30,
        "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 35,
    },
}

NORMATIVE = """-> (
    'Receive', 'Classify',
    X ( * ( 'Standard Review', 'Request Info' ),
        -> ( 'Enhanced Review', 'Compliance Check' ) ),
    'Decision', 'Notify' )"""

# tau is the silent choice. This candidate is intentionally unconditional:
# it cannot implement the EUR 50,000 predicate.
OPTIONAL_SIGNOFF = """-> (
    'Receive', 'Classify',
    X ( * ( 'Standard Review', 'Request Info' ),
        -> ( 'Enhanced Review', 'Compliance Check' ) ),
    X ( tau, 'Supervisor Sign-off' ),
    'Decision', 'Notify' )"""

normative_tree = pm4py.parse_process_tree(NORMATIVE)
norm_net, norm_im, norm_fm = pm4py.convert_to_petri_net(normative_tree)
candidate_tree = pm4py.parse_process_tree(OPTIONAL_SIGNOFF)
cand_net, cand_im, cand_fm = pm4py.convert_to_petri_net(candidate_tree)


def expand_variants(period, counts):
    log = EventLog()
    for variant, multiplicity in counts.items():
        # One trace per call avoids dependence on a multi-trace separator.
        parsed = pm4py.parse_event_log_string(variant)
        if len(parsed) != 1:
            raise ValueError(f"Expected one parsed trace for {variant!r}")
        for _ in range(multiplicity):
            trace = copy.deepcopy(parsed[0])
            trace.attributes["concept:name"] = f"{period}-{len(log) + 1}"
            log.append(trace)
    return log


def normalize(log, map_label=True, remove_queue=False):
    result = EventLog()
    for old_trace in log:
        trace = Trace(attributes=copy.deepcopy(old_trace.attributes))
        for old_event in old_trace:
            event = copy.deepcopy(old_event)
            if map_label and event["concept:name"] == "Risk Screen":
                event["concept:name"] = "Classify"
            if remove_queue and event["concept:name"] == "Queue Routed":
                continue
            trace.append(event)
        result.append(trace)
    return result


def report(period, view, log, net, im, fm):
    discovered = pm4py.discover_dfg(log)
    dfg = discovered[0] if isinstance(discovered, tuple) else discovered
    top_edges = sorted(dfg.items(), key=lambda item: item[1], reverse=True)[:8]
    diagnostics = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    fitting = sum(
        d.get("cost") == 0 or d.get("fitness") == 1.0
        for d in diagnostics
    )
    fitness = pm4py.fitness_alignments(log, net, im, fm)
    print(f"\n{period} / {view}: {len(log)} cases")
    print("Top frequency DFG edges:", top_edges)
    print("Zero-cost or unit-fitness alignments:", fitting)
    print("Alignment fitness:", fitness)
    print("First alignment diagnostic:", diagnostics[0] if diagnostics else None)
    return fitness


logs = {period: expand_variants(period, counts)
        for period, counts in VARIANTS.items()}
for period, raw in logs.items():
    report(period, "raw / normative", raw, norm_net, norm_im, norm_fm)
    mapped = normalize(raw, map_label=True, remove_queue=False)
    report(period, "label mapped / normative", mapped, norm_net, norm_im, norm_fm)
    cleaned = normalize(raw, map_label=True, remove_queue=True)
    report(period, "mapped + queue removed / normative",
           cleaned, norm_net, norm_im, norm_fm)
    if period == "Aug-Sep":
        report(period, "mapped + queue removed / optional sign-off",
               cleaned, cand_net, cand_im, cand_fm)
        print("August normative precision:",
              pm4py.precision_alignments(cleaned, norm_net, norm_im, norm_fm))
        print("August optional sign-off precision:",
              pm4py.precision_alignments(cleaned, cand_net, cand_im, cand_fm))

print("Caveat: these are expanded variant aggregates, not the original timestamped log.")
print("Source-sequence reordering and claim-value stratification require source data.")
print("An optional sign-off control-flow model cannot enforce the EUR 50,000 rule")
print("and may overgeneralize; compare precision and value-aware violations.")
print("Reconcile published fitting rates with case IDs and alignment settings.")
```

## 7. Provisional conclusion

**Primary explanation for the measured collapse: high confidence (about 90%).** The June deterioration is mainly a measurement and model-interface effect accumulated across three changes: the classification label became `Risk Screen`, the gateway inserted `Queue Routed`, and the ETL began using ingestion time for `Decision` and `Notify`. The alignment ladder—32% raw, 58% after label mapping, 81% after also removing the gateway event, and 89% after source ordering—is strong directional evidence. These stages should be reproduced on identical cases before treating the numerical increments as causal estimates. In fact, the displayed variant counts exhaust each period's stated case total yet cannot yield some of the reported exact fitting percentages. The run's filters, model revision, and alignment definition need reconciliation.

**Real compliance concern: unresolved, moderate confidence that some residual issue merits investigation (about 45%); low confidence that employee bypasses specifically caused the headline drop (about 25–35%).** The August policy makes some sign-offs legitimate and renders the old tree obsolete. The 210 observed sign-offs do not establish correct enforcement without claim values. A model allowing sign-off optionally improves fit but can miss both high-value omissions and low-value excesses. Likewise, the 25 and 30 enhanced-review traces without a recorded compliance check are a genuine audit priority, yet the present record cannot distinguish bypass from missing capture. `Manual Override` is another real action to examine by reason and authorization; it should not be discarded as gateway noise. Stable approvals and appeals do not resolve these questions, particularly with incomplete incident detection.

IT should preserve raw events, publish source/event IDs and timestamp provenance, validate source sequence, document the gateway producer, and reconcile all reported cohorts. Process owners should version the model at the policy effective date and specify the sign-off condition and authorized override paths. Compliance should sample missing-check and sign-off cases against independent source records, stratified by claim value, reviewer, and system, then investigate verified exceptions. **Do not claim** that employees became broadly noncompliant, that all deviations are harmless data errors, or that the optional model proves policy conformance.

## 8. Model-governance recommendation

1. Version normative models with effective dates, owners, and explicit links to policy changes; keep prior versions reproducible.
2. Maintain an event-semantic contract for activity names, source action IDs, payload meaning, and release-level mappings; require evidence before remapping labels.
3. Classify technical events by producer and business meaning, and publish a documented rule for including or excluding each from conformance views.
4. Retain source time, ingestion time, source sequence, event ID, and time-zone provenance; validate ordering and ties before alignment.
5. Encode claim-value thresholds and authorization requirements as data-aware checks alongside the control-flow model, with stratified fitness and precision.
6. After each UI, gateway, ETL, or policy release, validate case-matched variants, frequency DFGs, alignment moves, fitness, precision, and sampled source records before reporting trends.
