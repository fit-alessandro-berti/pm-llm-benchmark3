## 1. Normalization Assumptions

**Offset convention.** For a source clock, `recorded  true = offset  [a, b]`, so `true  [rec_lo  b, rec_hi  a]`. Resolution is applied first, then the offset.

**Rounding.**
- *Floor-to-minute* (OPS-BER, VENDOR-NY, LEGACY-BER): displayed `HH:MM` covers recorded clock `[HH:MM:00, HH:MM:59.999]`.
- *Round-to-nearest* (SENSOR ±5 s, MOBILE-LON ±30 s).
- *HUB*: exact to the displayed second, with ±0.5 s measurement uncertainty, so the resolution interval is `[r0.5, r+0.5]`. Combined with the offset `[1, +1]`, true HUB time is `[r1.5 s, r+1.5 s]`.

**Time-zone conversion.** Local times are converted with `zoneinfo` (standard library). Europe/Berlin is UTC+2 on 2026-06-01 (CEST). Europe/London is UTC+1 (BST). America/New_York is UTC4 (EDT).

**DST fold (LEGACY-BER, 2025-10-26).** Local 02:00–02:59 occurs twice. `fold=0` is the first occurrence (CEST, UTC+2). `fold=1` is the second occurrence (CET, UTC+1). Ingestion order (Alert  Investigation_Start  Containment_Complete) is treated as occurrence order. This is a **material assumption**. It excludes 7 of the 8 fold combinations (see T-405). It leaves each surviving timestamp as an interval, not a point.

**Inferred start (T-404).** The start is inferred as `Investigation_Complete  D`, with `D  [18, 25] min`. The inferred interval is `[10:34:58.5  25 min, 10:35:01.5  18 min]`. Investigation_Complete is not treated as Investigation_Start. The work record is assumed to measure duration from start to completion.

**Causal constraints.** Three constraints are applied, each labelled as an assumption and each tested in Section 4:
- (a) T-405: ingestion order = occurrence order.
- (b) T-407: Alert_Received  Investigation_Start (plausible, not logged).
- (c) T-409: Alert_Received  Investigation_Start (applied to the weak offset interval).

Where a constraint is applied, bounds are tightened with `earlier.hi  min(earlier.hi, later.hi)` and `later.lo  max(later.lo, earlier.lo)`. Unclipped intervals are reported when they matter.

**Mobile entry delay (T-406).** Primary treatment: entry delay shifts only the *record* time. The displayed value is taken as the occurrence estimate, with the rounding and offset bounds above. Alternative treatment: the displayed value is the entry time, so occurrence may be up to 300 s earlier, giving `[displayed-derived lo  300 s, hi]`. Both are reported.

**Alert_Sent (T-407).** Alert_Sent is not Alert_Received. Receipt is bounded as `[Sent_lo + 0, Sent_hi + 20 min]`. Queueing and delivery delay are assumed to be inside the [0, 20] min window.

**Engineering offset (T-409).** The NTP diagnostics are missing, so the bound `[12, +12] min` is used as a bound. It is weak evidence, not a guarantee. Any classification that depends on it is capped at INDETERMINATE.

**SLA and profile.** S1 = Alert_Received  Investigation_Start  900 s. S2 = Investigation_Start  Containment_Complete  2700 s. S3 = Containment_Complete  Close_Incident  129600 s. Tolerance additions (0, 2, 5 min) are applied to the SLA limits. Profile bands use `[  ,  + ]`, inclusive. Midpoints are used only as a secondary comparison in Sections 4 and 5.
