# 2. Shared Assumptions
* Events are logged at completion. Start times are unknown. Order in a trace is completion order.
* Supplier Confirmation optionality is confounded with missing data. S5 5-10% missing and S3/S4 external/stocked attribute absent  SC absence is modelled as a control-flow alternative, not proven optionality.
* Expedite Review is at most once per case and optional.
* Register Order is unique start and Archive Case unique end for all cases, per D1.
* Activities are atomic labels; duplicate labels are not merged across variants.
* Missingness is abstracted as XOR with silent skip in balanced/permissive models; conservative model treats observed absence as the only evidence.

# 3. Conservative Candidate

CC/ER ordering is not generalised to concurrency; SC optionality is enumerated only for the seven observed patterns; Expedite is only allowed in the two observed patterns.

Formal: RO  XOR_{i=1..7} Seq_i  AC  RP  Archive

Seq4 = ER·CC

# 4. Balanced Candidate
Inductive bias: Generalise interleavings where evidence supports overlap, keep SC optional and weakly pre-conditioned, keep Expedite constraints strict. CC and ER are modelled as unordered with completion-order artefact acknowledged. SC requires CC before it per observed data, may start before ER finishes per D5. Expedite requires both checks.

Formal: RO  PO{CC,ER,SC,Exp}  AC  RP  Archive with edges ROCC, ROER, CCSC, CCExp, ERExp, CCAC, ERAC, SCAC, ExpAC, ACRP, RPArchive. SC and Exp are optional in practice via abstraction.

```python
from pm4py.objects.powl.obj import StrictPartialOrder, Transition
ro = Transition('Register Order'); cc = Transition('Credit Check'); er = Transition('Engineering Review')
sc = Transition('Supplier Confirmation'); exp = Transition('Expedite Review')
ac = Transition('Approve Configuration'); rp = Transition('Release Production'); arc = Transition('Archive Case')
nodes = [ro, cc, er, sc, exp, ac, rp, arc]
po = StrictPartialOrder(nodes)
po.order.add_edge(ro, cc); po.order.add_edge(ro, er)
po.order.add_edge(cc, ac); po.order.add_edge(er, ac)
po.order.add_edge(cc, sc); po.order.add_edge(sc, ac)
po.order.add_edge(cc, exp); po.order.add_edge(er, exp); po.order.add_edge(exp, ac)
po.order.add_edge(ac, rp); po.order.add_edge(rp, arc)
model_balanced = po
```

Decision on CC/ER: Both directions in DFG + S2 parallel claim + D7 timestamp limitation  model as unordered partial order, not sequence. Sequence would enforce S1 and overfit.

Decision on SC: Observed CC before SC always, ER before SC in 5/6 SC cases, D5 allows start after either  model CCSC, no ERSC edge, keeping SC after CC but allowing ER overlap.

Decision on Expedite: D6+S6 require both checks before Exp and Exp before AC, order with SC free  edges CCExp, ERExp, ExpAC, no edge ExpSC.

# 5. Permissive Candidate
Inductive bias: Admit any trace consistent with high and medium confidence domain rules, even if unobserved. Separate missingness from true optionality by allowing SC and Exp to be skipped or interleaved arbitrarily subject to precedence constraints.

Formal: RO  AND(CC, ER, XOR(SC,), XOR(Exp,)) with constraints CCExp, ERExp, SCAC, ExpAC, CCAC, ERAC  AC  RP  Archive. In practice AND models CCER and allows SC/Exp to interleave with checks.

```python
tree_perm = "->(Register Order, and(Credit Check, Engineering Review, xor(Supplier Confirmation, tau), xor(Expedite Review, tau)), Approve Configuration, Release Production, Archive Case)"

```

Boundary: Reasonable generalisation = any order respecting CCAC, ERAC, CCExp, ERExp, ExpAC, SCAC if present. Forbidden = RO not first, Archive not last, RP before AC, Exp before both checks, SC after AC. Behaviour requiring CCER order, SC requiring both checks, or SC mandatory is forbidden as it contradicts S2/D5/S4.

import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, Transition
from pm4py.objects.process_tree.obj import Operator

# log reconstruction
variants = [
    ("Register Order, Credit Check, Engineering Review, Supplier Confirmation, Approve Configuration, Release Production, Archive Case",12),
    ("Register Order, Engineering Review, Credit Check, Supplier Confirmation, Approve Configuration, Release Production, Archive Case",7),

    ("Register Order, Engineering Review, Credit Check, Approve Configuration, Release Production, Archive Case",3),

traces = []

ro = Transition('Register Order'); cc = Transition('Credit Check'); er = Transition('Engineering Review')
sc = Transition('Supplier Confirmation'); exp = Transition('Expedite Review')
ac = Transition('Approve Configuration'); rp = Transition('Release Production'); arc = Transition('Archive Case')
nodes = [ro, cc, er, sc, exp, ac, rp, arc]
po = StrictPartialOrder(nodes)
po.order.add_edge(ro, cc); po.order.add_edge(ro, er)
po.order.add_edge(cc, ac); po.order.add_edge(er, ac)
po.order.add_edge(cc, sc); po.order.add_edge(sc, ac)
po.order.add_edge(cc, exp); po.order.add_edge(er, exp); po.order.add_edge(exp, ac)
po.order.add_edge(ac, rp); po.order.add_edge(rp, arc)
model_balanced = po

tree_perm = "->(Register Order, and(Credit Check, Engineering Review, xor(Supplier Confirmation, tau), xor(Expedite Review, tau)), Approve Configuration, Release Production, Archive Case)"
model_permissive = pm4py.parse_process_tree(tree_perm)

def evaluate(model):
    net, im, fm = pm4py.convert_to_petri_net(model)
    sound = pm4py.check_soundness(net, im, fm)
    fit = pm4py.fitness_alignments(log, net, im, fm)
    prec = pm4py.precision_alignments(log, net, im, fm)
    gen = pm4py.generalization_tbr(log, net, im, fm)
    simp = pm4py.simplicity_petri_net(net, im, fm)
    return {"sound":sound, "fitness":fit, "precision":prec, "generalization":gen, "simplicity":simp}

for name,m in [("conservative",model_conservative),("balanced",model_balanced),("permissive",model_permissive)]:
    print(name, evaluate(m))
# positive/negative suite
