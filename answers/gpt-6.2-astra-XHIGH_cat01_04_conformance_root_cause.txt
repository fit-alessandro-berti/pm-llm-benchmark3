```text
alignment_moves -> measured_fitness

```

The alignment compares an extracted sequence with the language of a particular model version. Renaming a completed classification can create both a log move for Risk Screen and a visible model move for Classify. Recording a gateway message adds a log move even if nobody does additional work. Sorting by arrival can make a timely notification look premature. Multiple optimal alignments can place the unmatched move on different activities when two events swap order. The June–July recovery from 32% to 58%, 81% and 89% follows the direction each mechanism predicts. These gains depend on the order of repairs and the reporting cohort.

In August, the policy changed what eligible reviewers had to do while the model stayed fixed. A supervisor who correctly signed a high-value claim could therefore lower measured fitness. An optional model accepts that trace and also accepts the omission of its required signature. For enhanced cases, a model move for Compliance Check identifies the evidence the replay needed. The unobserved event could have been lost between systems, or the decision could have proceeded without the check.

Appeals and approvals measure downstream consequences across the whole portfolio. A bypass affecting a small subgroup may change neither outcome in the observation window. Case mix, appeal maturity and incomplete incident detection further limit sensitivity. Stable rates are compatible with a logging change, localized noncompliance and a correctly implemented new control.

## 6. PM4Py reproduction and model-comparison code

```python
from collections import Counter
from statistics import mean

import pm4py

# Counts are case frequencies. Preserve the printed within-case order.
variants = {
    "Apr-May": [
        (380, "Receive,Classify,Standard Review,Decision,Notify"),
        (180, "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify"),
        (40, "Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify"),
    ],
    "Jun-Jul": [
        (270, "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify"),
        (145, "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify"),
        (70, "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision"),
        (90, "Receive,Risk Screen,Standard Review,Decision,Notify"),
        (30, "Receive,Classify,Queue Routed,Standard Review,Decision,Notify"),
        (25, "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify"),
        (20, "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify"),
    ],
    "Aug-Sep": [
        (210, "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify"),
        (150, "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify"),
        (90, "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify"),
        (60, "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify"),
        (45, "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision"),
        (30, "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify"),
        (35, "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify"),
    ],
}

review = "X(*('Standard Review','Request Info'),->('Enhanced Review','Compliance Check'))"
normative_tree = pm4py.parse_process_tree(
    f"->('Receive','Classify',{review},'Decision','Notify')"
)
candidate_tree = pm4py.parse_process_tree(
    f"->('Receive','Classify',{review},X(tau,'Supervisor Sign-off'),'Decision','Notify')"
)
# Each triple is (net, initial marking, final marking).
normative_net = pm4py.convert_to_petri_net(normative_tree)
candidate_net = pm4py.convert_to_petri_net(candidate_tree)


def build_log(rows, map_label=False, remove_queue=False):
    traces = []
    for count, trace in rows:
        activities = trace.split(",")
        if map_label:
            activities = [
                "Classify" if activity == "Risk Screen" else activity
                for activity in activities
            ]
        if remove_queue:
            activities = [activity for activity in activities if activity != "Queue Routed"]
        traces.extend([",".join(activities)] * count)
    # Parser supplies synthetic case IDs and timestamps. Only string order is evidence.
    log = pm4py.convert_to_event_log(pm4py.parse_event_log_string(traces))
    assert len(log) == len(traces)
    return log


def describe_log(log):
    counts = Counter(tuple(e["concept:name"] for e in trace) for trace in log)
    dfg, starts, ends = pm4py.discover_dfg(log)
    print("cases", len(log), "variant frequencies", counts)
    print("frequency DFG", dict(dfg), "starts", dict(starts), "ends", dict(ends))


def compare(log, accepting_net, measure_precision=False):
    diagnostics = pm4py.conformance_diagnostics_alignments(log, *accepting_net)
    log_only = Counter()
    model_only = Counter()
    for result in diagnostics:
        for observed, required in result["alignment"]:
            if required == ">>" and observed not in (None, ">>"):
                log_only[observed] += 1
            elif observed == ">>" and required not in (None, ">>"):
                model_only[required] += 1  # Exclude invisible routing transitions.
    fitness = pm4py.fitness_alignments(log, *accepting_net)
    print("alignment fitness", fitness)
    print("mean alignment cost (native PM4Py units)", mean(r["cost"] for r in diagnostics))
    print("log-only moves", dict(log_only), "visible model-only moves", dict(model_only))
    if measure_precision:
        print("alignment precision", pm4py.precision_alignments(log, *accepting_net))


stages = [
    ("raw", False, False),
    ("label mapped", True, False),
    ("label mapped and queue removed", True, True),
]
for period, rows in variants.items():
    for stage, map_label, remove_queue in stages:
        log = build_log(rows, map_label=map_label, remove_queue=remove_queue)
        print("\n", period, stage, "normative model")
        describe_log(log)
        compare_models = period == "Aug-Sep" and remove_queue
        compare(log, normative_net, measure_precision=compare_models)
        if compare_models:
            print(period, stage, "optional sign-off model, same cases and order")
            compare(log, candidate_net, measure_precision=True)

print("Source sequence numbers are absent. All runs retain the supplied order, including inversions.")
print("The exact variant replay and native costs can differ from the supplied alignment summaries.")
print("Optional sign-off on either branch cannot enforce the EUR 50,000 condition or signer authority.")
print("It can overgeneralize by accepting missing mandatory signatures. Check eligible cases separately.")
```

On the expanded June–July strings, the proportions of perfectly fitting cases are 0/650 raw, 90/650 after mapping, and 535/650 after mapping and queue removal. On the normalized August–September strings in supplied order, optional sign-off increases perfect fits from 300/620 to 510/620, exactly the 210 traces containing that step. In this replay, alignment precision also increases, from about 0.920 to 0.936. That metric evaluates continuations at observed prefixes. It cannot test whether the right claims received signatures.

## 7. Provisional conclusion

**Confidence is high that measurement changes drove most of the June–July conformance collapse.** The reported 32% raw fit rises to 58% when the renamed activity is mapped, to 81% when the gateway event is excluded, and to 89% when source ordering is used. Each repair predicts a particular change in the trace and its alignment. The endpoint approaches the reported 93% baseline. Exact attribution remains uncertain because the listed strings and raw alignment summaries disagree even on how many cases fit. The staged results warrant action on the measurement pipeline while its owners reconcile the original runs.

August adds a distinct, policy-driven cause. The old tree penalizes a pre-decision sign-off on either branch. Allowing that step raises reported fit from 66% to 86% on the same preprocessing. Confidence is high that the reference model needs revision. The extent of correct policy implementation remains unknown until the 210 recorded signatures are linked to claim value, applicability and signer authority.

**Confidence is low that employee noncompliance explains the aggregate collapse. The residual control risk is material and its incidence is unknown.** The 55 enhanced claims with no recorded check warrant file-level investigation. Override predates the August patch and can represent a legitimate routing correction. Neither a missing check event nor an override alone establishes staff misconduct.

IT should preserve the original extract, recover the run manifests and publish a traceable business-event view with verified labels, gateway filtering and validated source order. Process owners should version the August policy, specify its treatment of in-flight claims and test a mandatory pre-decision signature for eligible cases. Compliance should reconcile the 55 flagged cases and matched controls to independent records, verify override permissions and report confirmed failures separately from unresolved files. Current evidence supports neither a count of proven bypasses nor assurance that all high-value claims were signed. Stable appeals and improved model fitness cannot provide either conclusion.

## 8. Model-governance recommendation

1. Version each normative model with its approving owner, policy reference, effective dates and rule for in-flight cases. Pin the model, classifier, extraction version and replay settings in each conformance run.
2. Contract with each event producer on a stable activity identifier, business meaning, lifecycle trigger, case key and resource semantics. Require evidence of equivalence before aliasing a new display label to an existing activity.
3. Classify technical events by producer and purpose. Retain immutable raw records and publish a versioned business-event projection with explicit exclusions. Keep user actions such as overrides traceable to their actors and reasons.
4. Store occurrence, commit and ingestion time separately with timezone, source sequence and its scope. Validate ties, duplicates, gaps and cross-system ordering and flag ambiguous cases before replay.
5. Bind policy-effective value and role data to control checks. For claims above EUR 50,000 require an authorized sign-off before decision, and separately verify the enhanced-review compliance check. Route unknown attributes and unverified signatures for adjudication.
6. Validate each release on matched pre/post cases and held-out traces. Review variant and DFG changes, visible alignment moves, fitness, precision and cohort-specific control failures. Reconcile unexplained shifts to source records before publishing a compliance trend.
