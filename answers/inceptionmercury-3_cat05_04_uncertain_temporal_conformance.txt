## 1. Normalization Assumptions

- **Clock-offset direction**: I use the provided rule `clock_offset = recorded_clock - true_clock`. Therefore, for an offset interval `[a, b]`, true time is `recorded_time - offset`, so the true-time interval is `[recorded_min - b, recorded_max - a]` after resolution uncertainty is applied.
- **Timestamp resolution before clock correction**: For floor semantics, a displayed minute `HH:MM` is first expanded to `[HH:MM:00, HH:MM:59.999]` in the source local time zone. For round-to-nearest semantics, the displayed time is expanded to ± half of the rounding unit before clock offset is applied.
- **HUB**: A displayed UTC second plus measurement uncertainty ±0.5 s and clock offset ±1 s is treated as `±1.5 s` around the displayed timestamp.
- **OPS-BER**: Local times are Europe/Berlin. In June, CEST = UTC+2. The minute-floor interval is converted to UTC before applying the clock offset `[-90 s, +120 s]`. For T-409 the missing NTP diagnostics are represented by the weaker `[-720 s, +720 s]` engineering estimate.
- **SENSOR**: UTC rounding to the nearest 10 s gives ±5 s; clock offset ±5 s is added, giving a combined ±10 s interval.
- **VENDOR-NY**: Local times are America/New_York. In June, EDT = UTC-4. The minute-floor interval is converted to UTC before applying `[-180 s, +180 s]`.
- **LEGACY-BER**: For the 2025-10-26 ambiguous morning, each local time has two fold alternatives: CEST (UTC+2) and CET (UTC+1). I first preserve both alternatives, then use the stated ingestion order for T-405 to eliminate the impossible fold combinations. The surviving assignment is Alert_Received in CEST, Investigation_Start in CET, Containment_Complete in CET.
- **T-404 inferred start**: Investigation_Start is inferred from Investigation_Complete minus the signed investigation duration of 18–25 minutes. All uncertainty in both the completion timestamp and the duration is retained.
- **T-407 inferred receipt**: Alert_Received is not assumed to be identical to Alert_Sent. I infer `Alert_Received = Alert_Sent + [0, 20] minutes`, but label this as weak evidence because no receipt acknowledgment exists.
- **T-406 mobile entry delay**: The user-entry delay is treated as an occurrence-time uncertainty, not merely a record-time artifact. If the user entered the displayed time up to 5 minutes late, the true occurrence time is up to 5 minutes earlier than the clock-corrected record time. Thus I add `[0, 300] s` to the lower uncertainty side of the investigation-start interval.
- **Process order**: For temporal-profile pairs, I assume the activities are ordered as named by the profile. Where timestamp intervals overlap, feasible positive durations can approach 0. If order were not enforced, some duration intervals would include negative values, but the classifications below are not materially changed for the cases involved.
- **Baseline**: Section 3 uses `zeta = 1` for the temporal profile. Section 4 shows `zeta = 1, 2, 3` and SLA tolerances of 0, 2, and 5 minutes.

    start_utc = start_local.astimezone(timezone.utc)
    end_utc = end_local.astimezone(timezone.utc)
    a, b = offset_bounds
    # true time = recorded_utc - offset; offset in [a,b]
    return [(start_utc - timedelta(seconds=b), end_utc - timedelta(seconds=a))]

def sensor_interval(recorded):
    t = pd.Timestamp(recorded, tz="UTC")
    delta = pd.Timedelta(seconds=10)
    return [(t - delta, t + delta)]

def legacy_berlin_interval(recorded, fold):
    dt = datetime.strptime(recorded, "%Y-%m-%d %H:%M")
    tz = ZoneInfo("Europe/Berlin")
    start_local = dt.replace(tzinfo=tz, fold=fold)
    end_local = start_local + timedelta(seconds=59.999)
    start_utc = start_local.astimezone(timezone.utc)
    end_utc = end_local.astimezone(timezone.utc)
    return [(start_utc - timedelta(seconds=60), end_utc + timedelta(seconds=60))]

def mobile_london_interval(recorded):
    dt = datetime.strptime(recorded, "%Y-%m-%d %H:%M")
    tz = ZoneInfo("Europe/London")
    start_local = dt.replace(tzinfo=tz) - timedelta(seconds=30)
    end_local = dt.replace(tzinfo=tz) + timedelta(seconds=30)
    start_utc = start_local.astimezone(timezone.utc)
    end_utc = end_local.astimezone(timezone.utc)
    # Source clock offset [-300,+300]
    rec_lo = start_utc - timedelta(seconds=300)
    rec_hi = end_utc + timedelta(seconds=300)
    # Entry delay [0,300] shifts true occurrence earlier
    occ_lo = rec_lo - timedelta(seconds=300)
    occ_hi = rec_hi
    return [(occ_lo, occ_hi)]

def duration_intervals(from_intvs, to_intvs):
    results = []
    for fs, fe in from_intvs:
        for ts, te in to_intvs:
            if ts > fe:
                results.append((ts - fe, te - fs))
            elif te > fs:
                # ordered activities; durations are positive
                results.append((pd.Timedelta(0), te - fs))
    if not results:
        return []
    results.sort()
    merged = [[results[0][0], results[0][1]]]
    for lo, hi in results[1:]:
        if lo <= merged[-1][1] + pd.Timedelta(milliseconds=1):
            if hi > merged[-1][1]:
                merged[-1][1] = hi
        else:
            merged.append([lo, hi])
    return [(lo, hi) for lo, hi in merged]

def classify_interval_list(intvs, lo, hi):
    if not intvs:
        return "INDETERMINATE"
    if all(lo <= s and e <= hi for s, e in intvs):
        return "CERTAIN_PASS"
    if all(e < lo or s > hi for s, e in intvs):
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

## 7. Governance Recommendation

- **UTC storage**: Store all operational timestamps in UTC internally, but preserve the original raw local timestamp as a separate field.
- **Raw timestamp retention**: Retain the exact source string, source system, time zone, and rounding/display semantics for every event.
- **Source offset telemetry**: Record NTP/clock-offset diagnostics alongside each event or at least per hour, including the measurement bound and confidence.
- **Resolution metadata**: Store whether a timestamp is exact, floored, rounded, or user-entered, and include the granularity in the event schema.
- **Lifecycle semantics**: Distinguish `Alert_Sent` from `Alert_Received`, and `Investigation_Start` from `Investigation_Complete`; never treat semantically different events as interchangeable.
- **DST fold handling**: At DST transitions, log the fold or an unambiguous UTC conversion at capture time; do not rely on later inference from ingestion order.
- **Causal identifiers**: Link related events with case IDs, causal parent IDs, and ingestion order so ordering assumptions are explicit and auditable.
- **Enforcement policy**: Interval overlap should not be treated as proof of SLA compliance. Only `CERTAIN_PASS` should be considered compliant for enforcement. `POSSIBLE_VIOLATION` should trigger review and escalation, not automatic penalty; `CERTAIN_VIOLATION` should trigger immediate remediation.
- **Periodic audit**: Review clock-offset telemetry, timestamp-resolution metadata, and DST-fold handling to reduce the number of cases that remain only possible violations.
