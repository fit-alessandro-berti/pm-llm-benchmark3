## 6. Candidate Site B intervention
Eligibility: digital-channel cases without legal-review flag and without originals requirement.  
Tasks creatable concurrently after Register: Identity Check and Document Check.  
Statutory prerequisites retained: Originals Receipt before Document Check when required; Assessment waits for both verifications and any Legal Review.  
Queue/WIP controls: maximum six open verification tasks per reviewer; separate WIP limit of four for assessors.  
Resource responsibilities: identity pool owns Identity Check; document pool owns Document Check and Originals Receipt; assessors own Assessment; legal pool owns Legal Review and supplement handling.  
Logging: real-time event timestamps; explicit “task started” and “task completed” events; flag for concurrent ownership.  

POWL partial order:  
Register  Identity Check, Register  Originals Receipt (when required);  
Identity Check  Assessment;  
Originals Receipt  Document Check (when required);  
Document Check  Assessment;  
Assessment  Legal Review (when required);  
Legal Review  Request Supplement (optional loop back to Document Check)  Approve/Reject;  
Approve/Reject  Notify.

## 7. Pilot for transport learning

| design element | specification | causal purpose | operational safeguard | process-mining measurement |
|---|---|---|---|---|
| unit of assignment | case | isolates treatment effect | none | case-level trace |
| randomization or phased assignment | stratified randomization by digital/original channel | balances case mix | block randomization within strata | stratum-specific DFG |
| eligible strata | digital, no-legal-review | tests concurrency mechanism | exclude 62 % originals and 40 % legal | eligibility filter log |
| treatment versions | (1) parallel tasks, (2) control sequential | compare overlap and cycle | IT dual-ownership flag enabled only in treatment | overlap interval metric |
| primary outcome | median cycle time | detect waiting reduction | none | cycle-time distribution |
| secondary outcomes | p90 cycle time, rework rate, overlap % | detect tail or quality shift | daily dashboard | p90, rework DFG |
| interference controls | separate team queues | prevent spillover | capacity monitoring | queue-length time series |
| power/minimum-support | 600 cases per arm | detect 5 h median difference | minimum 4 weeks accrual | sample-size calculation |
| duration | 8 weeks | observe steady state | weekly review | cumulative trace count |
| stop rules | p90 increase >15 % or rework >20 % | protect quality | automatic pause | real-time alert |
| transportability analysis | compare digital vs originals strata | quantify effect modification | pre-specified subgroup analysis | stratum DFG differences |

The pilot separates mechanism failure from implementation failure by randomizing only within the digitally eligible stratum where concurrency is legally feasible, while simultaneously tracking the ineligible originals stratum as a within-site control. Real-time logging of task-start events distinguishes true concurrency from timestamp artifacts; capacity and queue-length metrics flag whether any observed change is due to resource reallocation rather than ordering. Supplement-loop frequency is monitored separately so that any increase in rework can be attributed to the Legal Review path rather than the parallel verification itself.

## 8. PM4Py model-construction code
```python
import pm4py
from pm4py.objects.powl.obj import POWL, StrictPartialOrder, Transition, SilentTransition, OperatorPOWL
from pm4py.objects.petri_net.utils import check_soundness

# Site A before
tree_a_before = pm4py.parse_process_tree("->('Register','Identity Check','Document Check','Assessment',X('Approve','Reject'),'Notify')")
net_a_before, im, fm = pm4py.convert_to_petri_net(tree_a_before)

# Site A after
tree_a_after = pm4py.parse_process_tree("->('Register',+('Identity Check','Document Check'),'Assessment',X('Approve','Reject'),'Notify')")
net_a_after, im2, fm2 = pm4py.convert_to_petri_net(tree_a_after)

# Site B candidate POWL
register = Transition("Register")
identity = Transition("Identity Check")
originals = Transition("Originals Receipt")
document = Transition("Document Check")
assessment = Transition("Assessment")
legal = Transition("Legal Review")
supplement = Transition("Request Supplement")
approve = Transition("Approve")
reject = Transition("Reject")
notify = Transition("Notify")

skip = SilentTransition()

po = StrictPartialOrder(nodes=[register, identity, originals, document, assessment, legal, supplement, approve, reject, notify])

po.add_edge(register, identity)
po.add_edge(register, originals)
po.add_edge(originals, document)
po.add_edge(identity, assessment)
po.add_edge(document, assessment)
po.add_edge(assessment, legal)
po.add_edge(legal, supplement)
po.add_edge(supplement, document)  # loop
po.add_edge(legal, approve)
po.add_edge(legal, reject)
po.add_edge(approve, notify)
po.add_edge(reject, notify)

net_b, im_b, fm_b = pm4py.convert_to_petri_net(po)

print(pm4py.check_is_workflow_net(net_b))
print(check_soundness.check_soundness(net_b, im_b, fm_b))

# Note: model cannot encode data-dependent legal flags, resource capacities, case locks, or durations
```

## 9. Recommendation
conditional go

The intervention should be transferred only to the digitally submitted, non-legal-review stratum (approximately 38 % of volume) where the originals gate is absent and concurrency is legally permissible. The statutory Originals Receipt  Document Check ordering, the mandatory Legal Review branch, and the single-task lock must not be copied. The pilot should begin with the digital, no-legal-review cases under randomized assignment, with a hard WIP limit of six and real-time event logging. Expected benefit is a 4–7 hour reduction in median cycle time for that stratum; risk is a possible lengthening of the p90 tail if assessment capacity becomes the new bottleneck. Expansion is triggered only if the pilot shows median reduction 4 h, p90 change +5 h, and rework rate increase 2 percentage points after 600 cases per arm. Modification is required if the IT lock prevents measurable overlap; abandonment is required if supplement-loop frequency rises above 20 % or if queue saturation increases document service time by more than 15 %. The design therefore tests the causal mechanism while protecting the site-specific constraints that Site A never faced.

## 10. Assumption register

2. IT case lock can be relaxed for pilot cases — needed for true overlap — test via IT change request success — consequence: measured overlap is artifactual only.
3. Assessment capacity remains stable during pilot — needed to isolate verification effect — test via daily utilization dashboard — consequence: bottleneck merely shifts downstream.
4. Supplement frequency is independent of verification order — needed to protect quality — test via stratum-specific DFG — consequence: parallelization increases loops.
5. Reviewers will respect WIP limit of six — needed to prevent overload — test via queue-length monitoring — consequence: document pool saturates.
6. Timestamp events will be entered in real time — needed for valid overlap metric — test via audit of start/complete pairs — consequence: pilot metrics are biased.
7. Marketing mix at Site B remains constant — needed for stable case mix — test via weekly complexity distribution — consequence: stratum composition drifts.
8. No external API change occurs during pilot — needed to attribute latency reduction — test via identity query log — consequence: confounding with Site A co-intervention.
