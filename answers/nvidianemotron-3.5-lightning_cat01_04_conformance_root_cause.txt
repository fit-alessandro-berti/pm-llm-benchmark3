# Function to expand a dict of {trace_str: count} into an EventLog
def expand_variants(variant_dict, log_name):
    log = EventLog()
    for trace_str, count in variant_dict.items():
        # Parse the comma-separated string into a list
        activities = trace_str.split(",")
        # Build a trace
        trace = Trace()
        for act in activities:
            ev = Event()
            ev["concept:name"] = act
            trace.append(ev)
        # Assign a case identifier (we'll use a simple integer per trace for uniqueness)
        # pm4py traces need a case_id; we'll set lifecycle events optionally.
        # For conformance, concept:name suffices.
        trace.attributes["case:concept:name"] = trace_str
        # Repeat trace 'count' times
        for _ in range(count):
            log.append(trace.copy())  # copy to avoid reference issues
    # Set log metadata
    log.attributes["concept:name"] = log_name
    return log

# 5. Transparent normalization pipeline:
#    a) map Risk Screen -> Classify
#    b) optionally remove Queue Routed
# -------------------------------------------------

def normalize_log(log, map_risk_to_classify=True, remove_queue_routed=True):
    """Return a new log with label remapping and/or technical-event removal."""
    new_log = EventLog()
    for trace in log:
        new_trace = Trace()
        for ev in trace:
            act_name = ev["concept:name"]
            if map_risk_to_classify and act_name == "Risk Screen":
                act_name = "Classify"
            if remove_queue_routed and act_name == "Queue Routed":
                # skip this event; we could also mark it but removing means it's absent
                continue
            # copy event with new name
            new_ev = Event()
            new_ev["concept:name"] = act_name
            # copy other attributes if needed
            for k, v in ev.items():
                if k != "concept:name":
                    new_ev[k] = v
            new_trace.append(new_ev)
        # Preserve case identifier
        case_id = trace.attributes.get("case:concept:name", "unknown")
        new_trace.attributes["case:concept:name"] = case_id
        new_log.append(new_trace)
    new_log.attributes["concept:name"] = log.attributes.get("concept:name", "normalized")
    return new_log

# Normalize each period's log

# Compute fitness for Aug-Sep normalized log with candidate model

## 7. Provisional Conclusion

The measured conformance collapse from April-May to June-July is primarily attributable to a compounded labeling and provenance defect: the UI replaced `Classify` with `Risk Screen` on May 31, the ETL began emitting a technical `Queue Routed` event on June 3, and the June 15 switch to warehouse ingestion time for `Decision`/`Notify` distorted event ordering. When traces are remapped (`Risk Screen`  `Classify`), `Queue Routed` removed, and logs reordered by source-system sequence number, alignment fitness rebounds to 81–89% and dominant misalignment moves (reversed `Notify`, `Manual Override`) largely vanish. The August policy requiring `Supervisor Sign-off` for claims above EUR 50,000 introduced a genuine model staleness issue— the normative process tree was not updated, causing `Supervisor Sign-off` to appear as a deviation in alignments—but this effect is confined to August-September and is separate from the initial June-July drop. Business outcomes (30-day appeal 3.6–3.8%, approval 71–72%) remain stable across periods, arguing against a real behavioral deterioration in claim processing.

Separately, a real compliance problem may persist because the policy change did introduce a new supervisory step that the current model does not codify, and 25–30 enhanced-review traces per period lack a recorded compliance check. However, the absence of increased appeal or confirmed incident rates, the supervisor memo’s lack of corroborating audit data, and the fitness recovery with data normalization suggest that any noncompliance is either sporadic or masked by extraction gaps. Confidence in the data-defect explanation as the primary cause of the conformance collapse is high (85%); confidence that an unresolved compliance risk remains is moderate (~60%). Immediate actions: IT should enforce `Classify` labeling in the UI and filter `Queue Routed` as a technical event in the ETL; the data-engineering team should default to source-system sequence numbers for temporal ordering; process owners must update the normative model to include the `Supervisor Sign-off` step with its EUR 50,000 condition; compliance should conduct a stratified manual audit of enhanced-review cases (high-value vs. low-value) to determine whether missing compliance checks reflect bypasses or logging omissions. No claim should yet be made that employee noncompliance drove the conformance drop, nor that the process is fully compliant after the suggested fixes—only that the dominant signal is attributable to logging and provenance artifacts.

## 8. Model-Governance Recommendation

1. **Model versioning**: Every change to the normative process tree, policy rules, or event-semantic definitions must be recorded in a version-controlled repository (e.g., Git) with a unique identifier, date, and impact assessment. Conformance checks should reference a specific model version; rolling back to a prior version must be a single-command operation.

2. **Event-semantic contract**: All activities emitted by the case-management system must map to a controlled vocabulary documented in a data-dictionary. New UI screens or technical events (e.g., `Risk Screen`, `Queue Routed`) require a formal semantic review before deployment, confirming whether the activity represents a control-flow step, a technical artifact, or a data attribute, and how it should be classified in conformance logs.

3. **Technical-event policy**: The ETL pipeline must maintain a whitelist of "control-flow" activities versus "technical/metadata" events. Technical events (e.g., routing identifiers, system-generated timestamps) should be either stripped before conformance checking or stored in a separate attribute log, never as parallel trace elements that compete with model activities.

4. **Timestamp provenance**: Event logs must record both the source-system sequence number and the original occurrence timestamp. Warehouse ingestion time may be captured as an auxiliary attribute but must not overwrite the primary control-flow timestamp used for alignment and DFG discovery. A pre-processing schema validation step should reject logs where the primary timestamp is derived solely from ingestion time.

5. **Data-aware constraints**: The normative model must explicitly encode data conditions that affect control flow (e.g., `Supervisor Sign-off` for claims >EUR 50,000). Process-tree extensions should be conditional on case attributes; a control-flow-only model must be flagged as an approximation, and fitness results must be stratified by the relevant attributes before being interpreted as process compliance.

6. **Post-release validation**: Any UI, ETL, or policy change that modifies trace strings or event ordering must trigger a conformance regression test suite before production rollout. The suite should compare fitness, DFG edges, and alignment move distributions against a baseline log captured in a frozen environment; any decline beyond a pre-agreed threshold (e.g., fitness drop >10 points) must halt the release and trigger a root-cause analysis following the diagnostic program outlined in this report.
