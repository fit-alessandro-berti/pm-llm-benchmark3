* **B – Permissive with SLA.** Allow `Activate Vendor` before `Obtain Legal Opinion` after escalation, but enforce an opinion within 24 h and require manual review. Compliance risk: the log cannot prove joint authorisation, so any activation-before-opinion is conservatively flagged as policy-dependent; false positives remain.

Chosen for the implemented model: **Resolution A – strict legal precedence**. R6 is treated as a manual exception process. Automated checks are conservative and will flag T6 as a violation; an exception workflow can override with external evidence.

# 3. Procedural Backbone

Compact description: `SEQ(Receive Onboarding Request, PAR(Capture Master Data, Run Sanctions Screening, Verify Bank Account), Classify Risk, XOR( RejectClose, Manager ApprovalActivateReleaseClose, Enhanced Due DiligenceCompliance ApprovalActivateReleaseClose))`

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

def leaf(label):
    return ProcessTree(operator=None, label=label)

def node(operator, children, label=None):
    return ProcessTree(operator=operator, children=children, label=label)

procedural_model = node(Operator.SEQUENCE, [
    leaf('Receive Onboarding Request'),
    node(Operator.PARALLEL, [
        leaf('Capture Master Data'),
        leaf('Run Sanctions Screening'),
        leaf('Verify Bank Account')
    ]),
    leaf('Classify Risk'),
    node(Operator.XOR, [
        node(Operator.SEQUENCE, [
            leaf('Reject Vendor'),
            leaf('Close Onboarding')
        ]),
        node(Operator.SEQUENCE, [
            leaf('Manager Approval'),
            leaf('Activate Vendor'),
            leaf('Release First Payment'),
            leaf('Close Onboarding')
        ]),
        node(Operator.SEQUENCE, [
            leaf('Enhanced Due Diligence'),
            leaf('Compliance Approval'),
            leaf('Activate Vendor'),
            leaf('Release First Payment'),
            leaf('Close Onboarding')
        ])
    ])
])
```

Concurrency is the PAR of the three checks. Choice after classification is XOR with three terminal branches. Clarification loops and post-activation `Change Bank Details / Suspend Vendor` are deliberately excluded from the block-structured backbone and handled declaratively / in the resource layer to avoid non-block-structured approximations.


Rule semantics

* `noncoexistence(A,B)`: A and B never appear together in a case.
* `response(A,B)`: if A occurs, B occurs later at least once.
* `altresponse(A,B)`: if A occurs, B occurs later and no other A occurs in between.
* `precedence(A,B)`: if B occurs, A occurs earlier.

# 7. Resource- and Data-Aware Checks

```python
def check_segregation(df):
    # df columns: case_id, activity, resource, timestamp
    fails = []
    for cid, g in df.groupby('case_id'):
        res = {a:r for a,r in zip(g.activity,g.resource)}
        verify = res.get('Verify Bank Account')
        approval = res.get('Manager Approval') or res.get('Compliance Approval')
        if verify and approval and verify == approval:
            fails.append((cid,'Verify vs approval'))
        capture = res.get('Capture Master Data')
        activate = res.get('Activate Vendor')
        if capture and activate and capture == activate:
            fails.append((cid,'Capture vs Activate'))
    return fails

def check_emergency_policy(df):
    # strict legal resolution: Obtain Legal Opinion must precede Activate Vendor if Sanctions Escalation present
    flags = []
    for cid,g in df.groupby('case_id'):
        acts = list(g.sort_values('timestamp').activity)
        if 'Sanctions Escalation' in acts and 'Activate Vendor' in acts and 'Obtain Legal Opinion' in acts:
            pos = {a:i for i,a in enumerate(acts)}
            if pos['Activate Vendor'] < pos['Obtain Legal Opinion']:
                flags.append((cid,'activate before opinion - policy dependent'))
    return flags
```

Missing attribute handling: if `resource` is null, the segregation check is skipped with a warning; if emergency authorisation attribute is missing, any activation-before-opinion is flagged as policy-dependent and requires manual evidence.

# 9. Contradictions, Redundancies, and Blind Spots

* Duplicated enforcement: noncoexistence and never_together repeat the same constraint across DECLARE and Log Skeleton; precedence is duplicated in Log Skeleton `always_before`.
* Conditional constraints become inconsistent under loops: R3 alternate response is vacuous when no clarification occurs; R11 post-activation change creates a loop that the procedural backbone excludes, leading to potential vacuity.
* DECLARE cannot express disjunctive approvals for R2; procedural XOR is authoritative.
* Missing case attributes: emergency authorisation and data conditions for R6 and R9 cannot be recovered from activity sequences alone.
* Timestamp-only limitation: temporal profile flags late opinions but cannot distinguish business-valid delays.
* Support/confidence metadata treated as normative: setting support=1.0 and confidence=1.0 makes the model normative, not mined; drift will be reported as violation.

# 10. Deployment Recommendation

Canonical procedural representation is the ProcessTree above for onboarding control-flow. Authoritative policy layer is the combination of DECLARE for activity ordering/response and the resource/data layer for segregation and emergency exceptions. Temporal profile is advisory.

Conformance order:
1. Procedural replay to filter structurally impossible traces.
2. Log Skeleton for cardinality and always-before/never-together.
3. DECLARE for response/precedence/noncoexistence.
4. Temporal profile  warnings only.
5. Resource/data checks  hard failures for segregation, policy-dependent flags for emergency.

Contradictory findings are surfaced as layered reports: procedural/DECLARE/Log Skeleton failures are hard, temporal deviations are warnings, resource violations are hard, and R5/R6 conflicts are policy-dependent with a manual override workflow requiring external authorisation evidence.
