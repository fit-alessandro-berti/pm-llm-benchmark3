The sudden conformance collapse from 93% (Apr–May) to 32% (Jun–Jul) and 66% preprocessed (Aug–Sep) is an **overdetermined composite phenomenon** in which four data-and-model artifacts mask two smaller but operationally vital behavioral shifts. First, `UI_release` 4.2 renamed `Classify` to `Risk Screen`, forcing standard alignments to pay both a log-move (`Risk Screen`) and a model-move (`Classify`) on nearly every trace. Days later, `gateway_routing_logic` injected `Queue Routed` (inflating log moves and null-resource rates), while `ETL_change` replaced business timestamps on `Decision` and `Notify` with warehouse-ingestion timestamps, inverting 115 traces. In August, `policy_change` mandated `Supervisor Sign-off` for claims above `claim_value_hidden` (EUR 50,000), altering `true_process` while leaving `normative_model` frozen (`model_policy_drift`). Together, these non-malicious mechanisms explain roughly 80–85% of observed alignment cost.

However, residual nonconformance persists after repairing labels, technical events, ordering, and sign-offs (11–14% non-fitting traces): 55 cases transition directly from `Enhanced Review` to `Decision` without `Compliance Check`, and 55 invoke `Manual Override` (potentially caused by `routing_errors` from the June gateway deployment or intentional shortcutting under `workload_or_incentives_hidden`). Crucially, **stable `business_outcomes` (approval ~71.8%, appeals ~3.7%) neither prove pure data error nor exonerate noncompliance**. First, renamed labels, technical events, and ETL timestamp inversions do not touch customer outcomes at all. Second, `Compliance Check` is a preventative regulatory control (e.g., AML/sanctions/fraud screening), not a customer-satisfaction driver: skipping it on ~4.3% of claims will not trigger customer appeals when claims are approved, and Compliance explicitly noted an `incident_detection_gap_hidden`. Macro outcome stability is simply insensitive to low-prevalence control bypasses.

## 6. PM4Py reproduction and model-comparison code

```python
import copy
import pm4py


def build_period_log_string(variant_counts):
    """Expand aggregate (trace_string, count) pairs into a newline-delimited string for PM4Py."""
    expanded_traces = []
    for trace_str, count in variant_counts:
        expanded_traces.extend([trace_str] * count)
    return "\n".join(expanded_traces)


def normalize_event_log(log, map_risk_screen=True, remove_queue_routed=False, fix_notify_order=False):
    """
    Transparent normalization pipeline operating on a PM4Py EventLog copy:
      1. Optionally maps 'Risk Screen' -> 'Classify' (UI 4.2 label equivalence).
      2. Optionally removes technical event 'Queue Routed' (gateway instrumentation).
      3. Optionally repairs 'Notify','Decision' -> 'Decision','Notify' as a variant-level
         proxy for sorting by source-system sequence number.
    """
    log_out = copy.deepcopy(log)
    for trace in log_out:
        filtered_events = []
        for event in trace:
            act = event["concept:name"]
            if remove_queue_routed and act == "Queue Routed":
                continue
            if map_risk_screen and act == "Risk Screen":
                event["concept:name"] = "Classify"
            filtered_events.append(event)

        if fix_notify_order and len(filtered_events) >= 2:
            if (
                filtered_events[-2]["concept:name"] == "Notify"
                and filtered_events[-1]["concept:name"] == "Decision"
            ):
                filtered_events[-2], filtered_events[-1] = (
                    filtered_events[-1],
                    filtered_events[-2],
                )

        trace._list = filtered_events
    return log_out


def summarize_alignments(log, net, im, fm):
    """Compute alignment fitness, precision, and dominant non-synchronous moves."""
    fitness_res = pm4py.fitness_alignments(log, net, im, fm)
    precision_val = pm4py.precision_alignments(log, net, im, fm)
    alignments = pm4py.conformance_diagnostics_alignments(log, net, im, fm)

    log_moves = {}
    model_moves = {}
    fitting_count = 0

    for al in alignments:
        if al["cost"] == 0:
            fitting_count += 1
        for log_label, model_label in al["alignment"]:
            # Synchronous move: log_label == model_label
            if log_label == model_label:
                continue
            # Move on log: model_label is '>>'
            if model_label == ">>" and log_label is not None:
                log_moves[log_label] = log_moves.get(log_label, 0) + 1
            # Visible move on model: log_label is '>>' and model_label is not silent (None)
            elif log_label == ">>" and model_label is not None:
                model_moves[model_label] = model_moves.get(model_label, 0) + 1

    pct_fitting = 100.0 * fitting_count / len(alignments) if alignments else 0.0
    return {
        "pct_fitting": pct_fitting,
        "log_fitness": fitness_res["log_fitness"],
        "avg_trace_fitness": fitness_res["average_trace_fitness"],
        "precision": precision_val,
        "top_log_moves": sorted(log_moves.items(), key=lambda x: -x[1])[:4],
        "top_model_moves": sorted(model_moves.items(), key=lambda x: -x[1])[:4],
    }


def main():
    # 1. Parse the normative process tree and convert to an accepting Petri net
    normative_tree_str = (
        "-> ( 'Receive', 'Classify', "
        "X ( * ( 'Standard Review', 'Request Info' ), -> ( 'Enhanced Review', 'Compliance Check' ) ), "
        "'Decision', 'Notify' )"
    )
    normative_tree = pm4py.parse_process_tree(normative_tree_str)
    norm_net, norm_im, norm_fm = pm4py.convert_to_petri_net(normative_tree)

    # 2. Expand supplied variant-frequency tables into PM4Py EventLogs
    apr_may_variants = [
        ("Receive,Classify,Standard Review,Decision,Notify", 380),
        ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
        ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40),
    ]
    jun_jul_variants = [
        ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
        ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
        ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
        ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
    ]
    aug_sep_variants = [
        ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
        ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),
    ]

    log_apr_may = pm4py.parse_event_log_string(build_period_log_string(apr_may_variants))
    log_jun_jul = pm4py.parse_event_log_string(build_period_log_string(jun_jul_variants))
    log_aug_sep = pm4py.parse_event_log_string(build_period_log_string(aug_sep_variants))

    # 3. Discover DFGs on raw logs
    print("=== SELECTED DISCOVERED DFG EDGES (RAW LOGS) ===")
    for period_name, log_obj in [
        ("Apr-May", log_apr_may),
        ("Jun-Jul", log_jun_jul),
        ("Aug-Sep", log_aug_sep),
    ]:
        dfg, start_acts, end_acts = pm4py.discover_dfg(log_obj)
```

## 7. Provisional conclusion

**Primary explanation for the conformance collapse (Confidence: 92% — High):**
The headline plunge in fitting traces from 93% (Apr–May) to 32% (Jun–Jul) and the subsequent dip to 66% (Aug–Sep) were overwhelmingly caused by **uncoordinated instrumentation, ETL, and policy-governance drift—not a mass compliance breakdown**. Specifically, four non-behavioral or authorized factors explain ~85% of raw nonconformance: (1) UI 4.2 renamed `Classify` to `Risk Screen` without updating the conformance mapping; (2) the event gateway injected an unmodeled technical event (`Queue Routed`); (3) an ETL change substituted warehouse-ingestion timestamps for source sequence numbers on `Decision` and `Notify`, artificially inverting 115 traces; and (4) an August policy mandated `Supervisor Sign-off` above EUR 50,000 while leaving the normative process tree unrevised and case-value-blind. Once these four factors are controlled, fitting traces rebound to **89% (Jun–Jul)** and **86% (Aug–Sep)**—within 4–7 percentage points of the 93% baseline.

**Assessment of whether a real compliance problem remains (Confidence: 55% — Moderate/Indeterminate pending audit):**
A genuine compliance exposure **cannot be ruled out** and warrants urgent investigation. Even after full normalization, 55 cases (25 Jun–Jul, 30 Aug–Sep) moved directly from `Enhanced Review` to `Decision` with no recorded `Compliance Check` (following a July supervisor warning against check bypasses), and 55 cases executed `Manual Override` before `Standard Review`. Furthermore, unstratified optional sign-off modeling has not yet verified whether *every* claim above EUR 50,000 actually received `Supervisor Sign-off`. Flat customer appeal rates (~3.7%) offer zero comfort here because customers rarely appeal approved claims that skipped internal compliance screening.

**Immediate actions:**
- **IT / Data Engineering:** Restore event ordering via source-system sequence numbers, maintain a versioned `Risk Screen` $\leftrightarrow$ `Classify` semantic mapping, tag technical events (`Queue Routed`) separately from business activities, and join `claim_amount` and `org:role` into the conformance mart.
- **Process Owners:** Audit `Manual Override` triggers against gateway routing rules to repair misrouting at the source, and co-maintain a versioned, value-stratified normative model (`<= EUR 50k` vs. `> EUR 50k`).
- **Compliance:** Conduct a 100% source-system provenance audit of all 55 missing-`Compliance Check` cases and all `> EUR 50k` Aug–Sep claims to check for unlogged checks vs. true bypasses.

**What must not be claimed yet:**
Leadership must **not** accuse reviewers of widespread noncompliance based on raw alignment moves, **not** declare the process 86% compliant until high-value sign-off coverage is verified by claim amount, and **not** dismiss the 55 missing compliance checks as an ETL bug without source-database proof.

## 8. Model-governance recommendation

1. **Synchronized Policy-to-Model Versioning:** Bind normative process models to regulatory and operational policy change management so that no policy rule (such as the EUR 50,000 `Supervisor Sign-off` mandate) takes effect without a co-dated, version-tagged normative model release (`v1.0` through `2026-07-31`; `v2.0` effective `2026-08-01`) so historical traces are always evaluated against the policy active at case execution.
2. **Immutable Event-Semantic Contracts:** Decouple front-end UI display strings from canonical event-log identifiers (`activity_id` vs. `ui_label`) via a governed schema registry; require CI/CD sign-off from Process Mining/Compliance owners whenever an application patch alters event names (e.g., `Classify` $\to$ `Risk Screen`) or logging trigger conditions (e.g., `Manual Override`).
3. **Explicit Technical-Event Tiering Policy:** Mandate an `event_layer` attribute (`business`, `routing_system`, `diagnostic`) and non-null `org:resource` semantics (`HUMAN:<id>` vs. `SYSTEM:<service>`) on every emitted event so middleware instrumentation like `Queue Routed` is automatically segregated from business-level conformance checking without ad-hoc string filtering.
4. **Business-Occurrence Timestamp & Sequence Provenance:** Prohibit substituting data-warehouse ingestion or batch-commit timestamps for source business-occurrence timestamps; require every extracted event to carry `(source_event_ts, monotonic_source_seq_no, etl_ingest_ts)` and enforce deterministic tie-breaking via `monotonic_source_seq_no` in all conformance pipelines.
5. **Data-Aware and Role-Aware Conformance Constraints:** Replace purely control-flow optional gateways (`X('Supervisor Sign-off', tau)`) with multi-perspective conformance checks (Petri nets with data guards or segmented normative models plus RBAC assertions) so conditional rules—such as `claim_amount > 50000 => Supervisor Sign-off by role='Supervisor'`—cannot be satisfied merely by skipping an optional branch.
6. **Canary Conformance Gate on Post-Release Deployments:** Run automated canary conformance and data-quality regression checks (tracking variant-entropy spikes, unknown activity labels, null-resource jumps, timestamp-inversion rates, and fitness/precision deltas) within 24 hours of every UI, gateway, or ETL release, quarantining broken extractions before unverified nonconformance metrics reach executive or regulatory dashboards.
