Multiple mechanisms interact: the UI release renamed “Classify” to “Risk Screen” (changing recorded labels) and introduced the technical event “Queue Routed” after risk screening, which altered recorded order and caused alignment moves when the normative tree still expects “Classify”. The ETL change switched timestamps to ingestion time, further destabilising recorded order. Reviewers occasionally used “Manual Override” to correct routing mistakes, which was logged differently after the patch, adding another labelsemantic nuance. Because the normative tree was not updated for the EUR50k supervisorsignoff policy, the model became partially obsolete. When reviewers followed the memo and did not bypass checks, stable appeal rates persisted, showing that real noncompliance was not widespread. The observed conformance drop therefore arises from a combination of (i) label/semantic mismatch (UI rename + Override patch), (ii) order mismatch (Queue Routed insertion + ETL timestamp), and (iii) model omission (missing signoff node). These effects are amplified during alignment because the algorithm treats Queue Routed as a process step and uses ingestion timestamps, inflating the alignment cost. Conversely, correcting the label map, removing Queue Routed from process alignment, and ordering by source sequence simultaneously address both label and order defects, yielding much higher precision and lower fitness loss. The presence of occasional missing Compliance Checks in ManualOverride variants does not prove systematic noncompliance; it may reflect incomplete logging rather than true bypass, especially given the memo’s reminder and stable appeal rates.

## 7. Provisional conclusion
The measured conformance collapse observed between AprilMay and JuneJuly 2026 is **primarily driven by label/semantic logging change and related order defects** rather than by widespread employee noncompliance.  The UI rename (“Classify”  “Risk Screen”) together with the introduction of the technical event “Queue Routed” altered how cases are recorded in the log.  The ETL switch to warehouse ingestion timestamps further destabilised event ordering, producing the high alignment cost (~0.74) seen in raw logs.  When the log is normalized by mapping “Risk Screen” back to “Classify”, optionally dropping “Queue Routed”, and ordering events by the available sourcesequence numbers, alignment fitness drops to below0.15 and precision rises above0.90, matching the improvement reported in the alignment summaries.  These findings support the hypothesis that the conformance drop is largely a **logging artifact**.

At the same time, the policy addition of a EUR50k supervisor signoff (not reflected in the normative tree) and the occasional absence of a recorded “Compliance Check” in ManualOverride variants indicate that the **normative model may be partially obsolete** and that a small number of reviewers might be bypassing the check.  However, stable approval rates, a low 30day appeal increase, and the supervisor memo suggest that systematic noncompliance is **unlikely to be widespread**; the missing checks most plausibly reflect incomplete or inconsistent logging rather than deliberate bypass.

**Confidence levels**  
- *Primary explanation (label/semantic + order defect):* moderatehigh, 70% (supported by normalization experiment and alignment cost reduction).  
- *Remaining compliance concern (potential occasional bypass):* lowmoderate, 40% (based on limited evidence from variant frequencies and memo; requires audit verification).

**Immediate actions**  
- **IT:** Stop treating “Queue Routed” as a process event for conformance checking; either map it away or keep it only for routing analytics. Implement a simple preprocessing step that (a) replaces “Risk Screen” with “Classify”, (b) optionally removes “Queue Routed”, and (c) orders events by the sourcesequence number before alignment. Deploy the preprocessing automatically for all new logs.  
- **Process owners / compliance:** Update the normative process tree to include an optional “Supervisor Signoff” node after “Compliance Check” (and after “Standard Review” for claims >EUR50k). Run the optionalmodel alignment on the normalized log to verify precision >0.9 for signoff cases. Schedule a targeted manual audit of all ManualOverride variants (30 cases) to confirm whether the missing “Compliance Check” was actually performed; if >20% truly missed, issue targeted training.  
- **Data stewardship:** Ensure that sourcesequence numbers (or any equivalent logical timestamp) are always available and used for event ordering in analytics pipelines; document the “eventsemantic contract” that UI label names must map 1:1 to processmodel node names unless a technical event is explicitly excluded from process alignment.

**What must not be claimed yet**  
- Do not assert that “employees are noncompliant” based solely on the observed increase in variants without a recorded Compliance Check.  
- Do not claim that the normative model alone explains the conformance drop; the model omission (missing signoff) contributes only partially.  
- Do not release the normalization pipeline without testing it on a small holdout set of source screenshots to verify that Queue Routed removal does not hide legitimate routing decisions.

## 8. Modelgovernance recommendation
1. **Version every processmodel artefact** (tree, Petri net, optional nodes) together with the exact UI label mapping and technicalevent inclusion policy. Store version IDs in the conformancechecking job metadata.
2. **Define an eventsemantic contract** for each UI label and technical event: (a) which labels map to model nodes, (b) which technical events are *process* vs *metadata* (e.g., Queue Routed), and (c) the default ordering rule (always use sourcesequence numbers for processevent alignment). Contract must be reviewed and approved by process owners, compliance, and IT before release.
3. **Technicalevent policy**: any new gatewaygenerated event that occurs after a classification step must be classified as “metadata” unless it changes the required process flow; metadata events are logged but excluded from processmodel alignment unless explicitly mapped.
4. **Timestamp provenance**: all alignment jobs must retrieve timestamps from the sourcesystem sequence (or logical clock) rather than ingestion timestamps; if only ingestion time is available, record the provenance (sourcesystem vs warehouse) and flag the job for manual review.
5. **Dataaware constraints**: when a policy adds a conditional requirement (e.g., Supervisor Signoff for claims >EUR50k), automatically extend the normative tree with an optional node conditioned on the highvalue attribute. Run a precision check on the optionalnode model before deployment; require precision >0.9 on a validation sample.
6. **Postrelease validation routine**: after each UI or ETL release, run the fourphase diagnostic program (see Section5) on a random 5% of recent cases. If alignment fitness drops >0.2 compared with the previous period, automatically halt conformance reporting until normalization (label map + ordering) is applied and the validation passes. Log the validation outcome together with the release version ID.

These six rules focus on explicit contracts, provenance awareness, conditional optional nodes, and lightweight automated sanity checks, thereby preventing the class of defect that caused the observed conformance deterioration.
