# **Diagnostic Lab Sample Process Redesign: Robust Under Disruption**

---

## **1. Stress Scenarios**
Four plausible disruption scenarios that vary by **case type mix**, **resource degradation**, and **external delays**:

| Scenario | Trigger | Case Mix Shift | Disruption Type | Expected Impact on Bottlenecks |
|----------|---------|----------------|------------------|--------------------------------|
| **Scenario 1: Winter Infection Wave (High Urgent + Complex-Panel)** | Sudden surge in respiratory infections (e.g., flu, COVID) | Routine  **Urgent 35%**, Complex-panel **25%**; Repeat-after-failure **12%** | **Medical validator shortages** (specialist absences) + **courier delays** (high-volume routes) | Medical validation queues explode; Urgent cases bypass Batch wait but fragment M1/M2 schedules. |
| **Scenario 2: Assay Machine Outage (M2 Failure)** | M2 machine crashes during peak load; M1 is slower and more error-prone | Routine **40%**, Urgent **30%**, Complex-panel **20%** | **Assay run  Technical validation bottleneck** | Routine cases routed to M1 create long queues; Urgent cases bypass Batch wait but M1 overloads. |
| **Scenario 3: Specialist Review Collapse** | Medical validator on second Friday absent; partner lab overflow | Urgent **25%**, Complex-panel **22%**; Repeat-after-failure **10%** | **Hold for specialist review  Medical validation queue** | Complex-panel cases stuck in "Hold for specialist review" for days; Urgent cases delayed due to priority rules. |
| **Scenario 4: Courier Compression (Early Morning Delays)** | Local courier service delays samples by 4h due to traffic; peak arrival spikes at 10:00/17:00 | Routine **38%**, Urgent **32%**, Complex-panel **18%** | **Receive sample  Pre-analytical check queue** | Pre-analytical check queues grow; Urgent cases delayed if samples arrive late. |

## **2. Bottleneck-Migration Analysis**
### **Normal Period Bottlenecks (Key Observations)**
- **Pre-analytical check**: High failure rate (760 recollections/18k cases)  **7.5% rework**.
- **Assay machines (M1/M2)**: 98% peak utilization; M2 has higher failure rate  **11.4% repeats**.
- **Medical validation**: 93% peak utilization; Complex-panel cases trigger **2.4x specialist review requests**.
- **Courier intake**: 88% peak utilization; arrival spikes create backlogs.

### **Scenario-Specific Bottleneck Migration**
| Scenario | Initial Bottleneck | Downstream Overload | Why? |
|----------|-------------------|---------------------|------|
| **Winter Infection Wave** | **Medical validation** (93% utilization)  **Hold for specialist review** (87% utilization) | Urgent cases bypass Batch wait but **M1/M2 fragmentation**  longer assay runs  more repeats. |
| **M2 Outage** | **Assay run  Technical validation** (101% utilization) | Routine cases routed to M1  **Pre-analytical check delays** (recollections); Urgent cases bypass Batch wait but M1 overloads. |
| **Specialist Review Collapse** | **Hold for specialist review** (87% utilization)  **Medical validation queue** | Complex-panel cases stuck  **Technical validation backlog** (3900 cases in normal period). |
| **Courier Compression** | **Receive sample  Pre-analytical check** (9.5h median queue) | Samples arrive late  **Pre-analytical check delays**  more recollections  **Test preparation bottlenecks**. |

**Key Insight**: No single station can be relieved without creating a new one. **Example**:
- **I3 (Dedicate M1 to Urgent/Complex-panel)** relieves assay run but **increases repeats** if M2 gets all Routine volume during peaks.

## **3. Robust Redesign Package**
### **Core Interventions (Applicable Across Scenarios)**
| Intervention | Purpose | Assumptions | Failure Mode |
|--------------|---------|-------------|--------------|
| **I6: Early Pre-analytical Defect Triage** | Reject poor samples within 2h to reduce recollections. | Defects are detectable early; no false positives. | Over-rejection may increase physician complaints. |
| **I2: Batch Size Increase (12  24 Routine)** | Improves preparation efficiency but requires strict priority rules. | Routine cases can tolerate longer waits; Urgent cases are not delayed. | **I1 (Urgent-first dispatch) must coexist** to avoid fragmentation. |
| **I4: Cross-Train 2 Technical Validators for Accession Correction** | Reduces accession correction queue (3.0h  1.5h median). | Technical validators can learn corrections in 4 weeks. | **Technical validation capacity may drop** if validators spend too much time correcting. |
| **I7: Shift Courier Pickup Slots** | Smooths arrival peaks (e.g., 06:00/14:00 instead of 10:00/17:00). | Couriers can adjust schedules without cost. | No impact if couriers cannot change routes. |

### **Why This Package is Robust**
- **Reduces rework** (I6/I4) without adding new bottlenecks.
- **Balances Routine/Urgent** (I2 + I1) by allowing batching for Routine but strict priority for Urgent.
- **Mitigates courier delays** (I7) before they cause pre-analytical backlogs.
- **Prevents specialist review collapse** by reducing Complex-panel cases (via I6/I2).

## **6. Residual Vulnerabilities**
1. **Medical Validation Overload**:
   - Even with I5/I10, **Complex-panel cases** (2.4x specialist review risk) may still cause bottlenecks if partner lab delays.
   - **Redesign failure**: I10’s 12h transport delay may worsen Urgent cases if not compensated.

2. **Assay Machine Fragmentation**:
   - **I3 (M1 Urgent/Complex-panel)** risks **M2 overload** if Routine volume spikes during peaks (e.g., after night shifts).
   - **No dynamic routing** to adjust for machine failures.

3. **Pre-analytical Check Rework Loop**:
   - **I6 (Early Triage)** may not catch all defects, leading to **recollections** that still delay Test preparation.
   - **No real-time feedback** to couriers on sample quality.

**Key Takeaway**: The redesign must **prioritize robustness over optimization**—no single intervention solves all scenarios. **Dynamic routing (I3), early defect rejection (I6), and courier smoothing (I7)** are the cornerstones. **Monitoring must focus on leading indicators** (e.g., assay machine utilization, pre-analytical failures) to trigger scenario-specific policies proactively.
