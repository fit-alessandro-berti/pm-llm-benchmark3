```python
# ---- 1. validation -------------------------------------------------
def validate(monthly, dfg):
    problems = []
    if not monthly["month"].is_unique: problems.append("duplicate months")
    if not monthly["month"].is_monotonic_increasing: problems.append("months unsorted")
    pct_cols = ["high_complexity_pct","supplier_z_pct","fast_variant_pct",
                "rework_variant_pct","missing_resource_pct","duplicate_open_case_pct"]
    for c in pct_cols:
        if not monthly[c].between(0,100).all(): problems.append(f"{c} out of [0,100]")
    for c in ["raw_model_fitness","mapped_model_fitness"]:
        if not monthly[c].between(0,1).all(): problems.append(f"{c} out of [0,1]")
    if (monthly["mapped_model_fitness"] < monthly["raw_model_fitness"] - 1e-9).any():
        problems.append("mapped < raw fitness somewhere (unexpected)")
    if not set(dfg["month"]).issubset(set(monthly["month"])):
        problems.append("DFG months missing from monthly table")
    rate_cols = [c for c in dfg.columns if c != "month"]
    if not dfg[rate_cols].apply(lambda s: s.between(0,110)).all().all():
        problems.append("DFG rate outside plausible [0,110]")
    # known structural fact: duplicates appear only from 2026-03
    pre = monthly[monthly["month"] < "2026-03"]
    if (pre["duplicate_open_case_pct"] != 0).any():
        problems.append("duplicates before migration (unexpected)")
    return problems or ["all checks passed"]

print("VALIDATION:", validate(monthly, dfg))

# ---- 2. baseline-relative changes ----------------------------------
BASELINE_MONTHS = ["2026-01", "2026-02"]
base = monthly[monthly["month"].isin(BASELINE_MONTHS)].mean(numeric_only=True)
delta = monthly.set_index("month").drop(index=BASELINE_MONTHS) - base

print(delta[["cases","high_complexity_pct","rework_variant_pct",
             "median_cycle_h","p90_cycle_h","mapped_model_fitness"]].round(2))

edges = [c for c in dfg.columns if c != "month"]
ref = dfg.loc[dfg["month"] == "2026-01", edges].iloc[0]
def l1(a, b): return float(np.abs(np.asarray(a, float) - np.asarray(b, float)).sum())
dfg["L1_vs_2026-01"] = dfg[edges].apply(lambda r: l1(r, ref), axis=1)
dfg["L1_month_over_month"] = [np.nan] + [l1(dfg[edges].iloc[i], dfg[edges].iloc[i-1])
                                          for i in range(1, len(dfg))]
dfg["mean_abs_per_edge"] = dfg["L1_vs_2026-01"] / len(edges)

def flag_change_points(series, k=3.5, eps=1e-9):
    """Robust month-over-month rule: flag m if the MoM jump is an outlier
    under a median/MAD model of all jumps (0.6745/MAD  normal consistency)."""
    d = series.diff().dropna()
    med, mad = d.median(), (d - d.median()).abs().median()
    if mad < eps:                       # degenerate: fall back to std
        mad = d.std() / 1.4826 if d.std() > eps else eps
    rz = 0.6745 * (d - med) / mad
    return [(m, round(float(d[m]), 2), round(float(rz[m]), 1))
            for m in rz.index if abs(rz[m]) > k]

for col in ["raw_model_fitness","mapped_model_fitness","median_cycle_h",
```

```python
def regime_starts(series, baseline_idx, k=3.0, min_effect=0.0, run=2, max_regimes=3):
    s = series.copy()
    cps, start = [], 0
    base = s.loc[baseline_idx]
    for _ in range(max_regimes):
        mu = base.mean()
        sig = 1.4826 * (base - base.mean()).abs().median()
        thr = max(k * sig, min_effect)
        breach = (s.iloc[start:] - mu).abs() > thr
        # find first index that begins a run of length `run`
        idx = list(breach.index)
        found = None
        for i in range(len(idx) - run + 1):
            if breach.loc[idx[i:i+run]].all():
                found = idx[i]; break
        if found is None: break
        cps.append(found)
        start = list(s.index).index(found)
        base = s.iloc[start:start+2]   # re-baseline on first 2 months of new regime
        start += 2
    return cps
```

## 2. Raw-versus-normalized interpretation

The 37-point gap between raw (0.55) and mapped (0.90) fitness in March is overwhelmingly a vocabulary and provenance artifact: the normative model expects `Validate Eligibility`, the migrated log emits `Eligibility Screen`, and duplicated technical `Open Case` events insert steps the model forbids. Recovery to 0.90 shows March–April trace structure stayed close to baseline, consistent with flat cycle times and a normalized DFG distance of only 3 per 100 cases.

But mapping proves equivalence only up to relabeling. It cannot detect frequency shifts (rework share doubling), new routing (senior assessment), or waiting-time inflation, and a permissive model can absorb deviations. Mapped fitness itself decays from 0.93 to 0.86–0.87 by July and November — a small but real behavioral signal no mapping explains.

Duplicates and missing resources damage different analyses. Duplicated events corrupt DFG counts, variant statistics, fitness, and timestamp-derived waiting times, so they must be removed before structural analysis. Missing resources (~5–6.5%, concentrated in migrated activities, non-random) mainly corrupt resource-level views — workload, handovers, per-assessor service times — and simply dropping affected cases would import selection bias into exactly the analyses needed to study staffing.

Post-May drift cannot be dismissed as logging. Migration artifacts are essentially constant from March (11 labels, ~4–6% duplicates, ~5–6.5% missing resources), while rework doubled in May, cycle times climbed through August and again in October, and supplier-affected share moved in step with dated external events. A static logging fault cannot generate time-varying, event-aligned changes in activities — `Assess`, `Request Info`, `Collect Documents` — that the migration never relabeled.

### 3.5 One global change point or many?

The data support **multiple mechanism-specific change points**, not one global one. The artifacts change at disjoint times: in March only logging metrics move (performance flat, normalized DFG stable); in May only behavioral/performance metrics move (logging metrics constant); in October case mix and the senior edge move. The correct design is per-artifact detection (separate screens for labels/schema, DFG structure, and temporal profiles) reconciled afterwards against the event calendar — which is exactly what Section 7 specifies.

## 6. Segmentation plan

| segment level | variables | purpose | minimum support rule | comparisons enabled | risk of conditioning bias |
|---|---|---|---|---|---|
| L0 global | all cases | system-health screens only (schema, duplicates, volume) | full log | gross change detection | Simpson's paradox; masks everything below |
| L1 time | calendar month (ISO week for operations) | trend, seasonality, change-point placement | 100 cases/period, else merge weeks | temporal alignment with event calendar | within-period composition shifts |
| L2 primary | supplier (Z / non-Z) × complexity (high / standard), per month | separate supplier shock and mix from organizational drift | 30 cases/cell-month ( ±9pp precision on a 50% rate); else merge to bimonthly | exposed-vs-control contrasts; within-cell drift | conditioning on supplier  conditioning on region/customer mix — interpret as association |
| L3 supplier detail | region / customer tier within Z | locate the supplier effect | 30 cases/cell-month | is the Z effect concentrated or uniform? | tiny cells; multiple comparisons |
| L4 policy | priority class × complexity, post-07-01 | test priority redistribution | 30 cases/class-month | waiting transfer between classes | class is endogenous to complexity (near-collinearity) |
| L5 resource | team / assessor, after resource-ID repair | workload equity, service-time attribution | 20 cases/resource-month | staffing-effect localization | non-random missingness; dropping incomplete cases selects on the artifact |

**Primary monitoring population:** the four monthly supplier × complexity cells, with **non-Z, standard-complexity cases as the reference segment**. This segment is untouched by the supplier shock, does not enter senior routing (avoiding the recording ambiguity), and is the cleanest substrate on which to read organizational drift (staffing, priority spillover). The other three cells are monitored as exposed groups; global aggregates are used only for health checks.

**Seasonality:** maintain year-ago seasonal references alongside fixed baselines; deseasonalize volume and mix before charting; widen control bands in known seasonal windows rather than suppressing monitoring; never pool October data against a March reference. **Multiple testing:** hierarchical alerting (global screen first, segment drill-down only on trigger); Benjamini–Hochberg FDR control (q  0.1) across concurrent segment monitors; minimum run-length rules (2 consecutive breaches) on all EWMA/CUSUM charts. Thresholds are monitor-specific by design — there is no universal limit, because a 2pp duplicate-event shift and a 2pp rework shift have entirely different meanings.

```python
def mom_outliers(series, k=3.5, eps=1e-9):
    """Flag months whose month-over-month jump is a robust outlier
    (median/MAD screen over the series of jumps)."""
    d = series.diff().dropna()
    med = d.median()
    mad = (d - med).abs().median()
    if mad < eps:
        mad = max(d.std() / 1.4826, eps)
    rz = 0.6745 * (d - med) / mad
    return [(m, round(float(d[m]), 2), round(float(rz[m]), 1))
            for m in rz.index if abs(rz[m]) > k]

def regime_starts(series, baseline_idx, k=2.0, min_effect=0.0, run=2,
                  max_regimes=3):
    """Recursive screen: first month starting a run of >=run consecutive
    breaches of baseline mean +/- max(k*robust_sd, min_effect);
    then re-baseline on the new regime and scan on (binary-segmentation-lite)."""
    s = series
    cps, pos, base_s = [], 0, s.loc[baseline_idx]
    for _ in range(max_regimes):
        mu = base_s.mean()
        sd = 1.4826 * (base_s - mu).abs().median()
        thr = max(k * sd, min_effect)
        breach = (s.iloc[pos:] - mu).abs() > thr
        idx = list(breach.index)
        found = None
        for i in range(len(idx) - run + 1):
            if breach.loc[idx[i:i + run]].all():
                found = idx[i]
                break
        if found is None:
            break
        cps.append(found)
        pos = list(s.index).index(found)
        base_s = s.iloc[pos:pos + 2]
        pos += 2
    return cps
```

```python
import pandas as pd
import pm4py

CASE_ID, ACT, TS = "case:concept:name", "concept:name", "time:timestamp"
LABEL_MAP = {"Eligibility Screen": "Validate Eligibility"}

def format_log(df):
    """Standardise a raw dataframe for PM4Py (does not mutate df)."""
    return pm4py.format_dataframe(df, case_id=CASE_ID, activity_key=ACT,
                                  timestamp_key=TS)

def slice_window(log, start, end, mode="events"):
    """Time-slice a log; mode='events' keeps events inside [start, end].
    Alternative modes: 'traces_contained', 'traces_intersecting'."""
    return pm4py.filter_time_range(log, start, end, mode=mode)

def monthly_dfgs(log):
    """One DFG per calendar month: {period: (dfg, start_acts, end_acts)}."""
    out = {}
    for period, chunk in log.groupby(log[TS].dt.to_period("M")):
        out[str(period)] = pm4py.discover_dfg(chunk)
    return out

def variant_table(log):
    """Variant -> frequency table (descending)."""
    variants = pm4py.get_variants(log)   # dict: variant -> list of traces
    return (pd.Series({k: len(v) for k, v in variants.items()}, name="count")
              .sort_values(ascending=False))

def temporal_profile(log):
    """{(activity_a, activity_b): (mean_seconds, std_seconds)} for
    directly-follows pairs; conformance via pm4py.conformance_temporal_profile."""
    return pm4py.discover_temporal_profile(log)

def constraint_models(log):
    """Optional declarative views: log skeleton + DECLARE."""
    return {"log_skeleton": pm4py.discover_log_skeleton(log),
            "declare": pm4py.discover_declare(log)}

def normalized_copy(df, label_map=LABEL_MAP):
    """Return a NORMALIZED COPY; the original log is never overwritten.
    Maps migrated labels and removes exact duplicate technical events
    (same case, activity, timestamp). Production dedup should target the
    known technical event ('Open Case') with a timestamp-tolerance rule."""
    out = df.copy()
    out[ACT] = out[ACT].replace(label_map)
    out = out.drop_duplicates(subset=[CASE_ID, ACT, TS])
    return out

def compare_raw_vs_normalized(df):
    """Discover DFGs on raw and normalized versions of the same log."""
    raw = format_log(df)
    norm = format_log(normalized_copy(df))
    return {"raw": pm4py.discover_dfg(raw),
            "normalized": pm4py.discover_dfg(norm)}

def dfg_l1(dfg_a, dfg_b, cases_a, cases_b):
    """L1 distance between two DFGs after per-100-cases normalization,
    over the union of edges (absent edge = 0)."""
    edges = set(dfg_a) | set(dfg_b)
    return sum(abs(dfg_a.get(e, 0) / cases_a - dfg_b.get(e, 0) / cases_b)
               for e in edges) * 100
```

## 9. Provisional attribution

**Strongest conclusions.** (1) The March fitness collapse is a logging/semantic artifact of the migration (confidence ~90–95%): mapped fitness recovers to 0.90, the normalized DFG moves by only 3 points of edge mass, and cycle times are flat across the boundary. (2) The May rework surge is supplier-driven (~80–85%): `AssessRequest Info` doubles exactly when Supplier Z's affected share jumps from 18% to 43%, and it partially reverses after Z's September recovery and the December document-quality campaign. (3) The October–November volume and complexity surge is seasonal population drift (~85%): it matches the known renewal calendar and should recur annually.

**Plausible but not proven.** The June–August deterioration is predominantly staffing-driven queueing (~70%): `Assess` service time rose only ~0.6h while median cycle time rose ~13h, implying waiting, not doing, absorbed the loss of four assessors. The July priority rule plausibly redistributed delay from high-complexity to standard cases (~60%), which would raise the aggregate median even with constant total work; the aggregate table cannot show this, and the July rework uptick (2429) may partly reflect aging standard cases rather than new behavior. A persistent behavioral adaptation — a "new normal" of more `Request Info` loops and more senior routing — is suggested by December residuals (rework 21% vs 11.5% baseline; senior edges 14 vs 4–5), but confidence is only ~50%, because December still carries seasonal tail (34% complex) and supplier backlog.

**Where attribution is blocked.** Supplier × staffing interaction: rework load peaked exactly when capacity was cut, so July–August deterioration is superadditive and cannot be cleanly split. The October senior-assessment jump (722 per 100) outruns the complexity increase; given historically inconsistent recording, this is an irreducible logging-versus-behavior ambiguity without a recording-practice audit. December's improvement has three concurrent causes (overtime, campaign, seasonal decline) that aggregates cannot separate.

**What would change my mind:** segment data showing standard-case waiting flat in July (weakens staffing/priority); prior-year October logs without a senior-edge jump (points to recording change); evidence that Z's affected share fell only because cases were rerouted (weakens supplier recovery); or an audit showing missing resources are random (weakens measurement-bias concerns).

## 10. Monitoring decision rules

1. IF raw fitness collapses while mapped fitness, normalized DFG rates, and cycle times are stable, THEN route to data engineering as a logging/semantic incident before any process intervention, BECAUSE relabeling and duplicate provenance break vocabulary-dependent conformance without changing behavior.
2. IF the `AssessRequest Info` rate rises concentrated in one supplier's segment, THEN trigger a supplier scorecard and document-quality sampling rather than a global process redesign, BECAUSE localized rework indicates an input-quality shock, not an internal control-flow change.
3. IF waiting before `Assess` rises across all supplier segments while service time stays flat, THEN treat it as a capacity/queueing problem and review staffing and utilization, BECAUSE flat-service-plus-rising-waiting is the signature of resource shortage, not of skill or case difficulty.
4. IF high-complexity waiting falls while standard-case waiting rises after a priority change, THEN report redistribution separately from net performance and assess SLA and fairness impact, BECAUSE aggregate medians conceal cross-class transfers of delay.
5. IF October volume and complexity shares rise in line with the prior year, THEN classify the change as seasonal population drift and switch to seasonal reference models instead of declaring new drift, BECAUSE recurring mix shifts mimic behavioral drift against a fixed baseline.
6. IF missing-resource rates are non-random by activity or team, THEN repair or exclude the affected fields before any resource-level analysis and flag the measurement bias, BECAUSE conditioning on incomplete provenance biases workload, handover, and staffing conclusions.
7. IF an improvement coincides with multiple concurrent interventions (overtime, campaign, seasonal decline), THEN withhold single-cause credit and evaluate via staggered rollout or holdout segments, BECAUSE concurrent treatments are not separately identifiable from aggregate data.
