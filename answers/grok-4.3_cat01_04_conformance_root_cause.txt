## 3. Causal-abductive explanation

```
UI_release -> recorded_labels
UI_release -> technical-event/extraction artifact
policy_change -> true_process
ETL_change -> recorded_order
reviewer_behavior -> recorded_labels (Manual Override)
true_process -> normative_model (via obsolescence)
recorded_labels -> alignment_moves
recorded_order -> alignment_moves
technical-event/extraction artifact -> alignment_moves
normative_model -> measured_fitness
alignment_moves -> measured_fitness
business_outcomes <- true_process
hidden: high_value_attribute
```

Multiple independent mechanisms produced the observed conformance collapse. The UI release altered only surface labels while the ETL change corrupted Decision/Notify ordering; both directly inflated log moves and reduced fitness. Addition of the technical Queue Routed event further increased visible moves until filtered. The August policy introduced a real behavioral requirement (Supervisor Sign-off) that the control-flow model never encoded, so even after label and ordering repairs a second fitness drop appeared. Because business outcomes remained stable, the logging defects explain most of the measured conformance collapse, yet they do not rule out a smaller, undetected noncompliance layer on high-value cases whose detection is known to be incomplete. An over-permissive model can restore fitness without proving operational safety.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py
from pm4py.objects.log.importer import parse_event_log_string
from pm4py.algo.conformance.alignments.petri_net import algorithm as alignments
from pm4py.algo.evaluation.replay_fitness import algorithm as fitness_eval
from pm4py.algo.evaluation.precision import algorithm as precision_eval

pt = pm4py.parse_process_tree("->('Receive','Classify',X(*( 'Standard Review','Request Info'),->('Enhanced Review','Compliance Check')),'Decision','Notify')")
net, im, fm = pm4py.convert_to_petri_net(pt)

# April-May log
log_apr = parse_event_log_string("""
Receive,Classify,Standard Review,Decision,Notify
Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify
Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify
""")

dfg_apr, start, end = pm4py.discover_dfg(log_apr)
aligned_apr = alignments.apply(log_apr, net, im, fm)
print("Apr-May fitness:", fitness_eval.evaluate(aligned_apr, log_apr, net, im, fm))

# June-July raw vs normalized
log_jun_raw = parse_event_log_string("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify\nReceive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify")
aligned_raw = alignments.apply(log_jun_raw, net, im, fm)
print("Jun-Jul raw fitness:", fitness_eval.evaluate(aligned_raw, log_jun_raw, net, im, fm))

# Normalization pipeline
log_norm = pm4py.replace_activity_names(log_jun_raw, {"Risk Screen": "Classify"})
log_norm = pm4py.filter_activities(log_norm, ["Queue Routed"], retain=False)
aligned_norm = alignments.apply(log_norm, net, im, fm)
print("Jun-Jul normalized fitness:", fitness_eval.evaluate(aligned_norm, log_norm, net, im, fm))

# August-September candidate model with optional sign-off
pt_sign = pm4py.parse_process_tree("->('Receive','Classify',X(*( 'Standard Review','Request Info'),->('Enhanced Review','Compliance Check')),?('Supervisor Sign-off'),'Decision','Notify')")
net_sign, im_sign, fm_sign = pm4py.convert_to_petri_net(pt_sign)
log_aug = parse_event_log_string("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify")
log_aug = pm4py.replace_activity_names(log_aug, {"Risk Screen": "Classify"})
log_aug = pm4py.filter_activities(log_aug, ["Queue Routed"], retain=False)
fitness_sign = fitness_eval.evaluate(alignments.apply(log_aug, net_sign, im_sign, fm_sign), log_aug, net_sign, im_sign, fm_sign)
precision_sign = precision_eval.evaluate(log_aug, net_sign, im_sign, fm_sign)
print("Aug-Sep sign-off model fitness/precision:", fitness_sign, precision_sign)

print("Caveat: control-flow-only optional sign-off model cannot enforce EUR 50k data condition and may overgeneralize.")
```

## 7. Provisional conclusion

The measured conformance collapse is primarily explained by three logging and model-maintenance defects that occurred in rapid succession: the UI label change, the injection of technical events, and the ETL timestamp substitution. These artifacts account for the majority of the fitness drop from 93 % to 32 %; staged normalization (label map + technical-event removal + source ordering) recovers fitness to 89 %, demonstrating that the underlying control flow remained largely stable. A secondary, genuine model-obsolescence effect appears after the August policy change, visible as a renewed fitness decline once logging repairs are applied.

A real compliance problem cannot yet be ruled out. The 25–30 enhanced-review traces lacking a recorded Compliance Check, the appearance of Supervisor Sign-off outside the model, and the known incompleteness of incident detection together leave open the possibility of selective bypasses on high-value cases. Stable appeal rates provide only weak reassurance.

IT should immediately restore source-system sequence ordering for Decision/Notify and publish an event-semantic contract. Process owners must version the normative model whenever policy changes occur. Compliance should commission a stratified manual audit of all high-value cases from June onward. It must not yet be claimed that “no compliance problem exists” or that “employees became noncompliant”; both assertions require the diagnostic program above.

## 8. Model-governance recommendation

1. Every normative model receives a version tag; any policy or UI change triggers a mandatory model revision within one release cycle.
2. Event labels are bound to semantic contracts; label changes require dual sign-off from business and process-mining teams before ETL propagation.
3. Technical events are explicitly tagged in the event log schema and filtered by default in conformance jobs unless explicitly promoted.
4. All timestamp fields carry provenance metadata (source vs. ingestion time); conformance jobs must default to source-system order when available.
5. High-value or authorization attributes are declared as data guards; control-flow models are automatically annotated with data conditions during conformance.
6. Post-release validation runs a 30-day shadow conformance check on both raw and normalized logs before the new model is declared normative.
