# 1. Executive Verdict

The net is structurally a workflow net: it has a unique source place, a unique sink place, and every node lies on some source-to-sink path. It should **not** be expected to be sound. The principal defect is that the waiver branch’s join, `t_join_waived`, consumes only `p_waived` and produces `p_decision`; it never consumes `p_analysis_done`. Consequently, after a waiver, `t_authorize` can fire before `t_analyze`, bypassing mandatory analysis, and even if `t_analyze` fires, its token remains in `p_analysis_done` and cannot be consumed. The business consequence is that a case may be authorized without the mandatory analysis, and the case may terminate with a token in the sink plus a leftover analysis token, so the exact final marking is not reached.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| source / sink / im / fm | Unique initial and final places; `im={source:1}`, `fm={sink:1}` | Correctly defined; source token starts, sink token ends | By themselves fine; final marking not reached on waiver path |
| `t_register` | Registration step | Consumes `source`, produces `p_ready` | None |
| `t_split` | AND-split to start analysis and review in parallel | Consumes `p_ready`, produces `p_analysis` and `p_review` | Correct |
| Analysis branch (`p_analysis`, `t_analyze`, `p_analysis_done`) | Mandatory analysis | Produces `p_analysis_done` | On waiver path, `p_analysis_done` is not consumed by `t_join_waived`; leftover or bypass |
| Review alternatives (`p_review`, `t_standard_review`, `t_waive_review`) | XOR choice: standard review or waiver | `p_review` consumed by exactly one; produces `p_review_done` or `p_waived` | Correct mutual exclusion |
| `t_standard_review -> p_review_done` | Standard review outcome | Feeds `t_join_normal` | Correct for standard path |
| `t_waive_review -> p_waived` | Waiver outcome | Feeds `t_join_waived` | Waiver token not synchronized with analysis |
| `t_join_normal` | AND-join of analysis_done and review_done | Consumes `p_analysis_done` and `p_review_done`, produces `p_decision` | Correct for standard path |
| `t_join_waived` | Join for waiver path | Consumes only `p_waived`, produces `p_decision` | Missing `p_analysis_done` input; authorize can fire without analysis; leftover analysis token |
| `t_authorize` | Authorization after both analysis and review outcome | Consumes `p_decision`, produces `sink` | Can fire prematurely on waiver path |
| Workflow-net path condition | Every node on a source-to-sink path | Yes: all places/transitions lie on at least one source-to-sink path | Structural workflow-net property holds; soundness still fails |

# 3. Marking-Based Counterexample

Counterexample 1 (waiver path authorizes before analysis):

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source:1}` | `t_register` | initial marking `im` |
| 1 | `t_register` | `{p_ready:1}` | `t_split` | registration complete |
| 2 | `t_split` | `{p_analysis:1, p_review:1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | parallel branches started |
| 3 | `t_waive_review` | `{p_analysis:1, p_waived:1}` | `t_analyze`, `t_join_waived` | waiver recorded; analysis still pending |
| 4 | `t_join_waived` | `{p_analysis:1, p_decision:1}` | `t_analyze`, `t_authorize` | `t_authorize` enabled before `t_analyze` |
| 5 | `t_authorize` | `{p_analysis:1, sink:1}` | `t_analyze` | sink token exists but not final marking |
| 6 | `t_analyze` | `{p_analysis_done:1, sink:1}` | none | deadlock; leftover `p_analysis_done` cannot be consumed |

At step 5 of Counterexample 1, a token exists in `sink`, but the exact final marking `fm={sink:1}` has not been reached because `p_analysis` is still present. At step 6, after `t_analyze`, the marking is `{p_analysis_done:1, sink:1}`. The leftover `p_analysis_done` cannot be consumed: `t_join_normal` requires `p_review_done`, which is absent because `t_standard_review` was not fired; `t_join_waived` requires `p_waived`, which was already consumed. Thus the net deadlocks with a sink token plus a leftover token.

Counterexample 2 (analysis completed before waiver) is an additional symptom: even with analysis completed, the waiver path deadlocks.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source:1}` | `t_register` | initial marking `im` |
| 1 | `t_register` | `{p_ready:1}` | `t_split` | |
| 2 | `t_split` | `{p_analysis:1, p_review:1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | |
| 3 | `t_analyze` | `{p_analysis_done:1, p_review:1}` | `t_standard_review`, `t_waive_review` | analysis completed first |
| 4 | `t_waive_review` | `{p_analysis_done:1, p_waived:1}` | `t_join_waived` | waiver recorded |
| 5 | `t_join_waived` | `{p_analysis_done:1, p_decision:1}` | `t_authorize` | `t_join_waived` leaves `p_analysis_done` |
| 6 | `t_authorize` | `{p_analysis_done:1, sink:1}` | none | deadlock; sink token plus leftover |

Counterexample 2 shows that even when `t_analyze` fires before `t_authorize`, the waiver path still leaves `p_analysis_done` unconsumed. After `t_authorize`, the marking is `{p_analysis_done:1, sink:1}`, not `fm`. The leftover `p_analysis_done` cannot be consumed for the same reason: `t_join_normal` needs `p_review_done` (absent), and `t_join_waived` needs `p_waived` (already consumed).

# 4. Minimal-Repair Alternatives

Edit-cost model: each added or removed arc costs 1; each added or removed place costs 1; each added or removed transition costs 1. Label-only changes cost 0 and are not used. A repair is minimal if no lower-cost repair satisfies the stated intent/policy.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| R1: proper two-input waiver join | Add arc `p_analysis_done -> t_join_waived` | 1 | Yes: mandatory analysis on waiver path; XOR review choice; final marking | Waiver path now blocks authorize until `p_analysis_done` is present; no other change | None significant; `t_join_waived` silent but already silent; no duplicate behavior because `p_review_done` and `p_waived` are mutually exclusive |
| R2: make analysis optional under waiver | Add arc `p_analysis_done -> t_join_waived`; add transition `t_skip_analysis` (silent); add arcs `p_analysis -> t_skip_analysis`, `p_waived -> t_skip_analysis`, `t_skip_analysis -> p_decision` | 5 | Partially: review choice and final marking preserved; analysis no longer mandatory under waiver | If waiver recorded before analysis completes, `t_skip_analysis` can cancel pending analysis and authorize; if analysis already completed, `t_join_waived` consumes `p_analysis_done` and `p_waived` | Policy change must be approved; introduces a new silent skip transition; audit must distinguish `t_skip_analysis` from `t_analyze` |
| R3: merge review outcomes into normal synchronization | Add arc `t_waive_review -> p_review_done`; remove arc `t_waive_review -> p_waived`; remove place `p_waived`; remove transition `t_join_waived`; remove arcs `p_waived -> t_join_waived` and `t_join_waived -> p_decision` | 6 | Yes: mandatory analysis; XOR review choice; final marking | Both review outcomes produce the same `p_review_done` token; waiver no longer has a distinct holding place; `t_join_waived` removed | Loss of marking-level distinguishability between standard review and waiver; downstream cannot tell which review type occurred from the net state alone (only from transition labels) |

Minimality: R1 is the unique minimum-cost repair that preserves mandatory analysis. Any repair must make the waiver path consume the analysis-done token; the cheapest way is to add one arc from `p_analysis_done` to the existing `t_join_waived`. No zero-cost repair exists because the current `t_join_waived` has only `p_waived` as input. R2 is the minimum-cost repair for the policy-change alternative (analysis optional under waiver): it adds one arc to handle the already-completed analysis case and one skip transition with three arcs to handle the pending-analysis case. R3 is a structurally distinct but higher-cost repair that merges review outcomes into `p_review_done`. No two repairs tie.

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

def format_marking(marking):
    return {p.name: marking[p] for p in marking if marking[p] > 0}

def fire_named_transition(net, marking, transition_name):
    enabled = pm4py.get_enabled_transitions(net, marking)
    enabled_names = {t.name for t in enabled}
    if transition_name not in enabled_names:
        raise ValueError(f"Transition {transition_name} is not enabled in marking {format_marking(marking)}")
    transition = next(t for t in net.transitions if t.name == transition_name)
    new_marking = Marking()
    for place, count in marking.items():
        new_marking[place] = count
    for arc in net.arcs:
        if arc.target == transition:
            new_marking[arc.source] -= 1
        elif arc.source == transition:
            if arc.target in new_marking:
                new_marking[arc.target] += 1
            else:
                new_marking[arc.target] = 1
    return new_marking

print("=== Original net ===")
print("is workflow net:", pm4py.check_is_workflow_net(net))
print("soundness:", pm4py.check_soundness(net, im, fm, print_diagnostics=True))
print("enabled at im:", [t.name for t in pm4py.get_enabled_transitions(net, im)])
print("reachability graph:", pm4py.convert_to_reachability_graph(net, im, fm))

print("=== Repaired net ===")
print("is workflow net:", pm4py.check_is_workflow_net(repaired_net))
print("soundness:", pm4py.check_soundness(repaired_net, repaired_im, repaired_fm, print_diagnostics=True))
print("enabled at repaired_im:", [t.name for t in pm4py.get_enabled_transitions(repaired_net, repaired_im)])
print("reachability graph:", pm4py.convert_to_reachability_graph(repaired_net, repaired_im, repaired_fm))

m = im

for step, tname in enumerate(sequence, start=1):
    m = fire_named_transition(net, m, tname)
    print(f"Step {step}: fired {tname}; marking = {format_marking(m)}; enabled = {[t.name for t in pm4py.get_enabled_transitions(net, m)]}")

print("=== Positive trace on repaired net ===")
```

Expected qualitative difference: both nets should be workflow nets. The original net should fail soundness, with diagnostics indicating deadlocks/improper completion; its reachability graph contains states with a sink token plus a leftover `p_analysis` or `p_analysis_done` token. The repaired net should pass soundness, and its reachability graph should contain no such deadlock states. Enabled transitions at the initial marking are the same (`t_register`).

# 7. Repair Trade-Offs and Residual Risks

- **Distinguishability:** In R1, waiver and standard review remain distinguishable before the join: `p_review_done` vs `p_waived`, and by transition labels `t_standard_review` vs `t_waive_review`. After the join, both paths converge to `p_decision`, so the net state alone does not record which review type occurred. If audit requires marking-level distinction after the join, keep separate decision places or add labels to the join transitions.

- **Silent transitions and duplicate behavior:** R1 adds no new transitions; `t_split`, `t_join_normal`, and `t_join_waived` remain silent. They do not create duplicate behavior because `p_review_done` and `p_waived` are mutually exclusive (both consume the same `p_review` token). However, silent transitions can make logs harder to read; consider labeling them if tooling supports.

- **Soundness vs business alignment:** Soundness proves option to complete, no deadlocks, and no leftover tokens at the final marking. It does not prove the business rule "authorization only after analysis and review outcome." A sound net could still allow authorization before analysis if the join were miswired differently. Therefore, soundness must be combined with trace-based regression tests.

- **Regression tests:** Positive traces: (1) `register, split, analyze, standard_review, join_normal, authorize`; (2) `register, split, analyze, waive_review, join_waived, authorize`; (3) interleavings with review before analysis. Negative traces: any trace where `t_authorize` fires while `p_analysis` or `p_analysis_done` is present; any trace where `t_authorize` fires after `t_join_waived` but before `t_analyze`; any trace where both `t_standard_review` and `t_waive_review` fire; any trace ending with `sink` plus any other token.

- **Detecting accidental bypass:** Add an invariant check: after firing `t_waive_review` and `t_join_waived`, `t_authorize` must not be enabled until `t_analyze` has fired and `p_analysis_done` is consumed. In code, assert that in the marking after `t_join_waived` on the waiver path, `t_authorize` is not enabled. Also use conformance checking against a reference model or check every complete trace contains exactly one `t_analyze`.

# 8. Final Recommendation

Deploy **R1** (add arc `p_analysis_done -> t_join_waived`). It is the unique minimal repair under the stated edit-cost model: one added arc, no new places or transitions, no policy change. It preserves mandatory analysis on both review paths, keeps the XOR choice between standard review and waiver, and restores soundness by ensuring the waiver join consumes both the waiver token and the analysis-done token. The only cost is that the waiver join remains silent, which was already the case.

Fallback: **R3** (merge review outcomes into `p_review_done` and remove `t_join_waived`). It also preserves mandatory analysis and is structurally clean, but costs six edits and removes the distinct `p_waived` place, so waiver and standard review are distinguishable only by transition labels, not by marking. Use R3 if the business wants a single synchronization point and accepts that marking-level distinction. Do not use R2 unless the business explicitly changes policy to make analysis optional under waiver.
