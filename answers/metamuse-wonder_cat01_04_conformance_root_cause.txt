Multiple mechanisms stack because measured fitness is a function of the recorded log, the model, and the alignment preprocessing, not of true behavior alone. In June, a semantic relabel makes every otherwise conforming trace contain a log move for Risk Screen and a model move for Classify, while Queue Routed adds a systematic log move where present. Because gateway coverage is incomplete, the same true behavior splits into variants with and without Queue Routed, inflating events per case from 5.4 to 6.3 without changing cycle time or appeals. The ETL ingestion-time ordering independently inverts Decision and Notify in a concentrated 70-case variant; source screenshots for 11 cases suggest this is recorded, not true, order, explaining why reordering by sequence restores fitness to 89% in June-July. In August, Supervisor Sign-off is a real, policy-mandated insertion that the un-updated tree cannot replay, so it appears as a log move even when execution is compliant with the new policy. Allowing it optionally raises August-September fitness, but that improvement alone does not prove conditional correctness. Residual Manual Override and Enhanced Review without Compliance Check could reflect true bypass, routing correction, or missing events. Unchanged approvals, cycle time, and appeals therefore neither prove pure artefact—logging errors and real insertions can leave outcomes stable—nor exclude noncompliance, especially because incident detection is incomplete, noncompliance can be low-frequency, outcomes are lagging and insensitive, and a skipped check need not change an approval. Outcomes provide weak corroboration, not identification.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py
from collections import Counter

# Activities use underscores because parse_event_log_string is whitespace-delimited.
# Mapping back: Standard_Review='Standard Review', etc.

NORMATIVE_STR = ("->( 'Receive', 'Classify', "
                 "X( *( 'Standard_Review', 'Request_Info' ), "
                 "->( 'Enhanced_Review', 'Compliance_Check' ) ), "
                 "'Decision', 'Notify' )")

# Candidate: optional Supervisor Sign-off immediately before Decision.
# 'tau' is used as the silent alternative in the choice; if a PM4Py version
# treats it as a label, replace with that version's silent-activity idiom.
CANDIDATE_STR = ("->( 'Receive', 'Classify', "
                 "X( *( 'Standard_Review', 'Request_Info' ), "
                 "->( 'Enhanced_Review', 'Compliance_Check' ) ), "
                 "X( 'Supervisor_Sign-off', 'tau' ), "
                 "'Decision', 'Notify' )")

VARIANTS = {
    "apr_may": [
        (("Receive","Classify","Standard_Review","Decision","Notify"), 380),
        (("Receive","Classify","Enhanced_Review","Compliance_Check","Decision","Notify"), 180),
        (("Receive","Classify","Standard_Review","Request_Info","Standard_Review","Decision","Notify"), 40),
    ],
    "jun_jul": [
        (("Receive","Risk_Screen","Queue_Routed","Standard_Review","Decision","Notify"), 270),
        (("Receive","Risk_Screen","Queue_Routed","Enhanced_Review","Compliance_Check","Decision","Notify"), 145),
        (("Receive","Risk_Screen","Queue_Routed","Standard_Review","Notify","Decision"), 70),
        (("Receive","Risk_Screen","Standard_Review","Decision","Notify"), 90),
        (("Receive","Classify","Queue_Routed","Standard_Review","Decision","Notify"), 30),
        (("Receive","Risk_Screen","Queue_Routed","Enhanced_Review","Decision","Notify"), 25),
        (("Receive","Risk_Screen","Queue_Routed","Manual_Override","Standard_Review","Decision","Notify"), 20),
    ],
    "aug_sep": [
        (("Receive","Risk_Screen","Queue_Routed","Standard_Review","Decision","Notify"), 210),
        (("Receive","Risk_Screen","Queue_Routed","Enhanced_Review","Compliance_Check","Supervisor_Sign-off","Decision","Notify"), 150),
        (("Receive","Risk_Screen","Queue_Routed","Enhanced_Review","Compliance_Check","Decision","Notify"), 90),
        (("Receive","Risk_Screen","Queue_Routed","Standard_Review","Supervisor_Sign-off","Decision","Notify"), 60),
        (("Receive","Risk_Screen","Queue_Routed","Standard_Review","Notify","Decision"), 45),
        (("Receive","Risk_Screen","Queue_Routed","Enhanced_Review","Decision","Notify"), 30),
        (("Receive","Risk_Screen","Queue_Routed","Manual_Override","Standard_Review","Decision","Notify"), 35),
    ],
}

def variants_to_log(variant_counts):
    # pm4py.parse_event_log_string expects traces separated by '!'.
    parts = []
    for trace, count in variant_counts:
        parts.extend([" ".join(trace)] * count)
    return pm4py.parse_event_log_string(" ! ".join(parts))

def normalize_log(log, remove_queue=True):
    """Transparent normalization: Risk_Screen->Classify, optionally drop Queue_Routed.
    Works on EventLog-like traces of dict events; adapts key names defensively."""
    out = []
    for trace in log:
        new_trace = []
        for event in trace:
            e = dict(event)
            key = "concept:name" if "concept:name" in e else list(e.keys())[0]
            name = e[key]
            if name == "Queue_Routed" and remove_queue:
                continue
            if name == "Risk_Screen":
                e[key] = "Classify"
            new_trace.append(e)
        out.append(new_trace)
    # Rebuild via string form to keep PM4Py object types consistent.
    strings = []
    for trace in out:
        vals = [(ev.get("concept:name", next(iter(ev.values())))) for ev in trace]
        strings.append(" ".join(vals))
    return pm4py.parse_event_log_string(" ! ".join(strings))

def summarize(name, log, petri_net, im, fm):
    dfg, start, end = pm4py.discover_dfg(log)
    alignments = pm4py.conformance_diagnostics_alignments(log, petri_net, im, fm)
    fitness = pm4py.fitness_alignments(log, petri_net, im, fm)
    try:
        precision = pm4py.precision_alignments(log, petri_net, im, fm)
    except Exception as exc:
        precision = f"not computed: {exc}"
    moves = Counter()
    for al in alignments:
        for move in al.get("alignment", []):
            moves[move] += 1
    print(f"\n{name}")
    print(" DFG top:", Counter(dfg).most_common(8))
    print(" starts:", start, "ends:", end)
    print(" fitness:", fitness)
    print(" precision:", precision)
    print(" common alignment moves:", moves.most_common(10))
    return fitness, precision

normative_tree = pm4py.parse_process_tree(NORMATIVE_STR)
normative_net, normative_im, normative_fm = pm4py.convert_to_petri_net(normative_tree)

candidate_tree = pm4py.parse_process_tree(CANDIDATE_STR)
candidate_net, candidate_im, candidate_fm = pm4py.convert_to_petri_net(candidate_tree)

logs = {k: variants_to_log(v) for k, v in VARIANTS.items()}

for period, log in logs.items():
    summarize(f"{period} RAW vs normative", log, normative_net, normative_im, normative_fm)
    norm = normalize_log(log, remove_queue=True)
    summarize(f"{period} NORMALIZED (label map + Queue_Routed removal) vs normative",
              norm, normative_net, normative_im, normative_fm)

aug_norm = normalize_log(logs["aug_sep"], remove_queue=True)
summarize("aug_sep NORMALIZED vs candidate optional sign-off",
          aug_norm, candidate_net, candidate_im, candidate_fm)

print("\nCAVEATS:")
print("- Supplied data are variant aggregates without timestamps, sequence numbers, "
      "resources, or claim values; exact aggregate alignment numbers need not reproduce.")
print("- Source-sequence ordering, ingestion-lag analysis, and high-value stratification "
      "cannot be performed on this aggregate log and require the original event log.")
print("- The candidate model is control-flow only: allowing optional Supervisor Sign-off "
      "cannot enforce 'required iff claim > EUR 50,000'.")
print("- Such an optional model may overgeneralize: it accepts sign-off for low-value cases "
      "and absence for high-value cases, so higher fitness may coincide with lower precision "
      "and hidden data-rule violations. A data-aware model / rule check is required.")
```

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a stacked measurement and model failure, not a sudden wholesale change in employee behavior. Confidence is high, about 85-90%. In June, the `Classify` to `Risk Screen` relabel made nearly every conforming trace non-fitting until mapped; the gateway's `Queue Routed` then split the same behavior into technical-event variants; and the ETL's use of ingestion time inverted `Decision` and `Notify` in a concentrated variant. The staged evidence is unusually diagnostic: label mapping, technical-event removal, and source-sequence ordering progressively restore June-July fitness from 32% to 89% while cycle time, approvals, and appeals remain essentially flat. In August, a second, distinct mechanism dominates: `Supervisor Sign-off` was really introduced by policy, but the normative tree was never versioned, so compliant execution under the new policy is scored as deviation. That is model obsolescence layered on top of earlier logging defects.

A real compliance problem may nevertheless remain, with materially lower but non-negligible confidence, roughly 35-45% that at least some residual cases are true bypasses. The unresolved signals are the 25 and then 30 Enhanced Review traces without a recorded Compliance Check, and the recurring `Manual Override` traces. Neither has been adjudicated: missing events, routing corrections, and genuine bypass predict similar alignments. Stable outcomes and the absence of reported incidents weaken claims of widespread noncompliance, but detection is admittedly incomplete, and a skipped check need not change approvals or appeals. The July memo is not evidence of an increase.

Immediate actions: IT must freeze and document the event-semantic mapping, certify source-sequence ordering, distinguish technical from business events at extraction, and preserve both source and ingestion timestamps. Process owners must issue a versioned model reflecting the sign-off policy, with its data condition stated explicitly. Compliance must audit all residual no-check cases before drawing personnel conclusions.

What must not be claimed yet: that employees became noncompliant, that the process was unchanged in every respect, that optional sign-off proves the EUR 50,000 rule is satisfied, or that restored fitness alone validates any repair.

## 8. Model-governance recommendation

1. **Model versioning:** Every policy, UI, or workflow change triggers a dated normative-model version, approval, effective period, and conformance runs reported by model version; never silently score a new policy against an old tree.
2. **Event-semantic contracts:** Maintain a governed activity dictionary mapping business activity, UI label, backend code, and log label; label renames require contract tests and a pre-registered remapping before release.
3. **Technical-event policy:** Classify events as business, technical, or system at the source with mandatory `event_type` and source-system fields; technical events are excluded from control-flow conformance by rule, not ad-hoc deletion.
4. **Timestamp provenance:** Preserve source timestamp, ingestion timestamp, and source sequence number for every event; declare the authoritative ordering key per activity and monitor ingestion lag and inversion rates after ETL changes.
5. **Data-aware constraints:** Encode attribute conditions such as Supervisor Sign-off required iff claim value exceeds EUR 50,000 as explicit data rules alongside the control-flow model; report fitness and precision stratified by the relevant attributes.
6. **Post-release validation:** After any UI, gateway, ETL, or policy release, run a validation pack within days—variant/DFG diffs, staged label/technical/order ablations, fitness-precision comparison, missingness checks, and a small manual provenance audit—with sign-off before conformance results are published.
