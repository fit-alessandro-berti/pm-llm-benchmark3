# 1. Executive Verdict
The net is structurally a workflow net: it has a unique source `source`, unique sink `sink`, and every node lies on some source-to-sink path. It should not be expected to be sound. The principal defect is `t_join_waived`: it consumes only `p_waived` and ignores the mandatory analysis token. On the waiver route, `t_authorize` can fire before analysis is done, or analysis can finish and leave `p_analysis_done` stranded. Business consequence: authorization may occur without a completed analysis, and the exact final marking `fm` may not be reached because a leftover analysis token remains.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source` / `sink` | Unique start and end | Correct unique source and sink. | Workflow-net check should not fail for source/sink uniqueness. |
| `t_register` | Register case | `source -> t_register -> p_ready`. | Correct. |
| `t_split` | Start analysis and review in parallel | `p_ready -> t_split -> p_analysis` and `p_review`. | Correct AND-split: two tokens created. |
| Analysis branch | Mandatory analysis | `p_analysis -> t_analyze -> p_analysis_done`. | Correct in isolation, but later not always synchronized on waiver route. |
| Standard review branch | Optional standard review | `p_review -> t_standard_review -> p_review_done`. | Correct for standard path. |
| Waiver branch | Alternative review outcome | `p_review -> t_waive_review -> p_waived`. | Produces waiver token but does not remember analysis completion. |
| `t_join_normal` | Synchronize analysis + standard review | Consumes `p_analysis_done` and `p_review_done`, outputs `p_decision`. | Correct for standard path. |
| `t_join_waived` | Synchronize analysis + waiver | Consumes only `p_waived`, outputs `p_decision`. | Defect: analysis completion is not required. |
| Initial/final markings | `im[source]=1`, `fm[sink]=1` | Correct initial and final places. | Final marking can be contaminated with leftover analysis token on waiver path. |
| Source-to-sink paths | Every node on some path | All nodes are structurally on paths to `sink`. | Structural workflow-net status does not imply behavioral soundness. |

import pm4py
from pm4py.objects.petri_net.obj import Marking

def nonzero_marking(marking):
    return {p.name: marking[p] for p in marking if marking[p] > 0}

def fire_named_transition(net, marking, transition_name):
    enabled = pm4py.get_enabled_transitions(net, marking)
    enabled_by_name = {t.name: t for t in enabled}

    if transition_name not in enabled_by_name:
        raise RuntimeError(
            f"Transition {transition_name} is not enabled. "
            f"Enabled: {sorted(enabled_by_name.keys())}"
        )

    t = enabled_by_name[transition_name]
    new_marking = Marking(marking)

    for arc in t.in_arcs:
        new_marking[arc.source] -= 1
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]

    for arc in t.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + 1

    return new_marking

def run_sequence_safely(net, im, sequence, label):
    print(f"--- {label} ---")
    marking = Marking(im)
    print("0", nonzero_marking(marking),
          "enabled:", sorted(t.name for t in pm4py.get_enabled_transitions(net, marking)))

    for i, t_name in enumerate(sequence, 1):
        try:
            marking = fire_named_transition(net, marking, t_name)
            print(i, t_name, nonzero_marking(marking),
                  "enabled:", sorted(t.name for t in pm4py.get_enabled_transitions(net, marking)))
        except RuntimeError as e:
            print(i, t_name, "BLOCKED:", e)
            break

    return marking

# 7. Repair Trade-Offs and Residual Risks

- **Waiver vs. standard review distinguishability:** Repair A keeps `p_waived` and `p_review_done` separate, so the two outcomes remain distinguishable both by marking and by visible transition labels. Repair C loses the distinct waiver marking and only preserves the visible label.
- **Silent transitions and duplicate behavior:** Repair A keeps `t_join_normal` and `t_join_waived` silent. They can both output to `p_decision`, but the single `p_review` token prevents both review alternatives from being taken in one case. Silent joins may still make path analysis less transparent; visible `t_standard_review` and `t_waive_review` preserve audit labels.
- **Soundness vs. business alignment:** Soundness proves no deadlocks and proper completion, but it does not prove that the waiver policy is legally or procedurally correct. Repair A enforces mandatory analysis on the waiver route, but business rules about who may record a waiver, required evidence, or authorization roles still need separate conformance checks.
- **Positive regression traces:** Register  standard review + analysis  authorize; register  waiver + analysis  authorize; both orders of analysis and waiver before join.
- **Negative regression traces:** Waiver  `t_join_waived`  `t_authorize` before `t_analyze`; final marking with `sink` plus any other token; standard review without analysis; authorization without either review outcome.
- **Detecting accidental analysis bypass:** Use reachability analysis to search for markings where `t_authorize` is enabled while `p_analysis` still has a token, or where `sink` is marked together with `p_analysis`/`p_analysis_done`. In the repaired net, no such marking should be reachable.
