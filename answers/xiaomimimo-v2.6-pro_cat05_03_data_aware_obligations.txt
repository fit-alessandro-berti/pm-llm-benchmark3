# ---- 8. coarse control-flow / DECLARE check ------------------------------
def _positions(trace, act): return [i for i,a in enumerate(trace) if a == act]
def precedence(trace, a, b):      # "a must happen before every b"
    pb = _positions(trace, b)
    if not pb: return None # vacuously satisfied -> no activation
    pa = _positions(trace, a)
    return all(any(i < j for i in pa) for j in pb)
def response(trace, a, b):        # "every a must be followed by b"
    pa = _positions(trace, a)
    if not pa: return None
    pb = _positions(trace, b)
    return all(any(i < j for j in pb) for i in pa)

1. Event stream normalization: sort by (case, time:timestamp, event_index); `ord` = tie-broken total order. All temporal predicates defined on `before(e1,e2)  (ts1,idx1) <lex (ts2,idx2)`.

# 1. Temporal Data Semantics

**1.1 Event stream and total order (R7).** Every case is a sequence of events totally ordered by the lexicographic pair `(time:timestamp, event_index)`. I write `e  e` ("e strictly before e") for `(ts, idx) <lex (ts, idx)`. `event_index` is source-system order within a second and is authoritative; if it were missing or non-authoritative, two events sharing a timestamp would be an *unordered pair* and every obligation depending on their relative order becomes INDETERMINATE (this is exactly the R7 consequence for TX-311's two 16:20:00Z events: `Enhanced_Review` (idx 3) `` `Update_Jurisdiction` (idx 4)).

**1.2 Blanks mean "no update".** Blank attribute cells are *not* writes of null. The state function is an as-of (forward-fill) reconstruction:

> `S(c,e,a)` = value written by the latest event `e` with `e  e` that carries a non-blank `a`; otherwise `UNKNOWN`.

Implementation is `groupby(case).ffill()` on ascending order — a pure forward fill. `bfill`, interpolation, or any group-aggregate (last/mean) would leak future values backward and is prohibited.

**1.3 Never copy the final state backward (R7).** The last row's values are used only as of the last event. TX-302's `Record_Exemption` at 11:00 does **not** make EX-77 "present" at 09:40 in the event stream; likewise `Settlement_Confirmed 150 000` (TX-305, +20 h later) is not the release amount, and TX-303's `HIGH` is not the risk at 10:00, and TX-311's `DE` is not the jurisdiction at 16:20:03. A hypothesis that a later value was already true earlier is permitted only when *evidence* establishes an earlier **effective time**, and it must be labelled as a hypothesis.

**1.4 Four distinct clocks.**

| Clock | Meaning | Example in this log |
|---|---|---|
| Event time (`time:timestamp`) | when the fact occurred / the update took effect | `Update_Amount` 08:20 |
| Effective (valid) time | when the fact is legally in force | EX-77 `effective_from` 09:00 although signed 09:05 |
| Record time | when the system persisted it | `Record_Exemption` 11:00 (outage) |
| Evidence time | when the *proof object* came into existence | qualified signature 09:05 (EX-77); signing-certificate creation 10:30 (EX-88) |

Conformance is computed on **event/effective time**. *Belief* in a past fact is decided on **evidence time**. Record time explains latency and changes nothing about validity: a late record may corroborate an earlier approval (EX-77: documented outage + valid hash + signature 09:05  trigger), whereas a displayed backdated field whose only proof artefact postdates the trigger is not conclusive (EX-88).

**1.5 Material change (a definition the rules presuppose but never give).** For R1 ("after the latest material data change") and R4 I use:

* amount **increase > 20 %** relative to the last known amount  **material** (R4); measured cumulatively against the amount *covered by the latest review*, not step-wise (the step-wise alternative is discussed in §4, TX-306);
* amount **decrease**  **not material** (R4, explicit);
* amount **increase  20 %**  **not material for amount-dependent obligations** (R4). This is the harmonising reading of R1's undefined word "material"; the literal reading ("any write") is flagged in the code and in §4;
* **unknown  known amount**  **not safely classifiable** (R4 last sentence)  treated as material for safety and flagged INDETERMINATE;
* any change to `risk_level`, `jurisdiction`, `customer_type`  **material** (they change the trigger set);
* `Sanctions_List_Update`  **material** (it creates an R3 obligation and changes screening currency);
* `Create_Transaction`  **baseline establishment**, not a "change" (nothing prior exists to change from);
* an `exemption_id` write is a **claim**, not a material change to governing data.

**1.6 Snapshots and burdens.** Each obligation is evaluated at its own trigger event using `S(c, trigger, ·)`. The review-under-test is evaluated against `S(c, review, ·)` to determine what it actually covered (coverage, not mere existence). Triggers use three-valued logic: `TRUE / FALSE / UNKNOWN`. `UNKNOWN` never collapses to "not triggered" (R6). Exemptions are **defeasible and burden-shifting**: the claimant must prove approval existed at the trigger (R5).

**Formal pseudo-logic** (temporal relations are directed: `before(E1,E2)` = *E1 strictly earlier than E2* in `(ts, idx)` order; `leq` = reflexive closure; `F  T` compares wall-clock effective times).

```prolog
% ---------- ordering (R7) ---------------------------------------------------
before(E1,E2) :- case(E1,C), case(E2,C),
                 ( ts(E1) < ts(E2) ; ts(E1)=ts(E2), idx(E1) < idx(E2) ).
leq(E1,E2)    :- before(E1,E2).            leq(E,E) :- event(E).

% ---------- as-of state: blanks are not writes (R6/R7) ----------------------
holds(E,A,V)  :- writes(E,A,V), V \= blank,
                 not exists E2: writes(E2,A,_), before(E,E2), before(E2,E).   % latest <= E
state(E,A,UNKNOWN) :- not exists V: holds(E,A,V).

% ---------- materiality (feeds R1 and R4) -----------------------------------
mat(E) :- writes(E,amount,New), state_before(E,amount,Old), known(Old), New > 1.20*Old.
mat(E) :- writes(E,amount,_),  state_before(E,amount,UNKNOWN).     % not safely classifiable
mat(E) :- writes(E,A,_), A in {risk_level,jurisdiction,customer_type}, changed(E,A).
mat(E) :- sanctions_list_update(E).
not_mat(E) :- writes(E,amount,New), state_before(E,amount,Old), known(Old), New =< Old.        % decrease
not_mat(E) :- writes(E,amount,New), state_before(E,amount,Old), known(Old),
              Old < New, New =< 1.20*Old.                                                       % small increase
last_mat_before(Rel,M) :- mat(M), before(M,Rel),
                          not exists M2: mat(M2), before(M,M2), before(M2,Rel).

% ---------- R1 --------------------------------------------------------------
r1_not(Rel) :- release(Rel), state(Rel,jurisdiction,DE).
r1_not(Rel) :- release(Rel), state(Rel,amount,A), known(A), A < 100000.
r1_yes(Rel) :- release(Rel), state(Rel,jurisdiction,J), J \= DE, state(Rel,amount,A), A >= 100000.
r1_ind(Rel) :- release(Rel), ( state(Rel,amount,UNKNOWN) ; state(Rel,jurisdiction,UNKNOWN) ),
               not r1_not(Rel).                                     % R6: never default
r1_met(Rel) :- r1_yes(Rel), exists ER: enhanced_review(ER), before(ER,Rel),
                          not exists M: mat(M), before(ER,M), before(M,Rel).   % ER after latest material change
r1_met(Rel) :- r1_yes(Rel), exists EX: valid_exemption(EX,Rel,R1).             % defeasible alternative
r1_breach(Rel) :- r1_yes(Rel), not r1_met(Rel), not r1_ind(Rel).

% ---------- R2 (no exemption defence) ---------------------------------------
r2_yes(Rel) :- release(Rel), ( state(Rel,risk_level,HIGH) ; state(Rel,customer_type,PEP) ).
r2_met(Rel) :- r2_yes(Rel), exists ER,CA: enhanced_review(ER), compliance_approve(CA),
                          before(ER,CA), before(CA,Rel).                        % ER  CA  Rel
r2_breach(Rel) :- r2_yes(Rel), not r2_met(Rel).
% standard_review(S) \= enhanced_review(S)          (semantic fact)
% compliance_approve_over_standard_packet(C) does not discharge r2_met/2.

% ---------- R3 --------------------------------------------------------------
r3_yes(Rel) :- release(Rel), state(Rel,jurisdiction,J), list_update(L,J),
               exists S: sanctions_screen(S), before(S,L), before(L,Rel),
               not exists S2: sanctions_screen(S2), before(S,S2), before(S2,L).
r3_met(Rel) :- r3_yes(Rel), list_update(L,_), exists S: sanctions_screen(S), before(L,S), before(S,Rel).
r3_breach(Rel) :- r3_yes(Rel), not r3_met(Rel).

% ---------- R4 ---------------------------------------------------------------
invalidated(Rev) :- review(Rev,_), state(Rev,amount,Old), known(Old),
                    exists Chg: writes(Chg,amount,New), known(New), New > 1.20*Old, before(Rev,Chg).
unclassifiable(Rev) :- review(Rev,_), ( state(Rev,amount,UNKNOWN)
                    ; exists Chg: before(Rev,Chg), writes(Chg,amount,_), state_before(Chg,amount,UNKNOWN) ).
valid(Rev) :- review(Rev,_), not invalidated(Rev), not unclassifiable(Rev).
% decreases and increases =< 20% never invalidate (R4)

% ---------- R5 (defeasible) --------------------------------------------------
valid_exemption(EX,T,R1) :-
    approved_by(EX,Head_Compliance), effective_from(EX,F), F =< T,
    scope(EX,Js,Cs,Max), state(T,jurisdiction,Js), state(T,customer_type,Cs),
    state(T,amount,A), A =< Max,
    expires(EX,X), X > T,
    proven(EX,approval,T).
proven(EX,approval,T) :- proof_artifact(EX,P), artifact_time(P,U), U =< T, integrity_verified(P).
defeats(EX,T)        :- proof_artifact(EX,P), artifact_time(P,U), U > T,          % backdated display
                        not independent_corroboration(EX,T).
supports(EX,approval,T) :- record_time(EX,R), R > T, outage_documented(EX),
                           proven(EX,approval,T).                                % late record = corroboration only

% ---------- R6 ---------------------------------------------------------------
classify(Rel,INDETERMINATE) :- decisive(state(Rel),UNKNOWN), not resolved_by(other_evidence).
```

# 4. Ambiguities and Alternative Readings

**TX-302 (COMPLIANT).** *What would change it:* (a) if one insists that the **documented** ground at 09:40 was the exemption (the release note says so) and that the exemption must be in the register when relied upon, the 11:00 insert becomes a documentation deviation — but R1's control was independently satisfied by the 09:20 ER, so the outcome stays COMPLIANT on the ER path (this is why the case is robustly compliant: it is over-determined). (b) If the ER packet were shown to cover a different amount or customer, the ER would be void and only EX-77 would carry the case  re-labelled **JUSTIFIED_EXCEPTION**. (c) If the outage documentation were false, or the hash/signature chain broken, EX-77's evidence would degrade to "backdated display + late record"  EX-77 unusable, still COMPLIANT via the ER. (d) The alternative literal reading of "material data change" as *any* write would count the release event's own `exemption_id` write (EX-77 at 09:40) as a change after the ER and fail R1; I reject it because an exemption reference is not a change to amount/risk/jurisdiction/customer-type and because terminal values of a release event cannot retroactively invalidate a review.

**TX-305 (INDETERMINATE).** *What would change it:* (a) an immutable release payload, bank instruction, or payment-order file showing amount < 100 000  R1 not triggered  **COMPLIANT**. (b) the same artefacts showing amount  100 000 **and** evidence that the 11:15 ER covered that amount  **COMPLIANT** (the ER post-dates the last material change and no change follows). (c)  100 000 plus evidence that the ER deliberately excluded amount coverage (the review document "has no amount")  **NONCOMPLIANT**. (d) If the settlement amount is shown to be *effective* at release (e.g. the payment order was for 150 000 and the settlement merely echoes it), then the state at release is 150 000; whether the ER still covers it depends on whether the amount was in fact 150 000 throughout (feed outage  no change  review stands) or became 150 000 only at release (an unknownknown transition, which R4 calls unclassifiable). *Alternative reading:* a precautionary reading of R1 ("if 100 000 cannot be excluded, require an ER anyway") yields COMPLIANT — the ER exists — but the ER's amount-less coverage pushes to REVIEW_REQUIRED. The reverse inference is barred by R4's last sentence ("an increase from an unknown amount is not safely classifiable"), which is why settlement-time knowledge cannot be pushed back to release time as a finding of fact.

**TX-310 (NONCOMPLIANT; INDETERMINATE is defensible).** *Fork:* if the burden is on the exemption claimant to prove approval existed at the trigger (my reading of R5's last condition plus "a displayed backdated field alone is not conclusive"), the exemption fails and R1 is breached  NONCOMPLIANT. If one takes "absence of proof of approval is not proof of absence" and accepts that Head_Compliance's oral approval at 08:45 is legally sufficient form, the case is **INDETERMINATE** (or even JUSTIFIED_EXCEPTION on the witness). *What would change it:* (a) a TSA token / HSM key-usage log / signature audit record showing a signing operation at 08:50 — i.e. the 10:30 certificate is a re-issuance or key migration —  **JUSTIFIED_EXCEPTION**; (b) an independent witness, Head_Compliance's own contemporaneous statement, a meeting minute or approval-system entry dated  09:59  INDETERMINATE or JUSTIFIED_EXCEPTION; (c) conversely, key-usage logs proving no signing key existed before 10:30 and no approval artefact of any kind before 10:00  NONCOMPLIANT at High confidence. Note the structural contrast with EX-77: there the late record sits on top of a *pre-trigger* proof artefact and a documented outage; here the proof artefact postdates the trigger and the record delay is unexplained.

**TX-311 (COMPLIANT; NONCOMPLIANT and INDETERMINATE are defensible).** *What would change it:* (a) evidence that the 16:20:00Z DE update is unauthorised, retro-dated, or lacks KYC provenance (it was made by `ops11`, the same actor who created and amount-updated the case, in the same second as the review)  the release-time jurisdiction becomes unestablished  **INDETERMINATE** (R6); if it is in fact US  **NONCOMPLIANT** (R1, with `Enhanced_Review`  material change, so the review is stale and no ER follows the change). (b) If the log adopts effective dating (the jurisdiction is effective from case creation or from the underlying counterparty facts), then the ER at 16:20:03 reviewed a DE case — still COMPLIANT, but the review is void as to the US version that existed 16:00–16:20. (c) If `event_index` were not authoritative, the two 16:20 events are an unordered pair and any obligation depending on their order is INDETERMINATE — precisely R7's stipulated consequence. (d) Whole-trace semantics ("the case was foreign at some point  R1 applies throughout") would make R1 triggered and breached; I reject it because R7 requires the latest known value *at the relevant event*, and the relevant event is the release. The asymmetry to keep in view: the case is compliant only because the change moved the case *out* of the obligation; the same edit pattern moving a case out of an obligation is a recognised control risk.

**TX-306 (COMPLIANT) — the "material data change" reading fork.** Under R4's harmonised materiality (increase  20 % non-material) R1 is satisfied; under the literal reading of R1's wording (any write to governing data is a material change), the `Enhanced_Review` 12:15  `Update_Amount` 12:30 and R1 fails. R2 is unaffected either way — its obligation text has no materiality clause and the CA (12:25) is after the ER (12:25 > 12:15) and before release. *What would change it:* a rule-version record defining "material"; or evidence that the 230 000 write is effective-dated to 12:00 (the customer's original order quantity), in which case no post-review change occurred at all and the case is COMPLIANT under both readings. A secondary gap: R4 speaks only of *reviews*, so it is silent on whether `Compliance_Approve` is amount-scoped; if it is, the same 20 % threshold would keep the approval alive.

**TX-308 (COMPLIANT).** Flips to NONCOMPLIANT if decreases count as "material data changes" (then `Enhanced_Review` 14:20  `Update_Amount` 14:25 fails R1's ordering clause); I follow R4's explicit statement that a decrease does not invalidate a review and treat it as non-material. Also note the boundary conventions that matter: 100 000 exactly **triggers** ("at least"), and the review covered 140 000, i.e. a superset of the released amount — a "coverage superset" argument that would survive even a stricter reading.

**TX-301 (NONCOMPLIANT).** Would flip only if the 125 000 write were shown to have an effective time after the release (e.g. a later contractual amendment) — then the released amount was 80 000, R1 would not trigger, and R4's invalidation would attach to a change the release never carried. It would also flip if `Standard_Review` were in substance enhanced due diligence — excluded by the semantic facts and by the activity taxonomy. Note the note field ("customer increased order") is narrative, not provenance: under the logged data the +56.25 % write stands at 08:20.

**TX-303 (NONCOMPLIANT).** Would become a *logging* deviation rather than a *control* deviation if a `Compliance_Approve` performed in another system before 10:30 were reconciled into the case. It would become NOT_TRIGGERED if the adverse-media `Risk_Reclassify` were reversed with evidence that the hit was a false positive and the reversal effective before release — no such event exists, and R7 forbids using later knowledge backward.

**TX-307 (NONCOMPLIANT).** The permitted alternative interpretation ("a Standard_Review that in substance performed enhanced due diligence, buttressed by a Head_Compliance approval, is substantial compliance") is defensible in principle but weak here: the taxonomy explicitly separates the activities; the CA note ties the approval to a *standard* packet; and the PEP trigger arose at 13:05, five minutes **before** the review, so the reviewer was on notice and the packet's scope was a choice, not an accident. Flips to NOT_TRIGGERED if the PEP classification is shown to be erroneous and effectively reversed before 13:20.

**TX-309 (NONCOMPLIANT).** Almost unflippable: the second increase is >20 % from the reviewed amount under *both* the cumulative and the step-wise reading. It would flip only if the 15:28 amount were effective-dated before the 15:25 review (e.g. the customer's instruction predated the review) — then the ER covered 145 000 and R1 is satisfied. Related general ambiguity: cumulative versus step-wise materiality — two successive 15 % rises (total +32.25 %) void a review under the cumulative reading but not under a naive step-wise one; I use the cumulative reading because R4 measures "an amount increase … after the latest review", i.e. relative to the reviewed amount.

def _known(x):
    return pd.notna(x)


def _s(x):
    return "UNKNOWN" if pd.isna(x) else str(x)


def _f(x):
    return "UNKNOWN" if pd.isna(x) else f"{x:,.0f}"


def approval_evidence(e, trig_ts):
    """R5 evidence test, decided from EVIDENCE TIMES (not from displayed fields)."""
    pat = e["proof_artifact_time"]
    if pd.isna(pat):
        return "NO_PROOF_ARTIFACT"
    if e["proof_integrity"] == "verified" and pat <= trig_ts:
        return "PROVEN_AT_TRIGGER"
    if (pd.notna(e["oral_claim_time"]) and e["oral_claim_time"] <= trig_ts
            and e["witness_independent"] == "yes"):
        return "ORAL_CLAIM_INDEPENDENT (still not conclusive alone)"
    return "NOT_PROVEN_AT_TRIGGER (proof artefact postdates trigger; backdated display not conclusive)"


def check_exemption(ex_id, trig_ts, jur, cust, amt):
    """R5 conjunctive test -> (status, detail, waives)."""
    if pd.isna(ex_id):
        return "NONE", "no exemption claimed", ""
    hit = ex_reg[ex_reg["exemption_id"].eq(ex_id)]
    if hit.empty:
        return "UNKNOWN_ID", f"{ex_id} absent from the register", ""
    e = hit.iloc[0]
    if not (_known(jur) and _known(cust) and _known(amt)):
        return "SCOPE_UNVERIFIABLE", "release state incomplete -> scope match untestable (R6)", e["waives"]
    hc = e["approved_by"] == "Head_Compliance"
    eff = _known(e["effective_from"]) and e["effective_from"] <= trig_ts
    fresh = _known(e["expires"]) and e["expires"] >= trig_ts
    scope = ((e["scope_jurisdiction"] == jur) and (e["scope_customer_type"] == cust)
             and (amt <= e["scope_amount_max"]))
    ev = approval_evidence(e, trig_ts)
    detail = (f"approved_by_HC={hc}; effective_from {e['effective_from']} <= trigger {trig_ts} = {eff}; "
              f"scope(jur/cust/amount)={scope}; unexpired={fresh}; evidence={ev}; "
              f"displayed_approval={e['displayed_approval']}; proof_artefact={e['proof_artifact']} "
              f"@{e['proof_artifact_time']} (integrity={e['proof_integrity']}); record={e['record_time']} "
              f"(delay_explained={e['record_delay_explained']}, outage={e['outage_documented']}); "
              f"oral_claim={e['oral_claim_time']} by {e['oral_claim_witness_role']} "
              f"(independent={e['witness_independent']})")
    if not (hc and eff and fresh and scope):
        return "INVALID_FORMAL_SCOPE", detail, e["waives"]
    return ("VALID_AT_TRIGGER" if ev == "PROVEN_AT_TRIGGER" else "NOT_PROVEN_AT_TRIGGER"), detail, e["waives"]

def rule_r1(rel, g, ex):
    """Foreign high-value enhanced review (state read as-of the release)."""
    jur, amt = rel["jurisdiction_asof"], rel["amount_asof"]
    rel_ord = rel["ord"]
    if not (_known(jur) and _known(amt)):
        return ("INDETERMINATE",
                "R6: amount/jurisdiction unknown at release -> >=100,000 & non-DE cannot be established or excluded")
    if jur == "DE":
        return ("NOT_TRIGGERED", "jurisdiction = DE at release (as-of semantics, no backward copying)")
    if amt < 100000:
        return ("NOT_TRIGGERED", f"amount {amt:,.0f} < 100,000 at release")
    m_ord = g.loc[g["mat_change"] & (g["ord"] < rel_ord), "ord"].max()
    er = g[(g[ACT] == "Enhanced_Review") & (g["ord"] < rel_ord)]
    ok, why = False, "no Enhanced_Review before release"
    if not er.empty:
        e_ord = er["ord"].max()
        if pd.isna(m_ord) or e_ord > m_ord:
            ok = True
            why = (f"Enhanced_Review ord {int(e_ord)} after the latest material change "
                   f"({int(m_ord) if pd.notna(m_ord) else 'none'}) and before release")
        else:
            why = (f"Enhanced_Review ord {int(e_ord)} PRECEDES the latest material change ord {int(m_ord)} "
                   f"[{g.loc[g['ord'].eq(m_ord), 'mat_change_kind'].iloc[0]}] -> stale review")
    ex_status, ex_detail, waives = ex
    ex_label = "none" if pd.isna(rel["exemption_id"]) else rel["exemption_id"]
    if ok:
        return ("SATISFIED", why)
    if ex_status == "VALID_AT_TRIGGER" and "R1" in waives:
        return ("EXEMPT", f"valid exemption {ex_label} already in force at trigger | {ex_detail}")
    return ("VIOLATION", f"{why} | exemption {ex_label}: {ex_status} | {ex_detail}")


def rule_r2(rel, g):
    """High-risk or PEP approval (no exemption defence)."""
    risk, cust, rel_ord = rel["risk_level_asof"], rel["customer_type_asof"], rel["ord"]
    trig = (risk == "HIGH") or (cust == "PEP")
    if not trig:
        if not (_known(risk) and _known(cust)):
            return ("INDETERMINATE", "R6: risk/customer_type unknown -> HIGH/PEP cannot be excluded")
        return ("NOT_TRIGGERED", f"risk={risk}, customer_type={cust}")
    er = g[(g[ACT] == "Enhanced_Review") & (g["ord"] < rel_ord)]
    ca = g[(g[ACT] == "Compliance_Approve") & (g["ord"] < rel_ord)]
    if er.empty:
        return ("VIOLATION", f"trigger risk={risk}/cust={cust}: Enhanced_Review missing "
                             f"(a Standard_Review is not an Enhanced_Review)")
    if ca.empty:
        return ("VIOLATION", "Enhanced_Review present but Compliance_Approve missing before release")
    if ca["ord"].max() <= er["ord"].max():
        return ("VIOLATION", "Compliance_Approve is not after the relevant Enhanced_Review")
    notes = [n for n in ca["note"].dropna().tolist() if "standard" in n.lower()]
    caveat = f" | CA packet note: {'; '.join(notes)} (standard-only packet does not cure a missing ER)" if notes else ""
    return ("SATISFIED",
            f"Enhanced_Review ord {int(er['ord'].max())} < Compliance_Approve ord {int(ca['ord'].max())} "
            f"< release{caveat}")


def rule_r3(rel, g):
    """Sanctions-list update -> mandatory re-screen."""
    jur, rel_ord = rel["jurisdiction_asof"], rel["ord"]
    if not _known(jur):
        return ("INDETERMINATE", "R6: jurisdiction unknown -> list membership untestable")
    ss = g[(g[ACT] == "Sanctions_Screen") & (g["ord"] < rel_ord)]
    slu = g[(g[ACT] == "Sanctions_List_Update") & (g["ord"] < rel_ord)]
    last_screen = -1 if ss.empty else ss["ord"].max()
    cand = slu[slu["ord"] > last_screen]
    matched = cand[cand["jurisdiction_asof"].eq(jur)]
    if matched.empty:
        if not cand.empty:
            return ("INDETERMINATE",
                    "a list update post-dates the last screen but its jurisdiction scope is not written in the log")
        return ("NOT_TRIGGERED", f"no sanctions-list update for {jur} after the last Sanctions_Screen")
    upd_ord = matched["ord"].max()
    rescreen = g[(g[ACT] == "Sanctions_Screen") & (g["ord"] > upd_ord) & (g["ord"] < rel_ord)]
    if rescreen.empty:
        return ("VIOLATION",
                f"Sanctions_List_Update ord {int(upd_ord)} ({jur}) post-dates the last screen; "
                f"no re-screen between it and release")
    return ("SATISFIED", f"re-screen ord {int(rescreen['ord'].max())} after list update ord {int(upd_ord)}")


def rule_r4(rel, g):
    """Material amount change -> review invalidation (amount-dependent duties)."""
    rel_ord, rel_amt = rel["ord"], rel["amount_asof"]
    rev = g[g[ACT].isin(REVIEWS) & (g["ord"] < rel_ord)]
    if rev.empty:
        return ("NOT_APPLICABLE", "no Standard_/Enhanced_Review before release -> nothing to invalidate")
    last = rev.iloc[-1]
    rev_amt = last["amount_asof"]
    if not (_known(rev_amt) and _known(rel_amt)):
        return ("UNCLASSIFIABLE",
                f"amount unknown at {last[ACT]} (ord {int(last['ord'])}) and/or at release -> "
                f"R4 delta not safely classifiable (R6)")
    ratio = rel_amt / rev_amt
    if ratio > 1.20:
        return ("REVIEW_INVALIDATED",
                f"{last[ACT]} covered {_f(rev_amt)}; release {_f(rel_amt)} -> +{(ratio - 1) * 100:.2f}% > 20% "
                f"(review void for amount-dependent obligations)")
    if ratio > 1.0:
        return ("REVIEW_VALID", f"+{(ratio - 1) * 100:.2f}% since {last[ACT]} <= 20% -> review stands")
    return ("REVIEW_VALID", f"{(ratio - 1) * 100:.2f}% since {last[ACT]} (decrease) -> review stands (R4)")
