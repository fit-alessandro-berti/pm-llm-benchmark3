| Randomization | Stratified block randomization (originals req × legal flag), 1:1 | Isolate treatment from confounders | Blocks of 20 within reviewer pool | Conformance to assigned model |
| Eligible strata | Non-originals, originals, legal | Test mechanism per modifier | Exclude statutory-violation attempts | Stratified waiting times |
| Treatment versions | (a) full/partial parallel per stratum, (b) standard sequential | Estimate effect sizes | Written SOP for each | Overlap interval % |
| Primary outcome | Median waiting before Assessment | Direct mechanism test | Weekly review | Timestamped wait |
| Secondary outcomes | Median/p90 cycle time, rework %, appeal % | Total impact and tail | Stop rules monitor | Trace duration, rework loops |
| Interference controls | Max 2 pilot cases per reviewer per day concurrent | Prevent queue spillover | WIP caps enforced | Resource utilization logs |
| Power / minimum support | 300 cases per arm to detect 4 h median shift (=.05, SD~12) | Adequate sensitivity | Recruit 3 months | Enrollment dashboard |
| Duration | 3 months + 1 month washout analysis | Capture tail and legal loops | Fixed calendar | Monthly p90 trend |
| Stop rules | Rework >22%, appeal >6%, or IT lock causes >20% back-entry | Protect quality | Immediate freeze | Alert thresholds |
| Transportability analysis | Compare effect modifiers (originals, IT, role) subgroups; compare A vs B overlap–wait slope | Test portability | Independent analyst | Causal graph refinement |

The pilot separates mechanism failure from implementation failure by randomizing the control-flow change while holding teams and IT constant. If assigned parallel cases show increased true overlap (measured by reliable timestamps) but no waiting reduction, the mechanism is attenuated by capacity or originals constraints—a mechanism failure. If overlap fails to appear because staff circumvent the lock with back-entry or ignore SOP, the treatment was not delivered—an implementation failure. Stratified outcomes reveal which modifier (originals, legal, role) drives any gap, while secondary rework/appeal signals quality tradeoffs. Process mining confirms conformance and quantifies the realized partial order versus the intended model.

## 8. PM4Py model-construction code

```python
import pm4py
from pm4py.objects.powl.obj import Transition, StrictPartialOrder, OperatorPOWL

# 1. Site A before and after process trees (PTML-like strings)
pt_before = pm4py.parse_process_tree(
    "->(Register, Identity Check, Document Check, Assessment, X(Approve, Reject), Notify)")
pt_after = pm4py.parse_process_tree(
    "->(Register, +(Identity Check, Document Check), Assessment, X(Approve, Reject), Notify)")

# 2. Convert both to accepting Petri nets
net_before, im_before, fm_before = pm4py.convert_to_petri_net(pt_before)
net_after, im_after, fm_after = pm4py.convert_to_petri_net(pt_after)

# 3. Site B candidate POWL model
t_register = Transition(label="Register")
t_identity = Transition(label="Identity Check")
t_originals = Transition(label="Originals Receipt")
t_doc = Transition(label="Document Check")
t_assess = Transition(label="Assessment")
t_legal = Transition(label="Legal Review")
t_supp = Transition(label="Request Supplement")
t_appr = Transition(label="Approve")
t_rej = Transition(label="Reject")
t_notify = Transition(label="Notify")

# Legal review with supplement loop (body: legal, redo: supplement)
legal_loop = OperatorPOWL(OperatorPOWL.LOOP, [t_legal, t_supp])

# Strict partial order for main flow (doc after originals; assessment after both checks)
b_powl = StrictPartialOrder([t_register, t_identity, t_originals, t_doc,
                             t_assess, legal_loop, t_appr, t_rej, t_notify])

# 4. Explicit order edges: Assessment waits for both identity and document verification
edges = [
    (t_register, t_identity),
    (t_register, t_originals),
    (t_originals, t_doc),     # statutory prerequisite for doc when originals required
    (t_identity, t_assess),
    (t_doc, t_assess),        # Assessment waits for Document Check
    (t_assess, legal_loop),
    (legal_loop, t_appr),
    (legal_loop, t_rej),
    (t_appr, t_notify),
    (t_rej, t_notify)
]
for e in edges:
    b_powl.order.add(e)

# 5. Convert POWL to accepting Petri net
net_b, im_b, fm_b = pm4py.convert_to_petri_net(b_powl)

# 6. Workflow-net / soundness checks
print("A before WF:", pm4py.check_is_workflow_net(net_before))
print("A after WF:", pm4py.check_is_workflow_net(net_after))
print("B candidate WF:", pm4py.check_is_workflow_net(net_b))
try:
    print("B soundness:", pm4py.check_soundness(net_b))
except Exception as ex:
    print("Soundness check not applicable:", ex)

# 7. Playout sample traces
for i, trace in enumerate(pm4py.play_out(net_b, num_traces=5)):
    print("Trace", i, [ev["concept:name"] for ev in trace])
```

## 9. Recommendation

`conditional go`

We recommend a conditional go: Site B should adopt a segmented, statutory-compliant version of Site A’s parallelization rather than copying the intervention wholesale. What should be transferred is the partial-order principle of starting Identity Check immediately and, where legally permissible, Document Check concurrently after Register. For the 38% of cases without required originals, full parallel verification is feasible and closely mirrors Site A’s mechanism. For the 62% originals-required cases, Identity Check should run concurrently with Originals Receipt, and Document Check should commence upon receipt; this captures part of the overlap benefit without violating legislation.

What should not be copied: the assumption of cross-trained reviewers, the unrestricted full parallelization for all cases, the co-interventions (API upgrade, added FTE, marketing mix shift, huddles) that confounded Site A’s results, and any removal of legal review ordering. Site B’s separate roles and legacy case lock must be respected via explicit task placeholders and real-time logging.

The first subgroup to enter should be non-originals (digital-style) cases, because they offer the highest fidelity to Site A’s precondition and lowest statutory risk.

Expected benefits: median waiting before Assessment could fall 4–8 h for that subgroup, translating to a 2–4 h overall median cycle reduction. Risks include IT-lock preventing true overlap, assessment bottleneck shifting the tail upward, and rework increasing if documents are checked before legal guidance.

Expansion triggers: pilot shows 4 h median waiting reduction with reliable overlap >50% and rework 18%. Modification triggers: tail (p90) worsens >10% or rework >22%. Abandonment triggers: IT lock yields overlap <15% or appeal rate rises above 6%.

## 10. Assumption register

1. Originals requirement truly blocks Document Check start for 62% of cases — why needed: determines eligible parallel share — how to test: legal audit + process mining of receipt-to-doc start — consequence if false: broader parallel possible and effect larger.

2. Site B IT lock cannot be circumvented without upgrade — why needed: true simultaneous task ownership — how to test: pilot workaround with placeholder tasks — consequence if false: easier transfer and higher overlap.

3. Identity and document checks use sufficiently independent data at B — why needed: parallelism reduces time rather than causes rework — how to test: data-dependency audit — consequence if false: parallel may increase rework and fail.

4. Capacity pools can absorb concurrent task creation without saturation — why needed: avoid bottleneck shift — how to test: discrete-event simulation of pilot volumes — consequence if false: tail worsens despite median gain.

5. Legal review frequency and supplement loop remain as baseline (40%, 360 supplements) — why needed: estimate tail impact — how to test: baseline rate monitoring — consequence if false: rework estimates invalid.

6. Timestamp back-entry can be eliminated in pilot — why needed: measure true overlap — how to test: logging compliance audit — consequence if false: no reliable causal measurement.

7. Case mix remains stable during pilot (no A-style marketing shift) — why needed: avoid confounded gains — how to test: weekly complexity tracking — consequence if false: effect overestimated.

8. Reduction in waiting before Assessment translates proportionally to cycle time — why needed: outcome projection — how to test: pilot median wait vs median cycle correlation — consequence if false: cycle-time benefit decoupled by legal/assessment delay.
