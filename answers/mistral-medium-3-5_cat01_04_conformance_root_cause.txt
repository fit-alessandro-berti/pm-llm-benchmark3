## 8. Model-governance recommendation

1. **Model versioning**: Tie normative models to policy versions with semantic versioning (e.g., `v1.0` for pre-August, `v2.0` post-policy change). Store models in a version-controlled repository with change logs.
2. **Event-semantic contracts**: Maintain a data dictionary linking UI labels to normative activities (e.g., `Risk Screen` = `Classify`). Require impact assessments for any UI label change.
3. **Technical-event policy**: Explicitly classify events as *business* (e.g., `Receive`) or *technical* (e.g., `Queue Routed`). Exclude technical events from conformance checks by default.
4. **Timestamp provenance**: Mandate that event logs include *source-system timestamps* and *ingestion timestamps*, with clear documentation of which is authoritative for ordering.
5. **Data-aware constraints**: Extend normative models to include critical case attributes (e.g., claim value) where they affect control flow (e.g., `Supervisor Sign-off` for >EUR 50,000).
6. **Post-release validation**: After any UI, policy, or ETL change, run a *delta conformance check* comparing pre- and post-change logs with both the old and new normative models. Flag unexplained fitness drops for investigation.
