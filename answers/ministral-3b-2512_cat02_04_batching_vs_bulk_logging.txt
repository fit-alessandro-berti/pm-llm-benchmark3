# 5. Robustness and alternative explanations

### **Resource IDs**
- **Trusted as unique**: G1-G4, G8 show sequential/overlapping patterns; G5-G7 are excluded due to shared accounts.
- **Treated as shared**: G5-G7 would appear as concurrent if `analyst_pool`/`T-F`/`T-G` are pooled; G1-G4 would show inflated utilization.

### **Timestamp Precision**
- **Exact timestamps**: G1-G4, G8 show clear patterns; G6-G7 would require rounding adjustments.
- **Interval-censored**: G6-G7 would appear as concurrent if precision is ignored; G1-G4 would show batching artifacts.

### **Same Patterns, Multiple Explanations**
1. **G1/G4 (Sequential Batching vs. Shared Setup)**:
   - `start` identical across records suggests shared setup; `queue_arrival` alignment suggests sequential processing.
2. **G2/G3 (End Batching vs. Concurrent Work)**:
   - `complete` identical suggests bulk submission; `start` identical suggests multitasking.
3. **G7 (Timestamp Coarsening vs. Sequential Batching)**:
   - Rounded timestamps could mask sequential processing; `start` identical suggests shared setup.

# 6. Data-collection redesign

1. **Execution Timestamps**: Add `pause/resume` events to track multitasking; use higher precision (e.g., 100ms) for critical clusters.
2. **Recording Timestamps**: Distinguish `recorded_at` from `queue_arrival`; add metadata for source clock drift.
3. **Resource Identity**: Retain badge-level identity for shared accounts; tag workstations by capacity (e.g., RBT-7’s 4-item limit).
4. **Group/Batch Identifiers**: Add `batch_id` or `group_id` to track operational batches; link to queue rules.
5. **Workstation Capacity**: Document machine limits (e.g., RBT-7’s 4-item fixture); correlate with `queue_arrival` spikes.
6. **Pause/Resume Events**: Log manual interruptions (e.g., breaks, tool changes); align with `start`/`complete` gaps.
7. **Timestamp Precision Metadata**: Tag timestamps by source granularity; document rounding rules (e.g., legacy MES).
