## 1. Control-Objective Decomposition

FEP-1 exists to prevent a single human actor from both initiating and authorizing a payment. The underlying objectives and threat scenarios are broader than “two different user IDs touched the case.” The table below decomposes the objective and maps each compensating control’s real effect.

| # | Objective / threat scenario | AV-2 | MG-4 | RA-7 | ED-1 | Notes |
|---|---|---|---|---|---|---|
| 1 | Single operator mistakenly pays wrong amount, duplicate, or exceeds limit | **Prevent** (duplicate, limit, PO match) | **Prevent** if independent review before settlement | **Detect** after fact | **Scopes** AV-2 + MG-4 as substitutes | AV-2 does not judge commercial intent |
| 2 | Payment routed to wrong / attacker-controlled bank account (incl. recent bank change) | **Prevent** (ownership + 7-day change check) unless unavailable or overridden | **Prevent** if manager inspects bank details | **Detect** post-settlement only | **Requires** no bank change in 7 days | AV-2 warning can be overridden by same user |
| 3 | Fraudulent or related-party vendor authorized by same user | **Partial prevent** (sanctions, ownership) but not intent | **Prevent/Detect** only if manager independent and conflict-free | **Detect** late; **Correct** only inside recall window | **Requires** independent L3+ manager | Conflict-of-interest manager fails objective |
| 4 | Collusion or captive pairing of two humans defeats independent judgment | **Fail** (does not assess human independence) | **Weak** if rubber-stamped or repeated pair | **Detect** only if audit samples case | **Not addressed** | Distinct IDs do not guarantee independence |
| 5 | Payment released without goods/services receipt (commercial reasonableness) | **Fail** (explicitly out of scope) | **Prevent** only if manager reviews receipt | **Detect** via audit | **Not addressed** | Fabricated receipt can pass AV-2 |
| 6 | Emergency used as pretext to bypass four-eyes without real necessity | **Fail** alone | **Prevent** if manager challenges emergency | **Detect** if audit tests token timing | **Gate** (token before prepare, amount, vendor age, etc.) | Late or missing token breaks permission |

## 2. Equivalence and Sufficiency Test

A compensating package is judged against the **control objective**, not merely against the letter of FEP-1.

### Tiers

| Tier | Conditions (all relevant must hold) | Interpretation |
|---|---|---|
| **Fully equivalent** | Independent manager (L3+, conflict-free) authorizes **before irrevocable settlement**; AV-2 fully operational and passed without self-override; evidence of manager review of invoice/bank/receipt; audit within recall window if same-user; no repeated-pair or workstation red flag; emergency only if ED-1 preconditions met | Objective met despite nominal violation |
| **Partially equivalent** | Core preventive effect present but a secondary condition weak: e.g., manager approves after release but before settlement; minor ED-1 paperwork gap; low amount/low-risk vendor; AV-2 passed but receipt not reviewed | Technically nonconforming but often tolerable |
| **Merely mitigating** | Only detective or after-settlement controls: manager ratifies after settlement; audit outside recall window; AV-2 warning overridden by same user; conflicted manager | Loss likelihood reduced but not objective |
| **Ineffective** | Same user, no independent pre-settlement authorization, AV bypassed/unavailable, audit late, high exposure, no recoverability | Objective failed |

### Required dimensions
- **Timing:** authorization must be before settlement to be preventive; after settlement it is only detective/corrective-late.
- **Independence:** not preparer/releaser, not direct supervisor, not repeated captive pair.
- **Coverage:** AV-2 checks are narrow; absence of goods-receipt check must be covered by manager.
- **Overrideability:** self-override of AV-2 warnings by the same user is not independent.
- **Recoverability:** within 24h recall window vs irrevocable settlement.
- **Evidence quality:** signed manager review, token logs, audit workpapers.
- **Collusion resistance:** repeated resource pairs and shared workstations reduce assurance even with two IDs.

### Why “same expected loss” is insufficient
Expected loss is one input, but the control objective also serves **deterrence**, **auditability**, **legal defensibility**, and **recoverability**. A low-amount case may have the same expected loss as a well-controlled high-amount case, yet the former may still violate governance because it normalizes single-operator behavior. Conversely, a distinct-user case with captive pairing may have low immediate loss but high latent control risk.

## 6. Evidence and Monitoring Recommendations

**Monitoring rules (generate alerts, not conclusions):**
- **Same-user rate:** Percentage of completed payments where `Prepare_Payment.resource == Release_Payment.resource`. Alert if >X% (e.g., >2%) or any case >EUR 100k.
- **Override rate:** Count of `Override_Warning` by preparer/releaser vs independent manager. Alert on any self-override of bank-change/limit warning.
- **Late manager approval:** `Manager_Approve/Ratify` timestamp after `Release_Payment` but before `Bank_Settlement` = hybrid; after settlement = alert.
- **Audit-before-recall-window:** Any `Audit_Review` >24h after release or >1 business day for emergency same-user. Alert.
- **Repeated resource pairs:** Rolling count of (uX,uY) pairs appearing together >N times in 30 days (u12/u13 pattern). Alert for review of cell design.
- **Shared workstations:** Correlation of prepare/release events from same device ID or same session. Alert; does not prove collusion.
- **Bank-change proximity:** Any payment within 7 days of `bank_change` event. Alert, especially if AV-2 only warning.
- **Control outages:** `Validation_Service_Unavailable` or manual checklist unsigned. Alert; block high-risk releases.
- **Emergency token timing:** Token active before `Prepare_Payment`? Alert if token created after prepare.

**Distinguishing alert from proof:** An alert indicates a control-design or behavior pattern requiring review. Proof of misconduct requires documented conflict, credential-sharing admission, or confirmed fraudulent receipt.
