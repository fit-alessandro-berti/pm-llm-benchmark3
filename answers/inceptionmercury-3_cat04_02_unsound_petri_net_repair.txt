# 1. Executive Verdict

The net is structurally a workflow net: one source, one sink, and every node lies on a source-to-sink path. It should not be expected to be sound. The principal defect is that the waiver join (`t_join_waived`) consumes only `p_waived` and produces `p_decision` without waiting for `p_analysis_done`; on any waiver case, `t_authorize` can fire before or after `t_analyze`, and the analysis token is stranded. Business consequence: a case can be authorized before the mandatory analysis is complete, and the process cannot reach the exact final marking, creating compliance risk and improper completion.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source`, `im` | Initial case token | One token at `source`; unique initial marking | None |
| `t_register` | Register case | Consumes `source`, produces `p_ready` | None |
| `t_split` | Start analysis and review in parallel | Produces one token in `p_analysis` and one in `p_review` | None; branches proceed independently |
| `t_analyze` chain | Mandatory analysis | `p_analysis`  `p_analysis_done` | On the waiver path, `p_analysis_done` has no consuming path |
| `t_standard_review` | Standard review outcome | `p_review`  `p_review_done` | Correct if the standard branch is chosen |
| `t_waive_review` | Waiver review outcome | `p_review`  `p_waived` | Creates a waiver token; bypasses `t_join_normal` |
| `t_join_normal` | Synchronize analysis + standard review | Requires `p_analysis_done` and `p_review_done`  `p_decision` | Works only for the standard path |
| `t_join_waived` | Synchronize analysis + waiver | Actually only requires `p_waived`  `p_decision` | Primary defect: authorization can be enabled before analysis is complete |
| `t_authorize`, `sink`, `fm` | Complete the case | Consumes `p_decision`, produces `sink` | A `sink` token can coexist with leftover analysis tokens, so `fm` is not reached |
| Every node | Source-to-sink condition | Structurally, all nodes have a path from `source` to `sink` | WF-net check should pass; unsoundness is behavioral, not structural |

# 3. Marking-Based Counterexample

A legal firing sequence that exposes the defect is:

`t_register`, `t_split`, `t_waive_review`, `t_join_waived`, `t_authorize`, `t_analyze`.

The sequence deliberately fires `t_authorize` before `t_analyze` to show premature authorization.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source: 1}` | `{t_register}` | Initial marking `im` |
| 1 | `t_register` | `{p_ready: 1}` | `{t_split}` | Registration complete |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `{t_analyze, t_standard_review, t_waive_review}` | Parallel branches started |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `{t_analyze, t_join_waived}` | Waiver selected; analysis token still present |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `{t_analyze, t_authorize}` | Waiver join did not require analysis; `t_authorize` and `t_analyze` are both enabled |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `{t_analyze}` | A token exists in `sink`, but this is not the exact final marking `fm` |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | `{}` | Leftover analysis token; no enabled transition can consume it |

A token in `sink` is necessary but not sufficient for `fm`. The final marking `fm` requires exactly one token at `sink` and no tokens elsewhere. After step 5, `p_analysis` remains; after step 6, `p_analysis_done` remains. If the order of steps 5 and 6 is reversed, the final leftover is the same: `{p_analysis_done: 1, sink: 1}`.

The leftover token cannot be consumed because `p_analysis_done` has only one outgoing continuation in the original net, through `t_join_normal`, and `t_join_normal` also requires `p_review_done`. The waiver route never creates `p_review_done`, so `t_join_normal` can never become enabled. Thus the process is stuck with a stranded token.

# 4. Minimal-Repair Alternatives

Edit-cost model: adding or removing an arc costs 1; adding or removing a place or transition costs 2; changing a label costs 1.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| R1: mandatory-analysis waiver join | Add arc `p_analysis_done  t_join_waived` | 1 | Full original business intent: analysis is mandatory on every path; standard/waiver alternatives remain; no remaining tokens | On the waiver path, `t_join_waived` now consumes both `p_analysis_done` and `p_waived`; `t_authorize` is disabled until analysis is complete | `p_analysis_done` is shared by both joins; if a future model allowed both standard review and waiver in the same case, the single analysis token could be consumed by one join and strand the other. In the current exclusive-choice model this cannot happen |
| R2: upfront waiver, analysis absent on waiver path | Remove arc `p_review  t_waive_review`; add arc `p_ready  t_waive_review` | 2 | Standard path remains unchanged; review may still be standard or waiver. Explicit policy change: analysis is no longer mandatory, and is not started, for waiver cases | The waiver decision is made before the parallel split. A waiver trace can be `t_register`, `t_waive_review`, `t_join_waived`, `t_authorize` without `t_analyze` | Deviates from the original “analysis always mandatory” business rule; the waiver is recorded earlier, before analysis has begun, so it is not a waiver chosen after a review was started |

R1 and R2 are behaviorally distinct: in R1 every complete case executes `t_analyze`, while in R2 complete waiver cases can authorize without ever executing `t_analyze`.

Minimality: R1 is minimal for preserving mandatory analysis because the original defect is exactly one missing precondition from the analysis branch to the waiver join. One added arc is necessary and sufficient; removing an arc cannot add the missing dependency, and adding a place or transition would cost more. R2 is minimal for its stated policy change because `t_waive_review` must be detached from `p_review`, which exists only after `t_split` has started analysis, and attached to `p_ready` before the split; that requires one arc removal and one arc addition. No single-arc edit can achieve that policy change. The two repairs are not tied in cost: R1 costs 1, R2 costs 2.

# 5. Corrected PM4Py Code

The code below implements R1.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_fixed")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in {
    source, p_ready, p_analysis, p_review,
    p_analysis_done, p_review_done, p_waived, p_decision, sink
}:
    repaired_net.places.add(p)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in {
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
}:
    repaired_net.transitions.add(t)

petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

# Repair R1: the waiver join now also waits for the mandatory analysis.
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

def fire_named(net, marking, transition_name):
    matching = [t for t in net.transitions if t.name == transition_name]
    if len(matching) != 1:
        raise ValueError(f"Transition {transition_name!r} not uniquely found")

    t = matching[0]
    if t not in pm4py.get_enabled_transitions(net, marking):
        raise ValueError(
            f"{transition_name} is not enabled in "
            f"{ {p.name: c for p, c in marking.items()} }"
        )

    new = Marking()
    for p, c in marking.items():
        new[p] = c

    for arc in t.in_arcs:
        new[arc.source] -= 1
        if new[arc.source] == 0:
            del new[arc.source]

    for arc in t.out_arcs:
        new[arc.target] = new.get(arc.target, 0) + 1

    return new

def print_marking(label, marking):
    print(label, {p.name: c for p, c in marking.items()})

# Diagnostics on both nets.
nets = [
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
]

for name, n, init, final in nets:
    print(f"\n=== {name} ===")
    print("workflow_net:", pm4py.check_is_workflow_net(n))
    pm4py.check_soundness(n, init, final, print_diagnostics=True)

    m = Marking()
    for p, c in init.items():
        m[p] = c

    print("enabled_at_im:", sorted(t.name for t in pm4py.get_enabled_transitions(n, m)))
    graph = pm4py.convert_to_reachability_graph(n, init, final)
    print("reachability_graph_type:", type(graph).__name__)

# Original counterexample.
print("\nOriginal counterexample:")
m = Marking()
for p, c in im.items():
    m[p] = c

for tname in [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_join_waived",
    "t_authorize",
    "t_analyze",
]:
    m = fire_named(net, m, tname)
    print_marking(tname, m)

# Repaired counterpart: analysis is forced before authorization on the waiver path.
print("\nRepaired waiver trace:")
m = Marking()
for p, c in repaired_im.items():
    m[p] = c

for tname in [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_analyze",
    "t_join_waived",
    "t_authorize",
]:
    m = fire_named(repaired_net, m, tname)
    print_marking(tname, m)
```

Expected qualitative difference: both nets should pass the workflow-net check. The original net should fail soundness, while the repaired net should pass. The original reachability graph contains a terminal marking with `sink` plus a stranded analysis token; the repaired graph’s terminal marking is exactly `sink`. At the critical waiver state, the enabled transitions differ: after `t_join_waived`, the original has `{t_analyze, t_authorize}`, while the repaired net has only `{t_analyze}` until analysis completes, and `t_authorize` becomes enabled only after `t_join_waived` fires.

# 7. Repair Trade-Offs and Residual Risks

- **Waiver vs standard review distinction:** R1 preserves the visible labels `Perform Standard Review` and `Record Review Waiver`. The joining transitions are silent, so the log shows which review label was chosen, but not which silent join consumed the analysis token. R2 also keeps the labels, but the waiver label moves earlier, before any analysis is started.
- **Silent transitions and duplicate behavior:** `t_split`, `t_join_normal`, and `t_join_waived` are silent. R1 does not introduce duplicate visible behavior because the review choice remains visible. However, the silent joins can make the exact synchronization point invisible in event logs. R2 changes the choice point but does not add new silent duplication.
- **Soundness vs business alignment:** Soundness guarantees the option to complete properly and no leftover tokens. It does not prove that every authorization is preceded by mandatory analysis. R1 is sound and also satisfies the business rule. R2 can be sound while intentionally violating the original mandatory-analysis policy.
- **Regression-test positive traces:**
  - `t_register`, `t_split`, `t_analyze`, `t_standard_review`, `t_join_normal`, `t_authorize`
  - `t_register`, `t_split`, `t_analyze`, `t_waive_review`, `t_join_waived`, `t_authorize`
  - `t_register`, `t_split`, `t_waive_review`, `t_analyze`, `t_join_waived`, `t_authorize`
  - If R2 is accepted, also `t_register`, `t_waive_review`, `t_join_waived`, `t_authorize`
- **Regression-test negative traces:**
  - `t_register`, `t_split`, `t_waive_review`, `t_authorize` — missing analysis, must be impossible in R1
  - `t_register`, `t_split`, `t_authorize` — missing review outcome
  - `t_register`, `t_split`, `t_analyze`, `t_standard_review`, `t_waive_review` — both review outcomes in one case, must be impossible
  - Any sequence that leaves `p_analysis` or `p_analysis_done` after `sink` receives a token
- **Detecting accidental bypass of mandatory analysis:** In R1, scan reachable markings and assert that whenever `p_decision > 0`, the marking has neither `p_analysis` nor `p_analysis_done`. In event logs, require every complete trace ending with `Authorize Case` to contain `Perform Analysis` and exactly one review label. The helper above can be used to step the net and check enabledness before every transition, so a premature `t_authorize` fails immediately.

# 8. Final Recommendation

I recommend deploying R1. It is a one-arc repair, preserves the original business intent, keeps analysis mandatory on every path, and directly removes premature authorization. Its cost is minimal, and its risk is localized to the waiver join.

R2 is the fallback if the business explicitly accepts a policy change making analysis optional or absent for waiver cases. R2 is structurally minimal for that policy change, but it changes compliance semantics and should require explicit sign-off. If mandatory analysis is non-negotiable, R2 should not be used.
