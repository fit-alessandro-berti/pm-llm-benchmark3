## 6. Candidate Site B intervention

Modified, segmented intervention — do not copy Site A verbatim.

- eligibility rules: Only cases with `digital_documents=true AND originals_required=false AND legal_review_required=false AND complexity=low/standard` enter Phase-1 parallel arm. Originals-required or legal-required or high-complexity remain sequential/default until evidence to expand. Eligibility computed at Register from checklist + document-channel flag.
- which tasks may be created/executed concurrently: For eligible: after Register, system creates both Identity Check and Document Check simultaneously; both may be executed concurrently by respective roles. For originals-required but non-legal: after Register, create Identity Check + Originals Receipt wait in parallel; Document Check creation blocked until Originals Receipt complete. Never create Document Check before Originals Receipt when legally required.
- statutory prerequisites that remain mandatory: Register first; Originals Receipt -> Document Check when required; Identity + Document complete -> Assessment; Assessment -> Legal Review when public/high-value; Legal may trigger Request Supplement -> repeat Document Check + Assessment; Approve/Reject -> Notify. No bypass.
- queue and WIP controls: Per-pool WIP caps (e.g., identity 6/reviewer, document 6, assessment 4, legal 3, adapted to 4/7/3/2 pools); pull for Assessment/Legal; daily 15-min huddles per pool (tested as separate factor); SLA prioritization for legal/originals-aged cases to protect tail.
- resource responsibilities: Keep separate roles; identity reviewers own Identity, document reviewers own Document, assessors own Assessment, legal owns Legal Review. No cross-pool execution except trained backup when queue > threshold. Handoff checklist signed before Assessment.
- handling of legal-review and supplement loops: Legal branch decided post-Assessment by rule; if Request Supplement, case returns to Document Check (with Originals re-check if needed) then Assessment then Legal; loop counted; cap repeats at 2 before senior review; Legal WIP reservation prevents starvation.
- logging requirements: System-enforced creation/start/complete timestamps, owner IDs, Originals Receipt scan, eligibility flag, WIP at creation, workaround prohibited; back-entry flagged; weekly conformance + overlap audit; negative-control process (e.g., Notify latency) tracked.

POWL-style description:

```text
Top = StrictPartialOrder( Register < Verification < Assessment < PostAssessment < Decision < Notify )
Verification = StrictPartialOrder( nodes = { IdentityCheck, DocBranch }, no edge between them (parallel) )
DocBranch = XOR( DigitalDocCheck, OriginalsThenCheck )
  DigitalDocCheck = Transition(DocumentCheck)  // only if originals_required=false
  OriginalsThenCheck = StrictPartialOrder( OriginalsReceipt < DocumentCheck )
PostAssessment = XOR( DirectDecision, LegalLoop )
  DirectDecision = Silent  // Assessment -> Decision
  LegalLoop = LOOP( do = StrictPartialOrder( LegalReview < XOR( Exit, SupplementPath ) ),
                    redo = StrictPartialOrder( RequestSupplement < DocumentCheck < Assessment < LegalReview ) )
Decision = XOR( Approve, Reject )
Constraints: Assessment waits for BOTH IdentityCheck AND DocumentCheck;
  DocumentCheck waits for OriginalsReceipt when required;
  LegalReview waits for Assessment; Supplement waits for LegalReview.
```

Partial-order relations: Register < IdentityCheck; Register < OriginalsReceipt; OriginalsReceipt < DocumentCheck (if required); IdentityCheck || OriginalsReceipt; IdentityCheck || DocumentCheck only if digital (else IdentityCheck < DocumentCheck via Originals); {IdentityCheck, DocumentCheck} < Assessment < {LegalReview?} < {Approve xor Reject} < Notify; RequestSupplement < DocumentCheck < Assessment (loop).

Pilot separates mechanism failure from implementation failure by randomizing assignment while independently measuring fidelity: intention-to-treat captures policy effect, true interval overlap captures mechanism dose, and IT/role logs capture delivery. If assignment does not raise true overlap (lock still binds, Document created but not started, back-entry flagged), null waiting/cycle effects indicate implementation failure, not disproof of parallelization. If true overlap rises to 60-70% yet waiting before Assessment does not fall, or falls but cycle/p90 does not improve due to assessor/legal queues, that indicates mechanism/bottleneck failure. Factorial huddles and negative-control process further separate queue-discipline effects and secular trends from overlap effects.

## 8. PM4Py model-construction code

```python
# Self-contained PM4Py model construction: Site A before/after + Site B candidate (POWL)
# Requires: pip install pm4py
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, Operator

# --- 1. Site A process trees via parse_process_tree ---
# Manual: pm4py.parse_process_tree("->('A','B')", "+", "X" operators)
tree_before_str = "->('Register','Identity Check','Document Check','Assessment',X('Approve','Reject'),'Notify')"
tree_after_str = "->('Register',+('Identity Check','Document Check'),'Assessment',X('Approve','Reject'),'Notify')"

tree_A_before = pm4py.parse_process_tree(tree_before_str)
tree_A_after = pm4py.parse_process_tree(tree_after_str)
print(tree_A_before)
print(tree_A_after)

# --- 2. Convert both to accepting Petri nets ---
net_b_before, im_b_before, fm_b_before = pm4py.convert_to_petri_net(tree_A_before)
net_b_after, im_b_after, fm_b_after = pm4py.convert_to_petri_net(tree_A_after)
print("A-before Petri net:", len(net_b_before.places), "places,", len(net_b_before.transitions), "transitions")
print("A-after Petri net:", len(net_b_after.places), "places,", len(net_b_after.transitions), "transitions")

# --- 3. Site B candidate as POWL with partial order + legal/supplement loop ---
# Nodes
t_register = Transition(label="Register")
t_identity = Transition(label="Identity Check")
t_originals = Transition(label="Originals Receipt")
t_document = Transition(label="Document Check")
t_assess = Transition(label="Assessment")
t_legal = Transition(label="Legal Review")
t_supplement = Transition(label="Request Supplement")
t_approve = Transition(label="Approve")
t_reject = Transition(label="Reject")
t_notify = Transition(label="Notify")

# Document branch: XOR(direct Document [digital], Originals -> Document [originals required])
# Originals-then-check sub-order
doc_seq = StrictPartialOrder(nodes=[t_originals, t_document])
doc_seq.order.add_edge(t_originals, t_document)

doc_branch = OperatorPOWL(operator=Operator.XOR, children=[t_document, doc_seq])

# Verification: Identity parallel with DocBranch (no edge between them)
# Assessment must wait for BOTH -> enforced by outer order edges into Assessment
verification = StrictPartialOrder(nodes=[t_identity, doc_branch])
# NOTE: no edge added here => concurrent

# Decision: Approve xor Reject
decision = OperatorPOWL(operator=Operator.XOR, children=[t_approve, t_reject])

# Legal loop: LOOP(do=Legal Review, redo=Request Supplement -> Document -> Assessment -> Legal)
# Simplified redo as partial order Supplement < Document < Assessment (return to Legal via loop)
redo = StrictPartialOrder(nodes=[t_supplement, t_document, t_assess])
redo.order.add_edge(t_supplement, t_document)
redo.order.add_edge(t_document, t_assess)

legal_loop = OperatorPOWL(operator=Operator.LOOP, children=[t_legal, redo])

# Post-assessment: XOR(skip legal [direct], legal loop) — data-dependent in reality
post_assess = OperatorPOWL(operator=Operator.XOR, children=[legal_loop, None])  # None ~ silent skip
# To avoid None issues in some versions, use silent transition instead if needed:
try:
    # rebuild with explicit silent if None unsupported
    from pm4py.objects.powl.obj import SilentTransition
    post_assess = OperatorPOWL(operator=Operator.XOR, children=[legal_loop, SilentTransition()])
except Exception:
    pass

# Top-level strict partial order
top = StrictPartialOrder(nodes=[t_register, verification, t_assess, post_assess, decision, t_notify])
top.order.add_edge(t_register, verification)
top.order.add_edge(verification, t_assess)  # Assessment waits for both Identity and Document branches
top.order.add_edge(t_assess, post_assess)
top.order.add_edge(post_assess, decision)
top.order.add_edge(decision, t_notify)

siteB_powl = top

# --- 5. Convert POWL to accepting Petri net ---
net_B, im_B, fm_B = pm4py.convert_to_petri_net(siteB_powl)
print("B POWL Petri net:", len(net_B.places), "places,", len(net_B.transitions), "transitions")

# --- 6. Workflow-net / soundness checks ---
for name, net, im, fm in [("A-before", net_b_before, im_b_before, fm_b_before),
                          ("A-after", net_b_after, im_b_after, fm_b_after),
                          ("B-candidate", net_B, im_B, fm_B)]:
    try:
        is_wf = pm4py.check_is_workflow_net(net, im, fm)
        print(name, "is_workflow_net:", is_wf)
    except Exception as e:
        print(name, "workflow check failed:", e)
    try:
        sound = pm4py.check_soundness(net, im, fm)
        print(name, "soundness:", sound)
    except Exception as e:
        print(name, "soundness check failed:", e)

# --- 7. Optional playout + sample traces ---
try:
    logs = pm4py.play_out(siteB_powl, no_traces=5)
    for i, trace in enumerate(logs):
        print(f"trace {i}:", [ev["concept:name"] for ev in trace])
except Exception as e:
    print("playout failed (version-dependent):", e)

# --- 8. What the model CANNOT encode ---
# - Data-dependent guards: originals_required (62%) and legal_review_required (40%) are
#   instance-level rules; POWL XOR is non-deterministic, not conditioned on case attributes.
# - Resource capacity: 4/7/3/2 pools, cross-training limits, WIP=6, huddles, queueing delays,
#   assessor/legal bottlenecks and highly variable 18h Originals delay need simulation, not control-flow.
# - Case locks: single-owner IT constraint that blocks true concurrency is not a Petri-net place;
#   workaround back-entry also corrupts timestamps used for overlap measurement.
# - Durations/tails: service (3.4h/8.1h), waiting (20h), p90=110h, rework/supplement probabilities
#   and appeal outcomes require performance/data simulation and causal estimation, not soundness.
```

## 9. Recommendation

`conditional go`

What should be transferred is the mechanism, not the headline number or the verbatim rule. Site A plausibly shows that when both verifications are legally startable, independently sourced, and jointly ownable, creating them together can reduce waiting before Assessment. That waiting-reduction logic, plus WIP limits and daily huddles with clean timestamping, is worth testing at Site B. What should not be copied is creating Identity Check and Document Check simultaneously for every case immediately after Register, nor the expectation of a nine-hour median or eighteen-hour p90 gain. At Site B that instruction is illegal for 62% of cases requiring originals, overloads three assessors and two legal reviewers covering 40% legal cases with a 26% supplement rate, and is physically blocked by the single-owner lock that keeps measured overlap at 6% and forces back-entry. Unmodified copying risks compliance breach, coordination overhead without true overlap, and a median-tail trade-off where digitals start faster but bunch at Assessment and Legal. The subgroup to enter first is digital-only, non-legal, low/standard complexity cases where Document Check needs no Originals Receipt, roughly one-third of volume and the only stratum structurally similar to Site A. For originals-required cases allow only Identity parallel with Originals waiting, keeping Originals Receipt to Document Check mandatory. Expected benefits in that slice are a two to five hour conditional median and waiting reduction with flat rework if checklists hold, translating to about one to two hours population median and little tail gain. Risks are bottleneck shift to Assessment and Legal, rework rise from specialized handoffs, and measurement illusion from workarounds. Evidence to expand is pre-registered: true overlap reaching sixty percent with waiting falling, no p90 increase beyond five hours, rework within two points, supplement and appeal flat, and lock violations under five percent over ten to fourteen weeks. Trigger to modify is median gain with p90 worsening or Legal queue growth, requiring tighter WIP, added assessor and legal slack, or narrower eligibility. Trigger to abandon is persistent lock blockage, zero waiting effect despite true overlap, or quality and tail deterioration.

## 10. Assumption register

1. assumption — Eligibility flag (digital vs originals-required, legal-required) can be determined reliably at Register — why needed — to enforce statutory Originals->Document and segment parallelization — how to test — audit flag vs later Originals/Legal outcome; conformance — consequence if false — illegal early Document starts and misclassified treatment.
2. assumption — Dual task ownership can be enabled for eligible cases (or workaround banned with alternative logging) — why needed — logical concurrency requires physical concurrency and trustworthy overlap — how to test — IT unlock logs + timestamp audit vs back-entry — consequence if false — IT-lock failure scenario: no true overlap, zero effect.
3. assumption — Identity and Document checks use independent data for digital cases — why needed — parallel execution without blocking or error inflation — how to test — joint-error/rework comparison parallel vs sequential in pilot stratum — consequence if false — rework/supplement rises, gains erased.
4. assumption — Assessor (3) and legal (2) pools have slack or WIP protection during pilot — why needed — prevents upstream gain shifting queue downstream — how to test — utilization, queue length, waiting-before-Assessment/Legal by arm — consequence if false — bottleneck-shift: median improves, p90 worsens.
5. assumption — No concurrent API, staffing, or mix changes during pilot — why needed — Site A was confounded; identification needs stability — how to test — change log + negative-control process stability — consequence if false — before/after bias repeats, transport unlearned.
6. assumption — Originals delay (median 18h, highly variable) is exogenous to parallelization — why needed — bounds savings for 62% to Identity-hiding-inside-wait only — how to test — Originals delay distribution by arm — consequence if false — if staff deprioritize originals chasing, tail extends.

8. assumption — Timestamps measure true execution (not back-entry) after logging discipline — why needed — overlap and waiting are the mechanism readouts — how to test — system creation/start/complete vs file-modification audit + case sampling — consequence if false — false overlap signal, process-mining misleads expansion decision.
