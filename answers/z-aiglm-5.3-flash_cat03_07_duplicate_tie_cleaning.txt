```python
def candidate_groups(sc):
    relsets = sc.relations.groupby(EID)[OID].agg(frozenset)
    out = []
    for (ts, act), g in sc.events.groupby([TS, ACT]):
        if len(g) < 2: continue
        rows = []
        for _, r in g.iterrows():
            rows.append({"eid": r[EID], "src": r[SRC], "skey": r[SKEY],
                         "objs": relsets.get(r[EID], frozenset()),
                         "hash": getattr(r, "payload_hash", "")})
        for a, b in itertools.combinations(rows, 2):
            jac = (len(a["objs"] & b["objs"]) /
                   max(1, len(a["objs"] | b["objs"])))
            kind = ("identical-row" if a["hash"] == b["hash"] and a["src"] == b["src"]
                    else "subset-or-summary" if a["objs"] <= b["objs"] or b["objs"] <= a["objs"]
                    else "cross-system-candidate" if jac > 0.5
                    else "concurrent-distinct")
            out.append({**{"pair": (a["eid"], b["eid"]), "ts": ts, "act": act,
                           "jaccard": round(jac, 2), "kind": kind},
                        "risk_flag": kind == "concurrent-distinct"})
    return pd.DataFrame(out)

def predict_library_drops(sc):            # replica of pm4py grouping predicate

    seen, drops = set(), []
    for eid, k in zip(ev[EID], key):
        (drops.append(eid) if k in seen else seen.add(k))
    return set(drops)
```

```python
def kahn_tie_layers(ids, pairs):
    pred = {i: set() for i in ids}; succ = {i: set() for i in ids}
    for a, b in pairs:
        if a in pred and b in pred:
            succ[a].add(b); pred[b].add(a)
    layer, done = {}, 0
    frontier = [i for i in ids if not pred[i]]
    while frontier:
        nxt = []
        for i in frontier: layer[i] = done
        for i in frontier:
            for s in succ[i]:
                pred[s].discard(i)
                if not pred[s]: nxt.append(s)
        frontier = nxt; done += 1
    leftover = [i for i in ids if i not in layer]     # cycle  escalate/quarantine
    for i in leftover: layer[i] = done
    return layer
```

## 3. Timestamp-tie ordering rules

Cluster events on the **original timestamp**; inside a cluster apply the cascade (first applicable rule separates, lower rules only break remaining ties):

- **P1 – Domain constraints (semantic).** Stated facts: e12e13 (M1), e09e10, {e13,e14}e15, derivation e06e07. Declared, reviewable assumptions: A1 pickspack on shared P1; A2 releaseacceptance; A3 invoice-issuefirst money movement (soft).
- **P2 – Lifecycle constraints on shared objects (semantic).** Applied per object lineage (P1: PickPackRelease; V1: IssueCapturesBalance-update). Restricted to the same object instance to avoid bleeding across P1/M1/M2.
- **P3 – Within-source sequence (semantic intra-source only).** `source_seq` is comparable exclusively between events of the same source (CARRIER 12 confirms e09e10; WMS 100110120; SCANNER 551552). Cross-source comparison is prohibited.
- **P4 – Source-specific semantics / authority (meta-semantic).** When hints conflict, the authoritative system for the object type decides (Carrier owns D-milestones, WMS owns release, PSP owns per-payment chronology).
- **P5 – Ingestion time (merely deterministic).** Penultimate tie-break; explicitly carries no business meaning.
- **P6 – Stable fallback: ascending eid (merely deterministic).** Any such pair is tagged `_tie_class=ARBITRARY-STABLE-FALLBACK`; consumers know the permutation inside the tag is arbitrary.

**Why microseconds-before-semantics encode a false story.** Flattening and DFG mining derive directly-follows and durations from timestamp order. Injecting µs offsets *before* fixing semantic order converts agnostic ties into invented immediate successions whose direction reflects whatever produced the offsets (often ingestion, i.e., integration-path latency). The fiction then propagates into waiting/service times and loop detection, and a later correction cannot distinguish synthesized offsets from recorded facts. Correct sequence: fix order with P1–P6 while keeping `original_timestamp`, expose the order as a separate column (`_order_seq`) and optionally an index-based timedelta clearly marked as synthetic resolution. This deterministic total order is a mining convenience; it does **not** prove the true physical order.

**Intended orders**

- **10:00:** `(e03  e05)`, e06, e07. Picks tie arbitrarily (tagged); A1 puts both before the WMS pack; e07 follows its message origin. Admissible alternative: swapping e03/e05; if A1 were rejected, only e06e07 is enforced plus WMS-internal seq.
- **10:15:** e08, e09, e10. e10-last is certain (fact 5 + carrier seq); e08e09 rests on A2 (admissible alternative: e08/e09 swapped, e10 last) — the tag `_tie_class` marks reliance on an assumption.
- **12:00 after merges (canonical e11):** e11, e12, `(e13  e14)` tagged, e15. e13/e14 interchangeable (distinct partials); without A3, e11/e12 may swap; e15-last is fact 8.

## 4. Conservative cleaning pipeline

Minimum-change design:

1. Deep-copy the raw OCEL; freeze `original_timestamp`, `original_activity`, `source`, `source_event_key` on every row (constraint 10 honored: business timestamps never rewritten).
2. Pre-check candidate groups; print Jaccard/object diagnostics per pair; predict what the library predicate would drop **before** invoking any library function.
3. Split harmonization collisions by refining labels (e07, e08, e09, e15) — this changes no event count.
4. Apply exactly two externally corroborated verified-pair merges: e04e03, e16e11 (audited, attributes coalesced/namespaced, aliases kept).
5. Safety-net `pm4py.ocel_drop_duplicates` over the residual log — after relabeling it is provably a no-op (assertion included), demonstrating the function is safe only once collisions were isolated by inspection.
6. Materialize the P1–P6 total order as `_order_seq`; `ocel_sort_by_additional_column`; only then `ocel_add_index_based_timedelta` for mining-resolution; referential-integrity validation.

Preserves abstraction-level events, both partial payments, both picks, and genuine concurrency (ties retained but classified). Retained event count: **17  2 verified merges = 15 events**, **44  5 = 39 E2O relations** (e04's 3, e16's 2). New ETs added by refinement; eids of untouched events unchanged.

## 5. Aggressive alternatives

**A. Evidence-based semantic merging (reviewer-confirmed).** Starts from conservative; additionally merges e06+e07 after human confirmation that they are two observations of one packaging transition: one `Pack Package` event, ERP fields folded under `erp:` shadows, derivation recorded. Retained: **14 events / 37 relations**. Likely damage: the ERP status milestone stops being individually observable (its timing metric disappears); if the two were actually distinct transitions (partial pack then confirmation), a real step is compressed, and Item-flattened traces lose the subtle WMS-detail stage boundary.

**B. Mechanically aggressive PM4Py merging.** `pm4py.ocel_merge_duplicates` on the raw copy with defaults (activity + timestamp + equal object set) and no inspection: silently fuses e03+e04 (accidentally right, zero audit), e08+e09 (**wrong**: release and acceptance fused — the transport hand-off chain degrades, dwell time becomes unmeasurable, WMS/carrier authority confused), e11+e16 (no conflict policy; authoritative-value provenance lost). Retained: **14 events / 36 relations (8 relation rows cut)**. Even where counts resemble scenario A, semantics and auditability differ fundamentally.

**B (illustrative worst case):** grouping purely on `[activity, timestamp]` yields **10 events / ~28 relations**: e05 destroyed (violates a hard constraint), e13+e14+e15 fused with united objects `{O1,V1,M1,M2}`, so one composite "capture" claims both partial payments, per-payment lifecycles vanish, and `Capture` self-loops/appearances become uninterpretable.

**Why `have_common_object=True` does not protect e13 and e14.** e13 and e14 share the container-level objects O1 and V1; any overlap-threshold or majority-overlap predicate sees two same-activity events on near-identical object sets. The only true discriminator is the finest-grained typed object — Payment (M1M2) — plus the fact that a card charge partitioned into partial captures legitimately repeats its label and container links. Common low-cardinality container objects are therefore weak evidence, not proof; discrimination must use the most granular object type and business keys, which is why §1 routes them to "retain both unchanged" and constraint law forbids their merge.

Mapping to requirements: deep copies per scenario (), provenance freezing (), `candidate_groups`/`predict_library_drops` pre-check (), `ocel_drop_duplicates` only after relabel-inspection with a no-op assertion (), warned `ocel_merge_duplicates` in a separate aggressive path (), `ocel_sort_by_additional_column` (), `ocel_add_index_based_timedelta` strictly post-ordering (), audited `merge_verified_pair` for e03/e04 and e11/e16 (), integrity validation (), raw untouched ().

```python
# ---------------------------------------------------------------------------
# Scenarios over `ocel_raw` (PM4Py OCEL). ocel_raw is NEVER mutated.
# events cols : ocel:eid, ocel:activity, ocel:timestamp, source,
#               source_event_key, source_seq, ingested_at, payload_hash
# relations   : ocel:eid, ocel:object_type, ocel:oid ; objects: ocel:oid,...
# ---------------------------------------------------------------------------
import copy, json, itertools
from functools import cmp_to_key
import pandas as pd
import pm4py

EID, ACT, TS = "ocel:eid", "ocel:activity", "ocel:timestamp"
OID, SRC, SKEY, SSEQ, ING = "ocel:oid", "source", "source_event_key", "source_seq", "ingested_at"
RULE_VERSION = "clean-v1.2"
AUDIT_TRAIL = []

# ---- provenance snapshot ----------------------------------------------------
def with_provenance(sc):
    sc.events["original_timestamp"] = sc.events[TS]      # frozen business truth
    sc.events["original_activity"]  = sc.events[ACT]
    sc.events["_ingest_rowid"]      = range(len(sc.events))   # forensic, not order
    sc.events["_tie_class"]         = ""
    return sc

REFINEMENTS = {"e07": "Pack Package (ERP status update)",
               "e08": "Release from Warehouse (WMS)",
               "e09": "Carrier Acceptance (carrier)",
               "e15": "Capture Payment (invoice balance summary)"}

def refine_labels(sc):
    m = sc.events[EID].isin(REFINEMENTS)
    sc.events.loc[m, ACT] = sc.events.loc[m, EID].map(REFINEMENTS)
    return sc

# ----  pre-check: inspect candidate groups BEFORE any modification ----------
def candidate_groups(sc):
    relsets = sc.relations.groupby(EID)[OID].agg(frozenset)
    rows = []
    for (ts, act), g in sc.events.groupby([TS, ACT]):
        if len(g) < 2: continue
        r = [{"eid": e, "src": s, "objs": relsets.get(e, frozenset())}
             for e, s in zip(g[EID], g[SRC])]
        for a, b in itertools.combinations(r, 2):
            jac = len(a["objs"] & b["objs"]) / max(1, len(a["objs"] | b["objs"]))
            kind = ("cross-system-candidate" if jac > 0.5 else "concurrent-distinct")
            rows.append({"pair": (a["eid"], b["eid"]), "ts": ts, "act": act,
                         "jaccard": round(jac, 2), "kind": kind})
    return pd.DataFrame(rows)

def predict_library_drops(sc):                      # replica of pm4py's predicate
    ev, rs = sc.events, sc.relations.groupby(EID)[OID].agg(frozenset)
    seen, drops = set(), []
    for eid, k in zip(ev[EID],
                      ev.apply(lambda x: (x[ACT], x[TS], rs.get(x[EID], frozenset())), axis=1)):
        drops.append(eid) if k in seen else seen.add(k)
    return set(drops)

# ----  audited verified-pair merge ------------------------------------------
def merge_verified_pair(sc, keep, drop, rule_id, reason, confidence):
    ev, rl = sc.events, sc.relations
    kr, dr = ev[ev[EID] == keep], ev[ev[EID] == drop]
    assert len(kr) == 1 and len(dr) == 1 and kr[TS].iloc[0] == dr[TS].iloc[0]
    moved = rl[rl[EID] == drop].copy()                     # (a) relations union
    have = set(rl.loc[rl[EID] == keep, OID])
    moved = moved[~moved[OID].isin(have)]; moved[EID] = keep
    sc.relations = pd.concat([rl[rl[EID] != drop], moved], ignore_index=True)
    src = dr[SRC].iloc[0]; upd = {}                        # (b) attributes
    for col in ev.columns:
        dv, kv = dr[col].iloc[0], kr[col].iloc[0]
        if col in (EID, SRC, SKEY, SSEQ, ING, "original_timestamp",
                   "original_activity", "_tie_class", "_ingest_rowid") or pd.isna(dv):
            continue
        if pd.isna(kv):               upd[col] = dv
        elif kv != dv:                upd[f"{src}:{col}"] = dv     # authoritative shadow
    for k, v in upd.items(): ev.loc[ev[EID] == keep, k] = v
    ev.loc[ev[EID] == keep, SKEY] += "|" + str(dr[SKEY].iloc[0])
    sc.events = ev[ev[EID] != drop].reset_index(drop=True) # (c) retire duplicate
    AUDIT_TRAIL.append(dict(canonical_eid=keep, source_event_ids=[keep, drop],
        merge_rule=rule_id, rule_version=RULE_VERSION, reviewer="auto-rule",
        original_activities=[kr[ACT].iloc[0], dr[ACT].iloc[0]],
        refined_activity=kr[ACT].iloc[0], original_ts=str(kr[TS].iloc[0]),
        adjusted_ts=None, attrs_from_each_source={"keep": "base", src: "shadow-columns"},
        discarded_conflicts=[], confidence=confidence, reason=reason))
    return sc

VR_PAIRS = [("e03", "e04", "VR-01 double physical scan (reconciliation report)",
             "high", "same scan, complementary payloads"),
            ("e11", "e16", "VR-02 invoice issuance duplicated on key V1",
             "high", "same V1, complementary authorities")]

# ----  deterministic order inside ties (cascade P1..P6) ----------------------
DOMAIN_PRECEDES = [("e12", "e13"), ("e13", "e15"), ("e14", "e15"),
                   ("e06", "e07"), ("e09", "e10"), ("e08", "e09"),
                   ("e03", "e06"), ("e05", "e06")]         # facts + flagged A1,A2

def tie_layers(ids, pairs):
    pred = {i: set() for i in ids}; succ = {i: set() for i in ids}
    for a, b in pairs:
        if a in pred and b in pred: succ[a].add(b); pred[b].add(a)
    layer, depth, frontier = {}, 0, [i for i in ids if not pred[i]]
    while frontier:
        for i in frontier: layer[i] = depth
        nxt = []
        for i in frontier:
            for s in succ[i]:
                pred[s].discard(i)
                if not pred[s]: nxt.append(s)
        frontier, depth = nxt, depth + 1
    for i in ids: layer.setdefault(i, depth)               # cycle  escalate
    return layer

def order_sc(sc):
    ev = sc.events; tl = {}
    for ts, g in ev.groupby(TS): tl.update(tie_layers(list(g[EID]), DOMAIN_PRECEDES))
    recs = ev.to_dict("records")
    def cmp(a, b):
        if a[TS] != b[TS]: return -1 if a[TS] < b[TS] else 1
        if tl[a[EID]] != tl[b[EID]]: return tl[a[EID]] - tl[b[EID]]
        if a[SRC] == b[SRC] and a[SSEQ] != b[SSEQ]: return a[SSEQ] - b[SSEQ]  # same source only
        if a[ING] != b[ING]: return -1 if a[ING] < b[ING] else 1              # deterministic only
        return (a[EID] > b[EID]) - (a[EID] < b[EID])                          # stable fallback
    recs.sort(key=cmp_to_key(cmp))
    pos = {r[EID]: i for i, r in enumerate(recs)}
    ev["_order_seq"] = ev[EID].map(pos)
    arb = [ts for ts, g in ev.groupby(TS)
           for _ in [0] if (g[EID].map(tl).nunique() < 2 or
                            (g.groupby(g[EID].map(tl)).size() > 1).any())]
    for ts in set(arb):
        m = ev[TS] == ts
        dup = ev[m][EID].map(tl).duplicated(keep=False)
        ev.loc[ev.index[m][dup], "_tie_class"] = "ARBITRARY-STABLE-FALLBACK"
    return sc

# ----  referential integrity -------------------------------------------------
def validate(sc, expect=None):
    probs = []
    if not sc.relations[EID].isin(set(sc.events[EID])).all():
        probs.append("orphan relation rows")
    if not sc.relations[OID].isin(set(sc.objects[OID])).all():
        probs.append("unknown objects referenced")
    if sc.events[EID].duplicated().any(): probs.append("duplicate eids")
    if expect is not None and len(sc.events) != expect:
        probs.append(f"count {len(sc.events)} != {expect}")
    assert not probs, probs
    return {"events": len(sc.events), "relations": len(sc.relations)}

# ---- scenario builders --------------------------------------------------------
def build_conservative():
    sc = refine_labels(with_provenance(copy.deepcopy(ocel_raw)))
    pre = candidate_groups(sc)                              # printed for reviewers
    assert predict_library_drops(sc) == {"e04", "e16"}, "gate failed: other collisions!"
    for k, d, r, c, w in VR_PAIRS: sc = merge_verified_pair(sc, k, d, r, w, c)
    sc = order_sc(sc)
    n0 = len(sc.events)
    sc = pm4py.ocel_drop_duplicates(sc)   # JUSTIFIED: relabeled axes isolate the
                                          # collisions; assertion proves pure no-op
    assert len(sc.events) == n0 == 15
    sc = pm4py.ocel_sort_by_additional_column(sc, "_order_seq")
    sc = pm4py.ocel_add_index_based_timedelta(sc)           # ONLY now, after order
    return sc, validate(sc, 15), pre

def build_evidence_semantic():
    sc = refine_labels(with_provenance(copy.deepcopy(ocel_raw)))
    for k, d, r, c, w in VR_PAIRS: sc = merge_verified_pair(sc, k, d, r, w, c)
    sc = merge_verified_pair(sc, "e06", "e07", "VR-03 reviewed single pack transition",
                             "human-confirmed; ERP fields folded under erp:", "medium")
    sc = order_sc(sc)
    sc = pm4py.ocel_sort_by_additional_column(sc, "_order_seq")
    sc = pm4py.ocel_add_index_based_timedelta(sc)
    return sc, validate(sc, 14)

def build_mechanically_aggressive():
    #  WARNING: demonstrates library damage on purpose. Blanket merge with no
    # provenance, no conflict policy, fuses e08+e09 (release  acceptance).
    sc = copy.deepcopy(ocel_raw); n0 = len(sc.events)
    sc = pm4py.ocel_merge_duplicates(sc)
    return sc, {"before": n0, "after": len(sc.events),
                "silently_removed": n0 - len(sc.events)}

cons, cons_stats, cons_pre = build_conservative()
evid, evid_stats           = build_evidence_semantic()
aggr, aggr_stats           = build_mechanically_aggressive()
json.dump(AUDIT_TRAIL, open("merge_audit.json", "w"), indent=2, default=str)
assert len(ocel_raw.events) == 17 and "original_timestamp" not in ocel_raw.events.columns
```

- **OC-DFG edges/frequencies:** issue-node incident frequency halves RAWCONS; ReleaseAcceptance edges exist only in CONS/EVI (in AGG-default the pair fuses); OT repetition count on Dispatch drops to zero under AGG for the wrong reason.
- **ET–OT weights:** RAW inflates Scanner-PickItem/Package weights ×2 and DispatchPackage/Delivery ×2 (collision under one label); CONS splits the latter into two ETs with correct individual weights; AGG removes mass instead of redistributing it.
- **OTG relations:** Invoice–Payment participation stable in CONS/EVI; AGG-blind fabricates one Payment-touching event linked to M1M2 simultaneously; Package–Delivery weights change from 2 same-type interactions to differentiated type-level interactions after refinement.
- **Apparent rework/loops:** Pick self-loop and Pack echo: artifact (killed by CONS/EVI); ReleaseAcceptHandover chain: real sequence, preserved only where labels survived; CaptureCapture: scheduling artifact, must not be reported as payment rework.
- **Lifecycle/performance:** RAW yields unstable zero-length intervals and run-to-run varying flattening; CONS gives reproducible order plus optional synthetic µs resolution clearly flagged, so warehouse dwell (releaseaccept) and handover latency become measurable; AGG variants shorten the logistics path artificially, inflating preceding waiting times and erasing internal phases.

Six edges whose interpretation changes concretely: (1) Pick(I1)Pick(I1); (2) Pick(Item)Pack(Package) frequency; (3) PackPack echo on Order view; (4) Release(WMS)Accept(Carrier) existence/dwell; (5) Accept(Carrier)Handover(Carrier) frequency; (6) Authorize(M1)Capture(M1) vs AuthorizeComposite-Capture; (7) Issue(V1)Authorize(M1) doubled-vs-single incidence.

## 8. Audit trail and reversibility

Schema (one row per applied rule, also for refusals/retentions of structural interest):

- `canonical_eid`; `source_event_ids` [all contributing eids incl. retired ones];
- `merge_rule` (EX-01/VR-01…VR-03) + `rule_version`;
- `reviewer` (user/rule ID) and timestamp of decision;
- `original_activities[]`, `refined_activity`;
- `original_ts`, `adjusted_ts` (NULL unless a sanctioned adjustment existed — here always NULL);
- `attrs_from_each_source`: map source  fields contributed, namespaced shadow columns created;
- `discarded_conflicts`: field, both values, chosen winner and why (empty by design here);
- `confidence`, `reason`, and pointers to evidence (e.g., reconciliation report ID);
- plus `relation_delta` (moved/united OIDs) and `_tie_class` annotations propagated to rows.

Reconstruction: raw events are archived immutably (hash of export, sha256). Expanding `source_event_ids` restores retired rows with their originally copied `original_*` columns and reinserts relation rows recorded in `relation_delta`; attribute shadow columns are mapped back onto their source rows. Joining archive + `merge_audit.json` replays the transformation inverted — yielding the raw view bit-for-bit, enabling before/after diffs and re-running any rule subset at different versions.

## 9. Failure modes and safeguards

1. **Collapsing distinct partial payments** via activity+tijd matching  Safeguard: finest-grained OT discriminator mandatory; constraint test on groups; e13/e14 whitelisted as protected.
2. **Abstraction-level updates turned into false rework** (Pack echo read as repetition)  refine summary labels; never treat subset relations as duplicates; annotate ET roles.
3. **Ordering by ingestion time** encoding queue latency as causality  ingestion relegated to penultimate deterministic fallback; `_ingest_rowid` forensic-only; assertion forbidding it in the primary key.
4. **Shared objects treated as duplication proof**  decision tree requires business-key/typed-discriminator; container overlap demoted to weak hint; §5 warning codified.
5. **Unioning incompatible E2O relations** (partner objects differing across observations)  verified-merge asserts object compatibility or records a conflict row; incompatible sets route to quarantine.
6. **Synthetic microseconds changing durations**  original timestamps frozen; synthetic resolution in separate flagged column (`ocel_add_index_based_timedelta` post-order); durations from it reported as resolutions, not measurements.
7. **Losing source-authoritative attributes** on merge  null-coalesce only; divergent fields namespaced per source; per-field origin in audit.
8. **Applying duplicate functions to the whole OCEL blind**  pre-check + predicted-dropset assertion gates every library call; counterfactual shows raw `drop_duplicates` would have deleted e09.
9. **Cross-source `source_seq` comparison** (551 vs 100 nonsense)  comparator applies seq only within equal `source`.
10. **Non-reproducible re-runs** (sort instability, rerun drift)  total comparator ends in eid fallback; every artifact stamped with rule_version and input hash; runs idempotent over archives.
