# 1. Source-Semantics Baseline

The witnesses below are complete visible traces after hiding transitions whose label is `None`. Abbreviations are used only in this table:

- `R` = Register Change
- `A` = Assess Risk
- `P` = Prepare Evidence
- `L` = Legal Review
- `C` = Configure Trial
- `I` = Inspect Trial
- `D` = Correct Defect
- `X` = Release Change
- `Z` = Archive Change

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| I1 | Register Change is the first visible activity. | `R,A,P,C,I,X,Z` | `A,R,P,C,I,X,Z` | Yes |
| I2 | Assess Risk and Prepare Evidence both occur after registration. | `R,A,P,C,I,X,Z` | `P,R,A,C,I,X,Z` | Yes |
| I3 | Assess Risk and Prepare Evidence are unordered: either visible order is allowed. | `R,A,P,C,I,X,Z` and `R,P,A,C,I,X,Z` | A converted model allowing only one of these orders | Partly: both interleavings are visible, but true concurrency is not directly observable from traces |
| I4 | Legal Review is optional and, when selected, occurs after Assess Risk. | `R,A,P,L,C,I,X,Z` and `R,A,P,C,I,X,Z` | `R,L,A,P,C,I,X,Z` | Partly: presence or absence of Legal Review is visible, but the silent skip itself is not |
| I5 | Verification cannot start until both Assess Risk and Prepare Evidence are complete. | `R,A,P,C,I,X,Z` | `R,A,C,P,I,X,Z` or `R,P,C,A,I,X,Z` | Yes |
| I6 | Optional Legal Review and verification have no causal order beyond their own prerequisites. Legal Review may precede, follow, or interleave with a verification iteration. | `R,A,P,L,C,I,X,Z`, `R,A,P,C,L,I,X,Z`, and `R,A,P,C,I,L,X,Z` | A converted model admitting only one fixed relative order | Partly: admissible interleavings are visible; model-level independence is not proved by them |
| I7 | Every verification iteration executes Configure Trial before Inspect Trial. | `R,A,P,C,I,X,Z` | `R,A,P,I,C,X,Z` | Yes |
| I8 | Correct Defect is the redo separator between completed verification iterations. It is neither the first loop action nor a final action without another trial body. | `R,A,P,C,I,D,C,I,X,Z` | `R,A,P,D,C,I,X,Z`, `R,A,P,C,I,C,I,X,Z`, or `R,A,P,C,I,D,X,Z` | Yes |
| I9 | The verification loop executes its trial body at least once. | `R,A,P,C,I,X,Z` | `R,A,P,X,Z` | Yes |
| I10 | Release Change waits for completion of both the optional-legal component and the verification loop. | `R,A,P,L,C,I,X,Z` and `R,A,P,C,I,X,Z` | `R,A,P,C,X,I,Z` or `R,A,P,C,I,X,L,Z` | Partly: early release is visible, but completion through the silent legal-skip branch is not directly visible |
| I11 | Archive Change follows Release Change and is the final visible activity. | `R,A,P,C,I,X,Z` | `R,A,P,C,I,Z,X` or any completed trace with a visible activity after `Z` | Partly: visible finality is observable; exact token cleanliness of a final marking is not |

# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| **Primary: POWL  accepting Petri net  BPMN** | `pm4py.convert_to_petri_net(source_powl)` followed by `pm4py.convert_to_bpmn(net, im, fm)` | Retains an accepting Petri net as an executable semantic checkpoint before generating BPMN. It does not first force the overlapping partial order into a block-structured form. | Petri-to-BPMN conversion can introduce many silent routing nodes and gateways. A visually plausible BPMN need not preserve the same accepted visible language after round trip. | Conversion exception, null initial/final marking, non-workflow-net result, unsoundness, failed witnesses, or a bounded trace-language difference after BPMN round trip. |
| **Secondary: POWL  accepting Petri net  process tree  BPMN** | `pm4py.convert_to_process_tree(net, im, fm)` followed, only on success, by `pm4py.convert_to_bpmn(tree)` | A successful process tree can produce a more structured, stakeholder-friendly BPMN and make XOR, parallel, and loop blocks explicit. | The source contains overlapping dependencies: Legal Review depends only on Assess Risk, while verification depends on both Assess Risk and Prepare Evidence. This resembles a non-series-parallel dependency pattern and may not admit a faithful process-tree decomposition. | `convert_to_process_tree(...)` raises an exception or returns `None`; alternatively, the tree succeeds syntactically but loses required interleavings, optionality, loop scope, or release synchronization. |

The first pipeline is primary. A process-tree exception is a meaningful conversion outcome, not an error to suppress. It may indicate non-block-structured behavior or a limitation of the installed conversion algorithm; it does not by itself prove which explanation applies.

# 3. Conversion Code

The following script recreates the authoritative source model, performs both pipelines, checks every accepting net it successfully creates, round-trips each produced BPMN, and attempts to save all visualizations.

```python
from pathlib import Path

import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator


# ---------------------------------------------------------------------------
# Authoritative source POWL
# ---------------------------------------------------------------------------

register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(
    operator=Operator.XOR,
    children=[legal_review, skip_legal],
)

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[trial_body, correct_defect],
)

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[
        register,
        assess_risk,
        prepare_evidence,
        optional_legal,
        verification_loop,
        release_change,
        archive_change,
    ]
)

source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)


# ---------------------------------------------------------------------------
# Utilities
# ---------------------------------------------------------------------------

OUTPUT_DIR = Path("conversion_artifacts")
OUTPUT_DIR.mkdir(parents=True, exist_ok=True)


def require_accepting_net(result, context):
    """
    Validate the shape of a PM4Py conversion result without assuming that
    either marking is present.
    """
    if not isinstance(result, (tuple, list)) or len(result) != 3:
        raise TypeError(
            f"{context} did not return an (net, initial_marking, "
            f"final_marking) triple: {type(result)!r}"
        )

    net, initial_marking, final_marking = result

    if net is None:
        raise ValueError(f"{context} returned a null Petri net")
    if initial_marking is None:
        raise ValueError(f"{context} returned a null initial marking")
    if final_marking is None:
        raise ValueError(f"{context} returned a null final marking")

    return net, initial_marking, final_marking


def run_net_diagnostics(name, net, initial_marking, final_marking):
    """Run both requested diagnostics and retain their raw results."""
    result = {
        "workflow_net": None,
        "soundness": None,
        "workflow_net_error": None,
        "soundness_error": None,
    }

    try:
        result["workflow_net"] = pm4py.check_is_workflow_net(net)
        print(f"[{name}] workflow net: {result['workflow_net']}")
    except Exception as exc:
        result["workflow_net_error"] = repr(exc)
        print(f"[{name}] workflow-net check failed: {exc!r}")

    try:
        result["soundness"] = pm4py.check_soundness(
            net,
            initial_marking,
            final_marking,
            print_diagnostics=True,
        )
        print(f"[{name}] soundness: {result['soundness']}")
    except Exception as exc:
        result["soundness_error"] = repr(exc)
        print(f"[{name}] soundness check failed: {exc!r}")

    return result


def save_or_report(description, saver, *args):
    """
    Visualization failures, such as a missing Graphviz installation, are
    reported separately from conversion failures.
    """
    try:
        saver(*args)
        print(f"Saved {description}")
    except Exception as exc:
        print(f"Could not save {description}: {exc!r}")


diagnostics = {}
accepting_nets = {}
produced_bpmns = {}
roundtripped_nets = {}
roundtrip_errors = {}


# ---------------------------------------------------------------------------
# Save the authoritative source
# ---------------------------------------------------------------------------

save_or_report(
    "source POWL",
    pm4py.save_vis_powl,
    source_powl,
    str(OUTPUT_DIR / "00_source_powl.png"),
)


# ---------------------------------------------------------------------------
# Primary pipeline: POWL -> accepting Petri net -> BPMN
# ---------------------------------------------------------------------------

net_from_powl, im_from_powl, fm_from_powl = require_accepting_net(
    pm4py.convert_to_petri_net(source_powl),
    "POWL-to-Petri conversion",
)

accepting_nets["net_from_powl"] = (
    net_from_powl,
    im_from_powl,
    fm_from_powl,
)
diagnostics["net_from_powl"] = run_net_diagnostics(
    "net_from_powl",
    net_from_powl,
    im_from_powl,
    fm_from_powl,
)

save_or_report(
    "Petri net converted from POWL",
    pm4py.save_vis_petri_net,
    net_from_powl,
    im_from_powl,
    fm_from_powl,
    str(OUTPUT_DIR / "01_petri_from_powl.png"),
)

bpmn_from_net = pm4py.convert_to_bpmn(
    net_from_powl,
    im_from_powl,
    fm_from_powl,
)
if bpmn_from_net is None:
    raise ValueError("Petri-to-BPMN conversion returned None")

produced_bpmns["bpmn_from_net"] = bpmn_from_net

save_or_report(
    "BPMN converted from the POWL-derived Petri net",
    pm4py.save_vis_bpmn,
    bpmn_from_net,
    str(OUTPUT_DIR / "02_bpmn_from_powl_petri_net.png"),
)


# ---------------------------------------------------------------------------
# Secondary pipeline: Petri net -> process tree -> BPMN
# ---------------------------------------------------------------------------

process_tree_from_net = None
process_tree_conversion_error = None
bpmn_from_tree = None
tree_to_bpmn_error = None

try:
    process_tree_from_net = pm4py.convert_to_process_tree(
        net_from_powl,
        im_from_powl,
        fm_from_powl,
    )
    if process_tree_from_net is None:
        raise ValueError("Petri-to-process-tree conversion returned None")
except Exception as exc:
    process_tree_conversion_error = exc
    print(
        "SECONDARY PIPELINE QUARANTINED at Petri-to-process-tree conversion. "
        "This may indicate non-block-structured behavior or an unsupported "
        f"net pattern. Exception: {exc!r}"
    )

if process_tree_from_net is not None:
    save_or_report(
        "process tree converted from the POWL-derived Petri net",
        pm4py.save_vis_process_tree,
        process_tree_from_net,
        str(OUTPUT_DIR / "03_process_tree_from_powl_petri_net.png"),
    )

    # This direct tree re-encoding is an additional semantic checkpoint.
    try:
        (
            net_reencoded_from_process_tree,
            im_reencoded_from_process_tree,
            fm_reencoded_from_process_tree,
        ) = require_accepting_net(
            pm4py.convert_to_petri_net(process_tree_from_net),
            "Process-tree-to-Petri conversion",
        )

        accepting_nets["net_reencoded_from_process_tree"] = (
            net_reencoded_from_process_tree,
            im_reencoded_from_process_tree,
            fm_reencoded_from_process_tree,
        )
        diagnostics["net_reencoded_from_process_tree"] = run_net_diagnostics(
            "net_reencoded_from_process_tree",
            net_reencoded_from_process_tree,
            im_reencoded_from_process_tree,
            fm_reencoded_from_process_tree,
        )

        save_or_report(
            "Petri net re-encoded from the process tree",
            pm4py.save_vis_petri_net,
            net_reencoded_from_process_tree,
            im_reencoded_from_process_tree,
            fm_reencoded_from_process_tree,
            str(OUTPUT_DIR / "04_petri_reencoded_from_process_tree.png"),
        )
    except Exception as exc:
        print(
            "Process tree existed, but its Petri-net re-encoding failed: "
            f"{exc!r}"
        )

    try:
        bpmn_from_tree = pm4py.convert_to_bpmn(process_tree_from_net)
        if bpmn_from_tree is None:
            raise ValueError("Process-tree-to-BPMN conversion returned None")

        produced_bpmns["bpmn_from_process_tree"] = bpmn_from_tree

        save_or_report(
            "BPMN converted through the process-tree intermediate",
            pm4py.save_vis_bpmn,
            bpmn_from_tree,
            str(OUTPUT_DIR / "05_bpmn_from_process_tree.png"),
        )
    except Exception as exc:
        tree_to_bpmn_error = exc
        print(
            "SECONDARY PIPELINE QUARANTINED at process-tree-to-BPMN "
            f"conversion: {exc!r}"
        )


# ---------------------------------------------------------------------------
# Convert every produced BPMN back to an accepting Petri net
# ---------------------------------------------------------------------------

for bpmn_name, bpmn_model in produced_bpmns.items():
    roundtrip_name = f"roundtrip_{bpmn_name}_to_petri"

    try:
        rt_net, rt_im, rt_fm = require_accepting_net(
            pm4py.convert_to_petri_net(bpmn_model),
            f"{bpmn_name} BPMN-to-Petri round trip",
        )
    except Exception as exc:
        roundtrip_errors[roundtrip_name] = exc
        print(f"[{roundtrip_name}] conversion failed: {exc!r}")
        continue

    roundtripped_nets[roundtrip_name] = (rt_net, rt_im, rt_fm)
    accepting_nets[roundtrip_name] = (rt_net, rt_im, rt_fm)

    diagnostics[roundtrip_name] = run_net_diagnostics(
        roundtrip_name,
        rt_net,
        rt_im,
        rt_fm,
    )

    save_or_report(
        f"round-tripped Petri net {roundtrip_name}",
        pm4py.save_vis_petri_net,
        rt_net,
        rt_im,
        rt_fm,
        str(OUTPUT_DIR / f"06_{roundtrip_name}.png"),
    )


print("Accepting nets created:", sorted(accepting_nets))
print("BPMN models created:", sorted(produced_bpmns))
print(
    "Round-trip failures:",
    {name: repr(exc) for name, exc in roundtrip_errors.items()},
)
```

# 4. Preservation and Loss Audit

The following is a pre-execution assessment. `expected preserved` states a converter obligation, not a measured result. A status should be upgraded to `validated preserved` only after the validation code succeeds for that artifact. A caught exception changes the applicable process-tree status to `conversion failed`.

| Source invariant | POWLPetri | PetriBPMN | PetriTree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| Register precedes all later work | expected preserved | expected preserved | ambiguous | not tested | Positive and negative ordering witnesses and footprints provide runtime checks. |
| Assess Risk and Prepare Evidence have no order between them | expected preserved | expected preserved | ambiguous | not tested | Both visible orders must survive. A process tree may be unable to represent the surrounding overlapping dependencies exactly. |
| True concurrency rather than an arbitrary choice between interleavings | expected preserved | ambiguous | ambiguous | not tested | Trace sets can show both orders but cannot alone prove simultaneous enablement. Petri-net structure, reachable markings, and the footprint parallel relation provide stronger but still representation-dependent evidence. |
| No edge or causal order between Optional Legal Review and verification | expected preserved | expected preserved | ambiguous | not tested | Legal Review must be possible before, during, and after the visible verification body, subject to its own prerequisite and the release join. |
| Silent optional-legal behavior | expected preserved | ambiguous | expected preserved | not tested | The absence of Legal Review and its presence must both remain possible. BPMN may encode the silent choice as a gateway edge rather than a task. |
| Configure Trial precedes Inspect Trial in every iteration | expected preserved | expected preserved | expected preserved | not tested | Negative witnesses reject an inverted or weakened trial body. |
| Binary-loop semantics: trial body once, then zero or more `Correct Defect; trial body` repetitions | expected preserved | ambiguous | expected preserved | not tested | A drawing can obscure which child is the loop body and which is the redo child. Traces must reject zero iterations, consecutive trial bodies without correction, and correction without a following trial body. |
| Release synchronizes optional legal completion and loop completion | expected preserved | expected preserved | ambiguous | not tested | Early-release witnesses and exact final-marking exploration test the join behavior. |
| Archive follows release and is final | expected preserved | expected preserved | expected preserved | not tested | Visible order is trace-testable; absence of residual tokens requires marking-based validation. |
| Visible activity labels are unique | expected preserved | ambiguous | ambiguous | not tested | The source has one transition per visible label. Conversion may duplicate a visible transition or alter labels; multiplicity must be audited separately from language comparison. |
| Initial and final markings | expected preserved | approximated | approximated | not tested | BPMN and process trees represent start/end behavior rather than carrying the original place markings. Their reconverted markings can only be checked internally, not equated by place identity with the source markings. |
| Gateway and silent routing-node interpretation | not tested | ambiguous | ambiguous | not tested | Gateway type and layout are derivative choices. A correct underlying net can still produce a misleading rendering. |

Important distinctions:

- **True concurrency versus interleaving:** both orders of two activities are necessary evidence for concurrency but are not sufficient. A model could nondeterministically choose one sequential order or the other. Co-enabled transitions, Petri-net structure, and footprint parallel relations provide additional evidence.
- **Absence of an edge:** there is no direct source order between Optional Legal Review and the verification loop. A converter need not preserve the same graph shape, but it must preserve the resulting admissible behavior.
- **Silent optional behavior:** the tau transition itself is intentionally unobservable. Preservation means retaining both the visible trace with Legal Review and the visible trace without it.
- **Binary loop:** the source loop means `trial_body (Correct Defect trial_body)*`, not a zero-or-more loop and not `trial_body (trial_body Correct Defect)*`.
- **Release join:** a visually adjacent Release Change is not enough. It must be unreachable until both top-level predecessors have completed.
- **Labels:** trace comparison assumes labels retain their meaning. Duplicate or changed labels make label-based equivalence ambiguous.
- **Markings:** every accepting-net conversion needs a non-null initial and final marking. A completed explored trace is accepted only at exact final-marking equality.
- **BPMN routing:** parallel or exclusive gateways may be inserted as routing machinery. Their positions and visual nesting need not correspond one-for-one with POWL operators.

# 5. Round-Trip Validation Code

This code is intended to run in the same Python session after the conversion code in Section 3.

The custom explorer handles ordinary weighted place/transition nets, hides exactly those transitions whose label is `None`, admits a trace only at exact final-marking equality, and bounds visible length, verification iterations, and consecutive tau firings.

```python
from collections import Counter, deque
import copy

import pm4py


# ---------------------------------------------------------------------------
# Validation bounds
# ---------------------------------------------------------------------------

MAX_VISIBLE_LENGTH = 16
MAX_VERIFICATION_ITERATIONS = 3
MAX_CONSECUTIVE_TAU = 40

CONFIGURE_LABEL = "Configure Trial"


# ---------------------------------------------------------------------------
# Marking and bounded-language utilities
# ---------------------------------------------------------------------------

def build_place_index(net):
    ordered_places = sorted(
        net.places,
        key=lambda p: (str(getattr(p, "name", "")), id(p)),
    )
    return {place: index for index, place in enumerate(ordered_places)}


def marking_signature(marking, place_index):
    """
    Canonical token vector within one net. Zero-token entries are omitted.
    A nonzero token on an object outside the net is treated as an error.
    """
    result = []

    for place, token_count in marking.items():
        if token_count == 0:
            continue
        if place not in place_index:
            raise ValueError(
                f"Marking contains a place outside the current net: {place!r}"
            )
        result.append((place_index[place], int(token_count)))

    return tuple(sorted(result))


def fire_enabled_transition(net, transition, marking):
    """
    Fire an already-enabled transition in an ordinary weighted P/T net.

    pm4py.get_enabled_transitions(...) is the authority for enablement.
    This function deliberately rejects nonstandard arc topology rather than
    guessing reset, inhibitor, or other extended-net semantics.
    """
    new_marking = copy.copy(marking)

    for arc in transition.in_arcs:
        place = arc.source
        if place not in net.places:
            raise TypeError(
                "Custom explorer encountered a nonstandard input arc"
            )

        weight = int(getattr(arc, "weight", 1) or 1)
        available = int(new_marking.get(place, 0))
        if available < weight:
            raise RuntimeError(
                "PM4Py reported a transition enabled, but the custom firing "
                "logic found insufficient tokens"
            )

        remaining = available - weight
        if remaining:
            new_marking[place] = remaining
        elif place in new_marking:
            del new_marking[place]

    for arc in transition.out_arcs:
        place = arc.target
        if place not in net.places:
            raise TypeError(
                "Custom explorer encountered a nonstandard output arc"
            )

        weight = int(getattr(arc, "weight", 1) or 1)
        new_marking[place] = int(new_marking.get(place, 0)) + weight

    return new_marking


def bounded_completed_visible_traces(
    net,
    initial_marking,
    final_marking,
    max_visible_length=MAX_VISIBLE_LENGTH,
    max_verification_iterations=MAX_VERIFICATION_ITERATIONS,
    max_consecutive_tau=MAX_CONSECUTIVE_TAU,
):
    """
    Return all visible traces accepted at exact final-marking equality under
    the explicit bounds.

    State identity includes the marking, visible trace, and current number of
    consecutive tau firings. This merges only states with the same future
    behavior under the remaining bounds.
    """
    if initial_marking is None or final_marking is None:
        raise ValueError("Bounded exploration requires both markings")

    place_index = build_place_index(net)
    final_signature = marking_signature(final_marking, place_index)

    initial_copy = copy.copy(initial_marking)
    initial_state = (initial_copy, tuple(), 0)

    queue = deque([initial_state])
    seen = {
        (
            marking_signature(initial_copy, place_index),
            tuple(),
            0,
        )
    }
    completed_traces = set()

    while queue:
        marking, visible_trace, consecutive_tau = queue.popleft()
        current_signature = marking_signature(marking, place_index)

        # Acceptance requires equality, not covering or containing fm.
        if current_signature == final_signature:
            completed_traces.add(visible_trace)
            continue

        enabled = pm4py.get_enabled_transitions(net, marking)

        for transition in enabled:
            label = getattr(transition, "label", None)

            if label is None:
                if consecutive_tau >= max_consecutive_tau:
                    continue
                next_trace = visible_trace
                next_tau_count = consecutive_tau + 1
            else:
                if len(visible_trace) >= max_visible_length:
                    continue

                if (
                    label == CONFIGURE_LABEL
                    and visible_trace.count(CONFIGURE_LABEL)
                    >= max_verification_iterations
                ):
                    continue

                next_trace = visible_trace + (label,)
                next_tau_count = 0

            next_marking = fire_enabled_transition(
                net,
                transition,
                marking,
            )
            key = (
                marking_signature(next_marking, place_index),
                next_trace,
                next_tau_count,
            )

            if key not in seen:
                seen.add(key)
                queue.append(
                    (next_marking, next_trace, next_tau_count)
                )

    return completed_traces


# ---------------------------------------------------------------------------
# Positive and negative semantic witnesses
# ---------------------------------------------------------------------------

positive_witnesses = {
    "optional_legal_skipped": (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",

    "optional_legal_taken": (

        "Register Change",

        "Prepare Evidence",
        "Configure Trial",
        "Legal Review",
        "Inspect Trial",
        "Release Change",

    ),
    "two_verification_iterations": (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Correct Defect",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
}

negative_witnesses = {
    "register_not_first": (
        "Assess Risk",
        "Register Change",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),

def evaluate_witnesses(trace_set):
    missing_positive = {
        name: trace
        for name, trace in positive_witnesses.items()
        if trace not in trace_set
    }
    admitted_negative = {
        name: trace
        for name, trace in negative_witnesses.items()
        if trace in trace_set
    }
    return missing_positive, admitted_negative

def soundness_as_boolean(raw_result):
    if isinstance(raw_result, (tuple, list)) and raw_result:
        raw_result = raw_result[0]
    try:
        return bool(raw_result)
    except Exception:
        return None


def safe_soundness(name, net, initial_marking, final_marking):
    result = {
        "workflow_net": None,
        "soundness_raw": None,
        "soundness_bool": None,
    }

    try:
        result["workflow_net"] = pm4py.check_is_workflow_net(net)
    except Exception as exc:
        result["workflow_net_error"] = repr(exc)

    try:
        raw = pm4py.check_soundness(
            net,
            initial_marking,
            final_marking,
            print_diagnostics=True,
        )
        result["soundness_raw"] = raw
        result["soundness_bool"] = soundness_as_boolean(raw)
    except Exception as exc:
        result["soundness_error"] = repr(exc)

    print(f"[{name}] diagnostic summary: {result}")
    return result


def visible_label_multiplicity(net):
    return Counter(
        transition.label
        for transition in net.transitions
        if getattr(transition, "label", None) is not None
    )


def safe_footprints(name, net, initial_marking, final_marking):
    try:
        result = pm4py.discover_footprints(
            net,
            initial_marking,
            final_marking,
        )
        print(f"[{name}] footprints discovered")
        return result
    except Exception as exc:
        print(f"[{name}] footprint discovery failed: {exc!r}")
        return None


def safe_reachability_summary(
    name,
    net,
    initial_marking,
    final_marking,
    soundness_result,
):
    """
    Full reachability construction is attempted only for a net reported
    sound. This avoids knowingly starting an unbounded exploration on an
    unsound candidate.
    """
    if soundness_result.get("soundness_bool") is not True:
        print(
            f"[{name}] reachability graph skipped because soundness "
            "was not established"
        )
        return None

    try:
        graph = pm4py.convert_to_reachability_graph(
            net,
            initial_marking,
            final_marking,
        )
        transition_names = Counter(
            str(getattr(transition, "name", None))
            for transition in graph.transitions
        )
        summary = {
            "states": len(graph.states),
            "transitions": len(graph.transitions),
            "transition_name_histogram": transition_names,
        }
        print(f"[{name}] reachability summary: {summary}")
        return summary
    except Exception as exc:
        print(f"[{name}] reachability conversion failed: {exc!r}")
        return None

def project_playout_log(log):
    """
    Project a PM4Py EventLog-like object to visible concept:name tuples.
    Unsupported log representations are reported by the caller.
    """
    projected = set()

    for trace in log:
        labels = []
        for event in trace:
            label = event.get("concept:name")
            if label is not None:
                labels.append(label)

        trace_tuple = tuple(labels)
        if (
            len(trace_tuple) <= MAX_VISIBLE_LENGTH
            and trace_tuple.count(CONFIGURE_LABEL)
            <= MAX_VERIFICATION_ITERATIONS
        ):
            projected.add(trace_tuple)

    return projected
```

The bounded trace exploration is exhaustive only for paths satisfying all three explicit bounds:

1. no more than 16 visible events;
2. no more than three occurrences of Configure Trial;
3. no more than 40 consecutive tau firings between visible events.

It is not exhaustive for the unbounded loop language. It may also omit a valid bounded visible trace if realizing that trace requires more than 40 consecutive tau firings. Playout and token replay are sampled or fitness-oriented checks and do not establish language equivalence.

Reachability-state counts are diagnostics, not canonical graph equivalence: generated place names, silent transitions, and routing structures can legitimately differ.

# 6. Visual-Semantics Review

A BPMN rendering can be misleading even when its reconverted accepting Petri net passes the behavioral checks.

- **Parallel gateways:** a converter may introduce parallel splits and joins to implement token dependencies. Their visual nesting can suggest that Assess Risk and Prepare Evidence form one clean parallel block followed by another block. That would obscure the asymmetric fact that Legal Review depends only on Assess Risk while verification depends on both activities.
- **Exclusive gateways:** the optional legal behavior may appear as an exclusive gateway with one branch containing Legal Review and another branch containing no task. A viewer can miss the empty branch and incorrectly conclude that Legal Review is mandatory.
- **Loop visualization:** Petri-to-BPMN conversion may render the verification loop as several gateways and backward sequence flows rather than a named loop subprocess. It can become unclear that the scope is `Configure Trial  Inspect Trial` and that Correct Defect is required only between iterations.
- **Silent routing nodes:** unlabeled transitions may become gateways, empty routes, or implementation-specific routing constructs. They are not additional business activities, but a viewer may treat them as missing tasks or errors.
- **Apparent graph ordering:** left-to-right, top-to-bottom, or vertical placement is layout, not semantics. Legal Review drawn above or before verification does not by itself create causal order. Only sequence flows and gateway semantics do.
- **Join ambiguity:** Release Change may be placed visually close to one branch, making it look as though only that branch controls release. The actual requirement is synchronization of both the optional-legal component and the verification loop.
- **Gateway type ambiguity:** a mistaken exclusive gateway where a parallel join is needed can look visually reasonable but alter behavior substantially.

Recommended annotations include:

1. A text annotation after registration: **“Assess Risk and Prepare Evidence are unordered.”**
2. A note on verification entry: **“Requires completion of both Assess Risk and Prepare Evidence.”**
3. An explicit optional marker on Legal Review: **“0..1; prerequisite: Assess Risk.”**
4. A loop annotation: **`Trial (Correct Defect; Trial)*`, minimum one trial.**
5. A note at Release Change: **“Waits for optional-legal completion and verification completion.”**
6. A legend stating that blank branches and unlabeled routing elements are tau behavior.
7. A note stating that physical placement does not imply order without a sequence-flow path.
8. Metadata linking the diagram to the authoritative POWL version, conversion version, and validation report.

# 7. Rejection Criteria

A result should be rejected or quarantined if any of the following occurs:

1. A required conversion raises an exception, returns `None`, or fails to return a three-part accepting-net result.
2. An initial or final marking is missing.
3. `pm4py.check_is_workflow_net(...)` reports false or cannot complete.
4. `pm4py.check_soundness(...)` reports unsoundness or raises an unexplained diagnostic exception.
5. A completed positive witness cannot reach exact final-marking equality.
6. A negative witness reaches exact final-marking equality.
7. Either `Assess Risk; Prepare Evidence` or `Prepare Evidence; Assess Risk` is lost.
8. Verification can start before either Assess Risk or Prepare Evidence has completed.
9. Legal Review becomes mandatory, becomes impossible, or can occur before Assess Risk.
10. The relative independence of Legal Review and verification is collapsed into one fixed order.
11. The loop admits zero trial iterations, reverses Configure Trial and Inspect Trial, permits two iterations without Correct Defect, or permits Correct Defect without a following trial body.
12. Release Change is admitted before verification completion or before a selected Legal Review completes.
13. Archive Change can occur before Release Change or visible behavior can continue after Archive Change.
14. A final trace reaches a marking that merely covers the expected final marking but contains residual tokens elsewhere.
15. Visible labels are removed, renamed, merged, or duplicated without an explicit and validated label mapping.
16. The round-tripped net has bounded visible traces absent from the source or loses bounded source traces.
17. Silent divergence exceeds the validation limit or prevents completion of required witnesses.
18. A process-tree conversion succeeds syntactically but its Petri or BPMN re-encoding fails the source invariants.
19. The BPMN relies on gateway semantics that the target execution engine interprets differently.
20. Visualization generation fails in a release process where the visual artifact is mandatory, even if the underlying semantic model remains separately usable.

# 8. Canonical Representation Recommendation

The authoritative storage representation should remain the **source POWL model**.

POWL directly states the partial-order dependencies, optional XOR with a silent alternative, and binary loop without forcing the overlapping dependencies into a block-structured decomposition. The source definition, its visible-label map, PM4Py version, and a stable source hash should be versioned together.

The recommended stakeholder representation is the **BPMN generated by the primary POWL  accepting Petri net  BPMN pipeline**. It is derivative and should not silently replace the POWL.

The artifact hierarchy should be:

1. **Authoritative:** source POWL.
2. **Executable semantic checkpoint:** accepting Petri net generated directly from POWL.
3. **Stakeholder visualization:** BPMN generated from that accepting Petri net.
4. **Validation artifacts:** round-tripped nets, footprints, reachability summaries, bounded trace sets, witness results, diagnostics, and rendered images.
5. **Optional derivative:** process tree and its BPMN only when the process-tree conversion succeeds and passes the same audit.

Every derivative should be accompanied by:

- source model version or hash;
- PM4Py and Python versions;
- conversion pipeline identifier;
- non-null initial/final marking confirmation where applicable;
- workflow-net and soundness results;
- visible-label and label-multiplicity comparison;
- positive and negative witness results;
- bounded trace-language differences;
- footprints and reachability summaries where successfully computed;
- any conversion, visualization, or validation exceptions;
- the exact exploration bounds.

A process-tree intermediate should be disabled by default for production generation. It may be allowed as an experimental or presentation artifact only if:

1. `convert_to_process_tree(...)` succeeds without coercion;
2. the tree re-encodes to a sound workflow net;
3. all witnesses pass;
4. bounded trace sets and footprints agree;
5. label multiplicity remains acceptable;
6. its BPMN round trip also passes.

Even then, the process tree should not become authoritative.

Future edits should be made only in the canonical POWL. The Petri net, BPMN, process tree, visualizations, and validation reports should be regenerated together. Editing generated BPMN and converting it back into POWL or another canonical format would create round-trip drift and should be prohibited unless handled as an explicit migration with a new invariant audit.

# 9. Residual Uncertainty

Even if every proposed test passes, the following claims remain unestablished:

1. **Unbounded language equivalence:** bounded exploration cannot prove equivalence for every possible number of verification iterations.
2. **True concurrency:** observing both interleavings and even a footprint parallel relation does not fully establish the same concurrency semantics under every execution interpretation.
3. **Converter correctness:** the tests cannot prove that the installed PM4Py algorithms are free from defects outside the explored behavior.
4. **Cross-version stability:** another PM4Py version may generate different routing structures or apply different conversion restrictions.
5. **BPMN engine interoperability:** a third-party BPMN engine may interpret empty branches, gateway synchronization, or loop routing differently from PM4Py.
6. **Tau behavior beyond the cutoff:** valid or divergent behavior requiring more than 40 consecutive silent firings is not explored.
7. **Global reachability equivalence:** equal reachability-state counts and transition counts do not prove labeled transition-system isomorphism or branching equivalence.
8. **Data, time, and resource semantics:** the source model contains no guards, data conditions, durations, roles, calendars, or exception semantics, so conversion validation cannot establish them.
9. **Human interpretation:** annotations reduce but cannot eliminate the possibility that stakeholders infer order from diagram layout.
10. **Marking correspondence across models:** exact final equality is checked within each net, but place identities and token meanings are not mapped one-to-one across converted nets.
