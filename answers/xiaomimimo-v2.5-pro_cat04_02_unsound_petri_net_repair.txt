| 4 | `t_analyze` | `{p_analysis_done: 1, p_waived: 1}` | `t_join_waived` | Analysis completes; **`t_join_normal` is NOT enabled** (needs `p_review_done` which is empty) |
| 5 | `t_join_waived` | `{p_analysis_done: 1, p_decision: 1}` | `t_authorize` | `t_join_waived` consumed only `p_waived`; **`p_analysis_done` is untouched** |
| 6 | `t_authorize` | `{p_analysis_done: 1, sink: 1}` | ** (deadlock)** | A token exists in `sink`, but `p_analysis_done` still holds 1 token. Marking  `fm`. No transition can consume the leftover. |

**Key observation:** `{p_analysis_done: 1, sink: 1}`  `{sink: 1}` (the final marking), but it is not equal to `fm`. This violates both soundness conditions: (a) proper completion requires that no marking reachable after `sink` is marked can have extra tokens; (b) from this deadlock state, there is no firing sequence to `fm`.

## Variant: Authorization Before Analysis Completes

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0–3 | (same as above) | `{p_analysis: 1, p_waived: 1}` | `t_analyze`, `t_join_waived` | Both analysis and join available |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, `t_authorize` | **Authorization possible before analysis** — business rule violated |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `t_analyze` | Case "authorized" but analysis not yet done |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | ** (deadlock)** | Same stranded-token outcome |

In both orderings the final marking `{sink: 1}` is never reached. The leftover token in `p_analysis_done` (or `p_analysis`) cannot be consumed by any transition: `t_join_normal` needs `p_review_done` (always empty on the waiver path), and all other transitions have already consumed their inputs.

# 4. Minimal-Repair Alternatives

**Edit-cost model:** Each atomic edit (add one arc, remove one arc, add one place, remove one place, add one transition, remove one transition) costs 1.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1: Add arc to `t_join_waived`** | Add arc `p_analysis_done`  `t_join_waived` | **1** | Mandatory analysis on both paths; waiver and standard review remain distinct join paths | `t_join_waived` now synchronizes analysis + waiver; authorization requires both to be complete | None significant; `t_join_waived` now mirrors `t_join_normal` structurally |
| **R2: Redirect waiver to shared review-outcome place** | (1) Remove arc `t_waive_review`  `p_waived`; (2) Add arc `t_waive_review`  `p_review_done`; (3) Remove arc `p_waived`  `t_join_waived`; (4) Remove arc `t_join_waived`  `p_decision`; (5) Remove transition `t_join_waived`; (6) Remove place `p_waived` | **6** | Mandatory analysis; single authorization gate; standard review path unchanged | Waiver token routes through `p_review_done` like standard review; `t_join_normal` is the sole synchronization point; the net has one fewer transition and one fewer place | Loss of structural trace distinguishing waiver from standard review at the place level (transition labels still differ); slightly harder to audit from Petri-net topology alone |

**Minimality justification:**

- **R1** is the absolute minimum: a single arc addition makes `t_join_waived` a proper two-input join, requiring both `p_analysis_done` and `p_waived`. No elements are added or removed. This is provably minimal because at least one edit is needed (the defect is a missing dependency), and one edit suffices.
- **R2** is minimal within the "unify join" repair family. The 6 edits cannot be reduced further because: (a) redirecting the waiver output requires removing one arc and adding another (2 edits); (b) `t_join_waived` and `p_waived` become dead code and must be removed to satisfy the workflow-net path condition (3 arc removals + 1 transition removal + 1 place removal = 5 more edits, but the two arcs of `t_join_waived` were already counted with the transition, giving a net of 4 additional edits). The total of 6 is the minimum to achieve a single-join architecture.
- The two repairs are **behaviorally distinct**: R1 preserves two separate synchronization transitions (`t_join_normal` for standard review, `t_join_waived` for waiver), while R2 eliminates `t_join_waived` entirely and routes both review outcomes through a single join (`t_join_normal`). R1 preserves place-level distinguishability; R2 sacrifices it.

import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking

# ================================================================
# Helper: fire a named transition with enabledness check
# ================================================================
def fire_named_transition(net, marking, t_name):
    """Attempt to fire transition t_name.  Return the resulting marking.
       Abort with a message if the transition is not enabled or not found."""
    target = None
    for t in net.transitions:
        if t.name == t_name:
            target = t
            break
    if target is None:
        print(f"  [ERR] Transition '{t_name}' not found in net.")
        return marking

    # Check enabledness: every input arc's source place must hold >= weight tokens
    for arc in target.in_arcs:
        if marking.get(arc.source, 0) < arc.weight:
            needed = {a.source.name for a in target.in_arcs}
            held   = {p.name: c for p, c in marking.items()}
            print(f"  [ERR] '{t_name}' is NOT enabled.")
            print(f"        Needs tokens in: {needed}")
            print(f"        Current marking: {held}")
            return marking

    new_marking = Marking()
    for pl, cnt in marking.items():
        new_marking[pl] = cnt
    for arc in target.in_arcs:
        new_marking[arc.source] -= arc.weight
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]
    for arc in target.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + arc.weight

    print(f"  [OK]  '{t_name}' -> { {p.name: c for p, c in new_marking.items()} }")
    return new_marking

    return {p.name: c for p, c in m.items()}

# 7. Repair Trade-Offs and Residual Risks

**Distinguishability of waiver vs. standard review:**
- Under R1, both `t_waive_review` ("Record Review Waiver") and `t_standard_review` ("Perform Standard Review") remain separate labeled transitions with separate output places (`p_waived` vs. `p_review_done`). They remain fully distinguishable in the model and in any event log derived from it.
- Under R2, the transitions are still labeled distinctly, but both produce a token in `p_review_done`. The place-level structural distinction is lost, meaning a structural analysis tool (without transition labels) cannot distinguish which review path was taken. For log-based conformance this is acceptable; for structural auditing it is a minor loss.

**Duplicate behavior through silent transitions:**
- R1 introduces no new transitions. `t_join_waived` and `t_join_normal` are both silent (label `None`), but they are never both fireable in the same marking (because `p_review_done` and `p_waived` are mutually exclusive). No duplicate trace behavior is introduced.
- R2 removes `t_join_waived`, so the only silent join is `t_join_normal`. No duplication risk.

**Soundness  full business alignment:**
- Soundness guarantees proper completion and absence of deadlocks, but it does not verify that "authorization only occurs after analysis and review are both complete" at the *business-logic* level. For example, soundness would also hold for a net where `t_authorize` consumed tokens directly from `p_analysis` and `p_waived` (skipping the join). Regression tests and declarative constraints (e.g., response/precedence constraints in Declare) should complement the Petri-net verification.

**Regression-test traces:**

| Trace (transition names) | Expected outcome | Purpose |
|---|---|---|
| `t_register  t_split  t_analyze  t_standard_review  t_join_normal  t_authorize` | Accept (reach `fm`) | Standard happy path |
| `t_register  t_split  t_waive_review  t_analyze  t_join_waived  t_authorize` | Accept (reach `fm`) | Waiver happy path — primary repair validation |
| `t_register  t_split  t_waive_review  t_join_waived  t_authorize` (no `t_analyze`) | **Blocked** — `t_join_waived` not enabled without `p_analysis_done` | Ensure analysis is not bypassable under waiver |
| `t_register  t_split  t_analyze  t_waive_review  t_authorize` (skip join) | **Blocked** — `t_authorize` not enabled without `p_decision` | Ensure authorization requires the join |
| `t_register  t_split  t_standard_review  t_join_normal  t_authorize` (no `t_analyze`) | **Blocked** — `t_join_normal` not enabled without `p_analysis_done` | Ensure analysis is mandatory on standard path |

**Detecting accidental bypass of mandatory analysis:**
- At the model level: verify structurally that every path from `p_analysis` to `p_decision` passes through `p_analysis_done` and a synchronization transition. This holds in R1 because both `t_join_normal` and `t_join_waived` have `p_analysis_done` as an input.
- At the log level: check the declarative constraint "every `Authorize Case` event is preceded by both `Perform Analysis` and either `Perform Standard Review` or `Record Review Waiver` in the same case." A violation of the analysis-precedence constraint indicates a bypass.

# 8. Final Recommendation

**Deployment: Repair R1 (add arc `p_analysis_done`  `t_join_waived`).**

R1 is the optimal repair for deployment for three reasons. First, its edit cost is 1 (a single arc addition), making it the provably minimal change that eliminates the defect. Second, it preserves the original modeler's structural intent: two distinct join points for two distinct review outcomes, each now properly synchronizing with mandatory analysis. Third, it carries the lowest regression risk because no existing element is modified or removed—no existing firing sequence on the standard-review path is altered.

**Fallback: Repair R2 (redirect waiver output to `p_review_done`, eliminate `t_join_waived` and `p_waived`).**

R2 is recommended as a fallback because it produces a structurally simpler net (one fewer transition and one fewer place), which is easier to maintain and reason about. However, its higher edit cost (6 operations) and the loss of place-level distinguishability between waiver and standard review make it better suited as a second choice—deployable if, for example, a coding standard mandates a single synchronization point per join or if the model is undergoing a broader refactoring.

Both repairs are behaviorally correct, sound, and aligned with the stated business intent. The choice between them is a trade-off between minimal change (R1) and structural simplicity (R2).
