### Are segment-specific models justified?

- **V3-specific recalibration is provisionally justified.** Its baseline risk, process deterioration, and model error differ materially from V1/V2. A transparent V3 intercept or risk shift is proportionate.
- **A separate V3 model is justified only if V3/routing is known at the diagnosis timestamp, sufficient mature V3 cases exist, and the challenger improves within-V3 discrimination.** Otherwise, use a global model with a V3 indicator or predicted-routing feature.
- **V1 and V2 can initially be pooled.** Their matured rates and remote/process behavior are comparatively stable. June's higher V2 share does not itself justify a separate V2 model.

## 5. Monitoring architecture

### Data and version architecture

Use four linked stores:

1. **Immutable raw-event store:** original source event ID, source system, activity text, timestamp, case ID, and ingestion metadata.
2. **Canonical event and feature layer:** versioned activity mapping, deterministic deduplication, event ordering, diagnosis cutoff, and feature lineage.
3. **Prediction and deployment store:** model version, feature version, score timestamp, score, threshold, eventual diagnostic variant, source, and decision/intervention.
4. **Outcome store:** label value, label-arrival timestamp, outcome version, promised date, and maturity status.

A PM4Py process sidecar should derive DFG, performance-DFG, variant, and temporal-feature summaries from the same canonical event layer. Every metric should carry `mature`, `provisional`, or `blocked` status and the associated DQ, label, and model versions.

### Monitor suite

| Monitor | Core measures | Alert behavior |
|---|---|---|
| **Predictive** | Fixed-vintage AUROC, PR-AUC, Brier, lift, risk-bin breach rate, and score-distribution drift | Raise a model-performance alert only when the cohort is label-mature, DQ-clean, and sufficiently powered. Otherwise mark the result provisional. |
| **Calibration** | Reliability curves, ECE, calibration intercept/slope, observed-to-predicted ratio, and Brier decomposition by month, variant, and source | A stable-ranking/poor-intercept pattern triggers recalibration review. Poor within-segment discrimination triggers feature/model review rather than calibration alone. |
| **Label maturity** | Label-arrival CDF, median/p95 delay, percent mature by SLA, cohort age, and label backlog by variant/source/path | Alarm on the label pipeline, suppress outcome-based retraining, and request API replay. It does **not** automatically trigger retraining. |
| **Data quality** | Unknown activity, missing feature and queue rates, duplicate rate, unmapped variants, diagnosis-anchor errors, schema drift, out-of-order events, and feature-lineage completeness | Critical DQ alarms block training and calibration. If live scoring features are invalid, use the last known-good pipeline or a documented fallback. |
| **Process variant** | V1/V2/V3 shares, first-branch distribution, rare paths, unexpected transitions, and route-known-at-score coverage | A mix alert starts operational and covariate review. It triggers no automatic model change unless mature within-segment performance also changes. |
| **Performance DFG** | Edge median/p90/p95, overdue-part rate, diagnosis-to-repair, and remote-fix duration; V1/V2 as controls | Trigger supplier/process remediation. A coupled mature V3 performance alert may initiate recalibration or retraining review. The future edge itself must not be fed into the diagnosis-time model. |
| **Population** | Source share, rurality, travel distance, device age, and other legitimate context distributions; source × variant coverage | Trigger reweighting, transport, missing-feature, and fairness review. Do not automatically create a source-specific model. |
| **Intervention/deployment** | Model and feature versions, override rate, threshold movement, intervention capacity, false-positive burden, and realized breach reduction | Gate promotion on decision benefit and subgroup effects, not AUROC alone. Monitor model rollback and alert fatigue. |

### Alert dependencies

1. A **label-delay alarm** sets outcome metrics to provisional, keeps process and DQ alarms active, and prevents automatic calibration or retraining.
2. A **critical DQ or lineage alarm** blocks training and calibration and requires a replay. A live scoring failure may require fallback, but not a new model.
3. A **performance-DFG alarm plus mature within-segment predictive deterioration** is evidence for recalibration or retraining. A DFG alarm alone is an operational intervention.
4. A **population-shift alarm** triggers reweighting and transport checks. It changes a model only if it also creates within-population performance gaps.
5. A **predictive alarm** is actionable only if the label-maturity and DQ gates are green.
6. Every challenger must pass fixed-vintage, subgroup, operational-capacity, and intervention-impact checks before promotion.

```python
import pandas as pd
import pm4py

CSV = "field_service_events.csv"
raw = pd.read_csv(CSV)
required = {"case_id", "activity", "timestamp"}
missing = required - set(raw.columns)
if missing:
    raise ValueError(f"Missing columns: {sorted(missing)}")

x = raw.copy()
x["activity_raw"] = x["activity"]
x["timestamp"] = pd.to_datetime(x["timestamp"], utc=True, errors="coerce")
if x["timestamp"].isna().any():
    raise ValueError("Unparseable timestamps")
x["activity"] = x["activity"].fillna("UNKNOWN_ACTIVITY").astype(str).str.strip()

# Canonicalize both sides of the 1-April source rename before any extraction.
diagnosis_aliases = {
    "initial diagnosis completed",
    "diagnostic assessment completed",
}
fold = x["activity"].str.casefold()
x.loc[fold.isin(diagnosis_aliases), "activity"] = "Initial Diagnosis Completed"

# Authoritative duplicate strategy: source event ID. The fallback is deliberately
# conservative; production should not fuzzy-collapse legitimate repeated events.
raw_month = x["timestamp"].dt.strftime("%Y-%m")
if "source_event_id" in x.columns and x["source_event_id"].notna().all():
    x = x.drop_duplicates(subset=["source_event_id"], keep="first")
else:
    x = x.drop_duplicates(
        subset=["case_id", "activity", "timestamp"], keep="first"
    )
dedup_month = x["timestamp"].dt.strftime("%Y-%m")
duplicates_removed_by_month = (
    raw_month.value_counts()
    .subtract(dedup_month.value_counts(), fill_value=0)
    .astype(int)
)

event_cols = ["case_id", "activity", "timestamp"]
log = pm4py.format_dataframe(x[event_cols].copy())

# Case-start timestamp: prefer Case Created, otherwise earliest retained event.
earliest = x.groupby("case_id")["timestamp"].min()
created = (
    x.loc[x["activity"].str.casefold().eq("case created")]
      .groupby("case_id")["timestamp"].min()
)
case_start = created.reindex(earliest.index).fillna(earliest)

months = pd.date_range(
    x["timestamp"].min().floor("D"),
    x["timestamp"].max().floor("D"),
    freq="MS",
)

def edge_median_hours(d, source, target):
    durations = []
    for _, g in d.sort_values(["case_id", "timestamp"]).groupby("case_id"):
        s = g.loc[g["activity"].eq(source), "timestamp"].min()
        if pd.isna(s):
            continue
        t = g.loc[
            g["activity"].eq(target) & g["timestamp"].ge(s), "timestamp"
        ].min()
        if not pd.isna(t):
            durations.append((t - s).total_seconds() / 3600.0)
    return float(np.median(durations)) if durations else np.nan

def temporal_audit(d):
    """Temporal features on the diagnosis prefix, not on the full future trace."""
    try:
        diagnosis = (
            d.loc[d["activity"].eq("Initial Diagnosis Completed")]
             .groupby("case_id")["timestamp"].min()
             .rename("_diagnosis_ts")
        )
        p = d.join(diagnosis, on="case_id")
        p = p.loc[p["timestamp"].le(p["_diagnosis_ts"])].copy()
        p["variant"] = p.groupby("case_id")["activity"].agg(tuple)
        features = pm4py.extract_temporal_features_dataframe(
            p[event_cols + ["variant"]],
            variant="variant",
            timestamp_column="timestamp",
            case_id_key="case_id",
            activity_key="activity",
        )
        feature_cols = [
            c for c in features.columns
            if c not in {"case_id", "variant"}
        ]
        missing_rate = (
            float(features[feature_cols].isna().to_numpy().mean())
            if feature_cols else 0.0
        )
        return len(features), missing_rate, ""
    except Exception as exc:
        return np.nan, np.nan, f"{type(exc).__name__}: {exc}"

def process_row(month, cohort, d, lg, interpretation, temporal=False):
    dfg, _ = pm4py.discover_dfg(lg)
    _, performance = pm4py.discover_performance_dfg(lg)
    variants = pm4py.get_variants(lg)
    counts = Counter(variants)
    variant_counts = {
        " > ".join(k): int(v) for k, v in sorted(counts.items())
    }
    top_variant, top_n = (
        counts.most_common(1)[0] if counts else ((), 0)
    )
    n_cases = d["case_id"].nunique()
    source_col = next(
        (c for c in ("partner", "partner_id", "source") if c in d.columns),
        None,
    )
    temporal_rows, temporal_missing, temporal_error = np.nan, np.nan, ""
    if temporal:
        temporal_rows, temporal_missing, temporal_error = temporal_audit(d)

    return {
        "month": month.strftime("%Y-%m"),
        "cohort": cohort,
        "n_cases": n_cases,
        "n_events": len(d),
        "unknown_activity_share":
            d["activity"].str.upper().eq("UNKNOWN_ACTIVITY").mean(),
        "duplicates_removed":
            int(duplicates_removed_by_month.get(month.strftime("%Y-%m"), 0)),
        "n_variants": len(counts),
        "top_variant": " > ".join(top_variant),
        "top_variant_share": top_n / n_cases if n_cases else np.nan,
        "variant_counts": json.dumps(variant_counts, sort_keys=True),
        "dfg_edges": dfg.number_of_edges(),
        "performance_dfg_edges":
            len(performance) if isinstance(performance, dict) else 0,
        "order_to_part_received_median_h":
            edge_median_hours(x, "Order Part", "Part Received"),
        "diagnosis_to_remote_fix_median_h":
            edge_median_hours(x, "Initial Diagnosis Completed", "Remote Fix"),
        "source_counts":
            json.dumps(d[source_col].value_counts().to_dict())
            if source_col else "",
        "temporal_rows": temporal_rows,
        "temporal_missing_cell_rate": temporal_missing,
        "temporal_error": temporal_error,
        "cohort_interpretation": interpretation,
    }

rows = []
for lo in months:
    hi = lo + pd.offsets.MonthBegin(1)

    # Event-calendar cohort: events occurring in the month. Open paths are
    # right-censored, so this is workload/process evidence, not an outcome cohort.
    cal_df = x.loc[x["timestamp"].ge(lo) & x["timestamp"].lt(hi)].copy()
    cal_log = pm4py.filter_time_range(
        log, str(lo), str(hi), mode="intersect"
    )
    cal_log = pm4py.filter_log(
        lambda e: lo <= pd.Timestamp(e["timestamp"]) < hi, cal_log
    )
    rows.append(process_row(
        lo, "event_calendar", cal_df, cal_log,
        "Events occurring in month; incomplete paths are right-censored.",
        temporal=False,
    ))

    # Case-start cohort: all events for cases started in the month. This is
    # retrospective full follow-up; for a live month-end snapshot, truncate d
    # to timestamp < hi and retain an open-case flag.
    ids = case_start.loc[case_start.ge(lo) & case_start.lt(hi)].index
    start_df = x.loc[x["case_id"].isin(ids)].copy()
    start_log = pm4py.format_dataframe(start_df[event_cols].copy())
    rows.append(process_row(
        lo, "case_start", start_df, start_log,
        "Cases initiated in month with retrospective follow-up; open cases remain censored.",
        temporal=True,
    ))

summary = pd.DataFrame(rows).sort_values(["month", "cohort"])
summary.to_csv("monthly_process_audit.csv", index=False)
print(summary)
```

## 6. Risks of acting on the wrong diagnosis

| Failure mode | Likely consequence | Mitigation |
|---|---|---|
| **Retraining or recalibrating on immature labels** | October's selected labels disproportionately represent short paths and may teach the model that high-risk long paths are safe. A subsequent label arrival can invalidate the model immediately. | Enforce a maturity gate; train only on fixed-vintage matured labels; use censoring weights or competing-risk analysis; shadow new models until a stable label curve is observed. |
| **Calibrating around the April pipeline bug** | Lowering the elevated predicted risks or retraining on corrupted prefixes would encode missingness and wrong diagnosis cutoffs as if they were genuine risk signals. | Quarantine April features, replay from raw events, and verify feature lineage before any calibration or model comparison. Do not use aggregate April ECE as a calibration target. |
| **Ignoring genuine supplier-driven deterioration** | Continuing to treat V3 as a 0.30–0.35 baseline underpredicts a potentially 0.60-plus-risk segment and wastes interventions on lower-risk cases. | Monitor V3-specific conditional calibration, use the part process as an operational trigger, and deploy a provisional transparent V3 adjustment or a new prospectively available supplier-regime feature. |
| **Attributing Partner Z to unfair model behavior without stratified evidence** | A source-only intervention could stigmatize a partner, encode rurality as a proxy, or misattribute supplier and maturity effects to the model. | Compare Partner Z and non-Partner-Z within the same variant; use overlap checks, reweighting, and transport; add legitimate operational context; evaluate calibration, error, and intervention benefit by source. Treat source as an audit dimension, not automatically as a decision feature. |
| **Overreacting to the June routing mix with full retraining** | The model would be unnecessarily churned around a favorable, stable remote process, while missing the later V3 problem. | Use V1/V2 as controls, standardize metrics to fixed mix weights, and reserve retraining for demonstrated within-segment ranking or conditional-outcome failure. |
| **Using future process information as a predictor** | `Part Received` or the observed `Order Part -> Part Received` duration can leak the outcome and produce impressive offline performance that fails immediately after diagnosis. | Enforce feature-available-time checks in the feature store; use future edge duration only for retrospective diagnosis; admit supplier conditions only if they were knowable at scoring. |
| **Comparing aggregate monthly AUROC and ECE without a fixed vintage** | Changes in label selection, case mix, and source composition can be mistaken for model deterioration or improvement, producing false retraining decisions. | Publish fixed-vintage and standardized metrics alongside raw metrics, with label-maturity and DQ status attached to every result. |
| **Allowing alerts to trigger uncontrolled model churn** | Label backlog, data-quality, process, and population alarms could each initiate retraining, creating unstable models and alert fatigue. | Use gated dependencies: labels and DQ must be healthy before model alarms are actionable; process and population alarms initiate investigations; only validated challengers can be promoted, with rollback and an intervention-impact review. |
