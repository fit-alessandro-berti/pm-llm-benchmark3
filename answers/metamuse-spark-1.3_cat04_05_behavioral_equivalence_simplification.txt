# 1. Equivalence Notions

## Observation model
Let `Sigma_vis = {'Open Case','Analyze Revision','Check Revision','Rework Case','Approve Revision','Close Case'}` and `tau` be silent.
A complete run is a firing sequence from initial marking `im` to final marking `fm`. Its **visible trace** is projection onto `Sigma_vis` deleting `tau` / `None`-labelled transitions. `L_vis(M)` is the set of complete visible traces.

**Duplicate visible labels:** distinguished only by **label + occurrence position/count**, not by transition identity. I.e. two `Check Revision` events are indistinguishable except for where they occur in the sequence and how many occur. In particular `|w|_Check` and interleaving order matter for trace equivalence, but which parallel branch instance produced the label does not.

- **Visible trace equivalence after hiding `tau`:** `M1 ~_vis M2` iff `L_vis(M1) = L_vis(M2)` as sets of label sequences. `tau` never appears in `w`; `X(Approve,tau)` creates two visible continuations per position: `... Approve ...` vs `...` (skip). Optional approval therefore doubles branching but does not hide counts of other labels.
- **Bounded visible-language equivalence under P3:** Let `L_P3(M) = { w in L_vis(M) | |w| <= 12 and count_Analyze(w) <= 3 }`. `M1 ~_P3 M2` iff `L_P3(M1)=L_P3(M2)`. This is a finite testable projection. `~_P3` inequivalence implies `~_vis` inequivalence, but `~_P3` equivalence does **not** imply `~_vis` equivalence.
- **Business-relevant equivalence under P1:** No abstraction. `M1 ~_P1 M2` iff `L_vis(M1)=L_vis(M2)` with `Approve Revision` retained as visible and `tau` hidden only. In addition every `w` is judged by predicate `C_P1(w)`: every `Analyze` has its own later `Check` before the next `Rework` or `Close`, `Rework` separates analyses, `Approve` optional per analysis. Since `C_P1` is a property of `w`, language equality implies identical compliant/violating status. Count and placement of `Check` and `Approve` are therefore decisive.
- **Abstracted dashboard equivalence under P2:** Define abstraction `alpha`:
  - drop `Approve Revision` and `tau`;
  - `Open` first, `Close` last enforced;
  - `nA(w)=count_Analyze(w) >=1`, `hasRework(w)=(count_Rework>0)`, `hasCheck(w)=(count_Check>=1)` collapsed to Boolean (`k Checks -> true`);
  - exact interleaving of `Analyze` vs `Check` forgotten.
  Then `M1 ~_P2 M2` iff `alpha(L_vis(M1)) = alpha(L_vis(M2))`. This is `equivalent only under stated abstraction`: information is deliberately lost.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | `*( BodyA, 'Rework Case')` where `BodyA=->(+(Analyze,Check), X(Approve,tau))`. Loop covers both `Analyze` and `Check`. | `*( BodyB, 'Rework Case')` where `BodyB=->(Analyze, X(Approve,tau))`. Loop covers only `Analyze(+Approve)`; single `Check` is sibling in outer `+`. | In A, iteration count `k>=1` forces `k` analyzes **and** `k` checks. In B, `k` analyzes with exactly `1` check regardless of `k`. |
| Minimum Check occurrences | 1 (one iteration yields `Analyze+Check`) | 1 (outer parallel branch must execute once) | Both require at least one check; single-iteration no-approve traces overlap. |
| Maximum Check occurrences | Unbounded, `= k` (linear in reworks) | Exactly 1 | For `k>=2` cardinalities diverge; decisive for P1/P3. |
| Possible placement of Check | Within iteration bounds: after `Open`/`Rework` and before `Approve?/Rework/Close` of same iteration; `Analyze<>Check` order free inside iteration, but `Check` must complete before that iteration's `Approve` starts. Cannot interleave across iterations. | Anywhere between `Open` and `Close` interleaved with whole loop: before first `Analyze`, between `Analyze` and its `Approve`, between `Approve` and `Rework`, between `Rework` and next `Analyze`, after last `Approve` before join. | A forbids `Analyze, Approve, Check` order; B allows it. B allows `Check` far from the `Analyze` it is supposed to cover. |
| Optional approval occurrences | `0..k`, one optional per iteration, strictly after both `Analyze` and `Check` of that iteration. Realized by `X(Approve,tau)`. | `0..k`, one optional per `Analyze`, strictly after that `Analyze` but concurrent with `Check`. `Check` can occur between `Analyze` and its `Approve`. | Same count range, different precedence: `Check < Approve` enforced in A, not in B. Visible language differs even for `k=1` when `Approve` present. |
| Concurrency | Inner `+(Analyze,Check)` per iteration; no concurrency across iterations or with `Rework`. | Outer `+(Check, Loop)`; `Check` concurrent with entire `Analyze/Rework/Approve` loop. Higher interleaving degree. | B has traces where `Check` splits `Analyze->Approve` atomicity of A. |
| Join before Close Case | `->(Open, Loop, Close)`: loop must exit then `Close`. All per-iteration checks/approves join before `Close`. | `->(Open, +(Check,Loop), Close)`: both `Check` and loop must complete/join before `Close`. | Both enforce `Open` first, `Close` last. In A join is sequential; in B join synchronizes parallel `Check` with loop exit. Does not equalize languages. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 operational compliance | `not equivalent` | high | A guarantees per-analysis `Check` before next `Rework`/`Close` with `Analyze=Check=k`; B has exactly one `Check` for `k>1` and allows `Check` detached from `Analyze`; approval-after-check enforced only in A. | Verdict assumes standard interleaving `+` and binary-loop semantics; a stricter P1 requiring `Analyze<Check` would also disqualify `Check<Analyze` interleavings of A. |
| P2 executive dashboard | `equivalent only under stated abstraction` | high | After `alpha` (hide `Approve/tau`, collapse `Check*` to Boolean, keep only `nA` and `hasRework`), both yield exactly `{ (k, k>1, true) \| k>=1 }`. | Equivalence holds only after lossy abstraction; it hides the compliance violation that matters for P1. Not trace equivalence. |
| P3 bounded testing (`<=12` events, `<=3` analyzes) | `not equivalent` | high (for bounded inequivalence) | Witnesses within bound exist in both directions (see Sec.4, all `<=7` events, `<=2` analyzes). Bounded inequivalence soundly implies unbounded inequivalence. | Bounded equivalence would be evidence only; bounded search cannot prove unbounded equivalence due to unbounded loop and state explosion. |

# 4. Counterexample Traces

Notation: `O=Open Case, A=Analyze Revision, C=Check Revision, W=Rework Case, P=Approve Revision, Z=Close Case`. All are complete visible traces (`O` first, `Z` last, `tau` hidden).

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| T-A1 | `O, A, C, W, A, C, Z` | yes | no | second `C`: A requires `k=2 -> 2xC`; B allows only `1xC`. `W` separates two analyses, each with own `C` in A. | P1, P3 |
| T-A2 | `O, A, C, P, W, C, A, P, Z` | yes | no | two `C` + two `P` each after its iteration's `C`. B cannot produce `2xC`; also B would allow `P` before `C` but here `C<P` per iteration fits A. Contains two analysis attempts. | P1, P3 |
| T-B1 | `O, A, C, W, A, Z` | no | yes | single `C` for two `A`s separated by `W`. A would need `A,C,W,A,C`; missing second `C` violates per-iteration scope. Contains two analysis attempts. | P1, P3 |
| T-B2 | `O, A, P, C, Z` | no | yes | `P` before `C`: A requires `+(A,C)` join before `X(P,tau)`, so `C<P` mandatory; B's outer `+` lets `C` interleave after `P`. Single iteration suffices. | P1, P3 |
| T-B3 (strengthening) | `O, A, P, C, W, A, Z` | no | yes | combines both differences: `1xC` for `2xA` and `P` before `C` in first iteration. | P1 |

**Why valid:**
- T-A1 in A: iter1 `A\|\|C` as `A,C`, no `P` via `tau`, `W`, iter2 `A,C`, exit. In B: any complete run has exactly one `C`; `2xC` impossible, so rejected.
- T-A2 in A: iter1 `A,C,P`, `W`, iter2 `C,A,P` (parallel allows `C<A`). In B rejected for `2xC`.
- T-B1 in B: loop `A,W,A` (no `P` via `tau`), `C` scheduled between first `A` and `W`. In A rejected: two iterations need two `C`s.
- T-B2 in B: loop `A,P`, `C` after `P` before join. In A rejected: `P` cannot precede `C`.

**Effect of optional `Approve` and hidden `tau`:** `X(P,tau)` means each `Analyze` yields two visible variants (with/without `P`) with no visible marker for the skip. Hiding `tau` does not merge `P`-present vs `P`-absent traces, nor does it hide extra `C`s. Thus T-A1/T-B1 distinguish models even with zero `P`s (pure `tau` path), while T-A2/T-B2 show `P` placement is independently distinguishing. An observer seeing only visible labels can count `C`s and order `C` vs `P` to decide inclusion; `tau` adds no confusion.

# 5. Bounded Comparison Code

```python
import pm4py
from collections import Counter, deque

tree_str_A = "->('Open Case', * (-> (+('Analyze Revision','Check Revision'), X('Approve Revision',tau)), 'Rework Case'), 'Close Case')"
tree_str_B = "->('Open Case', +('Check Revision', * (-> ('Analyze Revision', X('Approve Revision',tau)), 'Rework Case')), 'Close Case')"

tree_A = pm4py.parse_process_tree(tree_str_A)
tree_B = pm4py.parse_process_tree(tree_str_B)

net_A, im_A, fm_A = pm4py.convert_to_petri_net(tree_A)
net_B, im_B, fm_B = pm4py.convert_to_petri_net(tree_B)

print("Soundness A:", pm4py.check_soundness(net_A, im_A, fm_A, print_diagnostics=True))
print("Soundness B:", pm4py.check_soundness(net_B, im_B, fm_B, print_diagnostics=True))

def is_silent(trans):
    lbl = getattr(trans, 'label', None)
    return lbl is None or lbl == 'tau'

def fire(marking, trans):
    # marking: Counter(place->tokens)
    new_m = Counter(marking)
    for arc in trans.in_arcs:
        p = arc.source
        new_m[p] -= 1
        if new_m[p] <= 0 and new_m[p] == 0:
            del new_m[p]
        assert new_m[p] >= 0 if p in new_m else True
    for arc in trans.out_arcs:
        p = arc.target
        new_m[p] = new_m.get(p, 0) + 1
    # remove zeros
    return Counter({p: c for p, c in new_m.items() if c > 0})

def marking_key(m):
    return frozenset((id(p), c) for p, c in m.items())

def fm_equals(m, fm):
    return Counter({id(p): c for p, c in m.items() if c > 0}) == Counter({id(p): c for p, c in fm.items() if c > 0})

def bounded_language(net, im, fm, max_vis=12, max_analyze=3, max_total_steps=40):
    # Exhaustive BFS over (marking, visible-tuple) with explicit bounds.
    # Handles silent transitions without advancing visible length,
    # prunes by visible length and Analyze count, avoids re-exploring
    # same (marking, visible-trace) state, requires exact fm equality.
    lang = set()
    start = Counter(im)
    queue = deque()
    queue.append((start, ()))
    visited = set()
    visited.add((marking_key(start), ()))
    while queue:
        marking, vis = queue.popleft()
        if fm_equals(marking, fm):
            # complete trace within bound -> record (fm may still enable nothing)
            lang.add(vis)
            # do not extend beyond final marking
            continue
        if len(vis) > max_vis:
            continue
        if len(vis) >= max_vis and False:
            pass
        enabled = pm4py.get_enabled_transitions(net, marking)
        for t in enabled:
            nm = fire(marking, t)
            if is_silent(t):
                nvis = vis
                # bound silent exploration: limit total steps via visited + queue size;
                # silent loops pruned by (marking, vis) visited check
                key = (marking_key(nm), nvis)
                if key not in visited:
                    # prevent infinite silent wandering: also bound path length implicitly
                    visited.add(key)
                    queue.append((nm, nvis))
            else:
                lbl = t.label
                if len(vis) + 1 > max_vis:
                    continue
                nvis = vis + (lbl,)
                if sum(1 for x in nvis if x == 'Analyze Revision') > max_analyze:
                    continue
                key = (marking_key(nm), nvis)
                if key not in visited:
                    visited.add(key)
                    queue.append((nm, nvis))
    return lang

lang_A = bounded_language(net_A, im_A, fm_A, max_vis=12, max_analyze=3)
lang_B = bounded_language(net_B, im_B, fm_B, max_vis=12, max_analyze=3)

print(f"|L_P3(A)|={len(lang_A)} |L_P3(B)|={len(lang_B)}")
only_A = sorted(set(lang_A) - set(lang_B))
only_B = sorted(set(lang_B) - set(lang_A))
print("Unique to A (sample):")
for w in only_A[:20]:
    print(list(w))
print("Unique to B (sample):")
for w in only_B[:20]:
    print(list(w))
print(f"counts unique: A-only={len(only_A)} B-only={len(only_B)}")

# --- Heuristic / random playout is NOT exhaustive ---
# If instead we used pm4py.play_out(tree_A, ...) we would only sample
# stochastically up to a requested number of traces. Absence of a
# counterexample in a sample proves nothing; presence disproves equivalence.
# The BFS above is exhaustive *modulo the P3 bound* (all complete visible
# traces with <=12 events and <=3 Analyzes) because every reachable
# (marking, visible-prefix) within the bound is dequeued, silent steps
# do not escape the visited-pruning, and only fm-equal markings are accepted.
```

# 6. Stochastic and Footprint Comparison

- `pm4py.discover_footprints(...)` computes directly-follows / causality / parallelism relations (`->`, `||`, `#`) from the reachability graph or log. Useful to show that `A` has `A||C` per iteration but `C->P` always, while `B` has `A||C`, `P||C`, `W||C` globally. Difference in footprint matrix supports inequivalence but equal footprints would not imply language equality (footprints collapse long-term counts and loop-exit dependencies; e.g. `a*` vs `a+` variants or `1xC` vs `kxC` can share footprints).
- `pm4py.get_stochastic_language(...)` returns distribution over traces given transition weights/probabilities. `pm4py.compute_emd(language1, language2)` is Earth Mover's Distance between two stochastic languages under Levenshtein cost. Low EMD means statistically similar, not equivalent; EMD=0 on finite samples still does not prove infinite-language equality, and depends on declared probabilities.

print(fp_A)

# Compare: look for ('Analyze Revision','Check Revision') parallel in both,

# and ('Check Revision','Rework Case') never-direct in A vs interleaved in B.

**Why insufficient for proof:** footprints are binary abstractions (lose multiplicities: `C=1` vs `C=k` invisible if `C` can follow/precede same activities); stochastic EMD depends on assumed weights and trace cutoff, and `EMD0` can arise for very different infinite languages with similar short-trace mass. They are evidence, not decision procedures for `~_vis`.

# 7. Complexity Comparison

Structural counts via tree traversal (operator nodes + leaf labels). Pseudocode valid for `pm4py` `ProcessTree` (`tree.operator`, `tree.children`, `tree.label`):

```python
import pm4py

def tree_stats(t):
    # returns (total_nodes, depth_edges, n_visible_leaves, n_silent_leaves, labels)
    if not t.children:  # leaf
        lbl = t.label
        is_silent = (lbl is None or lbl == 'tau')
        return (1, 0, 0 if is_silent else 1, 1 if is_silent else 0, [lbl])
    child_stats = [tree_stats(c) for c in t.children]
    total = 1 + sum(s[0] for s in child_stats)
    depth = 1 + max(s[1] for s in child_stats)
    nvis = sum(s[2] for s in child_stats)
    nsil = sum(s[3] for s in child_stats)
    labs = []
    for s in child_stats:
        labs += s[4]
    return (total, depth, nvis, nsil, labs)

for name, tr in [("A", tree_A), ("B", tree_B)]:
    tot, dep, nv, ns, labs = tree_stats(tr)
    vis_labs = [l for l in labs if l not in (None, 'tau')]
    dup = len(vis_labs) - len(set(vis_labs))
    print(name, f"nodes={tot} depth={dep} visLeaves={nv} silLeaves={ns} dupVisible={dup} labels={labs}")

print("simplicity A:", pm4py.simplicity_petri_net(net_A, im_A, fm_A))
print("simplicity B:", pm4py.simplicity_petri_net(net_B, im_B, fm_B))
```

Derived manually (to be confirmed by running above):

- **Node count:** both 12 (5 operators: `->,*,->,+,X` + 7 leaves). No syntactic duplicate labels (`dup=0`); repetition arises only via loop.
- **Depth (edges rootleaf):** A = 4 (e.g. `->  *  ->  X  Approve`), B = 5 (e.g. `->  +  *  ->  X  Approve`). B one level deeper due to outer parallel wrapping the loop.
- **Visible leaves:** 6 each (`Open, Analyze, Check, Rework, Approve, Close`); **silent leaves:** 1 each (`tau`).
- **Converted Petri net simplicity:** must be obtained by executing `simplicity_petri_net`; do not invent values here. Expected qualitative: A and B have similar place/arc counts (loop + AND-split/join), B slightly less simple (extra parallel branch spanning loop increases places/arcs and lowers simplicity). Report exact numbers only from tool output.

# 8. Simplified Model

Target semantics: **P1 compromise that also preserves P2 abstraction.** P1 is normative for compliance (per-analysis check, visible approval); P2 is lossy and must not drive design. Full parallel interleaving (`Check` before `Analyze`) is not required by P1's wording and complicates audit, so sequentialize to `Analyze -> Check -> optional Approve` per iteration. This keeps P1 counts/placement exact up to the removed `C<A` interleaving, preserves P2 exactly, and weakens full `~_vis` (subset of A).

1. Compact process-tree (POWL equivalent: `sequence(Open, loop(sequence(Analyze,Check,xor(Approve,skip)), Rework), Close)`):

```text
->('Open Case', *(->('Analyze Revision','Check Revision',X('Approve Revision',tau)),'Rework Case'),'Close Case')
```

2. Self-contained PM4Py code:

```python
import pm4py
simplified_model = pm4py.parse_process_tree(
  "->('Open Case', *(->('Analyze Revision','Check Revision',X('Approve Revision',tau)),'Rework Case'),'Close Case')"
)
snet, sim, sfm = pm4py.convert_to_petri_net(simplified_model)
print(pm4py.check_soundness(snet, sim, sfm, print_diagnostics=True))
print("simplicity simplified:", pm4py.simplicity_petri_net(snet, sim, sfm))
```

Structural comparison: simplified has 4 operators (`->,*,->,X`) + 7 leaves = **11 nodes** vs 12/12; depth 4 edges (like A, shallower than B); 6 visible +1 silent leaves same; 0 duplicates; **no `+` operator** (removes concurrency). Converted net has fewer places/arcs (no AND-split/join), hence strictly higher `simplicity_petri_net` and easier audit. Qualitatively simpler than both originals.

3. Preservation table (relative to P1 intent):

| Property | Status | Comment |
|---|---|---|
| `Open` first, `Close` last | exact | same top-level `->` |
| `Analyze count = Check count = k`, `Rework = k-1` | exact | loop body has one of each; matches A, fixes B |
| Each `Check` after its `Analyze` before next `Rework`/`Close` | exact (strengthened) | sequential `A<C` enforces compliant order; A allowed `C<A`, B allowed detached `C` |
| Optional `Approve` per analysis, visible | exact in count, weakened in order | still `0..k`, but now always `C<P` (A allowed only `C<P` too for this order; B allowed `P<C` lost) |
| Parallel `A\|\|C` interleaving (`C` before `A`) | lost | deliberate: `O,C,A,Z` of A rejected; audit simplification |
| Outer-concurrent single-`Check` behavior of B | lost (intended) | non-compliant; must be rejected |
| P2 abstraction `(nA,hasRework,hasCheck)` | exact | yields same `{(k,k>1,true)}`, so dashboard unchanged |
| Full `~_vis` vs A/B | weakened (subset) | simplified `L`  `L(A)`; incomparable with `L(B)`; single model cannot preserve all three views |

4. Regression (must accept) and negative (must reject) traces (`O,A,C,W,P,Z` as above):

- R1 `O,A,C,Z` — single analysis, checked, auto-approved (tau path). Accepted.
- R2 `O,A,C,P,W,A,C,P,Z` — two iterations, each checked then approved. Accepted.
- R3 `O,A,C,W,A,C,Z` — two iterations, no approvals. Accepted (cf. T-A1).
- N1 `O,A,C,W,A,Z` — second analysis unchecked. Rejected (B-like violation; cf. T-B1).
- N2 `O,A,P,C,Z` — approval before check. Rejected (B-like interleaving; cf. T-B2). Also `O,C,A,Z` rejected (parallel interleaving sacrificed for simplicity).

# 9. Final Recommendation

- **P1 (operational compliance):** use **Model A only**; Model B is non-compliant (single check for many analyses, detached placement, `P<C` allowed). Neither original enforces `A<C` strictly — if audit requires check-after-analysis, adopt the **simplified model**, which strengthens A to sequential `A,C,P?` and should replace A after stakeholder sign-off on losing `C<A`.
- **P2 (executive dashboard):** either original or simplified suffices — all three are `~_P2`-equivalent. Prefer simplified for communication (no parallelism to explain).
- **P3 (bounded testing):** use bounded comparison only as regression harness (e.g. Sec.5 code with `<=12/<=3`). **Warning:** bounded equivalence/exhaustion does not prove unbounded `~_vis`; loops make languages infinite, sampling via `play_out` proves nothing when no counterexample is found, and EMD/footprint similarity never establishes trace equivalence. A bounded pass must be paired with structural reasoning (loop scope, Check cardinality, `C<P` precedence) and the counterexamples in Sec.4. Do not replace A by B on the basis of dashboard equality or short-trace similarity.
