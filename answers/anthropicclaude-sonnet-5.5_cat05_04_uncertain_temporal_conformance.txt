## 1. Normalization Assumptions

**Interval construction.** For each event I take the following steps.
1. Build the recorded-clock interval from the display resolution.
2. Convert local wall-clock time to UTC, using alternative folds where a DST fold is ambiguous.
3. Apply the clock correction. With `clock_offset = recorded  true  [a,b]`, the true time is `recorded  offset`. So the true interval is `[recorded_lo  b, recorded_hi  a]`.

| Source | Recorded-clock interval | True-time interval |
|---|---|---|
| HUB, exact second, ±0.5 s, offset ±1 s | t ± 0.5 s | t ± 1.5 s |
| OPS-BER, floor minute, offset [90,+120] s | [t, t+60 s) | [t120 s, t+150 s) |
| SENSOR, round to 10 s, offset ±5 s | t ± 5 s | t ± 10 s |
| VENDOR-NY, floor minute, offset ±180 s | [t, t+60 s) | [t180 s, t+240 s) |
| LEGACY-BER, floor minute, offset ±60 s | [t, t+60 s) | [t60 s, t+120 s) |
| MOBILE-LON, round minute, offset ±300 s | t ± 30 s | t ± 330 s |

- Upper ends of "floor" intervals are open suprema (:59.999 is treated as :60). No conclusion here sits within 1 ms of a threshold.
- Time zones: CEST = UTC+2, EDT = UTC4, BST = UTC+1.

**DST fold (T-405).**
- 2025-10-26 02:00–02:59 local is ambiguous. Fold 0 is CEST (UTC+2), so 02:xx becomes 00:xx UTC. Fold 1 is CET (UTC+1), so 02:xx becomes 01:xx UTC.

- I prune combinations using the ingestion order Alert < Start < Containment, read as a causal occurrence-order assumption.
- Ingestion order is only moderate evidence of occurrence order. I therefore also report the unpruned case.
- Pruning removes fold combinations but does not make the surviving timestamps exact. The surviving intervals keep their full ±60 s and minute-floor uncertainty.

```python
# ---------------------------------------------------------------- interval normalisation
def is_ambiguous(naive, tz):
    d, z = naive.to_pydatetime(), ZoneInfo(tz)
    return d.replace(tzinfo=z, fold=0).utcoffset() != d.replace(tzinfo=z, fold=1).utcoffset()

def local_to_utc(naive, tz, fold):
    d = naive.to_pydatetime().replace(tzinfo=ZoneInfo(tz), fold=fold)
    return pd.Timestamp(d.astimezone(timezone.utc))

def event_intervals(rec, system, offset=None, delay_s=0.0):
    """Resolution first, then tz/fold conversion, then clock correction (true = recorded - offset).
    Returns one dict per DST-fold alternative (a list = union of alternatives)."""
    tz = TZ[system]; before, after = RES[system]
    a, b = offset if offset is not None else OFF[system]
    t = pd.Timestamp(rec)
    lo_l, hi_l = t - pd.Timedelta(seconds=before), t + pd.Timedelta(seconds=after)
    folds = [0, 1] if (is_ambiguous(lo_l, tz) or is_ambiguous(hi_l, tz)) else [0]
    out = []
    for f in folds:
        lo = local_to_utc(lo_l, tz, f) - pd.Timedelta(seconds=b) - pd.Timedelta(seconds=delay_s)
        hi = local_to_utc(hi_l, tz, f) - pd.Timedelta(seconds=a)
        out.append({"fold": f if len(folds) > 1 else None, "lo": lo, "hi": hi})
    return out

def trim_chain(chain):
    """Bounds-consistency for a chain t1<=t2<=...; returns trimmed intervals or None if infeasible."""
    lo, hi = [c[0] for c in chain], [c[1] for c in chain]
    for i in range(1, len(chain)):
        lo[i] = max(lo[i], lo[i - 1])
    for i in range(len(chain) - 2, -1, -1):
        hi[i] = min(hi[i], hi[i + 1])
    return None if any(l > h for l, h in zip(lo, hi)) else list(zip(lo, hi))

def build_combos(case, cfg):
    opts = {}
    for act, rec, sysname in OBS[case]:
        opts[act] = event_intervals(rec, sysname, cfg.get("offset", {}).get(act), cfg.get("delay", {}).get(act, 0.0))
    for act, (src, lo_s, hi_s) in DERIVED.get(case, {}).items():
        opts[act] = [{"fold": o["fold"], "lo": o["lo"] + pd.Timedelta(seconds=lo_s),
                      "hi": o["hi"] + pd.Timedelta(seconds=hi_s)} for o in opts[src]]
    acts, combos = list(opts), []
    for pick in itertools.product(*[range(len(opts[a])) for a in acts]):
        cur = {a: (opts[a][i]["lo"], opts[a][i]["hi"]) for a, i in zip(acts, pick)}
        folds = {a: opts[a][i]["fold"] for a, i in zip(acts, pick)}
        chain = [a for a in cfg.get("order", []) if a in cur]
        if chain:
            t = trim_chain([cur[a] for a in chain])
            if t is None:
                continue                      # this fold combination is causally impossible
            cur.update(dict(zip(chain, t)))
        combos.append((cur, folds))
    return combos

# ---------------------------------------------------------------- durations and classification
def merge(iv):
    out = []
    for l, h in sorted(iv):
        if out and l <= out[-1][1]:
            out[-1][1] = max(out[-1][1], h)
        else:
            out.append([l, h])
    return [tuple(x) for x in out]

def durations(combos, a, b, ordered):
    out = []
    for cur, _ in combos:
        if a in cur and b in cur:
            lo = (cur[b][0] - cur[a][1]).total_seconds()
            hi = (cur[b][1] - cur[a][0]).total_seconds()
            out.append((max(lo, 0.0) if ordered else lo, hi))
    return merge(out)

def _label(can_pass, can_viol):
    if not can_viol: return "CERTAIN_PASS"
    if not can_pass: return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

def cls_le(iv, limit):
    return _label(any(l <= limit for l, h in iv), any(h > limit for l, h in iv))

def cls_band(iv, lo, hi):
    return _label(any(l <= hi and h >= lo for l, h in iv), any(l < lo or h > hi for l, h in iv))

def guarded(iv, ordered, fn, *args):
    if not iv: return "INDETERMINATE"
    if not ordered and any(l < 0 for l, h in iv): return "INDETERMINATE"   # causally impossible support
    return fn(iv, *args)

def fmt(iv): return "; ".join(f"[{l:.1f},{h:.1f}]" for l, h in iv)

# ---------------------------------------------------------------- run interval analysis
rows, event_rows, primary_combos = [], [], {}
for case in OBS:
    for k, (sname, cfg) in enumerate(SCEN[case]):
        combos = build_combos(case, cfg)
        if k == 0: primary_combos[case] = combos
        order = cfg.get("order", [])
        for a in {a for cur, _ in combos for a in cur}:
            ivs = merge([(cur[a][0].value / 1e9, cur[a][1].value / 1e9) for cur, _ in combos if a in cur])
            event_rows.append({"case": case, "scenario": sname, "activity": a,
                               "utc_intervals": "; ".join(f"[{pd.Timestamp(l, unit='s', tz='UTC').isoformat()}, "
                                                          f"{pd.Timestamp(h, unit='s', tz='UTC').isoformat()}]" for l, h in ivs)})
        pairs = {"S1": SLA["S1"][:2], "S2": SLA["S2"][:2], "S3": SLA["S3"][:2]}
        pairs.update({f"{a}->{b}": (a, b) for (a, b) in TEMPORAL_PROFILE})
        for name, (a, b) in pairs.items():
            ordered = a in order and b in order
            iv = durations(combos, a, b, ordered)
            if not iv: continue
            if name in SLA:
                for tol in TOLERANCES_S:
                    rows.append({"case": case, "scenario": sname, "test": name, "param": f"tol+{tol//60}min",
                                 "durations_s": fmt(iv), "class": guarded(iv, ordered, cls_le, SLA[name][2] + tol)})
            else:
                mean, sd = TEMPORAL_PROFILE[(a, b)]
                for z in ZETAS:
                    rows.append({"case": case, "scenario": sname, "test": name, "param": f"zeta={z}",
                                 "durations_s": fmt(iv), "class": guarded(iv, ordered, cls_band, mean - z*sd, mean + z*sd)})

events_df = pd.DataFrame(event_rows)
results = pd.DataFrame(rows)
pd.set_option("display.width", 250, "display.max_colwidth", 120, "display.max_rows", 500)
print(events_df.sort_values(["case", "scenario", "activity"]).to_string(index=False))
print(results.pivot_table(index=["case", "scenario", "test", "durations_s"], columns="param",
                          values="class", aggfunc="first").to_string())

# ---------------------------------------------------------------- MIDPOINT LOG (LOSSY APPROXIMATION)
# Collapses every event to the midpoint of its primary-scenario hull. It discards uncertainty and is
# used ONLY as a comparison. PM4Py does not resolve timestamp uncertainty.
PROFILE_ACTS = {A, I, C, X}
mid_rows = []
for case, combos in primary_combos.items():
    hull = {}
    for cur, _ in combos:
        for a, (lo, hi) in cur.items():
            if a in PROFILE_ACTS:
                l, h = hull.get(a, (lo, hi)); hull[a] = (min(l, lo), max(h, hi))
    for a, (lo, hi) in hull.items():
        mid_rows.append({"case_id": case, "activity": a, "timestamp": lo + (hi - lo) / 2})
mid_df = pd.DataFrame(mid_rows).sort_values(["case_id", "timestamp"]).reset_index(drop=True)

def midpoint_deviations(mid_df):
    """Returns {(case, zeta): set of (a,b) flagged by pm4py}. ASSUMPTION: each deviation is a tuple whose
    first two elements are the source and target activities (true for recent pm4py versions). The shape
    may differ by version, so it is isolated here; conformance is run one case at a time so the output
    order does not need to be mapped back."""
    try:
        import pm4py
    except ImportError:
        print("pm4py not installed: midpoint comparison skipped.")
        return None
    log_df = pm4py.format_dataframe(mid_df.copy(), case_id="case_id", activity_key="activity",
                                    timestamp_key="timestamp")
    flagged = {}
    for z in ZETAS:
        for case, sub in log_df.groupby("case:concept:name"):
            try:
                res = pm4py.conformance_temporal_profile(sub.sort_values("time:timestamp"),
                                                         TEMPORAL_PROFILE, zeta=z)
                devs = res[0] if res else []
                flagged[(case, z)] = {(d[0], d[1]) for d in devs}
            except Exception as e:                                   # version-shape problems
                print(f"pm4py conformance failed for {case}, zeta={z}: {e}")
                flagged[(case, z)] = None
    return flagged

flagged = midpoint_deviations(mid_df)

# ---------------------------------------------------------------- compare midpoint vs interval
if flagged is not None:
    comp = []
    prim = {c: SCEN[c][0][0] for c in OBS}
    for r in results[results.apply(lambda r: r["scenario"] == prim[r["case"]] and r["param"].startswith("zeta"), axis=1)].itertuples():
        a, b = r.test.split("->")
        z = int(r.param.split("=")[1])
        f = flagged.get((r.case, z))
        if f is None: continue
        mid_dev = (a, b) in f
        if r._7 == "CERTAIN_VIOLATION":
            msg = "agree" if mid_dev else "INCONSISTENT: check trimming"
        elif r._7 == "CERTAIN_PASS":
            msg = "INCONSISTENT: check trimming" if mid_dev else "agree"
        else:
            msg = "midpoint flags; violation not certain" if mid_dev else "midpoint HIDES possible violation"
        comp.append({"case": r.case, "pair": r.test, "zeta": z, "interval_class": r._7,
                     "midpoint_deviation": mid_dev, "comparison": msg})
    print(pd.DataFrame(comp).to_string(index=False))
    print("Note: midpoint results use a lossy approximation; they are not evidence of true conformance.")
```

**Notes on the code.**
- `r._7` refers to the `class` column, which itertuples renames because `class` is a Python keyword. If your pandas version numbers it differently, the comparison step is the one place to adapt.
- I have not executed this code. Expected midpoint behaviour is by hand calculation only. For example, T-401 AI has a midpoint of 855 s, which would be flagged at zeta 1 but not at zeta 2, even though the interval class is PV for both.
- T-408 IC has a midpoint of exactly 3300 s, the z2 band edge, so a float-equality quirk is possible.
- The PM4Py deviation format is the version-sensitive part and is isolated in `midpoint_deviations`.

## 6. Evidential Sufficiency

**Indeterminate or untestable results (missing activity evidence).**
- T-402, T-403, T-404, T-405, T-406, T-407 and T-409: S3 and CClose are untestable. A Close_Incident event with HUB-grade timing would settle them. A close with only a date would not, because 36 h needs second-level precision.
- T-405 without the order assumption: semantic evidence that ingestion order equals occurrence order, or a logged DST fold or UTC-native timestamp.

**Possible violations.**

|---|---|---|
| T-401 S1, profile AI | A start timestamp from a source with 3 s total uncertainty, or a measured OPS-BER offset at that time narrow enough to place the start entirely before 08:14:58.5 (pass) or after 08:15:01.5 (violation) | Stronger synchronization |
| T-402 S2 | Same kind of narrowing: start  10:02:01.5  2700 s = 09:17:01.5 makes it a pass, and start < 09:16:58.5 makes it a violation. A HUB-native start event resolves it | Stronger synchronization |

## 7. Governance Recommendation

**Storage and provenance.**
- Store all timestamps in UTC with the original raw value, local time zone and system of record retained beside them.
- Keep resolution metadata per source (exact, floor minute, round 10 s, round minute) so intervals can be reconstructed rather than guessed.
- Retain the causal identifiers and lineage needed to link related events across systems.

**Clock and offset telemetry.**
- Log source offset telemetry per event or per hour, not a daily bound. T-409 shows the cost: a missing diagnostic turned a certain pass into a possible violation.
- Require a valid offset bound for any source used to adjudicate an SLA. Record the source of each bound (measured, engineering estimate).

**Time zones and DST.**
- Log the DST fold or UTC offset with every local timestamp. T-405 needed inference from ingestion order because the fold was missing.
- Prefer UTC-native emission from legacy systems, or emit the UTC offset with the local time.

**Lifecycle and semantics.**
- Distinguish start from complete events, and sent from received events, in the schema (T-404, T-407).
- Record the semantics of user-entered times: whether the field is event time, entry time or user-declared time. Log both event time and entry time for mobile input, so the T-406 ambiguity disappears.
- Emit delivery acknowledgments so Alert_Received is an observed event.

**Vendor and external sources.**
- Require event-level synchronization or a trusted receipt timestamp on the internal side (T-403).

**Enforcement policy for interval overlap.**
- CERTAIN_VIOLATION (T-402 S1; T-408 S2 and S3): enforceable as breaches, with the interval bounds cited.
- POSSIBLE_VIOLATION: treat as a review flag and do not penalize automatically. Escalate for evidence collection when the potential excess is  Medium or the evidence is Low-confidence.
- INDETERMINATE: not enforceable.
- A tolerance or grace policy should be declared in advance and applied to the limit, not to the evidence. T-402 shows that a 5 min grace still leaves a possible violation.
- Report worst-case exceedance and midpoint diagnostics as supplements, never as a substitute for the interval classification.
