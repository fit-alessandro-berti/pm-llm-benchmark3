# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|----------|-------------|------------------|---------------|-------------------|
| **Primary: POWL  accepting Petri net  BPMN** | `convert_to_petri_net(source_powl)`  `convert_to_bpmn(net, im, fm)` | Preserves all concurrency and ordering constraints; direct representation of POWL semantics | BPMN may introduce gateway ambiguity; silent transitions may be lost in visualization | Petri net conversion fails or produces unsound net |
| Secondary: POWL  accepting Petri net  process tree  BPMN | `convert_to_petri_net(source_powl)`  `convert_to_process_tree(net, im, fm)`  `convert_to_bpmn(tree)` | Block-structured representation may be more readable; easier to validate | Process tree conversion may fail due to non-block-structured behavior; may lose concurrency | Process tree conversion raises exception |

    tree_from_net = pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)

    # Tree to BPMN
    bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
    pm4py.save_vis_bpmn(bpmn_from_tree, "conversion_output/tree_to_bpmn.png")

    # Round-trip: BPMN to Petri net
    net_from_bpmn_tree, im_from_bpmn_tree, fm_from_bpmn_tree = pm4py.convert_to_petri_net(bpmn_from_tree)
    pm4py.save_vis_petri_net(net_from_bpmn_tree, im_from_bpmn_tree, fm_from_bpmn_tree, "conversion_output/bpmn_tree_to_petri.png")

    tree_success = True
    tree_bpmn = bpmn_from_tree
    tree_net = net_from_bpmn_tree
    tree_im = im_from_bpmn_tree
    tree_fm = fm_from_bpmn_tree
except Exception as e:
    print(f"Process tree conversion failed: {str(e)}")
    tree_success = False

# 4. Round-trip: BPMN to Petri net (primary pipeline)
net_from_bpmn_net, im_from_bpmn_net, fm_from_bpmn_net = pm4py.convert_to_petri_net(bpmn_from_net)
pm4py.save_vis_petri_net(net_from_bpmn_net, im_from_bpmn_net, fm_from_bpmn_net, "conversion_output/bpmn_net_to_petri.png")

# 5. Soundness diagnostics
print("\nSoundness check for POWL-derived Petri net:")
soundness_powl = pm4py.check_soundness(net_from_powl, im_from_powl, fm_from_powl, print_diagnostics=True)

print("\nSoundness check for BPMN-derived Petri net (primary):")
soundness_bpmn_net = pm4py.check_soundness(net_from_bpmn_net, im_from_bpmn_net, fm_from_bpmn_net, print_diagnostics=True)

if tree_success:
    print("\nSoundness check for BPMN-derived Petri net (tree intermediate):")
    soundness_bpmn_tree = pm4py.check_soundness(tree_net, tree_im, tree_fm, print_diagnostics=True)

# 6. Footprint comparison
print("\nFootprint comparison:")
footprint_powl = pm4py.discover_footprints(net_from_powl, im_from_powl, fm_from_powl)
footprint_bpmn_net = pm4py.discover_footprints(net_from_bpmn_net, im_from_bpmn_net, fm_from_bpmn_net)
print("POWL Petri net footprint:", footprint_powl)
print("BPMN Petri net footprint:", footprint_bpmn_net)

if tree_success:
    footprint_bpmn_tree = pm4py.discover_footprints(tree_net, tree_im, tree_fm)
    print("BPMN Tree Petri net footprint:", footprint_bpmn_tree)

# 5. Round-Trip Validation Code

```python
from pm4py.simulation.playout import playout
from pm4py.objects.log.obj import EventLog, Trace, Event
from pm4py.objects.petri_net.utils import reachability_graph
import itertools

def create_witness_trace(event_names):
    """Create a trace from event names, filtering out None (silent) transitions"""
    trace = Trace()
    for name in event_names:
        if name is not None:  # Skip silent transitions
            event = Event()
            event["concept:name"] = name
            trace.append(event)
    return trace

def bounded_visible_trace_exploration(net, im, fm, max_visible_length=10, max_loop_iterations=3):
    """Explore all visible traces up to a bound, hiding silent transitions"""
    enabled = pm4py.get_enabled_transitions(net, im)
    traces = set()

    def explore(current_marking, current_trace, visible_length, loop_count):
        if visible_length > max_visible_length or loop_count > max_loop_iterations:
            return

        if current_marking == fm:
            traces.add(tuple(current_trace))
            return

        for trans in pm4py.get_enabled_transitions(net, current_marking):
            new_marking = pm4py.get_marking_after_transition(net, current_marking, trans)
            new_trace = current_trace.copy()
            if trans.label is not None:  # Visible transition
                new_trace.append(trans.label)
                explore(new_marking, new_trace, visible_length + 1, loop_count)
            else:  # Silent transition
                explore(new_marking, new_trace, visible_length, loop_count + 1)

    explore(im, [], 0, 0)
    return traces

def compare_nets(net1, im1, fm1, net2, im2, fm2, name1, name2):
    """Compare two Petri nets using bounded exploration and witness traces"""
    print(f"\nComparing {name1} and {name2}:")

    # 1. Check soundness
    sound1 = pm4py.check_soundness(net1, im1, fm1)
    sound2 = pm4py.check_soundness(net2, im2, fm2)
    print(f"Soundness: {name1}={sound1}, {name2}={sound2}")

    # 2. Bounded visible trace exploration
    traces1 = bounded_visible_trace_exploration(net1, im1, fm1)
    traces2 = bounded_visible_trace_exploration(net2, im2, fm2)

    print(f"Unique traces in {name1}: {len(traces1)}")
    print(f"Unique traces in {name2}: {len(traces2)}")

    # 3. Positive witness traces
    positive_witnesses = [
        ["Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"],
        ["Register Change", "Prepare Evidence", "Assess Risk", "Legal Review", "Configure Trial", "Inspect Trial", "Correct Defect", "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"],
        ["Register Change", "Assess Risk", "skip_legal", "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"]
    ]

    for i, witness in enumerate(positive_witnesses):
        trace = create_witness_trace(witness)
        log = EventLog([trace])

        # Check if trace is possible in both nets
        possible1 = pm4py.check_is_possible_trace(net1, im1, fm1, log)
        possible2 = pm4py.check_is_possible_trace(net2, im2, fm2, log)
        print(f"Positive witness {i+1}: {name1}={possible1}, {name2}={possible2}")

    # 4. Negative witness traces
    negative_witnesses = [
        ["Assess Risk"],  # I1 violation
        ["Register Change", "Assess Risk", "Assess Risk"],  # I2 violation
        ["Register Change", "Legal Review"],  # I3 violation
        ["Register Change", "Assess Risk", "Configure Trial"],  # I4 violation
        ["Configure Trial", "Inspect Trial", "Configure Trial"],  # I8 violation
        ["Release Change"],  # I9 violation
        ["Archive Change", "Release Change"]  # I10 violation
    ]

    for i, witness in enumerate(negative_witnesses):
        trace = create_witness_trace(witness)
        log = EventLog([trace])

        possible1 = pm4py.check_is_possible_trace(net1, im1, fm1, log)
        possible2 = pm4py.check_is_possible_trace(net2, im2, fm2, log)
        print(f"Negative witness {i+1}: {name1}={possible1}, {name2}={possible2}")

    # 5. Exact final marking comparison
    print(f"Final marking equality: {fm1 == fm2}")

    # 6. Reachability graph comparison (for small nets)
    try:
        rg1 = pm4py.convert_to_reachability_graph(net1, im1)
        rg2 = pm4py.convert_to_reachability_graph(net2, im2)
        print(f"Reachability graph states: {name1}={len(rg1.states)}, {name2}={len(rg2.states)}")
        print(f"Reachability graph edges: {name1}={len(rg1.transitions)}, {name2}={len(rg2.transitions)}")
    except:
        print("Reachability graph comparison skipped (net too large)")

    return traces1 == traces2

# Compare POWL Petri net with BPMN round-trip net
comparison_result = compare_nets(
    net_from_powl, im_from_powl, fm_from_powl,
    net_from_bpmn_net, im_from_bpmn_net, fm_from_bpmn_net,
    "POWL Petri net", "BPMN round-trip Petri net"
)

print(f"\nTrace equivalence under bounds: {comparison_result}")
print("Note: This comparison is exhaustive under the chosen bounds (max_visible_length=10, max_loop_iterations=3)")
```

# 6. Visual-Semantics Review

The BPMN visualization may introduce several ambiguities despite preserving the underlying semantics:

1. **Parallel Gateways**: The BPMN diagram may use parallel gateways to represent the unordered execution of Assess Risk and Prepare Evidence. While semantically correct, stakeholders might misinterpret this as requiring parallel execution rather than arbitrary interleaving.

2. **Exclusive Gateways**: The optional Legal Review (XOR with silent transition) may be visualized with an exclusive gateway. The silent path might not be clearly labeled, making it appear as if Legal Review is mandatory.

3. **Loop Visualization**: The verification loop may be represented with a loop marker, but the exact iteration semantics (at least one iteration, separated by Correct Defect) might not be visually apparent. Stakeholders might assume zero iterations are possible.

4. **Silent Routing Nodes**: The silent transition in the optional Legal Review branch may be represented as an unlabeled gateway or may be completely invisible in the visualization, making the optionality unclear.

5. **Apparent Ordering**: The layout algorithm might place the optional Legal Review branch above or below the verification loop, suggesting an order that doesn't exist in the semantics. Stakeholders might assume Legal Review must complete before verification starts.

6. **Join Before Release**: The synchronization before Release Change might be represented with a parallel gateway, which could be misinterpreted as requiring parallel execution of the two branches rather than completion of either branch.

**Proposed Annotations/Documentation**:
- Add a legend explaining gateway types and their semantics
- Label silent paths explicitly (e.g., "Skip Legal Review")
- Add text annotations for loops explaining minimum iterations
- Document the true concurrency semantics in accompanying materials
- Use consistent layout conventions (e.g., always place optional branches below main flow)
- Include example traces in documentation to clarify intended behavior

# 7. Rejection Criteria

A conversion result should be rejected or quarantined under the following conditions:

1. **Unsoundness**: The converted Petri net fails the soundness check (proper completion, option to complete, no dead transitions).

2. **Loss of Required Interleaving**: The converted model enforces an order between Assess Risk and Prepare Evidence that wasn't present in the source.

3. **Premature Release**: The converted model allows Release Change before both the optional-legal branch and verification loop complete.

4. **Collapse of Optional Behavior**: The optional Legal Review branch is converted to mandatory behavior or completely removed.

5. **Failed Exact-Final-Marking Test**: The round-trip conversion doesn't preserve the exact final marking (only Archive Change).

6. **Infinite Silent Cycling**: The converted model introduces unbounded silent cycles that weren't present in the source.

7. **Loss of Minimum Iteration**: The verification loop is converted to allow zero iterations.

8. **Activity Label Collision**: Multiple transitions in the Petri net share the same label, making them indistinguishable in traces.

9. **Initial Marking Mismatch**: The converted model doesn't start with only Register Change enabled.

10. **Failed Positive Witness Test**: A trace that should be possible in the source model is impossible in the converted model.

11. **Failed Negative Witness Test**: A trace that should be impossible in the source model is possible in the converted model.

12. **Process Tree Conversion Failure**: The secondary pipeline fails to produce a process tree, indicating the model isn't block-structured enough for some use cases.

# 8. Canonical Representation Recommendation

**Authoritative Model**: The POWL model should be the canonical representation for storage and future edits.

**Derivative Artifacts**:
1. Accepting Petri net (derived from POWL)
2. BPMN model (derived from Petri net)
3. Process tree (attempted derivation, may fail)

**Validation Evidence Requirements**:
- For the Petri net: Soundness check, footprint comparison with source, positive/negative witness tests
- For the BPMN model: Round-trip validation to Petri net, visual-semantics documentation
- For the process tree: Only if conversion succeeds; must include validation of block-structure preservation

**Process Tree Intermediate**: Should be allowed only when:
- The conversion succeeds without exceptions
- The tree preserves all source invariants
- The tree's BPMN visualization is more readable than the Petri-net-derived BPMN
- The tree is clearly marked as a derivative representation

**Future Edits**:
- All edits should be made to the POWL model first
- Derivative models should be regenerated after each edit
- Round-trip validation should be performed after regeneration
- Any edit that causes a previously successful process tree conversion to fail should be reconsidered or documented

# 9. Residual Uncertainty

Even if all tests pass, the following claims cannot be definitively established:

1. **Exhaustive Behavioral Equivalence**: The bounded trace exploration cannot guarantee equivalence for all possible traces, especially those exceeding the length/iteration bounds. There may be subtle behavioral differences in very long traces.

2. **Visual Interpretation**: While the underlying Petri net may be behaviorally equivalent, the BPMN visualization's layout and gateway choices may still be misinterpreted by stakeholders. The validation cannot guarantee correct human interpretation.

3. **Silent Transition Semantics**: The validation confirms that silent transitions are preserved in the Petri net, but it cannot guarantee that all BPMN visualization tools will represent them consistently or that stakeholders will understand their semantics.

4. **Performance Characteristics**: The validation doesn't assess whether the converted models have equivalent performance characteristics (e.g., state space size, simulation speed) for practical use cases.

5. **Tool-Specific Behavior**: The validation uses PM4Py's conversion and analysis functions, but other tools might interpret the models differently. The results may not generalize to all BPMN/Petri net tools.

6. **Future-Proofing**: The validation doesn't guarantee that future versions of PM4Py or other tools will continue to interpret the models equivalently. Semantic drift in tools could occur over time.
