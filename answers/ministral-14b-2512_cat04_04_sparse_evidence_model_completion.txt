# 2. Shared Assumptions

1. **Event-Completion Semantics**: Activities are atomic; completion timestamps mark when an activity finishes.
2. **Missing Supplier Confirmation**: ~10/30 traces lack it, likely due to:
   - Stocked components (S4).
   - Integration gaps (S5).
   - True optionality (D4).
   Represented as **optional branches** with uncertainty flags.
3. **External/Stocked Attribute**: Absent; assume **default to mandatory** unless evidence suggests otherwise.
4. **Optionality Representation**:
   - **XOR** for clear choices (e.g., `Expedite Review`).
   - **Partial order** for ambiguous concurrency (e.g., `Credit Check`/`Engineering Review`).
   - **Silent transitions** for missing data (e.g., unlogged `Supplier Confirmation`).

---

# 3. Conservative Candidate

**Inductive Bias**:
*"Only admit behavior explicitly observed or enforced by high-confidence rules (D1–D3). Treat all other variations as missing data or noise. Prioritize precision over generalization."*

**Formal Expression**:
```
Register Order  (Credit Check  Engineering Review)  Supplier Confirmation?  Approve Configuration  Release Production  Archive Case
```
- `Supplier Confirmation` is optional but **only if observed** (10/30 traces omit it).
- `Credit Check` and `Engineering Review` must both precede `Approve Configuration` (D3).
- No concurrency assumed; all observed interleavings are treated as sequential.

**PM4Py Code**:
```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

model_conservative = ProcessTree()
model_conservative.label = "Register Order"
model_conservative.children = [
    ProcessTree(label="Credit Check"),
    ProcessTree(label="Engineering Review")
]
model_conservative.operator = Operator.SEQUENCE
model_conservative.children[0].operator = Operator.SEQUENCE
model_conservative.children[0].children = [
    ProcessTree(label="Supplier Confirmation", operator=Operator.OPTIONAL),
    ProcessTree(label="Approve Configuration")
]
model_conservative.children[0].children[1].children = [
    ProcessTree(label="Release Production"),
    ProcessTree(label="Archive Case")
]
model_conservative.children[0].children[1].children[0].operator = Operator.SEQUENCE
```

**Excluded Behavior**:
1. Any trace where `Credit Check` or `Engineering Review` is missing.
2. Traces with `Supplier Confirmation` after `Approve Configuration`.
3. Traces with `Expedite Review` (not observed).
4. Concurrent `Credit Check`/`Engineering Review`.

**Underfitting Risks**:
- May reject valid traces where `Supplier Confirmation` is truly optional (e.g., stocked components).
- Ignores plausible concurrency (S2).

# 4. Balanced Candidate

**Inductive Bias**:
*"Generalize from observed patterns while explicitly modeling uncertainty. Allow partial order for `Credit Check`/`Engineering Review` and treat `Supplier Confirmation` as optional with missingness. Enforce D1–D6 but admit reasonable unobserved combinations."*

**Formal Expression**:
```
Register Order 
  (Credit Check ||| Engineering Review) 
  Supplier Confirmation? 
  Expedite Review? 
  Approve Configuration 
  Release Production 
  Archive Case
```
- `|||` = partial order (either may start first).
- `Supplier Confirmation` is optional but **likely mandatory for external components** (S3/S5).
- `Expedite Review` is optional but requires both `Credit Check` and `Engineering Review` (D6).

**POWL Code**:
```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL

model_balanced = StrictPartialOrder()
model_balanced.label = "Register Order"

# Partial order for Credit Check and Engineering Review
cc = model_balanced.add_activity("Credit Check")
er = model_balanced.add_activity("Engineering Review")
model_balanced.order.add_edge(cc, er)  # Allow either order
model_balanced.order.add_edge(er, cc)

# Supplier Confirmation (optional)
sc = model_balanced.add_activity("Supplier Confirmation")
model_balanced.order.add_edge(cc, sc)
model_balanced.order.add_edge(er, sc)

# Expedite Review (optional, requires both CC and ER)
ex = model_balanced.add_activity("Expedite Review")
model_balanced.order.add_edge(cc, ex)
model_balanced.order.add_edge(er, ex)

# Approve Configuration (requires CC, ER, and optionally SC/EX)
ac = model_balanced.add_activity("Approve Configuration")
model_balanced.order.add_edge(cc, ac)
model_balanced.order.add_edge(er, ac)
model_balanced.order.add_edge(sc, ac)
model_balanced.order.add_edge(ex, ac)

# Release Production and Archive Case
rp = model_balanced.add_activity("Release Production")
ac = model_balanced.add_activity("Approve Configuration")
model_balanced.order.add_edge(ac, rp)
arc = model_balanced.add_activity("Archive Case")
model_balanced.order.add_edge(rp, arc)
```

**Ordering Decisions**:
1. **Credit Check / Engineering Review**: Partial order (allow either to start first, but both must finish before `Approve`).
2. **Supplier Confirmation**: Optional but must precede `Approve` if present.
3. **Expedite Review**: Optional but requires both `Credit Check` and `Engineering Review`.

**Excluded Behavior**:
1. Traces where `Approve Configuration` occurs before both `Credit Check` and `Engineering Review`.
2. Traces with `Supplier Confirmation` after `Approve Configuration`.
3. Traces where `Expedite Review` occurs before either `Credit Check` or `Engineering Review`.

# 5. Permissive Candidate

**Inductive Bias**:
*"Admit all behavior consistent with domain rules (D1–D7) and stakeholder statements (S1–S7), even if unobserved. Assume concurrency where plausible and treat `Supplier Confirmation` as optional for stocked components."*

**Formal Expression**:
```
Register Order 
  (Credit Check ||| Engineering Review) 
  (Supplier Confirmation? ||| Expedite Review?) 
  Approve Configuration 
  Release Production 
  Archive Case
```
- `Supplier Confirmation` and `Expedite Review` are **independent optional branches**.
- `Credit Check`/`Engineering Review` are **fully concurrent** (S2).
- `Expedite Review` requires both `Credit Check` and `Engineering Review` (D6).

**ProcessTree Code**:
```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

model_permissive = ProcessTree(label="Register Order")
model_permissive.children = [
    ProcessTree(label="Credit Check"),
    ProcessTree(label="Engineering Review")
]
model_permissive.operator = Operator.PARTIAL_ORDER  # Allow concurrency

# Supplier Confirmation and Expedite Review as independent options
sc_ex_branch = ProcessTree(operator=Operator.XOR)
sc_ex_branch.children = [
    ProcessTree(label="Supplier Confirmation", operator=Operator.OPTIONAL),
    ProcessTree(label="Expedite Review", operator=Operator.OPTIONAL)
]
model_permissive.children.append(sc_ex_branch)

# Approve Configuration (requires CC and ER)
ac = ProcessTree(label="Approve Configuration")
ac.children = [
    ProcessTree(label="Release Production"),
    ProcessTree(label="Archive Case")
]
ac.operator = Operator.SEQUENCE
model_permissive.children.append(ac)
```

**Boundary Definition**:
- **Allowed**: Any interleaving of `Credit Check`/`Engineering Review`; `Supplier Confirmation` or `Expedite Review` in any order (but both optional).
- **Forbidden**: `Approve Configuration` before both `Credit Check` and `Engineering Review`.

   - `Register Order, Credit Check, Expedite Review, Approve Configuration, Release Production, Archive Case` (missing `Engineering Review`).
   - **Violation**: D6 (`Expedite Review` requires both checks).

# 9. Recommendation and Data-Collection Plan

**Recommendations**:
1. **Immediate Use**: `model_balanced` (balances precision and generalization).
2. **Sensitivity Analysis**: `model_permissive` (tests robustness to concurrency assumptions).

**Data-Collection Plan**:
1. **Resolve `Supplier Confirmation` ambiguity**:
   - Collect `external/stocked` attribute.
   - Log **start timestamps** (not just completion) to detect concurrency.
2. **Maximally Informative Traces**:
   - Force `Credit Check` and `Engineering Review` to start at the same time (true concurrency test).
   - Include/exclude `Supplier Confirmation` systematically.
   - Test `Expedite Review` in all valid positions.

**Key Attributes to Log**:
- Activity start/end timestamps (for concurrency detection).
- Component type (`external`/`stocked`).
- `Expedite Review` trigger reason (compliance audit).

# 10. Uncertainty Statement

**Confidence Assessments**:
1. **High Confidence**:
   - `Register Order`  `Approve Configuration`  `Release Production`  `Archive Case` (D1–D2).
   - `Credit Check` and `Engineering Review` must precede `Approve Configuration` (D3).
2. **Medium Confidence**:
   - `Supplier Confirmation` is optional but likely mandatory for external components (S3–S5).
   - `Expedite Review` requires both `Credit Check` and `Engineering Review` (D6).
3. **Low Confidence**:
   - True concurrency between `Credit Check`/`Engineering Review` (S2 vs. S1).
   - Missing `Supplier Confirmation` is due to stocked components vs. logging gaps.

**Plausible Alternative**:
- If `Credit Check` is **always** required before `Engineering Review` (S1), the `balanced` model would need to enforce a strict sequence, reducing generalization.

---
**Final Note**: The three models represent competing hypotheses. The `balanced` candidate is recommended for deployment, while `permissive` should be used to stress-test assumptions. Data collection should prioritize resolving concurrency and optionality ambiguities.
