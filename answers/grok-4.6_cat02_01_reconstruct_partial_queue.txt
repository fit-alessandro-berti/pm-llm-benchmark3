# 1. Assumptions and notation

**A1 (clock and window).** All clocks are on 2026-05-12. The observation window is the closed interval \([T_0,T_1]=[08{:}00,14{:}00]\) (360 min). Times below are also written as minutes after 08:00. Reported timestamps live on a 5-minute grid.

**A2 (rounding).** A reported time \(t\) stands for an actual time in about \([t-2.5,t+2.5]\) min. A difference of two reported times therefore has a worst-case error of \(\pm 5\) min if rounding errors are independent. Point estimates are computed on the reported grid; rounding is treated as a sensitivity layer, not by jittering every stamp in the base tables.

**A3 (event order at a tied stamp).** At a shared reported time \(t\), interpret completions / resource releases first, then service starts / seizures, then external arrivals. Activities occupy half-open intervals \([\text{start},\text{end})\). The only same-resource tie is P07’s C1 end and P09’s C1 start at 11:00, treated as an instantaneous handoff (P07 then P09). P08’s S2 end and P14’s S1 end at 12:00 are on different stations and commute.

**A4 (capacity).** S1 has two single-task resources I1, I2; S2 has two single-task resources C1, C2. C2 is unavailable for maintenance on the reported interval \([10{:}55,11{:}10]\) (15 min; actual duration about 10–20 min under A2). A resource is not allowed to process two cases at once. After applying A2–A3, no irresolvable overlap remains, so undocumented assistance is not invoked.

**A5 (routing / no bypass).** Every case must visit S1 then S2. External `arrival_s1` is S1 queue entry. S1 completion is S2 queue entry. A blank S1 interval means the case is still waiting for S1 at 14:00. A blank S2 interval after a finished S1 means the case is waiting for S2 at 14:00. OPEN means the activity started and is unfinished at 14:00. MISSING means the activity occurred and the resource and completion are known, but the start was not recorded.

**A6 (missing-start bounds, not a single fill-in).** For a MISSING start on resource \(r\), the feasible start \(s\) satisfies
\[
\max(\text{queue entry},\; \text{predecessor end on }r)\;\le\; s\;\le\;\text{this activity’s end},
\]
with nonnegative service and no overlap of \([s,\text{end})\) with the next job on \(r\). Three labelled imputations are carried (Section 6):
- **O (early / back-to-back):** \(s=\) predecessor end (0-gap).
- **C (central):** \(s=\) predecessor end \(+5\) min — the dominant empirical handoff on both stations.
- **P (late / customer-unfavourable):** \(s=\) end minus a minimum plausible service (20 min at S1, the shortest fully observed S1 service; 20 min at S2 unless the window is tighter).

Station sojourn is *not* imputed: when queue entry and completion are known, wait + service is known and only the split is uncertain.

**A7 (right censoring).** For OPEN activities, elapsed service \(B^{\mathrm{el}}=T_1-\text{start}\) is a lower bound on final service; it is counted as busy and as WIP, but it is not treated as a completed service time. For waiting cases, elapsed wait \(W^{\mathrm{el}}=T_1-\text{queue entry}\) is a lower bound. Residual service after 14:00 is unknown and is not replaced by a point value in the base tables.

**A8 (queue vs WIP).** Queue length counts cases waiting (arrived / handed off, not yet started). Station WIP = queue + in service. System WIP = cases that have arrived and have not yet completed S2 (or \(T_1\)).

**A9 (busy time and utilization).** Resource busy minutes in the window include completed intervals, centrally (or O/P) imputed missing-start intervals, and OPEN elapsed time. Gaps of 5 min between successive jobs on the same resource are counted as idle in the central estimate. Utilization \(=\) busy / 360 per resource, or busy / 720 at station level. A second S2 denominator subtracts the 15 min C2 outage (705 available resource-minutes). A competing reading that the 5 min gaps are pure rounding of continuous work is kept as a hypothesis, not mixed into the central rate.

**A10 (subperiods).** Hourly bins are left-closed, right-open: \([\mathrm{HH}{:}00,\mathrm{HH}{+}1{:}00)\), so a stamp at 10:00 belongs to the 10:00 hour. Coarser phases are 08:00–10:00 (build-up), 10:00–12:00 (outage and co-congestion), 12:00–14:00 (S1 drain, S2 still loaded).

**A11 (Little’s Law).** The sample-path identity \(\bar L=(1/T)\sum_i\) (time case \(i\) spends in the set during the window) always holds and is used as an arithmetic check on WIP integrals. An equilibrium-style check \(\bar L\approx\lambda\bar W\) is attempted only where WIP is roughly level, inflow \(\approx\) outflow, and there is no capacity shock. The full 08:00–14:00 window fails those conditions (empty start, declining external arrivals, right censoring, C2 outage).

**A12 (assignment).** S1 start order equals arrival order, and I1/I2 realize a perfect odd/even split. That pattern is implied both by a single FCFS shared queue with near-equal service times and by dedicated parity queues; the data do not separate those stories until 13:45 (I2 idle while P22 waits). S2 is approximately alternating C1/C2 until the outage, after which P10 is served on C1 and P08 is overtaken by P09.

Notation: \(a_i\) arrival; \(s_{1,i}^s,s_{1,i}^e\) S1 start/end; \(s_{2,i}^s,s_{2,i}^e\) S2 start/end; \(W_1,B_1,Y_1\) S1 wait, service, sojourn; \(W_2,B_2,Y_2\) the S2 analogues; \(Y=s_2^e-a\) case sojourn when S2 is complete.

# 2. Reconstruction method and formulas

**Observed identities (no imputation).**
- \(W_1=s_1^s-a\), \(B_1=s_1^e-s_1^s\), \(Y_1=s_1^e-a=W_1+B_1\) when both S1 stamps exist.
- \(W_2=s_2^s-s_1^e\), \(B_2=s_2^e-s_2^s\), \(Y_2=s_2^e-s_1^e=W_2+B_2\) when both S2 stamps exist.
- Completed-case sojourn \(Y=s_2^e-a=Y_1+Y_2\).

If only the start is missing, \(Y_1\) or \(Y_2\) is still known; the missing start merely partitions a known sojourn into wait vs service. If the activity is OPEN, replace the unknown end by \(T_1\) to get elapsed service and elapsed station time, and flag them as censored. If the case is still queued, service is 0 and wait is elapsed.

**Missing-start intervals used in Sections 3–6.**

| case | station | predecessor end | this end | queue entry | O start | C start | P start |

| P07 | S1 / I1 | P05 09:25 | 10:00 | 08:45 | 09:25 | 09:30 | 09:40 |
| P15 | S1 / I1 | P13 11:40 | 12:15 | 10:10 | 11:40 | 11:45 | 11:55 |
| P05 | S2 / C1 | P03 09:45 | 10:15 | 09:25 | 09:45 | 09:50 | 09:55 |
| P11 | S2 / C2 | P08 12:00 | 12:25 | 11:05 | 12:00 | 12:05 | 12:05 |

P11’s feasible window is only 25 min, so O/C/P nearly collapse. Zero service (\(s=\) end) is allowed by the algebra and rejected as operationally implausible.

**WIP and queues.** With A3,
\[
Q_{\mathrm{S1}}(t)=\lvert\{i:a_i\le t<s_{1,i}^s\}\rvert,\quad
\mathrm{WIP}_{\mathrm{S1}}(t)=\lvert\{i:a_i\le t<s_{1,i}^e\}\rvert
\]
(unstarted and OPEN cases use \(T_1\) as the right end). Analogously
\[
\mathrm{WIP}_{\mathrm{S2}}(t)=\lvert\{i:s_{1,i}^e\le t<s_{2,i}^e\}\rvert
\]
for every case that has left S1. System WIP is the disjoint sum \(\mathrm{WIP}_{\mathrm{S1}}+\mathrm{WIP}_{\mathrm{S2}}\). Time averages are
\[
\bar L=\frac1{T_1-T_0}\int_{T_0}^{T_1}\mathrm{WIP}(t)\,dt=\frac1{360}\sum_i\text{(minutes case \(i\) spends in the set inside the window)}.
\]
The second form is the computational source of record; the step-function integral is a cross-check.

**Rates.** External arrival rate in a bin is (number of `arrival_s1` in the bin) / duration. S1 throughput is S1 completions / duration. S2 arrival rate equals S1 throughput. S2 throughput is S2 completions / duration. OPEN and queued cases are excluded from completion counts and included in WIP.

**Utilization.** For resource \(r\),
\[
U_r=\frac{\sum_{i:r_i=r}B_i^{\text{window}}}{360},
\]
where \(B_i^{\text{window}}\) is the overlap of the (possibly imputed or elapsed) service interval with \([T_0,T_1]\). Station utilization averages the two resources, or uses 720 in the denominator. Lower/central/upper busy times follow scenarios P/C/O on the four missing starts (late start shortens service; early start lengthens it) plus the decision whether 5 min handoff gaps are idle (central) or collapsed (continuous-rounding hypothesis).

**Case-level vs station-level.** Summing \(B_1+B_2\) or feeding a two-activity log to a case-level PM4Py transform yields *case* service/wait, not station queueing metrics. Station wait at S2 is the handoff \(s_2^s-s_1^e\), which is not a case-cycle statistic. PM4Py case-level functions are therefore applied only to a completed-case projection that includes a zero-length ARRIVE event at \(a_i\), and those outputs are labelled case-level (Section 7).

**Little’s Law protocol.** Report the sample-path identity on the full window (it must match). Report an equilibrium-style \(\bar L\) vs \(\lambda\bar W\) only for S2 on 12:00–14:00, where WIP stays in a narrow band and there is no outage. Do not treat completed-case \(\bar W\) alone as the system \(W\) when OPEN and queued cases are a large share of WIP.

# 5. Bottleneck and temporal interpretation

**Evidence (stable under O/C/P and under \(\pm 5\) min rounding).**

1. **S1 is overloaded early.** External arrivals run at 6–7/h for two hours against a two-inspector capacity near 4/h. S1 wait climbs from 5 min (P01–P02) to about 100 min (P16–P21). S1 WIP moves from 1 to a plateau of 7–8 by mid-morning and stays there until arrivals stop. That is a textbook transient of \(\lambda>\mu\).

2. **S2 is the slower server and becomes the downstream constraint once S1 is feeding it.** Fully observed S2 service centres on 40 min versus ~28–30 at S1, so two calibrators clear about 3/h while two inspectors clear about 4/h. After 10:00, S1 throughput (3–4/h) meets or exceeds S2 capacity. S2 wait, which was 5–25 min before 10:20, steps up to 45–75 min. At 14:00 S2 still holds six cases (four queued) while S1 holds two.

3. **The bottleneck is time-varying, not a single station.**
   - *08:00–~10:00:* S1 is the visible bottleneck. S2 WIP is 1–3 and both calibrators often have slack between jobs. S1 already has a growing FCFS (or parity) backlog.
   - *10:00–12:00:* both stations are congested. S1 WIP stays at 7–8. S2 wait jumps, C2 goes out, P08 is skipped by P09, P10 is diverted onto C1. System WIP peaks at **13** around 11:30–11:50 (20 arrivals by 11:30, only seven S2 departures).
   - *12:00–14:00:* external arrivals have essentially stopped. S1 drains (WIP 8 → 2). S2 does not: WIP stays 5–7. The constraint has shifted downstream.

4. **Utilization over the whole window is high at both stations and does not by itself name the bottleneck** (central ~83% S1 vs ~78% S2). The identifying evidence is the demand–capacity path: S1 loses early when \(\lambda_{\mathrm{ext}}>\mu_{\mathrm{S1}}\); S2 loses later when \(\lambda_{\mathrm{S1}}\gtrsim\mu_{\mathrm{S2}}\). Peak queues (7 at S1, 5 at S2) and the 14:00 snapshot (S2 still loaded) complete the picture.

**Maintenance interval (evidence vs hypothesis).**

- *Evidence:* C2 has no job in [10:55, 11:10]. P06 ends 10:50; P08 starts 11:15. S2 completions in 11:00–12:00 drop to 2. P08’s S2 wait is 55 min, of which the outage and its two flanking 5 min gaps are 25 min; the rest is ordinary queueing behind P06. P09 seizes C1 at 11:00 instead of P08. P10 (even, the “C2” slot in the morning alternation) is processed on C1 for only 25 min.
- *Scale:* 15 min of lost C2 time is about 0.4 of a 40 min job — a small throughput hole, a larger delay hole because it hits an already non-empty S2 queue.
- *Hypothesis, not fact:* cases were loosely pre-assigned odd→C1 / even→C2, and the outage forced a one-time swap (P10↔P11). A shared FCFS queue with “P08 already committed to C2” produces the same overtaking. Either way, S2 is not a clean single FCFS server after 11:00.
- *Hypothesis:* the outage is an aggravating shock, not the root cause. S2 wait was already rising (P06=25, P07=20) and S2 service times drift up (45–50 min) later in the day even after C2 is back.

**Other observations that affect the bottleneck reading.**

- The systematic 5 min gap between successive jobs on the same resource, and between a free resource and the next start, is either a real setup/log-in delay (which cuts effective capacity by roughly one job per resource per three hours) or a rounding artefact of back-to-back work (A2). Those two readings move utilization by up to ~10 percentage points but do **not** move the early-S1 / late-S2 diagnosis.
- I2 is idle 13:45–14:00 while P22 has been waiting since 12:10. Under both a shared FCFS model and an even→I2 model, I2 should have taken P22. This is unused S1 capacity at the close of the window. Hypotheses consistent with the file: a stop-new-work cutoff, an unrecorded break, or a delay inside the last 5–15 min rounding cloud. It slightly *lowers* S1 utilization and does not create the morning queue.
- P11’s implied S2 service (~20–25 min) and P10’s 25 min are short relative to the 40 min cluster. They may be genuinely short calibrations or compressed by rounding; they slightly raise S2 throughput in the early afternoon and should not be averaged into a claim that S2 “sped up.”

**Censoring, treated separately from missing starts.**

- OPEN service is elapsed, not final: P21 \(B_1\ge 30\), P15 \(B_2\ge 30\), P17 \(B_2\ge 5\). P17 in particular would wreck a naive S2 service mean if 5 min were treated as a completed calibration.
- Four S2 waits and one S1 wait are lower bounds. Any “mean wait” that omits them is downward-biased, and the bias grows toward 14:00 (the longest leftover S2 waiter has already been in queue 85 min).
- Eight cases are still in the system at \(T_1\). Completed-case mean sojourn 146 min describes the morning cohort, not the process in isolation: later arrivals are slower and several have not finished.

**Rounding (A2), applied on top of C.** Every reported wait or service can move by up to 5 min. The 5 min handoff gaps have actual idle in about \([0,10]\) min; they are compatible with continuous occupation. The C2 outage duration is about 10–20 min. Hourly counts can flip by one for stamps that sit on the hour (P07, P08, P09, P12, P14). None of these flips change the sign of \(\lambda-\mu\) in the early S1 phase or the late S2 phase.

**Continuous-rounding hypothesis (not in O/C/P).** If every 5 min same-resource gap is an artefact and resources are busy from first start to last end/OPEN (except the named C2 outage and the genuine 10 min C2 hole before P15, and I2’s unused last 15 min), S1 busy time rises to ~690/720 \(\approx\) 96% and S2 to the mid-80s. That reading is internally consistent with A2 but *inconsistent* with treating reported start/end differences as idle-inclusive service. It is an alternative semantics for the same file, not a third imputation of MISSING.

**Stable conclusions**

- Completed sojourns, all station sojourns with a known completion, all WIP paths, peak queues, hourly arrival and completion counts (up to a boundary of 1), the early S1 overload, the late S2 residue, and the qualitative role of the C2 outage.
- Both stations are busy; neither is a low-utilization decorative stage.
- Little’s sample-path identities hold; completed-only Little’s Law on S2 is biased low.

**Unstable / fragile conclusions**

- The exact P07/P15 wait–service split, and therefore any claim that “S1 service is always 30 min.”
- Whether P11 is an outlier short S2 job (~20) or a 25 min job rounded against the next start.
- Station utilization to tighter than about \(\pm 5\) percentage points, and anything that depends on calling the 5 min gaps idle versus busy.
- Final service times and final sojourns of P15, P17, P21, and the five queued cases.
- Any single “the” bottleneck for the whole morning — the data support a hand-off from S1 to S2, not a static ranking.
- Equilibrium Little’s Law on the full window, or on S1 while the S1 queue is still climbing.

def parse_cell(val):
    """Return (kind, datetime|None). kinds: TIME, MISSING, OPEN, BLANK."""
    if val is None or (isinstance(val, float) and pd.isna(val)) or val == "":
        return "BLANK", None
    if val == "MISSING":
        return "MISSING", None
    if val == "OPEN":
        return "OPEN", None
    return "TIME", ts(val)

def apply_scenario(df, name):
    out = df.copy()
    imp = IMPUTATIONS[name]
    out["s1s"] = out["s1_start_t"]
    out["s1e"] = out["s1_end_t"]
    out["s2s"] = out["s2_start_t"]
    out["s2e"] = out["s2_end_t"]
    out.loc[out["case"] == "P07", "s1s"] = imp["P07_s1"]
    out.loc[out["case"] == "P15", "s1s"] = imp["P15_s1"]
    out.loc[out["case"] == "P05", "s2s"] = imp["P05_s2"]
    out.loc[out["case"] == "P11", "s2s"] = imp["P11_s2"]
    # OPEN ends contribute elapsed time to 14:00, not a final service
    out.loc[out["s1_end_kind"] == "OPEN", "s1e"] = T1
    out.loc[out["s2_end_kind"] == "OPEN", "s2e"] = T1
    out["s1_open"] = out["s1_end_kind"] == "OPEN"
    out["s2_open"] = out["s2_end_kind"] == "OPEN"
    out["s1_queued"] = out["s1_start_kind"] == "BLANK"
    out["s2_queued"] = (out["s1e"].notna()) & (out["s2_start_kind"] == "BLANK")
    return out


def case_metrics(df):
    recs = []
    for r in df.itertuples(index=False):
        a = r.arrival_s1_t
        w1 = b1 = w2 = b2 = y = None
        if r.s1s is not None and a is not None:
            w1 = minutes(r.s1s - a)
        if r.s1s is not None and r.s1e is not None:
            b1 = minutes(r.s1e - r.s1s)
        if r.s1_queued:
            w1 = minutes(T1 - a)
            b1 = 0.0
        if r.s2s is not None and r.s1e is not None:
            w2 = minutes(r.s2s - r.s1e)
        if r.s2s is not None and r.s2e is not None:
            b2 = minutes(r.s2e - r.s2s)
        if r.s2_queued:
            w2 = minutes(T1 - r.s1e)
            b2 = 0.0
        if r.s2e is not None and a is not None and not r.s2_open and not r.s2_queued:
            y = minutes(r.s2e - a)
        recs.append(
            dict(case=r.case, state=r.state_at_14_00,
                 W1=w1, B1=b1, W2=w2, B2=b2, Y=y,
                 s1_open=r.s1_open, s2_open=r.s2_open,
                 s1_queued=r.s1_queued, s2_queued=r.s2_queued,
                 s1r=r.s1_resource, s2r=r.s2_resource,
                 a=a, s1s=r.s1s, s1e=r.s1e, s2s=r.s2s, s2e=r.s2e)
        )
    return pd.DataFrame(recs)

def occupancy_integral(df, entry_col, exit_col):
    """Sum of minutes each case spends in [entry, exit) ∩ [T0, T1]."""
    total = 0.0
    for r in df.itertuples(index=False):
        left, right = getattr(r, entry_col), getattr(r, exit_col)
        if pd.isna(left) or pd.isna(right):
            continue
        lo, hi = max(left, T0), min(right, T1)
        if hi > lo:
            total += minutes(hi - lo)
    return total


def peak_and_mean_wip(df, entry_col, exit_col):
    events = []
    for r in df.itertuples(index=False):
        left, right = getattr(r, entry_col), getattr(r, exit_col)
        if pd.isna(left) or pd.isna(right) or right <= left:
            continue
        events.append((left, 1))
        events.append((right, -1))
    # A3: releases (-1) before seizures (+1) at a tied stamp
    events.sort(key=lambda x: (x[0], x[1]))
    wip = peak = 0
    last = T0
    area = 0.0
    for t, d in events:
        tclip = min(max(t, T0), T1)
        if tclip > last:
            area += wip * minutes(tclip - last)
            last = tclip
        if T0 <= t <= T1:
            wip += d
            peak = max(peak, wip)
    if T1 > last:
        area += wip * minutes(T1 - last)
    return area / 360.0, peak


def busy_minutes(df, start_col, end_col, resource_col, resources):
    out = {r: 0.0 for r in resources}
    for rec in df.itertuples(index=False):
        res = getattr(rec, resource_col)
        s, e = getattr(rec, start_col), getattr(rec, end_col)
        if res in out and pd.notna(s) and pd.notna(e) and e > s:
            out[res] += minutes(min(e, T1) - max(s, T0))
    return out


def hourly_counts(series):
    bins = [T0 + timedelta(hours=h) for h in range(7)]
    labels = [f"{8+h:02d}:00-{9+h:02d}:00" for h in range(6)]
    cat = pd.cut(series.dropna(), bins=bins, right=False, labels=labels)
    return cat.value_counts().sort_index()
