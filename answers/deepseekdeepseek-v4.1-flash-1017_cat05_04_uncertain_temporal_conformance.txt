## 1. Normalization Assumptions

- **True-time model:** For a source clock, `offset = recorded_clock - true_clock`; offset bound `[a,b]` gives `true_time = recorded_clock - offset`, hence for a recorded-clock interval `[c_lo,c_hi]` the true-time interval is `[c_lo - b, c_hi - a]`.
- **Resolution before correction:** floor/rounding uncertainty is applied to the source clock reading first, then clock offset is applied.
- **Tables below** use practical closed upper endpoints such as `.999` for minute-floor semantics. The code uses half-open minute-floor intervals where natural. Sub-millisecond endpoint differences do not materially affect classifications.
- **Time zones:** June 2026 conversions use `Europe/Berlin=CEST UTC+2`, `Europe/London=BST UTC+1`, and `America/New_York=EDT UTC-4`.
- **DST fold:** For `T-405`, both `Europe/Berlin` folds are possible from metadata alone. The ingestion order constraints eliminate all but: Alert in first occurrence/CEST, Investigation and Containment in second occurrence/CET. If that ordering evidence were revoked, the feasible set would need to be widened.
- **Inferred start `T-404`:** `Investigation_Start = Investigation_Complete - duration`, with duration `[18,25]` minutes. This retains all completion-time and duration uncertainty.
- **Inferred receipt `T-407`:** `Alert_Received = Alert_Sent + delivery_latency`, latency `[0,20]` minutes. I also apply the plausible causal constraint `Alert_Received  Investigation_Start`; the marginal received interval is correlated with the start interval. Duration calculations use the order constraint.
- **Mobile entry delay `T-406`:** In the main analysis, “entered up to five minutes late” is treated as an occurrence-time uncertainty: the actual investigation start may precede the normalized entry/record time by `[0,300]` seconds. An alternative where entry delay affects only record creation is discussed in Section 4.
- **Profile baseline in Section 3:** temporal-profile classifications use `=1`. Section 4 gives `=1,2,3`.
- **Classification semantics:**  
  - `CERTAIN_PASS`: every feasible duration satisfies the rule/band.  
  - `CERTAIN_VIOLATION`: every feasible duration violates the rule/band.  
  - `POSSIBLE_VIOLATION`: feasible durations include both satisfying and violating values.  
  - `INDETERMINATE`: missing/weak evidence prevents testing or makes the model inconsistent.
- **Severity convention:** hard-SLA certain violations are `Critical`, hard-SLA possible violations are `High`, statistical-profile deviations are `Medium`, and passes are `Low/n/a`.
- **Confidence convention:** `High` for HUB/order evidence or tight intervals, `Medium` for normal external/NTP/rounding evidence, `Low` for missing acknowledgment, weak NTP, mobile entry semantics, or inferred activities.

# Executable, self-contained code. Requires: pandas, pm4py (and Python 3.9+ for zoneinfo).
# Interval conclusions are authoritative for uncertain timestamps.
# The PM4Py log below is explicitly a lossy midpoint approximation, not an uncertainty-aware result.

from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo
import pandas as pd

UTC = timezone.utc

def dt_utc(s: str) -> datetime:
    return datetime.fromisoformat(s).replace(tzinfo=UTC)

def hub_interval(s: str):
    t = dt_utc(s)
    # display uncertainty +/-0.5 s; clock_offset in [-1, 1]
    return [(t - timedelta(seconds=1.5), t + timedelta(seconds=1.5))]

def sensor_round10_interval(s: str):
    t = dt_utc(s)
    # nearest 10 s gives clock reading in [t-5, t+5]; offset [-5, 5]
    return [(t - timedelta(seconds=10), t + timedelta(seconds=10))]

def local_floor_minute_intervals(s: str, tzname: str, off_low: float, off_high: float):
    """Floor-to-minute local timestamp. Returns one interval per possible DST fold.
       true = local_clock_interval - offset, offset in [off_low, off_high].
    """
    naive = datetime.fromisoformat(s)
    zone = ZoneInfo(tzname)
    outs = []
    for fold in [0, 1]:
        local = naive.replace(tzinfo=zone, fold=fold)
        c_start = local.astimezone(UTC)
        c_end = c_start + timedelta(minutes=1)  # half-open floor minute
        true_start = c_start - timedelta(seconds=off_high)
        true_end = c_end - timedelta(seconds=off_low)
        outs.append((true_start, true_end))
    # de-duplicate non-ambiguous cases
    dedup = []
    for x in outs:
        if x not in dedup:
            dedup.append(x)
    return dedup

def local_round_minute_mobile_with_entry(s: str, tzname: str, off_low: float, off_high: float,
                                          entry_delay_max: float):
    """Mobile rounded-to-minute timestamp. Main assumption: actual occurrence may precede
       normalized record time by up to entry_delay_max seconds.
    """
    local = datetime.fromisoformat(s).replace(tzinfo=ZoneInfo(tzname))
    c_start = local - timedelta(seconds=30)
    c_end = local + timedelta(seconds=30)
    utc_start = c_start.astimezone(UTC)
    utc_end = c_end.astimezone(UTC)
    record_start = utc_start - timedelta(seconds=off_high)
    record_end = utc_end - timedelta(seconds=off_low)
    occurrence_start = record_start - timedelta(seconds=entry_delay_max)
    occurrence_end = record_end
    return [(occurrence_start, occurrence_end)]

def merge_second_intervals(intervals):
    intervals = sorted(intervals)
    merged = []
    for lo, hi in intervals:
        if not merged or lo > merged[-1][1] + 1e-9:
            merged.append([lo, hi])
        else:
            merged[-1][1] = max(merged[-1][1], hi)
    return [(float(lo), float(hi)) for lo, hi in merged]

def ordered_duration_seconds(a_intervals, b_intervals):
    """Feasible durations B-A with causal constraint A <= B."""
    out = []
    for a0, a1 in a_intervals:
        for b0, b1 in b_intervals:
            lo = max(0.0, (b0 - a1).total_seconds())
            hi = (b1 - a0).total_seconds()
            if hi >= 0 and lo <= hi + 1e-9:
                out.append((lo, max(lo, hi)))
    return merge_second_intervals(out)

def classify_limit(intervals, limit):
    all_pass = all(hi <= limit + 1e-9 for lo, hi in intervals)
    all_viol = all(lo > limit + 1e-9 for lo, hi in intervals)
    if all_pass:
        return "CERTAIN_PASS"
    if all_viol:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

def classify_band(intervals, lo_band, hi_band):
    all_in = all(lo >= lo_band - 1e-9 and hi <= hi_band + 1e-9 for lo, hi in intervals)
    no_overlap = all(hi < lo_band - 1e-9 or lo > hi_band + 1e-9 for lo, hi in intervals)
    if all_in:
        return "CERTAIN_PASS"
    if no_overlap:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

    a, b = interval
    return a + (b - a) / 2

## 7. Governance Recommendation

- **Store all timestamps in UTC** as the canonical system-of-record value, while retaining the original raw timestamp string and its original timezone.
- **Retain raw timestamp and display metadata**: source timezone, DST fold if applicable, rounding/floor/nearest rule, resolution, display precision, and transformation history.
- **Require source offset telemetry**: NTP/clock-offset samples with uncertainty bounds, not just a single synchronized/not-synchronized flag. Alert when bounds materially affect SLA thresholds.
- **Record resolution semantics explicitly**: distinguish exact-to-second, floor-to-minute, nearest-minute, nearest-10-seconds, and human-entered values.
- **Separate start and completion/status events**: `Investigation_Start`, `Investigation_Complete`, `Containment_Complete`, and `Close_Incident` should have distinct lifecycle definitions, actor, system, and provenance.
- **Log DST fold explicitly**: for ambiguous local times, store the UTC offset, the fold index, and the raw local timestamp. Do not infer fold from display order unless that inference is captured as evidence.
- **Use causal identifiers and sequence evidence**: message IDs, alert delivery acknowledgments, parent incident IDs, correlation IDs, and ingestion sequence. Treat ingestion order as evidence, not proof of occurrence order, unless causally linked.
- **Capture human-entry provenance for mobile/manual systems**: creation time, submission time, user-reported occurrence time, entry delay, device clock quality, and whether the timestamp represents occurrence or record creation.
- **Enforce interval-aware SLA policy**: for enforcement, specify whether interval overlap with a violation is sufficient to open a case, whether certain violation is required for penalty, and how inferred activities are treated. A defensible default is: use certain violations for automatic penalties; route possible violations for human review with the interval evidence attached.
- **Version normalization and conformance rules**: store the clock-offset bounds, resolution model, DST rules, and temporal-profile parameters used at evaluation time so later audits can reproduce classifications.
