## 6. Intervention and learning plan

| phase | intervention | target mechanism | assignment unit | safeguards | process-mining measurements | causal learning value | stop or rollback rule |

| **Phase 0 — Instrument (2 weeks, no operational change)** | Add eventlevel start/end timestamps for every activity; log `reviewer_id`, `certification_level`, and live `queue_length` + `staff_on_duty` for the assigned group at the `Classify` routing timestamp; capture open/abandoned cases with censoring time | Separates `queue_wait` from compliance wait; unlocks reviewerlevel and queuestate controls; breaks the `case_completed` selection blind spot | Case (all cases) | No routing change; PIIsafe reviewer pseudonyms; no change to any case's handling | Variant conformance (fourvariant inventory), DFG frequencies per group/shift, waitcomponent split, WIP/queuelength trajectories by hour of day | Highest informationperrisk: gives us shift and queueadjusted contrasts and closes the selection gap. **Final recommendation**

Do **not** proceed with the blanket 50% reassignment. The supplied data show a textbook Simpson reversal: Orion's +6.72 h crude gap becomes a **2.51 h complexitystandardized advantage**, of which ~85% lives in `queue_wait` and only ~11% in `review_service`. Reassigning work to a group that is slower in *every* observed complexity stratum is unlikely to shorten cycle time and will probably lengthen it for highcomplexity and nightshift cases. Instead, run Phases 0–2 over the next 4–6 weeks: instrument queue state and reviewer identity at `Classify`, run a small stratified randomization only in complexity × shift cells with real support, and separately smooth night queue load via the shifthandoff buffer. Reestimate complexity and shiftstandardized contrasts on the enriched data before any scaling decision. Treat `resource_group` as a bundle of routing policy, staffing model, and skill mix — change one lever at a time and keep 30day quality as a hard guardrail.

# 3. Complexity-standardized contrast (common pooled-complexity weights)
# ------------------------------------------------------------------
print("\n" + "=" * 70)
print("3. COMPLEXITY-STANDARDIZED ORION-vs-NOVA CONTRAST")
print("=" * 70)

# Common weighting distribution: the POOLED complexity distribution across
# both groups (standardization to the combined population).
weights = df["complexity"].value_counts(normalize=True).sort_index()
print("\nCommon weighting distribution = pooled complexity mix across both groups:")
for cx, w in weights.items():
    print(f"    P({cx}) = {w:.4f}")

std_orion = (weights * strat_means["Orion"]).sum()
std_nova = (weights * strat_means["Nova"]).sum()
print(f"\n    Standardized mean cycle time, Orion = {std_orion:.3f} h")
print(f"    Standardized mean cycle time, Nova  = {std_nova:.3f} h")
print(f"    Standardized contrast (Orion - Nova) = {std_orion - std_nova:+.3f} h")

# Same decomposition split into wait / service / structural residual
print("\n    Standardized contrast split by component:")
for col, label in [
    ("wait_before_review_h", "queue_wait "),
    ("review_service_h", "review_svc "),
]:
    comp_means = df.groupby(["complexity", "group"])[col].mean().unstack()
    d = (weights * (comp_means["Orion"] - comp_means["Nova"])).sum()
    print(f"      {label} = {d:+.3f} h")

# Structural residual: cycle - wait - service is deterministic given variant
df["structural_h"] = (
    df["cycle_time_h"] - df["wait_before_review_h"] - df["review_service_h"]
)
print("\n    Structural residual (cycle - wait - service) by variant signature:")
variant_key = df["compliance_required"].astype(str) + "/RI=" + df["rework_count"].astype(str)
print(
    pd.DataFrame({"variant": variant_key, "structural_h": df["structural_h"]})
    .groupby("variant")["structural_h"]
    .agg(["count", "mean", "std"])
    .round(3)
)
comp_struct = df.groupby(["complexity", "group"])["structural_h"].mean().unstack()
d_struct = (weights * (comp_struct["Orion"] - comp_struct["Nova"])).sum()
print(f"      structural_h = {d_struct:+.3f} h")
print(f"      (sum should approximate the total standardized contrast above)")

# ------------------------------------------------------------------
# 4. Overlap counts for every (complexity, shift, resource_group) cell
# ------------------------------------------------------------------
print("\n" + "=" * 70)
print("4. OVERLAP / POSITIVITY DIAGNOSTICS")
print("=" * 70)

overlap = (
    df.groupby(["complexity", "shift", "group"])
    .size()
    .unstack("group")
    .reindex(columns=["Orion", "Nova"])
    .fillna(0)
    .astype(int)
)
print("\nObserved case counts per (complexity, shift, group):")
print(overlap)

print("\nSupport warnings:")
for (cx, sh), row in overlap.iterrows():
    for g, n in row.items():
        n = int(n)
        if n == 0:
            warnings.warn(
                f"ZERO SUPPORT: complexity={cx}, shift={sh}, group={g} -- "
                f"positivity violation; no causal contrast is identified here."
            )
        elif n < 3:
            warnings.warn(
                f"THIN CELL (n={n}): complexity={cx}, shift={sh}, group={g} -- "
                f"any comparison here is unstable."
            )

for (cx, g), sub in df.groupby(["complexity", "group"]):
    if len(sub) < 3:
        warnings.warn(
            f"THIN STRATUM: complexity={cx}, group={g}, n={len(sub)} -- "
            f"stratified contrast is not reliable."
        )

for (cx, sh), sub in df.groupby(["complexity", "shift"]):
    if sub["group"].nunique() < 2:
        warnings.warn(
            f"NO CROSS-GROUP COMPARISON POSSIBLE: complexity={cx}, shift={sh} -- "
            f"only one resource group observed."
        )

# ------------------------------------------------------------------
# 5. Trace variants and directly-follows relations by group (PM4Py)
# ------------------------------------------------------------------
print("\n" + "=" * 70)
print("5. TRACE VARIANTS AND DIRECTLY-FOLLOWS RELATIONS BY GROUP")
print("=" * 70)

print("\n[5a] Trace variant x group cross-tab:")
variants = pd.crosstab(df["trace"], df["group"])
print(variants)

print("\n[5b] Group-specific DFGs via PM4Py "
      "(pm4py.parse_event_log_string + pm4py.discover_dfg):")


def build_log_pm4py(sub: pd.DataFrame) -> EventLog:
    """
    Build a PM4Py EventLog from the `trace` column.

    Preferred path: use `pm4py.parse_event_log_string(...)` as prescribed by
    the PM4Py manual. Fallback: construct the EventLog explicitly from
    Trace/Event objects if the string parser is unavailable in the installed
    PM4Py version.  No event timestamps are fabricated -- only activity names
    and case identifiers are recorded.  This is a purely structural (variant
    and DFG) analysis, NOT a performance analysis.
    """
    joined = "\n".join(sub["trace"].astype(str).tolist())
    try:
        log = pm4py.parse_event_log_string(joined)
        return log
    except Exception as exc:  # pragma: no cover - version-dependent
        warnings.warn(
            f"pm4py.parse_event_log_string unavailable ({type(exc).__name__}); "
            f"falling back to explicit EventLog construction."
        )
        log = EventLog()
        for _, row in sub.iterrows():
            tr = Trace()
            tr.attributes["concept:name"] = row["case_id"]
            tr.attributes["group"] = row["group"]
            for act in str(row["trace"]).split(">"):
                tr.append(Event({"concept:name": act.strip()}))
            log.append(tr)
        return log


group_dfgs = {}
for g in ["Orion", "Nova"]:
    sub = df[df["group"] == g]
    log = build_log_pm4py(sub)
    dfg, start_acts, end_acts = pm4py.discover_dfg(log)
    group_dfgs[g] = dfg
    print(f"\n--- {g}: {len(sub)} traces ---")
    print(f"    start activities : {dict(start_acts)}")
    print(f"    end   activities : {dict(end_acts)}")
    print(f"    directly-follows relations (activity -> activity : count):")
    for (a, b), w in sorted(dfg.items(), key=lambda kv: (-kv[1], kv[0])):
        print(f"      {a} -> {b} : {w}")

print("\n[5c] DFG difference (Orion count - Nova count); "
      "structure is shared, frequencies differ:")
all_edges = sorted(set(group_dfgs["Orion"]) | set(group_dfgs["Nova"]))
for edge in all_edges:
    o = group_dfgs["Orion"].get(edge, 0)
    n = group_dfgs["Nova"].get(edge, 0)
    print(f"    {edge[0]} -> {edge[1]}: Orion={o}, Nova={n}, diff={o - n:+d}")

print("\n[5d] Variant-level cycle-time comparison (is any variant slower in Orion?):")
print(
    df.groupby(["trace", "group"])["cycle_time_h"]
    .agg(["count", "mean"])
    .round(3)
)

# ------------------------------------------------------------------
# 6. Explicit warnings for poor support (already emitted above); summary
# ------------------------------------------------------------------
print("\n" + "=" * 70)
print("6. SUPPORT SUMMARY")
print("=" * 70)
n_zero = int((overlap == 0).sum().sum())
n_thin = int(((overlap > 0) & (overlap < 3)).sum().sum())
print(f"    Zero-support cells            : {n_zero}")
print(f"    Thin cells (0 < n < 3)        : {n_thin}")
print(f"    Total (complexity x shift x group) cells : {overlap.size}")
if n_zero + n_thin > 0:
    warnings.warn(
        "OVERALL: poor overlap across complexity x shift x group. "
        "Any adjusted group contrast relies on extrapolation. "
        "Treat the standardized contrast as a descriptive diagnostic only -- "
        "it is NOT a causal estimate."
    )

print("\nDone. These diagnostics are descriptive and process-aware. "
      "They do not establish causation.")

## 8. Residual uncertainty

1. **Unobserved case risk within complexity strata** (the routing rule selects on "difficult", which is not the same as the threelevel `complexity` label). *Most valuable addition:* a continuous casedifficulty / risk score emitted by `Classify` (or the raw classifier feature vector), logged on every case.

2. **Selection into the completedcase sample** (only finished cases observed; abandoned or stillopen cases are censored out, and completion is affected by both `resource_group` and `unobserved_case_risk`). *Most valuable design change:* an allcases roster including `case_id`, `opened_at`, `closed_at` or `censored_at`, and a `status  {closed, open, abandoned}` field — enabling IPCW or survival analysis.

3. **Queuestate and staffing at the routing timestamp** (the 2.15 h `queue_wait` gap could be an Orion property or a nightstaffing property). *Most valuable addition:* `queue_length_WIP` and `staff_on_duty` for the assigned group at the moment `routing_rule` fires.

4. **Reviewer identity and skill level** (Orion's "more certified reviewers" is stated but never measured; reviewer effects and group effects are perfectly confounded). *Most valuable addition:* `reviewer_id` and `certification_level` on every `Review` activity event, enabling withinreviewer and reviewerfixedeffect comparisons.

5. **Timeordering and dynamic feedback** (`wait_before_review_h` conflates post`Classify` queueing with compliancestep wait; endogenous congestion and learningbydoing are invisible). *Most valuable addition:* eventlevel `start_timestamp` and `end_timestamp` for every activity, which would let us decompose the wait metric, reconstruct WIP trajectories, and control for timevarying confounders in a marginalstructuralmodel framework.
