# 1. Executive Verdict

The net **is a workflow net**: it has one source place, one sink place, and every node lies on a directed source-to-sink path. Nevertheless, the accepting net **is unsound** and does not realize the business intent.

The principal defect is that `t_join_waived` consumes only `p_waived`; it neither waits for nor consumes `p_analysis_done`. Consequently, authorization can occur before analysis. Performing analysis before authorization does not fix the problem: its completion token remains stranded.

Every waiver execution loses the possibility of reaching the exact final marking. It can put a token in `sink`, but another token remains in the analysis branch. Standard-review executions can finish correctly. The business consequences are premature authorization and waiver cases that appear completed while the net still contains unfinished or unconsumed analysis work.

# 2. Structural Diagnosis

All arcs have weight one. Markings below list only places with nonzero token counts.

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source`, `t_register`, `p_ready` | Admit and register one case. | `im = {source: 1}` enables only `t_register`, which creates one token in `p_ready`. | No defect here. |
| `t_split` | Enable analysis and review concurrently. | Consumes one `p_ready` token and produces one token in **each** of `p_analysis` and `p_review`. | The analysis obligation survives any review choice unless a later transition consumes it. |
| `t_analyze` | Complete mandatory analysis. | Moves the analysis token from `p_analysis` to `p_analysis_done`. Originally, only `t_join_normal` can consume that completion token. | Analysis completion becomes stranded on the waiver route. |
| `t_standard_review` | Select and complete standard review. | Consumes `p_review` and produces `p_review_done`. | Works with the normal two-input synchronization. |
| `t_waive_review` | Select and formally record a waiver. | Competes with standard review for the same single `p_review` token; produces `p_waived`. | The choice itself is exclusive and correct, but its downstream synchronization is incomplete. |
| Both review alternatives | Select exactly one review outcome. | Both may initially be enabled, but firing either disables the other by consuming their shared input token. The split does not create a token for each alternative. | There is no duplication of review outcomes in this single-case net. |
| `t_join_normal` | Wait for analysis and standard review. | Requires and consumes both `p_analysis_done` and `p_review_done`, then produces `p_decision`. | Correct synchronization on the standard route. |
| `t_join_waived` | Wait for analysis and recorded waiver. | Requires only `p_waived`, then produces `p_decision`. It is a one-input forwarding transition, despite its name. | Enables authorization prematurely and leaves the analysis branch unconsumed. |
| `p_decision`, `t_authorize` | Authorize after both obligations have been discharged. | `t_authorize` checks only `p_decision`; it trusts whichever preceding transition produced that token. | The waiver route supplies insufficient evidence of completion. |
| `sink`, `fm` | Complete with exactly one final token and no other tokens. | `fm = {sink: 1}`. A marking containing `sink` plus another place is not equal to `fm`. | Testing only whether `sink` is marked gives a false completion signal. |
| Whole graph | Satisfy workflow-net structure. | `source` is the unique place without incoming arcs, `sink` the unique place without outgoing arcs, and every place and transition lies on a directed path between them. | Structural workflow-net validity does not establish behavioral soundness. |

For example, the analysis branch has a structural path through `t_join_normal` to `sink`, while the waiver branch has one through `t_join_waived`. Such paths ignore whether the other inputs of a transition can be marked together. Thus the structural path condition does not detect the defect.

# 3. Marking-Based Counterexample

Consider this legal firing sequence, in which authorization precedes analysis:

```text
t_register, t_split, t_waive_review, t_join_waived,
t_authorize, t_analyze
```

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source: 1}` | `t_register` | Exact initial marking `im`. |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | Case registered. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token is created in each parallel branch. |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `t_analyze`, `t_join_waived` | Waiver selected; standard review is now disabled. |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, `t_authorize` | Authorization is enabled although analysis has not occurred. |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `t_analyze` | A sink token exists, but this is **not** `fm`. This marking is not yet deadlocked. |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | None | Analysis can still run after authorization, but the result is a dead marking unequal to `fm`. |

At step 5 the token in `p_analysis` can be consumed by `t_analyze`, but doing so merely moves it to `p_analysis_done`. Only `t_join_normal` can consume that token in the original net. That join also needs `p_review_done`, which cannot be produced: the unique `p_review` token has already been consumed by `t_waive_review`, and no transition replenishes it. There is no cleanup transition or legal continuation to `fm`.

The completion defect also occurs when analysis precedes authorization. A second legal sequence rules out a repair based merely on scheduling analysis earlier:

```text
t_register, t_split, t_analyze, t_waive_review,
t_join_waived, t_authorize
```

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source: 1}` | `t_register` | Start from `im`. |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | Registration complete. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | Both branches enabled. |
| 3 | `t_analyze` | `{p_analysis_done: 1, p_review: 1}` | `t_standard_review`, `t_waive_review` | Analysis has completed. |
| 4 | `t_waive_review` | `{p_analysis_done: 1, p_waived: 1}` | `t_join_waived` | Waiver completes the selected review outcome. |
| 5 | `t_join_waived` | `{p_analysis_done: 1, p_decision: 1}` | `t_authorize` | The analysis completion token is not consumed. |
| 6 | `t_authorize` | `{p_analysis_done: 1, sink: 1}` | None | Authorization follows analysis, yet proper completion still fails. |

These are two manifestations of the same missing synchronization, rather than unrelated defects. Once waiver is selected, the quantity

```text
M(p_analysis) + M(p_analysis_done)
```

remains one in every continuation: analysis only moves the token, and the normal join can never fire. Therefore **every** waiver continuation fails to reach `fm`, not just the displayed schedules. This violates both the option to complete from every reachable marking and proper completion when a sink token appears.

By contrast, `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize` reaches exactly `fm`. Every transition is executable in some run from `im`; the unsoundness does not require a globally dead transition. The net is also bounded and 1-safe for this initial marking. Neither property prevents the stranded-token defect.

# 4. Minimal-Repair Alternatives

Use the following unit edit cost:

```text
cost = arcs added + arcs removed
     + places added + places removed
     + transitions added + transitions removed
```

Retargeting an arc costs two: one removal and one addition. Removing a node would also require counting removal of its incident arcs. All repairs below retain the initial/final markings, all nodes, all visible labels, and unit arc weights. No implicit changes are included.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **A — Separate, proper waiver synchronization; selected** | Add `p_analysis_done -> t_join_waived`. | **1** arc added. | Mandatory analysis, parallel branch enablement, exclusive standard/waiver choice, authorization after both completions, and exact final completion. | Waiver join now waits for and consumes analysis completion together with `p_waived`. Both analysis-first and waiver-first orders remain possible. | Two separate joins must continue to enforce the same analysis prerequisite during future edits. |
| **B — Route waiver through the normal synchronization** | Remove `t_join_waived -> p_decision`; add `t_join_waived -> p_review_done`. Keep `p_waived` and `t_join_waived`. | **2** arc edits. | The same business behavior as A, including mandatory analysis and both completion orders. | `t_join_waived` becomes a silent forwarding step; both outcomes ultimately pass through `t_join_normal`. The waiver path contains two silent steps after recording the waiver. | `p_review_done` now means either review outcome completed, and the name `t_join_waived` is misleading for a forwarder. Internal scheduling has extra silent interleavings. |
| **C — Cancel unperformed analysis when recording waiver; policy change** | Add `p_analysis -> t_waive_review`. | **1** arc added. | Registration, exclusive review outcome, mandatory analysis on the standard route, proper authorization/completion under the revised policy. | Waiver consumes both the review token and the pending analysis token, so analysis never occurs on a waiver case. Once analysis fires, waiver is disabled and standard review is required. | Violates the given mandatory-analysis rule and makes waiver availability depend on which transition fires first. Requires an explicitly different business policy. |

**Minimality and distinctness.** Zero edits leave the demonstrated defect. A sound repair therefore costs at least one under this model. A attains that lower bound while preserving the intended analysis requirement and concurrency. C also attains it, but for a different policy. Their equal costs do not imply equal suitability: C accepts waiver cases without analysis and forbids waiver after analysis has fired.

B is minimum-cost **within the stated architecture of routing both outcomes through the existing normal join, keeping the existing nodes and normal route**. The direct waiver-to-decision arc must be removed, and a connection to the normal join's review-input place must be added. Both edits are necessary, giving a lower bound of two that B achieves. Removing the decision arc alone strands the waiver path; adding the forwarding arc alone leaves the bypass and creates an extra token. B is also inclusion-minimal: neither proper subset of its two edits repairs the net. It is not the global cost minimum when A is allowed. A and B have the same intended visible complete traces, but different internal structures; C supplies an additional, genuinely different visible behavior.

**Why the repairs are sound.** Under A, after the split, analysis moves its token to `p_analysis_done` and exactly one review alternative produces its outcome token. The corresponding join consumes both tokens and produces the sole decision token. Authorization then leaves exactly `fm`. From every intermediate marking, the outstanding work can finish; both joins and every other transition occur in some complete run. The unselected join has no outcome token and cannot fire.

Under B, the waiver's token instead travels through the forwarding transition to `p_review_done`, where `t_join_normal` synchronizes it with analysis completion. The same completion argument applies. Under C, either waiver first consumes both pending branch tokens and completes alone, or analysis/standard review precludes waiver and the normal route completes. These are sound alternatives, but C enforces the changed policy described above.

# 5. Corrected PM4Py Code

This standalone construction implements **A**, adding only the missing analysis-completion input to the waiver join.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils


repaired_net = PetriNet("parallel_review_with_waiver_repaired")

p = {
    name: PetriNet.Place(name)
    for name in (
        "source",
        "p_ready",
        "p_analysis",
        "p_review",
        "p_analysis_done",
        "p_review_done",
        "p_waived",
        "p_decision",
        "sink",
    )
}
repaired_net.places.update(p.values())

transition_specs = (
    ("t_register", "Register Case"),
    ("t_split", None),
    ("t_analyze", "Perform Analysis"),
    ("t_standard_review", "Perform Standard Review"),
    ("t_waive_review", "Record Review Waiver"),
    ("t_join_normal", None),
    ("t_join_waived", None),
    ("t_authorize", "Authorize Case"),
)
t = {
    name: PetriNet.Transition(name, label)
    for name, label in transition_specs
}
repaired_net.transitions.update(t.values())

arcs = (
    (p["source"], t["t_register"]),
    (t["t_register"], p["p_ready"]),
    (p["p_ready"], t["t_split"]),
    (t["t_split"], p["p_analysis"]),
    (t["t_split"], p["p_review"]),
    (p["p_analysis"], t["t_analyze"]),
    (t["t_analyze"], p["p_analysis_done"]),
    (p["p_review"], t["t_standard_review"]),
    (t["t_standard_review"], p["p_review_done"]),
    (p["p_review"], t["t_waive_review"]),
    (t["t_waive_review"], p["p_waived"]),
    (p["p_analysis_done"], t["t_join_normal"]),
    (p["p_review_done"], t["t_join_normal"]),
    (t["t_join_normal"], p["p_decision"]),
    (p["p_waived"], t["t_join_waived"]),
    # Waiver authorization must also consume completed analysis.
    (p["p_analysis_done"], t["t_join_waived"]),
    (t["t_join_waived"], p["p_decision"]),
    (p["p_decision"], t["t_authorize"]),
    (t["t_authorize"], p["sink"]),
)
for source_node, target_node in arcs:
    petri_utils.add_arc_from_to(source_node, target_node, repaired_net)

repaired_im = Marking({p["source"]: 1})
repaired_fm = Marking({p["sink"]: 1})
```

# 6. Diagnostic and Reachability Code

Run the following after both the supplied original construction and Section 5. It invokes every requested API on both nets and replays the counterexamples using checked Petri-net firing semantics.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking
from pm4py.objects.petri_net import semantics


def marking_text(marking):
    entries = sorted(
        (place.name, count)
        for place, count in marking.items()
        if count != 0
    )
    return "{" + ", ".join(
        f"{name}: {count}" for name, count in entries
    ) + "}"


def enabled_names(a_net, marking):
    return sorted(
        transition.name
        for transition in pm4py.get_enabled_transitions(a_net, marking)
    )


def fire_named(a_net, marking, name):
    matches = [tr for tr in a_net.transitions if tr.name == name]
    if len(matches) != 1:
        raise ValueError(f"Expected exactly one transition named {name!r}")
    transition = matches[0]
    if transition not in pm4py.get_enabled_transitions(a_net, marking):
        raise ValueError(
            f"{name} is disabled at {marking_text(marking)}; "
            f"enabled={enabled_names(a_net, marking)}"
        )
    next_marking = semantics.execute(transition, a_net, marking)
    if next_marking is None:
        raise RuntimeError("Execution failed after the enabledness check")
    return next_marking


def walk(title, a_net, initial, names):
    current = Marking(initial)
    print(f"\n{title}")
    print(0, "initial", marking_text(current), enabled_names(a_net, current))
    for step, name in enumerate(names, start=1):
        current = fire_named(a_net, current, name)
        print(step, name, marking_text(current), enabled_names(a_net, current))
    return current


reachability_graphs = {}
for title, a_net, initial, final in (
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
):
    print(f"\nDiagnostics: {title}")
    print("Workflow net:", pm4py.check_is_workflow_net(a_net))
    soundness_result = pm4py.check_soundness(
        a_net, initial, final, print_diagnostics=True
    )
    print("Soundness result:", soundness_result)
    print(
        "Initially enabled:",
        sorted(tr.name for tr in pm4py.get_enabled_transitions(a_net, initial)),
    )
    reachability_graphs[title] = pm4py.convert_to_reachability_graph(
        a_net, initial, final
    )

original_sequences = (
    (
        "Original: authorization before analysis",
        ["t_register", "t_split", "t_waive_review", "t_join_waived",
         "t_authorize", "t_analyze"],
    ),
    (
        "Original: analysis before authorization",
        ["t_register", "t_split", "t_analyze", "t_waive_review",
         "t_join_waived", "t_authorize"],
    ),
)
for title, sequence in original_sequences:
    end = walk(title, net, im, sequence)
    assert end != fm
    assert not pm4py.get_enabled_transitions(net, end)

waiver_prefix = walk(
    "Repaired: waiver selected while analysis is pending",
    repaired_net,
    repaired_im,
    ["t_register", "t_split", "t_waive_review"],
)
for forbidden in ("t_join_waived", "t_authorize"):
    try:
        fire_named(repaired_net, waiver_prefix, forbidden)
    except ValueError as error:
        print("Correctly blocked:", error)
    else:
        raise AssertionError(f"Unexpected bypass through {forbidden}")

repaired_end = walk(
    "Repaired: finish analysis, synchronize, and authorize",
    repaired_net,
    waiver_prefix,
    ["t_analyze", "t_join_waived", "t_authorize"],
)
assert repaired_end == repaired_fm
assert not pm4py.get_enabled_transitions(repaired_net, repaired_end)

for review, join in (
    ("t_standard_review", "t_join_normal"),
    ("t_waive_review", "t_join_waived"),
):
    for branch_order in (("t_analyze", review), (review, "t_analyze")):
        sequence = ["t_register", "t_split", *branch_order, join, "t_authorize"]
        end = walk("Repaired positive regression", repaired_net, repaired_im, sequence)
        assert end == repaired_fm
```

The qualitative results, also observed when running the supplied APIs locally, are:

| Check | Original | Repair A |
|---|---|---|
| Workflow-net structure | Passes. | Passes. |
| Soundness | Fails. | Passes. |
| Initially enabled transitions | Only `t_register`. | Only `t_register`. |
| After registration, split, and waiver | Both `t_analyze` and `t_join_waived` enabled. | Only `t_analyze` enabled. |
| Reachability behavior | Reachable nonfinal dead marking and reachable sink-containing markings with analysis residue. | Every reachable marking has a continuation to exact `repaired_fm`; reaching the sink leaves no residue. |

Repairs B and C also passed the local workflow-net and soundness checks. Their different policy implications still require the reasoning in Section 4. The code prints the actual diagnostic result without assuming specific WOFLAN diagnostic keys. Constructing a reachability graph alone is not a soundness proof: its markings and edges must be inspected or checked for the relevant properties.

# 7. Repair Trade-Offs and Residual Risks

**Outcome identity.** A retains separate outcome places, separate joins, and both original visible review labels. Standard review and waiver therefore remain distinguishable in the model and event log. B retains both visible labels, but after its silent forwarding step, the marking in `p_review_done` does not identify which outcome produced it. Historical event information is then needed to recover that distinction. C retains distinct labels but changes waiver semantics to include cancellation of analysis.

**Silent behavior.** A adds no transition or silent loop. Although both joins require `p_analysis_done`, they cannot both be enabled: the exclusive review choice produces only one of their outcome tokens. Thus A does not introduce duplicate competing join behavior or double authorization. B adds no nodes either, but reuses the waiver transition's silent successor as a forwarder before the normal join. Different interleavings of that forwarding step and analysis can project to the same visible trace; tools should treat silent steps consistently. Its inherited transition/place names also warrant documentation.

**Soundness and business correctness.** Soundness establishes completion properties, not that the chosen policy is correct. C is a concrete counterexample: it is sound while allowing authorization without analysis. A's stronger business argument is that both producers of `p_decision` consume `p_analysis_done`, whose only producer is `t_analyze`, together with exactly one review outcome. Event labels alone do not establish that real analysis was performed or that a waiver record contains the required evidence. The net models control flow, not those data checks or actual task start times.

**Positive regression traces.** For A, test all four combinations of review outcome and branch completion order. For each pair

```text
(r, j) = (t_standard_review, t_join_normal)
      or (t_waive_review, t_join_waived)
```

both of these must execute and finish at exactly `repaired_fm`:

```text
t_register, t_split, t_analyze, r, j, t_authorize
t_register, t_split, r, t_analyze, j, t_authorize
```

**Negative regression traces and markings.** Check that:

- Authorization cannot execute before analysis, including after a waiver has been recorded and after any available silent transitions.
- Analysis alone cannot enable authorization without a review outcome, and neither review outcome alone can enable authorization without analysis.
- After one review alternative fires, the other cannot fire for the same case; a join for the unselected outcome is disabled.
- Analysis, a review outcome, or authorization cannot be repeated using the same case tokens.
- A sink-containing marking with any additional token is rejected as final. In particular, both original counterexamples must fail proper-completion checks.

**Detecting future analysis bypasses.** Explore reachable states augmented with a Boolean recording whether `t_analyze` has fired and a value recording the selected review outcome. At every state where `t_authorize` is enabled, require that analysis has fired and exactly one review outcome has occurred. Track these facts with the marking, since different histories can otherwise merge into the same marking. Retain a shortest violating path as a counterexample. Separately check that any reachable marking containing a sink token equals the exact final marking and that every reachable marking can reach it. This catches both a new authorization bypass and a leftover-token regression; the original analysis-first counterexample demonstrates why checking event order alone is insufficient.

# 8. Final Recommendation

Deploy **Repair A**: add `p_analysis_done -> t_join_waived`. It has the minimum possible positive edit cost, preserves both review outcomes and parallel completion orders, and directly enforces mandatory analysis on both authorization routes. Its token-consumption argument is simple, and its code differs structurally from the original by one arc.

Use **Repair B** as the fallback when one shared synchronization point is preferred. Redirect the existing waiver forwarding transition into `p_review_done`, retaining the visible waiver event and requiring the normal join to consume analysis completion. It costs two arc edits and needs documentation of the shared place's broader meaning, but preserves the intended visible behavior.

Do not deploy C under the stated business intent. Its equally low edit cost repairs soundness only by allowing waiver to cancel analysis and restricting when waiver may be selected. Before deployment of A or B, require both soundness checks and the positive/negative policy regressions above, including exact final-marking equality.
