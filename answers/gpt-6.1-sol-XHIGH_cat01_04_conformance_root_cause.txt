Several mechanisms plausibly act together. The UI release creates a vocabulary mismatch: a completed classification can generate a Risk Screen log move and a Classify model move. Gateway instrumentation adds Queue Routed without necessarily adding business work. Ingestion timestamps can invert Decision and Notify even when the source execution is correct. The reported staged improvements support these mechanisms, but they are interventions on one measurement pipeline, not independent confirmations, and their sizes depend on preprocessing order.

August introduces a different mismatch. A mandated sign-off changes the legitimate process while the normative tree remains unchanged. Sign-offs therefore lower old-model fitness despite potentially improving compliance. An optional sign-off candidate accommodates observed behavior but also accepts a high-value case without sign-off; increased fitness is not policy validation.

Residual enhanced reviews without checks could reflect genuine bypasses, missing or mislinked events, or lifecycle capture differences. Manual Override is a user action whose authorization and purpose require investigation, particularly because its logging changed. Neither activity should be erased to maximize fitness.

Stable approval, appeal, and detected-incident rates constrain claims of widespread outcome-visible harm. They do not establish data error: legitimate extra controls or small deviations may leave these outcomes unchanged. Nor do they exclude noncompliance, because obligations can be violated without immediate appeals, detection is incomplete, and follow-up or case mix may mask effects. Finally, incompatible variant and summary statistics require provenance reconciliation before precise causal attribution.

## 4. Counterfactual predictions

Each repair preserves the same case population unless explicitly testing population differences. Changes refer to recorded behavior and measurement; repairing a historical log cannot retroactively improve actual operations.

## 6. PM4Py reproduction and model-comparison code

The code preserves the listed extracted order. Aggregate variants contain neither source sequence nor high-value attributes, so it deliberately does not manufacture ordering repairs or data-aware findings. It reproduces variant-based results, not the internally inconsistent aggregate alignment summaries. PM4Py is a prerequisite.

```python
from collections import Counter
from copy import deepcopy
from statistics import mean

import pm4py
from pm4py.util import constants
from pm4py.objects.log.obj import EventLog, Trace

constants.SHOW_PROGRESS_BAR = False
ACTIVITY = 'concept:name'
SOURCE_SEQUENCE = 'source:sequence'

VARIANTS = {
    'Apr-May': [
        ('Receive,Classify,Standard Review,Decision,Notify', 380),
        ('Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify', 180),
        ('Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify', 40),
    ],
    'Jun-Jul': [
        ('Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify', 270),
        ('Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify', 145),
        ('Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision', 70),
        ('Receive,Risk Screen,Standard Review,Decision,Notify', 90),
        ('Receive,Classify,Queue Routed,Standard Review,Decision,Notify', 30),
        ('Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify', 25),
        ('Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify', 20),
    ],
    'Aug-Sep': [
        ('Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify', 210),
        ('Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify', 150),
        ('Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify', 90),
        ('Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify', 60),

BRANCH = "X( *( 'Standard Review', 'Request Info' ), ->( 'Enhanced Review', 'Compliance Check' ) )"
NORMATIVE_TEXT = "->( 'Receive', 'Classify', " + BRANCH + ", 'Decision', 'Notify' )"
CANDIDATE_TEXT = (
    "->( 'Receive', 'Classify', " + BRANCH
    + ", X( tau, 'Supervisor Sign-off' ), 'Decision', 'Notify' )"
)
normative_tree = pm4py.parse_process_tree(NORMATIVE_TEXT)
normative_net, normative_im, normative_fm = pm4py.convert_to_petri_net(normative_tree)
candidate_tree = pm4py.parse_process_tree(CANDIDATE_TEXT)

def expand_variants(period, rows):
    strings = [variant for variant, count in rows for _ in range(count)]
    parsed = pm4py.parse_event_log_string(strings)
    # Some PM4Py versions return a DataFrame; make the log type explicit.
    log = pm4py.convert_to_event_log(parsed)
    log.attributes['period'] = period
    log.attributes['timestamp_provenance'] = (
        'Aggregate reproduction: parser timestamps are synthetic placeholders; '
        'trace positions reproduce the supplied extracted order.'
    )
    for number, trace in enumerate(log, 1):
        trace.attributes['concept:name'] = f'{period}-{number}'
    assert len(log) == sum(count for _, count in rows)
    return log


def normalize(log, remove_queue=False, order_by_source=False):
    """Keep the input intact; never delete Manual Override or insert missing checks."""
    result = EventLog(attributes=deepcopy(log.attributes))
    for trace in log:
        retained = []
        for original_event in trace:
            event = deepcopy(original_event)
            original = event[ACTIVITY]
            event['original:activity'] = original
            if original == 'Risk Screen':
                event[ACTIVITY] = 'Classify'
            if remove_queue and original == 'Queue Routed':
                continue
            retained.append(event)
        if order_by_source:
            # Use only a validated, case-local total ordering from the source.
            # Missing or duplicate sequence numbers cause failure, not guessing.
            if any(SOURCE_SEQUENCE not in event for event in retained):
                raise ValueError('Source sequence is absent; aggregates cannot repair ordering.')
            sequences = [int(event[SOURCE_SEQUENCE]) for event in retained]
            if len(sequences) != len(set(sequences)):
                raise ValueError('Ambiguous source sequence; reconcile source streams first.')
            retained.sort(key=lambda event: int(event[SOURCE_SEQUENCE]))
        result.append(Trace(retained, attributes=deepcopy(trace.attributes)))
    result.attributes['normalization'] = {
        'label_map': {'Risk Screen': 'Classify'},
        'removed_activity': 'Queue Routed' if remove_queue else None,
        'order': 'validated source sequence' if order_by_source else 'supplied trace order',
    }
    return result


def show_structure(title, log):
    variants = Counter(tuple(event[ACTIVITY] for event in trace) for trace in log)
    dfg, start_activities, end_activities = pm4py.discover_dfg(log)
    print('\nSTRUCTURE:', title, 'cases=', len(log))
    print('Variants:', dict(variants))
    print('Frequency DFG:', dict(sorted(dfg.items())))
    print('Start/end:', start_activities, end_activities)


def visible_moves(alignment):
    log_moves, model_moves = Counter(), Counter()
    for log_label, model_label in alignment:
        if model_label == '>>' and log_label not in (None, '>>'):
            log_moves[log_label] += 1
        elif log_label == '>>' and model_label not in (None, '>>'):
            model_moves[model_label] += 1
        # ('>>', None) is an invisible model transition, not a missing task.
    return log_moves, model_moves


def assess(title, log, accepting_net, include_precision=False):
    net, initial_marking, final_marking = accepting_net
    diagnostics = pm4py.conformance_diagnostics_alignments(
        log, net, initial_marking, final_marking
    )
    fitness = pm4py.fitness_alignments(log, net, initial_marking, final_marking)
    total_log_moves, total_model_moves = Counter(), Counter()
    visible_fits, representative = 0, {}
    for trace, diagnostic in zip(log, diagnostics):
        log_moves, model_moves = visible_moves(diagnostic['alignment'])
        total_log_moves.update(log_moves)
        total_model_moves.update(model_moves)
        visible_fits += int(not log_moves and not model_moves)
        if log_moves or model_moves:
            variant = tuple(event[ACTIVITY] for event in trace)
            representative.setdefault(variant, diagnostic['alignment'])
    summary = {
        'cases': len(log),
        'fitting_traces_no_visible_deviations_pct': 100 * visible_fits / len(log),
        'alignment_fitness': fitness,
        'mean_raw_alignment_cost': mean(diagnostic['cost'] for diagnostic in diagnostics),
        'moves_on_log': dict(total_log_moves),
        'visible_moves_on_model': dict(total_model_moves),
    }
    if include_precision:
        summary['alignment_precision'] = pm4py.precision_alignments(
            log, net, initial_marking, final_marking
        )
    print('\nASSESSMENT:', title)
    print(summary)
    print('One optimal alignment per deviating variant:', representative)
    return summary


raw_logs = {period: expand_variants(period, rows) for period, rows in VARIANTS.items()}
normalized_logs = {}
for period, raw_log in raw_logs.items():
    normalized_log = normalize(raw_log, remove_queue=True)
    normalized_logs[period] = normalized_log
    show_structure(period + ' raw', raw_log)
    show_structure(period + ' label map + queue removal', normalized_log)
    assess(period + ' raw / normative', raw_log, normative)
    assess(period + ' normalized / normative', normalized_log, normative,
           include_precision=(period == 'Aug-Sep'))

# Isolate the mapping intervention before adding technical-event removal.
assess('Jun-Jul label map only / normative', normalize(raw_logs['Jun-Jul']), normative)
assess('Aug-Sep normalized / optional sign-off', normalized_logs['Aug-Sep'], candidate,
       include_precision=True)

      'resources are supplied. No Decision/Notify swaps were manufactured.')
```

On the supplied variants, the reproduction yields 100% exact fitting in April–May, 0% for raw June–July, 13.85% after June label mapping alone, and 82.31% after June mapping plus queue removal. August mapping plus removal gives 48.39% against the original model and 82.26% against the optional candidate, without any ordering repair. This does not validate the candidate’s missing data guard. Invisible transition costs also explain why a perfectly fitting trace can have a small nonzero raw alignment cost.

## 7. Provisional conclusion

The strongest explanation for the measured collapse is a combination of changed event representation and an outdated policy model. June introduces a renamed classification activity, gateway routing events, and ingestion-based ordering. Each can create alignment deviations without an equivalent change in business execution. The reported successive improvements support their joint contribution. August then adds a legitimate policy obligation absent from the normative tree, making compliant sign-offs appear as deviations. Confidence is high, approximately 90/100, that these mechanisms explain a substantial portion of the deterioration; confidence in their exact numerical shares is much lower because the supplied reports and variants do not reconcile.

A real compliance problem may nevertheless remain. Fifty-five enhanced-review cases lack recorded checks, overrides are real user actions, and high-value sign-off omissions cannot be assessed from the aggregate report. Missing-check prevalence among recorded enhanced reviews is 14.7% in June–July and 11.1% in August–September, so the larger August count does not establish worsening behavior. Confidence that employee noncompliance actually occurred is low to moderate, approximately 40/100, pending independent audit. Confidence that these residuals deserve targeted investigation is high. Stable appeals and incomplete incident detection provide limited reassurance, not proof of compliance.

IT should reconcile report populations and configurations, preserve raw events, validate canonical labels and the technical-event projection, and restore trustworthy ordering from source provenance. It should verify missing-check capture before backfilling anything. Process owners should approve an effective-dated model that accommodates legitimate sign-offs while requiring them for applicable high-value cases, and establish the authorized meaning of overrides. Compliance should audit the 55 missing-check cases and matched controls, inspect supervisor authorization and actual notification timing, and assess reviewer differences only after correcting capture and case-mix effects.

It must not yet be claimed that employees caused the collapse, that every reversal is false, that missing events prove missing work, or that improved fitness establishes policy compliance. Neither the optional candidate nor unchanged outcomes demonstrate satisfaction of the EUR 50,000 condition. Historical measurement corrections and confirmed operational remediation should be reported separately.

## 8. Model-governance recommendation

1. **Version models with policy.** Record owner, approval, effective dates, applicable populations, and change rationale. Retain historical versions and test each case against the policy applicable to it; do not let a discovered process automatically redefine normative requirements.
2. **Maintain event-semantic contracts.** Define canonical activities, source action identifiers, lifecycle meanings, case linkage, and schema versions. Preserve original labels and approve equivalence mappings using source evidence; document changes to user-action capture such as Manual Override.
3. **Define the technical-event policy.** Preserve a complete raw audit stream and publish a versioned business-event projection. Exclude only provenance-validated technical events, with explicit filter manifests; missing resources or inconvenient alignment moves are insufficient grounds for removal.
4. **Preserve timestamp and ordering provenance.** Store occurrence, completion, dispatch, and ingestion times separately, including time zones and clock semantics. Validate sequence scope and tie handling, document ordering rules, and reject ambiguous chronology rather than silently substituting ingestion time.
5. **Enforce data-aware constraints.** Join applicable claim value, currency, policy date, and resource authorization to cases. Require authorized pre-decision sign-off above EUR 50,000 and the appropriate branch checks; treat unknown attributes as unresolved rather than compliant, and audit rules that plain control-flow models cannot express.
6. **Validate after releases and pipeline changes.** Compare fixed, reconciled cohorts before and after each change using variants, frequency DFGs, event completeness, alignment moves, fitness, precision, and stratified compliance-rule rates. Include source-backed audit samples and checks of report consistency, and assign owners to unexplained deviations before accepting improved fitness as evidence of success.
