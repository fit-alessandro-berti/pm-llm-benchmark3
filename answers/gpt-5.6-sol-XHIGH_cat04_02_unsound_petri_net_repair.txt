# 1. Executive Verdict

Structurally, the accepting net is a workflow net: it has one source place, one sink place, and every node lies on a directed source-to-sink path. It should not be expected to be sound. `t_join_waived` consumes only `p_waived`; it neither requires nor consumes the token representing completion of the mandatory analysis. Consequently, after a waiver, `t_authorize` can fire while the analysis token remains in `p_analysis`. A token can therefore appear in `sink` together with a residual analysis token. Even if analysis is then performed, the resulting `p_analysis_done` token cannot enter `t_join_normal` because the review token was spent on the waiver. The waiver branch violates the authorization rule and cannot reach the exact final marking `fm`, although the standard-review branch can.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source  t_register  p_ready` | Create and register one case | Produces one token in `p_ready` from the unique source token | Correct single-case initialization |
| `t_split` | Start analysis and review in parallel | Consumes one token from `p_ready` and produces one token in each of `p_analysis` and `p_review` | Correct AND-split; both branch tokens must eventually be accounted for |
| `t_analyze` | Perform mandatory analysis | Moves the analysis token from `p_analysis` to `p_analysis_done` | Correct locally, but the completion token is ignored by the waiver join |
| `t_standard_review` | Complete the standard review outcome | Competes with `t_waive_review` for the single token in `p_review`, then produces `p_review_done` | Implements one side of an XOR choice |
| `t_waive_review` | Formally record the alternative review outcome | Competes with `t_standard_review` and produces `p_waived` | Waiver and standard review remain visibly distinguishable |
| `t_join_normal` | Synchronize analysis with standard review | Requires both `p_analysis_done` and `p_review_done`, consuming both before producing `p_decision` | Correct two-input synchronization for the standard path |
| `t_join_waived` | Synchronize analysis with the recorded waiver | Has only `p_waived` as input and therefore behaves as a one-input pass-through | Enables authorization without analysis and leaves the analysis-branch token behind |
| `p_decision  t_authorize  sink` | Authorize only after all obligations are met | Authorization requires only a token in `p_decision`; it cannot detect residual tokens elsewhere | A token may reach `sink` even though the accepting final marking has not been reached |
| `im` and `fm` | Start with exactly one source token and finish with exactly one sink token | `im = {source: 1}` and `fm = {sink: 1}` are conventional workflow-net markings | `sink` being marked is insufficient if `p_analysis` or `p_analysis_done` is also marked |
| Whole directed graph | Form a workflow net | `source` is the only place without incoming arcs, `sink` is the only place without outgoing arcs, and every node lies on some directed source-to-sink path | The structural workflow-net check can pass even though the waiver behavior is unsound |

The source-to-sink path condition is graph-theoretic. It does not verify that all required input tokens of a transition can be jointly supplied in every execution.

# 3. Marking-Based Counterexample

The following is a legal firing sequence:

```text
t_register,
t_split,
t_waive_review,
t_join_waived,
t_authorize,
t_analyze
```

All unlisted place counts in the table are zero.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---:|---|---|---|---|
| 0 | — | `{source: 1}` | `t_register` | This is exactly `im`. |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | The case has been registered. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token has been created in each parallel branch. |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `t_analyze`, `t_join_waived` | The review token has selected the waiver outcome. Analysis is still outstanding. |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, `t_authorize` | The defective join consumes only the waiver token. Authorization and analysis are now concurrently enabled. |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `t_analyze` | A token exists in `sink`, but this marking is not `fm` because the analysis token remains. |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | None | Analysis can occur after authorization, but its completion token is now permanently stranded. |

Thus, `t_authorize` can occur before `t_analyze`. It can also occur after it. From the step-3 marking, the alternative suffix

```text
t_analyze, t_join_waived, t_authorize
```

ends in `{p_analysis_done: 1, sink: 1}`. In either ordering, the exact final marking is not reached.

The leftover token cannot be consumed because:

- `t_join_normal` also requires `p_review_done`;
- the only review token was consumed by `t_waive_review`, so `p_review_done` can no longer be produced;
- `t_join_waived` consumed `p_waived` and cannot fire again;
- `sink` has no outgoing arcs.

By contrast, the normal sequence

```text
t_register, t_split, t_analyze, t_standard_review,
t_join_normal, t_authorize
```

does reach exactly `{sink: 1}`. Early authorization and improper completion are two consequences of the same missing synchronization, rather than independent defects.

# 4. Minimal-Repair Alternatives

Use the edit-cost model

\[
C = \#\text{arc additions/removals}
  + \#\text{place additions/removals}
  + \#\text{transition additions/removals}.
\]

An endpoint rewrite counts as one arc removal plus one arc addition. Deleting a node would also require separately deleting its incident arcs. None of these alternatives changes `im` or `fm`.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| **A. Add the missing waiver synchronization input** | Add arc `p_analysis_done  t_join_waived` | **1** | Analysis remains mandatory; waiver and standard review remain distinct; both branch tokens are consumed before authorization | `t_join_waived` becomes a two-input join and cannot fire until both analysis and waiver are complete | `p_analysis_done` feeds two alternative joins, creating a non-free-choice-looking structure that future edits could accidentally destabilize |
| **B. Normalize waiver into the common review-completion place** | Remove arc `t_join_waived  p_decision`; add arc `t_join_waived  p_review_done` | **2** | Analysis remains mandatory; the visible waiver event remains distinct from standard review | `t_join_waived` becomes a silent waiver normalizer; `t_join_normal` is the sole synchronization before decision | Internal provenance is merged in `p_review_done`, and the transition name `t_join_waived` becomes misleading because it is no longer a join |
| **C. Policy change: allow waiver to waive analysis as well** | Add arc `p_analysis  t_join_waived`; add silent transition `t_waiver_normalize_after_analysis`; add arcs `p_waived  t_waiver_normalize_after_analysis  p_review_done` | **4** | Registration, parallel launch, exclusive review outcomes, and clean final completion remain; analysis is still mandatory for standard review | On the waiver path, the original join may consume an unperformed analysis token, allowing a visible trace with waiver and authorization but no analysis. If analysis has already run, the new transition routes the waiver through `t_join_normal` | Explicitly contradicts the stated mandatory-analysis policy and makes the cancellation of analysis silent rather than formally recorded |

Repair A is globally minimal under this cost model: the unchanged net is defective, so cost zero cannot repair it, while one added arc both requires and consumes the missing analysis-completion token.

Repair B is minimal within the design family that routes both review outcomes through the existing common synchronization. Merely adding a second output would retain the early `p_decision` token, while merely removing the old output would block completion. Therefore, one removal and one addition are both necessary.

Repair C is minimal under the constraints that the policy change is waiver-specific, all original arcs are retained, and both possible interleavings are supported. The existing waiver join needs one new input to consume an unperformed analysis token. Once analysis has already completed, a distinct route from `p_waived` to the normal synchronization is necessary; an ordinary Petri net requires a transition and two arcs for that route.

# 5. Corrected PM4Py Code

The following implements Repair A.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

r_source = PetriNet.Place("source")
r_ready = PetriNet.Place("p_ready")
r_analysis = PetriNet.Place("p_analysis")
r_review = PetriNet.Place("p_review")
r_analysis_done = PetriNet.Place("p_analysis_done")
r_review_done = PetriNet.Place("p_review_done")
r_waived = PetriNet.Place("p_waived")
r_decision = PetriNet.Place("p_decision")
r_sink = PetriNet.Place("sink")

for place in [
    r_source,
    r_ready,
    r_analysis,
    r_review,
    r_analysis_done,
    r_review_done,
    r_waived,
    r_decision,
    r_sink,
]:
    repaired_net.places.add(place)

r_register = PetriNet.Transition("t_register", "Register Case")
r_split = PetriNet.Transition("t_split", None)
r_analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
r_standard_review = PetriNet.Transition(
    "t_standard_review", "Perform Standard Review"
)
r_waive_review = PetriNet.Transition(
    "t_waive_review", "Record Review Waiver"
)
r_join_normal = PetriNet.Transition("t_join_normal", None)
r_join_waived = PetriNet.Transition("t_join_waived", None)
r_authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for transition in [
    r_register,
    r_split,
    r_analyze,
    r_standard_review,
    r_waive_review,
    r_join_normal,
    r_join_waived,
    r_authorize,
]:
    repaired_net.transitions.add(transition)

arcs = [
    (r_source, r_register),
    (r_register, r_ready),
    (r_ready, r_split),
    (r_split, r_analysis),
    (r_split, r_review),

    (r_analysis, r_analyze),
    (r_analyze, r_analysis_done),

    (r_review, r_standard_review),
    (r_standard_review, r_review_done),

    (r_review, r_waive_review),
    (r_waive_review, r_waived),

    (r_analysis_done, r_join_normal),
    (r_review_done, r_join_normal),
    (r_join_normal, r_decision),

    (r_waived, r_join_waived),
    # Repair: the waiver join must also consume completed analysis.
    (r_analysis_done, r_join_waived),
    (r_join_waived, r_decision),

    (r_decision, r_authorize),
    (r_authorize, r_sink),
]

for source_node, target_node in arcs:
    petri_utils.add_arc_from_to(source_node, target_node, repaired_net)

repaired_im = Marking()
repaired_im[r_source] = 1

repaired_fm = Marking()
repaired_fm[r_sink] = 1
```

# 6. Diagnostic and Reachability Code

This block assumes the original `net`, `im`, and `fm` and the repaired variables from the preceding block exist.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def marking_text(marking):
    entries = sorted(
        (place.name, count)
        for place, count in marking.items()
        if count != 0
    )
    return "{" + ", ".join(
        f"{name}: {count}" for name, count in entries
    ) + "}"


def enabled_names(petri_net, marking):
    return sorted(
        transition.name
        for transition in pm4py.get_enabled_transitions(
            petri_net, marking
        )
    )


def fire_named(petri_net, marking, transition_name):
    matches = [
        transition
        for transition in petri_net.transitions
        if transition.name == transition_name
    ]
    if len(matches) != 1:
        raise ValueError(
            f"Expected one transition named {transition_name!r}, "
            f"found {len(matches)}"
        )

    transition = matches[0]
    enabled = set(
        pm4py.get_enabled_transitions(petri_net, marking)
    )
    if transition not in enabled:
        raise RuntimeError(
            f"{transition_name} is not enabled at "
            f"{marking_text(marking)}; enabled transitions are "
            f"{sorted(t.name for t in enabled)}"
        )

    new_marking = Marking(marking)

    for arc in transition.in_arcs:
        place = arc.source
        weight = getattr(arc, "weight", 1)
        new_marking[place] -= weight
        if new_marking[place] == 0:
            del new_marking[place]

    for arc in transition.out_arcs:
        place = arc.target
        weight = getattr(arc, "weight", 1)
        new_marking[place] += weight

    print(
        f"after {transition_name}: {marking_text(new_marking)}; "
        f"enabled={enabled_names(petri_net, new_marking)}"
    )
    return new_marking


models = [
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
]

reachability_graphs = {}

for name, petri_net, initial_marking, final_marking in models:
    print(f"\n=== {name} ===")
    print(
        "workflow net:",
        pm4py.check_is_workflow_net(petri_net),
    )
    print(
        "soundness result:",
        pm4py.check_soundness(
            petri_net,
            initial_marking,
            final_marking,
            print_diagnostics=True,
        ),
    )
    print(
        "initially enabled:",
        sorted(
            transition.name
            for transition in pm4py.get_enabled_transitions(
                petri_net, initial_marking
            )
        ),
    )
    reachability_graphs[name] = (
        pm4py.convert_to_reachability_graph(
            petri_net,
            initial_marking,
            final_marking,
        )
    )
    print("reachability graph constructed")

print("\n=== Original waiver counterexample ===")
original_marking = Marking(im)
for transition_name in [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_join_waived",
    "t_authorize",
    "t_analyze",
]:
    original_marking = fire_named(
        net, original_marking, transition_name
    )
print("exact original fm reached:", original_marking == fm)

print("\n=== Repaired waiver completion ===")
repaired_marking = Marking(repaired_im)
for transition_name in [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_analyze",
    "t_join_waived",
    "t_authorize",
]:
    repaired_marking = fire_named(
        repaired_net, repaired_marking, transition_name
    )
print(
    "exact repaired fm reached:",
    repaired_marking == repaired_fm,
)
```

Qualitatively, both workflow-net checks should succeed. The original soundness check should fail because the waiver branch permits improper completion and reaches a dead marking containing `sink` plus `p_analysis_done`. Its reachability graph should also expose authorization before analysis. The repaired net should be reported as sound, with `t_join_waived` disabled until both `p_waived` and `p_analysis_done` are marked, and the demonstrated waiver sequence should end exactly in `repaired_fm`.

# 7. Repair Trade-Offs and Residual Risks

- **Distinguishability of review outcomes:** In Repair A, standard review and waiver remain separate visible transitions with distinct labels and places. They merge only after their corresponding join produces `p_decision`. Downstream markings do not retain the selected outcome, so persistent reporting must rely on the event history or additional case data.
- **Silent-transition risks:** `t_split`, `t_join_normal`, and `t_join_waived` remain silent. The two joins do not create duplicate reachable behavior in the repaired model because the single `p_review` token permits only one review outcome. Nevertheless, two silent synchronization transitions can look redundant to maintainers and may drift apart in future revisions.
- **Soundness versus policy conformance:** Soundness proves behavioral completion properties relative to `repaired_im` and `repaired_fm`; it does not prove the intended business policy. Repair C, for example, can be made sound while explicitly violating mandatory analysis.
- **Positive regression traces:** Test both orders of analysis and standard review, and both orders of analysis and waiver. Each complete positive trace must end in exactly `{sink: 1}`.
- **Negative regression traces:** Reject waiver followed by authorization without analysis, standard review followed by authorization without analysis, both review alternatives in one case, repeated authorization, and any purported completion containing `sink` plus another token.
- **Detecting an analysis bypass:** Traverse the reachability graph while carrying an auxiliary Boolean `analysis_seen`. Report any edge firing `t_authorize` where the flag is false. Also assert structurally that every transition producing `p_decision` requires the completed-analysis token directly or through a proven common synchronization.

# 8. Final Recommendation

Deploy **Repair A**. It is the global minimum under the stated edit-cost model, preserves every visible label and business rule, and directly expresses the missing requirement: the waiver join must consume both the waiver outcome and completed analysis. It is also easy to review as a one-arc patch and straightforward to regression-test.

Use **Repair B** as the fallback if maintainability concerns outweigh the desire for the smallest patch. It centralizes synchronization in `t_join_normal`, giving the model a conventional “XOR outcome normalization followed by AND-join” structure. If selected, rename or document `t_join_waived` as a waiver normalizer because it would no longer perform synchronization.

Do not deploy Repair C without explicit governance approval: although it can be sound, it changes the policy by allowing a review waiver to cancel mandatory analysis.
