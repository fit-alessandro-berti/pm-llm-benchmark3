# 1. Executive Verdict

The given accepting Petri net is a valid **structural workflow net**: it has a unique source place (`source` with an empty preset), a unique sink place (`sink` with an empty postset), and every place and transition lies on a directed path from `source` to `sink`. 

However, the net is **behaviorally unsound** and violates the business intent. The principal defect is an incomplete synchronization at the silent transition `t_join_waived`, which consumes a token from `p_waived` without requiring a token from `p_analysis_done`. 

**Business and behavioral consequences:**
1. **Compliance Violation (Premature Authorization):** When a review is waived via `t_waive_review`, the case can be authorized (`t_authorize`) before the mandatory analysis (`t_analyze`) is even performed.
2. **Improper Completion (Dead Tokens):** The token produced for the parallel analysis branch is stranded in either `p_analysis` or `p_analysis_done` when `sink` is reached, violating proper completion (`fm` is never cleanly reached on the waiver path).

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
| :--- | :--- | :--- | :--- |
| **`source` / `sink` and `im` / `fm`** | Define unique entry and exit points with single-token initial and final markings. | `•source = `, `sink• = `, `im = [source:1]`, `fm = [sink:1]`. Every node is on a directed path from `source` to `sink` (thus passing `check_is_workflow_net`). | None structurally; however, reaching `sink` with 1 token does not guarantee other places are empty. |
| **`t_split` (`p_ready` $\to$ `p_analysis`, `p_review`)** | Parallel AND-split initiating mandatory analysis and review concurrently. | Places 1 token in `p_analysis` and 1 token in `p_review`. | Creates a strict obligation to later synchronize *both* branches before reaching `sink`. |
| **Review branch (`p_review` $\to$ `t_standard_review` $\mid$ `t_waive_review`)** | Exclusive XOR-split choosing between standard review and recorded waiver. | Routes the single token from `p_review` to either `p_review_done` or `p_waived`. | Mutually exclusive outcomes: if `p_waived` gets a token, `p_review_done` will remain empty for this case. |
| **`t_join_normal` (`p_analysis_done`, `p_review_done` $\to$ `p_decision`)** | AND-join synchronizing completed analysis with completed standard review. | Requires 1 token in `p_analysis_done` and 1 in `p_review_done` to fire. | Becomes permanently deadlocked for the current case if the waiver path (`t_waive_review`) was chosen. |
| **`t_join_waived` (`p_waived` $\to$ `p_decision`)** | Intended to synchronize the waiver outcome with completed analysis. | Acts as a simple pass-through (`•t_join_waived = {p_waived}`). It lacks an input arc from `p_analysis_done`. | Fires as soon as `t_waive_review` completes, ignoring the state of the analysis branch and stranding its token. |

# 3. Marking-Based Counterexample

### Counterexample 1: Premature Authorization before Analysis (`t_authorize` before `t_analyze`)
Consider the legal firing sequence:
$$\sigma_1 = \langle \text{t\_register}, \text{t\_split}, \text{t\_waive\_review}, \text{t\_join\_waived}, \text{t\_authorize} \rangle$$

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| :--- | :--- | :--- | :--- | :--- |
| 0 | *(Initial)* | `source: 1` | `t_register` | Exact initial marking `im`. |
| 1 | `t_register` | `p_ready: 1` | `t_split` | Case is registered. |
| 2 | `t_split` | `p_analysis: 1`, `p_review: 1` | `t_analyze`, `t_standard_review`, `t_waive_review` | Parallel branches created; 1 token in each branch. |
| 3 | `t_waive_review` | `p_analysis: 1`, `p_waived: 1` | `t_analyze`, `t_join_waived` | Waiver recorded. `t_join_waived` is immediately enabled because its preset is only `{p_waived}`. |
| 4 | `t_join_waived` | `p_analysis: 1`, `p_decision: 1` | `t_analyze`, `t_authorize` | **Defect exposed:** `t_authorize` is enabled before `t_analyze` has fired. |
| 5 | `t_authorize` | `p_analysis: 1`, `sink: 1` | `t_analyze` | **Improper completion & policy violation:** A token is in `sink` prior to analysis, and the marking `[p_analysis: 1, sink: 1]` $\neq$ `fm` (`[sink: 1]`). |
| 6 | `t_analyze` | `p_analysis_done: 1`, `sink: 1` | *None (Dead)* | Even after `t_analyze` finally executes, the token in `p_analysis_done` cannot be consumed. |

### Counterexample 2: Post-Analysis Improper Completion (`t_authorize` after `t_analyze`)
Even if the analysis completes first along the sequence:
$$\sigma_2 = \langle \text{t\_register}, \text{t\_split}, \text{t\_analyze}, \text{t\_waive\_review}, \text{t\_join\_waived}, \text{t\_authorize} \rangle$$
- After `t_analyze` and `t_waive_review` fire, the marking is `[p_analysis_done: 1, p_waived: 1]`.
- Firing `t_join_waived` consumes only `p_waived`, yielding `[p_analysis_done: 1, p_decision: 1]`.
- Firing `t_authorize` yields the terminal marking `[p_analysis_done: 1, sink: 1]`.

**Why the leftover token cannot be consumed:**
In both $\sigma_1$ (at Step 6) and $\sigma_2$, a residual token is trapped in `p_analysis_done`. The only transition in the net with `p_analysis_done` in its preset is `t_join_normal` (`p_analysis_done• = {t_join_normal}`). However, firing `t_join_normal` requires a token in `p_review_done` (`•t_join_normal = {p_analysis_done, p_review_done}`). Because the single token in `p_review` was already consumed by `t_waive_review`, `p_review_done` is empty and can never receive a token. Thus, `t_join_normal` is permanently disabled, and the exact final marking `fm = [sink: 1]` is unreachable whenever a waiver occurs.

# 4. Minimal-Repair Alternatives

### Explicit Edit-Cost Model
Let the structural edit cost $C$ of a repair be defined as the unweighted sum of atomic graph edits:
$$C = \Delta_{\text{arc}} + \Delta_{\text{place}} + \Delta_{\text{transition}}$$
where each added or removed arc, place, or transition costs $1$. Changing a transition's label or silent status is not needed below, and re-routing an arc is counted as $1\text{ removal} + 1\text{ addition} = 2$.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **R1: Two-Input Waiver Synchronization** | **Add 1 arc:**<br>`(p_analysis_done, t_join_waived)` | **$1$**<br>*(1 arc added)* | Retains mandatory analysis on both paths; preserves all existing places, transitions, and labels. | `t_join_waived` now blocks until both `p_analysis_done` and `p_waived` contain a token. Both tokens are consumed upon firing. | Two silent AND-joins (`t_join_normal`, `t_join_waived`) share `p_analysis_done` as an input. While free-choice conflict does not occur because `p_review_done` and `p_waived` are mutually exclusive, the net retains an extra silent transition compared to a merged-place design. |
| **R2: Shared Review-Outcome Place (XOR-Join before AND-Join)** | **Remove 3 arcs:**<br>`(t_waive_review, p_waived)`<br>`(p_waived, t_join_waived)`<br>`(t_join_waived, p_decision)`<br>**Add 1 arc:**<br>`(t_waive_review, p_review_done)`<br>**Remove 1 place:** `p_waived`<br>**Remove 1 transition:** `t_join_waived` | **$6$**<br>*(4 arc edits, 1 place removed, 1 transition removed)* | Retains mandatory analysis on both paths; produces an isomorphic visible trace language to R1. | Both `t_standard_review` and `t_waive_review` deposit their output token directly into `p_review_done`, synchronizing via the single `t_join_normal` transition. | Post-review, pre-join markings no longer distinguish whether the review was standard or waived via place residency (`p_waived` is gone); state inspection relies on the firing history rather than the current marking. |
| **R3: Early Policy Branching (Policy Change: Waiver Bypasses Analysis)** | **Remove 2 arcs:**<br>`(p_review, t_waive_review)`<br>`(t_waive_review, p_waived)`<br>**Add 2 arcs:**<br>`(p_ready, t_waive_review)`<br>`(t_waive_review, p_decision)`<br>**Remove 1 place:** `p_waived`<br>**Remove 1 transition:** `t_join_waived` | **$6$**<br>*(4 arc edits, 1 place removed, 1 transition removed)* | Restores soundness and proper completion (`fm` is cleanly reached on all paths). | **Explicit Policy Change:** Choosing `t_waive_review` at `p_ready` skips `t_split` and `t_analyze` entirely, routing directly to `p_decision`. | **Business Compliance Risk:** Analysis is no longer mandatory when a review is waived. Acceptable *only* if business stakeholders explicitly revise the specification so a waiver cancels the entire analysis-and-review phase. |

### Justification of Minimality
Under our edit-cost model $C$:
- **R1 is the unique global minimum ($C = 1$):** Any valid repair must alter the relation between the analysis branch and the waiver branch, requiring at least one graph edit ($C \ge 1$). Because adding the single synchronizing arc `(p_analysis_done, t_join_waived)` achieves soundness and satisfies all business rules, no non-empty repair can have a lower cost than $1$.
- **Why R2 and R3 tie ($C = 6$):** Both R2 and R3 eliminate the redundant waiver-join subnet (`p_waived`, `t_join_waived`, and their 3 incident arcs, costing $5$ edits) and add $1$ new arc to reconnect `t_waive_review` (in R2, costing $1$) or move `t_waive_review` upstream by removing `(p_review, t_waive_review)` and adding `(p_ready, t_waive_review)` and `(t_waive_review, p_decision)` (in R3, costing $6$ edits if `p_waived` and `t_join_waived` are also removed, or $C=2$ if we merely added `(p_analysis, t_join_waived)` and `(p_analysis_done, t_join_waived)`—which wouldn't work without non-deterministic preemption). If in R3 we instead kept `p_waived` and `t_join_waived` and only moved `t_waive_review`'s input from `p_review` to `p_ready`, its cost would be $C = 2$ (1 arc removed, 1 arc added), making it the minimal policy-changing repair, though leaving an unnecessary silent transition `t_join_waived` in series.

# 5. Corrected PM4Py Code

Below is the standalone implementation of **Repair R1** (adding the synchronizing arc from `p_analysis_done` to `t_join_waived`, cost $C=1$):

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in {
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
}:
    repaired_net.places.add(p)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in {
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
}:
    repaired_net.transitions.add(t)

petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

# REPAIRED WAIVER SYNCHRONIZATION (Repair R1):
# Require both p_analysis_done and p_waived before t_join_waived can fire.
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

def format_marking(marking: Marking) -> str:
    return "{" + ", ".join(
        f"{p.name}: {c}" for p, c in sorted(marking.items(), key=lambda x: x[0].name) if c > 0
    ) + "}"

def fire_by_name(petri_net, marking: Marking, t_name: str) -> Marking:
    """Checks enabledness explicitly and fires the named transition to produce a new Marking."""
    enabled = pm4py.get_enabled_transitions(petri_net, marking)
    target_t = next((t for t in enabled if t.name == t_name), None)
    if target_t is None:
        enabled_names = sorted(t.name for t in enabled)
        raise ValueError(
            f"Transition '{t_name}' is NOT enabled at marking {format_marking(marking)}. "
            f"Enabled transitions: {enabled_names}"
        )
    new_marking = Marking(marking)
    for in_arc in target_t.in_arcs:
        new_marking[in_arc.source] -= in_arc.weight
        if new_marking[in_arc.source] == 0:
            del new_marking[in_arc.source]
    for out_arc in target_t.out_arcs:
        new_marking[out_arc.target] = new_marking.get(out_arc.target, 0) + out_arc.weight
    return new_marking

def replay_sequence(title: str, petri_net, initial_marking: Marking, final_marking: Marking, seq: list[str]):
    print(f"\n=== {title} ===")
    m = Marking(initial_marking)
    print(f"Step 0 [Initial]: marking={format_marking(m)}, enabled={sorted(t.name for t in pm4py.get_enabled_transitions(petri_net, m))}")
    for idx, t_name in enumerate(seq, start=1):
        try:
            m = fire_by_name(petri_net, m, t_name)
            enabled_now = sorted(t.name for t in pm4py.get_enabled_transitions(petri_net, m))
            print(f"Step {idx} [Fired {t_name}]: marking={format_marking(m)}, enabled={enabled_now}, is_exact_fm={m == final_marking}")
        except ValueError as err:
            print(f"Step {idx} [Blocked {t_name}]: {err}")
            break

# 1. Structural and Soundness Diagnostics on Original Net
print("--- ORIGINAL NET DIAGNOSTICS ---")

orig_sound = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
orig_rg = pm4py.convert_to_reachability_graph(net, im, fm)
print(f"Original is_workflow_net: {orig_is_wf}")
print(f"Original check_soundness: {orig_sound}")
print(f"Original reachability graph states: {len(orig_rg.states)}, transitions: {len(orig_rg.transitions)}")

# 2. Structural and Soundness Diagnostics on Repaired Net
print("\n--- REPAIRED NET DIAGNOSTICS ---")
rep_is_wf = pm4py.check_is_workflow_net(repaired_net)
rep_sound = pm4py.check_soundness(repaired_net, repaired_im, repaired_fm, print_diagnostics=True)
rep_rg = pm4py.convert_to_reachability_graph(repaired_net, repaired_im, repaired_fm)
print(f"Repaired is_workflow_net: {rep_is_wf}")
print(f"Repaired check_soundness: {rep_sound}")
print(f"Repaired reachability graph states: {len(rep_rg.states)}, transitions: {len(rep_rg.transitions)}")

# 3. Counterexample Replay on Both Nets
counterexample_seq = ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize", "t_analyze"]
replay_sequence("Original Net Counterexample", net, im, fm, counterexample_seq)

replay_sequence("Repaired Net Valid Waiver Sequence", repaired_net, repaired_im, repaired_fm, valid_waiver_seq)
```

### Expected Qualitative Difference in Diagnostics
- **`pm4py.check_is_workflow_net`:** Returns `True` for **both** `net` and `repaired_net` because both satisfy the purely graph-theoretical workflow net criteria (unique source, unique sink, all nodes on a source-to-sink path).
- **`pm4py.check_soundness`:** Returns `False` (or indicates unsoundness in the boolean element of its return structure) for the **original `net`**, flagging improper completion / dead transitions (`t_join_normal` cannot fire when `t_waive_review` is chosen, and markings with `sink: 1` retain residual tokens in `p_analysis` or `p_analysis_done`). For **`repaired_net`**, `check_soundness` returns `True` because every reachable marking can reach `repaired_fm = [sink: 1]`, no extra tokens remain when `sink` is marked, and every transition is live.
- **Reachability Graph (`convert_to_reachability_graph`) and Counterexample Replay:** In the original net, the reachability graph contains states where `sink` is marked alongside `p_analysis` or `p_analysis_done`, and replaying `counterexample_seq` succeeds through `t_authorize` before `t_analyze`. Specifically, by direct enumeration from `im`, the original net has **12 reachable markings** (including improper states `[p_analysis:1, p_decision:1]`, `[p_analysis:1, sink:1]`, `[p_analysis_done:1, p_decision:1]`, and `[p_analysis_done:1, sink:1]`), whereas `repaired_net` prunes those 4 improper states, leaving exactly **8 reachable markings** and a single terminal state `[sink: 1]`. In `repaired_net`, `fire_by_name` raises a `ValueError` at Step 4 (`t_join_waived`) because only `t_analyze` is enabled at `[p_analysis: 1, p_waived: 1]`.

# 7. Repair Trade-Offs and Residual Risks

1. **Distinguishability of Waiver vs. Standard Review:**
   - Both **R1** and **R2** keep the visible transitions `t_standard_review` ("Perform Standard Review") and `t_waive_review` ("Record Review Waiver") distinct in event logs.
   - However, **R1** also preserves **marking-level distinguishability** after the review step completes (`p_waived` vs. `p_review_done`), which is valuable if runtime monitoring, dashboards, or downstream guards inspect current token placement prior to synchronization. **R2** merges both outcomes into `p_review_done`, losing marking-level distinction while awaiting analysis completion.
2. **Silent Transitions and Structural Confusion:**
   - **R1** uses two silent synchronization transitions (`t_join_normal` and `t_join_waived`) that share `p_analysis_done` as an input place. Because `p_analysis_done` has two output transitions (`p_analysis_done• = {t_join_normal, t_join_waived}`), each having multiple inputs, the net is structurally **non-free-choice**. Although it is behaviorally deterministic and conflict-free (since `p_review_done` and `p_waived` can never hold tokens simultaneously in a 1-safe execution), some verification or process-discovery tools prefer free-choice nets like **R2** (where a single silent `t_join_normal` has a unique preset `{p_analysis_done, p_review_done}`). Neither R1 nor R2 introduces duplicate visible labels.
3. **Why Soundness Alone Does Not Prove Business Alignment:**
   - Classical soundness is a purely internal behavioral property (option to complete, proper completion, no dead transitions). **Repair R3** (where `t_waive_review` branches directly from `p_ready` to `p_decision`) is 100% sound workflow net, yet it completely violates the business rule that *"The analysis is always mandatory."* Verification must therefore combine soundness checks with temporal/trace specifications.
4. **Regression Test Suite (Positive and Negative Traces):**
   - *Positive traces (must be accepted and reach exact `fm`):*
     - $T^{+}_1 = \langle\text{Register Case}, \text{Perform Analysis}, \text{Perform Standard Review}, \text{Authorize Case}\rangle$
     - $T^{+}_2 = \langle\text{Register Case}, \text{Perform Standard Review}, \text{Perform Analysis}, \text{Authorize Case}\rangle$
     - $T^{+}_3 = \langle\text{Register Case}, \text{Perform Analysis}, \text{Record Review Waiver}, \text{Authorize Case}\rangle$
     - $T^{+}_4 = \langle\text{Register Case}, \text{Record Review Waiver}, \text{Perform Analysis}, \text{Authorize Case}\rangle$
   - *Negative traces (must be rejected / blocked before completion):*
     - $T^{-}_1 = \langle\text{Register Case}, \text{Record Review Waiver}, \text{Authorize Case}\rangle$ *(missing analysis)*
     - $T^{-}_2 = \langle\text{Register Case}, \text{Record Review Waiver}, \text{Authorize Case}, \text{Perform Analysis}\rangle$ *(premature authorization)*
     - $T^{-}_3 = \langle\text{Register Case}, \text{Perform Standard Review}, \text{Record Review Waiver}, \text{Perform Analysis}, \text{Authorize Case}\rangle$ *(both review options executed)*
5. **Detecting Accidental Bypass of Mandatory Analysis:**
   - **Model checking on the Reachability Graph:** Verify the LTL/CTL invariant $\mathbf{G}(\text{enable}(\text{t\_authorize}) \implies \text{executed}(\text{t\_analyze}))$, or check over the reachability graph that no transition labeled `"Authorize Case"` lies on a path from `im` that omits `"Perform Analysis"`.
   - **Place-invariant / S-invariant check:** Confirm that `{source, p_ready, p_analysis, p_analysis_done, p_decision, sink}` forms a P-invariant with weight 1, proving that a token in `p_decision` or `sink` strictly requires consuming the token from the analysis branch.

# 8. Final Recommendation

**Deploy Repair R1 (Two-Input Waiver Synchronization)** as the primary production fix, and retain **Repair R2 (Shared Review-Outcome Place)** as the architectural fallback.

**Rationale:**
1. **Minimal Risk and Minimal Diff (R1):** R1 requires adding a single arc `(p_analysis_done, t_join_waived)` ($C = 1$). It preserves every existing place, transition name, and identifier in the codebase, ensuring zero breakage for external process monitors, audit queries, or UI bindings that inspect `p_waived` to determine whether a case waiting for analysis has already had its review waived. It enforces the mandatory analysis rule and achieves full workflow soundness.
2. **When to use the Fallback (R2):** If downstream workflow engines or static analyzers require the net to be **structurally free-choice** (for example, to apply free-choice-specific reduction rules or avoid shared-input AND-joins), deploy **R2**. R2 merges the post-review state into a single place (`p_review_done`) and removes `p_waived` and `t_join_waived`, producing a smaller, free-choice workflow net with the exact same visible language as R1.
3. **Reject R3:** Repair R3 must not be deployed unless business compliance formally changes the policy to exempt waived cases from analysis.
