# 1. Executive Verdict  
• The net is a syntactically correct workflow net (unique source/sink and every node is on a source-to-sink path).  
• It must **not** be expected to be sound.  
• Principal defect: the “waiver” route (`t_waive_review  p_waived  t_join_waived`) reaches the decision place without synchronising with the analysis result.  
• Business consequence: a case can be authorised while the mandatory analysis is still pending, leaving an orphan token and allowing an un-checked case to be closed.

# 2. Structural Diagnosis  

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|-------------------|---------------|--------------------------|-------------------|
| `t_split` (AND split) | Start analysis and one review in parallel | Correctly creates two tokens | none |
| Analysis branch (`t_analyze`) | Always mandatory | Token can remain unconsumed if waiver path chosen | Orphan token |
| Standard review branch (`t_standard_review`) | Optional alternative to waiver | Works as intended | none |
| Waiver branch (`t_waive_review`) | Records formal waiver | Bypasses analysis synchronisation | Early authorisation |
| `t_join_normal` (AND join) | Waits for analysis + standard review | Correct | none |
| `t_join_waived` (silent) | Should wait for analysis + waiver | Waits only for waiver | Violation of rule |
| Initial / final markings | 1 token in `source` / `sink` | Final token can be reached while others remain | Lack of soundness |
| Source-to-sink paths | Every node is on at least one path | True | — |

# 3. Marking-Based Counterexample  

Firing sequence:  
`t_register, t_split, t_waive_review, t_join_waived, t_authorize`

Marking table  

| # | Fired transition | Non-zero marking afterwards | Enabled transitions | Observation |
|---|------------------|-----------------------------|---------------------|-------------|
| 0 | – | {source:1} | `t_register` | initial |
| 1 | t_register | {p_ready:1} | `t_split` | — |
| 2 | t_split | {p_analysis:1, p_review:1} | `t_analyze`, `t_standard_review`, `t_waive_review` | two parallel tokens |
| 3 | t_waive_review | {p_analysis:1, p_waived:1} | `t_analyze`, `t_join_waived` | waiver chosen |
| 4 | t_join_waived | {p_analysis:1, p_decision:1} | `t_analyze`, `t_authorize` | analysis still pending |
| 5 | t_authorize | {p_analysis:1, sink:1} | `t_analyze` | sink reached but extra token |

The net fires `t_authorize` before `t_analyze`; final marking `fm` is **not** reached because the token in `p_analysis` can no longer be consumed (no transition takes `p_analysis` after the case is authorised). Soundness is violated.

# 4. Minimal-Repair Alternatives  

| Repair | Exact edits (• add,  delete) | Edit cost* | Preserved intent | Changed behaviour | New risk |
|--------|------------------------------|------------|------------------|-------------------|----------|
| A (re-use common join) |  p_waivedt_join_waived,  t_join_waivedp_decision,  t_join_waived,  t_waive_reviewp_waived, • t_waive_reviewp_review_done,  p_waived | 6 | Analysis stays mandatory; single join waits for analysis + (review  waiver) | Waiver and standard review tokens are merged in `p_review_done` | Loss of distinct audit place for waivers |
| B (add analysis token to waiver join) | • p_analysis_donet_join_waived | 1 | Analysis mandatory on both paths, waiver and standard remain separate | Two alternative AND-joins remain | Token in `p_analysis_done` is consumed by whichever join fires first; no hazard |
| C (policy change: analysis optional with waiver) | • p_analysist_join_waived,  p_analysis_donet_join_normal | 2 | Explicitly allows “waiver  skip analysis” | Business policy changed | Lower assurance |

\*Edit cost = number of arcs / transitions / places added or removed.  

Minimality: Repair B adds only one arc, strictly dominating any alternative that preserves the rule. Repair A needs six edits because an entire subnet is deleted; it is minimal among solutions that remove the separate waiver join. If only the number of edits is considered, B is the unique minimum.

# 5. Corrected PM4Py Code  (selected Repair B)

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

# Places
source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in [source, p_ready, p_analysis, p_review, p_analysis_done,
          p_review_done, p_waived, p_decision, sink]:
    repaired_net.places.add(p)

# Transitions
register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in [register, split, analyze, standard_review,
          waive_review, join_normal, join_waived, authorize]:
    repaired_net.transitions.add(t)

# Arcs (identical to original except for one extra arc *)
petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
# *extra arc ensures analysis is also completed before waiver join fires
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking(); repaired_im[source] = 1
repaired_fm = Marking(); repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code  

```python
from pm4py.objects.petri_net import utils as pu
from pm4py.objects.conversion.wf_net import converter as wf_conv

def fire(net, marking, transition_name):
    trans = next(t for t in net.transitions if t.name == transition_name)
    if not pu.is_transition_enabled(transition=trans, marking=marking):
        raise RuntimeError(f"{transition_name} not enabled")
    pu.execute_transition(net, trans, marking)

for title, n, i, f in [("ORIGINAL", net, im, fm),
                       ("REPAIRED", repaired_net, repaired_im, repaired_fm)]:
    print(f"\n=== {title} ===")
    print("WF-net:", pm4py.check_is_workflow_net(n))
    pm4py.check_soundness(n, i, f, print_diagnostics=True)
    print("Enabled at start:", [t.name for t in pm4py.get_enabled_transitions(n, i)])
    rg = pm4py.convert_to_reachability_graph(n, i, f)
    print("States in RG:", len(rg.states))

# counterexample replay on original net
m = im.copy()
for t in ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize"]:
    fire(net, m, t)
    print(t, "", {p.name: c for p, c in m.items()})
```

Expected qualitative difference  
• `pm4py.check_soundness` flags the original net as unsound (token left behind) and the repaired net as sound.  
• Reachability graph of the repaired net has fewer dead markings because every successful path consumes the analysis token.  
• The helper prints the exact counterexample marking that violates soundness in the original net; the same sequence is impossible in the repaired net because `t_join_waived` is disabled until `t_analyze` fires.

# 7. Repair Trade-Offs and Residual Risks  

• Both review outcomes remain distinguishable in Repair B – the audit log can still tell whether a standard review or a waiver occurred.  

• The added silent arc does not duplicate behaviour: only one of `t_join_normal` or `t_join_waived` can fire because the review place supplies at most one token.  

• Soundness proves that no token is left behind but does not guarantee that “analysis happens before authorisation”; it only guarantees “analysis happens some-time”. Conformance testing should therefore include temporal ordering rules if that matters.  

Regression tests  
Positive traces:  
1. Register  split  analyse  standard review  authorise  
2. Register  split  analyse  waiver  authorise  

Negative traces:  
1. Register  split  waiver  authorise (should be impossible)  
2. Register  split  analyse  authorise without any review  

Detection of analysis bypass: add a business rule monitor that raises an alert whenever `t_authorize` occurs without a preceding `t_analyze` in the same case. This can be implemented as an LTL checker or a streaming SQL over the event log.

# 8. Final Recommendation  

Deploy **Repair B** because it costs only one edit, keeps the waiver data separate for audit purposes, and exactly enforces the stated rule that analysis is always required. If unforeseen compliance rules ever require a single join, fall back to **Repair A**, which is still sound but sacrifices the dedicated waiver place. Both repairs can be implemented immediately; however, a post-deployment conformance monitor should still be activated to detect future modelling errors or manual overrides that could bypass the analysis step.
