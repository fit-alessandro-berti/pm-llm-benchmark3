## 3. Causal-abductive explanation

```text
UI_release            -> recorded_labels              # Classify displayed/logged as Risk Screen (05-31)
gateway_change        -> technical_events_logged      # Queue Routed emitted conditionally (06-03)
ETL_change            -> recorded_order               # Decision/Notify use ingestion time (06-15)
source_seq            -> recorded_order               # available, unused by initial job
logging_patch         -> recorded_override_labels     # Manual Override logging changed (08-12)
policy_change         -> true_process                 # sign-off for claims > EUR 50,000 (08-01)
policy_change  -x->   normative_model                 # not propagated to model
high_value_share      -> true_process                 # hidden: drives sign-off requirement
high_value_share      -> sign_off_events              # hidden: moderates sign-off recording
supervisor_memo       -> reviewer_behavior            # 07-10 reminder
reviewer_behavior     -> true_process
reviewer_behavior     -> manual_override_events
true_process          -> recorded_events
technical_events_logged -> recorded_events
extraction_completeness -> recorded_events            # hidden: missing or duplicated events
recorded_labels       -> alignment_moves
recorded_order        -> alignment_moves
recorded_events       -> alignment_moves
normative_model       -> alignment_moves
alignment_moves       -> measured_fitness
true_process          -> business_outcomes            # weak, lagged
true_process          -> compliance_incidents_true
incident_detection    -> confirmed_incidents          # hidden: incomplete
compliance_incidents_true -> confirmed_incidents
```

Several mechanisms stack. A lexical UI change turns every June case into an unknown label, which alone pushes fitness down sharply. A conditional technical event then adds unmodelled moves to most Risk Screen traces. An ingestion-time ETL change can reverse Decision and Notify, adding a further class of deviations that look like process failure. Only after these measurement effects are removed do the policy-induced sign-off deviations appear, because the normative model was never updated for the 08-01 requirement. The remaining Manual Override and enhanced-without-check traces are small and specific, and they are where genuine behavioral questions sit.

Unchanged outcomes neither prove data error nor rule out noncompliance. Approval, appeal, and incident figures are aggregates that are insensitive to a minority of high-value bypasses, and appeals lag by up to 30 days. Detection is admittedly incomplete, so “no confirmed incidents” reflects detection capacity as much as behavior. Conversely, data artifacts can coexist with real deviations without changing averages. Fitness is itself a weak verdict: a more permissive model can raise fitness, and a flower control can reach near-perfect fitness while meaning nothing. Outcomes test materiality; alignments test conformance to a model; neither alone establishes compliance.

## 6. PM4Py reproduction and model-comparison code

```python
"""
Reproduction sketch: normative vs. normalized conformance for the claims process.

Assumptions and caveats
- Written against the PM4Py 2.x API. Verify signatures of pm4py.parse_event_log_string,
  pm4py.fitness_alignments and the alignment output keys in your installed version.
- The supplied tables are variant aggregates, not the original timestamped log.
  Case timestamps below are SYNTHETIC; recorded order is preserved by minute offsets.
- Source sequence numbers are NOT in the aggregates, so stage S3 (source ordering)
  is a documented no-op here. It only runs on real data carrying a sequence column.
- Silent transitions in the candidate tree use the token 'tau' (PM4Py process tree notation).
"""
import io
from collections import Counter

import pandas as pd
import pm4py

# ----------------------------------------------------------------- models
# Normative tree as supplied.
NORMATIVE_TREE = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "'Decision', 'Notify' )"
)

# Candidate: OPTIONAL Supervisor Sign-off between the review block and Decision.
# Control-flow only: the EUR 50,000 condition is NOT encoded and the model
# permits sign-off even for low-value claims and permits its omission for high-value ones.
CANDIDATE_TREE = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "X ( 'Supervisor Sign-off', tau ), "
    "'Decision', 'Notify' )"
)

ALL_ACTIVITIES = [
    "Receive", "Classify", "Risk Screen", "Queue Routed", "Standard Review",
    "Request Info", "Enhanced Review", "Compliance Check", "Manual Override",
    "Supervisor Sign-off", "Decision", "Notify",
]
# Overpermissive control: any sequence over observed activities.
FLOWER_TREE = "* ( tau, X ( " + ", ".join(f"'{a}'" for a in ALL_ACTIVITIES) + " ) )"

# ----------------------------------------------------------- aggregates
APR_MAY = [
    ("Receive,Classify,Standard Review,Decision,Notify", 380),
    ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
    ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40),
]
JUN_JUL = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
    ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
    ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
]
AUG_SEP = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),
]

# Normalization dictionaries: explicit and reviewable by process owners.
LABEL_MAP = {"Risk Screen": "Classify"}
TECHNICAL = {"Queue Routed"}  # Gateway event; NOT a business step.
# Manual Override is a real user action and is deliberately NOT removed.


# ------------------------------------------------------------- utilities
def expand(variants, period, start):
    """Expand (trace, count) pairs into (case, activity, timestamp, seq) rows.
    Minute offsets preserve the recorded order. seq is None: not in aggregates."""
    rows, k = [], 0
    for trace, n in variants:
        acts = [a.strip() for a in trace.split(",")]
        for _ in range(n):
            k += 1
            t0 = start + pd.Timedelta(hours=k)
            for pos, act in enumerate(acts):
                ts = (t0 + pd.Timedelta(minutes=pos)).strftime("%Y-%m-%dT%H:%M:%S")
                rows.append((f"{period}-{k:04d}", act, ts, None))
    return rows


def normalize(rows, label_map=None, drop_technical=False, use_source_seq=False):
    """Transparent pipeline: label mapping -> optional technical-event removal
    -> optional source-sequence ordering."""
    label_map = label_map or {}
    out = []
    for cid, act, ts, seq in rows:
        act = label_map.get(act, act)
        if drop_technical and act in TECHNICAL:
            continue
        out.append((cid, act, ts, seq))
    if use_source_seq:
        if out and all(r[3] is not None for r in out):
            out.sort(key=lambda r: (r[0], r[3]))  # stable sort within case
        else:
            print("  [warn] source sequence unavailable; ordering left unchanged")
    return out


def to_pm4py_log(rows):
    """Serialize rows to CSV text and parse with PM4Py."""
    buf = io.StringIO()
    buf.write("case:concept:name,concept:name,time:timestamp\n")
    for cid, act, ts, _ in rows:
        buf.write(f"{cid},{act},{ts}\n")
    obj = pm4py.parse_event_log_string(buf.getvalue(), sep=",")
    if isinstance(obj, pd.DataFrame):  # some versions return a DataFrame
        df = pm4py.format_dataframe(
            obj,
            case_id="case:concept:name",
            activity_key="concept:name",
            timestamp_key="time:timestamp",
        )
        obj = pm4py.convert_to_event_log(df)
    return obj


def pick(d, *keys):
    """Read a metric under alternative key names used across PM4Py versions."""
    for k in keys:
        if isinstance(d, dict) and k in d:
            return d[k]
    return None


def diagnose(label, rows, net, im, fm):
    log = to_pm4py_log(rows)
    dfg, starts, ends = pm4py.discover_dfg(log)
    aligns = pm4py.conformance_alignments(log, net, im, fm)
    fit = pm4py.fitness_alignments(log, net, im, fm)
    prec = pm4py.precision_alignments(log, net, im, fm)

    costs = [a["cost"] for a in aligns]
    fitting = sum(1 for c in costs if c == 0)

    log_only, model_only = Counter(), Counter()
    for a in aligns:
        for log_step, model_step in a["alignment"]:
            if model_step == ">>" and log_step != ">>":
                log_only[log_step] += 1          # move on log
            elif log_step == ">>" and model_step not in (">>", "tau", None):
                model_only[model_step] += 1      # move on model

    print(
        f"[{label}] traces={len(aligns)} fitting={100 * fitting / len(aligns):.1f}% "
        f"mean_cost={sum(costs) / len(costs):.3f} "
        f"log_fitness={pick(fit, 'log_fitness', 'averageFitness')} "
        f"precision={prec:.3f}"
    )
    print("  top log-only moves:  ", log_only.most_common(4))
    print("  top model-only moves:", model_only.most_common(4))
    print("  top DFG arcs:        ", sorted(dfg.items(), key=lambda kv: -kv[1])[:5])
    return {
        "fitting_pct": 100 * fitting / len(aligns),
        "mean_cost": sum(costs) / len(costs),
        "precision": prec,
    }


# ------------------------------------------------------------------ main
def main():
    net_n, im_n, fm_n = pm4py.convert_to_petri_net(pm4py.parse_process_tree(NORMATIVE_TREE))
    net_c, im_c, fm_c = pm4py.convert_to_petri_net(pm4py.parse_process_tree(CANDIDATE_TREE))
    net_f, im_f, fm_f = pm4py.convert_to_petri_net(pm4py.parse_process_tree(FLOWER_TREE))

    rows_am = expand(APR_MAY, "AM", pd.Timestamp("2026-04-01"))
    rows_jj = expand(JUN_JUL, "JJ", pd.Timestamp("2026-06-01"))
    rows_as = expand(AUG_SEP, "AS", pd.Timestamp("2026-08-01"))

    print("== Baseline Apr-May against normative model ==")
    diagnose("AM raw", rows_am, net_n, im_n, fm_n)

    print("\n== Jun-Jul: staged normalization against normative model ==")
    stages = [
        ("JJ S0 raw", normalize(rows_jj)),
        ("JJ S1 label map", normalize(rows_jj, LABEL_MAP)),
        ("JJ S2 label + drop Queue Routed",
         normalize(rows_jj, LABEL_MAP, drop_technical=True)),
        ("JJ S3 + source ordering",
         normalize(rows_jj, LABEL_MAP, drop_technical=True, use_source_seq=True)),
    ]
    stage_results = {}
    for name, rows in stages:
        stage_results[name] = diagnose(name, rows, net_n, im_n, fm_n)

    print("\n== Aug-Sep: normalized log, normative vs candidate vs flower control ==")
    as_norm = normalize(rows_as, LABEL_MAP, drop_technical=True, use_source_seq=True)
    res_n = diagnose("AS normative", as_norm, net_n, im_n, fm_n)
    res_c = diagnose("AS candidate (optional sign-off)", as_norm, net_c, im_c, fm_c)
    res_f = diagnose("AS flower (overpermissive control)", as_norm, net_f, im_f, fm_f)

    print("\n== Model comparison summary (Aug-Sep) ==")
    print(f"  normative : fitting={res_n['fitting_pct']:.1f}%  precision={res_n['precision']:.3f}")
    print(f"  candidate : fitting={res_c['fitting_pct']:.1f}%  precision={res_c['precision']:.3f}")
    print(f"  flower    : fitting={res_f['fitting_pct']:.1f}%  precision={res_f['precision']:.3f}")
    if res_c["precision"] <= res_f["precision"] + 0.05:
        print("  -> Candidate precision is not clearly above the flower control: "
```

**Primary explanation.** The measured Jun-Jul collapse is mainly a measurement and semantics artifact, not a demonstrated change in behavior. ## 8. Model-governance recommendation

1. **Model versioning:** Every policy, UI, or gateway change that affects activities or sequencing creates a versioned process-model change record with an effective date. Conformance jobs bind a model version to each log window and refuse to run if a policy change is effective without a corresponding model version.
2. **Event-semantic contract:** Activity labels form a controlled vocabulary mapped to stable activity IDs, each with a named business-function owner. Any UI rename requires contract approval and a mapping entry before release; release-note claims of unchanged function are not accepted as evidence.
3. **Technical-event policy:** Gateway and system events carry an explicit class (business or technical). Technical events are excluded from conformance by default and stored in a separate stream. Conditional emission of any event must be documented and tested, and any event that may encode routing must be reviewed before it is treated as technical.
4. **Timestamp provenance:** Store source event time, ingestion time, and source sequence for every event. Conformance orders events within each case by source sequence. Any ETL change to timestamp semantics requires a dated change record and a before/after reconciliation test on reversal rates and event counts.
5. **Data-aware constraints:** Conditions tied to case attributes (such as the EUR 50,000 sign-off rule) are specified as data-aware rules and checked separately, reported stratified by attribute value. Control-flow fitness is never reported alone, and every candidate model is reported with precision and a flower-model control.
6. **Post-release validation:** Within two weeks of any UI, gateway, ETL, or policy release, run a canary check covering event completeness, activity-label distribution shift, events-per-case reconciliation, missing-resource rates, and segment-level conformance. Pre-define the audit sample size and the alert thresholds before release.
