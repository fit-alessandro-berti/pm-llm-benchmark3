## 2. Ranked hypothesis table

**Cause of the drop versus operational concern.** The June fitness cliff is explained by hypotheses 1–3 stacked on a frozen tree. Hypothesis 4 is the main **later** measurement problem and a real governance failure. Hypothesis 5 is locally true (sign-off is real work) but is not what broke June conformance. Hypothesis 6 is not supported as the cause of the collapse and is not yet confirmed as a compliance incident; it remains the residual that must be audited, not inferred from moves on log.

## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels
UI_release -> Risk_Screen_for_Classify
gateway_release -> Queue_Routed_emission
Queue_Routed_emission -> recorded_labels
ETL_change -> recorded_order
ETL_change -> warehouse_time_on_Decision_Notify
warehouse_time_on_Decision_Notify -> Decision_Notify_inversions

reviewer_behavior -> true_process
reviewer_behavior -> Manual_Override
true_process -> business_outcomes
true_process -> recorded_labels
extraction_projection -> recorded_labels
extraction_projection -> recorded_order
missing_event_probability -> recorded_labels
recorded_labels -> alignment_moves
recorded_order -> alignment_moves
normative_model -> alignment_moves
alignment_moves -> measured_fitness
incomplete_incident_detection -> observed_compliance_incidents
business_outcomes -/-> recorded_labels
business_outcomes -/-> measured_fitness
```

The June fitness collapse is the product of three recording-layer shocks hitting a frozen control-flow tree, with a fourth policy-layer mismatch arriving in August. After UI 4.2 every case emits `Risk Screen` where the tree still expects `Classify`, so alignments book a log move and a model move on an unchanged work step. The gateway then inserts `Queue Routed` after most risk screens. That event is not a claim-handling activity, yet it is treated as one, adding another log move and inflating events per case without lengthening median cycle time. Separately, warehouse-ingestion clocks on `Decision` and `Notify` invert those activities in a visible subset of traces. Alignments then “see” a control-flow break that source screenshots often refute. The alignment staircase (32% → 58% → 81% → 89%) is exactly the additive signature of those three mechanisms.

August is different. `Supervisor Sign-off` is new work required by policy, so the true process did change, but the tree did not. Optional sign-off restores much residual fitness, which diagnoses model lag—and also shows how an overpermissive tree can buy fitness by sacrificing the EUR 50,000 condition.

Flat approval, appeal, and cycle-time figures are what you should see if customers still follow the same path and only labels, technical events, and clocks changed. They do not prove the residual enhanced-without-check traces are harmless extraction bugs: detection is avowedly incomplete, resource completeness worsened, and no audit has separated omitted events from bypasses. Unchanged outcomes therefore neither certify the log nor clear the workforce.

## 6. PM4Py reproduction and model-comparison code

```python
"""
Reproducible PM4Py comparison on the published variant aggregates.

The supplied tables are variant frequencies, not the original timestamped
extract. Numbers will not match the warehouse job exactly. The script shows
the same qualitative staircase: raw collapse, label map, technical-event
removal, a Decision/Notify order repair standing in for source sequence,
and an over-permissive optional sign-off model for August-September.
"""

from __future__ import annotations

import pm4py
from pm4py.objects.log.obj import EventLog


NORMATIVE_TREE_STR = (
    "->('Receive', 'Classify', "
    "X(*('Standard Review', 'Request Info'), "
    "->('Enhanced Review', 'Compliance Check')), "
    "'Decision', 'Notify')"
)

CANDIDATE_TREE_STR = (
    "->('Receive', 'Classify', "
    "X(*('Standard Review', 'Request Info'), "
    "->('Enhanced Review', 'Compliance Check')), "
    "X('Supervisor Sign-off', tau), "
    "'Decision', 'Notify')"
)

APR_MAY = {
    "Receive,Classify,Standard Review,Decision,Notify": 380,
    "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,
    "Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify": 40,
}

JUN_JUL = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 270,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 145,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,
    "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
    "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 20,
}

AUG_SEP = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 210,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify": 150,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 90,
    "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify": 60,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 45,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 35,
}


def variants_to_log(variant_counts: dict[str, int]) -> EventLog:
    traces: list[str] = []
    for variant, count in variant_counts.items():
        traces.extend([variant] * int(count))
    return pm4py.parse_event_log_string(traces)


def log_to_df(log: EventLog):
    return pm4py.convert_to_dataframe(log)


def df_to_log(df) -> EventLog:
    return pm4py.convert_to_event_log(df)


def normalize_log(
    log: EventLog,
    map_risk_screen: bool = True,
    remove_queue_routed: bool = False,
    repair_decision_notify_order: bool = False,
) -> EventLog:
    """
    Transparent projection used in the investigation.

    Source sequence numbers are not present on variant strings. Swapping an
    adjacent Notify-before-Decision pair is a documented stand-in for
    'order by source sequence number', not a production ETL implementation.
    """
    df = log_to_df(log).copy()
    if map_risk_screen and "concept:name" in df.columns:
        df["concept:name"] = df["concept:name"].replace({"Risk Screen": "Classify"})

    if remove_queue_routed:
        df = df[df["concept:name"] != "Queue Routed"].copy()

    log_n = df_to_log(df)

    if not repair_decision_notify_order:
        return log_n

    repaired: list[str] = []
    for trace in log_n:
        names = [ev["concept:name"] for ev in trace]
        i = 0
        out: list[str] = []
        while i < len(names):
            if (
                i + 1 < len(names)
                and names[i] == "Notify"
                and names[i + 1] == "Decision"
            ):
                out.extend(["Decision", "Notify"])
                i += 2
            else:
                out.append(names[i])
                i += 1
        repaired.append(",".join(out))
    return pm4py.parse_event_log_string(repaired)


def top_dfg_edges(log: EventLog, n: int = 8) -> list[tuple[tuple[str, str], int]]:
    dfg, _starts, _ends = pm4py.discover_dfg(log)
    return sorted(dfg.items(), key=lambda kv: (-kv[1], kv[0][0], kv[0][1]))[:n]


def summarize_alignments(log: EventLog, net, im, fm, sample_limit: int = 12) -> dict:
    aligned = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    fitness = pm4py.fitness_alignments(log, net, im, fm)

    n = len(aligned)
    perfectly_fitting = 0
    costs = []
    log_moves: dict[str, int] = {}
    model_moves: dict[str, int] = {}

    for rec in aligned:
        cost = rec.get("cost", rec.get("fitness") is not None and 0)
        if isinstance(cost, (int, float)):
            costs.append(float(cost))
        fit_flag = rec.get("fitness", None)
        if fit_flag == 1.0 or rec.get("cost", 1) == 0:
            perfectly_fitting += 1

        alignment = rec.get("alignment") or []
        for pair in alignment:
            # PM4Py alignments are typically ((log_lbl, model_lbl), ...)
            if not isinstance(pair, tuple) or len(pair) < 2:
                continue
            a, b = pair[0], pair[1]
            if isinstance(a, tuple) and len(a) == 2:
                log_lbl, model_lbl = a
            else:
                log_lbl, model_lbl = a, b
            if log_lbl is not None and log_lbl != ">>" and (model_lbl is None or model_lbl == ">>"):
                log_moves[str(log_lbl)] = log_moves.get(str(log_lbl), 0) + 1
            if model_lbl is not None and model_lbl != ">>" and (log_lbl is None or log_lbl == ">>"):
                if str(model_lbl) != "tau":
                    model_moves[str(model_lbl)] = model_moves.get(str(model_lbl), 0) + 1

    mean_cost = sum(costs) / len(costs) if costs else float("nan")
    pct_fit = 100.0 * perfectly_fitting / n if n else float("nan")
    return {
        "n": n,
        "pct_perfectly_fitting": pct_fit,
        "mean_reported_cost": mean_cost,
        "fitness_dict": fitness,
        "top_log_moves": sorted(log_moves.items(), key=lambda kv: -kv[1])[:sample_limit],
        "top_model_moves": sorted(model_moves.items(), key=lambda kv: -kv[1])[:sample_limit],
    }


def print_dfg(title: str, log: EventLog) -> None:
    print(f"\n=== DFG {title} ===")
    for (a, b), c in top_dfg_edges(log):
        print(f"  {a} -> {b}: {c}")


def print_alignment_summary(title: str, summary: dict) -> None:
    print(f"\n=== ALIGNMENTS {title} ===")
    print(f"  traces: {summary['n']}")
    print(f"  perfectly fitting % (cost==0 proxy): {summary['pct_perfectly_fitting']:.2f}")
    print(f"  mean reported cost: {summary['mean_reported_cost']:.4f}")
    print(f"  fitness object: {summary['fitness_dict']}")
    print(f"  dominant moves on log: {summary['top_log_moves']}")
    print(f"  dominant visible moves on model: {summary['top_model_moves']}")


def main() -> None:
    normative_tree = pm4py.parse_process_tree(NORMATIVE_TREE_STR)
    net, im, fm = pm4py.convert_to_petri_net(normative_tree)

    candidate_tree = pm4py.parse_process_tree(CANDIDATE_TREE_STR)
    net_c, im_c, fm_c = pm4py.convert_to_petri_net(candidate_tree)

    log_am = variants_to_log(APR_MAY)
    log_jj_raw = variants_to_log(JUN_JUL)
    log_as_raw = variants_to_log(AUG_SEP)

    print_dfg("Apr-May raw", log_am)
    print_dfg("Jun-Jul raw", log_jj_raw)
    print_dfg("Aug-Sep raw", log_as_raw)

    print_alignment_summary(
        "Apr-May raw vs normative",
        summarize_alignments(log_am, net, im, fm),
    )
    print_alignment_summary(
        "Jun-Jul raw vs normative",
        summarize_alignments(log_jj_raw, net, im, fm),
    )

    jj_map = normalize_log(log_jj_raw, map_risk_screen=True, remove_queue_routed=False)
    jj_map_nq = normalize_log(log_jj_raw, map_risk_screen=True, remove_queue_routed=True)
    jj_full = normalize_log(
        log_jj_raw,
        map_risk_screen=True,
        remove_queue_routed=True,
        repair_decision_notify_order=True,
    )

    print_dfg("Jun-Jul label map only", jj_map)
    print_dfg("Jun-Jul label map + drop Queue Routed", jj_map_nq)
    print_dfg("Jun-Jul label map + drop Queue Routed + order repair", jj_full)

    print_alignment_summary(
        "Jun-Jul map Risk Screen->Classify vs normative",
        summarize_alignments(jj_map, net, im, fm),
```

## 7. Provisional conclusion

The measured conformance collapse is not a sudden revolt against the claims policy. It is what a frozen process tree does when the extract stops speaking its language. Between 31 May and 15 June the UI renamed `Classify` to `Risk Screen`, the gateway injected a technical `Queue Routed` event on most cases, and the ETL began dating `Decision` and `Notify` by warehouse ingestion. Those three changes are independently dated, independently visible in variants and DFGs, and independently removable. Fitness falls from 93% to 32% on the raw June–July log and then climbs 58% → 81% → 89% as the label is mapped, the technical event is projected out, and source order is restored. Events per case rise while approval, appeal, and cycle time barely move—the signature of extra recorded events, not a different factory. I treat this stacked recording explanation as the primary cause of the June cliff, with confidence about 88.

A real operational issue still sits underneath that repair and must be kept separate from the measurement failure. On 1 August the firm required `Supervisor Sign-off` above EUR 50,000 and did not version the tree. Sign-off then appears on both review paths and accounts for most of the second fitness drop (preprocessed 66%, optional-sign-off model 86%). That is model obsolescence plus a genuine policy-driven process increment, not a logging synonym. Confidence about 75 that this, not a new crime wave, explains the August residual **as a conformance number**.

Whether a compliance problem remains is a third question, and the honest answer is that it is unadjudicated. After every justified repair, enhanced reviews without a recorded check persist (25, then 30), `Manual Override` persists, resource completeness is worse, and compliance says incident detection is incomplete. Flat appeal rates do not close that file. They also do not open it. Confidence that these residuals are confirmed bypasses is only about 35; confidence that they are entirely missing events is also only about 35. They are a targeted audit list, not a verdict.

IT should immediately bind activity names to stable codes, classify `Queue Routed` as technical, and make source sequence the conformance clock for `Decision`/`Notify`. Process owners should publish a dated tree that includes sign-off and must not “fix” fitness with an unconstrained optional activity. Compliance should audit the missing-check and override cases against source screenshots and the high-value flag before alleging or dismissing misconduct. What must not be claimed yet: that employees became noncompliant because moves on log increased; that the process is healthy because KPIs are flat; or that the optional-sign-off tree is the new normative model.

## 8. Model-governance recommendation

1. **Model versioning.** Every policy or SOP change gets a dated process-tree (or data-aware) version, a deprecation date for the previous gold standard, and a dual-run window. Conformance jobs must name the model version they used; a tree that still expects `Classify` the day after a rename or that omits a 1 August sign-off obligation is a governance defect, not a finding about staff.

2. **Event-semantic contracts.** Activity names in the extract are an API. UI copy (`Risk Screen`) may change only if the stable event code remains `Classify` or a synonym table is shipped with the release. Mixed labels in one window are a rollout incident. Conformance may consume synonyms only through that table, never through ad-hoc analyst edits.

3. **Technical-event policy.** Platform events such as `Queue Routed` are declared technical at emission, stored, and excluded from normative control-flow by projection—not deleted from the raw lake. User-asserted actions such as `Manual Override` stay visible until provenance shows otherwise. “Not in the tree” is not the same as “technical.”

4. **Timestamp provenance.** Each event carries business time, source sequence, and ingestion time as separate fields. Conformance and DFGs default to source sequence (or business time), never warehouse-ingestion time, for order-sensitive pairs. Any job that falls back to ingestion time must fail or flag rather than silently invert `Decision` and `Notify`.

5. **Data-aware constraints.** Obligations that depend on case data (Supervisor Sign-off iff amount > EUR 50,000) are encoded as data conditions or as stratified models, not as a free optional activity. High-value flags travel with every alignment report. A more fitting, less precise optional tree is a diagnostic instrument, not a policy model.

6. **Post-release validation.** After every UI, gateway, ETL, or policy release, rerun a fixed pack: variant diff, frequency DFG diff, alignment-move census, fitness and precision against the **versioned** model, and a small screenshot provenance sample. A fitness drop that disappears under label map, technical projection, or clock repair is filed as a pipeline incident. A residual that survives those repairs is filed to process owners and compliance with the case list attached.
