# 1. Assumptions and notation

- **A1 – Event ordering under 5minute rounding.** Two events rounded to the same clock value are treated as **concurrent for WIP snapshots**, with WIP counted as the maximum over all admissible orderings. For waiting/sojourn estimates, an endbeforestart pair at equal rounded times is treated as a singlebin conflict and is **not** interpreted as negative waiting time; in that case waiting time is bounded to `[0, 5)` min.
- **A2 – Capacity.** I1, I2, C1, C2 are each singletask (no parallel work) **except during the C2 outage 10:55–11:10**, when C2 is unavailable.
- **A3 – "MISSING" start semantics.** The activity occurred, on the listed resource, and the listed end timestamp is trustworthy. The true start time lies in `[end  max_service, end]`, where `max_service` is an upper bound from the same resource’s observed services plus a slack to allow for outliers (here, sameresource max observed service plus 5 min; see A6).
- **A4 – "OPEN" activity semantics.** Active work that began before 14:00 but had not completed by 14:00. Service time is rightcensored at `14:00  start`; sojourns and queues that depend on the future are also censored.
- **A5 – Waiting time definition.** For a case `c` at station `S{S1,S2}`:
  - W(c) = s1_start  arrival_s1
  - W(c) = s2_start  s1_end
  - Service S(c) = s_end  s_start
  - Sojourn T(c) = s_end  s_start_arrival (T uses arrival_s1; T uses s1_end)
- **A6 – Imputation bounds for MISSING starts.** Central estimate = midpoint of `[end  max_service_observed_on_resource, end]`, but constrained so the imputed start is **not earlier than the case’s `arrival_s1` minus 2.5 min** (rounding tolerance) and **not earlier than the previous activity on the same resource ended** (singletask constraint). The full admissible interval is the intersection of these constraints.
- **A7 – Bypass impossible.** Every completed case passed through S1 and S2 in order; blank S1/S2 cells for nonOPEN rows mean waiting or inservice at 14:00.
- **A8 – Maintenance window.** C2 not available 10:55–11:10. Any S2 case whose s2_start falls in that window is infeasible on C2.
- **A9 – Little’s Law applicability.** Applied only in **steady-ish, fully observed, nomaintenance subintervals with no MISSING/OPEN in the interior** ( 08:00–10:30 and 12:00–13:30), as mean values, with L from the mean WIP,  from completed departures, and W from mean sojourn of completed cases in the interval. Used as a sanity check, not as a precise estimate.
- **A10 – External arrivals.** `arrival_s1` carries the same ±2.5 min rounding tolerance as operational timestamps.

# 2. Reconstruction method and formulas

Let `t` be in minutes since 08:00. Let `C` denote completed cases in the analysis window and `O` the OPEN cases.

- **Service (S1, S2).** S(c) = end_k  start_k. For OPEN, report `min = elapsed = 14:00  start`, `max = inf` (rightcensored).
- **Waiting.** W(c) = s1_start  arrival_s1. W(c) = s2_start  s1_end. For MISSING starts, define a feasible range via A6.
- **Sojourn.** T = s1_end  arrival_s1, T = s2_end  s1_end. Total sojourn for completed = T + T + interstation transfer (0 here, since s1_end rounds to a slot and s2_start  s1_end, often the next slot).
- **WIP at time t.** WIP_S1(t) = #{c : arrival_s1(c)  t < s1_end(c)}; WIP_S2(t) = #{c : s1_end(c)  t < s2_end(c)}. Under A1, at a shared rounded timestamp the case with the earlier *true* end is considered out before the later case is considered in; WIP reported as the max of the two orderings.
- **Throughput / rates.**  = arrivals per hour;  = 1/mean(S) on completed cases; departures = completed services in interval.
- **Busy time.**  S(c) over completed cases + elapsed for OPEN cases on that resource, capped at 14:00.
- **Utilization range.** Lower = busy / (2 × interval length) when 2 resources are available, **halved** to `2×(interval  15 min)` during 10:55–11:10 (C2 only). Upper assumes documented assistance (e.g., P11’s C2 leg during outage is reascribed to C1) is permitted when the original resource is busy/out; in this dataset it is **not** required because no S2 case is assigned to C2 inside the outage window.
- **Little.** Check `L   · W` per subperiod in A9compatible windows.
- **Lower/central/upper service imputation for MISSING.**
  - Lower (optimistic) start = latest feasible (closest to end)  shortest S.
  - Upper (pessimistic) start = earliest feasible (respecting singletask)  longest S.
  - Central = midpoint of feasible interval, rounded to 5 min.

**Imputation reasoning (selected):**
- **P05 (S2 start MISSING).** C1 was busy 09:05–09:45 (P03) and again 10:20–11:00 (P07); it freed at 10:15, P05’s s2_end is 10:15  impossible if start  10:15. So start  [10:00, 10:10] (after P03 ends 09:45 + singletask), and wait = start  09:25  [35, 45] in clock terms. The earliest s2_start consistent with C1 availability is 10:00; the latest is 10:10 (must end by 10:15). Hence wait  [35, 45], central 10:05 (40 min). Using A6’s stricter formula gives **[35, 45], central 40**.
- **P07 (S1 start MISSING).** I1 free after P03 ends 09:25; case arrived 08:45. Earliest start = 09:25, latest  10:00 (since end 10:00). So service  [60, 75]; central 67.5  **[60, 75], central 70**.
- **P11 (S2 start MISSING, C2 outage constraint).** C2 unavailable 10:55–11:10. S2 end 12:25 on C2; service likely ~40 (C2 norm). Feasible start  [11:00, 11:10). Wait = start  11:05  [5, 5]  bounded to **[0, 5], central 0** under A1.
- **P15 (both).** S1 start  [11:00, 11:15] after I1 free postP13 (11:40) is violated; corrected: I1 free at 11:40, so start  11:40  service  35. Combined with end 12:15, start  [11:55, 12:15], service  [0, 20] is impossible. Recompute: I1’s prior is P13 11:10–11:40, so I1 free 11:40; start  11:40, end = 12:15  service  35.
