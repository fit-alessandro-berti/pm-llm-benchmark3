## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels
UI_release -> true_process        (release notes claim: none; audit supports none)
policy_change -> true_process
policy_change -> recorded_labels  (introduces Supervisor Sign-off)
ETL_change -> recorded_order
ETL_change -> recorded_labels     (adds/relocates ingestion-time events)
event_gateway_change -> recorded_labels  (Queue Routed technical event)
reviewer_behavior -> true_process

true_process -> recorded_labels
true_process -> recorded_order
recorded_labels -> alignment_moves
recorded_order -> alignment_moves
normative_model -> alignment_moves
policy_change -> normative_model  (SHOULD have; edge omitted -> obsolescence)
alignment_moves -> measured_fitness
true_process -> business_outcomes
reviewer_behavior -> business_outcomes
hidden_highvalue_attribute -> policy_change_applicability
hidden_highvalue_attribute -> true_process
hidden_detection_gap -> business_outcomes  (masks incidents)
hidden_extraction_completeness -> recorded_labels
```

The observed fitness collapse is a superposition of several independent shocks that all funnel into `alignment_moves` → `measured_fitness` without any single one requiring behavioral change. UI 4.2 renamed `Classify`, so every trace incurs a log/model mismatch even though `true_process` is unchanged. The gateway injected `Queue Routed`, a technical event with no model counterpart, adding move-on-log per case. The ETL time-source switch corrupted `recorded_order`, producing `Notify`-before-`Decision` reversals that are provenance artifacts, not real reorderings. Later, a genuine `policy_change` added `Supervisor Sign-off` to `true_process` but not to `normative_model`, so model obsolescence drives the Aug-Sep residual. Because these mechanisms are additive, fitness can crater dramatically while behavior barely moves — which is exactly why the staged, mechanical repairs recover most of it.

Unchanged business outcomes (approval, appeals, cycle time) neither prove data error nor rule out noncompliance. They are consistent with "the process is fine and the log was noisy," but appeal rate lags, incident detection is admittedly incomplete, and the model is control-flow-only, so a modest number of true compliance-check bypasses (the 25/30 no-check enhanced reviews) could persist without moving these aggregates. Conversely, stable outcomes do not certify data quality, since a relabel or injected technical event distorts fitness while leaving outcomes untouched. Provenance and outcome evidence must therefore be read jointly, not as substitutes.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py

# --- 1. Normative process tree ---
tree_str = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "'Decision', 'Notify' )"
)
norm_tree = pm4py.parse_process_tree(tree_str)
norm_net, norm_im, norm_fm = pm4py.convert_to_petri_net(norm_tree)

# --- 3. Expand variant tables into an event log string ---
def variants_to_log_string(variants):
    # pm4py.parse_event_log_string expects one trace per line; here we
    # replicate each variant `count` times to reflect frequencies.
    lines = []
    for trace, count in variants:
        acts = ",".join(a.strip() for a in trace.split(","))
        lines.extend([acts] * count)
    return lines

jun_jul = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
    ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
    ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
]
aug_sep = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),
]

# parse_event_log_string accepts an iterable of comma-separated activity strings
log_jj_raw = pm4py.parse_event_log_string(variants_to_log_string(jun_jul))
log_as_raw = pm4py.parse_event_log_string(variants_to_log_string(aug_sep))

# --- 4. Discover DFGs ---
dfg_jj, sa_jj, ea_jj = pm4py.discover_dfg(log_jj_raw)
dfg_as, sa_as, ea_as = pm4py.discover_dfg(log_as_raw)
print("Jun-Jul DFG edges:", len(dfg_jj))

# --- 5. Alignment diagnostics + fitness vs normative model (raw) ---
fit_jj_raw = pm4py.fitness_alignments(log_jj_raw, norm_net, norm_im, norm_fm)
print("Jun-Jul RAW fitness:", fit_jj_raw)

# --- 6. Transparent normalization pipeline ---
def normalize(log, map_label=True, drop_queue=False, reorder=False):
    import copy
    log = copy.deepcopy(log)
    for trace in log:
        # (6a) reorder by source sequence number if available (illustrative;
        # here we simply demonstrate where reordering would occur)
        if reorder:
            trace[:] = sorted(trace, key=lambda e: e.get("seq", 0))
        new_events = []
        for e in trace:
            if map_label and e["concept:name"] == "Risk Screen":
                e["concept:name"] = "Classify"          # (6) map Risk Screen -> Classify
            if drop_queue and e["concept:name"] == "Queue Routed":
                continue                                 # optionally remove technical event
            new_events.append(e)
        trace[:] = new_events
    return log

log_jj_norm = normalize(log_jj_raw, map_label=True, drop_queue=True)
fit_jj_norm = pm4py.fitness_alignments(log_jj_norm, norm_net, norm_im, norm_fm)

# --- 7. Compare raw vs normalized ---
print("Jun-Jul NORMALIZED fitness:", fit_jj_norm)
print("Delta trace-fitness:",
      fit_jj_norm["averageFitness"] - fit_jj_raw["averageFitness"])

# --- 8. Candidate model permitting an OPTIONAL Supervisor Sign-off ---
cand_str = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "X ( 'Supervisor Sign-off', tau ), "     # optional sign-off (control-flow only)
    "'Decision', 'Notify' )"
)
cand_tree = pm4py.parse_process_tree(cand_str)
cand_net, cand_im, cand_fm = pm4py.convert_to_petri_net(cand_tree)

log_as_norm = normalize(log_as_raw, map_label=True, drop_queue=True)
fit_as_norm = pm4py.fitness_alignments(log_as_norm, norm_net, norm_im, norm_fm)
fit_as_cand = pm4py.fitness_alignments(log_as_norm, cand_net, cand_im, cand_fm)
prec_as_norm = pm4py.precision_alignments(log_as_norm, norm_net, norm_im, norm_fm)
prec_as_cand = pm4py.precision_alignments(log_as_norm, cand_net, cand_im, cand_fm)
print("Aug-Sep normative   fitness/precision:", fit_as_norm, prec_as_norm)
print("Aug-Sep candidate    fitness/precision:", fit_as_cand, prec_as_cand)

# --- 9. Caveats ---
print("""
CAVEATS:
- The optional-sign-off model is CONTROL-FLOW ONLY. It cannot enforce the
  'Supervisor Sign-off required IFF amount > EUR 50,000' data condition; it
  merely permits sign-off anywhere, so it will accept both correct and
  incorrect applications and cannot flag a missing sign-off on a >50k claim.
- Higher fitness for the candidate model likely comes with LOWER precision
  (overgeneralization): making an activity optional trivially raises fitness.
  Report fitness AND precision together and prefer a data-aware guard.
- These logs are variant aggregates, not the original timestamped events;
  numbers are illustrative and need not match the supplied aggregates.
""")
```

## 7. Provisional conclusion

Primary explanation for the measured conformance collapse: the drop is overwhelmingly an artifact of non-behavioral changes to how the process was *labeled, logged, and ordered*, not a change in what people actually did. The Jun-Jul collapse from 93% to 32% is fully consistent with three dated technical events: the UI relabel `Classify`→`Risk Screen` (confirmed by the 40-case audit), the injected technical event `Queue Routed`, and the ETL switch to warehouse-ingestion time that reversed `Notify`/`Decision`. The staged, provenance-preserving repairs — label remap (→58%), technical-event removal (→81%), source-sequence reordering (→89%) — recover almost all lost fitness without altering behavior, which is the decisive signature of a data/semantic cause. For Aug-Sep, the residual is dominated by *model obsolescence*: the 2026-08-01 `Supervisor Sign-off` policy was never added to the normative tree, and an extended (optional-sign-off) model restores fitness (66%→86%). Confidence: high (~85%) that logging/label/order defects plus model obsolescence explain the measured collapse.

Whether a real compliance problem remains: this must be assessed separately and is *not* resolved by the fitness story. The 25 (Jun-Jul) and 30 (Aug-Sep) enhanced-review traces without a recorded compliance check are genuinely ambiguous — no audit yet distinguishes true bypasses from missing events. Flat approval/appeal rates and no confirmed incidents are mildly reassuring but explicitly undermined by incomplete incident detection and a control-flow-only model that ignores the EUR 50,000 condition. Confidence that there is *no* real compliance issue: low-to-moderate (~50%); it cannot be certified.

Immediate actions. IT: publish an event-semantic catalog, freeze the label map, tag `Queue Routed` as technical, and reprocess conformance using source-sequence ordering. Process owners: version and extend the normative model to include a *data-aware* optional `Supervisor Sign-off` guarded by value>EUR 50,000, reporting precision alongside fitness. Compliance: commission a targeted provenance audit of the no-check enhanced-review cases and the 70 reversed-`Notify` cases, stratified by high-value status.

Must not be claimed yet: that employees became noncompliant (moves-on-log rose for logging reasons), that the process behavior changed, or that the process is compliant. None of these is established.

## 8. Model-governance recommendation

1. **Model versioning with change linkage.** Every policy or regulatory change (e.g., the EUR 50,000 sign-off) must trigger a versioned update to the normative model, with a traceable link from the policy record to the model revision and an effective date; conformance jobs must pin the model version applicable to each event's period.

2. **Event-semantic contracts.** Maintain a signed contract/registry mapping each logged activity label to a stable semantic identity independent of UI wording; UI relabels (e.g., `Classify`→`Risk Screen`) must update the display name only, never the semantic key used for conformance.

3. **Technical-event policy.** Classify every event at emission as business vs. technical (e.g., `Queue Routed`), tag it in the log schema, and require conformance pipelines to exclude declared technical events by default, with the exclusion list reviewed on every gateway/integration change.

4. **Timestamp provenance.** Record and retain an authoritative ordering key (source-system sequence number) alongside any derived time (ingestion time); conformance must order by the provenance key, and any change of time source (like the 2026-06-15 ETL switch) must be flagged and validated against ordering.

5. **Data-aware constraints.** Where compliance depends on case attributes (value>EUR 50,000 ⇒ sign-off), encode data-aware/decision constraints rather than control-flow-only models, and never accept an over-permissive optional-activity model as a "fix" without reporting precision.

6. **Post-release validation.** After every UI, ETL, gateway, or logging release, run a mandatory conformance regression on a labeled hold-out sample with a documented normalization pipeline (label map, technical-event filter, source ordering) before attributing any fitness change to behavior, and gate release sign-off on it.
