The shared causal mechanism is that, when Identity Check and Document Check draw on mostly independent information and can both be legally started, overlap can reduce idle time before the Assessment join. The join mechanism is common: Assessment waits for both verification branches, so the benefit comes from replacing sequential elapsed time with the maximum of two branch durations plus their queue waits.

The site-specific mechanisms are substantial. Site A had mostly digital documents, cross-trained reviewers, simultaneous task ownership, an API upgrade, extra document capacity, queue huddles, and a simpler after-period case mix. Site B has original-document law, role-specialized queues, legal review, supplement loops, heavier tails, and a system lock that may convert intended concurrency into informal workarounds.

The strongest effect modifiers are originals-required status, digital document availability, legal-review requirement, case complexity, IT lock behavior, pool-specific capacity, and queue discipline. These variables affect either the ability to create true overlap or whether upstream acceleration merely moves waiting to Assessment or Legal Review.

A similar control-flow diagram does not guarantee transportability because process trees abstract away data conditions, statutory prerequisites, resources, queue states, timestamp fidelity, and downstream loops. The same `+` operator can mean real concurrent work at Site A but illegal, blocked, or only retrospectively recorded work at Site B.

## 6. Candidate Site B intervention

The proposed intervention should be a segmented, legally gated partial-order redesign rather than a literal copy of Site A.

Eligibility rules: first include cases with no legal originals required, digital documents available at Register, non-public/non-high-value status, and low or medium complexity. A second stratum may include originals-required cases, but only for concurrent Identity Check and Originals Receipt. Public-sector/high-value and high-complexity cases should enter later as separately powered strata.

Concurrent task rules: after Register, Identity Check may be released immediately. For no-original digital cases, Document Check may also be released immediately and executed concurrently with Identity Check. For originals-required cases, Originals Receipt may proceed concurrently with Identity Check, but Document Check is created only after Originals Receipt. Assessment remains blocked until both Identity Check and the legally valid Document Check are complete.

Statutory prerequisites: originals-required gating, mandatory Legal Review for public-sector/high-value cases, and repeated document/assessment work after Request Supplement remain mandatory.

Queue and WIP controls: cap open identity and document pilot tasks by pool; release new concurrent tasks only if downstream Assessment WIP is below threshold; maintain a separate legal WIP guardrail.

Resource responsibilities: identity, document, assessment, and legal pools keep distinct ownership. No informal case-lock bypass is allowed.

Legal-review and supplement loops: Legal Review can approve/reject or issue Request Supplement. Supplement cases return to document checking and then Assessment before returning to Legal Review.

Logging requirements: record task-created, task-started, task-completed, owner, pool, lock state, original-required flag, legal-review flag, supplement flag, and whether timestamps are system-generated or edited.

Compact POWL-style relation set:

```text
Root nodes:
  Register,
  Identity Check,
  Document Path,
  Assessment,
  Post-Assessment Path,
  Notify

Document Path:
  X(
    Document Check,                                      # no-original/digital path
    PO(Originals Receipt, Document Check;
       Originals Receipt -> Document Check)             # originals-required path
  )

Post-Assessment Path:
  X(
    X(Approve, Reject),                                  # non-legal path
    PO(
      LOOP(
        Legal Review,
        PO(Request Supplement, Document Check, Assessment;
           Request Supplement -> Document Check,
           Document Check -> Assessment)
      ),
      X(Approve, Reject);
      LOOP(...) -> X(Approve, Reject)
    )
  )

Root partial order:
  Register -> Identity Check
  Register -> Document Path
  Identity Check -> Assessment
  Document Path -> Assessment
  Assessment -> Post-Assessment Path
  Post-Assessment Path -> Notify
```

The pilot separates mechanism failure from implementation failure by measuring both assigned treatment and actual process behavior. If treatment cells show high true overlap, valid statutory gating, and lower waiting-before-Assessment but no cycle-time gain, the mechanism works locally but downstream bottlenecks absorb the benefit. If recorded overlap rises while system logs show late entry, same-owner conflicts, or lock workarounds, the failure is implementation fidelity, not causal transport. If no-original digital cases improve but originals-required or legal cases do not, the Site A mechanism transports only to a subset. If rework, supplements, or appeals rise despite faster verification, the intervention creates a quality failure even when the timing mechanism works.

```python
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator


def check_model(name, net, im, fm):
    print(f"\n=== {name} ===")

    try:
        is_wf = pm4py.check_is_workflow_net(net)
        print("workflow net:", is_wf)
    except Exception as exc:
        print("workflow-net check unavailable or failed:", repr(exc))

    try:
        sound, diagnostics = pm4py.check_soundness(net, im, fm)
        print("sound WF-net:", sound)
        if diagnostics:
            print("diagnostic keys:", list(diagnostics.keys()))
    except Exception as exc:
        print("soundness check unavailable or failed:", repr(exc))


# ---------------------------------------------------------------------
# 1. Site A process trees
# ---------------------------------------------------------------------

site_a_before_tree = pm4py.parse_process_tree(
    "-> ( "
    "'Register', "
    "'Identity Check', "
    "'Document Check', "
    "'Assessment', "
    "X ( 'Approve', 'Reject' ), "
    "'Notify' "
    ")"
)

site_a_after_tree = pm4py.parse_process_tree(
    "-> ( "
    "'Register', "
    "+ ( 'Identity Check', 'Document Check' ), "
    "'Assessment', "
    "X ( 'Approve', 'Reject' ), "
    "'Notify' "
    ")"
)

site_a_before_net, site_a_before_im, site_a_before_fm = pm4py.convert_to_petri_net(
    site_a_before_tree
)
site_a_after_net, site_a_after_im, site_a_after_fm = pm4py.convert_to_petri_net(
    site_a_after_tree
)

check_model("Site A before", site_a_before_net, site_a_before_im, site_a_before_fm)
check_model("Site A after", site_a_after_net, site_a_after_im, site_a_after_fm)


# ---------------------------------------------------------------------
# 2. Site B candidate POWL model
# ---------------------------------------------------------------------
# Interpretation:
# - Register precedes both Identity Check and a document path.
# - The document path is data-dependent:
#     * no-original/digital path: Document Check can occur immediately;
#     * originals-required path: Originals Receipt must precede Document Check.
# - Assessment waits for both Identity Check and the document path.
# - After Assessment, either a nonlegal decision is taken or a Legal Review
#   branch is executed.
# - Legal Review may loop through Request Supplement -> Document Check ->
#   Assessment, then Legal Review again, before final Approve/Reject.

# Core verification nodes
register = Transition(label="Register")
identity = Transition(label="Identity Check")
assessment = Transition(label="Assessment")
notify = Transition(label="Notify")

# Document path option 1: no-original / digital document path
doc_direct = Transition(label="Document Check")

# Document path option 2: originals-required path
orig_receipt = Transition(label="Originals Receipt")
doc_after_orig = Transition(label="Document Check")

orig_doc_path = StrictPartialOrder(nodes=[orig_receipt, doc_after_orig])
orig_doc_path.order.add_edge(orig_receipt, doc_after_orig)

document_path = OperatorPOWL(
    operator=Operator.XOR,
    children=[doc_direct, orig_doc_path],
)

# Nonlegal final decision
approve_nonlegal = Transition(label="Approve")
reject_nonlegal = Transition(label="Reject")
nonlegal_decision = OperatorPOWL(
    operator=Operator.XOR,
    children=[approve_nonlegal, reject_nonlegal],
)

# Legal branch with supplement loop
legal_review = Transition(label="Legal Review")

request_supplement = Transition(label="Request Supplement")
supplement_doc_check = Transition(label="Document Check")
supplement_assessment = Transition(label="Assessment")

supplement_redo = StrictPartialOrder(
    nodes=[request_supplement, supplement_doc_check, supplement_assessment]
)
supplement_redo.order.add_edge(request_supplement, supplement_doc_check)
supplement_redo.order.add_edge(supplement_doc_check, supplement_assessment)

# LOOP semantics: execute Legal Review; either exit, or execute supplement_redo
# and then Legal Review again; repeat until exit.
legal_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[legal_review, supplement_redo],
)

approve_legal = Transition(label="Approve")
reject_legal = Transition(label="Reject")
legal_decision = OperatorPOWL(
    operator=Operator.XOR,
    children=[approve_legal, reject_legal],
)

legal_path = StrictPartialOrder(nodes=[legal_loop, legal_decision])
legal_path.order.add_edge(legal_loop, legal_decision)

post_assessment_path = OperatorPOWL(
    operator=Operator.XOR,
    children=[nonlegal_decision, legal_path],
)

# Root partial order:
# - Identity and document path are concurrent after Register.
# - Assessment waits for both Identity and Document Path.
# - Notify waits for the chosen post-assessment path.
site_b_candidate = StrictPartialOrder(
    nodes=[
        register,
        identity,
        document_path,
        assessment,
        post_assessment_path,
        notify,
    ]
)

site_b_candidate.order.add_edge(register, identity)
site_b_candidate.order.add_edge(register, document_path)

# Explicit AND-join dependency: Assessment waits for both branches.
site_b_candidate.order.add_edge(identity, assessment)
site_b_candidate.order.add_edge(document_path, assessment)

site_b_candidate.order.add_edge(assessment, post_assessment_path)
site_b_candidate.order.add_edge(post_assessment_path, notify)

site_b_net, site_b_im, site_b_fm = pm4py.convert_to_petri_net(site_b_candidate)

check_model("Site B candidate POWL", site_b_net, site_b_im, site_b_fm)


# ---------------------------------------------------------------------
# 3. Optional playout
# ---------------------------------------------------------------------
try:
    print("\nSample Site B candidate traces:")
    log = pm4py.play_out(site_b_net, site_b_im, site_b_fm)

    for i, trace in enumerate(log):
        if i >= 5:
            break
        labels = [event["concept:name"] for event in trace]
        print(f"trace {i + 1}:", labels)

except Exception as exc:
    print("playout unavailable or failed:", repr(exc))


# ---------------------------------------------------------------------
# 4. Model-fidelity limitations
# ---------------------------------------------------------------------
print(
    "\nLimitations: this POWL/Petri-net model encodes feasible ordering, "
    "choice, concurrency, and the supplement loop. It does not encode "
    "case attributes such as originals_required or legal_required; those "
    "must be enforced by guards, conformance rules, or filtered event-log "
    "analysis. It also does not encode resource capacities, queue lengths, "
    "case-lock constraints, API/originals delays, service-time distributions, "
    "timestamp back-entry, or appeal/rework probabilities."
)
```

## 9. Recommendation

`conditional go`.

Site B should transfer the principle, not the literal Site A intervention. The transferable principle is: when two verification activities are genuinely independent, legally startable, technically co-owned, and protected by WIP controls, they should be represented as a partial order rather than a sequence. The non-transferable part is Site A’s blanket creation of Identity Check and Document Check immediately after Register for all cases. That would violate Site B’s originals requirement for 62% of cases and could overload specialized Assessment or Legal Review queues.

The first subgroup should be digital, no-original, non-public/non-high-value, low-to-medium complexity cases. This subgroup is closest to Site A’s digital operating context and avoids Site B’s strongest non-transportable constraints: original documents, mandatory Legal Review, and supplement loops. A second stage can test originals-required cases only as Identity Check running in parallel with Originals Receipt, with Document Check still gated. Legal-review cases should enter only after the legal pool has a WIP safeguard and enough evidence that accelerated verification does not increase supplements.

Expected benefits are modest but plausible: treated simple digital cases may see a 3h to 7h reduction, while all-case medians may improve only 0.5h to 2h in the first pilot because the eligible subgroup is limited. The main risks are fake overlap caused by case-lock workarounds, downstream bottleneck shifts to Assessment or Legal Review, increased rework from premature document checking, and misleading improvement from timestamp back-entry.

Expansion should be triggered by high true-overlap fidelity, lower waiting before Assessment, stable Assessment and Legal Review queues, no illegal starts, and no material increase in rework or early quality defects. Modification is needed if mechanism metrics improve but downstream queues absorb the gain. Abandonment is warranted if true overlap cannot be implemented without shadow work, if p90 worsens by more than the stop-rule threshold, or if rework/appeal indicators deteriorate after controlling for case mix.

## 10. Assumption register

1. No-original share is approximately 38% — needed because the prompt states 62% require originals but does not directly state the complement’s eligibility — test by validating the originals-required flag in recent Site B cases — if false, the eligible pilot population and expected all-case impact change.

2. No-original status and nonlegal status are approximately independent for the first sizing estimate — needed to approximate an initial 23% low-risk subgroup — test by cross-tabulating originals-required by public-sector/high-value flag — if false, pilot volume may be larger or smaller.

3. Digital documents at registration are available for most no-original cases — needed to justify immediate Document Check in the first subgroup — test by measuring document availability and completeness at Register — if false, the no-original stratum still needs a document-readiness gate.

4. Identity and document evidence are sufficiently independent in digital/no-original cases — needed for parallel work not to create duplicate or inconsistent effort — test by auditing rework causes and dependency notes — if false, parallelization may increase rework.

5. The legacy system can be configured for real dual ownership in the pilot — needed to distinguish true overlap from back-entered events — test by system log audit before rollout — if false, do not pilot concurrent task execution until IT support exists.

6. Assessment capacity can absorb a small first-stage pilot — needed because faster verification can shift the bottleneck — test by monitoring assessor utilization and queue age during a dry run — if false, add release controls or reserve assessor capacity.

7. Site A’s waiting-before-Assessment reduction contains some real overlap effect — needed to use A as a weak upper anchor for scenarios — test indirectly through Site B randomized mechanism outcomes — if false, expected benefits should be revised toward zero.

8. Appeal effects can be monitored with delayed follow-up while early quality proxies guide interim safety — needed because 90-day appeals mature after operational decisions begin — test correlation between early rework/supplement defects and later appeals — if false, expansion must wait for fully matured appeal outcomes.
