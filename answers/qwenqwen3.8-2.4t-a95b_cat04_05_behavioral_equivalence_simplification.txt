def bounded_language(net, im, fm, max_visible=12, max_a=3):
    final_key = norm_mark(fm)
    memo = {}
    def suffixes(marking, rem_vis, rem_a):
       key = (norm_mark(marking), rem_vis, rem_a)
       if key in memo: return memo[key]
       result = set()
       closure = silent_closure(net, marking)
       if any(norm_mark(m) == final_key for m in closure):
           result.add(tuple())
       if rem_vis > 0:
          for m in closure:
             for t in enabled_transitions(net, m):
                if is_silent(t): continue
                lab = visible_label(t)
                a_cost = 1 if lab == ANALYZE else 0
                if a_cost > rem_a: continue
                nm = fire_transition(net, m, t)
                for suf in suffixes(nm, rem_vis-1, rem_a-a_cost):
                    result.add((lab,) + suf)
       memo[key] = result
       return result
    lang = suffixes(im, max_visible, max_a)
    # keep only traces that look complete (Open first, Close last), as a sanity filter
    return {tr for tr in lang if tr and tr[0] == OPEN and tr[-1] == CLOSE}

def enabled_transitions(net, marking):
    if hasattr(pm4py, "get_enabled_transitions"):
        return pm4py.get_enabled_transitions(net, marking)
    if petri_utils is not None:
        return petri_utils.get_enabled_transitions(net, marking)
    raise RuntimeError("No enabled-transition API found")

def fire_transition(net, marking, trans):
    if petri_utils is not None and hasattr(petri_utils, "fire_transition"):
        return petri_utils.fire_transition(net, marking, trans)
    if hasattr(pm4py, "fire_transition"):
        return pm4py.fire_transition(net, marking, trans)
    raise RuntimeError("No fire-transition API found")

def norm_mark(marking):
    try:
        items = list(marking.items())
    except AttributeError:
        items = [(p, marking[p]) for p in marking]
    return tuple(sorted((str(getattr(p, "name", p)), int(cnt)) for p, cnt in items))

def is_silent(trans):
    name = getattr(trans, "name", None)
    if name is None:
        return True
    return str(name).strip().lower() in {"tau", "silent", ""}

def visible_label(trans):
    name = getattr(trans, "name", None)
    if name is None:
        name = getattr(trans, "label", str(trans))
    return str(name)

def silent_closure(net, marking):
    stack = [marking]
    seen = {norm_mark(marking)}
    result = []
    while stack:
        m = stack.pop()
        result.append(m)
        for t in enabled_transitions(net, m):
            if is_silent(t):
                nm = fire_transition(net, m, t)
                key = norm_mark(nm)
                if key not in seen:
                    seen.add(key)
                    stack.append(nm)
    return result

def bounded_language(net, im, fm, max_visible=12, max_analyze=3):
    final_key = norm_mark(fm)
    memo = {}

    def suffixes(marking, rem_visible, rem_analyze):
        key = (norm_mark(marking), rem_visible, rem_analyze)
        if key in memo:
            return memo[key]
        out = set()
        closure = silent_closure(net, marking)
        if any(norm_mark(m) == final_key for m in closure):
            out.add(tuple())
        if rem_visible > 0:
            for m in closure:
                for t in enabled_transitions(net, m):
                    if is_silent(t):
                        continue
                    lab = visible_label(t)
                    a_cost = 1 if lab == ANALYZE else 0
                    if a_cost > rem_analyze:
                        continue
                    nm = fire_transition(net, m, t)
                    for suf in suffixes(nm, rem_visible - 1, rem_analyze - a_cost):
                        out.add((lab,) + suf)
        memo[key] = out
        return out

    lang = suffixes(im, max_visible, max_analyze)
    return {tr for tr in lang if tr and tr[0] == OPEN and tr[-1] == CLOSE}

def check_sound(net, im, fm):
    try:
        return pm4py.check_soundness(net, im, fm, print_diagnostics=False)
    except TypeError:
        return pm4py.check_soundness(net, im, fm)

tree_a = pm4py.parse_process_tree(TREE_A)
tree_b = pm4py.parse_process_tree(TREE_B)

net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

print("Model A sound:", check_sound(net_a, im_a, fm_a))

# 1. Equivalence Notions

Let the visible activity abbreviations be:

- `O` = `Open Case`
- `A` = `Analyze Revision`
- `C` = `Check Revision`
- `P` = `Approve Revision`
- `R` = `Rework Case`
- `E` = `Close Case`

`tau` is silent and is removed when computing visible traces.

A **complete visible trace** is a word over `{O, A, C, P, R, E}` generated from the initial marking to the final accepting marking, after hiding `tau`.

### Visible trace equivalence after hiding `tau`

Two models are visible-trace equivalent iff their sets of complete visible traces are equal:

\[
L_{vis}(M_1) = L_{vis}(M_2)
\]

Duplicate visible labels are distinguished by **occurrence position** in the sequence. For example, `A C R A C E` and `A R A C E` are different traces. There are no separate event IDs; two occurrences of `Check Revision` are considered two occurrences of the same label at different positions.

Under this strong notion, Models A and B are not equivalent.

---

### Bounded visible-language equivalence under P3

Under P3, compare only complete visible traces satisfying:

- at most 12 visible events;
- at most three occurrences of `Analyze Revision`;
- `tau` hidden;
- all other visible labels retained, including `Approve Revision`.

Formally:

\[
L_{P3}(M) =
\{
w \in L_{vis}(M)
\mid
|w| \le 12 \text{ and } \#_A(w) \le 3
\}
\]

Models are P3-equivalent iff:

\[
L_{P3}(A) = L_{P3}(B)
\]

This is bounded evidence, not a proof of unbounded equivalence. In this particular case, however, the bounded difference witnesses also prove unbounded non-equivalence.

---

### Business-relevant equivalence under P1

P1 is an operational compliance view. I interpret it as follows:

1. `Open Case` is first and `Close Case` is last.
2. The case is divided into revision segments by `Rework Case`.
3. Every `Analyze Revision` occurrence must have its own distinct `Check Revision` occurrence before the next `Rework Case`, or before `Close Case` if it is the last analysis.
4. `Rework Case` separates two analysis attempts.
5. `Approve Revision` is optional, but when present it is visible, and its number and placement remain relevant.
6. `tau` represents silent auto-approval/skip and is hidden in the visible trace, but the absence of `Approve Revision` is meaningful as a skipped approval.

Under P1, equivalence is not merely “same activity set.” It requires the same compliance-relevant visible behavior. A model that permits executions where an analysis has no distinct check before the next rework/close is not P1-equivalent to a model that prevents such executions.

---

### Abstracted dashboard equivalence under P2

P2 defines a much coarser observation. For a complete visible trace `w`, define the dashboard abstraction:

\[
\alpha(w) =
(
\#_A(w),
\mathbf{1}_{C}(w),
\mathbf{1}_{R}(w)
)
\]

where:

- `#_A(w)` is the number of `Analyze Revision` occurrences;
- `1_C(w)` is Boolean: did at least one `Check Revision` occur?
- `1_R(w)` is Boolean: did at least one `Rework Case` occur?
- `Approve Revision` is hidden;
- `tau` is hidden;
- exact interleaving of `A` and `C` is ignored;
- repeated `C` occurrences are collapsed to a Boolean.

Models are P2-equivalent iff:

\[
\alpha(L_{vis}(A)) = \alpha(L_{vis}(B))
\]

Under this abstraction, duplicate `Check Revision` labels are not distinguished by count or position; only existence matters. Duplicate `Analyze Revision` labels are distinguished only by count, not by exact position. `Rework Case` is reduced to a Boolean.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The loop contains `->( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) )` as its first child and `Rework Case` as its second child. | The loop contains `->('Analyze Revision', X('Approve Revision', tau))` as its first child and `Rework Case` as its second child. The single `Check Revision` is outside the loop and parallel to the whole loop. | A repeats the check every loop iteration. B performs exactly one check for the entire loop. |
| Minimum `Check Revision` occurrences | 1 | 1 | Both guarantee at least one check. |
| Maximum `Check Revision` occurrences | Unbounded; equal to the number of loop iterations | Exactly 1 | For two or more analyses, A can have two or more checks; B can never have more than one. |
| Possible placement of `Check Revision` | Inside each iteration, concurrent with that iteration’s `Analyze Revision`, and before the following `Rework Case` or `Close Case`. Also before `Approve Revision` in that iteration because the parallel join precedes the exclusive choice. | Anywhere interleaved with the whole loop: before the first `Analyze Revision`, between analysis and approval, between approval and rework, after rework, after the last analysis, etc., but before `Close Case`. | B can place the only check after a rework or after an approval; A cannot place a check after the rework it is supposed to gate. |
| Optional approval occurrences | `Approve Revision` or `tau` occurs after both `Analyze Revision` and `Check Revision` of the same iteration. | `Approve Revision` or `tau` occurs after `Analyze Revision` inside the loop, but because `Check Revision` is globally parallel, approval may appear before or after the single check. | Trace `O A P C E` is possible in B but not in A. |
| Concurrency | Local concurrency: `Analyze Revision` and `Check Revision` are concurrent inside each iteration. | Global concurrency: one `Check Revision` is concurrent with the entire revision loop. | A has per-iteration parallelism; B has case-level parallelism. |
| Rework behavior | `Rework Case` occurs only between two loop iterations, therefore between two analysis attempts. | Same loop structure for rework: `Rework Case` occurs only between two analysis attempts. | Both satisfy “rework separates analysis attempts,” but only A also has a check before each rework. |
| Join before `Close Case` | The loop completes, then `Close Case` occurs. No separate global parallel join. | The parallel branch containing `Check Revision` and the loop branch must both complete before `Close Case`. | B can have the check finish early and wait at the join; A’s checks are embedded in the loop. |
| Silent behavior | `tau` skips `Approve Revision` in each iteration. | `tau` skips `Approve Revision` in each iteration. | Both can produce traces without approvals. Hiding `tau` makes skipped approvals indistinguishable from absent events except by the lack of `P`. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 — operational compliance | `not equivalent` | High | Model B admits complete traces with multiple `Analyze Revision` occurrences but only one `Check Revision`, or with the check after a `Rework Case`. Model A enforces one check inside each loop iteration before the next rework/close. | If the business artificially restricts B to exactly one loop iteration, many P1-compliant traces overlap, but the model itself still permits noncompliant multi-iteration behavior. |
| P2 — executive dashboard | `equivalent only under stated abstraction` | High | After hiding approvals, collapsing `Check Revision` to a Boolean, and retaining only `Analyze Revision` count and `Rework Case` Boolean, both models yield exactly the same dashboard records: for every `n >= 1`, `A_count = n`, `check_occurred = true`, `rework_occurred = n > 1`. | If the dashboard later adds check count, check-before-rework validation, approval count, or A/C ordering, the models are no longer equivalent. |
| P3 — bounded testing | `not equivalent` | High | There are counterexamples within the P3 bound of 12 visible events and at most 3 `Analyze Revision` occurrences in both directions. | Bounded equivalence would only be evidence. Here inequality is provable, but a bounded test alone would not prove unbounded equivalence if the bounded sets happened to match. |

### Effect of optional `Approve Revision` and hidden `tau`

The exclusive choice `X('Approve Revision', tau)` means each iteration may either:

- emit a visible `Approve Revision`; or
- silently skip it via `tau`.

Therefore, the absence of `Approve Revision` in a visible trace is not an missing event; it is the observable result of a silent skip.

This affects the verdicts as follows:

- Under **strong visible trace equivalence** and **P3**, `Approve Revision` is visible. Therefore traces with and without `P` are different, and traces with different placement of `P` relative to `C` are different.
- Under **P2**, `Approve Revision` is hidden. For example, B-only-2 abstracts to the same dashboard record as an A trace with one analysis and one check: `A_count = 1`, `check_occurred = true`, `rework_occurred = false`. Thus B-only-2 is not a P2 counterexample.
- Under **P1**, approvals are visible and their placement is potentially relevant. If the compliance rule requires approval only after a check, then B-only-2 is also a P1 violation. If P1 only requires the check before the next rework/close, B-only-2 is still a visible-language difference and becomes a P1 concern only if approval ordering is added to the compliance rule.

# 5. Bounded Comparison Code

The following code performs **exhaustive bounded exploration** over Petri-net markings. It is not a random playout. It hides silent transitions, respects the visible-length bound, respects the maximum number of `Analyze Revision` occurrences, and records only complete traces reaching the final marking.

By contrast, `pm4py.play_out(...)` would sample or heuristically generate executions and would not prove bounded language equality or inequality unless every possible bounded trace were generated.

```python
import sys
import pm4py

try:
    from pm4py.objects.petri_net.utils import petri_utils
except Exception:
    petri_utils = None

sys.setrecursionlimit(10000)

OPEN = "Open Case"
CLOSE = "Close Case"
ANALYZE = "Analyze Revision"

TREE_A = (
    "->('Open Case', *("
    "->( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) ), "
    "'Rework Case'), 'Close Case')"
)

TREE_B = (
    "->('Open Case', +("
    "'Check Revision', *("
    "->('Analyze Revision', X('Approve Revision', tau)), "
    "'Rework Case')"
    "), 'Close Case')"
)


def enabled_transitions(net, marking):
    if hasattr(pm4py, "get_enabled_transitions"):
        return pm4py.get_enabled_transitions(net, marking)
    if petri_utils is not None:
        return petri_utils.get_enabled_transitions(net, marking)
    raise RuntimeError("No enabled-transition API found.")


def fire_transition(net, marking, trans):
    if petri_utils is not None and hasattr(petri_utils, "fire_transition"):
        return petri_utils.fire_transition(net, marking, trans)
    if hasattr(pm4py, "fire_transition"):
        return pm4py.fire_transition(net, marking, trans)
    raise RuntimeError("No fire-transition API found.")


def norm_mark(marking):
    """
    Canonical representation of a marking for memoization.
    """
    try:
        items = list(marking.items())
    except AttributeError:
        items = [(p, marking[p]) for p in marking]

    return tuple(
        sorted(
            (str(getattr(p, "name", p)), int(cnt))
            for p, cnt in items
        )
    )


def is_silent(trans):
    """
    Hide PM4Py silent transitions and explicit tau leaves.
    """
    name = getattr(trans, "name", None)
    if name is None:
        return True
    return str(name).strip().lower() in {"tau", "silent", ""}


def visible_label(trans):
    name = getattr(trans, "name", None)
    if name is None:
        name = getattr(trans, "label", str(trans))
    return str(name)


def silent_closure(net, marking):
    """
    All markings reachable by firing only silent transitions.
    Handles silent cycles by remembering normalized markings.
    """
    stack = [marking]
    seen = {norm_mark(marking)}
    result = []

    while stack:
        m = stack.pop()
        result.append(m)

        for t in enabled_transitions(net, m):
            if is_silent(t):
                nm = fire_transition(net, m, t)
                key = norm_mark(nm)

                if key not in seen:
                    seen.add(key)
                    stack.append(nm)

    return result


def bounded_language(net, im, fm, max_visible=12, max_analyze=3):
    """
    Exhaustive bounded visible-language generation.

    Returns all complete visible traces such that:
      - visible length <= max_visible
      - number of Analyze Revision occurrences <= max_analyze
      - tau/silent transitions are hidden
      - final marking is reached
    """
    final_key = norm_mark(fm)
    memo = {}

    def suffixes(marking, rem_visible, rem_analyze):
        key = (norm_mark(marking), rem_visible, rem_analyze)

        if key in memo:
            return memo[key]

        out = set()
        closure = silent_closure(net, marking)

        # A complete trace may stop here if final is silently reachable.
        if any(norm_mark(m) == final_key for m in closure):
            out.add(tuple())

        if rem_visible > 0:
            for m in closure:
                for t in enabled_transitions(net, m):
                    if is_silent(t):
                        continue

                    lab = visible_label(t)
                    a_cost = 1 if lab == ANALYZE else 0

                    if a_cost > rem_analyze:
                        continue

                    nm = fire_transition(net, m, t)

                    for suf in suffixes(nm, rem_visible - 1, rem_analyze - a_cost):
                        out.add((lab,) + suf)

        memo[key] = out
        return out

    lang = suffixes(im, max_visible, max_analyze)

    # Sanity filter: complete case traces should start with Open and end with Close.
    return {
        tr for tr in lang
        if tr and tr[0] == OPEN and tr[-1] == CLOSE
    }


def check_sound(net, im, fm):
    try:
        return pm4py.check_soundness(net, im, fm, print_diagnostics=False)
    except TypeError:
        return pm4py.check_soundness(net, im, fm)


tree_a = pm4py.parse_process_tree(TREE_A)
tree_b = pm4py.parse_process_tree(TREE_B)

net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

print("Model A sound:", check_sound(net_a, im_a, fm_a))
print("Model B sound:", check_sound(net_b, im_b, fm_b))

lang_a = bounded_language(net_a, im_a, fm_a, max_visible=12, max_analyze=3)
lang_b = bounded_language(net_b, im_b, fm_b, max_visible=12, max_analyze=3)

only_a = sorted(lang_a - lang_b, key=lambda tr: (len(tr), tr))
only_b = sorted(lang_b - lang_a, key=lambda tr: (len(tr), tr))

print()
print("Bounded language size A:", len(lang_a))
print("Bounded language size B:", len(lang_b))

print()
print("Traces unique to Model A:")
for tr in only_a[:20]:
    print("   " + " -> ".join(tr))
if len(only_a) > 20:
    print(f"   ... {len(only_a) - 20} more")

print()
print("Traces unique to Model B:")
for tr in only_b[:20]:
    print("   " + " -> ".join(tr))
if len(only_b) > 20:
    print(f"   ... {len(only_b) - 20} more")
```

# 6. Stochastic and Footprint Comparison

Footprints, stochastic languages, and Earth Mover’s Distance can provide supporting evidence, but they are not substitutes for trace-language equivalence.

### Footprints

Footprints usually summarize pairwise activity relations, such as precedence, succession, parallelism, or exclusiveness. They lose information about:

- exact occurrence counts;
- loop iteration counts;
- global dependencies such as “one check per analysis”;
- the exact language of complete traces.

Therefore, even equal footprints would not prove Models A and B equivalent. For example, footprint relations may not distinguish “one global check concurrent with the loop” from “one local check repeated inside each loop iteration.”

```python
# Footprint comparison, where supported by the PM4Py version.
# Equal footprints are not sufficient for trace equivalence.

for name, model in [("Model A", tree_a), ("Model B", tree_b)]:
    try:
        fp = pm4py.discover_footprints(model)
    except Exception as exc1:
        try:
            net, im, fm = pm4py.convert_to_petri_net(model)
            fp = pm4py.discover_footprints((net, im, fm))
        except Exception as exc2:
            fp = f"unavailable: {exc1} / {exc2}"

    print(name, "footprints:")
    print(fp)
    print()
```

### Stochastic language and EMD

A stochastic comparison requires explicit probabilities. Without declared probabilities, stochastic similarity is not a semantic property of the original process trees.

For illustration only, one could declare:

- `X('Approve Revision', tau)` chooses `Approve Revision` with probability `0.5` and `tau` with probability `0.5`;
- at the end of a loop iteration, exit and rework each have probability `0.5`;
- parallel interleavings are chosen uniformly among enabled transitions.

These probabilities are assumptions, not facts derived from the models.

```python
# Declared illustrative stochastic semantics:
# - approval vs tau: 50/50
# - loop exit vs rework: 50/50
# - parallel interleavings: uniform among enabled transitions
#
# If pm4py.get_stochastic_language is available, this gives a distributional comparison.
# A low EMD would still not prove logical trace equivalence.

stochastic_parameters = {
    "seed": 42,
    "max_traces": 20000
}

try:
    stoch_a = pm4py.get_stochastic_language(
        tree_a,
        parameters=stochastic_parameters
    )
    stoch_b = pm4py.get_stochastic_language(
        tree_b,
        parameters=stochastic_parameters
    )

    emd = pm4py.compute_emd(stoch_a, stoch_b)

    print("Stochastic language A:", stoch_a)
    print("Stochastic language B:", stoch_b)
    print("EMD:", emd)

except Exception as exc:
    print("Stochastic-language comparison unavailable or API mismatch:", exc)
```

A low EMD could occur because:

- the chosen probabilities make multi-iteration traces rare;
- the metric compares summary features rather than exact traces;
- sampling hides low-probability counterexamples;
- the stochastic semantics is not part of the original control-flow model.

Thus, equal footprints or low EMD can support a similarity argument, but cannot establish trace equivalence or P1 compliance equivalence.

# 7. Complexity Comparison

The following structural counts use the displayed n-ary process-tree syntax. Depth is counted as the number of nodes on the longest root-to-leaf path. If a PM4Py implementation internally binarizes n-ary operators, exact node counts may vary slightly, but the relative comparison remains the same.

| Metric | Model A | Model B |
|---|---:|---:|
| Process-tree node count | 12 | 12 |
| Depth, nodes on longest path | 5 | 6 |
| Visible leaves | 6 | 6 |
| Silent leaves | 1 | 1 |
| Duplicate leaf-label extra occurrences | 0 | 0 |

Model B is slightly deeper because the parallel operator containing `Check Revision` sits above the loop, whereas in Model A the parallel operator is inside the loop body.

The following code computes these metrics and also reports PM4Py’s Petri-net simplicity metric.

```python
from collections import Counter

def process_tree_metrics(node, depth=1):
    """
    Count nodes, depth, leaves, visible/silent leaves, and labels.
    Depth is number of nodes on longest root-to-leaf path.
    """
    children = getattr(node, "children", [])

    if children:
        acc = {
            "nodes": 1,
            "depth": depth,
            "leaves": 0,
            "visible_leaves": 0,
            "silent_leaves": 0,
            "labels": []
        }

        for child in children:
            sub = process_tree_metrics(child, depth + 1)

            acc["nodes"] += sub["nodes"]
            acc["depth"] = max(acc["depth"], sub["depth"])
            acc["leaves"] += sub["leaves"]
            acc["visible_leaves"] += sub["visible_leaves"]
            acc["silent_leaves"] += sub["silent_leaves"]
            acc["labels"].extend(sub["labels"])

        return acc

    label = getattr(node, "label", getattr(node, "name", None))
    if label is None:
        label = "tau"

    label_s = str(label)
    silent = label_s.strip().lower() == "tau"

    return {
        "nodes": 1,
        "depth": depth,
        "leaves": 1,
        "visible_leaves": 0 if silent else 1,
        "silent_leaves": 1 if silent else 0,
        "labels": [label_s]
    }


def summarize_tree(tree):
    m = process_tree_metrics(tree)
    counts = Counter(m["labels"])
    m["duplicate_label_extra_occurrences"] = sum(
        c - 1 for c in counts.values() if c > 1
    )
    del m["labels"]
    return m


def petri_summary(net, im, fm):
    try:
        simplicity = pm4py.simplicity_petri_net(net, im, fm)
    except Exception as exc:
        simplicity = f"unavailable: {exc}"

    return {
        "places": len(net.places),
        "transitions": len(net.transitions),
        "arcs": len(net.arcs),
        "simplicity": simplicity
    }


# Reuses tree_a, tree_b, net_a, im_a, fm_a, net_b, im_b, fm_b
# from the bounded comparison code.

print("Model A tree metrics:", summarize_tree(tree_a))
print("Model B tree metrics:", summarize_tree(tree_b))

print()
print("Model A Petri summary:", petri_summary(net_a, im_a, fm_a))
print("Model B Petri summary:", petri_summary(net_b, im_b, fm_b))
```

The duplicate-label count in the tree leaves is zero for both models because each activity name appears once in the syntax. Repetition in behavior comes from the loop, not from duplicated leaves.

# 8. Simplified Model

I choose **P2, the executive dashboard view**, as the target for simplification. P2 explicitly authorizes hiding approvals, collapsing repeated checks to a Boolean, and ignoring exact `A`/`C` interleaving. This makes meaningful simplification possible.

A compact P2-oriented model is:

```text
->(
  'Open Case',
  'Check Revision',
  *('Analyze Revision', 'Rework Case'),
  'Close Case'
)
```

This model means:

1. Open the case.
2. Perform one `Check Revision`.
3. Execute the loop:
   - first child: `Analyze Revision`;
   - either exit, or execute `Rework Case` and then `Analyze Revision` again.
4. Close the case.

It preserves the dashboard facts:

- `Open Case` first;
- `Close Case` last;
- at least one `Analyze Revision`;
- at least one `Check Revision`;
- exact number of `Analyze Revision` occurrences;
- whether any `Rework Case` occurred.

It intentionally abandons P1’s per-iteration check and P3’s exact visible trace language.

```python
import pm4py

simplified_model = pm4py.parse_process_tree(
    "->('Open Case', 'Check Revision', *('Analyze Revision', 'Rework Case'), 'Close Case')"
)

# Optional validation
snet, sim, sfm = pm4py.convert_to_petri_net(simplified_model)

try:
    simplified_sound = pm4py.check_soundness(snet, sim, sfm, print_diagnostics=False)
except TypeError:
    simplified_sound = pm4py.check_soundness(snet, sim, sfm)

print("Simplified model sound:", simplified_sound)
```

### Structural comparison with originals

| Metric | Model A | Model B | Simplified P2 model |
|---|---:|---:|---:|
| Process-tree node count | 12 | 12 | 7 |
| Depth, nodes on longest path | 5 | 6 | 3 |
| Visible leaves | 6 | 6 | 5 |
| Silent leaves | 1 | 1 | 0 |
| Duplicate leaf-label extra occurrences | 0 | 0 | 0 |

The simplified model is structurally smaller than both originals under the same n-ary counting convention.

### Preservation table

| Property | Status in simplified P2 model | Explanation |
|---|---|---|
| `Open Case` first | Exact | Enforced by outer sequence. |
| `Close Case` last | Exact | Enforced by outer sequence. |
| At least one `Analyze Revision` | Exact | Binary loop executes first child once. |
| Number of `Analyze Revision` occurrences | Exact | Each loop iteration contributes exactly one `Analyze Revision`. |
| At least one `Check Revision` | Exact | One `Check Revision` is explicitly placed before the loop. |
| Number of `Check Revision` occurrences | Abstracted / weakened | Fixed to one. Model A can have many; P2 only needs Boolean existence. |
| `Check Revision` before each rework/close | Lost | The simplified model has only one global check. |
| `Rework Case` separates analyses | Exact | Loop second child is `Rework Case`, executed only between analyses. |
| Whether any `Rework Case` occurred | Exact | Rework occurs iff there is more than one analysis. |
| `Approve Revision` occurrences | Lost | Removed because P2 hides approvals. |
| Silent `tau` behavior | Lost / abstracted | No silent skip is needed once approvals are removed. |
| Exact interleaving of `Analyze Revision` and `Check Revision` | Lost | Simplified model fixes the check before the first analysis; P2 ignores interleaving. |
| P1 operational compliance | Lost | Not suitable if every analysis needs its own check. |
| P3 bounded visible trace equivalence | Lost | The simplified model’s visible language is not equal to either original model’s visible language. |

### Regression traces for the simplified model

These traces are valid complete traces of the simplified model.

| Trace ID | Trace | Why it is a regression trace |
|---|---|---|
| S1 | `Open Case`  `Check Revision`  `Analyze Revision`  `Close Case` | Minimal case: one analysis, no rework. |
| S2 | `Open Case`  `Check Revision`  `Analyze Revision`  `Rework Case`  `Analyze Revision`  `Close Case` | Two analyses, one rework. Dashboard records `A_count = 2`, `Rework = true`. |
| S3 | `Open Case`  `Check Revision`  `Analyze Revision`  `Rework Case`  `Analyze Revision`  `Rework Case`  `Analyze Revision`  `Close Case` | Three analyses, two reworks. Dashboard records `A_count = 3`, `Rework = true`. |

### Negative traces for the simplified model

These traces are rejected by the simplified model.

| Trace ID | Trace | Why it is negative |
|---|---|---|
| N1 | `Open Case`  `Analyze Revision`  `Check Revision`  `Close Case` | The simplified model requires the single check before the first analysis. |
| N2 | `Open Case`  `Check Revision`  `Analyze Revision`  `Approve Revision`  `Close Case` | `Approve Revision` was removed in the P2 simplification. |
| N3 | `Open Case`  `Check Revision`  `Analyze Revision`  `Rework Case`  `Close Case` | Loop semantics require `Rework Case` to be followed by another `Analyze Revision`. |

Under the P2 abstraction, some negative traces may collapse to the same dashboard record as a valid trace. For example, N1 has the same P2 dashboard summary as S1. That is expected: the simplified model preserves the dashboard abstraction, not the full trace language.

# 9. Final Recommendation

### P1 — operational compliance

Use **Model A**.

Model A enforces the core P1 rule: each loop iteration contains its own `Analyze Revision` and `Check Revision` before the next `Rework Case` or before `Close Case`. Model B should not be used for P1 because it permits cases with multiple analyses but only one check, and it permits the check to appear after rework or after approval.

The simplified P2 model should **not** replace Model A for P1.

---

### P2 — executive dashboard

Models A and B are equivalent **only under the stated P2 abstraction**.

For dashboard purposes, both models produce exactly the same abstract records:

- `Open Case` first;
- `Close Case` last;
- at least one `Analyze Revision`;
- at least one `Check Revision`;
- `Analyze Revision` count `n >= 1`;
- `Rework Case` occurred iff `n > 1`;
- approvals and interleavings ignored.

For this purpose, the simplified model is preferable because it is smaller and directly encodes only the dashboard-relevant behavior. It may replace either original model **only** for dashboard reporting, and only after stakeholders accept that per-iteration checks and approvals are no longer represented.

---

### P3 — bounded testing

Models A and B are **not equivalent** under P3.

The bounded comparison is useful because it finds concrete distinguishing traces within the prescribed limit. In this case, the bounded counterexamples also demonstrate unbounded non-equivalence. However, in general, if bounded languages were equal, that would not prove unbounded equivalence. Differences could still appear with more than 12 visible events or more than three `Analyze Revision` occurrences.

For P3 testing, choose the model that represents the intended ground truth. If the intended operational behavior is “one check per analysis,” Model A is the appropriate oracle. If the intended behavior is “one global check concurrent with the revision loop,” Model B is the appropriate oracle. They should not be treated as interchangeable.

---

### Final warning

Bounded trace comparison, footprint equality, stochastic language similarity, and low Earth Mover’s Distance are useful diagnostics, but they are not general equivalence proofs. The decisive distinction here is structural and semantic: Model A repeats `Check Revision` inside the loop, while Model B places one `Check Revision` concurrently with the entire loop. That difference is invisible to the P2 dashboard but visible and compliance-relevant under P1 and P3.
