## 1. Normalization Assumptions

**Interval Construction:**
All timestamps are converted to UTC uncertainty intervals `[t_min, t_max]`.
*   **Clock Offset:** Defined as `offset = recorded_clock - true_clock`. True time `T_true = T_recorded - offset`. If offset is `[a, b]`, then `T_true` shifts by `[-b, -a]`.
*   **Resolution:** Applied first. "Floor to minute" creates `[t:00, t:59.999]`. "Round to nearest X" creates `[t-X/2, t+X/2)`. "Exact" creates `[t-0.5, t+0.5]`.
*   **Time Zone:** Converted to UTC before offset correction.
*   **DST Folds:** For LEGACY-BER (T-405), the 02:00-02:59 fold is resolved using ingestion order constraints.
*   **Mobile Entry Delay (T-406):** Treated as an additional negative shift on the true time. If user enters time `T` up to 5 mins late, `T_true <= T_recorded`. Interval expands by subtracting `[0, 300s]`.
*   **Missing Events:** Inferred from causal constraints (e.g., `Alert_Received <= Investigation_Start`) or duration bounds (T-404).
*   **SLA vs Profile:** SLA is a hard limit. Temporal Profile is statistical (`mean +/- zeta * std`).
*   **Classification:**
    *   `CERTAIN_PASS`: Interval  Acceptance Region.
    *   `CERTAIN_VIOLATION`: Interval  Acceptance Region = .
    *   `POSSIBLE_VIOLATION`: Partial overlap.
    *   `INDETERMINATE`: Missing critical events or unbounded uncertainty.

## 7. Governance Recommendation

1.  **Timestamp Storage:** All systems must store timestamps in UTC with nanosecond precision. Raw local timestamps must be retained for audit but not used for logic.
2.  **Clock Telemetry:** Implement continuous clock offset monitoring (e.g., NTP drift logs) with a minimum 1-minute retention. Offsets must be tagged to the event ID.
3.  **Resolution Metadata:** Event schemas must include `timestamp_resolution` (e.g., "floor_minute", "round_second"). Downstream systems must propagate this metadata to prevent false precision assumptions.
4.  **DST Handling:** Systems must record the UTC offset used at the time of the event (e.g., `+02:00`), not just the local time zone name, to resolve fold ambiguities automatically.
5.  **Lifecycle Semantics:** Define `Investigation_Start` explicitly (e.g., "ticket assignment" vs "first analyst note"). Ambiguity here invalidates S1 comparisons.
6.  **Mobile Entry:** Mobile clients must synchronize time via NTP before recording. User-entry delays should be captured as a separate attribute `entry_lag` rather than modifying the timestamp.
7.  **Enforcement Policy:** SLA enforcement must use interval logic. If `min_duration > SLA`, it is a violation. If `max_duration < SLA`, it is a pass. If intervals overlap, the case should be flagged for manual review rather than auto-failed.
8.  **Provenance:** Chain of custody for timestamps must be maintained. If a timestamp is inferred (e.g., T-404, T-407), the inference logic must be logged alongside the event.
