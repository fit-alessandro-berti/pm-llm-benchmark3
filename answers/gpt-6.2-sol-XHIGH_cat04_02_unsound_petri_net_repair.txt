# 1. Executive Verdict

The original net is structurally a workflow net, but it is **not sound**. The split starts both branches, yet `t_join_waived` consumes only the waiver token. It puts a token in `p_decision` without requiring analysis to finish, so a waived case can be authorized early. Even if analysis finishes before authorization, its token is never collected on the waiver route. The case can put a token in `sink` but cannot reach the exact final marking. The standard-review route synchronizes correctly.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_register`, `t_split` | Register once and start both branches | Registration passes the source token to `p_ready`; the split consumes it and produces a token in each of `p_analysis` and `p_review`. | Both branches start; the split is not the fault. |
| `t_analyze` | Complete mandatory analysis | Moves the analysis token from `p_analysis` to `p_analysis_done`, whose only consumer is `t_join_normal`. | On the waiver route the analysis token has no way to leave `p_analysis_done`. |
| `t_standard_review`, `t_waive_review` | Select exactly one review outcome | Compete for the same token in `p_review`; produce `p_review_done` or `p_waived`, respectively. | Neither outcome is dead, but firing one excludes the other for this case. |
| `t_join_normal` | Wait for analysis and standard review | Consumes one token each from `p_analysis_done` and `p_review_done`, then marks `p_decision`. | The standard path cannot authorize too soon and leaves no branch tokens. |
| `t_join_waived` | Wait for analysis and a recorded waiver | Consumes just `p_waived` and marks `p_decision`. | Bypasses the analysis prerequisite and leaves its token behind. |
| `t_authorize` | Authorize a case ready for decision | Consumes `p_decision` and marks `sink`. It does not inspect either branch. | It trusts an incorrectly issued decision token on the waiver route. |
| `im`, `fm` | Start one case and finish with no residue | `im = {source: 1}` and `fm = {sink: 1}`; all unlisted counts are zero. | Marking `sink` alongside any other place is not completion. |
| Workflow-net connectivity | Connect every node to the case entry and exit | `source` alone has no incoming arcs and `sink` alone has no outgoing arcs. All nodes lie on directed source-to-sink paths. | Structural connectivity does not check whether a join can collect the tokens produced together. |

For path coverage, the common prefix is `source → t_register → p_ready → t_split` and the common suffix is `p_decision → t_authorize → sink`. Between them, the paths through `p_analysis → t_analyze → p_analysis_done → t_join_normal`, `p_review → t_standard_review → p_review_done → t_join_normal`, and `p_review → t_waive_review → p_waived → t_join_waived` cover every remaining node. These are graph paths, not claims about transition enabledness.

# 3. Marking-Based Counterexample

A legal firing sequence is `t_register → t_split → t_waive_review → t_join_waived → t_authorize → t_analyze`. In the table, a set of place names denotes one token in each listed place and zero elsewhere. Rows 5b–6b start from the same marking at step 4 and show the opposite order of authorization and analysis.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source}` | `t_register` | Initial marking `im`. |
| 1 | `t_register` | `{p_ready}` | `t_split` | Case registered. |
| 2 | `t_split` | `{p_analysis, p_review}` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token in each branch. |
| 3 | `t_waive_review` | `{p_analysis, p_waived}` | `t_analyze`, `t_join_waived` | The review token is spent; standard review cannot fire. |
| 4 | `t_join_waived` | `{p_analysis, p_decision}` | `t_analyze`, `t_authorize` | Authorization is enabled although analysis has not occurred. |
| 5a | `t_authorize` | `{p_analysis, sink}` | `t_analyze` | A sink token exists, but the marking is not `fm`. |
| 6a | `t_analyze` | `{p_analysis_done, sink}` | None | Nonfinal deadlock: the leftover token has no enabled consumer. |
| 5b | `t_analyze` | `{p_analysis_done, p_decision}` | `t_authorize` | Completing analysis first still leaves its token uncollected. |
| 6b | `t_authorize` | `{p_analysis_done, sink}` | None | Same nonfinal deadlock, with authorization after analysis. |

Only `t_join_normal` can consume `p_analysis_done`, and it requires `p_review_done`, which can no longer be produced after the waiver spends the sole review token. Firing `t_analyze` even earlier, before `t_join_waived`, does not help: the waiver join still does not consume the analysis token. Thus from step 3 there is no continuation to `fm` (failure of option to complete), and reachable markings containing a sink token plus residue violate proper completion. Every transition can fire on some prefix from `im`; the problem is not a structurally disconnected or never-enabled transition.

# 4. Minimal-Repair Alternatives

**Edit-cost model:** Adding or deleting one arc costs 1; redirecting one endpoint of an existing arc costs 1 when its other endpoint and weight are unchanged and the new arc is valid. Adding or deleting a place or transition costs 1 per node, with incident arc edits charged separately. Keep the visible activities, ordinary unit-weight semantics, and initial and final markings fixed.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| A — Separate guarded joins | Add `p_analysis_done → t_join_waived`. Keep all existing arcs. | 1 arc addition | Both review outcomes stay explicit; both joins require and consume completed analysis. | The waiver join cannot fire early. On the waiver route it alone performs synchronization and feeds `p_decision`. | There are two synchronization transitions to keep consistent if new prerequisites are added. |
| B — Merge outcomes before one guarded join | Redirect `t_join_waived → p_decision` to `t_join_waived → p_review_done`; change no other arcs. Interpret `p_review_done` as “review requirement satisfied.” | 1 arc redirection | Analysis is still mandatory. `t_standard_review` and `t_waive_review` still record distinct outcomes. | `t_join_waived` becomes a silent router that may fire before analysis. `t_join_normal` now synchronizes analysis with either outcome. | The shared place no longer records which outcome occurred. The old join names can mislead, and the waiver route has an extra silent step relative to A. |

Both repairs are minimum-cost under this model: cost zero leaves the counterexample unchanged, and each repair has cost one. If counting only primitive arc additions and deletions, A costs one and B costs two. Under that accounting B is minimal for the shared-join design that retains the existing nodes and uses `t_join_waived` as the router: it must remove the direct waiver-to-decision arc and add the router's output to the common review place.

These are not renamings. The prefix `t_register → t_split → t_waive_review → t_join_waived`, with no analysis yet, is executable in B but not in A. On a complete waiver run, A uses `t_join_waived` as its sole join, whereas B also fires `t_join_normal`. Their **visible** complete-trace languages are the same: registration, then analysis and exactly one review outcome in either order, then authorization. Neither repair changes the business policy.

In each repair, after the split and until synchronization there is exactly one analysis token (pending or done) and one review token (pending or at an outcome place). B can move that review token through the silent router, but cannot clone it or send it directly to decision. From any such marking the unfinished branch steps can complete, and an eligible join consumes both tokens to produce the sole `p_decision` token. Authorization then produces exactly `fm`. The initial and registration markings can reach this flow, and every transition occurs on some properly completing run. Both nets also retain structural workflow-net connectivity.

# 5. Corrected PM4Py Code

Repair A, built from scratch:

```python
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")
places = {name: PetriNet.Place(name) for name in (
    "source", "p_ready", "p_analysis", "p_review", "p_analysis_done",
    "p_review_done", "p_waived", "p_decision", "sink",
)}
transitions = {name: PetriNet.Transition(name, label) for name, label in (
    ("t_register", "Register Case"),
    ("t_split", None),
    ("t_analyze", "Perform Analysis"),
    ("t_standard_review", "Perform Standard Review"),
    ("t_waive_review", "Record Review Waiver"),
    ("t_join_normal", None),
    ("t_join_waived", None),
    ("t_authorize", "Authorize Case"),
)}
repaired_net.places.update(places.values())
repaired_net.transitions.update(transitions.values())
nodes = {**places, **transitions}

for source_name, target_name in (
    ("source", "t_register"),
    ("t_register", "p_ready"),
    ("p_ready", "t_split"),
    ("t_split", "p_analysis"),
    ("t_split", "p_review"),
    ("p_analysis", "t_analyze"),
    ("t_analyze", "p_analysis_done"),
    ("p_review", "t_standard_review"),
    ("t_standard_review", "p_review_done"),
    ("p_review", "t_waive_review"),
    ("t_waive_review", "p_waived"),
    ("p_analysis_done", "t_join_normal"),
    ("p_review_done", "t_join_normal"),
    ("t_join_normal", "p_decision"),
    ("p_waived", "t_join_waived"),
    # Require and consume completed analysis on the waiver route as well.
    ("p_analysis_done", "t_join_waived"),
    ("t_join_waived", "p_decision"),
    ("p_decision", "t_authorize"),
    ("t_authorize", "sink"),
):
    petri_utils.add_arc_from_to(nodes[source_name], nodes[target_name], repaired_net)

repaired_im = Marking({places["source"]: 1})
repaired_fm = Marking({places["sink"]: 1})
```

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net import semantics
from pm4py.objects.petri_net.obj import Marking


def show_marking(current_net, marking, final):
    tokens = dict(sorted((place.name, count) for place, count in marking.items() if count))
    enabled = pm4py.get_enabled_transitions(current_net, marking)
    enabled_names = sorted(transition.name for transition in enabled)
    print(tokens, "enabled:", enabled_names, "exact fm:", marking == final)


def replay(current_net, initial, final, names):
    by_name = {transition.name: transition for transition in current_net.transitions}
    marking = Marking(initial)
    print("im:", end=" ")
    show_marking(current_net, marking, final)
    for name in names:
        transition = by_name[name]
        if transition not in pm4py.get_enabled_transitions(current_net, marking):
            print(f"{name}: not enabled; replay stopped")
            return None
        successor = semantics.execute(transition, current_net, marking)
        if successor is None:
            raise RuntimeError(f"Could not fire enabled transition {name}")
        marking = successor
        print(f"{name}:", end=" ")
        show_marking(current_net, marking, final)
    return marking


reachability_graphs = {}
for title, current_net, initial, final in (
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
):
    print(f"\n{title}")
    print("Workflow net:", pm4py.check_is_workflow_net(current_net))
    is_sound, _ = pm4py.check_soundness(current_net, initial, final, print_diagnostics=True)
    print("Sound:", is_sound)
    reachability_graphs[title] = pm4py.convert_to_reachability_graph(current_net, initial, final)

prefix = ("t_register", "t_split")
early_attempt = (*prefix, "t_waive_review", "t_join_waived", "t_authorize", "t_analyze")
print("\nOriginal counterexample:")
bad_end = replay(net, im, fm, early_attempt)
assert bad_end is not None and bad_end != fm
assert not pm4py.get_enabled_transitions(net, bad_end)

print("\nSame attempt on repair A:")
blocked = replay(repaired_net, repaired_im, repaired_fm, early_attempt)
assert blocked is None

for review, join in (
    ("t_standard_review", "t_join_normal"),
    ("t_waive_review", "t_join_waived"),
):
    for branch_order in (("t_analyze", review), (review, "t_analyze")):
        print(f"\nRepaired completion: {branch_order}")
        outcome = replay(
            repaired_net, repaired_im, repaired_fm,
            (*prefix, *branch_order, join, "t_authorize"),
        )
        assert outcome == repaired_fm
```

Expect the workflow-net check to pass for both and the soundness check to fail for the original but pass for A. The original reachability graph contains a waiver path to a nonfinal deadlock with tokens in `p_analysis_done` and `sink`. Repair A blocks the replay at `t_join_waived` before analysis, and both review outcomes can reach the exact final marking in either branch order. WOFLAN's diagnostic wording and which check reports the failure first need not be the same across versions.

# 7. Repair Trade-Offs and Residual Risks

- **Auditability.** Both designs keep distinct visible standard-review and waiver events. A also distinguishes the outcomes in separate places up to synchronization. B loses the distinction in the marking as soon as the outcomes merge. Neither design stores it in the final marking; retain the event record for audit. The net does not check that a waiver was approved by the right person or backed by the required evidence.
- **Silent behavior.** In A, the two silent joins share the analysis input but cannot both be enabled for a single case: the one review token marks at most one outcome place. The joins cannot produce duplicate authorization or duplicate visible review events. B uses one synchronization transition, but the silent router can commute with analysis, giving different internal paths for the same visible trace without adding a visible event.
- **Positive regressions.** After registration, test analysis before and after standard review, and analysis before and after waiver. Each run must authorize once and terminate at exactly `{sink: 1}`.
- **Negative regressions.** Reject authorization before analysis (especially after waiver), before a review outcome, or before registration. Reject both review outcomes in one case, repeated analysis or authorization, and any purported completion with extra tokens. Check rejected behavior by enabledness or exact execution, not by a replay mode that inserts missing tokens.
- **Detecting bypasses.** Soundness does not prove policy conformance: a net could let a waived case skip analysis and still finish cleanly. Explore reachable states together with history flags for `t_analyze` and the review outcomes. Fail the regression if `t_authorize` is enabled on any history without analysis or without exactly one recorded outcome. Check the policy against transition identities and the audit labels, not just the presence of a token in a place named `p_decision`.

# 8. Final Recommendation

Deploy **Repair A**. It restores mandatory analysis on the waiver route with one added prerequisite arc, keeps the visible audit trail and existing route structure, and avoids a new silent routing step. Gate deployment on exact-final-marking regressions for both routes and the reachability check that authorization is never enabled before analysis and a review outcome.

Use **Repair B** as the fallback if synchronization prerequisites are likely to change and should be maintained in one place. It preserves the same visible policy, but operators must use the event record rather than the shared review place to determine which outcome occurred. Document that `t_join_waived` now routes a waiver and does not itself authorize or synchronize.
