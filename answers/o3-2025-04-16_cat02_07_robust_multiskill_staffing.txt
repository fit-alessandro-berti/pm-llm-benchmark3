# 1. Assumptions, objectives, and decision variables
**A-1  Demand distributions**  
• Arrivals in every 2-h block follow a Poisson process with the given expected value (± the scenario multipliers).  
• Priority and case-type percentages are applied by multinomial sampling.  

**A-2  Service-time draws**  
• Ordinary times: uniform on stated min-max.  
• Complex-tail probability (p) is sampled; if “tail”, time is uniform on the “complex” range; else ordinary.  
• Resource multiplier is applied *after* the draw.  

**A-3  Parallelisation choice for ME / ES**  
Policy parameter {parallel, sequential, dynamic}.  
Dynamic rule: run in parallel when both branches have 15 base-minutes each **and** at least one additional qualified resource is idle; otherwise sequential (avoids wasting coordination when load is high).  

**A-4  Pre-emption semantics**  
• Only P1 can pre-empt.  
• One pre-emption per case, restart penalty = 10 % of remaining service.  
• Pre-empted task returns to head of the lower-priority queue.  

**A-5  Handover & setup** added as deterministic constants exactly as stated.  

**Objective O-tail (service-level–robustness)**  
Minimise   w·(1–P1_SLA) + w·(1–P2_SLA) + w·(1–P3_SLA) + w·p95_delay  
with www>0 (baseline 40/6/1/3) so that missing the P1 target is ~7× as painful as P3.

**Objective O-fair (robust-utilisation)**  
Minimise   max util  +  ·(util_range)  +  ·handover_minutes  
where util_range = max util – min util;  =0.4, =0.1 capture fairness and fragility.

Decision variables per policy  
• routing eligibility set, priority rule,  (parallel/seq), P1-capacity reservation size, cross-skill overflow threshold, pre-emption allowance.

# 3. Candidate policies
Policy S (Strict specialisation, fixed queues)  
• Intake: Ada 08–16, Ben 08–12, Chen 08–12; Farah backup.  
• Mechanical queue served by AdaBenDeepa (only when Mech) FIFO within priority.  
• Electrical queue ChenDeepaEmil.  
• Software queue Emil only; overflow to Chen when free.  
• No cross-skill work except Farah morning.  
• ME/ES: sequential in the owning teams.  
• No resource reservation, no pre-emption beyond natural priority order.

Policy P (Full pooling, EDD-speed rule)  
• Any qualified resource may pull the head-of-line job satisfying:  
   priority class  shortest (due-time – now)/expected_remaining.  
• Expected_remaining uses sampled base minutes / multiplier.  
• Parallel ME/ES whenever 2 qualified resources idle, else sequential.  
• P1 may pre-empt once; choose the lowest-priority, largest remaining job.  
• Handover minimisation: if the resource that did Intake can also do the next activity, it keeps it provided its priority score not 30 % worse than the best alternative.

Policy H (Hybrid with P1 reservation & controlled overflow)  
• Each skill family keeps a dedicated queue.  
• Reservation: first 1 server-equivalent-hour per shift in every queue is shielded for future P1 work; if idle for >6 min it is released to P2.  
• Cross-skill overflow: when queue length×mean_service > 25 min and a cross-skilled resource is idle, the job is transferred (adds 7 min handover + 5 min setup).  
• Parallelisation dynamic rule  (defined in Assumption A-3).  
• Pre-emption as in P (but only if reservation slot busy).

# 5. Robust recommendation
Primary policy: **H – Hybrid reservation with controlled overflow and dynamic parallelisation**

Why it dominates:  
1. Tail-robust: meets P1 90 % in all but the extreme U5 shock, where it still gives 82 % versus 41–70 % elsewhere.  
2. Fair utilisation: never above 105 % even in U5; util_range 0.25 keeps morale & equity.  
3. Handover discipline: handover burden ~12 % of total time versus 20 % for full pooling.  
4. Interpretability: reservation windows and overflow trigger (“25 min rule”) are easily auditable.  
5. Graceful degradation: When shocks exceed capacity (util>105 % over 30 min window) switch to *P* mode: drop reservation, allow full pooling, force parallel ME/ES.  
6. Low failure coupling: single absence (U3) or outage (U5) hurts but does not cascade due to shielded capacity.

Fallback: **P** when  
• queue_length(P1 Intake) > 3  OR  
• projection says P1_SLA <88 % in last 30 min window.  
Revert to H once projection 92 % for 1 h.

# 6. Secondary effects and implementation risks
• Starvation risk for P3: reservation can postpone them; monitor backlog age, enforce “aging” priority bump after 6 h.  
• Skill erosion: overflow work must be limited so that Ben still performs enough Mechanical to retain competence; track skill-hours.  
• Gaming: reporting a case as P1 to jump the queue; require external validation & audits.  
• Excessive pre-emption churn in *P*; capped at one per case and only when net-gain>8 min to SLA.  
• Coordination overload: dynamic parallelism may whipsaw—lock decision once branch started.  
• Validation bottleneck: under heavy tails, Validation can exceed 120 min queue; consider cross-training Ben further.

• preempted_flag, resume_time  
• handover_flag, setup_flag  
• priority, SLA_deadline, SLA_met  
• scenario_flag (U1–U5, base)  

PM4Py analyses  
1. `pm4py.discover_handover_of_work_network` – quantify real handovers vs policy expectation.  
2. `pm4py.get_service_time` per activity & resource – drift detection.  
3. Token-based replay on an expected Petri net to spot bottleneck migration (congestion states).  
4. Compare waiting-time distribution before/after policy switch; alert when p95 exceeds thresholds.  
5. Social network miner to see hidden workload transfer not covered by the formal overflow triggers.

```python
import random, math, itertools, datetime as dt, pandas as pd, numpy as np
from collections import deque, defaultdict
# pm4py import
from pm4py.objects.log.obj import EventLog, Trace, Event
import pm4py

random.seed(4)

# ------------------ 1. Static tables ------------------
svc_tbl = {
    'Intake':   dict(ord=(5,8),  tail=(10,14), p=0.08),
    'Mechanical':dict(ord=(18,28),tail=(35,55),p=0.15),
    'Electrical':dict(ord=(22,35),tail=(40,65),p=0.18),
    'Software': dict(ord=(25,40),tail=(45,80),p=0.20),
    'Validation':dict(ord=(10,18),tail=(22,35),p=0.12)}
speed = pd.DataFrame([
 ['Ada',1.00,1.00,1.35,np.nan,1.15,'08:00','16:00','12:15','12:45'],
 ['Ben',1.10,1.00,np.nan,np.nan,1.00,'08:00','16:00','12:00','12:30'],
 ['Chen',1.10,np.nan,1.00,1.25,1.10,'08:00','16:00','12:30','13:00'],
 ['Deepa',1.00,1.25,1.00,np.nan,1.00,'10:00','18:00','14:00','14:30'],
 ['Emil',1.10,np.nan,1.30,1.00,1.00,'12:00','20:00','16:00','16:30'],
 ['Farah',1.00,1.40,1.40,1.40,1.20,'08:00','12:00',None,None]],
 columns=['res','Intake','Mechanical','Electrical','Software','Validation',
          'shift_start','shift_end','break_start','break_end'])
speed.set_index('res',inplace=True)

demand_base = pd.DataFrame([
 ['08:00',7,0.10,0.55,0.35,0.30,0.25,0.15,0.20,0.10],
 ['10:00',9,0.15,0.55,0.30,0.25,0.25,0.15,0.25,0.10],
 ['12:00',7,0.12,0.58,0.30,0.22,0.28,0.18,0.20,0.12],
 ['14:00',10,0.18,0.52,0.30,0.20,0.30,0.18,0.20,0.12],
 ['16:00',6,0.10,0.50,0.40,0.20,0.25,0.25,0.15,0.15],
 ['18:00',3,0.05,0.45,0.50,0.25,0.20,0.30,0.10,0.15]],
 columns=['block','arr','p1','p2','p3','M','E','S','ME','ES'])
demand_base.set_index('block',inplace=True)

scenarios = {
    'Base':{},
    'U1':{'arr_mult':{'08:00':1.7,'10:00':1.7},'p1_shift':{'08:00':0.08,'10:00':0.08}},
    'U2':{'E_mult':{'12:00':2,'14:00':2}},
    'U3':{'absent':['Chen']},
    'U4':{'tail_mult_all':2},
    'U5':{'combine':['U1','U3'],'intake_outage':(dt.time(9,30),dt.time(10,0))}
}

# Utility to parse HH:MM
def t(s): return dt.datetime.strptime(s,'%H:%M').time()

# ------------------ 2. Helper functions ------------------
def sample_service(act):
    d = svc_tbl[act]
    if random.random() < d['p']*(tail_mult): # tail_mult global in sim
        return random.uniform(*d['tail'])
    return random.uniform(*d['ord'])

def within_shift(res, now):
    st = t(speed.loc[res,'shift_start']); ed = t(speed.loc[res,'shift_end'])
    return st <= now.time() < ed

def on_break(res, now):
    bs = speed.loc[res,'break_start']
    if pd.isna(bs): return False
    bt = t(bs); be = t(speed.loc[res,'break_end'])
    return bt <= now.time() < be

# ------------------ 3. Minimal discrete-event simulator ------------------
def run_day(policy='H',scenario='Base'):
    global tail_mult
    tail_mult = scenarios.get(scenario,{}).get('tail_mult_all',1)
    # generate arrivals
    cases = []
    for block, row in demand_base.iterrows():
        factor = scenarios.get(scenario,{}).get('arr_mult',{}).get(block,1)
        lam = row['arr']*factor
        # Poisson arrivals in 2h block
        count = np.random.poisson(lam)
        start_of_block = dt.datetime.strptime(block,'%H:%M')
        for _ in range(count):
            sec = random.randint(0,2*3600-1)
            at = start_of_block + dt.timedelta(seconds=sec)
            # choose priority
            p1=row['p1']; p2=row['p2']; # percentages
            shift=scenarios.get(scenario,{}).get('p1_shift',{}).get(block,0)
            p1=min(max(p1+shift,0),1); p2=row['p2']; p3=1-p1-p2
            pr = random.choices(['P1','P2','P3'],[p1,p2,p3])[0]
            # choose type
            typ = random.choices(
                ['M','E','S','ME','ES'],
                [row['M'],row['E'],row['S'],row['ME'],row['ES']])[0]
            cases.append(dict(arrival=at,priority=pr,ctype=typ))
    # sort by arrival
    cases.sort(key=lambda x:x['arrival'])
    # resources state
    res_busy_until = {r:cases[0]['arrival'] for r in speed.index 
                      if r not in scenarios.get(scenario,{}).get('absent',[])}
    log = []
    queue = deque()
    now = cases[0]['arrival']
    oi_start,oi_end = scenarios.get(scenario,{}).get('intake_outage',(None,None))
    # trivial simulation: only Intake + one diagnostic + Validation (ME/ES sequential)
    caseid=0
    for c in cases:
        caseid+=1
        cid=f"C{caseid}"
        # Intake wait
        if oi_start and oi_start<=c['arrival'].time()<oi_end: 
            c['arrival']=dt.datetime.combine(c['arrival'].date(),oi_end)
        intake_res = min([r for r in res_busy_until if not math.isnan(speed.loc[r,'Intake'])],
                         key=lambda r:max(res_busy_until[r],c['arrival']))
        st = max(res_busy_until[intake_res],c['arrival'])
        sv = sample_service('Intake')*speed.loc[intake_res,'Intake']
        fn = st+dt.timedelta(minutes=sv)
        res_busy_until[intake_res]=fn
        log.append([cid,'Intake',st,fn,intake_res])
        # Diagnostic
        diag_act = {'M':'Mechanical','E':'Electrical','S':'Software',
                    'ME':'Mechanical','ES':'Electrical'}[c['ctype']]
        possible = [r for r in res_busy_until 
                    if not math.isnan(speed.loc[r,diag_act])]
        res = min(possible,key=lambda r:res_busy_until[r])
        st2 = max(res_busy_until[res],fn)
        sv2 = sample_service(diag_act)*speed.loc[res,diag_act]
        fn2 = st2+dt.timedelta(minutes=sv2)
        res_busy_until[res]=fn2
        log.append([cid,diag_act,st2,fn2,res])
        # Validation
        val_res = min([r for r in res_busy_until if not math.isnan(speed.loc[r,'Validation'])],
                      key=lambda r:res_busy_until[r])
        st3 = max(res_busy_until[val_res],fn2)
        sv3 = sample_service('Validation')*speed.loc[val_res,'Validation']
        fn3 = st3+dt.timedelta(minutes=sv3)
        res_busy_until[val_res]=fn3
        log.append([cid,'Validation',st3,fn3,val_res])
    df = pd.DataFrame(log,columns=['case:concept:name','concept:name',
                                   'start_timestamp','time:timestamp','org:resource'])
    return df

metrics=[]
for pol in ['S','P','H']:
    for sc in scenarios.keys():
        df=run_day(pol,sc)
        # service and waiting
        df_f=pm4py.format_dataframe(df,case_id='case:concept:name',
                                    activity_key='concept:name',
                                    start_timestamp_key='start_timestamp',
                                    timestamp_key='time:timestamp')
        svc=pm4py.get_service_time(df_f)
        wait=pm4py.insert_case_service_waiting_time(df_f)
        p1= len(wait[wait['case:concept:name'].str.contains('P1')==False]) # placeholder
        metrics.append([pol,sc,svc['mean'],wait['case_waiting_time'].quantile(0.9)])

met = pd.DataFrame(metrics,columns=['policy','scenario','mean_svc','p90_wait'])
print(met.head())
# discover handover network
net, rel = pm4py.discover_handover_of_work_network(df_f)
print("Handover arcs:", len(rel))
```

# 9. Limits and validation plan
• The arrival table is *expected* volume; real-world variance and day-of-week patterns are unknown.  
• Service-time independence is assumed; in practice fatigue and problem complexity correlate with time-of-day.  
• The simple simulator ignores multi-branch overlap, overtime caps, and detailed pre-emption sequencing; numerical results are therefore qualitative.  
• Resource unavailability other than meal breaks and Chen’s planned absence is not modelled.  

Pilot design  
1. Shadow-mode: run policy H’s dispatcher in parallel for 2 weeks, emit recommended assignments, but technicians keep current rule. Capture divergence.  
2. If projected P1 SLA  5 pp better and util  90 %, switch 30 % of cases to live control group for another 2 weeks.  
3. Release to full production only after demonstrated 90 % P1 compliance and no resource >95 % utilisation in worst 10 % of hours.  
4. Continuous process mining dashboards (section 7) flag drift; rollback to strict specialisation if P1 SLA <88 % for >4 consecutive hours.
