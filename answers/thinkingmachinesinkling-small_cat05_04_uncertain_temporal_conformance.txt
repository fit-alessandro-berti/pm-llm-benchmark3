## 1. Normalization Assumptions

**Interval construction rule.** For every event:  
1. Apply source-specific display/rounding to obtain a clock-time interval.  
2. Convert to UTC using the zone offset in force at the event date (CEST = UTC+2 for June 2026; CET = UTC+1 for 2025-10-26; EDT = UTC4; BST = UTC+1).  
3. Apply clock-offset direction `true_time = clock_time  offset` with `offset  [a,b]`; because `offset` is an interval, true time is `[C_min  b, C_max  a]`.  
4. Combine all sources of independence (rounding, clock error, time-zone interpretation) as interval arithmetic; do not collapse disjoint sets blindly.

**Clock-offset semantics.** `clock_offset = recorded_clock  true_clock`; therefore `true = recorded  offset`. A bound `[-90,+120]` s means true time can be up to 120 s earlier or 90 s later than the clock interval.

**Resolution / rounding.**  
- HUB: exact to second  clock interval `[t0.5, t+0.5]`; offset `[-1,+1]`.  
- OPS-BER / VENDOR-NY / LEGACY-BER: floor to minute  clock interval `[hh:mm:00, hh:mm:59.999]`.  
- SENSOR: round to nearest 10 s  clock interval `[t5, t+5]`.  
- MOBILE-LON: round to nearest minute  clock interval `[t30, t+30]`; clock offset `[-300,+300]`.

**DST fold (T-405, 2025-10-26, Europe/Berlin).** The transition at 03:00 CEST  02:00 CET creates a repetition of local 02:00–02:59. The event is either in the first fold (CEST, UTC+2) or second fold (CET, UTC+1). Ingestion ordering (`Investigation_Start` after `Alert_Received`; `Containment_Complete` after `Investigation_Start`) cross-filters combinations: only `Alert` in first fold + `Investigation/Containment` in second fold is feasible. Surviving intervals are disjoint; they are preserved, not averaged.

**Inferred starts (T-404).** `Investigation_Start = Investigation_Complete  d` with `d  [1080,1500]` s (18–25 min). Uncertainty of the completion event is propagated through subtraction; midpoint of duration is used only for comparison, never as the sole estimate.

**Mobile entry delay (T-406).** The 5-minute late-entry is treated as a **record/logging delay**, not a shift in occurrence time: the feasible UTC interval for the occurrence is derived from the rounded mobile clock and clock error; the entry delay is reported separately. ## 7. Governance Recommendation

**Timestamp storage.** All event logs must store **UTC with offset and local-time annotations**; never store only local time. For T-405-style folds, require an explicit `is_dst` or `fold_index` column.

**Clock / offset telemetry.** Mandatory: source clock offset bound from daily or per-event NTP diagnostics (not weak engineering estimates like T-409 ±12 min). If diagnostics are missing for an hour, the event should be flagged `clock_confidence = low`.

**Resolution metadata.** Each source must declare precision (`exact`, `floor_minute`, `round_10s`, `round_minute`). Do not treat 10:14 (floor) and 10:14:00 (exact) identically.

**Lifecycle semantics.** Distinguish `Alert_Received` from `Alert_Sent` (T-407); distinguish `Investigation_Start` from `Investigation_Complete` (T-404); distinguish `Containment_Complete` (completion) from `Containment_Start`. Use the profile pairs exactly as labeled.

**DST policy.** For transition-day records (e.g., 2025-10-26), logs must include either `first_occurrence` / `second_occurrence` flags, or be rejected if ambiguous. Ingestion order can be used to select combinations, but only when sequence is logged with monotonic sequence IDs.

**Causal identifiers.** Where receipt is inferred from sent + latency, require a `derived` flag and do not use such intervals for enforcement unless confirmed by acknowledgment. A policy should state whether **interval overlap** is sufficient for enforcement: recommend **no**—enforcement requires either `CERTAIN_VIOLATION` under a conservative interval interpretation, or a separate admission/acknowledgment. Possible violations trigger review, not automatic penalties.

**Interval-based enforcement policy.** Propose three tiers:  
- **CERTAIN_PASS:** No action; interval wholly inside SLA/profile.  
- **POSSIBLE_VIOLATION:** Escalate to manual review; do not penalize until interval is narrowed or acknowledgment obtained.  
- **CERTAIN_VIOLATION:** Action permitted; interval wholly outside.

**Midpoint prohibition for enforcement.** Explicit policy: midpoint estimates are permitted only for dashboard visualization, not for SLA adjudication. All conformance reviews must use feasible interval bounds.

**Mobile / user entry controls.** User-entered mobile timestamps must carry “entry_delay_estimate” and “device_sync_status”. If sync is absent and delay > 2 min, treat as low-confidence and require corroborating server event (e.g., HUB) within profile window.

**Data retention.** Retain raw recorded value, source system, resolution rule, clock-offset telemetry, timezone conversion rule, and DST interpretation. This allows re-analysis if clock errors are later corrected (e.g., T-409 NTP recovered).
