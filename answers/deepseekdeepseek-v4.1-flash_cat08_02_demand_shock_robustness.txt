# 3. Robust redesign package

The robust redesign should not be a single priority rule or a global capacity increase. It should be a layered system: stabilize intake, cap WIP by case type, protect critical capacity, and activate surge only at the bottleneck.

## Backbone 1: Stability and defect triage at intake
Combine I6, I7, and gated I8. Use courier smoothing (I7) to reduce 10:00/17:00 spikes. Use early pre-analytical defect triage (I6) to reject poor samples within 2h and prevent downstream assay/repeat/medical loads. Use registration automation (I8) only for orders with complete digital metadata.

Why robust: It reduces rework and variability before assay, medical validation, and specialist review. It helps mix-shift, courier, and repeat scenarios.

Assumptions: validated rejection criteria; courier route flexibility; metadata completeness.

Failure modes: over-rejection can overload recollection and courier; external courier delay can still cause stability failures; automation can expose pre-analytical and assay queues.

## Backbone 2: Deadline-aware priority with WIP caps
Replace strict Urgent-first dispatch (I1) with capped priority lanes. Reserve capacity for Urgent and Complex-panel at preparation, assay, medical validation, and specialist review, but set aging caps for Routine and caps on how much capacity can be bypassed.

Why robust: It protects Urgent contracts without permanently starving Routine/Complex. It prevents the WIP explosion that strict priority rules create.

Assumptions: accurate case-type flags; clinical governance for Routine tech-release; real-time queue visibility.

Failure modes: if Urgent+Complex volume exceeds reserved capacity, Routine will still starve; if caps are too loose, Urgent breaches rise.

## Backbone 3: Flexible surge staffing with bottleneck guardrails
Use I4 only as surge: cross-train two technical validators for accession correction when accession queue is high and technical-validation queue is low. Use I5 evening medical validation during peaks or validator absence, but pair it with specialist cross-coverage or Complex-panel overflow.

Why robust: It relieves the active bottleneck without permanently adding capacity everywhere.

Assumptions: cross-training completed; staff can be redeployed; medical and specialist scopes allow cross-cover.

Failure modes: I4 can move the bottleneck to technical validation; I5 can move it to specialist review.

## Backbone 4: Assay resilience and repeat control
Use dynamic M1/M2 routing rather than fixed dedication. M1 should preferentially handle Urgent, Complex-panel, and Repeat-after-failure cases. Routine can go to M2 only when M2 repeat/failure rate is below threshold. Use I2 larger Routine batches only off-peak or when Urgent queue is low.

Why robust: It protects critical cases and controls the repeat loop, which otherwise consumes assay capacity twice.

Assumptions: per-machine QC and repeat tracking; ability to switch routing in real time.

Failure modes: M1 outage removes the preferred critical lane; M2 degradation increases repeats; larger batches delay Urgent if not capped.

## Backbone 5: Complex-panel overflow safety valve
Use I10 only for non-Urgent Complex-panel cases when specialist review or medical validation is saturated. Trigger when specialist queue >24h or medical queue >12h and Complex-panel WIP is high.

Why robust: It prevents Complex-panel cases from monopolizing specialist/medical capacity and blocking simpler cases.

Assumptions: partner quality, traceability, and acceptable 12h transport delay for selected cases.

Failure modes: transport delay may violate targets for some Complex-panel cases; traceability complexity can create administrative rework.

## Backbone 6: Do not use I9 as a default
Holding Routine releases until a batch report is ready is not supported by the queue data as a core fix. It may reduce release work, but it adds waiting and can worsen Routine p90, already 120h peak. Use only if release administration is confirmed as the active bottleneck.

# 6. Residual vulnerabilities

- Assay machines remain a single-point fragility. Peak assay utilization is 98%, and M1 outage or M2 degradation can still cascade into repeat loops.
- Medical and specialist absence remains fragile. One specialist is unavailable every second Friday; Complex-panel cases are 2.4× more likely to need specialist review.
- Recollection loops remain long. Recollectionreceive is 42h normal / 60h peak; early triage may reduce downstream repeats but can increase recollection volume if over-rejection occurs.
- Cross-training technical validators to accession correction can create a redesign-caused technical-validation bottleneck. Peak technical validation is already 101% utilized with a 16h queue.
- Registration automation can create a redesign-caused pre-analytical/assay bottleneck by increasing clean intake faster than downstream capacity.
- Priority caps can still starve Routine if Urgent+Complex demand exceeds reserved capacity.
- Outsourcing Complex-panel adds 12h transport and traceability complexity; partner delays can become a new hidden bottleneck.
- Courier smoothing depends on external courier behavior; delays can still cause stability failures and cancellations.
