# 2. Shared Assumptions

1. **Completion-word semantics.** Every model describes visible sequences of completion events. `C  E` or an unordered partial order means that both completion interleavings are allowed; it is not proof that the underlying activities overlapped.
2. **Common backbone.** R is first, A-P-Z is the suffix, and C and E each occur exactly once before A. No candidate permits P before A.
3. **Single occurrence.** S and X occur at most once in a case. There is no evidence for loops or repeated confirmations. Repeated activity nodes in model code are duplicate **labels in alternative branches**, not repeated execution within one trace.
4. **Two kinds of optionality.**
   - X optionality is treated as genuine process optionality, subject to D6/S6.
   - A no-S path is only an **observation-level alternative**. It conflates “S legitimately not required” with “S occurred but its event was not exported.” It neither imputes an S event nor establishes that skipping S was compliant.
5. **Missing sourcing attribute.** Because external/stocked status is absent, none of the candidates can express the normative rule “S is XOR-skipped exactly for stocked cases.” That requires a data-aware model or guard.
6. **Counts are not probabilities.** The seven no-S cases are not a clean estimate of true S optionality, and the two X cases are not discarded merely because they are rare.
7. **Notation.** `;` denotes sequence, `+` XOR, `` unordered/interleaved execution, and `Q?` means `Q + `, where `` is silent. All three visible languages are finite and acyclic.

It factors only the universally observed prefix and suffix and otherwise memorizes the seven observed completion words. Frequencies do not remove rare variants. from pm4py.objects.process_tree.obj import ProcessTree, Operator

def leaf(label):
    return ProcessTree(label=label)

def pt_node(operator, children):
    node = ProcessTree(operator=operator)
    for child in children:
        child.parent = node
        node.children.append(child)
    return node

def pt_sequence(labels):
    return pt_node(Operator.SEQUENCE, [leaf(label) for label in labels])

# Only the portions between R and A are enumerated.
observed_middle_words = [
    (C, E, S),       # V1
    (E, C, S),       # V2

    (E, C, X, S),    # V7
]

model_conservative = pt_node(
    Operator.SEQUENCE,
    [
        leaf(R),
        pt_node(
            Operator.XOR,
            [pt_sequence(word) for word in observed_middle_words],
        ),
        leaf(A),
        leaf(P),
        leaf(Z),
    ],

# 4. Balanced Candidate

**Inductive bias.** This candidate generalizes only through two explicit abductive steps: unordered checks, supported by S2 and both observed orders, and local recombination of S/X placements supported by D5–D6 and S6. It preserves V5 rather than treating it as noise, adds the symmetric E-S-C possibility, but does not make S wholly independent of the checks. Let \(H=C\parallel E\) and \(X?=X+\tau\). The compact expression is:

\[
M_b=R;\left[
H;X?
\;+\;
H;(S+XS+SX)
\;+\;
C;S;E;X?
\;+\;
E;S;C;X?
\right];A;P;Z .
\]

The four terms respectively represent: no observed S, S after both checks, early S after C, and early S after E. The construction admits 14 visible core words, including all seven observed words.

**Ordering decisions**

- **C and E:** where S does not separate them, they are unordered. For two activities, an AND operator and an unordered partial order yield the same two visible completion words, C-E and E-C. This is a concurrency/generalization hypothesis based primarily on S2, not on the bidirectional DFG alone.
- **S:** it is not simply sequenced after both checks, because that would exclude V5. It is also not made completely parallel with C and E, because that would admit S before either check. The XOR decomposition encodes the conditional OR-trigger interpretation of D5.
- **X:** it is always after both checks. With late S, three mutually exclusive alternatives encode no X, X before S, and X after S. With early S or no S, X is an optional suffix. This avoids admitting two X occurrences.
- **Why not one balanced partial order?** Fixed edges CS and ES would overconstrain V5, while omitting both edges would admit supplier-first behavior. A single ordinary partial order does not directly express the optional, conditional “at least one check” rule as clearly as this decomposition.

**Self-contained PM4Py POWL code**

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

R = "Register Order"
C = "Credit Check"
E = "Engineering Review"
S = "Supplier Confirmation"
X = "Expedite Review"
A = "Approve Configuration"
P = "Release Production"
Z = "Archive Case"

def T(label):
    return Transition(label)

def powl_xor(*nodes):
    return OperatorPOWL(operator=Operator.XOR, children=list(nodes))

def powl_sequence(*nodes):
    # A sequence is a partial order with adjacent ordering edges.
    po = StrictPartialOrder(nodes=list(nodes))
    for left, right in zip(nodes, nodes[1:]):
        po.order.add_edge(left, right)
    return po

def powl_unordered(*nodes):
    return StrictPartialOrder(nodes=list(nodes))

def checks():
    # No C/E edge: this is a hypothesis, not proof of lifecycle concurrency.
    return powl_unordered(T(C), T(E))

def optional_x():
    return powl_xor(T(X), SilentTransition())

no_supplier_observation = powl_sequence(
    checks(),
    optional_x(),
)

late_supplier = powl_xor(
    powl_sequence(checks(), T(S)),          # no X
    powl_sequence(checks(), T(X), T(S)),    # X before S
    powl_sequence(checks(), T(S), T(X)),    # X after S
)

early_supplier = powl_xor(
    powl_sequence(T(C), T(S), T(E), optional_x()),
    powl_sequence(T(E), T(S), T(C), optional_x()),
)

core = powl_xor(
    no_supplier_observation,
    late_supplier,
    early_supplier,
)

model_balanced = powl_sequence(
    T(R), core, T(A), T(P), T(Z)
)
```

**Behavior deliberately excluded**

- S before either check completion, including S-C-E and S-E-C.
- X before both checks have completed, repeated X, or X after A.
- Repeated S, S after A, omitted C or E, and release before approval.
- Arbitrary additional activities, loops, or context-dependent exceptions not supported by the evidence.

**Known underfitting risks**

- D5 concerns when S may **begin**. Requiring a prior check **completion** may be too strong if S has a long lifecycle or uses partial check output.
- Multiple component-level supplier confirmations would not fit the single-S assumption.
- The model cannot tolerate missing C, E, or X events; only S missingness is abstracted.
- If no-S and X have context-specific interactions not represented by the current core words, those contexts remain indistinguishable.

There are also overgeneralization risks: if S1 is a hard universal rule, unordered checks are wrong, and if V5 is a timestamp artifact, the early-S branches may be unnecessary.

# 5. Permissive Candidate

**Inductive bias.** This candidate retains the medium/high-confidence safety constraints but relaxes the weakest ordering assumption, D5. It treats C, E, and optional S as unordered unless a dependency is explicitly represented, while retaining both check-to-X dependencies. It is intended to bound reasonable exploratory behavior and expose precision loss, not to assert that every admitted word is desirable.

Let \(\widehat{S}=S+\tau\) and \(\widehat{X}=X+\tau\). Then:

\[
M_p=R;
PO\!\left(
\{C,E,\widehat{S},\widehat{X}\},
\{C\prec\widehat{X},\;E\prec\widehat{X}\}
\right);
A;P;Z .
\]

The optional-X ordering edges apply even when its silent alternative is chosen. S has no incoming edge and can therefore appear before, between, or after check completions. At the visible-word level, this construction adds exactly four core words beyond balanced: S-C-E, S-C-E-X, S-E-C, and S-E-C-X.

**Self-contained PM4Py POWL code**

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

R = "Register Order"
C = "Credit Check"
E = "Engineering Review"
S = "Supplier Confirmation"
X = "Expedite Review"
A = "Approve Configuration"
P = "Release Production"
Z = "Archive Case"

def T(label):
    return Transition(label)

def powl_xor(*nodes):
    return OperatorPOWL(operator=Operator.XOR, children=list(nodes))

def powl_sequence(*nodes):
    po = StrictPartialOrder(nodes=list(nodes))
    for left, right in zip(nodes, nodes[1:]):
        po.order.add_edge(left, right)
    return po

c_node = T(C)
e_node = T(E)
s_optional = powl_xor(T(S), SilentTransition())
x_optional = powl_xor(T(X), SilentTransition())

core = StrictPartialOrder(
    nodes=[c_node, e_node, s_optional, x_optional]
)

# X, when visible, must follow both checks.
core.order.add_edge(c_node, x_optional)
core.order.add_edge(e_node, x_optional)

model_permissive = powl_sequence(
    T(R), core, T(A), T(P), T(Z)
)
```

**Boundary between reasonable generalization and forbidden behavior**

Reasonable generalization is limited to reordering and optionally omitting the existing pre-approval observations while preserving the fixed backbone and check/X dependencies. Supplier-first words are admitted only as a **risky sensitivity hypothesis**: they could reflect start/completion semantics or an overly narrow reading of D5, but they are not supported by an observed variant.

The following remain forbidden:

- X before either check, more than one X, or X after A.
- A without both C and E, P before A, or any visible S after A.
- Repeated S, omitted R/A/P/Z, arbitrary loops, and unrelated activities.
- Treating no-S as proof that an external order was compliant.

**Known underfitting/undercoverage risks**

- Its principal statistical risk is actually **underfitting the constraints**, that is, overgeneralization and low precision.
- It still cannot represent multiple supplier confirmations, genuine exceptions to D3/D4, or missing events other than S.
- Like the other candidates, it cannot represent lifecycle overlap or duration; it only admits completion interleavings.
- Its compact partial order hides the important distinction between legitimate stocked skips and missing supplier events.

| Model | Excluded complete trace | Earliest violated constraint |
|---|---|---|
| Conservative | R  E  S  C  A  P  Z | At S after prefix R-E: no observed branch has that continuation. This is sample-XOR exclusion, not a demonstrated domain violation. |

| Balanced | R  S  C  E  A  P  Z | At S: neither check has completed, violating balanced’s operationalization of D5. |
| Balanced | R  C  X  E  S  A  P  Z | At X: E has not completed, violating D6/S6. |

| Permissive | R  C  A  P  Z | At A: E is absent and the pre-approval core cannot have completed, violating D3. |
| Permissive | R  C  E  S  P  A  Z | At P: A has not occurred, violating D2 and the fixed suffix. |

# 7. Comparative Model Matrix

| Criterion | Conservative | Balanced | Permissive |
|---|---|---|---|
| Expected fitness on the 30 observed cases | Perfect in principle by construction; says nothing about future cases. | Perfect in principle because it contains every observed word. | Perfect in principle because it contains balanced’s language. |
| Expected precision risk | Low apparent training precision risk, but very high overfitting risk; a high measured value would be flattering rather than confirmatory. | Medium: seven targeted unobserved words, with C/E concurrency and early-S symmetry as contestable choices. | Highest of the three, although the visible extension is bounded. The supplier-first additions and independent-S semantics are particularly risky. |
| Generalization potential | None beyond the observed words. | Targeted and auditable; suitable for nearby sourcing/check/X recombinations. | Broadest within the fixed one-occurrence backbone; useful as an upper-bound sensitivity model. |
| Structural simplicity | Seven XOR branches; simple conceptually but repetitive and poorly scalable. | More nested structure and duplicate labels, but each branch has a process interpretation. | Compact source-level partial order; conversion may expand substantially and silent optional nodes complicate inspection. |
| Explainability | Easy to explain as an accepted-variant list, weak as a causal process explanation. | Best rationale: no-S, late-S, and two early-S modes are explicit. | The diagram is compact, but explaining why S is independent and why silent paths are not compliance decisions is harder. |
| Robustness to missing S events | Limited: handles observed no-S forms but rejects no-S forms involving X. | Good visible-log tolerance, including no-S plus X; cannot distinguish repaired missingness from a legitimate skip. | Similar tolerance, but greater danger that missing or genuinely absent required S is hidden inside a broad model. |
| Handling of unseen interleavings | Rejects all. | Accepts targeted symmetric and recombined interleavings only. | Accepts all linearizations of its partial order, including the risky supplier-first forms. |
| Main failure mode | Overfits the sample and underfits the target process. | May overcommit to S2 or to a completion-based reading of D5. | Underfits constraints and may admit undesirable behavior or mask data-quality problems. |
| Suitability for compliance versus exploration | Useful as an observed-log regression baseline, not as a normative compliance model. | Best interim descriptive/conformance candidate, with separate hard-rule checks and no standalone supplier-compliance claims. | Exploration and sensitivity analysis only; unsuitable as the sole compliance oracle. |

Alignment precision, token-replay generalization, and Petri-net simplicity measure particular structural/statistical properties. They should not be interpreted as probabilities that a candidate is the true process.

# 8. Validation Code

The following script is self-contained: it reconstructs the candidates and log, converts them, checks soundness, computes available metrics, performs sampled playout, and tests a manually specified acceptance/rejection suite. Unavailable version-dependent metrics are reported rather than replaced with invented values.

```python
import math
from collections import Counter

import pm4py
from pm4py.objects.process_tree.obj import ProcessTree, Operator
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.log.obj import EventLog, Trace, Event


# -----------------------------
# Labels
# -----------------------------
R = "Register Order"
C = "Credit Check"
E = "Engineering Review"
S = "Supplier Confirmation"
X = "Expedite Review"
A = "Approve Configuration"
P = "Release Production"
Z = "Archive Case"


# -----------------------------
# Conservative ProcessTree
# -----------------------------
def pt_leaf(label):
    return ProcessTree(label=label)


def pt_node(operator, children):
    node = ProcessTree(operator=operator)
    for child in children:
        child.parent = node
        node.children.append(child)
    return node


def pt_sequence(labels):
    return pt_node(Operator.SEQUENCE, [pt_leaf(x) for x in labels])


observed_middle_words = [
    (C, E, S),
    (E, C, S),
    (C, E),
    (E, C),
    (C, S, E),
    (C, E, S, X),
    (E, C, X, S),
]

model_conservative = pt_node(
    Operator.SEQUENCE,
    [
        pt_leaf(R),
        pt_node(
            Operator.XOR,
            [pt_sequence(w) for w in observed_middle_words],
        ),
        pt_leaf(A),
        pt_leaf(P),
        pt_leaf(Z),
    ],
)


# -----------------------------
# POWL helpers and candidates
# -----------------------------
def T(label):
    return Transition(label)


def powl_xor(*nodes):
    return OperatorPOWL(operator=Operator.XOR, children=list(nodes))


def powl_sequence(*nodes):
    po = StrictPartialOrder(nodes=list(nodes))
    for left, right in zip(nodes, nodes[1:]):
        po.order.add_edge(left, right)
    return po


def powl_unordered(*nodes):
    return StrictPartialOrder(nodes=list(nodes))


def checks():
    return powl_unordered(T(C), T(E))


def optional_x():
    return powl_xor(T(X), SilentTransition())


balanced_core = powl_xor(
    # No visible S.
    powl_sequence(checks(), optional_x()),

    # S after both checks; X absent, before S, or after S.
    powl_xor(
        powl_sequence(checks(), T(S)),
        powl_sequence(checks(), T(X), T(S)),
        powl_sequence(checks(), T(S), T(X)),
    ),

    # S after one check and before the other.
    powl_xor(
        powl_sequence(T(C), T(S), T(E), optional_x()),
        powl_sequence(T(E), T(S), T(C), optional_x()),
    ),
)

model_balanced = powl_sequence(
    T(R), balanced_core, T(A), T(P), T(Z)
)

c_node = T(C)
e_node = T(E)
s_optional = powl_xor(T(S), SilentTransition())
x_optional = powl_xor(T(X), SilentTransition())

permissive_core = StrictPartialOrder(
    nodes=[c_node, e_node, s_optional, x_optional]
)
permissive_core.order.add_edge(c_node, x_optional)
permissive_core.order.add_edge(e_node, x_optional)

model_permissive = powl_sequence(
    T(R), permissive_core, T(A), T(P), T(Z)
)

candidates = {
    "model_conservative": model_conservative,
    "model_balanced": model_balanced,
    "model_permissive": model_permissive,
}


# -----------------------------
# 1. Reconstruct the 30-case log
# -----------------------------
variant_rows = [
    (12, (R, C, E, S, A, P, Z)),
    (7,  (R, E, C, S, A, P, Z)),
    (4,  (R, C, E, A, P, Z)),
    (3,  (R, E, C, A, P, Z)),
    (2,  (R, C, S, E, A, P, Z)),
    (1,  (R, C, E, S, X, A, P, Z)),
    (1,  (R, E, C, X, S, A, P, Z)),
]

trace_strings = [
    ",".join(word)
    for count, word in variant_rows
    for _ in range(count)
]

log = pm4py.parse_event_log_string(trace_strings)


def log_word(case):
    return tuple(event["concept:name"] for event in case)


assert len(log) == 30
expected_counts = Counter({word: count for count, word in variant_rows})
assert Counter(log_word(case) for case in log) == expected_counts


# ------------------------------------------------------------
# Finite design oracle, used only for sanity checks.
# It is not independent evidence that the models match reality.
# ------------------------------------------------------------
def full(core):
    return (R,) + tuple(core) + (A, P, Z)


check_orders = ((C, E), (E, C))

conservative_cores = {
    (C, E, S),
    (E, C, S),
    (C, E),
    (E, C),
    (C, S, E),
    (C, E, S, X),
    (E, C, X, S),
}

balanced_cores = set()
for h in check_orders:
    balanced_cores.update({
        h,                  # no S, no X
        h + (X,),           # no S, X
        h + (S,),           # late S, no X
        h + (X, S),         # X before late S
        h + (S, X),         # X after late S
    })

balanced_cores.update({
    (C, S, E),
    (C, S, E, X),
    (E, S, C),
    (E, S, C, X),
})

permissive_cores = set(balanced_cores)
for h in check_orders:
    permissive_cores.add((S,) + h)
    permissive_cores.add((S,) + h + (X,))

intended = {
    "model_conservative": {full(w) for w in conservative_cores},
    "model_balanced": {full(w) for w in balanced_cores},
    "model_permissive": {full(w) for w in permissive_cores},
}

assert len(conservative_cores) == 7
assert len(balanced_cores) == 14
assert len(permissive_cores) == 18

assert intended["model_conservative"] == {
    word for _, word in variant_rows
}
assert (
    intended["model_conservative"]
    < intended["model_balanced"]
    < intended["model_permissive"]
)


# -----------------------------
# 2–3. Convert and check soundness
# -----------------------------
artifacts = {}

for name, model in candidates.items():
    net, im, fm = pm4py.convert_to_petri_net(model)
    artifacts[name] = (net, im, fm)

    print("\nSOUNDNESS:", name)
    soundness_result = pm4py.check_soundness(
        net, im, fm, print_diagnostics=True
    )
    print("result:", soundness_result)


# -----------------------------
# 4. Available quality metrics
# -----------------------------
def available(call):
    try:
        return call()
    except Exception as exc:
        return "UNAVAILABLE: {}: {}".format(type(exc).__name__, exc)


metrics = {}

for name, (net, im, fm) in artifacts.items():
    metrics[name] = {
        "fitness_alignments": available(
            lambda: pm4py.fitness_alignments(log, net, im, fm)
        ),
        "precision_alignments": available(
            lambda: pm4py.precision_alignments(log, net, im, fm)
        ),
        "generalization_tbr": available(
            lambda: pm4py.generalization_tbr(log, net, im, fm)
        ),
        "simplicity": available(
            lambda: pm4py.simplicity_petri_net(net, im, fm)
        ),
    }

for name, values in metrics.items():
    print("\nMETRICS:", name)
    for metric_name, value in values.items():
        print(" ", metric_name, "=", value)


# -----------------------------
# 5. Sampled playout
# -----------------------------
for name, (net, im, fm) in artifacts.items():
    try:
        simulated = pm4py.play_out(
            net, im, fm,
            parameters={"num_traces": 200},
        )
    except Exception as net_error:
        # Fallback for PM4Py versions with model-specific playout dispatch.
        try:
            simulated = pm4py.play_out(
                candidates[name],
                parameters={"num_traces": 200},
            )
        except Exception as model_error:
            print(
                "\nPLAYOUT UNAVAILABLE:", name,
                "| net:", repr(net_error),
                "| model:", repr(model_error),
            )
            continue

    seen = set()
    for case in simulated:
        word = log_word(case)
        seen.add(word)

        # Detects sampled output outside the intended design language.
        assert word in intended[name], (
            "Unexpected playout word", name, word
        )

    print(
        "\nPLAYOUT:", name,
        "| simulated cases:", len(simulated),
        "| unique visible words:", len(seen),
        "| intended language size:", len(intended[name]),
    )
    # Deliberately no assertion that seen == intended[name]:
    # sampled playout need not cover the language.


# -----------------------------
# 6. Manual positive/negative suite
# -----------------------------
model_names = tuple(candidates.keys())


def expectations(conservative, balanced, permissive):
    return dict(zip(
        model_names,
        (conservative, balanced, permissive),
    ))


suite = [
    (
        "observed V5",
        full((C, S, E)),
        expectations(True, True, True),
    ),
    (
        "observed V7",
        full((E, C, X, S)),
        expectations(True, True, True),
    ),
    (
        "balanced symmetric early S",
        full((E, S, C)),
        expectations(False, True, True),
    ),
    (
        "balanced no-S with X",
        full((C, E, X)),
        expectations(False, True, True),
    ),
    (
        "permissive supplier first",
        full((S, C, E)),
        expectations(False, False, True),
    ),
    (
        "X before engineering completion",
        full((C, X, E, S)),
        expectations(False, False, False),
    ),
    (
        "approval without engineering",
        full((C,)),
        expectations(False, False, False),
    ),
    (
        "duplicate supplier confirmation",
        full((C, E, S, S)),
        expectations(False, False, False),
    ),
    (
        "release before approval",
        (R, C, E, S, P, A, Z),
        expectations(False, False, False),
    ),
]


def one_case_log(word, case_name):
    result = EventLog()
    case = Trace()
    case.attributes["concept:name"] = case_name

    for activity in word:
        event = Event()
        event["concept:name"] = activity
        case.append(event)

    result.append(case)
    return result


for test_name, word, expected in suite:
    for name, (net, im, fm) in artifacts.items():
        # First check the test expectation against the finite design oracle.
        assert ((word in intended[name]) == expected[name]), (
            "Suite/oracle disagreement", test_name, name
        )

        # Then test the actual converted Petri net using alignment fitness.
        single_log = one_case_log(word, test_name)
        alignment_result = pm4py.fitness_alignments(
            single_log, net, im, fm
        )
        fitness_value = float(alignment_result["fitness"])

        accepted = math.isclose(
            fitness_value, 1.0,
            rel_tol=0.0, abs_tol=1e-9,
        )

        assert accepted == expected[name], (
            "Model suite failure",
            test_name,
            name,
            "expected", expected[name],
            "fitness", fitness_value,
            "word", word,
        )

    print("SUITE OK:", test_name)

print(
    "\nAll executed suite checks passed. "
    "Sampled playout coverage is diagnostic only."
)
```

These candidates are acyclic, so their intended visible languages are finite. Nevertheless, the script does **not** use PM4Py to prove Petri-net language inclusion: the subset assertion concerns the analytically constructed design oracle, and sampled playout proves neither inclusion nor exhaustive coverage. For loop-containing candidates with infinite languages, sampled playout and trace metrics could not exhaustively compare their languages; a formal bounded analysis would also need an explicit bound.

# 9. Recommendation and Data-Collection Plan

**Immediate use:** use `model_balanced` as the interim descriptive and conformance hypothesis, while keeping D1–D3 and the X dependency as separately explainable checks. It preserves all observed behavior, handles important missing-S manifestations, and makes its generalizations inspectable. It should not automatically approve orders or certify supplier compliance.

**Sensitivity analysis:** use `model_permissive` to test how conclusions change when the weakest D5 interpretation is relaxed. In particular, compare audit outcomes with and without the four supplier-first core words. Retain `model_conservative` as a useful observed-language regression baseline, but not as the recommended operational generalization.

A concrete uncertainty-reduction plan is:

1. **Export sourcing and requirement attributes.**
   - External/stocked status at component level.
   - An order-level `supplier_confirmation_required` flag derived from those components.
   - Order/product type, component count, expedite-required flag, and relevant policy version.
   - Supplier-confirmation identifiers so multiple component confirmations can be distinguished from repeated logging.

2. **Collect lifecycle rather than only completion events.**
   - Start, complete, suspend/resume where applicable, and cancellation timestamps for C, E, S, and X.
   - Original event timestamp, ingestion timestamp, ingestion index, activity-instance ID, case ID, and source-system event ID.
   - Higher timestamp precision and explicit timezone/synchronization information.

3. **Audit the no-S cases instead of imputing them silently.**
   Reconcile each case with procurement and integration records, classifying it as:
   - confirmed stocked legitimate skip;
   - external, confirmation performed but event missing;
   - external, confirmation genuinely absent before approval, hence a possible violation;
   - unresolved.
   
   Also audit a sample of cases with recorded S to estimate the integration error mechanism rather than assuming missingness is random.

4. **Resolve S1 versus S2 by scope and policy, not by discovery metrics.**
   Determine whether C-before-E is a universal compliance rule, a finance-only preference, or a rule limited to particular order types and dates. Evaluate it using C completion and E start timestamps where possible.

5. **Use complete, classified cases for comparative validation.**
   Discover on a training period and evaluate on a later holdout, stratified by sourcing and expediting. Repeat with:
   - S1 as a hard CE sequence versus S2-style unordered checks;
   - strict balanced D5 versus permissive independent S;
   - confirmed legitimate skips only versus observation-level no-S paths;
   - repaired versus unrepaired supplier logs.

The most informative future observations are:

| New observation, with known validity and complete lifecycle data | Main ambiguity resolved |
|---|---|
| C and E with strictly non-overlapping lifecycles, plus cases with genuinely overlapping lifecycles | Distinguishes sequential execution from possible concurrency. Completion-only C-E/E-C words cannot distinguish XOR-of-sequences from concurrency. |
| Context attributes showing that CE and EC belong to distinct order types | Supports a context-dependent XOR of sequences rather than one generally concurrent construct. |
| Verified valid E-S-C, together with additional C-S-E cases | Tests the balanced symmetry generalization and the “either check can trigger S” interpretation. |
| Verified valid S-C-E or S-E-C with reliable start/complete timestamps | Tests whether balanced underfits start/completion semantics or whether permissive supplier-first behavior is genuinely needed. |
| Confirmed stocked, completely logged C-E-X or E-C-X with no S | Supports true no-S/X optionality rather than a missing-data explanation. |
| External case with no logged S but a sourced procurement confirmation timestamp | Directly confirms missing logging; the no-S path should then be treated as observation repair, not legitimate process optionality. |
| External case with genuinely no S before A | A negative compliance example, not evidence that S should become optional. |
| Verified C-E-X-S and E-C-S-X | Tests whether the rare X placements can be recombined independently of check order, as balanced assumes. |
| Raw high-precision timestamps for same-time C/E or C/S/E events | Tests whether apparent variants are ingestion-index artifacts. |

Observing a new word alone is insufficient: it must also be known whether the case was compliant and whether its log was complete. Otherwise, process discovery can learn violations or integration defects as legitimate behavior.

# 10. Uncertainty Statement

| Modeling decision | Calibrated confidence | Reason and principal residual uncertainty |
|---|---|---|
| R start, Z end, and A before P | **Very high, within the observed process scope** | Supported by D1/D2 and all observed traces; only undocumented process exceptions would materially weaken it. |
| Both C and E before A, each once | **High** | Supported by D3 and 30/30 traces. Scope exceptions and unobserved lifecycle behavior remain possible. |
| Unordered C/E as a completion-language generalization | **Medium** | Both orders and S2 support it, but S1 conflicts. It is substantially weaker than claiming actual concurrency. |
| Actual C/E concurrency or overlap | **Low** | Completion timestamps cannot establish it. XOR-of-sequences remains fully compatible with the visible evidence. |
| Balanced’s “at least one check completion before S” rule | **Medium-low to medium** | V5 and D5 support flexibility, but D5 refers to starting S and does not precisely define a completion-level OR dependency. |
| No-S as genuine optionality in any particular case | **Low** | Sourcing is absent and S missingness is unresolved. Confidence is high only that the current silent path conflates hypotheses. |
| X optional, at most once, after both checks and before A | **Medium-high** | D6 and S6 agree and V6/V7 are consistent. Only two cases limit conclusions about frequency and context. |
| X may be recombined before/after S across check orders and no-S contexts | **Medium** | S6 supports relative freedom, but several resulting combinations are unobserved. |
| Permissive supplier-first behavior | **Low as a descriptive claim; useful only as a sensitivity hypothesis** | It depends on relaxing the least confident ordering rule and has no direct variant support. |
| Recommendation of balanced for interim use | **Medium and conditional** | It is the best-targeted hypothesis under S2/D5, but that recommendation does not extend to supplier-compliance certification. |

One materially different interpretation is that **S1 is a hard, universal compliance rule and the E-first variants are violations or defective timestamps**. In that case, unordered C/E is not an acceptable generalization; even the conservative model is merely fitting violations. The recommendation would shift to a normative C-before-E model built from a cleansed and scoped log, with observed deviations handled separately.

A second material alternative is that **all or nearly all no-S cases concern external orders**. If S actually occurred, the problem is log repair; if it did not, the approvals may be violations. In either situation, treating no-S as ordinary process optionality would be unsafe, and the balanced model should not be used for supplier conformance until the cases are classified.
