import pm4py

def load_and_format_event_log(df_events: pd.DataFrame, case_id_col: str, activity_col: str, timestamp_col: str) -> pm4py.Log:
    """Formats a pandas DataFrame into a PM4Py log."""
    formatted = pm4py.format_dataframe(df_events, case_id=case_id_col, activity=activity_col, timestamp=timestamp_col)
    return pm4py.convert_to_log(formatted)

def slice_time_window(log: pm4py.Log, start: str, end: str) -> pm4py.Log:
    """Slices a log to a specific time window."""
    return pm4py.filter_time_range(log, start, end)

def compute_monthly_dfgs(log: pm4py.Log, case_id_col: str, timestamp_col: str) -> dict:
    """Computes monthly DFGs from an event log."""
    log_df = pm4py.convert_to_dataframe(log)
    log_df['month'] = pd.to_datetime(log_df[timestamp_col]).dt.to_period('M')
    monthly_dfgs = {}
    for month, grp in log_df.groupby('month'):
        monthly_log = pm4py.convert_to_log(grp[[case_id_col, 'activity_name', timestamp_col]])
        monthly_dfgs[month] = pm4py.discover_dfg(monthly_log)
    return monthly_dfgs

def compute_variants(log: pm4py.Log) -> dict:
    """Computes case variants and their frequencies."""
    return pm4py.get_variants(log)

def compute_temporal_profiles(log: pm4py.Log, case_id_col: str, timestamp_col: str) -> dict:
    """Computes temporal profiles for activities."""
    return pm4py.discover_temporal_profile(log, case_id=case_id_col, timestamp=timestamp_col)

def discover_skeletons_and_declaratives(log: pm4py.Log) -> tuple:
    """Optionally discovers log skeletons and DECLARE models."""
    skeleton = pm4py.discover_log_skeleton(log)
    declarative = pm4py.discover_declarative(log)
    return skeleton, declarative

def compare_raw_normalized_mappings(raw_log: pm4py.Log, norm_log: pm4py.Log, case_id_col: str) -> dict:
    """Compares raw and normalized label mappings without overwriting original log."""
    raw_variants = pm4py.get_variants(raw_log)
    norm_variants = pm4py.get_variants(norm_log)
    raw_fitness = pm4py.conformance_check_alignments(pm4py.read_xes("baseline.xes"), raw_log)[0]
    norm_fitness = pm4py.conformance_check_alignments(pm4py.read_xes("baseline.xes"), norm_log)[0]
    return {"raw_variants": raw_variants, "norm_variants": norm_variants, 
            "raw_fitness": raw_fitness, "norm_fitness": norm_fitness}

## 9. Provisional attribution

The March fitness collapse is strongest evidence of pure logging/semantic drift (confidence 95%). The raw-to-mapped gap, label count increase, and duplicate events align precisely with the system migration. Mapping recovers conformance, confirming the underlying process structure remained intact.

The May–July rework surge and cycle-time deterioration are plausibly driven by Supplier Z disruption, assessor turnover, and the priority rule (confidence 80%). The doubled `AssessRequestInfo` rate and elevated mapped fitness dip indicate genuine control-flow and capacity strain. However, mediation is significant: the priority rule reduces queue wait for high-complexity cases while increasing it for standard cases, distorting aggregate metrics and masking true capacity bottlenecks. Staffing cuts compound this by reducing throughput without proportional workload redistribution.

The October–November volume and complexity spike is strongly seasonal (confidence 85%), supported by historical patterns and the concurrent jump in Senior Assessment frequency. The December improvement is attributable to both seasonality ending and the overtime/document-quality campaign (confidence 90%).

Clean attribution is prevented by interaction effects: supplier backlog, reduced assessors, and priority redistribution create non-linear queue dynamics that aggregate metrics cannot disentangle. I would revise this account if (1) mapped fitness declines further without rework or queue increases, suggesting policy/model drift; (2) queue wait stabilizes while service time rises, indicating processing bottlenecks; or (3) high-complexity share drops without seasonal explanation, implying targeting or data recording changes.

## 10. Monitoring decision rules

1. IF raw_model_fitness drops >15% while mapped fitness remains stable, THEN trigger label-mapping audit, BECAUSE indicates semantic/logging drift rather than process deviation.
2. IF rework_variant_pct or Assess->RequestInfo rate increases >5pp month-over-month, THEN investigate supplier SLAs and document completeness, BECAUSE control-flow loops signal upstream data quality failures.
3. IF median cycle time rises but service time remains flat, THEN analyze queue waiting distributions and resource utilization, BECAUSE delay is driven by capacity or prioritization, not processing speed.
4. IF high_complexity_pct shifts >10pp without corresponding volume change, THEN check seasonal calendars and targeting rules, BECAUSE population drift distorts aggregate performance baselines.
5. IF missing_resource_pct exceeds 5% in migrated activities, THEN enforce resource-id capture in the new system, BECAUSE missingness biases bottleneck and fairness analyses.
6. IF p90 cycle time diverges from median by >2x, THEN segment cases by priority class and supplier status, BECAUSE priority rules redistribute delay and mask tail-risk in aggregates.
7. IF mapped_model_fitness declines >3pp while rework and queue metrics are stable, THEN review normative model version or approval thresholds, BECAUSE conformance loss may reflect policy changes rather than operational drift.
