# 1. Executive Verdict

The net is structurally a workflow net: it has one input-free source place, one output-free sink place, and every node lies on a source-to-sink path. It should nevertheless be expected to be unsound.

The principal defect is that `t_join_waived` is not a synchronization: it requires only `p_waived`, not `p_analysis_done`. Consequently, a waiver can produce `p_decision` and enable `t_authorize` before analysis occurs.

The business consequence is twofold. First, a case may be authorized without mandatory analysis. Second, the analysis token remains in `p_analysis` or later `p_analysis_done`, so a marking containing a token in `sink` is reached without reaching the exact final marking `fm = {sink: 1}`.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source -> t_register -> p_ready` | Start and register a case. | A conventional single-entry start fragment. | No defect by itself. |
| `t_split` | Start analysis and review in parallel. | Correct AND-split: one token in `p_ready` becomes one token in each of `p_analysis` and `p_review`. | Both branches are independently enabled after the split. |
| `p_analysis -> t_analyze -> p_analysis_done` | Mandatory analysis branch. | Analysis is structurally required only by `t_join_normal`, not by `t_join_waived`. | On the waiver route, analysis can be skipped before authorization or completed too late. |
| `t_standard_review` | Standard review alternative. | Shares input place `p_review` with `t_waive_review`; therefore the alternatives are in Petri-net conflict and only one can fire per case. | This correctly implements an XOR-like review choice. |
| `t_waive_review` | Formally record a waiver instead of standard review. | Consumes `p_review` and produces `p_waived`. It does not affect the analysis token. | The waiver path leaves the analysis branch independently active. |
| `t_join_normal` | Synchronize completed analysis and completed standard review. | Correct two-input AND-join requiring both `p_analysis_done` and `p_review_done`. | Standard-review cases can reach proper completion. |
| `t_join_waived` | Synchronize analysis with a recorded waiver. | Has only one input, `p_waived`; it is a pass-through transition, not a synchronization. | It can create `p_decision` while analysis remains incomplete. |
| `p_decision -> t_authorize -> sink` | Authorize only after all required work is complete. | Authorization requires only a token in `p_decision`; on the waiver route that token does not imply analysis completion. | `t_authorize` can fire before `t_analyze`. |
| Initial marking `im = {source: 1}` | Start one case. | Correct single-token initial marking. | No defect by itself. |
| Final marking `fm = {sink: 1}` | Indicate complete execution with no remaining work. | Correct strict final-marking definition. A marking such as `{sink: 1, p_analysis: 1}` is not final. | A sink token can be produced without proper completion. |
| Whole net / path coverage | Workflow-net structure. | Every place and transition, including `t_join_waived`, lies on at least one directed path from `source` to `sink`. | The workflow-net structural check may succeed despite behavioral unsoundness. |

# 3. Marking-Based Counterexample

A legal firing sequence exposing the defect is:

```text
t_register,
t_split,
t_waive_review,
t_join_waived,
t_authorize,
t_analyze
```

Using unit-token notation, the resulting markings are:

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---:|---|---|---|---|
| 0 | — | `{source: 1}` | `t_register` | This is `im`. |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | Registration completed. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | The AND-split has created one token in each parallel branch. |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `t_analyze`, `t_join_waived` | The review token was consumed by the waiver, but the analysis token remains. |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, `t_authorize` | `t_join_waived` fires without requiring `p_analysis_done`. |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `t_analyze` | Authorization occurred before analysis. A token exists in `sink`, but this is not `fm`. |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | none | Analysis can occur after authorization, but its completion token is stranded. |

At step 5, `t_authorize` is enabled before `t_analyze` fires. It is also possible to choose the opposite order voluntarily:

```text
t_register,
t_split,
t_waive_review,
t_analyze,
t_join_waived,
t_authorize
```

That alternative ends in:

```text
{p_analysis_done: 1, sink: 1}
```

Thus, performing analysis before authorization does not repair the original net; `t_join_waived` still does not consume `p_analysis_done`.

The leftover `p_analysis_done` token cannot be consumed. Its only outgoing transition is `t_join_normal`, which also requires `p_review_done`. However, `p_review` was already consumed by `t_waive_review`, so `p_review_done` can never be produced in this execution. Therefore the exact final marking `{sink: 1}` is unreachable after taking the waiver route.

By contrast, the standard-review route can complete properly:

```text
t_register, t_split, t_analyze, t_standard_review,
t_join_normal, t_authorize
```

# 4. Minimal-Repair Alternatives

The edit-cost model used here is:

- add or delete one arc: cost 1;
- add or delete one place: cost 1;
- add or delete one transition: cost 1;
- changing an arc endpoint counts as one deletion plus one addition: cost 2;
- `im` and `fm` are fixed interface requirements and are not changed.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| A. Proper waiver synchronization | Add arc `p_analysis_done -> t_join_waived`. | 1 | Fully preserves the stated policy: analysis remains mandatory for both standard review and waiver. The review alternatives remain distinct. | `t_join_waived` becomes a real two-input AND-join. Authorization on the waiver path waits for both analysis and waiver. | Two silent joins now feed `p_decision`; this is correct, but may be less obvious to future maintainers or process-mining users. |
| B. Explicit policy change: waiver cancels unstarted analysis | Add arc `p_analysis -> t_waive_review`. | 1 | Preserves clean completion, the review choice, and mandatory analysis for the standard-review route. | Changes policy: a waiver consumes the analysis token, so analysis is optional on the waiver route. The waiver must occur before `t_analyze`; otherwise the waiver is no longer enabled. | The waiver now silently bypasses analysis. Scheduling becomes semantically important, and this may be unacceptable without explicit business approval. |

Repair A is globally minimal under the original business policy. At least one structural edit is necessary because the original net permits an invalid waiver execution. Adding one input arc from `p_analysis_done` to `t_join_waived` is sufficient and directly expresses the missing prerequisite.

Repair B is also minimal under its explicitly amended policy. Again, zero edits cannot remove the stranded analysis token. One added input arc causes `t_waive_review` to consume both the review and analysis tokens, allowing waiver cases to reach `fm` without performing analysis.

The repairs tie at cost 1, but they are behaviorally distinct: Repair A enforces mandatory analysis, whereas Repair B formally permits a waiver to bypass it.

# 5. Corrected PM4Py Code

The following implements Repair A, which preserves mandatory analysis on both review outcomes.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for place in [
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
]:
    repaired_net.places.add(place)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition(
    "t_standard_review", "Perform Standard Review"
)
waive_review = PetriNet.Transition(
    "t_waive_review", "Record Review Waiver"
)
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for transition in [
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
]:
    repaired_net.transitions.add(transition)

petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

# Repair: the waiver route must also wait for completed analysis.
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1

repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def marking_as_text(marking):
    items = sorted(
        ((place.name, tokens) for place, tokens in marking.items() if tokens > 0),
        key=lambda item: item[0]
    )
    return "{" + ", ".join(f"{name}: {tokens}" for name, tokens in items) + "}"


def transition_names(transitions):
    return sorted(transition.name for transition in transitions)


def fire_named_transition(petri_net, marking, transition_name):
    matching = [
        transition
        for transition in petri_net.transitions
        if transition.name == transition_name
    ]

    if len(matching) != 1:
        raise ValueError(
            f"Expected exactly one transition named {transition_name!r}; "
            f"found {len(matching)}."
        )

    transition = matching[0]
    enabled = pm4py.get_enabled_transitions(petri_net, marking)

    if transition not in enabled:
        raise RuntimeError(
            f"Transition {transition_name!r} is not enabled at "
            f"{marking_as_text(marking)}. Enabled transitions: "
            f"{transition_names(enabled)}"
        )

    next_marking = Marking()
    for place, tokens in marking.items():
        if tokens > 0:
            next_marking[place] = tokens

    for arc in transition.in_arcs:
        place = arc.source
        remaining = next_marking.get(place, 0) - arc.weight
        if remaining < 0:
            raise RuntimeError("Enabledness inconsistency while firing transition.")
        if remaining == 0:
            next_marking.pop(place, None)
        else:
            next_marking[place] = remaining

    for arc in transition.out_arcs:
        place = arc.target
        next_marking[place] = next_marking.get(place, 0) + arc.weight

    enabled_after = pm4py.get_enabled_transitions(petri_net, next_marking)
    print(
        f"Fired {transition_name}; marking={marking_as_text(next_marking)}; "
        f"enabled={transition_names(enabled_after)}"
    )
    return next_marking


for model_name, model_net, model_im, model_fm in [
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
]:
    print(f"\n--- {model_name.upper()} NET ---")
    print("workflow net:", pm4py.check_is_workflow_net(model_net))
    print(
        "soundness result:",
        pm4py.check_soundness(
            model_net,
            model_im,
            model_fm,
            print_diagnostics=True
        )
    )
    print(
        "enabled at initial marking:",
        transition_names(pm4py.get_enabled_transitions(model_net, model_im))
    )

    reachability_graph = pm4py.convert_to_reachability_graph(
        model_net,
        model_im,
        model_fm
    )
    print("reachability graph object:", type(reachability_graph).__name__)


print("\n--- ORIGINAL WAIVER COUNTEREXAMPLE ---")
counterexample_marking = im
print("Initial marking:", marking_as_text(counterexample_marking))

for name in [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_join_waived",
    "t_authorize",
    "t_analyze",
]:
    counterexample_marking = fire_named_transition(
        net,
        counterexample_marking,
        name
    )

print("Reached exact original final marking:", counterexample_marking == fm)


print("\n--- REPAIRED WAIVER COMPLETION TRACE ---")
repaired_marking = repaired_im
print("Initial marking:", marking_as_text(repaired_marking))

for name in [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_analyze",
    "t_join_waived",
    "t_authorize",
]:
    repaired_marking = fire_named_transition(
        repaired_net,
        repaired_marking,
        name
    )

print("Reached exact repaired final marking:", repaired_marking == repaired_fm)
```

Qualitatively, both nets should pass the structural workflow-net check. The original net’s soundness diagnostics should identify that proper completion is not guaranteed on the waiver route, because a sink token can coexist with an unconsumable analysis token. The repaired net should have proper waiver completion and should be sound under the ordinary workflow-net soundness criteria. No exact diagnostic keys or state-space counts should be assumed without running the installed PM4Py version.

# 7. Repair Trade-Offs and Residual Risks

Repair A keeps standard review and recorded waiver distinguishable. They retain separate visible transitions, separate outcome places (`p_review_done` and `p_waived`), and separate silent synchronization transitions.

The repaired model has two silent joins that both produce `p_decision`. This does not create duplicate business behavior because `t_standard_review` and `t_waive_review` compete for the single token in `p_review`; both review outcomes cannot occur in one case. However, silent transitions can make diagrams, event-log interpretation, and future model maintenance less obvious.

Soundness is necessary but not sufficient evidence of business alignment. Soundness establishes structural completion properties, not whether “Perform Analysis” represents the legally required analysis, whether waivers are authorized, or whether the visible labels are interpreted correctly by users.

Regression testing should include these positive complete traces:

- Standard review: `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize`.
- Standard review in the opposite branch order.
- Waiver after analysis: `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`.
- Waiver recorded before analysis completes: `t_register, t_split, t_waive_review, t_analyze, t_join_waived, t_authorize`.

Negative tests should confirm that:

- `t_join_waived` and `t_authorize` cannot fire after a waiver without `t_analyze`;
- authorization cannot follow analysis alone;
- authorization cannot follow review alone;
- standard review and waiver cannot both occur in the same case;
- no accepting execution ends with tokens outside `sink`.

An accidental bypass of mandatory analysis can be detected by reachability analysis augmented with a history flag indicating whether `t_analyze` fired. No reachable state should enable `t_authorize` while that flag is false. Structurally, each transition producing `p_decision` should also require `p_analysis_done`.

# 8. Final Recommendation

Deploy Repair A: add `p_analysis_done -> t_join_waived`.

It is the smallest possible repair under the stated business policy, preserves mandatory analysis, preserves the standard-review-versus-waiver distinction, and restores proper completion for waiver cases. It directly expresses the intended authorization rule: analysis plus exactly one review outcome must complete before authorization.

Keep Repair B as a fallback only if policy owners explicitly decide that a recorded waiver may cancel or bypass analysis. Repair B is equally small structurally, but it is not a neutral technical correction: it changes the business rule and introduces an ordering dependency between analysis and waiver recording. That dependency makes it unsuitable as a default repair where analysis is stated to be mandatory.
