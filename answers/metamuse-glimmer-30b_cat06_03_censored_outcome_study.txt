## 1. Target definition

**Primary target – conditional 90-day default given eventual activation**
* Prediction time `t0`: end of the prefix, e.g. completion of *Identity/KYC Check* or a fixed event count k=3, `t0  time of Credit Review decision`.
* Horizon: 90 days after the *Account Activated* event.
* Unit of analysis: one case = one credit application.
* Population: applications started 2024-01-01 to 2025-12-31.
* Estimand: 
`P( Default_90d = 1 | H_{t0},  Activation eventually occurs )`
where `H_{t0}` is the event history up to `t0`. The model is trained and evaluated only on cases that are eventually activated and whose label is mature by extraction. The target is operational because default is only defined after activation and we never impute a default for rejected/withdrawn cases.

**Credible alternative – multi-state competing outcome for all applications**
State at 180 days after start: `Rejected`, `Withdrawn`, `Transferred`, `Still open / censored`, `Activated & Default 90d`, `Activated & Non-default`. 
This answers “what will happen to the application” not “will it default if activated”. It requires no counterfactual but changes the business question from risk scoring to funnel forecasting.

## 2. Cohort construction

As-of date = 2026-02-15, label maturity requires `label_available_at  as-of` or `activation + 90d + 35d  as-of`.

Inclusion: `case_start` in [2024-01-01, 2025-12-31], prefix end `t0` before decision.
Exclusion for primary analysis: cases never activated or activated but label not mature.

Cohort flow

| Activated | 25,200 | |

For time-based splits, training requires case start early enough for label maturity: `case_start  2025-04-30` gives  90+35 days to maturity by 2026-02-15.

## 3. Censoring and missing-label strategy

* Ordinary right censoring: still open applications, no terminal event by extraction.
* Delayed labels: activated accounts with `activation + 90d` after extraction or external feed arriving 7-35 days later  label not yet known.
* Selection through activation: default is undefined for rejected/withdrawn/transferred. This is selection, not censoring.
* Transfer as competing event or missing follow-up: 60% linkage; remainder permanently missing.
* Permanently missing outcome feeds: partner-originated activated accounts with elevated missingness.

Primary analysis: restrict to activated & mature labelled cases, landmark at `t0`, require `label_available_at  as-of`. Report conditional performance and explicitly state selection conditioning.

Sensitivity analyses:
1. IPCW for activation selection using propensity for activation given `H_{t0}` and static attributes, to estimate unconditional risk `P(Default & Activation | H_{t0})`.
2. Competing-risk multi-state model on all 48k cases with states above, treating transfer/missing feed as competing and censored.
3. Landmark survival analysis for time-to-default after activation with right censoring for delayed labels.

Testable: covariate balance between mature vs delayed labels, association of censoring with observed history. Fundamentally untestable: counterfactual default risk under a different activation policy and missingness mechanism for partner feeds.

## 4. Prefix extraction

* Fixed event-count prefixes: k = 2,3,5 events from start. Short cases < k use full trace and are flagged.
* Elapsed-time prefixes: 24h, 72h, 7d after `case_start`. Prefix ends at last event with `time:timestamp  t0`.
* As-of rule: prefix is built from events only with `time:timestamp  t0`. No future events, no post-decision activities.
* Rework loops: count returns to *Credit Review*, number of document requests, loop length. Use prefix DFG and variant.
* Activity renaming from 2025-10-15 migration: apply canonical mapping before prefix creation; log variants separately per period.
* `documents_total` nightly snapshot: use value as of `t0` date, cap at `t0` timestamp to avoid same-day leakage.

## 5. Process-aware features

* Resource/queue: distinct resources in prefix, mean historical case handling time for those resources computed from training period only.

## 7. Validation design

Temporal validation by case start time, not random split.

* Train: start < 2025-04-01
* Validation: 2025-04-01 to 2025-06-30
* Test: 2025-07-01 to 2025-10-31   covers policy change 2025-07-01
* Hold-out: 2025-11-01 to 2025-12-31   covers migration 2025-10-15

Random split is misleading because it mixes pre/post policy and migration periods and leaks future information.

Metrics for conditional target: AUROC, AUPRC, Brier score, calibration slope/intercept, and expected calibration error per policy period, region, channel. Report performance stratified by prefix length and by time since start.

Label maturity handled by requiring mature labels in each fold; delayed labels are excluded from that fold.

## 8. Limitations and decision-use boundary

The study can claim association between early process history and default risk conditional on activation under the historical activation policy. It cannot claim counterfactual default risk for rejected/withdrawn applications without strong untestable assumptions.

Deployment can change the data generating process:
1. Model-informed decisions change activation thresholds  selection shift and covariate shift.
2. Applicants react to earlier interventions  process timing changes.
3. Feedback loop where predicted high risk leads to more document requests  feature distribution drift.

Do not use model outputs to label rejected cases as non-default.

```python
import pandas as pd
from pm4py.objects.log.util import dataframe_utils
from pm4py import format_dataframe, get_prefixes_from_log, discover_dfg, get_variants, extract_temporal_features_dataframe

# 1. Load and parse
df = pd.read_csv('applications_events.csv', parse_dates=['time:timestamp','label_available_at','data_extract_time'])
# canonical activity mapping for migration 2025-10-15
rename_map = {'KYC Check v2':'Identity/KYC Check', 'Credit Review New':'Credit Review'}
df['concept:name'] = df['concept:name'].replace(rename_map)

log = format_dataframe(df, case_id='case:concept:name', activity_key='concept:name', timestamp_key='time:timestamp')
dataframe_utils.convert_timestamp_columns_in_df(log)

as_of = pd.Timestamp('2026-02-15')

# 2. Case level as-of information
case_agg = df.groupby('case:concept:name').agg(
    case_start=('time:timestamp','min'),
    case_end=('time:timestamp','max'),
    activation_time=('time:timestamp', lambda x: df.loc[x.index, 'concept:name'].eq('Account Activated').idxmax() if any(df.loc[x.index, 'concept:name']=='Account Activated') else pd.NaT),
).reset_index()
# simplify activation detection
act = df[df['concept:name']=='Account Activated'][['case:concept:name','time:timestamp']].rename(columns={'time:timestamp':'activation_time'})
case_agg = case_agg.merge(act, on='case:concept:name', how='left')

case_agg['label_mature'] = df.groupby('case:concept:name')['label_available_at'].max() <= as_of
case_agg['activated'] = case_agg['activation_time'].notna()

# cohort counts
print('Total', len(case_agg))
print('Activated mature', ((case_agg['activated']) & (case_agg['label_mature'])).sum())

# 3. Temporal split by case start
case_agg['split'] = 'holdout'
case_agg.loc[case_agg['case_start'] < pd.Timestamp('2025-04-01'), 'split'] = 'train'
case_agg.loc[(case_agg['case_start'] >= pd.Timestamp('2025-04-01')) & (case_agg['case_start'] < pd.Timestamp('2025-07-01')), 'split'] = 'val'
case_agg.loc[(case_agg['case_start'] >= pd.Timestamp('2025-07-01')) & (case_agg['case_start'] < pd.Timestamp('2025-11-01')), 'split'] = 'test'

# 4. Prefixes for primary conditional cohort
primary_cases = case_agg[(case_agg['activated']) & (case_agg['label_mature'])]['case:concept:name']
log_primary = log[log['case:concept:name'].isin(primary_cases)]

log_train = log_primary[log_primary['case:concept:name'].isin(case_agg[case_agg['split']=='train']['case:concept:name'])]

# fixed length prefixes, max_length=5
prefixes = get_prefixes_from_log(log_train, parameters={'max_length':5, 'case_id_key':'case:concept:name'})

# 5. Leakage audit checks
forbidden = ['final_limit','decision_reason','collection_status']
leak = [c for c in forbidden if c in df.columns]
print('Forbidden columns present:', leak)

# 6. Process features example
# DFG and variants for audit
dfg = discover_dfg(log_train)
variants = get_variants(log_train)

# Temporal features, as-of prefix only
# extract_temporal_features_dataframe requires event log, use with caution to avoid future leakage
# features are built per prefix in prefixes

print('Variants count', len(variants))
print('Cohort flow done. Connect survival/competing-risk modeling downstream.')
```
