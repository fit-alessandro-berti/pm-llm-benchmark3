```
def bounded_visible_traces(net, im, fm, max_visible=12, max_analyze=3, max_silent_steps=200):
    pre, post, label_to_trans = build_net_tables(net)
    silent = {'tau', '', 'skip', ''}
    analyze = 'Analyze Revision'
    fm_key = mark_key(fm)
    start = {p: tok for p, tok in im.items() if tok != 0}
    queue = deque([(start, 0, 0, (), 0)])
    seen = {}
    traces = set()
    while queue:
        marking, vlen, acount, tr, silent_steps = queue.popleft()
        key = (mark_key(marking), vlen, acount, tr)
        prev = seen.get(key)
        if prev is not None and prev <= silent_steps:
            continue
        seen[key] = silent_steps
        if key[0] == fm_key:
            traces.add(tr)
            continue
        enabled = pm4py.get_enabled_transitions(net, marking)
        for e in enabled:
            if e in pre:
                candidates = [e]
            else:
                candidates = label_to_trans.get(str(e), [])
            for t in candidates:
                nm = fire_transition_obj(pre, post, marking, t)
                if nm is None: continue
                lbl = transition_label(t)
                is_silent = lbl in silent
                nv = vlen + (0 if is_silent else 1)
                na = acount + (1 if lbl == analyze else 0)
                ns = silent_steps + (1 if is_silent else 0)
                if nv > max_visible or na > max_analyze or ns > max_silent_steps:
                    continue
                ntr = tr + (() if is_silent else (lbl,))
                queue.append((nm, nv, na, ntr, ns))
    return traces
```

```
def bounded_visible_traces(net, im, fm, max_visible=12, max_analyze=3, max_silent_steps=200):
    pre, post, label_to_trans = build_net_tables(net)
    silent_labels = {'tau', '', 'skip', ''}
    analyze_label = 'Analyze Revision'
    fm_key = mark_key(fm)
    start = {p: tok for p, tok in im.items() if tok != 0}
    queue = deque([(start, 0, 0, (), 0)])
    seen = {}
    traces = set()
    while queue:
        marking, vlen, acount, tr, silent_steps = queue.popleft()
        mk = mark_key(marking)
        state_key = (mk, vlen, acount, tr)
        old_silent = seen.get(state_key)
        if old_silent is not None and old_silent <= silent_steps:
            continue
        seen[state_key] = silent_steps
        if mk == fm_key:
            traces.add(tr)
            continue
        enabled = pm4py.get_enabled_transitions(net, marking)
        for e in enabled:
            if e in pre:
                candidates = [e]
            else:
                candidates = label_to_trans.get(str(e), [])
            for t in candidates:
                nm = fire_transition_obj(pre, post, marking, t)
                if nm is None:
                    continue
                lbl = transition_label(t)
                silent = lbl in silent_labels
                nv = vlen + (0 if silent else 1)
                na = acount + (1 if lbl == analyze_label else 0)
                ns = silent_steps + (1 if silent else 0)
                if nv > max_visible or na > max_analyze or ns > max_silent_steps:
                    continue
                ntr = tr + (() if silent else (lbl,))
                queue.append((nm, nv, na, ntr, ns))
    return traces
```

I use these abbreviations:

```text
O  = Open Case
A  = Analyze Revision
K  = Check Revision
R  = Rework Case
Ap = Approve Revision
Cl = Close Case
  = tau / silent event
```

The visible alphabet is:

```text
v = {Open Case, Analyze Revision, Check Revision, Rework Case, Approve Revision, Close Case}
```

Silent `` is hidden. The exclusive choice `X('Approve Revision', )` means that, at that point, either a visible `Ap` occurs or nothing visible occurs.

## Visible trace equivalence after hiding `tau`

For a model `M`, let `Lvis(M)` be the set of finite visible sequences generated by executions from the initial state to the final state after deleting all silent `` events.

Formally:

```text
Lvis(M) = { _(w) | w is a complete execution trace of M }
```

where `_` removes silent events.

Two models are visible-trace equivalent iff:

```text
Lvis(A) = Lvis(B)
```

Duplicate visible labels are distinguished by **occurrence position in the trace**. For example, in the trace:

```text
O A K R A K Cl
```

the two `A` events are distinct occurrences at positions 2 and 5, and the two `K` events are distinct occurrences at positions 3 and 6. They are not distinguished by event identity, only by their position in the sequence.

## Bounded visible-language equivalence under P3

P3 compares only complete visible traces satisfying:

```text
visible length  12
number of Analyze Revision occurrences  3
```

Define:

```text
Lvis(M) = { w  Lvis(M) | |w|  12 and count_A(w)  3 }
```

Bounded visible-language equivalence under P3 is:

```text
Lvis(A) = Lvis(B)
```

This is a **bounded** equivalence. It is evidence about the models, but it is not a proof of unbounded trace equivalence.

## Business-relevant equivalence under P1

P1 is an operational compliance view. It requires:

1. `Open Case` is first and `Close Case` is last.
2. Each `Analyze Revision` must be paired with its own `Check Revision` before the next `Rework Case` or before `Close Case`.
3. `Rework Case` separates two analysis attempts.
4. `Approve Revision` is optional, but its number and placement remain visible.
5. Silent behavior is hidden.

A useful formalization is to split a complete trace into loop segments delimited by `R` events:

```text
O  segment1  R  segment2  R  ...  R  segmentn  Cl
```

A trace is P1-compliant if every segment contains one `A` and at least one `K` before the segment ends, with optional `Ap` after the analysis/check pair.

For P1 equivalence, I require both:

```text
Lvis(A) = Lvis(B)
```

and that both models generate only P1-compliant visible behavior. If one model admits non-compliant traces, it is not P1-equivalent to a model that enforces the compliance rule.

## Abstracted dashboard equivalence under P2

P2 is an executive dashboard abstraction. It:

1. Requires `Open Case` first and `Close Case` last.
2. Requires at least one `Analyze Revision` and at least one `Check Revision`.
3. Collapses repeated `Check Revision` occurrences to the Boolean fact: “a check occurred.”
4. Hides `Approve Revision` and all silent behavior.
5. Records the number of `Analyze Revision` occurrences.
6. Records whether any `Rework Case` occurred.
7. Ignores the exact interleaving of `Analyze Revision` and `Check Revision`.

Define the dashboard abstraction:

```text
2(w) = (
  count_A(w),
  count_K(w) > 0,
  count_R(w) > 0
)
```

Only traces with `O` first and `Cl` last are considered. P2 equivalence is:

```text
2(Lvis(A)) = 2(Lvis(B))
```

This is equivalence **only under the stated abstraction**. It does not imply visible trace equivalence.

# 2. Structural Comparison

All statements below assume the intended business semantics where `+` is parallel choice.

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The loop contains `->(+('Analyze Revision', 'Check Revision'), X('Approve Revision', tau))`, then `Rework Case`. | The loop contains only `->('Analyze Revision', X('Approve Revision', tau))`, then `Rework Case`. `Check Revision` is outside the loop, concurrent with the whole loop. | Model A ties one check to each loop iteration. Model B ties one check to the entire revision loop. |
| Minimum `Check Revision` occurrences | 1. The loop body executes at least once and contains `Check Revision`. | 1. The parallel branch contains `Check Revision`, and parallel choice requires both branches. | Both models guarantee at least one check. |
| Maximum `Check Revision` occurrences | Unbounded. One per loop iteration. | Exactly 1. There is only one `Check Revision` leaf outside the loop. | Model B cannot supply a second check for a second analysis attempt. |
| Possible placement of `Check Revision` | Inside the same iteration as its corresponding `Analyze Revision`, concurrent with it, and before the next `Rework Case` or `Close Case`. | Anywhere interleaved with the loop events, but before `Close Case` because of the parallel join. | Model B allows analyses to occur before, after, or between checks without a per-analysis check. |
| Optional approval occurrences | 0 to unbounded. At most one optional `Approve Revision` after each iteration’s `Analyze`/`Check` pair. | 0 to unbounded. At most one optional `Approve Revision` after each `Analyze Revision` in the loop. | Approvals are visible under P1 and P3, hidden under P2. Their placement can further distinguish interleavings. |
| Concurrency | `Analyze Revision` and `Check Revision` are concurrent inside each iteration. | `Check Revision` is concurrent with the entire revision loop. | Different interleaving languages. Model A has per-iteration concurrency; Model B has process-level concurrency. |
| Join before `Close Case` | Loop exit join: the final iteration body must complete before exiting the loop and closing. | Parallel join: both the single `Check Revision` branch and the loop exit must complete before closing. | Model B waits for one global check before closing, not for a check paired with each analysis. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---:|---:|---|---|
| P1 — operational compliance view | not equivalent | High | Model B admits traces where an `Analyze Revision` has no paired `Check Revision` before the next `Rework Case` or `Close Case`, e.g. `O A R A K Cl`. Model A enforces a check inside every loop iteration. | If P1 were weakened to “at least one check occurred,” the verdict could change, but that is not the stated P1. |
| P2 — executive dashboard view | equivalent only under stated abstraction | High | Under P2, both models collapse to the same dashboard facts: number of `Analyze Revision` occurrences `n  1`, a check occurred, and a rework occurred iff `n  2`. | The abstraction loses check-per-analysis placement. If the dashboard later needs per-analysis checks, the equivalence disappears. |
| P3 — bounded testing view | not equivalent | High | There are complete visible traces within the P3 bound admitted by one model and not the other, e.g. `O A K R A K Cl` for Model A and `O A R A K Cl` for Model B. | Bounded comparison is not a proof of unbounded equivalence, but here the bounded counterexamples already prove non-equivalence. |

**PM4Py notation caveat.** If the literal `+` is parsed as exclusive choice rather than parallel choice, the models no longer match the stated business descriptions. Under exclusive-choice semantics, Model B cannot generate both `Analyze Revision` and `Check Revision` in the same trace, while Model A can; P2 equivalence would also fail. The comparison above uses the business-required parallel interpretation.

# 4. Counterexample Traces

All traces below are complete visible traces. They use the abbreviations defined in Section 1. All are within the P3 bound: visible length  12 and at most three `Analyze Revision` occurrences.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|

## Effect of optional `Approve Revision` and hidden `tau`

The silent `` itself does not appear in visible traces. It only makes `Approve Revision` optional:

```text
X('Approve Revision', tau)
```

means either:

```text
... Ap ...
```

or:

```text
...
```

with no visible approval.

Because P1 and P3 retain visible labels, optional approvals can create additional distinguishing traces. For example:

```text
O A K Ap R A K Cl
```

is admitted by Model A but not by Model B because it contains two checks.

Likewise:

```text
O A Ap R A K Cl
```

is admitted by Model B but not by Model A because the second analysis lacks its own check.

Under P2, approvals and silent behavior are hidden, so they do not affect the P2 verdict. Under P1 and P3, they can strengthen the evidence for non-equivalence but are not needed for the four counterexamples above.

# 5. Bounded Comparison Code

The following code parses both process trees, converts them to accepting Petri nets, checks soundness, and performs an **exhaustive bounded BFS over markings** for P3. It is not a random playout. It explicitly handles silent transitions, repeated markings, visible-length bounds, analysis-count bounds, and final-marking equality.

```python
import re
from collections import deque

import pm4py

# ------------------------------------------------------------------------------
# 0. Parse the task's process trees.
#
# The task uses '+' as parallel choice. Some PM4Py versions use '' for parallel
# choice and '+' for exclusive choice. The following helper rewrites the textual
# '+' to PM4Py's parallel operator when possible.
# ------------------------------------------------------------------------------

try:
    from pm4py.process_tree import ProcessTreeOperator
    PARALLEL = ProcessTreeOperator.PARALLEL_CHOICE.value
except Exception:
    PARALLEL = ""

def to_pm4py_parallel(text: str) -> str:
    # Replace only operator '+' that is followed by '('.
    return re.sub(r"(?<![A-Za-z])\+(?=\s*\()", PARALLEL, text)


TREE_A_TEXT = """
->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
"""

TREE_B_TEXT = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)
"""

tree_a = pm4py.parse_process_tree(to_pm4py_parallel(TREE_A_TEXT))
tree_b = pm4py.parse_process_tree(to_pm4py_parallel(TREE_B_TEXT))

# ------------------------------------------------------------------------------
# 1. Convert to accepting Petri nets.
# ------------------------------------------------------------------------------

net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

# ------------------------------------------------------------------------------
# 2. Soundness check.
# ------------------------------------------------------------------------------

sound_a = pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=False)
sound_b = pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=False)

print("Model A sound:", sound_a)
print("Model B sound:", sound_b)

# ------------------------------------------------------------------------------
# 3. Helpers for exhaustive bounded exploration over markings.
# ------------------------------------------------------------------------------

def transition_label(t) -> str:
    if hasattr(t, "label"):
        lbl = t.label
        if lbl is not None:
            return str(lbl)
    if hasattr(t, "name"):
        return str(t.name)
    return str(t)


def build_net_tables(net):
    """
    Build pre/post tables keyed by transition objects when possible.
    Also build a label -> transitions map for cases where
    pm4py.get_enabled_transitions() returns labels.
    """
    trans_objs = list(net.transitions)
    trans_set = set(trans_objs)

    pre = {t: [] for t in trans_objs}
    post = {t: [] for t in trans_objs}
    label_to_trans = {}

    for t in trans_objs:
        label_to_trans.setdefault(transition_label(t), []).append(t)

    for arc in net.arcs:
        try:
            src, tgt = arc
        except Exception:
            src = getattr(arc, "source", None)
            tgt = getattr(arc, "target", None)

        if src in trans_set:
            post[src].append(tgt)
        if tgt in trans_set:
            pre[tgt].append(src)

    return pre, post, label_to_trans


def normalize_marking(marking):
    return {p: tok for p, tok in marking.items() if tok != 0}


def mark_key(marking):
    """
    Use id(place) to avoid relying on string equality of place objects.
    This is only used inside one Python process.
    """
    return tuple(sorted((id(p), tok) for p, tok in normalize_marking(marking).items()))


def fire_transition_obj(pre, post, marking, t):
    """
    Fire a transition object if enabled. Returns a normalized marking or None.
    """
    new_marking = dict(marking)

    for p in pre.get(t, []):
        if new_marking.get(p, 0) <= 0:
            return None
        new_marking[p] = new_marking.get(p, 0) - 1

    for p in post.get(t, []):
        new_marking[p] = new_marking.get(p, 0) + 1

    return normalize_marking(new_marking)


def bounded_visible_traces(
    net,
    im,
    fm,
    max_visible=12,
    max_analyze=3,
    max_silent_steps=200,
):
    """
    Exhaustive bounded exploration of complete visible traces.

    This is not random playout. It explores all paths up to:
      - visible event length <= max_visible
      - Analyze Revision occurrences <= max_analyze
      - silent steps <= max_silent_steps

    Silent steps are capped to guard against pathological tau cycles.
    For the given process trees, the cap is far above what is needed.
    """
    pre, post, label_to_trans = build_net_tables(net)

    silent_labels = {"tau", "", "skip", ""}
    analyze_label = "Analyze Revision"

    fm_key = mark_key(fm)
    start_marking = normalize_marking(im)

    # State:
    #   marking, visible_length, analyze_count, visible_trace_tuple, silent_steps
    queue = deque([(start_marking, 0, 0, (), 0)])

    # seen[state_key] = minimum silent_steps observed for that key.
    # state_key includes the actual visible trace because different prefixes
    # can lead to the same marking and still produce different complete traces.
    seen = {}
    traces = set()

    while queue:
        marking, vlen, acount, tr, silent_steps = queue.popleft()

        mk = mark_key(marking)
        state_key = (mk, vlen, acount, tr)

        old_silent = seen.get(state_key)
        if old_silent is not None and old_silent <= silent_steps:
            continue
        seen[state_key] = silent_steps

        # Complete trace reached final marking.
        if mk == fm_key:
            traces.add(tr)
            # Do not expand final marking. For sound process-tree nets, final
            # is a sink. If a non-sound net has outgoing transitions from final,
            # this convention records first completion traces.
            continue

        enabled = pm4py.get_enabled_transitions(net, marking)

        for e in enabled:
            # If get_enabled_transitions returns transition objects, use them.
            # If it returns labels, try all transitions with that label and let
            # fire_transition_obj() reject non-enabled candidates.
            if e in pre:
                candidates = [e]
            else:
                candidates = label_to_trans.get(str(e), [])

            for t in candidates:
                nm = fire_transition_obj(pre, post, marking, t)
                if nm is None:
                    continue

                lbl = transition_label(t)
                is_silent = lbl in silent_labels

                nv = vlen + (0 if is_silent else 1)
                na = acount + (1 if lbl == analyze_label else 0)
                ns = silent_steps + (1 if is_silent else 0)

                if nv > max_visible:
                    continue
                if na > max_analyze:
                    continue
                if ns > max_silent_steps:
                    continue

                ntr = tr + (() if is_silent else (lbl,))
                queue.append((nm, nv, na, ntr, ns))

    return traces


def fmt_trace(tr):
    return " ".join(tr)


def print_trace_set(title, s, limit=10):
    print()
    print(f"{title}: {len(s)} traces")
    for tr in sorted(s, key=lambda x: (len(x), x))[:limit]:
        print("  ", fmt_trace(tr))


# ------------------------------------------------------------------------------
# 4. Compare bounded visible languages under P3.
# ------------------------------------------------------------------------------

traces_a = bounded_visible_traces(
    net_a,
    im_a,
    fm_a,
    max_visible=12,
    max_analyze=3,
)

traces_b = bounded_visible_traces(
    net_b,
    im_b,
    fm_b,
    max_visible=12,
    max_analyze=3,
)

print()
print("Exhaustive bounded exploration under P3:")
print("  max visible events = 12")
print("  max Analyze Revision occurrences = 3")
print("  silent transitions hidden but explored")
print("  final marking equality required")
print("  NOT random playout")

print_trace_set("Model A bounded visible traces", traces_a)
print_trace_set("Model B bounded visible traces", traces_b)

print()
print("P3 bounded visible-language equivalence:", traces_a == traces_b)

unique_a = traces_a - traces_b
unique_b = traces_b - traces_a

print_trace_set("Traces unique to Model A", unique_a)
print_trace_set("Traces unique to Model B", unique_b)

# ------------------------------------------------------------------------------
# 5. Optional sanity check for the four counterexamples.
# ------------------------------------------------------------------------------

counterexamples_a_only = {
    ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
     "Analyze Revision", "Check Revision", "Close Case"),
    ("Open Case", "Check Revision", "Analyze Revision", "Rework Case",
     "Check Revision", "Analyze Revision", "Close Case"),
}

counterexamples_b_only = {
    ("Open Case", "Analyze Revision", "Rework Case", "Analyze Revision",
     "Check Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
     "Analyze Revision", "Close Case"),
}

print()
print("A-only counterexamples found:", counterexamples_a_only.issubset(unique_a))
print("B-only counterexamples found:", counterexamples_b_only.issubset(unique_b))
```

If one used `pm4py.play_out(...)` instead, the result would be a **heuristic sample**, not exhaustive. Random or heuristic playout can miss rare interleavings or loop repetitions and therefore cannot establish absence of distinguishing traces.

# 6. Stochastic and Footprint Comparison

## Footprints

`pm4py.discover_footprints(...)` can provide evidence about activities, direct follow relations, loop behavior, and sometimes activity counts. It is useful for quick sanity checks.

```python
fp_a = pm4py.discover_footprints(tree_a)
fp_b = pm4py.discover_footprints(tree_b)

print("Footprints equal:", fp_a == fp_b)
print("Model A footprints:")
print(fp_a)
print("Model B footprints:")
print(fp_b)
```

However, equal footprints do **not** establish trace equivalence. Footprints are summaries. They may record that `A` can directly follow `K`, that `K` can directly follow `A`, that `R` can follow `K`, and that `Cl` can follow `K`, without enforcing the global rule:

```text
every A must have its own K before the next R or Cl
```

For example, a footprint summary might see the same local pairs in both models while missing that Model B can generate:

```text
O A R A K Cl
```

where the second `A` has no paired `K`.

## Stochastic language and Earth Mover’s Distance

`pm4py.get_stochastic_language(...)` and `pm4py.compute_emd(...)` compare probability distributions over traces. They are useful only if a probability model is explicitly declared. I do not invent business probabilities here. A declared heuristic probability model could be uniform over enabled transitions, but that is an assumption, not evidence from the process trees.

```python
# Declared heuristic probability model: uniform over transitions.
# This is NOT a business-derived probability model.
def uniform_transition_probabilities(net):
    n = max(1, len(net.transitions))
    return {t: 1.0 / n for t in net.transitions}


prob_a = uniform_transition_probabilities(net_a)
prob_b = uniform_transition_probabilities(net_b)

# The exact keyword arguments can vary by PM4Py version.
# Conceptually:
lang_a = pm4py.get_stochastic_language(
    net_a,
    im_a,
    fm_a,
    transition_probabilities=prob_a,
)

lang_b = pm4py.get_stochastic_language(
    net_b,
    im_b,
    fm_b,
    transition_probabilities=prob_b,
)

emd = pm4py.compute_emd(lang_a, lang_b)

print("Declared uniform-transition-probability EMD:", emd)
```

A low or even zero EMD under a declared probability model does not prove trace equivalence:

- A low EMD means the distributions are close under the chosen probabilities.
- A zero EMD means the distributions are equal under the chosen probabilities, but only if the probability model has full support over the relevant traces.
- If some traces have probability zero, they may be invisible to the metric.
- Stochastic language is usually truncated or approximated, so it may not cover unbounded loop behavior.
- EMD is sensitive to the declared probabilities; changing probabilities can change the result.

Footprints and EMD can add supporting evidence, but the decisive comparison here is explicit trace reasoning and bounded exhaustive exploration.

## Pseudocode for structural counts

```python
def is_leaf(node):
    # PM4Py tree representations vary. Conceptually:
    return node.operator == "leaf" or not node.children


def tree_stats(node):
    if is_leaf(node):
        label = node.label
        visible = label != "tau"
        silent = label == "tau"
        return {
            "nodes": 1,
            "operators": 0,
            "leaves": 1,
            "depth": 1,
            "visible_leaves": int(visible),
            "silent_leaves": int(silent),
            "leaf_labels": [label],
        }

    child_stats = [tree_stats(c) for c in node.children]

    nodes = 1 + sum(s["nodes"] for s in child_stats)
    operators = 1 + sum(s["operators"] for s in child_stats)
    leaves = sum(s["leaves"] for s in child_stats)
    depth = 1 + max(s["depth"] for s in child_stats)
    visible_leaves = sum(s["visible_leaves"] for s in child_stats)
    silent_leaves = sum(s["silent_leaves"] for s in child_stats)
    leaf_labels = [lbl for s in child_stats for lbl in s["leaf_labels"]]

    duplicate_label_count = sum(
        max(0, leaf_labels.count(lbl) - 1)
        for lbl in set(leaf_labels)
    )

    return {
        "nodes": nodes,
        "operators": operators,
        "leaves": leaves,
        "depth": depth,
        "visible_leaves": visible_leaves,
        "silent_leaves": silent_leaves,
        "leaf_labels": leaf_labels,
        "duplicate_label_count": duplicate_label_count,
    }
```

# 8. Simplified Model

I choose **P1-core compliance with a fixed intra-iteration order** as the target semantics. This is a deliberate compromise:

- Preserve the essential operational rule: every analysis attempt must have its own check before the next rework or close.
- Preserve approvals as optional and visible per iteration.
- Preserve the P2 dashboard facts exactly.
- Weaken P3 by disallowing `Check Revision` before `Analyze Revision` within the same iteration.

The simplified model is:

```text
->(
  'Open Case',
  *(
    ->('Analyze Revision', 'Check Revision', X('Approve Revision', tau)),
    'Rework Case'
  ),
  'Close Case'
)
```

In compact notation:

```text
Open -> ( (Analyze ; Check ; Approve?) + ) -> Close
```

where `+` denotes the binary loop.

## PM4Py code

```python
import pm4py

SIMPLIFIED_TEXT = """
->(
  'Open Case',
  *(
    ->('Analyze Revision', 'Check Revision', X('Approve Revision', tau)),
    'Rework Case'
  ),
  'Close Case'
)
"""

simplified_model = pm4py.parse_process_tree(SIMPLIFIED_TEXT)

net_s, im_s, fm_s = pm4py.convert_to_petri_net(simplified_model)
sound_s = pm4py.check_soundness(net_s, im_s, fm_s, print_diagnostics=False)

print("Simplified model sound:", sound_s)
```

## Structural comparison to the originals

| Metric | Model A | Model B | Simplified model |
|---|---:|---:|---:|
| Process-tree nodes | 12 | 12 | 11 |
| Operator nodes | 5 | 5 | 4 |
| Leaf nodes | 7 | 7 | 7 |
| Maximum depth | 5 | 6 | 5 |
| Parallel-choice operators | 1 | 1 | 0 |
| Visible leaves | 6 | 6 | 6 |
| Silent leaves | 1 | 1 | 1 |
| Structural duplicate labels | 0 | 0 | 0 |

The simplified model removes the parallel choice inside the loop and replaces it with a sequential pair:

```text
Analyze Revision -> Check Revision
```

It is therefore simpler than both originals by structural metrics.

## Preservation table

| Property | Status | Explanation |
|---|---|---|
| `Open Case` first, `Close Case` last | exact | Same outer sequence. |
| At least one `Analyze Revision` | exact | Binary loop executes first child at least once. |
| At least one `Check Revision` | exact | Each loop iteration contains one check. |
| Every analysis has a check before next `Rework Case` or `Close Case` | exact | Each iteration is `A ; K ; optional Ap`, then either `R` or exit. |
| `Rework Case` separates attempts | exact | Same binary-loop structure. |
| Optional approvals visible per iteration | exact for `A -> K -> Ap` | Each iteration may emit `Ap` or silent ``. |
| `Check Revision` may occur before `Analyze Revision` within an iteration | lost | Simplified model fixes the order as `A` then `K`. |
| P2 dashboard facts | exact under abstraction | Both models yield `(n analyses, check occurred, rework occurred iff n > 1)`. |
| P3 full visible trace equivalence to Model A | weakened | Simplified model is a subset of Model A’s visible language because it removes `K`-before-`A` interleavings. |
| P3 full visible trace equivalence to Model B | not preserved / incomparable | Model B has different interleaving and check-multiplicity behavior. |

## Regression traces

These traces should be admitted by the simplified model and preserve the target compliance behavior.

| ID | Trace | Meaning |
|---|---|---|
| R1 | `O A K Cl` | Minimal compliant case: one analysis, one check, no rework, no approval. |
| R2 | `O A K Ap Cl` | Minimal compliant case with one optional approval. |
| R3 | `O A K R A K Cl` | Two analysis attempts, each with its own check, no approvals. |
| R4 | `O A K Ap R A K Cl` | Two attempts, approval after the first check, no approval after the second. |

## Negative traces

These traces should be rejected by the simplified model.

| ID | Trace | Why rejected |
|---|---|---|
| N1 | `O A R A K Cl` | Second analysis has no check before `Close Case`. |
| N2 | `O A Cl` | No check occurred. |
| N3 | `O K A Cl` | Rejected by the simplified model because it fixes `Analyze` before `Check`. This is a deliberate weakening relative to Model A. |

# 9. Final Recommendation

- **For P1, operational compliance:** Model A is the suitable original model. It enforces a check inside every revision iteration and preserves the visibility of optional approvals. Model B is not suitable because it admits traces where an analysis attempt has no paired check before the next rework or close.

- **For P2, executive dashboard:** Both original models are equivalent under the stated abstraction. The dashboard only sees the number of analyses, whether a check occurred, and whether a rework occurred. Under that abstraction, Model B is acceptable for reporting purposes, but it is not a good canonical process model if the same model must also support compliance or testing.

- **For P3, bounded visible testing:** Model A is the suitable original model for testing the intended per-iteration check behavior. Model B is not equivalent even under the bounded view. The simplified model is also not equivalent to Model A under P3 because it removes `Check`-before-`Analyze` interleavings.

- **Simplified model recommendation:** The simplified sequential model can replace Model A only if the business accepts the additional convention that `Check Revision` must follow `Analyze Revision` within each iteration. It preserves the core P1 compliance rule and P2 dashboard facts, but it weakens P3 by changing the visible interleaving language.

- **Warning about bounded comparison:** Bounded equivalence under P3 is not proof of unbounded equivalence. In this case, bounded counterexamples are sufficient to prove non-equivalence, but if the bounded sets had been equal, that would only mean no distinguishing trace exists within the chosen length and analysis-count bounds. Unbounded loop behavior, rare interleavings, and deeper rework patterns could still differ.
