# 1. Executive Verdict

- **Workflow net:** yes. `source` is the only place with an empty preset, `sink` is the only place with an empty postset, and every place and transition lies on a directed path from `source` to `sink`.
- **Soundness:** it should not be expected to be sound. It is safe and has no dead transitions, but it violates *option to complete* and *proper completion*.
- **Principal defect:** `t_split` is an AND-split that turns one token into two. On the waiver route, the branches are closed by `t_join_waived`, which consumes only `p_waived`. The analysis-branch token (`p_analysis` or `p_analysis_done`) is never consumed, because its only consumer is `t_join_normal`, and that transition needs `p_review_done`.
- **Business consequence:** every waived case can be authorized before, or independently of, the mandatory analysis. It ends with `sink` marked plus a stranded analysis token, so the exact final marking `[sink]` is never reached. Only standard-review cases complete correctly.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source` → `t_register` → `p_ready` | Case start ("Register Case") | Plain sequence. `source` is the unique source place | None |
| `t_split` (silent) | AND-split: start analysis and review in parallel | Consumes 1 token and produces 2 (`p_analysis`, `p_review`), so the total token count rises by +1. The net must later have a transition that consumes one token from **each** branch | Any route that has no two-input synchronization keeps an extra token |
| `p_analysis` → `t_analyze` → `p_analysis_done` | Mandatory analysis branch | `p_analysis_done` has exactly one consumer: `t_join_normal` | The analysis result can only be consumed on the standard-review route |
| `p_review` with consumers `t_standard_review` and `t_waive_review` | Exclusive choice of review outcome | Free-choice conflict: both consumers have preset `{p_review}`. Exactly one of them fires per case | Correct in itself |
| `t_standard_review` → `p_review_done` | Standard review outcome | Feeds `t_join_normal` | Correct |
| `t_waive_review` → `p_waived` | Formally recorded waiver | Feeds only `t_join_waived` | Correct in itself. The problem is downstream |
| `t_join_normal` (silent) | AND-join of analysis and standard review | Preset `{p_analysis_done, p_review_done}`, postset `{p_decision}`. Token count changes by −1, which restores one token | Correct |
| `t_join_waived` (silent) | AND-join of analysis and waiver | Preset `{p_waived}` only, postset `{p_decision}`. Despite its name, this is a 1-in/1-out sequence step, not a join. Token count stays the same | Analysis token is stranded. `t_authorize` becomes enabled while analysis is still pending |
| `p_decision` | XOR-merge of the two review routes | Two producers with different synchronization strength: one joins two branches, the other joins one | Holds a token while another token is still in the analysis branch |
| `t_authorize` → `sink` | Authorization, then end | `sink` is the unique sink place. It has no consumer | `sink` can be marked while work is still pending |
| `im = [source]`, `fm = [sink]` | Standard WF-net markings | Consistent with the WF-net convention | `fm` is unreachable on every waiver route |

**Split.** `t_split` is a correct AND-split. Its partner join exists only on the standard route.

**Review alternatives.** `p_review` is a correct free-choice XOR-split. Both outcomes are locally well formed.

**Joins.** `t_join_normal` is a correct AND-join. `t_join_waived` is the faulty one: it synchronizes the waiver with nothing. The net stays free-choice, because `p_analysis_done`, `p_waived` and `p_decision` each have a single consumer. So the defect is not a confusion between choice and concurrency. It is a missing input arc.

**Markings.** `im` and `fm` are the standard one-token markings on `source` and `sink`.

**Path condition.** Every node is covered:
- analysis path: `source → t_register → p_ready → t_split → p_analysis → t_analyze → p_analysis_done → t_join_normal → p_decision → t_authorize → sink`
- standard path: `… t_split → p_review → t_standard_review → p_review_done → t_join_normal → …`
- waiver path: `… t_split → p_review → t_waive_review → p_waived → t_join_waived → p_decision → …`

This is why `check_is_workflow_net` passes. The path condition is purely structural and cannot see that the waiver path drops the synchronization.

**Invariant view (precise statement of the defect).** Define two weighted place sums, where a marking M(p) is the number of tokens in place p:

- Analysis-branch sum: y = source + p_ready + p_analysis + p_analysis_done + p_decision + sink
- Review-branch sum: z = source + p_ready + p_review + p_review_done + p_waived + p_decision + sink

- **z is a P-invariant.** Every transition leaves z unchanged. For example, `t_join_waived` removes `p_waived` and adds `p_decision`, so the change is −1 + 1 = 0.
- **y is a P-invariant for every transition except `t_join_waived`.** That transition consumes nothing from the y-places but produces into `p_decision`, so it raises y by 1.
- **Consequence on the waiver route.** y becomes 2. When `sink` is marked (contributing 1 to y), exactly one more token remains in `p_analysis` or `p_analysis_done`.
- **Consequence in a sound repair.** y must be preserved by all transitions. Both intent-preserving repairs below restore it.

# 3. Marking-Based Counterexample

**Counterexample 1 (waiver route, authorization before analysis):**
σ1 = `t_register, t_split, t_waive_review, t_join_waived, t_authorize, t_analyze`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (`im`) | [source] | `t_register` | Initial marking |
| 1 | `t_register` | [p_ready] | `t_split` | One token |
| 2 | `t_split` | [p_analysis, p_review] | `t_analyze`, `t_standard_review`, `t_waive_review` | One token in **each** parallel branch. Token count is 2 |
| 3 | `t_waive_review` | [p_analysis, p_waived] | `t_analyze`, `t_join_waived` | Waiver chosen. `t_standard_review` is now disabled (`p_review` empty) |
| 4 | `t_join_waived` | [p_analysis, p_decision] | `t_analyze`, `t_authorize` | The "join" consumed only `p_waived`. The analysis token is untouched. Token count is still 2 |
| 5 | `t_authorize` | [p_analysis, sink] | `t_analyze` | **Authorization occurred before `t_analyze`.** A token exists in `sink`, but M ≠ `fm` (M = fm + [p_analysis]) and the case is still active |
| 6 | `t_analyze` | [p_analysis_done, sink] | none | **Dead marking.** M ≥ `fm` strictly (M = fm + [p_analysis_done]). The exact final marking `fm` was never reached: improper completion |

**Counterexample 2 (waiver route, analysis first).** This shows the defect is not an ordering artifact.
σ2 = `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (`im`) | [source] | `t_register` | Initial marking |
| 1 | `t_register` | [p_ready] | `t_split` | |
| 2 | `t_split` | [p_analysis, p_review] | `t_analyze`, `t_standard_review`, `t_waive_review` | One token per branch |
| 3 | `t_analyze` | [p_analysis_done, p_review] | `t_standard_review`, `t_waive_review` | Analysis complete, review not yet decided |
| 4 | `t_waive_review` | [p_analysis_done, p_waived] | `t_join_waived` | `t_join_normal` is **not** enabled: it needs `p_review_done` |
| 5 | `t_join_waived` | [p_analysis_done, p_decision] | `t_authorize` | Analysis result not consumed |
| 6 | `t_authorize` | [p_analysis_done, sink] | none | Same dead, non-final marking as σ1. Here `t_authorize` happens **after** `t_analyze`, but only by coincidence: σ1 shows it does not depend on analysis |

**Why the leftover token can never be consumed.** Trace the producers backwards:
- `p_analysis_done` has exactly one consumer, `t_join_normal`, which also needs `p_review_done`.
- `p_review_done` has exactly one producer, `t_standard_review`, which needs `p_review`.
- `p_review` has exactly one producer, `t_split`, which needs `p_ready`.
- `p_ready` has exactly one producer, `t_register`, which needs `source`.
- `source` has no producer and its only token was consumed at step 1.

So `p_review_done` can never be marked again, `t_join_normal` is dead in this marking, and `sink` has no consumer. No transition is enabled, and the marking can never be cleaned up.

**Why no waiver run can ever reach `fm`.** Only two transitions change the total token count: `t_split` (+1) and `t_join_normal` (−1).
- `t_split` fires exactly once per case, because a single token flows `source → p_ready`.
- Reaching `fm` (1 token) from `im` (1 token) therefore requires `t_join_normal` to fire exactly once.
- `t_join_normal` requires `t_standard_review`, which competes with `t_waive_review` for the single `p_review` token.

Hence **every** run that contains `t_waive_review` loses the option to complete. The same conclusion follows from the P-invariant y derived in Section 2.

**Full reachability (hand-derived).**
- The original net has 14 reachable markings and 17 firing edges.
- Two markings are dead: `[sink]` (= `fm`, proper) and `[p_analysis_done, sink]` (improper).
- Six markings cannot reach `fm`: [p_analysis, p_waived], [p_analysis_done, p_waived], [p_analysis, p_decision], [p_analysis_done, p_decision], [p_analysis, sink], [p_analysis_done, sink].
- The net is 1-safe and every transition can fire, so the only defect is improper completion and the loss of the option to complete.

# 4. Minimal-Repair Alternatives

**Edit-cost model.**
- Unit cost 1 for each added or removed arc, each added or removed place, each added or removed transition, and each changed label.
- Removing a node also requires removing its incident arcs, each costing 1.
- Admissibility constraints: the result must be a WF-net with the same `im`/`fm` convention and must be sound. It must also be language-equivalent to the intended behaviour on visible labels, unless a policy change is declared.
- The intended visible language L* has four traces: Register, then the interleavings of {Perform Analysis} with one of {Perform Standard Review, Record Review Waiver}, then Authorize.
- Tie-breakers, in order: fidelity to L*, free-choice/block structure, number of silent transitions.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1 – two-input waiver synchronization** | Add arc `p_analysis_done → t_join_waived` | 1 | Mandatory analysis on both routes. The waiver keeps its own place and its own join. All labels are preserved. Language = L* | Waiver runs now complete in `[sink]`. `t_authorize` can no longer precede `t_analyze` | `p_analysis_done` becomes a shared input of two joins with different presets, so the net is **no longer free-choice** and no longer block-structured (process-tree/BPMN conversion becomes harder). The "analysis is mandatory" rule is duplicated in two joins that must be kept consistent: the same kind of drift that caused the bug |
| **R2 – route the waiver into the normal synchronization** | Remove arc `t_join_waived → p_decision`. Add arc `t_join_waived → p_review_done` | 2 | Mandatory analysis enforced by the single join `t_join_normal`. All labels preserved. Language = L*. The waiver is still recorded by the visible `t_waive_review` | `t_join_waived` becomes a silent bridge that turns "waiver recorded" into "review outcome available". `p_decision` now has a single producer. The net stays **free-choice and block-structured** | After the silent bridge fires, the marking no longer shows whether the review was standard or waived (only the trace does). The name `t_join_waived` becomes misleading. One extra silent step that can interleave with `t_analyze` |
| **R2′ – clean rewire (cleanup variant of R2)** | Remove arcs `t_waive_review → p_waived`, `p_waived → t_join_waived`, `t_join_waived → p_decision`. Remove place `p_waived` and transition `t_join_waived`. Add arc `t_waive_review → p_review_done` | 6 | Same as R2. Language = L* | The waiver and the standard review lead to the identical marking immediately. One fewer silent transition | Explicit waiver state is gone. Any future waiver-specific follow-up must re-introduce it |
| **R3 – POLICY CHANGE: a waiver cancels the analysis** | Add arc `p_analysis → t_waive_review` | 1 | Sound WF-net. The waiver remains a distinct, visible outcome | **Policy change:** analysis is never performed under a waiver, and a waiver can only be recorded while analysis is still pending. Language = {Reg·Ana·Std·Auth, Reg·Std·Ana·Auth, Reg·Waive·Auth} | Violates "analysis is always mandatory". Creates a race between `t_analyze` and `t_waive_review`. Non-free-choice |
| **R4 – POLICY CHANGE: analysis optional under a waiver** | R1's arc `p_analysis_done → t_join_waived`, plus a new silent transition `t_join_waived_skip` with arcs `p_waived → t_join_waived_skip`, `p_analysis → t_join_waived_skip`, `t_join_waived_skip → p_decision` | 5 | Sound WF-net. Analysis is still possible under a waiver and mandatory under a standard review | **Policy change:** L* plus Reg·Waive·Auth. An analysis that has not started yet is dropped when the waiver path synchronizes first | Silent choice between `t_join_waived_skip` and `t_analyze` (hidden decision). Non-free-choice. Weakens the control |

**Minimality justification.**

**R1 is optimal.** Every admissible repair costs at least 1, because the original is unsound. R1 costs 1, so it is globally minimal. Its soundness can be verified directly:
- With R1, `t_join_waived` has preset `{p_analysis_done, p_waived}`, so y is now a P-invariant.
- y and z together cover all places. Whenever `sink` is marked, y = 1 and z = 1 force every other place to be empty, which gives proper completion.
- Hand-deriving the reachable markings gives 10 markings and 12 edges. All of them reach `[sink]`, and every transition occurs.

**Cost-1 candidates.** I enumerated them explicitly:
- Removing any single arc or node either leaves a node off a source-to-sink path (for example, removing `t_waive_review → p_waived` orphans `p_waived`) or removes the waiver outcome.
- Adding an isolated node breaks the WF-net property.
- Among single-arc additions:
  - `p_analysis → t_join_waived`: unsound. If `t_analyze` fires first, then `[p_analysis_done, p_waived]` deadlocks. It would also cancel the analysis.
  - `p_analysis_done → t_authorize`: unsound. It kills authorization on the standard route, because `t_join_normal` already consumed the token.
  - `t_waive_review → p_review_done`: unsound. It produces two tokens that both reach `p_decision`, so `t_authorize` fires twice.
  - `p_analysis → t_waive_review`: sound, but a policy change (R3).
  - `p_analysis_done → t_waive_review`: sound, but it forces the waiver to be recorded only after analysis. That removes the trace Reg·Waive·Ana·Auth from L* and restricts the intended parallelism.

**Ties.** R1, R3 and the `p_analysis_done → t_waive_review` variant tie at cost 1. The tie is broken by the fidelity criterion: only R1 reproduces L* exactly, so R1 is the unique cost-1 intent-preserving repair.

**R2 is minimal in its family.** "Rewire the waiver into the normal synchronization" needs at least one arc removal (otherwise `p_decision` is still reached through the one-input step) and one arc addition. R2 does exactly that, so it is minimal within that family. It does not tie with R1, since it costs 1 more.

**R1 versus R2 on behaviour.** Both have exactly the same visible-label language, L*. They differ only in structure and in the silent-step state space:
- R2: 10 markings, 13 edges. The extra edge is the silent bridge from [p_analysis, p_waived] to [p_analysis, p_review_done].
- R1: 10 markings, 12 edges.

**R2′ versus R2.** R2′ has the same language as R2 and costs 6. It is only preferable under a model that penalizes silent transitions more heavily than extra edits.

# 6. Diagnostic and Reachability Code

The script below assumes that `net`, `im`, `fm` (original) and `repaired_net`, `repaired_im`, `repaired_fm` (Section 5) are already defined.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def names(transitions):
    return sorted(t.name for t in transitions)


def as_dict(marking):
    return {p.name: n for p, n in marking.items() if n > 0}


def fmt(marking):
    items = sorted(as_dict(marking).items())
    return "[" + ", ".join(k if n == 1 else f"{n}*{k}" for k, n in items) + "]"


def get_transition(pn, name):
    matches = [t for t in pn.transitions if t.name == name]
    if len(matches) != 1:
        raise KeyError(f"expected exactly one transition named {name!r}, found {len(matches)}")
    return matches[0]


def is_enabled(t, marking):
    return all(marking[a.source] >= a.weight for a in t.in_arcs)


def execute(t, marking):
    new = Marking()
    for p, n in marking.items():
        if n > 0:
            new[p] = n
    for a in t.in_arcs:
        new[a.source] -= a.weight
        if new[a.source] == 0:
            del new[a.source]
    for a in t.out_arcs:
        new[a.target] += a.weight
    return new


def fire(pn, marking, name):
    """Fire a named transition only if it is enabled; otherwise raise."""
    t = get_transition(pn, name)
    enabled_by_pm4py = names(pm4py.get_enabled_transitions(pn, marking))
    if not is_enabled(t, marking):
        raise RuntimeError(f"{name} is NOT enabled in {fmt(marking)}; enabled: {enabled_by_pm4py}")
    assert name in enabled_by_pm4py, f"helper and pm4py disagree on enabledness of {name}"
    return execute(t, marking)


def walk(label, pn, m0, mf, sequence):
    print(f"\n--- {label} ---")
    m = m0
    print(f"  {'(im)':<18} {fmt(m):<36} enabled={names(pm4py.get_enabled_transitions(pn, m))}")
    for name in sequence:
        m = fire(pn, m, name)
        d = as_dict(m)
        print(f"  {name:<18} {fmt(m):<36} enabled={names(pm4py.get_enabled_transitions(pn, m))} "
              f"sink_token={d.get('sink', 0) > 0} equals_fm={d == as_dict(mf)}")
    if not pm4py.get_enabled_transitions(pn, m):
        ok = as_dict(m) == as_dict(mf)
        print("  no transition enabled ->", "proper completion" if ok else "DEAD marking with tokens outside fm")
    return m


def key(marking):
    return frozenset(as_dict(marking).items())


def explore(pn, m0, skip=(), limit=10_000):
    seen, edges, stack = {key(m0): m0}, [], [m0]
    while stack:
        m = stack.pop()
        for t in pn.transitions:
            if t.name in skip or not is_enabled(t, m):
                continue
            m2 = execute(t, m)
            edges.append((key(m), t.name, key(m2)))
            if key(m2) not in seen:
                if len(seen) >= limit:
                    raise RuntimeError("state-space limit exceeded")
                seen[key(m2)] = m2
                stack.append(m2)
    return seen, edges


def diagnose(label, pn, m0, mf):
    print(f"\n==================== {label} ====================")
    print("check_is_workflow_net:", pm4py.check_is_workflow_net(pn))
    result = pm4py.check_soundness(pn, m0, mf, print_diagnostics=True)
    is_sound = result[0] if isinstance(result, tuple) else bool(result)
    print("check_soundness ->", is_sound)
    print("enabled at initial marking:", names(pm4py.get_enabled_transitions(pn, m0)))

    ts = pm4py.convert_to_reachability_graph(pn, m0, mf)
    print(f"pm4py reachability graph: {len(ts.states)} states, {len(ts.transitions)} edges")
    print("pm4py states without successors:", sorted(s.name for s in ts.states if not s.outgoing))

    states, edges = explore(pn, m0)
    fm_key = key(mf)
    sources = {e[0] for e in edges}
    dead = [k for k in states if k not in sources]
    can_reach_fm = {fm_key}
    changed = True
    while changed:
        changed = False
        for src, _, dst in edges:
            if dst in can_reach_fm and src not in can_reach_fm:
                can_reach_fm.add(src)
                changed = True
    print(f"helper exploration: {len(states)} markings, {len(edges)} firing edges")
    print("dead markings other than fm:", [dict(k) for k in dead if k != fm_key])
    print("markings that cannot reach fm:", [dict(k) for k in states if k not in can_reach_fm])

    _, edges_without_analysis = explore(pn, m0, skip={"t_analyze"})
    print("t_authorize can fire in a run that never fires t_analyze:",
          any(e[1] == "t_authorize" for e in edges_without_analysis))
    return is_sound


original_sound = diagnose("ORIGINAL", net, im, fm)
walk("original: waiver route, authorize before analysis", net, im, fm,
     ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize", "t_analyze"])
walk("original: waiver route, analysis first", net, im, fm,
     ["t_register", "t_split", "t_analyze", "t_waive_review", "t_join_waived", "t_authorize"])

repaired_sound = diagnose("REPAIRED (R2)", repaired_net, repaired_im, repaired_fm)
walk("repaired: waiver route", repaired_net, repaired_im, repaired_fm,
     ["t_register", "t_split", "t_waive_review", "t_join_waived",
      "t_analyze", "t_join_normal", "t_authorize"])
walk("repaired: standard route", repaired_net, repaired_im, repaired_fm,
     ["t_register", "t_split", "t_standard_review", "t_analyze", "t_join_normal", "t_authorize"])
try:
    walk("repaired: attempted analysis bypass", repaired_net, repaired_im, repaired_fm,
         ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize"])
except RuntimeError as exc:
    print("  bypass rejected as expected:", exc)
else:
    raise AssertionError("repaired net allowed authorization without analysis")

assert not original_sound and repaired_sound
```

**Expected qualitative difference:**
- **Both nets:** `check_is_workflow_net` returns `True`, and the only transition enabled at the initial marking is `t_register`.
- **Original, soundness:** `check_soundness` returns not sound. WOFLAN analyzes the short-circuited net, where an extra transition moves the `sink` token back to `source`. The expected qualitative diagnosis is that the analysis-branch places (`p_analysis`, `p_analysis_done`) are not covered by any S-component. This is the counterpart of the broken P-invariant y from Section 2: in the short-circuited net, each waiver cycle leaves one more token in the analysis branch. The diagnostics should not point to dead transitions. I do not predict exact diagnostic keys.
- **Original, reachability:** the graph contains the non-final dead marking `[p_analysis_done, sink]` and the marking `[p_analysis, sink]`. Six markings cannot reach `fm`. The bypass query returns `True`. The two counterexample walks end in `sink_token=True, equals_fm=False`.
- **Repaired, soundness:** `check_soundness` returns sound.
- **Repaired, reachability:** the only dead marking is `[sink]`, every marking can reach `fm`, and the bypass query returns `False`. The attempted bypass raises at `t_authorize`, because `p_decision` is empty.
- **State-space sizes (hand-derived in Sections 3 and 4):** the original has 14 markings and 17 edges; R2 has 10 markings and 13 edges. The helper exploration should print these numbers. pm4py's transition system should show the same number of states; its edge count depends on how the installed version names and deduplicates edges.

# 7. Repair Trade-Offs and Residual Risks

**Are waiver and standard review still distinguishable?**
- **In the log:** yes, under every repair (R1, R2, R2′). The outcomes carry different visible labels, and exactly one of them occurs per case.
- **In R2's state:** the waiver is visible only in `p_waived`, until the silent bridge fires. After that, the marking `[…, p_review_done]` is the same as after a standard review.
- **In R1's state:** the distinction lasts until `p_decision`.
- **In R2′'s state:** the distinction is lost immediately.

If a future rule must treat waived cases differently after the join (for example, an extra sign-off before authorization), R2 would need to be split again. Under R1, the waiver route is already separate up to the join.

**Can silent transitions cause duplicate behavior or confusion?**
- R2 has three silent transitions: `t_split`, `t_join_normal` and `t_join_waived`.
- No two silent transitions are ever in conflict: `t_join_waived` needs `p_waived`, `t_join_normal` needs `p_review_done`, and the XOR at `p_review` makes these mutually exclusive until the bridge fires. So there is no hidden silent decision, and every visible trace has exactly one completing run up to the position of silent steps.
- The residual ambiguity is that `t_join_waived` is concurrent with `t_analyze`. Alignments therefore have several optimal solutions that differ only in where the silent step is placed. This is harmless for fitness, but it can make per-transition statistics on silent moves unstable.
- The name `t_join_waived` no longer describes a join. Renaming it (for example, to `t_waiver_as_review_outcome`) would cost 1 under the model and improve maintainability.
- R4, by contrast, introduces a real silent choice (`t_join_waived_skip` versus `t_analyze`), which is exactly the kind of hidden decision to avoid.

**Does soundness prove alignment with the business rule?** No.
- Soundness only guarantees termination in `[sink]`, no leftover tokens and no dead transitions. R3 and R4 are both sound but violate "analysis is always mandatory". So is a net that simply deletes the waiver path.
- Soundness also does not check that labels are correct, that authorization depends causally on analysis, or that data-level conditions are respected (for example, that a waiver is actually "formally recorded", which involves who recorded it and what evidence exists).
- Business conformance needs separate checks: language comparison against L* and rule checks such as the ones below.

**Regression traces** (visible labels):
- **Positive (must fit perfectly and end in `fm`):**
  - ⟨Register, Perform Analysis, Perform Standard Review, Authorize⟩
  - ⟨Register, Perform Standard Review, Perform Analysis, Authorize⟩
  - ⟨Register, Perform Analysis, Record Review Waiver, Authorize⟩
  - ⟨Register, Record Review Waiver, Perform Analysis, Authorize⟩
- **Negative (must not fit):**
  - ⟨Register, Record Review Waiver, Authorize⟩: analysis bypass. The original net accepts it as a prefix that marks `sink`. It should fit only under the declared policy changes R3/R4.
  - ⟨Register, Record Review Waiver, Authorize, Perform Analysis⟩: authorization before analysis.
  - ⟨Register, Perform Analysis, Authorize⟩: no review outcome.
  - ⟨Register, Perform Analysis, Perform Standard Review, Record Review Waiver, Authorize⟩: both outcomes.
  - ⟨Register, Perform Analysis, Perform Analysis, Perform Standard Review, Authorize⟩: duplicate analysis.
  - ⟨Register, Perform Analysis, Perform Standard Review, Authorize, Authorize⟩: double authorization.
  - ⟨Perform Analysis, Register, …⟩: work before registration.
- **How to check:**
  - At model level, walk each trace with the enabledness-checking `fire` helper, requiring `equals_fm=True` at the end.
  - At log level, positives must have alignment fitness 1.0 and token-based replay with zero missing and zero remaining tokens. Every negative must produce a deviation.

**Detecting an accidental bypass of mandatory analysis:**
1. **Structural check.** Verify that y (the analysis-branch sum) is a P-invariant: every transition's net effect on y is 0. This is the property the original violated, and a future edit that reintroduces a one-input path into `p_decision` breaks it immediately.
2. **State-space check.** Remove `t_analyze` and confirm that `t_authorize` is unreachable, as the `skip={"t_analyze"}` exploration does. Also confirm that every marking enabling `t_authorize` has `p_analysis = p_analysis_done = 0`.
3. **Event-data check.** Enforce Declare-style constraints `existence(Perform Analysis)` and `precedence(Perform Analysis, Authorize Case)`. Alert on authorized cases that have no analysis event or whose analysis is timestamped after authorization. In alignments, alert on any "model move" on Perform Analysis.

# 8. Final Recommendation

**Deploy R2** (redirect `t_join_waived` from `p_decision` to `p_review_done`, cost 2).
- **Same behaviour as intended.** It yields exactly the intended visible language, keeps every label, and still records the waiver as its own activity.
- **It removes the root cause.** The original error arose because the "analysis and review outcome" synchronization was implemented twice and one copy was wrong. R2 leaves a single join (`t_join_normal`) as the only way into `p_decision`, so the mandatory-analysis rule lives in one place.
- **It keeps the net easy to analyze.** The net stays free-choice and block-structured: AND-split, then analysis in parallel with an XOR of the two review outcomes, then AND-join, then authorization. That keeps soundness checking cheap and allows clean conversion to a process tree or BPMN.
- **The extra edit is worth it.** R2 costs one edit more than R1. Its drawback is a silent bridge after which the marking no longer shows the waiver; I mitigate this with the regression traces and the P-invariant check from Section 7.

**Fallback: R1** (add `p_analysis_done → t_join_waived`, cost 1).
- It is the unique globally minimal, intent-preserving repair and is sound.
- It keeps a dedicated waiver synchronization, which is useful if waived cases later need route-specific guards or data before `p_decision`.
- Its costs are losing the free-choice property and having to keep two joins consistent.

R3 and R4 should be used only if governance explicitly decides to make analysis skippable under a waiver.
