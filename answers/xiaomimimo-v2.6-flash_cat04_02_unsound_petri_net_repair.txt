def fire_transition(net, marking, transition_name):
    """Fire a named transition if enabled. Returns (new_marking, message) or (None, error)."""
    enabled = pm4py.get_enabled_transitions(net, marking)
    target = None
    for t in enabled:
        if t.name == transition_name:
            target = t
            break
    if target is None:
        return None, f"Transition '{transition_name}' is NOT enabled"
    
    new_marking = Marking()
    for p in net.places:
        new_marking[p] = marking[p]
    for arc in target.in_arcs:
        place = arc.source
        new_marking[place] -= 1
        if new_marking[place] <= 0:
            del new_marking[place]
    for arc in target.out_arcs:
        place = arc.target
        new_marking[place] = new_marking.get(place, 0) + 1

| **R2: Merge waiver outcome into the normal join** | Remove arc `waive_review  p_waived`; add arc `waive_review  p_review_done`; remove place `p_waived`; remove transition `join_waived`; remove arc `p_waived  join_waived`; remove arc `join_waived  p_decision` | **6** (1 arc removed, 1 arc added, 1 place removed, 1 transition removed, 2 arcs implicitly removed) | Analysis remains mandatory on both routes (enforced by `t_join_normal` requiring `p_analysis_done`); business policy unchanged | Single join for both review outcomes; waiver and standard review converge at `p_review_done`, losing structural distinguishability post-join (event-log distinction preserved via transition labels `t_standard_review` vs `t_waive_review`) | Post-join behavior cannot differentiate waiver from standard review from markings alone; reduced structural auditability |
| **R3: Make analysis optional under waiver (policy change)** | Add one arc: `p_analysis  waive_review` | **1** (1 arc added) | Waiver path and standard review remain structurally distinct | **Policy change:** when waiver is chosen, `t_waive_review` consumes the analysis token directly, skipping `t_analyze`. Analysis is now optional (skipped) on the waiver path. Additionally, `t_waive_review` and `t_analyze` become in conflict for `p_analysis`: if `t_analyze` fires first, `t_waive_review` is disabled, forcing the standard-review path | Waiver availability becomes time-sensitive (only available before `t_analyze` fires); violates the stated intent that "analysis is always mandatory" |

### Justification of minimality

Under the stated edit-cost model, **R1 and R3 tie at cost 1** — each requires exactly one added arc. They are **behaviorally distinct**: R1 retains mandatory analysis on the waiver path (preserving the original policy), while R3 changes the policy to make analysis optional under waiver. R2 costs 6 and is therefore not minimal under this model, but it is structurally the most radical simplification (eliminating a place, a transition, and three arcs while producing a single-join net).

R1 is the **globally minimal** repair that preserves the original business policy (mandatory analysis on all paths), since no repair can fix the synchronization defect with fewer than one added arc (the join is missing exactly one required input).

R2 is not minimal in edit cost but is minimal in **structural complexity**: it eliminates the redundant join and produces the simplest possible topology. The tie between R1 and R3 (both cost 1) is broken by intent: R1 preserves policy, R3 changes it.

import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking


def fire_transition(net, marking, transition_name):
    """Fire a named transition if enabled. Checks enabledness before moving tokens.
    Returns (new_marking, message). Returns (None, error_message) if not enabled."""
    enabled = pm4py.get_enabled_transitions(net, marking)
    target = None
    for t in enabled:
        if t.name == transition_name:
            target = t
            break
    if target is None:
        return None, f"Transition '{transition_name}' is NOT enabled"

    new_marking = Marking()
    for p in net.places:
        new_marking[p] = marking[p]
    # Consume one token from each input place
    for arc in target.in_arcs:
        place = arc.source
        new_marking[place] -= 1
        if new_marking[place] <= 0:
            del new_marking[place]
    # Produce one token in each output place
    for arc in target.out_arcs:
        place = arc.target
        new_marking[place] = new_marking.get(place, 0) + 1
    return new_marking, f"Transition '{transition_name}' fired"


def show_marking(m):
    if m is None:
        return "None"
    items = sorted([(p.name, tok) for p, tok in m.items() if tok > 0])
    if not items:
        return "{} (empty)"
    return "{" + ", ".join(f"{n}={tok}" for n, tok in items) + "}"


def run_trace(net, im, fm, sequence, label):
    """Run a firing sequence and print each step."""
    print(f"\n--- {label} ---")
    m = im
    for i, tname in enumerate(sequence):
        enabled = pm4py.get_enabled_transitions(net, m)
        enabled_names = sorted(t.name for t in enabled)
        m, msg = fire_transition(net, m, tname)
        print(f"  Step {i}: {msg}")
        print(f"    Marking: {show_marking(m)}")
        print(f"    Enabled: {enabled_names}")
        if m is None:
            print("    *** SEQUENCE BLOCKED — transition not enabled ***")
            return None
    print(f"  Reached fm exactly? {m == fm}")
    return m

# 7. Repair Trade-Offs and Residual Risks

**Waiver and standard review remain distinguishable.**
In R1 (selected repair), the two review outcomes produce different places (`p_waived` vs `p_review_done`) and are consumed by different joins (`t_join_waived` vs `t_join_normal`). The distinction is preserved both in markings and in event logs (transition labels `t_standard_review` vs `t_waive_review`). In R2, the distinction is preserved only in event logs (transition labels) but lost in the net's marking structure post-join, since both outcomes produce a token in `p_review_done`. This reduces structural auditability.

**Silent transitions and duplicate behavior.**
R1 retains two silent transitions (`t_join_normal`, `t_join_waived`) that both produce `p_decision`. Since only one of `p_review_done`/`p_waived` can contain a token (they are in conflict at `p_review`), the two joins never compete for the same input, so no nondeterministic duplicate behavior arises. However, an external observer (or conformance checker) that ignores silent transitions cannot distinguish which join fired. This is acceptable for control flow but may matter for audit trails. R2 eliminates this concern by having a single silent join.

**Soundness does not prove alignment with the business rule.**
A successful `check_soundness` call verifies three behavioral properties (option to complete, proper completion, no dead transitions), but it does **not** verify domain-specific invariants. For example, a sound net could be built where `t_analyze` is optional on *all* paths — it would be sound but violate "analysis is always mandatory." Soundness is necessary but not sufficient for business-rule conformance. Additional checks (trace predicates, conformance checking against a declarative model) are needed.

**Regression test traces:**

| Type | Trace | Expected outcome |
|---|---|---|
| Positive (standard) | `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize` | Completes; reaches `fm`; analysis precedes authorization |
| Positive (waiver) | `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize` | Completes; reaches `fm`; analysis precedes authorization |
| Positive (waiver, reverse order) | `t_register, t_split, t_waive_review, t_analyze, t_join_waived, t_authorize` | Completes; reaches `fm`; analysis precedes authorization |
| Negative (bypass) | `t_register, t_split, t_waive_review, t_join_waived, t_authorize` (without `t_analyze`) | **Must be blocked** — `t_join_waived` not enabled without `p_analysis_done` |
| Negative (negative trace) | Any sequence reaching a marking with tokens outside `sink` and no enabled transitions | Must not be reachable |

**Detecting accidental bypass of mandatory analysis:**
1. **Model-level:** Verify structurally that every path from `p_decision` to `sink` passes through a transition whose inputs include `p_analysis_done` (or a place fed by `t_analyze`). This can be checked via reachability analysis: enumerate all paths from `im` to `fm` and assert `t_analyze` fires on every one.
2. **Runtime monitoring:** After each case, check that the event log contains a `t_analyze` event before `t_authorize`. Any trace where `t_authorize` appears without a prior `t_analyze` is a violation.
3. **Automated invariant:** Encode a constraint `t_analyze` precedes `t_authorize` (e.g., using DECLARE/DMN or a monitoring rules engine) and run it as a regression test alongside the soundness check.

# 8. Final Recommendation

**Deployment choice: Repair R1** (add arc `p_analysis_done  join_waived`, edit cost 1).

R1 is the globally minimal repair under the stated edit-cost model: a single added arc closes the synchronization gap without changing any place, transition, or existing arc. It preserves the business policy exactly — analysis is mandatory on both the standard-review and waiver paths — and keeps the structural distinction between the two review outcomes (separate places `p_waived`/`p_review_done`, separate joins). The change is a one-line addition, trivially reviewable and reversible. It introduces no new silent transitions and no policy change.

**Fallback: Repair R2** (merge waiver into `p_review_done`, remove `join_waived` and `p_waived`; edit cost 6).

R2 is the structural simplification fallback. If the two-join topology causes maintenance confusion or if post-join auditability is deemed unnecessary (event-log labels suffice to distinguish waiver from standard review), R2 eliminates the redundant join and produces a simpler net with a single synchronization point. It is higher-cost and less structurally informative but equally sound and policy-preserving.
