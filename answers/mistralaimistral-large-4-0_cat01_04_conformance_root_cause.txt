The measured collapse is best explained by a stack of logging and model-governance defects rather than a single behavioral shift. The May 31 UI release changed the visible activity name from `Classify` to `Risk Screen`, so the normative model's `Classify` is moved on log in every post-release trace. The June 3 gateway added `Queue Routed`, a technical event that the control-flow model does not expect, inflating events per case and missing-resource rates. The June 15 ETL change used warehouse-ingestion time for `Decision` and `Notify`, producing reversed `Notify -> Decision` edges in 70 June-July and 45 August-September traces; source-sequence ordering removes most of this. The August 1 policy added `Supervisor Sign-off` for high-value claims, but the process tree was not updated, so 210 August-September traces contain an unmodeled activity. `Manual Override` appears to be a real user action, possibly a workaround, but its logging semantics changed on August 12 and its intent is not yet established. Finally, 25 June-July and 30 August-September enhanced traces lack a recorded `Compliance Check`; these could be true bypasses or missing events, and no reliable audit has resolved this.

Unchanged approval, appeal, and cycle-time outcomes neither prove the data are clean nor rule out noncompliance. Outcomes are aggregate, lagging, and insensitive to a missing check if the decision is still made; incident detection is explicitly incomplete; and improved fitness after normalization can coexist with real bypasses hidden by extraction gaps. Thus the conformance drop is mostly an artifact of labels, technical events, ordering, and model obsolescence, while a narrower compliance risk remains unresolved.

import pm4py
from datetime import datetime, timedelta
from pm4py.algo.conformance.alignments import algorithm as alignments_alg
from pm4py.algo.evaluation.fitness import algorithm as fitness_alg
from pm4py.algo.evaluation.precision import algorithm as precision_alg

# ---------- 1. Normative process tree ----------
normative_tree_str = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "'Decision', 'Notify' )"
)
normative_tree = pm4py.parse_process_tree(normative_tree_str)
normative_net, normative_im, normative_fm = pm4py.convert_to_petri_net(normative_tree)

# Candidate model: optional Supervisor Sign-off before Decision (control-flow only)
candidate_tree_str = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "X ( 'Supervisor Sign-off', tau ), "
    "'Decision', 'Notify' )"
)
candidate_tree = pm4py.parse_process_tree(candidate_tree_str)
candidate_net, candidate_im, candidate_fm = pm4py.convert_to_petri_net(candidate_tree)

# ---------- 2. Expand variant-frequency tables into event-log strings ----------
def expand_variants(variant_table, start_case=1, base_date="2026-04-01"):
    lines = []
    case_id = start_case
    base = datetime.fromisoformat(base_date)
    for trace, count in variant_table:
        activities = [a.strip() for a in trace.split(',')]
        for _ in range(count):
            for i, act in enumerate(activities):
                ts = (base + timedelta(minutes=case_id * 10 + i)).strftime("%Y-%m-%d %H:%M:%S")
                lines.append(f"{case_id},{act},{ts}")
            case_id += 1
    return "\n".join(lines)

apr_may_variants = [
    ("Receive,Classify,Standard Review,Decision,Notify", 380),
    ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
    ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40),
]
jun_jul_variants = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
    ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
    ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
]
aug_sep_variants = [

    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),

apr_may_str = expand_variants(apr_may_variants, start_case=1, base_date="2026-04-01")
jun_jul_str = expand_variants(jun_jul_variants, start_case=1000, base_date="2026-06-01")
aug_sep_str = expand_variants(aug_sep_variants, start_case=2000, base_date="2026-08-01")

apr_may_log = pm4py.parse_event_log_string(apr_may_str)
jun_jul_log = pm4py.parse_event_log_string(jun_jul_str)
aug_sep_log = pm4py.parse_event_log_string(aug_sep_str)

# ---------- 3. Transparent normalization pipeline ----------
def normalize_log_string(log_str, map_risk_to_classify=True, remove_queue_routed=True):
    out = []
    for line in log_str.strip().splitlines():
        case_id, act, ts = line.split(',')
        if map_risk_to_classify and act == 'Risk Screen':
            act = 'Classify'
        if remove_queue_routed and act == 'Queue Routed':
            continue
        out.append(f"{case_id},{act},{ts}")
    return "\n".join(out)

def apply_source_sequence_order(log_str):
    # Simulate source-system sequence ordering: where the extracted log has
    # Notify immediately before Decision, the source sequence says Decision first.
    traces = {}
    order = []
    for line in log_str.strip().splitlines():
        case_id, act, ts = line.split(',')
        if case_id not in traces:
            traces[case_id] = []
            order.append(case_id)
        traces[case_id].append((act, ts))
    out = []
    for case_id in order:
        events = traces[case_id]
        corrected = []
        i = 0
        while i < len(events):
            if i + 1 < len(events) and events[i][0] == 'Notify' and events[i+1][0] == 'Decision':
                corrected.append(events[i+1])
                corrected.append(events[i])
                i += 2
            else:
                corrected.append(events[i])
                i += 1
        for act, ts in corrected:
            out.append(f"{case_id},{act},{ts}")
    return "\n".join(out)

jun_jul_norm_log = pm4py.parse_event_log_string(jun_jul_norm_str)
jun_jul_src_str = apply_source_sequence_order(jun_jul_norm_str)

def print_dfg(log, title, top_k=8):
    dfg = pm4py.discover_dfg(log)
    graph = dfg.graph if hasattr(dfg, 'graph') else dfg
    print(f"\nDFG: {title}")
    edges = sorted(graph.items(), key=lambda kv: -kv[1])[:top_k]
    for (src, tgt), count in edges:
        print(f"  {src} -> {tgt}: {count}")

# ---------- 5. Alignment diagnostics, fitness, precision ----------
def summarize_alignment_moves(aligned_traces):
    log_moves = {}
    model_moves = {}
    for al in aligned_traces:
        for log_move, model_move in al['alignment']:
            if log_move != '>>':
                log_moves[log_move] = log_moves.get(log_move, 0) + 1
            if model_move != '>>':
                model_moves[model_move] = model_moves.get(model_move, 0) + 1
    return log_moves, model_moves

def evaluate_model(log, net, im, fm, label):
    aligned_traces = alignments_alg.apply(log, net, im, fm)
    fitness = fitness_alg.apply(log, net, im, fm)
    precision = precision_alg.apply(log, net, im, fm)
    log_moves, model_moves = summarize_alignment_moves(aligned_traces)
    print(f"\n=== {label} ===")
    print(f"fitness: {fitness}")
    print(f"precision: {precision}")
    print("top log moves:", sorted(log_moves.items(), key=lambda kv: -kv[1])[:6])
    print("top model moves:", sorted(model_moves.items(), key=lambda kv: -kv[1])[:6])
    return aligned_traces, fitness, precision

print("\n--- Normative model on raw/normalized/source-ordered logs ---")
evaluate_model(apr_may_log, normative_net, normative_im, normative_fm, "Apr-May raw vs normative")
evaluate_model(jun_jul_log, normative_net, normative_im, normative_fm, "Jun-Jul raw vs normative")
evaluate_model(jun_jul_norm_log, normative_net, normative_im, normative_fm, "Jun-Jul normalized vs normative")
evaluate_model(jun_jul_src_log, normative_net, normative_im, normative_fm, "Jun-Jul source-ordered vs normative")
evaluate_model(aug_sep_norm_log, normative_net, normative_im, normative_fm, "Aug-Sep normalized vs normative")

## 7. Provisional conclusion

Primary explanation: The measured conformance collapse from 93% to 32% in June-July is predominantly a measurement and model-governance artifact, not a sudden behavioral collapse. Four mechanisms account for most of the drop: (1) the May 31 UI release renamed `Classify` to `Risk Screen`, causing systematic log moves on `Classify`; (2) the June 3 gateway added `Queue Routed`, a technical event that inflated events per case and missing-resource rates; (3) the June 15 ETL change used warehouse-ingestion time for `Decision` and `Notify`, producing reversed `Notify -> Decision` edges; and (4) the August 1 policy added `Supervisor Sign-off` for high-value claims without updating the normative process tree. The staged improvement after label mapping, technical-event removal, and source-sequence ordering (32  58  81  89) strongly supports this interpretation. Confidence: high (85–90%) for the measured drop being mostly artifact.

Separate compliance assessment: A real compliance problem may remain. The 25 June-July and 30 August-September enhanced-review traces without a recorded `Compliance Check` are unresolved; they could be true bypasses or missing events. `Manual Override` is a real user action according to IT and reviewers, but its intent and frequency are unclear. The policy change requiring `Supervisor Sign-off` above EUR 50,000 is real, and the model does not enforce it. Confidence: moderate (50–60%) that some residual noncompliance or control gap exists, but low (20–30%) that it explains the bulk of the conformance drop.

Immediate actions: IT should fix the ETL to use source-system sequence/timestamps, publish an event-semantic contract distinguishing business and technical events, and preserve source sequence in the conformance log. Process owners should update the normative model to include `Supervisor Sign-off` as a data-aware guard for claims above EUR 50,000 and define `Manual Override` semantics. Compliance should audit the enhanced traces without `Compliance Check` and high-value traces without sign-off, stratify by reviewer and case value, and reconcile source documents with the log.

What must not be claimed yet: Do not claim employees became broadly noncompliant; do not claim the process is compliant merely because outcomes are stable; do not claim the optional sign-off model is sufficient; do not claim `Queue Routed` is harmless without checking routing effects. The current evidence supports a measurement/model-governance incident with an unresolved compliance tail.

## 8. Model-governance recommendation

1. Model versioning: Every normative model must have a version, effective date, owner, and change log; conformance reports must state which model version was used; policy changes must trigger model review before go-live.
2. Event-semantic contracts: Maintain a canonical event dictionary mapping UI labels, source-system activities, and log concept names; any label change requires a mapping table and regression test.
3. Technical-event policy: Classify events as business or technical; technical events must be excluded or explicitly modeled; gateway additions require conformance impact assessment.
4. Timestamp provenance: Store and use source-system timestamps and sequence numbers; never substitute warehouse-ingestion time for business event order; validate ordering with source screenshots.
5. Data-aware constraints: Encode data-dependent rules (e.g., `Supervisor Sign-off` for claims > EUR 50,000) in the model or as conformance filters; stratify conformance by case attributes.
6. Post-release validation: After UI, gateway, ETL, or policy releases, run a controlled conformance comparison on a labeled sample; require fitness/precision checks and manual audit before declaring a process change.
