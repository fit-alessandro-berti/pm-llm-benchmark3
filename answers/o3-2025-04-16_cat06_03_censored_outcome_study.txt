## 1. Target definition  
Primary target (chosen)  
• Unit of analysis: an application that eventually reaches the event “Account Activated”.  
• Prediction time: immediately after the *first* “Credit Review” exit (i.e., at the moment the credit officer decides whether to accept, reject, or ask for additional documents the first time).  
• Horizon: 90 days following the timestamp of “Account Activated”.  
• Estimand: P(default within 90 days | the case was activated, information available up to the first-pass Credit Review, policy environment in force at decision time).  
• Population: all applications started between 1-Jan-2024 and 15-Feb-2026 that were later activated *and* whose 90-day window plus 35-day feed delay has fully elapsed by 15-Feb-2026.  
Rationale: the outcome is well defined and (eventually) observable for every member of this set. We explicitly condition on activation; the model answers “among accounts we do open, who will default soon?”—an operational early-warning question that does not require counterfactual assumptions about rejected borrowers.

Credible alternative target  
A. Multistate competing-risk target for the full 48 000 applications: first absorbing state among {Activated-&-Default90d, Activated-&-Paid90d, Rejected, Withdrawn, Transferred, Still-Open}. This answers a *policy* question—“what is the probability the next outcome is bad, given we may also reject or the applicant may withdraw?”—but requires a more complex estimator and still leaves 40 % of transfers partially unobserved.  
B. Counterfactual “default if the application *had* been activated.” This is the classical reject-inference setup and is unidentifiable without strong, untestable assumptions; we therefore do **not** choose it as primary.

## 2. Cohort construction  
Cut-off date: 15-Feb-2026.  
Step | n remaining | comment  
1. All application IDs in `applications_events.csv`……………… 48 000  
2. Remove cases with start after 15-Nov-2025 (90 d + 35 d not mature)…… –2 700  45 300 (right-censored, will not enter modelling yet)  
3. Identify cases *ever* reaching “Account Activated”………………… 25 200  
3a. Of those, label matured (activation  23-Oct-2025)……………… 21 600 (analysis set)  
3b. Activation but label not yet mature…………………………………… 3 600 (delayed labels – hold out)  
4. Non-activated cases………………………………………………………… 19 , …  minerals  
Rejected………………………………… 9 100 (competing outcome)  
Withdrawn……………………………… 5 700 (competing outcome)  
Transferred (out)……………………… 2 900 (60 % traceable; competing/missing)  
Still open (no terminal event)………… 1 600 (after maturity filter)  
Final analysis set = 21 600 labelled, activation-conditioned cases.  
All other categories remain in a *policy* data mart for future multistate work but are *not* relabelled as non-default.

## 3. Censoring and missing-label strategy  
Mechanisms  
• Ordinary right censoring – activations after 23-Oct-2025.  
• Administrative delay (feed 7–35 d) – we wait until 35 d past horizon before considering a label observed.  
• Selection through activation – handled by conditioning.  
• Transfer – treated as a *competing event*; if linked (60 %), outcome may be imported, else considered lost-to-follow-up.  
• Permanently missing feed ( 2 % of partner accounts) – assumed Missing-Not-at-Random.  

Primary analysis  
• Fit a binary classifier + calibration on the 21 600 labelled activations.  
• Accounts with missing feed are *excluded*; sensitivity analyses below test impact.  

Sensitivity analyses  
S1. Worst-case imputation: treat missing-feed activations as defaults  lower-bound AUC and PD.  
S2. Best-case imputation: treat them as non-defaults  upper bound.  
S3. Inverse-probability censoring weights using logistic model of “feed arrived” vs covariates.  
Testable assumption: MAR for feed arrival (partially testable).  
Untestable: that excluded transfers would have the same default probability as observed ones.

## 4. Prefix extraction  
• Fixed-length: first k = 5 events **per case**, truncated at the first Credit Review exit if it comes earlier.  
• Time-elapsed: all events within 2 calendar days after case start, *capped* at prediction time.  
Implementation:  
– Build ordered traces; stop once `concept:name`  {‘Credit Review – Accept’, ‘Credit Review – Reject’, ‘Credit Review – Request Docs’} occurs the *first* time.  
– For very short cases (<5 events) pad with ‘’ activity tokens.  
System-migration rename harmonisation table maps old  new names prior to prefix extraction. Duplicate events are dropped by (case, activity, timestamp) distinct.

## 5. Process-aware features  
Static at start  
• channel, region, requested_amount (binned), initial risk_score.  
Prefix-derived  
• n_events, n_unique_activities, mean inter-event time, presence of ‘Request Docs’, loop count of (Request Docs  Credit Review).  
Timing  
• elapsed_minutes_to_pred_time, business-hours indicator, weekday.  
Resources / queue  
• count_distinct_org_resource up to prefix, officer_experience_at_event (pre-collected snapshot).  
Rework  
• max_loop_length for KYC  Credit Review.  
Historical reference  
• rolling 30-day default rate of last 100 activated cases *before prefix time* (requires forward-looking guard).  
Calendar / policy  
• indicator pre/post 1-Jul-2025 policy change; indicator pre/post 15-Oct-2025 migration.

## 6. Leakage audit  
Feature | Leakage risk | Availability rule | Keep/repair/drop | Rationale  
final_limit | set only after Accept  unavailable | drop | Reveals decision made after prediction  
decision_reason | same | drop | Same as above  
collection_status | reflects post-activation collections | drop | Directly signals default  
future events | obvious | exclude events > pred-time | drop  
documents_total | may include later-in-day uploads | keep with EoD-1 cutoff | safe if we time-slice at 00:00 of pred-day  
updated risk_score | could be updated *after* pred-time | keep first value  pred-time | aligns with as-of view  
resource experience | stored at extract date | repair: subtract (extract_date – event_date).years | approximates actual experience  
label_available_at | contains future info on maturity | keep only for censor logic, never as feature | operational flag, not predictive

## 7. Validation design  
• Split by application *start date*:  
Train: 01-Jan-2024 – 30-Jun-2025 (pre-policy-change)  
Val: 01-Jul-2025 – 14-Oct-2025 (post-policy, pre-migration)  
Test: 15-Oct-2025 – 23-Oct-2025 (post-migration, labels mature).  
• Ensures model is evaluated under distribution shifts (policy, system).  
• Metrics  
– AUROC and Brier score with IPCW for missing-feed censoring.  
– Calibration curve and Expected Calibration Error (ECE).  
– Sub-group AUROC by channel, region, amount decile.  
Random splits would mix pre/post policy data, leak temporal information, over-optimistic.

## 8. Limitations and decision-use boundary  
• Predictions are *conditional on activation*; they do *not* estimate how many rejected cases would have defaulted.  
• Selection bias: if future policy changes who gets activated, model may mis-calibrate.  
• Missing outcomes for transfers assumed similar after IPCW—may be wrong.  
• Deployment feedback loop: 1) high-risk early collections may reduce observed default; 2) officers may change decision thresholds if model score visible; 3) new migration waves could add unseen activity labels.

## 9. PM4Py-oriented Python implementation skeleton
```python
# -*- coding: utf-8 -*-
"""
Early-warning default model: data engineering & audit pipeline
Assumes: applications_events.csv is present.
Author: study design demo – adapt paths & cut-off as needed.
"""
import pandas as pd
import numpy as np
from datetime import timedelta
import pm4py
from pm4py.objects.log.util import dataframe_utils
from pm4py.algo.filtering.attribute import attribute_filter

# -------------- Parameters -----------------
CUT_OFF = pd.Timestamp("2026-02-15 00:00:00")
MAX_FEED_DELAY = timedelta(days=35)
DEFAULT_HORIZON = timedelta(days=90)
POLICY_CHANGE = pd.Timestamp("2025-07-01")
MIGRATION = pd.Timestamp("2025-10-15")
PREFIX_K = 5          # fixed-length prefix
TIME_PREFIX_DAYS = 2  # elapsed-time prefix

# -------------- Load & basic cleaning -------
df = pd.read_csv("applications_events.csv",
                 parse_dates=["time:timestamp", "label_available_at",
                              "data_extract_time"])
# unify column names for pm4py
df = dataframe_utils.convert_timestamp_columns_in_df(df)
pm4py.format_dataframe(df,
                       case_id="case:concept:name",
                       activity_key="concept:name",
                       timestamp_key="time:timestamp")

# -------------- Harmonise activity names ----
rename_map = {"CreditReviewOld": "Credit Review",
              "DocRequestOld": "Request Documents"}
df["concept:name"] = df["concept:name"].replace(rename_map)

# drop exact duplicate events created during migration
df = df.drop_duplicates(subset=["case:concept:name",
                                "concept:name",
                                "time:timestamp"])

# -------------- Build case level table -------
g = df.groupby("case:concept:name")
case_tbl = g.agg(start_time=("time:timestamp", "min"),
                 end_time=("time:timestamp", "max"),
                 activated_time=("time:timestamp",
                                 lambda x: x[g.get_group(x.name)["concept:name"]
                                             .str.contains("Account Activated")]
                                 .min() if (g.get_group(x.name)["concept:name"]
                                            .eq("Account Activated")).any()
                                 else pd.NaT))

case_tbl["label_mature_time"] = (case_tbl["activated_time"] +
                                 DEFAULT_HORIZON + MAX_FEED_DELAY)

case_tbl["label_available"] = (case_tbl["label_mature_time"] <= CUT_OFF)
case_tbl["default_90d"] = g["default_90d"].max()        # NaN for unlabeled

# cohort flags
case_tbl["status"] = np.select(
    [
        case_tbl["activated_time"].notna() & case_tbl["label_available"],
        case_tbl["activated_time"].notna() & ~case_tbl["label_available"],
        case_tbl["activated_time"].isna()
    ],
    ["Activated_Labeled", "Activated_Delayed", "Never_Activated"],
    default="Unknown")

# ---------- Cohort counts -------------------
print("COHORT COUNTS AS OF", CUT_OFF.date())
print(case_tbl["status"].value_counts(dropna=False))

# -------------- Temporal split --------------
train_mask = (case_tbl["start_time"] < POLICY_CHANGE)
val_mask = (case_tbl["start_time"].between(POLICY_CHANGE, MIGRATION - timedelta(days=1)))
test_mask = (case_tbl["start_time"].between(MIGRATION, CUT_OFF - DEFAULT_HORIZON - MAX_FEED_DELAY))

splits = {"train": train_mask, "val": val_mask, "test": test_mask}

# ------------- Prefix extraction example ----
analysis_ids = case_tbl.query("status == 'Activated_Labeled'").index
analysis_log = df[df["case:concept:name"].isin(analysis_ids)]

# clip events at prediction time (first Credit Review exit)
def clip_to_prediction(sublog):
    sublog = sublog.sort_values("time:timestamp")
    pred_idx = sublog[sublog["concept:name"]
                      .str.contains("Credit Review")].index[0]
    pred_time = sublog.loc[pred_idx, "time:timestamp"]
    return sublog[sublog["time:timestamp"] <= pred_time]

analysis_log = analysis_log.groupby("case:concept:name", group_keys=False).apply(clip_to_prediction)

# fixed length k prefix
prefix_log = pm4py.get_prefixes_from_log(df=analysis_log,
                                         prefix_length=PREFIX_K,
                                         case_id_key="case:concept:name",
                                         activity_key="concept:name",
                                         timestamp_key="time:timestamp")

# ------------- Feature engineering sketch ---
from pm4py.algo.discovery.dfg import algorithm as dfg_discovery
dfg = dfg_discovery.apply(prefix_log)
variants = pm4py.get_variants(prefix_log)

# example temporal feature: mean inter-event time
def temporal_feats(sublog):
    ts = sublog["time:timestamp"].sort_values()
    diffs = ts.diff().dropna().dt.total_seconds()
    return pd.Series({"mean_ie_time": diffs.mean() if not diffs.empty else 0,
                      "n_events": len(sublog)})
feat_tbl = prefix_log.groupby("case:concept:name").apply(temporal_feats)

# -------------- Leakage audit check ----------
leak_cols = ["final_limit", "decision_reason", "collection_status"]
leaks_present = [c for c in leak_cols if c in prefix_log.columns]
if leaks_present:
    raise ValueError(f"Potential leakage columns in prefix table: {leaks_present}")

# -------------- Save artefacts --------------
feat_tbl.to_parquet("prefix_features.parquet")
case_tbl.to_csv("case_level_cohort.csv")
```
