## 8. Model-governance recommendation

1.  **Versioned Process Models:** All normative models must be version-controlled and tagged with effective dates; conformance checks must automatically select the model version active at the time of the event.
2.  **Event-Semantic Contracts:** IT and Process Owners must sign off on event schemas; any UI label change triggering an activity name change requires an explicit log mapping configuration before deployment.
3.  **Technical Event Policy:** System-generated events (e.g., `Queue Routed`) must be flagged in metadata and excluded from control-flow conformance unless explicitly required for routing analysis.
4.  **Timestamp Provenance:** Conformance jobs must prioritize source-system transaction timestamps over warehouse ingestion times; ingestion-time usage requires documented justification.
5.  **Data-Aware Constraints:** Models must support data-aware constraints (e.g., guard conditions on attributes like EUR 50,000) rather than relying solely on control-flow variants.
6.  **Post-Release Validation:** Any process change deployment must include a parallel conformance run comparing pre- and post-release fitness; a drop exceeding 5% triggers an automatic investigation hold.
