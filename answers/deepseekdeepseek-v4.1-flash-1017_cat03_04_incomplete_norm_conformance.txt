## 1. Conformance semantics

I distinguish conformance classes by norm status plus evidence quality:

- **Forbidden behavior**: an explicitly forbidden relation occurs under a valid scope and linkage. These are closed-world violations only when the observed relation is not a join artifact, missing-scope artifact, or timestamp/linkage error.
- **Missing mandatory behavior**: a mandatory relation is absent within its stated scope after checking abstraction and data quality. Mandatory relations are closed-world only inside scope, but “eventually” rules cannot be judged as if they were directly-follows rules.
- **Unexpected but unregulated behavior**: an observed relation/event not covered by a normative edge. Under the open-world assumption this is not a violation merely because it is absent from the norm.
- **Typical-pattern absence**: a typical relation is missing. This is a possible exception or monitoring signal, not nonconformance.
- **Likely data-quality error**: a relation is contradicted by identifier reuse, missing attributes, carrier references without Delivery links, or known join defects.
- **Abstraction mismatch**: a rule is satisfied at one level but appears missing at another, e.g. eventual validation vs directly-follows, or OTG Package–Delivery present while ET–OT Dispatch Package–Delivery is missing for two events.
- **Insufficient evidence**: counts alone do not establish event order, same-object identity, scope, or whether unrecorded events exist.

Open-world interpretation applies to unspecified and most typical relations: absence from a normative edge set is not automatically noncompliance. Closed-world applies only to explicit forbidden relations and mandatory columns within scope.

## 3. Detailed reasoning by model family

### OC-DFG

OC-DFG establishes per-object directly-follows event-type relations and counts. It cannot prove that an event never occurred later under an “eventually” rule. Thus N1’s 98/100 is not enough to declare two violations: the two Orders may have an unrecorded review between creation and validation, or validation may occur after some other event, which is an **abstraction mismatch**. N3’s Cancel Order -> Dispatch Package 2 is different: if the same Order is cancelled and a package is dispatched after that cancellation, it is an explicit forbidden violation. N4’s 198/200 Pack Package -> Dispatch Package is a mandatory-scope gap for externally shipped packages, but data may be missing or scope misclassified. N2, N5, and Write Off/no-successor cases are typical or legitimate exceptions. Reopen->Close (N6) and Validate->Issue Invoice are not violations solely because no norm edge lists them.

### OTG

OTG establishes object-type interaction/co-birth/codeath edges. It cannot establish that a particular event had the required object, temporal ordering, or scope. T1 Order–Item 1450 appears consistent, but per-event gaps must be checked in ET–OT. T2 Package–Delivery 200 appears conforming at OTG; however, E6 shows only 198/200 Dispatch Package events link to Delivery. That is a useful abstraction contrast: object-level linkage exists, but event-level dispatch linkage is incomplete. T6 Order cobirth Payment is forbidden if valid. Package codeath Delivery is unspecified and must not be called a violation. T4/T5 are open-world unspecified.

### ET–OT

ET–OT establishes event-to-object-type links. It is closest to mandatory per-event checks but still cannot know scope labels such as “unapplied cash.” E8 requires Record Payment -> Invoice except explicitly typed unapplied cash; none are typed, so the one missing Invoice link is a mandatory gap, unless reclassified after evidence. E2 shows 1448 Add Item -> Order links versus 1450 Add Item -> Item links, so two Add Item events likely lack Order linkage. E6 has two missing Dispatch Package -> Delivery links; carrier references suggest data repair is plausible but do not satisfy the mandatory relation. E10 Sensor Heartbeat -> Invoice is forbidden in principle; because the join reused a numeric identifier, it is likely data quality and should be quarantined, not treated as process behavior until verified.

The main danger is treating an eventually expected business rule as directly-follows. N1 says Orders should eventually enter validation, but the summary approximates it by directly-follows. A missing direct edge is only evidence for investigation, not proof of missing validation.
