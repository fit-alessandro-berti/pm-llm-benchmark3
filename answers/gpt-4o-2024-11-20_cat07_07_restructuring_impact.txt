# 1. Mechanism map

This mechanism map links restructuring actions to expected process-mining effects:

| **Restructuring Action**                                   | **Effect**                                                                                                                       |
|-----------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------|
| Merge local tech specialists into Technical Shared Service | - **Nominal handover reduction**: Fewer unnecessary loops at local level                                                          |
|                                                           | - **Central queue formation**: Increased waiting time for high-complexity cases and cases requiring specific specialties          |
|                                                           | - **Specialist utilization**: Expected 15% higher utilization, but risk of bottlenecks                                            |
|                                                           | - **Local expertise loss**: Erosion of informal advice mechanisms                                                                 |
|                                                           | - **Resilience to absence**: More centralized resource pool makes covering leave easier                                           |
|                                                           | - **Role clarity**: Local roles become less specialized; shared specialists must balance competing priorities                     |
|                                                           | - **Fairness**: North/South risk loss of local expertise; East may become more equitable due to reduced overload                  |
| Centralize legal/risk/difficult quality checks            | - **Fairness across teams**: Broader access to scarce expertise                                                                   |
|                                                           | - **Rework**: May increase if centralized staff lacks contextual knowledge                                                        |
|                                                           | - **Role clarity and accountability**: Decisions become depersonalized; ownership may weaken                                      |
| Introduce shared approval queue                           | - **Nominal handover reduction**: Consolidates local supervisor approvals, standardizes routing                                   |
|                                                           | - **Queue formation**: Potential new waiting time bottlenecks for mid/high-value approvals                                        |
|                                                           | - **Role clarity**: Local accountability diffuses                                                                                 |
| Broaden routing rules to detect specialty cases           | - **Rework**: Could decrease if specialist expertise is applied earlier                                                          |
|                                                           | - **Queue time**: May worsen specialist queues due to increased detection of specialty-related cases                              |
|                                                           | - **Fairness**: Improved detection of complex cases may benefit underserved customers                                             |

|                                                           | - **Queue formation**: Requires monitoring to avoid unresolved/forgotten cases                                                   |

# 2. Scenario forecasts

## Optimistic Scenario
- **Handover pattern**: Nominal handovers decrease due to centralized routing. Local handover loops are reduced.
- **Queue/waiting-time pattern**: Shared queues operate within design parameters; average waiting times rise slightly but remain manageable.
- **Cycle-time distribution**: Average cycle time improves by 10%. Tail cycle times for high-complexity cases improve slightly.
- **Rework and quality pattern**: Fewer misrouted cases; rework rate decreases by 2%.
- **Role clarity and accountability**: Clear guidance on shared queue ownership, with minimal confusion.
- **Fairness implications**: East team experiences significant workload relief; North/South rely slightly more on centralized expertise but adapt well.
- **Early warning signs**: None; all metrics align with expected improvements.

## Central Scenario
- **Handover pattern**: Reduced local loops, but more referrals to centralized Technical and Legal/Risk queues.
- **Queue/waiting-time pattern**: Slight uptick in median wait times (4–6 hours), especially in shared queues.
- **Cycle-time distribution**: Improved averages, but tail delays remain for high-complexity and specialty cases.
- **Rework and quality pattern**: Initial rise in rework from shared queue errors, eventually stabilized.
- **Role clarity and accountability**: Local decision-making reduces; central queues face some ownership confusion.
- **Fairness implications**: North/South perceive reduced autonomy; East benefits from technical load sharing.
- **Early warning signs**: Complaints about increased queue times or unresolved specialist requests.

## Adverse Scenario
- **Handover pattern**: High-complexity cases repeatedly loop back due to long shared queues and unclear ownership.
- **Queue/waiting-time pattern**: Shared queues become bottlenecks; waiting times for technical and legal queues exceed 10 hours frequently.
- **Cycle-time distribution**: Average cycle time improves, but 90th percentile worsens drastically.
- **Rework and quality pattern**: Rework rate rises by 3-5%; corrective handovers spike.
- **Role clarity and accountability**: Responsibility confusion leads to dropped cases; local teams disengage.
- **Fairness implications**: East benefits slightly, but North/South struggle with loss of expertise. Customer fairness issues arise in underserved regions or segments.
- **Early warning signs**: Surge in unresolved shared-queue cases, higher SLA misses, and staff feedback indicating frustration.

# 4. Risks invisible in average cycle time

1. **Tail latency**: Improved averages hide increases in extreme delays for high-complexity cases.
2. **High-complexity cases**: Overloaded shared queues delay specialized reviews.
3. **Local knowledge loss**: Reduced informal advice increases errors not detected at process level.
4. **Fairness**: Regional adaptations are overlooked, harming underserved customer segments.
5. **Learning loss**: Local staff stop building technical expertise, leading to overdependence on centralized specialists.
6. **Accountability issues**: Shared approvals and queues blur ownership of outcomes, leading to dropped cases and unaddressed concerns.

# 5. Pilot design

### Pilot Scope
- Centralize Technical and Specialist Review for East team only.

### Comparison Group
- Maintain current local processes in North and South as control groups.

### Pre/Post Observation Window
- **Pre**: 2 months baseline data.
- **Post**: 4 months of pilot operations.

### Segmentation
- By **team**, **case complexity**, **specialty**, and **customer segment**.

### Guardrail Metrics
- Tail cycle times (90th percentile).
- Queue times exceeding thresholds per shared queue.
- Rework rates on cases with shared queue interactions.
- Customer satisfaction scores split by region and segment.

### Staff Feedback Collection
- Weekly staff surveys.
- Focus groups after 2-4 months of pilot.

### Rollback or Adjustment Triggers
- Shared queue waiting times > 2x baseline for high-complexity cases.
- SLA miss rates increase by >10%.
- Significant rise in rework or unresolved cases.

# 6. Recommendation

**Recommendation: Pilot First**

A pilot rollout is essential for evaluating effects across teams, complexity levels, and customer segments. Management should:
- Avoid inferring success from early averages as hidden risks (tail latency, fairness, accountability issues) take time to surface.
- Focus monitoring on queue times, team dynamics, and fairness metrics rather than average cycle time alone.
- Use East as a testbed to manage expectations and refine the model prior to full rollout.
