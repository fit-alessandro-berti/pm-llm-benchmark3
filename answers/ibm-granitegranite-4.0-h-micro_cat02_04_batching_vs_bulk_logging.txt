# 3. Consequences for performance analysis

- **G1-G4**: Genuine simultaneous batch leads to underestimation of waiting time and overestimation of service time. Throughput may appear high due to perceived parallelism, while resource utilization looks efficient.
- **G5**: Concurrent work or multitasking can inflate waiting times due to resource contention. Service time may appear shorter if tasks switch quickly. Utilization could be high if resources are used flexibly.
- **G6**: End-of-shift data entry can inflate waiting times while showing near-zero service time. Utilization may appear low due to perceived batching, but true service time is hidden.
- **G7**: Legacy MES rounding can create the illusion of simultaneous batch processing, obscuring true concurrency. Waiting times may be underestimated, and service times overestimated.
- **G8**: Queue accumulation after capacity loss can create misleading patterns of simultaneous batch work. Waiting times may be artificially high, and service times appear shorter due to perceived batching.

# 4. PM4Py and pandas analysis

```python
import pandas as pd
from pm4py.objects.log.factory import create_log
from pm4py.objects.log.xml_parser import XmlParserFactory
from pm4py.algo.discovery.batch.discover_batches import DiscoverBatches

# Construct the log
log_data = """<your_data_here>"""
log_factory = XmlParserFactory()
log = create_log(log_data, log_factory)

# Discover batches with different parameters
batch_results = []
for merge_distance in [60, 120]:  # 1 min, 2 min
    for min_batch_size in [2, 5]:  # 2, 5 cases
        result = DiscoverBatches(log, merge_distance=merge_distance, min_batch_size=min_batch_size)
        batch_results.append(result)

# Diagnostics
diagnostics = []
for result in batch_results:
    df = result.batch_log
    diagnostics.append({
        'Cluster': result.cluster_name,
        'Overlap Rate': df['overlap'].mean(),
        'Start Equality Groups': df['start_equal'].nunique(),
        'End Equality Groups': df['end_equal'].nunique(),
        'Recording Lag': df['record_lag'].mean(),
        'Timestamp Granularity': df['precision'].nunique(),
        'Queue Build-up': df['queue_arrival'].isnull().sum()
    })

print(diagnostics)
```

# 6. Data-collection redesign

1. **Execution timestamps**: Capture start and complete times with high precision (microseconds if possible).
2. **Recording timestamps**: Log the exact time of database insertion to distinguish between logging batches and real concurrent work.
3. **Source clocks**: Ensure all sources use synchronized clocks or provide a correction factor for clock drift.
4. **Resource/badge identity**: Use unique identifiers for each user or resource to distinguish shared accounts from individual users.
5. **Group/batch identifiers**: Assign batch numbers or timestamps indicating when a batch started and ended.
6. **Workstation capacity**: Monitor the capacity of each workstation to understand queue buildup and resource utilization.
7. **Pause/resume events**: Log any pauses or resumptions in workflow to distinguish between true batch processing and intentional breaks.
8. **Timestamp precision metadata**: Record the documented precision of each source to distinguish between logging batches and actual concurrent work.
