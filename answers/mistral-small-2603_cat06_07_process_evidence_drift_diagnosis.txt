## 2. Competing explanations and timeline

**January–March (baseline)**
- Stable variant mix (V1 45%, V2 35%, V3 20%).
- AUROC ~0.81–0.82, Brier ~0.13, ECE ~0.02.
- Median `Order Part  Part Received` ~30 h.
- **Conclusion**: No drift; model performs as expected.

**April (schema/pipeline incident)**
- Workflow-system migration renamed `Initial Diagnosis Completed` to `Diagnostic Assessment Completed`.
- 17% UNKNOWN_ACTIVITY, 14% missing queue feature, AUROC collapses to 0.67, ECE spikes to 0.110.
- Variant mix shows 18% unmapped/other.
- **Conclusion**: Data-pipeline failure; not a real performance drop.

**May (partial recovery)**
- Mapping patch deployed; most April records backfilled.
- UNKNOWN_ACTIVITY drops to 2%, missing queue feature to 3%.
- AUROC recovers to 0.78, but Brier and ECE remain elevated (0.146, 0.050).
- **Conclusion**: Pipeline partially repaired; residual covariate drift due to cached features.

**June (process mix change)**
- New remote-routing policy increases V2 share from 35% to 52%.
- V3 share drops to 18%.
- AUROC remains ~0.79, Brier ~0.139, ECE ~0.060.
- **Conclusion**: Process drift (routing mix) without concept drift; model generalizes to new mix.

**July (early supplier issues)**
- V3 share rises to 22%.
- Median `Order Part  Part Received` time increases to 65 h.
- AUROC ~0.76, Brier ~0.151, ECE ~0.042.
- **Conclusion**: Early signs of supplier-driven process drift; no immediate model degradation.

**August (supplier crisis)**
- V3 share jumps to 35%.
- Median `Order Part  Part Received` time spikes to 130 h.
- V3 breach rate jumps to 0.64.
- AUROC ~0.68, Brier ~0.197, ECE ~0.120.
- **Conclusion**: Overlapping process drift (supplier delays) and concept drift (V3 risk increases); model underestimates risk.

**September (Partner Z population shift)**
- Partner Z onboarded; 24% of cases, 58% of Partner Z cases follow V3.
- V3 share rises to 42%.
- Partner Z breach rate (immature) ~0.45 vs 0.27 for others.
- AUROC ~0.66, Brier ~0.214, ECE ~0.140.
- **Conclusion**: Population shift (Partner Z) and concept drift (higher V3 risk) overlap; model not calibrated for rural travel distance or device age.

**October (label immaturity)**
- Label maturity drops to 55%; median label delay 52 d.
- Outcome API backlog disproportionately affects longer resolution paths (V3).
- Observed breach rate (0.16) diverges from mature months.
- **Conclusion**: Label delay/censoring dominates; not a real performance drop.

## 4. Recalibration-versus-retraining decision

**Immediate containment (next 2 weeks)**
- Freeze April–May predictions; reprocess April–May events with corrected activity labels and duplicate removal.
- Deploy variant-specific dispatch thresholds for V3-heavy routing (June onward).
- Add Partner Z flag and rural travel distance feature to pipeline; backfill missing values.

**Short-term recalibration (next 4 weeks)**
- Recalibrate model on Jan–Mar data (mature labels) with corrected features.
- Recompute all derived features for April–May with normalized activity labels.
- Stratify calibration and discrimination by variant and source (Partner Z vs others).
- Adjust dispatch thresholds for V3 based on August–September breach rates.

**Feature repair (next 6 weeks)**
- Add rural travel distance and device age features; retrain on Jan–Mar data.
- Recompute `number of events before diagnosis` feature for April–May with corrected activity labels.
- Audit and backfill missing queue feature for April.

**Full retraining (next 8–12 weeks)**
- Retrain on Jan–Aug data (exclude September–October due to Partner Z population shift and label immaturity).
- Include variant-specific intercepts and interactions for V3 and Partner Z.
- Validate on held-out September data (mature labels only).
- **Unsafe months for training**: September–October (immature labels); April–May (pipeline issues until reprocessed).

**Segment-specific or variant-specific model**
- Justified for V3 and Partner Z due to distinct risk profiles and features.
- Deploy as ensemble: base model for V1/V2; variant-specific head for V3; source-specific head for Partner Z.

## 5. Monitoring architecture

**Monitors**
1. **Predictive monitor**: AUROC, Brier, ECE by month (alert if AUROC < 0.75 or ECE > 0.05).
2. **Calibration monitor**: ECE by variant and source (alert if ECE > 0.05 for any stratum).
3. **Label-maturity monitor**: Median label delay and % mature labels by month (alert if median delay > 40 d or maturity < 80%).
4. **Data-quality monitor**: UNKNOWN_ACTIVITY share, missing queue feature, duplicate rate (alert if >2% for any).
5. **Process-variant monitor**: Variant distribution vs baseline (alert if V3 share >30% or V2 share >60%).
6. **Performance-DFG monitor**: Median time on `Order Part  Part Received` and `Diagnostic Assessment  Remote Fix` (alert if >100 h or >10 h respectively).
7. **Population monitor**: Partner Z share and breach rate by source (alert if Partner Z share >30% or breach rate >0.40).
8. **Intervention/deployment monitor**: Dispatch thresholds and model version (alert if thresholds not updated for >2 weeks).

**Alert dependencies**
- Label-delay alarm  suppress predictive performance alarms for that month.
- Data-quality alarm  suppress calibration alarms until pipeline fixed.
- Process-variant alarm  trigger dispatch threshold review, not model retraining.

**Python code sketch**

```python
import pandas as pd
from pm4py.objects.conversion.log import converter as log_converter
from pm4py.objects.log.util import dataframe_utils
from pm4py.util import constants
from pm4py.algo.discovery import discover_dfg, discover_performance_dfg
from pm4py.algo.filtering import filter_time_range
from pm4py.statistics import get_variants
from pm4py.util import xes_constants as xes
import datetime

def monthly_process_evidence(events_path: str, year: int, month: int) -> dict:
    # Read and normalize
    df = pd.read_csv(events_path)
    df = dataframe_utils.convert_timestamp_columns(df)
    df = df[df[constants.CASE_CONCEPT_NAME].notna()]

    # Normalize renamed diagnosis labels
    diag_old = "Initial Diagnosis Completed"
    diag_new = "Diagnostic Assessment Completed"
    df["activity"] = df["activity"].replace(diag_new, diag_old)

    # Deduplicate: keep first event per case-timestamp-activity
    df = df.sort_values([constants.CASE_CONCEPT_NAME, "timestamp", "activity"])
    df = df.drop_duplicates(subset=[constants.CASE_CONCEPT_NAME, "timestamp", "activity"], keep="first")

    # Cohorts
    case_start_col = "case_start_timestamp"  # externally provided
    cohort = df[df["timestamp"].dt.to_period("M") == pd.Period(year=year, month=month, freq="M")]
    case_starts = df[df[case_start_col].dt.to_period("M") == pd.Period(year=year, month=month, freq="M")]

    # DFG and performance DFG
    log = log_converter.apply(cohort, variant=log_converter.Variants.TO_DATA_FRAME)
    dfg = discover_dfg(log)
    perf_dfg = discover_performance_dfg(log)

    # Variants
    variants = get_variants(log)

    # Monthly summary
    summary = {
        "month": f"{year}-{month:02d}",
        "cases_started": len(case_starts[constants.CASE_CONCEPT_NAME].unique()),
        "median_order_part_received_days": perf_dfg.get(("Order Part", "Part Received"), {}).get("median", None),
        "median_diag_to_remote_hours": perf_dfg.get((diag_old, "Remote Fix"), {}).get("median", None),
        "unknown_activity_share": (cohort["activity"] == "UNKNOWN_ACTIVITY").mean(),
        "duplicate_rate": 1 - len(cohort) / len(df[df["timestamp"].dt.to_period("M") == pd.Period(year=year, month=month, freq="M")].drop_duplicates()),
        "dfg_edges": len(dfg),
        "variants_count": len(variants),
    }
    return summary
```

## 6. Risks of acting on the wrong diagnosis

| Failure mode | Risk | Mitigation |
|---|---|---|
| **Retraining on immature October labels** | Model learns biased breach patterns from censored data; degrades September performance. | Freeze October predictions; prioritize outcome backlog resolution; report October with maturity caveat. |
| **Calibrating around April pipeline bug** | Model overfits to corrupted features; poor generalization to clean data. | Reprocess April–May events with corrected activity labels and duplicate removal before any recalibration. |
| **Ignoring genuine supplier-driven concept drift** | Model underestimates V3 risk; breach rate rises in August–September. | Stratify model by variant; add supplier delay feature; adjust dispatch thresholds for V3. |
| **Attributing Partner Z population shift to unfair model behavior** | Model unfairly penalizes Partner Z; leads to incorrect remediation (e.g., throttling Partner Z cases). | Reweight training data; add rural travel distance and device age features; validate with stratified calibration. |
