## 1. Control-Objective Decomposition

1.  **Unauthorized Initiation (Fraudulent Preparation):** A single actor creates a payment request without legitimate business need.
    *   *AV-2:* Detects anomalies (duplicate, sanctions) but cannot validate business intent.
    *   *MG-4:* Preventive if before release; Detective if after.
    *   *RA-7:* Detective (post-event).
    *   *ED-1:* Allows single initiation only under strict emergency constraints.
2.  **Unauthorized Authorization (Fraudulent Release):** The preparer bypasses approval to release funds.
    *   *AV-2:* Preventive (blocks if limits exceeded).
    *   *MG-4:* Primary preventive control (independent sign-off).
    *   *RA-7:* Detective (audit after release).
    *   *ED-1:* Waives requirement only if MG-4 occurs before settlement.
3.  **Erroneous Data Entry (Operational Error):** Correct intent, wrong amount/vendor.
    *   *AV-2:* Strong preventive (PO match, limit checks).
    *   *MG-4:* Strong preventive/detective (manager review).
    *   *RA-7:* Detective (recovery if timely).
    *   *ED-1:* Does not reduce error risk; relies on AV-2.
4.  **Collusion (Bypassing Segregation):** Two actors conspire to defeat independent checks.
    *   *AV-2:* Ineffective against collusion.
    *   *MG-4:* Ineffective if manager is complicit or relationship creates conflict (e.g., supervisor/subordinate).
    *   *RA-7:* Ineffective if auditors are part of the ring.
    *   *ED-1:* Does not address collusion risk; relies on token/audit.
5.  **Account Compromise (Bank Detail Fraud):** Vendor bank details changed to attacker account.
    *   *AV-2:* Strong preventive (checks bank change in previous 7 days).
    *   *MG-4:* Strong preventive (must validate bank details).
    *   *RA-7:* Corrective only if recall window open.
    *   *ED-1:* Explicitly forbids if bank change in previous 7 days.

## 2. Equivalence and Sufficiency Test

A compensating control package is **Fully Equivalent** if it achieves the same risk reduction as FEP-1 without introducing new vulnerabilities. It is **Partially Equivalent** if it reduces risk significantly but leaves residual exposure (e.g., timing gaps). It is **Merely Mitigating** if it addresses only a subset of threats. It is **Ineffective** if it fails to address the core threat.

**Structured Test Criteria:**
*   **Timing:** Controls must occur *before* irrevocable bank settlement. Post-settlement controls are detective/corrective only.
*   **Independence:** The approver must not be the preparer/releaser and must not have a conflict of interest (e.g., direct reporting line).
*   **Coverage:** Controls must cover the specific threat vector (e.g., AV-2 covers data errors, not collusion).
*   **Overrideability:** Human overrides (e.g., AV-2 warnings) must require higher-level authorization and justification.
*   **Recoverability:** If a control fails, funds must be recallable (e.g., within 24h window).
*   **Evidence Quality:** Logs must be immutable and link specific human actors to actions (no shared accounts).
*   **Collusion Resistance:** Segregation must be physical or logical enough to prevent two actors from bypassing checks together.

**Why "Same Expected Loss" is Insufficient:**
Focusing solely on expected loss (Probability × Impact) ignores **control integrity**. A process with low expected loss due to low volume but high vulnerability to fraud (e.g., single-user emergency mode) creates systemic risk. If the control objective is "independent verification," a single user bypassing it constitutes a failure of the *objective*, even if no money was lost. Compliance requires adherence to the control design logic, not just the outcome.

## 4. Preventive–Detective–Corrective Comparison

| Control | Primary Type | Timing Requirement | Strength | Weakness |
|---|---|---|---|---|
| **AV-2** | Preventive | Before Release | Blocks errors/fraud automatically. | Cannot detect collusion or validate commercial reasonableness. |
| **MG-4** | Preventive (if < Release) | Before Release/Settlement | Human judgment on intent and data. | Subject to conflict of interest or rubber-stamping. |
| **MG-4** | Detective (if > Release) | After Release, Before Settlement | Hybrid: Can stop settlement if caught. | Funds may be in transit; recovery uncertain. |
| **RA-7** | Detective | After Settlement | Identifies patterns/fraud post-event. | No recovery if recall window closed. |
| **ED-1** | Exception | Conditional | Enables business continuity. | High risk if conditions (token, audit) are faked. |

**Manager Action Semantics:**
A manager action **before Release_Payment** is **Preventive** because it stops the transaction from entering the bank queue.
A manager action **after Release_Payment but before Bank_Settlement** is **Hybrid (Detective/Corrective)**. It is detective because the release command has been sent, but corrective because the bank settlement (irrevocable transfer) has not occurred, allowing the manager to potentially recall or block the transaction at the bank interface.
A manager action **after Bank_Settlement** is **Detective** only. The control objective of preventing the transfer has failed; the goal shifts to recovery and accountability.

## 6. Evidence and Monitoring Recommendations

1.  **Same-User Rate:** Alert if >5% of payments are single-user without ED-1 token. *Alert vs Proof:* High rate indicates process drift; proof requires investigation of specific cases.
2.  **Override Rate:** Alert if AV-2 warning overrides exceed 2% of total volume. *Alert vs Proof:* High rate suggests system tuning issues or user bypass behavior.
3.  **Late Manager Approval:** Flag any MG-4 occurring after Bank_Settlement. *Alert vs Proof:* Indicates control failure; proof requires investigation of why settlement wasn't blocked.
4.  **Audit-Before-Recall-Window:** Monitor % of emergency payments audited within 24h. *Alert vs Proof:* Low % increases loss exposure; proof of negligence requires audit logs.
5.  **Repeated Resource Pairs:** Detect pairs (u12, u13) appearing together >10 times/month. *Alert vs Proof:* Suggests collusion risk; proof requires workstation/network logs.
6.  **Bank-Change Proximity:** Flag payments with bank changes <7 days prior. *Alert vs Proof:* High fraud risk; proof requires vendor confirmation.
7.  **Control Outages:** Track AV-2 unavailability duration. *Alert vs Proof:* Systemic risk; proof requires IT incident reports.

**Alert vs Proof:** An alert signals a deviation from the norm requiring investigation. Proof of misconduct requires corroborating evidence (e.g., logs, witness testimony, financial trails). Alerts are necessary for monitoring but insufficient for disciplinary action without further evidence.
