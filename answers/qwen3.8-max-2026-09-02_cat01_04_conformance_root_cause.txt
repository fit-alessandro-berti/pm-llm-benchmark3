```
def variants_to_xes(variants, prefix, map_label=False, remove_queue_routed=False):
    lines = ['<?xml version="1.0" encoding="UTF-8"?>', '<log>']
    case_id=0
    for trace_string, count in variants:
       acts = normalize_trace_string(trace_string, map_label, remove_queue_routed)
       if not acts: continue
       for _ in range(count):
          case_id += 1
          lines.append('<trace>')
          lines.append(f'<string key="concept:name" value="{prefix}_{case_id}"/>')
          for act in acts:
             lines.append('<event>')
             lines.append(f'<string key="concept:name" value="{escape(act, {chr(34): "&quot;"})}"/>')
             lines.append('</event>')
          lines.append('</trace>')
    lines.append('</log>')
    return '\n'.join(lines)
```

The observed collapse is overdetermined. The UI release did not necessarily change work, but it changed the activity label, so every post-May case immediately incurred a move on log (`Risk Screen`) and a move on model (`Classify`). The gateway then emitted `Queue Routed`, a technical event absent from the policy model, adding spurious log moves. The ETL change made warehouse-ingestion time authoritative for `Decision`/`Notify`, creating apparent sequence violations; source-sequence ordering recovers many of them. On 1 August, the real process did change for a subset of cases: supervisor sign-off became required for high-value claims, but the normative tree was not updated, so legitimate behaviour appears as deviations. Manual override may be another real corrective behaviour or a logging-semantics issue. Thus the same alignment cost can contain label noise, technical-event noise, timestamp inversions, and genuine model obsolescence. Stable appeal and approval rates do not prove the log is clean: business outcomes are slow, aggregate, and affected by incomplete incident detection. Conversely, they do not rule out noncompliance: a small number of bypassed compliance checks may not move appeals immediately, especially if detection is incomplete. The remaining enhanced-review traces without compliance checks are therefore the most serious operational residue, but they require source-system audit before being attributed to employee misconduct.

```python
XML_ESCAPES = {'"': "&quot;"}

def normalize_trace_string(trace_string, map_label=True, remove_queue_routed=True):
    activities = [a.strip() for a in trace_string.split(",")]
    normalized = []

    for activity in activities:
        if map_label and activity == "Risk Screen":
            activity = "Classify"

        if remove_queue_routed and activity == "Queue Routed":
            continue

        normalized.append(activity)

    return normalized


def variants_to_xes(variants, prefix, map_label=False, remove_queue_routed=False):
    lines = ['<?xml version="1.0" encoding="UTF-8"?>', "<log>"]
    case_id = 0

    for trace_string, count in variants:
        activities = normalize_trace_string(
            trace_string,
            map_label=map_label,
            remove_queue_routed=remove_queue_routed,
        )

        if not activities:
            continue

        for _ in range(count):
            case_id += 1
            lines.append("<trace>")
            lines.append(f'<string key="concept:name" value="{prefix}_{case_id}"/>')

            for activity in activities:
                escaped = escape(activity, XML_ESCAPES)
                lines.append("<event>")
                lines.append(f'<string key="concept:name" value="{escaped}"/>')
                lines.append("</event>")

            lines.append("</trace>")

    lines.append("</log>")
    return "\n".join(lines)


def load_log(variants, prefix, map_label=False, remove_queue_routed=False):
    xes_string = variants_to_xes(
        variants,
        prefix=prefix,
        map_label=map_label,
        remove_queue_routed=remove_queue_routed,
    )

    # Required PM4Py parsing entry point.
    try:
        return pm4py.parse_event_log_string(xes_string)
    except Exception:
        # Fallback for environments where parse_event_log_string is unavailable
        # or where the XES string parser is not enabled. The required method is
        # still attempted first.
        from pm4py.objects.log.obj import EventLog, EventTrace, Event

        log = EventLog()

        for trace_string, count in variants:
            activities = normalize_trace_string(
                trace_string,
                map_label=map_label,

            )

            for _ in range(count):

                for activity in activities:

def get_dfg(log):
    result = pm4py.discover_dfg(log)
    if isinstance(result, tuple):
        return result[0]

def top_edges(dfg, n=5):
    return sorted(dfg.items(), key=lambda kv: kv[1], reverse=True)[:n]


def get_alignments(log, net, im, fm):
    try:
        return pm4py.conformance_alignments(log, net, im, fm), None
    except Exception as exc:
        try:
            return pm4py.apply_alignments(log, net, im, fm), None
        except Exception as exc2:
            return None, f"alignment failed: {exc}; fallback failed: {exc2}"


def alignment_diagnostics(alignments):
    if alignments is None:
        return {"error": "alignments unavailable"}

    n = len(alignments)
    costs = []
    perfect = 0

    for alignment in alignments:
        if not isinstance(alignment, dict):
            continue

        cost = alignment.get("cost")
        if cost is not None:
            costs.append(cost)

        if cost == 0 or alignment.get("fitness") == 1:
            perfect += 1

    return {
        "aligned_traces": n,
        "mean_cost": sum(costs) / len(costs) if costs else None,
        "zero_cost_share": perfect / n if n else None,
    }


def get_fitness(log, net, im, fm):
    try:
        return pm4py.fitness_alignments(log, net, im, fm), None
    except Exception as exc:
        return None, str(exc)


def summarize_fitness(fitness_result):
    if fitness_result is None:
        return None

    if isinstance(fitness_result, dict):
        for key in ("averageFitness", "average_fitness", "log_fitness", "fitness"):
            if key in fitness_result:
                return fitness_result[key]
        return fitness_result

    if isinstance(fitness_result, (list, tuple)):
        return fitness_result[0] if len(fitness_result) > 0 else fitness_result

    return fitness_result


def get_precision(log, net, im, fm):
    try:
        return pm4py.precision_alignments(log, net, im, fm), None
    except Exception as exc:
        return None, str(exc)

    if precision_error:
        print("precision:", precision_error)
    else:
        print("precision:", precision_raw)

    print()
```

## 7. Provisional conclusion

Primary explanation: The measured conformance collapse is best explained as a composite measurement and model-governance failure, not a sudden breakdown of operational discipline. The label change from `Classify` to `Risk Screen` created immediate label mismatches; `Queue Routed` introduced an unmodeled technical event; the ETL change made ingestion time authoritative and produced apparent `Decision`/`Notify` inversions; and the August policy added `Supervisor Sign-off` without updating the normative tree. Together these explain most of the fitness decline and the staged recovery after remapping, filtering, and source-sequence ordering. Confidence: high, about 85%, that measurement/model causes are the primary driver of the reported collapse.

Separate compliance assessment: A real compliance concern may remain, but it is narrower. The persistent enhanced-review traces without recorded `Compliance Check`, plus the supervisor memo, justify targeted audit. `Manual Override` also needs authorization and semantic review. However, stable approvals, appeals, and cycle times do not show a broad operational deterioration, and there is no reliable audit evidence yet that missing checks are true bypasses. Confidence that a material employee-noncompliance problem exists: moderate-to-low, around 35%. Confidence that at least some residual deviations reflect genuine process or control gaps: moderate, around 55%.

Immediate actions: IT should restore source-sequence ordering, publish event semantics, and separate technical events from business events. Process owners should version the normative model and add a data-aware sign-off rule for claims above EUR 50,000. Compliance should audit all enhanced-review cases lacking `Compliance Check` and high-value cases lacking sign-off before drawing disciplinary conclusions.

Do not claim: employee noncompliance caused the collapse; the process is stable because appeals are stable; or the optional sign-off model is a compliant control. It may overgeneralize.

## 8. Model-governance recommendation

1. Maintain versioned normative models with effective dates, change owners, and mandatory update triggers when policy, UI, routing, or data semantics change.

2. Publish and enforce an event-semantic contract that maps UI labels, system actions, and canonical process activities; any release changing labels must include a conformance mapping before reporting.

3. Classify technical events explicitly in the event taxonomy and exclude them from control-flow conformance checking unless they represent business decisions or required controls.

4. Preserve timestamp provenance by storing event time, source-system time, warehouse-ingestion time, and source sequence number; conformance checking should default to the most operationally valid ordering, not ingestion time.

5. Encode data-aware constraints, such as supervisor sign-off for claims above EUR 50,000, using case attributes or data-aware conformance rules rather than relying on control-flow-only process trees.

6. Require post-release validation: after UI, ETL, gateway, or policy changes, compare variants, DFGs, alignment moves, fitness, precision, and a manual audit sample before interpreting conformance deterioration as operational failure.
