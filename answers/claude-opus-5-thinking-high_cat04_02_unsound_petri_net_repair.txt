# 1. Executive Verdict

**Workflow net?** Yes. There is exactly one source place (`source`, no input arcs), exactly one sink place (`sink`, no output arcs), and every place and transition lies on a directed `source → … → sink` path, so `check_is_workflow_net` should return `True`.

**Should it be sound?** Yes — the stated intent (always terminate in exactly `fm`, no residue) is precisely classical soundness.

**It is not sound.** Principal defect: `t_join_waived` is a "join" in name only. It has a single input place, `p_waived`, so the waiver route never synchronizes with the mandatory analysis branch. The token that `t_split` puts into `p_analysis` is never consumed on that route.

**Business consequence:** a waived case can be authorized *before* the analysis finishes, and it always terminates with an orphan token stranded in `p_analysis` or `p_analysis_done`. The case looks closed and simultaneously never closes.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source`, `im = [source]` | Unique start place, one token | Correct: no input arcs, single token | None |
| `t_register` → `p_ready` | Case intake | Correct sequential step | None |
| `t_split` (silent) | AND-split into analysis and review | Correct AND-split: one input `p_ready`, two outputs `p_analysis`, `p_review`; produces two concurrent tokens | Two live branches that **must** be re-synchronized exactly once; only one of the two join paths actually does so |
| `p_analysis` → `t_analyze` → `p_analysis_done` | Mandatory analysis branch | Correct as a branch, but `p_analysis_done` has exactly one output arc, to `t_join_normal` | The analysis token is consumable **only** through `t_join_normal`; if that transition never becomes enabled, the token is permanently stranded |
| `p_review` with `t_standard_review` / `t_waive_review` | XOR choice of review outcome | Correct free-choice XOR: both transitions share the single input place `p_review`, so firing one disables the other | Fine; the defect is downstream, not here |
| `t_standard_review` → `p_review_done` | Normal review outcome | Correct | None |
| `t_waive_review` → `p_waived` | Waiver outcome | Structurally correct as an outcome place, but it is routed into a degenerate join | Waiver route bypasses synchronization |
| `t_join_normal` (silent) | AND-join of analysis + standard review | **Correct** two-input AND-join: `p_analysis_done` and `p_review_done` → `p_decision` | Healthy on the standard route only |
| `t_join_waived` (silent) | Intended AND-join of analysis + waiver | **Degenerate**: exactly one input place (`p_waived`) and one output (`p_decision`). It is a silent pass-through / relabeling, not a join | Waiver alone enables authorization; analysis branch left unsynchronized; leftover token; premature authorization |
| `p_decision` → `t_authorize` → `sink` | Single authorization step | Correct locally, but `p_decision` can be marked while the analysis branch is still live | Authorization not causally preceded by analysis on the waiver route |
| `fm = [sink]` | Exact final marking | Correct as a specification; the net cannot always attain it | `sink` marked **plus** residue ⇒ improper completion |
| Connectivity (short-circuit view) | Every node on a source-to-sink path | Satisfied for all 9 places and 8 transitions; no dead transitions either — `t_join_waived` and `t_join_normal` are both quasi-live | A purely structural check (and any check limited to "dead transitions") **passes**, which is exactly why this bug survives review |

Key asymmetry: the net contains one genuine two-input synchronization (`t_join_normal`) and one fake one (`t_join_waived`). The AND-split produces two tokens on every run; only the standard-review route consumes both.

# 3. Marking-Based Counterexample

Markings are written as multisets of nonzero places; all places not listed hold 0 tokens. The net is 1-safe, so every entry below is 0 or 1.

## 3.1 Counterexample A — waiver taken before analysis completes

Legal firing sequence from `im`:

`t_register → t_split → t_waive_review → t_join_waived → t_authorize → t_analyze`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (`im`) | `[source]` | `t_register` | Start |
| 1 | `t_register` | `[p_ready]` | `t_split` | Intake done |
| 2 | `t_split` | `[p_analysis, p_review]` | `t_analyze`, `t_standard_review`, `t_waive_review` | **Two concurrent tokens created**, one per parallel branch |
| 3 | `t_waive_review` | `[p_analysis, p_waived]` | `t_analyze`, `t_join_waived` | Waiver route chosen; `t_standard_review` is now permanently disabled (`p_review` is empty and nothing ever re-marks it). The analysis token is still untouched |
| 4 | `t_join_waived` | `[p_analysis, p_decision]` | `t_analyze`, `t_authorize` | **The defect fires here.** `t_join_waived` needs only `p_waived`, so it enables authorization while the analysis branch is still pending |
| 5 | `t_authorize` | `[p_analysis, sink]` | `t_analyze` | `t_authorize` occurs **before** `t_analyze`. A token exists in `sink`, but the reached marking is `[p_analysis, sink] ≠ fm = [sink]`: `fm` has **not** been reached |
| 6 | `t_analyze` | `[p_analysis_done, sink]` | *(none)* | **Dead marking, and it is not `fm`.** The run is stuck |

Why the leftover token can never be consumed: the only output arc of `p_analysis_done` goes to `t_join_normal`, which additionally requires a token in `p_review_done`. `p_review_done` is produced only by `t_standard_review`, which requires `p_review`, which is produced only by `t_split`, which requires `p_ready`, which is produced only by `t_register`, which requires `source`. All of those places are empty and no transition can ever re-mark them (the net is acyclic). Hence `p_review_done` is unreachable from step 3 onward, `t_join_normal` is dead from step 3 onward, and the token in `p_analysis_done` is permanently stranded.

Two distinct soundness violations are exposed by this one run:

1. **Option to complete fails.** From the marking at step 4 (indeed from step 3), `fm` is not reachable at all — every maximal continuation dead-ends in `[p_analysis_done, sink]` (or, if step 6 is not taken, in `[p_analysis, sink]`, which is dead as well once `t_analyze` is the only enabled transition — firing it is the only continuation, so the unique dead marking of this branch is `[p_analysis_done, sink]`).
2. **Proper completion fails.** The reached dead marking strictly dominates the final marking: `[p_analysis_done, sink] > fm`. "A token is in the sink" is true; "the exact final marking `fm` has been reached" is false. Any tool that only tested `sink ≥ 1` would wrongly declare success.

Note also that `t_authorize` **can** occur either before `t_analyze` (steps 5–6 above) or after it (Counterexample B), because after step 3 the two are completely concurrent — there is no causal constraint between them on the waiver route. That is the business-rule violation, and it is separable from the leftover-token violation.

## 3.2 Counterexample B — additional defect: even the "well-behaved" waiver run terminates improperly

This second sequence performs the analysis first, i.e. it respects the business ordering, and still fails. It shows the residue defect is *not* merely a consequence of a bad interleaving.

`t_register → t_split → t_analyze → t_waive_review → t_join_waived → t_authorize`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (`im`) | `[source]` | `t_register` | Start |
| 1 | `t_register` | `[p_ready]` | `t_split` | — |
| 2 | `t_split` | `[p_analysis, p_review]` | `t_analyze`, `t_standard_review`, `t_waive_review` | Token created in each parallel branch |
| 3 | `t_analyze` | `[p_analysis_done, p_review]` | `t_standard_review`, `t_waive_review` | Analysis genuinely completed first |
| 4 | `t_waive_review` | `[p_analysis_done, p_waived]` | `t_join_waived` | Both branches are "done" in business terms; a correct AND-join would consume both tokens here |
| 5 | `t_join_waived` | `[p_analysis_done, p_decision]` | `t_authorize` | `t_join_waived` consumes **only** `p_waived`; `p_analysis_done` is left behind because nothing on this route reads it |
| 6 | `t_authorize` | `[p_analysis_done, sink]` | *(none)* | Dead marking `> fm`. Ordering was correct; termination is still improper |

Contrast with the healthy route, which shows the net is only *partially* broken:

`t_register → t_split → t_analyze → t_standard_review → t_join_normal → t_authorize` reaches `[p_decision]` and then exactly `[sink] = fm`, with no residue. Soundness therefore fails **only** on the waiver branch, and no transition is dead — so the net passes every naive structural or liveness-only screening.

# 4. Minimal-Repair Alternatives

## 4.1 Edit-cost model (stated before use)

For an edit set `E` transforming the original net into a candidate:

```
cost(E) = 1 × (#arcs added + #arcs removed)
        + 2 × (#places added + #places removed)
        + 2 × (#transitions added + #transitions removed)
        + 0 × (#pure relabelings, i.e. changes to a transition's visible label or a place's name)
```

Rationale: nodes are weighted `2` because adding or deleting a node necessarily perturbs the diagram, the element inventory, and any log-to-model mapping, whereas an arc is a local rewiring. Relabelings cost `0` in this metric but are audited separately in §7, because a relabeling can change conformance-checking semantics without changing the reachability graph. Markings (`im`, `fm`) are unchanged by all candidates below, so they contribute nothing.

Tie-break order when costs are equal: (i) fewer changes to the trace language of the already-correct standard-review route; (ii) fewer silent transitions in the result; (iii) preservation of existing element identities (`name` fields), because renamed/removed elements break stored alignments and dashboards.

## 4.2 Candidate repairs

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1 — Promote `t_join_waived` to a real two-input synchronization** | Add one arc: `p_analysis_done → t_join_waived`. Nothing else. | **1** (1 arc) | Analysis stays mandatory on both routes; waiver stays a distinct, visibly labeled outcome; standard route byte-for-byte unchanged | Waiver route now blocks until `t_analyze` has fired; `t_authorize` can no longer precede `t_analyze`; both branch tokens are consumed, so the run ends in exactly `fm` | The net retains two silent joins with the same output place; a reader must inspect input arcs to tell them apart. `t_join_waived` becomes non-free-choice-ish in appearance (it still is free-choice here, but the diagram is less obvious). No behavioral risk identified |
| **R2 — Fold the waiver outcome into the normal synchronization** | Remove arc `t_waive_review → p_waived`; add arc `t_waive_review → p_review_done`; remove arcs `p_waived → t_join_waived` and `t_join_waived → p_decision`; remove place `p_waived`; remove transition `t_join_waived`. (Optional 0-cost relabel: `p_review_done → p_review_settled`.) | **8** (4 arcs = 4, 1 place = 2, 1 transition = 2) | Analysis stays mandatory; single AND-join for all routes; the net becomes a textbook sound free-choice WF-net with one AND-split / one AND-join / one XOR-split / one XOR-join | Identical observable trace language to R1; internally the waiver and the standard review converge on one place, so there is one join instead of two | Loses the modeling distinction "which outcome produced the review token" at the *place* level; only the visible transition label `Record Review Waiver` carries it. The cleanup is **not optional**: if `p_waived` and `t_join_waived` were merely orphaned rather than deleted, `p_waived` would have no input arc, the net would then have two input-free places, and `check_is_workflow_net` would return `False` |
| **R3 — Policy change: analysis becomes optional once a waiver is recorded** | *Explicit policy change, see below.* Add arc `p_analysis_done → t_join_waived` (as in R1); add transition `t_skip_analysis` (visible label `"Skip Analysis (Waiver)"`); add arcs `p_analysis → t_skip_analysis`, `p_waived → t_skip_analysis`, `t_skip_analysis → p_analysis_done`, `t_skip_analysis → p_waived` (the last pair is a self-loop that *tests* the waiver without consuming it). | **7** (5 arcs = 5, 1 transition = 2) | Termination in exactly `fm`; waiver remains distinct; standard route unchanged and still mandates analysis | **Business policy changes**: on a waived case the analysis may be skipped by an explicit, *logged* step; the skip is enabled only after `t_waive_review` has fired, so it cannot leak into the standard route | Self-loop on `p_waived` makes the net non-free-choice, which weakens some structural soundness theorems (the behavioral check still applies). Requires sign-off from whoever owns the "analysis is always mandatory" rule. If the skip were made silent (`None` label) it would become an invisible bypass — see §7 |

Not admissible, and worth recording because it looks like a cheaper R1: adding `p_analysis → t_join_waived` instead of `p_analysis_done → t_join_waived` also costs 1, but it deadlocks. If `t_analyze` fires first, `p_analysis` is empty while `p_analysis_done` holds the token, `t_join_waived` can never fire, and the run dies in `[p_analysis_done, p_waived]`. Cost alone does not decide; the candidate must first be behaviorally correct.

## 4.3 Minimality justification

**R1 is minimal, and provably so under this cost model.** Cost 0 is impossible: the original is unsound, and the empty edit changes nothing. Cost 1 admits exactly three edit shapes — add one arc, remove one arc, or relabel (cost 0, but relabeling never changes the reachability graph and therefore never restores soundness).

- *Removing* a single arc cannot fix it. Removing any arc of the waiver route (`t_waive_review → p_waived`, `p_waived → t_join_waived`, `t_join_waived → p_decision`) leaves an input-free or output-free node, breaking the workflow-net property. Removing `t_split → p_analysis` would delete the analysis branch (violating "analysis is always mandatory" and again breaking connectivity for `p_analysis`).
- *Adding* one arc must give `t_join_waived` a second input that is guaranteed to be marked precisely when the waiver is complete, and must consume the analysis-branch token. The only place that satisfies both is `p_analysis_done` (as shown above, `p_analysis` deadlocks; `p_review_done` is unreachable on the waiver route and would deadlock immediately; `p_ready`, `p_review`, `source` are empty by then).

So `p_analysis_done → t_join_waived` is the unique cost-1 repair, hence globally minimal. R2 (8) and R3 (7) are strictly dominated on cost; they are retained because they differ *semantically*, not cosmetically: R2 removes a whole synchronization construct, and R3 alters the business policy.

**On ties.** R1 and R2 do not tie on cost, but they *are* behaviorally equivalent: both yield sound, 1-safe WF-nets whose observable trace languages are the same two sets of runs (analysis interleaved with either `Perform Standard Review` or `Record Review Waiver`, then `Authorize Case`). Where a genuine tie can arise is between R2 and its structural dual R2′ — keep `t_join_waived` (with an added `p_analysis_done` input) and delete `p_review_done`/`t_join_normal` instead, routing `t_standard_review → p_waived`. R2′ is behaviorally identical to R2 but costs 10, because `t_join_normal` carries three arcs to `t_join_waived`'s two; it is therefore dominated. Had they tied, tie-break (iii) would still pick R2, since R2′ deletes the *healthy* half of the model and would invalidate more existing alignments than R2 does.

# 5. Corrected PM4Py Code

Selected repair: **R1** — give `t_join_waived` its proper second input.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

# --- Places -------------------------------------------------------------
source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in [
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
]:
    repaired_net.places.add(p)

# --- Transitions (visible labels preserved verbatim) --------------------
register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in [
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
]:
    repaired_net.transitions.add(t)

# --- Arcs ---------------------------------------------------------------
petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)

# AND-split: one token per parallel branch.
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

# Mandatory analysis branch.
petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

# XOR on the review branch: both transitions share the input place p_review,
# so firing one permanently disables the other.
petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)
petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

# AND-join for the standard-review route.
petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

# REPAIR (R1): t_join_waived had only p_waived as input, so it was a silent
# pass-through, not a join. The single added arc below makes it a genuine
# two-input AND-join, so the waiver route also consumes the analysis token
# and cannot enable authorization before t_analyze has fired.
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)   # <-- added
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

# --- Markings (unchanged by the repair) ---------------------------------
repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

The block below assumes `net`, `im`, `fm` (original) and `repaired_net`, `repaired_im`, `repaired_fm` (from §5) already exist in the namespace.

```python
import copy
import pm4py
from pm4py.objects.petri_net.obj import Marking


# ---------------------------------------------------------------- helpers
def fmt(marking):
    """Deterministic, readable rendering of a marking."""
    items = sorted((p.name, c) for p, c in marking.items() if c > 0)
    return "[" + ", ".join(f"{n}:{c}" for n, c in items) + "]" if items else "[]"


def t_by_name(a_net, name):
    matches = [t for t in a_net.transitions if t.name == name]
    if len(matches) != 1:
        raise KeyError(f"transition {name!r} not uniquely found in {a_net.name}")
    return matches[0]


def is_enabled(t, marking):
    return all(marking.get(arc.source, 0) >= arc.weight for arc in t.in_arcs)


def fire(a_net, marking, name, verbose=True):
    """Fire a named transition. Raises instead of silently moving tokens."""
    t = t_by_name(a_net, name)
    if not is_enabled(t, marking):
        raise RuntimeError(f"{name} is NOT enabled in {fmt(marking)} - refusing to fire")
    new_marking = Marking(copy.copy(marking))
    for arc in t.in_arcs:
        new_marking[arc.source] -= arc.weight
        if new_marking[arc.source] <= 0:
            del new_marking[arc.source]   # keep zero entries out: Marking equality is key-sensitive
    for arc in t.out_arcs:
        new_marking[arc.target] += arc.weight
    if verbose:
        enabled = sorted(t.name for t in a_net.transitions if is_enabled(t, new_marking))
        print(f"  fired {name:<20} -> {fmt(new_marking):<45} enabled: {enabled}")
    return new_marking


def replay(a_net, marking, final_marking, sequence, title):
    print(f"\n--- {title} ---")
    print(f"  start                    {fmt(marking)}")
    m = marking
    for name in sequence:
        try:
            m = fire(a_net, m, name)
        except RuntimeError as exc:
            print(f"  BLOCKED: {exc}")
            break
    dead = not any(is_enabled(t, m) for t in a_net.transitions)
    print(f"  end marking      : {fmt(m)}")
    print(f"  token in sink?   : {any(p.name == 'sink' and c > 0 for p, c in m.items())}")
    print(f"  equals fm?       : {m == final_marking}")
    print(f"  dead marking?    : {dead}")


# ------------------------------------------------- structural + soundness
for label, (n, i, f) in {
    "ORIGINAL": (net, im, fm),
    "REPAIRED": (repaired_net, repaired_im, repaired_fm),
}.items():
    print(f"\n================ {label} ================")
    print("is workflow net :", pm4py.check_is_workflow_net(n))
    print("enabled at im   :", sorted(t.name for t in pm4py.get_enabled_transitions(n, i)))
    print("soundness       :")
    print(pm4py.check_soundness(n, i, f, print_diagnostics=True))


# -------------------------------------------- counterexample replays
CE_A = ["t_register", "t_split", "t_waive_review", "t_join_waived",
        "t_authorize", "t_analyze"]
CE_B = ["t_register", "t_split", "t_analyze", "t_waive_review",
        "t_join_waived", "t_authorize"]
HAPPY = ["t_register", "t_split", "t_analyze", "t_standard_review",
         "t_join_normal", "t_authorize"]

replay(net, im, fm, CE_A, "ORIGINAL / counterexample A (authorize before analyze)")
replay(net, im, fm, CE_B, "ORIGINAL / counterexample B (analyze first, still improper)")
replay(net, im, fm, HAPPY, "ORIGINAL / standard-review route (healthy)")

replay(repaired_net, repaired_im, repaired_fm, CE_A, "REPAIRED / counterexample A (must be blocked)")
replay(repaired_net, repaired_im, repaired_fm, CE_B, "REPAIRED / counterexample B (must now succeed)")
replay(repaired_net, repaired_im, repaired_fm, HAPPY, "REPAIRED / standard-review route (unchanged)")


# ------------------------------------------------- reachability graphs
ts_original = pm4py.convert_to_reachability_graph(net, im, fm)
ts_repaired = pm4py.convert_to_reachability_graph(repaired_net, repaired_im, repaired_fm)

for label, ts in (("ORIGINAL", ts_original), ("REPAIRED", ts_repaired)):
    deadlocks = [s for s in ts.states if len(s.outgoing) == 0]
    print(f"\n{label} reachability graph: |S|={len(ts.states)}, |T|={len(ts.transitions)}")
    print(f"  dead states: {sorted(str(s.name) for s in deadlocks)}")
```

## Expected qualitative difference

- `check_is_workflow_net`: `True` for **both** nets. This is the point of §1 — the structural check does not see the bug, and R1 does not disturb the source/sink/connectivity conditions.
- `check_soundness`: `False` for the original, `True` for the repaired net. The original's diagnostics should concern the option-to-complete / proper-completion side of soundness — reachable markings from which `fm` is unreachable, and dead markings that strictly cover `fm` (a token left in `p_analysis_done` beside the sink token). It should **not** report dead transitions, since every transition of the original is quasi-live. I deliberately do not quote diagnostic keys or counts I have not observed.
- `get_enabled_transitions`: at `im` both nets return `{t_register}`. The interesting difference is mid-run: in the original, `get_enabled_transitions(net, [p_analysis, p_waived])` includes `t_join_waived`; in the repaired net that same marking enables only `t_analyze`. And at `[p_analysis_done, sink]` the original returns the empty set — a deadlock away from `fm`.
- Replays: in the original, `CE_A` and `CE_B` both run to completion and end in the dead marking `[p_analysis_done:1, sink:1]`, with "token in sink" `True` but "equals fm" `False`. In the repaired net, `CE_A` is **blocked** at `t_join_waived` (only `p_waived` is marked; `p_analysis_done` is empty), which is exactly the enabledness check the helper is there to enforce; `CE_B` completes in exactly `fm`; `HAPPY` is unaffected in both.
- `convert_to_reachability_graph`: both graphs are finite, because the net is 1-safe (`t_split` is the only source of concurrency and each place receives at most one token per run). I do not claim exact state counts. Two facts *are* derivable without enumeration: (a) R1 only **adds** an input arc, which can only restrict firing, so the repaired reachable set is a subset of the original's, and it is a strict subset because `[p_analysis, p_decision]` is reachable in the original and impossible in the repaired net; (b) the original graph contains at least one dead state other than `fm`, namely `[p_analysis_done, sink]`, whereas the repaired graph's unique dead state is `fm` itself.

# 7. Repair Trade-Offs and Residual Risks

**Are waiver and standard review still distinguishable?** Under R1, yes and strongly so: `t_waive_review` keeps the visible label `Record Review Waiver`, `p_waived` remains a separate state, and the two routes reach `p_decision` through two different silent joins. Under R2 the distinction survives only at the transition label, since both outcomes deposit into one place; anything downstream that inspected `p_waived` (a report, a filter, a token-based KPI) would break. That is a real, if unglamorous, argument for R1.

**Duplicate behavior / confusion via silent transitions.** R1 leaves three silent transitions (`t_split`, `t_join_normal`, `t_join_waived`), and the two joins are now genuinely similar: both consume `p_analysis_done` plus one review-outcome place and both produce `p_decision`. They are not duplicates — their other input places differ, and those places are mutually exclusive by construction of the XOR at `p_review` — so alignment-based conformance cannot ambiguously choose between them: the choice is already forced by which review transition fired. Still, for a human reader the diagram now has two near-identical τ-joins, and I would attach descriptive names (`t_join_after_standard_review`, `t_join_after_waiver`) as a zero-cost relabel. R2's advantage is precisely that it removes one silent join altogether. R3's silent-transition risk is the sharpest: if the skip were modeled as a τ-transition, an analysis bypass would be *invisible in the event log*, which is why R3 above gives it a visible label.

**Does soundness prove business alignment?** No. Soundness is a statement about tokens, not about policy. Two illustrations from this very model: (i) R3 is sound and yet violates the stated rule "the analysis is always mandatory" — soundness is indifferent to that; (ii) a net in which `t_authorize` were duplicated, or in which the waiver could be recorded after authorization, could still be sound while contradicting intent. Conversely, one could produce a sound net whose waiver route silently drops the analysis entirely. Soundness is necessary, not sufficient; the ordering constraint "authorization only after analysis and the selected review outcome" has to be verified separately, e.g. by an LTL/declarative check (`Authorize Case` is always preceded by `Perform Analysis`) or by inspecting the reachability graph for a state where `t_authorize` is enabled while `p_analysis` or `p_review` is still marked.

**Regression tests.** Positive traces that must be replayable with zero deviation: (1) `Register Case, Perform Analysis, Perform Standard Review, Authorize Case`; (2) `Register Case, Perform Standard Review, Perform Analysis, Authorize Case` (the concurrent interleaving); (3) `Register Case, Perform Analysis, Record Review Waiver, Authorize Case`; (4) `Register Case, Record Review Waiver, Perform Analysis, Authorize Case`. Each must end in exactly `fm`. Negative traces that must **not** fit: (5) `Register Case, Record Review Waiver, Authorize Case` — the pre-repair bug, the single most important regression test; (6) `Register Case, Perform Analysis, Authorize Case` — no review outcome at all; (7) `Register Case, Perform Standard Review, Record Review Waiver, Perform Analysis, Authorize Case` — both review outcomes, which the XOR must forbid; (8) `Register Case, Perform Analysis, Record Review Waiver, Authorize Case, Authorize Case` — double authorization. Assert on the *exact* final marking, never on `sink ≥ 1`: test (5) against the original net would pass a sink-only assertion.

**Detecting an accidental bypass of mandatory analysis.** Four layers, cheapest first. (a) Static: assert that every transition producing a token into `p_decision` has `p_analysis_done` among its input places — a three-line invariant over `net.transitions` that would have caught the original bug at commit time, and that R3 deliberately and visibly breaks. (b) Structural/invariant: compute a place invariant covering the analysis branch, or simply short-circuit the net and check that no path from `t_split`'s review output reaches `t_authorize` without traversing `t_analyze`. (c) Behavioral: enumerate the reachability graph and flag any state in which `t_authorize` is enabled while `p_analysis` still holds a token — zero such states is the acceptance criterion. (d) Runtime, on real logs: token-based replay flagging remaining tokens per case, plus a footprint/precedence check that `Authorize Case` is always preceded by `Perform Analysis` in the same case. Layer (d) is the one that catches a bypass introduced downstream of the model, e.g. by an integration writing directly into `p_decision`.

# 8. Final Recommendation

**Deploy R1** — add the single arc `p_analysis_done → t_join_waived`. **Fallback: R2** — fold the waiver outcome into `p_review_done` and delete `p_waived` and `t_join_waived`.

R1 is the right deployment choice for three reasons. It is provably minimal under the stated cost model (cost 1, and §4.3 shows it is the unique correct single-edit repair), which means the smallest possible review surface and the smallest chance of collateral damage. It changes nothing about the standard-review route, so existing alignments, dashboards, and stored conformance results for the majority of cases remain valid. And it preserves the modeler's original intent literally: `t_join_waived` was clearly *meant* to be a two-input join, so the repair restores the design rather than replacing it, which makes the change easy to justify to the original author and to an auditor.

R2 is the fallback rather than the primary because its extra cost buys a genuine but secondary benefit: a simpler, single-AND-join free-choice net with one fewer silent transition, which is easier to read and to reason about with structural soundness theory. Choose it if the modeling standard forbids near-duplicate τ-joins, or if the waiver never needs to be distinguished at the state level. Its price is the loss of `p_waived` as an observable state and the invalidation of anything referencing it — and the deletion is mandatory, not cosmetic, since orphaning those nodes would create a second input-free place and cost the net its workflow-net status.

R3 is explicitly **not** recommended: it is sound, but it rewrites the policy "the analysis is always mandatory". It should only be considered if the business owner states in writing that a waiver also waives the analysis, and even then only with the skip step visibly labeled so the bypass appears in the log.
