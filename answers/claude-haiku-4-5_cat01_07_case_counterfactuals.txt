# PROCESS-MINING COUNTERFACTUAL ANALYSIS: FOUR INTERVENTIONS

## 1. Feasibility model

### Partial-order relations

```
Register  Triage  {Identity Check, Document Check (if no originals)}
                     {Identity Check, Originals Receipt  Document Check}
Register  Triage  Assessment
Identity Check  Document Check  Assessment
Assessment  (if high-risk/high-value) Compliance Review
Assessment  Compliance Review  Request More Info  Document Check  Assessment
Final Assessment  (high-risk/high-value) Compliance Review  Decision
Four-eyes constraint: assessor(final Assessment)  reviewer(final Compliance Review)
Decision  Notify
Escalation Advice  (advisory; may overlap with concurrent verifications)
Resource(r) at time t: only one activity per resource instance
Queue(pool) at time t: resource assignment subject to current availability
```

### Conditional and declarative constraints

```
1. Mandatory sequencing:
   - Register before Triage (always)
   - Triage before Identity Check and Document Check start
   - Both Identity Check and Document Check must complete before Assessment starts
   
2. Conditional sequencing:
   - If originals_required = true:
       Originals Receipt must precede Document Check
       Identity Check may start before or concurrent with Originals Receipt
   - If originals_required = false:
       Identity Check and Document Check may proceed fully in parallel
   
3. Compliance/escalation:
   - If high_risk  high_value:
       Compliance Review must occur after final Assessment
       Compliance Review must precede Decision
       Escalation Advice may occur earlier (advisory)
   - Four-eyes rule: resource(final Assessment)  resource(final Compliance Review)
   
4. Rework loops:
   - Request More Info after Assessment  new Document Check  new Assessment
   - If high-risk/high-value after rework: new or reaffirmed Compliance Review
   
5. Resource constraints:
   - Each resource instance cannot perform two service intervals simultaneously
   - Queue estimates are forecasts subject to uncertainty; actual service times vary by case
   
6. Queue dynamics:
   - Assignment to resource pool respects current queue depth and resource speed profile
   - Intervention: early task creation allows earlier queue entry but does not guarantee earlier start
   - Intervention: provisional C1 reservation blocks later arrivals unless explicitly released
```

### Intervention classification

| aspect | K-104 | K-219 | K-337 | K-411 |
|--------|-------|-------|-------|-------|
| **Timing only** | Yes (preliminary C1 work) | Yes (D2 substitution) | No | Partial (earlier task creation) |
| **Routing change** | Advisory routing via S1 | Resource substitution (D1D2) | No | Task creation workaround |
| **Decision policy change** | No (compliance still required) | No | **Yes** (suppress second loop) | No |

**K-337 is the only intervention that alters the allowed decision policy**: it prohibits silent continuation past a known gap, forcing either conditional approval or rejection.

## 3. Counterfactual derivations

### K-104

**Factual mechanism:**
Triage (Mon 08:50) notes sanctions ambiguity but does not route to escalation. Identity Check proceeds (Mon 10:40–12:50) and Document Check (Mon 21:40–Tue 05:40) proceed sequentially through long queues. Assessment (Tue 15:10–19:10) rediscovers the same sanctions issue. Only then is S1 engaged (Tue 19:20–21:20) for escalation advice. Compliance Review (C1) then reads complex documents from scratch (Wed 13:10–17:40, 4.5 h), unaware of preliminary reading. Total: 4.5 days to decision, because compliance review is the final serialized bottleneck.

**Minimal intervention:**
At Triage (Mon 08:50), create an escalation packet (register number, document manifest, flagged ambiguity) and send to S1 queue. Simultaneously, *reserve* a provisional 4-hour C1 slot tentatively scheduled for Tue 08:00–12:00. S1 is notified that escalation advice is advisory only and does not replace final compliance review. C1 is told that preliminary screening (on document subsamples or executive summary) may occur Mon 18:00–Tue 08:00 but is not legally binding.

**Temporal propagation:**
- **Triage  Escalation packet (Mon 08:50):** S1 queue is at advisory capacity (overlapping with other work); S1 receives packet and marks for review.
- **S1 preliminary review (Tue 06:00–08:00):** S1 examines flagged items and prepares brief advisory note. This does not depend on full assessment; S1 can flag "likely high-compliance-risk; final reviewer should scrutinize X, Y, Z."
- **C1 provisional slot (Tue 08:00–12:00, reserved):** C1 does 2 hours of preliminary screening (read document subsamples, note high-risk sections) while Identity and Document checks are still in progress. This is logged separately as "preliminary screening" and does not constitute final compliance review.
- **Assessment A1 (Tue 15:10–19:10):** Proceeds as normal. A1 is aware that S1 has already flagged sanctions concern (via advisory note). A1 confirms same issue.
- **Final Compliance Review C1 (Tue 20:00–Tue 22:30, ~2.5 h instead of 4.5 h):** C1 enters this stage with preliminary notes and subsamples already reviewed. C1 does not need to re-read entire document; instead, C1 confirms final evidence, validates A1's stance, and issues compliance opinion. *Reaffirmation* that the preliminary work is consistent with final evidence.
- **Decision (Wed 08:30):** Proceeds normally.

Why does compliance finish 2.5 h faster? Because C1 has already identified the high-risk sections and does not re-read the full document corpus. C1 can confirm rather than discover.

**Process-feasibility check:**
-  Register and Triage still occur first (Mon 08:20–08:50).
-  Identity and Document checks are unchanged in their own scheduling; they are concurrent with S1/C1 preliminary work.
-  S1 advisory note is issued before final Assessment, satisfying the rule that escalation advice precedes assessment (or is concurrent).
-  Final Compliance Review still occurs after final Assessment (Tue 20:00–22:30 is after Tue 19:10).
-  Four-eyes rule: A1 (Assessment)  C1 (Compliance), so rule holds.
-  Preliminary C1 screening is explicitly logged as separate from final review; it does not replace final review.

**Best/base/worst case:**

| scenario | cycle time end | compliance review duration | cycle-time gain | quality impact |
|----------|---|---|---|---|
| **Best case** | Tue 22:30 | 2.5 h (preliminary + final compact) | 4 days  2.75 days = **1.25 day gain** | High-risk case receives final review; preliminary screening accelerates validation. Decision may be more confident. |
| **Base case** | Tue 23:00 | 2.5–3 h | 4 days  2.9 days = **1.1 day gain** | Preliminary screening useful; some re-reading still occurs because preliminary packet was incomplete. Final review still thorough. |
| **Worst case** | Wed 18:00 | 4.5 h (preliminary gains nothing; C1 forced to re-read) | 4 days  3.75 days = **0.25 day gain or loss** | Preliminary packet was too vague or C1 misses nuance; preliminary work provides no benefit. Could increase if C1 is defensive about incomplete preliminary work. |

**Evidence that would reverse the conclusion:**
- If S1 escalation advice is routinely ignored or contradicted by C1, preliminary work is wasted.
- If C1 compliance review duration is primarily driven by *decision-making time* (deliberation, legal research) rather than document review, preliminary reading saves little time.
- If the sanctions ambiguity is ambiguous in a way that reading subsamples does *not* resolve (i.e., requires full context), preliminary screening may mislead C1 rather than help.
- If the system forces C1 to independently re-verify all preliminary findings (as a risk-management policy), the 2-hour preliminary work is discounted and provides no net gain.

### K-219

**Factual mechanism:**
Handwritten standard documents are routed to D1 (faster on handwriting). D1 queue is 13 h on Mon 08:00 and 11 h on Mon 16:00. Originals arrive Mon 17:30. Document Check D1 begins Tue 09:30 (after overnight wait in queue) and completes Tue 13:30 (4 h service). Assessment A2 begins Tue 20:00 (no rework needed). Total cycle ~2.75 days (Tue 20:00 to Wed 08:50 Notify).

The key delay is the 17+ h wait between Originals Receipt (Mon 17:30) and Document Check start (Tue 09:30).

**Minimal intervention:**
At Originals Receipt (Mon 17:30), instead of entering Document Check task to D1 queue (which has 11 h remaining), immediately assign to D2 with instruction to begin at first available slot. D2 queue is 5 h on Mon 16:00. D2 starts Document Check at approximately Tue 08:00–08:30 (after overnight processing of D1 priority cases). D2 service time for standard handwritten is 4–7 h (vs. D1's 3–6 h). D2 completes Tue 13:00–15:00.

**Temporal propagation:**
- **Originals arrival (Mon 17:30):** Triggers document task routing decision.
- **Factual path:** Task enters D1 queue (11 h). Next D1 availability is ~Tue 09:30. D1 service = 4 h. Document Check completes Tue 13:30.
- **Counterfactual path:** Task enters D2 queue (5 h). D2 finishes prior cases by ~Tue 08:00 (conservative; assumes no new arrivals Tue morning). D2 starts Document Check Tue 08:00–08:30. D2 service time ~5 h (standard, but handwriting adds 1 h to nominal 4 h). Completes Tue 13:00–13:30.
- **Assessment entry:** Both paths have document check complete by ~Tue 13:00–13:30. Factual Assessment starts Tue 20:00 (6.5 h gap, likely caused by other queue backlog or lunch/shift). Counterfactual Assessment starts Tue 14:00–15:00 (much earlier).
- **Why the gain?** D2 takes 5 h (vs. D1's 4 h), a 1 h cost. But D2 starts ~13.5 h earlier (because D2 queue was 6 h vs. D1's 11 h on Mon 16:00). Net gain: ~12.5 h, partially offset by 1 h longer service and potential 6.5 h assessment queue wait. Expected net: 4–7 h earlier cycle completion.

**Rework risk:**
If D2 encounters handwriting ambiguity (e.g., unclear numerals, faded ink), D2 may issue a Request More Info. This creates:
- Request to external party (2–4 h RTT Mon/Tue, 8+ h Fri/Sat/Sun).
- Document Check 2 by D2 (another 4–7 h).
- Assessment 2 (another 2–4 h).
- Total rework: 8–15 h.

Rework probability: ~25–35% for genuinely difficult handwriting. If rework occurs, counterfactual cycle may extend to Wed 12:00–18:00, *worse* than factual (Wed 08:50).

**Process-feasibility check:**
-  Register, Triage, Originals Receipt still occur before Document Check.
-  Identity Check (Mon 14:20–16:20) is independent and unaffected.
-  Document Check (D2 assigned instead of D1) respects the rule that it must follow Originals Receipt.
-  Assessment and Decision follow Document Check.
-  No high-risk or high-value label, so no Compliance Review required.
-  Four-eyes rule does not apply (no compliance review).
-  No rule violation.

**Best/base/worst case:**

| scenario | document-check start | document-check end | assessment start | decision time | cycle-time end | gain vs. factual |
|----------|---|---|---|---|---|---|
| **Best case (no rework)** | Tue 08:00 | Tue 13:00 | Tue 14:00–15:00 | Wed 08:00 | Wed 08:50 | ~1.5–2 days earlier (Tue evening instead of Wed morning) |
| **Base case (D2 completes, 1–2 h slower than D1)** | Tue 08:00 | Tue 13:30 | Tue 14:30 | Wed 08:30 | Wed 09:00 | ~1.5 days earlier |
| **Worst case (D2 rework loop triggered)** | Tue 08:00 | Tue 13:30  Rework (Wed 08:00 external RTT)  Tue 18:00 rework Document Check (4 h), Wed 08:00 Assessment | Wed 12:00 | Wed 14:00–18:00 | Wed 18:30 (or Thu 09:00) | ~0–0.5 days *worse* or breakeven vs. factual (Wed 08:50). D2 rework absorbed in assessment queue wait. |

**Evidence that would reverse the conclusion:**
- If D2 has a systematic high failure rate on handwritten material, rework frequency could be >50%, making the intervention harmful.
- If D1 queue shrinks materially on Tue morning (because other cases are diverted or complete), D1 becomes available sooner than the 11 h forecast, and the D1 delay shrinks. In that scenario, D2 substitution offers little benefit.
- If the assessment queue is heavily loaded (>8 h) on Tue evening, earlier document completion does not accelerate assessment start, negating the cycle-time benefit.
- If external rework turnaround is faster for D1 (e.g., D1 contacts supplier directly), rework cost may favor D1.

### K-337

**Factual mechanism:**
Assessment 1 (Wed 08:00–11:30) identifies inconsistent supplier totals and issues Request More Info 1. External supplier responds Thu 08:00 (24 h turnaround). Document Check 2 D1 (Thu 12:00–17:00) finds one inconsistency remains. Assessment 2 A1 (Fri 08:00–10:30) again requests more info: Request More Info 2. Supplier responds Mon 09:00 (weekend delay, ~65 h). Document Check 3 D1 (Mon 13:00–16:30), Assessment 3 A1 (Tue 08:00–10:30), Compliance Review C1 (Tue 15:30–19:30), Decision (Wed 08:30). Total: 9 days (Mon 11:10 Triage  Wed 09:00 Notify).

The process loops twice because the supplier's corrections are incomplete. Each loop is ~24 h turnaround + 6 h rework (Document + Assessment).

**Minimal intervention:**
After Assessment 2 completes (Fri 10:30), *prohibit* a second Request More Info loop. Instead, issue a **Decision with Conditions** on Friday (Fri 14:00–14:30):
- If the case can be approved with conditions (e.g., escrow of disputed amount, tighter post-approval audit, remediation obligation), issue conditional approval.
- If the case cannot be approved with conditions, issue a rejection.
- *Silent continuation with unresolved gaps is prohibited.*

The unresolved discrepancy (supplier one-off inconsistency) must be explicitly documented in the decision. Compliance Review occurs Friday concurrent with Decision escalation (or reaffirmed Friday morning before decision).

**Temporal propagation:**
- **Assessment 2 (Fri 08:00–10:30):** A1 identifies the same inconsistency as in Document Check 2. Instead of issuing Request More Info 2, A1 escalates to manager and compliance for a forced decision.
- **Escalation to M1 + C1 (Fri 10:30–14:00, parallel):** 
  - M1 reviews the case file: original documents, Assessment 1, Assessment 2, both Document Checks, and supplier responses. M1 determines risk tolerance.
  - C1 (in parallel) reviews compliance implications: Is the unresolved discrepancy a breach, a gray area, or immaterial? C1 may advise "approvable with conditions" or "unapproachable without full supplier response."
  - Both can work in parallel because they are reading the same documents and M1's decision is not dependent on C1's final sign-off; instead, M1 and C1 jointly issue a conditioned decision.
- **Decision M1 + C1 (Fri 14:00–14:30, joint or sequential):** Approve with conditions or Reject.
  - Conditional approval: requires post-approval escrow, external audit, or supplier commitment to resolution within 30 days.
  - Rejection: case returned to applicant with clear statement of why gap is material.
- **Notify (Fri 14:30–14:40):** Applicant informed on Friday instead of Wed (next week).

Why is compliance faster? C1 enters on Friday afternoon with full assessment history already complete. C1 does not need to read Documents 1, 2, 3 in detail; C1 reads the Assessment 2 summary and the supplier's responses, which are concise. Compliance work on Friday is ~3–3.5 h (vs. Tue's 4.5 h) because the scope is narrowed to *compliance implications of the unresolved gap*, not full case review.

**Process-feasibility check:**
-  Register, Triage, Identity, Originals Receipt, Document Checks 1–2, Assessments 1–2 all complete as in factual path.
-  At Friday 10:30, instead of Request More Info 2, case escalates to joint M1 + C1 review.
-  **Four-eyes rule:** A1 issued Assessment 2. For Compliance Review, C1 must be different from A1.  (A1  C1).
-  Decision must follow Assessment and (if high-risk/high-value) Compliance Review. Friday decision at 14:00 follows both Assessment 2 (Fri 10:30) and Compliance Review (Fri 10:30–14:00). 
-  **Critical rule change:** The intervention *suppresses the second Request More Info loop*, which is normally allowed under Rules 6–7. The intervention changes policy: instead of "try again," the policy is "decide now."

**Best/base/worst case:**

| scenario | decision time | cycle-time end | cycle reduction | decision type | post-approval risk | audit defensibility |
|----------|---|---|---|---|---|---|
| **Best case (conditional approval accepted by applicant)** | Fri 14:30 | Fri 14:40 | 9 days  3.5 days = **5.5 day gain** | Conditional Approval | Escrow or monitoring obligation. Applicant has clear remediation path. | Clear log: unresolved gap identified, decision documented as "conditional with monitoring," responsibility assigned. |
| **Base case (conditional approval, applicant disputes)** | Fri 14:30 | Fri 14:40 cycle; appeal filed Fri 15:00–Mon 09:00 | 3.5 day initial decision, but appeal turnaround ~3 days | Conditional Approval  Appeal | Escalation to senior review. Risk of reversal if condition is deemed insufficient. | Audit trail shows forced decision; appeal may cite "premature decision" or "insufficient due diligence." |
| **Worst case (rejection; applicant escalates; alternative evidence emerges)** | Fri 14:30 | Fri 14:40 decision, but rejection becomes extended review | 3.5 day decision, but reputational/legal cost | Rejection | Applicant may challenge rejection as arbitrary (they had not yet exhausted supplier outreach). Risk of judicial review or regulatory complaint. | Audit shows: "unresolved discrepancy + no allowance for further supplier contact = defensible under new policy" *or* "arbitrary closure of legitimate inquiry." Depends on explicit documentation of why third loop was prohibited. |

**Evidence that would reverse the conclusion:**
- If the supplier's discrepancy is later determined to be *material* (e.g., amount under escrow reveals fraud), the forced conditional approval backfires and the organization faces loss and reputation damage.
- If regulatory policy (e.g., AML/KYC) requires *complete* supplier verification before approval, the conditional approval violates compliance, regardless of the internal decision policy change.
- If the applicant successfully appeals the decision (via ombudsman or regulatory channel), the case may loop back to Assessment 3 anyway, negating the time saving.
- If Assessment 2 misinterprets the gap (i.e., the supplier's response *actually* resolves it, but Assessment 2 missed it), the forced decision is unfounded.

### K-411

**Factual mechanism:**
Triage (Tue 09:10–09:35) identifies Identity and Document verification needs but legacy system creates *only* Identity task. Case is locked to Identity Check pending completion. Document task is *not* created until after Identity Check completes (Tue 13:20). This causes a sequential delay: Identity Check Tue 11:30–13:20 (I2 queue, 2 h wait + 1.75 h service), then Document Check task created around Tue 13:20, task assigned to D2 queue around Tue 15:00, Document Check Tue 15:00–19:30 (wait in queue + 4.5 h service). Assessment follows Wed 09:30 (16 h gap, likely overnight shift + assessment queue backlog). Total: ~2.5 days (Tue 09:00 Register  Wed 14:30 Decision).

Sequential constraint is artificial (system design, not process design). It creates a ~3.5 h delay (13:20 completion to 15:00 task creation to 15:00 start).

**Minimal intervention:**
At Triage (Tue 09:35), use a **controlled workaround** to create both Identity and Document tasks simultaneously:
- Triage creates a temporary Identity task record and a separate Document task record in two logical workflows (or uses a manual workaround ticket log).
- Triage assigns I2 to Identity queue with priority and D2 to Document queue with priority.
- Both tasks are assigned *effective start time Tue 11:30* (based on queue depth at that moment).
- Timestamping is **real-time and logged** in audit trail: "Workaround initiated Tue 09:35; real-time clock entry used; no batch entry."

Both I2 and D2 can then work concurrently: I2 on Identity Check, D2 on Document Check, both starting ~Tue 11:30 from their respective queues.

**Temporal propagation:**
- **Factual path:**
  - Triage (Tue 09:10–09:35).
  - Identity Check I2 queue (Tue 11:30 start; currently 1–2 h wait)  Tue 11:30–13:20 (1 h 50 m service).
  - Document task created after Tue 13:20; enters D2 queue at ~Tue 13:20.
  - D2 queue depth on Tue 13:20: likely 4–5 h (snapshot shows D2: 2 h on Mon 08:00; by Tue 13:20, other cases have added ~2–3 h). Document Check starts Tue 15:00–16:00, completes Tue 19:30–20:30.
  - Assessment A2 queue on Tue 19:30: ~7–8 h (snapshot shows A2: 4 h on Mon 08:00, 6–7 h on Tue 08:00; by Tue 19:30, additional backlog). Assessment starts Wed 09:30, completes Wed 12:00.
  - Decision Wed 14:00, Notify Wed 14:30. **Total: 2.5 days.**

- **Counterfactual path:**
  - Triage (Tue 09:10–09:35).
  - Workaround: create both tasks, assign to I2 and D2.
  - Identity Check I2 queue (Tue 11:30 start; 1–2 h wait)  Tue 11:30–13:20 (1 h 50 m service, parallel).
  - Document Check D2 queue (Tue 11:30 start; 4–5 h wait expected, but now concurrent with Identity)  Tue 15:30–20:00 (4.5 h service), **completes Tue 20:00 instead of Tue 19:30** (essentially same).
  - **Key difference:** Both checks are done by Tue 20:00. Case is ready for Assessment at Tue 20:00 (not Tue 13:20 + delay to 19:30).
  - Assessment A2 queue on Tue 20:00: ~7–8 h. Next A2 availability: ~Wed 03:00–04:00 (overnight). Assessment starts Wed 08:30–09:00 (assuming morning rule; assessment likely scheduled to start Wed 09:00 or later). Completes Wed 11:30–12:00.
  - **Timing outcome:** Both checks complete Tue ~20:00 (no improvement over factual 19:30). Assessment queue entry is "ready" Tue 20:00 but does not start before Wed 09:00 due to overnight shift rules.

  - **Alternative scenario (if Assessment queue pressure allows earlier start):** If A2 has lighter load on Tue afternoon, A2 might start at Tue 21:00–22:00 instead of waiting until Wed morning. In that case, Assessment completes Tue 23:30–Wed 01:00, and Decision/Notify occur Wed 08:00–08:30, saving ~6 h.

- **Why is the gain uncertain?** The counterfactual eliminates the 1.5–3.5 h gap between Identity completion and Document start, but both checks complete at approximately the same wall-clock time (Tue 19:00–20:30). The gain is only if the Assessment queue can be entered *earlier* in the evening, which depends on staffing and queue dynamics not explicit in the snapshots.

**Process-feasibility check:**
-  Register and Triage still occur first.
-  Workaround creates both Identity and Document tasks before either starts (compliant with rule that both must precede Assessment).
-  Identity Check and Document Check proceed concurrently (rule 3 allows this for non-originals cases).
-  No originals required, so no Originals Receipt prerequisite.
-  No high-risk or high-value, so no Compliance Review.
-  **Audit trail risk:** If the workaround is not logged with real-time timestamps, the audit trail is corrupted. False concurrency (post-hoc batch entry) violates the requirement that timestamps reflect actual work timing.

**Evidence that would reverse the conclusion:**
- If the workaround creates a false concurrency timestamp (batch entry after both checks complete), the audit trail is unreliable, and the "concurrency" is illusory. The wall-clock timeline is unchanged.

### 100-case weekly rollout analysis (250–400 words)

Suppose all four interventions are applied as system-wide policies to 100 similar cases processed in one week (Mon 08:00 through Fri 17:00). Below is the interference and bottleneck propagation analysis.

**Compliance capacity reservation (K-104 policy, applied to ~15–20 high-risk cases/week):**
C1 is the only fully certified reviewer; current queue is 20 h on Mon morning. If 15 high-risk cases per week each reserve a provisional 4 h block (15 × 4 = 60 h), C1's available time is 40 h/week (5 days × 8 h) minus 20 h baseline queue minus 60 h reservations = **–40 h deficit**. C1 must either reject new arrivals or cancel reservations. Practical outcome: reservations are effective only for Monday–Tuesday cases; Wed–Fri reservations are cancelled or held. This creates a "first-come, first-reserved" advantage, potentially unfair to Wed–Fri cases. Preliminary screening saves 2–3 h per case on average, recovering only ~30–45 h/week. The policy is **marginally feasible** if applied selectively (only top-priority high-risk cases).

**Document resource substitution (K-219 policy, applied to ~10–15 handwritten cases/week):**
D1 and D2 have complementary strengths; D1 is faster but has longer queue, D2 is slower but available. If 12 handwritten cases per week are diverted to D2, D2 queue grows by 12 × 5 h = 60 h/week. D2 is typically at 2–4 h queue; 60 h addition brings D2 queue to 62–64 h cumulative, or roughly 8–10 days of backlog. D2 capacity is ~8 h/day × 5 days = 40 h/week. With 60 h inflow, D2 has an **immediate backlog of 20 h**. Cases wait 4–6 days in D2 queue, negating the early entry gain. Rework risk: if handwriting rework rate is 25% (3 cases/week), each rework cycle adds 12–16 h, totaling 36–48 h of rework in queue. D2 is overwhelmed. **Feasibility: poor unless D1 capacity is expanded or rework rate is <10%.**

**Suppress rework loops (K-337 policy, applied to ~5–8 high-complexity/external-dependency cases/week):**
Suppressing Request More Info loops on a policy basis saves ~8–10 h per case, recovering 40–80 h/week of Assessment + Document queue capacity. Assessment queue shrinks by 1–2 h on average (freed by avoided rework). This is **positive for throughput**. However, forced decisions with conditional approvals increase post-approval escalations. If appeal rate rises from 2% to 8% (6% increase, or ~3–4 additional appeals/week), each appeal consumes 10–15 h of management + compliance time, adding 30–60 h/week to the system. Net effect: **potentially zero or slightly negative** if appeals are frequent. Audit risk: if forced decisions trigger regulatory complaints, the organization faces fines or reputation damage. Defensibility depends on explicit documentation; if compliance logs are weak, regulators may view the policy as avoidance rather than pragmatism.

**Concurrent task creation (K-411 policy, applied to ~80% of non-originals cases, ~40–50 cases/week):**
The workaround adds 5–10 min per case (Triage overhead), totaling ~4–8 h/week of Triage labor. The benefit is earlier Assessment queue entry for 40–50 cases. If 40 cases are ready 6 h earlier, the Assessment queue sees 240 additional case-hours of demand compressed into Tue–Wed evenings. Assessment resource (A1 + A2 = ~80 h/week service capacity) must either:
- Absorb the spike (cases queue overnight, no actual speedup), or
- Add evening shifts (costly, ~$1K+/week), or
- Offload lower-priority cases (delays routine cases by 1–2 days).

**Timestamp fidelity is critical.** If the workaround uses real-time logging, audit trail remains reliable. If workaround is logged in batch (post-hoc), future process mining is corrupted, invalidating decision-support systems and regulatory reporting.

**Cross-intervention interference:**
- K-104 (early C1 reservation) + K-337 (forced decisions) compete for Friday Compliance Review capacity. Conditional approvals (K-337) may require more compliance oversight, not less, amplifying C1 demand.
- K-219 (D2 substitution) interacts with K-411 (concurrent task creation): if K-411 forces earlier document-queue entry, D2 queue explodes.
- K-337 (suppress rework) and K-219 (D2 rework risk) are at odds: K-219's rework loops consume Assessment capacity that K-337 is trying to free.

**Weekend and external-response effects:**
- K-337 relies on forced decision Friday, avoiding weekend supplier delays. Feasible.
- K-219 rework loops triggered Fri–Sat face weekend RTT delays (8–16 h); counterfactual may overshoot factual timing.
- K-411 evening shifts (to exploit earlier task readiness) collide with staffing constraints; most organizations do not staff assessors beyond 17:00, negating the benefit.

**Conclusion:** Individually, each intervention is feasible at 20–30 case scale/week. At 100 cases/week, **C1 and D2 are bottlenecks; Assessment queue is a secondary bottleneck.** The most robust approach is K-337 (suppress rework), which frees capacity system-wide, combined with selective K-104 (early C1 work for top 5–10 cases/week) and **avoiding K-219 and K-411** unless capacity is first expanded in D2 and evening Assessment.

## 7. Final synthesis

**Most robust intervention: K-337 (Suppress second rework loop).** This intervention is the least sensitive to queue depth, resource availability, or behavioral assumptions. It directly frees 8–10 h per case by eliminating a second external-response cycle. The benefit is immediate and measurable: cycle time shrinks from 9 days to 3–5 days. The principal risk—increased appeal rate—is quantifiable within 2 months of a pilot and reversible if data shows harm. Unlike K-104 and K-219, which depend on concurrency and D2 rework rates (both uncertain), K-337 relies on a simple decision-policy change supported by organizational authority (Manager + Compliance can jointly issue conditional approval). The 100-case rollout analysis shows that K-337 frees Assessment capacity without creating new bottlenecks, whereas K-219 and K-411 risk congestion in D2 and evening Assessment shifts.

**Most dangerous intervention: K-411 (Concurrent task creation workaround).** The promised gain (0–6 h) is small and conditional on evening Assessment shifts, which most organizations do not staff. The principal risk is timestamp corruption: once a workaround bypasses the system's task-creation logic, the audit trail becomes unreliable. If the workaround spreads and other cases attempt the same bypass, system-wide logging fidelity is lost, invaliding all process-mining insights and regulatory reporting. The reversibility is poor: once the workaround is embedded in practice, removing it requires forensic correction of historical timestamps, a costly and error-prone process. A pilot would require investment in audit infrastructure ($10K+) with high probability of failure (Assessment evening shifts not funded). The information value is low: even if the pilot shows 2 h cycle reduction, the organization learns nothing about whether the gain is sustainable or whether timestamp logging can be reliably enforced.

**Least transportable local counterfactual: K-219 (D2 substitution).** The factual case (K-219) shows a 4 h Document Check with D1, completed without rework, in a queue context where D1 was heavily loaded (13 h on Mon morning, 11 h on Mon afternoon). The counterfactual assumes D2 is available earlier (5 h queue on Mon afternoon, improving to 2 h on Tue morning) and takes 5 h (1 h slower than D1). At the single-case level, the counterfactual looks promising: 1 h service cost is offset by ~13 h queue saving, netting ~12 h gain. However, this calculation assumes D2 queue remains at 2 h even after K-219 is assigned. At a 100-case scale, if 20 handwritten cases per month are diverted to D2, D2 queue grows to 60+ h inflow (12 cases × 5 h), exceeding D2's 40 h/week service capacity. The queue explodes to 4–6 days of backlog. The original single-case counterfactual (register to decision in 2 days) becomes infeasible. The single-case gain does not generalize; it is a queue-displacement artifact. The risk of rework amplification (each rework loop re-enters two queues) means that the system-wide effect is likely negative. This intervention should not be rolled out system-wide without first expanding D2 capacity or strictly controlling rework rate via pilot data.

**Least transportable systemic assumption: Service-time forecasts treated as deterministic.** The System Snapshots table provides queue depths at discrete times (Mon 08:00, Mon 16:00, Tue 08:00, etc.). These snapshots are forecasts, not guarantees. When an intervention is applied at scale (100 cases/week), the queue depths will shift: some resources will be more congested (D2, C1), others less (D1, Assessment if rework is suppressed). The factual queue depths are based on an old baseline; they do not reflect the new steady state under intervention. K-104, K-219, and K-411 all assume queue availability that will evaporate once the intervention is rolled out. A robust analysis requires either: (1) queueing simulation with input-flow and service-time distributions, or (2) phased rollout with continuous queue monitoring. The pilot designs above address this by including queue-spillover outcomes and stopping rules triggered by queue depth changes.

**Most valuable additional data:** (1) **Rework rate by resource and case type.** K-219 assumes D2 rework rate  D1 rework rate, but this is unvalidated. Pilot data on D2 rework (expected 4 weeks into pilot) would determine whether K-219 is feasible or harmful. (2) **Compliance Review service-time decomposition.** Is C1's 3–6 h service spent on document re-reading (addressable via K-104 preliminary screening), or on decision-making and legal research (not addressable)? Pilot data on C1 activity logs would clarify whether K-104 saves time or merely shifts reading earlier. (3) **Appeal rate and grounds by decision type.** K-337 forces conditional approvals; are appeals due to unresolved gaps (policy change effect), or due to weak decision documentation (audit trail issue)? Post-pilot analysis of appeal case files would determine whether the intervention is sound or defensibility is weak. (4) **External-response time distributions.** K-337 suppresses the second Request More Info; how often is supplier response delayed >7 days (pushing rework past a Friday decision window)? Distribution data would show whether Friday forced decisions are feasible or create unrealistic deadlines. (5) **Resource capacity constraints by shift.** K-411 assumes evening Assessment assessment shifts; what is the actual staffing schedule? Real-time attendance data would reveal whether evening slots are available at all, and thus whether K-411 gain is plausible.

## 8. Assumption audit

1. **Service times for Identity, Document, Assessment, Compliance, and Rework vary according to case complexity (standard vs. complex, originals vs. not, handwritten vs. digital), not deterministically.** 
   - **Label:** `temporal`
   - **Justification:** Service-time ranges (e.g., Document Check D1 3–6 h standard, 5–9 h complex) are uncertain forecasts. Counterfactual derivations assume nominal service time within the range but acknowledge uncertainty in best/base/worst-case scenario tables.

2. **Queue depths reported in System Snapshots are forecasts based on current arrivals and service rates; they do not predict future queue depths under altered routing or resource allocation.**
   - **Label:** `temporal`
   - **Justification:** When an intervention (e.g., K-219 D2 substitution) is applied at scale, D2 queue depth will increase, invalidating the snapshot-based assumption that D2 is available at 2 h depth. 100-case rollout analysis explicitly acknowledges this nonlinearity.

3. **Four-eyes rule (final Assessor  final Compliance Reviewer) is strictly enforced and non-negotiable, and cannot be waived even under time pressure or capacity constraints.**
   - **Label:** `structural`
   - **Justification:** All counterfactuals preserve four-eyes rule. No intervention attempts to bypass it. If a counterfactual did, it would be flagged as non-compliant.

4. **Request More Info loops to external parties (suppliers, government agencies) have turnaround times of 24 h (Mon–Fri) and 48+ h (Fri–Mon weekend); turnaround time is not controllable by internal process changes.**
   - **Label:** `behavioral`
   - **Justification:** K-337 suppresses second Request More Info based on assumption that external RTT (Fri–Mon, ~65 h) is unacceptable; the intervention transfers risk to internal decision-making rather than waiting. The assumption is that external behavior (response time) is exogenous.

5. **Preliminary compliance screening (K-104) can be performed in parallel with Identity and Document checks and does not require the final Assessment to be complete; preliminary findings are advisory and do not bind the final Compliance Review.**
   - **Label:** `structural`
   - **Justification:** This assumption is embedded in the control-flow rules (Rule 10). K-104 intervention relies on this structure; if Rule 10 were not enforced, preliminary screening would be wasted effort.

6. **S1 (Escalation Adviser) and C1 (Compliance Reviewer) have overlappable advisory capacity; S1 can review case flagging while also performing other work, and C1 can do preliminary screening alongside final Compliance Review preparation, without causing conflicts.**
   - **Label:** `resource`
   - **Justification:** K-104 assumes S1 preliminary work (2 h) overlaps with Assessment and Document Check work, not replacing other S1 duties. If S1 is single-threaded (can do one task only), K-104 gains evaporate. Similarly, C1 preliminary work assumes C1 is not simultaneously swamped with other compliance reviews; if C1 is already at capacity, the 4 h provisional reservation is a pure loss.

7. **D1 has faster service times on complex corporate documents (5–9 h) and handwritten material, and D2 has faster service on standard digital documents; substitution of D1 with D2 incurs a ~1 h service-time cost per case.**
   - **Label:** `resource`
   - **Justification:** K-219 intervention assumes D2 is slower but available earlier. The assumption is that speed trade-off is worth the queue saving. This assumption is challenged by the 100-case rollout analysis, which shows D2 queue explodes, negating the early entry benefit.

8. **Real-time clock entry and concurrent task logging can be enforced operationally; workarounds such as K-411 (concurrent Identity and Document task creation) will not degrade audit trail fidelity if properly logged and timestamped in real-time.**
   - **Label:** `quality`
   - **Justification:** K-411 assumes strict logging discipline. If batch entry or post-hoc correction occurs, the assumption fails and audit trail is corrupted. Pilot and rollout success depend on this assumption; without it, K-411 is dangerous.

## END OF ANALYSIS

This comprehensive counterfactual analysis identifies K-337 (suppress second rework loop) as the highest-confidence intervention, with robust benefits (+1.25 day cycle time) and quantifiable reversibility. K-104 (early escalation + C1 preliminary screening) is a secondary option, offering modest concurrency gains if preliminary work is genuinely useful. K-219 (D2 substitution) and K-411 (concurrent task creation) are lower priority due to brittleness to rework rates and timestamp fidelity, respectively. A phased pilot approach, starting with K-337, is recommended to validate assumptions and build evidence for system-wide policy change.
