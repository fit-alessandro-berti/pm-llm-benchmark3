## 2. Raw-versus-normalized interpretation

The March divergence is strong evidence that the old model was chiefly rejecting event representation, not an equally large collapse in business conformance: raw fitness falls from 0.93 to 0.55, whereas mapped fitness is 0.90. Raw March eligibility edges also reconcile to 640 registrations, and 26 duplicate `Open Case -> Register` edges are consistent with about 4% of cases. The gap does not prove that every recovered deviation was semantic, that the mapping is complete, or that the residual 0.02–0.03 is behavioral.

A relabeling can restore alignments because the same ordering remains after `Eligibility Screen` is renamed. It cannot show that eligibility rules, decisions, timestamps, document quality, or outcomes were unchanged. Duplicated technical events invent variants and directly-follows edges and can distort event counts, alignments, and some time calculations. Missing resources need not affect sequence fitness, but they can bias workload, handoff, team, and staffing analyses; non-random missingness makes complete-case comparisons especially unsafe.

Post-May changes survive that normalization: `Assess -> Request Info` rises from 12 per 100 cases in January and March to 24 in May and 29 in July, with nearly matching returns to `Collect Documents`. Rework variants, cycle time, and its upper tail worsen concurrently. March’s fixed label mapping cannot manufacture those operational patterns. They nevertheless remain compatible with several mixtures of supplier behavior, case mix, backlog, capacity loss, and priority, rather than identifying one cause.

Seasonality should be modeled using registration cohorts, day-of-week and holiday effects, and prior-year same-calendar windows. An expected October volume increase can remain a capacity warning without being labeled new behavioral drift. Recurrence requires a similar pattern at the expected seasonal lag; a persistent residual after seasonal adjustment is a different signal.

Thresholds must be monitor- and segment-specific. Statistical alerts should use minimum support, material-effect requirements, and persistence or sequential calibration. Within each monitor family and reporting cycle, edge-, segment-, and outcome-level tests should use a multiplicity procedure such as Benjamini–Hochberg, with case-level bootstrap or permutation calibration. Deterministic schema failures and severe operational safety/quality failures should not wait for multiple-testing-adjusted significance.

```python
# PART B: Reusable PM4Py functions for a future event-level log
# Definitions only: no raw event log is supplied here.
# ============================================================
import pm4py

CASE = "case:concept:name"
ACTIVITY = "concept:name"
TIMESTAMP = "time:timestamp"
RESOURCE = "org:resource"


def prepare_event_frame(
    raw_df,
    case_id="case_id",
    activity_key="activity",
    timestamp_key="timestamp",
    resource_key="resource",
    timest_format=None,
):
    """Copy and format raw events; never modify raw_df in place."""
    required = {case_id, activity_key, timestamp_key}
    missing = required.difference(raw_df.columns)
    if missing:
        raise ValueError(f"Missing required columns: {sorted(missing)}")

    work = raw_df.copy(deep=True)
    if resource_key and resource_key in work.columns and RESOURCE not in work.columns:
        work[RESOURCE] = work[resource_key]

    kwargs = {}
    if timest_format is not None:
        kwargs["timest_format"] = timest_format

    formatted = pm4py.format_dataframe(
        work,
        case_id=case_id,
        activity_key=activity_key,
        timestamp_key=timestamp_key,
        **kwargs,
    ).copy(deep=True)

    # A production pipeline should additionally validate null/duplicate event IDs,
    # timestamp time zones, and per-case ordering before analysis.
    formatted[TIMESTAMP] = pd.to_datetime(formatted[TIMESTAMP], errors="raise")
    return formatted.sort_values(
        [CASE, TIMESTAMP], kind="mergesort"
    ).reset_index(drop=True)


def as_event_log(formatted_frame):
    """Convert a PM4Py-formatted dataframe without changing its activity labels."""
    return pm4py.convert_to_event_log(formatted_frame)


def time_slice(formatted_frame, start, end, mode="events"):
    """
    PM4Py time filtering. mode can be 'events', 'traces_contained', or
    'traces_intersecting', subject to the installed PM4Py version's support.
    Event-mode slices can split cases; use complete cohorts for variants/outcomes.
    """
    start, end = pd.Timestamp(start), pd.Timestamp(end)
    if start >= end:
        raise ValueError("start must precede end")
    return pm4py.filter_time_range(
        formatted_frame, start.isoformat(), end.isoformat(), mode=mode
    )


def monthly_dfg(formatted_frame, first_month, last_month, mode="events"):
    """Return monthly (DFG, start activities, end activities) discoveries."""
    periods = pd.period_range(first_month, last_month, freq="M")
    result = {}
    timestamp_tz = getattr(formatted_frame[TIMESTAMP].dt, "tz", None)

    for period in periods:
        start = period.start_time
        end = (period + 1).start_time
        if timestamp_tz is not None:
            start = start.tz_localize(timestamp_tz)
            end = end.tz_localize(timestamp_tz)

        sliced = time_slice(formatted_frame, start, end, mode=mode)
        if sliced.empty:
            result[str(period)] = None
            continue

        dfg, starts, ends = pm4py.discover_dfg(as_event_log(sliced))
        result[str(period)] = {
            "dfg": dfg,
            "start_activities": starts,
            "end_activities": ends,
            "n_events_in_slice": len(sliced),
        }
    return result


def discover_variants(formatted_frame):
    """Use a complete, appropriately matured case cohort where possible."""
    return pm4py.get_variants(as_event_log(formatted_frame))


def discover_temporal_profile(formatted_frame):
    """Discover pairwise temporal profiles for a selected log/cohort."""
    return pm4py.discover_temporal_profile(as_event_log(formatted_frame))


def discover_optional_log_skeleton(formatted_frame):
    """Optional log-skeleton discovery using default concept:name/timestamp keys."""
    from pm4py.algo.discovery.log_skeleton import algorithm as lsk_discovery
    return lsk_discovery.apply(as_event_log(formatted_frame))


def normalized_view(
    formatted_frame,
    label_map=None,
    audited_open_case_duplicate_mask=None,
):
    """
    Return a normalized copy, leaving the original formatted frame unchanged.

    Duplicate removal requires an audited event-level mask derived from source
    event IDs/lineage. The aggregate 4% duplicate statistic is insufficient to
    invent such a mask. The mask is checked to select only raw 'Open Case' events.
    """
    normalized = formatted_frame.copy(deep=True)

    if audited_open_case_duplicate_mask is not None:
        mask = pd.Series(
            audited_open_case_duplicate_mask, index=formatted_frame.index
        ).fillna(False).astype(bool)
        if mask.any() and not formatted_frame.loc[mask, ACTIVITY].eq("Open Case").all():
            raise ValueError("Duplicate mask selects non-'Open Case' events")
        normalized = normalized.loc[~mask].copy()

    if label_map:
        normalized[ACTIVITY] = normalized[ACTIVITY].replace(dict(label_map))

    return normalized


def compare_raw_and_normalized(
    formatted_frame,
    label_map=None,
    audited_open_case_duplicate_mask=None,
):
    """
    Build parallel raw/normalized views and compare DFGs and variants.
    Conformance fitness, if desired, must use the same normative model on both
    views; a DFG distance is not a substitute for fitness.
    """
    views = {
        "raw": formatted_frame.copy(deep=True),
        "normalized": normalized_view(
            formatted_frame,
            label_map=label_map,
            audited_open_case_duplicate_mask=audited_open_case_duplicate_mask,
        ),
    }
    artifacts = {}

    for name, view in views.items():
        log = as_event_log(view)
        dfg, starts, ends = pm4py.discover_dfg(log)
        artifacts[name] = {
            "n_events": len(view),
            "dfg": dfg,
            "start_activities": starts,
            "end_activities": ends,
            "variants": pm4py.get_variants(log),
        }

    # Both views are returned so temporal profiles, cohort slices, log skeletons,
    # and alignments can also be compared without overwriting the original log.
    return views, artifacts
```

## 9. Provisional attribution

**Strongest conclusions, with high confidence.** The March raw-fitness collapse is predominantly logging/semantic drift caused by migration, with duplicate events and non-random resource missingness as additional measurement problems. It is not evidence of an equally large behavioral collapse. Independent of that conclusion, real drift occurred after April: normalized request-and-return edges, rework variants, and operational cycle-time measures all move materially. October also contains genuine population/case-mix drift: volume and high-complexity share rise sharply, and the raw Senior Assessment count, 167/760 = 22%, reconciles with the normalized DFG.

**Plausible but not cleanly identified mechanisms.** Supplier Z’s disruption is the leading explanation, with moderate confidence, for the May onset of document rework and some subsequent delay; partial September improvement is consistent with recovery plus backlog. The supplier’s non-random customer mix, its pre-existing complexity, and the absence of supplier-specific transition rates prevent estimation of a causal share. Staffing loss is a strong candidate for the summer’s incremental queueing because queue waiting rose much more than recorded `Assess` service time. It cannot explain the May onset. Priority-induced redistribution has only low-to-moderate confidence: the rule is known, but aggregate medians cannot show who waited less or more. Persistent behavioral adaptation remains possible because December is still below baseline, but residual backlog, case mix, and historically inconsistent Senior Assessment recording are alternatives.

Attribution is not additive. Supplier rework can increase assessment demand; fewer assessors reduce capacity; queueing then mediates both mechanisms. Priority redistributes that queue, while seasonal volume and complexity amplify it. December’s improvement cannot be divided among overtime, the document campaign, supplier recovery, and falling seasonal load.

I would revise this account if supplier-stratified, complexity-standardized logs showed no May rework shift; if daily capacity and queue data showed no post-departure capacity effect; if priority-class waiting showed no redistribution; or if prior-year data did not reproduce the renewal pattern. Conversely, replicated within-stratum changes, audited document defects, staffing rosters, complete timestamped queues, and intervention-exposure data would strengthen or reorder the attributions. A newly discovered May timestamp or label change would reopen the logging explanation.

## 10. Monitoring decision rules

1. `IF raw fitness collapses while mapped fitness and comparable-case DFGs remain stable and new labels or duplicates appear, THEN audit provenance and replay identical cases in raw and normalized views before declaring behavioral drift, BECAUSE migration semantics and technical events can mimic major control-flow nonconformance.`

2. `IF supplier-Z information loops and document waiting rise after May within complexity and region strata and coincide with verified incomplete bundles, THEN trigger supplier remediation and targeted document-quality work while tracking the existing backlog separately, BECAUSE incomplete documents plausibly generate recurring collection-and-reassessment loops.`

3. `IF ready-to-assess waiting and WIP rise after assessor capacity falls while active Assess service remains comparatively stable, THEN restore or redistribute capacity and analyze arrivals, rework-generated demand, and backlog age, BECAUSE the dominant mechanism is more likely queueing than uniformly slower assessments.`

4. `IF high-complexity waiting falls after prioritization while standard-case waiting or its upper tail rises, THEN publish class-specific delay distributions and review the priority and capacity policy rather than declaring aggregate improvement or failure, BECAUSE prioritization can redistribute scarce capacity without creating or removing total work.`

5. `IF renewal-season volume and complexity increase but seasonally and case-mix-standardized within-stratum behavior remains stable, THEN treat the change primarily as expected population drift and adjust capacity plans, BECAUSE aggregate DFGs and cycle times can change solely because the case population changes.`

6. `IF resource missingness is concentrated in particular migrated activities or sources, THEN suspend affected assessor and team comparisons, repair provenance, and run missingness sensitivity analyses, BECAUSE non-randomly absent identifiers can manufacture organizational drift and bias staffing attribution.`

7. `IF a December-style improvement coincides with falling load, supplier recovery, overtime, and a quality campaign, THEN estimate daily exposure-adjusted intervention effects and continue monitoring mature cohorts before crediting any intervention, BECAUSE concurrent recovery mechanisms and backlog maturation prevent clean attribution from before-and-after monthly averages.`
