## 1. Normalization Assumptions

**A1 — Offset direction.** `offset = recorded  true`; offset  [a,b]  true  [recorded  b, recorded  a]. Resolution/rounding is applied to the recorded reading first, then the offset shift (the composition is additive, so order is immaterial numerically).

**A2 — Resolution windows.**
- HUB: displayed second s  reading  [s0.5, s+0.5]; with offset [1,+1]  true  [s1.5, s+1.5].
- Floor-to-minute (OPS-BER, VENDOR-NY, LEGACY-BER): displayed M  reading  [M, M+60) — the upper bound is a **supremum** (half-open). Treated as closed for classification; no decision below sits within 1 s of an affected bound (smallest margin anywhere is 1.5 s).
- SENSOR (round 10 s): displayed t  reading  [t5, t+5); with offset ±5  true  [t10, t+10].
- MOBILE-LON (round 1 min): displayed t  reading  [t30, t+30); with offset ±300  [t330, t+330].

**A3 — Time zones.** 20260601: Berlin = CEST (UTC+2), New York = EDT (UTC4), London = BST (UTC+1). 20251026 Berlin is the DST fold day.

**A4 — DST fold (T-405).** Each LEGACY-BER reading in local 02:xx yields **two disjoint candidate UTC windows** (CEST branch = UTC+2, CET branch = UTC+1), each carrying rounding + ±60 s offset uncertainty. The ingestion-order constraint (Alert < Investigation < Containment) is applied as a **chain-feasibility filter** over the Cartesian product of branches (greedy earliest-feasible test). Result: exactly one branch combination survives (Alert=CEST, Inv=CET, CC=CET). *Assumption:* ingestion order reflects occurrence order; if ingestion lag could approach 1 h, the branches reopen and S1 for T-405 degrades toward INDETERMINATE.

**A5 — Inferred start (T-404).** Investigation_Start := Investigation_Complete  d, d  [1080, 1500] s, propagated as interval arithmetic: Start  [IC_low  1500, IC_high  1080]. Assumes the signed work record measures StartInvestigation_Complete on the same clock domain as the HUB events. All uncertainty retained; no midpoint substitution.

**A6 — Derived receipt (T-407).** Alert_Received := Alert_Sent + ,   [0, 1200] s (network evidence). `Alert_Sent  Alert_Received` semantically; the causal constraint "receipt  start" is **not imposed** in the baseline (not logged). Imposing it changes the duration interval from raw [183, 1023] to [3, 1023] (clamped [0, 1023]) — classification unchanged.

**A7 — Mobile entry delay (T-406).** Primary treatment: the delay is an **additional additive error  [0, +300] s on (recorded  true)**, i.e., it widens the **occurrence-time** interval downward (we cannot distinguish "correct time typed late" from "entry time typed as event time"). Result: Inv  [12:04:30, 12:19:30) UTC. Alternative treatment (delay is pure recording latency; the typed value remains the claimed event time) gives [12:08:30, 12:19:30). **This assumption is material:** it flips T-406 S2 and profile (IC) at =1 from POSSIBLE_VIOLATION to CERTAIN_PASS. Flagged in §4.

**A8 — Non-negativity.** Physical durations are  0. Where evidence permits order inversion (T-407 raw low 183 s; T-409 raw low 481.5 s), the feasible set is clamped to [0, ·] for testing and the inversion is reported as an internal-consistency warning. Clamping never changes a classification here (negative durations violate every positive threshold/band anyway).

**A9 — Unions preserved.** Duration feasible sets are kept as merged unions of intervals; classifications evaluate every component. Acceptance regions: SLA [0, T] inclusive; profile [, +] inclusive.

## 5. PM4Py Temporal-Conformance Code

The midpoint log below is **explicitly a lossy approximation**: PM4Py consumes point timestamps and cannot represent interval uncertainty; it is used purely as a cross-check of the interval conclusions, never as ground truth. If your pm4py version returns a different deviation shape, `show_devs()` isolates that part and prints raw entries; nothing in §§3–4 depends on pm4py.

```python
# =============================================================================
# Interval-based temporal conformance (SLA + temporal profile) with a
# LOSSY midpoint PM4Py cross-check. No external files. Needs pandas; pm4py
# optional (guarded). Python >= 3.9 (zoneinfo).
# =============================================================================
from datetime import datetime, timedelta
from zoneinfo import ZoneInfo
import pandas as pd

UTC = ZoneInfo("UTC")

# ---------------- 1) Source metadata ----------------------------------------
RES_WINDOW = {"exact_sec": (-0.5, 0.5), "floor_min": (0.0, 60.0),
              "round_10s": (-5.0, 5.0), "round_min": (-30.0, 30.0)}

    "OPS-BER":     dict(tz="Europe/Berlin",    res="floor_min", off=(-90, 120),  entry=(0, 0)),
    "SENSOR":      dict(tz="UTC",              res="round_10s", off=(-5, 5),     entry=(0, 0)),

# ---------------- 2) Raw evidence (embedded) ---------------------------------
RAW = [

def _parse(rec):
    for f in ("%Y-%m-%d %H:%M:%S", "%Y-%m-%d %H:%M"):
        try: return datetime.strptime(rec, f)
        except ValueError: pass
    raise ValueError(rec)

IV = {}                                   # (case, activity) -> [(lo, hi), ...] UTC
def normalize(sysname, rec, special):
    if sysname == "INFERRED":             # T-404: start = IC - d, d in [1080,1500]
        return [(lo - timedelta(seconds=1500), hi - timedelta(seconds=1080))
                for lo, hi in IV[("T-404", "Investigation_Complete")]]

        if (lo, hi) not in ivs: ivs.append((lo, hi))
    e = meta["entry"][1]                  # entry delay widens OCCURRENCE interval (A7)
    if e: ivs = [(lo - timedelta(seconds=e), hi) for lo, hi in ivs]
    return ivs

for case, act, sysname, rec, sp in RAW:               # order matters (inferences)
    IV[(case, act)] = normalize(sysname, rec, sp)

# DST-fold branch pruning via ingestion-order chain feasibility (A4)
ORDER = ["Alert_Received", "Investigation_Start", "Containment_Complete"]
def chain_ok(seq):
    tprev = None
    for lo, hi in seq:
        t = lo if tprev is None else max(lo, tprev)
        if t > hi: return False
        tprev = t
    return True
for case in sorted({c for c, _ in IV}):
    acts = [a for a in ORDER if (case, a) in IV]
    lists = [IV[(case, a)] for a in acts]
    if any(len(l) > 1 for l in lists):
        surv = {a: set() for a in acts}
        def rec(i, chosen):
            if i == len(lists):
                for a, iv in zip(acts, chosen): surv[a].add(iv)
                return
            for iv in lists[i]:
                if chain_ok(chosen + [iv]): rec(i + 1, chosen + [iv])
        rec(0, [])
        for a in acts: IV[(case, a)] = sorted(surv[a])

# ---------------- 4) Duration sets + interval classification ------------------
def merge(ivs):
    out = []
    for lo, hi in sorted(ivs):
        if out and lo <= out[-1][1]: out[-1] = (out[-1][0], max(out[-1][1], hi))
        else: out.append((lo, hi))
    return out

def duration_set(xivs, yivs, clamp=True):
    ivs = []
    for xlo, xhi in xivs:
        for ylo, yhi in yivs:
            lo, hi = (ylo - xhi).total_seconds(), (yhi - xlo).total_seconds()
            if clamp and hi >= 0: lo = max(lo, 0.0)     # A8, warns printed below
            ivs.append((lo, hi))
    return merge(ivs)

def cls_sla(durs, lim):
    if all(h <= lim for _, h in durs): return "CERTAIN_PASS"
    if all(l > lim for l, _ in durs):  return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

def cls_band(durs, mu, sd, z):
    lo, hi = mu - z * sd, mu + z * sd
    if all(l >= lo and h <= hi for l, h in durs): return "CERTAIN_PASS"
    if all(h < lo or l > hi for l, h in durs):    return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"
```

## 7. Governance Recommendation

1. **UTC storage & raw retention.** Store all event times as UTC instants; retain the raw recorded string, source system, declared time zone, and resolution semantics as immutable provenance columns. Never overwrite raw values with normalized ones.
2. **Clock-offset telemetry.** Collect per-source, per-hour offset estimates (NTP/PTP), not daily aggregates; alarm on drift approaching enforcement margins. T-409 shows a missing one-hour diagnostic degrades a finding from testable-with-confidence to weak; T-401/T-402 show daily bounds leave multi-minute ambiguity exactly where SLAs are decided.
3. **Resolution metadata.** Machine-readable rounding/floor semantics per source (as in §1 A2) so interval construction is automatic, not tribal knowledge.
4. **Lifecycle semantics.** Emit Investigation_Start as a first-class lifecycle event (T-404's inference should be a fallback, never the norm). Mark SENSOR-style records explicitly as completion events. Define Alert_Sent vs Alert_Received as distinct activities joined by a message identifier with delivery acknowledgments (T-407).
5. **DST fold.** Never persist bare local time for fold hours; store UTC at ingest or a fold disambiguator. Ingestion-sequence numbers are a forensic fallback (as used for T-405), not a substitute.
6. **Causal identifiers.** Require explicit predecessor links (alertreceiptstartcontainmentclose) so ordering constraints are evidence, not assumption.
7. **User-entered timestamps.** Capture entry latency and device clock health; treat entry delay as occurrence-time uncertainty by default (A7) unless telemetry proves otherwise.
8. **Enforcement policy — interval overlap is necessary but not sufficient.** Recommend: (a) **certain violations** (entire feasible interval beyond the limit) are actionable findings; (b) **possible violations** route to a review queue with the responsible source's uncertainty attached; (c) SLA tolerance floors must exceed combined measurement uncertainty (here  ±1.5 s HUB, up to ±10 min mobile/vendor) so enforcement never punishes instrument noise — the +2/+5 min matrix shows most PVs dissolve under realistic tolerances while T-402 S1 and T-408 S2/S3 survive as genuine breaches; (d) recalibrate profile (, ) and  periodically, and treat  as a risk-appetite dial — never as a legal threshold; (e) publish which classifications are legally citable (certain only) versus investigative leads (possible).
