## 1. Duplicate-handling decision tree

Cleaning a multi-system Object-Centric Event Log (OCEL) requires evaluating candidate groups that share a timestamp window and related objects before mutating event or relation tables. In an OCEL, neither identical `(activity, timestamp)` pairs nor shared hub objects (such as an Order or Invoice) prove duplication, because multiple child objects can be processed concurrently and upstream activity harmonization often conflates distinct business steps.

```text
Candidate group shares timestamp (or narrow clock-skew window) AND >= 1 related object

 1. Same source, same source_event_key, AND identical payload_hash + E2O set?
    YES  [Exact technical duplicate]
               Action: DROP redundant copy (retain earliest ingestion record; log dropped ID).

 NO
    2. Same harmonized label, but source metadata/schemas show distinct business steps
         (e.g., warehouse release vs. carrier acceptance)?
       YES  [Harmonization collision between semantically distinct source activities]
                  Action: RETAIN BOTH WITH REFINED LABELS OR QUALIFIERS.
   
    3. Events reference distinct focal/leaf objects of the same object type
         (e.g., Item I1 vs. I2, or Payment M1 vs. M2) with distinct source keys?
       YES  [Concurrent same-label events involving different objects]
                  Action: RETAIN BOTH UNCHANGED.
   
    4. Cross-system reconciliation key or shared business identifier proves both records
         observe the exact same physical/business state transition?
       YES  [Same physical event observed by multiple systems]
                  Action: MERGE ATTRIBUTES AND RELATIONS (apply field-level source authority;
                  union verified E2O relations; preserve full multi-source provenance).
   
    5. Downstream record is an asynchronous status or balance rollup triggered by
         one or more detailed upstream transactions, lacking lower-level child objects?
       YES  [Summary event derived from a detailed event]
                   Conservative / system-audit view:
                     Action: RETAIN BOTH WITH REFINED LABELS OR QUALIFIERS.
                   Pure business-transition view (only if 1:1 or cleanly suppressible):
                      Action: MERGE ATTRIBUTES AND RELATIONS (if 1:1) or suppress rollup with
                      multi-parent provenance (never merge N detailed events through 1 rollup).
   
    6. Evidence is incomplete, keys are unaligned, or object scopes conflict without rule?
        YES  [Unresolved candidate]
                   Action: QUARANTINE FOR REVIEW (keep unchanged in analytical baseline with
                   `uncertain_duplicate=True` flag until domain sign-off).
```

Every terminal rule prioritizes reversibility: dropping is restricted to byte-identical technical retries, merging requires verified entity/event equivalence, and structural ambiguity defaults to label disambiguation or quarantine rather than destructive aggregation.

## 3. Timestamp-tie ordering rules

Because source timestamps have second-level resolution (`10:00:00`, `10:15:00`, `12:00:00`), multiple causally ordered operations collide at identical timestamps. Converting ties into a total order requires constructing a directed acyclic graph (DAG) of precedence constraints first and linearizing it second.

### Precedence hierarchy (semantic vs. deterministic)

1. **Domain constraints (Semantic):** Explicit business invariants across activities and objects (e.g., all items packed into `P1` must be picked before `P1` is packed; warehouse release precedes carrier acceptance; payment authorization on `M1` precedes capture on `M1`).
2. **Lifecycle constraints on shared objects (Semantic):** State-machine transitions of a specific object instance (e.g., Invoice `V1` must be issued before payments referencing `V1` are settled against it; Delivery `D1` is accepted by the carrier before onward carrier handover).
3. **Source-specific causal semantics (Semantic):** Cross-system message causality established by architecture (e.g., `e07` is generated from a WMS packing message `e06`, so `e06  e07`; `e15` is generated after PSP payment messages, so `{e13, e14}  e15`).
4. **Within-source sequence `source_seq` (Semantic for serialization within one engine):** Monotonic transaction counters inside a single source (`WMS`: `100 < 110 < 120`; `SCANNER`: `551 < 552`; `CARRIER`: `1 < 2`; `ERP`: `40 < 41`; `PSP`: `400 < 401 < 402`). Note: `source_seq` across *different* systems is incomparable (`ERP:30` vs. `WMS:110` means nothing). Furthermore, when a single engine serializes independent objects (`PSP:401` for `M1` vs. `PSP:402` for `M2`), `source_seq` reflects technical commit order rather than strict business dependency.
5. **Ingestion time `ingested_at` (Non-semantic / Excluded from business ordering):** Network retries, batch polling, and queue backlogs invert `ingested_at` relative to business reality (e.g., `BILLING` `e16` ingested at `12:00:04` after `PSP` captures `e13/e14` at `12:00:03`). Using `ingested_at` as a tie-breaker fabricates impossible lifecycles; it should be recorded only for technical latency monitoring, never as a primary tie-breaker.
6. **Stable fallback order (Purely deterministic):** Lexicographical sort on `(canonical_source, source_event_key, canonical_eid)` to break remaining incomparable ties reproducibly across runs.

### Why premature microsecond offsets encode a false story

Calling `pm4py.ocel_add_index_based_timedelta` (or adding row-index microseconds) *before* establishing semantic precedence Permanently bakes arbitrary DataFrame row order or ingestion order into `ocel:timestamp`. Downstream DFG discovery, OC-Petri net mining, and throughput calculators cannot distinguish a synthetic `+1 ms` offset from genuine physical precedence. Worse, if `e16` (`Issue Invoice`) sits at row 16 after `e13` (`Capture Payment`) at row 13, index-based offsets assert as hard fact that the customer paid an invoice before it was issued. Even after semantic sorting, a total order is only a *linear extension* of a partial order—it must never be interpreted as proof that concurrent branches could not occur in parallel.

### Intended orders for tied clusters

* **10:00:00 (`e03–e07`, after merging `e03/e04  e03`):**
  * *Semantic partial order:* `{e03, e05}  e06  e07` (`I1` and `I2` must both be picked before `P1` containing `{I1, I2}` is packed at `e06`; `e06` triggers ERP message `e07`). If `e03` inherits `e04`’s scanner provenance (`SCANNER:551 < SCANNER:552`), physical scan order further supports `e03  e05`; otherwise `e03` and `e05` are concurrent item picks.
  * *Deterministic total order:* `e03  e05  e06  e07` (Conservative) or `e03  e05  e06` (Evidence-based).
* **10:15:00 (`e08–e10`):**
  * *Semantic partial and total order coincide:* `e08  e09  e10`. Domain custody requires warehouse release (`e08`) before carrier acceptance (`e09`), and both Known Fact 5 and `CARRIER` `source_seq` (`1 < 2`) require `e09  e10`.
* **12:00:00 (`e11–e16`, after merging `e11/e16  e11`):**
  * *Semantic partial order:* `e11  e12  e13`, `e11  e14`, and `{e13, e14}  e15` (assuming `V1` issuance `e11` precedes settlement events referencing `V1`, corroborated by `ERP:40 < ERP:41`; Fact 7 + `PSP:400 < 401` fixes `e12  e13`; Fact 8 fixes `{e13, e14}  e15`). Within PSP, `source_seq` `401 < 402` places `e13` before `e14`, though `e14` (`M2`) is business-concurrent with `M1`’s sequence (`e11  e14  e12  e13  e15` or `e11  e12  e14  e13  e15` would also be domain-admissible if `M2` were processed on an independent channel).
  * *Deterministic total order:* `e11  e12  e13  e14  e15` (Conservative) or `e11  e12  e13  e14` (Evidence-based).

## 4. Conservative cleaning pipeline

The conservative pipeline minimizes semantic assumptions so both business-process analysts and IT integration auditors can trust the resulting OCEL:

1. **Immutable provenance snapshot:** Copy `ocel:timestamp` to `original_timestamp` and `ocel:activity` to `original_activity`; retain `source`, `source_event_key`, `source_seq`, `ingested_at`, and `payload_hash`.
2. **Exact technical retry filter:** Deduplicate only records sharing identical `(activity, timestamp, source, source_event_key, payload_hash, object_set)` (0 dropped here, safeguarding against accidental pipeline re-ingestion).
3. **Verified cross-system duplicate merge:** Merge only pairs backed by explicit reconciliation or shared entity-issuance proof:
   * `e03 + e04  e03` (retaining WMS enriched location + Scanner metadata/sequence provenance).
   * `e11 + e16  e11` (combining ERP accounting fields + BILLING customer fields).
4. **Targeted label disambiguation (preserving abstraction levels):**
   * Refine `e09` from `Dispatch Package` to `Accept Package (Carrier)` to undo the harmonization collision with `e08`.
   * Refine `e07` to `Record Pack Status (ERP)` and `e15` to `Post Payment Summary (ERP)` so derived ERP rollups remain visible for system-latency analysis without masquerading as repeated physical packing or payment captures.
5. **Partial-order ranking and guarded timestamp indexing:** Compute a topological `semantic_tie_rank` reflecting the rules in Section 3 while tagging incomparable concurrent pairs (e.g., `concurrency_group` metadata) so analysts know `e03/e05` and `M1/M2` were not strictly causal. Sort via `pm4py.ocel_sort_by_additional_column` and apply `pm4py.ocel_add_index_based_timedelta` solely to stabilize downstream PM4Py algorithms, never overwriting `original_timestamp`.

**Expected retained event count:** **15 events** (`17` raw minus `e04` and `e16`), with **39 E2O relations** (`44` raw minus `3` on `e04` and `2` on `e16`).

* Performs the verified merges (`e03/e04  e03`, `e11/e16  e11`) and keeps the `e08/e09` disambiguation (`Accept Package (Carrier)`), as well as distinct child-object events `e05` (`I2`) and `e14` (`M2`).
* Merges `e07` into `e06` (`Pack Package`), treating the ERP status update as a second observation of the packing transition.
* Retires `e15` into the provenance log as a derived multi-parent rollup of `{e13, e14}` rather than merging it into either `e13` or `e14`.
* **Retained count:** **13 events** (35 E2O relations).
* **Main semantic damage:** Erases cross-system ERP synchronization visibility (`WMS  ERP` and `PSP  ERP` integration lag disappears, hiding stuck-interface bottlenecks if ERP posting fails or lags in production).

### Alternative B: Mechanically aggressive PM4Py merging
Applies `pm4py.ocel_merge_duplicates(ocel, have_common_object=True)` directly to the harmonized raw log without label disambiguation or object-type cardinality checks:
* Collapses `e03 + e04 + e05` (3  1), `e06 + e07` (2  1), `e08 + e09` (2  1), `e11 + e16` (2  1), and `e13 + e14 + e15` (3  1).
* **Retained count:** **10 events** (28 E2O relations). *(Note: Even naive `pm4py.ocel_drop_duplicates`—which requires identical object sets—retains 14 events but silently deletes `e09`’s carrier acceptance and throws away `e16`’s authoritative billing attributes.)*
* **Main semantic damage & why `have_common_object=True` fails on `e13` and `e14`:** In `pm4py.ocel_merge_duplicates`, setting `have_common_object=True` merges any events with matching `(ocel:activity, ocel:timestamp)` whose related-object sets have a non-empty intersection ($O(e_a) \cap O(e_b) \neq \emptyset$). In hierarchical business schemas, hub/container objects like Order `O1`, Invoice `V1`, and Package `P1` are attached to nearly every child event. Thus, `e13` (`{O1, V1, M1}`) and `e14` (`{O1, V1, M2}`) intersect on `{O1, V1}` and get fused—along with `e15` (`{O1, V1}`)—into a single synthetic `Capture Payment` event linked to *both* `M1` and `M2`. Likewise, `e03` (`I1`) and `e05` (`I2`) intersect on `{O1, P1}` and fuse into one batch pick. Existential overlap (`have_common_object=True`) ignores **focal object-type discrimination**: two events referencing disjoint instances of the activity’s focal object type (`Payment` for `Capture Payment`, `Item` for `Pick Item`) are distinct business occurrences regardless of shared parent containers.

## 6. PM4Py-oriented Python implementation

The implementation below isolates every scenario via `copy.deepcopy`, inspects candidate clusters before touching events, uses `pm4py.ocel_drop_duplicates` safely on scoped exact technical signatures, applies verified merges and label refinements, computes semantic tie ranks before calling `pm4py.ocel_sort_by_additional_column` and `pm4py.ocel_add_index_based_timedelta`, contrasts `pm4py.ocel_merge_duplicates` in a quarantined aggressive branch, and enforces referential integrity.

```python
import copy
import json
import warnings
from typing import Dict, List, Any, Tuple
import pandas as pd
import pm4py
from pm4py.objects.ocel.obj import OCEL


def snapshot_provenance_columns(ocel: OCEL) -> OCEL:
    """Preserve immutable original timestamps, labels, and source keys on a deep copy."""
    out = copy.deepcopy(ocel)
    eid_col = out.event_id_column
    act_col = out.event_activity
    ts_col = out.event_timestamp

    if "original_timestamp" not in out.events.columns:
        out.events["original_timestamp"] = out.events[ts_col].copy()
    if "original_activity" not in out.events.columns:
        out.events["original_activity"] = out.events[act_col].copy()

    required_meta = ["source", "source_event_key", "source_seq", "ingested_at", "payload_hash"]
    missing = [c for c in required_meta if c not in out.events.columns]
    if missing:
        raise KeyError(f"Missing required provenance metadata columns: {missing}")

    if "provenance_sources_json" not in out.events.columns:
        out.events["provenance_sources_json"] = out.events.apply(
            lambda r: json.dumps([{
                "eid": r[eid_col],
                "source": r["source"],
                "source_event_key": r["source_event_key"],
                "source_seq": int(r["source_seq"]) if pd.notna(r["source_seq"]) else None,
                "ingested_at": str(r["ingested_at"]),
                "payload_hash": r["payload_hash"],
                "original_activity": r["original_activity"],
                "original_timestamp": str(r["original_timestamp"]),
            }]),
            axis=1,
        )
    return out


def inspect_candidate_groups(ocel: OCEL) -> pd.DataFrame:
    """Pre-check same-(timestamp, activity) clusters before running any deduplication."""
    eid_col = ocel.event_id_column
    act_col = ocel.event_activity
    ts_col = ocel.event_timestamp
    oid_col = ocel.object_id_column
    otype_col = ocel.object_type_column

    rel_summary = (
        ocel.relations.groupby(eid_col)
        .agg(
            object_set=(oid_col, lambda s: tuple(sorted(set(s)))),
            otype_counts=(otype_col, lambda s: dict(pd.Series(s).value_counts())),
        )
        .reset_index()
    )
    ev = ocel.events.merge(rel_summary, on=eid_col, how="left")
    grouped = ev.groupby([ts_col, act_col]).filter(lambda g: len(g) > 1)

    rows = []
    for (ts, act), grp in grouped.groupby([ts_col, act_col]):
        obj_sets = [set(x) if isinstance(x, tuple) else set() for x in grp["object_set"]]
        common_objs = set.intersection(*obj_sets) if obj_sets else set()
        union_objs = set.union(*obj_sets) if obj_sets else set()
        rows.append({
            "timestamp": ts,
            "activity": act,
            "candidate_eids": list(grp[eid_col]),
            "sources": list(grp["source"]),
            "common_objects": sorted(common_objs),
            "symmetric_diff_objects": sorted(union_objs - common_objs),
            "exact_object_match": len({frozenset(s) for s in obj_sets}) == 1,
        })
    return pd.DataFrame(rows)


def sync_relations_event_fields(ocel: OCEL) -> None:
    """Keep redundant activity and timestamp columns in ocel.relations synchronized with ocel.events."""
    eid_col = ocel.event_id_column
    act_col = ocel.event_activity
    ts_col = ocel.event_timestamp
    act_map = ocel.events.set_index(eid_col)[act_col]
    ts_map = ocel.events.set_index(eid_col)[ts_col]
    ocel.relations[act_col] = ocel.relations[eid_col].map(act_map)
    ocel.relations[ts_col] = ocel.relations[eid_col].map(ts_map)


def drop_exact_technical_duplicates_pm4py(ocel: OCEL, audit_log: List[Dict[str, Any]]) -> OCEL:
    """
    Justified use of pm4py.ocel_drop_duplicates:
    Temporarily scopes ocel:activity to the strict technical signature
    (activity + source + source_event_key + payload_hash) so pm4py.ocel_drop_duplicates
    removes ONLY true technical re-ingestions sharing identical E2O sets,
    never dropping cross-system collisions like e08/e09 or split-authority e11/e16.
    """
    work = copy.deepcopy(ocel)
    eid_col = work.event_id_column
    act_col = work.event_activity

    before_events = work.events.set_index(eid_col).copy()
    saved_activities = work.events.set_index(eid_col)[act_col].to_dict()

    work.events[act_col] = (
        work.events[act_col].astype(str)
        + "||" + work.events["source"].astype(str)
        + "||" + work.events["source_event_key"].astype(str)
        + "||" + work.events["payload_hash"].astype(str)
    )
    sync_relations_event_fields(work)

    deduped = pm4py.ocel_drop_duplicates(work)
    deduped.events[act_col] = deduped.events[eid_col].map(saved_activities)
    sync_relations_event_fields(deduped)

    dropped_eids = sorted(set(before_events.index) - set(deduped.events[eid_col]))
    for d_eid in dropped_eids:
        audit_log.append({
            "canonical_eid": None,
            "source_eids": [d_eid],
            "rule": "EXACT_TECHNICAL_DUPLICATE_DROP_V1",
            "confidence": "High",
            "reason": "Identical activity, timestamp, source, source_event_key, payload_hash, and E2O set.",
        })
    return deduped


def merge_verified_pairs(
    ocel: OCEL,
    merge_specs: List[Dict[str, Any]],
    audit_log: List[Dict[str, Any]],
) -> OCEL:
    """
    Deterministic verified-pair merger for reconciled cross-system observations
    (e.g., e03/e04, e11/e16, and optionally e06/e07 in evidence-based mode).
    """
    work = copy.deepcopy(ocel)
    eid_col = work.event_id_column
    oid_col = work.object_id_column
    qual_col = getattr(work, "qualifier", "ocel:qualifier")

    for spec in merge_specs:
        keep_eid = spec["canonical_eid"]
        absorb_eid = spec["absorb_eid"]
        if keep_eid not in set(work.events[eid_col]) or absorb_eid not in set(work.events[eid_col]):
            continue

        keep_idx = work.events.index[work.events[eid_col] == keep_eid][0]
        absorb_row = work.events.loc[work.events[eid_col] == absorb_eid].iloc[0]
        keep_row = work.events.loc[keep_idx]

        # Consolidate multi-source provenance JSON
        merged_prov = (
            json.loads(keep_row["provenance_sources_json"])
            + json.loads(absorb_row["provenance_sources_json"])
        )
        work.events.at[keep_idx, "provenance_sources_json"] = json.dumps(merged_prov)

        # Preserve secondary attributes under explicit source-namespaced columns
        sec_prefix = f"merged_{absorb_row['source'].lower()}"
        for col in ["source_event_key", "source_seq", "ingested_at", "payload_hash"]:
            ns_col = f"{sec_prefix}_{col}"
            if ns_col not in work.events.columns:
                work.events[ns_col] = None
            work.events.at[keep_idx, ns_col] = absorb_row[col]

        # Apply optional authoritative attribute overrides from absorbed event
        retained_attrs = {keep_row["source"]: ["default_canonical_fields"], absorb_row["source"]: []}
        discarded_conflicts = {}
        for attr in spec.get("authoritative_from_absorbed", []):
            if attr in work.events.columns and pd.notna(absorb_row[attr]):
                if pd.notna(keep_row[attr]) and keep_row[attr] != absorb_row[attr]:
                    discarded_conflicts[attr] = {
                        "discarded_source": keep_row["source"],
                        "discarded_value": keep_row[attr],
                    }
                work.events.at[keep_idx, attr] = absorb_row[attr]
                retained_attrs[absorb_row["source"]].append(attr)

        # Union E2O relations cleanly without duplicating (eid, oid, qualifier)
        work.relations.loc[work.relations[eid_col] == absorb_eid, eid_col] = keep_eid
        dedup_cols = [eid_col, oid_col] + ([qual_col] if qual_col in work.relations.columns else [])
        work.relations = work.relations.drop_duplicates(subset=dedup_cols).reset_index(drop=True)

        # Remove absorbed event row and resync relation attributes
        work.events = work.events.loc[work.events[eid_col] != absorb_eid].reset_index(drop=True)
        sync_relations_event_fields(work)

        audit_log.append({
            "canonical_eid": keep_eid,
            "source_eids": [keep_eid, absorb_eid],
            "rule": spec["rule"],
            "reviewer_or_version": "pipeline_rule_v1.2",
            "original_activity": keep_row["original_activity"],
            "refined_activity": work.events.loc[work.events[eid_col] == keep_eid, work.event_activity].iloc[0],
            "retained_attributes_by_source": retained_attrs,
            "discarded_conflicts": discarded_conflicts,
            "confidence": spec["confidence"],
            "reason": spec["reason"],
        })
    return work


def refine_activity_labels(
    ocel: OCEL,
    refinements: Dict[str, Tuple[str, str]],
    audit_log: List[Dict[str, Any]],
) -> OCEL:
    """Apply targeted activity disambiguation while preserving original_activity."""
    work = copy.deepcopy(ocel)
    eid_col = work.event_id_column
    act_col = work.event_activity

    for eid, (new_label, reason) in refinements.items():
        mask = work.events[eid_col] == eid
        if mask.any():
            orig_act = work.events.loc[mask, "original_activity"].iloc[0]
            work.events.loc[mask, act_col] = new_label
            audit_log.append({
                "canonical_eid": eid,
                "source_eids": [eid],
                "rule": "LABEL_DISAMBIGUATION_V1",
                "reviewer_or_version": "pipeline_rule_v1.2",
                "original_activity": orig_act,
                "refined_activity": new_label,
                "confidence": "High",
                "reason": reason,
            })
    sync_relations_event_fields(work)
    return work


def retire_multi_parent_summary_event(
    ocel: OCEL,
    summary_eid: str,
    parent_eids: List[str],
    reason: str,
    audit_log: List[Dict[str, Any]],
) -> OCEL:
    """Suppress an N:1 rollup summary (e.g., e15) in evidence-based mode without merging M1 and M2."""
    work = copy.deepcopy(ocel)
    eid_col = work.event_id_column
    if summary_eid not in set(work.events[eid_col]):
        return work

    sum_row = work.events.loc[work.events[eid_col] == summary_eid].iloc[0]
    work.events = work.events.loc[work.events[eid_col] != summary_eid].reset_index(drop=True)
    work.relations = work.relations.loc[work.relations[eid_col] != summary_eid].reset_index(drop=True)

    audit_log.append({
        "canonical_eid": None,
        "parent_canonical_eids": parent_eids,
        "source_eids": [summary_eid],
        "rule": "RETIRE_MULTI_PARENT_ROLLUP_V1",
        "reviewer_or_version": "pipeline_rule_v1.2",
        "original_activity": sum_row["original_activity"],
        "confidence": "Medium-High",
        "reason": reason,
        "archived_event_snapshot": json.loads(sum_row["provenance_sources_json"]),
    })
    return work


def apply_semantic_tie_order_and_timedelta(ocel: OCEL, audit_log: List[Dict[str, Any]]) -> OCEL:
    """
    Compute a deterministic partial-order linearization column FIRST, sort via
    pm4py.ocel_sort_by_additional_column, and ONLY THEN apply pm4py.ocel_add_index_based_timedelta.
    Never uses ingested_at as primary business order; preserves original_timestamp.
    """
    work = copy.deepcopy(ocel)
    eid_col = work.event_id_column
    act_col = work.event_activity
    ts_col = work.event_timestamp

    # Domain + lifecycle + causal tier within an identical second-level timestamp
    def semantic_tier(row: pd.Series) -> int:
        act = row[act_col]
        src = row["source"]
        # 10:00 cluster: Pick before WMS Pack before ERP Pack Status
        if act == "Pick Item":
            return 10
        if act == "Pack Package" and src == "WMS":
            return 20
        if act in ("Pack Package", "Record Pack Status (ERP)") and src == "ERP":
            return 30
        # 10:15 cluster: Warehouse release before Carrier accept before Handover
        if act == "Dispatch Package" and src == "WMS":
            return 10
        if act in ("Dispatch Package", "Accept Package (Carrier)") and src == "CARRIER":
            return 20
        if act == "Handover to Carrier":
            return 30
        # 12:00 cluster: Invoice issuance -> Auth -> Capture -> ERP Payment Summary
        if act == "Issue Invoice":
            return 10
        if act == "Authorize Payment":
            return 20
        if act == "Capture Payment" and src == "PSP":
            return 30
        if act in ("Capture Payment", "Post Payment Summary (ERP)") and src == "ERP":
            return 40
        return 50

    # Extract scanner sequence provenance if merged (e.g., e03 carries SCANNER seq 551 from e04)
    def effective_tie_seq(row: pd.Series) -> int:
        if "merged_scanner_source_seq" in row.index and pd.notna(row["merged_scanner_source_seq"]):
            return int(row["merged_scanner_source_seq"])
        return int(row["source_seq"]) if pd.notna(row["source_seq"]) else 999999

    work.events["_sem_tier"] = work.events.apply(semantic_tier, axis=1)
    work.events["_eff_seq"] = work.events.apply(effective_tie_seq, axis=1)

    # Create integer rank strictly respecting (timestamp, _sem_tier, _eff_seq, source, source_event_key, eid)
    ordered_eids = (
        work.events.sort_values(
            by=[ts_col, "_sem_tier", "_eff_seq", "source", "source_event_key", eid_col],
            kind="mergesort",
        )[eid_col]
        .tolist()
    )
    rank_map = {eid: idx for idx, eid in enumerate(ordered_eids)}
    work.events["semantic_tie_rank"] = work.events[eid_col].map(rank_map)
    work.events.drop(columns=["_sem_tier", "_eff_seq"], inplace=True)

    # Step 1: PM4Py sort using semantic_tie_rank
    sorted_ocel = pm4py.ocel_sort_by_additional_column(
        work,
        additional_column="semantic_tie_rank",
        primary_column=work.event_timestamp,
    )
    # Step 2: PM4Py index-based timedelta ONLY after semantic sorting; original_timestamp stays intact
    indexed_ocel = pm4py.ocel_add_index_based_timedelta(sorted_ocel)
    sync_relations_event_fields(indexed_ocel)

    audit_log.append({
        "rule": "SEMANTIC_TIE_ORDER_LINEARIZATION_V1",
        "ordered_eids": indexed_ocel.events[eid_col].tolist(),
        "note": "Total order is a deterministic linear extension; original_timestamp preserved.",
    })
    return indexed_ocel


def validate_ocel_integrity(ocel: OCEL, label: str) -> None:
    """Assert referential, schema, and provenance integrity after transformations."""
    eid_col = ocel.event_id_column
    oid_col = ocel.object_id_column
    act_col = ocel.event_activity
    ts_col = ocel.event_timestamp

    assert not ocel.events[eid_col].duplicated().any(), f"[{label}] Duplicate eid in events!"
    assert not ocel.objects[oid_col].duplicated().any(), f"[{label}] Duplicate oid in objects!"

    missing_eids = set(ocel.relations[eid_col]) - set(ocel.events[eid_col])
    missing_oids = set(ocel.relations[oid_col]) - set(ocel.objects[oid_col])
    assert not missing_eids, f"[{label}] Dangling eids in relations: {missing_eids}"
    assert not missing_oids, f"[{label}] Dangling oids in relations: {missing_oids}"

    merged_check = ocel.relations.merge(
        ocel.events[[eid_col, act_col, ts_col]],
        on=eid_col,
        suffixes=("_rel", "_ev"),
    )
    assert (merged_check[f"{act_col}_rel"] == merged_check[f"{act_col}_ev"]).all(), (
        f"[{label}] Activity mismatch between events and relations!"
    )
    assert (merged_check[f"{ts_col}_rel"] == merged_check[f"{ts_col}_ev"]).all(), (
        f"[{label}] Timestamp mismatch between events and relations!"
    )
    assert "original_timestamp" in ocel.events.columns, f"[{label}] original_timestamp lost!"
    assert "original_activity" in ocel.events.columns, f"[{label}] original_activity lost!"
```

### Six concrete edges/patterns whose interpretation changes

1. **`Pick Item  Pick Item` on `I1` vs. `O1`:** Raw exhibits a false item rework edge on `I1` (`e03  e04`); Conservative eliminates `I1` rework while preserving `O1`’s multi-item loop (`e03  e05`); Aggressive deletes `O1`’s loop and falsely models batch picking.
2. **`Pack Package  Pack Package` (`e06  e07`):** Appears in Raw as physical repacking of `P1`; becomes `Pack Package  Record Pack Status (ERP)` in Conservative; collapses into `Pack Package` in Evidence-based.
3. **`Dispatch Package  Dispatch Package` (`e08  e09`):** Appears in Raw as duplicate warehouse dispatch; Conservative restores the custody chain `Dispatch Package  Accept Package (Carrier)  Handover to Carrier`; Aggressive erases carrier acceptance.
4. **`Capture Payment  Issue Invoice` (`e13/e14  e16`):** Appears if Raw ties are broken by `ingested_at` (`12:00:03` vs. `12:00:04`), implying unbilled payment capture; disappears once `e11/e16` are merged and ordered by `V1` lifecycle (`Issue Invoice  Authorize Payment`).
5. **`Capture Payment  Capture Payment` (`e13  e14  e15`):** Raw mixes installment payments with an ERP balance post; Conservative separates `Capture Payment  Capture Payment` (installments) from ` Post Payment Summary (ERP)`; Aggressive fuses all three.
6. **Multi-object convergence on `Capture Payment` (`M1` + `M2`):** Absent in Raw, Conservative, and Evidence-based (`M1` and `M2` settle independently); fabricated in Aggressive library merge, falsely turning `Capture Payment` into a synchronization join in discovered OC-Petri nets.

## 8. Audit trail and reversibility

To guarantee regulatory auditability and lossless rollback, every transformation writes an append-only provenance table (`ocel_audit_ledger`) alongside event-level provenance columns:

| Field | Type | Description |
|---|---|---|
| `ledger_id` / `canonical_eid` | `string` (`nullable`) | Surviving `ocel:eid` in cleaned log (`null` if dropped as exact retry or retired rollup) |
| `source_eids` | `array<string>` | Complete list of raw `eid`s represented (`["e11", "e16"]`, `["e15"]`, etc.) |
| `merge_rule` | `string` | Machine rule ID (e.g., `SPLIT_AUTHORITY_INVOICE_MERGE_V1`, `LABEL_DISAMBIGUATION_V1`) |
| `reviewer_or_rule_version` | `string` | Automated rule semantic version (`pipeline_rule_v1.2`) or human steward ID |
| `activity_mapping` | `struct` | `{eid: {original_activity, refined_activity}}` for each participating source event |
| `timestamp_mapping` | `struct` | `{eid: {original_timestamp, adjusted_timestamp, semantic_tie_rank}}` |
| `retained_attributes_by_source` | `map<string, array>` | Exact attribute names sourced from `ERP`, `BILLING`, `WMS`, `SCANNER`, etc. |
| `discarded_conflicts` | `map<string, struct>` | Overwritten conflicting attribute values with source system and raw value |
| `confidence_and_reason` | `struct` | `{confidence: "High"|"Medium", reason: "...", parent_eids: [...]}` |
| `raw_relations_snapshot` | `array<struct>` | Original `(eid, oid, otype, qualifier)` tuples prior to union/retirement |

### Reconstructing `ocel_raw`
An analyst reconstructs the exact raw view deterministically in four steps without re-querying source systems:
1. **Unpack merged and retired events:** Expand `provenance_sources_json` on surviving events plus archived snapshots in `ocel_audit_ledger` (for dropped/retired `eid`s such as `e15`) back into individual event rows keyed by original `eid`.
2. **Restore overwritten attributes:** Reapply `discarded_conflicts` to restore any non-authoritative raw field values onto their respective raw `eid`s and drop synthetic `merged_*` and `semantic_tie_rank` columns.
3. **Restore original labels and timestamps:** Copy `original_activity  ocel:activity` and `original_timestamp  ocel:timestamp`.
4. **Restore raw E2O relations:** Replace merged relation rows for multi-source `canonical_eid`s using `raw_relations_snapshot`, then resynchronize `ocel:activity` and `ocel:timestamp` on `ocel.relations`.

## 9. Failure modes and safeguards

1. **Collapsing distinct partial payments (`e13` and `e14`):**
   * *Mechanism:* Deduplicating on `(activity, timestamp)` with shared `O1/V1` merges `M1` and `M2` into one payment event.
   * *Safeguard:* Enforce a **focal-object disjointness guard**—forbid merging two events if their E2O sets contain distinct instances of any non-container object type (`Payment`, `Item`).
2. **Converting abstraction-level updates into false rework (`e06/e07`, `e13/e15`):**
   * *Mechanism:* Harmonizing detailed WMS/PSP transactions and downstream ERP status updates to identical labels creates self-loops (`Pack  Pack`, `Capture  Capture`).
   * *Safeguard:* Qualify cross-layer status updates with system/abstraction suffixes (`Record Pack Status (ERP)`) while keeping `original_activity` for cross-log alignment.
3. **Ordering by ingestion time (`ingested_at`):**
   * *Mechanism:* Sorting `12:00:00` ties by `ingested_at` places `BILLING` `Issue Invoice` (`12:00:04`) after `PSP` `Capture Payment` (`12:00:03`).
   * *Safeguard:* Ban `ingested_at` from semantic tie-breaking; encode explicit object-lifecycle and within-source `source_seq` precedence before linearizing.
4. **Treating shared objects as proof of duplication:**
   * *Mechanism:* Hub objects (`O1`) link to every event in an order’s lifecycle, making `have_common_object=True` virtually equivalent to global `(activity, timestamp)` merging within an order.
   * *Safeguard:* Require positive reconciliation keys or shared business document keys *plus* compatible focal object sets before merging.
5. **Unioning incompatible E2O relations:**
   * *Mechanism:* Merging `e15` (`{O1, V1}`) with `e13` (`{O1, V1, M1}`) and `e14` (`{O1, V1, M2}`) attaches both `M1` and `M2` to a single capture, corrupting E2O qualifiers and per-payment amounts.
   * *Safeguard:* Block merges when an N:1 summary event spans multiple upstream detailed events; either keep the summary distinct with a refined label or retire it with multi-parent provenance.
6. **Changing durations through synthetic microseconds:**
   * *Mechanism:* `pm4py.ocel_add_index_based_timedelta` mutates `ocel:timestamp`; computing throughput on mutated timestamps invents sub-second/second lead times or distorts SLA compliance.
   * *Safeguard:* Always snapshot `original_timestamp` first, apply timedeltas *only* after semantic sorting for control-flow discovery, and bind all cycle-time KPIs strictly to `original_timestamp`.
7. **Losing source-authoritative attributes (`e11/e16`, `e03/e04`):**
   * *Mechanism:* Row-dropping deduplicators (`drop_duplicates`) keep whichever event arrived first, discarding `BILLING` line details or `WMS` bin locations.
   * *Safeguard:* Use field-level source-authority maps in `merge_verified_pairs` and log overridden values in `discarded_conflicts`.
8. **Applying duplicate functions to the whole OCEL without inspecting candidate groups:**
   * *Mechanism:* Blindly running `pm4py.ocel_drop_duplicates` or `ocel_merge_duplicates` silently deletes harmonization collisions like `e09` (`Dispatch Package` masking carrier acceptance).
   * *Safeguard:* Mandate `inspect_candidate_groups` pre-checks to review symmetric object-set differences and multi-source label collisions prior to executing any merge or drop step.
