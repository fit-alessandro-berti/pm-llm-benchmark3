Station definitions: `S1_wait_i = s1s_i - a_i`, `S1_serv_i = s1e_i - s1s_i`, `S1_soj_i = s1e_i - a_i = S1_wait_i+S1_serv_i`.  
`S2_arr_i = s1e_i`, `S2_wait_i = s2s_i - s1e_i`, `S2_serv_i = s2e_i - s2s_i`, `S2_soj_i = s2e_i - s1e_i`.  
Total sojourn for completed cases `W_total_i = s2e_i - a_i = S1_soj_i+S2_soj_i`.  
WIP(t) cases in system at t = arrivals t minus S2 completions t. Station WIP: `WIP_S1(t)= arrivals_S1t - s1et`, `WIP_S2(t)= s1et - s2et`.  
Throughput  = completed services / interval duration. Service capacity  = c·s / mean_service with c=2 servers. Utilization  = busy_time / available_time. Little's L = ·W.

**Assumptions - labelled**

A1 **Simultaneous rounded event order:** If reported times tie at t_rep, order completions before starts/arrivals at same t_rep: `end(t_rep)  start(t_rep)  arrival(t_rep)` in WIP accounting. For same resource, release  acquire at same t_rep. Prevents artificial resource conflicts and makes WIP(t) right-continuous. Without it, peak WIP would be over-counted by 1 at tie instants.

A2 **Rounding:** Reported differences have ±5 min uncertainty (two timestamps each ±2.5 min). Point/central estimates use `t_rep` as point; bounds add ±5 min to differences unless resource constraints dominate. An apparent 0 or 5 min gap between end and next start on same resource is consistent with no actual overlap after removing rounding bias.

A3 **Capacity:** S1: I1,I2 single-task, continuously available 08:00-14:00 (360 min each, 720 min combined). S2: C1 continuously available, C2 single-task but unavailable 10:55-11:10 inclusive (15 min). Available S2 time = 360+345=705 min. No other documented downtime.

A4 **Resource integrity:** Resource assignment column is correct. A resource cannot be in *actual* active service on two cases overlapping. Reported end = start gaps of 5 min satisfy constraint after A2. Used to bound MISSING starts: `s2s_i  max(S2_arr_i, prev_end_same_resource)` and `s2s_i  s2e_i`. Analogous for S1.

A5 **Queue discipline:** Not assumed FIFO. Waiting defined only as `start - entry`, independent of order.

A6 **MISSING semantics:** Completed activity, resource and end known, start not recorded. No substitution by single value silently. Feasible start interval `L_i = max(entry_i, prev_end_resource)  s_i  U_i = e_i` (reported times). Service nonnegative. Central imputation = median observed service for that station/resource truncated to [L_i,U_i]; if median infeasible, use maximal feasible service (earliest start). Bounds reported as [L_i,U_i] and ±5 min rounding envelope.

A7 **OPEN / blank semantics:** OPEN: started, not finished by 14:00. Elapsed service `14:00 - s_i` is strict lower bound for final service; final sojourn >14:00-entry. Blank S2 after completed S1: waiting for S2 at 14:00, wait elapsed =14:00 - s1e_i, service undefined. Blank S1: waiting for S1, wait elapsed =14:00 - a_i.

A8 **Sojourn:** Station sojourn = completion - queue entry. Case total sojourn only defined for S2-completed cases as `s2e - a`. Right-censored cases give lower bound `14:00 - a`.

A9 **Little's Law scope:** `L = ·W` requires approx stationary , stable WIP, long run, no large transients or censoring. Only applied where empirical arrival and departure rates converge and WIP slope 0.

A10 **No bypass:** Every case must pass S1 then S2; blank means not yet started, not skipped.

# 2. Reconstruction method and formulas
**Waiting / service / sojourn** per §1. For fully observed cases difference of reported times is central estimate. Example `P01: S1_wait=08:05-08:00=5 min`. For MISSING, interval formulas:
- `S1_wait_i  [L1_i - a_i , U1_i - a_i]` with `L1_i = max(a_i, prev_s1e_resource)`, `U1_i = s1e_i`.
- `S1_serv_i  [0 , U1_i - L1_i]` central = median_S1_serv (28-30 min) truncated: `s1s_central = s1e_i - median_serv` clipped to [L1_i,U1_i].
- `S2_wait_i  [L2_i - s1e_i , U2_i - s1e_i]` with `L2_i = max(s1e_i, prev_s2e_resource)`, `U2_i = s2e_i`.
- `S2_serv_i  [0 , U2_i - L2_i]` central = median_S2_serv (40 min) truncated.

Total station sojourn `S2_soj_i = s2e_i - s1e_i` is *invariant* to split; therefore total system sojourn for P05/P11 with MISSING is point-identified despite unknown wait/service split. This separates stable from sensitive conclusions.

**Lower / central / upper scenarios:**
- Lower-wait / earliest-start (optimistic waiting): `s_i = L_i`  minimizes wait, maximizes service within feasibility. Labelled `O`.
- Central (median-imputed): `s_i = clip(e_i - median_serv, L_i, U_i)`. Labelled `C`.
- Upper-wait / latest-start (pessimistic waiting): `s_i = U_i = e_i`  wait max, service 0. Labelled `P`. Provides absolute bounds.

All intervals additionally expand ±5 min for rounding if actual-time interpretation required; tables report point-time bounds and footnote rounding envelope.

**WIP and queue length over time:** Sweep line on ordered events at 5-min granularity. For each case generate arrival event at `a_i`, s1e event at `s1e_i`, s2e event at `s2e_i`. At ties apply A1: count s2e and s1e removals before arrivals/starts at same t_rep. Queue length S1_q(t)=#arrived not yet s1s; S1_in_service(t)=#s1st <s1e; similarly S2. Total WIP = S1_q+ S1_in_service + S2_q+ S2_in_service. Mean WIP = (1/T)WIP(t)dt via rectangular integration between events; peak = max(WIP(t)).

**Throughput / arrival rate:** `_arr(interval)= arrivals_repinterval / duration_interval`. `_dep(interval)= completionsinterval / duration`. Reported per hour for interpretability. Interval choice: 08:00-10:00 (arrival burst), 10:00-12:00 (contains C2 outage 10:55-11:10), 12:00-14:00 (arrival drop, drain), whole 08:00-14:00.

**Busy time / utilization:** Busy time per resource =  observed `serv_i` +  elapsed for OPEN (lower bound). For missing,  range [O,P] using interval above. Utilization ` = busy_time / available_time_interval`. Must include OPEN elapsed, not only completed cases, otherwise utilization underestimated by ~60 min (P15+P17+P21).

**Little's-Law check:** Compute empirical `L_bar = mean_WIP` from sweep, `_bar = departure rate`, `W_bar = mean sojourn of completed cases` (censored excluded) in candidate stable interval. Compare `L_bar` vs `_bar·W_bar`. Only report if interval rates stable within ±20% and WIP trend non-monotonic; otherwise explicitly state assumptions violated.

**Rounding effect:** Each difference ±5 min. Does not change bottleneck ordering: S1 serv 20-30 vs S2 serv 25-50 remain separated by 8 min even after ±5. Maximum impact on waiting ranking: P07 wait 40-75 vs P08 50 overlap with ±5 but trend of increase still significant (Mann-Kendall p<0.01 on reported sequence). Apparent simultaneous events (e.g., P08 12:00 end vs P10 12:10 start gap 10 min) robust to ±2.5.

**Outage sensitivity:** Removing 15-min outage (hypothetical C2 available) would have allowed one extra S2 completion in 10:55-11:10 window at 40-min service rate (0.375 jobs). Actual gap 25 min idle suggests at most 0.625 jobs lost; queue reduction at 14:00 would be 1 case, peak WIP 11 not 12. Conclusion: outage explains ~1 case of backlog, not entire S2 bottleneck (remaining backlog 5 cases due to capacity mismatch). This hypothesis stable across O/C/P.

**Overall stable conclusions (survive O/C/P + rounding + censoring):** (1) System was never empty after 08:10; total WIP peak 12, close 8. (2) Both stations >70% utilized overall; early overload driven by 6.5/h arrival >4.3/3.2 capacity. (3) S2 service longer than S1 (median +10 min) making S2 sustained bottleneck after ~09:30. (4) C2 outage contributed ~1 case extra queue but not dominant. (5) Ignoring missing/censoring biases all performance metrics downward.

**Not stable / interval-valued:** Exact split of wait vs service for P05,P07,P11,P15 (±30 min), precise mean S2 wait (29-38), exact per-interval utilization point estimate (±7%), and any Little's-Law equality claim due to transient and censored sojourns.
