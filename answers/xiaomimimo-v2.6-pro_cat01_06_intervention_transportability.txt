```python
# 3) Site B candidate model in POWL
#    Two eligibility tracks (statute-constrained), because POWL cannot express
#    the *data condition* "originals are legally required" -> modelled as a
#    free XOR between the two variants.
# --------------------------------------------------------------------------- #
def build_track(with_originals: bool):
    reg = Transition("Register")
    orig   = Transition("Originals Receipt")
    ic     = Transition("Identity Check")
    dc     = Transition("Document Check")
    assess = Transition("Assessment")
    legal  = Transition("Legal Review")
    supp   = Transition("Request Supplement")
    dc2    = Transition("Document Check")     # re-entry after supplement
    as2    = Transition("Assessment")         # re-assessment after supplement
    skip   = SilentTransition()               # cases that need no legal review
    appr   = Transition("Approve")
    rej = Transition("Reject")
    notify = Transition("Notify")

    # --- supplement loop body: Request Supplement -> Document Check -> Assessment
    redo = StrictPartialOrder(nodes=[supp, dc2, as2])
    redo.order[supp, dc2] = True
    redo.order[dc2,  as2] = True

    # --- optional legal review with the supplement loop
    legal_loop = OperatorPOWL(operator=Operator.LOOP, children=[legal, redo])
    post_assess = OperatorPOWL(operator=Operator.XOR, children=[legal_loop, skip])
    decision = OperatorPOWL(operator=Operator.XOR, children=[appr, rej])

    if with_originals:
        root = StrictPartialOrder(nodes=[reg, orig, ic, dc, assess, post_assess, decision, notify])
        root.order[reg, orig] = True # originals receipt starts after registration
        root.order[reg, ic]   = True
        root.order[orig, dc]  = True          # STATUTORY gate (rule 4)
    else:
        root = StrictPartialOrder(nodes=[reg, ic, dc, assess, post_assess, decision, notify])
        root.order[reg, ic] = True
        root.order[reg, dc] = True            # full parallelization allowed here

    # ---- THE core transport claim: Assessment waits for BOTH verifications ----
    root.order[ic,     assess] = True
    root.order[dc,     assess] = True
    root.order[assess, post_assess] = True
    root.order[post_assess, decision] = True
    root.order[decision, notify] = True
    # no root.order[ic, dc] and no root.order[dc, ic]  ->  genuine concurrency
    return root
```

Shared mechanisms: at both sites `Register` is the only genuine predecessor of the two verification activities, so removing a *false* serialization removes a span equal to `min(IC, DC)` on non-bottleneck paths and shrinks verification-stage WIP (Little's law). That core arrow `treatment_parallelization -> true_overlap -> verification_span -> cycle_time` is transportable.

Site-specific mechanisms: at B, `Document Check` is gated by `Originals Receipt` for 62% of cases, so the binding serialization is `IC/OR` and `OR/DC`, not `IC/DC`, and the residual waiting is exogenous (mail) rather than workforce scheduling. Site A's gain also rests on cross-trained reviewers, dual task ownership and unrestricted timestamps; Site B's `role_specialization` and `IT_case_lock` sever the same arrow from `treatment_parallelization` to `true_overlap`. Site A's FTE and API co-interventions act on `cycle_time` along paths with no Site B counterpart.

Effect modifiers: `originals_required`, `digital_documents`, `IT_case_lock`, `role_specialization`, `case_complexity`, `assessment_capacity`, `legal_capacity` (via `supplement_loop_rate`) sit on the path or moderate it; `identity_capacity`/`document_capacity` determine whether the saved span is real or merely relocated queue.

Identical control-flow diagrams describe only *possible* orderings. Behaviour also depends on data conditions (statutory prerequisites), resources (pool sizes, utilization), enabling technology (locks, timestamps) and discipline (WIP caps). Two sites can share one partial order yet differ in which edge is *binding*, so the transported effect is bounded by the weakest binding edge at B.

# 5. Quantitative transport scenarios

**Derivation notes (referenced as D1–D7 below).**

- **D1 — structural bound.** Serial `IC ; DC` (3.4 + 8.1 = 11.5 h) becomes `max(IC,DC)`, so the removed span is `min(IC,DC)` = 3.4 h at Site B medians; given the spread, the median of the case-level minimum is **2.4–3.4 h**. It materialises only if both resources are free.
- **D2 — Site A decomposition.** A's structural bound is `min(3.5, 7.2)` = 3.5 h, yet the median fell 9 h. Per-task service fell 0.4 h + 0.7 h (impossible from concurrency), FTE rose 11%, high-complexity share fell 8 pp, waiting fell 6 h. Defensible parallelism attribution at A = **0–3.5 h (central 2–3 h)**; 9 h is the transport ceiling only in the most optimistic reading.
- **D3 — eligibility from the DFG, not the diagram.** `OR -> DC` = 2,108 = 62.0% (exactly the statutory originals share): `DC` is *already* decoupled from `IC` there. `IC -> DC` = 1,160 = 34.1% is the population still serialised behind `IC`. Hence full-parallelism eligibility = **34–38%**. Cross-checks: `OR -> DC` + `IC -> DC` = 3,268  3,260 `DC -> Assessment`; `Assessment -> Legal` 1,360 = 40%.
- **D4 — pooled-median arithmetic.** A shift `d` in a stratum of weight `w` moves the pooled median by  `·d`, where `` is the stratum's density share at the median. A two-component mixture calibrated to B's 44 h/110 h (fast  30 h, slow  54 h medians) gives ``  0.35–0.5 at `w`  0.35; therefore `d` = 2.4–3.4 h in 38% of cases -> **1 to 2.5 h pooled**. Extending decoupling to the 62% stratum (identity absorbed into the 18 h wait) -> **3 to 5 h pooled**.
- **D5 — capacity arithmetic.** 3,400 cases/6 months  26 cases/day. Per-head task load: `IC` 26/4 = 6.5; `DC` 26×1.11/7 = 4.1; `Assessment` 26×1.11/3 = **9.6** (incl. 10.6% supplement re-entries); `Legal` 26×0.4/2 = 5.2. Assessment carries 2.3× the per-head load of document review: it is the bottleneck. Parallelisation does not change arrival rate at assessment in steady state -> the 20 h pre-assessment queue is where the gain is destroyed first.
- **D6 — tail asymmetry.** p90/median = 2.50 (B) vs 2.34 (A). The tail is generated by originals-delay variance, the 2-FTE legal pool and the supplement loop — none touched by re-sequencing. Queueing is convex, so congestion moves p90 up much faster than it moves the median.
- **D7 — Little's law cross-check.**  = 3,400/4,368 h = 0.78 cases/h; verification span  0.38×11.5 + 0.62×29.5 = 22.7 h; verification WIP  17.6 cases. Removing 3.4 h in 35% of cases removes  0.9 case (1.2 h cycle time); removing it in all cases removes  2.7 cases (3.5 h). Consistent with D1/D4.

# 6. Candidate Site B intervention

**Name:** *Prerequisite-gated concurrency (PGC)* — versioned as **V1** (parallel-only) and **V2** (V1 + daily stand-up).

**Eligibility rules**
- **Track 1 — full parallelism (target 30–38%):** (a) originals not legally required; (b) complete document set received digitally at `Register`; (c) not a supplement re-entry; (d) identity evidence valid for 30 days.
- **Track 2 — prerequisite-gated decoupling (all remaining cases):** `Identity Check` created and executed at `Register` and run *concurrently with* `Originals Receipt`; `Document Check` created only on `Originals Receipt` completion and then run concurrently with `Identity Check`.
- **Track 3 — observational only (first 8 weeks):** active supplement re-entries and open legal escalations.

**Concurrency permissions**
- `IC  Originals Receipt` — always (no statutory barrier).
- `IC  Document Check` — Track 1 from `Register`; Track 2 from `Originals Receipt` completion.
- `Originals Receipt  Document Check` — **forbidden** (rule 4).
- `Assessment` — starts only when both `IC` and `DC` are complete (unchanged).
- `Legal Review` — only after `Assessment`, for public-sector/high-value cases (unchanged).

**Statutory prerequisites that remain mandatory:** `Register` first; originals receipt before `Document Check` where legally required; `Assessment` after both verifications; `Legal Review` after `Assessment` for public/high-value; `Approve`/`Reject` then `Notify`. No change to decision rights or legal ordering.

**Queue and WIP controls:** per-role WIP cap — 3 open tasks (identity), 3 (document), 2 (assessment, reserving slack for re-entries), 2 (legal); verification-stage WIP cap  30 cases (1.2 days of arrivals at 26/day); pull-based release (a task is opened only when its prerequisites are satisfied *and* the owning role has a free slot); release throttle 60% of assessment starts from the parallel track until the pre-assessment queue is 18 h for five consecutive days; daily 15-minute cross-role stand-up (V2 only).

**Resource responsibilities:** role separation retained (cross-training is deliberately *not* transferred — it is a second treatment). A rotating **case coordinator** (0.2 FTE) holds the case record and owns no verification task, defeating the single-owner lock without blurring duties.

**Legal-review and supplement loops:** `Request Supplement` re-opens `Document Check` (rule 7) and re-enters `Assessment`; `Identity Check` is re-opened only if the supplement changes identity evidence or >30 days elapsed since identity completion (`identity_rerun_reason` logged). Loop re-entries enter the assessment queue as priority P2, capped at 20% of daily assessment starts; a second supplement escalates to a joint assessor/legal slot.

**Logging requirements:** system-clock `start_actual_at` / `start_recorded_at` and end events for every task; concurrency-group id; prerequisite timestamps (`registration_at`, `originals_received_at`, `identity_complete_at`, `document_complete_at`); eligibility track **plus counterfactual eligibility flags for ineligible cases**; lock events and workaround usage; WIP-cap violations; back-entry flag and back-entry delay. Weekly data-quality reconciliation with a published back-entry KPI.

**Compact POWL-style / partial-order specification**

```text
SiteB := XOR( Track1 , Track2 )            # chosen by a *data* condition (statute)

Track1 := PO{
  nodes : R, I, D, A, Q, Z, N
  order : R<I , R<D , I<A , D<A , A<Q , Q<Z , Z<N
  free  : (I || D)                          # THE intervention: no I<D edge
  where Q := XOR( LOOP( L , Redo ) , tau )  # optional legal review + supplement loop
        Redo := PO{ S, D2, A2 | S<D2 , D2<A2 }
        Z := XOR( o , x )
}

Track2 := PO{
  nodes : R, OR, I, D, A, Q, Z, N
  order : R<OR , R<I , OR<D , I<A , D<A , A<Q , Q<Z , Z<N
  free  : (I || OR) , (I || D)              # identity absorbs the mail delay
  where Q, Redo, Z as above
}
# PRESERVED:  D waits for OR; A waits for BOTH I and D; L only after A;
#             o|x only after A (or after L); N last.
```

Relation sets (primitive events, Track 2): ` = {R<OR, R<I, OR<D, I<A, D<A, A<Q, Q<Z, Z<N}` with `Q` optional and `Redo = {S<D2, D2<A2, A2<L}` under `LOOP(L, Redo)`; concurrency set ` = {(I,OR), (I,D)}`. Track 1 is the same minus `OR` and the edge `OR<D`, giving ` = {(I,D)}`.

The design separates three failure modes. **Implementation failure**: if true overlap (system-clock events, not back-entered intervals) does not rise from ~6% to 50% in the treated arm while eligibility and logging checks pass, the intervention was never delivered — the lock, role boundaries or back-entry defeated it. **Mechanism failure**: if overlap rises but the verification span `Register  Assessment-ready` does not shrink by 2–3 h, the saved span was reabsorbed by queueing at the identity or assessment pools; the per-stage service/wait decomposition names the pool. **Transport failure**: if the treated stratum's effect differs from Site A's reweighted prediction by more than the pre-registered 3 h, the discrepancy is decomposed into case-mix (post-stratification), statutory gating (originals stratum) and IT gating (lock events).

The control arm supplies the concurrent counterfactual Site A lacked, and the non-eligible stratum supplies a negative control: if its cycle time also improves, the change is not parallelisation. Fidelity metrics (duplicate touches, back-entry share, WIP-cap violations) are reported beside effects, so a null result can be *classified* rather than merely recorded.

# 8. PM4Py model-construction code

```python
# =============================================================================
# Site A / Site B process-model construction with PM4Py (>= 2.3.x, POWL support)
# Self-contained: needs only `pm4py`. No event log required.
# =============================================================================
import warnings
import pm4py
from pm4py.objects.powl.obj import (Transition, SilentTransition,
                                    StrictPartialOrder, OperatorPOWL)
from pm4py.objects.powl.constants import Operator

# ---------------------------------------------------------------------------
# 1) Site A BEFORE / AFTER process trees, parsed from the specification text
# ---------------------------------------------------------------------------
SITE_A_BEFORE = ("-> ( 'Register', 'Identity Check', 'Document Check', "
                 "'Assessment', X ( 'Approve', 'Reject' ), 'Notify' )")
SITE_A_AFTER  = ("-> ( 'Register', + ( 'Identity Check', 'Document Check' ), "
                 "'Assessment', X ( 'Approve', 'Reject' ), 'Notify' )")

def parse_tree(spec: str):
    """Parse a process tree; retry with collapsed whitespace if needed."""
    try:
        return pm4py.parse_process_tree(spec)
    except Exception as exc:                       # grammar whitespace tolerance
        warnings.warn(f"parse retry ({exc})")
        tight = spec.replace("( ", "(").replace(" )", ")")
        return pm4py.parse_process_tree(tight)

tree_before = parse_tree(SITE_A_BEFORE)            # -> ( IC ; DC )  serial
tree_after  = parse_tree(SITE_A_AFTER)             # -> ( IC + DC )  parallel
print("Site A before :", tree_before)
print("Site A after  :", tree_after)

# ---------------------------------------------------------------------------
# 2) Convert both trees to accepting Petri nets
# ---------------------------------------------------------------------------
net_before, im_before, fm_before = pm4py.convert_to_petri_net(tree_before)
net_after,  im_after,  fm_after  = pm4py.convert_to_petri_net(tree_after)

# ---------------------------------------------------------------------------
# 3) Site B candidate model in POWL
#    Two eligibility tracks are built, because POWL cannot express the DATA
#    condition "originals are legally required" -> represented as a free XOR.
# ---------------------------------------------------------------------------
def build_track(with_originals: bool):
    """
    Track 1 (no originals):   IC || DC  after Register          (~38% of B)
    Track 2 (originals req.): OR before DC;  IC || OR and IC || DC  (~62% of B)
    Both tracks:  Assessment AFTER identity AND document verification;
                  optional Legal Review with a Request-Supplement loop that
                  re-enters Document Check and Assessment;
                  XOR(Approve, Reject) then Notify.
    """
    reg    = Transition("Register")
    orig   = Transition("Originals Receipt")
    ic     = Transition("Identity Check")
    dc     = Transition("Document Check")
    assess = Transition("Assessment")
    legal  = Transition("Legal Review")
    supp   = Transition("Request Supplement")
    dc_red = Transition("Document Check")      # re-entry after a supplement
    as_red = Transition("Assessment")          # re-assessment after a supplement
    skip   = SilentTransition()                # cases that need no legal review
    appr   = Transition("Approve")
    rej    = Transition("Reject")
    notify = Transition("Notify")

    # --- supplement loop redo body: Request Supplement -> Document -> Assessment
    redo = StrictPartialOrder(nodes=[supp, dc_red, as_red])
    redo.order[supp,  dc_red] = True
    redo.order[dc_red, as_red] = True

    # --- optional legal-review branch carrying the supplement loop
    legal_loop  = OperatorPOWL(operator=Operator.LOOP, children=[legal, redo])
    post_assess = OperatorPOWL(operator=Operator.XOR, children=[legal_loop, skip])
    decision    = OperatorPOWL(operator=Operator.XOR, children=[appr, rej])

    if with_originals:
        root = StrictPartialOrder(nodes=[reg, orig, ic, dc,
                                         assess, post_assess, decision, notify])
        root.order[reg,  orig] = True          # Originals Receipt after Register
        root.order[reg,  ic]   = True          # Identity after Register (rule 2)
        root.order[orig, dc]   = True          # STATUTORY GATE (rule 4)
    else:
        root = StrictPartialOrder(nodes=[reg, ic, dc,
                                         assess, post_assess, decision, notify])
        root.order[reg, ic] = True
        root.order[reg, dc] = True             # full parallelisation allowed here

    # -------- THE transport claim: explicit PO edges into Assessment ----------
    root.order[ic,         assess]      = True   # Assessment waits for identity
    root.order[dc,         assess]      = True   # Assessment waits for documents
    root.order[assess,     post_assess] = True
    root.order[post_assess, decision]   = True
    root.order[decision,   notify]      = True
    # NO root.order[ic, dc] and NO root.order[dc, ic]  ->  genuine concurrency

    meta = dict(reg=reg, orig=orig, ic=ic, dc=dc, assess=assess,
                legal=legal, supp=supp, dc_red=dc_red, as_red=as_red,
                skip=skip, appr=appr, rej=rej, notify=notify,
                legal_loop=legal_loop, post_assess=post_assess,
                decision=decision, redo=redo)
    return root, meta
```

# 9. Recommendation

`conditional go`

Transfer the mechanism, not the artefact. The transferable element is the removal of a *false* serialization: once a task's own statutory prerequisite is satisfied it may proceed without waiting for the other verification to finish. What must not be copied is Site A's literal recipe — creating both verification tasks at `Register` for every case — because Rule 4 makes `Document Check` unstartable in the 62% of cases requiring originals; copying it would breach the statute or, worse, generate blocked tasks and back-entered timestamps, destroying the very measurement the pilot needs. Nor should Site A's cross-trained reviewers or its six-task WIP rule be copied: both were bundled with a capacity addition and a mix change and would confound the trial.

Enter first with the subgroup where the structure permits and variance is lowest: the 30–38% of cases with no originals requirement and a complete digital document set at registration. There the expected median gain is 2–3.5 h and the p90 gain 4–10 h. Second wave: the 62% originals stratum, where the intervention is different in kind — decouple `Identity Check` from the case lock so identity work absorbs part of the 18 h external delay; do not parallelize `Document Check` there.

Expected benefit: pooled median 3 to 5 h and verification WIP 10 to 15%, with decision quality unchanged if the guardrails hold. Expected risks: the gain is reabsorbed by the three-assessor bottleneck (p90 +8 to +22 h), identity staleness in supplement loops (rework 17%  20%+), and lock-driven back-entry producing a placebo improvement.

Expand if, after 250 eligible cases per arm, true overlap exceeds 50% measured on system-clock events, the treated stratum's median is at least 2 h below control, and rework stays 18%. Modify if overlap rises but the verification span does not shrink — that is a bottleneck shift: add assessment capacity or throttle release. Abandon if the treated stratum shows no span reduction despite fidelity 80%, or if rework exceeds 22% or appeals exceed 6%: either would show that the mechanism does not survive role specialization and statutory gating.

# 10. Assumption register

1. **"Service hours" (IC 3.4 h, DC 8.1 h) are elapsed task spans, not touch labour** — why needed: `min(IC,DC)` and the Little's-law WIP arithmetic (D1, D7) depend on it — how to test: sample 100 tasks per role with active-work timers; compare touch time to span — consequence if false: the span saving bound is smaller and queueing inside tasks absorbs it; all scenario ranges shift toward S3.
2. **The ~38% with no originals requirement are also the ~34% showing `IC -> Document Check`** — why needed: D3's eligibility share and the whole Track 1 targeting — how to test: cross-tab case attribute `originals_required` against observed `DC` predecessor activity on all 3,400 cases — consequence if false: eligibility could be far smaller or larger, and Track 1 may include cases that legally cannot start.
3. **Identity and document work use mostly independent data at Site B as at Site A** — why needed: the saving `min(IC,DC)` presumes the two tasks can genuinely progress in parallel — how to test: interview reviewers and measure the correlation of IC/DC durations and of data sources on 100 cases — consequence if false: positive dependence shrinks the saving toward zero and rework rises (S5 becomes likely).
4. **Identity evidence stays valid across a supplement loop (30 days)** — why needed: avoids forced identity re-verification and the rework increase — how to test: check registry/ID-evidence expiry rules and measure elapsed time `identity_complete -> final decision` for the 360 supplement cases — consequence if false: `true_overlap -> rework` is strongly positive; cap Track 1 for legal-flagged cases immediately.
5. **A second task slot (or coordinator role) can defeat the case lock without corrupting logs** — why needed: `IT_case_lock -> true_overlap` is the decisive transport edge — how to test: 2-week technical spike measuring true concurrent task ownership and back-entry rate under the workaround — consequence if false: S4 (placebo) is realised and the pilot measures reporting, not process.
6. **Assessment, not verification, is the binding bottleneck at Site B** — why needed: D5 and the S3/S6 distinction — how to test: derive per-role touch times and utilisation; compare queue lengths before each role for 4 weeks — consequence if false: if identity or document review binds, parallelisation raises throughput instead of lowering cycle time, and the effect estimate must be re-specified as a throughput effect.
7. **Directly-follows counts under concurrency are not misread as ordering** — why needed: D3 reads `OR -> DC` 62% and `IC -> DC` 34% as entry conditions — how to test: run a concurrency-aware miner (heuristics/PO discovery) and compare "directly follows" with "eventually follows" ratios on Site B's log — consequence if false: the 34% eligibility estimate is an artefact of interleaving and Track 1 targeting is wrong.
8. **Site B's baseline period is stable (no concurrent mix, capacity or IT change during the pilot)** — why needed: Site A's 9 h is uninterpretable precisely because of four co-changes; the same must not happen at B — how to test: monitor weekly arrival mix (complexity, digital share, legal flag), FTE, and external latency as control charts; freeze known IT/marking changes for the pilot window — consequence if false: the pilot replicates Site A's identification failure and no transport conclusion is possible.
