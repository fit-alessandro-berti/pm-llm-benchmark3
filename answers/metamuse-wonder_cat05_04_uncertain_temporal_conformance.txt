## 1. Normalization Assumptions

**Interval construction.** A point timestamp is never treated as the true
event time. For each event I construct, in order:

1. a *recorded-clock interval* from the display/rounding semantics
   (e.g. floor-to-minute `10:14` $\to$ clock time in
   $[10{:}14{:}00,\;10{:}14{:}59.999]$; round-to-nearest-$k$ $\to$
   $\pm k/2$; HUB "exact to second, $\pm0.5$ s measurement" $\to$ $\pm0.5$ s);
2. conversion of that interval from the source time zone to UTC using the
   stated zone rule (CEST = UTC+2, EDT = UTC$-$4, BST = UTC+1, etc.);
3. clock correction: with $\text{clock\_offset}=\text{recorded}-\text{true}
   \in[a,b]$, true time $=$ recorded $-\,$offset, i.e. the UTC interval is
   shifted by $[-b,-a]$. The offset is subtracted, never added.

Endpoints are quoted to the precision that matters; `.999` endings from
floor-to-minute are shown as the next second where harmless in duration
arithmetic, and no conclusion below turns on sub-second endpoint choices
except where explicitly flagged (T-402/T-404/T-408 borderline seconds).

**Midpoints** are used only inside the PM4Py comparison in §5 and are
labelled a lossy approximation there. No classification in §3 is based on
a midpoint.

**DST folds (T-405).** On 2025-10-26, Europe/Berlin local 02:00–02:59 occurs
twice: fold 1 = CEST (UTC+2), fold 2 = CET (UTC+1). With no fold logged,
each event's feasible set is the *disjoint union* of the two fold
intervals. I do not collapse this union into one wide interval. The
ingestion order (Alert $<$ Investigation $<$ Containment in true time) is
then used to prune fold combinations; it prunes combinations, it does not
shrink the surviving intervals.

**Inferred start (T-404).** Investigation_Start is inferred as
Investigation_Complete $-$ duration, duration $\in[18,25]$ min from the
signed work record. All uncertainty is retained: the inferred interval is
the complete-event interval widened by the full 7-minute duration range.
This inference is defensible for screening; it is weaker evidence than a
logged start.

**Missing receipt (T-407).** `Alert_Sent` is *not* `Alert_Received`.
Delivery latency $\in[0,20]$ min gives a candidate Received interval, but
there is no acknowledgment. The causal assumption "receipt $\le$
investigation start" is plausible but unlogged. I therefore report S1 and
the Alert-pairs for T-407 as INDETERMINATE primarily, with a clearly
labelled *conditional* POSSIBLE reading if both the latency bound and the
causal assumption are accepted.

**Mobile entry delay (T-406).** Substantive assumption, stated explicitly:
the user entered the displayed time *late*, i.e. the entry (record) time is
the displayed time and the *occurrence* preceded entry by a delay in
$[0,5]$ min. Under this "late recording" reading the delay shifts the
estimated occurrence interval *earlier* (subtract $[0,300]$ s after clock
correction) — it is not symmetric noise. If instead the displayed time
purported to state the occurrence time, the delay would be evidence about
reliability of that statement, not a shift; I flag where the two readings
differ. The primary analysis uses the late-recording reading.

**Weak offset evidence (T-409).** The normal OPS-BER bound $[-90,+120]$ s
does not apply (diagnostics missing). The $[-12,+12]$ min figure is a weak
engineering estimate. I compute intervals *conditionally* on it but
classify primarily as INDETERMINATE for enforcement, because the bound
itself is not trustworthy evidence — this is a judgement about evidence
strength, not about arithmetic.

**SLA vs. profile.** The SLA is a one-sided maximum (duration $\le$ limit
passes). The temporal profile is a two-sided statistical band
(avg $\pm\zeta\cdot$sd); an interval wholly above *or below* the band is a
certain violation of the profile, which is *not* an SLA breach. The two
regimes are classified independently throughout.

**Classification semantics.** CERTAIN_PASS: every feasible duration
satisfies the rule. CERTAIN_VIOLATION: every feasible duration violates
it. POSSIBLE_VIOLATION: the feasible set contains both. INDETERMINATE:
evidence too weak/unbounded/inconsistent, or the pair is not testable
under the stated semantics.

## 5. PM4Py Temporal-Conformance Code

```python
"""
Interval-first temporal conformance screening.

- Interval normalization uses pandas + stdlib zoneinfo only.
- DST ambiguity is represented as alternative (disjoint) intervals.
- A SEPARATE midpoint-only log is built for PM4Py. It is a LOSSY
  APPROXIMATION: PM4Py has no native notion of timestamp uncertainty,
  clock offset, rounding, or DST-fold unions. Midpoint results are
  diagnostics to compare against the interval conclusions, never a
  replacement for them.
"""
import pandas as pd
from zoneinfo import ZoneInfo
from datetime import datetime, timedelta, timezone

UTC = timezone.utc

def iv(lo, hi):
    return (pd.Timestamp(lo), pd.Timestamp(hi))

# --- Source metadata ---
# offset [a,b] means true = recorded_clock - offset  =>  shift by [-b, -a]
SOURCES = {
    "HUB":        dict(tz="UTC",           kind="exact_s",  half=0.5,  offset=(-1, 1)),
    "OPS-BER":    dict(tz="Europe/Berlin", kind="floor_min", half=None, offset=(-90, 120)),
    "SENSOR":     dict(tz="UTC",           kind="round_10s", half=5.0,  offset=(-5, 5)),
    "VENDOR-NY":  dict(tz="America/New_York", kind="floor_min", half=None, offset=(-180, 180)),
    "LEGACY-BER": dict(tz="Europe/Berlin", kind="floor_min", half=None, offset=(-60, 60), dst_fold=True),
    "MOBILE-LON": dict(tz="Europe/London", kind="round_min", half=30.0, offset=(-300, 300)),
}

def recorded_clock_interval(rec, src):
    """Interval of readings on the source's own clock (before tz/offset)."""
    if src["kind"] == "floor_min":
        lo = rec.replace(second=0, microsecond=0)
        hi = lo + timedelta(minutes=1) - timedelta(microseconds=1)
    elif src["kind"] in ("exact_s", "round_10s", "round_min"):
        h = timedelta(seconds=src["half"])
        lo, hi = rec - h, rec + h
    else:
        raise ValueError(src["kind"])
    return lo, hi

def normalize(case, activity, recorded, source, extra_lo_s=0.0, extra_hi_s=0.0):
    """
    Returns a list of feasible UTC intervals (a union; >1 only for DST folds).
    extra_lo_s/extra_hi_s shift the true-time interval afterwards
    (e.g. T-406 entry delay: occurrence = record - delay, delay in [0,300]
     => extra_lo_s=-300, extra_hi_s=0).
    """
    src = SOURCES[source]
    tz = ZoneInfo(src["tz"])
    naive = datetime.fromisoformat(recorded)          # local wall time as displayed
    lo_c, hi_c = recorded_clock_interval(naive, src)

    if src.get("dst_fold"):
        # Ambiguous local time: build one interval per fold (0=first/CEST, 1=second/CET)
        out = []
        for fold in (0, 1):
            lo_utc = lo_c.replace(tzinfo=tz, fold=fold).astimezone(UTC)
            hi_utc = hi_c.replace(tzinfo=tz, fold=fold).astimezone(UTC)
            out.append(_offset_correct(lo_utc, hi_utc, src, extra_lo_s, extra_hi_s))
        return out
    lo_utc = lo_c.replace(tzinfo=tz).astimezone(UTC)
    hi_utc = hi_c.replace(tzinfo=tz).astimezone(UTC)
    return [_offset_correct(lo_utc, hi_utc, src, extra_lo_s, extra_hi_s)]

def _offset_correct(lo_utc, hi_utc, src, extra_lo_s, extra_hi_s):
    a, b = src["offset"]                                # true = clock - offset
    lo = pd.Timestamp(lo_utc) + pd.Timedelta(seconds=-b + extra_lo_s)
    hi = pd.Timestamp(hi_utc) + pd.Timedelta(seconds=-a + extra_hi_s)
    return (lo, hi)

def feasible_unions(case, acts):
    """Enumerate combinations of per-event intervals; keep order-consistent ones."""
    import itertools
    pools = [intervals[(case, a)] for a in acts]
    good = []
    for combo in itertools.product(*pools):
        # order-consistent iff we can pick points increasingly; sufficient
        # check for intervals: each hi > previous lo and each lo < next hi,
        # strengthened here by requiring combo[i].hi > combo[i-1].lo and,
        # for this dataset, the surviving combo is unique and separated.
        if all(combo[i][0] < combo[i-1][1] or True for i in range(1, len(combo))):
            # strict feasibility of an increasing selection:
            t = combo[0][0]
            ok = True
            for lo, hi in combo:
                t = max(t, lo)
                if t > hi:
                    ok = False; break
            if ok:
                good.append(combo)
    return good

def classify_sla(durs, limit_s):
    if not durs: return "INDETERMINATE"
    if all(hi <= limit_s for _, hi in durs): return "CERTAIN_PASS"
    if all(lo > limit_s for lo, _ in durs): return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

def classify_profile(durs, avg, sd, zeta):
    lo_b, hi_b = avg - zeta * sd, avg + zeta * sd
    if not durs: return "INDETERMINATE"
    if all(lo >= lo_b and hi <= hi_b for lo, hi in durs): return "CERTAIN_PASS"
    if all(hi < lo_b or lo > hi_b for lo, hi in durs): return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"
```

## 7. Governance Recommendation

1. **UTC storage with raw retention.** Store every timestamp in UTC
   (ISO 8601 with offset) *and* retain the raw displayed value, source
   time zone, and fold/offset indicator (`+02:00` vs `+01:00`,
   `is_dst`). Never store a bare local wall time — T-405 was analysable
   only because ingestion order happened to survive.
2. **Clock-offset telemetry.** Each source should emit periodic,
   queryable offset estimates (NTP discipline logs) so that per-event
   bounds replace blanket bounds. Missing-diagnostics windows (T-409)
   should automatically downgrade affected events to "weak evidence" in
   conformance tooling rather than silently inheriting the normal bound.
3. **Resolution metadata.** Record display semantics (exact / floor /
   round-to-$k$) per source in a registry; floor-to-minute sources
   (OPS-BER, VENDOR-NY) should move to second resolution for
   SLA-relevant events — rounding alone contributed up to 60 s of the
   T-401/T-402 uncertainty.
4. **Start/complete lifecycle semantics.** Log start and completion as
   distinct events (T-404's inferred start, SENSOR's completion-only
   events). Inferred timestamps must be flagged as inferred, with the
   duration evidence attached, and must not be re-ingested as if logged.
5. **Causal identifiers.** Alerts, investigations and containments
   should carry shared IDs and, where receipt matters, delivery
   acknowledgments (T-407). "Sent" and "Received" are different
   activities and must never be merged in the event model.
6. **User-entered times.** Mobile/manual entries must capture device
   occurrence time separately from entry time, and state which the
   displayed value claims to be (T-406). Unlabelled manual times should
   default to weak-evidence status.
7. **Enforcement policy for interval overlap.** Adopt explicitly:
   CERTAIN_VIOLATION is enforceable; POSSIBLE_VIOLATION triggers
   investigation and evidence preservation, *not* sanction;
   INDETERMINATE triggers evidence collection duties on the operator of
   the weak source. Interval overlap with a limit must never be treated
   as proof of breach, and a midpoint pass must never be treated as
   proof of compliance. Tolerance (the +2/+5 min question in §4) is a
   legal/policy decision to be set in the SLA text itself — applied
   uniformly and prospectively — not an analyst-side adjustment.
