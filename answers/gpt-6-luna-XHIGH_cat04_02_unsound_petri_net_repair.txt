# 1. Executive Verdict

The net meets the structural workflow-net conditions: `source` and `sink` are the unique source and sink, and every node lies on a directed source-to-sink path. It should not be expected to be sound. The standard-review join waits for both analysis and review, but the waiver join waits only for the waiver token. Consequently, the waiver route can authorize before analysis, leaving the analysis token behind; if analysis later fires, its completion token cannot be consumed. A sink token can therefore coexist with leftover work, and a reachable non-final dead marking exists. This contradicts the business rule that analysis is mandatory and that completion leaves no tokens outside the final marking.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source`, `t_register`, `p_ready` | Start a registered case | One source token moves to `p_ready`; registration is a required first step | None by itself |
| `t_split` | Start analysis and review in parallel | Emits one token to `p_analysis` and one to `p_review` | Correct parallel fork; both branch tokens must eventually be handled |
| `t_analyze` | Mandatory analysis | Moves the analysis token from `p_analysis` to `p_analysis_done` | Analysis can occur before or after the review choice; the original waiver join does not wait for its result |
| `t_standard_review` | Select and complete standard review | Competes with `t_waive_review` for the single token in `p_review`, then puts one token in `p_review_done` | The two review outcomes are an XOR choice, not concurrent alternatives |
| `t_waive_review` | Record a waiver instead of a standard review | Consumes `p_review` and puts a token in `p_waived` | The visible choice is recorded, but it does not itself settle or consume the analysis branch |
| `join_normal` | Synchronize analysis and standard review | Requires both `p_analysis_done` and `p_review_done`, then emits one `p_decision` token | Correct synchronization for the standard-review route |
| `join_waived` | Synchronize the waiver route before authorization | Requires only `p_waived`, then emits `p_decision` | Defect: it bypasses analysis and can leave `p_analysis` or `p_analysis_done` behind |
| `t_authorize`, `sink` | Authorize and complete the case | Consumes `p_decision` and puts one token in `sink` | It can fire with an unfinished analysis branch after waiver |
| `im` and `fm` | Start with one case; finish with no other tokens | `im = {source: 1}` and `fm = {sink: 1}` | Reaching a marking containing `sink` is not sufficient; it must equal `fm` |

As a directed graph, every listed place and transition lies on at least one path from `source` to `sink`. In particular, the analysis branch reaches `sink` through `join_normal`, and the waiver branch reaches it through `join_waived`. Thus the graph passes the structural path condition even though a firing sequence can strand tokens. The review transitions are in conflict at `p_review`; whichever fires consumes that one token, so both outcomes cannot be selected in one case.

# 3. Marking-Based Counterexample

Write `{place: n}` for the nonzero token counts. One legal sequence takes the waiver route and authorizes before analysis:

`t_register`, `t_split`, `t_waive_review`, `t_join_waived`, `t_authorize`, `t_analyze`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---:|---|---|---|---|
| 0 | — | `{source: 1}` | `t_register` | This is `im`. |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | The case is registered. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token is created in each parallel branch. The review alternatives compete for `p_review`. |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `t_analyze`, `t_join_waived` | The waiver is recorded; analysis remains pending. |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, `t_authorize` | The waiver join creates a decision token without requiring analysis. |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `t_analyze` | Authorization has occurred before analysis. A token exists in `sink`, but this marking is not `fm`. |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | none | This is a reachable dead marking, not `fm`; `p_analysis_done` is stranded. |

At step 4, the model permits either `t_authorize` or `t_analyze` first. So authorization can also occur after analysis: from `{p_analysis: 1, p_decision: 1}`, fire `t_analyze` to reach `{p_analysis_done: 1, p_decision: 1}`, then `t_authorize` to reach `{p_analysis_done: 1, sink: 1}`. That still is not `fm`.

The leftover token cannot be consumed in either ordering. After `t_join_waived`, the waiver token is gone, so `t_join_waived` cannot fire again. The remaining analysis token can produce `p_analysis_done`, but `t_join_normal` also requires `p_review_done`, which the waiver route never produces. `t_authorize` consumes only `p_decision`, already consumed in the trace. Thus a sink token is not exact final completion, and the extra token cannot be removed.

# 4. Minimal-Repair Alternatives

For edit cost, count each added or removed ordinary arc, place, or transition as 1; labels and markings are not edits. “Minimal” is relative to the stated repair constraint: Repair 1 is globally minimum for retaining the existing business policy and nodes; Repair 2 is minimal among repairs that preserve the waiver subnet and make the existing `join_normal` the shared synchronization point; Repair 3 is minimal for the explicitly changed policy and existing parallel fork.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| 1. Give the waiver join its required analysis input | Add arc `p_analysis_done -> join_waived` | 1 | Keeps analysis mandatory for both standard review and waiver. The waiver and standard-review outcomes remain distinct. | `join_waived` now waits for both `p_waived` and `p_analysis_done`. | Two silent joins feed `p_decision`; the topology has two synchronization points to maintain. |
| 2. Route waiver through the existing normal join | Remove arc `join_waived -> p_decision`; add arc `join_waived -> p_review_done` | 2 | Keeps analysis mandatory and keeps standard review or recorded waiver as the review outcome. | The waiver token is forwarded to `p_review_done`; `join_normal` is the only place that synchronizes review outcome with analysis. | `join_waived` becomes a forwarding silent transition; maintainers must understand that `p_review_done` represents either review outcome. |
| 3. Make analysis optional only when review is waived | Add silent transition `t_waive_skip_analysis`; add arcs `p_waived -> t_waive_skip_analysis`, `p_analysis -> t_waive_skip_analysis`, and `t_waive_skip_analysis -> p_decision`; add arc `p_analysis_done -> join_waived` | 5 | Preserves mandatory analysis on the standard-review route and the registered-case fork. | Changes policy: after a waiver, analysis may be skipped if it has not started; if analysis has completed, the waiver join waits for that completion. | Adds a silent choice that must be explained and tested; traces for waived cases no longer guarantee analysis. |

Repair 1 is a one-arc global minimum under this cost model: zero edits leave the demonstrated counterexample unchanged. The added input is necessary and sufficient because it makes the existing waiver join wait for analysis completion while keeping its waiver input. No place or transition becomes unreachable, and all arcs still connect the same workflow branches.

Repair 2 is minimal under its stated shared-join constraint. To make the existing waiver path enter the existing `join_normal`, the old output arc to `p_decision` must be removed (otherwise waiver still authorizes early), and an output arc to `p_review_done` must be added. Those two arc edits suffice; no new or removed nodes are needed. It is a distinct topology from Repair 1, although both preserve the same visible business behavior.

Repair 3 makes the policy change explicit. Its new transition can consume `p_analysis` only together with `p_waived`, so skipping is available only after the waiver choice and only while analysis is pending. The added `p_analysis_done` input ensures that if analysis fires first, the ordinary waiver join consumes its completion. Under the stated parallel-fork structure, both routes are needed to dispose of the analysis token correctly; the new skip route costs one transition and three arcs, and the completed-analysis route costs one added arc. Repair 3 is therefore minimal for this specific skip-on-waiver policy and structure, but it is not a repair that preserves the original mandatory-analysis rule.

# 5. Corrected PM4Py Code

This selects Repair 1, adding the missing analysis-completion input to the waiver join.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for place in {
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
}:
    repaired_net.places.add(place)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for transition in {
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
}:
    repaired_net.transitions.add(transition)

petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)
petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

The following assumes the original `net`, `im`, and `fm` have been built and the repaired variables from the preceding code exist. The firing helper uses PM4Py's enabled-transition result and raises an error if the named transition is missing or disabled.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def inspect_net(label, candidate_net, initial_marking, final_marking):
    print(f"--- {label} ---")
    workflow_net = pm4py.check_is_workflow_net(candidate_net)
    print("workflow net:", workflow_net)

    soundness = pm4py.check_soundness(
        candidate_net, initial_marking, final_marking, print_diagnostics=True
    )
    print("soundness result:", soundness)

    initially_enabled = pm4py.get_enabled_transitions(
        candidate_net, initial_marking
    )
    print("initially enabled:", sorted(t.name for t in initially_enabled))

    reachability_graph = pm4py.convert_to_reachability_graph(
        candidate_net, initial_marking, final_marking
    )
    print("reachability graph constructed:", reachability_graph is not None)
    return workflow_net, soundness, reachability_graph


original_results = inspect_net("original", net, im, fm)
repaired_results = inspect_net(
    "repaired", repaired_net, repaired_im, repaired_fm
)


def marking_text(marking):
    entries = [
        f"{place.name}: {marking[place]}"
        for place in sorted(marking, key=lambda p: p.name)
        if marking[place] != 0
    ]
    return "{" + ", ".join(entries) + "}"


def fire_named(candidate_net, marking, transition_name):
    matches = [t for t in candidate_net.transitions if t.name == transition_name]
    if len(matches) != 1:
        raise ValueError(
            f"Expected one transition named {transition_name!r}; found {len(matches)}"
        )

    transition = matches[0]
    enabled = pm4py.get_enabled_transitions(candidate_net, marking)
    if transition not in enabled:
        raise RuntimeError(
            f"Transition {transition_name!r} is not enabled at {marking_text(marking)}"
        )

    next_marking = Marking(marking)
    for arc in transition.in_arcs:
        place = arc.source
        next_marking[place] = next_marking.get(place, 0) - arc.weight
        if next_marking[place] == 0:
            del next_marking[place]
    for arc in transition.out_arcs:
        place = arc.target
        next_marking[place] = next_marking.get(place, 0) + arc.weight
    return next_marking


def print_firing_sequence(candidate_net, initial_marking, transition_names):
    marking = Marking(initial_marking)
    print("start:", marking_text(marking))
    for name in transition_names:
        marking = fire_named(candidate_net, marking, name)
        enabled_names = sorted(
            t.name for t in pm4py.get_enabled_transitions(candidate_net, marking)
        )
        print(f"after {name}: {marking_text(marking)}; enabled={enabled_names}")
    return marking


counterexample_marking = print_firing_sequence(
    net,
    im,
    [
        "t_register",
        "t_split",
        "t_waive_review",
        "t_join_waived",
        "t_authorize",
        "t_analyze",
    ],
)
print("exactly fm:", counterexample_marking == fm)
```

Qualitatively, both nets should pass the structural workflow-net check. The original should fail soundness: the counterexample reaches a non-final dead marking with a sink token and a leftover analysis token. Repair 1 should pass soundness for the stated initial and final markings because either review outcome must now synchronize with completed analysis before authorization. The reachability-graph calls provide a way to inspect the reachable behavior; no particular state-space size is assumed here. Soundness output details depend on the PM4Py version and should be read from the actual diagnostics, not inferred from fabricated diagnostic keys.

# 7. Repair Trade-Offs and Residual Risks

- The selected repair preserves the distinction between `Perform Standard Review` and `Record Review Waiver`: these are still separate visible transitions, and they lead to different joins. If event logs omit or normalize those labels, the recorded traces may not reveal which outcome occurred.
- Repair 1 retains two silent joins feeding `p_decision`. This is valid, but model readers need to see that one join requires `p_review_done` and the other requires `p_waived`; otherwise the structure can look like duplicate ways to proceed. Repair 2 has one shared synchronization but uses `join_waived` as a silent forwarding step.
- Soundness establishes properties of the modeled net and markings; it does not prove that the net faithfully expresses the business rule. A sound model can still encode an unintended policy.
- Regression-test successful standard-review traces with analysis both before and after the review, and successful waiver traces with analysis both before and after waiver recording. In every successful trace, require the exact final marking `{sink: 1}`. Test that waiver without completed analysis cannot enable `t_authorize`, and test that a standard-review case cannot complete without analysis. For a negative trace, after selecting waiver but before analysis, verify the waiver join and authorization are disabled in Repair 1.
- To detect an accidental bypass, check every path to `t_authorize` in the model and verify it is causally guarded by `p_analysis_done`; also assert from reachable markings that authorization is never enabled on a waiver path while analysis remains in `p_analysis`. A trace-level invariant can require `t_analyze` to occur before `t_authorize` for every completed case.

# 8. Final Recommendation

Deploy Repair 1. It preserves the stated policy, makes the smallest possible change under the declared edit cost, and directly fixes the missing synchronization condition: waiver plus analysis completion are both required before authorization.

Keep Repair 2 as the fallback if maintainers prefer one shared join for both review outcomes. It preserves the same visible business behavior and mandatory-analysis rule, while adding one more arc edit and routing the waiver token through `p_review_done`. Repair 3 should be considered only if the business explicitly changes the rule so analysis may be skipped after a waiver. That policy change must be approved and reflected in process documentation and tests.
