## 1. Target definition

**Primary Target:** Probability of Default within 90 days post-activation, **conditional on the account being Activated**.
*   **Prediction Time:** Immediately following the completion of the "Credit Review" activity (final decision made, before Contract Signed).
*   **Horizon:** 90 days from `Account Activated` timestamp.
*   **Unit of Analysis:** Activated Credit Application Case.
*   **Population:** Applications that reached `Account Activated` status and have a matured outcome window (activation date + 90 days + 35 days feed delay < Data Extraction Date).
*   **Estimand:** $P(Default_{90d} = 1 \mid Activation = 1, Prefix Events)$.

**Alternative Target:** Multi-state Competing Risk Model.
*   **Definition:** Predict the absorbing state among {Default, Closed-NonDefault, Censored} for *all* applications starting from "Application Started".
*   **Why Different:** This answers "What is the ultimate outcome of this application?" rather than "Will this approved loan default?". It requires treating Rejection/Withdrawal as competing events rather than exclusions. It is statistically broader but operationally harder to act upon for *default* monitoring specifically, as drivers of rejection differ from drivers of default.

**Selection:** The Primary Target is selected because the business question specifically requests "default" prediction, and ground truth for default is physically unavailable for non-activated cases. Treating rejected cases as "non-default" induces severe selection bias (approving high-risk applicants who were previously rejected would not yield "non-defaults").

## 2. Cohort construction

**Inclusion Rules:**
1.  `case:concept:name` must have an `Account Activated` event.
2.  `Account Activated` date + 125 days (90 default + 35 feed) $\le$ 15 February 2026 (Data Extraction).
3.  Case start date $\ge$ 1 January 2024.

**Exclusion Rules:**
1.  Rejected, Withdrawn, Transferred, or Still-Open cases (not eligible for default target).
2.  Activated cases with immature outcome windows (right-censored, excluded from classification baseline).
3.  Cases with missing `default_90d` label after maturity.

## 3. Censoring and missing-label strategy

**Censoring Types:**
1.  **Ordinary Right Censoring:** 3,600 activated accounts where the 90-day window has not elapsed by extraction date.
2.  **Delayed Labels:** Even for matured accounts, the external feed arrives 7–35 days late. The `label_available_at` column must be respected to prevent look-ahead bias during temporal splits.
3.  **Selection through Activation:** The 26,800 non-activated cases (Rejected/Withdrawn/Open) represent a selected population. Their default risk is counterfactual.
4.  **Transfer as Missing Mechanism:** Transferred cases are effectively lost to follow-up. Since 40% lack linkage and partner feeds are unreliable, they are treated as missing not at random (MNAR).
5.  **Permanently Missing Feeds:** Partner-originated accounts may never report default.

**Analysis Strategy:**
*   **Primary:** Supervised classification on the 21,600 matured activated cases. This estimates $P(Default \mid Activated, Policy_{historical})$.
*   **Sensitivity:** Inverse Probability of Censoring Weighting (IPCW) to adjust for the 3,600 immature activated cases if extending the training window closer to the extraction date.
*   **Assumptions:**
    *   *Testable:* Distribution of features between early and late cohorts (Kolmogorov-Smirnov).
    *   *Partially Testable:* Stability of default rates across regions/channels.
    *   *Untestable:* Default rate of Rejected applications if they had been approved (Counterfactual).

## 4. Prefix extraction

**Prediction Point:** The timestamp of the last event where `concept:name` == "Credit Review" AND `decision_reason` is still missing (i.e., before the final Accept/Reject decision is recorded in the log). If "Credit Review" loops, use the completion of the *final* loop before decision.

**Extraction Rules:**
1.  **Fixed Event-Count:** Not used due to variable loop counts in Credit Review.
2.  **Elapsed-Time:** Not used primarily, as process speed varies by complexity.
3.  **Milestone-Based:** Extract all events $\le$ `prediction_timestamp`.
4.  **Handling Loops:** Aggregate counts of "Request Documents" events within the prefix.
5.  **Handling Renaming:** Apply a mapping dictionary to `concept:name` for events after 15 October 2025 to align with pre-migration activity names (e.g., "Credit Check v2" $\to$ "Credit Review").
6.  **Future Prevention:** Strict filter: `event.time:timestamp` $\le$ `case.prediction_timestamp`.

## 7. Validation design

**Temporal Split Strategy:**
*   **Train:** Cases started 1 Jan 2024 – 30 Jun 2025 (Pre-Policy Change).
*   **Validation:** Cases started 1 Jul 2025 – 14 Oct 2025 (Post-Policy, Pre-Migration).
*   **Test:** Cases started 15 Oct 2025 – 31 Dec 2025 (Post-Migration).

**Why Random Split Fails:**
Random splitting mixes policy regimes. A model trained on post-July data might learn the new stricter thresholds, failing to generalize to pre-July applications or vice versa. It also leaks future migration artifacts into training.

**Metrics:**
*   **Discrimination:** ROC-AUC, PR-AUC (due to class imbalance 2.7k vs 18.9k).
*   **Calibration:** Brier Score, Calibration Curve (reliability diagram).
*   **Stability:** PSI (Population Stability Index) on feature distributions between splits.

**Backtesting:**
Simulate deployment monthly. Train on data available at month $T$, predict month $T+1$. Ensure label maturity delay (35 days) is respected in the training set construction for each backtest step.

## 8. Limitations and decision-use boundary

**Claims:**
*   The model predicts default risk for applications that *would be approved under historical policy*.
*   It does not predict default for rejected applicants (counterfactual undefined).
*   It assumes the relationship between prefix events and default remains stable post-policy change.

**Decision-Use Boundary:**
*   **Do not use** to automatically approve rejected applications ("reverse scoring").
*   **Do not use** for cases started after Feb 2026 without re-calibration (data drift).
*   **Do not use** for transferred cases without validating partner feed quality.

**Deployment Risks (Data-Generating Process Changes):**
1.  **Goodhart's Law:** If officers know the model, they may manipulate `risk_score` inputs or document requests to game the prediction.
2.  **Policy Feedback:** If the model is used to tighten approval, the training population (activated accounts) becomes safer, potentially degrading model discrimination over time (selection bias shift).
3.  **Migration Artifacts:** New activity names may break feature engineering pipelines if mapping dictionaries are not maintained.

import pandas as pd
import pm4py
from datetime import timedelta

# 1. Load and Format Data
df = pd.read_csv('applications_events.csv', parse_dates=['time:timestamp', 'label_available_at', 'data_extract_time'])
# Ensure PM4Py compatible column names
log_df = pm4py.format_dataframe(df, case_id='case:concept:name', activity_key='concept:name', timestamp_key='time:timestamp')

# 2. Define Prediction Point (End of Credit Review, before Decision)
# Identify the last 'Credit Review' event before any 'Accept/Reject' decision for each case
def get_prediction_point(group):
    review_events = group[group['concept:name'] == 'Credit Review']
    # Simplified logic: assume last review before decision_reason is populated
    if not review_events.empty:
        return review_events.iloc[-1]['time:timestamp']
    return pd.NaT

log_df['prediction_timestamp'] = log_df.groupby('case:concept:name').apply(get_prediction_point).reset_index(level=0, drop=True)

# 3. Cohort Filtering (Activated & Matured)
# Identify activated cases
activated_cases = log_df[log_df['concept:name'] == 'Account Activated']['case:concept:name'].unique()
log_df = log_df[log_df['case:concept:name'].isin(activated_cases)]

# Label Maturity Check (90 days + 35 days feed delay)
extraction_date = pd.Timestamp('2026-02-15')
maturity_cutoff = extraction_date - timedelta(days=125)
# Get activation time per case
activation_times = log_df[log_df['concept:name'] == 'Account Activated'].groupby('case:concept:name')['time:timestamp'].max()
matured_cases = activation_times[activation_times <= maturity_cutoff].index
log_df = log_df[log_df['case:concept:name'].isin(matured_cases)]

# 4. Prefix Extraction (Events <= prediction_timestamp)
# Filter events to prevent leakage
prefix_df = log_df[log_df['time:timestamp'] <= log_df['prediction_timestamp']].copy()

# 5. Feature Engineering (Example: Activity Counts & Duration)
# Use PM4Py to get variants for control flow features
variants = pm4py.get_variants(prefix_df)
# Merge variant info back to case level (simplified)
case_features = prefix_df.groupby('case:concept:name').agg(
    event_count=('concept:name', 'count'),
    start_time=('time:timestamp', 'min'),
    pred_time=('prediction_timestamp', 'first') # Taken from original log_df alignment
).reset_index()
case_features['duration_hours'] = (case_features['pred_time'] - case_features['start_time']).dt.total_seconds() / 3600

# 6. Target Alignment
# Get label (must be from post-activation events, handled via merge)
labels = log_df[log_df['concept:name'] == 'Account Activated'][['case:concept:name', 'default_90d']].drop_duplicates()
model_df = case_features.merge(labels, on='case:concept:name', how='inner')

# 7. Temporal Split (Based on Case Start Time)
case_starts = log_df.groupby('case:concept:name')['time:timestamp'].min()
model_df['start_date'] = model_df['case:concept:name'].map(case_starts)

train = model_df[model_df['start_date'] < '2025-07-01']
val = model_df[(model_df['start_date'] >= '2025-07-01') & (model_df['start_date'] < '2025-10-15')]
test = model_df[model_df['start_date'] >= '2025-10-15']

# 8. Leakage Audit Check
# Ensure no future columns exist in model_df
forbidden_cols = ['final_limit', 'decision_reason', 'collection_status']
assert not any(col in model_df.columns for col in forbidden_cols), "Leakage detected!"

# 9. Output Cohort Counts
print(f"Train: {len(train)}, Val: {len(val)}, Test: {len(test)}")
print(f"Default Rate (Train): {train['default_90d'].mean():.2%}")
# Note: Survival modeling would connect here using durations and censoring indicators
