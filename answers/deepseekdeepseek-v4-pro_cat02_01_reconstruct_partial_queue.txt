# 1. Assumptions and notation

**Timestamps and rounding (A1)**  
All operational timestamps were rounded to the nearest 5min before extraction. Without further information we treat a reported time `t` as representing an actual moment in the interval `[t2.5min, t+2.5min]`. Numerical calculations are performed on the nominal clock time, but intervals reported later include explicit ±2.5min bands only where the rounding materially affects a bound.

**Eventorder convention (A2)**  
Because of the 5min rounding, distinct logical events may report the same timestamp. We adopt a conservative ordering: *service completion*  *arrival to next queue*  *service start*. This order avoids spurious resource conflicts and minimises overlap artifacts.

**Queue discipline and resource allocation (A3)**  
Cases at each station are served in a single firstcomefirstserved (FCFS) queue; when a resource becomes free it immediately takes the headofline case. Resources within a station are considered identical and interchangeable (workconserving).

**Capacity and availability (A4)**  
- S1 resources: I1, I2 (two singletask servers).  
- S2 resources: C1, C2 (two singletask servers).  
- C2 is unavailable from 10:55 through 11:10 (maintenance). No other resource unavailability is reported.

**Activity semantics and status (A5)**
- `MISSING` = the activity occurred, its resource and completion timestamp are known, but the start timestamp was not recorded. We bound the missing start with constraints (resource schedule, queue entry, nonnegative service).  
- `OPEN` = the activity had started but not finished by 14:00; end time is rightcensored.  
- Blank S1 start/end = the case had not started S1 by 14:00 (waiting/in queue).  
- Blank S2 start/end = the case had completed S1 but was waiting for S2 at 14:00.

**Observation window and censoring (A6)**  
The analysis covers 20260512 08:00–14:00. Cases that have not finished a station by 14:00 are rightcensored for that station (wait or inprogress service). Arrivals after 14:00 are not considered.

**Imputation and bounding philosophy (A7)**  
For each `MISSING` start we derive a **feasible interval** from:
- the moment the case entered the queue (S1 arrival time, or S1 completion for S2),
- the known completion time,
- the resource’s preceding and succeeding engagements,
- nonnegative service time.

Within those bounds we define three scenarios:
- **optimistic** for waiting time (earliest feasible start, corresponding to maximum service)  
- **pessimistic** for waiting time (latest feasible start, minimum service)  
- **central** (a plausible value consistent with the resource’s typical service time, taken as the midpoint of the typical servicetime distribution of the same resource on fully observed cases).

**No further assistance (A8)**  
No undocumented assistance (crosstraining, overtime, etc.) occurred; the recorded resource is the one that actually performed the work. Apparent conflicts are attributed to rounding.

# 2. Reconstruction method and formulas

### Caselevel quantities
For station \(j\) (\(j=1,2\)):

- **Arrival time to the station queue** \(A_j\):  
  \(A_1 = \text{arrival\_s1}\); \(A_2 = \text{s1\_end}\) (S1 completion).
- **Waiting time** \(W_j\):  
  If start is recorded: \(W_j = \text{start}_j - A_j\).  
  If start is MISSING: \(W_j\) is estimated by the interval between \(A_j\) and the imputed start, bounded as in §1.
- **Active service time** \(S_j\):  
  If end is recorded: \(S_j = \text{end}_j - \text{start}_j\).  
  If end is OPEN: only elapsed service \(=\min(14:00, \text{end})-\text{start}\) is known; final service is censored.
- **Station sojourn time** \(T_j\):  
  \(T_j = W_j + S_j\) (censored if \(S_j\) is censored).
- **Total sojourn time for completed cases**:  
  \(\text{s2\_end} - \text{arrival\_s1}\).

### Stationlevel aggregated metrics
- **Arrivals**: count of cases entering the station queue within [08:00,14:00].
- **Completed services**: count of cases whose activity *ended* (nonOPEN, nonblank) by 14:00.
- **Waitingtime / servicetime summary**: mean and range across fully observed cases, extended with imputed intervals for missing starts. Central scenario uses midpoint values.
- **WIP (WorkInProcess)**: for each station, \( \text{WIP}(t) = \text{queue}(t) + \text{in\_service}(t) \).  
  We reconstruct the timeline on a 5min grid using the chosen eventorder convention. Peak WIP and mean WIP are reported.
- **Resource busytime**: sum of service durations that fall within the window, including elapsed time of OPEN activities. For missing starts we use the imputed scenario’s service time.
- **Utilisation**: busytime / (available time × number of resources), where available time is 360min for each resource, except C2 whose availability is reduced by the 15min maintenance (available 345min).
- **Throughput rates**: arrivals or completions per hour, computed for the whole window and for meaningful subperiods (premaintenance, duringmaintenance, postmaintenance).

### Little’s Law check
We apply \(L = \lambda \cdot W\) only to intervals where the station is approximately stationary and a stable throughput can be defined (e.g. S1 over the subinterval when both server backlogs are emptying). For S2 the growing queue violates stationarity; we note the inconsistency rather than forcing a number.

- S1 capacity  \(2 / 28.3 \text{min}^{-1} = 4.24\) cases/hour.  
- S2 capacity  \(2 / 38.2 \text{min}^{-1} = 3.14\) cases/hour.

**Temporal behaviour**
- **08:00–10:00**: Both stations are lightly loaded; S1 queue is small; S2 processes cases almost immediately after S1.  
- **10:00–12:00**: The arrival batch (P08P14) arrives while S2 services are still long (many 40+min). S2 queue builds; S1 queue also grows because cases cannot leave S1 until S2 has capacity to absorb them (indirect blocking).  
- **C2 outage (10:5511:10)**: Removes one S2 server for 15min. This extends the S2 queue and delays P08 (which had to wait until 11:15) and cascades to later cases. The outage temporarily worsens the alreadypresent bottleneck.  
- **12:0014:00**: After S1 finishes its last arrivals, the S1 queue clears completely by 13:45 (P20), leaving only P21 in service and P22 waiting. S2, however, accumulates a growing queue of 4 cases (P16,P18P20) plus two inprogress services (P15,P17). This confirms that S2 is the longterm constraint.

**Hypothesis vs. evidence**  
The data show that S2 service times are intrinsically longer than S1’s, and that the S2 utilisation is high even with two servers. The C2 outage can explain a 15min postponement of two tasks (P08, P11), but even without that outage, the heavy S2 traffic would have led to a queue. Hence the bottleneck is **structurally S2**, and the maintenance interval only slightly amplified the congestion.

# Parse times (date 2026-05-12)

def parse_t(col, flag_col_name):
    timestamps = []
    flags = []
    for v, state in zip(df[col], df["state_at_14_00"] if flag_col_name is None else [None]*len(df)):
        if pd.isna(v) or v == "" or v is None:
            timestamps.append(pd.NaT)
            if "OPEN" in str(state) and "start" in col: # but not needed
                flags.append("WAITING")
            else:
                flags.append("MISSING_or_WAITING")
        elif str(v).upper() == "MISSING":
            timestamps.append(pd.NaT)
            flags.append("MISSING_START")
        elif str(v).upper() == "OPEN":
            timestamps.append(pd.NaT)
            flags.append("OPEN_END")
        else:
            ts = pd.to_datetime(date_str + str(v), format="%Y-%m-%d %H:%M",
                                errors="coerce")
            timestamps.append(ts)
            flags.append("RECORDED")
    return timestamps, flags

# 3. Stationspecific queue / service / WIP computation with pandas
# ---------------------------------------------------------------------
# We construct timelines for S1 and S2 using central imputation for missing starts,
# and track WIP by minute (5min grid) with event order: departures  arrivals  starts.

def build_timeline(station, df, central):
    events = []
    if station == "S1":
        arr_col = "arrival_s1_dt"
        start_col = "s1_start_dt"
        end_col = "s1_end_dt"
        start_flag_col = "s1_start_flag"
        impute_key = {"P07": "P07_s1", "P15": "P15_s1"}
    else:
        arr_col = "s1_end_dt"
        start_col = "s2_start_dt"
        end_col = "s2_end_dt"
        start_flag_col = "s2_start_flag"
        impute_key = {"P05": "P05_s2", "P11": "P11_s2"}

    for _, row in df.iterrows():
        case = row["case"]
        arr = row[arr_col]
        if pd.isna(arr):
            continue
        s_flag = row[start_flag_col]
        if pd.notna(row[start_col]):
            start = row[start_col]
            end = row[end_col] if pd.notna(row[end_col]) else pd.NaT
        else:
            # use central imputation
            key = impute_key.get(case)
            if key:
                imputed_start_str, dur = central[key]
                start = pd.to_datetime(date_str + imputed_start_str)
                service = timedelta(minutes=dur)
                if pd.notna(row[end_col]):
                    end = row[end_col]
                else:
                    end = start + service
            else:
                continue  # skip missing nonimputed
        events.append((case, "arrival", arr))
        events.append((case, "start", start))
        if pd.notna(end) and end <= pd.Timestamp("2026-05-12 14:00"):
            events.append((case, "end", end))
        elif pd.notna(end):
            events.append((case, "open_end", pd.Timestamp("2026-05-12 14:00")))  # censored
        else:
            events.append((case, "censor_start", pd.Timestamp("2026-05-12 14:00")))
    return sorted(events, key=lambda x: x[2])

# Central scenario
central = {
    "P05_s2": ("09:45", 30),
    "P07_s1": ("09:30", 30),
    "P11_s2": ("12:00", 25),
    "P15_s1": ("11:45", 30),
}

s1_events = build_timeline("S1", df, central)
s2_events = build_timeline("S2", df, central)

def compute_wip(events, end_window):
    grid = pd.date_range("2026-05-12 08:00", end_window, freq="5min")
    queue = 0
    in_service = 0
    wip_series = pd.Series(0.0, index=grid)
    for t in grid:
        for e in events:
            if e[2] == t:
                if e[1] == "end":
                    in_service -= 1
                elif e[1] == "start":
                    if queue > 0:
                        queue -= 1
                    in_service += 1
                elif e[1] == "arrival":
                    queue += 1
        wip_series[t] = queue + in_service
    return wip_series

s1_wip = compute_wip(s1_events, "2026-05-12 14:00")
s2_wip = compute_wip(s2_events, "2026-05-12 14:00")

print(f"S2 peak WIP: {s2_wip.max():.0f} cases, mean WIP: {s2_wip.mean():.1f} cases")

def case_table(df, central):
    rows = []
    for _, row in df.iterrows():

            s = (row["s1_end_dt"] - row["s1_start_dt"]).seconds//60
            s1_wait_str = str(w)
            s1_serv_str = str(s)
        elif case == "P07":
            s1_wait_str = "4075 (c:45)"
            s1_serv_str = "535 (c:30)"
        elif case == "P15":
            s1_wait_str = "90120 (c:95)"
            s1_serv_str = "535 (c:30)"
        elif row["state_at_14_00"] == "WAITING_FOR_S1":
            s1_wait_str = "WAITING"
            s1_serv_str = "–"
        # (P21 open: we note)
        # S2
        s2_wait_str, s2_serv_str = "", ""
        if pd.notna(row["s2_start_dt"]) and pd.notna(row["s2_end_dt"]):
            w = (row["s2_start_dt"] - row["s1_end_dt"]).seconds//60
            s = (row["s2_end_dt"] - row["s2_start_dt"]).seconds//60
            s2_wait_str = str(w)
            s2_serv_str = str(s)
        elif case == "P05":
            s2_wait_str = "2050 (c:20)"
            s2_serv_str = "530 (c:30)"
        elif case == "P11":
