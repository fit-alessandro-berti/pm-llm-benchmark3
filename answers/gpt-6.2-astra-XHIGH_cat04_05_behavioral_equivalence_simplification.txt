# 1. Equivalence Notions

Write `O` = Open Case, `A` = Analyze Revision, `C` = Check Revision, `P` = Approve Revision, `R` = Rework Case, and `Z` = Close Case. Observe one case from start to successful completion. A trace is a word of labels in execution order: the two `A`s in `O C A R A Z` occupy different positions, but carry no transition ID, revision ID, or timestamp. Parallel activities are observed by their possible interleavings. Frequencies are not part of equivalence.

- **Visible trace equivalence.** Let `L(M)` be the set of complete words of model `M` after deleting all silent events (`tau`), including silent routing in a net conversion. Models are equivalent iff these sets are equal. An executable prefix that cannot yet finish silently is not a complete trace.
- **P3: bounded visible-language equivalence.** Compare `L₃(M) = {w ∈ L(M) : |w| ≤ 12 and count_A(w) ≤ 3}` for equality. `O` and `Z` both count toward the length; silent transitions do not.
- **P1: operational equivalence.** Retain the endpoints and split the interior at each `R` into an ordered list of attempts. Keep the ordered `A`, `C`, and `P` occurrences in each attempt. Compare the sets of these records. On these alphabets the word can be reconstructed from the record. Separately, compliance requires a distinct `C` in the same attempt as each `A`, before that attempt's `R` or `Z`. A check in another attempt gives no credit. I interpret the stated deadline as allowing `C` before or after `A` *within* the attempt, not as requiring `A` before `C`.
- **P2: dashboard equivalence.** For a complete word `w`, keep `D(w) = (first label, last label, count_A, any_C, any_R)`, where `any` is Boolean. Hide `P` and silent events; retain neither the count of checks nor their order relative to other events. Compare the **sets of attainable records**, not their frequencies or the models' ability to replay each other's raw words. Valid cases require endpoints `O,Z`, positive `count_A`, and `any_C = true`.

# 2. Structural Comparison

For `n ≥ 1` attempts, Model A concatenates `n` blocks of the form `(AC | CA)(P | ε)`, separated by `R`, between `O` and `Z`. Model B first has a revision backbone of `n` blocks `A(P | ε)` separated by `R`; insert **one** `C` at any gap in that backbone, including the first or last gap, then surround it with `O,Z`. These characterizations follow from the mandatory first loop execution and the fork/join scopes.

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | Repeats the `A`/`C` pair and optional `P` | Repeats `A` and optional `P`; `C` is outside the loop | Both have `n` analyses and `n−1` reworks; only A renews the check obligation. |
| Number of checks | Min 1, no finite max; exactly `n` | Min = max = 1 | With two or more attempts the check counts cannot agree. |
| Check placement | In each attempt, on either side of `A`, before `P` if present, and before `R` or `Z` | Anywhere after `O` and before `Z`, even after the last `P` | A enforces a local deadline; B only a case-level deadline. |
| Optional approvals | Zero or one per attempt, after both `A` and `C` | Zero or one per attempt, after `A`, independent of `C` | Both allow 0 through `n` approvals, but not the same placements. |
| Concurrency | One fork for `A` and `C` per attempt | One fork for `C` and the entire revision loop | In B the loop can rework, or even finish, while the check is pending. |
| Join before close | Each local pair joins before its approval choice; `Z` follows loop exit | The outer join waits for both `C` and loop exit before `Z` | Neither can close unchecked; only A guarantees that every completed attempt was checked. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 | not equivalent | High: attempt-level invariant | A checks every attempt; B admits a rework with no prior check and cannot supply two distinct checks. | A does not guarantee that `C` follows `A`. If that stronger rule is intended, neither original enforces it. |
| P2 | equivalent only under stated abstraction | High: equality for all `n` | Both images are exactly `{(O, Z, n, true, n > 1) : n ≥ 1}`. Each `n` is realized by taking the redo branch `n−1` times. | This loses check multiplicity, approval placement, and interleaving; it says nothing about rates. |
| P3 | not equivalent | High: witnesses in both directions | Even a five-event, one-attempt trace (`O A P C Z`) separates B from A; two attempts also separate A from B. | The bound limits what was compared. One witness suffices to refute unbounded equality; agreement inside a bound would not prove it. |

# 4. Counterexample Traces

Each row is a complete visible word in the admitting model. The decisive event is the first at which the rejecting model can no longer match the prefix, even allowing silent moves.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| A1 | `O A C R A C Z` | yes | no | The second `C` has no transition left in B. | P1, P3 |
| A2 | `O C A P R C A P Z` | yes | no | The `C` immediately after `R` would be B's second check. | P1, P3 |
| B1 | `O A P C Z` | no | yes | At `P`, A's local pair has not joined: `C` is still missing. | P1 approval placement, P3 |
| B2 | `O A R C A Z` | no | yes | At `R`, A's first attempt lacks `C`. B's later check cannot satisfy that earlier deadline. | P1 compliance, P3 |
| B3 | `O C A R A Z` | no | yes | The first attempt is legal in A, but at `Z` its second attempt still lacks `C`. | P1 compliance, P3 |

Thus neither visible language includes the other, even within P3. Skipping approval emits `ε` rather than a visible auto-approval; it cannot skip a check or move a visible `P` past a join. B1 meets the check-by-close deadline but exposes the difference in approval placement. A1 and B2 distinguish the models without any approval. Under P2 none of the rows separates the dashboard images: the other model can realize the same record with a different word.

# 5. Bounded Comparison Code

This is exhaustive bounded exploration, not `play_out` sampling. The queue key is **(marking with token counts, visible prefix)**: merging by marking alone would erase different words reaching the same loop state. Merging the same pair is safe because its future continuations are identical. The converted workflow nets here are bounded and the allowed prefix set is finite, so this exploration terminates even if there are silent cycles. Soundness is checked separately; soundness does not imply language equivalence.

```python
from collections import deque
import pm4py
from pm4py.objects.petri_net import semantics

tree_text = {
    'A': "->('Open Case', *(->(+('Analyze Revision', 'Check Revision'), X('Approve Revision', tau)), 'Rework Case'), 'Close Case')",
    'B': "->('Open Case', +('Check Revision', *(->('Analyze Revision', X('Approve Revision', tau)), 'Rework Case')), 'Close Case')",
}
trees = {name: pm4py.parse_process_tree(text) for name, text in tree_text.items()}
nets = {name: pm4py.convert_to_petri_net(tree) for name, tree in trees.items()}

def bounded_language(net, initial, final, max_events=12, max_analyses=3):
    queue = deque()
    seen = set()
    accepted = set()

    def enqueue(marking, prefix):
        key = (frozenset((place, count) for place, count in marking.items() if count), prefix)
        if key not in seen:
            seen.add(key)
            queue.append((marking, prefix))

    enqueue(initial, ())
    while queue:
        marking, prefix = queue.popleft()
        if marking == final:  # exact equality, not just a token at the sink
            accepted.add(prefix)
        for transition in semantics.enabled_transitions(net, marking):
            label = transition.label
            successor_prefix = prefix
            if label is not None:
                if len(prefix) >= max_events:
                    continue
                if label == 'Analyze Revision' and prefix.count(label) >= max_analyses:
                    continue
                successor_prefix = prefix + (label,)
            # Silent moves remain possible even at either visible bound.
            successor = semantics.execute(transition, net, marking)
            enqueue(successor, successor_prefix)
    return accepted

languages = {}
for name, accepting_net in nets.items():
    sound, diagnostics = pm4py.check_soundness(*accepting_net)
    print(name, 'sound:', sound)
    if not sound:
        raise RuntimeError((name, diagnostics))
    languages[name] = bounded_language(*accepting_net)

left, right = languages['A'], languages['B']
print('A, B, common:', len(left), len(right), len(left & right))
print('P3 equivalent:', left == right)
for name, unique in [('A', left - right), ('B', right - left)]:
    print(name, 'only:', len(unique))
    for word in sorted(unique, key=lambda word: (len(word), word)):
        print(' / '.join(word))
```

**Independent count.** With `n` attempts and `k` approvals, A has length `3n+1+k` and `binom(n,k)·2ⁿ` words (choose approved attempts and each pair order). B has length `2n+2+k` and `binom(n,k)·(2n+k)` words (choose approvals and one of the gaps for the unique `C`). Summing for `0 ≤ k ≤ n` subject to length ≤ 12 gives counts for `n = 1,2,3` of `(4,16,56)` for A and `(5,20,60)` for B. Only `n=1` can have the same check count, and all four one-attempt A words occur in B. Hence **76 vs. 85 words; 4 shared, 72 A-only, 81 B-only**. Running the code with PM4Py 2.7.23.4 returned `True` for both soundness checks and matched these counts.

# 6. Stochastic and Footprint Comparison

Footprints summarize activity relations such as possible succession and parallelism. Comparing the tree footprints can identify a changed relation to investigate; matching pairwise summaries need not preserve how many checks occur or which iteration they belong to. For a distributional comparison one needs weights, not just a tree. The example continues section 5 and defines a *test distribution*: each distinct P3 word gets one case and hence equal mass **within its own model**. This is not a claim that real words, transitions, or loop exits are equiprobable.

```python
from pm4py.objects.log.obj import Event, EventLog, Trace

def one_case_per_word(words):
    log = EventLog()
    for index, word in enumerate(sorted(words)):
        case = Trace(attributes={'concept:name': str(index)})
        for label in word:
            case.append(Event({'concept:name': label}))
        log.append(case)
    return log

for name, tree in trees.items():
    footprint = pm4py.discover_footprints(tree)
    print(name, {key: footprint[key] for key in ('sequence', 'parallel')})
distributions = {name: pm4py.get_stochastic_language(one_case_per_word(words))
                 for name, words in languages.items()}
print('P3 uniform-word EMD:', pm4py.compute_emd(distributions['A'], distributions['B']))
```

In PM4Py 2.7.23.4 the tree footprint for A puts `(C,P)` in `sequence`; B puts `(C,P)` and `(P,C)` in `parallel`. B1 exhibits the newly possible `P C` adjacency. The EMD for the specified uniform-word distributions was approximately **0.18216** with the package defaults. EMD compares the cost of moving probability mass between trace variants using a ground distance. A low value can coexist with a rare but serious compliance violation or with many words differing by one event. Real case logs could supply empirical frequencies instead, but may miss legal behaviors. Even zero distance with a genuine metric and fully known bounded distributions would establish equality only of those distributions, not of the unbounded model languages. Equal footprints are not an equivalence proof either.

# 7. Complexity Comparison

Count every parsed operator and leaf once; depth is the maximum number of **edges** from root to leaf. Duplicate count is the sum of excess visible leaf occurrences per label, not the number of repetition opportunities at runtime.

| Structural measure | Model A | Model B |
|---|---:|---:|
| Operator nodes | 5 | 5 |
| Visible leaves | 6 | 6 |
| Silent leaves | 1 | 1 |
| Total nodes | 12 | 12 |
| Depth (edges) | 4 | 5 |
| Duplicate visible labels (excess leaves) | 0 | 0 |

Each has two sequence operators, a loop, a parallel operator and an XOR, plus one leaf per visible label and one `tau`. A longest path in A is sequence → loop → sequence → XOR → `P`; in B it is sequence → parallel → loop → sequence → XOR → `P`.

```python
from collections import Counter

def tree_counts(root):
    pending = [(root, 0)]
    labels = Counter()
    nodes = depth = silent = 0
    while pending:
        node, level = pending.pop()
        nodes += 1
        depth = max(depth, level)
        if node.operator is not None:
            pending.extend((child, level + 1) for child in node.children)
        elif node.label is None:
            silent += 1
        else:
            labels[node.label] += 1
    visible = sum(labels.values())
    return dict(nodes=nodes, operators=nodes-visible-silent, depth=depth,
                visible=visible, silent=silent, duplicates=visible-len(labels))

for name, tree in trees.items():  # trees and nets from section 5
    print(name, tree_counts(tree), 'net simplicity:', pm4py.simplicity_petri_net(*nets[name]))
```

The last call compares simplicity on the **converted nets**, not tree depth. It returned **0.81818 for A versus 0.77778 for B** (rounded, PM4Py 2.7.23.4); A scores higher despite the equal tree node counts. The default arc-degree score depends on the actual places, transitions, and arcs produced by the converter. It does not measure compliance.

# 8. Simplified Model

**Target: P2 only.** Use a single canonical word per dashboard record. Put the one check immediately after opening, omit approval altogether, and keep the analysis/rework loop:

```text
->('Open Case', 'Check Revision', *('Analyze Revision', 'Rework Case'), 'Close Case')
```

```python
import pm4py

simplified_model = pm4py.parse_process_tree(
    "->('Open Case', 'Check Revision', *('Analyze Revision', 'Rework Case'), 'Close Case')"
)
print('Net simplicity:', pm4py.simplicity_petri_net(*pm4py.convert_to_petri_net(simplified_model)))
```

The complete words are precisely `O C A (R A)* Z`. For each `n ≥ 1` there is exactly one such word with `n` analyses, `n−1` reworks, and a check. Its dashboard record is `(O,Z,n,true,n > 1)`. Conversely, every original record of section 3 is attained by choosing that `n`. Thus preservation is exact **on records**. Structurally this uses 2 operators and 5 visible leaves: **7 nodes, depth 2, no silent or duplicate leaves**, versus 12 nodes and depth 4 (A) or 5 (B). It removes both parallel and optional routing. Its converted-net simplicity score is **1.0** under the same version and settings.

| Property | Status | Consequence |
|---|---|---|
| Endpoints, analysis counts, and `n−1` intervening reworks | exact | All `n ≥ 1` remain possible; `any_R` iff `n > 1`. |
| Dashboard check flag | exact | Always true, just as in both originals. |
| Check count and check position | abstracted for P2 | The representative fixes one early check; this retains B's count but discards B's timing choices and A's repeated checks. |
| P1 per-attempt obligation | weakened relative to A | A case-level check no longer covers each attempt after a rework. |
| Visible approval occurrences and placement | lost | No `P` is emitted; this is safe only when approvals are hidden. |
| P3 raw trace set | lost | The representative language is a strict subset of B's; against A it both removes words and adds multi-attempt words with only one check. |

Regression and negative tests use **raw replay on the simplified model**. The last column distinguishes failure to replay a representative from an impossible dashboard record.

| Trace | Raw replay | Dashboard interpretation |
|---|---|---|
| `O C A Z` | accept | One analysis, checked, no rework. |
| `O C A R A Z` | accept | Two analyses, checked, rework. |
| `O C A R A R A Z` | accept | Three analyses, checked, rework. |
| `O A Z` | reject | No check: impossible record. |
| `O C A A Z` | reject | Two analyses but no rework: impossible record in these models. |
| `O A C P Z` | reject | Valid original word and record, but noncanonical; its dashboard representative is `O C A Z`. |

# 9. Final Recommendation

Use **Model A for P1** under the stated same-attempt deadline; B's global join is not an audit of every revision. **Either original is suitable for P2**; use the smaller model in their place only to generate or communicate the dashboard's possible records. Do not install it as an operational workflow or reject real cases merely for not following its representative order. **For P3, use the original whose implementation is under test**: A is the oracle for per-attempt checks and B for a case-wide concurrent check. Neither can replace the other or be replaced by the dashboard model as a visible-trace oracle. The bounded witnesses disprove equality here; passing every bounded test would still not prove unbounded equivalence.
