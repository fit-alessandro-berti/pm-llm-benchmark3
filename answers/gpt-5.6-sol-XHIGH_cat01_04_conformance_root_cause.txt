The most economical explanation is compositional rather than singular. The UI release changed the recorded name of classification, producing systematic log moves for `Risk Screen` and corresponding model moves for `Classify`. The gateway then inserted `Queue Routed`, an event outside the business-level model. These mechanisms explain the improvement from 32% fitting to 58% after label mapping and to 81% after queue removal. The ETL change independently made ingestion latency determine the apparent order of `Decision` and `Notify`; source-sequence ordering raises fitness further to 89%.

August adds a different mechanism. The policy changed the true required process, but the normative model remained on its pre-August version. The 210 sign-off traces and the improvement under a candidate model support model obsolescence, although an unconditional optional sign-off is too permissive to establish policy compliance. Claim value is a hidden effect modifier.

Residual moves should not automatically be assigned to employees. The 55 enhanced-review cases without a recorded check could be genuine bypasses, missing source events, or extraction failures. `Manual Override` appears to be real behavior, but it may be a legitimate corrective exception rather than misconduct.

Stable approval and appeal rates are compatible with all of these mechanisms. Logging defects need not change outcomes, while a low-rate compliance violation may be diluted in aggregate outcomes, have delayed consequences, or be poorly detected. Thus unchanged outcomes neither prove data error nor exclude noncompliance.

def expand_variant_table(table):
    """Expand (trace_string, frequency) pairs into a list of trace strings."""
    expanded = []
    for trace_string, frequency in table:
        expanded.extend([trace_string] * frequency)
    return expanded


def normalize_trace(
    trace_string,
    map_risk_screen=True,
    remove_queue_routed=False,
    reverse_pair_sensitivity=False,
):
    """
    Transparent activity-level normalization.

    reverse_pair_sensitivity is only a counterfactual for these aggregates.
    A real repair must sort original events by a validated source sequence;
    it must not infer order from the desired activity names.
    """
    activities = trace_string.split(",")

    if map_risk_screen:
        activities = [
            "Classify" if activity == "Risk Screen" else activity
            for activity in activities
        ]

    if remove_queue_routed:
        activities = [
            activity for activity in activities
            if activity != "Queue Routed"
        ]

    if reverse_pair_sensitivity:
        # Aggregate-only sensitivity: swap adjacent Notify, Decision.
        # This is not evidence that every such case was timestamp-corrupted.
        i = 0
        while i < len(activities) - 1:
            if activities[i] == "Notify" and activities[i + 1] == "Decision":
                activities[i], activities[i + 1] = (
                    activities[i + 1],
                    activities[i],
                )
                i += 2
            else:
                i += 1

    return ",".join(activities)


def make_log(
    table,
    map_risk_screen=False,
    remove_queue_routed=False,
    reverse_pair_sensitivity=False,
):
    traces = expand_variant_table(table)
    transformed = [
        normalize_trace(
            trace,
            map_risk_screen=map_risk_screen,
            remove_queue_routed=remove_queue_routed,
            reverse_pair_sensitivity=reverse_pair_sensitivity,
        )
        for trace in traces
    ]
    return pm4py.parse_event_log_string(transformed, sep=",")


def sort_real_dataframe_by_source_sequence(dataframe):
    """
    Illustration for the original case-level data, not used on aggregates.

    The dataframe should retain a stable raw-row ID to resolve equal sequence
    values without falling back silently to ingestion time.
    """
    required = {
        "case:concept:name",
        "source_sequence",
        "raw_row_id",
    }
    missing = required.difference(dataframe.columns)
    if missing:
        raise ValueError(f"Missing ordering columns: {sorted(missing)}")
    return dataframe.sort_values(
        ["case:concept:name", "source_sequence", "raw_row_id"],
        kind="stable",
    )

def flatten_strings(value):
    if isinstance(value, str):
        return [value]
    if isinstance(value, (tuple, list)):
        strings = []
        for element in value:
            strings.extend(flatten_strings(element))
        return strings
    return []


def alignment_side_label(value):
    """
    Supports both simple ('A', '>>') alignment steps and PM4Py versions that
    return transition tuples such as ('transition_name', 'A').
    """
    strings = flatten_strings(value)
    return strings[-1] if strings else None


def summarize_async_moves(diagnostics):
    log_moves = Counter()
    model_moves = Counter()

    for result in diagnostics:
        for step in result.get("alignment", []):
            if not isinstance(step, (tuple, list)) or len(step) != 2:
                continue

            log_side = alignment_side_label(step[0])
            model_side = alignment_side_label(step[1])

            if log_side not in (None, ">>") and model_side == ">>":
                log_moves[log_side] += 1
            elif log_side == ">>" and model_side not in (None, ">>"):
                model_moves[model_side] += 1

    return log_moves, model_moves


def numeric_summary(dictionary):
    summary = {}
    for key, value in dictionary.items():
        summary[key] = round(float(value), 4) if isinstance(value, Number) else value
    return summary


def evaluate(name, log, net, initial_marking, final_marking):
    diagnostics = pm4py.conformance_diagnostics_alignments(
        log, net, initial_marking, final_marking
    )
    fitness = pm4py.fitness_alignments(
        log, net, initial_marking, final_marking
    )
    precision = pm4py.precision_alignments(
        log, net, initial_marking, final_marking
    )

    costs = [
        float(result["cost"])
        for result in diagnostics
        if "cost" in result
    ]
    mean_cost = sum(costs) / len(costs) if costs else float("nan")
    log_moves, model_moves = summarize_async_moves(diagnostics)

    print(f"\n=== {name} ===")
    print("fitness:", numeric_summary(fitness))
    print("alignment precision:", round(float(precision), 4))
    print("mean diagnostic cost:", round(mean_cost, 4))
    print("dominant moves on log:", log_moves.most_common(8))
    print("dominant visible moves on model:", model_moves.most_common(8))

    return {
        "diagnostics": diagnostics,
        "fitness": fitness,
        "precision": precision,
        "mean_cost": mean_cost,
        "log_moves": log_moves,
        "model_moves": model_moves,
    }

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a **stack of representation and governance changes**, not a sudden organization-wide behavioral failure. Confidence in this conclusion is high, approximately **95%**. The May UI release renamed `Classify`; the June gateway added `Queue Routed`; and the June ETL change made warehouse-ingestion time determine the apparent order of decision and notification. Their contributions are empirically separated by the staged rise in Jun-Jul fitting traces from 32% to 58%, 81%, and 89%. From August, an additional high-confidence cause is model obsolescence: policy introduced value-conditioned sign-off while the normative tree remained unchanged.

A real operational change also occurred: sign-offs and some manual routing corrections appear to be genuine user actions. That does not make them noncompliant. Conversely, a real compliance problem cannot be excluded. The 25 Jun-Jul and 30 Aug-Sep enhanced-review cases without a recorded check are specific and potentially serious. Current confidence that at least some represent actual bypasses is only **low to moderate, around 35-40%**, because no reliable audit distinguishes bypass from event loss. Stable approval and appeal rates lower concern about a large outcome-producing breakdown but are not exculpatory.

IT should immediately preserve immutable source event IDs, validate source-sequence semantics, restore timestamp provenance, reconcile missing resources and events, and publish a versioned mapping that classifies `Queue Routed` as technical. Process owners should effective-date the normative model and define the legitimate position, purpose, and authorization of `Manual Override`. They should not adopt an unconditional optional-sign-off model as policy.

Compliance should audit all enhanced-without-check cases, high-value cases without sign-off, overrides, and a matched conforming sample. Results should be stratified by reviewer, connector, value, and release version.

It must not yet be claimed that employees caused the conformance decline, that every missing check was an ETL defect, that stable appeals prove compliance, or that the optional-sign-off candidate is a valid policy model.

## 8. Model-governance recommendation

1. **Version normative models by effective date:** Link each policy version, process model, semantic dictionary, and conformance result to explicit validity intervals and preserve historical replayability.

2. **Maintain event-semantic contracts:** Define immutable event codes, business meaning, lifecycle, triggering state change, actor, and permitted label aliases; treat display-label changes as governed schema changes.

3. **Govern technical events explicitly:** Maintain an approved registry distinguishing business, technical, duplicate, and diagnostic events, with documented abstraction rules rather than ad hoc fitness-driven filtering.

4. **Preserve timestamp provenance:** Store source occurrence time, source commit time, sequence number, gateway time, ingestion time, timezone, and tie-break rules; never silently substitute ingestion time for execution order.

5. **Represent data-aware constraints:** Encode or separately test guards such as claim value, authorization, and policy date; do not treat an unconditional optional activity as equivalent to a conditional obligation.

6. **Require post-release validation:** For every UI, gateway, ETL, or policy release, run golden-case provenance checks, variant and DFG comparisons, fitness-and-precision tests, attribute stratification, and targeted manual audits before accepting conformance trends.
