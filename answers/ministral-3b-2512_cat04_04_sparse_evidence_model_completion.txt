# Shared Assumptions
1. **Event-completion semantics**: Activities are atomic and complete before the next begins (no partial execution).
2. **Missing `Supplier Confirmation`**: Assume 5–10% of traces are missing due to integration errors. Represent as probabilistic exclusion (e.g., `Supplier Confirmation` is optional with probability 0.9).
3. **Absent `external/stocked` attribute**: Treat `Supplier Confirmation` as mandatory unless explicitly excluded by `S4` (probabilistic).
4. **Optionality**: Represented via:
   - **XOR splits** (conservative): Exclusive branches.
   - **Silent transitions** (balanced/permissive): Optional activities with no effect on control flow.
   - **Partial orders** (permissive): Allow interleaving where rules permit.

---

# Conservative Candidate (`model_conservative`)
**Inductive bias**: Enforce strict precedence where rules (D1–D6) are unambiguous, exclude all interleavings or missingness unless explicitly justified by high-confidence rules. Prioritize simplicity and explainability over generalization.

**Formal expression**:
```
Register Order  [XOR: (Credit Check  Engineering Review)  (Engineering Review  Credit Check)]
     [XOR: (Supplier Confirmation  None)  (Expedite Review  None)]
     Approve Configuration  Release Production  Archive Case
```
- `Supplier Confirmation` is mandatory (no probabilistic exclusion).
- `Expedite Review` is optional but requires both `Credit Check`/`Engineering Review` (strict sequence).
- `Credit Check`/`Engineering Review` are forced to be sequential (violates S2 but aligns with S1).

**PM4Py Code**:
```python
from pm4py.objects.process_tree.obj import Operator, Sequence, Xor

# Define operators
xor_cc_er = Xor()
xor_sc = Xor()
xor_approve = Xor()

# Build tree
tree = Sequence(
    Operator("Register Order"),
    xor_cc_er,
    Sequence(
        Operator("Credit Check"),
        xor_cc_er,
        Operator("Engineering Review")
    ),
    xor_sc,
    Sequence(
        Operator("Supplier Confirmation"),
        xor_sc,
        None  # None = skip
    ),
    Sequence(
        Operator("Expedite Review"),
        xor_cc_er,  # Requires both checks
        xor_sc,
        Operator("Approve Configuration")
    ),
    Sequence(
        Operator("Release Production"),
        Operator("Archive Case")
    )
)
```

**Excluded behavior**:
1. `Supplier Confirmation` after `Approve Configuration`.
2. `Expedite Review` without both `Credit Check`/`Engineering Review`.
3. Concurrent `Credit Check`/`Engineering Review`.

**Underfitting risks**:
1. Overly restrictive `Credit Check`/`Engineering Review` sequence (ignores S2).
2. No probabilistic handling of missing `Supplier Confirmation`.

# Balanced Candidate (`model_balanced`)
**Inductive bias**: Generalize where rules are ambiguous (D3/D5), use partial orders for concurrency, and model missingness probabilistically. Balance precision and generalization.

**Formal expression**:
```
Register Order  [Partial Order: (Credit Check  Engineering Review)  (Engineering Review  Credit Check)]
     [XOR: (Supplier Confirmation  None)  (Expedite Review  None)]
     Approve Configuration  Release Production  Archive Case
```
- `Supplier Confirmation` is optional (90% probability).
- `Credit Check`/`Engineering Review` are concurrent (partial order).
- `Expedite Review` requires both checks but may precede/delay `Supplier Confirmation`.

**PM4Py Code**:
```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL

# Define partial order for Credit Check/Engineering Review
po_cc_er = StrictPartialOrder()
po_cc_er.order.add_edge("Credit Check", "Engineering Review")
po_cc_er.order.add_edge("Engineering Review", "Credit Check")

# Define operators
xor_sc = Xor()
xor_approve = Xor()

# Build POWL
powl = OperatorPOWL(
    Operator("Register Order"),
    po_cc_er,
    xor_sc,
    OperatorPOWL(
        Operator("Supplier Confirmation"),
        xor_sc,
        None  # None = skip with 10% probability
    ),
    OperatorPOWL(
        Operator("Expedite Review"),
        OperatorPOWL(
            Operator("Credit Check"),
            OperatorPOWL(
                Operator("Engineering Review"),
                None  # Requires both checks
            )
        ),
        OperatorPOWL(
            Operator("Supplier Confirmation"),
            xor_sc,
            Operator("Approve Configuration")
        )
    ),
    Operator("Release Production"),
    Operator("Archive Case")
)
```

**Excluded behavior**:
1. `Supplier Confirmation` after `Approve Configuration`.
2. `Expedite Review` without both `Credit Check`/`Engineering Review`.
3. `Credit Check`/`Engineering Review` interleaved without partial order.

**Underfitting risks**:
1. Overestimates concurrency for `Credit Check`/`Engineering Review` (violates S1).
2. No explicit handling of `stocked` components.

# Permissive Candidate (`model_permissive`)
**Inductive bias**: Admit all behaviors consistent with domain rules (D1–D7) and stakeholder statements, including interleaving, missingness, and optionality. Prioritize flexibility over simplicity.

**Formal expression**:
```
Register Order  [Partial Order: (Credit Check  Engineering Review)  (Engineering Review  Credit Check)]
     [Silent Transition: Supplier Confirmation  (Expedite Review  None)]
     Approve Configuration  Release Production  Archive Case
```
- `Supplier Confirmation` is optional (90% probability).
- `Credit Check`/`Engineering Review` are fully concurrent (no precedence constraints).
- `Expedite Review` is optional and may precede/delay `Supplier Confirmation`.

**PM4Py Code**:
```python

# Define silent transitions for optionality

silent_er = SilentTransition("Expedite Review")

# Build POWL

    Operator("Register Order"),
    OperatorPOWL(
        Operator("Credit Check"),
        OperatorPOWL(
            Operator("Engineering Review"),
            silent_sc,
            silent_er,
            Operator("Approve Configuration")
        )
    ),
    silent_sc,
    Operator("Release Production"),
    Operator("Archive Case")
)
```

**Excluded behavior**:
1. `Supplier Confirmation` after `Approve Configuration`.
2. `Expedite Review` without both `Credit Check`/`Engineering Review`.
3. `Register Order` before `Archive Case`.

**Underfitting risks**:
1. No enforcement of `Supplier Confirmation`’s mandatory nature for external components.
2. Overly permissive for `stocked` components.
