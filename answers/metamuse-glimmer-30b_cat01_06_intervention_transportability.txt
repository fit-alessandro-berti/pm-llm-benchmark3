## 6. Candidate Site B intervention

Eligibility rules: Parallel creation allowed only for cases where Document Check is legally permissible to start immediately after Register. That is cases with `originals_not_required` OR `originals_already_received`. Public-sector/high-value cases remain eligible for pre-Assessment parallel but Legal Review loop remains unchanged.

Tasks may be created concurrently: `Identity Check` can be created after Register always; `Document Check` can be created after Register only if originals not required, otherwise after `Originals Receipt`. `Assessment` remains gated by completion of both checks. `Legal Review` remains optional after Assessment.

Statutory prerequisites remain: Document Check cannot start before Originals Receipt when originals are legally required; Assessment requires both checks complete; Legal Review precedes final decision for 40% cases.

Queue and WIP controls: Max six open verification tasks per reviewer per role; pull system from Register queue prioritising eligible digital cases; daily WIP review.

Resource responsibilities: Identity reviewers own Identity Check; Document reviewers own Document Check and Originals Receipt handling; Assessors own Assessment; Legal reviewers own Legal Review and Request Supplement.

Legal-review handling: After Legal Review issues Request Supplement, Document Check and Assessment are repeated; parallel creation is disabled for the repeat cycle.

Logging requirements: Event timestamps written at task start/completion by system, not manual back-entry; record true overlap intervals per case.

POWL partial order:
Register < Identity Check
Register < Originals Receipt
Originals Receipt < Document Check
Identity Check < Assessment
Document Check < Assessment
Assessment < Notify
Assessment -> Xor( Legal Review -> Xor( Request Supplement -> Document Check -> Assessment , Approve/Reject ), Approve/Reject )
With concurrency: Identity Check || Document Check when Document Check start condition satisfied.

The pilot separates mechanism failure from implementation failure by randomizing eligible cases to parallel creation while holding logging and WIP controls constant, allowing measurement of true overlap and waiting reduction. If treatment shows no waiting reduction despite high true overlap, the mechanism is absent at B. If overlap is low due to IT lock or late timestamps, implementation fidelity is the cause. Stratification by originals requirement and complexity isolates legal and data constraints from the parallelization effect.

## 9. Recommendation

`conditional go`

Transfer only the partial-order principle that independent pre-Assessment checks should start as early as legally permitted, not the blanket parallel creation copied from Site A. Site A’s nine-hour median reduction is confounded by an API upgrade, two additional document reviewers, a marketing-driven shift to simpler digital claims, daily huddles and improved timestamping, with no negative control. Site B’s statutory requirement for originals in 62% of cases makes Document Check legally impossible to start at registration for the majority of volume, and separate roles, case locking and a 40% legal review loop with supplement rework create different bottlenecks and failure modes.

Start with a stratified pilot limited to digital, no-originals cases where true overlap is feasible, with explicit WIP caps, real-time event logging and a control arm. Expected benefit is a modest median reduction of 3-5h in the eligible subgroup with stable rework; risk is tail worsening and rework inflation in legal cases if parallelization is applied too broadly. Do not copy Site A’s intervention for originals-required or legal-review cases.

Expand only if the pilot shows true overlap >50% in the eligible stratum, waiting before Assessment falls 4h with p90 not increasing, and rework/appeal remain stable. Modify by adding originals-receipt-triggered creation for the originals-required stratum once receipt delay can be monitored. Abandon if overlap remains artifactual due to case locking, if assessment becomes the bottleneck, or if rework rises >2pp.
