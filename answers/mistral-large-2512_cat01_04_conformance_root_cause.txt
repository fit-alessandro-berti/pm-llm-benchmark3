## 8. Model-governance recommendation

1. **Model versioning**: Tag normative models with policy versions and freeze them at release. Require explicit approval for model updates when policies change.
2. **Event-semantic contracts**: Define and enforce a schema for event labels, including semantic equivalence (e.g., `Risk Screen` = `Classify`). Log changes to this schema.
3. **Technical-event policy**: Exclude technical events (e.g., `Queue Routed`) from conformance checks by default. Document their purpose and impact.
4. **Timestamp provenance**: Require ETL pipelines to preserve source-system ordering for critical events (e.g., `Decision`, `Notify`). Audit timestamp provenance quarterly.
5. **Data-aware constraints**: Encode high-value conditions (e.g., EUR 50k) in models using case attributes, not just control flow.
6. **Post-release validation**: Conduct a conformance "smoke test" within 72 hours of any UI, ETL, or policy change. Compare fitness before/after using a holdout sample.
