### **2. Competing Explanations and Timeline**

**January–March (Baseline):**
Stable performance (AUROC ~0.81, Brier ~0.13). No drift detected. Variant distribution and breach rates are consistent.

**April (Pipeline Failure):**
- **Primary cause:** Workflow-system migration renamed `Initial Diagnosis Completed` to `Diagnostic Assessment Completed`. The feature pipeline missed the rename, causing:
  - 17% of events labeled `UNKNOWN_ACTIVITY`.
  - 14% missing queue features (predictions built on incorrect prefixes).
  - AUROC collapses to 0.67, ECE spikes to 0.11.
- **Why not other drifts?**
  - Process variants are stable (V1/V2/V3 shares only slightly distorted by unmapped cases).
  - No evidence of outcome-definition changes or supplier delays.

**May (Partial Recovery):**
- **Pipeline patch deployed:** Most April records backfilled, but some features (e.g., "number of events before diagnosis") were not recomputed.
- **Metrics improve but remain sub-baseline:** AUROC recovers to 0.78, but ECE (0.05) and Brier (0.146) suggest lingering issues.
- **Action:** Audit feature lineage to confirm full backfill.

**June (Process Drift – Routing Policy):**
- **New remote-routing policy:** V2 share jumps from 35% to 52%. V1 drops from 45% to 30%.
- **Why not concept drift?**
  - V2 breach rate improves (0.11  0.09), suggesting the policy is effective.
  - AUROC (0.79) and Brier (0.139) remain stable. No evidence of changed outcome relationships.
- **Confounder:** V3 share increases slightly (18%  22%), but `Order Part  Part Received` time is stable (42h).

**July (Early Supplier Delays):**
- **Supplier delays begin:** Median `Order Part  Part Received` time jumps from 42h to 65h.
- **Metrics worsen slightly:** AUROC drops to 0.76, Brier to 0.151.
- **Label maturity:** 98% (not a major confounder).
- **Hypothesis:** Covariate drift (longer part delays) may be contributing, but AUROC drop suggests concept drift is also possible.

**August–September (Overlapping Drifts):**
- **Supplier delays worsen:** `Order Part  Part Received` time spikes to 130h (Aug) and 148h (Sep).
- **V3 share increases:** 35% (Aug)  42% (Sep). V3 breach rate spikes to 0.64 (Aug) and 0.61 (Sep).
- **Partner Z onboarded (September):** 24% of cases, 58% follow V3. Partner Z’s observed breach rate (0.45) is higher than non-Partner-Z (0.27).
- **Metrics collapse:** AUROC drops to 0.66–0.68, Brier to 0.197–0.214, ECE to 0.12–0.14.
- **Competing explanations:**
  1. **Concept drift:** The relationship between features and breach risk may have changed (e.g., longer part delays now more predictive).
  2. **Population shift:** Partner Z’s rural cases and older devices introduce new feature distributions.
  3. **Process drift:** V3 share increase alone doesn’t explain the breach rate spike (V3 was always high-risk).
  4. **Label delay:** September’s maturity is 82%, but August’s 93% suggests maturity isn’t the primary issue.

**October (Label Maturity Confounding):**
- **Label maturity drops to 55%:** Median label delay increases to 52 days. Observed breach rate (0.16) is likely immature.
- **Supplier delays persist:** `Order Part  Part Received` time at 155h.
- **Partner Z share increases to 27%.**
- **Metrics remain poor:** AUROC 0.64, Brier 0.205.
- **Key insight:** October’s metrics cannot be compared to mature months. The observed breach rate is artificially low due to censoring.

**Python Code for Monthly Process-Evidence Extraction:**
```python
import pandas as pd
import pm4py
from pm4py.objects.log.util import dataframe_utils
from pm4py.objects.conversion.log import converter as log_converter

def extract_monthly_process_evidence(events_path: str, output_dir: str):
    # Read and preprocess
    df = pd.read_csv(events_path)
    df = pm4py.format_dataframe(df, case_id='case_id', activity_key='activity', timestamp_key='timestamp')

    # Normalize diagnosis labels (April migration)
    df['activity'] = df['activity'].replace({
        'Diagnostic Assessment Completed': 'Initial Diagnosis Completed',
        'UNKNOWN_ACTIVITY': 'Initial Diagnosis Completed'  # Conservative imputation
    })

    # Remove duplicates (post-20 April)
    df = df.sort_values(['case_id', 'timestamp']).drop_duplicates(
        subset=['case_id', 'activity', 'timestamp'], keep='first'
    )

    # Create event log
    log = log_converter.apply(df)

    # Monthly summaries
    monthly_summaries = []
    for month in pd.date_range(start='2026-01-01', end='2026-10-01', freq='MS'):
        month_str = month.strftime('%Y-%m')
        month_end = month + pd.offsets.MonthEnd(1)

        # Filter by event time (calendar cohort)
        month_log = pm4py.filter_time_range(log, month, month_end, mode='events')

        # Filter by case start (case cohort)
        case_start_log = pm4py.filter_time_range(log, month, month_end, mode='cases_start')

        # Variant distribution
        variants = pm4py.get_variants_sorted(month_log)
        variant_dist = {k: len(v) / len(month_log) for k, v in variants.items()}

        # Performance DFG
        perf_dfg, start_activities, end_activities = pm4py.discover_performance_dfg(month_log)
        median_edge_times = {
            f"{k[0]}  {k[1]}": v['median'] for k, v in perf_dfg.items()
        }

        # Temporal features (e.g., time to diagnosis)
        temp_features = pm4py.extract_temporal_features_dataframe(
            df[df['case_id'].isin([e.attributes['concept:name'] for e in month_log])]
        )

        # Save summary
        summary = {
            'month': month_str,
            'calendar_cohort_cases': len(month_log),
            'case_cohort_cases': len(case_start_log),
            'variant_distribution': variant_dist,
            'median_edge_times': median_edge_times,
            'temporal_features': temp_features.describe().to_dict()
        }
        monthly_summaries.append(summary)

    # Save to disk
    pd.DataFrame(monthly_summaries).to_csv(f"{output_dir}/monthly_process_evidence.csv", index=False)
    return monthly_summaries
```
