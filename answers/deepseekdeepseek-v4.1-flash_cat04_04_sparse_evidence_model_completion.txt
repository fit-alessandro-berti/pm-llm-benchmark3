# 4. Balanced Candidate

**Inductive-bias statement.** The balanced model encodes high/medium-confidence rules, admits all observed traces, and generalizes only where domain rules justify it. It treats CC/ER as unordered, SC as optional and after at least one check, and EX as optional after both checks before AC. D5 uncertainty is managed by an XOR between “SC after CC” and “SC after ER.”

**Compact formal expression.**  
`RO  XOR(B_A, B_B)  AC  RP  AR`, where  
`B_A = PO(CC, ER, SC?, EX?)` with edges `CCSC?`, `CCEX?`, `EREX?`;  
`B_B = PO(CC, ER, SC?, EX?)` with edges `ERSC?`, `CCEX?`, `EREX?`;

```python
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
)
from pm4py.objects.process_tree.obj import Operator

def xor(*children):
    return OperatorPOWL(Operator.XOR, list(children))

def seq(*children):
    return OperatorPOWL(Operator.SEQUENCE, list(children))

def opt(label):
    return xor(Transition(label), SilentTransition())

def po(children, edges):
    po = StrictPartialOrder(children)
    for s, t in edges:
        po.order.add_edge(s, t)
    return po
```

```python
    return OperatorPOWL(Operator.XOR, list(children))

def seq(*children):
    return OperatorPOWL(Operator.SEQUENCE, list(children))

def opt(label):
    return xor(Transition(label), SilentTransition())

def po(children, edges):
    po = StrictPartialOrder(children)
    for s, t in edges:
        po.order.add_edge(s, t)
    return po

RO = Transition('Register Order')
CC = Transition('Credit Check')
ER = Transition('Engineering Review')
SC = opt('Supplier Confirmation')
EX = opt('Expedite Review')
AC = Transition('Approve Configuration')
RP = Transition('Release Production')
AR = Transition('Archive Case')

branchA = po([CC, ER, SC, EX], [(CC, SC), (CC, EX), (ER, EX)])
branchB = po([CC, ER, SC, EX], [(ER, SC), (CC, EX), (ER, EX)])
model_balanced = seq(RO, xor(branchA, branchB), AC, RP, AR)

# Permissive POWL
SC2 = opt('Supplier Confirmation')
EX2 = opt('Expedite Review')
middle = po([CC, ER, SC2, EX2], [(CC, EX2), (ER, EX2)])
model_permissive = seq(RO, middle, AC, RP, AR)

# 3. Convert each candidate to an accepting Petri net
def to_net(model):
    return pm4py.convert_to_petri_net(model)

nets = {}
for name, model in [
    ('conservative', model_conservative),
    ('balanced', model_balanced),
    ('permissive', model_permissive),
]:
    try:
        net, im, fm = to_net(model)
        nets[name] = (net, im, fm)
    except Exception as e:
        print(f"Conversion failed for {name}: {e}")
        nets[name] = None

# 4. Soundness and available metrics
for name, triple in nets.items():
    if triple is None:
        continue
    net, im, fm = triple
    print(f"\n--- {name} ---")
    try:
        sound = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
        print("soundness:", sound)
    except Exception as e:
        print("soundness check failed:", e)

    for metric_name, fn in [
        ("fitness", lambda: pm4py.fitness_alignments(log, net, im, fm)),
        ("precision", lambda: pm4py.precision_alignments(log, net, im, fm)),
        ("generalization", lambda: pm4py.generalization_tbr(log, net, im, fm)),
        ("simplicity", lambda: pm4py.simplicity_petri_net(net, im, fm)),
    ]:
        try:
            print(metric_name, fn())
        except Exception as e:
            print(f"{metric_name} failed:", e)

# 5. Bounded/sampled playout
for name, model in [
    ('conservative', model_conservative),
    ('balanced', model_balanced),
    ('permissive', model_permissive),
]:
    print(f"\n--- playout {name} ---")
    try:
        traces = pm4py.play_out(model, num_traces=10, max_trace_length=50)
        for t in traces:
            print(t)
    except Exception as e:
        print("play_out model failed:", e)

    if nets.get(name):
        net, im, fm = nets[name]
        try:
            traces = pm4py.play_out(net, im, fm, num_traces=10, max_trace_length=50)
            for t in traces:
                print(t)
        except Exception as e:
            print("play_out net failed:", e)

# 6. Manual positive/negative trace suite
positive = [s for _, s in trace_specs]
negative = [
    "Register Order,Supplier Confirmation,Credit Check,Engineering Review,Approve Configuration,Release Production,Archive Case",
    "Register Order,Credit Check,Expedite Review,Engineering Review,Approve Configuration,Release Production,Archive Case",
    "Register Order,Credit Check,Engineering Review,Approve Configuration,Supplier Confirmation,Release Production,Archive Case",
    "Register Order,Credit Check,Engineering Review,Release Production,Approve Configuration,Archive Case",
]

def accepts(net, im, fm, trace_string):
    l = pm4py.parse_event_log_string([trace_string])
    try:
        fit = pm4py.fitness_alignments(l, net, im, fm)
        return fit.get('percentage_of_fitting_traces', 0.0) == 1.0
    except Exception:
        return None

for name, triple in nets.items():
    if triple is None:
        continue
    net, im, fm = triple
    print(f"\n--- manual suite {name} ---")
    for t in positive:
        print("POS", accepts(net, im, fm, t), t)
    for t in negative:
        print("NEG", accepts(net, im, fm, t), t)

print("\nLIMITATION: sampled playout and the finite manual suite do not prove language inclusion or exact equivalence. Infinite ProcessTree/POWL languages require symbolic comparison.")
```

# 9. Recommendation and Data-Collection Plan

**Immediate use.** Recommend `model_balanced`. It admits all 30 observed cases, encodes the high-confidence rules D1–D4 and D6, and manages D5 uncertainty without the severe overfitting of the conservative model or the high compliance risk of the permissive model.

**Sensitivity analysis.** Use `model_permissive` as a sensitivity model. If operational results and compliance checks remain acceptable under the permissive language, then early SC or broader interleavings may be tolerated. If not, the extra behavior should be treated as risky or forbidden.

**Concrete data-collection plan.**

1. Export the missing external/stocked attribute at order-line or component level.
2. Collect lifecycle timestamps for each activity: start, complete, enable, assign, suspend, resume.
3. Add a missingness flag and integration-error log for Supplier Confirmation.
4. Collect millisecond timestamps and timezone to detect true overlap between CC and ER.
5. Collect case attributes that might explain check order: supplier type, component stock status, engineering priority, credit risk.
6. Prioritize future traces:
   - `RO, SC, CC, ER, AC, RP, AR` to test whether SC can precede both checks.
   - `RO, CC, ER, EX, AC, RP, AR` to test EX without SC.
   - `RO, ER, SC, CC, AC, RP, AR` to test SC after ER but before CC.
   - External component with no SC to quantify missingness vs stocked skip.
   - Traces with overlapping CC/ER start/end times to distinguish concurrency from sequence.

# 10. Uncertainty Statement

| Modeling decision | Calibrated confidence | Comment |
|---|---:|---|
| D1: RO start, AR end | 0.95 | Strongly supported and consistent. |
| D2: AC before RP | 0.95 | Strongly supported. |
| D3: both CC and ER before AC | 0.80 | Strong domain support. |
| D4: SC before AC when present | 0.70 | Medium confidence. |
| D5: SC after at least one check | 0.50 | Used in balanced; permissive relaxes this. |
| D6: EX after both checks, before AC | 0.70 | Medium confidence. |
| D7: concurrency unknown | 0.30 | Completion-only timestamps limit inference. |
| Missing SC due to integration/stocked skip | 0.80 | Plausible and explicitly stated. |
| Balanced model as best immediate choice | 0.60 | Best compromise, but not certain. |

A plausible alternative interpretation that would materially change the recommendation is that S1 is true: Credit Check must finish before Engineering Review starts. If so, the balanced and permissive models are too permissive on CC/ER order, and a sequential model with `CC  ER` would be preferable. Another material alternative is that Supplier Confirmation is mandatory for all external components and the no-SC traces are mostly missing events; then SC should be modeled as mandatory with a missingness-repair step, not as true optionality.
