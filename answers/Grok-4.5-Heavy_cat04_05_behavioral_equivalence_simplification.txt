# 1. Equivalence Notions

We define four observation-dependent notions. In all cases the alphabet of visible labels is \(\Sigma = \{\)‘Open Case’, ‘Analyze Revision’, ‘Check Revision’, ‘Approve Revision’, ‘Rework Case’, ‘Close Case’\(\}\); \(\tau\) is always projected away.

- **Visible trace equivalence after hiding \(\tau\)**. Two models are equivalent when the sets of complete sequences of visible labels they produce are identical (ordinary language equality \(L(A)=L(B)\subseteq\Sigma^*\)). Occurrences of the same label are distinguished solely by their positions in the sequence; multiplicity and order matter.

- **Bounded visible-language equivalence under P3**. The subsets of the visible languages consisting of those traces that contain at most 12 visible events and at most three occurrences of ‘Analyze Revision’ are equal. Equality inside the bound is only evidence; it does not constitute a proof of unbounded equivalence.

- **Business-relevant equivalence under P1**. Two models are equivalent when they generate identical sets of visible traces *and* every generated trace satisfies the operational compliance constraints with the same force:
  - every occurrence of ‘Analyze Revision’ is paired with its own distinct ‘Check Revision’ that appears after any preceding ‘Rework Case’ (or after Open) and before the next ‘Rework Case’ or Close;
  - ‘Rework Case’ separates successive analysis attempts;
  - ‘Approve Revision’ remains optional and its occurrences stay visible and positionally relevant.
  Consequently the models must produce exactly the same language of compliant executions. Because the languages already differ, the models are not equivalent under P1.

- **Abstracted dashboard equivalence under P2**. Let \(\varphi\) be the abstraction that (i) discards every ‘Approve Revision’ and \(\tau\), (ii) collapses any positive number of ‘Check Revision’ occurrences to the Boolean fact “a check occurred”, (iii) retains the exact multiplicity of ‘Analyze Revision’, (iv) retains the Boolean “any Rework Case occurred”, and (v) ignores the precise interleaving order among the remaining Analyze and Check events while preserving the Open-first / Close-last frame. The models are equivalent under P2 when the sets \(\{\varphi(\sigma)\mid\sigma\in L(\text{model})\}\) coincide. Under this observation, multiplicities of Analyze are distinguished by count while Checks are Booleanized.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---------|---------|---------|----------------------|
| Loop scope | Parallel Analyze\(\parallel\)Check followed by optional Approve lies *inside* the binary loop | Only Analyze followed by optional Approve lies inside the loop; Check is concurrent with the whole loop | A repeats a Check with every iteration; B executes Check exactly once |
| Minimum # Check Revision | 1 | 1 | Identical |
| Maximum # Check Revision | unbounded (exactly equal to # Analyze) | 1 | A admits arbitrarily many Checks; B never more than one |
| Possible placement of Check | Concurrent solely with its paired Analyze, after any preceding Rework and before the optional Approve of that iteration | Any interleaving point relative to the entire sequence of Analyzes, Approves and Reworks produced by the loop | B permits a Check after a Rework (or after an Approve) without a fresh Analyze-Check pair; A forbids it |
| Optional Approve occurrences | One optional visible Approve per iteration, sequenced *after* the Analyze\(\parallel\)Check of that iteration | One optional visible Approve per iteration, sequenced after its Analyze (and concurrent with the single Check) | Optionality is the same; the relative order of Approve versus Check differs |
| Concurrency | Analyze \(\parallel\) Check inside each iteration; successive iterations are sequential (separated by Rework) | Single Check \(\parallel\) entire multi-iteration loop | B admits far richer interleavings of its single Check |
| Join before Close | After the loop exits | After both the Check branch and the loop have completed | Both enforce the Open \(\ldots\) Close sequential frame |

Optional Approve Revision and hidden \(\tau\) affect the verdict because the position at which an Approve *may* appear is constrained by the nesting of the XOR: after the parallel pair in A, after Analyze (while Check may still be pending) in B. Choosing the \(\tau\) branch simply omits the Approve label; the sequencing constraint remains and is decisive already for the single-iteration case T_B2.

# 5. Bounded Comparison Code

```python
import pm4py
from pm4py.objects.petri_net.semantics import execute, enabled_transitions
from collections import deque

def marking_key(m):
    return tuple(sorted((str(p), m[p]) for p in m if m[p] > 0))

def collect_bounded_traces(net, im, fm, max_vis=12, max_ana=3, max_steps=40):
    """Exhaustive BFS over markings. Silent transitions are taken without
    extending the visible trace. Visited set is (marking, visible-trace,
    analyze-count) to avoid cycles while still exploring all distinct
    visible sequences. Only complete traces (final marking reached) that
    satisfy the length and analyze bounds are retained. This is exhaustive
    within the stated bounds; it is not a random or heuristic playout."""
    queue = deque()
    queue.append((im, [], 0, 0))
    visited = set()
    completes = set()
    while queue:
        m, vt, na, steps = queue.popleft()
        if steps > max_steps:
            continue
        key = (marking_key(m), tuple(vt), na)
        if key in visited:
            continue
        visited.add(key)
        if m == fm:
            if len(vt) <= max_vis and na <= max_ana:
                completes.add(tuple(vt))
            continue
        for t in enabled_transitions(net, m):
            label = t.label
            new_m = execute(t, net, m)
            new_vt = list(vt)
            new_na = na
            if label is not None:
                new_vt.append(label)
                if label == 'Analyze Revision':
                    new_na += 1
                if len(new_vt) > max_vis or new_na > max_ana:
                    continue
            queue.append((new_m, new_vt, new_na, steps + 1))
    return completes

# Parse and convert
tree_a = pm4py.parse_process_tree(
    "->( 'Open Case', *( ->( +( 'Analyze Revision', 'Check Revision' ), "
    "X( 'Approve Revision', tau ) ), 'Rework Case' ), 'Close Case' )")
tree_b = pm4py.parse_process_tree(
    "->( 'Open Case', +( 'Check Revision', *( ->( 'Analyze Revision', "
    "X( 'Approve Revision', tau ) ), 'Rework Case' ) ), 'Close Case' )")

net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

print("Soundness A:", pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=False)[0])
print("Soundness B:", pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=False)[0])

traces_a = collect_bounded_traces(net_a, im_a, fm_a)
traces_b = collect_bounded_traces(net_b, im_b, fm_b)

only_a = sorted(traces_a - traces_b)
only_b = sorted(traces_b - traces_a)
print(f"\nTraces unique to A ({len(only_a)}):")
for t in only_a[:10]:
    print(t)
print(f"\nTraces unique to B ({len(only_b)}):")
for t in only_b[:10]:
    print(t)
print(f"\nCommon within bound: {len(traces_a & traces_b)}")
```

The exploration is exhaustive (BFS + visited on marking+trace+count). Using `pm4py.play_out` would be non-exhaustive (random sampling) and is therefore avoided for the bounded-language claim.

# 6. Stochastic and Footprint Comparison

Footprints and stochastic languages can supply additional *evidence* of inequivalence but never a proof of trace equivalence.

# 7. Complexity Comparison

```python
from pm4py.objects.process_tree.obj import Operator

def count_nodes(t):
    if t.operator is None:
        return 1
    return 1 + sum(count_nodes(c) for c in t.children)

def depth(t):
    if t.operator is None:
        return 1
    return 1 + max((depth(c) for c in t.children), default=0)

def count_leaves(t, silent=False):
    if t.operator is None:
        return 1 if (t.label is None) == silent else 0
    return sum(count_leaves(c, silent) for c in t.children)

def count_dups(t):
    labels = []
    def collect(x):
        if x.operator is None and x.label is not None:
            labels.append(x.label)
        for c in x.children:
            collect(c)
    collect(t)
    from collections import Counter
    return sum(v - 1 for v in Counter(labels).values() if v > 1)

for name, tree in [("A", tree_a), ("B", tree_b)]:
    print(name, "nodes:", count_nodes(tree),
          "depth:", depth(tree),
          "vis leaves:", count_leaves(tree, False),
          "sil leaves:", count_leaves(tree, True),
          "dups:", count_dups(tree))
    net, im, fm = pm4py.convert_to_petri_net(tree)
    print("  Petri places/transitions:", len(net.places), len(net.transitions),
          "simplicity:", pm4py.simplicity_petri_net(net, im, fm))
```

# 8. Simplified Model

The most appropriate target is P1 (operational compliance).  A single simplification cannot simultaneously preserve the pure visible languages of both originals *and* the P2 abstraction without further collapsing distinctions that P1 regards as essential.  We therefore sequentialise the compliant model A, removing the parallel operator while retaining every compliance guarantee of P1 (and strengthening the order to Analyze \(\prec\) Check, which is still fully compliant).

**Compact process tree**

```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

**PM4Py assignment**

```python
simplified_model = pm4py.parse_process_tree(
    "->( 'Open Case', *( ->( 'Analyze Revision', 'Check Revision', "
    "X( 'Approve Revision', tau ) ), 'Rework Case' ), 'Close Case' )")
```

Structural comparison: 11 nodes (versus 12), no parallel operator, Petri-net simplicity \(\approx 0.867\) (higher than both originals), same 6 visible + 1 silent leaves, 0 duplicates, depth 5.

**Preservation table**

| Property | Status under simplified model |
|----------|-------------------------------|
| Open first / Close last | exact |
| \(\lvert\)Check\(\rvert=\lvert\)Analyze\(\rvert\geq 1\) | exact |
| Own Check after its Analyze and before next Rework/Close | exact (strengthened to Analyze \(\prec\) Check) |
| Rework separates analysis attempts | exact |
| Approve optional after the pair | exact |
| Analyze \(\parallel\) Check interleaving of original A | lost (only sequential order) |
| Single-Check concurrency of B | lost (and was non-compliant under P1) |
| P2 abstracted observations | preserved under \(\varphi\) |
| Pure visible language of A | weakened (proper subset) |

**Regression traces (accepted)**

- R1: Open Case, Analyze Revision, Check Revision, Close Case  
- R2: Open Case, Analyze Revision, Check Revision, Approve Revision, Close Case  
- R3: Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Approve Revision, Close Case  

**Negative traces (rejected)**

- N1: Open Case, Analyze Revision, Approve Revision, Check Revision, Close Case (Approve before Check)  
- N2: Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case (missing Check for first Analyze)

# 9. Final Recommendation

- **P1 (operational compliance)**: Model A is suitable; Model B is not.  The sequential simplification may replace A whenever the business accepts the forced order Analyze \(\prec\) Check (still fully compliant).  If concurrent Analyze/Check is required, retain original A.
- **P2 (executive dashboard)**: both originals (and the simplification) become equivalent under the stated abstraction; either may be used.
- **P3 (bounded testing)**: Model A is the safer reference; the simplification is a conservative under-approximation of A’s bounded language.

**Warning**.  Bounded comparison (Section 5) supplies decisive *evidence* of inequivalence inside the given limits but is not a proof for the unbounded languages.  Full language equality can only be established by a complete formal argument or an exhaustive state-space exploration without length restrictions, which is infeasible for unrestricted loops.
