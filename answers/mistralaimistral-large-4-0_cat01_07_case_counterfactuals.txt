## 1. Feasibility model

Partial-order relation set:

```text
Reg < Tri
Tri < Id
Tri < Doc
Id < Assess
Doc < Assess
Orig < Doc                 [if originals_required = yes]
Assess < CR                [if high_risk = yes or high_value = yes; after latest relevant Assess]
CR < Dec                   [if high_risk = yes or high_value = yes]
Dec < Notify
Assess_i < RMI_i           [if RMI issued by Assessment]
CR_i < RMI_i               [if RMI issued by Compliance Review]
RMI_i < Doc_{i+1}
Doc_{i+1} < Assess_{i+1}
Assess_{i+1} < CR_{i+1}    [if high_risk/high_value; new or reaffirmed]
CR_{i+1} < Dec
Id || Doc                  [if originals_required = no]
Esc/Prelim > Tri           [preliminary escalation/compliance preparation after Triage]
Esc/Prelim || Id, Doc      [may overlap verification]
Esc/Prelim < CR_final      [preparation precedes final compliance review; final CR also after final Assess]
```

Conditional and declarative constraints:

```text
IF originals_required = yes THEN Orig < Doc; Id may be before, during, or after Orig.
IF originals_required = no THEN Id || Doc is allowed.
IF high_risk = yes OR high_value = yes THEN latest Assess < CR < Dec.
IF RMI issued THEN new Doc and new Assess before Dec; IF high_risk/high_value THEN new or reaffirmed CR after latest Assess.
Four-eyes: resource(final Assess) != resource(final CR).
Preliminary compliance screen does NOT replace final CR.
Resource intervals must not overlap.
Queue snapshots are forecasts, not guarantees.
K-104 intervention: Tri < Esc/Prelim; provisional C1 reservation allowed; final CR still after final Assess.
K-219 intervention: Orig < Doc_D2; if D2 requests clarification THEN RMI < Doc_new < Assess_new < Dec.
K-337 intervention: after Assess2, RMI2 is prohibited; Dec must explicitly address unresolved discrepancy (approve with conditions or reject); CR still after Assess2.
K-411 intervention: Tri creates Id and Doc tasks; Id || Doc with real-time timestamps; both < Assess.
```

K-104 alters timing/preparation and C1 scheduling, not routing or decision policy. K-219 alters routing, D1 to D2, and timing, with possible rework routing. K-337 alters the allowed decision policy, suppressing the second RMI, and therefore timing; it is not a pure timing change. K-411 alters timing/concurrency and control-flow task creation/logging, not resource routing or decision policy.

## 3. Counterfactual derivations

### K-104

Factual mechanism: The sanctions ambiguity was visible at Triage (Mon08:20-08:50) but not escalated. The complex corporate document check waited behind D1's long queue and ran Mon21:40-Tue05:40. A1's Assessment Tue15:10-19:10 rediscovered the ambiguity, after which S1 spent Tue19:20-21:20 advising. C1's final compliance review Wed13:10-17:40 had to read much of the evidence from scratch, delaying Decision to Wed18:00 and Notify to Wed18:40.

Minimal intervention: At Triage, send a preliminary escalation packet to S1 and reserve a provisional C1 slot. S1 performs preliminary sanctions/corporate-structure review while Id and Doc proceed. The final C1 review remains after the final Assessment.

Temporal propagation: Identity and Document queues are unchanged, so Id I1 Mon10:40-12:50 and Doc D1 Mon21:40-Tue05:40 remain. Assessment A1 Tue15:10-19:10 also remains because the A1 queue forecast dominates. The change is downstream: S1's post-assessment validation shortens from 2h to about 1h because the packet already exists. C1's reserved slot starts Wed13:10 as in the factual case, but the review shortens from 4.5h to 2.5-3.5h because S1 pre-read the evidence. Decision and Notify move from Wed18:00-18:40 to Wed16:30-17:10. If the reservation pulls C1 to Wed09:00, the case can finish Wed12:30-13:40, but that displaces queued C1 work.

Process-feasibility check: High-risk/high-value requires CR after the latest relevant Assessment and before Decision. A1 assesses, C1 reviews, so four-eyes is satisfied. S1's preliminary work is advisory and does not replace final CR. No resource overlap: S1 Mon08:50-11:00 overlaps Id/Doc but S1 advisory work may overlap; C1 Wed13:10-16:10 is after Assessment and before Decision.

Best/base/worst case: Best: C1 reserved Wed09:00, review 2.5h, Decision Wed12:00-12:30, Notify Wed12:30-12:40, saving about 6h, but urgent C1 cases are delayed. Base: C1 Wed13:10-16:10, Decision Wed16:30-17:00, Notify Wed17:00-17:10, saving 1.5h. Worst: the early packet is incomplete or the sanctions facts change, so C1 still needs 4.5h or issues RMI; then the case gains nothing or enters a new Doc/Assess/CR loop and becomes 8-36h+ slower.

Evidence that would reverse the conclusion: If C1 capacity is strictly zero-sum and urgent cases cannot be displaced, the reservation benefit disappears. If preliminary packets are often incomplete or S1's work duplicates C1 effort, final review time will not fall. If C1's queue is not actually available at Wed13:10, the base path is infeasible.

### K-219

Factual mechanism: Handwritten standard documents were routed to D1 because handwriting can be difficult. Originals arrived Mon17:30, but D1 did not start until Tue09:30 and finished Tue13:30. A2 assessed Tue20:00-22:30, and M1 decided Wed08:30-08:50.

Minimal intervention: At originals receipt, assign the Document Check to D2 instead of waiting for D1. D2's Mon16 queue forecast is 5h, so D2 can start around Mon22:30.

Temporal propagation: D2 starts about 11h earlier than D1 did and, at 4-8h standard service, completes Tue02:30-06:30 instead of Tue13:30. The case then enters the Assessment queue earlier. The Tue08 A2 queue forecast is 6h, so A2 can start around Tue14:00 rather than Tue20:00. Assessment takes 2-4h, completing Tue16:00-18:00. Because M1 can sign in the evening, as in K-104, Decision and Notify move to Tue17:00-19:00 instead of Wed08:30-09:00. If D2 requests clarification, the path becomes Doc D2  RMI external  Doc2  Assess2  Dec, and the external wait dominates.

Process-feasibility check: Originals are required, and Orig Mon17:30 precedes Doc. Identity completed Mon16:20. No high-risk/high-value flag means no Compliance Review is required. D2 is a valid Documents resource. If D2 requests clarification, a new Document Check and Assessment are required before Decision, preserving the rework rule.

Best/base/worst case: Best: D2 4h, no clarification, A2 2.5h, Decision Tue17:00, Notify Tue17:30, saving about 15.5h. Base: D2 6h, A2 2.5-3h, Decision Tue17:00-17:20, Notify Tue17:20-17:30, saving about 15.5h. Worst: D2 8h and requests clarification; with external RMI 8-36h, Doc2 4-8h, and Assess2 2-5h, cycle time becomes 32-71h, i.e., up to 16h faster or up to 23h slower than factual. If M1 cannot sign same evening, the no-rework saving disappears.

Evidence that would reverse the conclusion: If D2's actual queue is much longer than 5h, or D2's clarification rate on handwritten standard documents is high, the savings disappear. If M1 decision capacity is only next-morning, earlier assessment does not shorten cycle time. If D2 errors on handwriting and triggers rework, the intervention can be slower.

### K-337

Factual mechanism: Supplier totals were inconsistent. Doc1 D1 Tue08:30-14:30 found inconsistencies; Assess1 A1 Wed08:00-11:30 requested a corrected schedule; RMI1 took Wed11:30-Thu08:00. Doc2 D1 Thu12:00-17:00 left one inconsistency; Assess2 A1 Fri08:00-10:30 requested one more confirmation; RMI2 spanned the weekend Fri10:30-Mon09:00. Only then did Doc3, Assess3, CR, Decision, and Notify occur.

Minimal intervention: After Assess2 Fri10:30, prohibit the second RMI. The unresolved discrepancy is documented and carried into the final Compliance Review and Decision. The decision must explicitly address it—approve with conditions or reject—not silently ignore it.

Temporal propagation: Removing RMI2 deletes the Fri10:30-Mon09:00 external wait (~70.5h) and the subsequent Doc3 Mon13:00-16:30 and Assess3 Tue08:00-10:30. The latest relevant Assessment becomes Assess2 Fri10:30. C1 can review on Friday, the Thu08 C1 queue forecast was 5h, suggesting capacity clears by Friday, e.g., Fri11:00-15:00. M1 can decide Fri15:30-16:00 and Notify by Fri16:10. Thus the case finishes about 4.5 days earlier, and D1/A1/C1 capacity is freed for other cases.

Process-feasibility check: High-risk/high-value requires CR after the latest relevant Assessment and before Decision. Assess2 is the latest; C1 reviews after it. Four-eyes is satisfied because A1 assessed and C1 reviews. The intervention overrides the usual permission for Compliance Review to issue RMI after Assess2; C1's output is findings/conditions. Decision precedes Notify. No new Doc/Assess is required because no RMI is issued.

Best/base/worst case: Best: C1 starts Fri11:00, review 4h, approve with conditions, Notify Fri16:10, saving about 113h. Base: C1 starts Fri13:00, review 4-6h, Decision Fri17:00-18:00, Notify Fri18:10, saving about 110h. Worst: the decision is rejection or a conditional approval that triggers appeal/remediation; appeal adds weeks and audit/loss exposure, or compliance deems the decision on incomplete evidence indefensible and forces rework. Cycle time may still be shorter, but quality cost is high.

Evidence that would reverse the conclusion: If the unresolved discrepancy is material to valuation or sanctions, deciding without supplier confirmation may be indefensible. If appeal/loss costs exceed the value of 4.5 days, the intervention is bad. If C1 cannot complete a defensible review without another confirmation, the suppression is infeasible. If the supplier would have responded quickly, the factual rework cost was overstated.

### K-411

Factual mechanism: The legacy system created only the identity task at Triage. A case lock prevented document task ownership until Identity completed. Id I2 ran Tue11:30-13:20; Doc D2 started only at Tue15:00 and finished Tue19:30. A2 assessed Wed09:30-12:00, and M1 decided Wed14:00-14:20.

Minimal intervention: At Triage, create both verification tasks and use a controlled workaround so I2 and D2 can work concurrently. Require real-time timestamps rather than later batch entry.

Temporal propagation: The Document task now exists at Tue09:35. D2's Tue08 queue forecast is 4h, so D2 starts around Tue12:00 instead of Tue15:00. Identity I2 starts Tue11:30 as before. The two checks overlap Tue12:00-13:20 and both are complete by Tue16:30, three hours earlier than the factual Document completion. The case enters the Assessment queue earlier. The Tue08 A2 queue forecast is 6h, clearing around Tue14:00; with the case ready at Tue16:30, A2 can start Tue16:30. Assessment 2.5h completes Tue19:00. M1 decides Tue19:30-19:50 and notifies by Tue20:00. The bottleneck migrates from document wait to assessment queue.

Process-feasibility check: No originals are required, so Identity and Document may be concurrent. Both complete before Assessment. No high-risk/high-value flag means no Compliance Review. I2 and D2 are distinct resources, so no overlap. Real-time timestamps are required to ensure the concurrency is true; batch entry would create false concurrency.

Best/base/worst case: Best: A2 starts Tue16:30, Decision Tue19:30, Notify Tue20:00, saving 18.5h. Base: A2 starts Tue16:30-18:00, saving about 15.5-18.5h with minor assessment spillover. Worst: the assessment queue is congested and A2 cannot start until Wed09:30 as in the factual case, so cycle time is unchanged, saving 0h, but WIP is lower; if the workaround is poorly logged, false concurrency may invalidate the path. Intermediate: A2 starts Tue22:30 or Wed08:00, saving about 5.5-11h.

Evidence that would reverse the conclusion: If assessment is the binding constraint and cannot accept earlier cases, the cycle-time saving vanishes. If real-time timestamps reveal no true concurrency or resource overlap, the intervention is infeasible. If dual task creation increases D2/I2 workload and delays non-target cases, the system-wide effect is negative.

## 4. Capacity and interference analysis

| intervention | local resource demand change | queue likely to shrink | queue likely to grow | affected non-target cases | sign of system-wide effect | key nonlinearity |
|---|---|---|---|---|---|---|
| K-104 early escalation/compliance prep | S1 +1-2h early; C1 final review -1-3h but reserved slot; C1 capacity shifted earlier. | Target-case compliance wait; final C1 service time. | C1 queue for non-target urgent cases due reservation; S1 queue if many packets. | Urgent compliance cases delayed by reserved C1 slot; cases needing S1 advice. | Ambiguous; locally positive, system-wide negative if C1 is bottleneck and reservations displace urgent cases. | C1 reservation is zero-sum; many reservations can create queue explosion or meaningless holds; incomplete packets may cause rework. |
| K-219 D1D2 substitution | D2 +4-8h; D1 -4h; possible extra D2/A2 rework if clarification. | D1 queue; target document wait. | D2 queue; assessment queue if cases arrive earlier; external RMI workload if rework. | D2 cases delayed; D1 cases benefit; assessment cases may be delayed. | Ambiguous; positive only if D1 bottleneck severe and D2 has slack and rework rate low. | Rework probability; D2 slower service and clarification can erase savings and add a full rework loop. |
| K-337 suppress second RMI | Removes external RMI2 (~70.5h), Doc3 D1 -3.5h, Assess3 A1 -2.5h; C1 review earlier but similar duration. | D1, A1, C1 queues later in week; external supplier workload. | Appeal/remediation/audit workload if decision challenged. | Cases behind K-337 in D1/A1/C1 benefit; future appeal/audit cases may consume compliance/legal resources. | Positive cycle time, negative quality/compliance risk; net ambiguous. | Decision policy change; suppressing rework shifts unresolved discrepancy into decision conditions/rejection, increasing appeal/loss/audit risk. |
| K-411 parallel verification | Same I2/D2 service hours but concurrent; D2 starts earlier; no extra resource hours. | Document queue wait for target; identity wait unchanged. | Assessment queue, earlier ready cases; simultaneous I/D workload. | Assessment cases delayed; D2/I2 cases may see slight queue growth. | Positive if assessment has slack; negative if assessment bottleneck. | Bottleneck migration from document to assessment; false concurrency if timestamps are batch-entered. |

At 100 similar cases per week, the four local effects do not add linearly. K-104's provisional C1 reservations are the clearest zero-sum interference: C1 is the only fully certified compliance reviewer. If every high-risk/high-value case reserves a slot, C1 becomes a reservation queue; urgent non-target compliance cases are displaced, and unused or incomplete reservations waste scarce capacity. A cap, expiry rule, or release-if-not-ready rule is essential. K-219's D1-to-D2 substitution shifts work from D1 to D2. D2 is slower on standard and complex documents and has a higher clarification risk on handwritten material. At scale, D2's queue grows, and any rework adds a full Document Check + Assessment + external wait, so total workload can rise even while D1's queue shrinks. K-337's suppression of second RMI loops removes large external waits and weekend effects, freeing D1, A1, and C1 capacity for other cases. But it changes decision policy for high-risk/high-value cases: unresolved supplier discrepancies become conditions or rejections, which can increase appeals, losses, and audit findings. Those downstream costs may offset the cycle-time savings. K-411's parallel verification is the most scalable because it uses existing I and D resources concurrently without adding service hours, but it migrates congestion to assessment. If 100 cases complete verification earlier, A1/A2 queues grow; when assessment is the bottleneck, earlier readiness does not produce earlier final completion and non-target cases are delayed. Weekend and external-response effects are nonlinear: suppressing a weekend RMI saves about 70h in K-337, but many external waits will still span weekends, and parallelization cannot remove supplier latency. Timestamp behavior matters: K-411's concurrency is real only if start/complete events are logged in real time; batch entry can create false concurrency and overstate capacity. Overall, the local counterfactuals are optimistic; system-wide, bottleneck migration and zero-sum resource reservations dominate.

## 7. Final synthesis

K-411 is the most robust intervention. It does not alter decision policy or waive compliance, uses existing resources concurrently, and is highly reversible; its main risk is bottleneck migration into assessment, which can be measured and managed. K-337 is the most dangerous despite potential speed: it saves roughly 4.5 days by suppressing a second rework loop, but it changes the decision policy for a high-risk/high-value case and forces a decision on unresolved supplier discrepancies. That can increase appeal risk, loss exposure, and compliance defensibility problems, and a bad decision is hard to reverse. The least transportable local counterfactual is K-104's provisional C1 reservation. Locally, one case can reserve scarce C1 capacity and save a few hours, but if 100 similar cases all reserve C1 slots, the single compliance reviewer becomes a reservation queue and urgent non-target cases are displaced; the local saving is zero-sum and does not scale. K-337's decision-policy change is also poorly transportable, but its risk is quality rather than capacity. The most valuable additional data are real-time resource-level start/complete timestamps, queue arrival and service events, C1 reservation and non-target urgent-case delays, D1/D2 clarification and rework events, external RMI response times, weekend/after-hours calendars, and decision outcomes/appeals. These would distinguish true concurrency from batch-entered timestamps, quantify bottleneck migration, and measure whether early compliance preparation actually reduces final review time or merely shifts work.

## 8. Assumption audit

1. `structural` — Mandatory precedence, final compliance review for high-risk/high-value cases, and the four-eyes rule remain binding; K-337's intervention overrides only the second RMI loop, not the final compliance review.
2. `temporal` — Queue snapshots are forecasts, not guarantees; counterfactual starts are placed using snapshot queues plus service-time ranges, so actual times may shift.
3. `resource` — No resource performs overlapping service intervals; S1 advisory work may overlap with verification; C1 is the only final compliance reviewer.
4. `behavioral` — D2 is more likely than D1 to request clarification on handwritten standard documents; triage staff can create dual tasks and send escalation packets when instructed.
5. `quality` — Preliminary escalation/compliance preparation can reduce final C1 review time by 1-3h but cannot replace final review; suppressing a rework loop changes decision policy and may increase appeal/loss/compliance risk.
6. `interference` — C1 reservations and earlier case readiness are zero-sum or congestion-shifting at system level; local queue reductions can increase non-target waits.
7. `temporal` — External RMI response times are 8-36h and weekend effects can add ~48-72h; overnight service is possible for some pools but not uniformly guaranteed.
8. `resource` — M1 can sign decisions outside standard morning hours when prerequisites are complete, as in K-104 factual, but decision capacity is not modeled as a queue and may become a bottleneck under rollout.
