## 1. Normalization Assumptions

**Interval construction:** All times normalized to UTC as closed intervals `[earliest_true, latest_true]` (exclusive upper minute bounds treated as inclusive `59.999` - difference immaterial, preserved as `...:00` to `...:30/60` etc.). Feasible duration for `A->B` is `[min(B)-max(A), max(B)-min(A)]`. For unions, pairwise differences of branches are kept unless a stated order prunes branches.

**Clock-offset direction:** `clock_offset = recorded_clock - true_clock`, `offset in [a,b]` => `true in [recorded-b, recorded-a]`. I.e. `[ -1,+1]` widens by 1s each side. This is applied **after** resolution uncertainty:
`displayed -> clock-time interval (rounding) -> UTC conversion -> minus offset`.

**Rounding / resolution:**
- HUB UTC exact to second: clock in `R +/-0.5s`. + offset `[-1,+1]` => `R +/-1.5s`.
- OPS-BER floor to minute: `HH:MM` => clock local `[HH:MM:00, HH:MM:60)`. No midpoint substitution.
- SENSOR UTC round to nearest 10s: clock in `R +/-5s`. + offset `[-5,+5]` => `R +/-10s`. Device event is completion - no further shift.
- VENDOR-NY floor to minute, same as OPS-BER.
- LEGACY-BER floor to minute, same.
- MOBILE-LON round to nearest minute: `HH:MM` => clock local `[HH:MM:00-30s, HH:MM:00+30s)`.

**Time-zone conversion:** CEST = UTC+2, EDT = UTC-4, BST = UTC+1, CET = UTC+1. Zone applied to the clock interval, then offset subtracted. Example: `10:14 CEST` => UTC clock `[08:14:00,08:15:00)`.

**DST folds T-405:** On 2025-10-26 Berlin `02:00-02:59` occurs twice. Fold not logged. Each LEGACY-BER time yields union: Branch-1 CEST (UTC=local-2h), Branch-2 CET (UTC=local-1h), each then `+/-60s` offset + 60s floor width => 180s wide branches, 1h apart. Ingestion order is assumed to imply true occurrence order `Alert < Investigation_Start < Containment_Complete`. This prunes 7/8 fold combinations but does **not** collapse remaining interval width to a point.

**Inferred starts:**
- T-404: `Investigation_Start = Investigation_Complete - duration`, `duration in [1080,1500]s`. Full interval propagation retained: `[complete_min-1500, complete_max-1080]`. Signed record treated as medium-strength.
- T-407: `Alert_Received` missing. `Alert_Sent` true + latency `[0,1200]s` => wide inferred interval. No receipt ack. Base analysis imposes **no** causal constraint, allowing negative `Investigation-Receipt` durations. A secondary analysis imposes `Receipt <= Investigation_Start` as plausible but unlogged, yielding `[0,max]` durations. `Alert_Sent != Alert_Received` definitionally.

**Mobile entry delay T-406:** Displayed time may have been entered up to 5 min late. Assumption: this is **occurrence uncertainty**, not just record latency. I.e. true occurrence can be up to 300s **earlier** than clock+offset implies. It therefore extends only the lower bound: `[clock_min-offset_max-300, clock_max-offset_min]`. Stated separately. Without it interval would be `[12:08:30,12:19:30]Z`; with it `[12:03:30,12:19:30]Z`. This materially flips S2.

**Midpoints:** Never used for primary classification. Only used in Sec.5 as explicitly lossy secondary comparison.

**Reference thresholds:** S1 `<=900s`, S2 `<=2700s`, S3 `<=129600s`. Temporal profile bands `mean +/- zeta*sd`. Main Sec.3 table uses `zeta=2`. Sec.4 varies `zeta=1,2,3` and SLA tolerance `+0,+120,+300s`.

# ---------- 2. interval normalization ----------
def parse_naive(s):
    fmt = "%Y-%m-%d %H:%M:%S" if len(s)>16 else "%Y-%m-%d %H:%M"
    return datetime.strptime(s, fmt)

def normalize_interval(recorded_str, system, tz_name, weak_ops_ber=False):
    """Return list of (utc_min, utc_max) branches. Handles DST fold via fold 0/1."""
    naive = parse_naive(recorded_str)
    tz = ZoneInfo(tz_name)
    # clock-interval in local time before offset
    if system=="HUB":
        # exact second +/-0.5s
        base = naive.replace(tzinfo=timezone.utc) if tz_name=="UTC" else naive.replace(tzinfo=tz).astimezone(timezone.utc).replace(tzinfo=None)
        # simpler: HUB is UTC
        dt = naive.replace(tzinfo=timezone.utc)
        lo_c = dt - timedelta(seconds=0.5); hi_c = dt + timedelta(seconds=0.5)
        lo_c, hi_c = lo_c, hi_c  # already UTC clock
        a,b = -1, 1
        return [(lo_c - timedelta(seconds=b), hi_c - timedelta(seconds=a))]
    if system=="SENSOR":
        dt = naive.replace(tzinfo=timezone.utc)
        lo_c = dt - timedelta(seconds=5); hi_c = dt + timedelta(seconds=5)
        a,b = -5, 5
        return [(lo_c - timedelta(seconds=b), hi_c - timedelta(seconds=a))]
    if system in ("OPS-BER","VENDOR-NY","LEGACY-BER"):
        # floor to minute: [naive, naive+60s)
        lo_local_naive = naive
        hi_local_naive = naive + timedelta(seconds=60) - timedelta(microseconds=1)
        # For fold-ambiguous LEGACY, produce two branches using fold attribute
        branches=[]
        folds = [0,1] if (system=="LEGACY-BER" and lo_local_naive.month==10 and lo_local_naive.day==26 and lo_local_naive.hour==2) else [None]
        for f in folds:
            if f is None:
                lo_aware = lo_local_naive.replace(tzinfo=tz)
                hi_aware = hi_local_naive.replace(tzinfo=tz)
            else:
                lo_aware = lo_local_naive.replace(tzinfo=tz, fold=f)
                # hi within same minute => same fold
                hi_aware = hi_local_naive.replace(tzinfo=tz, fold=f)
            lo_c = lo_aware.astimezone(timezone.utc)
            hi_c = hi_aware.astimezone(timezone.utc)
            if system=="OPS-BER":
                a,b = (-720,720) if weak_ops_ber else (-90,120)
            elif system=="VENDOR-NY":
                a,b = (-180,180)
            else:
                a,b = (-60,60)
            branches.append((lo_c - timedelta(seconds=b), hi_c - timedelta(seconds=a)))
        # deduplicate if same UTC (non-ambiguous date)
        return branches
    if system=="MOBILE-LON":
        # round nearest minute: [-30,+30)
        lo_local_naive = naive - timedelta(seconds=30)
        hi_local_naive = naive + timedelta(seconds=30) - timedelta(microseconds=1)
        lo_aware = lo_local_naive.replace(tzinfo=tz)
        hi_aware = hi_local_naive.replace(tzinfo=tz)
        lo_c = lo_aware.astimezone(timezone.utc); hi_c = hi_aware.astimezone(timezone.utc)
        a,b = -300, 300
        lo_t = lo_c - timedelta(seconds=b); hi_t = hi_c - timedelta(seconds=a)
        # entry delay: occurrence up to 300s earlier -> extend lower only
        lo_t_entry = lo_t - timedelta(seconds=300)
        return [(lo_t_entry, hi_t)]
    raise ValueError(system)

def duration_interval(loA_hiA_list, loB_hiB_list):
    # union of branches: [minB-maxA, maxB-minA] per combo, unioned
    res=[]
    for a_lo,a_hi in loA_hiA_list:

def classify(durs, thresh, two_sided=None):
    # thresh: max allowed (one-sided) or two_sided=(low,high)
    if two_sided is not None:
        lo,hi = two_sided
        inside = all(d[0]>=lo and d[1]<=hi for d in durs)
        outside = all(d[1]<lo or d[0]>hi for d in durs)
        if inside: return "CERTAIN_PASS"
        if outside: return "CERTAIN_VIOLATION"
        return "POSSIBLE_VIOLATION"
    else:
        if all(d[1]<=thresh for d in durs): return "CERTAIN_PASS"
        if all(d[0]>thresh for d in durs): return "CERTAIN_VIOLATION"
        return "POSSIBLE_VIOLATION"

## 6. Evidential Sufficiency

For each `POSSIBLE_VIOLATION` or `INDETERMINATE`, minimum extra evidence to make certain (distinguishing sync, activity, duration, semantic evidence):

- **T-401 S1 PV, T-402 S2 PV, T-403 S1 PV, T-404 S1/S2 PV, T-405 S1 PV, T-406 S1/S2 PV:** Need **stronger synchronization evidence**: per-event NTP offset telemetry / logged `clock_offset` at event time (not daily bound), plus logged resolution (exact second vs floor) and raw clock value + UTC storage. For OPS-BER 60-270s widths, reducing offset bound to e.g. ±10s would collapse straddle. For T-406 also need **semantic evidence**: whether 5-min entry delay is occurrence-earlier vs record-later; a UI log (keystroke time vs entered value) or policy statement. Without it S2 flips PPV.
- **T-404 inferred Start PV:** Need **missing activity evidence**: actual `Investigation_Start` log (start lifecycle transition) with HUB-grade timestamp; or **stronger duration evidence**: narrower signed duration (e.g. ±1 min with time-stamped start/complete signatures) instead of 18-25 min range. Currently 423s wide.
- **T-405 S1 PV (post-order):** Need **DST semantic evidence**: logged `fold` / UTC offset (`+02:00` vs `+01:00`) or UTC storage + raw local retention. Order + intervals already prune to one combo but leave 360s width; fold logging alone would not narrow width - still need offset telemetry to get certainty. Without ingestion-order assumption, need **causal identifiers** (e.g. ticket lineage linking Alert->Investigation) to justify pruning; otherwise revert to INDETERMINATE union.
- **T-407 S1 / profiles involving Receipt I:** Need **missing activity evidence**: receipt acknowledgment timestamp on high-trust clock, or network log proving delivery time. Latency bound `[0,20min]` alone is insufficient and allows negative durations. Also need **semantic evidence**: logged causal rule `Receipt <= Start` vs allowing post-start receipt. With ack, S1 becomes testable certain/possible; without, no tolerance/zeta makes it certain.
- **T-409 S1 / Alert-Start / Start-Cont I:** Need **stronger synchronization evidence**: NTP diagnostics for that hour (actual offset, not weak ±12min estimate). Weak estimate is not enforceable. Also need to rule out negative durations via causal `Alert<Start` log. If offset proven ±60s, interval shrinks from 1500s to ~180s and classification becomes certain. Until then strict policy must treat as INDETERMINATE, not PV.
- **Temporal PVs generally (e.g. T-401 A-I, T-408 I-C 3s exceed, T-403 A-I 1.5s exceed):** Need same sync narrowing + **semantic evidence** that statistical band is enforcement vs expectation. A 3s exceed on a ±1.5s HUB clock should not trigger enforcement without stated tolerance; need governance on whether interval overlap suffices.

In short: sync evidence fixes width; activity evidence fixes missing Receipt/Start; duration evidence fixes T-404; semantic evidence fixes entry-delay direction, DST fold meaning, and Receipt<=Start causality.

## 7. Governance Recommendation

1. **UTC storage + raw retention:** Store canonical `event_time_utc` with `recorded_raw`, `source_tz`, `tz_version (IANA)`, `resolution (exact/floor/round + quantum)`, `clock_offset_estimate + bound`, `fold (for ambiguous local times)`. Never overwrite local with converted UTC.
2. **Source offset telemetry:** Require per-event or per-minute NTP/PTP offset logs, not daily bounds. Reject weak engineering estimates (`±12min`) for enforcement; mark such events `evidence_strength=weak => INDETERMINATE` by policy. External VENDOR-NY and MOBILE-LON must be quarantined to low-trust with wide bounds unless synchronized.
3. **Resolution metadata:** Log floor vs round vs exact and quantum (1s, 60s, 10s). Enforce that consumers apply resolution before offset correction. Prohibit silent midpoint substitution in pipelines; midpoints allowed only in explicitly labelled lossy exports.
4. **Start/complete semantics:** Adopt lifecycle model (e.g. `start/complete` transitions with activity instance IDs). Forbid inferring `Start = Complete - duration` for SLA enforcement unless duration is signed with its own uncertainty and retained. SENSOR completion events must be labelled `complete`, not occurrence-start.
5. **DST fold:** Require logging `fold`/`utc_offset` at capture for Europe/Berlin, Europe/London. On fallback days, reject fold-missing timestamps for enforcement; retain union and require ingestion-order causal IDs to prune. Ingestion sequence alone must not be assumed as occurrence order without explicit lineage.
6. **Causal identifiers:** Log `alert_id`, `sent_time`, `received_time`, `ack_id`, network latency measurements separately. `Alert_Sent != Alert_Received`. Do not assume `Receipt <= Start` without log; encode as explicit assumption with sensitivity.
7. **User-entry delay policy:** Decide and document whether entry delay shifts occurrence estimate (earlier) or only record time (late recording, occurrence unchanged but provenance delayed). Log both `occurrence_claim` and `record_time`; capture UI entry latency. Treat per current analysis as occurrence-earlier unless proven otherwise, and show sensitivity both ways.
8. **Enforcement policy for intervals:** Adopt: `CERTAIN_VIOLATION` required for penalty; `POSSIBLE_VIOLATION` triggers review/additional evidence, not automatic fine; `INDETERMINATE` blocks automated judgment. Define SLA tolerance (e.g. +2min grace) explicitly in contract, not post-hoc. Define temporal-profile `zeta` (recommend `zeta=2` for monitoring, `zeta=3` for alerting) and state that profile deviation is expectation, not legal breach - a case can violate SLA but pass profile and vice versa.
9. **Provenance & audit:** Every normalized interval must carry `evidence_strength (High/Med/Low)` and assumption log. Interval code (Sec.5 logic) versioned; midpoint PM4Py diagnostics labelled lossy and never used to override interval conclusions.
