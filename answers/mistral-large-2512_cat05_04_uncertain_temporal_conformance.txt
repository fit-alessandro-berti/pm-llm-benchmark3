## 1. Normalization Assumptions

1. **Clock-offset direction**: `true_time = recorded_time - clock_offset`, where `clock_offset  [a,b]` per source metadata.
2. **Rounding semantics**:
   - *Floor to minute*: recorded time `t` means true clock time  `[t, t + 59.999s]`.
   - *Round to nearest 10s/1min*: true clock time  `[t - 5s, t + 5s]` or `[t - 30s, t + 30s]` respectively.
3. **Time-zone conversion**: Convert local time to UTC using `pytz` or `zoneinfo` with DST rules for 2025/2026.
4. **DST folds (T-405)**:
   - On 2025-10-26 in Europe/Berlin, local times 02:00–02:59 occur twice.
   - Ingestion order (`Alert_Received` before `Investigation_Start` before `Containment_Complete`) rules out the second occurrence for `Alert_Received` and the first for `Containment_Complete`.
   - `Investigation_Start` at 02:05 could be either fold; both are preserved as disjoint UTC intervals.
5. **Inferred starts (T-404)**:
   - `Investigation_Start = Investigation_Complete - duration`, where duration  [1080s, 1500s].
   - Retain all uncertainty: `Start  [Completion - 1500s, Completion - 1080s]`.
6. **Mobile entry delay (T-406)**:
   - Treat as late recording: the displayed time is the user’s best estimate of occurrence time, but entry may be delayed up to 5 minutes.
   - This shifts the *recorded* time, not the occurrence time; thus, the occurrence time is `recorded_time - entry_delay`, where `entry_delay  [0, 300s]`.
7. **Causal constraints (T-407)**:
   - `Alert_Received` must not be after `Investigation_Start`.
   - Network latency bounds `Alert_Received  [Alert_Sent, Alert_Sent + 1200s]`.
   - Intersect with causal constraint to derive feasible `Alert_Received` interval.

import pandas as pd

from zoneinfo import ZoneInfo
from typing import List, Tuple, Union

# --- Interval normalization utilities ---
def utc_interval(recorded: datetime, tz: str, rounding: str, offset_bounds: Tuple[float, float], entry_delay: Tuple[float, float] = (0, 0)) -> List[Tuple[datetime, datetime]]:
    """Convert recorded local time to UTC interval(s)."""
    tz_obj = ZoneInfo(tz)
    local = recorded.astimezone(tz_obj)

    # Rounding
    if rounding == "floor_min":
        start = local.replace(second=0, microsecond=0)
        end = start + timedelta(seconds=59.999)
    elif rounding == "round_10s":
        start = local - timedelta(seconds=5)
        end = local + timedelta(seconds=5)
    elif rounding == "round_min":
        start = local - timedelta(seconds=30)
        end = local + timedelta(seconds=30)
    else:  # exact
        start = end = local

    # Clock offset: true_time = recorded_time - offset
    offset_low, offset_high = offset_bounds
    utc_start = (start - timedelta(seconds=offset_high)).astimezone(ZoneInfo("UTC"))
    utc_end = (end - timedelta(seconds=offset_low)).astimezone(ZoneInfo("UTC"))

    # Entry delay (shifts recorded time, not occurrence)
    if entry_delay != (0, 0):
        delay_low, delay_high = entry_delay
        utc_start = utc_start - timedelta(seconds=delay_high)
        utc_end = utc_end - timedelta(seconds=delay_low)

    return [(utc_start, utc_end)]

def dst_fold_intervals(recorded: datetime, tz: str, offset_bounds: Tuple[float, float]) -> List[Tuple[datetime, datetime]]:
    """Handle DST fold ambiguity."""
    tz_obj = ZoneInfo(tz)
    local = recorded.astimezone(tz_obj)

    end = start + timedelta(seconds=59.999)

    fold1 = [(start.replace(fold=1), end.replace(fold=1))]

        utc_end = (fold[0][1] - timedelta(seconds=offset_low)).astimezone(ZoneInfo("UTC"))
        intervals.append((utc_start, utc_end))
    return intervals

## 7. Governance Recommendation

1. **Timestamp storage**:
   - Store all timestamps in UTC with microsecond precision.
   - Retain raw local timestamps and time-zone metadata in a separate `raw_timestamp` field.

2. **Clock synchronization**:
   - Enforce NTP with 100ms offset for all systems; log offset telemetry hourly.
   - For mobile devices, require GPS or network time synchronization.

3. **Resolution metadata**:
   - Annotate each timestamp with rounding semantics (e.g., `floor_min`, `round_10s`).
   - For user-entered timestamps, log entry delay separately.

4. **Lifecycle semantics**:
   - Distinguish `start` and `complete` events with explicit activity identifiers.
   - For inferred events (e.g., T-404), retain duration uncertainty in metadata.

5. **DST handling**:
   - Log DST fold (`fold=0` or `fold=1`) for ambiguous local times.
   - For legacy systems, require external time source during DST transitions.

6. **Causal identifiers**:
   - Assign unique `alert_id` to `Alert_Received` and `Alert_Sent` to link network latency.
   - Log receipt acknowledgments for external alerts.

7. **Enforcement policy**:
   - Use interval overlap for SLA enforcement: a case passes if *any* feasible duration satisfies the rule.
   - For temporal profiles, require *all* feasible durations to lie within the band for "certain pass."
   - Document assumptions about clock offsets, rounding, and entry delays in audit logs.
