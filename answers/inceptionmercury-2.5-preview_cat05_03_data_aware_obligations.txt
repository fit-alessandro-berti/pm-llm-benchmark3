

## 1. Temporal Data Semantics
State reconstruction follows the latest non-blank event attribute per case, respecting causality. Blank cells indicate no update at that timestamp; they do not reset values to null. Events with identical UTC timestamps are ordered by `event_index`. Material changes include updates to amount, jurisdiction, risk, or customer type. Final attributes are never copied backward to trigger points. Event time is the timestamp; effective time is inferred from evidence (or event time if explicit); record time is database write; evidence time is validation date.

**Formal Pseudo-Logic (R1):**
`if (jurisdiction != "DE") and (amount >= 100000) at Release_Funds then`
    `requires Enhanced_Review where (time > last_material_change_time) and (time < Release_Funds_time)`
    `unless (Exemption_Visible(exemption_id, release_time))`

def get_state_at_release(case_df):
    release_row = case_df[case_df['concept:name'] == 'Release_Funds'].iloc[0]
    cols = ['amount', 'risk_level', 'jurisdiction', 'customer_type']
    state = release_row[cols].to_dict()
    # Fill missing using forward-fill before release
    mask = case_df['time:timestamp'] <= release_row['time:timestamp']

        if pd.isna(state[col]):
            state[col] = case_df.loc[mask, col].ffill().iloc[-1] if not case_df.loc[mask, col].ffill().empty else None
    return state

## 6. Why Control-Flow-Only Conformance Is Insufficient
1.  **Final-State Leakage:** Process mining often assumes the final state is valid at all points. TX-311 shows jurisdiction changed *after* review at the same time.
2.  **Post-Hoc Exemptions:** EX-77 is logged after release; control-flow ignores timing of record creation.
3.  **Material Changes After Review:** R4 requires semantic check of deltas, not just presence of an event.
4.  **Conditional Activation:** R1/R2 trigger only on data attributes (e.g., Amount  100k), invisible to pure control flow.
5.  **Missing Data:** Control-flow checks event types, not absence of critical fields (e.g., TX-305).
6.  **Same-Timestamp Ordering:** Without event_index, causality between Update and Review is ambiguous.

## 7. Recommended Logging and Control Improvements
1.  **Immutable Release Payloads:** Record all attributes at release time, including effective jurisdiction and amount.
2.  **Effective/Record Timestamps:** Log both event time and record write time for exemptions.
3.  **Rule Version:** Tag events with the rule version active at the time of execution.
4.  **Exemption Scope Fields:** Explicitly log approved scopes (risk, amount, jurisdiction) in exemption events.
5.  **Change Provenance:** Track user/system origin and justification for updates (e.g., "order increase").
6.  **Stable Event Ordering:** Ensure unique, increasing sequence numbers per case to resolve simultaneous events deterministically.
