# 1. Executive Verdict

The net is a workflow net: one source, one sink, and every node lies on a directed source-to-sink path. It should not be expected to be sound. The principal defect is that `t_join_waived` consumes only `p_waived` and produces `p_decision`, leaving the analysis token outside the waiver synchronization. On every waiver execution `t_authorize` can fire while `p_analysis` or `p_analysis_done` is still marked, and that leftover token has no consumer. A waived case can therefore be authorized before mandatory analysis, and the exact final marking `[sink]` is unreachable on the waiver route. The standard-review route can reach `[sink]` alone. `t_waive_review` is fireable and is absent from every accepting run.

# 2. Structural Diagnosis

The graph is a free-choice workflow net and, by the enumeration in Section 3, 1-safe. The review branch is a well-formed conflict. The failure is local to the waiver join.

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
| --- | --- | --- | --- |
| `source`, `sink`, `im`, `fm` | Unique start and unique clean end: `im = [source]`, `fm = [sink]` | `source` is the only place with an empty preset. `sink` is the only place with an empty postset. Both markings are the usual accepting pair | A workflow-net check can succeed while waiver runs still end with a token beside `sink` |
| `t_split` | AND-split: start analysis and review together | One input `p_ready`; two outputs `p_analysis` and `p_review` | After `t_split`, both branch places hold one token and the three task transitions are enabled |
| `t_analyze`, `p_analysis`, `p_analysis_done` | Mandatory analysis on every case | A single-input, single-output sequence. The only producer of `p_analysis_done` is `t_analyze`. In the original net the only consumer is `t_join_normal` | The analysis token is stranded whenever the review token is sent to `p_waived` |
| `t_standard_review` and `t_waive_review` | XOR: one review outcome, standard or recorded waiver | Both presets equal `{p_review}`, so the choice is free-choice and exactly one of them fires. Outputs are `p_review_done` and `p_waived` respectively | The two outcomes remain mutually exclusive. The waiver outcome is routed away from the working join |
| `t_join_normal` | AND-join of analysis and standard review | Preset `{p_analysis_done, p_review_done}`, postset `{p_decision}` | Standard interleavings reach `[p_decision]` and then `fm` |
| `t_join_waived` | AND-join of analysis and waiver | Preset `{p_waived}` only, postset `{p_decision}`. It is a silent relay, despite the synchronization comment in the original model | Waiver enables `t_authorize` with the analysis token still present; `fm` stays unreachable on that route |
| `t_authorize`, `p_decision` | Single authorization after both branches | The only consumer of `p_decision`. Both joins produce that same place | The authorizing activity is shared, so an early waiver join uses the legitimate authorization transition |
| Every node versus source-to-sink paths | Workflow-net path condition | Each place and transition, including `p_waived` and `t_join_waived`, lies on a directed path from `source` to `sink` | Structural path existence holds. It does not imply that every maximal execution consumes every token it creates |

No transition is dead: each is enabled in some reachable marking, including both joins and `t_authorize`. Classical soundness fails on option to complete and on proper completion along the waiver branch.

# 4. Minimal-Repair Alternatives

Edit-cost model: each added arc, removed arc, added place, removed place, added transition, and removed transition costs 1. Retargeting an arc is one removal plus one addition. Ordinary place/transition arcs only.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
| --- | --- | --- | --- | --- | --- |
| J. Two-input waiver join | Add one arc `p_analysis_done → t_join_waived`. Preset of `t_join_waived` becomes `{p_analysis_done, p_waived}` | 1 | Mandatory analysis on the waiver path; both completion orders; XOR review; clean `fm` | Waiver runs become accepting. `t_authorize` fires only after `t_analyze` and the selected review. `t_join_waived` consumes the analysis token | Leaves the free-choice class: `t_join_normal` and `t_join_waived` share `p_analysis_done` with unequal presets. Two silent joins remain |
| G. Analysis-gated waiver | Add one arc `p_analysis_done → t_waive_review`. Preset of `t_waive_review` becomes `{p_review, p_analysis_done}` | 1 | Mandatory analysis; standard path and its interleavings; XOR still chooses one review; clean `fm` | `t_waive_review` becomes enabled only after `t_analyze`. The trace in which the waiver is recorded before analysis disappears. `t_waive_review` itself consumes `p_analysis_done`, so the old one-input relay is then safe | Also non-free-choice, at `p_review` and at `p_analysis_done`. Narrows the parallel block: the waiver activity waits for analysis |
| R. Relay waiver into the normal join | Remove `t_join_waived → p_decision`. Add `t_join_waived → p_review_done` | 2 | Mandatory analysis; both completion orders; visible labels; free-choice; clean `fm` | Every accepting run, waiver included, fires `t_join_normal`. On the waiver path `t_join_waived` is a silent hop that moves `p_waived` into `p_review_done` | An extra silent step on the waiver path. After the hop, the place name `p_review_done` holds either outcome. Post-join marking is still just `p_decision` |
| O. Optional analysis under waiver | Add silent `t_join_waived_done`. Add arcs `p_analysis → t_join_waived`, `p_waived → t_join_waived_done`, `p_analysis_done → t_join_waived_done`, `t_join_waived_done → p_decision` | 5 | Parallel start, XOR review, clean `fm`, and mandatory analysis on the standard path. Explicit policy change: a waived review may be authorized with `t_analyze` absent | New accepting runs contain `t_waive_review` and omit `t_analyze`. If the analysis token is still pending, `t_join_waived` absorbs it. If analysis already completed, `t_join_waived_done` synchronizes `p_analysis_done` with `p_waived` | Skipping analysis is silent. A later soundness success hides the policy change. Non-free-choice between the two waiver joins |

J and G tie at cost 1 and are the only cost-1 repairs that restore soundness while keeping analysis mandatory. A single new arc can fix the waiver route only by making a waiver-only transition consume `p_analysis_done`. The waiver-only transitions are `t_waive_review` and `t_join_waived`. Adding that input to `t_register`, `t_split`, or `t_analyze` deadlocks the net, because the token does not yet exist or the arc would be circular. Adding it to `t_authorize` deadlocks the standard route, because `t_join_normal` has already consumed `p_analysis_done`. Removing one existing element cannot create the missing consumption. Adding an isolated place or transition breaks the workflow-net path condition and moves no token. Hence the cost-1 sound mandatory-analysis repairs are exactly J and G. They tie on the cost model and differ in language: J keeps both orders of `t_analyze` and `t_waive_review`; G admits only analysis-then-waiver.

J is preferred over G on intent. The business starts the two branches together and allows either review outcome; it restricts authorization, and it does not restrict the order in which analysis and the waiver may be recorded. J is the unique cost-1 repair that keeps those interleavings.

No cost-1 repair stays free-choice. `p_analysis_done` already has postset `{t_join_normal}` with preset `{p_analysis_done, p_review_done}`. Free-choice requires any added consumer of that place to have the same preset, which neither J nor G does. Repair R is the cheapest free-choice repair that keeps both interleavings and mandatory analysis: the waiver token is carried into the existing join, whose preset is unchanged, and the two edits are necessary to retarget the relay. Deleting `p_waived` and `t_join_waived` and producing `p_review_done` directly from `t_waive_review` has the same visible language and also stays free-choice, at cost 6, so it is a cleanup of R and is dominated on this cost model.

Repair O is the sound form of the other policy. One transition cannot consume “`p_analysis` or `p_analysis_done`” as alternatives; each ordinary transition ANDs its preset. Covering both orders therefore needs a second waiver join and four arcs around the existing relay, cost 5. A single arc `p_analysis → t_join_waived` would cancel a pending analysis and deadlock the analysis-first waiver schedule, so it is not a sound shortcut.

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def marking_dict(marking):
    return {
        place.name: tokens
        for place, tokens in marking.items()
        if tokens
    }


def fire_named(net, marking, transition_name):
    """Fire one transition by name. Refuse the step when it is not enabled."""
    enabled = pm4py.get_enabled_transitions(net, marking)
    matches = [t for t in enabled if t.name == transition_name]
    enabled_names = sorted(t.name for t in enabled)
    if len(matches) != 1:
        raise RuntimeError(
            f"{transition_name} is not uniquely enabled; "
            f"enabled={enabled_names}; marking={marking_dict(marking)}"
        )
    transition = matches[0]
    successor = Marking()
    for place, tokens in marking.items():
        if tokens:
            successor[place] = tokens
    for arc in transition.in_arcs:
        weight = getattr(arc, "weight", 1)
        successor[arc.source] -= weight
        if successor[arc.source] <= 0:
            del successor[arc.source]
    for arc in transition.out_arcs:
        weight = getattr(arc, "weight", 1)
        successor[arc.target] += weight
    return successor


def replay(net, marking, names):
    current = marking
    print("start", marking_dict(current))
    for name in names:
        try:
            current = fire_named(net, current, name)
        except RuntimeError as exc:
            print("blocked:", exc)
            return current
        enabled = sorted(
            t.name for t in pm4py.get_enabled_transitions(net, current)
        )
        print(f"fired {name} -> {marking_dict(current)}; enabled={enabled}")
    return current


def marking_key(marking):
    return tuple(sorted(marking_dict(marking).items()))


def reachable_report(net, im, fm):
    queue = [im]
    seen = {marking_key(im)}
    terminals = []
    sink_plus = []
    while queue:
        current = queue.pop()
        enabled = list(pm4py.get_enabled_transitions(net, current))
        names = marking_dict(current)
        if not enabled:
            terminals.append(names)
        if "sink" in names and names != {"sink": 1}:
            sink_plus.append(names)
        for transition in enabled:
            successor = fire_named(net, current, transition.name)
            key = marking_key(successor)
            if key not in seen:
                seen.add(key)
                queue.append(successor)
    print("reachable markings:", len(seen))
    print("terminal markings:", terminals)
    print("markings that contain sink together with another token:", sink_plus)
    print("fm reachable:", marking_key(fm) in seen)
    print("fm is a terminal:", marking_dict(fm) in terminals)


def reachability_size(result):
    graph = result[0] if isinstance(result, tuple) else result
    if hasattr(graph, "number_of_nodes"):
        return graph.number_of_nodes()
    if hasattr(graph, "states"):
        return len(list(graph.states))
    return None


def diagnose(label, net, im, fm):
    print("====", label, "====")
    print("workflow net:", pm4py.check_is_workflow_net(net))
    print(
        "soundness return:",
        pm4py.check_soundness(net, im, fm, print_diagnostics=True),
    )
    print(
        "enabled at im:",
        sorted(t.name for t in pm4py.get_enabled_transitions(net, im)),
    )
    print("-- waive before analyze --")
    replay(
        net,
        im,
        [
            "t_register",
            "t_split",
            "t_waive_review",
            "t_join_waived",
            "t_authorize",
            "t_analyze",
        ],
    )
    print("-- analyze, waive, then the matching join and authorize --")
    ending = replay(
        net,
        im,
        [
            "t_register",
            "t_split",
            "t_analyze",
            "t_waive_review",
            "t_join_waived",
            "t_authorize",
        ],
    )
    print("ending equals fm:", marking_dict(ending) == marking_dict(fm))
    reachable_report(net, im, fm)
    graph_result = pm4py.convert_to_reachability_graph(net, im, fm)
    print("reachability result type:", type(graph_result))
    print("library state count:", reachability_size(graph_result))


diagnose("original", net, im, fm)
diagnose("repaired J", repaired_net, repaired_im, repaired_fm)
```

# 7. Repair Trade-Offs and Residual Risks

Under repair J, waiver and standard review stay distinguishable in the firing sequence. A case fires exactly one of `t_standard_review` and `t_waive_review`, and the corresponding silent join is `t_join_normal` or `t_join_waived`. After either join the marking is `[p_decision]`, so the token vector at authorization time is the same for both outcomes. Audit of which review occurred belongs to the trace. The visible labels already carry that distinction: `Perform Standard Review` versus `Record Review Waiver`.

Repair J does not add a second visible way to complete. It adds the previously non-accepting waiver interleavings, each still containing `t_analyze` and exactly one review activity. The two silent joins can confuse a conformance view that drops unnamed transitions: both outcomes then look like register, analysis, one review label, authorize. That abstraction is appropriate for the business labels. It becomes misleading if an analyst treats “which silent join fired” as evidence beyond the review label, or if a later editor adds another silent producer of `p_decision`. Because `p_analysis_done` now has two consumers with different presets, the repaired net is no longer free-choice. In this particular state space the earlier XOR keeps `p_review_done` and `p_waived` mutually exclusive, so only one join is enabled in any reachable marking. A future edit that marked both review places would leave one token stuck, and free-choice reductions would no longer apply.

Soundness is a completion property: from every reachable marking one can reach `fm`, `fm` is the only marking that covers the sink, and every transition is enabled somewhere. A sound net can still skip analysis, collapse the two review labels, or authorize on a different causal schedule. Repair O is the concrete witness. It can be sound while accepting a waived case that never fires `t_analyze`.

Regression traces use the visible labels. These four should be accepted by J, G’s standard traces, and R, in every listed order:

- `Register Case`, `Perform Analysis`, `Perform Standard Review`, `Authorize Case`
- `Register Case`, `Perform Standard Review`, `Perform Analysis`, `Authorize Case`
- `Register Case`, `Perform Analysis`, `Record Review Waiver`, `Authorize Case`
- `Register Case`, `Record Review Waiver`, `Perform Analysis`, `Authorize Case`

G must reject the fourth trace and accept the third. O accepts a fifth trace that J, G, and R must reject: `Register Case`, `Record Review Waiver`, `Authorize Case`.

Further negative traces for the deployed repair:

- `Register Case`, `Authorize Case`
- `Register Case`, `Perform Analysis`, `Authorize Case`
- `Register Case`, `Perform Standard Review`, `Authorize Case`
- `Register Case`, `Record Review Waiver`, `Authorize Case`
- any trace containing both `Perform Standard Review` and `Record Review Waiver`
- any run whose terminal marking contains `sink` together with `p_analysis` or `p_analysis_done`

An accidental bypass of mandatory analysis is visible in the reachability graph even when soundness remains true. Every path from the initial marking to `fm` must include the name `t_analyze`. Structurally, after repair J the only producer of `p_analysis_done` is `t_analyze`, and both producers of `p_decision` consume `p_analysis_done`. Reaching `fm` therefore fires `t_analyze` exactly once. The check fails as soon as a skip transition or a waiver relay is given an arc into `p_analysis_done` or into `p_decision`. Aligning the negative waiver-only trace above is the log-facing version of the same test: fitness must record a missing analysis activity.

# 8. Final Recommendation

Deploy repair J: the single arc `p_analysis_done → t_join_waived`. It is the unique minimum-cost edit that keeps analysis mandatory and keeps both orders of analysis and waiver. Authorization then has one causal history. Each producer of `p_decision` has consumed `p_analysis_done` and exactly one review outcome, and the only successor of `[p_decision]` is `fm`.

Use repair G as the same-cost reserve, and use it only together with an explicit concurrency decision. G also forces analysis and also reaches a clean sink, and it makes the recorded waiver wait until analysis has completed. That is a smaller language than the one the parallel split suggests. Prefer it when the business wants a waiver to be signable only against a finished analysis.

If the implementation must remain free-choice, deploy repair R instead of J. Cost 2 is the minimum once free-choice is required, the visible language matches J, and the ordinary join continues to be the only synchronization. Leave repair O unused unless the business owner changes the rule and accepts a waived case with no analysis event. A soundness flag on O would look as healthy as a soundness flag on J; the rejecting test is the trace `Register Case`, `Record Review Waiver`, `Authorize Case`.
