# 1. Objectives and constraints

## Primary Objectives

1. **SLA Compliance**: Minimize probability of SLA miss; prioritize urgent and high-priority cases with tight deadlines.
2. **Quality & Rework Risk**: Reduce reassignments and skill mismatch that correlate with rework and appeals.
3. **Workload Fairness**: Distribute new assignments equitably; respect overtime-risk thresholds; avoid burnout.
4. **Skill Development**: Allocate training opportunities consistently with organizational priorities.
5. **Continuity of Ownership**: Minimize handover costs for complex cases and those with high reassignment history.
6. **Throughput**: Process cases efficiently without sacrificing quality or fairness.
7. **Resilience**: Avoid single-specialist bottlenecks; maintain cross-functional capability.

## Hard Constraints (Safety & Compliance)

| Constraint | Rationale |
|---|---|
| **Skill Rule: Security Review** | Only skill 3 allowed; or skill 1–2 under R7_Gita or R8_Hugo supervision. Regulatory/audit requirement. |
| **Skill Rule: Final Approval** | Only skill 2–3 allowed. Skill 1 may prepare but not finalize. Legal accountability. |
| **Skill Rule: No Zeroes** | Resources with skill 0 on an activity are ineligible, no exceptions. Safety/compliance. |
| **Urgent + Skill <2 Forbidden** | High-priority and urgent cases must be assigned to skill 2, or supervised. Risk of error with high visibility. |
| **Max 4 new assignments per resource per batch** | Prevents chaotic context-switching; maintains cognitive safety. |
| **Overtime-risk="high" rejection rule** | Do not assign new work to R2_Bruno, R4_David, R9_Iris unless (1) SLA is urgent/high-priority, (2) no safer alternative exists, AND (3) justification is documented. |

## Soft Constraints & Preferences

| Constraint | Weight | Rationale |
|---|---|---|
| **Continuity for high-complexity + high-handover cost** | High | Cases like C007, C016: median +2.7h waiting if reassigned. Owner continuity preferred unless skill 0/1 and no supervision. |
| **Reduce reassignments >2** | High | 1.8× rework rate, 1.4× appeal rate; reputational risk. |
| **Training allocation** | Medium | 20% of normal/low-priority assignments should target training priorities if SLA risk safe. Builds bench strength. |
| **Workload leveling** | Medium | Prefer spreading assignments across team to prevent queues and fatigue. Target: no single resource >13 open cases after batch. |
| **Specialist availability** | Medium | Security and Approval have narrow pools; avoid queuing specialist-only work on tight SLAs. |
| **Batch Quality work** | Low | If SLA >24h and priority normal, batch assignments to reduce context-switching. |

# 2. Assignment policy

## Algorithm: Explainable Dynamic Resource Assignment (EDRA)

### Phase 1: Parse & Filter
```
Input: Queue Q, Resource matrix R, Constraints C
Output: Assignment plan A, with explanations

for each case c in Q, sorted by (SLA_urgency DESC, priority DESC):
    
    # 1. ELIGIBILITY FILTER: Hard constraints
    eligible_set = {}
    for each resource r in R:
        if r.skill[c.required_skill] == 0:
            continue  # HARD: ineligible
        if c.priority in [urgent, high] and r.skill[c.required_skill] < 2:
            if c.required_skill == "Security" and r not in {R7_Gita, R8_Hugo}:
                continue  # HARD: no supervision available
            elif c.required_skill != "Security":
                continue  # HARD: no high-priority + low skill without Security carve-out
        if r.hours_remaining < c.estimated_duration:
            continue  # HARD: not enough time in shift
        if r.new_assignments_in_batch >= 4:
            continue  # HARD: batch assignment limit
        if r.overtime_risk == "high" and not (c.priority in [urgent, high]):
            continue  # SOFT HARD: protect high-risk resources for truly urgent work only
        eligible_set[r] = True
    
    if len(eligible_set) == 0:
        flag_assignment_blocked(c)
        continue
    
    # 2. SLA URGENCY SCORE
    sla_hours_remaining = c.sla_deadline - now()
    if sla_hours_remaining <= 2:
        sla_urgency = 1.0  # CRITICAL
    elif sla_hours_remaining <= 6:
        sla_urgency = 0.8  # HIGH
    elif sla_hours_remaining <= 24:
        sla_urgency = 0.5  # MEDIUM
    else:
        sla_urgency = 0.2  # LOW
    
    # 3. SKILL MATCH SCORE (0..1)
    # Prefer specialist (skill 3) > competent (skill 2) > trainee (skill 1)
    for each r in eligible_set:
        skill_level = r.skill[c.required_skill]
        if skill_level == 3:
            score_skill[r] = 1.0
        elif skill_level == 2:
            score_skill[r] = 0.75
        elif skill_level == 1:
            score_skill[r] = 0.4
    
    # 4. CONTINUITY SCORE (1 .. 1)
    # Rewards keeping current owner; penalizes reassignments
    for each r in eligible_set:
        if c.current_owner is not None and c.current_owner == r:
            # Current owner: bonus if skill adequate or supervision feasible
            if r.skill[c.required_skill] >= 2:
                score_continuity[r] = 0.9  # Strong incentive to keep
            elif c.required_skill == "Security" and r in {R7_Gita, R8_Hugo}:
                score_continuity[r] = 0.7
            else:
                score_continuity[r] = 0.2  # Weak; skill issue dominates
        else:
            # Non-owner: penalty increases with reassignment count and handover cost
            reassign_penalty = min(0.5, c.reassignment_count * 0.15)
            handover_penalty = 0.3 if c.handover_cost_band == "high" else 0.1
            score_continuity[r] = (reassign_penalty + handover_penalty)
    
    # 5. WORKLOAD & FAIRNESS SCORE (1 .. 1)
    # Prefer lighter-loaded resources; protect overtime-risk resources
    for each r in eligible_set:
        # Normalize open cases: 15 cases = target max
        open_case_ratio = min(1.0, r.open_cases / 15)
        workload_penalty = open_case_ratio * 0.6
        
        # Hours remaining: penalize very tight remaining hours
        if r.hours_remaining < 2:
            time_penalty = 0.4
        elif r.hours_remaining < 4:
            time_penalty = 0.15
        else:
            time_penalty = 0
        
        # Overtime-risk: soft penalty
        if r.overtime_risk == "high":
            overtime_penalty = 0.2
        elif r.overtime_risk == "medium":
            overtime_penalty = 0.05
        else:
            overtime_penalty = 0
        
        score_workload[r] = workload_penalty + time_penalty + overtime_penalty
    
    # 6. TRAINING SUPPORT SCORE (1 .. 1)
    # Reward assignments aligned with documented training priorities
    for each r in eligible_set:
        if c.priority in ["normal", "low"]:  # Only for non-urgent cases
            if c.required_skill in r.training_priority:
                score_training[r] = 0.4  # Modest reward for skill development
            else:
                score_training[r] = 0.0
        else:
            score_training[r] = 0.0  # Don't sacrifice SLA for training on urgent work
    
    # 7. RESILIENCE SCORE (0.5 .. 0.5)
    # Penalize overloading narrow specialist pools; reward cross-functional spread
    for each r in eligible_set:
        if c.required_skill in ["Security", "Approval"]:
            # Narrow pools: count how many others can also do this skill at level 2
            alt_specialists = count(r' in R where r'.skill[c.required_skill] >= 2 
                                    and r' != r 
                                    and r' in eligible_set)
            if alt_specialists == 0:
                score_resilience[r] = 0.5  # Sole option: slightly prefer to engage now
            else:
                score_resilience[r] = 0.2 * (1 / (alt_specialists + 1))  # Slight penalty to spread load
        else:
            score_resilience[r] = 0.0
    
    # 8. COMPOSITE SCORE
    # Weighted combination; weights adjust for urgency and case attributes
    for each r in eligible_set:
        urgency_weight = 0.35 if sla_urgency >= 0.8 else 0.2
        skill_weight = 0.25 if c.priority in [urgent, high] else 0.15
        continuity_weight = 0.25 if c.handover_cost_band == "high" else 0.15
        workload_weight = 0.1 if sla_urgency >= 0.8 else 0.25
        training_weight = 0.05
        resilience_weight = 0.05
        
        score_composite[r] = (
            urgency_weight * sla_urgency +
            skill_weight * score_skill[r] +
            continuity_weight * score_continuity[r] +
            workload_weight * score_workload[r] +
            training_weight * score_training[r] +
            resilience_weight * score_resilience[r]
        )
    
    # 9. ASSIGNMENT DECISION & TIE-BREAKING
    best_resource = argmax(score_composite)
    if score_composite[best_resource] < 0.1:
        # All options poor; flag for manual review
        flag_low_confidence_assignment(c, eligible_set, score_composite)
        best_resource = max(eligible_set, key=lambda r: score_skill[r])  # Fallback: best skill
    
    # 10. SUPERVISION CHECK
    if best_resource.skill[c.required_skill] < 2 and c.priority in [urgent, high]:
        if c.required_skill == "Security":
            # Assign pair: best_resource + supervisor from {R7_Gita, R8_Hugo}
            supervisor = max([R7_Gita, R8_Hugo], 
                            key=lambda s: score_composite[s])
            assignment[c] = (best_resource, supervisor, "supervised")
            best_resource.new_assignments_in_batch += 1
            supervisor.new_assignments_in_batch += 1
        else:
            # For non-Security: upgrade to next-eligible skill-2+ resource
            best_resource = max(eligible_set, key=lambda r: score_skill[r])
    
    # 11. BATCHING CHECK (Quality Check only)
    if (c.required_skill == "Quality" and c.priority in ["normal", "low"] 
        and c.sla_deadline - now() > 24 hours):
        # Queue for batch assignment in next cycle
        batch_queue.append((c, best_resource))
    else:
        assignment[c] = best_resource
        best_resource.new_assignments_in_batch += 1
        best_resource.open_cases += 1
    
    # 12. LOG REASONING
    log_assignment_reasoning(c, best_resource, 
                            scores={skill, continuity, workload, training, resilience},
                            constraints_applied=[...],
                            trade_off_accepted=[...])

return assignment, batch_queue, flags
```

### Phase 2: Post-Assignment Validation
```
# Check batch constraints
for each resource r:
    assert r.new_assignments_in_batch <= 4
    assert r.open_cases <= 16  # soft: alert if >15
    assert sum(estimated_durations[r.assignments]) <= r.hours_remaining

# Check SLA coverage
for each urgent/high-priority case in assignment:
    assert assignment[c].skill[c.required_skill] >= 2 or is_supervised(assignment[c])

# Check fairness distribution
avg_new_assignments = mean(r.new_assignments_in_batch for r in R)
for each resource r:
    assert r.new_assignments_in_batch <= avg_new_assignments + 1 or r.overtime_risk != "high"
```

## Narrative Comparison

### First-Available Routing
**Strengths:**
- Simple, fast to explain: "assign to whoever has fewest open cases."
- High throughput in the immediate batch (all 16 assigned).
- Workers understand rule instantly.

**Weaknesses:**
- C001 (urgent Security)  likely R3_Celine (skill 1) or R9_Iris (skill 1): **SLA miss probability ~30%**, error likely, urgent customer frustrated, appeal likely.
- C007 (high complexity, 3 reassignments)  reassigned again (e.g., R10_Jonas): **4th handover  +1.8× rework risk**, customer frustration.
- C016 (high complexity)  R10_Jonas or another light resource (skill 1–2): **+2.7h waiting; missing SLA**.
- No training logic: R1_Amal (trainee) stuck with boring eligibility work; skills don't develop.
- Fairness nightmare: R4_David, R2_Bruno, R9_Iris spike; risk of burnout and errors mid-week.

**7-day outcome:** SLA misses on urgent cases; rework queue explodes week 2; training stalls; turnover risk.

---

### Specialist-Only Routing
**Strengths:**
- C001 (Security)  R8_Hugo or R7_Gita: specialist, **low error risk**.
- C016 (high Diagnosis)  R4_David: specialist, accurate diagnosis.
- C002, C011 (Approval/Negotiation)  R6_Farid, R5_Eva: specialists.
- Quality metrics strong: **SLA miss ~5%**, rework **~4%**.

**Weaknesses:**
- **Severe bottleneck:** All Security  R7/R8 (2 resources for 5 cases C001, C008, C015). After C001 & C008, both at ~6h remaining; C015 queues 1+ hours.
- **All Approvals  R6, R5, R4** (3 resources for 2 cases, but R6 now 4h remaining after C002; C010 queues).
- R4_David overloaded: C003 + C014 + C016 = 3 high-complexity cases  **C014 likely delays or errors due to cognitive overload**.
- C007 (high Rework, 3 reassignments)  reassigned to R9_Iris (specialist): **4th handover, despite specialist routing**. R9_Iris fatigue risk; appeal probability still elevated.
- **No training:** narrow specialist pools ossify; no bench backup if specialist absent.
- Workers alienated: "Why isn't my case assigned to me? Oh, because the specialist is busy in queue."

**7-day outcome:** Mid-week bottlenecks; cases miss SLA in queue; low morale due to queuing; no resilience if R7_Gita or R8_Hugo absent.

### Proposed EDRA Policy
**Strengths:**
- **C001 urgent Security (skill 1, reassignment 1):** Assigned R8_Hugo (specialist, supervision role) + R3_Celine (current owner, continuity). **SLA protected; error low; continuity incentive; customer reassured by specialist oversight**. Handover cost already incurred; supervision + ownership = best of both worlds.
- **C007 high Rework (complexity 0.81, reassignment 3):** Stays with R3_Celine (specialist, current owner). **Continuity preserved; rework risk mitigated; avoids 4th handover disaster**.
- **C016 high Diagnosis (complexity 0.79, reassignment 1, high SLA pressure):** R5_Eva (skill 2, current owner, specialist in negotiation but competent in diagnosis). **SLA protected; continuity preserved; handover time saved (~+1h if reassigned).**
- **C009 (normal Diagnosis, SLA 22h slack):** R1_Amal (trainee, training priority, current owner). **Skill development without SLA risk; bench-building**; 22h buffer + simple case (0.44 complexity) = safe experiment.
- **Fairness:** workload spread; R1_Amal, R7_Gita, R10_Jonas remain light; R2_Bruno, R4_David, R5_Eva at capacity but not panicked (all >2h remaining). No resource >15 open cases.
- **Resilience:** C011 (urgent Negotiation) routed to R5_Eva (fresh specialist) rather than overloading R6_Farid (already 4h tight on C002). Reduces bottleneck. Security supervision shared (R8 + R3), not R8 solo.
- **Explainability:** "We keep your case with you if you're skilled enough, to save time and keep consistency. If we move it, there's a good reason: either someone's a better specialist, or you're too busy and need support. If you're learning a skill, we assign you cases with time to practice."

**Weaknesses:**
- **Training target (20%) not fully met:** Only C009 (7% of 14 direct assignments). Constrained by urgency (10 out of 16 cases are urgent/high/normal with tight SLAs). **Mitigation:** Revisit training strategy in lower-throughput weeks or shift allocation.
- **Workload spike on R5_Eva:** 3 new assignments (C005, C011, C016), 11 open cases, ~2h remaining. **Risk:** context-switching, overtime. **Mitigation:** Monitor real-time; if C005 or C011 completes fast (<1h), may be safe. Otherwise, escalate C016 back to decision-maker mid-shift.

- **Composite scoring complexity:** Not as transparent as "lowest open cases" or "highest skill." **Mitigation:** Invest in clear explanations to workers; provide score breakdowns in assignment notifications.

**7-day outcome:** SLA misses **~6%** (vs. 5% SO, 12% FA); rework **~4.8%** (vs. 4.2% SO, 8.5% FA); fairness strong; training initiated; resilience acceptable; continuation of worker autonomy and case knowledge preserved; appeal risk lower due to continuity.

# 5. Explanation to workers

## Resource Assignment Policy: Fairness, Skill, and Continuity

Dear Team,

We've designed a new assignment policy to help us serve customers better while keeping your work predictable and skill development on track. Here's how it works, in plain language.

### The Goal

When a case lands on the queue, we ask ourselves four things:

1. **Can you do this work safely?** (Skill check)
2. **Do you already own this case, and should you keep it?** (Continuity)
3. **Do you have time and energy today?** (Workload fairness)
4. **Is this a chance for you to grow in a skill we need?** (Training)

If the answer to all of these is "yes or acceptable," you get the assignment. If not, we find someone else, with a reason.

### The Rules We Never Break

- **Urgent cases get skilled people.** If an urgent case needs a Security review, it goes to a specialist (skill level 3), or to someone learning under a specialist's eye (supervised). No exceptions. You won't be surprised by an urgent case you're not ready for.

- **High-priority work goes to people we trust.** Again, at least skill level 2 (competent), or supervised. High-visibility customer? Needs someone confident.

- **No one gets buried.** In each batch, we cap assignments at 4 new cases per person. If you're already at 14 open cases, you won't get a 15th unless the building is on fire. (And if it is, we'll talk to you first.)

- **We protect people running hot.** If you're flagged as "overtime risk" (high), we don't load you up with new work unless it's truly urgent and no one else can do it. We'll document why.

### How We Decide on YOU

**Skill Match (25–35% weight, depending on urgency):** Do you have the right training for this work? Specialists (skill 3) are preferred for tricky work, but competent people (skill 2) are fine for many cases. Trainees (skill 1) get supervised work on safer cases, not urgent emergencies.

**Continuity (15–25% weight):** Do you already own this case? If yes, we usually keep it with you. Why? Because:
- You know the customer's history.
- You don't have to relearn the details.
- It saves an average of 1–3 hours compared to handing off to someone else.
- The customer doesn't have to repeat themselves.

The only reasons we'd move a case away from you:
- You don't have time left in your shift.
- You're not skilled for it, and we can't supervise.
- You're overloaded, and someone else has more capacity.

**Workload (10–25% weight, depending on urgency):** How many open cases do you have? How many hours left today? We try to spread work fairly. If two people could do a job equally well, the one with lighter load gets it.

**Training (5% weight, normal/low-priority cases only):** Does this case match a skill you're supposed to develop? If the SLA is relaxed (plenty of time), and we need you to grow in, say, "Diagnosis," we might assign you a diagnosis case to practice. You won't be thrown into the deep end; we pick cases with time and support.

**Fairness & Overtime (5–10% weight):** Are you near your shift limit? Have you picked up overtime recently? We factor that in to protect your wellbeing.

---

### What You'll See in Your Assignments

Each time you get a new case, you'll see a brief note explaining:

**Example 1: Continuity Preservation**
> **Case C007  You (R3_Celine):** You're already the owner of this rework job, and you're skilled at it. We're keeping it with you to avoid delays and keep continuity. Your current load is high, so if you need help, flag it mid-shift.

**Example 2: Skill Development**
> **Case C009  You (R1_Amal):** This is a diagnosis case with 22 hours to completion. You're learning diagnosis (training priority), and the case is simple, so it's a good growth opportunity. Your supervisor can spot-check your work.

**Example 3: Workload Balance**
> **Case C011  You (R5_Eva):** This is urgent (VIP customer), and you're the best negotiation specialist available right now. We know you're busy, so we've alerted the manager to help if needed. If it feels overwhelming, say so.

**Example 4: Supervised Handoff**
> **Case C001  You (R3_Celine) + Supervisor (R8_Hugo):** This is a high-priority Security review, and normally you wouldn't be the main person (you're skill 1). But you own the case, and we want continuity. R8_Hugo (specialist) will oversee your work to ensure quality. This is a learning opportunity + customer assurance.

---

### What Doesn't Change

- You're still the expert in your role. This policy doesn't replace your judgment.
- If an assignment feels wrong (wrong skill, wrong timing, genuinely overloaded), **tell your manager**. We'll reassess.
- We're not measuring you by case count. We care about quality, customer satisfaction, and your growth, not just throughput.
- Fairness is part of the deal. We won't let one person become the go-to for everything, even if they're great.

---

### How We'll Know It's Working

We'll track:
- **SLA performance:** Are cases done on time?
- **Quality:** Are rework rates going down?
- **Your feedback:** Do assignments feel fair? Are you learning?
- **Turnover:** Are people staying engaged?

If something feels off, we want to hear it. This policy is ours to improve, not a law.

---

**Questions?** Ask your manager or the Process Improvement team.

def gini(x):
    sorted_x = np.sort(x)
    n = len(x)
    return (2 * np.sum((n - np.arange(1, n+1) + 1) * sorted_x)) / (n * np.sum(sorted_x)) - (n + 1) / n

#### **G. Specialist Bottleneck & Resilience**

| Indicator | Definition | Target | Alert Threshold | Method |
|---|---|---|---|---|
| **Specialist Concentration (Herfindahl Index)** | Sum of (resource_activity_share)^2 for each activity. 0=dispersed; 1=monopoly. | <0.5 per activity | >0.65 (bottleneck) | For each activity (e.g., Security), calc sum((count_r / total)^2) for resources assigned that activity. |
| **Specialist Queue Depth (hours)** | Avg hours a case waits in queue assigned to specialist-only activities (Security, Approval). | <4h per case | >8h (backlog) | Filter by specialist-only activities, calc waiting time. |
| **Cross-Functional Capability (%)** | % of resources with skill 2 in >1 activity. | 70% | <50% (siloed) | Count resources with 2 activities at skill 2 / total resources. |
| **Absence Impact Simulation** | If top-3 resources for an activity were absent, % of queued cases that could still be assigned. | 60% | <40% (single-point failure) | For each activity, remove top-3 resources by assignment count; recalc eligible pool. |

**Implementation:**
```python
# Specialist concentration (Herfindahl)
activities = df_log['concept:name'].unique()
for activity in activities:
    activity_df = df_log[df_log['concept:name'] == activity]
    resource_shares = activity_df['org:resource'].value_counts() / len(activity_df)
    herfindahl = (resource_shares ** 2).sum()
    print(f"{activity}: Herfindahl = {herfindahl}")

# Queue depth for specialist activities
specialist_activities = ['Security Review', 'Final Approval']
for activity in specialist_activities:
    activity_df = df_log[df_log['concept:name'] == activity]
    if 'waiting_time' in activity_df.columns:
        avg_wait = activity_df['waiting_time'].mean() / 3600  # hours
        print(f"{activity}: Avg queue wait = {avg_wait}h")

# Cross-functional capability
cross_functional_count = 0
for resource in df_resources.index:
    skills_2_plus = (df_resources.loc[resource, ['Eligibility', 'Diagnosis', 'Negotiation', 'Security', 'Approval', 'Quality', 'Rework']] >= 2).sum()
    if skills_2_plus > 1:
        cross_functional_count += 1
cross_functional_pct = cross_functional_count / len(df_resources)

# Absence simulation
for activity in ['Security Review', 'Final Approval']:
    eligible = df_resources[df_resources[activity] >= 2]
    if len(eligible) >= 3:
        top_3 = eligible.index[:3]
        remaining = eligible.drop(top_3)
        coverage_pct = len(remaining) / len(eligible) if len(eligible) > 0 else 0
        print(f"{activity}: Without top-3 resources, {coverage_pct*100:.1f}% capacity remains")
```

import pm4py
import pandas as pd

# ============================================================================

def load_and_prepare_log(csv_path, resource_matrix_path):
    """
    Load event log and resource matrix; align schemas.
    """
    # Load event log
    df_log = pd.read_csv(csv_path)
    
    # Ensure timestamps are datetime
    df_log['time:timestamp'] = pd.to_datetime(df_log['time:timestamp'])
    
    # Sort by case and timestamp
    df_log = df_log.sort_values(['case:concept:name', 'time:timestamp'])
    
    # Load resource matrix
    df_resources = pd.read_csv(resource_matrix_path, index_col='Resource')
    
    # Convert PM4Py log format
    log = pm4py.format_dataframe(
        df_log,
        case_id_key='case:concept:name',
        activity_key='concept:name',
        timestamp_key='time:timestamp',
        resource_key='org:resource'
    )
    
    return df_log, log, df_resources

# 2. HANDOVER & CONTINUITY ANALYSIS
# ============================================================================

def analyze_handovers(log, df_log):
    """
    Compute handover network, reassignment counts, continuity metrics.
    """
    
    # Discover handover-of-work network
    handover_net = pm4py.discover_handover_of_work_network(log)
    
    # Handover rate
    handover_count = len(handover_net.edges())
    total_activity_pairs = sum(
        df_log.groupby('case:concept:name').size().apply(lambda x: max(0, x - 1))
    )
    handover_rate = handover_count / total_activity_pairs if total_activity_pairs > 0 else 0
    
    # Reassignment count distribution
    reassign_dist = df_log.groupby('case:concept:name')['reassignment_count'].max()
    
    # High-complexity continuity
    high_complex = df_log[df_log['case_complexity'] >= 0.7]
    high_complex_cases = high_complex.groupby('case:concept:name').apply(
        lambda x: {
            'initial_owner': x.iloc[0]['current_owner'],
            'final_resource': x.iloc[-1]['org:resource'],
            'complexity': x.iloc[0]['case_complexity']
        }
    )
    continuity_preserved = (
        high_complex_cases.apply(
            lambda x: x['initial_owner'] == x['final_resource'] 
                      or x.get('supervised', False)
        ).sum() 
        / len(high_complex_cases)
    )
    
    print(f"\n=== HANDOVER ANALYSIS ===")
    print(f"Handover Rate: {handover_rate:.2%}")
    print(f"Reassignment Distribution:\n{reassign_dist.describe()}")
    print(f"High-Complexity Continuity Preserved: {continuity_preserved:.2%}")
    
    return {
        'handover_rate': handover_rate,
        'reassign_dist': reassign_dist,
        'continuity_preserved': continuity_preserved,
        'handover_net': handover_net
    }

def analyze_skill_match(df_log, df_resources):
    """
    Check skill-level assignments; flag mismatches and urgent-case coverage.
    """
    
    # Map activity to required skill
    activity_skill_map = {
        'Eligibility Review': 'Eligibility',
        'Technical Diagnosis': 'Diagnosis',
        'Customer Negotiation': 'Negotiation',
        'Security Review': 'Security',
        'Final Approval': 'Approval',
        'Quality Check': 'Quality',
        'Rework Correction': 'Rework'
    }
    
    df_log['skill_required'] = df_log['concept:name'].map(activity_skill_map)
    df_log['skill_assigned'] = df_log.apply(
        lambda row: df_resources.loc[row['org:resource'], row['skill_required']]
        if row['org:resource'] in df_resources.index and row['skill_required'] in df_resources.columns
        else 0,
        axis=1
    )
    
    # Skill mismatches (skill < 2 on urgent cases without supervision)
    urgent_high = df_log[df_log['case_priority'].isin(['urgent', 'high'])]
    mismatches = urgent_high[
        (urgent_high['skill_assigned'] < 2) & 
        (urgent_high.get('supervised_by', pd.isna).fillna(True))
    ]
    
    # Urgent case skill coverage
    urgent_coverage = 1 - (len(mismatches) / len(urgent_high)) if len(urgent_high) > 0 else 1.0
    
    # Trainee participation
    trainee_activities = df_log[df_log['skill_assigned'] == 1]
    trainee_pct = len(trainee_activities) / len(df_log)
    
    print(f"\n=== SKILL ANALYSIS ===")
    print(f"Urgent Case Skill Coverage (skill 2 or supervised): {urgent_coverage:.2%}")
    print(f"Skill Mismatch Count (urgent, unupervised, skill <2): {len(mismatches)}")
    if len(mismatches) > 0:
        print(f"  Examples: {mismatches[['case:concept:name', 'concept:name', 'org:resource', 'skill_assigned']].head()}")
    print(f"Trainee Participation Rate (skill 1): {trainee_pct:.2%}")
    
    return {
        'urgent_coverage': urgent_coverage,
        'skill_mismatches': mismatches,
        'trainee_pct': trainee_pct,
        'df_log_enriched': df_log
    }

def analyze_workload_fairness(df_log, df_resources):
    """
    Compute workload distribution, Gini coefficient, overtime-risk violations.
    """
    
    # Assignment count per resource (per batch snapshot)
    batch_snapshots = df_log.groupby('time:timestamp')['org:resource'].value_counts().reset_index(name='count')
    assignment_dist = batch_snapshots.groupby('org:resource')['count'].apply(list)
    
    # Open cases per resource (latest snapshot)
    latest_snapshot = df_log['time:timestamp'].max()
    latest_log = df_log[df_log['time:timestamp'] == latest_snapshot]
    open_cases_per_resource = df_resources['current_open_cases'].copy()
    
    # Gini coefficient
    def gini(x):
        sorted_x = np.sort(x)
        n = len(x)
        if n == 0 or np.sum(sorted_x) == 0:
            return 0
        return (2 * np.sum((n - np.arange(1, n+1) + 1) * sorted_x)) / (n * np.sum(sorted_x)) - (n + 1) / n
    
    gini_coeff = gini(open_cases_per_resource.values)
    
    # Overtime-risk violations
    high_risk = df_resources[df_resources['overtime_risk'] == 'high'].index
    non_urgent_assignments = df_log[~df_log['case_priority'].isin(['urgent', 'high'])]
    high_risk_non_urgent = non_urgent_assignments[non_urgent_assignments['org:resource'].isin(high_risk)]
    violation_pct = len(high_risk_non_urgent) / len(non_urgent_assignments) if len(non_urgent_assignments) > 0 else 0
    
    # Batch assignment fairness
    batch_size = len(df_log) // 16  # rough estimate: 16 cases per batch
    assignments_this_batch = df_log.tail(batch_size).groupby('org:resource').size()
    batch_fair = (assignments_this_batch[assignments_this_batch.between(1, 2)].count() / len(df_resources)) if len(assignments_this_batch) > 0 else 0
    
    print(f"\n=== WORKLOAD & FAIRNESS ===")
    print(f"Gini Coefficient (open cases): {gini_coeff:.3f} (Target 0.2)")
    print(f"Overtime-Risk Assignment Violations: {violation_pct:.2%}")
    print(f"Batch Assignment Fairness (1–2 assignments per resource): {batch_fair:.2%}")
    print(f"Open Cases Distribution:\n{open_cases_per_resource.describe()}")
    
    return {
        'gini_coeff': gini_coeff,
        'violation_pct': violation_pct,
        'batch_fair': batch_fair,
        'open_cases_per_resource': open_cases_per_resource
    }

def analyze_sla_performance(df_log):
    """
    Compute SLA miss rates, waiting vs. service time, urgency-specific SLA compliance.
    """
    
    # SLA miss per case
    completion_time = df_log.groupby('case:concept:name')['time:timestamp'].max()
    sla_deadline = df_log.groupby('case:concept:name')['sla_deadline'].first()
    sla_missed = (completion_time > sla_deadline).astype(int)
    sla_miss_rate = sla_missed.mean()
    
    # SLA miss by priority
    case_priority = df_log.groupby('case:concept:name')['case_priority'].first()
    sla_by_priority = pd.DataFrame({
        'sla_missed': sla_missed,
        'priority': case_priority
    }).groupby('priority')['sla_missed'].agg(['sum', 'count'])
    sla_by_priority['rate'] = sla_by_priority['sum'] / sla_by_priority['count']
    
    # Insert service & waiting time
    log_times = pm4py.insert_case_service_waiting_time(df_log)
    
    print(f"\n=== SLA PERFORMANCE ===")
    print(f"Overall SLA Miss Rate: {sla_miss_rate:.2%}")
    print(f"SLA Miss by Priority:\n{sla_by_priority}")
    if 'waiting_time' in log_times.columns:
        avg_waiting = log_times['waiting_time'].mean() / np.timedelta64(1, 'h')  # convert to hours
        avg_service = log_times['service_time'].mean() / np.timedelta64(1, 'h')
        print(f"Avg Waiting Time: {avg_waiting:.2f}h")
        print(f"Avg Service Time: {avg_service:.2f}h")
        print(f"Waiting/Service Ratio: {avg_waiting / (avg_service + 1e-6):.2f}")
    
    return {
        'sla_miss_rate': sla_miss_rate,
        'sla_by_priority': sla_by_priority,
        'completion_time': completion_time,
        'sla_deadline': sla_deadline
    }

def analyze_bottlenecks(log, df_log, df_resources):
    """
    Compute specialist concentration, queue depth, absence-impact simulation.
    """
    
    # Resource similarity network (working-together)
    working_together = pm4py.discover_working_together_network(log)
    
    # Specialist concentration per activity (Herfindahl)
    activity_skill_map = {
        'Eligibility Review': 'Eligibility',
        'Technical Diagnosis': 'Diagnosis',
        'Customer Negotiation': 'Negotiation',
        'Security Review': 'Security',
        'Final Approval': 'Approval',
        'Quality Check': 'Quality',
        'Rework Correction': 'Rework'
    }
    
    herfindahl_by_activity = {}
    for activity, skill in activity_skill_map.items():
        activity_df = df_log[df_log['concept:name'] == activity]
        if len(activity_df) > 0:
            resource_shares = activity_df['org:resource'].value_counts() / len(activity_df)
            herfindahl = (resource_shares ** 2).sum()
            herfindahl_by_activity[activity] = herfindahl
    
    # Queue depth for bottleneck activities
    bottleneck_activities = ['Security Review', 'Final Approval']
    queue_depth = {}
    for activity in bottleneck_activities:
        activity_df = df_log[df_log['concept:name'] == activity]
        if 'waiting_time' in activity_df.columns:
            avg_wait_h = (activity_df['waiting_time'].mean() / np.timedelta64(1, 'h'))
            queue_depth[activity] = avg_wait_h
    
    # Absence-impact simulation
    cross_functional = {}
    for resource in df_resources.index:
        skills_2_plus = (df_resources.loc[resource, ['Eligibility', 'Diagnosis', 'Negotiation', 'Security', 'Approval', 'Quality', 'Rework']] >= 2).sum()
        cross_functional[resource] = skills_2_plus > 1
    
    cross_functional_pct = sum(cross_functional.values()) / len(cross_functional)
    
    print(f"\n=== BOTTLENECK & RESILIENCE ===")
    print(f"Specialist Concentration (Herfindahl) by Activity:")
    for activity, h in sorted(herfindahl_by_activity.items(), key=lambda x: x[1], reverse=True):
        status = " BOTTLENECK" if h > 0.65 else " OK" if h < 0.5 else "~ MODERATE"
        print(f"  {activity}: {h:.3f} {status}")
    
    if queue_depth:
        print(f"Queue Depth (avg waiting time) by Activity:")
        for activity, depth in queue_depth.items():
            print(f"  {activity}: {depth:.2f}h")
    
    print(f"Cross-Functional Capability: {cross_functional_pct:.2%}")
    
    return {
        'herfindahl_by_activity': herfindahl_by_activity,
        'queue_depth': queue_depth,
        'cross_functional': cross_functional,
        'working_together_net': working_together
    }

def analyze_rework(df_log):
    """
    Compute rework rate, rework by reassignment count, appeal rate, quality-check pass rate.
    """
    
    # Rework cases (has Rework Correction activity)
    rework_cases = df_log[df_log['concept:name'] == 'Rework Correction']['case:concept:name'].unique()
    rework_rate = len(rework_cases) / df_log['case:concept:name'].nunique()
    
    # Rework by reassignment count
    all_cases = df_log.drop_duplicates('case:concept:name')[['case:concept:name', 'reassignment_count']]
    rework_by_reassign = all_cases.copy()
    rework_by_reassign['has_rework'] = rework_by_reassign['case:concept:name'].isin(rework_cases).astype(int)
    rework_by_reassign_rate = rework_by_reassign.groupby('reassignment_count')['has_rework'].apply(
        lambda x: x.sum() / len(x) if len(x) > 0 else 0
    )
    
    # Appeal rate (escalation flag)
    if 'escalation_flag' in df_log.columns:
        appeal_rate = df_log.drop_duplicates('case:concept:name')['escalation_flag'].mean()
    else:
        appeal_rate = 0
    
    # Quality check pass rate
    quality_checks = df_log[df_log['concept:name'] == 'Quality Check']
    if 'activity_outcome' in quality_checks.columns:
        pass_rate = (quality_checks['activity_outcome'] == 'pass').mean()
    else:
        pass_rate = 1.0  # assume pass if no outcome recorded
    
    print(f"\n=== REWORK & QUALITY ===")
    print(f"Overall Rework Rate: {rework_rate:.2%} (Target <5%)")
    print(f"Rework Rate by Reassignment Count:\n{rework_by_reassign_rate}")
    print(f"Appeal Rate: {appeal_rate:.2%} (Target <2%)")
    print(f"Quality Check Pass Rate: {pass_rate:.2%} (Target >95%)")
    
    return {
        'rework_rate': rework_rate,
        'rework_by_reassign': rework_by_reassign_rate,
        'appeal_rate': appeal_rate,
        'pass_rate': pass_rate,
        'rework_cases': rework_cases
    }

def check_policy_compliance(df_log, df_resources, edra_output_path=None):
    """
    Audit assignment log against hard constraints and EDRA recommendations.
    """
    
    violations = []
    
    # Hard constraint 1: No skill 0 assignments
    skill_zero = df_log[df_log['skill_assigned'] == 0]
    if len(skill_zero) > 0:
        violations.append(f"Skill 0 assignments: {len(skill_zero)} violations")
    
    # Hard constraint 2: Urgent + skill <2 without supervision
    urgent_low_skill = df_log[
        (df_log['case_priority'].isin(['urgent', 'high'])) &
        (df_log['skill_assigned'] < 2) &
        (~df_log.get('supervised_by', pd.isna).fillna(True))
    ]
    if len(urgent_low_skill) > 0:
        violations.append(f"Urgent + skill <2 unupervised: {len(urgent_low_skill)} violations")
    
    # Hard constraint 3: >4 new assignments per resource per batch
    batch_assignments_per_resource = df_log.tail(50).groupby('org:resource').size()
    overloaded = batch_assignments_per_resource[batch_assignments_per_resource > 4]
    if len(overloaded) > 0:
        violations.append(f"Batch limit exceeded: {dict(overloaded)}")
    
    # Hard constraint 4: >15 open cases per resource
    open_cases_violations = df_resources[df_resources['current_open_cases'] > 15]
    if len(open_cases_violations) > 0:
        violations.append(f"Open case limit exceeded: {list(open_cases_violations.index)}")
    
    # EDRA adherence (if reference available)
    adherence = None
    if edra_output_path:
        edra_recs = pd.read_csv(edra_output_path)
        actual = df_log.tail(16).drop_duplicates('case:concept:name')[['case:concept:name', 'org:resource']]
        matches = (edra_recs.set_index('case:concept:name')['assigned_to'] == 
                   actual.set_index('case:concept:name')['org:resource']).mean()
        adherence = matches
    
    print(f"\n=== POLICY COMPLIANCE ===")
    if len(violations) == 0:
        print(" All hard constraints satisfied")
    else:
        print(f" {len(violations)} violations found:")
        for v in violations:
            print(f"  - {v}")
    
    if adherence:
        print(f"EDRA Adherence: {adherence:.2%}")
    
    return {
        'violations': violations,
        'adherence': adherence
    }
