# 1. Equivalence Notions

Let the visible-label abbreviations be:

- \(O\): `Open Case`
- \(A\): `Analyze Revision`
- \(K\): `Check Revision`
- \(P\): `Approve Revision`
- \(R\): `Rework Case`
- \(Z\): `Close Case`

Only complete executions reaching the final marking are considered.

## Visible trace equivalence after hiding `tau`

For a model \(M\), let \(L_v(M)\) be the set of complete firing sequences after projecting away every silent `tau` transition and retaining all visible labels.

Models \(M_1\) and \(M_2\) are visibly trace equivalent iff

\[
L_v(M_1)=L_v(M_2).
\]

Standard trace equivalence observes labels and their positions, not transition identities. Thus two occurrences of `Check Revision` are distinguishable by multiplicity and sequence position, but not by an internal transition identifier. For example, \(AKKZ\) and \(AKZ\) are different traces.

The languages can be characterized directly.

For Model A, one loop execution has language

\[
D=\{AK,KA\}\cdot\{\epsilon,P\}.
\]

Therefore

\[
L_v(A)=
\{O\,d_1\,(R\,d_2)\cdots(R\,d_n)\,Z
\mid n\geq 1,\ d_i\in D\}.
\]

In particular, a trace with \(n\) analyses has exactly \(n\) checks.

For Model B, let

\[
u_n=Aq_1(RAq_2)\cdots(RAq_n),
\qquad q_i\in\{\epsilon,P\}.
\]

Then

\[
L_v(B)=
\{O\,w\,Z \mid w\in \operatorname{shuffle}(K,u_n),\ n\geq1\}.
\]

Here `shuffle` inserts the single \(K\) at any event boundary while preserving the order of \(u_n\). Every complete Model B trace has exactly one check.

## Bounded visible-language equivalence under P3

Define

\[
L_{P3}(M)=
\{t\in L_v(M)\mid |t|\leq12,\ \#_A(t)\leq3\}.
\]

The length includes `Open Case`, `Close Case`, approvals, checks, analyses, and reworks. Silent transitions do not contribute.

Models are P3-equivalent iff

\[
L_{P3}(A)=L_{P3}(B).
\]

This remains label-based trace equality; internal transition identity is ignored. Equality under this bound would be testing evidence only, not proof of equality outside the bound. Conversely, one bounded counterexample is sufficient to prove both bounded and unbounded non-equivalence.

## Business-relevant equivalence under P1

For P1, `Rework Case` partitions the execution into analysis-attempt segments. A check can be assigned to an analysis only if it occurs in the same segment, before that segment ends in the next `Rework Case` or `Close Case`. One check cannot be assigned to multiple analyses.

The P1 observation retains:

- segment boundaries induced by `Rework Case`;
- analysis and check multiplicities per segment;
- the visible number and placement of approvals;
- `Open Case` and `Close Case`;
- no silent transitions.

Two models are P1-equivalent iff they admit the same audit-relevant observations and guarantee an assignable check for every analysis attempt.

This definition permits a check to occur before or after its analysis inside the same segment because P1 only explicitly requires it before the next rework or close. If the business additionally requires “analyze, then check,” Model A would also need refinement.

## Abstracted dashboard equivalence under P2

For a complete visible trace \(t\), define

\[
\alpha_{P2}(t)=
(\text{first}=O,\ \text{last}=Z,\ \#_A(t),\
\mathbf{1}_{\#_K(t)>0},\
\mathbf{1}_{\#_R(t)>0}).
\]

`Approve Revision` and `tau` are hidden. Check multiplicity is collapsed to a Boolean, and the internal ordering of analyses, checks, and reworks is not recorded beyond the stated counters and flags.

Two models are P2-equivalent iff their sets of abstract observations are equal:

\[
\alpha_{P2}(L_v(A))=\alpha_{P2}(L_v(B)).
\]

For both models this abstract language is exactly

\[
\{(O,Z,n,\text{true},n>1)\mid n\geq1\}.
\]

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The parallel `Analyze Revision`/`Check Revision` block and optional approval are inside the loop body. | Only analysis and optional approval are in the loop; one check is parallel to the entire loop. | A creates one check per attempt. B creates one check per complete case. |
| Analysis and rework counts | \(n\geq1\) analyses and exactly \(n-1\) reworks. | Same. | The models agree on these counts, including whether any rework occurred. |
| Minimum Check Revision occurrences | 1 | 1 | Both satisfy the dashboard requirement that some check occurs. |
| Maximum Check Revision occurrences | Unbounded; exactly one per analysis attempt. | Exactly 1. | Any Model A trace with multiple attempts has more checks than any Model B trace. |
| Possible Check Revision placement | In each attempt, before or after that attempt’s analysis, but after the preceding rework and before its approval and following rework/close. | Anywhere within the outer parallel region: before the first analysis, between analysis and approval, around a rework, or after the final analysis/approval. | B can leave an attempt without a check in its rework-delimited segment. B can also approve before its single check. |
| Optional approval occurrences | Each attempt independently contributes zero or one approval; with \(n\) attempts there are 0 through \(n\) approvals. Approval follows both the analysis and check of that attempt. | Each attempt independently contributes zero or one approval; with \(n\) attempts there are 0 through \(n\) approvals. Approval follows its analysis, but the outer check may occur before or after it. | Approval counts can agree, but approval/check ordering differs. |
| Concurrency | Analysis and check are concurrent separately in every loop execution. | The single check is concurrent with the entire loop, including analyses, approvals, and reworks. | The concurrency scopes are behaviorally different even though both trees contain a parallel operator. |
| Join before Close Case | The loop must finish before close; all checks belonging to completed attempts have already finished. | The outer parallel join waits for both the single check and the entire loop before close. | Both force at least one check before close, but only A forces one in every attempt segment. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 — operational compliance | not equivalent | High | Model A has one check in every rework-delimited attempt. Model B has only one check for the entire case and admits multi-attempt executions with unchecked segments. Approval/check placement also differs. | Model A allows the check before the analysis. If compliance means “analysis must finish before checking,” neither original exactly satisfies it. |
| P2 — executive dashboard | equivalent only under stated abstraction | High | Both abstract to exactly one or more analyses, some check, and `any rework = true` iff there is more than one analysis. Approval and check multiplicity are hidden. | This does not imply visible trace equivalence or operational substitutability. |
| P3 — bounded testing | not equivalent | High | Counterexamples in both directions have at most 12 visible events and at most three analyses. | Had the bounded sets been equal, that would not prove unbounded equivalence. Here bounded inequality is already conclusive. |

# 4. Counterexample Traces

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---:|---:|---|---|
| A-only-1 | `Open Case  Analyze Revision  Check Revision  Rework Case  Check Revision  Analyze Revision  Close Case` | Yes | No | The second `Check Revision` is required by A’s second loop execution, but B’s check branch executes only once. | P1, P3 |
| A-only-2 | `Open Case  Check Revision  Analyze Revision  Approve Revision  Rework Case  Analyze Revision  Check Revision  Close Case` | Yes | No | Again there are two checks, one in each attempt; B has exactly one globally. | P1, P3 |
| B-only-1 | `Open Case  Check Revision  Analyze Revision  Rework Case  Analyze Revision  Close Case` | No | Yes | B can finish two attempts with one global check. A cannot finish the second attempt without another check. | P1, P3 |
| B-only-2 | `Open Case  Analyze Revision  Approve Revision  Check Revision  Close Case` | No | Yes | In B, the loop can perform analysis and approval while the concurrent check is delayed. In A, approval is enabled only after both analysis and check complete. | P1, P3 |

These witnesses also prove that neither visible language includes the other.

The `X('Approve Revision', tau)` choice is made independently on each loop execution:

- choosing `Approve Revision` contributes a visible event;
- choosing `tau` contributes no visible event and does not indicate an incomplete execution;
- hiding `tau` can cause multiple internal executions to map to the same visible trace.

Both models permit between zero and \(n\) visible approvals for \(n\) attempts. The difference is placement relative to the check. P1 and P3 retain approvals, so `B-only-2` remains decisive. P2 hides approvals and check placement, so this distinction disappears under that abstraction.

# 5. Bounded Comparison Code

The following code performs exhaustive bounded state-space exploration. It does not use random playout. States are deduplicated only when both the current marking and visible trace prefix agree, so alternative silent paths to the same observable state are safely merged.

```python
from collections import deque
import pm4py
from pm4py.objects.petri_net.obj import Marking

MODEL_A = """
->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
"""

MODEL_B = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)
"""

tree_a = pm4py.parse_process_tree(MODEL_A)
tree_b = pm4py.parse_process_tree(MODEL_B)

net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

sound_a_result = pm4py.check_soundness(
    net_a, im_a, fm_a, print_diagnostics=True
)
sound_b_result = pm4py.check_soundness(
    net_b, im_b, fm_b, print_diagnostics=True
)

def sound_status(result):
    # Accommodates PM4Py versions returning either bool or a tuple
    # whose first component is the Boolean status.
    if isinstance(result, tuple):
        return bool(result[0])
    return bool(result)

sound_a = sound_status(sound_a_result)
sound_b = sound_status(sound_b_result)

print("Model A sound:", sound_a)
print("Model B sound:", sound_b)

if not sound_a or not sound_b:
    raise RuntimeError("Exploration aborted because a converted net is unsound.")


def fire_transition(marking, transition):
    """
    Fires an enabled transition in an ordinary weighted Petri net.
    Process-tree conversion produces ordinary arcs, so reset and
    inhibitor semantics are not needed here.
    """
    result = Marking(marking)

    for arc in transition.in_arcs:
        place = arc.source
        weight = getattr(arc, "weight", 1)
        result[place] -= weight
        if result[place] == 0:
            del result[place]

    for arc in transition.out_arcs:
        place = arc.target
        weight = getattr(arc, "weight", 1)
        result[place] += weight

    return result


def exhaustive_bounded_visible_language(
    net,
    initial_marking,
    final_marking,
    max_visible_events=12,
    max_analyze_events=3,
):
    """
    Exhaustively enumerates complete visible traces satisfying the bounds.

    Important details:
      * transitions with label None are silent;
      * silent transitions do not consume the visible-length budget;
      * visible transitions beyond either bound are not followed;
      * a trace is accepted only when marking == final_marking;
      * repeated (marking, visible-prefix) states are merged;
      * final markings are not expanded further.
    """
    ordered_places = sorted(net.places, key=lambda p: str(p.name))
    place_index = {place: i for i, place in enumerate(ordered_places)}

    def marking_key(marking):
        return tuple(
            sorted(
                (place_index[place], int(tokens))
                for place, tokens in marking.items()
                if tokens
            )
        )

    queue = deque()
    queue.append((Marking(initial_marking), tuple(), 0))

    seen = {
        (marking_key(initial_marking), tuple())
    }
    complete_traces = set()

    while queue:
        marking, visible_trace, analyze_count = queue.popleft()

        # Explicit final-marking equality, not subset or coverability.
        if marking == final_marking:
            complete_traces.add(visible_trace)
            continue

        enabled = pm4py.get_enabled_transitions(net, marking)
        enabled = sorted(
            enabled,
            key=lambda t: (
                "" if t.label is None else str(t.label),
                str(t.name),
            ),
        )

        for transition in enabled:
            label = transition.label

            if label is None:
                next_trace = visible_trace
                next_analyze_count = analyze_count
            else:
                if len(visible_trace) + 1 > max_visible_events:
                    continue

                next_analyze_count = (
                    analyze_count
                    + (1 if label == "Analyze Revision" else 0)
                )
                if next_analyze_count > max_analyze_events:
                    continue

                next_trace = visible_trace + (label,)

            next_marking = fire_transition(marking, transition)
            state_key = (marking_key(next_marking), next_trace)

            if state_key not in seen:
                seen.add(state_key)
                queue.append(
                    (next_marking, next_trace, next_analyze_count)
                )

    return complete_traces


traces_a = exhaustive_bounded_visible_language(
    net_a, im_a, fm_a,
    max_visible_events=12,
    max_analyze_events=3,
)
traces_b = exhaustive_bounded_visible_language(
    net_b, im_b, fm_b,
    max_visible_events=12,
    max_analyze_events=3,
)

only_a = traces_a - traces_b
only_b = traces_b - traces_a

def print_trace_set(title, traces):
    print("\n" + title)
    if not traces:
        print("  <none>")
        return
    for trace in sorted(traces, key=lambda x: (len(x), x)):
        print("  " + " -> ".join(trace))

print("\nMethod: exhaustive bounded marking exploration; no random playout.")
print("Bounded complete traces in Model A:", len(traces_a))
print("Bounded complete traces in Model B:", len(traces_b))
print("P3 equivalent:", traces_a == traces_b)

print_trace_set("Traces unique to Model A:", only_a)
print_trace_set("Traces unique to Model B:", only_b)
```

The exploration is exhaustive for the stated bounds. A plain `pm4py.play_out(...)` run would not be exhaustive unless a specific exhaustive playout variant and its termination guarantees were established; ordinary randomized playout can miss low-probability or long traces.

# 6. Stochastic and Footprint Comparison

## Footprints

`pm4py.discover_footprints(...)` can compare activities, start/end activities, and pairwise causal, parallel, and choice relations.

```python
# Continuing from the objects constructed in Section 5.

footprints_a = pm4py.discover_footprints(tree_a)
footprints_b = pm4py.discover_footprints(tree_b)

print("Footprints equal:", footprints_a == footprints_b)

all_keys = sorted(
    set(footprints_a.keys()) | set(footprints_b.keys()),
    key=str,
)

for key in all_keys:
    value_a = footprints_a.get(key)
    value_b = footprints_b.get(key)
    if value_a != value_b:
        print(f"Footprint difference for {key!r}:")
        print("  Model A:", value_a)
        print("  Model B:", value_b)
```

Footprints may expose the different concurrency scopes, particularly relations involving `Check Revision`, `Rework Case`, and `Approve Revision`. They are still pairwise abstractions. They generally do not preserve:

- occurrence counts;
- the fact that a relation must hold once per loop iteration;
- arbitrary long-range ordering constraints;
- the complete language of repeated-label traces.

Consequently, equal footprints would not establish trace equivalence. Unequal footprints are useful evidence of a difference, but equal footprints are only a coarse necessary consistency check.

## Stochastic languages and Earth Mover’s Distance

The process trees specify nondeterministic control flow, not probabilities. In particular, no probability is given for:

- selecting approval versus `tau`;
- exiting versus repeating the loop;
- choosing an interleaving in a parallel block.

A true stochastic comparison therefore requires declared branch, loop, and scheduling probabilities. Random playout would impose a simulator-specific distribution rather than recover one from the process tree.

The following is a declared diagnostic convention: every distinct P3-bounded trace is inserted once into an event log. The resulting empirical stochastic language is therefore uniform over bounded variants. It is not claimed to be the operational distribution of either model.

```python
# Continuing from Section 5.
from pm4py.objects.log.obj import EventLog, Trace, Event

def one_case_per_variant(variants):
    """
    Deliberately creates a uniform empirical distribution over distinct
    bounded variants: each variant appears exactly once.
    """
    log = EventLog()

    for case_number, variant in enumerate(
        sorted(variants, key=lambda x: (len(x), x))
    ):
        case = Trace(
            attributes={"concept:name": f"case-{case_number}"}
        )
        for activity in variant:
            case.append(Event({"concept:name": activity}))
        log.append(case)

    return log

bounded_log_a = one_case_per_variant(traces_a)
bounded_log_b = one_case_per_variant(traces_b)

stochastic_language_a = pm4py.get_stochastic_language(bounded_log_a)
stochastic_language_b = pm4py.get_stochastic_language(bounded_log_b)

emd = pm4py.compute_emd(
    stochastic_language_a,
    stochastic_language_b,
)

print("Declared distribution: uniform over distinct P3-bounded traces")
print("Bounded stochastic-language size A:", len(stochastic_language_a))
print("Bounded stochastic-language size B:", len(stochastic_language_b))
print("EMD:", emd)
```

A low EMD would mean that, under the declared distribution and distance metric, probability mass can be moved between similar traces at low cost. It would not establish trace equivalence:

- unsupported traces can carry little probability;
- sampling can fail to observe valid traces;
- similar but unequal traces may have a small edit distance;
- EMD compares weighted distributions, not exact support equality.

# 7. Complexity Comparison

The following counts use the syntactic process tree as written:

- every operator and leaf is one node;
- the root has edge-depth 0;
- duplicate-label count is \(\sum_\ell \max(0,\operatorname{count}(\ell)-1)\) over visible leaf labels.

| Structural metric | Model A | Model B |
|---|---:|---:|
| Total process-tree nodes | 12 | 12 |
| Operator nodes | 5 | 5 |
| Leaf nodes | 7 | 7 |
| Visible leaves | 6 | 6 |
| Silent leaves | 1 | 1 |
| Duplicate visible-leaf-label excess | 0 | 0 |
| Maximum edge-depth | 4 | 5 |
| Maximum node levels, counting root | 5 | 6 |

The duplicate-label count is zero because each visible activity appears in only one syntactic leaf. Dynamic repetitions arise from the loop, not from duplicate leaves.

Thus neither original is smaller by node count. Model B is syntactically deeper because its optional-approval choice is nested under sequence, loop, and outer parallel operators.

```python
from collections import Counter
import pm4py

def process_tree_counts(root):
    labels = []
    operator_nodes = 0
    silent_leaves = 0
    total_nodes = 0
    max_depth = 0

    stack = [(root, 0)]

    while stack:
        node, depth = stack.pop()
        total_nodes += 1
        max_depth = max(max_depth, depth)

        children = list(getattr(node, "children", None) or [])

        if children:
            operator_nodes += 1
            for child in children:
                stack.append((child, depth + 1))
        else:
            label = getattr(node, "label", None)
            if label is None:
                silent_leaves += 1
            else:
                labels.append(label)

    frequencies = Counter(labels)
    duplicate_excess = sum(
        max(0, count - 1)
        for count in frequencies.values()
    )

    return {
        "total_nodes": total_nodes,
        "operator_nodes": operator_nodes,
        "leaf_nodes": len(labels) + silent_leaves,
        "visible_leaves": len(labels),
        "silent_leaves": silent_leaves,
        "duplicate_visible_label_excess": duplicate_excess,
        "max_edge_depth": max_depth,
        "max_levels": max_depth + 1,
        "visible_label_frequencies": dict(frequencies),
    }

print("Model A tree counts:", process_tree_counts(tree_a))
print("Model B tree counts:", process_tree_counts(tree_b))


def petri_metrics(net, im, fm):
    return {
        "places": len(net.places),
        "transitions": len(net.transitions),
        "silent_transitions": sum(
            1 for transition in net.transitions
            if transition.label is None
        ),
        "arcs": len(net.arcs),
        "simplicity": pm4py.simplicity_petri_net(net, im, fm),
    }

petri_a = petri_metrics(net_a, im_a, fm_a)
petri_b = petri_metrics(net_b, im_b, fm_b)

print("Model A Petri metrics:", petri_a)
print("Model B Petri metrics:", petri_b)

if petri_a["simplicity"] > petri_b["simplicity"]:
    print("Model A has the higher PM4Py Petri-net simplicity score.")
elif petri_b["simplicity"] > petri_a["simplicity"]:
    print("Model B has the higher PM4Py Petri-net simplicity score.")
else:
    print("The PM4Py Petri-net simplicity scores are equal.")
```

Petri-net place, transition, arc, and simplicity values should be measured rather than inferred from tree node count. They can depend on the PM4Py conversion implementation and version. Under PM4Py’s normalized simplicity measure, a higher score denotes greater simplicity.

# 8. Simplified Model

P2 is the most appropriate target for simplification because it explicitly discards check multiplicity, approval behavior, and detailed interleaving. A compact representative is:

```text
->(
  'Open Case',
  'Check Revision',
  *(
    'Analyze Revision',
    'Rework Case'
  ),
  'Close Case'
)
```

Its complete visible language is

\[
\{O\,K\,A\,(R\,A)^{n-1}\,Z\mid n\geq1\}.
\]

Its concrete ordering is intentionally only one representative of each P2 dashboard observation.

```python
import pm4py

SIMPLIFIED_TREE = """
->(
  'Open Case',
  'Check Revision',
  *(
    'Analyze Revision',
    'Rework Case'
  ),
  'Close Case'
)
"""

simplified_model = pm4py.parse_process_tree(SIMPLIFIED_TREE)

simplified_net, simplified_im, simplified_fm = (
    pm4py.convert_to_petri_net(simplified_model)
)

simplified_sound = pm4py.check_soundness(
    simplified_net,
    simplified_im,
    simplified_fm,
    print_diagnostics=True,
)

print("Simplified model soundness:", simplified_sound)
print(
    "Simplified Petri-net simplicity:",
    pm4py.simplicity_petri_net(
        simplified_net,
        simplified_im,
        simplified_fm,
    ),
)
```

The simplification has:

| Metric | Model A | Model B | Simplified |
|---|---:|---:|---:|
| Total tree nodes | 12 | 12 | 7 |
| Operator nodes | 5 | 5 | 2 |
| Visible leaves | 6 | 6 | 5 |
| Silent leaves | 1 | 1 | 0 |
| Maximum edge-depth | 4 | 5 | 2 |
| Duplicate visible-label excess | 0 | 0 | 0 |

It is therefore structurally simpler than both originals, not merely diagrammatically different.

## Preservation table

| Property | Status | Explanation |
|---|---|---|
| `Open Case` first and `Close Case` last | exact | Preserved directly by the outer sequence. |
| At least one analysis | exact | The loop body executes once before exit. |
| At least one check | exact | Exactly one check is executed. |
| Number of analyses | exact | Every \(n\geq1\) remains possible. |
| Rework count \(=n-1\) | exact | The binary loop retains the same analysis/rework relation. |
| P2 Boolean “any rework” | exact | It is false for \(n=1\) and true for \(n>1\). |
| P2 Boolean “a check occurred” | exact | Always true in all three models. |
| Check multiplicity | abstracted | Model A’s repeated checks are represented by one check. |
| Analysis/check interleaving | abstracted | The simplified model fixes check before analysis because P2 does not observe the ordering. |
| Optional approvals | lost | They are removed because P2 hides them. |
| P1 per-attempt compliance | weakened | Only one global check remains, so repeated attempts do not each receive a check. |
| P3 visible language | lost | Approval traces, alternative check placements, and repeated checks are not preserved. |

## Regression traces

| Trace | Expected result | P2 observation |
|---|---|---|
| `Open Case  Check Revision  Analyze Revision  Close Case` | Accepted | 1 analysis, check=true, rework=false |
| `Open Case  Check Revision  Analyze Revision  Rework Case  Analyze Revision  Close Case` | Accepted | 2 analyses, check=true, rework=true |
| `Open Case  Check Revision  Analyze Revision  Rework Case  Analyze Revision  Rework Case  Analyze Revision  Close Case` | Accepted | 3 analyses, check=true, rework=true |

## Negative traces

| Trace | Expected result | Reason |
|---|---|---|
| `Open Case  Check Revision  Close Case` | Rejected | No analysis occurred. |
| `Open Case  Check Revision  Analyze Revision  Rework Case  Close Case` | Rejected | Under binary-loop semantics, a rework must be followed by another analysis before exit. |
| `Check Revision  Open Case  Analyze Revision  Close Case` | Rejected | `Open Case` is not first. |

Concrete original traces with a different analysis/check ordering need not be accepted by the simplified model. Preservation is equality of P2 abstract languages, not equality of concrete trace languages.

# 9. Final Recommendation

| Business view | Suitable original model | Recommendation |
|---|---|---|
| P1 operational compliance | Model A, subject to the stated interpretation | Use A if a check may occur before or after its analysis within the same rework-delimited attempt. If checking must follow analysis, replace the parallel block with a sequence `Analyze Revision  Check Revision`. Do not use B as a compliance guarantee for repeated attempts. |
| P2 executive dashboard | Both A and B | They are equivalent under P2. Prefer the simplified model as a reporting or dashboard model because it preserves the exact P2 abstract language with 7 rather than 12 tree nodes. |
| P3 bounded testing | Neither is a substitute for the other | The bounded languages already differ in both directions. Select A when the intended requirement is one check per attempt; select B only when one case-level check concurrent with the whole revision process is intended. |

The simplified model should replace neither original as an operational executable specification. It may replace either one only in the P2 reporting layer, where approvals, check multiplicity, and detailed ordering are deliberately unobservable.

Finally, bounded exploration has asymmetric evidential force: finding a bounded counterexample conclusively disproves equivalence, as it does here; finding no bounded counterexample would not prove unbounded equivalence.
