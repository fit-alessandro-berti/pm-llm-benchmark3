# 1. Objectives and constraints

## Optimization Objectives (Soft Constraints)
1. **Throughput**: Minimize average case cycle time while respecting SLA deadlines.
2. **Skill Development**: Allocate 20% of normal/low-priority cases to support documented training priorities.
3. **Workload Fairness**: Distribute assignments to avoid overloading any single resource or team.
4. **Continuity of Case Ownership**: Prefer keeping cases with their current owner when handover costs are high.
5. **SLA Risk Mitigation**: Prioritize cases with imminent deadlines or high priority.
6. **Resilience**: Avoid creating single points of failure (e.g., specialist bottlenecks).
7. **Error/Rework Reduction**: Minimize skill mismatches and reassignments.

## Hard Constraints (Safety/Compliance)
1. **Skill Requirements**:
   - Security Review: Skill level 3, or level 1-2 only under supervision by R7_Gita/R8_Hugo.
   - Final Approval: Skill level 2-3. Level 1 may prepare but not finalize.
   - No high-priority case assigned to skill level <2 unless supervised.
2. **Overtime Risk**: Avoid assigning to "high" overtime-risk resources unless SLA risk is urgent and no safer alternative exists.
3. **Batch Processing**: Quality Check may be batched only if priority is normal/low and SLA time remaining >24h.
4. **Reassignment Limits**: No resource should receive >4 new assignments in the current batch.
5. **Handover Costs**: For high-complexity cases with high handover cost, prefer continuity unless current owner has skill 0/1 and no supervision is feasible.

# 2. Assignment Policy

### Pseudocode Algorithm
```python
def assign_cases(cases, resources, skill_matrix, constraints):
    # Preprocessing
    cases = sort_by_urgency(cases)  # Urgent > High > Normal > Low
    eligible_resources = filter_eligible_resources(resources, skill_matrix, constraints)
    assignments = []

    for case in cases:
        # Step 1: Filter eligible resources
        candidates = []
        for resource in eligible_resources:
            if not is_eligible(resource, case, skill_matrix, constraints):
                continue
            if resource.new_assignments >= 4:
                continue  # Fairness constraint

            # Step 2: Score candidates
            score = calculate_score(resource, case, skill_matrix, constraints)
            candidates.append((resource, score))

        if not candidates:
            # Handle exceptions (e.g., escalate or relax constraints)
            assignment = handle_exception(case, resources, constraints)
        else:
            # Step 3: Select best candidate
            best_candidate = max(candidates, key=lambda x: x[1])
            assignment = best_candidate[0]

            # Step 4: Update resource state
            assignment.new_assignments += 1
            assignment.current_open_cases += 1
            assignment.hours_remaining -= estimate_effort(case)

        assignments.append((case, assignment, get_assignment_reason(case, assignment)))

    return assignments

def calculate_score(resource, case, skill_matrix, constraints):
    score = 0

    # SLA Urgency (weight: 40%)
    sla_score = min(1, max(0, 1 - (case.sla_remaining / 48)))  # Normalize to 48h
    if case.priority == "urgent":
        sla_score = 1
    score += 0.4 * sla_score

    # Skill Match (weight: 30%)
    skill_level = skill_matrix[resource][case.required_skill]
    if skill_level == 3:
        skill_score = 1.0
    elif skill_level == 2:
        skill_score = 0.8
    elif skill_level == 1:
        skill_score = 0.5 if case.priority in ["normal", "low"] else 0.0  # No level 1 for high/urgent
    else:
        skill_score = 0.0
    score += 0.3 * skill_score

    # Continuity (weight: 15%)
    if case.current_owner == resource:
        continuity_score = 1.0
    elif case.handover_cost == "high":
        continuity_score = 0.2  # Penalize handover
    else:
        continuity_score = 0.5
    score += 0.15 * continuity_score

    # Workload Fairness (weight: 10%)
    workload_score = 1 - min(1, resource.current_open_cases / 15)  # Normalize to max 15 cases
    if resource.overtime_risk == "high" and case.priority not in ["urgent", "high"]:
        workload_score *= 0.5  # Penalize high-risk resources
    score += 0.1 * workload_score

    # Training (weight: 5%)
    if case.priority in ["normal", "low"] and resource.training_priority == case.required_skill:
        training_score = 1.0
    else:
        training_score = 0.0
    score += 0.05 * training_score

    return score
```

### Key Components:
1. **Eligibility Filtering**:
   - Remove resources with skill level 0 or insufficient skill for high-priority cases.
   - Enforce supervision rules (e.g., Security Review with skill 1-2).
   - Exclude resources with >4 new assignments.

2. **Scoring**:
   - **SLA Urgency**: Higher weight for urgent/high-priority cases.
   - **Skill Match**: Prefer specialists (level 3) but allow competent (level 2) for normal/low-priority.
   - **Continuity**: Penalize handover for high-complexity/high-cost cases.
   - **Workload Fairness**: Avoid overloading resources, especially those with high overtime risk.
   - **Training**: Allocate 20% of normal/low-priority cases to training priorities.

3. **Tie-Breaking**:
   - If scores are equal, prefer:
     1. Resources with fewer open cases.
     2. Resources with higher skill level.
     3. Resources with lower overtime risk.

4. **Exception Handling**:
   - If no eligible resource, relax constraints in this order:
     1. Allow skill level 1 for normal/low-priority cases (with supervision if required).
     2. Assign to high-overtime-risk resource if SLA is urgent.
     3. Escalate to supervisor.

# 4. Comparison with Baseline Policies

| Metric                     | Proposed Policy                          | First-Available Routing               | Specialist-Only Routing               |
|----------------------------|------------------------------------------|---------------------------------------|---------------------------------------|
| **Throughput**             | Balanced (prioritizes urgent cases)      | High (minimizes waiting)              | Low (bottlenecks at specialists)      |
| **SLA Risk**               | Low (urgent cases prioritized)           | Medium (may delay urgent cases)       | High (specialists become bottlenecks) |
| **Error/Rework Risk**      | Low (skill matching + continuity)        | High (skill mismatches, reassignments)| Low (highest skill)                   |
| **Fairness of Workload**   | High (limits per resource, avoids overload) | Low (overloads available resources)   | Low (overloads specialists)           |
| **Skill Development**      | High (20% training cases)                | Low (ignores training)                | Low (ignores training)                |
| **Continuity**             | High (prefers current owner)             | Low (ignores handover cost)           | Medium (depends on specialist)        |
| **Resilience**             | High (avoids specialist bottlenecks)     | Medium (depends on availability)      | Low (single points of failure)        |

### Trade-offs:
- **Proposed Policy**:
  - Sacrifices some throughput for fairness, skill development, and continuity.
  - Accepts minor skill mismatches for training (e.g., C003, C015).
  - Avoids overloading high-overtime-risk resources (e.g., R2_Bruno, R4_David).
- **First-Available**:
  - Maximizes throughput but increases rework and skill mismatches.
  - Ignores training and continuity, leading to higher long-term costs.
- **Specialist-Only**:
  - Minimizes errors but creates queues (e.g., Security Review, Final Approval).
  - Poor resilience (e.g., if R8_Hugo is absent, Security Review stalls).

# 5. Explanation to Workers

**Why Your Assignments Matter**

Every day, we balance several goals to keep our work fair, efficient, and high-quality. Here’s how assignments are made:

1. **Urgent Cases First**:
   - If a case is marked "urgent" or has a tight deadline (like C001 or C011), it gets priority. This helps us meet SLAs and keep customers happy.

2. **Skill Matching**:
   - We try to match cases to your strongest skills (e.g., R8_Hugo for Security Review). For normal/low-priority cases, we may assign work slightly outside your comfort zone to help you grow—this is part of our training goals.

3. **Continuity**:
   - If you’ve worked on a case before (like R3_Celine on C007), we’ll usually keep it with you unless there’s a good reason not to. This avoids handover delays and reduces errors.

4. **Fair Workloads**:
   - We limit how many new cases you get at once to avoid burnout. If you’re flagged as "high overtime risk" (like R2_Bruno or R4_David), we’ll be extra careful not to overload you unless the case is urgent.

5. **Training Opportunities**:
   - About 20% of normal/low-priority cases are assigned to help you develop new skills (e.g., R10_Jonas learning Security Review with R8_Hugo’s supervision). This helps us build a more flexible team.

6. **Teamwork**:
   - Some cases require supervision (e.g., Security Review by trainees). This ensures quality while giving you a chance to learn from experts like R7_Gita or R8_Hugo.

**What This Means for You**:
- You might see cases that aren’t your "usual" work—this is intentional to help you grow.
- If you’re feeling overloaded, let your supervisor know. We monitor workloads and can adjust.
- If you’re assigned a case you’re not confident about, ask for guidance. We’d rather help you succeed than risk errors.

# 7. PM4Py Implementation Sketch

```python
import pm4py
from pm4py.objects.log.util import dataframe_utils
from pm4py.objects.conversion.log import converter as log_converter

# Load and preprocess event log
log = pm4py.read_xes("process_log.xes")
df = pm4py.convert_to_dataframe(log)
df = pm4py.format_dataframe(df, case_id="case:concept:name", activity_key="concept:name", timestamp_key="time:timestamp")

# 1. Discover handover of work network (for continuity analysis)
handover_network = pm4py.discover_handover_of_work_network(df)
pm4py.view_sna(handover_network)

# 2. Discover working-together network (for workload fairness)
working_together_network = pm4py.discover_working_together_network(df)
pm4py.save_vis_sna(working_together_network, "working_together.png")

# 3. Calculate service/waiting times (for SLA risk)
df_with_waiting = pm4py.insert_case_service_waiting_time(df)
service_times = pm4py.get_service_time(df_with_waiting, activity="Security Review")

# 4. Filter cases by priority/SLA risk
urgent_cases = pm4py.filter_event_attribute_values(df, "case_priority", ["urgent"])
high_sla_risk = pm4py.filter_case_performance(df, "SLA_remaining < 4h")

# 5. Discover organizational roles (for skill matching)
roles = pm4py.discover_organizational_roles(df)
resource_similarity = pm4py.discover_activity_based_resource_similarity(df)

# 6. Audit training assignments
training_cases = df[
    (df["priority"].isin(["normal", "low"])) &
    (df["required_skill"] == df["training_priority"])
]
training_share = len(training_cases) / len(df[df["priority"].isin(["normal", "low"])])

# 7. Audit specialist bottlenecks
specialist_activities = ["Security Review", "Final Approval"]
specialist_cases = df[df["concept:name"].isin(specialist_activities)]
bottleneck_metric = specialist_cases.groupby("concept:name")["waiting_time"].mean()

# 8. Audit deviations from policy
deviations = df[
    (df["case_priority"].isin(["high", "urgent"])) &
    (df["skill_level"] < 2) &
    (df["supervision"] != "yes")
]
deviation_rate = len(deviations) / len(df[df["case_priority"].isin(["high", "urgent"])])
```

### Key PM4Py Functions Used:
- **Network Discovery**: `discover_handover_of_work_network`, `discover_working_together_network` for continuity and fairness.
- **Performance Analysis**: `get_service_time`, `insert_case_service_waiting_time` for SLA risk.
- **Filtering**: `filter_event_attribute_values`, `filter_case_performance` for priority/SLA analysis.
- **Organizational Mining**: `discover_organizational_roles`, `discover_activity_based_resource_similarity` for skill matching.
- **Visualization**: `view_sna`, `save_vis_sna` for auditing networks.
