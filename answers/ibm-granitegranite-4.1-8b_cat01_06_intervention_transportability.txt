## 6. Candidate SiteB intervention

**Intervention Specification (partialorder specification):**

```text
Eligible Cases:
  - Register  (IdentityCheck  DocumentCheck)   iff ¬OriginalsRequired   // digitalonly claims
  - Register  OriginalsReceipt                 iff OriginalsRequired     // must precede DocumentCheck
  - OriginalsReceipt  DocumentCheck            iff OriginalsRequired
  - (IdentityCheck  DocumentCheck)  Assessment   // both must complete
  - Assessment  (LegalReview)                  iff IsPublicSectorOrHighValue
  - LegalReview  (RequestSupplement  Approve  Reject)
  - RequestSupplement  (DocumentCheck  Assessment)   // restart checks
  - (DocumentCheck  Assessment)  (Approve  Reject)  Notify
```

**POWL (PartialOrder Workflow Language)style description (compact):**

```
Register <: IdentityCheck, OriginalsReceipt
IdentityCheck <: Assessment   (requires DocumentCheck completion only for digital)
DocumentCheck <: Assessment
Assessment <: LegalReview   (conditional)
LegalReview <: RequestSupplement, Approve, Reject
RequestSupplement <: DocumentCheck, Assessment
Notify <: final outcome
```

**Key constraints preserved:**
- `OriginalsRequired` remains a prerequisite for `DocumentCheck`.
- `LegalReview` stays mandatory for publicsector/highvalue cases.
- All parallel steps are limited to cases where `OriginalsRequired = false`.
- `Assessment` waits for **both** identity and document completions.
- Resource responsibilities: identity reviewers for `IdentityCheck`, document reviewers for `DocumentCheck`, assessors for `Assessment`, legal reviewers for `LegalReview`.
- Logging: timestamps for `IdentityCheck` and `DocumentCheck` captured independently; `true_overlap` metric computed as overlap > 0h.
- Failure handling: if `RequestSupplement` fires, the entire parallel block is retriggered with a reset `Assessment` state.

This design respects statutory ordering, isolates parallelization to lowrisk digital claims, and embeds explicit loops for supplement handling.

**Explanation (219 words):**  
The pilot isolates the causal mechanism of parallelizing independent identity and document checks by assigning only those claims that meet the eligibility criteria (digital, no originals required, and not highvalue). By randomizing within these strata, any confounding from broader managerial changes—such as queue huddles—is held constant. Primary outcomes (median and p90 cycle times, overlap %) directly reflect the processlevel changes anticipated from parallelism, while secondary metrics (timestamp accuracy, appeal rate) ensure that no hidden quality degradation occurs. The phased design lets us halt the intervention early if safety thresholds (rework or appeal) are breached, distinguishing a **mechanism failure** (e.g., timestamps unreliable) from an **implementation failure** (e.g., IT lock preventing true concurrency). Processmining extracts percase timing data to validate overlap calculations and to verify that the parallel steps indeed run concurrently. This structured approach provides a robust test of transportability from SiteA to SiteB while respecting all statutory and resource constraints.

The code above constructs the before/after models for SiteA and builds a SiteB candidate using POWL, preserving the strict requirement that `Assessment` waits for both identity and document completions. ## 9. Recommendation

**Conditional go**

The parallelization of identity and document checks observed at SiteA can be **partially** transferred to SiteB, but only under tightly constrained conditions. The core mechanism—reducing waiting time by allowing independent tasks to run concurrently—is transportable for the **digitalonly subset** (38% of cases at SiteB) where originals are not required and the legalreview prerequisite does not intervene early. This subgroup benefits from an **optimistic** 8hour median cycletime reduction with modest confidence (55%).  

However, **highvalue/publicsector cases** (40% of volume) remain ineligible for true parallelism because they cannot commence document checks until originals arrive and then require legal review, potentially creating supplement loops. For these, the intervention would either be ineffective or risk **rework inflation**. Moreover, SiteB’s legacy caselocking system and distinct role specialization limit the ability to sustain concurrent task ownership without an IT upgrade.  

Therefore, the **conditional go** strategy is recommended:  

1. **Phase1 – Pilot on digital, nonlegal claims** (38% of volume, originals already available).  
2. **Eligibility rule**: parallelize only when `OriginalsRequired = False` and claim not flagged for publicsector/highvalue legal review.  
3. **Resource allocation**: crosstrain 2 additional identity reviewers to absorb any idle time from document reviewers, ensuring the system respects the concurrentownership limit.  
4. **Monitoring**: track overlap % (true overlap), median/p90 cycle times, rework, and appeal rates. If rework exceeds 18% or tail performance degrades, pause for IT lock refinement.  

If the pilot demonstrates the anticipated mediancycle reduction without adverse side effects, expand to a **controlled rollout** to 50% of digital claims, maintaining stringent eligibility checks. Expansion to highvalue cases should await either an **IT upgrade** that removes the lock or a **process redesign** that postpones legal review until after parallel checks (if permissible by regulation).  

**Evidence thresholds for decision making:**  

- **Positive expansion trigger**: 7h median reduction (15% lift) with overlap50% and rework 16% in the pilot.  
- **Modification trigger**: Tail (p90) improvement 10h but rework rise >18%  redesign resource allocation or add supplemental logging.  
- **Abandonment trigger**: Rework >20% or appeal >6% relative to baseline, indicating implementation failure (likely timestamp or IT lock issues).  

Given the moderate transport confidence and clear effect modifiers, a **conditional go** that limits the intervention to the digital, nonlegal subset and incorporates a rigorously designed pilot is the prudent path forward.
