def strict(children, edges):
    try:
        return StrictPartialOrder(children, edges)
    except TypeError:
        spo = StrictPartialOrder()
        for c in children:
            try:
                spo.add_child(c)
            except AttributeError:
                spo.children.append(c)
        for a,b in edges:
            try:
                spo.add_order(a,b)
            except AttributeError:
                spo.order.add((a,b))
        return spo

## 6. Candidate Site B intervention

**Process specification — conditional verification partial-order release with statutory gates and WIP controls**

- **Eligibility rules:** Stage entry by stratum. First: low-complexity digital/no-originals non-legal cases. Second: digital legal-review cases with legal WIP cap. Third: originals-required non-legal cases with validated receipt timestamps. Fourth: originals plus legal-review or supplement-prone/high-complexity cases. Exclude cases with active supplement or known missing originals from initial concurrency expansion.
- **Tasks that may be concurrent:** After Register, `Identity Check` and `Originals Receipt` may be created concurrently for all cases. `Identity Check` and `Document Check` may execute concurrently only when the document artifact is legally available: digital at registration, or originals already received when required. For originals-required cases, `Document Check` must not be created before `Originals Receipt`; it may then overlap with an unfinished `Identity Check`.
- **Mandatory statutory prerequisites:** Register first. Originals receipt before Document Check when legally required. Assessment waits for both Identity Check and Document Check. Public-sector/high-value cases require Legal Review before final decision. Request Supplement returns to Document Check and Assessment before Legal Review/decision. Approve/Reject followed by Notify.
- **Queue and WIP controls:** Role-specific WIP caps: identity 4 open, document 7, assessment 3, legal 2; do not release new verification work when downstream queue exceeds a pre-set threshold or when p90 queue time is trending upward. Separate rework/supplement queue with priority and cap. Daily queue huddles only as review, not as substitute for capacity control.
- **Resource responsibilities:** Identity pool owns identity tasks; document pool owns document tasks; assessors own Assessment; legal reviewers own Legal Review. Do not force cross-training. Optional certified floaters may help simple digital identity/document queues only after pilot evidence.
- **Legal-review and supplement loops:** Legal Review is created only after Assessment for eligible cases. Legal may Approve/Reject or issue Request Supplement. Supplement triggers a prioritized Document Check repeat, Assessment repeat, then Legal Review; the loop count is logged and capped by WIP policy.
- **Logging requirements:** Log task ready/created/started/completed timestamps, owner, role, case lock state, back-entry flag, original receipt timestamp, document availability, WIP level, queue time, legal review/supplement events, and decision/notify. Reconcile any late entry against system events.

Compact POWL-style relation set:

```text

Register < OriginalsReceipt (mandatory if legally required; optional-skip otherwise)
IdentityCheck and OriginalsReceipt may be concurrent after Register
OriginalsReceipt < DocumentCheck (when originals required)
Register < DocumentCheck (only when no originals required and digital document is available)
IdentityCheck < Assessment
DocumentCheck < Assessment
Assessment < LegalReview (if public/high-value)
Assessment < FinalDecision (if no legal review)
LegalReview < FinalDecision
LegalReview < RequestSupplement
RequestSupplement < DocumentCheck_repeat
DocumentCheck_repeat < Assessment_repeat
Assessment_repeat < LegalReview
FinalDecision = X(Approve, Reject)
FinalDecision < Notify
```

The pilot separates mechanism failure from implementation failure by measuring both intermediate process changes and final outcomes. True overlap is measured from system start/end events with lock and back-entry flags, not manual timestamps. Treatment fidelity is checked at task level: identity and originals receipt created concurrently where allowed; document task not created before originals when legally required; assessment waiting for both checks; WIP caps enforced. If fidelity is high but true overlap does not rise, the mechanism failed—e.g., originals delay or role queues. If true overlap rises but cycle time does not, the bottleneck shifted or downstream capacity/rework absorbed the gain. If overlap rises and waiting falls but p90 worsens, queue variance or legal/rework congestion is implicated. Implementation failure appears as treatment flags missing, high back-entry, illegal early Document Check, or overridden WIP caps; these are tracked as deviations and excluded from per-protocol mechanism estimates while retained in intention-to-treat. Stratified effects and negative controls for ineligible cases distinguish transport failure from general time trends.

    SilentTransition = None


def T(label):
    return Transition(label)


def tau():
    if SilentTransition is not None:
        return SilentTransition()
    return Transition("tau")


def strict_partial_order(children, edges):
    try:
        return StrictPartialOrder(children, edges)
    except TypeError:
        spo = StrictPartialOrder()
        for c in children:
            try:
                spo.add_child(c)
            except AttributeError:
                spo.children.append(c)
        for a, b in edges:
            try:
                spo.add_order(a, b)
            except AttributeError:
                spo.order.add((a, b))
        return spo


def operator_powl(kind, children):
    try:
        return OperatorPOWL(kind, children)
    except TypeError:
        return OperatorPOWL(operator=kind, children=children)


def loop_powl(body, redo, exit_node=None):
    # Try PM4Py's common loop signatures. The model remains a sound control-flow
    # approximation; the exact loop arity depends on the installed PM4Py version.
    variants = []
    if exit_node is not None:
        variants.append([body, redo, exit_node])
    variants.append([body, redo])
    last_err = None
    for ch in variants:
        try:
            return OperatorPOWL(PT_Operator.LOOP, ch)
        except TypeError as e1:
            last_err = e1
            try:
                return OperatorPOWL(operator=PT_Operator.LOOP, children=ch)
            except TypeError as e2:
                last_err = e2
    raise last_err

## 9. Recommendation

`conditional go`

Transfer the partial-order principle, not Site A’s blanket “create Identity Check and Document Check simultaneously immediately after Register for every case.” Site B should allow `Identity Check` to run concurrently with `Originals Receipt` for all cases, and allow `Identity Check` and `Document Check` to overlap only when the document artifact is legally available—digital at registration, or originals already received. Never create `Document Check` before statutory originals; never bypass `Legal Review` or the supplement loop. The first subgroup should be low-complexity digital/no-original non-legal cases. Then digital legal cases with legal WIP caps, then originals-required non-legal cases with validated receipt timestamps. High-complexity, originals-plus-legal, and supplement-prone cases should enter last.

Expected benefit is reduced waiting before `Assessment` and some median cycle-time reduction—not Site A’s full nine-hour gain. Risks are false overlap from case locking, bottleneck shift to assessment/legal, increased rework, and tail growth from releasing work in bursts. Use role-specific WIP caps, queue huddles, rework priority, event-level timestamps, and a lock/back-entry flag. Expand only if true overlap rises, waiting before `Assessment` falls, median cycle time improves by at least about 2 hours without p90 worsening, and rework/appeal do not deteriorate. Modify if median improves but p90 or rework worsens: add admission control, separate rework lane, or cap the legal queue. Abandon or restrict if true overlap does not rise despite high treatment fidelity, if document tasks are illegally started, if lock/back-entry prevents trustworthy timing, or if p90 rises by more than about 10 hours or rework rises by more than 3 percentage points with no compensating median gain. Expansion should require replication in the next eligible stratum and process-mining confirmation that the intended partial order—not just timestamp entry—changed.

## 10. Assumption register

1. **True overlap can be measured from system start/end events and lock flags, not only back-entered timestamps** — needed to distinguish real concurrency from recording improvements — test by timestamp audit against system events and sampled screens/logs — if false, the apparent benefit may be a measurement artifact and the pilot cannot identify the mechanism.
2. **Identity and document checks are sufficiently independent when documents are legally available** — needed for concurrency to shorten the critical path — test by process-mining dependency and a small locked-case pilot — if false, parallelization adds coordination without reducing waiting.
3. **Originals Receipt delay is the dominant blocker for 62% of cases and cannot be reduced by verification parallelization alone** — needed to set realistic eligibility and effect sizes — test with survival/queue analysis of original receipt — if false, more benefit is possible, but the intervention should include the receipt process.
4. **Site B IT can release or safely work around the one-active-task lock while preserving auditability** — needed for true simultaneous ownership — test IT workflow, lock-state logs, and back-entry rates — if false, the intervention is largely illusory and system changes are required first.
5. **Assessment and legal capacity may absorb or bottleneck earlier verification releases** — needed to anticipate bottleneck-shift and tail-risk scenarios — test utilization, queue length, and waiting before Assessment/Legal Review — if false, optimistic median and p90 benefits are more plausible.
6. **Legal-review supplement loops and rework can be managed with a priority lane and WIP caps** — needed to prevent tail blow-up in 40% legal cases and 17% rework baseline — test rework queue performance during pilot — if false, restrict legal/supplement-heavy cases and prioritize process redesign before expansion.
7. **Pilot assignment by team/queue is sufficiently isolated to estimate causal effects** — needed to approximate SUTVA and avoid contamination through shared pools — test cross-arm task ownership and shared-resource flows — if false, use stronger cluster/stepped-wedge modeling or separate queues and interpret effects cautiously.
8. **Site A’s observed overlap increase and nine-hour median reduction are confounded and are not identified treatment effects** — needed to avoid overclaiming transportability — test using negative-control processes and timestamp audits — if false, the organization would overestimate expected benefit and set unsafe expansion thresholds.
