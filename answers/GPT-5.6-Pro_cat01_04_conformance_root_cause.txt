## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels
    [Classify renamed to Risk Screen]

policy_change -> true_process
    [Supervisor Sign-off required conditionally]

ETL_change -> recorded_order
    [Decision and Notify ordered by ingestion time]

reviewer_behavior -> true_process
    [Manual Override; possible Compliance Check bypass]

true_process -> recorded_labels
    [executed activities generate observable events]

true_process -> business_outcomes
reviewer_behavior -> business_outcomes

recorded_labels -> alignment_moves
recorded_order -> alignment_moves
normative_model -> alignment_moves
alignment_moves -> measured_fitness

hidden_gateway_configuration -> recorded_labels
    [Queue Routed emitted for most cases]

hidden_extraction_completeness -> recorded_labels
    [missing Compliance Check events and resources]

hidden_high_value_status -> true_process
    [activates the sign-off requirement]

hidden_source_sequence -> recorded_order
    [alternative ordering witness]

policy_change -> hidden_model_version_gap
hidden_model_version_gap -> normative_model
    [old model remains deployed]

hidden_detection_completeness -> business_outcomes
    [confirmed incidents and appeals are imperfectly observed]
```

The pattern is best explained by a causal stack. The May UI release changes the observed symbol, not necessarily the business step: `Classify` becomes `Risk Screen`, creating one move on log and one visible model move until remapped. The June gateway then inserts `Queue Routed`, adding a further log move. From June 15, ingestion-time ordering can place `Notify` before `Decision`; source-sequence sorting removes much of that apparent control-flow violation. These mechanisms jointly explain why fitness rises in stages from 32% to 58%, 81%, and 89% without any comparable discontinuity in approval or appeal outcomes.

August adds a different mechanism. The above-EUR-50,000 sign-off policy changes the intended and apparently executed process, while the frozen model still requires immediate progression to `Decision`. Thus `Supervisor Sign-off` is a genuine move on log under an obsolete model, not evidence of misconduct. An unconditional optional-sign-off model repairs fitness but may accept sign-off in low-value cases and omission in high-value cases.

A residual concern remains: enhanced review followed directly by decision may reflect reviewer bypass, missing `Compliance Check` events, or extraction incompleteness. Increased missing-resource rates make the latter credible, but the supervisor memo and repeated variants keep behavioral noncompliance live. Stable approval and appeal rates weaken a theory of widespread harmful deterioration; they do not identify event truth, may be insensitive to control violations, and are themselves subject to incomplete incident detection. Conformance metrics, source provenance, case attributes, and manual audit must therefore be triangulated.

def normalize_trace(
    trace: str,
    *,
    map_risk_screen: bool = False,
    remove_queue_routed: bool = False,
) -> str:
    """
    Apply only explicitly declared transformations.

    Manual Override is deliberately preserved because the supplied evidence
    describes it as a real user action, not as a technical event.
    """
    activities = [activity.strip() for activity in trace.split(",")]

    if map_risk_screen:
        activities = [
            "Classify" if activity == "Risk Screen" else activity
            for activity in activities
        ]

    if remove_queue_routed:
        activities = [
            activity
            for activity in activities
            if activity != "Queue Routed"
        ]

    return ",".join(activities)


def make_log(
    table: VariantTable,
    *,
    map_risk_screen: bool = False,
    remove_queue_routed: bool = False,
):
    """
    Expand each aggregate count into one trace string per case and then
    construct a PM4Py log/DataFrame using parse_event_log_string().
    """
    traces: List[str] = []

    for trace, count in table:
        if count < 0:
            raise ValueError(f"Negative count for variant {trace!r}")

        normalized_trace = normalize_trace(
            trace,
            map_risk_screen=map_risk_screen,
            remove_queue_routed=remove_queue_routed,
        )
        traces.extend([normalized_trace] * count)

    return pm4py.parse_event_log_string(traces, sep=",")


def move_label(value: Any) -> Any:
    """
    PM4Py versions may expose an alignment side as a label or as a
    (transition_name, transition_label) descriptor.
    """
    if isinstance(value, (tuple, list)):
        if len(value) >= 2:
            return value[1]
        if len(value) == 1:
            return value[0]
    return value


def is_skip(value: Any) -> bool:
    return value is None or value == ">>" or value == "»"


def visible_move_counts(diagnostics) -> Tuple[Counter, Counter]:
    """Count visible moves on log and visible moves on model."""
    log_moves: Counter = Counter()
    model_moves: Counter = Counter()

    for result in diagnostics:
        alignment = result.get("alignment", []) if result else []

        for pair in alignment:
            if not isinstance(pair, (tuple, list)) or len(pair) != 2:
                continue

            log_side = move_label(pair[0])
            model_side = move_label(pair[1])

            if not is_skip(log_side) and is_skip(model_side):
                log_moves[str(log_side)] += 1
            elif is_skip(log_side) and not is_skip(model_side):
                model_moves[str(model_side)] += 1

    return log_moves, model_moves

        initial_marking,
        final_marking,
        multi_processing=False,
    )

    costs = [
        float(result["cost"])
        for result in diagnostics
        if result is not None and result.get("cost") is not None
    ]

    log_moves, model_moves = visible_move_counts(diagnostics)

    report: Dict[str, Any] = {
        "dfg": dfg,
        "start_activities": start_activities,
        "end_activities": end_activities,
        "diagnostics": diagnostics,
        "fitness": fitness,
        "mean_alignment_cost": (
            fmean(costs) if costs else float("nan")
        ),
        "dominant_log_moves": log_moves.most_common(8),
        "dominant_model_moves": model_moves.most_common(8),
    }

    if with_precision:
        report["precision"] = pm4py.precision_alignments(
            log,
            net,
            initial_marking,
            final_marking,
            multi_processing=False,
        )

    return report


def print_report(
    period: str,
    pipeline: str,
    report: Dict[str, Any],
) -> None:
    top_dfg_edges = sorted(
        report["dfg"].items(),

        reverse=True,
    )[:10]

    fitness = report["fitness"]
    fitting_percentage = fitness.get(
        "percentage_of_fitting_traces",
        fitness.get("perc_fit_traces", float("nan")),
    )

    print(f"\n=== {period} | {pipeline} ===")
    print("alignment fitness:", fitness)
    print("fitting traces %:", fitting_percentage)
    print(
        "mean default-cost alignment cost:",
        report["mean_alignment_cost"],
    )
    print("top DFG edges:", top_dfg_edges)
    print(
        "dominant visible moves on log:",
        report["dominant_log_moves"],
    )
    print(
        "dominant visible moves on model:",
        report["dominant_model_moves"],
    )

    if "precision" in report:
        print("alignment precision:", report["precision"])

def order_real_extract_by_source_sequence(
    events: pd.DataFrame,
    sequence_column: str = "source_sequence",

    """

## 7. Provisional conclusion

**Primary explanation — high confidence, 97/100:** The measured collapse is predominantly a measurement and model-governance failure, not a sudden workforce-wide behavioral breakdown. The chronology and staged repairs function as a strong quasi-experiment: mapping `Risk Screen` to `Classify` recovers 26 percentage points of June–July fitness; removing the technical `Queue Routed` event recovers another 23; source-sequence ordering recovers 8 more and nearly restores the April–May baseline. In August–September, much of the remaining deterioration is explained by a genuine policy change—conditional `Supervisor Sign-off`—that was omitted from the normative model. The candidate model’s recovery to 86% corroborates obsolescence, although its unconditional optionality is not policy-faithful.

**Remaining compliance concern — moderate-low confidence, 45/100 that at least some true bypass occurred; low confidence about prevalence or culpability:** The 25 and 30 enhanced-review traces without a recorded check cannot be dismissed. They are not proof of bypass because event and resource completeness deteriorated and no source-grounded audit exists. `Manual Override` is a real action and deserves governance review, but its mere presence is not noncompliance.

IT should immediately version the extraction, implement the validated label map, classify `Queue Routed` as excluded technical telemetry for policy conformance, order `Decision` and `Notify` by source sequence, and repair missing event/resource provenance. Process owners should issue an August-effective model version with a data-aware above-EUR-50,000 sign-off requirement, retaining the legacy model for earlier cases. A universally optional sign-off should not become the final control model. Compliance should audit the 55 no-check cases at source, stratified by claim value, reviewer, release, extraction source, and override use, with matched conforming controls.

It must not yet be claimed that employees caused the conformance collapse, that every reversed pair was executed in reverse, that every absent check was bypassed, that stable appeals prove compliance, or that higher fitness alone validates the candidate model. 

## 8. Model-governance recommendation

1. **Version models by effective date and scope.** Store the policy version, process model, conformance configuration, and effective interval together; never evaluate post-change cases silently against a superseded model.

2. **Maintain enforceable event-semantic contracts.** For every business activity, define its source state, event trigger, canonical label, aliases, payload, business meaning, and permitted cardinality; require compatibility review before UI or logging changes.

3. **Separate business events from technical telemetry.** Maintain an approved inclusion policy for routing, queue, retry, ingestion, and integration events; technical-event removal must be explicit, versioned, activity-specific, and reversible rather than based on ad hoc filtering.

4. **Preserve timestamp and ordering provenance.** Retain source timestamp, source sequence, ingestion timestamp, timezone, event ID, and tie-breaking rule; select the canonical ordering field according to event semantics and continuously monitor disagreements between order witnesses.

5. **Represent data-aware controls explicitly.** Do not replace a conditional rule such as “sign-off required above EUR 50,000” with universally optional control flow; combine the control-flow model with validated case attributes and separately test required presence and forbidden omission.

6. **Run post-release validation before accepting conformance trends.** After every UI, gateway, ETL, policy, or logging release, compare variants, DFGs, fitness, precision, attribute completeness, and a source-audited sample against the prior version; block employee-level attribution until data and model lineage pass those checks.
