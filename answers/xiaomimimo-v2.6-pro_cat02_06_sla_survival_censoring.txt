```python
def km_steps(t, e):
    """Plain KM for a single event type. e in {0,1}; competing events must be pre-coded as 0."""
    order = np.argsort(t, kind="mergesort")
    t, e = np.asarray(t)[order], np.asarray(e)[order]
    rows, S = [], 1.0
    for tt in np.unique(t[e == 1]):
        n = int((t >= tt).sum()) # at risk (ties counted together)
        d = int(((t == tt) & (e == 1)).sum())
        S *= (1 - d / n)
        rows.append((tt, n, d, S))
    return pd.DataFrame(rows, columns=["t", "n_risk", "d", "S"])
```

def aj_cif(t, cause, codes=(1, 2, 3, 4)):
    order = np.argsort(t, kind="mergesort")
    t, c = np.asarray(t)[order], np.asarray(cause)[order]
    S, cif = 1.0, {k: 0.0 for k in codes}
    rows = []
    for tt in np.unique(t[c > 0]):
        n = int((t >= tt).sum())
        d_tot = int(((t == tt) & (c > 0)).sum())
        S_prev = S
        for k in codes:
            d_k = int(((t == tt) & (c == k)).sum())
            cif[k] += S_prev * d_k / n
        S *= (1 - d_tot / n)
        rows.append({"t": tt, "n_risk": n, "d": d_tot, "S_all": S,
                     **{f"CIF_{k}": cif[k] for k in codes}})
    return pd.DataFrame(rows)

def restricted_mean(step_df, value_col, t_col="t", tau=SLA, start_val=1.0):
    # integral_0^tau of the step function defined by (t, value) with value = start_val before the first t
    t_prev, v_prev, area = 0.0, start_val, 0.0
    for _, r in step_df.iterrows():
        if r[t_col] >= tau: break
        area += (r[t_col] - t_prev) * v_prev
        t_prev, v_prev = r[t_col], r[value_col]
    area += (tau - t_prev) * v_prev
    return area

# ---------- 1. estimands ------------------------------------------------------
def e1a(r):
    """E1a  P(not resolved INTERNALLY by 72h): 0=resolved in time, 1=breach, nan=unknown."""
    if r.observed_status == "resolved":
        return 0.0 if r.time_obs <= SLA else 1.0
    if r.observed_status in ("withdrawn", "rejected"):
        return 1.0                     # absorbing non-resolution -> breach identified
    if r.observed_status == "transferred":
        return 1.0                     # T1: no internal Resolve can follow a handoff
    return 1.0 if r.time_obs > SLA else np.nan    # open: age>72 => breach already observed

def e1b(r):
    """E1b  P(not resolved SUBSTANTIVELY by 72h) -- external resolution after a handoff would count as resolution but is unobserved."""
    if r.observed_status == "resolved":
        return 0.0 if r.time_obs <= SLA else 1.0
    if r.observed_status in ("withdrawn", "rejected"):
        return 1.0
    if r.observed_status == "transferred":
        return 1.0 if r.time_obs > SLA else np.nan  # handoff before 72 -> external outcome unknown
    return 1.0 if r.time_obs > SLA else np.nan

def restricted_mean(tab, col, tau, start=1.0):
    area, t_prev, v_prev = 0.0, 0.0, start
    for _, r in tab.iterrows():
        if r["t"] >= tau: break
        area += (r["t"] - t_prev) * v_prev
        t_prev, v_prev = r["t"], r[col]
    area += (tau - t_prev) * v_prev
    return area

# 1. SLA estimands and time definitions

## 1.1 Clock, observation scheme and notation

**Time origin.** t = 0 at `Submit` (the SLA clock starts there). **Horizon:**  = 72 h, fixed in advance.

**[Assumption A1]** `duration_or_age_h` is elapsed time since `Submit` (duration to the terminal outcome for terminal rows, age at the freeze for `open` rows), i.e. the single supplied number is Y = min(T, C) on the SLA clock. *Needed because the SLA is defined on elapsed time and the extract contains no timestamps.*

**[Assumption A2]** `last_event_gap_h` = 0 for **every** terminal row and > 0 for **every** open row (it is measured "to the terminal event or to the cutoff", and the terminal event is the last recorded event). It is therefore a *measurement artifact that encodes the outcome label*, not a covariate (see §5). *Needed to interpret the column correctly.*

**Latent times.** T_R = time to `Resolve`, T_W = `Withdraw`, T_J = `Reject`, T_X = `Transfer` (hand-off). T = min(T_W, T_J, T_X, T_R), J = argmin  {R, W, J, X}. C = age at the freeze for `open` rows. Observed: Y = min(T, C),  = 1{T  C}, J.

|---|---|---|---|
| **Observed event** |  = 1 (terminal row) | 23 rows | identified (0 or 1) |

**Identification rule for any "resolved by 72 h" indicator (E1):**
`known = ( = 1 and J  R) or (Y > 72)`. The indicator is unknown **only** for cases censored before 72 h. A row can simultaneously be right-censored for the *time-to-resolution* estimand (S09 is censored at 92 h for T_R) and a **known failure** for the *by-72h* estimand. ## 1.2 Estimands

**E1a — Internal non-resolution by 72 h (strict SLA breach).**
_a(72) = P(T_R^int > 72), where T_R^int =  if no internal `Resolve` ever occurs (so W/J/X preclude resolution).
*Decision:* SLA compliance reporting and governance — "did **we** close this case with `Resolve` within 72 h of `Submit`?"

**E1b — Substantive non-resolution by 72 h (customer outcome).**
_b(72) = P(T_R^sub > 72), where an external resolution after a hand-off would count as resolution (its time is unobserved).
*Decision:* contractual/customer-experience SLA where the organisation stays accountable after hand-off; also service-credit decisions.

**E2 — Still in flight at 72 h (no terminal disposition).**
_2(72) = P(T > 72), where a "disposition" is any of `Resolve`/`Withdraw`/`Reject`/`Transfer`.
*Decision:* queue staffing, breach notifications, "do we still own work at 72 h", backlog pressure.

**E3 — Late-resolution mass.** _3(h) = P(72 < T_R  h) = F_R(h)  F_R(72): the probability of being **resolved late** (as opposed to never). Distinct from E1a, which also counts never-resolved cases.
*Decision:* rescue/escalation policy design ("of the breaches, how many are recoverable?") and rework capacity.

**E4 — Cause-specific cumulative incidences and hazards.** F_W(72), F_J(72), F_X(72) and the cause-specific hazards _k(t).
*Decision:* root-cause programmes (why do cases exit unresolved), transfer/off-load policy.

**E5 — Landmark (rescue) estimands.** _5 = P(eventually `Resolve` | still in flight at 72 h), plus the dynamic quantity P(still in flight at 72 | history (t)) and E[residual in-flight time | (t)].
*Decision:* alerting and escalation **at** the breach point — "is it worth pushing this case?"

**Estimand  decision map:** E1a = governance/compliance; E1b = customer/contract; E2 = capacity and ownership; E3 = rescue policy; E4 = root-cause work; E5 = real-time alerting. Note that these can disagree sharply (see §6).

## 2.1 `transferred` under four plausible assumptions

**T1 — Hand-off is a competing terminal event ("we never resolve it internally").** Code 4; contributes to F_X(t) and permanently removes mass from F_R. E1a = 1 for all three transfers (identified). This is the base case for a strict internal SLA and requires no assumption about external behaviour.

**T2 — Hand-off is independent right-censoring at T_X.** Code 0 at T_X; the estimand becomes a *hypothetical/net* one: "what would resolution look like if handed-off cases could continue to be resolved internally and resolved like the cases we keep". **[Hypothesis, questionable]** All 3/3 transfers follow `Escalate` and 3/3 are P1; hand-off is a severity-driven routing decision, so independence is implausible. T2 is reported only as a labelled hypothetical.

**T3 — Hand-off is (worst/best-case) informative censoring: external resolution at the hand-off time.** Code 1 at T_X (bounding best case for E1b). The pessimistic counterpart (external resolution never occurs) is exactly T1. T1 and T3 therefore bracket E1b, and the data cannot choose between them.

**T4 — Hand-off is a successful disposition of a *different* SLA ("disposed or resolved within 72 h").** Composite success; then E2-style "in flight at 72" is the breach measure and S08 (68 h) and S21 (26 h) count as compliant. This is a legitimate but *different* estimand — it has to be named as such, not smuggled in.

**[Key point]** The transfer ambiguity affects **only** estimands about *eventual/substantive* resolution (E1b, E3, E5) and hypothetical net risks (T2). For **E1a** ("resolved internally by 72 h") all three transfers are **observed failures**, because internal observation is complete up to the hand-off and no `Resolve` was recorded. Conversely, for **E2**, `Transfer` is an observed disposition and is an event under every assumption.

## 2.2 Withdrawal / rejection

They are **competing events**, not ordinary censoring: a withdrawn or rejected case can no longer reach `Resolve`. Treating them as censoring (KM with W/J censored) is only defensible for a *hypothetical* "no-abandonment" estimand and requires that withdrawal be unrelated to the resolution time — implausible here (all 3 `Reject` are P3; withdrawals cluster at 15–70 h). Reported as W2/J2 in §6 for contrast only.

## 2.3 Censoring taxonomy for this extract

* **Administrative right-censoring (9 `open` rows):** censoring at a common freeze date. Given a case's entry date this is independent of the outcome; but entry dates are unknown and staggered, cohort B is later than A, and younger cases are more likely to be censored  censoring is plausibly **differential by cohort** (informative marginally).
* **Competing events:** W, J, and X (under T1/T3-pessimistic).
* **Already-observed breaches:** 18 rows (see §1.1) — identified failures for the by-72h estimands even though several of them are right-censored for the time-to-event estimands.
* **Informative censoring risk:** `Transfer` is severity-driven (3/3 escalated, 3/3 P1) and the long `last_event_gap_h` values (S26 = 72 h of silence, S11 = 55, S25 = 48, S09 = 31) indicate dormancy, i.e. a subgroup whose resolution time distribution differs from that of active cases. KM/AJ censoring assumptions are exactly what these two features threaten.

# 3. Why naive completed-case analysis is biased

**What a completed-case analysis of this extract would say.** Restricting to the 13 `resolved` rows: mean duration 49.8 h, **median 41 h**, and "breach rate" 4/13 = **30.8 %** (S03 76, S13 110, S20 74, S28 88). By cohort: median 47.5 h (A) vs 39.0 h (B)  "the policy change made cases faster".

**Every one of those statements is biased.** The defensible comparators are: E1a breach 69.6 % (AJ) with bounds [56.3 %, 71.9 %] and 80–90 % of the window's case-hours still unspent (§4). The completed-case breach rate understates SLA tail risk by roughly 40 percentage points.

**Survivor / length bias (drop the still-open tail).** The excluded `open` rows are precisely the long ones: S26 (104 h), S09 (92 h), S11 (81 h), S25 (79 h) — four **already-observed breaches**. Removing cases because they have not finished conditions on the outcome (duration) itself and truncates the right tail of the duration distribution. Any estimator that requires a terminal row therefore estimates a distribution conditional on "finishing quickly enough to be observed finishing".

**Informative censoring (the event-gap column).** Last-event times are recoverable as age  gap: S09 61 h, S10 28 h, S11 26 h, S15 33 h, S24 63 h, S25 31 h, S26 32 h, S29 45 h, S31 20 h. Four cases (S09, S11, S25, S26) have spent 34–69 % of their life in silence; five (S10, S15, S24, S29, S31) are still warm (6–13 %). **[Hypothesis]** the silent cases are stalled and their resolution-time distribution is stochastically larger than that of active cases. If true, censoring them "as if" they behaved like S15 (gap = 2 h) over-states resolution; the extreme assumption "stalled cases never resolve" pushes _a to its upper bound.

**Competing risks.** Withdrawing (S06, S12, S22, S30) or being rejected (S05, S14, S23) removes the possibility of resolution. A KM curve for `Resolve` that censors these rows estimates a *net* (hypothetical) risk: 1  S_KM(72) = 36.1 % resolved by 72 vs the real-world CIF 30.4 % (T1). The gap (5.7 pp) is exactly the "eliminate abandonment" fantasy embedded in the KM curve. Counting only resolved cases is the extreme version of the same error.

**Cohort imbalance and treatment contamination.** n = 15 (A) vs 17 (B); B is later and more censored (5/17 open vs 4/15) and contains 2 of the 3 transfers and the single worst stalled case (S26). Rollout compliance is incomplete *and* contaminated: `AutoCheck` appears in 13/17 B cases but also in 2/15 A cases (S01, S15). So "cohort" (intention-to-treat) and "`AutoCheck` path" (per-protocol) are different exposures with different confounding, and neither was randomised. Crude E1a breach: A 9/15 = 60.0 % (bounds [60.0, 73.3]), B 9/17 = 52.9 % (bounds [52.9, 70.6]) — the intervals overlap almost completely, so the completed-case "B is faster" claim is unsupported.

**Open below vs open above 72 h must not be pooled.**
* S10 (47), S15 (35), S24 (67), S29 (51), S31 (23)  genuinely right-censored before the horizon; their breach indicator is unknown. Treating them as breaches inflates  by up to 5/32 = 15.6 pp.
* S09 (92), S11 (81), S25 (79), S26 (104)  **known breaches**. Dropping them deflates  by 4/32 = 12.5 pp and deletes the entire observed tail.

A "drop all open cases" analysis loses both groups; a "count all open cases as breaches" analysis invents 5 failures. The correct handling is asymmetric, and that asymmetry is only visible if `duration_or_age_h` is split into (time, status) before modelling.

# 4. Statistical analysis plan

## 4.1 Method-by-method on *these* data (n = 32, 4 outcomes, 9 censored, 27 distinct variants, no ties)

| Method | What it estimates | Verdict here |
|---|---|---|
| **Kaplan–Meier** | P(T_R > t) with all non-resolutions censored = **net/hypothetical** risk; or time-to-any-disposition with one event type | Secondary. Correct for E2 (single event type, administrative censoring) and *labelled* as hypothetical for E1. Gives 1  S(72) = 36.1 % (net resolution) and S_all(72) = 38.0 % (in flight). Its tail is an artifact: S drops to 0 at 110 h with n = 1 at risk — truncate reporting at the last time with  5 at risk. |
| **Aalen–Johansen CIF** | F_R, F_W, F_J, F_X in the **real world** with competing events | **Primary.** Identifies E1a (1  F_R(72)), E3 (F_R(h)  F_R(72)), E4, and (via S_all) E2, without any assumption *between causes*; requires only independent administrative censoring. |
| **Cause-specific hazards** | _k(t): instantaneous rate among those still at risk; competing events censored in the partial likelihood is *valid for the hazard* | Secondary/explanatory. | **Landmarking** | P(T >  \| (t_L)), for t_L <  | **Secondary / operational primary for alerting.** The only design in this task that is immune to immortal-time bias for post-baseline process events (§5). Implementable here at t_L = 72 only; needs event timestamps for 24/48 h landmarks. |
| **Multi-state (Aalen–Johansen transition probabilities, Cox per transition)** | State occupancy P(X(t) = k), transition intensities | Exploratory. ## 4.2 Workload decomposition (RMST) — computed in §8

Using S_all(t) (time to **any** disposition, `open` censored) and the four CIFs over the 72 h window:

* **Restricted mean in-flight time within the SLA window:** ² S_all(t) dt = **50.4 case-hours per case** (of a possible 72) — this is the queue load the SLA window generates.
* Decomposition of the 72 case-hours: 50.4 still in flight + 11.4 after a `Resolve` + 10.2 after a non-resolving disposition.
* **Restricted mean "unresolved" time:** ² (1  F_R(t)) dt = **60.6 case-hours per case** — the "SLA-hours at risk of breach" metric for governance.

These two numbers convert directly into staffing (multiply by intake volume) and are far more stable than any tail estimate on 32 cases.

## 4.3 Recommendation

**Primary: Aalen–Johansen with 4-cause competing-risk coding under T1 (hand-off = competing event), reported together with the nonparametric bounds of §1.3 and the implied-assumption audit (§6).** Justification: (i) E1a/E2 are real-world probabilities with competing events, which is exactly the AJ estimand; (ii) the dominant uncertainty in this extract is *identification* (5 cases censored before 72 h, unknown external outcomes), and bounds make that visible, whereas regression cannot create information that is not there; (iii) with n = 32 no multivariable model is credible, so the primary analysis should be assumption-light.

**Secondary:** (a) RMST decomposition (§4.2) for capacity/governance; (b) KM-net reported explicitly as the labelled hypothetical "no abandonment / no hand-off" quantity; (c) on the *full* log (with event timestamps): a landmarked cause-specific or Fine–Gray model at 24/48/72 h with time-varying process states for alerting, and a multi-state model for stage-specific hazards. **Exploratory:** multi-state / transition analysis on this extract (DFG-level only).

**Uncertainty:** Greenwood/Aalen variances or 1 000-replicate bootstrap for the point estimates, but always printed *next to* the bounds — with n = 32 the identification interval is wider than the confidence interval, and conflating the two is the main reporting risk.
