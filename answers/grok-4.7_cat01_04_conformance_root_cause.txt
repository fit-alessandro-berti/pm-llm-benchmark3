## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels
UI_release -> classification_rule_hidden
classification_rule_hidden -> true_process
gateway_instrumentation -> recorded_labels
ETL_change -> recorded_order
source_sequence_unused -> recorded_order
policy_change -> true_process
policy_change -> model_update_omitted
high_value_attribute -> true_process
high_value_attribute -> reviewer_behavior
reviewer_behavior -> true_process
logging_patch -> recorded_labels
extraction_loss -> recorded_labels
model_update_omitted -> normative_model
true_process -> recorded_labels
case_mix -> true_process
incident_detection_incomplete -> business_outcomes
true_process -> business_outcomes
recorded_labels -> alignment_moves
recorded_order -> alignment_moves
normative_model -> alignment_moves
alignment_moves -> measured_fitness
```

measured_fitness is the comparison of recorded_labels and recorded_order with normative_model, not a reading of customer harm. UI_release on 31 May rewrote Classify as Risk Screen in recorded_labels. The June screen audit ties that caption to the old screen. A change to the classification rule inside true_process remains the hidden variable classification_rule_hidden. On 3 June gateway_instrumentation wrote Queue Routed into recorded_labels for most cases. On 15 June ETL_change stored warehouse-ingestion time on Decision and Notify. source_sequence_unused left the reliable order key off the conformance job, so recorded_order can reverse work that was still done as decision then notification. Those three edges create alignment_moves and are sufficient to push fitting traces from the low 90s into the low 30s while true_process stays put.

policy_change on 1 August is a different incoming edge. Together with high_value_attribute it changes true_process, and reviewer_behavior places Supervisor Sign-off on both review tracks. model_update_omitted means normative_model still rejects the new activity, so August alignment_moves return after the logging repairs. Manual Override and enhanced reviews that lack a compliance check are smaller edges into the log, from reviewer_behavior or from extraction loss.

Flat approvals, cycle time, and appeals do not select an edge. A logging fault leaves business_outcomes still, so calm KPIs are not evidence that the extract is faithful. A skipped check can leave appeals still, because incident_detection_incomplete filters the outcome and many missed controls never become appeals. The same flat series is compatible with a recording artifact, with an obsolete model of a real policy change, and with a narrow noncompliant residue. One-edge repairs, then a source audit, separate them.

    tree = pm4py.parse_process_tree(tree_string)
    net, initial_marking, final_marking = pm4py.convert_to_petri_net(tree)
    return net, initial_marking, final_marking


def reorder_notify_decision(activities):
    """Proxy for source-sequence repair: swap an adjacent Notify, Decision pair.

    Valid only where an independent clock says Decision happened first.
    The same swap would also hide a genuine business inversion.
    """
    rewritten = []
    index = 0
    while index < len(activities):
        current = activities[index]
        nxt = activities[index + 1] if index + 1 < len(activities) else None
        if current == "Notify" and nxt == "Decision":
            rewritten.extend(["Decision", "Notify"])
            index += 2
        else:
            rewritten.append(current)
            index += 1
    return rewritten


def transform_variants(variants, map_label, drop_queue, reorder):
    totals = Counter()
    for trace, count in variants:
        activities = [part.strip() for part in trace.split(",") if part.strip()]
        if map_label:
            activities = ["Classify" if name == "Risk Screen" else name for name in activities]
        if drop_queue:
            activities = [name for name in activities if name != "Queue Routed"]
        if reorder:
            activities = reorder_notify_decision(activities)
        totals[",".join(activities)] += count
    return totals.most_common()


def variants_to_csv(variants, origin):
    lines = ["case_id,activity,timestamp"]
    case_id = 1
    origin_dt = datetime.strptime(origin, "%Y-%m-%d %H:%M:%S")
    for trace, count in variants:
        activities = [part.strip() for part in trace.split(",") if part.strip()]
        for _ in range(count):
            for step, activity in enumerate(activities):
                stamp = origin_dt + timedelta(minutes=case_id * 20 + step)
                lines.append(
                    f"{case_id},{activity},{stamp.strftime('%Y-%m-%d %H:%M:%S')}"
                )
            case_id += 1
    return "\n".join(lines) + "\n"


def activity_names(log):
    names = set()
    for trace in log:
        for event in trace:
            names.add(event["concept:name"])
    return names


def ensure_event_log(parsed):
    if type(parsed).__name__ in {"EventLog", "EventStream"}:
        return parsed
    if isinstance(parsed, pd.DataFrame):
        frame = parsed
        columns = set(frame.columns)
        if {"case_id", "activity", "timestamp"} <= columns:
            frame = pm4py.format_dataframe(
                frame,
                case_id="case_id",
                activity_key="activity",
                timestamp_key="timestamp",
            )
        return pm4py.convert_to_event_log(frame)
    return parsed


def log_via_dataframe(csv_text):
    frame = pd.read_csv(StringIO(csv_text))
    frame = pm4py.format_dataframe(
        frame,
        case_id="case_id",
        activity_key="activity",
        timestamp_key="timestamp",
    )
    return pm4py.convert_to_event_log(frame)


def load_log(csv_text):
    """Parse with pm4py.parse_event_log_string; rebuild if the header is mishandled."""
    parsed = None
    try:
        parsed = ensure_event_log(pm4py.parse_event_log_string(csv_text))
        names = activity_names(parsed)
        if len(parsed) > 0 and (names & KNOWN_ACTIVITIES) and "activity" not in names:
            return parsed
    except Exception:
        parsed = None
    return log_via_dataframe(csv_text)


def log_from_variants(variants, origin):
    return load_log(variants_to_csv(variants, origin))


def step_labels(step):
    """Accept either ('log', 'model') or nested PM4Py alignment pairs."""
    if isinstance(step, (list, tuple)) and len(step) == 2 and all(
        isinstance(part, str) or part is None for part in step
    ):
        return step[0], step[1]
    if isinstance(step, (list, tuple)):
        nested = [
            part for part in step
            if isinstance(part, (list, tuple)) and len(part) == 2
        ]
        if nested:
            return nested[-1][0], nested[-1][1]
    return None, None


def is_hidden(label):
    if label is None:
        return True
    text = str(label)
    return text in {">>", "None", "tau", "skip"} or text.startswith("tau") or text.startswith("skip")


def summarize_alignments(diagnostics):
    log_moves = Counter()
    model_moves = Counter()
    costs = []
    for item in diagnostics:
        if not isinstance(item, dict):
            continue
        costs.append(item.get("cost", 0))
        for step in item.get("alignment", []):
            log_label, model_label = step_labels(step)
            if log_label is None and model_label is None:
                continue
            if model_label == ">>" and not is_hidden(log_label):
                log_moves[str(log_label)] += 1
            elif log_label == ">>" and not is_hidden(model_label):
                model_moves[str(model_label)] += 1
    mean_cost = (sum(costs) / len(costs)) if costs else None
    fitting = (sum(cost == 0 for cost in costs) / len(costs)) if costs else None
    return fitting, mean_cost, log_moves, model_moves


def summarize_dfg(log, limit=8):
    dfg, start_activities, end_activities = pm4py.discover_dfg(log)
    ranked = sorted(dfg.items(), key=lambda item: item[1], reverse=True)
    return ranked[:limit], start_activities, end_activities


def report(title, log, net, initial_marking, final_marking):
    print(f"\n== {title} ==")
    print(f"traces: {len(log)}")
    top_dfg, _, _ = summarize_dfg(log)
    print("top directly-follows:")
    for (source, target), count in top_dfg:
        print(f"  {source} -> {target}: {count}")
    fitness = pm4py.fitness_alignments(log, net, initial_marking, final_marking)
    print("alignment fitness:", fitness)
    diagnostics = pm4py.conformance_diagnostics_alignments(
        log, net, initial_marking, final_marking
    )
    fitting, mean_cost, log_moves, model_moves = summarize_alignments(diagnostics)
    print(f"share cost==0: {fitting}")
    print(f"mean alignment cost: {mean_cost}")
    print("visible log moves:", log_moves.most_common(6))
    print("visible model moves:", model_moves.most_common(6))
    if mean_cost not in (0, None) and not log_moves and not model_moves:
        sample = diagnostics[0].get("alignment", [None])[0] if diagnostics else None
        print("unparsed alignment step:", sample)
    return fitness


def precision_of(log, net, initial_marking, final_marking):
    return pm4py.precision_alignments(log, net, initial_marking, final_marking)


def build(variants, origin, map_label, drop_queue, reorder):
    transformed = transform_variants(variants, map_label, drop_queue, reorder)
    return log_from_variants(transformed, origin)


def main():
    normative_net, normative_im, normative_fm = tree_to_net(NORMATIVE_TREE)
    candidate_net, candidate_im, candidate_fm = tree_to_net(CANDIDATE_TREE)

    scenarios = [
        ("raw", False, False, False),
        ("label map Risk Screen->Classify", True, False, False),
        ("label map and drop Queue Routed", True, True, False),
        ("label map, drop Queue Routed, Notify/Decision swap proxy", True, True, True),
    ]
    periods = [
        ("April-May", APRIL_MAY, "2026-04-01 09:00:00"),
        ("June-July", JUNE_JULY, "2026-06-01 09:00:00"),
        ("August-September", AUGUST_SEPTEMBER, "2026-08-01 09:00:00"),
    ]

    cleaned_august = None
    for period_name, variants, origin in periods:
        for scenario_name, map_label, drop_queue, reorder in scenarios:
            log = build(variants, origin, map_label, drop_queue, reorder)
            report(
                f"{period_name} | {scenario_name} | normative tree",
                log,
                normative_net,
                normative_im,
                normative_fm,
            )
            if period_name == "August-September" and scenario_name.startswith("label map, drop"):
                cleaned_august = log

    print("\n== August-September cleaned | candidate optional sign-off ==")
    candidate_fitness = report(
        "August-September | cleaned | optional Supervisor Sign-off",
        cleaned_august,
        candidate_net,
        candidate_im,
        candidate_fm,
    )
    normative_precision = precision_of(
        cleaned_august, normative_net, normative_im, normative_fm
    )
    candidate_precision = precision_of(
        cleaned_august, candidate_net, candidate_im, candidate_fm
    )
    print("August cleaned precision, normative tree:", normative_precision)
    print("August cleaned precision, optional sign-off tree:", candidate_precision)
    print("candidate fitness object:", candidate_fitness)

    print("\nCAVEATS")
    print(
        "1. Variant aggregates were expanded with synthetic timestamps. "
        "Results will not match the published 93/32/58/81/89/66/86 figures exactly. "
        "April-May should fit the normative tree almost perfectly; the published "
        "93% and cost 0.08 are not recoverable from this census."
    )
    print(
        "2. The Notify/Decision swap is a proxy for ordering by source sequence. "
        "It is not a provenance repair, and it would also 'fix' a real inversion."
    )
    print(
        "3. A control-flow-only optional Supervisor Sign-off cannot enforce the "
        "EUR 50,000 condition. It overgeneralizes: every case may take the "
        "sign-off and every case may skip it, so low-value insertions and "
        "high-value omissions both fit. A higher fitness or a stable precision "
        "against this log does not make that tree the policy."
    )
    print(
        "4. Label mapping assumes Risk Screen is Classify. Dropping Queue Routed "
        "assumes it is not a business step. Neither assumption is proved by fitness."
    )


if __name__ == "__main__":
    main()

## 7. Provisional conclusion

The June collapse, from 93% fitting traces to 32%, is primarily a recording and extraction failure scored against an old vocabulary. Mapping Risk Screen to Classify, dropping Queue Routed, and ordering Decision and Notify by the unused source sequence recover June–July to 89% fitting and mean cost 0.12, beside 93% and 0.08 in April–May. In that repair order, each step removes the moves predicted by one dated change: the 31 May label, the 3 June gateway event, and the 15 June warehouse clock. Confidence that this trio produced the June number is about 80%. Confidence that every inversion is an artifact is about 60%: the other June inversions and all 45 August inversions were not checked, and any re-sort toward the model raises fitness even when the key is wrong.

The residual question is a control question. Cleaned August fitness is 66% because 210 traces carry Supervisor Sign-off after the 1 August rule for claims above EUR 50,000, on both review tracks. That is an authorized process change together with an obsolete tree. Optional sign-off reaches 86% by permitting the step, and its absence, on every claim, without the value test the alignment extract omitted. The gain is a control-flow approximation, not evidence the rule holds. In parallel, 25 then 30 enhanced reviews have no compliance check and are still unclassified as bypass or lost event. Manual Override rises from 20 to 35 traces across the 12 August logging patch, so that rise is not yet a change in behavior. Approvals, appeals, cycle time, and confirmed incidents barely moved, and detection is incomplete. Confidence that a material breach is already shown is about 30%. Confidence that this residue still has to be audited before the case is closed is about 75%.

IT should restore source-sequence ordering, keep Queue Routed out of the activity stream, and publish the 4.2 label map. Process owners should version a sign-off rule conditioned on claim value and explain the Request Info disappearance and the August mix shift. Compliance should source-audit the 55 unchecked enhanced reviews and stratify sign-off and override by value and reviewer before any conduct review.

It is not yet justified to say that employees caused the collapse, that cleaned or optional-model fitness is the policy, that stable appeals clear the log or the reviewers, or that Risk Screen kept the old decision logic.

## 8. Model-governance recommendation

1. Model versioning. Every policy effective date has a process-tree version with a validity interval, an owner, and a conformance job pinned to the version in force at the policy’s case anchor. A model change is a release. Supervisor Sign-off on 1 August would have been a new version, not an edit that never shipped.

2. Event-semantic contracts. Each business activity has a stable identifier distinct from the UI caption. Release 4.2 may show Risk Screen only if the event still carries the semantic id Classify, or if the same release ships a versioned alias map that conformance loads. Captions are allowed to change. Unmapped strings are not allowed to become new activities by default.

3. Technical-event policy. Gateway and infrastructure records such as Queue Routed are stored as attributes, or in an event class the conformance projection drops by default. Promoting one into the business stream requires a business owner, a written meaning, and a model change in the same release. Coverage that is “most but not all” cases is a warning, not a new step.

4. Timestamp provenance. Every event keeps source-system time, warehouse-ingestion time, and source sequence as separate fields. Conformance orders by source sequence or source time. Ingestion time is a data-quality field. The job fails closed when the chosen order key is null, instead of silently substituting the warehouse clock as it did on 15 June.

5. Data-aware constraints. An obligation that depends on claim value, including Supervisor Sign-off above EUR 50,000, is encoded as a guard or an equivalent data-aware rule and is reported inside the value slice. A control-flow-only tree is labeled an approximation. Fitness for an optional branch is not accepted as proof of the guard. The case attribute required by the guard is part of the conformance extract.

6. Post-release validation. After every UI, ETL, gateway, or policy release, compare a paired window on variants, frequency DFGs, alignment moves, fitness, and precision, and audit a small source-system sample of disputed labels, disputed orders, and missing controls. A fitness drop stops the conformance feed until the label map, the technical-event filter, the order key, and the model version have each been accounted for. Precision is reported beside fitness so a more permissive tree cannot clear the gate by overgeneralizing.
