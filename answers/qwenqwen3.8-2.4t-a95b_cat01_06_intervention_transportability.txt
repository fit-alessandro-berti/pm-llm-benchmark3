## 6. Candidate Site B intervention

Do not copy Site A’s universal parallel `Identity Check` + `Document Check` design. Use a segmented, legally constrained parallelization policy.

### Eligibility rules

1. **Tier 1: Digital/no-originals cases**
   - `originals_required = false`
   - Complete digital documents available at `Register`
   - No missing mandatory attachments
   - Initially prefer:
     - low/medium complexity,
     - non-legal-review cases, if volume permits.

2. **Tier 2: Originals-required cases**
   - `originals_required = true`
   - `Identity Check` may start after `Register`.
   - `Originals Receipt` may start after `Register`.
   - `Document Check` must not start until `Originals Receipt` is complete.

3. **Exclusions during early pilot**
   - Fraud or compliance holds.
   - Cases with known incomplete digital documents.
   - Cases requiring urgent legal escalation unless explicitly managed.

### Concurrent task rules

- `Register` always precedes all other tasks.
- In Tier 1, create `Identity Check` and `Document Check` simultaneously after `Register`.
- In Tier 2, create `Identity Check` and `Originals Receipt` simultaneously after `Register`; create or release `Document Check` only after `Originals Receipt` completes.
- `Assessment` must wait for both `Identity Check` and `Document Check`.
- `Legal Review` remains mandatory for public-sector/high-value cases.
- `Request Supplement` must route back to the appropriate rework task, usually `Document Check`, and may require repeated `Assessment`.

### Queue and WIP controls

- Per-reviewer WIP limit: maximum six open verification tasks, mirroring a controlled Site A condition.
- Pool-level CONWIP caps:
  - Identity pool: no more than 24 open tasks unless utilization evidence supports change.
  - Document pool: no more than 42 open tasks.
  - Assessment pool: no more than 18 open tasks.
  - Legal pool: no more than 12 open tasks.
- Priority rule: oldest case within SLA band first, with escalation for near-breach cases.
- Do not release more verification work into assessment/legal than those pools can absorb.

### Resource responsibilities

- Identity reviewers own `Identity Check`.
- Document reviewers own `Document Check` and supplement-related document rework.
- Assessors own `Assessment`.
- Legal reviewers own `Legal Review` and `Request Supplement` decisions.
- Cross-ownership is prohibited unless a reviewer is explicitly certified and the case system supports it.

### Legal-review and supplement loops

- After `Assessment`, legal-required cases enter `Legal Review`.
- If legal issues `Request Supplement`:
  - create a supplement package,
  - route to `Document Check` or `Originals Receipt` as needed,
  - repeat `Assessment` if document findings affect decision readiness,
  - do not repeat `Identity Check` unless identity is implicated.
- Track supplement loop count and reason code.

### Logging requirements

- System-generated timestamps for:
  - task creation,
  - task claim,
  - task start,
  - task completion,
  - task blocking/unblocking,
  - legal supplement issuance and closure.
- Record:
  - `originals_required`,
  - `legal_required`,
  - `digital_channel`,
  - `complexity_band`,
  - `pilot_arm`,
  - `lock_override_flag`.
- Prohibit manual backdating except with audit reason and supervisor approval.

### Compact POWL-style description

Let:

- `R = Register`
- `I = Identity Check`
- `O = Originals Receipt`
- `D = Document Check`
- `A = Assessment`
- `L = Legal Review`
- `S = Request Supplement`
- `P = Approve`
- `J = Reject`
- `N = Notify`

For digital/no-originals cases:

```text
R
SPO({I, D, A}, order = {I < A, D < A})
if legal_required:
    A < L
    L < P or L < J or L < S
    S < D_repeat < A_repeat < L
else:
    A < P or A < J
P/J < N
```

For originals-required cases:

```text
R
SPO({I, O, D, A}, order = {O < D, I < A, D < A})
if legal_required:
    A < L
    L < P or L < J or L < S
    S < D_repeat < A_repeat < L
else:
    A < P or A < J
P/J < N
```

Concurrency is allowed only where no order edge exists:

```text
Tier 1: I || D
Tier 2: I || O, but O < D
Always: R before all; A after I and D; legal constraints preserved.
```

## 7. Pilot for transport learning

| design element | specification | causal purpose | operational safeguard | process-mining measurement |
|---|---|---|---|---|
| Unit of assignment | Individual eligible case, randomized by case ID hash after `Register` | Isolates treatment effect from calendar and team trends | Randomization flag stored in case system; prevent manual arm changes | Count and balance of cases by arm, stratum, date |
| Randomization or phased assignment | Stratified case-level randomization; if case-level assignment is operationally unstable, use phased rollout by intake day/team | Controls confounding from mix and time | Pre-register strata and phase sequence | Treatment assignment compliance over time |
| Eligible strata | Phase 1: no originals required, complete digital documents, low/medium complexity, non-legal if possible. Phase 2: no-originals legal cases. Phase 3: originals-required identity/originals parallel only. | Tests effect modifiers rather than assuming uniform transport | Do not open phase until prior phase meets stability criteria | Eligible volume, exclusions, stratum balance |
| Treatment versions | T1: `Identity Check` + `Document Check` parallel. T2: `Identity Check` + `Originals Receipt` parallel, `Document Check` gated. Control: current sequential/statutory process. | Separates digital parallelism from originals-receipt parallelism | Clear task flags so workers know version | Actual task creation order and overlap by version |
| Primary outcomes | Median cycle time, p90 cycle time, waiting before `Assessment`, true overlap rate | Measures intended causal chain | Dashboard with weekly review | Interval overlap, join waiting, end-to-end duration |
| Secondary outcomes | Rework, supplements, appeals, identity/document service times, legal queue age | Detects quality and bottleneck side effects | Guardrail thresholds and escalation path | Rework loops, legal handoffs, service-time distributions |
| Interference controls | Separate queues where feasible; cap treatment share at 30–50% of eligible volume; prohibit control cases from receiving parallel task creation | Prevents spillover and contamination | Queue ownership rules and audit | Control-arm overlap and queue migration |
| Power / minimum-support logic | Target at least 500 treatment and 500 control cases in Phase 1, or extend pilot until 95% bootstrap CI for median difference excludes trivial effect. For p90, require at least 200 cases per tail-relevant stratum. | Avoids decisions based on underpowered before/after comparisons | Predefined minimum sample and CI rules | Sample size, CI width, stratum support |
| Duration | 8–12 weeks after stabilization, excluding major holidays or system changes | Allows enough cases and queue cycles | Change freeze for pilot processes | Weekly volume and stability charts |
| Stop rules | Pause if p90 worsens by >10h, rework rises >2pp, appeals rise >1pp, lock violations >5%, or true overlap <40% of treatment cases | Protects customers and identifies implementation failure | Automated alerts and governance review | Threshold metrics and violation logs |
| Transportability analysis | Compare Site B stratum-specific effects with Site A evidence; adjust for digital share, complexity, legal review, capacity, and timestamp reliability | Determines whether A’s mechanism transports, modifies, or fails | Pre-registered analysis plan | Effect estimates by modifier and subgroup |

The pilot separates mechanism failure from implementation failure by measuring both treatment activation and downstream response. If assigned cases show high true overlap but no reduction in waiting before `Assessment`, the causal mechanism is failing or the bottleneck has moved to assessment/legal capacity. If true overlap is low despite assignment, the failure is implementation: case locks, unavailable documents, queue rules, or back-entered timestamps. Stratifying by originals requirement and legal review tests whether Site A’s digital-enabled mechanism exists at Site B. Randomization protects against mix and calendar confounds, while process-mining metrics identify co-interventions such as huddles or staffing changes. Stop rules separate harms: quality stops for rework/appeals, tail stops for p90 worsening, and fidelity stops for low overlap or lock violations. If Tier 1 improves digital cases but Tier 2 does not improve originals cases, expand only Tier 1. If both improve overlap but p90 worsens, modify WIP/legal capacity before scaling.

# ---------------------------------------------------------------------
# Helper utilities for minor API differences in PM4Py versions
# ---------------------------------------------------------------------

def get_operator(*names):
    """Return first available Operator attribute among names."""
    for name in names:
        if hasattr(Operator, name):
            return getattr(Operator, name)
    raise AttributeError(f"None of these POWL operators found: {names}")


SEQ = get_operator("SEQUENCE", "SEQ")
CHOICE = get_operator("CHOICE", "XOR")
LOOP = get_operator("LOOP", "STAR", "WHILE")


def make_task(label):
    """
    Create a leaf POWL node representing an activity.
    PM4Py versions differ; try common constructor patterns.
    """
    try:
        return POWL(operator=None, children=[], name=label)
    except TypeError:
        try:
            return POWL(name=label)
        except TypeError:
            node = POWL()
            node.name = label
            return node


def make_operator_node(operator, children):
    """Create a POWL operator node robustly."""
    try:
        return POWL(operator=operator, children=children)
    except TypeError:
        try:
            return POWL(operator, children)
        except TypeError:
            node = POWL()
            node.operator = operator
            node.children = children
            return node


def make_strict_partial_order(children):
    """Create a strict partial order node robustly."""
    try:
        return StrictPartialOrder(children=children)
    except TypeError:
        try:
            return StrictPartialOrder(children)
        except TypeError:
            spo = StrictPartialOrder()
            spo.children = children
            return spo


def add_order(spo_node, source, target):
    """
    Add an order edge source < target to a strict partial order.
    This assumes the PM4Py object stores order edges as object pairs.
    If a version uses indices or another attribute, adapt accordingly.
    """
    if not hasattr(spo_node, "order"):
        spo_node.order = set()
    spo_node.order.add((source, target))

## 9. Recommendation

**conditional go**

Transfer the mechanism, not the universal control-flow change. Site A provides weak causal evidence: its before/after comparison is confounded by an API upgrade, added document reviewers, a marketing-driven mix shift, daily huddles, and possible timestamp improvements. The nine-hour median reduction should not be copied as an expected Site B treatment effect. The transportable signal is narrower: when documents are already digital, identity and document checks are independent, and IT supports concurrent task ownership, true overlap can reduce waiting before assessment.

Site B should not copy Site A by creating simultaneous `Identity Check` and `Document Check` tasks for every case. For 62% of cases, `Document Check` legally cannot begin until originals are received. The legacy case lock may also make simultaneous ownership fictive unless the system is changed. Therefore the first pilot subgroup should be cases without originals requirement, with complete digital documents, low/medium complexity, and preferably no legal-review requirement. This subgroup isolates the core parallel-verification mechanism while limiting legal bottleneck interference. For originals-required cases, allow only `Identity Check` and `Originals Receipt` to run in parallel, with `Document Check` strictly gated.

Expected benefits are modest but real: median cycle-time reduction of roughly 2–6 hours in eligible digital cases and reduced waiting before assessment. The p90 may improve less because assessment and legal capacity remain constrained. Risks include nominal parallelism from back-entered timestamps, document rework, assessment/legal saturation, and worse tail performance.

Expand only if the pilot shows true overlap above about 60%, waiting before assessment falls by at least 3 hours, median cycle time improves without p90 worsening more than about 5 hours, and rework/appeals remain within roughly 1 percentage point of baseline. Modify if the bottleneck shifts to assessment or legal review by adding capacity, tightening WIP, or staging legal intake. Abandon if the case lock prevents real concurrency, if rework or appeals rise materially, or if p90 worsens persistently. Do not treat Site A’s co-interventions as optional decoration; if huddles, API improvements, or staffing changes are needed, test them as separate levers.

## 10. Assumption register

1. **Site A’s observed 9-hour median reduction is not a clean parallelization effect — needed to avoid overestimating transportability — test by stratifying Site A data by complexity, digital share, staffing, and timestamp quality, then estimate adjusted effects — if false, the true parallelization effect may be smaller or larger, but Site B still needs local pilot evidence.**

2. **True overlap, not nominal task creation, is the active mechanism — needed because Site B’s case lock can create fake parallelism — test by measuring system-generated overlapping intervals and comparing them with waiting before assessment — if false, parallel task creation will not reduce cycle time and may increase coordination risk.**

3. **Digital/no-originals cases are the most transportable subgroup — needed because Site A’s concurrency depended on documents being available early — test by comparing baseline service times and waiting in digital versus originals-required cases — if false, even digital cases may not benefit due to document quality, hidden prerequisites, or capacity limits.**

4. **Originals receipt delay dominates Site B’s document-check path — needed to decide whether identity/originals parallelism is worthwhile — test by analyzing delay distribution for `Originals Receipt` and its correlation with cycle time — if false, broader document parallelism may be more valuable, but statutory constraints still limit immediate document checking.**

5. **Assessment and legal capacity can absorb earlier verification completions — needed because parallelization can shift the bottleneck downstream — test by monitoring assessment and legal queue age, utilization, and p90 during the pilot — if false, median may improve slightly while p90 worsens, requiring capacity or WIP changes before expansion.**

6. **The legacy case lock can be overcome or safely worked around with reliable timestamps — needed because simultaneous ownership is required for true concurrency — test by auditing lock overrides, task ownership records, and timestamp entry lag — if false, the intervention becomes nominal and measurement is unreliable; IT redesign is required.**

7. **Role specialization does not prevent effective parallel execution — needed because Site B lacks Site A’s cross-trained reviewers — test by measuring identity/document pool utilization, queue starvation, and task aging — if false, parallelization may create imbalance and require cross-training or dynamic task routing.**

8. **Site A co-interventions are not essential for the parallelization effect — needed to know whether B must also replicate API upgrades, added staff, or huddles — test by estimating pilot effects while holding co-interventions constant, or by adding them in separate experimental arms — if false, Site B must implement the supporting co-interventions or expect a smaller effect.**
