# **1. Assumptions and Interpretation**
1. **Risk classification (low/high)**: Represented via an **XOR split** after `Analyze Root Cause` into two subtrees: one for `Supervisor Review` (low risk) and one for `Quality Review` + `Regulatory Review` (high risk).
2. **Optional supplier consultation**: Represented as a **conditional branch** (e.g., `XOR` or `IF` in POWL) that can only start after `Analyze Root Cause` and must complete before `Release Material`. Its presence is determined by case data (not modeled explicitly).
3. **Passing inspection**: Abstracted as a **loop termination condition** in the `LOOP` subtree for trial iterations. The loop exits only when `Inspect Trial` succeeds (no explicit event label for "pass/fail").
4. **Duplicate visible labels**: Permitted only for **internal concurrency** (e.g., `Quality Review` and `Regulatory Review` can appear in parallel). No duplicate labels are allowed for the same activity across branches.
5. **Approximation policy**: **Conservative under-approximation** for the Process Tree. The tree omits explicit concurrency between branches (e.g., `Plan Verification` and `Design Corrective Action` are modeled as sequential dependencies rather than true parallelism). Overlaps are approximated via `XOR` or `IF` conditions.
6. **"May overlap" interpretation**: Treated as **true concurrency** in POWL (via `StrictPartialOrder` edges without ordering constraints) and **absence of ordering** in the Process Tree (via `PARALLEL` or `XOR` where applicable).
