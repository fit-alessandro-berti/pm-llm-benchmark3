## 6. Candidate Site B intervention

**Eligibility:** Only cases without statutory physical original requirement.
**Concurrency:** `Identity Check` and `Document Check` may start after `Register` but `Document Check` requires `Originals Receipt` completion when required.
**Statutory Prerequisites:** `Originals Receipt` must precede `Document Check` for 62% of cases. `Legal Review` precedes decision for 40%.
**Queue and WIP Controls:** Implement WIP limits of 8 tasks per reviewer role; block new starts if limit hit.
**Resource Responsibilities:** Identity and Document reviewers operate in parallel; Assessment waits for completion tokens.
**Legal/Supplement Loops:** If `Legal Review` requests supplement, `Document Check` restarts only after `Originals Receipt` confirmed.
**Logging:** Enforce real-time timestamp recording; audit for back-entry.

**POWL Partial Order:**
```text
Register -> {IdentityCheck, OriginalsReceipt}
OriginalsReceipt -> DocumentCheck (if required)
IdentityCheck -> Assessment
DocumentCheck -> Assessment
Assessment -> {LegalReview, Approve, Reject}
LegalReview -> {RequestSupplement, Approve, Reject}
RequestSupplement -> DocumentCheck
```

| transportability analysis | subgroup comparison | measure generalization | legal audits | variance decomposition |

The pilot isolates mechanism failure by targeting digital cases where structural barriers are minimal. This separates implementation constraints, like IT locks, from causal theory, parallelism reducing waits. By randomizing within strata, we control for case mix differences. If the control group shows similar improvements, the mechanism is likely confounded rather than causal. Conversely, if treatment reduces wait without increasing rework, parallelism is validated. Safeguards like rework thresholds protect against quality failure, while log audits reveal implementation issues like timestamp errors.

## 8. PM4Py model-construction code

```python
from pm4py import parse_process_tree, convert_to_petri_net, check_is_workflow_net, check_soundness
from pm4py.play_out import play_out
from pm4py.objects.powl.obj import ProcessOWL, Node, Arc
import pm4py

# Site A Before Tree
before_tree = parse_process_tree("Sequence(Register, IdentityCheck, DocumentCheck, Assessment, Or(Approve, Reject), Notify)")

# Site A After Tree
after_tree = parse_process_tree("Sequence(Register, Parallel(IdentityCheck, DocumentCheck), Assessment, Or(Approve, Reject), Notify)")

# Convert to Petri nets
before_net = convert_to_petri_net(before_tree)
after_net = convert_to_petri_net(after_tree)

# Site B POWL Model
site_b_model = ProcessOWL()
r = Node("Register")
i = Node("IdentityCheck")
o = Node("OriginalsReceipt")
d = Node("DocumentCheck")
a = Node("Assessment")
l = Node("LegalReview")
s = Node("RequestSupplement")
approve = Node("Approve")
reject = Node("Reject")
notify = Node("Notify")

site_b_model.add_node(r)
site_b_model.add_node(i)
site_b_model.add_node(o)
site_b_model.add_node(d)
site_b_model.add_node(a)
site_b_model.add_node(l)
site_b_model.add_node(s)
site_b_model.add_node(approve)
site_b_model.add_node(reject)
site_b_model.add_node(notify)

# Order edges
site_b_model.add_arc(Arc(r, i))
site_b_model.add_arc(Arc(r, o))
site_b_model.add_arc(Arc(o, d)) # Physical dependency
site_b_model.add_arc(Arc(i, a))
site_b_model.add_arc(Arc(d, a))
site_b_model.add_arc(Arc(a, l))
site_b_model.add_arc(Arc(a, approve))
site_b_model.add_arc(Arc(a, reject))
site_b_model.add_arc(Arc(l, s))
site_b_model.add_arc(Arc(s, d))
site_b_model.add_arc(Arc(l, approve))
site_b_model.add_arc(Arc(l, reject))
site_b_model.add_arc(Arc(approve, notify))

# Convert B model to Petri net
site_b_net = convert_to_petri_net(site_b_model)

# Checks

# Playout

    print(t)
```

## 9. Recommendation

I recommend a conditional go. Site A's success should not be copied wholesale due to structural and regulatory divergences. The parallelization principle is valid but only for digital-first cases. Site B must segment its population before attempting intervention. Digital claims without physical original requirements can safely mirror Site A's concurrent tasks. This subgroup minimizes statutory conflict and maximizes overlap opportunities. However, physical-document cases require retaining sequential dependencies. Forcing parallelism here would create phantom completions and legal risks. Additionally, resource specialization differs. Site A used cross-trained staff; Site B relies on siloed roles. Shifting tasks without rebalancing capacity risks creating new bottlenecks at assessment or legal review. The pilot should target high-volume digital claims exclusively. Expansion relies on evidence showing no degradation in audit quality or review time. If rework rates increase significantly, the change should be paused. Implementation fidelity must be monitored via log quality. Site A's timestamp issues suggest weak controls; Site B should not replicate this weakness. Therefore, proceed only where constraints allow true parallel execution. Monitor downstream queues for signs of saturation before scaling to complex cases. This approach balances innovation with regulatory compliance. By isolating digital claims, we mitigate the risk of violating document receipt laws while testing the core efficiency theory. If this narrow segment shows gains without quality loss, we may cautiously extend to hybrid cases with strict WIP controls. Failure to validate these conditions could result in legal exposure and operational chaos.
