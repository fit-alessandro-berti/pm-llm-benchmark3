## 1. Stress scenarios

All scenarios assume baseline peak volume ~3,300 cases/week (vs 2,300 normal, +43%) but differ in *mix* and *resource availability*. Total volume alone is misleading: peak absolute loads are Urgent 414/wk -> 957/wk (+131%) and Complex-panel 299/wk -> 660/wk (+121%).

**S1 - Winter Infection Surge (Mix-shift dominant):** No equipment failure, no absences. Routine 42%, Urgent 29%, Complex-panel 20%, Repeat 9% as in observed peak. Courier arrival peaks at 10:00/17:00 remain. Tests the pure effect of contractual pressure + medical validation demand. This is not just "more cases" - it is more cases that *require* Medical validation (Complex 3.1x, Urgent contract 18h) and Hold for specialist review (Complex 2.4x).

**S2 - Assay Degradation / Half-outage:** S1 mix + M2 degraded (higher failure) or M1 offline for 48-72h. Historical signal: peak Assay run -> Repeat assay 1,260/8,140 = 15.5% vs normal 1,140/16,550 = 6.9%. Repeat assay -> Assay run median 10h -> 26h. Assay utilization normal 71% -> peak 98% with median queue 4.0h -> 18.0h. In this scenario effective capacity drops 25-40% while re-entrant load doubles.

**S3 - Validation Bottleneck / Specialist Absence:** S1 mix + 1-2 Medical validators unavailable (93% peak util, 22.0h median queue) and specialist review Friday pattern amplified to 3-day absence. Historical: Hold for specialist review 290 normal -> 610 peak (+110%), median Hold->Medical 18h -> 48h, Technical validation -> Medical 8h -> 24h, Technical validators already at 101% peak utilization (overload via overtime). Tests what happens when downstream sign-off, not machines, is constraint.

**S4 - Front-Door Collapse (Courier compression + Pre-analytical failure):** Early-winter snow + respiratory season: courier arrivals compress to single spike, accession errors rise. Pre-analytical check 74% -> 96% util, queue 1.8h -> 9.5h; Accession correction specialists (only 2) 62% -> 91% util, queue 3.0h -> 14.0h; Manual accession correction -> Test prep median 5h -> 16h; Request recollection 760 normal -> 780 peak but on smaller denominator (4.2% -> 8.0% of pre-analytical checks), Recollection -> Receive 42h -> 60h, Cancel after recollection 290 -> 370. Tests recollection loop consuming clerk/courier capacity that should be intake.

> S2, S3, S4 can co-occur (e.g., night shift + M2 use -> Repeat-after-failure clustering during S3 medical absence). Worst-case is not in averages.

## 2. Bottleneck-migration Analysis

Evidence used: Frequency DFG branching, Performance DFG median edge times, and station queue/utilization.

**S1 - Surge migration: Pre-analytical -> Assay -> Technical -> Medical/Specialist.** Front-door saturates first: Receive->Pre-analytical 2h->9h and Pre->Test prep 4h->13h. Accession correction queue at 14h blocks 420 cases. Only 8,530/9,730 go directly to Test prep vs 16,860/18,120 normal. Preparation benches (89% util, 11h queue) then Batch wait rises 760->1,180 cases, 6h->14h to batch, 9h->22h to assay. Urgent bypass falls 74%->58% so urgent cases fragment batches and lose their advantage. Assay (98%, 18h) feeds Repeat assay loop (median Repeat->Assay 26h). If Assay is relieved, work instantly appears at Technical validators (101%, 16h queue, 8h->24h to Medical) then at Medical (93%, 22h queue) and Specialist review (87%, 36h queue, 18h->48h edge). DFG shows Technical -> Medical 3,420/7,240 =47% vs normal 3,900/15,890=25% - surge doubles validation burden. Relieving assay without validation capacity simply moves the 16-24h queue downstream.

**S2 - Assay degradation migration: Assay -> Repeat loop -> Preparation starvation -> Validation idle then flood.** Initial bottleneck Assay. M2 higher failure rate + faster runtime tempts routing, but Repeat-after-failure cases already consume assay twice and cluster after M2/night shifts. Assay->Repeat median 3h->8h and Repeat->Assay 10h->26h creates re-entrant WIP that occupies M1/M2 while Preparation benches block (Batch wait 1180, but assays not available). Technical validation queue temporarily drops (no output), then when assays complete, a wave hits Technical (101%) and Medical simultaneously. Intervention I3 (dedicate M1 to Urgent/Complex, M2 to Routine) in this scenario risks: Routine on M2 generates more repeats -> even more assay load -> Routine p90 explodes beyond 120h while Urgent still waits for Technical validation (which is now shared). DFG proves rework is not waste but *second consumption of the scarcest resource*.

**S3 - Validation migration: Medical/Specialist -> Technical -> Assay blocking.** Medical queue 22h and Hold->Medical 48h are leading. Technical validators at 101% cannot clear to Release (Technical->Release falls 11,700/15,890=74% normal to 4,050/7,240=56% peak; more must go via Medical). Accession correction cross-training would pull from this same pool. If you add evening medical shift (I5) without controlling inflow, Technical validation becomes sole outlet (3.5h->16h) and assay machines block because they cannot hand off to Technical (Assay->Technical 5h->15h). Specialist unavailability every second Friday creates a 2-day cohort of Complex-panel that all become eligible Monday, spiking Medical->Release 2h->5h simultaneously.

**S4 - Front-door migration: Courier -> Registration -> Pre-analytical -> Recollection loop.** Courier intake 60%->88% util, 1.0h->7.5h; Registration 68%->85%, 0.7h->2.8h but error rate rises after 9h overtime - this creates the accession errors that feed Pre-analytical. Automating registration (I8) or smoothing couriers (I7) in isolation pushes arrivals faster into Pre-analytical (96%, 9.5h) and Accession correction (91%, 14h) which have *no* automation buffer. Performance shows Manual correction->Test prep 5h->16h and Pre->Request recollection 3h->7h. Every recollection loop costs 60h median plus clerk time explaining to physicians, reducing intake capacity further - a positive feedback. Relieving front-door without early defect triage (I6) increases rework from 7.5%->11.8% and re-clogs Assay with repeat-after-failure cases (peak 9% of mix but consumes ~18% of assay slots due to double use).

> General law: Historical median 38h/11h/64h is irrelevant. Peak p90 Routine 120h (vs 72h target +67% breach), Urgent 33h (vs 18h contract +83% breach), Complex 210h shows tail risk, not average, drives penalty and WIP explosion. Optimizing median via batching/prioritization fragments flow for other case types.

## 3. Robust Redesign Package

Principles: control inflow quality before capacity, make flow smooth not fast, keep validation pools flexible, never prioritize all types at once. Each intervention notes downstream overload risk.

**R1 - Front-door flow control [I6 + I7 + I8-light]: Early defect triage + Smoothed courier + Selective registration automation.** 
*What:* I6: within 2h of Receive, pre-analytical defect triage rejects poor samples with standardized physician message (no clerk negotiation). I7: shift courier slots from 2 spikes to 4 windows (08:00, 11:30, 15:00, 18:30) with reservation. I8: automate *only* orders with complete digital metadata (~30-40% of Routine), not Urgent/Complex.
*Why robust:* Works in S1,S3,S4,S2. Cuts recollection loops (source of 60h delays and clerk load) and reduces peak Pre-analytical 9.5h queue regardless of downstream bottleneck. Smoothing reduces Courier 7.5h queue and Pre-analytical 96% spikes without adding staff.
*Downstream risk:* If successful, exposes Preparation 11h and Assay 18h queues faster - must pair with R3 batching guardrails. Automation without triage would overload Pre-analytical (classic I8 risk).
*Assumptions:* Physicians accept early rejection in <2h vs 42-60h loop; courier contractors can stagger; IT can flag complete metadata reliably.
*Fails when:* Lab error is analytical not pre-analytical (S2 degradation) - triage doesn't reduce repeats.

**R2 - Pooled validation with protected core [Modified I4 + I5-standby]:**
*What:* Cross-train *one* (not two) technical validator to accession correction, with rule: trainee returns to validation if Technical queue >10h. Create *standby* evening medical validation shift (2 validators) that is *not* rostered by default, activated via triggers (see §4), funded by overtime budget, not permanent headcount.
*Why robust:* Accession correction has only 2 specialists; queue 14h blocks entire flow in all scenarios. One pooled worker relieves 91% util without dropping Technical below 95% (101% peak shows no slack for two). Evening shift addresses Medical 93%/22h and Specialist 36h queues that dominate S1/S3 p90.
*Downstream risk:* I4 relieves accession but starves Technical validation - the reason we limit to one and add re-entry trigger. Evening medical shift if always-on would pull cases forward and flood Release/admin or encourage over-reliance.
*Assumptions:* 4-week cross-training feasible; medical validators willing for peak standby; specialist review still needs medical sign-off.
*Fails when:* Both Technical and Accession peak simultaneously for >3 days - pool oscillates.

**R3 - Adaptive preparation & machine routing with guardrails [Modified I2 + Modified I3]:**
*What:* Keep batch size 12 for Routine (reject I2=24). Allow batch 16-18 *only* if Urgent share <25% *and* Assay queue <12h. Machine routing: M1 preferred for Urgent/Complex, M2 for Routine, but with automatic failover: if M2 repeat rate >10% in 24h or M1 queue >15h, routing opens to both machines (no hard dedication). Urgent bypass of Batch wait remains but capped at 65% to avoid fragmentation (vs 58-74% observed).
*Why robust:* Preserves preparation efficiency (69%->89% util) without starving Routine/Complex (I2/I3 conflicts). Hard dedication (I3) in S2 increases repeats; large batches (I2) delay Urgent. Guardrails make the policy *load-aware*.
*Downstream risk:* Larger batches improve preparation but increase Assay arrival burstiness -> Assay 18h queue and Technical 16h queue. Shared routing during degradation increases Technical validation load from repeats.
*Assumptions:* Batch size measurable in real time; machine repeat rate monitored daily.
*Fails when:* Both machines degraded - guardrail reverts to FIFO, which is correct but still slow.

We explicitly **reject** as always-on: I1 strict Urgent-first (starves Routine, inflates WIP, Routine p90 already 120h), I9 Hold Routine releases (adds waiting to already 62h median for Routine, reduces Release work but destroys 72h target), and unconditional I10 outsourcing (12h transport + traceability complexity hurts Urgent 18h SLA more than it helps Complex 210h p90 unless specialist queue is extreme).

## 4. Scenario-Specific Policies

Policies are off by default; triggers include both activation and deactivation to avoid oscillation.

**P-S1 Urgent surge - Priority with WIP cap (Conditional I1):**
*Trigger ON:* Urgent median queue >12h *and* Urgent p90 breach >25% of cases >18h for 2 consecutive days *and* Routine WIP <450 cases. *Trigger OFF:* Routine p90 >90h or Technical queue >14h. Action: Urgent-first at Preparation and Assay only, with WIP cap: max 30% of preparation slots to Urgent. Prevents starvation seen in hint I1.

**P-S2 Machine degradation - Rework containment (Conditional I3 + repeat brake):**
*Trigger ON:* Repeat rate >10% daily or M2 failure log >2 repeats/shift or Assay queue >20h. Action: Stop M2 for Routine, divert Routine to M1 in small batches, reduce M2 to low-complexity assays only; add mandatory second pre-analytical check for repeat-after-failure cases. Freeze Batch wait bypass for Urgent (force batch 8) to stabilize schedule fragmentation. *Trigger OFF:* Repeat rate <7% for 48h.

**P-S3 Validation surge - Evening surge plus Hold deflection (Conditional I5 + I10):**
*Trigger ON:* Medical validator median queue >15h or Hold for specialist review >30h for 48h *or* specialist absence >2 days. Action: Activate evening medical shift (3rd package R2) and, only if Specialist review queue >36h *and* Complex-panel share >18%, outsource *next-day* Complex-panel overflow to partner (I10) with explicit 12h transport budgeted - never Urgent. *Trigger OFF:* Medical queue <8h for 2 days - cease outsourcing first, then evening shift.

**P-S4 Front-door surge - Early triage escalation (Conditional I6+):**
*Trigger ON:* Pre-analytical queue >10h or Request recollection rate >7% of checks or Manual accession queue >12h. Action: Escalate to 1-hour defect triage, clerks use templated rejection (no phone explanation), registration overtime capped at 9h (error rise point) and excess routed to next courier window (I7). Cross-trained validator locked to accession. *Trigger OFF:* Pre-analytical queue <6h and recollection <5% for 2 days.

## 6. Residual Vulnerabilities

1.  **Evening medical demand induction:** R2/P-S3 succeeds and pulls Technical->Medical faster (8h->24h edge), then Technical validators (101% peak) become the hard constraint with no further pool to draw from. Optimizing Medical without adding Technical training creates a faster conveyor to a blocked station.
2.  **Automation-induced upstream flood (redesign-created):** R1 selective automation will temporarily increase effective arrival rate to Pre-analytical by ~20-30% without courier smoothing fully catching up. If I7 staggering fails (couriers cannot comply), Pre-analytical 96% -> >100% and Accession correction (only 2 specialists +1 trainee) overflows despite I6. This vulnerability is *caused by* relieving registration.
3.  **Correlated Friday+machine failure:** One specialist unavailable every second Friday + M2 degradation on night shift creates Repeat-after-failure clustering that our guardrailed routing cannot absorb. Historical: Repeat-after-failure 8%->9% but consumes double assay slots, so 9% of cases = ~18% of assay time. With Medical validators at 93% and Specialist review at 87%, a 3-day window can backlog 600 Complex/Urgent cases that need both machine and specialist, pushing p90 >240h.
4.  **Priority inversion under multiple triggers:** If S1 (urgent surge), S3 (medical absence) and S4 (courier crush) fire together, P-S1 (prioritize urgent) and P-S3 (evening medical) and P-S4 (lock validator to accession) conflict over the same flexible validator. No rule can satisfy all three SLA buckets; we must explicitly let Routine breach 72h to protect Urgent 18h contract - contractual penalty remains exposed.
5.  **Outsourcing traceability & quality drift:** I10 even when selective introduces 12h transport + handoff errors. DFG shows Cancel after recollection 290->370 peak; outsourced Complex-panel has higher risk of lost sample metadata, which circles back as Manual accession correction (14h queue). Partner capacity also surges in same winter wave - SLA may not hold.

## 7. Minimum Monitoring Dashboard

**Leading indicators (act before SLA breaches, review every 4-8h during peaks):**

*   **Queue + WIP:** Pre-analytical median queue (>6h yellow, >10h red); Accession correction queue (>8h / >12h) and WIP >80 cases; Preparation queue (>8h / >12h); Assay queue (>10h / >18h); Technical validation queue (>8h / >14h); Medical validator queue (>10h / >15h); Specialist review queue (>20h / >30h). *Why leading:* Performance DFG shows these edges inflate 2-3× before p90 moves.
*   **Mix & arrival:** % Urgent and % Complex-panel per 24h (yellow >25% Urgent, >18% Complex; red >30% / >20%); Courier arrival coefficient of variation and 10:00/17:00 spike ratio; Registration error rate after 9h shift.
*   **Flow quality:** Request recollection % of pre-analytical checks (yellow >6%, red >8%); Manual accession correction % (yellow >5%); Assay repeat rate 24h rolling (yellow >8%, red >10%) + M2 repeat count; Batch wait bypass % for Urgent (watch <60% or >75% both risky); WIP total cases in system (>600 red, peak normally ~450).
*   **Capacity signals:** Utilization proxy (queue growth rate); number of cases >12h in any queue (peak 54% vs 22% normal - track % cases with queue>12h daily, red >35%).

**Lagging outcome metrics (confirm impact, review daily):**

*   Median and p90 cycle time *per case type* (Routine vs 72h target, Urgent vs 18h contract, Complex-panel vs 64h/111h baseline); Urgent SLA breach % and penalty exposure; Rework % overall (7.5%->11.8%) and Repeat-after-failure share; Cancel order rate (570 normal vs 540 peak on fewer cases - rising); Release throughput vs intake (END 15,870 vs 8,040 per period) to detect WIP accumulation.

**Interpretation rule:** If leading queues rise but lagging p90 still normal, intervene early (front-door policies) - don't wait for median to move. If leading queues fall but lagging p90 stays high, bottleneck has migrated (e.g., Assay cleared but Medical 22h remains) - switch from R1 to P-S3. Do not anchor to normal-period averages (38h/11h) - judge against peak p90 bands (120h/33h/210h).
