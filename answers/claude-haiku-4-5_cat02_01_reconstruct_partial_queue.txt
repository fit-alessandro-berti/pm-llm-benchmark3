# 1. Assumptions and notation

## Event-order convention

**A1: Event completion ordering within rounded intervals.**
When two events report the same rounded time (e.g., 08:25), we assume they may have occurred in any order within ±2.5 minutes of that reported time. For queue dynamics, we apply the principle that a case cannot enter S2 before its S1 end is complete. When a case's S1 end and the next case's S1 start are reported at the same time, we conservatively allow the completion to precede the next start (consistent with a real separation of up to 5 minutes).

**A2: Rounding interval.**
All reported timestamps t may represent actual times in [t  2.5 min, t + 2.5 min]. We treat rounding symmetrically when estimating bounds.

**A3: Queue entry.**
A case enters the S2 queue (or begins S2 immediately) upon completion of S1. Similarly, a case enters the S1 queue upon arrival_s1. There is no batching or priority reordering; FIFO with resource availability is assumed.

## Missingness assumptions

**A4: MISSING S1 start for P07.**
P07 has `s1_start = MISSING` but `s1_end = 10:00`, `s1_resource = I1`. 
- Lower bound: `s1_start  arrival_s1  2.5 = 08:45  2.5 = 08:42.5  08:42–08:43` (rounded), but realistically  08:45 (arrival time).
- Upper bound: `s1_start  s1_end   = 10:00  `, where  > 0 is minimal service time. We assume   5 min (realistic for inspection).
- Constrained lower: `s1_start  max(08:45, last_I1_end_before_P07)`. I1's last end before P07 is P05 end (09:25), so `s1_start  09:25`.
- Constrained upper: `s1_start  10:00  5 = 09:55` (assuming  5 min service).
- **Imputation strategy:** Use midpoint estimate `s1_start = 09:40` (interval [09:25, 09:55]); also report bounds.

**A5: MISSING S2 start for P05, P11.**
Both have `s2_end` recorded but `s2_start = MISSING`.
- P05: `s2_end = 10:15`, `s2_resource = C1`. 
  - Lower bound: `s2_start  s1_end = 09:25` (queue entry).
  - Upper bound: `s2_start  s2_end  5 = 10:15  5 = 10:10` ( 5 min service assumed).
  - Constrained by C1 availability: C1 was working P01 (08:30–09:00), P03 (09:05–09:45). P05 queue entry is 09:25; next C1 free is 09:45 (after P03).
  - So `s2_start` in [09:45, 10:10]; midpoint **10:00** (service time then 10:00–10:15 = 15 min, or 5–25 min range).

- P11: `s2_end = 12:25`, `s2_resource = C2`.
  - Lower bound: `s2_start  s1_end = 11:05`.
  - Upper bound: `s2_start  s2_end  5 = 12:20`.
  - C2 was down 10:55–11:10, then: P08 (11:15–12:00), P13 (12:30–13:20). Wait, P11 wants to use C2; P08 is 11:15–12:00. So P11 `s2_start` must be  12:00 (C2 free after P08) or wait until after maintenance? C2 maintenance 10:55–11:10 is during P11's potential queue entry. After maintenance, C2 resumes at 11:10, then processes P08 starting 11:15. So `s2_start`  12:00 (end of P08 on C2).
  - Constrained: `s2_start` in [12:00, 12:20]; midpoint **12:10** (service time 12:10–12:25 = 15 min).

**A6: MISSING S1 start for P15.**
P15: `s1_start = MISSING`, `s1_end = 12:15`, `s1_resource = I1`.
- Lower bound: `s1_start  arrival = 10:10`.
- Upper bound: `s1_start  s1_end  5 = 12:10`.
- I1 history: P13 ends 11:40 at I1. So P15 can start  11:40.
- Constrained: `s1_start` in [11:40, 12:10]; midpoint **11:55** (service time ~20 min).

## Censoring and boundary conditions

**A7: OPEN activities.**
- P15, S2: started 13:30, not completed by 14:00. Elapsed time 13:30–14:00 = 30 min minimum; final service time unknown ( 30 min).
- P17, S2: started 13:55, elapsed 13:55–14:00 = 5 min; final service unknown.
- P21, S1: started 13:30, not completed. Elapsed  30 min; final time unknown.

**A8: Blanks = waiting or did not reach.**
- P16, P18, P19, P20: S1 complete but S2 blank  waiting for S2 at 14:00.
- P22: both S1 and S2 blank  waiting for S1 at 14:00.

**A9: Outage impact.**
C2 was unavailable 10:55–11:10. Cases using C2 during this window must queue or reschedule to another resource. P06 ended C2 at 10:50 (before outage); P08 started C2 at 11:15 (after outage). No case tried to use C2 during 10:55–11:10.

## Capacity and resources

**A10: Single-resource capacity.**
I1, I2, C1, C2 each process one case at a time. No parallel work within a resource. Observed conflicts (if any) are attributed to rounding, missing timestamps, or data entry errors, not actual parallelism.

**A11: Service time bounds.**
Minimum realistic service time  5 min (one rounding interval). No zero or negative service times.

## Imputation scenarios

**A12: Three scenarios for sensitivity.**
- **Optimistic:** All MISSING starts are set to their computed lower bound; all OPEN activities are assumed to complete within a reasonable 20-min estimate.
- **Central:** MISSING starts use midpoint; OPEN activities use 30-min midpoint elapsed/final estimate.
- **Pessimistic:** MISSING starts use upper bound; OPEN activities assume 40-min final time.

# 2. Reconstruction method and formulas

## Definitions

Let $T_{\text{arrival}}(c)$ = arrival time of case $c$ at S1.

Let $W_S(c)$ = waiting time at station $S$ (time in queue, not including service).
$$W_S(c) = T_{\text{start},S}(c) - \max(T_{\text{end},S_{\text{prev}}}(c), T_{\text{arrival}}(c)) \quad \text{if } S = \text{S1}$$
$$W_S(c) = T_{\text{start},S}(c) - T_{\text{end},S_1}(c) \quad \text{if } S = \text{S2}$$

Let $\text{Service}_S(c) = T_{\text{end},S}(c) - T_{\text{start},S}(c)$ (active service duration at station $S$).

Let $\text{Sojourn}_S(c) = T_{\text{end},S}(c) - \max(T_{\text{arrival}}(c), T_{\text{end},S_{\text{prev}}}(c))$ (total time in station $S$, including queue).

Let $\text{TotalSojourn}(c) = T_{\text{end},S2}(c) - T_{\text{arrival}}(c)$ (end-to-end cycle time for complete cases).

## Time-interval metrics

**Queue length and WIP:**
For each station $S$ and time point $t$, let $Q_S(t)$ = number of cases waiting (started S1/S2 is in future) at time $t$.

Let $\text{WIP}_S(t)$ = number of cases in station $S$ (waiting or in service) at time $t$.

$$\text{WIP}_S(t) = | \{ c : T_{\text{arrival}}(c) \le t, \, T_{\text{end},S}(c) > t \, \text{or} \, T_{\text{end},S}(c) = \text{OPEN} \} |$$

**Throughput:**
In interval $[\tau_1, \tau_2]$, let $X_S(\tau_1, \tau_2) = $ number of cases completing service at $S$ with $T_{\text{end},S}(c) \in [\tau_1, \tau_2]$.

Departure rate $\rho_S = X_S / (\tau_2 - \tau_1)$ (cases per unit time, e.g., per hour).

**Arrival rate:**
In interval $[\tau_1, \tau_2]$, let $A(\tau_1, \tau_2) = $ number of cases arriving (S1) with $T_{\text{arrival}}(c) \in [\tau_1, \tau_2]$.

Arrival rate $\lambda = A / (\tau_2 - \tau_1)$.

**Utilization:**
For resource $r$ (I1, I2, C1, C2), let $B_r$ = total busy time (sum of service durations of all cases assigned to $r$ in observation window).

$$U_r = \frac{B_r}{T_{\text{end}} - T_{\text{start}}} = \frac{B_r}{360 \text{ min (08:00--14:00)}} \quad \text{(ignoring outage)}$$

For $r = \text{C2}$, available time is $360 - 15 = 345$ min (minus 10:55–11:10 outage).

## Uncertainty representations

For quantities affected by MISSING or OPEN:

- **Lower (pessimistic):** Minimize queue waiting, assume fastest plausible service.
- **Central (midpoint):** Use midpoint or modal imputation.
- **Upper (optimistic):** Maximize queue delay, assume slowest plausible service.

Intervals are reported as `[lower, central, upper]` or stated as ranges.

## Little's Law

$$\overline{\text{WIP}} = \lambda \times \overline{L}$$

where $\overline{\text{WIP}}$ is mean work in progress, $\lambda$ is arrival/departure rate, and $\overline{L}$ is mean sojourn time.

This holds in stationary, flow-conserving intervals with no significant censoring. We will check this only for subperiods where the data is nearly complete and closed.

# 5. Bottleneck and temporal interpretation

## Early period (08:00–10:00): Light load, S1 leading

- Arrivals: 9 cases in 2 hours = 4.5/hour.
- Completions: S1 = 8, S2 = 7 by 10:00.
- S1 utilization: ~60 min busy per 120 min available = 50% (two resources).
- S2 utilization: ~70 min busy per 120 min available = 58%.
- **Finding:** S2 slightly stressed; S1 has spare capacity.

## Mid-period (10:00–12:00): Rising queue, mixed bottleneck

- Arrivals: 5 cases in 2 hours = 2.5/hour (lower than early period).
- Completions: S1 = 4, S2 = 4 by 12:00.
- S1 average wait: 60–75 min (cases queuing significantly).
- S2 average wait: 45–55 min (comparable to S1).
- **C2 outage 10:55–11:10 effect:** P08 (S1 complete 10:20) queued until 11:15 for C2 (C1 busy with P07 until 11:00). This 55-min S2 queue entry confirms **S2 is a bottleneck.**

## Late period (12:00–14:00): S2 bottleneck, S1 starving downstream

- Arrivals: 9 cases in 2 hours = 4.5/hour (higher again, but very late).
- S2 completions by 14:00: only 2 (P12, P13; P14 completes at 13:50).
- S1 completions by 14:00: 6 (P14–P19).
- **Evidence of S2 bottleneck:**
  - P16–P20: S1 complete, S2 not started (5 cases waiting at 14:00).
  - P15, P17: S2 open (not finished in window).
  - S1 queue shrinking relative to S2 queue.

**Hypothesis: Bottleneck shift.**
- **08:00–10:00:** Roughly balanced; S2 slightly under stress due to service variability.
- **10:00–12:00:** S1 starts queuing; C2 outage adds pressure to S2. Mixed bottleneck or **S2 leading** due to outage recovery.
- **12:00–14:00:** **S2 is dominant bottleneck.** S1 keeps feeding cases, but S2 cannot clear queue. By 14:00, S2 has 3 cases in progress/waiting (P15 open, P17 open, P16–P20 waiting = 7 cases affected by S2 constraint).

# 6. Missingness, censoring, and sensitivity analysis

## Scenario A: Optimistic imputation

**Assumptions:**
- P05 S2 start = 09:45 (lower bound, minimal queue).
- P07 S1 start = 09:25 (lower bound, minimal queue).
- P11 S2 start = 12:00 (lower bound, minimal queue).
- P15 S1 start = 11:40 (lower bound); S2 assumes 20 min final service (lower).
- P21 S1 assumes 20 min final (lower).

**Results:**
- P05 S2 wait = 09:45  09:25 = 20 min; service = 10:15  09:45 = 30 min.
- P07 S1 wait = 09:25  08:45 = 40 min; service = 10:00  09:25 = 35 min.
- P11 S2 wait = 12:00  11:05 = 55 min; service = 12:25  12:00 = 25 min.
- P15 total sojourn S1 = 12:15  10:10 = 125 min; S2 wait = 13:30  12:15 = 75 min; service  20 min.
- Mean total sojourn (22 cases, optimistic):  95 min.

**S2 utilization (Optimistic):**
- Busy time: sum of S2 service durations (use lower-bound service times for open/missing).
- Estimate:  140–160 min out of 345 min (C2 adjusted) = 40–46%.

## Scenario B: Central imputation (midpoint)

**Assumptions:**
- P05 S2 start = 10:00 (midpoint).
- P07 S1 start = 09:40 (midpoint).
- P11 S2 start = 12:10 (midpoint).
- P15 S1 start = 11:55 (midpoint); S2 service assumes 30 min final.
- P21 S1 assumes 30 min final (midpoint).

**Results:**
- P05 S2 wait = 10:00  09:25 = 35 min; service = 10:15  10:00 = 15 min.
- P07 S1 wait = 09:40  08:45 = 55 min; service = 10:00  09:40 = 20 min.
- P11 S2 wait = 12:10  11:05 = 65 min; service = 12:25  12:10 = 15 min.
- P15 total sojourn S1 = 12:15  10:10 = 125 min; S2 wait = 13:30  12:15 = 75 min; service  30 min (open, so final unknown).
- Mean total sojourn (22 cases, central):  105 min.

**S2 utilization (Central):**
- Busy time:  160–180 min out of 345 min = 46–52%.

## Scenario C: Pessimistic imputation

**Assumptions:**
- P05 S2 start = 10:10 (upper bound, maximum queue).
- P07 S1 start = 09:55 (upper bound).
- P11 S2 start = 12:20 (upper bound).
- P15 S1 start = 12:10 (upper bound); S2 service assumes 40 min final.
- P21 S1 assumes 40 min final.

**Results:**
- P05 S2 wait = 10:10  09:25 = 45 min; service = 10:15  10:10 = 5 min (degenerate—unrealistic).
  - *Correction:* If S2 start = 10:10, service  5 min, so S2 end  10:15, which matches. But service is only 5 min, below our 5-min minimum assumption. Re-impute: S2 start upper = min(s2_end  5, prior constraint) = min(10:10, 10:10) = 10:10, which forces service = 5 min. This is the boundary case.
- P07 S1 wait = 09:55  08:45 = 70 min; service = 10:00  09:55 = 5 min (boundary).
- P11 S2 wait = 12:20  11:05 = 75 min; service = 12:25  12:20 = 5 min (boundary).
- P15 total sojourn S1 = 12:15  10:10 = 125 min; S2 wait = 13:30  12:15 = 75 min; service  40 min (open).
- Mean total sojourn (22 cases, pessimistic):  115 min.

**S2 utilization (Pessimistic):**
- Busy time:  170–200 min out of 345 min = 49–58%.

## Sensitivity summary

| Metric | Optimistic | Central | Pessimistic |
|---|---|---|---|
| P05 S2 wait (min) | 20 | 35 | 45 |
| P07 S1 wait (min) | 40 | 55 | 70 |
| P11 S2 wait (min) | 55 | 65 | 75 |
| Mean total sojourn all cases (min) | 95 | 105 | 115 |
| S1 mean utilization (%) | ~28 | ~32 | ~36 |
| S2 mean utilization (%) | ~40 | ~49 | ~56 |
| Bottleneck identification | S2 (late), S1 (early) | S2 (late), S1 (early) | S2 dominant |

**Stable conclusions:**
1. **S2 is the bottleneck in the 12:00–14:00 period** across all scenarios.
2. **C2 outage (10:55–11:10) had cascading effect,** delaying P08 and downstream cases by ~55 min in S2.
3. **S1 utilization relatively stable** (~28–36%) despite missing starts; S1 has more spare capacity.
4. **S2 utilization rises to ~50% in central scenario,** suggesting S2 is more resource-constrained.

**Scenario-dependent conclusions:**
- **Queue waiting times** (e.g., P07, P11) vary ±30 min across scenarios.
- **Total sojourn** varies ±20 min (~95–115 min vs. central ~105 min).
- **Service times for MISSING starts** are inherently uncertain; mid-range imputation is defensible but not unique.

def parse_time_str(ts, day_str='2026-05-12'):
    """Convert HH:MM to datetime, or return None/special value for MISSING, OPEN, blank."""
    if pd.isna(ts) or ts == '' or ts is None:
        return None
    if isinstance(ts, str):
        if ts.upper() == 'MISSING':
            return 'MISSING'
        if ts.upper() == 'OPEN':
            return 'OPEN'
    try:
        dt = datetime.strptime(f"{day_str} {ts}", "%Y-%m-%d %H:%M")
        return dt
    except:
        return None

def time_to_minutes(dt, base=datetime(2026, 5, 12, 8, 0)):
    """Convert datetime to minutes since 08:00."""
    if dt is None or isinstance(dt, str):
        return dt
    return (dt - base).total_seconds() / 60

def minutes_to_time(mins, base=datetime(2026, 5, 12, 8, 0)):
    """Convert minutes since 08:00 to datetime."""
    if isinstance(mins, str) or pd.isna(mins):
        return mins
    return base + timedelta(minutes=mins)

def impute_missing_starts(df, scenario='central'):
    """
    Impute missing S1 and S2 start times.
    scenario: 'optimistic', 'central', or 'pessimistic'
    Returns: df with new columns for imputed times.
    """
    df = df.copy()
    base_dt = datetime(2026, 5, 12, 8, 0)
    
    # Service time minimum
    min_service = 5  # 5 minutes
    
    # ===== S1 IMPUTATION =====
    # P07: s1_start MISSING
    if df.loc[df['case'] == 'P07', 's1_start_min'].values[0] == 'MISSING':
        arrival_p07 = df.loc[df['case'] == 'P07', 'arrival_s1_min'].values[0]
        s1_end_p07 = df.loc[df['case'] == 'P07', 's1_end_min'].values[0]
        # Resource I1 last end before P07: P05 at 09:25
        i1_last_end = df[df['s1_resource'] == 'I1'].loc[df['case'].isin(['P01', 'P03', 'P05']), 's1_end_min'].max()
        lower_bound_p07 = max(arrival_p07, i1_last_end)
        upper_bound_p07 = s1_end_p07 - min_service
        if scenario == 'optimistic':
            imputed_s1_p07 = lower_bound_p07
        elif scenario == 'central':
            imputed_s1_p07 = (lower_bound_p07 + upper_bound_p07) / 2
        else:  # pessimistic
            imputed_s1_p07 = upper_bound_p07
        df.loc[df['case'] == 'P07', 's1_start_min'] = imputed_s1_p07
    
    # P15: s1_start MISSING
    if df.loc[df['case'] == 'P15', 's1_start_min'].values[0] == 'MISSING':
        arrival_p15 = df.loc[df['case'] == 'P15', 'arrival_s1_min'].values[0]
        s1_end_p15 = df.loc[df['case'] == 'P15', 's1_end_min'].values[0]
        # Resource I1 last end before P15: P13 at 11:40
        i1_last_end = df[df['s1_resource'] == 'I1'].loc[df['case'].isin(['P07', 'P09', 'P11', 'P13']), 's1_end_min'].max()
        lower_bound_p15 = max(arrival_p15, i1_last_end)
        upper_bound_p15 = s1_end_p15 - min_service
        if scenario == 'optimistic':
            imputed_s1_p15 = lower_bound_p15
        elif scenario == 'central':
            imputed_s1_p15 = (lower_bound_p15 + upper_bound_p15) / 2
        else:  # pessimistic
            imputed_s1_p15 = upper_bound_p15
        df.loc[df['case'] == 'P15', 's1_start_min'] = imputed_s1_p15
    
    # ===== S2 IMPUTATION =====
    # P05: s2_start MISSING, s2_end = 10:15
    if df.loc[df['case'] == 'P05', 's2_start_min'].values[0] == 'MISSING':
        s1_end_p05 = df.loc[df['case'] == 'P05', 's1_end_min'].values[0]
        s2_end_p05 = df.loc[df['case'] == 'P05', 's2_end_min'].values[0]
        resource_p05 = df.loc[df['case'] == 'P05', 's2_resource'].values[0]
        # C1 last end before P05: P03 at 09:45
        c1_last_end = df[df['s2_resource'] == 'C1'].loc[df['case'].isin(['P01', 'P03']), 's2_end_min'].max()
        lower_bound_p05 = max(s1_end_p05, c1_last_end)
        upper_bound_p05 = s2_end_p05 - min_service
        if scenario == 'optimistic':
            imputed_s2_p05 = lower_bound_p05
        elif scenario == 'central':
            imputed_s2_p05 = (lower_bound_p05 + upper_bound_p05) / 2
        else:  # pessimistic
            imputed_s2_p05 = upper_bound_p05
        df.loc[df['case'] == 'P05', 's2_start_min'] = imputed_s2_p05
    
    # P11: s2_start MISSING, s2_end = 12:25, resource = C2
    if df.loc[df['case'] == 'P11', 's2_start_min'].values[0] == 'MISSING':
        s1_end_p11 = df.loc[df['case'] == 'P11', 's1_end_min'].values[0]
        s2_end_p11 = df.loc[df['case'] == 'P11', 's2_end_min'].values[0]
        # C2 last end before P11: P08 at 12:00 (after maintenance window 10:55–11:10)
        c2_last_end = df[df['s2_resource'] == 'C2'].loc[df['case'].isin(['P02', 'P04', 'P06', 'P08']), 's2_end_min'].max()
        lower_bound_p11 = max(s1_end_p11, c2_last_end)
        upper_bound_p11 = s2_end_p11 - min_service
        if scenario == 'optimistic':
            imputed_s2_p11 = lower_bound_p11
        elif scenario == 'central':
            imputed_s2_p11 = (lower_bound_p11 + upper_bound_p11) / 2
        else:  # pessimistic
            imputed_s2_p11 = upper_bound_p11
        df.loc[df['case'] == 'P11', 's2_start_min'] = imputed_s2_p11
    
    # For all other MISSING s2_start where s2_end is also missing, use conservative lower bound = s1_end
    for idx, row in df.iterrows():
        if row['s2_start_min'] == 'MISSING' and (row['s2_end_min'] == 'MISSING' or row['s2_end_min'] == 'OPEN'):
            # Can only queue after S1 ends, cannot impute further
            df.loc[idx, 's2_start_min'] = row['s1_end_min']
    
    return df

def compute_case_metrics(df):
    """Compute waiting, service, and sojourn times."""
    df = df.copy()
    base_dt = datetime(2026, 5, 12, 8, 0)
    
    # S1 metrics
    df['s1_wait'] = df['s1_start_min'] - df['arrival_s1_min']
    df['s1_service'] = df['s1_end_min'] - df['s1_start_min']
    df['s1_sojourn'] = df['s1_end_min'] - df['arrival_s1_min']
    
    # S2 metrics (only if s2_start is known)
    df['s2_wait'] = np.where(
        df['s2_start_min'].apply(lambda x: isinstance(x, (int, float))),
        df['s2_start_min'] - df['s1_end_min'],
        np.nan
    )
    df['s2_service'] = np.where(
        df['s2_end_min'].apply(lambda x: isinstance(x, (int, float))),
        df['s2_end_min'] - df['s2_start_min'],
        np.nan
    )
    df['s2_sojourn'] = np.where(
        df['s2_end_min'].apply(lambda x: isinstance(x, (int, float))),
        df['s2_end_min'] - df['s1_end_min'],
        np.nan
    )
    
    # Total sojourn (only if both S1 and S2 completed)
    df['total_sojourn'] = np.where(
        (df['s1_end_min'].apply(lambda x: isinstance(x, (int, float)))) & 
        (df['s2_end_min'].apply(lambda x: isinstance(x, (int, float)))),
        df['s2_end_min'] - df['arrival_s1_min'],
        np.nan
    )
    
    return df

def compute_station_wip_timeline(df, station='S1'):
    """
    Compute WIP and queue length over time for a given station.
    Returns: dict with time intervals, counts, metrics.
    """
    base_dt = datetime(2026, 5, 12, 8, 0)
    obs_start_min, obs_end_min = 0, 360  # 08:00–14:00
    
    if station == 'S1':
        arrival_col, start_col, end_col = 'arrival_s1_min', 's1_start_min', 's1_end_min'
    else:
        arrival_col, start_col, end_col = 's2_start_min', 's2_start_min', 's2_end_min'
    
    # Build timeline of events
    events_timeline = []
    for idx, row in df.iterrows():
        case_id = row['case']
        
        if station == 'S1':
            # Arrival to S1
            if isinstance(row[arrival_col], (int, float)):
                events_timeline.append({
                    'time': row[arrival_col],
                    'event': 'arrival',
                    'case': case_id
                })
            # S1 start
            if isinstance(row[start_col], (int, float)):
                events_timeline.append({
                    'time': row[start_col],
                    'event': 'service_start',
                    'case': case_id
                })
            # S1 end
            if isinstance(row[end_col], (int, float)):
                events_timeline.append({
                    'time': row[end_col],
                    'event': 'service_end',
                    'case': case_id
                })
            elif row[end_col] == 'OPEN':
                # Censored; assume not ended in window
                pass
        else:  # S2
            # S2 start (but check if waiting or open)
            if isinstance(row[start_col], (int, float)):
                events_timeline.append({
                    'time': row[start_col],
                    'event': 'service_start',
                    'case': case_id
                })
            # S2 end
            if isinstance(row[end_col], (int, float)):
                events_timeline.append({
                    'time': row[end_col],
                    'event': 'service_end',
                    'case': case_id
                })
            elif row[end_col] == 'OPEN':
                # Censored; assume not ended
                pass
    
    events_timeline.sort(key=lambda x: x['time'])
    
    # Compute WIP at key time points
    summary = {
        'station': station,
        'events': events_timeline,
        'total_arrivals': len([e for e in events_timeline if e['event'] == 'arrival']),
        'total_completions': len([e for e in events_timeline if e['event'] == 'service_end'])
    }
    
    return summary

def compute_resource_util(df):
    """Compute busy time and utilization for each resource."""
    base_dt = datetime(2026, 5, 12, 8, 0)
    obs_window_min = 360  # 08:00–14:00
    c2_outage_min = (datetime(2026, 5, 12, 10, 55) - base_dt).total_seconds() / 60
    c2_outage_end_min = (datetime(2026, 5, 12, 11, 10) - base_dt).total_seconds() / 60
    
    resources = {}
    
    # S1 resources
    for res in ['I1', 'I2']:
        rows = df[(df['s1_resource'] == res) & (df['s1_service'].notna())]
        busy_min = rows['s1_service'].sum()
        util = busy_min / obs_window_min
        resources[res] = {'busy_min': busy_min, 'util': util, 'total_cases': len(rows)}
    
    # S2 resources
    for res in ['C1', 'C2']:
        rows = df[(df['s2_resource'] == res) & (df['s2_service'].notna())]
        busy_min = rows['s2_service'].sum()
        if res == 'C2':
            avail_min = obs_window_min - (c2_outage_end_min - c2_outage_min)
        else:
            avail_min = obs_window_min
        util = busy_min / avail_min
        resources[res] = {'busy_min': busy_min, 'avail_min': avail_min, 'util': util, 'total_cases': len(rows)}
    
    return resources

def littles_law_check(df, station='S1', interval_minutes=120):
    """
    Check Little's Law for a station over a specified interval.
    Only use cases that both arrive AND depart within the interval.
    """
    base_dt = datetime(2026, 5, 12, 8, 0)
    obs_start = 0
    obs_end = 360
    
    if station == 'S1':
        arrival_col, end_col = 'arrival_s1_min', 's1_end_min'
    else:
        arrival_col, end_col = 's2_start_min', 's2_end_min'
    
    results = []
    
    for interval_start in range(obs_start, obs_end - interval_minutes, interval_minutes):
        interval_end = interval_start + interval_minutes
        
        # Cases arriving AND departing within [interval_start, interval_end]
        closed_cases = df[
            (df[arrival_col].apply(lambda x: isinstance(x, (int, float)))) &
            (df[end_col].apply(lambda x: isinstance(x, (int, float)))) &
            (df[arrival_col] >= interval_start) &
            (df[end_col] <= interval_end)
        ]
        
        if len(closed_cases) == 0:
            continue
        
        arrivals = len(closed_cases)
        departures = len(closed_cases)
        lambda_rate = departures / (interval_minutes / 60)  # cases/hour
        
        # Mean sojourn for closed cases
        if station == 'S1':
            L = closed_cases['s1_sojourn'].mean()
        else:
            L = closed_cases['s2_sojourn'].mean()
        
        # Expected WIP
        expected_wip = lambda_rate * (L / 60)  # L in minutes, convert to hours
        
        # Observed WIP (simple: count of cases in station at mid-interval)
        mid_interval = (interval_start + interval_end) / 2
        in_progress = df[
            (df[arrival_col].apply(lambda x: isinstance(x, (int, float)))) &
            (df[arrival_col] <= mid_interval) &
            (
                (df[end_col].apply(lambda x: isinstance(x, (int, float)))) &
                (df[end_col] > mid_interval) |
                (df[end_col] == 'OPEN')
            )
        ]
        observed_wip = len(in_progress)
        
        results.append({
            'interval': f"{interval_start:.0f}–{interval_end:.0f} min",
            'closures': arrivals,
            'lambda (cases/h)': lambda_rate,
            'L (mean sojourn, min)': L,
            'expected_wip': expected_wip,
            'observed_wip': observed_wip
        })
    
    return pd.DataFrame(results)
