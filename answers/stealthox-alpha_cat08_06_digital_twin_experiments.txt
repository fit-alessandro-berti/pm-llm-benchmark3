# 1. Model scope and state variables

**Boundary.** The twin covers the end-to-end permit process: portal submission  completeness (with missing-document loops)  parallel reviews  public notice  inspection (with rework)  decision drafting  legal check  issue/reject, plus first-round appeal rework. Out of scope: fee/payment processing, post-permit construction compliance, court-level appeals, and the rare emergency decisions that were removed from the log (their exclusion is carried as a documented tail bias, not silently ignored). Applicants, architects, objectors, and environmental consultants are **exogenous stochastic actors** (response-time processes), not simulated municipal resources — except where interventions (D1, D7, D9) deliberately make applicant behavior partly endogenous.

**Level of detail.** Discrete-event simulation (DES) at activity level, minute resolution. Resources are capacity pools of interchangeable FTEs (with one skill split: two planners handle only Simple renovation). Inspector travel is a district-level time matrix added to Site inspection service; no route-level spatial simulation beyond batching travel savings.

**Entities and attributes**

| Entity | Key attributes |
|---|---|
| Case | case_type, district, architect_id (cluster tag), application_value, latent area proxy, requires_fire / env / notice (routing outcomes), prior_violation flag (latent), D2-eligibility, arrival time, SLA clock, aging class, rework counters per loop site, bundle_id, **latent** objection flag |
| Document request | parent case, request time, applicant response draw, reminder schedule (none in baseline) |
| Objection (**latent**, never observed) | cluster (architect × district), onset during notice, heavy-tailed extension draw |
| Inspection bundle | district, member cases, release time, per-case travel saving |
| Resource unit | pool, skill tags, calendar state, current assignment |

**Global state:** simulation clock; NHPP intensity state (month, day-of-week, trend); holiday and council-meeting calendars; backlog/WIP counters per stage; KPI accumulators.

**Queue state:** one FIFO structure per (activity × resource pool × priority class) with enqueue timestamps; inspection batching buffers per district; a legal "urgent lane" for council weeks; aging-priority override flag (active under D6).

**Resource state:** per pool — capacity function of time (below), busy units, reserved fractions; per busy unit — case, expected completion.

| Pool | Capacity | Calendar constraints |
|---|---|---|
| Clerks | 5 FTE (4 on Mondays) | Mon–Fri 08:00–16:00; 1 clerk on portal support Mondays |
| Planners | 8 FTE (2 simple-only) | Mon–Fri 09:00–17:00 |
| Fire reviewers | 2 FTE | Tue–Thu only |
| Environmental reviewers | 3 × 0.6 = 1.8 effective FTE | Mon–Fri; 40% reserved for non-permit duties |
| Inspectors | 4 FTE (+1 temp in peak months under D4) | Tue–Fri field days; district travel matrix (D3/D5 longer) |
| Legal officers | 2 FTE (0.2 urgent lane in council weeks) | Blocked during council-meeting weeks |
| Portal/system |  | — |

**Cross-case dependencies (explicitly modeled; independence is rejected):**
1. **Shared resource pools** — the primary coupling channel; all cases interact through queues.
2. **Architect submission bursts** — compound NHPP: top-20 architects (31% of volume) trigger same-week correlated batches.
3. **Inspection bundling** — related same-district cases share slots: first-in-bundle waits longer, travel per case drops.
4. **Objection clusters** — correlated public-notice extensions among related cases (same architect/district).
5. **Calendar shocks** — holidays and council weeks hit all in-system Legal check / Public-notice cases simultaneously.
6. **Policy-induced shifts** — D2 removes inspection demand (frees inspectors for others), D7 re-times arrivals, D6 changes queue discipline (fairness coupling), D8 shifts environmental load between classes.

**Latent state (calibrated, never treated as observed):** objection process, building-area threshold, environmental-sensitivity flags, prior violations, emergency-case absence.

# 2. Parameter-estimation plan

**PM4Py's role (analytics and calibration targets only — it never simulates).**
- Ingest: `pandas.read_csv`  `pm4py.format_dataframe(case_id=..., activity_key=..., timestamp_key=...)`  `pm4py.convert_to_event_log`.
- Control flow: `pm4py.stats.get_variants` (variant frequencies per case type), `pm4py.discover_dfg`, `pm4py.discover_performance_dfg` (edge sojourn statistics  waiting calibration targets), `pm4py.parse_process_tree` for the nominal tree, `pm4py.discover_petri_net_inductive` for a reference net used in conformance.
- Conformance: `pm4py.fitness_token_based_replay`, `pm4py.precision_token_based_replay`, `pm4py.conformance_diagnostics_alignments` (on a stratified sample).
- Timing: `pm4py.statistics.service_time.log.get.get_service_time` where start stamps exist; `pm4py.statistics.traces.generic.log.case_arrival.get_case_arrival_average` for arrival cadence; time-range filtering for hold-outs.

**(a) Arrivals.** Non-homogeneous Poisson process (t) =  · s_month(m) · s_dow(d) · (optional trend). From 31,200 cases / 18 months  57.8/day average; with the 1.7× seasonal weights the implied baseline is  43/day off-peak and  74/day in Mar–May / Sep–Nov. Estimate  and multipliers by Poisson regression on daily counts; anchor Monday = 2.2 × Wednesday and fit remaining day-of-week factors; intra-day submission times from the empirical CDF. **Bursts:** detect architect-week clusters; estimate batch probability and batch-size distribution (negative binomial) for top-20 architects; implement as compound arrivals with correlated district/type within a batch.

**(b) Service times.** Where start+completion exist: direct durations; fit log-normal per activity × case type ( = ln(p90/median)/1.2816 when fitting from quantile summaries); splice a generalized-Pareto tail above p90 where tails are heavier. **Completion-only activities:** the service/waiting split is *not identifiable from the log alone*. Remedy: (i) calendar-aware lower bounds, (ii) transfer of service/waiting ratios from activities with start stamps, (iii) treat the service mean as a **calibration parameter** tuned until simulated waiting reproduces observed waiting medians. Every inferred parameter is flagged and carries wider uncertainty.

**(c) Waiting times — explicit limitation.** Observed waiting medians (e.g., Planning 6 d, Environmental 8 d) are **calibration/validation targets, never simulation inputs** — waiting must emerge from queueing in the twin, otherwise it would be double-counted. Any published service/waiting split for completion-only activities is model-based inference, not observation.

**(d) Branching and rework.** Per case type: P(missing-doc loop), loop-count distribution (geometric/negative binomial on repeated activities), P(fire), P(env), P(notice), P(legal), P(reject), rework probabilities after Planning/Inspection/Legal, appeal probability — from variant shares, refined with logistic models on value/district/architect where sample size supports. Latent thresholds (building area, environmental sensitivity) are calibrated to marginal rates and carried as uncertain parameters (±20% relative sensitivity). Inspection no-show rates estimated from schedulinginspection gaps.

**(e) Resource calendars.** HR-derived templates encoded as capacity functions c_pool(t) exactly as tabulated in §1. Because they are HR-reconstructed, not event-derived, they are validated by comparing simulated vs. observed activity-count histograms by hour/weekday and adjusted within ±10%.

**(f) Dependencies.** Bundling: detect same-district/same-day inspection clusters in the log  baseline bundling rate, bundle-size distribution, travel saving per bundle size. Objections: **not observed** — a latent Bernoulli process p_obj(type, district, architect cluster) plus a heavy-tailed extension is calibrated by simulated method of moments so that simulated Public-notice durations match the observed distribution (median 14 d, p90  60 d). Objections are never counted as observed events.

**(g) Non-stationarity.** Monthly and day-of-week multipliers estimated from the full window; case-mix stationarity across seasons tested (²) — if unstable, the mix becomes month-dependent; council calendar exogenous.

**(h) Missing data.** Missing start timestamps  imputation via calibration, with widened parameter variance (multiple parameter draws per replication); removed emergency cases  tails slightly underestimated, covered by a tail stress scenario; unstructured rework reasons  rework modeled as rates only, homogeneous within variant group; flattened log  dependency strength likely underestimated, mitigated with architect/district cluster features and acknowledged as residual bias.

# 3. Assumptions

Tags: **[F]** fitted from log, **[C]** calibrated latent, **[E]** expert-imposed.

**Arrivals**
- Compound NHPP; seasonal 1.7× (Mar–May, Sep–Nov), Dec  0.8 [F]; Monday 2.2× Wednesday [F], other DOW factors fitted [F].
- Top-20 architects generate 31% of cases in same-week batches; batch members correlated in district and type [F/E].
- No abandonment or reneging (unobservable) [E]; sensitivity-tested.
- Case attributes independent conditional on architect cluster [E].

**Service times**
- Log-normal bodies with GPD tails above p90; case-type refinements [F/E].
- Completion-only splits are inferred calibration parameters, reported as uncertain [C].
- Travel added to Site inspection from district matrix (D3, D5 larger) [F/E]; no-show probability fitted [F].
- Public notice: 14-day fixed minimum [F/policy]; all extension comes from the latent objection process [C].
- System activities  0 service, unlimited capacity [F].

**Routing**
- Branching probabilities per case type from variant shares; covariate refinements where supported [F].
- Latent thresholds calibrated to marginals, ±20% sensitivity [C].
- D2 eligibility = value < €50k and no prior violations; violation prevalence assumed  5% [E]; D2 assumed not to raise downstream rework (tested at +10pp in sensitivity) [E].
- D8 triage misrouting rate assumed 5–10% [E].

**Resources / calendars**
- HR templates used with ±10% capacity uncertainty [C]; no absenteeism in baseline (stress S2 adds it) [E].
- Environmental effective capacity 1.8 FTE; fire Tue–Thu; legal zero in council weeks except urgent lane [F/HR].
- FTEs interchangeable within pool; two planners restricted to Simple renovation [F].

**Rework**
- Loop counts geometric/negative binomial per site [F]; reasons not modeled (unstructured) — stated limitation.
- Rework service = 1.0–1.2× base activity [E]; appeal returns the case to Decision drafting with small per-type probability [C].

**Applicant / third-party response**
- Missing-document response: heavy-tailed log-normal, median 5 d, p90  15 d [F from requestreceive gaps]; never merged with municipal service times.
- Objection extension | objection: log-normal median  30 d, p90  90 d [C]; correlated within architect clusters [C].
- Environmental consultant-report delays inflate a subset of env services [E]; D1 shifts applicant effort pre-submission (fewer loops, small submission delay) [E].

**Cross-case dependencies**
- Coupling only via the six mechanisms listed in §1; no other spillovers [E].
- Baseline bundling behavior as observed; D3 imposes fixed batching windows [E]; FIFO discipline at baseline, aging override under D6 [policy].

**Non-stationary demand**
- Multipliers stable over the horizon; optional trend term tested [F/E]; council calendar repeats annually [E]; case-mix seasonality tested, made month-dependent if rejected [F].

**Missing data**
- Imputation adds variance, assumed not bias [C]; emergency exclusion biases tails low (stress-covered); objection proxy only — never treated as observed; flattened-log dependency underrepresentation acknowledged; HR calendars may misalign with real work (validated against event histograms).

# 5. Warm-up, replications, and uncertainty treatment

- **Run length and warm-up.** Horizon 48 months (covers 3 full seasonal cycles and council calendars); warm-up 6 months, chosen via **Welch's method** on daily WIP and weekly median cycle time averaged over 20 replications — the warm-up must span into a peak season so queues start realistically filled. Alternatively, a 6-month pre-run seeds the initial state (initial backlog drawn from the observed end-of-snapshot WIP). KPIs are computed only after warm-up.
- **Replications.** 50 per cell for screening; 150–200 for finalists and any cell feeding a decision. **Common random numbers:** replication *i* uses child seed *i* in every cell, so intervention vs. baseline differences are paired; report CIs on **paired differences**.
- **Seeds.** `numpy.random.SeedSequence(base).spawn(n_reps)`, each replication further spawned into 7 independent streams (arrivals, routing, service, applicant response, objections, travel, calendar noise) to prevent cross-stream correlation.
- **Uncertainty quantification.** Means: 95% t-intervals. Tail quantiles (p90/p95): bootstrap across replications (B = 2000). **Two-level uncertainty:** stochastic noise (replications) × parameter uncertainty (100 draws of latent/inferred parameters — objection probability and extension, applicant response, inferred service means, environmental reserved fraction — each with 10 replications), with a variance decomposition reported so the municipality knows whether conclusions are noise-limited or knowledge-limited.
- **Heavy tails.** Spliced log-normal/GPD service and response distributions; decisions keyed to **medians and p90, never means alone**; tail-stability check (double replications; flag if p90 CI shifts >5%); Complex variance (p90 260 d) gets dedicated tail diagnostics; emergency-case exclusion handled by a tail stress scenario rather than ignored.
- **Sensitivity analysis.** OFAT ±20% on: seasonal amplitude, Monday factor, objection probability, objection extension median, applicant response median, environmental reserved fraction, D2 violation prevalence; inferred service means ±25%. Sobol indices (k = 6, N  512) for finalist interventions only.
- **Stopping rule.** Replications increase until the half-width of the paired-difference CI  5% of the baseline estimate, capped at 200.

# 6. Validation strategy

1. **Face validation.** Walkthroughs with planners, clerks, fire/legal staff; trace animation of simulated Complex variance cases; review of policy logic (D2 eligibility, D6 aging) with policy owners; plausibility of variant frequencies.
2. **Event-log replay / conformance.** Discover a reference Petri net with `pm4py.discover_petri_net_inductive`; fitness/precision via token-based replay on the log; alignment-based conformance on a stratified sample per variant group. Then convert simulated traces to an event log and compute the same metrics: target fitness  0.90 on both; simulated-vs-observed variant distribution total-variation distance  0.10.
3. **Distributional validation.** Per-activity service times (where observed): KS/AD tests and Q–Q plots. Case-duration distributions per variant group: simulated median within ±15% and p90 within ±20% of the empirical table (e.g., New residential with fire+notice: 48 d / 95 d; Complex variance: 140 d / 260 d). Public-notice duration distribution is a primary calibration target for the latent objection model.
4. **Resource-utilization validation.** Compare simulated busy fractions per pool against log-inferred bounds (completion counts × median service ÷ calendar capacity); verify the Monday clerk spike, Tue–Thu fire concentration, and the environmental 1.8-FTE effect reproduce observed waiting patterns; tolerance ±5 percentage points.
5. **Bottleneck validation.** Spearman rank correlation  0.8 between simulated and observed waiting medians across activities; top-3 bottlenecks (environmental, planning, inspection) must match.
6. **Out-of-sample validation.** Hold out the final 3 months (and separately the Sep–Nov peak): refit on the first 15 months, predict hold-out throughput, per-type median duration, and notice-duration distribution; acceptance: duration error  10%, throughput error  10%. A model that only reproduces the calibration period is not signed off.
7. **Calibration protocol.** Two stages: (i) direct fitting of marginals (§2), (ii) simulated-method-of-moments / ABC for latent parameters against waiting medians, variant shares, monthly throughput, and the Monday spike, with documented acceptance thresholds and a registry of every calibrated parameter.

# 7. Decision criteria

| Metric | Definition | Adoption threshold |
|---|---|---|
| Median cycle time (per case type) | Submit  decision, post-warm-up | 10% reduction vs. baseline; paired 95% CI excludes 0 |
| Tail duration (p90/p95, per type) | Same, upper quantiles | 10% reduction; 5% degradation tolerated only if median gain 15% |
| SLA compliance | % within {Simple 30 d, New residential 60 d, Commercial 90 d, Complex variance 180 d} | 85% per type; no type 5 pp vs. baseline |
| District fairness | max over districts of (median_d / median_all) | 1.25; no district >10% worse than baseline |
| Architect fairness | median(top-20 architects) / median(rest) | within ±5% of baseline |
| Resource utilization | Busy fraction per pool | mean in 0.70–0.90; 0.95 in stress peaks |
| Rework | % cases with 1 rework loop; rework hours per case | increase 2 pp / 5% |
| Backlog | End-of-horizon WIP; share waiting >90 d | WIP  baseline; >90 d share reduced |
| Robustness | SLA compliance under S1–S3 | thresholds met in 2 of 3 primary stress scenarios |
| Cost proxy | Added FTE-days per 100 permits | reported; weighted by the municipal budget constraint |

**Decision rule.** (1) Paired CRN comparison of every intervention vs. baseline; (2) Pareto screen on (median, tail, fairness, cost); (3) robustness filter over stress scenarios; (4) D10 is preferred only if it dominates the best single intervention or its gain exceeds the additive sum of components minus an interaction discount; (5) recommended interventions go to a staged pilot, and the twin is **recalibrated after each rollout** — it is a living model.

**Explicit limitation:** the twin ranks and stress-tests interventions under stated assumptions; it does **not** prove global optimality, and no such claim is made before calibration (§6) and pilot confirmation.

def load_log_df(csv_text: str = EXCERPT_CSV) -> pd.DataFrame:
    raw = pd.read_csv(io.StringIO(csv_text))
    df = pm4py.format_dataframe(
        raw,
        case_id="case:concept:name",
        activity_key="concept:name",
        timestamp_key="time:timestamp",
    )
    df["time:timestamp"] = pd.to_datetime(df["time:timestamp"])
    return df.sort_values(["case:concept:name", "time:timestamp"]).reset_index(drop=True)


def add_timing_columns(df: pd.DataFrame) -> pd.DataFrame:
    """
    Split service vs waiting ONLY where start timestamps exist.
    With completion timestamps only, the inter-event gap conflates queueing
    delay + service + calendar idle time; it is kept as 'inter_event_gap_s'
    and is deliberately NOT labelled as service or waiting. For the full log,
    inferred splits for completion-only activities come from the calibration
    procedure (Section 2), not from this column.
    """
    df = df.copy()
    if "start:timestamp" in df.columns:
        df["start:timestamp"] = pd.to_datetime(df["start:timestamp"])
        df["service_s"] = (df["time:timestamp"] - df["start:timestamp"]).dt.total_seconds()
        prev_end = df.groupby("case:concept:name")["time:timestamp"].shift(1)
        df["waiting_s"] = (df["start:timestamp"] - prev_end).dt.total_seconds()
    else:
        prev_end = df.groupby("case:concept:name")["time:timestamp"].shift(1)
        df["inter_event_gap_s"] = (df["time:timestamp"] - prev_end).dt.total_seconds()
        df["service_s"] = np.nan   # not identifiable from this excerpt
        df["waiting_s"] = np.nan   # not identifiable; calibrated in simulation
    return df


# ===========================================================================
# Layer 1b -- PM4Py analytics (calibration targets)
# ===========================================================================

def pm4py_analytics(df: pd.DataFrame) -> dict:
    log = pm4py.convert_to_event_log(df)
    out: dict = {}

    # Variants
    out["variants"] = pm4py.stats.get_variants(log)

    # Frequency DFG
    dfg, start_activities, end_activities = pm4py.discover_dfg(log)
    out["dfg"], out["start_activities"], out["end_activities"] = dfg, start_activities, end_activities

    # Performance DFG (edge sojourn statistics -> waiting calibration targets).
    # pm4py 2.x returns (dfg, start_acts, end_acts, act_occurrences, edge_perf).
    perf = pm4py.discover_performance_dfg(log)
    out["performance_dfg"] = perf[0]
    out["edge_performance"] = perf[-1]

    # Average time between consecutive case starts (seconds)
    from pm4py.statistics.traces.generic.log import case_arrival
    out["avg_case_arrival_seconds"] = case_arrival.get_case_arrival_average(log)
    first_ts = df.groupby("case:concept:name")["time:timestamp"].min().sort_values()
    out["avg_case_arrival_seconds_pandas"] = float(first_ts.diff().dt.total_seconds().mean())

    # Service-time statistics where activity timing allows (completion-only
    # activities reflect inter-event gaps, not true service -- see caveat).
    try:
        from pm4py.statistics.service_time.log import get as svc_get
        out["service_time_stats"] = svc_get.get_service_time(log)
    except Exception as exc:
        out["service_time_stats"] = f"unavailable: {exc}"
    return out

def parse_nominal_tree():
    return pm4py.parse_process_tree(TREE_STRING)

SLA_TARGET_DAYS = {"Simple renovation": 30, "New residential": 60,
                   "Commercial": 90, "Complex variance": 180}
DISTRICT_TRAVEL_H = {"D1": 0.5, "D2": 0.5, "D3": 1.5, "D4": 0.75, "D5": 1.5}  # fit from log


@dataclass

    D1_pre_submission_checker: bool = False
    D2_skip_inspection_low_value: bool = False
    D3_district_batching: bool = False
    D4_temp_inspector_peak_months: bool = False

    D6_aging_planner_reserve: bool = False
    D7_appointment_slots: bool = False
    D8_env_triage: bool = False
    D9_objection_early_warning: bool = False
    batching_window_days: float = 3.5     # active when D3
    aging_threshold_days: float = 45.0    # active when D6


@dataclass
class ScenarioConfig:
    demand_multiplier: float = 1.0
    fire_capacity_factor: float = 1.0
    legal_capacity_factor: float = 1.0
    objection_probability_multiplier: float = 1.0
    applicant_response_multiplier: float = 1.0
    extra_council_weeks_per_year: int = 0


def fit_lognormal(median: float, p90: float):
    """Log-normal parameters from quantile summaries (hours or days)."""
    sigma = (np.log(p90) - np.log(median)) / 1.2815515655446004  # z_{0.90}
    mu = np.log(median) - 0.5 * sigma * sigma
    return mu, sigma


class ArrivalGenerator:
    """NHPP with monthly + day-of-week seasonality and architect batch bursts
    (compound arrivals). Multipliers refit from the full 18-month log."""
    MONTH_FACTOR = {1: 1.0, 2: 1.0, 3: 1.7, 4: 1.7, 5: 1.7, 6: 1.0, 7: 1.0,
                    8: 1.0, 9: 1.7, 10: 1.7, 11: 1.7, 12: 0.8}
    DOW_FACTOR = {0: 2.2, 1: 1.5, 2: 1.0, 3: 1.1, 4: 1.3, 5: 0.4, 6: 0.3}  # Mon..Sun; Mon/Wed anchored
    CASE_TYPES = ["Simple renovation", "New residential", "Commercial", "Complex variance"]
    CASE_TYPE_P = [0.45, 0.28, 0.17, 0.10]
    TOP20_SHARE = 0.31
    BATCH_TRIGGER_P = 0.14  # P(an arrival opens a same-week batch); fit from architect-week clusters

    def __init__(self, rng: np.random.Generator, scenario: ScenarioConfig):
        self.rng, self.scenario = rng, scenario
        mean_factor = float(np.mean(list(self.MONTH_FACTOR.values())))
        self.base_per_day = (31200 / (18 * 30.44)) / mean_factor  # ~43/day off-peak

    def intensity(self, ts: pd.Timestamp) -> float:
        return (self.base_per_day * self.scenario.demand_multiplier
                * self.MONTH_FACTOR[ts.month] * self.DOW_FACTOR[ts.dayofweek])

    def sample_arrivals(self, t_start, t_end):
        """Thinned NHPP + architect batches; yields (timestamp, case_attrs)."""
        lam_max = self.base_per_day * self.scenario.demand_multiplier * 1.7 * 2.2
        t = t_start
        while t < t_end:
            t += pd.Timedelta(hours=float(self.rng.exponential(24.0 / lam_max)))
            if t >= t_end:
                break
            if self.rng.random() < self.intensity(t) / lam_max:
                yield t, self._draw_case(t)
                if self.rng.random() < self.BATCH_TRIGGER_P:
                    for _ in range(int(self.rng.integers(1, 4))):  # same architect, same week
                        dt = pd.Timedelta(days=float(self.rng.uniform(0, 5)))
                        yield t + dt, self._draw_case(t + dt, same_architect=True)

    def _draw_case(self, t, same_architect=False):
        return {"case_type": self.rng.choice(self.CASE_TYPES, p=self.CASE_TYPE_P),
                "district": f"D{int(self.rng.integers(1, 6))}",
                "architect_id": "A17" if same_architect else f"A{int(self.rng.integers(1, 60))}",
                "application_value": float(np.exp(self.rng.normal(11.5, 1.2))),  # placeholder; fit per type
                "submit_ts": t}


class RoutingModel:
    """Branching probabilities / rework loop counts per case type. Initial
    values anchored to the variant-share summary; refit from the full log
    (frequencies + logistic models on value/district/architect)."""
    P = {
        "Simple renovation": dict(missing_docs=0.42, fire=0.02, env=0.02, notice=0.05, legal=0.05,
                                  reject=0.05, planning_rework=0.03, inspection_rework=0.05,
                                  legal_rework=0.01, appeal=0.01),
        "New residential":   dict(missing_docs=0.35, fire=0.85, env=0.20, notice=0.65, legal=0.30,
                                  reject=0.08, planning_rework=0.08, inspection_rework=0.10,
                                  legal_rework=0.03, appeal=0.02),
        "Commercial":        dict(missing_docs=0.30, fire=0.90, env=0.90, notice=0.30, legal=0.90,
                                  reject=0.10, planning_rework=0.10, inspection_rework=0.12,
                                  legal_rework=0.05, appeal=0.03),
        "Complex variance":  dict(missing_docs=0.40, fire=0.70, env=0.70, notice=1.00, legal=0.90,
                                  reject=0.15, planning_rework=0.25, inspection_rework=0.20,
                                  legal_rework=0.10, appeal=0.10),
    }

    def __init__(self, rng: np.random.Generator):
        self.rng = rng

    def sample_route(self, case: dict) -> dict:
        p = self.P[case["case_type"]]
        r = self.rng
        loops = int(r.geometric(0.55)) if r.random() < p["missing_docs"] else 0
        return {"n_missing_doc_loops": loops,
                "fire": r.random() < p["fire"], "env": r.random() < p["env"],
                "notice": r.random() < p["notice"], "legal": r.random() < p["legal"],
                "reject": r.random() < p["reject"],
                "planning_rework": r.random() < p["planning_rework"],
                "inspection_rework": r.random() < p["inspection_rework"],
                "legal_rework": r.random() < p["legal_rework"],
                "appeal": r.random() < p["appeal"]}


class ServiceTimeModel:
    """Log-normal service distributions (hours) anchored to the empirical
    median/p90 table; heavy tails beyond p90 get a GPD splice at calibration.
    Case-type refinement added at calibration. Travel is added for Site
    inspection. Applicant-side delays live in ApplicantResponseModel, NOT here."""
    H = {
        "Completeness check": fit_lognormal(25 / 60, 90 / 60),
        "Request missing documents": fit_lognormal(10 / 60, 25 / 60),
        "Planning review": fit_lognormal(3.5, 14.0),
        "Fire-safety review": fit_lognormal(2.5, 9.0),
        "Environmental review": fit_lognormal(4.0, 18.0),
        "Inspection scheduling": fit_lognormal(20 / 60, 1.0),
        "Site inspection": fit_lognormal(1.0, 3.0),
        "Decision drafting": fit_lognormal(2.0, 8.0),
        "Legal check": fit_lognormal(3.0, 16.0),
        "Issue permit": fit_lognormal(5 / 60, 20 / 60),
        "Reject application": fit_lognormal(0.5, 2.0),
    }

    def __init__(self, rng: np.random.Generator):
        self.rng = rng

    def sample(self, activity: str, case: dict, with_travel: bool = False) -> float:
        mu, sigma = self.H[activity]
        t = float(self.rng.lognormal(mu, sigma))
        if with_travel:
            t += DISTRICT_TRAVEL_H[case["district"]]
        return t


class ApplicantResponseModel:
    """Exogenous applicant behaviour. Missing-document response is HEAVY-TAILED
    and applicant-driven; it is never merged with municipal service times."""
    def __init__(self, rng: np.random.Generator, scenario: ScenarioConfig):
        self.mu, self.sigma = fit_lognormal(5.0, 15.0)   # days; refit from request->receive gaps
        self.rng, self.scenario = rng, scenario

    def sample_missing_docs_response_days(self) -> float:
        return float(self.rng.lognormal(self.mu, self.sigma)
                     * self.scenario.applicant_response_multiplier)


class ObjectionModel:
    """Objection events are NOT in the log. This is a LATENT process calibrated
    so simulated public-notice durations reproduce the observed distribution
    (median 14 d, p90 ~60 d). Objections are never treated as observed events;
    all parameters carry calibration uncertainty (Section 5)."""
    P_OBJECTION = {"Simple renovation": 0.05, "New residential": 0.20,
                   "Commercial": 0.25, "Complex variance": 0.50}

    def __init__(self, rng: np.random.Generator, scenario: ScenarioConfig):
        self.rng, self.scenario = rng, scenario
        self.mu_ext, self.sigma_ext = fit_lognormal(30.0, 90.0)  # extra days | objection

    def sample(self, case: dict):
        p = min(self.P_OBJECTION[case["case_type"]]
                * self.scenario.objection_probability_multiplier, 1.0)
        if self.rng.random() < p:
            return True, float(self.rng.lognormal(self.mu_ext, self.sigma_ext))
        return False, 0.0


class MunicipalCalendar:
    """HR-derived capacity templates (reconstructed, not event-derived:
    validate against activity-count histograms; +-10% capacity uncertainty)."""
    def __init__(self, scenario: ScenarioConfig, interventions: InterventionConfig | None = None,
                 holidays=None, council_weeks=None):
        self.scenario = scenario
        self.interventions = interventions or InterventionConfig()
        self.holidays = holidays or set()        # set of datetime.date
        self.council_weeks = council_weeks or set()  # ISO week numbers

    def _workday(self, ts):
        return ts.dayofweek < 5 and ts.date() not in self.holidays

    def in_council_week(self, ts):
        return ts.isocalendar().week in self.council_weeks

    def capacity_fte(self, pool: str, ts: pd.Timestamp) -> float:
        dow, s, iv = ts.dayofweek, self.scenario, self.interventions
        if pool == "clerks":
            return (4.0 if dow == 0 else 5.0) if self._workday(ts) else 0.0  # Mon: 1 clerk on portal
        if pool == "planners":
            return 8.0 if self._workday(ts) else 0.0
        if pool == "fire":
            return s.fire_capacity_factor * (2.0 if dow in (1, 2, 3) else 0.0)   # Tue-Thu
        if pool == "env":
            return 3.0 * 0.6 if self._workday(ts) else 0.0                        # 40% reserved
        if pool == "inspectors":
            if dow not in (1, 2, 3, 4):                                           # Tue-Fri field days
                return 0.0
            cap = 4.0
            if iv.D4_temp_inspector_peak_months and ts.month in (3, 4, 5, 9, 10, 11):
                cap += 1.0                                                        # D4 hook
            return cap
        if pool == "legal":
            if self.in_council_week(ts):
                return 0.2 * s.legal_capacity_factor                              # urgent lane only
            return 2.0 * s.legal_capacity_factor
        if pool == "system":
            return float("inf")
        raise KeyError(pool)


class ResourcePool:
    """Counting pool over interchangeable FTEs; extend with skill tags where
    individual constraints matter (e.g., two simple-only planners)."""
    def __init__(self, name: str, calendar: MunicipalCalendar):
        self.name, self.calendar = name, calendar
        self.busy = 0.0
        self.busy_seconds = 0.0   # utilisation accounting (update in engine handlers)

    def available(self, ts):
        return max(self.calendar.capacity_fte(self.name, ts) - self.busy, 0.0)

    def acquire(self, ts, units=1.0):
        if self.available(ts) >= units:
            self.busy += units
            return True
        return False

    def release(self, units=1.0):
        self.busy = max(self.busy - units, 0.0)


class Queue:
    """FIFO with optional aging-based priority override (intervention D6)."""
    def __init__(self, discipline: str = "FIFO"):
        self.items, self.discipline = deque(), discipline

    def push(self, item):
        self.items.append(item)

    def pop(self, now=None, aging_threshold_days=None):
        if not self.items:
            return None
        if (self.discipline == "AGING" and aging_threshold_days and now is not None):
            for idx, it in enumerate(self.items):
                age = (now - it["enqueue_ts"]).total_seconds() / 86400.0
                if age >= aging_threshold_days:
                    del self.items[idx]
                    return it
        return self.items.popleft()


class InspectionBundler:
    """Groups inspection-ready cases per district; releases a bundle when the
    batching window closes (D3) or immediately (baseline behaviour)."""
    def __init__(self, interventions: InterventionConfig):
        self.buf, self.cfg = defaultdict(list), interventions

    def add(self, case):
        self.buf[case["district"]].append(case)

    def maybe_release(self, district, now):
        b = self.buf[district]
        if not b:
            return []
        if not self.cfg.D3_district_batching:
            out, self.buf[district] = b, []
            return out
        oldest = min(c["ready_ts"] for c in b)
        if (now - oldest).total_seconds() / 86400.0 >= self.cfg.batching_window_days or len(b) >= 4:
            out, self.buf[district] = b, []
            return out
        return []


class DigitalTwinEngine:
    """
    Event-loop skeleton. Event types: ARRIVAL, START_SERVICE, COMPLETE_SERVICE,
    APPLICANT_RESPONSE, BATCH_RELEASE. State model follows Section 1:
    per-case attributes, per-queue lists, per-pool busy units, latent objection
    flags, global clock. Analytics come from Layer 1; nothing here calls PM4Py.
    """
    def __init__(self, interventions, scenario, rngs):
        self.cfg, self.sc = interventions, scenario
        self.arrivals = ArrivalGenerator(rngs[0], scenario)
        self.routing = RoutingModel(rngs[1])
        self.service = ServiceTimeModel(rngs[2])
        self.applicant = ApplicantResponseModel(rngs[3], scenario)
        self.objections = ObjectionModel(rngs[4], scenario)
        self.calendar = MunicipalCalendar(scenario, interventions)
        self.pools = {p: ResourcePool(p, self.calendar) for p in
                      ["clerks", "planners", "fire", "env", "inspectors", "legal"]}
        self.queues = defaultdict(lambda: Queue(
            discipline="AGING" if interventions.D6_aging_planner_reserve else "FIFO"))
        self.bundler = InspectionBundler(interventions)
        self.events, self.traces, self._seq = [], [], 0

    def schedule(self, ts, etype, payload):
        heapq.heappush(self.events, (ts, self._seq, etype, payload))
        self._seq += 1

    def run(self, horizon_days=1460, warmup_days=180):
        t0 = pd.Timestamp("2026-01-01")
        for ts, attrs in self.arrivals.sample_arrivals(t0, t0 + pd.Timedelta(days=horizon_days)):
            self.schedule(ts, "ARRIVAL", attrs)
        while self.events:
            ts, _, etype, payload = heapq.heappop(self.events)
            getattr(self, f"on_{etype.lower()}")(ts, payload)
        return self.traces

    # ---- handlers (placeholders: implement per the Section 1 state model) --
    def on_arrival(self, ts, case):
        case["start_ts"] = ts
        case["route"] = self.routing.sample_route(case)
        has_obj, ext_days = self.objections.sample(case)
        case["objection"], case["notice_extension_days"] = has_obj, ext_days
        case["enqueue_ts"] = ts
        case["n_rework"] = 0
        self.queues["Completeness check"].push(case)
        # next: try_start_next("Completeness check", ts) -> acquire clerk unit,
        # schedule COMPLETE_SERVICE after service.sample(...); on completion,
        # route per case["route"] (missing-doc loop -> APPLICANT_RESPONSE event
        # with applicant.sample_missing_docs_response_days(), etc.).

    def on_start_service(self, ts, payload):
        raise NotImplementedError("acquire resource unit, record service start")

    def on_complete_service(self, ts, payload):
        raise NotImplementedError("release unit, append trace record on terminal activity, route next step")

    def on_applicant_response(self, ts, payload):
        raise NotImplementedError("re-enter Completeness check or advance case")

    def on_batch_release(self, ts, payload):
        raise NotImplementedError("schedule bundled inspections with reduced travel")

def kpis_from_traces(traces, warmup_ts):
    """traces: one record per completed case with end_ts, cycle_days,
    case_type, n_rework (produced by COMPLETE_SERVICE handler)."""
    df = pd.DataFrame(traces)
    if df.empty:
        return {}
    df = df[pd.to_datetime(df["end_ts"]) >= warmup_ts]
    out = {"by_case_type": {}}
    for ct, g in df.groupby("case_type"):
        out["by_case_type"][ct] = {
            "n": int(len(g)),
            "cycle_median_d": float(g["cycle_days"].median()),
            "cycle_p90_d": float(g["cycle_days"].quantile(0.90)),
            "sla_rate": float((g["cycle_days"] <= SLA_TARGET_DAYS[ct]).mean()),
            "rework_rate": float((g["n_rework"] > 0).mean()),
        }
    out["global"] = {"backlog_over_90d_rate": float((df["cycle_days"] > 90).mean())}
    return out


def t_ci(x, alpha=0.05):
    x = np.asarray(x, float)
    n, m, se = len(x), x.mean(), x.std(ddof=1) / np.sqrt(len(x))
    try:
        from scipy.stats import t as tdist
        crit = tdist.ppf(1 - alpha / 2, n - 1)
    except Exception:
        crit = 1.96
    return float(m), float(m - crit * se), float(m + crit * se)


def bootstrap_quantile_ci(x, q=0.90, B=2000, alpha=0.05, seed=0):
    rng = np.random.default_rng(seed)
    x = np.asarray(x, float)
    stats = np.quantile(rng.choice(x, size=(B, len(x)), replace=True), q, axis=1)
    return (float(np.quantile(x, q)), float(np.quantile(stats, alpha / 2)),
            float(np.quantile(stats, 1 - alpha / 2)))


class ExperimentRunner:
    """Runs (interventions x scenario x replications) with COMMON RANDOM
    NUMBERS: replication i uses child seed i in every cell, so paired
    intervention-vs-baseline differences are less noisy."""
    N_STREAMS = 7  # arrivals, routing, service, applicant, objections, travel, calendar noise

    def __init__(self, base_seed: int = 20260101):
        self.base_seed = base_seed

    def run_cell(self, interventions, scenario, n_reps=50, horizon_days=1460, warmup_days=180):
        rep_seeds = np.random.SeedSequence(self.base_seed).spawn(n_reps)
        rep_kpis = []
        warmup_ts = pd.Timestamp("2026-01-01") + pd.Timedelta(days=warmup_days)
        for rs in rep_seeds:
            rngs = [np.random.default_rng(s) for s in np.random.SeedSequence(rs).spawn(self.N_STREAMS)]
            engine = DigitalTwinEngine(interventions, scenario, rngs)
            traces = engine.run(horizon_days, warmup_days)
            rep_kpis.append(kpis_from_traces(traces, warmup_ts))
        return rep_kpis  # aggregate per metric with t_ci / bootstrap_quantile_ci
