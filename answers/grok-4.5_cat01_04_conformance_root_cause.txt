The June fitness collapse is best read as a **measurement shock**, not a sudden collapse of work quality. The UI synonym (`Risk Screen`), the gateway’s `Queue Routed` inject, and ETL re-timing of `Decision`/`Notify` jointly multiply moves on log/model against a frozen control-flow tree. Staged repairs—label map, technical-event removal, source ordering—recover fitness from 32% to ~89% in Jun–Jul, which is the signature of **label + provenance + order** defects rather than mass deviant execution.

From August, a **second mechanism** appears: a real policy-mandated `Supervisor Sign-off` that the normative tree never absorbed. That is genuine model obsolescence layered on an already noisy log. Optional control-flow sign-off improves fitness but buys permissiveness: it does not encode EUR 50,000, so better fitness is not proof of correct governance.

Unchanged approval and appeal rates show that whatever is happening has not yet moved coarse customer outcomes. That neither proves “only data error” (silent bypasses and incomplete incident detection can leave appeals flat) nor proves “employees went rogue” (most deviation mass tracks IT and model lag). Residual enhanced-review traces without compliance checks remain **ambiguous** between true bypass, extraction loss, and routing via `Manual Override`. Multi-cause abduction is required: logging semantics and technical events explain the sharp measured drop; policy–model drift explains the post-August residual; noncompliance is a tail risk that needs provenance, not blame from raw moves on log.

def variants_to_log_string(variant_counts):
    """Expand frequencies into newline-separated traces for parse_event_log_string."""
    lines = []
    for variant, cnt in variant_counts.items():
        for _ in range(cnt):
            lines.append(variant)
    return "\n".join(lines)


def variants_to_event_log(variant_counts, label_map=None, drop_activities=None, fix_notify_decision_order=False):
    """
    Build an EventLog. Optional normalization:
      - label_map: dict old->new
      - drop_activities: set of activities to remove (technical events)
      - fix_notify_decision_order: simulate source-sequence repair when Notify precedes Decision
    """
    label_map = label_map or {}
    drop_activities = drop_activities or set()
    log = EventLog()
    case_id = 0
    for variant, cnt in variant_counts.items():
        acts = [a.strip() for a in variant.split(",")]
        for _ in range(cnt):
            case_id += 1
            mapped = [label_map.get(a, a) for a in acts]
            filtered = [a for a in mapped if a not in drop_activities]
            if fix_notify_decision_order:
                # If both present and Notify before Decision, swap to source-business order
                if "Notify" in filtered and "Decision" in filtered:
                    i_n = filtered.index("Notify")
                    i_d = filtered.index("Decision")
                    if i_n < i_d:
                        filtered[i_n], filtered[i_d] = filtered[i_d], filtered[i_n]
            tr = Trace()
            tr.attributes["concept:name"] = f"case_{case_id}"
            for i, a in enumerate(filtered):
                ev = Event({
                    "concept:name": a,
                    "time:timestamp": __import__("datetime").datetime(2026, 6, 1) +
                                      __import__("datetime").timedelta(minutes=i),
                })
                tr.append(ev)
            log.append(tr)
    return log


def log_from_pm4py_string(variant_counts):
    s = variants_to_log_string(variant_counts)
    # activity delimiter default comma matches our strings
    return pm4py.parse_event_log_string(s.split("\n"))


def summarize_dfg(log, name):
    dfg, start_act, end_act = pm4py.discover_dfg(log)
    print(f"\n=== DFG: {name} (top 12 edges) ===")
    for edge, c in sorted(dfg.items(), key=lambda x: -x[1])[:12]:
        print(f"  {edge[0]} -> {edge[1]} : {c}")
    return dfg


def alignment_report(log, net, im, fm, name):
    """Alignments + fitness; print dominant move types (simplified)."""
    print(f"\n=== Alignments: {name} ===")
    try:
        fit = pm4py.fitness_alignments(log, net, im, fm)
    except Exception:
        fit = fitness_algo.apply(log, net, im, fm)
    print("Fitness:", fit)

    try:
        aligns = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    except Exception:
        aligns = alignments_algo.apply(log, net, im, fm)

    move_log = Counter()
    move_model = Counter()
    fitted = 0
    total_cost = 0.0
    for al in aligns:
        cost = al.get("cost", al.get("fitness", None))
        # PM4Py alignment cost key is typically 'cost'; fitness may be separate
        if isinstance(al, dict) and "cost" in al:
            total_cost += al["cost"]
            if al["cost"] == 0:
                fitted += 1
        alignment = al.get("alignment") or []
        for move in alignment:
            # moves are ((log_lbl, model_lbl), ...) depending on version
            if not move:
                continue
            if isinstance(move[0], tuple):
                log_lbl, model_lbl = move[0], move[1]
            else:
                log_lbl, model_lbl = move[0], move[1]
            if log_lbl is not None and model_lbl is None:
                move_log[str(log_lbl)] += 1
            elif log_lbl is None and model_lbl is not None:
                move_model[str(model_lbl)] += 1

    n = len(aligns) if aligns else 1
    print(f"Fitting traces % (zero cost): {100.0 * fitted / n:.1f}")
    print(f"Mean alignment cost (raw): {total_cost / n:.4f}")
    print("Dominant moves on log:", move_log.most_common(8))
    print("Dominant moves on model:", move_model.most_common(8))
    return fit, aligns


def precision_report(log, net, im, fm, name):

        prec = pm4py.precision_alignments(log, net, im, fm)
    except Exception:
        prec = precision_algo.apply(log, net, im, fm)
    print("Precision:", prec)
    return prec

## 7. Provisional conclusion

The **primary explanation for the measured conformance collapse** is a stack of **data and model provenance failures**, not a sudden organization-wide abandonment of the claims procedure. In June the UI synonym `Risk Screen`, the partial inject of technical `Queue Routed`, and ETL warehouse times on `Decision`/`Notify` jointly devastated fitness against an unchanged process tree. The staged alignment recovery—label map, technical-event removal, source ordering—from roughly 32% to about 89% fitness in Jun–Jul is decisive abductive evidence that **label/semantic change, technical-event extraction, and timestamp/order defects** caused most of the *reported* deterioration. Business outcomes (approval rate, appeals) stayed flat, which is consistent with a measurement shock.

A **separate, real operational issue** begins 2026-08-01: policy-mandated `Supervisor Sign-off` for high-value claims without a model update. After honest preprocessing, Aug–Sep fitness remains depressed until the model admits sign-off—classic **normative model obsolescence**. That is a governance defect even when employees follow the new policy. Whether **employee noncompliance** exists is **not settled**: enhanced reviews without compliance checks and growing `Manual Override` use survive normalization. Stable appeals do not clear them, because detection is admittedly incomplete and missing events remain possible. Confidence: **~85–90%** that IT/logging/model-lag explain the bulk of the *measured* June collapse; **~75–80%** that August residual is largely model obsolescence plus policy-real behavior; **only ~35–45%** that residual compliance-check gaps are true bypasses until provenance audit closes the loop.

**Immediate actions:** IT—freeze a synonym map, technical-event allow-list, and source-sequence ordering in the conformance ETL; re-extract Jun–Sep. Process owners—version the process tree with the Aug 1 sign-off rule and, urgently, a data-aware amount guard. Compliance—do not open a mass misconduct case from raw June fitness; instead audit the finite set of enhanced-without-check and override cases with source screenshots, stratified by amount and resource. **Must not be claimed yet:** that employees caused the conformance crisis; that optional sign-off “solves” compliance; that flat appeals prove control effectiveness; or that fitness after an overpermissive model equals regulatory conformance.

## 8. Model-governance recommendation

1. **Model versioning:** Bind every normative process tree/Petri net to a dated policy ID, owner, and effective interval; block conformance jobs when policy registry version  model version without an explicit waiver.
2. **Event-semantic contracts:** Maintain a controlled vocabulary mapping UI labels, backend activity IDs, and conformance names (e.g., `Risk Screen``Classify`); synonym changes require contract update before release, not after fitness drops.
3. **Technical-event policy:** Classify gateway/platform events (`Queue Routed`, heartbeats) as technical by default; exclude them from business conformance unless compliance explicitly promotes them; document partial-emission rules.
4. **Timestamp provenance:** Store and prefer source-system timestamps and monotonic sequence numbers for order-sensitive activities; never silently substitute warehouse-ingestion time in legal/control-flow analytics.
