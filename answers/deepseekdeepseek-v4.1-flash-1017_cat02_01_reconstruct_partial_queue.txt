```
def sweep(intervals, T=360):
    ev=[]
    for s,e in intervals:
        if pd.isna(s) or pd.isna(e): continue
        s=max(0,s); e=min(T,e)
        if e<s: continue
        if e>s:
            ev.append((s,1)); ev.append((e,-1))
    if not ev: return 0.0,0
    ev.sort(key=lambda x:(x[0], x[1])) # exits (-1) before entries
    cur=0; last=0; area=0; peak=0
    i=0
    while i<len(ev):
        t=ev[i][0]
        area += cur*(t-last)
        while i<len(ev) and ev[i][0]==t:
            cur += ev[i][1]
            i+=1
        peak=max(peak,cur)
        last=t
    area += cur*(T-last)
    return area/T, peak
```

# 1. Assumptions and notation

**A1 — Time origin and event order.** I use 08:00 as time 0 and 14:00 as time 360 minutes. All timestamps are handled as recorded rounded times. For queue/WIP sweeps, when a completion and an arrival/start share the same rounded timestamp, I process completions/exits before starts/entries in the central convention; snapshots are therefore “post-event.” This only affects instantaneous peaks by at most 1 case, not interval areas.

**A2 — Rounding.** Each reported timestamp may represent an actual time in ±2.5 minutes, so a duration from two rounded timestamps has up to roughly ±5 minutes uncertainty. I report recorded-time point estimates and treat sub-5-minute differences as not precisely identifiable.

**A3 — Capacity and outage.** S1 has two single-task resources I1 and I2. S2 has two single-task resources C1 and C2. C2 is unavailable 10:55–11:10, i.e. 175–190 minutes after 08:00, a 15-minute capacity loss. S2 available resource-time in the window is therefore 360 + (360  15) = 705 resource-minutes. Apparent simultaneous resource use is treated as a logging/rounding artifact unless evidence says otherwise.

**A4 — Missing starts are not point-imputed silently.** For each MISSING start I derive a feasibility interval using queue entry, resource availability, previous/next work on the same resource, and known completion. The main “central” case table uses a typical-service-duration imputation where feasible:
- P05 S2 start = 10:45? No: 09:45 = 105 min, service 30, wait 20. Feasible start interval [09:45, 10:15] = [105,135].
- P07 S1 start = 09:30 = 90 min, service 30, wait 45. Feasible start interval [09:25, 10:00] = [85,120].
- P11 S2 start = 12:00 = 240 min, service 25, wait 55. Feasible start interval [12:00, 12:25] = [240,265].
- P15 S1 start = 11:45 = 225 min, service 30, wait 95. Feasible start interval [11:40, 12:15] = [220,255].

**A5 — OPEN activities.** For P15, P17, and P21, elapsed service is 14:00 minus known start. Final service duration is right-censored and is at least the elapsed amount. Final completion time is unknown.

**A6 — Blank S2 after completed S1.** P16, P18, P19, P20 are waiting for S2 at 14:00. Their S2 waiting time is a lower bound equal to 14:00 minus S1 completion. P22 is waiting for S1 at 14:00; its S1 waiting time is a lower bound equal to 14:00 minus arrival.

**A7 — No bypass.** Every case must complete S1 before entering the S2 queue. S2 queue entry is S1 completion.

**A8 — WIP conventions.** Station WIP = waiting at the station + in active service at that station. Queue length = waiting only. Total WIP = all arrived cases not yet fully complete at 14:00. For censored cases, WIP is counted up to 14:00.

**A9 — Sojourn.** Station sojourn = queue wait + active service. Completed-case total sojourn = final S2 completion  external S1 arrival. For open/waiting cases, elapsed sojourn to 14:00 is reported, not final sojourn.

**A10 — Utilization.** Utilization = active service busy-time divided by available resource-time. For S1 denominator = 2 × 360 = 720 resource-minutes. For S2 denominator = 705 resource-minutes including the C2 outage. Open cases contribute elapsed service; waiting cases contribute zero service.

**A11 — Little’s Law.** Formal stationary Little’s Law is not credible over the whole nonstationary, censored window. I use only a finite-window arithmetic consistency check, and I treat it as an identity, not as independent confirmation of stationarity.

# 2. Reconstruction method and formulas

Let:

- \(A\) = external S1 arrival time.
- \(S1_s, S1_e\) = S1 start/end.
- \(S2_s, S2_e\) = S2 start/end.
- \(T=360\) minutes = 14:00.

**S1 waiting:**  
\[
W_1 = S1_s - A
\]
For P22, \(W_1 \ge T-A\).

**S1 service:**  
\[
P_1 = S1_e - S1_s
\]
For P21, \(P_1^{\text{elapsed}} = T-S1_s\) and final \(P_1 \ge P_1^{\text{elapsed}}\).

**S2 waiting:** since S2 queue entry is S1 completion,  
\[
W_2 = S2_s - S1_e
\]
For waiting cases P16/P18/P19/P20, \(W_2 \ge T-S1_e\).

**S2 service:**  
\[
P_2 = S2_e - S2_s
\]
For P15/P17, \(P_2^{\text{elapsed}} = T-S2_s\) and final \(P_2 \ge P_2^{\text{elapsed}}\).

**Station sojourn:**  
\[
R_i = W_i + P_i \quad (i=1,2)
\]

**Completed-case total sojourn:**  
\[
R = S2_e - A
\]

For missing starts, lower/upper bounds come from the feasible start interval. A central estimate is produced by choosing a typical observed service duration where it is feasible, otherwise using the resource-imposed feasible duration. Scenario analysis in Section 6 varies this choice.

**Queue/WIP areas:** for each case, its waiting interval contributes to queue area in case-minutes; station WIP area = waiting area + active service area; total WIP area = S1 WIP area + S2 WIP area. Mean queue/WIP length over 0–360 is area/360. Peaks are from event sweeps using the A1 tie convention.

**Utilization:**  
\[
U_i = \frac{\text{active service busy-time}_i}{\text{available resource-minutes}_i}
\]

**Little’s Law finite-window check:** if all cases arriving in the window are included and unfinished cases are censored at \(T\), then
\[
L_{\text{time avg}} = \lambda W_{\text{censored}},
\quad
\lambda = N/T,
\]
where \(W_{\text{censored}}\) is the mean time in system within the window. This is an arithmetic consistency identity; it does not establish stationarity.

# 5. Bottleneck and temporal interpretation

Using half-open subperiods:

- **08:00–10:00.** External S1 arrivals: 13 cases, about 6.5/h. S1 completions: 6, about 3.0/h. S2 completions: 3, about 1.5/h. The S1 queue grows quickly; by 10:00 S1 has 6 waiting, 7 WIP, while S2 has 2 waiting and 4 WIP. Evidence: the arrival burst loads S1 first, and S1 is the immediate queueing constraint early.
- **10:00–11:30.** External S1 arrivals: 6, about 4.0/h. S1 completions: 5, about 3.33/h. S2 completions: 4, about 2.67/h. Total WIP reaches its peak near 11:30–12:00. The C2 outage from 10:55–11:10 reduces S2 capacity by 15 resource-minutes and plausibly contributes to downstream delay, but it is not the only cause because S2 already has long service times and backlog.
- **11:30–14:00.** External S1 arrivals: 3, about 1.2/h. S1 completions: 9, about 3.6/h. S2 completions: 7, about 2.8/h. S1 drains from 6 waiting at 12:00 to 1 waiting plus 1 in service at 14:00. S2 queue instead grows to 4 waiting plus 2 in service at 14:00. Evidence: the later part of the window is clearly S2-constrained.

Bottleneck verdict: the evidence is most consistent with a **time-varying combination**: S1 is the first constraint during the early arrival surge, while S2 becomes the dominant downstream bottleneck over the middle and late window. The stronger S2 evidence is longer S2 service duration (roughly 35–40 min central vs roughly 28–30 min at S1), only 14 completed S2 services by 14:00 versus 20 completed S1 services, and 6 S2 WIP at 14:00 versus 2 S1 WIP. Utilization alone is not decisive because S1 and S2 busy-time percentages are close and are sensitive to missing starts. The C2 outage is real but too small by itself to explain the whole S2 backlog; it is a secondary capacity shock.

# 6. Missingness, censoring, and sensitivity analysis

Scenario definitions for the four MISSING starts:

- **Earliest feasible / long service:** use the earliest allowed start, which also maximizes feasible service for the known completion. P05 start 105, P07 start 85, P11 start 240, P15 start 220.
- **Median-service central:** main A4 imputation. P05 105, P07 90, P11 240, P15 225.
- **Midpoint feasible:** use the midpoint of each feasible start interval. P05 120, P07 102.5, P11 252.5, P15 237.5.
- **Latest feasible / short service:** use the latest allowed start, giving minimal service. P05 135, P07 120, P11 265, P15 255. Mechanistic bounds allow zero service here; requiring at least 5 min would shift these modestly.

Stable conclusions:

- The known S1 completion and S2 start/end events fix station WIP curves, total WIP, total sojourn for completed cases, and all completion-event throughput counts. These do not change across the missing-start scenarios.
- Total WIP mean is 9.51 cases and peak is 13 cases under all scenarios; this is driven by known arrival, S1 completion, and S2 completion events.
- Completed cases P01–P14 have mean total sojourn about 146.4 min; this is unaffected by missing-start allocations because their final S2 completions are known.
- S2 has a persistent late backlog of 4 waiting plus 2 open/in-service at 14:00. This, together with longer S2 service times and fewer completed S2 services, supports a late-window S2 bottleneck even under unfavorable imputations.

Unstable conclusions:

- S1 versus S2 utilization ranking changes under extreme missing-start assumptions. S1 utilization can range from about 74% to 84%; S2 from about 73% to 81%. Therefore utilization alone should not be used to declare a single bottleneck.
- Waiting-time means and queue-length peaks for S1/S2 are conditional on how missing starts are imputed. The ranges above should be quoted rather than a single exact queue length.
- OPEN and waiting cases materially affect utilization and Little’s-Law checks. Omitting them would understate WIP, final backlog, and active resource use. For P15/P17/P21, elapsed service is a lower bound only.

C2 outage and rounding:

- The C2 outage removes 15 resource-minutes out of 720 nominal S2 resource-minutes, about 2.1% of nominal S2 capacity, or 4.2% of C2 nominal time. It reduces the S2 denominator used here to 705. Ignoring the outage would lower apparent S2 utilization by roughly 1–2 percentage points; it would not remove the late S2 queue.
- Rounding may shift individual wait/service durations by up to about ±5 minutes and may change instantaneous peaks by 1 case at tied timestamps. It does not materially alter the main pattern of rising S1 queue early and rising S2 queue late.

Little’s-Law check, finite window only: using all 22 arrivals censored at 14:00, total WIP area 3425 case-min gives mean WIP 9.51. Arrival rate is \(22/360 = 0.0611\) cases/min. Mean censored time in system is \(3425/22 = 155.7\) min. Then \(0.0611 \times 155.7 = 9.51\), which is an arithmetic consistency identity for this censored finite window, not evidence of stationarity. For S2, entries = 20, S2 WIP mean = 3.722, mean censored S2 sojourn = \(1340/20=67.0\) min, and \(20/360 \times 67.0 = 3.722\). I would not use a stationary Little’s-Law test on shorter subperiods because the queues are visibly nonstationary and right-censored.

```python
def sweep_area_peak(intervals, T=360.0):
    events = []
    for s, e in intervals:
        if pd.isna(s) or pd.isna(e):
            continue
        s = max(0.0, float(s))
        e = min(T, float(e))
        if e > s:
            events.append((s, +1))
            events.append((e, -1))
    if not events:
        return 0.0, 0
    events.sort(key=lambda x: (x[0], x[1]))  # exits (-1) before entries (+1)
    cur = 0
    last = 0.0
    area = 0.0
    peak = 0
    i = 0
    while i < len(events):
        t = events[i][0]
        area += cur * (t - last)
        while i < len(events) and events[i][0] == t:
            cur += events[i][1]
            i += 1
        peak = max(peak, cur)
        last = t
    area += cur * (T - last)
    return area / T, peak

def build_scenario(name):
    d = df.copy()
    d['s1s_f'] = d['s1s']
    d['s2s_f'] = d['s2s']
    for case, t in scenario_starts[name].items():
        if case in ('P05', 'P11'):
            d.loc[d['case'] == case, 's2s_f'] = t
        if case in ('P07', 'P15'):
            d.loc[d['case'] == case, 's1s_f'] = t

    # S1 waiting: known/imputed start minus arrival; P22 waits to 14:00
    d['s1_wait'] = np.where(
        d['s1s_f'].notna(),
        d['s1s_f'] - d['a'],
        np.where(d['a'].notna(), T - d['a'], np.nan)
    )
    # S1 service: known/elapsed end minus start; P22 not started
    d['s1_service'] = np.where(
        d['s1s_f'].notna() & d['s1e_eff'].notna(),
        d['s1e_eff'] - d['s1s_f'],
        np.nan
    )
    # S2 queue entry only if S1 truly completed by 14:00 (not OPEN P21)
    entered_s2 = d['s1e'].notna()
    d['entered_s2'] = entered_s2
    d['s2_wait'] = np.where(
        entered_s2 & d['s2s_f'].notna(),
        d['s2s_f'] - d['s1e'],
        np.where(entered_s2 & d['s2s_f'].isna(), T - d['s1e'], np.nan)
    )
    d['s2_service'] = np.where(
        d['s2s_f'].notna() & d['s2e_eff'].notna(),
        d['s2e_eff'] - d['s2s_f'],
        np.nan
    )

    s1_wait_area = d['s1_wait'].sum(skipna=True)
    s1_service_area = d['s1_service'].sum(skipna=True)
    s2_wait_area = d['s2_wait'].sum(skipna=True)
    s2_service_area = d['s2_service'].sum(skipna=True)

    s1_wip_area = s1_wait_area + s1_service_area
    s2_wip_area = s2_wait_area + s2_service_area

    # WIP/queue peaks from intervals
    s1_wip_intervals = list(zip(
        d['a'],
        np.where(d['s1e_eff'].notna(), d['s1e_eff'], T)
    ))
    s1_q_intervals = list(zip(
        d['a'],
        np.where(d['s1s_f'].notna(), d['s1s_f'], T)
    ))
    s2_wip_intervals = list(zip(
        d.loc[entered_s2, 's1e'],
        np.where(d.loc[entered_s2, 's2e_eff'].notna(), d.loc[entered_s2, 's2e_eff'], T)
    ))
    s2_q_intervals = list(zip(
        d.loc[entered_s2, 's1e'],
        np.where(d.loc[entered_s2, 's2s_f'].notna(), d.loc[entered_s2, 's2s_f'], T)
    ))

    s1_wip_mean, s1_wip_peak = sweep_area_peak(s1_wip_intervals)
    s1_q_mean, s1_q_peak = sweep_area_peak(s1_q_intervals)
    s2_wip_mean, s2_wip_peak = sweep_area_peak(s2_wip_intervals)
    s2_q_mean, s2_q_peak = sweep_area_peak(s2_q_intervals)

    return {
        'scenario': name,
        'S1_wait_area': s1_wait_area,
        'S1_wait_mean_queue': s1_wait_area / T,
        'S1_service_busy': s1_service_area,
        'S1_util': s1_service_area / (2.0 * T),
        'S1_WIP_mean': s1_wip_mean,
        'S1_WIP_peak': s1_wip_peak,

# Hourly snapshots for central scenario
def count_at(intervals, t, T=360.0):
    c = 0
    for s, e in intervals:
        if pd.isna(s) or pd.isna(e):
            continue
        s = float(s); e = float(e)
        if s <= t and ((e > t) or (t == T and e >= T)):
            c += 1
    return c

s2_wip_ints = list(zip(d.loc[entered, 's1e'], np.where(d.loc[entered, 's2e_eff'].notna(), d.loc[entered, 's2e_eff'], T)))
```
