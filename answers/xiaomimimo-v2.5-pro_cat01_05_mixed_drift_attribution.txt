**Primary monitoring population:** Supplier × Complexity × Month segments, with minimum support of 30 cases per segment. This balances the need to isolate key drivers (supplier, complexity) while maintaining temporal resolution. Monitoring at this level can distinguish supplier-specific issues from case-mix effects, while monthly aggregation provides sufficient support.

# 4. Compute DFG distance (Weighted Jaccard)
def weighted_jaccard_distance(series1, series2, columns):
    """Compute weighted Jaccard distance between two DFG rate vectors."""
    # Treat missing as 0
    v1 = series1[columns].fillna(0).values
    v2 = series2[columns].fillna(0).values
    
    # Weight by average rate
    weights = (v1 + v2) / 2
    weights = np.where(weights == 0, 1, weights)  # avoid division by zero
    
    # Compute weighted intersection and union
    intersection = np.minimum(v1, v2) * weights
    union = np.maximum(v1, v2) * weights
    
    # Avoid division by zero
    if union.sum() == 0:
        return 0.0
    
    jaccard_similarity = intersection.sum() / union.sum()
    return 1 - jaccard_similarity

def format_event_log(df: pd.DataFrame,

                     timestamp_col: str = 'timestamp',

    """
    Format dataframe for PM4Py processing.
    
    Args:
        df: Raw event log dataframe
        case_id_col: Column name for case identifier
        activity_col: Column name for activity
        timestamp_col: Column name for timestamp
        resource_col: Optional column name for resource
    
    Returns:
        Formatted dataframe
    """
    formatted = pm4py.format_dataframe(
        df, 
        case_id=case_id_col,
        activity_key=activity_col,
        timestamp_key=timestamp_col,
        resource_key=resource_col
    )
    return formatted

def slice_time_window(df: pd.DataFrame,
                      start_date: str,
                      end_date: str,
                      timestamp_col: str = 'timestamp') -> pd.DataFrame:
    """
    Filter event log to specific time window.
    
    Args:
        df: Formatted event log
        start_date: Start date (YYYY-MM-DD)
        end_date: End date (YYYY-MM-DD)
        timestamp_col: Timestamp column name
    
    Returns:
        Filtered dataframe
    """

        df,
        timestamp_key=timestamp_col,
        start_date=start_date,
        end_date=end_date
    )

def compute_monthly_dfgs(df: pd.DataFrame,
                         case_id_col: str = 'case:concept:name',
                         activity_col: str = 'concept:name',
                         timestamp_col: str = 'time:timestamp') -> Dict[str, Tuple]:
    """
    Compute DFG for each month in the event log.
    
    Args:
        df: Formatted event log
        case_id_col: Case ID column
        activity_col: Activity column
        timestamp_col: Timestamp column
    
    Returns:
        Dictionary mapping month strings to (dfg, start_activities, end_activities)
    """
    # Add month column
    df = df.copy()
    df['month'] = df[timestamp_col].dt.to_period('M').astype(str)
    
    monthly_dfgs = {}
    for month, month_df in df.groupby('month'):
        if len(month_df) > 0:
            dfg, start_act, end_act = pm4py.discover_dfg(
                month_df,
                case_id_key=case_id_col,
                activity_key=activity_col,
                timestamp_key=timestamp_col
            )
            monthly_dfgs[month] = (dfg, start_act, end_act)
    
    return monthly_dfgs

def apply_label_mapping(df: pd.DataFrame,
                        mapping: Dict[str, str],
                        activity_col: str = 'concept:name',
                        keep_original: bool = True) -> pd.DataFrame:
    """
    Apply label mapping without overwriting original log.
    
    Args:
        df: Formatted event log
        mapping: Dictionary mapping old labels to new labels
        activity_col: Activity column name
        keep_original: Whether to keep original column
    
    Returns:
        DataFrame with mapped labels
    """
    df = df.copy()
    if keep_original:
        df[f'{activity_col}_original'] = df[activity_col].copy()
    
    df[activity_col] = df[activity_col].map(mapping).fillna(df[activity_col])
    return df

def remove_duplicate_events(df: pd.DataFrame,
                            duplicate_activity: str = 'Open Case',
                            case_id_col: str = 'case:concept:name',
                            activity_col: str = 'concept:name') -> pd.DataFrame:
    """
    Remove duplicate technical events (e.g., duplicate Open Case).
    
    Args:
        df: Formatted event log
        duplicate_activity: Activity to deduplicate
        case_id_col: Case ID column
        activity_col: Activity column
    
    Returns:
        DataFrame with duplicates removed
    """
    # Identify duplicates (keep first occurrence per case)
    mask = df[activity_col] == duplicate_activity
    duplicate_indices = df[mask].groupby(case_id_col).apply(
        lambda x: x.index[1:] if len(x) > 1 else []
    ).explode().dropna().tolist()
    
    return df.drop(duplicate_indices)

## 9. Provisional attribution

**Strongest conclusions:**
1. **Logging/semantic drift** is clearly the primary driver of the March fitness collapse (confidence: 90%). The simultaneous appearance of `Eligibility Screen`, duplicated `Open Case`, and missing resource data following system migration, with immediate recovery upon label mapping, is compelling. The gap between raw (0.55) and mapped (0.90) fitness directly quantifies this effect.

2. **Supplier-driven rework** is strongly implicated in the May-June performance deterioration (confidence: 80%). The temporal alignment of supplier Z's API disruption with a doubling of `Request Info` rates, coupled with the disproportionate share of supplier Z cases (43-46%), creates a clear signature. The continued elevation of rework even after September recovery suggests some persistent adaptation or backlog effects.

**Plausible mechanisms:**
3. **Staffing-driven queueing** likely amplified cycle time increases after June 15 (confidence: 70%). The reconstruction showing queue waits increasing more than service times aligns with capacity reduction. However, this interacts with supplier issues—more rework increases workload exactly when capacity decreased.

4. **Priority rule redistribution** appears to have changed delay patterns starting July 1 (confidence: 60%). The continued rise in rework rates could reflect standard cases experiencing longer waits and thus more rework requests, but the aggregate data cannot distinguish priority classes.

5. **Seasonal population drift** clearly explains the October-November volume and complexity surge (confidence: 85%), but its contribution to performance degradation is confounded with ongoing staffing and supplier issues.

**Mediation/interaction issues:**
The primary interaction is between supplier disruption and staffing cuts: increased rework volume from supplier issues directly increased workload at a time of reduced capacity. This prevents clean attribution of queueing delays to either mechanism alone. Similarly, the priority rule's effect is likely mediated by the existing queue congestion.

**What would revise the account:**
1. If case-level analysis showed that supplier Z cases did not have higher rework rates after controlling for complexity, the supplier mechanism would weaken.
2. If team-level analysis revealed no correlation between staffing changes and queue waits, the staffing mechanism would weaken.
3. If the priority rule affected high-complexity cases differently than predicted (e.g., their rework also increased), the redistribution hypothesis would need revision.
4. If January-February showed similar patterns to later months when segmented by supplier/complexity, some effects might be pre-existing rather than driven by timeline events.

**Most likely overall narrative:**
System migration caused a logging crisis in March that masked real process changes. The May supplier disruption initiated a performance decline through increased rework, which was amplified by June staffing cuts causing queueing delays. The July priority rule may have redistributed delays but didn't reduce overall rework. The seasonal October surge further strained the system, while December interventions provided partial relief. The process never returned to baseline, suggesting persistent behavioral adaptation to new constraints.
