# 2. Candidate Conversion Pipelines

| Pipeline                              | PM4Py calls                                                                                     | Expected benefit                                    | Expected risk                             | Failure condition                               |
|---------------------------------------|------------------------------------------------------------------------------------------------|---------------------------------------------------|--------------------------------------------|------------------------------------------------|
| POWL  Petri net  BPMN               | `convert_to_petri_net`, `convert_to_bpmn`                                                      | Relatively direct; preserves most semantics       | BPMN layout ambiguity; loss of concurrency    | BPMN collapse on loops or silent transitions  |
| POWL  Petri net  Process tree  BPMN | `convert_to_petri_net`, `convert_to_process_tree`, `convert_to_bpmn`                           | Hierarchical clarity if successful                | Process tree may fail; more abstraction risk  | Process tree exception; loop misinterpretation |

The preferred primary pipeline is `POWL  Petri net  BPMN`, as the behaviorally consistent Petri net establishes a firm foundation for BPMN conversion. The process tree adds conversion risk.

# 3. Conversion Code

```python
import pm4py

# Convert POWL to Petri net
net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(source_powl)

# Save initial Petri net visualization
pm4py.save_vis_petri_net(net_from_powl, im_from_powl, fm_from_powl, "petri_from_powl.png")

# Convert Petri net to BPMN
bpmn_from_net = pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)
pm4py.save_vis_bpmn(bpmn_from_net, "bpmn_from_net.png")

# Attempt intermediate process-tree conversion
try:
    tree_from_net = pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)
    pm4py.save_vis_process_tree(tree_from_net, "tree_from_net.png")
    
    # BPMN from process tree
    bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
    pm4py.save_vis_bpmn(bpmn_from_tree, "bpmn_from_tree.png")
except Exception as e:
    print(f"Process tree conversion failed: {e}")
    tree_from_net = None

# BPMN round trip back to Petri net
net_from_bpmn, im_from_bpmn, fm_from_bpmn = pm4py.convert_to_petri_net(bpmn_from_net)
pm4py.save_vis_petri_net(net_from_bpmn, im_from_bpmn, fm_from_bpmn, "net_from_bpmn.png")

# Diagnostics and soundness checks
if pm4py.check_is_workflow_net(net_from_powl):
    print("Initial net is a workflow net.")
if pm4py.check_is_workflow_net(net_from_bpmn):
    print("Round-tripped BPMN net is a workflow net.")

# Test reachability differences
reach_orig = pm4py.convert_to_reachability_graph(net_from_powl, im_from_powl, fm_from_powl)
reach_roundtrip = pm4py.convert_to_reachability_graph(net_from_bpmn, im_from_bpmn, fm_from_bpmn)
print(f"Original net reachability states: {len(reach_orig.states)}")
print(f"Round-tripped net reachability states: {len(reach_roundtrip.states)}")
```

# 5. Round-Trip Validation Code

```python
# Validate using footprints and bounded trace exploration
footprint_orig = pm4py.discover_footprints(net_from_powl, im_from_powl, fm_from_powl)
footprint_roundtrip = pm4py.discover_footprints(net_from_bpmn, im_from_bpmn, fm_from_bpmn)
assert footprint_orig == footprint_roundtrip, "Footprint mismatch between original and round-tripped nets."

# Bounded visible trace exploration with tau elimination
def explore_traces(net, im, fm, max_loops=3):
    traces = []
    explored = set()
    to_explore = [(tuple(im.items()), [])]

    while to_explore:
        marking, trace = to_explore.pop()
        if tuple(marking) in explored:
            continue
        explored.add(tuple(marking))

        if marking == fm:
            traces.append(trace)
            continue

        enabled_trans = pm4py.get_enabled_transitions(net, marking)
        for trans in enabled_trans:
            if trans.label is not None and len([t for t in trace if t == trans.label]) < max_loops:
                new_marking = pm4py.execute_transition(net, marking, trans)
                to_explore.append((new_marking, trace + [trans.label]))
    
    return traces

traces_orig = explore_traces(net_from_powl, im_from_powl, fm_from_powl)
traces_roundtrip = explore_traces(net_from_bpmn, im_from_bpmn, fm_from_bpmn)
assert traces_orig == traces_roundtrip, "Trace mismatch in visible sequences."
```

# 6. Visual-Semantics Review

Despite behavioral correctness, the BPMN visualizations may mislead stakeholders due to:

1. **Parallel Gateways** — Lack of clear concurrency versus interleaving distinction.
2. **Exclusive Gateways** — Silent transitions appear missing routes.
3. **Loop Representation** — BPMN loops may confuse binary-loop meanings.
4. **Routing Nodes** — Implicit routing (silent transitions) reduced to ambiguities.
5. **Graph Layout** — Unintended ordering imposed by visual positioning.

Suggested improvements include:

- Annotate all gateways with their explicit semantics (e.g., XOR vs AND).
- Provide a textual specification accompanying the BPMN diagram.
- Clearly document silent transitions in annotations.

# 7. Rejection Criteria

1. Generated Petri net or markings fail soundness checks.
2. A loop-iteration invariant is violated (e.g., loop skips).
3. Concurrency collapses to interleaving inappropriately.
4. Optional behavior cannot be represented in BPMN.
5. Final markings deviate after round-trip processes.
6. Silent transitions improperly eliminate paths.

# 8. Canonical Representation Recommendation

- **Canonical Model for Storage:** Petri net with accepting initial and final markings.
- **Visualization Model for Stakeholders:** BPMN diagrams annotated for semantic clarity.
- **Process-Tree Intermediate:** Permissible only for hierarchical subsystems.
- **Validation Evidence:** Round-trip verification traces, soundness tests, and invariant audits must accompany derived models.

# 9. Residual Uncertainty

1. Silent-transition behaviors across joining gateways cannot always be validated visually.
2. Concurrency versus interleaving fidelity depends on trusting Petri net models.
3. Exact fidelity to the XOR-gateway representation for optional behavior is unverifiable without stakeholder confirmation.
