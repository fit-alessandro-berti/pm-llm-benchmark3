## 1. Normalization Assumptions

The baseline uses zero added SLA tolerance and temporal-profile zeta = 1. All classifications concern sets of feasible true times, not probabilities or midpoint estimates. Different defensible treatments of weak evidence are shown separately.

For a displayed timestamp whose clock-time resolution interval, converted to UTC, is [r_lo, r_hi], and clock offset o in [a,b], the true-time interval is

`[r_lo - b, r_hi - a]`.

A positive offset means the source clock is fast, so it is subtracted. Resolution uncertainty is applied before clock correction. I retain the supplied millisecond endpoint for minute flooring: [display, display + 59.999 s]. Nearest-10-second rounding contributes ±5 s; nearest-minute rounding contributes ±30 s. Closed rounding endpoints conservatively include tie cases. HUB's measurement uncertainty and offset combine to ±1.5 s. Thus, relative to a displayed timestamp interpreted in UTC, the source envelopes are:

| Source | True-time displacement from displayed UTC value |
|---|---|
| HUB | [-1.5, +1.5] s |
| OPS-BER, normal diagnostics | [-120, +149.999] s |
| SENSOR | [-10, +10] s |
| VENDOR-NY | [-180, +239.999] s |
| LEGACY-BER | [-60, +119.999] s, separately for each fold |
| MOBILE-LON, before entry-delay interpretation | [-330, +330] s |
| T-409 OPS-BER, weak estimate only | [-720, +779.999] s; conditional, not a certified bound |

June Berlin is CEST, UTC+02:00; June New York is EDT, UTC−04:00; June London is BST, UTC+01:00. For Berlin's 2025-10-26 repeated hour, fold 0 uses UTC+02:00 and fold 1 uses UTC+01:00. I retain both alternatives before applying joint order constraints. None of the supplied rounding intervals crosses a local offset transition within its selected fold.

The clock bounds constrain each event separately. I do not assume that a source's offset is constant across events: daily diagnostics do not establish that correlation. A certified common offset would cancel in same-source differences and can tighten some results. No independence in a probabilistic sense, uniform distribution, or most-likely midpoint is assumed.

For two uncoupled event intervals X=[x_lo,x_hi] and Y=[y_lo,y_hi], the elapsed-time interval is [y_lo−x_hi, y_hi−x_lo]. With alternative intervals or dependent evidence, I instead project each feasible joint assignment onto Y−X and take the union. I do not subtract endpoints after discarding relevant dependencies, or add separate duration bounds to obtain a tighter direct-pair duration.

The baseline treats the named activities as stages of the same incident, with Alert_Received ≤ Investigation_Start ≤ Containment_Complete ≤ Close_Incident whenever those activities exist. Equality is allowed. These are lifecycle/causal assumptions, not SLA deadlines: an SLA violation is never removed from the feasible set. The temporal-profile pairs are eventually-following pairs, including the non-adjacent Alert_Received→Containment_Complete pair. If this lifecycle linkage is disputed, conclusions relying on it must be revisited.

An inclusive maximum M passes at equality. For a feasible duration set F, CERTAIN_PASS means F is nonempty and contained in the acceptance region; CERTAIN_VIOLATION means F is nonempty and disjoint from it; POSSIBLE_VIOLATION means both accepted and rejected durations exist. Empty, unbounded, insufficient, or semantically untestable evidence is INDETERMINATE, never a vacuous pass. For a two-sided profile, disjoint components can all violate on opposite sides of the band; their convex hull must not manufacture a passing duration.

## 5. PM4Py Temporal-Conformance Code

The following self-contained Python program requires pandas, PM4Py, and a Python time-zone database available to zoneinfo. It reconstructs all 29 supplied records, adds the two explicitly labeled inferred activities, normalizes the uncertainty, and uses difference constraints to preserve causal and inference dependencies. Each DST combination is a separate branch; infeasible branches are removed, and projections are merged only when they overlap. Empty branch sets classify as indeterminate.

The primary T-409 calculation omits the weak clock bound. The conditional model accepts it and supplies the **separate, explicitly lossy midpoint log** used for PM4Py. That log also assumes receipt occurred in T-407. Marginal midpoints are taken within one surviving joint branch, rounded down by at most 0.5 ms to retain integer milliseconds, and checked for joint feasibility; no midpoint is taken across a gap between DST alternatives. PM4Py receives ordinary point timestamps and does not resolve these uncertainty sets or evidential questions itself.

def merge(intervals):
    out = []
    for lo, hi in sorted(intervals):
        if lo > hi:
            continue
        if out and lo <= out[-1][1]:
            out[-1] = (out[-1][0], max(out[-1][1], hi))
        else:
            out.append((lo, hi))
    return out


def normalize(row, occurrence_delay=True):
    zone, rlo, rhi, olo, ohi = META[row.system]
    if row.case_id == "T-409" and row.activity == I:
        olo, ohi = -720000, 720000  # conditional weak estimate
    wall = datetime.fromisoformat(row.recorded)
    zi = ZoneInfo(zone)
    candidates = []
    for fold in (0, 1):
        aware = wall.replace(tzinfo=zi, fold=fold)
        utc = aware.astimezone(timezone.utc)
        # Reject nonexistent local times; deduplicate unambiguous folds below.
        if utc.astimezone(zi).replace(tzinfo=None) != wall:
            continue
        base = pd.Timestamp(utc).value // 1_000_000
        # Resolution interval first, then subtract offset interval.
        lo, hi = base + rlo - ohi, base + rhi - olo
        if row.system == "MOBILE-LON" and occurrence_delay:
            lo -= 300000  # occurrence = entry time - delay in [0, 5 min]
        candidates.append((lo, hi))
    if not candidates:
        raise ValueError("Nonexistent local timestamp: " + row.recorded)
    return merge(candidates)


def close_zone(bounds, constraints):
    """Exact difference constraints; D[i][j] bounds time_i - time_j."""
    names = ["ZERO"] + sorted(bounds)
    idx = {name: j for j, name in enumerate(names)}
    n = len(names)
    d = [[math.inf] * n for _ in range(n)]
    for j in range(n):
        d[j][j] = 0
    for name, (lo, hi) in bounds.items():
        j = idx[name]
        d[j][0], d[0][j] = hi, -lo
    for x, y, lo, hi in constraints:  # lo <= time_y - time_x <= hi
        ix, iy = idx[x], idx[y]
        d[iy][ix] = min(d[iy][ix], hi)
        d[ix][iy] = min(d[ix][iy], -lo)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                d[i][j] = min(d[i][j], d[i][k] + d[k][j])
    if any(d[j][j] < 0 for j in range(n)):
        return None
    return idx, d


def build_models(occurrence_delay=True, use_weak409=False):
    observed, domains, models = {}, {}, {}
    for case, group in raw.groupby("case_id", sort=True):
        dom = {r.activity: normalize(r, occurrence_delay)
               for r in group.itertuples(index=False)}
        observed[case] = {a: list(xs) for a, xs in dom.items()}
        extra = []
        if case == "T-409" and not use_weak409:
            # Do not promote the engineering estimate to a certified bound.
            # Retain only the stated baseline lifecycle order A <= I <= C.
            dom[I] = [(dom[A][0][0], dom[C][0][1])]
        if case == "T-404":
            dom[I] = [(lo - 1500000, hi - 1080000) for lo, hi in dom[K]]
            extra.append((I, K, 1080000, 1500000))
        if case == "T-407":
            # Contingent model: delivery occurred, and receipt preceded start.
            dom[A] = [(lo, hi + 1200000) for lo, hi in dom[S]]
            extra.append((S, A, 0, 1200000))
        chain = [a for a in (A, I, C, Z) if a in dom]
        extra += [(x, y, 0, math.inf) for x, y in zip(chain, chain[1:])]
        names = sorted(dom)
        branches = []
        for choices in product(*(dom[name] for name in names)):
            branch = close_zone(dict(zip(names, choices)), extra)
            if branch is not None:
                branches.append(branch)
        domains[case], models[case] = dom, branches
    return observed, domains, models


def projection(branch, x, y):
    idx, d = branch
    return -d[idx[x]][idx[y]], d[idx[y]][idx[x]]


def event_union(branches, activity):
    return merge(projection(b, "ZERO", activity) for b in branches)


def duration_union(branches, first, second):
    if not branches or first not in branches[0][0] or second not in branches[0][0]:
        return []
    return merge(projection(b, first, second) for b in branches)


def classify(intervals, lower_s, upper_s):
    if not intervals or any(not math.isfinite(v) for ab in intervals for v in ab):
        return IND
    lower, upper = lower_s * 1000, upper_s * 1000
    any_pass = any(max(lo, lower) <= min(hi, upper) for lo, hi in intervals)
    any_fail = any(lo < lower or hi > upper for lo, hi in intervals)
    if not any_pass:
        return CV
    return PV if any_fail else CP


def evidential_class(case, first, second, conditional):
    if case == "T-407" and A in (first, second):
        return IND
    return conditional


def iso(ms):
    return pd.to_datetime(ms, unit="ms", utc=True).isoformat(timespec="milliseconds").replace("+00:00", "Z")


def utc_text(intervals):
    return " U ".join(f"[{iso(lo)}, {iso(hi)}]" for lo, hi in intervals)


def seconds_text(intervals):
    return " U ".join(f"[{lo / 1000:.3f}, {hi / 1000:.3f}]" for lo, hi in intervals)

def decode_diagnostics(raw_diagnostics, ordered_cases):

## 6. Evidential Sufficiency

For a possible violation, the minimum useful evidence is a sufficiently narrow **certified duration bound**, or equivalent linked endpoint evidence, that lies wholly inside or wholly outside the relevant acceptance region. More decimal places on an unsynchronized timestamp do not provide that certificate. For a two-sided profile, evidence may need to eliminate both early and late possibilities. The following covers every baseline possible/indeterminate finding and every additional possible finding introduced by the sensitivity matrices.

| Case and unresolved findings | Minimum additional evidence that can make the classification certain |
|---|---|
| T-401 S1; P(A,I) at zeta 1–2 | Event-level OPS clock offset/drift evidence and the unrounded start timestamp, or a trusted paired A→I elapsed-time record. Narrow the duration relative to the selected SLA threshold and profile band; a tighter bound already sufficient to fall on one side is enough. |
| T-402 S1 at +2/+5 minutes; S2 at zero tolerance; P(A,I) at zeta 2–3; P(I,C) at zeta 1 | A trusted investigation-start time linked to this incident, or equivalent bounds on both A→I and I→C. Start uncertainty drives all of these; the HUB endpoints are already narrow. For example, P(A,I) at zeta 2 becomes certainly violated if its lower bound can be certified above 960 s. S2/P(I,C) require resolving the 2700 s boundary. |
| T-403 S1 at 0/+2 minutes; P(A,I) at all zeta; P(A,C) at zeta 1 | Receiver-side alert evidence or event-level vendor synchronization plus the unrounded alert time. ## 7. Governance Recommendation

Store occurrence times in UTC with explicit offsets, while retaining the original timestamp string, source time zone, IANA zone identifier, and conversion-rule version. For repeated local times, capture the numeric UTC offset and DST fold at the event. Reject or quarantine unresolved ambiguous/nonexistent local timestamps rather than silently choosing an offset. Preserve alternative intervals when ambiguity cannot be resolved.

Retain timestamp resolution and its semantics: floor, nearest rounding, truncation, measurement error, and tie handling. Record separate occurrence, entry, send, receipt, and ingestion times. User-entered fields should explicitly identify what time the user is asserting; any late-entry bound belongs to its own provenance field.

Capture source offset telemetry and drift bounds at a cadence appropriate to the SLA, including synchronization failures, clock steps, and the validity interval of each diagnostic. Preserve relative-clock/correlation evidence when it justifies cancellation. Distinguish certified bounds from engineering estimates and never carry a daily bound across an unmonitored gap without an explicit policy.

Use stable incident, alert, message, and activity-instance identifiers to connect sender/receiver acknowledgments and start/complete lifecycle events. Record start and completion separately, including whether a work duration is elapsed time or active effort. Keep signed work records and inferred timestamps as derived evidence with their formulas and dependencies; do not overwrite the missing raw event. Ingestion sequence should be documented as an ordering guarantee or treated only as ingestion order.

Version SLA definitions, any authorized tolerances, temporal-profile parameters, and semantic assumptions. Keep legal/operational maxima separate from statistical expectations, including the profile's lower bounds: unusually fast behavior can be statistically atypical while satisfying an SLA. Report evidence quality alongside the finding rather than embedding an undocumented confidence adjustment in the timestamp.

For enforcement, require credible evidence and **CERTAIN_VIOLATION** before an automatic breach determination. Interval overlap is sufficient to withhold an automatic breach finding, but is insufficient to certify compliance. Route POSSIBLE_VIOLATION to evidence collection and operational review; route INDETERMINATE to a missing-evidence or data-quality workflow. Award automated compliance only for CERTAIN_PASS under documented, accepted assumptions. Preserve the interval engine's findings as the auditable result and label any midpoint PM4Py dashboard as a lossy analytical view.
