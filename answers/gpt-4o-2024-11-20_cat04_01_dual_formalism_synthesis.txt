# 1. Assumptions and Interpretation

1. The low-risk/high-risk classification is modeled using an XOR split where the chosen path corresponds to either Supervisor Review (low risk) or Quality Review and Regulatory Review (high risk performed concurrently).
2. Optional supplier consultation is modeled with an XOR gateway to include a branch for Consult Supplier and a branch that skips it.
3. A passing inspection is abstracted as the completion of an Inspect Trial activity after one or more looped trial cycles.
4. Duplicate visible labels are **not permitted** in this model to avoid ambiguous trace analysis.
5. The process tree uses **permissive over-approximation**, allowing some additional interleavings to preserve flexibility in concurrency and synchronization.
6. "May overlap" is interpreted as true concurrency, enabling parallel execution of activities without explicit ordering constraints unless stated otherwise.

# 2. Intended Dependency Specification

| ID | Source activity or submodel     | Target activity or submodel    | Relation             | Rationale                                                                 |
|----|---------------------------------|--------------------------------|----------------------|---------------------------------------------------------------------------|
| 1  | Register Deviation              | Contain Material               | Sequence             | Containment starts immediately after registration.                        |
| 2  | Register Deviation              | Analyze Root Cause             | Sequence             | Root-cause analysis begins immediately after registration.                |
| 3  | Contain Material                | Plan Verification              | Sequence             | Verification planning depends on material containment being completed.    |
| 4  | Analyze Root Cause              | Design Corrective Action       | Sequence             | Corrective action design requires root-cause analysis completion.         |
| 5  | Analyze Root Cause              | Supervisor/Quality/Regulatory Reviews | XOR Sequence        | The risk level gates which approval track is needed after root analysis.  |
| 6  | Regulatory Review               | Release Material               | Sequence             | For high-risk cases, regulatory approval is required for release.         |
| 7  | Consult Supplier                | Release Material               | Sequence             | If supplier consultation occurs, it must finish before material release.  |
| 8  | Design Corrective Action, Plan Verification | Execute Trial | AND Sequence | Trials depend on both corrective action and verification planning.         |
| 9  | Execute Trial                   | Inspect Trial                  | Sequence             | Trial inspection always follows execution.                                |
| 10 | Inspect Trial                   | Adjust Parameters              | Loop Condition       | If inspection fails, parameters are adjusted, and a new trial is run.     |
| 11 | Approval reviews, passing Inspect Trial | Release Material | AND Synchronization | Releases occur only with a passing trial and completed approvals.         |
| 12 | Release Material                | Archive Case                   | Sequence             | Cases are archived after material release.                                |

# 3. PM4Py Process-Tree Model

### Compact Process-Tree Expression
``` 
(SEQUENCE(Register Deviation, AND(SEQUENCE(Contain Material, Plan Verification), SEQUENCE(Analyze Root Cause, XOR(SEQUENCE(Supervisor Review), PARALLEL(Quality Review, Regulatory Review)), Optional Consult Supplier, SEQUENCE(AND(Design Corrective Action, Plan Verification), LOOP(Execute Trial, Inspect Trial, Adjust Parameters)))), Release Material, Archive Case))
```

### Python Code
```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

# Create nodes for the process tree
register_deviation = ProcessTree(label="Register Deviation")
contain_material = ProcessTree(label="Contain Material")
analyze_root_cause = ProcessTree(label="Analyze Root Cause")
plan_verification = ProcessTree(label="Plan Verification")
design_corrective_action = ProcessTree(label="Design Corrective Action")
supervisor_review = ProcessTree(label="Supervisor Review")
quality_review = ProcessTree(label="Quality Review")
regulatory_review = ProcessTree(label="Regulatory Review")
consult_supplier = ProcessTree(label="Consult Supplier")
execute_trial = ProcessTree(label="Execute Trial")
inspect_trial = ProcessTree(label="Inspect Trial")
adjust_parameters = ProcessTree(label="Adjust Parameters")
release_material = ProcessTree(label="Release Material")
archive_case = ProcessTree(label="Archive Case")

# Define the trial loop
trial_loop = ProcessTree(operator=Operator.LOOP)
trial_loop.children = [execute_trial, inspect_trial, adjust_parameters]

# Define the risk evaluations
risk_evaluation = ProcessTree(operator=Operator.XOR)
risk_evaluation.children = [supervisor_review, ProcessTree(operator=Operator.PARALLEL, children=[quality_review, regulatory_review])]

# Define parallel branches for containment and root-cause analysis
containment_and_analysis = ProcessTree(operator=Operator.AND)
containment_and_analysis.children = [
    ProcessTree(operator=Operator.SEQUENCE, children=[contain_material, plan_verification]),
    ProcessTree(operator=Operator.SEQUENCE, children=[
        analyze_root_cause, risk_evaluation, consult_supplier, 
        ProcessTree(operator=Operator.AND, children=[design_corrective_action, plan_verification]),
        trial_loop
    ])
]

# Assemble the full process
tree = ProcessTree(operator=Operator.SEQUENCE)
tree.children = [register_deviation, containment_and_analysis, release_material, archive_case]
```

### Approximation Explanation
- Over-approximation allows concurrent activities even if strict dependencies exist (e.g., supplier consultation need not wait for reviews explicitly).
- The process tree cannot enforce the loop termination condition where Adjust Parameters must not occur after a passing inspection; this is semantically imprecise.
- Optional Consult Supplier is modeled as always concurrent where allowed; the process tree cannot model conditions for its inclusion/exclusion explicitly.

# 4. PM4Py POWL Model

### Compact POWL Description
``` 
XOR(Register Deviation -> AND(Contain Material, Analyze Root Cause)) ->
AND(SEQUENCE(Contain Material -> Plan Verification),
    SEQUENCE(Analyze Root Cause -> XOR(Supervisor Review, PARALLEL(Quality Review, Regulatory Review)), 
             Optional Consult Supplier, 
             AND(Design Corrective Action, Plan Verification) -> 
             LOOP(Execute Trial -> Inspect Trial -> Adjust Parameters))) ->
SEQUENCE(Release Material -> Archive Case)
```

### Python Code
```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition

# Define transitions
register_deviation = Transition("Register Deviation")
contain_material = Transition("Contain Material")
analyze_root_cause = Transition("Analyze Root Cause")
plan_verification = Transition("Plan Verification")
design_corrective_action = Transition("Design Corrective Action")
supervisor_review = Transition("Supervisor Review")
quality_review = Transition("Quality Review")
regulatory_review = Transition("Regulatory Review")
consult_supplier = Transition("Consult Supplier")
execute_trial = Transition("Execute Trial")
inspect_trial = Transition("Inspect Trial")
adjust_parameters = Transition("Adjust Parameters")
release_material = Transition("Release Material")
archive_case = Transition("Archive Case")

# Create StrictPartialOrder model
powl_model = StrictPartialOrder()

# Add transitions to model
powl_model.nodes.update({register_deviation, contain_material, analyze_root_cause, plan_verification,
                         design_corrective_action, supervisor_review, quality_review, regulatory_review,
                         consult_supplier, execute_trial, inspect_trial, adjust_parameters,
                         release_material, archive_case})

# Define precedence relations
powl_model.order.add_edge(register_deviation, contain_material)
powl_model.order.add_edge(register_deviation, analyze_root_cause)
powl_model.order.add_edge(contain_material, plan_verification)
powl_model.order.add_edge(analyze_root_cause, design_corrective_action)
powl_model.order.add_edge(analyze_root_cause, supervisor_review)
powl_model.order.add_edge(analyze_root_cause, quality_review)
powl_model.order.add_edge(analyze_root_cause, regulatory_review)
powl_model.order.add_edge(design_corrective_action, execute_trial)
powl_model.order.add_edge(plan_verification, execute_trial)
powl_model.order.add_edge(execute_trial, inspect_trial)
powl_model.order.add_edge(inspect_trial, adjust_parameters)  # Loop connection
powl_model.order.add_edge(inspect_trial, release_material)   # Passing inspection
powl_model.order.add_edge(release_material, archive_case)
```

### Explanation of Concurrency
- Nodes not connected by an `add_edge` relation are explicitly concurrent (e.g., Design Corrective Action and Plan Verification).
