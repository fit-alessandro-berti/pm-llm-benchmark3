## 1. Target definition

**Primary formulation — multi-state / competing-outcome cumulative incidence for all applications.**

- **Unit of analysis:** one credit application (one `case:concept:name`).
- **Prediction time :** the timestamp of the 3rd canonical event (post-deduplication, post-renaming map; see §4). Secondary landmark: application start + 5 elapsed days. Cases that reach a terminal state at or before  are not scored at  (their outcome is already known) and form a separate short-prefix stratum.
- **Horizon:** landmark at  + 180 days. The default event is defined as: `Account Activated` occurs by  + 90 days **and** a default is recorded within 90 days of activation (the warehouse `default_90d` semantics). The activation window (90d) must be validated against the observed startactivation distribution and widened if the 95th percentile exceeds it.
- **Population:** all 48,000 applications started 2024-01-01…2025-12-31 — not just the 21,600 labeled rows.
- **Estimand:** the cause-specific cumulative incidence function
  F_default(t | x) = P(T  t, J = default | X() = x), t = 180d,
  with competing states J  {default, activated-and-survived-90d, rejected, withdrawn, transferred} and right censoring. This is a **dynamic prediction under the observed activation policy**, not a causal effect.

**Why this is the defensible primary target.** Default is physically impossible without activation, and activation is fully observed in the event log. Therefore "default by +180d" is *defined for every application*, including rejected and withdrawn ones (for whom it is structurally 0 under the observed policy — not an imputed "non-default label" on a missing outcome). It uses all 48,000 cases, never conditions on the post-prediction selection event (activation), matches the business question ("early warning over the pipeline"), and maps onto standard competing-risk machinery (Aalen–Johansen; discrete-time cause-specific hazards).

**Alternative targets (different questions):**

1. **Default among activated accounts** — P(default_90d = 1 | activated, X()). Answers "risk of loans we actually booked" (pricing/limit-setting). It is *not* an answer to "default for every application": it conditions on a post-, policy-dependent selection event, so its population shifts silently at the 2025-07-01 policy change. Kept as a **secondary model** for the credit-risk team.
2. **Time-to-default after activation with right censoring** — refines timing among activated accounts; same selection caveat; useful for provisioning curves.
3. **Policy-specific counterfactual** — P(default_90d under do(activate)) for a proposed acceptance policy . This is the question underwriting actually wants for policy design, but it requires exchangeability given observed covariates, positivity, and consistency — and for rejected applicants it extrapolates into a region with zero support. It is labeled **research-only, requiring explicit causal assumptions**, and is not identified from these data alone.

Rejected, withdrawn, and open cases are **never** coded as non-default.

## 2. Cohort construction

**Inclusion:** applications with `Application Started` in 2024-01-01…2025-12-31; 1 canonical event; not an internal/test case.
**Exclusions (from the k=3 modeling cohort only, still counted in the flow):** cases with <3 canonical events or a terminal event at/before  (already resolved at prediction time); exact duplicate events removed by the dedupe rule.
**As-of rules:** (i) features use only events with timestamp  ; (ii) a label is usable at analysis as-of date C only if `label_available_at`  C; (iii) an activated account with no feed is declared *permanently missing* only after activation + 90d + 35d (max feed lag)  C, otherwise it is *label-pending*; (iv) walk-forward backtests additionally hide all events after C.

**Cohort flow (extraction as-of 2026-02-15):**

| Segment | N | % | Role in primary analysis |
|---|---|---|---|
| Applications started | 48,000 | 100 | Source population |
| Activated, label mature (`default_90d` received) | 21,600 | 45.0 | **Labeled**: 2,700 default events, 18,900 activated-survived |
| Activated, outcome/feed not matured | 3,600 | 7.5 | Right-censored (delayed label); subset past activation+125d without feed  **permanently missing feed** (MNAR risk, enriched for partner-originated) |
| Rejected | 9,100 | 19.0 | **Competing terminal state** — never at risk of default under observed policy |
| Withdrawn | 5,700 | 11.9 | **Competing terminal state** |
| Transferred | 2,900 | 6.0 | Censored at transfer (primary); ~1,740 (60%) linked  partially recoverable follow-up; ~1,160 unlinked |
| Still open at extraction | 5,100 | 10.6 | Administratively right-censored at 2026-02-15 |
| *of which:* resolved at/before  (count from log, expected small, mostly fast rejections/withdrawals) | TBD | — | Excluded from k=3 scoring cohort; short-prefix stratum |

Check: 21,600 + 3,600 + 9,100 + 5,700 + 2,900 + 5,100 = 48,000. The 21,600-row export is **not** the study cohort; it is the labeled subset of a selectively observed cohort.

## 3. Censoring and missing-label strategy

| Mechanism | Nature | Handling |
|---|---|---|
| **Ordinary right censoring** (5,100 open; part of 3,600 pending) | Administrative, calendar-driven | Censor at min(extraction, +180d); standard KM/Aalen–Johansen or discrete-time hazards |
| **Delayed labels** (feed lag 7–35d) | Label valid only when `label_available_at`  as-of | Maturity rule (activation+125d); never treat "no feed yet" as non-default |
| **Selection through activation** | Outcome *undefined* without activation; activation is post- and policy-dependent | Primary estimand does not condition on activation; conditional model is secondary and era-stratified |
| **Transfer** (2,900) | Hybrid: competing event for *our book*; missing follow-up for the *applicant* | Primary: censor at transfer; linked 60% used to audit; sensitivity: competing terminal / bounds |
| **Permanently missing feeds** (partner-originated) | Potentially MNAR | Complete-case + IPCW (missingness model on channel, region, source_system); pattern-mixture sensitivity |

**Primary strategy:** discrete-time cause-specific hazard model (multinomial over states per period) with administrative censoring at min(extraction, +180d), transfer censoring at transfer time, maturity-gated labels, and IPCW for feed missingness. Nonparametric Aalen–Johansen CIFs per era as a reference.

**Sensitivity analyses:** (1) transfer-as-competing vs. transfer-as-censoring vs. linked-only; (2) tipping-point pattern mixture: inflate default odds among `feed_missing` by   [0.5, 3] and report where conclusions flip; (3) best/worst-case bounds for unlinked transfers; (4) conditional-on-activation survival model.

**Testability:** feed-delay distribution — **testable** from received feeds. Non-informativeness of administrative censoring — **partially testable** (covariate balance censored vs. not). Transfer-censoring ignorability — **partially testable** within the linked 60%, but linkage selection itself is untestable. MAR for permanent feeds — **untestable** (MNAR plausible by construction). Counterfactual default of rejected applicants — **fundamentally untestable** from these data.

## 4. Prefix extraction

1. **Canonicalize before anything else:** apply the activity-rename map for the 2025-10-15 migration; validate by comparing `pm4py.get_variants` / DFG structure pre- vs. post-migration. Version the mapping.
2. **Deduplicate:** drop same-case, same-canonical-activity events within a 2-minute window (migration artifact); document the threshold.
3. **Order:** sort by timestamp with a stable tie-break; record the rule.
4. **Fixed-count prefixes:** first k canonical events, k  {1,…,5}, primary k=3; _k = timestamp of the k-th event. Terminal events (Accept/Reject/Withdrawn/Transferred) are **outcome-defining, never features**; cases terminating at or before event k are excluded from the k-cohort.
5. **Elapsed-time prefixes:** all events with timestamp  start + ,   {1,3,5,10} days, truncated at any terminal event; a case with no further events in  has prefix = start event only. Report the two prefix families separately: event-count prefixes mix heterogeneous elapsed times; elapsed-time prefixes mix heterogeneous event counts.
6. **Short cases:** scored with the largest feasible k or the -prefix; never padded with future events.
7. **Document loops:** repeated `Credit Review  Request Documents` cycles are **kept** (loop count is signal); canonical naming ensures loops are counted identically across eras.
8. Assert per case: all prefix events  ;  < terminal time.

## 5. Process-aware features

**Static case attributes (recorded at/before ):** channel, region, requested_amount, source_system, application day-of-week/month.

**Prefix-derived (computed only from events  ):** counts per activity; number of document-request loops and review cycles; last activity; variant id; prefix duration; inter-event waiting times (mean/max — queue proxy); time since start; number of distinct handlers and handoffs; `risk_score` trajectory within the prefix (first, last, delta) **after verifying the values are event-sourced, not backfilled**; era indicators (pre/post 2025-07-01 policy, pre/post 2025-10-15 migration).

**Historical reference features (as-of , maturity-aware):** rolling default rate for channel×region using **only labels with `label_available_at`  ** (equivalently, activations older than ~125 days — a naive rolling rate is biased downward because recent defaults are not yet observable); team workload/queue length in the prior 7 days; handler historical throughput estimated from pre- data only.

**Excluded:** resource experience (stored at extraction time — drop unless an HR history allows as-of reconstruction); `documents_total` unless recomputed from upload events   (see §6).

## 6. Leakage audit

| Feature or data element | Leakage or bias risk | Valid availability rule | Keep/repair/drop | Rationale |
|---|---|---|---|---|
| `final_limit` | Populated only after final credit decision — post- | Only if decision precedes  (not the case for early warning) | **Drop** | Encodes the decision the model must precede |
| `decision_reason` | Written at/after Accept/Reject | Never at  | **Drop** | Directly reveals the decision |
| `collection_status` | Post-activation; may literally encode default | Never at  | **Drop** | Label leakage |
| Future events (Contract Signed, Account Activated, Collections Contact, Default Recorded) | Post- | Only for outcome bookkeeping (activation time, competing states), never as features | **Keep for labels only** | Prefix assertion `event_time  ` enforced in code |
| `documents_total` | Nightly snapshot includes same-day-later uploads | Recompute as count of upload events with timestamp   | **Repair** | Event-time count restores as-of semantics |
| `risk_score` (updated at several events) | If overwritten in place, the "historical" value is the current one | Use value at last prefix event only after verifying within-case variation across events; if constant per case  backfilled | **Repair / conditional keep** | Backfilled scores leak future risk assessments |
| Resource experience | Stored at extraction date, not event time | Only if reconstructable as-of  from HR history | **Drop** (repair if history exists) | Future information; also survivorship-biased |
| `label_available_at` | Delay correlates with outcome; also defines maturity | Use only to gate label usability (` as-of`); never a feature | **Keep for audit, drop as feature** | Prevents using immature labels; prevents delay-as-signal leakage |
| `default_90d` on events | Label, not a feature; usable only after `label_available_at` | Event-level gating by `label_available_at  as-of` | **Keep as label only** | Avoids training on labels that "arrived early" |
| `data_extract_time` | Constant per snapshot; any full-extraction aggregate leaks | Never a feature | **Drop** | Trivial future information |
| Post-migration duplicate events | Not leakage but double-counts loops/waits | Dedupe rule (§4) | **Repair** | Bias in rework/queue features |
| Transfer linkage table | Non-random 60% coverage | Outcome augmentation in sensitivity analyses only | **Keep (sensitivity)** | Using it in the primary analysis imports linkage-selection bias |
| `case:channel`, `case:region`, `case:requested_amount`, `org:resource` | Low risk if recorded at start; resource effects must be estimated pre- | Value as of  | **Keep** | Baseline legitimate predictors |

## 7. Validation design

**Primary split — temporal by case start time** (never random):
- Train: starts 2024-01-01…2024-12-31 (fully mature by extraction).
- Validation: 2025-01-01…2025-06-30 (pre-policy-change).
- Test A: 2025-07-01…2025-10-14 (post-policy, pre-migration).
- Test B: 2025-10-15…2025-12-31 (post-migration).

Note the honest constraint: Test B cases activated late in 2025 cannot be label-mature by 2026-02-15 (activation + 125d), so Test B supports **drift detection and partial, censoring-corrected evaluation only** — definitive post-migration outcome evaluation is impossible at this extraction date, and the report must say so.

**Walk-forward backtesting:** quarterly as-of cutoffs (2025-01-01, 2025-04-01, 2025-07-01, 2025-10-01, 2026-01-01). At each cutoff C: rebuild the case table using only events  C and labels with `label_available_at`  C (the `as_of_view` function in §9), refit, evaluate on the next window. This reproduces what was actually knowable in production, including the 125-day label lag.

**Why a random split misleads here:** it mixes pre/post policy-change selection mechanisms and pre/post-migration measurement regimes; it places future cases in training while their labels share the same extraction date as past cases (maturity leakage); it hides calibration drift across eras; and it overstates performance under the exact shift (2025-07-01) the model will face. `pm4py.split_train_test` may be reported as a convenience baseline but is not evidence.

**Metrics (matched to target and censoring):** IPCW-weighted time-dependent Brier score and integrated Brier at 180d; time-dependent AUC for the default CIF; IPCW calibration curves and calibration-in-the-large at the landmark; cause-specific log-loss for the discrete-time model. For the secondary conditional model: PR-AUC (prevalence 12.5% among labeled), Brier, calibration slope/intercept, Spiegelhalter test. Case-level bootstrap CIs, **clustered by linked applicant identity** for reappearing transfers.

**Subgroups and shift:** report metrics plus censoring proportions by channel (partner vs. direct — the MNAR risk group), region, era, amount bands, and loop-count strata; PSI on key prefix features across eras; variant-distribution comparison across the migration; CIF comparison across the policy change with interaction terms.

## 8. Limitations and decision-use boundary

**What the study can claim:** calibrated, era-specific predictive association — the cumulative incidence of default within 180 days of  for applications resembling those processed under the observed policy; ranking quality within eras; conditional 90-day default risk among activated accounts.

**What it cannot claim:** the default risk a rejected applicant *would have had* (undefined under the observed policy, not zero); the portfolio effect of changing acceptance thresholds; any causal effect of model-driven actions; outcomes of unlinked transfers; MNAR-corrected default rates without untestable assumptions.

**Association vs. selection vs. counterfactual:** the primary CIF is associational under the *observed* activation policy. The conditional model among activated accounts carries a **selection effect**: the activated mix is produced by a policy that changed on 2025-07-01, so the same prefix can map to different risk across eras. The counterfactual "risk if we activate this applicant" is a **different estimand** requiring exchangeability, positivity, and consistency, and is not point-identified for rejected applicants.

**Deployment will change the data-generating process (at least):**
1. **Selective labels / feedback loop:** if the model influences acceptance, future training labels become conditioned on the model's own score; the activated cohort drifts and naive retraining amplifies the bias.
2. **Informative transfer censoring:** routing model-flagged applications to partners makes transfer censoring outcome-dependent and increases reliance on the partner feed with elevated permanent missingness.
3. **Applicant/intermediary adaptation:** document timing, channel choice, and application structuring respond to the model, changing the prefixoutcome mapping.
4. **Operational change:** triage alters queues and resource assignment, so waiting-time and handoff features change meaning.
5. **Policy drift:** future threshold changes shift selection exactly as on 2025-07-01.

Required safeguards: logged policy/score at decision time, drift monitoring with maturity-aware dashboards, periodic recalibration per era, champion–challenger with randomized holdout where ethically permissible, and periodic re-linkage of transfers.

## 9. PM4Py-oriented Python implementation skeleton

```python
"""
As-of-correct data/audit pipeline for the early-warning study (Sections 1-8).
Primary target: competing-risk cumulative incidence of default at landmark
tau + 180d (default := activated by tau+90d AND default_90d == 1).
No model fitting here; survival/competing-risk hooks are marked. [A#] = assumptions.
"""
import numpy as np
import pandas as pd
import pm4py

CSV = "applications_events.csv"
CASE, ACT, TS = "case:concept:name", "concept:name", "time:timestamp"
K = 3                                  # fixed prefix length (events)
HOR = pd.Timedelta(days=180)           # landmark horizon from tau
ACT_WIN = pd.Timedelta(days=90)        # activation must occur by tau + 90d
FEED_MAX = pd.Timedelta(days=35)       # worst-case outcome-feed delay
EXTRACT = pd.Timestamp("2026-02-15")   # extraction / as-of date
POLICY = pd.Timestamp("2025-07-01")    # credit-policy change
MIGR = pd.Timestamp("2025-10-15")      # system migration
TERMINAL = {"Rejected", "Withdrawn", "Transferred"}   # pre-activation terminal states
ACTIVATED = "Account Activated"
ACT_MAP = {  # [A1] canonicalisation across the migration; validate vs. runbook + variants
    "KYC_Check": "Identity/KYC Check", "Identity Verification": "Identity/KYC Check",
    "Credit_Review": "Credit Review", "App_Started": "Application Started",
}
BANNED = {"final_limit", "decision_reason", "collection_status", "default_90d",
          "label_available_at", "data_extract_time"}   # post-decision/outcome: never features

# ---------------- load, canonicalise, de-duplicate ---------------------------
df = pd.read_csv(CSV, parse_dates=[TS, "label_available_at", "data_extract_time"])
df[ACT] = df[ACT].replace(ACT_MAP)
df = df.sort_values([CASE, TS], kind="mergesort").reset_index(drop=True)  # stable tie order [A2]
dupe = (df[CASE].eq(df[CASE].shift()) & df[ACT].eq(df[ACT].shift())
        & df[TS].sub(df[TS].shift()).le(pd.Timedelta(minutes=2)))  # [A3] migration duplicates
df = df.loc[~dupe].copy()
df = pm4py.format_dataframe(df, case_id=CASE, activity_key=ACT, timestamp_key=TS)
log = pm4py.convert_to_event_log(df)

# ------------- case-level outcome bookkeeping as of a configurable cutoff ----
def build_case_table(events, as_of):
    """Everything knowable at `as_of`: events after as_of are invisible; labels
    count only once their feed has arrived (label_available_at <= as_of)."""
    ev = events.loc[events[TS].le(as_of)]
    g = ev.groupby(CASE)
    case = pd.DataFrame({"t_start": g[TS].min(), "n_events": g.size(),
                         "tau": g[TS].nth(K - 1)})            # prediction time (NaT if < K events)
    case["t_activation"] = ev.loc[ev[ACT].eq(ACTIVATED)].groupby(CASE)[TS].min()
    term = ev.loc[ev[ACT].isin(TERMINAL)].groupby(CASE).agg(t_term=(TS, "min"), state=(ACT, "first"))
    case = case.join(term)
    lbl = ev["default_90d"].where(ev["label_available_at"].le(as_of))   # event-level label gating
    case["label"] = lbl.groupby(ev[CASE]).max()                          # 1.0 / 0.0 / NaN (no feed)
    case["label_at"] = g["label_available_at"].min()
    # Optional: merge transfer linkage (~60%) to recover partner outcomes [A4: linkage not random]
    overdue = case["t_activation"].add(pd.Timedelta(days=90) + FEED_MAX).le(as_of)
    seen = case["label"].notna()
    conds = [case["state"].isin(["Rejected", "Withdrawn"]),
             case["state"].eq("Transferred"),
             case["t_activation"].notna() & seen,
             case["t_activation"].notna() & ~seen & overdue,   # permanently missing feed (MNAR risk)
             case["t_activation"].notna()]                     # delayed label / not yet mature
    case["cohort"] = np.select(conds, ["competing", "transfer_censored", "labeled",
                                       "feed_missing", "label_pending"], default="open_censored")
    case["Y"] = np.where(case["cohort"].eq("labeled"),
                         (case["label"].eq(1.0) & case["t_activation"].le(case["tau"] + ACT_WIN)).astype(float),
                         np.nan)  # [A5] default with activation after tau+ACT_WIN scored 0; refine with true default dates
    return case

case = build_case_table(df, EXTRACT)
print(case["cohort"].value_counts())
assert len(case) == 48_000            # reconcile with the snapshot (Section 2)

# ---------------- eligibility at prediction time -----------------------------
resolved_early = case["t_term"].le(case["tau"]) | case["n_events"].lt(K)
model_ids = case.index[~resolved_early & case["tau"].notna()]   # early-resolved: separate stratum

# ---------------- temporal split by case start (NO random split) -------------
bins = [pd.Timestamp("2024-01-01"), pd.Timestamp("2025-01-01"), POLICY, MIGR, pd.Timestamp("2026-01-01")]
case["split"] = pd.cut(case["t_start"], bins=bins, right=False,
                       labels=["train_2024", "val_pre_policy", "test_post_policy", "test_post_migration"])
# Convenience baseline only (random, era-mixing; NOT used for validation):
# pm4py.split_train_test(log, train_percentage=0.8)

# ---------------- fixed-length prefixes (future cannot enter) ----------------
prefix_log = pm4py.get_prefixes_from_log(log, K)                # first K canonical events per case
pdf = pm4py.convert_to_dataframe(prefix_log)
pdf = pdf.merge(case[["tau"]], left_on=CASE, right_index=True, how="inner")
assert pdf[TS].le(pdf["tau"]).all()                             # hard as-of guarantee

# ---------------- process audit across eras ----------------------------------
for era_name, sub in pdf.groupby(np.where(pdf[TS].lt(MIGR), "pre_migr", "post_migr")):
    dfg, sa, ea = pm4py.discover_dfg(sub)        # [A6] edges/variants should match after ACT_MAP
    print(era_name, "| variants:", len(pm4py.get_variants(sub)),
          "| top edges:", sorted(dfg, key=dfg.get, reverse=True)[:5])

# ---------------- features from prefixes only --------------------------------
pdf["wait_h"] = pdf.groupby(CASE)[TS].diff().dt.total_seconds().div(3600.0)  # queue/rework proxy
# NB: pm4py.insert_case_service_waiting_time assumes start+complete timestamps; with a single
# timestamp per event, 'service time' is not identifiable -> waiting time only.
feat = pdf.groupby(CASE).agg(
    n_prefix_events=(ACT, "size"),
    n_doc_requests=(ACT, lambda s: int(s.eq("Request Documents").sum())),
    n_review_loops=(ACT, lambda s: max(int(s.eq("Credit Review").sum()) - 1, 0)),
    last_activity=(ACT, "last"),
    prefix_hours=(TS, lambda s: (s.max() - s.min()).total_seconds() / 3600.0),
    wait_h_max=("wait_h", "max"),
    n_handlers=("org:resource", "nunique"),
    channel=("case:channel", "first"), region=("case:region", "first"),
    amount=("case:requested_amount", "first"),
    risk_at_tau=("risk_score", "last"),          # [A7] value AT last prefix event; reject if backfilled
)
tmp = pm4py.extract_temporal_features_dataframe(pdf.drop(columns=["tau"]))  # PREFIX frame only
feat = feat.merge(tmp.add_prefix("tmp_").rename(columns={f"tmp_{CASE}": CASE}), on=CASE, how="left")

# ---------------- assemble modelling table + leakage audit -------------------
data = (feat.join(case[["Y", "cohort", "split", "tau", "t_start"]])
            .loc[lambda d: d.index.isin(model_ids)])
data["post_policy"] = data["t_start"].ge(POLICY).astype(int)
data["post_migration"] = data["t_start"].ge(MIGR).astype(int)

def leakage_audit(frame):
    issues = []
    if BANNED & set(frame.columns):
        issues.append(f"banned post-prediction columns present: {sorted(BANNED & set(frame.columns))}")
    if pdf[TS].gt(pdf["tau"]).any():
        issues.append("post-tau events inside prefix features")
    stale = case["cohort"].eq("labeled") & case["label_at"].gt(EXTRACT)
    if stale.any():
        issues.append(f"{int(stale.sum())} labels used before label_available_at")
    return issues or ["clean"]

data = data.drop(columns=[c for c in BANNED if c in data.columns], errors="ignore")
print(leakage_audit(data))
print(data.groupby(["split", "cohort"], observed=True).size())  # era x cohort reconciliation

# ---------------- modelling hooks (outside PM4Py) -----------------------------
# * Competing-risk CIF: per case build (t_event, state) with
#   t_event = min(t_term, t_activation, tau + HOR, as_of) and fit Aalen-Johansen or
#   discrete-time cause-specific hazards (lifelines / scikit-survival), with IPCW for
#   transfer censoring and feed missingness. PM4Py has no survival estimator - do not fake one.
# * Walk-forward backtest: for cutoff in [...]: tbl = build_case_table(df, cutoff);
#   train on tbl['split']-consistent past, evaluate on the next window.
# * Secondary conditional model: cohort == 'labeled', binary default_90d, maturity-gated.
```
