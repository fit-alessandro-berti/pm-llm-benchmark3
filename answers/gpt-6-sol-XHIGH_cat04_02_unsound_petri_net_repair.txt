# 1. Executive Verdict

The net is a workflow net: `source` and `sink` are its unique entry and exit, and every node lies on a source-to-sink path. It is nevertheless unsound. `t_join_waived` consumes the waiver token without consuming or waiting for the analysis token. Thus `t_authorize` can fire before analysis, and the waiver route can put a token in `sink` while leaving a token in `p_analysis` or `p_analysis_done`. That marking is not the required final marking. A case with a recorded waiver can therefore appear authorized and finished even though mandatory analysis is incomplete, and it cannot finish cleanly.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_split` | Start analysis and review in parallel. | Consumes `p_ready` and creates one token in each of `p_analysis` and `p_review`. | Both tokens must eventually be accounted for. |
| `t_standard_review` | Record the standard review outcome. | Competes for the single `p_review` token and produces `p_review_done`. | This route can synchronize correctly with analysis. |
| `t_waive_review` | Record the waiver as the alternative review outcome. | Competes for that same `p_review` token and produces `p_waived`; the alternatives are exclusive. | Once waiver fires, `p_review_done` cannot be produced in that case. |
| `t_join_normal` | Wait for analysis and standard review. | Requires both `p_analysis_done` and `p_review_done`, then produces `p_decision`. | Correct on the standard route; permanently unavailable after waiver. |
| `t_join_waived` | Wait for analysis and waiver. | Requires only `p_waived`, then produces `p_decision`. | Authorization is enabled while analysis is unfinished; the analysis token is stranded. |
| `im` and `fm` | Start with one case token and finish with exactly one token in `sink`. | `im = {source: 1}` and `fm = {sink: 1}`. A marking containing `sink` plus another token is not `fm`. | Apparent completion can be improper completion. |
| Whole graph | Provide a workflow from entry to exit. | `source` has no incoming arcs, `sink` has no outgoing arcs, and every place and transition lies on some source-to-sink path. | The structural workflow-net check succeeds despite the behavioral defect. |

# 3. Marking-Based Counterexample

A legal sequence is `t_register, t_split, t_waive_review, t_join_waived, t_authorize, t_analyze`. Each listed marking has one token in each named place.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (`im`) | `{source}` | `t_register` | One case begins. |
| 1 | `t_register` | `{p_ready}` | `t_split` | The case is ready to split. |
| 2 | `t_split` | `{p_analysis, p_review}` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token exists in each parallel branch. |
| 3 | `t_waive_review` | `{p_analysis, p_waived}` | `t_analyze`, `t_join_waived` | Waiver has consumed the only review token; analysis is pending. |
| 4 | `t_join_waived` | `{p_analysis, p_decision}` | `t_analyze`, `t_authorize` | The decision token was created without analysis. |
| 5 | `t_authorize` | `{p_analysis, sink}` | `t_analyze` | Authorization occurred before analysis. A token exists in `sink`, but this marking is not `fm`. |
| 6 | `t_analyze` | `{p_analysis_done, sink}` | None | Analysis can occur after authorization, but the marking still is not `fm` and is dead. |

Analysis before authorization does not fix the waiver route. For example, `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize` ends at `{p_analysis_done, sink}`. After `t_waive_review`, no token can reach `p_review_done`, so `t_join_normal` cannot consume `p_analysis_done`. `t_join_waived` consumes only `p_waived`. Hence the leftover analysis token cannot be cleared, whether analysis fires before or after authorization. This is another ordering of the same defect, not an independent structural fault.

# 4. Minimal-Repair Alternatives

Edit cost is one per added or removed ordinary arc, place, or transition. Redirecting an arc costs two: remove the old arc and add the new one. Labels and comments have no cost. The costs below are relative to the given net.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| A. Synchronize the waiver join | Add `p_analysis_done → t_join_waived`. | 1 | Analysis is mandatory; either review outcome must finish before authorization. | Waiver authorization now waits for completed analysis. | Two silent joins remain, so their different purposes should be clear to maintainers. |
| B. Route waiver through the common join | Remove `t_join_waived → p_decision`; add `t_join_waived → p_review_done`. | 2 | Same business rule and same visible task traces as A. | `t_join_waived` becomes a silent conversion of waiver into a completed review token; `t_join_normal` synchronizes both review outcomes with analysis. | The name `t_join_waived` becomes misleading, and the waiver route has an extra silent step before synchronization. |
| C. Explicitly allow analysis to be skipped under waiver | Add `p_analysis → t_join_waived`; add a silent transition `t_waiver_to_review` and arcs `p_waived → t_waiver_to_review → p_review_done`. | 4 | Standard review still requires analysis; a waiver remains visibly recorded. | On waiver, `t_join_waived` can consume the unfinished analysis token and authorize without `t_analyze`. If analysis happens, the new silent transition can route the waiver to the normal join. This **changes the stated business policy**. | A silent choice determines whether analysis remains required, and authorization without analysis becomes valid. |

A is globally minimal under this cost model: zero edits retain the counterexample, and its single added input arc makes the waiver join consume both parallel branches. B is minimal within the common-join rerouting approach: removing only the old output loses the route to the sink, while adding only the new output leaves the old premature decision path. The two required arc changes cost two. C is minimal within the addition-only construction that preserves the standard route and uses the existing waiver join for bypass: that join needs an input from `p_analysis` to consume the unfinished token, and an analyzed waiver needs a separate path from `p_waived` to `p_review_done` (one new transition and two arcs). Thus C costs at least four in that construction. A and B differ in internal firing behavior but have the same visible task traces; C adds the visibly shorter waiver trace without analysis.

# 5. Corrected PM4Py Code

Repair A is selected. Its only graph edit is the additional input arc to `t_join_waived`.

```python
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

place_names = (
    "source", "p_ready", "p_analysis", "p_review",
    "p_analysis_done", "p_review_done", "p_waived",
    "p_decision", "sink",
)
places = {name: PetriNet.Place(name) for name in place_names}
repaired_net.places.update(places.values())

transition_labels = {
    "t_register": "Register Case",
    "t_split": None,
    "t_analyze": "Perform Analysis",
    "t_standard_review": "Perform Standard Review",
    "t_waive_review": "Record Review Waiver",
    "t_join_normal": None,
    "t_join_waived": None,
    "t_authorize": "Authorize Case",
}
transitions = {
    name: PetriNet.Transition(name, label)
    for name, label in transition_labels.items()
}
repaired_net.transitions.update(transitions.values())

arcs = (
    ("source", "t_register"),
    ("t_register", "p_ready"),
    ("p_ready", "t_split"),
    ("t_split", "p_analysis"),
    ("t_split", "p_review"),
    ("p_analysis", "t_analyze"),
    ("t_analyze", "p_analysis_done"),
    ("p_review", "t_standard_review"),
    ("t_standard_review", "p_review_done"),
    ("p_review", "t_waive_review"),
    ("t_waive_review", "p_waived"),
    ("p_analysis_done", "t_join_normal"),
    ("p_review_done", "t_join_normal"),
    ("t_join_normal", "p_decision"),
    ("p_waived", "t_join_waived"),
    ("p_analysis_done", "t_join_waived"),  # Waiver also waits for analysis.
    ("t_join_waived", "p_decision"),
    ("p_decision", "t_authorize"),
    ("t_authorize", "sink"),
)

for source_name, target_name in arcs:
    source_node = places[source_name] if source_name in places else transitions[source_name]
    target_node = places[target_name] if target_name in places else transitions[target_name]
    petri_utils.add_arc_from_to(source_node, target_node, repaired_net)

repaired_im = Marking()
repaired_im[places["source"]] = 1
repaired_fm = Marking()
repaired_fm[places["sink"]] = 1
```

# 6. Diagnostic and Reachability Code

Run this after the original code and the repaired code above. The helper checks enabledness before changing any tokens.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def show_marking(marking):
    parts = sorted(
        (place.name, count)
        for place, count in marking.items()
        if count > 0
    )
    return "{" + ", ".join(f"{name}: {count}" for name, count in parts) + "}"


def fire_named(petri_net, marking, transition_name):
    matches = [
        transition for transition in petri_net.transitions
        if transition.name == transition_name
    ]
    if len(matches) != 1:
        raise ValueError(f"Expected one transition named {transition_name}")
    transition = matches[0]
    enabled = pm4py.get_enabled_transitions(petri_net, marking)
    if transition not in enabled:
        raise ValueError(
            f"{transition_name} is not enabled at {show_marking(marking)}"
        )

    next_marking = Marking(dict(marking))
    for arc in transition.in_arcs:
        place = arc.source
        next_marking[place] -= arc.weight
        if next_marking[place] == 0:
            del next_marking[place]
    for arc in transition.out_arcs:
        place = arc.target
        next_marking[place] = next_marking.get(place, 0) + arc.weight

    next_enabled = sorted(
        t.name for t in pm4py.get_enabled_transitions(petri_net, next_marking)
    )
    print(transition_name, "->", show_marking(next_marking),
          "enabled:", next_enabled)
    return next_marking


for title, petri_net, initial, final in (
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
):
    print(title, "workflow net:", pm4py.check_is_workflow_net(petri_net))
    soundness_result = pm4py.check_soundness(
        petri_net, initial, final, print_diagnostics=True
    )
    # PM4Py versions may return a Boolean or (Boolean, diagnostics).
    sound = soundness_result[0] if isinstance(soundness_result, tuple) else soundness_result
    print(title, "sound:", sound)
    print(title, "initially enabled:", sorted(
        t.name for t in pm4py.get_enabled_transitions(petri_net, initial)
    ))
    graph = pm4py.convert_to_reachability_graph(petri_net, initial, final)
    print(title, "reachability graph constructed:", graph is not None)

original_marking = Marking(dict(im))
print("original start:", show_marking(original_marking))
for name in (
    "t_register", "t_split", "t_waive_review",
    "t_join_waived", "t_authorize", "t_analyze",
):
    original_marking = fire_named(net, original_marking, name)
print("original exact final marking:", original_marking == fm)

repaired_marking = Marking(dict(repaired_im))
print("repaired start:", show_marking(repaired_marking))
for name in (
    "t_register", "t_split", "t_waive_review",
    "t_analyze", "t_join_waived", "t_authorize",
):
    repaired_marking = fire_named(repaired_net, repaired_marking, name)
print("repaired exact final marking:", repaired_marking == repaired_fm)
```

Both workflow-net checks should succeed. The original soundness check should fail; its reachability graph contains waiver-route markings with `sink` and a leftover analysis token. The repaired soundness check should succeed, and its waiver replay should reach exactly `repaired_fm`. Diagnostic wording and returned detail may vary by PM4Py version.

# 7. Repair Trade-Offs and Residual Risks

The selected repair retains separate visible transitions for standard review and recorded waiver, so an event log can distinguish them. The two silent joins remain mutually exclusive in a case because the review alternatives compete for one token. They do not create duplicate completion tokens. Concurrent analysis and review can still appear in either order in a trace. Repair B adds a silent waiver-conversion step, which may make a model diagram or alignment less obvious; repair C adds a hidden policy choice.

Soundness proves a property of the modeled token flow, not that the model implements the intended policy. In particular, repair C is sound while violating mandatory analysis. Regression tests should accept both analysis/review orders for each review outcome and should require exact final marking. They should reject authorization before `t_analyze`, authorization before a review outcome, both review outcomes in one case, and any purported completion with tokens outside `sink`.

To detect an accidental analysis bypass, explore reachable states while tracking whether `t_analyze` has fired, and fail if `t_authorize` can fire with that flag false. Also replay visible traces and reject any completed case lacking `Perform Analysis`, including a waived case.

# 8. Final Recommendation

Deploy repair A: add `p_analysis_done → t_join_waived`. It is the one-edit repair, keeps analysis mandatory on both review paths, and makes each join consume the analysis and selected review outcome before authorization. Use repair B as the fallback if the model should have one common synchronization point. It preserves the same visible behavior but costs two arc edits and makes `t_join_waived` a silent waiver-conversion transition, so its role should be documented or renamed during a later model cleanup. Do not deploy repair C under the stated policy; it is appropriate only if the business explicitly approves skipping analysis for waived reviews.
