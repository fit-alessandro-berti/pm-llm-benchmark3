## 1. Target definition

**Primary target (selected):** *Time-to-default within 90 days after activation, right-censored, among applications that activate under the observed policy.*

- **Unit of analysis:** one credit application (case); optionally observed at several prefix checkpoints (`t = first Credit Review completion`, and k  {3, 5, 7} events / 24 h, 72 h elapsed).
- **Population:** the *activation-conditional cohort* — cases whose terminal state by the administrative end date (E = 20260215) is *Accepted  Contract Signed  Account Activated*. At extract date this is 25,200 cases (21,600 matured + 3,600 immature).
- **Event time:** T = days from `Account Activated` to the earliest default indication (a `Default Recorded` event, a collection status revealing default, or a fed `default_90d = 1`) if it occurs within [activation, activation + 90 d]; otherwise censored at min(activation + 90 d, last reliable follow-up). Feed latency means a case is **definitionally complete** only at activation + 90 d + 35 d (grace). Before that sentinel, "no default" is provisional, never a label.
- **Estimand:** S(t) and the 90-day incidence P(Default  90 d | eventual activation, prefix information up to t). Estimation uses survival methods with administrative censoring; evaluation uses IPCW-weighted discrimination and calibration.
- **Operational semantics, stated honestly:** the score answers *"conditional on this applicant going on to activate, how likely is a 90-day default?"* It is **not** the unconditional default propensity of an applicant, because default is undefined without activation. In production, the conditional score ships together with a separately fitted *activation-probability* model; combining them into a joint probability requires an extra independence/dependence assumption that must be declared, not smuggled in.

**Why this is the defensible primary:** the label is well-defined and (given maturity) actually observed for exactly the cohort where credit risk exists; omitted cases are never forced into the negative class; immaturity becomes ordinary right censoring, which survival methodology handles without fabricating negatives.

**Alternatives (different questions):**
1. *All-application multistate/competing-outcome target.* States reachable from Start: Accepted-path (then default / clean), Rejected, Withdrawn, Transferred, Open-censored. Answers "where does each application end up and how much latent credit risk enters through each route" — usable with all 48,000 cases because terminal routing events, unlike default outcomes, are in the event log. Conditional-on-activation hazard appears here as a second-stage model.
2. *Policy-specific counterfactual target:* "probability of default within 90 d had the contract been extended regardless of accept/reject/transfer." Requires exchangeability/positivity assumptions across the acceptance frontier that cannot be verified; suitable only for policy simulation, clearly labeled as such.

Rejected/withdrawn/open cases are **not** relabeled as non-default anywhere in this design.

## 3. Censoring and missing-label strategy

Mechanisms distinguished:

- **Ordinary right censoring:** still-open cases and window truncation — benign if administrative (calendar-driven), which holds for the 3,600 premature cases (censoring time set by extract date, independent of risk given covariates by design).
- **Delayed labels:** 7–35 d feed latency  "clean" is only provable after activation + 125 d. Interim non-events treated as censored, not negative.
- **Selection through activation:** default is observed only conditional on passing accept/contract/activation gates whose criteria depend on prefix variables (risk_score, document outcomes). Selection is therefore *on observables at least*; conditional-on-activation inference is coherent, unconditional inference is not, without an activation model.
- **Transfer:** a competing event ending local exposure. The 60 % linkage is genuinely helpful only as sensitivity analysis; the unlinked 40 % plus the documented *elevated permanent feed missingness for partner-originated accounts* makes missingness depend on origin  MAR is doubtful, treat as potentially MNAR.
- **Permanently missing outcome feeds:** silence after the 125 d sentinel; enumerated by export/log diffing; modeled as unknown, not as zero.

**Primary strategy:** activation-conditional survival model on the 25,200-case cohort; maturity governed by the 125 d sentinel; IPCW evaluation; outcomes assembled with precedence *internal evidence (Default Recorded / collection status) > external feed*, conflicts flagged as data-quality incidents.

**Sensitivity analyses:** (a) headline metrics recomputed on the *fully mature stratum only* (activation + 125 d  E) versus IPCW-weighted full cohort; (b) Manski-style bounds imputing partner-missing outcomes as all-default / all-non-default to bracket the incidence estimate; (c) transfer-linked defaults traced via the linkage table added back, versus pure-local definitions; (d) include-censored vs matured-only training comparison.

**Testability:** administrative censoring independence — holds by construction (calendar cutoffs). MAR of feeds given partner/partner-class — *partially* testable (missingness-rate contrasts on the 60 % linked subset). Selection given covariates — partially testable via pre/post-policy overlap diagnostics. Counterfactual-target assumptions — fundamentally untestable here; that is why the counterfactual stays an explicitly labeled auxiliary.

## 4. Prefix extraction

- **Canonicalization first:** apply the migration rename map to all events (documented mapping; no outcome information involved) so pre/post-October 2025 traces speak one vocabulary; then deduplicate `(case, activity, canonical activity, timestamp, resource)` created around 15 Oct 2025; count and report the removal rate — undeduplicated remnants would distort frequency features asymmetrically across the split.
- **Fixed-count prefixes:** order each case's events by timestamp with a deterministic tie-break (resource, original row); take the first k events (k = 3, 5, 7). Demonstrated with `pm4py.get_prefixes_from_log` on the filtered, canonical log. Short cases simply emit fewer/none of these checkpoints — never padded, never dropped from the population statistics.
- **Elapsed-time prefixes:** all events with `time:timestamp  start + ` (  {24 h, 72 h}), verified by an assertion that no feature view contains an event after the checkpoint. For a still-open case, the effective prediction moment is the checkpoint; its subsequent silence contributes censoring, not features.
- **Rework/document loops:** captured as counts of `Request Documents` and repeat `Credit Review` entries within the prefix — loop-robust and invariant to the renaming.
- **Guardrail:** a single parameterized feature builder receives `t` and filters upstream; every downstream consumer is unit-checked against banned columns and future timestamps (audit implemented in §9).

## 5. Process-aware features

- **Static (present at start):** channel, region, requested_amount, source_system/start period (also serves as regime marker), calendar (weekday, month, holiday proximity).
- **Prefix-derived control-flow:** event count, distinct activities, presence/count indicators per canonical activity, document-loop count, repeated Credit Review count, current stage at t, trace-shape encoded against a **variant dictionary frozen on the training fold only**.
- **Timing/queueing:** elapsed since start; mean/max inter-event gaps; accumulated waiting vs service components in Credit Review (justifies `insert_case_service_waiting_time`: distinguishes applicant-side stalling from examiner workload, a leading signal of review friction); concurrent-load of the handling resource at t.
- **Resource:** number of distinct handlers so far; resource's *historical* handled-volume/experience computed causally from prior events (**repairs** the extraction-time experience field). Contemporary workload percentiles vs trailing 8 weeks (causal rolling window).
- **Risk dynamics:** last-known `risk_score`  t; delta and update count since Start.
- **Requires historical reference data:** rolling approval rates, volume baselines, DFG-edge frequencies from earlier cohorts (context/staleness signals). All reference computations use only data anterior to the checkpoint.

## 6. Leakage audit

| Feature or data element | Leakage or bias risk | Valid availability rule | Keep/repair/drop | Rationale |
|---|---|---|---|---|
| `final_limit` | Populated only post-decision; encodes the outcome of the very decision being predicted | Only at checkpoints where the final decision event precedes t; never at early anchors | **Drop** at early anchors; gated feature later | Early-warning anchors precede the decision; even a "decided?" flag at t collapses the prediction problem |
| `decision_reason` | Deterministic function of the decision that hasn't happened yet | Never  early t | **Drop** | Post-decision field; also fingerprints policy era |
| `collection_status` | Directly reveals default; exists only post-activation | Valid exclusively inside label-derivation logic, behind the maturity sentinel | **Drop as feature; keep for labels** | Classic target leak if any slip into X |
| Future events (`Contract Signed`, `Account Activated`, `Collections Contact`, `Default Recorded`) | Hard leakage; also defines the selection that creates the label | Events filtered ` t` at the log level, with assertion | **Truncate; drop from features** | Enforced mechanically, not by discipline |
| `documents_total` (nightly snapshot) | Same-calendar-day uploads after t contaminate t | As-of join on the *previous closed snapshot* (< t) or rebuilt from document events ` t` | **Repair** | Snapshot semantics violate point-in-time unless joined on last-*completed* state |
| Updated `risk_score` | Values recorded at post-decision events reflect the decision | Use last value with event timestamp  t; skip rows after decision events at early anchors | **Keep with as-of rule** | Trajectory is informative; the leak is positional, not intrinsic |
| Resource experience (stored at extract) | Anachronistic — reflects Feb 2026 staffing | Recompute experience-causally from prior events; or exclude | **Repair** | Proxy for reviewer skill drift is legitimate only in real time |
| `default_90d`, `label_available_at` | Label columns | Outcome assembly only, after maturity rules | **Drop from features** | Column blacklist enforced in code |
| `data_extract_time` | Constant describing the extract, not the case | — | **Drop** | Carries no permissible information |
| Post-migration duplicate events | Inflate post-Oct frequency features; correlated across train/test | Dedupe on composite key after canonicalization | **Repair** | Silent multiplicity masquerades as behavioral signal |
| Multiple checkpoints of the same case | Row-level splitting places sister checkpoints in train and test | All checkpoints of a case forced into one fold | **Structural rule** | Random row split would leak within-case |

## 7. Validation design

**Temporal roles (by case start time; whole case = atomic unit):**

| Fold | Starts | Purpose / caveats |
|---|---|---|
| FIT/TRAIN | 20240101 – 20250630 | Pre-policy and pre-migration; variant dictionary, DFG references, models fit here |
| CALIBRATION | 20250701 – 20250930 | First post-policy quarter; recalibration intercept, threshold/cost tuning; check transportability across the policy break |
| HOLDOUT TEST | 20251001 – 20251231 | Post-migration era. Headline metrics **only on the maturity-gated subset** (activation + 125 d  E); the remainder is registered in shadow mode with labels backfilled spring 2026 |

Policy-change consequence made explicit: post-policy activations mature only through ~13 Oct 2025 (activation + 125 d  20260215), so the matured post-policy sample is thin — reported with confidence intervals, never hidden.

**Why not random:** a random case split (a) pools pre- and post-policy populations whose identical prefixes have different P(y) by the stated change; (b) lets near-duplicate migration artifacts and sibling checkpoints straddle folds (within-case leakage); (c) randomly samples late-2025 immature labels into training, silently converting censored positives/negatives into fabricated ones. Each failure mode independently inflates apparent performance.

**Evaluation:** for the survival target — Uno's concordance, IPCW cumulative/dynamic AUC@90 d, IPCW Brier@90 d with the censoring KM  estimated within evaluation strata; calibration slope/intercept and reliability curves on the mature-gated test set; AUPRC@90 d given the 12.5 % incidence; precision@top-decile and expected-cost under an asymmetric loss matrix (missed default  false alarm). Lead-time is reported as *warning horizon before activation*, matching operations.

**Subgroups & shift:** discrimination/calibration stratified by channel, region, requested-amount terciles, partner-linked origin, pre/post policy, pre/post migration; monthly cluster bootstrap CIs; per-feature PSI and JS divergence of variant frequencies fit-month vs deployment month, with alarms wired to champion/challenger retraining. `pm4py.split_train_test` may be quoted as a convenience baseline but every decision is taken on the temporal protocol above.

## 8. Limitations and decision-use boundary

**Can claim:** calibrated, discriminative *early conditional risk of 90-day default among cases that will activate*, under the regimes represented in 2024–Q4 2025; detected drift over policy/migration boundaries; subgroup contrast sizes.

**Cannot claim:** (i) unconditional "applicant default propensity" — the activation gate mediates and the gate depends on prefix observables (selection effect); (ii) causal effect of accepting or of faster reviews — no randomization, and rejection-frontier comparisons violate overlap near thresholds; (iii) counterfactual "default had we approved" — requires assumptions disqualified in §3; that target remains simulation-only labeling.

**Deployment feedback mechanisms that change the DGP (3):**
1. Alert-driven enhanced verification rejects/withdraws incipient defaulters  those outcomes vanish exactly where the model fires (collider contamination of future labels).
2. Acceptance-threshold retuning after observing early-warning results moves the selection frontier  covariate shift concentrated precisely where data was sparsest (boundary extrapolation).
3. Routing/notifications based on scores change applicant behavior (withdrawals, channel switching) and staff allocation  queueing and resource features become endogenous.
4. Vendor risk-score recalibration or partner-contract changes alter upstream covariates mid-stream.
Mitigation: drift monitors, scheduled recalibration on newly matured labels, incident logging of interventions.

Illustrative wiring of data engineering + audits; models connect at marked points."""
import numpy as np
import pandas as pd
import pm4py

CSV, CASE, ACTV, TS = "applications_events.csv", "case:concept:name", "concept:name", "time:timestamp"
EXTRACT   = pd.Timestamp("2026-02-15")

GRACE     = pd.Timedelta(days=35)                  # feed latency allowance -> 125d sentinel
ACTIVATE_EV, DEFAULT_EV = "Account Activated", "Default Recorded"
COLL_DEF  = {"default"}                            # collection_status values revealing default
NEVER_FEATURES = {"final_limit", "decision_reason", "collection_status",
                  "default_90d", "label_available_at", "data_extract_time"}
RENAME = {"Credit Review v2": "Credit Review",     # from migration release notes (ASSUMPTION)
          "KYC_Check_Neu": "Identity/KYC Check"}

raw = pd.read_csv(CSV)
raw[TS] = pd.to_datetime(raw[TS], errors="coerce", utc=True).dt.tz_localize(None)
ev = pm4py.format_dataframe(raw.dropna(subset=[TS]).copy(),
                            case_id=CASE, activity_key=ACTV, timestamp_key=TS)

ev[ACTV] = ev[ACTV].replace(RENAME)                              # canonicalize BEFORE variants
KEY = [CASE, ACTV, TS, "org:resource"]
n_dup = int(ev.duplicated(KEY).sum())                            # migration artefact count
ev = ev.sort_values([CASE, TS]).drop_duplicates(KEY)
N_EVENTS = ev.groupby(CASE).size().rename("n_events_total")

def classify(g, as_of):
    """Case state STRICTLY as of cutoff. Backward-looking only."""
    g = g.loc[g[TS] <= as_of]
    if g.empty:
        return {}
    acts, out = g[ACTV], {"start_ts": g[TS].min(), "last_ts": g[TS].max()}
    act_t = g.loc[acts.eq(ACTIVATE_EV), TS].min()
    out["activated"], out["activated_at"] = pd.notna(act_t), act_t
    if pd.notna(act_t):
        hz_end, feed_dl = act_t + HORIZON, act_t + HORIZON + GRACE
        evt_def = acts.eq(DEFAULT_EV).any()
        col_def = g["collection_status"].astype(str).str.lower().isin(COLL_DEF).any()
        feed    = pd.to_numeric(g["default_90d"], errors="coerce").max()   # 0/1 when fed
        if pd.notna(feed):                     # precedence: feed agrees/adjudicated elsewhere
            out["status"] = "default" if feed == 1 else "clean"
            out["conflict"] = int(bool(evt_def or col_def) != bool(feed))
        elif evt_def or col_def:
            out["status"], out["conflict"] = "default", 0
        elif as_of >= feed_dl:
            out["status"] = "suspect_perm_missing"          # silence AFTER grace = unknown
        elif as_of >= hz_end:
            out["status"] = "pending_feed"
        else:
            out["status"] = "censored_pending"              # ordinary right censoring
    else:
        tm = {"Rejected": "rejected", "Withdrawn": "withdrawn", "Transferred": "transferred"}
        hits = [v for k, v in tm.items() if acts.eq(k).any()]
        out.update(status=(hits[0] if hits else "open"), activated=False, activated_at=pd.NaT)
    return out

rows = [dict(case_id=c, **classify(g, EXTRACT)) for c, g in ev.groupby(CASE, sort=False)]
cases = pd.DataFrame(rows).join(N_EVENTS, on="case_id")
cnt = cases["status"].value_counts()
print("-- cohort reconciliation --\n", cnt.to_string())
print(f"activated={int(cnt.get('default',0)+cnt.get('clean',0)+cnt.get('pending_feed',0)"
      f"+cnt.get('censored_pending',0)+cnt.get('suspect_perm_missing',0))}, "
      f"export should equal default+clean={int(cnt.get('default',0)+cnt.get('clean',0))}")

def role(s):                                        # TEMPORAL split by case start
    if s <= pd.Timestamp("2025-06-30"): return "fit_train"        # pre-policy
    if s <= pd.Timestamp("2025-09-30"): return "calibration"      # post-policy
    return "holdout_test"                                         # post-migration
cases["role"] = cases["start_ts"].map(role)
mat = cases["activated_at"].add(HORIZON + GRACE).le(EXTRACT)      # 125d maturity gate
cases["eval_eligible"] = cases["status"].isin(["default", "clean"]) & mat
print(cases.groupby("role")["case_id"].nunique())

BLACKLIST = lambda: NEVER_FEATURES.intersection(ev.columns)
def prefix_events(t_limit):
    """ALL downstream views come from here: future-proof by construction."""
    banned = BLACKLIST()
    assert not banned, f"label/post-decision columns cannot sit beside features: {banned}"
    v = ev.loc[ev[TS] <= t_limit]
    assert v[TS].max() <= t_limit
    return v.copy()

tr_ev = prefix_events(pd.Timestamp("2025-06-30 23:59"))
demo  = pm4py.convert_to_event_log(tr_ev.head(20000))
pfx3  = pm4py.get_prefixes_from_log(demo, n=3)          # fixed-length-3 prefixes
var_train = pm4py.get_variants(demo)                    # FROZEN vocabulary (train era only)
dfg, sa, ea = pm4py.discover_dfg(demo)                  # train-era edge reference for drift PSIs
tf = pm4py.extract_temporal_features_dataframe(demo)    # aggregate durations/waits context
# NOTE: pm4py.split_train_test exists but is sample-random -> deliberately not used.

def features_until(t, k_anchor=None):
    v = prefix_events(t)
    g = v.sort_values(TS).groupby(CASE)
    f = pd.DataFrame({
        "n_events":    g.size(),
        "elapsed_h":   (t - g[TS].min()).dt.total_seconds() / 3600,
        "doc_loops":   g[ACTV].apply(lambda s: int(s.eq("Request Documents").sum())),
        "review_visits": g[ACTV].apply(lambda s: int(s.eq("Credit Review").sum())),
        "n_handlers":  g["org:resource"].nunique(),
        "risk_last":   g["risk_score"].apply(lambda s: s.iloc[-1] if len(s) else np.nan),
        "risk_delta":  g["risk_score"].apply(lambda s: s.iloc[-1] - s.iloc[0] if len(s) else np.nan),
    })
    if k_anchor is not None:
        f = f[f["n_events"] == k_anchor]               # fixed-count checkpoint
    return f

try:   # wait vs service split => distinguishes applicant stall from examiner effort
    svc = pm4py.insert_case_service_waiting_time(tr_ev[[CASE, ACTV, TS]].copy())
    wait_col = next(c for c in svc.columns if "waiting" in c.lower())
    feat = features_until(pd.Timestamp("2025-05-31")).join(
        svc.set_index(CASE)[wait_col].rename("wait_total_s"), how="left")
except Exception as exc:                               # degrade gracefully; manual fallback
    print("service/waiting helper unavailable:", exc)
    feat = features_until(pd.Timestamp("2025-05-31"))

# Join labels LAST - analysis table is the only place they ever meet features.
analysis = feat.join(cases.set_index("case_id")[["status", "role", "eval_eligible",
                                                 "activated_at", "activated", "start_ts"]])
rate = analysis.groupby("role").apply(
    lambda d: (d.status == "default").mean() if d.eval_eligible.any() else np.nan)
print("crude matured incidence by fold:\n", rate.to_string())
