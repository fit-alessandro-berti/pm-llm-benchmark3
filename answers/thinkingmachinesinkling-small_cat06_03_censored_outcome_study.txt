## 1. Target definition

**Primary target (selected): Conditional binary default for activated accounts with mature labels**
- **Prediction target:** `default_90d` = 1 if a default occurred within 90 days after `Account Activated`; 0 if the account survived 90 days without default.
- **Unit of analysis:** Application case (`case:concept:name`).
- **Population:** Only applications that (a) reach `Account Activated`, and (b) have a mature label (`label_available_at` + 35-day feed delay  `data_extract_time` = 15 Feb 2026). This yields the 21,600 mature activated cases (18,900 non-default; 2,700 default).
- **Prediction time (as-of):** The end of the first `Credit Review` event, or after the 3rd observed event, whichever occurs first, but explicitly **before** `Contract Signed` / `Account Activated`. This ensures the model is an early warning, not a retrospective classifier.
- **Prediction horizon:** 90 days from `Account Activated` (the outcome is defined by calendar time after activation).
- **Estimand:** E[default_90d | activated, label mature, process prefix P] = p. Reported as a conditional risk score for cases that have already passed credit review and are expected to activate.

**Why primary:** It is operationally defensible because the lender’s loss event is literally “default on an activated account,” and the current warehouse only defines `default_90d` under activation. It is statistically honest because it does not impute a non-existent default for rejected, withdrawn, or open cases.

**Alternative 1 — Multi-state competing-outcome target (for all 48,000):**
- States: `Rejected`, `Withdrawn`, `Transferred`, `Open/Censored`, `Activated-Non-default`, `Activated-Default`.
- Answers: “What is the eventual disposition of this application from early events?” It respects that default is undefined for non-activated cases but requires a multi-state or competing-risk framework (e.g., Fine-Gray or multinomial with selection).

**Alternative 2 — Policy-counterfactual target (clearly labeled):**
- “What is the probability of 90-day default if this application were activated under the current credit-policy regime?”
- Requires strong ignorability of the activation/approval decision (selection on unobserved risk). We do not adopt this as primary because the observed selection mechanism (credit review, document loops, risk-score updates) is partly unmodeled.

**As-of rules to prevent future leakage:**

**Activity renaming (post-15 Oct 2025):** Apply a canonical mapping before prefix extraction:
- Old names (`Credit Review`, `Doc Request`)  new unified ontology.

## 7. Validation design

**Why not a random split:** Random splitting ignores (1) the July 2025 policy threshold change (selection and outcome relationship shift), (2) the Oct 2025 migration (measurement shift / duplicates), (3) label maturity (recent cases are unlabeled, causing “training on future labels” if not handled temporally). Random splits also mix pre- and post-policy cases, overstating stability.

**Temporal validation / backtesting scheme:**
- **Train:** Cases started < 1 July 2025 (pre-policy; mature labels largely available).
- **Validation:** 1 July 2025  start < 15 Oct 2025 (post-policy, pre-migration; tests policy shift).
- **Test:** 15 Oct 2025  start  31 Dec 2025 (post-policy, post-migration; tests measurement/system shift + label immaturity).

**Backtesting:** For each calendar quarter, simulate as of the quarter start using only cases started before that quarter with mature labels; predict on the next quarter’s starts. This mimics real deployment.

**Label maturity handling in evaluation:** Only evaluate on cases whose labels are known at the evaluation time (rolling maturity window). Report “maturity-corrected” AUC that excludes recent activations until their feeds arrive.

**Calibration:** Use Platt scaling / isotonic regression fitted on the temporal validation set; evaluate with Brier score and Expected Calibration Error (ECE) on test.

**Subgroup performance:** Report metrics by `post_policy`, `case:region`, `source_system`, and `case:channel`. If partner-originated accounts have missing feeds, flag reduced reliability for that subgroup.

**Metrics for conditional binary target:** AUC-ROC, Average Precision / PR-AUC (important because ~12.5% event rate), Brier score, calibration slope, and a decision-curve analysis at relevant thresholds.

**Survival / competing-risk connection (future step):** For the sensitivity analysis, a time-to-default model with right-censoring and competing activation/rejection would use a C-index; not fitted in primary skeleton, but the temporal split and cohort definitions support it.

## 8. Limitations and decision-use boundary

**What the study can claim:**
- Among activated accounts that have matured 90-day outcomes, early process prefixes (before activation) have predictive association with default.
- The model ranks risk within the activated population.
- Policy and migration shifts can be quantified via temporal validation.

**What it cannot claim:**
- **Predictive association  causal effect:** A high predicted score does not mean the application “should be rejected” without considering selection effects.
- **No counterfactual default for non-activated cases:** We cannot say “if rejected, this case would have defaulted with probability p.” That requires untestable ignorability of approval.
- **No universal “application default rate”:** Because rejected/withdrawn/transferred/open cases have no observed `default_90d`, the population default rate is undefined without a policy assumption.

**Three deployment-change risks (data-generating process):**
1. **Selection / collider effect:** If the model is used to approve/reject, cases predicted as high-risk are rejected; they never activate; observed default rate among activated falls (collider bias), making future monitoring misleading.
2. **Policy / economic shift:** The July 2025 change already altered selection; future cycles (interest rates, employment) will change the default mechanism, degrading temporal validation performance.
3. **Migration / recording change:** After Oct 2025, duplicates are removed and activities renamed; loop counts and inter-event durations may change systematically, shifting feature distributions.

**Decision-use boundary:** Use the model only as an **early warning for cases expected to activate**, with explicit labeling: “Estimated default risk conditional on activation; not a universal score for all applications.”
