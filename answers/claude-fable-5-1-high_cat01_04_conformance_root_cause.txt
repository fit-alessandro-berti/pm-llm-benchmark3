## 3. Causal-abductive explanation

```text
UI_release            -> recorded_labels            # Classify renamed Risk Screen (620/650); 30 cases lag
UI_release            -> gateway_capture            # hidden: event gateway coverage/loss rate ("most, not all")
UI_release            -> true_process (?)           # possible change of screening/routing logic (enhanced share 26% -> 43%)
gateway_capture       -> recorded_events            # adds Queue Routed; may drop Compliance Check events
override_logging_patch-> recorded_events            # Manual Override count 20 -> 35 partly a logging effect
policy_change         -> true_process               # Supervisor Sign-off inserted for > EUR 50k
policy_change         -> reviewer_behavior          # escalation habits, sign-offs after Standard Review
policy_change         -> routing_mix                # more cases steered to Enhanced Review
case_mix / high_value_share -> true_process         # hidden confounder for routing mix and sign-off frequency
routing_errors        -> reviewer_behavior          # Manual Override used to fix mis-routing
reviewer_behavior     -> true_process               # overrides; possible genuine check bypass
true_process          -> recorded_events
true_process          -> recorded_labels
ETL_change            -> recorded_order             # ingestion time for Decision/Notify only
source_sequence       -> recorded_order             # ground truth, unused by initial job
recorded_labels       -> alignment_moves
recorded_events       -> alignment_moves
recorded_order        -> alignment_moves
normative_model       -> alignment_moves
model_maintenance_lag -> normative_model            # tree not updated after 2026-08-01
alignment_moves       -> measured_fitness
true_process          -> business_outcomes
reviewer_behavior     -> business_outcomes (weak)   # a skipped check rarely changes approval or appeal
business_outcomes     -> incident_detection         # hidden: detection incomplete
extraction_lineage    -> measured_fitness           # variant table and alignment summary come from different extracts
```

The measured collapse is over-determined. Four independent interventions on the recording chain—a screen rename, a new gateway event, an ingestion-time substitution, and a policy that added an activity to reality but not to the model—each inject moves into alignments. Alignments are additive in cost, so the mechanisms stack: a June trace typically carries a `Risk Screen` log move plus a `Classify` model move plus a `Queue Routed` log move plus, for one in ten cases, a swapped `Notify`/`Decision` pair. The 32% raw fitness is the joint product of these, not a signal about people. The staged recovery to 89% is the abductive fingerprint: each repair removes exactly the move type predicted by its dated cause and nothing else.

Unchanged outcomes cut both ways. Stable approval and appeal rates are consistent with data artefacts, but the metrics sit downstream of `Decision`; a skipped `Compliance Check` or a downgrade override on a few dozen enhanced-bound cases would not move approval rates or appeals, which measure customer dissatisfaction rather than regulatory exposure. Conversely, stable outcomes do not prove data error either, because the artefacts explain the bulk of the drop directly, without needing the outcome evidence. What the outcomes exclude is only a large-scale, outcome-relevant behavioral change. The residual—55 enhanced reviews with no recorded check and 55 overrides that always end in the standard path—remains open and cannot be resolved by conformance arithmetic; it requires provenance and reviewer-level evidence.

## 6. PM4Py reproduction and model-comparison code

```python
#!/usr/bin/env python3
"""
Claims-process conformance investigation: PM4Py reproduction and model comparison.

The supplied evidence consists of variant-frequency aggregates, not the original
timestamped, resource-annotated log. The script therefore
  * rebuilds logs from variant counts,
  * applies the same staged normalization used in the incident report
    (label map -> technical-event removal -> [counterfactual] re-ordering),
  * compares raw and normalized alignment diagnostics against the normative model,
  * compares the normative model with a candidate that permits an optional
    Supervisor Sign-off, and with a deliberately over-permissive candidate,
    on August-September, reporting fitness AND precision.
Numbers approximate, and will not exactly reproduce, the aggregate report.
Written against the pm4py 2.7.x simplified interface.
"""
from collections import Counter

import pandas as pd
import pm4py

# --------------------------------------------------------------------------- #
# 1-2. Normative model: process tree -> accepting Petri net
# --------------------------------------------------------------------------- #
NORMATIVE_TREE = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "'Decision', 'Notify' )"
)
normative_tree = pm4py.parse_process_tree(NORMATIVE_TREE)
norm_net, norm_im, norm_fm = pm4py.convert_to_petri_net(normative_tree)

# --------------------------------------------------------------------------- #
# 3. Variant tables (exactly as supplied) -> event logs
# --------------------------------------------------------------------------- #
VARIANTS = {
    "Apr-May": [
        ("Receive,Classify,Standard Review,Decision,Notify", 380),
        ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
        ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40),
    ],
    "Jun-Jul": [
        ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
        ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
        ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
        ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
    ],
    "Aug-Sep": [
        ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
        ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),
    ],
}


def variants_to_log(variant_counts):
    """Expand (trace string, count) pairs into a PM4Py event log."""
    traces = []
    for trace, count in variant_counts:
        traces.extend([trace] * count)
    return pm4py.parse_event_log_string(traces, sep=",")


def counterfactual_reorder(variant_counts):
    """Ceiling of the 'order by source sequence' repair on aggregate data:
    every reversed Notify,Decision pair is put back into Decision,Notify order.
    On the real extract, do NOT do this; instead use order_by_source_sequence()."""
    return [(t.replace("Notify,Decision", "Decision,Notify"), c) for t, c in variant_counts]


def order_by_source_sequence(df, seq_col="source_seq"):
    """Real-log version of the ordering repair: rebuild event order from the
    source-system sequence number instead of warehouse-ingestion timestamps."""
    return df.sort_values(["case:concept:name", seq_col]).reset_index(drop=True)


logs = {period: variants_to_log(rows) for period, rows in VARIANTS.items()}

# --------------------------------------------------------------------------- #
# Helpers: DFG, alignment diagnostics, normalization
# --------------------------------------------------------------------------- #
FOCUS = {"Classify", "Risk Screen", "Queue Routed", "Notify", "Decision",
         "Enhanced Review", "Compliance Check", "Supervisor Sign-off", "Manual Override"}


def print_dfg(log, title, focus=FOCUS):
    """4. Frequency DFG, restricted to the relations that matter for the hypotheses."""
    dfg, start_acts, end_acts = pm4py.discover_dfg(log)
    print(f"\n[DFG] {title}")
    for (a, b), freq in sorted(dfg.items(), key=lambda kv: -kv[1]):
        if a in focus or b in focus:
            print(f"   {a} -> {b}: {freq}")
    print(f"   start activities: {dict(start_acts)}")
    print(f"   end activities:   {dict(end_acts)}")
    return dfg


def _fmt(x):
    return f"{x:.3f}" if isinstance(x, (int, float)) else str(x)


def alignment_report(log, net, im, fm, title):
    """5. Alignment diagnostics + alignment fitness, with move-on-log and
    visible move-on-model counters (the diagnostic content of the alignments)."""
    fitness = pm4py.fitness_alignments(log, net, im, fm)
    diagnostics = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    log_moves, model_moves = Counter(), Counter()
    fitting, visible_cost = 0, 0
    for aln in diagnostics:
        if aln["fitness"] >= 1.0 - 1e-9:
            fitting += 1
        # standard cost function: 10000 per visible log/model move, ~1 per tau move
        visible_cost += round(aln["cost"] / 10000)
        for log_step, model_step in aln["alignment"]:
            if log_step != ">>" and model_step == ">>":
                log_moves[log_step] += 1
            elif log_step == ">>" and model_step not in (">>", None):
                model_moves[model_step] += 1
    n = len(diagnostics)
    print(f"\n[ALIGN] {title}")
    print(f"   fitting traces: {fitting}/{n} = {100.0 * fitting / n:.1f}%")
    print(f"   mean visible alignment moves per trace: {visible_cost / n:.2f}")
    print(f"   average trace fitness: "
          f"{_fmt(fitness.get('average_trace_fitness', fitness.get('averageFitness')))}")
    print(f"   log fitness: {_fmt(fitness.get('log_fitness'))}")
    print(f"   moves on log: {dict(log_moves.most_common())}")
    print(f"   visible moves on model: {dict(model_moves.most_common())}")
    return {"fitting_pct": 100.0 * fitting / n,
            "log_moves": log_moves, "model_moves": model_moves, "fitness": fitness}


def normalize(log, label_map=None, drop_activities=()):
    """6. Transparent normalization pipeline.
    label_map: {'Risk Screen': 'Classify'}  -- semantic mapping, must be documented
    drop_activities: ('Queue Routed',)      -- technical events removed as events,
                                              never as cases."""
    df = pm4py.convert_to_dataframe(log)
    if label_map:
        df["concept:name"] = df["concept:name"].replace(label_map)
    out = pm4py.convert_to_event_log(df)
    if drop_activities:
        out = pm4py.filter_event_attribute_values(
            out, "concept:name", list(drop_activities), level="event", retain=False)
    return out


def stratified_fitness(log, attribute, net, im, fm):
    """Case-attribute stratification (e.g. 'case:high_value'). The supplied
    aggregates carry no attributes, so this only runs if the column exists."""
    df = pm4py.convert_to_dataframe(log)
    if attribute not in df.columns:
        print(f"\n[STRATIFY] attribute {attribute!r} not present in this extract - "
              f"request it; without it H2 (obsolete model) and H5 (noncompliance) "
              f"cannot be separated for sign-off and check-less traces.")
        return
    for value, sub in df.groupby(attribute):
        sub_log = pm4py.convert_to_event_log(sub)
        alignment_report(sub_log, net, im, fm, f"{attribute}={value}")
```

## 7. Provisional conclusion

Primary explanation. The measured conformance collapse is predominantly a measurement artefact produced by four dated changes to the recording chain rather than a change in how claims are handled. The 2026-05-31 interface release renamed `Classify` to `Risk Screen` (620 of 650 traces; confirmed by the 40-case audit); the 2026-06-03 gateway added the technical event `Queue Routed`; the 2026-06-15 ETL change substituted ingestion time for `Decision` and `Notify` and produced the reversed pairs in exactly those two activities; and the 2026-08-01 sign-off policy inserted a real, sanctioned activity that the normative tree never received. Each repair removes exactly the move type its cause predicts and nothing else, which is the abductive signature of artefact rather than behavior. On the supplied aggregates roughly 26 percentage points are attributable to the label, 23 to the technical event, 8 to ordering, and about 20 of the August-September gap to model obsolescence. Confidence that these mechanisms explain the large majority of the drop: high (about 85-90%), tempered by the fact that the variant table and the alignment summary are not mutually consistent, so exact shares are uncertain.

Residual compliance risk. After all defensible repairs, 55 enhanced-review cases across June-September have no recorded `Compliance Check` (zero before June), and 55 `Manual Override` events all lead to the standard path. Stable approval and appeal rates do not clear this residual, because those metrics are insensitive to a skipped control on a few dozen cases, and compliance itself says incident detection is incomplete. The simultaneous onset with the gateway change makes dropped events at least as plausible as bypass. Confidence that a real compliance problem exists: low-to-moderate (about 30-40%), but the potential severity in a regulated process justifies treating it as open.

Immediate actions. IT: publish the event-type inventory of the gateway with per-type capture rates, restore the source sequence number as the ordering key, and re-extract a single lineage-controlled log from which both variants and alignments are computed. Process owners: issue a versioned label-mapping and technical-event policy, update the normative model with a data-aware sign-off constraint guarded by claim value, and freeze the current dashboard until the reconciled baseline is available. Compliance: audit the 55 check-less enhanced cases and a sample of overrides against the source system (not the warehouse), stratified by claim value and reviewer, and report per case whether the control was performed, lost, or skipped.

What must not be claimed yet. Not that employees became noncompliant; not that the process is compliant because outcomes are stable; not that the optional-sign-off model is the correct model (it cannot enforce the EUR 50,000 condition and would hide missing high-value sign-offs); and not that `Manual Override` is noise.

## 8. Model-governance recommendation

1. Model versioning: the normative model is a versioned artefact with an owner, an effective date, and a change log; every policy change (such as the 2026-08-01 sign-off rule) must trigger a model review before it takes effect, and every conformance report must cite the model version and the log extract version it was computed against.
2. Event-semantic contracts: each activity label in the log is bound to a documented business function in a data dictionary; UI or system releases that rename, split, or merge screens must update the mapping table before go-live, and the conformance pipeline applies mappings from that table only, never ad hoc.
3. Technical-event policy: every event type is classified as business, technical, or unknown at the source, with a stated rule (keep, drop at event level, or quarantine for review); technical events are never removed by hand, new unknown event types raise an alert, and user actions such as `Manual Override` are never reclassified as technical to improve fitness.
4. Timestamp provenance: every event carries both source timestamp and source sequence number with the ingestion time stored separately; event ordering for conformance uses source sequence, and any ETL change touching timestamp fields requires a before/after ordering test on a reference sample.
5. Data-aware constraints: rules that depend on case data (sign-off above EUR 50,000, high-value routing, resource authorizations) are encoded as guarded constraints or stratified checks, not as optional branches in a control-flow model; conformance reports must state which rules are enforced and which are only approximated.
6. Post-release validation: any change to the UI, gateway, ETL, policy, or model is followed within one reporting cycle by a shadow conformance run on a fixed reference log with expected deviation profiles; unexplained shifts in move-on-log or move-on-model distributions block sign-off of the release, and a small manual provenance audit against the source system is mandatory before any people-related conclusion is communicated.
