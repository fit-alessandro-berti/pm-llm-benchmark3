import pm4py
from pm4py.objects.log.obj import EventLog, Trace

def build_log_from_variants(variant_counts: dict[str, int]) -> EventLog:
    trace_strings = []
    for trace_str, count in variant_counts.items():
        trace_strings.extend([trace_str] * count)
    return pm4py.parse_event_log_string(trace_strings, sep=",")


apr_may_variants = {
    "Receive,Classify,Standard Review,Decision,Notify": 380,
    "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,

jun_jul_variants = {

    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 145,

    "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
    "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,

    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify": 150,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 90,
    "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify": 60,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 45,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 35,
}

log_apr_may = build_log_from_variants(apr_may_variants)
log_jun_jul_raw = build_log_from_variants(jun_jul_variants)
log_aug_sep_raw = build_log_from_variants(aug_sep_variants)

# ---------------------------------------------------------------------------
# 3. Transparent normalization pipeline (label map + optional tech removal)
# ---------------------------------------------------------------------------
def normalize_log(
    log: EventLog,
    map_risk_screen: bool = True,
    remove_queue_routed: bool = False,
) -> EventLog:
    normalized = EventLog()
    for trace in log:
        new_trace = Trace(attributes=copy.deepcopy(trace.attributes))
        for event in trace:
            ev = copy.deepcopy(event)
            act = ev["concept:name"]
            if remove_queue_routed and act == "Queue Routed":
                continue
            if map_risk_screen and act == "Risk Screen":
                ev["concept:name"] = "Classify"
            new_trace.append(ev)
        normalized.append(new_trace)
    return normalized


def evaluate_log(label: str, log: EventLog, net, im, fm) -> None:
    dfg, _, _ = pm4py.discover_dfg(log)
    fit_res = pm4py.fitness_alignments(log, net, im, fm)
    alignments = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    perfect = sum(1 for a in alignments if a["fitness"] == 1.0)
    mean_cost = sum(a["cost"] for a in alignments) / len(alignments)
    print(f"--- {label} ---")
    print(
        f"Cases: {len(log)} | Exact-fit traces: {perfect / len(log):.1%} | "
        f"Log fitness: {fit_res['log_fitness']:.3f} | Mean raw cost: {mean_cost:.2f}"
    )
    top_edges = sorted(dfg.items(), key=lambda kv: kv[1], reverse=True)[:5]
    print("Top DFG edges:", top_edges)


# ---------------------------------------------------------------------------
# 4. Compare Apr-May baseline vs. raw and normalized Jun-Jul logs
# ---------------------------------------------------------------------------
evaluate_log("Apr-May (raw vs. normative)", log_apr_may, norm_net, norm_im, norm_fm)
evaluate_log("Jun-Jul (raw vs. normative)", log_jun_jul_raw, norm_net, norm_im, norm_fm)

log_jun_jul_mapped = normalize_log(
    log_jun_jul_raw, map_risk_screen=True, remove_queue_routed=False

evaluate_log(
    "Jun-Jul (label-mapped only vs. normative)",
    log_jun_jul_mapped,
    norm_net,

## 7. Provisional conclusion

The sudden conformance collapse from 93% to 32% in June–July—and 66% normalized in August–September—was **primarily caused by instrumentation, ETL, and model-governance failures rather than a sudden collapse in employee compliance**. In June–July, three non-behavioral factors explain nearly all of the drop (+57 percentage points, recovering fitness from 32% to 89%): a UI rename (`Classify` to `Risk Screen`, +26 pp), an unexcluded technical gateway event (`Queue Routed`, +23 pp), and warehouse-ingestion timestamps inverting `Decision` and `Notify` (+8 pp). In August–September, an additional 20 percentage points of apparent nonconformity stemmed from an obsolete normative process tree that was never updated after the August 1 `Supervisor Sign-off` policy for claims exceeding EUR 50,000. Confidence in this primary diagnosis for the *measured conformance drop* is **high (90%)**, grounded in release chronology, manual UI/screenshot audits, and staged counterfactual recovery.

However, **a real operational compliance concern remains unresolved** with **moderate confidence (~50–55%)**. Across June–September, 55 `Enhanced Review` cases (4.3% of post-May volume, up from 0% in April–May) lack a recorded `Compliance Check`, and `Manual Override` usage rose from 20 to 35 cases. Stable appeal rates (~3.7%) do not rule out violations because compliance incident detection is admittedly incomplete and 4–5% bypasses can hide in aggregate averages.

**Immediate actions:**
- **IT:** Deploy a versioned semantic mapping (`Risk Screen` -> `Classify`), tag and exclude `Queue Routed` from business conformance views, restore `source_sequence_number` ordering for `Decision`/`Notify`, and check gateway logs for dropped `Compliance Check` events.
- **Process Owners:** Update and version the normative model to include data-aware `Supervisor Sign-off` (> EUR 50,000) and define explicit logging/authorization rules for `Manual Override`.
- **Compliance:** Audit all 55 `Enhanced Review -> Decision` cases directly against source compliance records and stratify `Supervisor Sign-off` by the EUR 50,000 attribute.

**What must not be claimed yet:** Do not claim that employees caused the conformance crash, nor declare the process fully compliant until the 55 missing compliance checks, remaining `Notify -> Decision` inversions, and EUR 50,000 sign-off boundaries are verified in source systems.

## 8. Model-governance recommendation

1. **Formal Model Versioning and Policy Synchronization:** Maintain versioned normative models tied to policy effective dates (`valid_from` / `valid_to`), requiring model updates to be approved and deployed concurrently with any policy change (such as `Supervisor Sign-off`) before conformance dashboards evaluate post-change cases.
2. **Event-Semantic Contracts for UI and Application Changes:** Enforce a binding event-ontology contract requiring product/UI teams to map display-label changes (e.g., `Classify` -> `Risk Screen`) to stable canonical activity IDs (`concept:name`) and log schema versions before release.
3. **Technical-Event Segregation Policy:** Require event gateways and middleware to tag non-business telemetry (e.g., `Queue Routed`) with an explicit `event_class = technical` attribute and filter technical events out of control-flow conformance pipelines by default.
4. **Timestamp Provenance and Source-Sequence Preservation:** Prohibit ETL pipelines from overwriting business execution timestamps with warehouse-ingestion clocks; store `source_event_timestamp`, `source_sequence_number`, and `etl_ingested_at` separately and order conformance traces deterministically by source sequence.
5. **Data-Aware Conformance Constraints:** Upgrade control-flow-only process trees to data-aware models (e.g., Data Petri Nets or guarded conformance rules) whenever business rules depend on case attributes or roles (e.g., `Supervisor Sign-off` required iff `claim_value > EUR 50,000`), preventing optional-branch overgeneralization.
6. **Automated Post-Release Validation Gates:** Run shadow conformance and DFG-diff checks on the first 48–72 hours of data after every UI, gateway, ETL, or policy release, automatically flagging sudden drops in fitness, spikes in resource-less events, or new variants for provenance triage before reporting compliance breaches.
