# 1. Equivalence Notions

Let a **visible trace** be the sequence of activity labels executed from the initial marking (`Open Case`) to the final marking (`Close Case`), with silent steps (`tau` or `None`-labelled transitions) removed. Parallel (`+`) produces all interleavings of its children; sequence (`->`) enforces order; exclusive choice (`X`) selects one branch; loop (`*`) executes child-1 once, then either exits or executes child-2 followed by child-1, repeating.

- **Visible trace equivalence after hiding `tau`**: Two models are equivalent iff they generate exactly the same set of visible trace strings (complete runs Open…Close). Duplicate visible labels are **distinguished by occurrence position** in the linear trace; the multiset of labels is not sufficient.
- **Bounded visible-language equivalence (P3)**: Restrict visible-trace equivalence to complete traces with `|visible events|  12`, `count('Analyze Revision')  3`, and silent-step paths bounded (`silent_steps  30`). This is an **exhaustive bounded exploration**, not an unbounded proof.
- **Business-relevant equivalence (P1)**: Two traces/models are equivalent iff they satisfy the same compliance relation: for every analysis attempt there is a paired `Check Revision` that occurs **before** the next `Rework Case` or `Close Case`; `Rework Case` separates attempts; `Approve Revision` is present optionally (via `X` with `tau`); and the number/placement of approvals is retained as observable.
- **Abstracted dashboard equivalence (P2)**: Traces are mapped to an abstract record `{Open, Close, analyze_count  {1,2,3,…}, rework_occurred  {T,F}, check_occurred  {T,F}}`. `Approve Revision`, all `tau`, interleavings, and duplicate `Check Revision` occurrences are collapsed/hidden. Two models are equivalent iff they produce the identical multiset of abstract records.

# 6. Stochastic and Footprint Comparison

```python
# Footprint relations (direct succession, parallel, etc.)
# Note: footprints abstract ordering beyond pairwise relations.
footprint_A = pm4py.discover_footprints(net_A, im_A, fm_A)
footprint_B = pm4py.discover_footprints(net_B, im_B, fm_B)

# Stochastic language requires declared transition probabilities.
# We do NOT invent probabilities. Without them, get_stochastic_language
# and compute_emd are not meaningful.
# If probabilities were assigned, equal footprints or a low EMD
# would STILL not establish trace equivalence, because footprints
# discard multi-step ordering and EMD compares distributions,
# not language membership.
```

**Why footprints / low EMD are insufficient:**
- `discover_footprints` collapses all traces into pairwise relations (``, `||`, `#`). Two nets can share footprints while differing on three-step interleavings (e.g., `Check` placed globally vs locally).
- `get_stochastic_language` requires a stochastic net; none is declared here.
- `compute_emd` measures distributional distance between stochastic languages. Even `EMD  0` only says the *probability masses* are close; it permits hidden trace differences that cancel out in the metric, and it says nothing about deterministic equivalence.

# 7. Complexity Comparison

```python
def tree_struct_stats(tree_str):
    tree = pm4py.parse_process_tree(tree_str)
    nodes = 0
    max_depth = 0
    visible_leaves = 0
    silent_leaves = 0
    label_counts = Counter()

    def rec(node, d):
        nonlocal nodes, max_depth, visible_leaves, silent_leaves
        nodes += 1
        max_depth = max(max_depth, d)
        if node.children is None or len(node.children) == 0:
            # leaf
            lbl = getattr(node, 'label', str(node))
            label_counts[lbl] += 1
            if lbl == 'tau' or lbl is None or lbl == '':
                silent_leaves += 1
            else:
                visible_leaves += 1
        else:
            for child in node.children:
                rec(child, d + 1)

    rec(tree, 0)
    dup_labels = sum(1 for c in label_counts.values() if c > 1)
    return {
        'nodes': nodes,
        'max_depth': max_depth,
        'visible_leaves': visible_leaves,
        'silent_leaves': silent_leaves,
        'duplicate_labels': dup_labels,
        'label_counts': dict(label_counts)
    }

stats_A = tree_struct_stats(model_A_str)
stats_B = tree_struct_stats(model_B_str)

print("Model A stats:", stats_A)
print("Model B stats:", stats_B)

net_A, im_A, fm_A = pm4py.convert_to_petri_net(tree_A)
net_B, im_B, fm_B = pm4py.convert_to_petri_net(tree_B)
simp_A = pm4py.simplicity_petri_net(net_A, im_A, fm_A)
simp_B = pm4py.simplicity_petri_net(net_B, im_B, fm_B)
print("Simplicity A:", simp_A)
print("Simplicity B:", simp_B)
```

**Derived structural counts (manual verification from tree syntax):**

| Metric | Model A | Model B |
|---|---|---|
| **Process-tree nodes** | 12 | 12 |
| **Depth (rootdeepest leaf)** | 4 | 5 |
| **Visible leaves** | 6 (`Open`, `Analyze`, `Check`, `Approve`, `Rework`, `Close`) | 6 (same labels) |
| **Silent leaves (`tau`)** | 1 | 1 |
| **Duplicate-label leaf nodes** | 0 | 0 |
| **Converted-net simplicity** | Reported by code (`simplicity_petri_net`) | Reported by code (`simplicity_petri_net`); B expected slightly lower due to extra parallel join/split layer outside the loop |

The trees have identical leaf-label multiset and identical node count, but **B is deeper** (depth 5 vs 4) because the loop is nested inside the parallel child.

# 8. Simplified Model

**Target semantics:** **P2 (executive dashboard)** — the highest-level abstraction that collapses approvals, hides `tau`, ignores interleaving, collapses `Check` to a boolean, and records only `Analyze` count and `Rework` presence.

**Simplified expression (pure sequence, no parallel, no hidden choice):**

```python
simplified_model = ("->('Open Case', "
                    "->('Check Revision', "
                    "  *('Analyze Revision', 'Rework Case')"
                    "), 'Close Case')")

simplified_tree = pm4py.parse_process_tree(simplified_model)
```

This removes:
- The `+` concurrency (interleaving is abstracted away; `Check` is ordered before the loop, which is acceptable under P2 because placement is hidden).
- The `X('Approve Revision', tau)` inside the loop (approval is hidden; loop body is now a single visible step).
- The extra nesting depth of B’s parallel-join structure.

**Preservation table:**

| Property | Status in simplified model | Note |
|---|---|---|
| `Open Case` first / `Close Case` last | **Exact** | Top-level `->` preserved |
| At least one `Analyze Revision` | **Exact** | Loop `*` requires child-1 (`Analyze`) at least once |
| At least one `Check Revision` | **Exact** | Explicit `Check` before loop |
| `Analyze` occurrence count visible | **Exact** | Equals loop iteration count |
| `Rework Case` presence visible | **Exact** | Present iff loop repeats (`count > 1`) |
| `Check` interleaving with loop | **Abstracted / lost** | Forced to precede loop; P2 does not observe interleaving |
| `Approve Revision` visible | **Lost** | Removed; P2 hides it |
| Silent `tau` paths | **Lost** | Removed; P2 hides silent behavior |
| Multiple `Check` occurrences | **Weakened to boolean** | Exactly one `Check` in model; P2 collapses duplicates anyway |
| 1:1 `Check`–`Analyze` pairing (P1) | **Lost** | Not required by P2 target |

**Regression traces (should be admitted by simplified model):**

| ID | Trace | Meaning |
|---|---|---|
| R1 | `Open`  `Check`  `Analyze`  `Close` | Single analysis, no rework |
| R2 | `Open`  `Check`  `Analyze`  `Rework`  `Analyze`  `Close` | Two analyses, one rework |
| R3 | `Open`  `Check`  `Analyze`  `Rework`  `Analyze`  `Rework`  `Analyze`  `Close` | Three analyses, two reworks |

**Negative traces (should NOT be admitted — they require features removed/abstracted):**

| ID | Trace | Why rejected |
|---|---|---|
| N1 | `Open`  `Analyze`  `Check`  `Close` | `Check` follows `Analyze`; simplified forces `Check` first |
| N2 | `Open`  `Check`  `Analyze`  `Approve`  `Close` | `Approve` removed |
| N3 | `Open`  `Check`  `Analyze`  `Rework`  `Analyze`  `Check`  `Close` | Second `Check` impossible (only one exists) |

**Structural justification of “simpler”:**  
The simplified tree has **no `+` nodes, no `X` nodes, and no nested `->` inside the loop**, reducing operator variety from `{, +, *, X}` to `{, *}` only. Node count drops from 12 to 8 (`Open`, `Check`, loop `*`, `Analyze`, `Rework`, `Close`, plus root `` and inner ``).

# 9. Final Recommendation

| Business view | Suitability | Recommendation |
|---|---|---|
| **P1 — Compliance / Audit** | **Model A** only | A enforces the required 1:1 pairing of `Check` with each loop iteration. **Model B must not be used** for compliance verification because a single global `Check` can cover multiple revisions, violating the “own check before next rework” rule. |
| **P2 — Executive Dashboard** | **Both A and B acceptable**; **use the simplified model** | The simplified sequential model (`Check`  loop  `Close`) preserves all dashboard-relevant facts (`Analyze` count, `Rework` boolean, `Check` boolean, `Open`/`Close` boundaries) and eliminates unnecessary concurrency and hidden choices. Replace both originals with the simplified tree for reporting. |
| **P3 — Bounded Regression Testing** | **Test both originals separately**; do **not** merge test suites | Within the P3 bound (`12` visible, `3` `Analyze`), A and B generate disjoint trace sets (see Section 4). Bounded exploration is valuable **evidence** but is not a proof of unbounded equivalence; maintain separate bounded suites for A and B. |

**Warning on bounded comparison:**  
The P3 analysis in Section 5 is exhaustive **only** within the declared bounds (`visible  12`, `Analyze  3`). Because both loops are unbounded (`*` allows infinite repetition), bounded equivalence does **not** imply unbounded equivalence. A divergence could appear at iteration 4 or at visible length 13. Therefore, bounded results should be reported as “no counterexample found within bounds” rather than “models are equivalent.”

**Overall:**  
Keep **Model A** as the authoritative compliance model. Adopt the **simplified P2 model** for dashboards and high-level reporting. Do **not** treat A and B as interchangeable for audit or testing purposes.
