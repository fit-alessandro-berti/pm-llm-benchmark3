def expand_variants(variants):

    return pm4py.parse_event_log_string("\n".join(lines))

def normalize_trace(trace, map_risk=True, remove_queue=False):
    acts=[a.strip() for a in trace.split(",")]
    if map_risk:
        acts=["Classify" if a=="Risk Screen" else a for a in acts]
    if remove_queue:
        acts=[a for a in acts if a!="Queue Routed"]
    return ",".join(acts)

def normalize_variants(variants, map_risk=True, remove_queue=False):
    out=Counter()
    for trace,count in variants.items():
        out[normalize_trace(trace,map_risk,remove_queue)] += count
    return dict(out)

def eval_log(log, net, im, fm, name):

Measured fitness collapses because the recorded log and the normative model stop describing the same process language. Still, the process may have a real operational concern. The sign-off policy is real and conditional on high value. The defensible conclusion is layered: primary cause of the measured collapse is logging/order/technical artifact plus model obsolescence; unresolved compliance risk remains until source-of-record audit and high-value stratification are completed.

    lines = []

def normalize_trace(trace, map_risk=True, remove_queue=False):
    acts = [a.strip() for a in trace.split(",")]
    if map_risk:
        acts = ["Classify" if a == "Risk Screen" else a for a in acts]
    if remove_queue:
        acts = [a for a in acts if a != "Queue Routed"]
    return ",".join(acts)

    out = Counter()

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is instrumentation and model-governance failure, not a sudden mass behavioral shift. Confidence: 90%. The evidence is staged: the UI label change explains the first Jun-Jul drop; mapping `Risk Screen` to `Classify` raises fitness substantially; removing the technical `Queue Routed` event improves it further; source-sequence ordering removes many reversed `Notify`/`Decision` moves; and the Aug policy change makes the normative model obsolete. These are exactly the signatures of labels, technical events, timestamp provenance, and model versioning, not proof of widespread employee misconduct. The process may genuinely have changed for high-value claims, but the model failed to encode that data-aware condition.

A real compliance problem may still remain. Confidence that at least some genuine compliance exceptions exist is moderate, around 40–50%, but confidence that the observed fitness collapse proves them is low. The unresolved risk is concentrated in enhanced reviews without a recorded `Compliance Check`, high-value cases without `Supervisor Sign-off`, and reviewer-level use of `Manual Override`. No reliable audit has established whether those are true bypasses or missing events. Stable appeal and incident rates are reassuring but insufficient because detection is incomplete.

Immediate actions: IT should fix event semantics, publish a label/event dictionary, preserve source sequence numbers, tag technical events, and restore missing resource fields. Process owners should version the normative model by effective date and add a conditional high-value sign-off model rather than an overpermissive optional one. Compliance should audit every enhanced case without a compliance check, every high-value case without sign-off, and reviewer clusters using `Manual Override`, linking findings to source-system records and appeal/incident outcomes.

Do not claim yet that employees are noncompliant because alignment moves increased. Do not claim stable appeals prove there is no compliance problem. Do not treat the optional sign-off model as the correct policy model, because it cannot enforce EUR 50,000 and may inflate fitness by permitting too much.

## 8. Model-governance recommendation

1. Version every normative model by effective date, scope, policy change, and process variant; conformance jobs must select the model valid for the event date and case attributes.
2. Maintain event-semantic contracts for every activity label, including UI label changes, synonyms, deprecations, and mappings such as `Risk Screen``Classify`.
3. Govern technical events explicitly: label them as technical, exclude them from business conformance by default, and require provenance evidence before treating them as process behavior.
4. Record timestamp provenance: preserve source-system sequence numbers, distinguish source time from ingestion/warehouse time, and validate ordering before alignment.
5. Encode data-aware constraints or pair the control-flow model with separate rules for high-value thresholds, sign-off, authorizations, and compliance checks.
6. Run post-release validation after every UI, policy, gateway, or ETL change: compare raw and normalized fitness/precision, inspect variants and DFGs, audit semantic drift, and alert when conformance changes without corresponding business-outcome change.
