import pandas as pd

def to_utc_interval(local_str, tz_name, semantics, offset_bounds, fmt="%Y-%m-%d %H:%M:%S"):
    """
    Returns list of [low, high) UTC datetimes (usually one, two for DST ambiguity).
    semantics: "exact_s" (HUB), "floor_min", "round_10s", "round_min"
    offset_bounds: (a,b) with offset=recorded - true in seconds
    """
    # parse naïve
    try:
        dt_naive = datetime.strptime(local_str, fmt)
    except ValueError:
        # try without seconds
        dt_naive = datetime.strptime(local_str, "%Y-%m-%d %H:%M")
    tz = ZoneInfo(tz_name) if tz_name else timezone.utc

    # preimage in wall time
    if semantics == "exact_s":
        c_lows = [dt_naive - timedelta(seconds=0.5)]
        c_highs = [dt_naive + timedelta(seconds=0.5)]
    elif semantics == "floor_min":
        c_lows = [dt_naive]
        c_highs = [dt_naive + timedelta(minutes=1)]
    elif semantics == "round_10s":
        c_lows = [dt_naive - timedelta(seconds=5)]
        c_highs = [dt_naive + timedelta(seconds=5)]
    elif semantics == "round_min":
        c_lows = [dt_naive - timedelta(seconds=30)]
        c_highs = [dt_naive + timedelta(seconds=30)]
    else:
        raise ValueError(semantics)

    a,b = offset_bounds
    intervals = []
    # DST ambiguity: for Europe/Berlin 2025-10-26 02:xx, create fold=0 and fold=1 versions
    folds = [0,1] if ("2025-10-26 02:" in local_str and tz_name=="Europe/Berlin") else [None]
    for c_low, c_high in zip(c_lows, c_highs):
        for fold in folds:
            # attach tz and handle fold
            if fold is None:
                low_wall = c_low.replace(tzinfo=tz)
                high_wall = c_high.replace(tzinfo=tz)
            else:
                low_wall = c_low.replace(tzinfo=tz, fold=fold)
                high_wall = c_high.replace(tzinfo=tz, fold=fold)
            low_utc = low_wall.astimezone(timezone.utc)
            high_utc = high_wall.astimezone(timezone.utc)
            # true = clock - offset  ->  [low_utc - b , high_utc - a)
            true_low = low_utc - timedelta(seconds=b)
            true_high = high_utc - timedelta(seconds=a)
            intervals.append((true_low, true_high))
    # deduplicate (folds may give same)
    uniq = []
    for iv in intervals:
        if iv not in uniq:
            uniq.append(iv)
    return uniq

def duration_interval(A_intervals, B_intervals):
    """Minkowski difference union, preserving disjointness."""
    d_intervals = []
    for a_l,a_h in A_intervals:
        for b_l,b_h in B_intervals:
            d_l = (b_l - a_h).total_seconds()
            d_h = (b_h - a_l).total_seconds()
            d_intervals.append((d_l,d_h))
    # merge overlapping for reporting, but keep disjoint flag
    d_intervals.sort()
    return d_intervals

def classify_interval(d_intervals, accept_low=-1e18, accept_high=1e18):
    """Returns CERTAIN_PASS / CERTAIN_VIOLATION / POSSIBLE_VIOLATION."""
    # feasible as union
    # wholly inside: all intervals inside [low,high]
    # wholly outside: all intervals strictly below low or strictly above high
    all_inside = all(l >= accept_low and h <= accept_high for l,h in d_intervals)
    if all_inside:
        return "CERTAIN_PASS"
    all_below = all(h < accept_low for l,h in d_intervals)
    all_above = all(l > accept_high for l,h in d_intervals)
    if all_below or all_above:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

def feasible_with_order(A_ivs, B_ivs, enforce_order=False):
    if not enforce_order:

            if nl <= h:

            # if all negative, resulting empty means inconsistent
        return filtered if filtered else d  # return empty flag handled outside

## 6. Evidential Sufficiency

For each `POSSIBLE_VIOLATION`/`INDETERMINATE` we state minimal additional evidence to reach certainty, distinguishing categories:

* **T-401 S1, Temporal AI – POSSIBLE:** *Stronger synchronization.* 60 s floor + 210 s offset dominates. Need NTP diagnostic for that minute proving offset `0` and second-resolution log (or HUB-corroborated start). ±30 s improvement would make S1 certainly PASS (threshold 900 >991 becomes false). *Duration evidence* not helpful (already duration-based SLA).

* **T-402 S1 CERTAIN, S2 POSSIBLE, Temporal – POSSIBLE/CERTAIN:** *No additional needed for S1* – even best-case OPS-BER misses SLA. For S2 need per-minute NTP offset log to shrink 270 s width from 2488-2761 to <14 s to decide PASS vs VIOLATION. *Missing activity* not needed.

* **T-403 S1, Temporal AI/AC – POSSIBLE:** *Stronger sync.* VENDOR-NY external with `±180s` + floor gives 420 s width. Need vendor clock sync proof (`30s`) or second-precision receipt ack. Also *semantic evidence*: contractual definition whether vendor `04:00` is send vs receive; receipt ack would fix.

* **T-404 S1/S2 inferred – POSSIBLE (borderline 3s):** *Duration evidence:* narrower signed work record (e.g., 20-22 min vs 18-25 min) would collapse 426 s width to ~120 s, making S2 certainly PASS (27032580) and S1 decision sharper. *Missing activity evidence:* actual `Investigation_Start` timestamp with HUB precision would be definitive. *Resolution metadata:* confirm whether `Investigation_Complete` is truly completion.

* **T-405 S1 – POSSIBLE (after disambiguation):** *Semantic/DST fold evidence:* logged fold flag (`is_dst`) for each timestamp would make intervals independent without inference; currently fold eliminated only via ingestion order (logical causality). * **T-406 S1/S2 – POSSIBLE, low confidence:** *Semantic evidence for entry delay:* policy whether 0-5 min user delay is occurrence uncertainty (primary) vs pure log lag (alt). * **T-407 S1, Temporal A* – INDETERMINATE / POSSIBLE:** *Missing activity evidence:* receipt acknowledgment (network ACK, app log) is definitionally required; `Alert_Sent + [0,20m]` is bound, not identity. *Semantic evidence:* logged causal ID linking receiptinvestigation would allow strong `RI` truncation; without it no enforcement. * **T-408 S2/S3 – CERTAIN_VIOLATION:** No additional needed – HUB-HUB tight intervals (>10 min over for S2, >2.4 h over for S3) even with +5 min grace remain violation.

General principle: `POSSIBLE` requires **narrower clock/rounding bounds**; `INDETERMINATE` requires **existence of event evidence** (receipt, start, fold flag, causal ID) plus bounds.

## 7. Governance Recommendation

**1. Storage:** Store all timestamps **as UTC with original local wall time, zone ID, fold flag, and raw string preserved**. Never store only local wall time. Store `recorded_at_utc`, `recorded_at_local`, `zone`, `fold`, `source_id`.

**2. Raw timestamp retention & resolution metadata:** Log `display_semantics` (`exact_s`, `floor_min`, `round_10s`, `round_min`, `floor_min_completion` etc.), `resolution`, and `completion vs start` lifecycle qualifier per activity. Prohibit aggregating floor/rounded times into second-precision without flag.

**3. Clock-offset telemetry:** Require continuous NTP/PTP diagnostics per source (min 1/min). Store offset `[a,b]` per event (or 1-min bucket) not global bound. Missing diagnostics  mark event `sync_weak` and downgrade evidence strength (as T-409). External sources (VENDOR-NY, MOBILE) must provide offset attestation or be treated as `low` trust for SLA enforcement.

**4. Time-zone & DST:** Use IANA `ZoneInfo`; on DST fallback **mandate fold logging** (`fold=0/1`, `is_dst`). LEGACY-BER must be upgraded to capture fold. Ingestion pipelines must reject 02:00-02:59 timestamps without fold during transition weeks, or quarantine for manual fold resolution.

**5. Lifecycle & provenance:** Enforce `start` vs `complete` semantics in XES `lifecycle:transition`. `SENSOR` completion-only events must be typed as `complete`; inference of start from completion±duration (T-404) must be recorded as derived with retained `duration_interval` and `source_work_record_id`. `Alert_Sent` vs `Alert_Received` must have distinct activity names and `causal_id` (message ID) linking sendreceive; network latency bounds `[0,20m]` stored as `delivery_sla` not as receipt.

**6. User-entered / mobile:** Separate fields `event_occurrence_time` vs `record_entry_time`. Entry delay `5m` must be measured (tap telemetry) and stored as `entry_delay_interval`. Policy decision documented: for SLA we evaluate **occurrence time** (primary assumption) – record lag does not excuse violation unless occurrence proven earlier.

**7. Interval-based enforcement policy:** 
   * `CERTAIN_VIOLATION`  automatic SLA breach, penalty, and corrective action.
   * `POSSIBLE_VIOLATION`  mandatory investigation, no penalty until additional evidence (narrowed sync, missing ack) obtained; treat as at-risk.
   * `CERTAIN_PASS`  close, retain temporal deviation as informational if certain temporal violation.
   * `INDETERMINATE`  suspend enforcement, request missing evidence per §6.
   Overlap of feasible interval with threshold is **insufficient** for penalty – prevents false positives from 270 s OPS-BER or 960 s MOBILE widths.

**8. Verification & audit:** Nightly interval-recomputation job (pandas/ZoneInfo library as in §5) recomputes all durations with current telemetry; sensitivity analysis (`+2m/+5m`, `zeta 1-3`) published with each conformance report. Midpoints may be shown only as “illustrative secondary view – lossy”.

Adopting these controls makes the distinction `POSSIBLE` vs `CERTAIN` auditable, eliminates DST and floor-induced false certainty, and aligns with the instruction that a point timestamp is not automatically true time.
