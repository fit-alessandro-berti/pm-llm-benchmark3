# 1. Objectives and constraints

The policy aims to optimize resource assignment through a multi-objective scoring function that balances efficiency, compliance, and human factors.

**Optimization Objectives:**
*   **Throughput:** Minimize case waiting time and total service time.
*   **SLA Compliance:** Prioritize cases with imminent deadline violations.
*   **Quality:** Minimize rework by matching case complexity to resource skill.
*   **Fairness:** Distribute workload evenly to prevent burnout (load balancing).
*   **Development:** Allocate specific cases to resources based on training priorities.
*   **Continuity:** Minimize handovers to reduce context-switching costs and errors.

**Hard Constraints (Safety/Compliance):**
1.  **Skill Floors:** Security Review requires Skill 3 (or 1–2 supervised); Final Approval requires Skill 2–3.
2.  **Priority Protection:** High/Urgent priority cases cannot be assigned to Skill < 2 without supervision.
3.  **Batch Limit:** No resource receives > 4 new assignments in a single decision batch.
4.  **Overtime Cap:** Resources with `Overtime risk = High` cannot receive new work unless the case is Urgent and no alternative exists.
5.  **Supervision:** Trainees (Skill 1–2) on critical activities must be paired with a designated supervisor (Skill 3).

**Soft Constraints (Preference Trade-offs):**
1.  **Training Quota:** At least 20% of Normal/Low priority assignments should support documented training priorities, provided SLA risk is low.
2.  **Continuity vs. Skill:** Prefer current owner for high-complexity/high-handover-cost cases, unless owner skill is insufficient (0–1) without supervision.
3.  **Batching:** Quality Checks should be batched if Priority is Normal/Low and SLA > 24h.

# 2. Assignment policy

The policy uses a weighted scoring model executed per decision batch.

**Algorithm: Dynamic Resource Assignment**

1.  **Preprocessing:**
    *   Sort cases by Priority (Urgent > High > Normal > Low) then by SLA remaining (ascending).
    *   Filter resources: Remove resources exceeding `Max Assignments (4)` or `Hours Remaining = 0`.

2.  **Eligibility Filtering (Hard Constraints):**
    *   For each case `c` and resource `r`:
        *   If `c.required_skill` > `r.skill`: Mark `Ineligible` (unless Supervision available).
        *   If `c.priority` in [Urgent, High] AND `r.skill` < 2: Mark `Ineligible` (unless Supervision available).
        *   If `r.overtime_risk` == "High" AND `c.priority` not "Urgent": Mark `Ineligible`.
        *   If `c.activity` == "Security Review" AND `r.skill` < 3: Require Supervisor (R7 or R8).
        *   If `c.activity` == "Final Approval" AND `r.skill` < 2: Mark `Ineligible`.

3.  **Scoring Function `S(r, c)`:**
    *   **SLA Urgency (0–30 pts):** Higher score if `SLA remaining` < 4h.
    *   **Skill Match (0–25 pts):** Higher score if `r.skill` >= 3. Bonus if `r.training_priority` == `c.activity`.
    *   **Continuity (0–20 pts):** Max score if `r` == `c.current_owner`. Penalty if `c.reassignment_count` > 2.
    *   **Workload Fairness (0–15 pts):** Higher score if `r.current_open_cases` is low relative to team average.
    *   **Resilience (0–10 pts):** Penalty if `r.overtime_risk` == "High".

4.  **Selection & Assignment:**
    *   Select `r` with highest `S(r, c)`.
    *   **Training Check:** If < 20% of Normal/Low cases are assigned for training, boost score for resources with matching `training_priority` on low-risk cases.
    *   **Batching:** If `c.activity` == "Quality Check" and SLA > 24h, group with other Quality cases for the same resource.
    *   **Update:** Increment `r.assignments_in_batch`. If limit (4) reached, remove `r` from pool for subsequent cases.

5.  **Exception Handling:**
    *   If no eligible resource found: Escalate to Process Owner for manual override (log reason).
    *   If Supervision required: Assign Supervisor resource explicitly in the log (`supervisor_id`).

# 6. Process-mining audit indicators

To ensure the policy is working as intended and remains auditable, the following indicators will be tracked using the event log:

1.  **Handover Frequency:** `count(reassignment_count > 0) / total_cases`. Target: < 15%. High values indicate continuity failures.
2.  **Skill Mismatch Rate:** `count(assignments where resource_skill < required_skill) / total_assignments`. Target: 0% for Urgent/High priority.
3.  **Workload Distribution (Gini Coefficient):** Measure variance in `workload_snapshot` across resources. Target: < 0.3 (Equitable distribution).
4.  **Overtime Risk Exposure:** `count(assignments to resources with overtime_risk='High')`. Target: Trending down, except for Urgent cases.
5.  **SLA Miss Rate by Assignment Type:** Compare SLA misses for "Training Assignments" vs. "Standard Assignments". Ensures training doesn't compromise deadlines.
6.  **Rework/Appeal Rate Post-Assignment:** `count(case_variant contains 'Rework')` grouped by `assignment_reason`. Detects if specific routing logic causes errors.
7.  **Training Assignment Share:** `count(assignments matching training_priority) / count(normal_low_priority_cases)`. Target:  20%.
8.  **Specialist Bottleneck Indicator:** Average `waiting_time` for activities routed to Skill 3 resources only. Detects if specialist-only logic is creating queues.
9.  **Policy Deviation Count:** `count(manual_overrides)`. High values suggest the algorithmic policy is misaligned with reality.
