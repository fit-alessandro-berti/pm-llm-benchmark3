# 1. Assumptions and notation

**Notation.** All times are 2026-05-12. Window `W = [08:00, 14:00)`, length 360 min. For case *i*:
`a_i` = external arrival (S2-irrelevant), `b1_i / e1_i` = S1 start/end, `b2_i / e2_i` = S2 start/end.
Queue entry into S1 is `a_i`; queue entry into S2 is `e1_i` (given by the scenario).
`Wq1 = b1 − a`, `Sv1 = e1 − b1`, `Wq2 = b2 − e1`, `Sv2 = e2 − b2`.
Station sojourn `Soj1 = e1 − a = Wq1 + Sv1`, `Soj2 = e2 − e1 = Wq2 + Sv2`. Case sojourn `Soj = e2 − a`.
`Lq_s(t)` = number waiting at station *s*; `Lw_s(t)` = WIP at station *s* (waiting + in service);
`L(t)` = total system WIP. Rates are counts per hour on a stated interval.

**A1 — Event-order / tie convention.** Because timestamps are rounded to 5 min, ties are frequent and
often artificial. All step functions are right-continuous and, at a shared timestamp, events are applied
in the order *service completion → queue exit (service start) → queue entry*. Rationale: this avoids
phantom simultaneous occupancy (e.g. P07 ends on C1 at 11:00 and P09 starts on C1 at 11:00 — with
exits-first this is a clean handover, with entries-first it is a spurious double-booking). Time-averages
are unaffected by the tie order (ties have measure zero); only instantaneous peaks can move, so both
orderings are reported for peaks in §4.

**A2 — Rounding model.** A reported `t` represents a true time uniform on `[t−2.5, t+2.5]`. Hence a
*duration* computed from two reported timestamps is unbiased but has error support `[−5, +5]` min and
SD ≈ 2.04 min. Consequence used throughout: **a reported 5-min gap is consistent with a true gap
anywhere in `(0, 10)` min**, so the ubiquitous 5-min gap between consecutive jobs on one resource may be
a real changeover, a rounding artifact, or both. Adjacent/identical timestamps on one resource are
therefore *not* treated as evidence of a conflict (as the scenario warns).

**A3 — Capacity.** S1 = {I1, I2}, S2 = {C1, C2}, each single-task, each available for the whole window
except C2, unavailable 10:55–11:10 (15 min). Server-minutes available: S1 = 720, S2 = 720 − 15 = 705.

**A4 — No bypass, mandatory order.** Every case must complete S1 before S2; a blank S2 pair with a
completed S1 means the case is in the S2 queue at 14:00 (not skipped).

**A5 — Status semantics are kept distinct.** `MISSING` = activity happened, start unrecorded (bounded
below/above, §2). `OPEN` = started, not finished by 14:00 → *elapsed* service is observed, *final*
service is right-censored. Blank = the activity never started → the **waiting time** is right-censored at
14:00 and no service duration exists. These three are never collapsed into one code.

**A6 — Imputation constraints for a MISSING start** `b`: (i) `b ≥` queue entry; (ii) `b ≥` the end of the
previous job of the same resource (no overlap); (iii) `b ≤` the recorded end (non-negative service);
(iv) FIFO consistency with neighbouring cases on the same resource. These give a *hard feasible interval*.

**A7 — Central estimate inside the feasible interval.** The line shows an almost deterministic
"previous end + 5 min" handover (I2: 10/10 consecutive jobs; I1: 9/9 observed; C1: 6/7; C2: 5/6).
The central estimate is therefore `b = min(upper, max(lower, prev_end + 5 min))`. This is an explicitly
justified point inside the interval, not a silent default; §6 varies it to both endpoints.

**A8 — Right-censoring is never discarded.** Censored waits enter every sum as their *elapsed* value, i.e.
as a **lower bound**; open services enter busy-time as elapsed minutes clipped at 14:00. Point predictions
for final values are given separately (§6) using the resource's own empirical service distribution.

**A9 — Server-availability basis for utilisation.** Utilisation = busy minutes / available minutes, with
C2's 15 maintenance minutes removed from the denominator. Utilisation is computed from *all* work in the
window, including work on open activities — never from completed cases only.

**A10 — Routing hypothesis (used only for interpretation, not for imputation).** Cases P01–P09 map
I1→C1 and I2→C2; from P10 the mapping swaps (I2→C1, I1→C2). I therefore treat S2 as *two loosely
paired sub-queues* rather than one strict FIFO pool. This is what makes P09 (queued 10:35) start at
11:00 before P08 (queued 10:20) a routing effect, not a queue-discipline violation. It is a hypothesis;
all station metrics below are computed on the pooled station and do not depend on it.

**A11 — Arrival timestamps come from another system** but with identical rounding, so `Wq1` inherits the
same `[−5, +5]` error; no systematic clock offset is assumed (none is observable, since `b1 ≥ a` holds for
all 21 started cases).

**A12 — Nothing is assumed about behaviour after 14:00** except in explicitly labelled projections (§6).

# 2. Reconstruction method and formulas

**Waiting / service / sojourn.** As defined in §1. Three estimate levels are produced for every quantity
that involves a `MISSING` start:

| level | rule | interpretation |
|---|---|---|
| lower / "early" | `b = ` earliest feasible start (A6) | longest possible service, shortest possible wait |
| central | `b = prev_end + 5 min`, clipped to the feasible interval (A7) | modal handover behaviour of the line |
| upper / "late" | `b = ` recorded end | degenerate zero service, longest possible wait |

The "late" column is a *hard bound*, not a plausible operational story (a 0-min calibration is not
credible); it is retained to show what the data alone can exclude.

**Counting processes.** For station *s*, `Lq_s(t) = #{entries ≤ t} − #{starts ≤ t}` and
`Lw_s(t) = #{entries ≤ t} − #{ends ≤ t}`, both with A1's tie rule. Total `L(t) = #{a_i ≤ t} − #{e2_i ≤ t}`.
Time averages are exact integrals of the step functions over the stated interval (1-min grids are used
only for the idle-time decomposition, which is exact at 5-min data grain).

**Finite-window accounting identity.** `∫_W Lq_s(t) dt = Σ_i (time case i spends in queue s within W)`,
where censored cases contribute their elapsed wait. This is an identity, not a test — it is used to
cross-check the step functions (S2: 780 case-min both ways; S1: 1490 case-min both ways).

**Throughput / rates.** `arrivals(I) = #{a_i ∈ I}`, `S1 throughput(I) = #{e1_i ∈ I}` (which is also the S2
arrival stream), `system throughput(I) = #{e2_i ∈ I}`, each divided by `|I|` and scaled to per hour.

**Busy time and utilisation.** `busy(r, I) = Σ_jobs |[b, e] ∩ I|` with `e := 14:00` for open jobs;
`ρ(r, I) = busy(r, I) / (|I| − maintenance(r, I))`. Station utilisation pools the two servers.
Idle time is further split into *idle while own queue non-empty* (real lost capacity: changeover,
unexplained) and *idle while own queue empty* (starvation — evidence **against** that station being the
constraint at that moment).

**Capacity arithmetic.** With mean service `μ_s` and 2 servers, nominal capacity is `120/μ_s` per hour;
with an assumed real 5-min changeover it is `120/(μ_s + 5)`. Both are reported because A2 leaves the
changeover only partially identified.

**Little's Law.** `L = λW` is applied *only* on intervals `I` where (i) `Lq(start) = Lq(end)` and
(ii) entries ≈ exits, so that the interval is flow-balanced and the "which cohort" ambiguity is small.
Then `λ = entries/|I|`, `L = (1/|I|)∫_I Lq`, and `W_pred = L/λ` is compared with the *arrival-cohort*
mean wait (cases entering in `I`) and the *departure-cohort* mean wait (cases starting service in `I`).
In a system with rising waits these two cohorts differ substantially, and `L/λ` should track the arrival
cohort; a case where it does not is shown as a counter-example.

**Uncertainty is reported at three separate levels** and never mixed silently: (a) *imputation* bounds
(early/central/late + a non-nested "assistance" variant for P11), (b) *rounding* bands from a Monte-Carlo
de-rounding of every timestamp, (c) *censoring* bounds (observed lower bound vs. projected completion).

# 5. Bottleneck and temporal interpretation

**Evidence (measured, scenario-robust).**

1. *Service asymmetry.* Mean fully observed service is 28.1 min at S1 (n = 18, range 20–30) and 40.0 min
   at S2 (n = 12, range 30–50). Per case, S1 consumes 14.1 server-minutes and S2 20.0 — S2 is ≈1.4×
   slower with the same headcount. This ordering survives every imputation and rounding scenario in §6.
2. *Capacity vs. demand.* Nominal ceilings are 4.3 cases/h (S1) and 3.0 (S2); with the observed 5-min
   handover treated as real, 3.6 and 2.7. Observed throughput was 3.3 /h (S1) and 2.8 /h (S2, from 09:00).
   Arrivals ran at 5.3 /h until 12:10. **Both stations were overloaded**; the demand-capacity gap is the
   primary cause of the growth, and neither station alone "explains" it.
3. *Queue occupancy.* The S1 queue was non-empty for all 360 min; the S2 queue only for 310. C1 reached
   92 % utilisation in the core interval — the single most loaded resource in the log.
4. *The drain experiment (strongest single piece of evidence).* Arrivals stop at 12:10. Between 12:10 and
   14:00 the S1 queue falls 6 → 1 and I2 goes idle at 13:45, while the S2 queue **rises** 3 → 4 with both
   C servers busy and 6 cases in S2 WIP at 14:00. A station that drains when the input stops is not the
   constraint; a station that keeps filling is.
5. *Wait dynamics.* S1 waits plateau at 95–105 min from P14 onward (a queue in quasi-equilibrium with its
   server rate), whereas S2 waits are still climbing at the window edge (65 → 75 → ≥ 85 for the head of
   the queue). Rising-versus-flat is the temporal signature of where the residual overload sits.

**Interpretation, by regime.**

- **08:00–09:10 (ramp).** No bottleneck in any meaningful sense at S2 — it was *starved* for 50 min. S1
  waits nevertheless begin growing immediately because arrivals (7 /h) exceed even S1's ceiling. Sojourn
  times are dominated by service, not queueing (P01: 60 min total, 50 of it work).
- **09:10–10:55 (build-up).** Both stations saturated. S1 owns the visible congestion (queue 4–6, waits
  45–75 min) while the S2 queue holds 1–3. Mechanism: S1 is the *entry gate*, so the S1 queue absorbs the
  backlog of the whole line and physically throttles S2's input to ≈3.3 /h — S2 cannot exhibit a long
  queue while its feeder is slower than its own arrival potential. Reading "longest queue = bottleneck"
  here would be exactly the error the drain experiment refutes.
- **10:55–11:15 (maintenance).** S2 capacity is halved for 15 min. The *effective* gap on C2 is 25 min
  (10:50–11:15, i.e. the outage plus its two shoulder handovers) with three cases queued throughout.
  Consequences: P08's wait jumps to 55 min against a contemporaneous norm of ~25; P10 is rerouted to C1
  and waits 50; the I1→C1 / I2→C2 pairing flips permanently (A10), producing the only apparent FIFO
  violation in the log (P09 served before the longer-waiting P08); the system departure rate in
  11:00–12:00 dips to 2 /h, its lowest non-ramp value.
- **11:15–12:10 (peak).** Total WIP peaks at 13, S1 queue at 7 (11:30). This is the maximum-stress point
  of the window and it is caused by the accumulated demand-capacity gap, not by any single station.
- **12:10–14:00 (drain).** Unambiguously S2. S1 clears its backlog and even idles; S2 finishes 5 cases
  but takes in 6, and at 14:00 has 4 waiting plus 2 in service.

**Conclusion.** The evidence is most consistent with a **time-varying combination in which S2 is the
structural bottleneck and S1 is the visible-queue bottleneck**: S2 has the lower capacity throughout
(hypothesis-free, from service times and the drain experiment), but for 08:00–12:10 the binding
constraint on flow time is the arrival rate exceeding *both* stations, with S1's queue acting as the
system's waiting room. Calling S1 "the bottleneck" from queue length alone, or S2 "fine" from its short
morning queue, would both be wrong.

**Hypotheses (labelled as such, not established).** (H1) A fixed ~5-min changeover exists; if real it
costs each station ≈11 % of capacity and is the cheapest available improvement — but A2 means it may be
a rounding artifact. (H2) The paired routing of A10 and its post-outage swap. (H3) Something ended I2's
availability at 13:45 (P22 unserved while I2 idle) — an undocumented shift boundary or logging lag.
(H4) P11 received undocumented assistance (§6). None of these change the bottleneck ranking.

**Outage accounting.** Nominal loss 15 min = 0.375 of a C2 service. Attributable excess waiting is
≈50–90 case-minutes (P08 ≈ +30, P10 ≈ +25, knock-on to P12 ≈ +20), i.e. 6–12 % of the 780 S2 queue-minutes.
More important than the arithmetic: because S2 stayed saturated to 14:00, the lost capacity was **never
recovered** — every subsequent departure is shifted roughly 15–25 min later. Counter-consideration: C2 also
idled 15 min *after* the outage while cases waited (12:25–12:30, 13:20–13:30), so part of that permanent
shift is attributable to handover/dispatch behaviour rather than to the maintenance itself.

The fourth scenario is the operationally interesting one. P11's C2-only window forces a service ≤ 25 min
against C2's observed 40–50. Three readings: (a) a genuinely short calibration (then C2's service
distribution is bimodal and the S2 capacity estimate improves slightly); (b) a mis-rounded or
late-logged `s2_end` (then P11 tells us nothing); (c) undocumented assistance — another resource began the
calibration around 11:45 and C2 only finished it, making P11's wait ≈40 and its service ≈40, at the cost
of an unrecorded resource and a violation of the two-server capacity assumption. The table shows the
consequence is small in aggregate (mean `Wq2` 39.0 → 38.0, mean `Sv2` 37.5 → 38.9) but decisive for any
statement about C2's service-time distribution.

**Rounding sensitivity** (4000 de-rounding draws, each reported timestamp perturbed independently by
U(−2.5, +2.5) min, central imputation fixed; the 14:00 boundary is exact and not perturbed):
5–95 % bands are I1 busy 294–316 min (ρ 82–88 %), I2 279–300 (78–83 %), C1 285–305 (79–85 %),
C2 257–274 (74–79 % of the 345 available min), mean `Sv1` 27.5–29.0, mean `Sv2` 36.6–38.4. Rounding alone
therefore moves any single utilisation figure by ±3 pp and *cannot* separate S1 from S2 utilisation at the
full-window level — which is why §5 leans on the core interval and the drain experiment instead.

**Censoring scenarios.** Naively averaging only completed observations understates every waiting metric.
For S2 waiting over the 20 entrants: elapsed-value lower bound **39.0** min; observed-only (16 cases) 37.2,
which is *biased downward twice over* (it drops the four longest-waiting cases); projection-based estimate
**48.2** min, from continuing the queue past 14:00 with C1/C2 mean services (C2 frees ≈14:13, C1 ≈14:33)
under FIFO:

| case | wait at 14:00 | projected server | projected start | projected final wait |
|---|---|---|---|---|
| P16 | 85 | C2 | ≈14:13 | ≈98 |
| P18 | 50 | C1 | ≈14:32 | ≈83 |
| P19 | 35 | C2 | ≈15:01 | ≈96 |
| P20 | 15 | C1 | ≈15:17 | ≈93 |

So the four censored waits will very likely land in the 80–100 min band, i.e. *above* every observed S2
wait. Analogously for open services: P21 (S1, elapsed 30) is already at the top of I1's 20–30 range and
should finish ≈14:00–14:05; P15 (C2, elapsed 30) has an expected final ≈43 → end ≈14:13; P17 (C1, elapsed 5)
expected final ≈38 → end ≈14:33. `Wq1`'s mean is almost insensitive to censoring (67.7 → ≈68.4) because only
P22 is affected. Discarding the 8 unfinished cases entirely — the tempting simplification — would drop the
mean case sojourn to 146 min and hide the fact that the last four arrivals will exceed 250 min.

**Stable conclusions** (hold in all four imputation scenarios and across the rounding band):
S2's per-case service exceeds S1's (≥ 34 vs ≤ 29 in every scenario); both stations were saturated with
essentially no starvation after 09:10; S2 is the residual/structural bottleneck and is unambiguously so
after 12:10; mean total WIP ≈ 9–10 with peak 13; S1 mean wait exceeds S2 mean wait (68 vs 39–48);
utilisation is high but not 100 % everywhere (73–88 % window-wide, 84–92 % in the core), so capacity loss
to handovers/gaps is real in every scenario; the C2 outage produced the only visible dip in system
throughput and its cost was never recovered.

**Not stable / weakly identified:** the individual services of P05 (0–30) and P11 (0–25) and hence C1's and
C2's service distributions in 09:45–12:25; whether P11 evidences undocumented assistance; any utilisation
figure to better than ±5 pp; whether the 5-min handover gaps are real changeover or rounding (this alone
swings the capacity estimates by ~11 %); the *size* of the S1–S2 waiting gap (the sign is stable, the
magnitude depends on censoring treatment: 68 vs 39 or 68 vs 48); the final waits of P16/P18/P19/P20, which
depend entirely on unobserved post-14:00 behaviour; and the reason P22 was never started while I2 was idle.

# ------------------------------------------- 4. step functions (queue / WIP)
def step_series(entries, exits, t0=T0, t1=TEND):
    """Right-continuous step count on [t0,t1]. Tie convention: exits before entries.

    The level at t0 is the number already present (entered <= t0, not yet exited), so the
    function is also valid on sub-intervals. Returns
    (time_average, peak_exit_first, peak_entry_first, series).
    """
    entries = [t for t in entries if pd.notna(t)]
    exits = [t for t in exits if pd.notna(t)]
    lvl0 = sum(1 for t in entries if t <= t0) - sum(1 for t in exits if t <= t0)
    ev = [(t, 0, -1) for t in exits if t0 < t <= t1] + [(t, 1, +1) for t in entries if t0 < t <= t1]
    ev.sort(key=lambda x: (x[0], x[1]))
    lvl, area, prev_t, peak_ef, peak_nf, series = lvl0, 0.0, t0, lvl0, lvl0, []
    i = 0
    while i < len(ev):
        t = ev[i][0]
        area += lvl * (t - prev_t).total_seconds() / 60
        # entry-first alternative peak at this instant
        n_entries = sum(1 for e in ev if e[0] == t and e[2] == +1)
        peak_nf = max(peak_nf, lvl + n_entries)
        while i < len(ev) and ev[i][0] == t:
            lvl += ev[i][2]
            peak_ef = max(peak_ef, lvl)
            i += 1
        series.append((t, lvl))
        prev_t = t
    area += lvl * (t1 - prev_t).total_seconds() / 60
    return area / ((t1 - t0).total_seconds() / 60), peak_ef, max(peak_nf, peak_ef), series


def busy_minutes(station, scen, t0=T0, t1=TEND):
    """Busy minutes per resource inside [t0,t1], OPEN work clipped at t1."""
    f = frames[scen]
    out = {}
    for case, r in df.iterrows():
        res = r[f"s{station}_res"]
        if res is None:
            continue
        s = f.loc[case, f"S{station}_start"]
        e = r[f"s{station}_end"]
        if pd.isna(s):
            continue
        e = t1 if pd.isna(e) else e
        ov = (min(e, t1) - max(s, t0)).total_seconds() / 60
        if ov > 0:
            out[res] = out.get(res, 0.0) + ov
    return out

def rate_table(bins):
    out = []
    for a, b in bins:
        ta, tb = pd.Timestamp(f"{DAY} {a}"), pd.Timestamp(f"{DAY} {b}")
        m = (tb - ta).total_seconds() / 60

            s = df[col]

            "interval": f"{a[:5]}-{b[:5]}", "min": m,
            "ext_arrivals": n("arrival"), "S1_completions": n("s1_end"), "S2_completions": n("s2_end"),

            "S2_thr_per_h": round(n("s2_end") * 60 / m, 2),
        })
    return pd.DataFrame(out)

# ------------------------------------------- 8. Little's law on a balanced interval
def little(station, a, b):
    ta, tb = pd.Timestamp(f"{DAY} {a}"), pd.Timestamp(f"{DAY} {b}")
    ent = pd.Series([cen.loc[c, f"S{station}_qentry"] for c in cen.index], index=cen.index)
    ext = pd.Series([cen.loc[c, f"S{station}_start"] for c in cen.index], index=cen.index)
    lvl_a = int(((ent <= ta) & ~(ext <= ta)).sum())
    lvl_b = int(((ent <= tb) & ~(ext <= tb)).sum())
    nin = int(((ent > ta) & (ent <= tb)).sum())
    nout = int(((ext > ta) & (ext <= tb)).sum())
    L = step_series(ent, ext, ta, tb)[0]
    lam = nin / ((tb - ta).total_seconds() / 60)
    coh_arr = cen.loc[(ent > ta) & (ent <= tb), f"S{station}_wait"].mean()
    coh_dep = cen.loc[(ext > ta) & (ext <= tb), f"S{station}_wait"].mean()
    return {"station": f"S{station}", "interval": f"{a}-{b}", "L_start": lvl_a, "L_end": lvl_b,
            "entries": nin, "exits": nout, "mean_L": round(L, 2), "lambda_per_min": round(lam, 4),
            "W_from_L_over_lambda": round(L / lam, 1),
            "W_arrival_cohort": round(coh_arr, 1), "W_departure_cohort": round(coh_dep, 1)}


print("\n=== 8. Little's law: only on intervals with balanced flow & equal end-point queue ===")
print(pd.DataFrame([little(1, "10:00", "12:00"), little(2, "11:15", "12:30"),
                    little(2, "08:00", "09:05"), little(2, "10:00", "13:00")]).to_string(index=False))
print("(last row is a deliberate counter-example: queue grows 2->4, entries 10 vs exits 8, so"
      " L/lambda is NOT a valid W and the arrival/departure cohorts disagree)")

# Rounding-only Monte Carlo: every reported timestamp is perturbed independently by
# U(-2.5,+2.5) min (de-rounding). Order constraints are not re-imposed, so this is a
# deliberately conservative width for aggregates.
rng = np.random.default_rng(7)
ivs = []   # (resource, start, end, station) for the central scenario, OPEN clipped at 14:00
for case, r in df.iterrows():
    for st in (1, 2):
        s = cen.loc[case, f"S{st}_start"]
        if pd.isna(s):
            continue
        e = r[f"s{st}_end"]
        ivs.append((r[f"s{st}_res"], s, TEND if pd.isna(e) else e, st, pd.isna(e)))
mc = []
for _ in range(4000):
    busy, svc = {}, {1: [], 2: []}
    for res, s, e, st, open_flag in ivs:
        ds = rng.uniform(-HALF, HALF)
        de = 0.0 if open_flag else rng.uniform(-HALF, HALF)   # 14:00 boundary is not rounded
        d = (e - s).total_seconds() / 60 + de - ds
        busy[res] = busy.get(res, 0.0) + d
        if not open_flag:
            svc[st].append(d)
    mc.append({"I1_busy": busy["I1"], "I2_busy": busy["I2"], "C1_busy": busy["C1"],
               "C2_busy": busy["C2"], "S1_svc_mean": np.mean(svc[1]), "S2_svc_mean": np.mean(svc[2])})
