## 2. Raw-versus-normalized interpretation

The raw-versus-mapped fitness gap is large and informative. In March raw fitness falls from 0.93 to 0.55 while mapped fitness is 0.90; the mapping recovers 0.35 points, about 78% of the maximum possible recovery. April shows a similar pattern. This implies that the March conformance collapse is mostly a label/schema and duplicate-event artifact: `Eligibility Screen` is a renamed `Validate Eligibility`, and duplicated `Open Case` events create false traces. It does not imply the business process was unchanged. A mapping can restore conformance by imposing an assumed equivalence; it cannot detect a real routing change hidden inside the renamed activity, nor repair missing resources, duplicate case openings, or new variants. It also cannot prove that the underlying work remained identical.

Duplicated technical events inflate trace length, create spurious variants and rework, and distort DFG counts and conformance. Missing resources are concentrated in migrated activities, so resource-level performance and conformance analyses become biased and team attribution is unreliable.

The post-May patterns cannot be dismissed as logging drift alone. After normalization, mapped fitness remains below baseline (0.86–0.90 vs 0.925), the `Assess -> Request Info -> Collect Documents` loop roughly doubles, the decision rate falls, rework variant share doubles, supplier Z share jumps from 16% to 43%, and p90 cycle time rises from 68 to 116–121 hours. Meanwhile Assess service time changes only modestly, while queue waiting rises substantially. These are business-process and performance signals, not merely label noise.

### 3.5 One global change point or multiple mechanism-specific change points?

The data support multiple mechanism-specific change points, not one global change point. March is primarily a logging/semantic event. May is primarily a supplier-driven behavioral/rework event. June is primarily a staffing-driven queueing event. July adds a priority-policy redistribution. October adds seasonal population/case-mix drift and possibly improved `Senior Assessment` recording. December is a mixed intervention/seasonal recovery. A single global change point would incorrectly attribute the March label split to later rework and queueing, or incorrectly attribute the May–November performance drift to the March migration.

## 6. Segmentation plan

| segment level | variables | purpose | minimum support rule | comparisons enabled | risk of conditioning bias |
|---|---|---|---|---|---|
| Global monthly | Month only | Overall drift monitoring | 300 cases/month | Baseline vs current | Masks subgroup redistribution |
| Phase/period | Pre-migration, migration, supplier, staffing/priority, seasonal, intervention | Align with change points | 100 cases per period cell | Pre/post each event | Period confounds multiple mechanisms |
| Supplier | Supplier Z vs non-Z | Isolate supplier disruption | 30 cases per supplier per month or 100 per quarter | Supplier-specific DFG, rework, cycle | Supplier subset non-random; case mix |
| Complexity/priority | High vs standard complexity; priority vs standard | Isolate case mix and priority redistribution | 50 cases per cell per month or 150 per quarter | Waiting time, senior assessment, variants | Complexity and priority correlated; conditioning on post-treatment variable |
| Resource/team | Team/resource ID | Isolate staffing/resource drift | 30 cases per team per month or 100 per quarter | Queue, service, missingness | Missing resources; redistribution; small cells |
| Schema version | Pre/post migration; raw vs mapped labels | Isolate logging drift | 100 cases per schema period | Raw vs mapped fitness, DFG | Mapping assumptions |
| Outcome | Approve/reject | Outcome-specific drift | 50 cases per outcome per month | Outcome-specific DFG, rework | Outcome is downstream; conditioning bias |
| Cross-cut optional | Supplier × complexity | Interaction detection | 30 cases per cell per quarter; otherwise suppress | Supplier-specific complexity effects | Tiny cells; overaggregation |

Primary monitoring population: schema-normalized, deduplicated cases with non-missing resource, supplier, complexity, and priority fields. This removes known March logging artifacts while preserving business-process signal. Always report coverage and compare against the all-case population to detect selection bias; monitor raw/unmapped and missing-resource cases separately as data-quality segments.

Seasonality is handled with same-month-prior-year or seasonal-index reference windows, control-chart thresholds with 2–3 sigma, and alert persistence over two consecutive periods. Multiple testing is handled by using monitor-specific thresholds, requiring persistence, and applying Benjamini–Hochberg false-discovery-rate control across the monitor portfolio. No universal threshold is used.

def month_windows(start, end):
    start = pd.to_datetime(start)
    end = pd.to_datetime(end)
    first_month_start = start.to_period("M").to_timestamp()
    month_starts = pd.date_range(start=first_month_start, end=end, freq="MS")
    windows = []
    for ms in month_starts:
        window_start = max(start, ms)
        window_end = ms + pd.DateOffset(months=1)
        if window_end > end:
            window_end = end
        if window_start >= window_end:
            continue
        windows.append(
            (
                window_start.strftime("%Y-%m-%d %H:%M:%S"),
                window_end.strftime("%Y-%m-%d %H:%M:%S"),
            )
        )
    return windows


def slice_time_window(log, start, end):
    _require_pm4py()
    return pm4py.filter_time_range(log, timest_start=start, timest_end=end)


def _unpack_dfg(discovered):
    if isinstance(discovered, tuple) and len(discovered) == 3:
        return discovered
    return discovered, None, None


def monthly_dfg(
    log,
    start,
    end,
    activity_key="concept:name",
    case_id_key="case:concept:name",
    timestamp_key="time:timestamp",
):
    _require_pm4py()
    result = {}
    for window_start, window_end in month_windows(start, end):
        sublog = pm4py.filter_time_range(log, timest_start=window_start, timest_end=window_end)
        if len(sublog) == 0:
            continue
        discovered = pm4py.discover_dfg(
            sublog,
            activity_key=activity_key,
            case_id_key=case_id_key,
            timestamp_key=timestamp_key,
        )
        dfg, start_activities, end_activities = _unpack_dfg(discovered)
        result[window_start[:7]] = {
            "dfg": dfg,
            "start_activities": start_activities,
            "end_activities": end_activities,
            "cases": len(sublog),
        }
    return result

def normalize_labels(log, mapping, activity_key="concept:name"):
    normalized = copy.deepcopy(log)
    for trace in normalized:
        for event in trace:
            if event[activity_key] in mapping:
                event[activity_key] = mapping[event[activity_key]]
    return normalized


def remove_duplicate_open_case(log, activity="Open Case", activity_key="concept:name"):
    cleaned = copy.deepcopy(log)
    for trace in cleaned:
        seen = False
        kept = []
        for event in trace:
            if event[activity_key] == activity:
                if seen:
                    continue
                seen = True
            kept.append(event)
        trace[:] = kept
    return cleaned

## 9. Provisional attribution

Strongest attribution: March is predominantly logging/semantic drift. The raw fitness collapse is almost fully recovered by mapping `Eligibility Screen` to `Validate Eligibility` and removing duplicate `Open Case` events; normalized DFG rates are nearly unchanged. Confidence high. May is predominantly supplier-driven behavioral rework. Supplier Z share jumps from 16% to 43%, rework variant share rises from 13% to 24%, and the `Assess -> Request Info -> Collect Documents` loop doubles; this is unlikely to be only case mix because the loop rate itself rises. Confidence high. June is predominantly staffing-driven queueing. Four assessors left, median and p90 cycle times rise sharply, while Assess service time changes only modestly and queue waiting before Assess increases substantially. Confidence high.

Plausible but less certain: July priority rule redistributes delay. Aggregate median worsens, but the additional observation says high-complexity cases may wait less while standard cases wait more; without segmented waiting times, this is plausible, not proven. October is a mixed seasonal population and possible logging/semantic change: renewal volume and high-complexity share rise sharply, and Senior Assessment recording jumps from 9 to 22 per 100 cases; because senior assessment was historically inconsistent, part of that jump may be improved recording. December improvement is mixed: overtime and document-quality campaign coincide with lower seasonal load and supplier recovery, so attribution to interventions is only plausible.

Mediation and interaction prevent clean attribution: Supplier Z serves a non-random, somewhat more complex subset; staffing cuts amplify supplier rework; the priority rule changes queueing by complexity; seasonality increases both volume and complexity. These mechanisms are stacked, so aggregate month-level changes are not additive.

I would revise the account if event-level data showed supplier-specific DFGs with no non-Z rework increase, if complexity/priority-segmented waiting times showed no redistribution, if prior-year seasonal baselines showed October-November is normal, or if missing-resource cases differ materially from complete cases.

## 10. Monitoring decision rules

1. IF raw fitness drops >10 pp while mapped fitness recovers >80% of the gap and label frequencies show `Eligibility Screen` replacing `Validate Eligibility` plus duplicate `Open Case`/missing-resource increases, THEN treat as logging/semantic drift, open a data-engineering investigation, and do not trigger operational escalation, BECAUSE the conformance collapse is explained by schema/provenance artifacts rather than business routing.

2. IF mapped fitness remains >2 pp below baseline after normalization and the rework-loop rate rises >5 pp, THEN investigate behavioral drift and supplier/document quality, BECAUSE normalization removes known logging artifacts but residual nonconformance indicates real process change.

3. IF Supplier Z rework variant and `Assess -> Request Info -> Collect Documents` loop rates rise sharply while non-Z rates remain stable, THEN escalate the Supplier Z document-quality issue and consider supplier-specific SLA or quarantine actions, BECAUSE the pattern localizes a supplier-driven behavioral mechanism.

4. IF queue waiting before `Assess` rises while `Assess` service time remains within ±10% of baseline and assessor capacity falls, THEN investigate staffing/resource drift and rebalance capacity, BECAUSE the evidence indicates queueing rather than service productivity.

5. IF high-complexity waiting falls but standard-case waiting rises after a priority-rule change while aggregate median worsens, THEN audit priority-rule redistribution and segment by priority class, BECAUSE aggregate cycle time can mask opposite movements in subpopulations.

6. IF volume and high-complexity share rise in October–November relative to a seasonal reference and senior-assessment rate jumps, THEN activate the seasonal capacity plan and validate `Senior Assessment` recording, BECAUSE renewal season changes population/case mix and may also improve label consistency.

7. IF cycle time and rework improve after the overtime/document-quality campaign but also after seasonal load falls, THEN do not attribute recovery solely to interventions; run difference-in-differences or interrupted time series against a seasonal baseline before claiming success, BECAUSE December improvement is confounded by seasonality and supplier recovery.
