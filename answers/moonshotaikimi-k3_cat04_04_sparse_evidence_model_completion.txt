from pm4py.objects.process_tree.obj import Operator

A_SUP="Supplier Confirmation"; A_EXP="Expedite Review"
A_APP="Approve Configuration"; A_REL="Release Production"; A_ARC="Archive Case"

def opt(label):
    return OperatorPOWL(Operator.XOR, [Transition(label=label), SilentTransition()])

def seq_po(nodes):
    po = StrictPartialOrder(list(nodes))
    for a, b in zip(nodes, nodes[1:]):
        po.order.add_edge(a, b)
    return po

**Why both DFG directions do not prove concurrency.** The edges (C,E)=17 and (E,C)=11 only show that both completion orders occur across cases. Under completion-only semantics (D7), four generative processes produce exactly this pattern: (a) true concurrent execution; (b) a case-level XOR between two sequential procedures; (c) free choice resolved by resource availability; (d) timestamp granularity with ingestion-index tie-breaking (S7). Indeed, for two activities occurring at most once, the parallel split AND(C,E) and the choice XOR((C,E), (E,C)) have *identical languages* {CE, EC} — they are indistinguishable from this log by construction. Only interval timestamps (start+complete) showing overlap, or an explicit dependency attribute, can separate (a) from (b)–(c).

**Quantitative note on S absence.** 7/30  23% of cases lack S, versus S5's 5–10% event-loss estimate. If S were truly mandatory and absences were pure loss, one would expect 1.5–3 absent-S cases; observing 7 has binomial tail probability 0.2% (p=0.05) to 5% (p=0.10). Conversely, solving q·(1p_loss)=23/30 for the true external fraction q gives q81–85%, implying 1.2–2.6 of the 7 absences are losses and 5–6 are genuine skips. Conclusion: genuine optionality very likely exists, but per-case attribution is impossible without the attribute.

# 2. Shared Assumptions

1. **Event-completion semantics.** Each logged event marks activity completion. "a directly followed by b" means a's completion was recorded before b's; it implies neither causation nor non-overlap of execution (D7, S7).
2. **Single occurrence.** Every activity occurs at most once per case (30/30 traces). No loops or rework are modeled by any candidate.
3. **Closed alphabet.** Only the eight listed activities exist.
4. **Hard backbone.** R is the unique start, Z the unique end (D1); A immediately precedes P in the control flow (D2); C and E both precede A (D3); S, when present, precedes A (D4); X is optional, 1, after CE, before A (D6, S6). All three candidates share these.
5. **Missing Supplier Confirmation.** The XOR skip branch for S is an *abstraction that conflates two different realities*: "S not required" (stocked, S4) and "S required but event lost" (S5). No candidate can separate them; this is disclosed wherever the branch appears.
6. **Absent external/stocked attribute.** Because the discriminating attribute was not exported (S5), optionality is modeled *unconditionally* — an over-approximation: any case may skip S, not only stocked ones.
7. **Optionality encoding.** Optionality is represented as XOR with a silent transition , never as a data condition or a loop.
8. **S1 is not encoded.** Finance's claim is contradicted by 11/30 traces; data overrides testimony for descriptive models. It is retained as a compliance question, not a constraint.

# 3. Conservative Candidate

**Inductive bias.** *The log is the population.* This model memorizes: it admits exactly the seven observed words and nothing else. It trusts high-confidence rules only to the extent they are already instantiated in the data, refuses to operationalize stakeholder generalizations (S2's parallelism, D5's mechanism), and prefers false rejections over false acceptances. It is the high-bias/low-variance hypothesis: maximally safe against admitting unsupported behavior, maximally brittle to process drift and data loss.

**Compact formal expression.**

L_cons = { w1..w7 } (the seven observed words), i.e. a process tree ×( (w1), …, (w7) ). |L_cons| = 7.

# 4. Balanced Candidate

**Inductive bias.** *Generalize only along axes jointly licensed by data and domain rules, and commit to the weakest structure that explains the observations.* Where evidence cannot distinguish concurrency from case-dependent order choice, the model asserts neither — it asserts a partial order (a set of permitted orders). Epistemic gaps (missing S events) are represented explicitly as  choices and disclosed, not smoothed away. Testimony contradicted by data (S1) is dropped; testimony consistent with data (S2, S6) may license, but never force, structure.

**How each ordering decision is made.**

- **C vs E  unordered (no edge).** Both orders are frequent (17 vs 11); no high/medium rule fixes the order; S1 is empirically refuted. A sequence would destroy fitness on 11/30 cases. Between AND-split and partial order: with completion-only events and single occurrences they are language-equivalent, so the partial order is chosen because it is the *weaker claim* — it does not assert unobservable execution overlap (D7). Upgrade to AND only if start-timestamps later show overlap.
- **S vs {C,E}  disjunctive precedence.** V5 proves S need not wait for both checks (a strict join would underfit); 0/23 S-traces show S before *both* checks, and D5 supplies the mechanism ("after either has produced enough information"). A single partial order cannot express "at least one predecessor", so the core is an XOR of two partial orders: PO1 with CS, PO2 with ES. This admits the symmetric unobserved case E,S,C — a principled, D5-licensed generalization — while still forbidding S-first.
- **X  optional node with edges CX, EX, no edge to S.** D6/S6 fix the lower bounds; V6 and V7 show both relative orders to S, so none is imposed.
- **A  after the whole core; P, Z  sequence tail** (D2–D4).

**Compact formal expression.**

( R, ×( PO({C,E,S^?,X^?}, {CS, CX, EX}), PO({C,E,S^?,X^?}, {ES, CX, EX}) ), A, P, Z ), where (·)^? = ×(·, ). |L_bal| = 14 words (7 observed + 7 licensed unobserved); L_cons  L_bal.

**Code.**

import pm4py
from pm4py.objects.powl.obj import (StrictPartialOrder, OperatorPOWL,
                                    Transition, SilentTransition)
from pm4py.objects.process_tree.obj import Operator

R, C, E = "Register Order", "Credit Check", "Engineering Review"
S, X = "Supplier Confirmation", "Expedite Review"
A, P, Z = "Approve Configuration", "Release Production", "Archive Case"

def opt(label):  # optional activity = XOR with silent transition ()
    return OperatorPOWL(Operator.XOR, [Transition(label=label), SilentTransition()])

def chain(nodes):  # sequence encoded as a total partial order
    po = StrictPartialOrder(list(nodes))
    for u, v in zip(nodes, nodes[1:]):
        po.order.add_edge(u, v)
    return po

# Branch 1: Supplier Confirmation requires Credit Check (Engineering Review free) — D5 left disjunct
c1, e1, s1, x1 = Transition(label=C), Transition(label=E), opt(S), opt(X)
po1 = StrictPartialOrder([c1, e1, s1, x1])
po1.order.add_edge(c1, s1)          # D5
po1.order.add_edge(c1, x1)          # D6
po1.order.add_edge(e1, x1)          # D6

# Branch 2: Supplier Confirmation requires Engineering Review (Credit Check free) — D5 right disjunct
c2, e2, s2, x2 = Transition(label=C), Transition(label=E), opt(S), opt(X)
po2 = StrictPartialOrder([c2, e2, s2, x2])
po2.order.add_edge(e2, s2)          # D5
po2.order.add_edge(c2, x2)          # D6
po2.order.add_edge(e2, x2)          # D6

core = OperatorPOWL(Operator.XOR, [po1, po2])
model_balanced = chain([Transition(label=R), core, Transition(label=A),
                        Transition(label=P), Transition(label=Z)])
```

**Cost disclosure.** The XOR-of-POs encoding duplicates the labels C, E, S, X across the two branches (POWL has no OR-join). Alignments remain correct on labels, but diagnostics cannot say which branch fired, and alignment-based precision is mildly distorted. Mitigation if this matters: collapse to a single partial order and accept S-first over-generalization (i.e., move toward the permissive candidate).

**Behavior deliberately excluded.** S before both checks (S-first words); X before either check or after A; S after A; skipping C or E; any duplicate activity; anything outside the alphabet.

**Known underfitting risks.** (i) If rush orders legitimately confirm suppliers before either check (D5 merely descriptive), those cases are rejected. (ii) If X can occur without both checks in emergencies, excluded. (iii) If S is sometimes required-but-skipped (non-compliance), the  branch waves it through — a missingness/optionality conflation, not detectable here. (iv) The unobserved symmetric pattern E,S,C is admitted on D5's authority alone; if future data never produces it, the model is slightly over-general, not underfit.

def opt(label):
    return OperatorPOWL(Operator.XOR, [Transition(label=label), SilentTransition()])

c, e, s, x = Transition(label=C), Transition(label=E), opt(S), opt(X)
core = StrictPartialOrder([c, e, s, x])
core.order.add_edge(c, x)   # D6: Expedite Review needs Credit Check
core.order.add_edge(e, x)   # D6: Expedite Review needs Engineering Review
# deliberately NO edges into s: D5 is treated as descriptive, not normative

tail = StrictPartialOrder([Transition(label=R), core, Transition(label=A),
                           Transition(label=P), Transition(label=Z)])
for u, v in [(0, 1), (1, 2), (2, 3), (3, 4)]:
    tail.order.add_edge(tail.children[v - 1] if False else [tail.order][0] and None, None) if False else None
# (chain edges added explicitly below for clarity)
tail = StrictPartialOrder([Transition(label=R), core, Transition(label=A),
                           Transition(label=P), Transition(label=Z)])
_nodes = list(tail.children)
for _u, _v in zip(_nodes, _nodes[1:]):
    tail.order.add_edge(_u, _v)

model_permissive = tail
```

(A process tree could express this only by duplicating X across interleaving branches to encode "X after CE"; the POWL partial order is the natural sound representation, which is why two of three candidates are POWL.)

**Boundary: reasonable generalization vs. forbidden.** *Admitted* (reasonable): any interleaving of the core satisfying the edges — including S-first words, X without S, and all licensed reorderings. *Forbidden* (hard boundary): (i) any event before R or after Z (D1); (ii) P without preceding A (D2); (iii) A before C or E completes (D3); (iv) S after A (D4); (v) X before C or E, X after A, or two X's (D6); (vi) missing or duplicated mandatory activities R, C, E, A, P, Z; (vii) unknown labels. Relaxing D5 is defensible only under the timestamp-noise reading; if D5 is promoted to a hard rule, this candidate collapses to the balanced one.

**Behavior deliberately excluded.** Everything on the forbidden list above — in particular: approval without both checks, release before approval, expedite before both checks, supplier confirmation after approval, any rework/loop.

**Known underfitting risks.** Residual only: real rework loops (e.g., repeated engineering review), corrective S after A, and multi-round expediting remain excluded. The dominant risk is the opposite: **over-generalization that masks non-compliance** — a case that *should* have had S but skipped it is indistinguishable from a legitimate stocked skip, and S-first words may legitimize premature supplier commitments.

# 8. Validation Code

```python
"""
Section 8 — validation harness (self-contained).
Rebuilds the 30-case log, rebuilds all three candidates (identical to §§3–5),
converts to Petri nets, checks soundness, computes metrics, samples playout,
and runs a positive/negative trace suite.
Because every candidate is acyclic (each activity <= 1 per case), all languages
are FINITE; we therefore enumerate them exactly. Sampled playout is used only
as a net-level sanity check — it is NOT a proof of language inclusion.
"""
import itertools
import pm4py
from pm4py.objects.process_tree.obj import ProcessTree, Operator
from pm4py.objects.powl.obj import (StrictPartialOrder, OperatorPOWL,
                                    Transition, SilentTransition)

R, C, E = "Register Order", "Credit Check", "Engineering Review"
S, X = "Supplier Confirmation", "Expedite Review"
A, P, Z = "Approve Configuration", "Release Production", "Archive Case"

# ---------- 1. reconstruct the 30-case log ----------
VARIANTS = [
    (12, (R, C, E, S, A, P, Z)),
    (7,  (R, E, C, S, A, P, Z)),
    (4,  (R, C, E, A, P, Z)),
    (3,  (R, E, C, A, P, Z)),
    (2,  (R, C, S, E, A, P, Z)),
    (1,  (R, C, E, S, X, A, P, Z)),
    (1,  (R, E, C, X, S, A, P, Z)),
]
trace_strings = [", ".join(v) for n, v in VARIANTS for _ in range(n)]
assert len(trace_strings) == 30

try:
    log = pm4py.parse_event_log_string(trace_strings)
except Exception:  # fallback: manual EventLog construction
    from pm4py.objects.log.obj import EventLog, Trace, Event
    log = EventLog()
    for i, s_ in enumerate(trace_strings):
        tr = Trace(attributes={"concept:name": f"case-{i:02d}"})
        for act in s_.split(", "):
            tr.append(Event({"concept:name": act}))
        log.append(tr)

# cross-check reconstruction against the provided frequency DFG
EXPECTED_DFG = {
    (R, C): 19, (R, E): 11, (C, E): 17, (E, C): 11, (C, S): 9, (E, S): 13,
    (S, E): 2, (E, A): 6, (C, A): 3, (S, A): 20, (S, X): 1, (C, X): 1,
    (X, S): 1, (X, A): 1, (A, P): 30, (P, Z): 30,
}
try:
    dfg, starts, ends = pm4py.discover_dfg(log)
    assert dict(dfg) == EXPECTED_DFG and dict(starts) == {R: 30} and dict(ends) == {Z: 30}
    print("[ok] reconstructed log reproduces the provided DFG exactly")
except Exception as ex:
    print("[warn] DFG cross-check skipped/failed:", repr(ex))

# ---------- 2. rebuild the three candidates (same code as §§3–5) ----------
def build_conservative():
    def seq(labels):
        node = ProcessTree(operator=Operator.SEQUENCE)
        for lb in labels:
            leaf = ProcessTree(label=lb); leaf.parent = node; node.children.append(leaf)
        return node
    root = ProcessTree(operator=Operator.XOR)
    for _, v in VARIANTS:
        ch = seq(v); ch.parent = root; root.children.append(ch)
    return root

def _opt(label):
    return OperatorPOWL(Operator.XOR, [Transition(label=label), SilentTransition()])

def _chain(nodes):
    po = StrictPartialOrder(list(nodes))
    for u, v in zip(nodes, nodes[1:]):
        po.order.add_edge(u, v)
    return po

def build_balanced():
    c1, e1, s1, x1 = Transition(label=C), Transition(label=E), _opt(S), _opt(X)
    po1 = StrictPartialOrder([c1, e1, s1, x1])
    po1.order.add_edge(c1, s1); po1.order.add_edge(c1, x1); po1.order.add_edge(e1, x1)
    c2, e2, s2, x2 = Transition(label=C), Transition(label=E), _opt(S), _opt(X)
    po2 = StrictPartialOrder([c2, e2, s2, x2])
    po2.order.add_edge(e2, s2); po2.order.add_edge(c2, x2); po2.order.add_edge(e2, x2)
    core = OperatorPOWL(Operator.XOR, [po1, po2])
    return _chain([Transition(label=R), core, Transition(label=A),
                   Transition(label=P), Transition(label=Z)])

def build_permissive():
    c, e, s, x = Transition(label=C), Transition(label=E), _opt(S), _opt(X)
    core = StrictPartialOrder([c, e, s, x])
    core.order.add_edge(c, x); core.order.add_edge(e, x)
    return _chain([Transition(label=R), core, Transition(label=A),
                   Transition(label=P), Transition(label=Z)])

model_conservative = build_conservative()
model_balanced = build_balanced()
model_permissive = build_permissive()

# ---------- exact finite languages (exhaustive comparison IS possible here) ----------
def enumerate_core(s_first_allowed):
    words = set()
    for has_s in (False, True):
        for has_x in (False, True):
            acts = [C, E] + ([S] if has_s else []) + ([X] if has_x else [])
            for p in itertools.permutations(acts):
                if has_x and (p.index(X) < p.index(C) or p.index(X) < p.index(E)):
                    continue                                   # D6
                if (has_s and not s_first_allowed
                        and p.index(S) < p.index(C) and p.index(S) < p.index(E)):
                    continue                                   # D5 (balanced only)
                words.add((R,) + p + (A, P, Z))
    return words

L_CONS = {v for _, v in VARIANTS}
L_BAL, L_PERM = enumerate_core(False), enumerate_core(True)
assert L_CONS < L_BAL < L_PERM
print(f"[languages] |cons|={len(L_CONS)} |bal|={len(L_BAL)} |perm|={len(L_PERM)}")
assert all(w in L_BAL for w in L_CONS)   # fitness precondition, net-independent

# ---------- 3. convert to accepting Petri nets ----------
def to_net(model):
    try:
        return pm4py.convert_to_petri_net(model)
    except Exception:  # older pm4py: explicit POWL converter
        from pm4py.objects.conversion.powl.converter import apply as powl_to_net
        return powl_to_net(model)

NETS = {"conservative": to_net(model_conservative),
        "balanced": to_net(model_balanced),
        "permissive": to_net(model_permissive)}

# ---------- 4. soundness ----------
for name, (net, im, fm) in NETS.items():
    try:
        ok = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
    except TypeError:
        ok = pm4py.check_soundness(net, im, fm)
    print(f"[soundness] {name}: {ok}")   # expected True for all three

# ---------- 5. metrics ----------
# Caveats: alignment-based precision is approximate when labels are duplicated
# (conservative: 7x each label; balanced: 2x C/E/S/X). Metric APIs vary by version.
for name, (net, im, fm) in NETS.items():
    row = {}
    try:
        fit = pm4py.fitness_alignments(log, net, im, fm)
        row["fitness"] = fit.get("log_fitness", fit.get("averageFitness"))
        row["pct_fitting"] = fit.get("percentage_of_fitting_traces")
    except Exception as ex:
        row["fitness"] = f"unavailable ({type(ex).__name__})"
    for key, fn, args in [
        ("precision", pm4py.precision_alignments, (log, net, im, fm)),
        ("generalization", pm4py.generalization_tbr, (log, net, im, fm)),
        ("simplicity", pm4py.simplicity_petri_net, (net, im, fm)),
    ]:
        try:
            row[key] = fn(*args)
        except Exception as ex:
            row[key] = f"unavailable ({type(ex).__name__})"
    print(f"[metrics] {name}: {row}")

# ---------- 6. sampled playout (sanity check only) ----------
LANG = {"conservative": L_CONS, "balanced": L_BAL, "permissive": L_PERM}
def words_of(lg):
    return {tuple(e["concept:name"] for e in t) for t in lg}

for name, (net, im, fm) in NETS.items():
    try:
        sim = pm4py.play_out(net, im, fm, parameters={"num_traces": 25})
    except Exception:
        sim = pm4py.play_out(net, im, fm)
    sampled = words_of(sim)
    print(f"[playout] {name}: {len(sampled)} distinct sampled words; "
          f"{len(sampled - LANG[name])} outside the enumerated language")
    # NOTE: sampling cannot prove language inclusion. Inclusion here is decided
    # EXACTLY via the enumerated finite languages above. For loop-containing
    # (infinite-language) models, neither enumeration nor playout would suffice;
    # a bounded reachability graph (pm4py.convert_to_reachability_graph) would
    # only extend the decidable frontier, not close it.

# ---------- 7. positive / negative trace suite ----------
def trace_fits(net, im, fm, word):
    tl = pm4py.parse_event_log_string([", ".join(word)])
    r = pm4py.fitness_alignments(tl, net, im, fm)
    return r.get("log_fitness", r.get("averageFitness", 0.0)) >= 1.0 - 1e-9

POSITIVE = {
    "conservative": [(R, E, C, S, A, P, Z), (R, C, S, E, A, P, Z), (R, E, C, X, S, A, P, Z)],
    "balanced":     [(R, E, S, C, A, P, Z), (R, C, E, X, A, P, Z), (R, C, E, X, S, A, P, Z)],
    "permissive":   [(R, S, C, E, A, P, Z), (R, S, E, C, X, A, P, Z), (R, E, S, C, A, P, Z)],
}
NEGATIVE_ALL = [                        # must be rejected by EVERY candidate
    (R, C, A, E, S, P, Z),              # D3: approval before Engineering Review
    (R, C, E, A, S, P, Z),              # D4: Supplier Confirmation after approval
    (R, C, E, S, P, A, Z),              # D2: release before approval
    (R, E, X, C, S, A, P, Z),           # D6: expedite before Credit Check
    (R, C, E, S, X, X, A, P, Z),        # D6: expedite twice
    (C, E, S, A, P, Z),                 # D1: no registration
]
NEGATIVE_EXTRA = {
    "conservative": [(R, E, S, C, A, P, Z), (R, C, E, X, A, P, Z)],  # unobserved words
    "balanced":     [(R, S, C, E, A, P, Z), (R, S, E, C, X, A, P, Z)],  # S-first (D5)
    "permissive":   [],
}
for name, (net, im, fm) in NETS.items():
    for w in POSITIVE[name]:
        assert trace_fits(net, im, fm, w), (name, "FALSE REJECTION", w)
    for w in NEGATIVE_ALL + NEGATIVE_EXTRA[name]:
        assert not trace_fits(net, im, fm, w), (name, "FALSE ACCEPTANCE", w)
    print(f"[suite] {name}: all positive/negative checks passed")
```

# 9. Recommendation and Data-Collection Plan

**Immediate use: `model_balanced`.** It is the only candidate that (a) replays all 30 cases, (b) encodes every medium+ confidence rule as inspectable structure, (c) generalizes only where data *and* rules jointly license it, and (d) absorbs S-event loss without hiding that it does so. Its duplicate-label cost is a metric nuisance, not a behavioral one.

**Sensitivity analysis: `model_permissive`.** It bounds the cost of relaxing D5. Operationally: run future logs against both; traces accepted only by the permissive model are exactly the D5-violating (S-first) population — if that population stays empty, the balanced model's disjunctive precedence is empirically confirmed; if it grows, promote the relaxation. Keep `model_conservative` as the audit floor for forensic replay ("has this exact variant ever been seen?").

**Data-collection plan (in priority order):**
1. **Export the external/stocked attribute** (per order, ideally per component from the BOM). This single field resolves the S3/S4 conflict and attributes each absent-S case to skip vs. loss.
2. **Lifecycle start + complete timestamps** for C, E, S, X. Interval overlap is the only decisive evidence for true concurrency (D7); it also enables duration-based explanations of completion order.
3. **Repair the S integration** and reconcile event counts against the procurement system of record; add `event_source`/`ingestion_id` fields so loss can be detected rather than assumed (calibrates S5's 5–10%).
4. **Record the Expedite Review trigger** (requester, reason code) to validate D6 and explain its rarity.
5. **Monotonic sequence numbers / higher-resolution timestamps** to eliminate ingestion-index ordering (S7).
6. **Case attributes** (customer segment, order value, product family) to test whether C/E order is a data-driven choice rather than concurrency.

**Maximally informative future traces:** (i) any case with overlapping C/E intervals — directly decides concurrency vs. sequential choice; (ii) E,S,C (S after E only) — a few occurrences confirm D5's symmetry (balanced); persistent absence over a large sample justifies tightening to the C-based disjunct only; (iii) an S-first case — falsifies the balanced model outright; (iv) an external-flagged case with no S event — direct measurement of the loss rate; (v) X without S — tests the presumed independence; (vi) even a single A-without-E case — would demote D3 from hard rule to tendency and force all three candidates to be rebuilt.

| C and E unordered (both orders legitimate) | 0.90 | 17 vs. 11 split; S1 refuted by 11/30 |

| OR-precedence for S (1 check before S) | 0.60 | D5 (low-medium) + V5 (2 cases); symmetric case unobserved |
| X constraints (after CE, 1, before A) | 0.75 | D6 + S6 + 2/2 traces, but only 2 observations |
| S5's 5–10% loss figure | 0.50 | Self-reported, unreconciled |

**Alternative interpretations that would materially change the recommendation.**
1. **S1 is right and the log is misordered.** If CE is a real control rule and the 11 E-first traces are timestamp/ingestion artifacts (S7), then both balanced and permissive over-generalize on the C/E axis; the recommendation would shift to a conservative variant with a hard CE sequence, plus a timestamp audit before any modeling.
2. **S is de facto mandatory and the loss rate is ~23%, not 5–10%.** Then the  branch hides data corruption rather than legitimate optionality; the correct move is data repair first, a mandatory-S model second, and conformance monitoring with the conservative candidate until the integration is fixed.
3. **Expedite Review is a rework loop, not a one-shot.** If multiple expedite rounds occur (currently unobserved), all three candidates underfit on that axis and a loop construct must be added.

Until lifecycle timestamps and the sourcing attribute arrive, the honest epistemic position is: the *backbone* (R … AP … Z, both checks before approval) is near-certain; the *internal ordering semantics* of {C, E, S} are known only up to a set of permitted orders; and the *optionality of S* is real in aggregate but unattributable per case.
