# **1. Normalization Assumptions**

### **Core Principles**
- **Clock Offset Direction**: For a source clock with `clock_offset = recorded_clock - true_clock`, the true time is `recorded_clock - offset`. If the offset is in `[a, b]`, the true time is in `[recorded_clock - b, recorded_clock - a]`.
- **Rounding/Display Semantics**:
  - **Floor to minute** (e.g., OPS-BER, VENDOR-NY, LEGACY-BER): `[displayed_time, displayed_time + 59.999s]`.
  - **Round to nearest X seconds** (e.g., SENSOR: ±5s, MOBILE-LON: ±30s): `[displayed_time - X/2, displayed_time + X/2]`.
  - **Exact to second** (HUB): No rounding uncertainty.
- **Time-Zone Conversion**: Convert all timestamps to UTC using IANA time-zone rules (e.g., `Europe/Berlin`  `Europe/Berlin` with DST).
- **DST Fold Ambiguity (LEGACY-BER)**:
  - On 2025-10-26, local times `02:00–02:59` could be either:
    - **No DST transition** (true UTC = local time + 2h).
    - **DST transition** (true UTC = local time + 1h, with `02:00–02:59` skipped).
  - Ingestion order constraints:
    - `Alert_Received` (02:50) must precede `Investigation_Start` (02:05)  **invalid if both in skipped hour**.
    - Thus, feasible interpretations:
      1. **No transition**: All times are +2h UTC.
      2. **Transition**: `Alert_Received` is +1h (02:50  01:50 UTC), `Investigation_Start` is +2h (02:05  00:05 UTC).
- **Inferred Starts (T-404)**:
  - `Investigation_Start` = `Investigation_Complete` - duration.
  - Duration `[18, 25]` min  `Investigation_Start`  `[10:35:00 - 25min, 10:35:00 - 18min]` = `[10:10:00, 10:17:00]`.
- **Mobile Entry Delay (T-406)**:
  - User may enter timestamp up to 5 min late **after** clock uncertainty.
  - Treat as **additional uncertainty** on the recorded time (not a shift in occurrence time).
- **Causal Constraints**:
  - `Alert_Received` must precede `Investigation_Start`.
  - `Investigation_Start` must precede `Containment_Complete`.
  - `Containment_Complete` must precede `Close_Incident`.
- **Missing `Alert_Received` (T-407)**:
  - `Alert_Sent` + `[0, 20]` min  `Alert_Received`  `[14:00:00, 14:20:00]`.
  - Causal constraint: `Alert_Received`  `Investigation_Start` (14:17:00).
  - Thus, `Alert_Received`  `[14:00:00, 14:17:00]`.

# **5. PM4Py Temporal-Conformance Code**

```python
import pandas as pd
import numpy as np
from datetime import datetime, timedelta
import pytz
from pm4py.objects.log.util import dataframe_utils
from pm4py.conformance.temporal_profile import check_temporal_profile

# --- Helper Functions ---
def normalize_timestamp(recorded, system, tz_str=None, rounding=None, offset_bounds=None, dst_ambiguity=None):
    """Convert recorded timestamp to UTC interval(s) considering system metadata."""
    if dst_ambiguity == "fold":
        # Handle DST fold (LEGACY-BER)
        local_time = datetime.strptime(recorded, "%Y-%m-%d %H:%M")
        tz = pytz.timezone(tz_str)
        if tz_str == "Europe/Berlin" and local_time.date() == datetime(2025, 10, 26).date():
            # Possible interpretations:
            # 1. No transition: UTC = local + 2h
            # 2. Transition: UTC = local + 1h (skipped hour)
            utc1 = tz.localize(local_time, is_dst=None).astimezone(pytz.UTC)  # May raise AmbiguousTimeError
            try:
                utc2 = tz.localize(local_time, is_dst=False).astimezone(pytz.UTC)  # Force non-DST
            except pytz.exceptions.AmbiguousTimeError:
                utc2 = None
            if utc2:
                return [utc1 - timedelta(hours=1), utc2 - timedelta(hours=1)]  # Adjust for fold
            else:
                return [utc1 - timedelta(hours=1)]
        else:
            raise ValueError("Unsupported DST ambiguity.")

    # Standard case: apply offset, rounding, and timezone
    tz = pytz.timezone(tz_str) if tz_str else pytz.UTC
    dt = datetime.strptime(recorded, "%Y-%m-%d %H:%M:%S") if ":00" in recorded else datetime.strptime(recorded, "%Y-%m-%d %H:%M")
    if tz_str:
        dt = tz.localize(dt, is_dst=None)
    utc_dt = dt.astimezone(pytz.UTC)

    # Apply rounding
    if rounding == "floor_minute":
        lower = utc_dt
        upper = utc_dt + timedelta(minutes=1, seconds=-1)
    elif rounding == "round_10s":
        lower = utc_dt - timedelta(seconds=5)
        upper = utc_dt + timedelta(seconds=5)
    elif rounding == "round_30s":
        lower = utc_dt - timedelta(seconds=15)
        upper = utc_dt + timedelta(seconds=15)
    elif rounding == "round_minute":
        lower = utc_dt - timedelta(seconds=30)
        upper = utc_dt + timedelta(seconds=30)
    else:
        lower, upper = utc_dt, utc_dt

    # Apply clock offset
    if offset_bounds:
        a, b = offset_bounds
        lower = lower - timedelta(seconds=b)
        upper = upper - timedelta(seconds=a)

    return [lower, upper]

# --- Event Data ---
events = [
    # T-401
    {"case_id": "T-401", "activity": "Alert_Received", "timestamp": "2026-06-01 08:00:00", "system": "HUB", "tz": "UTC", "offset": [-1, 1]},
    {"case_id": "T-401", "activity": "Investigation_Start", "timestamp": "2026-06-01 10:14", "system": "OPS-BER", "tz": "Europe/Berlin", "offset": [-90, 120], "rounding": "floor_minute"},
    {"case_id": "T-401", "activity": "Containment_Complete", "timestamp": "2026-06-01 08:51:10", "system": "SENSOR", "tz": "UTC", "offset": [-5, 5], "rounding": "round_10s"},
    {"case_id": "T-401", "activity": "Close_Incident", "timestamp": "2026-06-02 09:00:00", "system": "HUB", "tz": "UTC", "offset": [-1, 1]},
    # ... (other cases truncated for brevity)
]

# --- Normalize to UTC Intervals ---
df = pd.DataFrame(events)
df["utc_interval"] = df.apply(
    lambda row: normalize_timestamp(
        row["timestamp"],
        row["system"],
        row.get("tz"),
        row.get("rounding"),
        row.get("offset"),
        row.get("dst_ambiguity")
    ),
    axis=1
)

# --- Derive Durations ---
def compute_durations(df):
    durations = []
    for case_id, case_df in df.groupby("case_id"):
        activities = case_df["activity"].tolist()
        intervals = case_df["utc_interval"].tolist()
        for i in range(len(activities) - 1):
            start = intervals[i]
            end = intervals[i+1]
            if isinstance(start, list):  # DST ambiguity
                for s in start:
                    for e in end:
                        if s <= e:  # Ensure causal order
                            durations.append((case_id, activities[i], activities[i+1], s, e))
            else:
                durations.append((case_id, activities[i], activities[i+1], start[0], start[1], end[0], end[1]))
    return durations

durations = compute_durations(df)

# --- PM4Py Midpoint Log (Lossy) ---
midpoint_df = df.copy()
midpoint_df["timestamp"] = midpoint_df["utc_interval"].apply(lambda x: (x[0] + x[1]) / 2 if isinstance(x, list) else (x[0] + x[1]) / 2)
midpoint_df = dataframe_utils.convert_timestamp_columns_in_df(midpoint_df)
midpoint_log = dataframe_utils.convert_to_event_log(midpoint_df)

# --- PM4Py Temporal Profile Check ---
profile = {
    ('Alert_Received', 'Investigation_Start'): (600, 180),
    ('Investigation_Start', 'Containment_Complete'): (2100, 600),
    ('Alert_Received', 'Containment_Complete'): (2700, 720),
    ('Containment_Complete', 'Close_Incident'): (86400, 21600)
}

for zeta in [1, 2, 3]:
    print(f"\n--- Zeta = {zeta} ---")
    result = check_temporal_profile(midpoint_log, profile, zeta=zeta)
    print(result)
```

**Note**: PM4Py does not natively handle interval uncertainty, so this code:
1. Computes midpoint timestamps for a **lossy** approximation.
2. Uses `pm4py.conformance_temporal_profile` for comparison.
3. **Does not** claim equivalence with interval-based reasoning (which is more precise).

# **7. Governance Recommendation**

### **Timestamp & Clock Controls**
1. **UTC Storage**: All systems must store timestamps in UTC with sub-second precision.
2. **Raw Timestamp Retention**: Log raw timestamps (before rounding/conversion) for audit.
3. **Source Offset Telemetry**: Continuously monitor and log `clock_offset` (e.g., via NTP diagnostics).
4. **Resolution Metadata**: Record display/rounding semantics (e.g., "floor to minute") in system metadata.

### **Time-Zone & DST**
5. **DST Fold Handling**: Explicitly log DST transitions or use IANA time-zone rules with `is_dst` flags.
6. **Ambiguity Resolution**: For ambiguous times (e.g., 02:30 on DST transition), require manual review or default to non-DST.

### **Lifecycle & Provenance**
7. **Start/Complete Semantics**: Distinguish between:
   - **Event start** (e.g., `Alert_Received` = network receipt).
   - **Activity start** (e.g., `Investigation_Start` = human action).
8. **Causal Identifiers**: Include unique IDs to link events (e.g., `Alert_ID`  `Investigation_ID`).
9. **Interval Overlap Policy**: For SLAs, require **non-overlapping intervals** (not just midpoint checks).

### **Policy for Enforcement**
- **SLA Compliance**: Use **interval arithmetic** (not midpoints) to enforce rules.
- **Temporal Profiles**: Allow configurable `zeta` for statistical tolerance.
- **Audit Trail**: Retain all normalization steps (e.g., "OPS-BER 10:14  UTC [10:12:30, 10:16:10]").

---
**Key Insight**: Interval reasoning reveals violations that midpoint analysis misses (e.g., T-401’s negative containment duration). Governance must prioritize **uncertainty preservation** over point estimates.
