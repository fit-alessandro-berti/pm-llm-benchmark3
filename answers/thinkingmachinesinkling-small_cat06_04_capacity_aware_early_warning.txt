**Selective intervention changing future training labels.** If we swarm high-p cases and they do not breach, future models learn “high p + swarm  no breach,” confounding the causal effect of the swarm with selection. Conversely, if low-value cases are never swarmed and breach, the training set reinforces that low-value cases “should” breach.

- *Safeguard:* Record `swarm_flag` as a feature; **exclude swarmed cases from direct outcome-label updates** unless paired with matched controls. Use a **hold-out no-intervention cohort** (matched by stage, segment, time-to-SLA) to estimate the counterfactual. Retrain on a dataset where the intervention is either randomized or explicitly modeled (e.g., double machine learning).

**Spillover harms systematically falling on untreated groups.** Each slot delays diagnosis-stage cases. If the untreated group is disproportionately from one segment (e.g., small public-sector cases with long queues), spillover is regressive.

- *Safeguard:* **Monitor untreated breach rates by segment** on swarm vs. non-swarm days. If spillover causes >0.03 increase in untreated breach probability per case, reduce concurrent slots (from 4 to 2). Rotate which cases are left untreated to avoid persistent congestion on any single queue group.

## 6. Monitoring and recalibration plan

**Operational monitoring (every slot / daily).**
- Slot usage (used / reserve used / idle), time from alert to swarm start, specialist interruption minutes.
- Aggregate diagnosis-queue delay per swarm (target: observe 8–20 min; if >20 min for 2+ consecutive slots, freeze next slot).
- Stage progression post-swarm: % reaching `Diagnosis Complete` on time.

**Predictive monitoring (weekly).**
- Calibration plots by segment (SME, Strategic, Public, Non-Native) in 10-point bins; Brier score; observed vs. predicted breach rate.
- Alert fatigue: % of alerts suppressed; conversion rate of alerted cases to breach.

**Causal-effect monitoring (monthly; update ranges quarterly).**
- **Matching:** For each swarmed eligible case, find a matched untreated control (same stage, calibrated `p_adj`, segment, time-to-SLA ±1 h, value quartile).
- **Difference-in-differences / ATT:** Estimate absolute risk reduction per segment. Update the “Estimated absolute risk reduction” ranges (currently 0.05–0.35) using these estimates, not just backtests.
- **Model-reason audit:** For cases where swarm was deployed but breach occurred anyway or where no breach occurred despite high p, review feature importance to detect “wrong reason” alerts (adverse scenario).

**Capacity monitoring (daily / weekly).**
- Queue length at `Diagnosis Started`; specialist availability; aggregate delay.
- Reserve-slot usage rate: if regulatory arrival is <10% by 14:00 across 4 weeks, consider reducing reserve to 0.5 slot (i.e., allow 3.5 used).

**Fairness monitoring (weekly).**
- Distribution of swarms by segment, by value quartile, by language-support status.
- Untreated diagnosis-stage breach rate by segment; compare to baseline week.

**Decision triggers to change the rule / threshold:**
- **Calibration drift:** If any segment calibration error >0.05 for 2 consecutive weeks  freeze automatic swarms for that segment and revert to manual co-sign.
- **Effect decay:** If observed ATT < lower half of current effect range for 4 weeks  raise the evidence bar (require `p > 0.10` or new event for second alerts).
- **Spillover alarm:** If untreated diagnosis-stage breach rate rises >0.03 per case relative to baseline on swarm days  reduce concurrent slots from 4 to 2.
- **Reserve policy:** Re-evaluate monthly; if reserve is never used for 8 weeks, release it to general pool earlier (e.g., 13:00).

This framework treats the intervention as **uncertain, heterogeneous, and externally costly**, refusing to rank by `p_now` alone and explicitly protecting untreated cases from congestion.
