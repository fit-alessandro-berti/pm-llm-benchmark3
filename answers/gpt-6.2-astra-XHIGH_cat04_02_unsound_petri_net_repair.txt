# 1. Executive Verdict

The net is a workflow net and is unsound. It has a unique source and sink, and every node lies on a directed path between them. The defect is in `t_join_waived`: a recorded waiver alone enables it to produce the decision token. The case can therefore be authorized before `t_analyze` fires. Even if analysis finishes first, its completion token survives authorization. The standard-review route can reach the exact final marking. Once the waiver fires, the case can put a token in the sink but can never reach the exact final marking.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source`, `t_register`, `p_ready` | Admit and register one case | `im = {source: 1}`. Registration moves that one token to `p_ready`. | The split can fire once per case. |
| `t_split` | Start analysis and review in parallel | Consumes the ready token and produces one token in each of `p_analysis` and `p_review`. | Both branches have work outstanding, including on a future waiver run. |
| `t_analyze` | Complete mandatory analysis | Moves the analysis token to `p_analysis_done`. Its only downstream consumer is `t_join_normal`. | Completed analysis can be stranded on the waiver route. |
| `t_standard_review` | Record standard completion | Consumes the only `p_review` token and marks `p_review_done`. | Standard review excludes a subsequent waiver. |
| `t_waive_review` | Record the alternative outcome | Competes for the same `p_review` token and marks `p_waived`. | A waiver excludes standard review, so `p_review_done` can never be marked on this run. |
| `t_join_normal` | Synchronize completed analysis and standard review | Requires and consumes both completion tokens, producing one token in `p_decision`. | This route waits for both activities and clears both branches. |
| `t_join_waived` | Synchronize completed analysis and a waiver | Consumes only `p_waived` and marks `p_decision`. | Authorization can become enabled while `t_analyze` is still enabled. |
| `t_authorize`, `sink` | Close the case at `fm = {sink: 1}` | Authorization moves the decision token to the sink. It has no input from either analysis place. | The sink can be marked while another place still holds a token. |
| Whole graph | Connect all workflow nodes | Only `source` has no incoming arcs and only `sink` has no outgoing arcs. From the split, the analysis and standard-review paths lead through the normal join, and the waiver path leads through the waiver join. Both lead through authorization to the sink. | Every node meets the structural path condition. This graph test does not check which tokens can coexist. |

# 3. Marking-Based Counterexample

A legal firing sequence is `t_register → t_split → t_waive_review → t_join_waived → t_authorize → t_analyze`. In the tables and sequences below, each listed place holds one token. All omitted places are empty.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source}` | `t_register` | Initial marking. |
| 1 | `t_register` | `{p_ready}` | `t_split` | Case registered. |
| 2 | `t_split` | `{p_analysis, p_review}` | `t_analyze, t_standard_review, t_waive_review` | One token belongs to each parallel branch. The two review transitions compete for the same token. |
| 3 | `t_waive_review` | `{p_analysis, p_waived}` | `t_analyze, t_join_waived` | The waiver join is already enabled. |
| 4 | `t_join_waived` | `{p_analysis, p_decision}` | `t_analyze, t_authorize` | Authorization and analysis can fire in either order. |
| 5 | `t_authorize` | `{p_analysis, sink}` | `t_analyze` | Authorization precedes analysis. The sink is marked, the marking differs from `fm`, and work can still fire. |
| 6 | `t_analyze` | `{p_analysis_done, sink}` | ∅ | Terminal marking different from `fm`. |

There is a second ordering with the same failure to finish cleanly. Follow steps 0–4, then fire `t_analyze` to obtain `{p_analysis_done, p_decision}`. Only `t_authorize` is enabled. Firing it produces `{p_analysis_done, sink}` with nothing enabled. Thus delaying authorization until analysis has finished does not repair token consumption.

At step 5 in the table, `t_analyze` can consume the leftover branch token, but it only moves it to `p_analysis_done`. To consume that token, `t_join_normal` would also need `p_review_done`. The waiver consumed the sole review token at step 3, and the split cannot fire again. This proves loss of the option to reach `fm` from step 3 and improper completion when the sink is reached. Every transition can fire in some run of the original net. The normal join fires on the standard route and the waiver join fires at step 4.

# 4. Minimal-Repair Alternatives

Count one edit for adding or removing a unit arc, redirecting one endpoint of a unit arc, or adding or removing a node. Charge incident arc changes separately from node changes. Keep the supplied markings, visible labels, and ordinary Petri-net firing semantics. In the table, an added input is a consuming arc.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| A. Synchronize at the waiver join | Add `p_analysis_done → t_join_waived`. | 1 addition | Either review outcome may occur before or after analysis. Authorization requires analysis and the selected outcome. | The waiver join consumes the analysis and waiver tokens together. | The two joins encode the analysis requirement separately. A later change to that requirement could update only one join. |
| B. Synchronize when recording the waiver | Add `p_analysis_done → t_waive_review`. Keep `p_review → t_waive_review`. | 1 addition | Both branches start at the split. Authorization requires analysis and one recorded outcome. Standard review stays independent of analysis. | **Tighter policy.** Recording a waiver now waits for completed analysis and consumes its token. The visible order “Record Review Waiver, Perform Analysis” is lost. | A waiver ready early cannot be recorded immediately, potentially delaying its audit timestamp. |
| C. Route the waiver through the common join | Redirect the target of `t_join_waived → p_decision` to `p_review_done`. Keep `p_waived → t_join_waived` and both inputs of `t_join_normal`. | 1 redirection | Both review labels and both orders relative to analysis remain possible. | The silent waiver transition forwards the waiver token to the common review-completion place. Only `t_join_normal` can issue a decision. | Monitoring that equates `p_review_done` with a *standard* review would misclassify waivers. |

Zero edits leave the counterexample intact. Each repair costs one edit and suffices, so all three attain the global lower bound under this model. If redirection is priced as a deletion plus an addition, A and B still tie at the global minimum of one, and C costs two. A and B have different visible traces. A and C have the same complete visible traces but different internal routes to the decision.

To check sufficiency, on the standard route in every repair, analysis and review can finish in either order and the normal join consumes both tokens. On the waiver route, A waits at the waiver join, B consumes both branch tokens when recording the waiver, and C forwards the review outcome and waits at the common join. Any unfinished prerequisite can still fire. In every case exactly one decision token remains after synchronization and forwarding, and authorization takes it to `fm`. Both outcomes are reachable and together exercise every transition.

# 5. Corrected PM4Py Code

Repair A retains the supplied nodes and labels.

```python
from pm4py.objects.petri_net.obj import Marking, PetriNet
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

place_names = (
    "source", "p_ready", "p_analysis", "p_review", "p_analysis_done",
    "p_review_done", "p_waived", "p_decision", "sink",
)
places = {name: PetriNet.Place(name) for name in place_names}
repaired_net.places.update(places.values())

labels = {
    "t_register": "Register Case",
    "t_split": None,
    "t_analyze": "Perform Analysis",
    "t_standard_review": "Perform Standard Review",
    "t_waive_review": "Record Review Waiver",
    "t_join_normal": None,
    "t_join_waived": None,
    "t_authorize": "Authorize Case",
}
transitions = {
    name: PetriNet.Transition(name, label) for name, label in labels.items()
}
repaired_net.transitions.update(transitions.values())

arcs = [
    ("source", "t_register"),
    ("t_register", "p_ready"),
    ("p_ready", "t_split"),
    ("t_split", "p_analysis"),
    ("t_split", "p_review"),
    ("p_analysis", "t_analyze"),
    ("t_analyze", "p_analysis_done"),
    ("p_review", "t_standard_review"),
    ("t_standard_review", "p_review_done"),
    ("p_review", "t_waive_review"),
    ("t_waive_review", "p_waived"),
    ("p_analysis_done", "t_join_normal"),
    ("p_review_done", "t_join_normal"),
    ("t_join_normal", "p_decision"),
    ("p_waived", "t_join_waived"),
    ("p_analysis_done", "t_join_waived"),  # Consume analysis on the waiver route.
    ("t_join_waived", "p_decision"),
    ("p_decision", "t_authorize"),
    ("t_authorize", "sink"),
]
nodes = {**places, **transitions}
for start, end in arcs:
    petri_utils.add_arc_from_to(nodes[start], nodes[end], repaired_net)

repaired_im = Marking({places["source"]: 1})
repaired_fm = Marking({places["sink"]: 1})
```

# 6. Diagnostic and Reachability Code

Run this block with the original and repaired variables in scope. The replay prints the marking, exact-final test, and enabled names initially and after each firing. It stops at the first disabled request.

```python
import pm4py
from pm4py.objects.petri_net import semantics

models = (
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
)
graphs = {}
for name, model, initial, final in models:
    print(name, "workflow net", pm4py.check_is_workflow_net(model))
    sound, _ = pm4py.check_soundness(model, initial, final, print_diagnostics=True)
    print(name, "sound", sound)
    initial_enabled = pm4py.get_enabled_transitions(model, initial)
    print(name, "initially enabled", sorted(t.name for t in initial_enabled))
    graphs[name] = pm4py.convert_to_reachability_graph(model, initial, final)


def replay(model, initial, final, names):
    marking = initial
    by_name = {t.name: t for t in model.transitions}

    def report(step):
        tokens = dict(sorted((p.name, n) for p, n in marking.items() if n))
        enabled = pm4py.get_enabled_transitions(model, marking)
        print(step, tokens, "exact final", marking == final,
              "enabled", sorted(t.name for t in enabled))
        return enabled

    enabled = report("start")
    for name in names:
        transition = by_name[name]
        if transition not in enabled:
            print("blocked", name)
            return False
        marking = semantics.execute(transition, model, marking)
        enabled = report(name)
    return marking == final


prefix = ["t_register", "t_split", "t_waive_review"]
early = prefix + ["t_join_waived", "t_authorize", "t_analyze"]
for name, model, initial, final in models:
    print(name, "early authorization attempt")
    replay(model, initial, final, early)

print("repaired waiver completion")
assert replay(repaired_net, repaired_im, repaired_fm,
              prefix + ["t_analyze", "t_join_waived", "t_authorize"])
```

With PM4Py 2.7.23.4, both structural checks passed. The original failed soundness. Its terminal waiver marking contains the stranded analysis token alongside the sink token. A passed soundness, and replay of the counterexample stopped at `t_join_waived`. Completing analysis then enabled the join, and the remaining firings reached exactly `repaired_fm`. The exact final marking is reachable on **both** models via standard review, so testing only its existence misses the defect.

# 7. Repair Trade-Offs and Residual Risks

- **Auditability.** “Perform Standard Review” and “Record Review Waiver” remain distinct visible events. In A their joins have distinct internal names but are silent. The single review token makes the two joins mutually exclusive within a case. Only the join for the selected outcome can issue the decision token. After the join, the decision marking alone does not identify the chosen review outcome. Retain the visible event for audit.
- **Replay interpretation.** Silent joins can be absent from a visible log. For A, a waiver join cannot fire until both visible prerequisites occur. Different interleavings of analysis and the selected review are intentional. Adding the input arc introduces no transition or duplicate route.
- **Positive tests for A.** Start each trace with “Register Case” and end it with “Authorize Case”. For each of “Perform Standard Review” and “Record Review Waiver”, test both orders of that event and “Perform Analysis”. Require replay with zero deviations, allowing silent transitions, and the exact final marking.
- **Negative tests for A.** After registration, reject authorization following a waiver alone, standard review alone, or analysis alone. Reject an extra analysis after authorization and reject traces with both review outcomes, in either order. Check the original counterexample at the prefix where authorization is attempted as well as at the end. Testing only successful complete traces can hide an early authorization that strands a token.
- **Mandatory-analysis invariant.** Explore reachable pairs of a marking and its firing history summarized by an `analyzed` flag and the recorded review outcome (none, standard, or waiver). Start with `False` and no outcome, update the flags on the corresponding visible firings, and fail on a second review outcome. At every pair where `t_authorize` is enabled, require completed analysis and exactly one outcome. Explore every enabled transition, including silent ones, and keep distinct histories in the visited key when their flags differ. Separately require every reachable marking containing a sink token to equal `fm`. This catches even a sound redesign that achieves clean completion by omitting mandatory work.

# 8. Final Recommendation

Deploy **A**. The added input states exactly what the waiver join must wait for, preserves independent timing of the recorded waiver, and closes the case with no residual tokens. It also preserves existing interpretations of the review places and join names.

Use **C** as the fallback when a single authorization gate is easier to maintain. It preserves the same visible traces and centralizes the analysis requirement. Update any monitoring that interprets the common completion place or join as evidence of standard review, and identify waivers from their recorded event. Reserve **B** for an explicit policy decision to delay waiver recording until analysis finishes.
