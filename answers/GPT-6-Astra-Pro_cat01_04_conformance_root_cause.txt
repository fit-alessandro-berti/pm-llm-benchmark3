## 1. Evidence ledger

**Interpretive basis.** I distinguish a deviation in the *recorded trace*, a deviation from the *current business policy*, and evidence that an employee actually omitted a required control. These are not interchangeable.

For compactness, H1 denotes real behavioral process change; H2, an obsolete normative model; H3, label or semantic logging change; H4, a timestamp/order defect; H5, employee noncompliance; and H6, a technical-event/extraction artifact. Reliability scores assess how strongly an item supports the stated inference, not the probability that its source is truthful.

**Assumption A1:** For reconstruction, the supplied variant tables are treated as complete, frequency-weighted activity sequences in their stated order. The aggregate alignment report is treated separately because it does not fully reconcile with those sequences.

For August–September, mapping and removal yield 300/620 fitting cases, or **48.4%**. ## 3. Causal-abductive explanation

The following is a proposed causal structure. Annotated possible links are hypotheses, not additional observations.

```text
UI_release -> recorded_labels
UI_release -> reviewer_behavior [possible workflow side effect; unverified]

gateway_change -> technical_event_capture
technical_event_capture -> recorded_events

ETL_change -> recorded_order
ETL_change -> event_completeness [possible extraction side effect; unverified]

policy_change -> required_controls
policy_change -> reviewer_behavior
required_controls -> normative_model [intended governance update]
model_update_failure -> normative_model [leaves the old specification in force]

business_outcomes -> reported_business_outcomes
detection_sensitivity -> reported_business_outcomes

timestamp_provenance -> reported_business_outcomes
```

The most economical explanation is a layered measurement break followed by a genuine policy change. In June, the classifier still expected Classify, while many records used Risk Screen. The gateway added Queue Routed, and the ETL later substituted ingestion timestamps for two business activities. These mechanisms can produce extra log moves, missing-model-label moves, and apparent ordering violations without changing the underlying business execution. 

The reported staged repairs are therefore diagnostically informative: they reportedly restore 57 percentage points of fitting traces before any reviewer intervention. However, that is a conditional, within-report contrast, not an identified causal decomposition. The supplied variants contradict several reported percentages, and sequential repair effects depend on which repairs were already applied. 

August adds a different mechanism. A required sign-off became part of the policy, but not the model. Correctly executed sign-offs can consequently reduce measured fitness. Making sign-off optional removes that mismatch for some traces while still accepting a high-value case that wrongly omits it. Such a model fixes one false-positive mechanism without resolving the corresponding false-negative risk.  

Residual missing checks and Manual Override require separate investigation. Missing records may reflect omitted controls or omitted events; an override may be an authorized routing correction. Approximately stable aggregate outcomes cannot distinguish these explanations because case mix, detection sensitivity, follow-up maturity, and timestamp contamination remain unresolved. Harmful deviations may be rare or delayed, and authorized controls may change behavior without materially changing approval or appeal rates.

def expand_variants(period: str, entries: list[tuple[str, int]]) -> EventLog:
    strings = []
    for text, frequency in entries:
        if not isinstance(frequency, int) or frequency <= 0:
            raise ValueError("Variant frequencies must be positive integers.")
        strings.extend([text] * frequency)
    parsed = pm4py.parse_event_log_string(strings)
    # PM4Py versions may return a DataFrame or an EventLog.
    log = parsed if isinstance(parsed, EventLog) else pm4py.convert_to_event_log(parsed)
    assert len(log) == sum(n for _, n in entries)
    for i, trace in enumerate(log):
        trace.attributes[ACT] = f"{period}:{i}"
        trace.attributes["period"] = period
        for position, event in enumerate(trace):
            event["audit:raw_activity"] = event[ACT]
            event["audit:input_position"] = position  # NOT a source sequence.
            event["audit:synthetic_timestamp"] = True
    observed = Counter(",".join(e[ACT] for e in trace) for trace in log)
    assert observed == Counter(dict(entries))
    return log


def normalize(log: EventLog, *, map_label: bool, remove_queue: bool) -> EventLog:
    result = EventLog(
        attributes=deepcopy(log.attributes), properties=deepcopy(log.properties)
    )
    for trace in log:
        cleaned = Trace(attributes=deepcopy(trace.attributes))
        for event in trace:
            if remove_queue and event[ACT] == "Queue Routed":
                continue  # Business-control-flow projection; original remains intact.
            copied = deepcopy(event)
            if map_label and copied[ACT] == "Risk Screen":
                copied[ACT] = "Classify"
            cleaned.append(copied)
        result.append(cleaned)
    assert len(result) == len(log)
    # Never remove Manual Override, Supervisor Sign-off, or missing-check cases.
    return result


def source_ordered_log(
    events: pd.DataFrame, *, sequence_semantics_verified: bool = False

    Requires an audited, unique, per-case source sequence covering all events.
    Preserves timestamps; constructs ordered traces without timestamp re-sorting.
    """

        raise ValueError("Verify source-sequence scope and business semantics first.")
    required = [CASE, ACT, "source_sequence"]

    data = events.copy()

    if data.duplicated([CASE, "source_sequence"]).any():
        raise ValueError("Sequence ties/resets need investigation, not arbitrary sorting.")
    data = data.sort_values([CASE, "source_sequence"], kind="mergesort")
    result = EventLog()
    for case_id, group in data.groupby(CASE, sort=False):
        trace = Trace(attributes={ACT: str(case_id)})
        for row in group.to_dict("records"):
            trace.append(Event({k: v for k, v in row.items() if k != CASE}))
        result.append(trace)
    return result


def describe(log: EventLog, title: str) -> None:
    counts = Counter(tuple(e[ACT] for e in trace) for trace in log)
    variants = pd.DataFrame(
        [(" -> ".join(v), n) for v, n in counts.items()],
        columns=["variant", "cases"],
    ).sort_values("cases", ascending=False)
    dfg, starts, ends = pm4py.discover_dfg(log)
    edges = pd.DataFrame(
        [(a, b, n) for (a, b), n in dfg.items()],
        columns=["from", "to", "frequency"],
    ).sort_values(["frequency", "from", "to"], ascending=[False, True, True])
    print(f"\n{title}\n{variants.to_string(index=False)}")
    print(edges.to_string(index=False))
    print("Start activities:", starts, "End activities:", ends)


def evaluate(
    log: EventLog, model: tuple, *, precision: bool = False
) -> dict[str, Any]:
    diagnostics = pm4py.conformance_diagnostics_alignments(
        log, *model, multi_processing=False, return_diagnostics_dataframe=False
    )
    fitness = pm4py.fitness_alignments(log, *model, multi_processing=False)
    log_moves, model_moves = Counter(), Counter()
    visible_counts, costs = [], []
    for diagnostic in diagnostics:
        if diagnostic is None or diagnostic.get("alignment") is None:
            raise RuntimeError("An alignment was not computed; do not score it as fitting.")
        visible = 0
        for left, right in diagnostic["alignment"]:
            if right == ">>" and left not in (None, ">>"):
                log_moves[left] += 1
                visible += 1
            elif left == ">>" and right not in (None, ">>"):
                model_moves[right] += 1
                visible += 1
            # Synchronous moves and invisible model moves are not deviations.
        visible_counts.append(visible)
        costs.append(diagnostic["cost"])
    fitting = sum(n == 0 for n in visible_counts)
    print("Alignment-fitness dictionary:", fitness)
    print("Visible log moves:", dict(log_moves))
    print("Visible model moves:", dict(model_moves))
    return {
        "cases": len(log),
        "strict_fitting_cases": fitting,
        "strict_fitting_pct": 100.0 * fitting / len(log),
        "average_trace_fitness": fitness["average_trace_fitness"],
        "log_fitness": fitness["log_fitness"],
        "mean_cost_PM4Py_units": pd.Series(costs, dtype=float).mean(),
        "mean_visible_moves": pd.Series(visible_counts, dtype=float).mean(),
        "precision": (
            pm4py.precision_alignments(log, *model, multi_processing=False)
            if precision else float("nan")
        ),
    }


def main() -> None:
    print("PM4Py version:", pm4py.__version__)
    normative_model = pm4py.convert_to_petri_net(pm4py.parse_process_tree(NORMATIVE))
    candidate_model = pm4py.convert_to_petri_net(pm4py.parse_process_tree(CANDIDATE))
    expected = {
        "Apr-May": [600, 600, 600],
        "Jun-Jul": [0, 90, 535],
        "Aug-Sep": [0, 0, 300],
    }
    stages = [("raw", False, False), ("label_map", True, False),
              ("label_map_remove_queue", True, True)]
    reports, lengths = [], []
    for period, entries in VARIANTS.items():
        original = expand_variants(period, entries)
        lengths.append({
            "period": period, "cases": len(original),
            "recorded_events": sum(map(len, original)),
            "mean_recorded_events": sum(map(len, original)) / len(original),
        })
        for index, (stage, map_label, remove_queue) in enumerate(stages):
            log = normalize(original, map_label=map_label, remove_queue=remove_queue)
            describe(log, f"{period}: {stage}")
            compare = period == "Aug-Sep" and remove_queue
            row = evaluate(log, normative_model, precision=compare)
            assert row["strict_fitting_cases"] == expected[period][index]
            reports.append({"period": period, "stage": stage, "model": "normative", **row})
            if compare:
                other = evaluate(log, candidate_model, precision=True)
                assert other["strict_fitting_cases"] == 510
                reports.append({"period": period, "stage": stage,
                                "model": "optional_signoff", **other})
    print("\nVARIANT-DERIVED EVENT TOTALS")
    print(pd.DataFrame(lengths).to_string(index=False))
    print("\nSAME-INPUT CONFORMANCE COMPARISONS")
    print(pd.DataFrame(reports).to_string(index=False))
    print("\nCAVEATS")
    print("No source ordering was performed: actual source sequences are unavailable.")
    print("Parser timestamps are synthetic; do not calculate durations or release dates.")
    print("These variants do not reconcile with all supplied aggregate alignment figures.")
    print("PM4Py costs use its own scale, not the unspecified report normalization.")
    print("Invisible transitions are not visible deviations, even with nonzero cost.")
    print("Optional sign-off cannot enforce amount > EUR 50,000 or effective-date scope.")
    print("The candidate may overgeneralize; precision cannot validate the data condition.")
    print("No amounts, reviewer authorizations, audit findings, or business outcomes were invented.")


if __name__ == "__main__":
    main()

## 7. Provisional conclusion

The primary explanation for the measured deterioration is a combination of event-label incompatibility, added technical events, and unreliable event ordering, followed in August by an obsolete policy model. My confidence is **high in this combined explanation**, but only **moderate in any numerical allocation** of the collapse among its components. The reported June–July repairs recover fitting-trace coverage from 32% to 89% without changing employees’ actions. Nevertheless, those percentages cannot be reproduced from the supplied variants under literal trace conformance, so they must remain reported evidence rather than verified causal effect sizes. 

A real compliance problem may remain. The 55 enhanced-review cases without recorded checks are unresolved control exceptions, not 55 established employee violations. Their observed rate among enhanced-review cases decreases from 14.7% to 11.1%; this does not establish improving compliance either. High-value cases lacking sign-off create another potential exposure that the existing model—and the optional-sign-off candidate—can miss entirely. Confidence is high that these exposures require investigation, but low to moderate that the supplied evidence establishes actual bypasses. Intent or reviewer culpability is not established.   

IT should preserve raw evidence, reconcile report lineage, validate the activity mapping, isolate technical events without deleting them, and rebuild ordering from an audited source sequence. Process owners should issue a versioned policy representation with explicit applicability and resolve the status of routing overrides. Compliance should prioritize source-level adjudication of missing checks and applicable high-value cases, including apparently fitting cases; maintain required controls while the diagnosis proceeds.

It must not yet be claimed that employees caused the collapse, that all reversed traces were timestamp errors, that sign-off presence proves policy compliance, or that stable appeal rates demonstrate safety. Nor should a higher fitness score justify removing business actions or weakening mandatory controls. The immediate objective is trustworthy measurement alongside targeted control assurance—not cosmetic restoration of a dashboard.

## 8. Model-governance recommendation

1. **Version models together with policy applicability.** Record the policy owner, effective scope, model hash, approved exceptions, and applicability to in-flight cases. Preserve historical baselines rather than retroactively applying new obligations. Require model review whenever a policy changes a required control.

2. **Maintain event-semantic contracts.** Separate stable business activity identifiers from interface labels. Specify each event’s triggering state transition, lifecycle meaning, source, and required attributes. Approve synonym mappings only after functional verification, and retain original labels and mapping versions.

3. **Define an explicit technical-event policy.** Maintain separate raw, technical, and business-control-flow views with reversible lineage. Exclude only approved technical categories from business conformance. Never classify a real action such as `Manual Override` as technical merely because removing it improves fitness.

4. **Protect timestamp and ordering provenance.** Store business occurrence time, ingestion time, timezone, source sequence, and sequence scope separately. Validate ties, resets, missing values, and cross-source ordering. Quarantine unresolved ordering rather than imposing the order preferred by the normative model.

5. **Represent data-aware obligations explicitly.** Couple control-flow checking with policy-versioned predicates for claim value, applicability, and any specified authorization requirements. Treat missing attributes as unknown—not as low risk. An optional-sign-off model is a diagnostic abstraction, not a replacement for the mandatory high-value rule.

6. **Validate releases against evidence and negative tests.** Before and after UI, gateway, ETL, or policy releases, compare fixed-cohort variants, DFGs, alignment moves, fitness, precision, event totals, and missingness. Include adjudicated compliant cases and deliberately invalid examples, reconcile every dashboard to source IDs, and require joint IT, process-owner, and compliance approval for material changes.
