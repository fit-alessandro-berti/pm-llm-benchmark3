The best explanation is a sequence of measurement changes followed by a genuine model-governance gap, with possible residual behavior deviations. Release 4.2 makes the same apparent screening function look like an unmodeled activity. The gateway then inserts Queue Routed, and removing that event plus mapping the label explains much of the June fitness loss. Separately, the ETL change can invert Decision and Notify because ingestion time is not occurrence time; the source-order improvement and the audited screenshots support that mechanism, but only for a subset so far. From August, the policy adds a real sign-off obligation for high-value cases while the normative tree remains unchanged. An optional sign-off branch improves fitness, but without the value threshold it also grants the step to ineligible cases and may lower precision.

Stable aggregate approvals and appeals make a severe broad outcome deterioration less likely, but do not establish that controls were followed. Aggregates can hide high-value or reviewer-specific problems, appeals are an imperfect and delayed detector, and confirmed incidents are known to be under-detected. Conversely, an alignment move for a missing Compliance Check is a discrepancy between a recorded trace and a control-flow model, not proof that an employee skipped the check: the event may be absent from extraction, or the check may be a different event label. Case-level provenance and a blinded audit are needed to separate those explanations.

## 6. PM4Py reproduction and model-comparison code

```python
import copy
import xml.etree.ElementTree as ET
import pm4py

# Variant aggregates transcribed from the question. Trace order is preserved.
period_rows = {
    "Apr-May": [
        ("Receive,Classify,Standard Review,Decision,Notify", 380),
        ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
        ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40),
    ],
    "Jun-Jul": [
        ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
        ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
        ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
        ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
    ],
    "Aug-Sep": [
        ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
        ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),
    ],
}


def parse_aggregate_rows(rows, period):
    """Expand comma-delimited variants to XES and parse via PM4Py's public API."""
    root = ET.Element("log", {
        "xes.version": "1.0",
        "xes.features": "nested-attributes",
        "openxes.version": "1.0",
    })
    case_no = 0
    for variant, frequency in rows:
        activities = variant.split(",")
        for _ in range(frequency):
            case_no += 1
            trace = ET.SubElement(root, "trace")
            ET.SubElement(trace, "string", {
                "key": "concept:name",
                "value": f"{period}-{case_no}",
            })
            for activity in activities:
                event = ET.SubElement(trace, "event")
                ET.SubElement(event, "string", {
                    "key": "concept:name",
                    "value": activity,
                })
    xes_text = ET.tostring(root, encoding="unicode")
    return pm4py.parse_event_log_string(xes_text)


# Control-flow-only normative model from the question.
normative_tree = pm4py.parse_process_tree(
    "->('Receive','Classify',X(*( 'Standard Review','Request Info'),"
    "->('Enhanced Review','Compliance Check')),'Decision','Notify')"
)
normative_net, normative_im, normative_fm = pm4py.convert_to_petri_net(
    normative_tree
)


def normalize_log(log, remove_queue_routed=False, order_by_source_sequence=False):
    """Apply explicit, inspectable label, optional event, and order repairs.

    Aggregate variants contain no source sequence, so this code will not invent
    one. If a real XES event has an integer `source:seq` attribute on every
    event in a trace, the trace is reordered by that field before label mapping.
    """
    normalized = copy.deepcopy(log)
    sorted_traces = 0
    for trace in normalized:
        if (order_by_source_sequence and trace
                and all("source:seq" in event for event in trace)):
            ordered = sorted(trace, key=lambda event: int(event["source:seq"]))
            trace.clear()
            trace.extend(ordered)
            sorted_traces += 1

        for event in trace:
            if event.get("concept:name") == "Risk Screen":
                event["concept:name"] = "Classify"

        if remove_queue_routed:
            kept = [event for event in trace
                    if event.get("concept:name") != "Queue Routed"]
            trace.clear()
            trace.extend(kept)
    return normalized, sorted_traces


def show_dfg(label, log):
    dfg, starts, ends = pm4py.discover_dfg(log)
    print(f"\nDFG: {label}")
    for (left, right), count in sorted(dfg.items(), key=lambda item: (-item[1], item[0])):
        print(f"  {left} -> {right}: {count}")
    print("  start activities:", starts)
    print("  end activities:", ends)


def show_fitness(label, log, net, im, fm):
    result = pm4py.fitness_alignments(log, net, im, fm)
    print(f"\nAlignment fitness: {label}: {result}")
    return result


logs = {period: parse_aggregate_rows(rows, period)
        for period, rows in period_rows.items()}

# Compare raw, label-mapped, and fully normalized DFGs and fitness.
normalized_logs = {}
for period, raw_log in logs.items():
    mapped_log, _ = normalize_log(raw_log)
    normalized_log, sorted_count = normalize_log(
        raw_log, remove_queue_routed=True, order_by_source_sequence=True
    )
    normalized_logs[period] = normalized_log
    print(f"\n=== {period}; source-sequence-sorted traces in aggregate: {sorted_count} ===")
    show_dfg(f"{period} raw", raw_log)
    show_dfg(f"{period} label mapped", mapped_log)
    show_dfg(f"{period} mapped + Queue Routed removed", normalized_log)
    show_fitness(f"{period} raw vs normative", raw_log,
                 normative_net, normative_im, normative_fm)
    show_fitness(f"{period} mapped vs normative", mapped_log,
                 normative_net, normative_im, normative_fm)
    show_fitness(f"{period} mapped + technical-event removal vs normative",
                 normalized_log, normative_net, normative_im, normative_fm)

# Detailed move diagnostics on normalized June-July and August-September cases.
for period in ("Jun-Jul", "Aug-Sep"):
    diagnostics = pm4py.conformance_diagnostics_alignments(
        normalized_logs[period], normative_net, normative_im, normative_fm
    )
    print(f"\nAlignment diagnostics: {period}; traces={len(diagnostics)}")
    for diagnostic in diagnostics[:3]:
        print("  example:", diagnostic)

# Candidate: after the existing review choice, sign-off is optional, then
# Decision and Notify. `tau` is the silent alternative in the XOR.
candidate_tree = pm4py.parse_process_tree(
    "->('Receive','Classify',X(*( 'Standard Review','Request Info'),"
    "->('Enhanced Review','Compliance Check')),"
    "X('Supervisor Sign-off',tau),'Decision','Notify')"
)
candidate_net, candidate_im, candidate_fm = pm4py.convert_to_petri_net(
    candidate_tree
)
aug_log = normalized_logs["Aug-Sep"]

# Compare both fitness and precision; fitness alone rewards permissive models.
show_fitness("Aug-Sep normalized vs normative", aug_log,
             normative_net, normative_im, normative_fm)
print("Aug-Sep alignment precision, normative:",
      pm4py.precision_alignments(aug_log, normative_net,
                                 normative_im, normative_fm))
show_fitness("Aug-Sep normalized vs optional-signoff candidate", aug_log,
             candidate_net, candidate_im, candidate_fm)
print("Aug-Sep alignment precision, optional-signoff candidate:",
      pm4py.precision_alignments(aug_log, candidate_net,
                                 candidate_im, candidate_fm))

print("\nCaveats:")
print("- The aggregate variants contain no timestamps, source sequence, resources, or case attributes.")
print("- Therefore source ordering cannot be reconstructed here; the conditional sorter only uses real source:seq fields when present.")
print("- The optional-signoff tree is control-flow-only: it cannot enforce the EUR 50,000 condition or effective date.")
print("- An unconditional optional branch can overgeneralize; review precision and high-value-stratified evidence before adopting it.")
print("- Alignment values from these expanded aggregates need not match the supplied summaries or a timestamped production log.")
```

## 7. Provisional conclusion

The primary explanation for the measured June conformance collapse is a compound observability defect: the UI label changed, a gateway telemetry event entered most traces, and the ETL began ordering Decision and Notify by ingestion time. This account has high confidence (90/100) because each proposed repair produces the predicted staged improvement: 32% fitting raw traces, 58% after label mapping, 81% after removing Queue Routed, and 89% after source-sequence ordering. These repairs explain most of the sudden June deviation without assuming a sudden wave of reviewer misconduct. Their precise contribution still depends on validating mappings and sequence coverage against source records.

A separate real control concern remains. The August policy made Supervisor Sign-off mandatory for high-value claims, so the normative model is incomplete for that period; confidence in this governance gap is very high (95/100). The optional-signoff candidate's improved fitness is consistent with it, but does not prove the candidate is correct because it permits sign-off without the EUR 50,000 condition. Confidence that enhanced-review bypasses actually occurred is low to moderate (35/100): 25 June-July and 30 August-September traces omit a recorded Compliance Check, but event completeness has not been established. Stable aggregate appeals and approvals lower concern about a broad outcome collapse, not about specific control failures, especially given incomplete incident detection.

IT should preserve immutable source event IDs, event occurrence times, ingestion times, source sequence, release version, and actor/resource fields; validate the Classify/Risk Screen equivalence; and document Queue Routed and Manual Override semantics. Process owners should issue a dated, versioned model reflecting the sign-off rule and its eligibility condition, and define which override paths are authorized. Compliance should conduct a blinded, representative source audit of missing-check and override cases, with reviewer and high-value strata, then reconcile findings to event lineage. All teams should retain unresolved cases as unresolved until that evidence exists.

Do not claim that employees broadly bypassed checks, that the June process itself materially changed, that the optional-signoff model is compliant, or that unchanged appeals prove controls were followed. The current evidence supports a measurement-led explanation for the sudden fitness drop plus an August model update need, while leaving a narrower compliance question open.

## 8. Model-governance recommendation

1. **Version models with policy.** Store the normative process tree, policy identifier, effective dates, owner, and approval history together; require a controlled release whenever obligations or exceptions change.
2. **Maintain event-semantic contracts.** Define each business event, source field, UI label, actor, lifecycle meaning, and versioned mapping; treat label changes as data-contract changes even when the business function is claimed to be unchanged.
3. **Set a technical-event policy.** Classify gateway and infrastructure events explicitly as business, technical, or excluded; record lineage and require process-owner review before excluding an event from conformance.
4. **Preserve timestamp provenance.** Keep occurrence time, ingestion time, timezone, source sequence, and ordering rules as separate fields; never silently replace occurrence ordering with warehouse arrival ordering.
5. **Encode data-aware constraints.** Where compliance depends on amount, risk, authorization, or date, use guarded rules or stratified checks; do not treat a control-flow-only tree as proof that those conditions were enforced.
6. **Validate every release after deployment.** Compare versioned event semantics, variants, frequency DFGs, alignment fitness and precision, resource completeness, and case attributes against a baseline; investigate abrupt shifts before drawing conclusions about behavior.
