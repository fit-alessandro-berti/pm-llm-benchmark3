### 5.2 System level

**Operational compliance: materially noncompliant in a bounded, highseverity minority — not wholesale.** The sample yields 6 NONCOMPLIANT (703, 705, 708, 712, 714, 715), 2 JUSTIFIED_EXCEPTION, 3 COMPLIANT, 3 MODEL_OR_SCOPE_DEFECT, 1 indeterminate. The aggregate supports **20 unauthorized autoapprovals** (14 clearly ineligible + 6 postexpiry) out of 312, i.e. 6.4% of the pilotroute population, with 9 further cases indeterminate. Two failure modes are systemic rather than incidental: (a) **eligibility was operatorselectable**, so the pilot's scope control was an honour system (703); (b) **expiry was not enforced in any system**, so timeboxed authority decayed into practice (705, 714, six August cases). Separately, the SoD/COI control family is **unmeasured** (U7): 712 and 715 were found by inspection, not by monitoring, so prevalence must be presumed unknown and swept.

**Model validity: M0 is invalid as a compliance oracle and valid only as a coarse skeleton of the standard route.** It is (i) *unfaithful* (overconstrains rejection, omits SoD), (ii) *incomplete* (no loop, no riskbased routing, no deferred quality, no withdrawal), (iii) *unscoped* (leads, reactivations), (iv) *stale* (alphabet), and (v) *resourceblind*. It should be retained only as a historical baseline for pre2026 standardroute fitness and replaced by the layered architecture in §6.

**Reporting reform (mandatory).** Publish three *separate* metrics and never sum them: (1) **normative conformance** to the applicable ruleset version resolved per case (CS9  valid overlays); (2) **model fitness** to M1; (3) **data completeness/identifiability** (mirroring rate, linkage stability, eligibilitysnapshot coverage). The current "high deviation rate" conflates all three, which is why both sides can quote it.

**Dominant systemic finding.** The deepest defect is *authority and scope management*, not operator behaviour: exceptions were never incorporated, expiry was never systemenforced, eligibility was never computed, scope was never published, identity/COI was never encoded, and logging was changed without conformance impact assessment. Operations' noncompliance is largely downstream of that.

1. **M0 fitness as compliance** — rejected for 707, 709, 711, 713, and for reading 701's linearization as deviance.
2. **Missing notification as misconduct** — rejected for 706 under B4; 29%  30% expected missingness.

1. **"PD3/FD7 amended CS9"** — rejected; overlay validity is scope and timebounded, and PD3's derogation competence remains unproved.

## 6. Revised Normative Architecture

**L0 — Scope and case taxonomy (organizational + data dictionary).** Publish case types: `LEAD_PRESCREEN`, `NEW_ONBOARDING`, `REACTIVATION`, `WITHDRAWAL`, plus terminal states `REJECTED`, `WITHDRAWN`, `CLOSED`. Rules attach per type: CS9's activationtriggered duties attach only where an `Activate_Supplier` can occur; leads follow a distinct intake model (fixes 709 without needing to win the scope argument). Reactivation requires `prior_case_id` and a *logged* Quality_Review whose evidence may be a valid prior certificate (`method=DESK_REVIEW`, `cert_expiry`), rather than a silent skip (fixes 710 without weakening the gate). Case boundaries and effective timestamps are immutable.

**L1 — Control flow in POWL (M1).** Blockstructured routing belongs here: entry (register / reactivate / legacy silent start), a predecision phase with **concurrent** sanctions and a repeatable Request_More_Info mechanism, then XOR of four routes — standard (quality  manual approval, both before activation), PD3 auto route (autoapprove  masterdata validation  activation, quality unordered w.r.t. activation), FD7 provisional route (activation  {quality  retrospective approval}), and reject/withdraw — then Notify  Close. Note the deliberate improvement over M0: CS9 requires quality *before activation*, not before approval, so quality and manual approval are concurrent in the standard route.

**L2 — DECLARE / logskeleton constraints (crosscutting, nonblockstructured).** POWL cannot express these cleanly, so declare them:
- `precedence(Sanctions_Check, Activate_Supplier)` — **nonderogable under every overlay** (708).
- `precedence(Notify_Requester, Close_Case)`; `existence(Notify_Requester)` satisfied by federated CRM evidence.
- `at_most_once(Activate_Supplier)` per case, except the documented PROVISIONALFINAL pattern.
- `absence(Auto_Approve)` unless a valid overlay guard holds (703, 714).
- `response(Activate_Supplier[PROVISIONAL], Quality_Review)` **within 2 business days** (timed constraint).
- `not_coexistence(open Request_More_Info, Activate_Supplier)` — no activation with an open evidence request (the 47case invariant).
- `chain_precedence(Manual_Procurement_Approval[RETRO], spend > cap)`.

**L3 — pandas / data checks.** Overlay window  scope  eligibility snapshot at decision time; risk/country/group predicates; €20,000 cap until retrospective approval; businessday deadline arithmetic with a holiday calendar; label canonicalization via versioned mappings; dedup on `(case_id, activity, source_txn_id)`; CRM reconciliation on stable `notification_id`; missingness accounting reported separately from conformance.

**L4 — Resource and COI (organizational system of record + data checks).** SoD on resolved `person_id`, not aliases (712); alias registry sourced from HR with immutable effective intervals; delegation evidence for any proxy approval; COI disclosure registry with relatedparty and reportingline detection (715); mandatory independent second approver when a relationship is disclosed; foureyes strengthened to two *independent* humans for HIGH risk. Proposed amendment: prohibit or ringfence approver/reviewer relationships within one reporting line — currently only disclosure is required, which is a genuine rule gap.

**L5 — Overlay governance (organizational).** A registry with: issuer and *derogation competence* traced to a CS9 derogation clause; effective/record timestamps; scope predicate; derogated rule IDs; compensating controls; monitoring cadence; expiry **enforced in the UI and API** (hard block, not warning); eligibility **computed, never operatorselected**; mandatory exit/ratification decision before expiry; no renewal by practice. Retroactive ratification may relabel a past deviation as "ratified" but must not delete the breach record (705, 714).

### 7.2 Stated limitations (not hidden)
1. **Guards are not POWLexpressible.** M1's XOR admits the auto and emergency routes unconditionally; SUP703 and SUP714 *fit M1's control flow* and are rejected only by L2/L3. This is intentional and explicit: POWL models routing, guards live in DECLARE/pandas.
2. **Request_More_Info** is encoded as `LOOP(, Request_More_Info)` placed unordered against sanctions, so it may interleave (matching SUP707) but cannot occur after activation. Unboundedness is a real limitation: bound it with an L2/L3 SLA rule (e.g. 3 cycles then escalate). A boundedunrolling fallback is provided.
3. **Provisional vs final activation** share the label `Activate_Supplier` (so SUP704/705 align) and are distinguished by an `activation_type` attribute, not by a new label; a silent transition is *not* used to hide the difference.
4. **Silent case entry** admits legacy/reactivation cases lacking Register_Supplier; this weakens the model and is compensated by a mandatory data rule (`case_type=NEW  Register_Supplier exists`).
5. **New labels** (`Reactivate_Supplier`, `Master_Data_Validation`, `Withdraw_Case`) are *proposed instrumentation*; until deployed, alignment must accept documented attributebased equivalents, or M1 will generate artificial deviations.
6. **Notification** stays mandatory (never silent); CRM evidence is admitted by federation on stable `notification_id`, so mirroring gaps are not punished — but unstable links yield indeterminate, not pass.

### 7.3 Event / datacollection proposal
Appendonly, hashchained event store with bitemporal fields: `event_id`, `case_id`, `case_type`, `prior_case_id`, `activity_code` (canonical) + `activity_version`, `source_system`, `source_txn_id` (immutable dedup key), `effective_ts` (UTC, immutable), `recorded_ts`, `actor_person_id` + `actor_alias_id` + `delegation_id`, `rule_version_id`, `overlay_id`, `eligibility_snapshot_id` (risk, country, group_id, evaluated_ts, evaluator, computed_not_selected=true), `activation_type`, `spend_amount`/`currency`, `notification_id` (immutable UUID; **no mutable text links**), `coi_disclosure_id`, `quality_evidence_id`/`cert_expiry`, `monitoring_run_id`. CRM must emit `notification_id` back into the onboarding stream (or expose a federated conformance view); label mappings and alias mappings are versioned with approval timestamps and validity intervals; every logging change requires a conformance impact assessment.

M1: layered supplier-onboarding conformance architecture.
Self-contained: constructs POWL models, an overlay registry, and data/resource guards.
No external files are read. Ordering checks use the OBSERVED ORDER supplied in the case
material; absolute-date checks use only dates actually stated (unknown dates -> skipped).

from pm4py.objects.process_tree.obj import Operator

# ----------------------------------------------------------------------------- L1: POWL
def T(lbl): return Transition(label=lbl)

def po(nodes, edges=()):
    m = StrictPartialOrder(nodes=list(nodes))
    for a, b in edges:
        m.order.add_edge(a, b)
    return m

def xor(children): return OperatorPOWL(operator=Operator.XOR, children=list(children))

def rmi_block(mode="loop"):
    """Repeatable Request_More_Info. LOOP(tau, rmi) = tau (rmi tau)*  -> zero or more.
    Limitation: unbounded; bound it with an L2/L3 SLA rule. Fallback = bounded unrolling."""
    if mode == "loop":
        return OperatorPOWL(operator=Operator.LOOP, children=[SilentTransition(), T("Request_More_Info")])
    variants = [SilentTransition()]
    for k in (1, 2, 3):
        ts = [T("Request_More_Info") for _ in range(k)]
        variants.append(po(ts, list(zip(ts, ts[1:]))))
    return xor(variants)

def build_m1(rmi_mode="loop"):
    entry = xor([T("Register_Supplier"), T("Reactivate_Supplier"), SilentTransition()])
    # pre-decision phase: sanctions CONCURRENT with the RMI mechanism (unordered nodes)
    pre = po([T("Sanctions_Check"), rmi_block(rmi_mode)])

    # standard route: quality || manual approval, both strictly before activation
    q, m, a = T("Quality_Review"), T("Manual_Procurement_Approval"), T("Activate_Supplier")
    standard = po([q, m, a], [(q, a), (m, a)])

    # PD-3 route: auto approval -> master-data validation -> activation; quality unordered
    au, mdv = T("Auto_Approve"), T("Master_Data_Validation")
    a2, q2 = T("Activate_Supplier"), T("Quality_Review")
    pilot = po([au, mdv, a2, q2], [(au, mdv), (mdv, a2), (au, q2)])

    # FD-7 route: provisional activation first, then quality || retrospective approval
    a3, q3, m3 = T("Activate_Supplier"), T("Quality_Review"), T("Manual_Procurement_Approval")
    emergency = po([a3, q3, m3], [(a3, q3), (a3, m3)])

    decision = xor([standard, pilot, emergency, T("Reject_Supplier"), T("Withdraw_Case")])
    notify, close = T("Notify_Requester"), T("Close_Case")
    return po([entry, pre, decision, notify, close],
              [(entry, pre), (pre, decision), (decision, notify), (notify, close)])

    if isinstance(node, StrictPartialOrder):
        out = set()
        for n in node.nodes: out |= alphabet(n)
        return out

        for ch in node.children: out |= alphabet(ch)
        return out
    lbl = getattr(node, "label", None)
    return {lbl} if lbl and lbl not in ("tau", "silent") else set()

def assess(c):
    seq, dropped = canonical_dedup(mk(c["case_id"], c["labels"], c.get("dup", False)))
    f, ov = [], valid_overlays(c)
    a, s, q, m = (idx(seq, x) for x in
                  ("Activate_Supplier", "Sanctions_Check", "Quality_Review", "Manual_Procurement_Approval"))
    if dropped: f.append(f"DATA: {dropped} duplicate event(s) removed by source_txn_id")
    if c["case_type"] == "LEAD_PRESCREEN":
        f.append("SCOPE: intake case type -> CS-9 activation duties not attached")
    if c["case_type"] == "REACTIVATION" and "Register_Supplier" not in seq:
        f.append("SCOPE: reactivation entry; prior_case_id + cert validity required")
    if a is not None:
        f.append("PASS INV-SANC" if (s is not None and s < a) else "FAIL INV-SANC (non-derogable)")
        if q is None:
            f.append("FAIL quality review absent")
        elif q < a:
            f.append("PASS quality before activation")
        else:
            ok = any(r in ov for r in ("PD3", "FD7"))
            f.append("EXCEPTION quality deferred under " + ",".join(ov) if ok
                     else "FAIL quality after activation without authority")
            if ok and c["quality_offset_bd"] is not None:
                f.append("PASS TIM-Q2BD" if c["quality_offset_bd"] <= 2 else "FAIL TIM-Q2BD")
            elif ok:
                f.append("INDETERMINATE TIM-Q2BD (offset unknown)")
        if "Auto_Approve" in seq:
            f.append("EXCEPTION auto-approval under " + ",".join(ov) if "PD3" in ov
                     else "FAIL GRD-AUTO unauthorized auto-approval")
            f.append("PASS MDV" if ("Master_Data_Validation" in seq or c["mdv"] is True)
                     else "INDETERMINATE MDV (no event/flag)")
        elif m is None or m > a:
            f.append("EXCEPTION retrospective approval under FD7" if "FD7" in ov
                     else "FAIL manual approval not before activation")
        if "FD7" in ov and c["spend_eur"] is not None:
            f.append("PASS GRD-CAP" if c["spend_eur"] <= 20000 else "FAIL GRD-CAP")
    n = idx(seq, "Notify_Requester")
    if n is None and c["crm"] and c["crm"]["stable_id"]:
        f.append("PASS notify via federated CRM stable notification_id (ordering vs Close unverified)")
    elif n is None and c["crm"]:
        f.append("INDETERMINATE notify: CRM candidate with mutable link")
    elif n is None:
        f.append("FAIL notify absent")
    else:
        cl = idx(seq, "Close_Case")
        f.append("PASS INV-NOTIFY" if cl is None or n < cl else "FAIL INV-NOTIFY")
    if c["approver"] not in (None, "SYS") and c["requester"] == c["approver"]:
        f.append("FAIL SoD: requester == approver (resolved person_id)")
    if c["relationship"] and not c["coi_disclosed"]:
        f.append("FAIL COI disclosure duty")
    if c["activation_date"] is None:
        f.append("NOTE: activation date unknown -> temporal overlay checks skipped")
    return dict(case_id=c["case_id"], overlays=",".join(ov) or "CS9-only", findings=" | ".join(f))
