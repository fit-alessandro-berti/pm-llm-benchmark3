The correct identity per case:

total_flow_time = upstream_elapsed + (join_ready - fork_release) + downstream_queue + final_service

and the branch-level view decomposes (join_ready - fork_release) = max_i (queue_i + service_i), where each branch's (queue_i + service_i + sync_i) = join_ready - fork_release for every branch. So each branch's full timeline (queue+service+sync) equals the fork-join elapsed time. Summing across branches triple-counts. The sync waits are the "slack" that aligns each branch's timeline to the maximum; only the critical branch has zero sync.

So the identity: for each branch i: queue_i + service_i + sync_i = join_ready - fork_release. Summing over i: (queue_i + service_i) + sync_i = 3*(join_ready - fork_release). total_flow_time = upstream_elapsed + max_i(queue_i + service_i) + downstream_queue + final_service

Definitions section: formal formulas.

Let case index c, branches i  {A, B, C}. Timestamps as minutes.

- t_arr(c): arrival
- t_fork(c): fork_release
- s_i(c), e_i(c): branch start/end
- t_fs(c), t_fe(c): final start/end

Components:
- upstream_elapsed(c) = t_fork(c)  t_arr(c)
- queue_i(c) = s_i(c)  t_fork(c)  0
- service_i(c) = e_i(c)  s_i(c)
- completion offset: d_i(c) = queue_i(c) + service_i(c) = e_i(c)  t_fork(c)
- join_ready(c) = max_i e_i(c) = t_fork(c) + max_i d_i(c)
- sync_i(c) = join_ready(c)  e_i(c) = max_j d_j(c)  d_i(c)  0 (zero iff i critical)
- fork_join_elapsed(c) = join_ready(c)  t_fork(c) = max_i d_i(c)
- downstream_queue(c) = t_fs(c)  join_ready(c)
- final_service(c) = t_fe(c)  t_fs(c)
- total_flow_time(c) = t_fe(c)  t_arr(c)

Additive identity:
total_flow_time(c) = upstream_elapsed + fork_join_elapsed + downstream_queue + final_service.

Double-counting proof: For every branch i: queue_i + service_i + sync_i = (s_i  t_fork) + (e_i  s_i) + (join_ready  e_i) = join_ready  t_fork = fork_join_elapsed. So each branch's three components tile exactly the same fork-join interval. Summing over the three branches gives 3 × fork_join_elapsed; in particular _i sync_i = 3·fork_join_elapsed  _i (queue_i + service_i)  fork_join_elapsed  max_i(...). If an analyst adds all branch sync waits into the case total (e.g., upstream + (queue+service) + sync + downstream + final), the fork-join interval is counted three times, inflating total flow time by 2 × fork_join_elapsed. The correct rule: attribute fork_join_elapsed once, via the critical branch (max), and treat sync_i as non-additive diagnostics (waiting time of completed work, i.e., inventory holding). Alternatively, one can allocate the fork-join interval across branches with shares summing to 1 (e.g., d_i / d_i), but never sum raw branch timelines.

Numerical example (F02): queues+services: A 50, B 60, C 25; syncs: 10, 0, 35; each row sums to 60 = fork-join elapsed; naive sum of everything = 180 = 3×60.

Also, critical branch definition: i*(c) = argmax_i e_i(c) (equivalently argmax d_i). Ties: deterministic handling — e.g., alphabetical by branch label, or report tie explicitly; in this data there are no exact ties in raw data, but counterfactual CF2 creates ties (F02, F06 at exactly 50). Handle by deterministic tie-break (alphabetical order A<B<C) and flag.

```python
def simulate_final(jr, n_servers=2, service=20):
    """Treat downstream wait as a pure FCFS resource queue and re-time the
    final station. Returns new final_end per case (order = join_ready order)."""
    order = np.argsort(jr, kind="stable")          # FCFS by readiness
    free = np.zeros(n_servers)                     # server free-at times
    new_end = np.zeros(len(jr))
    for k in order:
        s = max(jr[k], free.min())
        j = int(np.argmin(free))
        free[j] = s + service
        new_end[k] = s + service
    return new_end
```

Let me define: for case c and branch i  {A,B,C}, all timestamps in minutes:

- t_arr(c), t_fork(c), s_i(c), e_i(c), t_fs(c), t_fe(c).

Components:
1. upstream_elapsed(c) = t_fork(c)  t_arr(c)
2. queue_i(c) = s_i(c)  t_fork(c) ( 0 by rule A2)
3. service_i(c) = e_i(c)  s_i(c)
4. completion offset d_i(c) = queue_i(c) + service_i(c) = e_i(c)  t_fork(c)
5. join_ready(c) = max{e_A, e_B, e_C}(c) [inferred; not logged]

    order = np.argsort(jr, kind="stable")
    free = np.full(n_servers, -np.inf)
    end = np.empty(len(jr))
    for k in order:
        j = int(np.argmin(free))
        s = max(jr[k], free[j])
        free[j] = s + service
        end[k] = s + service
    return end
