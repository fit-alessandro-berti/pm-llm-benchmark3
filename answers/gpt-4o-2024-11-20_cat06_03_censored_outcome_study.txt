## 1. Target Definition

### Primary Target Definition:
- **Target**: Probability of default within 90 days of activation, conditioned on activation.
- **Prediction Time**: At a fixed prefix length or at a given elapsed time from the case start (e.g., immediately after `Credit Review` is completed for the first time).
- **Time Horizon**: 90 days post `Account Activated` timestamp.
- **Unit of Analysis**: A credit application case.
- **Population**: All credit applications initiated within the study period (1 January 2024 to 31 December 2025). The population includes both activated and non-activated cases.
- **Estimand**: Conditional probability of default among activated accounts, accounting for censoring and competing risks at earlier steps (withdrawal, transfer, rejection).

### Alternative Target:
**Multi-State Modeling Across All Cases**:
- Define target as competing risks for all cases:
   1. `default_90d` if activated and defaulted within 90 days.
   2. `no_default` if no default occurs within 90 days of activation.
   3. `non-activation` for cases withdrawn, rejected, transferred, or still open.
   
This formulation addresses the broader business question of differentiating case outcomes irrespective of activation. However, it introduces strong counterfactual assumptions on what the outcome for non-activated cases might have been under different policies.

### Justification for Choosing the Primary Target:
The chosen target avoids counterfactual assumptions about non-activated cases, limits the scope to observed activations, and aligns well with operational needs (understanding conditional risk among activated customers). This focuses the study on decision-critical applications while still allowing secondary exploration of broader process dynamics.

## 3. Censoring and Missing-Label Strategy

### Types of Missingness:
1. **Right Censoring**: Cases remain open by the data-extraction date or are transferred unlinked.
2. **Delayed Labels**: Activation occurred but 90-day default outcome feed is incomplete.
3. **Selection through Activation**: Default risk is undefined or unobserved for non-activated cases.
4. **Permanently Missing Feeds**: Certain partner-originated activated accounts lack outcome feeds.

### Primary Strategy:
Use a survival/competing-risks framework:
- Model default as competing with non-activation outcomes (withdrawal, rejection, transfer).
- Handle delayed labels via a "matured-window" approach, relying on only observable matured labels for training but imputing/informing uncensored likelihoods during risk estimation.

### Sensitivity Analysis:
1. Estimate the effect of missing outcome feeds (partner-originated).
2. Compare pre- and post-policy periods explicitly for shifts in activation/default dynamics.

### Assumption Testing:
- Test partially for changes in activation thresholds and outcome rates pre/post-policy change.
- Assess linkage-table validity empirically for transfer follow-up cases.

## 4. Prefix Extraction

### Approach:
1. **Fixed-Length Prefixes**: Extract sequences of 3, 5, or other fixed number of events.
2. **Elapsed-Time Prefixes**: Use prefixes up to a set time horizon (e.g., 14 days after `Application Started`).

### Handling Specific Data Issues:
- **Short Cases**: Retain incomplete prefixes; flag as such for feature encoding.
- **Document Loops**: Collapse multiple `Request Documents` loops to avoid over-counting repeated work.
- **Activity Renaming**: Standardize renamed activities post-migration.

---

## 5. Process-Aware Features

### Process Features:
1. **Control-flow**: Transition frequencies and loop counts (e.g., loops in `Request Documents`).
2. **Timing**: Event inter-arrival times and overall prefix duration.
3. **Resource/Queue**: Specialist handoffs or delays (`org:resource` counts/changes).
4. **Calendar**: Day of the week, quarter/holiday time effects.
5. **Historical Reference**: Relative changes in `risk_score` over time.

### Feature Categories:
- **Static**: `case:region`, `case:channel`.
- **Prefix-derived**: Transition entropy, time to `Credit Review`.
- **Historical**: Resource experience adjusted to event time (based on extracted snapshots).

## 6. Leakage Audit

| **Feature or Data Element** | **Leakage or Bias Risk**                 | **Valid Availability Rule**                          | **Keep/Repair/Drop** | **Rationale**                                                                 |
|-----------------------------|------------------------------------------|-----------------------------------------------------|-----------------------|-------------------------------------------------------------------------------|
| `final_limit`               | Post-decision information               | Drop                                                | Not available at prediction time.                                            |
| `decision_reason`           | Post-accept/reject                      | Drop                                                | Leaks end-state information.                                                 |
| `collection_status`         | Direct default signal after activation  | Drop                                                | Not observable at time of activation prediction.                             |
| Future events               | Future knowledge of process             | Drop                                                | Must exclude events beyond prediction time.                                  |
| `documents_total`           | Same-day updates leak post-prefix info  | Repair                                              | Truncate to value as of prefix extraction time.                              |
| Updated `risk_score`        | Retrospective model adjustment          | Repair                                              | Use only up to last visible event in prefix.                                 |
| Resource experience         | Incorrect retrospect calculation        | Repair                                              | Adjust to experience as of historical event time.                            |
| `label_available_at`        | Metadata-derived bias                   | Drop                                                | Not predictive; strictly for labeling mechanics.                             |

## 7. Validation Design

### Temporal Cross-Validation:
- Split cohorts by `Application Started` time, ensuring no case crosses splits.
- Ensure at least one pre-policy, one post-policy, and one mixed split:
  - Train: Jan 2024–June 2025, Validate: July–Oct 2025, Test: Nov–Dec 2025.
- Consider calibration drift pre/post-policy.

### Metrics:
- C-index (survival models), Brier Score, time-dependent AUC.
- Calibration curves for default probability.

---

## 8. Limitations and Decision-Use Boundary

1. **Predictive Nature**: Explains observed default risk, not causal drivers.
2. **Selection Bias**: Reflects activation trends under historic policy, not counterfactual defaults.
3. **Deployment Feedback**: Model performance will shift as policies change activation dynamics.

Deployment could skew:
1. Activation thresholds (new population mix).
2. Collection behavior (fewer defaults with stricter management).
3. Document workflows (automation).

import pandas as pd
from pm4py.objects.log.importer.csv import factory as csv_importer
from pm4py.util.constants import PARAMETER_CONSTANT_TIMESTAMP_KEY
from pm4py.algo.transformation.log_to_features import factory as feature_factory
from datetime import timedelta

# Load the event log.
df = pd.read_csv("applications_events.csv")
df['time:timestamp'] = pd.to_datetime(df['time:timestamp'])

# Format the dataframe for PM4Py.
from pm4py.objects.log.util import dataframe_utils
df = dataframe_utils.convert_timestamp_columns_in_df(df)
df = pm4py.format_dataframe(df, case_id='case:concept:name', activity_key='concept:name',
                            timestamp_key='time:timestamp')

# Censor late labels.
cutoff = pd.Timestamp("2026-02-15")
df = df[df['time:timestamp'] <= cutoff]

# Assign maturity and censoring information.
case_end = df.groupby('case:concept:name')['time:timestamp'].max()
df['case:end_time'] = df['case:concept:name'].map(case_end)
df['censored'] = (df['case:end_time'] > cutoff).astype(int)

# Filter prefixes using PM4Py.
prefix_length = 3
prefixes = pm4py.algo.transformation.prefix_extraction.factory.apply(df, parameters={"prefix_length": prefix_length})

# Generate process-aware features.
features = feature_factory.apply(prefixes, parameters={"timestamp_key": "time:timestamp"})

# Temporal train-test split by case start time.
train = prefixes[prefixes['time:timestamp'] < pd.Timestamp("2025-07-01")]
test = prefixes[prefixes['time:timestamp'] >= pd.Timestamp("2025-07-01")]

# Output cohort flow counts and a leakage audit summary.
cohort_counts = train['case:concept:name'].nunique(), test['case:concept:name'].nunique()
print("Cohort Counts:", cohort_counts)
