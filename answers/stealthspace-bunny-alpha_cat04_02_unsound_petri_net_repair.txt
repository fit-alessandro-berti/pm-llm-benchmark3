# 1. Executive Verdict

Yes: it is a workflow net in the structural PM4Py sense—there is one source, one sink, and every node is on a source-to-sink path. It is not sound and does not enforce mandatory analysis. The waiver join requires only `p_waived` before producing `p_decision`, so `t_authorize` can fire while `p_analysis` still holds a token. Authorization consumes `p_decision` irreversibly. Analysis can then produce an unconsumable `p_analysis_done` token, or the analysis token can remain beside the sink token. Thus, a token in `sink` does not mean exact `fm` has been reached; a correct standard-review trace does not repair the waiver bypass.

# 2. Structural Diagnosis

All displayed arc weights are one.

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| Initial marking and `t_register` | Start with one unregistered case and create one ready case. | `im = {source: 1}`; `t_register` consumes it and creates one `p_ready` token. | Ordinary registration works. |
| `t_split` | Start mandatory analysis and one review alternative in parallel. | Consumes the single `p_ready` token and creates one `p_analysis` and one `p_review` token. | Correct parallel start. |
| Standard-review alternative | Choose and complete a standard review. | `t_standard_review` consumes `p_review` and creates `p_review_done`. Because `p_review` is consumed, standard review and waiver cannot both occur in the same execution. | Correct exclusive alternative. |
| Waiver alternative | Choose and record a waiver. | `t_waive_review` consumes `p_review` and creates `p_waived`. | A waiver token is available without any analysis-completion token. |
| `t_join_normal` | Require both analysis completion and standard-review completion. | Requires `p_analysis_done` and `p_review_done`, consumes both, and creates `p_decision`. | Correct normal-route synchronization. |
| `t_join_waived` | Require both waiver completion and analysis completion. | Requires only `p_waived` and creates `p_decision`; it does not inspect `p_analysis_done`. | Principal defect: the waiver route bypasses the analysis barrier. |
| `t_authorize` | Authorize only after mandatory analysis and a completed review outcome. | Requires only `p_decision`, consumes it, and creates one `sink` token. | Can authorize before analysis. Once authorized, another authorization is impossible because `p_decision` has been consumed. |
| Initial/final markings | Begin with one source token and finish with exactly one sink token. | `im` is reachable and has a correct standard-review path to exact `fm`. The defective waiver trace can instead reach `{p_analysis: 1, sink: 1}`. | Existence of a proper standard trace does not imply that every terminal execution reaches `fm`. |
| Source-to-sink connectivity | Every modeled element should participate in the workflow. | Every original node lies on at least one structural source-to-sink path, including the defective route `p_review  t_waive_review  t_join_waived  p_decision  t_authorize  sink`. | Structural reachability of that route does not make it a sound completion route. |

There are no unreachable original nodes or duplicate initial/final tokens. The problem is behavioral, not syntactic or merely a failure of the workflow-net connectivity check.

# 3. Marking-Based Counterexample

The following tables show only nonzero token counts; every omitted place has zero tokens.

### Correct standard-review trace

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---:|---|---|---|---|
| 0 | — | `{source: 1}` | `t_register` | Initial marking. |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | Registration consumes the source token. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token is created in each parallel branch. |
| 3 | `t_analyze` | `{p_review: 1, p_analysis_done: 1}` | `t_standard_review`, `t_waive_review` | Analysis completes while review remains available. |
| 4 | `t_standard_review` | `{p_analysis_done: 1, p_review_done: 1}` | `t_join_normal` | The standard-review outcome is recorded. |
| 5 | `t_join_normal` | `{p_decision: 1}` | `t_authorize` | Both normal-route requirements are consumed. |
| 6 | `t_authorize` | `{sink: 1}` | None | This is exactly `fm`, not merely a marking containing a sink token. |

This trace establishes **option to complete** for the initial marking. It does not establish that all other executions also complete correctly.

### Defective waiver trace

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---:|---|---|---|---|
| 0 | — | `{source: 1}` | `t_register` | Start from `im`. |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | Legal registration. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | Both parallel branches receive a token. |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `t_analyze`, `t_join_waived` | The waiver is recorded while analysis is still pending. |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, `t_authorize` | The defective join creates a decision without consuming or requiring analysis completion. |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `t_analyze` | `t_authorize` occurs **before** `t_analyze`. The marking contains a sink token but is not exact `fm`. |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | None | Analysis can consume `p_analysis`, but its output cannot be consumed. `p_decision` is already gone, so authorization cannot occur again. |

At step 5, the pending analysis token can still be consumed by `t_analyze`; it is not immediately stuck. However, consuming it creates a different leftover token in `p_analysis_done`. That place has no outgoing arc. Moreover, `t_authorize` has already consumed the only `p_decision`, and `sink` has no outgoing arc.

The final marking in this second table is a deadlock—a *proper completion* in workflow-net terminology—but it is **not** the designated final marking. That is a soundness failure. Also, `p_analysis` cannot be covered by exact `fm`: it is reachable from `im`, but after authorization there is no route back to it.

# 4. Minimal-Repair Alternatives

For this comparison, retain the original places and transitions. Each added or removed arc costs one unit, as does each added or removed place or transition; a weight change also costs one. Renaming or relabeling is cost-free and provides no semantic repair. Thus the cost is:

\[
|\Delta A| + |\Delta P| + |\Delta T| + |\Delta W|
\]

No policy relaxation is included in R1 or R2.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| **R1: Gate the dedicated waiver join** | Add `p_analysis_done  t_join_waived`. No removals. | **1**: one added arc | Fully preserves mandatory analysis, either review alternative, and exact final consumption. | `t_join_waived` now requires both `p_waived` and `p_analysis_done`. | Two silent, case-specific joins must remain synchronized in policy. A future edit could weaken one. |
| **R2: Centralize the analysis gate at authorization** | Remove `p_analysis_done  t_join_normal`; add `p_analysis_done  t_authorize`. | **2**: one removed arc and one added arc | Fully preserves mandatory analysis, either review alternative, and exact final consumption. | Either review join may create `p_decision` before analysis is complete, but `t_authorize` requires both `p_decision` and `p_analysis_done`. | The final authorization gate becomes especially critical. The earlier review-only joins can misleadingly look like complete case synchronization. |

R1 deliberately does **not** add `p_review_done  t_join_waived`. That input would be impossible on the waiver route: `t_waive_review` already consumes the sole `p_review` token, preventing `t_standard_review` from ever creating `p_review_done`. The correct waiver synchronization is therefore **waiver recorded AND analysis complete**.

### Minimality

- **Zero edits** cannot fix the defect because the waiver route remains able to create `p_decision` before analysis.
- **R1 is globally minimal within the retained-element edit model:** one added arc is sufficient, and zero edits is insufficient. It is also the cheaper faithful repair.
- **R2 is minimal for the stated final-authorization-gate strategy.** Adding `p_analysis_done  t_authorize` alone would be wrong: `t_join_normal` would consume the analysis-completion token before authorization, making the normal route unable to authorize. Therefore both the addition and removal are necessary for this strategy. A different two-arc implementation may exist, but that does not make R2 a one-edit solution.
- The two repairs do not tie: R1 costs one and R2 costs two. R2 is selected only if centralizing the barrier at authorization is preferable to maintaining separate, correctly gated joins.

For R1, the marking invariant is direct: after `t_split`, there is one analysis token and one review-choice token. The review choice consumes `p_review` and creates exactly one of `p_review_done` or `p_waived`. `t_analyze` creates exactly one `p_analysis_done`. The corresponding join consumes that token together with the appropriate review-outcome token, creating one `p_decision`. Only `t_authorize` consumes `p_decision`, and it creates exactly one `sink` token. No transition recreates the consumed intermediate tokens, so the two review outcomes cannot both fire and no terminal marking can contain an additional token.

# 5. Corrected PM4Py Code

This standalone implementation selects **R1**.

```python
import pm4py
from pm4py.objects.petri.net.obj import PetriNet, Marking
from pm4py.objects.petri.net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for place in {
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
}:
    repaired_net.places.add(place)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition(
    "t_standard_review", "Perform Standard Review"
)
waive_review = PetriNet.Transition(
    "t_waive_review", "Record Review Waiver"
)
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for transition in {
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
}:
    repaired_net.transitions.add(transition)

petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

petri_utils.add_arc_from_to(
    p_analysis_done, join_normal, repaired_net
)
petri_utils.add_arc_from_to(
    p_review_done, join_normal, repaired_net
)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

# R1: the waiver synchronization requires analysis completion too.
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(
    p_analysis_done, join_waived, repaired_net
)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1

repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

This block assumes `net`, `im`, and `fm` from the original model exist, and that the repaired variables from the preceding block have been defined.

```python
import pm4py
from pm4py.objects.petri.net.utils import petri_utils


def marking_to_string(marking):
    entries = [
        f"{place.name}={marking.get(place, 0)}"
        for place in sorted(marking, key=lambda p: p.name)
        if marking.get(place, 0) != 0
    ]
    return "{" + ", ".join(entries) + "}"


def enabled_names(model_net, marking):
    return sorted(
        transition.name
        for transition in pm4py.get_enabled_transitions(model_net, marking)
    )


def fire_named(model_net, marking, transition_name):
    matches = [
        transition
        for transition in model_net.transitions
        if transition.name == transition_name
    ]

    if len(matches) != 1:
        raise ValueError(
            f"Expected one transition named {transition_name!r}; "
            f"found {len(matches)}"
        )

    transition = matches[0]
    enabled = set(pm4py.get_enabled_transitions(model_net, marking))

    if transition not in enabled:
        raise ValueError(
            f"Cannot fire {transition_name}; "
            f"enabled transitions are {enabled_names(model_net, marking)}"
        )

    next_marking = marking.copy()
    petri_utils.fire_transition(transition, next_marking)
    return next_marking


def print_trace(model_net, initial_marking, sequence, target_marking):
    marking = initial_marking.copy()

    print(
        f"  0: {marking_to_string(marking)}; "
        f"enabled={enabled_names(model_net, marking)}; "
        f"exact_final={marking == target_marking}"
    )

    for step, transition_name in enumerate(sequence, start=1):
        marking = fire_named(model_net, marking, transition_name)
        print(
            f"  {step}: {transition_name} -> {marking_to_string(marking)}; "
            f"enabled={enabled_names(model_net, marking)}; "
            f"exact_final={marking == target_marking}"
        )

    return marking


models = {
    "original": (net, im, fm),
    "repaired": (repaired_net, repaired_im, repaired_fm),
}

for model_name, (model_net, initial_marking, final_marking) in models.items():
    print(f"\nDiagnostics for {model_name}")

    workflow_result = pm4py.check_is_workflow_net(model_net)
    print(f"  check_is_workflow_net: {workflow_result}")

    soundness_result = pm4py.check_soundness(
        model_net,
        initial_marking,
        final_marking,
        print_diagnostics=True,
    )
    print(f"  check_soundness: {soundness_result}")

    initial_enabled = pm4py.get_enabled_transitions(
        model_net, initial_marking
    )
    print(
        "  initially enabled:",
        sorted(transition.name for transition in initial_enabled),
    )

    reachability_graph = pm4py.convert_to_reachability_graph(
        model_net, initial_marking, final_marking
    )
    print("  reachability graph computed successfully.")

print("\nOriginal: correct standard-review trace")
print_trace(
    net,
    im,
    [
        "t_register",
        "t_split",
        "t_analyze",
        "t_standard_review",
        "t_join_normal",
        "t_authorize",
    ],
    fm,
)

print("\nOriginal: waiver authorization before analysis")
print_trace(
    net,
    im,
    [
        "t_register",
        "t_split",
        "t_waive_review",
        "t_join_waived",
        "t_authorize",
        "t_analyze",
    ],
    fm,
)

print("\nRepaired: standard-review trace")
print_trace(
    repaired_net,
    repaired_im,
    [
        "t_register",
        "t_split",
        "t_analyze",
        "t_standard_review",
        "t_join_normal",
        "t_authorize",
    ],
    repaired_fm,
)

print("\nRepaired: waiver trace with mandatory analysis")
print_trace(
    repaired_net,
    repaired_im,
    [
        "t_register",
        "t_split",
        "t_waive_review",
        "t_analyze",
        "t_join_waived",
        "t_authorize",

    repaired_fm,

print("\nRepaired: negative early-waiver-join test")
try:
    print_trace(
        repaired_net,
        repaired_im,
        [
            "t_register",
            "t_split",
            "t_waive_review",
            "t_join_waived",
            "t_authorize",

except ValueError as error:
    print(f"  Expected failure: {error}")
else:
    raise AssertionError("The repaired net allowed an analysis bypass.")
```

The expected qualitative difference is:

- **Original:** the workflow-net check returns `True`; soundness returns `False`. There is an option-to-final path, but also the terminal mismatched marking `{p_analysis_done: 1, sink: 1}`.
- **Repaired R1:** both checks return `True`. Standard review and waiver each have proper completion paths.
- After `t_waive_review`, the original enables both `t_analyze` and `t_join_waived`. R1 enables only `t_analyze`. After analysis, R1 enables `t_join_waived`.
- Both reachability graphs are computed without assuming their cardinalities or the exact diagnostic text produced by a particular PM4Py version.

# 7. Repair Trade-Offs and Residual Risks

- **Review-outcome distinguishability:** R1 preserves `p_review_done` for standard review and `p_waived` for waiver review. They remain distinguishable until the shared `p_decision` place. After that merge, the final marking alone does not reveal which review outcome occurred, so transition-level audit logging matters.
- **Silent transitions and duplicate behavior:** `t_split`, `t_join_normal`, and `t_join_waived` have no visible labels. They need not create duplicate behavior in R1: the single `p_review` token permits exactly one review transition, and the exclusive outcome markers prevent both joins from firing. Nevertheless, silent transitions can confuse users and maintainers; logs should record both the selected review transition and its corresponding join.
- **Soundness versus business alignment:** Soundness proves option to complete, proper deadlocks at exact `fm`, and related behavioral conditions for the supplied initial/final markings. It does not establish that a business-required activity is mandatory. A model that makes analysis optional could still be sound because it offers an analysis-before-authorization execution. R1’s business alignment comes from its explicit input arcs, not merely from a successful diagnostic.
- **Positive regression tests:** Execute both standard-review and waiver routes, with analysis before review and review before analysis. Every trace should end in exact `repaired_fm`, have no enabled transitions at completion, and contain `t_analyze` before `t_authorize`.
- **Negative regression tests:** For both review outcomes, attempt to proceed to authorization without analysis. Also test attempts to perform both reviews, authorize before the appropriate join, and continue after the sink token is created. Every prohibited action must fail the enabledness check.
- **Detecting an accidental bypass:** Statically assert that `p_analysis_done` is an input to every transition producing `p_decision`—both joins in R1. Dynamically assert that every authorization event has a preceding `t_analyze` event and that no sink-containing marking has pending analysis or analysis-completion tokens. If either review join later loses its analysis input, these structural and trace tests should fail.

# 8. Final Recommendation

Deploy **R1**: add only `p_analysis_done  t_join_waived`. It is the least-cost faithful repair and preserves both review alternatives and their case-specific synchronization. Both producers of `p_decision` then require proof of analysis, while the waiver route correctly requires `p_waived` rather than the incompatible `p_review_done`.

Keep **R2** as the fallback: remove `p_analysis_done  t_join_normal` and add `p_analysis_done  t_authorize`. This centralizes mandatory analysis at the final authorization gate and allows a review decision to wait for analysis. It is minimal for that two-arc strategy, but costs one additional edit and makes the final gate especially critical.

Prefer R1 unless a single authorization barrier materially simplifies auditing or future rework. Under either repair, test both review outcomes in both branch-completion orders and verify that every authorization follows `t_analyze`. A successful soundness result should supplement, not replace, those policy-specific controls.
