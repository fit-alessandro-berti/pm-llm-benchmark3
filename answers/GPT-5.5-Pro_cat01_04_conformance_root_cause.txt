## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels [Classify displayed/logged as Risk Screen]
UI_release -> hidden_label_mapping_contract
hidden_label_mapping_contract -> alignment_moves [Risk Screen log moves; Classify model moves]

event_gateway_change -> recorded_labels [Queue Routed inserted]
technical_event_policy -> alignment_moves [technical events treated as business deviations]

ETL_change -> recorded_order [Decision/Notify ordered by ingestion time]
source_sequence_available -> recorded_order [repair path if used]
recorded_order -> alignment_moves [Notify-before-Decision deviations]

policy_change -> true_process [Supervisor Sign-off required for high-value claims]
policy_change -> normative_model [model becomes incomplete if not versioned]
high_value_status_hidden -> alignment_moves [sign-off cannot be judged conditionally]

reviewer_behavior -> true_process [Manual Override; possible compliance bypass]
routing_mistakes -> reviewer_behavior [override used to correct routing]
event_extraction_loss -> recorded_labels [possible missing Compliance Check]
resource_logging_defect -> event_extraction_loss

true_process -> business_outcomes
true_process -> recorded_labels
recorded_labels -> alignment_moves
recorded_order -> alignment_moves
normative_model -> alignment_moves
alignment_moves -> measured_fitness
case_mix -> business_outcomes
incident_detection_incompleteness -> business_outcomes
```

The observed pattern is best explained as a layered failure rather than one clean cause. The first June collapse is highly consistent with recorded-log semantics changing faster than the conformance setup: `Classify` became `Risk Screen`, `Queue Routed` was introduced, and `Decision`/`Notify` ordering became vulnerable to ingestion-time sequencing. The staged repairs are abductively powerful because each targeted correction removes a specific family of deviations and improves fitness in the expected order.

August-September adds a different mechanism. The process itself changed for high-value claims when `Supervisor Sign-off` became mandatory, but the normative model remained control-flow-only and unversioned. The optional sign-off candidate therefore improves measured fitness, yet it is not necessarily the correct compliance model because it permits sign-off without enforcing the EUR 50,000 condition.

Unchanged approval, cycle-time, and appeal outcomes do not prove the deterioration is merely a data error. Conformance can detect control-flow, ordering, and authorization issues before customer outcomes move. Conversely, unchanged outcomes also do not rule out noncompliance: incident detection is incomplete, missing compliance checks may be rare but serious, and appeals are an indirect lagging indicator. The defensible conclusion is mixed causality with residual compliance risk.

def split_trace(trace_string):
    return [activity.strip() for activity in trace_string.split(",")]


def repair_adjacent_notify_decision(activities):
    """
    Aggregate-level approximation of source-sequence ordering.
    In the real log, do not use this heuristic; sort by source sequence number.
    """
    repaired = []
    i = 0
    while i < len(activities):
        if (
            i + 1 < len(activities)
            and activities[i] == "Notify"
            and activities[i + 1] == "Decision"
        ):
            repaired.extend(["Decision", "Notify"])
            i += 2
        else:
            repaired.append(activities[i])
            i += 1
    return repaired


def expand_to_event_log_string(
    variant_rows,
    label_map=None,
    remove_activities=None,
    repair_order=False,
):
    label_map = label_map or {}
    remove_activities = set(remove_activities or [])
    trace_lines = []

    for trace_string, count in variant_rows:
        activities = split_trace(trace_string)
        activities = [label_map.get(activity, activity) for activity in activities]
        activities = [activity for activity in activities if activity not in remove_activities]

        if repair_order:
            activities = repair_adjacent_notify_decision(activities)

        trace_lines.extend([",".join(activities)] * count)

    return "\n".join(trace_lines)


def make_log(
    variant_rows,
    label_map=None,
    remove_activities=None,
    repair_order=False,
):
    log_string = expand_to_event_log_string(
        variant_rows,
        label_map=label_map,
        remove_activities=remove_activities,
        repair_order=repair_order,
    )
    return pm4py.parse_event_log_string(log_string)


def discover_frequency_dfg(log):
    dfg_result = pm4py.discover_dfg(log)
    # Some PM4Py versions return (dfg, start_activities, end_activities).
    if isinstance(dfg_result, tuple):
        return dfg_result[0]
    return dfg_result


def safe_precision_alignments(log, net, im, fm):
    """
    Use top-level PM4Py precision if available; otherwise fall back to the
    algorithm module used in many PM4Py installations.
    """
    if hasattr(pm4py, "precision_alignments"):
        return pm4py.precision_alignments(log, net, im, fm)

    from pm4py.algo.evaluation.precision import algorithm as precision_evaluator

    return precision_evaluator.apply(
        log,
        net,
        im,
        fm,
        variant=precision_evaluator.Variants.ALIGN_ETCONFORMANCE,
    )


def alignment_summary(log, net, im, fm, label):
    diagnostics = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    fitness = pm4py.fitness_alignments(log, net, im, fm)

    total = len(diagnostics)
    zero_cost = 0
    total_cost = 0
    move_counter = Counter()

    for alignment in diagnostics:
        cost = alignment.get("cost", 0)
        total_cost += cost
        if cost == 0:
            zero_cost += 1

        for move in alignment.get("alignment", []):
            # Typical move representation: (model_activity, log_activity).
            if isinstance(move, tuple) and len(move) >= 2:
                model_move, log_move = move[0], move[1]
                if model_move == ">>" or log_move == ">>":
                    move_counter[(model_move, log_move)] += 1

    print(f"\n=== {label} ===")
    print(f"traces: {total}")
    print(f"zero-cost traces: {zero_cost} ({zero_cost / total:.1%})")
    print(f"mean raw alignment cost: {total_cost / total:.4f}")
    print(f"fitness object: {fitness}")
    print("top non-synchronous moves:")
    for move, count in move_counter.most_common(10):
        print(f"  {move}: {count}")

    return {
        "label": label,
        "total_traces": total,
        "zero_cost_share": zero_cost / total,
        "mean_cost": total_cost / total,
        "fitness": fitness,
        "top_moves": move_counter.most_common(10),
    }


def print_top_dfg_edges(log, label, n=12):
    dfg = discover_frequency_dfg(log)
    print(f"\n--- Top DFG edges: {label} ---")
    for edge, count in sorted(dfg.items(), key=lambda item: item[1], reverse=True)[:n]:
        print(f"{edge}: {count}")

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a combination of logging-semantic and extraction/order changes, not a sudden organization-wide breakdown in reviewer behavior. Confidence in that primary explanation is high, around 85%. The strongest evidence is the staged recovery: June-July fitness improves substantially after mapping `Risk Screen` to `Classify`, improves again after removing `Queue Routed`, and improves again when `Decision` and `Notify` are ordered by source-system sequence. Those repairs correspond exactly to the 2026-05-31 UI release, 2026-06-03 gateway change, and 2026-06-15 ETL timestamp change.

A real compliance problem may still remain. Confidence in a residual operational concern is moderate, around 45%, not negligible but not proven. The unresolved risk is concentrated in enhanced-review traces without a recorded `Compliance Check`, the increase in `Manual Override`, and the August-September sign-off regime. `Supervisor Sign-off` itself is not evidence of employee noncompliance; it is expected after the August policy change. But the existing process tree became obsolete because it was not updated and because it lacks the high-value attribute condition. At the same time, the missing compliance checks cannot be dismissed as data noise until source records are audited.

Immediate IT actions should be to restore timestamp provenance, use source sequence for ordering, document label mappings, classify technical events, and repair missing-resource extraction. Process owners should version the normative model from 2026-08-01 and create a data-aware sign-off rule tied to the EUR 50,000 threshold. Compliance should audit enhanced-review cases missing compliance checks and analyze `Manual Override` by reviewer, reason, authorization, and claim type.

What must not be claimed yet: that employees caused the conformance collapse; that all missing compliance checks are harmless extraction defects; that the optional sign-off model is the correct policy model; or that stable appeal rates prove compliance safety.

## 8. Model-governance recommendation

1. Maintain dated model versions aligned to policy and release calendars; conformance reports must state which normative model version applies to each case period.

2. Require event-semantic contracts for every activity label, including owner, business meaning, allowed synonyms, release-impact assessment, and backward-compatible mappings.

3. Separate business events from technical, routing, gateway, audit, and derived events; technical events such as queue-routing markers must be excluded or modeled explicitly by policy.

4. Preserve timestamp provenance by storing source timestamp, source sequence number, ingestion timestamp, and extraction timestamp; conformance ordering rules must prefer source order when available.

5. Add data-aware constraints for policies depending on claim value, role, authorization, or resource separation; do not rely on a control-flow-only tree for conditional compliance rules.

6. After each UI, gateway, ETL, or policy release, run post-release validation comparing variants, DFGs, fitness, precision, dominant alignment moves, and a manual audit sample before publishing compliance conclusions.
