## 3. Supporting and contradicting cases

### QA
- **Support:** A03 started at 08:20 despite A02 arriving earlier; the appointment rule (08:20) explains this jump.
- **Contradiction:** A04 (P1, arrival 08:13) started before A06 (P2, arrival 08:29) but after A05 (P3). If pure priority, A04 should have preempted A05; if FIFO, A04 should have waited longer.

### QB
- **Support:** B03 (P2) completed before B05 (P1) arrived, consistent with non-preemptive priority once a job starts.
- **Contradiction:** B02 (P1) preempted B01 (P3) mid-run, inconsistent with pure non-preemptive priority unless "urgent arrival" is a special override.

### QC
- **Support:** C04 (est=22) started before C05 (est=40) despite C05 having higher priority and an earlier deadline.
- **Contradiction:** C05 (P1) started before C06 (P3, est=6), which violates SPT and expected behavior if C06 was eligible at 10:54 (but C06 arrived 10:25).

### QD
- **Support:** D02 (firmware) started on D-F (11:01) and D03 (electrical) on D-F (11:21); skill eligibility explains the resource selection over strict priority.
- **Contradiction:** D08 (P1) was available 11:00 and started 11:35 after D04 (P3), indicating P1 non-preemption.

## 4. Counterfactual discrimination tests

### Episode 1: QB at 09:48 (B03 vs. B05)
- **Next-job prediction:**
    - Non-preemptive priority: B03 (already started)  B05 (P1) next.
    - Pure preemptive priority: B05 (P1) should have preempted B03 (P2) at start.
- **Discriminators:**
    - Observe whether B03 was already running at 09:48. If it was, non-preemptive priority is consistent. If it was not (queued), pure preemptive is supported.

### Episode 2: QA at 08:58 (A04 vs. A05)
- **Next-job prediction:**
    - Priority rule: A04 (P1) starts before A05 (P3).
    - Appointment/FIFO with delay: A05 arrived before A04's start slot due to calibration block (08:52–08:58).
- **Discriminators:**
    - Inspect A04's service segment. If A04 started exactly at 08:58 (right after calibration), it’s a FIFO/availability-driven decision. If A04 was waiting while A05 was processed before it, priority was applied.

## 5. Operational exceptions and alternative explanations

1.  **Calibration gaps (QA):** A04 started after a calibration window (08:52–08:58). This explains A04's gap in FIFO sequence. Plausibility: high. It changes QA from pure FIFO to FIFO-with-availability.
2.  **Dispatcher reassignment (QB):** B01 was interrupted twice; the second stop was due to reassignment. This may mask a standard priority jump. Plausibility: medium. It suggests policy exceptions exist.
3.  **Skill constraints dominate (QD):** D-F only handles firmware/electrical; D-M only mechanical. If a queue enforces skills strictly, priority order is irrelevant. Plausibility: high. It changes priority rules to skill-first routing.
4.  **Noisy est_min data (QC):** If estimates are strategic or inaccurate, SPT rules could misfire. Plausibility: medium. It would change QC to a priority-tiebreaker model rather than SPT.

## 6. Additional event data needed

- **Decision time (dispatch):** Exact timestamp when a job was chosen, not just start.
- **Eligibility set:** Which jobs were waiting at decision time and met skill/appointment constraints.
- **Resource state:** Detailed availability window and whether the resource is blocked (e.g., calibration).
- **Preemption reason code:** Distinguish "urgent arrival," "error," vs. "policy priority."
- **Est_min provenance:** Whether est_min was fixed at arrival or updated mid-job.
- **SLA threshold flag:** Whether any job was at SLA risk at decision time.
- **Appointment tolerance:** Allowed window (e.g., ±5 min) vs. exact time.

## 7. Final synthesis

- **Most identifiable:** QB. Its preemption and resume behavior provides a clear signal distinguishing preemptive from non-preemptive rules.
- **Least identifiable:** QC. Resource unavailability (11:18–11:40) and ambiguous estimates make SPT vs. priority indistinguishable.
- **Dangerous inference:** Assuming strict priority rules from QA or QD data alone would misallocate capacity; in QA, appointments dominate; in QD, skill constraints override priority.

Assumptions
- Appointment windows are treated as start-time requests rather than just arrival-time flags.
- est_min values are treated as dispatch-time estimates, not actual processing times.
- Resource calibration and meetings are hard constraints that override queue discipline.
