## 2. Process-model consistency checks

**Fixture.** Maintain a replayable golden log per case: canonical event order via a mandatory gap-free `sequence_index`, raw event store, and a feature registry where every feature declares `available_from`, computation logic version, and owner.

**Test suite (release-gating):**

- **T1 – Prefix-time availability (PIT compliance).** For every feature × case, recompute from events  t0 in a replay harness and compare with stored training values. Mismatch rate above  fails the build. *Limitation:* verifies only features we know how to recompute; identical mistakes in replay and warehouse stay invisible — mitigate with independent re-derivation from raw logs.
- **T2 – Truncation invariance.** Recompute features on traces truncated at t0; any value change proves complete-trace dependence. Cheap detector that complements T1 (catches aggregates and rollups like `last_resource_role`).
- **T3 – Order feasibility (footprint/precedence scan).** Derive directly-follows relations from the log and compare against normative precedence (Registration  Coverage  {Assessment  DocRequest(s)}; Assessment  Decision  Appeal?  Decision*  Closed). Bulk-triage forbidden pairs (e.g., Closed  Damage). *Limitation:* footprints are noise-blind and destroyed by tie-poisoning — hence T4 first.
- **T4 – Same-timestamp ambiguity stressor.** Detect collisions crossing precedence-critical pairs; permute tie groups; report feature-flip and explanation-flip rates. Releases blocked above threshold until a reliable sequence index exists. Without a stable total order, every order-sensitive statistic (including T3, T5) is undefined, not merely noisy.
- **T5 – Alignment-based conformance.** Align traces to the normative model; quantify fitness and localize deviations (e.g., synchronous moves swapping Close and Assessment). Sampled due to cost. *Limitation:* garbage in, garbage out — requires a trustworthy reference model and T4-resolved timestamps.
- **T6 – Structural leakage lint.** Static scan of SQL/DAGs for closure-table joins, `final_*`/`total_*` fields, and `extraction_date` predicates; registry rejects features lacking `available_from`.
- **T7 – Explanation-token enabling audit.** For every activity referenced by an explainer, classify at t0 via reachability/enabling analysis: **enabled**, **impossible**, **future-possible but unobserved**. At t0 the enabled set is roughly `{Damage Assessment (fast track), Documents Requested (slow track), Fraud Investigation (conditional)}`; `Claim Closed`, `Appeal`, and both Settlement Decision events are future-possible; a Closed  Damage pair is impossible. Any pattern token that can only match by observing future classes auto-flags the explanation as leakage-derived.
- **T8 – Repeated-Decision semantics.** Declarative constraints: assessment precedes any DEC (with Withdrawn-early enumerated as an explicit exception); DEC multiplicity  {1, 2}; a second DEC requires an intervening Appeal; an Appeal requires a preceding DEC  {Partial, Deny}. This lets validators distinguish a legitimate second DEC from an anomaly and lets late-checkpoint models reference DEC-2 safely.
- **T9 – DFG-vs-normative gate.** Frequent DFG edges are descriptive only. Promoting an edge or pattern to an explanation construct requires: conformance support (T5), a semantic rationale, survival under tie-permutation (T4), and model-owner sign-off. "Frequent  normative" is codified as a checklist item.

Overall limitation: all tests certify consistency between the log, the model, and the pipeline — not truth about the world. They are necessary hygiene, not proof of causal relevance.

## 5. Recommendations for explanation validation

**P0 – Contain (immediate).** Freeze the top-12 feature set and all shipped sequence patterns; quaran­tine served explanations referencing them; issue a defect note to consumers distinguishing data-quality artifacts (Closed  Damage) from pure temporal leakage (Appeal  Decision). Purge anything whose computation window overlaps the label window.

**P1 – Data foundation (feature-store design + historical timestamps + prefix-only recomputation).**
- Rebuild the store around a raw, append-only event log with a mandatory gap-free `sequence_index`; every derived feature carries `(available_from event-time, ingested_at, logic_version)`; point-in-time joins only.
- Convert undated dimensions to bitemporal histories: team assignments, risk-score versions, employee experience, document uploads, reserve setting.
- Stand up a replay harness that regenerates training matrices by truncating traces at each prediction checkpoint; retrain from scratch with the repaired `prior_claim_count` predicate and prefix signatures; permanently delete target-overlapping derivations.

**P2 – Validation gates (conformance tests + calibration + explanation stability + fairness).**
- Wire T1–T9 into CI as release blockers: PIT availability, truncation invariance, footprint/order feasibility, tie-collision stressor, alignment fitness floors, leakage lint, enabling-status classification of explanation tokens, repeated-DEC legitimacy rules, DFG promotion checklist.
- After feature removal, expect honest metric drops; set acceptance thresholds ex ante. Time-based cross-validation per checkpoint; recalibrate probabilities (isotonic/Platt); report AUC, Brier, and ECE by horizon and cohort.
- Explanation-stability suite: tie-group permutation, ±5-minute snapshot jitter, seed variance; flag explanations whose driver rankings move beyond tolerance. Communicate that attribution magnitudes will shift after decontamination.
- Proxy/fairness program: correlation and transferability audit for region/channel/language; subgroup calibration and error-parity monitoring; documented decisions on retention; ban on these variables in user-facing causal phrasing; annual necessity review.

**P3 – Operate (monitoring).**
- Schema and process drift: PSI on retained features; novel activity/variant share; timestamp-collision rate; alignment-fitness trend; feature-importance drift tagged by `policy_era` and holiday periods; snapshot-latency gaps for the queue feed.
- Governance loop: model cards state per-feature epistemic status (association / state / proxy / regime-sensitive); quarterly re-audit repeats the leak scan over the full registry (including previously unranked features like employee experience); incidents feed fixes back into the feature-store contracts.

Throughout, explanation templates must match epistemic status: "was associated with" for predictors, "operational load observed at intake" for state signals, silence for proxies toward customers, and nothing at all for features that have not survived the repair pipeline.
