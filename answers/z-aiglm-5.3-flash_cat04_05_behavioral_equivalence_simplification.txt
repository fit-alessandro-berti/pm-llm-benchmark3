# 1. Equivalence Notions

Throughout, `_vis = {Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, Close Case}` and `` denotes the silent label.

**(a) Visible trace equivalence after hiding  (classical language equivalence).**
Build the accepting Petri net of each tree (complete, sound workflow nets; visible budget unbounded). For a net *N* define `Vis(N) = {  _vis* |  = h(w) for some complete firing sequence w from IM to FM}`, where `h` erases exactly the silent firings. Models are equivalent iff `Vis(A) = Vis(B)` (full trace inclusion both directions, unbounded length).

**(b) Bounded visible-language equivalence under P3.**
Define `Vis_L(N) = {  Vis(N) : ||  12  ||Analyze Revision  3}`, where `||_a` counts occurrences of label *a*. Equivalence under P3 means `Vis_L(A) = Vis_L(B)`. By definition this is *only* a finite-horizon approximation; agreement (or disagreement) of the bounded fragments is evidence about, not a proof of, (a). Disagreement inside the bound, however, is a proof of disagreement in (a).

**(c) Business-relevant equivalence under P1 (operational compliance).**
Two traces are P1-equivalent iff they have the same entire visible sequence of labels including `Approve Revision` and all repeats of `Check Revision`; positions matter. Two *models* are P1-equivalent iff (i) their visible languages are equal **and** (ii) in every accepted case there exists a 1-1 positional association “analysis attempt  following-or-interleaved Check Revision” such that each `Check Revision` of the pair precedes the next `Rework Case` and precedes `Close Case`. P1 is deliberately stricter than plain trace equality: it encodes the compliance rule directly.

**(d) Abstracted dashboard equivalence under P2.**
Define the dashboard map `` on complete visible traces:

- precondition filter: first = `Open Case`, last = `Close Case`, `||_Analyze  1`, `||_Check  1`;
- output record `(n, r, c)` with `n = ||_Analyze  1`, `r = (||_Rework  1)`, `c = True` (Boolean collapse of all `Check` occurrences);
- `Approve Revision` and -influenced gaps are deleted, order beyond the first/last anchor is discarded.

Models are P2-equivalent iff `(Vis(A)) = (Vis(B))` as sets of records.

**Duplicate labels.** Duplicate visible occurrences (e.g., a second `Check Revision`) are distinguished by **occurrence position**: each firing instance is an occurrence, equality of instances is by index within the trace, and language membership tests use only the label sequence. No persistent “identity” links two occurrences.

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | Loop wraps `( +(Analyze, Check), X(Approve, ) )` and uses `Rework` as redo part: the **Check is re-executed every iteration** | Loop wraps `(Analyze, X(Approve, ))` with `Rework` as redo; the **Check sits outside the loop**, concurrent with the whole loop | In A, each loop iteration adds one Check; in B the total Check supply is fixed before/without any loop decision |
| Min Check occurrences | 1 (do-loop 1 iteration; AND completes the pair) | 1 (left AND-branch must complete) | Identical lower bound; cannot distinguish |
| Max Check occurrences | Unbounded; exactly `||_Analyze` in every complete trace | Exactly 1 always | Decisive multiplicity asymmetry: every A-trace with 2 Analyses has 2 Checks, impossible in B |
| Possible placement of Check | Only inside an iteration block: between the previous `Rework` (or `Open`) and the next `Rework` (or the closing choice), always jointly scheduled with that iteration’s Analyze, and strictly **before** that iteration’s optional Approve | Anywhere strictly between `Open` and `Close`: before the first Analyze, between any Rework/Approve, or **after the last Approve** | B admits orderings forbidden in A (e.g. Approve before Check) even when multiplicities agree |
| Optional approval occurrences | 0..n (one per iteration, skippable via ) | 0..n (identical mechanism inside its loop) | Approval mechanism is semantically parallel in both;  makes “skip approve” invisible, so short traces exist in both |

| Join before `Close Case` | Sequential join only: loop termination is the only synchronization; Close needs the loop (hence the last pair) to be finished | AND-join synchronizes the single Check **and** full loop termination before Close | Completion requirement is behaviorally almost inert (everything must finish anyway), but it is what authorizes B’s free-floating Check |

Why the BFS is exhaustive *within the bound*: (i) silent steps are folded by `eps_*` closures with their own visited-set, so -chains cannot explode or loop forever; (ii) final-marking equality is tested on the closure, so silent splits/joins after the last visible event are handled; (iii) pruning by maximum remaining budget only removes dominated states — every surviving continuation is preserved — therefore, together with finiteness of the reachable region implied by the 12-visible budget (each additional loop round costs  2 visible events), the computed sets are the **complete** P3 fragments. `play_out`, by contrast, draws according to unspecified model probabilities; its outputs are anecdotes.

**Footprints.** Reasoning over the models: single-event adjacency tends to agree — Start/End profiles match (any label that can follow `Open`, or precede `Close`, is the same set in both); `DF(Analyze,Check)`/`DF(Check,Analyze)` hold in both; `DF(Rework,Check)` holds in both (new A-iteration may emit Check first; B may linearize the concurrent Check right after a Rework); `DF(Check,Check)`, `DF(Approve,Analyze)` are false in both. Expect the code to print empty differences or near-empty ones — and *that is the lesson*: footprints encode pairwise directly-follows facts and cannot see multiplicity (A’s “one check per iteration”) nor non-adjacent relations (Approve…Check in B). Equal footprints  plausible isomorphism of local order texture, never of languages: `(a,a,a)` and `(a)` can share every adjacency fact with appropriate filler events. Their value here is negative-testing hygiene: if footprints *had* differed on pairs not explainable by §2, our §3 verdicts would need revisiting.

```python

# P3-bounded traces (tau-free view). Nothing inherited from the tool is trusted.
def uniform_language(traces):
    n = len(traces)
    return {", ".join(s): 1.0 / n for s in traces}

la = uniform_language(sorted(lang_a)); lb = uniform_language(sorted(lang_b))
try:
    emd = pm4py.compute_emd(la, lb)
    print("EMD(uniform, P3-bounded) =", emd)   # > 0 expected: disjoint nontrivial parts
except Exception as e:
    print("compute_emd unavailable/needs env config:", e)
```

`pm4py.get_stochastic_language` requires a stochasticPetriNet whose transition weights the library reads off a discoverer; attaching, say, a default aggregator would inject undeclared probabilities, so instead we *declare* the distribution (uniform over bounded complete traces) and feed `compute_emd`. Expected outcome: a positive EMD, driven by the non-shared mass of §4 — quantitative corroboration that the languages differ. Why low EMD still proves nothing: (i) EMD depends entirely on the chosen weighting and metric — a skewed or near-uniform-on-common-core re-weighting can shrink it arbitrarily without changing a single trace set; (ii) continuous distances are unstable under support changes introduced by a single extra trace; (iii) stochastically indistinguishable models are routinely trace-inequivalent. EMD ranks candidates for dashboard reproduction; it never certifies behavioral equality.

# 8. Simplified Model

**Target chosen: P2 (executive dashboard semantics)** — explicitly defined as: generate exactly the visible record stream `{ (n, r) : n  1, r = (n  2) }` with check-presence guaranteed true, order-of-check irrelevant, approvals excluded from the abstraction. A P1-faithful simplification of *both* originals is impossible because they themselves contradict each other at P1; a P3 surrogate would need the full generality of the originals, defeating “simplification”. P2 is the only view whose abstraction tolerates a compact, interpretable generator.

**Compact POWL-style expression:**

```text
SEQ( OpenCase, LOOP*( AnalyzeRevision, ReworkCase ), CheckRevision, CloseCase )
```

i.e. `->( 'Open Case', *( 'Analyze Revision', 'Rework Case' ), 'Check Revision', 'Close Case' )`.

# 9. Final Recommendation

- **P1 (operational compliance):** Only **Model A** is a viable documentation source — it is the sole model of the two that realizes one-Check-per-attempt with Rework separating attempts. Model B must be ruled out for compliance artefacts (single Check, and even the permissive ordering `Approve``Check`). Keep A; do not replace it with B or with the simplified model.
- **P2 (executive dashboard):** Both originals are **equivalent only under the stated abstraction**; any of them powers the dashboard identically. Prefer the **simplified model** (and only it, fed straight into aggregates/validation logic) to reduce maintenance surface: 7 nodes, no , no choices, yet provably the same dashboard image in closed form (bounded confirmation included in the §8 script). Retain one original (A) upstream as the audit authority; regenerate the simplified artifact from it automatically so drift is detectable.
- **P3 (bounded testing):** Neither model subsumes the other. Use **both** as independent oracles: run the §5 exhaustive bounded comparator per release, triage any trace appearing in only one side, and extend to neighborhood traces (mutation-style). The simplified model is *not* a legal P3 surrogate for either original — it deliberately discards the interactions P3 wishes to exercise.

**Limits of bounded comparison (explicit warning).** Passing every test with  12 visible events and  3 analyses establishes nothing about iteration 4+ and events 13+. To make a *positive* equivalence claim, users must lift the reasoning beyond the bound — e.g., exhibit a bisimulation-like invariant over markings parameterized by the loop counter and prove by induction (on iteration count k) that key invariants transfer: “after loop-round k, models X and Y expose the same residual trace offers.” Absent such a lifting, treat bounded results strictly as regression coverage, never as certificates.
