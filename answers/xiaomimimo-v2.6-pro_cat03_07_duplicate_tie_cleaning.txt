# 1. Duplicate-handling decision tree

Apply the tree **pairwise (or per candidate group)**, top-down. The first satisfied branch wins. "Container objects" are Order (O1) and Invoice (V1): they are case-level and are touched by almost every event, so they are *excluded* from any object-identity test. Define `objs_canon(e) = related_objects(e) \ {objects of type Order, Invoice}`.

- **Q0 — Exact technical duplicate?** Same `source`, same `source_event_key`, same `payload_hash`, same `timestamp`, same `activity`.
  - *Yes*  **CLASS A: exact technical duplicate**  **drop** one row (record the dropped eid and its key in the audit trail). Zero information loss by construction.
  - *No*  Q1.
- **Q1 — Same physical event observed by multiple systems?** Different `source`; `objs_canon` sets **equal and non-empty**; identical `activity` **and identical pre-harmonisation semantics** (checked against `original_activity`/source profile); plus at least one *independent* corroborator: shared business key (invoice no. V1, scan id, reconciliation report), or an authoritative statement from a source owner.
  - *Yes, with a clear per-attribute authority map*  **CLASS B: multi-system observation of one occurrence**  **merge attributes and relations** (canonical eid retained; every source value kept source-tagged).
  - *Yes, but two sources are authoritative for the **same** key attribute with different values*  **quarantine for review** (do not merge).
  - *No*  Q2.
- **Q2 — Summary derived from a detailed event?** One row is a status/summary posting generated from a message that the other row's system emitted (derivation direction known), the summary's object set is a **subset** of the detail's, and the mapping is **1 : 1**.
  - *Yes*  **CLASS C: summary of a detail event**  **retain both with refined labels or qualifiers** (`abstraction = detail | summary`, `derived_from = <eid>`). Dropping the summary is only allowed if the analyst's target abstraction is explicitly the detailed level, and must be logged as a deliberate projection.
  - *No*  Q3.
- **Q3 — Harmonisation collision?** Equal harmonised `activity` but different `original_activity`, or different source semantics, such that the harmonisation erased a real business-stage distinction (e.g. "released from warehouse" vs. "accepted by carrier").
  - *Yes*  **CLASS D: harmonisation collision between semantically distinct source activities**  **retain both with refined labels or qualifiers** (restore the pre-harmonisation meaning in `activity_refined`). Never merge; never drop.
  - *No*  Q4.
- **Q4 — Concurrent same-label events on different objects?** Equal `activity` and `timestamp`, but `objs_canon` sets differ on at least one **transactional** object identity (Item, Payment, Package…).
  - *Yes*  **CLASS E: concurrent same-label events involving different objects**  **retain both unchanged**; record them as *unordered/parallel* in the constraint table.
  - *No*  Q5.
- **Q5 — Ambiguous evidence?** Derivation is 1 : n or n : 1 (one summary summarising several detailed events), the object sets differ only on containers, or the "same occurrence" claim rests on nothing but timing and labels.
  -  **CLASS F: unresolved candidate**  **quarantine for review**: keep both events in the log, mark `decision_status = unresolved`, forbid merging, keep the tie as a tie.

Terminal actions in one line: A  drop; B  merge attributes+relations (or quarantine on attribute conflict); C  retain both with qualifiers; D  retain both with refined labels; E  retain both unchanged; F  quarantine.

Two guards are mandatory: (i) an *existential* object test ("they share an object") is **never** evidence of duplication; (ii) equal activity + equal timestamp is never evidence of duplication either — it is the signature of classes C, D, E and F as much as of B.

| e14 / e15 | Class F — idem, would attribute to M2 | quarantine for review, retain both | Low (0.3) | n/a | none | none | both | idem, mirrored on M2 |

# 3. Timestamp-tie ordering rules

**Rule set (ordered by strength).** R1–R4 are *semantic*, R5–R6 are *merely deterministic*.

- **R1 — domain constraints (semantic, hard).** Create  Validate; `Pick(Item i)`  `Pack(involving i)`; Pack  Release; Release  Accept-by-Carrier  Handover  Confirm-Delivery; Authorize(M)  Capture(M); `Issue Invoice`  any payment event referencing that invoice (this last one is an *assumption* and is tagged `assumed=true`, because no fact states it).
- **R2 — within-source sequence (semantic, medium).** `source_seq` monotonic **within one source only**. Counters can wrap and postings can be late, so it is soft evidence; it is never applied across sources (ERP `seq 41` and PSP `seq 402` are incomparable).
- **R3 — lifecycle constraints on shared objects (semantic, medium).** Per object, its events must follow that object's type lifecycle (Item: Pick  Pack; Payment: Authorize  Capture; Invoice: Issue  Pay). A violation is reported as a data error; it is **not** silently repaired by reordering.
- **R4 — source-specific semantics (semantic, interpretive).** Harmonised labels do not carry stage information (`Dispatch Package` means release in WMS and acceptance at the carrier). Each `(source, original_activity)` pair is mapped to a `stage_rank` from a declared source profile; the derivation direction ("ERP status generated from a WMS message") orders the **observation**, not necessarily the business transition, and is tagged `observation_only=true`.
- **R5 — ingestion time (deterministic only).** `ingested_at` (with microseconds) may break ties *below* R1–R4 and is tagged `ordering_evidence = ingest_fallback`. It is never used as business order (fact 9) and never enters a duration.
- **R6 — stable fallback (deterministic only).** Ascending `canonical_eid` lexicographically, guaranteeing reproducibility independent of DataFrame row order.

**Total order.** Build a DAG from R1–R4, then run a Kahn topological sort where the ready-set is popped by the key
`(stage_rank, lifecycle_rank_on_shared_transactional_object, source_seq_within_source, observation_precedence, ingested_at_us, canonical_eid)`.
Every produced edge is written to `ordering_constraints` with its `rule_id`, `hard/soft` flag and `semantic: true|false`, so that linearisation artifacts are distinguishable from real partial-order edges. Afterwards `pm4py.ocel_sort_by_additional_column(ocel, "order_idx")` materialises the order and only then `pm4py.ocel_add_index_based_timedelta` may be applied — its `@@timedelta` is an **index gap**, not a business duration.

**Why not to add microseconds first.** Micro-stamps (i) hard-code one of several admissible orders before any semantic rule has been consulted; (ii) fabricate durations that flow into `ocel_objects_intervals`, temporal summaries and performance DFGs (PickPack becomes a 3 µs "processing time"); (iii) erase the tie itself, so the analyst can no longer see that `Pick(I1)` and `Pick(I2)` are potentially parallel; (iv) turn "e05 may be before or after e03" into the false story "I1 was picked, then I2"; (v) create non-determinism through float rounding. Microseconds belong **only** inside the derived `tie_break_key`, while `original_timestamp` stays intact (fact 10).

**Intended orders.**

- **10:00 cluster** (after merging e03/e04  `c03`): constraints `c03  e06` (R2: WMS 100  110; R3: Pick(I1)  Pack), `e05  e06` (R3: Pick(I2)  Pack), `e06  e07` (R4 derivation). `c03` and `e05` are **semantically unordered**. Deterministic break (SCANNER 551  552) yields **c03, e05, e06, e07**; the equally admissible alternative is **e05, c03, e06, e07**. Under evidence-based merging the cluster is `c03, e05, c06`.
- **10:15 cluster:** **e08, e09, e10** — unique given facts 4 and 5 (R4 stage ranks 5  6  7, corroborated by CARRIER `source_seq` 1  2). Without fact 5, e09/e10 would remain a tie broken only by R2/R5.
- **12:00 cluster (conservative, `c11`  e11+e16):** constraints `c11  e12` (assumed R1), `e12  e13` (fact 7), `c11  e14`, `e13  e14`, `e13  e15` and probably `e14  e15` (fact 8). Deterministic break (PSP 401  402) gives **c11, e12, e13, e14, e15**; the alternative **c11, e12, e13, e15, e14** is admissible if e15 summarises only the M1 chain. In the strict-min variant where e11 and e16 are both kept, `Issue Invoice` is tied and only R5 (12:00:01  12:00:04) decides — giving e11, e16, e12, e13, e14, e15 and therefore a `Issue Invoice  Issue Invoice` edge. That edge is a *linearisation artifact*, not evidence of a physical sequence: a deterministic total order never proves the true physical order.

# 4. Conservative cleaning pipeline

0. **Freeze.** `snapshot = deepcopy(ocel_raw)` written to immutable storage with a SHA-256 fingerprint; all later steps operate on copies.
1. **Annotate, do not delete.** Copy `original_eid`, `original_activity`, `original_timestamp`, `source`, `source_event_key`, `source_seq`, `ingested_at`, `payload_hash` into reserved columns; add `objs_canon`, `stage_rank`, `abstraction`, `decision_status = retained`.
2. **Pre-check.** Emit the candidate-group report (classes A–F) with evidence and confidence. Nothing is removed here; the report *is* the justification for every later removal.
3. **Class A only.** If and only if the pre-check reports exact technical duplicate groups (identical `source_event_key` + `payload_hash`), apply `pm4py.ocel_drop_duplicates` to that scope and assert the event-count delta equals the reported group size. On the given candidate set the report is empty, so this step is provably a no-op — which is exactly why it is safe to run.
4. **Class B only, verified pairs.** Merge `e03|e04  e03` and `e11|e16  e11` with per-attribute authority maps, source-tagged retention of every conflicting value, and relation union restricted to identical/ object sets. Each merge writes an audit record and a `merged_from` chain.
5. **Labels and qualifiers only (C, D, F).** Refine `e08  "Release Package (WMS)"`, `e09  "Accept by Carrier"`; qualify `e06` (`detail`) and `e07` (`summary`, `derived_from=e06`); mark `e13/e15` and `e14/e15` as `unresolved`. **No event is removed in this step.**
6. **Ordering.** Build the R1–R4 DAG, linearise with the R5/R6 key, store `order_idx`, `tie_break_key`, `ordering_evidence`, then `pm4py.ocel_sort_by_additional_column` and only afterwards `pm4py.ocel_add_index_based_timedelta`.
7. **Validate.** Referential integrity (every relation's eid and oid resolves; every event has 1 object; eids unique; no NaN activity/timestamp), re-run the pre-check on the output and diff, and export the audit trail.
8. **Concurrency preserved.** `e05`, `e13`, `e14` keep their ties as ties in `ordering_constraints` (`parallel = true`), so concurrency-aware discovery still sees them.

**Expected retained count: 15 events** (17  2 merged pairs) and **39 E2O relations** (44  3  2). A strict minimum-change variant that refuses to merge e11/e16 yields **16 events / 41 relations** and keeps `Issue Invoice` twice with refined labels; the trade-off is one extra false rework edge in the Order- and Invoice-flattened DFGs.

# 5. Aggressive alternatives

**E1 — evidence-based semantic merging (14 events / 37 E2O relations).** Start from the conservative result and additionally merge `e06|e07  e06` (1:1 derivation, object set , one business transition). *Damage:* the abstraction echo `Pack  Pack` disappears (good) but so does the WMSERP posting latency, an integration-quality metric; the summary's "no Item detail" signal is lost, so `Pack Package–Item` ET-OT weight jumps from 1.0 to 2.0. If the rule is stretched to merge `e08|e09` (13 events / 34 relations) the warehousecarrier hand-off segment — precisely where SLAs live — vanishes. `e15` must **not** be merged: it summarises an unattributable set of payment messages (1 : n), so any merge invents an attribution no source makes.

**E2 — mechanically aggressive PM4Py merging (10 events / 28 E2O relations).** Apply `pm4py.ocel_merge_duplicates` over (activity, timestamp), or `ocel_drop_duplicates` keeping `first`. Merged groups: `Pick Item` {e03,e04,e05}, `Pack Package` {e06,e07}, `Dispatch Package` {e08,e09}, `Issue Invoice` {e11,e16}, `Capture Payment` {e13,e14,e15}. *Damage:* two picks of two items become one mega-pick carrying I1 and I2 (pick count 2  1, `Pick Item–Item` weight 1.0  2.0); the release/acceptance collision becomes one 0-second double dispatch; **two partial payments M1 and M2 plus an ERP invoice-level balance update become a single capture related to M1 and M2**, so per-payment throughput halves, the M2 flattening inherits a capture it never had, and `Capture Payment–Payment` weight becomes 2.0 on one event. `keep='first'` is additionally destructive because it silently keeps only one source's authoritative attributes (e.g. drops the billing amounts).

**E2 — object-set-guarded aggressive (13 events).** A variant that merges only when `objs_canon` sets are equal merges {e03,e04}, {e11,e16} **and** {e08,e09}. This shows that object-set equality is *necessary but not sufficient*: the e08/e09 pair is identical in objects yet is a harmonisation collision. The semantic check (Q3) is not optional.

**Why `have_common_object=True` does not protect e13 and e14.** The test is existential over the *full* related-object set, and O1 (Order) and V1 (Invoice) are container objects touched by every event of the case. e13 and e14 therefore satisfy `have_common_object=True` — they share O1 and V1 — while their discriminating objects are M1 and M2, two different partial payments of the same invoice. In a single-order log the guard degenerates to "everything shares an object", i.e. it blocks nothing. The correct guard is **container-invariant object-set equality plus at least one shared transactional object plus a business-key check**: `{M1}  {M2}` blocks the merge and keeps both partial captures intact.

```python
# ============================================================================
# Scenario builder for the 6-source OCEL.  PM4Py >= 2.3 (dict-style OCEL).
# Assumes: ocel_raw exists; ocel_raw["ocel:events"] carries the metadata
# columns source, source_event_key, source_seq, ingested_at, payload_hash.
# ocel_raw is NEVER mutated: every scenario starts from a deepcopy and the
# pristine log is fingerprinted first.
# ============================================================================
import copy, hashlib, json, warnings
import numpy as np
import pandas as pd
import pm4py

EV, OBJ, REL = "ocel:events", "ocel:objects", "ocel:relations"
EID, ACT, TS  = "ocel:eid", "ocel:activity", "ocel:timestamp"
OID, OTYP, QUAL = "ocel:oid", "ocel:type", "ocel:qualifier"
CONTAINER_TYPES = {"Order", "Invoice"}        # case-level containers
RULE_VERSION    = "ocelclean-2026.05-r1"
AUDIT           = {}                          # scenario -> provenance frames

# --------------------------------------------------------------------- utils
def fingerprint(ocel):
    h = hashlib.sha256()
    h.update(ocel[EV].to_csv().encode()); h.update(ocel[REL].to_csv().encode())
    return h.hexdigest()

def freeze_originals(ocel, scenario):
    """Reserved columns: nothing downstream may overwrite them."""
    ev = ocel[EV].copy()
    ev["original_eid"]       = ev.index.astype(str)
    ev["original_activity"]  = ev[ACT]
    ev["original_timestamp"] = ev[TS]
    ev["scenario"], ev["decision_status"] = scenario, "retained"
    ev["abstraction"] = "detail"
    ocel[EV] = ev
    return ocel

def obj_type_map(ocel):
    return ocel[OBJ][OTYP].astype(str).to_dict()

def object_sets(ocel, drop_containers=False):
    g = ocel[REL].groupby(EID)[OID].apply(lambda s: frozenset(map(str, s)))
    if drop_containers:
        typ = obj_type_map(ocel)
        g = g.apply(lambda s: frozenset(o for o in s if typ.get(o) not in CONTAINER_TYPES))
    return g.to_dict()

# ------------------------------------------------- 1. pre-check (no deletion)
def duplicate_precheck(ocel):
    """Groups candidates and classifies them (A..F). Purely diagnostic."""
    ev = ocel[EV].reset_index()
    ev["objset"]       = ev[EID].map(object_sets(ocel))
    ev["objset_canon"] = ev[EID].map(object_sets(ocel, drop_containers=True))
    rows = []

    def emit(tag, df, cls, why, conf, action):
        rows.append(dict(group=tag, eids=list(df[EID]), sources=sorted(set(df["source"])),
                         cls=cls, evidence=why, confidence=conf, proposed_action=action))

    for _, df in ev.groupby(["source_event_key", "payload_hash", TS, ACT]):
        if len(df) > 1:
            emit("G1", df, "A_exact_technical_duplicate",
                 "same source_event_key + payload_hash + ts + activity", 1.0, "drop")
    for _, df in ev.groupby(["payload_hash", TS, ACT]):
        if len(df) > 1 and df["source"].nunique() > 1:
            emit("G2", df, "B_candidate_same_physical_event",
                 "identical payload_hash across sources", 0.8, "merge_if_verified")
    for _, df in ev.groupby([ACT, TS]):
        if len(df) == 1:
            continue
        if df["objset_canon"].map(lambda s: s).nunique() == 1:
            emit("G3", df, "B_or_C_or_D", "equal activity+ts+canonical object set",
                 0.5, "inspect_semantics")
        else:
            emit("G4", df, "E_concurrent_distinct",
                 "canonical object sets differ (transactional objects)", 0.95,
                 "retain_both_unchanged")
    # summary candidates: strict subset of another event's objects at the same ts
    for _, df in ev.groupby(TS):
        for i, a in df.iterrows():
            for j, b in df.iterrows():
                if i != j and a["objset"] < b["objset"]:
                    emit("G5", df.loc[[i]], "C_summary_or_F_unresolved",
                         f"objects are a strict subset of {b[EID]}", 0.4,
                         "retain_with_qualifier")
    return pd.DataFrame(rows)

# ---------------------------------------- 2. custom verified-pair merge/dedup
def merge_verified_pairs(ocel, pairs, mode="merge"):
    """
    pairs: [{"master": eid, "duplicates": [eid...], "cls": str, "evidence": str,
             "confidence": float, "attr_policy": "authority_tagged"|"master",
             "attr_authority": {column: source}, "rel_policy":
             "union"|"intersection"|"master"}]
    mode="merge"          -> canonical event keeps the master eid, duplicates are
                             absorbed (attributes source-tagged, relations merged).
    mode="drop_nonmaster" -> deduplication variant: master row survives untouched,
                             duplicate rows are deleted (use only for CLASS A).
    Returns (ocel, provenance_df); the input object is deep-copied first.
    """
    ocel = copy.deepcopy(ocel)
    ev, rel = ocel[EV].reset_index(), ocel[REL].copy()
    typ = obj_type_map(ocel)
    prov = []

    for p in pairs:
        ids = [p["master"]] + list(p["duplicates"])
        rows = ev[ev[EID].isin(ids)]
        assert len(rows) == len(ids), f"unknown eid in {ids}"
        master = p["master"]
        conflicts, merged = [], {}

        if mode == "merge":
            for col in ev.columns:
                if col in ("objset", "objset_canon"):
                    continue
                vals = {r[EID]: r[col] for _, r in rows.iterrows() if pd.notna(r[col])}
                if not vals:
                    continue
                src_of = dict(zip(rows[EID], rows["source"]))
                if len(set(map(str, vals.values()))) == 1:
                    merged[col] = next(iter(vals.values()))
                else:
                    auth = p.get("attr_authority", {}).get(col)
                    winner = rows.loc[rows["source"] == auth, EID] if auth else pd.Series(dtype=object)
                    merged[col] = vals[winner.iloc[0]] if len(winner) else vals[master]
                    tagged = {src_of[k]: str(v) for k, v in vals.items()}
                    merged[col + "@sources"] = json.dumps(tagged, sort_keys=True)
                    conflicts.append(dict(attr=col, values=tagged,
                                          resolution=f"authoritative source {auth or master}"))
            # relations: guarded, never blind union across incompatible sets
            sub = rel[rel[EID].isin(ids)]
            sets = {eid: set(sub.loc[sub[EID] == eid, OID].astype(str)) for eid in ids}
            if p["rel_policy"] == "intersection":
                keep_oids = set.intersection(*sets.values())
            elif p["rel_policy"] == "master":
                keep_oids = sets[master]
            else:  # union, allowed only if one set contains the others
                chain = all(sets[a] <= sets[b] or sets[b] <= sets[a]
                            for a in ids for b in ids)
                assert chain or set.union(*sets.values()) == sets[master], \
                    f"relation sets of {ids} are incompatible: refuse union"
                keep_oids = set.union(*sets.values())
            keep = sub[sub[OID].astype(str).isin(keep_oids)].drop_duplicates(
                subset=[OID, QUAL], keep="first").copy()
            keep[EID] = master
            keep["merged_from"] = "|".join(sorted(ids))
            rel = pd.concat([rel[~rel[EID].isin(ids)], keep], ignore_index=True)

        prov.append(dict(canonical_eid=master, source_event_ids="|".join(sorted(ids)),
                         merge_rule=p["cls"], rule_version=RULE_VERSION,
                         reviewer="rule-engine:auto", evidence=p["evidence"],
                         confidence=p["confidence"], mode=mode,
                         attributes_retained={c: str(v) for c, v in merged.items()},
                         discarded_conflicts=json.dumps(conflicts),
                         original_activity=rows.set_index(EID)[
                             "original_activity"].astype(str).to_dict()
                             if "original_activity" in ev else {},
                         original_timestamp=rows.set_index(EID)[TS].astype(str).to_dict()))
        drop_ids = [i for i in ids if i != master]
        if mode == "merge":
            for col, val in merged.items():
                ev.loc[ev[EID] == master, col] = val
            ev.loc[ev[EID] == master, "decision_status"] = "merged_canonical"
        ev = ev[~ev[EID].isin(drop_ids)]

    ocel[EV] = ev.set_index(EID)
    ocel[REL] = rel
    ocel["custom:provenance"] = pd.DataFrame(prov)
    return ocel, pd.DataFrame(prov)

# ------------------------------------------- 3. label refinement / qualifiers
def refine_labels(ocel, refinements):
    """refinements: {eid: (new_activity, abstraction, derived_from_or_None)}"""
    ocel = copy.deepcopy(ocel)
    ev = ocel[EV].copy()
    for eid, (act, abstract, derived) in refinements.items():
        ev.loc[ev.index == eid, ACT] = act
        ev.loc[ev.index == eid, "abstraction"] = abstract

# ------------------------------------------------- 4. ordering (R1..R6)
STAGE_RANK = {("ERP","Create Order"):1, ("ERP","Validate Order"):2,
              ("WMS","Pick Item"):3, ("SCANNER","Pick Item"):3,
              ("WMS","Pack Package"):4, ("ERP","Pack Package"):4,
              ("WMS","Dispatch Package"):5, ("WMS","Release Package (WMS)"):5,
              ("CARRIER","Dispatch Package"):6, ("CARRIER","Accept by Carrier"):6,
              ("CARRIER","Handover to Carrier"):7,
              ("ERP","Issue Invoice"):8, ("BILLING","Issue Invoice"):8,
              ("PSP","Authorize Payment"):9, ("PSP","Capture Payment"):10,
              ("ERP","Capture Payment"):10, ("CARRIER","Confirm Delivery"):11}

# (from_original_eid, to_original_eid, rule_id, semantic, hard)
CONSTRAINTS = [("e01","e02","R1_domain",True,True), ("e03","e06","R2_wms_seq",True,False),
               ("e05","e06","R3_item_lifecycle",True,True),
               ("e06","e07","R4_derivation",True,False),
               ("e08","e09","R4_source_semantics",True,False),
               ("e09","e10","fact5_known_order",True,True),
               ("e11","e12","R1_assumed_domain",True,False),
               ("e12","e13","fact7_m1_chain",True,True),
               ("e13","e15","R4_derivation",True,False),
               ("e14","e15","R4_derivation",True,False)]

def build_order(ocel, constraints=CONSTRAINTS):
    ocel = copy.deepcopy(ocel)
    ev = ocel[EV].copy()
    ev["_stage"] = [STAGE_RANK.get((s, a), 50) for s, a in
                    zip(ev["source"], ev[ACT].astype(str))]
    ev["_seq"]   = ev["source_seq"].fillna(10**9).astype(float)
    ev["_ing"]   = pd.to_datetime(ev["ingested_at"]).astype("int64")
    ev["order_key"] = list(zip(ev["_stage"], ev["_seq"], ev["_ing"],
                               ev.index.astype(str)))
    name2id = ev["original_eid"].to_dict()
    edges = [(name2id[a], name2id[b], r, sem, hard) for a, b, r, sem, hard in constraints
             if a in name2id and b in name2id]
    # deterministic topological sort (Kahn) with the order_key as heap priority
    import heapq
    succ, indeg = {}, {i: 0 for i in ev.index}
    for a, b, *_ in edges:
        succ.setdefault(a, []).append(b); indeg[b] += 1
    heap = [(ev.at[i, "order_key"], str(i)) for i, d in indeg.items() if d == 0]
    heapq.heapify(heap); order = []
    while heap:
        _, eid = heapq.heappop(heap); order.append(eid)
        for nxt in succ.get(eid, []):
            indeg[nxt] -= 1
            if indeg[nxt] == 0:
                heapq.heappush(heap, (ev.at[nxt, "order_key"], str(nxt)))
    assert len(order) == len(ev), "cycle in the constraint graph"
    ev = ev.loc[order]
    ev["order_idx"] = np.arange(len(ev))
    ev["tie_break_timestamp"] = [ts + pd.Timedelta(microseconds=i + 1)
                                 for i, ts in enumerate(ev[TS])]
    ev["ordering_evidence"] = ["semantic_then_R5_R6_fallback"] * len(ev)
    ev = ev.drop(columns=["_stage", "_seq", "_ing"])
    ocel[EV] = ev
    # PM4Py: materialise the order, then and only then the index-based delta
    ocel = pm4py.ocel_sort_by_additional_column(ocel, "order_idx")
    ocel = pm4py.ocel_add_index_based_timedelta(ocel)   # "@@timedelta" = index gap!
    return ocel

# ------------------------------------------------- 5. integrity validation
def validate_integrity(ocel, label=""):
    ev_ids = set(ocel[EV].index.astype(str))
    obj_ids = set(ocel[OBJ].index.astype(str))
    rel = ocel[REL]
    problems = {}
    if sorted(set(rel[EID].astype(str)) - ev_ids):
        problems["orphan_relation_eid"] = sorted(set(rel[EID].astype(str)) - ev_ids)
    if sorted(set(rel[OID].astype(str)) - obj_ids):
        problems["orphan_relation_oid"] = sorted(set(rel[OID].astype(str)) - obj_ids)
    if sorted(ev_ids - set(rel[EID].astype(str))):
        problems["events_without_objects"] = sorted(ev_ids - set(rel[EID].astype(str)))
    if not ocel[EV].index.is_unique:
        problems["duplicate_eids"] = True
    if ocel[EV][TS].isna().any() or ocel[EV][ACT].isna().any():
        problems["nan_ts_or_activity"] = True
    for col in ("original_timestamp", "original_activity", "source", "source_event_key"):
        if col not in ocel[EV]:
            problems[f"lost_column:{col}"] = True
    return dict(scenario=label, n_events=len(ev_ids), n_e2o=len(rel),
                n_objects=len(obj_ids), problems=problems)

def expand_to_raw_view(ocel):
```

# 7. Sensitivity analysis

| Metric | raw | conservative | evidence merge | aggressive merge |
|---|---|---|---|---|
| events | 17 | 15 | 14 | 10 |
| E2O relations | 44 | 39 | 37 | 28 |
| Order-DFG edges | 16 | 14 | 13 | 9 |
| of which `XX` self-loops | 7 | 3 | 2 | 0 |
| `Pick Item–Item` ET-OT weight | 1.0 | 1.0 | 1.0 | 2.0 |
| `Capture Payment–Payment` weight | 0.67 | 0.67 | 0.67 | 2.0 |

**Order-flattened DFG (O1 contains all 17 events).** Raw is dominated by artifacts: 7 of its 16 edges are self-loops, so a miner reports a process that is nearly half rework. Conservative removes `PickPick` (one of two) and `Issue InvoiceIssue Invoice`, leaving `PackPack` (detail/summary echo), `PickPick` (real but parallel) and `CaptureCapture` (real: two partial payments). Evidence-based removes `PackPack`. Aggressive has **zero** self-loops and reads as a flawless straight-through process — the opposite error, because genuine anomalies (two captures of one invoice) are now invisible.

**Item-flattened.** Raw I1 = {e03, e04, e06} yields `PickPick` and `PickPack`: a phantom second pick of the same item. Conservative I1 = {c03, e06} yields only `PickPack`; I2 = {e05, e06} yields `PickPack`. Aggressive maps I1 and I2 onto one mega-pick, so both items show `PickPack` but the pick **count** (2 pickers, 2 scans) collapses to 1.

**Payment-flattened.** M1 = {e12, e13}  `AuthorizeCapture` in every scenario. M2 = {e14}  a single orphan `Capture` node with no DFG edge: a genuine data-quality signal (no authorisation record for M2) that is destroyed under aggressive merging, where the merged capture event relates to both M1 and M2 and the M2 flattening silently inherits the merged event. e15 appears in **no** payment flattening (fact 8) — that absence is itself the proof that it is not a capture.

**OC-DFG, ET–OT weights, OTG.** Six patterns whose interpretation changes:
1. `Pick Item  Pick Item` **via I1** — raw freq 1 (false rework), conservative 0.
2. `Pick Item  Pick Item` **via O1** — conservative 1 (c03e05): real concurrency that only reads as rework because of the linearisation.
3. `Pack Package  Pack Package` via P1 — raw/conservative 1 (abstraction echo), evidence 0.
4. `Dispatch Package  Dispatch Package` via P1/D1 — raw 1; conservative 0 once relabelled to `Release Package  Accept by Carrier`, which also exposes the warehousecarrier segment that aggressive merging deletes.
5. `Issue Invoice  Issue Invoice` via V1 — raw 1 (dual observation), conservative 0. If e11/e16 are kept (strict-min variant) it survives and is indistinguishable from a genuine invoice re-issue.
6. `Capture Payment  Capture Payment` via O1/V1 — raw 2, conservative 1 (the e14e15 echo, flagged), aggressive 0.
7. `Authorize Payment  Capture Payment` via M1 — invariant here, but any cross-activity timestamp-only rule would delete it.
8. `Handover to Carrier  Issue Invoice` — changes if e16 is linearised before or after the payment cluster.

ET–OT weights move as shown in the table (`Capture Payment–Payment` 0.67  2.0). OTG relation *edges* stay stable (Order–Item, Item–Package, Order–Package, Package–Delivery, Order–Invoice, Invoice–Payment), but aggressive merging creates **new self-co-occurrences**: I1 and I2 inside one `Pick Item` event (a spurious `Item–Item` co-occurrence) and M1 and M2 inside one `Capture Payment` event (spurious `Payment–Payment`) — neither ever happened physically.

**Lifecycle and performance.** V1's raw lifecycle shows two `Issue Invoice` occurrences, reading as an invoice correction cycle; I1 shows `PickPickPack`. Conservative cleans both. All timestamps tie at second granularity, so every non-zero duration comes from `@@timedelta`, which is a **linearisation gap**: `PackPick` would report a fabricated micro-duration. Legitimate measurable spans are `ValidatePick` (55 min), `PackRelease` (15 min), `HandoverIssue Invoice` (1 h 45 min), `Issue InvoiceConfirm Delivery` (21 h). Merging e08/e09 deletes the releaseaccept segment; merging e06/e07 deletes the WMSERP posting latency ( 55 s) — a real integration metric.

# 8. Audit trail and reversibility

Four tables plus an immutable snapshot (`raw_snapshot`: object-store pointer + SHA-256 + pipeline run id).

**`event_provenance`** — `canonical_eid` (PK); `source_event_ids` (JSON list of `{eid, source, source_event_key, source_seq}`); `merge_rule` (class A–F + rule id) and `rule_version`, `reviewer`; `original_activity` (per source, JSON map) and `refined_activity`; `original_timestamp` (per source, ISO-8601 with µs) and `adjusted_timestamp` / `tie_break_key` / `order_idx` / `ordering_evidence`; `attributes_retained` (JSON map `attr  {source  value, status: authoritative|secondary|conflicting}`); `discarded_conflicts` (JSON list `{attr, values per source, resolution, reason}`); `confidence` (0–1) and `reason` (free text) plus `evidence_ref` (report id); `decision_status` (retained | merged_canonical | dropped | quarantined | unresolved); `pipeline_run_id`, `created_at`, `config_hash`.

**`relation_provenance`** — `canonical_eid`, `oid`, `qualifier`, `object_type`, `contributed_by` (list of source eids), `relation_policy_applied` (union | intersection | master), `status` (kept | deduped | refused). Refusals are recorded, so "this Payment link was never added to e15" is auditable.

**`ordering_constraints`** — `from_eid`, `to_eid`, `rule_id`, `semantic` (bool), `hard` (bool), `evidence`, `assumed` (bool), `parallel_group` (id for ties left unordered).

**`raw_snapshot`** — pointer, hash, import config, source system versions.

**Reconstruction of the raw view.** Two lossless routes: (a) load `raw_snapshot`; (b) *expand* without the snapshot: for every `merged_canonical` row, re-emit one row per `source_event_id`, restoring `original_activity`, `original_timestamp` and that source's attribute values from `attributes_retained`/`@sources` tags, re-attaching that source's E2O pairs from `relation_provenance.contributed_by`, re-inserting `dropped` rows in reverse rule order (drop is logged as a tombstone, never a hard delete) and reverting `refined_activity` back to `original_activity`. The pre-check is then re-run on the rebuilt log and its candidate groups must reproduce the original report bit-for-bit (config hash comparison) — a machine-checkable reversibility test.

# 9. Failure modes and safeguards

1. **Collapsing distinct partial payments** (e13/e14: same O1, V1; M1  M2). *Safeguard:* container-invariant object-set equality **plus** at least one shared transactional object **plus** business-key equality; a test on `{M1}  {M2}` must block. Regression test asserting e14 survives.
2. **Turning abstraction updates into false rework** (e06e07, e14e15). *Safeguard:* `abstraction` and `derived_from` qualifiers; rework/loop metrics exclude edges where either endpoint is `summary`, and "echo edges" are reported separately.
3. **Ordering by ingestion time.** *Safeguard:* R5 is subordinate to R1–R4 and tagged `ingest_fallback`; a test shuffles `ingested_at` and asserts the semantic edge set is unchanged; ingestion time is banned from duration and throughput computation.
4. **Treating shared objects as proof of duplication.** *Safeguard:* the decision tree rejects existential object tests; in a single-order case every pair shares O1, so the guard degenerates to "merge everything".
5. **Unioning incompatible E2O relations.** *Safeguard:* per-pair `rel_policy`; `union` is executed only when one object set contains the others, otherwise the merge is refused (asserted in `merge_verified_pairs`). Merging e13 with e15 would attach M1 to an invoice-level balance update that no source claims.
6. **Changing durations with synthetic microseconds.** *Safeguard:* `original_timestamp` immutable; micro-stamps live only in `tie_break_key`; `@@timedelta` labelled "index gap"; performance reported only across second-resolution boundaries.
7. **Losing source-authoritative attributes** (keep-first drop, or a blind `combine_first`). *Safeguard:* per-attribute authority map, source-tagged retention of every value, `discarded_conflicts` audit, and a test that each source's authoritative fields survive in `attr@sources`.
8. **Applying duplicate functions to the whole OCEL without inspecting groups.** *Safeguard:* mandatory pre-check report; `ocel_merge_duplicates`/`ocel_drop_duplicates` run only on whitelisted scopes in the labelled scenario; event and E2O counts asserted before/after and diffed against the report; `warnings.warn` on the destructive path.
9. **Non-deterministic merge/keep-first** (pandas row order decides which row survives). *Safeguard:* explicit `master` eid per verified pair, stable sorting before any `drop_duplicates`, and a `config_hash` recorded in the audit trail so two runs must produce identical output.
10. **Irreversible merges / in-place mutation of `ocel_raw`.** *Safeguard:* `copy.deepcopy` per scenario, immutable raw snapshot with hash, tombstones instead of deletions, and the `expand_to_raw_view` reversibility test from §8.
11. **Reading the total order as physical truth.** *Safeguard:* `ordering_constraints` carry `semantic`/`hard` flags and `parallel_group` ids; reports state explicitly that linearisation is a rendering choice and that e03e05 and e13e14 remain unordered facts.
12. **Dropping e05 or e14 as "same activity + timestamp".** *Safeguard:* class E is terminal-retention by construction, with an assertion that no deletion path is reachable for rows whose `objs_canon` sets differ.
