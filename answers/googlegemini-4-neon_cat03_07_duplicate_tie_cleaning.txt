## 1. Duplicate-handling decision tree

Candidate duplicate groups are formed by inspecting events that share an identical `(timestamp, activity)` pair—or fall within a tight reconciliation window on shared objects—before applying any transformation. Each candidate pair is routed through the following decision tree:

```text
Candidate pair (e_a, e_b) with same timestamp (or tight window) and overlapping objects

 Q1: Identical (source, source_event_key, payload_hash, object_set)?
    YES  [Exact technical duplicate]
             ACTION: Drop duplicate row (keep canonical eid; retain duplicate ingestion metadata in audit log).

 Q2: Different sources, same harmonized activity, AND external reconciliation key /
      authoritative cross-reference confirms the SAME physical or business occurrence?
    YES  [Same physical event observed by multiple systems]
            ACTION: Merge attributes and relations (canonical eid, source-authoritative field mapping,
            verified E2O union, full source provenance preserved).
    NO   Continue to Q3.

 Q3: Same or different sources, same activity, AND the events reference DISTINCT
      fine-grained focal objects of the same type (e.g., I1 vs. I2; M1 vs. M2)?
    YES  [Concurrent same-label events involving different objects]
            ACTION: Retain both unchanged (never merge; preserve concurrency flag).
    NO   Continue to Q4.

 Q4: Different source systems where original pre-harmonization labels denote
      DISTINCT operational states or organizational responsibilities?
    YES  [Harmonization collision between semantically distinct source activities]
            ACTION: Retain both with refined labels or qualifiers (restore pre-harmonization semantics;
            preserve harmonized label in provenance).
    NO   Continue to Q5.

 Q5: One event is a downstream status/balance summary derived from one or more
      detailed operational events (often lacking fine-grained objects)?
    YES  [Summary event derived from a detailed event]
            ACTION (Conservative): Retain both with refined labels or qualifiers (explicit abstraction-level tag).
            ACTION (Evidence-based merge): Merge into single parent if 1:1, or retire to object-level
            reconciliation table if many-to-1—never attach blindly to one child.
    NO   [Unresolved candidate]
             ACTION: Quarantine for review (retain in staging with `review_status='quarantined'`;
             exclude from automated merges until SME adjudication).
```

This tree prevents premature deduplication by requiring positive identity evidence before any merge or drop, while separating technical noise from legitimate multi-object concurrency, harmonization artifacts, and multi-abstraction logging.

## 3. Timestamp-tie ordering rules

When events share an identical second-level UTC timestamp, converting their partial order into a reproducible total order requires a strict precedence hierarchy separating **semantic constraints** from **merely deterministic tie-breakers**:

1. **Primary business timestamp (`original_timestamp`)** *(Semantic)*: Distinct UTC timestamps always govern order across tie groups.
2. **Domain and causal precedence constraints** *(Semantic)*: Known physical or inter-organizational dependencies within a tie group—such as `Pick Item < Pack Package`, `Warehouse Release < Carrier Acceptance < Handover`, `Issue Invoice < ERP Payment Balance Summary`, and `Authorize Payment < Capture Payment` on the same Payment object.
3. **Lifecycle constraints on shared objects** *(Semantic)*: State-machine transitions on focal objects (e.g., an `Item` must be picked before being packed into `P1`; `M1` must be authorized before captured).
4. **Within-source sequence (`source_seq`)** *(Semantic within one source only)*: Monotonic sequence numbers emitted by the same system (e.g., `WMS: 100 < 110 < 120`, `CARRIER: 1 < 2`, `PSP: 400 < 401 < 402`, `ERP: 40 < 41`, and reconciled `SCANNER: 551 < 552`). Never compare `source_seq` across different systems.
5. **Source-specific propagation semantics** *(Semantic)*: Primary operational systems (WMS, PSP) precede downstream ERP status/balance summaries generated from their messages (`e06 < e07`; `{e13, e14} < e15`).
6. **Ingestion time (`ingested_at`)** *(Non-semantic — excluded from business ordering)*: Recorded strictly as technical observability metadata. Because network delays, batching, and retries invert business causality (for example, `e16` was ingested at `12:00:04`, *after* payment captures `e13`/`e14` at `12:00:03`), `ingested_at` must never serve as a primary business ordering rule.
7. **Stable fallback key (`canonical_eid` / `(source, source_event_key)`)** *(Merely deterministic)*: Breaks remaining ties among genuinely concurrent events solely to guarantee reproducible dataframe sorting across runs.

Rules 1–5 represent defensible semantic ordering constraints; Rule 7 is strictly a deterministic linearization aid and **does not prove true physical execution order** for concurrent events.

### Why synthetic microseconds must follow—never precede—semantic ordering

Calling `pm4py.ocel_add_index_based_timedelta` on an unsorted or ingestion-ordered log permanently hardcodes arbitrary row order into timestamps. In the raw table at `12:00:00`, ordering by `eid` places `e16` (`Issue Invoice`) *after* `e15` (`Capture Payment`), and ordering by `ingested_at` places `e16` between `e14` and `e15`. Adding microseconds first would fabricate a causal narrative where payment capture precedes invoicing, corrupting every downstream DFG, conformance check, and cycle-time query. Synthetic microsecond offsets must only be applied *after* computing a semantic sort key, while preserving `original_timestamp` and a `concurrency_group_id` so analysts know which precedences are merely linearized ties.

## 4. Conservative cleaning pipeline

The conservative pipeline minimizes semantic damage by modifying only what is strongly justified by source facts while retaining full diagnostic transparency:

1. **Immutable snapshot and metadata preservation:** Deep-copy `ocel_raw` and immediately persist `original_timestamp`, `original_activity`, `source`, `source_event_key`, `source_seq`, `ingested_at`, and `payload_hash` as protected event attributes.

3. **Harmonization and abstraction refinement:** Restore semantic distinctions obscured by upstream harmonization (`e08 -> Release Package from Warehouse`, `e09 -> Accept Package by Carrier`) and distinguish ERP summaries from operational events (`e07 -> Confirm Package Packed (ERP)`, `e15 -> Post Payment Summary (ERP)`), tagging `abstraction_level` as `operational` or `summary`.
4. **Scoped technical-duplicate hygiene:** Run `pm4py.ocel_drop_duplicates` only *after* verified merging and label refinement, confirmed by a pre-check to target solely exact technical duplicates or redundant E2O relation rows (dropping 0 business events here).
5. **Semantic tie-breaking and concurrency tagging:** Assign a `concurrency_group_id` to every original timestamp tie, sort using the Section 3 precedence key via `pm4py.ocel_sort_by_additional_column`, and only then apply `pm4py.ocel_add_index_based_timedelta` so deterministic tooling works without losing `original_timestamp`.

* `e13 + e14 + e15` collapse into one `Capture Payment` event (`{O1, V1, M1, M2}`).

**Expected retained count:** **10 events** and **28 E2O relations**.
**Most likely semantic damage:** Severe structural corruption. Distinct item picks (`e03`, `e05`), distinct partial payments (`e13`, `e14`), and distinct inter-organizational logistics steps (`e08`, `e09`) are silently destroyed, while BILLING-authoritative attributes from `e16` are dropped under first-record-wins behavior.

### Why `have_common_object=True` fails to protect `e13` and `e14`

In object-centric logs, events frequently carry both **coarse-grained context objects** (`Order O1`, `Invoice V1`, `Package P1`) and **fine-grained focal objects** (`Payment M1` vs. `M2`; `Item I1` vs. `I2`). The condition `have_common_object=True` checks only for a *non-empty intersection* of related objects ($\text{obj}(e_a) \cap \text{obj}(e_b) \neq \emptyset$). Because `e13` (`{O1, V1, M1}`) and `e14` (`{O1, V1, M2}`) share both `O1` and `V1`, the predicate evaluates to `True` and merges them—even though their focal `Payment` objects are strictly disjoint (`M1 != M2`). The identical flaw collapses `e03` and `e05` via shared `O1` and `P1`. Safe object-aware deduplication must reject merges whenever two events link to disjoint non-empty object sets of the same focal object type.

## 6. PM4Py-oriented Python implementation

The script below assumes `ocel_raw` is a loaded PM4Py `OCEL` object whose `events` DataFrame contains `source`, `source_event_key`, `source_seq`, `ingested_at`, and `payload_hash`. It leaves `ocel_raw` completely untouched, synchronizes both `events` and `relations` tables across custom merges, and compares all three cleaning pipelines.

```python
import copy
import warnings
import pandas as pd
import pm4py


def snapshot_and_preserve_metadata(ocel):
    """Deep-copy OCEL and freeze immutable provenance columns."""
    out = copy.deepcopy(ocel)
    ev = out.events
    ev["original_timestamp"] = ev[out.event_timestamp]
    ev["original_activity"] = ev[out.event_activity]
    # Guard required provenance metadata columns
    for col in ["source", "source_event_key", "source_seq", "ingested_at", "payload_hash"]:
        if col not in ev.columns:
            raise KeyError(f"Required metadata column missing: {col}")
    ev["merged_source_eids"] = ev[out.event_id_column].astype(str)
    ev["abstraction_level"] = "operational"
    return out


def precheck_duplicate_candidates(ocel):
    """Inspect (timestamp, activity) tie groups before any deduplication."""
    ev_id = ocel.event_id_column
    ev_act = ocel.event_activity
    ev_ts = ocel.event_timestamp
    obj_id = ocel.object_id_column
    obj_type = ocel.object_type_column

    rel_map = (
        ocel.relations.groupby(ev_id)[obj_id]
        .apply(lambda s: frozenset(s))
        .to_dict()
    )
    obj_type_map = ocel.objects.set_index(obj_id)[obj_type].to_dict()

    reports = []
    for (ts, act), grp in ocel.events.groupby([ev_ts, ev_act], sort=True):
        if len(grp) < 2:
            continue
        eids = grp[ev_id].tolist()
        obj_sets = [rel_map.get(e, frozenset()) for e in eids]
        shared_objs = set.intersection(*(set(s) for s in obj_sets)) if obj_sets else set()

        # Check if events diverge on any focal object type (e.g., Item or Payment)
        divergent_types = set()
        for otype in set(obj_type_map.values()):
            per_event_typed = [
                frozenset(o for o in s if obj_type_map.get(o) == otype)
                for s in obj_sets
            ]
            non_empty = [s for s in per_event_typed if s]
            if len(non_empty) > 1 and len(set(non_empty)) > 1:
                divergent_types.add(otype)

        exact_tech_dups = grp.duplicated(
            subset=["source", "source_event_key", "payload_hash", ev_ts, ev_act]
        ).sum()

        reports.append({
            "timestamp": ts,
            "activity": act,
            "eids": eids,
            "sources": grp["source"].tolist(),
            "shared_objects": sorted(shared_objs),
            "divergent_object_types": sorted(divergent_types),
            "exact_technical_duplicates": int(exact_tech_dups),
            "safe_for_blind_merge": bool(exact_tech_dups == len(grp) - 1),
        })
    return pd.DataFrame(reports)


def merge_verified_pair(
    ocel,
    canonical_eid,
    secondary_eid,
    rule_id,
    reason,
    secondary_attr_prefix,
    audit_log,
    secondary_authoritative_cols=None,
):
    """
    Merge a verified duplicate pair (secondary_eid -> canonical_eid) with
    source-authoritative attribute handling, E2O union, and audit logging.
    """
    ev_id = ocel.event_id_column
    ev_act = ocel.event_activity
    ev_ts = ocel.event_timestamp
    obj_id = ocel.object_id_column

    ev = ocel.events
    rel = ocel.relations
    c_mask = ev[ev_id] == canonical_eid
    s_mask = ev[ev_id] == secondary_eid
    if not c_mask.any() or not s_mask.any():
        raise ValueError(f"Pair ({canonical_eid}, {secondary_eid}) not found.")

    c_row = ev.loc[c_mask].iloc[0]
    s_row = ev.loc[s_mask].iloc[0]

    # Preserve secondary provenance and optionally promote authoritative fields
    for meta in ["source", "source_event_key", "source_seq", "payload_hash", "ingested_at"]:
        ev.loc[c_mask, f"{secondary_attr_prefix}_{meta}"] = s_row[meta]

    discarded_conflicts = {}
    for col in (secondary_authoritative_cols or []):
        if col in ev.columns and pd.notna(s_row[col]):
            if pd.notna(c_row[col]) and c_row[col] != s_row[col]:
                discarded_conflicts[col] = {
                    "kept_from": secondary_eid,
                    "discarded_from": canonical_eid,
                    "discarded_value": c_row[col],
                }
            ev.loc[c_mask, col] = s_row[col]

    ev.loc[c_mask, "merged_source_eids"] = (
        f"{c_row['merged_source_eids']},{secondary_eid}"
    )

    # Re-point secondary E2O relations to canonical_eid and union cleanly
    s_rel_mask = rel[ev_id] == secondary_eid
    rel.loc[s_rel_mask, ev_id] = canonical_eid
    rel.loc[s_rel_mask, ev_act] = c_row[ev_act]
    rel.loc[s_rel_mask, ev_ts] = c_row[ev_ts]
    dedup_subset = [c for c in [ev_id, obj_id, ocel.qualifier] if c in rel.columns]
    ocel.relations = rel.drop_duplicates(subset=dedup_subset).reset_index(drop=True)

    # Drop secondary event row after relation transfer
    ocel.events = ev.loc[~s_mask].reset_index(drop=True)

    audit_log.append({
        "canonical_eid": canonical_eid,
        "source_eids": [canonical_eid, secondary_eid],
        "merge_rule": rule_id,
        "rule_version": "v1.0",
        "original_activity": [c_row["original_activity"], s_row["original_activity"]],
        "refined_activity": c_row[ev_act],
        "original_timestamp": str(c_row["original_timestamp"]),
        "adjusted_timestamp": None,  # Populated after deterministic ordering
        "attributes_retained": {
            canonical_eid: ["primary_payload", c_row["source"]],
            secondary_eid: [f"{secondary_attr_prefix}_*", *(secondary_authoritative_cols or [])],
        },
        "discarded_conflicts": discarded_conflicts,
        "confidence": "High",
        "reason": reason,
    })
    return ocel


def relabel_event(ocel, eid, new_activity, abstraction_level=None, audit_log=None, reason=""):
    """Refine activity label in both events and relations tables."""
    ev_id, ev_act = ocel.event_id_column, ocel.event_activity
    mask_ev = ocel.events[ev_id] == eid
    old_act = ocel.events.loc[mask_ev, ev_act].iloc[0]
    ocel.events.loc[mask_ev, ev_act] = new_activity
    if abstraction_level is not None:
        ocel.events.loc[mask_ev, "abstraction_level"] = abstraction_level
    ocel.relations.loc[ocel.relations[ev_id] == eid, ev_act] = new_activity
    if audit_log is not None:
        audit_log.append({
            "canonical_eid": eid,
            "source_eids": [eid],
            "merge_rule": "RELABEL_SEMANTIC",
            "rule_version": "v1.0",
            "original_activity": [old_act],
            "refined_activity": new_activity,
            "original_timestamp": str(ocel.events.loc[mask_ev, "original_timestamp"].iloc[0]),
            "adjusted_timestamp": None,
            "attributes_retained": {eid: ["all"]},
            "discarded_conflicts": {},
            "confidence": "High",
            "reason": reason,
        })
    return ocel


def apply_semantic_ordering(ocel, audit_log):
    """
    Compute deterministic partial-order-to-total-order rank BEFORE adding
    microsecond tie-breakers via pm4py.ocel_add_index_based_timedelta.
    """
    ev = ocel.events
    ev_id = ocel.event_id_column
    ev_act = ocel.event_activity
    ev_ts = ocel.event_timestamp

    # Assign concurrency group IDs for ties on original_timestamp
    tie_counts = ev.groupby("original_timestamp")[ev_id].transform("count")
    ev["concurrency_group_id"] = ev["original_timestamp"].astype(str).where(tie_counts > 1, None)

    # Domain & abstraction stage ranks (semantic rules 2, 3, 5)
    stage_rank = {
        "Create Order": 10,
        "Validate Order": 20,
        "Pick Item": 30,
        "Pack Package": 40,
        "Confirm Package Packed (ERP)": 45,
        "Release Package from Warehouse": 50,
        "Accept Package by Carrier": 55,
        "Handover to Carrier": 60,
        "Issue Invoice": 70,
        "Authorize Payment": 80,
        "Capture Payment": 85,
        "Post Payment Summary (ERP)": 90,
        "Confirm Delivery": 100,
    }

    # Effective within-source sequence: use reconciled SCANNER seq=551 for e03 so e03 < e05
    def effective_seq(row):
        if row[ev_act] == "Pick Item" and pd.notna(row.get("scanner_source_seq")):
            return int(row["scanner_source_seq"])
        return int(row["source_seq"])

    ev["_stage_rank"] = ev[ev_act].map(stage_rank).fillna(999).astype(int)
    ev["_eff_seq"] = ev.apply(effective_seq, axis=1)

    # Build monotonic composite sort key (original_timestamp -> domain stage -> within-source seq -> stable eid)
    ordered = ev.sort_values(
        by=["original_timestamp", "_stage_rank", "_eff_seq", ev_id],
        ascending=[True, True, True, True],
        kind="mergesort",
    )
    rank_map = {eid: idx for idx, eid in enumerate(ordered[ev_id].tolist())}
    ev["semantic_order_rank"] = ev[ev_id].map(rank_map)
    ev.drop(columns=["_stage_rank", "_eff_seq"], inplace=True)

    # Step 1: Establish semantic order via PM4Py
    ocel = pm4py.ocel_sort_by_additional_column(ocel, "semantic_order_rank")

    # Step 2: Apply microsecond tie-breakers ONLY AFTER semantic order is fixed
    ocel = pm4py.ocel_add_index_based_timedelta(ocel)

    # Record adjusted timestamps in audit entries
    adj_map = ocel.events.set_index(ev_id)[ev_ts].astype(str).to_dict()
    for entry in audit_log:
        entry["adjusted_timestamp"] = adj_map.get(entry["canonical_eid"])
    return ocel


def validate_ocel_integrity(ocel, label, expected_events=None, expected_rels=None):
    """Verify referential integrity, provenance preservation, and relation hygiene."""
    ev_id, obj_id = ocel.event_id_column, ocel.object_id_column
    event_ids = set(ocel.events[ev_id])
    object_ids = set(ocel.objects[obj_id])

    orphan_rel_events = set(ocel.relations[ev_id]) - event_ids
    orphan_rel_objects = set(ocel.relations[obj_id]) - object_ids
    assert not orphan_rel_events, f"[{label}] Orphan event IDs in relations: {orphan_rel_events}"
    assert not orphan_rel_objects, f"[{label}] Orphan object IDs in relations: {orphan_rel_objects}"

    dedup_cols = [c for c in [ev_id, obj_id, ocel.qualifier] if c in ocel.relations.columns]
    dup_rels = ocel.relations.duplicated(subset=dedup_cols).sum()
    assert dup_rels == 0, f"[{label}] Duplicate E2O relations found: {dup_rels}"
    assert "original_timestamp" in ocel.events.columns, f"[{label}] original_timestamp missing"
    assert ocel.events["original_timestamp"].notna().all(), f"[{label}] Null original_timestamp"

    if expected_events is not None:
        assert len(ocel.events) == expected_events, (
            f"[{label}] Expected {expected_events} events, got {len(ocel.events)}"
        )
    if expected_rels is not None:
        assert len(ocel.relations) == expected_rels, (
            f"[{label}] Expected {expected_rels} relations, got {len(ocel.relations)}"
        )

candidate_report = precheck_duplicate_candidates(ocel_raw)
print("Candidate duplicate groups:\n", candidate_report.to_string(index=False))

# ---------------------------------------------------------------------------

ocel_conservative = merge_verified_pair(

# Refine harmonization collisions and abstraction-level summaries
ocel_conservative = relabel_event(

    abstraction_level="summary", audit_log=audit_conservative,

ocel_conservative = relabel_event(

ocel_conservative = relabel_event(

ocel_conservative = relabel_event(

# Justified use of pm4py.ocel_drop_duplicates: ONLY after verified merges and
# label refinement, acting as an exact technical-duplicate / relation hygiene guard.
pre_drop_count = len(ocel_conservative.events)
ocel_conservative = pm4py.ocel_drop_duplicates(ocel_conservative)
assert len(ocel_conservative.events) == pre_drop_count, (
    "Unexpected business event drop during technical hygiene step."
)

ocel_conservative = apply_semantic_ordering(ocel_conservative, audit_conservative)
validate_ocel_integrity(ocel_conservative, "conservative", expected_events=15, expected_rels=39)

# ---------------------------------------------------------------------------
# 2. Evidence-based semantic merging (13 events, 35 E2O relations)
# ---------------------------------------------------------------------------
audit_evidence = copy.deepcopy(audit_conservative)
ocel_evidence = copy.deepcopy(ocel_conservative)

# Absorb 1:1 ERP pack summary (e07 -> e06)
ocel_evidence = merge_verified_pair(
    ocel_evidence, "e06", "e07",
    rule_id="ABSORB_1TO1_SUMMARY",
    reason="Absorb downstream ERP pack status into detailed WMS packing event.",
    secondary_attr_prefix="erp_summary",
    audit_log=audit_evidence,
)

# Retire many-to-1 ERP payment summary (e15) to invoice reconciliation table
e15_ev = ocel_evidence.events[ocel_evidence.events[ocel_evidence.event_id_column] == "e15"]
invoice_reconciliation_table = e15_ev.copy()
ocel_evidence.events = ocel_evidence.events[
    ocel_evidence.events[ocel_evidence.event_id_column] != "e15"
].reset_index(drop=True)
ocel_evidence.relations = ocel_evidence.relations[
    ocel_evidence.relations[ocel_evidence.event_id_column] != "e15"
].reset_index(drop=True)
audit_evidence.append({
    "canonical_eid": None,
    "source_eids": ["e15"],
    "merge_rule": "RETIRE_MANY_TO_1_SUMMARY",
    "rule_version": "v1.0",
    "original_activity": ["Capture Payment"],
    "refined_activity": "RETIRED_TO_INVOICE_METADATA",
    "original_timestamp": str(e15_ev["original_timestamp"].iloc[0]),
    "adjusted_timestamp": None,
    "attributes_retained": {"e15": ["moved_to_invoice_reconciliation_table"]},
    "discarded_conflicts": {},
    "confidence": "Medium",
    "reason": "Avoid attaching invoice-level balance summary to a single partial payment.",
})

validate_ocel_integrity(ocel_evidence, "evidence_based", expected_events=13, expected_rels=35)

# ---------------------------------------------------------------------------
# 3. Mechanically aggressive PM4Py merging (10 events, 28 E2O relations)
# ---------------------------------------------------------------------------
ocel_aggressive = snapshot_and_preserve_metadata(ocel_raw)
warnings.warn(
    "UNSAFE BASELINE: pm4py.ocel_merge_duplicates(have_common_object=True) collapses "
    "distinct Item picks (e03/e05), distinct Payment captures (e13/e14), and "
    "harmonization collisions (e08/e09) because they share coarse objects (O1, P1, V1).",
    UserWarning,
)
ocel_aggressive = pm4py.ocel_merge_duplicates(ocel_aggressive, have_common_object=True)
validate_ocel_integrity(ocel_aggressive, "aggressive_library", expected_events=10, expected_rels=28)
```

## 7. Sensitivity analysis

| Metric / View | Raw (`17` ev / `44` rels) | Conservative (`15` ev / `39` rels) | Evidence-based (`13` ev / `35` rels) | Aggressive library (`10` ev / `28` rels) |
|---|---|---|---|---|
| **Order-flattened DFG (`O1`)** | Noisy self-loops on Pick (`3x`), Pack (`2x`), Dispatch (`2x`), Invoice (`2x`), Capture (`3x`); tie order can emit bogus `Capture -> Issue Invoice` (`e15->e16`). | Clean linear spine with legitimate `Pick -> Pick` (`2x`) and `Capture -> Capture` (`2x`), plus explicit ERP sync and carrier handoff nodes. | Cleanest operational spine; ERP sync nodes removed; retains `2x` Pick and `2x` Capture. | All self-loops vanish; appears as a single-item, single-payment, single-dispatch order. |
| **Item-flattened DFG (`I1`, `I2`)** | `I1` shows false `Pick Item -> Pick Item` rework (`e03->e04`); `I2` has single Pick. | Both `I1` and `I2` cleanly follow `Pick Item -> Pack Package` (`1x` each). | Identical to Conservative (`Pick -> Pack` per item). | Both `I1` and `I2` show `Pick -> Pack`, but share one merged Pick event (false batch-pick). |
| **Payment-flattened DFG (`M1`, `M2`)** | `M1`: `Authorize -> Capture`; `M2`: `Capture` (ERP `e15` absent from Payment view). | Identical clean per-payment lifecycles (`M1` and `M2` strictly isolated). | Identical to Conservative. | Per-payment traces look unchanged, masking the fatal merge of `M1` and `M2` into one event. |
| **OC-DFG & frequency metrics** | Inflated activity counts (Pick=3, Pack=2, Dispatch=2, Invoice=2, Capture=3) and spurious directly-follows arcs. | Accurate physical counts (Pick=2, Pack=1, Invoice=1, Capture=2) plus 2 ERP summary activities and 2 distinct dispatch activities. | Strictly operational frequencies (Pick=2, Pack=1, Release=1, Accept=1, Invoice=1, Capture=2). | Deflated frequencies (Pick=1, Capture=1) understate operational workload by 50% on picking and captures. |
| **ET–OT weights (avg objects/event)** | `Pick`: 1.0 Item; `Capture`: 0.67 Payment (`e15` lowers avg); `Pack`: 1.0 Item (`e07` halves avg). | `Pick`: 1.0 Item; `Pack`: 2.0 Items; `Capture`: 1.0 Payment; ERP summaries cleanly separated. | Same clean operational ET–OT weights without ERP summary event types. | **`Pick`: 2.0 Items** (false batching); **`Capture`: 2.0 Payments** (false bundled capture). |
| **OTG / co-occurrence relations** | `I1–I2` co-occur only in `Pack`; `M1–M2` never co-occur. | Same accurate co-occurrence structure as Raw. | Same accurate co-occurrence structure. | Invents false `M1–M2` co-occurrence in `Capture Payment` and false `I1–I2` co-occurrence in `Pick Item`. |
| **Apparent rework / loops** | 5 apparent rework loops (`Pick`, `Pack`, `Dispatch`, `Invoice`, `Capture`). | 0 false rework loops; only true multi-object repetitions (`2` items picked, `2` partial payments captured). | Same as Conservative. | 0 loops—suppresses real partial-payment and multi-item picking repetitions. |
| **Lifecycle & performance KPIs** | Tie ambiguity produces arbitrary 0-second or inverted durations; ERP summaries skew cycle times. | Preserves `original_timestamp` for KPIs (avoiding microsecond artifacts); exposes WMS-to-ERP and PSP-to-ERP ingestion lag. | Clean operational throughput times; loses ERP synchronization latency visibility. | Corrupts pick-to-pack and partial-payment settlement counts; drops carrier-acceptance checkpoint. |

### Concrete edges and patterns whose interpretation changes

1. **`Pick Item -> Pick Item` on `I1` vs. `O1`:** In Raw, `e03 -> e04` creates a false rework loop on `I1`. Conservative eliminates the `I1` loop while keeping `Pick Item -> Pick Item` on `O1` (two distinct items). Aggressive removes the `O1` loop too, falsely implying single-scan batch picking.
2. **`Pack Package -> Pack Package` on `O1`/`P1`:** Raw displays physical re-packing rework (`e06 -> e07`). Conservative transforms it into `Pack Package -> Confirm Package Packed (ERP)`, revealing system propagation. Evidence-based and Aggressive remove the edge entirely.
3. **`Dispatch Package -> Dispatch Package` on `O1`/`P1`/`D1`:** Raw implies double-dispatching (`e08 -> e09`). Conservative and Evidence-based reveal the true inter-organizational handoff `Release Package from Warehouse -> Accept Package by Carrier -> Handover to Carrier`. Aggressive deletes carrier acceptance altogether.
4. **`Issue Invoice -> Issue Invoice` on `O1`/`V1`:** Raw shows erroneous double-invoicing (`e11 -> e16`), and sorting Raw by `eid` or `ingested_at` creates a bogus backward **`Capture Payment -> Issue Invoice`** edge (`e15 -> e16` or `e14 -> e16`). Conservative and Evidence-based eliminate both artifacts while retaining ERP and BILLING attributes.
5. **`Capture Payment -> Capture Payment` on `O1`/`V1`:** Raw conflates two partial captures and an ERP balance update into a 3-event loop. Conservative isolates the 2 legitimate partial captures followed by `Capture Payment -> Post Payment Summary (ERP)`. Aggressive collapses all three into a single capture, hiding split-payment behavior.
6. **`Payment` ET–OT weight on `Capture Payment` (and `M1–M2` OTG co-occurrence):** Conservative maintains a strict 1:1 `Capture Payment`–`Payment` ratio with zero `M1–M2` co-occurrence. Aggressive doubles the weight to 2 Payments per Capture and fabricates a direct `M1–M2` co-occurrence link.
7. **`Item` ET–OT weight on `Pick Item`:** Conservative preserves 1 Item per `Pick Item` (`I1` and `I2` picked individually). Aggressive doubles it to 2 Items per `Pick Item`, rewriting warehouse picking semantics.

## 8. Audit trail and reversibility

Every cleaning transformation writes an append-only JSON/Parquet record to `ocel_cleaning_audit`, paired with an immutable raw staging snapshot (`ocel_raw_events`, `ocel_raw_relations`).

### Provenance schema

| Column | Type | Purpose |
|---|---|---|
| `canonical_eid` | `string \| null` | Surviving event ID in cleaned OCEL (`null` if retired to object metadata) |
| `source_eids` | `list<string>` | All raw `eid` values contributing to this decision (e.g., `["e11", "e16"]`) |
| `merge_rule` | `string` | Rule identifier (`VERIFIED_PHYSICAL_SCAN`, `RELABEL_SEMANTIC`, `RETIRE_MANY_TO_1_SUMMARY`) |
| `reviewer_or_rule_version` | `string` | Automated rule version (e.g., `pipeline-v1.0`) or human SME reviewer ID |
| `original_activity` | `list<string>` | Pre-cleaning harmonized activity labels for each `source_eid` |
| `refined_activity` | `string` | Post-cleaning label (or retirement target) |
| `original_timestamp` | `timestamp_utc` | Unmodified business UTC timestamp |
| `adjusted_timestamp` | `timestamp_utc` | Post-tie-breaking timestamp with microsecond offset |
| `attributes_retained` | `json` | Map of `source_eid -> retained column names / prefixed fields` |
| `discarded_conflicts` | `json` | Conflicting field values dropped during merges, with source and value |
| `confidence` | `enum` | `High`, `Medium`, `Low`, or `Quarantined` |
| `reason` | `string` | Human-readable business justification and external evidence reference |

### Reconstructing the raw view

An analyst reconstructs the exact raw OCEL in two ways:
1. **Direct snapshot join:** Join `ocel_cleaning_audit.source_eids` back to immutable `ocel_raw_events` and `ocel_raw_relations` to inspect raw payloads, original E2O links, and pre-merge counts side-by-side with cleaned metrics.
2. **Inverse replay:** For any subset of rules (for example, rolling back `ABSORB_1TO1_SUMMARY` while keeping `VERIFIED_PHYSICAL_SCAN`), expand each affected `canonical_eid` back into its `source_eids`, restore `original_activity` and `original_timestamp`, rehydrate dropped attributes from `discarded_conflicts` and the raw snapshot, and restore per-source E2O tuples. No destructive in-place overwrite ever occurs.

## 9. Failure modes and safeguards

1. **Collapsing distinct partial payments (`e13`/`e14`):**
   * *Failure:* Grouping by `(timestamp, activity)` with `have_common_object=True` merges `M1` and `M2` via shared `O1`/`V1`, erasing partial payment counts.
   * *Safeguard:* Enforce a focal-object disjointness veto—block any merge when two events reference non-empty, disjoint sets of the same object type (`Payment`, `Item`).
2. **Converting abstraction-level updates into false rework (`e06`/`e07`, `e13`/`e14`/`e15`):**
   * *Failure:* Leaving ERP status/balance messages under identical operational labels creates phantom `Pack -> Pack` and `Capture -> Capture` rework loops.
   * *Safeguard:* Tag `abstraction_level` (`operational` vs. `summary`) and qualify summary labels (or route them to a separate reconciliation view) before DFG discovery.
3. **Ordering by ingestion time (`ingested_at`):**
   * *Failure:* Asynchronous ETL delays place `e16` (`12:00:04`) after `e13`/`e14` (`12:00:03`), fabricating backward `Capture Payment -> Issue Invoice` edges.
   * *Safeguard:* Explicitly ban `ingested_at` from semantic sort keys; retain it solely for ETL latency monitoring.
4. **Treating shared objects as proof of duplication:**
   * *Failure:* Assuming shared `O1`, `P1`, or `V1` implies event identity collapses concurrent events (`e03`/`e05`) and harmonization collisions (`e08`/`e09`).
   * *Safeguard:* Require positive cross-system identity evidence (reconciliation report, shared business key such as invoice `V1`, or exact technical key) plus source-label compatibility before merging.
5. **Unioning incompatible E2O relations:**
   * *Failure:* Blindly unioning relations from merged events fabricates impossible multi-object co-occurrences (`M1–M2` in `Capture Payment`, `I1–I2` in `Pick Item`) and distorts ET–OT weights.
   * *Safeguard:* Assert object-set compatibility prior to relation union (identical sets for verified duplicates, or strict subset only for verified 1:1 summary absorption; prohibit many-to-1 merges).
6. **Changing durations through synthetic microseconds:**
   * *Failure:* Applying `ocel_add_index_based_timedelta` before semantic sorting locks in false order, and feeding synthetic timestamps into SLA/duration formulas distorts zero-duration tie detection.
   * *Safeguard:* Compute semantic order via `ocel_sort_by_additional_column` first, keep `original_timestamp` intact, tag `concurrency_group_id`, and compute all business duration KPIs on `original_timestamp`.
7. **Losing source-authoritative attributes:**
   * *Failure:* Dropping one row blindly during deduplication discards WMS warehouse location (`e03`) or BILLING tax/document metadata (`e16`).
   * *Safeguard:* Implement field-level authority maps in custom merge helpers and log every overwritten conflict in `discarded_conflicts`.
8. **Applying duplicate functions to the whole OCEL without inspecting candidate groups:**
   * *Failure:* Running `ocel_merge_duplicates` or `ocel_drop_duplicates` globally silently alters unrelated event types and drops legitimate concurrency.
   * *Safeguard:* Mandate a candidate-group pre-check report (`precheck_duplicate_candidates`), scope `ocel_drop_duplicates` strictly to post-refinement technical hygiene with event-count assertions, and quarantine any unresolved candidate for SME review.
