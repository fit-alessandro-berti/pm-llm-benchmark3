## 1. Control-Objective Decomposition

FEP-1 is not merely “two different user IDs.” It is a segregation-of-duties control whose purpose is to stop one human from both initiating and authorizing an erroneous or fraudulent transfer. Decomposed objectives / threat scenarios:

| # | Objective / threat | AV-2 | MG-4 | RA-7 | ED-1 |
|---|---|---|---|---|---|
| T1 | Solo honest error (wrong vendor, amount, duplicate) reaches the bank | **Prevent** (duplicate, PO match, limits); weak on commercial judgment | **Prevent** if pre-settlement review is real; else detect only | **Detect**; **correct** only inside recall window | Permits solo path only if other gates hold; does not itself validate accuracy |
| T2 | Solo malicious fraud by preparer/releaser | **Partial prevent** (sanctions, recent bank change, limits); **fails** collusion-free intent and receipt reality | **Prevent** if independent and pre-settlement; **fails** if rubber-stamp, subordinate capture, or shared credentials | **Detect** after the fact; **correct** only if timely recall still possible | **Fails** the threat if conditions are incomplete; is a constrained exception, not a substitute for independence |
| T3 | Account-takeover / compromised operator credentials | **Partial** (bank-change, sanctions, limits); **does not** establish who controlled the session | **Partial** if manager is out-of-band and reviews bank details; **fails** if same channel/credentials | **Detect** anomalous pattern; recovery uncertain | **Fails** if emergency path is used under compromise |
| T4 | Collusion between two nominal actors (or preparer + captured manager) | **Does not address** collusion or fake receipts | **Fails** if manager is not independent or does not review substance | **Detect** via sampling/forensics; late audit often non-corrective | **Does not address** collusion; may concentrate power in one operator |
| T5 | Fraudulent payee / recent bank-account diversion | **Prevent/warn** on 7-day bank change and ownership checks | **Prevent** if bank details reviewed before irrevocable settlement | **Detect**; recall possible briefly | Requires no 7-day bank change and live AV-2 — otherwise ED-1 is invalid |
| T6 | Payment without goods/services / commercial unreasonableness | **Does not address** (explicit limitation) | **Prevent** only if invoice + receipt/support reviewed substantively | **Detect** fabricated support; often after money moved | **Does not** remove need for substance review under MG-4 |
| T7 | Post-release recoverability when preventive SoD failed | N/A (pre-release) | **Hybrid** if before settlement; weak after settlement | **Correct** only ~24h recall; else mostly detective/loss accounting | Demands MG-4 before settlement and RA-7 within one business day as compensating recoverability |

**Cross-cutting failure modes:** shared service accounts (not independent humans); manager override credentials held by the operator; rubber-stamp MG-4; AV-2 outage; audit after recall window; repeated pairs/shared workstations that recreate single-team control.

## 2. Equivalence and Sufficiency Test

A compensating package is judged against FEP-1’s objectives (T1–T7), not against activity counts.

**Fully equivalent** — All of the following hold: (a) **timing:** independent human challenge occurs before irrevocable bank settlement (ideally before release); (b) **independence:** reviewer  preparer/releaser, not a performance-rating superior in an unresolved conflict, no shared emergency/override credential; (c) **coverage:** payee identity, bank details, amount/authority, and supporting receipt/commercial basis are in scope (AV-2 alone never equals full coverage); (d) **overrideability:** no self-override of AV-2 warnings; blocks cannot be silently bypassed; (e) **recoverability:** if release already happened, settlement not yet final and recall path still live, or amount/vendor residual risk is inherently negligible *and* detective control is immediate; (f) **evidence quality:** contemporaneous review artifacts, not post-hoc ratification; (g) **collusion resistance:** no strong pattern of captured pairs, shared workstations without compensating rotation, or credential sharing. ED-1 met in full can be treated as a **policy-authorized equivalent path**, not as “FEP-1 disappeared.”

**Partially equivalent** — Core diversion/error paths are largely constrained (e.g., clean AV-2 + independent pre-settlement MG-4 on low-complexity established vendor) but at least one pillar is weak: late manager action, thin substance review, missing receipt assurance, borderline audit timing, or unjustified same-user convenience on a non-emergency.

**Merely mitigating** — Controls reduce expected loss or narrow some threat scenarios but leave a material open path (self-override, manager after settlement, AV-2 down, dependent manager, audit outside recall window, high amount + bank-change proximity).

**Ineffective** — Nominal activities occurred but failed independence, timing, or coverage so badly that T2/T5-style loss remains plausible; or detective-only response after irrevocable settlement with no real recovery.

**Why “same expected loss” is not the only standard**
- **Control integrity / non-financial objectives:** regulators and group policy care about authorization integrity, not only EL. A lucky non-loss high-risk path is still nonconforming.
- **Uncertainty and fat tails:** EL models understate rare fraud and collusion; evidence quality and independence bound model error.
- **Recoverability asymmetry:** post-settlement legal recovery is exceptional; a control that only equalizes *average* loss can still create unacceptable unrecoverable tails.
- **Moral hazard / monitoring:** repeated “mitigated” exceptions erode culture and enable credential sharing.
- **Option value of prevention:** preventive SoD preserves the chance to stop payment; pure detective equality assumes detection probability and recall that often do not exist.

 sufficiency is therefore: **risk reduced enough relative to case threat profile, with the right control type at the right time, by sufficiently independent actors, with durable evidence** — not merely “something fired” or “amount was small.”

## 4. Preventive–Detective–Corrective Comparison

| Control | Primary type | When it binds | Strength conditions | Typical failure mode |
|---|---|---|---|---|
| FEP-1 (distinct prepare/release humans) | Preventive SoD | At release authorization | True human independence; no shared accounts | Collusion; pair capture; service accounts |
| AV-2 | Preventive (block) / preventive-with-escape (warn+override) | Before release | Full operational status; no self-override; rules cover bank change, dup, limits | Outage; override; no receipt/collusion coverage |
| MG-4 | Preventive if before release; **hybrid** if after release but before settlement; detective if after settlement | Relative to release & settlement | L3+, independent, substance review of invoice/bank/receipt | Rubber stamp; dependent manager; credential lending; late ratify |
| RA-7 | Detective; **partly corrective** only inside bank recall (~24h) and before irreversible end-state | Post-release | 100% on emergency same-user; speed; authority to trigger recall | Audit after recall window  loss accounting only |
| ED-1 | Conditional authorization framework (not a detective control) | Gates the legality of same-user path | All 7 conditions concurrent | Partial condition satisfaction treated as full permission |

**Semantics for manager action after `Release_Payment` but before settlement:**  
Treat as **hybrid preventive–corrective**, not pure detective. Rationale: the payment instruction may be cancellable or recallable before bank settlement; an independent manager who can still **stop irrevocable outflow** is exercising a preventive control on the *loss event*, even though the *system release step* already occurred. After settlement, the same “Manager_Ratify” is **detective** (and only weakly corrective via exceptional legal recovery). Rubber-stamp post-release ratification without stop authority is detective theater.

**Ordering insight:** AV-2 and pre-release MG-4 dominate risk reduction. RA-7 never fully substitutes for them on high-amount or bank-change cases. ED-1 is a **structured residual-risk acceptance** requiring the other controls to be green.

## 5. Counterfactual and Residual-Risk Analysis

**AP-202 (realized loss)**  
- **Loss mechanism:** fresh bank diversion on new vendor + solo operator self-override + conflicted delayed manager  funds to employee relative.  
- **Chain break that should have worked:** hard AV-2 block (or dual control) on bank change + operator limit without self-override; independent pre-settlement MG-4.  
- **Still exposed after partial fixes:** collusion if supervisor participates; compromised override vault.  
- **Independent second releaser:** likely blocks or forces visible dual authorization on bank-change warning; **qualitative loss probability drops from high to low**, unless collusion includes the second releaser (then still open — needs rotation/audit).  

**AP-204 (fabrication despite nominal SoD)**  
- **Mechanism:** fake receipt + stable u12/u13 pair/shared workstation  effective single team.  
- **Chain break:** substance MG-4 or receiving confirmation independent of the pair; forensic audit before repeat high-value consulting pays.  
- **Remains exposed:** sophisticated collusion with rotated third party still possible but harder.  
- **True independent second releaser (not the habitual pair):** materially raises collusion cost; **residual fraud risk mediumlower**, not zero.  

**AP-208 (legitimate outcome, intolerable control hole)**  
- **Mechanism (counterfactual fraud):** payee swap during AV-2 outage + solo release + post-settlement manager.  
- **Chain break:** deny release without AV-2 or mandatory independent manual ownership verification logged pre-release; amount far above ED-1 cap.  
- **Remains exposed:** manual verification quality; emergency culture pressure.  
- **Independent second releaser during outage:** forces dual acceptance of unsigned checklist risk; **unrecoverable tail exposure highmoderate**, still unacceptable without AV-2.  

**AP-201 (low-amount convenience breach)**  
- **Mechanism:** solo mis-key or small fraud on office supply.  
- **Chain break already partly present:** AV-2 + independent m04 before settlement.  
- **Remains exposed:** post-release window misuse; habit-forming same-user releases.  
- **Independent second releaser:** little change to *this* loss path (already low); **improves control culture / monitoring purity**. EL already low.  

**AP-206 (token timing ambiguity)**  
- **Mechanism if abusive:** operator prepares first, then mints emergency token to justify solo release during “outage.”  
- **Chain break:** enforce token-active-before-prepare in system workflow (not log narrative); keep pre-release MG-4 (present).  
- **Remains exposed:** manager social-engineered by outage urgency.  
- **Independent second releaser:** removes need to trust token chronology for SoD; **policy risk highlow** even if operational urgency remains.  

**AP-203 / AP-207 (ED-1 successes — brief)**  
- Plausible loss mechanism is urgency-driven rubber stamp; broken by documented pre-settlement independent MG-4 + live AV-2. Independent second releaser would add little on T1/T5 given clean facts; main residual is rare manager–operator collusion (**low** on stated independence).

## 6. Evidence and Monitoring Recommendations

**Collect / retain**
- Immutable prepare/release resource IDs (reject service accounts for either step unless dual person-bound MFA).  
- AV-2 mode: pass / warn / block / **unavailable**; rule-level hits; override principal  operator.  
- Emergency token: issuer, valid-from/to, **binding to case ID**, server-side time.  
- Manager act: before_release / before_settlement / after_settlement; independence check (HR graph); conflict flags (direct supervisor).  
- Audit start vs release vs bank settlement; recall attempted Y/N.  
- Workstation/device ID, IP, and co-location for prepare+release pairs.  
- Vendor age, bank-change timestamps, amount vs limits.  
- Receipt/PO/receiving evidence hash linked at approval time.

**Monitoring rules (alert  proof of misconduct)**

| Signal | Alert use | Not proof by itself |
|---|---|---|
| Same-user prepare+release rate by operator/day | Spike vs baseline; 100% RA-7 queue | Could be ED-1-heavy role |
| AV-2 override rate + self-override | Hard alert; block policy | Need intent investigation |
| Late MG-4 (after settlement) | Conformance breach alert | Does not prove theft |
| Audit not started within recall window on same-user/emergency | SLA breach + recall desk trigger | May be staffing delay |
| Repeated resource pairs (e.g., u12–u13) above threshold | Collusion/concentration risk review; force rotation | May be designed two-person cell — needs org evidence |
| Shared workstation on high-value releases | Elevated sampling | Shift-based dual desk possible |
| Bank change within 7 days + release | Mandatory independent MG-4 pre-release; no ED-1 | Legitimate vendor updates exist |
| AV-2 outage window releases | Freeze or dual control; post-incident QA | Outage may be brief/partial |
| Manager credential used by non-manager | Security incident | Could be break-glass with ticket — still verify |

**Governance:** score packages with the equivalence test in §2; never auto-close “AV-2 passed  compliant.” Treat AP-204-class pair risk as **objective** monitoring even when FEP-1 nominally holds.

def first_time(cid, activities):
    if isinstance(activities, str):
        activities = [activities]
    sub = log_df[
        (log_df["case:concept:name"] == cid)
        & (log_df["concept:name"].isin(activities))
    ].sort_values("time:timestamp")
    if sub.empty:
        return pd.NaT
    return sub["time:timestamp"].iloc[0]


def last_time(cid, activities):
    if isinstance(activities, str):
        activities = [activities]
    sub = log_df[
        (log_df["case:concept:name"] == cid)
        & (log_df["concept:name"].isin(activities))
    ].sort_values("time:timestamp")
    if sub.empty:
        return pd.NaT
    return sub["time:timestamp"].iloc[-1]

    prep_t = first_time(cid, "Prepare_Payment")
    rel_t = first_time(cid, "Release_Payment")
    att_t = first_time(cid, "Attempt_Release")
    mgr_t = first_time(cid, ["Manager_Approve", "Manager_Ratify"])
    aud_t = first_time(cid, "Audit_Review")
    set_t = first_time(cid, "Bank_Settlement")
    av_pass = first_time(cid, "Automated_Validate")

    pair = None
    if prep_r and rel_r:

        "has_attempt_no_release": pd.notna(att_t) and pd.isna(rel_t),

def evidence_banner(r):
    notes = []
    if r["has_attempt_no_release"] or r["av_block_event"] and not r["has_release"]:
        notes.append("EVIDENCE:prevented_before_completion")
    if r["nominal_fep1_violation_completed"]:
        notes.append("EVIDENCE:nominal_SoD_break_completed_payment")
    if r["nominal_fep1_satisfied_completed"]:
        notes.append("EVIDENCE:nominal_SoD_form_ok")
    if r["av_unavailable_event"]:
        notes.append("EVIDENCE:av2_outage_at_release_path")
    if r["override_by_preparer"]:
        notes.append("EVIDENCE:self_override")
    if r["manager_after_settlement"]:
        notes.append("EVIDENCE:manager_after_irrevocable_settlement")
    if r["manager_after_release_before_settlement"]:
        notes.append("EVIDENCE:manager_hybrid_pre_settlement")
    if r["manager_before_release"]:
        notes.append("EVIDENCE:manager_pre_release_preventive")
    if r.get("bank_changed_7d") == True:
        notes.append("EVIDENCE:bank_change_proximity")
    if r.get("flag_repeated_pair"):
        notes.append("EVIDENCE:repeated_resource_pair")
    if r.get("shared_workstation_pair") == True:
        notes.append("EVIDENCE:shared_workstation_fact")
    if r.get("fabricated_support") == True:
        notes.append("EVIDENCE:audit_found_fabricated_support")
    if r.get("funds_lost") == True:
        notes.append("EVIDENCE:loss_realized")
    if r.get("manager_conflict") == True:
        notes.append("EVIDENCE:manager_independence_conflict")
    if r["nominal_fep1_violation_completed"] and r["ed1_mechanical_all_green"]:
        notes.append("EVIDENCE:ed1_gates_mechanically_green")
    elif r["nominal_fep1_violation_completed"] and r["emergency_token_present"]:
        notes.append("EVIDENCE:ed1_incomplete_or_ambiguous")
    if pd.notna(r["audit_hours_after_release"]) and r["audit_hours_after_release"] > 24:
        notes.append("EVIDENCE:audit_outside_24h_recall_heuristic")
    return "|".join(notes)


merged["preliminary_evidence_flags"] = merged.apply(evidence_banner, axis=1)
