import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.bpmn.obj import BPMN
from pm4py.objects.process_tree.obj import ProcessTree

# --- Source POWL (from task description) ---
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")
legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(operator=Operator.XOR, children=[legal_review, skip_legal])
configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)
correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(operator=Operator.LOOP, children=[trial_body, correct_defect])
release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[register, assess_risk, prepare_evidence, optional_legal, verification_loop, release_change, archive_change]
)
source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)

# --- Pipeline 1: POWL  Petri Net  BPMN ---
print("=== Pipeline 1: POWL  Petri Net  BPMN ===")
try:
    # Convert POWL to Petri net
    net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(source_powl)
    print("Petri net conversion successful.")
    pm4py.save_vis_petri_net(net_from_powl, im_from_powl, fm_from_powl, "powl_to_petri_net.png")

    # Convert Petri net to BPMN
    bpmn_from_net = pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)
    print("BPMN conversion successful.")
    pm4py.save_vis_bpmn(bpmn_from_net, "powl_to_bpmn_via_petri.png")

    # Round-trip BPMN back to Petri net
    net_from_bpmn, im_from_bpmn, fm_from_bpmn = pm4py.convert_to_petri_net(bpmn_from_net)
    pm4py.save_vis_petri_net(net_from_bpmn, im_from_bpmn, fm_from_bpmn, "bpmn_roundtrip_petri_net.png")

except Exception as e:
    print(f"Pipeline 1 failed: {e}")

# --- Pipeline 2: POWL  Petri Net  Process Tree  BPMN ---
print("\n=== Pipeline 2: POWL  Petri Net  Process Tree  BPMN ===")
try:
    # Reuse Petri net from Pipeline 1
    net, im, fm = net_from_powl, im_from_powl, fm_from_powl

    # Attempt process tree conversion
    try:
        tree = pm4py.convert_to_process_tree(net, im, fm)
        print("Process tree conversion successful.")
        pm4py.save_vis_process_tree(tree, "petri_to_process_tree.png")

        # Convert process tree to BPMN

except Exception as e:

**Key Observations**:
- **True concurrency vs. interleaving**: The Petri net preserves true concurrency (e.g., `Assess Risk` || `Prepare Evidence`), but BPMN may render this as a parallel gateway (correct) or as arbitrary interleaving (misleading).
- **Lack of edge between Optional Legal and Verification**: The Petri net correctly models these as concurrent, but BPMN may imply a false dependency due to layout.
- **Silent optional behavior**: The silent transition (`skip_legal`) is preserved in the Petri net but may be invisible in BPMN.
- **Binary-loop semantics**: The LOOP operator in POWL is faithfully represented in the Petri net, but BPMN loops are often approximated with ad-hoc gateways.
- **Join before Release**: The synchronization is preserved in the Petri net and expected in BPMN.
- **Activity-label uniqueness**: All labels are unique in the source and preserved in conversions.
- **Gateway ambiguity**: BPMN may use exclusive gateways for XOR (correct for `optional_legal`) but may misrepresent concurrency.

# 5. Round-Trip Validation Code

```python
import itertools
from pm4py.objects.log.obj import Trace

def get_visible_traces(net, im, fm, max_visible_length=5, max_silent_steps=10):
    """Bounded exploration of visible traces, hiding silent transitions."""
    visited = set()
    queue = [(im, [])]
    traces = set()

    while queue:
        marking, trace = queue.pop(0)
        state_key = frozenset(marking.items())

        if state_key in visited:
            continue
        visited.add(state_key)

        # Check if final marking is reached
        if marking == fm:
            traces.add(tuple(trace))
            continue

        # Stop if trace exceeds bounds
        if len([t for t in trace if t is not None]) >= max_visible_length:
            continue

        # Get enabled transitions
        enabled = pm4py.get_enabled_transitions(net, marking)
        for t in enabled:
            new_marking = marking.copy()
            # Fire the transition
            for arc in net.arcs:
                if arc.source == t:
                    new_marking[arc.target] = new_marking.get(arc.target, 0) + 1
                if arc.target == t:
                    new_marking[arc.source] = new_marking.get(arc.source, 0) - 1
            new_marking = {p: count for p, count in new_marking.items() if count > 0}

            # Skip if silent transition would exceed bound
            if t.label is None and trace.count(None) >= max_silent_steps:
                continue

            new_trace = trace + [t.label]
            queue.append((new_marking, new_trace))

    return traces

# --- Compare nets ---
print("\n=== Round-Trip Validation ===")

# 6. Visual-Semantics Review

**Potential Misinterpretations in BPMN Rendering**:
1. **Parallel Gateways**: The concurrency between `Assess Risk` and `Prepare Evidence` may be correctly shown as a parallel gateway, but stakeholders might assume sequential execution if the layout is linear.
2. **Exclusive Gateways**: The XOR for `optional_legal` is correct, but the silent transition (`skip_legal`) may not be visible, leading to confusion about the "skip" path.
3. **Loop Visualization**: The verification loop may be rendered as a cyclic path, but BPMN does not natively support strict partial-order loops. The `Correct Defect` transition may appear as a conditional branch rather than a loop separator.
4. **Silent Routing Nodes**: Silent transitions (e.g., `skip_legal`) may be omitted or replaced with invisible gateways, making the optional behavior harder to trace.
5. **Apparent Ordering**: The BPMN layout may imply an order between `optional_legal` and `verification_loop` (e.g., left-to-right) even though they are concurrent in the Petri net.

**Proposed Annotations**:
- Add text annotations to clarify that `Assess Risk` and `Prepare Evidence` are unordered.
- Explicitly label the silent transition path in the XOR gateway (e.g., "Skip Legal Review").
- Use a sub-process with a loop marker for the verification loop and document that `Correct Defect` separates iterations.
- Add a note that `Release Change` waits for both `optional_legal` and `verification_loop`.

# 7. Rejection Criteria

A conversion result should be rejected or quarantined if:
1. **Unsoundness**: The converted Petri net or BPMN model fails soundness checks (e.g., deadlocks, livelocks, or lack of proper completion).
2. **Missing Synchronization**: The join before `Release Change` is missing, allowing `Release Change` to fire before both `optional_legal` and `verification_loop` complete.
3. **Lost Optionality**: The silent transition (`skip_legal`) is removed or replaced with a visible transition, collapsing the optional behavior.
4. **Loop Semantics Violation**: The verification loop does not enforce at least one iteration or allows `Correct Defect` to fire without a prior `Inspect Trial`.
5. **Final Marking Mismatch**: The final marking does not require `Archive Change` to be the last activity.
6. **Trace Non-Inclusion**: A positive witness trace from the source POWL (e.g., `<Register Change, Assess Risk, Prepare Evidence, Configure Trial, Inspect Trial, Release Change, Archive Change>`) is not replayable in the converted model.
7. **Spurious Traces**: The converted model admits a negative witness trace (e.g., `<Register Change, Release Change>`).
8. **Label Non-Uniqueness**: Activity labels are duplicated or altered in the converted model.

# 8. Canonical Representation Recommendation

**Authoritative Representation**: The **POWL model** should be the authoritative storage format because:
- It explicitly captures partial orders, concurrency, and loop semantics without ambiguity.
- It is machine-readable and supports formal validation.

**Derivative Artifacts**:
- **Petri Net**: Generated from POWL for behavioral analysis (e.g., soundness, reachability). Must be accompanied by:
  - Soundness validation results.
  - Footprint comparison with the source POWL.
  - Round-trip validation evidence.
- **BPMN**: Generated from the Petri net for stakeholder visualization. Must be accompanied by:
  - A warning that layout does not imply semantics.
  - Annotations clarifying concurrency and optionality.
  - Round-trip validation results.

**Process Tree Intermediate**: Should **not** be allowed as an intermediate for this model because:
- The source POWL contains non-block-structured behavior (loop with partial order), which will cause the process-tree conversion to fail.
- Even if it succeeds for simpler models, process trees cannot represent all POWL semantics (e.g., true concurrency).

**Avoiding Round-Trip Drift**:
- Store the original POWL model and regenerate derivatives on demand.
- Never edit the BPMN or Petri net directly; always edit the POWL and re-export.
- Use automated validation (e.g., footprint comparison, soundness checks) to detect drift.

# 9. Residual Uncertainty

Even if all tests pass, the following claims **cannot** be established:
1. **Full Behavioral Equivalence**: The bounded trace exploration cannot guarantee that all possible traces (including infinite ones) are preserved due to loop iteration limits.
2. **Concurrency Preservation in BPMN**: While the Petri net preserves true concurrency, the BPMN visualization may still mislead stakeholders into assuming sequential behavior due to layout.
3. **Silent Transition Observability**: The silent transition (`skip_legal`) is unobservable in logs, so its presence cannot be validated empirically (only structurally).
4. **Loop Iteration Count**: The minimum iteration count (1) is enforced structurally, but the converted model may allow more iterations than intended without explicit bounds.
5. **Gateway Semantics in BPMN**: The BPMN standard allows tool-specific interpretations of gateways, so the rendered model may behave differently in other BPMN engines.
