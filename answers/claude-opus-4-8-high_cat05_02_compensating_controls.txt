## 1. Control-Objective Decomposition

FEP-1 ("preparer ≠ releaser") is a proxy for a set of underlying control objectives. Separating the person who *initiates* a transfer from the person who *authorizes* it is meant to interrupt several distinct causal chains. Below I decompose it into objectives/threat scenarios and map how each compensating control (AV-2, MG-4, RA-7, ED-1) relates to it.

**O1 — Prevent a single actor from unilaterally initiating AND authorizing an erroneous payment (honest-error containment).**
- AV-2: PREVENTS the mechanical subset (duplicate invoice, sanctions, PO match, amount-vs-limit, bank-change). Does not cover receipt/commercial reasonableness.
- MG-4: PREVENTS if performed before release/settlement with genuine review of invoice, bank details, receipt; else weak.
- RA-7: DETECTS after the fact; becomes partly CORRECTIVE only inside the recall window.
- ED-1: Does not itself prevent/detect; it is a *permission gate* that requires the others to be in place before it will tolerate same-user handling.

**O2 — Prevent unilateral fraud by one insider (deliberate diversion of funds).**
- AV-2: PARTIAL prevent (catches naïve fraud like duplicate invoices, sanctioned payees, recent bank changes) but FAILS against a fraud designed to pass mechanical checks (aged vendor, no recent bank change, plausible amount).
- MG-4: PREVENTS if the manager is independent and actually inspects; a rubber stamp or a manager who is the fraudster's supervisor FAILS.
- RA-7: DETECTS; CORRECTIVE only if within recall window.
- ED-1: Gate only; conditions (aged vendor, no bank change, AV-2 clean, independent MG-4) are designed to shrink the O2 attack surface.

**O3 — Prevent collusion between two (or more) actors.**
- AV-2: FAILS to address (it cannot see relationships or intent).
- MG-4: PARTIAL — a genuinely independent L3+ manager adds a third pair of eyes that collusion must also capture; FAILS if the manager is inside the conflict (e.g., supervisor of the actor, or part of the colluding cell).
- RA-7: DETECTS collusion patterns only weakly and late (needs pattern analytics, not single-case audit).
- ED-1: Does not address collusion directly; independence conditions help only marginally.
- Note: FEP-1's distinct-user requirement itself does NOT stop collusion; two distinct colluding users satisfy FEP-1 nominally while defeating O3. This is why AP-204/AP-209 matter.

**O4 — Prevent authorization of payments for goods/services not received or not commercially reasonable (substance, not form).**
- AV-2: FAILS by design (explicitly does not establish receipt or commercial reasonableness).
- MG-4: PREVENTS only if the manager reviews supporting receipt/service report before release; otherwise FAILS.
- RA-7: DETECTS (e.g., fabricated receipt in AP-204 was found by audit); CORRECTIVE only if timely.
- ED-1: Does not address; assumes MG-4 carries this load.

**O5 — Prevent payment to a compromised or spoofed payee / bank account (payment-redirection / BEC).**
- AV-2: PARTIAL prevent — flags bank-account changes in the last 7 days and bank-ownership checks, but "does not establish who controlled a compromised account."
- MG-4: PARTIAL — can catch a suspicious bank change if the manager actually validates bank details.
- RA-7: DETECTS; CORRECTIVE only within 24h recall.
- ED-1: Conditions 4 (no bank change in 7 days) and 5 (AV-2 clean, no override) are specifically anti-redirection guards.

**O6 — Preserve recoverability / limit unrecoverable exposure (timing objective).**
- AV-2/MG-4: indirectly help by stopping bad payments *before* settlement.
- RA-7: this is its core objective — 100% audit within one business day so defects can be caught while recall (≤24h) is still feasible.
- ED-1: condition 7 (audit within one business day) encodes this.

**O7 — Preserve independent, tamper-evident evidence and accountability (attribution).**
- AV-2: produces a check record but only for covered items; an override credential can mask the true actor (AP-202).
- MG-4: adds an independent attestation *if* independence holds.
- RA-7: is the evidence-gathering control.
- ED-1: condition on emergency *token active before Prepare* is an attribution/pre-authorization artifact.

Summary: no single compensating control substitutes for FEP-1. AV-2 covers mechanical prevention (O1/O2 partial, O5 partial); MG-4 is the main human substitute for the second pair of eyes (O1–O5) but only when independent and substantive; RA-7 provides O6/O7 and limited correction; ED-1 is a conditional permission that only reduces risk if all of O1–O7's guards are actually satisfied.

## 2. Equivalence and Sufficiency Test

A compensating package is judged on seven dimensions. For each I state what "full equivalence" to true four-eyes requires.

1. **Timing** — Does the compensating human review occur *before the irrevocable event* (release, and critically before bank settlement)? Full: independent review before settlement, ideally before release. Partial: before settlement but after release. Ineffective for prevention: only after settlement (then it is detective at best).
2. **Independence** — Is the second/third actor free of hierarchical, financial, or relational conflict, and L3+ for MG-4? Full: strict independence. Fails: releaser = preparer with a supervisor who owns the override (AP-202), or a rubber-stamp.
3. **Coverage** — Do the controls address the *specific* threats live in this case (receipt substance, bank change, collusion), not just mechanical items? A clean AV-2 pass covers only what AV-2 checks; it never covers receipt/collusion.
4. **Overrideability** — Can a warning be overridden, and by whom, with what independence? An override by the same operator using a supervisor's credential (AP-202) collapses both independence and coverage.
5. **Recoverability** — If a defect is found, can funds still be stopped/recalled? Before settlement: high. Within ~24h of settlement: uncertain. After: effectively unrecoverable.
6. **Evidence quality** — Is there reliable, independent, tamper-evident evidence for the covered checks *at the time of release* (signed checklist, AV-2 log, reviewed receipt)? An unavailable AV-2 with an unsigned manual checklist (AP-208) is near-zero evidence.
7. **Collusion resistance** — Does the package require corruption of ≥2 genuinely independent parties to fail? A distinct preparer/releaser who share a workstation and always pair (AP-204/AP-209) provides low collusion resistance despite nominal conformance.

**Grading rubric:**
- **Fully equivalent** — All seven satisfied: independent substantive review before settlement, full relevant coverage, no unresolved override, funds still recoverable at decision time, strong evidence, genuine collusion resistance. In practice reachable only when MG-4 is independent + substantive + pre-settlement AND AV-2 covers the live threats.
- **Partially equivalent** — Independent human review exists and is substantive but one dimension is degraded (e.g., timing is post-release-pre-settlement, or coverage misses one live threat that another control catches later).
- **Merely mitigating** — Some risk reduction but a core dimension fails (independence broken, coverage misses the live threat, evidence weak). Loss probability is reduced but the FEP-1 objective is not actually met.
- **Ineffective** — The package does not break the dominant causal chain (AV-2 unavailable, review after settlement, override by conflicted party).

**Why "same expected loss" is not the only standard.** Expected loss (probability × magnitude) is one lens, but internal control also cares about: (a) *tail risk and recoverability* — a package that yields the same mean but a fat unrecoverable tail (AP-208's EUR 900k) is worse; (b) *evidentiary/attribution value* — controls must produce proof of who authorized what, independent of outcome; (c) *governance legitimacy* — an override by a conflicted supervisor is unacceptable even if that particular payment was fine, because it destroys the control's deterrent and audit function; (d) *deterrence and future exposure* — tolerating same-user handling as convenience (AP-201) raises systemic probability of future misuse even when this instance is harmless. So two packages with identical expected loss can differ sharply in acceptability.

## 4. Preventive–Detective–Corrective Comparison

| Control | Preventive? | Detective? | Corrective? | Notes / dependencies |
|---|---|---|---|---|
| AV-2 (automated validation) | Yes — for its covered mechanical checks; can block or warn | Weak — logs anomalies it checks | No | Preventive strength = 0 for uncovered threats (receipt, collusion, commercial reasonableness). An override or an outage nullifies it. |
| MG-4 before Release | Yes (strongest) | Incidental | No | Full four-eyes substitute only if independent + substantive. |
| MG-4 after Release but before Bank_Settlement | **Hybrid (preventive-capable)** | Yes | Yes (can still stop settlement) | See semantics below. |
| MG-4 after Bank_Settlement | No | Yes | Only if within ~24h recall | Post-settlement it degrades to detective/limited-corrective (AP-208). |
| RA-7 (retrospective audit) | No | Yes (primary) | Partly — only if defect can still be stopped/recalled/recovered | Corrective capacity is a function of timing vs. the 24h recall window. |
| ED-1 (emergency permission) | Meta-gate: enables same-user only if preventive/detective/corrective conditions hold | — | — | Not a control that acts on a payment; it conditions when the others must be present. |

**Semantics of "manager action after Release_Payment but before Bank_Settlement."** I classify this as **hybrid, weighted preventive**. Rationale: internal control treats the *irrevocable* event as bank settlement, not the release click. As long as settlement has not occurred, an independent manager who reviews and could halt the transfer is still *preventing* the loss event (the money has not irrevocably left). It is detective with respect to the release act (it looks back at what was released) but preventive with respect to the loss. Therefore I score pre-settlement MG-4 as substantively preventive (AP-201 m04, AP-207 m15, AP-206 m11), while MG-4 that occurs only after settlement (AP-208 m21) is detective/limited-corrective. The decisive line is settlement, because that is where recoverability drops sharply.

## 5. Counterfactual and Residual-Risk Analysis

For each case: most plausible loss mechanism → control that breaks the chain → what remains exposed → effect of a truly independent second releaser. Probabilities are qualitative (low/medium/high); any number is illustrative only.

**AP-202 (realized loss).** Mechanism: insider-facilitated payment redirection to a related-party account (bank changed 2h prior). Chain-breakers that *should* have fired: AV-2 warning (fired, then overridden) and an independent MG-4 (defeated because the override credential belonged to u23's own rating supervisor m09). What remains exposed: everything — funds gone, recall window passed. Under a truly independent second releaser: the bank-change warning would have required a genuinely independent authorizer; a non-conflicted releaser would likely have refused a 2-hour-old bank change on a new 480k payment. Residual risk would drop from high to low-medium. This is the case where independence, not distinct-user form, is decisive.

**AP-204 (distinct users, fabricated receipt).** Mechanism: collusive or negligent approval of a payment with no genuine receipt (fabricated service receipt), EUR 220k. Chain-breaker: none preventive fired (AV-2 doesn't check receipt substance; the "second" user u13 is part of the always-together pair on a shared workstation). RA-7 detected it, but 4 days later — recovery uncertain. What remains exposed: recoverability and the systemic 37-co-approval pattern. Under a truly independent second releaser (not u12's constant partner, different workstation/session): probability of catching a fabricated receipt rises substantially; residual risk medium→low. This shows FEP-1 form ≠ objective O3/O4.

**AP-206 (late emergency token).** Mechanism: same-user emergency payment where the permission precondition (token before Prepare) may not have held; risk is that the "emergency" is manufactured to justify same-user handling. Chain-breaker: independent MG-4 (m11) reviewed before release and settlement, AV-2 clean, aged vendor, no bank change. What remains exposed: only the governance/attribution question of the token timing. Under an independent second releaser: little change — substance was already strong; this is why I lean MET despite the ED-1 technicality. Residual risk low.

**AP-208 (AV-2 down, 900k).** Mechanism: payment redirection / unverified payee on a young vendor with a recent (3-day) bank change, released with the primary preventive control offline and only an unsigned manual checklist. Chain-breaker: none reliable — AV-2 unavailable, MG-4 after settlement, audit 4 days later. What remains exposed: full EUR 900k, unrecoverable, with no bank-ownership evidence at release time. Under a truly independent second releaser: an independent human, knowing AV-2 was down on a young-vendor + recent-bank-change 900k payment, would very likely have deferred until validation was restored. Residual risk high→low-medium. Acceptability here is driven by control state and tail exposure, not the (lucky) legitimate outcome.

**AP-201 (convenience same-user, low value).** Mechanism: unnecessary same-user handling normalizes control bypass; direct loss risk on this item is minimal (aged vendor, EUR 1,800, no bank change). Chain-breaker: AV-2 mechanical pass + independent m04 before settlement. What remains exposed: systemic/deterrence risk (audit started after the 24h recall window). Under an independent second releaser: essentially no change to this payment's outcome; the value is deterrence and precedent. Residual risk low but non-zero systemically.

**AP-205 (prevented).** Mechanism: duplicate-invoice double payment. Chain-breaker: AV-2 block — worked. Exposed: nothing; no funds left. Independent releaser: irrelevant; preventive control already stopped completion.

## 6. Evidence and Monitoring Recommendations

**Evidence to collect per payment (standing dataset):**
- Actor identities for Prepare/Release/Approve, plus authentication session and workstation/IP for each, to distinguish nominal distinct-user from effectively-single-context handling (AP-204/AP-209).
- Emergency token issuance timestamp and issuer, compared to Prepare_Payment time (AP-206).
- AV-2 result AND operational state (pass/warn/block/unavailable), the specific checks covered, and any override: who overrode, whose credential, and their relationship to the actor (AP-202).
- Manager approval timestamp relative to both Release and Bank_Settlement; whether invoice, bank details, and receipt/service report were actually opened/reviewed (system access logs), not just an approve click.
- Independent bank-ownership verification artifact captured at release time, especially when a bank change occurred in the prior 7 days.
- Audit start time vs. release/settlement, to compute audit-within-recall-window.

**Monitoring rules / metrics (with alert thresholds; alert ≠ proof):**
- **Same-user (FEP-1) rate** overall and split by (a) justified emergency (ED-1 fully met) vs. (b) convenience. Alert when convenience same-user > 0, or emergency same-user rate trends up.
- **Override rate**, and specifically overrides where the credential owner is in a reporting relationship with the operator (hard alert — AP-202 signature).
- **Late manager approval**: approvals after settlement (alert) vs. before settlement (informational).
- **Audit-before-recall-window**: flag any case whose audit starts >24h after settlement, weighted by amount and recoverability.
- **Repeated resource pairs**: preparer/releaser pairs whose co-occurrence exceeds an expected baseline (e.g., u12/u13's 37/30 days), and pairs sharing a workstation/session.
- **Shared workstation / session reuse** between preparer and releaser on the same case.
- **Bank-change proximity**: releases where payee bank changed within 7 days, escalating for new/young vendors and large amounts (AP-202, AP-208).
- **Control outages**: any release while AV-2 was unavailable or a manual checklist was unsigned (AP-208) — hard alert.

**Alert vs. proof.** Every rule above produces an *investigation trigger*, not a misconduct finding. A repeated u12/u13 pairing may be a legitimate dedicated two-person cell (org-design docs missing); a late token may be a logging delay; an override may be a documented, independent decision. Alerts prioritize review and evidence-gathering; a finding of misconduct requires corroborating substantive evidence (intent, relationship, fabricated documents, unresolved conflict). Conversely, a "clean" case with strong outcomes (AP-208) can still be a control failure. The monitoring system should therefore report control-state conformance separately from outcome.

# 6. Preliminary evidence flags (heuristics, NOT verdicts).
# repeated preparer/releaser pairs across cases:
pair = prep_rel.dropna().apply(lambda r: (r["prepare"], r["release"]), axis=1)
pair_counts = pair.value_counts()
repeated_pairs = {k: int(v) for k, v in pair_counts.items() if v > 1}

def flags(row):
    f = []
    c = row["case"]
    same_user = c in nominal_violations
    if same_user:
        f.append("NOMINAL_FOUR_EYES_VIOLATION")
    # emergency (ED-1) eligibility hints
    if row["emergency_token"]:
        if row["token_before_prepare"] is False:
            f.append("ED1_TOKEN_NOT_BEFORE_PREPARE")
        if row["amount_eur"] >= 100000:
            f.append("ED1_AMOUNT_OVER_LIMIT")
        if row["vendor_days"] < 180:
            f.append("ED1_VENDOR_TOO_NEW")
        if row["bank_change_prev7d"]:
            f.append("ED1_RECENT_BANK_CHANGE")
        if row["av2"] != "pass":
            f.append("ED1_AV2_NOT_CLEAN")
    elif same_user:
        f.append("SAME_USER_WITHOUT_EMERGENCY_TOKEN")
    # AV coverage / state
    if row["av2"] == "unavailable":
        f.append("AV2_UNAVAILABLE")
    if row["av2"] == "warn_override":
        f.append("AV2_WARNING_OVERRIDDEN")
    if row["av2"] == "block":
        f.append("AV2_BLOCKED_COMPLETION")
    # manager timing
    if row["manager_indep"] is False:
        f.append("MANAGER_NOT_INDEPENDENT")
    if row["manager_timing"] == "post_settlement":
        f.append("MANAGER_AFTER_SETTLEMENT")
    if row["manager_timing"] == "post_recall":
        f.append("MANAGER_AFTER_RECALL_WINDOW")
    if row["manager_timing"] == "none_pre":
        f.append("NO_MANAGER_BEFORE_RELEASE")
    # audit timing
    if row["audit_within_1bd"] is False:
        f.append("AUDIT_OUTSIDE_ONE_BUSINESS_DAY")
    # bank change proximity
    if row["bank_change_prev7d"]:
        f.append("BANK_CHANGE_WITHIN_7D")
    # repeated pair
    pr = prep_rel.loc[c] if c in prep_rel.index else None
    if pr is not None and (pr["prepare"], pr["release"]) in repeated_pairs:
        f.append("REPEATED_PREP_RELEASE_PAIR")
    return ", ".join(f) if f else "no_flags"

facts["evidence_flags"] = facts.apply(flags, axis=1)

# 7. Output — clearly labeled as EVIDENCE, not a compliance verdict.
print("=" * 70)
print("PRELIMINARY EVIDENCE FLAGS — INPUT TO HUMAN JUDGMENT, NOT A VERDICT")
print("A flag is an investigation trigger, not proof of misconduct; a case")
print("with no flags is not automatically compliant, and a flagged case is")
print("not automatically noncompliant.")

**PM4Py behavior I cannot guarantee across versions.** The exact semantics of `pm4py.filter_four_eyes_principle` have varied: depending on the version it may return the *violating* subset or the *conforming* subset, it may raise if the log is a DataFrame rather than an EventLog object, and the resource attribute it inspects (`org:resource` vs. a role key) can differ. The keyword names of `pm4py.format_dataframe` have also changed historically. For these reasons the code (a) wraps the pm4py call in a defensive `try/except`, (b) always computes an independent manual ground truth for the nominal FEP-1 violations, and (c) treats attempted-but-blocked releases (AP-205) separately, since a four-eyes filter keyed only on completed Release_Payment activities would not flag a case that never released. All computed outputs are explicitly labeled as evidence for judgment, not the final compliance verdict.
