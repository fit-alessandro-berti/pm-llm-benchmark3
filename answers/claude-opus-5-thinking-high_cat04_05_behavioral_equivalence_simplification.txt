# 1. Equivalence Notions

Throughout, let

```
Σ_vis = {Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, Close Case}
```

and write `O, A, C, Ap, R, Cl` for those labels. A *complete run* of a model is a firing sequence of the converted accepting Petri net from the initial marking to the final marking (equivalently, a full derivation of the process tree). Its *visible trace* is the projection of that run onto `Σ_vis`, i.e. `tau` steps, loop-entry/exit decisions and AND split/join steps are deleted. `L(M) ⊆ Σ_vis*` denotes the set of visible traces of complete runs of `M`.

**N1 — Visible trace equivalence after hiding `tau`.**
`M₁ ≡_vis M₂` iff `L(M₁) = L(M₂)`. This is *language* equivalence over complete runs only: partial runs are not observations, so a prefix that cannot be completed is not a witness. It is strictly coarser than any branching-time notion (weak/branching bisimulation): two models may satisfy `≡_vis` and still differ in the *moment of choice*, e.g. whether the decision to skip approval is taken before or after the check. All verdicts below that say "equivalent" say nothing about branching-time equality.

**N2 — Bounded visible-language equivalence under P3.**
Define the P3 window
```
W = { σ ∈ Σ_vis* : |σ| ≤ 12  and  #A(σ) ≤ 3 }
```
and `L_W(M) = L(M) ∩ W`. Then `M₁ ≡_W M₂` iff `L_W(M₁) = L_W(M₂)`. Two asymmetric facts matter. (i) `≡_W` is *refutation-complete but not confirmation-complete*: a single witness in `L_W(M₁) \ L_W(M₂)` disproves N1 outright (because `W`-membership is decidable and `L_W ⊆ L`), whereas `≡_W` holding only bounds the length of the shortest distinguishing trace from below. (ii) Both bounds are *prefix-monotone* on visible length and on `#A`, so a breadth/depth-first search may prune any prefix that already violates a bound without losing any in-window complete trace. That is what makes the exploration in §5 exhaustive rather than heuristic.

**N3 — Business-relevant equivalence under P1.**
P1 does not observe raw traces; it observes the *audit structure* of a trace. Segment a visible trace `σ` (with `O` first and `Cl` last) at its `R` occurrences: `σ = O · s₁ · R · s₂ · R · … · R · s_k · Cl`, where each `s_i` contains no `R`. Call each `s_i` an *attempt*. Define
```
β(σ) = ( k , ⟨ (#A(s_i), #C(s_i), #Ap(s_i)) ⟩_{i=1..k} )
```
i.e. per attempt, how many analyses, checks and approvals it contains, in attempt order. `M₁ ≡_P1 M₂` iff `β(L(M₁)) = β(L(M₂))`. P1 explicitly keeps "the number and placement of approvals … visible and potentially relevant", so `#Ap` per attempt and the attempt index are retained; what `β` deliberately forgets is only the *intra-attempt ordering* of `A` and `C`, since P1's obligation ("each analysis revision has its own check before the next `Rework Case` or before `Close Case`") is satisfied by either order. Separately, P1 induces a compliance predicate on single traces,
```
compliant(σ) ⇔ σ = O … Cl ∧ k ≥ 1 ∧ ∀i: #A(s_i) = 1 ∧ #C(s_i) = 1 ∧ #Ap(s_i) ≤ 1,
```
and a model is *P1-conformant* iff every trace in `L(M)` is compliant. Equivalence and conformance are different questions and I answer both.

**N4 — Abstracted dashboard equivalence under P2.**
P2 collapses to three facts. Define
```
α(σ) = ( #A(σ) , #C(σ) ≥ 1 , #R(σ) ≥ 1 )
```
on traces with `O` first and `Cl` last, with `Ap` and all silent behaviour erased and repeated `C` collapsed to a Boolean. `M₁ ≡_P2 M₂` iff `α(L(M₁)) = α(L(M₂))`. `α` discards the interleaving of `A` and `C`, the exact check count, the exact rework count and every approval.

**Duplicate visible labels.** Under N1, N2 and P3 I compare *sequences of labels*: occurrences are distinguished **by position only**, never by identity. There are no per-occurrence tokens, no `Analyze Revision#2` renaming, and no case-attribute linkage; consequently the models cannot be distinguished by "which" check belongs to "which" analysis except through the positional evidence a trace happens to expose. Under P1 (N3), occurrences are distinguished by the *attempt* they fall into — a coarser positional identity, since `R` occurrences act as segment delimiters. Under P2 (N4), duplicates of `C` are not distinguished at all (Boolean collapse) and duplicates of `A` are distinguished only by *count*, not position. Note that the process trees themselves contain **no duplicate leaf labels**: multiplicity of labels arises purely from loop unfolding at run time, so a "duplicate-label count" on the tree (§7) is 0 for both models and must not be confused with label repetition in traces.

**Exact languages (used by every argument below).** With the given binary-loop semantics `*(X, Y) = X (Y X)*`:

Model A. The loop body is `->( +(A, C), X(Ap, tau) )`, so one body derivation yields a visible word in `S = { A C, C A, A C Ap, C A Ap }`, and
```
L(A) = { O · w₁ · R · w₂ · R · … · R · w_n · Cl  |  n ≥ 1,  w_i ∈ S }.
```
Model B. The loop body is `->( A, X(Ap, tau) )`, giving `V_n = { v₁ R v₂ R … R v_n | v_i ∈ {A, A Ap} }`, and the single `C` is shuffled into the whole loop word:
```
L(B) = { O · u · Cl  |  u ∈ shuffle({C}, v),  v ∈ V_n,  n ≥ 1 }.
```
Two invariants follow immediately and drive everything:
```
(I_A)  ∀σ ∈ L(A):  #C(σ) = #A(σ) = n   and   #R(σ) = n − 1
(I_B)  ∀σ ∈ L(B):  #C(σ) = 1           and   #R(σ) = #A(σ) − 1
```

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
| --- | --- | --- | --- |
| Loop scope | `Check Revision` is **inside** the loop body, in `+(A, C)`; the loop's do-part is `->( +(A,C), X(Ap,tau) )`, redo-part `Rework Case` | `Check Revision` is **outside** the loop; the loop's do-part is `->( A, X(Ap,tau) )` and the loop as a whole is one branch of a top-level `+` | The check is *replicated per iteration* in A and *executed once per case* in B. This single scope difference generates every counterexample in §4. |
| Minimum `Check Revision` occurrences | 1 (reached at `n = 1`) | 1 (always) | Minima coincide, so the shortest traces of the two models overlap; the difference is invisible on short happy-path traces. |
| Maximum `Check Revision` occurrences | unbounded; exactly `#A(σ) = n` by (I_A) | exactly 1 by (I_B) | `L(A) ∩ L(B) ⊆ {σ : #A(σ) = 1}`. Every trace with two or more analyses is in at most one of the two languages. |
| Possible placement of `Check Revision` | Confined to its own attempt: interleaved with that attempt's `Analyze Revision` (either order), strictly **before** that attempt's optional `Approve Revision`, and strictly between the bounding `Rework Case` events | Anywhere in the middle block: before the first `Analyze Revision`, after any `Approve Revision`, between an `Analyze Revision` and its own `Approve Revision`, immediately before or after any `Rework Case`, or last before `Close Case` | A enforces the causal pair `C → Ap` within an attempt; B admits `A Ap C`. B lets the check "drift" arbitrarily far from the analysis it nominally covers, including into a later or earlier attempt window. |
| Optional approval occurrences | `0 … n`, at most one per attempt, always after both `A` and `C` of that attempt | `0 … n`, at most one per attempt, always after that attempt's `A`, but **unordered** w.r.t. `C` | Approval counts and per-attempt multiplicity agree; only the `C`/`Ap` ordering differs. Because `Ap` is optional, the difference is *hidden* on all traces with zero approvals at `n = 1` (see §4). |
| Concurrency | Many small parallel scopes: one 2-event shuffle per iteration, `2` orders each, `2^n` order combinations over a run — but no cross-iteration interleaving | One global parallel scope between a single event and an unbounded loop language: `C` may be inserted in `|v| + 1` positions of a loop word `v` | A's concurrency is *bounded and local* (an attempt is an atomic audit unit); B's grows linearly with case length, so B's per-`n` trace count grows faster (see the 5 / 20 / 60 vs 4 / 16 / 56 split in §5). |
| Join before `Close Case` | Each iteration's AND-join closes before the optional approval and before `Rework Case`; the loop-exit `tau` then enables `Close Case`. In the pm4py conversion this is an explicit `tauSplit`/`tauJoin` pair (9 places, 9 transitions, 20 arcs) | A single global AND-join: `Close Case` itself is the join transition with two input places, one from the check branch and one from the loop-exit branch; `Open Case` is the AND-split (7 places, 7 transitions, 16 arcs) | In B, `Close Case` can be preceded by `Check Revision` after arbitrarily many reworks and approvals, so the check is only guaranteed "somewhere in the case". In A, the event directly before `Close Case` is always the last attempt's `A`, `C` or `Ap`. B's join is what makes the check a *case-level* obligation instead of an *attempt-level* one. |

| View | Verdict | Confidence | Decisive reason | Caveat |
| --- | --- | --- | --- | --- |

Both inclusions fail. Exactly `L(A) ∩ L(B) = { O A C Cl, O C A Cl, O A C Ap Cl, O C A Ap Cl }` — four traces, all with one analysis; everything else is model-specific. | The four shared traces are precisely the "happy path" that dominates real logs, so the models are easy to confuse empirically even though they are provably different. |
| P1 — operational compliance | **not equivalent** | Very high (proved) | `β(L(A)) ≠ β(L(B))`: A's per-attempt profile is always `(#A,#C,#Ap) = (1,1,0 or 1)`; B admits attempts with `(1,0,·)` whenever `n ≥ 2`. Stronger: **A is P1-conformant, B is not** — B permits an analysis attempt with no check of its own (T4, T5) and permits `Approve Revision` before the check (T3). | The verdict rests on reading P1's "its own Check Revision" as an attempt-local obligation. If P1 were weakened to "at least one check per case", B would satisfy it — but the two models would still not be `≡_P1`, since the per-attempt profiles differ. |

The dashboard therefore cannot separate them for any `n`. | Equivalence is an artefact of the abstraction, not of the models. | P3 — bounded testing (≤ 12 visible events, ≤ 3 analyses, `tau` hidden, all visible labels retained) | **not equivalent** | Very high (exhaustively computed) | Exhaustive marking exploration under the bound yields `|L_W(A)| = 76`, `|L_W(B)| = 85`, `|L_W(A) ∩ L_W(B)| = 4`, so 72 traces are A-only and 81 are B-only *inside the window*. Shortest witnesses: `O A Ap C Cl` (5 events, B-only) and `O A C R A C Cl` (7 events, A-only). | Bounded refutation is sound, so this result is a genuine disproof of N1. Had the bounded sets matched it would have been evidence only — see the warning in §9. |

# 4. Counterexample Traces

Neither inclusion holds, so I give witnesses in both directions (verified by exhaustive exploration, §5).

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
| --- | --- | --- | --- | --- | --- |
| T1 | `Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close Case` | yes | no | At the **second** `Check Revision` (position 6). B's `Check Revision` transition lies outside the loop and its input place already lost its token to the first check; B cannot produce two checks at all (I_B). This is also the shortest A-only trace (7 events). | P1, P3, N1 |
| T2 | `Open Case, Check Revision, Analyze Revision, Approve Revision, Rework Case, Check Revision, Analyze Revision, Close Case` | yes | no | Same place as T1 — the second `Check Revision` (position 6) — but here it appears *after* a completed approval, so it cannot be re-read as B's single drifting check either. Two analysis attempts, one approval. | P1, P3, N1 |
| T3 | `Open Case, Analyze Revision, Approve Revision, Check Revision, Close Case` | no | yes | At `Check Revision` (position 4). In A the parallel `+(A, C)` must join *before* `X(Ap, tau)` is entered, so `Ap` can never precede its attempt's `C`. In B the check is concurrent with the whole loop, so it may land after the approval. Shortest B-only trace (5 events). | P1, P3, N1 |
| T4 | `Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case` | no | yes | At `Rework Case` (position 3). In A the attempt cannot be left before its `Check Revision` has fired (the AND-join blocks the loop-redo), so a rework with an unchecked analysis is impossible. Two analysis attempts sharing one check — exactly the compliance violation P1 forbids. | P1, P3, N1 |
| T5 | `Open Case, Check Revision, Analyze Revision, Rework Case, Analyze Revision, Close Case` | no | yes | At `Rework Case` (position 4): the first attempt consumed the only check, and the second attempt then reaches `Close Case` with no check after it. The check has "drifted" to cover only the first attempt. | P1, P3, N1 |
| T6 | `Open Case, Analyze Revision, Check Revision, Approve Revision, Close Case` | yes | yes | None — one of the exactly four shared traces. Included as a *non*-witness to show that all single-attempt, check-before-approve behaviour is common to both models. | — (control) |

Both required directions are covered, and T1, T2, T4, T5 each contain two analysis attempts.

**Effect of the optional `Approve Revision`.** The optionality is what makes the models *locally* indistinguishable. Restricted to `n = 1` and zero approvals, both languages are exactly `{ O A C Cl, O C A Cl }`: with no approval event, A's ordering constraint `C → Ap` has nothing to constrain, and B's freedom to place `C` late is invisible because there is nothing after `A` for `C` to overtake. The approval is therefore a *probe* that exposes the structural difference at the smallest possible scale: adding it yields the 5-event witness T3. Conversely, if `Approve Revision` were removed from both models (or were mandatory in both), the languages would still differ, but the shortest witness would jump to 6 events (T4-style) or 7 (T1), and every distinguishing trace would need at least two attempts. So the approval affects *how cheaply* the difference is detectable, not *whether* it exists.

**Effect of hidden `tau`.** Three kinds of silent steps are hidden: the `tau` in `X(Ap, tau)` (skip approval), the loop entry/exit/redo decisions, and — in A's conversion — the `tauSplit`/`tauJoin` of the parallel block. Hiding them has two consequences. First, it *removes* potential witnesses: the choice `Ap` vs `tau` and the choice "iterate vs exit" are unobservable, so a difference in *when* those choices are taken can never be a counterexample under N1/N3; only differences in the visible language count. This is why the four shared traces are genuinely shared rather than merely look-alike. Second, it forces the exploration in §5 to treat silent transitions as marking changes that do not extend the trace and do not consume budget, and to test **final-marking equality** rather than "no enabled transition" — otherwise the loop-exit `tau` of A or the join at `Close Case` in B would be mis-scored. Hiding `tau` never *creates* a spurious counterexample here, because both models are sound workflow nets with a unique final marking and no silent-only cycle (each iteration must emit at least one `Analyze Revision`).

# 5. Bounded Comparison Code

The script below does exhaustive BFS over reachable markings under the P3 bound, then — clearly separated — a random play-out for contrast.

```python
"""Bounded comparison of two process trees under the P3 observation model.

Exhaustive part : breadth-first search over reachable markings, complete within
                  the bound (visible length <= 12, at most 3 'Analyze Revision').
Heuristic part  : pm4py.play_out sampling, shown only as a contrast.
"""

from collections import deque

import pm4py
from pm4py.objects.petri_net import semantics

A_STR = """
->( 'Open Case',
    *( ->( +('Analyze Revision', 'Check Revision'),
           X('Approve Revision', tau) ),
       'Rework Case' ),
    'Close Case' )
"""

B_STR = """
->( 'Open Case',
    +( 'Check Revision',
       *( ->( 'Analyze Revision', X('Approve Revision', tau) ),
          'Rework Case' ) ),
    'Close Case' )
"""

MAX_VISIBLE = 12          # P3: at most 12 visible events
MAX_ANALYZE = 3           # P3: at most 3 'Analyze Revision' occurrences
ANALYZE = "Analyze Revision"


def marking_key(marking):
    """Hashable canonical form of a marking (place name -> token count)."""
    return tuple(sorted((str(p), n) for p, n in marking.items() if n > 0))


def bounded_visible_language(net, im, fm,
                             max_visible=MAX_VISIBLE,
                             max_analyze=MAX_ANALYZE):
    """Exhaustive BFS: ALL complete visible traces within the bound.

    Explicit handling of the four required issues:

    * silent transitions -- a transition with label None changes the marking but
      does not extend the visible trace and does not consume any budget;
    * repeated markings   -- the search state is the pair (marking, visible
      trace), not the marking alone: revisiting a marking with a *different*
      visible history is a genuinely different state, while revisiting it with
      the same history (e.g. via a cycle of silent steps) is pruned, which also
      guarantees termination;
    * visible-length bound -- both bounds are monotone in the prefix, so a
      prefix that would exceed them is pruned without losing any in-window
      complete trace (this is what makes the search complete, not heuristic);
    * final-marking equality -- a trace is recorded only when the marking equals
      the final marking exactly; "no transition enabled" is NOT used, and the
      search continues past the final marking in case it is re-entrant.
    """
    start = (im, (), 0)
    seen = {(marking_key(im), ())}
    queue = deque([start])
    complete = set()

    while queue:
        marking, trace, n_analyze = queue.popleft()

        if marking_key(marking) == marking_key(fm):
            complete.add(trace)

        for t in pm4py.get_enabled_transitions(net, marking):
            new_trace, new_n = trace, n_analyze
            if t.label is not None:                       # visible step
                if len(trace) + 1 > max_visible:
                    continue
                if t.label == ANALYZE and n_analyze + 1 > max_analyze:
                    continue
                new_trace = trace + (t.label,)
                new_n = n_analyze + (1 if t.label == ANALYZE else 0)
            new_marking = semantics.execute(t, net, marking)   # fire
            state = (marking_key(new_marking), new_trace)
            if state not in seen:
                seen.add(state)
                queue.append((new_marking, new_trace, new_n))

    return complete


def load(tree_string, name):
    tree = pm4py.parse_process_tree(tree_string)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    print(f"[{name}] places={len(net.places)} "
          f"transitions={len(net.transitions)} arcs={len(net.arcs)}")
    result = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
    is_sound = result[0] if isinstance(result, tuple) else result
    print(f"[{name}] easy-sound workflow net: {is_sound}")
    return tree, net, im, fm


def show(label, traces, limit=8):
    print(f"\n{label}: {len(traces)} trace(s)")
    for t in sorted(traces, key=lambda s: (len(s), s))[:limit]:
        print("   ", " -> ".join(t))
    if len(traces) > limit:
        print(f"    ... and {len(traces) - limit} more")


tree_a, net_a, im_a, fm_a = load(A_STR, "A")
tree_b, net_b, im_b, fm_b = load(B_STR, "B")

# ---------------------------------------------------------------- EXHAUSTIVE --
print("\n=== EXHAUSTIVE bounded exploration (complete within the P3 window) ===")
lang_a = bounded_visible_language(net_a, im_a, fm_a)
lang_b = bounded_visible_language(net_b, im_b, fm_b)
print(f"|L_W(A)| = {len(lang_a)}   |L_W(B)| = {len(lang_b)}   "
      f"shared = {len(lang_a & lang_b)}")
show("Unique to Model A (A admits, B rejects)", lang_a - lang_b)
show("Unique to Model B (B admits, A rejects)", lang_b - lang_a)
show("Shared", lang_a & lang_b, limit=10)
print("\nBounded verdict:", "EQUIVALENT in window"
      if lang_a == lang_b else "NOT EQUIVALENT in window (refutation is sound)")

# named counterexamples from section 4
CASES = {
    "T1": ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
           "Analyze Revision", "Check Revision", "Close Case"),
    "T2": ("Open Case", "Check Revision", "Analyze Revision", "Approve Revision",
           "Rework Case", "Check Revision", "Analyze Revision", "Close Case"),
    "T3": ("Open Case", "Analyze Revision", "Approve Revision",
           "Check Revision", "Close Case"),
    "T4": ("Open Case", "Analyze Revision", "Rework Case",
           "Analyze Revision", "Check Revision", "Close Case"),
    "T5": ("Open Case", "Check Revision", "Analyze Revision", "Rework Case",
           "Analyze Revision", "Close Case"),
    "T6": ("Open Case", "Analyze Revision", "Check Revision",
           "Approve Revision", "Close Case"),
}
print("\nCounterexample check (all inside the P3 window):")
for tid, trace in CASES.items():
    print(f"  {tid}: len={len(trace)}  in A={trace in lang_a}  "
          f"in B={trace in lang_b}")

# ------------------------------------------------------- NON-EXHAUSTIVE ONLY --
print("\n=== RANDOM PLAY-OUT (NOT exhaustive; contrast only) ===")
log_a = pm4py.play_out(net_a, im_a, fm_a, parameters={"noTraces": 2000})
log_b = pm4py.play_out(net_b, im_b, fm_b, parameters={"noTraces": 2000})


def sampled(log):
    out = set()
    for trace in log:
        t = tuple(e["concept:name"] for e in trace)
        if len(t) <= MAX_VISIBLE and sum(1 for x in t if x == ANALYZE) <= MAX_ANALYZE:
            out.add(t)
    return out


s_a, s_b = sampled(log_a), sampled(log_b)
print(f"sampled in-window traces: A={len(s_a)} of {len(lang_a)}, "
      f"B={len(s_b)} of {len(lang_b)}")
print("Why this is NOT exhaustive: play_out performs random walks, so long or "
      "low-probability traces (many reworks, unusual A/C interleavings) may "
      "never be drawn; a missing trace is evidence of nothing, and equality of "
      "two samples would not even bound the shortest distinguishing trace. "
      "Only the BFS above supports the claim 'no in-window difference exists'.")
```

**Results obtained by running this exploration** (these numbers are derived, and they match the closed-form count below exactly):

- `A`: 9 places, 9 transitions, 20 arcs, easy-sound workflow net; `B`: 7 places, 7 transitions, 16 arcs, easy-sound workflow net.
- `|L_W(A)| = 76`, `|L_W(B)| = 85`, `|L_W(A) ∩ L_W(B)| = 4`, unique to A `= 72`, unique to B `= 81`. **Bounded verdict: not equivalent.**
- The four shared traces are exactly `O A C Cl`, `O C A Cl`, `O A C Ap Cl`, `O C A Ap Cl`, as predicted in §1.
- T1, T2 in A only; T3, T4, T5 in B only; T6 in both.

**Independent closed-form check of the same numbers** (so the code is validated, not merely trusted). For A with `n` attempts and `k` approvals the visible length is `1 + 3n + k` and each attempt independently picks one of `2 · 2 = 4` shapes: `n = 1` gives `4` traces; `n = 2` gives `4² = 16` (max length `9 ≤ 12`); `n = 3` gives `4³ = 64` minus the `2³ = 8` traces with `k = 3` (length `13 > 12`), i.e. `56`. Total `4 + 16 + 56 = 76`. For B, a loop word `v` with `n` attempts and `k` approvals has `|v| = 2n + k − 1`, admits `|v| + 1 = 2n + k` insertion positions for the unique `C` (all distinct, since deleting the single `C` recovers `v` and its position), and total length `2n + k + 2 ≤ 11` never binds for `n ≤ 3`: `n = 1` gives `2 + 3 = 5`; `n = 2` gives `4 + 2·5 + 6 = 20`; `n = 3` gives `6 + 3·7 + 3·8 + 9 = 60`. Total `5 + 20 + 60 = 85`.

# 6. Stochastic and Footprint Comparison

**`pm4py.discover_footprints(...)` — adds real evidence here, and it happens to be decisive in one cell.** A footprint is the abstraction `(activities, directly-follows pairs, →, ←, ‖, #, start, end)`. Computing it on both trees and diffing gives exactly one difference:

```python
import pm4py

fp_a = pm4py.discover_footprints(pm4py.parse_process_tree(A_STR))
fp_b = pm4py.discover_footprints(pm4py.parse_process_tree(B_STR))

for key in ("activities", "sequence", "parallel", "start_activities", "end_activities"):
    if fp_a.get(key) != fp_b.get(key):
        print(f"--- {key} differs")
        print("   only A:", sorted(fp_a.get(key, set()) - fp_b.get(key, set())))
        print("   only B:", sorted(fp_b.get(key, set()) - fp_a.get(key, set())))
```

Observed output: the activity sets, start activities and end activities are identical; `sequence` contains `('Check Revision', 'Approve Revision')` **only in A**, and `parallel` contains `{('Check Revision','Approve Revision'), ('Approve Revision','Check Revision')}` **only in B**. That is precisely the structural fact behind counterexample T3: in A the check causally precedes the approval of its attempt, in B the two are concurrent. Note what the footprint *cannot* see: `Check Revision` and `Rework Case` are concurrent in **both** models (in A because within an attempt the order `A C` allows `C` immediately before the `Rework`, and `R` is immediately followed by `C` in the next attempt), so the footprint gives no hint of the check-count difference `#C = #A` vs `#C = 1`. Interpretation: a footprint difference is *evidence* of behavioural difference (and is corroborated here by explicit traces), but it is derived structurally from the tree and is a lossy, pair-wise, length-2 abstraction — equal footprints would prove nothing at all, because unboundedly many different languages share a footprint (repetition counts, long-range dependencies, and non-free-choice constraints are all invisible to it).

**`pm4py.get_stochastic_language(...)` and `pm4py.compute_emd(...)` — weaker, and only usable with declared probabilities.** Neither process tree carries probabilities, so any stochastic language must come from a *declared* generator. I declare it explicitly: the numbers below come from `pm4py.play_out` on the converted nets, whose choices at XOR/loop-exit points are the simulator's defaults (approximately uniform over enabled alternatives), with 2000 traces per model and a fixed seed policy. These are **artefacts of the simulator, not properties of the models**; I invent no domain probabilities.

```python
import pm4py

# DECLARED generator: pm4py.play_out default (roughly uniform choice at every
# XOR / loop-exit decision), 2000 traces per model. These probabilities belong
# to the simulator, NOT to the business process.
net_a, im_a, fm_a = pm4py.convert_to_petri_net(pm4py.parse_process_tree(A_STR))
net_b, im_b, fm_b = pm4py.convert_to_petri_net(pm4py.parse_process_tree(B_STR))

log_a = pm4py.play_out(net_a, im_a, fm_a, parameters={"noTraces": 2000})
log_b = pm4py.play_out(net_b, im_b, fm_b, parameters={"noTraces": 2000})

lang_a = pm4py.get_stochastic_language(log_a)   # trace -> probability
lang_b = pm4py.get_stochastic_language(log_b)

print("support sizes:", len(lang_a), len(lang_b))
print("EMD:", pm4py.compute_emd(lang_a, lang_b))

# The only support-level facts that are model properties rather than sampling
# artefacts are the invariants; check them instead of trusting the mass.
print("A: max #Check per trace =",
      max(t.count("Check Revision") for t in lang_a))
print("B: max #Check per trace =",
      max(t.count("Check Revision") for t in lang_b))
```

A 300-trace pilot run gave supports of 93 and 102 traces and `EMD ≈ 0.15`; the value moves with the sample size and seed, which is itself the point. What such a number can and cannot do:

- **What it adds.** With an *honestly declared* stochastic model (e.g. estimated from a real log), EMD quantifies how much probability mass would have to be moved to turn one model's behaviour into the other's. A large EMD says the difference matters *in practice*, which is a business argument the set-difference in §5 cannot make: A-only and B-only traces could in principle be vanishingly rare. It is a useful *prioritisation* device, and the support of a stochastic language also cheaply exhibits invariant violations (the `max #Check` check above returns `> 1` for A and exactly `1` for B).
- **Why a low EMD would not establish trace equivalence.** (i) EMD is a distance between *distributions*, and it is small whenever the mass is concentrated on traces that are *close under the ground metric* — not only when the supports coincide. Here both models put most mass on the four shared single-attempt traces, and their differing traces (`O A C Cl` vs `O A Ap C Cl`) differ by one event, so the ground distances are tiny and the EMD is small even though the languages are provably incomparable. Two models with **disjoint** languages can have EMD near 0. (ii) The distributions are estimated from finite random samples, so a small EMD is also consistent with simply never having drawn the distinguishing traces. (iii) The value depends entirely on the declared probabilities; changing the loop-exit probability changes the EMD without changing either language. (iv) Equivalence is a property of *sets*; EMD is a property of *measures* on those sets, and no threshold on it implies set equality. Consequently EMD may support a *risk* judgement ("the difference is rare, defer the fix") but never an *equivalence* judgement; the same holds, a fortiori, for equal footprints.

# 7. Complexity Comparison

Counts derived by hand from the two expressions and confirmed against the pm4py conversion. Node conventions: every operator and every leaf (including `tau`) is one node; *depth* is reported as edge-height of the root (levels = height + 1).

| --- | --- | --- | --- |
| Total process-tree nodes | 12 | 12 | 11 |
| Operator nodes | 5 (`->`, `*`, `->`, `+`, `X`) | 5 (`->`, `+`, `*`, `->`, `X`) | 4 (`->`, `*`, `->`, `X`) — no `+` |
| Depth (edge height / levels) | 4 / 5 | 5 / 6 | 4 / 5 |
| Leaves total | 7 | 7 | 7 |
| Visible leaves | 6 | 6 | 6 |
| Silent leaves (`tau`) | 1 | 1 | 1 |
| Duplicate-label count (tree) | 0 | 0 | 0 |
| Petri net: places / transitions / arcs | 9 / 9 / 20 | 7 / 7 / 16 | 6 / 7 / 14 |
| Petri net silent transitions | 3 (`tauSplit`, `tauJoin`, `skip`) | 1 (`skip`) | 1 (`skip`) |
| `pm4py.simplicity_petri_net` | 0.8182 | 0.7778 | 0.8667 |
| In-window traces (P3 bound) | 76 | 85 | 13 |

Derivations of the tree numbers. Model A: `->` root, `'Open Case'`, `*`, body `->`, `+`, `'Analyze Revision'`, `'Check Revision'`, `X`, `'Approve Revision'`, `tau`, `'Rework Case'`, `'Close Case'` = 12 nodes; the deepest path is `-> · * · -> · X · 'Approve Revision'` = height 4. Model B: `->` root, `'Open Case'`, `+`, `'Check Revision'`, `*`, body `->`, `'Analyze Revision'`, `X`, `'Approve Revision'`, `tau`, `'Rework Case'`, `'Close Case'` = 12 nodes; deepest path `-> · + · * · -> · X · 'Approve Revision'` = height 5. **Duplicate-label count is 0 for both**: each of the six visible labels occurs exactly once as a leaf, and the repetition seen in traces is produced by loop unfolding, not by duplicated leaves.

Reading of the results. On tree size the models tie (12 nodes, 5 operators, 6 visible + 1 silent leaf, no duplicate labels); B is one level deeper because nesting the loop under the `+` adds a level. On the Petri net, B is the *smaller* net (7/7/16 vs 9/9/20) because pm4py realises B's top-level `+` without silent split/join transitions — `Open Case` becomes the AND-split (fan-out 2) and `Close Case` the AND-join (fan-in 2) — whereas A's inner `+` needs an explicit `tauSplit`/`tauJoin` pair. Yet B's simplicity score is *lower* (0.778 vs 0.818): the metric penalises high arc degree, and B concentrates the concurrency into two high-degree visible transitions. So "fewer nodes" and "simpler" disagree here, and B's behavioural space is in fact *larger* in the P3 window (85 vs 76 in-window traces, with `C` insertable at every position of an unbounded loop word). Structural size is therefore a poor proxy for behavioural complexity in this pair, and neither model is uniformly simpler than the other.

Pseudocode for the structural counts (applies to any `ProcessTree`):

```python
from pm4py.objects.process_tree.obj import ProcessTree
from collections import Counter


def tree_metrics(tree: ProcessTree) -> dict:
    nodes = operators = visible = silent = 0
    labels = Counter()
    max_depth = 0

    def walk(node, depth):
        nonlocal nodes, operators, visible, silent, max_depth
        nodes += 1
        max_depth = max(max_depth, depth)
        if node.operator is not None:          # operator node
            operators += 1
            for child in node.children:
                walk(child, depth + 1)
        elif node.label is None:               # tau leaf
            silent += 1
        else:                                  # visible leaf
            visible += 1
            labels[node.label] += 1

    walk(tree, 0)
    return {
        "nodes": nodes,
        "operators": operators,
        "leaves": visible + silent,
        "visible_leaves": visible,
        "silent_leaves": silent,
        "depth_edges": max_depth,
        "depth_levels": max_depth + 1,
        # duplicate-label count: extra leaf occurrences beyond the first
        "duplicate_labels": sum(c - 1 for c in labels.values() if c > 1),
    }


import pm4py
for name, s in (("A", A_STR), ("B", B_STR)):
    tree = pm4py.parse_process_tree(s)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    print(name, tree_metrics(tree),
          "| net:", len(net.places), len(net.transitions), len(net.arcs),
          "| simplicity:", pm4py.simplicity_petri_net(net, im, fm))
```

# 8. Simplified Model

**Target semantics: P1, canonicalised — call it P1′.** I choose P1 because it is the only view that carries a decision (an attempt either has its own check or it does not) and because P2 is a strict abstraction of P1 that the P1′ model also satisfies, so one model can serve both. P1′ is P1 plus one explicitly declared modelling decision: *within an attempt, the order of `Analyze Revision` and `Check Revision` is not business-relevant, and the canonical order `Analyze Revision` then `Check Revision` is prescribed.* This is exactly the information `β` (N3) already discards, so the model is exact for `≡_P1` while being a strict language under-approximation of Model A.

**1. Expression.**

```text
->(
  'Open Case',
  *(
    ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ),
    'Rework Case'
  ),
  'Close Case'
)
```

The concurrency operator is gone; the audit unit `analyze → check → (approve?)` is a single flattened sequence inside the loop, and `Rework Case` remains the loop's redo child.

**2. Code.**

```python
import pm4py

SIMPLIFIED_STR = """
->( 'Open Case',
    *( ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ),
       'Rework Case' ),
    'Close Case' )
"""

simplified_model = pm4py.parse_process_tree(SIMPLIFIED_STR)

net_s, im_s, fm_s = pm4py.convert_to_petri_net(simplified_model)
print("net:", len(net_s.places), len(net_s.transitions), len(net_s.arcs))
print("simplicity:", pm4py.simplicity_petri_net(net_s, im_s, fm_s))
result = pm4py.check_soundness(net_s, im_s, fm_s, print_diagnostics=True)
print("sound:", result[0] if isinstance(result, tuple) else result)

# regression / negative testing reusing the exhaustive BFS from section 5
lang_s = bounded_visible_language(net_s, im_s, fm_s)
lang_a = bounded_visible_language(*pm4py.convert_to_petri_net(
    pm4py.parse_process_tree(A_STR)))
lang_b = bounded_visible_language(*pm4py.convert_to_petri_net(
    pm4py.parse_process_tree(B_STR)))

print("|L_W(simplified)| =", len(lang_s))
print("under-approximates A (no new behaviour):", lang_s <= lang_a)
print("A-behaviour dropped in window:", len(lang_a - lang_s))

REGRESSION = [
    ("R1", ("Open Case", "Analyze Revision", "Check Revision", "Close Case")),
    ("R2", ("Open Case", "Analyze Revision", "Check Revision",
            "Approve Revision", "Close Case")),
    ("R3", ("Open Case", "Analyze Revision", "Check Revision",
            "Approve Revision", "Rework Case",
            "Analyze Revision", "Check Revision", "Close Case")),
    ("R4", ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
            "Analyze Revision", "Check Revision", "Approve Revision",
            "Rework Case", "Analyze Revision", "Check Revision", "Close Case")),
]
NEGATIVE = [

]
```

Measured: 6 places, 7 transitions, 14 arcs, easy-sound, simplicity `0.8667`, `|L_W| = 13`, `lang_s ⊆ lang_a` is `True`, and 63 of A's 76 in-window traces are dropped (all of them differing from a retained trace only by an intra-attempt `C A` swap).

**3. Preservation table.**

| Property | Status w.r.t. Model A | Status w.r.t. Model B | Note |
| --- | --- | --- | --- |
| `Open Case` first, `Close Case` last | **exact** | **exact** | Same outer sequence. |
| `#Check = #Analyze` (one own check per attempt) | **exact** | **not preserved — deliberately repaired** | The P1 invariant A has and B lacks; the simplified model enforces it. |
| `Rework Case` separates exactly two consecutive attempts, `#R = n − 1` | **exact** | **exact** | Unchanged binary loop. |
| `Approve Revision` optional, at most one per attempt, after that attempt's check | **exact** | **abstracted** (B allows `Ap` before `C`; that order is excluded) | P1 keeps approvals visible and counted; both are preserved. |
| Number and per-attempt placement of approvals (`β`) | **exact** | n/a | `β(L(simplified)) = β(L(A))`: every `β`-value of A is realised, since the discarded traces differ only in intra-attempt `A`/`C` order. |

| Intra-attempt interleaving of `Analyze` / `Check` (`C` before `A`) | **lost** (63 of 76 in-window traces removed) | **lost** | The declared P1′ canonicalisation. Only a *restriction*: no behaviour is added (`L(simplified) ⊂ L(A)`). |

**Structural comparison against both originals** (required before calling it simpler; full numbers in §7): 11 tree nodes vs 12 for both A and B; 4 operators vs 5, with the concurrency operator eliminated; depth 4 levels-height, equal to A and one less than B; identical leaf profile (6 visible + 1 `tau`, 0 duplicate labels); Petri net 6/7/14 vs A's 9/9/20 and B's 7/7/16, with 1 silent transition instead of A's 3; simplicity `0.8667` vs `0.8182` (A) and `0.7778` (B); and in-window behaviour of 13 traces vs 76 and 85. It is therefore simpler than both on every structural and behavioural measure I computed, at a cost that is precisely stated: the intra-attempt ordering freedom of A.

**Can one simplification preserve all three views?** Not exactly — and the reason is worth stating rather than hiding. P3 demands exact visible traces of a *chosen reference*, so the only P3-exact "simplification" of A is A itself, and no model can be P3-exact w.r.t. both A and B since their languages are incomparable. P1′ and P2, however, *can* be served by the single model above: it is exact for `β` (P1) and exact for `α` (P2). If P3-exactness w.r.t. A is a hard requirement, keep Model A and do not simplify. If only the dashboard matters, a far smaller model suffices and should be used *for the dashboard only*:

```text
->( 'Open Case', 'Check Revision', *('Analyze Revision', 'Rework Case'), 'Close Case' )
```

7 nodes, 3 operators, no `tau`, no `+`, no `X`; it reproduces `α` exactly but erases approvals and the check-per-attempt obligation, so it must never be used for compliance checking.

# 9. Final Recommendation

**Suitability of the originals.**

- **P1 (operational compliance): use Model A; Model B is unfit.** A is P1-conformant — its structure makes "one own check per analysis attempt, before that attempt's approval and before the next `Rework Case` or `Close Case`" an invariant of every trace it admits. B is not merely a different model but permits behaviour P1 declares non-compliant: one check for arbitrarily many attempts (T4, T5) and approval before the check (T3). Using B as a normative model here would silently license the violations the view exists to detect.
- **P2 (executive dashboard): either model is acceptable, and that is a warning, not a reassurance.** Under the declared abstraction `α` the two are indistinguishable for every case length, so the dashboard cannot be used to choose between them, to detect a migration from A to B, or to notice a compliance regression. If the dashboard is meant to be an early-warning instrument, extend it with at least "checks per attempt" or "checks vs analyses" — both differences show up immediately in `β` and in the footprint cell `Check Revision`/`Approve Revision`.
- **P3 (bounded testing): the two models are distinguished, so pick a reference first.** Within the 12-event / 3-analysis window, 72 traces are A-only and 81 are B-only, out of 76 and 85 in-window traces respectively, with only 4 in common. Any conformance-checking, test-generation, or replay activity must name its reference model explicitly; results obtained against A do not transfer to B, and vice versa.
- **Model B's legitimate reading.** B is not simply a broken variant of A: it faithfully models a *different* policy — one case-level quality check that may run any time while revisions iterate. If that is the real process, B is correct and P1 is the wrong specification. This is a question for the business, not for the tooling, and it should be resolved before either model is adopted; note that a "similar-looking" diagram with equal activity sets and identical minimum check counts is exactly the situation in which such a policy divergence goes unnoticed.

**Should the simplified model replace either original?** It should **replace Model A as the normative P1 model, and simultaneously replace Model B as the dashboard model**, provided the stakeholders accept the one documented restriction: `Check Revision` is prescribed to follow `Analyze Revision` within an attempt, so the 63-of-76 in-window A-traces that check before analysing are no longer accepted. In exchange it is smaller on every structural measure (11 vs 12 nodes, 4 vs 5 operators, no concurrency, 6/7/14 vs 9/9/20 and 7/7/16 net elements, 1 vs 3 silent transitions, simplicity 0.867 vs 0.818 and 0.778), exact for `β` and for `α`, and a strict under-approximation of A — it can never accept behaviour A forbids. It should **not** replace Model A where the intra-attempt order genuinely varies: for *conformance checking of real logs*, the canonicalisation turns legitimate `Check → Analyze` executions into false violations. In that setting, keep Model A as the conformance reference and use the simplified model for communication, training and dashboards; if false alarms are unacceptable and the diagram must also be minimal, the honest answer is that A's `+` operator is carrying real information and A should be kept unchanged. And if the audited concern is only "did any check happen", use the 7-node dashboard model from §8 — but never for compliance.

**Warning about the limits of bounded comparison.** Every bounded result above is asymmetric in strength. The refutations are *proofs*: the exhaustive breadth-first exploration is complete within the P3 window because both bounds are prefix-monotone, so the 72 A-only and 81 B-only witnesses are real, and each one on its own disproves unbounded visible trace equivalence — which is why the N1 verdict is stated as proved and is additionally backed by the closed-form languages and the invariants `#C = #A` vs `#C = 1`. Had the bounded sets been *equal*, nothing comparable would follow: bounded agreement establishes only that the shortest distinguishing trace exceeds 12 visible events or 3 analyses, and process trees with loops routinely hide their first difference beyond any fixed window (a fourth iteration, a rarer interleaving, a longer approval pattern). Do not report "bounded-equivalent" as "equivalent". Three further limits apply. First, all of this is *linear-time*: even exact language equality would leave branching-time differences (moment of choice for approval and for loop exit) undetected, and those matter for anything driven by decision points rather than by traces. Second, the play-out, stochastic-language and EMD figures depend on a *declared* simulator distribution that is not a property of either model; they can rank differences by likely business impact but can never certify equivalence, and a low EMD is compatible with provably disjoint languages. Third, equal footprints would prove nothing either, being a length-2 pairwise abstraction; here they happen to *differ*, which corroborates the trace-level refutation but adds no independent proof. For an unbounded guarantee, use the closed-form language characterisations and the counting invariants in §1 — they, not the bounded search, are what actually settle the question.
