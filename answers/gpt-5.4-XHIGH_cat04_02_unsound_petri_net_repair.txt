# 1. Executive Verdict
It is structurally a workflow net: there is one source place (`source`), one sink place (`sink`), and every place and transition lies on at least one directed source-to-sink path. It should nevertheless be expected to be unsound. The principal defect is the waiver route: `t_join_waived` consumes only `p_waived`, so it can produce `p_decision` without synchronizing with `p_analysis_done`. Therefore `t_authorize` can fire before `t_analyze`; even if analysis is executed later, the leftover token in `p_analysis` or `p_analysis_done` cannot be removed. The business consequence is that a waived case can be authorized without mandatory analysis, and executions can place a token in `sink` without ever reaching the exact final marking `{sink: 1}`.

# 2. Structural Diagnosis
| Element or subnet | Intended role | Actual structural effect | Potential symptom |
| --- | --- | --- | --- |
| `source`, `t_register`, `p_ready`, `im` | Unique start of the case | One token starts in `source`, then moves to `p_ready` before branching | Start behavior is ordinary and not the defect source |
| `t_split` | AND-split into mandatory analysis and review work | Consumes one token from `p_ready` and creates one token in `p_analysis` and one in `p_review` | Both branches now need to be accounted for before proper completion |
| `p_analysis -> t_analyze -> p_analysis_done` | Mandatory analysis branch | Produces the only token that can satisfy the analysis side of `t_join_normal` | Analysis is mandatory only on the standard-review route, not on the waiver route |
| `p_review -> t_standard_review -> p_review_done` | Standard review alternative | Exclusive review choice that feeds `t_join_normal` | Standard path behaves like the intended review completion |
| `p_review -> t_waive_review -> p_waived` | Waiver alternative | Exclusive review choice that bypasses `p_review_done` entirely | Waiver can finish the review branch without resolving the analysis branch |
| `t_join_normal` | Synchronize analysis and standard review | Proper 2-input AND-join on `p_analysis_done` and `p_review_done` | Normal cases can complete cleanly |
| `t_join_waived` | Synchronize analysis and waiver before authorization | Actually only a 1-input pass-through from `p_waived` to `p_decision` | Waived cases can reach authorization with analysis unfinished or unconsumed |
| `p_decision -> t_authorize -> sink`, `fm` | Final decision and completion | Any token in `p_decision` can be authorized into `sink`; `fm` requires that no other place still contains a token | A token in `sink` is not enough; extra tokens mean the exact final marking has not been reached |
| Whole net and source-to-sink paths | Workflow-net structure | Unique source and sink are present, and every node lies on some directed source-to-sink path | `pm4py.check_is_workflow_net(...)` can succeed even though soundness fails |

# 3. Marking-Based Counterexample
A legal firing sequence exposing the defect is:

`t_register, t_split, t_waive_review, t_join_waived, t_authorize`

This already shows that authorization can occur before `t_analyze`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| --- | --- | --- | --- | --- |
| 0 | start from `im` | `{source: 1}` | `t_register` | Initial marking |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | Registration is complete |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze, t_standard_review, t_waive_review` | The split creates one token in each parallel branch |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `t_analyze, t_join_waived` | The waiver finishes the review side but leaves the analysis token untouched |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `t_analyze, t_authorize` | `t_authorize` is now enabled even though `t_analyze` has not fired |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `t_analyze` | A token exists in `sink`, but the exact final marking `fm = {sink: 1}` has not been reached because `p_analysis` still holds a token |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | none | The leftover token moved to `p_analysis_done`, but it still cannot be consumed: `t_join_normal` also needs `p_review_done`, and `t_join_waived` no longer has an input token to use |

So the defect is not just early authorization. It also causes improper completion: the net reaches a dead marking that is not equal to `fm`.

A second legal counterexample shows that even performing analysis first does not save the waiver route:

`t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`

This reaches `{p_analysis_done: 1, sink: 1}`. Here `t_authorize` occurs after `t_analyze`, but the final marking is still not reached because `p_analysis_done` cannot be consumed without `p_review_done`, and the waiver join never consumes `p_analysis_done`.

# 4. Minimal-Repair Alternatives
Edit-cost model used below:

- add one arc = 1
- remove one arc = 1
- add one place = 1
- remove one place = 1
- add one transition = 1
- remove one transition = 1
- rename or comment change = 0

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
| --- | --- | --- | --- | --- | --- |
| A. Proper two-input waiver join | Add arc `p_analysis_done -> t_join_waived` | 1 | Analysis stays mandatory on both review outcomes; standard review and waiver remain distinct; authorization still happens only after a review outcome and analysis | Waiver may still be recorded before analysis, but authorization is blocked until both are complete | Two silent joins (`t_join_normal`, `t_join_waived`) still lead to the same `p_decision`, which can complicate interpretation of invisible routing |
| B. Synchronize at waiver recording time | Add arc `p_analysis_done -> t_waive_review` | 1 | Authorization still requires analysis plus one review outcome; no leftover analysis token remains on waived cases | Waiver cannot be recorded until analysis has completed | This is stricter than the stated policy and may reject legitimate cases where the waiver is decided early |
| C. Shared post-review place and single join | Remove arc `t_waive_review -> p_waived`; remove arc `p_waived -> t_join_waived`; remove arc `t_join_waived -> p_decision`; remove place `p_waived`; remove transition `t_join_waived`; add arc `t_waive_review -> p_review_done` | 6 | Analysis remains mandatory; review is still an exclusive choice; authorization still waits for analysis plus a completed review outcome | Standard review and waiver now share one post-review place and one synchronization point | The place `p_review_done` becomes semantically broader: it now means "review resolved" rather than only "standard review done" |

Repairs A and B are globally minimal under this cost model: no zero-cost change can alter the behavior, and one added arc is sufficient to block the defective waiver-only completion while keeping workflow-net structure intact.

They tie because they each inject exactly one missing dependency, but at different points:

- Repair A enforces the dependency at the waiver join.
- Repair B enforces the dependency at waiver recording.

Repair C is not globally minimal, but it is minimal within the "remove the waiver-specific join and use one shared synchronization place" family. If any of the obsolete waiver-only nodes or arcs are left behind, the net either remains unsound or retains structurally dead elements that are no longer on a proper source-to-sink path.

# 6. Diagnostic and Reachability Code
Expected qualitative difference:

- The original net should still satisfy the workflow-net structure check, but its soundness diagnostics should expose improper completion on waiver traces because `sink` can be marked while an analysis token remains elsewhere.
- The repaired net should keep workflow-net status and remove that defective waiver completion; `t_authorize` on the waiver route should only become reachable after analysis has been completed.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def marking_to_str(marking):
    items = sorted((place.name, count) for place, count in marking.items() if count)
    return "{" + ", ".join(f"{name}: {count}" for name, count in items) + "}"


def fire_named(net, marking, transition_name):
    enabled = {t.name: t for t in pm4py.get_enabled_transitions(net, marking)}
    if transition_name not in enabled:
        raise RuntimeError(
            f"{transition_name} is not enabled at {marking_to_str(marking)}; "
            f"enabled={sorted(enabled)}"
        )

    t = enabled[transition_name]
    new_marking = Marking()
    for place, count in marking.items():
        new_marking[place] = count

    for arc in t.in_arcs:
        new_marking[arc.source] -= arc.weight
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]

    for arc in t.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + arc.weight

    print(f"Fired {transition_name} -> {marking_to_str(new_marking)}")
    return new_marking


for label, current_net, current_im, current_fm in [
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
]:
    print(f"\n=== {label.upper()} ===")
    print("workflow net:", pm4py.check_is_workflow_net(current_net))
    print("sound:", pm4py.check_soundness(current_net, current_im, current_fm, print_diagnostics=True))
    print(
        "enabled at initial marking:",
        sorted(t.name for t in pm4py.get_enabled_transitions(current_net, current_im)),
    )
    reachability_graph = pm4py.convert_to_reachability_graph(current_net, current_im, current_fm)
    print("reachability graph object:", reachability_graph)


print("\nOriginal counterexample:")
m = im
for name in [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_join_waived",
    "t_authorize",
]:
    m = fire_named(net, m, name)
print("Exact original final marking reached:", m == fm, marking_to_str(m))


print("\nRepaired waiver route:")
m = repaired_im
for name in [
    "t_register",
    "t_split",
    "t_waive_review",
]:
    m = fire_named(repaired_net, m, name)
print(
    "Enabled after waived review in repaired net:",
    sorted(t.name for t in pm4py.get_enabled_transitions(repaired_net, m)),
)
m = fire_named(repaired_net, m, "t_analyze")
m = fire_named(repaired_net, m, "t_join_waived")
m = fire_named(repaired_net, m, "t_authorize")
print("Exact repaired final marking reached:", m == repaired_fm, marking_to_str(m))
```

# 7. Repair Trade-Offs and Residual Risks
- Under the selected repair, waiver and standard review remain distinguishable because the visible transitions are still `t_standard_review` and `t_waive_review`; only the invisible synchronization changes.
- The selected repair keeps two silent joins that both feed `p_decision`. That is acceptable, but it means different internal routes can lead to the same visible outcome, which can complicate model interpretation and alignment debugging.
- Soundness alone does not prove alignment with the business rule. A sound net could still be wrong by making analysis optional under waiver, by forcing waiver too late, or by imposing unintended ordering constraints.
- Positive traces to regression-test include: `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize`; `t_register, t_split, t_standard_review, t_analyze, t_join_normal, t_authorize`; `t_register, t_split, t_waive_review, t_analyze, t_join_waived, t_authorize`; and `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`.
- Negative traces to regression-test include: `t_register, t_split, t_waive_review, t_join_waived, t_authorize` without `t_analyze`; any trace that enables `t_authorize` immediately after `t_join_waived` while `p_analysis_done` is absent; and any completed execution leaving tokens outside `sink`.
- To detect an accidental bypass of mandatory analysis, add an automated reachability assertion that every marking enabling `t_authorize` must be reachable only after one occurrence of `t_analyze`, and add process tests that fail whenever a completed waived case lacks the analysis event.

# 8. Final Recommendation
Deploy Repair A: add the single arc `p_analysis_done -> t_join_waived`. It is the cheapest repair under the stated cost model, preserves the business policy as written, and keeps the desirable concurrency: analysis and review handling can still proceed independently, but authorization on the waiver route is blocked until both obligations are complete. It also preserves the visible activity vocabulary, so downstream event semantics do not change.

Keep Repair C as the fallback if the team prefers a cleaner structural model with one shared post-review completion place and no waiver-specific join. That variant is more invasive, but it simplifies the synchronization story and may be easier to explain to future modelers. I would not deploy Repair B by default unless the business explicitly wants waiver recording to be impossible before analysis finishes, because that introduces an extra sequencing constraint that is not stated in the original intent.
