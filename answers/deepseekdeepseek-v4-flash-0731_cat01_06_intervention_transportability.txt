The shared causal mechanism is simple: creating truly concurrent verification tasks removes the sequential wait between Identity Check and Document Check. If those tasks are independent and the queue is not saturated, the waiting time before Assessment falls, which reduces total cycle time. This mechanism is likely transportable to Site B’s digital/no-original subgroup.

Site-specific mechanisms are substantial. Originals Receipt is a statutory prerequisite for Document Check in 62% of B cases. Separate roles and a legacy case lock prevent true overlap unless explicitly enabled. Legal Review and supplement loops introduce a second queue that A did not have. API latency, queue huddles, and staffing changes at A were co-interventions, not structural parts of the parallelization intervention.

Important effect modifiers are originals_required, digital_documents, role_specialization, IT_case_lock, legal_capacity, assessment_capacity, case_complexity, and queue saturation. The selection nodes S_… show why the causal graph differs between A and B. Two control-flow diagrams can look similar, but the selection nodes change which conditional distributions are available. A cannot identify the Site-B-specific effect without either modeling those modifiers or running a randomized transport experiment at B.

## 6. Candidate Site B intervention

Modified intervention: **segmented parallelization**, not blanket copying of Site A.

Eligibility rules:
- **T1 — digital/no-original claims**: after Register, create Identity Check and Document Check concurrently. This matches Site A’s after-state.
- **T2 — originals-required claims**: after Register, create Identity Check and Originals Receipt concurrently. Document Check is created only after Originals Receipt completes.
- **Legal-review cases**: verification follows T1 or T2 based on the originals rule. Legal Review remains after Assessment. If Request Supplement is issued, Document Check and Assessment are repeated according to existing legal workflow.

Statutory prerequisites that remain mandatory:
- Originals Receipt must precede Document Check when originals are required.
- Assessment requires both Identity Check and Document Check complete.
- Public-sector/high-value cases require Legal Review before final decision.
- Any supplement request repeats the document/assessment stages required by the legal review decision.

Queue and WIP controls:
- Cap open identity tasks per identity reviewer at 6.
- Cap open document tasks per document reviewer at 6.
- For originals-required cases, do not create Document Check before Originals Receipt even if identity is idle.
- Monitor Assessment queue length and Legal Review queue length; stop expansion if either queue grows above baseline by more than 25% for two consecutive weeks.

Resource responsibilities:
- Identity reviewers own Identity Check.
- Document reviewers own Document Check.
- Originals Receipt is recorded by the intake/clerical function.
- Assessors and legal reviewers retain current responsibilities.
- No cross-training is assumed.

Legal-review and supplement-loop handling:
- Legal Review remains a separate mandatory task for eligible cases.
- Request Supplement returns the case to Document Check and then Assessment for the affected parts.
- Parallel verification tasks are not recreated on a supplement unless identity or document evidence has specifically changed.

Logging requirements:
- Automatic start/complete timestamps for every task.
- No manual back-entry for overlap.
- A case may have two active verification tasks only if the system supports simultaneous ownership or the pilot uses an audited event log that can prove concurrency.

POWL-style partial-order description:

```text
R: Register
I: Identity Check
D: Document Check
OR: Originals Receipt
A: Assessment
LR: Legal Review
ReqSup: Request Supplement
App/Rej: Approve/Reject
N: Notify

Digital path:
R < I, R < D, I < A, D < A

Originals path:
R < I, R < OR, OR < D, I < A, D < A

Legal-review option:
A < LR; LR -> ReqSup -> D -> A; LR -> App/Rej
Final:
App/Rej < N
```

The pilot separates mechanism failure from implementation failure by measuring both the process mechanism and the outcome. If T1 shows no reduction in median Assessment time but overlap percentage is high, the parallelization mechanism failed to produce benefit because of queues or bottlenecks, not because the process was not implemented. If overlap percentage is low, implementation failed due to case locking, timestamps, or workflow violations. If overlap is high and Assessment time improves but final cycle time does not, the shift occurred at Legal Review or Assessment. The randomized design also controls for the co-interventions that confounded Site A: equivalent queue huddles, no marketing shift, and fixed API monitoring.

## 8. PM4Py model-construction code

```python
import pm4py
from pm4py.objects.powl.obj import Operator, OperatorType, StrictPartialOrder

# ----------------------------------------------------------------------
# 1. Site A before and after process trees
# ----------------------------------------------------------------------
tree_a_before = pm4py.parse_process_tree(
    "->( 'Register', 'Identity Check', 'Document Check', 'Assessment', "
    "X( 'Approve', 'Reject' ), 'Notify' )"
)
tree_a_after = pm4py.parse_process_tree(
    "->( 'Register', +( 'Identity Check', 'Document Check' ), 'Assessment', "
    "X( 'Approve', 'Reject' ), 'Notify' )"
)

net_before, im_before, fm_before = pm4py.convert_to_petri_net(tree_a_before)
net_after, im_after, fm_after = pm4py.convert_to_petri_net(tree_a_after)

def report_soundness(name, net, im, fm):
    try:
        wf = pm4py.check_is_workflow_net(net, im, fm)
        print(name, "workflow net:", wf)
    except Exception as e:
        print(name, "workflow-net check unavailable:", e)
    try:
        s = pm4py.check_soundness(net, im, fm)
        if isinstance(s, tuple):
            s = s[0] if len(s) == 1 else s
        print(name, "sound:", s)
    except Exception as e:
        print(name, "soundness check unavailable:", e)

report_soundness("Site A before", net_before, im_before, fm_before)
report_soundness("Site A after", net_after, im_after, fm_after)

# ----------------------------------------------------------------------
# 2. Site B candidate using POWL classes
# ----------------------------------------------------------------------
def act(label):
    # Atomic activity as a trivial XOR operator.
    # Some PM4Py versions provide a dedicated Activity class; this wrapper
    # keeps the example portable across tree-style POWL representations.
    return Operator(OperatorType.XOR, children=[label])

def make_spo(nodes, edges):
    po = StrictPartialOrder()
    for n in nodes:
        po.add_node(n)
    for a, b in edges:
        po.add_order(a, b)
    return po

register = act("Register")

# Digital path: Identity and Document both precede Assessment
identity_d = act("Identity Check")
document_d = act("Document Check")
assessment_d = act("Assessment")

digital_path = make_spo(
    [identity_d, document_d, assessment_d],
    [(identity_d, assessment_d), (document_d, assessment_d)]
)

# Originals path: Identity and Originals Receipt are parallel;
# Document waits for receipt; Assessment waits for Identity and Document.
identity_o = act("Identity Check")
originals_receipt = act("Originals Receipt")
document_o = act("Document Check")
assessment_o = act("Assessment")

originals_path = make_spo(
    [identity_o, originals_receipt, document_o, assessment_o],
    [
        (identity_o, assessment_o),
        (originals_receipt, document_o),
        (document_o, assessment_o)
    ]
)

after_reg = Operator(OperatorType.XOR, children=[digital_path, originals_path])
main = Operator(OperatorType.SEQUENCE, children=[register, after_reg])

# Optional legal-review branch with supplement loop
legal_review = act("Legal Review")
document_repeat = act("Document Check (repeat)")
assessment_repeat = act("Assessment (repeat)")
request_supplement = act("Request Supplement")

supplement_loop = Operator(
    OperatorType.LOOP,
    children=[
        Operator(OperatorType.SEQUENCE, children=[document_repeat, assessment_repeat]),
        request_supplement
    ]
)

approve_legal = act("Approve")
reject_legal = act("Reject")
legal_decision = Operator(OperatorType.XOR, children=[approve_legal, reject_legal])
legal_branch = Operator(
    OperatorType.SEQUENCE,
    children=[legal_review, supplement_loop, legal_decision]
)

approve_direct = act("Approve")
reject_direct = act("Reject")
direct_decision = Operator(OperatorType.XOR, children=[approve_direct, reject_direct])
final_choice = Operator(OperatorType.XOR, children=[legal_branch, direct_decision])

notify = act("Notify")
site_b_candidate = Operator(OperatorType.SEQUENCE, children=[main, final_choice, notify])

# Convert POWL candidate to accepting Petri net
net_b, im_b, fm_b = pm4py.convert_to_petri_net(site_b_candidate)
report_soundness("Site B candidate", net_b, im_b, fm_b)

# ----------------------------------------------------------------------
# 3. Playout sample traces
# ----------------------------------------------------------------------
print("\nSample traces from Site B candidate:")
for trace in pm4py.play_out(net_b, im_b, fm_b, num_traces=5, max_trace_length=50):
    print(" -> ".join(trace))

# ----------------------------------------------------------------------
# Comments on model limitations
# ----------------------------------------------------------------------
# The Petri net/POWL model cannot encode data-dependent eligibility:
# e.g., whether a case requires originals or legal review is represented as
# nondeterministic XOR choice, not as a case attribute.
# Resource capacities, case locks, queue discipline, durations, and API
# latency are not encoded in the control-flow model.
```

## 9. Recommendation

`conditional go`

Transfer Site A’s underlying mechanism, not its exact universal rule. The mechanism worth transferring is creating real concurrency between verification tasks that are causally independent and have no statutory ordering constraint. At Site B this is legal for digital/no-original claims: Identity Check and Document Check can be parallel. For originals-required claims, the only safe parallelization is Identity Check with Originals Receipt; Document Check must still wait for receipt. Do not copy Site A’s concurrent Document Check into the originals-required path, because that would violate the statutory prerequisite. Do not copy Site A’s co-interventions — API upgrade, extra document reviewers, marketing shift, or queue huddles — as if they were part of the parallelization treatment.

The first entry subgroup should be digital claims that do not require originals and, if possible, do not require Legal Review. This subgroup is structurally closest to Site A’s after-state and has the smallest number of non-transportable constraints. Expected benefit is a 4–7 h median reduction in time to Assessment and perhaps a 6–10 h p90 reduction if queues are not saturated. The main risks are that the legacy case lock prevents true overlap, that Assessment or Legal Review becomes the new bottleneck, and that back-entered timestamps create a false appearance of success.

Expansion should occur only if the pilot shows: true overlap in at least 60% of treated digital cases, median time to Assessment reduced by at least 5 h versus control, p90 not worsened by more than 5%, and no material increase in rework or appeals. If p90 worsens by more than 15%, stop and add bottleneck capacity or tighten WIP. If true overlap remains low, the intervention is an implementation failure caused by case locking; upgrade the IT system or abandon the manual workaround. If overlap is high but outcomes do not improve, the mechanism failed because of queue saturation or downstream bottlenecks; add capacity or narrow eligibility.

`conditional go` means: proceed only with the segmented pilot first, not with a full rollout to all cases.

## 10. Assumption register

1. 2. Site B digital/no-original cases are comparable to Site A’s simpler digital mix — why needed: they are the primary transport stratum — how to test: compare case attributes, complexity scores, document types — consequence if false: restrict transport to an even narrower subgroup.
3.
