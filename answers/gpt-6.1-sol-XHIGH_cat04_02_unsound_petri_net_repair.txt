# 1. Executive Verdict

The net **is a workflow net**: it has one source place, one sink place, and every node lies on a directed source-to-sink path. It **is not sound**.

The principal defect is that `t_join_waived` consumes only `p_waived`; it does not synchronize with the mandatory analysis branch. Consequently, authorization can occur before analysis finishes. Completing analysis afterward does not repair the execution: its completion token remains stranded.

The standard-review route can reach the exact final marking. Every waiver execution instead leaves an analysis token outside the sink, so a sink token alone is not evidence of proper completion. The model therefore violates both mandatory-analysis-before-authorization and clean case completion.

# 2. Structural Diagnosis

Assume ordinary Petri-net firing semantics, unit-weight arcs, and the specified single-case initial marking. A marking lists token counts; unlisted places contain zero tokens.

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source → t_register → p_ready` | Register one case before starting work. | Moves the initial token to `p_ready`. | No defect in this prefix. |
| `t_split` | Start analysis and review in parallel. | Consumes one `p_ready` token and produces one token in each of `p_analysis` and `p_review`. | Two obligations now exist; a successful completion must discharge both. |
| `t_analyze` | Complete mandatory analysis. | Moves the analysis token from `p_analysis` to `p_analysis_done`. | On the waiver route, the resulting token has no enabled consumer. |
| `t_standard_review` | Perform the standard review alternative. | Consumes `p_review` and produces `p_review_done`. | Works with `t_join_normal`; cannot also take the waiver alternative. |
| `t_waive_review` | Record the waiver alternative. | Competes with `t_standard_review` for the same single `p_review` token and produces `p_waived`. | Review alternatives are correctly exclusive, but waiver does not discharge analysis. |
| `t_join_normal` | Synchronize completed analysis and standard review. | Requires and consumes one token from each of `p_analysis_done` and `p_review_done`, producing one `p_decision` token. | Correct synchronization on the standard route. |
| `t_join_waived` | Synchronize completed analysis and the recorded waiver. | Requires only `p_waived`, producing `p_decision` independently of analysis. | Premature authorization and an unconsumed analysis obligation. |
| `t_authorize` | Authorize after both obligations are complete. | Requires only `p_decision`, whose provenance is trusted. | The defective waived join can supply authorization permission too early. |
| `im = {source: 1}` | Start exactly one case. | Contains no other tokens. | Does not explain away or compensate for the waiver defect. |
| `fm = {sink: 1}` | Finish with exactly one sink token and no other tokens. | Specifies exact completion, not merely `sink ≥ 1`. | `{sink: 1, p_analysis_done: 1}` is not `fm`. |
| Whole graph | Meet the workflow-net structural conditions. | `source` is the only place with no incoming arcs; `sink` is the only place with no outgoing arcs. Every place and transition lies on a directed path between them. | Structural workflow-net status does not establish soundness. |

In particular, the analysis subnet reaches the sink through `t_join_normal`, while the waiver subnet reaches it through `t_join_waived`. A directed path ignores whether all inputs of an AND-join can simultaneously be marked. Thus the path condition holds even though waiver executions cannot complete properly.

# 3. Marking-Based Counterexample

A legal sequence that authorizes before analysis is:

```text
t_register, t_split, t_waive_review, t_join_waived,
t_authorize, t_analyze
```

Enabled transitions below are the complete enabled sets at the resulting markings.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source: 1}` | `{t_register}` | Exactly `im`. |
| 1 | `t_register` | `{p_ready: 1}` | `{t_split}` | Registration completes. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `{t_analyze, t_standard_review, t_waive_review}` | One token is created in each parallel branch. |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `{t_analyze, t_join_waived}` | The review token is consumed exclusively by waiver. |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `{t_analyze, t_authorize}` | Authorization is enabled although analysis has not fired. |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `{t_analyze}` | A sink token exists, but the marking is not `fm`. |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | `∅` | Deadlock outside `fm`. |

At step 5, the pending analysis token can still be consumed by `t_analyze`. That merely moves it to `p_analysis_done`; it does not eliminate the outstanding token. The only consumer of `p_analysis_done` is `t_join_normal`, which also requires `p_review_done`. The review token was consumed by waiver, and neither `p_review` nor an upstream token remains to produce `p_review_done`. No further firing can consume the leftover token.

The same defect persists when analysis finishes **before** authorization. A second legal sequence is:

```text
t_register, t_split, t_analyze, t_waive_review,
t_join_waived, t_authorize
```

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source: 1}` | `{t_register}` | Exactly `im`. |
| 1 | `t_register` | `{p_ready: 1}` | `{t_split}` | Registration completes. |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `{t_analyze, t_standard_review, t_waive_review}` | Both branches are marked. |
| 3 | `t_analyze` | `{p_analysis_done: 1, p_review: 1}` | `{t_standard_review, t_waive_review}` | Analysis finishes first. |
| 4 | `t_waive_review` | `{p_analysis_done: 1, p_waived: 1}` | `{t_join_waived}` | The analysis completion token cannot enable the normal join. |
| 5 | `t_join_waived` | `{p_analysis_done: 1, p_decision: 1}` | `{t_authorize}` | The waived join ignores completed analysis too. |
| 6 | `t_authorize` | `{p_analysis_done: 1, sink: 1}` | `∅` | Authorization follows analysis, but completion is still improper. |

These are two consequences of the same missing synchronization, not evidence of a separate syntax defect. The premature authorization is a legal firing prefix, but neither waiver sequence is an accepted complete trace: acceptance requires exactly `fm`. The original accepting language therefore omits successful waiver completions. Every transition is reachable on some execution; the decisive failures are lack of proper completion and lack of an option to reach `fm` from waiver markings. A standard execution such as `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize` does reach exactly `fm`, but one successful route is insufficient for soundness.

# 4. Minimal-Repair Alternatives

**Edit-cost model.** Each added or removed unit-weight arc, place, or transition costs 1. Rewiring an arc costs 2: remove its old instance and add its replacement. Removing a node does not make its incident-arc removals free. Labels, weights, `im`, and `fm` remain unchanged. Repairs must leave a sound workflow net. Global minimality refers to this edit space; a constrained minimum is explicitly identified below.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **A — Proper separate waiver synchronization** | Add `p_analysis_done → t_join_waived`. | **1; globally minimal.** | Mandatory analysis, exclusive standard review or recorded waiver, authorization after both obligations, exact completion. | The waived join waits for and consumes the analysis completion token. | No new token-flow defect under these assumptions; the two joins must both remain synchronized if the model later changes. |
| **B — Shared completion and normal synchronization** | Remove `t_join_waived → p_decision`; add `t_join_waived → p_review_done`. Retain all nodes and other arcs. | **2; minimal within the shared-join family described below.** | All original business requirements. Visible standard-review and waiver labels remain distinct. | `t_join_waived` becomes a silent adapter from `p_waived` to a common review-completion place. Both routes then use `t_join_normal`. | The old name suggests a join although this transition now only forwards a token. The common place no longer records which review outcome occurred; the event history must retain that evidence. |
| **C — Joint waiver of review and pending analysis** | Add `p_analysis → t_waive_review`. | **1; globally minimal for the explicitly changed policy.** | Exclusive review choice and exact completion; analysis remains mandatory on the standard route. | Waiver consumes both pending branch tokens and exempts analysis. It is possible only before `t_analyze`; if analysis fires first, standard review becomes the only remaining review choice. | Violates the original mandatory-analysis rule and forbids a review waiver after analysis. Requires adoption of this different business policy. |

**Minimality.** Zero edits retain the demonstrated unsound net. A and C each yield a sound workflow net with one edit, so both attain the global lower bound. They tie in structural edit cost, but differ substantially in policy: A waits for analysis; C cancels its pending token when waiver is recorded.

B is not claimed to be a global minimum. Its constrained objective is to retain all existing nodes and make both review outcomes synchronize through `t_join_normal`. The existing waived output to `p_decision` must be removed, and the waived result must gain a route to `p_review_done`; B performs exactly those two operations. Adding the new output without removing the old one would create an authorization bypass and eventually a second decision token. Removing the old output alone would strand waiver tokens and break the workflow-net path condition. Thus one operation cannot realize this shared-join design.

**Why the repairs are sound.** In A, after the split, analysis moves its token to `p_analysis_done`, and the review choice moves its token to exactly one of `p_review_done` or `p_waived`. The matching join consumes both tokens and produces one decision token. Authorization consumes that token and leaves exactly one sink token. Every reachable unfinished marking can follow this progression, and every transition participates in a successful execution.

B additionally forwards the waiver token to `p_review_done`, after which the same two-input normal join consumes both obligations. In C, waiver consumes both pending tokens before analysis, or an analysis/standard-review firing makes waiver unavailable and the normal route completes. C therefore restores soundness while changing policy.

A and B preserve the same completed visible traces, but their internal behavior and structure differ: after waiver, B can fire its silent adapter before analysis and later fires the normal join; A cannot fire its waived join until analysis is complete. C also differs in visible behavior by permitting completion without `Perform Analysis`.

# 5. Corrected PM4Py Code

This standalone implementation selects **Repair A**. Its sole structural change from the supplied model is the additional input to `t_join_waived`.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

repaired_net.places.update({
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink,
})

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition(
    "t_standard_review", "Perform Standard Review"
)
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

repaired_net.transitions.update({
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize,
})

petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)
petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
# The waiver join must also wait for and consume completed analysis.
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking({source: 1})
repaired_fm = Marking({sink: 1})
```

# 6. Diagnostic and Reachability Code

The following block assumes the original `net`, `im`, `fm` and the repaired variables exist. It checks both models, constructs both reachability graphs, and replays the counterexamples with enabledness checks.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking
from pm4py.objects.petri_net import semantics


def marking_text(marking):
    entries = sorted(
        (place.name, count)
        for place, count in marking.items()
        if count != 0
    )
    return "{" + ", ".join(f"{name}: {count}" for name, count in entries) + "}"


def enabled_names(candidate_net, marking):
    return sorted(
        transition.name
        for transition in pm4py.get_enabled_transitions(candidate_net, marking)
    )


def fire_named(candidate_net, marking, transition_name):
    matches = [
        transition
        for transition in candidate_net.transitions
        if transition.name == transition_name
    ]
    if len(matches) != 1:
        raise ValueError(f"Expected one transition named {transition_name!r}")

    transition = matches[0]
    enabled = pm4py.get_enabled_transitions(candidate_net, marking)
    if transition not in enabled:
        raise RuntimeError(
            f"{transition_name} is disabled at {marking_text(marking)}; "
            f"enabled={sorted(t.name for t in enabled)}"
        )

    result = semantics.execute(transition, candidate_net, marking)
    if result is None:
        raise RuntimeError("Execution failed after the enabledness check")
    return result


def replay(candidate_net, initial, final, sequence):
    marking = Marking(initial)
    print("initial:", marking_text(marking), enabled_names(candidate_net, marking))
    for name in sequence:
        marking = fire_named(candidate_net, marking, name)
        print(name, marking_text(marking), enabled_names(candidate_net, marking))
    print("Exact final marking reached:", marking == final)
    return marking


graphs = {}
for title, candidate_net, initial, final in (
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
):
    print("\nModel:", title)
    print("Workflow net:", pm4py.check_is_workflow_net(candidate_net))
    sound, diagnostics = pm4py.check_soundness(
        candidate_net, initial, final, print_diagnostics=True
    )
    print("Sound:", sound)
    print("Initially enabled:", enabled_names(candidate_net, initial))
    graphs[title] = pm4py.convert_to_reachability_graph(
        candidate_net, initial, final
    )
    print("Reachability graph constructed")


early_authorization = [
    "t_register", "t_split", "t_waive_review", "t_join_waived",
    "t_authorize", "t_analyze",
]
analysis_first = [
    "t_register", "t_split", "t_analyze", "t_waive_review",
    "t_join_waived", "t_authorize",
]

print("\nOriginal: authorization before analysis")
original_end = replay(net, im, fm, early_authorization)
assert original_end != fm
assert not pm4py.get_enabled_transitions(net, original_end)

print("\nOriginal: analysis before authorization")
original_end = replay(net, im, fm, analysis_first)
assert original_end != fm
assert not pm4py.get_enabled_transitions(net, original_end)

print("\nRepaired: reject the premature waived join")
try:
    replay(repaired_net, repaired_im, repaired_fm, early_authorization)
except RuntimeError as error:
    print("Blocked as expected:", error)
else:
    raise AssertionError("Mandatory analysis was bypassed")

positive_sequences = [
    ["t_register", "t_split", "t_analyze", "t_standard_review",
     "t_join_normal", "t_authorize"],
    ["t_register", "t_split", "t_standard_review", "t_analyze",
     "t_join_normal", "t_authorize"],
    ["t_register", "t_split", "t_analyze", "t_waive_review",
     "t_join_waived", "t_authorize"],
    ["t_register", "t_split", "t_waive_review", "t_analyze",
     "t_join_waived", "t_authorize"],
]
for sequence in positive_sequences:
    print("\nRepaired positive sequence:")
    assert replay(repaired_net, repaired_im, repaired_fm, sequence) == repaired_fm
```

Expected qualitative results are:

- **Original:** workflow-net check passes; soundness fails. Reachability includes a sink token with a pending analysis token and a terminal marking containing both `sink` and `p_analysis_done`. Some reachable markings have no continuation to `fm`.
- **Repair A:** workflow-net and soundness checks pass. After waiver but before analysis, `t_join_waived` is disabled. Every reachable marking has a continuation to `repaired_fm`, and a sink token occurs only in that exact final marking.

Local checks of these APIs and exhaustive marking exploration confirmed these results; B and C also passed soundness under their stated policies. No particular diagnostic dictionary keys or state-space sizes are needed for the argument.

# 7. Repair Trade-Offs and Residual Risks

**Outcome identity.** A retains separate `p_review_done` and `p_waived` places and separate matching joins, so the selected review outcome remains structurally distinguishable until synchronization. All repairs retain the visible labels `Perform Standard Review` and `Record Review Waiver`. B merges the outcome tokens into a shared completion place; its event history still distinguishes the outcomes.

**Silent behavior.** In A, the joins cannot both fire for one case: the single review token produces only one review outcome, and the matching join consumes the single analysis completion token. There is no second authorization or duplicate completed behavior from these joins. Their shared input place does not create a choice when only one review outcome is marked. B adds a silent forwarding step on the waiver route, permitting different internal interleavings with analysis that can project to the same visible trace. This can create multiple equivalent alignment explanations and make the old `t_join_waived` name confusing, although it does not duplicate case completion.

**Soundness and policy.** Soundness proves properties of the modeled token behavior, not that the model expresses the business rules. C demonstrates the distinction: it is sound but accepts a waiver execution without analysis. Likewise, these uncolored tokens do not identify cases if multiple cases are pooled into one marking; the analysis assumes the supplied single-case marking. Real deployments must preserve case isolation and separately enforce who may record a waiver.

**Regression traces.** For A and B, test these complete visible traces, inserting the appropriate silent transitions:

| Expected | Visible trace or condition |
|---|---|
| Accept | `Register Case → Perform Analysis → Perform Standard Review → Authorize Case` |
| Accept | `Register Case → Perform Standard Review → Perform Analysis → Authorize Case` |
| Accept | `Register Case → Perform Analysis → Record Review Waiver → Authorize Case` |
| Accept | `Register Case → Record Review Waiver → Perform Analysis → Authorize Case` |
| Reject | `Register Case → Record Review Waiver → Authorize Case`, with analysis absent or postponed until after authorization. |
| Reject | Authorization after analysis with neither review outcome. |
| Reject | Both review outcomes in the same case, repeated analysis, or a second authorization. |
| Reject as complete | Any execution with a sink token and another nonzero place. |

For B, waiver positives must include the adapter followed by the normal join. For C, the analysis-free waiver trace becomes positive, while a waiver after analysis becomes negative; these changed expectations must be approved as a policy change before using C.

**Detecting analysis bypass.** In regression checking, augment reachability states with a Boolean recording whether `t_analyze` has fired. Assert that every reachable state enabling `t_authorize` has this flag set, and that exactly one review outcome has occurred. Explore all enabled transitions, including silent transitions, rather than only the four positive traces. Carry history flags in the exploration key alongside the marking so histories are not accidentally merged. For these finite, acyclic nets, this exploration terminates.

Checking merely whether `p_analysis_done` is currently marked would be wrong: a correct join consumes that token before enabling authorization. The history monitor directly tests the rule that analysis precedes authorization, and would reject C for the original policy. Separately assert that every reachable marking containing `sink` equals `fm` and that every reachable marking can reach `fm`; these checks catch leftover tokens even when the visible event ordering looks correct.

# 8. Final Recommendation

Deploy **Repair A**, adding `p_analysis_done → t_join_waived`. It is globally minimal under the stated cost model, preserves every original business requirement and visible label, and keeps waiver and standard-review outcomes structurally distinct. Both joins then consume completed analysis together with the selected review outcome, leaving one decision token and ultimately exactly `fm`.

Use **Repair B** as the fallback when the maintained model should have a single authorization synchronization. Its two arc edits preserve the same completed visible behavior, at the cost of an additional silent forwarding step and merged review-completion state. Document the adapter’s purpose and retain waiver evidence in the event history.

Do not deploy C under the original requirements. Its equal one-edit cost restores soundness by changing the policy, allowing waiver to exempt analysis. Whichever policy-preserving repair is chosen, require both soundness checks and explicit positive/negative ordering tests before deployment.
