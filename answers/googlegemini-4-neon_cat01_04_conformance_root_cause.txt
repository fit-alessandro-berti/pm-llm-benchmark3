The observed conformance collapse from 93% to 32% is best explained as a compound measurement artifact overlaid on real policy and behavioral changes rather than a single-cause failure. In June–July, three independent instrumentation changes—the UI relabeling of `Classify` to `Risk Screen`, the gateway injection of technical `Queue Routed` events, and the ETL switch to warehouse-ingestion timestamps—altered `recorded_labels`, event counts, and `recorded_order` without altering the underlying `true_process`. Because trace alignments penalize every unmatched label or inverted activity pair against a static `normative_model`, these logging defects stacked additively into high alignment costs and steep drops in `measured_fitness`. By August–September, a fourth mechanism compounded the signal: the EUR 50,000 `policy_change` legitimately altered `true_process` through `Supervisor Sign-off`, while `normative_model` remained obsolete.

Simultaneously, two residual behaviors resist purely technical explanations: `Manual Override` workarounds driven by routing errors and `Enhanced Review` cases lacking `Compliance Check` (14.7% in June–July; 11.1% in August–September). Importantly, stable `business_outcomes` (approval 71.5–72.0%; 30-day appeals 3.6–3.8%) neither confirm pure data error nor exonerate employees. First, appeals are a lagging, customer-initiated metric: customers rarely appeal favorable or undetected regulatory shortcuts, and Compliance explicitly noted incomplete incident detection. Second, unrecorded compliance checks could reflect either genuine reviewer bypasses (invisible to appeal rates) or silent logging loss (invisible to customers). Conversely, a slight cycle-time increase (26.0 to 27.4 hours) aligns with legitimate `Supervisor Sign-off` workload rather than widespread shortcutting. Disentangling these overlapping pathways requires provenance-level auditing rather than aggregate KPIs.

def build_log_from_variants(variant_counts: dict[str, int]) -> pd.DataFrame:
    """Expand trace-frequency dictionary using pm4py.parse_event_log_string."""
    traces: list[str] = []
    for trace_str, count in variant_counts.items():
        traces.extend([trace_str] * count)
    event_log = pm4py.parse_event_log_string(traces, sep=",")
    return pm4py.convert_to_dataframe(event_log)


def normalize_log(
    log_df: pd.DataFrame,
    label_map: dict[str, str] | None = None,
    drop_activities: set[str] | None = None,
) -> pd.DataFrame:
    """Transparent, non-destructive log normalization pipeline."""
    df = log_df.copy()
    if label_map:
        df["concept:name"] = df["concept:name"].replace(label_map)
    if drop_activities:
        df = df[~df["concept:name"].isin(drop_activities)].copy()
    # Preserve original within-case ordering deterministically
    df = df.sort_values(
        ["case:concept:name", "time:timestamp"], kind="mergesort"
    ).reset_index(drop=True)
    return df


def summarize_alignments(
    log_df: pd.DataFrame, net, im, fm, label: str, compute_precision: bool = False
) -> dict:
    """Compute alignment diagnostics, fitness, move counts, and optional precision."""
    diagnostics = pm4py.conformance_diagnostics_alignments(log_df, net, im, fm)
    fitness = pm4py.fitness_alignments(log_df, net, im, fm)

    log_moves = Counter()
    visible_model_moves = Counter()
    total_cost = 0.0

    for diag in diagnostics:
        total_cost += float(diag.get("cost", 0.0))
        for log_act, model_act in diag.get("alignment", []):
            if log_act != ">>" and model_act == ">>":
                log_moves[log_act] += 1
            elif log_act == ">>" and model_act not in (">>", None):
                visible_model_moves[model_act] += 1

    perc_fit = fitness.get("percFitTraces", fitness.get("percentage_of_fitting_traces"))
    avg_fit = fitness.get("averageFitness", fitness.get("average_trace_fitness"))
    log_fit = fitness.get("log_fitness", avg_fit)
    mean_cost = total_cost / max(len(diagnostics), 1)

    result = {
        "condition": label,
        "cases": len(diagnostics),
        "perc_fit_traces": round(float(perc_fit), 2),
        "log_fitness": round(float(log_fit), 4),
        "mean_raw_alignment_cost": round(mean_cost, 2),
        "top_log_moves": log_moves.most_common(4),
        "top_visible_model_moves": visible_model_moves.most_common(4),
    }
    if compute_precision:
        precision = pm4py.precision_alignments(log_df, net, im, fm)
        result["alignment_precision"] = round(float(precision), 4)
    return result

## 7. Provisional conclusion

**Primary explanation for the measured conformance collapse (High confidence: 85–90%).** The headline deterioration in fitting traces—from 93% in April–May to 32% in June–July and 66% in August–September—was predominantly caused by data-provenance defects and model obsolescence rather than a sudden breakdown in employee discipline. Three IT and instrumentation changes explain 57 percentage points of the June–July drop (restoring fitness from 32% to 89%): the May 31 UI relabeling of `Classify` to `Risk Screen` (+26 pp), the June 3 injection of technical `Queue Routed` events (+23 pp), and the June 15 ETL switch to warehouse-ingestion timestamps (+8 pp). The subsequent August–September drop to 66% reflects an obsolete normative model that omitted the August 1 `Supervisor Sign-off` mandate; permitting optional sign-off restores fitness to 86%.

**Residual compliance risk assessment (Moderate confidence: 55–65% that a material operational or compliance issue persists).** Separating measurement noise from real risk reveals three unresolved concerns that cannot be dismissed: (1) 55 enhanced-review cases across June–September lack a recorded `Compliance Check` (14.7% of June–July and 11.1% of August–September enhanced reviews); (2) `Manual Override` rose from 20 to 35 cases, reflecting routing defects, unauthorized workarounds, or expanded August 12 logging; and (3) without claim-value stratification, adherence to `Supervisor Sign-off` for claims above EUR 50,000 remains unverified.

**Immediate actions.**
- **IT:** Switch conformance extraction to source-system sequence numbers; maintain a versioned semantic mapping for `Risk Screen` and isolate `Queue Routed` into a technical log layer; investigate why 90 June–July cases lacked `Queue Routed` and whether `Compliance Check` events can be dropped during ingestion.
- **Process owners:** Formalize a data-aware updated process model encoding the EUR 50,000 sign-off rule; diagnose routing errors driving `Manual Override`.
- **Compliance:** Audit all 55 enhanced-review cases missing `Compliance Check` against independent workpapers, stratify high-value claims against `Supervisor Sign-off`, and review `Manual Override` concentration by reviewer.

**What must not be claimed yet.** Stakeholders must not blame employees for the headline conformance collapse, claim compliance is intact based on flat appeal rates, treat the optional sign-off model as proof of EUR 50,000 adherence, or assume all `Notify -> Decision` inversions and missing compliance checks are purely technical artifacts.

## 8. Model-governance recommendation

1. **Effective-dated model versioning:** Bind every normative process model to explicit effective start/end dates and policy change tickets so that conformance jobs evaluate each case against the model version legally in force at case execution time, preventing policy updates like `Supervisor Sign-off` from appearing as retroactive violations.
2. **Event-semantic contracts:** Require UI, workflow, and ETL teams to emit immutable canonical business-activity codes (e.g., `ACT_CLASSIFY`) decoupled from user-facing screen labels (`Classify` vs. `Risk Screen`), governed by a versioned semantic contract that triggers automated change notifications before any label or logging patch reaches production.
3. **Technical-event classification policy:** Enforce a mandatory `event_layer` attribute (`business`, `technical`, `audit`) on every emitted event so gateway and infrastructure telemetry such as `Queue Routed` are stored for IT diagnostics but excluded by default from business-level conformance views.
4. **Timestamp provenance and dual-ordering standards:** Record explicit timestamp semantics (`source_event_ts`, `warehouse_ingestion_ts`) alongside monotonic `source_seq_num` for every event, and mandate that conformance pipelines sort by source-system time and sequence number while flagging warehouse-ingestion fallback as a data-quality failure.
5. **Data-aware conformance constraints:** Prohibit using unguarded optional control-flow branches to represent conditional regulatory mandates; encode attribute-conditioned rules (such as `claim_value > EUR 50,000 => Supervisor Sign-off`) using guarded data-aware Petri nets, stratified models, or declarative rules evaluated jointly for fitness and precision.
6. **Post-release conformance validation gates:** Require a mandatory pre- and post-release log-diff and shadow conformance check (tracking variant drift, event-volume shift, missing-resource %, and unmapped-label counts) within 72 hours of any UI, gateway, ETL, or policy release before conformance KPIs are published to Compliance or Operations.
