### **1. Interaction-Graph Description**
The system’s object-centric dependencies form a **multi-layered, asynchronous coordination network** where jobs are indirectly coupled through shared resources, policy constraints, and event synchronization. Key node types and edge qualifiers:

#### **Node Types**
- **Jobs (J1–J6)**: End-to-end processes with discrete stages.
- **Components (C1–C6)**: Physical artifacts consumed/produced by jobs.
- **ComponentLots (L7, L8)**: Groups of components with release synchronization.
- **Machines (CNC-2, OVEN-1, TEST-1)**: Physical processors with capacity limits.
- **Tools (FIX-A, RACK-7, CAL-3)**: Shared fixtures with capacity or calibration constraints.
- **Batches (B1, B2)**: Logical groupings of jobs requiring shared racking (RACK-7).
- **Shipments (S1–S3)**: Consolidation groups delaying early-ready jobs.

#### **Edge Types and Qualifiers**
| Edge Type               | Qualifier          | Direction       | Observed? | Inferred? |
|-------------------------|--------------------|-----------------|-----------|-----------|
| **Job  Component**     | `requires`         | Source  Target | Yes       | No        |
| **Batch  Job**         | `batches`          | Source  Target | Yes       | No        |
| **ComponentLot  Job**  | `contains`         | Source  Target | Yes       | Yes*     |
| **Machine  Job**       | `uses`             | Source  Target | Yes       | No        |
| **Tool  Job**          | `acquires`         | Source  Target | Yes       | Yes*     |
| **Shipment  Job**      | `consolidates`     | Source  Target | Yes       | No        |
| **Batch  Machine**     | `loads`            | Source  Target | Yes       | No        |
| **Tool  Batch**        | `shared`           | Source  Target | Yes       | No        |
| **ComponentLot  Release** | `quarantine`/`release` | Source  Target | Yes       | Yes*     |

*Inferred via event chaining (e.g., `quarantine`  `release`  job completion).

#### **Higher-Order Motifs**
1. **Batch-Job-Tool Coupling**
   - *Example*: B1 (J1, J2, J3)  OVEN-1 (loads batch)  RACK-7 (shared tool)  FIX-A (contention for J4).
   - *Temporal precedence*: Batch start  Tool contention  Job processing.
   - *Policy*: RACK-7 cleaning/quarantine delays B2 (J4, J5).

2. **ComponentLot-Job-Shipment Triad**
   - *Example*: L7 (C2, C5)  J2/J5  S3 (consolidates J5, J6).
   - *Causal chain*: Lot release  Job readiness  Shipment dispatch delay.

3. **Tool-Machine-Job Chain**
   - *Example*: FIX-A  CNC-2  J4.
   - *Contention*: J3 holds FIX-A (09:00–11:40), blocking J4’s CNC-2 process (11:45).

### **4. What Flattenings Miss**
#### **Job-Flattened DFG**
- **Visible**: Job stages (e.g., `Release  Machine Process`).
- **Hidden**: Batch synchronization (e.g., J1–J3 waiting for B1).
- **Misleading**: Per-job cycle times ignore cross-job delays (e.g., J1’s 1.8 above mean is misleading if J1 waits 3h55m).

#### **Machine-Flattened Summary**
- **Visible**: Machine idle gaps (e.g., OVEN-1 12:55–14:50).
- **Hidden**: Tool contention (e.g., FIX-A blocking J4) or batch-level delays.
- **Misleading**: Utilization (44%) does not account for RACK-7 cleaning delays.

#### **Batch-Flattened View**
- **Visible**: Batch start/end times.
- **Hidden**: Tool/tool-lot interactions (e.g., RACK-7 cleaning).
- **Misleading**: Batch duration alone does not reflect job-level synchronization.

#### **Shipment-Flattened DFG**
- **Visible**: Shipment consolidation steps.
- **Hidden**: Per-job waiting (e.g., J1 packed at 13:30 but dispatches at 19:25).
- **Misleading**: Consolidation metrics ignore early-ready jobs.

#### **Tool-Flattened View**
- **Visible**: Tool acquisition/release.
- **Hidden**: Lot/tool interactions (e.g., L7’s quarantine affecting J2/J5).
- **Misleading**: No explicit `Wait for Tool` event in Job-flattening.

#### **ComponentLot-Flattened View**
- **Visible**: Lot release/quarantine events.
- **Hidden**: Job-specific impacts (e.g., J2/J5 delays from L7).
- **Misleading**: Lot events are inconsistently linked to jobs.

#### **Why Low Machine Utilization Coexists with Long Waits**
- **Example**: OVEN-1 is idle 12:55–14:50 (73m) but processes B1 (J1–J3) and B2 (J4–J5) sequentially.
- **Root Cause**: **Asynchronous synchronization** (e.g., RACK-7 cleaning) and **policy-driven delays** (e.g., shipment consolidation) mask machine-level bottlenecks.

### **5. Object-Lifecycle Narratives**
#### **Narrative 1: Batch B1 and RACK-7 Contention**
1. **Temporal**: B1 starts at 12:05; RACK-7 cleaning begins at 10:20 (pre-B1).
2. **Resource**: RACK-7 is shared by B1 and B2; cleaning delays B2 (14:50 start).
3. **Policy**: No explicit rule forces B1 to wait for RACK-7, but cleaning is unplanned.
4. **Causal**: J1–J3 wait 3h55m–3h40m due to RACK-7’s cleaning/quarantine (10:20–14:35).

2. **Resource**: FIX-A is held until 11:40; CNC-2 is idle 10:05–10:47.
3. **Policy**: No tool reservation system; contention arises from job sequencing.
4. **Causal**: J4’s CNC-2 process starts at 11:45 (15m after FIX-A release).

#### **Narrative 3: ComponentLot L7 and Shipment S3**
1. **Temporal**: L7 quarantined at 10:20; released at 13:50.
2. **Resource**: C2/C5 for J2/J5 cannot release until L7 is cleared.
3. **Policy**: Shipment S3 consolidates J5/J6; J5 waits until L7 is released.
4. **Causal**: J5’s test starts at 16:10 (after L7 release at 13:50 + 2h20m).

### **8. Falsification and Additional Data**
#### **Falsification Observations**
1. **Lot Events Are Not Always Job-Centric**: If L7’s quarantine/release affects J2/J5 but is not linked to them in the Job-flattening, the ComponentLot coupling may be overstated.
2. **Tool Contention Is Inferred**: Without explicit `Wait for Tool` events, FIX-A’s impact is speculative.
3. **Shipment Consolidation Metrics Are Incomplete**: S1/S2/S3 delays may include per-job packing times, not just consolidation.
4. **Machine Idle Gaps Do Not Imply Bottlenecks**: OVEN-1’s 73m gap (12:55–14:50) could be due to maintenance, not synchronization.
5. **Batch Duration  Job Delay**: B1’s 3h55m wait is not captured in machine utilization.
6. **Calibration Tool CAL-3 Is Rare**: Only J5/J6 are affected; no evidence of systemic calibration delays.

#### **Additional Data Fields Needed**
1. **`Wait for Lot` Event**: Explicitly track when jobs wait for component-lot release.
2. **Tool Contention Timestamps**: Log `Tool Acquire`/`Release` with job IDs.
3. **Shipment Packing Times**: Record per-job packing duration before consolidation.
4. **Rack Cleaning Schedule**: Log RACK-7 maintenance intervals.
5. **Machine Setup Times**: Distinguish between machine process and setup delays.
6. **ComponentLot Usage History**: Track which lots are quarantined and by whom.
