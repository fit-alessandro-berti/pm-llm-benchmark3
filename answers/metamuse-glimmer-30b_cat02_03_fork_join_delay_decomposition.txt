# 1. Delay-decomposition definitions

For case $c$ and branch $i\in\{A,B,C\}$

* $upstream\_elapsed_c = fork\_release_c - arrival_c$
* $queue_{i,c}= start_{i,c}-fork\_release_c\ge 0$
  Branch can start after fork_release because of its own queue.
* $service_{i,c}= end_{i,c}-start_{i,c}$
* $join\_ready_c = \max_i end_{i,c}$ 
  join_ready is not logged, under the stated rule it is the latest branch completion.
* $sync\_wait_{i,c}= join\_ready_c - end_{i,c}\ge 0$
  A completed branch may wait for synchronization.
* $fork\_join\_elapsed_c = join\_ready_c - fork\_release_c = \max_i \big(queue_{i,c}+service_{i,c}\big)$
* $downstream\_queue_c = final\_start_c - join\_ready_c$
  $final\_start - join\_ready$ is downstream queueing if model assumptions hold.
* $final\_service_c = final\_end_c - final\_start_c$
* $total\_flow_c = final\_end_c - arrival_c$
  $total\_flow_c = upstream\_elapsed_c + fork\_join\_elapsed_c + downstream\_queue_c + final\_service_c$

Summing synchronization waits double counts elapsed time. 
$\sum_i sync\_wait_{i,c}=3\,join\_ready_c-\sum_i end_{i,c}$ 
whereas the elapsed fork-join stage is $join\_ready_c-fork\_release_c$. 
Only the critical branch determines the stage length; the other branches contribute waiting that is not additive.

Assumption: $queue_{i,c}\ge0$ and downstream queue is pure waiting, not a release policy.

df['downstream_queue'] = df.apply(lambda r: mins(r.join_ready, r.final_start), axis=1)
df['final_service'] = df.apply(lambda r: mins(r.final_start, r.final_end), axis=1)
df['total_flow_time'] = df.apply(lambda r: mins(r.arrival, r.final_end), axis=1)

# ---- counterfactuals ----
# 1 A service -20%
df['A_service_cf1'] = df['A_service']*0.8
df['A_end_cf1'] = df['A_start'] + pd.to_timedelta(df['A_service_cf1'], unit='m')
ends_cf1 = ends.copy()
ends_cf1['A'] = df['A_end_cf1']
df['join_ready_cf1'] = ends_cf1.max(axis=1)
df['save_cf1'] = df.apply(lambda r: mins(r.join_ready, r.join_ready_cf1) if r.join_ready_cf1<r.join_ready else 0, axis=1)

# 2 B queue -50%
df['B_queue_cf2'] = df['B_queue']*0.5
df['B_start_cf2'] = df['fork_release'] + pd.to_timedelta(df['B_queue_cf2'], unit='m')
df['B_end_cf2'] = df['B_start_cf2'] + pd.to_timedelta(df['B_service'], unit='m')
ends_cf2 = ends.copy()
ends_cf2['B'] = df['B_end_cf2']
df['join_ready_cf2'] = ends_cf2.max(axis=1)
df['save_cf2'] = df.apply(lambda r: mins(r.join_ready, r.join_ready_cf2) if r.join_ready_cf2<r.join_ready else 0, axis=1)

# 3 downstream queue elimination
df['save_cf3'] = df['downstream_queue']

print(df[['case','upstream_elapsed','A_queue','A_service','B_queue','B_service','C_queue','C_service','join_ready','critical_branch','downstream_queue','final_service','total_flow_time']])

log_rows=[]

# 7. Limits of inference

* Causality cannot be identified from timestamps alone; queue delays may reflect resource capacity, priority policy or arrival burstiness.
* Branch resource capacity, number of parallel servers, and work preemption are not logged.
* Whether final-station waiting is a true FIFO queue or a release policy / batching rule cannot be distinguished from final_start - join_ready.
* Service times are observed, not independent of queue; a reduction in service may change queue dynamics.
* Only 12 cases on one day; tail estimates and generalisation are bounds, not population values.
* Ties in max end are resolved deterministically here; real process may have simultaneous completion ambiguity.
* No information on rework, interruptions, or data quality beyond one-minute granularity.

These limits imply recommendations are hypotheses to be piloted with additional logging of resource utilisation and queue policies.
