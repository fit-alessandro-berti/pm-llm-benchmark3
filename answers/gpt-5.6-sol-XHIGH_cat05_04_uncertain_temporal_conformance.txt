## 1. Normalization Assumptions

- All intervals below are conservative closed intervals. A floor-to-minute endpoint shown as `59.999` follows the supplied semantics. Open/closed tie behavior for rounded timestamps does not materially change any classification.
- For a recorded-clock interval \(R=[r_l,r_u]\) and offset bound \(O=[o_l,o_u]\), with `offset = recorded  true`:
  \[
  T=[r_l-o_u,\ r_u-o_l].
  \]
  Resolution uncertainty is applied before clock correction.
- Time-zone conversion is applied using the stated offset in effect:
  - CEST/BST: UTC+2/UTC+1 respectively.
  - EDT: UTC4.
  - The Berlin fallback on 2025-10-26 is represented with both folds before applying the sequence constraint.
- No probability distribution is assumed inside an interval. Event endpoints are treated as independently feasible unless a stated duration, fold, or causal constraint couples them. Consequently, same-source duration intervals are conservative; event-level evidence that the same clock offset persisted would sometimes narrow them.
- Activity-pair durations use eventually-following semantics and are constrained to be nonnegative. If the raw timestamp bounds permit a negative duration but also permit correct order, only ordered combinations are retained.
- The primary temporal-profile classification in Section 3 uses `zeta = 2`. SLA classifications there use no added tolerance. Section 4 gives other choices.
- SLA acceptance regions are `[0, maximum]`. Profile bands are inclusive and two-sided.
- `CERTAIN_PASS` means every feasible duration is accepted. `CERTAIN_VIOLATION` means every feasible duration is outside the acceptance region. Mixed outcomes are `POSSIBLE_VIOLATION`.
- T-404: `Investigation_Start` is inferred as `Investigation_Complete  duration`, preserving the full signed duration range `[18,25]` minutes and completion timestamp uncertainty.
- T-405: before sequence constraints, every event has two DST-fold alternatives. Treating the stated ingestion sequence as evidence of actual lifecycle order leaves only:
  - alert in the first/CEST fold;
  - investigation and containment in the second/CET fold.
  If ingestion order were merely database arrival order, T-405 would instead be indeterminate because some alternatives imply reversed occurrence order.
- T-406 primary interpretation: the displayed mobile timestamp is the entry/submission time, and the occurrence may have preceded it by `[0,5]` minutes. Thus the delay shifts only the lower occurrence bound earlier. Alternative interpretation: the field records the user’s claimed occurrence time and was merely submitted late; then the delay affects record/ingestion time but not the occurrence interval.
- T-407: delivery latency provides a conditional receipt interval only if delivery actually occurred. The lack of acknowledgment means `Alert_Received` is not established. Conditional calculations also impose the plausible, but unlogged, constraint `Alert_Received  Investigation_Start`; unconditional alert-dependent results remain `INDETERMINATE`.
- Severity describes operational importance, not statistical confidence. Profile deviations are advisory and do not themselves establish an SLA breach.

- T-408’s S2 and S3 breaches are much larger than five minutes and remain certain.

def resolution_bounds(recorded_value, semantics):
    """Return naive local recorded-clock bounds before clock correction."""
    t = pd.Timestamp(recorded_value)

    if semantics == "exact_second":
        return (
            t - pd.Timedelta(milliseconds=500),
            t + pd.Timedelta(milliseconds=500),
        )
    if semantics == "floor_minute":
        return t, t + pd.Timedelta(seconds=59, milliseconds=999)
    if semantics == "nearest_10_seconds":
        return t - pd.Timedelta(seconds=5), t + pd.Timedelta(seconds=5)
    if semantics == "nearest_minute":
        return t - pd.Timedelta(seconds=30), t + pd.Timedelta(seconds=30)

    raise ValueError(f"Unknown resolution semantics: {semantics}")


def local_naive_to_utc(naive_timestamp, zone_name, fold=0):
    """
    Attach a standard-library ZoneInfo timezone and explicitly set fold.
    fold=0 is the earlier DST occurrence; fold=1 is the later occurrence.
    """
    py_dt = naive_timestamp.to_pydatetime().replace(
        tzinfo=ZoneInfo(zone_name), fold=fold
    )
    return pd.Timestamp(py_dt.astimezone(timezone.utc))


def normalize_row(row, offset_override=None, folds=(0,)):
    """
    Apply resolution first and then:
        true = recorded - offset
    Offset is recorded_clock - true_clock.
    """
    spec = SYSTEMS[row["system"]]
    offset_low, offset_high = (
        offset_override if offset_override is not None else spec["offset"]
    )
    recorded_low, recorded_high = resolution_bounds(
        row["recorded_value"], spec["resolution"]
    )

    true_wall_low = recorded_low - pd.Timedelta(seconds=offset_high)
    true_wall_high = recorded_high - pd.Timedelta(seconds=offset_low)

    alternatives = []
    for fold in folds:
        alternatives.append({
            "fold": fold,
            "lo": local_naive_to_utc(true_wall_low, spec["tz"], fold),
            "hi": local_naive_to_utc(true_wall_high, spec["tz"], fold),
        })
    return alternatives

def ordered_values_exist(intervals):
    """Whether x0 <= x1 <= ... can be selected from the listed intervals."""
    selected = intervals[0][0]
    if selected > intervals[0][1]:
        return False
    for lo, hi in intervals[1:]:

    return True

def merge_numeric_intervals(intervals):
    if not intervals:
        return []
    intervals = sorted(intervals)
    merged = [list(intervals[0])]
    for lo, hi in intervals[1:]:
        if lo <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], hi)
        else:
            merged.append([lo, hi])
    return [tuple(x) for x in merged]


def duration_intervals(case, activity_a, activity_b, causal=True):
    """Cartesian interval difference, preserving disjoint duration ranges."""
    a_intervals = event_intervals.get((case, activity_a), [])
    b_intervals = event_intervals.get((case, activity_b), [])
    result = []

    for a_lo, a_hi in a_intervals:
        for b_lo, b_hi in b_intervals:
            lo = (b_lo - a_hi).total_seconds()
            hi = (b_hi - a_lo).total_seconds()

            if causal:
                if hi < 0:
                    continue
                lo = max(0.0, lo)

            result.append((lo, hi))

    return merge_numeric_intervals(result)

def classify_interval_union(intervals, acceptance_low, acceptance_high,
                            indeterminate=False):
    if indeterminate or not intervals:
        return "INDETERMINATE"

    all_inside = all(
        lo >= acceptance_low and hi <= acceptance_high
        for lo, hi in intervals
    )
    if all_inside:
        return "CERTAIN_PASS"

    all_outside = all(
        hi < acceptance_low or lo > acceptance_high
        for lo, hi in intervals
    )
    if all_outside:
        return "CERTAIN_VIOLATION"

    return "POSSIBLE_VIOLATION"

## 7. Governance Recommendation

1. **Store normalized UTC and the original evidence**
   - Persist an authoritative UTC timestamp where available.
   - Retain the original timestamp string, source time zone, numeric UTC offset, locale, and source-system identifier.
   - Never overwrite the raw timestamp during correction.

2. **Store uncertainty explicitly**
   - Record timestamp resolution and semantics: exact, floor, ceiling, nearest-unit rounding, or user-entered.
   - Persist lower and upper event-time bounds rather than only a corrected point.
   - Preserve disjoint alternatives for unresolved DST folds or other multimodal evidence.

3. **Capture clock telemetry**
   - Store event-level or tightly time-bounded NTP offset, uncertainty, stratum, last synchronization time, drift, and synchronization health.
   - Do not substitute a daily bound when hour-specific telemetry exists.
   - Flag periods with missing NTP diagnostics, as in T-409, instead of silently applying the normal bound.

4. **Make time-zone provenance durable**
   - Store the IANA zone name, UTC offset used at capture, time-zone database version, and DST `fold`.
   - Reject or quarantine ambiguous local times unless the fold or offset is provided.
   - For legacy imports, retain all alternatives until independent sequence or offset evidence resolves them.

5. **Define lifecycle semantics**
   - Distinguish `start`, `complete`, `sent`, `delivered`, `received`, `acknowledged`, `entered`, and `submitted`.
   - A completion event must not be silently treated as a start.
   - Derived starts such as T-404 should carry a derivation rule, source document identifier, signer, duration interval, and provenance flag.

6. **Control mobile and user-entered timestamps**
   - Store occurrence time separately from entry/submission time.
   - Record whether a field is device-generated or user-asserted.
   - Capture device offset telemetry when possible and retain server receipt time.
   - Define whether reported entry delay changes the estimated occurrence time; do not leave this to case-by-case inference.

7. **Require causal identifiers**
   - Link sent, delivered, received, investigation, containment, and closure events with immutable incident and message identifiers.
   - Sequence numbers should distinguish event occurrence order from ingestion order.
   - Delivery telemetry should state whether a latency bound is conditional on successful delivery.

8. **Adopt an interval-aware enforcement policy**
   - For legal or disciplinary SLA enforcement, automatically assert a breach only for `CERTAIN_VIOLATION`.
   - Treat `POSSIBLE_VIOLATION` as requiring evidence review, not automatically as either pass or breach.
   - Interval overlap with the passing region should not be treated as conclusive compliance, and overlap with the violating region should not by itself establish a legal breach.
   - `INDETERMINATE` should trigger an evidentiary-control finding rather than an SLA conclusion.
   - Statistical temporal-profile deviations should remain advisory unless governance explicitly converts them into operational thresholds.

9. **Keep point analytics secondary**
   - Midpoints may be used for visualization or compatibility with point-based tools such as PM4Py, but logs and dashboards must label them as lossy approximations.
   - Enforcement, audit, and root-cause analysis should use the retained intervals, unions, causal constraints, and provenance.
