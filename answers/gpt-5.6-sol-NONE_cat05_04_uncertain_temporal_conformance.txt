## 1. Normalization Assumptions

- All intervals are closed for classification. Display-semantic half-open upper bounds are conservatively represented at microsecond precision.
- If source-clock time is \(C\), resolution interval is \([C_l,C_u]\), and `clock_offset = recorded_clock - true_clock` lies in \([a,b]\), then true time is:
  \[
  [C_l-b,\ C_u-a].
  \]
- HUB timestamps have measurement uncertainty ±0.5 s and clock offset \([-1,+1]\) s, yielding ±1.5 s total.
- Floor-to-minute timestamps initially represent `[displayed minute, next minute)`.
- Nearest-10-second SENSOR timestamps represent ±5 s before clock correction.
- Nearest-minute MOBILE-LON timestamps represent ±30 s before clock correction.
- CEST and BST are UTC+2 and UTC+1, respectively; EDT is UTC4.
- Duration \(B-A\), for event intervals \(A=[A_l,A_u]\), \(B=[B_l,B_u]\), is \([B_l-A_u,\ B_u-A_l]\). For unions, each causally feasible interval pairing is retained.
- Normal event order is imposed for eventually-following pairs: duration must be nonnegative. This matters chiefly for T-405. Recorded ingestion order is additionally enforced there.
- T-404 Investigation_Start is inferred from Investigation_Complete minus the signed duration `[18,25]` minutes. This retains both completion timestamp and duration uncertainty.
- T-405 has two Berlin folds: CEST/UTC+2 and CET/UTC+1. Ingestion order eliminates fold combinations that imply decreasing true event time, but does not remove within-minute uncertainty. Pairwise durations are therefore unions.
- T-406 primary interpretation: the mobile value is a late record of an earlier occurrence, so entry delay \(D\in[0,5]\) minutes is subtracted in addition to resolution and clock correction. If delay affects only record creation and the entered value denotes the actual occurrence time, do not subtract it; that sensitivity is stated below.
- T-407 Alert_Received is not replaced by Alert_Sent. For a conditional analysis, delivery latency `[0,20]` minutes bounds receipt after sending, and the plausible causal constraint `receipt <= Investigation_Start` is imposed. Without that semantic assumption, S1 and alert-based profile tests are **INDETERMINATE**.
- T-409 uses the hour-specific weak offset estimate `[-12,+12]` minutes instead of the normal OPS-BER diagnostic bound.
- SLA acceptance regions are one-sided `[0, maximum+tolerance]`; negative durations are excluded by causal semantics.
- Profile acceptance regions are two-sided \([\max(0,\mu-\zeta\sigma),\mu+\zeta\sigma]\). Section 3 uses `zeta = 2` as the primary profile setting.
- Severity labels: **Critical** for certain SLA violation, **High** for possible SLA violation, **Moderate** for profile-only deviations, and **Informational** for pass.

def corrected(clock_lo, clock_hi, off_lo_s, off_hi_s):
    # true = recorded clock - offset
    return (clock_lo - timedelta(seconds=off_hi_s),
            clock_hi - timedelta(seconds=off_lo_s))

def normalize(row):
    n = parse_local(row.recorded)
    system = row.system
    activity = row["concept:name"]

    if system == "HUB":
        c = n.replace(tzinfo=UTC)
        return [(c - timedelta(seconds=.5) - timedelta(seconds=1),
                 c + timedelta(seconds=.5) - timedelta(seconds=-1))]

    if system == "OPS-BER":
        c0 = local_to_utc(n, "Europe/Berlin")
        # floor minute: [minute, next minute)
        return [corrected(c0, c0 + timedelta(minutes=1) - EPS, -90, 120)]

    if system == "OPS-BER-WEAK":
        c0 = local_to_utc(n, "Europe/Berlin")
        return [corrected(c0, c0 + timedelta(minutes=1) - EPS, -720, 720)]

    if system == "SENSOR":
        c = n.replace(tzinfo=UTC)
        return [corrected(c - timedelta(seconds=5),
                          c + timedelta(seconds=5), -5, 5)]

    if system == "VENDOR-NY":
        c0 = local_to_utc(n, "America/New_York")
        return [corrected(c0, c0 + timedelta(minutes=1) - EPS, -180, 180)]

    if system == "MOBILE-LON":
        c = local_to_utc(n, "Europe/London")
        # Nearest minute gives +/-30 sec; offset is +/-300 sec.
        lo, hi = corrected(c - timedelta(seconds=30),
                           c + timedelta(seconds=30), -300, 300)
        # Primary semantics: entry occurred 0..5 min after occurrence.
        return [(lo - timedelta(minutes=5), hi)]

    if system == "LEGACY-BER":
        out = []
        for fold in (0, 1):
            c0 = local_to_utc(n, "Europe/Berlin", fold=fold)
            out.append(corrected(c0, c0 + timedelta(minutes=1) - EPS,
                                 -60, 60))
        return out
    raise ValueError(system)

events = {}
for _, r in raw.iterrows():
    events[(r["case:concept:name"], r["concept:name"])] = normalize(r)

# T-404 inferred start = completion interval minus [18,25] minutes.
ic = events[("T-404", "Investigation_Complete")][0]
events[("T-404", "Investigation_Start")] = [
    (ic[0] - timedelta(minutes=25), ic[1] - timedelta(minutes=18))
]

# T-407 conditional inferred receipt: sent + latency [0,20m], intersected
# with a conservative upper bound from Investigation_Start.
sent = events[("T-407", "Alert_Sent")][0]
start407 = events[("T-407", "Investigation_Start")][0]
receipt = (sent[0], min(sent[1] + timedelta(minutes=20), start407[1]))
events[("T-407", "Alert_Received")] = [receipt]

def intersect_interval(x, y):
    lo, hi = max(x[0], y[0]), min(x[1], y[1])
    return (lo, hi) if lo <= hi else None

def duration_union(case, a, b, enforce_order=True):
    """Cartesian alternatives; returns duration intervals in seconds."""
    out = []
    for ai, bi in itertools.product(events[(case, a)], events[(case, b)]):
        lo = (bi[0] - ai[1]).total_seconds()
        hi = (bi[1] - ai[0]).total_seconds()
        if enforce_order:
            lo = max(0.0, lo)
        if hi >= lo:
            out.append((lo, hi))
    # Merge only overlapping duration components, preserving gaps.
    out.sort()
    merged = []
    for x in out:
        if not merged or x[0] > merged[-1][1]:
            merged.append(list(x))
        else:
            merged[-1][1] = max(merged[-1][1], x[1])
    return [tuple(x) for x in merged]

def classify(intervals, acceptance):
    if not intervals:
        return "INDETERMINATE"
    al, ah = acceptance
    wholly_inside = all(lo >= al and hi <= ah for lo, hi in intervals)
    wholly_outside = all(hi < al or lo > ah for lo, hi in intervals)
    if wholly_inside:
        return "CERTAIN_PASS"
    if wholly_outside:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

profiles = {
    ("Alert_Received","Investigation_Start"): (600,180),
    ("Investigation_Start","Containment_Complete"): (2100,600),
    ("Alert_Received","Containment_Complete"): (2700,720),
    ("Containment_Complete","Close_Incident"): (86400,21600),
}
slas = {
    ("Alert_Received","Investigation_Start"): 900,
    ("Investigation_Start","Containment_Complete"): 2700,
    ("Containment_Complete","Close_Incident"): 129600,
}

interval_results = []
cases = sorted(raw["case:concept:name"].unique())
for case in cases:
    for pair, limit in slas.items():
        if (case, pair[0]) in events and (case, pair[1]) in events:
            d = duration_union(case, *pair)
            interval_results.append(
                (case, "SLA", pair, d, classify(d, (0, limit)))
            )
    for pair, (mean, sd) in profiles.items():
        if (case, pair[0]) in events and (case, pair[1]) in events:
            d = duration_union(case, *pair)
            for zeta in (1, 2, 3):
                band = (max(0, mean-zeta*sd), mean+zeta*sd)
                interval_results.append(
                    (case, f"profile_zeta_{zeta}", pair, d,
                     classify(d, band))
                )

interval_df = pd.DataFrame(
    interval_results,
    columns=["case","test","pair","duration_intervals_s","interval_class"]
)
print(interval_df.to_string(index=False))

# ---------------------------------------------------------------------
# Midpoint-only log: explicitly LOSSY; alternatives are collapsed.
# This is diagnostic only and is not used for interval conclusions.
# ---------------------------------------------------------------------
mid_rows = []
for (case, activity), alternatives in events.items():
    all_lows = [x[0] for x in alternatives]
    all_highs = [x[1] for x in alternatives]
    # For a union, midpoint of the overall envelope can lie in a gap.
    # That fact itself illustrates why this representation is lossy.
    midpoint = min(all_lows) + (max(all_highs) - min(all_lows)) / 2
    mid_rows.append({
        "case:concept:name": case,
        "concept:name": activity,
        "time:timestamp": pd.Timestamp(midpoint),
        "uncertainty_note": "LOSSY midpoint-only approximation"
    })

mid_df = pd.DataFrame(mid_rows).sort_values(
    ["case:concept:name", "time:timestamp"]
)
mid_df = pm4py.format_dataframe(
    mid_df,
    case_id="case:concept:name",
    activity_key="concept:name",
    timestamp_key="time:timestamp"
)

# PM4Py versions differ in accepted temporal-profile representation.
# The common representation is {(activity_a, activity_b): (mean, std)}.
temporal_profile = profiles
pm_diagnostics = {}
for zeta in (1, 2, 3):
    try:
        pm_diagnostics[zeta] = pm4py.conformance_temporal_profile(
            mid_df, temporal_profile, zeta=zeta
        )
    except TypeError:
        # Some versions expose parameters differently.
        pm_diagnostics[zeta] = pm4py.conformance_temporal_profile(
            mid_df, temporal_profile,
            parameters={"zeta": zeta}
        )

for zeta, diag in pm_diagnostics.items():
    print(f"\nPM4Py midpoint-only diagnostics, zeta={zeta}")
    print(diag)

# Comparison is deliberately qualitative because diagnostic dataframe/list
# columns vary by PM4Py version. PM4Py receives only point timestamps and
# therefore cannot natively decide CERTAIN vs POSSIBLE interval violations.
for zeta in (1, 2, 3):
    subset = interval_df[interval_df["test"] == f"profile_zeta_{zeta}"]
    print(f"\nInterval conclusions, zeta={zeta}")
    print(subset[["case","pair","duration_intervals_s",
                  "interval_class"]].to_string(index=False))

The PM4Py call is intentionally isolated because some releases return a list of deviations while others return a dataframe-like object, and some use a parameter dictionary rather than a named `zeta` argument. In all versions, the midpoint log is a lossy auxiliary diagnostic, not an uncertainty-aware conformance result.

## 6. Evidential Sufficiency

Minimum evidence needed for each possible or indeterminate family:

| Case/result | Minimum evidence needed to make the conclusion certain |
|---|---|
| T-401 S1 and AlertStart profile | Event-level OPS synchronization reducing the start upper bound below 08:15:00Z for pass, or lower bound above the applicable threshold for violation; second-resolution start evidence would suffice. |
| T-402 S2 | A synchronized start or containment bound proving duration 45m or >45m. T-402 S1 is already certainly violated at zero tolerance. |
| T-402 AlertStart profile | Tighter OPS offset/resolution establishing duration wholly 16m or wholly >16m. |
| T-403 S1/profile | Vendor receipt timestamp with event-level NTP/offset telemetry, or a HUB-side correlated alert identifier recording receipt. |
| T-404 S1/profile | Direct Investigation_Start evidence, or a narrower signed investigation-duration bound. To prove S1 pass, duration from completion must place start no later than 10:15Z; to prove violation, strictly later. |
| T-404 S2 | Direct start timestamp or slightly tighter duration/clock evidence; the current ambiguity is only about three seconds over 45m. |
| T-405 S1 | Logged DST fold for alert and start plus tighter minute/offset evidence if the resulting interval still crosses 15m. |
| T-405 S2 and profile pairs | Fold bits for all three events are the minimum decisive semantic evidence. For StartContainment, knowing containment is in the first or second fold relative to start removes the 60-minute alternative. For AlertContainment, complete fold assignment removes the near-zero versus 48–56m ambiguity. |
| T-406 S1/S2/profile AlertStart | Semantic declaration whether entered time denotes occurrence or entry; then device clock synchronization and a narrower entry-delay audit trail. S2 becomes certain pass under the “record-time only” interpretation. |
| T-407 alert-based tests | Actual Alert_Received acknowledgment carrying the same causal alert identifier. Short of that, a binding rule that investigation cannot start before receipt converts indeterminate tests into bounded possible tests, but does not necessarily make pass/violation certain. |
| T-408 StartContainment profile at =1/2 | Sub-second or authoritative timestamps showing the duration wholly on one side of the 45m/55m statistical boundary. SLA S2 and S3 are already certain violations. |
| T-409 S1/profile | Restore hour-specific NTP diagnostics or correlate the start with a synchronized server-side action. The weak ±12m estimate is the dominant uncertainty. |

For a **POSSIBLE_VIOLATION**, “making it certain” can mean either certain pass or certain violation; evidence must move the entire feasible duration set to one side of the threshold. For T-407 without causal semantics, the deficiency is not merely clock precision—it is missing activity and semantic evidence.

## 7. Governance Recommendation

1. **Store UTC event time and original representation**
   - Persist an authoritative UTC timestamp when available.
   - Retain the raw local string, source time-zone identifier, numeric UTC offset, and conversion version.
   - Never overwrite raw evidence during normalization.

2. **Retain explicit uncertainty**
   - Store lower and upper UTC bounds, not only a corrected point.
   - Record timestamp resolution and semantics: exact, floor, ceiling, or nearest-unit rounding.
   - Preserve disjoint alternatives for DST folds and other ambiguity rather than storing only their envelope or midpoint.

3. **Clock provenance and synchronization**
   - Capture event-level or near-event NTP/PTP offset, uncertainty, stratum, last synchronization time, and diagnostic status.
   - Distinguish measured offset bounds from weak engineering estimates.
   - Alert when synchronization telemetry is missing, as in T-409.

4. **Time-zone and DST controls**
   - Store IANA zone names and the UTC offset actually used.
   - Persist the PEP 495-style DST `fold` value for ambiguous local times.
   - Reject or quarantine ambiguous local timestamps lacking fold metadata in SLA-sensitive workflows.

5. **Lifecycle semantics**
   - Use explicit activities such as `Investigation_Start` and `Investigation_Complete`; do not infer one from the other unless a separately signed duration record is retained.
   - Store lifecycle transition (`start`, `complete`, `suspend`, `resume`) independently from activity name.
   - Document whether device events denote initiation, observation, transmission, or completion.

6. **Mobile and manual-entry controls**
   - Store occurrence time, entry time, and synchronization time as separate fields.
   - Record whether a user entered “when it happened” or whether the application automatically timestamped submission.
   - Avoid folding entry delay into clock error; they represent different mechanisms.

7. **Causal identity**
   - Assign immutable incident, alert, delivery, acknowledgment, investigation, and containment identifiers.
   - Link Alert_Sent and Alert_Received with a delivery ID rather than assuming equivalence.
   - Record ingestion sequence separately from event-time order.

8. **Enforcement policy**
   - For legal SLA enforcement, interval overlap with the violation region should not automatically be called a proven breach. Label it **POSSIBLE_VIOLATION**, preserve evidence, and seek stronger synchronization or activity proof.
   - A breach should be enforced automatically only when the entire feasible duration set exceeds the limit, unless the governing contract explicitly allocates uncertainty risk differently.
   - Conversely, certify compliance only when the entire feasible set is within the limit.
   - Statistical temporal-profile deviations should remain operational diagnostics and must not be substituted for SLA findings.

9. **Audit and reproducibility**
   - Version normalization rules, time-zone databases, profile parameters, tolerance policies, and causal assumptions.
   - Retain both interval-based results and any midpoint diagnostics, clearly labeling midpoint results as lossy.
   - Require reports to identify whether conclusions are certain, possible, conditional, or indeterminate.
