# 2. Core versus peripheral activities

Core activities are defined by the primary responsibility and authority of a resource, often reflected in high frequency for routine roles (e.g., Nora, Amira, Ben) but driven by case complexity and formal authority for specialists (e.g., Erik, Hana). Peripheral activities typically emerge from three sources:
1. **End-to-end case ownership**: Technical Analysts (Chen, Dina) occasionally perform A12 (Close Request) to finish their own cases rather than handing them back to the front office.
2. **Temporary substitutions**: Giorgio performing A7 (Pricing) and Mateo performing A9 (Supervisor Approval) are peripheral activities that emerge when primary owners are absent or overloaded.
3. **Cross-functional handovers**: Mateo's broad activity profile reflects his role in coordinating handovers between technical, security, and management teams. 

Organizational authority heavily influences this distinction. While Mateo frequently performs A9 (Supervisor Approval), this is a peripheral activity for him because he lacks formal authority; his work is preliminary and often rechecked by Hana, for whom A9 is a core activity.

# 3. Shadow and bridging roles

- **R07_Giorgio as a commercial shadow role**: Giorgio officially acts as a Senior Service Agent but serves as a shadow commercial specialist. He bridges the gap when Fatima is absent, ensuring pricing exceptions do not completely stall. **Benefits**: Provides critical resilience and prevents bottlenecks. **Risks**: He is less efficient (pricing exception duration doubled from 38 to 74 minutes), indicating that temporary substitution does not equate to permanent competence.
- **R13_Mateo as a cross-functional escalation broker**: Mateo bridges Technical, Security, and Management silos. He filters low-risk security referrals for Erik and performs preliminary approvals for Hana. **Benefits**: Protects rare specialists from noise (false escalations decreased). **Risks**: Ambiguous authority leads to delays (critical cases waited >2 days) and rework (13 approvals rechecked by Hana).
- **R05_Erik as a rare but critical specialist**: Erik handles low-volume but highly critical security reviews. He acts as a bridging role in the sense that his interventions are rare but necessary for high-risk cases across the entire process, requiring Mateo to route work to him carefully.
- **R11_Kai & R12_Lina as temporary-workforce roles**: They act as a low-complexity buffer for the front office. **Benefits**: Absorbs seasonal load. **Risks**: Lower quality work leading to downstream rework (reopens due to incomplete Validate Entitlement notes).

# 5. PM4Py role-discovery and similarity code

```python
import pandas as pd
import pm4py

# 1. Load and format a pandas dataframe
df = pd.read_csv("event_log.csv")
df = pm4py.format_dataframe(
    df, 
    case_id='case:concept:name', 
    activity_key='concept:name', 
    timestamp_key='time:timestamp',
    resource_key='org:resource'
)

# 2. Run pm4py.discover_organizational_roles
# Discovers roles based on activity frequency profiles (naïve clustering)
naive_roles = pm4py.discover_organizational_roles(df)

# 3. Run pm4py.discover_activity_based_resource_similarity
# Computes cosine similarity between resources based on activity execution
similarity_matrix = pm4py.discover_activity_based_resource_similarity(df)

# 4. Compute handover-of-work and working-together networks
hw_network = pm4py.discover_handover_of_work_network(df)
wt_network = pm4py.discover_working_together_network(df)

# 5. Join role-discovery output with case_complexity and temporary_substitution indicators
# Aggregate context attributes per resource
resource_context = df.groupby('org:resource').agg(
    median_complexity=('case_complexity', 'median'),
    substitution_count=('temporary_substitution', 'sum')
).reset_index()

# Map the discovered roles to resources
role_mapping = []
for role_idx, resources in enumerate(naive_roles):
    for res in resources:
        role_mapping.append({'org:resource': res, 'mined_role': f'Role_{role_idx}'})
roles_df = pd.DataFrame(role_mapping)

# Join the naïve roles with the contextual indicators
enriched_roles = pd.merge(roles_df, resource_context, on='org:resource')

# 6. Avoid over-interpreting activity-frequency clusters as formal authority
# Filter the log for high/critical complexity cases to see the "true" expert network
high_complexity_df = pm4py.filter_event_attribute_values(
    df, 
    "case_complexity", 
    ["High", "Critical"], 
    level="case", 
    retain=True
)
expert_hw_network = pm4py.discover_handover_of_work_network(high_complexity_df)
expert_roles = pm4py.discover_organizational_roles(high_complexity_df)
```
