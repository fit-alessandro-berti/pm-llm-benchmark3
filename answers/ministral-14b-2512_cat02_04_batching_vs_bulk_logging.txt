def compute_diagnostics(df):
    diagnostics = []

    # Overlap rate per resource
    for resource in df['resource'].unique():
        res_df = df[df['resource'] == resource]
        if len(res_df) < 2:
            continue
        overlaps = 0
        total_pairs = 0
        for i in range(len(res_df)):
            for j in range(i+1, len(res_df)):
                total_pairs += 1
                start_i, end_i = res_df.iloc[i]['start'], res_df.iloc[i]['complete']
                start_j, end_j = res_df.iloc[j]['start'], res_df.iloc[j]['complete']
                if not (end_i <= start_j or end_j <= start_i):
                    overlaps += 1
        overlap_rate = overlaps / total_pairs if total_pairs > 0 else 0

            'resource': resource,
            'overlap_rate': overlap_rate,
            'num_events': len(res_df)

# 6. Data-collection redesign

**Prioritized Recommendations**:

1. **Execution Timestamps**:
   - **Capture actual start/complete times** with **sub-second precision** (e.g., PLC timestamps for G1, tablet timestamps for G2).
   - **Avoid rounding** (e.g., G7’s 15-min rounding, G6’s hourly rounding).
   - **Log pause/resume events** to distinguish true delays from batching.

2. **Recording Timestamps**:
   - **Decouple `recorded_at` from `complete`** (e.g., G6’s `recorded_at` is 17:01 but `complete` is 17:00).
   - **Log database insertion time separately** to detect bulk submissions.

3. **Source Clocks**:
   - **Synchronize all clocks** (e.g., G8’s repair queue and safety system have different clocks).
   - **Log clock offsets** if synchronization is impossible.

4. **Resource/Badge Identity**:
   - **Replace shared accounts** (e.g., `analyst_pool`) with **individual badges**.
   - **Log operator swaps** if tasks are handed off.

5. **Group/Batch Identifiers**:
   - **Explicitly label batches** (e.g., `batch_id` for G1’s fixture, `folder_id` for G3’s reviews).
   - **Log batch capacity** (e.g., G1’s "4 items on one fixture").

6. **Workstation Capacity**:
   - **Record queue lengths** (e.g., G6’s queue build-up before 17:00).
   - **Log workstation state** (e.g., G1’s PLC occupancy, G2’s inspection screen state).

7. **Timestamp Precision Metadata**:
   - **Document true precision** (e.g., G7’s "15 min" is undocumented; G2’s "1 min" may be exact).
   - **Log timestamp source** (e.g., PLC vs. manual entry).

### **Key Takeaways for Process Mining**
1. **Never assume identical timestamps = simultaneous work** (e.g., G6’s 17:00 `start` timestamps hide 3-hour queue).

3. **Resource identity is critical** (e.g., G5’s `analyst_pool` invalidates batching assumptions).
4. **Timestamp precision metadata is more important than exact values** (e.g., G7’s 15-min rounding invalidates fine-grained analysis).
5. **G6-like data is a red flag for queue analysis**—inflated waiting times and near-zero service times are artifacts of batching.
