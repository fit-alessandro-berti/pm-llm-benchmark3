The shared causal mechanism is straightforward: parallelization creates `true_overlap` only when both verification tasks are ready; overlap then reduces `waiting_before_assessment` and, in turn, `cycle_time`. That mechanism is transportable in principle, but only for cases where both tasks are legally and operationally enabled. Site-specific mechanisms include `originals_required` blocking Document Check, `IT_case_lock` preventing simultaneous ownership, `role_specialization` creating separate queues, and `legal_capacity` governing a downstream review loop. A’s additional improvements from `queue_huddles`, `API_latency`, mix shift, and added FTE are co-interventions, not parallelization mechanisms.

Important effect modifiers are `digital_documents`, `originals_required`, `case_complexity`, `role_specialization`, `IT_case_lock`, and all capacity variables. A similar control-flow diagram does not guarantee transportability because a process tree abstracts away data-dependent guards, resource pools, queueing, system locking, and timestamp reliability. The selection nodes `S_` represent these site-level differences, and they block simple transport of A’s before/after estimates.

## 6. Candidate Site B intervention

**Process specification: segmented verification parallelism**

- Eligibility:
  - Cohort C1: no statutory originals requirement and document image available at registration.
  - Cohort C2: originals required; only Identity Check and Originals Receipt can start concurrently.
  - Cohort C3: public-sector/high-value legal-required cases are included only as a stratified analysis group; legal review is never parallelized.
- Task creation and concurrency:
  - Register always occurs first.
  - For C1, Identity Check and Document Check are both created after Register and may execute concurrently.
  - For C2, Identity Check and Originals Receipt are created after Register; Document Check is created only after Originals Receipt is complete.
  - For C3, the same verification rules apply but Assessment is followed by mandatory Legal Review.
- Statutory prerequisites:
  - Assessment waits for both Identity Check and Document Check to be complete.
  - Document Check waits for Originals Receipt when originals are legally required.
  - Legal Review occurs before final decision for public-sector/high-value cases.
  - Approve/Reject occurs after Assessment, or after Legal Review when required.
- Queue and WIP controls:
  - Default cap: six open verification tasks per reviewer in each role.
  - Release a C1 parallel pair only when at least one identity slot and one document slot are open.
  - For C2, release identity when an identity slot is open; after receipt, release document when a document slot is open.
  - Use a pull scheduler rather than pushing all cases into parallel tasks.
- Resource responsibilities:
  - Keep existing roles: identity reviewers, document reviewers, assessors, legal reviewers.
  - Cross-training is optional and only after the first pilot wave; if introduced, log it as a separate co-intervention.
- Legal-review and supplement loops:
  - Legal Review remains after Assessment.
  - If Legal Review issues Request Supplement, Document Check and Assessment are repeated for the supplemented scope, followed by Legal Review again.
  - Escalate to a supervisor after two supplement requests on the same case.
- Logging requirements:
  - Automatic timestamps for task creation, start, completion, resumption, and case state changes.
  - No manual back-entry.
  - Log case attributes: originals_required, legal_required, complexity, owner, queue entry/exit, open-task count.

**POWL-style partial-order description**

```text
SEQ(
  Register,
  XOR(
    PAR(IdentityCheck, DocumentCheck),                        # C1: no originals required
    PAR(IdentityCheck, SEQ(OriginalsReceipt, DocumentCheck))  # C2: originals required
  ),
  Assessment,
  XOR(
    SEQ(LegalReview, ...),   # legal-required path
    SKIP                     # non-legal path
  ),
  XOR(Approve, Reject),
  Notify
)

Legal supplement loop:
LegalReview -> RequestSupplement
RequestSupplement -> DocumentCheck
DocumentCheck -> Assessment
Assessment -> LegalReview
```

## 7. Pilot for transport learning

| design element | specification | causal purpose | operational safeguard | process-mining measurement |
|---|---|---|---|---|
| Unit of assignment | Cluster-period: work-week block, not individual case | Avoid interference from shared queues and staff | Clear schedule; no case-level randomization within a week | Log week ID and arm for every case |
| Randomization or phased assignment | Stepped wedge over four 3-week blocks after a 2-week baseline; order of treatment introduction randomized | Estimate treatment effect while controlling for time trends | Pre-register the schedule; keep originals-required cases as negative control | Record calendar time and phase |
| Eligible strata | C1: no-originals, low-complexity, non-legal; C1-L: no-originals legal-required; C2: originals-required | Test mechanism in clean subgroup before expanding | Do not mix C1 and C2 in primary analysis | Stratify all metrics by cohort and legal flag |
| Treatment versions | V0 control; V1 parallel verification on current IT lock; V2 parallel verification after lock fix | Separate implementation failure from mechanism failure | V2 only if V1 fails and lock fix is feasible | Log lock errors and actual simultaneous owners |
| Primary outcomes | Verification-completion time from Register to both checks complete; cycle time for C1 | Directly measure the parallelization mechanism and end-to-end effect | Predefine endpoint definitions before analysis | Event-log timestamps |
| Secondary outcomes | p90 cycle time, waiting before Assessment, queue lengths, rework rate, appeal rate, supplement rate | Detect harmful tail and quality effects | Monitor p90 and rework as stop-rule metrics | Compute from complete event log |
| Interference controls | Negative-control stratum: originals-required cases should be unaffected; monitor spillover to control weeks | Detect time trends, learning, and contamination | Do not change originals-required process | Compare negative-control outcomes across treatment/control weeks |
| Power / minimum support | Minimum 400 eligible C1 cases per treatment version; with 8 experimental weeks  400–600 C1 cases available | Detect a 2h median shift with reasonable precision | Conservative nonparametric tests; use sequential analysis | Track accrual and censoring |
| Duration | 2-week run-in, 8-week experimental period, 2-week washout, plus 90-day appeal follow-up | Capture both immediate cycle effects and delayed quality effects | No change to legal/statutory constraints during pilot | Ongoing log extraction and weekly dashboards |
| Stop rules | Stop if treatment p90 worsens >10h, rework/appeal rises >2pp, lock errors exceed 5%, or legal backlog grows >20% | Protect operations and patients | Management review at pre-specified checkpoints | Automated alerts on dashboards |
| Transportability analysis | Estimate conditional average treatment effects by stratum; fit a transport model combining A’s confounded estimate with B’s direct estimate | Quantify site differences and effect modification | Use the DAG in Section 2 to justify covariates | Compare Site A and B DFGs and service-time distributions |

The pilot separates mechanism failure from implementation failure by running two treatment versions. V1 tests the intervention on the current legacy system. If V1 shows no effect but V2 shows an effect after the case-lock fix, the failure is implementation-related, not a failure of the parallelization mechanism. If V2 also shows no effect despite system-confirmed true overlap, the mechanism itself is not transportable to B. The originals-required negative-control stratum detects time trends and contamination. Process-mining measurement verifies that overlap is real, not merely a timestamp artifact. Thus a “no effect” result can be correctly assigned to mechanism or implementation rather than to confounding.

## 8. PM4Py model-construction code

```python
import pm4py
from pm4py.objects.powl.obj import OperatorPowl, Transition, Operator

# 1. Site A before and after process trees
tree_a_before = pm4py.parse_process_tree(
    "-> ( 'Register', 'Identity Check', 'Document Check', 'Assessment', "
    "X ( 'Approve', 'Reject' ), 'Notify' )"
)
tree_a_after = pm4py.parse_process_tree(
    "-> ( 'Register', + ( 'Identity Check', 'Document Check' ), 'Assessment', "
    "X ( 'Approve', 'Reject' ), 'Notify' )"
)

# 2. Convert Site A trees to accepting Petri nets
net_a_before, im_a_before, fm_a_before = pm4py.convert_to_petri_net(tree_a_before)
net_a_after, im_a_after, fm_a_after = pm4py.convert_to_petri_net(tree_a_after)

# 3. Build Site B candidate using POWL classes
def trans(name, label=None):
    return Transition(name, label=label)

seq = OperatorPowl(operator=Operator.SEQUENCE)

reg = trans("Register")
identity = trans("Identity Check")
doc_direct = trans("Document Check", label="Document Check")
originals = trans("Originals Receipt")
doc_after_originals = trans("Document Check", label="Document Check")
assessment = trans("Assessment")
legal_review = trans("Legal Review")
supplement = trans("Request Supplement")
approve = trans("Approve")
reject = trans("Reject")
notify = trans("Notify")

# Verification block:
# PAR( Identity, XOR( DocumentCheck, SEQ(OriginalsReceipt, DocumentCheck) ) )
verification = OperatorPowl(operator=Operator.PARALLEL)

required_doc = OperatorPowl(operator=Operator.SEQUENCE)
required_doc.add_child(originals)
required_doc.add_child(doc_after_originals)

doc_choice = OperatorPowl(operator=Operator.XOR)
doc_choice.add_child(doc_direct)
doc_choice.add_child(required_doc)

verification.add_child(identity)
verification.add_child(doc_choice)

# Legal-review block with supplement loop.
# REDO is used to approximate: LegalReview -> (RequestSupplement -> DocumentCheck -> Assessment) -> LegalReview
supplement_body = OperatorPowl(operator=Operator.SEQUENCE)
supplement_body.add_child(supplement)
supplement_body.add_child(trans("Document Check", label="Document Check"))
supplement_body.add_child(trans("Assessment", label="Assessment"))

legal_redo = OperatorPowl(operator=Operator.REDO)
legal_redo.add_child(legal_review)
legal_redo.add_child(supplement_body)

legal_choice = OperatorPowl(operator=Operator.XOR)
legal_choice.add_child(legal_redo)
legal_choice.add_child(trans("skip_legal", label=None))

decision = OperatorPowl(operator=Operator.XOR)
decision.add_child(approve)
decision.add_child(reject)

seq.add_child(reg)
seq.add_child(verification)
seq.add_child(assessment)
seq.add_child(legal_choice)
seq.add_child(decision)
seq.add_child(notify)

# 4. Explicit strict partial-order edges.
# The parent/child nesting already preserves most orderings; this list documents
# the strict partial order explicitly for the converter/auditor.
order_edges = [
    (reg, identity),
    (reg, originals),
    (originals, doc_after_originals),
    (identity, assessment),
    (doc_direct, assessment),
    (doc_after_originals, assessment),
    (assessment, legal_choice),
    (legal_choice, decision),
    (decision, notify),
]

if hasattr(seq, "add_order"):
    for src, tgt in order_edges:
        seq.add_order(src, tgt)
else:
    # Some PM4Py versions expose an order collection on OperatorPowl.
    seq.order = order_edges

# 5. Convert POWL model to an accepting Petri net
net_b, im_b, fm_b = pm4py.convert_to_petri_net(seq)

# 6. Check workflow-net and soundness properties
print("A before workflow net:", pm4py.check_is_workflow_net(net_a_before))
print("A after workflow net:", pm4py.check_is_workflow_net(net_a_after))
print("B workflow net:", pm4py.check_is_workflow_net(net_b))
print("B soundness:", pm4py.check_soundness(net_b, im_b, fm_b))

# 7. Optional playout and sample traces
traces_b = pm4py.play_out(net_b, im_b, fm_b, num_traces=5, max_trace_length=30)
for trace in traces_b:
    print([event["concept:name"] for event in trace])

# 8. What the model cannot encode:
# - Data-dependent legal requirements (are originals required? is legal review required?)
# - Resource capacities and role specialization
# - Legacy case-lock behavior
# - Durations, queueing, and WIP limits
# - Real-world supplements triggered by document content/quality rather than by structure
```

## 9. Recommendation

Recommendation: conditional go.

Transfer the structural principle of exploiting independence, not Site A’s final process. In Site B, only no-originals cases can support true Identity/Document overlap. For the 62% of cases with statutory originals requirements, the only safe parallel action is to start Identity Check and Originals Receipt simultaneously after Register, leaving Document Check gated on receipt. Do not copy A’s two-week full rollout, its FTE increase, marketing mix shift, API upgrade, or daily huddles as if they were part of the same treatment. Do not force Document Check to begin before originals are received. Do not parallelize Legal Review with verification.

The first cohort should be no-originals, low-complexity, non-legal cases. This is the largest subgroup where the structural condition matches Site A and where downstream legal/rework confounders are minimized. Start with V1 on the current system; if V1 fails because of case locking, invest in the IT lock release and run V2. Keep originals-required and legal-required cases as comparison and negative-control strata until the C1 mechanism is proven.

Expected benefits are modest: roughly 1–2h median improvement in C1 and 0.5–1.5h all-case median improvement. Site A’s raw 9h reduction should not be extrapolated. Main risks are lock-induced no-op, assessment bottleneck shift, legal queue growth, rework/appeal increases, and p90 worsening.

Expansion triggers: if after 200–300 C1 cases the treatment arm shows at least 2h verification-completion improvement and at least 1h cycle-time improvement, rework/appeal no worse than +1pp, and system-confirmed overlap at least 50%, then expand to all no-originals cases. Modification triggers: if the assessment queue grows, add assessment capacity or priority scheduling; if legal congestion appears, delay legal cases from the pilot or increase legal capacity; if lock failure is observed, add the IT fix. Abandonment triggers: if p90 worsens by more than 10h, rework/appeal rises by more than 2pp, or event-log audit shows implementation fidelity was never achieved, stop and do not expand.

## 10. Assumption register

1. **Assumption:** Site B’s event log, after correcting back-entry, reflects actual process order. — **Why needed:** all before/after and transport estimates depend on timeline accuracy. — **How to test:** audit 50 random cases against physical files and system states. — **Consequence if false:** pilot measurement is invalid; automated logging must be implemented first.

2. **Assumption:** Site A’s 9h median reduction is not entirely causal; only the structural overlap mechanism is transportable. — **Why needed:** to avoid overpromising and to set realistic B expectations. — **How to test:** reconstruct A’s data by stratum and co-intervention adjustments; mediation analysis. — **Consequence if false:** A’s effect may be larger, but B’s originals, legal, lock, and role constraints still cap the transferable benefit.

3. **Assumption:** The 38% no-originals cases are digitally available at registration and can start Document Check immediately. — **Why needed:** defines the eligible pilot cohort. — **How to test:** inspect document-arrival metadata; confirm no policy prevents early document check. — **Consequence if false:** the eligible share is smaller and a scanning or digitization step is needed.
