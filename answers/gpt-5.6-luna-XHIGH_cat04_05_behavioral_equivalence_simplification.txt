# 1. Equivalence Notions

Let `tau` be silent and let the visible alphabet be all other labels. For a complete firing or execution path `p`, write `vis(p)` for the sequence obtained by deleting every `tau` occurrence. The visible language of a model is

`Lvis(M) = { vis(p) : p is a complete execution of M }`.

Visible-trace equivalence after hiding `tau` means `Lvis(A) = Lvis(B)`. This is a language equality: it compares every complete visible sequence, including its length, multiplicity of labels, and order. Repeated occurrences of the same label are distinguished by their sequence positions and multiplicity, but not by the identity of the underlying transition. Thus two different transitions with the same visible label are observationally the same unless a richer observation records transition identity.

For P3, define

`L12,3(M) = { t in Lvis(M) : |t| <= 12 and count(t, 'Analyze Revision') <= 3 }`.

Bounded visible-language equivalence is equality of `L12,3(A)` and `L12,3(B)`, with `Approve Revision`, `Check Revision`, and `Rework Case` still visible. The bound applies after hiding `tau`. This is a finite test of the language, not a proof that the unbounded languages are equal.

Business-relevant equivalence under P1 is stricter than merely satisfying the same high-level rule. It requires the models to admit the same relevant attempt histories, where `Rework Case` separates attempts, each analysis segment has its own check before the next `Rework Case` or `Close Case`, and visible approval occurrences and their positions are retained. Under this observation, a check cannot be silently shared across several attempts.

For P2, use the abstraction

`O2(t) = (number of Analyze Revision labels, CheckOccurred(t), ReworkOccurred(t))`,

after requiring `Open Case` to be first, `Close Case` to be last, and at least one analysis and one check. `Approve Revision` and `tau` are removed, repeated checks are mapped to one Boolean, and the interleaving of analysis and check is discarded. Abstracted dashboard equivalence means that the sets of these records are equal, not that the raw visible languages are equal.

# 2. Structural Comparison

Here `+` is parallelism and `X` is exclusive choice. The binary-loop convention makes the first loop child execute at least once.

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The loop body is a per-attempt sequence: parallel `Analyze Revision` and `Check Revision`, followed by optional approval. `Rework Case` is the continuation separator. | The loop contains `Analyze Revision`, optional approval, and `Rework Case`; a single `Check Revision` is outside that loop in a parallel branch. | A couples one check to every loop iteration; B has one global check for the whole revision activity. |
| Minimum Check Revision occurrences | Exactly one in the mandatory first iteration. | Exactly one, from the mandatory outer parallel branch. | Both have at least one check. |
| Maximum Check Revision occurrences | Unbounded: one check per iteration. | Exactly one. | The raw languages differ as soon as two attempts are possible. |
| Possible placement of Check Revision | In each attempt, either before or after `Analyze Revision` because of the per-iteration `+`; it must occur before that attempt's approval, `Rework Case`, or `Close Case`. | Anywhere allowed by interleaving the single check with the whole loop: before the first analysis, between analysis and approval, between attempts, or after the last attempt, but before `Close Case`. | B permits checks that are not tied to a particular attempt; A requires one check before every attempt boundary. |
| Optional approval occurrences | One `Approve Revision` or `tau` choice per iteration, after both parallel children have completed. | One `Approve Revision` or `tau` choice per iteration, after that iteration's analysis; the global check may occur before or after it. | Approval count can grow with the number of attempts in both models, but its relative position to the check differs. |
| Concurrency | Parallelism is local to each loop iteration and joins before approval and before continuation. | Parallelism is global between the one check and the entire revision loop. | Moving the `+` across the loop changes both check cardinality and legal interleavings. |
| Join before Close Case | The outer sequence waits for the loop to finish, including the final per-attempt parallel join and approval choice, then closes. | The outer sequence waits for both the one check and the entire loop to finish, then closes. | Both close last, but the join has different obligations: all per-attempt checks in A versus one global check in B. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 — operational compliance | not equivalent | high | A has one check in every attempt; B has only one check for an unbounded number of attempts and permits it to be outside any particular attempt. Approval placement also differs and remains visible. | On the literal wording, A's parallelism allows `Check Revision` before `Analyze Revision`. If P1 additionally requires analysis-before-check, A would need an ordering repair too. |
| P2 — executive dashboard | equivalent only under stated abstraction | high | For every `n >= 1`, both can produce the dashboard record `(n, true, n > 1)`: `n` analyses, at least one check, and a rework exactly when there is more than one attempt. | The raw traces are not equal. This verdict relies on hiding approvals, collapsing check multiplicity, and ignoring analysis/check interleaving. |
| P3 — bounded testing | not equivalent | high | Differences already occur within the bound, including two-check traces from A and traces with approval before the global check from B. | Passing this finite comparison would not prove unbounded equivalence; here it fails, so the bound is already sufficient to refute equality. |

# 4. Counterexample Traces

The traces below are complete visible traces. A missing approval means that the `tau` branch of the corresponding `X` was selected.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---:|---:|---|---|
| A-only-1 | `Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close Case` | yes | no | The second loop iteration contains a second `Check Revision`; B has only one check total. | P1, P3 |
| A-only-2 | `Open Case, Check Revision, Analyze Revision, Approve Revision, Rework Case, Check Revision, Analyze Revision, Close Case` | yes | no | A can complete two per-iteration parallel joins, each with its own check; B cannot fire its sole check twice. | P1, P3 |
| B-only-1 | `Open Case, Analyze Revision, Approve Revision, Check Revision, Close Case` | no | yes | In B, the global check may occur after the first loop iteration's approval. In A, approval follows the per-iteration check, so `Approve Revision` cannot precede that check. | P1, P3 |
| B-only-2 | `Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case` | no | yes | B may delay its sole check until after two analyses. A cannot cross the first `Rework Case` without completing a check in the first attempt. | P1, P3 |

The first two traces use the silent branch, so hiding `tau` does not remove the decisive second-check difference. The third trace uses the visible approval branch: optional approval creates a direct P3 witness because A requires the check before approval while B's outer parallelism does not. If the silent branch is selected instead, B still has witnesses such as `Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case`.

Under P2, these raw differences are intentionally erased. For example, the two-check A-only trace and a one-check B trace with the same number of analyses and rework status map to the same Boolean `CheckOccurred = true`; the approval in B-only-1 is hidden.

# 5. Bounded Comparison Code

The following program uses accepting Petri nets and an exhaustive breadth-first exploration up to the P3 bounds. It does not use random playout. A state is retained by marking, visible trace, and analysis count; this permits different traces reaching the same marking while preventing silent cycles from causing nontermination. A trace is accepted only when the current marking is exactly the declared final marking.

```python
from collections import deque

import pm4py
from pm4py.objects.petri_net.obj import Marking


MODEL_A_STRING = (
    "->('Open Case',*(->(+('Analyze Revision','Check Revision'),"
    "X('Approve Revision',tau)),'Rework Case'),'Close Case')"
)

MODEL_B_STRING = (
    "->('Open Case',+( 'Check Revision',*(->('Analyze Revision',"
    "X('Approve Revision',tau)),'Rework Case'))),'Close Case')"
)


tree_a = pm4py.parse_process_tree(MODEL_A_STRING)
tree_b = pm4py.parse_process_tree(MODEL_B_STRING)

net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

print("Model A soundness:")
print(pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=True))
print("Model B soundness:")
print(pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=True))


def marking_key(marking):
    # Place names are unique within a generated Petri net.
    return tuple(sorted((place.name, int(count))
                        for place, count in marking.items()
                        if count))


def fire(net, marking, transition):
    """Fire an already-enabled ordinary Petri-net transition."""
    result = Marking(marking)
    for arc in transition.in_arcs:
        place = arc.source
        remaining = result[place] - arc.weight
        if remaining:
            result[place] = remaining
        elif place in result:
            del result[place]
    for arc in transition.out_arcs:
        place = arc.target
        result[place] += arc.weight
    return result


def bounded_complete_visible_language(net, initial_marking, final_marking,
                                      max_visible=12, max_analyze=3):
    """Exhaustively enumerate complete visible traces under the P3 bound."""
    queue = deque([(Marking(initial_marking), tuple(), 0)])
    seen = {(marking_key(initial_marking), tuple(), 0)}
    complete = set()

    while queue:
        marking, trace, analyze_count = queue.popleft()

        # Do not accept a deadlock merely because it has no enabled moves.
        if marking == final_marking:
            complete.add(trace)
            continue

        enabled = pm4py.get_enabled_transitions(net, marking)
        for transition in enabled:
            label = transition.label
            if label is None or label == "":
                next_trace = trace       # hide tau
                next_analyze_count = analyze_count
            else:
                next_trace = trace + (label,)
                if len(next_trace) > max_visible:
                    continue
                next_analyze_count = (
                    analyze_count + (label == "Analyze Revision")
                )
                if next_analyze_count > max_analyze:
                    continue

            next_marking = fire(net, marking, transition)
            state_key = (marking_key(next_marking), next_trace,
                         next_analyze_count)
            if state_key not in seen:
                seen.add(state_key)
                queue.append((next_marking, next_trace,
                              next_analyze_count))

    return complete


language_a = bounded_complete_visible_language(net_a, im_a, fm_a)
language_b = bounded_complete_visible_language(net_b, im_b, fm_b)

only_a = sorted(language_a - language_b)
only_b = sorted(language_b - language_a)

print("P3 language sizes:", len(language_a), len(language_b))
print("P3-equivalent:", language_a == language_b)
print("Complete traces unique to Model A:")
for trace in only_a:
    print("  ", trace)
print("Complete traces unique to Model B:")
for trace in only_b:
    print("  ", trace)
```

The search is exhaustive for the specified finite bounds: every enabled visible and silent transition is explored, visible length is counted only for non-silent labels, and repeated `(marking, visible trace, analysis count)` states are pruned. It is not an unbounded language-equivalence decision procedure. `pm4py.play_out(...)` would be a sampling or configured playout approach unless its coverage were separately proven exhaustive; using it alone would not establish bounded set equality.

# 6. Stochastic and Footprint Comparison

`pm4py.discover_footprints(...)` can compare coarse relations such as start/end activity information, directly-follow relations, and parallelism. It is useful diagnostic evidence: it may reveal that both models expose the same local activity names and some similar relations. It is not a complete representation of loop scope. In particular, a footprint can fail to record that A repeats `Check Revision` per iteration while B permits only one check globally, or that B can place the check after an approval or after several analyses.

For example, after constructing the two trees or accepting nets, a footprint check can be written as:

```python
footprints_a = pm4py.discover_footprints(tree_a)
footprints_b = pm4py.discover_footprints(tree_b)
print("Equal footprints:", footprints_a == footprints_b)

# If a PM4Py version expects accepting nets for this operation instead:
# footprints_a = pm4py.discover_footprints((net_a, im_a, fm_a))
# footprints_b = pm4py.discover_footprints((net_b, im_b, fm_b))
```

There is no probability distribution in either input tree. The `X` choices, loop continuation choices, and scheduling of concurrent branches therefore do not define a unique stochastic language. The following code deliberately declares a finite, artificial distribution: one copy of every complete trace in the already enumerated P3 language, giving every such bounded trace equal mass. It uses PM4Py's stochastic-language and EMD APIs where supported by the installed version.

```python
from pm4py.objects.log.obj import Event, EventLog, Trace


def uniform_log(trace_set):
    log = EventLog()
    for trace_tuple in sorted(trace_set):
        log.append(Trace([
            Event({"concept:name": label}) for label in trace_tuple
        ]))
    return log


bounded_log_a = uniform_log(language_a)
bounded_log_b = uniform_log(language_b)
stochastic_language_a = pm4py.get_stochastic_language(bounded_log_a)
stochastic_language_b = pm4py.get_stochastic_language(bounded_log_b)
emd = pm4py.compute_emd(stochastic_language_a, stochastic_language_b)
print("Artificial bounded-language EMD:", emd)
```

This EMD is evidence about the declared bounded empirical distributions, not about the unbounded process models. A low EMD can hide a rare but business-critical trace, and a nonzero EMD can be caused by different probabilities even when supports are equal. Even an EMD of zero would establish equality only for the chosen finite support, event encoding, and probability assignment; it would not prove equality of the complete trace sets. A genuine stochastic comparison would have to declare loop-exit probabilities, approval probabilities, and a policy or distribution for concurrent interleavings. No such probabilities are supplied here, so they must not be inferred from the trees.

# 7. Complexity Comparison

Count every operator and every leaf as one process-tree node, count depth as root-to-leaf edges, count `tau` as a silent leaf, and count static duplicate labels as repeated non-silent leaf labels in the tree. Under these conventions:

| Metric | Model A | Model B | Comparison |
|---|---:|---:|---|
| Process-tree nodes | 12 | 12 | Equal static node count. |
| Maximum depth | 4 | 5 | B is one level deeper because the outer parallel node encloses the loop. |
| Visible leaves | 6 | 6 | Both contain `Open Case`, `Analyze Revision`, `Check Revision`, `Approve Revision`, `Rework Case`, and `Close Case`. |
| Silent leaves | 1 | 1 | Both contain one `tau` leaf in the approval choice. |
| Static duplicate-label count | 0 | 0 | Each visible label occurs once as a tree leaf; loop execution repeats occurrences dynamically. |
| Dynamic Check Revision multiplicity | Unbounded, one per attempt | Exactly one | This is the important behavioral complexity difference despite equal static size. |

For example, the static figures can be derived directly from a parsed PM4Py tree as follows:

```python
def tree_statistics(node, depth=0):
    # A process-tree leaf has no operator and no children.
    if node.operator is None:
        label = node.label
        return {
            "nodes": 1,
            "max_depth": depth,
            "visible_leaves": int(label is not None),
            "silent_leaves": int(label is None),
            "labels": [] if label is None else [label],
        }

    totals = {
        "nodes": 1,
        "max_depth": depth,
        "visible_leaves": 0,
        "silent_leaves": 0,
        "labels": [],
    }
    for child in node.children:
        child_stats = tree_statistics(child, depth + 1)
        totals["nodes"] += child_stats["nodes"]
        totals["max_depth"] = max(totals["max_depth"],
                                   child_stats["max_depth"])
        totals["visible_leaves"] += child_stats["visible_leaves"]
        totals["silent_leaves"] += child_stats["silent_leaves"]
        totals["labels"].extend(child_stats["labels"])
    return totals


for name, tree in (("A", tree_a), ("B", tree_b)):
    stats = tree_statistics(tree)
    duplicate_count = len(stats["labels"]) - len(set(stats["labels"]))
    print(name, {**stats, "duplicate_labels": duplicate_count})

print("Petri-net simplicity A:",
      pm4py.simplicity_petri_net(net_a, im_a, fm_a))
print("Petri-net simplicity B:",
      pm4py.simplicity_petri_net(net_b, im_b, fm_b))
```

The two calls to `simplicity_petri_net` are the appropriate converted-net comparison. I do not assign numerical scores without running the exact PM4Py version and conversion implementation, because generated place/transition structure and metric details are version-dependent. The structural comparison predicts that B has more nesting, but tree node count alone does not determine which converted net receives the higher simplicity score; the API result should be reported with the PM4Py version used.

# 8. Simplified Model

I choose P2 as the target semantics. P2 does not need to preserve the number or placement of checks, approval events, or analysis/check interleavings. A minimal model for that dashboard abstraction is:

```text
->(
  'Open Case',
  'Check Revision',
  *('Analyze Revision', 'Rework Case'),
  'Close Case'
)
```

The check is placed before the loop only because P2 ignores its interleaving with analysis. The loop still executes one analysis and then either exits or emits `Rework Case` before the next analysis.

Self-contained PM4Py construction:

```python
import pm4py

SIMPLIFIED_TREE_STRING = (
    "->('Open Case','Check Revision',"
    "*('Analyze Revision','Rework Case'),'Close Case')"
)

simplified_model = pm4py.parse_process_tree(SIMPLIFIED_TREE_STRING)
simplified_net, simplified_im, simplified_fm = \
    pm4py.convert_to_petri_net(simplified_model)
```

Its structure is smaller than both originals under the same counting convention:

| Metric | Model A | Model B | Simplified P2 model | Effect |
|---|---:|---:|---:|---|
| Process-tree nodes | 12 | 12 | 7 | Removes the approval XOR, its `tau` leaf, the per-attempt parallel node, and the outer global parallel node. |
| Maximum depth | 4 | 5 | 2 | No nested approval or parallel branch remains. |
| Visible leaves | 6 | 6 | 5 | `Approve Revision` is intentionally absent because P2 hides it. |
| Silent leaves | 1 | 1 | 0 | No hidden approval branch is needed for the dashboard abstraction. |
| Static duplicate-label count | 0 | 0 | 0 | No duplicate leaf labels. |

Preservation under the selected target is:

| Property | Status in simplified model |
|---|---|
| `Open Case` first and `Close Case` last | exact |
| At least one `Analyze Revision` and one `Check Revision` | exact |
| Number of analyses `n` | exact for every `n >= 1` |
| Whether any `Rework Case` occurred | exact: it occurs iff `n > 1` |
| Dashboard fact that a check occurred | exact, with the one check representing the Boolean fact |
| Repeated-check multiplicity | abstracted away, as allowed by P2 |
| Analyze/check interleaving | weakened: fixed to check-before-loop, but ignored by P2 |
| `Approve Revision` occurrences and positions | lost intentionally |
| P1 per-attempt check obligation | lost; the simplified model has one check total |
| P3 raw visible language | lost; P3 retains approval and exact order |

Regression traces for the simplified model are:

| Type | Trace | Reason |
|---|---|---|
| positive | `Open Case, Check Revision, Analyze Revision, Close Case` | One mandatory analysis and one check, with no rework. |
| positive | `Open Case, Check Revision, Analyze Revision, Rework Case, Analyze Revision, Close Case` | Two analyses and one rework. |
| positive | `Open Case, Check Revision, Analyze Revision, Rework Case, Analyze Revision, Rework Case, Analyze Revision, Close Case` | Three analyses and two reworks. |
| negative | `Open Case, Analyze Revision, Check Revision, Close Case` | The simplified dashboard model fixes the check before its analysis loop. |
| negative | `Open Case, Check Revision, Analyze Revision, Rework Case, Close Case` | A loop continuation must be followed by the next loop iteration's analysis. |
| negative | `Open Case, Check Revision, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case` | The simplified model contains exactly one check, even though P2 would collapse repeated checks if they existed in an upstream model. |

# 9. Final Recommendation

Use Model A for P1's per-attempt compliance semantics, subject to the caveat that a strict analysis-before-check rule would require replacing its per-iteration `+` with an ordered sequence. Model B is not suitable as the P1 source of truth because its single check can be shared across the whole loop.

Under P2, Models A and B are equivalent after the stated dashboard abstraction. The seven-node simplified model is preferable as the dashboard-facing representation and may replace either original only at that abstraction boundary; it should not replace the operational model.

Under P3, the originals are not equivalent, and the supplied bound already exposes the difference. Retain the model whose loop scope matches the intended business rule: A for one check per attempt, B for one global check. A bounded comparison can refute equivalence when it finds a witness, as it does here, but even a passing bound would not prove unbounded behavioral equivalence.
