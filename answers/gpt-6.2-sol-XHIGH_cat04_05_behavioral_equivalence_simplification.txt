# 1. Equivalence Notions

Write `o` for `Open Case`, `a` for `Analyze Revision`, `c` for `Check Revision`, `p` for `Approve Revision`, `w` for `Rework Case`, and `z` for `Close Case`. A trace is complete when its execution ends in the designated final state.

- **Visible trace equivalence.** Delete every `tau` from every complete execution. Two models are equivalent if the resulting sets of ordered label sequences are equal. A label can occur more than once in a trace and each occurrence occupies its own position. Events have no observable transition or revision identity. Executions that produce the same label sequence contribute one element to the set.
- **Bounded visible-language equivalence (P3).** Restrict each visible language to traces of length at most 12 with at most three occurrences of `a`, then compare the sets. Silent steps consume neither bound.
- **Business-relevant equivalence (P1).** Between `o` and `z`, split the trace at each `w`. Observe the ordered attempt records. Each record contains the counts of `a` and `c` and an ordered list of approvals. For each approval, record how many analyses and checks precede it within that attempt. This retains approval count and placement, including placement relative to the check and the attempt boundary. It treats the order of analysis and check as immaterial when changing it leaves these records unchanged. Equivalence means equality of the sets of records. For these models, each block contains one analysis. Compliance requires a check in each block before the terminating `w` or `z`, so each analysis gets its own check occurrence. An approval may be absent.
- **Abstracted dashboard equivalence (P2).** Project a trace to $(b,n,q,r)$, where $b$ indicates that `o` is first and `z` is last, $n$ is the number of analyses, $q$ indicates at least one check, and $r$ indicates at least one rework. A valid dashboard outcome has $b=q=\mathrm{true}$ and $n\geq 1$. Approval and silent behavior are hidden, and check position and multiplicity are discarded. Equivalence means equality of the sets of projected outcomes.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The loop body executes analysis and check, then optional approval. | The loop body executes analysis, then optional approval. The check is outside the loop. | A repeats the check with each attempt. B repeats the analysis and approval choice only. |
| Check count | Minimum one, with no finite maximum. Exactly $n$ for $n$ attempts. | Minimum and maximum both one, for every $n$. | Any case with multiple attempts has different check counts in the two models. |
| Check placement | Within each attempt, before or after its analysis, before any approval in that attempt, and before the next rework or close. | At any position after open and before close, including before the first analysis, between attempts, or after the last approval. | B allows a rework to precede the case's only check and allows approval before the check. |
| Optional approval | Zero or one per attempt, after both analysis and check. | Zero or one per attempt, after analysis. The check may occur on either side of it. | Both permit every total from zero to $n$ approvals. Their relative placement can differ. |
| Concurrency | Parallel analysis and check within each attempt. | The single check runs in parallel with the entire revision loop. | The parallel branches span different portions of the case. |
| Join before close | Each attempt joins analysis and check before taking its approval choice. Close follows loop exit. | The outer join waits for the single check and loop exit. Close follows that join. | Both wait for a check before close. Only A also waits for an attempt-specific check before rework. |

The complete visible words of A have the form `o D (w D)* z`, where `D = (a c | c a) p?`. For B, start with `E (w E)*`, where `E = a p?`. Insert exactly one `c` in any gap, including the gaps at either end, then wrap the result with `o` and `z`. Here `?` means optional and the postfix `*` means zero or more repetitions.

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 — operational compliance | not equivalent | High, by loop scope | A checks every attempt. For two or more attempts, B leaves at least one attempt unchecked. | A one-attempt B case meets the per-attempt check requirement. B can still produce a different approval placement in such a case. |
| P2 — executive dashboard | equivalent only under stated abstraction | High, by equality of projected outcome sets | For each $n\geq 1$, both yield exactly $(\mathrm{true},n,\mathrm{true},n>1)$. Both can realize every such $n$. | The projection discards the information needed to audit check coverage and approval placement. |
| P3 — bounded testing | not equivalent | High, by bounded witnesses and exhaustive enumeration | There are 72 A-only traces and 81 B-only traces within the bound. | These counts apply to complete traces satisfying both bounds. |

The P3 witnesses also disprove unbounded visible trace equivalence because they are complete traces of the original models.

# 4. Counterexample Traces

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| A1 | `o a c w a c z` | Admitted | Rejected | The second `c` requires another check occurrence. B has already executed its only check. | P1, P3 |
| A2 | `o c a p w c a p z` | Admitted | Rejected | The `c` immediately after `w` is the second check. | P1, P3 |
| B1 | `o a w a c z` | Rejected | Admitted | The first `w` ends an attempt that has no check. | P1, P3 |
| B2 | `o c a w a z` | Rejected | Admitted | The `z` ends the second attempt without its own check. | P1, P3 |
| B3 | `o a p c z` | Rejected | Admitted | The approval occurs while the attempt's check is still pending. | P1 approval placement, P3 |

A1, B1, and B2 witness the check-coverage difference even with every approval omitted. The optional `tau` branch lets each attempt finish without emitting `p`. Hiding `tau` leaves all `a`, `c`, `p`, and `w` events in place. With a visible approval, B3 distinguishes the models even for one attempt. B3 satisfies the stated P1 check deadline because the check occurs before close, while its approval position differs from A's allowed positions. Under P2, A1, A2, B1, and B2 all yield the same two-attempt outcome, and B3 yields the one-attempt outcome.

# 5. Bounded Comparison Code

This breadth-first search exhaustively explores the converted nets under P3. A state includes both the marking and the visible prefix. Two paths reaching the same marking with the same prefix have the same continuations, including the same remaining event budgets. The search follows silent transitions even when the visible budget is exhausted, and it accepts a trace only at exact final-marking equality. The converted nets for these trees have finitely many reachable markings. Each parallel branch carries a single active control flow and synchronizes either before the next iteration in A or before close in B. Iteration does not accumulate tokens.

```python
from collections import deque

import pm4py
from pm4py.objects.petri_net import semantics

model_strings = {
    "A": """
        ->(
          'Open Case',
          *(
            ->(
              +('Analyze Revision', 'Check Revision'),
              X('Approve Revision', tau)
            ),
            'Rework Case'
          ),
          'Close Case'
        )
    """,
    "B": """
        ->(
          'Open Case',
          +(
            'Check Revision',
            *(
              ->(
                'Analyze Revision',
                X('Approve Revision', tau)
              ),
              'Rework Case'
            )
          ),
          'Close Case'
        )
    """,
}

trees = {
    name: pm4py.parse_process_tree(" ".join(expression.split()))
    for name, expression in model_strings.items()
}
accepting_nets = {
    name: pm4py.convert_to_petri_net(tree) for name, tree in trees.items()
}


def marking_key(marking):
    return frozenset((place, tokens) for place, tokens in marking.items() if tokens)


def bounded_language(net, initial, final, max_events=12, max_analyses=3):
    final_key = marking_key(final)
    pending = deque([(initial, (), 0)])
    visited = {(marking_key(initial), ())}
    complete = set()

    while pending:
        marking, prefix, analysis_count = pending.popleft()
        if marking_key(marking) == final_key:
            complete.add(prefix)

        for transition in pm4py.get_enabled_transitions(net, marking):
            label = transition.label
            next_prefix = prefix
            next_analysis_count = analysis_count
            if label is not None:
                next_analysis_count += int(label == "Analyze Revision")
                if len(prefix) == max_events or next_analysis_count > max_analyses:
                    continue
                next_prefix = prefix + (label,)

            next_marking = semantics.execute(transition, net, marking)
            state = (marking_key(next_marking), next_prefix)
            if state not in visited:
                visited.add(state)
                pending.append((next_marking, next_prefix, next_analysis_count))

    return complete


bounded_languages = {}
for name, (net, initial, final) in accepting_nets.items():
    sound, diagnostics = pm4py.check_soundness(
        net, initial, final, print_diagnostics=False
    )
    print(f"{name} sound: {sound}")
    if not sound:
        raise RuntimeError(f"Unsound model {name}: {diagnostics}")
    bounded_languages[name] = bounded_language(net, initial, final)

language_a = bounded_languages["A"]
language_b = bounded_languages["B"]
print(
    f"Exhaustive P3 counts: A={len(language_a)}, B={len(language_b)}, "
    f"shared={len(language_a & language_b)}"
)
print("P3 equivalent:", language_a == language_b)
for name, unique in (("A", language_a - language_b), ("B", language_b - language_a)):
    print(f"{name} only ({len(unique)}):")
    for trace in sorted(unique, key=lambda trace: (len(trace), trace)):
        print("  " + " -> ".join(trace))
```

The counts also follow from the visible word forms. For $n$ attempts and $k$ approvals, A has length $3n+1+k$ and $2^n\binom{n}{k}$ distinct words. The factors count analysis/check orders and the attempts with an approval. B has length $2n+2+k$ and $(2n+k)\binom{n}{k}$ distinct words. Its revision word has $2n+k$ gaps for inserting the check. Applying both P3 bounds gives the following counts.

| Attempts | A | B | Shared |
|---:|---:|---:|---:|
| 1 | 4 | 5 | 4 |
| 2 | 16 | 20 | 0 |
| 3 | 56 | 60 | 0 |
| **Total** | **76** | **85** | **4** |

At three attempts, the length cap removes A's words with three approvals. All B words with at most three attempts meet the length cap. For $n=1$, B allows all four A words plus B3. For $n\geq 2$, different check counts rule out any common word. Random or heuristic playout can find witnesses, but a missing trace in a sample gives no guarantee of absence from the language.

# 6. Stochastic and Footprint Comparison

`pm4py.discover_footprints(...)` summarizes relations such as succession and parallelism. For these trees, the process-tree footprint places `(Check Revision, Approve Revision)` in A's sequence relation and both directions of the pair in B's parallel relation. B3 realizes the extra direct succession from approval to check. A footprint combines relations across traces and omits information such as how many checks occur in a complete case or how they are distributed across attempts. Equal footprints therefore cannot establish trace equivalence.

`pm4py.get_stochastic_language(...)` can estimate trace probabilities from an event log. To give reproducible weights for this comparison, the code below creates one log case per distinct P3 trace, giving each trace in a model's bounded support equal mass. This distribution is defined for the experiment. An execution-based distribution would require a specified loop exit policy, approval choice probabilities, and interleaving policy, or empirical frequencies from a log.

`pm4py.compute_emd(...)` compares the distributions by the cost of transporting mass between traces. A low distance can coexist with different supports when a distinguishing trace has little probability or is cheap to edit into another trace. Even a zero distance on sampled or bounded distributions leaves behavior outside the sample or bound unresolved. The uniform P3 distributions give a distance of about 0.1822 in PM4Py 2.7.23.4.

```python
from pm4py.objects.log.obj import Event, EventLog, Trace

# Reuses trees and bounded_languages from section 5.
for name, tree in trees.items():
    print(name, pm4py.discover_footprints(tree))


def uniform_bounded_language(traces):
    log = EventLog()
    for labels in sorted(traces):
        log.append(Trace([Event({"concept:name": label}) for label in labels]))
    return pm4py.get_stochastic_language(log)


distribution_a = uniform_bounded_language(bounded_languages["A"])
distribution_b = uniform_bounded_language(bounded_languages["B"])
print("EMD for uniform P3 trace distributions:",
      pm4py.compute_emd(distribution_a, distribution_b))
```

# 7. Complexity Comparison

Depth counts edges from the root to the deepest leaf. Each original has five operators, six visible leaves, and one silent leaf, so each has 12 nodes. The longest paths to the approval leaf are sequence → loop → sequence → choice → leaf in A, and sequence → parallel → loop → sequence → choice → leaf in B. A's check has an equally deep path through its parallel node. The duplicate-label count sums the number of visible leaves beyond the first leaf of each distinct label.

| Metric | Model A | Model B |
|---|---:|---:|
| Process-tree nodes | 12 | 12 |
| Depth | 4 | 5 |
| Visible leaves | 6 | 6 |
| Silent leaves | 1 | 1 |
| Duplicate visible labels | 0 | 0 |
| Converted net places / transitions / arcs | 9 / 9 / 20 | 7 / 7 / 16 |
| Converted-net simplicity | $9/11\approx 0.8182$ | $7/9\approx 0.7778$ |

The net counts come from the PM4Py 2.7.23.4 conversion. Its default simplicity measure is $1/(1+\max(\bar d-2,0))$, where $\bar d$ is the mean incident-arc degree over all places and transitions. Each arc contributes two incidences. For A this gives $\bar d=40/18$, and for B it gives $\bar d=32/14$. B has fewer net elements, while A scores higher because its mean incident-arc degree is lower. These scores depend on the conversion and measure.

```python
from collections import Counter

# Reuses trees and accepting_nets from section 5.
def tree_counts(tree):
    nodes = 0
    depth = 0
    silent = 0
    labels = Counter()
    pending = [(tree, 0)]
    while pending:
        node, level = pending.pop()
        nodes += 1
        depth = max(depth, level)
        if node.children:
            pending.extend((child, level + 1) for child in node.children)
        elif node.label is None:
            silent += 1
        else:
            labels[node.label] += 1

    visible = sum(labels.values())
    return {
        "nodes": nodes,
        "depth": depth,
        "visible_leaves": visible,
        "silent_leaves": silent,
        "duplicate_visible_labels": visible - len(labels),
    }


for name, tree in trees.items():
    net, initial, final = accepting_nets[name]
    print(name, tree_counts(tree))
    print("Places, transitions, arcs:", len(net.places), len(net.transitions), len(net.arcs))
    print("Simplicity:", pm4py.simplicity_petri_net(net, initial, final))
```

# 8. Simplified Model

Target **P2**. Use the process tree `->('Open Case', 'Check Revision', *('Analyze Revision', 'Rework Case'), 'Close Case')`. It picks one representative for each dashboard outcome by placing the check immediately after open and omitting approvals. Its complete visible words are `o c a (w a)* z`. For every $n\geq 1$ there is exactly one such word with $n$ analyses, and it yields $(\mathrm{true},n,\mathrm{true},n>1)$. That is exactly the projected outcome set of both originals. Every representative is also a complete trace of B, obtained by placing its check first and skipping all approvals.

```python
import pm4py

simplified_model = pm4py.parse_process_tree(
    "->('Open Case', 'Check Revision', "
    "*('Analyze Revision', 'Rework Case'), 'Close Case')"
)
net, initial, final = pm4py.convert_to_petri_net(simplified_model)
print(pm4py.simplicity_petri_net(net, initial, final))
```

The simplified tree has two operators, five visible leaves, no silent leaves, and no duplicate visible labels. Its seven nodes and depth of two compare with 12 nodes in each original and depths of four and five. In the same PM4Py conversion it has five places, five transitions, and ten arcs. Its mean incident-arc degree is $20/10=2$, giving simplicity $1.0$.

| Property | Preservation | Explanation |
|---|---|---|
| Open first and close last | Exact | Every execution starts with `o` and ends with `z`. |
| Analysis count and rework | Exact | Every positive analysis count is possible. A single `w` separates each pair of consecutive attempts, so rework occurs exactly when $n>1$. |
| At least one check occurred | Exact | Every execution has a check, giving the same Boolean dashboard value. |
| Raw check count and placement | Abstracted | The model uses one fixed placement for the check. It preserves B's check count and represents A's repeated checks by a single occurrence. |
| A's check obligation per attempt | Weakened | The model guarantees one check per case. A case with multiple attempts has unchecked attempts. |
| Approval count and placement | Lost | The simplified trace has no approval event. P2 hides these events in both originals. |
| Complete visible language, including P3 | Lost | The allowed trace set changes. For example, both originals admit `o a c z`, and the simplified model requires the opposite order. |

| Test | Complete visible trace | Expected result in simplified model | Reason |
|---|---|---|---|
| Regression 1 | `o c a z` | Accept | One analysis, a check, and no rework. |
| Regression 2 | `o c a w a z` | Accept | Two analyses, a check, and rework. |
| Regression 3 | `o c a w a w a z` | Accept | Three analyses, a check, and rework. |
| Negative 1 | `o a z` | Reject | The required check is missing. |
| Negative 2 | `o c a a z` | Reject | A second analysis requires a preceding rework. |
| Negative 3 | `o a c z` | Reject | Both originals admit this ordering. Its dashboard outcome is represented by Regression 1. |
| Negative 4 | `o c a p z` | Reject | Both originals admit this approval. Its dashboard outcome is represented by Regression 1. |

# 9. Final Recommendation

Use Model A for P1. Its loop enforces a separate check before each attempt ends and retains optional approvals for review. Either original is suitable for P2. The simplified tree can replace either original as a model of the projected P2 outcomes. Keep A for operational enforcement.

For P3, use the bounded language of whichever original is under test. Use A as the reference if the tests are intended to enforce the per-attempt check rule. The originals have different P3 languages, and the simplified tree changes both, so each needs its own expected trace set. A bounded counterexample disproves unbounded trace equivalence. Agreement inside a bound alone supplies evidence only for that bound.
