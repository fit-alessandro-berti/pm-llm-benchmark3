# 1. Source-Semantics Baseline

Let `R`, `A`, `P`, `L`, `C`, `I`, `D`, `E`, and `H` denote Register, Assess, Prepare, Legal, Configure, Inspect, Correct, Release, and Archive respectively. Traces below omit silent (`tau`) transitions.

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| S1 | Register Change occurs first and exactly once. | `R,A,P,C,I,E,H` | `A,R,P,C,I,E,H` | Yes |
| S2 | Assess Risk and Prepare Evidence both follow registration. | `R,A,P,C,I,E,H` | `R,P,C,I,E,H` without `A` | Yes |
| S3 | Assess Risk and Prepare Evidence are unordered: either may occur first. | Both `R,A,P,…` and `R,P,A,…` | A model admitting only one of those prefixes | Yes |
| S4 | Legal Review is optional after Assess Risk. | Both `R,A,P,C,I,E,H` and `R,A,L,P,C,I,E,H` | `R,L,A,P,C,I,E,H` | Yes, by comparing traces with and without `L`; the silent choice itself is hidden |
| S5 | Verification requires completion of both Assess Risk and Prepare Evidence. | `R,A,P,C,I,E,H` | `R,A,C,P,I,E,H` | Yes |
| S6 | Optional Legal and verification have no source order once their prerequisites hold. | `R,A,P,L,C,I,E,H` and `R,A,P,C,L,I,E,H` | A target permitting only one placement of `L` relative to verification | Yes when `L` occurs |
| S7 | Every verification iteration executes Configure Trial before Inspect Trial. | `R,A,P,C,I,E,H` | `R,A,P,I,C,E,H` | Yes |
| S8 | A repeated verification iteration is separated by Correct Defect. | `R,A,P,C,I,D,C,I,E,H` | `R,A,P,C,I,C,I,E,H` | Yes |
| S9 | Verification has at least one iteration; zero iterations are forbidden. | `R,A,P,C,I,E,H` | `R,A,P,E,H` | Yes |
| S10 | Correct Defect belongs to loop repetition, not the first mandatory iteration or post-loop path. | `R,A,P,C,I,D,C,I,E,H` | `R,A,P,D,C,I,E,H` | Yes |
| S11 | Release waits for completion of both the optional-legal branch and verification. | `R,A,P,C,I,E,H`; `R,A,P,L,C,I,E,H` | `R,A,P,E,C,I,H` | Yes |
| S12 | Archive occurs after Release and is the final visible activity. | `R,A,P,C,I,E,H` | `R,A,P,C,I,H,E` | Yes |
| S13 | Completion means reaching the designated final marking, not merely a dead marking or a prefix ending in Archive. | A trace ending in `H` at exactly `fm` | A dead marking different from `fm` | No; marking-level validation is required |

Witnesses are illustrative, not a complete language characterization. In particular, a legal review may overlap the verification region at the partial-order level, producing multiple visible interleavings.

# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| **Primary: POWL  accepting Petri net  BPMN** | `convert_to_petri_net(source_powl)`; `convert_to_bpmn(net, im, fm)` | Petri nets directly represent concurrency, synchronization, silence, and looping; avoids forcing block structure prematurely | BPMN gateways and silent routing may be expanded or visually obscure; reverse conversion may alter structure while retaining some behavior | Conversion exception, missing markings, unsound net, or failed invariant/trace comparison |
| **Secondary: POWL  accepting Petri net  process tree  BPMN** | `convert_to_process_tree(net, im, fm)`; on success `convert_to_bpmn(tree)` | Produces a hierarchical, readable, explicitly block-structured artifact | The source’s partial-order dependencies may not be representable faithfully as a process tree; conversion can fail or restructure behavior | Exception, null tree, lost interleaving/concurrency, changed loop language, or failed round-trip validation |
| Optional audit path: BPMN  accepting Petri net | `convert_to_petri_net(bpmn)` | Enables diagnostics and bounded behavior comparison of generated BPMN | It validates the converter’s formal interpretation, not what a human infers from layout | Exception, missing markings, unsoundness, or semantic witness mismatch |

The direct accepting-Petri-net route is primary. The process-tree route is experimental and must not be treated as equivalent merely because conversion returns an object.

# 3. Conversion Code

```python
from pathlib import Path
import traceback
import pm4py

# source_powl is assumed to be the authoritative object created by the code
# in the task statement.

OUT = Path("conversion_artifacts")
OUT.mkdir(parents=True, exist_ok=True)


def require_accepting_net(result, artifact_name):
    """Require the conventional (net, initial marking, final marking) result."""
    if not isinstance(result, tuple) or len(result) != 3:
        raise RuntimeError(
            f"{artifact_name}: expected (net, initial_marking, final_marking), "
            f"received {type(result)!r}"
        )

    net, im, fm = result
    if net is None:
        raise RuntimeError(f"{artifact_name}: conversion returned no Petri net")
    if im is None or fm is None:
        raise RuntimeError(
            f"{artifact_name}: accepting markings are missing "
            f"(im is None={im is None}, fm is None={fm is None})"
        )
    return net, im, fm


def diagnose_accepting_net(name, net, im, fm):
    """Run both required diagnostics without treating a call as proof."""
    report = {
        "workflow_net": None,
        "soundness": None,
        "diagnostic_errors": [],
    }

    try:
        report["workflow_net"] = pm4py.check_is_workflow_net(net)
    except Exception as exc:
        report["diagnostic_errors"].append(
            f"workflow-net diagnostic failed: {type(exc).__name__}: {exc}"
        )

    try:
        report["soundness"] = pm4py.check_soundness(
            net, im, fm, print_diagnostics=True
        )
    except Exception as exc:
        report["diagnostic_errors"].append(
            f"soundness diagnostic failed: {type(exc).__name__}: {exc}"
        )

    print(f"{name}: {report}")
    return report


accepting_nets = {}
bpmn_models = {}
diagnostics = {}
tree_from_net = None
tree_conversion_error = None

# Save the authoritative source visualization. This is illustrative only.
pm4py.save_vis_powl(source_powl, str(OUT / "00_authoritative_source_powl.svg"))

# 1. POWL -> accepting Petri net
net_from_powl, im_from_powl, fm_from_powl = require_accepting_net(
    pm4py.convert_to_petri_net(source_powl),
    "POWL -> Petri net",

accepting_nets["net_from_powl"] = (
    net_from_powl,
    im_from_powl,
    fm_from_powl,
)
diagnostics["net_from_powl"] = diagnose_accepting_net(
    "net_from_powl", net_from_powl, im_from_powl, fm_from_powl
)
pm4py.save_vis_petri_net(
    net_from_powl,
    im_from_powl,
    fm_from_powl,
    str(OUT / "01_powl_to_accepting_petri_net.svg"),
)

# 2. Accepting Petri net -> BPMN
bpmn_from_net = pm4py.convert_to_bpmn(
    net_from_powl, im_from_powl, fm_from_powl
)
if bpmn_from_net is None:
    raise RuntimeError("Petri net -> BPMN returned None")

bpmn_models["bpmn_from_net"] = bpmn_from_net
pm4py.save_vis_bpmn(
    bpmn_from_net,
    str(OUT / "02_petri_net_to_bpmn.svg"),
)

# 3. Every produced BPMN -> accepting Petri net where possible
try:
    net_rt_direct, im_rt_direct, fm_rt_direct = require_accepting_net(
        pm4py.convert_to_petri_net(bpmn_from_net),
        "direct BPMN -> Petri-net round trip",
    )
except Exception as exc:
    print(
        "Direct BPMN round trip failed:",
        f"{type(exc).__name__}: {exc}",
    )
else:
    accepting_nets["net_rt_direct_bpmn"] = (
        net_rt_direct,
        im_rt_direct,
        fm_rt_direct,

    diagnostics["net_rt_direct_bpmn"] = diagnose_accepting_net(

        net_rt_direct,

        net_rt_direct,

# 4. Attempt Petri net -> process tree; failure is meaningful.
try:
    tree_from_net = pm4py.convert_to_process_tree(
        net_from_powl, im_from_powl, fm_from_powl
    )
    if tree_from_net is None:
        raise RuntimeError("Petri net -> process tree returned None")
except Exception as exc:
    tree_conversion_error = exc
    print(
        "Process-tree intermediate unavailable; this may indicate that the "
        "net is not faithfully block-structured:",
        f"{type(exc).__name__}: {exc}",
    )
    traceback.print_exc()
else:
    pm4py.save_vis_process_tree(
        tree_from_net,
        str(OUT / "04_petri_net_to_process_tree.svg"),

    # 5. Successful process tree -> BPMN
    bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)

    bpmn_models["bpmn_from_tree"] = bpmn_from_tree
    pm4py.save_vis_bpmn(

    # 6. Process-tree-derived BPMN -> accepting Petri net
    try:
        net_rt_tree, im_rt_tree, fm_rt_tree = require_accepting_net(

    except Exception as exc:

            "Tree-derived BPMN round trip failed:",
            f"{type(exc).__name__}: {exc}",
        )
    else:
        accepting_nets["net_rt_tree_bpmn"] = (
            net_rt_tree,
            im_rt_tree,
            fm_rt_tree,

        diagnostics["net_rt_tree_bpmn"] = diagnose_accepting_net(

            net_rt_tree,

        pm4py.save_vis_petri_net(
            net_rt_tree,

print("Produced BPMN models:", sorted(bpmn_models))
print("Accepting nets available for validation:", sorted(accepting_nets))
```

The code deliberately checks markings instead of assuming every conversion produced an accepting net. Diagnostic exceptions and process-tree conversion failures remain visible.

# 4. Preservation and Loss Audit

These are design-time assessments until the validation code is executed. “Validated” must only be assigned from actual run evidence.

| Source invariant | POWLPetri | PetriBPMN | PetriTree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| Register is first | expected preserved | expected preserved | ambiguous | not tested | Positive and negative prefix witnesses must be explored |
| Assess/Prepare true concurrency or absence of order | expected preserved | approximated | ambiguous | not tested | A Petri net can encode concurrency; bounded traces only establish both interleavings, not true concurrency |
| No edge/order between Optional Legal and verification | expected preserved | approximated | ambiguous | not tested | Require witnesses placing Legal before and during verification; process trees may force nesting |
| Legal Review optional through a silent branch | expected preserved | approximated | ambiguous | not tested | Tau is hidden; both legal-present and legal-absent completed traces must remain |
| Verification requires Assess and Prepare | expected preserved | expected preserved | ambiguous | not tested | Reject any trace with Configure before either prerequisite |
| Configure before Inspect in every iteration | expected preserved | expected preserved | ambiguous | not tested | Check single and repeated-iteration witnesses |
| Binary-loop semantics: mandatory body, `Correct Defect` redo separator | expected preserved | approximated | ambiguous | not tested | BPMN may render routing rather than an obvious binary loop; tree conversion may reinterpret loop structure |
| At least one verification iteration | expected preserved | expected preserved | ambiguous | not tested | Explicitly reject zero-iteration release witnesses |
| Join before Release | expected preserved | approximated | ambiguous | not tested | Gateway shape is insufficient evidence; Petri behavior must show both branches completed |
| Archive finality and exact final marking | expected preserved | expected preserved | ambiguous | not tested | Completion requires exact equality with `fm`, not merely no enabled transitions |
| Activity-label uniqueness | expected preserved | expected preserved | ambiguous | not tested | Verify each required visible label maps to one visible transition where that is required by governance |
| Initial and final markings | expected preserved | approximated | ambiguous | not tested | BPMN does not expose Petri markings directly; validate markings generated on reconversion |
| Silent routing structure | expected preserved | approximated | ambiguous | not tested | Added tau transitions may be behavior-preserving or may introduce divergence |
| BPMN gateway/routing-node meaning | expected preserved | ambiguous | ambiguous | not tested | Rendering and node placement cannot prove split/join semantics |

A successful process-tree conversion would change its column from `ambiguous` only after language-oriented checks. An exception changes it to `conversion failed`; it is not evidence that the primary route failed.

**Concurrency caveat:** observing both `A,P` and `P,A` traces proves freedom of visible order under the tested conditions, not true step concurrency, independence, or preservation of the source partial-order relation. Interleaving-equivalent sequential-choice machinery can pass those trace tests.

# 5. Round-Trip Validation Code

The following code assumes Section 3 has run and populated `accepting_nets`. It compares the source-derived accepting net with each round-tripped net.

```python
from collections import deque
from dataclasses import dataclass
import pm4py

# Exact labels from the authoritative source.
R = "Register Change"
A = "Assess Risk"
P = "Prepare Evidence"
L = "Legal Review"
C = "Configure Trial"
I = "Inspect Trial"
D = "Correct Defect"
E = "Release Change"
H = "Archive Change"

REQUIRED_LABELS = {R, A, P, L, C, I, D, E, H}


def marking_key(marking):
    """
    Stable within one in-memory net. Place names are not assumed unique across
    different nets, so this key is used only for exploration inside one net.
    """
    return tuple(sorted(
        (id(place), int(tokens))
        for place, tokens in marking.items()
        if tokens
    ))


def fire_transition(net, marking, transition):
    """
    Standard P/T-net firing using arc weights. This avoids relying on an
    unlisted high-level execution helper.
    """
    result = marking.__class__(marking)

    for arc in transition.in_arcs:
        weight = int(getattr(arc, "weight", 1))
        source = arc.source
        available = int(result.get(source, 0))
        if available < weight:
            raise RuntimeError("Attempted to fire a disabled transition")
        remaining = available - weight
        if remaining:
            result[source] = remaining
        elif source in result:
            del result[source]

    for arc in transition.out_arcs:
        weight = int(getattr(arc, "weight", 1))
        target = arc.target
        result[target] = int(result.get(target, 0)) + weight

    return result


@dataclass(frozen=True)
class ExplorationResult:
    completed_traces: frozenset
    visible_prefixes: frozenset
    truncated: bool
    explored_states: int


def bounded_visible_traces(
    net,
    im,
    fm,
    max_visible=14,
    max_correct_defect=2,
    max_tau_steps_between_visible=100,
    max_states=250000,
):
    """
    Explore visible traces while hiding transitions with label None.

    Safeguards:
      * exact marking equality is required for completed traces;
      * state keys include marking, visible trace, redo count, and the set of
        markings reached silently since the last visible event;
      * revisiting a marking through only tau transitions is suppressed;
      * visible length and Correct-Defect count are bounded;
      * a tau-step cap and global state cap guard against silent divergence.

    The result is exhaustive only for states reachable within all these bounds
    and only if `truncated` is False.
    """
    initial = im.__class__(im)
    queue = deque([
        (initial, tuple(), 0, 0, frozenset({marking_key(initial)}))
    ])

    visited = set()
    completed = set()
    prefixes = set()
    truncated = False
    explored = 0

    while queue:
        marking, trace, redo_count, tau_depth, tau_seen = queue.popleft()
        state_key = (
            marking_key(marking),
            trace,
            redo_count,
            tau_depth,
            tau_seen,
        )
        if state_key in visited:
            continue
        visited.add(state_key)

        explored += 1
        if explored > max_states:
            truncated = True
            break

        prefixes.add(trace)
        if marking == fm:
            completed.add(trace)
            # Exact final marking denotes completion; do not extend it here.
            continue

        enabled = list(pm4py.get_enabled_transitions(net, marking))
        for transition in enabled:
            label = transition.label

            if label is None:
                if tau_depth >= max_tau_steps_between_visible:
                    truncated = True
                    continue

                next_marking = fire_transition(net, marking, transition)
                mk = marking_key(next_marking)

                # Prevent infinite or redundant tau-only cycling before the
                # next visible event.
                if mk in tau_seen:
                    continue

                queue.append((
                    next_marking,
                    trace,
                    redo_count,
                    tau_depth + 1,
                    tau_seen | {mk},
                ))
                continue

            if len(trace) >= max_visible:
                truncated = True
                continue

            next_redo_count = redo_count + (1 if label == D else 0)
            if next_redo_count > max_correct_defect:
                truncated = True
                continue

            next_marking = fire_transition(net, marking, transition)
            next_trace = trace + (label,)
            queue.append((
                next_marking,
                next_trace,
                next_redo_count,
                0,
                frozenset({marking_key(next_marking)}),
            ))

    return ExplorationResult(
        completed_traces=frozenset(completed),
        visible_prefixes=frozenset(prefixes),
        truncated=truncated,
        explored_states=explored,
    )


def labels_to_count(net):
    counts = {}
    for transition in net.transitions:
        if transition.label is not None:
            counts[transition.label] = counts.get(transition.label, 0) + 1
    return counts


def must_be_completed(result, *traces):
    return {trace: trace in result.completed_traces for trace in traces}


def must_be_absent_as_prefix(result, *traces):
    return {trace: trace not in result.visible_prefixes for trace in traces}


# Positive witnesses. PLACES OF L relative to verification demonstrate
# absence of a forced order, rather than true concurrency itself.
positive_witnesses = [
    (R, A, P, C, I, E, H),             # legal skipped
    (R, P, A, C, I, E, H),             # P before A
    (R, A, P, L, C, I, E, H),          # legal before verification
    (R, A, P, C, L, I, E, H),          # legal during verification
    (R, A, P, C, I, L, E, H),          # legal after verification body
    (R, A, P, C, I, D, C, I, E, H),    # one repetition
]

# Negative witnesses may be impossible completed traces or forbidden prefixes.
negative_completed = [
    (R, A, P, E, H),                    # zero verification iterations
    (R, A, P, I, C, E, H),             # Inspect before Configure
    (R, A, P, C, I, C, I, E, H),       # repeat without Correct Defect
    (R, A, P, D, C, I, E, H),          # Correct before first iteration
    (R, L, A, P, C, I, E, H),          # Legal before Assess
    (R, A, P, C, I, H, E),             # Archive before Release
]

negative_prefixes = [
    (A,),                                # Register not first
    (R, A, C),                           # verification before Prepare
    (R, P, C),                           # verification before Assess
    (R, A, P, E),                        # release before verification
    (R, A, P, C, I, E, L),              # legal after release
]


def safe_call(description, fn):
    try:
        return {"ok": True, "value": fn(), "error": None}
    except Exception as exc:
        return {
            "ok": False,
            "value": None,
            "error": f"{type(exc).__name__}: {exc}",
        }


def validate_net(name, net, im, fm):
    report = {"name": name}

    report["workflow_net"] = safe_call(
        "workflow net",
        lambda: pm4py.check_is_workflow_net(net),
    )
    report["soundness"] = safe_call(
        "soundness",
        lambda: pm4py.check_soundness(
            net, im, fm, print_diagnostics=True
        ),
    )
    report["footprints"] = safe_call(
        "footprints",
        lambda: pm4py.discover_footprints(net, im, fm),
    )
    report["reachability_graph"] = safe_call(
        "reachability graph",
        lambda: pm4py.convert_to_reachability_graph(net, im, fm),
    )

    counts = labels_to_count(net)
    report["visible_label_counts"] = counts
    report["required_labels_present"] = REQUIRED_LABELS.issubset(counts)
    report["required_labels_unique"] = all(
        counts.get(label, 0) == 1 for label in REQUIRED_LABELS
    )

    exploration = bounded_visible_traces(
        net,
        im,
        fm,
        max_visible=14,
        max_correct_defect=2,
        max_tau_steps_between_visible=100,
        max_states=250000,
    )
    report["exploration"] = exploration
    report["positive_witnesses"] = must_be_completed(
        exploration, *positive_witnesses
    )
    report["negative_completed_absent"] = {
        trace: trace not in exploration.completed_traces
        for trace in negative_completed
    }
    report["negative_prefixes_absent"] = must_be_absent_as_prefix(
        exploration, *negative_prefixes
    )
    return report


def compare_bounded_languages(reference_report, candidate_report):
    ref = reference_report["exploration"]
    cand = candidate_report["exploration"]

    return {
        "equal_completed_trace_sets":
            ref.completed_traces == cand.completed_traces,
        "missing_completed_traces":
            sorted(ref.completed_traces - cand.completed_traces),
        "extra_completed_traces":
            sorted(cand.completed_traces - ref.completed_traces),
        "equal_visible_prefix_sets":
            ref.visible_prefixes == cand.visible_prefixes,
        "missing_prefixes":
            sorted(ref.visible_prefixes - cand.visible_prefixes),
        "extra_prefixes":
            sorted(cand.visible_prefixes - ref.visible_prefixes),
        "reference_truncated": ref.truncated,
        "candidate_truncated": cand.truncated,
        "exhaustive_under_configured_bounds":
            not ref.truncated and not cand.truncated,
    }


# Validate the source-derived net and every available BPMN round trip.
validation_reports = {}
for name, (net, im, fm) in accepting_nets.items():
    validation_reports[name] = validate_net(name, net, im, fm)

reference = validation_reports["net_from_powl"]
comparisons = {}

for name, report in validation_reports.items():
    if name == "net_from_powl":
        continue
    comparisons[name] = compare_bounded_languages(reference, report)

for name, report in validation_reports.items():
    print("\nVALIDATION:", name)
    print("workflow_net:", report["workflow_net"])
    print("soundness:", report["soundness"])
    print("label counts:", report["visible_label_counts"])
    print("required labels unique:", report["required_labels_unique"])
    print("positive witnesses:", report["positive_witnesses"])
    print("negative completed absent:", report["negative_completed_absent"])
    print("negative prefixes absent:", report["negative_prefixes_absent"])
    print(
        "bounded exploration:",
        {
            "completed_count": len(report["exploration"].completed_traces),
            "prefix_count": len(report["exploration"].visible_prefixes),
            "states": report["exploration"].explored_states,
            "truncated": report["exploration"].truncated,
        },
    )

for name, comparison in comparisons.items():
    print("\nCOMPARISON WITH SOURCE-DERIVED NET:", name)
    print(comparison)
```

`discover_footprints` and reachability-graph construction provide additional evidence, but object equality is not assumed to mean semantic equivalence. Footprint comparison is especially coarse around loops, silence, and concurrency.

The trace comparison is **not globally exhaustive**, because the source contains an unbounded loop. It is exhaustive only within the configured visible-length, redo-count, tau-depth, and state limits when `truncated` is false. If `truncated` is true, even bounded completeness has not been established.

Model/trace playout is omitted because no needed playout signature is guaranteed by the supplied API reminders. The explicit state-space exploration gives reproducible witness checks without inventing an API.

# 6. Visual-Semantics Review

A BPMN diagram can be behaviorally acceptable when reconverted to a Petri net and still invite incorrect human interpretations:

- **Parallel gateways:** A parallel split may correctly expose Assess and Prepare concurrently, but a reader may assume that visually left-to-right placement imposes order. Conversely, converter-generated gateway chains may encode synchronization without looking like one simple split/join pair.
- **Exclusive gateways:** Optional Legal may appear as an XOR gateway with one unlabeled bypass. The bypass can be mistaken for a missing branch, an error, or unconditional flow. It represents the silent alternative.
- **Loop visualization:** The POWL loop is binary: execute the body at least once, then either exit or execute Correct Defect and repeat. A BPMN back-edge can be misread as allowing Correct Defect before the first trial, permitting zero iterations, or repeating only Inspect Trial.
- **Silent routing nodes:** Tau transitions may become gateways, intermediate routing structures, or unlabeled paths. Their visual presence does not imply business activity, and their omission from a simplified view does not prove they are behaviorally irrelevant.
- **Gateway pairing:** A split and join that look paired by proximity need not form a block. The converter may create several gateways to preserve Petri-net behavior.
- **Graph layout:** Vertical or horizontal position is a layout decision. Legal drawn above Configure does not imply Legal precedes Configure unless sequence-flow semantics enforce it.
- **Join before Release:** A line entering Release is not sufficient evidence that both legal completion/bypass and verification completion are required. The synchronization must be checked in the formal model.
- **Apparent concurrency:** Side-by-side activities may merely represent XOR or arbitrary drawing placement. Conversely, a serial-looking layout can still contain concurrent branches.

Recommended documentation:

1. Add a note: “Diagram placement does not define order; only sequence flow and gateway semantics do.”
2. Label the legal bypass **“Skip Legal Review”**, while documenting that it is a silent routing choice, not a source activity.
3. Add a loop annotation: **“Trial body executes at least once; repeat path is Correct Defect  Configure Trial.”**
4. Annotate Release: **“Requires legal branch completion/bypass AND verification completion.”**
5. Mark Assess and Prepare: **“Unordered after registration.”**
6. Include the artifact version, source POWL hash, PM4Py version, conversion path, and validation-report identifier.
7. Keep a small invariant/witness legend adjacent to the diagram.

# 7. Rejection Criteria

Reject or quarantine a derivative if any of the following occurs:

1. POWL-to-Petri, Petri-to-BPMN, or required BPMN round-trip conversion raises an exception or returns `None`.
2. An accepting-net conversion lacks a non-null initial or final marking.
3. `check_is_workflow_net` returns false or cannot complete reliably.
4. `check_soundness` returns false, reports unsoundness, or fails diagnostically.
5. Register is not the first visible activity.
6. Either `Assess  Prepare` or `Prepare  Assess` witness is lost.
7. Configure Trial can occur before either Assess Risk or Prepare Evidence.
8. The optional behavior collapses: Legal becomes mandatory, or Legal can no longer occur.
9. Legal Review can occur before Assess Risk.
10. The derivative forces an order between Legal and verification that eliminates required source interleavings.
11. Release can occur before one mandatory verification iteration completes.
12. Release does not synchronize verification with completion or bypass of the legal branch.
13. A zero-iteration verification trace is admitted.
14. Inspect can precede Configure within an iteration.
15. Repetition is admitted without Correct Defect, or Correct Defect is allowed before the first trial.
16. Archive can precede Release or completion can occur without Archive.
17. A purported completed trace ends in a marking not exactly equal to the designated final marking.
18. Required activity labels are missing, changed, duplicated ambiguously, or attached to routing transitions.
19. Bounded comparison finds any extra or missing visible completed trace or forbidden prefix.
20. Exploration truncates before mandatory witnesses can be decided; quarantine rather than claim preservation.
21. Unbounded silent cycling is detected or cannot be ruled out sufficiently for deployment.
22. A process-tree route succeeds syntactically but fails any source-invariant check.

# 8. Canonical Representation Recommendation

The **source POWL should remain authoritative for storage**. It directly states the intended partial order, optional legal branch, and binary verification loop without requiring a block-structured reinterpretation.

Use the **generated BPMN from the direct accepting-Petri-net route for stakeholder visualization**. BPMN is familiar to stakeholders, but it is derivative and must not silently replace the POWL as the editable source.

Artifact policy:

- **Authoritative:** versioned POWL construction/data and its semantic-invariant specification.
- **Primary formal derivative:** accepting Petri net generated directly from POWL, including initial and final markings.
- **Visualization derivative:** BPMN generated from that accepting Petri net.
- **Audit derivative:** Petri net reconverted from BPMN, reachability graph, footprints, witness report, and bounded trace comparison.
- **Experimental derivative:** process tree and its BPMN only if conversion succeeds and all applicable validation passes.

Each derivative should carry:

- source revision or content hash;
- PM4Py and Python versions;
- exact pipeline;
- workflow-net and soundness outcomes;
- visible-label inventory;
- positive/negative witness results;
- bounded-language differences and exploration bounds;
- whether exploration truncated;
- any conversion or diagnostic exceptions.

A process-tree intermediate may be allowed only as an **optional presentation experiment**. It must never be required for publication and must be rejected when conversion fails or changes source behavior. Failure is a valid indication that forcing block structure is inappropriate.

Future edits should be made in the canonical POWL and regenerated outward. Editing generated BPMN and converting it back into POWL or replacing the source with a round-tripped net risks cumulative drift. If stakeholders propose BPMN edits, translate those changes into explicit POWL invariants first, update the POWL, then regenerate and rerun the audit.

# 9. Residual Uncertainty

Even if every proposed test passes, the validation cannot establish:

1. **Global language equivalence.** The verification loop is unbounded, while trace exploration uses finite visible, redo, tau, and state bounds.
2. **True concurrency equivalence.** Both interleavings can be preserved by a model that encodes sequential nondeterminism rather than the same partial-order independence.
3. **Branching-time or history-preserving equivalence.** Equal bounded visible traces do not establish bisimulation, causal equivalence, or preservation of conflict structure.
4. **Absence of all silent divergence.** Bounded tau-cycle controls prevent the validator from hanging but do not constitute a general proof for arbitrary converted nets.
5. **Human interpretation fidelity.** A formally acceptable BPMN artifact can still be misunderstood because of layout, unlabeled bypasses, or gateway complexity.
6. **Correctness outside the tested PM4Py version.** Converter algorithms and normalization choices can change across releases.
7. **Business semantics beyond control flow.** Roles, data conditions, resources, timing, risk thresholds, and the decision rule for Legal Review are not present in the source.
8. **Uniqueness of structural representation.** Behaviorally similar nets or BPMN diagrams may differ substantially in places, transitions, gateways, and routing nodes.
9. **Completeness of footprints as an equivalence test.** Matching footprints does not prove matching languages, loop scope, finality, or silent behavior.
