## 1. Consistency rules and evidence model

**Hard invariants.**
- *Referential integrity.* Every relation must reference an existing event and an existing object; no invented identifiers.
- *Customer coherence.* ORD-A, ORD-B, and INV-44 all carry `customer=C17`, so any candidate linking them is not blocked by a customer mismatch.

- *Lifecycle order.* A Pack event must follow an Add Item event for the same item; Dispatch must follow Pack; Confirm Delivery should follow Dispatch; Issue Invoice must follow at least one Order Create; Record Payment should follow Issue Invoice. These are temporal ordering constraints, not exact-time constraints.

**Strong defaults.**
- *Cardinality of Create/Add/Pack/Dispatch/Payment.* From rules 1, 2, 3, 4, 7: each Create Order relates to one Order; each Add Item relates to one Order and one Item; each Pack Item to one Item and one Package (with the explicit scanner-outage exception); each Dispatch to one Package and one Delivery; each Payment to one Payment object and normally one Invoice.
- *Direction of qualifiers (rule 8).* `carries`, `packs`, `bills`, `settles`, `contains` are directional and stored in one orientation; the reverse is not implied.

**Weak heuristics.**
