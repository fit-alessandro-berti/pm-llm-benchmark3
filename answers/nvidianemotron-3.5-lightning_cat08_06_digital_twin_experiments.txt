## 5. Warmup, replications, and uncertainty treatment

**Warmup approach**  
Discard initial transient period. Two equivalent strategies:  
1. Run first 5% of simulated clock time (30days in a 6month horizon) with zero initial backlog, then record metrics.  
2. Use “equilibration”: retain simulation output only after average queue length across consecutive 7day windows changes <3%.  
Warmup period is validated by checking that resource utilization and case counts stabilize across the transition.

**Run length**  
Simulate 3 calendar years (365×3 = 1095simulated days) to capture multiple nonstationary cycles (summer peaks, winter troughs, councilmeeting rotations). This horizon corresponds to ~95000 cases (31200 × 3), ensuring steadystate metrics with <5% confidenceinterval width for median durations.

**Replications**  
30 independent replications per experiment. Each replication uses a unique random seed (e.g., seeds 101–130). Compute 95% confidence intervals on median total duration, rework rate, throughput. For heavytailed outputs (p90 durations, publicnotice with objections), also report 90% prediction intervals via block bootstrap (1000 resamples).

**Random seeds**  
Set via `numpy.random.seed(seed)` before each replication; seed list provided in supplementary materials for reproducibility across experiments.

**Heavytailed durations**  
Model service/publicnotice/inspection travel with lognormal or Gamma distributions fitted to empirical median/p90. For publicnotice with objections, use a mixture: 60% base duration (from empirical minimum), 40% extended with a Pareto tail (scale 20d, shape 1.2) to capture longtail objection effects. Sensitivity analysis on tail shape parameter (±0.3) as part of uncertainty analysis.

**Sensitivity analysis**  
- Onefactoratatime (OAT) on key parameters: arrival base rate (±20%), resource FTE (±1), rework probability (±5pp), seasonal multiplier (±0.2).  
- Followed by variancebased Sobol indices on primary outputs (median duration, rework rate, resource utilization) to identify the top 3 most influential parameters for targeted calibration.

**Uncertainty treatment**  
Report median and interquartile range (IQR) across the 30 replications for each metric. For decision criteria (Section7), use the 25th75th percentile range as a robustness indicator; interventions whose benefits persist across this range are preferred. Credible intervals (Bayesian alternative) not required but could be approximated via MCMC on key distribution parameters if desired.



## 6. Validation strategy

**Face validation**  
Workshop with municipal planning department staff. Present simulated workflow diagrams (DFG, queue lengths, calendar gating). Validate that activity sequences, resource assignments, and rework loops match known process knowledge. Check that policy overrides (D2, D5) behave as intended and that districtspecific travel times are correctly applied.

**Eventlog replay validation**  
Use PM4Py tokenbased or frontier replay on a holdout sample (e.g., last 6months of the log). Compare simulated trace precision/recall against observed traces. Compute trace fitness fraction. Validate that activity timing distributions (waiting + service) match empirical medians/p90 from the summary table. Focus on highfrequency activities: Completeness check, Planning review, Inspection scheduling.

**Distributional validation**  
For each activity, plot simulated duration histogram against empirical kernel density from the log. Use KolmogorovSmirnov test or QQ plot comparison. Focus on heavytailed activities: publicnotice, inspection travel, rework loops. Ensure simulated p90 aligns with reported p90 within 10% margin. If discrepancies >10%, revisit distribution assumptions or calendar gating.

**Resourceutilization validation**  
Sum simulated working hours per week per role. Compare to FTE capacity (e.g., 5 clerks × 8h × 5d = 200h/week). Check for sustained >90% utilization indicating bottleneck. Validate observed historical bottlenecks (Planning review queue spikes after Monday submissions, Fire reviewer parttime calendar constraints) are reproduced in simulation output.

**Bottleneck validation**  
Identify simulated activities with highest average utilization or longest mean waiting time. Crossreference with known bottlenecks from the eventlog summary: Planning review (district/type dependent), Fire reviewer (parttime calendar), Inspectors (travel/D3/D5). Use heatmaps of weekly utilization by role to visually confirm alignment.

**Outofsample validation**  
Calibrate model on 12months of log data, hold out the remaining 6months (or a specific district/case type). Run simulation with heldout parameters and compare predicted vs actual case durations, rework rates, and resource utilization. Use mean absolute percentage error (MAPE) on median durations; target <15% for acceptance. If MAPE exceeds threshold, revisit parameter estimates or dependency modeling.



## 7. Decision criteria

**Decision metrics** (per experiment, averaged across 30 replications):

1. **Median total duration** (days): from case submission to permit issue/reject, per case type.  
2. **p90 total duration** (days): tail risk; SLAbreach indicator.  
3. **SLA compliance rate** (%): proportion of cases meeting typespecific targets (Simple reno 30d, New residential 60d, Commercial 90d, Complex variance 180d).  
4. **Rework rate** (%): cases experiencing 1 rework loop (after Planning, Inspection, Legal, Appeal).  
5. **Resource utilization** (%): average and peak weekly usage per role; peak must not exceed 95% to avoid instability.  
6. **Backlog age index**: % cases waiting >60d, % waiting >90d.  
7. **Fairness index**: ratio of median duration across districts (D3/D5 vs D1/D2); also architectburst impact: variance of cases per architect within simulation.  
8. **Policy robustness score**: weighted average rank of experiment performance across 3 stress scenarios (S1–S3); higher weight on scenarios most likely (e.g., S1 given seasonal patterns).

**Thresholds for selecting interventions**

- **Minimum improvement**: Must reduce median total duration by 5% for at least 3 case types without increasing p90 by >10% for any type.  
- **Rework constraint**: Rework rate must not increase by >3 percentage points relative to baseline.  
- **Resource constraint**: Average resource utilization 90%; peak utilization 95% in any week.  
- **Fairness constraint**: District duration ratio must not worsen by >15% relative to baseline; architect variance must not increase by >20%.  
- **Robustness requirement**: Intervention must retain top2 ranking in robustness score across at least 2 of 3 stress scenarios.  
- **Cost/benefit implicit**: Interventions requiring additional FTE (e.g., D4) must show sufficient duration reduction to justify cost, or be evaluated under budget constraints not modeled here. Interventions that improve fairness or reduce backlog without exceeding resource limits are favored when tradeoffs are comparable.

class ArrivalGenerator:
    """Nonstationary case arrival generator."""
    def __init__(self, base_daily_rate, monday_mult=2.2, season_peaks=None):
        self.base_rate = base_daily_rate
        self.monday_mult = monday_mult
        self.season_peaks = season_peaks or {3:1.7, 4:1.7, 5:1.7, 9:1.7, 10:1.7, 11:1.7}

    def daily_count(self, date):
        import datetime as dt
        dow = date.weekday()  # 0=Mon
        month = date.month
        mult = 1.0
        if dow == 0: mult *= self.monday_mult
        if month in self.season_peaks: mult *= self.season_peaks[month]
        return int(np.random.poisson(self.base_rate * mult))


class ResourceCalendar:
    """Resource working calendar with FTE, daily hours, weekly days, and holidays."""
    def __init__(self, fte, work_start, work_end, weekly_days, holidays=None):
        self.fte = fte
        self.work_start = work_start
        self.work_end = work_end
        self.weekly_days = weekly_days  # e.g., [0,1,2,3,4] MonFri
        self.holidays = holidays or []

    def is_working_time(self, dt_obj):
        if dt_obj.weekday() not in self.weekly_days: return False
        if dt_obj.date() in self.holidays: return False
        h = dt_obj.hour + dt_obj.minute/60
        return self.work_start <= h < self.work_end
