## 6. Candidate Site B intervention

Do not copy Site A’s universal parallel Identity/Document task. Instead, implement a segmented, legally compliant parallel-verification intervention.

Eligibility rules:
- At Register, classify each case as `originals_required`, `digital_complete`, `legal_required`, and `complexity_band`.
- Lane D, digital/no-originals: `originals_required = false` and documents are digitally available and complete. Identity Check and Document Check may be executed concurrently.
- Lane O, originals-required: `originals_required = true`. Identity Check and Originals Receipt may proceed concurrently. Document Check may not start until Originals Receipt is complete.
- Excluded or held cases: fraud hold, missing mandatory registration fields, illegible uploads, or incomplete mandatory documents. These enter a triage queue before parallel release.

Task creation and execution:
- In Lane D, create and release Identity Check and Document Check as executable tasks immediately after Register.
- In Lane O, create Identity Check immediately and create Originals Receipt as an external tracking task or milestone. Document Check may be created in a blocked state, but it must not count as active WIP and must not be assignable until originals are received.
- Assessment may start only after both Identity Check and Document Check are complete.
- Legal Review remains mandatory for public-sector and high-value cases. Legal Review occurs after Assessment and before final Approve/Reject.
- If Legal Review issues Request Supplement, create a supplement task, repeat Document Check as needed, then repeat Assessment and return to Legal Review.

Queue and WIP controls:
- Maximum active tasks per reviewer: Identity 5, Document 6, Assessment 4, Legal 3.
- Blocked Document Check tasks do not count as active reviewer WIP.
- Release new parallel tasks only when downstream Assessment queue is below a defined threshold.
- Rework and supplement tasks receive priority over new intakes to avoid loop accumulation.
- Daily queue review should monitor role-specific queues, but it should be standardized so it is not an uncontrolled co-intervention.

Resource responsibilities:
- Identity reviewers execute Identity Check only.
- Document reviewers execute Document Check only, including repeat checks after supplements.
- Assessors execute Assessment only.
- Legal reviewers execute Legal Review and supplement decisions.
- Mailroom/service desk owns Originals Receipt and logs receipt time.
- No role should bypass the case lock unless a controlled subtask or milestone design has been approved.

Logging requirements:
- Log case flags: `originals_required`, `legal_required`, `digital_complete`, `complexity_band`.
- Log task states: created, blocked, eligible, active, suspended, complete.
- Use system-generated timestamps for active and complete events.
- Prohibit backdated start events except through audited correction.
- Record supplement reason and whether Document Check or Assessment was repeated.

Compact POWL-style partial-order specification:

```text
Common:
  Register  Notify
  Final decision  Notify

Lane D, digital/no originals:
  Register  Identity Check
  Register  Document Check
  Identity Check  Document Check
  Identity Check  Assessment
  Document Check  Assessment

Lane O, originals required:
  Register  Identity Check
  Register  Originals Receipt
  Identity Check  Originals Receipt
  Originals Receipt  Document Check
  Identity Check  Assessment
  Document Check  Assessment

Legal-required branch:
  Assessment  Legal Review
  Legal Review  Approve_after_Legal | Reject_after_Legal
  or
  Legal Review  Request Supplement
  Request Supplement  Document Check_repeat
  Document Check_repeat  Assessment_repeat
  Assessment_repeat  Legal Review

Non-legal branch:
  Assessment  Approve | Reject
```

## 7. Pilot for transport learning

| design element | specification | causal purpose | operational safeguard | process-mining measurement |

| Treatment versions | T0 current sequential/statutory process; T1 Lane D immediate Identity/Document; T2 Lane O Identity/Originals with deferred Document; T3 T1/T2 plus WIP and IT-lock fix | Separates structural parallelization from implementation supports | Training and role instructions before launch | Task state transitions and active intervals |

Secondary: p90 cycle time, true overlap, rework, supplements, appeals, role utilization | Measures both end-to-end effect and mechanism pathway | Common metric definitions frozen before pilot | Event-log derived cycle time, waiting, overlap, loop counts |

| Power / minimum support | Target detection of about 4h median reduction from 44h baseline; with SD around 20h, 80% power and alpha 0.05 requires roughly 400 cases per arm; minimum 800 eligible cases or 12 weeks | Ensures enough precision for a policy decision | Stop early if volume is too low | Cumulative eligible cases per arm |

| Transportability analysis | Estimate stratum-specific treatment effects; compare true overlap to waiting reduction; use Site A only as a prior, not as ground truth; test sensitivity to timestamp corrections | Quantifies whether the Site A mechanism transports | Pre-registered analysis plan | Causal mediation-style comparison: treatment  true overlap  waiting  cycle time |

The pilot distinguishes mechanism failure from implementation failure by measuring both fidelity and pathway. Implementation fidelity is true overlap, correct task states, no blocked document work, WIP compliance, and clean timestamps. Mechanism pathway is whether true overlap reduces waiting before Assessment and cycle time. If treated cases achieve high true overlap but waiting/cycle time does not fall, the parallelization mechanism is not transporting—likely because assessment/legal capacity, originals delays, or complexity dominate. If true overlap is low because the legacy lock prevents simultaneous ownership, staff back-enter events, or document tasks are created while originals are missing, the pilot identifies implementation failure; the mechanism may still be valid after IT/workflow fixes. Stratifying by originals requirement and legal review prevents misattributing statutory constraints to treatment. Randomized or phased assignment, together with interference caps, separates the treatment effect from secular trends and co-interventions. Stop rules protect against quality harm.

## 8. PM4Py model-construction code

```python
import pm4py
from pm4py.objects.powl import obj as powl_obj

# ---------------------------------------------------------------------
# 1. Site A before/after process trees
# ---------------------------------------------------------------------

tree_a_before = pm4py.parse_process_tree(
    "-> ( 'Register', 'Identity Check', 'Document Check', 'Assessment', "
    "X ( 'Approve', 'Reject' ), 'Notify' )"
)

tree_a_after = pm4py.parse_process_tree(
    "-> ( 'Register', + ( 'Identity Check', 'Document Check' ), 'Assessment', "
    "X ( 'Approve', 'Reject' ), 'Notify' )"
)

net_a_before, im_a_before, fm_a_before = pm4py.convert_to_petri_net(tree_a_before)
net_a_after, im_a_after, fm_a_after = pm4py.convert_to_petri_net(tree_a_after)

# ---------------------------------------------------------------------
# 2. Helper functions for POWL construction
# ---------------------------------------------------------------------

def get_class(*names):
    for name in names:
        cls = getattr(powl_obj, name, None)
        if cls is not None:
            return cls
    raise AttributeError(f"None of these POWL classes found: {names}")

def get_class_or_none(*names):
    for name in names:
        cls = getattr(powl_obj, name, None)
        if cls is not None:
            return cls
    return None

StrictPartialOrder = get_class("StrictPartialOrder")
Choice = get_class("Choice", "ExclusiveChoice", "Xor")
Loop = get_class("Loop")

# Task constructors can vary by PM4Py version.
VisibleTask = get_class_or_none("VisibleTask", "Task", "AtomicTask", "Activity")

def task(label):
    if VisibleTask is not None:
        return VisibleTask(label)
    # Some POWL implementations accept plain string labels.
    return label

def make_choice(children):
    try:
        return Choice(list(children))
    except TypeError:
        return Choice(*children)

def make_loop(children):
    # Try common constructor shapes. POWL/Loop APIs can vary by version.
    attempts = [
        lambda: Loop(list(children)),
        lambda: Loop(*children),
        lambda: Loop(children=list(children)),
    ]
    last_error = None
    for attempt in attempts:
        try:
            return attempt()
        except TypeError as e:
            last_error = e
    raise TypeError(f"Could not construct Loop with children {children}: {last_error}")

# ---------------------------------------------------------------------
# 3. Site B candidate POWL model
#
# This model represents the originals-required lane, which is the safer
# transport target for Site B. The digital/no-originals lane is analogous,
# except Originals Receipt is omitted and Document Check can start after
# Register.
#
# The model cannot encode data-dependent eligibility, resource capacity,
# case locks, or durations. Those are operational constraints outside
# pure control-flow.
# ---------------------------------------------------------------------

def build_site_b_powl(originals_required=True, legal_optional=True):
    R = task("Register")
    I = task("Identity Check")
    A = task("Assessment")
    N = task("Notify")

    if originals_required:
        O = task("Originals Receipt")
        D = task("Document Check")

        core_children = [R, I, O, D, A]

        # Explicit strict partial-order edges.
        # Important: Assessment waits for both Identity and Document.
        # Identity and Originals Receipt are unordered, allowing concurrency.
        # Originals Receipt precedes Document Check because of statutory rule.
        core_order = {
            (R, I),
            (R, O),
            (O, D),
            (I, A),
            (D, A),
            # Explicit transitive edges for clarity and compatibility.
            (R, D),
            (R, A),
        }
    else:
        D = task("Document Check")

        core_children = [R, I, D, A]

        # Digital/no-originals lane: Identity and Document are unordered.
        core_order = {
            (R, I),
            (R, D),
            (I, A),
            (D, A),
            (R, A),
        }

    # Plain non-legal decision branch.
    approve_plain = task("Approve")
    reject_plain = task("Reject")
    plain_decision = make_choice([approve_plain, reject_plain])

    if legal_optional:
        # Legal branch with a supplement loop.
        # Legal Review can either finish through a legal decision or trigger
        # Request Supplement -> Document Check repeat -> Assessment repeat,
        # after which Legal Review becomes possible again.
        approve_legal = task("Approve after Legal")
        reject_legal = task("Reject after Legal")
        legal_decision = make_choice([approve_legal, reject_legal])

        L = task("Legal Review")
        S = task("Request Supplement")
        D_repeat = task("Document Check (repeat)")
        A_repeat = task("Assessment (repeat)")

        supplement_spo = StrictPartialOrder(
            [S, D_repeat, A_repeat],
            {
                (S, D_repeat),
                (D_repeat, A_repeat),
                (S, A_repeat),
            }
        )

        # Loop semantics are version-dependent. The intended semantics are:
        # do Legal Review, then either exit via legal_decision or redo via
        # the supplement path and return to Legal Review.
        legal_loop = make_loop([L, supplement_spo, legal_decision])

        # Optional legal branch: case mix may or may not require legal review.
        # Data-dependent routing is not encoded in the Petri net.
        post_assessment = make_choice([plain_decision, legal_loop])
    else:
        post_assessment = plain_decision

    top_children = core_children + [post_assessment, N]

    # Assessment precedes the post-assessment branch; branch precedes Notify.
    top_order = set(core_order)
    top_order.update({
        (A, post_assessment),
        (post_assessment, N),
        (A, N),
    })

    return StrictPartialOrder(top_children, top_order)

powl_b_originals_legal = build_site_b_powl(
    originals_required=True,
    legal_optional=True
)

# ---------------------------------------------------------------------
# 4. Convert Site B POWL model to accepting Petri net
# ---------------------------------------------------------------------

net_b, im_b, fm_b = pm4py.convert_to_petri_net(powl_b_originals_legal)

# ---------------------------------------------------------------------
# 5. Check workflow-net and soundness properties
# ---------------------------------------------------------------------

def check_net(name, net, im, fm):
    try:
        wf = pm4py.check_is_workflow_net(net)
        print(f"{name}: workflow-net = {wf}")
    except Exception as e:
        print(f"{name}: workflow-net check unavailable: {e}")

    try:
        try:
            sound = pm4py.check_soundness(net, im, fm)
        except TypeError:
            sound = pm4py.check_soundness(net)
        print(f"{name}: soundness = {sound}")
    except Exception as e:
        print(f"{name}: soundness check unavailable: {e}")

check_net("Site A before", net_a_before, im_a_before, fm_a_before)
check_net("Site A after", net_a_after, im_a_after, fm_a_after)
check_net("Site B candidate POWL", net_b, im_b, fm_b)

# ---------------------------------------------------------------------
# 6. Optional playout: print a few sample traces
# ---------------------------------------------------------------------

try:
    log_b = pm4py.play_out(powl_b_originals_legal)
    for idx, case in enumerate(log_b):
        if idx >= 3:
            break
        trace = [e.get("concept:name") for e in case]
        print(f"Sample Site B trace {idx + 1}: {trace}")
except Exception as e:
    print(f"Playout unavailable or non-finite for this POWL model: {e}")

# ---------------------------------------------------------------------
# 7. What the model cannot encode
#
# - Data-dependent legal requirements: whether Legal Review is mandatory
#   depends on public-sector/high-value flags, not on control-flow alone.
# - Statutory document availability: Originals Receipt delay is external
#   and variable; the net only encodes precedence, not waiting time.
# - Resource capacity: identity, document, assessment, and legal pools
#   have finite FTEs and cannot be represented by this control-flow model.
# - Legacy case lock: the one-active-task-owner constraint is an IT/state
#   constraint, not a Petri-net precedence relation.
# - Durations and service-time distributions: cycle-time effects require
#   simulation or event-log analysis, not just structural soundness.
# - Timestamp quality: back-entered events can make nominal overlap look
#   like true overlap; the model cannot distinguish them.
# ---------------------------------------------------------------------
```

## 9. Recommendation

`conditional go`

We should transfer the mechanism, not Site A’s literal control-flow. The transferable idea is to make verification tasks start as soon as they are legally and informationally executable, thereby reducing idle time before Assessment. Site B should not copy “create Identity Check and Document Check simultaneously for every case” because Document Check is statutorily blocked for 62% of cases, legal review and supplement loops affect 40% of cases, and the legacy case lock can make nominal parallel tasks impossible to execute. The first subgroup should be digital, no-originals, low-to-medium complexity cases that do not require legal review. This subgroup has the closest structural match to Site A: Document Check can start immediately, identity and document data are separable, and the main expected pathway is reduced waiting before Assessment. A second early subgroup can be originals-required cases, but the intervention there is only Identity Check in parallel with Originals Receipt, with Document Check released after receipt. Expected benefits are modest: median cycle-time reduction perhaps 2-6 hours overall initially, with larger gains in the digital subgroup and possible waiting reduction before Assessment. Risks include assessment/legal bottleneck shift, worse p90, increased rework if cases are assessed before documents are truly complete, false overlap from back-entered timestamps, and resource contention caused by simultaneous task release. Expansion should occur only if the pilot shows high true overlap, reduced waiting before Assessment, stable or improved rework/appeals, and no material p90 deterioration in treated cases. Modification is needed if the median improves but p90 worsens: add assessment/legal capacity, WIP limits, or prioritize complex/legal cases. Abandon or pause if true overlap cannot be achieved after IT/workflow fixes, if rework/appeals exceed stop thresholds, or if the legal/supplement loop dominates and parallelization adds no end-to-end benefit.

## 10. Assumption register

1. For cases flagged as no-originals-required, Document Check can legally and operationally start immediately after Register — needed to define the digital parallel lane — test with legal policy review and a sample case audit — if false, the digital lane must be narrowed, delayed, or redesigned.

2. Identity Check and Document Check can be performed independently without requiring the output of the other — needed for true concurrency to shorten the critical path — test dependency mapping and reviewer interviews — if false, parallelization will increase rework rather than reduce cycle time.

3. A meaningful part of Site A’s improvement came from reduced serial waiting, not only from co-interventions — needed to justify a Site B pilot — test stratified reanalysis of Site A and Site B pilot mechanism metrics — if false, Site A evidence provides little support for transfer.

4. Site B identity and document pools have enough slack to absorb earlier parallel release without harming other work — needed to avoid queue saturation — test baseline utilization and queue depth — if false, WIP limits or added capacity are required before expansion.

5. Assessment and Legal Review capacity can absorb earlier verification completions without severe tail growth — needed because parallelization can shift the bottleneck — test queue simulation or pilot monitoring — if false, median may improve while p90 worsens.

6. The legacy case lock can be modeled around with controlled task states, subtasks, or milestones without compromising auditability — needed for true parallel execution and measurement — test IT sandbox and user workflow — if false, nominal parallelism will produce false overlap and little real gain.

7. System-generated timestamps can be enforced and back-entry can be audited — needed to distinguish true overlap from measurement artifact — test timestamp policy and event-log audit — if false, process-mining evaluation cannot support causal claims.

8. A randomized or phased pilot is operationally feasible with limited interference between treatment and control cases — needed to identify transport effects — test intake volume, assignment controls, and resource sharing — if false, use a carefully analyzed stepped-wedge or interrupted time-series design instead.
