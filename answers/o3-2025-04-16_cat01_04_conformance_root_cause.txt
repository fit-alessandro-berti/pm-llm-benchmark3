## 3. Causal-abductive explanation
```
UI_release -> recorded_labels
UI_release -> true_process (none)
ETL_change -> recorded_order
ETL_change -> recorded_labels? (resource blanks)
policy_change -> true_process -> recorded_labels ("Supervisor Sign-off")
policy_change -> normative_model (stale)
recorded_labels + recorded_order + technical_gateway_event -> alignment_moves
alignment_moves -> measured_fitness
measured_fitness -> (perception of) compliance_drop
true_process --> business_outcomes
reviewer_behavior -> true_process
hidden_variable: logging_noise -> recorded_labels, recorded_order
```

Multiple mechanisms interact.  
The 4.2 UI release merely re-captioned the classification step, yet that new label breaks the string-matching conformance checker. A gateway patch adds “Queue Routed,” inflating traces with a non-functional transition. An ETL shortcut replaces source timestamps with warehouse-ingest time for two activities, reversing their apparent order. Together these three data-generation defects lower fitness from 93 % to 32 %.  

In August, a genuine policy introduces “Supervisor Sign-off.” Because the normative model was not updated, those legitimate events continue to be flagged as deviations. Once we map the altered labels, remove technical events, restore order by source sequence, and extend the model with an optional sign-off, fitness rebounds to 86 %. Residual mis-moves mostly concern “Manual Override” (potentially genuine) and missing “Compliance Check,” whose reality is still unclear.  

Stable approval, cycle time, and appeal metrics show that operational outputs did not deteriorate, but they cannot guarantee compliance—undetected bypasses might be rare yet material. Thus poor conformance scores stem chiefly from data-semantics drift and model staleness, yet a smaller unresolved slice could still reflect real reviewer behaviour.

## 6. PM4Py reproduction and model-comparison code
```python
import pm4py
from pm4py.objects.process_tree import parser as pt_parser
from pm4py.objects.log.obj import EventLog, Trace, Event
from pm4py.algo.discovery.dfg import algorithm as dfg_disc
from pm4py.algo.conformance.alignments import algorithm as align_algo
from copy import deepcopy

# 1. encode normative tree
tree_str = "-> ('Receive','Classify',X(*( 'Standard Review','Request Info'),->('Enhanced Review','Compliance Check')),'Decision','Notify')"
tree = pt_parser.parse_process_tree(tree_str)

# 2. convert to Petri net
net, im, fm = pm4py.convert_to_petri_net(tree)

# helper to create traces from variant strings and counts
def make_log(variant_freq):
    log = EventLog()
    for variant, count in variant_freq:
        activities = variant.split(',')
        for _ in range(count):
            t = Trace()
            for idx, act in enumerate(activities):
                ev = Event({"concept:name": act,
                            "time:timestamp": pm4py.utils.get_properties_random_date()})
                t.append(ev)
            log.append(t)
    return log

# 3. expand supplied tables (subset for brevity)
apr_may = [
    ("Receive,Classify,Standard Review,Decision,Notify", 380),
    ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
    ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40)
]
jun_jul = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70)
]
log_raw = make_log(apr_may + jun_jul)

# 4. DFG discovery
dfg_raw = dfg_disc.apply(log_raw)

# 5. alignment diagnostics raw
align_raw = align_algo.apply_log(log_raw, net, im, fm)
fitness_raw = pm4py.fitness_evaluator.apply(align_raw, variant="percentage")

# 6. Normalization: map Risk Screen->Classify, drop Queue Routed
def normalize(log):
    new_log = EventLog()
    for tr in log:
        nt = Trace()
        for ev in tr:
            name = ev["concept:name"]
            if name == "Risk Screen":
                name = "Classify"
            if name == "Queue Routed":
                continue
            ev2 = deepcopy(ev)
            ev2["concept:name"] = name
            nt.append(ev2)
        new_log.append(nt)
    return new_log

log_norm = normalize(log_raw)
dfg_norm = dfg_disc.apply(log_norm)
align_norm = align_algo.apply_log(log_norm, net, im, fm)
fitness_norm = pm4py.fitness_evaluator.apply(align_norm, variant="percentage")

print("Raw fitness:", fitness_raw)
print("Normalized fitness:", fitness_norm)

# 8. Candidate tree with optional Supervisor Sign-off
tree2_str = "-> ('Receive','Classify',X(*( 'Standard Review','Request Info'),->('Enhanced Review','Compliance Check')),'(Supervisor Sign-off)?','Decision','Notify')"
tree2 = pt_parser.parse_process_tree(tree2_str)
net2, im2, fm2 = pm4py.convert_to_petri_net(tree2)
```

## 7. Provisional conclusion
Most of the apparent conformance collapse between April – May and June – July is explained by data-semantics drift: a harmless screen-label rename, insertion of a system “Queue Routed” event, and loss of timestamp fidelity for Decision/Notify. After systematic cleaning and ordering the same traces fit the unchanged policy model almost as well as before (89 %).  

In August a genuine business-rule change introduced mandatory Supervisor Sign-off for high-value claims. Because the normative process tree was not updated, those legitimate paths generate new deviations, but an extended model that makes Sign-off optional restores fitness to 86 %. Therefore the primary measured conformance drop is attributable to logging and model-governance issues rather than to operational misconduct.  

Nevertheless, roughly 4-5 % of enhanced-review cases still lack a recorded Compliance Check. Given the supervisor memo discouraging bypasses, and no pattern in appeals, true non-compliance remains plausible but unproven.  

Confidence that data/model issues dominate: 0.8  
Confidence that some real compliance risk persists: 0.4  

Immediate actions  
IT: 1) retroactive label mapping; 2) re-export Decision and Notify with source timestamps; 3) tag technical events.  
Process owner: formally version the model and include the Sign-off gateway with a data guard on claim value.  
Compliance: audit a statistically valid sample of the 55 cases without a logged Compliance Check; cross-verify Manual Override usage.  

What we must not claim yet: that every Compliance Check omission is a logging glitch, or that Sign-off is always performed for >EUR 50k—both need document proof.

## 8. Model-governance recommendation
1. Maintain version-controlled process models; update them immediately when policy or UI changes are promoted.  
2. Sign formal event-semantic contracts between application owners and mining teams: every UI label change must ship a mapping table.  
3. Classify and tag all purely technical or infrastructural events, and exclude them from default conformance runs unless explicitly modelled.  
4. Preserve original source timestamps and sequence numbers end-to-end; ETL layers may add but must never overwrite provenance fields.  
5. Express data-aware obligations (e.g., Supervisor Sign-off over EUR 50k) as declarative constraints bound to attributes, not as purely control-flow nodes.  
6. Institute a post-release validation window: rerun benchmark conformance on representative historical logs; any fitness delta >5 % blocks deployment pending root-cause analysis.
