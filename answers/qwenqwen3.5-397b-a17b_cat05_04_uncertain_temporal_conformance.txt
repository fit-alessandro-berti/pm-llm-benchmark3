## 1. Normalization Assumptions

To evaluate conformance, all timestamps are normalized to Coordinated Universal Time (UTC) uncertainty intervals. The following assumptions and construction rules apply:

1.  **Interval Construction**: For a displayed time $T_{disp}$, resolution uncertainty $U_{res}$, and clock offset bound $[O_{min}, O_{max}]$, the true time interval is $[T_{disp} + U_{res\_start} - O_{max}, T_{disp} + U_{res\_end} - O_{min}]$. Measurement uncertainty is added to the bounds.
2.  **Clock Offset Direction**: `clock_offset = recorded_clock - true_clock`. Therefore, `true_clock = recorded_clock - offset`. A positive offset bound subtracts from the recorded time to find the earliest true time.
3.  **Rounding Semantics**:
    *   **Floor to Minute**: $T_{disp}$ implies $[T_{disp}:00, T_{disp}:59.999]$.
    *   **Round to Nearest 10s**: $T_{disp}$ implies $[T_{disp}-5s, T_{disp}+5s]$.
    *   **Round to Nearest Minute**: $T_{disp}$ implies $[T_{disp}-30s, T_{disp}+30s]$.
    *   **Exact**: $T_{disp}$ implies $\pm 0.5s$ measurement uncertainty.
4.  **Time Zone Conversion**:
    *   **June 2026**: Europe/Berlin is CEST (UTC+2); America/New_York is EDT (UTC-4); Europe/London is BST (UTC+1).
    *   **October 2025**: Europe/Berlin observes DST transition on Oct 26. Times 02:00–02:59 are ambiguous (fold).
5.  **DST Folds (T-405)**: Where fold is missing, we generate a union of intervals for both possible offsets. Causal ingestion order (Alert < Inv < Contain) is used to prune impossible fold combinations.
6.  **Inferred Starts (T-404)**: `Investigation_Start` is derived as `Investigation_Complete` minus `Duration`. Uncertainty propagates additively.
7.  **Mobile Entry Delay (T-406)**: The "up to five minutes late" entry delay is treated as a one-sided uncertainty on the *occurrence time*. The recorded timestamp is the *entry time*. True Event Time $\in$ [Entry Time - Max Delay - Clock Uncertainty, Entry Time + Clock Uncertainty]. This assumes the user back-dated the entry to the event time but may have been late in doing so.
8.  **Causal Constraints (T-407)**: `Alert_Received` is bounded by `Alert_Sent` + Network Latency. A causal constraint `Alert_Received` $\le$ `Investigation_Start` is applied to prune the feasible interval for `Alert_Received`.

## 7. Governance Recommendation

To reduce indeterminacy and enforce SLAs reliably, the following controls are recommended:

1.  **UTC Storage**: All systems must store timestamps in UTC internally. Display time zones should be applied only at the presentation layer to avoid DST fold ambiguity (e.g., T-405).
2.  **Raw Timestamp Retention**: Store raw clock values alongside normalized UTC times to allow re-calculation if offset bounds change.
3.  **Source Offset Telemetry**: Automate the collection of clock offset diagnostics (NTP/PTP) at the time of event ingestion. Do not rely on daily averages (e.g., T-409) for SLA-critical events.
4.  **Resolution Metadata**: Log the precision of the source clock (e.g., "floor_minute", "round_10s") as a metadata field to automate uncertainty interval construction.
5.  **Start/Complete Semantics**: Enforce logging of both `Start` and `Complete` timestamps for all lifecycle activities. Inferring starts from durations (T-404) introduces unacceptable uncertainty for SLA enforcement.
6.  **DST Fold Handling**: Systems operating in DST zones must log the UTC offset explicitly (e.g., `+02:00`) rather than relying on local time interpretation, eliminating fold ambiguity.
7.  **Causal Identifiers**: Link `Alert_Sent` and `Alert_Received` with a correlation ID to measure true network latency rather than bounding it statistically (T-407).
8.  **Enforcement Policy**: Interval overlap (POSSIBLE_VIOLATION) should trigger a "Review Required" status, not an automatic penalty. Automatic penalties should only apply to CERTAIN_VIOLATION. However, repeated POSSIBLE_VIOLATIONS due to poor clock sync should trigger infrastructure remediation.
