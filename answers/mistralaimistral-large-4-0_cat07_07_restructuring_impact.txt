# 1. Mechanism map

The restructuring does not simply “remove handovers.” It changes the **topology** of work: local dyadic loops are replaced by queue-mediated hub-and-spoke relationships, and several previously separate demand streams are merged into shared queues. The process-mining effect is therefore not a single number but a shift in handover networks, waiting-time distributions, role structures, and segment-level fairness.

```text

 A2 Centralize Specialist Review + Legal + Risk + difficult Quality Check in shared queue
 A3 Keep Intake + simple Eligibility Review local
 A4 Routing rules: high-complexity  TSS; legal/risk/security  shared queue; pull model
 A5 Remove one local supervisor  shared approval queue for medium/high-value cases
 A6 Management target: +15% specialist utilization
        
        
Organizational mechanisms

 Legal/Risk (already 91–93% utilized) absorb more demand: broader detection + difficult QC
 Standardized routing replaces local discretion and early informal technical advice
 Approval ownership is diffused across a shared queue
 Load is consolidated onto fewer specialists

 Handover network: local loops replaced by hub-and-spoke; count may not fall
 Central queue formation: waiting time before Specialist Review / Technical Assessment / Approval / QC
```

Explicit mechanism-map elements:

- **Nominal handover reduction.** Management expects fewer handover loops. PM measures: handover frequency per case, handover-network density, and specific edges (local caseworkerembedded tech vs. caseworkerTSS). Expect a **topology change more than a count reduction**: the local loop is replaced by two queue handoffs.
- **Central queue formation.** PM measures: `discover_handover_of_work_network`, `discover_working_together_network`, `discover_subcontracting_network` centralization; waiting time before Specialist Review, Technical Assessment, Supervisor Approval, Quality Check via `discover_performance_dfg` and `insert_case_service_waiting_time`.
- **Specialist utilization.** PM measures: resource busy time, cases per specialist, `get_service_time`. Watch the divergence between service time and waiting time: high utilization with rising waiting time is a bottleneck.
- **Rework.** PM measures: `rework_flag`, `get_rework_cases_per_activity`, rework rate after handover, segmented by `case_complexity` and `customer_segment`.
- **Local expertise loss.** PM measures: `local_expertise_flag`, `discover_activity_based_resource_similarity` between local caseworkers and local techs, `discover_organizational_roles` role diversity, local Technical Assessment event counts.
- **Role clarity.** PM measures: `reassignment_count`, `handover_reason` distribution, role-discovery ambiguity, outcome accountability by resource.
- **Resilience to absence.** PM measures: cross-team handover frequency, `handover_reason` = absence cover, waiting-time variance, recovery time after a specialist absence, subcontracting-network concentration.
- **Fairness across teams/customer segments.** PM measures: cycle time, waiting time, SLA miss, rework, and CSAT segmented by `team`, `location`, `customer_segment`, `priority`, `case_complexity`.

# 2. Scenario forecasts

## Optimistic scenario

- **Handover pattern.** Local caseworkerembedded-tech loops disappear; handover network becomes a clean hub-and-spoke with TSS. Cross-team handovers fall 63 per 100. Total handover count is roughly stable or slightly lower because automation absorbs some intakecaseworker handoffs (8883). Handover reasons shift from “local loop” to “standard routing.”
- **Queue/waiting-time pattern.** TSS waiting time stays near the management estimate of 4.0h median with a tight distribution. Legal/Risk waiting time rises only modestly (9.610.5h) because routing rules correctly filter only true legal/risk/security cases. Shared approval queue waits ~3.0h. No queue exceeds 85% utilization.
- **Cycle-time distribution.** East improves materially: median 8.6d  ~7.0d, p90 22.8d  ~18d, because E_Tech’s overload is relieved. North and South are roughly stable or slightly worse (6.87.0d, 7.47.6d). Overall median improves; p90 improves for East and is stable for North/South.
- **Rework and quality pattern.** Overall rework falls. East rework drops 11.5%  ~9.5%. North/South rework rises only slightly (8.28.5%, 9.09.2%) because centralized difficult Quality Check catches defects earlier. Standardized specialist advice reduces rework after handover.
- **Role clarity and accountability.** Routing rules are clear; TSS owns specialist advice; shared approval queue has a named owner per case; local teams retain intake, eligibility, and customer contact. Reassignment count stays flat.
- **Fairness implications.** East benefits most. North/South experience a small wait increase but remain within SLA. Regional/language accommodation is preserved because Local Customer Contact stays local. High-complexity cases receive specialist attention faster than before.
- **Early warning signs.** TSS utilization <85%; TSS waiting-time p90 <8h; Legal/Risk wait <12h; reassignment_count flat; CSAT stable or improved; no rise in complex-case rework.

## Central scenario (most likely)

- **Handover pattern.** The local loop is replaced by two queue-mediated handoffs, so total handover events per case are **similar or slightly higher**, not lower. Handover reasons shift to “queue pull,” “capacity,” and “routing rule.” Cross-team handovers fall 63, but reassignment_count rises because cases bounce between local caseworker and TSS when advice is incomplete.
- **Queue/waiting-time pattern.** TSS becomes a visible bottleneck: utilization >90%, median wait ~4.0h but p90 12–24h. Legal/Risk, already at 91–93%, absorb broader detection (912 per 100) plus difficult Quality Check, pushing waits from 9.6h to 14–18h. Shared approval queue waits ~3.0h median but p90 8h+. High-complexity cases queue multiple times: TSS  Legal/Risk  shared approval  difficult QC.
- **Cycle-time distribution.** Average median may improve slightly because East improves and simple cases stay local. But the distribution becomes **bimodal**: simple cases are fast and local; complex cases are slow and central. North/South p90 worsens; East p90 improves. High-complexity p90 worsens across all teams.
- **Rework and quality pattern.** Overall rework is roughly stable or slightly worse. East improves; North/South worsen because early informal technical advice disappears and local context is lost. Centralized difficult QC catches some defects, but late detection increases rework cost. Rework after handover rises for complex and regional cases.
- **Role clarity and accountability.** Accountability blurs in the shared approval queue. Local teams are unsure whether they or TSS own the technical assessment. Reassignment_count rises. Handover reasons include “ownership unclear” and “queue return.” Role discovery shows the approval role fragmented across the shared queue.
- **Fairness implications.** East improves; North/South degrade (longer waits, lower CSAT, loss of local expertise). High-complexity cases and customers needing regional/language accommodation face more handovers and longer waits. Priority cases may not receive priority in a FIFO shared queue. Legal/Risk scarcity means high-complexity cases wait longest.
- **Early warning signs.** TSS utilization >90%; TSS waiting-time p90 rising week over week; Legal/Risk wait >12h; reassignment_count above baseline; North/South CSAT falling; rework rising for high-complexity and regional cases; local Technical Assessment events declining in North/South.

## Adverse scenario

- **Handover pattern.** Handover count actually increases due to queue-mediated loops, incomplete advice returns, and exception handling. Cross-team handovers rise again when the central queue fails and local cover is needed. The handover network becomes fragmented with many reassignments.
- **Queue/waiting-time pattern.** TSS is a severe bottleneck: utilization >95%, waits of days. Legal/Risk effectively collapse: waits 20h+. Shared approval queue becomes a second bottleneck. High-complexity cases cycle through multiple queues; even medium/high-value simple cases are delayed by shared approval.
- **Cycle-time distribution.** Average cycle time may still look acceptable because simple cases dominate the average. But p90/p95 explode. East improves initially, then degrades as the central queue saturates. North/South p90 worsens significantly. SLA misses rise across teams.
- **Rework and quality pattern.** Rework rises overall. Loss of early informal advice generates unnecessary referrals and rework after advice. Centralized difficult QC finds defects late. Customer complaints rise; outcome attribute deteriorates for complex cases.
- **Role clarity and accountability.** Severe ambiguity. Shared approval reduces individual accountability. Local staff stop developing technical skill. “Who owns the case” is unclear. Reassignment_count is high; handover reasons are dominated by “queue,” “capacity,” and “unclear ownership.”
- **Fairness implications.** North/South and regional/language customers are hit hardest. High-complexity cases wait longest. East’s initial gain erodes. Priority and customer-segment fairness deteriorates. Specialist utilization is high, but throughput is low: specialists are busy but not productive.
- **Early warning signs.** TSS utilization >95% sustained; queue waits of days; SLA miss >12%; rework >12%; CSAT <3.5; reassignment_count spike; local technical skill atrophy signals (no local Technical Assessment events); negative staff feedback; a single TSS specialist absence causes a wait spike >24h.

# 4. Risks invisible in average cycle time

1. **Tail latency explosion.** Average cycle time can improve because many simple cases stay local and fast, while p90/p95 worsen for high-complexity and North/South cases. PM measure: percentile cycle time by `case_complexity` and `team`; performance DFG waiting-time p90; SLA miss rate. A stable mean with a rising p90 is a warning, not a success.

2. **High-complexity cases.** Routing rules send all high-complexity cases to TSS, then possibly Legal/Risk, then shared approval, then difficult Quality Check. These cases accumulate multiple queue waits that the average hides. PM measure: segment by `case_complexity='high'`; count queue transitions per case; waiting time before each of Specialist Review, Legal/Risk, Approval, Quality Check; variants for complex cases.

3. **Local knowledge loss.** North and South currently use local expertise to reduce rework on complex and regional cases. After centralization, early informal advice disappears, so more cases are referred unnecessarily and more advice returns for rework. Average rework may stay flat while complex/regional rework rises. PM measure: `local_expertise_flag`; rework rate after handover segmented by `case_complexity` and `customer_segment`; `discover_activity_based_resource_similarity` between local caseworkers and TSS; local Technical Assessment event counts.

4. **Fairness across teams and customer segments.** East may improve while North/South degrade. The average conceals divergence. Customers needing language or regional accommodation may face more handovers. Priority cases may not receive priority in a FIFO shared queue. PM measure: cycle time, waiting time, SLA miss, rework, and CSAT segmented by `team`, `location`, `customer_segment`, `priority`; compare East vs North/South gap before/after.

5. **Learning and skill atrophy.** Local staff may stop developing technical skill because hard cases are routed away. Short-term cycle time may improve, but long-term capability declines. PM measure: local Technical Assessment events in North/South; `discover_organizational_roles` role diversity; rework on complex local cases over time; resource similarity between local caseworkers and centralized specialists.

6. **Accountability and role clarity.** Shared approval may standardize decisions but diffuse ownership. Average cycle time may improve while reassignment_count rises and no one is clearly accountable for the outcome. PM measure: `reassignment_count`; `handover_reason` distribution (“ownership unclear,” “queue return”); `discover_organizational_roles` ambiguity; `outcome` by resource/team.

7. **Exception handling and resilience.** Cross-team handover is reduced from 6 to 3 per 100 cases, but the central queue is a single point of failure. A stable average hides the fact that one TSS or Legal/Risk absence now causes a spike. PM measure: cross-team handover frequency during absence; `handover_reason` = absence cover; waiting-time variance; recovery time after a specialist absence; subcontracting-network concentration.

# 5. Pilot design

## Pilot scope

Phase 1: **East only**. Move E_Tech into the Technical Shared Service and route East high-complexity cases to TSS. Introduce the shared approval queue for East medium/high-value cases only. Keep Intake and simple Eligibility Review local everywhere. Do **not** add difficult Quality Check to Legal/Risk in Phase 1, because Legal/Risk are already at 91–93% utilization.

Phase 2 (only if Phase 1 guardrails pass): add **South** to TSS and shared approval, with **North** as the remaining control. This tests the local-expertise-loss risk in a team with strong local expertise.

## Comparison group

North and South continue the current model in Phase 1 (local techs, local supervisor approval). In Phase 2, North remains the control. This concurrent control is essential: pre/post alone cannot separate the restructuring effect from seasonality, volume shifts, or automation effects.

## Pre/post observation window

- **Baseline:** 8–12 weeks before any change.
- **Phase 1 post:** 12–16 weeks after East cutover, with the first 4 weeks treated as stabilization and excluded from guardrail judgments.
- **Phase 2 post:** 12–16 weeks after South cutover, again with a 4-week stabilization window.
- Total observation: approximately 6 months.

## Segmentation

Segment all metrics by:
- `team` (East vs North vs South)
- `case_complexity` (low / medium / high)
- `required_specialty` (legal / risk / security / technical / none)
- `customer_segment` (standard vs regional/language accommodation needs)
- `priority` (high / medium / low)
- `location`

## Guardrail metrics

Phase 1 pass criteria (East pilot):
- TSS utilization 85% sustained.
- TSS waiting-time p90 8h.
- Legal/Risk waiting time 12h.
- Shared approval waiting-time p90 6h.
- Reassignment_count per case  baseline +0.5.
- East rework rate  baseline +1pp.
- East SLA miss  baseline +1pp.
- East CSAT  baseline 0.2.
- Cross-team handover  baseline.
- High-complexity p90 cycle time not worse than baseline +10%.
- Control teams (North/South): no deterioration beyond normal variance.

Phase 2 pass criteria (South added):
- Same guardrails for South.
- North (control) remains stable.
- No widening of the East–North fairness gap.
- Local Technical Assessment events in North remain stable (learning preserved in control).

## Staff feedback collection

- Weekly 3-question pulse survey: role clarity, workload, perceived fairness.
- Structured interviews at weeks 4, 8, and 12 with East caseworkers, E_Tech/TSS specialists, and the shared approval queue.
- Free-text capture of `handover_reason` and “why was this case reassigned?” to detect ownership ambiguity.
- Specialist feedback on queue pull model: is advice complete? Are cases returned too often?

## Rollback or adjustment triggers

Roll back or adjust if any of the following occur:
- TSS utilization >90% for 2 consecutive weeks.
- TSS waiting-time p90 >12h.
- Legal/Risk waiting time >15h.
- Pilot-team rework rate > control +2pp.
- Pilot-team SLA miss > control +2pp.
- CSAT drop >0.3 vs baseline.
- Reassignment_count spike above baseline +1.0.
- Staff role-clarity score <3.5/5 for 2 consecutive weeks.
- A single TSS specialist absence causes waiting-time spike >24h.

Adjustments before rollback: add TSS capacity; tighten routing rules (only high-complexity to TSS, not all technical cases); restore local supervisor approval for high-value or regional cases; add priority-based queueing; improve case-note standardization.

# 6. Recommendation

**Recommendation: pilot first, with modifications. Do not proceed to full rollout now.**

The proposal has a plausible mechanism for reducing local handover loops and improving East, but it also concentrates risk in queues that are already near capacity (Legal/Risk at 91–93%) and removes local expertise from the teams that currently perform best. The management estimate of “fewer handovers” is misleading: the local loop is replaced by two queue-mediated handoffs, so handover **count** may not fall even if the **topology** improves. The +15% specialist utilization target is not a benefit by itself; utilization above 90% with rising waiting times is a bottleneck.

Proceed with the phased pilot described above: **East first, South second, North as control**. Modify the proposal before piloting:

1. **Do not add difficult Quality Check to Legal/Risk** until capacity is added; they are already near saturation.
2. **Keep local Technical Assessment for low/medium-complexity cases** to preserve early informal advice and local learning.
3. **Retain local supervisor approval for high-value or regionally sensitive cases**; use the shared approval queue only for standardized medium-value cases.
4. **Add priority-based queueing** to the shared queues so high-priority and high-complexity cases are not disadvantaged by FIFO.
5. **Define case ownership explicitly** in the shared approval queue; a named owner per case is a guardrail, not an overhead.
6. **Standardize case notes before relying on cross-team cover**; the current cross-team rework rate of 18% is driven by inconsistent notes.

The recommendation is conditional on the monitoring indicators in Section 3. Advance from Phase 1 to Phase 2 only if the East pilot meets the guardrail metrics. Roll back or adjust if any rollback trigger fires.

**What management should not infer from early averages:**

- Do **not** infer success from a falling average cycle time in the first 4–8 weeks. Early improvement may be driven by simple cases, by East’s relief from overload, or by novelty effects. Require 12–16 weeks and a control group.
- Do **not** infer that fewer local handover loops means better performance. The local loop is replaced by queue handoffs; waiting time after handover may rise even as the handover count falls.
- Do **not** infer that higher specialist utilization means higher productivity. Utilization above 90% with rising waiting times means the specialist is a bottleneck.
- Do **not** infer that standardization has improved quality if average rework is flat. Rework may be shifting to high-complexity, regional, and North/South cases.
- Do **not** infer fairness from an overall SLA miss rate. East may improve while North/South and regional/language customers degrade.
- Do **not** infer long-term capability from short-term cycle time. Local skill atrophy is a lagging risk that appears only after quarters.

```python
def network_centralization(net):
    """Degree centralization as a hub-formation proxy."""
    try:

        G = net if hasattr(net, "nodes") else nx.DiGraph(net)
        if G.number_of_edges() == 0:
            return 0.0
        deg = dict(G.degree())
        max_deg = max(deg.values())
        denom = (len(deg) - 1) * (len(deg) - 2) if len(deg) > 2 else 1
        num = sum(max_deg - d for d in deg.values())
        return num / denom if denom else 0.0
    except Exception:
        return None

def waiting_times_before_activity(log, target_activity):
    """Hours between previous event and target activity, per case."""
    waits = []
    for case in log:
        events = sorted(case, key=lambda e: e[TS])
        for i in range(1, len(events)):
            if events[i][ACT] == target_activity:
                delta_h = (events[i][TS] - events[i-1][TS]).total_seconds() / 3600.0
                waits.append(delta_h)
    return waits

def wait_stats(log, activity):
    w = waiting_times_before_activity(log, activity)
    if not w:
        return {"activity": activity, "n": 0}
    s = pd.Series(w)
    return {"activity": activity, "n": len(s), "median": s.median(),
            "p90": s.quantile(0.90), "mean": s.mean()}

# 7. Cycle time, SLA misses, rework, fairness
# ------------------------------------------------------------------
def case_durations(log):
    """Case duration in days per case id."""
    durations = {}
    for case in log:
        ts = [e[TS] for e in case]
        durations[case.attributes.get(CASE, str(case))] = (max(ts) - min(ts)).total_seconds() / 86400.0
    return durations

def cycle_time_by_segment(df, log, segment_col, sla_days=10.0):
    durations = case_durations(log)
    tmp = df.drop_duplicates(CASE).set_index(CASE)
    rows = []
    for val, grp in tmp.groupby(segment_col):
        case_ids = grp.index
        durs = pd.Series([durations[c] for c in case_ids if c in durations])
        rows.append({
            segment_col: val,
            "n": len(durs),
            "median_days": durs.median(),
            "p90_days": durs.quantile(0.90),
            "p95_days": durs.quantile(0.95),
            "sla_miss_rate": (durs > sla_days).mean(),
        })
    return pd.DataFrame(rows)
```
