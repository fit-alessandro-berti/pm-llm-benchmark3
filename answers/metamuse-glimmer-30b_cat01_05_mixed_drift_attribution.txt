# Part B: Reusable PM4Py functions for event log
import pandas as pd
import pm4py

def prepare_log(df, case_id='case_id', activity='activity', timestamp='timestamp', resource='resource'):
    df = df.copy()
    df[timestamp] = pd.to_datetime(df[timestamp])
    df = pm4py.format_dataframe(df, case_id=case_id, activity=activity, timestamp=timestamp)
    if resource in df.columns:
        df = pm4py.format_dataframe(df, case_id=case_id, activity=activity, timestamp=timestamp, resource=resource)
    return df

def monthly_artifacts(log, start, end):
    window = pm4py.filter_time_range(log, start, end)
    dfg = pm4py.discover_dfg(window)
    variants = pm4py.get_variants(window)
    temporal = pm4py.discover_temporal_profile(window)
    return {'dfg':dfg,'variants':variants,'temporal':temporal}

def compare_mappings(log, mapping):
    log_mapped = log.copy()
    log_mapped['activity'] = log_mapped['activity'].replace(mapping)
    # compute conformance on both without overwriting original
    return log, log_mapped

## 9. Provisional attribution

The March fitness collapse is strongest evidence for pure logging-semantic drift from the system migration; raw fitness falls to 0.55 while mapped fitness remains ~0.90 and normalized DFG rates are essentially unchanged. Missing resources and duplicated Open Case events are concentrated on migrated activities, supporting a provenance issue rather than a business change.

Supplier-driven rework is strongly supported from May onward. Supplier Z share jumps from ~16% to 43-46% and rework variant share rises 1327% in lockstep, with normalized AssessRequestInfo rising from 12 to 29 per 100 cases. Supplier Z cases were already more complex, so population and behavioral effects are mediated; segmentation by supplier is required for clean attribution.

Staffing-driven queueing is plausible and temporally aligned with the June 15 assessor departures. Median service time for Assess rises only modestly 4.85.4h while median cycle and especially p90 accelerate sharply, and fast variant share declines. The effect is confounded by simultaneous supplier rework and rising case mix, so the share of cycle time attributable to pure queueing is uncertain, likely 30-40% of the peak increase.

Priority-induced redistribution is plausible but not proven at aggregate level. The July 01 rule should reduce waiting for high-complexity cases at the expense of standard cases; aggregate median continues rising, consistent with redistribution plus capacity loss. Discriminating evidence requires complexity-stratified waiting distributions.

Seasonal population drift is strongest in October-November. High-complexity share rises 2645% with volume increase, and AssessSeniorAssessment rate jumps 722 per 100, partly reflecting historic under-recording now visible. The December improvement coincides with overtime, a quality campaign, and seasonal load decline, so intervention vs natural seasonality cannot be cleanly separated.

Overall, logging drift dominates March, supplier rework dominates May-July, staffing and priority drive performance deterioration June-October, and seasonal case mix amplifies the peak. Interaction prevents clean additive attribution; a joint supplier×staffing×priority effect explains the non-linear p90 growth.

## 10. Monitoring decision rules

1. IF raw_model_fitness drops >0.20 month-over-month while mapped_model_fitness is stable, THEN trigger label schema audit and mapping review, BECAUSE system migration or semantic drift is likely.
2. IF rework_variant_pct rises >5 pp and AssessRequestInfo rate rises >5 per 100 cases, THEN segment by supplier and complexity, BECAUSE supplier-driven document incompleteness is likely.
3. IF median service time is stable but median cycle and p90 diverge with fast_variant_pct falling, THEN inspect resource workload and queue waiting, BECAUSE staffing-driven queueing is likely.
4. IF high_complexity_pct rises >10 pp seasonally and AssessSeniorAssessment rate increases disproportionately, THEN compare complexity-stratified cycle times year-over-year, BECAUSE seasonal population drift and logging visibility change may be confounding.
5. IF missing_resource_pct rises >3% and is concentrated on migrated activities, THEN flag data pipeline quality, BECAUSE logging provenance degradation biases conformance and resource metrics.
6. IF mapped_model_fitness declines gradually >0.03 over two months with stable labels, THEN run alignment diagnostics by variant, BECAUSE persistent behavioral adaptation or new control-flow is emerging.
7. IF queue waiting for standard cases rises while high-complexity waiting falls after a priority change, THEN recompute waiting distributions by complexity class, BECAUSE priority-induced redistribution of delay is occurring.
