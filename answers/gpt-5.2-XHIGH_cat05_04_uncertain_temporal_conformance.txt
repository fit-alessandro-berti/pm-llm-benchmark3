## 1. Normalization Assumptions

### 1.1 Interval construction (resolution → semantic shifts → clock correction → UTC)
- **Step A — expand the displayed timestamp to a recorded-clock interval \(R\)** using the source’s rounding/resolution rule.
- **Step B — apply any additional semantic shift** that affects occurrence time (e.g., mobile late entry) to obtain an occurrence-on-recorded-clock interval \(O\).
- **Step C — apply clock-offset correction** using the provided direction:
  - `clock_offset = recorded_clock - true_clock`, with `clock_offset ∈ [a,b]`
  - therefore `true_time = recorded_time - offset`
  - for \(O=[o_{\min},o_{\max}]\), the feasible true-time interval is:
    - \([o_{\min}-b,\;o_{\max}-a]\)
- **Step D — convert to UTC**, preserving unions of alternative intervals where relevant.

### 1.2 Source rounding / measurement semantics used
- **HUB (UTC)**: measurement uncertainty ±0.5 s around the displayed second; then apply clock-offset bound.
- **floor-to-minute** (OPS-BER, VENDOR-NY, LEGACY-BER):
  - displayed `HH:MM` means recorded-clock time in \([HH{:}MM{:}00.000,\;HH{:}MM{:}59.999]\).
- **round-to-nearest-10-seconds** (SENSOR):
  - displayed time `...:ss` represents the nearest 10 s bucket; modeled as \([t-5\text{s},\;t+5\text{s}]\) on the device clock.
- **round-to-nearest-minute** (MOBILE-LON):
  - displayed `HH:MM` modeled as \([t-30\text{s},\;t+30\text{s}]\) on the phone clock.

### 1.3 DST fold handling (LEGACY-BER on 2025-10-26)
- For local times in **Europe/Berlin** between **02:00 and 02:59** on 2025-10-26, interpret the local timestamp as a **union** of:
  - **fold 0 (CEST, UTC+02)** and
  - **fold 1 (CET, UTC+01)**,
  producing two UTC intervals separated by 1 hour.
- For **T-405**, ingestion order constraints (“after”) are used to **prune fold combinations** that make the order impossible, while retaining minute/offset uncertainty on the surviving fold(s).

### 1.4 Inferred events and weak-evidence semantics
- **T-404**: `Investigation_Start` is inferred from `Investigation_Complete` minus a signed duration interval \([18,25]\) minutes, propagating all uncertainty.
- **T-407**: `Alert_Received` is missing; I construct an **inferred** receipt interval from `Alert_Sent + delivery_latency`, where latency ∈ \([0,20]\) minutes.
  - This is explicitly a **semantic bridge** (Sent ≠ Received) and is treated as **low-strength** evidence.

### 1.5 Duration computation over intervals / unions
- For two single intervals \(A=[a_1,a_2]\) and \(B=[b_1,b_2]\), feasible duration \(D=B-A\) is:
  - \([b_1-a_2,\;b_2-a_1]\)
- For unions of intervals, compute all pairwise differences and keep the resulting **union**, merging overlaps but not collapsing disjoint components.
- **Eventual-following constraint**: for the provided “eventually-following” profile pairs (and for SLA comparisons where the order is semantically required), negative durations are excluded by intersecting feasible durations with \([0,\infty)\). If a negative part exists, it is treated as reduced evidential strength about order.

### 1.6 Classification rules (interval-based)
- **CERTAIN_PASS**: every feasible duration lies inside the acceptance region.
- **CERTAIN_VIOLATION**: every feasible duration lies outside the acceptance region.
- **POSSIBLE_VIOLATION**: feasible durations overlap both inside and outside the acceptance region.
- **INDETERMINATE**: required events are missing and not defensibly inferable under stated semantics, or feasible duration set is empty/inconsistent.

### 1.7 Baseline parameters for reporting
- **SLA tolerance (baseline)**: 0 minutes (sensitivity: +0, +2, +5 minutes).
- **Temporal-profile zeta (baseline)**: \(zeta=2\) (sensitivity: \(zeta=1,2,3\)).
- **Midpoints** are used only as a secondary, explicitly lossy comparison for PM4Py.

### 1.8 Mobile entry delay semantics (T-406)
- Baseline assumption: “late entry” introduces uncertainty about **occurrence time**, not just logging time.
  - occurrence time can be **earlier** than the entered time by \(d \in [0,300]\) s (in addition to phone clock offset and rounding).
- Alternative assumption (not used for primary intervals): the user typed the actual start time (delay affects only record creation). This would generally shrink uncertainty and tends to make S1/S2 easier to pass.
