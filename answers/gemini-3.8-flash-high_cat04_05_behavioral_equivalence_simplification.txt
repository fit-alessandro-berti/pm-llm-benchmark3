# 1. Equivalence Notions

To rigorously evaluate whether Model A and Model B are equivalent, the observation boundary, abstraction criteria, and behavioral relations must be defined formally.

### 1.1 Formal Definitions

* **Visible Alphabet ($\Sigma$):** The set of visible activity labels:
  $$\Sigma = \{\text{'Open Case'}, \text{'Analyze Revision'}, \text{'Check Revision'}, \text{'Approve Revision'}, \text{'Rework Case'}, \text{'Close Case'}\}$$
  The silent label is denoted $\tau \notin \Sigma$. The projection homomorphism $\pi_\Sigma: (\Sigma \cup \{\tau\})^* \to \Sigma^*$ maps each $a \in \Sigma$ to $a$ and $\tau$ to the empty string $\epsilon$.

* **Visible Trace Equivalence after Hiding $\tau$:**
  Let $M$ be a workflow model (process tree or accepting Petri net $(N, M_0, M_f)$). The firing language $L_{fire}(M) \subseteq (T)^*$ is the set of transition sequences leading from initial marking $M_0$ to final marking $M_f$. The visible trace language $L(M) \subseteq \Sigma^*$ is defined as:
  $$L(M) = \{ \pi_\Sigma(\lambda(t_1)\lambda(t_2)\dots\lambda(t_n)) \mid M_0 [t_1 t_2 \dots t_n \rangle M_f \}$$
  Two models $M_A$ and $M_B$ are **visible trace equivalent** iff:
  $$L(M_A) = L(M_B)$$

* **Bounded Visible-Language Equivalence under P3:**
  The bounded language $L_{\text{P3}}(M) \subseteq L(M)$ restricts $L(M)$ to complete visible traces satisfying the bounds:
  $$L_{\text{P3}}(M) = \{ \sigma \in L(M) \mid |\sigma| \le 12 \ \land \ |\sigma|_{\text{'Analyze Revision'}} \le 3 \}$$
  where $|\sigma|$ denotes total visible length and $|\sigma|_a$ denotes the count of activity $a$ in trace $\sigma$.
  Two models are **bounded visible-language equivalent under P3** iff:
  $$L_{\text{P3}}(M_A) = L_{\text{P3}}(M_B)$$

* **Business-Relevant Equivalence under P1 (Operational Compliance View):**
  P1 establishes an operational compliance contract over visible executions:
  1. *Per-Revision Verification:* Every occurrence of $\text{'Analyze Revision'}$ must be paired with its own occurrence of $\text{'Check Revision'}$ prior to the subsequent $\text{'Rework Case'}$ or $\text{'Close Case'}$.
  2. *Separation:* $\text{'Rework Case'}$ strictly delineates consecutive analysis attempts.
  3. *Optional Approval:* $\text{'Approve Revision'}$ is optional in each revision cycle, but when present, its ordering and occurrence count are operationally visible and must follow verification.
  Two models are **P1-equivalent** iff they admit the identical set of operationally compliant traces satisfying these constraints.

* **Abstracted Dashboard Equivalence under P2 (Executive Dashboard View):**
  The executive dashboard view applies an abstraction function $\alpha_{\text{P2}}: \Sigma^* \to \{0, 1\} \times \mathbb{N}_{\ge 1} \times \{0, 1\} \times \{0, 1\}$ defined for any complete trace $\sigma$ as:
  $$\alpha_{\text{P2}}(\sigma) = \left( \mathbb{I}_{endpoints}(\sigma), \ |\sigma|_{\text{'Analyze Revision'}}, \ \mathbb{I}(|\sigma|_{\text{'Check Revision'}} \ge 1), \ \mathbb{I}(|\sigma|_{\text{'Rework Case'}} \ge 1) \right)$$
  where $\mathbb{I}_{endpoints}(\sigma) = 1$ iff $\sigma$ starts with $\text{'Open Case'}$ and ends with $\text{'Close Case'}$, and $\mathbb{I}(c) = 1$ if condition $c$ holds, else $0$. Approvals, silent steps, and the interleaving order between analysis and checking are completely ignored.
  Two models are **P2-equivalent** iff:
  $$\alpha_{\text{P2}}(L(M_A)) = \alpha_{\text{P2}}(L(M_B))$$

### 1.2 Treatment of Duplicate Visible Labels
Duplicate visible labels (e.g., repeated occurrences of $\text{'Analyze Revision'}$ or $\text{'Check Revision'}$ across loop iterations) are distinguished **solely by their occurrence position (sequence index)** within a trace $\sigma = \langle e_1, e_2, \dots, e_n \rangle$. They do **not** carry transition-instance identity, object IDs, or Petri-net transition GUIDs.

### 4.1 Effect of Optional Approve Revision and Hidden $\tau$
The choice operator $X(\text{'Approve Revision'}, \tau)$ allows each revision cycle to either execute an explicit approval or silently skip it via $\tau$.
* **Trace Projection:** Under projection $\pi_\Sigma$, $\tau$ transitions vanish ($\pi_\Sigma(\tau) = \epsilon$). In traces where $\tau$ fires, $\text{'Approve Revision'}$ is omitted without leaving a visible placeholder (as in **T_A2** and **T_B3**).
* **Impact on Non-Equivalence:** Hiding $\tau$ does **not** restore equivalence. Even if all approval transitions are skipped via $\tau$, Model A generates traces where $\text{'Check Revision'}$ repeats after every $\text{'Rework Case'}$, whereas Model B strictly produces exactly one $\text{'Check Revision'}$.
* **Ordering Exposure:** When $\text{'Approve Revision'}$ is executed, it exposes a critical synchronization defect in Model B: Model B permits approval to execute before verification has occurred ($\text{Analyze} \to \text{Approve} \to \text{Check}$ in **T_B1**). In Model A, the join preceding the XOR choice ensures that approval can never fire prior to verification.

# 5. Bounded Comparison Code

The following self-contained Python script parses both process trees, converts them into accepting Petri nets, verifies workflow soundness, and performs an exhaustive Breadth-First Search (BFS) over reachable markings under the P3 bound ($|\sigma| \le 12$, $|\sigma|_{\text{'Analyze Revision'}} \le 3$).

```python
import pm4py
from collections import deque

# Process tree definitions
tree_str_a = """->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)"""

tree_str_b = """->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)"""

# 1. Parse process trees
tree_a = pm4py.parse_process_tree(tree_str_a)
tree_b = pm4py.parse_process_tree(tree_str_b)

# 2. Convert to accepting Petri nets
net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

# 3. Check soundness
sound_a, _ = pm4py.check_soundness(net_a, im_a, fm_a)
sound_b, _ = pm4py.check_soundness(net_b, im_b, fm_b)
print(f"Model A Sound: {sound_a}, Model B Sound: {sound_b}")
assert sound_a and sound_b, "Both generated workflow nets must be sound."

# 4 & 5. Exhaustive bounded exploration under P3
def explore_bounded_language(net, im, fm, max_visible_len=12, max_analyze=3):
    """
    Exhaustively computes all complete visible traces reaching final marking fm
    subject to P3 bounds:
      - len(trace) <= max_visible_len
      - trace.count('Analyze Revision') <= max_analyze
    Explicitly handles silent transitions (tau), repeated markings,
    and exact final marking equality.
    """
    def freeze_marking(m):
        return tuple(sorted((p.name, c) for p, c in m.items() if c > 0))

    initial_state = (freeze_marking(im), tuple())
    queue = deque([(im, tuple())])
    visited = {initial_state}
    complete_traces = set()

    while queue:
        curr_m, curr_trace = queue.popleft()

        # Check if marking matches the accepting final marking fm
        if curr_m == fm:
            complete_traces.add(curr_trace)

        # Explore enabled transitions from current marking
        enabled_transitions = pm4py.get_enabled_transitions(net, curr_m)
        for t in enabled_transitions:
            is_visible = (t.label is not None)

            if is_visible:
                # Prune paths exceeding visible length bound
                if len(curr_trace) >= max_visible_len:
                    continue
                # Prune paths exceeding Analyze Revision bound
                if t.label == 'Analyze Revision' and curr_trace.count('Analyze Revision') >= max_analyze:
                    continue
                next_trace = curr_trace + (t.label,)
            else:
                # Silent transition (tau) does not append to visible trace
                next_trace = curr_trace

            # Fire transition t: consume tokens from input places, produce in output places
            next_m = curr_m.copy()
            for arc in t.in_arcs:
                next_m[arc.source] -= arc.weight
                if next_m[arc.source] == 0:
                    del next_m[arc.source]
            for arc in t.out_arcs:
                next_m[arc.target] = next_m.get(arc.target, 0) + arc.weight

            state_key = (freeze_marking(next_m), next_trace)
            if state_key not in visited:
                visited.add(state_key)
                queue.append((next_m, next_trace))

    return complete_traces

traces_a = explore_bounded_language(net_a, im_a, fm_a, max_visible_len=12, max_analyze=3)
traces_b = explore_bounded_language(net_b, im_b, fm_b, max_visible_len=12, max_analyze=3)

# 6. Compare visible trace sets and print unique traces
shared_traces = traces_a & traces_b
unique_a = traces_a - traces_b
unique_b = traces_b - traces_a

print("\n--- Bounded Language Comparison Results (P3 Bound) ---")
print(f"Total traces admitted by Model A : {len(traces_a)}")
print(f"Total traces admitted by Model B : {len(traces_b)}")
print(f"Shared traces (Intersection)     : {len(shared_traces)}")
print(f"Traces unique to Model A         : {len(unique_a)}")
print(f"Traces unique to Model B         : {len(unique_b)}")

print("\nSample Traces Unique to Model A (first 3):")
for t in sorted(unique_a)[:3]:
    print(" ", t)

print("\nSample Traces Unique to Model B (first 3):")
for t in sorted(unique_b)[:3]:
    print(" ", t)
```

### 5.1 Exhaustive Bounded Exploration vs. Playout
* **Exhaustive BFS Exploration:** The search algorithm above guarantees complete coverage of the language subset $L_{\text{P3}}$. By tracking the state space as $(M, \sigma_{vis})$ and systematically evaluating all enabled transitions, it guarantees that every possible interleaving and path leading to $M_f$ within the specified bound is discovered.
* **Why `pm4py.play_out(...)` is NOT Exhaustive:** `pm4py.play_out` relies on stochastic Monte Carlo simulation or heuristic playout. At conflict places (XOR choices, loop exit vs. redo) and concurrent interleavings, it samples paths according to random or uniform probabilities. Consequently:
  1. It provides no coverage guarantee: low-probability paths (such as multiple loop iterations combined with specific interleavings) are frequently missed.
  2. Playout redundancy: multiple simulations generate duplicate common traces while leaving rare corner-case traces unexplored.
  3. Termination: playout terminates after a fixed trace count $N$, which cannot prove the absence of a counterexample trace.

# 6. Stochastic and Footprint Comparison

Process mining provides behavioral footprint matrices and stochastic language distance metrics (such as Earth Mover's Distance) to compare models.

### 6.1 Demonstration Code

```python
import pm4py

# 1. Discover behavioral footprints directly from process trees
fp_a = pm4py.discover_footprints(tree_a)
fp_b = pm4py.discover_footprints(tree_b)

print("Footprint equality:", fp_a == fp_b)
diff_seq_a = fp_a['sequence'] - fp_b['sequence']
diff_par_b = fp_b['parallel'] - fp_a['parallel']
print("In Model A sequence, not in B:", diff_seq_a)
print("In Model B parallel, not in A:", diff_par_b)

# 2. Derive stochastic languages (assumes default uniform distribution at conflicts)
stoch_lang_a = pm4py.get_stochastic_language(net_a, im_a, fm_a)
stoch_lang_b = pm4py.get_stochastic_language(net_b, im_b, fm_b)

# 3. Compute Earth Mover's Distance
emd_value = pm4py.compute_emd(stoch_lang_a, stoch_lang_b)
print(f"Earth Mover's Distance (EMD): {emd_value:.4f}")
```

### 6.2 Analysis of Footprints
The footprint comparison directly confirms behavioral divergence:
* In Model A, `('Check Revision', 'Approve Revision')` belongs to the **sequence** relation ($\to$), because $\text{'Check Revision'}$ must precede $\text{'Approve Revision'}$.
* In Model B, both `('Check Revision', 'Approve Revision')` and `('Approve Revision', 'Check Revision')` belong to the **parallel** relation ($||$), reflecting the lack of synchronization between checking and approval.

### 6.3 Why Equal Footprints or Low EMD Do Not Establish Trace Equivalence
1. **Footprint Limitations:** Footprints only capture pairwise, local relationships between adjacent or concurrent events ($a \to b, a \leftarrow b, a || b, a \# b$). They cannot capture global invariants, loop cardinalities, or long-range dependencies. For instance, footprints cannot detect whether an activity executes exactly once versus once per loop iteration.
2. **EMD Limitations and Declared Probabilities:**
   * **Stochastic Assumption:** PM4Py's `get_stochastic_language` assigns a **uniform probability distribution** across all transitions enabled at each marking. This is an external modeling assumption, not a property of the unweighted process tree.
   * **Exponential Decay Masks Loop Differences:** Under uniform branching at the loop exit/redo choice, the probability of executing $k$ iterations decays exponentially ($2^{-k}$). Traces with 2 or 3 revisions have tiny probabilities ($p < 0.05$). Because EMD computes the minimum transport cost weighted by trace probabilities, substantial behavioral divergence occurring in iterations $k \ge 2$ contributes minimally to the total distance, producing a misleadingly low EMD ($\approx 0.1457$) despite complete operational divergence.
   * **Horizon Truncation:** Deriving stochastic languages over cyclic nets requires truncating the infinite language at an arbitrary depth or probability mass threshold, omitting behavioral differences in the tail.

### 7.2 Exact Derivation and Code
The tree structures and their node counts are derived as follows:
* **Model A:**
  1. `->` (root)
     2. `'Open Case'` (leaf)
     3. `*` (loop)
        4. `->` (loop body)
           5. `+` (parallel)
              6. `'Analyze Revision'` (leaf)
              7. `'Check Revision'` (leaf)
           8. `X` (exclusive choice)
              9. `'Approve Revision'` (leaf)
              10. `tau` (silent leaf)
        11. `'Rework Case'` (loop redo leaf)
     12. `'Close Case'` (leaf)
  *Depth:* Root (1) $\to$ `*` (2) $\to$ `->` (3) $\to$ `+` (4) $\to$ Leaf (5). Max Depth = **5**.

* **Model B:**
  1. `->` (root)
     2. `'Open Case'` (leaf)
     3. `+` (parallel)
        4. `'Check Revision'` (leaf)
        5. `*` (loop)
           6. `->` (loop body)
              7. `'Analyze Revision'` (leaf)
              8. `X` (exclusive choice)
                 9. `'Approve Revision'` (leaf)
                 10. `tau` (silent leaf)
           11. `'Rework Case'` (loop redo leaf)
     12. `'Close Case'` (leaf)
  *Depth:* Root (1) $\to$ `+` (2) $\to$ `*` (3) $\to$ `->` (4) $\to$ `X` (5) $\to$ Leaf (6). Max Depth = **6**.

* **Petri Net Simplicity Derivation:**
  PM4Py implements arc-degree simplicity:
  $$\text{simplicity} = \frac{1}{1 + \max(\bar{d} - 2, 0)}, \quad \text{where } \bar{d} = \frac{2 \cdot |F|}{|P| + |T|}$$
  * For Model A: $|P|=9, |T|=9, |F|=20$. Total nodes = 18. $\bar{d} = \frac{40}{18} = \frac{20}{9} \approx 2.2222$.
    $$\text{simplicity}_A = \frac{1}{1 + (\frac{20}{9} - 2)} = \frac{1}{1 + \frac{2}{9}} = \frac{9}{11} \approx 0.8182$$
  * For Model B: $|P|=7, |T|=7, |F|=16$. Total nodes = 14. $\bar{d} = \frac{32}{14} = \frac{16}{7} \approx 2.2857$.
    $$\text{simplicity}_B = \frac{1}{1 + (\frac{16}{7} - 2)} = \frac{1}{1 + \frac{2}{7}} = \frac{7}{9} \approx 0.7778$$
  Even though Model A generates more places and transitions, its average node degree is closer to the baseline 2, yielding a higher simplicity score than Model B.

```python
def compute_structural_stats(tree):
    nodes = []
    def traverse(curr):
        nodes.append(curr)
        for child in curr.children:
            traverse(child)
    traverse(tree)

    def get_depth(curr):
        if not curr.children:
            return 1
        return 1 + max(get_depth(c) for c in curr.children)

    leaves = [n for n in nodes if not n.children]
    visible_leaves = [n for n in leaves if n.label is not None]
    silent_leaves = [n for n in leaves if n.label is None]

    return {
        "node_count": len(nodes),
        "depth": get_depth(tree),
        "visible_leaves": len(visible_leaves),
        "silent_leaves": len(silent_leaves)
    }
```

# 8. Simplified Model

### 8.1 Target Semantics Selection: P1 (Operational Compliance)
Targeting **P1** is the only defensible operational choice for the business:
1. Model B is operationally unsound because it decouples checks from revisions and permits approval before checking.
2. Model A is compliant with respect to check cardinality, but contains an operational anomaly: the parallel operator `+('Analyze Revision', 'Check Revision')` permits $\text{'Check Revision'}$ to execute *before* $\text{'Analyze Revision'}$, which violates causal reality (a revision cannot be checked before it has been analyzed).
3. By replacing the inner parallel construct with a sequential revision pipeline ($\text{Analyze} \to \text{Check}$), we eliminate spurious interleavings, enforce strict causal compliance, and eliminate concurrency places and arcs.

### 8.2 Compact Process-Tree Expression
```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)

    'Rework Case'
  ),
  'Close Case'
)
```

# 9. Final Recommendation

### 9.1 Suitability of Original Models by Business View

1. **Operational Compliance View (P1):**
   * **Model A:** Conditionally acceptable, but flawed. It guarantees that every revision is checked and approvals are gated, but its inner concurrency permits checking before analysis.
   * **Model B:** **Completely unsuitable.** It creates severe compliance vulnerabilities: cases can undergo multiple rework cycles and approvals with only a single, potentially uncoordinated check.
2. **Executive Dashboard View (P2):**
   * Both Model A and Model B satisfy P2, but only because P2 aggregates away the operational details (collapsing checks to a single Boolean and hiding approvals). Model B’s apparent suitability is an artifact of high-level aggregation masking operational defects.
3. **Bounded Testing View (P3):**
   * Neither model can substitute for the other. With an intersection of only 4 traces out of 76 (A) and 85 (B), they represent radically different execution languages.

### 9.2 Replacement Recommendation
**The proposed Simplified Model should replace both Model A and Model B.**
* It eliminates the concurrency overhead of Model A, reducing Petri net places from 9 to 6 and arcs from 20 to 14, while increasing simplicity from 0.8182 to 0.8667.
* It enforces proper causal ordering ($\text{Analyze} \to \text{Check} \to \text{Approve}$), eliminating the spurious interleavings permitted by Model A.
* It restores complete operational integrity, rejecting the critical compliance failures inherent in Model B.
* It satisfies the P2 executive dashboard view identically while providing a deterministic, deadlock-free, and race-free workflow.

### 9.3 Warning on the Limits of Bounded Comparison
Bounded language comparison ($|\sigma| \le 12$, $|\sigma|_{\text{Analyze}} \le 3$) provides a formal refutation technique: discovering a counterexample within the bound conclusively disproves trace equivalence. However, **bounded equivalence cannot establish unbounded equivalence**. In cyclic processes with redo loops or unbounded buffer places:
* Differences may manifest only after $k > 3$ iterations or after specific token accumulation patterns.
* Two models that coincide across thousands of bounded traces can still diverge on subtle starvation, termination, or fairness conditions in the unbounded tail.
* Bounded verification is a necessary testing filter, but unbounded behavioral equivalence requires structural inductive proofs or bisimulation analysis on the underlying reachability graphs.
