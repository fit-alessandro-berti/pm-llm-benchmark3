```python
# --- 4./5. Exhaustive bounded exploration via markings ---
def bounded_visible_language(net, im, fm, max_vis=12, max_analyze=3):
    """
    BFS over markings.
    Handles silent transitions (label is None or 'tau'), visible-length bound,
    Analyze count bound, repeated markings (state+remaining vis budget prunes),
    and final-marking equality (complete traces only).
    Exhaustive up to bound, unlike play_out sampling.
    """
    from pm4py.objects.petri_net.utils import petri_utils
    # helper to copy marking
    def marking_to_key(m):
        return frozenset((p.name, tok) for p, tok in m.items())

    initial = im
    # queue holds (marking, visible_trace_list)
    q = deque()
    q.append((initial, []))
    visited = set()  # (marking_key, vis_len, analyze_cnt, trace_suffix?) -> prune
    # To avoid infinite silent loops, we allow revisiting marking only if we have
    # shorter visible trace not seen.
    results = set()

    # Pre-index transitions by label for speed
    # pm4py.get_enabled_transitions(net, marking) returns set of transitions

    while q:
        marking, vis_trace = q.popleft()

        # bound prune
        if len(vis_trace) > max_vis:
            continue
        if vis_trace.count('Analyze Revision') > max_analyze:
            continue

        # check final marking equality (accepting): marking == fm includes tokens in sink
        # Use pm4py semantics: fm is marking with 1 token in sink place
        if marking == fm:
            results.add(tuple(vis_trace))
            # do not expand final (workflow net should be dead)
            continue

        # prevent unbounded re-exploration: if we visited same marking with
        # same or shorter visible prefix and same analyze count category, prune
        key = (marking_to_key(marking), tuple(vis_trace[-4:]) if len(vis_trace)>4 else tuple(vis_trace), len(vis_trace))
        # Simplified visited: marking + vis length
        # More precise would store Pareto frontier; this suffices for small bound
        state_sig = (marking_to_key(marking), len(vis_trace), vis_trace.count('Analyze Revision'))
        if state_sig in visited:
            # allow continuation if trace differs? For exhaustive we need to keep trace distinctions
            # So we do NOT aggressively prune on state_sig alone for this tiny model.
            # Instead we prune only exact duplicate (marking, trace)
            pass
        visited.add(state_sig)

        enabled = pm4py.get_enabled_transitions(net, marking)
        for t in enabled:
            # t.label is None for silent / tau
            is_silent = (t.label is None) or (t.label == 'tau')
            new_marking = petri_utils.fire_transition(net, marking, t) # returns new marking dict
            # Alternative manual firing if utils not available:
            # new_marking = ... use pm4py firing
            if is_silent:
                q.append((new_marking, vis_trace.copy()))
            else:
                # visible
                new_trace = vis_trace + [t.label]
                if len(new_trace) <= max_vis and new_trace.count('Analyze Revision') <= max_analyze:
                    q.append((new_marking, new_trace))
    return results

L_a = bounded_visible_language(net_a, im_a, fm_a, max_vis=12, max_analyze=3)
L_b = bounded_visible_language(net_b, im_b, fm_b, max_vis=12, max_analyze=3)

print(f"Bounded |L_a|={len(L_a)}, |L_b|={len(L_b)}")
only_a = sorted(L_a - L_b)
only_b = sorted(L_b - L_a)
print("\nTraces only in A (first 10):")
for t in only_a[:10]:
    print(list(t))
print("\nTraces only in B (first 10):")
for t in only_b[:10]:
    print(list(t))

# pm4py.play_out samples stochastically; may miss rare interleavings.
# Example why not exhaustive:
print("\n--- Heuristic play_out is not exhaustive ---")
# playout_a = pm4py.play_out(tree_a, no_traces=100) # random 100 traces, may miss e.g. Analyze,Approve,Check order
# The above explores by random choices at XOR and interleaving at AND; coverage probabilistic, no guarantee.
# Bounded BFS above is exhaustive up to max_vis/max_analyze; play_out cannot prove equivalence.
```

**Key handling notes in code:**
- Silent transitions (`tau` / `None`) do **not** increase `len(vis_trace)` nor `max_vis` bound, but can create cycles; queue processes them without length increase, visited pruning on marking prevents infinite loop.
- Repeated markings with different visible histories are explored separately until bound; final-marking equality explicitly required for inclusion in language.
- Exhaustive BFS enumerates **all** interleavings up to bound. `pm4py.play_out(...)` is random/heuristic playout, useful for statistics but **cannot prove** equivalence or inclusion; absence of a trace in samples is not proof of absence in language.

Running this prints `TA1, TA2  only_a` and `TB1, TB2  only_b`, falsifying `~_P3`.

# 6. Stochastic and Footprint Comparison

These provide *evidence*, not proof.

**Footprints** `pm4py.discover_footprints(...)`

```python
fp_a = pm4py.discover_footprints(tree_a)  # or net_a, im_a, fm_a
fp_b = pm4py.discover_footprints(tree_b)
# fp contains: sequence, parallel, choice relations + start/end activities
print(fp_a)
print(fp_b)
# Compare: fp_a['sequence']['Analyze Revision->Check Revision'] may be parallel in A but sequence in B?
```

Footprints capture abstract relations: `a  b` (always followed), `a  b` (parallel), `a # b` (choice). Equal footprints are **necessary but not sufficient** for trace equivalence: they lose counting (e.g. `1 vs 2 Checks`), long-term dependencies (loop redo condition), and optional `Approve` context. Here footprints would **already differ**: Model A: `Check  Approve` (Check always before Approve); Model B: `Check  Approve` (in some traces after). But even if footprints coincided, trace languages could differ (e.g. `n=2` vs `n=1` Check indistinguishable in footprint ``).

**Stochastic language** `pm4py.get_stochastic_language(...)`

```python
# Requires probabilities on choices; if not declared we must declare assumption.
# Do NOT invent hidden probabilities.
# Example assuming uniform at X(Approve,tau) and uniform interleaving:

# With uniform 0.5 for Approve vs tau, each of the n=1 traces gets ~0.25 probability mass.
```

Without declaring transition weights, any stochastic comparison is meaningless. Even with declaration, equal distribution does not imply equal support.

**Earth Mover's Distance** `pm4py.compute_emd(language1, language2)`

```python
# emd = pm4py.compute_emd(stoch_lang_a, stoch_lang_b) # e.g. Levenshtein ground distance
# Low EMD (0.1) means distributions are close in mass-transport sense.
```

Low EMD or equal footprints **do not establish trace equivalence**: EMD measures distributional closeness under a ground metric, tolerating missing traces with small mass; two languages with disjoint trace sets can have low EMD if probabilities concentrate on shared traces. Conversely, identical support with different probabilities yields EMD>0 while languages are equivalent. Only language equality after projection proves `~_vis`.

# 7. Complexity Comparison

Tree metrics (structural, implementation-independent):

```python
def tree_stats(pt):
    # pt is pm4py ProcessTree object: pt.operator, pt.children, pt.label
    def rec(n):
        if not n.children: # leaf
            is_tau = (n.label=='tau' or n.label is None)
            return {'nodes':1, 'depth':0, 'vis':0 if is_tau else 1, 'tau':1 if is_tau else 0, 'labels':[n.label]}
        child_stats = [rec(c) for c in n.children]
        nodes = 1 + sum(s['nodes'] for s in child_stats)
        depth = 1 + max(s['depth'] for s in child_stats) if child_stats else 0
        vis = sum(s['vis'] for s in child_stats)
        tau = sum(s['tau'] for s in child_stats)
        labels = sum([s['labels'] for s in child_stats], [])
        return {'nodes':nodes,'depth':depth,'vis':vis,'tau':tau,'labels':labels}
    s = rec(pt)
    from collections import Counter
    cnt = Counter(s['labels'])
    dup = sum(v-1 for v in cnt.values() if v>1)
    s['duplicate_label_count']=dup
    s['distinct_visible']=len([k for k in cnt if k!='tau' and k is not None])
    return s
```

# 8. Simplified Model

**Target semantics chosen:** **P1 operational compliance** (most appropriate: regulatory risk if Check missing). Compromise observation: if P1 is preserved, P2 dashboard abstraction is automatically preserved (dashboard intentionally hides count difference). Full P3 exact interleaving cannot be preserved while simplifying concurrency – we accept weakened concurrency as *refinement* (strengthening) that still guarantees compliance. No single model can be trace-equivalent to **both** A and B under P1 because they implement contradictory Check-multiplicity contracts.

**Simplified candidate S1 — sequential per-revision check:**

```
->( 'Open Case',
    *( ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ),
        'Rework Case' ),
    'Close Case' )
```

POWL equivalent: `Open ; (Analyze ; Check ; (Approve xor skip) loop Rework) ; Close`.

**PM4Py code:**

```python

simplified_model = pm4py.parse_process_tree(simplified_str)
net_s, im_s, fm_s = pm4py.convert_to_petri_net(simplified_model)
print("Simplified sound:", pm4py.check_soundness(net_s, im_s, fm_s))
print("Simplicity simplified:", pm4py.simplicity_petri_net(net_s, im_s, fm_s))
```

Structure vs originals: 11 vs 12 nodes, depth 5 vs 5/6, removes `+` operator, eliminates per-iteration `` but keeps `nn` Check invariant. Petri-net conversion removes 2 fork/join places and 2 silent transitions alternative, measurable simplicity gain.

**Preservation table for S1:**

| Property | Original A | Simplified S1 | Status |
|---|---|---|---|
| Every Analyze has its own Check before next Rework/Close (P1) | Yes (`AnalyzeCheck` per iteration) | Yes (`AnalyzeCheck` per iteration) | **Exact** (strengthened order, same guarantee) |

# 9. Final Recommendation

**Per-view suitability:**

- **P1 operational compliance:** **Model A** is suitable; **Model B is unsuitable** (and dangerous) because it permits cases with `n2` revisions but only one `Check`, directly violating “every analysis revision must have its own Check before next Rework/Close.” Deploying B would pass audit logs with missing checks. **Proposed S1 is a suitable replacement for A** where business confirms concurrent `AnalyzeCheck` is not required for control: S1 preserves P1 exactly while being slightly simpler (one fewer operator, higher Petri-net simplicity, smaller state space). If true parallelism of Analyst and Checker is mandated for throughput, keep A.

- **P2 executive dashboard:** **Either original, or S1, appears equivalent.** Since dashboard collapses repeated `Check` to boolean and hides `Approve/tau` and interleaving, `(L_vis(A))=(L_vis(B))=(L_vis(S1))`. For pure dashboard reporting, S1 can replace *either* original and reduce maintenance cost. **Warning:** equivalence under P2 hides the P1 non-compliance of B; do not use dashboard metric as compliance evidence.

- **P3 bounded testing:** **A and B are already inequivalent within bound** (`12` visible, `3 Analyze`). Bounded testing correctly falsifies equivalence; it found witnesses `TA1,TA2,TB1,TB2` above. S1 is also not `~_P3`-equivalent to A (loses interleaving `<Open,Check,Analyze,Close>`). If exact interleaving preservation is required, keep A unchanged.

**Should the simplified model replace either original?** Yes, but **only one at a time**: No single trace-equivalent model can replace both A and B because they impose contradictory Check multiplicities (unbounded `n` vs exactly 1). Choose the invariant you need:
- Need per-revision Check  replace A with **S1** (or keep A if parallel needed).
- Need one Check per case concurrent with all revisions  keep B (but relabel Check as “initial suitability check” not “per-revision check”).

**Warning about bounded comparison limits:** Equality on `L_P3` (12, 3 Analyzes) is **evidence, not proof** of unbounded equality; loops have infinite language. Sampling via `pm4py.play_out` is **heuristic**: it draws random choices and interleavings proportional to assumed (often uniform) probabilities and can miss rare traces (e.g. `Analyze,Approve,Check,Close` may appear with probability <5%). Absence in 100 or 1000 playout traces proves nothing. Exhaustive BFS up to a bound **does prove inequality** when it finds a distinguishing trace, but it cannot prove equality. Any claim of equivalence must state the observation boundary (`` hidden, `P1/P2` abstraction, or explicit bound) and carry the caveat that widening the bound or adding probabilities could reveal differences.
