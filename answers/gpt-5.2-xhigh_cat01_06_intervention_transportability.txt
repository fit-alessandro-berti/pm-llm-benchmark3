Shared mechanisms: when both verifications can *start early* and run with independent capacity, increasing `true_overlap` shortens the time until both prerequisites are satisfied, reducing join delay and thus `waiting_before_assessment`, which lowers `cycle_time`. This mechanism is plausibly shared across sites for the digital-only stratum, and partially shared for originals-required cases only insofar as Identity can be overlapped with Originals Receipt and Document Check can be “pre-queued” to start immediately when originals arrive.

Site-specific mechanisms: `originals_required` at B inserts a high-variance external delay; `IT_case_lock` and `role_specialization` limit achievable overlap and add handoff/coordination delays; and the legal branch plus supplement loop (captured via `legal_capacity` → `cycle_time` and `rework`) can dominate the tail. Co-interventions at A (`API_latency` improvements and `queue_huddles`) can mimic a parallelization effect via faster tasks and better routing.

Key effect modifiers are `originals_required`, `digital_documents`, `IT_case_lock`, `role_specialization`, capacities (identity/document/assessment/legal), and `case_complexity`. A similar control-flow diagram is insufficient because it omits (i) which tasks are legally startable, (ii) resource contention/queue disciplines, (iii) data-dependent routing (legal requirement), (iv) measurement validity of timestamps/overlap, and (v) co-occurring operational changes that confound before/after contrasts. Thus transport requires matching operational constraints, not only the partial-order skeleton.

## 6. Candidate Site B intervention

Modified intervention (do **not** copy Site A verbatim):

- **Eligibility rules**
  - Stage 1: `originals_required = false` and `legal_required = false` (digital-only, no-legal), any complexity up to a pre-set threshold (e.g., exclude top 10% by predicted complexity).
  - Stage 2: add `originals_required = true` cases but keep `legal_required = false`.
  - Stage 3: include `legal_required = true` with explicit throttling and loop controls.

- **Concurrent creation/execution**
  - After `Register`, create in parallel:
    - `Identity Check` (may execute immediately).
    - `Document Intake/Triage` (checks completeness, requests missing items, scans/indexes; *not* the legally constrained originals-based verification).
    - If `originals_required = true`: `Originals Receipt` tracking task (execute immediately).
  - `Document Check (execution)` may start:
    - immediately after `Register` when `originals_required = false`;
    - only after `Originals Receipt` when `originals_required = true`.
  - `Assessment` may start **only after** `Identity Check` **and** `Document Check (execution)` complete.

- **Statutory prerequisites preserved**
  - No Document Check execution before Originals Receipt when originals are legally required.
  - Legal Review remains mandatory for `legal_required = true` and can trigger supplements.

- **Queue and WIP controls**
  - Per-pool WIP caps (identity/doc/intake/assessment/legal) and a global cap on “verification-in-progress”.
  - A bounded “assessment-ready” buffer; do not release additional verification work if Assessment queue age exceeds a threshold.
  - Aging priority for cases waiting on originals or stuck in supplement loops.

- **Resource responsibilities**
  - Keep specialized roles; add a coordinator role for the pilot lane to enforce prerequisites and WIP.
  - Reserve a small capacity slice in each pool for the pilot lane to reduce interference.

- **Legal review + supplement loop handling**
  - If `Legal Review -> Request Supplement`: create `Supplement Intake`, then `Document Check (redo)`, then `Assessment (redo)`, then return to `Legal Review`.
  - Track `supplement_cycle_count`; escalate or stop after a maximum count (policy-defined).

- **Logging requirements**
  - System-generated start/complete timestamps; explicit “entered-late” flags.
  - Record `originals_required`, `legal_required`, channel, and reasons for delay (lock-wait, missing originals, external lookup latency).
  - Capture `true_overlap` via concurrent active-task states (not only timestamp intervals).

Compact partial-order / POWL-style constraints (stratified):

```text
Digital-only, no-legal:
Register < {Identity Check, Document Check}; {Identity Check, Document Check} < Assessment;
Assessment < (Approve XOR Reject) < Notify

Originals-required, no-legal:
Register < {Identity Check, Originals Receipt}; Originals Receipt < Document Check;
{Identity Check, Document Check} < Assessment;
Assessment < (Approve XOR Reject) < Notify

Legal extension (if legal_required):
Assessment < Legal Review < (Approve XOR Reject) < Notify
Loop on supplement:
Legal Review < Request Supplement < Document Check (redo) < Assessment (redo) < Legal Review
```

The pilot separates mechanism failure from implementation failure by explicitly measuring the mediator chain: if treatment increases **true_overlap** and reduces “time-to-both-verifications-complete” but cycle time does not move, the mechanism is being blocked downstream (assessment/legal bottleneck) rather than failing to execute. Conversely, if overlap does not change (or only recorded overlap changes while system-state overlap does not), the issue is implementation/IT-lock fidelity. Versioning (T1 vs T2 vs T3) isolates which component (parallel creation, trigger-start on originals, throttling) drives changes. Loop metrics (supplement rate, repeat counts, time-in-loop) distinguish quality degradation from pure capacity effects. Negative controls (unchanged steps like Notify timing) help detect global productivity shifts unrelated to parallelization.

## 8. PM4Py model-construction code

```python
import pm4py

from pm4py.objects.powl.obj import Transition, StrictPartialOrder, OperatorPOWL, Sequence
from pm4py.objects.process_tree.obj import Operator as PTOperator
from pm4py.algo.simulation.playout.petri_net.variants import basic_playout


# 1) Site A process trees (before / after)
pt_a_before = pm4py.parse_process_tree(
    "->('Register','Identity Check','Document Check','Assessment',X('Approve','Reject'),'Notify')"
)
pt_a_after = pm4py.parse_process_tree(
    "->('Register',+('Identity Check','Document Check'),'Assessment',X('Approve','Reject'),'Notify')"
)

# 2) Convert to accepting Petri nets
net_ab, im_ab, fm_ab = pm4py.convert_to_petri_net(pt_a_before)
net_aa, im_aa, fm_aa = pm4py.convert_to_petri_net(pt_a_after)

print("Site A before WF-net:", pm4py.check_is_workflow_net(net_ab))
print("Site A after  WF-net:", pm4py.check_is_workflow_net(net_aa))


# 3) Site B candidate using POWL (partial order + optional legal review with supplement loop)
reg = Transition("Register")
notify = Transition("Notify")

# Branch 1: digital-only verification (Identity || Document), then Assessment
id_d = Transition("Identity Check")
doc_d = Transition("Document Check")
ass_d = Transition("Assessment")
po_digital = StrictPartialOrder([id_d, doc_d, ass_d])
po_digital.add_edge(id_d, ass_d)
po_digital.add_edge(doc_d, ass_d)

# Branch 2: originals-required (Identity || Originals Receipt; Document after Originals; Assessment after Identity and Document)
id_o = Transition("Identity Check")
orig_o = Transition("Originals Receipt")
doc_o = Transition("Document Check")
ass_o = Transition("Assessment")
po_originals = StrictPartialOrder([id_o, orig_o, doc_o, ass_o])
po_originals.add_edge(orig_o, doc_o)
po_originals.add_edge(id_o, ass_o)
po_originals.add_edge(doc_o, ass_o)

verif_and_assess = OperatorPOWL(PTOperator.XOR, [po_digital, po_originals])

# Post-assessment: either direct decision OR legal review with a supplement loop
direct_decision = OperatorPOWL(PTOperator.XOR, [Transition("Approve"), Transition("Reject")])

legal = Transition("Legal Review")
req_supp = Transition("Request Supplement")
doc_redo = Transition("Document Check")
ass_redo = Transition("Assessment")
redo_seq = Sequence([req_supp, doc_redo, ass_redo])
legal_loop = OperatorPOWL(PTOperator.LOOP, [legal, redo_seq])
legal_path = Sequence([legal_loop, OperatorPOWL(PTOperator.XOR, [Transition("Approve"), Transition("Reject")])])

post_assessment = OperatorPOWL(PTOperator.XOR, [direct_decision, legal_path])

# Full Site B candidate
model_b = Sequence([reg, verif_and_assess, post_assessment, notify])

# 4-5) Convert POWL model to accepting Petri net
net_b, im_b, fm_b = pm4py.convert_to_petri_net(model_b)

# 6) WF-net / soundness checks
print("Site B candidate WF-net:", pm4py.check_is_workflow_net(net_b))
sound, diagnostics = pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=False)
print("Site B candidate sound:", sound)

# 7) Optional playout: print sample traces
log = pm4py.play_out(
    net_b,
    im_b,
    fm_b,
    parameters={
        basic_playout.Parameters.NO_TRACES: 5,
        basic_playout.Parameters.MAX_TRACE_LENGTH: 50,
    },
)
for i, trace in enumerate(log):
    print("trace", i + 1, [e.get("concept:name") for e in trace])

# 8) Limitations:
# - This control-flow model cannot encode data-dependent rules (e.g., legal_required/originals_required as attributes),
#   resource capacities (4/7/3/2 pools), IT case-lock constraints, or time distributions (API/originals delays).
# - Transport questions hinge on those omitted mechanisms; they must be handled via data + simulation/queueing layers,
#   not only via the Petri net / POWL structure.
```

## 9. Recommendation

`conditional go`

Transfer the **mechanism**, not the observed number: at Site A, the intended change increases *true* overlap between Identity and Document verification and reduces join delay before Assessment. That mechanism is plausibly transferable to **digital-only** cases at Site B, but it is structurally weakened for the 62% of cases requiring originals (Document Check cannot legally start) and is strongly modified by Site B’s specialized roles, IT case-locking, and the mandatory legal/supplement loop for 40% of cases. Site A’s before/after improvement is confounded by added verification FTE, an API latency upgrade, a simpler inbound mix, and daily queue huddles; therefore, the 9-hour median reduction should be treated as an *upper bound* for a best-case stratum, not a transported effect.

Do **not** copy: “create Identity and Document Check simultaneously immediately after Register for every case.” For originals-required cases it violates the practical start condition (and invites pseudo-overlap via back-entry). For legal-required cases it risks tail amplification by pushing incomplete dossiers into legal review, increasing supplement loops and worsening p90 even if medians improve.

Start with the subgroup most likely to exhibit the same mediator chain: **digital-only, no-legal, low-to-mid complexity** cases. Implement parallel execution only where it is legally startable, and pair it with strict WIP controls and logging that distinguishes `true_overlap` from recorded timestamps. Success criteria should prioritize (i) reduced “time until both verifications complete”, (ii) reduced waiting_before_assessment, and (iii) **non-inferior p90** and stable rework/supplement rates. Expand to originals-required cases only after demonstrating that trigger-starting Document Check at Originals Receipt and early Document Intake/Triage reduce idle gaps without increasing rework. Expand to legal-required cases only if legal queue age and supplement-loop metrics remain stable under throttled release.

Evidence that triggers expansion: sustained mediator improvement with stable tail and quality across ≥400 treated cases per stratum. Evidence that triggers modification or abandonment: overlap increases without mediator improvement (implementation failure), mediator improves but p90 worsens (bottleneck shift), or supplements/rework/appeals rise beyond stop thresholds (mechanism/quality failure).

## 10. Assumption register

1. `true_overlap` can be increased at Site B (not just recorded overlap) — needed to test the mechanism — test via system-state “active task” logs + lock-wait auditing — if false, expect no cycle-time gain and misleading overlap KPIs.
2. `originals_required` is known at or immediately after Register — needed for eligibility/trigger logic — test by comparing registration attributes to later legal determinations — if false, misrouting will increase rework and violate prerequisites.
3. Identity Check is legally startable before Originals Receipt — needed to overlap identity with originals delay — test with compliance/legal review and exception logs — if false, concurrency must be limited to intake/administrative tasks.
4. Document Check execution is the main gating predecessor for Assessment in digital-only cases — needed for expected median gains — test by decomposing join delay (“which predecessor finishes last”) — if false, focus shifts to assessment/legal capacity rather than parallelization.
5. Pilot phases can hold staffing and queue policies stable within phase — needed to reduce confounding — test via roster + policy-change log — if false, estimates require stronger adjustment and confidence drops.
6. Rework/supplement rates are sensitive to dossier completeness and coordination — needed to use quality guardrails — test by coding rework reasons and correlating with intake completeness — if false, quality monitoring must use alternative metrics (e.g., external audit outcomes).
7. Interference across arms can be limited (or measured) despite shared pools — needed for causal inference — test by tracking cross-arm resource usage and queue spillovers — if false, switch to cluster/step-wedge designs and report bounds.
8. Appeal behavior responds (at least directionally) to decision quality and/or delays within the pilot horizon — needed for safety monitoring — test with leading indicators (complaints, supplements) and delayed appeal linkage — if false, do not over-interpret appeals; rely on rework/supplement audits.
