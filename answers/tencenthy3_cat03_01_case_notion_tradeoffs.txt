## 1. Analytical assumptions

**Case notion, convergence, and divergence:**  
In this analysis, a *case notion* is a chosen object type whose instances serve as anchors for extracting an event sequence (trace). An event is projected into a case trace if the object instance appears in that event’s direct event-to-object (E2O) relation set. *Convergence* occurs when multiple distinct object instances (of the same or different types) co-occur in a single event, such as O2 and O3 both appearing in `e13` (Pack Package) or `e19` (Issue Invoice). *Divergence* occurs when a single object instance is associated with multiple subordinate objects that follow different physical or administrative paths, such as O1 being split across P1 and P2 (`e11`, `e12`) and subsequently across D1 and D2 (`e15`, `e16`).

**Copied shared events:**  
I treat copied shared events as *both* evidence and duplication. They are evidence of interaction points (e.g., `e16` proves O1, O2, and O3 were physically consolidated in D2), and they are duplication when naive aggregation across flattened cases multiplies the true occurrence count of a single physical business action.

**Analytical transformations:**  
I permit relation propagation through object-to-object (O2O) links *only* as an explicitly separated analytical step (e.g., inferring that because P3 packs I21 and O2 contains I21, `e13` indirectly touches O2). The base flattening strictly respects the supplied direct E2O relations. This separation prevents confounding directly observed execution with graph-inferred context.
