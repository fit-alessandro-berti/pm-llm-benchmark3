```python
from pm4py.objects.petri_net import semantics as pn_semantics

VISIBLE_BOUND = 12        # max visible actions in one explored execution
STEP_BOUND = 96           # max transition firings (kills unbounded tau/token cycles)
STATE_CAP = 500_000       # safety valve against state explosion
MAX_LOOP_ITER = 2         # documented intent: at most 2 verification iterations

def marking_key(m):
    # canonical multiset view; explicit zero counts are not part of a multiset
    return tuple(sorted((p.name, c) for p, c in m.items() if c > 0))

def bounded_visible_traces(net, im, fm,
                           visible_bound=VISIBLE_BOUND,
                           step_bound=STEP_BOUND,
                           state_cap=STATE_CAP):
    """
    BFS over (marking, visible-trace) pairs.
    - transitions with label None are executed but hidden (tau-projection)
    - a trace is accepted ONLY if the reached marking equals fm exactly
      (canonical multiset equality -> proper completion, no residual tokens)
    - silent cycles are cut by the visited-set when they revisit a marking;
      silent/token-generating cycles that keep changing the marking are cut
      by step_bound (reported via truncated=True)
    Returns (accepted: set[tuple[str, ...]], truncated: bool)
    """
    fm_key = marking_key(fm)
    accepted = set()
    visited = set()
    stack = [(im, (), 0)]
    truncated = False
    while stack:
        marking, vis, depth = stack.pop()
        state = (marking_key(marking), vis)
        if state in visited:
            continue
        visited.add(state)
        if len(visited) > state_cap:
            truncated = True
            break
        if marking_key(marking) == fm_key:
            accepted.add(vis)
            continue  # in a sound net nothing is enabled at fm; do not explore past it
        if depth >= step_bound or len(vis) > visible_bound:
            truncated = True
            continue
        for t in pm4py.get_enabled_transitions(net, marking):
            nxt = pn_semantics.execute(t, net, marking)
            if nxt is None:
                continue
            nvis = vis if t.label is None else vis + (t.label,)
            if len(nvis) > visible_bound:
                truncated = True
                continue
            stack.append((nxt, nvis, depth + 1))
    return accepted, truncated
```

```python
def footprint_diff(fp_a, fp_b):
    keys = ("sequence", "parallel", "start_activities", "end_activities", "activities")
    diff = {}
    for k in keys:
```

# 4. Preservation and Loss Audit

Verdicts below cite the §5 checks. `validated preserved` means "established by executing §5 against that artifact, within the stated bounds"; none of the code has been executed as part of this analysis, so `expected preserved` marks claims that are plausible but must be confirmed by running §3/§5. The `PetriTree` column assumes the expected exception; if P2 unexpectedly succeeds, every cell in that column must be re-audited before use.

| Source invariant | POWLPetri | PetriBPMN | PetriTree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| INV-01 register first | validated preserved | expected preserved | conversion failed | validated preserved | Negative witness N-type "AR before R"; trace-set equality in bound |
| INV-02 AR  PE | validated preserved | expected preserved | conversion failed | validated preserved | Footprint `parallel(AR,PE)`; both orders in accepted set. True concurrency vs either-order is *not* separable by traces (see below) |
| INV-03 optionality, silent skip | validated preserved | approximated | conversion failed | approximated | BPMN has no tau; the skip becomes an XOR-gateway branch or an unlabeled task; projected (tau-hidden) trace sets must still match |
| INV-04 loop-entry join (AR  PE) | validated preserved | expected preserved | conversion failed | validated preserved | Negative witness N5 (CT without PE); footprints `sequence`/`causal` relations |
| INV-05 no edge legalloop | validated preserved | ambiguous | conversion failed | validated preserved | Positive witness W3 (LR mid-loop). Layout may *visually* suggest an order the model does not state — that is a rendering risk, not a net-semantics risk |
| INV-06 CT < IT per iteration | validated preserved | expected preserved | conversion failed | validated preserved | Negative witness N2 (IT before CT) |
| INV-07 CD separates iterations | validated preserved | approximated | conversion failed | validated preserved | Negative N4 (exit after CD); bounded trace set contains only `CT IT (CD CT IT)*` shapes |
| INV-08  1 iteration | validated preserved | expected preserved | conversion failed | validated preserved | Negative N3 (RL with no CT); `activities`/`sequence` footprints |
| INV-09 join before RL (incl. silent branch) | validated preserved | ambiguous | conversion failed | validated preserved | Negative N6 (RL before LR); exact-final-marking equality in exploration; skip-branch resolution is invisible in traces when skipped |
| INV-10 finality, proper completion | validated preserved | expected preserved | conversion failed | validated preserved | Soundness diagnostics + acceptance requires `marking == fm` exactly (no residual tokens) |

**True concurrency versus arbitrary interleaving.** The POWL partial order states genuine absence of order; the Petri net encodes it structurally (one token forked into two places). All trace-based and footprint checks in §5, however, can only observe *interleavings*. A hypothetical round-trip net that replaced the AND-split with an XOR between the two sequentializations would pass every trace check while being semantically different (no simultaneity, different state space). Concurrency preservation is therefore `validated preserved` only at the interleaving/footprint level; a claim of true concurrency rests additionally on structural inspection that the converter emitted AND-gateways — a partly visual judgment.

**The lack of an edge between optional legal and verification.** This is a *negative* fact (independence), and negative facts are the easiest to lose silently: a converter that sequences the legal branch before the loop, or folds it into the loop, produces a simpler-looking and still sound net. W3 (LR between IT and CD) is the discriminating witness: it is accepted by the source net and must be accepted by every round-trip net.

**Silent optional behavior.** `skip_legal` is a tau transition. BPMN has no silent-task concept, so the netBPMN step must either introduce an XOR gateway with an unlabeled/empty branch or a blank task. Both are approximations: the first invites a "who decides, and when?" reading; the second invents a visible work item. Trace-level equivalence is preserved only under tau-hiding, which §5 enforces.

**Binary-loop semantics.** POWL `LOOP(do, redo)` means: `do` once, then zero or more `(redo; do)` cycles — at least one iteration, CD only between iterations, never exit via CD. A BPMN rendering via loop marker or back-edge gateway can easily admit zero iterations or exit-after-redo if the gateway wiring is wrong; N3 and N4 are the targeted negative witnesses.

**The join before Release Change.** RL has two structural predecessors (the optional-legal branch and the loop), one of which terminates invisibly when skipped. In BPMN this must surface as an AND-join; if the converter emits an XOR-join, RL could fire when only one branch completes — N6 catches exactly this at the trace level, and exact-final-marking equality catches the residual-token symptom.

**Activity-label uniqueness.** All seven visible labels are unique in the source, so a visible trace is a faithful behavioral signature. If a converter renames, suffixes, or duplicates labels, trace-set comparison silently weakens; §3 asserts `visible_labels_unique` on every net and §5 compares on raw labels.

**Initial and final markings.** Converters are not trusted to return non-null markings (`ensure_markings`). Places have different identities across nets, so markings can never be compared *across* nets; finality is instead checked *per net* by requiring exact equality with that net's own `fm` for acceptance, plus soundness diagnostics (option to complete, proper completion).

**Gateway / routing-node ambiguity in BPMN visualization.** Even a behaviorally perfect BPMN export can be *read* wrongly: AND vs XOR gateway confusion, blank routing tasks mistaken for work, layout-implied order. This is a presentation-layer risk and is treated in §6; it justifies quarantining a *diagram* without rejecting the underlying net.

```python
from pm4py.objects.petri_net import semantics as pn_semantics

# ------------------------------------------------------------------
# Bounds. VISIBLE_BOUND = 14 visible actions covers up to 3 loop
# iterations (2 Correct Defects) plus all fixed activities and LR.
# ------------------------------------------------------------------
VISIBLE_BOUND = 14
STEP_BOUND = 96        # total firings; kills silent/token-generating cycles
STATE_CAP = 500_000    # safety valve against state explosion

def marking_key(m):
    # canonical multiset view; explicit zero counts are not part of a multiset
    return tuple(sorted((p.name, c) for p, c in m.items() if c > 0))

def bounded_visible_traces(net, im, fm,
                           visible_bound=VISIBLE_BOUND,
                           step_bound=STEP_BOUND,
                           state_cap=STATE_CAP):
    """
    DFS over (marking, visible-trace) pairs.
      - transitions with label None are executed but hidden (tau projection);
      - a trace is ACCEPTED only when the reached marking equals fm EXACTLY
        (canonical multiset equality => proper completion, no residual tokens);
      - silent cycles that revisit a (marking, trace) state are cut by the
        visited set; silent cycles that keep changing the marking are cut by
        step_bound; visible growth (the verification loop) is cut by
        visible_bound. Any cut other than the visited set sets truncated=True,
        which voids exhaustiveness claims.
    Returns (accepted: set[tuple[str, ...]], truncated: bool)
    """
    fm_key = marking_key(fm)
    accepted, visited = set(), set()
    stack = [(im, (), 0)]
    truncated = False
    while stack:
        marking, vis, depth = stack.pop()
        state = (marking_key(marking), vis)
        if state in visited:
            continue
        visited.add(state)
        if len(visited) > state_cap:
            truncated = True
            break
        if marking_key(marking) == fm_key:
            accepted.add(vis)
            continue          # nothing may legitimately continue past fm
        if depth >= step_bound:
            truncated = True
            continue
        for t in pm4py.get_enabled_transitions(net, marking):
            nxt = pn_semantics.execute(t, net, marking)
            if nxt is None:
                continue
            nvis = vis if t.label is None else vis + (t.label,)
            if len(nvis) > visible_bound:
                truncated = True
                continue
            stack.append((nxt, nvis, depth + 1))
    return accepted, truncated

# Witness traces (visible labels only; tau hidden)
# ------------------------------------------------------------------

NEGATIVE_WITNESSES = {

def model_footprints(net, im, fm):
    try:
        return pm4py.discover_footprints(net, im, fm)
    except Exception as exc:
        return {"error": repr(exc)}

def footprint_diff(fp_ref, fp_cand):
    diff = {}
    for k in ("activities", "start_activities", "end_activities",
              "sequence", "parallel"):
        a, b = fp_ref.get(k), fp_cand.get(k)
        if isinstance(a, (set, frozenset, list)) and isinstance(b, (set, frozenset, list)):
            if set(a) != set(b):
                diff[k] = {"source_only": sorted(map(str, set(a) - set(b))),
                           "candidate_only": sorted(map(str, set(b) - set(a)))}

def reachability_summary(net, im, fm):
    """Smoke signal only: place identities differ across nets, so state
    counts cannot prove equivalence; a wildly different count is a red flag."""
    try:
        ts = pm4py.convert_to_reachability_graph(net, im, fm)

    except Exception as exc:
        return {"error": repr(exc)}

def playout_check(net, im, fm, accepted):
    try:
        log = pm4py.play_out(net, im, fm)
    except Exception as exc:
        return {"status": f"not tested ({exc!r})"}
    offending = []
    for trace in log:
        vis = tuple(ev["concept:name"] for ev in trace)
        if len(vis) <= VISIBLE_BOUND and vis not in accepted:
            offending.append(vis)

            "offending": offending[:5]}

    try:
        rep["is_workflow_net"] = pm4py.check_is_workflow_net(net)
    except Exception as exc:
        rep["is_workflow_net"] = f"error: {exc!r}"
    try:
        rep["is_sound"] = pm4py.check_soundness(net, im, fm, print_diagnostics=False)
    except Exception as exc:
        rep["is_sound"] = f"error: {exc!r}"

    accepted, truncated = bounded_visible_traces(net, im, fm)
    rep["exploration_truncated"] = truncated
    rep["n_accepted_traces_in_bound"] = len(accepted)
    rep["missing_positive_witnesses"] = sorted(
        w for w, tr in POSITIVE_WITNESSES.items() if tr not in accepted)
    rep["admitted_negative_witnesses"] = sorted(
        w for w, tr in NEGATIVE_WITNESSES.items() if tr in accepted)

        rep["traces_only_in_candidate"] = sorted(accepted - ref_traces)[:10]
    fp = model_footprints(net, im, fm)
    if ref_fp is not None and "error" not in fp and "error" not in ref_fp:

    rep["reachability_summary"] = reachability_summary(net, im, fm)
    rep["playout"] = playout_check(net, im, fm, accepted)

    ok = (rep["is_sound"] is True
          and not truncated
          and not rep["missing_positive_witnesses"]
          and not rep["admitted_negative_witnesses"]
          and (ref_traces is None or rep["trace_set_equal_in_bound"])
          and not rep.get("footprint_differences"))
    rep["status"] = "PASS (within bound)" if ok else "FAIL / QUARANTINE"
```

# 6. Visual-Semantics Review

A BPMN rendering of a behaviorally acceptable net can still be misread:

- **Parallel gateways.** A faithful export shows an AND-split after *Register Change* and AND-joins before the loop and before *Release Change*. If the converter infers XOR gateways (or the reader mistakes forked sequence flows for alternatives), concurrency reads as choice; conversely, the AND-join at release must not be read as "whichever finishes first triggers release" — that is XOR-join behavior and admits INV-09 violations.
- **Exclusive gateways.** The legal optionality appears as an XOR diamond with one labeled and one unlabeled/silent branch. Stakeholders tend to read this as "a decision is taken by someone, at one fixed moment." The model actually states only: *Legal Review may occur at most once, any time after Assess Risk, resolved before Release Change* — including between loop iterations. The XOR encodes do/skip, not timing.
- **Loop visualization.** A loop marker on a subprocess is often read as "repeat as needed, possibly zero times" or "loop until success" with a data condition that does not exist in the model. The actual contract — at least one iteration; *Correct Defect* occurs only between iterations, never as the last act — is invisible in a standard loop rendering.
- **Silent routing nodes.** If the exporter materializes tau transitions as blank or `None`-labeled tasks, readers invent meaning for them ("an unnamed review step?"). If it drops them, the diagram looks cleaner but the routing logic (skip branch, loop exit) becomes implicit and join semantics become harder to reconstruct from the picture.
- **Apparent ordering of layout.** Left-to-right/top-to-bottom placement suggests sequence: *Assess Risk* drawn above *Prepare Evidence* reads as "first"; *Legal Review* drawn adjacent to the loop reads as membership in it; the crossing edge `Prepare Evidence  verification loop` looks like an anomaly or a dependency it is not; split vs join gateways are distinguished only by small markers that are easy to miss.

**Mitigating annotations and documentation.** (1) Attach the §1 invariant table to the diagram as BPMN documentation. (2) Add text annotations: "Assess Risk  Prepare Evidence — any order, possibly concurrent"; "Legal Review — optional; any time between Assess Risk and Release Change"; "Verification —  1 iteration; Correct Defect only between iterations"; "Release — waits for legal decision AND loop completion". (3) Name gateways explicitly (`AND-split: post-registration`, `AND-join: release gate`, `XOR: legal-skip routing`). (4) Label any materialized silent node as `routing (no work)`. (5) State on the diagram that spatial layout carries no semantics. (6) Ship the witness traces as executable examples and keep the Petri-net rendering as the normative companion for engineers.

# 7. Rejection Criteria

Reject or quarantine the artifact when any of the following holds:

1. **Primary-path technical failure:** any stage of P1 raises or returns `None` (net, BPMN, or round-trip net).
2. **Structural unsoundness:** `check_is_workflow_net` is false, or `check_soundness` is false or errors, on any produced accepting net (deadlocks, dead transitions, residual tokens, improper completion).
3. **Unrecoverable markings:** `ensure_markings` cannot establish a unique initial/final marking (zero or multiple candidate source/sink places), or markings are ambiguous in any other way.
4. **Positive-witness loss:** any of W1–W4 is missing from the candidate's accepted set — in particular loss of the skip-legal completion (W1) or of the legal-inside-loop interleaving (W3), which signals a collapsed optionality or an imposed order.
5. **Negative-witness admission:** any of N1–N6 is accepted — most critically release without verification (N3), release before legal-branch resolution (N6), Inspect before Configure (N2), or loop exit via Correct Defect (N4).
6. **Bounded trace-set mismatch:** with `truncated=False` on both nets, the accepted trace sets of `net_from_powl` and a round-trip net differ in either direction (lost required interleaving, or admitted forbidden behavior).
7. **Inconclusive harness:** `truncated=True` on the *source* net — the validation suite itself cannot certify anything; quarantine the verdict and raise bounds.
8. **Footprint drift on shared labels:** e.g., `parallel(AR, PE)` lost (order imposed), `Legal Review` placed in a sequence relation with loop activities, or start/end activity sets changed.
9. **Label-integrity breach:** visible labels renamed, suffixed, or duplicated; silent transitions surfaced as labeled tasks; visible transitions hidden.
10. **Rendering-level contradiction:** the BPMN *diagram* shows wrong gateway types, a fixed order the model does not state, or a misleading loop marker — quarantine the diagram even when the underlying net passes all checks.
11. **Failed exact-final-marking test:** executions that exhaust the visible behavior but terminate with residual tokens, or reach `fm` only via extra firings, fail by construction of the acceptance test and reject the artifact.

# 8. Canonical Representation Recommendation

- **Authoritative representation: the source POWL model** (as version-controlled code plus a serialized export). It is the least-derived artifact; it expresses the partial order, the XOR-skip optionality, and the binary loop directly and readably; every other artifact is regenerable from it. No conversion output may ever become the source of truth.
- **Canonical *verification* artifact: the accepting Petri net `net_from_powl` with its explicit `im`/`fm`**, versioned alongside the POWL. All automated evidence (workflow-net check, soundness, footprints, bounded exploration, witnesses, playout) is computed against this net, because it is the lowest-level representation with native partial-order semantics and explicit completion criteria.
- **Stakeholder visualization: the BPMN model from P1** (`POWL  net  BPMN`), treated strictly as a derivative rendering. It is never fed back into the pipeline, never edited, and always published together with the §6 annotations.
- **Derivative artifacts:** `bpmn_from_net`, round-trip nets, the process tree and `bpmn_from_tree` (if they exist), and all PNGs. Each derivative must ship with its validation evidence: the §5 report (soundness, workflow-net status, trace-set equality within bound, witness verdicts, footprint diff, reachability smoke signal, playout result), the bound parameters and truncation flags, the PM4Py version, a timestamp, and a hash of the source POWL it was generated from.
- **Process-tree intermediate: not allowed on the canonical path.** The expected outcome for this model is an exception, because the crossing dependency `Prepare Evidence  verification loop` makes the net non-series-parallel; that failure is informative and must be logged, not suppressed. A tree intermediate may be produced only in a sandbox; if it unexpectedly *succeeds*, the artifact is quarantined until it passes the full §5 suite, because a "successful" reduction on this structure risks silent serialization of the legal/verification interleaving.
- **Avoiding round-trip drift:** all edits happen in the POWL source only; one build regenerates net, BPMN, and visualizations together; the §5 suite runs as a regression gate on every regeneration; PM4Py (and Graphviz) versions are pinned; BPMN is never edited and back-converted. Any artifact whose validation report is missing, stale (source hash mismatch), or failing is quarantined automatically.

# 9. Residual Uncertainty

Even if every test passes, the following claims remain unestablished:

1. **Unbounded equivalence.** The comparison is exhaustive only within the bounds ( 14 visible actions,  96 firings, i.e., up to 3 loop iterations). Behavioral differences that manifest only from the fourth iteration onward, or behind very long silent prefixes, are undetected; no language-equivalence or bisimulation proof is produced.
2. **True concurrency.** Trace sets and footprints observe interleavings only. A round-trip net that serializes *Assess Risk*/*Prepare Evidence* as a choice between two orders, with the same trace set, passes all checks while denying genuine concurrency; likewise for the legal/verification overlap. Concurrency claims rest on structural (partly visual) inspection of AND-gateways.
3. **Branching-time and decision timing.** After tau-hiding it is invisible *when* the legal-skip decision is resolved. A converted model that commits to skip-or-review earlier or later than the source is indistinguishable to §5, yet behaves differently under stochastic, timed, or resource-constrained interpretation.
4. **Soundness  fidelity.** `check_soundness` establishes generic correctness (deadlock freedom, option to complete, proper completion) — a perfectly sound round-trip net can still encode the wrong process; only the sampled witnesses and bounded trace sets speak to fidelity, and they are samples.
5. **Converter and renderer version dependence.** PM4Py's netBPMN gateway inference, POWLnet translation details, and Graphviz layout are version-dependent; passing results today do not transfer across upgrades without re-running the suite.
6. **Out-of-scope semantics.** Data conditions, roles/authorizations (e.g., *who* may skip Legal Review), durations, deadlines, and resources are not represented in POWL, nets, or BPMN control flow; nothing in this validation says anything about them.
7. **Cross-net marking comparison.** Places have different identities in each net, so finality is validated per net (exact equality with that net's own `fm`) and never structurally against the source net's final marking; a systematic but behaviorally invisible redistribution of places/tokens would go unnoticed.
