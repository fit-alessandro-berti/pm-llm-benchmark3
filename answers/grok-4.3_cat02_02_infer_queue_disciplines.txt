# 5. Operational exceptions and alternative explanations

1. Arrival-scan delay (up to 2 min) – highest plausibility; alters FIFO ordering in QA and QB.  
2. Strategic under-estimation of est_min – medium; would make SPT appear as priority.  
3. Unlogged preemption reasons – medium; explains B01 resumption.  
4. Resource calibration/meeting windows treated as hard constraints – lower; mainly affects QD and QC start times.

# 6. Additional event data needed

- Exact dispatch-decision timestamp (second granularity)  
- Eligibility set at each decision  
- Resource state (busy/idle, current skill match)  
- Appointment tolerance window (± minutes)  
- Preemption reason code (even when none)  
- Policy version active at decision time  
- Queue-entry time (distinct from arrival scan)

# 7. Final synthesis

QD is most identifiable (clear skill constraints). QC is least identifiable (priority and deadline risk observationally equivalent). Inferring pure priority from QC alone would be most dangerous; the data cannot rule out deadline-driven selection.
