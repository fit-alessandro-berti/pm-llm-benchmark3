# 1. Equivalence Notions

Every verdict below is relative to a stated **observation function** `obs: Trace  View`. Two models are "equivalent under view V" iff `{obs_V() :   L(A)} = {obs_V() :   L(B)}`, where `L(·)` is the (generally infinite, loop-generated) set of complete firing sequences from initial to final marking.

**Duplicate visible labels.** Neither process trees nor the resulting Petri nets carry case/instance identifiers. A trace is a *word* over the activity alphabet. Repeated labels (e.g. two `Analyze Revision` events from two loop iterations) are therefore distinguished **only by their position in the sequence**, never by a persistent identity. Where P1 talks about "its own Check Revision," this is not a native identity link — it is an *interpretive grouping* we impose by segmenting the trace at `Rework Case` boundaries. This interpretation is made explicit below and must not be silently assumed to be part of raw trace semantics.

**(a) Visible trace equivalence after hiding .**
Project every firing sequence onto visible labels (drop -labelled transitions, keep all other labels including duplicates). `A _visible B` iff the two (possibly infinite) sets of visible words are set-equal. This is the strongest notion used here and requires no abstraction beyond removing .

**(b) Bounded visible-language equivalence under P3.**
Restrict comparison to `` with `||  12` (visible events) and `count(,'Analyze Revision')  3`. Because this restricted alphabet-bounded language is finite, `A _P3 B` iff the two finite sets are equal, and this is **decidable by exhaustive enumeration**. A witness inside the bound proves inequality unconditionally; absence of a witness inside the bound proves nothing about the unbounded languages ("evidence, not proof").

**(c) Business-relevant equivalence under P1.**
Define a *coverage predicate* `cover()`: partition `` into segments delimited by `Rework Case` (and by `Open Case`/`Close Case` at the ends); `cover()` holds iff every segment that contains an `Analyze Revision` also contains at least one `Check Revision` *in that same segment*. `A _P1 B` requires both (i) the same visible language up to this predicate being *uniformly true* in one and not the other, and (ii) that placement/number of `Approve Revision` remain visible and comparable (P1 says approvals stay relevant — it does not require them to collapse). P1-equivalence is therefore visible-trace equivalence **conjoined with** identical satisfaction of `cover`.

**(d) Abstracted dashboard equivalence under P2.**
Define `h() = (n, checked, reworked)` where `n = count(,'Analyze Revision')`, `checked = (count(,'Check Revision')  1)`, `reworked = (count(,'Rework Case')  1)`, after first hiding  and deleting `Approve Revision` from  entirely. `A _P2 B` iff `{h(): L(A)} = {h(): L(B)}`.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | `*` body = `->( +(AR,CR), X(Approve,) )`; CR is **inside** every iteration | `*` body = `->( AR, X(Approve,) )`; CR is **outside** the loop, in parallel with the whole loop | A re-creates a fresh CR per iteration; B has a single CR for the entire case |
| Min/max `Check Revision` occurrences | exactly `n` (= number of iterations = number of AR), `n  1`, unbounded | exactly `1`, always, independent of `n` | Cardinality of CR is the single decisive structural difference |
| Placement of CR | only within its own iteration, concurrent with that iteration's AR; cannot cross a `Rework Case` boundary | anywhere in the global interleaving of the entire loop's visible events — before the first AR, between any two loop events, or after the last iteration, but only once | B's CR has global placement freedom but zero repeatability; A's CR has local placement freedom but full repeatability |
| Optional `Approve Revision` occurrences | 0 or 1 per iteration (`X(Approve,)`), independent of CR | 0 or 1 per iteration (`X(Approve,)`), independent of CR | Identical in both — not a distinguishing feature |
| Concurrency degree | `n` independent local `+` nodes (one per iteration)  up to `2` AR/CR orderings across iterations | one global `+` between a single CR leaf and the whole loop subtree  CR insertable at any of `O(iterations·events)` positions, but only once | Same operator (`+`) used at different granularity: per-iteration vs. whole-case |
| Join before `Close Case` | `Close Case` waits only for the loop's last iteration (last local `+` and last `X`) to finish | `Close Case` waits for **both** branches of the top `+`: the loop **and** the single, possibly still-pending, CR | In B, CR can even be forced to fire as the very last event before `Close Case`; in A that slot is already fixed to be the last iteration's own CR/AR |

Note: both trees have identical operator multisets `{->, ->, *, +, X}`, identical leaf multisets, and identical total node count (12, see §7) — a textbook case of "similar diagrams, different behavior."

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 (compliance) | **not equivalent** | high | For any run with 2 analysis attempts, A guarantees a CR in every segment (`cover()` always true); B provides exactly one global CR, so `cover()` fails for all segments after the first that contains an AR without its own CR | Even a single iteration (`n=1`) trace can coincide between A and B; the divergence is only visible once `n  2`, which P1 explicitly cares about ("Rework Case separates two analysis attempts") |
| P2 (dashboard) | **equivalent only under stated abstraction** | high | `h()` maps every reachable A-trace and every reachable B-trace onto the same image set `{(n, True, n>1) : n  1}`, because both models force `n  1` and both guarantee `checked = True` (A: 1 CR always; B: exactly 1 CR always) | This equivalence is **only** valid for the exact abstraction `h`; it says nothing about order, approval count, or CR cardinality, all of which differ |
| P3 (bounded testing) | **not equivalent** | high | Concrete within-bound witnesses exist in both directions (§4); `count(,'Analyze Revision')=2  3` and `||=6–7  12` for all four counterexamples | This is a proof of *bounded* inequivalence, not a claim about behavior above the bound — but since it already fails inside the bound, no further reasoning about "evidence vs proof" is needed for P3 itself |

| C3 | `OC,AR,RW,AR,CR,CC` |  |  (CR delayed to the very end) | in A, iteration 1 (containing the first `AR`) has **no** CR in its segment — impossible in A, since every iteration's local `+` forces a CR before the next `RW` | P1, P3 |

All four decisive traces contain **two analysis attempts** (`n=2`), as required.

**Effect of optional `Approve Revision` / hidden .** `Approve Revision` is symmetric in both models (an `X(·,)` choice attached identically to every iteration's body), so its presence/absence never changes which of C1–C4 is admitted — it only adds/removes one optional token per iteration (see C2 vs C1). Hiding  never adds a visible event ( contributes nothing to the trace), so it cannot mask or repair the CR-cardinality mismatch. The single structural fact driving all four counterexamples is: **A  #CR = #AR always; B  #CR = 1 always.** Neither `Approve Revision` nor  can bridge that gap.

# 5. Bounded Comparison Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking
from collections import deque, Counter

MODEL_A = """
->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
"""

MODEL_B = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)
"""

tree_a = pm4py.parse_process_tree(MODEL_A)
tree_b = pm4py.parse_process_tree(MODEL_B)

net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

print("Soundness A:", pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=True))
print("Soundness B:", pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=True))


def fire(marking, transition):
    """pm4py has no single public 'fire transition' call — replicate the
    token game explicitly so the exploration below is self-contained."""
    new_marking = Marking(marking)
    for arc in transition.in_arcs:
        new_marking[arc.source] -= 1
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]
    for arc in transition.out_arcs:
        new_marking[arc.target] += 1
    return new_marking


def marking_key(marking):
    return frozenset(marking.items())


def exhaustive_bounded_traces(net, im, fm, max_visible=12, max_ar=3, max_states=500_000):
    """EXHAUSTIVE breadth-first exploration bounded by P3's visible-length and
    Analyze-Revision-count bounds. Every (marking, partial-trace) state is
    expanded at most once via the `seen` set, so nothing within the bound is
    skipped — this is not a sample, it is a full enumeration of the bounded
    language."""
    start = (im, tuple())
    frontier = deque([start])
    seen = set()
    completed = set()
    explored = 0

    while frontier:
        marking, trace = frontier.popleft()
        key = (marking_key(marking), trace)
        if key in seen:
            continue
        seen.add(key)
        explored += 1
        if explored > max_states:
            raise RuntimeError("state bound exceeded; tighten P3 bound or raise max_states")

        if marking == fm:
            completed.add(trace)

        if len(trace) >= max_visible:
            continue
        if trace.count('Analyze Revision') > max_ar:
            continue

        for t in pm4py.get_enabled_transitions(net, marking):
            label = t.label
            if label == 'Analyze Revision' and trace.count('Analyze Revision') >= max_ar:
                continue
            new_marking = fire(marking, t)
            new_trace = trace if label is None else trace + (label,)
            if len(new_trace) > max_visible:
                continue
            frontier.append((new_marking, new_trace))

    return completed


traces_a = exhaustive_bounded_traces(net_a, im_a, fm_a)
traces_b = exhaustive_bounded_traces(net_b, im_b, fm_b)

only_a = traces_a - traces_b
only_b = traces_b - traces_a

print("Traces admitted ONLY by A (bounded, exhaustive):")
for t in sorted(only_a):
    print(" ", t)

print("Traces admitted ONLY by B (bounded, exhaustive):")
for t in sorted(only_b):
    print(" ", t)

print("P3-bounded equivalence:", traces_a == traces_b)

# --- NON-exhaustive contrast: random/heuristic playout -----------------------
# pm4py.play_out simulates a finite, stochastically-chosen sample of runs.
# It is NOT exhaustive: the absence of a trace from the sample is not
# evidence of its absence from the language, and the sample may include
# traces outside the P3 bound (which must then be filtered, not trusted as-is).
log_a = pm4py.play_out(tree_a, parameters={"num_traces": 200})
log_b = pm4py.play_out(tree_b, parameters={"num_traces": 200})
```

# 6. Stochastic and Footprint Comparison

**Footprints.** `pm4py.discover_footprints` computes, for each ordered pair of activities, whether it is a directly-follows, never-follows, or (both directions observed) "parallel" relation. Footprints are an **existential, count-free abstraction**: they record *that* an order occurs somewhere in the language, never *how many times* an activity occurs relative to another. This is exactly why footprints are unsuited to prove equivalence here — but in this specific case a hand-derived footprint fact already **disproves** equivalence:

- In Model B, `Approve Revision` can be directly followed by `Check Revision` (schedule: iteration finishes with `AR, Approve`, then the still-pending single global CR fires before `Rework Case`/`Close Case`). This is achievable because CR remains available at any point until it fires exactly once.
- In Model A, once `Approve Revision` fires for iteration *k*, that iteration's local `+(AR,CR)` has already completed (Approve is sequenced *after* the `+` node), and the *next* CR only becomes enabled inside iteration *k+1*'s own `+`, which cannot start before `Rework Case` fires. Hence `Approve Revision  Check Revision` is **never** a directly-follows pair in A.

So `discover_footprints(A)  discover_footprints(B)` on at least this pair — a genuine (if narrow) footprint-level distinguishing fact, obtainable in code as:

```python
fp_a = pm4py.discover_footprints(tree_a)
fp_b = pm4py.discover_footprints(tree_b)
print("df-relations only in B:", fp_b['sequence'] - fp_a['sequence'])
print("df-relations only in A:", fp_a['sequence'] - fp_b['sequence'])
```

**Why footprint equality (in general) would still not prove trace equivalence.** Even where footprints coincide, they say nothing about *cardinalities* (A: `#CR=#AR`; B: `#CR=1`) or about which segment a relation instance belongs to. Two models can have identical footprints while one forbids and the other permits `n=5` distinct CR occurrences. Footprint equality is necessary-but-far-from-sufficient evidence.

**Stochastic language / EMD.** `pm4py.get_stochastic_language` and `pm4py.compute_emd` require **declared, not discovered, probabilities**, since neither model has an attached log. We declare, purely for illustration: `P(loop continues) = 0.5`, `P(Approve chosen over ) = 0.5`, uniform ordering probability for every concurrent branch.

```python
params = {"loop_prob": 0.5, "silent_prob": 0.5}  # explicitly declared, not measured
lang_a = pm4py.get_stochastic_language(tree_a, parameters=params)
lang_b = pm4py.get_stochastic_language(tree_b, parameters=params)
emd = pm4py.compute_emd(lang_a, lang_b)
print("EMD (declared-probability model):", emd)
```

A low EMD here would only mean that, **under this arbitrary probability assignment and the chosen ground trace-distance metric**, the two distributions place similar mass on similarly-distant traces (e.g. because both distributions concentrate mass on short `n=1` traces where A and B already coincide). It would say nothing about the exact trace sets, nothing about `cover()` (P1), and would change if the declared probabilities changed — it is evidence about a *specific stochastic instantiation*, not about the qualitative process-tree languages.

# 7. Complexity Comparison

Hand-derived from the tree text (both trees fully enumerated node-by-node):

| Metric | Model A | Model B |
|---|---|---|
| Node count (operators + leaves) | 12 | 12 |
| Operator multiset | `{->, ->, *, +, X}` | `{->, ->, *, +, X}` (same) |
| Max depth (root = 0) | 4 | 5 |
| Visible leaves | 6 (`OpenCase, AR, CR, Approve, RW, CloseCase`) | 6 (same labels) |
| Silent leaves | 1 (``) | 1 (``) |
| Duplicate-label count (structural, in the tree) | 0 (every label appears at exactly one leaf) | 0 |

Both trees are structurally the *same size* with the *same leaf/operator multisets* — the only structural difference is **where** the `+` node attaches (inside vs. outside the `*`), and this single re-attachment produces the entire behavioral divergence in §2–4. This is the clearest demonstration in this task that "similar diagrams" (here: literally identical node/operator/leaf counts) must not be assumed to imply equal behavior.

```python
def count_nodes(node):
    return 1 + sum(count_nodes(c) for c in node.children)

def max_depth(node):
    return 0 if not node.children else 1 + max(max_depth(c) for c in node.children)

def leaf_labels(node):
    if not node.children:
        return [node.label]
    out = []
    for c in node.children:
        out += leaf_labels(c)
    return out

for name, t in [("A", tree_a), ("B", tree_b)]:
    labels = leaf_labels(t)
    visible = [l for l in labels if l is not None]
    silent = [l for l in labels if l is None]
    dup = {k: v for k, v in Counter(visible).items() if v > 1}
    print(name, "nodes:", count_nodes(t), "depth:", max_depth(t),
          "visible leaves:", len(visible), "silent leaves:", len(silent),
          "duplicate labels:", dup)
```

**Petri-net simplicity.** I do not assert exact numeric simplicity values here, because pm4py's tree-to-net converter inserts implementation-specific invisible routing (fork/join/skip) transitions whose exact count depends on the library version and is not something I can safely hand-derive. Use:

```python
print("Simplicity A:", pm4py.simplicity_petri_net(net_a, im_a, fm_a))
print("Simplicity B:", pm4py.simplicity_petri_net(net_b, im_b, fm_b))
```

and report the printed values rather than an invented number. Qualitatively expect B's net to require at least one extra join-synchronization construct at the top level (the single global CR must synchronize with the *entire* loop subtree's completion, not with a single iteration), which is a plausible source of a marginally larger/more complex net than A's per-iteration synchronization — but this must be *measured*, not assumed.

# 8. Simplified Model

**Target semantics chosen: P2 (executive dashboard).** P1 requires exactly the per-iteration coverage invariant that only Model A already provides "for free" — simplifying A further risks silently dropping the very property P1 exists to protect, so A itself, not a simplification, is the right P1 artifact. P2, by contrast, is explicitly an abstraction (it already discards ordering, approval detail, and CR multiplicity), so a genuinely smaller model can represent it faithfully.

**8.1 Process tree**

```text
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      'Analyze Revision',
      'Rework Case'
    )
  ),
  'Close Case'
)
```

`Approve Revision`/`` are dropped entirely (P2 hides them unconditionally, and they never affect `n`, `checked`, or `reworked`).

**8.2 PM4Py assignment**

```python
SIMPLIFIED_DASHBOARD = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      'Analyze Revision',
      'Rework Case'
    )
  ),
  'Close Case'
)
"""

simplified_model = pm4py.parse_process_tree(SIMPLIFIED_DASHBOARD)
net_s, im_s, fm_s = pm4py.convert_to_petri_net(simplified_model)
print("Soundness simplified:", pm4py.check_soundness(net_s, im_s, fm_s, print_diagnostics=True))
```

**8.3 Preservation table**

| Property | Status vs. A/B |
|---|---|
| `n = count(AR)  1` | exact match to both A and B |
| `checked = (#CR1)` always True | exact match to both A and B |
| `reworked = (n>1)` | exact match to both A and B |
| P2 abstracted image set `{(n,True,n>1): n1}` | **exact** |
| Exact ordering of AR/CR/RW | lost (by design — P2 does not require it) |
| `Approve Revision` visibility | abstracted away (matches P2's "hide approvals") |
| P1 `cover()` (per-segment CR) | **lost** — simplified model behaves like B (single global CR), so it must never be used for P1 |
| P3 exact bounded trace set vs. A or B | **not preserved** — different underlying language from both |
| Structural size | 8 nodes, depth 3, 5 visible leaves, 0 silent leaves — smaller than both A and B (12 nodes each) |
