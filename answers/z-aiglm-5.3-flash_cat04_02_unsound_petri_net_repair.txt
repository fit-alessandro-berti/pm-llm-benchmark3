import pm4py
from pm4py.objects.petri_net.obj import Marking


def marking_dict(marking):
    return {p.name: cnt for p, cnt in marking.items()}


def fire_named(net, marking, transition_name):
    """Fire a named transition if enabled; otherwise raise (no silent token moves)."""
    transition = next((t for t in net.transitions if t.name == transition_name), None)
    if transition is None:
        raise ValueError(f"Unknown transition: {transition_name}")
    enabled_names = {t.name for t in pm4py.get_enabled_transitions(net, marking)}
    if transition_name not in enabled_names:
        raise ValueError(
            f"{transition_name} is NOT enabled in marking {marking_dict(marking)}"
        )
    new_marking = Marking()
    for place, cnt in marking.items():
        new_marking[place] = cnt
    for arc in transition.in_arcs:
        new_marking[arc.source] -= 1
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]
    for arc in transition.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + 1
    return new_marking


def replay(net, im, sequence, label):
    print(f"--- {label} ---")
    marking = Marking(im)  # hmm, does Marking(im) copy? Marking is dict subclass; Marking(im) works if im is dict of place->count.
    print("start:", marking_dict(marking))
    for name in sequence:
        marking = fire_named(net, marking, name)
        print(f"fired {name:>18} ->", marking_dict(marking))
    print("final replay marking:", marking_dict(marking))
    return marking

    print("check_soundness ->", sound)

    print("enabled at im:", sorted(t.name for t in pm4py.get_enabled_transitions(net, im)))

          "| arcs =", len(rg.transitions) if hasattr(rg, "transitions") else "n/a")

# 1. Executive Verdict

### Counterexample 1 — authorization *before* analysis (premature authorization)

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (initial `im`) | `source=1` | `t_register` | legal start |
| 1 | `t_register` | `p_ready=1` | `t_split` | case registered |
| 2 | `t_split` | `p_analysis=1, p_review=1` | `t_analyze`, `t_standard_review`, `t_waive_review` | one token created in **each** parallel branch |
| 3 | `t_waive_review` | `p_analysis=1, p_waived=1` | `t_analyze`, `t_join_waived` | waiver recorded; `t_join_waived` is **already enabled although the analysis has not run** |
| 4 | `t_join_waived` | `p_analysis=1, p_decision=1` | `t_analyze`, `t_authorize` | the oneinput join ignores the analysis branch; `t_authorize` is now enabled |
| 5 | `t_authorize` | `p_analysis=1, sink=1` | `t_analyze` | **a token exists in the sink, but the marking  `fm`**; authorization occurred before `t_analyze` |
| 6 | `t_analyze` | `p_analysis_done=1, sink=1` | — (none) | forced move; **deadlock outside `fm`** |

### Counterexample 2 — authorization *after* analysis (still improper completion)

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (initial `im`) | `source=1` | `t_register` | |
| 1 | `t_register` | `p_ready=1` | `t_split` | |
| 2 | `t_split` | `p_analysis=1, p_review=1` | `t_analyze`, `t_standard_review`, `t_waive_review` | parallel branches created |
| 3 | `t_analyze` | `p_analysis_done=1, p_review=1` | `t_standard_review`, `t_waive_review` | analysis completes first |
| 4 | `t_waive_review` | `p_analysis_done=1, p_waived=1` | `t_join_waived` | waiver chosen; `p_review_done` is now unreachable |
| 5 | `t_join_waived` | `p_analysis_done=1, p_decision=1` | `t_authorize` | `t_authorize` enabled after `t_analyze` — yet the analysis token was **not consumed** |
| 6 | `t_authorize` | `p_analysis_done=1, sink=1` | — (none) | even the wellordered waiver execution ends in a terminal, **nonfinal** marking |

**Why the leftover token can never be consumed.** `p_analysis_done` has exactly one consumer, `t_join_normal`, which additionally requires `p_review_done`. `p_review_done` can only be produced from `p_review`, whose single token was consumed by `t_waive_review` (XOR choice, no cycle refills it). Hence after the waiver choice, any analysis token is stranded — whether it still sits in `p_analysis` (CE1; `t_analyze` merely moves it into the trap) or already in `p_analysis_done` (CE2). By the same argument, **every** firing sequence that uses `t_waive_review` terminates in `{p_analysis_done=1, sink=1}`; `fm` is reachable only via the standard route. Note the distinction: step 5 of CE1 and step 6 of CE2 both have *a token in the sink*, but neither *is* the exact final marking `fm={sink:1}`.

On the defect count: I found **no independent second defect**. CE1 and CE2 isolate the two symptoms — an ordering violation (`t_authorize` before `t_analyze`) and a tokenconservation violation (improper completion) — of the single structural root cause: `t_join_waived` lacks its second input.

# 4. Minimal-Repair Alternatives

**Editcost model C:** cost = 1 per arc added/removed + 3 per place added/removed + 3 per transition added/removed + 1 per label change. (Arcs are the finestgrained controlflow edits; places/transitions restructure state.) A valid repair must restore soundness and either preserve the stated policy or state the policy change explicitly. Under an equalweight model (every edit = 1) the ordering of the repairs below is unchanged.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1** — proper twoinput waiver join | add arc `p_analysis_done  t_join_waived` | **1** | Analysis stays mandatory on **both** routes; waiver keeps its own place and visible label; no labels change | Standard route untouched; waiver route now waits for analysis before the join | None behavioral: the two silent joins have disjoint, mutually exclusive presets, so no confusion; only a mild readability cost (two silent joins into `p_decision`) |
| **R2** — merge waiver into the normal synchronization | remove arcs `t_waive_reviewp_waived`, `p_waivedt_join_waived`, `t_join_waivedp_decision`; remove place `p_waived`; remove transition `t_join_waived`; add arc `t_waive_reviewp_review_done` | 4 arcs + 3 + 3 = **10** | Analysis mandatory (via `t_join_normal`); both review outcomes still recorded by visible labels | Waiver and standard review converge earlier; the marking no longer records which outcome occurred (only the event label does); one silent join instead of two | Outcome distinguishability survives only via the label, not the state; larger edit touches more elements |
| **R3** — *policy change:* waiver cancels the pending analysis | add arc `p_analysis  t_waive_review` | **1** | No leftovers; authorization properly gated; soundness restored | **Policy change (stated):** recording a waiver also consumes the pending analysis token, so waived cases are authorized *without* analysis, and a waiver is only possible **before** the analysis completes (afterwards only the standard review remains) | Race between `t_analyze` and `t_waive_review`: once analysis has run, the waiver option disappears; business must accept waiverbeforeanalysis semantics |
| **R4** — *policy change:* waiver decided at registration | remove arcs `p_reviewt_waive_review`, `t_waive_reviewp_waived`; add arcs `p_readyt_waive_review`, `t_waive_reviewp_waived` | **4** | Sound; proper completion; waiver keeps its label and its own join | **Policy change (stated):** a waived case never enters the parallel phase at all — neither review nor analysis is started; analysis is mandatory only for standardreview cases | No posthoc waiver; the model no longer represents "review started, then waived" |

(A fifth option — deleting the waiver feature entirely — costs 10 under C (4 arcs + place + transition) and is **rejected**: it removes a required business capability.)

**Minimality justification.** Cost 0 is impossible (the unchanged net is unsound). Any repair that keeps analysis mandatory must create a new *consumption* relation from the analysis branch (`p_analysis` or `p_analysis_done`) into a transition on the waiver route's path to the sink; the cheapest such edit is a single arc, so the lower bound is 1. Pure removals cannot fix the net, because the defect is a **missing consumer**, not an extra one: removing any single arc either kills a needed route, removes a producer/consumer needed for completion, or still leaves `p_analysis_done` unconsumed on the waiver route. Checking all singlearc additions confirms only two attain cost 1: `p_analysis_done  t_join_waived` (R1) and `p_analysis  t_waive_review` (R3). (Other candidates fail: `p_analysis  t_join_waived` strands `p_analysis_done` if analysis ran; `p_waived  t_join_normal` demands `p_review_done  p_waived`, unsatisfiable after the XOR; `p_analysis_done  t_authorize` disables the standard route because `t_join_normal` already consumed the token.) Note that *directly* adding `p_waived  t_join_normal` is invalid in Petri semantics — multiple input places are AND, not OR — which is why the "rewire into the normal synchronization" family must be realized as R2 (converge into `p_review_done`) or as a duplicated join (R1). **R1 and R3 tie at cost 1**; the tie is broken by policy fidelity: R1 preserves the stated business rule verbatim, so R1 is the deployment choice and R3 the equally cheap policychanging alternative. R2 (10) and R4 (4) are deliberately nonminimal but admissible distinct families.

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

# Assumes the original variables `net`, `im`, `fm` and the repaired variables
# `repaired_net`, `repaired_im`, `repaired_fm` already exist in scope.


def marking_dict(marking):
    return {p.name: c for p, c in marking.items()}


def fire_named(net, marking, transition_name):
    """Fire a named transition only if it is enabled; otherwise raise."""
    transition = next((t for t in net.transitions if t.name == transition_name), None)
    if transition is None:
        raise ValueError(f"Unknown transition: {transition_name}")
    enabled_names = {t.name for t in pm4py.get_enabled_transitions(net, marking)}
    if transition_name not in enabled_names:
        raise ValueError(
            f"{transition_name} is NOT enabled in marking {marking_dict(marking)}"
        )
    new_marking = Marking()
    for place, count in marking.items():
        new_marking[place] = count
    for arc in transition.in_arcs:
        new_marking[arc.source] -= 1
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]
    for arc in transition.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + 1
    return new_marking


def replay(net, im, sequence, label, fm=None):
    print(f"--- {label} ---")
    marking = Marking()
    for p, c in im.items():
        marking[p] = c
    print("start:", marking_dict(marking))
    for name in sequence:
        marking = fire_named(net, marking, name)
        print(f"fired {name:<18} ->", marking_dict(marking))
    if fm is not None:
        reached = marking_dict(marking) == marking_dict(fm)
        print("reached the EXACT final marking fm:", reached)
    return marking


def enabled_after(net, im, sequence, label):
    marking = Marking()
    for p, c in im.items():
        marking[p] = c
    for name in sequence:
        marking = fire_named(net, marking, name)
    print(label, sorted(t.name for t in pm4py.get_enabled_transitions(net, marking)))


def reachability_summary(rg):
    states = list(rg.states)
    sources_of = set()
    for tr in rg.transitions:
        sources_of.add(tr.from_state.name)
    dead = [s.name for s in states if s.name not in sources_of]
    print("reachability graph: states =", len(states), "| dead (terminal) states =", len(dead))


def run_diagnostics(name, net, im, fm):
    print("=" * 60)
    print(name)
    print("=" * 60)
    print("is_workflow_net:", pm4py.check_is_workflow_net(net))
    try:
        sound = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
    except Exception as exc:  # some pm4py versions raise on unsound nets
        sound = f"raised {type(exc).__name__}"
    print("check_soundness ->", sound)
    print("enabled at im:", sorted(t.name for t in pm4py.get_enabled_transitions(net, im)))
    reachability_summary(pm4py.convert_to_reachability_graph(net, im, fm))


# Counterexample on the ORIGINAL net: premature authorization + stranded token.
replay(net, im,
       ["t_register", "t_split", "t_waive_review", "t_join_waived",
        "t_authorize", "t_analyze"],
       "ORIGINAL net: waiver route (defect)", fm=fm)

# The only consumer of p_analysis_done is unreachable after the waiver choice:
try:
    replay(net, im, ["t_register", "t_split", "t_waive_review", "t_join_normal"],
           "ORIGINAL net: attempt to consume the analysis token via t_join_normal")
except ValueError as err:
    print("blocked as expected:", err)

# Same route on the REPAIRED net: analysis is forced before the waiver join.
replay(repaired_net, repaired_im,
       ["t_register", "t_split", "t_waive_review", "t_analyze",
        "t_join_waived", "t_authorize"],
       "REPAIRED net: waiver route (sound)", fm=repaired_fm)

# The repaired net must reject the premature sequence:
try:
    replay(repaired_net, repaired_im,
           ["t_register", "t_split", "t_waive_review", "t_join_waived"],
           "REPAIRED net: premature join attempt (must fail)")
except ValueError as err:
    print("blocked as expected:", err)

# Contrast enabledness at the critical intermediate marking {p_analysis=1, p_waived=1}:
enabled_after(net, im, ["t_register", "t_split", "t_waive_review"],
              "ORIGINAL  enabled after waiver:")
enabled_after(repaired_net, repaired_im, ["t_register", "t_split", "t_waive_review"],
              "REPAIRED  enabled after waiver:")

run_diagnostics("ORIGINAL net", net, im, fm)
run_diagnostics("REPAIRED net", repaired_net, repaired_im, repaired_fm)
```

Repaired: `check_soundness`  `True` with no diagnostics; the **only** terminal state corresponds to `fm`; `t_join_waived` before `t_analyze` is rejected by the enabledness check. At the critical marking `{p_analysis=1, p_waived=1}`, the original enables `{t_analyze, t_join_waived}` while the repaired net enables only `{t_analyze}`. Handderived state counts (verify with the script): 14 reachable markings for the original, 10 for R1.

# 7. Repair Trade-Offs and Residual Risks

- **Distinguishability of the two review outcomes.** R1 keeps `p_waived` and `p_review_done` as separate states and both visible labels, so waiver and standard review remain fully distinguishable in model and log. R2 keeps the labels but converges into `p_review_done`, so distinction survives only in the event stream, not in markings. R3/R4 keep the visible waiver label but change *when* it may occur.
- **Duplicate behavior / silenttransition confusion.** R1 adds no new silent transitions. The net already contains three (`t_split`, `t_join_normal`, `t_join_waived`); the two joins have disjoint, XORexclusive presets, so no firing sequence becomes ambiguous and no behavior is duplicated. R2 actually removes one silent join. The genuinely risky family is a *silent skip* of analysis: two traces differing only by a silent skip are indistinguishable in logs — one reason I prefer R4's explicit presplit waiver choice over a silent skip variant.
- **Soundness  business conformance.** Soundness guarantees option to complete, proper completion, and no dead transitions — nothing more. R4 (and any skipbased variant) is sound **while violating** "analysis is always mandatory"; soundness would not flag that. Policy rules such as "Authorize Case requires a prior Perform Analysis and exactly one of Perform Standard Review / Record Review Waiver" must be checked with alignments or declarative constraints (e.g., LTL/response rules), not inferred from a `True` soundness result.
- **Regression traces.** Positive: `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize`; `t_register, t_split, t_standard_review, t_analyze, t_join_normal, t_authorize`; `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`; `t_register, t_split, t_waive_review, t_analyze, t_join_waived, t_authorize` (R1/R2; under R3 the last order must be rejected, under R4 both waiver orders are impossible). Negative: any trace with `t_authorize` but no `t_analyze`; `t_waive_review` followed by `t_join_waived` without analysis; traces containing both `t_standard_review` and `t_waive_review`; traces ending with a sink token plus leftovers (e.g., `{p_analysis_done:1, sink:1}`).
- **Detecting an accidental bypass of mandatory analysis.** (a) *Bottleneck test:* delete `t_analyze` and its arcs from the repaired net and assert `fm` becomes unreachable — if not, analysis is no longer structural. (b) *Alignment conformance* against the repaired model: any missing "Perform Analysis" model move is a red flag. (c) *Declarative monitoring:* every case must satisfy "`Perform Analysis` before `Authorize Case`" in production logs. (d) For R3/R4, the bypass is intended, so the check must instead verify the recorded waiver precedes authorization.

# 8. Final Recommendation

**Deploy R1** (add the single arc `p_analysis_done  t_join_waived`). It attains the proven lower bound of the cost model — one arc, no new places or transitions, no label changes — and it restores the missing ANDsynchronization exactly where it is missing, on the waiver route. The standard route is untouched, so the regression surface is minimal; the waiver remains a firstclass, distinguishable outcome with its own place and visible label; analysis stays mandatory on every path to `t_authorize`; and the repaired net is sound with a single terminal marking equal to `fm`.

**Fallback: R2** (route `t_waive_review` into `p_review_done` and delete `p_waived`/`t_join_waived`; cost 10). Choose it if the team prefers a single silent synchronization point over two: it is equally policypreserving and structurally simpler, at the price of a larger edit and of outcome distinguishability surviving only through the visible event label.

**R3 and R4 are conditional.** Both make analysis skippable for waived cases (R3 additionally forces the waiver to be recorded before the analysis starts) and both are sound, but they change the stated business rule. They must not ship without explicit business signoff precisely because a passing soundness check would silently legitimize the policy change. Before any deployment, rerun the Section 6 diagnostics on both nets, replay the two counterexamples (the prematureauthorization sequence must be rejected on the repaired net), and execute the Section 7 positive/negative regression traces.
