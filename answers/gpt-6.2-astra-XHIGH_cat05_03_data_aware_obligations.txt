## 1. Temporal Data Semantics

For each case I order events by the UTC pair (event timestamp, event_index). Write x ≺ y when the pair for x is lexicographically smaller than the pair for y. Thus x ≺ y means x happened strictly before y, including when their clocks agree and x has the lower index. At each event e, S(e) includes the updates on e itself. For each transaction attribute it contains the most recent nonblank observation through e, or unknown if there has been none. A blank leaves the prior value in place. I take the review and approval events in this extract to represent completed actions. A list-update row identifies the jurisdiction added to the list. It changes the list and supplies no new transaction declaration.

A review covers the state at its completion. For amount I use the reviewed amount as the baseline and a strict greater-than-20% test. This catches several small increases that cumulatively cross the threshold. Once crossed, a later decrease cannot restore that packet. A fresh review establishes a fresh baseline for the obligations that type of review can satisfy. A standard packet cannot renew an enhanced packet. For other materiality I treat a change of jurisdiction, risk level or customer class as a change in the review context for R1. For R2 I require the enhanced packet to cover the HIGH or PEP basis present at release and the approval to cover that packet. These are interpretations of “material” and “relevant.” R4 itself only invalidates amount-dependent coverage. A change before the first review has no prior packet to invalidate.

Event time dates an action. Effective time determines when a fact or grant applies. Record time dates its entry in a system. Evidence time dates an attestation, such as a trusted signing timestamp, or the later observation at which an assessor can substantiate a fact. These times can differ. By default an attribute observation applies starting at its event. I give a different effective time weight only to the extent supported by evidence. An assessor can use a later-retrieved signed grant to establish an earlier approval. In contrast, the settlement observation establishes EUR 150,000 on April 7 and says only “may equal” about April 6. Release decisions use S(release), and review adequacy uses S(review) as well.

For definite missing-activity findings I assume the supplied activity log, list additions and candidate grants cover the stated period and cases. I preserve explicit gaps in attribute values and disputed evidence. R3 is a repeat-screen duty following a matching addition and an earlier screen. The supplied rules impose no general initial-screen duty. An exemption reference identifies a candidate grant. In this extract both grants that could match a release by scope are referenced on that release, and both waive R1 only.

**Pseudo-logic.** Let t be a release, r a review, a an approval, u an update and s a screen. All action witnesses are for the same case as t. List facts are shared and keyed by jurisdiction. x ≼ y means x ≺ y or x = y. Every interval below runs from earlier to later. Use three-valued AND, OR and implication (G ⇒ W means ¬G OR W). A definite alternative witness suffices.

1. **R1.** G1(t) = (S(t).jurisdiction ≠ DE) AND (S(t).amount ≥ 100000). Require G1(t) ⇒ (E1(t) OR W1(t)). E1(t) holds if there is a completed enhanced r ≺ t with adequate amount evidence and no material change m with r ≼ m ≼ t. Equivalently, r must strictly follow the last applicable material change, if any. W1(t) is a valid R1 grant under R5.
2. **R2.** G2(t) = (S(t).risk = HIGH) OR (S(t).type = PEP). Require G2(t) ⇒ ∃r,a [Enhanced(r) AND covers_release_risk_basis(r,t) AND Approve(a,r) AND r ≺ a ≺ t]. Approve(a,r) refers to the packet approved. A standard-only approval supplies no such witness.
3. **R3.** For every Add(j,u) with j = S(t).jurisdiction and u ≺ t, if an applicable screen s₀ ≺ u exists, require an applicable s₁ with u ≺ s₁ ≺ t. Operationally a new addition reopens a previously screened jurisdiction, and a subsequent screen closes the duty up through that addition. An update for XZ is irrelevant to a US release.
4. **R4.** With b = S(r).amount, a later upward update u crosses the threshold when S(u).amount > 1.20 × b. On crossing, mark the reviewed packet stale for amount-dependent duties from u onward. Track the latest review of either kind and retain the baseline of any enhanced packet still being relied on. A new enhanced review after u can satisfy R1. A known decrease does not initiate invalidation. If a possible crossing depends on an unknown baseline or amount, the packet's amount coverage is uncertain.
5. **R5.** Wk(t) = ∃g [k in g.waived_rules AND g.authority = Head_Compliance AND g.from ≤ time(t) < g.expiry AND scope_matches(g,S(t)) AND credible_approval_by(g,t)]. I use an exclusive expiry endpoint. Neither release is at expiry. If an approval and release share a timestamp, an effective-from date alone cannot place the approval first. Use the source order or independent evidence that the grant already existed.
6. **R6.** Evaluate using the known facts. For example, false AND unknown is false, true OR unknown is true. A proven deviation gives NONCOMPLIANT. Otherwise a decisive unresolved duty gives INDETERMINATE. If all active duties are discharged, use JUSTIFIED_EXCEPTION when a waiver is needed and COMPLIANT when the ordinary evidence suffices.
7. **R7.** For attribute f, S(e).f = value of the last supported transaction update to f effective at or before e, or unknown if none. Order same-time events by source index. Never take an update effective after e as the default for S(e).

## 4. Ambiguities and Alternative Readings

- **TX-302.** A reporting convention that labels any release expressly invoking a proven waiver JUSTIFIED_EXCEPTION would use that label because the release cites EX-77. I report COMPLIANT because the enhanced review independently discharges R1. If that packet were shown to have been incomplete at release, the verified grant would become necessary and the finding would change to JUSTIFIED_EXCEPTION. Losing confidence in the grant alone would leave the ordinary review route intact.
- **TX-305.** An immutable release payload below EUR 100,000 would exclude R1. A high release amount together with an authenticated amount-bearing enhanced packet and a complete history showing no subsequent material change would satisfy R1. A high release amount plus proof of a material increase after the only enhanced review would establish a breach. Merely discovering a high release amount settles the trigger while leaving the review baseline open. A reading that accepts any logged enhanced review until a change is positively proved could credit the existing review, but the blank packet makes amount coverage unverified under the stated evidence standard.
- **TX-310.** A contemporaneous, authenticated Head_Compliance authorization identifying EX-88 and its scope, or independent corroboration of the oral decision if oral approval is permitted, could yield JUSTIFIED_EXCEPTION. An authoritative audit trail showing that first approval was after 10:00 would yield NONCOMPLIANT. A policy requiring a qualified signature by release would also reject the offered oral route and the post-release certificate would not support timely signing. Under the supplied policy the interested witness provides weak evidence and the PDF has a timing conflict. A preventive gate could block release while an assessor records historical uncertainty.
- **TX-311.** If authoritative effective-time evidence moved the DE change until after release, release would be foreign and R1 would activate. The supplied US enhanced review could still satisfy it. If the effective jurisdiction changed from US to a different foreign jurisdiction after the review and before release, the review would need to cover the new context under the materiality interpretation used here. Without a fresh review or waiver that would yield NONCOMPLIANT. Swapping just indices 3 and 4 would change the review snapshot to DE but would still leave DE at release. The given order is unambiguous.
- **TX-306 and TX-309.** Treating every amount increase as requiring a new review would reverse TX-306, contrary to R4's threshold. For TX-309, if a source correction proved that the final increase took effect only after release, the 118,000 enhanced packet would still cover the release and the case would be COMPLIANT. Its actual recorded effective order places the second crossing before release.

## 5. PM4Py and pandas Checking Code

The script takes the transaction and register evidence as inline input. It emits one diagnostic row per (case, release), preserving repeated releases if present. Boolean evidence flags use None for unknown. Where the log lacks packet IDs, the checker uses the single preceding enhanced packet for an ordinary approval, honors the explicit standard-only note, and exposes ambiguous links for review. The register separates trusted timestamps from displayed fields and testimony.

```python
assert not raw.duplicated([C, T, I]).any()

ev = pm4py.format_dataframe(raw.sort_values(order), case_id=C, activity_key=A,
                            timestamp_key=T).sort_values(order, kind="stable").copy()

def key(row):
    return (row[T], int(row[I]))

def records(frame):
    # Python scalars and None for missing evidence, including after a left join.
    return frame.astype(object).where(frame.notna(), None).to_dict("records")

list_rows = ev[A].eq("Sanctions_List_Update")
# All list updates in this fixture are effective additions.
adds = [(key(d), d["jurisdiction"]) for d in records(ev.loc[list_rows])]
ev.loc[list_rows, "jurisdiction"] = None
# Preserve the database write as evidence with its OWN time.
insertions = (ev.loc[ev[A].eq("Record_Exemption")]
              .groupby("exemption_id")[T].min().rename("recorded_at"))

ev["amount_written"] = ev["amount"].notna()
ev[fields] = ev.groupby(C, sort=False)[fields].ffill()

def and3(*xs):
    return False if False in xs else (None if None in xs else True)

def or3(*xs):
    return True if True in xs else (None if None in xs else False)

def implies(g, w):
    return or3(None if g is None else not g, w)

def eq(x, y):
    return None if x is None or y is None else x == y

review_names = {"Standard_Review", "Enhanced_Review"}
releases = []
for case_id, trace in ev.groupby(C, sort=False):
    prev = latest = enhanced = None
    material = possible_material = None
    context = ["jurisdiction", "risk_level", "customer_type"]
    last = {}                    # activity -> most recent completion key
    packets, links, screens = [], [], []
    crossings = []               # (review key, invalidating amount-update key)
    basis_since = {}             # when each current risk designation began

    for d in records(trace):
        k, act, amt = key(d), d[A], d["amount"]
        if prev is not None:
            for f in context:
                if d[f] != prev[f]:
                    if prev[f] is None:
                        possible_material = k
                    else:
                        material = k
            old = prev["amount"]
            if d["amount_written"] and (old is None or amt > old):

                monitored = [latest] if latest is not None else []
                if enhanced is not None and enhanced is not latest:
                    monitored.append(enhanced)
                for packet in monitored:

                    if old is None or base is None:
                        possible_material = k
                        packet["stale"] = or3(packet["stale"], None)

                        if packet["stale"] is not True:
                            crossings.append((packet["key"], k))

            if prev is None or prev[f] != d[f]:
                basis_since[f] = k
        if act in review_names:
            latest = dict(key=k, amount=amt, stale=False, jurisdiction=d["jurisdiction"],

            if act == "Enhanced_Review":
                enhanced = latest
                packets.append(enhanced)
        elif act == "Compliance_Approve":
            if "standard" not in (d["note"] or "").lower() and packets:

                               ("Standard_Review" not in last or
                                last["Standard_Review"] < packets[0]["key"]))
                for p in packets:
                    # Possible link if packet identity cannot be inferred uniquely.
                    links.append((p, k, True if unambiguous else None))
        elif act == "Sanctions_Screen":
            screens.append((k, d["jurisdiction"]))
        last[act] = k
        prev = d
        if act != "Release_Funds":
            continue

        j, typ, risk = d["jurisdiction"], d["customer_type"], d["risk_level"]
        g1 = and3(None if j is None else j != "DE",
                  None if amt is None else amt >= 100000)
        if enhanced is None:
            e1 = False
        elif material is not None and enhanced["key"] <= material:
            e1 = False
        elif (enhanced["amount"] is None or amt is None or
              (possible_material is not None and enhanced["key"] <= possible_material)):
            e1 = None
        else:
            e1 = True

        high, pep = eq(risk, "HIGH"), eq(typ, "PEP")
        g2 = or3(high, pep)
        pairs = []
        for p, a, link in links:
            def covers(f, value):
                return and3(eq(p[f], value), basis_since[f] <= p["key"])
            pairs.append(and3(link, p["key"] < a < k,
                              implies(high, covers("risk_level", "HIGH")),
                              implies(pep, covers("customer_type", "PEP"))))
        e2 = or3(*pairs)

        g3s, r3_checks, matching_adds = [], [], []
        for u, added_j in adds:
            if u >= k:
                continue
            match = eq(j, added_j)
            if match is True:
                matching_adds.append(u)
            before = or3(*(eq(sj, added_j) for s, sj in screens if s < u))
            after = or3(*(eq(sj, added_j) for s, sj in screens if u < s < k))
            trigger = and3(match, before)
            g3s.append(trigger)
            r3_checks.append(implies(trigger, after))

        out = {C: case_id, "release_at": k[0], "release_index": k[1],
               **{f: d[f] for f in fields},
               **{"unknown_" + f: d[f] is None for f in fields[:4]},
               "r1_trigger": g1, "r1_review_ok": e1,
               "r2_trigger": g2, "r2_pair_ok": e2, "r2_ok": implies(g2, e2),
               "r3_trigger": or3(*g3s), "r3_ok": and3(*r3_checks),
               "last_matching_list_add": max(matching_adds, default=None),
               "last_material": material, "last_possible_material": possible_material,
               "r4_crossings": list(crossings),
               "last_review_amount": latest["amount"] if latest else None,
               "enhanced_amount": enhanced["amount"] if enhanced else None,
               "enhanced_jurisdiction": enhanced["jurisdiction"] if enhanced else None,
               "r4_latest_stale": latest["stale"] if latest else None,
               "r4_baseline_unknown": latest is not None and latest["amount"] is None}
        for name in sorted(review_names | {"Compliance_Approve", "Sanctions_Screen"}):
            out["last_" + name] = last.get(name)
        releases.append(out)

# Register metadata and independent evidence. A certificate creation is not a signing.
reg = pd.DataFrame([
    ("EX-77", "R1", "Head_Compliance", "GB", "CORPORATE", 250000,
     "09:05", "09:00", "18:00", "09:05", True, None, None, None),
    ("EX-88", "R1", "Head_Compliance", "AE", "CORPORATE", 250000,
     "08:50", "08:00", "12:00", None, None, "10:30", "08:45", "requester"),
], columns=["exemption_id", "waives", "authority", "scope_j", "scope_type", "cap",
            "displayed_at", "effective_from", "expiry", "trusted_signature", "hash_valid",
            "cert_created", "oral_claim_at", "witness"])
for col in ["displayed_at", "effective_from", "expiry", "trusted_signature",
            "cert_created", "oral_claim_at"]:
    reg[col] = pd.to_datetime("2026-04-06 " + reg[col], utc=True)
reg = reg.merge(insertions.reset_index(), how="left", on="exemption_id")
joined = pd.DataFrame(releases).merge(reg, how="left", on="exemption_id",
                                     validate="many_to_one")

def waiver(d):
    if d["exemption_id"] is None:
        return False             # given candidate register and case associations
    if d["waives"] is None:
        return None              # referenced grant missing from register
    t, sig = d["release_at"], d["trusted_signature"]
    timing = and3(None if d["effective_from"] is None else d["effective_from"] <= t,
                  None if d["expiry"] is None else t < d["expiry"])
    cap_ok = (None if d["amount"] is None or d["cap"] is None
              else d["amount"] <= d["cap"])
    # A verified timely signature is sufficient. An unverified displayed time,
    # even with a witness claim, leaves historical authorization for adjudication.
    timely_proof = True if sig is not None and sig <= t and d["hash_valid"] else None
    return and3(eq(d["waives"], "R1"), eq(d["authority"], "Head_Compliance"),
                eq(d["jurisdiction"], d["scope_j"]), eq(d["customer_type"], d["scope_type"]),
                cap_ok, timing, timely_proof)

rows = []
for d in records(joined):
    w = waiver(d)
    ordinary = implies(d["r1_trigger"], d["r1_review_ok"])
    r1 = implies(d["r1_trigger"], or3(d["r1_review_ok"], w))
    ok = and3(r1, d["r2_ok"], d["r3_ok"])
    if ok is False:
        verdict = "NONCOMPLIANT"
    elif ok is None:
        verdict = "REVIEW_REQUIRED"
    elif ordinary is not True and w is True:
        verdict = "JUSTIFIED_EXCEPTION"
    else:
        verdict = "COMPLIANT"
    cert, displayed, recorded = d["cert_created"], d["displayed_at"], d["recorded_at"]
    rows.append(dict(d, waiver_ok=w, r1_ok=r1, diagnostic=verdict,
                     recorded_after_release=None if recorded is None else recorded > d["release_at"],
                     cert_after_release=None if cert is None else cert > d["release_at"],
                     display_predates_cert=(None if cert is None or displayed is None
                                            else displayed < cert)))

diagnostics = pd.DataFrame(rows).set_index([C, "release_at", "release_index"]).sort_index()
print(diagnostics[["amount", "r1_trigger", "r1_review_ok", "waiver_ok", "r2_trigger",
                   "r2_pair_ok", "r3_trigger", "r3_ok", "r4_baseline_unknown",
                   "diagnostic"]].to_string())
```

The full `diagnostics` dataframe retains the UTC event keys, review amounts, invalidating changes, unknown-field flags and joined evidence dates behind the printed subset. A false witness flag when its trigger is false is harmless. R4 staleness affects the R1 review route and has no independent release penalty. REVIEW_REQUIRED is the code's referral outcome for the narrative INDETERMINATE findings.

## 6. Why Control-Flow-Only Conformance Is Insufficient

1. **Conditional activation.** The same release sequence can be legal in DE and require an enhanced review in the US at EUR 100,000. Checking for an enhanced review before every release would flag releases for which R1 never activated. TX-307 also shows why LOW alone cannot turn off R2.
2. **Final-state leakage.** Attaching TX-305's eventual 150,000 to all events invents an amount in the review packet. Attaching TX-311's final DE to every event erases the US jurisdiction that the reviewer saw.
3. **Stale review.** “Enhanced before release” succeeds for both TX-306 and TX-309. Their post-review increases are 4.55% and 22.88%, respectively. Determining adequacy requires the baseline and intervening values. TX-308 further requires the direction of change and the inclusive release threshold.
4. **Post-hoc grants.** Both exemption insertions follow release. A pattern requiring insertion before release would reject EX-77 despite the trusted signature. Accepting any eventual grant reference would credit EX-88 despite conflicting evidence. Neither pattern tests the waiver's rule and scope.
5. **Unknown values.** With an unknown amount the same TX-305 prefix admits releases on either side of the threshold. A two-valued filter such as “amount ≥ 100,000” can silently drop this release and report a misleading pass.
6. **Equal timestamps.** Without event_index, TX-311's update can appear before the review and change the apparent packet jurisdiction. Even when the ultimate release label agrees, the resulting audit explanation can be wrong.
7. **External shared state.** TX-304 has a screen before release. The applicable list changed in between. A generic screen-order constraint misses that breach. A generic “any list update requires rescreening” also misapplies an XZ addition to other jurisdictions.
8. **Packet identity.** An approval activity establishes that someone approved something. TX-307's note identifies a standard packet. A trace that checks only “approval before release” cannot certify the linked enhanced review required by R2.

## 7. Recommended Logging and Control Improvements

- Persist an immutable release payload keyed to the release event, with amount, currency, jurisdiction, customer type, risk, sources and versions. Preserve explicit unknowns and distinguish “unchanged,” “cleared” and “unavailable.” Link settlement and any reconciliation adjustment to the original release.
- Give each completed review a packet ID, completion timestamp, reviewer, reviewed attribute values, risk basis and packet hash. Have Compliance_Approve name the packet ID, version, approver authority and decision time. This would settle whether an approval covered a particular enhanced packet.
- Record each change's old and new values, effective time, event time, record time, actor, source and reason. Preserve corrections as new records with links to the corrected fact and its provenance. Retain the evidence receipt time so an auditor can reconstruct both historical truth and what the release gate could know then.
- Capture each exemption as a versioned, signed grant with waived rule IDs, jurisdiction and customer-type scope, amount cap and currency, effective_from, expiry and any revocation. Store authority evidence, verified signature timestamp, certificate validity, hash, record timestamp and the grant version cited by release. Specify whether oral approval is admissible and what evidence it requires.
- Version the sanctions feed, log jurisdiction-specific additions/removals with their effective and ingestion times, and put the jurisdiction and exact list version on each screen. A release gate can then detect that a later applicable addition requires a fresh screen.
- Store the rule version in force at release, the threshold and materiality calculation, the reviewed baseline, the triggering change IDs, the exemption or ordinary witness used, and each rule's pass/fail/unknown decision. Route unresolved decisive facts for adjudication before releasing funds.
- Use durable event IDs and a stable source sequence within a timestamp. Preserve causal links across review, update, approval and release systems, including the list version visible to the transaction system. Log late arrivals and clock corrections so that replay preserves the same decision order.
