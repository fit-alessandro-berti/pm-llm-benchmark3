*   Use BPMN "Sequence Flow" labels to explicitly denote "Wait for Verification" and "Wait for Legal".
*   Document that `archive_change` is the only valid end state.

# 7. Rejection Criteria

A conversion result should be rejected or quarantined if:

1.  **Unsoundness:** `pm4py.check_soundness` returns `False` or indicates a deadlock reachable state.
2.  **Loss of Join:** The round-tripped model allows `release_change` to fire before `verification_loop` or `optional_legal` completes.
3.  **Collapsed Optionality:** The `optional_legal` XOR is converted to a mandatory path or a self-loop that cannot be skipped.
4.  **Loop Flattening:** The `verification_loop` is converted to a linear sequence without the possibility of repetition (e.g., `correct_defect` is missing).
5.  **Final Marking Mismatch:** The round-tripped model does not reach `archive_change` from `im_powl` with exactly 1 token.
6.  **Visual Misrepresentation:** The BPMN visualization explicitly depicts a dependency (e.g., arrow from Risk to Evidence) that contradicts the POWL Partial Order.

# 8. Canonical Representation Recommendation

*   **Authoritative Model:** The **POWL `source_powl`** is the canonical source. It explicitly defines the partial order and operators.
*   **Derivative Artifacts:** The **Accepting Petri Net** and **BPMN** models are derivatives. They should be regenerated from the POWL whenever the source changes.
*   **Validation Evidence:** Each derivative must be accompanied by the output of `pm4py.check_soundness` and the result of the bounded trace exploration (Section 5).
*   **Process-Tree Intermediate:** The process-tree intermediate should **not** be allowed as a canonical storage format because `convert_to_process_tree` failed for complex loops in this model. It is only useful for visualization if it succeeds, but it is not authoritative.
*   **Avoiding Drift:** Future edits must be made to the POWL source. BPMN should be locked after generation to prevent manual edits that introduce semantic drift. If BPMN must be edited, it must be converted back to POWL and validated against the source semantics before re-exporting.

# 9. Residual Uncertainty

The following claims cannot be established even if every test passes:

1.  **Semantic Equivalence of Silent Transitions:** `pm4py.convert_to_bpmn` may map a silent transition to a visible task with no logic attached. The verification that the "skip" behavior is preserved in the BPMN logic is heuristic, not structural.
2.  **Human Interpretation of BPMN:** A BPMN viewer might interpret a parallel gateway as "synchronous" rather than "concurrent," leading to a misunderstanding of the `assess_risk`/`prepare_evidence` ordering, regardless of the underlying net.
3.  **Timeout/Duration Constraints:** The source POWL model does not specify time constraints. The Petri net and BPMN may imply default durations or lack them. Validation cannot confirm if specific timing requirements (SLAs) are preserved.
