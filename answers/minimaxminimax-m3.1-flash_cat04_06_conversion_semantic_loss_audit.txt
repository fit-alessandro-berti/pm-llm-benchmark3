```python
def powl_signature(powl):
    """Canonical, order-insensitive signature of a POWL model (for drift detection)."""
    import json, hashlib
    def node_repr(n):
        if isinstance(n, Transition):
            return {"kind": "transition", "label": n.label}
        if isinstance(n, OperatorPOWL):
            return {"kind": n.operator, "children": sorted([node_repr(c) for c in n.children], key=json.dumps)}
        if isinstance(n, StrictPartialOrder):
            edges = sorted([f"{node_repr(a)}->{node_repr(b)}" for (a,b) in n.order.edges])
            return {"kind": "spo", "nodes": sorted([node_repr(x) for x in n.nodes], key=json.dumps), "edges": edges}
        return {"kind": type(n).__name__, "repr": str(n)}
    payload = json.dumps(node_repr(powl), sort_keys=True)
    return hashlib.sha256(payload.encode()).hexdigest()[:16], payload
```

# 1. Source-Semantics Baseline

The POWL object in the task is the **authoritative** artifact. Everything below (pipelines, audit, validation code) is derived from it and is subordinate to it. No direct `POWL  BPMN` API is used anywhere in this document, because the PM4Py interface listed in the brief exposes only `POWL  (net, im, fm)` and `{(net, im, fm) | tree}  BPMN`.

The POWL source states the following structural facts (read directly off the graph):

* `Register Change` is the unique predecessor of `Assess Risk` and `Prepare Evidence`; those two successors are **unordered** with respect to each other (no edge between them).
* `Assess Risk  optional_legal`; `Assess Risk  verification_loop`; `Prepare Evidence  verification_loop`. So the verification loop has a **two-input join** on `Assess Risk` *and* `Prepare Evidence`.
* `optional_legal  release_change` and `verification_loop  release_change`: a **second join** before `Release Change`.
* There is **no edge** between `optional_legal` and `verification_loop`, i.e. legal review and verification are unordered at the model level.
* `optional_legal` is `XOR[Legal Review, ]`: one visible activity, one silent skip.
* `verification_loop` is `LOOP[trial_body, Correct Defect]` with `trial_body = StrictPartialOrder[Configure Trial  Inspect Trial]`: a **binary loop**, body executed at least once, redo part executed only when another iteration follows.

Two framing remarks, because they drive most of the downstream risk analysis:

1. **"Concurrence" is not the same as "arbitrary interleaving".** The POWL states a *partial order*, not a set of sequence choices. A converter that turns `Assess Risk`/`Prepare Evidence` into an XOR of two sequences produces a net whose trace set (as a set of linear traces) is indistinguishable from a parallel split — but whose *states* differ: in the true AND-split, both activities are simultaneously enabled (one token each), which is exactly what a resource-aware or "how long is this pending" analysis would see. Conversely, a converter that turns the partial order into a fixed sequence matches the eighteen-month-old workflow shape but destroys I-03. This is why §5 uses a **marking-level** co-enablement probe in addition to trace enumeration.
2. **A converted net that is sound and workflow-shaped can still be semantically wrong.** `check_soundness` only asks "can every reachable marking reach `fm`?". It says nothing about optional branches, loop bounds, or join ordering. The table above therefore never uses "sound" as evidence for anything except I-13.

| **D** Analysis-only pipeline (no BPMN) | `pm4py.convert_to_reachability_graph(net, im, fm)`, `pm4py.discover_footprints(net, im, fm)`, custom bounded exploration with `pm4py.get_enabled_transitions` | Supplies the *evidence* for I-03, I-07, I-11 (cycle  unboundedness) and for the I-05/I-09 witness traces, without any second serialisation step that could add loss. | Reachability-graph blow-up; footprints collapse occurrence counts, so a bounded loop and an unbounded loop can be footprint-identical. | reachability construction exceeds the state budget (explicitly reported, never silently truncated). |
| **E** Curated (hand-authored) BPMN from the invariant table | none (authored), then pipeline **C** to re-derive a net and check it against the source net | The only route that can express *modelling intent* explicitly (e.g. a named `: legal skipped` task, an explicit "no order" annotation, a `Correct Defect` rework loop as a boundary event + compensation-like path) without inheriting a converter's blind spots. | Human error; drifts from the POWL unless checked by pipeline C + §5 probes; annotations are not semantics. | the re-derived net differs from `net_from_powl` on any I-01…I-14 probe  the curated BPMN, not the POWL, is wrong and must be corrected (or the POWL changed deliberately). |

**Primary pipeline: A**, with **C** as its mandatory validation step and **D** as the evidence generator. **B** is run and reported but its failure is *expected and informative*, not a defect of the source model: the source is deliberately **not** block-structured (three independent reasons: the AND-split/AND-join on `Assess Risk`/`Prepare Evidence`, the unordered legal-vs-verification pair, and the optional XOR branch that has to merge back into a join). A classic process tree cannot express "both may be pending at once", so any tree that the converter produces has already lost information *before* it becomes BPMN.

# 3. Conversion Code

The block below is one runnable module. §5 continues in the same namespace (or `import pipeline_core` if the two blocks are stored separately). Nothing here assumes a conversion succeeded, and **no marking is dereferenced before it has been checked for `None`**.

```python
# -*- coding: utf-8 -*-
"""
pipeline_core.py
  A: POWL -> accepting Petri net -> BPMN                (primary)
  B: POWL -> accepting Petri net -> process tree -> BPMN (may legitimately fail)
  C: BPMN -> accepting Petri net round trips
  D: analysis (reachability graph, footprints)
Every failure is *recorded*, never swallowed.
"""
import hashlib
import json
import os
import traceback

import pm4py
from pm4py.objects.process_tree.obj import Operator
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition,
)

PM4PY_VERSION = getattr(pm4py, "__version__", "unknown")
OUT_DIR = "conversion_out"
os.makedirs(OUT_DIR, exist_ok=True)

REPORT = {"pm4py_version": PM4PY_VERSION, "pipelines": {}, "nets": {}, "warnings": []}


# ------------------------------------------------------------------
# 3.1  SOURCE OF TRUTH -- verbatim from the change-request model
# ------------------------------------------------------------------
register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(operator=Operator.XOR, children=[legal_review, skip_legal])

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(operator=Operator.LOOP, children=[trial_body, correct_defect])

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[register, assess_risk, prepare_evidence, optional_legal,
           verification_loop, release_change, archive_change]
)
source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)


def powl_signature(powl):
    """Canonical, order-insensitive signature of the POWL model.
    Used in section 8 to detect drift between source and regenerated artefacts."""
    def node_repr(n):
        if isinstance(n, OperatorPOWL):
            kids = sorted((node_repr(c) for c in n.children), key=json.dumps)
            return {"kind": "op:" + str(n.operator), "children": kids}
        if isinstance(n, StrictPartialOrder):
            edges = sorted("%s -> %s" % (node_repr(a), node_repr(b))
                           for (a, b) in n.order.edges)
            nodes = sorted((node_repr(x) for x in n.nodes), key=json.dumps)
            return {"kind": "spo", "nodes": nodes, "edges": edges}
        return {"kind": "act", "label": getattr(n, "label", None)}
    payload = json.dumps(node_repr(powl), sort_keys=True)
    return hashlib.sha256(payload.encode("utf-8")).hexdigest()[:16], payload


SOURCE_SIG, SOURCE_PAYLOAD = powl_signature(source_powl)
REPORT["source_signature"] = SOURCE_SIG
REPORT["source_payload"] = SOURCE_PAYLOAD


# ------------------------------------------------------------------
# 3.2  small, defensive helpers
# ------------------------------------------------------------------
def _fn(name):
    """Fetch a pm4py entry point, or None (never raises AttributeError later)."""
    return getattr(pm4py, name, None)


def try_call(fn, variants):
    """Try each call signature in `variants` (tuples of positional args).
    Returns (ok, value, error). A TypeError is treated as 'wrong signature';
    any other exception is a genuine conversion failure and is reported."""
    if fn is None:
        return False, None, "pm4py entry point unavailable"
    last = None
    for args in variants:
        try:
            return True, fn(*args), None
        except TypeError as exc:
            last = exc
            continue
        except Exception as exc:
            return False, None, "%s: %s" % (type(exc).__name__, exc)
    return False, None, "no viable signature (last TypeError: %s)" % last


def normalise_net_triple(value):
    """(net, im, fm) with explicit None-reporting. Never assumes markings exist."""
    if not isinstance(value, (tuple, list)) or len(value) != 3:
        return None, None, None, "unexpected return shape: %r" % type(value)
    net, im, fm = value
    missing = [n for n, v in (("net", net), ("im", im), ("fm", fm)) if v is None]
    if missing:
        return net, im, fm, "missing artefact(s): %s" % ",".join(missing)
    return net, im, fm, None


def visible_labels(net):
    return sorted({t.label for t in net.transitions if getattr(t, "label", None) is not None})


def label_multiplicity(net):
    out = {}
    for t in net.transitions:
        lab = getattr(t, "label", None)
        if lab is not None:
            out[lab] = out.get(lab, 0) + 1
    return out


def tau_count(net):
    return sum(1 for t in net.transitions if getattr(t, "label", None) is None)


def structural_signature(net):
    """Representation-independent fingerprint used to compare nets across a round trip."""
    return {
        "visible_label_set": visible_labels(net),
        "visible_label_multiplicity": label_multiplicity(net),
        "tau_transitions": tau_count(net),
        "n_places": len(net.places),
        "n_transitions": len(net.transitions),
        "n_arcs": len(net.arcs),
    }


# ------------------------------------------------------------------
# 3.3  PIPELINE A -- POWL -> accepting Petri net            (mandatory)
# ------------------------------------------------------------------
net_from_powl = im_from_powl = fm_from_powl = None

ok, value, err = try_call(_fn("convert_to_petri_net"), [(source_powl,)])
if ok:
    net_from_powl, im_from_powl, fm_from_powl, problem = normalise_net_triple(value)
    REPORT["pipelines"]["A_powl_to_net"] = {
        "status": "ok" if problem is None else "partial",
        "problem": problem,
    }
else:
    REPORT["pipelines"]["A_powl_to_net"] = {"status": "conversion failed", "error": err}
    REPORT["warnings"].append("Pipeline A aborted at POWL->net: %s" % err)

if net_from_powl is not None:
    REPORT["nets"]["net_from_powl"] = structural_signature(net_from_powl)


# ------------------------------------------------------------------
# 3.4  PIPELINE A -- accepting Petri net -> BPMN
# ------------------------------------------------------------------
def to_bpmn(net, im, fm):
    ok, value, err = try_call(_fn("convert_to_bpmn"),
                              [((net, im, fm),), (net, im, fm), (net,)])
    if not ok:
        return None, err
    # Normalise: some builds return a tuple whose first element is the graph.
    if isinstance(value, (tuple, list)) and value:
        first = value[0]
        if hasattr(first, "get_flow_nodes") or hasattr(first, "get_elements_by_type"):
            value = first
    if value is None:
        return None, "converter returned None"
    return value, None


bpmn_from_net = None
if net_from_powl is not None and im_from_powl is not None and fm_from_powl is not None:
    bpmn_from_net, err = to_bpmn(net_from_powl, im_from_powl, fm_from_powl)
    REPORT["pipelines"]["A_net_to_bpmn"] = (
        {"status": "ok"} if bpmn_from_net is not None
        else {"status": "conversion failed", "error": err})
else:
    REPORT["pipelines"]["A_net_to_bpmn"] = {"status": "not attempted",
                                            "reason": "missing net/im/fm from pipeline A"}


# ------------------------------------------------------------------
# 3.5  PIPELINE B -- net -> process tree -> BPMN   (may legitimately fail)
# ------------------------------------------------------------------
tree_from_net = None
bpmn_from_tree = None

ok, value, err = try_call(_fn("convert_to_process_tree"),
                          [(net_from_powl, im_from_powl, fm_from_powl),
                           (net_from_powl,), (net_from_powl, im_from_powl)])
if ok and value is not None:
    tree_from_net = value
    REPORT["pipelines"]["B_net_to_tree"] = {"status": "ok",
                                            "tree_repr": repr(tree_from_net)[:2000]}
    bpmn_from_tree, err2 = to_bpmn(tree_from_net, None, None)
    REPORT["pipelines"]["B_tree_to_bpmn"] = (
        {"status": "ok"} if bpmn_from_tree is not None
        else {"status": "conversion failed", "error": err2})
else:
    # The EXPECTED outcome for a partially-ordered source: the net is not
    # block-structured (AND-split/AND-join + unordered optional branch).
    REPORT["pipelines"]["B_net_to_tree"] = {
        "status": "conversion failed",
        "error": err,
        "interpretation": ("Expected for a non-block-structured source. A tree would have to "
                           "linearise the Assess/Prepare concurrency or invent an OR-branch; "
                           "any tree produced here must be treated as 'approximated' and must "
                           "NOT be used as the parent of a published BPMN artefact."),
    }
    REPORT["pipelines"]["B_tree_to_bpmn"] = {"status": "not attempted",
                                              "reason": "no usable process tree"}

# Also probe (and record) whether this PM4Py build even exposes POWL -> tree.
ok_powl_tree, val_powl_tree, err_powl_tree = try_call(
    _fn("convert_to_process_tree"), [(source_powl,)])
REPORT["pipelines"]["B_direct_powl_to_tree"] = (
    {"status": "ok"} if ok_powl_tree else
    {"status": "unsupported", "error": err_powl_tree,
     "note": "the documented interface does not guarantee POWL->tree; no direct "
             "POWL->BPMN API is assumed anywhere in this document."})


# ------------------------------------------------------------------
# 3.6  PIPELINE C -- BPMN -> accepting Petri net round trips
# ------------------------------------------------------------------
ROUNDTRIPS = {}   # tag -> {"net":..., "im":..., "fm":..., "status":...}

for tag, bpmn_obj in (("A_net2bpmn", bpmn_from_net), ("B_tree2bpmn", bpmn_from_tree)):
    entry = {"status": "not attempted"}
    if bpmn_obj is None:
        entry["reason"] = "no BPMN model produced by the corresponding pipeline"
    else:
        ok, value, err = try_call(_fn("convert_to_petri_net"), [(bpmn_obj,)])
        if ok:
            net, im, fm, problem = normalise_net_triple(value)
            entry = {"status": "ok" if problem is None else "partial",
                     "problem": problem, "net": net, "im": im, "fm": fm}
            if net is not None:
                REPORT["nets"]["net_rt_" + tag] = structural_signature(net)
        else:
            entry = {"status": "conversion failed", "error": err}
    ROUNDTRIPS[tag] = entry
    REPORT["pipelines"]["C_roundtrip_" + tag] = {
        k: v for k, v in entry.items() if k not in ("net", "im", "fm")}


# ------------------------------------------------------------------
# 3.7  diagnostics on every accepting net
# ------------------------------------------------------------------
def diagnose(tag, net, im, fm):
    d = {"tag": tag}
    if net is None:
        d["status"] = "no net"
        return d
    try:
        d["workflow_net"] = bool(pm4py.check_is_workflow_net(net))
    except Exception as exc:
        d["workflow_net"] = "error: %s: %s" % (type(exc).__name__, exc)
    if im is None or fm is None:
        d["sound"] = "not tested (missing initial/final marking)"
        d["status"] = "partial"
    else:
        try:
            d["sound"] = bool(pm4py.check_soundness(net, im, fm, print_diagnostics=True))
        except Exception as exc:
            d["sound"] = "error: %s: %s" % (type(exc).__name__, exc)
        d["status"] = "ok" if d.get("sound") is True else "not sound"
    d.update(structural_signature(net))
    return d


ACCEPTING_NETS = {}
if net_from_powl is not None:
    ACCEPTING_NETS["net_from_powl"] = (net_from_powl, im_from_powl, fm_from_powl)
for tag, entry in ROUNDTRIPS.items():
    if entry.get("net") is not None:
        ACCEPTING_NETS["net_rt_" + tag] = (entry["net"], entry["im"], entry["fm"])

REPORT["diagnostics"] = [diagnose(t, n, i, f) for t, (n, i, f) in ACCEPTING_NETS.items()]


# ------------------------------------------------------------------
# 3.8  analysis pipeline D -- footprints & reachability graph
# ------------------------------------------------------------------
def footprints_of(net, im, fm):
    if net is None or im is None or fm is None:
        return None, "missing markings"
    try:
        fps = pm4py.discover_footprints(net, im, fm)
    except Exception as exc:
        return None, "%s: %s" % (type(exc).__name__, exc)
    out = {}
    for item in fps:
        act, fpset = item[0], item[1]
        name = getattr(act, "label", act)
        out.setdefault(name, set()).update(tuple(f) for f in fpset)
    return {k: sorted(v) for k, v in out.items()}, None


def reachability_summary(net, im, fm):
    """Defensive: the return shape of convert_to_reachability_graph varies."""
    if net is None or im is None or fm is None:
        return {"status": "not tested", "reason": "missing markings"}
    try:
        out = pm4py.convert_to_reachability_graph(net, im, fm)
    except Exception as exc:
        return {"status": "conversion failed", "error": "%s: %s" % (type(exc).__name__, exc)}
    summary = {"status": "ok", "raw_type": str(type(out))}
    cands = out if isinstance(out, (tuple, list)) else [out]
    for cand in cands:
        if cand is None:
            continue
        states = getattr(cand, "states", None)
        if states is not None:
            summary["n_states"] = len(states)
            arcs = getattr(cand, "transitions", None)
            summary["n_arcs"] = len(arcs) if arcs is not None else None
            # a cycle through the loop body is the evidence for I-11 (unboundedness)
            summary["has_cycle"] = bool(arcs) and summary.get("n_arcs", 0) > summary.get("n_states", 0)
            break
        if isinstance(cand, dict):
            summary["n_states"] = len(cand)
            break
    return summary


REPORT["analysis"] = {}
for tag, (n, i, f) in ACCEPTING_NETS.items():
    fp, err = footprints_of(n, i, f)
    REPORT["analysis"][tag] = {
        "footprints": fp, "footprints_error": err,
        "reachability": reachability_summary(n, i, f),
    }


# ------------------------------------------------------------------
# 3.9  visualisations (never fatal) + artefacts on disk
# ------------------------------------------------------------------
def safe_save(fn_name, *args):
    fn = _fn(fn_name)
    if fn is None:
        return "pm4py.%s unavailable" % fn_name
    try:
        fn(*args)
        return "ok"
    except Exception as exc:
        return "failed: %s: %s" % (type(exc).__name__, exc)


SAVES = {}
SAVES["01_source_powl.png"] = safe_save("save_vis_powl", source_powl,
                                        os.path.join(OUT_DIR, "01_source_powl.png"))
if net_from_powl is not None and im_from_powl is not None and fm_from_powl is not None:
    SAVES["02_net_from_powl.png"] = safe_save(
        "save_vis_petri_net", net_from_powl, im_from_powl, fm_from_powl,
        os.path.join(OUT_DIR, "02_net_from_powl.png"))
if bpmn_from_net is not None:
    SAVES["03_pipelineA_bpmn.png"] = safe_save(
        "save_vis_bpmn", bpmn_from_net, os.path.join(OUT_DIR, "03_pipelineA_net_to_bpmn.png"))
if tree_from_net is not None:
    SAVES["04_pipelineB_tree.png"] = safe_save(
        "save_vis_process_tree", tree_from_net,
        os.path.join(OUT_DIR, "04_pipelineB_process_tree.png"))
if bpmn_from_tree is not None:
    SAVES["05_pipelineB_bpmn.png"] = safe_save(
        "save_vis_bpmn", bpmn_from_tree, os.path.join(OUT_DIR, "05_pipelineB_tree_to_bpmn.png"))
if ROUNDTRIPS.get("A_net2bpmn", {}).get("net") is not None:
    e = ROUNDTRIPS["A_net2bpmn"]
    SAVES["06_roundtripA_net.png"] = safe_save(
        "save_vis_petri_net", e["net"], e["im"], e["fm"],
        os.path.join(OUT_DIR, "06_roundtripA_bpmn_to_net.png"))
REPORT["visualisations"] = SAVES

# The nets themselves are re-derivable from source_powl + pinned pm4py version;
# only the evidence report is stored as a first-class artefact.
with open(os.path.join(OUT_DIR, "conversion_report.json"), "w") as fh:
    json.dump(REPORT, fh, indent=2, default=str)
print(json.dumps({k: v for k, v in REPORT.items() if k != "source_payload"},
                 indent=2, default=str))
```

Notes on the code above:

* `try_call` distinguishes a **signature mismatch** (`TypeError`) from a **real conversion failure** (any other exception). Both are recorded; neither is suppressed with a bare `except: pass`.
* `normalise_net_triple` exists because `convert_to_petri_net` on a BPMN that has lost its start/end events can legitimately return `im=None`/`fm=None`. The follow-up code then reports `not tested (missing initial/final marking)` instead of crashing.
* `to_bpmn` is signature-tolerant because the brief shows `convert_to_bpmn(net, im, fm)` while some builds expose `convert_to_bpmn(obj)` taking a `(net, im, fm)` tuple; all three call shapes are attempted and the failure is reported.
* `structural_signature` deliberately captures **label multiplicity**, because a loop body that is unfolded into the net produces two distinct transitions with the same visible label — a defect a label *set* comparison would hide (I-14).

# 4. Preservation and Loss Audit

The cells below are **pre-test expectations**. §3.8/§5 produce `validation_report.json`, which must upgrade (`expected preserved  validated preserved`) or downgrade (` lost` / `conversion failed`) these cells. A disagreement between this table and the generated report is itself a quarantine trigger (§7, R-11).

| Source invariant | POWLPetri | PetriBPMN | PetriTree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| I-01 Entry discipline (`Register Change` only at `im`) | `expected preserved` | `expected preserved` | `conversion failed` | `ambiguous` | Probe C3: `enabled(im)` visible set = `{Register Change}` on source and on the re-imported net. BPMN risk: a re-import may synthesise extra start activities or a second start event. |
| I-02 Precedence `Register  Assess/Prepare` | `expected preserved` | `expected preserved` | `conversion failed` | `ambiguous` | Trace check: no completed trace of either net may contain `Register Change` after another activity. Structural check on the BPMN: the start event must have exactly one visible outgoing flow. |
| I-03 True concurrency of `Assess  Prepare` | `approximated` | `ambiguous` | `conversion failed` | `ambiguous` | **Highest-risk cell.** PM4Py’s POWLnet route for a `StrictPartialOrder` is version-dependent; a process-tree-based route resolves an AND-split by *choosing* one order, which keeps both orders of the *trace* but destroys simultaneity. Probe C1 (co-enablement of both labels) decides. Confirmed by the classic nettree converter’s own inability to represent parallelism  consistent with the claim that the tree route *cannot* preserve I-03. |

Over-constraint is a semantic loss even though every trace it admits is also a source trace. |

The probe detects which convention was used; the *intended* semantics are given by §1 I-09, so a mismatch = `lost`, not merely `ambiguous`. |
| I-10 Minimum one iteration | `expected preserved` | `expected preserved` | `expected preserved` | `ambiguous` | Probe L1: every completed trace contains `Configure Trial` and `Inspect Trial`. Note: this invariant is *not* implied by soundness. |
| I-11 Iteration count unbounded | `expected preserved` | `ambiguous` | `expected preserved` | `ambiguous` | Probe L2 ( 2 iterations reachable) plus a cycle in the reachability graph. Bounded enumeration can never *prove* unboundedness  residual risk even when all tests pass (§9). |
| I-12 Join before `Release Change` | `expected preserved` | `expected preserved` | `conversion failed` | `ambiguous` | Probe R-JOIN: no completed trace contains `Release Change` before `Inspect Trial`; **and** no completed trace contains `Release Change` before `Prepare Evidence`. A BPMN re-import that merges the two joins into one, or that lets the legal branch float past the release, breaks this. |
| I-13 Finality (`Archive Change` last, exact `fm`, deadlock at `fm`) | `expected preserved` | `expected preserved` | `conversion failed` | `ambiguous` | Exact final-marking equality (see §5) + `enabled(fm) == ` on both nets. BPMN risk: a re-imported model whose end event is missing gives `fm = None`  the check degrades to `not tested`, which must be treated as a failure for publication (§7 R-6). |
| I-14 Activity set / no phantoms, no duplicates | `expected preserved` | `ambiguous` | `conversion failed` | `ambiguous` | Structural signature comparison (label **multiplicity**). Duplicate `Configure Trial`/`Inspect Trial` tasks appear if the loop body is unfolded; a visible task with an empty or placeholder name appears if a  is exported as a task. Both are label-level defects invisible to trace-set comparison if the duplicate is never exercised. |
| Gateway / routing-node structure in the BPMN artefact | `not tested` | `ambiguous` | `not tested` | `ambiguous` | PM4Py’s netBPMN emits gateway nodes whose *kind* (parallel vs exclusive) must be read from the model, not from the picture. §6. Rendered gateway count is not a semantics check; only the re-imported net is. |

### Required discussion points, explicitly

* **True concurrency vs. arbitrary interleaving.** The trace-level evidence for I-03 (both orders occur) is satisfied both by an AND-split and by an XOR-of-sequences. The difference is visible only in the *state space*: with the AND-split there is a marking where `Assess Risk` and `Prepare Evidence` are simultaneously enabled. Only probe C1 distinguishes them. This is precisely why I-03 is `approximated` and not `expected preserved` — the converter may well have produced an interleaving-only model.
* **The lack of an edge between optional legal review and verification.** The POWL states *no constraint*. A conversion that introduces one (say, legal review must finish before verification starts) is **not** a harmless simplification: it removes the trace family `...,Configure Trial, Legal Review, Inspect Trial,...`. The audit therefore treats it as a removable-but-real behaviour class, and the trace-set comparison (`prefix_extra`/`prefix_missing`) is exactly the instrument that exposes it. Note the asymmetry: a *missing* constraint (converter allows something the source forbids) is worse than an *added* constraint, because it introduces behaviours that were never authorised — e.g. release before verification.
* **Silent optional behaviour.**  is the carrier of “this may not happen” and of “this is not a business event”. After tau-hiding, optionality is observable only as the *absence* of a label, and the XOR’s “exactly one branch” property is largely unobservable. Any BPMN rendering that materialises the  as a visible, named task changes the business meaning (“Legal Review skipped” becomes an auditable activity). The validator therefore compares  **counts** and the *set of completed traces without* `Legal Review`; it does not claim to verify the branch identity.
* **Binary-loop semantics.** `LOOP[trial_body, Correct Defect]` has exactly two children: the body and the redo part, with the “repeat?” decision carried by an *unlabelled* choice. That is a **binary do-while with rework**, i.e. it says “after inspecting, you may correct and re-test”, but it says nothing about *how often* and nothing about *why*. It is also the part of the model most likely to be re-interpreted by a converter that renders a loop as “body  redo  body” without a visible exit. The audit therefore tests I-09 (redo placement), I-10 (minimum count), I-11 (unboundedness) separately, and refuses to accept “the diagram shows a loop” as evidence for any of them.
* **The join before `Release Change`.** This is a two-input join (`optional_legal`, `verification_loop`) *plus* the transitive requirement that `Prepare Evidence` is done. BPMN will show it as a gateway, but the *kind* of gateway is the risk: an inclusive gateway in the BPMN, re-imported by a tool that normalises gateways, can become an exclusive one, silently dropping the “both must be satisfied” property. The re-imported net is the only acceptable evidence (probe R-JOIN).
* **Activity-label uniqueness.** The nine source labels are unique, but *the net is not*: PM4Py’s loop handling can place two instances of the body (`Configure Trial`, `Inspect Trial`) in the net for the first iteration and the repeat iteration. After BPMN round trip this becomes two tasks with identical names, which (a) breaks any label-keyed analytics, (b) makes `discover_footprints` ambiguous, and (c) is a classic source of “why does the log show two Configure Trial activities?” support tickets. The comparison must therefore use label **multiplicity**, not label sets.
* **Initial and final markings.** The POWLnet conversion picks `im` (one token in the source place) and `fm` (one token in the sink place). BPMN must carry a start and an end event for those to be recoverable on re-import. If the BPMN is re-authored by a vendor tool that replaces the start event with a *message* start event, or drops the end event, `convert_to_petri_net` returns `im`/`fm` that differ from the source’s, or `None`. The round trip is then **not** an accepting Petri net any more and `check_soundness` cannot even be attempted — which is why §3 guards every marking access and §7 R-6 makes “marking missing” a rejection, not a warning.
* **Gateway / routing-node ambiguity in the BPMN visualisation.** PM4Py’s netBPMN emits routing nodes for XOR/AND structure, and the *number and kind* of gateways it emits depends on how it chose to encode the net (e.g. an AND-split plus AND-join vs. a duplicated parallel gateway pair). Therefore the *gateway count* is not a semantics check. The semantics live in the net, and the only legitimate check on the BPMN is to re-import it and re-run the probe suite.

# 5. Round-Trip Validation Code

`net_from_powl` is the reference. Each round-tripped net (`net_rt_A_net2bpmn`, and `net_rt_B_tree2bpmn` if that pipeline produced anything) is compared against it with: witness traces (positive and negative), a bounded visible-trace enumeration, footprint comparison, reachability-graph summary, structural (label-multiplicity) comparison, and trace replay.

**Exhaustiveness statement.** The enumeration below is **exhaustive *within the stated bound***: for a bounded visible length `L`, a bounded number of transition firings per path `S`, and a bounded number of consecutive silent firings `T`, it enumerates *every* visible trace of length  `L` that can be produced with  `T` consecutive -firings between two visible events. It is **not** exhaustive over the infinite trace sets (the loop is unbounded), it does not explore past `S` firings, and it does not distinguish histories that reach the same marking with the same visible prefix but a different internal  history — the latter is irrelevant for visible traces but is exactly what -counting probes must not rely on.

```python
# ==================================================================
# SECTION 5 -- ROUND-TRIP VALIDATION (continues in the same namespace)
# ==================================================================

MAX_VISIBLE = 12      # visible events per trace (covers 2 redo iterations + legal)
MAX_STEPS   = 90      # total transition firings along one path
MAX_TAU_RUN = 30      # consecutive silent firings between two visible events


# ------------------------------------------------------------------
# 5.1 markings that are safe to hand to pm4py
# ------------------------------------------------------------------
def make_marking(net, mapping=None):
    """A pm4py Marking in which every place of the net is present (0 if absent),
    so that marking[place] never raises for an empty place."""
    m = pm4py.PetriNet.Marking()
    for place in net.places:
        m[place] = 0
    for place, tokens in (mapping or {}).items():
        m[place] = tokens
    return m


def marking_key(marking):
    """Comparable key. Places with zero tokens are omitted: the exploration
    reifies all places, whereas pm4py markings are sparse. Any SURPLUS token
    still breaks equality, so this keeps the 'exact final marking' semantics."""
    if marking is None:
        return None
    items = []
    for place, tokens in marking.items():
        if int(tokens) > 0:
            items.append((getattr(place, "name", str(place)), int(tokens)))
    return tuple(sorted(items))


def fire(marking, trans):
    out = pm4py.PetriNet.Marking()
    for place, tokens in marking.items():
        out[place] = tokens
    for place in trans.input:
        out[place] = out[place] - 1
    for place in trans.output:
        out[place] = out[place] + 1
    return out


def enabled_transitions(net, marking):
    fn = _fn("get_enabled_transitions")
    if fn is None:
        from pm4py.objects.petri.utils import get_enabled_transitions as fn  # fallback
    return fn(net, marking)


# ------------------------------------------------------------------
# 5.2 bounded visible-trace exploration
# ------------------------------------------------------------------
def explore_visible_traces(net, im, fm,
                            max_visible=MAX_VISIBLE,
                            max_steps=MAX_STEPS,
                            max_tau_run=MAX_TAU_RUN):
    """Enumerate visible traces. Transitions with label None are EXECUTED but
    not recorded (tau hiding). A trace counts as completed only if the marking
    reached equals the final marking EXACTLY."""
    empty = {"completed": set(), "prefixes": set(), "states": 0,
             "truncated": set(), "tau_firings": 0, "max_depth_reached": 0}
    if net is None or im is None or fm is None:
        empty["truncated"].add("missing net/im/fm")
        return empty

    target = marking_key(fm)
    start_marking = make_marking(net, im)
    stack = [(start_marking, (), 0, 0)]
    seen = {(marking_key(start_marking), (), 0)}
    completed, prefixes = set(), set()
    truncated, tau_firings = set(), 0

    while stack:
        marking, prefix, tau_run, steps = stack.pop()
        prefixes.add(prefix)
        empty["max_depth_reached"] = max(empty["max_depth_reached"], len(prefix))
        if marking_key(marking) == target:
            completed.add(prefix)          # exact final-marking equality
        if len(prefix) >= max_visible:
            truncated.add("visible-length bound")
            continue
        if steps >= max_steps:
            truncated.add("step bound")
            continue
        try:
            enabled = enabled_transitions(net, marking)
        except Exception as exc:
            truncated.add("get_enabled_transitions failed: %s" % exc)
            continue
        for trans in enabled:
            try:
                nxt = fire(marking, trans)
            except Exception:
                continue
            label = getattr(trans, "label", None)
            if label is None:                       # silent: hidden from the trace
                new_tau = tau_run + 1
                tau_firings += 1
                if new_tau > max_tau_run:
                    truncated.add("silent-run bound")
                    continue
                new_prefix = prefix
            else:
                new_prefix = prefix + (label,)
                new_tau = 0
            key = (marking_key(nxt), new_prefix, new_tau)
            if key in seen:
                continue                          # same state + same visible history
            seen.add(key)
            stack.append((nxt, new_prefix, new_tau, steps + 1))

    return {"completed": completed, "prefixes": prefixes, "states": len(seen),
            "truncated": truncated, "tau_firings": tau_firings,
            "max_depth_reached": empty["max_depth_reached"]}


# ------------------------------------------------------------------
# 5.3 marking-level probes (concurrency, entry discipline)
# ------------------------------------------------------------------
def snapshot_enabled_sets(net, im, max_states=4000):
    """Breadth-first exploration of the MARKING graph (labels ignored).
    Returns a map: frozenset(enabled visible labels) -> an example marking,
    plus the set of markings visited."""
    fn = _fn("get_enabled_transitions")
    if fn is None:
        from pm4py.objects.petri.utils import get_enabled_transitions as fn
    start = make_marking(net, im)
    seen = {marking_key(start): start}
    queue = [start]
    snapshots = {}
    while queue and len(seen) < max_states:
        marking = queue.pop(0)
        try:
            enabled = fn(net, marking)
        except Exception:
            continue
        labs = frozenset(getattr(t, "label", None) for t in enabled
                         if getattr(t, "label", None) is not None)
        snapshots.setdefault(labs, marking)
        for trans in enabled:
            try:
                nxt = fire(marking, trans)
            except Exception:
                continue
            k = marking_key(nxt)
            if k not in seen:
                seen[k] = nxt
                queue.append(nxt)
    return snapshots, seen, len(seen) >= max_states


def co_enabled(snapshots, a, b):
    """True iff some marking enables BOTH a and b simultaneously."""
    for labs in snapshots:
        if a in labs and b in labs:
            return True
    return False


# ------------------------------------------------------------------
# 5.4 witnesses
# ------------------------------------------------------------------
POSITIVE_WITNESSES = {
    "W1_minimal_without_legal":
        ("Register Change", "Assess Risk", "Prepare Evidence",
         "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"),
    "W2_legal_before_verification":
        ("Register Change", "Assess Risk", "Legal Review", "Prepare Evidence",
         "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"),
    "W3_legal_interleaved_with_verification":
        ("Register Change", "Prepare Evidence", "Assess Risk", "Configure Trial",
         "Legal Review", "Inspect Trial", "Release Change", "Archive Change"),
    "W4_one_redo_iteration":
        ("Register Change", "Assess Risk", "Prepare Evidence",
         "Configure Trial", "Inspect Trial", "Correct Defect",
         "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"),
}

NEGATIVE_WITNESSES = {
    "N1_release_before_verification":
        ("Register Change", "Assess Risk", "Prepare Evidence",
         "Release Change", "Archive Change"),
    "N2_release_before_prepare_evidence":
        ("Register Change", "Assess Risk", "Release Change", "Archive Change"),
    "N3_trailing_redo_without_new_iteration":
        ("Register Change", "Assess Risk", "Prepare Evidence",
         "Configure Trial", "Inspect Trial", "Correct Defect",
         "Release Change", "Archive Change"),
    "N4_redo_before_first_configuration":
        ("Register Change", "Assess Risk", "Prepare Evidence", "Correct Defect",
         "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"),
    "N5_inspect_before_configure":
        ("Register Change", "Assess Risk", "Prepare Evidence",
         "Inspect Trial", "Configure Trial", "Release Change", "Archive Change"),
    "N6_final_activity_not_archive":
        ("Register Change", "Assess Risk", "Prepare Evidence",
         "Configure Trial", "Inspect Trial", "Release Change"),
    "N7_release_without_register":
        ("Release Change", "Archive Change"),
}


def witness_report(completed, prefixes):
    rep = {"positive": {}, "negative": {}}
    for name, tr in POSITIVE_WITNESSES.items():
        rep["positive"][name] = {
            "in_completed": tr in completed,
            "is_prefix": tr in prefixes,
        }
    for name, tr in NEGATIVE_WITNESSES.items():
        rep["negative"][name] = {
            "in_completed": tr in completed,
            "is_prefix": tr in prefixes,
        }
    return rep


# ------------------------------------------------------------------
# 5.5 replay of a visible trace against a net (trace playout)
# ------------------------------------------------------------------
def replay_visible(net, im, visible_trace, tau_budget=MAX_TAU_RUN):
    """Replay a visible trace: at each step, if the target activity is not
    enabled, fire silent transitions (within budget) until it is.
    Returns (ok, detail)."""
    if net is None or im is None:
        return False, "missing net/im"
    marking = make_marking(net, im)
    detail = []
    for label in visible_trace:
        fired = False
        for _ in range(tau_budget):
            enabled = enabled_transitions(net, marking)
            target = [t for t in enabled if getattr(t, "label", None) == label]
            if target:
                marking = fire(marking, target[0])
                detail.append(("visible", label))
                fired = True
                break
            silent = [t for t in enabled if getattr(t, "label", None) is None]
            if not silent:
                break
            marking = fire(marking, silent[0])
            detail.append(("tau", None))
        if not fired:
            return False, "activity '%s' not reachable in %d steps (%s)" % (
                label, tau_budget, detail[-3:])
    return True, detail


# ------------------------------------------------------------------
# 5.6 comparison of two nets
# ------------------------------------------------------------------
def compare_nets(ref_tag, ref, other_tag, other):
    out = {"reference": ref_tag, "candidate": other_tag}
    if ref is None or other is None:
        out["status"] = "not tested (missing net)"
        return out

    src = explore_visible_traces(*ref)
    cand = explore_visible_traces(*other)

    out["source_exploration"] = {
        "completed": len(src["completed"]), "prefixes": len(src["prefixes"]),
        "states": src["states"], "truncated": sorted(src["truncated"]),
        "tau_firings": src["tau_firings"],
    }
    out["candidate_exploration"] = {
        "completed": len(cand["completed"]), "prefixes": len(cand["prefixes"]),
        "states": cand["states"], "truncated": sorted(cand["truncated"]),
        "tau_firings": cand["tau_firings"],
    }

    out["completed_missing_in_candidate"] = sorted(src["completed"] - cand["completed"])
    out["completed_extra_in_candidate"] = sorted(cand["completed"] - src["completed"])
    out["prefix_missing_in_candidate"] = sorted(src["prefixes"] - cand["prefixes"])
    out["prefix_extra_in_candidate"] = sorted(cand["prefixes"] - src["prefixes"])
    out["trace_sets_identical_under_bound"] = (
        src["completed"] == cand["completed"] and src["prefixes"] == cand["prefixes"])

    # witnesses
    out["witnesses_source"] = witness_report(src["completed"], src["prefixes"])
    out["witnesses_candidate"] = witness_report(cand["completed"], cand["prefixes"])
    out["positive_witnesses_lost"] = [
        k for k, v in out["witnesses_candidate"]["positive"].items()
        if not v["in_completed"] and v["in_completed"] is False
        and out["witnesses_source"]["positive"][k]["in_completed"]]
    out["negative_witnesses_admitted"] = [
        k for k, v in out["witnesses_candidate"]["negative"].items() if v["in_completed"]]

    # replay (trace playout) of the positive witnesses on the candidate net
    out["replay"] = {}
    for name, tr in POSITIVE_WITNESSES.items():
        ok, detail = replay_visible(other[0], other[1], tr)
        out["replay"][name] = {"ok": ok, "detail": str(detail)}

    # structural comparison (catches duplicate labels)
    out["structure_ref"] = structural_signature(ref[0])
    out["structure_candidate"] = structural_signature(other[0])
    out["label_multiplicity_changed"] = (
        out["structure_ref"]["visible_label_multiplicity"]
        != out["structure_candidate"]["visible_label_multiplicity"])
    out["label_set_changed"] = (
        out["structure_ref"]["visible_label_set"]
        != out["structure_candidate"]["visible_label_set"])

    # concurrency probes on the candidate
    snaps, _, truncated = snapshot_enabled_sets(other[0], other[1])
    out["probe_C1_assess_and_prepare_co_enabled"] = co_enabled(
        snaps, "Assess Risk", "Prepare Evidence")
    out["probe_C2_legal_and_configure_co_enabled"] = co_enabled(
        snaps, "Legal Review", "Configure Trial")
    out["probe_C3_entry_discipline"] = (
        frozenset(visible_labels(other[0])[:0]) == frozenset() and
        set(k for k in list(snaps.keys())[0]) <= {"Register Change"}) if snaps else False
    out["probe_C4_marking_graph_truncated"] = truncated

    # footprints
    fp_ref, e1 = footprints_of(*ref)
    fp_cand, e2 = footprints_of(*other)
    out["footprints_error"] = [e1, e2]
    if fp_ref and fp_cand:
        missing = {a: fp_ref[a] for a in fp_ref if a not in fp_cand}
        differing = {a: {"ref": fp_ref[a], "cand": fp_cand.get(a)}
                     for a in fp_ref if a in fp_cand and fp_ref[a] != fp_cand[a]}
        out["footprint_activities_missing"] = sorted(missing)
        out["footprint_activities_differing"] = sorted(differing)
    else:
        out["footprint_activities_missing"] = "not tested"

    out["reachability_candidate"] = reachability_summary(*other)
    out["reachability_reference"] = reachability_summary(*ref)
    return out


VALIDATION = {"comparisons": [], "source": {}}
if net_from_powl is not None:
    VALIDATION["source"] = {
        "exploration": {k: (len(v) if isinstance(v, set) else v)
                        for k, v in explore_visible_traces(
                            net_from_powl, im_from_powl, fm_from_powl).items()},
        "structure": structural_signature(net_from_powl),
        "diagnostics": [d for d in REPORT["diagnostics"] if d["tag"] == "net_from_powl"],
    }
    for tag, entry in ROUNDTRIPS.items():
        if entry.get("net") is None:
            VALIDATION["comparisons"].append({
                "candidate": tag, "status": "not tested (no round-tripped net)",
                "reason": entry.get("reason") or entry.get("error")})
            continue
        VALIDATION["comparisons"].append(
            compare_nets("net_from_powl",
                         (net_from_powl, im_from_powl, fm_from_powl),
                         "net_rt_" + tag,
                         (entry["net"], entry["im"], entry["fm"])))

with open(os.path.join(OUT_DIR, "validation_report.json"), "w") as fh:
    json.dump(VALIDATION, fh, indent=2, default=str)
print(json.dumps(VALIDATION, indent=2, default=str))
```

### Interpretation rules for the reports

* `completed_missing_in_candidate` non-empty  the round trip **removed** authorised behaviour (e.g. the legal-review-free trace, or the redo trace)  **quarantine**.
* `completed_extra_in_candidate` non-empty  the round trip **invented** behaviour (e.g. release before verification)  **quarantine**, and this is the more serious of the two, because it authorises an unapproved release.
* `positive_witnesses_lost` non-empty  a semantic loss against §1 (I-05, I-09, I-10 depending on which witness).
* `negative_witnesses_admitted` non-empty  a semantic violation of I-09/I-12/I-13.
* `probe_C1_assess_and_prepare_co_enabled == False` while the trace sets match  the conversion turned an AND-split into an interleaving  I-03 is `lost` even though every trace looks right (this is the classic false negative of trace-only comparison).
* `label_multiplicity_changed == True`  the artefact now contains duplicate activities  I-14 `lost`.
* `truncated` non-empty  the comparison is **inconclusive**, and the report must say so rather than claiming equivalence (§7 R-12).

# 6. Visual-Semantics Review

A behaviourally acceptable net can still produce a BPMN diagram that a domain expert reads incorrectly. The following are the concrete misreadings to expect for *this* model, each with a mitigation.

1. **Parallel gateway vs. sequence of two branches.** PM4Py’s netBPMN will emit a parallel split for the `Assess Risk`/`Prepare Evidence` fork — but whether that fork is drawn as a single diverging pair of flows or as two independent lanes with a *later* re-merge determines whether a reader sees “either/or, in any order” or “two mandatory independent activities that may or may not overlap”. **Reading hazard:** “two parallel branches” is often summarised as “they happen at the same time”, which is wrong — the AND-split only says they are *not ordered*. **Mitigation:** annotate the split node with the invariant ID `I-03` and the wording “no causal order; may overlap; both required”.

2. **Exclusive gateway used for the optional legal review.** The XOR branch is one visible activity and one silent skip. Depending on the exporter, the BPMN may show (a) an exclusive gateway with **two outgoing flows, one of them leading nowhere visible** (looks like a broken diagram), (b) an exclusive gateway with a single outgoing flow and a decorative dangling edge (looks like the model *requires* legal review), or (c) the silent branch dropped entirely (the optionality is gone and nobody notices). **Reading hazard:** an exclusive gateway with one visible path is routinely read as “must pass through”. **Mitigation:** name the gateway `Legal Review? (optional — I-05)`, give the skip branch an explicit labelled node `: legal review skipped (no record)`, and add a text annotation stating that the *absence* of a legal-review activity is the expected outcome in the normal case.

3. **The loop drawn as a linear “configure  inspect  correct  configure” chain.** If the µ-net of the loop is exported in a flat layout, the redo appears *before* the visual exit, and a reader concludes that **every** change request goes through `Correct Defect`. That contradicts I-09/I-10 (the redo is only executed when another iteration follows). Symmetrically, a loop drawn as “configure  inspect  (loop back)” with the correction *outside* the loop visually suggests the defect correction happens after the whole trial sequence has ended. **Reading hazard:** “the diagram shows the correction before the second trial, therefore it always happens”. **Mitigation:** annotate the loop node with `LOOP (1 iteration; redo only when repeating — I-09/I-10/I-11)` and ensure the exit branch is drawn *from* the inspect activity, not from the correction activity.

4. **The loop’s exit and the release join look the same.** `Release Change` waits for *both* the legal branch and the verification loop. If the two inbound flows merge at a single gateway, a reader cannot tell whether the merge means “AND” (both required) or “OR” (whichever finishes first). **Reading hazard:** assuming an OR merge  believing a change can be released without verification — a control failure, not just a diagram failure. **Mitigation:** label the join explicitly (`AND join — I-12`), and in the BPMN XML ensure the merge gateway is a **parallel** gateway, never an inclusive one (inclusive gateways are notoriously re-normalised by vendor tools).

5. **Silent routing nodes.** Any  that survives into the BPMN as a task with an empty name, or as a task named "Task"/"(tau)"/"None", is a *visible* activity in every downstream tool: it will appear in conformance reports, in cycle-time statistics, and in the activity list of the stakeholder diagram, even though the business never performs it. **Reading hazard:** “the process has nine activities” (nine is the true visible count) versus “the diagram shows ten boxes”. **Mitigation:** give every routing node an explicit, non-business name (`route: legal decision`, `route: loop exit`) and keep them out of the activity taxonomy; document the mapping in the artefact manifest.

6. **Layout order  execution order.** BPMN serialisers emit flows in the order they were created in the model. The resulting picture frequently lays out `Prepare Evidence` *before* `Assess Risk` (or `Legal Review` *after* `Release Change`) purely because of the order in which the converter created the nodes. Domain readers systematically over-weight the left-to-right reading of a diagram. **Reading hazard:** “the diagram shows legal review last, so legal review happens after the release”. **Mitigation:** state explicitly in the artefact documentation that position carries no meaning, and publish the invariant table (which is order-free) next to the picture.

7. **Duplicate activities after loop unfolding.** If the converter unrolls the loop body, the diagram shows *two* `Configure Trial` boxes and *two* `Inspect Trial` boxes. A reader concludes there are two different trial activities (a second trial type) — and any label-keyed analytics will silently merge or split their data. **Mitigation:** the artefact must carry the multiplicity report from `structural_signature`; duplicates must be eliminated by the exporter or explicitly labelled as loop instances.

8. **Generic mitigation package.** Every generated BPMN should ship with: (i) a `TextAnnotation` on every gateway quoting its invariant ID (e.g. `AND join — I-12`); (ii) a `TextAnnotation` on the loop with the iteration semantics; (iii) a `TextAnnotation` on the optional branch stating that omission is normal; (iv) a sidecar `conversion_report.json` + `validation_report.json`; (v) a swimlane per actor if roles are known, so that a lane change is not read as a temporal precedence; and (vi) a *documented BPMN id  source element* mapping table (the BPMN ids are stable, the picture is not).

# 7. Rejection Criteria

A conversion result must be **rejected** (not published) or **quarantined** (published internally, marked as not authoritative) if any of the following holds. R-1..R-6 are technical failures; R-7..R-12 are semantic mismatches; R-13..R-14 are governance failures.

* **R-1 — Unsound net.** `pm4py.check_soundness(net, im, fm)` is `False` or raises on the source-derived net. (A non-sound net exhibits dead ends: executions that can never finish.) *Technical failure.*
* **R-2 — Not a workflow net.** `pm4py.check_is_workflow_net(net)` is `False` for the source-derived net, i.e. the conversion produced a net with dead transitions or improper token flow. *Technical failure.*
* **R-3 — Missing markings.** Any conversion returns `im=None` or `fm=None` (e.g. a BPMN re-import without start/end events). The result is no longer an *accepting* Petri net and no soundness statement is possible; it may not be published as a verified artefact. *Technical failure.*
* **R-4 — Conversion exception.** Any step of the pipeline raises (POWLnet, netBPMN, nettree, BPMNnet). The exception must be captured and interpreted — the classical “the Petri net is not block structured” from pipeline B is *expected* and merely blocks pipeline B; an exception in pipeline A or C blocks the whole chain. *Technical failure.*
* **R-5 — Unreachable final marking / surplus tokens.** `fm` is not reachable, or a completed trace leaves a token outside `fm` (the exact-final-marking test fails), or `fm` is not a deadlock (`enabled(fm)  `). *Technical failure.*
* **R-6 — Silent truncation.** The bounded exploration reports any truncation flag (`visible-length bound`, `step bound`, `silent-run bound`, `marking-graph truncated`) and the report still claims equivalence. *Technical failure of the validation, not of the conversion.*
* **R-7 — Release admitted before verification.** Any completed trace of the candidate contains `Release Change` before `Inspect Trial` or before `Prepare Evidence` (i.e. the join of I-12 collapsed, typically because an inclusive/OR merge was used in the BPMN). *Semantic mismatch; high severity — this is a control bypass.*
* **R-8 — Lost required interleaving / collapsed concurrency.** The candidate never enables `Assess Risk` and `Prepare Evidence` simultaneously (probe C1), or never enables `Legal Review` and `Configure Trial` simultaneously (probe C2), while the source does. **Over-constraint is a loss**, even if every candidate trace is also a source trace. *Semantic mismatch.*
* **R-9 — Optional behaviour collapsed.** No completed trace of the candidate omits `Legal Review`, i.e. the -skip branch was dropped or turned into a mandatory activity; or the candidate contains a *visible* activity named like the skip, converting a non-event into an auditable business step. *Semantic mismatch.*
* **R-10 — Loop semantics violated.** `Correct Defect` appears before the first `Configure Trial`, or between `Configure Trial` and `Inspect Trial`, or as the last visible event of a completed trace; or `Configure Trial` occurs zero times in some completed trace; or the loop is bounded to a single iteration. *Semantic mismatch.*
* **R-11 — Audit table vs. generated report disagreement.** The executed `validation_report.json` contradicts the pre-test audit table of §4 (e.g. the table says `expected preserved` and the probe says otherwise, or the checklist is not regenerated at all). The §4 table must then be corrected and the artefact re-reviewed; publishing with a stale table is itself a rejection. *Governance failure.*
* **R-12 — Inconclusive equivalence.** `truncated` is non-empty and/or `prefix_extra`/`prefix_missing` are non-empty *without* an explicit, written justification of why the missing/extra behaviours are semantically irrelevant. *Semantic failure of the validation.*
* **R-13 — Label drift.** The candidate’s visible label set differs from the nine source labels, or label **multiplicity** differs (duplicate `Configure Trial`/`Inspect Trial`), or a visible placeholder label (`Task`, `(tau)`, empty) appears. *Semantic mismatch.*
* **R-14 — Non-reproducible artefact.** The artefact cannot be regenerated bit-for-bit from the source POWL plus a pinned PM4Py version, or the source signature hash in the artefact manifest does not match the current source. *Governance failure  drift is inevitable.*

Additional, softer quarantine triggers (mark as *not authoritative*, but publishable with warnings): a pipeline-B tree that was produced at all (mark `approximated`), a BPMN whose gateway kinds could not be verified by re-import, or a diagram whose layout suggests an ordering not present in the net.

# 8. Canonical Representation Recommendation

### Authoritative model (for storage)

**The POWL source, plus its invariant table, is the single source of truth.** Concretely, the stored canonical artefact set is:

1. `source_powl` (version-controlled text/serialisation), and
2. `§1 invariant table` (I-01…I-14) maintained **in the same repository, in the same commit** as the model — because the table, not the syntax, is what the converters are audited against; and
3. `compiled/` — the *generated* accepting Petri net `(net, im, fm)` produced by `pm4py.convert_to_petri_net(source_powl)` with a **pinned PM4Py version**, stored together with the SHA-256 signature of the POWL and the SHA-256 of the petri-net serialisation.

Why the POWL rather than the net or the BPMN:

* The POWL is **human-authored and human-auditable**: the XOR and the LOOP are explicit, the partial order is explicit, and the operator semantics are unambiguous *given the convention check in I-09*. Neither the BPMN (routing nodes, no operator semantics, layout-sensitive) nor the process tree (necessarily block-structured, therefore a different model) carries that property.
* The BPMN cannot be round-tripped back to the POWL without loss in PM4Py (BPMNPOWL goes through a net and a tree, and both lose the partial order). Making BPMN canonical would therefore mean making a lossy projection canonical.
* The net, although executable, is **not hand-editable** (places, arcs, silent transitions, markings). Editing it by hand is how marking drift and silent-token bugs are introduced. Its role is *compiled artefact*, not source.

**Exception / fallback:** if the organisation needs one single stored model rather than source + compiled artefact, then the **compiled accepting Petri net with its markings** is the best single candidate (it is the only one with a formal, checkable semantics). It must still be stored *with* the invariant table and the signature hash, because the net alone cannot be interpreted without them.

### Derivative models (for consumers)

* **BPMN (stakeholder visualisation).** Derivative, read-only, regenerated from the compiled net for each release. Shipped with `conversion_report.json` (PM4Py version, POWL signature), `validation_report.json` (all probe outcomes), the annotation sheet of §6, and the BPMN-id  source-element mapping.
* **Process tree (analysis only).** Derivative, **analysis-only**. Permitted for alignment, variant analysis, or a simplified narrative — never as the parent of a published BPMN and never as a source of truth. If a tree is produced at all it must be registered with the status `approximated` and the caveat that the class of process trees representable without a parallel operator cannot express I-03.
* **Images/diagrams.** Pure derivatives; they carry no semantics and are never the artefact under review.

### Validation evidence that must accompany each derivative

| Artefact | Mandatory accompanying evidence |
|---|---|
| Compiled net | PM4Py version pin; POWL signature hash; `check_is_workflow_net`, `check_soundness`; reachability-graph state count; footprint map |
| BPMN | all of the above, **plus** the re-imported net’s probe results (C1–C4, L1–L3, R-JOIN, R-OPT, R-TAU), the witness-trace coverage table, the label multiplicity map, the annotation sheet, and an explicit statement of which invariants are `validated preserved` vs `expected preserved` vs `not tested` |
| Process tree | the net it was derived from, the exception/approximation note, and a statement that I-03 (concurrency), I-07 (unordered legal  verification) and I-11 (unboundedness) are *not* guaranteed |

### Should a process-tree intermediate be allowed?

**Allowed for analysis, forbidden for authoring.** Concretely:

* `pm4py.convert_to_process_tree(net, im, fm)` may be *attempted* and its outcome recorded — a failure is a legitimate, informative result (this source is deliberately not block-structured) and must be reported as such, not hidden.
* If it *succeeds*, the resulting tree must be labelled `approximated`; it must not be used to generate a BPMN for publication, because a tree that can represent the model must have resolved the AND-split by choosing an ordering (I-03 `lost`) and, if it also succeeded on the unordered legal/verification pair, has over-constrained the model (I-07 `lost`). Publishing such a tree-derived BPMN would ship a model that is *wrong in a way every trace-level test cannot see*, because the missing behaviours are the ones being removed.
* In no case may a tree be edited by hand and re-imported; tree editing is the classic entrance to silent duplication of activities.

### How future edits should avoid round-trip drift

1. **Edit the POWL, never the derivative.** A change request that arrives as “the BPMN needs a new step” becomes a POWL edit, followed by regeneration. Hand-edited BPMN is not merged back; if the BPMN must change, the change is re-expressed in the POWL and the diagram is regenerated.
2. **Regeneration is a CI job**, not a manual step: `PIPELINE (POWL  net  BPMN)  re-import  probes  report`. The published artefacts are the output of a green run.
3. **Pin the toolchain** (PM4Py version, Python version) and record it in the artefact manifest; the conversion is a *function* of (POWL, toolchain) and nothing else.
4. **Diff the evidence, not the picture.** Each regeneration must reproduce: the same source signature, the same witness-trace verdicts, the same label multiplicity map, and a compatible footprint map. A change in any of these is a *semantic* change and must be reviewed as such — even if the picture looks identical.
5. **Keep the invariant table executable.** The I-IDs are referenced by the probes, the annotations and the audit; a new behaviour without an invariant is a modelling gap, and an invariant without a probe is an unaudited claim.
6. **Version the invariant table with the model.** If a business decision changes (e.g. legal review becomes mandatory), that is a change to I-05/I-07 in the same commit as the POWL change — the converter is not the place where that decision is encoded.

# 9. Residual Uncertainty

Even if every test in §5 passes and every report is green, the following claims are **not** established by this validation:

1. **Equivalence of the infinite trace sets.** The enumeration is bounded (`L = 12` visible events, `S = 90` firings, `T = 30` consecutive ). A behavioural difference that requires, say, four redo iterations interleaved with two legal-review decisions is outside the bound and is not tested. “No difference found under the bound” is strictly weaker than “no difference”.
2. **Unboundedness (I-11) is argued, not proven.** The evidence is a cycle in the reachability graph plus the presence of  2 iterations in the witness traces. A converter could in principle emit a net in which the reachable cycle is *not* the trial loop but an unrelated -cycle, leaving the trial bounded to two iterations while the cycle check still passes. Distinguishing this requires cycle-attribution (does the cycle pass through `Configure Trial`/`Inspect Trial`?) which the current probe does not perform.
3. **Identity of hidden structure.** Two nets can have identical visible trace sets and different -scaffolding: e.g. one silent “skip” placeholder xor a silent “loop exit” versus two distinct silent transitions. The visible semantics coincide, so the comparison cannot distinguish them; but downstream tools that *do* expose  (approximate conformance, model checking on the structural level) may behave differently. Equality of visible traces is not equality of models.
4. **Footprint-based conclusions are count-blind.** `discover_footprints` discards occurrence counts, so a loop bounded to 1 and a loop bounded to  can have identical footprints. Footprints are therefore only used as a *sanity* signal, never as proof of I-10/I-11.
5. **Rendering comprehension.** Nothing in the pipeline validates that a domain expert reads the BPMN correctly. The §6 hazards (parallel-vs-exclusive confusion, “correct defect always happens”, layout-as-order) are human-factors risks; they can only be reduced by annotations and by user testing, not by the probes.
6. **Downstream-tool behaviour.** The pipeline stops at PM4Py’s own BPMN serialisation and re-import. Vendor tools that normalise gateways, merge inclusiveexclusive, auto-rename empty tasks, or re-generate start/end events are outside the tested scope, so the *shipped* artefact may differ from the one validated here.
7. **The intended semantics versus the tool semantics of the binary loop.** The POWL `LOOP[trial_body, correct_defect]` is interpreted by PM4Py according to a convention (body first, redo on repetition). The probes detect *which* convention produced the net, but they cannot establish that the original author intended that convention — only the process owner can. If the author meant “redo first, then trial”, the converter is faithful to the code and unfaithful to the intent; only §1 I-09 (the declared intended semantics) makes that visible, which is why I-09 is written as a normative statement rather than as an observation.
8. **Concurrency vs. resource reality.** The POWL states ordering constraints; it says nothing about resources, volumes or timing. A net that preserves I-03 exactly may still be unusable if two concurrent activities require the same engineer — the converted model inherits that gap from the source and the validation cannot detect it.
9. **Governance questions.** Whether the artefact is “the” auditable version of the change process (e.g. for a compliance audit) is a decision about the evidence chain, not a property that any probe can establish.
10. **Version-to-version converter behaviour.** All statements about PM4Py’s POWLnet internals are statements about a **pinned build**. A different PM4Py version may linearise the partial order where the pinned one does not; the signature hash and evidence bundle make that detectable, but they cannot prevent it.
