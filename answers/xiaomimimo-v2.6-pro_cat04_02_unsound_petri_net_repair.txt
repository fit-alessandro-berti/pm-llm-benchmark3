```python
# ------------------------------------------------------------------ helpers
def transition_by_name(net, name):
    ...

def enabled_names(net, marking): ...

def fire_raw(marking, transition): # assumes enabled
    new = Marking()
    for p, v in marking.items():
        new[p] = v
    for a in transition.in_arcs:
        new[a.source] -= 1
        if new[a.source] == 0:
            del new[a.source]
    for a in transition.out_arcs:
        if a.target in new:
            new[a.target] += 1
        else:
            new[a.target] = 1
    return new

def fire_named(net, marking, name):
    """Fire a named transition, *after* checking enabledness. Returns the new marking or None."""
    t = transition_by_name(net, name)
    if t not in pm4py.get_enabled_transitions(net, marking):
        print(f"    !! {name} is not enabled in {fmt(marking)} -> firing refused")
        return None
    return fire_raw(marking, t)

def replay(net, im, fm, seq, title):
    print(f"\n--- {title} ---")
    m = Marking(); m.update(im)
    print(f"  step 0 | marking {fmt(m)} | enabled {enabled_names(net, m)}")
    for i, name in enumerate(seq, start=1):
        m2 = fire_named(net, m, name)
        if m2 is None:
            print(f"  step {i} | {name} could not be executed; replay stops here")
            return None
        m = m2
        print(f"  step {i} | fired {name:18s} | marking {fmt(m)} | enabled {enabled_names(net, m)}")
    covered = all(m.get(p, 0) >= v for p, v in fm.items())
    equal = (m == fm) or (dict(m) == dict(fm))
    print(f"  final marking {fmt(m)} | covers fm: {covered} | equals fm: {equal}")
    return m

def reachable_markings(net, im, cap=50000):
    start = Marking(); start.update(im)
    todo, seen, out = [start], set(), []
    while todo:
        m = todo.pop()
        key = frozenset(m.items())
        if key in seen:
            continue
        seen.add(key); out.append(m)
        if len(out) > cap:
            raise RuntimeError("enumeration cap reached")
        for t in pm4py.get_enabled_transitions(net, m):
            todo.append(fire_raw(m, t))
    return out
```

# 1. Executive Verdict

Structurally this is a workflow net: a single source place (`source`), a single sink place (`sink`), and every node on a sourcetosink path. It is **not** sound and should not be expected to be. The principal defect is `t_join_waived`: with one input and one output it is a channel, not a synchronization. On the waiver route the case reaches `p_decision`/`sink` while the analysis token is still in `p_analysis` (or `p_analysis_done`), and `t_join_normal`, the only consumer of `p_analysis_done`, is then permanently blocked. Business consequence: authorization may be recorded before the analysis exists — or with no analysis at all — and every waiver case closes with a stranded token, so `fm = {sink: 1}` is never reached, only covered.

| 3 | `t_waive_review` | `{p_analysis:1, p_waived:1}` | `{t_analyze, t_join_waaved}` | waiver recorded (token B moved to `p_waaved`); token A untouched. **`t_join_waived` is already enabled although the analysis has not run** |
| 4 | `t_join_waaved` | `{p_analysis:1, p_decision:1}` | `{t_analyze, t_authorize}` | the "join" consumed **only** the waiver token  `t_authorize` is enabled before `t_analyze` |

Remarks required by the task:

* **Token accounting.** After `t_split` there are two tokens (A in the analysis branch, B in the review branch). `t_join_waived` maps 1 token to 1 token (`p_waived``p_decision`), so it merges nothing: token A survives the whole run and is still present at steps 5 and 6.
* **`t_authorize` before or after `t_analyze`?** Both are possible: steps 5 and 6 commute (`t_authorize` and `t_analyze` are both enabled at step 4). Hence the model admits *authorization before analysis* and even *authorization with no analysis at all* (1 truncated after step 5). By contrast, on the standard route the order is enforced: `t_join_normal` needs `p_analysis_done`.
* **"A token is in the sink" vs. "`fm` was reached".** At steps 5 and 6 the marking *covers* `fm` (`{sink:1}  m`) but is not equal to `fm`. Soundness (proper completion) requires the only reachable marking carrying a token in `sink` to be `fm` itself — here three different markings do.
* **Can the leftover token be consumed?** No.
  * At step 5 the only transition reading `p_analysis` is `t_analyze`, which merely *moves* the token to `p_analysis_done`.
  * At step 6 the only transition reading `p_analysis_done` is `t_join_normal`, which additionally needs `p_review_done`. `p_review_done` can only be produced by `t_standard_review`, which needs a token in `p_review`; `p_review` was emptied in step 3 and `t_split` cannot fire again (its preset `p_ready` is empty). So the token in `p_analysis_done` is unremovable and the run deadlocks in a nonfinal marking.
  * Consequently `fm` is not reachable from the step5/step6 markings: the **option to complete** fails as well.

# 4. Minimal-Repair Alternatives

**Editcost model** (stated before the table so the cost column is readable): adding or removing one arc = 1; adding or removing one place = 1; adding or removing one transition = 1; retargeting an arc = 2 (one removal + one addition); changing one visible label = 1; changing one marking token = 1. Deleting a node requires deleting its incident arcs separately (otherwise the object is left with dangling arcs). Total cost = sum of edits. A repair is **minimal** if no strictly cheaper repair exists *within the same behavioural class* (classes defined after the table).

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **A1 — make the waiver join a real synchronization** (selected) | **Add** arc `p_analysis_done  t_join_waaved` | **1** | everything: analysis mandatory on both routes, full analysis  review concurrency, waiver and standard review both available in every state, authorization strictly after both | only the illegal behaviour disappears: `Register, Record Review Waiver, Authorize` and `Authorize` before `Perform Analysis` are no longer producible | two silent joins remain with asymmetric presets (net stays nonfreechoice, harder for WOFLANstyle tooling); a future third review outcome needs a third join, so the same bug class can reappear |
| **A2 — collapse the two joins into one synchronization** | **Remove** arcs `t_waive_review  p_waaved`, `p_waived  t_join_waaved`, `t_join_waaved  p_decision`; **remove** transition `t_join_waaved`; **remove** place `p_waaved`; **add** arc `t_waive_review  p_review_done` (`p_review_done` becomes "review resolved: standard **or** waived") | **6** | everything (same set of legal visible traces as A1) | no tracelevel change; structurally one join, 8 places / 7 transitions, reachable markings drop from 14 to 10/8 (see §6) | the waiver is no longer distinguishable in the net (only the label "Record Review Waiver" remains)  weaker netlevel audit; if a later rule treats waived cases differently, the place must be split again |
| **B1 — waiver only after the analysis** | **Add** arc `p_analysis_done  t_waive_review` (the waiver consumes and discards the analysis result) | **1** | analysis remains mandatory; authorization strictly after analysis and review outcome | **policy change:** the waiver can only be *recorded* after the analysis is complete; the interleaving `Record Review Waiver` before `Perform Analysis` is removed (the review starts in parallel but its waiver outcome is serialized behind the analysis) | a business rule of the form "the review may be waived immediately after registration" would be broken; the hidden dependence reviewanalysis may surprise users |
| **B2 — waiver cancels a stillpending analysis** | **Add** arc `p_analysis  t_waive_review` | **1** | concurrency skeleton | **policy change (large):** a recorded waiver *cancels* a notyetperformed analysis (`Register, Record Review Waiver, Authorize` becomes legal), and once the analysis *has* been performed the waiver is disabled, so only a standard review remains possible in `{p_analysis_done, p_review}` | violates "the analysis is always mandatory" *and* "the review can be either"; the behaviour loss is silent and easy to overlook |
| **B3 — analysis optional under waiver with a recorded skip** | **Add** transition `t_skip_analysis` labelled "Skip Analysis"; **add** arcs `p_analysis  t_skip_analysis`, `p_waived  t_skip_analysis`, `t_skip_analysis  p_decision`; **add** arc `p_analysis_done  t_join_waived` (covers the case where the analysis already ran) | **5** | concurrency; analysis mandatory on the **standard** route; the waiver option stays available in every state; the waiver remains recorded | **policy change (declared):** after a recorded waiver the analysis may be replaced by an explicit, logged "Skip Analysis" step; new trace `Register, Record Review Waiver, Skip Analysis, Authorize` | new visible label must be produced by the source system (log alphabet changes); if the `p_waaved` guard is dropped the same 4arc skeleton degrades to "analysis optional everywhere" (cost 4) and becomes a bypass |

**Classes and minimality.**

*Class P (policypreserving):* exactly the four legal traces `Register · {A·S, S·A, A·W, W·A} · Authorize`. A1 and A2 are in P.

*Lower bound for any repair (cost  1).* Cost0 means no edit. Label edits do not change enabling semantics, so they cannot remove the bad run. Marking edits cannot work either: the three reachable sinkmarkings `{p_analysis:1,sink:1}`, `{p_analysis_done:1,sink:1}`, `{sink:1}` are pairwise distinct and all reachable, so no single `fm` can equal all of them; setting `fm` to one of the first two merely makes the *other* runs (including the legal standardreview run) uncompletable. Hence at least one structural edit is required, and every structural edit costs  1.

*Class P is uniquely minimized by A1 (cost 1).* The only plausible 1arc edits are additions/removals of a single arc. Every single deletion breaks either the WFnet condition (e.g. removing `t_split  p_analysis` leaves `p_analysis` a second source place and `t_analyze` dead) or the option to complete (e.g. removing `p_waaved  t_join_waaved` strands the waiver token). Among 1arc additions, `p_analysis  t_join_waaved` deadlocks in `{p_analysis_done, p_waaved}` (nothing enabled) and `p_analysis_done  t_analyze`style additions do not remove the bad run. Only `p_analysis_done  t_join_waaved` (A1) and `p_analysis_done  t_waive_review` (B1) and `p_analysis  t_waive_review` (B2) yield a sound net; the latter two change the policy, so within P the optimum is A1 and it is unique.

*The tie (A1 = B1 = B2 = 1) is genuine*: each adds exactly one arc, so unit arc cost makes them equal. They differ in *where* the missing analysis dependency is attached (join vs. waiver transition) and therefore in the induced partial order — cost alone cannot rank them, only the business class can.

*Class "one synchronization" is minimized by A2 (cost 6).* To have a single synchronization, `t_join_waaved` must disappear: its two incident arcs (2) and the transition (1) must go; then `p_waaved` has no path to the sink, so it must go too (1) together with its remaining input arc (1), and `t_waive_review` needs a new output arc (1) because a transition without an output arc is not on any sourcetosink path. Lower bound 6, attained. The mirror variant (keeping `t_join_waaved`, deleting `t_join_normal`) costs **7**, because the surviving join must then also gain the `p_analysis_done` input arc — this asymmetry is exactly the root cause of the original defect.

*Class "analysis optional under waiver, waiver option preserved, skip must be logged" is minimized by B3 (cost 5).* A new transition is unavoidable (no existing transition can dispose of a notyetanalysed token without performing the analysis); it needs  1 input and  1 output arc,  1 arc to/from `p_waaved` to be guarded by the waiver, and  1 arc to discharge the `p_analysis_done` case (`p_analysis_done  t_join_waaved`). Lower bound 1 + 4 = 5, attained. Cheaper members of the broader "optional analysis" family (B2 at 1, or an unguarded `t_skip_analysis: p_analysis  p_analysis_done` at 4) buy their discount only by destroying other behaviour, as recorded in the table.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


# ----------------------------------------------------------------- helpers
def transition_by_name(net, name):
    for t in net.transitions:
        if t.name == name:
            return t
    raise KeyError("no transition named %r in %s" % (name, net.name))


def fmt(marking):
    if not marking:
        return "{}"
    return "{" + ", ".join("%s:%d" % (p.name, v)
                           for p, v in sorted(marking.items(), key=lambda kv: kv[0].name)) + "}"


def enabled_names(net, marking):
    return sorted(t.name for t in pm4py.get_enabled_transitions(net, marking))


def fire_raw(marking, transition):
    """Execute an ALREADY ENABLED transition; returns a fresh Marking."""
    new = Marking()
    for p, v in marking.items():
        new[p] = v
    for a in transition.in_arcs:
        new[a.source] = new[a.source] - 1
        if new[a.source] == 0:
            del new[a.source]
    for a in transition.out_arcs:
        new[a.target] = new[a.target] + 1 if a.target in new else 1
    return new


def fire_named(net, marking, name):
    """Fire a transition BY NAME. Checks enabledness first; never moves tokens blindly."""
    t = transition_by_name(net, name)
    if t not in pm4py.get_enabled_transitions(net, marking):
        print("    !! %s is NOT enabled in %s -> firing refused" % (name, fmt(marking)))
        return None
    return fire_raw(marking, t)


def replay(net, im, fm, seq, title):
    print("\n--- %s ---" % title)
    m = Marking()
    m.update(im)
    print("  step 0 | marking %-34s | enabled %s" % (fmt(m), enabled_names(net, m)))
    for i, name in enumerate(seq, start=1):
        m2 = fire_named(net, m, name)
        if m2 is None:
            print("  step %d | replay stops here" % i)
            return None
        m = m2
        print("  step %d | fired %-18s | marking %-34s | enabled %s"
              % (i, name, fmt(m), enabled_names(net, m)))
    covers = all(m.get(p, 0) >= v for p, v in fm.items())
    print("  end    | covers fm: %s | equals fm: %s" % (covers, dict(m) == dict(fm)))
    return m


def reachable_markings(net, im, cap=50000):
    """Exhaustive marking enumeration (these nets are bounded)."""
    start = Marking()
    start.update(im)
    todo, seen, out = [start], set(), []
    while todo:
        m = todo.pop()
        key = frozenset(m.items())
        if key in seen:
            continue
        seen.add(key)
        out.append(m)
        if len(out) > cap:
            raise RuntimeError("enumeration cap reached")
        for t in pm4py.get_enabled_transitions(net, m):
            todo.append(fire_raw(m, t))
    return out


def report(tag, net, im, fm):
    print("\n" + "=" * 72)
```

# 7. Repair Trade-Offs and Residual Risks

* **Distinguishability of waiver and standard review.** In A1 (and B1/B2) the two outcomes stay structurally distinct: `p_waaved` vs `p_review_done`, so a "was this case waived?" property is directly checkable at net level. In A2 the two outcomes collapse into one place; the distinction survives only in the visible labels of `t_standard_review` / `t_waive_review`, i.e. only in the event log. All repairs preserve the label "Record Review Waiver"; only B3 adds a label ("Skip Analysis").

* **Duplicate behaviour and silent transitions.** A1 keeps two *silent* joins (`t_join_normal`, `t_join_waived`) that both perform the same kind of synchronization and write to `p_decision`. They emit no events, so conformance checking is unaffected and no visible trace acquires a second derivation (each legal visible trace has a unique silent skeleton here — checked on the four legal traces). The residual hazard is maintenancelevel: any future rule attached to one join but not the other (e.g. "authorization must be countersigned when waived") would silently apply to only half of the cases. Note also why B3 introduces a *visible* label instead of a second silent variant of `t_waive_review`: the latter would give one trace two step sequences (duplicate behaviour), which confuses alignments and discovery.

* **Soundness is not business alignment.** Soundness is invariant under label renaming and says nothing about data, roles or ordering policies. Two counterexamples among the repairs above are sound but wrong: B2 (waiver cancels the analysis) and the "delete the analysis branch entirely" variant (7 edits: drop `t_split  p_analysis`, `p_analysis  t_analyze`, `t_analyze  p_analysis_done`, `p_analysis_done  t_join_normal`, `t_analyze`, `p_analysis`, `p_analysis_done`) — the latter is a perfectly sound net that simply has no analysis. B1 is sound but forbids interleavings the business may want. A green `check_soundness` therefore proves only hygiene (option to complete, proper completion, no dead transitions), never compliance with "the analysis is always mandatory".

* **Regression tests (positive / negative traces).**
 Positive: `R,A,S,Auth`; `R,S,A,Auth`; `R,A,W,Auth`; `R,W,A,Auth` (and, only if B3 is deployed, `R,W,Skip,Auth`).
 Negative: `R,W,Auth` (the bug of this model); `R,S,Auth`; `R,Auth`; `R,A,S,W,Auth` (both outcomes); `R,W,A,Auth,A`; `R,A,S,Auth,A`; `R,S,S,A,Auth` (double review); any trace with two `Auth`. Discriminators between the repairs: `R,W,A,Auth` is legal for A1/A2 but illegal for B1; `R,W,Auth` is illegal for A1/A2 but legal for B2 — so these two traces alone separate the repair families.

* **Detecting an accidental bypass of mandatory analysis.** (i) A lint/unit invariant on the net object: *every transition with `p_decision` in its postset must have `p_analysis_done` in its preset* — this is exactly the class of defect found here and it costs one assertion. (ii) The reachability assertion used in §6: *no reachable marking may cover `fm` without being `fm`*. (iii) Replay test: the `fire_named` sequence `t_register t_split t_waive_review t_join_waived t_authorize` must be **refused**, not merely "not reach `fm`". (iv) Caselevel conformance: `#("Perform Analysis") == #("Register Case")` in every completed case, and an optimal alignment against the repaired net must cost 0 (any missing analysis must show up as a moveonmodel). (v) Monitor `t_authorize` inputs at runtime: assert that one `p_analysis_done` token was consumed for the case being authorized.

# 8. Final Recommendation

**Deploy A1** (add `p_analysis_done  t_join_waaved`); keep **A2** (single synchronization) as the fallback.

A1 is a onearc diff: it is reviewable at a glance, it cannot introduce transcription errors, and it changes nothing except the illegal behaviour. Most importantly it preserves the business policy *exactly* — the analysis stays mandatory on the waiver route, the analysis and the review remain genuinely parallel (all four interleavings stay legal), and the waiver stays a structurally distinct, auditable state (`p_waaved`) as befits a "formally recorded waiver". Its two acknowledged costs are cosmetictoanalytical: the net stays nonfreechoice and a second, now redundant join remains.
