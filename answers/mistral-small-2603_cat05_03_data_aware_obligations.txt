## 1. Temporal Data Semantics

### State Reconstruction
- **Blank attributes**: Treated as "no update at this event" (not null). The last known value persists until explicitly changed.
- **State at event**: For any obligation evaluation, use the latest known value at the event timestamp (not the final case state). If two events share a timestamp, `event_index` breaks ties (lower index = earlier in tie).
- **Material changes**: Any change to `amount`, `risk_level`, `jurisdiction`, or `customer_type` is considered material unless explicitly stated otherwise.
- **Effective time**: Updates are effective at their event timestamp unless evidence explicitly establishes another effective time (e.g., exemption effective_from).
- **Evidence time**: For late evidence (e.g., `Record_Exemption`), the evidence time is the event timestamp, but the effective time may be earlier (e.g., exemption effective_from).
- **Unknown values**: If an attribute is unknown at the time of an obligation trigger, classify as `INDETERMINATE` unless other evidence resolves it (per R6).

### Key Distinctions
- **Event time**: When the event occurred (timestamp).
- **Effective time**: When an attribute change takes effect (may differ from event time, e.g., exemption effective_from).
- **Record time**: When evidence was recorded (e.g., `Record_Exemption` at 11:00 for EX-77).
- **Evidence time**: When evidence becomes available (e.g., witness testimony for EX-88).

## 2. Normalized Rule Table

| Rule | Trigger event and condition | Required prior/subsequent event | Ordering constraint | State snapshot used | Exception | Missing-data treatment | Evidence needed |
|------|-----------------------------|---------------------------------|---------------------|---------------------|-----------|------------------------|-----------------|
| R1 | Release_Funds; current jurisdiction  DE; current amount  EUR 100,000 | Enhanced_Review after latest material change and before Release_Funds; no matching exemption | Enhanced_Review must precede Release_Funds | Latest state at Release_Funds | Exemption matching R1 scope | INDETERMINATE if amount unknown | Exemption register, Enhanced_Review timestamp |
| R2 | Release_Funds; current risk_level = HIGH or customer_type = PEP | Enhanced_Review and Compliance_Approve; both before Release_Funds; Compliance_Approve after Enhanced_Review | Compliance_Approve must follow Enhanced_Review | Latest state at Release_Funds | None | INDETERMINATE if risk_level/customer_type unknown | Enhanced_Review and Compliance_Approve timestamps |
| R3 | Sanctions_List_Update after latest Sanctions_Screen and before Release_Funds | New Sanctions_Screen after Sanctions_List_Update and before Release_Funds | Sanctions_Screen must follow Sanctions_List_Update | State at Release_Funds | None | INDETERMINATE if jurisdiction unknown | Sanctions_List_Update and Sanctions_Screen timestamps |
| R4 | Amount increase > 20% after latest Standard_Review or Enhanced_Review | None (invalidates review) | N/A | State at Review event | None | INDETERMINATE if amount unknown | Review timestamp, amount change timestamps |
| R5 | Exemption validity at Release_Funds | Exemption approved by Head_Compliance; effective_from  obligation trigger; scope matches; not expired | N/A | Exemption register | None | INDETERMINATE if exemption evidence weak | Exemption register, evidence timestamps |
| R6 | Missing amount/risk/jurisdiction/customer_type at obligation trigger | N/A | N/A | N/A | N/A | INDETERMINATE | None |
| R7 | Equal timestamps | Use event_index to order events | Lower event_index = earlier | State at event | N/A | N/A | None |

### Pseudo-Logic for R1–R7
```python
# R1: Foreign high-value enhanced review
def r1_triggered(release_state):
    return (release_state.jurisdiction != "DE" and
            release_state.amount >= 100000 and
            not exemption_matches(release_state, "R1"))

def r1_satisfied(release_state):
    latest_review = latest_enhanced_review(release_state.case)
    return (latest_review is not None and
            latest_review.time < release_state.time and
            latest_review.time > latest_material_change(release_state.case))

# R2: High-risk or PEP approval
def r2_triggered(release_state):
    return (release_state.risk_level == "HIGH" or
            release_state.customer_type == "PEP")

def r2_satisfied(release_state):
    enhanced_review = latest_enhanced_review(release_state.case)
    compliance_approve = latest_compliance_approve(release_state.case)
    return (enhanced_review is not None and
            compliance_approve is not None and
            compliance_approve.time > enhanced_review.time and
            compliance_approve.time < release_state.time)

# R3: Sanctions-list update
def r3_triggered(release_state):
    latest_screen = latest_sanctions_screen(release_state.case)
    sanctions_update = latest_sanctions_update(release_state.case)
    return (sanctions_update is not None and
            sanctions_update.time > latest_screen.time and
            sanctions_update.time < release_state.time)

def r3_satisfied(release_state):
    new_screen = sanctions_screen_after_update(release_state.case)
    return (new_screen is not None and
            new_screen.time > latest_sanctions_update(release_state.case).time and
            new_screen.time < release_state.time)

# R4: Material amount change
def r4_invalidates_review(review_event, case):
    if review_event.type not in ["Standard_Review", "Enhanced_Review"]:
        return False
    amount_before = amount_at_time(case, review_event.time)
    amount_after = amount_at_time(case, release_funds_time(case))
    if amount_before is None or amount_after is None:
        return None  # INDETERMINATE
    return (amount_after > amount_before * 1.2)

# R5: Exemption validity
def exemption_valid(exemption, obligation_time):
    return (exemption.approved_by == "Head_Compliance" and
            exemption.effective_from <= obligation_time and
            not exemption.expired(obligation_time) and
            evidence_strong(exemption.evidence))

# R6: Missing data
def missing_data_triggered(obligation):
    return any(getattr(obligation, attr) is None for attr in ["amount", "risk_level", "jurisdiction", "customer_type"])

# R7: Event-time semantics
def state_at_event(case, event_time, event_index=None):
    events = sorted(case.events, key=lambda e: (e.time, e.event_index))
    state = {}
    for e in events:
        if e.time > event_time or (e.time == event_time and e.event_index >= event_index):
            break
        for attr in ["amount", "risk_level", "jurisdiction", "customer_type"]:
            if getattr(e, attr) is not None:
                state[attr] = getattr(e, attr)
    return state
```

## 4. Ambiguities and Alternative Readings

### TX-302
- **Ambiguity**: EX-77's evidence is strong (qualified digital signature), but the exemption was recorded late (11:00). The exemption's effective_from (09:00) aligns with the transaction time.
- **Alternative reading**: If the exemption's effective_from were not supported by evidence, it would be INDETERMINATE.
- **Evidence needed**: None; current evidence is sufficient.

### TX-305
- **Ambiguity**: Amount is unknown at release but known at settlement (150000). The release payload omits the amount.
- **Alternative reading**: If the release amount were reliably known to be 150000 at release time, R1 would be triggered (150000  100000, jurisdiction=CADE).
- **Evidence needed**: Immutable release payload with amount.

### TX-310
- **Ambiguity**: EX-88's evidence is weak (witness testimony, PDF timestamp after release, signing certificate created late).
- **Alternative reading**: If the witness testimony were corroborated by another source, it might be COMPLIANT.
- **Evidence needed**: Corroborating evidence for oral approval at 08:45.

### TX-311
- **Ambiguity**: Jurisdiction changes to DE at the same timestamp as Enhanced_Review (event_index 4 > 3). The jurisdiction change is after the review.
- **Alternative reading**: If jurisdiction change were before the review, R1 would not apply (jurisdiction=DE).
- **Evidence needed**: None; event_index ordering is clear.

## 6. Why Control-Flow-Only Conformance Is Insufficient

1. **Final-state leakage**: Control-flow-only checks might copy final attributes backward in time, violating R7.
2. **Post-hoc exemptions**: Exemptions recorded after release (e.g., EX-77 at 11:00) could be used to justify earlier releases if control-flow is the only check.
3. **Material changes after review**: R4 requires tracking amount changes after reviews, which control-flow cannot do.
4. **Conditional activation**: Rules like R1 and R2 depend on dynamic state (e.g., amount, risk), not just event order.
5. **Missing data**: Control-flow cannot handle unknown values (e.g., TX-305 amount).
6. **Same-timestamp ordering**: Without `event_index`, jurisdiction changes at the same timestamp as reviews could be misordered.
7. **Late evidence**: Evidence time (e.g., EX-88's weak evidence) is not captured by control-flow.
8. **Exemption scope**: Exemptions must match scope (e.g., R1 only), which requires attribute-level checks beyond control-flow.

## 7. Recommended Logging and Control Improvements

1. **Immutable release payload**: Include amount, risk, jurisdiction, and customer_type in the release event with a cryptographic hash.
2. **Effective/record/signature timestamps**: Separate fields for when an attribute change takes effect, when it was recorded, and when it was signed.
3. **Rule version**: Include the rule version in exemption scopes (e.g., "R1 v2.1").
4. **Exemption scope**: Store exemption scope as structured data (e.g., JSON) with clear waiver lists.
5. **Change provenance**: Log the source of each attribute change (e.g., "customer portal", "system feed").
6. **Stable event ordering**: Use `event_index` or UUIDs to ensure deterministic ordering for same-timestamp events.
7. **Material change flags**: Explicitly mark events that are material changes (e.g., `is_material_change=True`).
8. **Exemption evidence**: Store exemption evidence (e.g., digital signatures, witness IDs) with timestamps.
9. **Obligation triggers**: Log when an obligation is triggered (e.g., "R1 triggered at Release_Funds due to amount=125000, jurisdiction=US").
10. **Audit trail**: Maintain an immutable audit log for all attribute changes and reviews.
