# 2. Shared Assumptions

1. **Event completion semantics**: A recorded activity is assumed complete, but it does not strictly imply when it started or in what order events were executed.
2. **Missing Supplier Confirmation**: Absent events may either reflect missing data due to integration issues or legitimate skipping (e.g., stocked components).
3. **Optionality**: Attributes, notably stocked vs. external components, are unobserved; optional tasks like `Expedite Review` or `Supplier Confirmation` must account for this uncertainty.
4. **Concurrency vs. sequence**: Only variant-based reconciliation of concurrency claims (e.g., `Credit Check` and `Engineering Review`) is possible.

# 3. Conservative Candidate

### Inductive-Bias Statement
The conservative model minimizes behavioral overgeneralizations by adhering strictly to observed variant sequences, high-reliability domain rules, and excluding plausible but unobserved event combinations. This ensures precision but risks underfitting.

### Formal Expression
Tree representation:
- Sequence(`Register Order`, XOR(`Credit Check`, `Engineering Review`), Optional(`Supplier Confirmation`), Optional(`Expedite Review`), `Approve Configuration`, `Release Production`, `Archive Case`)

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator as Op, Task

tree = ProcessTree(constraints=Op.SEQUENCE)
tree.add_child(Task("Register Order"))

# XOR for ordering ambiguity between Credit Check and Engineering Review
xor_check_review = ProcessTree(constraints=Op.XOR)
xor_check_review.add_child(Task("Credit Check"))
xor_check_review.add_child(Task("Engineering Review"))
tree.add_child(xor_check_review)

# Add optional Supplier Confirmation
opt_supplier = ProcessTree(constraints=Op.XOR)
opt_supplier.add_child(Task("Supplier Confirmation"))
opt_supplier.add_child(ProcessTree(constraints=Op.NONE))  # Skip branch
tree.add_child(opt_supplier)

# Optional Expedite Review
opt_expedite = ProcessTree(constraints=Op.XOR)
opt_expedite.add_child(Task("Expedite Review"))
opt_expedite.add_child(ProcessTree(constraints=Op.NONE))
tree.add_child(opt_expedite)

# Final sequence
tree.add_child(Task("Approve Configuration"))
tree.add_child(Task("Release Production"))
tree.add_child(Task("Archive Case"))

model_conservative = tree
```

### Excluded Behaviors
- Concurrency between `Credit Check` and `Engineering Review`.
- Activity placements not supported by observed sequences (e.g., `Expedite Review` between `Approve Configuration` and `Release Production`).

### Underfitting Risks
- Over-exclusion of plausible interleavings (e.g., concurrent credit/engineering checks).
- Inability to generalize beyond exact observed traces.

# 4. Balanced Candidate

### Inductive-Bias Statement
The balanced model prioritizes plausible generalization, balancing observed patterns with medium-confidence domain knowledge. It allows partial concurrency but respects ordering constraints where needed.

### Formal Expression
Directed dependency graph with partial concurrency:
- Sequence(`Register Order`, Parallel([`Credit Check`, `Engineering Review`]), XOR(`Supplier Confirmation`, None), `Expedite Review`  Optional, `Approve Configuration`, `Release Production`, `Archive Case`)

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator as Op, Task

tree = ProcessTree(constraints=Op.SEQUENCE)
tree.add_child(Task("Register Order"))

# Parallel behavior between checks
parallel_checks = ProcessTree(constraints=Op.PARALLEL)
parallel_checks.add_child(Task("Credit Check"))
parallel_checks.add_child(Task("Engineering Review"))
tree.add_child(parallel_checks)

# XOR Optional Supplier Confirmation
opt_supplier = ProcessTree(constraints=Op.XOR)
opt_supplier.add_child(Task("Supplier Confirmation"))
opt_supplier.add_child(ProcessTree(constraints=Op.NONE))
tree.add_child(opt_supplier)

# Optional Expedite Review
opt_expedite = ProcessTree(constraints=Op.XOR)
opt_expedite.add_child(Task("Expedite Review"))
opt_expedite.add_child(ProcessTree(constraints=Op.NONE))
tree.add_child(opt_expedite)

# Final sequence
tree.add_child(Task("Approve Configuration"))
tree.add_child(Task("Release Production"))
tree.add_child(Task("Archive Case"))

model_balanced = tree
```

### Behavior Excluded
- Irregular placements of `Supplier Confirmation` before checks (e.g., skipping entire dependency checks).
- Allowing `Expedite Review` after `Release Production`.

### Underfitting Risks
- May misinterpret skipped `Supplier Confirmation` as legitimate behavior.

# 5. Permissive Candidate

### Inductive-Bias Statement
The permissive model maximally admits plausible behaviors consistent with domain rules and missingness assumptions. It tolerates flexible orderings constrained primarily by global dependencies like start/end and approval prerequisites.

### Formal Expression
Directed dependency graph supports maximum concurrency and optionality:
- Start  XOR of interdependent chains:
  - Any order(`Credit Check`, `Engineering Review`)
  - Optional(`Supplier Confirmation`)
  - Optional(`Expedite Review`  before `Approve Configuration`)
  - Final sequence(`Release Production`, `Archive Case`).
