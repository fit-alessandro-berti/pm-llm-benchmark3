The collapse is best read as a stack of independent distortions on the path from true behavior to measured fitness, not as one event. Release 4.2 changed the recorded label, so every renamed case gains a log move on `Risk Screen` and a model move on `Classify`. The gateway added `Queue Routed`, another log move in most cases. A trace fits only when all its events fit, so these effects interact: in the supplied variants 415 of 650 June-July cases need both repairs, and single-step attributions depend on repair order. The ETL change then swapped `Decision` and `Notify` in a subset, and from August the policy added a real, compliant step that the frozen model counts as deviation. Under that noise sit two small signals no repair removes: enhanced reviews without a recorded check, and `Manual Override`.

Stable outcomes fit this reading but cannot settle it. They argue against 68% of cases truly deviating. Yet relabels, technical events and a stale model leave outcomes untouched whatever the quality of the remaining data, so stability does not certify the log. Nor does it clear reviewers. The 25-30 possible bypasses are 4-5% of cases; if their appeal rate doubled, the aggregate would move about 0.2 points against a sampling error near 0.75. Appeals are lagged and censored for September, incident detection is incomplete, harm from a skipped check may surface as fraud or regulatory exposure instead of appeals, and cycle time is itself computed from ingestion-stamped events.

def build_log(variant_counts):
    """Expand {trace string: count} into an event log (synthetic timestamps keep the listed order)."""
    traces = [trace for trace, count in variant_counts.items() for _ in range(count)]
    return pm4py.parse_event_log_string(traces)

def map_labels(df, mapping=LABEL_MAP):
    out = df.copy()
    out[ACT] = out[ACT].replace(mapping)

def drop_technical(df, technical=TECHNICAL_EVENTS):
    return df[~df[ACT].isin(technical)].copy()


def order_by_source_sequence(df, seq_col="source_seq"):
    """Real repair: order events inside each case by the source-system sequence number."""
    return df.sort_values([CASE, seq_col], kind="stable").reset_index(drop=True)


def whatif_decision_before_notify(df):
    """Aggregate-only stand-in for the repair above (the variant tables carry no sequence numbers).
    Swaps adjacent Notify,Decision pairs. This ASSUMES every reversal is an ingestion-time artifact,
    which is confirmed for only 11 of 70 June-July cases, so the result is an upper bound."""
    out = df.sort_values([CASE, TS], kind="stable").reset_index(drop=True)
    acts = out[ACT].tolist()
    cases = out[CASE].tolist()
    for i in range(len(acts) - 1):
        if cases[i] == cases[i + 1] and acts[i] == "Notify" and acts[i + 1] == "Decision":
            acts[i], acts[i + 1] = acts[i + 1], acts[i]
    out[ACT] = acts
    return out

# ------------------------------------------------------------ 4. diagnostics
def dfg_table(df, top=12):
    dfg, start_acts, end_acts = pm4py.discover_dfg(df)
    rows = sorted(dfg.items(), key=lambda kv: -kv[1])[:top]
    return pd.DataFrame([(a, b, n) for (a, b), n in rows], columns=["from", "to", "count"]), start_acts, end_acts


def alignment_report(df, model):
    net, im, fm = model
    diagnostics = pm4py.conformance_diagnostics_alignments(df, net, im, fm)
    fitness = pm4py.fitness_alignments(df, net, im, fm)
    log_moves, model_moves = Counter(), Counter()
    deviating_traces = 0
    for diag in diagnostics:
        deviates = False
        for log_step, model_step in diag["alignment"]:
            if log_step != SKIP and model_step == SKIP:
                log_moves[log_step] += 1
                deviates = True
            elif log_step == SKIP and model_step is not None:   # None = silent (tau) transition
                model_moves[model_step] += 1
                deviates = True
        deviating_traces += deviates
    n = len(diagnostics)
    return {
        "cases": n,
        "fitting_traces_%": round(100.0 * (n - deviating_traces) / n, 1),
        "pm4py_percFitTraces": round(fitness["percFitTraces"], 1),
        "avg_trace_fitness": round(fitness["averageFitness"], 3),
        "log_fitness": round(fitness["log_fitness"], 3),
        "mean_deviating_moves": round((sum(log_moves.values()) + sum(model_moves.values())) / n, 2),
        "moves_on_log": dict(log_moves.most_common()),
        "visible_moves_on_model": dict(model_moves.most_common()),
    }


def data_aware_check(df, flag_col="case:high_value"):
    """What control flow cannot do: sign-off mandatory above EUR 50,000 and not expected below it."""
    if flag_col not in df.columns:
        print(f"\n[data-aware check skipped: '{flag_col}' is not in the variant aggregates]")
        return None
    high = df[df[flag_col].astype(bool)]
    rest = df[~df[flag_col].astype(bool)]
    return {"high_value_vs_mandatory_signoff": alignment_report(high, MODELS["mandatory_signoff_all_cases"]),
            "other_cases_vs_normative": alignment_report(rest, MODELS["normative"])}

## 7. Provisional conclusion

**Primary explanation.** The measured collapse is mainly a measurement and model-maintenance failure, not a behavioral one. In June-July three recording changes stack: the `Classify` to `Risk Screen` relabel, the inserted `Queue Routed` event, and ingestion-time ordering of `Decision` and `Notify`. Repairing them lifts reported fitness from 32% to 89% against a 93% baseline. In August-September a fourth, different mechanism appears: a real, policy-mandated `Supervisor Sign-off` that the frozen model rejects; allowing it lifts 66% to 86%. Confidence that these four mechanisms explain most of the drop: about 85%. Confidence in the exact shares: low, because the early staged percentages cannot be reproduced from the supplied variants and the repairs interact.

**Residual compliance concern.** A real problem may remain and is not yet measurable. Enhanced reviews without a recorded compliance check went from 0 of 180 to 25 of 170 and 30 of 270. `Manual Override` rose from 0 to 20 to 35 and always precedes standard review. Some reversed notifications may survive source ordering. Nobody has tested whether every claim above EUR 50,000 was signed off. I put the probability that at least one of these reflects material true noncompliance at 40-45%, and the probability that noncompliance caused the fitness collapse below 10%.

**Immediate actions.**
- IT: switch the conformance job to source sequence; publish a versioned label map and technical-event register; explain the 30 old-label cases, the 90 unrouted cases and the rise in missing resources; reconcile the report with the variant table.
- Process owners: issue model version 2 with sign-off bound to claim value, decide the normative status of `Manual Override`, and confirm in writing what `Risk Screen` does.
- Compliance: audit all 55 no-check cases against source records, sample overrides and unsigned high-value claims, and analyze by reviewer only after adjusting for case mix.

**What must not be claimed yet.** That staff became noncompliant. That the repaired 89% or 86% equals true compliance. That the optional sign-off model verifies the policy. That all reversed notifications are artifacts, since only 11 are corroborated. That stable appeals and incidents clear the missing checks. That `Manual Override` is technical noise.

## 8. Model-governance recommendation

1. **Model versioning.** Give every normative model a version, an owner, effective-from and effective-to dates, and a link to the policy it implements. Check each case against the version in force on its reference date. No policy goes live without an updated model or a recorded, time-limited waiver, and past results are never silently recomputed.
2. **Event-semantic contracts.** Identify activities by a stable code that is independent of UI display text. Any change to a label, emission point, lifecycle or granularity needs a versioned mapping entry and a business sign-off of semantic equivalence before release.
3. **Technical-event policy.** Keep a register that classifies every event type as business, technical or under review, with an owner. Report conformance with and without technical events, raise an alert on any unregistered event type, and never let IT alone filter a user action such as `Manual Override`.
4. **Timestamp provenance.** Store source event time, source sequence and ingestion time on every event, plus a flag for which one a job used. Order by source time and sequence with a documented tie-break, never use ingestion time for ordering or cycle-time metrics, and monitor the inversion rate between the two orderings.
5. **Data-aware constraints.** Encode attribute-dependent rules, such as sign-off above EUR 50,000 and resource authorizations, as explicit guards, stratified models or declarative rules that are tested next to control flow. Any model relaxation must report precision and list the violations it would newly accept; fitness alone never selects a model.
6. **Post-release validation.** After every UI, gateway, ETL or policy release, run a canary comparison against the prior period: activity vocabulary, DFG differences, events per case, missing-attribute rates, order inversions, fitness and precision, plus a small sample traced from source screen to log. Annotate or hold regulatory conformance reporting until that check is signed off.
