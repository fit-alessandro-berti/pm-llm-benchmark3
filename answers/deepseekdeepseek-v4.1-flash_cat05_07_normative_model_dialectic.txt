## 6. Revised Normative Architecture

**1. Revised control-flow model.** Use a route-selecting POWL after Register_Supplier:
- **Standard route:** Register_Supplier  (Sanctions_Check  Quality_Review  optional Request_More_Info loop)  XOR(Manual_Procurement_Approval  Activate_Supplier, Reject_Supplier).
- **Low-risk auto route:** Register_Supplier  Sanctions_Check  Auto_Approve  Activate_Supplier  Quality_Review.
- **Emergency/provisional route:** Register_Supplier  Sanctions_Check  Activate_Supplier  (Quality_Review  Manual_Procurement_Approval).
- **Pre-screen reject route:** Register_Supplier  Sanctions_Check  Reject_Supplier.
- **Common tail:** Notify_Requester  Close_Case.
- **RMI:** repeatable loop before decision/activation; exact interleaving with concurrent checks is approximated in POWL and enforced by log-skeleton/data rules.
- **Withdrawals:** separate route Register_Supplier  Withdraw_Supplier  Notify_Requester  Close_Case, with no activation.

**2. Data-aware eligibility/amount/time rules.** Put these in pandas/data checks or DECLARE/log-skeleton constraints:
- Sanctions_Check before Activate_Supplier for all routes.
- Manual_Procurement_Approval before Activate_Supplier for standard route.
- Quality_Review before Activate_Supplier for standard route.
- Auto_Approve only if risk = LOW, country = DE, group_approved = true, master_data_validated = true, and policy overlay active.
- Emergency route only if critical relief, written authority ID, effective window valid, spend  EUR 20,000 until retrospective approval, daily monitoring, and Quality_Review within two business days.
- Notification before Close_Case; require stable notification_id.
- Amount caps and time deltas checked with effective timestamps.

**3. Resource and conflict-of-interest rules.** Organizational controls plus DECLARE constraints:
- Requester  Manual_Procurement_Approver.
- Delegate identity and delegation evidence must be recorded.
- Quality reviewer and approver must disclose prohibited close relationships; if prohibited, approval invalid.
- Segregation-of-duties checks using authoritative actor aliases.

**4. Policy-overlay governance.** Maintain a policy-overlay table with authority, version, scope, effective start/end, control-flow effect, data conditions, monitoring, retrospective approval, and immutable effective/record timestamps. No informal normalization. Permanent low-risk auto-approval requires a formal CS-9 amendment.

**5. Scope rules.**
- **Rejected leads:** if only a pre-screen, use a separate intake model. If full onboarding, CS-9 checks apply.
- **Reactivations:** separate procedure: Register_Reactivation, Sanctions_Check, material-change/risk check, prior certification validity check, and manual approval if required.
- **Withdrawals:** no activation; notification and closure.

**Where each belongs.**
- **POWL:** control-flow order, concurrency, XOR choices, route selection, loops.
- **DECLARE/log-skeleton:** precedence, response, absence, and time-bounded constraints, e.g., Sanctions before Activate, Manual before Activate for standard, Notify before Close.
- **pandas/data checks:** risk, country, group, amount, date windows, time deltas, notification IDs, actor aliases, delegation, eligibility snapshots.
- **Organizational controls:** approvals, COI disclosure, emergency/pilot authority, retrospective approvals, monitoring, audit sign-off.

## 7. PM4Py Model and Data Proposal

The following code constructs a revised POWL. It does **not** enforce risk, date, amount, identity, delegation, or authority. Those must be enforced by the policy-overlay and data checks. The RMI loop is a defensible POWL approximation; exact interleaving with concurrent checks should be enforced as a DECLARE/log-skeleton constraint.

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator


def T(label):
    return Transition(label=label)


# Common start/end
register = T("Register_Supplier")
notify = T("Notify_Requester")
close = T("Close_Case")

# ---------------------------------------------------------------------
# Standard route:
# Register -> (Sanctions || Quality || RMI loop) -> XOR(Manual->Activate, Reject)
# ---------------------------------------------------------------------
std_sanctions = T("Sanctions_Check")
std_quality = T("Quality_Review")
std_rmi = T("Request_More_Info")
std_manual = T("Manual_Procurement_Approval")
std_activate = T("Activate_Supplier")
std_reject = T("Reject_Supplier")

# POWL approximation of repeatable Request_More_Info.
# LIMITATION: exact arbitrary interleaving with concurrent checks is not fully
# enforced here; use a DECLARE/log-skeleton rule for "no activation before
# requested evidence arrives."
std_rmi_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[std_rmi, SilentTransition()]
)

std_checks = StrictPartialOrder(
    nodes=[std_sanctions, std_quality, std_rmi_loop]
)

std_manual_activate = StrictPartialOrder(nodes=[std_manual, std_activate])
std_manual_activate.order.add_edge(std_manual, std_activate)

std_decision = OperatorPOWL(
    operator=Operator.XOR,
    children=[std_manual_activate, std_reject]
)

std_route = StrictPartialOrder(nodes=[std_checks, std_decision])
std_route.order.add_edge(std_checks, std_decision)

# ---------------------------------------------------------------------
# Low-risk auto-approval route:
# Register -> Sanctions -> Auto_Approve -> Activate -> Quality
# ---------------------------------------------------------------------
auto_sanctions = T("Sanctions_Check")
auto_approve = T("Auto_Approve")
auto_activate = T("Activate_Supplier")
auto_quality = T("Quality_Review")

auto_route = StrictPartialOrder(
    nodes=[auto_sanctions, auto_approve, auto_activate, auto_quality]
)
auto_route.order.add_edge(auto_sanctions, auto_approve)
auto_route.order.add_edge(auto_approve, auto_activate)
auto_route.order.add_edge(auto_activate, auto_quality)

# ---------------------------------------------------------------------
# Emergency/provisional route:
# Register -> Sanctions -> Activate -> (Quality || Manual)
# ---------------------------------------------------------------------
em_sanctions = T("Sanctions_Check")
em_activate = T("Activate_Supplier")
em_quality = T("Quality_Review")
em_manual = T("Manual_Procurement_Approval")

em_post_activate = StrictPartialOrder(nodes=[em_quality, em_manual])

em_route = StrictPartialOrder(nodes=[em_sanctions, em_activate, em_post_activate])
em_route.order.add_edge(em_sanctions, em_activate)
em_route.order.add_edge(em_activate, em_post_activate)

# ---------------------------------------------------------------------
# Pre-screen rejection route:
# Register -> Sanctions -> Reject
# ---------------------------------------------------------------------
ps_sanctions = T("Sanctions_Check")
ps_reject = T("Reject_Supplier")

ps_route = StrictPartialOrder(nodes=[ps_sanctions, ps_reject])
ps_route.order.add_edge(ps_sanctions, ps_reject)

# ---------------------------------------------------------------------
# Route choice and common tail
# ---------------------------------------------------------------------
route_choice = OperatorPOWL(
    operator=Operator.XOR,
    children=[std_route, auto_route, em_route, ps_route]
)

M_revised = StrictPartialOrder(nodes=[register, route_choice, notify, close])
M_revised.order.add_edge(register, route_choice)
M_revised.order.add_edge(route_choice, notify)
M_revised.order.add_edge(notify, close)

print(M_revised)
```

### Event/data-collection proposal

Collect and retain, at minimum:
- `case_id`, `activity`, `event_timestamp`, `record_timestamp`, `source_system`
- `source_record_id`, `transaction_id`, `immutable_event_hash`
- `actor_id`, `actor_alias`, `actor_role`, `delegation_id`, `delegation_evidence`
- `rule_version_id`, `policy_overlay_id`, `authority_id`, `authority_effective_start`, `authority_effective_end`
- `eligibility_snapshot_id`, `risk_level`, `country`, `group_id`, `group_approved`, `master_data_validated`
- `amount`, `currency`, `spend_cap`, `retrospective_approval_id`
- `notification_id`, `notification_channel`, `notification_status`, `notification_link_type`
- `quality_review_timestamp`, `manual_approval_timestamp`, `activation_timestamp`
- `conflict_disclosure_id`, `conflict_status`, `reviewer_approver_relationship`

Notification links must use stable `notification_id` rather than mutable text. Eligibility must be snapshotted at decision time, not reconstructed later. Emergency/pilot authority must be stored as immutable policy-overlay records with effective and record timestamps. Actor aliases and delegation evidence must be resolved through an authoritative identity table before separation-of-duties checks.
