
The adjacency list shows three recording paths into `alignment_moves`: `UI_release` changes `recorded_labels`, `event_gateway` injects a technical event, and `ETL_change` corrupts `recorded_order`. All three produce alignment moves without any change in `true_process`. The staged alignment results confirm this: label remap alone raises fitness from 32% to 58%, adding technical-event removal reaches 81%, and source ordering reaches 89%. The remaining moves come from `reviewer_behavior`, `unknown_true_bypass`, missing compliance records, and `Manual Override`. In August, `policy_change` creates a real change in `true_process` and `high_value_status`, but `normative_model` is not updated; consequently new alignment moves appear even with clean data. The optional sign-off candidate improves fitness but overgeneralizes by ignoring the high-value condition. `business_outcomes` are driven by `true_process`, not by `measured_fitness`; therefore stable approval/appeal rates cannot refute either the logging-artifact explanation or the possibility of noncompliance. They simply show that the measured fitness drop is not itself an outcome metric and that current incident detection is too incomplete to certify compliance. The central abductive conclusion is that the early conformance collapse is predominantly a data/model artifact, while a smaller real compliance risk remains unquantified.

Each phase isolates one mechanism. A raw conformance rerun would confound label changes, technical events, timestamp defects, model staleness, and possible noncompliance.

```python
from datetime import datetime, timedelta

import pm4py
from pm4py.objects.log.obj import EventLog, Trace, Event

# ----------------------------------------------------------------------
# Process trees
# ----------------------------------------------------------------------
NORMATIVE_TREE = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "'Decision', 'Notify' )"
)

CANDIDATE_TREE = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "X ( 'Supervisor Sign-off', tau ), "
    "'Decision', 'Notify' )"
)

# ----------------------------------------------------------------------
# Variant-frequency tables from the problem statement
# ----------------------------------------------------------------------
VARIANTS_APR_MAY = {
    "Receive,Classify,Standard Review,Decision,Notify": 380,
    "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,
    "Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify": 40,
}

VARIANTS_JUN_JUL = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 270,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 145,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,
    "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
    "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 20,
}

VARIANTS_AUG_SEP = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 210,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify": 150,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 90,
    "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify": 60,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 45,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 35,
}

# ----------------------------------------------------------------------
# Log construction helpers
# ----------------------------------------------------------------------
def parse_trace(trace_str):
    """Parse one trace string, returning an EventLog."""
    parsed = pm4py.parse_event_log_string(trace_str)
    if isinstance(parsed, EventLog):
        return parsed
    if isinstance(parsed, Trace):
        return EventLog([parsed])
    return EventLog([Trace(parsed)])


def expand_variants(variants, apply_source_order=False):
    """
    Build an EventLog from a {trace_string: count} dictionary.

    If apply_source_order is True, the trace is sorted by a reconstructed
    source-system sequence. In production this attribute must come from the
    source system, not from a heuristic swap.
    """
    log = EventLog()
    for vid, (trace_str, count) in enumerate(variants.items()):
        template_log = parse_trace(trace_str)
        for rep in range(count):
            for template_trace in template_log:
                trace = Trace()
                trace.attributes["concept:name"] = f"case_{vid}_{rep}"
                for pos, template_event in enumerate(template_trace):
                    event = Event(dict(template_event))
                    event["concept:name"] = template_event["concept:name"]
                    event["case:concept:name"] = trace.attributes["concept:name"]
                    event["time:timestamp"] = datetime(2026, 1, 1) + timedelta(hours=pos)
                    event["source_sequence_number"] = pos
                    trace.append(event)

                if apply_source_order:
                    acts = [e["concept:name"] for e in trace]
                    if "Decision" in acts and "Notify" in acts:
                        ni = acts.index("Notify")
                        di = acts.index("Decision")
                        if ni < di:
                            # Extracted order was Notify -> Decision.
                            # Source-system sequence had Decision -> Notify.
                            trace[ni]["source_sequence_number"] = di
                            trace[di]["source_sequence_number"] = ni
                            trace.sort(key=lambda e: e["source_sequence_number"])

                log.append(trace)
    return log


def normalize_log(log, label_map=None, remove_activities=None,
                  sort_by_source_sequence=False):
    """Transparent normalization pipeline."""
    label_map = label_map or {}
    remove_activities = set(remove_activities or [])
    normalized = EventLog()

    for trace in log:
        new_trace = Trace()
        new_trace.attributes.update(trace.attributes)

        for event in trace:
            new_event = Event(dict(event))
            if new_event["concept:name"] in label_map:
                new_event["concept:name"] = label_map[new_event["concept:name"]]
            if new_event["concept:name"] in remove_activities:
                continue
            new_trace.append(new_event)

        if sort_by_source_sequence:
            new_trace.sort(key=lambda e: e.get("source_sequence_number", 0))

        normalized.append(new_trace)

    return normalized

# ----------------------------------------------------------------------
# Build logs
# ----------------------------------------------------------------------

jun_raw = expand_variants(VARIANTS_JUN_JUL)

jun_label = normalize_log(jun_raw, label_map={"Risk Screen": "Classify"})
jun_label_noqr = normalize_log(
    jun_raw,
    label_map={"Risk Screen": "Classify"},
    remove_activities=["Queue Routed"],

jun_label_noqr_source = normalize_log(
    expand_variants(VARIANTS_JUN_JUL, apply_source_order=True),
    label_map={"Risk Screen": "Classify"},
    remove_activities=["Queue Routed"],

aug_norm = normalize_log(
    expand_variants(VARIANTS_AUG_SEP, apply_source_order=True),

    remove_activities=["Queue Routed"],
    sort_by_source_sequence=True,

# ----------------------------------------------------------------------

# ----------------------------------------------------------------------

candidate_tree = pm4py.parse_process_tree(CANDIDATE_TREE)
candidate_net, candidate_im, candidate_fm = pm4py.convert_to_petri_net(candidate_tree)

# ----------------------------------------------------------------------
# DFG discovery
# ----------------------------------------------------------------------
dfg_apr, start_apr, end_apr = pm4py.discover_dfg(apr_log)
dfg_jun, start_jun, end_jun = pm4py.discover_dfg(jun_raw)

print("Apr-May DFG:", dfg_apr)
print("Jun-Jul raw DFG:", dfg_jun)

# ----------------------------------------------------------------------
# Alignment diagnostics
# ----------------------------------------------------------------------
def alignment_report(name, log, petri_net, p_im, p_fm):
    aligned = pm4py.alignments(log, petri_net, p_im, p_fm)
    fitness = pm4py.fitness_alignment(aligned)

    try:
        precision_val = pm4py.precision_alignment(log, petri_net, p_im, p_fm)
        if isinstance(precision_val, dict):
            precision_val = precision_val.get("precision", precision_val)
    except Exception:
        precision_val = None

    fitted = fitness.get("percentage_of_fitting_traces", float("nan"))
    if fitted <= 1:
        fitted *= 100

    print(f"{name}")
    print(f"  fitting traces: {fitted:.1f}%")
    print(f"  log fitness: {fitness.get('log_fitness', float('nan')):.3f}")
    print(f"  precision: {precision_val}")
    print()


alignment_report("Apr-May raw vs normative", apr_log, net, im, fm)
alignment_report("Jun-Jul raw vs normative", jun_raw, net, im, fm)
alignment_report("Jun-Jul label map", jun_label, net, im, fm)
alignment_report("Jun-Jul label map + remove Queue Routed", jun_label_noqr, net, im, fm)
alignment_report("Jun-Jul label map + remove Queue Routed + source order", jun_label_noqr_source, net, im, fm)
alignment_report("Aug-Sep normalized vs normative", aug_norm, net, im, fm)
alignment_report("Aug-Sep normalized vs optional sign-off candidate", aug_norm, candidate_net, candidate_im, candidate_fm)

# ----------------------------------------------------------------------
# Caveats
# ----------------------------------------------------------------------
print("Caveats:")
print("1. The log was built from aggregate variant frequencies; it lacks real timestamps, resources, case attributes, and source-sequence values. Numbers will not exactly match the supplied alignment summaries.")
print("2. The optional sign-off model is control-flow only. It does not enforce the EUR 50,000 high-value condition, so it may show high fitness while allowing sign-off on low-value cases or missing mandatory sign-off on high-value cases.")
print("3. Source-sequence repair in this code is applied to all Decision/Notify reversals in the supplied traces, whereas in production it must be applied only when the source system provides trustworthy sequence numbers.")
print("4. Alignment fitness alone is insufficient; precision must be compared to detect overpermissive models.")
```

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a combination of logging and model artifacts, not a sudden wave of employee noncompliance. In June, three simultaneous technical changes transformed the recorded log without necessarily changing the underlying work: the UI label change from `Classify` to `Risk Screen`, the gateway’s new `Queue Routed` technical event, and the ETL switch to warehouse-ingestion time for `Decision` and `Notify`. The staged normalization results are strong evidence: label remapping alone raises fitness from 32% to 58%, removing `Queue Routed` raises it to 81%, and ordering by source sequence raises it to 89%. The 70 reversed `Notify`-before-`Decision` traces are largely timestamp artifacts; at least 11 verified screenshots show the decision occurred first.

The August–September residual is different. A real policy change added `Supervisor Sign-off` for high-value claims, but the normative model was not updated. An optional sign-off candidate raises normalized fit from 66% to 86%, confirming that model obsolescence is the main cause of the post-policy conformance gap. That candidate is nevertheless overpermissive: it allows sign-off on every case and cannot enforce the EUR 50,000 condition.

A separate real compliance concern cannot be dismissed. Twenty-five enhanced-review traces in June–July and thirty in August–September are missing a recorded compliance check, and `Manual Override` appears in 20 and 35 traces respectively. No reliable audit has established whether these are true bypasses, legitimate routing corrections, or extraction defects. Business outcomes are stable, but appeal rate and confirmed incidents are coarse and incomplete; they do not exonerate employees.

Confidence: 90% that label/technical/timestamp artifacts caused the early fitness collapse; 80% that model obsolescence explains most August–September sign-off deviations; 40–50% that a real compliance problem exists among the missing-check and `Manual Override` cases. Immediate actions: IT should implement a canonical event contract, filter technical events, and use source-sequence ordering; process owners should update the normative model with a data-aware sign-off constraint and maintain model versioning; compliance should audit all missing-check and `Manual Override` cases. It must not yet be claimed that employees are noncompliant, that the compliance problem is negligible, or that sign-off is being applied correctly to high-value claims.

## 8. Model-governance recommendation

1. Model versioning: tie every normative model version to a policy version and effective date; when a policy changes, the model must be reviewed and versioned before the policy goes live.
2. Event-semantic contracts: every logged activity must have a semantic contract linking the UI label, backend event code, trigger, and authorized users; a UI rename must not change the backend business event without a mapping and validation step.
3. Technical-event policy: store infrastructure events such as `Queue Routed` in a separate namespace or tag them as technical; exclude them from business conformance by default unless a business meaning is explicitly documented.
4. Timestamp provenance: record business event time, ingestion time, and source-system sequence for every event; conformance should order by business event time or source sequence, with ingestion time retained for diagnostics.
5. Data-aware constraints: control-flow-only models cannot enforce case-attribute conditions such as the EUR 50,000 sign-off threshold; use attribute-stratified conformance or guardrails to enforce data-dependent rules.
6. Post-release validation: before deploying UI, ETL, or interface changes, run shadow conformance on old and new logs using the same frozen model; explain every variant and fitness change before releasing the change.
