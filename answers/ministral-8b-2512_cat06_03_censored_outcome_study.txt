Here is a comprehensive design for the uncertainty-aware predictive process monitoring study, adhering strictly to the nine-section structure and addressing all specified challenges:

---

## 1. Target Definition
### Primary Target:
**Default within 90 days after activation (conditional on activation)**.
- **Prediction time**: First event after `Identity/KYC Check` (or earliest event if no KYC).
- **Horizon**: 90 days post-activation.
- **Unit of analysis**: Activated accounts (cases with `Account Activated` event).
- **Population**: All 48,000 applications started between 1 Jan 2024–31 Dec 2025.
- **Estimand**: Probability of default *among activated accounts*, given the observed prefix up to prediction time. This avoids conflating selection bias (e.g., rejected cases) with default risk.

### Alternative Target:
**Multi-state outcome for all applications** (default, withdrawn, transferred, still-open).
- **Question**: Predicts the *distribution* of outcomes across all paths, not just default. Requires competing-risk modeling (e.g., Fine-Gray) and addresses policy-specific selection effects. However, it assumes a counterfactual "default" for non-activated cases is not estimable from data.

---

## 2. Cohort Construction
### Inclusion/Exclusion Rules:
| Category               | Count | Status                          | Label Status                     |
|------------------------|-------|---------------------------------|----------------------------------|
| **Activated (labeled)** | 18,900 | Default=0/2,700                 | `default_90d` available           |
| **Activated (unlabeled)** | 3,600 | 90-day horizon not mature        | Right-censored at data extract    |
| **Rejected**           | 9,100 | Closed without activation       | No default possible               |
| **Withdrawn**          | 5,700 | Closed by applicant             | No default possible               |
| **Transferred**        | 2,900 | May reappear under new ID       | Missing or delayed outcome        |
| **Still-open**         | 5,100 | Active at extraction            | Right-censored at extraction     |
| **Total**              | 48,000 |                                 |                                  |

### Cohort Flow:
1. **Activated (labeled)**: 18,900 cases with `default_90d` (90-day horizon passed).
2. **Activated (unlabeled)**: 3,600 cases where 90-day horizon not yet mature (right-censored at 15 Feb 2026).
3. **Non-activated**:
   - Rejected/withdrawn/transferred: **No default possible** (competing outcomes).
   - Still-open: Right-censored at extraction (no default observed yet).

---

## 3. Censoring and Missing-Label Strategy
### Types of Missingness:
- **Ordinary right censoring**: Still-open cases (5,100) or activated cases (3,600) where 90-day horizon not mature.
- **Delayed labels**: Transferred cases (2,900) with partial linkage (60%).
- **Selection through activation**: Rejected/withdrawn cases (14,800) have no default outcome.
- **Permanently missing feeds**: Partner-originated activated accounts (subset of 21,600).

### Primary Strategy:
- **Survival analysis** (Kaplan-Meier or Cox) for activated cases, treating right-censored cases as time-to-event data.
- **Sensitivity analysis**: Impute missing outcomes for transferred cases using:
  - **Assumption 1**: Default rate = global average (2,700/21,600  12.5%).
  - **Assumption 2**: Default rate = rate among linked transfers (if linkage table available).

### Testable vs. Untestable Assumptions:
- **Testable**: Policy change (1 Jul 2025) can be evaluated via interaction terms.
- **Partially testable**: System migration (15 Oct 2025) affects event naming but not default risk (unless it alters credit decisions).
- **Untestable**: Counterfactual default risk for rejected cases (requires external data).

---

## 4. Prefix Extraction
### Rules:
- **Fixed-length prefix**: First 5 events after `Identity/KYC Check` (or earliest event if no KYC).
- **Time-based prefix**: Events up to 7 days after `Identity/KYC Check` (to avoid `documents_total` leakage).
- **Handling short cases**: If <5 events, pad with nulls or use last observed event.
- **Document loops**: Ignore repeated `documents_total` events within the same day.
- **Activity renaming**: Use `concept:name` as-is; no imputation for renamed events.

### PM4Py Implementation:

## 5. Process-Aware Features
### Categories:
1. **Control-flow**:
   - `has_document_loop`: Boolean if `documents_total` appears >1x in prefix.
   - `path_variants`: Count of unique activity sequences (from `pm4py.get_variants`).
2. **Timing**:
   - `kyc_to_decision_time`: Time from KYC to first `Credit Review` event.
   - `rework_count`: Number of `documents_total` events in prefix.
3. **Resource/Queue**:
   - `avg_employee_experience`: Mean experience of handlers for prefix events.
   - `queue_length`: Count of concurrent cases in `Credit Review` at event time.
4. **Cohort/Calendar**:
   - `policy_period`: Binary (pre/post 1 Jul 2025).
   - `migration_period`: Binary (pre/post 15 Oct 2025).

### Feature Sources:
- **Static**: `case:requested_amount`, `case:region`.
- **Prefix-derived**: All control-flow/timing features.
- **Reference data**: Employee experience (extracted at event time).

---

## 6. Leakage Audit
| Feature/Data Element       | Leakage/Bias Risk                          | Valid Availability Rule                          | Action  | Rationale                                                                 |
|----------------------------|--------------------------------------------|--------------------------------------------------|---------|---------------------------------------------------------------------------|
| `final_limit`              | Post-decision leakage                      | Only available after `Accept`/`Reject` event     | Drop    | Cannot be observed at prediction time.                                  |
| `decision_reason`         | Post-decision leakage                      | Only populated at/after `Accept`/`Reject`        | Drop    | Not available until after prediction time.                              |
| `collection_status`       | Future event leakage                       | Only populated after `Account Activated`         | Drop    | Default status is not known at prediction time.                          |
| Future events (`Contract Signed`) | Future leakage                          | Excluded via prefix extraction                    | Drop    | Prediction must use only pre-prediction events.                         |
| `documents_total`         | Same-day leakage                           | Only include events up to 7 days after KYC       | Repair  | Use `documents_total` only if uploaded before prediction time.           |
| Updated `risk_score`       | Dynamic leakage                            | Use risk score at the latest event before prediction | Repair  | Later updates may reflect future decisions.                               |
| Resource experience       | Static but misaligned                      | Extract experience at event time (not extraction) | Repair  | Experience may change between event and extraction.                      |
| `label_available_at`      | Label leakage                               | Only use labels for cases with `default_90d`     | Keep    | Critical for survival analysis.                                          |

---

## 7. Validation Design
### Temporal Split:
- **Train**: Applications started 1 Jan 2024–30 Jun 2025 (excluding policy change).
- **Validation**: 1 Jul 2025–31 Oct 2025 (post-policy change, pre-migration).
- **Test**: 1 Nov 2025–31 Dec 2025 (post-migration).

### Metrics:
- **Primary**: Integrated Brier score (accounts for censoring).
- **Secondary**:
  - Area under the ROC curve (AUC) for activated cases.
  - Calibration slope (ensures probability estimates are reliable).
  - Subgroup performance by `case:region` and `policy_period`.

### Why Not Random Split?
- Random splits ignore temporal dependencies and policy shifts. Temporal splits preserve temporal validity.

---

## 8. Limitations and Decision-Use Boundary
### Claims:
- **Can claim**: Predictive association between prefix events and default *among activated accounts*.
- **Cannot claim**:
  - Default risk for rejected/withdrawn cases (counterfactual).
  - Performance outside the observed policy window (e.g., post-1 Jul 2026).
  - Causal impact of credit decisions (requires experimental data).

### Deployment Risks:
1. **Policy changes**: New thresholds may alter selection/outcome relationships.
2. **System drift**: Migration (15 Oct 2025) may introduce unmodeled event patterns.
3. **Label delay**: Partner-originated accounts may have permanently missing outcomes.

---

## 9. PM4Py Implementation Skeleton
```python
import pandas as pd
import pm4py
from pm4py.objects.log.util import dataframe_utils
from pm4py.objects.conversion.log import converter as log_converter

# --- Data Loading and Preprocessing ---
def load_and_filter_data(filepath):
    df = pd.read_csv(filepath)
    df["time:timestamp"] = pd.to_datetime(df["time:timestamp"])
    return df

# --- Cohort Construction ---
def build_cohort(df, extract_date="2026-02-15"):
    cohort = df.copy()
    cohort["is_activated"] = cohort.groupby("case:concept:name")["concept:name"].transform(
        lambda x: "Account Activated" in x.values
    )
    cohort["label_available"] = cohort["default_90d"].notna()
    cohort["is_censored"] = (
        (cohort["label_available"] == False) &
        (cohort["time:timestamp"] <= pd.to_datetime(extract_date))
    )
    cohort["is_transferred"] = cohort["concept:name"] == "Transferred"
    return cohort

# --- Prefix Extraction ---
def extract_prefixes(cohort, prediction_time="2025-10-15"):
    log = pm4py.format_dataframe(
        cohort,
        case_id="case:concept:name",
        activity_key="concept:name",
        timestamp_key="time:timestamp"
    )
    filtered_log = [trace for trace in log if any(
        event["time:timestamp"] <= pd.to_datetime(prediction_time)
        and event["concept:name"] in ["Identity/KYC Check", "Credit Review"]
        for event in trace
    )]
    prefixes = pm4py.get_prefixes_from_log(filtered_log, variant_selection="first")
    return prefixes

# --- Feature Engineering ---
def extract_features(prefixes):
    features = []
    for prefix in prefixes:
        # Control-flow features
        has_loop = any(event["concept:name"] == "documents_total" for event in prefix) > 1
        # Timing features
        kyc_time = min(event["time:timestamp"] for event in prefix if event["concept:name"] == "Identity/KYC Check")
        decision_time = min(event["time:timestamp"] for event in prefix if event["concept:name"] == "Credit Review")
        time_diff = (decision_time - kyc_time).total_seconds() / 3600
        # Resource features (simplified)
        avg_experience = prefix["org:resource"].mean()  # Placeholder
        features.append({
            "has_document_loop": has_loop,
            "kyc_to_decision_time": time_diff,
            "avg_employee_experience": avg_experience,
            "case_id": prefix[0]["case:concept:name"]
        })
    return pd.DataFrame(features)

# --- Main Pipeline ---
if __name__ == "__main__":
    # Load data
    df = load_and_filter_data("applications_events.csv")
    cohort = build_cohort(df)

    # Extract prefixes (time-based)
    prefixes = extract_prefixes(cohort, prediction_time="2025-10-15")

    # Feature extraction
    features = extract_features(prefixes)
    print("Feature table shape:", features.shape)

    # Cohort summary
    print("\nCohort summary:")
    print(cohort.groupby("is_activated").size())
    print(cohort.groupby("is_censored").size())

    # Leakage audit (example check)
    print("\nLeakage audit:")
    print("Final_limit available before prediction:", cohort[
        (cohort["time:timestamp"] <= pd.to_datetime("2025-10-15")) &
        cohort["final_limit"].notna()
    ].shape[0])
```

---
### Key Assumptions:
1. **Prediction time** is defined as the first event after KYC (or earliest event if no KYC).
2. **Censoring** is handled via survival analysis; missing outcomes are not imputed.
3. **Leakage** is mitigated by strict prefix extraction and feature validation.

This design avoids misleading outcome estimates by explicitly modeling selective observation and censoring, while providing a PM4Py-compatible pipeline for implementation.
