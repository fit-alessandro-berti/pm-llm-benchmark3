# 1. Assumptions and notation

**Notation.** Times are on 2026-05-12. For calculation, minutes from 08:00: \(t_{08:00}=0,\ldots,t_{14:00}=360\). Station sojourn = queue wait + active service. Case sojourn (completed) = S2 end  external arrival. WIP = cases that have arrived and not yet finished S2 (or still in system at 14:00). Station WIP counts cases in that station’s queue or in service.

**A1 (event-order convention).** At a common rounded timestamp, on the same resource an end is ordered before a subsequent start. Across stations, S1 end precedes S2 queue entry for that case. Simultaneous rounded events that are not constrained by the same resource are ordered by logical process flow (arrival  S1 start  S1 end  S2 start  S2 end). For WIP step functions, at an exact tied minute we apply departures/completions before new service starts, then external arrivals (conservative instantaneous WIP).

**A2 (rounding).** Every reported timestamp \(t\) stands for an actual instant in \([t-2.5,t+2.5]\) minutes. A difference of two independent rounded times therefore has an additional discretization uncertainty of roughly \(\pm 5\) minutes; we treat reported 5-minute grids as the working data and state rounding as a sensitivity band, not as a second full imputation layer in every cell.

**A3 (capacity).** S1 has two single-task resources I1, I2; S2 has C1, C2. A resource does not intentionally execute two cases at once. C2 is unavailable for maintenance \([10:55,11:10]\) (minutes \(175\)–\(190\)). Apparent overlaps are attributed to rounding, missing starts, or logging delay (A2/A5), not to extra hidden servers unless forced by the data.

**A4 (no bypass).** Every case must visit S1 then S2. Blank S2 with completed S1  in S2 queue at 14:00. Blank S1  in S1 queue at 14:00. OPEN  activity started, not finished by 14:00; elapsed service is a lower bound on final service.

**A5 (missing start imputation).** For `MISSING` starts we do **not** substitute a single silent value. Feasible start interval =
\[
[\max(t_{\text{queue entry}}, t_{\text{prev end on same resource}}, t_{\text{resource available}}),\ t_{\text{recorded end}}],
\]
with service \(>0\) (strictly, at least one rounding grain in spirit).  
- **Optimistic (short wait / long service where applicable):** start as early as the lower bound.  
- **Pessimistic (long wait / short service):** start as late as possible while keeping service \(\ge 5\) min (one reported tick) when a zero-length service is implausible.  
- **Central:** early start at resource-free instant (FCFS-friendly, maximum use of idle gap after previous case), which matches “resource takes next waiting case when free.”

**A6 (OPEN / right censoring).** Elapsed service \(= 14:00 - t_{\text{start}}\) is a lower bound; final service \(\ge\) elapsed. Wait for OPEN S2 is fully observed (start known). Cases still waiting have wait-so-far \(= 14:00 - t_{\text{queue entry}}\) as a lower bound on final wait.

**A7 (queue entry).** S1 queue entry = external `arrival_s1`. S2 queue entry = `s1_end` (known for all cases that reached S2 or wait for S2).

**A8 (analysis window).** Metrics are over \([08:00,14:00]\) unless a subperiod is named. Utilization denominators use resource presence in the window (C2 presence excludes the 15 min outage). Arrivals after 08:00 and unfinished work at 14:00 are retained (no deletion of open cases).

**A9 (Little’s Law).** \(L \approx \lambda W\) is checked only on subintervals where arrivals are roughly regular, no major capacity shock dominates, and censoring is light enough that mean WIP and mean sojourn refer to the same population. Early window \(08:00\)–\(10:00\) is the primary candidate; full-day LL is diagnostic only.

**A10 (aggregation).** Fully observed, unremarkable completed cases may be summarized in ranges in prose; P05, P07, P11, P15–P17, P21, P22 always appear explicitly.

# 2. Reconstruction method and formulas

**Case-level (station \(k \in \{S1,S2\}\))**

- Queue wait: \(W_{i,k} = t^{\text{start}}_{i,k} - t^{\text{entry}}_{i,k}\) (range if start missing; lower bound if still waiting).
- Active service: \(S_{i,k} = t^{\text{end}}_{i,k} - t^{\text{start}}_{i,k}\) (range if start missing; \(\ge\) elapsed if OPEN).
- Station sojourn: \(T_{i,k} = W_{i,k} + S_{i,k} = t^{\text{end}}_{i,k} - t^{\text{entry}}_{i,k}\) (for finished station visits this is often exact even when start is missing!).
- Case sojourn (both stations completed): \(T_i = t^{S2\text{ end}}_i - t^{\text{arrival}}_i\).

**Important identity.** When only the start is missing but end and entry are known, station sojourn \(T_{i,k}\) is **point-identified**; uncertainty falls entirely on the wait/service split.

**WIP / queue length.** Discrete-event step functions on the 5-minute grid (and optional finer grid for ties):

- External arrival: +1 total WIP, +1 S1 queue.
- S1 start: 1 S1 queue, +1 S1 busy.
- S1 end: 1 S1 busy, +1 S2 queue.
- S2 start: 1 S2 queue, +1 S2 busy.
- S2 end: 1 S2 busy, 1 total WIP.

Missing starts: WIP paths are computed under optimistic / central / pessimistic start scenarios (A5). OPEN cases remain in busy state through 14:00.

**Rates.** Arrival rate \(\lambda\) in a subperiod = (external arrivals in period) / length. Departure (throughput) \(\mu_{\text{out}}\) = S2 completions in period / length. Station completion rates analogously.

**Resource busy time / utilization.** Busy time of resource \(r\) = measure of time intervals with an assigned case (using imputed starts under each scenario; OPEN contributes elapsed busy time to 14:00).  
\[
U_r = \frac{\text{busy time}}{\text{time available in window}}.
\]
C2 available time \(= 360 - 15 = 345\) min. Ranges span imputation scenarios; rounding adds ~few percent ambiguity (not double-counted as false precision).

**Lower / central / upper estimates**

| Quantity | Lower | Central | Upper |
|---|---|---|---|
| Wait with MISSING start | early start | start at resource-free time | late start (svc  5) |
| Service with MISSING start | late start | early/resource-free start | complementary to wait |
| OPEN service | elapsed | elapsed (reported as LB) | unbounded / not invented |
| Waiting at 14:00 | wait-so-far | wait-so-far (LB) | unbounded |
| Utilization | short busy (late starts + only elapsed OPEN) | central starts + elapsed OPEN | early starts + elapsed OPEN (still LB for OPEN) |

**PM4Py role.** Interval log for cases with usable start and end; `insert_case_service_waiting_time` / `insert_case_arrival_finish_rate` only on a **case-level projection of fully bounded complete cases** (labeled case-level, not station queue metrics). Station queue/WIP with missingness is computed in pandas (safer than forcing PM4Py case semantics onto station multi-resource queues).

# 5. Bottleneck and temporal interpretation

**Evidence (observations, not hypotheses)**

1. **S1 waits grow almost monotonically** with arrival epoch: from single-digit minutes (P01–P02) to ~100 min (P16–P21) and P22 still unstarted after 110 min. Both I1 and I2 show near-continuous assignment chains with only short gaps (often 5 min = one rounding tick).
2. **S2 waits are small early** (P01–P04: 5–15), then **rise**, with a clear disruption at the **C2 maintenance [10:55, 11:10]**: C2’s next start is P08 at 11:15; P08’s S2 wait is 55 min. Afterward S2 queue remains elevated (P10–P14 waits 45–65; P11 central wait 55).
3. **At 14:00:** S1 has 1 in service + 1 waiting; S2 has 2 in service + 4 waiting. Residual S2 queue (4) > residual S1 queue (1), but S1 had already imposed large upstream delays.
4. **Utilization** of all four resources is high (roughly 0.78–0.90 under central imputation). Neither station has large sustained idle after ~09:00 except C2’s planned outage.
5. **Throughput** of completed S2 cases (~2.3/h over the day) is well below morning arrival rate (7/h early), so **system WIP must rise**—and it does in the case list.

**Interpretation by period**

- **08:00–~10:00:** S1 is the primary binder. Two inspectors face a burst of arrivals; S2 still absorbs output with short queues. Bottleneck evidence: S1 wait formation while S2 wait remains low; both I-resources busy.
- **~10:55–11:30 (maintenance):** **Local S2 bottleneck shock.** C2 down 15 min while work continues to arrive from S1 (P07 ends 10:00, P08–P09 move). P08 waits until 11:15. This is capacity loss, not a change in S1.
- **Late morning–afternoon:** **Combination / shifting constraint.** S1 remains saturated (long waits, P22 unserved). S2 fails to clear: four cases waiting for S2 at 14:00 and two OPEN in S2. Downstream congestion is real; upstream S1 still limits feed rate but has already built a large S2 backlog earlier.

**Hypotheses (labeled)**

- **H1:** Without the C2 outage, P08’s S2 wait would shrink toward the residual C1/C2 contention level (~20–40 min rather than 55), but afternoon S2 queue would still form because arrival cumulative > dual-calibrator capacity at observed service times (~35–40 min mean service  raw capacity ~3/h vs sustained demand).
- **H2:** Apparent 5-minute gaps between consecutive assignments on the same resource are largely rounding/logging rather than true idle (A2/A3).
- **H3:** The process is **arrival-burst + dual dual-server saturation**, not a single static bottleneck; policy attention on only S1 or only S2 would miss the handoff pile-up after 11:00.

**Maintenance effect (summary).** Direct: 15 min C2 loss  0.4 job of mean S2 service. Indirect: re-sequences C2 work (P08 delayed), increases S2 queue variance, and contributes to later waits for P10+ (partially confounded with general load). Evidence is consistent with a visible but not sole driver of afternoon congestion.

# 6. Missingness, censoring, and sensitivity analysis

**Three imputation scenarios for the four MISSING starts**

| Scenario | Rule | P07 S1 start | P15 S1 start | P05 S2 start | P11 S2 start |
|---|---|---|---|---|---|
| Optimistic waits (O) | Earliest feasible (= central resource-free) | 85 (10:25) | 220 (11:40) | 105 (09:45) | 240 (12:00) |
| Central (C) | Same as O here (take work when free) | 85 | 220 | 105 | 240 |
| Pessimistic waits (P) | Latest with service 5 | 115 | 250 | 130 | 260 |

(If zero service were allowed, P would push starts to the recorded end; we reject that as operationally implausible.)

**OPEN / queue censoring (all scenarios)**  
P15 S2 service 30, P17 S2 5, P21 S1 30; P16/P18/P19/P20 S2 waits 85/50/35/15; P22 S1 wait 110. Final totals for these cases are **right-censored**—any mean sojourn including them needs survival-style bounds, not naive averages of completed only.

**What stays stable across O/C/P**

- Rank order of congestion: waits increase through the day at both stations.
- Completed-case sojourns P01–P14 (starts not required).
- Station sojourns for missing-start visits (P05 S2=50, P07 S1=75, P11 S2=80, P15 S1=125).
- Qualitative bottleneck path: S1-first, S2 shock at outage, combined saturation later.
- High utilization regime (all U remain 0.75).
- Existence of S2 backlog at 14:00 (4 waiting) and unfinished S1 (P21/P22).
- C2 outage impact direction.

**What moves with imputation**

- Wait/service **split** for P05/P07/P11/P15 (tens of minutes).
- Exact mean S1/S2 wait (±5–15 min on station averages).
- Precise busy-time (± up to ~30–40 min total across resources).
- Peak WIP timing by one event slot if late starts delay busy increments.
- Any LL numerical match in mid/late day (censorship dominates more than missing starts).

**Rounding sensitivity.** ±2.5 min per stamp  wait/service each ±~5 min; does not overturn hour-scale waits late in the day or util in the 0.8 region. Could create or remove 5-minute “idle gaps” on Gantt charts—hence A3 treats tiny gaps as non-informative.

**Little’s Law check (defensible interval)**  
Early window 08:00–10:00, central reconstruction:

- Rough mean system WIP \(L\) (time-average of cases arrived and not S2-finished): about **4.5–5.5** cases (arrivals 14, only 4 S2 completions, build-up to ~10 in system by 10:00; triangular-ish average ~5–6).
- Mean sojourn for cases that both arrived and completed S2 inside early window is a small select set (P01–P04 mostly); \(W\) full-system including those still present is not the same as completed-only \(W\). Using \(W \approx L/\lambda\) with \(\lambda=7\)/h gives \(W \approx 0.7–0.85\) h = 42–51 min, which matches **early completers** (P01–P04 sojourns 60–105 already stretching) only order-of-magnitude—**selection and non-steady state** violate LL.  
- Full-day: \(\lambda\approx 3.67\)/h, time-average \(L\) roughly 8–11 (22 arrivals, 14 exits, 8 residual  average inventory high). Implied \(W\approx L/\lambda \approx 2.2–3.0\) h, comparable to completed mean ~2.5 h and censored cases still longer—**directionally consistent** but not a precise steady-state validation. LL is used only as a sanity bound, not a calibrated estimator.

**Censoring bias warning.** Metrics from completed cases alone **understate** true mean sojourn and late waits (slow cases still open). Utilization from completed services alone **understates** busy time (OPEN elapsed must be included—as done above).

# 2) Feasible bounds for MISSING starts (resource chains)

# Known resource previous-end lower bounds (from data inspection / A5)
# Central = optimistic early = resource-free time
MISSING_BOUNDS = {
    # case, station: (lo_start, hi_start_inclusive_for_svc_ge_5, queue_entry, end, resource)
    ("P07","S1"): (T("09:25"), T("09:55"), T("08:45"), T("10:00"), "I1"),  # free after P05 09:25
    ("P15","S1"): (T("11:40"), T("12:10"), T("10:10"), T("12:15"), "I1"),  # free after P13 11:40
    ("P05","S2"): (T("09:45"), T("10:10"), T("09:25"), T("10:15"), "C1"),  # free after P03 09:45
    ("P11","S2"): (T("12:00"), T("12:20"), T("11:05"), T("12:25"), "C2"),  # free after P08 12:00
}

def minutes(td):
    if pd.isna(td):
        return np.nan
    return td.total_seconds() / 60.0

def scenario_starts(scenario="central"):
    """Return dict case-> {s1_start, s2_start} datetime with imputation."""
    s1s, s2s = {}, {}
    for _, r in raw.iterrows():
        c = r["case"]
        # S1 start
        if r["s1s_kind"] == "TIME":
            s1s[c] = r["s1s_ts"]
        elif r["s1s_kind"] == "MISSING":
            lo, hi, _, _, _ = MISSING_BOUNDS[(c, "S1")]
            s1s[c] = lo if scenario in ("central", "optimistic") else hi
        else:
            s1s[c] = pd.NaT
        # S2 start
        if r["s2s_kind"] == "TIME":
            s2s[c] = r["s2s_ts"]
        elif r["s2s_kind"] == "MISSING":
            lo, hi, _, _, _ = MISSING_BOUNDS[(c, "S2")]
            s2s[c] = lo if scenario in ("central", "optimistic") else hi
        else:
            s2s[c] = pd.NaT
    return s1s, s2s

# 3) Case-level metrics under scenarios
# ---------------------------------------------------------------------------
def case_table(scenario="central"):
    s1s, s2s = scenario_starts(scenario)
    recs = []
    for _, r in raw.iterrows():
        c = r["case"]
        arr = r["arr_ts"]
        s1_start = s1s[c]
        s1_end = r["s1e_ts"] if r["s1e_kind"] in ("TIME", "OPEN") else pd.NaT
        s1_open = r["s1e_kind"] == "OPEN"
        s2_start = s2s[c]
        s2_end = r["s2e_ts"] if r["s2e_kind"] in ("TIME", "OPEN") else pd.NaT
        s2_open = r["s2e_kind"] == "OPEN"

        def w_s(entry, start, end, open_end, waiting):
            if waiting:
                return minutes(WIN_END - entry), np.nan, True  # wait_so_far, svc na
            if pd.isna(start) and pd.isna(end):
                return np.nan, np.nan, False
            wait = minutes(start - entry) if not pd.isna(start) else np.nan
            if open_end:
                svc = minutes(WIN_END - start)  # elapsed LB
                return wait, svc, True
            svc = minutes(end - start) if not pd.isna(end) and not pd.isna(start) else np.nan
            return wait, svc, False

        s1_waiting = r["state_at_14_00"] == "WAITING_FOR_S1"
        s2_waiting = r["state_at_14_00"] == "WAITING_FOR_S2"

        w1, sv1, c1 = w_s(arr, s1_start, s1_end, s1_open, s1_waiting)
        entry_s2 = s1_end if not s1_open and not pd.isna(s1_end) else pd.NaT
        if s1_open or s1_waiting:
            w2, sv2, c2 = np.nan, np.nan, False
        else:
            w2, sv2, c2 = w_s(entry_s2, s2_start, s2_end, s2_open, s2_waiting)

        # sojourns
        s1_soj = minutes(s1_end - arr) if not pd.isna(s1_end) and not s1_open and not s1_waiting else (
            minutes(WIN_END - arr) if s1_open or s1_waiting else np.nan)
        if not pd.isna(s2_end) and r["s2e_kind"] == "TIME":
            case_soj = minutes(s2_end - arr)
        else:
            case_soj = np.nan

        recs.append(dict(
            case=c, scenario=scenario,
            S1_wait=w1, S1_svc=sv1, S1_svc_censored=c1 or s1_open,
            S2_wait=w2, S2_svc=sv2, S2_svc_censored=c2 or s2_open,
            S1_sojourn=s1_soj, case_sojourn_completed=case_soj,
            state=r["state_at_14_00"], flag=r["flag"],
            s1_resource=r["s1_resource"], s2_resource=r["s2_resource"],
            s1_start=s1_start, s1_end=s1_end if not s1_open else pd.NaT,
            s2_start=s2_start, s2_end=s2_end if not s2_open else pd.NaT,
            s1_open=s1_open, s2_open=s2_open,
        ))
    return pd.DataFrame(recs)

ct_c = case_table("central")

def busy_minutes(scenario="central"):
    s1s, s2s = scenario_starts(scenario)
    busy = {"I1": 0.0, "I2": 0.0, "C1": 0.0, "C2": 0.0}
    for _, r in raw.iterrows():
        c = r["case"]
        # S1
        if r["s1_resource"] in busy:
            st = s1s[c]
            if r["s1e_kind"] == "TIME":
                en = r["s1e_ts"]
            elif r["s1e_kind"] == "OPEN":
                en = WIN_END
            else:
                en = pd.NaT
            if not pd.isna(st) and not pd.isna(en) and en > st:
                busy[r["s1_resource"]] += minutes(en - st)
        # S2
        if r["s2_resource"] in busy:
            st = s2s[c]
            if r["s2e_kind"] == "TIME":
                en = r["s2e_ts"]
            elif r["s2e_kind"] == "OPEN":
                en = WIN_END
            else:
                en = pd.NaT
            if not pd.isna(st) and not pd.isna(en) and en > st:
                busy[r["s2_resource"]] += minutes(en - st)
    return busy

print("\n=== Resource busy minutes & utilization ===")
for sc in ("central", "pessimistic"):
    b = busy_minutes(sc)
    avail = {"I1": 360, "I2": 360, "C1": 360, "C2": 345}  # C2 minus outage
    print(f"Scenario {sc}:")
    for r in ["I1","I2","C1","C2"]:
        print(f"  {r}: busy={b[r]:.0f} min, U={b[r]/avail[r]:.2f}")

# 5) WIP over time (pandas step grid) — safer than PM4Py for station multi-resource
# Comment: pm4py.convert_log_to_time_intervals is oriented toward activity intervals
# in a case log; station-level multi-resource queues with MISSING starts, OPEN
# censoring, and a partial outage are more transparently handled by an explicit
# event calendar in pandas. We still build a PM4Py interval log below for the
# usable complete observations and demo case-level PM4Py helpers.
# ---------------------------------------------------------------------------
def wip_profile(scenario="central", freq="5min"):
    s1s, s2s = scenario_starts(scenario)
    events = []  # (time, delta_s1q, delta_s1b, delta_s2q, delta_s2b, delta_sys, label)
    for _, r in raw.iterrows():
        c = r["case"]
        arr = r["arr_ts"]
        events.append((arr, +1, 0, 0, 0, +1, f"{c}-arr"))
        st1 = s1s[c]
        if not pd.isna(st1):
            events.append((st1, -1, +1, 0, 0, 0, f"{c}-s1s"))
        if r["s1e_kind"] == "TIME":
            en1 = r["s1e_ts"]
            events.append((en1, 0, -1, +1, 0, 0, f"{c}-s1e"))
        elif r["s1e_kind"] == "OPEN":
            pass  # remains busy through end
        # S2
        st2 = s2s[c]
        if not pd.isna(st2):
            events.append((st2, 0, 0, -1, +1, 0, f"{c}-s2s"))
        if r["s2e_kind"] == "TIME":
            en2 = r["s2e_ts"]
            events.append((en2, 0, 0, 0, -1, -1, f"{c}-s2e"))
    # sort with A1 tie-break: completions/ends before starts before arrivals at same ts
    rank = {"s2e": 0, "s1e": 1, "s2s": 2, "s1s": 3, "arr": 4}
    def sort_key(e):
        lab = e[6].split("-")[-1]
        return (e[0], rank.get(lab, 5))
    events.sort(key=sort_key)

    # build step samples every 5 min
    grid = pd.date_range(BASE, WIN_END, freq=freq)
    s1q = s1b = s2q = s2b = sys = 0
    ei = 0
    rows_w = []
    for t in grid:
        while ei < len(events) and events[ei][0] <= t:
            _, d1q, d1b, d2q, d2b, dsys, _ = events[ei]
            s1q += d1q; s1b += d1b; s2q += d2q; s2b += d2b; sys += dsys
            ei += 1
        rows_w.append(dict(time=t, S1_queue=s1q, S1_busy=s1b, S1_wip=s1q+s1b,
                           S2_queue=s2q, S2_busy=s2b, S2_wip=s2q+s2b, SYS_wip=sys))
    return pd.DataFrame(rows_w)
