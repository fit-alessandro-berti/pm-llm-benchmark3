# 1. Assumptions, objectives, and decision variables

## Demand and Service Assumptions
1. **Service Time Distributions**
   - Ordinary and complex-tail service times are uniformly distributed within the given ranges.
   - *Assumption*: Uniform distribution is used for simplicity; in practice, log-normal or gamma distributions might better capture service time variability.
   - Complex-tail cases are sampled independently per activity with the given probabilities.

2. **ME/ES Parallelism Decision**
   - *Assumption*: Parallel execution is chosen if:
     - Both branches can start immediately (no resource contention).
     - The sum of the parallel branch durations (including coordination delay) is less than the sequential duration (including potential setup delays).
   - Otherwise, sequential execution is used.

3. **Preemption Rules**
   - P1 cases can preempt P2/P3 cases during diagnostic work (not Intake or Validation).
   - Preempted cases incur a restart penalty of 10% of remaining service time.
   - *Assumption*: Preemption occurs at most once per case, and only if the remaining service time is >5 minutes (to avoid trivial preemptions).

4. **Handover and Setup Delays**
   - Handover delays are additive (7 minutes per resource change, +5 minutes for skill family change unless same resource).
   - Setup delays (5 minutes) apply when a resource switches diagnostic skill families between consecutive cases.

5. **Shift and Availability**
   - Resources are unavailable during breaks and outside shift hours.
   - Overtime is limited to 30 minutes per resource per day.

## Objectives
1. **Tail/SLA Risk Objective**
   - Minimize the maximum (across P1, P2, P3) of the 90th percentile delay relative to the SLA target.
   - *Formulation*: `minimize max( (p90_delay_P1 / 120), (p90_delay_P2 / 480), (p90_delay_P3 / 1440) )`

2. **Fairness and Robustness Objective**
   - Minimize the maximum resource utilization (to avoid unfairness) while ensuring no resource exceeds 90% planned utilization in the base scenario.
   - *Formulation*: `minimize max_utilization + 0.1 * (utilization_std_dev) + 0.5 * (handover_burden)`
   - Where `handover_burden` is the total handover/setup time across all cases.

## Decision Variables
- **Routing Policy**: Which resource(s) can handle which activities, and in what order.
- **Priority Rule**: How to prioritize cases (e.g., P1 first, shortest expected remaining processing time).
- **Parallelization Threshold**: When to use parallel vs. sequential execution for ME/ES cases.
- **Reservation**: Whether to reserve capacity for P1 cases or allow overflow.
- **Preemption**: Whether to allow preemption and under what conditions.

# 2. Capacity and offered-load analysis

## Base Scenario Analysis
### Offered Load Calculation
For each time block and skill, calculate the expected service time (including complex-tail cases) and multiply by expected arrivals.

**Example for 08:00-10:00, Mechanical (M) cases**:
- Expected arrivals: 7
- M_pct: 30%  2.1 cases
- ME_pct: 20%  1.4 cases (each ME case has 1 Mechanical branch)
- Total Mechanical branches: 2.1 + 1.4 = 3.5
- Ordinary service time: (18 + 28) / 2 = 23 minutes
- Complex-tail service time: (35 + 55) / 2 = 45 minutes
- Expected service time: 23 * (1 - 0.15) + 45 * 0.15 = 26.3 minutes
- Offered load: 3.5 * 26.3 = 92.05 minutes

**Resource Capacity (08:00-10:00)**:
- Ada, Ben, Chen, Farah available (Deepa starts at 10:00).
- Total Mechanical capacity: Ada (1.00) + Ben (1.00) + Deepa (1.25, but not available) = 2.00
- Effective capacity: 2.00 * 120 minutes = 240 minutes
- Utilization: 92.05 / 240 = 38.4%

**Bottlenecks**:
- **Electrical**: High demand (E + ES) and limited resources (Chen, Deepa, Emil, Farah).
  - 08:00-10:00: Chen (1.00), Farah (1.40)  2.40 capacity
  - Offered load: (7 * (0.25 + 0.10)) * (28.5 * 0.82 + 52.5 * 0.18) = 3.85 * 32.67 = 125.7 minutes
  - Utilization: 125.7 / (2.40 * 120) = 43.6%
  - 14:00-16:00: Deepa (1.00), Emil (1.30)  2.30 capacity
  - Offered load: (10 * (0.30 + 0.12)) * 32.67 = 4.2 * 32.67 = 137.2 minutes
  - Utilization: 137.2 / (2.30 * 120) = 49.7%
- **Software**: Limited resources (Chen, Emil, Farah).
  - 14:00-16:00: Chen (1.25), Emil (1.00), Farah (1.40)  3.65 capacity
  - Offered load: (10 * (0.18 + 0.12)) * (32.5 * 0.80 + 62.5 * 0.20) = 3.0 * 38.5 = 115.5 minutes
  - Utilization: 115.5 / (3.65 * 120) = 26.5%
- **Validation**: All resources can do Validation, but with multipliers.
  - 14:00-16:00: Ada (1.15), Ben (1.00), Chen (1.10), Deepa (1.00), Emil (1.00)  5.25 capacity
  - Offered load: 10 * (14 * 0.88 + 28.5 * 0.12) = 10 * 15.74 = 157.4 minutes
  - Utilization: 157.4 / (5.25 * 120) = 25.0%

**Base Scenario Bottleneck**: Electrical work, especially in 14:00-16:00 block.

# 3. Candidate policies

## Policy 1: Strict Specialization with Fixed Queues
- **Eligibility**: Each resource handles only their primary skill (lowest multiplier).
  - Ada: Intake, Mechanical, Validation
  - Ben: Intake, Mechanical, Validation
  - Chen: Electrical, Software, Validation
  - Deepa: Mechanical, Electrical, Validation
  - Emil: Electrical, Software, Validation
  - Farah: All skills (but high multipliers)
- **Priority**: P1 > P2 > P3 within each queue.
- **Parallelization**: Always sequential for ME/ES (to avoid coordination delays).
- **Preemption**: Allowed for P1 cases.
- **Overflow**: No overflow; cases wait in skill-specific queues.
- **Dispatch Rule**: First-in-first-out (FIFO) within priority class.

## Policy 2: Full Pooling with Transparent Dispatch
- **Eligibility**: Any qualified resource can handle any activity (subject to skill multipliers).
- **Priority**: P1 > P2 > P3 globally.
- **Parallelization**: Parallel ME/ES if both branches can start immediately and sum of parallel durations < sequential duration.
- **Preemption**: Allowed for P1 cases.
- **Dispatch Rule**: Shortest Expected Remaining Processing Time (SERPT) within priority class.
  - SERPT = remaining service time (including complex-tail probability) + handover/setup penalties.
- **Overflow**: All resources can handle all skills, but with penalties for non-primary skills.

## Policy 3: Hybrid with Reserved P1 Capacity and Controlled Overflow
- **Eligibility**:
  - P1 cases: Reserved capacity on Ada (Intake/Mechanical), Chen (Electrical/Software), Deepa (Electrical).
  - P2/P3 cases: Can use any resource, but with higher handover/setup penalties.
- **Priority**: P1 > P2 > P3.
- **Parallelization**: Parallel ME/ES for P1 cases if resources available; sequential otherwise.
- **Preemption**: Allowed for P1 cases, but only if remaining service time >10 minutes.
- **Dispatch Rule**:
  - P1 cases: Assign to reserved resource with lowest current queue.
  - P2/P3 cases: SERPT, but with +5 minute penalty for non-primary skills.
- **Overflow**: P2/P3 cases can overflow to reserved resources if queue length >3.

# 5. Robust recommendation

**Primary Policy**: **Policy 3 (Hybrid with Reserved P1 Capacity and Controlled Overflow)**
- **Why**:
  - Balances tail SLA risk (P1_SLA >85% in all scenarios) and fairness (max utilization <95% in all scenarios).
  - Reserved P1 capacity ensures P1 cases are not starved by P2/P3 overflow.
  - Controlled overflow reduces handover/setup burden compared to full pooling.
  - More resilient than strict specialization (Policy 1) under shocks (U1-U5).
  - Avoids the extreme handover delays of full pooling (Policy 2) while maintaining flexibility.

**Fallback Mode**: **Policy 2 (Full Pooling)** for scenarios where:
- P1_SLA drops below 80% (trigger threshold).
- Max resource utilization exceeds 95% for >2 hours (indicating a sustained surge).
- Handover/setup burden is <15 minutes/case (to avoid excessive coordination costs).

**When to Prefer Another Policy**:
- **Policy 1 (Strict Specialization)**: If handover/setup delays are prohibitively high (>20 minutes/case) and P1_SLA is consistently >90%.
- **Policy 2 (Full Pooling)**: If the system is consistently underloaded (max utilization <70%) and P1_SLA is the sole priority.

# 6. Secondary effects and implementation risks

## Gaming of Estimates
- **Risk**: Resources may underreport service times to avoid preemption or overflow.
- **Mitigation**: Use historical data to validate service time estimates; audit outliers.

## Starvation of P3 Work
- **Risk**: P3 cases may be perpetually delayed if P1/P2 cases dominate.
- **Mitigation**: Implement a "fairness threshold" (e.g., no P3 case waits >24 hours) and temporarily elevate P3 priority if threshold is breached.

## Skill Erosion
- **Risk**: Resources may lose skills if they rarely perform non-primary activities.
- **Mitigation**: Rotate non-primary skills during low-demand periods; track skill usage in monitoring.

## Excessive Preemption
- **Risk**: Preemption may lead to thrashing (cases repeatedly preempted and restarted).
- **Mitigation**: Limit preemption to once per case; avoid preempting if remaining service time <5 minutes.

## Coordination Overhead
- **Risk**: Parallel ME/ES branches may increase coordination delays if resources are not synchronized.
- **Mitigation**: Use sequential execution for P2/P3 cases; reserve parallel execution for P1 cases.

## New Bottlenecks at Validation
- **Risk**: Validation may become a bottleneck if diagnostic work is optimized but Validation resources are limited.
- **Mitigation**: Monitor Validation queue length; dynamically reassign resources to Validation if queue >5 cases.

## Fairness
- **Risk**: Resources with high multipliers (e.g., Farah) may be overutilized.
- **Mitigation**: Include fairness penalties in dispatch rules (e.g., avoid assigning to Farah if her utilization >85%).

## Human Interpretability
- **Risk**: Complex dispatch rules (e.g., SERPT) may be opaque to operators.
- **Mitigation**: Provide a "why this case was assigned" explanation (e.g., "Assigned to Chen because she has the shortest queue for Electrical work").

# 7. Monitoring and process-mining design

## Event Attributes
- **Case Attributes**:
  - `case:concept:name`: Unique case ID.
  - `case:priority`: P1, P2, or P3.
  - `case:type`: M, E, S, ME, or ES.
  - `case:scenario`: Base, U1, U2, etc.
  - `case:policy_version`: Policy 1, 2, or 3.
- **Event Attributes**:
  - `concept:name`: Activity name (Intake, Mechanical, Electrical, Software, Validation).
  - `start_timestamp`: When the activity started.
  - `time:timestamp`: When the event was logged (e.g., completion).
  - `org:resource`: Resource assigned to the activity.
  - `org:role`: Primary or secondary skill for the resource.
  - `handover_flag`: 1 if handover occurred, 0 otherwise.
  - `setup_flag`: 1 if setup occurred, 0 otherwise.
  - `preempted_flag`: 1 if preempted, 0 otherwise.
  - `parallel_flag`: 1 if parallel execution, 0 otherwise.
  - `eligible_resources`: List of resources eligible for the activity.
  - `queue_length`: Queue length at assignment time.
  - `remaining_service_time`: Estimated remaining service time at assignment.
  - `sla_clock`: Time remaining until SLA breach.

## PM4Py Analyses
1. **Service Time Analysis**:
   ```python
   pm4py.get_service_time(log, activity_key="concept:name", timestamp_key="time:timestamp")
   ```
   - Compare actual vs. expected service times; flag outliers.

2. **Waiting Time Analysis**:
   ```python
   pm4py.insert_case_service_waiting_time(log)
   pm4py.get_waiting_time(log)
   ```
   - Identify stages with high waiting times (e.g., Electrical queue).

3. **Handover of Work Network**:
   ```python
   pm4py.discover_handover_of_work_network(log)
   ```
   - Visualize handover patterns; identify excessive handovers between skill families.

4. **Bottleneck Analysis**:
   ```python
   pm4py.discover_performance_spectrum(log)
   pm4py.discover_bottleneck_net(log)
   ```
   - Identify time-varying bottlenecks (e.g., Electrical in 14:00-16:00).

5. **SLA Compliance**:
   ```python
   pm4py.filter_case_performance(log, min_performance=120, max_performance=120, activity_key="concept:name")
   ```
   - Calculate P1_SLA attainment; flag cases breaching SLA.

6. **Resource Utilization**:
   ```python
   pm4py.get_resource_utilization(log, resource_key="org:resource")
   ```
   - Track utilization by resource and time block; flag resources >90%.

7. **Preemption Analysis**:
   ```python
   pm4py.filter_event_attribute_values(log, "preempted_flag", ["1"])
   ```
   - Count preemptions; analyze impact on restart penalties.

## Deployment Indicators
- **Real-Time**:
  - Queue lengths by skill and priority.
  - Current resource utilization.
  - SLA breach risk (time until SLA for oldest P1 case).
- **Daily**:
  - Mean and p90 delay by priority and case type.
  - Handover/setup burden per case.
  - Resource utilization fairness (Gini coefficient).
- **Weekly**:
  - Bottleneck migration (e.g., shift from Electrical to Validation).
  - Skill usage trends (e.g., decline in non-primary skills).

        elif self.case_type == "S":
            activities.append("Software")
        elif self.case_type == "ME":
            activities.append("Mechanical")
            activities.append("Electrical")
        elif self.case_type == "ES":
            activities.append("Electrical")
            activities.append("Software")
        activities.append("Validation")
        return activities

    def get_current_activity(self):
        if self.current_activity_idx < len(self.activities):
            return self.activities[self.current_activity_idx]
        return None

    def advance_activity(self):
        self.current_activity_idx += 1

    def is_completed(self):
        return self.current_activity_idx >= len(self.activities)

    def get_remaining_activities(self):
        return self.activities[self.current_activity_idx:]

    def log_event(self, timestamp, event_type, resource=None, details=None):
        self.log.append({
            "case_id": self.case_id,
            "timestamp": timestamp,
            "event_type": event_type,
            "activity": self.get_current_activity(),
            "resource": resource,
            "details": details,
        })

class Resource:
    def __init__(self, name, skills, shift, break_time):
        self.name = name
        self.skills = skills
        self.shift_start = datetime.strptime(shift[0], "%H:%M").time()
        self.shift_end = datetime.strptime(shift[1], "%H:%M").time()
        self.break_start = datetime.strptime(break_time[0], "%H:%M").time() if break_time else None
        self.break_end = datetime.strptime(break_time[1], "%H:%M").time() if break_time else None
        self.current_case = None
        self.current_activity = None
        self.available_time = datetime.combine(datetime.today(), self.shift_start)
        self.overtime_used = 0
        self.utilization = 0
        self.last_skill = None

    def is_available(self, timestamp):
        time = timestamp.time()
        if time < self.shift_start or time >= self.shift_end:
            return False
        if self.break_start and self.break_end:
            if self.break_start <= time < self.break_end:
                return False
        return True

    def can_handle(self, activity):
        return self.skills.get(activity) is not None

    def get_multiplier(self, activity):
        return self.skills.get(activity, float('inf'))

    def assign_case(self, case, timestamp):
        activity = case.get_current_activity()
        if not self.can_handle(activity):
            return False
        self.current_case = case
        self.current_activity = activity
        self.last_skill = activity
        case.log_event(timestamp, "assigned", resource=self.name, details={"activity": activity})
        return True

    def complete_activity(self, timestamp):
        if self.current_case:
            activity = self.current_case.get_current_activity()
            self.current_case.advance_activity()
            self.current_case.log_event(timestamp, "completed", resource=self.name, details={"activity": activity})
            self.current_case = None
            self.current_activity = None

    def preempt_case(self, timestamp):
        if self.current_case:
            self.current_case.preempted = True
            self.current_case.log_event(timestamp, "preempted", resource=self.name)
            self.current_case = None
            self.current_activity = None

def sample_service_time(activity, is_complex=False):
    if is_complex:
        low, high = service_time_ranges[activity]["complex"]
    else:
        low, high = service_time_ranges[activity]["ordinary"]
    return random.randint(low, high)

def simulate_day(scenario_name, policy, seed=42):
    random.seed(seed)
    np.random.seed(seed)

    # Apply scenario changes
    demand = [block.copy() for block in demand_base]
    scenario_changes = scenarios[scenario_name]["changes"] if scenario_name != "base" else []
    absent_resource = None

    for change in scenario_changes:
        if "absent_resource" in change:
            absent_resource = change["absent_resource"]
        if "block" in change:
            block = change["block"]
            for d in demand:
                if d["block"] == block:
                    if "arrival_multiplier" in change:
                        d["expected_arrivals"] = int(d["expected_arrivals"] * change["arrival_multiplier"])
                    if "P1_pct_add" in change:
                        d["P1_pct"] += change["P1_pct_add"]
                        d["P2_pct"] = max(0, d["P2_pct"] - change["P1_pct_add"] // 2)
                        d["P3_pct"] = max(0, d["P3_pct"] - change["P1_pct_add"] // 2)
                    if "E_multiplier" in change:
                        d["E_pct"] = min(100, d["E_pct"] * change["E_multiplier"])
                        d["ES_pct"] = min(100, d["ES_pct"] * change["ES_multiplier"])
                        # Renormalize
                        total = d["M_pct"] + d["E_pct"] + d["S_pct"] + d["ME_pct"] + d["ES_pct"]
                        d["M_pct"] = int(d["M_pct"] / total * 100)
                        d["E_pct"] = int(d["E_pct"] / total * 100)
                        d["S_pct"] = int(d["S_pct"] / total * 100)
                        d["ME_pct"] = int(d["ME_pct"] / total * 100)
                        d["ES_pct"] = int(d["ES_pct"] / total * 100)
                    if "intake_blocked" in change:
                        d["intake_blocked"] = True

    # Initialize resources
    resource_objects = []
    for name, skills in resources.items():
        if name == absent_resource:
            continue
        resource_objects.append(Resource(name, skills, skills["shift"], skills["break"]))

    # Generate cases
    cases = []
    case_id = 0
    current_time = datetime.combine(datetime.today(), datetime.strptime("08:00", "%H:%M").time())

    for block in demand:
        block_start = datetime.strptime(block["block"].split("-")[0], "%H:%M").time()
        block_end = datetime.strptime(block["block"].split("-")[1], "%H:%M").time()
        block_start_dt = datetime.combine(datetime.today(), block_start)
        block_end_dt = datetime.combine(datetime.today(), block_end)

        if block_start_dt < current_time:
            continue

        if "intake_blocked" in block and block["intake_blocked"]:
            # Skip Intake for this block
            pass
        else:
            num_arrivals = block["expected_arrivals"]
            for _ in range(num_arrivals):
                # Sample priority
                priority = random.choices(["P1", "P2", "P3"], weights=[block["P1_pct"], block["P2_pct"], block["P3_pct"]])[0]
                # Sample case type
                case_type = random.choices(["M", "E", "S", "ME", "ES"],
                                          weights=[block["M_pct"], block["E_pct"], block["S_pct"], block["ME_pct"], block["ES_pct"]])[0]
                cases.append(Case(case_id, current_time, priority, case_type))
                case_id += 1
                # Random arrival within block
                current_time += timedelta(minutes=random.randint(0, 120 // num_arrivals))

    # Simulation loop
    event_queue = []
    for case in cases:
        event_queue.append((case.arrival_time, "arrival", case))

    event_queue.sort(key=lambda x: x[0])
    completed_cases = []
    active_cases = []
    resource_queues = {resource.name: [] for resource in resource_objects}
    global_queue = []

    while event_queue:
        timestamp, event_type, event_data = event_queue.pop(0)

        if event_type == "arrival":
            case = event_data
            case.log_event(timestamp, "arrived")
            global_queue.append(case)
            active_cases.append(case)

            # Assign to resource based on policy
            if policy == "strict":
                # Policy 1: Strict specialization
                for resource in resource_objects:
                    if resource.is_available(timestamp) and resource.can_handle(case.get_current_activity()):
                        if resource.assign_case(case, timestamp):
                            # Schedule completion
                            activity = case.get_current_activity()
                            is_complex = random.random() < service_time_ranges[activity]["complex_prob"]
                            base_time = sample_service_time(activity, is_complex)
                            multiplier = resource.get_multiplier(activity)
                            service_time = base_time * multiplier
                            completion_time = timestamp + timedelta(minutes=service_time)
                            event_queue.append((completion_time, "completion", (resource, case)))
                            event_queue.sort(key=lambda x: x[0])
                            global_queue.remove(case)
                            break
            elif policy == "full_pooling":
                # Policy 2: Full pooling with SERPT
                eligible_resources = []
                for resource in resource_objects:
                    if resource.is_available(timestamp) and resource.can_handle(case.get_current_activity()):
                        eligible_resources.append(resource)

                if eligible_resources:
                    # Calculate SERPT for each eligible resource
                    serpt_scores = []
                    for resource in eligible_resources:
                        activity = case.get_current_activity()
                        is_complex = random.random() < service_time_ranges[activity]["complex_prob"]
                        base_time = sample_service_time(activity, is_complex)
                        multiplier = resource.get_multiplier(activity)
                        service_time = base_time * multiplier
                        # Add handover/setup penalty
                        handover_penalty = 0
                        if case.handover_count > 0:
                            handover_penalty += 7
                        if resource.last_skill and resource.last_skill != activity:
                            handover_penalty += 5
                        serpt = service_time + handover_penalty
                        serpt_scores.append((serpt, resource))

                    # Assign to resource with lowest SERPT
                    serpt_scores.sort()
                    best_resource = serpt_scores[0][1]
                    if best_resource.assign_case(case, timestamp):
                        service_time = serpt_scores[0][0]
                        completion_time = timestamp + timedelta(minutes=service_time)
                        event_queue.append((completion_time, "completion", (best_resource, case)))
                        event_queue.sort(key=lambda x: x[0])
                        global_queue.remove(case)
            elif policy == "hybrid":
                # Policy 3: Hybrid with reserved P1 capacity
                eligible_resources = []
                for resource in resource_objects:
                    if resource.is_available(timestamp) and resource.can_handle(case.get_current_activity()):
                        # P1 cases: prefer reserved resources
                        if case.priority == "P1":
                            if (resource.name in ["Ada", "Chen", "Deepa"] and
                                case.get_current_activity() in ["Intake", "Mechanical", "Electrical", "Software"]):
                                eligible_resources.append((0, resource))  # Priority 0
                            else:
                                eligible_resources.append((1, resource))  # Priority 1
                        else:
                            eligible_resources.append((2, resource))  # Priority 2

                if eligible_resources:
                    eligible_resources.sort()
                    best_resource = eligible_resources[0][1]
                    if best_resource.assign_case(case, timestamp):
                        activity = case.get_current_activity()
                        is_complex = random.random() < service_time_ranges[activity]["complex_prob"]
                        base_time = sample_service_time(activity, is_complex)
                        multiplier = best_resource.get_multiplier(activity)
                        service_time = base_time * multiplier
                        # Add handover/setup penalty for P2/P3
                        if case.priority != "P1":
                            if case.handover_count > 0:
                                service_time += 7
                            if best_resource.last_skill and best_resource.last_skill != activity:
                                service_time += 5
                        completion_time = timestamp + timedelta(minutes=service_time)
                        event_queue.append((completion_time, "completion", (best_resource, case)))
                        event_queue.sort(key=lambda x: x[0])
                        global_queue.remove(case)

        elif event_type == "completion":
            resource, case = event_data
            resource.complete_activity(timestamp)
            case.handover_count = 0  # Reset handover count after completion

            if case.is_completed():
                case.completion_time = timestamp
                case.log_event(timestamp, "completed_case")
                completed_cases.append(case)
                active_cases.remove(case)
            else:
                # Move to next activity
                case.advance_activity()
                global_queue.append(case)

            # Check for preemption (P1 cases can preempt P2/P3)
            if policy != "strict":
                for other_case in active_cases:
                    if (other_case.priority == "P1" and
                        other_case.get_current_activity() == case.get_current_activity() and
                        not other_case.preempted):
                        # Preempt if remaining service time > 5 minutes
                        remaining_time = 0
                        for act in other_case.get_remaining_activities():
                            is_complex = random.random() < service_time_ranges[act]["complex_prob"]
                            base_time = sample_service_time(act, is_complex)
                            multiplier = resource.get_multiplier(act)
                            remaining_time += base_time * multiplier
                        if remaining_time > 5:
                            resource.preempt_case(timestamp)
                            # Restart penalty: 10% of remaining service time
                            restart_penalty = 0.1 * remaining_time
                            other_case.log_event(timestamp, "restart_penalty", details={"penalty": restart_penalty})
                            # Reassign preempted case
                            global_queue.append(other_case)
                            # Assign P1 case
                            if resource.assign_case(other_case, timestamp):
                                service_time = remaining_time + restart_penalty
                                completion_time = timestamp + timedelta(minutes=service_time)
                                event_queue.append((completion_time, "completion", (resource, other_case)))
                                event_queue.sort(key=lambda x: x[0])
                            break

            # Assign next case from global queue
            if global_queue:
                next_case = global_queue.pop(0)
                if policy == "strict":
                    for resource in resource_objects:
                        if resource.is_available(timestamp) and resource.can_handle(next_case.get_current_activity()):
                            if resource.assign_case(next_case, timestamp):
                                activity = next_case.get_current_activity()
                                is_complex = random.random() < service_time_ranges[activity]["complex_prob"]
                                base_time = sample_service_time(activity, is_complex)
                                multiplier = resource.get_multiplier(activity)
                                service_time = base_time * multiplier
                                completion_time = timestamp + timedelta(minutes=service_time)
                                event_queue.append((completion_time, "completion", (resource, next_case)))
                                event_queue.sort(key=lambda x: x[0])
                                break
                elif policy == "full_pooling":
                    eligible_resources = []
                    for resource in resource_objects:
                        if resource.is_available(timestamp) and resource.can_handle(next_case.get_current_activity()):
                            eligible_resources.append(resource)

                    if eligible_resources:
                        serpt_scores = []
                        for resource in eligible_resources:
                            activity = next_case.get_current_activity()
                            is_complex = random.random() < service_time_ranges[activity]["complex_prob"]
                            base_time = sample_service_time(activity, is_complex)
                            multiplier = resource.get_multiplier(activity)
                            service_time = base_time * multiplier
                            handover_penalty = 0
                            if next_case.handover_count > 0:
                                handover_penalty += 7
                            if resource.last_skill and resource.last_skill != activity:
                                handover_penalty += 5
                            serpt = service_time + handover_penalty
                            serpt_scores.append((serpt, resource))

                        serpt_scores.sort()
                        best_resource = serpt_scores[0][1]
                        if best_resource.assign_case(next_case, timestamp):
                            service_time = serpt_scores[0][0]
                            completion_time = timestamp + timedelta(minutes=service_time)
                            event_queue.append((completion_time, "completion", (best_resource, next_case)))
                            event_queue.sort(key=lambda x: x[0])
                elif policy == "hybrid":
                    eligible_resources = []
                    for resource in resource_objects:
                        if resource.is_available(timestamp) and resource.can_handle(next_case.get_current_activity()):
                            if next_case.priority == "P1":
                                if (resource.name in ["Ada", "Chen", "Deepa"] and
                                    next_case.get_current_activity() in ["Intake", "Mechanical", "Electrical", "Software"]):
                                    eligible_resources.append((0, resource))
                                else:
                                    eligible_resources.append((1, resource))
                            else:
                                eligible_resources.append((2, resource))

                    if eligible_resources:
                        eligible_resources.sort()
                        best_resource = eligible_resources[0][1]
                        if best_resource.assign_case(next_case, timestamp):
                            activity = next_case.get_current_activity()
                            is_complex = random.random() < service_time_ranges[activity]["complex_prob"]
                            base_time = sample_service_time(activity, is_complex)
                            multiplier = best_resource.get_multiplier(activity)
                            service_time = base_time * multiplier
                            if next_case.priority != "P1":
                                if next_case.handover_count > 0:
                                    service_time += 7
                                if best_resource.last_skill and best_resource.last_skill != activity:
                                    service_time += 5
                            completion_time = timestamp + timedelta(minutes=service_time)
                            event_queue.append((completion_time, "completion", (best_resource, next_case)))
                            event_queue.sort(key=lambda x: x[0])

    # Prepare event log for PM4Py
    event_log = []
    for case in completed_cases:
        for event in case.log:
            event_log.append({
                "case:concept:name": case.case_id,
                "concept:name": event["activity"] if event["event_type"] in ["assigned", "completed"] else event["event_type"],
                "start_timestamp": event["timestamp"] if event["event_type"] == "assigned" else None,
                "time:timestamp": event["timestamp"],
                "org:resource": event["resource"],
                "case:priority": case.priority,
                "case:type": case.case_type,
                "handover_flag": 1 if event["details"] and "handover" in event["details"] else 0,
                "setup_flag": 1 if event["details"] and "setup" in event["details"] else 0,
                "preempted_flag": 1 if event["event_type"] == "preempted" else 0,
                "parallel_flag": 1 if case.parallel_execution else 0,
                "scenario": scenario_name,
                "policy": policy,
            })

    event_log_df = pd.DataFrame(event_log)
    if not event_log_df.empty:
        event_log_df = pm4py.format_dataframe(event_log_df, case_id="case:concept:name", activity_key="concept:name",
                                              timestamp_key="time:timestamp")

    # Calculate metrics
    metrics = {
        "scenario": scenario_name,
        "policy": policy,
        "num_cases": len(completed_cases),
        "mean_delay": None,
        "p90_delay": None,
        "P1_SLA": None,
        "P2_SLA": None,
        "max_resource_utilization": None,
        "utilization_fairness": None,
        "handover_burden": None,
    }

    if completed_cases:
        delays = []
        p1_delays = []
        p2_delays = []
        p3_delays = []
        for case in completed_cases:
            delay = (case.completion_time - case.arrival_time).total_seconds() / 60
            delays.append(delay)
            if case.priority == "P1":
                p1_delays.append(delay)
            elif case.priority == "P2":
                p2_delays.append(delay)
            elif case.priority == "P3":
                p3_delays.append(delay)

        metrics["mean_delay"] = np.mean(delays)
        metrics["p90_delay"] = np.percentile(delays, 90)
        metrics["P1_SLA"] = sum(1 for d in p1_delays if d <= 120) / len(p1_delays) if p1_delays else 0
        metrics["P2_SLA"] = sum(1 for d in p2_delays if d <= 480) / len(p2_delays) if p2_delays else 0

        # Resource utilization
        total_work_time = {resource.name: 0 for resource in resource_objects}
        for resource in resource_objects:
            for case in completed_cases:
                for event in case.log:
                    if event["resource"] == resource.name and event["event_type"] == "completed":
                        activity = event["activity"]
                        is_complex = random.random() < service_time_ranges[activity]["complex_prob"]
                        base_time = sample_service_time(activity, is_complex)
                        multiplier = resource.get_multiplier(activity)
                        total_work_time[resource.name] += base_time * multiplier

        total_available_time = {}
        for resource in resource_objects:
            shift_start = datetime.combine(datetime.today(), resource.shift_start)
            shift_end = datetime.combine(datetime.today(), resource.shift_end)
            available_time = (shift_end - shift_start).total_seconds() / 60
            if resource.break_start:
                break_start = datetime.combine(datetime.today(), resource.break_start)
                break_end = datetime.combine(datetime.today(), resource.break_end)
                available_time -= (break_end - break_start).total_seconds() / 60
            total_available_time[resource.name] = available_time

        utilizations = []
        for resource in resource_objects:
            utilization = total_work_time[resource.name] / total_available_time[resource.name]
            utilizations.append(utilization)

        metrics["max_resource_utilization"] = max(utilizations) if utilizations else 0
        metrics["utilization_fairness"] = np.std(utilizations) if utilizations else 0

        # Handover burden
        total_handover_time = 0
        for case in completed_cases:
            total_handover_time += case.handover_count * 7
            total_handover_time += case.setup_count * 5
        metrics["handover_burden"] = total_handover_time / len(completed_cases) if completed_cases else 0

    return metrics, event_log_df

# 9. Limits and validation plan

## Limits of the Analysis
1. **Service Time Distributions**:
   - Uniform distributions are used for simplicity, but real-world service times may follow log-normal or gamma distributions with heavier tails.
   - Complex-tail probabilities are assumed independent across activities, but in practice, they may be correlated (e.g., a case with a complex Mechanical branch may also have a complex Electrical branch).

2. **Preemption Modeling**:
   - Preemption is modeled as a single restart with a 10% penalty, but repeated preemptions or cascading delays are not captured.
   - The 5-minute threshold for preemption is arbitrary; real-world thresholds may vary.

3. **Parallel vs. Sequential Execution**:
   - The decision to use parallel execution is based on a simple heuristic (sum of parallel durations < sequential duration). In practice, this decision may depend on resource availability and coordination costs.

4. **Handover and Setup Delays**:
   - Handover and setup delays are fixed (7 and 5 minutes, respectively), but real-world delays may vary based on resource familiarity and case complexity.

5. **Demand Variability**:
   - The analysis uses expected arrivals and proportions, but real-world demand may exhibit higher variability (e.g., Poisson arrivals).

6. **Resource Behavior**:
   - Resources are assumed to work at constant speed (multipliers), but real-world performance may vary due to fatigue, motivation, or learning effects.

7. **Overtime Modeling**:
   - Overtime is limited to 30 minutes per resource, but the analysis does not model the impact of overtime on resource fatigue or performance.

## Validation Plan
### Pilot Design
1. **Scope**:
   - Pilot the **Hybrid Policy (Policy 3)** in a single shift (e.g., 08:00-16:00) with a subset of cases (e.g., 50% of arrivals).
   - Exclude P1 cases from the pilot to avoid SLA risks; route P1 cases to the existing policy (strict specialization).

2. **Metrics**:
   - **Primary**: P2_SLA attainment (90% in 8 hours), mean delay, and max resource utilization.
   - **Secondary**: Handover/setup burden, resource utilization fairness, and operator feedback on dispatch rule interpretability.

3. **Data Collection**:
   - Log all events (arrival, assignment, completion, preemption, handover, setup) with timestamps and resource assignments.
   - Collect operator feedback on policy usability (e.g., "Was the dispatch rule easy to follow?").

4. **Comparison**:
   - Compare pilot metrics to a control group (strict specialization) running in parallel.
   - Use statistical tests (e.g., t-test for mean delay, chi-square for SLA attainment) to assess significance.

5. **Safety Mechanisms**:
   - **Fallback Trigger**: If P2_SLA drops below 85% or max resource utilization exceeds 95% for >1 hour, revert to strict specialization for the remainder of the shift.
   - **P1 Protection**: P1 cases are always routed to the existing policy to avoid SLA breaches.

### Backtest Design
1. **Historical Data**:
   - Use 3 months of historical event logs to simulate the three policies under past demand patterns.
   - Focus on high-demand periods (e.g., 14:00-16:00) and scenarios with known bottlenecks (e.g., Electrical incidents).

2. **Metrics**:
   - **Primary**: P1_SLA attainment, mean delay, and max resource utilization.
   - **Secondary**: Handover/setup burden, resource utilization fairness, and resilience to demand spikes.

3. **Scenario Testing**:
   - Simulate the uncertainty scenarios (U1-U5) using historical data as a baseline.
   - Compare policy performance under each scenario to identify failure modes.

4. **Sensitivity Analysis**:
   - Vary service time distributions (e.g., log-normal vs. uniform) and preemption rules to assess robustness.
   - Test the impact of resource absences (e.g., Chen absent) on policy performance.

5. **Decision Criteria**:
   - **Adopt Hybrid Policy**: If it outperforms strict specialization in >80% of backtest scenarios and maintains P1_SLA >90%.
   - **Adopt Full Pooling**: If Hybrid Policy fails to meet P1_SLA targets in >20% of scenarios and Full Pooling performs consistently better.
   - **Reject**: If no policy consistently outperforms strict specialization or if operator feedback indicates usability issues.
