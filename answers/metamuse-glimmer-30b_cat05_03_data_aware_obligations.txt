## 1. Temporal Data Semantics
* State reconstruction is forward-fill per `case` ordered by `time:timestamp` then `event_index`. Blank cells mean “no update at this event”. A value is never copied backward in time.
* Final case attributes are not projected backward. The state used for an obligation is the latest known value **at the relevant event timestamp**.
* Event time = `time:timestamp`. Effective time = timestamp of the event that creates the update unless evidence explicitly states another effective time. Record time = timestamp of `Record_Exemption`. Evidence time = timestamp of the proof of approval, e.g. qualified signature timestamp.
* Equal timestamps are ordered by `event_index` as tie-breaker. For TX-311 event_index 3 precedes 4, so Enhanced_Review is evaluated before the jurisdiction change to DE at the same instant.
* Material change for R4 is amount increase >20% after the latest Standard_Review/Enhanced_Review. Decrease does not invalidate. Increase from unknown amount is not safely classifiable.
* Missing amount/risk/jurisdiction/customer type is never silently defaulted to low risk. Trigger cannot be established or excluded  INDETERMINATE per R6.

R6: if s.amount unknown  s.jurisdiction unknown  s.risk_level unknown  s.customer_type unknown and trigger depends on it  INDETERMINATE  
R7: order(e1,e2)  e1.time<e2.time  e1.time=e2.time  e1.event_index<e2.event_index

## 4. Ambiguities and Alternative Readings
* TX-302: If the late DB insert at 11:00 were taken as the approval time, exemption would be post-hoc and R1 would be NONCOMPLIANT. Strong signature timestamp 09:05 resolves it.
* TX-305: Using settlement amount 150000 as proxy for release amount would make R1 trigger and Enhanced_Review would satisfy it  COMPLIANT. Policy forbids copying final state backward and no immutable release payload exists, hence INDETERMINATE.
* TX-310: With a strict “displayed approval suffices” reading, EX-88 would be valid and case would be JUSTIFIED_EXCEPTION. With evidence-based reading per R5, approval not proven at trigger time  NONCOMPLIANT. Current evidence is contradictory  INDETERMINATE.
* TX-311: If same-timestamp ordering were ignored, jurisdiction DE could be taken as effective before Enhanced_Review, making R1 never triggered either way. With event_index tie-breaker, review precedes jurisdiction change, still no R1 at release. If material change were defined as any amount change, the 27.8% increase at 16:10 would require review after it, which holds.

## 5. PM4Py and pandas Checking Code
```python
import pandas as pd
import io
from pm4py import format_dataframe

csv = """case:concept:name,event_index,concept:name,time:timestamp,org:resource,amount,risk_level,jurisdiction,customer_type,exemption_id,note
TX-301,1,Create_Transaction,2026-04-06T08:00:00Z,ops01,80000,LOW,US,CORPORATE,,
TX-301,2,Standard_Review,2026-04-06T08:10:00Z,rev01,,,,,,reviewed current state
TX-301,3,Update_Amount,2026-04-06T08:20:00Z,ops01,125000,,,,,customer increased order
TX-301,4,Release_Funds,2026-04-06T08:25:00Z,rel01,,,,,,
...
"""
# full CSV as above
df = pd.read_csv(io.StringIO(csv))
df['time:timestamp'] = pd.to_datetime(df['time:timestamp'], utc=True)
df = format_dataframe(df, case_id='case:concept:name', activity_key='concept:name', timestamp_key='time:timestamp')
df = df.sort_values(['case:concept:name','time:timestamp','event_index'])

attrs = ['amount','risk_level','jurisdiction','customer_type']
for a in attrs:
    df[a] = df.groupby('case:concept:name')[a].ffill()

def latest_before(sub, act, t):
    ev = sub[(sub['concept:name']==act) & (sub['time:timestamp']<=t)]
    if ev.empty: return None
    return ev.sort_values(['time:timestamp','event_index']).iloc[-1]

diag = []
for case, g in df.groupby('case:concept:name'):
    g = g.sort_values(['time:timestamp','event_index'])
    rel = g[g['concept:name']=='Release_Funds']
    for _, r in rel.iterrows():
        state = {a: r[a] for a in attrs}
        latest_std = latest_before(g, 'Standard_Review', r['time:timestamp'])
        latest_enh = latest_before(g, 'Enhanced_Review', r['time:timestamp'])
        latest_app = latest_before(g, 'Compliance_Approve', r['time:timestamp'])
        latest_screen = latest_before(g, 'Sanctions_Screen', r['time:timestamp'])
        # material amount change
        amt_changes = g[(g['concept:name']=='Update_Amount') & (g['time:timestamp']<=r['time:timestamp'])]
        # flags
        r1_trigger = pd.notna(state['jurisdiction']) and pd.notna(state['amount']) and state['jurisdiction']!='DE' and state['amount']>=100000
        r2_trigger = (pd.notna(state['risk_level']) and state['risk_level']=='HIGH') or (pd.notna(state['customer_type']) and state['customer_type']=='PEP')
        diag.append({
            'case':case,
            'release_time':r['time:timestamp'],
            'amount':state['amount'],
            'jurisdiction':state['jurisdiction'],
            'risk_level':state['risk_level'],
            'customer_type':state['customer_type'],
            'r1_trigger':r1_trigger,
            'r2_trigger':r2_trigger,
            'latest_enhanced_review': latest_enh['time:timestamp'] if latest_enh is not None else None,
            'latest_compliance_approve': latest_app['time:timestamp'] if latest_app is not None else None,
            'amount_unknown': pd.isna(state['amount'])
        })
diag_df = pd.DataFrame(diag)
print(diag_df.head(20))
```
The code reconstructs state with forward fill, preserves event_index ordering, computes state at Release_Funds and tracks latest reviews. Control-flow DECLARE checks can be added, but data-dependent obligations such as amount thresholds and exemption validity require attribute state and evidence timestamps, which control-flow alone cannot capture.

## 6. Why Control-Flow-Only Conformance Is Insufficient
* Final-state leakage: copying final amount/risk/jurisdiction backward would falsely trigger or clear R1/R2.
* Post-hoc exemptions: a Release_Funds referencing EX-77/EX-88 with DB record after release looks compliant in control-flow but fails R5 evidence-time check.
* Material changes after review: control-flow sees Enhanced_Review before Release_Funds but misses >20% amount increase invalidating the review per R4.
* Conditional activation: R1/R2/R3 only activate on data values at release time; control-flow cannot evaluate thresholds.
* Missing data: blank amount leads to indeterminate trigger; control-flow would default to present/absent.
* Same-timestamp ordering: TX-311 jurisdiction change and review share timestamp; event_index determines whether R1 is triggered.

## 7. Recommended Logging and Control Improvements
* Immutable release payload with snapshot of amount, risk, jurisdiction, customer_type at Release_Funds.
* Effective time, record time and evidence time separate columns for every attribute update and exemption approval with qualified signature timestamp.
* Rule version tag on each event and exemption scope fields: jurisdiction list, customer_type, amount min/max.
* Change provenance: who/what triggered Update_Amount/Update_Jurisdiction/Risk_Reclassify with reason code.
* Stable total order: guarantee monotonic event_index per case or use Lamport clocks to avoid same-timestamp ambiguity.
* Exemption register write-ahead with approval signature before release; reject releases referencing exemptions not yet cryptographically proven.
