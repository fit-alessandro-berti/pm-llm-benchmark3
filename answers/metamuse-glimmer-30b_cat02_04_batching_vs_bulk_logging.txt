# 5. Robustness and alternative explanations

If resource IDs are trusted, G5 overlap is interpreted as concurrent multitasking. If treated as shared-account, the same pattern is a logging artifact and physical concurrency is unknown. Assumption: analyst_pool login is shared.

If timestamps are taken as exact, G7 shows perfect batch start/end. If timestamps are interval-censored by stated 15 min precision, start  [13:52:30,14:07:29] and complete  [14:07:30,14:22:29] under a down-round rule, so equality is spurious.

Three cases with multiple defensible explanations:
* G1 identical start/end: genuine fixture batch vs PLC scan-cycle batching that writes same timestamp for a group.
* G7 identical start/end: genuine batch vs coarse 15 min rounding; recorded_at staggered supports logging order.
* G3 identical end: bulk form submission vs common deadline causing synchronized completion reporting.

# 6. Data-collection redesign

1. Execution timestamps: capture start, pause/resume, complete at device level with wall-clock, not form submission time.
2. Recording timestamps: store separate recorded_at and execution timestamps; never overwrite.
3. Source clocks: NTP sync and log clock drift; record source identifier and precision metadata per event.
4. Resource/badge identity: enforce individual badge login; deprecate shared accounts; log workstation id.
5. Group/batch identifiers: explicit batch_id and item_position within fixture; do not infer from timestamp equality.
6. Workstation capacity: log fixture capacity and queue state to distinguish physical batching from logging batching.
7. Timestamp precision metadata: store actual resolution and rounding rule, not just documented precision.

# 7. Final adjudication

High confidence interpretation possible: G1 genuine simultaneous batch, G4 sequential serial work, G6 end-of-shift bulk submission. These can be used with documented caveats.

Should be interval-censored or excluded from queue analysis: G6 service is zero and waiting is submission delay; G7 timestamps are 15 min censored; G3 complete is bulk submission; G2 start is group start. Use bounds not point estimates.

Requires operational validation before performance conclusions: G5 shared analyst_pool needs individual identity validation; G8 queue build-up needs clock alignment between safety system and scanner and confirmation of capacity loss period.
