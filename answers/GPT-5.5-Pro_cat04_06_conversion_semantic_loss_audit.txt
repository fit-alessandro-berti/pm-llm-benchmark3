# 2. Candidate Conversion Pipelines

| Pipeline                                                                            | PM4Py calls                                                                                                                                                                                                                                         | Expected benefit                                                                                                                                                                                     | Expected risk                                                                                                                                                                                                                                                                  | Failure condition                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Primary: `POWL → accepting Petri net → BPMN → accepting Petri net`                  | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)`; `pm4py.convert_to_petri_net(bpmn_from_net)`                                                                                          | Uses the supported POWL-to-Petri conversion as the semantic bridge. Avoids inventing a direct POWL-to-BPMN API. Produces a BPMN visualization while retaining an accepting Petri net for validation. | BPMN may introduce gateways and silent routing nodes whose layout is visually misleading. A returned BPMN object does not prove that the partial order, optional skip, loop, and release join survived.                                                                        | Exception; returned `None`; missing initial/final marking on any accepting-net conversion; unsound net; workflow-net failure; positive witness rejected; negative witness accepted; bounded-language mismatch.                      |
| Secondary: `POWL → accepting Petri net → process tree → BPMN → accepting Petri net` | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)` inside `try/except`; if successful, `pm4py.convert_to_bpmn(tree_from_net)`; then `pm4py.convert_to_petri_net(bpmn_from_tree)` | If exact conversion succeeds, the BPMN may be more block-structured and easier to explain. Process trees also have explicit XOR, parallel, and loop operators.                                       | The source partial order is not obviously block-structured: `Prepare Evidence` gates verification, while `Legal Review` depends only on `Assess Risk` and is unordered with verification. A process tree may fail, serialize behavior, or approximate the N-shaped dependency. | `convert_to_process_tree(...)` raises an exception; tree is `None`; BPMN from tree fails; tree-derived BPMN loses either `Assess Risk`/`Prepare Evidence` order freedom or legal/verification order freedom; loop semantics change. |
| Diagnostic-only: `POWL → accepting Petri net`, no BPMN promotion                    | `pm4py.convert_to_petri_net(source_powl)`; diagnostics and witness tests on the net                                                                                                                                                                 | Establishes a compiled semantic baseline before any visualization step. Useful for regression tests and conformance execution.                                                                       | Not a stakeholder-friendly diagram. Petri-net structure may contain silent places/transitions that are hard to explain.                                                                                                                                                        | Missing markings; non-workflow net; unsoundness; witness mismatch against the intended invariants.                                                                                                                                  |

Primary pipeline choice: use `POWL → accepting Petri net → BPMN` as the stakeholder-visualization pipeline, but treat the generated BPMN as derivative and non-authoritative. The process-tree pipeline should be experimental/quarantined unless it passes the same validation suite.

# 3. Conversion Code

```python
import os
import traceback
from collections import Counter

import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator


# ---------------------------------------------------------------------
# 1. Authoritative source POWL definition
# ---------------------------------------------------------------------

register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(
    operator=Operator.XOR,
    children=[legal_review, skip_legal],
)

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[trial_body, correct_defect],
)

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[
        register,
        assess_risk,
        prepare_evidence,
        optional_legal,
        verification_loop,
        release_change,
        archive_change,
    ]
)

source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)


# ---------------------------------------------------------------------
# 2. Helpers
# ---------------------------------------------------------------------

OUT_DIR = "powl_conversion_audit_artifacts"
os.makedirs(OUT_DIR, exist_ok=True)


def out_path(filename: str) -> str:
    return os.path.join(OUT_DIR, filename)


def short_exception(exc: BaseException) -> str:
    return "".join(traceback.format_exception_only(type(exc), exc)).strip()


def require_accepting_net(name: str, conversion_result):
    """
    PM4Py accepting-net conversions should return (net, initial_marking, final_marking).
    Do not assume markings are present.
    """
    if not isinstance(conversion_result, tuple) or len(conversion_result) != 3:
        raise TypeError(
            f"{name} did not return a 3-tuple (net, im, fm); "
            f"got {type(conversion_result)!r}"
        )

    net, im, fm = conversion_result
    if net is None:
        raise ValueError(f"{name} returned net=None")
    if im is None:
        raise ValueError(f"{name} returned initial_marking=None")
    if fm is None:
        raise ValueError(f"{name} returned final_marking=None")

    return net, im, fm


def visible_label_counter(net) -> Counter:
    return Counter(
        t.label
        for t in getattr(net, "transitions", [])
        if getattr(t, "label", None) is not None
    )


def diagnose_accepting_net(name: str, net, im, fm) -> dict:
    """
    Run workflow-net and soundness diagnostics.
    Keep exceptions visible; do not silently convert them to success.
    """
    print(f"\n=== Diagnostics for {name} ===")
    diagnostics = {}

    try:
        diagnostics["visible_label_counts"] = dict(visible_label_counter(net))
        print("visible_label_counts:", diagnostics["visible_label_counts"])
    except Exception as exc:
        diagnostics["visible_label_counts_error"] = short_exception(exc)
        print("visible_label_counts_error:", diagnostics["visible_label_counts_error"])

    try:
        diagnostics["is_workflow_net"] = pm4py.check_is_workflow_net(net)
        print("is_workflow_net:", diagnostics["is_workflow_net"])
    except Exception as exc:
        diagnostics["is_workflow_net_error"] = short_exception(exc)
        print("is_workflow_net_error:", diagnostics["is_workflow_net_error"])

    try:
        diagnostics["soundness"] = pm4py.check_soundness(
            net, im, fm, print_diagnostics=True
        )
        print("soundness:", diagnostics["soundness"])
    except Exception as exc:
        diagnostics["soundness_error"] = short_exception(exc)
        print("soundness_error:", diagnostics["soundness_error"])

    return diagnostics


def safe_save(label: str, save_function, *args) -> None:
    """
    Visualization failures should be visible, but should not be confused with
    semantic conversion failures.
    """
    try:
        save_function(*args)
        print(f"saved {label}: {args[-1]}")
    except Exception as exc:
        print(f"visualization_save_failed[{label}]: {short_exception(exc)}")


# ---------------------------------------------------------------------
# 3. Save authoritative source visualization
# ---------------------------------------------------------------------

safe_save(
    "source_powl",
    pm4py.save_vis_powl,
    source_powl,
    out_path("01_source_powl.svg"),
)


# ---------------------------------------------------------------------
# 4. Pipeline 1: POWL -> accepting Petri net -> BPMN
# ---------------------------------------------------------------------

conversion_errors = {}
diagnostics = {}
accepting_nets = {}
bpmn_models = {}

net_from_powl, im_from_powl, fm_from_powl = require_accepting_net(
    "POWL -> accepting Petri net",
    pm4py.convert_to_petri_net(source_powl),
)

accepting_nets["net_from_powl"] = (net_from_powl, im_from_powl, fm_from_powl)
diagnostics["net_from_powl"] = diagnose_accepting_net(
    "net_from_powl", net_from_powl, im_from_powl, fm_from_powl
)

safe_save(
    "net_from_powl",
    pm4py.save_vis_petri_net,
    net_from_powl,
    im_from_powl,
    fm_from_powl,
    out_path("02_powl_to_petri_net.svg"),
)

try:
    bpmn_from_net = pm4py.convert_to_bpmn(
        net_from_powl, im_from_powl, fm_from_powl
    )
    if bpmn_from_net is None:
        raise ValueError("pm4py.convert_to_bpmn(net, im, fm) returned None")

    bpmn_models["bpmn_from_net"] = bpmn_from_net

    safe_save(
        "bpmn_from_net",
        pm4py.save_vis_bpmn,
        bpmn_from_net,
        out_path("03_powl_to_petri_to_bpmn.svg"),
    )
except Exception as exc:
    conversion_errors["petri_to_bpmn"] = short_exception(exc)
    print("conversion_failed[petri_to_bpmn]:", conversion_errors["petri_to_bpmn"])


# ---------------------------------------------------------------------
# 5. Pipeline 2: POWL -> Petri net -> process tree -> BPMN
#    This branch is allowed to fail. Failure is diagnostic information.
# ---------------------------------------------------------------------

tree_from_net = None
bpmn_from_tree = None

try:
    tree_from_net = pm4py.convert_to_process_tree(
        net_from_powl, im_from_powl, fm_from_powl
    )
    if tree_from_net is None:
        raise ValueError("pm4py.convert_to_process_tree(...) returned None")

    safe_save(
        "tree_from_net",
        pm4py.save_vis_process_tree,
        tree_from_net,
        out_path("04_petri_to_process_tree.svg"),
    )

    bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
    if bpmn_from_tree is None:
        raise ValueError("pm4py.convert_to_bpmn(tree_from_net) returned None")

    bpmn_models["bpmn_from_tree"] = bpmn_from_tree

    safe_save(
        "bpmn_from_tree",
        pm4py.save_vis_bpmn,
        bpmn_from_tree,
        out_path("05_petri_to_process_tree_to_bpmn.svg"),
    )

except Exception as exc:
    conversion_errors["petri_to_process_tree_or_tree_to_bpmn"] = short_exception(exc)
    print(
        "conversion_failed[petri_to_process_tree_or_tree_to_bpmn]:",
        conversion_errors["petri_to_process_tree_or_tree_to_bpmn"],
    )


# ---------------------------------------------------------------------
# 6. Round-trip every produced BPMN model back to an accepting Petri net
# ---------------------------------------------------------------------

round_tripped_nets = {}

for bpmn_name, bpmn_model in bpmn_models.items():
    rt_name = f"roundtrip_net_from_{bpmn_name}"
    try:
        rt_net, rt_im, rt_fm = require_accepting_net(
            f"BPMN -> accepting Petri net for {bpmn_name}",
            pm4py.convert_to_petri_net(bpmn_model),
        )

        round_tripped_nets[rt_name] = (rt_net, rt_im, rt_fm)
        accepting_nets[rt_name] = (rt_net, rt_im, rt_fm)

        diagnostics[rt_name] = diagnose_accepting_net(rt_name, rt_net, rt_im, rt_fm)

        safe_save(
            rt_name,
            pm4py.save_vis_petri_net,
            rt_net,
            rt_im,
            rt_fm,
            out_path(f"06_{rt_name}.svg"),
        )

    except Exception as exc:
        conversion_errors[rt_name] = short_exception(exc)
        print(f"conversion_failed[{rt_name}]:", conversion_errors[rt_name])


# ---------------------------------------------------------------------
# 7. Conversion summary
# ---------------------------------------------------------------------

print("\n=== Conversion Summary ===")
print("BPMN models produced:", sorted(bpmn_models.keys()))
print("Accepting nets available:", sorted(accepting_nets.keys()))
print("Round-tripped nets:", sorted(round_tripped_nets.keys()))
print("Conversion errors:", conversion_errors)
print("Diagnostics keys:", sorted(diagnostics.keys()))
```

# 4. Preservation and Loss Audit

This audit is pre-execution. A row should be promoted to `validated preserved` only after the code in sections 3 and 5 runs cleanly for that row: diagnostics pass, positive/negative witnesses behave correctly, and bounded-language comparison shows no relevant difference. If the process-tree call raises, treat the process-tree branch as `conversion failed`, not as a semantic failure of the source POWL.

| Source invariant                                                                                           | POWL→Petri         | Petri→BPMN         | Petri→Tree | BPMN round trip | Evidence or uncertainty                                                                                                                                                                                              |
| ---------------------------------------------------------------------------------------------------------- | ------------------ | ------------------ | ---------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Register Change` first; `Archive Change` final                                                            | expected preserved | expected preserved | ambiguous  | not tested      | Workflow-net, soundness, exact-final-marking witness replay, and negative archive-before-release trace test this.                                                                                                    |
| `Assess Risk` and `Prepare Evidence` unordered after registration                                          | expected preserved | ambiguous          | ambiguous  | not tested      | Trace tests can validate both visible orders. They do not prove true concurrency as a structural relation unless footprints/reachability also support it. BPMN layout may falsely suggest sequence.                  |

# 5. Round-Trip Validation Code

Append this code after the conversion script above. It compares `net_from_powl` against every BPMN round-tripped accepting net in `round_tripped_nets`.

```python
from collections import Counter, deque
import math

# ---------------------------------------------------------------------
# 1. Marking and transition execution helpers
# ---------------------------------------------------------------------

def clean_marking(marking):
    """
    Remove zero-token entries. This keeps final-marking equality exact while
    avoiding false mismatches caused only by explicit zeroes.
    """
    return {p: int(c) for p, c in dict(marking).items() if int(c) != 0}


def same_marking(m1, m2) -> bool:
    """
    Exact equality within the same net: same places, same token counts,
    no extra tokens.
    """
    return clean_marking(m1) == clean_marking(m2)


def marking_state_key(marking):
    """
    Stable key for exploration within a single net execution.
    Uses place object identity because round-trip nets have different places.
    """
    return tuple(sorted((id(p), int(c)) for p, c in clean_marking(marking).items()))


def transition_sort_key(t):
    label = getattr(t, "label", None)
    name = getattr(t, "name", "")
    return ("" if label is None else str(label), str(name))


def enabled_sorted(net, marking):
    return sorted(
        list(pm4py.get_enabled_transitions(net, marking)),
        key=transition_sort_key,
    )


def arc_weight(arc) -> int:
    return int(getattr(arc, "weight", 1) or 1)


def clone_marking_like(original_marking, data):
    """
    Try to preserve PM4Py's Marking class if possible.
    """
    try:
        return type(original_marking)(data)
    except Exception:
        return dict(data)


def fire_transition(marking, transition):
    """
    Fire a Petri-net transition using transition.in_arcs and transition.out_arcs.
    Enabledness is still delegated to pm4py.get_enabled_transitions(...).
    """
    new_m = clean_marking(marking)

    for arc in getattr(transition, "in_arcs", []):
        place = arc.source
        weight = arc_weight(arc)
        new_m[place] = new_m.get(place, 0) - weight
        if new_m[place] < 0:
            raise RuntimeError(
                f"Negative marking after firing {transition}: "
                f"place={place}, tokens={new_m[place]}"
            )
        if new_m[place] == 0:
            del new_m[place]

    for arc in getattr(transition, "out_arcs", []):
        place = arc.target
        weight = arc_weight(arc)
        new_m[place] = new_m.get(place, 0) + weight
        if new_m[place] == 0:
            del new_m[place]

    return clone_marking_like(marking, new_m)


# ---------------------------------------------------------------------
# 2. Exact witness replay with hidden tau transitions
# ---------------------------------------------------------------------

def accepts_trace_exact(
    net,
    im,
    fm,
    visible_trace,
    max_states=100_000,
):
    """
    Check whether the net accepts exactly the given visible trace.

    Semantics:
    - transitions with label None are hidden;
    - hidden transitions may occur before, between, and after visible labels;
    - visible transitions not matching the next requested label are ignored;
    - a trace is accepted only if the final marking is reached exactly;
    - visited-state tracking avoids infinite silent cycling.
    """
    visible_trace = tuple(visible_trace)
    start = clone_marking_like(im, clean_marking(im))

    queue = deque([(start, 0)])
    seen = {(marking_state_key(start), 0)}

    while queue:
        marking, pos = queue.popleft()

        if pos == len(visible_trace) and same_marking(marking, fm):
            return True

        for t in enabled_sorted(net, marking):
            label = getattr(t, "label", None)

            if label is None:
                next_pos = pos
            elif pos < len(visible_trace) and label == visible_trace[pos]:
                next_pos = pos + 1
            else:
                continue

            next_marking = fire_transition(marking, t)
            key = (marking_state_key(next_marking), next_pos)

            if key not in seen:
                seen.add(key)
                if len(seen) > max_states:
                    raise RuntimeError(
                        f"State limit exceeded while replaying {visible_trace}"
                    )
                queue.append((next_marking, next_pos))

    return False


# ---------------------------------------------------------------------
# 3. Bounded visible-language exploration
# ---------------------------------------------------------------------

def bounded_visible_language(
    net,
    im,
    fm,
    max_visible_len=14,
    max_label_counts=None,
    max_tau_depth=50,
    max_states=250_000,
):
    """
    Explore accepted visible traces under explicit bounds.

    Bounds:
    - max_visible_len limits visible trace length;
    - max_label_counts can bound loop-related visible labels;
    - max_tau_depth prevents unproductive silent exploration;
    - exact final-marking equality is required for acceptance.

    This is exhaustive only within these bounds and the silent-depth limit.
    It is not exhaustive for the unbounded LOOP language.
    """
    max_label_counts = max_label_counts or {}
    start = clone_marking_like(im, clean_marking(im))

    accepted = set()
    stack = [(start, tuple(), 0)]
    seen = set()

    while stack:
        marking, trace, tau_depth = stack.pop()
        key = (marking_state_key(marking), trace)

        if key in seen:
            continue
        seen.add(key)

        if len(seen) > max_states:
            raise RuntimeError("State limit exceeded during bounded exploration")

        if same_marking(marking, fm):
            accepted.add(trace)

        for t in enabled_sorted(net, marking):
            label = getattr(t, "label", None)
            next_marking = fire_transition(marking, t)

            if label is None:
                if tau_depth < max_tau_depth:
                    stack.append((next_marking, trace, tau_depth + 1))
                continue

            if len(trace) >= max_visible_len:
                continue

            if label in max_label_counts and trace.count(label) >= max_label_counts[label]:
                continue

            stack.append((next_marking, trace + (label,), 0))

    return accepted

def safe_footprints(name, net, im, fm):
    try:
        fp = pm4py.discover_footprints(net, im, fm)
        print(f"footprints[{name}]: computed")
        return fp
    except Exception as exc:
        print(f"footprints_failed[{name}]: {short_exception(exc)}")
        return None


def safe_reachability_summary(name, net, im, fm):
    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        states = getattr(rg, "states", None)
        transitions = getattr(rg, "transitions", None)
        summary = {
            "constructed": True,
            "states": None if states is None else len(states),
            "transitions": None if transitions is None else len(transitions),
        }
        print(f"reachability[{name}]:", summary)
        return summary
    except Exception as exc:
        summary = {"constructed": False, "error": short_exception(exc)}
        print(f"reachability_failed[{name}]:", summary["error"])
        return summary


def label_count_summary(name, net):
    counts = visible_label_counter(net)
    duplicates = {label: count for label, count in counts.items() if count > 1}
    print(f"visible_label_counts[{name}]:", dict(counts))
    print(f"visible_label_duplicates[{name}]:", duplicates)
    return counts, duplicates
```

# 6. Visual-Semantics Review

A BPMN rendering can be behaviorally acceptable and still be misleading to readers.

Parallel gateways may suggest “simultaneous work,” while the source POWL states a partial-order constraint: `Assess Risk` and `Prepare Evidence` are unordered after registration, but verification additionally waits for both. A diagram reader may also infer that branches are independent when they are not: `Legal Review` depends on `Assess Risk`, whereas verification depends on both `Assess Risk` and `Prepare Evidence`.

Exclusive gateways for optional legal review can hide the silent skip branch. If the BPMN layout shows only the `Legal Review` task prominently, stakeholders may believe legal review is mandatory. If the skip edge is drawn as a thin unlabeled path, they may miss that the model intentionally permits release without visible legal review, provided verification has completed.

Loop visualization is especially risky. A BPMN loop may look like `Correct Defect` can happen after inspection and then exit directly. The source does not allow a trailing `Correct Defect`; correction separates verification iterations and must be followed by another `Configure Trial` then `Inspect Trial`. The annotation should explicitly say: “Verification = one or more `Configure Trial → Inspect Trial` iterations; repeated iterations are separated by `Correct Defect`; no zero-iteration loop; no trailing correction.”

Silent routing nodes and generated gateways should not be read as business activities. The BPMN should distinguish generated routing from visible tasks. If the visualization tool renders silent transitions as unlabeled gateways or technical nodes, include a legend: “Unlabeled routing nodes are converter artifacts and carry no business work.”

Graph layout is not semantics. A left-to-right or top-to-bottom placement of `Legal Review` before the verification loop does not mean legal must precede verification. Conversely, if verification is drawn above legal, that does not mean verification must precede legal. The documentation should attach invariant witnesses to the BPMN: one trace with legal before verification, one with legal after verification, and one with legal between `Configure Trial` and `Inspect Trial`.

Recommended annotations:

* Mark the BPMN as “generated derivative from authoritative POWL.”
* Add a side note: “Do not infer sequence from layout; infer sequence only from flow edges and gateway semantics.”
* Label the optional legal gateway: “XOR: perform `Legal Review` or silent skip.”
* Label the release join: “Release waits for verification and completion of optional-legal branch.”
* Label the verification loop with its visible regular expression: `Configure Trial, Inspect Trial, (Correct Defect, Configure Trial, Inspect Trial)*`.
* Include the invariant table and witness-test report beside the diagram.

# 7. Rejection Criteria

Reject or quarantine a conversion result if any of the following occur:

1. The primary `POWL → accepting Petri net` conversion raises an exception, returns `None`, or does not return `(net, im, fm)`.

2. Any accepting-net conversion returns a missing initial marking or missing final marking.

3. `pm4py.check_is_workflow_net(...)` is false, raises unexpectedly, or the net has no clear single-entry/single-exit workflow interpretation.

4. `pm4py.check_soundness(net, im, fm, print_diagnostics=True)` reports unsoundness, raises an unexplained exception, or reveals dead transitions, improper completion, or unreachable finalization.

5. A required positive witness is rejected, especially:

   * `Prepare Evidence` before `Assess Risk`;
   * `Assess Risk` before `Prepare Evidence`;
   * legal before verification;
   * verification before legal;
   * legal between `Configure Trial` and `Inspect Trial`;
   * two verification iterations separated by `Correct Defect`.

6. A forbidden negative witness is accepted, especially:

   * `Release Change` before verification;
   * `Configure Trial` before both `Assess Risk` and `Prepare Evidence`;
   * `Legal Review` before `Assess Risk`;
   * `Inspect Trial` before `Configure Trial`;
   * trailing `Correct Defect` before release;
   * `Archive Change` before `Release Change`.

7. The optional legal behavior collapses: `Legal Review` becomes mandatory, impossible, allowed before assessment, or detached from the release join.

8. The verification loop semantics change: zero iterations become possible, repeated iterations no longer require `Correct Defect`, or `Correct Defect` can occur without a following full verification iteration.

9. The release synchronization is lost: release becomes possible before the verification loop completes, or before legal completes when the legal branch is chosen.

10. A BPMN round trip introduces extra accepted bounded traces or loses source accepted bounded traces under the configured validation bounds.

11. Visible activity labels are renamed, duplicated, or hidden in a way that invalidates label-based trace comparison.

12. Exact final-marking equality fails for accepted complete traces: for example, the trace reaches a marking with extra tokens, missing final tokens, or enabled visible work after `Archive Change`.

13. The process-tree intermediate succeeds but serializes the legal/verification relation or the `Assess Risk`/`Prepare Evidence` relation. A successful tree object is not enough; it must pass the same invariant suite.

14. The BPMN visualization is so ambiguous that stakeholders are likely to infer a mandatory legal review, a false order between legal and verification, or an incorrect loop. In that case, quarantine the diagram even if the underlying net passes behavioral checks.

# 8. Canonical Representation Recommendation

The authoritative storage representation should be the source POWL model plus its invariant contract. POWL is the best canonical form here because the source explicitly uses partial-order structure, optional silent behavior, and a loop without forcing the model into block-structured process-tree form. The accepting Petri net produced from POWL is a compiled semantic artifact, useful for diagnostics and replay, but it should not replace the POWL as the source of truth unless the organization deliberately changes its modeling standard.

The stakeholder visualization should be the BPMN produced by the primary pipeline, `POWL → accepting Petri net → BPMN`, but only with annotations and a validation report. The BPMN should be labeled as derivative. It is suitable for discussion, not for unreviewed editing.

Generated artifacts are derivative:

* `net_from_powl`;
* `bpmn_from_net`;
* any process tree from `convert_to_process_tree(...)`;
* any BPMN from the process tree;
* any BPMN round-tripped accepting Petri net;
* all SVG/PNG/PDF visualizations.

Each derivative should be accompanied by:

* conversion logs and exceptions;
* non-null initial/final marking checks;
* workflow-net and soundness diagnostics;
* visible-label counts;
* positive and negative witness results;
* bounded visible-language comparison against `net_from_powl`;
* footprint comparison where available;
* reachability-graph construction summary;
* the explicit bound statement for loop validation.

The process-tree intermediate should not be allowed as a normal production path. It may be run as an experiment, but its failure is acceptable and possibly expected because the source has a partial-order dependency pattern that is not obviously block-structured. If it succeeds, it should remain quarantined until it passes the full witness and bounded-language comparison. Even then, it should not become canonical unless the source model is intentionally redesigned into a process-tree-compatible structure.

Future edits should avoid round-trip drift by following a one-way governance rule: edit the POWL and invariant table, regenerate all derivatives, rerun validation, and publish new artifacts with versioned reports. Do not edit the generated BPMN and then treat the edited BPMN as equivalent to the POWL. If stakeholders request a diagram change, translate that request back into a POWL/invariant change first, then regenerate.

# 9. Residual Uncertainty

Even if every proposed test passes, the validation cannot establish all possible claims.

1. It cannot prove full unbounded equivalence of the verification loop. The bounded exploration checks only traces within the configured visible-length and `Correct Defect` bounds.

2. It cannot prove true concurrency in the strongest semantic sense. Visible traces and footprints can show both interleavings, but interleaving equivalence is weaker than structural or causal equivalence.

3. It cannot prove that every BPMN engine will execute the generated BPMN with the same semantics as PM4Py’s conversion. Gateway, loop, and silent-routing interpretations may vary across tools.

4. It cannot prove that stakeholders will read the visualization correctly. Misinterpretation of layout, gateways, and silent branches remains a communication risk.

5. It cannot validate non-control-flow semantics that are absent from the source POWL, such as task duration, resource assignment, data conditions, legal thresholds, risk scores, or actual temporal overlap.

6. It cannot prove that generated silent routing nodes are harmless in every downstream system. They are hidden in the trace comparison, but another tool may expose or transform them.

7. It cannot prove semantic identity under duplicate labels in future models. The current source has unique visible labels; if future edits introduce duplicate labels, label-based witness and language comparison must be replaced or strengthened with stable activity identifiers.

8. It cannot prove that the process-tree conversion, if it succeeds, is conceptually appropriate for governance. Passing finite tests would make it a usable derivative, not an authoritative representation.
