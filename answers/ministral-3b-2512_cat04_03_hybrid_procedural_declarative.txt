# 1. Policy Interpretation and Conflict Resolution

## Material Assumptions
1. All activities are atomic and timestamped relative to case start.
2. Resources are distinct and can be checked for segregation-of-duties.
3. Clarification loops are handled by tracking response chains rather than single events.
4. Temporal deviations are warnings unless explicitly tied to control-flow constraints.
5. The "emergency" policy (R6) is only enforced via external checks since it requires joint authorization attributes not present in logs.

## Conflict Resolution: R5/R6
The core conflict is:
- R5: Legal department requires Obtain Legal Opinion precedes Activate Vendor after Sanctions Escalation
- R6: Operations allows emergency activation before opinion if jointly authorized (but opinion arrives within 24h)

**Resolution Chosen**: Strict Legal Precedence with Conservative Enforcement
- We implement R5 as mandatory (no emergency exceptions)
- Emergency cases are flagged as warnings but not automatically rejected
- This preserves legal compliance while maintaining operational flexibility

**Compliance Risk**: Emergency cases may be rejected if opinion arrives late, but this is a business decision rather than technical violation.

# 7. Resource- and Data-Aware Checks

```python
def validate_resources(events):
    # R9: Verify Bank Account resource  approval resource
    verify_bank = next(e for e in events if e['activity'] == 'Verify Bank Account')
    approval = next(e for e in events if e['activity'] in ['Manager Approval', 'Compliance Approval'])
    if verify_bank['concept_attr']['resource'] == approval['concept_attr']['resource']:
        raise ValueError("Resource segregation violated")

    # R9: Capture Master Data  Activate Vendor
    capture = next(e for e in events if e['activity'] == 'Capture Master Data')
    activate = next(e for e in events if e['activity'] == 'Activate Vendor')
    if capture['concept_attr']['resource'] == activate['concept_attr']['resource']:
        raise ValueError("Resource segregation violated")

    # R5/R6: Legal opinion validation
    sanctions = next(e for e in events if e['activity'] == 'Sanctions Escalation')
    opinion = next(e for e in events if e['activity'] == 'Obtain Legal Opinion')
    if sanctions and opinion:
        if opinion['timestamp'] > sanctions['timestamp'] + 12*3600:
            raise ValueError("Legal opinion too late")

def validate_emergency(events):
    # R6: Emergency check (requires joint authorization)
    if any(e['concept_attr'].get('emergency') for e in events):
        opinion = next(e for e in events if e['activity'] == 'Obtain Legal Opinion')
        if opinion and opinion['timestamp'] > 24*3600:
            return "warning"  # Flag but don't reject
```

# 9. Contradictions, Redundancies, and Blind Spots

1. **Redundancies**:
   - DECLARE's `exactly_one` and Log Skeleton's `never_together` for approvals
   - ProcessTree's concurrency and Log Skeleton's `always_before` for clarification chains

2. **Inconsistencies**:
   - Post-activation behavior (R11) requires case-level tracking not available in logs
   - Emergency policy (R6) conflicts with strict R5 enforcement

3. **Blind Spots**:
   - Missing case attributes (emergency flag, joint authorization)
   - Temporal deviations don't trigger control-flow changes
   - Resource segregation requires external data

4. **Vacuity**:
   - DECLARE rules don't enforce single-occurrence for terminal activities
   - Log Skeleton doesn't prevent multiple approvals
