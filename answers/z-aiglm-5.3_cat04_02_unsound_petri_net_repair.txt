import pm4py

def fire_named(net, marking, name):
    """Fire the transition called `name` in `marking` and return (new_marking, transition).

    Enabledness is checked with pm4py.get_enabled_transitions; the helper raises
    ValueError instead of silently moving tokens.
    """
    enabled = pm4py.get_enabled_transitions(net, marking)
    t = next((x for x in enabled if x.name == name), None)
    if t is None:
        raise ValueError(
            "transition '%s' is NOT enabled in %s; enabled: %s"
            % (name, marking, sorted(x.name for x in enabled))
        )
    new_m = Marking()
    for p, n in marking.items():
        new_m[p] = n
    for a in t.in_arcs:      # consume
        new_m[a.source] -= a.weight
    for a in t.out_arcs:     # produce (handles self-loops correctly)
        new_m[a.target] += a.weight
    for p in [p for p, n in new_m.items() if n <= 0]:
        del new_m[p]
    return new_m, t

# 1. Executive Verdict

**Workflow net?** Yes. `source` is the unique place without input arcs, `sink` the unique place without output arcs, and every place and transition lies on a source-to-sink path, so `pm4py.check_is_workflow_net` should return `True`. **Sound?** No — it must be expected to be unsound. **Principal defect:** `t_join_waived` consumes only `p_waived`; it never synchronizes with the mandatory analysis branch, while `p_analysis_done` has no other consumer on the waiver route (`t_join_normal` additionally needs `p_review_done`). **Business consequence:** on the waiver route, `t_authorize` can fire before `t_analyze` (cases authorized without analysis — a compliance breach), and the analysis token is permanently stranded: the exact final marking `{sink: 1}` is unreachable, so waived cases never properly complete and leave stuck tokens behind.

I found no second *structural* defect: both symptoms (premature authorization; impossible proper termination) trace to the single missing input arc on `t_join_waived`, which is why Counterexample 2 is a variant of the same root cause rather than an independent flaw.

**Minimality justification.**

- **Cost 0 is impossible:** Counterexamples 1 and 2 prove the original net unsound; no relabeling changes behavior.
- **Cost 1:** adding an isolated place or transition would violate the workflow-net path condition, so the only 1-edit candidates are single-arc edits. import pm4py
from pm4py.objects.petri_net.obj import Marking


def fmt(marking):
    return "{%s}" % ", ".join(
        "%s:%d" % (p.name, c) for p, c in sorted(marking.items(), key=lambda kv: kv[0].name)
    )


def fire_named(net, marking, name):
    """Fire transition `name` in `marking`; return (new_marking, transition).
    Checks enabledness via pm4py.get_enabled_transitions and raises
    ValueError instead of silently moving tokens."""
    enabled = pm4py.get_enabled_transitions(net, marking)
    t = next((x for x in enabled if x.name == name), None)
    if t is None:
        raise ValueError(
            "transition '%s' is NOT enabled in %s; enabled: %s"
            % (name, fmt(marking), sorted(x.name for x in enabled))
        )
    new_m = Marking()
    for p, n in marking.items():
        new_m[p] = n
    for a in t.in_arcs:      # consume
        new_m[a.source] -= a.weight
    for a in t.out_arcs:     # produce (self-loops handled correctly)
        new_m[a.target] += a.weight
    for p in [p for p, n in new_m.items() if n <= 0]:
        del new_m[p]
    return new_m, t


def run_sequence(net, start_marking, names, title):
    print("\n--- %s ---" % title)
    m = start_marking
    print("step 0 | marking: %s" % fmt(m))
    for i, nm in enumerate(names, start=1):
        m, t = fire_named(net, m, nm)
        enabled = sorted(x.name for x in pm4py.get_enabled_transitions(net, m))
        print("step %d | fired %s | marking: %s | enabled: %s" % (i, t.name, fmt(m), enabled))
    return m

# 7. Repair Trade-Offs and Residual Risks

**Distinguishability of waiver vs. standard review.** All three repairs keep the labels "Perform Standard Review" and "Record Review Waiver" on distinct transitions with distinct outcome places (`p_review_done` vs. `p_waived`). In R1 the two silent joins are mutually exclusive in every reachable marking (`p_review_done` and `p_waived` both descend from the single `p_review` token), so the log always shows which outcome was chosen. R2 preserves distinguishability trivially (choice at registration). R3 preserves it but adds a silent skip that the log cannot show.

**Duplicate behavior / confusion through silent transitions.** R1 adds no new silent transition, but leaves two structurally similar silent joins (`t_join_normal`, `t_join_waived`) that both consume `p_analysis_done` and produce `p_decision`. At most one is ever enabled, so there is no duplicate firing; however the net is no longer free-choice, so free-choice-specific tooling and theory no longer apply, and a careless future edit (e.g., adding `p_waived` to `t_join_normal`) would instantly deadlock the standard route. R3's `t_analyze` vs. `t_skip_analysis` is a visible/silent pair converging on the same marking — intended under its policy, but exactly the pattern a reviewer should challenge.

**Soundness does not prove alignment.** A passing soundness check establishes only well-formedness (option to complete, proper completion, no dead transitions). R2 and R3 are expected to be sound yet encode different policies than the stated intent; conversely, soundness says nothing about *which* visible orderings are allowed. Alignment must be argued via the regression traces and the invariant below — never inferred from `check_soundness` alone.

**Regression traces.** Positive for R1 (must be accepted): Register, Analyze, Standard Review, Authorize, Register, Standard Review, Analyze, Authorize, Register, Analyze, Waive, Authorize, Register, Waive, Analyze, Authorize. Negative (must be rejected): Register, Waive, Authorize — the counterexample trace, Register, Analyze, Authorize, Register, Standard Review, Authorize, Register, Authorize, …, Register, Standard Review, Waive, …, and anything with Authorize before Analyze/Waive. For R2/R3, Register, Waive, Authorize flips to positive — that flip must be explicitly signed off as policy.

**Detecting an accidental bypass of mandatory analysis.** (i) Reachability-graph invariant: in every reachable marking, if `p_decision` or `sink` is marked then `p_analysis = p_analysis_done = 0`; assert by enumerating RG nodes. (ii) Negative unit tests replaying the Section 3 sequences with `fire_named`, asserting that `t_authorize` raises while an analysis place is marked. (iii) Conformance checking (alignments) on production logs, flagging any case containing "Authorize Case" without "Perform Analysis". (iv) A runtime LTL-style rule: Authorize must be preceded by Analyze in the same case. (v) KPI: count of cases whose terminal marking differs from `fm`.

# 8. Final Recommendation

Deploy **R1**. It is the unique minimal repair under the unit edit-cost model (one added arc), preserves the stated policy exactly — analysis mandatory on both routes, review outcome chosen by XOR, authorization strictly after both, clean termination in `fm` — and changes no visible label, keeping the diff auditable and log-compatible. Its residual risks (non-free-choice structure, two similar silent joins) are mitigated by the regression trace set and the reachability invariant; the reachable set (10 markings) is small enough to verify exhaustively. Keep **R2** as the fallback: it is the cheapest structurally clean encoding (cost 2, still free-choice) of the policy "waived cases skip analysis," and it is the right answer only if the business explicitly signs off that policy change — never deploy it as a silent "fix," because it converts the negative regression trace Register, Record Review Waiver, Authorize into valid behavior. Hold R3 in reserve for the intermediate policy "analysis optional under waiver"; its silent skip is difficult to govern and should not be the default. Whatever ships, wire the Section 6 diagnostics and the Section 7 invariant into CI so that any future arc edit reopening the analysis bypass fails the build rather than production.
