## 1. Normalization Assumptions
* Interval construction: recorded clock interval from rounding/flooring/rounding semantics is built first, then clock correction is applied. `true = recorded - offset` with `offset  [a,b]`  `true  [recorded_min - b , recorded_max - a]`.
* HUB: displayed second ±0.5 s resolution, offset [-1,+1] s, UTC.
* OPS-BER / LEGACY-BER: floor to minute `[m:00,m:59.999]` local, Europe/Berlin, offset as stated. True local then converted to UTC. 2025-10-26 02:00-02:59 is a DST fold. Fold is kept as a union of CEST UTC+2 and CET UTC+1 and pruned by ingestion order.
* SENSOR: round to nearest 10 s  ±5 s resolution, offset [-5,+5] s, UTC, completion semantics.
* VENDOR-NY: floor to minute local, America/New_York, offset [-180,+180] s.
* MOBILE-LON: round to nearest minute  ±30 s, Europe/London, offset [-300,+300] s. User entry delay up to 5 min late is modelled as the recorded timestamp being later than occurrence: `true_event = recorded_clock - d` with `d[0,300] s`. This shifts the occurrence interval earlier, not the record time.
* Inferred start T-404: `Start = Complete - duration` with duration [18,25] min = [1080,1500] s. Uncertainty of Complete is propagated.
* Causal / latency constraints are applied as feasible set intersections, not as point fixes. `Alert_Received` for T-407 is `Alert_Sent + latency [0,20] min` intersected with ` Investigation_Start`. The plausible but unlogged causal assumption is kept explicit.
* Duration intervals are `[min_possible , max_possible] = [t2_min - t1_max , t2_max - t1_min]`. Union of disjoint DST possibilities is preserved.

import pandas as pd
from zoneinfo import ZoneInfo
from datetime import datetime, timedelta

# --- interval helpers ---
def floor_min(dt):  return dt.replace(second=0,microsecond=0)
def apply_offset(interval, off_lo, off_hi):
    lo, hi = interval
    return (lo - timedelta(seconds=off_hi), hi - timedelta(seconds=off_lo))

# Example construction for one case, pattern repeated for all cases
events = []

def add_event(case, act, local_dt, tz_name, rounding, off_lo, off_hi, note=''):
    tz = ZoneInfo(tz_name)
    # resolution interval
    if rounding=='exact':
        lo = local_dt - timedelta(seconds=0.5)
        hi = local_dt + timedelta(seconds=0.5)
    elif rounding=='floor_min':
        lo = floor_min(local_dt)
        hi = floor_min(local_dt)+timedelta(seconds=59,999999)
    elif rounding=='round_min':
        lo = local_dt - timedelta(seconds=30)
        hi = local_dt + timedelta(seconds=30)
    elif rounding=='round_10s':
        lo = local_dt - timedelta(seconds=5)
        hi = local_dt + timedelta(seconds=5)
    lo_tz = lo.replace(tzinfo=tz)
    hi_tz = hi.replace(tzinfo=tz)
    lo_utc = lo_tz.astimezone(ZoneInfo('UTC'))
    hi_utc = hi_tz.astimezone(ZoneInfo('UTC'))
    lo_utc, hi_utc = apply_offset((lo_utc,hi_utc), off_lo, off_hi)
    events.append({'case':case,'activity':act,'start':lo_utc,'end':hi_utc,'note':note})

# Build intervals for all cases as per Section 2, DST folds kept as separate entries
# ... add_event calls for T-401..T-409 ...

df_int = pd.DataFrame(events)

# Feasible duration intervals
def duration_interval(a_start,a_end,b_start,b_end):
    d_min = (b_start - a_end).total_seconds()
    d_max = (b_end - a_start).total_seconds()
    return d_min, d_max

# Midpoint lossy log for PM4Py
mid_log = []
for _,r in df_int.iterrows():
    mid = r['start'] + (r['end']-r['start'])/2
    mid_log.append({'case_id':r['case'],'activity':r['activity'],'timestamp':mid})
mid_df = pd.DataFrame(mid_log)
mid_df = mid_df.sort_values(['case_id','timestamp'])
mid_df.rename(columns={'case_id':'case:concept:name',
                       'activity':'concept:name',
                       'timestamp':'time:timestamp'}, inplace=True)
import pm4py
mid_df = pm4py.format_dataframe(mid_df, 'time:timestamp')
# Temporal profile from the problem statement
profile = {('Alert_Received','Investigation_Start'):(600,180),
           ('Investigation_Start','Containment_Complete'):(2100,600),
           ('Alert_Received','Containment_Complete'):(2700,720),
           ('Containment_Complete','Close_Incident'):(86400,21600)}
for zeta in [1,2,3]:
    res = pm4py.conformance_temporal_profile(mid_df, profile, zeta=zeta)
    print(zeta, res.head())

# Interval classification is performed externally as in Section 3.
# PM4Py operates on point estimates only; midpoint diagnostics are a lossy approximation.

## 7. Governance Recommendation

* Store all timestamps in UTC with original local wall time, source system, resolution semantics, and raw recorded value retained.
* Record clock offset telemetry per source at event time; bound offsets with daily NTP diagnostics, not engineering estimates.
* Capture resolution metadata: floor/round semantics and measurement uncertainty.
* Enforce start/complete semantics at lifecycle design; never infer start from completion unless duration is logged with evidence grade.
* Log DST fold explicitly; never rely on ambiguous local times.
* Use causal identifiers for Alert_Sent/Received to bound delivery latency instead of assumptions.
* Policy: interval overlap is not sufficient for enforcement. Require CERTAIN_PASS for SLA compliance; POSSIBLE_VIOLATION triggers evidence upgrade before penalty. Temporal-profile conformance should be reported with zeta sensitivity and interval classification, not point estimates.
