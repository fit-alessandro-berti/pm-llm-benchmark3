# 1. Executive Verdict

The net **is structurally a workflow net**: `source` is the only source place, `sink` the only sink place, and every node lies on a source-to-sink path. It **is not sound**. The principal defect is that `t_join_waived` has only `p_waived` as input; it neither waits for nor consumes `p_analysis_done`. On the waiver route, `t_authorize` can therefore fire while analysis is still pending. If analysis has already fired, its completion token is simply bypassed. Thus waiver cases can put a token in `sink` while retaining a token in `p_analysis` or `p_analysis_done`; that is not the exact accepting marking `fm`, and the leftover token can become stuck. Business consequences are authorization without mandatory analysis and waiver cases that cannot complete cleanly with no residual tokens.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_split` and its outputs | Start analysis and review in parallel | It is an AND-split: one token is placed in each of `p_analysis` and `p_review` | Two branch tokens must subsequently be accounted for; the waiver join accounts for only the review-side outcome |
| Analysis branch: `p_analysis  t_analyze  p_analysis_done` | Make analysis mandatory and record its completion | Produces a completion token that, in the original net, is consumed only by `t_join_normal` | On the waiver route, either `p_analysis` or `p_analysis_done` can remain marked |
| `t_standard_review` | Complete the standard-review alternative | Consumes the sole token in `p_review` and produces `p_review_done` | Correctly supplies the review input to the normal join |
| `t_waive_review` | Complete the review requirement through a recorded waiver | Competes with `t_standard_review` for the same `p_review` token, so the review choice is XOR; it produces `p_waived` | The choice itself is correct, but its outcome bypasses `t_join_normal` |
| `t_join_normal` | Synchronize analysis and standard review | Two-input AND-join over `p_analysis_done` and `p_review_done` | The standard route can complete properly; a successful standard-case replay therefore does not expose the waiver defect |
| `t_join_waived` | Synchronize analysis and waiver | One-input pass-through from `p_waived` to `p_decision`; analysis is absent from its preset | It can fire with analysis pending, or bypass an existing analysis-completion token |
| `p_decision  t_authorize` | Permit authorization only after both required activities | Authorization tests only for a token in `p_decision` | `p_decision` can coexist with `p_analysis` or `p_analysis_done`, allowing early authorization or improper completion |
| `im` and `fm` | Start one case and accept only a cleanly completed case | `im={source:1}` and `fm={sink:1}` are appropriate accepting markings | Merely testing whether `sink` can become marked is insufficient: `sink` can be marked while other places are also marked |
| Whole-net node coverage | Satisfy the workflow-net structural conditions | There is a unique source place and sink place, and every place and transition, including both joins, lies on some structural source-to-sink path | The workflow-net check can succeed without detecting the missing behavioral synchronization |

# 3. Marking-Based Counterexample

The following is a legal firing sequence in the original net:

```text
t_register, t_split, t_waive_review, t_join_waived,
t_authorize, t_analyze
```

All omitted places in the table have zero tokens.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (`im`) | `{source=1}` | `{t_register}` | Initial marking |
| 1 | `t_register` | `{p_ready=1}` | `{t_split}` | Case is registered |
| 2 | `t_split` | `{p_analysis=1, p_review=1}` | `{t_analyze, t_standard_review, t_waive_review}` | Both parallel branch tokens are now visible |
| 3 | `t_waive_review` | `{p_analysis=1, p_waived=1}` | `{t_analyze, t_join_waived}` | Waiver consumes the review token; analysis remains pending |
| 4 | `t_join_waived` | `{p_analysis=1, p_decision=1}` | `{t_analyze, t_authorize}` | Analysis and authorization are both enabled; either can occur next |
| 5 | `t_authorize` | `{p_analysis=1, sink=1}` | `{t_analyze}` | Authorization occurs before analysis. A sink token exists, but this marking is not `fm` |
| 6 | `t_analyze` | `{p_analysis_done=1, sink=1}` | `` | Analysis can occur after authorization, but its output token is now stuck |

At Step 5, the marking covers `fm` in the sense that `sink` contains one token, but it does **not** equal the exact final marking `fm={sink:1}`.

The leftover token at Step 5 can still be consumed by `t_analyze`, but that only moves it to `p_analysis_done`. At Step 6:

- `t_join_normal` cannot consume it because `p_review_done` is empty and can no longer become marked;
- `t_join_waived` does not consume `p_analysis_done`, and `p_waived` has already been emptied;
- `sink` has no outgoing arc.

Consequently, `fm` cannot be reached from this marking.

**Second counterexample: analysis first does not fix completion.** After the common prefix `t_register, t_split`, fire:

```text
t_analyze, t_waive_review, t_join_waived, t_authorize
```

The marking evolution is:

```text
{p_analysis_done=1, p_review=1}
   {p_analysis_done=1, p_waived=1}
   {p_analysis_done=1, p_decision=1}
   {p_analysis_done=1, sink=1}
```

Here authorization occurs after analysis, but the final marking still has a leftover token and no enabled transition. Thus early authorization and improper completion are two consequences of the same missing synchronization. The standard-review route can reach `fm` exactly, so `fm` is not globally unreachable; the failure is specific to post-waiver behavior.

# 4. Minimal-Repair Alternatives

**Edit-cost model.** Adding or removing one arc costs 1; adding or removing one place or transition costs 1. Retargeting an arc therefore costs 2. Label and comment changes cost 0. Incident arc removals are counted separately when deleting a node.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| **A — dedicated waiver AND-join** | Add arc `p_analysis_done  t_join_waived` | **1** | Fully preserved: analysis remains mandatory, standard review is unchanged, and waiver may still be recorded before or after analysis | `t_join_waived` now consumes both `p_analysis_done` and `p_waived`; waiver-first and analysis-first executions both reach exactly `fm` | Two silent joins encode related synchronization logic, so future maintenance could again change only one of them |
| **B — presynchronize at the visible waiver transition** | Add arc `p_analysis_done  t_waive_review`; leave `t_join_waived` unchanged | **1** | Mandatory analysis and authorization-after-completion are preserved; standard cases are unchanged | **Policy/timing strengthening:** on waiver cases, analysis must finish before the waiver may be recorded. `t_waive_review` consumes both the review token and analysis-completion token | Waiver can no longer be recorded while analysis is running; the visible waiver transition also acquires a hidden synchronization role |
| **C — converge both review outcomes into one join** | Remove arcs `t_waive_review  p_waived`, `p_waived  t_join_waived`, and `t_join_waived  p_decision`; add `t_waive_review  p_review_done`; remove place `p_waived` and transition `t_join_waived` | **6**: four arc edits plus two node removals | Fully preserved, including both analysis/waiver orderings | Both review alternatives produce `p_review_done`, and every case uses `t_join_normal`; waiver internally no longer uses its separate join | Larger diff; the common completion place and the name `t_join_normal` are less specific about which review outcome occurred |

Repairs A and B are behaviorally distinct: A permits `t_waive_review` before `t_analyze`, whereas B deliberately forbids that ordering. B is nevertheless behaviorally clean because its added input arc makes the waiver transition consume the analysis-completion token before the existing waiver join fires.

Zero edits leave the counterexamples unchanged, so every edit-based repair has cost at least 1. A and B attain that bound and therefore tie for **global minimality under this cost model**. If preserving waiver-first concurrency is mandatory, B is not a full-intent alternative, while A remains a cost-1 repair.

C is not claimed to be globally minimal. Its edit set is minimal for that particular clean, single-join convergence plan: omitting its node and incident-arc cleanup would leave disconnected or dead waiver machinery.

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def copy_marking(marking):
    result = Marking()
    for place, tokens in marking.items():
        if tokens > 0:
            result[place] = tokens
    return result


def marking_dict(marking):
    return {
        place.name: tokens
        for place, tokens in sorted(
            marking.items(), key=lambda item: item[0].name
        )
        if tokens > 0
    }


def enabled_names(net_value, marking):
    enabled = pm4py.get_enabled_transitions(net_value, marking)
    return sorted(t.name for t in enabled)


def fire_named(net_value, marking, transition_name):
    candidates = [
        t for t in net_value.transitions if t.name == transition_name
    ]
    if len(candidates) != 1:
        raise ValueError(
            f"Expected one transition named {transition_name}, "
            f"found {len(candidates)}"
        )

    transition = candidates[0]
    enabled = pm4py.get_enabled_transitions(net_value, marking)

    # Check enabledness before changing any token count.
    if transition not in enabled:
        raise RuntimeError(
            f"{transition_name} is not enabled at "
            f"{marking_dict(marking)}; enabled={enabled_names(net_value, marking)}"
        )

    result = copy_marking(marking)

    for arc in transition.in_arcs:
        weight = getattr(arc, "weight", 1)
        result[arc.source] = result.get(arc.source, 0) - weight
        if result[arc.source] <= 0:
            del result[arc.source]

    for arc in transition.out_arcs:
        weight = getattr(arc, "weight", 1)
        result[arc.target] = result.get(arc.target, 0) + weight

    return result


def run_sequence(net_value, initial_marking, sequence):
    marking = copy_marking(initial_marking)
    print("start:", marking_dict(marking))

    for transition_name in sequence:
        marking = fire_named(net_value, marking, transition_name)
        print(
            transition_name,
            "->",
            marking_dict(marking),
            "; enabled:",
            enabled_names(net_value, marking),
        )

    return marking


def diagnose(tag, net_value, initial_marking, final_marking):
    print(f"\n=== {tag} ===")
    print(
        "workflow net:",
        pm4py.check_is_workflow_net(net_value),
    )
    sound = pm4py.check_soundness(
        net_value,
        initial_marking,
        final_marking,
        print_diagnostics=True,
    )
    print("sound:", sound)
    print(
        "enabled at initial marking:",
        enabled_names(net_value, initial_marking),
    )
    reachability_graph = pm4py.convert_to_reachability_graph(
        net_value, initial_marking, final_marking
    )
    print("reachability graph constructed:", type(reachability_graph).__name__)
    return reachability_graph


original_rg = diagnose("original", net, im, fm)
repaired_rg = diagnose(
    "repaired", repaired_net, repaired_im, repaired_fm
)

original_bad_sequence = [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_join_waived",
    "t_authorize",
    "t_analyze",
]
original_end = run_sequence(net, im, original_bad_sequence)
print("Original counterexample ends exactly at fm:", original_end == fm)

repaired_waiver_sequence = [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_analyze",
    "t_join_waived",
    "t_authorize",
]
repaired_end = run_sequence(
    repaired_net, repaired_im, repaired_waiver_sequence
)
print(
    "Repaired waiver sequence ends exactly at repaired_fm:",
    repaired_end == repaired_fm,
)
```

For the original, the workflow-net check should be `True`, while soundness should be `False`. Immediately after waiver, the original enables both `t_analyze` and `t_join_waived`; its reachability graph contains the improper-completion states derived above.

For Repair A, both checks should be `True`. Immediately after waiver and before analysis, only `t_analyze` is enabled, and the printed waiver sequence ends exactly at `repaired_fm`. # 7. Repair Trade-Offs and Residual Risks

- **Distinguishability of review outcomes.** The visible events `Perform Standard Review` and `Record Review Waiver` remain distinct in all three repairs. Repair A also retains separate waiver places and joins until synchronization. Once either silent join produces `p_decision`, however, the current marking alone no longer identifies the selected review outcome; event history is required. Repair C converges the outcomes earlier and therefore relies even more on event history for audit distinction.

- **Silent-transition duplication or confusion.** Repair A adds no transition and creates no duplicate authorization. Its two silent joins are mutually exclusive because standard review and waiver compete for one `p_review` token. They can nevertheless confuse maintenance or state-based monitoring because both produce the same place. Repair B avoids changing the joins but hides synchronization inside a visible business transition, which is arguably less transparent.

- **Soundness is not business alignment.** Soundness does not evaluate labels or the desired ordering policy. Repair B can be sound while disallowing waiver recording during analysis. More generally, a net can complete cleanly and still implement the wrong approval policy. Soundness checks must therefore be supplemented with business-level trace tests.

- **Positive firing-sequence tests for Repair A.** Each sequence below should end exactly at `repaired_fm`:
  - Standard, analysis first: `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize`.
  - Standard, review first: `t_register, t_split, t_standard_review, t_analyze, t_join_normal, t_authorize`.
  - Waiver, analysis first: `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`.
  - Waiver, waiver first: `t_register, t_split, t_waive_review, t_analyze, t_join_waived, t_authorize`.

- **Negative tests.**
  - After `t_register, t_split, t_waive_review`, assert that `t_join_waived` and `t_authorize` are not enabled before analysis.
  - After standard review but before analysis, assert that `t_join_normal` is not enabled.
  - Assert that selecting either review alternative disables the other for that case.
  - Assert that every reachable marking containing `sink` equals the final marking, and that no reachable nonfinal marking is terminal.
  - Assert that authorization cannot occur twice and cannot occur without exactly one selected review outcome.

- **Detecting an analysis bypass.** For Repair A, add a structural regression assertion that `p_analysis_done` is an input place of both joins. Also inspect the reachability graph: every path to an authorization edge must contain `t_analyze` and exactly one review-outcome transition. Do not merely require `p_analysis_done` in authorization’s premarking—a correct join has already consumed that token. As an additional operational check, flag any log case containing `Authorize Case` without a preceding `Perform Analysis`, or without a completed selected review outcome.

# 8. Final Recommendation

Deploy **Repair A**. It is a one-arc correction at the actual synchronization fault, preserves standard behavior and both intended waiver/analysis interleavings, and makes each review outcome consume the analysis-completion token before producing `p_decision`. It therefore addresses both early authorization and improper completion without changing labels or business policy.

Use **Repair C** as the fallback if maintainers prefer one common review-outcome place and one AND-join. It costs more but presents a conventional AND-split/XOR-review/AND-join structure.

Do not select Repair B merely because it ties A in edit cost: it strengthens the policy by requiring analysis to finish before a waiver can be recorded. That is acceptable only with explicit business approval. In every case, deployment should include reachability checks and the positive and negative trace tests above; a successful soundness call alone is insufficient.
