## 3. Robust redesign package

1. **Replace strict Urgent-first dispatch with deadline-aware dispatch and WIP caps.**  
   Use Urgent deadlines as the top priority only within a capped express lane; reserve scheduled slots for Complex-panel cases needing specialist/medical validation; let Routine batch only when no Urgent breach is projected and batch wait is bounded. This is robust because it prevents a single priority rule from starving Routine/Complex work. It depends on reliable queue visibility and projected release times. It can fail if the Urgent cap is too high, pushing extra work into assay or medical validation.

2. **Build a pre-analytical front door: early defect triage, recollection fast lane, and accession-correction standard work.**  
   Activate I6 within 2h of receipt, with direct feedback to collection sites and a dedicated fast lane for re-collection. This is robust across courier, quality, and demand surges because it reduces downstream repeat-assay work and long recollection loops. It may increase early recollection/cancellation workload; without dedicated courier/registration capacity it can overload intake. Once defects fall, assay/repeat capacity may become the next bottleneck.

3. **Smooth courier arrivals and stagger intake.**  
   Use I7 to spread 10:00/17:00 spikes and align staffing with scheduled slots. This is robust for courier compression and pre-analytical queueing. It depends on external courier compliance. If smoothing only shifts arrival into a larger pre-analytical wave, it will move the bottleneck to pre-analytical check; staffing and acceptance slots must be coordinated.

4. **Use controlled assay scheduling and constrained batching, not permanent dedicated machines.**  
   Reserve M1 for Urgent, Complex-panel, and high-repeat-risk cases, but keep dynamic review of M2 QC/failure. Use I2 larger batches only for Routine cases with sufficient deadline slack and only when Urgent backlog is below threshold. This avoids the I3 failure mode where all Routine goes to a higher-failure M2 and repeats rise. The next bottleneck is technical validation after assay recovery; batching must be released before recovery bursts.

5. **Create a flexible cross-trained pool with a protected validation floor and medical-validation surge.**  
   Cross-train more than two staff for accession correction/technical validation and add temporary evening medical validation during peaks. Use cross-trained staff for accession only when the accession queue exceeds threshold and technical validation remains below its warning band. This helps S1/S3/S5 but can create a technical-validation shortage if the floor is not protected. Evening medical validation may simply move the queue to specialist review.

6. **Create a Complex-panel pathway and selective partner overflow.**  
   Pre-identify Complex-panel cases, reserve specialist-review slots, and use protocol-based medical sign-off where allowed. Use I10 only for non-urgent Complex-panel overflow where 12h transport still leaves target slack and traceability/result integration is reliable. This relieves specialist review in S1/S3, but transport delay and reconciliation can fail or create new work.

7. **Gate registration automation and Routine release batching by downstream WIP.**  
   Use I8 only for orders with complete digital metadata and only while pre-analytical/assay WIP is below caps. Use I9 Routine release batching only when release workload is high and Routine target slack is sufficient; set a maximum hold time. Both are useful but can create WIP surges or Routine delay if used without downstream capacity gating.

## 6. Residual vulnerabilities

- **Priority tuning remains fragile.** If Urgent dispatch is too generous, Complex-panel and Routine cases starve; if too restrictive, Urgent penalties rise. The control rules need daily recalibration.
- **Cross-training can hollow out technical validation.** This is a redesign-created vulnerability: using technical validators for accession correction can reduce the accession queue while increasing the 101%-utilised technical-validation queue.
- **Controlled M2 routing can create a repeat cluster.** If Routine volume is concentrated on M2 during outages, its higher failure rate can cause the next repeat-assay wave. M2 QC and repeat trends must be able to override the routing rule.
- **Early defect triage can overload the front door.** Rejecting poor samples within 2h reduces downstream work, but increases recollection calls, cancellations, courier rebooking, and collection-site explanations.
- **Medical-validation surge does not solve specialist scarcity.** Evening medical validation can push more Complex-panel cases into the already long specialist-review queue.
- **Selective outsourcing introduces traceability and reconciliation risk.** The 12h transport delay may still breach targets, and partner results must be integrated without creating manual rework.
- **Courier smoothing depends on external actors.** If couriers do not comply or a route is delayed, pre-analytical queues can still spike and sample stability can degrade.
- **Automation can create WIP shocks.** Gated registration automation helps only if the gate reacts quickly to downstream pre-analytical and assay WIP.
