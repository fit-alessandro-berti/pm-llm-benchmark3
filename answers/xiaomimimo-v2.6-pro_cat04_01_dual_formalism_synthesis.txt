```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator


def _node(parent, label=None, operator=None):
    """Create a process-tree node and attach it to `parent` explicitly."""
    pt = ProcessTree(operator=operator, label=label)
    if parent is not None:
        parent.children.append(pt)      # register the child ...
        pt.parent = parent              # ... and set the back-pointer
    return pt


# ---------------------------------------------------------------- root
tree = ProcessTree(operator=Operator.SEQUENCE)

# 1) Register Deviation
rd = _node(tree, label="Register Deviation")

# 2) two independent initial work streams (may overlap)
par_work = _node(tree, operator=Operator.PARALLEL)

seq_cont = _node(par_work, operator=Operator.SEQUENCE)
cm = _node(seq_cont, label="Contain Material")
pv = _node(seq_cont, label="Plan Verification")

seq_root_cause = _node(par_work, operator=Operator.SEQUENCE)
arc = _node(seq_root_cause, label="Analyze Root Cause")
par_post = _node(seq_root_cause, operator=Operator.PARALLEL)
dca = _node(par_post, label="Design Corrective Action")

# risk route: XOR(low-risk route, high-risk route)
xor_risk = _node(par_post, operator=Operator.XOR)
sr = _node(xor_risk, label="Supervisor Review")
par_high = _node(xor_risk, operator=Operator.PARALLEL)
qr = _node(par_high, label="Quality Review")
rr = _node(par_high, label="Regulatory Review")

# optional Consult Supplier (exactly one silent "skip" alternative)
xor_cs = _node(par_post, operator=Operator.XOR)
tau_cs = _node(xor_cs, label=None)          # silent transition = skip
cs = _node(xor_cs, label="Consult Supplier")

# 3) trial cycle  *( ->(Execute Trial, Inspect Trial), Adjust Parameters )
loop_trial = _node(tree, operator=Operator.LOOP)
seq_iter = _node(loop_trial, operator=Operator.SEQUENCE)
et = _node(seq_iter, label="Execute Trial")
it = _node(seq_iter, label="Inspect Trial")
ap = _node(loop_trial, label="Adjust Parameters")

# 4) release & archive
rm = _node(tree, label="Release Material")
ac = _node(tree, label="Archive Case")
```

# 1. Assumptions and Interpretation

1. **Event granularity.** Each label denotes one completed activity instance, recorded at completion time (rule 11). The models are controlflow only; no data attribute (risk level, supplier involvement, inspection outcome) is a model element.
2. **Lowrisk / highrisk choice.** Represented as a *mandatory exclusive choice* (XOR) after `Analyze Root Cause`: alternative A = `Supervisor Review` (low risk), alternative B = a block containing `Quality Review` and `Regulatory Review` (high risk). There is no “skip” alternative: every case takes exactly one route. The choice is *unguarded* — which branch is correct is decided by case data that rule 11 explicitly places outside the model. Alternative B is a twonode partial order / `PARALLEL` block with **no** ordering edge, so the two reviews may run concurrently and complete in either order (rule 5).
3. **Optional supplier consultation.** Represented as `XOR(silent, Consult Supplier)` — i.e. zeroorone occurrence. Because the alternative is a direct XOR child (not a loop), “at most once” is structural. When taken, `Consult Supplier` is ordered after `Analyze Root Cause` and before `Release Material`, and is unordered with respect to design, planning, the approval route and the trial cycle (rule 6). The decision to take it is unguarded (datadependent), same caveat as point 2.
4. **Abstraction of “passing inspection”.** Inspection outcomes are not labels. The trial cycle is modelled as `LOOP( body = SEQUENCE(Execute Trial, Inspect Trial), redo = Adjust Parameters )`. **Exiting the loop is identified with “the last `Inspect Trial` passed.”** Consequences, stated explicitly: (a) every trace contains at least one `Execute Trial`–`Inspect Trial` pair; (b) the final `Inspect Trial` of the trace is by definition the passing one, so rule 9’s “passing `Inspect Trial`” means “the trialcycle block has completed”; (c) `Adjust Parameters` lives only in the redo part and is therefore always followed by a new `Execute Trial`–`Inspect Trial` pair — it can never occur after the passing inspection (rule 8). A trace in which the *last* inspection actually failed is indistinguishable from a compliant one at controlflow level; this must be checked in a data layer.
5. **Duplicate visible labels: not permitted.** Every visible label occurs as exactly one model node in each model (repetition of `Execute Trial`, `Inspect Trial`, `Adjust Parameters` comes only from loop semantics). Rationale: keeps the logtonode mapping 1:1, keeps alignments, footprint and modelrepair diagnostics unambiguous. A duplicationbased encoding (e.g. copying the trial cycle into two XOR order variants) is explicitly *not* used; its consequences are discussed in §6 and §8.
6. **Approximation policy for the process tree: conservative underapproximation.** The tree admits **only** intended behaviour (no unsafe behaviour is introduced) at the price of excluding some intended behaviour: the tree requires the *whole* selected approval route **and** (if taken) `Consult Supplier` to complete before the **first** `Execute Trial`. Thus rules 6 and 7 (“may overlap the trial work / the trial cycle”) are only approximated in the tree. The POWL model keeps them exact. The two affected witnesses are W4 and W5 in §5. This policy was chosen over a permissive overapproximation because the only overapproximations available would have had to break either “`Design Corrective Action`/`Plan Verification` complete before the trial” or “the route is selected after `Analyze Root Cause`” — both are compliancerelevant safety properties — and over a duplicationbased encoding because the nonblockstructured core involves the trial **loop**, whose exact split across XOR branches is unbounded (see §3).
7. **“May overlap” = true concurrency.** Interpreted as *absence of an order constraint* — not as “some fixed interleaving is allowed”. The models therefore admit **every** interleaving of the events of two unordered nodes (e.g. `Execute Trial`, `Quality Review`, `Inspect Trial`), and concurrency is expressed as a `PARALLEL` block in the tree and as missing edges in the POWL partial order. Interleaving happens at wholeactivity granularity: a node must complete before its successors may start.
8. **Rule 9’s list of release preconditions is exhaustive.** No extra constraint is invented. (Nothing is lost: `Contain Material` and `Analyze Root Cause` are transitively complete before `Release Material` anyway, via `Plan Verification`/`Design Corrective Action`  trial  `Release Material`.)
9. **Order of the two initial work streams is unconstrained in both directions** (rule 2): `Contain Material` may finish before or after `Analyze Root Cause` starts/finishes; neither is anchored to the other.
10. **The loop executes at least once and finitely often** (repeat **until** pass, rule 8); the number of iterations is unbounded.
11. **`Adjust Parameters` is never the last event of the trial block**: a failed iteration is `Execute Trial  Inspect Trial  Adjust Parameters`, and every `Adjust Parameters` is followed by a new iteration.
12. **The approval route may complete after the passing inspection** but must complete before `Release Material` (literal reading of rules 7 and 9 together). This is admitted by both models (witness W5).
13. **Silent transitions** are used only for “supplier not consulted” (and are introduced by conversions/loop exits). They are not visible labels and never appear in traces.
14. **Start/end anchors** are structural: `Register Deviation` is the unique minimal and `Archive Case` the unique maximal element of every execution (rule 1).

# 3. PM4Py Process-Tree Model

**Compact processtree expression** (operator symbols: `->` = `Operator.SEQUENCE`, `+` = `Operator.PARALLEL` (all children, arbitrary interleaving), `X` = `Operator.XOR` (exactly one child), `*(A, B)` = `Operator.LOOP` with `A` the body and `B` the redo part, `tau` = silent/skip):

```text
          +( 'Design Corrective Action',                         # R5

                +( 'Quality Review', 'Regulatory Review' ) ),    # R6  high risk (R8)

```

**Mapping to the narrative (for `pm4py.parse_process_tree`):** the five toplevel `->` children correspond to rules 1–2 (registration), rule 2 (the two concurrent streams), rules 7–8 (the trial cycle), rule 9 (release) and rules 10–1 (archiving). Stream A realises R4 (`Contain Material` before `Plan Verification`); stream B realises R5 and R6 and ends in a `PARALLEL` block whose three children are the design, the mandatory XOR risk route (R7/R8) and the optional supplier XOR (R11). The trial cycle is `*( ->(Execute Trial, Inspect Trial), Adjust Parameters )`, which yields `(ET·IT)·(AP·ET·IT)*`, i.e. rule 8 including “`Adjust Parameters` never after the passing inspection” (assumption 4). `Release Material` is a single sequence element after the parallel block and the loop, which is precisely the ANDjoin of R20 *with the extra constraint of assumption 6*.

**Selfcontained construction code** (explicit parent/child handling):

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator


def child(parent, label=None, operator=None):
    """Create a process-tree node and attach it to `parent`
    (insert into parent.children *and* set the child's back-pointer)."""
    node = ProcessTree(operator=operator, label=label)
    parent.children.append(node)
    node.parent = parent
    return node


# ------------------------------------------------------------------ root
tree = ProcessTree(operator=Operator.SEQUENCE)          # ->(...)

# (1) start anchor
child(tree, label="Register Deviation")

# (2) two independent, overlapping work streams  ->  PARALLEL
par_streams = child(tree, operator=Operator.PARALLEL)   # +(...)

# --- stream A: containment -> verification planning -------------------
seq_a = child(par_streams, operator=Operator.SEQUENCE)
child(seq_a, label="Contain Material")
child(seq_a, label="Plan Verification")

# --- stream B: root cause -> {design, risk route, optional supplier} ---
seq_b = child(par_streams, operator=Operator.SEQUENCE)
child(seq_b, label="Analyze Root Cause")
par_b = child(seq_b, operator=Operator.PARALLEL)        # R5, R7/R8, R11 unordered
child(par_b, label="Design Corrective Action")

xor_risk = child(par_b, operator=Operator.XOR)          # route selection (R7)
child(xor_risk, label="Supervisor Review")              #   low risk
par_high = child(xor_risk, operator=Operator.PARALLEL)  #   high risk (R8)
child(par_high, label="Quality Review")
child(par_high, label="Regulatory Review")

xor_cs = child(par_b, operator=Operator.XOR)            # optional supplier (R11)
child(xor_cs, label=None, operator=None)                #   tau  = "not consulted"
child(xor_cs, label="Consult Supplier")

# (7)(8) trial cycle:  *( ->(Execute Trial, Inspect Trial), Adjust Parameters )
loop_trial = child(tree, operator=Operator.LOOP)
seq_iter = child(loop_trial, operator=Operator.SEQUENCE)
child(seq_iter, label="Execute Trial")
child(seq_iter, label="Inspect Trial")
child(loop_trial, label="Adjust Parameters")            # redo part

# (9)(10) release and archive
child(tree, label="Release Material")
child(tree, label="Archive Case")

# OPTIONAL cross-check with the string notation above (same tree):
# TREE_STR = "->('Register Deviation', ...)"               # expression of this section
# tree_from_string = pm4py.parse_process_tree(TREE_STR)    # should equal `tree`
```

All operator arities are respected (`SEQUENCE`  1, `PARALLEL`/`XOR`  2, `LOOP` exactly 2), all labels are unique, and the tree is therefore sound by construction.

**Requirements the tree cannot represent exactly.** The tree represents rules 1–5, 8, 10, 11 and the ordering halves of rules 6, 7 and 9 exactly, but it cannot represent rule 6’s “`Consult Supplier` … may overlap … trial work” and rule 7’s “the selected approval route … may overlap the trial cycle” exactly: those two relations form, together with `Plan Verification  trial`, `Design Corrective Action  trial` and `Analyze Root Cause  {design, route, supplier}`, a nonseriesparallel (Nshaped) subposet, so no nesting of `->`/`+`/`X`/`*` blocks reproduces it (a block containing both `Plan Verification` and `Design Corrective Action` must be finished before any node placed after it, while the route hangs off `Analyze Root Cause` in the other stream and must stay unordered with the trial). Because the joint element is the *trial loop*, a duplicationbased exact encoding would have to split `Execute Trial`/`Inspect Trial`/`Adjust Parameters` across mutually exclusive order variants, which is unbounded (arbitrarily many interleavings of the route with arbitrarily many iterations) — “unreasonably complex” in the sense of the task. I therefore use **conservative underapproximation**: the tree additionally requires the selected approval route and (if taken) `Consult Supplier` to complete before the **first** `Execute Trial`; witnesses W4 and W5 in §5 are intendedlegal traces the tree rejects. Beyond that single loss, the tree also inherits the abstractions of assumptions 2, 3 and 4: the risk route and the supplier optionality are *unguarded* XORs (the data conditions of rules 5, 6 and 11 are not representable), and “the passing `Inspect Trial`” is identified with loop exit rather than an observed outcome. No behaviour is added (the tree language is a strict subset of the intended language), so the approximation is safebutincomplete, and no visible label is duplicated.

**Loss ledger (process tree):**

| Intended element | Status in the tree |
|---|---|
| R3, R4, R5, R7, R8, R13–R17, R21, R22 | exact |
| R6, R11 (`Consult Supplier` optionality and its `ARC``RM` window) | exact except the overlap with the trial |
| R9, R10, R12, R18, R19, R20 | approximated: R18/R19’s overlap with the trial is **forbidden** (overconstraint) |
| Data conditions (risk level, supplier involvement, inspection outcome) | not representable (rule 11) — unguarded XORs / loop exit |

# 4. PM4Py POWL Model

**Compact POWL description:**

```text
StrictPartialOrder(root) with nodes
    RD   = Transition('Register Deviation')
    CM   = Transition('Contain Material')
    ARC  = Transition('Analyze Root Cause')
    PV   = Transition('Plan Verification')
    DCA  = Transition('Design Corrective Action')
    RISK = OperatorPOWL(XOR, [ Transition('Supervisor Review'),                 # low risk
                               StrictPartialOrder([Transition('Quality Review'),
                                                   Transition('Regulatory Review')]) ])  # high, concurrent
    CSOPT= OperatorPOWL(XOR, [ SilentTransition(), Transition('Consult Supplier') ])     # optional, <= 1
    TRIAL= OperatorPOWL(LOOP, [ StrictPartialOrder([Transition('Execute Trial')  -> Transition('Inspect Trial')]),
                                Transition('Adjust Parameters') ])                       # repeat until pass
    RM   = Transition('Release Material')
    AC   = Transition('Archive Case')

root.order = { RD->CM, RD->ARC,            # start anchor (R1)
               CM->PV,                      # R4
               ARC->DCA, ARC->RISK, ARC->CSOPT,   # R5, R6, R9
               PV->TRIAL, DCA->TRIAL,       # R12 (AND-join into the trial)
               RISK->RM, CSOPT->RM, TRIAL->RM,    # R20 (AND-join into release)
               RM->AC }                     # R21
```

**Selfcontained construction code:**

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

# ------------------------------------------------ visible transitions
rd  = Transition("Register Deviation")
cm  = Transition("Contain Material")
arc = Transition("Analyze Root Cause")
pv  = Transition("Plan Verification")
dca = Transition("Design Corrective Action")
sr  = Transition("Supervisor Review")
qr  = Transition("Quality Review")
rr  = Transition("Regulatory Review")
cs  = Transition("Consult Supplier")
et  = Transition("Execute Trial")
it  = Transition("Inspect Trial")
ap  = Transition("Adjust Parameters")
rm  = Transition("Release Material")
ac  = Transition("Archive Case")

# ------------------------------------------- high-risk branch (R5/R8)
# two nodes, deliberately NO edge  ->  concurrent, either completion order
risk_high = StrictPartialOrder([qr, rr])

# ------------------------------------------- risk route (R6/R7): XOR
risk = OperatorPOWL(Operator.XOR, [sr, risk_high])

# ------------------------------- optional supplier consultation (R11)
tau_cs = SilentTransition()                 # "not consulted"
cs_opt = OperatorPOWL(Operator.XOR, [tau_cs, cs])

# ----------------------- trial cycle (R12-R17): *( ->(ET, IT), AP )
trial_body = StrictPartialOrder([et, it])
trial_body.order.add_edge(et, it)           # R13: Execute Trial -> Inspect Trial
trial = OperatorPOWL(Operator.LOOP, [trial_body, ap])

# ---------------------------------------------------- root partial order
powl = StrictPartialOrder([rd, cm, arc, pv, dca, risk, cs_opt, trial, rm, ac])

powl.order.add_edge(rd,  cm)        # R1  start anchor
powl.order.add_edge(rd,  arc)       # R1  start anchor
powl.order.add_edge(cm,  pv)        # R4
powl.order.add_edge(arc, dca)       # R5
powl.order.add_edge(arc, risk)      # R6  route selected after root cause
powl.order.add_edge(arc, cs_opt)    # R9  supplier after root cause
powl.order.add_edge(pv,  trial)     # R12 AND-join into the trial
powl.order.add_edge(dca, trial)     # R12 AND-join into the trial
powl.order.add_edge(risk,    rm)    # R20 AND-join into release
powl.order.add_edge(cs_opt,  rm)    # R10/R20
powl.order.add_edge(trial,   rm)    # R9  passing Inspect Trial
powl.order.add_edge(rm,  ac)        # R21 end anchor
```

Transitive closure makes `rd` the unique minimal element (R1/R22) and `ac` the unique maximal element; no further edges are needed.

**Why intentionally unconnected node pairs may stay concurrent.** The root order leaves exactly thirteen node pairs unordered; each is granted concurrency by the narrative:

* *Crossstream pairs* `(CM, ARC)`, `(CM, DCA)`, `(CM, RISK)`, `(CM, CSOPT)`, `(ARC, PV)`: rules 2–6 impose only **withinstream** precedences (`CMPV`, `ARC{DCA, RISK, CSOPT}`); the containment stream and the rootcause stream are explicitly independent and may overlap (R3, R24).
* *Independent work products* `(PV, DCA)`: no rule orders verification planning against correctiveaction design; both are merely two inputs of the ANDjoin R12, so their relative order is free.
* *Design vs. obligations* `(DCA, RISK)`, `(DCA, CSOPT)`: rules 4–6 give them only the common predecessor `ARC` and (for the latter two) the common successor `RM`; nothing orders design against review or supplier work.
* *Approvals vs. supplier* `(RISK, CSOPT)`: two independent obligations synchronised only at `Release Material`.
* *The two deliberate overlaps* `(RISK, TRIAL)` and `(CSOPT, TRIAL)`: rules 6 and 7 explicitly say the route “may overlap the trial cycle” and the supplier consultation “may overlap … trial work”; leaving these pairs edgefree is the whole point of using POWL here.
* Inside submodels: `(QR, RR)` unordered because rule 5 states concurrency and free completion order. The pairs `(SR, risk_high)`, `(, CS)` are **not** concurrent — they are XOR alternatives; `(body, ap)` inside the loop is a loop alternation; `(ET, IT)` is ordered.

# 7. Preferred Representation and Validation Plan

**Canonical representation: the POWL model.** Reasons: (1) it is the only one of the two that expresses the crossbranch dependencies (`Design Corrective Action`/`Plan Verification`  trial, and the threeway ANDjoin at `Release Material`) as *explicit* partialorder edges instead of by serialisation; (2) its language coincides with the intended language modulo the two documented data abstractions (unguarded XORs, passinginspection = loop exit) — perpair inspection in §4 shows **no** over or underordering; (3) it avoids both approximation hazards at once: it neither drops legal behaviour (the tree’s loss of the approval/supplier  trial overlap) nor duplicates labels (the duplicationbased alternative). The process tree is kept as a *conservative, blockstructured surrogate* for tooling that requires a tree (discovery, treebased repair, teaching cases), and is explicitly labelled incomplete.

**Validation plan** (concrete, ordered; every step is evidence to inspect, not proof of fidelity):

1. **Conversion to accepting Petri nets.**
   ```python
   import pm4py

   net_t, im_t, fm_t = pm4py.convert_to_petri_net(tree)          # tree -> (net, im, fm)
   net_p, im_p, fm_p = pm4py.convert_to_petri_net(powl)          # POWL dispatch (if supported)

   # fallback for versions without POWL dispatch in convert_to_petri_net:
   # from pm4py.objects.conversion.powl.converter import apply as powl_to_net
   # net_p, im_p, fm_p = powl_to_net(powl)
   ```
   Record which conversion variant was used, and diff the resulting net’s visible labels against the model’s labels (step 5).
2. **Soundness of the converted nets.**
   ```python
   pm4py.check_soundness(net_t, im_t, fm_t, print_diagnostics=True)
   pm4py.check_soundness(net_p, im_p, fm_p, print_diagnostics=True)
   ```
   Require option to complete, proper completion, absence of dead transitions and of livelock. Additionally check `len(net_p.transitions) - len(visible)` to see how many silent transitions the conversion introduced (expect 1 for the supplier skip, plus loop/conversion artefacts). Soundness is a *necessary* property of a usable model, not evidence of narrative fidelity.
3. **Bounded / sampled playout.** Use the converted nets with a bound (loops make the language infinite):
   ```python
   sim_p = pm4py.play_out(net_p, im_p, final_marking=fm_p, max_trace_length=30)  # ~5000 samples
   sim_t = pm4py.play_out(net_t, im_t, final_marking=fm_t, max_trace_length=30)
   ```
   (Parameter names/variants differ across PM4Py releases — `pm4py.algo.simulation.playout` with `max_trace_length`/`max_execution_time`, or `pm4py.algo.simulation.tree_playout` on `tree`.) Feed **every** sampled trace through an executable checker `violations(trace)` that encodes rules 1–10 as predicates (RD first, AC last, `CM<pV`, `ARC<DCA`, `ARC`< route activity, `ET` after `PV` and `DCA`, `AP` only between two iterations, `RM` after the last `IT` and after all route activities and after `CS`, `CS`  1, `CS` before `RM`). Require zero violations for both playouts (this is the *no unsafe behaviour* half).
4. **Positive and negative trace tests.** Build a small `EventLog` from the eight witnesses of §5 plus extra negatives (`CS` twice; `CS` before `ARC`; `CS` after `RM`; missing `RD`; `AC` before `RM`; `RM` without any `IT`; `SR` **and** `QR` in one trace; no route activity at all; `AP` as the last event of the trial block; `ET` before `PV`), then run
   ```python
   res_p = pm4py.conformance.conformance_diagnostics_alignments(test_log, net_p, im_p, fm_p)
   res_t = pm4py.conformance.conformance_diagnostics_alignments(test_log, net_t, im_t, fm_t)
   ```
   Expected: cost 0 for W1–W5 on the POWL net; cost > 0 for F1–F3 and every extra negative; cost > 0 for **W4 and W5 on the tree net** — this is the *measured* size of the documented approximation (it must be reported as a known falsenegative rate, not hidden). Reverse direction: MonteCarlo sample linearisations of the intended partial order (topological sorts of the §2 relation set) and require each to be accepted by the POWL net (cost 0) — this is the *no missing behaviour* half, bounded by the sampler.
5. **Silentbehaviour / duplicatedlabel checks.** (a) Collect all leaf nodes of `tree` and all `Transition` nodes of `powl` (recursively through `OperatorPOWL`/`StrictPartialOrder` children) and assert `Counter(labels)[l] == 1` for every visible label — a guard that no duplicationbased approximation has crept in. (b) `from pm4py.objects.petri_net.utils.petri_utils import get_visible_transitions`; assert `get_visible_transitions(net_p)` equals the 14 intended labels and that every invisible transition lies on the supplierskip alternative or is a loop/conversion artefact. (c) On every playout trace assert: nonempty, exactly one `RD`, exactly one `AC`, at least one `ET` and one `IT`, the trace never ends with `AP`, `CS` occurs at most once; and check that a trace consisting only of the silent alternative (`RD CM ARC PV DCA SR RM AC`) is still accepted — i.e. the skip does not make any mandatory activity unreachable. (d) Rerun (a) on the *converted nets* to detect silent transitions that duplicate a visible label’s effect.
6. **Limitations of the plan.** Playout is sampling, not exhaustive (the loop is unbounded, so “all traces” is untestable); alignments are heuristic/bounded and their cost is not a semantic distance; Petrinet conversion of a partial order may itself unfold into a net that admits interleavings the POWL does not intend (or vice versa), so the net must be inspected nodebynode against §4; `check_soundness` proves net properties only — a sound net can still misrepresent the narrative; the unguarded XORs and the passinginspection abstraction cannot be validated at controlflow level at all (they need a dataaware layer); the tree’s conservative approximation guarantees systematic alignment cost on any log containing legal approval/trial overlap, which will bias any comparison of the two models on real data.

# 8. Final Self-Critique

1. **(Semantics) The “passing inspection” abstraction is not falsifiable inside either model.** By identifying loop exit with a passing `Inspect Trial`, both models accept a case whose *recorded* inspection outcome is “failed” as long as the control flow looks right, and conversely cannot represent a case in which the outcome is decided by data midloop (e.g. a passing inspection that is later invalidated). The counterexample I cannot rule out with these models is: `… ET IT (outcome = fail, but the case is released) RM AC` — controlflow conformant, businesscritical violation. My validation plan only partially covers this (step 3 checks the shape, not the data).
2. **(Semantics) The unguarded XORs turn two business rules into plain alternatives.** Rules 5 and 6 (“lowrisk cases *require* supervisor review”, “supplier consultation … depends on case data”) are modelled as free controlflow choices; therefore a highrisk case that takes `Supervisor Review`, or a case that skips a *mandatory* supplier consultation, conforms to both models. This is allowed by rule 11, but it means “conformance” is weaker than “compliance”, and my §5 witnesses deliberately never test this gap.
3. **(Semantics / method) The process tree’s conservative underapproximation has measurable behavioural side effects.** By forcing the route and the supplier consultation before the first `Execute Trial`, the tree not only loses W4/W5shaped traces but also *recommends* a more serial way of working; if the tree is used for discovery or as the training model, users adapt to it and the organisation loses the cycletime benefit of overlapping approvals and trial work. I mitigated this by naming POWL as canonical and quantifying the loss with two witnesses, but I did not quantify how frequent such traces are in real data.
4. **(Technical) The code has not been executed here.** Constructor/keyword signatures (`StrictPartialOrder(nodes=…)`, `OperatorPOWL(operator=…, children=…)`, `check_soundness(…)`, `play_out(…)`) and `convert_to_petri_net`’s POWL dispatch vary between PM4Py releases; I used positional arguments and documented fallbacks to reduce the risk, but a versionpinned run is still required before the models can be trusted as executable artefacts.
