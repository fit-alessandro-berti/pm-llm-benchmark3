The shared mechanism is that, when both verification tasks are runnable, overlapping their service and queue time can shorten the path to the join at Assessment. The strongest common structural feature is therefore the AND-join, not an identical end-to-end process. Site A's reviewers could flex between checks, its system supported simultaneous ownership, and most documents were already digital. Site B has specialized role pools, a case lock, and a statutory originals gate for 62% of cases. Those differences can suppress actual overlap or move waiting to identity, assessment, or legal queues. A's API upgrade and queue huddles also changed waiting independently of the task order.

Effect modifiers include original-document requirement and channel, case complexity, legal-review eligibility, role specialization and capacity, IT locking, and queue load. Selection nodes represent that the distribution and sometimes the meaning of these modifiers differ by site; transport requires conditioning or segmenting on them and checking support. True overlap is a mediator and an implementation-fidelity measure, not equivalent to merely creating two tasks. Rework and appeals are quality outcomes as well as possible consequences of haste or changed case mix. Similar control-flow diagrams do not guarantee transportability: they omit legal conditions, arrival and service distributions, shared-resource interference, task ownership, and measurement practices. Even with the same nominal partial order, those factors alter which path is critical, whether concurrency can occur, and how the treatment changes total cycle time and quality.

## 6. Candidate Site B intervention

**Eligibility and task release.** At registration, record the legal originals requirement, channel, complexity, and legal-review flag. For claims that do not require originals, release Identity Check and Document Check together. For claims that do require originals, release Identity Check and Originals Receipt together; release Document Check only after a verified receipt event. Cases without reliable channel or legal classification stay on the current sequence until classified. Begin with low-complexity, digital, nonlegal cases that pass these rules.

**Concurrency, capacity, and ownership.** Do not override statutory dependencies. Use separate, system-supported child tasks with explicit owners and contemporaneous timestamps. If the legacy lock cannot safely support distinct work, keep that case sequential during the pilot rather than using off-system work and back-entry. Identity, document, assessment, and legal work stay with their trained pools. Apply per-role WIP caps, initially conservative and calibrated to observed utilization; do not release work faster than the receiving pool can absorb it. Daily huddles may coordinate aging items, but record their use because they can affect waiting independently.

**Legal and supplement paths.** After both checks, Assessment may proceed. Public-sector/high-value cases then require Legal Review. A Request Supplement returns the case to the documented supplement intake, then Document Check and Assessment as required, followed by Legal Review again when applicable. Preserve decision and notification order; record why repeat work was requested and which stage was repeated.

**Logging.** Store immutable event time, event-entry time, task owner, queue entry/exit, pause/resume, receipt confirmation, task version, eligibility reason, WIP, and any lock workaround. Audit a sample against source documents and user activity logs.

Textual partial order (with conditional branches):

```text
Register < Identity Check < Assessment
Register < Document path < Assessment
Document path = (Originals Receipt < Document Check) if originals_required,
                otherwise Document Check
Assessment < (Legal Review [< Request Supplement < repeat Document Check
                            < repeat Assessment < Legal Review])* if legal_required
Assessment or completed Legal path < (Approve XOR Reject) < Notify
```

This is a partial-order specification: Identity and the lawful document path may overlap; Assessment waits for both. The optional legal branch and supplement repetition are data-dependent operational gates.

The design separates mechanism failure from implementation failure by measuring both assignment and verified execution. If cases assigned to a runnable version do not achieve owner-verified overlap because the legacy lock blocks work or timestamps are late, that is implementation failure; the intention-to-treat estimate captures the operational proposal, while treatment-on-received evidence describes fidelity. If verified overlap is achieved but pre-Assessment wait and cycle time do not improve, the proposed mechanism may be weak or another queue may dominate. If Assessment wait falls but total cycle or p90 worsens alongside rising assessor/legal WIP, that is a bottleneck shift. Stratification by originals and legal status tests where the path is genuinely runnable. Rework, errors, and mature appeals distinguish faster completion from acceptable completion. Randomized saturation levels reveal whether effects on treated cases are offset by congestion imposed on controls.

## 8. PM4Py model-construction code

```python
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.powl.constants import Operator

# Site A trees: the after model changes only the verification relation to AND.
a_before_tree = pm4py.parse_process_tree(
    "->('Register','Identity Check','Document Check','Assessment',"
    "X('Approve','Reject'),'Notify')"
)
a_after_tree = pm4py.parse_process_tree(
    "->('Register',+('Identity Check','Document Check'),'Assessment',"
    "X('Approve','Reject'),'Notify')"
)
a_before_net, a_before_im, a_before_fm = pm4py.convert_to_petri_net(a_before_tree)
a_after_net, a_after_im, a_after_fm = pm4py.convert_to_petri_net(a_after_tree)

# Site B: a document-path XOR approximates whether originals are required.
# The legal/data condition is not encoded by this silent alternative.
register = Transition(label="Register")
identity = Transition(label="Identity Check")
originals = Transition(label="Originals Receipt")
document = Transition(label="Document Check")
assessment = Transition(label="Assessment")

originals_gate = OperatorPOWL(
    operator=Operator.XOR,
    children=[SilentTransition(), originals],
)
document_path = StrictPartialOrder(nodes=[originals_gate, document])
document_path.order.add_edge(originals_gate, document)

# Legal review is optional by case data. In the legal branch, the loop's redo
# path represents a supplement followed by repeated document check and assessment.
legal_review = Transition(label="Legal Review")
request_supplement = Transition(label="Request Supplement")
repeat_document = Transition(label="Document Check (repeat)")
repeat_assessment = Transition(label="Assessment (repeat)")
redo_path = StrictPartialOrder(
    nodes=[request_supplement, repeat_document, repeat_assessment]
)
redo_path.order.add_edge(request_supplement, repeat_document)
redo_path.order.add_edge(repeat_document, repeat_assessment)
legal_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[legal_review, redo_path],
)
legal_gate = OperatorPOWL(
    operator=Operator.XOR,
    children=[SilentTransition(), legal_loop],
)

decision = OperatorPOWL(
    operator=Operator.XOR,
    children=[Transition(label="Approve"), Transition(label="Reject")],
)
notify = Transition(label="Notify")

# The explicit edges make both checks prerequisites of Assessment.
site_b = StrictPartialOrder(
    nodes=[register, identity, document_path, assessment, legal_gate, decision, notify]
)
site_b.order.add_edge(register, identity)
site_b.order.add_edge(register, document_path)
site_b.order.add_edge(identity, assessment)
site_b.order.add_edge(document_path, assessment)
site_b.order.add_edge(assessment, legal_gate)
site_b.order.add_edge(legal_gate, decision)
site_b.order.add_edge(decision, notify)

site_b_net, site_b_im, site_b_fm = pm4py.convert_to_petri_net(site_b)

for name, net in [
    ("A before", a_before_net),
    ("A after", a_after_net),
    ("B candidate", site_b_net),
]:
    # A workflow-net check is a structural check, not a proof of operational fit.
    print(name, "workflow net:", pm4py.check_is_workflow_net(net))

# This model cannot encode the data rule that selects the originals/legal branch,
# role capacities, queue discipline, IT case locks, resource ownership, or durations.
# The optional XORs are abstractions; validate those conditions in the pilot data.
```

## 9. Recommendation

**conditional go**

Transfer the mechanism that can be justified from the process structure: start independent verification work as early as it is legally runnable, and let Assessment begin only after identity and document checks are both complete. Do not transfer Site A's nine-hour median reduction as an expected effect, and do not create Identity Check and Document Check for every B case immediately after Register. For the 62% requiring originals, Document Check remains blocked until receipt. Identity can potentially overlap Originals Receipt, while the other 38% may support concurrent Identity and Document Check if their legal classification is confirmed.

Start with low-complexity digital claims that do not require originals or Legal Review, and only where the case system can record distinct task owners and event times contemporaneously. This subgroup tests the cleanest mechanism with the fewest mandatory dependencies. Then test original-required cases using the separate version that overlaps Identity with receipt but preserves the document gate. Include high-complexity and legal cases only after early strata show safe execution and sufficient capacity. The expected benefit is a modest reduction in pre-Assessment waiting, likely a few hours for runnable cases; Site A's larger apparent change is confounded. Risks include assessor and legal queue congestion, WIP growth, hidden serialization caused by the case lock, and more rework or worse tail outcomes.

Expand a version when randomized assignment produces verified overlap, shorter total time or pre-Assessment wait, stable p90/queue age, and no material increase in rework, errors, or mature appeals. Modify WIP caps or eligible strata if the join wait improves but downstream queues grow. Pause immediately for statutory ordering violations or serious decision errors. Abandon a version if it cannot achieve auditable overlap, if total cycle time fails to improve despite faithful execution, or if quality and tail harm exceed prespecified margins. Reassess transport whenever staffing, system ownership, or legal rules change.

## 10. Assumption register

1. **Case-level legal classification is available before task release** — Needed to select the lawful document path — Audit registration fields against a sample of claim files and legal decisions — If false, defer concurrent document release until classification and exclude ambiguous cases.
2. **Identity and document work use sufficiently independent evidence for eligible cases** — Needed for parallel work not to create dependency errors — Map source calls and compare exception/rework reasons by treatment — If false, define a dependency-based subset or retain sequential order for dependent checks.
