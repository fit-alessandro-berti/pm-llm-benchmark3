# Process Tree Equivalence Analysis

## 1. Equivalence Notions

### Visible Trace Equivalence (after hiding )
- **Definition**: Two models are equivalent if they produce the same set of complete traces when silent transitions (`tau`) are hidden.
- **Label handling**: Duplicate visible labels are distinguished by occurrence position (e.g., "Check Revision" at position 2 vs 4 in a trace).
- **Scope**: Unbounded trace sets.

### Bounded Visible-Language Equivalence (P3)
- **Definition**: Models are equivalent if their sets of complete visible traces match exactly when:
  - Silent transitions are hidden
  - Traces contain 12 visible events
  - Traces contain 3 "Analyze Revision" occurrences
- **Label handling**: Same as above, but with bounded length.
- **Scope**: Finite trace sets under specified bounds.

### Business-Relevant Equivalence (P1 - Operational Compliance)
- **Definition**: Models are equivalent if:
  - Every "Analyze Revision" is immediately followed by its own "Check Revision" before any "Rework Case" or "Close Case"
  - "Rework Case" separates analysis attempts
  - Approval occurrences and their placement remain visible
  - The sequence structure around revisions is preserved
- **Label handling**: Labels are distinguished by both content and context (e.g., which revision attempt they belong to).

### Abstracted Dashboard Equivalence (P2 - Executive View)
- **Definition**: Models are equivalent if:
  - Both start with "Open Case" and end with "Close Case"
  - Both contain 1 "Analyze Revision" and 1 "Check Revision"
  - The Boolean fact "a check occurred" is equivalent (collapsing multiple checks)
  - The count of "Analyze Revision" occurrences matches
  - The presence/absence of "Rework Case" matches
  - Approvals and silent behavior are ignored
- **Label handling**: Multiple "Check Revision" labels are collapsed to a single Boolean fact.

## 2. Structural Comparison

| Feature                          | Model A                                                                 | Model B                                                                 | Semantic Consequence                                                                 |
|----------------------------------|-------------------------------------------------------------------------|-------------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| Loop Scope                       | Check inside revision loop                                              | Check concurrent with entire revision loop                              | Model A enforces check per revision attempt; Model B allows checks at any time     |
| Min Check Revision occurrences   | 1 per analysis attempt (must have 1 check per revision)                | 1 (can occur once for all revisions)                                    | Model A requires more checks in multi-revision scenarios                           |
| Max Check Revision occurrences   | Unbounded (one per analysis attempt)                                    | Unbounded (can occur any number of times)                               | Model B allows more flexibility in check placement                                 |
| Check placement                  | Must occur after each "Analyze Revision" before "Rework Case" or exit   | Can occur at any point during the revision loop                         | Model A enforces strict sequencing; Model B allows interleaving                   |
| Optional approval occurrences    | Approval can occur after any check (inside loop)                        | Approval can occur after any analysis (inside loop)                     | Both models allow optional approvals, but placement constraints differ             |
| Concurrency                      | No concurrency                                                          | Check runs concurrently with revision loop                              | Model B introduces potential parallelism between check and revision activities     |
| Join before Close Case           | Sequential join (all revision activities complete before closing)       | Parallel join (check and revision activities complete before closing)   | Model B allows more flexible completion paths                                      |

## 3. Verdicts

| View | Verdict                          | Confidence | Decisive Reason                                                                                     | Caveat                                                                 |
|------|----------------------------------|------------|-----------------------------------------------------------------------------------------------------|------------------------------------------------------------------------|
| P1   | not equivalent                   | High       | Model A enforces check-after-analysis per revision; Model B allows checks at any time               | The operational compliance requirement is violated by Model B          |
| P2   | equivalent only under abstraction| Medium     | Both satisfy dashboard requirements when checks are collapsed to Boolean and approvals are hidden   | Exact interleaving of checks and analyses differs                      |
| P3   | not equivalent                   | High       | Bounded exploration reveals traces unique to each model (see counterexamples)                       | Bounded equivalence doesn't guarantee unbounded equivalence            |

- In Model A, approvals can only occur after a check (inside the loop)
- In Model B, approvals can occur after any analysis (inside the loop)

- This creates different silent behavior patterns that become visible in trace timing

## 5. Bounded Comparison Code

```python
import pm4py
from pm4py.objects.petri_net.utils import reachability_graph
from pm4py.objects.petri_net.utils.petri_utils import add_arc_from_to
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.log.obj import Trace, Event
from collections import deque
from typing import Set, Tuple, Dict, List

def parse_and_convert(tree_str: str) -> Tuple[PetriNet, Marking, Marking]:
    tree = pm4py.parse_process_tree(tree_str)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    return net, im, fm

def is_sound(net: PetriNet, im: Marking, fm: Marking) -> bool:
    return pm4py.check_soundness(net, im, fm)

def get_visible_traces_bounded(net: PetriNet, im: Marking, fm: Marking,
                              max_visible: int = 12, max_analyze: int = 3) -> Set[Tuple[str, ...]]:
    """Breadth-first exploration of visible traces with bounds"""
    visited = set()
    queue = deque()
    initial_state = (im, tuple())
    queue.append(initial_state)
    visited.add((im, tuple()))

    traces = set()

    while queue:
        current_marking, current_trace = queue.popleft()

        if len(current_trace) > max_visible:
            continue

        if current_marking == fm:
            if len(current_trace) > 0:  # Only complete traces
                traces.add(current_trace)
            continue

        enabled_transitions = pm4py.get_enabled_transitions(net, current_marking)

        for trans in enabled_transitions:
            if trans.label is None:  # Silent transition
                new_marking = pm4py.get_marking_after_transition(net, current_marking, trans)
                new_state = (new_marking, current_trace)
                if new_state not in visited:
                    visited.add(new_state)
                    queue.append(new_state)
            else:  # Visible transition
                analyze_count = current_trace.count("Analyze Revision")
                if trans.label == "Analyze Revision" and analyze_count >= max_analyze:
                    continue

                new_marking = pm4py.get_marking_after_transition(net, current_marking, trans)
                new_trace = current_trace + (trans.label,)
                new_state = (new_marking, new_trace)

                if new_state not in visited:
                    visited.add(new_state)
                    queue.append(new_state)

    return traces

def compare_models_bounded(tree_a: str, tree_b: str):
    # Parse and convert both models
    net_a, im_a, fm_a = parse_and_convert(tree_a)
    net_b, im_b, fm_b = parse_and_convert(tree_b)

    # Check soundness
    print("Model A sound:", is_sound(net_a, im_a, fm_a))
    print("Model B sound:", is_sound(net_b, im_b, fm_b))

    # Get bounded traces
    traces_a = get_visible_traces_bounded(net_a, im_a, fm_a)
    traces_b = get_visible_traces_bounded(net_b, im_b, fm_b)

    # Find unique traces
    unique_to_a = traces_a - traces_b
    unique_to_b = traces_b - traces_a

    print(f"\nTotal traces in Model A: {len(traces_a)}")
    print(f"Total traces in Model B: {len(traces_b)}")
    print(f"Traces unique to Model A: {len(unique_to_a)}")
    print(f"Traces unique to Model B: {len(unique_to_b)}")

    print("\nSample traces unique to Model A:")
    for trace in sorted(unique_to_a, key=lambda x: (len(x), x))[:5]:
        print(" -> ".join(trace))

    print("\nSample traces unique to Model B:")
    for trace in sorted(unique_to_b, key=lambda x: (len(x), x))[:5]:
        print(" -> ".join(trace))

    return traces_a, traces_b

# Model definitions
model_a = """->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)"""

model_b = """->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)"""

# Run comparison
traces_a, traces_b = compare_models_bounded(model_a, model_b)
```

## 6. Stochastic and Footprint Comparison

### Footprint Analysis
```python
def compare_footprints(tree_a: str, tree_b: str):
    tree_a_obj = pm4py.parse_process_tree(tree_a)
    tree_b_obj = pm4py.parse_process_tree(tree_b)

    footprint_a = pm4py.discover_footprints(tree_a_obj)
    footprint_b = pm4py.discover_footprints(tree_b_obj)

    print("Model A footprint:")
    print(footprint_a)
    print("\nModel B footprint:")
    print(footprint_b)

    # Check if footprints are equal
    return footprint_a == footprint_b

footprint_equal = compare_footprints(model_a, model_b)
print(f"\nFootprints equal: {footprint_equal}")
```

**Why equal footprints don't imply trace equivalence**:
1. Footprints only capture direct precedence relationships, not complete trace structures
2. They don't distinguish between different loop structures that might produce the same immediate relationships
3. They don't account for silent transitions that affect trace generation
4. They collapse multiple occurrences of the same activity into single relationships

### Stochastic Language Comparison
```python
def compare_stochastic_languages(tree_a: str, tree_b: str, num_traces: int = 1000):
    tree_a_obj = pm4py.parse_process_tree(tree_a)
    tree_b_obj = pm4py.parse_process_tree(tree_b)

    # Generate stochastic languages with uniform probabilities
    # Note: We're inventing transition probabilities here for demonstration
    # In practice, these should come from domain knowledge or logs
    lang_a = pm4py.get_stochastic_language(tree_a_obj, num_traces=num_traces)
    lang_b = pm4py.get_stochastic_language(tree_b_obj, num_traces=num_traces)

    # Compute Earth Mover's Distance
    emd = pm4py.compute_emd(lang_a, lang_b)
    print(f"Earth Mover's Distance: {emd}")

    return emd

emd = compare_stochastic_languages(model_a, model_b)
```

**Limitations of stochastic comparison**:
1. EMD depends on the transition probabilities assigned to silent transitions
2. Different probability assignments can yield different EMD values
3. A low EMD doesn't guarantee trace equivalence - it just shows similarity in the sampled traces
4. The comparison is only as good as the probability model used

## 7. Complexity Comparison

```python
def compare_complexity(tree_a: str, tree_b: str):
    tree_a_obj = pm4py.parse_process_tree(tree_a)
    tree_b_obj = pm4py.parse_process_tree(tree_b)

    # Convert to Petri nets
    net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a_obj)
    net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b_obj)

    # Process tree metrics
    def count_nodes(tree):
        if tree is None:
            return 0
        count = 1
        for child in tree.children:
            count += count_nodes(child)
        return count

    def tree_depth(tree):
        if tree is None or not tree.children:
            return 0
        return 1 + max(tree_depth(child) for child in tree.children)

    def count_leaves(tree):
        if tree is None:
            return 0
        if not tree.children:
            return 1
        return sum(count_leaves(child) for child in tree.children)

    def count_visible_leaves(tree):
        if tree is None:
            return 0
        if not tree.children:
            return 0 if tree.label is None else 1
        return sum(count_visible_leaves(child) for child in tree.children)

    def count_duplicate_labels(tree):
        labels = []
        if tree is not None and tree.label is not None:
            labels.append(tree.label)
        for child in tree.children if tree is not None else []:
            labels.extend(count_duplicate_labels(child))
        return len(labels) - len(set(labels))

    # Petri net simplicity
    simplicity_a = pm4py.simplicity_petri_net(net_a, im_a, fm_a)
    simplicity_b = pm4py.simplicity_petri_net(net_b, im_b, fm_b)

    # Print results
    print("Model A complexity:")
    print(f"  Node count: {count_nodes(tree_a_obj)}")
    print(f"  Depth: {tree_depth(tree_a_obj)}")
    print(f"  Total leaves: {count_leaves(tree_a_obj)}")
    print(f"  Visible leaves: {count_visible_leaves(tree_a_obj)}")
    print(f"  Duplicate labels: {count_duplicate_labels(tree_a_obj)}")
    print(f"  Petri net simplicity: {simplicity_a}")

    print("\nModel B complexity:")
    print(f"  Node count: {count_nodes(tree_b_obj)}")
    print(f"  Depth: {tree_depth(tree_b_obj)}")
    print(f"  Total leaves: {count_leaves(tree_b_obj)}")
    print(f"  Visible leaves: {count_visible_leaves(tree_b_obj)}")
    print(f"  Duplicate labels: {count_duplicate_labels(tree_b_obj)}")
    print(f"  Petri net simplicity: {simplicity_b}")

compare_complexity(model_a, model_b)
```

**Regression Traces** (should be accepted by all models):
1. `Open Case -> Analyze Revision -> Check Revision -> Close Case`
2. `Open Case -> Analyze Revision -> Approve Revision -> Check Revision -> Close Case`
3. `Open Case -> Analyze Revision -> Rework Case -> Analyze Revision -> Check Revision -> Close Case`

**Negative Traces** (should be rejected by simplified model):
1. `Open Case -> Check Revision -> Analyze Revision -> Close Case` (check before analysis)
2. `Open Case -> Analyze Revision -> Close Case` (missing check)

## 9. Final Recommendation

**For Business Views**:
- **P1 (Operational Compliance)**: Use **Model A** as it enforces the required check-after-analysis per revision. The simplified model loses this critical compliance property.
- **P2 (Executive Dashboard)**: The **simplified model** is most appropriate as it preserves the dashboard-relevant properties while being more concise. Model B could also be used but is unnecessarily complex for this view.
- **P3 (Bounded Testing)**: Either model can be used for testing, but **Model A** is preferable as it better represents the operational constraints. The simplified model could miss some compliance violations.

**Simplification Recommendation**:
- The simplified model should **replace Model B** for executive reporting purposes, as it provides the same dashboard-relevant information with less complexity.
- **Do not replace Model A** for operational compliance purposes, as it enforces critical sequencing constraints that the simplified model does not.
- For organizations that need both views, maintain both Model A (for operations) and the simplified model (for reporting), with clear documentation of their different purposes.

**Warning About Bounded Comparison**:
- The bounded comparison (P3) provides evidence of non-equivalence but does not prove unbounded equivalence.
- Some counterexamples may only appear with longer traces (>12 events) or more analysis attempts (>3).
- The bounded analysis is useful for testing but should not be the sole basis for process redesign decisions.
- Always verify critical business rules with formal methods when possible, especially for compliance-critical processes.
