# 2. Shared Assumptions

1. **Event-completion semantics.** Each event is the completion of an activity. Trace order is completion order; equal timestamps are ordered arbitrarily (S7). Therefore no model claim about concurrency is an observed fact — concurrency operators encode *hypotheses* about interval overlap that completion data cannot confirm (D7).
2. **Missing Supplier Confirmation events.** Per S5, an estimated 1–3 of the 7 SC-free traces are corrupted external-component cases, the rest legitimate stocked-component skips (S4). All three models represent SC absence with a single control-flow alternative `XOR(Supplier Confirmation, τ)`. This deliberately conflates "legitimately skipped" and "executed but unlogged". It is the only representable choice without the external/stocked attribute, and it is disclosed as an abstraction, not a claim that the process truly allows arbitrary skipping.
3. **Absent external/stocked attribute.** Because the routing condition is unlogged, the SC choice is modeled as nondeterministic. No model attempts data-aware (guarded) routing.
4. **Optionality representation.** Optional behavior (SC, EX) is encoded as an exclusive choice between the labeled activity and a silent transition; EX occurs at most once (D6) — no loops anywhere, so all three model languages are finite.
5. **Fixed skeleton.** RO is the unique start, and AC → RP → ARC is a strict closing sequence (D1, D2; 30/30 traces). CC ≺ AC and ER ≺ AC always hold (D3; 30/30 traces).
6. **No noise filtering.** All 7 variants, including the singletons, are treated as genuine behavior for fitness purposes; their *generalization* weight differs per candidate.

# 3. Conservative Candidate

**Inductive-bias statement.** This model assumes the log is a complete specification: any trace not literally observed is presumed disallowed until proven otherwise. It maximizes precision and guarantees perfect fitness on the given log, at the cost of near-zero generalization. Its bias is "distrust interpolation": even the symmetric counterpart of an observed trace (e.g., ER-first with Expedite Review after SC) is rejected because it was never seen.

**Compact formal expression.**

```
×( →(RO, CC, ER, SC, AC, RP, ARC),
   →(RO, ER, CC, SC, AC, RP, ARC),
   →(RO, CC, ER, AC, RP, ARC),
   →(RO, ER, CC, AC, RP, ARC),
   →(RO, CC, SC, ER, AC, RP, ARC),
   →(RO, CC, ER, SC, EX, AC, RP, ARC),
   →(RO, ER, CC, EX, SC, AC, RP, ARC) )
```

**Code.**

```python
import pm4py

     "Approve Configuration", "Release Production", "Archive Case"],
    ["Register Order", "Engineering Review", "Credit Check", "Supplier Confirmation",
     "Approve Configuration", "Release Production", "Archive Case"],
    ["Register Order", "Credit Check", "Engineering Review",
     "Approve Configuration", "Release Production", "Archive Case"],
    ["Register Order", "Engineering Review", "Credit Check",
     "Approve Configuration", "Release Production", "Archive Case"],
    ["Register Order", "Credit Check", "Supplier Confirmation", "Engineering Review",
     "Approve Configuration", "Release Production", "Archive Case"],

     "Expedite Review", "Approve Configuration", "Release Production", "Archive Case"],

    return "->( " + ", ".join(f"'{a}'" for a in acts) + " )"

model_conservative = pm4py.parse_process_tree(tree_string)
```

**Duplicate labels and scalability (required discussion).** The XOR enumeration duplicates every activity label across branches (e.g., `Register Order` appears 7 times, `Credit Check` 7 times). Process trees permit this, but: (a) the resulting Petri net has one transition per duplicate, so alignment computation cost grows with the number of variants; (b) precision/generalization metrics behave oddly on trace models (near-perfect precision, degenerate generalization); (c) the construction scales linearly in the number of *variants*, which in real logs grows with log size — with thousands of variants this becomes an unusable "flower's opposite", a memorization. It is defensible here only because there are exactly 7 variants.

**Behavior deliberately excluded.**
- Any unobserved interleaving of CC/ER with SC or EX (e.g., RO, ER, CC, SC, EX, AC, RP, ARC).
- SC after ER without a preceding CC…ER order other than the two observed shapes.
- EX combined with an SC-skip (never observed).
- Any trace where EX appears with the check order CC, ER but before SC (V7's mirror).

**Known underfitting risks.**
- With 30 cases and rare paths (EX seen twice, V5 seen twice), the true process almost certainly has unobserved legal variants; every future legitimate case matching an unseen interleaving will be flagged as deviant.
- The two singleton variants are memorized verbatim — if either is itself a data artifact (S7 tie-breaking), the model enshrines noise while excluding real behavior: simultaneous over- and underfitting.
- Any trace whose SC event is lost by the integration problem (S5) fits only if the corrupted trace happens to collapse onto V3/V4's shape; corrupting V6 yields RO, CC, ER, EX, AC, RP, ARC, which the model rejects.

# 4. Balanced Candidate

**Inductive-bias statement.** This model generalizes exactly where evidence is corroborated from two independent sources (variants + a stakeholder/domain rule) and stays conservative where evidence is single-sourced. It hypothesizes CC ∥ ER (both orders frequent, S2, D7 makes sequence unprovable anyway); keeps the empirically unviolated constraint CC ≺ SC (23/23 SC-traces, plausible business logic: do not commit suppliers before credit clears); drops ER ≺ SC (refuted by V5); and places EX after both checks, unordered with SC (D6, S6, V6+V7). Its bias is "generalize symmetric interleavings, keep every ordering constraint that has zero observed counterexamples."

**Compact formal expression** (strict partial order; χSC = ×(SC, τ), χEX = ×(EX, τ)):

```
Nodes: RO, CC, ER, χSC, χEX, AC, RP, ARC
Edges: RO<CC, RO<ER, CC<χSC, CC<χEX, ER<χEX, ER<AC, CC<AC,
       χSC<AC, χEX<AC, AC<RP, RP<ARC
(CC ∥ ER;  χSC ∥ ER;  χSC ∥ χEX)
```

**How sequence vs. concurrency vs. partial order was decided (per pair).**
- **CC vs. ER — unordered (concurrent).** Both orders observed at high frequency (19 vs. 11 first-completions); S2 asserts parallelism; S1 asserts sequence but is contradicted by 11 traces; D7 says the data cannot decide. When the data cannot refute concurrency and a credible stakeholder asserts it, the partial order leaves the pair unordered. (Encoding a per-case XOR of two sequences would fit equally well but doubles structure without evidence of two distinct sub-populations.)
- **CC vs. SC — ordered CC ≺ SC.** All 23 traces containing SC have CC complete first; zero counterexamples; the constraint also has a plausible causal story. This is an inductive leap (absence of counterexamples in 23 cases is not proof), and it is the first constraint I would re-test with new data.
- **ER vs. SC — unordered.** V5 (2 traces) shows SC completing before ER. Weak evidence (S7 tie-risk), but a hard ER ≺ SC edge would misfit observed cases; the balanced model refuses to misfit any observed trace.
- **EX — after both CC and ER, before AC, unordered with SC.** D6 and S6 agree; V6 (SC before EX) and V7 (EX before SC) jointly show both relative orders. Optionality via XOR with τ; at-most-once by construction (no loop).

**Code.**

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

ro  = Transition("Register Order")
cc  = Transition("Credit Check")
er  = Transition("Engineering Review")
ac  = Transition("Approve Configuration")
rp  = Transition("Release Production")
arc = Transition("Archive Case")
x_sc = OperatorPOWL(Operator.XOR, [Transition("Supplier Confirmation"), SilentTransition()])
x_ex = OperatorPOWL(Operator.XOR, [Transition("Expedite Review"), SilentTransition()])

model_balanced = StrictPartialOrder([ro, cc, er, x_sc, x_ex, ac, rp, arc])
for src, tgt in [
    (ro, cc), (ro, er),
    (cc, x_sc),               # CC before SC: unviolated in all 23 SC-traces
    (cc, x_ex), (er, x_ex),   # D6/S6: Expedite after both checks
    (cc, ac), (er, ac),       # D3
    (x_sc, ac),               # D4
    (x_ex, ac),               # D6
    (ac, rp), (rp, arc),      # D2, D1
]:
    model_balanced.order.add_edge(src, tgt)
```

**Behavior deliberately excluded.**
- SC before CC (e.g., RO, SC, CC, …) — no observed support; violates the retained CC ≺ SC hypothesis.
- SC after ER *only* (RO, ER, SC, CC, …) — the disjunctive D5 reading; excluded because every observed SC follows CC.
- EX before either check completes; EX after AC; more than one EX.
- Skipping CC, ER, AC, RP, or ARC; any repetition of any activity.

**Known underfitting risks.**
- If D5's disjunctive reading is true (SC genuinely needs only *one* check), legitimate ER-then-SC-before-CC cases will be rejected. 23 conforming cases is thin evidence for a hard constraint.
- If EX may legally occur (per some future policy) with only one check complete, the model rejects it — but here D6/S6 explicitly back the constraint.
- If checks are genuinely sequential per S1 and ER-first traces are artifacts, the model is *over*fitting noise rather than underfitting — see Section 10.

# 5. Permissive Candidate

**Inductive-bias statement.** This model treats the domain rules, not the variant list, as the specification, and admits every interleaving they allow. Supplier Confirmation becomes fully concurrent with both checks (dropping even the CC ≺ SC regularity, on the grounds that 23 conforming cases may reflect typical durations rather than a constraint, and that missing-event corruption argues for tolerance); Expedite Review keeps its compliance-backed guard (after both checks, before approval, at most once). Its bias is "everything not forbidden by a medium-or-higher-confidence rule is allowed."

**Compact formal expression.**

```
→( RO,
   ∧( →( ∧(CC, ER), ×(EX, τ) ),
      ×(SC, τ) ),
   AC, RP, ARC )
```

**Code.**

```python
import pm4py

model_permissive = pm4py.parse_process_tree(
    "->( 'Register Order', "
    "    +( ->( +( 'Credit Check', 'Engineering Review' ), "
    "            X( 'Expedite Review', tau ) ), "
    "       X( 'Supplier Confirmation', tau ) ), "
    "    'Approve Configuration', 'Release Production', 'Archive Case' )"
)
```

**Boundary between reasonable generalization and forbidden behavior.**
*Admitted although unobserved:* any interleaving of SC with CC/ER/EX — including SC first (weakest defensible reading: SC is an external interaction that may be initiated early; also tolerant to event-loss reordering). All check orders combined freely with EX presence/absence and SC presence/absence.
*Still forbidden (the hard floor, from medium+ confidence rules):* RP without prior AC (D2); AC before CC or ER complete (D3); SC or EX after AC (D4, D6); EX before both checks complete or more than once (D6, S6); skipping RO, CC, ER, AC, RP, ARC; any activity repetition; anything after ARC (D1). Note the model knowingly over-generalizes relative to D5's own wording (D5 requires at least one check before SC); this is accepted only because D5 is the lowest-confidence rule and SC event-loss (S5) makes SC-position evidence the least trustworthy.

**Behavior deliberately excluded.** The "still forbidden" list above; concretely e.g. RO, EX, CC, ER, AC, RP, ARC and RO, CC, ER, RP, AC, ARC.

**Known underfitting risks.** Essentially none for control-flow *within* this activity set (it fits all 30 observed traces and their rule-consistent recombinations); residual risks: a legal second EX iteration (excluded by D6, but D6 is only medium confidence), and reworks/loops of any activity, which no candidate admits because none were observed.

# 8. Validation Code

```python
"""Self-contained validation for the three candidate models."""
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

# ---------------------------------------------------------------- 1. log
RO, CC, ER, SC, EX = ("Register Order", "Credit Check", "Engineering Review",
                      "Supplier Confirmation", "Expedite Review")
AC, RP, ARC = "Approve Configuration", "Release Production", "Archive Case"

VARIANTS = [
    ([RO, CC, ER, SC, AC, RP, ARC], 12),
    ([RO, ER, CC, SC, AC, RP, ARC],  7),
    ([RO, CC, ER, AC, RP, ARC],      4),
    ([RO, ER, CC, AC, RP, ARC],      3),
    ([RO, CC, SC, ER, AC, RP, ARC],  2),
    ([RO, CC, ER, SC, EX, AC, RP, ARC], 1),
    ([RO, ER, CC, EX, SC, AC, RP, ARC], 1),
]
trace_strings = []
for acts, count in VARIANTS:
    trace_strings.extend([",".join(acts)] * count)
log = pm4py.parse_event_log_string(trace_strings)   # 30 cases
# recent pm4py returns a DataFrame: count cases, not rows/events
assert log["case:concept:name"].nunique() == 30

# ------------------------------------------------------------- 2. models
def _seq(acts):
    return "->( " + ", ".join(f"'{a}'" for a in acts) + " )"

model_conservative = pm4py.parse_process_tree(
    "X( " + ", ".join(_seq(v) for v, _ in VARIANTS) + " )")

ro, cc, er = Transition(RO), Transition(CC), Transition(ER)
ac, rp, arc = Transition(AC), Transition(RP), Transition(ARC)
x_sc = OperatorPOWL(Operator.XOR, [Transition(SC), SilentTransition()])
x_ex = OperatorPOWL(Operator.XOR, [Transition(EX), SilentTransition()])
model_balanced = StrictPartialOrder([ro, cc, er, x_sc, x_ex, ac, rp, arc])
for s, t in [(ro, cc), (ro, er), (cc, x_sc), (cc, x_ex), (er, x_ex),
             (cc, ac), (er, ac), (x_sc, ac), (x_ex, ac), (ac, rp), (rp, arc)]:
    model_balanced.order.add_edge(s, t)

model_permissive = pm4py.parse_process_tree(
    f"->( '{RO}', "
    f"    +( ->( +( '{CC}', '{ER}' ), X( '{EX}', tau ) ), "
    f"       X( '{SC}', tau ) ), "
    f"    '{AC}', '{RP}', '{ARC}' )")

models = {
    "conservative": model_conservative,
    "balanced": model_balanced,
    "permissive": model_permissive,
}

# ------------------------------- 3-4. Petri nets, soundness, quality metrics
nets, results = {}, {}
for name, model in models.items():
    net, im, fm = pm4py.convert_to_petri_net(model)
    nets[name] = (net, im, fm)
    sound = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
    fit  = pm4py.fitness_alignments(log, net, im, fm)
    prec = pm4py.precision_alignments(log, net, im, fm)
    gen  = pm4py.generalization_tbr(log, net, im, fm)
    simp = pm4py.simplicity_petri_net(net, im, fm)
    results[name] = dict(sound=sound[0], fitness=fit["log_fitness"],
                         precision=prec, generalization=gen, simplicity=simp)
    print(f"[{name}] sound={sound[0]} fitness={fit['log_fitness']:.4f} "
          f"precision={prec:.4f} generalization={gen:.4f} simplicity={simp:.4f}")

# ------------------------------------------------ 5. bounded/sampled playout
observed_variants = {",".join(a) for a, _ in VARIANTS}
for name, (net, im, fm) in nets.items():
    sim_log = pm4py.play_out(net, im, fm)   # sampled playout
    sim_variants = {",".join(e["concept:name"] for e in tr) for tr in sim_log}
    unseen = sim_variants - observed_variants
    print(f"[{name}] sampled playout: {len(sim_variants)} distinct variants, "
          f"{len(unseen)} not in the observed log")
    for v in sorted(unseen):
        print("   unseen:", v)
# LIMITATION: playout SAMPLES the model language. It can exhibit admitted
# unobserved behavior but can NEVER prove language inclusion or equality.
# All three models are loop-free (finite languages), yet pm4py exposes no
# exhaustive language-comparison API; conclusions above about "admits exactly
# the 7 variants" rest on the model structure, not on sampling.

# --------------------------------------- 6. positive / negative trace suite
def accepts(net, im, fm, trace_str):
    tiny = pm4py.parse_event_log_string([trace_str])
    fit = pm4py.fitness_alignments(tiny, net, im, fm)
    return fit["log_fitness"] > 0.9999

SUITE = [
    # (trace, expected: conservative, balanced, permissive)
    (",".join([RO, CC, ER, SC, AC, RP, ARC]),        True,  True,  True),   # V1
    (",".join([RO, ER, CC, EX, SC, AC, RP, ARC]),    True,  True,  True),   # V7
    (",".join([RO, ER, CC, SC, EX, AC, RP, ARC]),    False, True,  True),   # recombination
    (",".join([RO, CC, ER, EX, AC, RP, ARC]),        False, True,  True),   # EX with SC skipped
    (",".join([RO, ER, SC, CC, AC, RP, ARC]),        False, False, True),   # SC after ER only (D5)
    (",".join([RO, SC, CC, ER, AC, RP, ARC]),        False, False, True),   # SC before both checks
    (",".join([RO, EX, CC, ER, SC, AC, RP, ARC]),    False, False, False),  # EX before checks (D6)
    (",".join([RO, CC, ER, SC, RP, AC, ARC]),        False, False, False),  # RP before AC (D2)
    (",".join([RO, CC, SC, AC, RP, ARC]),            False, False, False),  # ER skipped (D3)
]
order = ["conservative", "balanced", "permissive"]
for trace, *expected in SUITE:
    for name, exp in zip(order, expected):
        got = accepts(*nets[name], trace)
        status = "OK " if got == exp else "FAIL"
        print(f"{status} [{name}] expected={exp} got={got} :: {trace}")
```

# 9. Recommendation and Data-Collection Plan

**Recommendation.** Use `model_balanced` for immediate operational purposes (documentation, conformance monitoring with manual review of deviations): it fits all 30 cases, every constraint traces to a named rule or an unviolated regularity, and its unobserved admissions are symmetric recombinations of observed patterns. Use `model_permissive` for sensitivity analysis: replay future data against both and inspect the traces that only the permissive model accepts — that delta is precisely the set of behaviors on which the two hypotheses disagree (SC before CC, SC after ER only), so it directly measures how wrong the balanced model's CC ≺ SC assumption is. The conservative model should be retained only as a frozen "as-observed" baseline for audit, not deployed as a norm.

**Data-collection plan.**
1. **Export the external/stocked attribute (S3/S4/S5).** This single attribute separates true SC optionality from missingness: stocked+no-SC = legitimate skip; external+no-SC = lost event. It would let the XOR(SC, τ) abstraction be replaced by data-aware routing and would quantify the S5 loss rate directly.
2. **Fix the SC integration and backfill or flag affected cases**, so future skip statistics are trustworthy.
3. **Collect start *and* complete lifecycle timestamps** for Credit Check, Engineering Review, and Supplier Confirmation. Interval overlap between CC and ER in even a handful of cases would settle D7/S1-vs-S2 (concurrency vs. sequence) — completion-only data can never settle it, no matter the volume.
4. **Record millisecond-precision timestamps or an explicit intra-case sequence number** to eliminate the S7 tie-breaking artifact that undermines the low-count evidence (V5, V7).
5. **Maximally informative future traces to watch for:**
   - *SC before CC completes* (e.g., RO, ER, SC, CC, …): refutes the balanced model's CC ≺ SC edge → move toward permissive.
   - *CC start after ER completion (from lifecycle data) in many cases*: supports S1's sequencing for a sub-population → consider a case-level XOR of sequences instead of concurrency.
   - *External-component cases without SC after the integration fix*: real optionality beyond stocked parts, or residual data loss.
   - *Any EX before one of the checks, or a second EX*: refutes D6 → restructure the expedite guard.
   - *More EX cases in general* (only 2 observed): needed before any EX-related constraint deserves high confidence.

# 10. Uncertainty Statement

Calibrated confidence in the major decisions:

- **Skeleton RO first; AC → RP → ARC tail (all models): ~0.95.** 30/30 traces plus high-confidence rules D1/D2; residual risk is only sample size.
- **CC and ER unordered/concurrent (balanced, permissive): ~0.6.** Both orders are frequent and S2 supports it, but D7 is explicit that completion data cannot prove it, and S1 asserts the opposite.
- **SC optionality via XOR(SC, τ): ~0.7 that some genuine optionality exists** (23% absence far exceeds the 5–10% loss rate), but **low confidence (~0.4) in the exact skip semantics**, since the deciding attribute is unlogged and 1–3 absences are probably data loss.
- **CC ≺ SC (balanced only): ~0.55.** Unviolated in 23 traces with a plausible causal story, but never asserted by any domain rule, and D5 leans against it.
- **EX guard — optional, ≤1, after both checks, before AC: ~0.75 despite only 2 observations**, because compliance (S6) and D6 independently assert it; frequency-related conclusions about EX remain very weak.
- **No loops/rework anywhere: ~0.6.** No repetition in 30 cases, but 30 cases is weak evidence against rework that plausibly exists in custom production (e.g., failed engineering review).

**Alternative interpretation that would materially change the recommendation.** If S1 is correct — Credit Check must finish before Engineering Review starts — then the 11 ER-first completions must be artifacts of near-simultaneous completions ordered by ingestion index (S7) or of ER completions logged late. Under that reading, the true control flow is the sequence RO → CC → ER (→ SC?) → …, the concurrency in the balanced and permissive models is overfitting to logging noise, and the recommended model would become a strict sequence with SC optionality — closer in spirit to the conservative candidate. Lifecycle timestamps (plan item 3) would decide between these two worlds with a handful of cases; this is the single highest-value data investment, and until it is made, the balanced model's concurrency operator should be read as a hypothesis, not a finding.
