## 1. Normalization Assumptions

The conclusions below are conditional on the following explicit assumptions. They are not a claim that any displayed timestamp is the exact event time.

**Interval construction and clock-offset direction**

For each source, first construct the possible **source-clock interval** implied by display resolution. Then apply the clock offset.

If:

\[
\text{clock offset } o = \text{recorded clock} - \text{true clock}, \qquad o\in[a,b]
\]

and the display semantics imply a source-clock interval \(C=[c_\ell,c_h)\), then:

\[
T_{\text{true}}\in[c_\ell-b,\;c_h-a)
\]

The lower true-time bound subtracts the largest possible positive clock offset; the upper bound subtracts the smallest possible offset.

Resolution intervals are:

- **HUB:** displayed second \(r\), source-clock value in \([r-0.5s,r+0.5s]\), then offset \([-1s,+1s]\). Thus the true-time interval is \(r\pm1.5s\).
- **OPS-BER / VENDOR-NY / LEGACY-BER:** displayed minute \(m\) means source-clock time in \([m,m+60s)\), followed by the source offset.
- **SENSOR:** nearest-10-second display \(r\) means source-clock time in \([r-5s,r+5s)\), followed by offset \([-5s,+5s]\).
- **MOBILE-LON:** nearest-minute display \(r\) means source-clock time in \([r-30s,r+30s)\), followed by offset \([-300s,+300s]\).

Rounding endpoints are represented as half-open where appropriate. No conclusion below depends on the inclusion or exclusion of an endpoint.

**Time-zone conversion**

The local source-clock interval is converted to UTC using the applicable IANA time-zone offset:

- June Berlin timestamps use CEST, UTC+02:00.
- June New York timestamps use EDT, UTC04:00.
- June London timestamps use BST, UTC+01:00.
- UTC sources require no zone conversion.

**Independent uncertainty hull**

Unless event-level clock errors are known to be correlated, errors for two events are treated independently within their stated bounds. A duration between start interval \(S\) and end interval \(E\) is therefore represented by the conservative interval hull:

\[
D=[E_\ell-S_h,\;E_h-S_\ell)
\]

A common clock offset across two HUB events could make some durations narrower, but no correlation evidence is supplied, so no cancellation is assumed.

**Negative lower duration bounds**

A negative lower bound means that the timestamp evidence permits the apparent event order to invert. It is not interpreted as a physically negative elapsed duration. For the primary analysis, I retain the negative side because T-407 expressly says that the receipt-before-investigation assumption is not directly logged. Clipping such intervals at zero does not change any classification below.

**DST fold treatment for T-405**

For LEGACY-BER on 2025-10-26, each ambiguous local minute has two possible mappings:

- fold 0, CEST, UTC+02:00;
- fold 1, CET, UTC+01:00.

Resolution and clock correction are applied separately to each fold, producing a union of two UTC intervals.

I treat the stated ingestion sequence as evidence of actual event order:

\[
Alert < Investigation < Containment
\]

The only fold assignment capable of satisfying that order is:

- Alert_Received: fold 0/CEST;
- Investigation_Start: fold 1/CET;
- Containment_Complete: fold 1/CET.

The raw disjoint alternatives are still shown in Section 2. If “ingestion sequence” means only database arrival order, rather than occurrence order, this is weaker semantic evidence and the raw unions must be retained.

**T-404 inferred start**

The signed duration evidence gives:

\[
Investigation\_Start = Investigation\_Complete - d,
\qquad d\in[18,25]\text{ minutes}
\]

The complete event’s HUB uncertainty is retained, so the inferred start interval is:

\[
[10:34:58.5-25m,\;10:35:01.5-18m]
=
[10:09:58.5,\;10:17:01.5]
\]

No midpoint substitution is used.

**T-406 mobile entry delay**

Primary interpretation: the user entered the currently displayed time up to five minutes after the actual investigation start. Entry delay is therefore an additional uncertainty about the **occurrence time**, shifting it backward by \(d\in[0,300]\) seconds:

\[
T_{\text{occurrence}}=T_{\text{mobile clock at entry}}-d-o
\]

This produces a wider occurrence interval. If “late entry” instead means that the user later typed an already-known event time, the delay affects only record provenance, not occurrence time. That alternative is examined in Section 4 because it materially changes S2.

**T-407 inferred receipt**

`Alert_Sent` is not equated with `Alert_Received`. The primary inferred receipt interval is:

\[
Alert\_Received \in Alert\_Sent + [0,20]\text{ minutes}
\]

The plausible but unlogged causal cap `Alert_Received <= Investigation_Start` is tested as a secondary assumption. It does not change the S1 or profile classification.

**T-409 weak clock evidence**

Because NTP diagnostics are missing for that hour, the primary analysis uses the case-specific weak estimate \([-12,+12]\) minutes instead of relying on the normal OPS-BER diagnostic bound \([-90,+120]\) seconds. If the table’s narrower bound is nevertheless treated as a hard invariant, T-409 changes materially; this alternative is shown in Section 4.

**Reference profile setting**

Section 3 uses \(\zeta=2\) as the reference temporal-profile setting. Section 4 evaluates \(\zeta=1,2,3\). The temporal profile is statistical; a profile violation is not automatically a legal or operational SLA violation.

def clock_interval_from_display(recorded: str, rounding: str):
    base = pd.Timestamp(recorded)

    if rounding == "exact_second_pm_half":
        return (
            base - pd.Timedelta(seconds=0.5),
            base + pd.Timedelta(seconds=0.5),
        )
    if rounding == "floor_minute":
        return base, base + pd.Timedelta(minutes=1)
    if rounding == "nearest_10s":
        return base - pd.Timedelta(seconds=5), base + pd.Timedelta(seconds=5)
    if rounding == "nearest_minute":
        return base - pd.Timedelta(seconds=30), base + pd.Timedelta(seconds=30)

    raise ValueError(f"Unknown rounding semantics: {rounding}")

        clock_high_utc = pd.Timestamp(aware_high.astimezone(UTC))

        true_high = clock_high_utc - pd.Timedelta(seconds=offset_low)

        # Primary T-406 semantics: late user entry means occurrence may be earlier.
        delay_low, delay_high = rec.get("entry_delay_s", (0, 0))
        true_low -= pd.Timedelta(seconds=delay_high)
        true_high -= pd.Timedelta(seconds=delay_low)

        alternatives.append(
            UtcInterval(
                true_low,
                true_high,
                label=f"fold={fold}, utc_offset={aware_low.utcoffset()}",
            )
        )

    return alternatives

def merge_intervals(intervals):
    intervals = sorted(intervals, key=lambda x: (x[0], x[1]))
    merged = []
    for low, high in intervals:
        if not merged or low > merged[-1][1]:
            merged.append([low, high])
        else:
            merged[-1][1] = max(merged[-1][1], high)
    return [(low, high) for low, high in merged]


def duration_union(first_alternatives, second_alternatives):
    """
    Cartesian interval hulls. Disjoint unions are merged only when touching.
    """
    result = []
    for first in first_alternatives:
        for second in second_alternatives:
            result.append((second.low - first.high, second.high - first.low))
    return merge_intervals(result)


def classify_duration_union(intervals, acceptance_low=None, acceptance_high=None):
    if not intervals:
        return INDETERMINATE

    # One-sided SLA acceptance: duration <= acceptance_high.
    if acceptance_low is None:
        if all(high <= acceptance_high for _, high in intervals):
            return CERTAIN_PASS
        if all(low > acceptance_high for low, _ in intervals):
            return CERTAIN_VIOLATION
        return POSSIBLE_VIOLATION

    relations = []
    for low, high in intervals:
        if low >= acceptance_low and high <= acceptance_high:
            relations.append("inside")
        elif high < acceptance_low or low > acceptance_high:
            relations.append("outside")
        else:
            relations.append("partial")

    if all(x == "inside" for x in relations):
        return CERTAIN_PASS
    if all(x == "outside" for x in relations):
        return CERTAIN_VIOLATION
    return POSSIBLE_VIOLATION

# PM4Py output shape is version-dependent. This parser is deliberately isolated.
def parse_pm4py_temporal_output(raw):
    """
    Assumed common row layout:
    [case, source_activity, target_activity, duration, diagnostic]

    Some PM4Py versions return a DataFrame, nested lists, dictionaries,
    or a different diagnostic column. Unknown shapes are retained as raw text
    rather than silently reinterpreted.
    """
    known_activities = {
        activity
        for pair in TEMPORAL_PROFILE
        for activity in pair
    } | {"Alert_Sent", "Investigation_Complete"}

    if isinstance(raw, pd.DataFrame):
        lookup = {str(c).strip().lower(): c for c in raw.columns}

        def pick(*names):
            for name in names:
                if name in lookup:
                    return lookup[name]
            return None

        case_col = pick("case", "case_id", "case:concept:name", "caseid")
        source_col = pick(
            "source", "source_activity", "activity_1", "activity1", "first_activity"
        )
        target_col = pick(
            "target", "target_activity", "activity_2", "activity2", "second_activity"
        )
        diagnostic_col = pick(
            "diagnostic", "result", "status", "is_fit", "fit", "deviation"
        )

        if case_col and source_col and target_col:
            return pd.DataFrame(
                {
                    "case": raw[case_col].astype(str),
                    "source": raw[source_col].astype(str),
                    "target": raw[target_col].astype(str),
                    "diagnostic": (
                        raw[diagnostic_col] if diagnostic_col else None
                    ),
                }
            ), "dataframe"

        return pd.DataFrame({"raw_output": [repr(raw)]}), "unparsed_dataframe"

    rows = []

    def visit(obj):
        if isinstance(obj, dict):
            lookup = {str(k).strip().lower(): k for k in obj}

            def pick(*names):
                for name in names:
                    if name in lookup:
                        return lookup[name]
                return None

            case_key = pick("case", "case_id", "case:concept:name", "caseid")
            source_key = pick(
                "source", "source_activity", "activity_1", "activity1"
            )
            target_key = pick(
                "target", "target_activity", "activity_2", "activity2"
            )
            diagnostic_key = pick(
                "diagnostic", "result", "status", "is_fit", "fit", "deviation"
            )

            if case_key and source_key and target_key:
                rows.append(
                    {
                        "case": str(obj[case_key]),
                        "source": str(obj[source_key]),
                        "target": str(obj[target_key]),
                        "diagnostic": (
                            obj[diagnostic_key] if diagnostic_key else None
                        ),
                    }
                )
            else:
                for value in obj.values():
                    visit(value)

        elif isinstance(obj, (list, tuple)):
            if (
                len(obj) >= 5
                and str(obj[1]) in known_activities
                and str(obj[2]) in known_activities
            ):
                rows.append(
                    {
                        "case": str(obj[0]),
                        "source": str(obj[1]),
                        "target": str(obj[2]),
                        "duration_seconds": obj[3],
                        "diagnostic": obj[4],
                    }
                )
            else:
                for value in obj:
                    visit(value)

    visit(raw)

    if rows:
        return pd.DataFrame(rows), "common_row_layout"
    return pd.DataFrame({"raw_output": [repr(raw)]}), "unparsed_shape"


def diagnostic_status(value, zeta):
    if isinstance(value, bool):
        return CERTAIN_PASS if value else CERTAIN_VIOLATION

    text = str(value).strip().lower()
    if text in {"ok", "pass", "passed", "fit", "true", "conforming"}:
        return CERTAIN_PASS
    if text in {
        "deviating",
        "deviation",
        "fail",
        "failed",
        "false",
        "nonconforming",
        "violation",
    }:
        return CERTAIN_VIOLATION

    # Common numeric diagnostic assumption: standardized deviation score.
    try:
        numeric = float(value)
        return CERTAIN_PASS if abs(numeric) <= zeta else CERTAIN_VIOLATION
    except (TypeError, ValueError):
        return "UNPARSED_PM4PY_DIAGNOSTIC"


def point_profile_class(duration_seconds, pair, zeta):
    mean, stddev = TEMPORAL_PROFILE[pair]
    low = mean - zeta * stddev
    high = mean + zeta * stddev
    return CERTAIN_PASS if low <= duration_seconds <= high else CERTAIN_VIOLATION

    print("Raw PM4Py sample:", repr(raw_result)[:1000])

The midpoint log is deliberately labeled as a **lossy approximation**. PM4Py receives one timestamp per event and therefore cannot see rounding intervals, clock-offset intervals, mobile-entry delay, inferred-event uncertainty, or the discarded DST fold. The PM4Py parser assumes a common row layout of case, source activity, target activity, duration, and diagnostic; PM4Py versions that return a DataFrame or another shape are isolated in `parse_pm4py_temporal_output` rather than silently reinterpreted.

Notable expected midpoint behavior is that T-406 can look conforming at its interval midpoint while the interval result remains POSSIBLE_VIOLATION, and T-408’s IC midpoint lies exactly at the =2 profile boundary while the interval straddles it.

## 7. Governance Recommendation

1. **Store UTC as the operational timeline.** Retain UTC event intervals alongside local display values. Local time should be presentation and provenance, not the sole system of record.

2. **Retain raw timestamps.** Preserve the exact source string, displayed precision, source time zone, UTC offset, rounding rule, ingestion time, and source system. Never overwrite the raw value with a normalized midpoint.

3. **Record resolution semantics explicitly.** Distinguish exact-second measurement, floor-to-minute, nearest-minute, nearest-10-second, and free-text entry. A displayed minute should carry a machine-readable interval, not be silently interpreted as `:00`.

4. **Collect clock-offset telemetry with validity windows.** NTP/PTP diagnostics should include measured offset, uncertainty, poll time, stratum/source, and the interval over which the bound is valid. Missing-hour telemetry should automatically widen the event-time interval, as in T-409.

5. **Use event-level synchronization for high-impact boundaries.** Where an SLA margin may be minutes or seconds, require sync markers, cross-system heartbeats, or signed timestamp attestations rather than relying on daily clock averages.

6. **Separate lifecycle semantics.** Maintain distinct fields for `Alert_Sent`, `Alert_Delivered`, `Alert_Received`, `Investigation_Start`, `Investigation_Complete`, `Containment_Complete`, and `Close_Incident`. Completion events should not be treated as starts without explicit duration evidence.

7. **Require start events for enforceable lifecycle SLAs.** A signed duration may support interval inference, as in T-404, but should not permanently replace a first-class start event.

8. **Handle DST folds explicitly.** For ambiguous local times, require `fold`, `utcoffset`, or an unambiguous UTC timestamp. Ingestion order should be labeled as causal/order evidence or merely database arrival order.

9. **Separate user-claimed occurrence time from record time.** Mobile systems should store the user-entered value, device clock at entry, server receipt time, estimated entry delay, and whether the entered value is claimed occurrence time or current display time.

10. **Use causal and provenance identifiers.** Each event should carry incident ID, source event ID, preceding-event references, message/delivery IDs, ingestion sequence, actor/device, and transformation lineage.

11. **Version temporal profiles and  policy.** Profile means, standard deviations, training windows, exclusions, and  should be versioned. A statistical profile deviation should trigger review or model-drift analysis, not automatically constitute a legal SLA breach.

12. **Adopt an explicit interval-enforcement policy.** Recommended policy:
    - `CERTAIN_PASS`: clear conformance.
    - `CERTAIN_VIOLATION`: sufficient for hard-SLA enforcement, subject to appeal and provenance checks.
    - `POSSIBLE_VIOLATION`: trigger evidence collection and operational review; do not impose a punitive finding solely from interval overlap unless policy expressly adopts that risk standard.
    - `INDETERMINATE`: no adverse inference; require missing or semantic evidence.

13. **Define SLA tolerances separately from timestamp uncertainty.** A grace period should be added transparently to the rule threshold, not used to rewrite source timestamps or select midpoints.

14. **Retain both interval and point diagnostics.** Tools such as PM4Py may operate on midpoint logs for exploratory diagnostics, but the authoritative conformance record should retain interval bounds, assumptions, and sensitivity results.
