# 2. Shared Assumptions

- **Abbreviations used in tables and code:**  
  RO = Register Order, CC = Credit Check, ER = Engineering Review, SC = Supplier Confirmation, X = Expedite Review, AC = Approve Configuration, RP = Release Production, AR = Archive Case.

- **Completion-event semantics:**  
  Each observed event is interpreted as a **completion** of the activity, not a start. Therefore, an observed order such as CC before ER only means CC completed before ER completed. It does not prove CC started before ER, that ER started after CC finished, or that the two activities were not overlapping.

- **Same-timestamp ambiguity:**  
  If two activities share a completion timestamp, the log orders them by ingestion index. This order is treated as unreliable for causal or precedence inference.

- **Missing Supplier Confirmation events:**  
  The absence of SC in a trace may mean either:
  1. SC was legitimately not required, e.g., stocked components; or  
  2. SC occurred but was missing due to integration failure.  
  The models cannot distinguish these cases from the provided log.

- **Absent external/stocked attribute:**  
  Because the external/stocked attribute was not exported, SC optionality is represented through **control-flow alternatives**, not through a data-driven condition. This is an abstraction: true optionality and missing data are conflated in the model.

- **Optionality representation:**  
  SC and X are treated as optional. The models use explicit choice alternatives for optional activities. At most one X is enforced in all three candidates based on D6. At most one SC is also enforced as a reasonable simplification; if multiple supplier confirmations are possible, all three models would underfit that behavior.

- **Constraints enforced in all three models:**  
  - RO is the start.  
  - AR is the end.  
  - AC precedes RP.  
  - Both CC and ER precede AC.  
  - If SC occurs, it precedes AC.  
  - If X occurs, it precedes AC and follows both CC and ER.

- **No rework or loops:**  
  The observed traces are linear. All three candidates exclude rework, loops, and repeated RO/AR events. If rework exists, the models will underfit.

# 3. Conservative Candidate

**Inductive bias:**  
The conservative model minimizes generalization. It admits only the seven observed variant shapes, plus the high-confidence start/end and ACRP constraints. It does not infer that CC and ER are interchangeable beyond observed variants, does not infer that SC may occur in unobserved slots, and does not treat missing SC as a reason to admit unobserved SC placements. It is best understood as an XOR enumeration of observed completion-order templates.

**Formal expression:**  
Let M_c be the set of observed middle segments:

```text
M_c = {
  CC, ER, SC
  ER, CC, SC
  CC, ER
  ER, CC
  CC, SC, ER
  CC, ER, SC, X
  ER, CC, X, SC
}
```

Then:

```text
L_conservative = { RO ; m ; AC ; RP ; AR | m  M_c }
```

**PM4Py code:**

```python
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
)
from pm4py.objects.process_tree.obj import Operator

RO = "Register Order"
CC = "Credit Check"
ER = "Engineering Review"
SC = "Supplier Confirmation"
X = "Expedite Review"
AC = "Approve Configuration"
RP = "Release Production"
AR = "Archive Case"

def chain_powl(labels):
    """
    Build a strict partial order that is a total chain.
    Each chain is one observed complete variant.
    """
    powl = StrictPartialOrder()
    trans = [Transition(lbl) for lbl in labels]

    # Register activities if the API exposes such methods.
    for t in trans:
        if hasattr(powl, "add_activity"):
            powl.add_activity(t)
        elif hasattr(powl.order, "add_node"):
            powl.order.add_node(t)

    # Add chain edges.
    for a, b in zip(trans, trans[1:]):
        powl.order.add_edge(a, b)

    # Some POWL implementations expose start/end activity sets.
    try:
        powl.start_activities = {trans[0]}
        powl.end_activities = {trans[-1]}
    except Exception:
        pass

    return powl

conservative_middles = [
    [CC, ER, SC],
    [ER, CC, SC],
    [CC, ER],
    [ER, CC],
    [CC, SC, ER],
    [CC, ER, SC, X],
    [ER, CC, X, SC],
]

conservative_full_variants = [
    [RO] + m + [AC, RP, AR] for m in conservative_middles
]

model_conservative = OperatorPOWL(
    Operator.CHOICE,
    [chain_powl(v) for v in conservative_full_variants]
)
```

**Behavior deliberately excluded:**

- SC after ER but before CC: `RO, ER, SC, CC, AC, RP, AR`.
- X before SC when CC precedes ER: `RO, CC, ER, X, SC, AC, RP, AR`.
- X without SC when ER precedes CC: `RO, ER, CC, X, AC, RP, AR`.
- SC before both CC and ER: `RO, SC, CC, ER, AC, RP, AR`.
- Any SC placement not present in the observed variants.
- Any X placement not present in the observed variants.
- Any rework, loop, repeated activity, or post-AR activity.

**Known underfitting risks:**

- If 5–10% of SC events are missing, some observed no-SC traces may actually be missing-SC traces. The conservative model treats no-SC as true and does not recover unobserved SC placements.
- If CC and ER are truly interchangeable, the model still forbids unobserved combinations, e.g., `ER, SC, CC`.
- If X can occur after both checks in more positions than observed, the model underfits.
- If SC can occur after only ER, the model underfits because only `CC, SC, ER` is observed, not `ER, SC, CC`.
- The model is highly sensitive to logging noise, especially same-timestamp ingestion ordering.

**Duplicate-label and scalability note:**  
The conservative model uses an XOR enumeration. The same activity label appears in multiple branches. When converted to a Petri net, this may create multiple transitions with the same label. Depending on PM4Py’s conversion behavior, this can cause replay ambiguity, larger nets, or, if labels are merged, unintended cross-branch behavior. The approach is also not scalable: if more variants, optional activities, or orderings appear, the number of explicit branches grows rapidly.

# 4. Balanced Candidate

**Inductive bias:**  
The balanced model generalizes the observed completion-order evidence while preserving the strongest domain constraints. It treats CC and ER as unordered at the completion level, allows SC after at least one principal check, and allows X after both principal checks either before or after SC. It does not use an explicit parallel/concurrency operator because completion timestamps alone do not prove concurrency. Instead, it uses a choice of linearizations as a partial-order abstraction over completion order.

**Formal expression:**  
Let M_b be the balanced set of middle segments:

```text
M_b = {
  CC, ER
  ER, CC
  CC, SC, ER
  ER, SC, CC
  CC, ER, SC
  ER, CC, SC
  CC, ER, X
  ER, CC, X
  CC, ER, SC, X
  ER, CC, SC, X
  CC, ER, X, SC
  ER, CC, X, SC
  CC, SC, ER, X
  ER, SC, CC, X
}
```

Then:

```text
L_balanced = { RO ; m ; AC ; RP ; AR | m  M_b }
```

- Any rework or loop.

**Known underfitting risks:**

- If SC may legitimately begin before both CC and ER, the balanced model underfits.
- If SC may occur multiple times, the model underfits.
- If X may occur before both checks in exception cases, the model underfits.
- If the true process contains rework or loops, the model underfits.
- If missing SC events are common and correspond to unmodeled SC slots, the model may still underfit the true underlying process even though it fits the observed log.

**Decision rule for sequence, concurrency, and partial order:**

- **CC and ER:**  
  We do **not** use a hard sequence because both CCER and ERCC are observed. We do **not** use an explicit parallel operator because completion timestamps cannot prove concurrency. We use a **partial-order abstraction over completion order**, implemented as a choice of the two linearizations `CC, ER` and `ER, CC`. If start/end timestamps later show overlap, this can be upgraded to a true parallel operator or a POWL partial order.

- **SC:**  
  D4 requires SC before AC if present. D5 and V5 support SC after only one principal check. Therefore, SC is allowed after CC, after ER, or after both, but not before both in the balanced model. This is a disjunctive placement constraint, which is why the model uses explicit linearization templates rather than a single simple sequence.

- **X:**  
  D6 is medium confidence but clear: X is optional, at most once, after both CC and ER, and before AC. S6 says X may occur before or after SC. Therefore, X is allowed after both checks either before SC or after SC, but not before both checks.

# 5. Permissive Candidate

**Inductive bias:**  
The permissive model admits all completion-order combinations that are broadly consistent with the domain rules, even if not observed. It keeps the high-confidence constraints and the medium-confidence constraints for X, but it relaxes D5 by allowing SC before both principal checks as a controlled uncertainty allowance. This is intended to stress-test the model against missing data and unobserved but not obviously impossible behavior.

```text
  SC, CC, ER
  SC, ER, CC
  SC, CC, ER, X
  SC, ER, CC, X
}
```

Then:

```text
L_permissive = { RO ; m ; AC ; RP ; AR | m  M_p }
```

**Boundary between reasonable generalization and forbidden behavior:**

- **Reasonable generalization:**

  SC before both CC and ER is admitted only because D5 is low-to-medium confidence and missing data may obscure the true process. If D5 is later interpreted strictly as “SC may not begin before at least one principal check completes,” the four SC-before-both branches should be removed.

```python
def chain_powl(labels):
    powl = StrictPartialOrder()
    trans = [Transition(lbl) for lbl in labels]

    for t in trans:
        if hasattr(powl, "add_activity"):
            powl.add_activity(t)
        elif hasattr(powl.order, "add_node"):
            powl.order.add_node(t)

    for a, b in zip(trans, trans[1:]):
        powl.order.add_edge(a, b)

    try:
        powl.start_activities = {trans[0]}
        powl.end_activities = {trans[-1]}
    except Exception:
        pass

    return powl

conservative_middles = [
    [CC, ER, SC],
    [ER, CC, SC],
    [CC, ER],
    [ER, CC],
    [CC, SC, ER],
    [CC, ER, SC, X],
    [ER, CC, X, SC],
]

conservative_full = [
    [RO] + m + [AC, RP, AR] for m in conservative_middles
]

model_conservative = OperatorPOWL(
    Operator.CHOICE,
    [chain_powl(v) for v in conservative_full]
)

# Fallback ProcessTree for conservative model, used only if POWL conversion fails.
conservative_alt_strings = [f"({', '.join(m)})" for m in conservative_middles]
model_conservative_tree = pm4py.parse_process_tree(
    f"({RO}, [{', '.join(conservative_alt_strings)}], {AC}, {RP}, {AR})"
)

# ------------------------------------------------------------------
# Balanced model: ProcessTree choice of balanced linearizations
# ------------------------------------------------------------------
balanced_middles = [
    [CC, ER],
    [ER, CC],
    [CC, SC, ER],
    [ER, SC, CC],
    [CC, ER, SC],
    [ER, CC, SC],
    [CC, ER, X],
    [ER, CC, X],
    [CC, ER, SC, X],
    [ER, CC, SC, X],
    [CC, ER, X, SC],
    [ER, CC, X, SC],
    [CC, SC, ER, X],
    [ER, SC, CC, X],
]

balanced_strings = [f"({', '.join(m)})" for m in balanced_middles]
model_balanced = pm4py.parse_process_tree(
    f"({RO}, [{', '.join(balanced_strings)}], {AC}, {RP}, {AR})"
)

# ------------------------------------------------------------------
# Permissive model: ProcessTree choice of permissive linearizations
# ------------------------------------------------------------------
permissive_middles = balanced_middles + [
    [SC, CC, ER],
    [SC, ER, CC],
    [SC, CC, ER, X],
    [SC, ER, CC, X],
]

permissive_strings = [f"({', '.join(m)})" for m in permissive_middles]
model_permissive = pm4py.parse_process_tree(
    f"({RO}, [{', '.join(permissive_strings)}], {AC}, {RP}, {AR})"
)

# ------------------------------------------------------------------
# Reconstruct the 30-case log
# ------------------------------------------------------------------
log_counts = [
    (12, [CC, ER, SC]),
    (7, [ER, CC, SC]),
    (4, [CC, ER]),
    (3, [ER, CC]),

trace_strings = []
for count, middle in log_counts:

log = pm4py.parse_event_log_string(trace_strings)
print("log traces:", len(log))

# ------------------------------------------------------------------
# Helper: convert model to Petri net with initial/final markings
# ------------------------------------------------------------------
def to_net(model, fallback=None):
    try:
        conv = pm4py.convert_to_petri_net(model)
    except Exception:
        if fallback is None:
            raise
        conv = pm4py.convert_to_petri_net(fallback)

    if isinstance(conv, tuple):
        net, im, fm = conv
    else:
        net = conv
        im = getattr(net, "im", None)
        fm = getattr(net, "fm", None)

        if im is None:
            try:
                im = pm4py.get_petri_net_im(net)
            except Exception:
                im = None

        if fm is None:
            try:
                fm = pm4py.get_petri_net_fm(net)
            except Exception:
                fm = None

    return net, im, fm

# ------------------------------------------------------------------
# Helper: soundness
# ------------------------------------------------------------------
def soundness(net, im, fm):
    try:
        return pm4py.check_soundness(net, im, fm, print_diagnostics=True)
    except Exception as e:
        return f"soundness error: {e}"

# ------------------------------------------------------------------
# Helper: metrics with fallbacks
# ------------------------------------------------------------------
def metric(fn_name, log=None, net=None, im=None, fm=None):
    candidates = [fn_name]

    if fn_name.startswith("fitness"):
        candidates.append("fitness_replay")

    if fn_name.startswith("precision"):
        candidates.append("precision_tbr")

    last_err = None

    for name in candidates:
        fn = getattr(pm4py, name, None)
        if fn is None:
            continue

        try:
            if name.startswith("simplicity"):
                return fn(net, im, fm)
            return fn(log, net, im, fm)
        except Exception as e:
            last_err = e

    return f"unavailable or error: {last_err}"

# ------------------------------------------------------------------
# Helper: normalize playout traces
# ------------------------------------------------------------------
def normalize_trace(trace):
    if trace is None:
        return []

    if isinstance(trace, str):
        return [trace]

    if isinstance(trace, (list, tuple)):
        if len(trace) > 0 and isinstance(trace[0], dict):
            return [
                e.get("concept:name", e.get("activity", str(e)))
                for e in trace
            ]
        return [str(x) for x in trace]

    return [str(trace)]

# ------------------------------------------------------------------
# Helper: bounded playout
# ------------------------------------------------------------------
def play_out_bounded(model, net, im, fm, expected, max_depth=12, max_traces=10000):
    used_fallback = False

    try:
        gen = pm4py.play_out(model, max_depth=max_depth, max_traces=max_traces)
    except Exception:
        try:
            gen = pm4py.play_out(net, im, fm, max_depth=max_depth, max_traces=max_traces)
        except Exception:
            gen = expected
            used_fallback = True

    if gen is None:
        gen = expected
        used_fallback = True

    try:
        iterator = iter(gen)
    except TypeError:
        iterator = iter(expected)
        used_fallback = True

    traces = []
    for t in iterator:
        traces.append(tuple(normalize_trace(t)))
        if len(traces) >= max_traces:
            break

    if not traces:
        traces = [tuple(t) for t in expected]
        used_fallback = True

    return traces, used_fallback

# ------------------------------------------------------------------
# Expected finite languages for the three candidates
# ------------------------------------------------------------------
expected_by_model = {
    "conservative": [tuple(t) for t in conservative_full],
    "balanced": [tuple([RO] + m + [AC, RP, AR]) for m in balanced_middles],
    "permissive": [tuple([RO] + m + [AC, RP, AR]) for m in permissive_middles],
}

models = {
    "conservative": (model_conservative, model_conservative_tree, expected_by_model["conservative"]),
    "balanced": (model_balanced, None, expected_by_model["balanced"]),
    "permissive": (model_permissive, None, expected_by_model["permissive"]),
}

# ------------------------------------------------------------------
# Positive and negative trace suite
# ------------------------------------------------------------------
positive_by_model = {
    "conservative": expected_by_model["conservative"],
    "balanced": expected_by_model["balanced"],
    "permissive": expected_by_model["permissive"],
}

negative_traces = [
    # Missing principal checks before AC.
    [RO, AC, RP, AR],

    # RP before AC.
    [RO, CC, ER, RP, AC, AR],

    # AR not last.
    [RO, CC, ER, SC, AC, RP, AR, RO],

    # X before both principal checks.
    [RO, X, CC, ER, AC, RP, AR],

    # Multiple SC.
    [RO, CC, ER, SC, SC, AC, RP, AR],

    # Multiple X.
    [RO, CC, ER, X, X, AC, RP, AR],
]

# ------------------------------------------------------------------
# Run validation
# ------------------------------------------------------------------
for name, (model, fallback, expected) in models.items():
    net, im, fm = to_net(model, fallback)

    print(f"\n=== {name} ===")
    print("soundness:", soundness(net, im, fm))
    print("fitness:", metric("fitness_alignments", log, net, im, fm))
    print("precision:", metric("precision_alignments", log, net, im, fm))
    print("generalization:", metric("generalization_tbr", log, net, im, fm))
    print("simplicity:", metric("simplicity_petri_net", net, im, fm))

    played, used_fallback = play_out_bounded(model, net, im, fm, expected)
    played_set = set(played)
    expected_set = set(expected)

    print("playout used expected fallback:", used_fallback)
    print("played count:", len(played_set))
    print("expected count:", len(expected_set))
    print("expected missing from playout:", expected_set - played_set)
    print("extra traces in playout:", played_set - expected_set)

    print("positive suite:")
    for trace in positive_by_model[name]:
        accepted = tuple(trace) in played_set
        print("  accepted:", accepted, trace)

    print("negative suite:")
    for trace in negative_traces:
        accepted = tuple(trace) in played_set
        print("  accepted:", accepted, trace)
```

**Limitation statement:**  
Bounded or sampled playout does **not** prove language inclusion or equivalence. If a model contains loops or an infinite language, bounded playout can only sample part of the language. In the three candidates above, the intended languages are finite because no loop operator is used, but PM4Py playout is still treated as a bounded diagnostic, not a formal proof.

# 9. Recommendation and Data-Collection Plan

**Recommended candidate for immediate use:**  
Use **`model_balanced`** for immediate operational monitoring and compliance screening. It fits all observed variants, enforces the high-confidence constraints, and generalizes only where the evidence and domain rules support it: CC/ER completion order is unordered, SC may follow at least one principal check, and X may occur before or after SC after both checks. It avoids the most risky unobserved behavior, such as SC before both checks, while still being more robust than the conservative model.

**Recommended candidate for sensitivity analysis:**  
Use **`model_conservative`** as the primary sensitivity-analysis baseline. It shows what happens if only observed behavior is admitted. Additionally, run **`model_permissive`** as a stress test to measure how much extra behavior is admitted when D5 is weakened and SC-before-both is allowed. The gap between conservative, balanced, and permissive precision/fitness results will quantify the cost of uncertainty.

**Data-collection plan to resolve ambiguities:**

1. **Collect start and completion timestamps for every activity.**  
   Required attributes:
   - `start_time`
   - `end_time`
   - `activity`
   - `case_id`

   This is the most important change. It distinguishes:
   - CC and ER sequential: one starts after the other ends.
   - CC and ER concurrent/overlapping: start/end intervals overlap.
   - Same-timestamp completion ambiguity: ingestion index no longer determines true order.

2. **Export the external/stocked component attribute.**  
   Required attributes:
   - `external_component` boolean
   - `stocked_component` boolean
   - `component_id`
   - `supplier_id`

   This distinguishes true SC optionality from missing SC data.

3. **Collect SC lifecycle timestamps.**  
   Required attributes:
   - `sc_requested_time`
   - `sc_confirmed_time`
   - `sc_missing_flag`
   - `integration_status`

   This tests whether SC can begin after only one principal check, as in D5.

4. **Collect Expedite Review metadata.**  
   Required attributes:
   - `expedite_reason`
   - `expedite_approved_by`
   - `expedite_requested_time`
   - `expedite_completed_time`

   This validates D6 and the relationship between X and SC.

5. **Collect same-timestamp group metadata.**  
   Required attributes:
   - `timestamp_group_id`
   - `ingestion_index`
   - `source_system`

   This allows analysis of whether ingestion-index ordering creates apparent precedence.

**Future traces that would be maximally informative:**

- **Concurrent CC/ER traces with start/end overlap:**  
  Example: CC and ER start before either ends. This would support replacing the balanced partial-order abstraction with a true parallel/concurrency model.

- **SC after only one principal check with SC start timestamp:**  
  Example: CC completes, SC starts, ER completes later. This would strongly support D5.

- **SC before both principal checks:**  
  If observed and justified by domain rules, it would support the permissive model. If never observed and ruled out by stakeholders, it would support removing SC-before-both branches.

- **Stocked-component no-SC traces with explicit `stocked_component = true`:**  
  This would validate true optionality of SC.

- **External-component traces with missing SC flag:**  
  This would quantify missingness and show whether no-SC observed traces are data-quality artifacts.

- **Expedite Review traces with X before and after SC:**  
  These would validate S6 and help determine whether X/SC order is truly free after both principal checks.

- **Deliberately instrumented same-timestamp completion cases:**  
  These would test whether ingestion-index ordering creates false DFG edges.

# 10. Uncertainty Statement

| Major modeling decision | Calibrated confidence | Alternative interpretation that would materially change recommendation |
|---|---:|---|
| RO is start and AR is end | 0.95 | If post-archive corrections or pre-registration activities exist, all models need additional start/end alternatives. |
| AC must precede RP | 0.95 | If emergency production release can bypass approval, D2 is false and all models are non-compliant. |
| Both CC and ER must precede AC | 0.85 | If approval can occur after only one principal check in exception cases, D3 is too strong and all models underfit. |
| CC and ER are unordered at completion level | 0.70 | If S1 is true and CC must finish before ER starts, then balanced/permissive models overfit by admitting ER-before-CC and SC-after-ER-before-CC. A CCER sequence model would be preferred. |
| CC and ER are not asserted as concurrent | 0.80 | If start/end timestamps show frequent overlap, the balanced model should be upgraded from a completion-order choice to a true parallel/concurrency model. |
| SC is optional | 0.70 | If SC is mandatory for all external components and missing SC events are rare, no-SC branches should be treated as data-quality exceptions, not legitimate process behavior. |
| SC must precede AC when present | 0.80 | If SC can be completed after AC in exception paths, all models underfit and need post-approval SC branches. |
| SC may follow at least one principal check | 0.60 | If D5 is false and SC must wait for both CC and ER, balanced and permissive models overfit by admitting `CC, SC, ER` and `ER, SC, CC`. |
| SC before both checks is possible | 0.35 | If stakeholders confirm SC cannot begin before at least one check, the permissive model is too permissive and should be rejected. |
| X is optional, at most once, after both checks, before AC | 0.75 | If X can occur before both checks in emergency cases, or multiple X events are possible, all models underfit. |
| X may occur before or after SC | 0.70 | If compliance requires X strictly before SC or strictly after SC, the balanced and permissive models must be constrained accordingly. |
| Missing SC events are material | 0.75 | If missing SC is negligible, conservative or balanced models may be sufficient. If missing SC is common, permissive or attribute-conditioned models are needed. |
| Balanced model is the best immediate compromise | 0.70 | If the organization prioritizes strict auditability over generalization, conservative should be used instead. If the organization prioritizes robustness to missing data over precision, permissive may be preferred. |
