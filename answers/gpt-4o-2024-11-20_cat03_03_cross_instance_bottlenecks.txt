## 1. Interaction-graph description

An object-centric interaction graph connects different object types (nodes) based on their dependencies and interactions (edges). In this case, the relevant node types, edge types, and higher-order patterns can be summarized as follows:

### Important Node Types
1. **Job** (`J1`–`J6`): Represents the six production jobs.
2. **Component** (`C1`–`C6`): Materials required for the jobs.
3. **ComponentLot** (`L7`, `L8`): Groupings of components.
4. **Machine** (`CNC-2`, `OVEN-1`, `TEST-1`): Machines performing operations.
5. **Tool** (`FIX-A`, `RACK-7`, `CAL-3`): Tools required during operations and calibration.
6. **Batch** (`B1`, `B2`): Groups of jobs processed together.
7. **Shipment** (`S1`–`S3`): Consolidated dispatches of completed jobs.

### Important Edge Types and Qualifiers
1. **Job requires Component** (e.g., `J1 -> C1`): Recorded directly.
2. **Job batched in Batch** (e.g., `J1 -> B1`): Recorded directly.
3. **Batch processed on Machine** (e.g., `B1 -> OVEN-1`): Recorded directly.
4. **Job requires Tool** (e.g., `J3 -> FIX-A`): Inferred from acquire/release events.
5. **Job grouped in Shipment** (e.g., `J1 -> S1`): Recorded directly.
6. **Component in ComponentLot** (e.g., `C2 -> L7`): Recorded directly.
7. **ComponentLot processed via Quarantine/Release** (e.g., `L7 -> Release`): Recorded directly but inconsistently mapped to Jobs.

### Higher-Order Motifs (Involving >2 Object Types)
1. **Batch Synchronization:** Jobs (`J1`, `J2`, `J3`) -> Batch (`B1`) -> Machine (`OVEN-1`) -> Tool (`RACK-7`).
2. **Tool Contention:** Job (`J4`) -> Machine (`CNC-2`) -> Tool (`FIX-A`).
3. **Shipment Dependency:** Jobs (`J1`, `J4`) -> Shipment (`S1`) -> Dispatch timing locks.
4. **Component Lot Release Coupling:** Jobs (`J2`, `J5`) -> Component Lot (`L7`) -> Release synchronization.

### Direct Observations vs. Inferences
- **Direct Observations:** Job requirements, batch formation, machine processing, shipments, and component lot relationships.
- **Inferences:** Tool allocations (via acquire/release), idle times, and implicit dependencies through waiting periods.

### Compact Edge List Representation
```
J1 -> C1, J2 -> C2, J3 -> C3, J4 -> C4, J5 -> C5, J6 -> C6
C2 -> L7, C5 -> L7, C1 -> L8, C3 -> L8
J1 -> B1, J2 -> B1, J3 -> B1, J4 -> B2, J5 -> B2
B1 -> OVEN-1, B2 -> OVEN-1, OVEN-1 -> RACK-7
J1 -> S1, J4 -> S1, J2 -> S2, J3 -> S2, J5 -> S3, J6 -> S3
J3 -> FIX-A, J4 -> FIX-A
CAL-3 -> TEST-1
```

## 2. Quantitative Delay Decomposition

### 1. Synchronization-Induced Waiting for J1 and J2 in Batch B1
- **Observation:** `J1` ready at 08:10; `J2` ready at 08:25; Batch starts at 12:05.
- **Delay Calculation:**
  - J1 waits: \(12:05 - 08:10 = 3 \, \text{h} \, 55 \, \text{min}\).
  - J2 waits: \(12:05 - 08:25 = 3 \, \text{h} \, 40 \, \text{min}\).
  - Total avoidable delay for J1 and J2 (if B1 started earlier): Sum of waiting = \(3:55 + 3:40 = 7:35\).
- **Counterfactual Assumption:** If J3’s readiness (11:55) did not delay B1.

---

### 2. Delay Associated with FIX-A for J4
- **Observation:** J3 holds `FIX-A` from 09:00–11:40; J4 wants it at 09:50 but starts at 11:45.
- **Delay Calculation:** CNC-2 idle from 10:05–10:47 because J4 lacks `FIX-A`.
  - Total avoidable tool delay for J4: \(11:45 - 10:05 = 1 \, \text{h} \, 40 \, \text{min}\).
- **Counterfactual Assumption:** J3 releases FIX-A earlier so CNC-2 can start.

---

### 3. Delay Imposed on J1 by S1 Consolidation
- **Observation:** `J1` packed at 13:30; `J4` packed at 19:10; shipment dispatches at 19:25.
- **Delay Calculation:** \(19:25 - 13:30 = 5 \, \text{h} \, 55 \, \text{min}\).
- **Counterfactual Assumption:** S1 permitted partial dispatch instead of waiting for J4.

---

### 4. Delay Associated with CAL-3 for J6
- **Observation:** CAL-3 recalibrates from 16:35–17:20 after J5 finishing at 16:35. J6 starts at 17:25.
- **Delay Calculation:** \(17:25 - 16:05 = 1 \, \text{h} \, 20 \, \text{min}\).
- **Counterfactual Assumption:** CAL-3 recalibrates proactively or a second calibration tool exists.

---

### 5. Time OVEN-1 is Idle due to RACK-7 Cleaning
- **Observation:** `RACK-7` cleans from 12:55–14:35; B2 is delayed until 14:50 for RACK-7 availability.
- **Delay Calculation:** \(14:50 - 12:55 = 1 \, \text{h} \, 55 \, \text{min}\).
- **Counterfactual Assumption:** Additional rack availability or faster cleaning.

## 4. What Flattening Misses

### Job Flattening
- **Visible:** Duration per job and isolated task timings.
- **Hidden:** Inter-job dependencies via batches, tools, or lots.

### Machine Flattening
- **Visible:** Utilization and idle windows.
- **Hidden:** Job-specific effects; does not tie delays to batching or tools.

### Batch Flattening
- **Visible:** Synchronous delays within a batch (e.g., B1, B2).
- **Hidden:** Job readiness not uniformly tied to batch starts.

### Tool Flattening
- **Visible:** Contention spans (e.g., FIX-A).
- **Hidden:** Job-machine-tool combinations.
