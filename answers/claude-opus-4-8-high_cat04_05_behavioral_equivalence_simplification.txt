# 1. Equivalence Notions

Throughout, let `O = Open Case`, `A = Analyze Revision`, `C = Check Revision`, `R = Rework Case`, `Ap = Approve Revision`, `X = Close Case`, and `tau` = silent step. A *complete trace* is a firing sequence from the initial marking to the final marking of the accepting Petri net obtained from the tree.

**Label treatment.** Both trees use each visible label exactly once as a *leaf*, but every leaf inside a loop can fire many times. I therefore treat visible labels **by label only** in the observed language (two occurrences of `C` are indistinguishable to an observer), while internally, for reasoning about counterexamples, I track **occurrence position** (which iteration produced which event). Identity-based distinction (tagging the *i*-th `A` as `A_i`) is *not* part of any observation model below; it is used only as scaffolding in prose. This choice matters: under label-only observation, Model A traces such as `A C A C` and `A A C C` differ, but relabeling cannot hide the *count* of `C`.

**(a) Visible trace equivalence after hiding `tau`.** Let `Vis(M)` be the set of complete traces of `M` with every `tau` (including the silent branch of `X(Approve, tau)` and the loop's internal skips) projected out. Models are *visible-trace equivalent* iff `Vis(A) = Vis(B)` as sets of finite words over `{O,A,C,R,Ap,X}`. This is language (not bisimulation) equivalence: branching structure is ignored.

**(b) Bounded visible-language equivalence (P3).** Fix the bound `B = {complete traces with ≤ 12 visible events and ≤ 3 occurrences of A}`. Models are *bounded-equivalent* iff `Vis(A) ∩ B = Vis(B) ∩ B`. Bounded equality is *evidence*, never proof: two models can agree on every trace in `B` and diverge at length 13 or at the 4th analysis attempt.

**(c) Business-relevant equivalence (P1, operational compliance).** Define the P1 observation to keep all visible labels *and their multiplicities and relative order*, but abstract silent steps. The compliance-critical invariant is: **each `A` in an iteration is accompanied by exactly one `C` in the same iteration, before the next `R` or before `X`.** Two models are P1-equivalent iff their `tau`-hidden languages are equal *and* both enforce the "one dedicated `C` per `A`, count(C) = count(A)" invariant with the same admissible interleavings per iteration. Because P1 explicitly says "number and placement of approvals remains visible," `Ap` occurrences are observed.

**(d) Abstracted dashboard equivalence (P2).** Define an abstraction map `α` on a `tau`-hidden trace:
- delete all `Ap`;
- replace the whole multiset of `C` occurrences by a single Boolean `chk = (count(C) ≥ 1)`;
- record `nA = count(A)` and `rework = (count(R) ≥ 1)`;
- keep `O` first, `X` last;
- discard the exact interleaving of `A` and `C`.
So `α(trace) = (O, nA, chk, rework, X)`. Two models are P2-equivalent iff `{ α(t) : t ∈ Vis(M) }` is equal for both. This is the coarsest notion here.

Summary of strength: (c) P1 ⇒ (a) visible-trace ⇒ (b) bounded; (d) P2 is coarser than all and is implied by (a) but not conversely.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | Loop body = `->(+(A,C), X(Ap,tau))`; redo = `R` | Loop body = `->(A, X(Ap,tau))`; redo = `R`; loop is *inside* a `+` with a single `C` | In A the check is regenerated every iteration; in B a single check exists for the whole run. |
| Min `C` occurrences | 1 (one iteration is mandatory, and it contains a `C`) | 1 (the single `C` leaf always fires) | Both have ≥ 1 `C`; equal minimum masks the difference. |
| Max `C` occurrences | Unbounded; `count(C) = count(A) =` number of iterations | Exactly 1, regardless of iterations | Decisive divergence: A ties `C` to iterations, B fixes `C` at one. |
| Placement of `C` | Interleaved with the *same-iteration* `A` only (via `+(A,C)`), never crossing `R` | Anywhere in the whole loop run (before `O`? no — after `O`, before `X`), may fall before any `A`, between iterations, after the last `A`, even after an `R` | B allows `C` in positions A forbids (e.g. `A R A ... C`), and allows `C` before the first `A`. |
| Optional `Ap` | One optional `Ap` per iteration ⇒ `0 ≤ count(Ap) ≤ count(A)` | One optional `Ap` per iteration ⇒ `0 ≤ count(Ap) ≤ count(A)` | Same per-iteration approval semantics; not a distinguishing feature. |
| Concurrency | Local: `+(A,C)` inside each iteration (2-way interleave per iteration) | Global: `+(C, loop)`; a single `C` interleaves with the entire, arbitrarily long loop | Different concurrency *scope* is the root cause of all language differences. |
| Join before `Close Case` | Loop must exit (its final `A/C` iteration completes) then `->` to `X` | The `+` must synchronize: both the single `C` and the whole loop must finish before `X` | In B, `C` may still be "pending" while loop iterates; the join defers `X` until `C` fired. In A there is nothing to defer. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| Visible trace equivalence (after hiding `tau`) | not equivalent | high | `count(C)` is unbounded and equals `count(A)` in A, but is fixed at exactly 1 in B; any run with ≥ 2 iterations differs. | With exactly one iteration and specific interleavings the languages overlap, so they are not *disjoint*. |
| P3 bounded (≤ 12 visible, ≤ 3 `A`) | not equivalent | high | Already within the bound: a 2-`A` trace in A has 2 `C`'s (`O A C R A C X`), impossible in B (only 1 `C`). | Some short single-iteration traces coincide, so bounded intersection is non-empty; equality fails, not membership. |
| P1 operational compliance | not equivalent | high | P1 requires "every analysis revision must have its own `Check Revision`." A enforces `count(C)=count(A)`; B provides a single shared `C`, violating "its own check" for the 2nd+ analysis. | If a case never reworks (exactly one `A`), both satisfy P1 for that single trace family. |
| P2 executive dashboard | equivalent only under stated abstraction | medium-high | Under `α`, `C` collapses to `chk = true` (both always have ≥ 1 `C`), `nA` and `rework` are recoverable identically, `Ap`/`tau` are hidden ⇒ identical abstract tuples. | Requires the *global* join in B to still force `X` last and `O` first, which holds; equivalence is destroyed if the dashboard ever cares about per-attempt checks. |

# 4. Counterexample Traces

I do **not** claim a clean one-directional inclusion; each model admits traces the other forbids, so I give witnesses in both directions. Notation: traces are `tau`-hidden and shown with `Ap` where a revision was approved.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| T1 | `O A C R A C X` | yes | no | Two iterations ⇒ two `C` in A; B has only one `C` leaf, cannot produce a second `C`. | (a),(b),P1 |
| T2 | `O A C Ap R A C Ap X` | yes | no | Same as T1 with both revisions approved; B still cannot supply the 2nd `C`. | (a),(b),P1 |
| T3 | `O C A X` | no | yes | `C` fires *before* the only `A`. In A, `C` is inside `+(A,C)` of the iteration and can precede `A` — so actually A also admits `C A` within one iteration; but B additionally admits `C` with the loop, and the decisive B-only case is T4/T5. (See note.) | (a) |
| T4 | `O A R A C X` | no | yes | Two `A` iterations but only one `C`, placed after the second `A`. A forces a `C` in the first iteration too (`count(C)=count(A)=2`); B allows a single global `C`. | (a),(b),P1 |
| T5 | `O A Ap R A Ap C X` | no | yes | Two approved analyses, single trailing `C`; A would require two `C`'s. | (a),(b),P1 |

Note on T3: single-iteration interleavings such as `O C A X` and `O A C X` are admitted by **both** models (A via the local `+(A,C)`, B via the global `+(C, loop)` with one iteration). T3 is therefore *not* a clean separator and is listed only to show where the languages overlap. The genuine B-only witnesses are **T4 and T5**, whose defining feature is *two analysis attempts served by a single check*. The genuine A-only witnesses are **T1 and T2**, defined by *two checks*. This satisfies the requirement of at least two A-only and two B-only traces (T1, T2 vs. T4, T5), and at least one counterexample per direction contains two analysis attempts (all of T1, T2, T4, T5 do).

**Effect of optional `Ap` and hidden `tau`.** `Ap` is orthogonal to the decisive difference: for every witness with `Ap` there is a twin without it (T1↔T2, T4↔T5), because `X(Approve, tau)` inserts either `Ap` or nothing per iteration in *both* models identically. Hiding `tau` removes the silent skip branch and the loop's internal `tau`s but does **not** merge the languages, because the surviving observable difference is the *cardinality and placement of `C`*, which no amount of `tau`-hiding can equalize. Thus optional approval and silence are red herrings for equivalence; the check-scope is the whole story.

# 5. Bounded Comparison Code

```python
"""
Bounded visible-language comparison of Model A and Model B.
EXHAUSTIVE BFS over Petri-net markings up to a visible-length bound and an A-count bound.
This is exact within the bound (P3), NOT a proof of unbounded equivalence.
"""
import pm4py
from collections import deque

MODEL_A = """->('Open Case', *( ->( +('Analyze Revision','Check Revision'),
                                   X('Approve Revision', tau) ),
                              'Rework Case'), 'Close Case')"""
MODEL_B = """->('Open Case', +('Check Revision',
                               *( ->('Analyze Revision', X('Approve Revision', tau)),
                                  'Rework Case')), 'Close Case')"""

MAX_VISIBLE = 12
MAX_A = 3

def build(tree_str):
    tree = pm4py.parse_process_tree(tree_str)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    sound = pm4py.check_soundness(net, im, fm)  # returns (bool, ...) or bool depending on version
    return tree, net, im, fm, sound

def marking_key(m):
    # hashable, order-independent representation of a marking (place -> tokens)
    return frozenset((p.name, c) for p, c in m.items())

def bounded_language(net, im, fm, max_visible=MAX_VISIBLE, max_a=MAX_A):
    """
    Exhaustive BFS. State = (marking, visible_trace_tuple).
    We bound the SEARCH by visible length and by count of 'Analyze Revision'.
    Silent transitions (t.label is None) extend the marking but not the visible trace.
    A state is accepted when marking == fm.
    To keep the search finite in the presence of loops, we cap visible length; because
    every loop iteration emits at least one visible event ('Analyze Revision'),
    the visible-length cap makes the reachable set finite.
    """
    from pm4py.objects.petri_net.semantics import ClassicSemantics
    sem = ClassicSemantics()
    accepted = set()
    A_LABEL = 'Analyze Revision'
    start = (marking_key(im), ())
    # we must carry the real marking object, keyed by marking_key for dedup of (marking,trace)
    frontier = deque()
    frontier.append((im, ()))
    seen = set()
    seen.add((marking_key(im), ()))
    while frontier:
        m, vis = frontier.popleft()
        if marking_key(m) == marking_key(fm):
            accepted.add(vis)
            # do not 'continue': fm might be re-enterable via loop; but if fm is a dead final
            # marking, no transitions are enabled and the loop below just adds nothing.
        # expand
        enabled = pm4py.get_enabled_transitions(net, m)
        for t in enabled:
            m2 = sem.execute(t, net, m)
            if m2 is None:
                continue
            if t.label is None:               # silent / tau
                vis2 = vis
            else:
                vis2 = vis + (t.label,)
                if len(vis2) > max_visible:
                    continue
                if vis2.count(A_LABEL) > max_a:
                    continue
            key = (marking_key(m2), vis2)
            if key not in seen:
                seen.add(key)
                frontier.append((m2, vis2))
    return accepted

def main():
    tA, netA, imA, fmA, sA = build(MODEL_A)
    tB, netB, imB, fmB, sB = build(MODEL_B)
    print("Soundness A:", sA)
    print("Soundness B:", sB)

    langA = bounded_language(netA, imA, fmA)
    langB = bounded_language(netB, imB, fmB)

    onlyA = sorted(langA - langB)
    onlyB = sorted(langB - langA)
    both  = langA & langB

    print(f"|Vis(A)∩B| = {len(langA)}, |Vis(B)∩B| = {len(langB)}, shared = {len(both)}")
    print("EXHAUSTIVE within bound (<=12 visible, <=3 Analyze). Not a proof of unbounded eq.")
    print("\n--- Traces admitted by A only ---")
    for t in onlyA[:20]:
        print("  ", t)
    print("\n--- Traces admitted by B only ---")
    for t in onlyB[:20]:
        print("  ", t)
    print("\nBounded-equivalent?" , langA == langB)

if __name__ == "__main__":
    main()
```

**Exhaustive vs. sampled.** The function `bounded_language` is *exhaustive within the P3 bound*: it enumerates every marking/visible-trace state reachable without exceeding 12 visible events or 3 `A`'s, deduplicating on `(marking, visible_trace)`. It is finite because each loop turn emits at least one visible `A`, so the visible cap bounds iterations. If one instead calls `pm4py.play_out(tree, ...)`, the result is a *random or heuristic sample*: play-out draws a finite number of traces stochastically (or up to a trace cap), so absence of a distinguishing trace in play-out output proves nothing, and it may miss rare interleavings such as `O A R A C X` in B. Exhaustive BFS is required to *decide* bounded equality; play-out can only *witness* inequality.

# 6. Stochastic and Footprint Comparison

**`pm4py.discover_footprints(...)`.** The footprint records directly-follows / parallel / choice relations over the *alphabet*, not over multiplicities or global scope.

```python
fpA = pm4py.discover_footprints(pm4py.parse_process_tree(MODEL_A))
fpB = pm4py.discover_footprints(pm4py.parse_process_tree(MODEL_B))
# compare fpA['dfg'], fpA['parallel'], fpA['sequence'], fpA['activities'] against fpB
```
Both models exhibit `A || C` (in A it is the local `+`, in B the global `+`), `A -> C`, `C -> A`, `A -> R`, `R -> A`, `R -> C` (B) etc. The footprints are likely to be *equal or nearly equal* because both allow `C` before/after `A` and both allow rework. **Equal footprints do not imply trace equivalence**: footprints are a length-2 (directly-follows) abstraction; they cannot express "exactly one `C` in total" (a *global cardinality* constraint) versus "one `C` per iteration." T1 vs T4 have identical directly-follows pairs but different global check counts, so the footprint is blind to the decisive difference.

**`pm4py.get_stochastic_language(...)`.** This yields a probability distribution over traces. Without a log or a declared executable stochastic semantics there are **no probabilities to read off the trees**; I decline to invent them. If one *declares* a semantics (e.g. exit-vs-redo probability `p` at the loop, approve-vs-skip `q` at the choice, uniform interleaving of concurrent branches), then:

```python
# DECLARED (not discovered) parameters — stated explicitly:
#   p = 0.5 probability to exit the loop at each decision point
#   q = 0.5 probability that a revision is approved
# Only under such a DECLARATION is a stochastic language well-defined.
langA = pm4py.get_stochastic_language(playout_log_A)   # from a log generated under the declaration
langB = pm4py.get_stochastic_language(playout_log_B)
```
The distributions differ because B places all probability mass on single-`C` traces while A spreads mass across multi-`C` traces.

**`pm4py.compute_emd(...)`.** EMD (Earth Mover's Distance) between the two stochastic languages would be *positive* here, quantifying how far apart the distributions are.

```python
emd = pm4py.compute_emd(langA, langB)  # > 0 expected
```
**Why a low EMD still would not establish trace equivalence.** EMD is a metric over *distributions*; a small EMD means the models rarely disagree *by probability mass*, not that their *supports* (trace sets) are equal. Two models can have EMD ≈ 0 if the distinguishing traces (multi-iteration runs) carry tiny probability (e.g. exit probability near 1), yet those traces still exist and still violate P1. Equivalence of *languages* is a support question; EMD answers a *mass* question. Only EMD = 0 with identical supports would coincide with distributional equality, and even that is weaker than the qualitative P1 invariant.

# 7. Complexity Comparison

**Structural counts (derived by inspection of the two tree strings).**

Model A tree, node by node:
- operators: `->`(root), `*`, inner `->`, `+`, `X` = 5 operator nodes
- leaves: `Open Case`, `Analyze Revision`, `Check Revision`, `Approve Revision`, `tau`, `Rework Case`, `Close Case` = 7 leaves (6 visible + 1 silent)

Model B tree, node by node:
- operators: `->`(root), `+`, `*`, inner `->`, `X` = 5 operator nodes
- leaves: `Open Case`, `Check Revision`, `Analyze Revision`, `Approve Revision`, `tau`, `Rework Case`, `Close Case` = 7 leaves (6 visible + 1 silent)

| Metric | Model A | Model B |
|---|---|---|
| Total nodes (operators + leaves) | 5 + 7 = **12** | 5 + 7 = **12** |
| Depth (root = 1) | root `->` (1) → `*` (2) → inner `->` (3) → `+` (4) → leaves `A,C` (5); the `X` branch: `->`(3)→`X`(4)→leaves(5). Max depth = **5** | root `->` (1) → `+` (2) → `*` (3) → inner `->` (4) → leaves `A` and `X`(4→5)→`Ap,tau`(6? ) Recount below | 
| Visible leaves | **6** (`O,A,C,Ap,R,X`) | **6** (`O,C,A,Ap,R,X`) |
| Silent leaves | **1** (`tau`) | **1** (`tau`) |
| Duplicate-label count | **0** (every label appears once as a leaf) | **0** |

Depth for B, carefully: `->`(1) → `+`(2) → `*`(3) → inner `->`(4) → `X`(5) → `tau/Ap`(6). So **depth B = 6**, one deeper than A because the `*` sits *under* the `+` in B, whereas in A the `+` sits *under* the `*` and the deepest chain is length 5.

| Metric (corrected) | Model A | Model B |
|---|---|---|
| Depth (root=1) | **5** | **6** |

Note: "duplicate-label count = 0" refers to *static leaves*; dynamically, both loops make labels *recur*, but that is behavioral multiplicity, not structural duplication.

**Code for the structural counts:**

```python
import pm4py
from pm4py.objects.process_tree.obj import Operator

def counts(tree_str):
    t = pm4py.parse_process_tree(tree_str)
    nodes = visible = silent = 0
    labels = {}
    def walk(n, d):
        nonlocal nodes, visible, silent
        nodes += 1
        depth = d
        if n.operator is None:            # leaf
            if n.label is None:
                silent += 1
            else:
                visible += 1
                labels[n.label] = labels.get(n.label, 0) + 1
        for c in n.children:
            depth = max(depth, walk(c, d + 1))
        return depth
    depth = walk(t, 1)
    dup = sum(1 for k, v in labels.items() if v > 1)
    return dict(nodes=nodes, depth=depth, visible=visible, silent=silent, duplicates=dup)

print("A:", counts(MODEL_A))
print("B:", counts(MODEL_B))
```

**Petri-net simplicity:**

```python
for name, s in [("A", MODEL_A), ("B", MODEL_B)]:

```
I report the simplicity metric as *code to run*, not a fabricated number, since its exact value depends on the PM4Py version's conversion (silent-transition placement, arc-degree distribution). Expected qualitative result: both nets are of comparable simplicity; B's *single* `C` transition sitting in parallel with the loop tends to give a slightly cleaner net (fewer arcs into `C`) than A's per-iteration `+(A,C)`, but node counts are close.

# 8. Simplified Model

**Chosen target semantics: P1 (operational compliance) applied to Model A.** P1 is the strictest business view and the one the two models genuinely disagree on; a dashboard-only (P2) simplification would silently discard the "one check per analysis" invariant that compliance needs. I therefore build a model *behaviorally equivalent to Model A under P1* (not to B), then note it cannot serve P2's blindness for free.

The simplification observes that in Model A the intra-iteration concurrency `+(A, C)` is *behaviorally rich but compliance-irrelevant*: P1 only requires that each iteration contains one `A` and one dedicated `C` "before the next `R` or `Close`." Fixing the order to `A` then `C` (dropping the interleaving) removes concurrency while preserving `count(C)=count(A)`, per-iteration pairing, optional approval, and the rework separator. This is a **weakening** of interleaving but an **exact** preservation of the P1 invariant.

**Compact process tree:**

```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

**PM4Py code:**

```python
import pm4py

SIMPLIFIED = """->('Open Case',
                   *( ->('Analyze Revision', 'Check Revision', X('Approve Revision', tau)),
                      'Rework Case'),
                   'Close Case')"""

simplified_model = pm4py.parse_process_tree(SIMPLIFIED)
net, im, fm = pm4py.convert_to_petri_net(simplified_model)
print("soundness:", pm4py.check_soundness(net, im, fm))
```

**Structural comparison to BOTH originals** (using the `counts` function of §7):
- Simplified: operators `->`(root), `*`, inner `->` (now 3 children), `X` = 4 operators; leaves `O,A,C,Ap,tau,R,X` = 7 leaves (6 visible + 1 silent); **total nodes = 11**, one fewer than A's 12 and B's 12; **depth = 5** (root→*→inner->→X→tau); duplicates = 0.
- It is strictly *simpler than A* (removes the `+` concurrency operator, −1 node, same depth) and *simpler than B* (removes the global `+` and its scope subtlety, −1 node, depth 5 < 6).

**Preservation table (vs. the P1-target = Model A):**

| Property | Status | Note |
|---|---|---|
| `Open Case` first, `Close Case` last | exact | Unchanged sequence skeleton. |
| `count(C) = count(A)` (one dedicated check per analysis) | exact | Fixed `A;C` per iteration preserves the pairing. |
| Approve optional per iteration (`0 ≤ count(Ap) ≤ count(A)`) | exact | `X(Approve, tau)` retained verbatim. |
| `Rework` separates two analysis attempts | exact | Redo child unchanged. |
| Intra-iteration interleaving `A||C` (order `C A` allowed) | weakened / lost | Only `A C` order now; `C A`, i.e. check-before-analyze in the same attempt, is dropped. |
| Number/placement of approvals visible (P1 requirement) | exact | `Ap` positions identical to A. |
| P2 collapse of `C` to Boolean | not addressed | Simplified model still emits one `C` per `A`; to serve P2 it would need the `α` abstraction applied downstream, not baked in. |

**Regression traces (must be accepted by the simplified model):**
1. `O A C X` — one analysis, checked, auto-approved (silent). Accepted.
2. `O A C Ap X` — one analysis, checked, approved. Accepted.
3. `O A C R A C Ap X` — two attempts, each with its own check, second approved. Accepted (this is the compliance-critical multi-attempt case, matching A's T1/T2 family).

**Negative traces (must be rejected):**
1. `O A R A C X` — two analyses, only one check ⇒ violates `count(C)=count(A)`. Rejected (this is exactly Model B's T4; the simplification deliberately excludes B's behavior).
2. `O C A X` — check *before* analyze within the single attempt. Rejected, because the simplified model fixed the order to `A;C`; this is the *intended weakening* and confirms the model is stricter than A on ordering while identical on counts.

# 9. Final Recommendation

- **Model A** is suitable for **P1** (it enforces one dedicated check per analysis) and, under the `α` abstraction, also satisfies **P2**. It is *not* interchangeable with B.
- **Model B** is **unsuitable for P1**: a single global check cannot certify each of several analysis attempts. B is acceptable **only under P2**, and only because `α` collapses `C` to a Boolean and both models guarantee `chk = true`. B models a genuinely different business reality ("one review of the whole case" rather than "one review per revision").
- **P3** merely confirms the split: within ≤ 12 visible events and ≤ 3 analyses the languages already differ (T1 vs T4), so bounded testing *falsifies* equivalence early.
- **Should the simplified model replace either original?** It should replace **Model A** *only where the intra-iteration `C`-before-`A` interleaving is agreed to be operationally irrelevant*, since it is structurally smaller (11 vs 12 nodes, no concurrency operator) while preserving every P1 invariant exactly. It must **not** replace **Model B**, because it encodes the opposite check-scope. No single simplified model can preserve P1 and B's single-check semantics simultaneously — the "one check per analysis" and "one check per case" requirements are contradictory at `count(A) ≥ 2`.
- **Warning on bounded comparison.** The BFS in §5 decides equality only within `≤ 12` visible events and `≤ 3` analyses. Agreement inside that window would be *evidence*, never proof: the decisive divergence (`count(C)` unbounded in A vs. fixed at 1 in B) is a global, unbounded property. Any claim of equivalence must be qualified by the explicit observation model (P1/P2/P3) and by the bound; here, even the bounded evidence already refutes equivalence for P1 and P3, and P2-equivalence holds *only* under the declared `α` abstraction.
