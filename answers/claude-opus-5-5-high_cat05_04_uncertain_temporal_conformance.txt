## 1. Normalization Assumptions

**A1. Interval construction order (per event).**
1. Take the displayed local wall-clock value.
2. Apply the source's resolution semantics to get the interval of the *source clock reading* in local wall time:
   - HUB: display ± 0.5 s (measurement uncertainty).
   - OPS-BER, VENDOR-NY, LEGACY-BER: floor to minute, so `hh:mm` means `[hh:mm:00.000, hh:mm:59.999]`.
   - SENSOR: round to nearest 10 s, so `t` means `[t − 5 s, t + 5 s]`.
   - MOBILE-LON: round to nearest minute, so `hh:mm` means `[hh:mm − 30 s, hh:mm + 30 s]`.
3. Convert the local clock reading to UTC using the IANA zone, and the DST fold where one exists.
4. Correct for clock offset. With `offset = recorded − true` and offset ∈ [a, b], true ∈ [clock_lo − b, clock_hi − a].
   - A clock that runs **fast** (positive offset) means the event really happened **earlier** than recorded.
5. Apply any event-specific occurrence semantics: mobile entry delay, inferred starts, latency.

Closed intervals are used. The `.999` upper ends stand in for the half-open floor intervals.

**A2. Time zones (validated in code against the declared abbreviations).**
- CEST = UTC+2 on 2026-06-01, so OPS-BER 10:14, 11:18 and 18:04 become 08:14, 09:18 and 16:04 UTC-clock.
- EDT = UTC−4, so VENDOR-NY 04:00 becomes 08:00 UTC-clock.
- BST = UTC+1, so MOBILE-LON 13:14 becomes 12:14 UTC-clock.

Treating these local values as UTC would put investigation start *after* containment in T-401, T-402, T-406 and T-409. This is a classic naive-local-time error.

**A3. DST fold (T-405).**
- On 2025-10-26, Europe/Berlin moved from 03:00 CEST back to 02:00 CET at 01:00 UTC.
- A LEGACY-BER wall time 02:mm is therefore either:
  - fold 0 (CEST, UTC+2), which is 00:mm UTC; or
  - fold 1 (CET, UTC+1), which is 01:mm UTC.
- Each event is represented as a **union of two disjoint intervals**, and every fold combination (2³ = 8 "worlds") is evaluated.
- **Ingestion order** (Alert → Investigation → Containment) is treated as evidence of true occurrence order and applied as a hard constraint in the primary analysis.
- It removes 7 of the 8 worlds. The only survivor is Alert = CEST, Investigation = CET, Containment = CET.
- Removing the order constraint is shown as a sensitivity case.
- Ingestion order does not narrow the surviving intervals. They keep their full ±60 s + floor width.

**A4. Offsets are treated as independent per event (conservative).**
- Each event's offset may be anywhere in its source's bound, even for two events from the same clock.
- If one shared offset were assumed for same-clock events close together in time, same-source durations would narrow. For HUB–HUB pairs they would narrow to ±1 s.
- This is reported as a sensitivity in Section 4. It is not used for any headline classification.

**A5. Inferred start (T-404).**
- Investigation_Start = Investigation_Complete − d, with d ∈ [1080, 1500] s from the signed work record.
- d is read as elapsed wall-clock duration with inclusive bounds.
- The HUB uncertainty on Investigation_Complete is kept, so the start interval is [IC_lo − 1500, IC_hi − 1080].
- If d is really effort time rather than elapsed time, the inference is not valid (semantic risk, Section 6).

**A6. Missing receipt (T-407).**
- Alert_Received = Alert_Sent + latency, with latency ∈ [0, 1200] s.
- `Alert_Sent` is **not** treated as `Alert_Received`.
- Primary analysis adds the plausible causal constraint Receipt ≤ Investigation_Start. This removes negative durations but, as shown below, changes no classification.
- An alternative semantics, where the SLA clock starts at Alert_Sent, is analysed as a sensitivity case.

**A7. Weak offset (T-409).**
- The ±12 min engineering estimate is used for a **conditional** result.
- Headline policy: a result involving a weakly bounded event is reported as certain only if it stays certain when the weak bound is dropped entirely and only causal order (Alert ≤ Investigation ≤ Containment) bounds the event.
- Otherwise it is labelled `INDETERMINATE (conditional X)`.
- In the primary analysis the causal order constraint is also applied to T-409, because without it the weak bound allows Investigation_Start to precede Alert_Received.

**A8. Mobile entry delay (T-406).**
- Primary assumption: the displayed value is the time the user created the entry. The entry may have been made up to 5 min *after* the investigation actually started.
- Under this reading the delay changes the **estimated occurrence time**: occurrence = entry time − delay, delay ∈ [0, 300] s. This widens the interval **only downward**.
- Alternative: the user typed the actual occurrence time, and the delay only affects when the record was created. Occurrence then has only the rounding and ±300 s clock uncertainty.
- Both readings are shown. They produce different S2 classifications.

**A9. SLA and profile semantics.**
- "No later than" is inclusive: duration ≤ limit passes. Tolerance adds to the limit.
- Negative durations satisfy the SLA inequality mathematically but are flagged as order anomalies. In the primary analysis they only arise where the order constraint is removed.
- Temporal-profile bands [μ − ζσ, μ + ζσ] are closed. This matches PM4Py, which flags only strict `<` or `>`.
- Profile checks apply to the four supplied eventually-follows pairs. Section 3 uses ζ = 2 as the reference; ζ = 1 and ζ = 3 are in Section 4.
- SENSOR events are completion events, which is consistent with `Containment_Complete`. No lifecycle shift is applied.

**A10. Joint computation.**
- Each case is solved as a simple temporal network. The network combines:
  - box bounds per event;
  - duration and latency relations;
  - order constraints.
- Floyd–Warshall gives the exact feasible range of every pairwise difference, and detects infeasible fold combinations.
- Duration intervals are therefore joint-feasible, not naive differences of marginal intervals.

**Cases whose classification changes, and why:**

**Assumption sensitivities (evidence semantics, not tolerance):**
- **T-405 without ingestion order.** All 8 fold worlds are feasible and durations become disjoint unions:

  - S1 is unaffected, because the delay only moves the event earlier.

  - If S1 is measured from Alert_Sent instead of Alert_Received, the interval is [1017, 1023].

## 5. PM4Py Temporal-Conformance Code

How the code works:
- The interval analysis is primary. It encodes normalization, fold alternatives and joint constraints as a simple temporal network per fold combination.
- The PM4Py part runs on a **separate, explicitly lossy midpoint log**, and is used only to compare against the interval conclusions.
- PM4Py's temporal profile works on point timestamps. It does not model timestamp uncertainty, DST folds or inferred events.

Version assumptions:
- Tested against pm4py 2.7.x. In that version `conformance_temporal_profile` returns one list per case, ordered like `df['case:concept:name'].unique()`, of `(act1, act2, flow_time_seconds, zeta_score)` tuples for pairs strictly outside the band.
- Some versions accept `return_diagnostics_dataframe=True` and return a DataFrame instead. The call is isolated in `pm4py_deviations`, handles both shapes, and is invoked per single-case frame, so it never depends on case ordering.
- `format_dataframe` coerces date-like strings such as `T-401` into datetimes, so the midpoint log uses case IDs of the form `case T-401`.

# --------------------------------------------------------------------------
# 2. Normalization: display -> clock interval (resolution) -> UTC -> true time (offset)
# --------------------------------------------------------------------------
def fold_alternatives(naive, tz_name, fold_logged=True):
    """Return [(label, fold)] for a local wall time; >1 entry only in a DST fold."""
    z = ZoneInfo(tz_name)
    a, b = naive.replace(tzinfo=z, fold=0), naive.replace(tzinfo=z, fold=1)
    if a.utcoffset() == b.utcoffset():
        return [("unambiguous", 0)]
    round_trip = [x for x in (a, b) if x.astimezone(UTC).astimezone(z).replace(tzinfo=None) == naive]
    if len(round_trip) < 2:
        raise ValueError(f"{naive} does not exist in {tz_name} (spring-forward gap)")
    if fold_logged:
        raise ValueError("fold was logged; pass it explicitly")
    return [(f"fold0_{a.tzname()}", 0), (f"fold1_{b.tzname()}", 1)]


def to_epoch(naive_local, tz_name, fold):
    return naive_local.replace(tzinfo=ZoneInfo(tz_name), fold=fold).astimezone(UTC).timestamp()


def normalize(row, scenario):
    """List of alternatives (label, true_lo, true_hi) in UTC epoch seconds (one per DST fold)."""
    src = SOURCES[row.system]
    ex = row.extras
    naive = datetime.fromisoformat(row.recorded_local)
    r_lo, r_hi = RESOLUTION[src["res"]]
    off_lo, off_hi = ex.get("offset_override", src["offset"])
    if ex.get("weak_offset") and scenario["weak_offsets"] == "drop":
        off_lo, off_hi = -INF, INF
    alts = []
    for label, fold in fold_alternatives(naive, src["tz"], ex.get("fold_logged", True)):
        z = ZoneInfo(src["tz"])
        if "declared_utc_offset_h" in ex:
            got = naive.replace(tzinfo=z, fold=fold).utcoffset() / timedelta(hours=1)
            assert got == ex["declared_utc_offset_h"], (row.case_id, row.activity, got)
        clock_lo = to_epoch(naive + timedelta(seconds=r_lo), src["tz"], fold)
        clock_hi = to_epoch(naive + timedelta(seconds=r_hi), src["tz"], fold)
        true_lo, true_hi = clock_lo - off_hi, clock_hi - off_lo   # true = recorded - offset
        if "entry_delay_s" in ex and scenario["mobile_delay_shifts_occurrence"]:
            d_lo, d_hi = ex["entry_delay_s"]
            true_lo, true_hi = true_lo - d_hi, true_hi - d_lo      # occurred before it was entered
        alts.append((label, true_lo, true_hi))
    return alts

# --------------------------------------------------------------------------
# 3. Simple temporal network (Floyd-Warshall) = exact joint interval propagation
# --------------------------------------------------------------------------
def solve_stn(nodes, constraints):
    """constraints: (x, y, lo, hi) meaning lo <= t_y - t_x <= hi. Returns (index, distance matrix) or None if inconsistent."""
    idx = {n: i for i, n in enumerate(nodes)}
    n = len(nodes)
    d = [[0.0 if i == j else INF for j in range(n)] for i in range(n)]
    for x, y, lo, hi in constraints:
        i, j = idx[x], idx[y]
        d[i][j] = min(d[i][j], hi)
        d[j][i] = min(d[j][i], -lo)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if d[i][k] + d[k][j] < d[i][j]:
                    d[i][j] = d[i][k] + d[k][j]
    if any(d[i][i] < -1e-9 for i in range(n)):
        return None
    return idx, d


def bounds(sol, x, y):
    idx, d = sol
    return (-d[idx[y]][idx[x]], d[idx[x]][idx[y]])


def merge(intervals):
    out = []
    for lo, hi in sorted(intervals):
        if out and lo <= out[-1][1] + 1e-6:
            out[-1] = (out[-1][0], max(out[-1][1], hi))
        else:
            out.append((lo, hi))
    return out


def analyse_case(case, scenario):
    rows = raw_df[raw_df.case_id == case]
    alts = {r.activity: normalize(r, scenario) for r in rows.itertuples()}
    nodes = ["Z"] + list(alts) + sorted({a for c, a in INFERRED if c == case})
    rel = [(x, y, lo, hi) for x, y, lo, hi, _ in RELATIONS.get(case, [])]
    if scenario["order_constraints"]:
        rel += [(x, y, 0, INF) for x, y in ORDER.get(case, [])]
    worlds = []
    for combo in itertools.product(*[[(act, a) for a in lst] for act, lst in alts.items()]):
        cons = list(rel)
        for act, (label, lo, hi) in combo:
            cons.append(("Z", act, lo, hi))
        sol = solve_stn(nodes, cons)
        if sol is not None:
            worlds.append(({act: a[0] for act, a in combo}, sol))
    return nodes, alts, worlds


def pair_union(worlds, x, y):
    return merge([bounds(sol, x, y) for _, sol in worlds])


def classify(union, lo_acc, hi_acc):
    if not union:
        return "INDETERMINATE"
    if any(math.isinf(v) for iv in union for v in iv):
        return "INDETERMINATE"
    if all(lo_acc <= lo and hi <= hi_acc for lo, hi in union):
        return "CERTAIN_PASS"
    if all(hi < lo_acc or lo > hi_acc for lo, hi in union):
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"


def fmt_union(u):
    return " U ".join(f"[{lo:.1f}, {hi:.1f}]s" for lo, hi in u) or "empty"


def iso(t):
    return datetime.fromtimestamp(t, UTC).isoformat(timespec="milliseconds").replace("+00:00", "Z")

    return u, cls

def pm4py_deviations(log_df, zeta):
    """Version-isolated call. Assumes pm4py 2.x output: one list per case, in order of
    log_df['case:concept:name'].unique(), of (act1, act2, flow_time_s, zeta_score)
    tuples for violated profile pairs.  Called per single-case frame to avoid relying
    on case ordering."""
    out = {}
    for c, sub in log_df.groupby("case:concept:name", sort=False):
        try:
            res = pm4py.conformance_temporal_profile(sub, PROFILE, zeta=zeta,
                                                     activity_key="concept:name",
                                                     timestamp_key="time:timestamp",
                                                     case_id_key="case:concept:name",
                                                     return_diagnostics_dataframe=False)
        except TypeError:   # older signature without return_diagnostics_dataframe
            res = pm4py.conformance_temporal_profile(sub, PROFILE, zeta=zeta)
        if isinstance(res, pd.DataFrame):   # diagnostics-dataframe shape (version dependent)
            out[c] = {(r.iloc[0], r.iloc[1]): float(r.iloc[2]) for _, r in res.iterrows()}
        else:
            out[c] = {(d[0], d[1]): float(d[2]) for d in (res[0] if res else [])}
    return {k.removeprefix("case "): v for k, v in out.items()}


def midpoint_pairs(log_df):
    pairs = {}
    for c, sub in log_df.sort_values("time:timestamp").groupby("case:concept:name", sort=False):
        ev = list(zip(sub["concept:name"], sub["time:timestamp"]))
        for i, (a, ta) in enumerate(ev):
            for b, tb in ev[i + 1:]:
                if (a, b) in PROFILE:
                    pairs[(c.removeprefix("case "), a, b)] = (tb - ta).total_seconds()
    return pairs


print("\n=== Midpoint (LOSSY) PM4Py vs interval conclusions ===")
mp = midpoint_pairs(midpoint_log)
for z in ZETAS:
    dev = pm4py_deviations(midpoint_log, z)
    for (c, a, b), cls in profile_findings.items():
        d_mid = mp.get((c, a, b))
        pm = "NOT_CHECKED(order inverted)" if d_mid is None else (
            "DEVIATION" if (a, b) in dev.get(c, {}) else "ok")
        icls = cls[z]
        flag = ""
        if pm == "ok" and icls != "CERTAIN_PASS":
            flag = "  <-- midpoint hides uncertainty"
        elif pm == "DEVIATION" and icls != "CERTAIN_VIOLATION":
            flag = "  <-- midpoint overstates certainty"
        mid_txt = "n/a" if d_mid is None else f"{d_mid:.1f}s"
        print(f"z={z} {c} {a}->{b}: midpoint={mid_txt} pm4py={pm} interval={icls}{flag}")

print("\nMidpoint SLA check (LOSSY):")
for c, rule, u, cls in findings:
    x, y, limit = SLA[rule]
    sub = midpoint_log[midpoint_log["case:concept:name"] == f"case {c}"].set_index("concept:name")["time:timestamp"]
    d_mid = (sub[y] - sub[x]).total_seconds()
    print(f"{c} {rule}: midpoint={d_mid:.1f}s -> {'pass' if d_mid <= limit else 'violation'}; interval={cls[0]}")

## 7. Governance Recommendation

1. **UTC storage with raw retention.**
   - Store every event as UTC with an explicit offset (RFC 3339, e.g. `2026-06-01T08:14:00+02:00` together with its normalized UTC value).
   - Keep the **raw displayed value, source zone (IANA name), source system and parser version** alongside it. Never overwrite raw values with normalized ones.
   - Normalization must be reproducible and re-runnable when metadata improves, such as the T-409 NTP logs.
2. **Store intervals, not points.**
   - Persist `ts_lo` and `ts_hi` (or a union of intervals) and an evidence-strength grade per event.
   - Point timestamps and midpoints may be derived for dashboards, but must be labelled as approximations.
3. **Resolution metadata.** Each source must declare its rounding semantics: floor, round or truncate, and granularity. Sub-minute resolution should be mandatory for SLA-relevant activities; minute-floor sources caused most of the POSSIBLE findings.
4. **Source offset telemetry.**
   - Collect continuous NTP/PTP offset logs per host with at least hourly granularity, stored as a time series.
   - Stamp each event with the last measured offset and the time since sync.
   - Missing diagnostics (T-409) must raise a data-quality incident. They must not be filled with engineering guesses.
   - External sources (VENDOR-NY) must provide contractual clock-sync attestation, and HUB must stamp their receipt time.
5. **DST fold.**
   - Ban local-time-only storage.
   - Where legacy systems cannot be changed, log the UTC offset or the PEP 495 `fold` bit at capture time.
   - Flag every event in an ambiguous or non-existent local hour for review.
   - Do not rely on ingestion order to resolve folds unless ingestion is proven to be FIFO per case.
6. **Lifecycle (start/complete) semantics.**
   - Every activity needs a lifecycle attribute (`start`, `complete`, `sent`, `received`).
   - SLA definitions must name the exact trigger event: `Alert_Received` vs `Alert_Sent`, and receipt at *our* boundary for vendor alerts.
   - Start events must be logged directly, so that durations are not inferred from completion minus duration (T-404).
   - Mobile apps must capture occurred-at (user-asserted) separately from entered-at (device) and server-received-at (HUB).
7. **Causal identifiers and provenance.**
   - Propagate an alert or message ID from `Alert_Sent` through delivery acknowledgment (`Alert_Received`) to `Investigation_Start`.
   - This makes causal order observable instead of assumed (T-407).
   - Record ingestion sequence numbers together with evidence that they reflect occurrence order.
8. **Enforcement policy for interval overlap.**
   - **Overlap alone is not sufficient for enforcement.** Legal or disciplinary action on SLA breaches requires CERTAIN_VIOLATION computed from *validated* bounds, with the contractual tolerance fixed in advance (not chosen after seeing results).
   - POSSIBLE_VIOLATION triggers review, an evidence request and an "at-risk" count in reporting. It is not recorded as a breach.
   - Where the organisation bears the burden of proof (e.g. regulatory reporting of its own compliance), POSSIBLE_VIOLATION must be disclosed as "compliance not demonstrable".
   - Results that rest on weak or unvalidated evidence (T-409) are INDETERMINATE for enforcement in either direction. The evidence gap is itself logged as a control failure.
   - Temporal-profile deviations are diagnostic only. They never override SLA status, and the ζ used must be stated with every report.
   - Any midpoint/PM4Py outputs are secondary and must carry a lossy-approximation label.
