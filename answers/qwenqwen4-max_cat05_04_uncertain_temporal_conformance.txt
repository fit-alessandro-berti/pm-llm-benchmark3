## 1. Normalization Assumptions

**A1 — Interval algebra (worst-case, not probabilistic).** Every timestamp is a *set* of possible true instants. For a recorded display value `D` with resolution window `[r_lo, r_hi]` (in the source's own wall-clock space) and clock offset bound `[o_lo, o_hi]` where `offset = recorded_clock  true_clock`:

```
true_local  [r_lo  o_hi , r_hi  o_lo]
```

Resolution uncertainty is applied **first**, then the offset is subtracted (never added). Bounds are combined by interval addition (independent worst case), not by RSS/convolution, so all intervals are conservative supersets. No probability mass is assumed inside them.

**A2 — Resolution windows.**
- HUB "exact to displayed second ±0.5 s": `[D0.5 s, D+0.5 s]`; with offset `[-1,+1]`  **true = D ± 1.5 s** (width 3 s).
- Floor-to-minute (OPS-BER, VENDOR-NY, LEGACY-BER): `[HH:MM:00.000, HH:MM:59.999]` (upper end is a supremum; I keep the stated 59.999 rather than 60.000).
- Round-to-nearest-minute (MOBILE-LON): `[HH:MM30 s, HH:MM+29.999 s]`.
- Round-to-nearest-10 s (SENSOR): `[D5 s, D+4.999 s]`.

**A3 — Time-zone conversion.** Convert *after* resolution + offset correction, using IANA rules via `zoneinfo`: CEST = UTC+2, CET = UTC+1, BST = UTC+1, EDT = UTC4. Zone labels supplied in the evidence are taken as given (June 2026  CEST/BST/EDT).

**A4 — DST fold (LEGACY-BER, 2025-10-26).** Local 02:00–02:59:59.999 occurs twice: fold 0 = CEST  UTC 00:00–00:59:59.999; fold 1 = CET  UTC 01:00–01:59:59.999. Each ambiguous event is normalized into **two candidate UTC intervals** (a union, not a hull). I verified that all three offset-corrected local windows stay strictly inside 02:00–03:00, so no candidate crosses out of the ambiguous block (this would otherwise require splitting intervals at the fold boundary). Fold selection is then constrained by ingestion order (A6).

**A5 — Inferred starts.**
- T-404: `Investigation_Start = Investigation_Complete  d`, `d  [1080, 1500] s` from the signed work record, treated as hard bounds on the *startcomplete* interval. Interval subtraction retains full width (423 s). Semantic risk: if "investigation duration" means active work time (pauses excluded) or is itself minute-rounded, the start moves earlier; sensitivity is shown in §4.
- T-407: `Alert_Received = Alert_Sent + latency`, `latency  [0, 1200] s`. **`Alert_Sent` is not `Alert_Received`.** No acknowledgment exists, so the anchor activity is *assumed*, not evidenced.

**A6 — Causal / order constraints.** "Eventually-following" pairs imply non-negative duration. Where ingestion order is given (T-405) I use it as a hard constraint on true times and enumerate fold combinations, keeping only feasible chains (greedy earliest-assignment test). For T-407 the constraint `Received  Investigation_Start` is *plausible but unlogged*; I report results both with and without it, and cap the receipt interval at `max(Investigation_Start)` only in the conditional branch. Where an interval admits negative durations (T-407, T-409) I report the raw lower bound as a **semantic red flag** and clip to 0 only for the conditional classification.

**A7 — Mobile entry delay (T-406), treated separately from clock offset.** Two substantive readings, both carried:
- **Interpretation A (primary, occurrence-shifting):** the user captured the clock reading up to 5 min *after* the event, so the displayed value is late relative to occurrence. Occurrence = corrected time  `[0, 300] s`  interval extends **earlier**: `[12:03:30, 12:19:29.999]`.
- **Interpretation B (record-time only):** the user typed the event's actual wall time; the delay affects only row-creation metadata. Occurrence interval unchanged: `[12:08:30, 12:19:29.999]`.
Because B  A, the union over interpretations equals A; I therefore use A for conservative classification and report B explicitly wherever the verdict differs (it differs for **S2** and for the IC profile pair). The delay is *not* folded into the ±300 s clock bound.

**A8 — Evidence-strength gate (material policy).**
- Bounds backed by diagnostics/metadata (HUB, OPS-BER on 2026-06-01, SENSOR, VENDOR-NY, LEGACY-BER, MOBILE-LON clock bound) are treated as *hard*.
- T-409's `[-12 min, +12 min]` is a **weak engineering estimate**, not telemetry. Policy: a weak bound may support a CERTAIN_PASS (flagged conditional, with robustness margin), but any *adverse* verdict driven by that bound is reported **INDETERMINATE**, with the conditional verdict shown.
- A missing anchor activity (T-407 `Alert_Received`) forces **INDETERMINATE** regardless of arithmetic.

**A9 — Marginality.** Duration intervals are per-pair projections of the joint feasible set. They can overstate what is *jointly* possible; I flag the cases where a sum constraint forbids simultaneous violations (T-401, T-404, T-406) or permits them (T-402).

**A10 — Acceptance regions.** SLA: `duration  limit` (inclusive), limit + tolerance for sensitivity. Profile: `[mean  ·sd, mean + ·sd]` (two-sided, inclusive). Midpoints are computed **only** in §4/§5 as a labelled lossy comparison, never as evidence.

```python
def resolution_window(t: datetime, kind: str):
    if kind == "exact_second": return (t - timedelta(milliseconds=500), t + timedelta(milliseconds=500))
    if kind == "floor_minute": return (t, t + td(59) + MS*999)
    if kind == "round_minute": return (t - td(30), t + td(29) + MS*999)
    if kind == "round_10s":    return (t - td(5),  t + td(4)  + MS*999)
    raise ValueError(kind)

    return local_naive.replace(tzinfo=ZoneInfo(zone), fold=fold).astimezone(UTC)

def normalize(recorded, system, offset=None, entry_delay=(0, 0), fold_mode="both"):
    """resolution FIRST, then true = recorded - offset, then tz conversion.
    entry_delay=(lo,hi) shifts the OCCURRENCE estimate earlier (interpretation A)."""
    m = SOURCES[system]

    true_lo = r_lo - td(o_hi) - td(entry_delay[1])
    true_hi = r_hi - td(o_lo) - td(entry_delay[0])
    folds = [0, 1] if (fold_mode == "both" and is_ambiguous(t, m["zone"])) else [0]
    out = []
    for f in folds:

        out.append(dict(lo=to_utc(true_lo, m["zone"], f),
                        hi=to_utc(true_hi, m["zone"], f), fold=f, needs_review=cross))
    return out

def durations(a, b, enforce_order=True):

           for alo, ahi in a for blo, bhi in b]

def classify(durs, lower, upper, weak=False, anchor_missing=False, order_conflict=False):
    if not durs: return "INDETERMINATE", "INDETERMINATE"
    all_in  = all(lo >= lower - EPS and hi <= upper + EPS for lo, hi in durs)
    all_out = all(hi <  lower - EPS or lo >  upper + EPS for lo, hi in durs)
    cond = "CERTAIN_PASS" if all_in else ("CERTAIN_VIOLATION" if all_out else "POSSIBLE_VIOLATION")
    if anchor_missing or (weak and (cond != "CERTAIN_PASS" or order_conflict)):
        return "INDETERMINATE", cond
    return cond, cond

mid_df = pd.DataFrame(mid_rows).sort_values(["case_id","timestamp"]).reset_index(drop=True)
naive_df = mid_df[mid_df.case_id != "T-407"].copy()
naive_df = pd.concat([naive_df, pd.DataFrame([dict(case_id="T-407", activity="Alert_Received",
    timestamp=datetime(2026,6,1,14,0,0), approximation="LOSSY_AND_SEMANTICALLY_WRONG:Sent_as_Received")])],
    ignore_index=True).sort_values(["case_id","timestamp"]).reset_index(drop=True)

def midpoint_pair_check(df, z):
    out = {}
    for case, g in df.groupby("case_id"):
        ts = dict(zip(g.activity, g.timestamp))
        for (a, b), (mu, sd) in PROFILE.items():
            if a in ts and b in ts:
                d = (ts[b] - ts[a]).total_seconds()
                out[(case, f"P:{a}->{b}")] = ("CERTAIN_PASS" if mu - z*sd <= d <= mu + z*sd
                                              else "CERTAIN_VIOLATION")
    return out

def _leaves(o):
    if isinstance(o, (list, tuple, set)):
        for x in o: yield from _leaves(x)
    else: yield o

def pm4py_case_flags(res, cases):
    """VERSION ISOLATION: pm4py releases differ in the shape of the returned
    deviation records (tuple order / nesting / DataFrame vs list). We only rely
    on the case identifier appearing as a string somewhere in each record."""
    flags = {c: False for c in cases}
    if hasattr(res, "columns"):
        col = next((c for c in res.columns if "case" in str(c).lower()), None)
        if col is not None:
            for v in res[col]:
                if v in flags: flags[v] = True
        return flags
    for rec in (res if isinstance(res, (list, tuple)) else [res]):
        for leaf in _leaves(rec):
            if isinstance(leaf, str) and leaf in flags: flags[leaf] = True
    return flags

cases = sorted(mid_df.case_id.unique())
try:
    import pm4py
    HAVE = True
except Exception as exc:                                    # pragma: no cover
    HAVE = False
    print(f"\n[pm4py unavailable: {exc}] Running the labelled pure-pandas midpoint "
          f"fallback instead. This is NOT a PM4Py result.")

pm_flags = {}
if HAVE:
    for tag, df in (("midpoint", mid_df), ("midpoint+Sent_as_Received", naive_df)):
        formatted = pm4py.format_dataframe(df.copy(), case_id="case_id",
                                           activity_key="activity", timestamp_key="timestamp")
        log = pm4py.convert_to_event_log(formatted)
        for z in (1, 2, 3):
            try:
                res = pm4py.conformance_temporal_profile(log, PROFILE, parameters={"zeta": z})
            except TypeError:
                res = pm4py.conformance_temporal_profile(log, PROFILE)  # older signature
            pm_flags[(tag, z)] = pm4py_case_flags(res, cases)
            print(f"pm4py {tag} zeta={z} case-level deviation flags:", pm_flags[(tag, z)])

# ---------------- 7. midpoint vs interval comparison ----------------
cmp_rows = []
for z in (1, 2, 3):
    mp = midpoint_pair_check(mid_df, z)
    mp_naive = midpoint_pair_check(naive_df, z)
    for (case, test), verdict in mp.items():
        row = findings[(findings.scenario == "primary(A/causal/weak)") &
                       (findings.case == case) & (findings.test == test) &
                       (findings.param == f"zeta={z}")]
        interval_verdict = row.reported.iloc[0] if len(row) else "n/a"
        cmp_rows.append(dict(zeta=z, case=case, pair=test,
                             midpoint_only=verdict,
                             midpoint_naive_T407=mp_naive.get((case, test), "n/a"),
                             interval_reported=interval_verdict,
                             agreement=(verdict == interval_verdict),
                             pm4py_case_flag=(pm_flags.get(("midpoint", z), {}).get(case, "n/a"))))
print("\nMIDPOINT vs INTERVAL (midpoint columns are lossy, not evidence):")
print(pd.DataFrame(cmp_rows).to_string(index=False))
print("\nPM4Py sees point timestamps only; every POSSIBLE_VIOLATION / INDETERMINATE above "
      "is invisible to it by construction. Interval verdicts govern enforcement.")
```

**Version assumptions isolated:** (i) `conformance_temporal_profile(log, profile, parameters={"zeta": z})` — older builds may ignore/reject `parameters`, handled by `TypeError` fallback; (ii) the returned deviation structure is scanned for case-id strings rather than indexed by fixed columns (`pm4py_case_flags`); (iii) the *supplied* profile is used as the reference rather than one discovered from these nine cases (discovery from 9 heterogeneous cases would be statistically meaningless); (iv) `format_dataframe` receives tz-naive UTC datetimes. If pm4py is absent, the fallback is explicitly labelled as *not* a PM4Py result.

## 6. Evidential Sufficiency

Minimum additional evidence to convert each non-certain verdict into a certain one.

**Missing activity evidence (highest priority).**
- **T-407 S1 / P:AI / P:AC (INDETERMINATE):** a receiver-side `Alert_Received` acknowledgment with a HUB-grade timestamp. That alone fixes the anchor; latency bounds and the unlogged causal rule become irrelevant. Second-best: a signed delivery receipt with a *bounded, verified* latency (±30 s) plus explicit logging of the receiptstart ordering rule. Note that even a perfect receipt could yield a certain violation (the naive reading gives 17 min), so this is a compliance question, not just a data question.
- **T-404 S1/S2 (POSSIBLE):** a directly logged `Investigation_Start` (HUB-grade). Absent that, a work record with **second-resolution** duration and an explicit statement that it measures startcomplete wall-clock elapsed time (no pause exclusion) shrinks the inferred start from 423 s to ~3 s and makes both verdicts certain (S1 pass, S2 pass at d2100 s region).

**Stronger synchronization evidence.**
- **T-401 S1 (POSSIBLE):** OPS-BER offset telemetry for that hour narrower than ~±45 s, or a second corroborating start record (e.g., analyst workstation UTC event). With offset uncertainty ±30 s the interval width drops to ~120 s and the verdict becomes certain (pass if the true start 08:15).
- **T-403 S1 / P:AI / P:AC (POSSIBLE):** event-level synchronization for VENDOR-NY (signed NTP/chrony sample near 04:00 EDT, or a vendor-side UTC echo of the same alert). Reducing the offset bound from ±180 s to ±30 s makes S1 certain-pass. A corroborating HUB-side inbound-delivery log would remove the vendor clock from the chain entirely.
- **T-409 S1 / P:AI / P:IC (INDETERMINATE):** the missing NTP diagnostics for 18:04 CEST, or any independent UTC start witness. This is the *only* fix; tolerance and  cannot help. Note the twist: strong synchronization would likely make S1 certain-pass but P:AI a certain 1 violation (start too fast), so collect the evidence with an open mind about which rule fails.
- **T-402 S1 (CERTAIN_VIOLATION, marginal):** to *overturn* it you would need evidence that the OPS-BER offset exceeded the documented +120 s bound (i.e., a diagnostics defect), or a second start witness. To *confirm* it, an OPS-BER second-resolution timestamp suffices. Current certain-violation status is robust within the documented bounds.

**Semantic evidence (decides verdicts without any new clock data).**
- **T-406 S2 / P:IC (POSSIBLE under A, PASS under B):** a written statement of what the mobile field means — "clock reading at entry" vs "recalled event time" — plus whether the 5-minute lag is one-sided. **Duration/boundary evidence for the razor-thin cases (T-404 S2 3 s; T-402 P:AI 1.5 s; T-403 P:AI 1.5 s; T-408 P:IC 3 s).** These are artifacts of the ±1.5 s HUB envelope and the 59.999 s floor convention. Until then they should be reported as boundary-fragile and excluded from automated enforcement.

## 7. Governance Recommendation

**Timestamp and clock controls**
1. **Store UTC instants as the system of record** (RFC 3339 with explicit `Z`, microsecond precision), and *never* overwrite them with normalized values. Keep the raw display string, the source's declared zone, the resolution semantics, and the applied correction as separate, immutable columns.
2. **Publish per-source uncertainty metadata** as first-class schema: `resolution_semantics  {exact, floor, round}`, `resolution_value`, `measurement_uncertainty`, `clock_offset_bound`, `offset_bound_provenance  {ntp_diagnostics, engineering_estimate, unknown}`, `offset_sample_time`. A bound without provenance must be flagged weak and must not support adverse enforcement (the T-409 rule).
3. **Offset telemetry at event granularity:** persist the NTP/chrony offset sample nearest each event, with sync age and stratum. Alert when sync age exceeds a threshold or when |offset| approaches the declared bound; escalate to "weak" automatically (this is exactly the T-409 failure mode).
4. **Ban silent rounding.** Emit full precision internally; round only in UI. Floor-to-minute logging (OPS-BER, VENDOR-NY, LEGACY-BER) injects up to 60 s of irreducible uncertainty and is the single largest contributor to POSSIBLE_VIOLATION verdicts here.

**Time-zone and DST controls**
5. Store the **UTC offset and the IANA zone id separately**, plus an explicit **fold/`is_dst` flag** for local times in ambiguous windows; reject or quarantine ambiguous local timestamps that lack it. LEGACY-BER must be remediated: recovering the fold from ingestion order (T-405) is a rescue, not a control.
6. Never derive elapsed time from local wall clocks across a transition; compute durations only on UTC instants. Add a regression test for fall-back and spring-forward windows.

**Lifecycle and semantics controls**
7. **Distinguish start / complete / sent / received / recorded** as different activity types with mandatory lifecycle fields. `Alert_Sent  Alert_Received` (T-407): require a receiver-side acknowledgment, and make `Alert_Received` a mandatory SLA anchor with a delivery-latency SLO.
8. For user-entered timestamps, capture **three** fields: asserted event time, entry time (server clock), and a declared `entry_delay_semantics` flag (record-time-only vs occurrence-shifting). T-406 shows this flag alone decides an SLA verdict.
9. When a start event is missing, allow inference **only** as a labelled derived activity carrying its full interval and the duration evidence's provenance, resolution and semantics (T-404). Derived anchors must never be silently promoted to observed facts.

**Provenance and causal controls**
10. Attach **causal identifiers** (alert id  investigation id  containment id  closure id) and monotonic per-case sequence numbers emitted at the source, so ordering constraints are evidence rather than pipeline artifacts.
11. Retain an auditable **normalization provenance record** per event: raw value  resolution window  offset correction  zone/fold conversion  resulting interval, with the code version that produced it. Re-running with tightened bounds must be reproducible.

**Enforcement policy on interval overlap (the decisive governance choice)**
12. Adopt a **three-tier policy**, explicitly ratified by Legal/Compliance:
 - **CERTAIN_VIOLATION** (entire feasible set beyond the limit)  automatic breach record. Today: T-402 S1; T-408 S2 and S3.
 - **POSSIBLE_VIOLATION**  *no automatic breach*. Route to a review queue with a mandatory evidence-collection SLA, and report the worst-case exceedance. Sub-threshold cases (worst-case exceedance < 5 s, or overlap slivers < 5 s: T-404 S2, T-402/T-403/T-408 profile slivers) are auto-classified "measurement-limited, non-actionable" and tracked as data-quality debt.
 - **INDETERMINATE**  never a breach and never a pass; block SLA attestation for that case until the missing anchor/telemetry/semantics is supplied (T-407, T-409).
13. **Interval overlap alone is never sufficient for enforcement.** Enforce only on certain violations; use possible violations to prioritize instrumentation, not penalties. Publish a per-case "evidence sufficiency score" so improving clocks is rewarded rather than punished.
14. **Separate the legal SLA from the statistical profile in all reporting.**  is a tuning knob for anomaly detection, not a compliance threshold: at =3, T-408's 2 h 25 m closure breach becomes a profile "pass". Fix =1 or 2 for triage, forbid  changes on closed compliance reports, and version the profile.
15. **Tolerance changes are policy acts, not analysis.** Log every tolerance addition with approver and rationale; report both the +0 verdict and the tolerated verdict side by side (T-402 S1 stays a possible violation even at +5 min; T-401 S1 becomes a pass at +2 min purely by fiat).
16. **Tooling honesty:** midpoint-only conformance tools (including PM4Py's temporal profile) must be labelled lossy in every artifact they produce, run only as a secondary diagnostic, and never be the sole basis for a breach finding — T-405's midpoint lands exactly on 900 s and would have hidden a 180 s breach tail, while T-403's midpoint invents a violation that the intervals do not support.
