Multiple mechanisms acted jointly and sequentially. The 31 May UI release changed the visible label of an otherwise unchanged activity from Classify to Risk Screen, producing systematic log moves against the normative model. Almost simultaneously the gateway began emitting the technical Queue Routed event after risk screening, further inflating traces and alignment cost. The 15 June ETL switch to warehouse-ingestion timestamps for Decision and Notify disordered a non-negligible subset of cases (Notify before Decision), an artifact corroborated by source-system screenshots in 11 of 70 reversed traces. These three provenance defects account for the bulk of the June–July fitness collapse; successive repairs—label mapping, technical-event removal, source-sequence reordering—restore fitness from 32 % to 89 %.

Separately, the 1 August high-value policy introduced a genuine behavioral step (Supervisor Sign-off) that was never added to the normative process tree, rendering the model obsolete for affected cases and explaining the residual August–September gap that an optional-sign-off candidate largely closes. Reviewer statements and IT confirmation indicate that Manual Override is a real corrective action, while the 55 enhanced-review traces lacking a recorded Compliance Check remain ambiguous between true bypass and missing events. Stable approval, appeal and cycle-time figures show that any genuine noncompliance has not yet produced detectable downstream harm; however, incomplete incident detection and the unused high-value attribute leave open the possibility of selective, still-hidden deviations. Unchanged outcomes therefore neither prove that all residual moves are data error nor rule out localized noncompliance; they merely indicate that the dominant measured-fitness drop was artifactual while model lag and residual behavioral uncertainty constitute distinct operational concerns.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py

# ========== 1-2. Normative process tree and Petri net ==========
normative_tree_str = "-> ( 'Receive', 'Classify', X ( * ( 'Standard Review', 'Request Info' ), -> ( 'Enhanced Review', 'Compliance Check' ) ), 'Decision', 'Notify' )"
normative_tree = pm4py.parse_process_tree(normative_tree_str)
net, im, fm = pm4py.convert_to_petri_net(normative_tree)

# ========== 3. Expand variant-frequency tables into event logs ==========
def expand_to_log(variant_counts):
    """Repeat each variant string according to its count and parse."""
    traces = []
    for vstr, cnt in variant_counts.items():
        traces.extend([vstr] * int(cnt))
    return pm4py.parse_event_log_string(traces, sep=",")

apr_may = {
    "Receive,Classify,Standard Review,Decision,Notify": 380,
    "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,
    "Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify": 40,
}
jun_jul = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 270,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 145,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,
    "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
    "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 20,
}
aug_sep = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 210,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify": 150,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 90,
    "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify": 60,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 45,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 35,
}

log_apr = expand_to_log(apr_may)
log_jun = expand_to_log(jun_jul)
log_aug = expand_to_log(aug_sep)

# ========== 4. Discover DFGs ==========
dfg_apr, sa_apr, ea_apr = pm4py.discover_dfg(log_apr)
dfg_jun, sa_jun, ea_jun = pm4py.discover_dfg(log_jun)
print("Sample Apr-May DFG relations:", list(dfg_apr.items())[:4])
print("Jun-Jul DFG contains Risk Screen / Queue Routed:", any("Risk Screen" in str(k) or "Queue Routed" in str(k) for k in dfg_jun))

# ========== 5. Raw alignment fitness ==========
fit_apr = pm4py.fitness_alignments(log_apr, net, im, fm)
fit_jun_raw = pm4py.fitness_alignments(log_jun, net, im, fm)
print("Raw Apr-May fitness:", fit_apr)
print("Raw Jun-Jul fitness:", fit_jun_raw)

# ========== 6-7. Normalization pipeline (label map + remove Queue Routed) + approximate order repair ==========
def normalize_variants(variant_counts, map_label=True, remove_queue=True, fix_order=True):
    """Operate on variant strings for transparency with aggregates."""
    new_counts = {}
    for vstr, cnt in variant_counts.items():
        acts = [a.strip() for a in vstr.split(",")]
        if map_label:
            acts = ["Classify" if a == "Risk Screen" else a for a in acts]
        if remove_queue:
            acts = [a for a in acts if a != "Queue Routed"]
        if fix_order and "Notify" in acts and "Decision" in acts:
            # Approximate source-seq: if Notify appears before Decision, swap them
            i_n = acts.index("Notify")
            i_d = acts.index("Decision")
            if i_n < i_d:
                acts[i_n], acts[i_d] = acts[i_d], acts[i_n]
        new_v = ",".join(acts)
        new_counts[new_v] = new_counts.get(new_v, 0) + cnt
    return expand_to_log(new_counts)

log_jun_norm = normalize_variants(jun_jul, map_label=True, remove_queue=True, fix_order=True)
log_aug_norm = normalize_variants(aug_sep, map_label=True, remove_queue=True, fix_order=True)

fit_jun_norm = pm4py.fitness_alignments(log_jun_norm, net, im, fm)
fit_aug_norm = pm4py.fitness_alignments(log_aug_norm, net, im, fm)
print("Normalized Jun-Jul fitness (map + remove QR + order fix):", fit_jun_norm)
print("Normalized Aug-Sep fitness vs normative:", fit_aug_norm)

dfg_jun_n, _, _ = pm4py.discover_dfg(log_jun_norm)
print("Normalized Jun DFG no longer dominated by technical labels")

# ========== 8. Candidate model with optional Supervisor Sign-off ==========
candidate_tree_str = "-> ( 'Receive', 'Classify', X ( * ( 'Standard Review', 'Request Info' ), -> ( 'Enhanced Review', 'Compliance Check' ) ), X ( 'Supervisor Sign-off', tau ), 'Decision', 'Notify' )"
candidate_tree = pm4py.parse_process_tree(candidate_tree_str)
cnet, cim, cfm = pm4py.convert_to_petri_net(candidate_tree)

fit_aug_cand = pm4py.fitness_alignments(log_aug_norm, cnet, cim, cfm)
print("Aug-Sep fitness vs optional-sign-off candidate:", fit_aug_cand)

# Precision (may be computationally heavier)
try:
    prec_aug_cand = pm4py.precision_alignments(log_aug_norm, cnet, cim, cfm)
    print("Aug-Sep precision vs candidate:", prec_aug_cand)
except Exception as e:
    print("Precision computation skipped or failed (common on large/aggregate logs):", str(e)[:80])

# ========== 9. Required caveats ==========
print("""
CAVEATS (must be reported):
- A control-flow-only optional Supervisor Sign-off model cannot enforce the EUR 50,000 data condition.
- It may overgeneralize by permitting Sign-off on low-value cases, thereby inflating fitness while harming precision.
- The supplied data are variant aggregates, not the original timestamped log; therefore source-sequence reordering is only approximated by swapping known reversed pairs, and high-value stratification cannot be performed here.
- Residual moves (Manual Override, Enhanced Review without Compliance Check) persist after normalization and require separate provenance audit before any noncompliance conclusion.
- Fitness numbers are illustrative; exact reproduction of the problem's aggregate alignment costs is not expected from frequency tables alone.
""")
```

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a cascade of data-provenance and logging artifacts: the May UI label change (Classify → Risk Screen), the June injection of the technical Queue Routed event, and the ETL switch to warehouse-ingestion timestamps that disordered Decision/Notify in a subset of cases. These three defects jointly drove fitness from 93 % to 32 %; the staged recovery to 89 % after label mapping, technical-event removal and source-sequence ordering demonstrates that the bulk of the drop was artifactual rather than behavioral. Confidence in this primary account is high (~90).

A secondary, real operational concern remains. The August policy introduced Supervisor Sign-off for claims above EUR 50 000 without a corresponding model update, rendering the normative process tree obsolete; an optional-sign-off candidate recovers most of the residual fitness gap, yet a pure control-flow optional model cannot enforce the value threshold. In addition, the 55 enhanced-review traces that lack a recorded Compliance Check, together with Manual Override usage, have not been fully explained. Stable approval, appeal and cycle-time metrics argue against widespread noncompliance, but incomplete incident detection and the unused high-value attribute leave open the possibility of selective bypasses. Confidence that a material residual compliance problem exists is therefore only moderate (~40–50) pending targeted audit and stratification.

Immediate actions: IT must restore source-sequence (or business-time) ordering for Decision/Notify, tag technical events explicitly, and expose activity identifiers that survive UI label changes. Process owners must version the normative model in lock-step with policy releases and incorporate a data-aware or optional Supervisor Sign-off construct. Compliance must commission a stratified sample audit of the residual missing-check and Manual Override cases, focusing on high-value claims and the resources that executed them.

What must not be claimed yet: that employees systematically became noncompliant, that the process itself fundamentally changed in a way that affects customer outcomes, or that stable KPIs prove the residual moves are harmless. The measured collapse was largely diagnostic of logging and model-governance failures; the residual risk is real but still unquantified.

## 8. Model-governance recommendation

1. Every normative process model must be versioned and explicitly linked to the policy-change ticket or regulatory release that justifies it; no policy may go live without a corresponding model update or documented temporary exemption.
2. Event-semantic contracts must declare activity labels and identifiers as immutable without a joint IT–process-owner change request; UI display labels may change only if the backend activity key remains stable and a mapping table is published.
3. Technical events (gateway routing, queueing, system heartbeats) must carry an explicit technical flag and be filtered by default from conformance pipelines unless a documented business justification exists.
4. Timestamp provenance must prefer source-system sequence numbers or business event time over warehouse-ingestion time; any ETL that substitutes ingestion time must retain the original sequence attribute and document the substitution.
5. Value- or attribute-dependent steps (e.g., Supervisor Sign-off above EUR 50 000) must be encoded with data-aware guards or at least with stratified evaluation; pure control-flow optional constructs are insufficient for regulated processes.
6. Within seven days of any UI, ETL, gateway or policy release, a post-release validation suite must recompute frequency DFGs, variant distributions and alignment fitness against the current normative model, and a small manual provenance sample must be inspected before the change is accepted into the production conformance baseline.
