## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels
ETL_change -> recorded_order
policy_change -> true_process
policy_change -> reviewer_behavior
event_gateway_config -> recorded_labels
event_gateway_config -> routing_accuracy
routing_accuracy -> reviewer_behavior
claim_value_attribute -> true_process
reviewer_behavior -> true_process
true_process -> business_outcomes
true_process -> recorded_labels
true_process -> recorded_order
logging_completeness -> recorded_labels
recorded_labels -> alignment_moves
recorded_order -> alignment_moves
normative_model -> alignment_moves
alignment_moves -> measured_fitness
business_outcomes -> incident_detection_sensitivity
```

The observed conformance collapse is a compound effect of four distinct mechanisms—lexical drift, technical event injection, ETL timestamp distortion, and unmodeled policy evolution—superimposed onto a smaller baseline of potential operational deviations. First, in June–July, UI Release 4.2 renamed `Classify` to `Risk Screen` (`UI_release -> recorded_labels`), forcing optimal alignments to pair a log move on `Risk Screen` with a visible model move on `Classify` in 95.4% of cases. Simultaneously, the event gateway injected `Queue Routed` (`event_gateway_config -> recorded_labels`), adding log moves in 86.2% of traces and raising missing-resource events from 1.2% to 5.9%. Third, the June 15 ETL change substituted warehouse-ingestion timestamps for `Decision` and `Notify` (`ETL_change -> recorded_order`), inverting their recorded order in 70 traces without altering `true_process`. Together, these three data-pipeline artifacts reduced fitting traces from 93% to 32% (mean cost 0.74); repairing them restores fitting traces to 89% (cost 0.12). In August–September, the mandatory `Supervisor Sign-off` policy for claims over EUR 50,000 (`policy_change -> true_process`) without updating `normative_model` lowered normalized conformance from 89% to 66%.

Crucially, stable business outcomes—approval rates (72.0% to 71.5%), 30-day appeals (3.8% to 3.6%), and median cycle times (26.0h to 27.4h)—neither prove pure data error nor rule out noncompliance. Because `Compliance Check` is a preventative audit control, bypassing it in 55 `Enhanced Review` cases need not alter approvals or customer appeals, especially given incomplete incident detection. Conversely, logging and ETL defects corrupt `recorded_labels` and `recorded_order` downstream of `true_process`, collapsing `measured_fitness` while leaving `business_outcomes` unchanged.

## 5. Diagnostic program

Each phase below is sequenced so that upstream data-hygiene and ordering repairs are locked in before downstream model comparisons and behavioral compliance audits are executed, preventing upstream noise from confounding downstream alignment diagnostics.

from copy import deepcopy
import pm4py
from pm4py.objects.log.obj import EventLog, Trace, Event


def build_log_from_variants(variant_counts: dict[str, int]) -> EventLog:
    """Expand a variant-frequency table into an EventLog using pm4py.parse_event_log_string."""
    expanded_traces = [
        trace_str
        for trace_str, count in variant_counts.items()
        for _ in range(count)
    ]
    return pm4py.parse_event_log_string(*expanded_traces, sep=",")


def normalize_event_log(
    log: EventLog,
    label_map: dict[str, str] | None = None,
    remove_activities: set[str] | None = None,
    fix_notify_decision_order: bool = False,
) -> EventLog:
    """
    Transparent normalization pipeline:
    1. Maps renamed labels (e.g., 'Risk Screen' -> 'Classify').
    2. Optionally removes technical events (e.g., 'Queue Routed').
    3. Optionally restores 'Decision,Notify' order where warehouse ingestion inverted them.
    """
    label_map = label_map or {}
    remove_activities = remove_activities or set()
    normalized_trace_strings: list[str] = []

    for trace in log:
        activities = [
            label_map.get(event["concept:name"], event["concept:name"])
            for event in trace
            if event["concept:name"] not in remove_activities
        ]
        if fix_notify_decision_order and len(activities) >= 2:
            if activities[-2:] == ["Notify", "Decision"]:
                activities[-2:] = ["Decision", "Notify"]
        normalized_trace_strings.append(",".join(activities))

    return pm4py.parse_event_log_string(*normalized_trace_strings, sep=",")


def evaluate_conformance(
    log: EventLog,
    net,
    im,
    fm,
    compute_precision: bool = False,
) -> dict:
    """Compute DFG, alignment diagnostics, alignment fitness, and optional alignment precision."""
    dfg, start_activities, end_activities = pm4py.discover_dfg(log)
    alignments = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    fitness = pm4py.fitness_alignments(log, net, im, fm)
    result = {
        "dfg": dfg,
        "start_activities": start_activities,
        "end_activities": end_activities,
        "alignments": alignments,
        "fitness": fitness,
    }
    if compute_precision:
        result["precision"] = pm4py.precision_alignments(log, net, im, fm)
    return result


def main() -> None:

        "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,
        "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
        "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,

## 7. Provisional conclusion

**Primary Explanation for the Conformance Collapse (Confidence: High, 90–95%)**
The sharp drop in measured conformance—from 93% fitting traces (mean cost 0.08) in April–May to 32% (cost 0.74) in June–July—was primarily driven by uncoordinated logging and ETL changes, followed in August–September by normative model obsolescence. In June–July, three data-pipeline artifacts explain 57 of the 61 percentage-point drop in fitting traces: UI Release 4.2 renaming `Classify` to `Risk Screen` (+26 points upon remapping), the event gateway injecting technical `Queue Routed` events (+23 points upon removal), and the June 15 ETL pipeline substituting warehouse-ingestion timestamps that inverted `Decision` and `Notify` (+8 points upon restoring source sequence order). In August–September, the secondary drop from 89% to 66% fitting traces is mainly explained (+20 points) by the August 1 policy requiring `Supervisor Sign-off` on claims above EUR 50,000 without updating the normative process tree.

**Assessment of Residual Compliance Risk (Confidence: Moderate, 55–65%)**
Even after normalizing labels, technical events, event ordering, and optional sign-offs, 11%–14% of traces remain non-fitting (mean cost 0.12–0.15). Specifically, 25 June–July (3.8%) and 30 August–September (4.8%) `Enhanced Review` cases lack a recorded `Compliance Check`, while `Manual Override` cases grew from 20 to 35. A localized but serious compliance gap remains plausible.

**Immediate Actions**
- **IT:** Configure the ETL pipeline to sort by source-system sequence numbers, filter `Queue Routed` from business logs, maintain an alias map (`Risk Screen` $\rightarrow$ `Classify`), and verify in source database tables whether missing `Compliance Check` events reflect dropped messages or unexecuted screens.
- **Process Owners:** Upgrade the normative model to enforce `Supervisor Sign-off` conditionally on `claim_amount > EUR 50,000` and define explicit authorization rules for `Manual Override`.
- **Compliance:** Perform a manual audit of the 55 `Enhanced Review` cases missing `Compliance Check` and audit whether all claims over EUR 50,000 received sign-off.

**What Must Not Be Claimed Yet**
Nobody may claim that employees caused the aggregate conformance collapse, nor that stable approval and appeal rates prove zero noncompliance. Specifically, until source provenance checks and high-value attribute stratification are completed, it must not be claimed either that the 55 missing compliance checks are confirmed employee violations or that the 86% fitness under an optional sign-off model proves compliance with the EUR 50,000 threshold.

## 8. Model-governance recommendation

1. **Synchronized Model Versioning and Policy Change Control:** Bind every operational policy change (such as the 2026-08-01 EUR 50,000 `Supervisor Sign-off` rule) to a versioned normative process model release with effective-date metadata, ensuring historical traces are evaluated against the normative specification active at case start or decision time.
2. **Immutable Event-Semantic Contracts and Taxonomy Mapping:** Decouple front-end UI screen labels (`Risk Screen` vs. `Classify`) and patch-level instrumentation changes (`Manual Override`) from canonical process-mining activity identifiers (`concept:name`) through a governed schema registry that requires formal semantic-mapping sign-off before UI deployments.
3. **Explicit Technical-Event Tiering and Filtering Policy:** Require all middleware, queue, and event-gateway telemetry (such as `Queue Routed`) to carry an explicit event-layer classification attribute (`event_tier = technical | business`) and a valid system/human actor type so conformance pipelines automatically exclude infrastructure routing hops from business control-flow views.
4. **Dual-Timestamp and Monotonic Sequence Provenance:** Mandate that ETL pipelines preserve both immutable source-system business occurrence timestamps (`time:timestamp`), monotonic intra-case transaction sequence numbers (`source_seq_num`), and warehouse ingestion timestamps (`etl:ingested_at`), strictly prohibiting ingestion timestamps from overwriting or ordering business execution events.
5. **Data-Aware and Multi-Perspective Conformance Constraints:** Encode attribute-dependent regulatory rules (such as `claim_amount > EUR 50,000 => Supervisor Sign-off` and role authorization rules for `Manual Override`) using data-aware Petri nets or stratified sub-model conformance checks, rather than relying on overpermissive optional control-flow branches (`X(activity, tau)`) that inflate fitness at the expense of precision.
6. **Automated Post-Release Canary Conformance Validation:** Run automated canary conformance and DFG-drift regression checks in staging and on the first 48 hours of post-release production logs after every UI, gateway, or ETL deployment—alerting IT immediately if unmapped activity labels, sudden spikes in missing `org:resource` rates, or reversed activity pairs (`Notify -> Decision`) appear.
