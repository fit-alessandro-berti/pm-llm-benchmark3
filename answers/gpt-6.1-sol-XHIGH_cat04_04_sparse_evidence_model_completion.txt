# 1. Evidence Ledger

The supplied DFG agrees with the variants. C and E are present in all 30 cases, S in 23, and X in 2. Seven cases have no visible S. These are sample counts, not probabilities of routing choices. The 7/30 absence fraction mixes legitimate skips and lost observations; it is not an estimate of supplier-event loss, and S5 does not specify a comparable denominator.

**Both directions in a DFG do not prove concurrency.** C→E and E→C can come from parallel completions, XOR between sequential routes, conditional order changes, or tied timestamps ordered by ingestion. In other datasets, rework can also create bidirectional edges. Here no repeated activity is observed, so no loop is needed to explain the sample. A DFG edge means recorded adjacency, not causality. Similarly, S→X and X→S show alternative completion orders, not proven overlap.

# 2. Shared Assumptions

1. The scope is completed production orders containing only the eight named activities. R, C, E, A, P, and Z each occur once; visible S and X occur zero or one time. Only X has an explicit at-most-once domain rule. The other occurrence bounds, exclusion of cancellation, and fixed A,P,Z suffix are sample-based restrictions.
2. Visible transitions represent recorded completions. Precedence constrains that completion projection. Unordered nodes permit concurrency in a candidate's execution semantics, but do not establish historical overlap. Durations, scheduling, and resources are unmodeled.
3. Every candidate requires C and E before A, A before P, and any visible S or X before A. X also requires completion of C and E.
4. A no-visible-S route abstracts either a legitimate stocked-component skip or a required physical S whose event was lost. Its silent transition neither certifies procurement completion nor authorizes omission. A richer physical/observation model would keep required S and separately allow its event to be erased.
5. The absent external/stocked attribute prevents data guards for supplier requirement. Other eligibility/routing attributes are absent too. XOR and silent choices approximate unknown conditions; they are nondeterministic control flow, not estimated probabilities. Counts do not weight the branches.
6. Optional X represents a genuine skip versus one execution; no missing-X mechanism is assumed. Optional S represents observational optionality with the two explanations above. Absence alone cannot classify a case as stocked.
7. The generalized candidates use a completed check as a sufficient-information witness for S. D5 allows information to become available earlier, so this is a stronger assumption and a possible source of underfitting.
8. All models describe possible complete recorded traces, not a population distribution or a proven scheduling policy. Fitting these traces establishes compatibility, not identification.

# 3. Conservative Candidate

**Inductive bias.** Memorize the seven observed complete variants and admit no additional complete behavior. The varying C/E orders become separate sequential routes rather than a concurrency claim. This resolves neither S1 versus S2 nor the source of S absences. It prioritizes empirical caution, with strong risk of overfitting incidental ordering and export errors while underfitting legitimate future behavior.

**Formal expression**, where a dot denotes concatenation:

`R · XOR(C E S, E C S, C E, E C, C S E, C E S X, E C X S) · A · P · Z`.

The following full-sequence enumeration has the same visible language as that factored expression.

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

L = {
    "R": "Register Order", "C": "Credit Check",
    "E": "Engineering Review", "S": "Supplier Confirmation",
    "X": "Expedite Review", "A": "Approve Configuration",
    "P": "Release Production", "Z": "Archive Case",
}
variants = [
    "R C E S A P Z", "R E C S A P Z",
    "R C E A P Z", "R E C A P Z", "R C S E A P Z",
    "R C E S X A P Z", "R E C X S A P Z",
]
model_conservative = ProcessTree(operator=Operator.XOR)
for text in variants:
    branch = ProcessTree(operator=Operator.SEQUENCE,
                         parent=model_conservative)
    branch.children = [
        ProcessTree(label=L[token], parent=branch)
        for token in text.split()
    ]
    model_conservative.children.append(branch)
```

Duplicate labels are distinct nodes; no object is reused across branches. Conversion creates several transitions with the same visible label. Alignments can search the alternatives, but duplicates can complicate token replay and structural metrics. Enumeration grows with variant count and length, repeats shared work, and explains examples better than dependencies. Factoring shared prefixes/suffixes improves size but does not solve interleaving explosion. No branch probabilities are attached.

**Deliberately excluded:**

- Every unobserved complete combination, including C,E,X,S and E,C,S,X between R and A.
- X without visible S, even though D6 specifies no supplier prerequisite.
- E,S,C, premature approval/release, repeated activities, and post-approval reviews.

**Known underfitting risks:**

- Unseen legitimate interleavings, stocked expedited orders, and expedited cases with lost S events.
- Engineering-triggered procurement, rework, or other valid new routes.
- Freezing ingestion tie-breaking into route restrictions.

# 4. Balanced Candidate

**Inductive bias.** Generalize C/E to independently enabled work, permit S after C without waiting for E, and make X independently optional after both checks. This admits all observations and uses D6/S6 to generalize X instead of inferring a supplier prerequisite from two co-occurrences. Every visible S follows C, motivating a provisional credit gate; D5's engineering-only trigger remains an alternative hypothesis. The candidate balances a compact dependency explanation with explicit uncertainty about concurrency, supplier enablement, and optionality.

**Formal expression.** Let `opt(Y)=XOR(τ,Y)`:

`R · PO({C,E,opt(S),opt(X)}; C<opt(S), C<opt(X), E<opt(X)) · A · P · Z`.

The whole PO block finishes before A. In its visible projection C<S when S occurs, and both C and E precede X when X occurs.

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

L = {
    "R": "Register Order", "C": "Credit Check",
    "E": "Engineering Review", "S": "Supplier Confirmation",
    "X": "Expedite Review", "A": "Approve Configuration",
    "P": "Release Production", "Z": "Archive Case",
}

def po(nodes, edges):
    n = len(nodes)
    reach = [[False] * n for _ in range(n)]
    for i, j in edges:
        reach[i][j] = True
    for k in range(n):
        for i in range(n):
            for j in range(n):
                reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j])
    if any(reach[i][i] for i in range(n)):
        raise ValueError("Cyclic precedence relation")
    result = StrictPartialOrder(nodes)
    for i in range(n):
        for j in range(n):
            if reach[i][j]:
                result.order.add_edge(nodes[i], nodes[j])
    return result

def opt(code):
    return OperatorPOWL(
        Operator.XOR, [SilentTransition(), Transition(L[code])]
    )

body = po(
    [Transition(L["C"]), Transition(L["E"]), opt("S"), opt("X")],
    [(0, 2), (0, 3), (1, 3)],
)
nodes = [Transition(L["R"]), body, Transition(L["A"]),
         Transition(L["P"]), Transition(L["Z"])]
model_balanced = po(nodes, [(0, 1), (1, 2), (2, 3), (3, 4)])
```

The helper stores transitive closure explicitly, ensuring a strict partial order rather than only a collection of immediate edges.

The choices between sequence, concurrency, and partial order are:

- **C/E:** no edge, representing independent enablement. S2 and both recorded orders motivate this hypothesis; D7/S7 prevent claiming proof. XOR between two sequential routes remains observationally plausible.
- **C/S:** C precedes S, preserving all observed supplier orders. Inferring enablement from that consistent completion order is provisional.
- **E/S:** no edge; requiring E<S would reject V5. S may finish before or after E once C has completed.
- **C/E/X:** C and E both precede X, enforcing the D6/S6 join.
- **S/X:** no edge; S6 and both X cases permit either completion order. Actual overlap is unidentified. X without visible S is also allowed because no supplied rule requires S for X.
- **A/P/Z:** all selected work finishes before A, then P and Z follow sequentially.

Dependencies apply to optional nodes even when their silent branch is chosen. Such a skip creates no visible event and cannot bypass the principal checks before approval.

**Deliberately excluded:**

- S before C, including E,S,C.
- X before either check, reviews after A, and P before A.
- Repetitions, cancellation, missing principal checks, and altered start/end boundaries.

**Known underfitting risks:**

- Engineering-only procurement enablement or intermediate information available before either check completes.
- Condition-specific sequential routing instead of concurrent principal checks.
- Multiple supplier confirmations, retries, and rework.
- Lack of sourcing guards: no-visible-S can neither enforce external obligations nor distinguish lost events from true skips.

# 5. Permissive Candidate

**Inductive bias.** Accept D5's either-check procurement trigger as a reasonable possibility and allow all combinations of optional X and supplier observation under the principal-check, approval, and release boundaries. Engineering completion may now enable S before C finishes. This explores uncertain dependencies while retaining bounded, single-occurrence behavior; it does not treat all admitted combinations as equally likely or empirically established.

**Formal expression:**

- `B0 = PO({C,E,opt(X)}; C<opt(X), E<opt(X))`;
- `BC = PO({C,E,S,opt(X)}; C<S, C<opt(X), E<opt(X))`;
- `BE = PO({C,E,S,opt(X)}; E<S, C<opt(X), E<opt(X))`.

`R · XOR(B0, BC, BE) · A · P · Z`.

For visible S the union imposes **C<S or E<S**, not both. BC and BE overlap when both checks finish before S. This is an alternative-trigger representation of a language-level disjunction, not a dynamic OR-join or a recovered routing attribute.

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

L = {
    "R": "Register Order", "C": "Credit Check",
    "E": "Engineering Review", "S": "Supplier Confirmation",
    "X": "Expedite Review", "A": "Approve Configuration",
    "P": "Release Production", "Z": "Archive Case",
}

def po(nodes, edges):
    n = len(nodes)
    reach = [[False] * n for _ in range(n)]
    for i, j in edges:
        reach[i][j] = True
    for k in range(n):
        for i in range(n):
            for j in range(n):
                reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j])
    if any(reach[i][i] for i in range(n)):
        raise ValueError("Cyclic precedence relation")
    result = StrictPartialOrder(nodes)
    for i in range(n):
        for j in range(n):
            if reach[i][j]:
                result.order.add_edge(nodes[i], nodes[j])
    return result

def route(trigger):
    # Fresh node objects in every branch, including duplicate visible labels.
    nodes = [Transition(L["C"]), Transition(L["E"])]
    edges = []
    if trigger is not None:
        nodes.append(Transition(L["S"]))
        edges.append((0 if trigger == "C" else 1, 2))
    xi = len(nodes)
    nodes.append(OperatorPOWL(
        Operator.XOR, [SilentTransition(), Transition(L["X"])]
    ))
    edges.extend([(0, xi), (1, xi)])
    return po(nodes, edges)

body = OperatorPOWL(
    Operator.XOR, [route(None), route("C"), route("E")]
)
nodes = [Transition(L["R"]), body, Transition(L["A"]),
         Transition(L["P"]), Transition(L["Z"])]
model_permissive = po(nodes, [(0, 1), (1, 2), (2, 3), (3, 4)])
```

Duplicate labels across branches are intentional. A visible trace admitted by both supplier branches does not receive extra probability: no probabilities are specified.

**Boundary of reasonable generalization.** E,S,C is supported as a possibility by D5. X without visible S is supported by D6 plus either physical optionality or event loss. Their combinations are permitted. S as the first completion after R remains excluded by the completed-check information-witness assumption, which is stronger than D5. Premature X, approval without both checks, and release before approval remain forbidden. A no-visible-S external order remains an observation abstraction, not an exemption from S3.

**Deliberately excluded:**

- S before both principal completions; X before either check; premature approval/release.
- Multiple X events, repeated checks or confirmations, and post-approval reviews.
- Missing principal checks, cancellation, and different boundaries.

**Known underfitting risks:**

- Legitimate S completion based on intermediate information before either principal completion.
- Multiple suppliers, procurement retries, rework, cancellation, and additional eligibility conditions.

Its additional **overgeneralization risks** are admitting an engineering-only supplier trigger when a real credit gate applies, and treating optionality as independent when hidden eligibility conditions couple activities.

# 8. Validation Code

The script below is self-contained in a PM4Py environment and reconstructs every candidate. Short log labels are replaced with full activity names after parsing. It computes available metrics and explicitly reports API failures rather than inventing values. These are proposed executable checks, not reported results of a PM4Py run.

Bounded playout explores Petri-net firings, including silent transitions, and collects accepting visible traces of at most eight events. Successful exploration is exhaustive within that bound; a state-budget overrun raises an error. These candidates are structurally loop-free with at most eight visible events, so the bound covers their whole visible languages. For arbitrary unbounded models, bounded or sampled playout cannot prove language inclusion.

```python
from collections import deque
import pm4py
from pm4py.objects.process_tree.obj import ProcessTree, Operator
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition,
)
from pm4py.objects.petri_net import semantics

L = {
    "R": "Register Order", "C": "Credit Check",
    "E": "Engineering Review", "S": "Supplier Confirmation",
    "X": "Expedite Review", "A": "Approve Configuration",
    "P": "Release Production", "Z": "Archive Case",
}
SHORT = {label: code for code, label in L.items()}
VARIANTS = [
    (12, "R,C,E,S,A,P,Z"), (7, "R,E,C,S,A,P,Z"),
    (4, "R,C,E,A,P,Z"), (3, "R,E,C,A,P,Z"),
    (2, "R,C,S,E,A,P,Z"), (1, "R,C,E,S,X,A,P,Z"),
    (1, "R,E,C,X,S,A,P,Z"),
]

# Reconstruct the 30-case log with the stated multiplicities.
strings = [text for count, text in VARIANTS for _ in range(count)]
log = pm4py.parse_event_log_string(strings)
for trace in log:
    for event in trace:
        event["concept:name"] = L[event["concept:name"]]
assert len(log) == 30
observed = {
    tuple(event["concept:name"] for event in trace) for trace in log
}
assert len(observed) == 7

model_conservative = ProcessTree(operator=Operator.XOR)
for _, text in VARIANTS:
    branch = ProcessTree(operator=Operator.SEQUENCE,
                         parent=model_conservative)
    branch.children = [
        ProcessTree(label=L[token], parent=branch)
        for token in text.split(",")
    ]
    model_conservative.children.append(branch)

# POWL helper with explicit transitive closure.
def po(nodes, edges):
    n = len(nodes)
    reach = [[False] * n for _ in range(n)]
    for i, j in edges:
        reach[i][j] = True
    for k in range(n):
        for i in range(n):
            for j in range(n):
                reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j])
    if any(reach[i][i] for i in range(n)):
        raise ValueError("Cyclic precedence relation")
    result = StrictPartialOrder(nodes)
    for i in range(n):
        for j in range(n):
            if reach[i][j]:
                result.order.add_edge(nodes[i], nodes[j])
    return result

def opt(code):
    return OperatorPOWL(
        Operator.XOR, [SilentTransition(), Transition(L[code])]
    )

def surround(body):
    nodes = [Transition(L["R"]), body, Transition(L["A"]),
             Transition(L["P"]), Transition(L["Z"])]
    return po(nodes, [(0, 1), (1, 2), (2, 3), (3, 4)])

model_balanced = surround(po(
    [Transition(L["C"]), Transition(L["E"]), opt("S"), opt("X")],
    [(0, 2), (0, 3), (1, 3)],
))

def supplier_route(trigger):
    nodes = [Transition(L["C"]), Transition(L["E"])]
    edges = []
    if trigger is not None:
        nodes.append(Transition(L["S"]))
        edges.append((0 if trigger == "C" else 1, 2))
    xi = len(nodes)
    nodes.append(opt("X"))
    edges.extend([(0, xi), (1, xi)])
    return po(nodes, edges)

model_permissive = surround(OperatorPOWL(
    Operator.XOR,
    [supplier_route(None), supplier_route("C"), supplier_route("E")],
))
models = {
    "conservative": model_conservative,
    "balanced": model_balanced,
    "permissive": model_permissive,
}

# Exact acceptance helpers using PM4Py firing semantics.
def marking_key(marking):
    return frozenset((p, int(n)) for p, n in marking.items() if n)

def silent_closure(net, markings, state_cap=200000):
    reached, queue = {}, deque()
    for marking in markings:
        key = marking_key(marking)
        if key not in reached:
            reached[key] = marking
            queue.append(marking)
    while queue:
        marking = queue.popleft()
        for transition in semantics.enabled_transitions(net, marking):
            if transition.label is None:
                nxt = semantics.execute(transition, net, marking)
                if nxt is None:
                    continue
                key = marking_key(nxt)
                if key not in reached:
                    reached[key] = nxt
                    queue.append(nxt)
                    if len(reached) > state_cap:
                        raise RuntimeError("Silent closure exceeded state budget")
    return list(reached.values())

def accepts_trace(net, im, fm, word):
    # Existential acceptance over all duplicate-label and silent choices.
    current = silent_closure(net, [im])
    for label in word:
        following = {}
        for marking in current:
            for transition in semantics.enabled_transitions(net, marking):
                if transition.label == label:
                    nxt = semantics.execute(transition, net, marking)
                    if nxt is not None:
                        following[marking_key(nxt)] = nxt
        if not following:
            return False
        current = silent_closure(net, following.values())
    return any(marking == fm for marking in current)

def bounded_playout(net, im, fm, max_events=8, state_cap=200000):
    # Keep visible prefixes in state keys to retain distinct interleavings.
    queue = deque([(im, ())])
    seen = {(marking_key(im), ())}
    accepted = set()
    while queue:
        marking, word = queue.popleft()
        if marking == fm:
            accepted.add(word)
        for transition in semantics.enabled_transitions(net, marking):
            if transition.label is None:
                next_word = word
            elif len(word) < max_events:
                next_word = word + (transition.label,)
            else:
                continue
            nxt = semantics.execute(transition, net, marking)
            if nxt is None:
                continue
            key = (marking_key(nxt), next_word)
            if key not in seen:
                seen.add(key)
                queue.append((nxt, next_word))
                if len(seen) > state_cap:
                    raise RuntimeError("Bounded playout exceeded state budget")
    return accepted
```

# 9. Recommendation and Data-Collection Plan

Use **model_balanced immediately for analysis and anomaly triage**, marking the credit-to-supplier dependency as provisional. It fits every observed variant, preserves the domain joins, and avoids imposing a supplier requirement on X from two examples. Use **model_permissive for sensitivity analysis** of the engineering supplier trigger. Keep the conservative model as an observed-language baseline. None should alone authorize missing supplier confirmation for an external order.

Collect a prospective cohort spanning external/stocked orders, expedited/ordinary orders, and operating teams. Freeze model predictions before evaluating it. Oversample rare informative conditions for mechanism investigation, but report representative frequency estimates separately.

1. **Identify skips versus event loss.** Export order/component IDs, external/stocked status, supplier-required flag and reason, supplier-event ID, source occurrence time, ingestion time, and export status. Reconcile no-S cases against procurement records. Estimate missingness among events that should exist, and stratify by supplier, expedite status, route, and integration version. Repair/re-export histories before interpreting order differences as process differences.
2. **Identify sequence versus concurrency.** Collect C/E enablement, start, completion, suspension/resumption where relevant, performer, blocking reason, workflow version, and routing decision. Preserve timestamp resolution, clock synchronization information, and tie flags. Trustworthy `C_start < E_start < C_complete < E_complete`, or the reverse overlap, contradicts universal finish-before-start sequencing. Independent enablement helps identify workflow concurrency. Absence of overlap can result from resource scheduling and does not prove a sequence constraint.
3. **Identify XOR routing.** Reconcile S1/S2 by recording the conditions under which each applies. Distinct nonoverlapping C-then-E and E-then-C routes tied to a routing attribute support XOR between sequences. More completion traces alone may remain indistinguishable from a parallel model's schedules. XOR choosing only C or only E contradicts all current complete cases and D3; a verified single-check case would require an exception to D3 or a data-quality investigation.
4. **Identify supplier prerequisites.** Record the actual supplier trigger, when usable credit/engineering information becomes available, sourcing eligibility, and S start/completion. A reliable `R,E,S,C,A,P,Z` distinguishes the engineering-trigger model from the balanced C gate. `R,S,C,E,A,P,Z` with documented earlier intermediate information would overturn both generalized candidates' completion-witness assumption while potentially agreeing with D5. Absence of these traces does not establish the C gate.
5. **Identify optionality and expedite guards.** Record expedite eligibility/reason, authorization, and X lifecycle. Verified stocked `R,C,E,X,A,P,Z` establishes X without physical S. External no-S exports with recovered procurement events establish loss instead of optionality. Additional S-before-X/X-before-S cases plus lifecycle events test order allowances and overlap. C/E completion variation alone still cannot distinguish concurrency from conditional sequence.
6. **Challenge shared restrictions.** Link approval/release authorization IDs; check lifecycle ordering. Inspect repeated checks, multiple confirmations, cancellation, and reopened approval. Verified premature X or release is a compliance exception or evidence requiring rule qualification, not a reason to automatically permit that behavior.

Reserve a time-separated holdout and evaluate by sourcing/expedite strata. Adjudicate cases on which the candidates disagree, separating legitimate new behavior from data errors. Combine metrics with false-alarm review, lifecycle evidence, routing guards, and missingness estimates; a scalar discovery score cannot resolve these causal ambiguities.

# 10. Uncertainty Statement

Confidence is qualitative: these sparse observations do not justify posterior probabilities for the competing process hypotheses.

| Decision | Confidence | Basis and uncertainty |
|---|---|---|
| Intended R start, Z end, A before P | High within scope. | D1/D2 and all traces agree; canceled/exceptional cases are unobserved. |
| C and E before A | Medium-to-high. | D3 and all 30 cases agree; policy exceptions could exist. |
| Visible S before A | Medium-to-high for this cohort. | D4 and visible events agree; hidden events prevent complete physical assessment. |
| Fixed A,P,Z adjacency and mandatory release | Moderate. | Universal here, but stronger than D2 and conditional on completed-order scope. |
| C/E concurrency rather than conditional sequential routing | Low-to-medium. | S2 and both completion orders motivate it; S1/D7/S7 leave it unidentified. |
| Balanced C-completion gate for S | Low-to-medium. | Every visible S follows C; completion consistency is not causal proof and D5 suggests another trigger. |
| Either-check supplier trigger | Medium as a domain possibility, low as an established rule. | D5 supports it; no E,S,C case exists. The completion-witness proxy is particularly uncertain. |
| Physical S optionality | Moderate as a conditional possibility; low for classifying the seven absences. | S3/S4 are compatible; absent sourcing data and event loss confound classification. |
| Optional, at-most-once X after both checks and before A | Medium-to-high for the intended rule. | D6/S6 agree with both cases; empirical coverage is sparse. |
| No fixed S/X completion order | Moderate as an allowance; low for actual overlap. | Both orders observed and S6 permits them. |
| X without physical S | Low-to-medium. | No supplied rule requires S for X; observed co-occurrence and hidden eligibility could still couple them. |
| Single C/E/S executions and no rework | Low-to-moderate beyond this sample. | No repetitions observed; only X has an explicit upper bound. |

A material alternative is that S1 is a universal implemented rule and E-before-C records contain timestamp, ingestion, or export errors. Then a repaired-log sequential model plus an explicit observation-error mechanism would be preferable to concurrent candidates. Another plausible explanation is condition-specific sequential routing, which can generate the same completion words; lifecycle and routing evidence are needed to distinguish it.

If all seven S absences are external orders with lost confirmations, the physical model should require S in that cohort and represent erasure separately. If intermediate engineering information enables S before either check completes, even the permissive candidate underfits. Perfect observed-trace compatibility, structural soundness, and compactness cannot identify the true process or resolve those alternatives.
