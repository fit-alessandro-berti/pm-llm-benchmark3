# 1. Source-Semantics Baseline

Witnesses below are complete visible traces. Abbreviations:

- `Reg` = Register Change  
- `Risk` = Assess Risk  
- `Ev` = Prepare Evidence  
- `Leg` = Legal Review  
- `Cfg` = Configure Trial  
- `Insp` = Inspect Trial  
- `Cor` = Correct Defect  
- `Rel` = Release Change  
- `Arc` = Archive Change  

Tau transitions are hidden in the witnesses.

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| INV-01 | The model is a sound workflow net with an exact initial marking and exact final marking. | `Reg, Risk, Ev, Leg, Cfg, Insp, Rel, Arc` | Any complete visible sequence that does not end in the exact final marking, e.g. `Reg, Risk, Ev, Leg, Cfg, Insp, Rel` | Yes |
| INV-02 | `Reg` occurs first, before both `Risk` and `Ev`. | `Reg, Risk, Ev, Leg, Cfg, Insp, Rel, Arc` | `Risk, Reg, Ev, Cfg, Insp, Rel, Arc` | Yes |
| INV-03 | After `Reg`, `Risk` and `Ev` are unordered and may occur in either order. | `Reg, Risk, Ev, ...` and `Reg, Ev, Risk, ...` | A model that rejects either order is non-conforming; trace-level negative: `Reg, Ev, Cfg, Insp, Rel, Arc` omits `Risk` before verification | Yes |
| INV-04 | Legal review is optional: exactly one XOR branch occurs, either `Leg` or a silent skip. | `Reg, Risk, Ev, Leg, Cfg, Insp, Rel, Arc` and `Reg, Risk, Ev, Cfg, Insp, Rel, Arc` | `Reg, Risk, Leg, Leg, Ev, Cfg, Insp, Rel, Arc` | Ambiguous for skip vs omitted; `Leg` presence is observable |
| INV-05 | There is no order between the optional-legal branch and the verification loop; they may overlap. | `Reg, Risk, Ev, Cfg, Leg, Insp, Rel, Arc` | `Reg, Risk, Ev, Cfg, Insp, Rel, Leg, Arc` | Yes |
| INV-06 | Verification cannot start until both `Risk` and `Ev` are complete. | `Reg, Risk, Ev, Cfg, Insp, Rel, Arc` | `Reg, Risk, Leg, Cfg, Insp, Rel, Arc` | Yes |
| INV-07 | Each verification iteration executes `Cfg` before `Insp`; iterations are separated by `Cor`. | `Reg, Risk, Ev, Cfg, Insp, Cor, Cfg, Insp, Rel, Arc` | `Reg, Risk, Ev, Insp, Cfg, Rel, Arc` or `Reg, Risk, Ev, Cor, Cfg, Insp, Rel, Arc` | Yes |
| INV-08 | At least one verification iteration occurs before release. | `Reg, Risk, Ev, Cfg, Insp, Rel, Arc` | `Reg, Risk, Ev, Leg, Rel, Arc` | Yes |
| INV-09 | `Rel` waits for both the optional-legal branch and the verification loop. | `Reg, Risk, Ev, Leg, Cfg, Insp, Rel, Arc` | `Reg, Risk, Ev, Cfg, Insp, Rel, Arc` without the silent skip in the full net; `Reg, Risk, Ev, Leg, Rel, Arc` | Ambiguous after hiding tau for skip vs omitted; visible missing branch is observable |
| INV-10 | `Arc` occurs after `Rel` and is final. | All complete traces end with `Arc` | `Reg, Risk, Ev, Cfg, Insp, Arc, Rel` | Yes |
| INV-11 | Visible activity labels are unique; silent transitions have label `None`. | Traces use each visible label at most once, except loop labels | Duplicate `Leg` in one trace | Yes for visible labels; tau itself is not observable |

# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| **Primary: POWL  accepting Petri net  BPMN** | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_bpmn(net, im, fm)`; reverse with `pm4py.convert_to_petri_net(bpmn)` for validation | Uses the supported POWL-to-Petri-net conversion; preserves Petri-net semantics for concurrency, optionality, loop, and synchronization; enables soundness, workflow-net, footprint, and reachability diagnostics | BPMN gateway semantics and layout may be ambiguous; silent routing nodes may be hidden or misread; PetriBPMN is not guaranteed to be a perfect inverse | Conversion exception; null markings; reverse net is not a workflow net or is unsound; bounded trace-set mismatch; positive witness missing or negative witness admitted |
| **Secondary: POWL  accepting Petri net  process tree  BPMN** | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_process_tree(net, im, fm)` inside `try/except`; if successful, `pm4py.convert_to_bpmn(tree)`; reverse with `pm4py.convert_to_petri_net(bpmn)` | If the source were block-structured, a process tree would give a clean BPMN; useful as a diagnostic of block-structuredness | The source is not block-structured enough: optional legal review is concurrent with the verification loop, but the verification loop also depends on `Prepare Evidence`; a process tree may impose false ordering or fail | `convert_to_process_tree` raises; or tree-derived BPMN round trip admits/rejects wrong traces; or tree imposes an order between optional legal review and verification |

# 3. Conversion Code

```python
import copy
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

# ---------------------------------------------------------------------------
# Authoritative source POWL model
# ---------------------------------------------------------------------------
register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(
    operator=Operator.XOR,
    children=[legal_review, skip_legal],
)

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[trial_body, correct_defect],
)

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[
        register,
        assess_risk,
        prepare_evidence,
        optional_legal,
        verification_loop,
        release_change,
        archive_change,
    ]
)

source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)

# ---------------------------------------------------------------------------
# Helpers
# ---------------------------------------------------------------------------
def require_markings(im, fm, context):
    if im is None or fm is None:
        raise ValueError(f"{context}: conversion returned null marking(s)")
    return im, fm

# ---------------------------------------------------------------------------
# Primary pipeline: POWL -> accepting Petri net -> BPMN
# ---------------------------------------------------------------------------
net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(source_powl)
require_markings(im_from_powl, fm_from_powl, "POWL -> Petri net")
print("POWL -> accepting Petri net: OK")

bpmn_from_net = pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)
print("Petri net -> BPMN (primary): OK")

# ---------------------------------------------------------------------------
# Secondary pipeline: POWL -> accepting Petri net -> process tree -> BPMN
# This is allowed to fail; failure may be the correct outcome.
# ---------------------------------------------------------------------------
tree_from_net = None
bpmn_from_tree = None

try:
    tree_from_net = pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)
    print("Petri net -> process tree: returned (inspect carefully; source may not be block-structured)")
    try:
        bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
        print("Process tree -> BPMN: OK")
    except Exception as exc:
        print(f"Process tree -> BPMN failed: {exc!r}")
except Exception as exc:
    print(f"Petri net -> process tree failed (acceptable for non-block-structured source): {exc!r}")

# ---------------------------------------------------------------------------
# Convert each produced BPMN model back to an accepting Petri net where possible
# ---------------------------------------------------------------------------
roundtrip_nets = {}

for name, bpmn in [
    ("bpmn_from_net", bpmn_from_net),
    ("bpmn_from_tree", bpmn_from_tree),
]:
    if bpmn is None:
        continue
    try:
        net_rt, im_rt, fm_rt = pm4py.convert_to_petri_net(bpmn)
        if im_rt is None or fm_rt is None:
            print(f"{name} -> Petri net returned null markings; skipping")
            continue
        roundtrip_nets[name] = (net_rt, im_rt, fm_rt)
        print(f"{name} -> accepting Petri net: OK")
    except Exception as exc:
        print(f"{name} -> Petri net failed: {exc!r}")

# ---------------------------------------------------------------------------
# Workflow-net and soundness diagnostics on every accepting net
# ---------------------------------------------------------------------------
accepting_nets = {
    "net_from_powl": (net_from_powl, im_from_powl, fm_from_powl),
}
accepting_nets.update(roundtrip_nets)

for name, (net, im, fm) in accepting_nets.items():
    try:
        is_wn = pm4py.check_is_workflow_net(net)
    except Exception as exc:
        is_wn = f"error: {exc!r}"

    try:
        sound = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
    except Exception as exc:
        sound = f"error: {exc!r}"

    print(f"[{name}] workflow_net={is_wn} sound={sound}")

# ---------------------------------------------------------------------------
# Save visualizations with clear filenames
# ---------------------------------------------------------------------------
pm4py.save_vis_powl(source_powl, "source_powl.png")
pm4py.save_vis_petri_net(net_from_powl, im_from_powl, fm_from_powl, "net_from_powl.png")
pm4py.save_vis_bpmn(bpmn_from_net, "bpmn_from_net_from_powl.png")

if tree_from_net is not None:
    pm4py.save_vis_process_tree(tree_from_net, "tree_from_net.png")

if bpmn_from_tree is not None:
    pm4py.save_vis_bpmn(bpmn_from_tree, "bpmn_from_tree.png")

for name, (net, im, fm) in roundtrip_nets.items():
    pm4py.save_vis_petri_net(net, im, fm, f"{name}_roundtrip.png")

print("Visualizations saved.")
```

# 4. Preservation and Loss Audit

Assessment terms used: `expected preserved`, `validated preserved`, `approximated`, `ambiguous`, `lost`, `conversion failed`, `not tested`.

| Source invariant | POWLPetri | PetriBPMN | PetriTree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| INV-01 Soundness and exact markings | expected preserved | ambiguous | conversion failed | ambiguous | `check_is_workflow_net` and `check_soundness` on nets; BPMN start/end events must map to non-null `im`/`fm` |
| INV-02 Register first | expected preserved | expected preserved | conversion failed | ambiguous | Sequence flow likely preserved; verify traces start with `Register Change` |
| INV-03 Assess/Prepare concurrency | expected preserved | approximated | conversion failed | ambiguous | Petri net has true concurrency; BPMN parallel gateway may be correct but layout is ambiguous; trace sets alone cannot prove true concurrency vs interleaving |
| INV-04 Optional legal XOR with silent skip | expected preserved | approximated | conversion failed | ambiguous | Silent skip may become an invisible gateway or be omitted; after hiding tau, skip is invisible |
| INV-05 No order between optional legal and verification | expected preserved | approximated | conversion failed | ambiguous | Must remain concurrent; BPMN may impose a false sequence if converter chooses XOR or sequence flow |
| INV-06 Verification synchronization | expected preserved | approximated | conversion failed | ambiguous | Join before loop must be preserved; BPMN may not show an explicit join |
| INV-07 Loop scope and order | expected preserved | approximated | conversion failed | ambiguous | POWL LOOP is body then optional `(Correct Defect + body)*`; BPMN loop marker may be misread |
| INV-08 Minimum loop iteration | expected preserved | ambiguous | conversion failed | ambiguous | BPMN loop may be interpreted as zero-or-more; zero-iteration release must be rejected |
| INV-09 Join before Release | expected preserved | approximated | conversion failed | ambiguous | Parallel join required; an XOR join would admit release after only one branch |
| INV-10 Finality | expected preserved | expected preserved | conversion failed | ambiguous | Archive after Release; BPMN end event should correspond to final marking |
| INV-11 Label uniqueness and tau | expected preserved | ambiguous | conversion failed | ambiguous | Silent tau may be hidden or unlabeled; visible labels must remain unique for trace comparison |

Key distinctions:

- **True concurrency versus arbitrary interleaving.** The Petri net preserves true concurrency. BPMN parallel gateways also denote true concurrency, but a BPMN diagram may be read as arbitrary interleaving. Process trees with AND blocks also denote concurrency but impose block structure. Trace-set comparison alone cannot distinguish true concurrency from interleaving; footprints or partial-order semantics would be needed for stronger evidence.
- **Lack of edge between Optional Legal Review and verification.** The source has no edge between `optional_legal` and `verification_loop`. They may overlap. A BPMN conversion that places them in sequence, or joins them with an XOR, loses this invariant.
- **Silent optional behavior.** The XOR skip is a tau transition. After hiding tau, a trace without `Legal Review` is valid, but it is indistinguishable from a trace where the optional branch was omitted entirely. Tau-aware marking checks are needed to confirm the skip actually fired.
- **Binary-loop semantics.** The POWL LOOP is not a generic “repeat as needed” block. It is: execute `trial_body` once, then optionally execute `Correct Defect` followed by `trial_body` again. At least one `Configure Trial`/`Inspect Trial` iteration is mandatory. A BPMN loop marker may be misread as zero-or-more.
- **Join before Release Change.** Release requires both the optional-legal branch and the verification loop. In BPMN this should be a parallel join. An exclusive join would admit release after only one branch.
- **Activity-label uniqueness.** Source visible labels are unique. BPMN conversion may duplicate or rename labels, which makes trace comparison ambiguous. Silent transitions must remain label-`None`.
- **Initial and final markings.** The Petri net conversion must return non-null `im` and `fm`. BPMN has start/end events rather than markings; reverse conversion must recover exact final-marking behavior.
- **Gateway or routing-node ambiguity.** BPMN visual layout can imply ordering that is not in the model. Parallel gateways, exclusive gateways, loop markers, and silent routing nodes must be annotated.

# 5. Round-Trip Validation Code

This code assumes the Section 3 variables exist: `net_from_powl`, `im_from_powl`, `fm_from_powl`, `roundtrip_nets`, and `accepting_nets`.

```python
import copy

# ---------------------------------------------------------------------------
# Marking and transition helpers
# ---------------------------------------------------------------------------
def marking_key(marking):
    if marking is None:
        return None
    try:
        return tuple(sorted((str(place), int(marking[place])) for place in marking))
    except Exception:
        return tuple(sorted((str(place), int(count)) for place, count in marking.items()))


def markings_equal(m1, m2):
    return marking_key(m1) == marking_key(m2)


def fire_transition(net, transition, marking):
    new_marking = copy.deepcopy(marking)
    for arc in transition.in_arcs:
        weight = getattr(arc, "weight", 1) or 1
        new_marking[arc.source] -= weight
    for arc in transition.out_arcs:
        weight = getattr(arc, "weight", 1) or 1
        new_marking[arc.target] += weight
    return new_marking

# ---------------------------------------------------------------------------
# Bounded visible-trace exploration
# ---------------------------------------------------------------------------
LOOP_ITERATION_LABELS = {"Inspect Trial"}
MAX_VISIBLE_LEN = 12
MAX_LOOP_ITERATIONS = 3
MAX_SILENT_DEPTH = 20
MAX_STATES = 20000


def explore_visible_traces(
    net,
    im,
    fm,
    max_visible_len=MAX_VISIBLE_LEN,
    max_loop_iterations=MAX_LOOP_ITERATIONS,
    max_silent_depth=MAX_SILENT_DEPTH,
    max_states=MAX_STATES,
):
    """
    Explore visible traces up to a bounded length and loop-iteration count.
    Transitions with label None are treated as tau and hidden.
    A completed trace must reach exactly the final marking.
    Silent cycles are avoided by tracking the silent-only marking chain.
    """
    if im is None or fm is None:
        return set()

    traces = set()
    visited = set()
    state_count = 0

    def dfs(marking, visible, loop_count, silent_depth, silent_chain):
        nonlocal state_count
        state_count += 1

        if state_count > max_states:
            return

        if markings_equal(marking, fm):
            traces.add(visible)
            return

        if len(visible) >= max_visible_len or loop_count > max_loop_iterations:
            return

        key = (marking_key(marking), visible, loop_count)
        if key in visited:
            return
        visited.add(key)

        try:
            enabled = pm4py.get_enabled_transitions(net, marking)
        except Exception:
            return

        for trans in enabled:
            label = trans.label

            if label is None:
                if silent_depth >= max_silent_depth:
                    continue
                new_marking = fire_transition(net, trans, marking)
                mk = marking_key(new_marking)
                if mk in silent_chain:
                    continue
                dfs(
                    new_marking,
                    visible,
                    loop_count,
                    silent_depth + 1,
                    silent_chain | {mk},
                )
            else:
                new_loop_count = loop_count + (1 if label in LOOP_ITERATION_LABELS else 0)
                if new_loop_count > max_loop_iterations:
                    continue
                new_marking = fire_transition(net, trans, marking)
                dfs(
                    new_marking,
                    visible + (label,),
                    new_loop_count,
                    0,
                    frozenset({marking_key(new_marking)}),
                )

    dfs(im, tuple(), 0, 0, frozenset({marking_key(im)}))

    if state_count >= max_states:
        print("WARNING: state bound reached; bounded trace set may be incomplete")

    return traces


def replay_visible_trace(net, im, fm, trace):
    """
    Replay one visible trace, allowing silent transitions before/between/after
    visible activities. Returns True only if the trace can be completed and the
    exact final marking is reached.
    """
    if im is None or fm is None:
        return False

    def dfs(marking, idx, silent_depth, silent_chain):
        if markings_equal(marking, fm) and idx == len(trace):
            return True

        if silent_depth > MAX_SILENT_DEPTH:
            return False

        try:
            enabled = pm4py.get_enabled_transitions(net, marking)
        except Exception:
            return False

        # Allow silent transitions before the next visible activity or before final.
        for trans in enabled:
            if trans.label is None:
                new_marking = fire_transition(net, trans, marking)
                mk = marking_key(new_marking)
                if mk not in silent_chain:
                    if dfs(new_marking, idx, silent_depth + 1, silent_chain | {mk}):
                        return True

        if idx < len(trace):
            target = trace[idx]
            for trans in enabled:
                if trans.label == target:
                    new_marking = fire_transition(net, trans, marking)
                    if dfs(new_marking, idx + 1, 0, frozenset({marking_key(new_marking)})):
                        return True

        return False

    return dfs(im, 0, 0, frozenset({marking_key(im)}))

# ---------------------------------------------------------------------------
# Positive and negative witnesses
# ---------------------------------------------------------------------------
POSITIVE_WITNESSES = [
    (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Legal Review",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
    (
        "Register Change",
        "Prepare Evidence",
        "Assess Risk",
        "Configure Trial",
        "Inspect Trial",
        "Correct Defect",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
    (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Legal Review",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
]

NEGATIVE_WITNESSES = [
    # Release before verification / zero loop iterations
    (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Legal Review",
        "Release Change",
        "Archive Change",
    ),
    # Correct Defect before first Configure Trial
    (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Correct Defect",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
    # Duplicate Legal Review
    (
        "Register Change",
        "Assess Risk",
        "Legal Review",
        "Legal Review",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
    # Inspect Trial before Configure Trial
    (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Inspect Trial",
        "Configure Trial",
        "Release Change",
        "Archive Change",
    ),
    # Verification started without Prepare Evidence
    (
        "Register Change",
        "Assess Risk",
        "Legal Review",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
    # Archive before Release
    (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Archive Change",
        "Release Change",
    ),
]

# ---------------------------------------------------------------------------
# Diagnostics on every accepting net
# ---------------------------------------------------------------------------
for name, (net, im, fm) in accepting_nets.items():
    try:
        wn = pm4py.check_is_workflow_net(net)
        sound = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
        print(f"[{name}] workflow_net={wn} sound={sound}")
    except Exception as exc:
        print(f"[{name}] diagnostics failed: {exc!r}")

    try:
        fp = pm4py.discover_footprints(net, im, fm)
        print(f"[{name}] footprints discovered: {type(fp)}")
    except Exception as exc:
        print(f"[{name}] footprints failed: {exc!r}")

    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        print(f"[{name}] reachability graph type: {type(rg)}")
        if isinstance(rg, tuple) and len(rg) >= 2:
            print(f"[{name}] reachability graph states={len(rg[0])} edges={len(rg[1])}")
        elif hasattr(rg, "states"):
            print(f"[{name}] reachability graph states={len(rg.states)}")
    except Exception as exc:
        print(f"[{name}] reachability graph failed: {exc!r}")

# ---------------------------------------------------------------------------
# Bounded trace-set comparison
# ---------------------------------------------------------------------------
source_traces = explore_visible_traces(net_from_powl, im_from_powl, fm_from_powl)
print(f"Source bounded visible traces: {len(source_traces)}")

for w in POSITIVE_WITNESSES:
    print("Positive witness accepted by source:", w in source_traces, w)

for w in NEGATIVE_WITNESSES:
    print("Negative witness rejected by source:", w not in source_traces, w)

for name, (net, im, fm) in roundtrip_nets.items():
    traces = explore_visible_traces(net, im, fm)
    print(f"[{name}] bounded visible traces: {len(traces)}")
    print(f"[{name}] exact bounded trace-set match: {traces == source_traces}")

    if traces != source_traces:
        print("  missing from round trip:", sorted(source_traces - traces)[:5])
        print("  extra in round trip:", sorted(traces - source_traces)[:5])

    for w in POSITIVE_WITNESSES:
        print(f"[{name}] positive replay {w}: {replay_visible_trace(net, im, fm, w)}")

    for w in NEGATIVE_WITNESSES:
        print(
            f"[{name}] negative replay rejected {w}: "
            f"{not replay_visible_trace(net, im, fm, w)}"
        )
```

The comparison is **not exhaustive beyond the chosen bound**. It is exhaustive only for visible traces up to length 12 and at most 3 `Inspect Trial` loop iterations. Longer loop counts are not proven equivalent.

# 6. Visual-Semantics Review

Even when the underlying converted Petri net is behaviorally acceptable, the BPMN rendering can be misread.

- **Parallel gateways.** A parallel gateway correctly denotes concurrency, but readers may interpret the left-to-right layout as a sequence. The diagram should be annotated: “Branches are concurrent; no order is implied by layout.”
- **Exclusive gateways.** An XOR gateway for the optional legal review is correct only if it has exactly two branches: `Legal Review` and a silent/invisible skip. If the silent branch is omitted, readers may think legal review is mandatory. The diagram should show an explicit annotation: “Silent skip branch omitted; exactly one branch executes.”
- **Loop visualization.** A BPMN loop marker on `Configure Trial`/`Inspect Trial` may be read as “zero or more iterations.” The source requires at least one iteration and places `Correct Defect` only between iterations. The diagram should state: “At least one trial iteration; `Correct Defect` only separates iterations.”
- **Silent routing nodes.** BPMN often hides tau transitions or renders them as unlabeled gateways. This is semantically convenient but can hide the optional skip and the loop routing. Annotate: “Unlabeled routing nodes are silent transitions.”
- **Apparent ordering of graph layout.** BPMN diagrams are often laid out left-to-right or top-to-bottom. That layout can falsely suggest that `Legal Review` must occur before `Configure Trial`, or that `Prepare Evidence` must occur before `Legal Review`. The source has no such edges. A note should say: “Only sequence-flow arrows impose order; spatial position does not.”

Recommended documentation: include a legend, a statement of the authoritative semantics, the invariant table from Section 1, and a warning that the BPMN is a derivative visualization, not the canonical model.

# 7. Rejection Criteria

Reject or quarantine a conversion result if any of the following occurs:

1. **Technical failure.** Any conversion raises an exception, returns null markings, or produces an object that cannot be reverse-converted to an accepting Petri net.
2. **Unsoundness or non-workflow-net.** `pm4py.check_is_workflow_net(net)` is false, or `pm4py.check_soundness(net, im, fm)` is false for any accepting net.
3. **Exact final-marking failure.** A completed trace does not reach exactly the final marking, or the final marking is null/ambiguous.
4. **Bounded trace-set mismatch.** The round-tripped net misses a positive witness or admits a negative witness under the bounded exploration.
5. **Release before verification.** A trace such as `Register, Assess, Prepare, Legal, Release, Archive` is accepted, meaning the verification loop was bypassed.
6. **Optional behavior collapse.** The model allows zero legal-review branches without a silent skip, allows two `Legal Review` occurrences, or makes legal review mandatory.
7. **Loop semantics violation.** The model allows zero verification iterations, allows `Correct Defect` before the first `Configure Trial`, allows `Inspect Trial` before `Configure Trial`, or allows release immediately after `Correct Defect` without another trial body.
8. **Loss of required concurrency.** The model rejects `Register, Prepare Evidence, Assess Risk, ...` or rejects overlap such as `Configure Trial, Legal Review, Inspect Trial`.
9. **False join before Release.** The model allows `Release Change` after only one of the optional-legal branch or verification loop.
10. **Label corruption.** Visible activity labels are duplicated, renamed, or silent transitions become visible activities, making trace comparison unreliable.
11. **Process-tree intermediate imposes false order.** If the process-tree pipeline succeeds but its BPMN round trip imposes an order between optional legal review and verification, reject the tree-derived BPMN.
12. **Visual ambiguity without annotation.** The BPMN uses unlabeled gateways or layout that materially misrepresents concurrency, optionality, or loop scope and no annotation is provided.

# 8. Canonical Representation Recommendation

**Authoritative semantic source:** the POWL model remains the authoritative human-editable definition of the controlled technical change.

**Canonical storage model:** the accepting Petri net compiled from the POWL should be the canonical executable/storage artifact. It is directly analyzable with workflow-net, soundness, footprint, reachability, and trace-replay diagnostics, and it is the hub from which BPMN derivatives are generated.

**Stakeholder visualization model:** the BPMN model derived from the accepting Petri net is a derivative visualization artifact. It must be labeled as non-authoritative.

**Derivative artifacts and required evidence:**

- `net_from_powl`: canonical compiled artifact. Evidence: non-null `im`/`fm`, workflow-net check, soundness check, bounded trace set, positive/negative witness results.
- `bpmn_from_net`: stakeholder visualization. Evidence: reverse conversion to Petri net, workflow-net/soundness checks, bounded trace-set comparison against `net_from_powl`, visual-semantics annotation.
- `tree_from_net` / `bpmn_from_tree`: diagnostic only. Evidence: if conversion fails, record the exception and treat failure as acceptable; if it succeeds, compare trace sets and reject if any invariant is lost or false order is imposed.
- All saved images: derivative artifacts; they must not be edited directly.

**Process-tree intermediate:** not allowed as a canonical representation. It may be attempted only as a diagnostic. Because the source is not block-structured enough, a successful process-tree conversion is suspicious and must be quarantined unless its BPMN round trip passes the full invariant audit.

**Avoiding round-trip drift:** future edits should be made only in the POWL source. After each edit, recompile the accepting Petri net, rerun the invariant checks and bounded trace comparison, regenerate BPMN, and store the validation evidence alongside the derivative. Never edit the BPMN or Petri net directly and then convert back to POWL.

# 9. Residual Uncertainty

Even if every test passes, the proposed validation cannot establish at least the following:

1. **Unbounded loop equivalence.** The bounded trace exploration covers at most 3 `Inspect Trial` loop iterations. It does not prove equivalence for arbitrary loop counts.
2. **Human comprehension of BPMN.** Behavioral equivalence of the underlying net does not prove that a human reader will correctly interpret the BPMN diagram, gateways, loop markers, and silent routing nodes.
3. **Tool-specific BPMN semantics.** PM4Py’s BPMN conversion and reverse conversion may not match the token semantics of every BPMN engine or modeling tool.
4. **True concurrency vs interleaving.** Trace-set comparison alone cannot fully distinguish true concurrency from arbitrary interleaving; stronger partial-order or branching-time evidence would be needed.
5. **Silent skip vs omitted optional branch.** After hiding tau, a trace without `Legal Review` is valid, but the validation cannot always prove from visible traces alone that the silent skip actually fired rather than the optional branch being omitted.
