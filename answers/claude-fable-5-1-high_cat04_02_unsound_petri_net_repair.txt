# 1. Executive Verdict

The net **is a workflow net**: `source` is the only place without incoming arcs, `sink` the only place without outgoing arcs, and every place and transition lies on a directed path from `source` to `sink`. It should **not** be expected to be sound, and it is not. The principal defect is `t_join_waived`: it consumes only `p_waived` and ignores the analysis branch, so on the waiver route the token that `t_split` put into `p_analysis` (or, after `t_analyze`, into `p_analysis_done`) is never consumed. Every waiver trace therefore ends in a marking `{sink, p_analysis}` or `{sink, p_analysis_done}`, never in `fm = {sink}`, and from those markings `fm` is unreachable (no option to complete, no proper completion). Business consequence: a case can be authorized with the mandatory analysis not yet performed (`t_authorize` can fire while `p_analysis` is still marked), and every waived case leaves an orphaned work item behind.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source → t_register → p_ready` | Start of case, single entry | Correct: `source` has no input arcs; `t_register` moves the single token to `p_ready` | None |
| `t_split` (silent), `p_ready → t_split → {p_analysis, p_review}` | AND-split: start analysis and review concurrently | Correct AND-split: one input, two outputs; produces exactly one token in each branch | None in isolation; it is the *source* of the two tokens that must later be re-synchronized |
| `p_analysis → t_analyze → p_analysis_done` | Mandatory analysis branch | Correct sequence; `p_analysis_done` has two consumers, `t_join_normal` (arc present) and, by intent, the waiver join (arc **missing**) | On the waiver route the token in `p_analysis` / `p_analysis_done` becomes an orphan |
| `p_review → t_standard_review → p_review_done` | Review alternative 1 | Correct: `p_review` is a free-choice-like XOR-split place with two consumers (`t_standard_review`, `t_waive_review`) | None |
| `p_review → t_waive_review → p_waived` | Review alternative 2 (formally recorded waiver) | Correct as an alternative; the choice between review and waiver is a proper XOR at `p_review`; the alternative outcomes live in two *different* places (`p_review_done` vs `p_waived`) | None by itself; it does mean the two outcomes need two different joins or must be merged |
| `t_join_normal` (silent), `{p_analysis_done, p_review_done} → t_join_normal → p_decision` | AND-join for analysis + standard review | Correct two-input synchronization | None on the standard route |
| `t_join_waived` (silent), `p_waived → t_join_waived → p_decision` | AND-join for analysis + waiver | **Defect**: single-input transition; it is a plain sequence step, not a synchronization. It never consumes anything from the analysis branch. `p_analysis` / `p_analysis_done` are the only places not covered by any S-component, which is exactly the structural fingerprint of this omission | `p_decision` marked while analysis pending; leftover token in `p_analysis` or `p_analysis_done` at the end; improper completion; `t_authorize` before `t_analyze` |
| `p_decision → t_authorize → sink` | Authorization after both prerequisites | Correct locally, but `p_decision` can be reached via `t_join_waived` without the analysis prerequisite | Premature authorization |
| `im = {source:1}`, `fm = {sink:1}` | Standard WF-net initial/final markings | Correct definitions. `fm` demands *exactly* one token in `sink` and none elsewhere | On the waiver route `sink` gets a token but `fm` is never reached |
| Source-to-sink path condition | Every node on a path from `source` to `sink` | Satisfied for all 9 places and 8 transitions (`p_waived`, `t_join_waived` are reachable from `source` via `t_waive_review` and reach `sink` via `p_decision`) | None; this is why `check_is_workflow_net` returns `True` although the net is unsound |

Summary of the structural picture: one AND-split creates two concurrent tokens; the standard route has a matching two-input AND-join; the waiver route has a one-input "join". The split/join pair is unbalanced on exactly one of the two XOR branches.

# 3. Marking-Based Counterexample

**Counterexample A (waiver before analysis; exposes premature authorization and the orphan token).**
Firing sequence: `t_register, t_split, t_waive_review, t_join_waived, t_authorize, t_analyze`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | – (start at `im`) | `{source:1}` | `t_register` | Single token, as required for a WF-net |
| 1 | `t_register` | `{p_ready:1}` | `t_split` | Case registered |
| 2 | `t_split` | `{p_analysis:1, p_review:1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token created in each parallel branch |
| 3 | `t_waive_review` | `{p_analysis:1, p_waived:1}` | `t_analyze`, `t_join_waived` | Waiver route chosen; analysis has not started |
| 4 | `t_join_waived` | `{p_analysis:1, p_decision:1}` | `t_analyze`, `t_authorize` | The "join" fired while `p_analysis` is still marked; nothing was synchronized |
| 5 | `t_authorize` | `{p_analysis:1, sink:1}` | `t_analyze` | **`t_authorize` fired before `t_analyze`**: mandatory analysis bypassed. A token exists in `sink`, but the marking is `{p_analysis, sink}` ≠ `fm` |
| 6 | `t_analyze` | `{p_analysis_done:1, sink:1}` | (none) | Dead marking. `sink` is marked, but `fm = {sink}` has **not** been reached |

Why the leftover token cannot be consumed: the only consumer of `p_analysis` is `t_analyze` (fired at step 6), and the only consumer of `p_analysis_done` is `t_join_normal`, which also needs `p_review_done`. `p_review_done` is produced only by `t_standard_review`, which needs `p_review`, and the single `p_review` token was consumed by `t_waive_review` at step 3 and can never be regenerated (no cycles in the net). Hence from `{p_analysis_done, sink}` no transition is enabled and `fm` is unreachable: the option to complete is violated, and the marking that does mark `sink` also marks another place (improper completion).

**Counterexample B (analysis before waiver; shows the defect is not merely an ordering issue).**
Firing sequence: `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | – (start at `im`) | `{source:1}` | `t_register` | |
| 1 | `t_register` | `{p_ready:1}` | `t_split` | |
| 2 | `t_split` | `{p_analysis:1, p_review:1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | Two parallel tokens |
| 3 | `t_analyze` | `{p_analysis_done:1, p_review:1}` | `t_standard_review`, `t_waive_review` | Analysis completed first (the "good" order) |
| 4 | `t_waive_review` | `{p_analysis_done:1, p_waived:1}` | `t_join_waived` | Both prerequisites of the intent are now complete |
| 5 | `t_join_waived` | `{p_analysis_done:1, p_decision:1}` | `t_authorize` | The join moved on but left `p_analysis_done` untouched |
| 6 | `t_authorize` | `{p_analysis_done:1, sink:1}` | (none) | Here `t_authorize` fires **after** `t_analyze`, i.e. the business order was respected, yet the result is still a dead marking ≠ `fm` |

Conclusion from A and B together: `t_authorize` can occur both before (A) and after (B) `t_analyze` on the waiver route, and in **both** cases the net terminates in a marking with a token in `sink` plus one orphan token. There is no waiver trace at all that reaches `fm`; only the standard-review route (`t_register, t_split, {t_analyze ∥ t_standard_review}, t_join_normal, t_authorize`) reaches exactly `{sink:1}`.

No further independent defect exists: the standard route is correct, the net is 1-safe (every reachable marking has at most one token per place), and no transition is dead from `im`. The complete reachable state space of the original net, derived by hand from the two tables above plus the standard route, has 14 markings: `{source}`, `{p_ready}`, `{p_analysis,p_review}`, `{p_analysis_done,p_review}`, `{p_analysis,p_review_done}`, `{p_analysis,p_waived}`, `{p_analysis_done,p_review_done}`, `{p_analysis_done,p_waived}`, `{p_decision}`, `{p_analysis,p_decision}`, `{p_analysis_done,p_decision}`, `{sink}`, `{p_analysis,sink}`, `{p_analysis_done,sink}`, connected by 17 firing edges; two of them are dead ends: `{sink}` (correct) and `{p_analysis_done,sink}` (defective).

# 4. Minimal-Repair Alternatives

**Edit-cost model.** Cost = number of primitive edits, where each of the following counts 1: add an arc, remove an arc, add a place, remove a place, add a transition, remove a transition, change a label. Removing a node does *not* remove its arcs for free; each incident arc removed is a separate edit (this prevents "delete a hub node" from looking cheap). Relabeling silent transitions and renaming variables cost 0 only if the label stays `None`.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1 – make the waiver join a real AND-join** | add arc `p_analysis_done → t_join_waived` | **1** | Analysis mandatory on both routes; analysis and review still start in parallel; waiver and standard review remain distinct places and distinct joins; authorization only after both are complete | Only the defective interleavings disappear: `t_join_waived` is now enabled only at `{p_analysis_done, p_waived}`. All standard-route behavior unchanged | Two silent joins with the same output place; a future edit to one join and not the other reintroduces asymmetry. Sound, all tasks live |
| **R2 – rewire the waiver outcome into the normal synchronization** | remove arc `t_waive_review → p_waived`; add arc `t_waive_review → p_review_done`; remove arcs `p_waived → t_join_waived` and `t_join_waived → p_decision`; remove place `p_waived`; remove transition `t_join_waived` | **6** | Analysis mandatory on both routes; parallel start preserved; waiver still a visible, labeled activity (`Record Review Waiver`) | Waiver and standard review now share the post-state `p_review_done`; only one join remains. Smaller net and smaller state space | Loss of *marking-level* distinction between "reviewed" and "waived" (only the event label distinguishes them); if later logic needs to branch on waiver status, a place must be re-added. Sound |
| **R3 – policy change: analysis becomes optional under waiver** (stated policy change: a waived case may be authorized without analysis) | add arc `p_analysis → t_join_waived` (so `t_join_waived` = `{p_analysis, p_waived} → p_decision`, "skip analysis"); add silent transition `t_join_waived_after_analysis`; add arcs `p_analysis_done → t_join_waived_after_analysis`, `p_waived → t_join_waived_after_analysis`, `t_join_waived_after_analysis → p_decision` | **5** | Proper completion and option to complete restored; waiver distinct; parallel start preserved | **Business policy changed**: after a waiver, analysis may be skipped (race between `t_analyze` and `t_join_waived` at `{p_analysis, p_waived}`); if analysis already finished, the second join consumes it | Non-deterministic skip of analysis; contradicts the stated intent "analysis is always mandatory". Note the one-arc version of this idea (only `p_analysis → t_join_waived`, cost 1) is **not** a valid repair: at `{p_analysis_done, p_waived}` (analysis first) no transition is enabled – a deadlock – so the second join is required |
| R1b – alternative cost-1 fix, mentioned for the tie discussion | add arc `p_analysis_done → t_waive_review` | 1 | Analysis mandatory; final marking reached; waiver distinct | Waiver can be recorded **only after** analysis is complete: the interleaving "waive, then analyze" is removed, so the two branches are no longer truly parallel for waived cases; `t_waive_review` consumes the analysis token and `t_join_waived` becomes a pure sequence step | Silently changes the ordering rule (sequentializes analysis before waiver), a behavioral restriction not requested by the intent |
| R1c – cost-1 *policy-changing* fix, listed for completeness | add arc `p_analysis → t_waive_review` | 1 | Final marking reached; waiver distinct | **Policy change**: waiver consumes the unstarted analysis token, so a waived case never performs analysis, and waiver is only possible before analysis starts | Directly violates "analysis is always mandatory"; only admissible if the business explicitly accepts it |

**Minimality justification.**

- A lower bound of 1 is trivial: the unmodified net (cost 0) is unsound. R1 achieves cost 1 and preserves the stated intent, so it is minimal in the absolute sense.
- Uniqueness at cost 1 under the intent: any sound repair must let the waiver route consume the analysis-branch token. With one arc this can only be an arc from `p_analysis` or `p_analysis_done` into some transition that fires on the waiver route (`t_waive_review`, `t_join_waived`, `t_authorize`). `p_analysis → t_join_waived` deadlocks when analysis fires first (shown above); `p_analysis(_done) → t_authorize` breaks the standard route, where `t_authorize` at `{p_decision}` would need an analysis token that has already been consumed by `t_join_normal` (deadlock at `{p_decision}`). Removing a single arc never helps: removing `p_review → t_waive_review` or `t_waive_review → p_waived` either destroys the source-to-sink path property or makes the waiver token vanish while leaving the analysis token orphaned. That leaves exactly three cost-1 candidates, R1, R1b and R1c. They tie on cost but not on intent: R1 is the only one that keeps analysis mandatory *and* keeps analysis and waiver concurrent, R1b keeps analysis mandatory but sequentializes it before the waiver, R1c abandons mandatory analysis. Under the tie, R1 wins because it changes only the defective transitions and nothing else.
- R2 is minimal *within its family* (merge the two review outcomes): redirecting the waiver output requires at least one removed and one added arc (2), after which `p_waived` and `t_join_waived` are no longer on any source-to-sink path and must be deleted with their two arcs (4 more) to keep the WF-net property; total 6. Leaving them dangling would make `check_is_workflow_net` fail.
- R3 is minimal within the "analysis optional under waiver" family: the one-arc version deadlocks, so at least a second consumer of `{p_analysis_done, p_waived}` is required, which costs 1 transition + 3 arcs on top of the first arc.

# 5. Corrected PM4Py Code

Selected repair: **R1** (single added arc `p_analysis_done → t_join_waived`).

# 6. Diagnostic and Reachability Code

Assumes `net`, `im`, `fm` (original) and `repaired_net`, `repaired_im`, `repaired_fm` (Section 5) exist in the session.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking
from pm4py.objects.petri_net import semantics


def transition_by_name(a_net, name):
    matches = [t for t in a_net.transitions if t.name == name]
    if len(matches) != 1:
        raise KeyError(f"transition {name!r} not found (or not unique) in {a_net.name}")
    return matches[0]


def show_marking(m):
    return "{" + ", ".join(f"{p.name}:{k}" for p, k in sorted(m.items(), key=lambda x: x[0].name) if k > 0) + "}"


def fire_sequence(a_net, start_marking, names, final_marking):
    """Fire the named transitions in order, refusing to fire a disabled one."""
    m = Marking(start_marking)
    print(f"  step 0  start                   {show_marking(m)}")
    for i, name in enumerate(names, start=1):
        t = transition_by_name(a_net, name)
        if not semantics.is_enabled(t, a_net, m):
            print(f"  step {i}  {name} is NOT enabled at {show_marking(m)} -> stopping")
            return m
        m = semantics.execute(t, a_net, m)
        enabled = sorted(x.name for x in pm4py.get_enabled_transitions(a_net, m))
        print(f"  step {i}  fired {name:18s} -> {show_marking(m)}  enabled={enabled}")
    print(f"  sink marked: {any(p.name == 'sink' and k > 0 for p, k in m.items())} | "
          f"exact final marking reached: {m == final_marking}")
    return m


def diagnose(label, a_net, a_im, a_fm):
    print("=" * 72)
    print(label)
    print("workflow net:", pm4py.check_is_workflow_net(a_net))
    is_sound, diag = pm4py.check_soundness(a_net, a_im, a_fm, print_diagnostics=True)
    print("sound:", is_sound)
    print("enabled at im:", sorted(t.name for t in pm4py.get_enabled_transitions(a_net, a_im)))
    rg = pm4py.convert_to_reachability_graph(a_net, a_im, a_fm)
    dead_ends = sorted(s.name for s in rg.states if not s.outgoing)
    print(f"reachability graph: {len(rg.states)} states, {len(rg.transitions)} edges")
    print("dead-end states (no outgoing edge):", dead_ends)


waiver_first = ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize", "t_analyze"]
analysis_first = ["t_register", "t_split", "t_analyze", "t_waive_review", "t_join_waived", "t_authorize"]

diagnose("ORIGINAL net", net, im, fm)
print("counterexample A (waiver before analysis):")
fire_sequence(net, im, waiver_first, fm)
print("counterexample B (analysis before waiver):")
fire_sequence(net, im, analysis_first, fm)

diagnose("REPAIRED net (R1)", repaired_net, repaired_im, repaired_fm)
print("same sequence A on repaired net (must stop: t_join_waived not enabled):")
fire_sequence(repaired_net, repaired_im, waiver_first, repaired_fm)
print("sequence B on repaired net (must reach exactly repaired_fm):")
fire_sequence(repaired_net, repaired_im, analysis_first, repaired_fm)
```

**Expected qualitative difference.**

- `check_is_workflow_net`: `True` for **both** nets. This is the structural check only; it cannot see the defect.
- `check_soundness(..., print_diagnostics=True)`: original returns `False`; its printed diagnostics should report that the net is a workflow net but that the analysis places (`p_analysis`, `p_analysis_done`) are not covered by any S-component, which is the structural shadow of the missing synchronization. Repaired returns `True` with messages to the effect that all places are covered, there are no dead tasks and all tasks are live. (In current PM4Py releases this function is flagged as deprecated but still works; the same analysis is available through the WOFLAN module. Do not rely on exact dictionary keys or message wording across versions.)
- `get_enabled_transitions(net, im)`: `{t_register}` for both. The interesting differences appear along the sequences: at `{p_analysis, p_waived}` the original enables `t_join_waived`, the repaired net does not; at `{p_analysis, p_decision}` the original enables `t_authorize` while `p_analysis` is still marked; this marking is unreachable in the repaired net.
- `convert_to_reachability_graph`: for the original, the 14 markings and 17 edges derived in Section 3, with **two** dead-end states, `{sink}` and `{p_analysis_done, sink}` (the third defective marking `{p_analysis, sink}` is not a dead end because `t_analyze` is still enabled there). For the repaired net the three markings containing `sink` plus another place and the marking `{p_analysis, p_decision}` disappear, as does `{p_analysis_done, p_decision}` (the waiver join now consumes both tokens): 10 markings, 12 edges, and a **single** dead-end state equal to `repaired_fm`. A sound WF-net must have exactly one dead-end state and it must equal the final marking; the original violates this, the repaired net satisfies it.
- The helper refuses to fire `t_join_waived` at step 4 of sequence A on the repaired net, which is precisely the desired behavior: authorization before analysis is no longer a legal run.

# 7. Repair Trade-Offs and Residual Risks

**Distinguishability of waiver and standard review.** Under R1 (and R3) the two outcomes remain distinguishable at three levels: different visible labels (`Perform Standard Review` vs `Record Review Waiver`), different post-places (`p_review_done` vs `p_waived`), and different silent joins. Under R2 only the label distinguishes them; the marking after the review step is identical (`p_review_done`). For conformance checking and token replay this is harmless, since alignments operate on labels; for any later extension that must react to "this case was waived" (e.g., an extra approval step), R2 would require re-introducing a place.

**Duplicate behavior and confusion through silent transitions.** R1 keeps two silent transitions (`t_join_normal`, `t_join_waived`) that both produce `p_decision`. They are never simultaneously enabled (their input sets require `p_review_done` and `p_waived` respectively, which are mutually exclusive after the XOR at `p_review`), so no duplicate paths and no non-determinism arise; the visible language is unchanged except for removing the illegal interleavings. In alignments the two silent joins are invisible and cost nothing, so they do not create spurious model moves. The residual confusion is maintenance-related: two joins must stay symmetric with respect to the analysis branch. R3 does introduce genuine non-determinism at `{p_analysis, p_waived}` (fire `t_analyze` or skip via `t_join_waived`), which is the price of the policy change and a real source of confusion in replay: a trace without `Perform Analysis` becomes conforming.

**Soundness is not alignment with the business rule.** R1c (`p_analysis → t_waive_review`) is sound with cost 1 yet lets every waived case skip analysis; R1b is sound yet forbids recording a waiver before analysis has finished. Soundness only guarantees proper termination, option to complete and absence of dead transitions; it says nothing about *which* orderings are required. The business rules "analysis is mandatory" and "authorization only after both" must be checked as explicit properties (e.g., every complete trace contains `Perform Analysis`; `Authorize Case` is never preceded by fewer than one `Perform Analysis`). The repaired net satisfies these by construction of the two-input joins, but that is an argument about the model, not a consequence of the `True` returned by `check_soundness`.

**Regression traces (labels of visible transitions).**

Positive (must fit the repaired model, reaching exactly `repaired_fm`):
1. `Register Case, Perform Analysis, Perform Standard Review, Authorize Case`
2. `Register Case, Perform Standard Review, Perform Analysis, Authorize Case`
3. `Register Case, Perform Analysis, Record Review Waiver, Authorize Case`
4. `Register Case, Record Review Waiver, Perform Analysis, Authorize Case` (waiver first, analysis still performed; this is the interleaving R1b would wrongly reject)

Negative (must **not** fit, i.e. alignments must show model or log moves):
5. `Register Case, Record Review Waiver, Authorize Case` (analysis missing; the original net accepts this trace, the repaired one must not)
6. `Register Case, Record Review Waiver, Authorize Case, Perform Analysis` (analysis after authorization; counterexample A)
7. `Register Case, Perform Standard Review, Authorize Case` (analysis missing on the standard route; both nets reject it, kept as a control)
8. `Register Case, Perform Analysis, Perform Standard Review, Record Review Waiver, Authorize Case` (both review outcomes on one case)
9. `Register Case, Perform Analysis, Authorize Case` (no review decision at all)

**Detecting an accidental bypass of mandatory analysis.** Three complementary checks: (a) *model-level*: enumerate the reachability graph and assert that every edge labelled `t_authorize` leaves a marking whose history contains `t_analyze`; simpler and equivalent here: assert that no reachable marking contains both `p_decision` (or `sink`) and `p_analysis`, and that `t_analyze` is enabled in no marking that already marks `sink`. (b) *log-level*: replay the event log against the repaired model and flag every trace where `Authorize Case` occurs without a preceding `Perform Analysis`; with the repaired net these traces are non-fitting, with the original they were fitting, so a sudden increase in fitness for such traces after a model change is itself an alarm. (c) *structural regression*: assert that every transition with `p_decision` in its postset has `p_analysis_done` in its preset; this is the invariant the original modeler broke and would catch a re-introduction of the bug in any future edit.

# 8. Final Recommendation

**Deploy R1** (add the single arc `p_analysis_done → t_join_waived`). It is the unique minimal repair that preserves every stated element of the business intent: analysis and review still start concurrently, analysis is mandatory on both routes, waiver and standard review stay distinguishable in labels and in markings, and authorization is gated on both completed prerequisites. It touches only the transition that was wrong, so it is easy to review and to explain to the original modeler ("your waiver join was missing its second input"). It restores soundness, removes exactly the defective interleavings, and leaves the standard route untouched. Its only residual cost is two silent joins that must remain symmetric; the structural regression check in Section 7 covers that.

**Fallback: R2** (route the waiver outcome into `p_review_done` and delete `p_waived` / `t_join_waived`). It costs 6 edits and gives up the marking-level distinction between waived and reviewed cases, but yields the smallest net with a single join and a smaller state space, which is attractive if the model is used mainly for label-based conformance checking and no downstream logic needs the waiver state. Choose it if reviewers prefer one synchronization point, or if the risk of asymmetric future edits to two joins is judged higher than the loss of `p_waived`.

R3 and R1c should be deployed only if the business explicitly changes the rule; R1b should not be deployed, because it silently forbids recording a waiver before analysis finishes, contradicting the parallel-start requirement.
