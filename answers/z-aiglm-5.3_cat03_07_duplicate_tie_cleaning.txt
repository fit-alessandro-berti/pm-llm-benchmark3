    ev, rel, obj = ocel.events, ocel.relations, ocel.objects
    eids, oids = set(ev["ocel:eid"]), set(obj["ocel:oid"])

def merge_verified_pair(ocel, keep_eid, drop_eid, rule, reviewer="pipeline v1.0",
                        confidence=0.9, reason="", audit_rows=None):
    """Attribute+relation merge of two *verified* duplicates.
    keep_eid survives; drop-only attributes are carried over prefixed by source;
    conflicts are decided for the keeper and logged, never silently discarded."""
    ev, rel = ocel.events, ocel.relations
    ki = ev.index[ev["ocel:eid"] == keep_eid][0]
    di = ev.index[ev["ocel:eid"] == drop_eid][0]
    drop_src = ev.at[di, "source"]
    carried, conflicts = [], []
    for col in ev.columns:
        if col in META:
            continue
        dv, kv = ev.at[di, col], ev.at[ki, col]
        if pd.isna(dv):
            continue
        if pd.isna(kv):
            tgt = f"{drop_src}:{col}"
            ev.at[ki, tgt] = dv
            carried.append(tgt)
        elif kv != dv:
            conflicts.append((col, kv, dv))          # keeper's value wins
    rel.loc[rel["ocel:eid"] == drop_eid, "ocel:eid"] = keep_eid
    sub = [c for c in ("ocel:eid", "ocel:oid", "ocel:qualifier") if c in rel.columns]
    ocel.relations = rel.drop_duplicates(subset=sub).reset_index(drop=True)
    row = dict(zip(AUDIT, [keep_eid, drop_eid,
             f"{ev.at[ki,'source']}:{ev.at[ki,'source_event_key']}|{drop_src}:{ev.at[di,'source_event_key']}",
             rule, reviewer, ev.at[ki, "original_activity"], ev.at[ki, "ocel:activity"],
             str(ev.at[ki, "original_timestamp"]), str(ev.at[ki, "ocel:timestamp"]),
             carried, conflicts, confidence, reason]))
    if audit_rows is not None:
        audit_rows.append(row)
    ocel.events = ev.drop(index=di).reset_index(drop=True)
    return ocel

def deterministic_order(ocel):
    """Tiered ordering: semantic edges -> within-source seq -> stable fallback.
    ingested_at is intentionally excluded (technical time, not business time)."""
    ev = ocel.events.set_index("ocel:eid")
    eids = set(ev.index)
    edges = [e for e in SEMANTIC_EDGES + SEQ_EDGES if e[0] in eids and e[1] in eids]
    succ, indeg = {e: [] for e in eids}, {e: 0 for e in eids}
    for a, b in edges:
        succ[a].append(b); indeg[b] += 1
    def fallback(eid):
        r = ev.loc[eid]
        return (r["ocel:timestamp"], SOURCE_RANK.get(r["source"], 99),
                str(r["source_event_key"]), eid)
    order, ready = [], sorted([e for e in eids if indeg[e] == 0], key=fallback)
    while ready:
        n = ready.pop(0); order.append(n)
        for m in succ[n]:
            indeg[m] -= 1
            if indeg[m] == 0:
                ready.append(m); ready.sort(key=fallback)
    assert len(order) == len(eids), "cycle in semantic order constraints"
    ev = ev.loc[order].reset_index()
    ev["order_index"] = range(len(ev))
    ev["sort_key"] = [f"{t:%Y%m%dT%H%M%S}_{i:04d}"
                      for t, i in zip(ev["ocel:timestamp"], ev["order_index"])]
    ocel.events = ev
    return ocel

## 1. Duplicate-handling decision tree

Candidate groups are formed by (activity, timestamp) collisions, plus business-key matches. The tree is applied per group, strongest evidence first:

```
Q1. Same source AND same source_event_key AND same payload_hash AND same object set?
    YES  EXACT TECHNICAL DUPLICATE  DROP (deterministic survivor: lowest eid),
          full audit record. Zero semantic loss.
    NO  Q2
Q2. External evidence of ONE physical/business occurrence
    (reconciliation report, shared business key, message-id link)?
    YES  SAME PHYSICAL EVENT, MULTI-SYSTEM OBSERVATION 
          MERGE attributes and relations; one canonical eid = system of record
          for that activity type; attribute-authority matrix resolves conflicts;
          foreign-only attributes carried with source prefix; E2O unioned.
          [e03/e04, e11/e16]
    NO  Q3
Q3. Distinguishing qualifier object of the activity's own object type
    (I1 vs I2, M1 vs M2) or otherwise disjoint distinguishing set?
    YES  CONCURRENT SAME-LABEL EVENTS, DIFFERENT OBJECTS 
          RETAIN BOTH UNCHANGED. [e03/e05, e13/e14]
    NO  Q4
Q4. Is one event a status/summary row produced from a message emitted by the
    other system about a detailed transaction?
    YES  SUMMARY DERIVED FROM DETAIL  default: RETAIN BOTH with refined
          labels (Detail/Status); MERGE only with positive linkage evidence,
          keeping the detailed event canonical; if even labeling is contested,
          QUARANTINE. [e06/e07, e13/e15, e14/e15]
    NO  Q5
Q5. Do the pre-harmonization source activity codes differ in meaning?
    YES  HARMONIZATION COLLISION  RETAIN BOTH with refined labels reflecting
          source semantics; NEVER merge. [e08/e09]
    NO  Q6
Q6.  UNRESOLVED CANDIDATE  QUARANTINE for review; keep both rows in the
    analytical log with a quarantine flag; no auto-merge.
```

Precedence rules: attested identity (Q2) overrides payload differences; **identical object sets prove nothing** (e08/e09 share every modeled object yet are distinct transitions); concurrency (Q3) is the default when qualifier objects differ.

## 3. Timestamp-tie ordering rules

| Tier | Rule | Class | Examples |
|---|---|---|---|
| T1 | Attested domain constraints | Semantic | e09<e10 (fact 5), e12<e13 (fact 7), e13/e14<e15 (fact 8), e06<e07 (fact 3) |
| T2 | Within-source `source_seq` | Semantic within source, deterministic across sources | e12(400)<e13(401)<e14(402); e09(1)<e10(2) |
| T3 | Lifecycle stage order on shared objects | Semantic | Item: pick<pack (e03/e05<e06); Package: pack<release<handover<delivery; Payment: authorize<capture; Invoice: issue<settle |
| T4 | Source-specific semantics | Semantic | Warehouse release precedes carrier acceptance (e08<e09) |
| T5 | `ingested_at` | **Deterministic only; disabled by default** | Never a business order (fact 9); may only appear after all semantic tiers, if at all |
| T6 | Stable fallback: (source priority rank, source_event_key, payload_hash, eid) | Deterministic | ERP<WMS<SCANNER<CARRIER<PSP<BILLING |

**Algorithm:** build a DAG from T1–T4 edges, verify acyclicity, then produce a total order by a Kahn-style topological sort in which the next node is always the available node with the smallest (timestamp, T6 key). T1–T4 are semantic; T5–T6 merely make the output reproducible. **The resulting total order does not prove physical order** — among incomparable events (e03/e05; e13/e14) it is an arbitrary but stable serialization that must be reported as concurrency, not causation.

**Why pre-deciding microseconds is harmful:** if microsecond offsets are injected (e.g., by ingestion order or hash) *before* the semantic order is decided, downstream tools read them as measured time. PM4Py discovery, DFGs, and performance analysis all key on timestamps; a fabricated 3 µs "handover duration," or a capture placed 1 µs *before* authorization because a batch arrived early, becomes indistinguishable from real evidence and silently pollutes waiting-time percentiles. Worse, the artificial order can contradict attested constraints and encode the violation as fact. Decide the order first, encode it second, and keep `original_timestamp` intact (fact 10).

The correct protection is an object-set-equality test on the primary object type plus an explicit protected-events invariant — neither of which the library performs.

    keep_eid survives; drop-only attributes are carried over prefixed by the
    dropping source; conflicts are decided for the keeper and logged, never
    silently discarded."""
    ev, rel = ocel.events, ocel.relations
    ki = ev.index[ev["ocel:eid"] == keep_eid][0]
    di = ev.index[ev["ocel:eid"] == drop_eid][0]
    drop_src = ev.at[di, "source"]
    carried, conflicts = [], []
    for col in ev.columns:
        if col in META:
            continue
        dv, kv = ev.at[di, col], ev.at[ki, col]
        if pd.isna(dv):
            continue
        if pd.isna(kv):
            tgt = f"{drop_src}:{col}"          # e.g. SCANNER:operator_id
            ev.at[ki, tgt] = dv
            carried.append(tgt)
        elif kv != dv:
            conflicts.append((col, kv, dv))     # keeper wins; conflict recorded
    rel.loc[rel["ocel:eid"] == drop_eid, "ocel:eid"] = keep_eid
    sub = [c for c in ("ocel:eid", "ocel:oid", "ocel:qualifier") if c in rel.columns]
    ocel.relations = rel.drop_duplicates(subset=sub).reset_index(drop=True)
    if audit_rows is not None:
        audit_rows.append(dict(zip(AUDIT, [
            keep_eid, drop_eid,
            f"{ev.at[ki,'source']}:{ev.at[ki,'source_event_key']}"
            f"|{drop_src}:{ev.at[di,'source_event_key']}",
            rule, reviewer, ev.at[ki, "original_activity"], ev.at[ki, "ocel:activity"],
            str(ev.at[ki, "original_timestamp"]), str(ev.at[ki, "ocel:timestamp"]),
            carried, conflicts, confidence, reason])))
    ocel.events = ev.drop(index=di).reset_index(drop=True)
    return ocel

def deterministic_order(ocel):
    """Tiered ordering: semantic edges -> within-source seq -> stable fallback.
    ingested_at is intentionally excluded (technical time, not business time).
    The result is a reproducible serialization, NOT proof of physical order."""
    ev = ocel.events.set_index("ocel:eid")
    eids = set(ev.index)
    edges = [e for e in SEMANTIC_EDGES + SEQ_EDGES
             if e[0] in eids and e[1] in eids]
    succ, indeg = {e: [] for e in eids}, {e: 0 for e in eids}
    for a, b in edges:
        succ[a].append(b)
        indeg[b] += 1
    def fallback(eid):
        r = ev.loc[eid]
        return (r["ocel:timestamp"], SOURCE_RANK.get(r["source"], 99),
                str(r["source_event_key"]), eid)
    order, ready = [], sorted([e for e in eids if indeg[e] == 0], key=fallback)
    while ready:
        n = ready.pop(0)
        order.append(n)
        for m in succ[n]:
            indeg[m] -= 1
            if indeg[m] == 0:
                ready.append(m)
                ready.sort(key=fallback)
    assert len(order) == len(eids), "cycle in semantic order constraints"
    ev = ev.loc[order].reset_index()
    ev["order_index"] = range(len(ev))
    ev["sort_key"] = [f"{t:%Y%m%dT%H%M%S}_{i:04d}"
                      for t, i in zip(ev["ocel:timestamp"], ev["order_index"])]
    ocel.events = ev
    return ocel

**Order-flattened DFG:** raw shows back-to-back same-activity edges that read as rework. Conservative removes the invoice duplication, converts the Dispatch pair into a *handoff* edge (ReleaseCarrier Acceptance) and the Pack pair into DetailStatus via refined labels; the remaining PickPick (e03e05) and CaptureCapture (e13e14) are genuine concurrency and must be interpreted as such. Aggressive shows a single Pick, Pack, Dispatch, Invoice, Capture — clean but false.

**Item-flattened DFG:** I1 raw shows PickPick (e03e04), pure duplicate artifact; conservative shows PickPack. I2 shows PickPack throughout. Aggressive shows both items with one shared pick event — the trace for I2 reuses the event that physically belongs to I1, undercounting picks.

**Payment-flattened DFG:** M1: AuthorizeCapture everywhere. M2: Capture only (a real "captured without authorization" observation). Aggressive makes both payments point at one composite capture event, so M1/M2 frequencies and amounts are conflated.

**OC-DFG edges/frequencies, ET–OT, OTG:** PickPack (Item) frequency drops 32 (conservative) but 1 (aggressive). One merge/refinement record per decision, persisted as a table:

| Field | Example (e03/e04) |

| source_event_ids | WMS:W-77, SCANNER:S-901 |
| merge_rule | REC-REPORT-scan-reconciliation v1.2 |
| reviewer / rule_version | auto / pipeline v1.0 |
| original_activity / refined_activity | Pick Item / Pick Item (unchanged) |
| original_timestamp / adjusted_timestamp | 2026-05-18 10:00:00 / unchanged (delta flagged `synthetic_tiebreak`) |

| discarded_conflicts | [(payload_hash, h-pick-i1, h-pick-i1-alt)] |

**Reconstruction of the raw view:** `ocel_raw` is immutable and is the ground truth. Additionally, each audit row stores a full snapshot of the dropped event row and its original E2O relations. Replaying the audit log in reverse — reinsert dropped snapshots, restore `ocel:activity` from `original_activity`, `ocel:timestamp` from `original_timestamp`, drop `sort_key`/`order_index`/synthetic deltas — deterministically regenerates the raw event log, so any analytical number can be traced to both the cleaned and the raw populations.

## 9. Failure modes and safeguards

1. **Collapsing distinct partial payments (e13/e14):** shared O1/V1 passes `have_common_object` checks. Safeguard: object-set comparison on the primary object type (Payment) plus a protected-events invariant asserted after every scenario.
2. **Abstraction-level updates become false rework (e06/e07, e13/e15):** either merging them or leaving identical labels creates loops. Safeguard: retain both with Detail/Status qualifiers; never let a DFG self-loop be read as redo.
3. **Ordering by ingestion time:** `ingested_at` reflects batch/network latency (carrier rows arrive ~20 s late, ERP summaries up to a minute late); using it as primary order can serialize handover before acceptance. Safeguard: excluded from the rule stack by default; if ever enabled, only after all semantic tiers and never reported as business order.
4. **Shared objects treated as proof of duplication (e08/e09):** identical object sets, different transitions. Safeguard: the decision tree requires *evidence*, not overlap; Q5 checks pre-harmonization source codes.
5. **Unioning incompatible E2O relations:** merging e15 (no Payment objects) into e13 attaches an invoice-level posting to M1; merging e05 into e03 attaches I2 to I1's pick. Safeguard: relation union only under verified physical identity; every relation diff logged.
6. **Synthetic microseconds changing durations:** tie-break deltas leak into KPIs as measured waiting time (or negative durations if inverted). Safeguard: keep `original_timestamp`; compute performance from originals with a declared tie policy; flag adjusted timestamps.
7. **Losing source-authoritative attributes:** naive keep-first dedup drops BILLING tax details or SCANNER operator IDs. Safeguard: attribute-authority matrix, source-prefixed carry-over, conflict log.
8. **Library duplicate functions applied to the whole OCEL unscoped:** `ocel_merge_duplicates` absorbs e05/e14 silently while referential integrity still validates — the damage is semantic, so structural validation alone cannot catch it. Safeguard: mandatory pre-check of candidate groups, scoped application, protected-event assertions, before/after diff reporting.
9. **Cycle introduction from conflicting semantic edges** across scenario variants: safeguard: acyclicity assertion inside the topological sort.
10. **Label refinement breaking cross-dataset comparability:** refined labels split DFG nodes between pipeline versions. Safeguard: `original_activity` retained and a label-taxonomy version recorded per dataset.

Throughout: a deterministic total order is a reproducible serialization, never a claim about the true physical order; concurrency (e03e05, e13e14) is preserved as a fact and merely *serialized* for tooling.
