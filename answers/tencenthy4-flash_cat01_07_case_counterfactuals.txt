## 1. Feasibility model

```text
Generic core:
Register < Triage
Identity Check < Assessment
Document Check < Assessment
if originals_required: Originals Receipt < Document Check
Decision < Notify

High-risk/high-value:
latest relevant Assessment < final Compliance Review < Decision
final Assessment resource != final Compliance Review resource

After RMI_i issued by Assessment or Compliance Review:
Assessment_i or Compliance Review_i -> Request More Info_i
Request More Info_i -> new Document Check_(i+1)
new Document Check_(i+1) -> new Assessment_(i+1)
if high-risk/high-value:
    new Assessment_(i+1) < new/reaffirmed Compliance Review < Decision

Preliminary work:
Triage < S1 preliminary escalation packet review
Triage < C1 preliminary compliance screen
S1 preliminary work  Identity Check / Document Check is allowed
C1 preliminary screen is not a substitute for final Compliance Review

Case-specific parallelism:
K-104: Identity Check  Document Check permitted; originals not required
K-219: Identity Check  Document Check only after Originals Receipt for document start
K-337: each RMI loop requires new Document Check and Assessment unless explicitly prohibited
K-411: Identity Check  Document Check permitted; originals not required
```

```text
- Register must be first and must be followed by Triage.
- Identity Check and Document Check must both complete before any final Assessment.
- If originals are required, Originals Receipt must precede Document Check; Identity Check may still run earlier or concurrently.
- High-risk/high-value cases require final Compliance Review after the latest relevant Assessment and before Decision.
- Four-eyes rule: the final Assessment performer and final Compliance Review performer must differ.
- A preliminary compliance screen may start early but cannot replace final Compliance Review.
- Request More Info invalidates prior evidence finality: a new Document Check and Assessment are required before Decision; high-risk/high-value cases need new or explicitly reaffirmed compliance.
- Resources cannot perform overlapping service intervals; queue snapshots are uncertain forecasts.
- K-104 intervention: S1 packet review and C1 preliminary work are timing/preparation changes; final C1 review must remain after final A1 assessment.
- K-219 intervention: D2 substitution is a routing/resource change; if clarification occurs, normal rework path resumes.
- K-337 intervention: prohibiting RMI2 changes the allowed decision policy; residual uncertainty must be explicitly accepted via conditional approval or rejection, not ignored.
- K-411 intervention: creating both tasks early is a workflow/logging change; real-time timestamps are required to substantiate true concurrency.
```

Timing-only changes are closest in K-411, where concurrency is already process-permissible and the intervention mainly removes an avoidable task-creation delay. K-104 changes timing and resource scheduling, because S1 and C1 do earlier preparatory work, but it preserves final gates. K-219 changes document routing from D1 to D2. K-337 changes decision policy, because it removes a lawful rework loop and permits decision under residual uncertainty.

## 3. Counterfactual derivations

### K-104

Factual mechanism: The critical delay was informational as much as service-based. Triage noticed sanctions ambiguity but did not escalate it, so A1 effectively rediscovered the issue during assessment. S1 advice then came after assessment, and C1 had to read most evidence fresh after the compliance queue became available. The D1 and assessment queues also imposed real waits, so the counterfactual should not erase them.

Minimal intervention: Keep registration, triage, identity, document, assessor, and final decision resources unchanged. Add an S1 preliminary escalation review immediately after Triage and a C1 preliminary screen/reserved final slot. The final C1 review remains a distinct post-assessment activity, with A1 as assessor and C1 as reviewer.

Temporal propagation: S1 can work during identity and document waits, so escalation advice becomes available before A1 starts. That does not make A1 start earlier, but it can shorten A1's issue-discovery work and make evidence better organized. C1 preliminary reading can also occur while D1 work and assessment queuing continue. The reserved C1 slot reduces the post-assessment compliance wait; if the slot is scheduled after A1 completion, the final review can move from Wednesday afternoon to Tuesday evening or Wednesday morning.

Process-feasibility check: Originals are not required, so identity and document concurrency is allowed; here the original service intervals can remain as factual. Final Compliance Review still follows final Assessment and precedes Decision. The four-eyes rule is satisfied because A1 assesses and C1 reviews. The early C1 screen is explicitly preliminary and not a substitute.

Best/base/worst case: Best case: S1 packet is complete, A1 finishes early Tuesday, and C1's reserved slot supports same-evening final review, moving notify to Tuesday late. Base case: C1 final occurs Wednesday morning, saving roughly 5-9 hours. Worst case: the packet is incomplete, the C1 slot is displaced by urgent cases, or final assessment slips; then notify remains Wednesday afternoon and C1 may reread the file, erasing the benefit.

Evidence that would reverse the conclusion: Reversal would be warranted if the triage packet lacked the sanctions detail needed by S1/C1, if C1 preliminary work could not be reused, if the reserved slot caused material delay to higher-priority compliance cases, if A1 final assessment slipped beyond the slot, or if audit evidence showed final Compliance Review occurring before final Assessment.

### K-219

Factual mechanism: Triage routed the handwritten standard documents to D1 because of handwriting risk. D1's queue caused a long wait from originals receipt to Tuesday morning, but D1 completed accurately, avoiding rework. The assessment and manager decision then occurred on separate later queues.

Minimal intervention: Change only the document resource selection. Once originals arrive Monday 17:30, create the document task for D2 rather than waiting for D1; leave identity, assessment, and decision assignment unchanged unless the earlier document completion naturally changes their start times.

Temporal propagation: D2's queue at Monday 16:00 was shorter than D1's, so D2 can plausibly start Monday evening rather than Tuesday morning. D2's service is slower for handwritten work, but if it avoids clarification the document check still completes Tuesday early. That moves the case into A2's queue earlier; because A2 had a six-hour queue Tuesday morning, some or all of the saved document time may become assessment waiting. Decision can occur Tuesday only if M1 signs outside the Wednesday batch.

Process-feasibility check: Originals Receipt precedes Document Check, satisfying the originals rule. Identity Check precedes Assessment. If D2 requests clarification, the process must branch through Request More Info, then a new Document Check and new Assessment before Decision. No compliance review is required because the case is neither high-risk nor high-value.

Best/base/worst case: Best case: D2 reads the handwriting correctly, A2 assesses Tuesday, and M1 signs Tuesday afternoon, yielding 15-17 hours earlier notify with the same approval. Base case: D2 completes early but A2 queue or M1 batching absorbs much of the gain, producing little end-to-end improvement despite earlier verification. Worst case: D2 requests clarification; the 8-36 hour external response plus new document and assessment work makes the case 10-40 hours slower than factual.

Evidence that would reverse the conclusion: Reversal would be warranted if D2's actual queue is not shorter than D1's, if handwritten complexity places D2 at the upper 8-hour service bound, if clarification probability is high, if M1 cannot sign Tuesday, or if D2's intervention displaces urgent documents and creates system-wide delay exceeding the local gain.

### K-337

Factual mechanism: The factual case was dominated by external supplier inconsistency. A2 requested a second confirmation, which created a Friday-to-Monday weekend wait, then D1 and A1 had to repeat work before compliance. The intervention does not remove the underlying discrepancy; it removes the formal loop that would resolve it.

Minimal intervention: Allow Assessment2 to end without RMI2, but require an explicit residual-risk statement. The case then proceeds directly to final Compliance Review, followed by Decision. The decision must be conditional approval with stated controls or rejection; it cannot silently treat the inconsistency as resolved.

Temporal propagation: Avoiding RMI2 eliminates the external supplier wait, Document Check 3, and Assessment 3. Because final Assessment is now A2 on Friday, C1 can review Friday afternoon rather than the following Tuesday. Decision may still occur Monday if M1 signs in batches, but even then the case avoids the weekend supplier loop. If C1 refuses to endorse the residual-risk file, the intervention either becomes rejection or fails.

Process-feasibility check: High-risk/high-value compliance is preserved because C1 reviews after final Assessment2 and before Decision. Four-eyes is satisfied because A1 is final assessor and C1 is final reviewer. The intervention explicitly changes decision policy by permitting a decision under residual uncertainty, but it does not waive compliance.

Best/base/worst case: Best case: C1 and M1 complete Friday, moving notify about three days earlier. Base case: C1 reviews Friday and M1 signs Monday, saving about two days. Worst case: C1 finds the unresolved discrepancy materially indefensible; the result is rejection or reopened information gathering, with appeal or loss exposure and little or no reliable time saving.

Evidence that would reverse the conclusion: Reversal would be warranted if policy requires supplier confirmation for this risk class, if the inconsistency affects a material control total, if C1 cannot document a defensible conditional approval, if appeal likelihood is high, or if the supplier response would have arrived quickly without weekend delay.

### K-411

Factual mechanism: The legacy lock artificially created only the identity task. Document work waited until I2 finished, even though originals were not required and D2 could have worked in parallel. The later assessment queue then grew, so the factual case has both an avoidable verification delay and a downstream queue effect.

Minimal intervention: At Triage, create both verification tasks and use a controlled workaround that gives D2 task ownership before I2 completes. Require real-time timestamps for task creation, work start, work completion, and ownership transfer.

Temporal propagation: D2 can start when D2 becomes available rather than after I2 finishes. Because I2 and D2 are different resources, their intervals can overlap without violating capacity. Both checks complete Tuesday afternoon rather than Tuesday evening. That earlier readiness enters the A2 queue earlier; if A2 is near capacity, the saved time becomes waiting rather than earlier service. If A2 has slack, assessment and decision can move earlier.

Process-feasibility check: Originals are not required, so concurrency is allowed. Both checks complete before Assessment. Decision remains before Notify. No high-risk compliance or four-eyes requirement applies. The main process risk is evidentiary: if timestamps are batch-entered, the log may claim concurrency that did not physically occur.

Best/base/worst case: Best case: D2 starts midday, both checks finish by 16:30, A2 starts Wednesday morning early, and notify moves 3-5 hours earlier. Base case: A2 still starts around 09:30 because of queueing, yielding verification-time gain but little end-to-end saving. Worst case: workaround creates duplicate tasks, ownership conflicts, or batch timestamps; then the case may need audit correction or rework, offsetting any time gain.

Evidence that would reverse the conclusion: Reversal would be warranted if D2 is unavailable until after I2 finishes, if the workaround cannot assign valid task ownership, if real-time logging is impossible, if assessment queue forecasts show the saved time will be fully absorbed, or if concurrency creates control failures.

At 100 similar cases per week, the local counterfactuals stop being independent. For K-104-like cases, both preliminary and final C1 work consume the only fully certified reviewer. A two-hour preliminary packet per case is 200 hours before any final reviews, so most “reservations” would either displace urgent compliance work or sit idle when final assessments arrive later. If packets are incomplete, C1 may need to reread, turning preparation into extra work. For K-219-like cases, moving documents from D1 to D2 shifts rather than removes demand: D1 frees capacity, but D2's slower standard service and higher clarification likelihood create a new queue. The critical threshold is rework; once clarifications enter the 8-36 hour external-response range, saved D1 queue time is consumed by new document and assessment loops. K-337-style suppression avoids exactly that external weekend loop and frees D1/A1 slots, but at scale the freed capacity may be filled by other cases while conditional-approval appeals or risk reviews reappear later as a different queue.

K-411 and successful K-219 cases make verification complete earlier, pushing many cases into A1/A2 queues. In queueing terms, the bottleneck migrates from identity/document tasks to assessment: apparent service-time savings become waiting time unless assessment capacity or triage priority is also managed. Weekend effects remain asymmetric: external supplier responses and handwritten clarifications can jump to Monday, whereas C1 reservations cannot create weekend capacity. K-104/K-337 interventions consume or reorder scarce C1 slots, so urgent high-risk cases outside the pilot may miss decision windows. Timestamp behavior is decisive for K-411: real-time ownership logs support true concurrency, while batch entry can produce false concurrency, invalidating audit trails and making queue metrics look better than physical work. Benefits are transportable only where the relieved resource is the true bottleneck and downstream gates have slack.

## 7. Final synthesis

The most robust intervention is K-411's controlled parallelization, assuming real-time event capture. It touches a case where concurrency is already permitted, uses separable resources, preserves all gates, and is easy to stop; its benefit is modest but its failure modes are visible in logs. K-219 is a reasonable second because D2 often has a shorter queue and the decision policy is unchanged, but its value collapses if handwriting triggers clarification. K-104 is attractive for risk discovery yet depends on scarce C1 capacity and complete early packets. The most dangerous despite apparent speed is K-337: suppressing the second rework loop can save days, but it converts a factual, confirmed approval into a judgement under residual uncertainty. For a high-risk/high-value case, that changes compliance defensibility, appeal exposure, and loss exposure; the counterfactual is only acceptable if the file explicitly records the discrepancy and C1 endorses a conditional decision.

The least transportable local counterfactual is K-104's provisional C1 reservation. In one case, reserving a slot can cut queue wait; across many cases, the same action reallocates a singleton bottleneck and can harm more urgent cases. K-411 is also less transportable if assessment capacity is near saturation: earlier checks may simply create assessment waiting. The most valuable additional data are event-level queues by skill and time of day; actual service-time distributions for D1/D2 by handwriting and corporate complexity; C1 work content and reservation cancellation rates; external-response times including weekends; M1 signing batches; and linkable logs that distinguish task creation, real work start, and batch entry. These data reveal whether a queue is being removed, merely shifted, or converted into downstream risk.

## 8. Assumption audit

1. (structural) The normative process rules remain authoritative; only K-337 explicitly changes the allowed decision policy by suppressing RMI2.
2. (temporal) Queue snapshots are forecasts with uncertainty, not guarantees of exact start times.
3. (resource) C1 is the only fully certified compliance reviewer in the window, and no resource performs overlapping service intervals.
4. (behavioral) S1 and C1 can use preliminary packets productively before all evidence is final, while still avoiding final sign-off.
5. (quality) Preliminary compliance preparation saves only 1-3 hours when the later evidence is sufficiently complete and the packet is accurate.
6. (quality) K-337 conditional approval is defensible only if the unresolved discrepancy is explicitly documented and endorsed by Compliance.
7. (interference) Non-target urgent cases may be displaced by reserved C1 slots, earlier D2 use, or earlier assessment arrivals.
8. (interference) K-411's real-time logging is valid; if timestamps are batch-entered, apparent concurrency may not be true concurrency.
