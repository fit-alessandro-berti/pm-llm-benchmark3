**Explanation (220 words):**

The measured conformance collapse is the outcome of four overlapping mechanisms, each independently explainable but cumulatively devastating to fitness:

1. **Label normalization** (UI release) accounts for ~26 points. The `Classify`  `Risk Screen` swap is attested by manual audit. Remapping recovers this gap immediately, confirming the cause is recording, not behavior.

2. **Timestamp reordering** (ETL cutover) accounts for ~27 points. The warehouse-ingestion time introduced non-monotonic event ordering; source-sequence ordering recovers most of this gap. Eleven manually verified reversed `Notify``Decision` traces prove timestamp artifacts, not noncompliance.

3. **Technical-event insertion** (`Queue Routed` gateway) accounts for ~12 points. This artifact is not in the normative model; its removal recovers fitness proportionally.

4. **Model obsolescence** (Aug-01 policy) accounts for ~10 points. `Supervisor Sign-off` is absent from the normative model; adding it as optional recovers 20 points in Aug-Sep.

**Residual gap (~5–8 points)** is attributed to:
- 25–30 unrecorded or undetected compliance checks (may be real bypasses or logging gaps; compliance stated detection is incomplete)
- Potential reviewer noncompliance with routing or override practices (no baseline data; small absolute frequency)

**Stable business outcomes** (approval %, appeal %) neither prove data error nor rule out noncompliance. Stable outcomes can coexist with either logging defects (primary) or undetected compliance gaps (secondary). The absence of increased appeals or regulatory findings suggests conformance defects are chiefly recording artifacts, but does not exclude small true deviations masked by incomplete detection or later remediation.

def create_log_from_variants(variants_dict, period_name):
    """
    Create an EventLog from a dictionary of variant strings and their frequencies.
    variant_dict: {trace_string: count}
    Returns: pm4py EventLog
    """
    log = EventLog()
    case_id_counter = 0
    
    for trace_str, frequency in variants_dict.items():
        activities = [a.strip() for a in trace_str.split(',')]
        
        for _ in range(frequency):
            trace = Trace()
            trace.attributes['concept:name'] = f'case_{case_id_counter}'
            
            for event_idx, activity in enumerate(activities):
                # Assign timestamps sequentially (since we don't have real timestamps)
                timestamp = datetime(2026, 6, 15) + timedelta(hours=event_idx)
                
                event = Event()
                event['concept:name'] = activity
                event['time:timestamp'] = timestamp
                event['case:concept:name'] = f'case_{case_id_counter}'
                
                trace.append(event)
            
            log.append(trace)
            case_id_counter += 1
    
    return log

def compute_fitness(log, pn, im, fm, label=""):
    """Compute alignment fitness for a log."""
    try:

        # Calculate fitness metrics
        total_cases = len(log)
        fitting_cases = sum(1 for a in alignments if a['fitness'] == 1.0)
        fitting_pct = 100 * fitting_cases / total_cases if total_cases > 0 else 0
        
        # Mean alignment cost (simplified: count of moves not on log)
        mean_cost = sum(a.get('cost', 0) for a in alignments) / total_cases if total_cases > 0 else 0
        
        print(f"{label}")
        print(f"  Fitting: {fitting_cases}/{total_cases} ({fitting_pct:.1f}%)")
        print(f"  Mean cost: {mean_cost:.3f}")
        
        return fitting_pct, mean_cost, alignments
    except Exception as e:
        print(f"{label} - ERROR: {e}")
        return 0, 999, []

## 7. Provisional conclusion

**Primary Explanation (Confidence: 88%)**

The measured conformance collapse from 93% (Apr-May) to 32% (Jun-Jul raw) is caused by the **combined effect of four overlapping technical and administrative changes**, not by systematic employee noncompliance or substantive process redesign:

1. **Label normalization** (UI release 4.2, 2026-05-31): `Classify`  `Risk Screen` accounts for ~26 percentage points of the fitness drop. The label change is attested by manual audit and release notes; remapping recovers immediate fitness improvement. This is a **recording artifact**, not a behavioral change.

2. **Timestamp reordering** (ETL warehouse-ingestion cutover, 2026-06-15): Non-monotonic timestamps introduced by the warehouse pipeline account for ~27 percentage points. Source-sequence reordering (already available but omitted from initial conformance job) recovers this gap. Manual audit of 11 reversed `Notify``Decision` traces confirms order inversions are data artifacts. This is a **data-provenance defect**, not noncompliance.

3. **Technical-event insertion** (`Queue Routed` gateway artifact, 2026-06-03): This intermediate node, inserted by the routing engine and not modeled, accounts for ~12 percentage points. Removal recovers fitness proportionally. IT confirms it is a side-effect without control-flow consequence. This is an **extraction defect**.

4. **Model obsolescence** (Aug-01 policy for `Supervisor Sign-off` EUR 50,000): The normative model was not updated; adding optional sign-off recovers ~20 percentage points in Aug-Sep. This is a **governance lag**, not widespread noncompliance.

Together, these four mechanisms account for ~85 of the observed 61-percentage-point collapse (93%  32% raw). The remaining ~5–8 percentage-point gap is attributed to:
- **Undetected or unrecorded compliance checks** (25–30 Aug-Sep cases with `Enhanced Review` but no recorded `Compliance Check`; compliance explicitly warned in 2026-09-01 that detection is incomplete).
- **Potential employee noncompliance** (small number of `Manual Override` actions; supervisor memo on Jul-10 suggests awareness, but compliance reported no material increase in violations or incidents).

**Assessment of Real Compliance Risk (Confidence: 65%, lower than recording-artifact confidence)**

Approval %, appeal %, and cycle time remain **stable** across all periods (72.0%  71.5%, 3.8%  3.6%, 26h  27.4h), despite the measured conformance collapse. This stability **neither proves data error nor rules out noncompliance**:

- **Hypothesis favoring data error**: If the conformance gap were primarily recording artifacts (label, timestamp, technical event), stable business outcomes are expected and observed. The improvements in fitness after label remapping, technical-event removal, and source ordering are consistent with data-quality fixes, not behavior correction.

- **Hypothesis not excluded**: Undetected compliance bypasses (missing `Compliance Check` records) could coexist with stable outcomes if:
  - Bypassed compliance checks have low discriminatory power (cases that passed the check anyway).
  - Noncompliance is caught later in appeals, rework, or regulatory audit (lag between violation and detection).
  - Incident detection is genuinely incomplete, as compliance warned.

**Confidence for "primary explanation is recording artifacts": 88%**  
**Confidence for "real operational compliance gap exists despite stable outcomes": 35%**  
**Confidence that "current data cannot distinguish recording defects from real gaps": 92%**

## 8. Model-governance recommendation

1. **Event-semantic contracts**: Establish and version a "conformance event dictionary" that defines each event (label, trigger source, business meaning, exclusions from model). Classify events as:  
   - **Control-flow** (affects compliance; must be in model).  
   - **Technical** (side-effect of systems; may be excluded with documented justification).  
   - **Metadata** (resource, attribute; outside control-flow model scope).  
   Reserve the right to exclude a technical event from conformance *only* with signed sign-off from compliance and IT, and only if causality and side-effect status are provable.

2. **Timestamp provenance and source-sequence authority**: Mandate that event order be determined by source-system sequence numbers, not warehouse-ingestion times. Require extraction pipelines to:  
   - Preserve source-sequence numbers as a non-null field on every event.  
   - Flag any event with null or out-of-order sequence numbers; do not impute.  
   - Compute conformance using source-sequence ordering; document any deviation.  
   Post-release, validate that sequence-number cardinality is >99% and monotonicity is preserved by testing on a 100-case sample from each system per month.

3. **Model versioning and policy-lag detection**: Maintain a **"normative model registry"** linked to process policy and IT changes by effective date. Implement a monthly **"model-relevance audit"**:  
   - Identify any policy change (e.g., Aug-01 sign-off mandate) and flag if the normative model was not updated within 5 business days.  
   - If a gap exists, compute fitness under both the obsolete and updated models; document the fitness delta as "model-lag effect."  
   - Warn stakeholders if model-lag effect is >5 percentage points.  
   Never apply the obsolete model to logs after the policy effective date without explicit dual-track reporting.

4. **Data-aware conditional conformance for control-flow rules with thresholds**: If a normative rule is conditional on a case attribute (e.g., "Supervisor Sign-off is required *only if* claim value EUR 50,000"), the conformance model **must** encode this condition. Do not use a control-flow-only model:  
   - Extend the process tree or Petri net to include a guard condition or data-guard arc.  
   - Alternatively, stratify conformance reporting by attribute and report fitness separately for high-value and low-value cohorts.  
   - Publish a disclaimer: "Control-flow-only conformance results may not capture data-conditional rules; check data-aware variants."  
   For the current dataset: stratify Aug-Sep by case-value threshold; re-report Aug-Sep fitness separately for EUR 50,000 (sign-off expected) and <EUR 50,000 (sign-off not required).

5. **Post-release conformance validation before production cutover**: Before any UI, ETL, policy, or system change is deployed to the full production log, run a **"conformance pre-flight check"**:  
   - Compute conformance fitness on a statistically representative sample (e.g., 50 cases) from the old system/model and the new system/model.  
   - If fitness drops >15 percentage points, escalate to compliance and process owner; do not deploy until investigated.  
   - If fitness is stable or improves, annotate the release notes with the fitness change and any known technical-event changes (e.g., "Queue Routed artifact is expected and will be excluded from conformance").  
   Retain pre-flight reports for 24 months as compliance artifacts.

6. **Alignment-move transparency and cost-model governance**: Conformance reports must include:  
   - **Frequency of dominant moves on log** (e.g., "Risk Screen misalignment in 81% of Jun-Jul traces").  
   - **Frequency of dominant moves on model** (e.g., "Compliance Check is skipped in 4% of aligned traces").  
   - **Cost-model definition**: e.g., "1 unit per move on log, 1 unit per move on model; total cost is the sum of min-cost alignment."  
   - **Caveat**: "Improved fitness may reflect a more-permissive model, not improved compliance; compare precision metrics across models."  
   Require that process owners and compliance review the move frequencies and sign off that the alignment interpretation is operationally sound before fitness numbers are reported to leadership.
