from collections import deque
from pm4py.objects.petri_net.obj import Marking

def marking_key(m):
    if m is None:
        return None
    items = []
    for p, c in m.items():
        try:
            c_int = int(c)
        except Exception:
            c_int = c
        if c_int:
            items.append((getattr(p, "name", str(p)), c_int))
    return tuple(sorted(items, key=lambda x: str(x[0])))

def markings_equal(m1, m2):
    return marking_key(m1) == marking_key(m2)

def token_count(m):
    return sum(int(c) for c in m.values()) if m is not None else None

def marking_summary(m):
    return {"key": marking_key(m), "tokens": token_count(m)}

def bounded_visible_traces(net, im, fm, max_visible_len=12, max_steps=200, max_silent_streak=20, max_states=200000):
    if net is None or im is None or fm is None:
        return set(), True, "null model or marking"
    traces = set()
    q = deque()
    q.append((Marking(im), tuple(), 0, 0))
    seen = set()
    truncated = False
    reason = ""
    while q:
        marking, trace, steps, silent_streak = q.popleft()
        key = (marking_key(marking), trace, steps, silent_streak)
        if key in seen:
            continue
        seen.add(key)
        if len(seen) > max_states:
            truncated = True
            reason = "max_states exceeded"
            break
        if markings_equal(marking, fm):
            traces.add(trace)
            continue  # exact final marking reached; do not explore beyond final
        if steps >= max_steps:
            truncated = True
            reason = "max_steps reached"
            continue
        if len(trace) > max_visible_len:
            truncated = True
            reason = "max_visible_len exceeded"
            continue
        try:
            enabled = list(pm4py.get_enabled_transitions(net, marking))
        except Exception as e:
            truncated = True
            reason = f"get_enabled_transitions failed: {e!r}"
            break
        for t in enabled:
            lbl = vis_label(t)
            is_silent = (lbl is None)
            if not is_silent:
                if len(trace) >= max_visible_len:
                    truncated = True
                    reason = "visible transition would exceed max_visible_len"
                    continue
                new_trace = trace + (lbl,)
                new_silent_streak = 0
            else:
                new_trace = trace
                new_silent_streak = silent_streak + 1
                if new_silent_streak > max_silent_streak:

                    reason = "max_silent_streak exceeded"
                    continue

| INV-05 | Optional legal branch and verification loop are unordered and may overlap/interleave at the model level. | `RAPCLIRelArc` is a valid visible linearization. | No single source-invalid trace; a converter that rejects `RAPCLIRelArc` has lost an allowed interleaving. | Partially: interleavings are visible, but true simultaneous overlap is not directly observable in a linear trace. |
| INV-06 | Each verification iteration executes `C` before `I`; a repeated iteration is separated by `D`. | `RAPCIDCIRelArc` | `RAPICRelArc`; `RAPCICIRelArc` | Yes: loop body and redo activities are visible. |
| INV-07 | At least one verification iteration occurs. | `RAPCIRelArc` | `RAPRelArc` | Yes: at least one `C,I` pair must occur. |
| INV-08 | Release waits for completion of both the optional-legal branch and the verification loop. | `RAPLCIRelArc`; skip case `RAPCIRelArc` with hidden `` before `Rel`. | `RAPLRelCIArc`; `RAPCIRelArcL` | Yes: `Rel` must come after legal-branch completion and verification completion. |
| INV-09 | Archive Change occurs after Release Change and is final. | `RAPCIRelArc` | `RAPCIArcRel`; trace ending at `Rel` without `Arc`; any task after `Arc`. | Yes: `Arc` must be last. |
| INV-10 | Visible activity labels are unique and distinguish loop body, rework, optional legal, and final activities. | Unique labels as in source model. | Duplicate or collapsed labels, e.g. using `Configure Trial` for another activity or hiding `D`. | Yes: label collision changes trace equivalence and auditability. |

# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| P1: POWL  accepting Petri net  BPMN, primary | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_bpmn(net, im, fm)`; round-trip `pm4py.convert_to_petri_net(bpmn)` | Directly uses the supported POWL-to-accepting-Petri conversion and keeps the Petri net as the executable semantic reference before generating BPMN. | BPMN conversion and layout may introduce gateway ambiguity or serialize concurrent branches visually; markings may be null or regenerated. | Exception, null initial/final marking, unsound net, failed BPMN round-trip, or bounded-trace mismatch. |
| P2: POWL  accepting Petri net  process tree  BPMN | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_process_tree(net, im, fm)` inside `try/except`; `pm4py.convert_to_bpmn(tree)` | If successful, may produce a more block-structured tree/BPMN that is easier for stakeholders to read. | The source contains a partial order with unordered optional legal and verification branches plus a loop, so process-tree conversion may fail or may approximate/block-structure away allowed interleavings. | `convert_to_process_tree` raises or returns `None`; tree-to-BPMN fails; tree-derived BPMN cannot be converted back to a sound equivalent net; trace mismatch. |

Primary pipeline: **P1**. It avoids forcing this non-block-structured partial order into a process tree. P2 is retained as a diagnostic attempt and is allowed to fail.

# 4. Preservation and Loss Audit

Assessment terms are used conservatively because this is an audit design, not an execution transcript. A run of the provided validation code should promote `expected preserved` to `validated preserved` or reject the artifact.

| Source invariant | POWLPetri | PetriBPMN | PetriTree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| Register Change first | expected preserved | ambiguous | conversion failed | ambiguous | Direct POWL-to-Petri conversion should encode precedence. BPMN layout may visually place other routing artifacts before the first task. |
| `A` and `P` unordered after `R` | expected preserved | ambiguous | conversion failed | ambiguous | Must see both `RAP...` and `RPA...`; BPMN parallel gateway can preserve this, but a serialized layout would not. |
| Optional Legal Review with silent skip | expected preserved | ambiguous | conversion failed | ambiguous | The silent branch may become a BPMN default flow or an unlabelled gateway. It can look mandatory or absent in the diagram. |
| No edge between Legal Review and verification loop | expected preserved | ambiguous | conversion failed | ambiguous | Trace `RAPCLIRelArc` is a required interleaving. BPMN may visually suggest `L` before or after `C/I`. |
| Loop body `C` before `I`, redo separated by `D` | expected preserved | ambiguous | conversion failed | ambiguous | Source loop is at least one `C,I`; repeated body requires `D`. BPMN loop marker may not make minimum iteration count or redo separation explicit. |
| At least one verification iteration | expected preserved | ambiguous | conversion failed | ambiguous | Negative witness `RAPRelArc` must be rejected. A BPMN loop may visually allow zero iterations if not documented. |
| Join before Release Change waits for optional-legal branch and verification loop | expected preserved | ambiguous | conversion failed | ambiguous | Must reject `RAPLRelCIArc`. BPMN gateway join type is critical: parallel join vs exclusive join changes semantics. |
| Archive Change after Release and finality | expected preserved | expected preserved | conversion failed | ambiguous | Exact final marking and trace `...RelArc` must hold. BPMN end event placement may be visually misleading. |
| Activity-label uniqueness | expected preserved | ambiguous | conversion failed | ambiguous | Source labels are unique; BPMN conversion may introduce unnamed gateways or duplicate structural labels, affecting trace comparison if not hidden correctly. |
| Initial and final markings non-null and exact | expected preserved | ambiguous | conversion failed | not tested | Every generated net must have checked non-null `im`/`fm`; BPMN round-trip may regenerate place names or token placements. |
| Gateway/routing-node ambiguity in BPMN | not tested | ambiguous | conversion failed | ambiguous | Parallel, exclusive, and inclusive gateways may be visually similar. Silent routing nodes can hide required synchronization. |

Discussion:

- **True concurrency vs arbitrary interleaving:** A Petri net can preserve concurrency structurally, but trace-based validation only observes interleavings. Seeing both `A,P` and `P,A` orders is necessary but does not prove the model has true concurrency rather than arbitrary interleaving. The BPMN parallel gateway must be inspected.
- **Lack of edge between Optional Legal Review and verification:** The source allows `L` between `C` and `I`. A BPMN layout that shows Legal Review wholly before or wholly after the verification loop is at risk of suggesting an ordering that does not exist.
- **Silent optional behavior:** The XOR skip branch uses a silent transition. Hiding tau is correct for trace comparison, but BPMN may render the skip as a default flow, an unnamed gateway, or no node at all. This makes optionality easy to misread.
- **Binary-loop semantics:** The PM4Py loop operator with `children=[trial_body, correct_defect]` must be interpreted as at least one `trial_body`, with `correct_defect` as the redo/separator for repeated iterations. BPMN loop visualization may not express “at least once” or “redo separated by Correct Defect” without annotation.
- **Join before Release Change:** Both the optional-legal branch and the verification loop must complete before `Rel`. A BPMN exclusive join would admit `Rel` too early. This is a semantic rejection condition.
- **Activity-label uniqueness:** Visible labels are unique in the source. Round-tripped nets and BPMN diagrams must be checked for duplicated labels or hidden activities that accidentally collide with visible labels.
- **Initial and final markings:** A conversion returning a net object is insufficient. Non-null markings and exact final-marking acceptance must be tested. BPMN round-trip may regenerate place identities, so marking equality by place name is evidence, not proof.
- **Gateway or routing-node ambiguity:** BPMN gateways encode semantics through type and topology, not through layout. Parallel gateways, exclusive gateways, loop markers, and silent routing nodes must be annotated or validated against the Petri net.

# 5. Round-Trip Validation Code

This code assumes Section 3 has been executed and that `net_from_powl`, `im_from_powl`, `fm_from_powl`, and `roundtrip_nets` are available. The custom bounded exploration is the net playout used here. It hides transitions whose label is `None`, requires exact final-marking equality for completed traces, avoids infinite silent cycling with a silent-streak bound, and enforces visible-length and total-step bounds. It is not exhaustive beyond the chosen bounds.

```python
from collections import deque
from pm4py.objects.petri_net.obj import Marking

# -------------------------------------------------------------------------
# Marking utilities
# -------------------------------------------------------------------------
def marking_key(marking):
    if marking is None:
        return None
    items = []
    for place, count in marking.items():
        try:
            count_int = int(count)
        except Exception:
            count_int = count
        if count_int:
            items.append((getattr(place, "name", str(place)), count_int))
    return tuple(sorted(items, key=lambda x: str(x[0])))


def markings_equal(m1, m2):
    return marking_key(m1) == marking_key(m2)


def token_count(marking):
    if marking is None:
        return None
    return sum(int(c) for c in marking.values())


def marking_summary(marking):
    return {
        "key": marking_key(marking),
        "tokens": token_count(marking),
    }


# -------------------------------------------------------------------------
# Petri-net firing without assuming a non-null marking or a playout API
# -------------------------------------------------------------------------
def arc_weight(arc):
    w = getattr(arc, "weight", 1)
    try:
        return int(w)
    except Exception:
        return int(getattr(w, "value", 1))


def fire_transition(net, marking, transition):
    new_marking = Marking(marking)

    for arc in transition.in_arcs:
        place = arc.source
        weight = arc_weight(arc)
        new_marking[place] = new_marking.get(place, 0) - weight
        if new_marking[place] <= 0:
            new_marking.pop(place, None)

    for arc in transition.out_arcs:
        place = arc.target
        weight = arc_weight(arc)
        new_marking[place] = new_marking.get(place, 0) + weight

    return new_marking


def visible_label(transition):
    label = getattr(transition, "label", None)
    return None if label is None else str(label)


# -------------------------------------------------------------------------
# Bounded visible-trace exploration
# -------------------------------------------------------------------------
def bounded_visible_traces(
    net,
    im,
    fm,
    max_visible_len=12,
    max_steps=250,
    max_silent_streak=25,
    max_states=250000,
):
    if net is None or im is None or fm is None:
        return set(), True, "null net or marking"

    accepted_traces = set()
    queue = deque([(Marking(im), tuple(), 0, 0)])
    seen = set()

    truncated = False
    reason = ""

    while queue:
        marking, trace, steps, silent_streak = queue.popleft()
        state_key = (marking_key(marking), trace, steps, silent_streak)

        if state_key in seen:
            continue
        seen.add(state_key)

        if len(seen) > max_states:
            truncated = True
            reason = "max_states exceeded"
            break

        if markings_equal(marking, fm):
            accepted_traces.add(trace)
            # Exact final marking reached. Do not continue beyond finality.
            continue

        if steps >= max_steps:
            truncated = True
            reason = "max_steps exceeded"
            continue

        if len(trace) > max_visible_len:
            truncated = True
            reason = "max_visible_len exceeded"
            continue

        try:
            enabled = list(pm4py.get_enabled_transitions(net, marking))
        except Exception as e:
            truncated = True
            reason = f"get_enabled_transitions failed: {e!r}"
            break

        for transition in enabled:
            label = visible_label(transition)
            is_silent = label is None

            if is_silent:
                new_trace = trace
                new_silent_streak = silent_streak + 1
                if new_silent_streak > max_silent_streak:
                    truncated = True
                    reason = "max_silent_streak exceeded"
                    continue
            else:
                if len(trace) >= max_visible_len:
                    truncated = True
                    reason = "visible transition would exceed max_visible_len"
                    continue
                new_trace = trace + (label,)
                new_silent_streak = 0

            new_marking = fire_transition(net, marking, transition)
            queue.append(
                (new_marking, new_trace, steps + 1, new_silent_streak)
            )

    return accepted_traces, truncated, reason


# -------------------------------------------------------------------------
# Safe diagnostics and comparison helpers
# -------------------------------------------------------------------------
def safe_soundness(net, im, fm):
    try:
        return pm4py.check_soundness(net, im, fm, print_diagnostics=False)
    except Exception as e:
        return ("ERROR", repr(e))


def safe_footprints(net, im, fm):
    try:
        return pm4py.discover_footprints(net, im, fm)
    except Exception as e:
        return ("ERROR", repr(e))


def safe_reachability_graph(net, im, fm):

        return pm4py.convert_to_reachability_graph(net, im, fm)
    except Exception as e:
        return ("ERROR", repr(e))


def compare_to_reference(
    ref_net,
    ref_im,
    ref_fm,
    other_net,
    other_im,
    other_fm,
    label,
    max_visible_len=12,
):
    result = {
        "label": label,
        "reference_markings": {
            "im": marking_summary(ref_im),
            "fm": marking_summary(ref_fm),
        },
        "other_markings": {
            "im": marking_summary(other_im),
            "fm": marking_summary(other_fm),
        },
    }

    result["initial_marking_equal_by_key"] = markings_equal(ref_im, other_im)
    result["final_marking_equal_by_key"] = markings_equal(ref_fm, other_fm)

    result["soundness_reference"] = safe_soundness(ref_net, ref_im, ref_fm)
    result["soundness_other"] = safe_soundness(other_net, other_im, other_fm)

    fp_ref = safe_footprints(ref_net, ref_im, ref_fm)
    fp_other = safe_footprints(other_net, other_im, other_fm)
    result["footprints_equal"] = fp_ref == fp_other
    result["footprints_reference"] = repr(fp_ref)
    result["footprints_other"] = repr(fp_other)

    rg_ref = safe_reachability_graph(ref_net, ref_im, ref_fm)
    rg_other = safe_reachability_graph(other_net, other_im, other_fm)
    result["reachability_equal_by_repr"] = repr(rg_ref) == repr(rg_other)
    result["reachability_reference"] = repr(rg_ref)
    result["reachability_other"] = repr(rg_other)

    traces_ref, trunc_ref, reason_ref = bounded_visible_traces(
        ref_net, ref_im, ref_fm, max_visible_len=max_visible_len
    )
    traces_other, trunc_other, reason_other = bounded_visible_traces(
        other_net, other_im, other_fm, max_visible_len=max_visible_len
    )

    result["bounded_traces_equal"] = traces_ref == traces_other
    result["truncated_reference"] = [trunc_ref, reason_ref]
    result["truncated_other"] = [trunc_other, reason_other]
    result["only_in_reference"] = sorted(traces_ref - traces_other)
    result["only_in_other"] = sorted(traces_other - traces_ref)

    return result

print("Round-trip comparisons:")

        "Archive Change",
    ),
    # Archive before Release.
    (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Archive Change",
        "Release Change",
    ),
]


def witness_audit(net, im, fm, positive, negative, max_visible_len=12):
    accepted, truncated, reason = bounded_visible_traces(
        net, im, fm, max_visible_len=max_visible_len
    )

    return {
        "positive_results": {
            trace: trace in accepted for trace in positive
        },
        "negative_results": {
            trace: trace in accepted for trace in negative
        },
        "truncated": [truncated, reason],
        "accepted_trace_count": len(accepted),
    }


witness_results = {
    "reference_net_from_powl": witness_audit(
        net_from_powl,
        im_from_powl,
        fm_from_powl,
        positive_witnesses,
        negative_witnesses,
    )
}

for label, (net, im, fm) in roundtrip_nets.items():
    witness_results[label] = witness_audit(
        net, im, fm, positive_witnesses, negative_witnesses
    )

print("Witness results:")
print(json.dumps(witness_results, indent=2, default=str))
```

Exhaustiveness statement: the bounded exploration is exhaustive only within the supplied bounds (`max_visible_len`, `max_steps`, `max_silent_streak`, `max_states`) and only if `truncated` remains false for all relevant branches. Passing witnesses do not prove full behavioral equivalence; they only validate the invariant checks exercised up to the chosen bound.

# 6. Visual-Semantics Review

A behaviorally acceptable converted Petri net can still produce a misleading BPMN diagram:

- **Parallel gateways:** The source has true concurrency between `A` and `P`, and no ordering between the optional legal branch and the verification loop. If the BPMN uses parallel gateways correctly, semantics may be preserved, but the layout can still imply a left-to-right or top-to-bottom sequence. If it accidentally uses exclusive or inclusive gateways, the interleavings may be lost.
- **Exclusive gateways:** Optional Legal Review requires an XOR split/join with a silent skip path. A BPMN reader may interpret an unlabelled default flow as mandatory or may not notice that Legal Review can be skipped. The XOR join must not become a synchronization point that waits for both `L` and ``.
- **Loop visualization:** The PM4Py loop contains `trial_body` as the body and `correct_defect` as the redo/separator. BPMN loop markers often show a generic loop-back arrow. The diagram may not communicate that `C` must precede `I`, that at least one iteration occurs, and that repeated iterations require `D` between them.
- **Silent routing nodes:** Hiding tau is correct for visible-trace comparison, but BPMN silent routing nodes are semantically important. An anonymous gateway or default flow may be the only evidence that skipping Legal Review is allowed. Removing it from an explanatory diagram can make the process look mandatory.
- **Apparent ordering of graph layout:** Horizontal position, vertical layering, and arrow placement are not semantic constraints. A diagram may place Legal Review above the verification loop, but the source does not impose that order. Stakeholders may incorrectly infer precedence from layout.
- **Gateway join before Release Change:** The join before `Release Change` must wait for both the optional-legal branch and the verification loop. The diagram should explicitly annotate this as an AND-join over branch completion and verification completion, not an exclusive merge.

Recommended annotations/documentation:

- Label XOR gateways “Legal Review or skip” and mark the silent skip flow explicitly.
- Label the join before `Release Change` “wait for optional-legal branch and verification loop.”
- Label the verification loop “at least once; repeat only after Correct Defect.”
- Add a note that graph layout is illustrative and not a precedence constraint.
- Provide the invariant table and positive/negative witness traces alongside the BPMN.
- Reference the authoritative POWL or accepting Petri net in the diagram footer, including conversion tool/version.

# 7. Rejection Criteria

Reject or quarantine a conversion result if any of the following hold:

1. Any conversion returns `None` for the net, BPMN, process tree, initial marking, or final marking when that artifact is required.
2. `pm4py.check_is_workflow_net(net)` returns false for an accepting net that is supposed to be a workflow net.
3. `pm4py.check_soundness(net, im, fm, ...)` reports unsoundness, deadlock, improper completion, or unbounded silent behavior.
4. The BPMN round-trip net admits `Release Change` before the verification loop has completed, e.g. `RAPLRelCIArc`.
5. The converted model rejects a required interleaving, such as `RPACIRelArc` or `RAPCLIRelArc`.
6. Optional Legal Review collapses to mandatory, or legal-skip traces are rejected.
7. The verification loop permits zero iterations, or repeated iterations occur without `Correct Defect` as a separator.
8. Archive Change is not final, occurs before Release Change, or a completed trace does not end in the exact final marking.
9. Activity labels collide or visible activities are hidden as if silent, destroying the ability to distinguish loop body, rework, optional legal, and final activities.
10. BPMN gateways are semantically inconsistent with the net, e.g. an exclusive join before Release Change instead of a synchronization join.
11. The bounded visible-trace comparison produces source-accepted traces missing from the round-trip net, or round-trip-only traces that violate the invariant table.
12. The process-tree intermediate is accepted despite a failed `convert_to_process_tree` call, a `None` tree, or evidence that block-structuring erased required interleavings.

# 8. Canonical Representation Recommendation

Canonical storage recommendation:

- **Authoritative model:** Store the source POWL as the normative representation, together with the invariant table, version metadata, and validated positive/negative witness traces. The POWL captures the partial-order, optional, and loop semantics without BPMN gateway interpretation.
- **Executable semantic reference:** Store the directly generated accepting Petri net `net_from_powl`, `im_from_powl`, `fm_from_powl` as a derived executable reference. It is not a replacement for the POWL source, but it is the preferred artifact for soundness, reachability, footprint, and bounded playout checks.
- **Stakeholder visualization:** Generate BPMN from the accepting Petri net and mark it clearly as a visualization/derivative. The BPMN should not be treated as authoritative unless a controlled BPMN-editing workflow with full round-trip validation is introduced.

Derivative artifacts and required evidence:

| Artifact | Status | Required validation evidence |
|---|---|---|
| Source POWL | authoritative | Versioned source, invariant table, positive/negative witnesses. |
| `net_from_powl` | derived semantic reference | Non-null markings, workflow-net check, soundness check, bounded trace exploration, witness audit. |
| `bpmn_from_net` | derivative visualization | Round-trip BPMNPetri conversion, trace/footprint comparison against `net_from_powl`, gateway and silent-flow annotations. |
| `tree_from_net` and `bpmn_from_tree` | optional diagnostic derivatives | Only if conversion succeeds; must pass same round-trip and witness checks. Otherwise record `conversion failed`. |
| Visualizations | illustrative | Must reference the authoritative model and validation report; layout must not be read as semantics. |

Process-tree intermediate recommendation: **do not allow the process-tree intermediate as canonical for this model.** It may be attempted for visualization only, and only if `pm4py.convert_to_process_tree(...)` succeeds and the resulting tree/BPMN passes the same bounded trace and witness validation. If it raises an exception, the correct audit outcome is `conversion failed`; it must not be suppressed or replaced by a hand-made tree.

Future edits: edit the authoritative POWL or the validated accepting Petri net under version control, regenerate all BPMN/tree visualizations, and rerun the invariant and round-trip tests. Do not edit the BPMN and silently round-trip it back as a new source model unless the BPMN is explicitly promoted with fresh validation evidence. Version the converter and PM4Py version because conversion behavior can change.

# 9. Residual Uncertainty

Even if all generated tests pass, the validation cannot establish the following:

1. **Full behavioral equivalence beyond the chosen bound:** Bounded visible-trace exploration and finite reachability comparisons cannot prove equivalence over unbounded loop iterations, unbounded silent firing, or state spaces beyond `max_states`.
2. **True concurrency preservation:** Trace equivalence and footprint comparison can show accepted interleavings, but they do not by themselves prove that the converted BPMN or Petri net models true concurrency rather than arbitrary interleaving in every relevant semantic framework.
3. **BPMN renderer/execution-engine semantics:** A BPMN diagram can be behaviorally acceptable as a converted net but be interpreted differently by a particular BPMN engine or by human stakeholders, especially around gateways, default flows, and loop markers.
4. **Business meaning of labels:** The validation checks label preservation and trace behavior, but it cannot prove that “Legal Review,” “Assess Risk,” or “Correct Defect” have the same organizational meaning after conversion.
5. **Correctness of the converter implementation itself:** Passing tests reduce risk but do not prove PM4Py’s converter is free of version-specific bugs or that it handles all silent-cycle or partial-order edge cases correctly.
6. **Exact initial/final marking correspondence across newly generated nets:** When BPMN round-trip regenerates place identities, equality by place name/key is evidence but not a canonical proof of marking correspondence.
7. **Absence of unmodeled compliance or temporal constraints:** The source POWL and invariant table do not capture external deadlines, authorization rules, or legal requirements that may not be expressible in the model.
