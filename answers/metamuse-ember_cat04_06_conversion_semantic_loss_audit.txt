# 1. Source-Semantics Baseline

The POWL model is the authoritative statement of intent. Its only silent transition is the skip branch of the optional legal step. The visible labels are abbreviated below as Reg = Register Change, Ass = Assess Risk, Prep = Prepare Evidence, Leg = Legal Review, Conf = Configure Trial, Insp = Inspect Trial, Corr = Correct Defect, Rel = Release Change, and Arc = Archive Change. Witnesses are visible traces after hiding the silent transition.

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| I01 | Register Change is first. | [Reg, Ass, Prep, Conf, Insp, Rel, Arc] | [Ass, Reg, Prep, Conf, Insp, Rel, Arc] | Yes |
| I02 | Assess Risk and Prepare Evidence are unordered after registration. | [Reg, Ass, Prep, Conf, Insp, Rel, Arc] and [Reg, Prep, Ass, Conf, Insp, Rel, Arc] | No single negative trace; either fixed order is refuted by the opposite positive trace | Yes |
| I03 | Legal Review, when present, occurs after Assess Risk and before Release Change. | [Reg, Ass, Leg, Prep, Conf, Insp, Rel, Arc]; [Reg, Ass, Prep, Conf, Leg, Insp, Rel, Arc] | [Reg, Leg, Ass, Prep, Conf, Insp, Rel, Arc]; [Reg, Ass, Prep, Conf, Insp, Rel, Leg, Arc] | Occurrence is observable; timing of the silent skip is not |
| I04 | Legal Review is optional and occurs at most once. | Completed traces both with and without Leg | [Reg, Ass, Leg, Leg, Prep, Conf, Insp, Rel, Arc] | Visible count is observable; the silent choice itself is not |
| I05 | Verification cannot start until both Assess Risk and Prepare Evidence are complete. | Conf occurs only after both Ass and Prep, in either order | [Reg, Ass, Conf, Insp, Rel, Arc] | Yes |
| I06 | Optional Legal Review and verification are otherwise unordered and may interleave. | Leg before Conf; Leg between Conf and Insp; Leg after Insp but before Rel | No single negative trace; forcing Leg before verification is refuted by Leg after Insp, and forcing it after is refuted by Leg before Conf | Interleavings are observable; physical simultaneity is not |
| I07 | In every verification iteration, Configure Trial precedes Inspect Trial. | Each iteration contains Conf before Insp; Leg may occur between them | [Reg, Ass, Prep, Insp, Conf, Rel, Arc] | Yes |
| I08 | The loop contains only the trial body and Correct Defect; Correct Defect separates repeated trials. | [Conf, Insp, Corr, Conf, Insp] as the verification segment | [Corr, Conf, Insp] as the verification segment | Yes |
| I09 | At least one complete verification iteration occurs, and Correct Defect is never the final loop activity before release. | At least one [Conf, Insp] before Rel; Corr only between iterations | [Reg, Ass, Prep, Rel, Arc]; [Reg, Ass, Prep, Conf, Insp, Corr, Rel, Arc] | Yes |
| I10 | Release Change waits for both the optional-legal branch and the verification loop. | Rel follows completion of both branches, with or without visible Leg | Rel before Conf and Insp; Rel before a later Leg | Visible predecessors are observable; completion of the silent skip is only inferred |
| I11 | Release Change precedes Archive Change, and Archive Change is the final visible activity. | [..., Rel, Arc] followed by termination | [..., Rel, Arc, Leg]; treating [..., Rel] as completed | Yes |
| I12 | Visible activity labels are distinct activity types; Conf, Insp, and Corr repeat only across loop iterations. | Each non-loop label occurs once; loop labels repeat only in the I08 pattern | Duplicate Reg, Leg, Rel, or Arc outside their permitted patterns | Yes |

# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| P1: POWL to accepting Petri net to BPMN | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)`; `pm4py.convert_to_petri_net(bpmn_from_net)` for round-trip testing | Uses the supported POWL-to-Petri path and the supported Petri-to-BPMN path; the Petri net can encode the partial order and synchronization directly | BPMN gateways and silent routing nodes may obscure token semantics; round-trip Petri structure may differ even when visible behavior is close | Any required conversion raises, a marking is missing, the net is not a sound workflow net, or the bounded trace comparison differs |
| P2: POWL to accepting Petri net to process tree to BPMN | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)` inside try/except; if successful, `pm4py.convert_to_bpmn(tree_from_net)`; then BPMN-to-Petri round trip | A process tree would be compact and may be easier to explain if it were faithful | The source contains a non-block-structured partial order, so the tree stage may raise an exception or impose an extra order. A returned tree does not prove that Legal Review remains unordered with verification | Petri-to-tree conversion raises, or a returned tree fails witness, soundness, footprint, or bounded-trace validation |
| P3: POWL to accepting Petri net only | `pm4py.convert_to_petri_net(source_powl)` plus workflow-net, soundness, footprint, reachability, and trace checks | Best baseline for executable semantics and validation; avoids BPMN interpretation risk | Less accessible to non-technical stakeholders | Missing marking, unsoundness, missing witness, or admitted negative witness |
| Rejected: direct POWL to BPMN | No such call is used | Would be shortest if it existed in the provided API | Would invent an unsupported conversion and bypass the Petri baseline | Not applicable; rejected because the task provides no direct POWL-to-BPMN API |

**Primary pipeline: P1.** P2 is an exploratory audit pipeline only. P3 supplies the baseline against which P1 and any P2 artifact are tested.

# 3. Conversion Code

Run this section and Section 5 in the same process. The code treats a missing net or marking as quarantine, not as a successful conversion.

```python
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(
    operator=Operator.XOR,
    children=[legal_review, skip_legal],
)

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[trial_body, correct_defect],
)

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[
        register,
        assess_risk,
        prepare_evidence,
        optional_legal,
        verification_loop,
        release_change,
        archive_change,
    ]
)

source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)


def _has_marking(marking):
    if marking is None:
        return False
    try:
        return len(marking) > 0
    except Exception:
        return False


def _soundness_bool(result):
    if isinstance(result, bool):
        return result
    if isinstance(result, dict):
        for key in ("is_sound", "sound"):
            if key in result:
                return bool(result[key])
    if isinstance(result, (tuple, list)) and result and isinstance(result[0], bool):
        return bool(result[0])
    return None


def _diagnose(name, net, im, fm):
    print(f"\n[diagnose] {name}")
    if net is None:
        print(" status: quarantined - net is None")
        return
    if not _has_marking(im) or not _has_marking(fm):
        print(f" status: quarantined - missing marking im={im!r} fm={fm!r}")
        return
    try:
        try:
            workflow_result = pm4py.check_is_workflow_net(net)
        except TypeError:
            workflow_result = pm4py.check_is_workflow_net(net, im, fm)
        print(f" workflow_net: {workflow_result!r}")
    except Exception as exc:
        print(f" workflow_net: not tested ({type(exc).__name__}: {exc})")
    try:
        soundness_result = pm4py.check_soundness(
            net, im, fm, print_diagnostics=True
        )
        print(
            " soundness: "
            f"{_soundness_bool(soundness_result)!r} "
            f"raw={soundness_result!r}"
        )
    except Exception as exc:
        print(f" soundness: not tested ({type(exc).__name__}: {exc})")


def _save_petri(name, net, im, fm, path):
    if net is None or not _has_marking(im) or not _has_marking(fm):
        print(f" save skipped for {name}: missing net or marking")
        return
    try:
        pm4py.save_vis_petri_net(net, im, fm, path)
        print(f" saved {path}")
    except Exception as exc:
        print(f" save failed for {path}: {type(exc).__name__}: {exc}")


def _save_bpmn(name, bpmn, path):
    if bpmn is None:
        print(f" save skipped for {name}: BPMN model is None")
        return
    try:
        pm4py.save_vis_bpmn(bpmn, path)
        print(f" saved {path}")
    except Exception as exc:
        print(f" save failed for {path}: {type(exc).__name__}: {exc}")


def _save_tree(name, tree, path):
    if tree is None:
        print(f" save skipped for {name}: process tree is None")
        return
    try:
        pm4py.save_vis_process_tree(tree, path)
        print(f" saved {path}")
    except Exception as exc:
        print(f" save failed for {path}: {type(exc).__name__}: {exc}")


"""Step 1: POWL to accepting Petri net."""

net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(
    source_powl
)
if (
    net_from_powl is None
    or not _has_marking(im_from_powl)
    or not _has_marking(fm_from_powl)
):
    raise ValueError(
        "POWL-to-Petri conversion returned a missing net or marking; "
        "quarantine all downstream artifacts"
    )
_diagnose("net_from_powl", net_from_powl, im_from_powl, fm_from_powl)
_save_petri(
    "net_from_powl",
    net_from_powl,
    im_from_powl,
    fm_from_powl,
    "02_net_from_powl.png",
)
try:
    pm4py.save_vis_powl(source_powl, "01_source_powl.png")
    print(" saved 01_source_powl.png")
except Exception as exc:
    print(f" save failed for 01_source_powl.png: {type(exc).__name__}: {exc}")

"""Step 2: primary pipeline, Petri net to BPMN."""

bpmn_from_net = None
try:
    bpmn_from_net = pm4py.convert_to_bpmn(
        net_from_powl, im_from_powl, fm_from_powl
    )
except Exception as exc:
    print(
        " conversion failed: P1 Petri-to-BPMN raised "
        f"{type(exc).__name__}: {exc}"
    )
_save_bpmn("bpmn_from_net", bpmn_from_net, "03_bpmn_from_net.png")

"""Step 3: exploratory process-tree intermediate. Failure here is informative."""

tree_from_net = None
try:
    tree_from_net = pm4py.convert_to_process_tree(
        net_from_powl, im_from_powl, fm_from_powl
    )
except Exception as exc:
    print(
        " conversion failed: P2 Petri-to-process-tree raised "
        f"{type(exc).__name__}: {exc}; no tree or BPMN-from-tree "
        "artifact is created"
    )

"""Step 4: BPMN from the tree only if the tree stage succeeded."""

bpmn_from_tree = None
if tree_from_net is not None:
    _save_tree("tree_from_net", tree_from_net, "04_tree_from_net.png")
    try:
        bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
    except Exception as exc:
        print(
            " conversion failed: process-tree-to-BPMN raised "
            f"{type(exc).__name__}: {exc}"
        )
    _save_bpmn("bpmn_from_tree", bpmn_from_tree, "05_bpmn_from_tree.png")
else:
    print(" process-tree intermediate unavailable; P2 stops before BPMN")

"""Step 5: convert every produced BPMN model back to an accepting Petri net."""

roundtripped_nets = {}


def _roundtrip_bpmn(name, bpmn, image_path):
    if bpmn is None:
        print(f" round trip skipped for {name}: BPMN model is None")
        return None
    try:
        rt_net, rt_im, rt_fm = pm4py.convert_to_petri_net(bpmn)
    except Exception as exc:
        print(
            f" conversion failed: BPMN-to-Petri round trip for {name} "
            f"raised {type(exc).__name__}: {exc}"
        )
        return None
    if rt_net is None or not _has_marking(rt_im) or not _has_marking(rt_fm):
        print(
            f" round trip quarantined for {name}: missing net or marking "
            f"im={rt_im!r} fm={rt_fm!r}"
        )
        return None
    _diagnose(name, rt_net, rt_im, rt_fm)
    _save_petri(name, rt_net, rt_im, rt_fm, image_path)
    return (rt_net, rt_im, rt_fm)


roundtripped_nets["bpmn_from_net"] = _roundtrip_bpmn(
    "net_from_bpmn_from_net",
    bpmn_from_net,
    "06_net_from_bpmn_from_net.png",
)
if bpmn_from_tree is not None:
    roundtripped_nets["bpmn_from_tree"] = _roundtrip_bpmn(
        "net_from_bpmn_from_tree",
        bpmn_from_tree,
        "07_net_from_bpmn_from_tree.png",
    )
else:
    roundtripped_nets["bpmn_from_tree"] = None

print("\nConversion artifacts produced or explicitly recorded as failed:")
print(f" net_from_powl: {net_from_powl is not None}")
print(f" bpmn_from_net: {bpmn_from_net is not None}")
print(f" tree_from_net: {tree_from_net is not None}")
print(f" bpmn_from_tree: {bpmn_from_tree is not None}")
print(f" roundtripped_nets keys: {sorted(roundtripped_nets)}")
```

# 4. Preservation and Loss Audit

The terms below are pre-execution assessments. `validated preserved` may be used only after the Section 5 checks pass on the actual generated artifacts.

| Source invariant | POWL to Petri | Petri to BPMN | Petri to Tree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| True concurrency of Assess Risk and Prepare Evidence, and of Legal Review and verification | expected preserved | approximated | conversion failed | approximated | The Petri net can encode independence with fork places. Visible traces record interleavings, not simultaneity. Footprints may indicate parallelism between adjacent visible activities but cannot prove physical overlap. |
| No edge between Optional Legal Review and verification | expected preserved | approximated | conversion failed | approximated | The source has no such edge. A BPMN layout or gateway grouping can visually suggest sequence or a shared fork-join scope. A faithful process tree is not expected because the partial order is non-block-structured; a returned tree would probably add Legal after Prepare or Legal before verification. |
| Silent optional behavior | expected preserved | ambiguous | conversion failed | ambiguous | The skip transition has label None in the Petri stage. In BPMN it may appear as an exclusive-gateway branch, an unnamed routing node, or may be difficult to distinguish from other silent transitions. After hiding tau, absence of Legal Review does not identify when or where the skip fired. |
| Binary loop semantics and minimum iteration count | expected preserved | approximated | conversion failed | approximated | The Petri stage should retain trial body as the loop body and Correct Defect as the redo branch. BPMN normally renders this as a backward flow rather than a loop operator, so entry, exit, and the prohibition on exiting after Correct Defect are visually ambiguous. |
| Synchronization before Release Change | expected preserved | approximated | conversion failed | approximated | Release requires completion of both the legal branch and verification. A BPMN parallel join can express synchronization, but identical parallel-gateway symbols are also used for the Assess and Prepare fork, creating scope ambiguity. |
| Register first, Configure before Inspect in each iteration, Release before Archive | expected preserved | expected preserved | conversion failed | expected preserved | These are direct visible precedence relations and are the most likely to survive as sequence flows. They still require witness and trace-set confirmation. |
| Activity-label uniqueness | expected preserved | ambiguous | conversion failed | ambiguous | The source has nine distinct visible labels. BPMN and round-trip Petri nets may add silent routing transitions sharing label None, so visible-label uniqueness can remain while transition-level uniqueness is lost. |
| Initial and final markings | expected preserved | ambiguous | conversion failed | ambiguous | The Petri conversion must return non-null initial and final markings. BPMN start and end events are not token markings. After BPMN-to-Petri conversion, exact final-marking equality is meaningful only within that round-tripped net; cross-net comparison must be by visible trace sets. |
| Gateway and routing-node ambiguity in BPMN visualization | not tested | ambiguous | conversion failed | ambiguous | There is no BPMN gateway at the POWL-to-Petri stage. In BPMN, parallel and exclusive gateways, silent nodes, and backward flows require annotation; the diagram alone may be misread. |

The expected P2 outcome is `conversion failed` for a faithful tree. If the installed PM4Py version instead returns a tree without raising, that tree must be reclassified as `approximated` and quarantined until Section 5 proves otherwise. The relevant partial order has the shape Assess before Legal and verification, and Prepare before verification, but no order between Legal and verification and no order between Assess and Prepare. That crossing structure is not a straightforward series-parallel block decomposition, so a tree can easily add an order that the source does not contain.

# 5. Round-Trip Validation Code

The comparison below is exhaustive only under the stated bound: visible traces of length at most 16, at most 2 Correct Defect occurrences, and at most 20 consecutive silent transitions before a visible transition. It is not exhaustive for unbounded loop repetitions or for behavior requiring more silent steps. Completion requires exact equality with the candidate net's own final marking, not merely reaching a marking that contains the final place.

```python

from pm4py.objects.petri_net.obj import Marking

MAX_VISIBLE_LENGTH = 16
MAX_CORRECT_DEFECT = 2
MAX_SILENT_PER_VISIBLE = 20
CORRECT_LABEL = "Correct Defect"

POSITIVE_WITNESSES = [
    ["Register Change", "Assess Risk", "Prepare Evidence",
     "Configure Trial", "Inspect Trial", "Release Change",
     "Archive Change"],

     "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Release Change", "Archive Change"],
    ["Register Change", "Assess Risk", "Prepare Evidence",

    ["Register Change", "Assess Risk", "Prepare Evidence",
     "Configure Trial", "Inspect Trial", "Correct Defect",

     "Legal Review", "Configure Trial", "Inspect Trial",
     "Correct Defect", "Configure Trial", "Inspect Trial",

     "Inspect Trial", "Configure Trial", "Release Change",

    ["Register Change", "Assess Risk", "Prepare Evidence",
     "Correct Defect", "Configure Trial", "Inspect Trial",

    ["Register Change", "Legal Review", "Assess Risk",
     "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Release Change", "Archive Change"],
    ["Register Change", "Assess Risk", "Prepare Evidence",
     "Configure Trial", "Inspect Trial", "Release Change",
     "Archive Change", "Legal Review"],
    ["Assess Risk", "Register Change", "Prepare Evidence",
     "Configure Trial", "Inspect Trial", "Release Change",
     "Archive Change"],
    ["Register Change", "Assess Risk", "Prepare Evidence",
     "Configure Trial", "Inspect Trial", "Release Change"],
    ["Register Change", "Assess Risk", "Legal Review",
     "Legal Review", "Prepare Evidence", "Configure Trial",
     "Inspect Trial", "Release Change", "Archive Change"],
]


def _marking_key(marking):
    if marking is None:
        return None
    try:
        return frozenset(
            (place, count) for place, count in marking.items() if count
        )
    except Exception:
        return None


def _has_marking(marking):
    if marking is None:
        return False
    try:
        return len(marking) > 0
    except Exception:
        return False


def _fire_transition(net, marking, transition):
    counts = dict(_marking_key(marking) or [])
    try:
        in_places = transition.in_places
        out_places = transition.out_places
    except Exception:
        return None
    for place in in_places:
        if counts.get(place, 0) < 1:
            return None
        counts[place] -= 1
        if counts[place] == 0:
            del counts[place]
    for place in out_places:
        counts[place] = counts.get(place, 0) + 1
    new_marking = Marking()
    for place, count in counts.items():
        new_marking[place] = count
    return new_marking


def _enabled_transitions(net, marking):
    try:
        enabled = pm4py.get_enabled_transitions(net, marking)
    except Exception as exc:
        print(
            " get_enabled_transitions failed: "
            f"{type(exc).__name__}: {exc}"
        )
        return []
    return list(enabled or [])


def _explore_completed_visible_traces(
    net,
    im,
    fm,
    max_visible=MAX_VISIBLE_LENGTH,
    max_correct=MAX_CORRECT_DEFECT,
    max_silent=MAX_SILENT_PER_VISIBLE,
):
    completed = set()
    if net is None or not _has_marking(im) or not _has_marking(fm):
        return completed
    fm_key = _marking_key(fm)
    stack = [(im, (), 0)]
    visited = {(_marking_key(im), (), 0)}
    while stack:
        marking, visible, silent_since = stack.pop()
        if visible and _marking_key(marking) == fm_key:
            completed.add(visible)
        for transition in _enabled_transitions(net, marking):
            label = getattr(transition, "label", None)
            if label is None:
                if silent_since >= max_silent:
                    continue
                new_visible = visible
                new_silent = silent_since + 1
            else:
                if len(visible) >= max_visible:
                    continue
                if (
                    label == CORRECT_LABEL
                    and visible.count(CORRECT_LABEL) >= max_correct
                ):
                    continue
                new_visible = visible + (label,)
                new_silent = 0
            new_marking = _fire_transition(net, marking, transition)
            if new_marking is None:
                continue
            state = (_marking_key(new_marking), new_visible, new_silent)
            if state in visited:
                continue
            visited.add(state)
            stack.append((new_marking, new_visible, new_silent))
    return completed


def _soundness_bool(result):
    if isinstance(result, bool):
        return result
    if isinstance(result, dict):
        for key in ("is_sound", "sound"):
            if key in result:
                return bool(result[key])
    if isinstance(result, (tuple, list)) and result and isinstance(result[0], bool):
        return bool(result[0])
    return None


def _footprint_signature(footprint):
    if isinstance(footprint, dict):
        return repr(sorted(footprint.items(), key=lambda item: repr(item)))
    for attribute in ("processes", "footprint", "relations", "footprints"):
        if hasattr(footprint, attribute):
            return repr(getattr(footprint, attribute))
    return repr(footprint)


def _diagnose_net(name, net, im, fm):
    info = {"name": name}
    if net is None or not _has_marking(im) or not _has_marking(fm):
        info["status"] = "not tested - missing net or marking"
        return info
    info["status"] = "diagnosed"
    try:
        try:
            info["workflow_net"] = pm4py.check_is_workflow_net(net)
        except TypeError:
            info["workflow_net"] = pm4py.check_is_workflow_net(net, im, fm)
    except Exception as exc:
        info["workflow_net"] = (
            f"not tested ({type(exc).__name__}: {exc})"
        )
    try:
        soundness_result = pm4py.check_soundness(
            net, im, fm, print_diagnostics=True
        )
        info["soundness"] = _soundness_bool(soundness_result)
        info["soundness_raw"] = repr(soundness_result)
    except Exception as exc:
        info["soundness"] = None
        info["soundness_raw"] = (
            f"not tested ({type(exc).__name__}: {exc})"
        )
    try:
        footprint = pm4py.discover_footprints(net, im, fm)
        info["footprint_signature"] = _footprint_signature(footprint)
    except Exception as exc:
        info["footprint_signature"] = (
            f"not tested ({type(exc).__name__}: {exc})"
        )
    try:
        rg_result = pm4py.convert_to_reachability_graph(net, im, fm)
        rg = (
            rg_result[0]
            if isinstance(rg_result, (tuple, list)) and rg_result
            else rg_result
        )
        info["reachability_graph"] = (
            f"created as diagnostic only; type={type(rg).__name__}; "
            "not compared across nets because places may differ"
        )
    except Exception as exc:
        info["reachability_graph"] = (
            f"not tested ({type(exc).__name__}: {exc})"
        )
    return info


def _try_playout_trace(name, net, im, fm, trace):
    playout_trace = getattr(pm4py, "playout_trace", None)
    if not callable(playout_trace):
        return "not tested - pm4py.playout_trace is not available"
    try:
        result = playout_trace(trace, net, im, fm)
        return (
            f"playout_trace returned {type(result).__name__}; "
            "return shape intentionally not assumed"
        )
    except Exception as exc:
        return (
            f"playout_trace failed ({type(exc).__name__}: {exc}); "
            "diagnostic only"
        )

def _compare_candidate(name, net, im, fm, source_completed, source_footprint):
    info = _diagnose_net(name, net, im, fm)
    if info.get("status") != "diagnosed":
        info["traces_equal_under_bound"] = None
        info["only_in_source"] = set(source_completed)
        info["only_in_candidate"] = set()
        info["positive_missing"] = [tuple(t) for t in POSITIVE_WITNESSES]
        info["negative_admitted"] = []
        return info
    completed = _explore_completed_visible_traces(net, im, fm)
    info["completed_count_under_bound"] = len(completed)
    info["traces_equal_under_bound"] = completed == source_completed
    info["only_in_source"] = source_completed - completed
    info["only_in_candidate"] = completed - source_completed
    info["positive_missing"] = [
        tuple(trace)
        for trace in POSITIVE_WITNESSES
        if tuple(trace) not in completed
    ]
    info["negative_admitted"] = [
        tuple(trace)
        for trace in NEGATIVE_WITNESSES
        if tuple(trace) in completed
    ]
    info["footprint_signature_equal"] = (
        info.get("footprint_signature") == source_footprint
    )
    info["trace_playout"] = [
        _try_playout_trace(name, net, im, fm, trace)
        for trace in POSITIVE_WITNESSES[:2]
    ]
    info["model_playout"] = _try_model_playout(name, net, im, fm)
    return info
```

# 6. Visual-Semantics Review

A BPMN image can be readable and still be semantically misleading.

- **Parallel gateways:** The same symbol is used for token splitting and token joining. In the generated model, a parallel gateway after Register Change may be read as opening a single global parallel region, whereas the source has two different synchronization scopes: Assess Risk and Prepare Evidence converge only for verification, while Optional Legal Review and verification converge only for Release Change. The diagram must label which tokens each join actually waits for.
- **Exclusive gateways:** An exclusive gateway may represent the optional Legal Review choice, but PM4Py may also introduce exclusive routing for silent Petri transitions that are not business decisions. A stakeholder may therefore invent a decision that does not exist in the source or miss the fact that the skip branch is silent.
- **Loop visualization:** BPMN has no direct binary-loop operator in this rendering. The loop will appear as a backward sequence flow from Correct Defect toward Configure Trial, possibly through merging gateways. That can be misread as an optional jump that permits exit after Correct Defect, or as a loop that can be skipped entirely. The entry point, the requirement of at least one trial, and the rule that exit occurs only after Inspect Trial must be annotated explicitly.
- **Silent routing nodes:** Unnamed tasks, events, or gateway branches may be mistaken for real activities or deleted during stakeholder editing. Conversely, a visible Legal Review task may be treated as mandatory if the silent skip branch is visually weak.
- **Layout ordering:** Graph layout places nodes above, below, or left of one another for readability. Vertical position, edge length, and crossing edges have no process semantics. In particular, placing Assess Risk above Prepare Evidence, or Legal Review near verification, must not be read as sequence. Only directed sequence flows and gateway token rules carry meaning, and even those require the annotations below.

Recommended annotations, kept in a sidecar document if the generated BPMN cannot carry them without changing the model:

1. A banner stating that the BPMN is a derivative visualization and that the POWL/Petri source is authoritative.
2. Invariant IDs I01 to I12 placed beside the relevant subgraph.
3. Gateway labels stating the exact split or join scope, for example which incoming branches a join waits for.
4. A loop annotation at entry and exit: entry requires Assess Risk and Prepare Evidence; at least one trial; Correct Defect is a redo separator, never an exit.
5. A legend stating that unlabeled routing nodes are silent, that the Legal Review skip is invisible in visible traces, and that layout position has no semantics.
6. The positive and negative witness traces displayed with the diagram.
7. A warning not to edit the rendered BPMN and present the edit as the same converted model.

# 7. Rejection Criteria

1. **Technical conversion failure:** Reject or quarantine any primary-pipeline artifact if a required conversion raises, returns None, or returns a missing initial or final marking. A failed P2 tree stage is acceptable as an audit result, but no P2 BPMN may be claimed from it.
2. **Unsoundness or non-workflow structure:** Reject a net if `check_is_workflow_net` is false, if `check_soundness` is false or cannot be interpreted as true, or if diagnostics show deadlocks, unreachable completion, or tokens left behind.
3. **Bounded trace-language mismatch:** Reject if the source and round-tripped completed-trace sets differ in either direction under the Section 5 bound, regardless of whether the BPMN file opens or renders.
4. **Missing required interleaving:** Reject if either Assess-Prepare order, Legal before Prepare, Legal between Configure and Inspect, or Legal after Inspect disappears. Loss of an interleaving is a semantic change even if one representative trace still works.
5. **Release before verification:** Reject if any completed trace reaches Release Change before at least one complete Configure Trial and Inspect Trial, or if Release is admitted before a later Legal Review.
6. **Loop-scope or minimum-iteration failure:** Reject if zero iterations can reach Release, if Correct Defect can occur first, if Correct Defect can be followed directly by Release, or if a second iteration within the bound is lost.
7. **Collapse of optional behavior:** Reject if Legal Review becomes mandatory, impossible, duplicated, or allowed before Assess Risk or after Release Change. A trace without Legal Review must remain possible, and a trace with exactly one Legal Review must remain possible.
8. **Failed exact-final-marking test:** Reject if a trace ending at Release Change, or any other non-final marking, is classified as completed. Completion requires exact equality with that net's own final marking.
9. **Label or silent-structure corruption:** Reject if the visible-label set changes, if a visible activity is renamed into ambiguity, or if silent routing is converted into a visible business task. Extra silent transitions require investigation even when visible traces match.
10. **Unvalidated process-tree derivative:** Quarantine any tree or BPMN-from-tree artifact that was produced by an approximate tree conversion but has not passed the same soundness, witness, and bounded-trace checks. Visual neatness is not evidence.

# 8. Canonical Representation Recommendation

- **Authoritative intent:** `source_powl`, stored as version-controlled model definition, is the authoritative statement of the controlled technical change.
- **Canonical executable semantics:** `net_from_powl` with its initial and final markings is the canonical executable representation for analysis and validation. If the Petri net and POWL ever disagree, the POWL wins and the net must be regenerated and revalidated.
- **Derivative artifacts:** BPMN models, images, any process tree, and round-tripped Petri nets are derivatives. They must never be edited and then treated as the source of the next generation.
- **Required validation evidence per derivative:** conversion script and PM4Py version; generated filenames; workflow-net and soundness results; bounded trace-set comparison and difference sets; positive and negative witness results; footprint diagnostic; reachability-graph status; and an explicit statement of the bound used.
- **Process-tree intermediate:** Allow it only as a quarantined diagnostic. Because the source partial order is not faithfully block-structured, a process tree must not be a production intermediate and must not become canonical. If P2 returns a tree, it remains suspect until it passes the full Section 5 comparison, and even then it should not replace the POWL/Petri canonical pair.
- **Stakeholder visualization:** Use the P1 BPMN, accompanied by the annotations in Section 6, as the presentation model. It is separate from the canonical model.
- **Avoiding round-trip drift:** Use a one-way generation chain from POWL to Petri to BPMN. Round-trip nets are test artifacts only; never feed a round-tripped net back into storage or regeneration. Future edits should be made only in the POWL, followed by complete regeneration and a fresh Section 5 comparison. If stakeholders must edit BPMN, that edited BPMN is a new source requiring its own conversion and validation, not a silent update to the canonical model.

# 9. Residual Uncertainty

1. **Unbounded behavior:** Passing the bounded exploration does not prove equivalence for traces longer than 16, for more than 2 Correct Defect occurrences, or for executions requiring long silent chains. It also does not prove fairness or termination when an executor chooses to repeat the loop indefinitely.
2. **True concurrency and timing:** Visible traces can establish possible interleavings and precedence, but they cannot establish that activities physically overlap, use the same resources, or satisfy timing, cost, role, or data constraints that are absent from the source model.
3. **Silent-choice observability:** Even with matching visible traces, validation cannot prove exactly when the silent legal skip fired, nor can it distinguish all internal silent-routing structures that collapse to the same visible language.
4. **Global language equivalence:** Footprint equality is local, reachability-graph creation is diagnostic, and bounded trace equality is not full language equality. Different place structures can also make direct marking or reachability-graph comparison meaningless across nets.
5. **Execution-engine interpretation:** A BPMN file that round-trips to a matching Petri trace set under the bound may still be interpreted differently by a BPMN execution engine, especially around gateway synchronization, event semantics, and compensation or exception behavior not represented in the POWL source.
