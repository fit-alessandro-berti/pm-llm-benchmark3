# 1. Assumptions and Interpretation

1. **Activity abstraction.** Each activity is one event recorded at completion. "Y may start only after X is complete" therefore becomes "the X event precedes the Y event". Start times are not observed.
2. **Risk route.** Risk is an exclusive choice made after *Analyze Root Cause*. It is modelled as `XOR(Supervisor Review, PAR(Quality Review, Regulatory Review))`. The data condition is not represented, so the choice is non-deterministic. Mixed routes are excluded. In the high-risk branch both reviews are mandatory and unordered.
3. **Optional supplier consultation.** It is modelled as `XOR(Consult Supplier, )`, so it occurs 0 or 1 times.
   - The  branch stands for "not selected".
   - A trace without the activity is compatible with "not selected". The model cannot detect a case where the supplier was needed but skipped, because that depends on data.
   - If the activity occurs, it comes after *Analyze Root Cause* and before *Release Material*.
4. **Passing inspection.** There is no pass/fail label. Trial work is `LOOP(do = SEQ(Execute Trial, Inspect Trial), redo = Adjust Parameters)`.
   - An *Inspect Trial* followed by *Adjust Parameters* is interpreted as a failure.
   - The last *Inspect Trial* before the loop exit is interpreted as the pass.
   - *Adjust Parameters* is always followed by a new *Execute Trial* and *Inspect Trial*. It is never the last trial event.
   - Only complete traces are considered.
5. **Duplicate visible labels.**
   - Process tree: permitted, as bounded duplication of subtrees.
   - POWL: not used. Every visible label appears exactly once.
6. **Process-tree approximation policy.** The dependencies contain an induced N-shaped poset, for example CM<ET, ARC<ET, ARC<Approval, with CM not before Approval. It cannot be expressed as a series-parallel block without duplication.
   - The policy is *conservative under-approximation via bounded duplication*.
   - The route and supplier blocks are each placed either wholly **early** (before the first *Execute Trial*) or wholly **late** (after PV and DCA are both complete, in parallel with the trial loop). This gives four variants.
   - The tree is intended never to admit a behaviour that the intent forbids. It drops some allowed behaviour, described in Section 3.
7. **"May overlap".** It is interpreted as absence of an ordering constraint between completion events, which yields all interleavings. Process-tree `PARALLEL` and POWL unordered nodes both give interleaving semantics. Durations and start/complete lifecycle pairs are not modelled.
8. **Multiplicity.** RD, CM, ARC, PV, DCA, RM and AC occur exactly once. The route activities occur exactly once in the chosen branch. CS occurs at most once. The trial activities occur only within the loop.
9. **Unordered pairs.** Any pair with no ordering constraint in the narrative is left unordered. For example, approvals may complete before or after PV, DCA or the trial.

```text
V2 = ->( PRE(ROUTE),        +( TRIAL, 'Consult Supplier') )  # route early, supplier late
V3 = ->( PRE(SUPP?),        +( TRIAL, ROUTE ) )              # route late, supplier early/absent
V4 = ->( PRE(),             +( TRIAL, ROUTE, 'Consult Supplier') ) # both late
```

**Mapping to the narrative.**
- The outer sequence enforces D1 and D19.
- `PRE` is the parallel block of CMPV and ARCDCA. It gives D2, D3 and D4, and PV and DCA are unordered (D15).
- "Early" items sit inside the ARC branch after ARC, so D5 and D9 hold, and they can overlap CM, PV and DCA.
- The sequence `PRE ; TRIAL` gives the join of PV and DCA before the first ET (D10, D11).
- In V2–V4 the "late" items sit in a `PARALLEL` with `TRIAL`. They are only reachable after `PRE` is complete, so they follow ARC, and they overlap the trial (D13, D14).
- The loop is `*(do, redo)`, which gives ET IT (AP ET IT)*. There is no AP after the last IT (D12).
- The outer `SEQUENCE` places RM after the whole variant block, which includes the trial, route and supplier (D16–D18).
- V1 and V3 use `SUPP?`, so "not selected" lives there. V2 and V4 have a mandatory CS, so the no-supplier case is not duplicated.

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

def leaf(label):
    return ProcessTree(label=label)            # visible leaf

def tau():
    return ProcessTree()                       # silent leaf (operator=None, label=None)

def node(operator, children):
    n = ProcessTree(operator=operator)
    for c in children:                         # explicit parent/child handling
        c.parent = n
        n.children.append(c)
    return n

# Factories: every call returns FRESH nodes, so no node is ever shared between parents
def route():
    return node(Operator.XOR, [
        leaf("Supervisor Review"),
        node(Operator.PARALLEL, [leaf("Quality Review"), leaf("Regulatory Review")])])

def supp_optional():
    return node(Operator.XOR, [leaf("Consult Supplier"), tau()])

def supp_mandatory():
    return leaf("Consult Supplier")

def trial():
    return node(Operator.LOOP, [
        node(Operator.SEQUENCE, [leaf("Execute Trial"), leaf("Inspect Trial")]),  # do
        leaf("Adjust Parameters")])                                               # redo

def pre(early):
    """CM->PV || ARC->(DCA || early items)"""
    after_arc = [leaf("Design Corrective Action")] + early
    arc_part = node(Operator.SEQUENCE, [
        leaf("Analyze Root Cause"),
        after_arc[0] if len(after_arc) == 1 else node(Operator.PARALLEL, after_arc)])
    cm_part = node(Operator.SEQUENCE, [leaf("Contain Material"), leaf("Plan Verification")])
    return node(Operator.PARALLEL, [cm_part, arc_part])

def post(late):
    """trial loop || late items (or the bare loop if no late items)"""
    return trial() if not late else node(Operator.PARALLEL, [trial()] + late)

def variant(early, late):
    return node(Operator.SEQUENCE, [pre(early), post(late)])

v1 = variant([route(), supp_optional()], [])
v2 = variant([route()],                  [supp_mandatory()])
v3 = variant([supp_optional()],          [route()])
v4 = variant([],                         [route(), supp_mandatory()])

tree = node(Operator.SEQUENCE, [
    leaf("Register Deviation"),
    node(Operator.XOR, [v1, v2, v3, v4]),
    leaf("Release Material"),
    leaf("Archive Case")])
```

**What the tree cannot represent exactly.**
1. **Cross-branch synchronization (approximation by duplication).** Approvals and supplier consultation depend on ARC only, but they may overlap PV, DCA and the trial. Together with the join of PV and DCA before ET, this forms an N-shape that has no block-structured tree. The approximation is the four-variant duplication. The visible labels CM, ARC, PV, DCA, ET, IT, AP, SR, QR, RR and CS each occur four times.
2. **Under-approximation (lost behaviour).**
   - An "early" route completes wholly before the first ET. A "late" route starts wholly after PV and DCA are both complete.
   - A high-risk case in which one review is done before the PV/DCA gate and the other after the first ET is therefore *rejected*, although the intent allows it. Trace T4 in Section 5 is an example.
   - Formally, the tree rejects a trace exactly when one of {QR, RR} precedes the completion of both PV and DCA and the other follows the first ET.
   - SR and CS are single events, so their placement is lossless.
   - Exactness could be recovered by placing QR and RR independently, which gives about 12 variants with 12 copies of the loop. I judged that unreasonable, because it is hard to read and hard to maintain.
3. **Silent choices and data.** Risk, supplier selection and inspection outcome are silent non-deterministic choices. The tree cannot check them against case data.
4. **Concurrency.** The tree has interleaving semantics only, so it cannot distinguish "true overlap" from "either order".
5. **Ambiguity.** Some traces can be derived from several variants, for example CS between the gate and ET, or SR after the gate. The language is unaffected, but derivations are not unique, which matters for alignments and for frequency analysis.
6. **Over-approximation.** I believe there is none, but this is to be checked with the tests in Section 7, not assumed.

# 4. PM4Py POWL Model

```text
PO0 = { RD, CM, ARC, PV, DCA, ROUTE, SUPP, TRIAL, RM, AC }
ROUTE = X( SR, PO{ QR, RR } )              # PO{QR,RR} has no edges
SUPP  = X( CS, tau )
TRIAL = *( PO{ ET -> IT }, AP )
Edges:  RD->CM, RD->ARC, CM->PV, ARC->DCA, ARC->ROUTE, ARC->SUPP,
        PV->TRIAL, DCA->TRIAL, TRIAL->RM, ROUTE->RM, SUPP->RM, RM->AC
```

```python
from pm4py.objects.process_tree.obj import Operator
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition)

rd  = Transition(label="Register Deviation")
cm  = Transition(label="Contain Material")
arc = Transition(label="Analyze Root Cause")
pv  = Transition(label="Plan Verification")
dca = Transition(label="Design Corrective Action")
sr  = Transition(label="Supervisor Review")
qr  = Transition(label="Quality Review")
rr  = Transition(label="Regulatory Review")
cs  = Transition(label="Consult Supplier")
et  = Transition(label="Execute Trial")
it  = Transition(label="Inspect Trial")
ap  = Transition(label="Adjust Parameters")
rm  = Transition(label="Release Material")
ac  = Transition(label="Archive Case")

# Risk route: low = SR; high = QR and RR (no edge => concurrent, either order)
high  = StrictPartialOrder(nodes=[qr, rr])
route = OperatorPOWL(operator=Operator.XOR, children=[sr, high])

# Optional supplier consultation
supplier = OperatorPOWL(operator=Operator.XOR, children=[cs, SilentTransition()])

# Trial cycle: (ET -> IT) then optionally (AP, ET -> IT) again, until pass
attempt = StrictPartialOrder(nodes=[et, it])
attempt.order.add_edge(et, it)
trial = OperatorPOWL(operator=Operator.LOOP, children=[attempt, ap])

powl = StrictPartialOrder(nodes=[rd, cm, arc, pv, dca, route, supplier, trial, rm, ac])
o = powl.order
o.add_edge(rd, cm)
o.add_edge(rd, arc)
o.add_edge(cm, pv)
o.add_edge(arc, dca)
o.add_edge(arc, route)
o.add_edge(arc, supplier)
o.add_edge(pv, trial)
o.add_edge(dca, trial)
o.add_edge(trial, rm)
o.add_edge(route, rm)
o.add_edge(supplier, rm)
o.add_edge(rm, ac)
```

**Why the unconnected pairs may stay concurrent.**
- **CM  ARC:** independent work streams (D2).
- **CM, PV  ARC, DCA:** PV needs only CM, and DCA needs only ARC. Any edge between the two chains would add an unrequested constraint.
- **PV  DCA:** both feed the trial, and neither depends on the other.
- **ROUTE  CM, PV, DCA, TRIAL:** approvals depend only on ARC, and the narrative explicitly allows them to overlap the trial. Because the loop is a single node in the partial order, route events may interleave with ET, IT and AP.
- **SUPP  CM, PV, DCA, ROUTE, TRIAL:** CS may overlap all of them. It only has to follow ARC and precede RM.
- **QR  RR:** either completion order is allowed.

RD reaches every other node through CM or ARC. RM is reached from every node other than AC, so RD is first and AC is last without extra edges.

**Why T4 exposes the tree approximation.**
- The prefix RD ARC QR is accepted.
- In V1 and V2 the route is "early", so both QR and RR must precede ET. The first ET at position 7 is rejected because RR is still pending.
- In V3 and V4 the route is "late", so QR must follow both PV and DCA. QR at position 3 precedes PV and is rejected.
- **No variant accepts the trace.** The earliest event that no variant accepts is ET at position 7.
- The POWL accepts it, because only ARCQR and ARCRR are required, and both hold.

| Requirement | Intended semantics | Process tree | POWL | Overconstraint or underconstraint | Business consequence |
|---|---|---|---|---|---|
| Two initial work streams | CM  ARC after RD | `PAR(SEQ(CM,PV), SEQ(ARC,…))`, exact (interleavings) | Unordered CM and ARC after RD, exact | None | Parallel containment and analysis are visible |
| Split dependencies into planning/design | PV needs CM only; DCA needs ARC only | Chains are separate inside `PRE`, exact | Edges CMPV and ARCDCA, exact | None | An early PV before ARC is allowed, as intended |
| Risk route | Exactly one of SR, or QR+RR (concurrent), after ARC | XOR inside 4 variants, exact for SR and for high risk if both reviews sit on the same side of the gate | XOR node with PO{QR,RR}, exact | Tree: under-constrains nothing but drops T4-like traces (under-approximation) | The tree flags legal high-risk parallel reviews as deviations |
| Overlap of approval and trial | Route  Trial, both after ARC | Only via "late" variants (start after PV and DCA) or "early" (finish before ET). Partial straddling of QR/RR is lost | No edge between ROUTE and TRIAL, exact | Tree: overconstrained | A tree-based conformance check yields false alarms |
| Optional supplier consultation | 0 or 1 CS, after ARC, before RM, overlapping | `XOR(CS, )` early, or mandatory CS late, exact for CS | `XOR(CS, )` unordered, ARCSUPP and SUPPRM, exact | Neither model links CS to case data | A missed but required supplier consultation cannot be detected |

# 7. Preferred Representation and Validation Plan

**Canonical representation: the POWL model.**
- It matches the dependency table one-to-one, with one node per activity and one edge per dependency.
- It needs no duplicated labels and has no known under- or over-approximation.
- The process tree is retained as a derived, conservative artifact for tools that require block-structured input. It admits nothing forbidden but rejects the T4-type traces.

**Validation plan.** The code below runs the checks. It assumes a pm4py version with POWL support. Parameter names and return shapes vary across versions (see the limitations below).

```python
import pm4py
from collections import Counter
from pm4py.objects.petri_net import semantics

# --- 1. Conversion to accepting Petri nets ---
tnet, tim, tfm = pm4py.convert_to_petri_net(tree)
pnet, pim, pfm = pm4py.convert_to_petri_net(powl)

# --- 2. Soundness of the converted nets ---
print(pm4py.check_soundness(tnet, tim, tfm, print_diagnostics=True))
print(pm4py.check_soundness(pnet, pim, pfm, print_diagnostics=True))

# --- 3. Independent oracle for the intended semantics (not derived from either model) ---
FULL = {"RD":"Register Deviation","CM":"Contain Material","ARC":"Analyze Root Cause",
        "PV":"Plan Verification","DCA":"Design Corrective Action","SR":"Supervisor Review",
        "QR":"Quality Review","RR":"Regulatory Review","CS":"Consult Supplier",
        "ET":"Execute Trial","IT":"Inspect Trial","AP":"Adjust Parameters",
        "RM":"Release Material","AC":"Archive Case"}
SHORT = {v: k for k, v in FULL.items()}

def oracle(t):                      # t: list of abbreviations
    cnt = t.count
    if any(cnt(a) != 1 for a in ["RD","CM","ARC","PV","DCA","RM","AC"]) or cnt("CS") > 1:
        return False
    low  = cnt("SR") == 1 and cnt("QR") == 0 and cnt("RR") == 0
    high = cnt("SR") == 0 and cnt("QR") == 1 and cnt("RR") == 1
    if not (low or high) or t[0] != "RD" or t[-1] != "AC":
        return False
    p = {a: t.index(a) for a in set(t)}
    route = ["SR"] if low else ["QR", "RR"]
    supp = ["CS"] if "CS" in p else []
    if not (p["CM"] < p["PV"] and p["ARC"] < p["DCA"]): return False
    if any(p[a] < p["ARC"] for a in route + supp): return False
    tr = [a for a in t if a in ("ET", "IT", "AP")]
    if len(tr) % 3 != 2 or tr[:2] != ["ET","IT"] or tr[2:] != ["AP","ET","IT"] * ((len(tr)-2)//3):
        return False
    first_et = t.index("ET"); last_it = len(t) - 1 - t[::-1].index("IT")
    if not (p["PV"] < first_et and p["DCA"] < first_et): return False
    return all(p[a] < p["RM"] for a in route + supp) and last_it < p["RM"] < p["AC"]

# --- 4. Token-game membership test with silent closure and earliest-failure index ---
def silent_closure(net, markings):
    seen, stack = set(markings), list(markings)
    while stack:
        m = stack.pop()
        for t in semantics.enabled_transitions(net, m):
            if t.label is None:
                m2 = semantics.execute(t, net, m)
                if m2 not in seen:
                    seen.add(m2); stack.append(m2)
    return seen

def accepts(net, im, fm, trace):    # returns (accepted, index of first unaccepted event or None)
    cur = silent_closure(net, {im})
    for i, a in enumerate(trace):
        nxt = set()
        for m in cur:
            for t in semantics.enabled_transitions(net, m):
                if t.label == FULL[a]:
                    nxt.add(semantics.execute(t, net, m))
        cur = silent_closure(net, nxt)
        if not cur:
            return False, i
    return (fm in cur), (None if fm in cur else len(trace))

# --- 5. Explicit positive and negative tests ---
S = lambda s: s.split()
tests = {
 "T1": (S("RD ARC CM DCA PV ET SR IT RM AC"), True, True),
 "T2": (S("RD CM ARC CS DCA PV QR ET RR IT RM AC"), True, True),
 "T3": (S("RD CM ARC DCA PV ET IT AP ET IT SR RM AC"), True, True),
 "T4": (S("RD ARC QR CM DCA PV ET RR IT RM AC"), False, True),   # tree approximation
 "T5": (S("RD ARC CM PV DCA ET IT QR RR CS RM AC"), True, True),
 "F1": (S("RD ARC CM DCA ET PV IT SR RM AC"), False, False),
 "F2": (S("RD CM ARC PV DCA ET IT SR RM CS AC"), False, False),
 "F3": (S("RD CM ARC PV DCA ET IT AP SR RM AC"), False, False),
 "D1": (S("RD ARC CM PV DCA ET IT SR SR RM AC"), False, False),  # duplicate-copy check
}
for name, (tr, exp_tree, exp_powl) in tests.items():
    assert oracle(tr) == exp_powl, name          # oracle agrees with the intended verdict
    assert accepts(tnet, tim, tfm, tr)[0] == exp_tree, name
    assert accepts(pnet, pim, pfm, tr)[0] == exp_powl, name
    print(name, accepts(tnet, tim, tfm, tr), accepts(pnet, pim, pfm, tr))

# --- 6. Sampled playout ---
def sample(net, im, fm, n=300):
    # Parameter names differ between pm4py versions; adjust if needed. Truncated or non-final traces are filtered out.
    log = pm4py.play_out(net, im, fm, parameters={"num_traces": n, "max_trace_length": 80})
    return [[SHORT[e["concept:name"]] for e in tr] for tr in log]

tree_traces = sample(tnet, tim, tfm)
powl_traces = sample(pnet, pim, pfm)
assert all(oracle(t) for t in tree_traces)        # tree is a subset of the intent (no over-approximation on the sample)
assert all(oracle(t) for t in powl_traces)        # POWL sound w.r.t. the oracle on the sample
assert all(accepts(pnet, pim, pfm, t)[0] for t in tree_traces)   # tree language within POWL language
gap = [t for t in powl_traces if not accepts(tnet, tim, tfm, t)[0]]
print("POWL playouts rejected by the tree:", len(gap), "of", len(powl_traces))

# --- 7. Silent-behaviour and duplicate-label checks ---
print(Counter(t.label for t in tnet.transitions if t.label))   # expect 4 copies of most labels
print(Counter(t.label for t in pnet.transitions if t.label))   # expect exactly 1 copy of every label
for t in tree_traces + powl_traces:
    assert t.count("CS") <= 1 and t.count("SR") + t.count("QR") in (1, 2)
    if "CS" in t: assert t.index("CS") < t.index("RM")         # the tau branch of the supplier XOR cannot be undone by a late CS
```

Additional checks to run:
- Assert that every silent transition in the POWL net belongs to the supplier XOR or to structural split/join nodes.
- For POWL completeness, generate random linearizations of the dependency poset with a random number of trial iterations and confirm that all are accepted.

**Limitations of the validation plan.**
- Playout is a random sample and can miss rare interleavings.
- Loops are unbounded, so completeness can only be tested up to a bound.
- `check_soundness` and playout signatures differ between pm4py versions.
- The oracle is my own reading of the narrative. It shares my assumptions and would repeat any misreading.
- Passing tests shows consistency with my oracle, not fidelity to reality.

# 8. Final Self-Critique

1. **Semantic (process tree).** The tree still drops allowed high-risk behaviour: one review before the gate and the other after ET. Because it is a fixed four-variant design, nothing in it can be tuned. The claim that it has no over-approximation rests on reasoning and sampled tests, not on a proof or exhaustive verification.
2. **Semantic (both models).** The data conditions are only silent nondeterminism. A case that needed supplier consultation but skipped it is accepted, as is a "failed" inspection that silently ends the loop. Completion-only events cannot express "may start after". So overlap means only "no order between completion events", and a trace like "supplier started before ARC but completed after" is not distinguishable.
3. **Implementation.** I could not run the code. The `ProcessTree()` silent-leaf constructor, the POWL constructors, the playout parameter names, the return shape of `check_soundness`, and the hashability of `Marking` are assumed from PM4Py 2.7-style APIs. The Petri-net conversion may add silent transitions I have not inspected. The duplicated-label tree is also hard to explain to business users and may distort analytics.
