# Formal Comparison of Models A and B

## 1. Equivalence Notions

### 1.1 Visible Trace Equivalence (After Hiding )
Two process models are **visible-trace equivalent** if, after removing all silent transitions (), they generate the same set of complete traces from initial to final marking. A complete trace ends in the final marking with no enabled visible transitions.

**Definition:** `L_vis(M_A) = L_vis(M_B)` where `L_vis(M)` = {  (_vis)* |  is obtainable from M by hiding all }.

**Duplicate handling:** Visible labels are distinguished by *position and identity*; the sequence `[Analyze, Check, Analyze, Check]` is distinct from `[Analyze, Analyze, Check, Check]`.

### 1.2 Bounded Visible-Language Equivalence (P3)
Two models are **bounded-equivalent under P3** if their visible traces restricted to at most 12 visible events and at most 3 Analyze Revision occurrences are identical.

**Definition:** `L_vis^{12,3A}(M_A) = L_vis^{12,3A}(M_B)`.

**Purpose:** Detects divergences in finite, realistic execution windows without claiming unbounded equivalence.

### 1.3 Business-Relevant Equivalence (P1: Operational Compliance)
Two models are **P1-equivalent** if:
1. Every `Analyze Revision` is followed (transitively, with no other analysis-loop exit before `Close Case`) by exactly one `Check Revision`;
2. Every `Check Revision` occurs after an `Analyze Revision` and before the next `Rework Case` or before `Close Case`;
3. The relative ordering of `Analyze Revision`, `Check Revision`, and `Approve Revision` is preserved;
4. The count and position of `Approve Revision` occurrences (which may be 0, 1, or more per loop iteration) remain observable.

**Criterion:** Require that in **every** visible trace, the sequence of (Analyze, Check) pairs and their relation to Rework boundaries is identical.

### 1.4 Abstracted Dashboard Equivalence (P2)
Two models are **P2-equivalent** if, after the following abstractions:
- Remove all `Approve Revision` and `tau`;
- Replace all occurrences of `Check Revision` with the Boolean flag `[Check occurred]` (independent of multiplicity);
- Collapse repeated `Rework Case` to a Boolean `[Rework occurred]`;
- Record count of `Analyze Revision` occurrences;

they admit the same set of abstracted traces.

**Definition:** Let `abstract_P2()` = (Open, [Check occurred  ], count of Analyze, [Rework occurred  ], Close). Two models are P2-equivalent iff `{abstract_P2() |   L_vis(M)} ` is identical for both.

## 2. Structural Comparison

| Feature | Model A | Model B | Semantic Consequence |
|---------|---------|---------|----------------------|
| **Overall structure** | Sequential: Open  loop  Close | Sequential: Open  (Check  loop)  Close | A's Check is *inside* the loop; B's Check is *concurrent with* the entire loop. |
| **Loop definition** | `*(seq(+(Analyze, Check), X(Approve, tau)), Rework)` | `seq(Analyze, X(Approve, tau)), Rework)` inside a `*` | A repeats (Analyze, Check, optional Approve) then Rework; B repeats only (Analyze, optional Approve, Rework) while Check runs in parallel. |
| **Scope of Check Revision** | Inside the loop: must repeat with each `Analyze Revision` | Outside the loop: executes once, concurrently with *all* loop iterations. |
| **Minimum Check Revision count** | 1 (one per loop iteration; loop runs 1) | 1 (runs once in parallel; loop runs 1) |
| **Maximum Check Revision count** | Unbounded (one per `Analyze`  same as Analyze count) | 1 (runs once, terminates independently of loop count) |
| **Placement relative to Analyze** | *Immediately after* each Analyze (within same loop iteration, before optional Approve) | *Concurrent* with the entire loop; Check is not locally bound to any single Analyze. |
| **Placement relative to Rework** | Check completes before Rework begins (sequential within loop iteration) | Check may occur *any time* during or after the loop; Check completion is not synchronized with Rework. |
| **Approval occurrences** | One per loop iteration (0 or 1, i.e., optional per iteration; total count = loop iterations) | One per loop iteration (same as Model A's loop count) |
| **Concurrency** | None; all operations sequential within loop iteration | `Check Revision` and the loop are concurrent; Check execution is independent of loop pacing. |
| **Join/synchronization before Close** | Implicit: loop exits, then Close; no explicit join. | Explicit: `+` (parallel) must complete *all branches* (loop finishes AND Check finishes) before Close. |
| **Soundness risk** | Low: sequential flow is straightforward. | Moderate: the parallel join must ensure both branches terminate in compatible states. |

| **T6: Implicit Silent Approve (tau)** | `[Open, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close]` |  Valid (Approve is skipped via `tau` path in both iterations). |  Valid (Approve is skipped in both iterations). | None—both admit silent transitions. | — |

**Analysis:**

- **T2 is the decisive counterexample:** Model A generates the visible trace with **2 Check events** (one per Analyze). Model B generates only **1 Check event** (concurrent, single instance), so it **cannot produce T2 as written**. Instead, Model B would produce something like `[Open, Analyze, Rework, Analyze, Check, Close]` (out-of-order Check) or `[Open, Analyze, Check, Rework, Analyze, Close]` (early Check).

- **T3 is the dual counterexample:** Model B admits the possibility of Check firing out-of-order (e.g., after the second Analyze but possibly before the first within a larger context). Model A strictly enforces Check immediately after Analyze within each loop iteration, so T3 is invalid in A.

- **Approve Revision interaction:** Approval is optional in both models (via `tau`). The presence or absence of Approve does not alter the core difference: Model A repeats Check, Model B does not. Thus, Approve does not rescue equivalence.

- **Silent transitions:** The `tau` path in Model A's `X(Approve, tau)` choice is hidden. Both models have identical silent behavior; hiding it does not change the verdict.

```python
def bfs_bounded_traces(net, initial_marking, final_marking, 
                        max_visible_events=12, max_analyze_count=3, 
                        max_iterations=10000):
    """
    Exhaustive BFS exploration of visible traces up to bounds.
    
    Returns set of visible traces (tuples of visible event labels).
    """
    visible_traces = set()
    
    # State: (marking, visible_trace_so_far, analyze_count, iteration_count)
    queue = deque([(initial_marking, tuple(), 0, 0)])
    visited = set()  # (marking_tuple, visible_trace_tuple) to avoid infinite loops
    
    def marking_to_tuple(m):
        """Convert marking to hashable form."""
        return tuple(sorted((str(p), m[p]) for p in m if m[p] > 0))
    
    iteration = 0
    while queue and iteration < max_iterations:
        iteration += 1
        marking, vis_trace, analyze_count, depth = queue.popleft()
        
        state_key = (marking_to_tuple(marking), vis_trace)
        if state_key in visited:
            continue
        visited.add(state_key)
        
        # Check if we've reached final marking (complete trace)
        if marking == final_marking:
            visible_traces.add(vis_trace)
            continue
        
        # Prune: exceeded bounds
        if len(vis_trace) >= max_visible_events or analyze_count >= max_analyze_count:
            continue
        
        # Enumerate enabled transitions
        try:
            enabled = pm4py.get_enabled_transitions(net, marking)
        except:
            enabled = []
        
        for trans in enabled:
            # Fire transition
            new_marking = pm4py.semantics.petri_net.semantics.execute(net, marking, trans)
            
            # Check if visible
            label = trans.label if hasattr(trans, 'label') else str(trans)
            is_visible = (label is not None and label != 'tau')
            
            # Update analyze count
            new_analyze_count = analyze_count + (1 if is_visible and 'Analyze' in label else 0)
            
            # Only proceed if within bounds
            if new_analyze_count <= max_analyze_count:
                new_vis_trace = vis_trace + (label,) if is_visible else vis_trace
                if len(new_vis_trace) <= max_visible_events:
                    queue.append((new_marking, new_vis_trace, new_analyze_count, depth + 1))
    
    print(f"[BFS] Iterations: {iteration}, states explored: {len(visited)}")
    return visible_traces

print("=" * 70)
```

## 6. Stochastic and Footprint Comparison

### 6.1 Footprints and Causality

Footprints capture **directly-follows** relationships and **concurrency**. A footprint is a pair (DFR, ConcurrencySet) where:
- **DFR** (direct follows relations) = {(a, b) | a is immediately followed by b in at least one trace}
- **Concurrency** = {(a, b) | both ab and ba are in DFR, or neither depends on the other}

**Why equal footprints would NOT establish equivalence:**
- Footprints ignore *ordering constraints* within concurrent regions.
- Example: In Model B, if Check and Analyze are concurrent, footprints capture (Analyze, Check) and (Check, Analyze) as both possible. But they do *not* encode that in Model A, Check is *always immediately after* the Analyze that caused it.
- Footprints are *necessary* but not *sufficient* for trace equivalence.

### 6.2 Stochastic Language

`pm4py.get_stochastic_language(net)` returns a probability distribution over traces (if transitions have assigned probabilities). Without explicit probability assignments, this is undefined or uniform.

**Caveat:** Even if both models had identical stochastic languages (e.g., both uniform over their trace sets), this would still not imply trace equivalence if the trace sets themselves differ.

### 6.3 Earth Mover's Distance (EMD)

EMD measures the "cost" of transforming one probability distribution into another. A low EMD would suggest the models are behaviorally "close," but:
- **EMD requires probabilities:** Without stochastic annotations, EMD is meaningless or defaults to uniform.
- **EMD does not imply equivalence:** Even a low EMD can mask fundamental structural differences if the cost metric is not aligned with business semantics.

## 7. Complexity Comparison

### 7.1 Structural Metrics (Tree Level)

```python
# ============================================================================
# STRUCTURAL COMPLEXITY METRICS
# ============================================================================

def count_tree_nodes(tree):
    """Recursively count all nodes in a process tree."""
    count = 1  # Count self
    if hasattr(tree, 'children') and tree.children:
        for child in tree.children:
            count += count_tree_nodes(child)
    return count

def tree_depth(tree):
    """Maximum depth of process tree."""
    if not hasattr(tree, 'children') or not tree.children:
        return 1
    return 1 + max(tree_depth(child) for child in tree.children)

def count_visible_leaves(tree):
    """Count leaf nodes that are visible (non-tau)."""
    if not hasattr(tree, 'children') or not tree.children:
        # This is a leaf
        label = tree.label if hasattr(tree, 'label') else str(tree)
        return 1 if (label and label != 'tau') else 0
    total = 0
    for child in tree.children:
        total += count_visible_leaves(child)
    return total

def count_silent_leaves(tree):
    """Count leaf nodes that are silent (tau)."""
    if not hasattr(tree, 'children') or not tree.children:
        # This is a leaf
        label = tree.label if hasattr(tree, 'label') else str(tree)
        return 1 if label == 'tau' else 0
    total = 0
    for child in tree.children:
        total += count_silent_leaves(child)
    return total

def count_duplicate_labels(tree, label_counts=None):
    """Count how many distinct labels appear more than once."""
    if label_counts is None:
        label_counts = defaultdict(int)
    
    if not hasattr(tree, 'children') or not tree.children:
        # Leaf node
        label = tree.label if hasattr(tree, 'label') else str(tree)
        if label:
            label_counts[label] += 1
    else:
        for child in tree.children:
            count_duplicate_labels(child, label_counts)
    
    return sum(1 for count in label_counts.values() if count > 1), label_counts
```
