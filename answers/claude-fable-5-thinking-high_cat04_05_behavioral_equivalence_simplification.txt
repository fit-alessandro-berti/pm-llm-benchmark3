# 1. Equivalence Notions

All notions below operate on **complete visible traces**: sequences of transition labels produced by runs of the model from its initial state to its final state (for the Petri-net translation: from the initial marking to the final marking of the accepting net), with every `tau` (silent) step deleted. A trace is only counted when the run actually completes; prefixes are not compared.

**Duplicate-label convention.** Events are distinguished **only by label**. Two occurrences of `Check Revision` in one trace are two occurrences of the same label at different sequence positions; there is no event identity beyond position in the sequence. Neither model contains duplicate labels among its leaves (each visible label occurs exactly once per tree), so no leaf-identity ambiguity arises; multiplicity in traces comes solely from the loop.

1. **Visible trace equivalence after hiding `tau`.**
   Let `L(M)` be the set of complete visible traces of model `M`. Models A and B are visibly trace-equivalent iff `L(A) = L(B)`. This is the strongest notion used here (I do not use bisimulation; no view in P1–P3 observes branching structure, only completed traces).

2. **Bounded visible-language equivalence (P3).**
   Let `L≤(M) = { t ∈ L(M) : |t| ≤ 12 and #AnalyzeRevision(t) ≤ 3 }`, where `|t|` counts visible events. A and B are P3-equivalent iff `L≤(A) = L≤(B)`. A positive result is only *evidence* for unbounded equivalence; a negative result is a *proof* of non-equivalence (any bounded counterexample is a genuine counterexample).

3. **Business-relevant equivalence (P1, operational compliance).**
   P1 observes the full visible trace (approvals included, `tau` hidden) and additionally evaluates the compliance predicate `comply(t)`: split `t` between `Open Case` and `Close Case` into segments separated by `Rework Case`; `comply(t)` holds iff **every** segment contains at least one `Analyze Revision` and at least one `Check Revision` (each analysis has "its own" check before the next `Rework Case` or before `Close Case`). Two models are P1-equivalent iff they have the same visible language **and** therefore the same set of compliant/non-compliant behaviors. Because P1 hides nothing except `tau`, P1-equivalence coincides with visible trace equivalence, but the verdict must additionally report whether each model *guarantees* `comply(t)` for all its traces.

4. **Abstracted dashboard equivalence (P2).**
   Define the abstraction `α(t)` on a complete visible trace `t`:
   - drop `Approve Revision` (and all silent behavior, already hidden);
   - verify `Open Case` is first and `Close Case` is last (structural precondition);
   - record the triple `(n, c, r)` where `n = #AnalyzeRevision(t) ≥ 1`, `c = (#CheckRevision(t) ≥ 1)` (Boolean — repeated checks collapse), `r = (#ReworkCase(t) ≥ 1)` (Boolean).
   Interleaving of `Analyze Revision` and `Check Revision` is deliberately not recorded. A and B are P2-equivalent iff `α(L(A)) = α(L(B))`.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | Loop body = `->( +(Analyze, Check), X(Approve, tau) )`; **Check is inside the loop body** | Loop body = `->( Analyze, X(Approve, tau) )`; **Check is outside the loop**, parallel to the whole loop | In A the check is re-executed every iteration; in B it is executed exactly once per case regardless of iteration count |
| Min / max `Check Revision` occurrences | min 1, max = number of loop iterations `n` (exactly one per iteration, so `#Check = #Analyze = n`) | exactly 1 (min 1, max 1) | Any trace with ≥ 2 iterations distinguishes the models by check count alone |
| Possible placement of `Check Revision` | Within its own iteration segment: freely interleaved with that iteration's `Analyze` (before or after it), but always **before** that iteration's optional `Approve` and before the next `Rework`/`Close` | Anywhere between `Open Case` and `Close Case`: before the first `Analyze`, after the last `Approve`, or in the middle of any iteration, including **after `Rework Case`** and **after `Approve Revision`** | A enforces per-revision check discipline; B allows the single check to float, e.g. all analysis/rework work can complete before the only check happens |
| Optional approval occurrences | 0 or 1 `Approve Revision` per iteration (via `X(Approve, tau)`), i.e. 0..n per case; each approval follows the `+(Analyze, Check)` block of its own iteration | 0 or 1 per iteration, 0..n per case; each approval follows its own `Analyze`; ordering w.r.t. the single `Check` is unconstrained | In A, `Check → Approve` within an iteration is a hard sequence; in B, `Approve` then `Check` is possible (footprint difference: A has sequence Check→Approve, B has Check ∥ Approve) |
| Concurrency | `+` scoped to one iteration: only `Analyze` and `Check` of the *same* iteration interleave | `+` scoped to the entire loop: `Check` interleaves with *all* iterations, including `Rework Case` | A's interleaving window is 2 activities wide; B's is unbounded — `Check ∥ Rework` is possible only in B... (in A, `Check` and `Rework` of the same case never overlap within one iteration structure, though `Check→Rework` and `Rework→Check` both occur as directly-follows across iteration borders) |
| Join before `Close Case` | Loop exit (silent) directly precedes `Close Case`; the check obligation was already discharged inside the last iteration | AND-join: `Close Case` waits for **both** the loop exit **and** the single `Check` | Both models guarantee ≥ 1 check before `Close Case`; but B guarantees only one, and it may be the case's *only* check after arbitrarily many reworks |

Both trees have 12 nodes, 6 visible leaves, 1 silent leaf (`tau`), and no duplicate labels; A has depth 4, B depth 5 (see §7).

|---|---|---|---|---|

| P1 (operational compliance) | not equivalent | Certain | B violates the per-revision-check rule for every trace with ≥ 2 iterations (e.g. `⟨Open, Analyze, Rework, Analyze, Check, Close⟩`: the first segment `⟨Analyze⟩` has no check); A satisfies `comply(t)` for **all** its traces by construction | If the business also accepts "check *before* the analysis of the same iteration" as that revision's own check, A remains compliant; if not, A's `Check→Analyze` orderings need the stricter model of §8 |
| P2 (executive dashboard) | equivalent only under stated abstraction | High | `α(L(A)) = α(L(B)) = { (n, true, n≥2) : n ≥ 1 }`: both always produce ≥ 1 check (collapsed to a Boolean), the analysis count ranges over all `n ≥ 1` in both, and rework occurs iff `n ≥ 2` in both. Verified exhaustively for `n ≤ 3` (identical abstraction sets `{(1,T,F),(2,T,T),(3,T,T)}`) and extended by induction on the loop unfolding | Equivalence holds **only** because the dashboard discards check multiplicity and interleaving; any future dashboard field like "number of checks" or "checked before rework" immediately breaks it |
| P3 (bounded testing, ≤ 12 visible events, ≤ 3 analyses) | not equivalent | Certain (exhaustive) | Exhaustive breadth-first exploration of both accepting Petri nets under the bound: `|L≤(A)| = 76`, `|L≤(B)| = 85`, `|L≤(A) ∩ L≤(B)| = 4` (only A's four single-iteration traces are shared); 72 traces unique to A, 81 unique to B | The bound is irrelevant to *this* negative verdict; it would only matter if the bounded languages had been equal |

# 4. Counterexample Traces

Inclusion facts proved first, because they shape which witnesses exist:

- **Restricted inclusion:** for single-iteration traces (`#Analyze = 1`), `L(A) ⊆ L(B)` strictly. Proof: a one-iteration A-trace is `Open · w · Close` where `w` is an interleaving of `{Analyze, Check}` optionally followed by `Approve`; B can reproduce it by scheduling its concurrent `Check` at the same position. B additionally admits `Check` *after* `Approve`, which A cannot. (Verified: all 4 one-iteration A-traces ∈ L(B).)
- **Disjointness beyond one iteration:** for `#Analyze = n ≥ 2`, `L(A)` and `L(B)` are disjoint, since every such A-trace has `n ≥ 2` checks and every B-trace has exactly 1. (Verified: intersection of the ≥ 2-analysis sublanguages under the P3 bound is empty.)

Hence full inclusion holds in neither direction, and witnesses exist on both sides. All four traces below were machine-verified with the code of §5.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| T1 | ⟨Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, **Check Revision**, Close Case⟩ | accepted | rejected | The **second** `Check Revision` (position 6): B's single concurrent check token is already consumed; B has no transition left to fire it | P1, P3 (two analysis attempts) |
| T2 | ⟨Open Case, Check Revision, Analyze Revision, Approve Revision, Rework Case, **Check Revision**, Analyze Revision, Close Case⟩ | accepted | rejected | The second `Check Revision` (position 6) — same counting argument; also shows A allows check-before-analyze within an iteration | P1, P3 |
| T3 | ⟨Open Case, Analyze Revision, **Approve Revision, Check Revision**, Close Case⟩ | rejected | accepted | `Check Revision` after `Approve Revision` (position 4): in A the iteration's `X(Approve, tau)` can only start after `+(Analyze, Check)` completed, so `Check` strictly precedes any `Approve` of its iteration; in B the check is concurrent with the whole loop and may fire last | P3 (even at a single iteration) |
| T4 | ⟨Open Case, Analyze Revision, **Rework Case**, Analyze Revision, Check Revision, Close Case⟩ | rejected | accepted | `Rework Case` at position 3 with **no prior check**: A's loop redo is only reachable after the iteration body (which contains `Check`) completed; B happily reworks before its one check occurs | P1 (compliance violation made visible), P3 (two analysis attempts) |

**Role of optional `Approve Revision` and hidden `tau`.** The `X(Approve, tau)` choice means an approval either appears as one visible event or vanishes entirely — silent completion is unobservable after hiding, so approvals can never be used to *force* a distinction (T1 and T4 contain no approval at all and still distinguish the models). But approvals do sharpen the distinction where ordering matters: T3 exists only because B's concurrency scope lets `Check` overtake `Approve`, which A's iteration-local sequencing forbids. Hiding `tau` also matters for the loop mechanics: the loop's redo/exit decisions and the skipped approvals are all silent, so equality must be tested on completed visible traces reaching the final marking — comparing raw firing sequences would spuriously distinguish structurally different but observationally identical runs.

# 5. Bounded Comparison Code

The script below performs an **exhaustive** breadth-first exploration of the reachability space of each accepting Petri net, restricted by the P3 bound (≤ 12 visible events, ≤ 3 `Analyze Revision`). It is exhaustive — not a playout — because: (i) both nets are sound workflow nets, hence bounded, so the marking space is finite; (ii) the search state is the pair (marking, visible trace), silent transitions extend the marking but not the trace, and a visited-set on these pairs cuts every cycle (including pure-`tau` cycles); (iii) a trace is recorded only when the reached marking **equals the final marking** (multiset equality). By contrast, `pm4py.play_out(...)` samples runs by making random choices with a bounded number of traces/steps; it gives no coverage guarantee, can miss rare interleavings, and can never certify that a trace is *absent* — which is exactly what a counterexample claim needs.

```python
import pm4py
from collections import deque
from pm4py.objects.petri_net import semantics

TREE_A = "->( 'Open Case', *( ->( +('Analyze Revision','Check Revision'), X('Approve Revision', tau) ), 'Rework Case' ), 'Close Case' )"
TREE_B = "->( 'Open Case', +( 'Check Revision', *( ->( 'Analyze Revision', X('Approve Revision', tau) ), 'Rework Case' ) ), 'Close Case' )"

MAX_VISIBLE = 12          # P3: at most 12 visible events
MAX_ANALYZE = 3           # P3: at most three Analyze Revision occurrences

def marking_key(m):
    """Hashable canonical form of a marking (multiset of places)."""
    return tuple(sorted((p.name, m[p]) for p in m if m[p] > 0))

def bounded_language(net, im, fm):
    """Exhaustive BFS over (marking, visible-trace) states under the P3 bound."""
    final_key = marking_key(fm)
    complete, seen = set(), set()
    queue = deque([(im, ())])
    while queue:
        marking, trace = queue.popleft()
        state = (marking_key(marking), trace)
        if state in seen:                      # cuts repeated markings and tau-cycles
            continue
        seen.add(state)
        if marking_key(marking) == final_key:  # explicit final-marking equality
            complete.add(trace)
        for t in semantics.enabled_transitions(net, marking):
            m2 = semantics.execute(t, net, marking)
            if t.label is None:                # silent: marking advances, trace unchanged
                queue.append((m2, trace))
            else:
                nt = trace + (t.label,)
                if len(nt) > MAX_VISIBLE:                       # visible-length bound
                    continue
                if nt.count('Analyze Revision') > MAX_ANALYZE:  # P3 analysis bound
                    continue
                queue.append((m2, nt))
    return complete

def build(tree_string, name):
    tree = pm4py.parse_process_tree(tree_string)          # (1) parse
    net, im, fm = pm4py.convert_to_petri_net(tree)        # (2) accepting Petri net
    diagnostics = pm4py.check_soundness(net, im, fm, print_diagnostics=True)  # (3)
    assert diagnostics[0], f"model {name} is not a sound workflow net"
    return net, im, fm

netA, imA, fmA = build(TREE_A, "A")
netB, imB, fmB = build(TREE_B, "B")

LA = bounded_language(netA, imA, fmA)                     # (4)/(5) exhaustive derivation
LB = bounded_language(netB, imB, fmB)

only_A, only_B = LA - LB, LB - LA                          # (5) compare, (6) uniques
print(f"|L<=(A)| = {len(LA)}, |L<=(B)| = {len(LB)}, shared = {len(LA & LB)}")
print(f"P3 verdict: {'EQUIVALENT under bound' if not only_A and not only_B else 'NOT equivalent'}")
print(f"\n{len(only_A)} traces only in A (shortest 5):")
for t in sorted(only_A, key=len)[:5]:
    print("   ", t)
print(f"\n{len(only_B)} traces only in B (shortest 5):")
for t in sorted(only_B, key=len)[:5]:
    print("   ", t)
# (7) This exploration is EXHAUSTIVE within the stated bound (sound WF-nets are
# bounded; the visited-set over (marking, visible trace) makes the search finite).
# A random alternative such as pm4py.play_out(tree, ...) would NOT be exhaustive:
# it samples finitely many runs with random choice resolution and cannot certify
# the absence of any trace.
```

**Executed results** (PM4Py 2.7.23.4): both nets sound; `|L≤(A)| = 76`, `|L≤(B)| = 85`, shared = 4 (exactly A's four one-iteration traces), 72 unique to A, 81 unique to B. The shortest uniques reproduce T1–T4 of §4.

# 6. Stochastic and Footprint Comparison

**Footprints — `pm4py.discover_footprints(...)`.** Footprints abstract a model to directly-follows / sequence / parallel relations between label pairs. They *can* add cheap evidence and here they already refute equivalence: A's footprint contains the **sequence** relation `Check Revision → Approve Revision` (iteration-local ordering), whereas B's footprint declares `Check Revision ∥ Approve Revision` (loop-wide concurrency). This matches counterexample T3.

```python
fpA = pm4py.discover_footprints(pm4py.parse_process_tree(TREE_A))
fpB = pm4py.discover_footprints(pm4py.parse_process_tree(TREE_B))
print("footprints equal:", fpA == fpB)
print("sequence only in A:", fpA["sequence"] - fpB["sequence"])
print("parallel only in B:", fpB["parallel"] - fpA["parallel"])
```

Executed: `footprints equal: False`; sequence only in A = `{(Check Revision, Approve Revision)}`; parallel only in B = `{(Check Revision, Approve Revision), (Approve Revision, Check Revision)}`. **However, equal footprints would not establish trace equivalence**: footprints are a pairwise, occurrence-count-blind abstraction. They cannot express "one check per iteration" versus "one check per case" — a footprint has no notion of multiplicity or long-range constraints, so two models with identical footprints can still have disjoint languages beyond length 2 windows.

**Stochastic language and EMD — `pm4py.get_stochastic_language(...)`, `pm4py.compute_emd(...)`.** Neither original tree carries probabilities, so any stochastic comparison **requires declaring** a probability assignment; I declare the PM4Py default playout semantics (uniformly random resolution of choices/interleavings, bounded trace count) and stress that this is an *assumption*, not part of the models:

```python
# DECLARED assumption: uniform random choice resolution via play_out; results are
# estimates of the induced stochastic language, NOT properties of the (non-stochastic) trees.
logA = pm4py.play_out(pm4py.parse_process_tree(TREE_A), parameters={"num_traces": 5000})
logB = pm4py.play_out(pm4py.parse_process_tree(TREE_B), parameters={"num_traces": 5000})
slA = pm4py.get_stochastic_language(logA)
slB = pm4py.get_stochastic_language(logB)
print("EMD(A, B) =", pm4py.compute_emd(slA, slB))
```

A clearly positive Earth Mover's Distance is (sampling noise aside) evidence of behavioral difference and would be expected here, since ~half of each sampled language lies outside the other model. But a **low EMD would still not establish trace equivalence**: EMD measures mass transport between *frequency-weighted* trace distributions under the declared probabilities. Two different languages can yield near-zero EMD if their differences sit on low-probability traces (e.g. deep loop iterations that uniform playout rarely reaches), and sampling truncates the infinite language anyway. EMD is a distance between two arbitrary distributions, not a decision procedure for language equality.

# 7. Complexity Comparison

Structural counts derived by the following traversal (executed on the parsed trees):

```python
def tree_metrics(node, depth=0):
    """Returns (node_count, max_depth, visible_leaves, silent_leaves, labels)."""
    if not node.children:
        lab = [] if node.label is None else [node.label]
        return 1, depth, len(lab), 1 - len(lab), lab
    n, d, v, s, labs = 1, depth, 0, 0, []
    for c in node.children:
        cn, cd, cv, cs, cl = tree_metrics(c, depth + 1)
        n += cn; d = max(d, cd); v += cv; s += cs; labs += cl
    return n, d, v, s, labs
# duplicate-label count = len(labels) - len(set(labels))

netA, imA, fmA = pm4py.convert_to_petri_net(pm4py.parse_process_tree(TREE_A))
netB, imB, fmB = pm4py.convert_to_petri_net(pm4py.parse_process_tree(TREE_B))
print(pm4py.simplicity_petri_net(netA, imA, fmA))   # inverse-arc-degree simplicity
print(pm4py.simplicity_petri_net(netB, imB, fmB))
```

Executed values (PM4Py 2.7.23.4; Petri-net figures depend on the converter version):

| Metric | Model A | Model B |
|---|---|---|
| Process-tree node count | 12 | 12 |
| Depth (root = 0) | 4 | 5 |
| Visible leaves | 6 | 6 |
| Silent leaves (`tau`) | 1 | 1 |
| Duplicate-label count | 0 | 0 |
| Converted net: places / transitions / arcs | 9 / 9 / 20 | 7 / 7 / 16 |
| `simplicity_petri_net` (inverse arc degree) | 0.8182 | 0.7778 |

Interpretation: the trees are almost equally complex; B is deeper but converts to a smaller net, yet scores *lower* on inverse-arc-degree simplicity because its AND-join before `Close Case` concentrates arcs. Neither model dominates the other structurally — the real difference is semantic (check multiplicity and scope), not size.

# 8. Simplified Model

**Target semantics: P1 (operational compliance), with one explicitly documented strengthening.** P1 is the most demanding and most safety-relevant view, and only Model A can serve it (§3). Within P1, the `+('Analyze Revision','Check Revision')` interleaving allows a check to occur *before* the analysis it is supposed to check — operationally dubious and, under a strict reading of "every analysis revision must have its own Check Revision", arguably non-compliant itself. I therefore fix the order `Analyze → Check`, which (a) removes the only concurrency operator, (b) strengthens compliance (the check now demonstrably follows the work it checks), and (c) leaves every P1-relevant guarantee intact: one check per revision, checks before the next `Rework`/`Close`, approvals optional, visible, and correctly placed.

**1. Compact process tree:**

```text
->(
  'Open Case',
  *(
    ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ),
    'Rework Case'
  ),
  'Close Case'
)
```

**2. PM4Py code:**

```python
import pm4py

simplified_model = pm4py.parse_process_tree(
    "->( 'Open Case', "
    "    *( ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ), "
    "       'Rework Case' ), "
    "    'Close Case' )"
)
net_s, im_s, fm_s = pm4py.convert_to_petri_net(simplified_model)
assert pm4py.check_soundness(net_s, im_s, fm_s)[0]
```

**Simplicity, compared to both originals** (same metrics and tooling as §7, executed): 11 tree nodes (vs 12 / 12), depth 4 (vs 4 / 5), 6 visible + 1 silent leaves (unchanged), 0 duplicate labels, converted net 6 places / 7 transitions / 14 arcs (vs 9/9/20 and 7/7/16), `simplicity_petri_net` = **0.8667** (vs 0.8182 and 0.7778). It is strictly simpler than both originals on node count, net size, and the simplicity metric, and it eliminates concurrency entirely, shrinking the reachable state space.

**3. Preservation table** (relative to Model A as the P1 reference; verified: `L(simplified) ⊂ L(A)` and the P2 abstraction sets coincide):

| Property | Status | Justification |
|---|---|---|
| One `Check Revision` per revision, before next `Rework`/`Close` (P1 core) | exact (strengthened) | Loop body still contains exactly one check per iteration; ordering now guarantees it follows its analysis |
| Number and placement of approvals (P1) | exact | `X(Approve, tau)` unchanged, still per-iteration, still after the check |
| `Open` first / `Close` last, ≥ 1 analysis, ≥ 1 check (P2) | exact | Sequence skeleton and loop unchanged |
| P2 abstraction `α` (analysis count, check Boolean, rework Boolean) | exact | `α(L(simplified)) = α(L(A)) = α(L(B)) = {(n, true, n≥2) : n ≥ 1}` — machine-checked for n ≤ 3, inductive for all n |
| `Check`-before-`Analyze` interleavings of Model A | weakened (deliberately dropped) | The `+` is replaced by a sequence; e.g. ⟨Open, Check, Analyze, Close⟩ is no longer accepted |
| Model B's floating-check behaviors (check after approve / after rework / one check for many revisions) | lost (deliberately) | These are exactly the P1 violations; a P1 model must reject them |
| P3 bounded language equality with either original | lost | `L≤(simplified)` = 13 traces, a strict subset of A's 76; the simplification is not behavior-preserving at the raw-trace level and does not claim to be |

**4. Regression traces (must be accepted — all machine-verified accepted):**

- R1: ⟨Open Case, Analyze Revision, Check Revision, Close Case⟩ — minimal compliant case, auto-approved.
- R2: ⟨Open Case, Analyze Revision, Check Revision, Approve Revision, Close Case⟩ — single revision with explicit approval.
- R3: ⟨Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Approve Revision, Close Case⟩ — two revisions, each with its own check, second one approved.

**Negative traces (must be rejected — both machine-verified rejected):**

- N1: ⟨Open Case, Check Revision, Analyze Revision, Close Case⟩ — check precedes the analysis it should validate (accepted by both originals; rejected here by the documented strengthening).
- N2: ⟨Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case⟩ — first revision reworked without any check (Model B's compliance hole; rejected here and by A).

# 9. Final Recommendation

- **P1 (operational compliance): use Model A — or better, the simplified model.** Model B is unsuitable for P1: it structurally guarantees only one check per case, so every multi-revision execution (T4 and all 81 B-unique bounded traces with ≥ 2 iterations or a floating check) violates the per-revision-check rule while still completing successfully. The simplified model should replace A **if** the business confirms that a revision's check must *follow* its analysis; if check-before-analysis within an iteration is genuinely acceptable, keep A unchanged, because the simplified model rejects those orderings.
- **P2 (executive dashboard): either original works, and so does the simplified model.** All three induce the identical abstraction set `{(n, check=true, rework = n≥2) : n ≥ 1}`. Since the simplified model is structurally the smallest of the three and also serves P1, it is the best single artifact if one model must feed both views.
- **P3 (bounded testing): the models are provably different**, so no testing view should treat them as interchangeable; 157 of the 161 bounded traces belong to exactly one model.
- **No single simplification preserves all three views at the raw-trace level.** Any model whose full visible language matched both A and B is impossible (their languages differ), so the compromise is a model that is P1-exact and P2-exact while abandoning trace-level agreement with B — which is what §8 delivers.

**Warning on bounded comparison.** The exhaustive exploration in §5 is complete only within its bounds (≤ 12 visible events, ≤ 3 analyses). Here the bound did not weaken the conclusion, because the verdict is negative and every bounded counterexample is a real one — and the counting argument (`#Check = #Analyze` in A vs `#Check = 1` in B) extends the non-equivalence proof to the unbounded languages. Had the bounded languages been *equal*, that would have been evidence only: loop-generated differences can first appear beyond any finite bound, and no finite exploration, playout, footprint comparison, or EMD score can by itself prove unbounded trace equivalence.
