# Dynamic Resource-Assignment Policy Design

## # 1. Objectives and constraints

### Optimization objectives (soft constraints)
1. **Short-term throughput**: Minimize average waiting time for cases while maintaining quality
2. **Skill development**: Provide training opportunities where SLA risk permits
3. **Workload fairness**: Distribute new assignments evenly across resources
4. **Case ownership continuity**: Minimize unnecessary reassignments
5. **SLA risk mitigation**: Prioritize cases with imminent deadlines
6. **Resilience**: Avoid creating single points of failure in critical skills

### Hard safety/compliance constraints
1. **Skill requirements**:
   - Security Review: Must be skill 3 or supervised by R7_Gita/R8_Hugo
   - Final Approval: Must be skill 2-3 (skill 1 may prepare only)
   - All other activities: Minimum skill 1 (trainees must be supervised)

2. **Overtime risk**:
   - High overtime risk resources (R2_Bruno, R4_David, R9_Iris) should not receive new assignments unless:
     - Case priority is urgent AND
     - No other resource with lower overtime risk is available

3. **Training constraints**:
   - Maximum 20% of normal/low-priority assignments to training priorities
   - Training assignments must have SLA time remaining >6h

4. **Workload limits**:
   - No resource receives >4 new assignments in a batch
   - No resource should exceed 8 total open cases (current + new)

5. **Case continuity**:
   - High-complexity cases with handover_cost="high" should keep current owner unless:
     - Current owner has skill 0-1 AND
     - No supervision available

### Preference trade-offs
1. **Urgency vs. skill match**: Urgent cases may go to slightly less optimal skill matches if no better option exists
2. **Throughput vs. training**: Training assignments may slightly delay urgent cases
3. **Continuity vs. fairness**: May override workload fairness for high-handover-cost cases
4. **Specialization vs. resilience**: May use slightly less skilled resources to avoid bottlenecks

## # 2. Assignment policy

```python
def assign_cases(cases, resources):
    # Step 1: Filter resources by eligibility (skill, overtime risk, workload)
    eligible_resources = []
    for res in resources:
        # Check skill requirements
        if not meets_skill_requirements(res, cases):
            continue

        # Check workload limits
        if res.current_open_cases >= 8 or res.hours_remaining < 1:
            continue

        # Check overtime risk
        if res.overtime_risk == "high" and not is_urgent_case(cases):
            continue

        eligible_resources.append(res)

    # Step 2: Score each case-resource pair
    scored_assignments = []
    for case in cases:
        for res in eligible_resources:
            score = calculate_assignment_score(case, res)
            scored_assignments.append((case, res, score))

    # Step 3: Sort by score (descending) and apply constraints
    scored_assignments.sort(key=lambda x: x[2], reverse=True)

    # Step 4: Select assignments while respecting constraints
    assignments = []
    used_resources = {res: 0 for res in eligible_resources}  # Track new assignments

    for case, res, score in scored_assignments:
        # Check resource assignment limit
        if used_resources[res] >= 4:
            continue

        # Check training priority share
        if case.priority in ["normal", "low"] and res.training_priority != "none":
            if sum(1 for c, r, _ in assignments if r.training_priority != "none") >= 0.2 * len(cases):
                continue

        # Check case continuity for high handover cost
        if case.handover_cost_band == "high" and case.current_owner != "none":
            if not should_keep_continuity(case, res):
                continue

        # Assign and mark resource as used
        assignments.append((case, res))
        used_resources[res] += 1
        break  # Move to next case

    # Step 5: Handle unassigned cases (fallback to first-available)
    unassigned = [case for case in cases if not any(case == a[0] for a in assignments)]
    for case in unassigned:
        for res in eligible_resources:
            if used_resources[res] < 4:
                assignments.append((case, res))
                used_resources[res] += 1
                break

    return assignments
```

### Key scoring components:

1. **SLA urgency score** (0-100):
   - Urgent priority: 100
   - High priority: 80
   - Normal priority: 60
   - Low priority: 40
   - Adjusted by SLA time remaining (linear decay from 100% at deadline to 0% at 2x deadline)

2. **Skill match score** (0-50):
   - Exact skill match: 50
   - Skill match +1: 40
   - Skill match -1: 30
   - Skill match -2: 20
   - Below minimum skill: 0

3. **Continuity score** (0-30):
   - Same owner: 30
   - Trainee supervised by owner: 25
   - Different owner but handover_cost="low": 20
   - Different owner with handover_cost="medium": 10
   - Different owner with handover_cost="high": 0

4. **Workload fairness score** (0-20):
   - Inverse of current open cases (normalized)
   - Inverse of hours remaining (normalized)

5. **Training score** (0-10):
   - If case priority is normal/low and resource has training priority:
     - Exact match: 10
     - Related skill: 7
   - Otherwise: 0

6. **Resilience score** (0-10):
   - Avoids overloading resources with overtime risk
   - Avoids creating bottlenecks in critical skills

### Tie-breaking:
1. Higher skill match
2. Higher continuity
3. Lower current workload
4. Resource with lower overtime risk
5. Random selection

## # 5. Explanation to workers

**How cases are assigned:**

We use a balanced approach that considers several important factors:

1. **Your skills and current workload**: We look at what you're qualified to do and how busy you are right now. We try to give you work that matches your skills while keeping your workload manageable.

2. **Case urgency**: Cases with tight deadlines get priority, but we never assign urgent work to someone who isn't properly trained for it.

3. **Case history**: If a case has been moved around a lot, we try to keep it with its current owner unless there's a good reason to reassign it.

4. **Learning opportunities**: About 25% of routine cases are assigned to help team members develop new skills, but only when it won't delay the case.

5. **Team balance**: We try to spread new assignments fairly so no one gets overwhelmed.

**Why you might get certain cases:**
- You get complex cases when you're the most qualified person available
- You get training cases when you've shown interest in developing new skills
- You might get a case you've worked on before to avoid starting over
- Routine cases might go to newer team members to help them learn

**What we monitor:**
- We watch how long cases take after assignment
- We track if cases need to be reassigned
- We check if training assignments are helping without causing delays
- We look for cases that keep getting moved around unnecessarily

This system helps us balance getting work done quickly with maintaining quality and helping team members grow in their careers.

## # 6. Process-mining audit indicators

### Primary indicators (to be calculated monthly)
1. **Handover frequency**:
   - Percentage of cases with >1 handover
   - Median handover count per case
   - Distribution of handover counts

2. **Reassignment patterns**:
   - Cases with >2 reassignments (target: <5% of cases)
   - Reassignment rate by activity
   - Time between reassignments

3. **Skill mismatch**:
   - Percentage of assignments where assigned resource's skill < required skill
   - Service time increase for skill-mismatched assignments
   - Rework rate by skill mismatch level

4. **Workload distribution**:
   - Gini coefficient of workload across resources
   - Percentage of resources at >80% capacity
   - Overtime hours by resource

5. **SLA performance**:
   - Percentage of cases meeting SLA
   - SLA breach rate by priority level
   - Time from assignment to completion

6. **Training effectiveness**:
   - Percentage of training assignments that complete without reassignment
   - Skill progression of trainees (time to next skill level)
   - Supervisor feedback on training assignments

7. **Bottleneck indicators**:
   - Queue length at specialist-only activities
   - Utilization rate of top 3 most used resources
   - Time waiting for specialist resources

### Secondary indicators (for deeper analysis)
8. **Continuity metrics**:
   - Percentage of cases keeping original owner
   - Time saved by maintaining continuity
   - Rework rate for cases with vs. without continuity

9. **Overtime risk exposure**:
   - Percentage of high-overtime-risk resources receiving assignments
   - Cases assigned to high-risk resources that breach SLA
   - Time pressure at assignment for high-risk resources

10. **Policy compliance**:
    - Percentage of assignments following the policy rules
    - Cases assigned in violation of constraints
    - Reasons for policy violations

### Visualization recommendations
- **Handover network**: Use `pm4py.discover_handover_of_work_network` to show who hands off to whom
- **Workload distribution**: Use `pm4py.view_sna` to show resource utilization
- **Performance DFG**: Use `pm4py.discover_performance_dfg` to show bottlenecks
- **Skill similarity**: Use `pm4py.discover_activity_based_resource_similarity` to identify cross-training opportunities
- **Case variants**: Use `pm4py.get_variants` to analyze case paths and rework loops

## # 7. PM4Py implementation sketch

```python
import pandas as pd
from pm4py.objects.log.util import dataframe_utils
from pm4py.objects.conversion.log import converter as log_converter
import pm4py

def load_and_prepare_log(event_log_path):
    """Load and prepare event log with required columns"""
    df = pd.read_csv(event_log_path)

    # Ensure required columns exist
    required_columns = [
        'case:concept:name', 'concept:name', 'time:timestamp',
        'org:resource', 'required_skill', 'case_priority',
        'sla_deadline', 'case_complexity', 'current_owner',
        'team', 'assignment_reason', 'reassignment_count',
        'workload_snapshot', 'handover_cost_band'
    ]

    # Convert to proper types
    df['time:timestamp'] = pd.to_datetime(df['time:timestamp'])
    df['sla_deadline'] = pd.to_datetime(df['sla_deadline'])

    return df

def calculate_assignment_metrics(df):
    """Calculate metrics for policy evaluation"""
    # Convert to event log
    parameters = {dataframe_utils.CASE_ID_KEY: 'case:concept:name',
                 dataframe_utils.ACTIVITY_KEY: 'concept:name',
                 dataframe_utils.TIMESTAMP_KEY: 'time:timestamp'}
    log = log_converter.apply(df, variant=log_converter.Variants.TO_EVENT_LOG, parameters=parameters)

    # Calculate waiting times
    log = pm4py.insert_case_service_waiting_time(log)

    # Discover handover network
    handover_net = pm4py.discover_handover_of_work_network(log)
    pm4py.view_sna(handover_net)

    # Discover working together network
    together_net = pm4py.discover_working_together_network(log)
    pm4py.view_sna(together_net)

    # Discover performance DFG
    perf_dfg = pm4py.discover_performance_dfg(log)
    pm4py.view_performance_dfg(perf_dfg)

    # Get variants to analyze rework loops
    variants = pm4py.get_variants(log)

    return {
        'handover_network': handover_net,
        'working_together': together_net,
        'performance_dfg': perf_dfg,
        'variants': variants,
        'waiting_times': pm4py.get_service_time(log)
    }

def evaluate_policy_compliance(df, assignments):
    """Evaluate how well assignments follow policy rules"""
    # Convert assignments to DataFrame
    assignment_df = pd.DataFrame(assignments, columns=['case', 'resource'])

    # Check skill requirements
    violations = []
    for _, row in assignment_df.iterrows():
        case = df[df['case:concept:name'] == row['case']].iloc[0]
        resource = next(r for r in resources if r['resource'] == row['resource'])

        # Check minimum skill
        min_skill = get_min_skill(case['required_skill'])
        if resource['skills'][case['required_skill']] < min_skill:
            violations.append({
                'case': row['case'],
                'rule': 'skill_requirement',
                'details': f"Assigned {resource['resource']} (skill {resource['skills'][case['required_skill']]}) to {case['required_skill']} (min {min_skill})"
            })

        # Check overtime risk
        if resource['overtime_risk'] == 'high' and case['case_priority'] != 'urgent':
            violations.append({
                'case': row['case'],
                'rule': 'overtime_risk',
                'details': f"Assigned urgent case to high overtime risk resource {resource['resource']}"
            })

    return violations
```
