normative_net, initial_marking, final_marking = pm4py.convert_to_petri_net(normative_tree)

# 3. Expand variant-frequency tables into logs (simulating parse_event_log_string)

jun_jul_variants = "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify|Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify|Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision"
aug_sep_variants = "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify|Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify"

alignments_raw = apply_replay_log(jun_jul_log, normative_net, initial_marking, final_marking)
fitness_raw = evaluate_fitness(jun_jul_log, alignments_raw)
print(f"Raw fitness (Jun-Jul): {fitness_raw}")

# 6. Normalization pipeline: map Risk Screen -> Classify, remove Queue Routed
def normalize_log(log):
    normalized = log_factory.create()
    for case in log:
        new_case = log_factory.create_case()
        for event in case:
            act = event['concept:name']
            if act == 'Risk Screen':
                act = 'Classify'
            if act == 'Queue Routed':
                continue
            new_event = {'concept:name': act, 'time:timestamp': event['time:timestamp']}
            new_case.append(new_event)
        normalized.append(new_case)
    return normalized

jun_jul_norm = normalize_log(jun_jul_log)
alignments_norm = apply_replay_log(jun_jul_norm, normative_net, initial_marking, final_marking)
fitness_norm = evaluate_fitness(jun_jul_norm, alignments_norm)

## 7. Provisional conclusion

The measured conformance collapse is primarily a measurement artifact driven by three compounding data-provenance and modeling shifts: the UI label rename (`Classify`  `Risk Screen`), the injection of the technical `Queue Routed` event, and the ETL timestamp substitution that inverted `Decision` and `Notify` ordering. These factors alone explain the majority of the alignment cost increase, as demonstrated by the staged fitness recovery (32%  89%) after semantic normalization and source-sequence reordering. A secondary contributor is normative model obsolescence: the August policy introducing conditional `Supervisor Sign-off` was not reflected in the control-flow-only process tree, causing additional false deviations until an extended model was applied.

Regarding a real compliance problem, the evidence suggests limited operational risk. Aggregate business outcomes (cycle times, approval rates, appeal rates) remain statistically stable, indicating that the underlying decision logic and customer impact have not degraded. However, the persistent subset of enhanced-review cases missing a recorded compliance check (25–30 per period) warrants scrutiny. While this may reflect extraction gaps or legitimate routing corrections via `Manual Override`, it cannot be dismissed as purely artifactual without targeted auditing.

Confidence in the primary explanation (data/model artifacts) is high (85–90%). Confidence in the absence of widespread noncompliance is moderate (60–70%), constrained by incomplete incident detection and the small sample size of missing-check cases.

Immediate actions: IT must revert the ETL timestamp logic to source-system sequence numbers and publish a formal event-semantic dictionary mapping UI labels to canonical process terms. Process owners should update the normative model to include the optional `Supervisor Sign-off` branch and encode the EUR 50,000 threshold as a data-aware constraint. Compliance should initiate a stratified manual audit of the missing compliance-check cases, focusing on high-value claims and specific reviewer resources, to distinguish extraction failures from intentional bypasses.

Crucially, we must not claim that conformance has fully recovered based solely on fitness metrics, as overpermissive model extensions can mask residual violations. We also must not assert that employee behavior is flawless; stable outcomes do not rule out localized noncompliance that is currently offset by compensating controls or undetected by aggregate metrics.

## 8. Model-governance recommendation

1. **Model Versioning & Change Control:** Every normative process model must be version-controlled and tied to a specific policy effective date. Conformance jobs must explicitly reference the model version active during the log period, preventing anachronistic comparisons.
2. **Event-Semantic Contracts:** UI and system label changes must be governed by a canonical event dictionary. Release pipelines must automatically map new interface labels to existing process terms, and any unmapped label must trigger a conformance pipeline halt until a semantic mapping is approved.
3. **Technical-Event Policy:** All non-user-facing system events (e.g., routing, queueing, batch jobs) must be tagged with a `technical_event=true` attribute. Conformance checking must exclude these events by default, with explicit opt-in only for audited routing logic.
4. **Timestamp Provenance & Ordering:** Event logs must preserve the original source-system sequence number or transaction timestamp as an immutable attribute. ETL pipelines are prohibited from substituting ingestion or warehouse timestamps for control-flow ordering; alignment must always prioritize source provenance.
5. **Data-Aware Constraints:** Control-flow models must be supplemented with declarative data constraints (e.g., OCL or PM4Py data-aware extensions) to enforce conditional requirements like the EUR 50,000 supervisor sign-off. Purely structural trees cannot validate attribute-dependent compliance.
6. **Post-Release Validation Gate:** Before any UI, ETL, or policy change goes live, a shadow conformance run must compare pre- and post-change logs using standardized fitness, precision, and alignment-move diagnostics. A fitness drop >5% without a corresponding model update or semantic mapping blocks production deployment.
