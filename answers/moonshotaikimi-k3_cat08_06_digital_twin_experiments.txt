def generate_arrivals(self, t0, t1):
    t = t0

A short framing note: the design below treats the digital twin as a **discrete-event simulation (DES) calibrated from process mining**, with an explicit separation between the PM4Py layer (log/model handling, parameter extraction) and the simulation layer (arrivals, routing, resources, cross-case coupling). # 1. Model scope and state variables

## 1.1 Boundary and level of detail

- **In scope**: from `Submit application` (portal) to `Issue permit` / `Reject application`, including applicant response delays, public-notice period, inspections, rework loops, and resource contention.
- **Exogenous but modeled**: applicant behavior (missing-document response, inspection readiness/no-shows), neighborhood objections (latent process — see §2.7 and §3), architects as arrival-cluster generators.
- **Out of scope**: pre-design work by architects (except as a D1-induced submission delay), post-decision construction, and emergency decisions (removed from the log — a documented bias, handled in §3 and §6).
- **Granularity**: activity-level DES, event timestamps at minute resolution, simulation clock in float days with origin 2026-01-01. Resources are modeled as **role pools with calendars**, not individual employees, except where the log shows structural assignment rules (e.g., two planners restricted to Simple renovation, one clerk on Monday portal support). This matches log granularity and avoids overfitting.

## 1.2 Entities and attributes

| Entity | Key attributes |
|---|---|
| Case | case_id, case_type, district, architect_id, application_value, requires_fire / requires_environment / requires_public_notice flags, arrival_time, current node(s) in the parallel region, loop counters (completeness, inspection, legal/appeal), latent objection flag, bundle_id, SLA class, priority |
| ArchitectCluster | architect_id, parent arrival time, offspring count, intra-cluster spread (days), shared "document quality" random effect |
| ObjectionEvent (latent) | neighborhood/district, onset time, affected case set, notice-extension draw |
| InspectionBundle | district, open case list, max size, max hold time, planned route/travel time |

## 1.3 Resources, queues, calendars

| Pool | Capacity & calendar | Queue discipline |
|---|---|---|
| Clerks | 5 FTE, Mon–Fri 08:00–16:00; 1 clerk reserved for portal support on Mondays | FIFO; Monday spike reproduced |
| Planners | 8 FTE, Mon–Fri 09:00–17:00; 2 restricted to Simple renovation | FIFO; optional aging-priority lane (D6) |
| Fire reviewers | 2 FTE-equivalent, Tue–Thu only | FIFO |
| Environmental reviewers | 3 FTE Mon–Fri, 40% of time reserved for non-permit duties  effective 0.6 × 3 | FIFO; optional triage fast lane (D8) |
| Inspectors | 4 FTE, field visits Tue–Fri; district-dependent travel; batching possible | Staging queue per district with bundle release rule (size  k or max hold) |
| Legal officers | 2 FTE; unavailable during council-meeting weeks except urgent cases | FIFO with urgent override |
| System tasks | Effectively infinite capacity | No queue |

Calendars are **capacity functions of time**: weekly templates × holiday calendar × council-week blackouts × seasonal extra capacity (D4). Work only accrues during working hours; waiting accrues in wall-clock time.

## 1.4 State variables

- Global: clock, season index (month, weekday), holiday/council flags, policy toggles (D1–D10).
- Per-case: process location (including *set* of active branches in the parallel region), remaining service (in working minutes), loop counts, latent objection state, bundle membership.
- Per-pool: busy/available count over time, queue contents and ages, utilization accumulators.
- Dependency state: active architect clusters, open inspection bundles per district, active objection events and their affected-case sets.
- KPI accumulators: cycle times, waiting/service per activity, backlog age profile, rework counts, SLA flags.

## 1.5 Cross-case dependencies (explicitly modeled, not assumed away)

1. **Resource contention** — all cases share pools (the baseline coupling).
2. **Architect submission clusters** — correlated arrivals; a shared per-architect quality effect correlates missing-document probability within a cluster.
3. **Latent objection events** — one objection event extends the public-notice period of *several* related cases simultaneously (shared shock), consistent with the proxy in the log.
4. **Inspection bundling** — cases in the same district are held in a staging queue and released as a bundle: per-case travel time drops, but the first case in a bundle waits longer. This is a first-class trade-off in the model, matching D3.

- Where start/complete lifecycle pairs exist, fit per-activity, per-case-type distributions (compare lognormal/gamma/Weibull by AIC; use empirical quantiles where fits are poor).
- Where only completion timestamps exist, service time is **not identifiable from the log alone**. Strategy: quantile-match a lognormal to the *documented* median and p90 service summaries ( = ln median;  = (ln p90  ln median)/z.), then treat the waiting/service split as a **bounded sensitivity parameter** (§5.4). The performance DFG gives sojourn time (waiting + service of the target activity, possibly distorted by calendar gaps), which is an **upper bound** on service — never equate the two.
- Convert wall-clock service into **working minutes** using the pool calendars, so that calendar interruptions (council weeks, holidays) emerge from the model rather than being baked into durations.

## 2.4 Waiting times

- Waiting = sojourn  service, calendar-adjusted. Because the split is partly inferred, we fit waiting and service **jointly** so that simulated sojourn times reproduce the observed medians (e.g., 6 d before Planning review, 8 d before Site inspection) and the service quantiles simultaneously. Report the identification interval, not a point value.

## 2.5 Branching probabilities and routing

- From `pm4py.get_variants` joined to case attributes: P(missing docs), P(fire), P(environmental), P(public notice), P(legal check), P(reject), each stratified by case_type and district.
- For thresholds missing from the log (fire area threshold, environmental sensitivity), fit logistic models on available attributes and **calibrate the intercept so predicted shares match observed variant shares** per stratum; flag these as calibrated, not observed.
- `Decision drafting` is modeled as a **join**: it starts only when all applicable branches (planning, fire, environmental, public notice, inspection) have completed — matching the known rule and the observed "waits for all review results".

## 2.6 Rework

- Detect loops from variants (repeated `Completeness check`, repeated `Site inspection`, legal/appeal re-entries). Estimate per-loop probabilities by case type and a loop-count distribution (geometric, truncated at observed max). Because rework *reasons* are unstructured text, rework is modeled as an exogenous probability; interventions that claim to reduce rework (D1, D6) are parameterized by an assumed reduction factor with a sensitivity range — never treated as known.

## 2.7 Latent objections

- Objection events are **not observed**. Fit a two-component mixture on `Public-notice period` duration: component 1  fixed 14 d minimum + small noise; component 2  long-tailed (~60 d) with objections. The mixing weight is an *estimate* of P(objection) by case type/district, reported with a plausibility interval. D9 is modeled as compressing component 2 (earlier detection), with the compression factor as a scenario parameter.

## 2.8 Calendars and travel

- Encode HR-reconstructed calendars as capacity functions; validate by checking that simulated activity timestamps fall on plausible weekdays/hours (e.g., fire reviews only Tue–Thu; legal output near zero in council weeks).
- Travel time per district from inspection-duration residuals; D3/D5 get inflated travel. Bundling: per-case travel  base + route/n style sharing, calibrated so simulated savings match any historically observable batching.

# 3. Assumptions

**Arrivals**
- A1. Within a (month, weekday) stratum, arrivals are Poisson with multiplicative intensity; no year-over-year trend (a trend term is a stress-scenario knob).
- A2. Architect bursts follow the fitted cluster process; cluster offspring have the submitting architect's case-type mix.
- A3. D1 shifts submissions later by an applicant preparation delay and reduces missing-doc probability; the magnitude is a scenario parameter, not a measured effect.

**Service times**
- A4. Service times are stationary within (activity, case type) and lognormal unless the fit rejects it; quantile-matched where start timestamps are missing.
- A5. Service accrues only during the pool's working calendar; no overtime except in stress scenarios.

**Routing**
- A6. Observed flags drive routing where present; missing thresholds are replaced by calibrated probabilities that reproduce observed variant shares.
- A7. Fire/environmental/public-notice requirements are independent given attributes (checked against observed co-occurrence; relaxed if rejected).

**Resources/calendars**
- A8. HR calendars are accurate; absenteeism is ignored in the baseline and tested in a stress scenario.
- A9. Environmental reviewers' permit-available capacity is 60% of FTE; system tasks never block.

**Rework**
- A10. Loop repetitions are conditionally independent given case type; rework service times equal first-pass service times (no learning effect).

**Applicant/third-party response**
- A11. Response delays are heavy-tailed (lognormal vs Pareto chosen by AIC), independent of municipal workload; consultant-report delays are folded into environmental-review variability.

**Cross-case dependencies**
- A12. Bundling occurs only within a district and a maximum hold window; objection events affect cases within a neighborhood and a time window; no other hidden coupling.

**Non-stationary demand**
- A13. Seasonality is periodic with a 12-month cycle (periodic steady state), which drives the warm-up and batching design in §5.

**Missing data**
- A14. Missing start timestamps are missing at random within activity; the waiting/service split is reported as an interval.
- A15. Removed emergency decisions bias the tail downward; we report this bias direction explicitly and do not "correct" it with invented data.
- A16. Objection mixture weights are latent-class estimates with wide intervals; conclusions about D9 are stated conditionally.

# 5. Warm-up, replications, and uncertainty treatment

## 5.1 Warm-up
- The system is **periodically non-stationary** (12-month cycle), so we target *periodic* steady state: warm-up = one full seasonal cycle (365 d), started in January (low season), with initial backlog sampled from the empirical open-case snapshot to reduce initialization bias.
- Confirm warm-up length with Welch's graphical method / MSER-5 on weekly backlog and weekly completed-case cycle time; extend if the backlog age distribution has not stabilized (the 260-d tail of Complex variance cases forces warm-up  the tail scale).

## 5.2 Run length and batching
- Data collection horizon: 24 months (2 full cycles) per replication; sensitivity check at 36 months.
- Because of periodicity, use **cycle-consistent batch means** (weekly batches aligned to the seasonal phase) rather than naive i.i.d. batching.

## 5.3 Replications and seeds
- Start with 40 replications per scenario; adaptively add replications until the 95% CI half-width is 5% of the mean for mean cycle time and 10% for p90.
- **Common random numbers** across B0 and all D-scenarios (same `SeedSequence` spawn per replication) for variance reduction on *differences*; seeds logged for reproducibility.

## 5.4 Uncertainty treatment
- **Stochastic uncertainty**: t-based CIs on replication means; bootstrap percentile CIs for medians/p90s.
- **Parameter uncertainty**: two-level Monte Carlo — bootstrap the event log at the *case-cluster* level (resample architect clusters whole, preserving dependence), refit key parameters, and run a reduced ensemble (e.g., 10 parameter sets × 10 replications) to produce credible intervals for KPI differences.
- **Sensitivity analysis**: Morris screening over ~12 key parameters (missing-doc probability, objection probability and tail, service-time , waiting/service split bounds, inspector capacity, bundling window), then Sobol indices on the top 5. The waiting/service split (§2.4) is always varied across its identification interval.
- **Heavy tails**: no trimming. Use median + p90 as primary statistics, quantile CIs, optional generalized-Pareto tail fit for extrapolation; cases censored at the horizon are handled with Kaplan–Meier estimates of duration survival curves so long cases are not silently dropped.

# 6. Validation strategy

1. **Face validation**: structured walkthroughs with clerks, planners, inspectors, legal officers; review of calendars, queue disciplines, bundling rule, and D-policy mechanics; sign-off on assumption list §3.
2. **Event-log replay validation**: convert the reference tree via `pm4py.convert_to_petri_net` and run `pm4py.conformance_diagnostics_token_based_replay` (and alignments via `pm4py.conformance_diagnostics_alignments`) of the historical log against the reference model to quantify fitness; replay a *simulated* log as well and compare fitness/precision — a simulated log that fits much better than the real one signals an over-simplified model.
3. **Distributional validation**: overlay simulated vs historical distributions of case duration per variant group (median, p90), per-activity waiting, weekly arrival counts, and variant shares; use Wasserstein distance and KS/AD tests with multiple-comparison caution; Q-Q plots for tails.
4. **Resource-utilization validation**: simulated utilization per pool vs HR-informed expectations (e.g., fire reviewers loaded only Tue–Thu; environmental permit-utilization consistent with the 60% availability rule; Monday clerk spike reproduced).
5. **Bottleneck validation**: the model must reproduce the known bottlenecks (post-Monday completeness queue, inspection backlog, legal stalls in council weeks). Perturbation test: +1 inspector must relieve the inspection queue in D3/D5; if it does not, the calendar/travel submodel is wrong.
6. **Out-of-sample validation**: temporal split — calibrate on months 1–12, validate on months 13–18 (and reverse); hold out the "other rare variants" group; backcast any known historical change if one exists in the period. Cross-case checks: simulated same-architect same-week counts and objection-correlated notice extensions vs their empirical proxies.

# 7. Decision criteria

Metrics (per case type unless stated):

- **Duration**: median and p90 end-to-end; SLA compliance (illustrative SLAs pending council ratification: Simple 30 d, New residential 90 d, Commercial 130 d, Complex 260 d).
- **Flow**: throughput, backlog size and age profile, rework loops per case.
- **Resources**: utilization per pool — target band 0.70–0.85; sustained >0.90 is a rejection flag (fragility).
- **Fairness**: ratio of p90 duration across districts (max/min  1.25), top-20 architects vs rest; no case type loses >2 pp SLA compliance.
- **Quality/risk**: expected undetected-violation exposure for D2 (reported, not monetized silently).
- **Robustness**: worst-case SLA compliance across S1–S4; minimax-regret comparison of shortlisted policies.
- **Cost-effectiveness**: cost per case-day of p90 saved (e.g., D4's temporary-inspector cost).

Selection rule (example, to be ratified): shortlist interventions with 10% median *or* 15% p90 improvement vs baseline with CRN-paired CIs excluding zero, no fairness violation, utilization within band, and robustness (SLA drop 5 pp under S1–S3). Prefer D10 over components only if its paired improvement exceeds the best single policy beyond the interaction uncertainty interval. All recommendations are stated as "best under the validated model and stated assumptions", never as optimal.

def mine_process_knowledge(log: pd.DataFrame) -> dict:
    # Variants: keys are activity tuples for a formatted pandas log.
    variants = pm4py.get_variants(log)
    variant_counts = sorted(
        ((v, c if isinstance(c, int) else len(c)) for v, c in variants.items()),
        key=lambda kv: -kv[1],
    )

    # DFG and performance DFG. IMPORTANT: performance-DFG edge values are
    # times between CONSECUTIVE events, i.e. sojourn time (waiting + service
    # of the target activity, plus calendar gaps) -- pure service time is NOT
    # identifiable where start timestamps are missing. business_hours=True is
    # available as an option in discover_performance_dfg.
    dfg, start_acts, end_acts = pm4py.discover_dfg(log)
    perf_dfg, p_start, p_end = pm4py.discover_performance_dfg(log)

    arrival_avg_s = pm4py.get_case_arrival_average(log)      # seconds between case starts
    case_durations = pm4py.get_all_case_durations(log)       # seconds

    # Data-driven tree for reconciliation with the reference tree
    # (meaningful only on the full log).
    discovered_tree = pm4py.discover_process_tree_inductive(log)

    ref_tree, ref_err = get_reference_tree()

    return {
        "variant_counts": variant_counts,
        "dfg": dfg, "start_activities": start_acts, "end_activities": end_acts,
        "performance_dfg": perf_dfg,
        "case_arrival_average_days": arrival_avg_s / 86400.0,
        "case_durations_days": [d / 86400.0 for d in case_durations],
        "reference_tree": ref_tree, "reference_tree_error": ref_err,
        "discovered_tree": discovered_tree,
    }


def add_timing_columns(log: pd.DataFrame) -> pd.DataFrame:
    """Waiting-from-previous-event always; service time ONLY if start
    timestamps (or lifecycle transitions) exist. Never conflate the two."""
    df = log.sort_values(["case:concept:name", "time:timestamp"]).copy()
    prev_ts = df.groupby("case:concept:name")["time:timestamp"].shift(1)
    df["wait_from_prev_event_s"] = (df["time:timestamp"] - prev_ts).dt.total_seconds()
    start_candidates = [c for c in df.columns
                        if c.lower() in ("start_timestamp", "time:starttimestamp")]
    if start_candidates:
        st = pd.to_datetime(df[start_candidates[0]])
        df["service_time_s"] = (df["time:timestamp"] - st).dt.total_seconds()
    else:
        df["service_time_s"] = np.nan  # completion-only log: not identifiable
    return df


def arrival_profile(log: pd.DataFrame) -> pd.DataFrame:
    """First event per case -> NHPP covariates (month, weekday) for fitting
    lambda(t) = lambda0 * month_factor * weekday_factor, plus architect
    cluster statistics (same architect, <=7 days apart)."""
    first = log.groupby("case:concept:name").agg(
        arrival=("time:timestamp", "min"),
        architect_id=("architect_id", "first"),
        district=("district", "first"),
        case_type=("case_type", "first"),
    )
    first["month"] = first["arrival"].dt.month
    first["weekday"] = first["arrival"].dt.dayofweek
    return first

@dataclass
class Calendar:
    """Capacity as a function of simulation time (float days from origin)."""
    workdays: Tuple[int, ...] = (0, 1, 2, 3, 4)   # Mon=0
    day_start_h: float = 8.0
    day_end_h: float = 16.0
    holidays: set = field(default_factory=set)     # ordinal dates
    blackout_weeks: set = field(default_factory=set)  # e.g. council weeks (legal)
    availability: float = 1.0                       # e.g. 0.6 environmental

    def is_working(self, t: float) -> bool:
        day = int(t)
        wd = day % 7  # align origin so weekday mapping matches 2026 calendar
        if wd not in self.workdays or day in self.holidays:
            return False
        if (day // 7) in self.blackout_weeks:
            return False
        frac = t - day
        return self.day_start_h / 24.0 <= frac < self.day_end_h / 24.0

    def next_work_start(self, t: float) -> float:
        while not self.is_working(t):
            t = int(t) + 1 + self.day_start_h / 24.0
        return t

class ArrivalGenerator:
    """NHPP by (month, weekday) via Lewis-Shedler thinning, plus a
    Neyman-Scott-style architect cluster process (offspring within ~7 days,
    same architect, usually same district)."""

    def __init__(self, base_rate_per_day, month_factors, weekday_factors,
                 cluster_prob, cluster_size_lambda, rng):
        self.base, self.mf, self.wf = base_rate_per_day, month_factors, weekday_factors
        self.cluster_prob, self.cluster_lambda = cluster_prob, cluster_size_lambda
        self.rng = rng

    def intensity(self, t: float) -> float:
        month = 1 + (int(t) % 365) // 30
        weekday = int(t) % 7
        return self.base * self.mf.get(month, 1.0) * self.wf.get(weekday, 1.0)

    def generate(self, t0: float, t1: float) -> List[Tuple[float, Optional[str]]]:
        lam_max = self.base * max(self.mf.values()) * max(self.wf.values())
        arrivals, t = [], t0
        while t < t1:
            t += self.rng.exponential(1.0 / lam_max)
            if t >= t1:
                break
            if self.rng.uniform() < self.intensity(t) / lam_max:
                arrivals.append((t, None))
                if self.rng.uniform() < self.cluster_prob:      # architect burst
                    k = 1 + self.rng.poisson(self.cluster_lambda)
                    cid = f"CLU-{len(arrivals)}"
                    for _ in range(k):
                        arrivals.append((t + self.rng.uniform(0, 7), cid))
        return sorted(arrivals)


class Router:
    """Attribute-driven routing + rework probabilities, per case type.
    Values below are PLACEHOLDERS to be replaced by the fitted values from
    variants/logistic models (Section 2.5-2.6). Policy toggles implement D1-D9."""

    DEFAULT = {
        "Simple renovation": dict(p_missing=0.35, p_fire=0.05, p_env=0.02,
                                  p_notice=0.05, p_legal=0.20, p_reject=0.05,
                                  p_plan_rework=0.05, p_insp_rework=0.08,
                                  p_legal_rework=0.03, p_objection=0.05),
        "New residential":   dict(p_missing=0.30, p_fire=0.80, p_env=0.10,
                                  p_notice=0.60, p_legal=0.40, p_reject=0.08,
                                  p_plan_rework=0.10, p_insp_rework=0.10,
                                  p_legal_rework=0.05, p_objection=0.20),
        # "Commercial", "Complex variance": analogous, fitted from the log.
    }

    def __init__(self, probs=None, policy: Optional[dict] = None, rng=None):
        self.probs = probs or self.DEFAULT
        self.policy = policy or {}
        self.rng = rng or np.random.default_rng(0)

    def required_branches(self, case: Case) -> set:
        p = self.probs[case.case_type]
        branches = {"Planning review"}
        if case.requires_fire or self.rng.uniform() < p["p_fire"]:
            branches.add("Fire-safety review")
        if case.requires_environment or self.rng.uniform() < p["p_env"]:
            branches.add("Environmental review")
        if case.requires_public_notice or self.rng.uniform() < p["p_notice"]:
            branches.add("Public-notice period")
        return branches

    def skip_inspection(self, case: Case) -> bool:
        # D2: low-risk Simple renovation rule (threshold from policy config).
        pol = self.policy.get("skip_inspection_rule")
        return bool(pol and case.case_type == "Simple renovation"
                    and case.application_value < pol["value_threshold"]
                    and not case.loops.get("violation_flag", False))

    def needs_legal(self, case: Case) -> bool:
        return self.rng.uniform() < self.probs[case.case_type]["p_legal"]

    def sample_rework(self, case: Case, stage: str) -> bool:
        return self.rng.uniform() < self.probs[case.case_type][f"p_{stage}_rework"]


class PermitTwin:
    """Heap-based DES core. Flow: completeness loop -> parallel reviews
    (fork/join via Case.pending_branches) -> optional public notice (latent
    objection shocks can extend several related cases) -> inspection staging
    with district bundling -> decision drafting (join) -> optional legal ->
    issue/reject, with case-type-dependent rework loops."""

    def __init__(self, config: dict, rng: np.random.Generator):
        self.config, self.rng = config, rng
        self.events: List[Tuple[float, int, str, object]] = []
        self._counter = itertools.count()
        self.pools = self._build_pools()
        self.arrivals = ArrivalGenerator(**config["arrival_params"], rng=rng)
        self.router = Router(policy=config.get("policy"), rng=rng)
        self.staging: Dict[str, List[Case]] = {}   # district -> bundle staging
        self.kpis = {"durations": [], "backlog_ts": [], "rework": 0}

    def _build_pools(self) -> Dict[str, ResourcePool]:
        return {
            "clerk":  ResourcePool("clerk", 5, Calendar(8.0 and 8.0, 16.0) if False
                                   else Calendar(day_start_h=8.0, day_end_h=16.0)),
            "planner": ResourcePool("planner", 8, Calendar(day_start_h=9.0, day_end_h=17.0)),
            "fire":   ResourcePool("fire", 2, Calendar(workdays=(1, 2, 3))),   # Tue-Thu
            "env":    ResourcePool("env", 3, Calendar(availability=0.6)),
            "inspector": ResourcePool("inspector", 4, Calendar(workdays=(1, 2, 3, 4)),
                                      seasonal_extra=self.config.get("seasonal_inspector", {})),
            "legal":  ResourcePool("legal", 2, Calendar(blackout_weeks=set(
                                      self.config.get("council_weeks", [])))),
        }

    def schedule(self, t: float, kind: str, payload: object) -> None:
        heapq.heappush(self.events, (t, next(self._counter), kind, payload))

    # --- handlers (bodies are calibrated placeholders) ---
    def on_arrival(self, case: Case): ...          # enter completeness queue
    def on_activity_complete(self, case: Case, activity: str): ...
    def on_bundle_release(self, district: str): ...  # D3: size>=k or max hold
    def on_objection_event(self, event): ...         # latent shared shock (D9)

    def run(self, warmup_days: float, horizon_days: float) -> dict:
        for t, cid in self.arrivals.generate(0.0, warmup_days + horizon_days):
            self.schedule(t, "ARRIVAL", cid)
        while self.events:
            t, _, kind, payload = heapq.heappop(self.events)
            if t > warmup_days + horizon_days:
                break
            # dispatch to handlers; KPI collection only for t >= warmup_days
            # and only for cases arriving after warm-up (periodic steady state).
            ...
        return self.kpis

def merged(base: dict, overrides: dict) -> dict:
    out = {**base, **overrides}
    out["policy"] = {**base.get("policy", {}), **overrides.get("policy", {})}
    return out


def run_experiment(name: str, overrides: dict, n_reps: int = 40,
                   warmup_days: float = 365.0, horizon_days: float = 730.0,
                   master_seed: int = 42) -> pd.DataFrame:
    rows = []
    seed_seq = np.random.SeedSequence(master_seed)
    for rep, child in enumerate(seed_seq.spawn(n_reps)):
        rng = np.random.default_rng(child)   # CRN: same seeds for every scenario
        sim = PermitTwin(config=merged(BASELINE, overrides), rng=rng)
        kpis = sim.run(warmup_days, horizon_days)
        d = np.asarray(kpis["durations"], dtype=float)
        rows.append({"experiment": name, "rep": rep,
                     "median_days": np.median(d), "p90_days": np.percentile(d, 90)})
    return pd.DataFrame(rows)

Key implementation notes for the skeleton:

- **PM4Py separation**: everything PM4Py-specific lives in `load_*`, `mine_process_knowledge`, `add_timing_columns`, and `arrival_profile`. `PermitTwin`, `ArrivalGenerator`, `Router`, `ResourcePool`, and `run_experiment` consume only plain dicts/DataFrames, so the engine can be swapped (e.g., to SimPy) without touching the mining layer.
- **Service vs waiting**: `add_timing_columns` emits `service_time_s` only when start timestamps exist; the performance DFG is used strictly as a sojourn-time upper bound, consistent with the missing-start-timestamp limitation.
- **Cross-case coupling hooks**: `cluster_id` on cases, `staging` per district for bundling, and `on_objection_event` for the latent shared shock — the model is not an independent-case simulation.
- **Calendars**: every pool carries a `Calendar`; seasonal capacity (D4) and council-week blackouts (legal) are capacity changes, not duration fudge factors.
