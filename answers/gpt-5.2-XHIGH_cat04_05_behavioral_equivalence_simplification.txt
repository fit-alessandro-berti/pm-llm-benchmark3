# 1. Equivalence Notions

Let \(\Sigma=\{\)Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, Close Case\(\}\). A **complete run** is any execution from the initial state to proper completion (final marking / successful termination). A **visible trace** is the sequence of labels observed along a complete run.

## Visible trace equivalence after hiding `tau`

- **Hiding**: map each complete run to a word in \(\Sigma^\*\) by erasing every silent event (`tau` in the tree and any unlabeled/silent transition created by compilation), and keeping all visible labels.
- **Equivalence**: \(A \equiv_{\text{vis}} B\) iff the visible languages are equal:
  \[
  L_{\text{vis}}(M)=\{\text{hide}_\tau(\rho)\mid \rho\text{ is a complete run of }M\},\quad
  L_{\text{vis}}(A)=L_{\text{vis}}(B).
  \]
- **Duplicate labels**: **distinguished by occurrence position** (standard word semantics). Two traces are equal only if they are identical sequences, including multiplicities.

## Bounded visible-language equivalence (P3)

P3 compares only complete visible traces within a bound:

- **Bound**: \(|w|\le 12\) visible events and \(\#_{\text{Analyze Revision}}(w)\le 3\).
- **Bounded language**:
  \[
  L_{P3}(M)=\{w\in L_{\text{vis}}(M)\mid |w|\le 12,\ \#_{\text{Analyze}}(w)\le 3\}.
  \]
- **Equivalence**: \(A \equiv_{P3} B\) iff \(L_{P3}(A)=L_{P3}(B)\).
- **Duplicate labels**: still distinguished by position (no further abstraction besides hiding `tau` and applying the bound).

## Business-relevant equivalence (P1: operational compliance)

P1 keeps all visible labels (including Approve Revision) and is sensitive to **per-attempt checks**.

- **Attempt segmentation**: in a visible trace \(w\), each `Rework Case` is a separator between analysis attempts; the final attempt ends at `Close Case`.
- **Compliance predicate** \(C_{P1}(w)\): for every attempt segment \(s\),
  - \(s\) contains an `Analyze Revision`, and
  - there is a `Check Revision` **before** the boundary that ends the attempt (the next `Rework Case` or the final `Close Case`).
  (Approve Revision is optional; its count and position remain visible.)
- **P1-equivalence**: \(A \equiv_{P1} B\) iff they induce the same set of compliant visible traces:
  \[
  \{w\in L_{\text{vis}}(A)\mid C_{P1}(w)\}=\{w\in L_{\text{vis}}(B)\mid C_{P1}(w)\}.
  \]
- **Duplicate labels**: distinguished by position (especially approvals and separators); P1 does not collapse repeated checks.

## Abstracted dashboard equivalence (P2: executive)

P2 defines an observation function \(D(\cdot)\) that hides Approve and `tau`, collapses checks to a boolean, and ignores Analyze–Check interleaving.

- **Dashboard abstraction** for a complete visible trace \(w\):
  - must have `Open Case` first and `Close Case` last;
  - \(n_A(w)=\#_{\text{Analyze Revision}}(w)\) (count is kept);
  - \(hasCheck(w)=\mathbb{1}[\#_{\text{Check Revision}}(w)\ge 1]\) (boolean);
  - \(hasRework(w)=\mathbb{1}[\#_{\text{Rework Case}}(w)\ge 1]\) (boolean);
  - ignore all `Approve Revision` and silent behavior; do not record the exact interleaving of Analyze and Check.
  So \(D(w)=(n_A(w), hasCheck(w), hasRework(w))\) under the Open/Close constraint.
- **P2-equivalence**: \(A \equiv_{P2} B\) iff \(\{D(w)\mid w\in L_{\text{vis}}(A)\}=\{D(w)\mid w\in L_{\text{vis}}(B)\}\).
- **Duplicate labels**:
  - Analyze duplicates are **counted** (\(n_A\));
  - Check duplicates are **collapsed** (boolean);
  - Rework duplicates are **collapsed** (boolean);
  - Approve duplicates are **hidden**.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| **Loop scope** | Loop encloses `+ (Analyze, Check)` and optional `Approve` | Loop encloses `Analyze` and optional `Approve`; `Check` is outside | A binds a check to each loop iteration; B makes check case-level |
| **Minimum #Check Revision** | \(\ge 1\); in fact equals \(\#\)iterations \(\ge 1\) | Exactly 1 per case | B can never produce two checks, even with two analyses |
| **Maximum #Check Revision** | Unbounded (grows with iterations) | 1 | Visible-language sets differ as soon as \(\#\)iterations \(>1\) |
| **Placement of Check Revision** | In every iteration, before any `Approve` and before the next `Rework`/`Close`; can be before or after `Analyze` (due to `+`) | Anywhere after `Open` and before `Close`; can be between `Analyze` and `Approve`, after `Approve`, or after a `Rework` | B admits “late checks” w.r.t. specific attempts; A forbids them |
| **Approve Revision optionality** | Optional **per iteration** (X(Approve, tau)) | Optional **per iteration** (same X) | Both can have 0..k approvals for k analyses, but their relation to checks differs |
| **Approve–Check relation** | `Approve` can occur only after both `Analyze` and `Check` of that iteration | `Approve` occurs after its `Analyze`, independent of the (single) `Check` | B allows `Approve` before the check; A does not |
| **Concurrency** | Only `Analyze` \(\parallel\) `Check` inside each iteration | `Check` \(\parallel\) (entire revision loop) | B yields extra interleavings: `Check` can interleave with `Rework` and with any `Approve` |
| **Join before Close Case** | No AND-join; simply exit loop then `Close` | AND-join: must complete both `Check` and the loop before `Close` | Guarantees `Close` after the single `Check` in B, but does not enforce per-attempt checking |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---:|---|---|
| **P1 (operational compliance)** | not equivalent | High | Model B allows an analysis attempt to be followed by `Rework Case` (or by the final `Close Case`) before any check for that attempt, and can have multiple analyses with only one check | If the business instead required only “at least one check per case” (not per attempt), B could be acceptable; that is not P1 |
| **P2 (dashboard abstraction)** | equivalent only under stated abstraction | High | After hiding approvals and collapsing checks to a boolean while keeping \(\#\)analyzes and \(hasRework\), both models generate exactly the same summaries \(D(w)=(k,\text{true},k>1)\) for all \(k\ge 1\) | This equivalence is fragile: it disappears immediately if the dashboard later starts counting checks or cares about timing |
| **P3 (bounded testing)** | not equivalent | High | There are complete traces within the bound (\(|w|\le 12\), \(\#Analyze\le 3\)) that appear in A but not B (multiple checks) and in B but not A (check after approve / after rework) | Bounded agreement would not prove unbounded equivalence, but here the separating traces are already within the bound |

# 4. Counterexample Traces

Notation: `Open` = Open Case, `Analyze` = Analyze Revision, `Check` = Check Revision, `Approve` = Approve Revision, `Rework` = Rework Case, `Close` = Close Case. All traces below are complete and already have `tau` removed.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| **A≠B-1** | Open → Analyze → Check → Rework → Analyze → Check → Close | ✔ | ✘ | B has **exactly one** `Check` per case; this trace needs two checks (two attempts) | P1, P3, \( \equiv_{\text{vis}} \) |
| **A≠B-2** | Open → Check → Analyze → Approve → Rework → Analyze → Check → Approve → Close | ✔ | ✘ | Same as above: B cannot realize **two** checks; also A binds each approve to an iteration with its check | P1, P3, \( \equiv_{\text{vis}} \) |
| **B≠A-1** | Open → Analyze → Approve → Check → Close | ✘ | ✔ | In A, every `Approve` can occur only **after** the iteration’s `Check`; B allows the single check **after** approve | P1, P3, \( \equiv_{\text{vis}} \) |
| **B≠A-2** | Open → Analyze → Rework → Analyze → Check → Close | ✘ | ✔ | B allows `Rework` after an `Analyze` **without** a prior check for that attempt; A requires a check in every attempt before rework/close | P1, P3, \( \equiv_{\text{vis}} \) |
| **B≠A-3** | Open → Check → Analyze → Rework → Analyze → Close | ✘ | ✔ | Multiple analyses with only one check (second attempt has no check before close); impossible in A | P1, P3, \( \equiv_{\text{vis}} \) |

## Effect of optional `Approve Revision` and hidden `tau`

- In both models, `X('Approve Revision', tau)` means **each analysis attempt may or may not show an `Approve`**. Choosing `tau` yields no visible event, so traces without `Approve` are not “shortcuts”; they are valid outcomes.
- Hiding `tau` does **not** reconcile A and B: the separating reasons above are about **(i) how many checks occur** and **(ii) where checks may appear relative to attempt boundaries and approvals**, all of which remain visible after `tau` removal.

# 5. Bounded Comparison Code

```python
import pm4py
from collections import deque
from pm4py.objects.petri_net.obj import Marking

MODEL_A = """
->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
""".strip()

MODEL_B = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)
""".strip()


def marking_key(m):
    # Marking is a mapping Place -> token count
    return tuple(sorted((p.name, c) for p, c in m.items()))


def fire(marking, transition):
    # Minimal Petri net firing for enabled transitions.
    # Assumes the transition is enabled in 'marking'.
    new_m = Marking(marking)
    for arc in transition.in_arcs:
        p = arc.source
        w = getattr(arc, "weight", 1)
        new_m[p] = new_m.get(p, 0) - w
        if new_m[p] <= 0:
            del new_m[p]
    for arc in transition.out_arcs:
        p = arc.target
        w = getattr(arc, "weight", 1)
        new_m[p] = new_m.get(p, 0) + w
    return new_m


def bounded_complete_traces(net, im, fm, max_visible_len=12, max_analyze=3):
    """
    Exhaustive bounded exploration (NOT random playout).
    Enumerates all complete visible traces w such that:
      len(w) <= max_visible_len and count(Analyze Revision) <= max_analyze.
    Silent/unlabeled transitions do not add visible events.
    """
    start_state = (im, tuple(), 0, 0)  # (marking, trace, visible_len, analyze_count)
    q = deque([start_state])
    seen = set()
    complete = set()

    while q:
        marking, trace, vlen, acnt = q.popleft()
        state_id = (marking_key(marking), trace, vlen, acnt)
        if state_id in seen:
            continue
        seen.add(state_id)

        if marking == fm:
            complete.add(trace)
            continue

        enabled = pm4py.get_enabled_transitions(net, marking)
        for t in enabled:
            lbl = t.label  # None means silent
            nm = fire(marking, t)

            ntrace = trace
            nvlen = vlen
            nacnt = acnt

            if lbl is not None:
                ntrace = trace + (lbl,)
                nvlen = vlen + 1
                if lbl == "Analyze Revision":
                    nacnt = acnt + 1

            if nvlen > max_visible_len or nacnt > max_analyze:
                continue

            q.append((nm, ntrace, nvlen, nacnt))

    return complete


def fmt(trace):
    return " -> ".join(trace)


def main():
    tree_a = pm4py.parse_process_tree(MODEL_A)
    tree_b = pm4py.parse_process_tree(MODEL_B)

    net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
    net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

    print("Soundness A:", pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=True))
    print("Soundness B:", pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=True))

    # Exhaustive bounded exploration under P3
    LA = bounded_complete_traces(net_a, im_a, fm_a, max_visible_len=12, max_analyze=3)
    LB = bounded_complete_traces(net_b, im_b, fm_b, max_visible_len=12, max_analyze=3)

    only_a = sorted(LA - LB)
    only_b = sorted(LB - LA)

    print("\nP3-bounded complete traces:")
    print("  |LA| =", len(LA))
    print("  |LB| =", len(LB))
    print("  A\\B =", len(only_a))
    print("  B\\A =", len(only_b))

    print("\nTraces in A but not B:")
    for tr in only_a:
        print("  ", fmt(tr))

    print("\nTraces in B but not A:")
    for tr in only_b:
        print("  ", fmt(tr))

    # Non-exhaustive alternative (random/heuristic evidence only):
    # pm4py.play_out(...) samples runs; it cannot prove bounded equivalence.
    # sampled_log_a = pm4py.play_out(tree_a, parameters={"no_traces": 500, "max_trace_length": 12, "seed": 0})
    # sampled_log_b = pm4py.play_out(tree_b, parameters={"no_traces": 500, "max_trace_length": 12, "seed": 0})


if __name__ == "__main__":
    main()
```

# 6. Stochastic and Footprint Comparison

## How they can help (and their limits)

- **Footprints (`pm4py.discover_footprints`)** summarize causal/parallel relations between labels (a lossy abstraction). They can provide quick evidence of mismatch:
  - In **Model A**, `Analyze Revision` and `Check Revision` are parallel *within an iteration*, but `Check Revision` is not parallel with `Rework Case` (rework is after the iteration).
  - In **Model B**, `Check Revision` is parallel with the *whole loop*, so it can be parallel with `Rework Case` as well.
  This difference strongly suggests non-equivalence under full trace semantics, but **equal footprints would not prove equivalence** because footprints discard multiplicity, loop scoping, and many ordering constraints.

- **Stochastic language (`pm4py.get_stochastic_language`)** turns a model into a probability distribution over traces, given an explicit probabilistic semantics (e.g., probabilities for XOR choices and loop continuation/exit). Without declared probabilities, results depend on defaults/assumptions and are only indicative.

- **Earth Mover’s Distance (`pm4py.compute_emd`)** can quantify how different two stochastic languages are. A low EMD (under some probabilities) still does **not** establish trace equivalence: two models can differ on rare traces (or outside the sampled/bounded support) while having similar mass on common traces.

## Plausible evidence code

```python
import pm4py

# Assuming tree_a, tree_b already parsed as in Section 5

fp_a = pm4py.discover_footprints(tree_a)
fp_b = pm4py.discover_footprints(tree_b)

print("Footprints A:", fp_a)
print("Footprints B:", fp_b)

# Stochastic language and EMD require an explicit probabilistic semantics.
# If your pm4py version supports deriving a stochastic language from a process tree
# with default/uniform choices, you can do:

lang_a = pm4py.get_stochastic_language(tree_a, parameters={"max_trace_length": 12, "max_no_traces": 2000})
lang_b = pm4py.get_stochastic_language(tree_b, parameters={"max_trace_length": 12, "max_no_traces": 2000})

emd = pm4py.compute_emd(lang_a, lang_b)
print("EMD(lang_a, lang_b) =", emd)

# Interpretation:
# - footprints/EMD are evidence, not a proof of (non-)equivalence;
# - probabilities (if any) must be stated; changing them can change EMD drastically.
```

# 7. Complexity Comparison

Below, “node count” counts **all** process-tree nodes (operators + leaves). Depth is the maximum number of nodes on a root-to-leaf path (including both ends).

## Exact structural counts (derived from the given trees)

| Metric | Model A | Model B |
|---|---:|---:|
| **Process-tree node count** | 12 | 12 |
| **Depth** | 5 | 6 |
| **# visible leaves** | 6 | 6 |
| **# silent leaves (`tau`)** | 1 | 1 |
| **Duplicate-label count (tree-level)** | 0 | 0 |

Explanation sketch:

- Both trees have 5 operator nodes (`->`, `*`, `->`, `+`, `X`) and 7 leaves.
- Model B is deeper because `Check Revision` sits under the top-level `+` while the loop nests further beneath that `+`.

## Structural counting pseudocode (PM4Py trees)

```python
def pt_stats(node):
    # node.operator is None for leaves; node.children is a list
    if node.operator is None:
        is_silent = (node.label is None) or (str(node.label).lower() == "tau")
        return {
            "nodes": 1,
            "depth": 1,
            "visible_leaves": 0 if is_silent else 1,
            "silent_leaves": 1 if is_silent else 0,
            "labels": [] if is_silent else [node.label],
        }
    child_stats = [pt_stats(c) for c in node.children]
    labels = []
    for cs in child_stats:
        labels.extend(cs["labels"])
    return {
        "nodes": 1 + sum(cs["nodes"] for cs in child_stats),
        "depth": 1 + max(cs["depth"] for cs in child_stats),
        "visible_leaves": sum(cs["visible_leaves"] for cs in child_stats),
        "silent_leaves": sum(cs["silent_leaves"] for cs in child_stats),
        "labels": labels,
    }

def duplicate_label_count(labels):
    from collections import Counter
    c = Counter(labels)
    return sum((v - 1) for v in c.values() if v > 1)
```

# 8. Simplified Model

## Target semantics

I target **P2 (executive dashboard)** because it is the only stated view that intentionally abstracts away (i) the exact number of checks and (ii) the interleaving of checks with the revision loop, while still caring about Open/Close order, \(\#\)analyses, and whether any rework occurred.

## 8.1 Compact simplified expression

A canonical “dashboard model” that preserves \(D(w)=(\#Analyze, hasCheck, hasRework)\) while removing unnecessary concurrency and approvals:

```text
->(
  'Open Case',
  'Check Revision',
  *('Analyze Revision', 'Rework Case'),
  'Close Case'
)
```

This produces traces:
- Open, Check, Analyze, Close
- Open, Check, Analyze, Rework, Analyze, Close
- Open, Check, Analyze, Rework, Analyze, Rework, Analyze, Close
- … (any number of analyzes \(\ge 1\), with rework between attempts)

## 8.2 Self-contained PM4Py code (`simplified_model`)

```python
import pm4py

simplified_tree_str = """
->(
  'Open Case',
  'Check Revision',
  *('Analyze Revision', 'Rework Case'),
  'Close Case'
)
""".strip()

simplified_model = pm4py.parse_process_tree(simplified_tree_str)
net_s, im_s, fm_s = pm4py.convert_to_petri_net(simplified_model)
print("Soundness simplified:", pm4py.check_soundness(net_s, im_s, fm_s, print_diagnostics=True))
print("Simplicity simplified:", pm4py.simplicity_petri_net(net_s, im_s, fm_s))
```

## 8.3 Preservation table (relative to P2)

| Property | Status in simplified model | Notes |
|---|---|---|
| Open first, Close last | **Exact** | Enforced by outer `->` |
| At least one Analyze | **Exact** | Loop first child executes at least once |
| \(\#\)Analyze occurrences | **Exact** | One Analyze per loop iteration |
| “A check occurred” boolean | **Exact** | Exactly one `Check Revision` per case |
| “Any rework occurred” boolean | **Exact** | Rework occurs iff \(\#Analyze>1\) |
| Exact number of checks | **Lost / abstracted away** | Intentionally collapsed to boolean under P2 |
| Exact interleaving of Analyze vs Check | **Lost** | Check fixed before loop (canonicalization) |
| Approve Revision visibility | **Lost** | Intentionally hidden under P2 |
| P1 per-attempt check compliance | **Weakened / not guaranteed** | Not a compliance model; do not use for P1 |
| P3 bounded visible-language equality | **Not preserved** | Simplified traces differ from A/B even under bounds |

## 8.4 Regression and negative traces

### Regression (must be accepted by the simplified model)

- **R1**: Open → Check → Analyze → Close
- **R2**: Open → Check → Analyze → Rework → Analyze → Close
- **R3**: Open → Check → Analyze → Rework → Analyze → Rework → Analyze → Close

### Negative (must be rejected by the simplified model)

- **N1**: Open → Check → Close  (violates “at least one Analyze”)
- **N2**: Open → Analyze → Close  (violates “at least one Check”)

| Depth | 5 | 6 | **3** |
| # visible leaves | 6 | 6 | **5** |

# 9. Final Recommendation

- **For P1 (operational compliance)**: Prefer **Model A**. It enforces a check inside each revision attempt (and before rework/close) and keeps approvals visible per attempt. **Model B is unsuitable** because it can delay the single check past rework boundaries and cannot represent “one check per analysis attempt” when there are multiple attempts.

- **For P2 (executive dashboard)**: **Models A and B are equivalent only under the stated abstraction** \(D(w)\). Use the **simplified dashboard model** from Section 8 as the canonical representation for reporting, because it preserves exactly what P2 records and is substantially simpler.

- **For P3 (bounded testing)**: **Not equivalent**; bounded exploration already finds separating traces within \(|w|\le 12\) and \(\#Analyze\le 3\). Use bounded comparison as a fast falsification tool, but remember: **bounded agreement is not proof of unbounded equivalence**—it can miss differences that occur only beyond the chosen bounds.
