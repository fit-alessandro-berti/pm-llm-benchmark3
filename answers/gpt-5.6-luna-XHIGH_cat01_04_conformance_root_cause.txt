## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels
UI_release -> reviewer_behavior
ETL_change -> recorded_order
ETL_change -> alignment_moves
gateway_release -> technical_event_coverage
technical_event_coverage -> recorded_labels
policy_change -> normative_model
policy_change -> true_process
high_value_status -> required_signoff
required_signoff -> true_process
reviewer_behavior -> true_process
reviewer_behavior -> recorded_labels
true_process -> recorded_labels
source_sequence_truth -> recorded_order
recorded_labels -> alignment_moves
recorded_order -> alignment_moves
normative_model -> alignment_moves
alignment_moves -> measured_fitness
alignment_moves -> measured_precision
true_process -> business_outcomes
recorded_labels -> business_outcomes [only indirectly through observed controls]
audit_detection_power -> observed_incidents
resource_capture -> observed_incidents
high_value_status -> confounding_in_alignment_aggregate
confounding_in_alignment_aggregate -> measured_fitness
```

The June collapse is best explained as a measurement stack-up. Release 4.2 changes the visible activity name, the gateway inserts an unevenly captured technical event, and ETL switches the ordering basis for the final two activities. Each mechanism creates log moves or model moves without necessarily changing the work. The staged repairs behave like interventions: canonicalizing the label, removing the technical event, and restoring source order progressively recover fit. This does not eliminate a real process component. The August policy changes the true process by adding a sign-off requirement, so the old normative model becomes stale; a candidate model therefore recovers another part of the fit. Missing compliance checks and manual overrides remain plausible true deviations or missing records after these repairs.

Stable cycle time, approvals, and appeals make a large operational collapse less likely, but they are downstream and relatively insensitive measures. A reviewer can bypass a control while producing the same decision and customer outcome, and incomplete incident detection can leave such a problem unseen. Conversely, a technically inflated deviation rate can coexist with a small genuine bypass rate. Thus unchanged outcomes support a dominant data-quality explanation, but neither prove that the data are wrong nor rule out noncompliance. The key separation is case-level provenance: establish what happened, what was recorded, and what the policy required for that case.

def xes_from_variants(variants):
    lines = [
        '<?xml version="1.0" encoding="UTF-8" ?>',
        '<log xes.version="1.2" xmlns="http://www.xes-standard.org/">',
    ]
    case_no = 0
    for labels, frequency in variants.items():
        for _ in range(frequency):
            case_no += 1
            lines.append(f'<trace><string key="concept:name" value="case-{case_no}"/>')
            for label in labels:
                lines.append(
                    '<event><string key="concept:name" value="%s"/></event>'
                    % escape(label)
                )
            lines.append("</trace>")
    lines.append("</log>")
    return "\n".join(lines)


def parse_variants(variants):
    return pm4py.parse_event_log_string(xes_from_variants(variants))


def normalize_log(log, remove_queue=False):
    """Canonicalize the UI label; optionally omit gateway-only events."""
    normalized = EventLog()
    for old_trace in log:
        new_trace = Trace(attributes=deepcopy(old_trace.attributes))
        for old_event in old_trace:
            event = Event(deepcopy(dict(old_event)))
            name = event.get("concept:name")
            if name == "Risk Screen":
                event["concept:name"] = "Classify"
            if remove_queue and event.get("concept:name") == "Queue Routed":
                continue
            new_trace.append(event)
        normalized.append(new_trace)
    return normalized


def order_by_source_sequence(log, sequence_key="source:sequence"):
    """Use only an authoritative, unique source sequence when it exists."""
    ordered = EventLog()
    for old_trace in log:
        new_trace = Trace(attributes=deepcopy(old_trace.attributes))
        events = [Event(deepcopy(dict(e))) for e in old_trace]
        if not all(sequence_key in e for e in events):
            raise ValueError("source sequence is unavailable in an aggregate-expanded log")
        events.sort(key=lambda e: e[sequence_key])
        new_trace.extend(events)
        ordered.append(new_trace)
    return ordered


normative_text = """
->(
    'Receive',
    'Classify',
    X(
        *('Standard Review', 'Request Info'),
        ->('Enhanced Review', 'Compliance Check')
    ),

def report(label, log, tree, show_dfg=True):

    dfg, starts, ends = pm4py.discover_dfg(log)

    fitness = pm4py.fitness_alignments(log, net, im, fm)

    if show_dfg:
        print("frequency DFG:", dfg)
        print("start activities:", starts)
        print("end activities:", ends)
    return {
        "dfg": dfg,
        "diagnostics": diagnostics,
        "fitness": fitness,
        "precision": precision,
    }

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a compound observability change, with high confidence (about 90%). Release 4.2 changed `Classify` to `Risk Screen`; the gateway added an unevenly captured `Queue Routed`; and ETL began ordering `Decision` and `Notify` by warehouse-ingestion time. The staged results are unusually discriminating: label mapping, technical-event removal, and source-sequence ordering move June-July from 32% to 89% fitting traces and reduce mean alignment cost from 0.74 to 0.12. Stable cycle time, approval rate, and appeals are consistent with a large apparent rather than operational collapse. These facts support a conformance-measurement failure, not a conclusion that the claims process suddenly became broadly nonconformant.

There is nevertheless a separate, moderate-confidence real compliance concern (about 55% that at least some true violations remain). The August policy created a previously unmodeled sign-off requirement, and the optional-signoff candidate materially improves fit. That explains policy-driven residuals, but not whether sign-off was required for each case: the high-value attribute was omitted, so an optional control-flow model can overfit. The 25 and 30 enhanced-review traces without a recorded compliance check, plus manual overrides, are unresolved. They may represent genuine bypasses, events performed in another system, or extraction omissions. The unchanged outcomes and incomplete incident detection do not settle this.

Immediately, IT should freeze raw immutable events, preserve source sequence and ingestion timestamps separately, publish an activity/technical-event contract, and reconcile the missing-check and reversal traces. Process owners should version the model effective 1 August, specify the sign-off condition and legal placement, and approve a canonical label map without deleting technical provenance. Compliance should perform a blinded, value-stratified audit of missing checks and overrides by reviewer and authorization, then feed confirmed cases back into control monitoring.

Do not yet claim that employees caused the collapse, that every `Queue Routed` event is harmless, that every missing check is a bypass, or that the optional-signoff model proves policy conformance. Do not report a single repaired fitness score as the operational truth until provenance and case attributes are validated.

## 8. Model-governance recommendation

1. Version every normative model with an effective date, policy source, change owner, and backward-comparable conformance baseline.
2. Maintain an event-semantic contract mapping UI labels and source event IDs to canonical activities, including aliases, deprecations, and business meaning.
3. Classify technical events explicitly; retain them in a provenance stream and exclude them from control-flow conformance only under a documented, tested policy.
4. Preserve source event time, source sequence, ingestion time, and late-arrival/retry metadata as separate fields, and validate ordering before every conformance run.
5. Encode data-aware constraints such as EUR 50,000 eligibility, resource authorization, and required checks through case-aware rules or stratified analysis rather than an overpermissive control-flow tree.
6. Make post-release validation a gate: replay representative cases, compare variants, DFGs, alignments, fitness, precision, and audit samples before publishing a new conformance metric.
