# 1. Executive Verdict

- **Workflow net:** Yes, structurally. `source` is the only place without an input, `sink` the only place without an output, and every node lies on a source-to-sink path. `pm4py.check_is_workflow_net` should return `True`.
- **Soundness:** It should not be sound.
- **Principal defect:** `t_join_waived` has only one input place (`p_waived`). It is not a synchronization, so the waiver route never consumes the analysis token and never waits for it.
- **Business consequence:** `t_authorize` can fire before `t_analyze`, or without analysis ever being done. Every waiver run ends in `{sink:1, p_analysis_done:1}`, which is a stuck marking, not `fm`.

- R2 costs 2 because it needs one arc removed and one added. The other single-edit options I examined all fail:
  - Adding `t_waive_review  p_review_done` double-produces tokens.
  - Removing `t_join_waived  p_decision` kills the waiver route.
  - Removing `t_waive_review  p_waived` removes the waiver route (its transition would consume the review token and produce nothing).

- R1 and R2 do not tie on cost. They differ by 1, and R2 buys free-choice structure and a single sync point for that extra unit.

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

def show(marking):
    return {p.name: n for p, n in marking.items() if n > 0}

def fire(net, marking, tname):
    """Fire a named transition only if it is enabled; return a new marking."""
    t = next((x for x in net.transitions if x.name == tname), None)
    if t is None:
        raise KeyError(f"Unknown transition {tname}")
    enabled = pm4py.get_enabled_transitions(net, marking)
    if t not in enabled:
        raise RuntimeError(
            f"{tname} NOT enabled at {show(marking)}; "
            f"enabled: {sorted(x.name for x in enabled)}")
    new = Marking(marking)
    for a in t.in_arcs:
        new[a.source] -= a.weight
    for a in t.out_arcs:
        new[a.target] += a.weight
    for p in [p for p, v in new.items() if v == 0]:
        del new[p]
    return new

def replay(net, im, fm, seq, title):
    print(f"\n== {title} ==")
    m = Marking(im)
    print("start", show(m))
    for name in seq:
        try:
            m = fire(net, m, name)
        except RuntimeError as e:
            print("BLOCKED:", e)
            return
        en = sorted(x.name for x in pm4py.get_enabled_transitions(net, m))
        print(f"{name:20s} -> {show(m)}  enabled={en}")
    print("final marking == fm ?", m == fm, "| sink marked ?", m.get(
        next(p for p in net.places if p.name == "sink"), 0) > 0)

def terminal_markings(net, im):
    """Exhaustive search for reachable markings with no enabled transition."""
    seen, stack, dead = set(), [Marking(im)], []
    while stack:
        m = stack.pop()
        key = frozenset(show(m).items())
        if key in seen:
            continue
        seen.add(key)
        en = pm4py.get_enabled_transitions(net, m)
        if not en:
            dead.append(show(m))
        for t in en:
            stack.append(fire(net, m, t.name))
    return dead

def diagnose(label, n, i, f):
    print(f"\n######## {label} ########")
    print("workflow net:", pm4py.check_is_workflow_net(n))
    print("soundness:", pm4py.check_soundness(n, i, f, print_diagnostics=True))
    print("enabled at initial marking:",
          sorted(t.name for t in pm4py.get_enabled_transitions(n, i)))
    ts = pm4py.convert_to_reachability_graph(n, i, f)
    print("reachability graph: states =", len(ts.states),
          "| transitions =", len(ts.transitions))
    print("terminal markings:", terminal_markings(n, i))

diagnose("ORIGINAL", net, im, fm)
diagnose("REPAIRED", repaired_net, repaired_im, repaired_fm)

bad = ["t_register", "t_split", "t_waive_review", "t_join_waived",
       "t_authorize", "t_analyze"]
replay(net, im, fm, bad, "Original, Sequence A")
replay(repaired_net, repaired_im, repaired_fm, bad, "Repaired, Sequence A (must be blocked)")
good = ["t_register", "t_split", "t_waive_review", "t_analyze",
        "t_join_waived", "t_authorize"]
replay(repaired_net, repaired_im, repaired_fm, good, "Repaired, waiver with analysis")
```

- **Original:** the workflow-net check returns `True`. The soundness check reports unsound, with improper completion (a token left besides `sink`) and inability to always reach `fm`. The reachability graph contains a terminal marking `{sink, p_analysis_done}` that is not `fm`. `fire(...)` lets `t_authorize` run while `p_analysis` is still marked.

# 7. Repair Trade-Offs and Residual Risks

- **Distinguishability.** The visible transitions `Perform Standard Review` and `Record Review Waiver` stay distinct, and in R1 the `p_waived` place records the waiver in the marking. R2 would make both outcomes look alike at `p_review_done`, though the visible labels still differ.
- **Silent transitions.** `t_split`, `t_join_normal` and `t_join_waived` are invisible in logs. In R1 the two joins cannot both fire for one case, because the single `p_review` token goes to either `p_review_done` or `p_waived`. There is no duplicate behavior, but alignments and discovered models may show two interchangeable silent paths. R2 adds one silent step on the waiver route.
- **Soundness is not alignment.** A sound net can still encode the wrong policy. R3 is sound yet allows authorization without analysis. Soundness says nothing about who may waive, whether a waiver needs a reason, or whether a waiver may follow a standard review in a real-world context.
- **Positive regression traces** (visible labels, with silent steps handled by alignment or replay):

  - Register, Standard Review, Analysis, Authorize
  - Register, Analysis, Waiver, Authorize
  - Register, Waiver, Analysis, Authorize

# 8. Final Recommendation

**Deploy R1.** It costs one arc, which is the lower bound for any repair here. It keeps the stated policy: analysis is mandatory on both routes and authorization waits for analysis plus the chosen review outcome. The waiver stays a distinct visible transition, and `p_waived` keeps a marking-level record of it. The added arc leaves `p_analysis_done` with two consumers, but the exclusive review choice means they never actually compete. The argument is short enough to check by hand, and it can be confirmed mechanically with the ablation and graph tests from section 7.

**Fallback: R2.** It costs 2 edits and leaves the net free-choice, with a single synchronization point (`t_join_normal`) that gates authorization. Use it if tooling or review practice needs free-choice structure, or if reviewers prefer one gate. Rename `t_join_waived` when adopting it, because it is no longer a join. Its visible behavior matches R1.

**Do not deploy R3** unless the business explicitly confirms that a waiver may replace analysis. It changes the policy, and it would make `Register, Waiver, Authorize` a valid trace. Whichever repair is chosen, run the regression traces in section 7, because a sound net does not prove the business rule is met.
