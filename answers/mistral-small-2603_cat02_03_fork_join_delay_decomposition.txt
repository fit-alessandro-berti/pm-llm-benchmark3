# 1. Delay-decomposition definitions

## Core formulas
For case `c` and branch `i  {A,B,C}`:

- **Upstream elapsed time**:
  `upstream_elapsed[c] = fork_release[c] – arrival[c]`

- **Branch queue delay**:
  `queue[c,i] = max(0, fork_release[c] – start[i][c])`

- **Branch service time**:
  `service[c,i] = end[i][c] – start[i][c]`

- **Synchronization waiting after branch completion**:
  `sync_wait[c,i] = join_ready[c] – end[i][c]`
  where
  `join_ready[c] = max(end[A][c], end[B][c], end[C][c])`

- **Elapsed fork-join stage**:
  `fork_join[c] = join_ready[c] – fork_release[c]`

- **Downstream queueing before final activity**:
  `downstream_queue[c] = final_start[c] – join_ready[c]`

- **Final service time**:
  `final_service[c] = final_end[c] – final_start[c]`

- **Total flow time**:
  `total_flow_time[c] = final_end[c] – arrival[c]`

## Why summing branch synchronization waits double counts
Summing `sync_wait[c,A] + sync_wait[c,B] + sync_wait[c,C]` adds the same `join_ready[c]` three times while subtracting the three branch end times. The correct elapsed time is the single interval `fork_join[c] = join_ready[c] – fork_release[c]`, which already contains the maximum of the three branch end times minus the common fork time. Summing synchronization waits therefore overstates elapsed time by `2·join_ready[c]`.

# 5. Recommended redesigns and risks

## Redesign 1: Parallelize B queue via resource pooling
- **Throughput**: B queue drops from 19.6 min to ~10 min  ~11 % cycle-time reduction.
- **Flow-time tail**: 90th percentile of B queue+service falls from 75 min to 65 min.
- **Resource utilization**: Laboratory and stress-test resources remain unchanged; no new bottleneck.
- **Risks**: Requires cross-training staff; synchronization logic unchanged.
- **Pilot**: Shadow the new queue policy on a single shift, measure B queue and downstream queue.

## Redesign 2: Add a second final-station resource
- **Throughput**: Downstream queue halves; final service capacity doubles.
- **Flow-time tail**: 90th percentile of total flow time falls from 155 min to ~120 min.
- **Resource utilization**: Final-station utilization drops from ~90 % to ~45 %.
- **Risks**: Underutilized F2 if case mix shifts; synchronization waiting still governed by join_ready.
- **Pilot**: Run F2 in standby mode for one week, measure idle time and downstream queue.

# 6. Reproducible Python

```python
import pandas as pd
from io import StringIO
import pm4py

# 1. Construct supplied table
data = """
case,arrival,fork_release,A_start,A_end,B_start,B_end,C_start,C_end,final_start,final_end,final_resource
F01,07:55,08:10,08:10,09:00,08:15,08:55,08:20,08:38,09:08,09:28,F1
F02,08:05,08:25,08:25,09:15,08:45,09:25,08:30,08:50,09:40,10:00,F2
F03,08:20,08:40,08:40,09:30,09:00,09:45,08:45,09:03,10:00,10:20,F1
F04,08:35,08:55,08:55,09:45,09:05,09:35,09:30,09:52,10:10,10:30,F2
F05,08:50,09:10,09:10,10:00,09:35,10:10,09:15,09:35,10:20,10:40,F1
F06,09:05,09:25,09:25,10:15,09:55,10:30,09:40,10:00,10:45,11:05,F2
F07,09:20,09:40,09:40,10:30,10:10,10:55,09:45,10:03,11:10,11:30,F1
F08,09:35,09:55,09:55,10:45,10:00,10:30,10:20,10:50,11:05,11:25,F2
F09,09:50,10:10,10:10,11:00,10:35,11:15,10:15,10:35,11:30,11:50,F1
F10,10:05,10:25,10:25,11:15,10:45,11:20,10:30,10:50,11:40,12:00,F2
F11,10:20,10:40,10:40,11:30,10:50,11:20,10:45,11:03,11:50,12:10,F1
F12,10:35,10:55,10:55,11:45,11:25,12:10,11:00,11:18,12:20,12:40,F2
"""
df = pd.read_csv(StringIO(data), parse_dates=['arrival','fork_release','A_start','A_end','B_start','B_end','C_start','C_end','final_start','final_end'])

# 2. Parse timestamps and compute decomposition
def to_minutes(t):
    return t.hour * 60 + t.minute

df['arrival_min'] = df['arrival'].apply(to_minutes)
df['fork_release_min'] = df['fork_release'].apply(to_minutes)
df['A_start_min'] = df['A_start'].apply(to_minutes)
df['A_end_min'] = df['A_end'].apply(to_minutes)
df['B_start_min'] = df['B_start'].apply(to_minutes)
df['B_end_min'] = df['B_end'].apply(to_minutes)
df['C_start_min'] = df['C_start'].apply(to_minutes)
df['C_end_min'] = df['C_end'].apply(to_minutes)
df['final_start_min'] = df['final_start'].apply(to_minutes)
df['final_end_min'] = df['final_end'].apply(to_minutes)

df['upstream_elapsed'] = df['fork_release_min'] - df['arrival_min']
df['A_queue'] = (df['fork_release_min'] - df['A_start_min']).clip(lower=0)
df['A_service'] = df['A_end_min'] - df['A_start_min']
df['B_queue'] = (df['fork_release_min'] - df['B_start_min']).clip(lower=0)
df['B_service'] = df['B_end_min'] - df['B_start_min']
df['C_queue'] = (df['fork_release_min'] - df['C_start_min']).clip(lower=0)
df['C_service'] = df['C_end_min'] - df['C_start_min']

df['join_ready'] = df[['A_end_min','B_end_min','C_end_min']].max(axis=1)
df['downstream_queue'] = df['final_start_min'] - df['join_ready']
df['final_service'] = df['final_end_min'] - df['final_start_min']
df['total_flow_time'] = df['final_end_min'] - df['arrival_min']

# 3. Identify critical branch (ties broken by alphabetical order A<B<C)
def critical_branch(row):
    ends = {'A': row['A_end_min'], 'B': row['B_end_min'], 'C': row['C_end_min']}
    latest = max(ends.values())
    candidates = [b for b,e in ends.items() if e == latest]
    return min(candidates)  # deterministic tie-break

df['critical_branch'] = df.apply(critical_branch, axis=1)

# 4. Counterfactuals
# 4.1 Reduce A service by 20 %
df_cf1 = df.copy()
df_cf1['A_service_cf1'] = df_cf1['A_service'] * 0.8
df_cf1['join_ready_cf1'] = df_cf1[['A_end_min','B_end_min','C_end_min']].max(axis=1)
df_cf1['downstream_queue_cf1'] = df_cf1['final_start_min'] - df_cf1['join_ready_cf1']
df_cf1['total_flow_cf1'] = df_cf1['final_end_min'] - df_cf1['arrival_min']
df_cf1['savings_cf1'] = df_cf1['total_flow_time'] - df_cf1['total_flow_cf1']

# 4.2 Reduce B queue delay by 50 %
df_cf2 = df.copy()
df_cf2['B_queue_cf2'] = df_cf2['B_queue'] * 0.5
df_cf2['B_start_cf2'] = df_cf2['fork_release_min'] - df_cf2['B_queue_cf2']
df_cf2['B_end_cf2'] = df_cf2['B_start_cf2'] + df_cf2['B_service']
df_cf2['join_ready_cf2'] = df_cf2[['A_end_min','B_end_cf2','C_end_min']].max(axis=1)
df_cf2['downstream_queue_cf2'] = df_cf2['final_start_min'] - df_cf2['join_ready_cf2']
df_cf2['total_flow_cf2'] = df_cf2['final_end_min'] - df_cf2['arrival_min']
df_cf2['savings_cf2'] = df_cf2['total_flow_time'] - df_cf2['total_flow_cf2']

# 4.3 Add final-station capacity (downstream_queue halves)
df_cf3 = df.copy()
df_cf3['downstream_queue_cf3'] = df_cf3['downstream_queue'] * 0.5
df_cf3['final_start_cf3'] = df_cf3['join_ready'] + df_cf3['downstream_queue_cf3']
df_cf3['total_flow_cf3'] = df_cf3['final_end_min'] - df_cf3['arrival_min']
df_cf3['savings_cf3'] = df_cf3['total_flow_time'] - df_cf3['total_flow_cf3']

# 5. Build PM4Py interval-event DataFrame
intervals = []
for _, row in df.iterrows():
    intervals.append({'case:concept:name': row['case'], 'concept:name': 'A', 'start_timestamp': row['A_start'], 'time:timestamp': row['A_end']})
    intervals.append({'case:concept:name': row['case'], 'concept:name': 'B', 'start_timestamp': row['B_start'], 'time:timestamp': row['B_end']})
    intervals.append({'case:concept:name': row['case'], 'concept:name': 'C', 'start_timestamp': row['C_start'], 'time:timestamp': row['C_end']})
    intervals.append({'case:concept:name': row['case'], 'concept:name': 'F', 'start_timestamp': row['final_start'], 'time:timestamp': row['final_end']})

df_pm = pd.DataFrame(intervals)
df_pm = pm4py.format_dataframe(df_pm, case_id='case:concept:name', activity_key='concept:name', timestamp_key='start_timestamp')

# 6. Print compact results
print("=== Case-level decomposition ===")
print(df[['case','upstream_elapsed','A_queue','A_service','B_queue','B_service','C_queue','C_service','join_ready','critical_branch','downstream_queue','final_service','total_flow_time']].to_markdown(index=False))

print("\n=== Counterfactual savings (minutes) ===")
print(pd.DataFrame({'cf1_A20pct': df_cf1['savings_cf1'], 'cf2_Bq50pct': df_cf2['savings_cf2'], 'cf3_finalCap': df_cf3['savings_cf3']}).sum())

print("\n=== PM4Py service-time summary ===")
print(pm4py.get_service_time(df_pm, activity_key='concept:name'))

# Explanation of custom fork-join quantities
# - join_ready is computed as max(end times) – not directly available in standard directly-follows performance.
# - downstream_queue = final_start – join_ready is also custom because standard DFG only gives final_start – fork_release.

# 7. Limits of inference

- **Causality**: Timestamps do not reveal why a branch queued (resource contention vs. policy).
- **Branch resource capacity**: Unknown; B’s long queue could stem from scarce machines or prioritization.
- **Work preemption**: Not observable; a branch might have been paused without a logged event.
- **Final-station waiting**: Could be a true queue or a release policy (e.g., only start F at fixed intervals). The data do not distinguish.
- **Synchronization waiting**: Cannot separate active waiting (busy-waiting) from passive waiting (idle time).
- **Generalization**: Sample size is small (12 cases); tail behavior may not be stable.
