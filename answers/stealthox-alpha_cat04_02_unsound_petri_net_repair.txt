# 1. Executive Verdict

The net **is** a workflow net: it has a single source place (`source`, no input arcs), a single sink place (`sink`, no output arcs), and every node lies on at least one source-to-sink path (the waiver route covers `t_waive_review`/`t_join_waived`; the standard route covers the rest; both end at `t_authorize`). It should therefore **not** be expected to be sound. The principal defect is that `t_join_waived` is a *partial* AND-join: it consumes only `p_waived` and ignores the analysis branch. Consequences: (i) `t_authorize` becomes enabled while analysis is pending or running, violating "authorize only after analysis and the selected review outcome"; (ii) every waiver trace strands a token in `p_analysis`/`p_analysis_done` that no transition can ever consume, so the exact final marking `{sink: 1}` is unreachable on the waiver route — improper completion. Business impact: unauthorized-by-policy authorizations and permanently stuck waiver cases.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_split` | AND-fork: start analysis and review in parallel | Correct: one token each into `p_analysis`, `p_review` | None |
| Standard-review branch (`p_review  t_standard_review  p_review_done`) | One XOR outcome of the review choice | Correct producer for the normal join | None |
| Waiver branch (`p_review  t_waive_review  p_waived`) | The other XOR outcome | Producer is fine; its **consumer** is defective | Feeds a join that ignores analysis |
| `t_join_normal` | AND-join of analysis + standard review | Correct: preset `{p_analysis_done, p_review_done}` | None on the standard route |
| `t_join_waived` | Should AND-synchronize analysis + waiver | Defective: preset is only `{p_waived}`; the analysis branch is not coupled in | Premature `t_authorize`; orphaned analysis token; deadlock |
| `im = {source:1}`, `fm = {sink:1}` | Start/end conditions | Appropriate; but `fm` demands the *exact* marking `{sink:1}` | Waiver route can never satisfy it |
| Node coverage | Every node on a source-to-sink path | Holds for all 8 transitions and 9 places | Workflow-net check passes — the defect is purely behavioral |

Key separation: the workflow-net property (structure) holds; soundness (behavior) fails. The root cause is one missing input arc on `t_join_waived`.

# 3. Marking-Based Counterexample

**Counterexample 1 (primary — premature authorization *and* stranded token).** Legal sequence: `t_register  t_split  t_waive_review  t_join_waived  t_authorize  t_analyze`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source: 1}` | `t_register` | start at `im` |
| 1 | `t_register` | `{p_ready: 1}` | `t_split` | |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `t_analyze`, `t_standard_review`, `t_waive_review` | token created in each parallel branch |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `t_analyze`, `t_join_waived` | waiver route taken; analysis still pending |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, **`t_authorize`** | DEFECT: authorization enabled although analysis has not even started |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `t_analyze` | a token exists in `sink`, but the marking  `fm = {sink: 1}` |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` |  | deadlock; leftover token unconsumable |

Why the leftover token can never be consumed: `p_analysis_done`'s only consumer is `t_join_normal`, whose preset additionally requires `p_review_done` — unreachable once the waiver was recorded. So "sink marked"  "`fm` reached"; proper completion fails.

**Counterexample 2 (additional defect dimension — even the disciplined order fails).** `t_register  t_split  t_analyze  t_waive_review  t_join_waived  t_authorize`:

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0–2 | reg, split | `{p_analysis: 1, p_review: 1}` | analyze / std / waive | branches created |
| 3 | `t_analyze` | `{p_analysis_done: 1, p_review: 1}` | `t_standard_review`, `t_waive_review` | analysis finished first |
| 4 | `t_waive_review` | `{p_analysis_done: 1, p_waived: 1}` | `t_join_waived` | |
| 5 | `t_join_waived` | `{p_analysis_done: 1, p_decision: 1}` | `t_authorize` | analysis ignored by the join |
| 6 | `t_authorize` | `{p_analysis_done: 1, sink: 1}` |  | deadlock; `fm` unreachable |

Together the two derivations show: `t_authorize` can fire **before** analysis (C1, steps 4–5) and **after** it (C2) — but on *every* waiver trace completion is improper. The standard route (`… t_analyze, t_standard_review  t_join_normal  t_authorize`) is correct; the defect is isolated to the waiver synchronization. Hand extension of this enumeration to all routes yields 14 reachable markings / 17 edges for the original net (used in §6).

# 4. Minimal-Repair Alternatives

**Edit-cost model:** each added or removed arc, place, or transition costs 1; total cost = sum of primitives.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1 – Complete the waiver AND-join** | Add arc `p_analysis_done  t_join_waived`. Nothing else. | **1** | Everything: mandatory analysis on both routes; authorize only after analysis + chosen outcome; exact `fm`; soundness | None — implements exactly the stated policy | Asymmetric join presets (cosmetic only) |
| **R2 – Single shared join with explicit XOR-merge** | Remove arcs `p_waivedt_join_waived`, `t_join_waivedp_decision`, `p_review_donet_join_normal`; remove transition `t_join_waived`; add place `p_review_outcome`; add silent transitions `t_collect_review_done`, `t_collect_waiver`; add arcs `p_review_donet_collect_review_done`, `t_collect_review_donep_review_outcome`, `p_waivedt_collect_waiver`, `t_collect_waiverp_review_outcome`, `p_review_outcomet_join_normal` | **12** | Same as R1 (identical trace language) | None behaviorally; structurally one gateway | Two new silent transitions: larger state space, silent moves in alignments |
| **R3 – Policy change: "a recorded waiver discharges the analysis"** | Add arc `p_analysis  t_join_waived` (waiver cancels a *pending* analysis); add silent transition `t_join_waived_post_analysis` with arcs `p_waivedt_…`, `t_…p_decision` (handles waiver *after* completed analysis) | **4** | Registration, parallelism, standard route, exact `fm`, soundness | **Stated policy change:** authorization may follow the waiver immediately; pending analysis is cancelled, completed analysis discarded | Compliance/audit exposure: cases closed without analysis; needs explicit business sign-off |

**Why the tempting cost1 edit "add `p_waived  t_join_normal`" is invalid:** a transition's preset is conjunctive, so `t_join_normal` would then require `p_review_done  p_waived`, which can never co-occur — the standard route would deadlock. A plain rewiring therefore needs the XOR-merge scaffolding of R2.

**Minimality justification.** Any sound repair must create a dependency between the analysis branch and the waiver synchronization (or delete the branch); pure deletions or relabelings cannot add dependencies, so  1 addition is necessary — R1 attains exactly 1 and is globally minimal. Within the other families: R3 needs  1 extra transition because one join cannot consume "either `p_analysis` or `p_analysis_done`" (conjunctive presets), and each new transition needs  2 arcs plus the cancel arc  4 is minimal there; R2 needs the merge place, two collectors, and five arcs because one AND-transition cannot take an XOR of inputs  12 is minimal there. No ties across families.

# 5. Corrected PM4Py Code

Selected repair: **R1** (complete the waiver AND-join).

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

# Repair R1: ONE added arc  p_analysis_done --> t_join_waived,
# so authorization under a waiver also waits for the analysis.

repaired_net = PetriNet("parallel_review_with_waiver_R1")

source          = PetriNet.Place("source")
p_ready         = PetriNet.Place("p_ready")
p_analysis      = PetriNet.Place("p_analysis")
p_review        = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done   = PetriNet.Place("p_review_done")
p_waived        = PetriNet.Place("p_waived")
p_decision      = PetriNet.Place("p_decision")
sink            = PetriNet.Place("sink")

for p in {source, p_ready, p_analysis, p_review, p_analysis_done,
          p_review_done, p_waived, p_decision, sink}:
    repaired_net.places.add(p)

register        = PetriNet.Transition("t_register", "Register Case")
split           = PetriNet.Transition("t_split", None)
analyze         = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review    = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal     = PetriNet.Transition("t_join_normal", None)
join_waived     = PetriNet.Transition("t_join_waived", None)
authorize       = PetriNet.Transition("t_authorize", "Authorize Case")

for t in {register, split, analyze, standard_review, waive_review,
          join_normal, join_waived, authorize}:
    repaired_net.transitions.add(t)

def arc(fr, to):
    petri_utils.add_arc_from_to(fr, to, repaired_net)

arc(source, register)
arc(register, p_ready)
arc(p_ready, split)
arc(split, p_analysis)
arc(split, p_review)

arc(p_analysis, analyze)
arc(analyze, p_analysis_done)

arc(p_review, standard_review)
arc(standard_review, p_review_done)
arc(p_review, waive_review)
arc(waive_review, p_waived)

arc(p_analysis_done, join_normal)
arc(p_review_done, join_normal)
arc(join_normal, p_decision)

arc(p_waived, join_waived)
arc(p_analysis_done, join_waived)   # <-- THE REPAIR (R1): sync waiver with analysis
arc(join_waived, p_decision)

arc(p_decision, authorize)
arc(authorize, sink)

repaired_im = Marking()
repaired_im[source] = 1

repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

# ---------- helpers ----------
def clone_marking(m):
    c = Marking()
    for p, k in m.items():
        c[p] = k
    return c

def md(m):
    return {p.name: k for p, k in sorted(m.items(), key=lambda kv: kv[0].name)}

def t_by_name(net, name):
    for t in net.transitions:
        if t.name == name:
            return t
    raise KeyError(name)

def fire(net, marking, name):
    """Fire `name` only if it is enabled; never move tokens silently."""
    enabled = {t.name for t in pm4py.get_enabled_transitions(net, marking)}
    if name not in enabled:
        raise ValueError(f"{name} NOT enabled at {md(marking)}")
    nxt = t_by_name(net, name).fire(marking)
    print(f"  fired {name:<18} {md(marking)} -> {md(nxt)}")
    return nxt

def run(tag, net, im, seq, fm):
    print(f"\n=== {tag} ===")
    m = clone_marking(im)
    print(f"  start {md(m)}")
    for name in seq:
        try:
            m = fire(net, m, name)
        except ValueError as e:
            print(" ", e)
            return m
    print(f"  final marking : {md(m)}")
    print(f"  equals fm ?   : {md(m) == md(fm)}")
    print(f"  still enabled : {[t.name for t in pm4py.get_enabled_transitions(net, m)]}")
    return m

# ---------- counterexamples ----------
run("original: waiver route, authorize BEFORE analyze (legal but improper)",
    net, im,
    ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize", "t_analyze"],
    fm)

run("original: analyze FIRST, still stranded token",
    net, im,
    ["t_register", "t_split", "t_analyze", "t_waive_review", "t_join_waived", "t_authorize"],
    fm)

run("repaired: premature t_join_waived is now REFUSED",
    repaired_net, repaired_im,
    ["t_register", "t_split", "t_waive_review", "t_join_waived"],
    repaired_fm)

run("repaired: proper waiver trace reaches fm exactly",
    repaired_net, repaired_im,
    ["t_register", "t_split", "t_waive_review", "t_analyze", "t_join_waived", "t_authorize"],
    repaired_fm)

# ---------- diagnostics ----------
for tag, n, i, f in [("original", net, im, fm),
                     ("repaired (R1)", repaired_net, repaired_im, repaired_fm)]:
    print(f"\n--- diagnostics: {tag} ---")
    print("is_workflow_net:", pm4py.check_is_workflow_net(n))
    try:
        sound = pm4py.check_soundness(n, i, f, print_diagnostics=True)
        print("soundness:", sound)
    except Exception as ex:
        print("soundness check raised:", type(ex).__name__, ex)
    rg = pm4py.convert_to_reachability_graph(n, i, f)
    states = getattr(rg, "states", None)
    edges = getattr(rg, "transitions", None)
    if states is not None:
        print(f"reachability graph: {len(states)} states / {len(edges)} edges")
    else:
        print("reachability graph:", rg)
```

**Expected qualitative difference.** Original: `check_is_workflow_net`  `True`; `check_soundness`  `False`, with diagnostics of the improper-completion/deadlock kind (terminal markings strictly larger than `fm`, e.g. `{p_analysis_done: 1, sink: 1}`; the waiver route can never terminate properly). Repaired: workflow-net `True` **and** soundness `True`; the only terminal marking is `fm`. Hand-derived state spaces (extended from the §3 enumeration, not guessed): original 14 markings / 17 edges; repaired 10 markings / 12 edges — the script prints the tool's own counts to confirm.

# 7. Repair Trade-Offs and Residual Risks

- **Distinguishability.** Under R1/R2 the visible activities "Perform Standard Review" and "Record Review Waiver" are unchanged, so log traces identify the route unambiguously. Under R3, a waiver trace may legitimately contain no "Perform Analysis" — still distinguishable, but only defensible with the signed-off policy change.
- **Silent transitions / confusion.** R1 adds none. R2 adds two -collectors; each is enabled only by its single, mutually-exclusive input place, so there is no concurrency-induced confusion and no duplicated observable behavior — but they enlarge the state space and appear as silent moves in alignments. Keep their labels `None`.
- **Soundness  business conformance.** Soundness guarantees proper completion and no dead ends; it does not encode "analysis is mandatory" as a compliance rule. R3 is provably sound yet violates the original mandate — proof that a green soundness call must never be treated as business acceptance.
- **Regression tests.** Positive: `[Register, Perform Analysis, Perform Standard Review, Authorize]`, `[Register, Perform Standard Review, Perform Analysis, Authorize]`, `[Register, Record Review Waiver, Perform Analysis, Authorize]`, `[Register, Perform Analysis, Record Review Waiver, Authorize]` — each must end in exactly `fm`. Negative: `[Register, Authorize]`; `[Register, Record Review Waiver, Authorize]` (must be rejected under R1/R2); `[Register, Perform Analysis, Authorize]` (no review outcome); any trace firing both review outcomes or authorizing twice.
- **Detecting an accidental bypass of mandatory analysis.** (a) Conformance/token-replay against the repaired model: a bypass surfaces as missing tokens at a join input; (b) a CI assertion that every accepted trace containing "Authorize Case" also contains "Perform Analysis" (valid under R1/R2 policy); (c) model-governance review that flags any edit removing `p_analysis_done` from `t_join_waived`'s preset — the exact regression repaired here.

# 8. Final Recommendation

**Deploy R1**: add the single arc `p_analysis_done  t_join_waived`. It is the global minimum under the stated edit-cost model (cost 1), it restores the precise business rule — authorization only after the analysis and the chosen review outcome — with zero change to the trace language, introduces no silent transitions, keeps all visible labels intact, and is trivially reviewable and reversible. The counterexamples in §3 disappear by construction: the premature firing is structurally impossible, and every waiver trace now ends in exactly `{sink: 1}`.

**Fallback: R2** (explicit XOR-merge of `p_review_done`/`p_waived` into one shared join). Choose it only if your modeling standards forbid two joins with different presets writing to the same place and mandate a canonical single synchronization gateway. It is behaviorally identical to R1 but costs 12 edit units and adds two silent transitions, so it should not be the default.

**R3** (waiver discharges the analysis) is sound and cheap (cost 4) but changes policy: cases could be authorized without any analysis. Deploy it only with explicit, documented business and compliance sign-off, and pair it with the negative-trace suite adjusted accordingly. Whichever variant ships, rerun the §6 diagnostics and treat soundness as necessary — not sufficient — evidence of correctness.
