## 2. Dependency and Prerequisite Map

### 2.1 Upstream Data Quality Dependencies

```
Receive Application (12,000)
    
[A1: Auto-registration & duplicate detection]
     (clean application payload required)
[A2: Product/exposure classification] 
     (correct routing required)
     [A3: KYC hit pre-classifier]  Cannot operate safely if misrouted
            (escalation capacity required)
       [A4: Entity-mismatch resolver]  Prerequisite: escalation procedures documented
    
     [Financial document review]
             (PDF quality variance endemic)
        [A6: Financial-statement extraction]  Cannot exceed 90% OCR accuracy on low-quality PDFs; 16% rework baseline indicates variance
             (normalized financials needed)
        [A8: Committee pack assembly]  Garbage-in/garbage-out if normalization incomplete
```

**Critical dependency chain:**
- **A1  A2  A3  A4** (control safety): A1 uncovers misclassification errors (8% baseline)  A2 must improve classification accuracy before A3 can safely pre-screen KYC hits  A4 must resolve downstream entity mismatches to unblock contract flow.
- **A1  A2  A6** (analyst capacity): A1+A2 success routes more clean cases to financial review  A6 must absorb normalization to prevent analyst queue explosion.
- **A6  A8  A9** (control-rule chain): A6 normalizes financials  A8 assembles consistent pack  A9 generates contract with rule checks enforcing KYC-to-signing gate.

### 2.2 Legal and Compliance Control Gates

| Control | Enforced By | Automation Candidate | Risk if Skipped |
|---------|---|---|---|
| KYC clearance must precede signing | System flag + four-eyes | A3, A4, A9 must validate before A10 operates | 6.5% provisional signing; 1.1% remediation loops |
| Four-eyes on High-exposure credit | Manual workflow | A2 (routing), A8 (packaging) must tag High-exposure; A9 cannot skip second reviewer | 5.8% month-end violations |
| Contract terms  Committee decision alignment | Legal manual check | A8 (pack assembly) and A9 (rule library) must enforce consistency | 8.5% contract rework; 14% for credit-line renewal |
| Entity-mismatch resolution before contract prep | Manual | A4 must complete before A8, A9 execute | 82% of mismatch cases on critical path; 31h median wait |

**Compliance implication:** A3, A4, A9, A12 are *control-strengthening* automations; they embed gates that are currently enforced manually and often violated under time pressure.

### 2.3 Human Escalation Capacity

| Resource Pool | Current FTE | Saturation Point | Bottleneck Trigger |
|---|---|---|---|
| Compliance ops (KYC) | 3 (2 seniors) | ~5,000–6,000 KYC checks/month | A3 + A4 must reduce escalations; if escalation rate stays >15%, team is blocked |
| Credit analysts | 9 | ~50–60 normalizations/month if manual; ~200+ if A6 automates | A6 prerequisite: if A1+A2 succeed without A6, analyst queue explodes |
| Legal ops | 4 | ~600–700 contracts/month (month-end peak 1,000+) | A9 prerequisite: Legal must validate rule library; cannot automate faster than rule maintenance |
| Relationship managers | ~15 (inferred) | Ad hoc | A5 (missing docs), A10 (e-signing) create new RM overhead if not designed with RM workflow in mind |

**Escalation logic:**
- A3 (KYC pre-classifier) feeds false-positive/false-negative cases to 3 FTE specialists. If classifier is 95% accurate, ~575 cases/month escalate; at 99%, ~115 escalate. **Threshold: A3 feasible only if accuracy >98%.**
- A6 (statement normalization) relieves analysts. Without A6, A1+A2 success will queue financial-review work to the point of analyst stalling at normalization step (5,200/month at 75 min each = 6,500 analyst-hours/month; 9 FTE = ~1,440 available hours after meetings/admin). **A6 is a *prerequisite* for A1+A2 ROI.**

### 2.4 External Valuation Dependency

| Aspect | Current State | Automation Opportunity | Risk |
|---|---|---|---|
| Triggering | 2,400 requests/month; 2,350 valuations completed | A7: triage, routing, SLA enforcement | Low direct labor savings; partner quality disputes if routing logic not transparent |
| Wait time | 58h median external wait (blocking 1,980 cases/month entering Committee packaging) | A7: parallelize with other activities; escalate slow partners | Partner capacity is fixed; automation cannot shorten wait unless partners are replaced |
| Sync point | Wait-for-valuation is critical path in ~82% of collateral cases | **Upstream parallelization** (start collateral request earlier, in parallel with credit analysis) is higher-ROI than A7 | Requires workflow redesign, not new automation candidate |

**Finding:** A7 has low ROI on labor; only viable if re-prioritization (parallelizing collateral request with credit analysis) is part of portfolio.

### 2.5 Core-Banking Integration Constraints

**Two deep integrations allowed in first 6 months:**

| Candidate | Integration Depth | Timeline | Data Coupling |
|---|---|---|---|
| **A1: Auto-registration** | DEEP (duplicate detection against core DB) | Phase 1 (Month 1–3) | Core customer, account tables |
| **A2: Classification recommender** | MEDIUM (read core GL, infer product type) | Phase 1 (Month 1–3) | Core product, account tables; may not require deep coupling |
| **A6: Statement normalization** | MEDIUM (OCR + NLP, no core update) | Phase 2 (Month 4–6) | Document storage; optional core GL read |
| **A9: Contract generation** | DEEP (read KYC, decision, write contract to core; enforce legal gates) | Phase 2 (Month 4–6) | Core contract, agreement, KYC tables |
| **A11, A12** | DEEP/MEDIUM (control flag write-back) | Phase 3 (Q3–Q4) | Core control, workflow tables |

**Implication:** **First two modules must be A1 (registration) + one of {A2, A6, A9}**. Recommend **A1 + A6** (second 6 months: A1 deep + A6 medium, reserving A9/A12 deep slots for Phase 2).

## 3. Portfolio Alternatives

### Portfolio A: Quick-Win / Labor Efficiency

**Modules: A1 (auto-registration), A5 (missing-doc nudging), A10 (e-signing), A11 (loan activation bot)**

**Optimization:** Direct labor savings, high-frequency activities, political wins.

**Trade-offs:**
- Does NOT address critical bottlenecks (entity mismatch 31h wait, financial normalization, classification accuracy).
- A11 is unsafe without A12 (control remediation); violates compliance prerequisite.
- Missing A6 causes analyst overload if A1 succeeds.
- Does NOT strengthen controls; all four candidates are labor-saving only.

**Not recommended** due to unsafe A11 and missing control module (compliance mandate).

---

### Portfolio B: Bottleneck and Synchronization Focus

**Modules: A4 (entity-mismatch resolver), A6 (financial-statement normalization), A9 (contract generation), A12 (control remediation)**

**Optimization:** Removes synchronization delays, reduces rework, strengthens control gates, unblocks critical-path activities.

**Rationale:**
- **A4**: Removes 31h median wait on 1,750 cases; 82% on critical path. Unblocks KYCContract flow.
- **A6**: Reduces analyst time by ~6,000 hours/month (5,200 cases × 75 min / 5,200 normalized = high ROI); prerequisite for downstream flow.
- **A9**: Embeds contract-rules checking, enforces KYC-to-signing gate, reduces 8.5% rework rate.
- **A12**: Removes 650 case blockages, prevents 6.5% provisional-signing workarounds, enables A9 and A11 to operate safely.

**Does NOT include:**
- A1, A2: Saves labor but does not address process synchronization; deferred to Phase 2.
- A5, A10: Lower priority; signing and missing-doc loops are symptoms of upstream delays.

---

### Portfolio C: Compliance-First + Foundation

**Modules: A1 (auto-registration), A2 (classification recommender), A3 (KYC hit pre-classifier), A12 (control remediation)**

**Optimization:** Strengthens control gates, fixes misclassification root cause, establishes data quality foundation for Phase 2 automation.

**Rationale:**
- **A1**: High-frequency, exposes downstream issues; prerequisite data quality for A2 and A3.
- **A2**: Fixes 8% misclassification error rate; high-frequency; risk gate for A3 and subsequent routing.
- **A3**: Automates KYC escalation; medium feasibility; reduces specialist overload if A2 improves routing.
- **A12**: Compliance mandate; removes provisional-signing risk; enables downstream (A9, A11) in Phase 2.

**Does NOT include:**
- A4, A6, A9: Deferred to Phase 2 after data quality foundation is solid.
- A5, A10, A11: Lower control priority.

## 5. Risks and Compensating Controls

### 5.1 Data Quality and Model Drift Risks

| Risk | Candidate(s) | Impact | Compensating Control |
|---|---|---|---|
| **OCR/NLP fails on low-quality PDFs; statement extraction accuracy decays** | A6 | 16% baseline rework may increase if document quality worsens (e.g., customer uploads poor scans). | Monthly accuracy audit; escalation SLA if OCR confidence <80%; fallback to manual extraction; retraining trigger if accuracy <85%. |
| **Classification recommender drifts due to portfolio mix change** | A2 | 8% baseline error rate may increase if product mix shifts (e.g., more Equipment finance, fewer Working capital). | Quarterly retraining; confusion matrix tracking by product type; alert if any class accuracy drops below 95%. |
| **KYC hit pre-classifier false-negatives increase due to new sanction-list entries** | A3 | Compliance risk: false negatives mean sanctions-listed entities are missed; high-severity reputational/legal risk. | Weekly sanction-list sync; weekly false-negative audit (sample 5% of hits); alert if FN rate >2%; escalation to Compliance CRO if FN occurs. |

### 5.2 Automation Rule and Logic Risks

| Risk | Candidate(s) | Impact | Compensating Control |
|---|---|---|---|
| **Contract generation rule library becomes outdated; legal terms drift from policy** | A9 | 8.5% contract-rework rate may persist or increase if rules are not updated when policies change. New products or regulatory changes may not be captured. | Rule version control; quarterly legal review of rule library; change log with effective dates; legal sign-off before rule deployment; monthly contract-remediation tracking. |
| **Entity-mismatch resolution assistant incorrectly merges entities** | A4 | If assistant forces merge of two legitimate different entities (e.g., two directors with same name), contracts will be signed to wrong party; legal risk. | Confidence thresholding; all merges require human confirmation before contract prep; audit trail of merge suggestion + human override; monthly false-positive rate tracking. |
| **Control remediation workbench allows workarounds; KYC gate is bypassed** | A12 | If control flags are cleared without resolution (e.g., entity mismatch logged but not fixed), A9 and A11 will proceed on incomplete data. | All flag resolutions require documented evidence; escalation to Compliance if resolution is incomplete; four-eyes sign-off for High-exposure cases; monthly gap audit. |

### 5.3 False-Positive and False-Negative Risks

| Risk | Candidate(s) | Type | Likelihood | Impact | Compensating Control |
|---|---|---|---|---|---|

## 6. Recommended Phased Rollout

### Phase 1: Foundation and Data Quality (Months 1–6)

**Deep integrations:** A1 (auto-registration), A6 (financial-statement normalization)  
**Shallow integrations:** A2 (classification recommender), A12 (control remediation workbench)

#### Sequence and Rationale

| Month | Module | Rationale | Integration Depth | Success Criteria |
|---|---|---|---|---|
| **M1–2** | **A1: Auto-registration** | High frequency (12,000), high feasibility; exposes downstream issues; prerequisite data quality. Deep integration: duplicate detection against core customer DB. | **DEEP** | Duplicate detection accuracy >99%; registration queue wait <0.5h; <1% false-positive duplication flags. |
| **M1–2 (parallel)** | **A12: Control remediation workbench** | Compliance mandate; low-risk pilot; establishes control-gate discipline before downstream automation. Shallow integration: control-flag workflow. | MEDIUM | Control-flag resolution time <24h; zero provisional-signing events; gap audit shows <5% unresolved flags. |
| **M3–4** | **A2: Classification recommender** | Builds on A1 clean registrations; high frequency (11,820); fixes 8% misclassification rate; risk gate for A3 (if phased). Shallow integration: read-only GL, infer product type. | MEDIUM | Classification accuracy >98%; misrouting rate <2%; High-exposure override audit <5%. |
| **M4–6** | **A6: Financial-statement extraction & normalization** | Medium feasibility; high analyst time savings (6,000 hours/month); prerequisite for downstream flow if A1+A2 succeed. Deep integration: OCR/NLP pipeline, optional core GL sync for validation. | **DEEP** | OCR accuracy >90%; normalization completion rate >85% without manual fallback; analyst time per case drops from 75 min to 20 min (average). |

#### Phase 1 Gates and Monitoring

**Gate 1 (M2 end):** A1 duplicate-detection accuracy >99% and <1% false-positive rate. If not met, pause A2 rollout until A1 is stable.

**Gate 2 (M3 end):** A12 control-flag resolution SLA met; zero provisional-signing events. If not met, postpone A6 rollout; focus on A12 discipline.

**Gate 3 (M5 end):** A2 classification accuracy >97% for SME, >95% for High-exposure (stricter threshold). If not met, retain A2 as recommender-only (no auto-routing) through M6.

**Gate 4 (M6 end):** A6 OCR accuracy >88% and analyst-time reduction >40%. If not met, configure A6 as extraction-only (no auto-normalization) pending model retraining.

#### Phase 1 Monitoring Metrics

| Metric | A1 | A2 | A6 | A12 |
|---|---|---|---|---|
| **Throughput** | Registration queue <0.5h median wait | Misrouting rate <2% | Normalization completion >85% | Control flags resolved <24h |
| **Accuracy** | Duplicate detection >99% | Classification accuracy >97% | OCR >88% | Flag resolution audit <5% gaps |
| **Labor** | Back office queue relief >20% | Classification override rate <5% | Analyst time per case <25 min (avg) | RM/specialist time <10 min per flag |
| **Risk** | Zero duplicate approvals | Zero High-exposure misroutes | Zero extraction-caused rework | Zero provisional-signing events |
| **Control** | Audit trail of duplicates | Override reason logged | Confidence score thresholding | Four-eyes sign-off on High-exposure |

## 7. Final Recommendation

### Recommended Portfolio: **Portfolio B (Bottleneck and Synchronization Focus)**

**Modules in Year 1:**

4. **A12: Control remediation workbench** (Phase 1, M1–2)

### Trade-Off Argument: Why Not Automate by Frequency Alone

**Highest-frequency activity is A1 (Registration, 12,000 cases/month).** However, automating A1 *without* addressing downstream bottlenecks will:

1. **Expose hidden queues:** Back office utilization (12 FTE) is currently below 65% after 15:00, suggesting spare capacity. A1 automation will redirect that capacity upstream, but unmasking misclassification (8%), KYC exceptions (11%), and financial-review rework (24%) will shift burden to Compliance (3 FTE, already saturated) and Credit analysts (9 FTE, central bottleneck).

2. **Cause analyst overload without A6:** If A1 + A2 succeed (clean, correctly-routed cases), the 11,820 cases/month will flow into Financial document review (9,200/month)  Normalize financial statements (5,200/month). At 75 min per case (current manual baseline), 5,200 cases = 6,500 analyst-hours/month. Nine FTE = ~1,440 available hours/month after meetings, admin, and credit-analysis work. **Analyst queue will explode unless A6 (statement normalization) reduces the per-case time from 75 min to ~15 min.**

3. **Defer control improvements:** Frequency-first automation (A1, A2, A5, A10, A11) saves labor but does not strengthen control gates. Compliance mandate requires at least one control-strengthening module. Portfolio A (quick-win) violates this because A11 (loan activation) is unsafe without A12 (control remediation).

### Why Portfolio B Is Superior

**Portfolio B addresses process *dependencies* and *bottlenecks*, not just frequency:**

- **A4 (Entity-mismatch resolver):** Removes 31h median waiting time on 1,750 cases; 82% on critical path. This is a *synchronization bottleneck*—it blocks KYC clearance and contract preparation. Frequency is low, but impact is massive.

- **A6 (Financial-statement normalization):** Prerequisite for downstream success. If A1 + A2 are deployed without A6, analysts will be buried. A6 reduces per-case time from 75 min to ~15 min, freeing analyst capacity for credit analysis (the judgment-heavy task). This is a *resource-bottleneck* fix.

- **A9 (Contract generation):** Embeds control rules (KYC-to-signing gate, contract-termsdecision alignment). Reduces 8.5% contract-rework rate (650 cases/month). Frequency is high (7,600), but the *control-embedding* aspect (not just labor-saving) justifies inclusion.

- **A12 (Control remediation workbench):** Removes 650 provisional-signing case blockages per month; prevents 6.5% signing-before-KYC-clearance violations. This is a *control-gate risk* fix and a *process-dependency* enabler for A9 and A11 (Phase 3).

### Why Portfolio C (Compliance-First) Is Not Recommended for Year 1

Portfolio C (A1, A2, A3, A12) is a *foundation builder* but has **lower Year 1 ROI:**

- **Longer path to bottleneck relief:** A4, A6, A9 (the synchronization/resource fixes) are deferred to Phase 2, meaning critical-path waits (31h mismatch, 20h normalization) persist through Q2.
- **Model-tuning risk:** A2 (classifier) and A3 (KYC pre-classifier) are medium-feasibility, complex models. If accuracy targets are not met by M3–4, the portfolio stalls.
- **Analyst overload potential:** If A1 + A2 succeed without A6, Year 1 will show analyst queue growth before relief arrives in Q3 (when A6 is ready). This creates staffing pressure and political risk mid-year.

**However, Portfolio C is a strong *second-year* strategy** if Phase 1 (A1, A6, A2, A12) is executed first, enabling Phase 2 (A4, A3, A9) to build on solid data quality and control discipline.

### Dependency Justification

**Portfolio B is *internally consistent* in its dependencies:**

- A4 (entity-mismatch resolver) requires A1/A2 to generate clean, correctly-routed cases upstream. 
- A9 (contract generation) requires A4 (resolved entities), A6 (normalized financials), A3 (clean KYC), A12 (control gates). 
- A12 (control remediation) is upstream of A9 and enables A11 (Phase 3). 

**Portfolio B avoids *dangerous cycles*:**

- Does NOT include A1 + A2 without A6 (would cause analyst overload).
- Does NOT include A11 without A12 (would bypass control gates).
- Does NOT leave A4 unresolved before contract prep (would allow entity-mismatch cases to proceed).
