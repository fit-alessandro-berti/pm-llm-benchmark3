# 1. Equivalence Notions

Let complete executions begin at `Open Case`, reach the final marking after `Close Case`, and obey the stated binary-loop semantics. Process-tree `+` is parallel/interleaving, `X` is exclusive choice, `*` is loop, and `->` is sequence.

Duplicate visible labels are **not assigned persistent transition identities** in the language comparisons. A trace is a sequence of labels; repeated labels are distinguished by their **occurrence positions and multiplicity**. Thus `(Analyze, Analyze)` differs from `(Analyze)`, but two executions producing the same label sequence are observationally identical.

### Visible trace equivalence after hiding `tau`

For model \(M\), let \(L_{\mathrm{vis}}(M)\) be the set of all complete firing sequences projected onto visible labels, deleting every `tau`. Models \(A\) and \(B\) are visibly trace-equivalent iff

\[
L_{\mathrm{vis}}(A)=L_{\mathrm{vis}}(B).
\]

This preserves order, multiplicity, approvals, checks, analyses, and reworks.

### Bounded visible-language equivalence under P3

Define

\[
L_{P3}(M)=
\{\sigma\in L_{\mathrm{vis}}(M):
|\sigma|\leq 12
\land
\#_{\text{Analyze Revision}}(\sigma)\leq 3
\}.
\]

Models are P3-equivalent iff these finite bounded languages are equal. `tau` does not contribute to either bound.

This comparison is exhaustive only if all states reachable through arbitrarily many silent transitions and all complete traces meeting the visible bounds are explored. Equality under this bound does not imply unbounded equality.

### Business-relevant equivalence under P1

For each complete trace, partition the revision work into attempts separated by `Rework Case`. P1 observes:

- each `Analyze Revision` occurrence;
- the `Check Revision` associated with that attempt;
- whether the check occurs after that analysis and before the next `Rework Case` or `Close Case`;
- all `Approve Revision` occurrences and their positions;
- attempt boundaries.

A model satisfies P1 compliance if every analysis attempt has its own later check in the same attempt interval:

\[
\forall a_i,\ \exists c_i:
a_i<c_i<b_i,
\]

where \(b_i\) is the next `Rework Case`, or `Close Case` for the last attempt. Distinct attempts require distinct check occurrences.

Two models are P1 business-equivalent when their complete traces induce the same set of compliant attempt-level observations, including approval placement and multiplicity. Under this definition, merely sharing visible activity labels is insufficient.

### Abstracted dashboard equivalence under P2

For a complete trace \(\sigma\), define

\[
\alpha_{P2}(\sigma)=
(\text{open-first},\text{close-last},
N_A,\mathbf{1}_{N_C>0},\mathbf{1}_{N_R>0}),
\]

where \(N_A\), \(N_C\), and \(N_R\) count analyses, checks, and reworks. `Approve Revision`, `tau`, exact check multiplicity, and the interleaving of analysis with check are hidden.

The dashboard accepts only observations having open first, close last, \(N_A\geq1\), and \(N_C\geq1\). Models are P2-equivalent iff their sets of accepted abstract observations are equal.

For both models that set is

\[
\{(1,1,n,1,\mathbf{1}_{n>1}) : n\geq1\}.
\]

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The loop body contains parallel `Analyze Revision`/`Check Revision`, followed by optional approval | The loop contains analysis and optional approval; one check is parallel to the whole loop | A creates one check per attempt; B creates one check per case |
| Minimum Check Revision occurrences | 1 | 1 | Both satisfy P2’s Boolean “a check occurred” requirement |
| Maximum Check Revision occurrences | Unbounded: one per loop-body execution | Exactly 1 | Multiplicity separates the visible languages as soon as A has two attempts |
| Placement of Check Revision | In each attempt, parallel with its analysis; before that attempt’s optional approval and before the next rework/close | Anywhere after open and before the parallel join, interleaved with the entire loop | B’s sole check can occur before all analyses, between attempts, or after all analyses and reworks |
| Optional approval occurrences | Zero or one per attempt | Zero or one per attempt | Approval multiplicity agrees by attempt count, but its ordering relative to checks differs |
| Concurrency | Fresh analysis/check parallel block for every loop iteration | One case-level check concurrent with the entire revision loop | The concurrency scopes differ materially |
| Rework behavior | Between completed per-attempt bodies; therefore after that attempt’s check | Between analysis/approval bodies; the case-level check need not have occurred | B can rework before any check |
| Join before Close Case | Sequence waits for the loop; each attempt already completed its check | Outer parallel join waits for both the single check and the entire loop | B may postpone its check until all revision activity is complete, but never past close |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---:|---|---|
| Full visible trace semantics | not equivalent | High | A has one check per attempt; B has exactly one. Their approval/check ordering also differs for one attempt | This is stricter than P2 |
| P1 operational compliance | not equivalent | High | A guarantees a distinct check after every analysis and before the boundary; B does not | A’s parallel block also permits a check before its analysis, so A does **not fully satisfy** P1 as worded |
| P2 executive dashboard | equivalent only under stated abstraction | High | Both yield every analysis count \(n\geq1\), Boolean check=true, and rework iff \(n>1\) | Equivalence disappears if check count or check placement becomes visible |
| P3 bounded language | not equivalent | High | Counterexamples of 4–7 visible events lie well within the bound | Exhaustive code establishes only the stated finite bound |

Neither original exactly implements P1: Model A guarantees one check per attempt but allows `Check Revision` to occur before its concurrent `Analyze Revision`. Model B additionally loses per-attempt check multiplicity.

# 4. Counterexample Traces

Abbreviations below are expanded to full labels:

- `O` = `Open Case`
- `A` = `Analyze Revision`
- `C` = `Check Revision`
- `P` = `Approve Revision`
- `R` = `Rework Case`
- `Z` = `Close Case`

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---:|---:|---|---|
| A1 | `O, A, P, C, Z` | Yes | No | In A, the parallel check completes before approval can fire, so this row actually needs correction: it is **not** admitted by A | — |
| A2 | `O, A, C, R, A, C, Z` | Yes | No | Two attempts force two checks in A; B has exactly one | P1, P3 |
| A3 | `O, C, A, R, C, A, Z` | Yes | No | Two loop iterations again create two checks | P1, P3 |
| B1 | `O, A, P, C, Z` | No | Yes | B can approve in its loop before its independent case-level check; A requires the parallel check before approval | P1, P3 |
| B2 | `O, A, R, A, C, Z` | No | Yes | B can rework and perform a second analysis before its sole check; A requires a check before each rework | P1, P3 |
| B3 | `O, C, A, R, A, Z` | No | Yes | B’s single early check covers the whole loop; A requires another check in iteration two | P1, P3 |

To satisfy the requirement without treating the explicitly corrected row A1 as a witness, the two valid A-only witnesses are A2 and A3, and the valid B-only witnesses are B1–B3.

The strongest general facts are:

- Every complete Model B trace has exactly one `Check Revision`.
- Every complete Model A trace with \(n\) analyses has exactly \(n\) checks.
- Therefore every A trace with \(n\geq2\) is absent from B, and every B trace with \(n\geq2\) is absent from A.
- For one attempt, some traces overlap, but approval exposes another difference. A’s optional approval is sequenced after completion of both concurrent `Analyze Revision` and `Check Revision`; B’s approval belongs only to the loop and can occur before its independent check.

The hidden `tau` is the branch that omits an approval. Removing `tau` does not remove the choice: both approved and auto-approved visible traces remain possible. Silent transitions neither increase the P3 visible-event count nor appear in counterexamples, but exploration must still fire them to reach all complete visible traces.

# 5. Bounded Comparison Code

The following performs exhaustive breadth-first exploration under P3. A search state includes both marking and visible trace; retaining only the marking would be wrong because different bounded traces can reach the same marking. Silent cycles are controlled by remembering complete `(marking, trace)` states.

```python
import pm4py
from collections import deque

MODEL_A = """->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)"""

MODEL_B = """->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)"""

tree_a = pm4py.parse_process_tree(MODEL_A)
tree_b = pm4py.parse_process_tree(MODEL_B)

net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

print("A sound:", pm4py.check_soundness(
    net_a, im_a, fm_a, print_diagnostics=True))
print("B sound:", pm4py.check_soundness(
    net_b, im_b, fm_b, print_diagnostics=True))

MAX_VISIBLE = 12
MAX_ANALYSES = 3

def marking_key(marking):
    """Canonical hashable representation, including token counts."""
    return tuple(sorted(
        ((p.name, int(tokens)) for p, tokens in marking.items() if tokens),
        key=lambda x: x[0]
    ))

def fire_transition(t, marking):
    """
    Fire an enabled ordinary Petri-net transition without relying on
    a version-specific low-level PM4Py execute() API.
    """
    result = dict(marking)

    for arc in t.in_arcs:
        weight = getattr(arc, "weight", 1)
        result[arc.source] = result.get(arc.source, 0) - weight
        if result[arc.source] == 0:
            del result[arc.source]

    for arc in t.out_arcs:
        weight = getattr(arc, "weight", 1)
        result[arc.target] = result.get(arc.target, 0) + weight

    # Preserve the concrete PM4Py Marking class.
    return marking.__class__(result)

def exhaustive_p3_language(net, im, fm):
    """
    Exhaustive for complete traces satisfying:
      visible length <= 12
      Analyze Revision count <= 3

    Because zero-length silent cycles could otherwise be revisited forever,
    visited states are keyed by (marking, visible trace). Petri nets produced
    from these finite process trees are bounded; hence this bounded product
    state space is finite.
    """
    initial_trace = tuple()
    queue = deque([(im, initial_trace)])
    seen = {(marking_key(im), initial_trace)}
    complete = set()

    while queue:
        marking, trace = queue.popleft()

        # Final-marking equality is explicit, not merely "no enabled moves".
        if marking == fm:
            complete.add(trace)
            # Accepting-net completion ends here for language purposes.
            continue

        for transition in pm4py.get_enabled_transitions(net, marking):
            label = transition.label  # None denotes an invisible transition
            next_trace = trace

            if label is not None:
                if len(trace) >= MAX_VISIBLE:
                    continue
                next_trace = trace + (label,)
                if next_trace.count("Analyze Revision") > MAX_ANALYSES:
                    continue

            next_marking = fire_transition(transition, marking)
            state = (marking_key(next_marking), next_trace)

            if state not in seen:
                seen.add(state)
                queue.append((next_marking, next_trace))

    return complete

lang_a = exhaustive_p3_language(net_a, im_a, fm_a)
lang_b = exhaustive_p3_language(net_b, im_b, fm_b)

only_a = sorted(lang_a - lang_b, key=lambda x: (len(x), x))
only_b = sorted(lang_b - lang_a, key=lambda x: (len(x), x))

print("P3 language sizes:", len(lang_a), len(lang_b))
print("P3 equivalent:", lang_a == lang_b)

print("\nUnique to A:")
for trace in only_a:
    print(trace)

print("\nUnique to B:")
for trace in only_b:
    print(trace)

# Optional heuristic evidence only; this is NOT exhaustive:
# sampled = pm4py.play_out(tree_a)
# Random/default playout may miss rare interleavings, loop counts, and choices.
```

The bounded state key intentionally contains the full visible prefix. Collapsing all visits to the same marking would omit distinct traces. Conversely, `play_out` alone would provide samples rather than a bounded-language proof.

# 6. Stochastic and Footprint Comparison

### Footprints

Footprints summarize relations such as sequence, parallelism, and choice. They can quickly reveal that `Check Revision` has different relations with activities such as `Rework Case` or `Approve Revision`.

```python
fp_a = pm4py.discover_footprints(tree_a)
fp_b = pm4py.discover_footprints(tree_b)

print("Footprints equal:", fp_a == fp_b)
print("A footprint:", fp_a)
print("B footprint:", fp_b)
```

API support can vary by PM4Py version; if direct tree footprints are unavailable, pass the accepting-net representation supported by that installation.

Footprints are abstractions. They generally discard global constraints, multiplicity, and long-range dependencies. Equal footprints would therefore not prove trace equivalence, while unequal footprints are useful evidence of behavioral difference.

### Stochastic languages and EMD

A stochastic language requires declared probability or weight assumptions. The supplied process trees specify nondeterminism, concurrency, and looping, but **no probabilities**. It would be invalid to silently invent uniform branch or loop probabilities.

If stochastic maps are explicitly supplied or learned from data, a version-dependent workflow is:

```python
# Illustrative only: no stochastic probabilities are declared in the task.
#
# stochastic_a = {...}  # Explicit transition/choice weights or learned model
# stochastic_b = {...}
#
# sl_a = pm4py.get_stochastic_language(net_a, im_a, fm_a, stochastic_a)
# sl_b = pm4py.get_stochastic_language(net_b, im_b, fm_b, stochastic_b)
# distance = pm4py.compute_emd(sl_a, sl_b)
# print("EMD:", distance)
```

The exact `get_stochastic_language` signature depends on the PM4Py release and stochastic-map representation; it should be checked with:

```python
import inspect
print(inspect.signature(pm4py.get_stochastic_language))
print(inspect.signature(pm4py.compute_emd))
```

EMD can measure how much probability mass must be moved between traces under an edit-distance-like ground metric. A low EMD gives distributional evidence that common behavior is similar. It does not establish equal support, equal rare behavior, or trace equivalence. Even EMD zero proves only equality under the chosen stochastic-language representation and distance assumptions.

# 7. Complexity Comparison

Counting every operator and leaf as a process-tree node, with the root at depth 0:

| Metric | Model A | Model B |
|---|---:|---:|
| Total process-tree nodes | 13 | 12 |
| Operator nodes | 6 | 5 |
| Visible leaves | 6 | 6 |
| Silent leaves | 1 | 1 |
| Maximum depth, edges from root | 5 | 5 |
| Maximum depth, levels including root | 6 | 6 |
| Duplicate visible-label leaves | 0 | 0 |
| Distinct visible labels | 6 | 6 |

Derivation:

- A operators: outer sequence, loop, inner sequence, parallel, XOR, inner sequence implicit in the displayed loop body structure: 6 total.
- B operators: outer sequence, parallel, loop, inner sequence, XOR: 5 total.
- Both have one leaf for each of the six visible labels and one `tau`.
- “Duplicate-label count” is \(\sum_l \max(0,\text{leaf-count}(l)-1)=0\). Runtime repetitions arise from loops, not duplicate leaves.

Self-contained structural-count code:

```python
from collections import Counter

def tree_metrics(root):
    nodes = 0
    operators = 0
    visible = 0
    silent = 0
    max_depth = 0
    labels = Counter()

    stack = [(root, 0)]
    while stack:
        node, depth = stack.pop()
        nodes += 1
        max_depth = max(max_depth, depth)

        children = list(getattr(node, "children", []) or [])
        if children:
            operators += 1
            stack.extend((child, depth + 1) for child in children)
        else:
            label = getattr(node, "label", None)
            if label is None:
                silent += 1
            else:
                visible += 1
                labels[label] += 1

    duplicate_count = sum(max(0, n - 1) for n in labels.values())

    return {
        "nodes": nodes,
        "operators": operators,
        "visible_leaves": visible,
        "silent_leaves": silent,
        "max_depth_edges": max_depth,
        "depth_levels": max_depth + 1,
        "duplicate_label_count": duplicate_count,
        "distinct_visible_labels": len(labels),
    }

print("A tree metrics:", tree_metrics(tree_a))
print("B tree metrics:", tree_metrics(tree_b))

print("A Petri simplicity:",
      pm4py.simplicity_petri_net(net_a, im_a, fm_a))
print("B Petri simplicity:",
      pm4py.simplicity_petri_net(net_b, im_b, fm_b))

# Also report raw converted-net size rather than relying on one score alone.
def net_metrics(net):
    return {
        "places": len(net.places),
        "transitions": len(net.transitions),
        "silent_transitions": sum(t.label is None for t in net.transitions),
        "arcs": len(net.arcs),
    }

print("A net metrics:", net_metrics(net_a))
print("B net metrics:", net_metrics(net_b))
```

`simplicity_petri_net` is conversion- and PM4Py-version-sensitive, so its numeric result should be computed rather than asserted here. Model B is smaller by one tree operator/node, but that structural reduction changes behavior; it is not a semantics-preserving P1 simplification.

# 8. Simplified Model

The target is **P1 operational compliance**, because per-attempt checking is a safety/compliance requirement and should not be erased merely for dashboard convenience.

A compliant, structurally smaller model is:

```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

It replaces Model A’s per-attempt parallel operator with sequence. This enforces the required order “analysis, then its check, then optional approval,” while retaining attempts, rework boundaries, and visible approval multiplicity.

```python
import pm4py

SIMPLIFIED = """->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)"""

simplified_model = pm4py.parse_process_tree(SIMPLIFIED)
simplified_net, simplified_im, simplified_fm = \
    pm4py.convert_to_petri_net(simplified_model)

print(pm4py.check_soundness(
    simplified_net, simplified_im, simplified_fm,
    print_diagnostics=True
))
```

Its exact structural metrics under the preceding convention are:

| Metric | Model A | Model B | Simplified |
|---|---:|---:|---:|
| Total nodes | 13 | 12 | 12 |
| Operators | 6 | 5 | 5 |
| Visible leaves | 6 | 6 | 6 |
| Silent leaves | 1 | 1 | 1 |
| Maximum depth in edges | 5 | 5 | 5 |

It is simpler than A by one node/operator. It ties B on these tree counts, while being behaviorally simpler in the sense that it removes revision/check concurrency and its interleavings. Converted-net simplicity should also be measured with the code in Section 7; tree counts do not guarantee a particular Petri-net score.

### Preservation table

| Property | Status | Explanation |
|---|---|---|
| Open first and close last | Exact | Outer sequence retained |
| At least one analysis | Exact | Loop body executes once |
| One check per analysis attempt | Exact | Both occur once in every body execution |
| Check after its analysis | Exact and strengthened relative to A | Sequence replaces A’s concurrency |
| Check before next rework or close | Exact | Check is inside body before loop continuation/exit |
| Rework separates attempts | Exact | Standard binary-loop structure retained |
| Optional approval per attempt | Exact | Same `X(Approve Revision, tau)` |
| Approval multiplicity/placement visibility | Exact for intended P1 rule | Approval remains after that attempt’s check |
| Model A traces with check before analysis | Lost intentionally | Such traces violate the selected P1 requirement |
| Model B’s one case-level check | Lost intentionally | Incompatible with per-attempt compliance |
| P2 dashboard observations | Exact after P2 abstraction | Analysis count and any-rework Boolean remain the same; repeated checks collapse to true |
| Full visible language of A or B | Not preserved | The target is P1 compliance, not either original language |

### Regression traces

These must be admitted:

1. `Open Case, Analyze Revision, Check Revision, Close Case`
2. `Open Case, Analyze Revision, Check Revision, Approve Revision, Close Case`
3. `Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close Case`
4. `Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, Analyze Revision, Check Revision, Approve Revision, Close Case`

These must be rejected:

1. `Open Case, Check Revision, Analyze Revision, Close Case`
2. `Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case`
3. `Open Case, Analyze Revision, Approve Revision, Check Revision, Close Case`

A compact regression check can reuse `exhaustive_p3_language`:

```python
simple_lang = exhaustive_p3_language(
    simplified_net, simplified_im, simplified_fm
)

positive = {
    ("Open Case", "Analyze Revision", "Check Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Check Revision",
     "Approve Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
     "Analyze Revision", "Check Revision", "Close Case"),
}

negative = {
    ("Open Case", "Check Revision", "Analyze Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Rework Case",
     "Analyze Revision", "Check Revision", "Close Case"),
}

assert positive <= simple_lang
assert negative.isdisjoint(simple_lang)
```

# 9. Final Recommendation

- **P1:** Neither original is fully suitable. Model A is substantially closer because it creates one check per attempt, but its parallel operator permits checking before analysis. Replace A with the simplified sequential per-attempt model if P1’s wording is mandatory. Model B is unsuitable.
- **P2:** Models A and B are equivalent only after the declared dashboard abstraction. Either can feed that dashboard, but Model B more directly represents one case-level check, whereas the simplified model preserves the same dashboard outputs while retaining stronger operational compliance.
- **P3:** The originals are not equivalent. Short bounded counterexamples exist in both directions. Model A-only and Model B-only behavior appears well below the 12-event/three-analysis limits.

The simplified P1 model should replace Model A when the intended rule is genuinely “analyze, then check each attempt.” It should not be described as preserving Model A’s complete visible language, because it deliberately removes check-before-analysis interleavings. It should replace Model B only if the business changes from one case-level check to one check per attempt.

Finally, bounded equality would only show agreement within the chosen test envelope. It cannot prove unbounded trace equivalence; loops can introduce differences after the bound even when every bounded test passes.
