## 1. Analytical assumptions

- **Case notion:** In this context, a case notion is a projection boundary that groups events into a linear trace for traditional process mining. Flattening an OCEL onto an object type treats each instance of that type as an independent case, copying all directly related events into its trace.
- **Convergence:** Occurs when multiple distinct objects participate in a single event (e.g., `e13` packing `I21` and `I31`). Flattening breaks convergence by duplicating the event across separate traces, thereby hiding the merge point and inflating apparent parallelism.
- **Divergence:** Occurs when one object spawns or links to multiple downstream objects (e.g., `O1` split across `P1` and `P2`). Flattening preserves divergence in the trace but duplicates intermediate events, which can distort cycle-time calculations and variant frequencies.
- **Copied shared events:** I treat them as both structural evidence and analytical duplication. They accurately reflect that the event touched multiple objects, but in a flattened log they behave as independent occurrences, artificially boosting frequency metrics and creating false concurrency in DFGs. I will explicitly flag them when evaluating distortion.
- **Analytical transformations:** I will not silently propagate E2O relations through the O2O graph. Propagation (e.g., linking `I11` to `O1` via `contains`) is permitted only as an explicit sensitivity variant in Section 7. The baseline analysis strictly respects the provided E2O relations.
