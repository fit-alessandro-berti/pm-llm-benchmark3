## 1. Interaction-graph description

The system is best modeled as a typed hypergraph where objects of different types interact via temporal, resource, and policy constraints. A flattening collapses these interactions into a single process view, obscuring the multi-object coupling.

**Node Types:**
- **Job (J1–J6):** Primary work items with readiness timestamps.
- **Component (C1–C6):** Physical parts consumed by jobs.
- **ComponentLot (L7, L8):** Batches of components subject to quality events (Quarantine/Release).
- **Batch (B1, B2):** Aggregations of jobs requiring simultaneous machine/tool usage.
- **Machine (CNC-2, OVEN-1, TEST-1):** Processing resources with utilization gaps.
- **Tool (FIX-A, RACK-7, CAL-3):** Shared fixtures/calibrators required for operations.
- **Shipment (S1–S3):** Aggregations of jobs for dispatch.

**Edge Types and Qualifiers:**
- `requires`: Job  Component (static dependency).
- `contains`: ComponentLot  Component, Batch  Job (composition).
- `consolidates`: Shipment  Job (logistics grouping).
- `uses`: Job  Machine/Tool (dynamic resource acquisition, inferred from acquire/release events).
- `affects`: ComponentLot  Job (quality events blocking progress, inferred from timing).
- `synchronizes`: Batch  Job (temporal barrier at batch start).
- `delays`: Job  Shipment (waiting for partners, inferred from packed/dispatch gaps).

**Higher-Order Motifs:**
1. **Lot-Coupling Motif:** `Job J2`  `Component C2`  `ComponentLot L7`  `Quarantine/Release`  `Job J5`. A quality event on L7 blocks J2 and J5 simultaneously. J2 bypasses via override; J5 waits. This creates a divergent outcome for jobs sharing a lot.
2. **Batch-Sync-Tool Motif:** `Jobs J1, J2, J3`  `Batch B1`  `Machine OVEN-1` + `Tool RACK-7`. B1 requires synchronization of three jobs and a shared tool. RACK-7 cleaning in B2 propagates delay to J4/J5.
3. **Shipment-Consolidation Motif:** `Job J1`  `Shipment S1`  `Job J4`. J1 completes early but waits for J4. S1 policy imposes a post-completion lag. This couples the completion time of J1 to J4's readiness, independent of machine constraints.

   - *Attributable Delay:* **3h 55m**.

2. **J2 Synchronization Waiting in B1:**
   - *Observed:* J2 ready 08:25, Batch starts 12:05.
   - *Calculation:* $12:05 - 08:25 = 3\text{h } 40\text{m}$.
   - *Counterfactual:* Immediate single-job processing.
   - *Attributable Delay:* **3h 40m**.

3. **Delay Associated with FIX-A for J4:**
   - *Observed:* J4 arrives CNC-2 at 09:50. J3 releases FIX-A at 11:40. J4 process starts 11:45. CNC-2 idle 10:05–10:47.
   - *Calculation:* J4 blocked 09:50 to 11:40 by FIX-A unavailability (1h 50m). CNC-2 available 10:05. If FIX-A free at 09:50, J4 could start 10:05.
   - *Counterfactual:* FIX-A available at 09:50. J4 starts 10:05. Actual start 11:45.
   - *Attributable Delay:* $11:45 - 10:05 = 1\text{h } 40\text{m}$. (Note: 100 min of total 115 min wait is FIX-A related).

4. **Delay Imposed on J1 by S1 Consolidation:**
   - *Observed:* J1 packed 13:30. S1 dispatch 19:25. S2/S3 dispatch ~30m after last job.

   - *Counterfactual:* If S1 dispatched immediately upon J1 packed (or with standard 15m lag for first job), dispatch ~13:30–13:45.
   - *Attributable Delay:* **~5h 40m** waiting for J4 (J4 packed 19:10).

5. **Delay Associated with CAL-3 Recalibration for J6:**
   - *Observed:* J6 ready 16:05. J5 tests 16:10–16:35. CAL-3 recal 16:35–17:20. J6 tests 17:25.
   - *Calculation:* J6 wait = $17:25 - 16:05 = 1\text{h } 20\text{m}$.
   - *Counterfactual:* If CAL-3 recalibration did not occur (or J6 had priority), J6 could start 16:35 (immediately after J5).
   - *Attributable Delay:* $17:25 - 16:35 = 50\text{m}$ due to CAL-3 recal. (Remaining 30m due to J5 queue).

## 4. What flattening misses

- **Job Flattening:**
  - *Visible:* Activity sequence, per-job duration.
  - *Hidden:* Lot blocking, batch sync waits, shipment partner waits.
  - *Misleading Conclusion:* "No job exceeds 1.8 duration." Masks extreme coupling waits; J1/J2 appear normal because waits are attributed to "Stage Component" or hidden.

- **Machine Flattening:**
  - *Visible:* Utilization, gaps, sequences.
  - *Hidden:* Reasons for gaps (tool unavailability, lot quarantine, batch sync).
  - *Misleading Conclusion:* "No severe machine bottleneck." Utilization low, but jobs wait due to resource constraints outside machines.

- **Batch Flattening:**
  - *Visible:* Batch start/end, composition.
  - *Hidden:* Job-level readiness variance within batch.
  - *Misleading Conclusion:* Batches look efficient; ignores that early-ready jobs wait hours.

- **Tool Flattening:**
  - *Visible:* Tool usage duration.
  - *Hidden:* Tool acquisition delays, contention with other jobs.
  - *Misleading Conclusion:* Tools used; ignores queuing.

- **ComponentLot Flattening:**
  - *Visible:* Quarantine/Release events.
  - *Hidden:* Impact on downstream jobs.
  - *Misleading Conclusion:* Lots processed; ignores job delays caused by lot status.

- **Shipment Flattening:**
  - *Visible:* Create->Load->Dispatch timing.
  - *Hidden:* Job-to-shipment wait.
  - *Misleading Conclusion:* "Shipment fast." J1 waits 6h hidden; only dispatch latency visible.

**Low Utilization vs. Long Wait:** Machines are idle because jobs cannot proceed due to unavailability of inputs (lots, tools, batch partners). Utilization measures machine busy time, not system throughput or job flow. Gaps reflect resource constraints elsewhere.

## 5. Object-lifecycle evidence

**Narrative 1: J1, B1, OVEN-1, RACK-7, S1**
- *Temporal:* J1 ready 08:10  B1 starts 12:05  B1 ends ~13:18  J1 packed 13:30  S1 dispatch 19:25.
- *Resource:* RACK-7 required for B1. OVEN-1 processes B1. S1 consolidates J1/J4.
- *Policy:* Batch window forces J1 to wait 4h. Shipment policy forces J1 to wait 6h post-pack.
- *Causal:* RACK-7 availability and batch sync policy cause initial delay; shipment policy causes final delay. J1 delayed by ~10h total due to coupling.

**Narrative 2: J4, FIX-A, CNC-2, J3**
- *Temporal:* J3 acquires FIX-A 09:00  J4 arrives CNC-2 09:50  J3 releases FIX-A 11:40  J4 process 11:45.
- *Resource:* FIX-A shared. CNC-2 available 10:05 but idle until J4 gets FIX-A.
- *Policy:* No explicit tool scheduling. J4 must wait for J3.
- *Causal:* J3 holds FIX-A, blocking J4. CNC-2 idle gap (10:05–10:47) confirms J4 unable to start despite machine availability. Delay ~100m attributable to FIX-A.

**Narrative 3: J5, L7, J2, B2, CAL-3**
- *Temporal:* L7 Quarantine 10:20  L7 Release 13:50  J5 ready 14:40  B2 starts 14:50  J5 test 16:10  CAL-3 recal 16:35  J6 test 17:25.
- *Resource:* L7 contains C5 (J5). CAL-3 required for test.
- *Policy:* Lot release blocks J5 (if ready earlier). J2 override bypasses lot. CAL-3 recal policy blocks J6.
- *Causal:* Lot coupling creates divergent paths for J2/J5. J5 waits for lot release (if ready <13:50). CAL-3 recal delays J6. J5 test 16:10 suggests J5 ready after release, but lot coupling risk remains.

## 6. Intervention portfolio and spillovers

1. **Dynamic Batching / Reduced Batch Windows**
   - *Target:* Batch synchronization.
   - *Benefit:* J1/J2 waits reduced.
   - *Helped:* J1, J2, J3.
   - *Harmed:* OVEN-1 utilization may drop; setup overhead may increase.
   - *Risk:* Reduced batch efficiency.
   - *Perverse Metric:* If OVEN-1 util is KPI, utilization drops.
   - *Evaluation:* Compare J1/J2 wait times before/after; track OVEN-1 util.

2. **Tool Duplication or Scheduling for FIX-A**
   - *Target:* Shared tool contention.
   - *Benefit:* J4 starts earlier.
   - *Helped:* J4.
   - *Harmed:* Capex increase.
   - *Risk:* Underutilized second fixture.
   - *Perverse Metric:* If tool cost is KPI, ROI may fail.
   - *Evaluation:* Measure J4 start time; track FIX-A wait events.

3. **Partial Shipment / Early Dispatch Policy**
   - *Target:* Shipment consolidation.
   - *Benefit:* J1 dispatches earlier.
   - *Helped:* J1.
   - *Harmed:* Logistics cost increases; J4 may not benefit.
   - *Risk:* Customer dissatisfaction with partial shipments.
   - *Perverse Metric:* If dispatch count is KPI, partial shipments inflate count.
   - *Evaluation:* Track J1 dispatch time; measure logistics cost delta.

4. **Lot Release Pre-Approval or Faster QC**
   - *Target:* Component lot release.
   - *Benefit:* J5 availability improves.
   - *Helped:* J5, J2.
   - *Harmed:* Quality risk if pre-approval used.
   - *Risk:* Defects escape quarantine.
   - *Perverse Metric:* If defect rate is KPI, pre-approval may increase rate.
   - *Evaluation:* Track L7 release time; measure J5 readiness vs release.

5. **Logging Integration for Lot-Job Links**
   - *Target:* Data integration artifacts.
   - *Benefit:* Visibility of lot blocking.
   - *Helped:* Managers, analysts.
   - *Harmed:* Data volume increases.
   - *Risk:* No operational change; only visibility.
   - *Perverse Metric:* If log volume is KPI, volume increases.
   - *Evaluation:* Compare Job flattening with/without lot links; measure detection time of lot issues.
