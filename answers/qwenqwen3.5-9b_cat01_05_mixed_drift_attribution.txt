## 2. Raw-versus-normalized interpretation

The divergence between `raw_model_fitness` and `mapped_model_fitness` in March is definitive evidence of logging drift, not process failure. The raw model penalized the schema change (`Eligibility Screen` vs. `Validate Eligibility`) and technical duplication (`Open Case`), causing the 40-point fitness drop. The mapped model recovers because it normalizes labels, proving the business logic remained intact during migration. However, the persistent gap post-March indicates real process drift. A label mapping recovers conformance scores without proving the underlying process is unchanged; it merely confirms the *schema* is not the cause of the deviation.

Duplicated technical events artificially inflate volume and skew DFG frequencies in raw logs, making March appear worse than it was operationally. Missing resource identifiers obscure accountability but do not inherently change cycle times. Crucially, the post-May DFG patterns—specifically the sustained rise in `Assess->RequestInfo` and `rework_variant_pct`—cannot be dismissed as logging artifacts. These represent genuine control-flow deviations (rework loops) and performance degradation (waiting times) that persist even after the schema is corrected. Therefore, while March was purely semantic, May through December reflects compounded operational drift driven by supplier and staffing factors.

import pandas as pd
import numpy as np
import math

# 1. Embed Data
monthly_data = {

    'cases': [620, 640, 680, 715, 760, 690],
    'high_complexity_pct': [21, 22, 25, 28, 41, 34],
    'rework_variant_pct': [12, 12, 24, 29, 26, 21],
    'median_cycle_h': [31.5, 31.2, 36.5, 44.2, 47.8, 42.3],
    'raw_model_fitness': [0.92, 0.55, 0.49, 0.5, 0.55, 0.58],
    'mapped_model_fitness': [0.92, 0.9, 0.88, 0.86, 0.88, 0.9]
}
df_metrics = pd.DataFrame(monthly_data)

# 2. Calculate Baseline-Relative Changes
baseline = df_metrics.iloc[0]
df_metrics['rel_complexity'] = df_metrics['high_complexity_pct'] / baseline['high_complexity_pct']
df_metrics['rel_cycle'] = df_metrics['median_cycle_h'] / baseline['median_cycle_h']

# 3. Compute DFG Distance (Euclidean on Normalized Rates)
dfg_rates = {
    '2026-01': [100, 98, 95, 12, 11, 4, 83],
    '2026-03': [100, 98, 94, 12, 11, 5, 82],
    '2026-05': [100, 96, 91, 24, 23, 7, 76],
    '2026-07': [100, 95, 89, 29, 28, 9, 72],
    '2026-10': [100, 95, 90, 26, 25, 22, 73],
    '2026-12': [100, 97, 93, 21, 20, 14, 78]
}

def euclidean_dist(v1, v2):
    return math.sqrt(sum((a-b)**2 for a, b in zip(v1, v2)))

baseline_dfg = np.array(dfg_rates['2026-01'])
df_metrics['dfg_distance'] = df_metrics['month'].apply(lambda m: euclidean_dist(baseline_dfg, np.array(dfg_rates[m])))

# 4. Raw-to-Mapped Fitness Recovery
df_metrics['fitness_gap'] = df_metrics['raw_model_fitness'] - df_metrics['mapped_model_fitness']

# 5. Flag Change Points (Simple Rule: Fitness Drop > 0.2 or DFG Dist > 0.15)
df_metrics['change_point'] = df_metrics.apply(
    lambda r: 'Logging' if r['fitness_gap'] > 0.3 else ('Behavioral' if r['dfg_distance'] > 0.15 else 'Stable'),
    axis=1
)

# 6. Caveats
print("Caveat: Omitted edges in DFG fragments may underestimate distance.")
print("Caveat: Aggregate data masks team-level variations.")
