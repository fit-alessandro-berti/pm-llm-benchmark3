The collapse is best explained by several measurement breaks stacking in sequence, not a single behavioural rupture. The UI release changed the recorded label for the same classification step, so alignments charged a log move for Risk Screen and a model move for Classify on almost every case. The gateway then inserted Queue Routed, a technical routing event absent from the model, adding a log move per case and raising events per case without changing cycle time or approvals. The ETL change used warehouse ingestion time for Decision and Notify instead of source-system order, so cases ingested out of order appeared as Notify before Decision, creating log and model moves. Each repair removed one layer: mapping the label lifted fitting from 32% to 58%, removing Queue Routed to 81%, and ordering by source sequence to 89%, with mean cost 0.12. That staged recovery shows most of the drop was artefactual. It is not the whole story. Traces remain where Enhanced Review goes directly to Decision, and Manual Override persists, which could be true bypasses, missing Compliance Check events, or corrections of routing errors. Supervisor Sign-off after August is probably legitimate but unmodelled; without stratifying by the omitted high-value attribute we cannot tell whether it is selective or indiscriminate. Unchanged approval and appeal rates neither prove data error nor exonerate staff: outcomes are lagging aggregates insensitive to a few bypassed checks, and incident detection is incomplete. Conformance must be re-estimated on provenance-correct data before behavioural conclusions.

}


def build_log(variant_dict):
    """Expand variant frequencies into a PM4Py event log string and parse it."""
    lines = []
    for trace, count in variant_dict.items():
        lines.extend([trace] * count)
    return pm4py.parse_event_log_string("\n".join(lines))


def normalize_log(log, map_label=True, remove_technical=True):
    """Transparent normalization: Risk Screen to Classify and optional Queue Routed removal."""
    if isinstance(log, pd.DataFrame):
        df = log.copy()
        if map_label:
            df["concept:name"] = df["concept:name"].replace({"Risk Screen": "Classify"})
        if remove_technical:
            df = df[df["concept:name"] != "Queue Routed"]
        return df

    # Fallback for an EventLog object: reconstruct normalized trace strings and reparse.
    lines = []
    for trace in log:
        activities = []
        for event in trace:
            try:
                activity = event["concept:name"]
            except Exception:
                activity = event.get("concept:name", "")
            if map_label and activity == "Risk Screen":
                activity = "Classify"
            if remove_technical and activity == "Queue Routed":
                continue
            activities.append(activity)
        lines.append(",".join(activities))
    return pm4py.parse_event_log_string("\n".join(lines))


def alignment_diagnostics(log, net, im, fm):
    """Compute fitting percentage, mean alignment cost, and dominant log/model moves."""
    alignments = pm4py.get_alignment(log, net, im, fm)
    fitting = 0
    total_cost = 0
    move_counter = Counter()

    for item in alignments:
        alignment = item["alignment"]
        cost = sum(1 for log_move, model_move in alignment if log_move == ">>" or model_move == ">>")
        total_cost += cost
        if cost == 0:
            fitting += 1
        for log_move, model_move in alignment:
            if log_move != ">>" and model_move == ">>":
                move_counter[("log", log_move)] += 1
            if model_move != ">>" and log_move == ">>":
                move_counter[("model", model_move)] += 1

    n = len(alignments) if alignments else 1
    return {
        "fitting_pct": 100.0 * fitting / n,
        "mean_cost": total_cost / n,
        "dominant_moves": move_counter.most_common(10),
    }


def evaluate(log, net, im, fm, label):
    """Discover DFG, compute alignment diagnostics, fitness, and precision."""
    dfg = pm4py.discover_dfg(log)
    top_dfg = sorted(dfg.items(), key=lambda kv: kv[1], reverse=True)[:10]
    diagnostics = alignment_diagnostics(log, net, im, fm)
    fitness = pm4py.fitness_token_based_replay(log, net, im, fm)
    precision = pm4py.precision_token_based_replay(log, net, im, fm)

    print(f"\n=== {label} ===")
    print("Top DFG edges:", top_dfg)
    print("Alignment diagnostics:", diagnostics)
    print("Token-based fitness:", fitness)
    print("Token-based precision:", precision)
    return {
        "dfg": dfg,
        "diagnostics": diagnostics,
        "fitness": fitness.get("fitness") if isinstance(fitness, dict) else fitness,
        "precision": precision.get("precision") if isinstance(precision, dict) else precision,
    }


def main():
    jun_jul_log = build_log(jun_jul_variants)
    aug_sep_log = build_log(aug_sep_variants)

    # Raw versus normalized comparison for June-July.
    print("June-July raw log")
    evaluate(jun_jul_log, normative_net, normative_im, normative_fm, "Jun-Jul raw, normative model")

    jun_jul_mapped = normalize_log(jun_jul_log, map_label=True, remove_technical=False)
    evaluate(jun_jul_mapped, normative_net, normative_im, normative_fm, "Jun-Jul label mapped only")

    jun_jul_normalized = normalize_log(jun_jul_log, map_label=True, remove_technical=True)
    evaluate(jun_jul_normalized, normative_net, normative_im, normative_fm, "Jun-Jul label mapped and Queue Routed removed")

    # Candidate model permitting optional Supervisor Sign-off.
    # Note: the supplied aggregates have no source-sequence field, so source ordering
    # cannot be reproduced from these variant strings alone.
    candidate_pt_str = (
        "->('Receive','Classify',"
        "X(*('Standard Review','Request Info'),"
        "->('Enhanced Review','Compliance Check')),"
        "X('Supervisor Sign-off',tau),"
        "'Decision','Notify')"
    )
    candidate_pt = pm4py.parse_process_tree(candidate_pt_str)
    candidate_net, candidate_im, candidate_fm = pm4py.convert_to_petri_net(candidate_pt)

    aug_sep_normalized = normalize_log(aug_sep_log, map_label=True, remove_technical=True)
    evaluate(aug_sep_normalized, normative_net, normative_im, normative_fm, "Aug-Sep normalized, normative model")
    evaluate(aug_sep_normalized, candidate_net, candidate_im, candidate_fm, "Aug-Sep normalized, optional sign-off candidate")

    print("\nCAVEAT: The optional Supervisor Sign-off candidate is control-flow only.")
    print("CAVEAT: It cannot enforce the EUR 50,000 data condition, so it allows sign-off for low-value cases.")
    print("CAVEAT: It may overgeneralize and inflate fitness while reducing precision.")
    print("CAVEAT: Variant aggregates lack timestamps, source sequence, resources, and high-value attributes,")
    print("CAVEAT: therefore exact alignment percentages from the brief cannot be reproduced from these strings alone.")


if __name__ == "__main__":
    main()

## 7. Provisional conclusion

The measured collapse from 93% fitting in April-May to 32% in June-July is primarily a measurement and model-governance failure, not evidence of a general breakdown in how claims were worked. Timing and staged repair are diagnostic: renaming Risk Screen back to Classify, removing the technical Queue Routed event, and restoring source-system order moved fitting to 89% and mean alignment cost to 0.12 in June-July. Those repairs track the May-June UI, gateway, and ETL changes and are supported by the audit samples. My confidence that these three mechanisms explain most of the June-July drop is high, around 85%. For August-September, the additional failure is model obsolescence: Supervisor Sign-off became policy for claims above EUR 50,000 on 1 August but the process tree was not updated, so compliant high-value cases were penalised. Adding optional sign-off raised fitting from 66% to 86%, although that model is over-permissive and cannot enforce the value threshold. Confidence in model obsolescence as the main August-September driver is moderately high, around 75%, pending high-value stratification.

A real compliance concern may nevertheless remain. After label, technical-event, and ordering repairs, some Enhanced Review traces still go directly to Decision without a recorded Compliance Check, 25 in June-July and 30 in August-September, and Manual Override persists. No reliable audit has distinguished true bypass from missing events, and unchanged approval and appeal rates do not resolve this because incident detection is incomplete and outcomes are insensitive to a small number of cases. My confidence that a material number of true bypasses remains is low to moderate, around 35%, but the potential regulatory impact justifies investigation regardless of its probability.

IT should freeze semantics, publish an event contract, re-extract Decision and Notify in source order, and retain raw and normalised logs with provenance. Process owners should version the model, replace the control-flow-only optional sign-off with a data-aware rule for high-value cases, and decide whether Queue Routed and Manual Override belong in the business process. Compliance should run a stratified manual audit of no-check enhanced cases and reviewer-level analysis before judging individuals. It must not yet be claimed that employees became noncompliant, that all deviations were data errors, or that optional sign-off proves policy conformance.

## 8. Model-governance recommendation

1. Model versioning: maintain a versioned normative model registry in which every policy change, including the EUR 50,000 Supervisor Sign-off rule, requires a dated model revision, owner approval, and an effective-date mapping before conformance is reported against the old version.
2. Event-semantic contracts: require each activity label, including Risk Screen versus Classify, to have a contract specifying its business meaning, source system, UI screen, generating actor, and allowed predecessors and successors, with changes treated as breaking semantic changes until proven equivalent.
3. Technical-event policy: maintain an explicit allowlist separating business activities from technical events such as Queue Routed, record the generator and purpose for every technical event, and exclude or separately report technical events in business conformance unless the process owner formally adopts them.
4. Timestamp provenance: store source-system timestamp, source sequence number, ingestion timestamp, and ETL transformation version for every event, and require conformance jobs to state which ordering field they use and to preserve the alternatives for audit.
5. Data-aware constraints: encode high-value, claim amount, and other policy conditions as data-aware constraints or decision rules rather than optional control-flow steps, and report fitness and precision stratified by the relevant case attributes so optional steps cannot overgeneralize.
6. Post-release validation: after any UI, gateway, ETL, or logging release, run a mandatory validation comparing variants, frequency DFGs, alignment moves, fitness and precision, event counts per case, and missing-field rates against the pre-release baseline, with sign-off blocked until label, order, and technical-event effects are explained.
