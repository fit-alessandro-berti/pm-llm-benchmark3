# 1. Stress scenarios
Define scenarios by **mix + disruption**, not total volume alone. Peak is already +43% weekly rate (2,300/week normal to 3,300/week peak) but with mix shift: Routine 61%->42%, Urgent 18%->29%, Complex 13%->20%.

**S1 - Winter Urgent + Complex surge:** Total ~3,300-3,800/week, Urgent >=28%, Complex >=18%, Repeat ~9-11%. No equipment outage, but demand composition stresses downstream validators. This is observed peak log: `Technical validation -> Medical validation` 3,900/15,890 (24.5%) normal to 3,420/8,080 (42.3%) peak; `-> Hold for specialist review` 290 to 610 (1.8% to 7.5% of technical exits). Tests SLA breach for Urgent and p90 explosion for Complex.

**S2 - Assay degradation / M2 outage:** M2 higher failure rate but faster runtime; M1 alone or degraded throughput. Triggers: night-shift clustering + M2 usage already linked to Repeat-after-failure. Peak already shows assay stress: `Assay run -> Repeat assay` 1,140/17,270 runs (6.6%) normal to 1,260/9,170 (13.7%); `Repeat assay -> Assay run` median 10h->26h; `Batch wait -> Assay run` median 9h->22h; utilization M1/M2 71%->98%, median queue 4.0h->18.0h. Full M2 loss removes ~40-50% assay capacity and doubles re-entrance load.

**S3 - Medical validator / specialist-review absence:** Evening/weekend gap + one specialist unavailable every second Friday. Normal medical utilization 58% looks safe, peak 93% with median queue 2.0h->22.0h; specialist 43%->87%, median queue 5.0h->36.0h, edge `Hold -> Medical validation` 18h->48h median. Complex-panel 3.1x more likely to need medical validation, 2.4x more likely to enter Hold. Even moderate S1 mix triggers this bottleneck without any volume growth.

**S4 - Courier arrival compression + intake delay:** 10:00 and 17:00 spikes, winter road delays turning into bunched arrivals. Courier intake 60%->88%, queue 1.0h->7.5h; `Register -> Receive sample` 5h->8h; `Receive -> Pre-analytical check` 2h->9h. Recollection loop adds clerk work: `Request recollection -> Receive sample` 42h->60h median, consumes intake capacity via physician explanations.

**S5 - Pre-analytical quality cascade (compound):** Poor sample quality + overtime errors + M2 repeats. Pre-analytical check 74%->96%, queue 1.8h->9.5h; recollection rate `Pre-analytical -> Request recollection` 760/18,120 (4.2%) to 780/9,730 (8.0%); `Manual accession correction -> Request recollection` 70 to 110; overall rework 7.5%->11.8%; cases with queue >12h 22%->54%. This scenario links front-end failure to back-end overload: every recollection and repeat consumes assay twice (Repeat-after-failure median 70h->145h, p90 132h->240h).

# 2. Bottleneck-migration analysis
Logic: utilization >85-90% + large median queue jump + outgoing DFG share change = migrating bottleneck. Relieving upstream without downstream protection moves the queue.

**S1 sequence: Pre-analytical -> Preparation/Batch -> Assay -> Technical -> Medical/Specialist.**
Evidence: front-end still congests first (pre-analytical 96%, prep benches 89% queue 11.0h, batch entries `Test prep -> Batch wait` 760 to 1,180 despite fewer total cases). Urgent bypass of Batch wait falls 74%->58% in peak: urgent protection collapses, fragmenting machine schedules. Then assay queue 18h + technical validators 101% queue 16h become hard block. Finally `Technical -> Medical` median 8h->24h explains Urgent p90 19h->33h (breach of 18h contract) and Complex median 64h->111h, p90 118h->210h via 48h Hold edge. If you add strict Urgent-first (I1) here, Urgent median improves but Routine starves: Routine median already 38h->62h, p90 68h->120h (breach of 72h target), WIP rises and pre-analytical + accession queues worsen because starved Routine cases wait and re-enter queries.

**S2 sequence: Assay -> Repeat loop -> Technical starvation then flooding -> Medical idle then surge.**
Degraded assay amplifies the repeat loop: Assay->Repeat 3h->8h plus Repeat->Assay 10h->26h means each failure costs ~34h median in peak vs 13h normal. Repeat-after-failure cases consume assay twice, clustered after night shifts/M2 usage. Preparation batching (I2: 12 to 24) improves setup efficiency upstream but delivers work in bursts to already 98% assay, spiking `Batch wait -> Assay` 22h and forcing more Urgent into batch path. Dedicating M1 to Urgent/Complex (I3) protects critical cases initially but pushes all Routine to failure-prone M2; under high load M2 repeat rate rises, total assay demand inflates (re-entrance), and M1 idles on low Routine days while M2 queue explodes. Automating registration (I8) in S2 is dangerous alone: it relieves clerks (68%->85%) but exposes pre-analytical (96%) and assay (98%) — faster inflow with no outflow gain increases WIP and p90 without improving SLA adherence.

**S3 sequence: Medical/Specialist -> Technical Hold -> Assay throttling -> Preparation WIP inflation.**
Medical queue 22h + specialist 36h + `Hold -> Medical` 48h means Complex-panel cannot exit. `Technical -> Hold` 6h->12h, Hold->Medical volume 260->560 (more than doubles). Technical validators become holders of WIP waiting for medical sign-off, so their 101% utilization is partly blocked time, not throughput. Adding evening medical shift (I5) relieves this but immediately overloads Release and increases transport/traceability load if combined with outsourcing (I10). Cross-training technical validators to accession (I4) backfires in S3: accession 62%->91% queue 14h looks attractive to relieve, but technical is already >100% — moving 2 validators creates shortage in technical validation, lengthening `Assay -> Technical` 5h->15h and stalling even Routine cases that could have bypassed medical (`Technical -> Release` falls from 11,700/15,890 to 4,050/8,080).

**S4 sequence: Courier/Registration -> Pre-analytical -> Accession correction -> Recollection loop.**
Compressed arrivals create synchronized queues: registration 2.8h + courier 7.5h + pre-analytical 9.5h stack. Accession specialists (only 2) go 62%->91%, queue 3.0h->14.0h, edge `Manual correction -> Test prep` 5h->16h. Poor triage under time pressure increases `Pre-analytical -> Request recollection` and `Manual -> Request recollection` (70->110). Recollection loop median 60h dominates Routine 62h median and Repeat 145h median — front-end defect creates 2-3 day penalty that no downstream speedup can recover. Smoothing couriers (I7) without adding pre-analytical triage capacity just moves queue from intake to pre-analytical check; early defect triage (I6) within 2h helps but if rejection criteria are too strict, cancellations rise (`Request recollection -> Cancel` 290->370, `Cancel -> END` 570->540 on smaller base = higher cancel rate) and clerk explanation load reduces intake capacity further.

**S5 sequence: Pre-analytical/Accession -> Assay repeats -> Every downstream queue.**
This is the observed peak trap: front-end quality failure + back-end repeat failure compound. % queue >12h 54% means more than half experience at least one long wait; optimizing historical average (Routine median 38h) hides p90 68h->120h and Repeat p90 240h. Any single-station fix migrates: larger Routine batches (I2) help prep efficiency but delay Urgent unless exceptions are perfect; holding Routine releases for batch reports (I9) saves release work but adds waiting that directly breaches 72h Routine target already at p90 120h and inflates WIP that clogs accession and prep.

Prioritization constraint: Urgent (18h penalty), Complex (specialist-dependent, long p90), Routine (batch-tolerant but 72h target) cannot all be first. Peak proves it: when Urgent bypass drops to 58%, all three medians deteriorate simultaneously.

# 3. Robust redesign package
Goal: acceptable p90/SLA across S1-S5, not best average in normal period. Do not add capacity everywhere. Baseline robust bundle (always on):

**R1 - Early pre-analytical defect triage within 2h (modified I6) + protected recollection channel.**
Why robust: cuts 42h/60h recollection penalty at source, reduces assay waste from poor samples, helps S1, S4, S5 and indirectly S2/S3 by lowering re-entrance. Evidence: recollection rate doubled in peak; failure here creates loops. Must include dedicated clerk time for physician explanation so triage does not steal intake capacity. Assumption: lab can define objective reject criteria and rapid feedback to wards. Fails if: reject threshold too aggressive -> cancel surge and recollection explanation overload; or if courier delay makes 2h infeasible -> needs time-from-receipt, not from registration, SLA.
Downstream risk: increases short-term `Request recollection` and `Cancel` volume; without smoothing (R2) it floods courier intake. Mitigate by pairing with R2.

**R2 - Courier smoothing + registration automation for complete metadata only (I7 + limited I8).**
Why robust: de-bunches 10:00/17:00 peaks, cuts registration 0.7h->2.8h queue growth without requiring overtime errors (>9h shifts). Limit I8 to complete digital metadata to avoid pushing defective orders to pre-analytical. Assumption: wards/couriers accept staggered slots; IT can flag incomplete orders for manual path. Fails if: winter road delays re-bunch arrivals anyway; automation misclassifies incomplete as complete.
Downstream risk: explicitly exposes pre-analytical and assay bottlenecks (faster inflow). Therefore cap with WIP limit: if pre-analytical queue >6h, throttle automated inflow to manual review buffer rather than pushing to benches.

**R3 - Controlled batching: keep 12 for mixed flow, allow 24 only for pure Routine lane with Urgent/Complex bypass guardrail (modified I2, reject strict I1 as baseline).**
Why robust: preserves prep efficiency for Routine (tolerates batching) while preventing Urgent starvation observed when bypass fell to 58%. Use visible Urgent lane at preparation and assay with max Routine batch wait (e.g., Routine batch closes after 4h or 12 units, whichever first). Assumption: preparation benches can physically separate lanes; dispatch discipline can be audited. Fails if: exception control lapses under stress -> de facto large batches for all.
Downstream risk: large Routine batches arrive as bursts to assay; mitigate with assay pacing (R4) and by forbidding I9 (holding Routine releases) as baseline — I9 adds waiting for minimal release saving and directly threatens 72h target.

**R4 - Flexible assay routing, not strict dedication (modified I3): default pooled M1/M2 with repeat-aware routing.**
Why robust: pooling absorbs S2 degradation better than hard dedication; strict M1=Urgent/Complex, M2=Routine increases repeats when M2 overloaded (M2 higher failure rate). Rule: route away from M2 for Repeat-after-failure and night-shift repeats; prefer M1 for repeats and Complex; keep Routine on both with load balancing. Avoid M2 for second repeats. Assumption: repeat risk by machine/shift is tracked daily. Fails if: one machine fully down -> must switch to scenario policy P2.
Downstream risk: fragmented schedules if Urgent bypass uncontrolled; mitigate with R3 guardrail and by limiting bypass to true Urgent (penalty-bearing), not all Complex.

**R5 - Cross-trained on-call pool, not permanent transfer (modified I4) + standard work for accession.**
Why robust: 2 accession specialists are single point of failure (91%, 14h queue, unblock many cases). Train 2 technical validators for accession but keep them in technical by default; deploy 2-4h accession help only when accession queue >8h AND technical queue <10h. Document correction checklists to cut `Manual -> Test prep` 16h. Assumption: 4-week cross-training feasible in normal period; skills maintained. Fails if: deployed during S1/S3 when technical >100% -> technical collapse. Hence interlock with trigger (see Section 4).
Downstream risk: depletes technical validation; interlock prevents it.

What is deliberately NOT in robust baseline: strict Urgent-first (I1), full dedication (I3), permanent evening shift (I5), routine release holding (I9), outsourcing (I10) — these are scenario-specific because they help one case type while harming others or adding fixed cost/complexity.

# 4. Scenario-specific policies
Each with ON/OFF triggers to avoid permanent over-optimization.

**P1 - Strict Urgent-first dispatch at prep + assay (I1). Only for S1 urgent SLA crisis.**
ON when: Urgent p90 >18h for 2 consecutive days OR Urgent WIP >1.5x normal AND medical queue <15h (downstream can absorb). OFF when: Urgent p90 <15h for 2 days OR Routine p90 >90h OR Routine queue >12h share >35% (starvation signal). Must include WIP cap: max 30% Routine waiting >24h triggers temporary Routine flush shift. Why conditional: helps Urgent but starves Routine/Complex and inflates total WIP.

**P2 - Temporary machine dedication M1=Urgent/Complex, M2=Routine (I3). Only when both machines healthy and assay queue is mix-driven, not failure-driven.**
ON when: assay median queue >12h, repeat rate <10%, both machines up, Complex+Urgent >45% of WIP. OFF when: repeat rate >12% OR M2 queue >1.5x M1 queue OR any machine down -> revert to R4 pooled repeat-aware routing. Why conditional: relieves M1 congestion for critical cases but amplifies repeats under S2.

**P3 - Evening medical-validation shift (I5). Only for S1/S3 medical backlog.**
ON when: medical median queue >12h OR `Technical -> Medical` median >15h OR specialist Hold >30 cases waiting. OFF when: medical queue <6h for 3 days. Pair with morning technical pacing so evening shift does not idle then surge Release. Why conditional: fixed labor cost + fatigue/error risk; relieves specialist review queue but can push traceability/release errors if overused. Do not use to compensate for chronic understaffing — use R5 + outsourcing instead if ON >3 weeks.

**P4 - Outsource Complex-panel overflow to partner (I10). Only for S3 specialist blockage.**
ON when: Hold->Medical median >36h AND specialist unavailable (Friday gap / absence) AND Complex p90 >150h. Select only stable Complex-panel overflow (no repeat history), accept 12h transport delay as better than 48h hold. OFF when: Hold queue <20 OR transport delay >18h (winter roads) -> keep in-house with P3. Requires pre-agreed traceability protocol. Why conditional: relieves specialist but adds transport + quality variance; never use for Urgent (penalty + transport = breach).

**P5 - Expanded Routine batch 24 + deferred Routine release batching (I2-full + I9-limited). Only for S4 intake glut with healthy downstream.**
ON when: courier/pre-analytical queue >8h, assay/technical/medical queues healthy (<8h), Routine-heavy WIP. OFF immediately if Urgent share >25% OR assay queue >10h OR Routine p90 approaches 65h (near 72h target). Why conditional: improves prep setup efficiency but pushes Urgent into longer waits and I9 directly adds Routine waiting.

Cross-training deployment interlock (R5 activation): deploy accession help ONLY if accession median queue >8h for 1 day AND technical median queue <10h AND technical utilization <95%. Recall immediately if technical queue rises >12h.

# 6. Residual vulnerabilities
- **Medical + specialist remains fragile even after redesign.** Peak medical 93% and specialist 87% with only 2 accession specialists and 1 frequent-absent specialist means S1+S3 compound (surge + Friday absence) still breaches Urgent 18h and Complex p90. Evening shift and outsourcing are temporary; chronic solution requires hiring or partner retainer, not just rostering.
- **Assay single point of failure.** M1/M2 at 98% leaves no slack for S2 outage. Pooled routing mitigates but cannot create capacity; one machine loss under S1 mix guarantees assay queue >24h and repeat spiral. No redesign without redundant capacity or load shedding (cancel/defer non-critical Routine) survives this.
- **Recollection tail irreducible.** `Request -> Receive` 60h median is dominated by patient recollection outside lab control. Even perfect triage shortens detection (2h) but not patient return time. Repeat-after-failure p90 240h will remain worst-in-class; must be managed by expectation and separate reporting, not averaged with Routine.
- **Courier winter re-bunching.** Smoothed slots collapse with road delays; S4 can reappear despite R2. Need dynamic slot reallocation, not static timetable.
- **Redesign-induced vulnerability: faster front-end exposes downstream and increases cancellations.** R1+R2 together accelerate inflow of clean cases to assay/technical/medical that are already 98-101% in peak, raising WIP and p90 if WIP caps are ignored. Simultaneously, stricter 2h triage mechanically raises `Request recollection` and `Cancel` counts in the short term (as seen 290->370), increasing clerk explanation load and physician friction, potentially reducing ward compliance and increasing incomplete orders — a feedback loop caused by the redesign itself if reject criteria and communication are not jointly managed.
- **Automation brittleness and skill atrophy.** Selective auto-registration depends on metadata quality; wards may game completeness flags. On-call accession pool decays without practice; deploying rusty validators under stress raises correction errors.

# 7. Minimum monitoring dashboard
Monitor daily in peak; act on leading indicators, judge on lagging outcomes. All queues as medians + p90 where noted.

**Leading indicators (act today to prevent tomorrow's breach):**
- Pre-analytical median queue: green <3h, yellow 3-6h, red >6h; recollection request %: green <5%, red >7% (normal 4.2%, peak 8.0%).
- Accession correction queue + count waiting: green <5h/<15 cases, red >8h/>30 cases (peak 14h). Trigger for R5 interlock.
- Preparation `Test prep -> Batch wait` share + Urgent bypass %: red if bypass <65% (normal 74%, peak 58%) or batch entries >15% of prep exits.
- Assay queue by machine + repeat % + repeats by machine/shift: green repeat <8%, red >11% (normal 6.6%, peak 13.7%); red if assay median >12h or M2-M1 queue ratio >1.5x.
- Technical validation queue: green <6h, red >10h (peak 16h, 101% utilization = red).
- Medical validation queue + Hold-for-specialist count: green <6h/<20, red >12h/>30 or `Technical->Medical` >15h (peak 24h).
- Courier arrival coefficient of variation + registration queue: red if 10:00/17:00 spikes >2x hourly mean or registration >2h.
- WIP by case type (Routine/Urgent/Complex/Repeat) and % cases with queue >12h: red if >30% (normal 22%, peak 54%).

**Lagging outcome metrics (judge redesign, do not steer intraday):**
- Urgent median/p90 and % >18h (contract penalty): target p90 <18h; red if p90 >20h (peak 33h).
- Routine median/p90 and % >72h: red if p90 >65h approaching target (peak 120h).
- Complex-panel median/p90: red if p90 >150h (peak 210h); Repeat-after-failure median/p90 separately reported, not averaged.
- Overall rework %: green <8%, red >10% (normal 7.5%, peak 11.8%).
- Cancel rate and `Request recollection -> Cancel` share to detect over-triage.

Rule: never average across case types; report Routine, Urgent, Complex, Repeat separately and prioritize p90/SLA breach over median improvement.
