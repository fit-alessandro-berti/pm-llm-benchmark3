# 1. Assumptions and notation

**Notation.** For case *i* and station *k* ∈ {S1, S2}: queue entry \(q^k_i\) (\(q^1_i\) = external arrival `arrival_s1`, \(q^2_i\) = S1 completion `s1_end`), service start \(s^k_i\), service end \(e^k_i\). Window \([T_0, T_1)\) = [08:00, 14:00), 360 min. All durations are in minutes. "Observed" = read directly from the table; "imputed" = reconstructed within stated bounds; "≥x" = right-censored lower bound at 14:00; "elapsed" = service time accumulated by 14:00 for an OPEN activity, which is not the final service time.

| ID | Assumption | Why it is needed |
|---|---|---|
| A1 | **Rounding.** Each reported time *t* is the true time rounded to the nearest 5 min, so the true time lies in [t−2.5, t+2.5]. Errors are treated as independent and uniform. A duration (the difference of two stamps) therefore has error in [−5, +5] min, SD ≈ 2.0 min. Central values use reported stamps. | Every duration is a difference of two rounded stamps; this bounds the error of individual durations and aggregates. |
| A2 | **Arrival clock.** The external-arrival system has no systematic offset relative to the S1/S2 system. Sensitivity: ±5 min. Observed S1 waits of 5 min for P01/P02 imply the arrival clock cannot run more than about 7.5–10 min late, but an early-running clock cannot be detected. | The arrival stamps come from a different system; S1 waits and total sojourn depend on it. |
| A3 | **Event order / simultaneity.** States are right-continuous: a case is in a state over the half-open interval [enter, leave). All events that share a rounded stamp are applied before the state is read. When narrating, the order is: completions, then queue joins (an S1 completion *is* the S2 queue join, at the same instant), then service starts, then external arrivals. A resource that ends one job and starts another at the same stamp (C1 at 11:00: P07 ends, P09 starts) is treated as sequential, not concurrent. | Needed for peak and snapshot counts. Time averages do not depend on it. |
| A4 | **Closed population.** The 22 rows are every case present in the window. The system is empty at 08:00, and there are no unrecorded arrivals after 12:10. | Needed for WIP, arrival rates, and the finite-horizon identity. |
| A5 | **Capacity.** I1, I2 and C1 are available the whole window (no breaks are recorded). C2 is available the whole window except 10:55–11:10, and the outage bounds are treated as exact, so C2 has 345 available minutes. Resources are single-task. The data contain no overlapping intervals on any resource (checked), so no undocumented assistance is assumed. | Denominator for utilization; the capacity model. |
| A6 | **Transfer.** The buffer between S1 and S2 is unlimited, S1 is never blocked, and transport time is zero. Any transport or handling delay is counted as S2 waiting. | The prompt states that S2 queue entry = S1 completion. |
| A7 | **Hand-over gap.** Of the 28 consecutive-job transitions where work was waiting and both stamps are known, 26 show exactly 5 min between one job's end and the next start on the same resource (one is 0 min on C1 at 11:00, one is 10 min on C2 at 13:20–13:30). Rounding cannot produce such a systematic gap. The true gap is in [0, 10] min with a mode of about 5. I treat it as a real non-logged hand-over (setup, paperwork, transport, or logging lag). It counts as *idle-with-work-waiting* in "logged busy" utilization and as occupied in a sensitivity variant. | It drives the gap between ~80–88 % "logged" utilization and ~100 % "occupied" utilization, and it is the basis of the central imputation rule. |
| A8 | **MISSING starts.** Feasible window = [max(queue entry, previous completion on the same resource), own completion]. Scenarios: **early** = lower bound (maximum service, minimum wait). **central** = previous completion on the resource + 5-min hand-over (A7), capped so service is not below the station's minimum fully observed service (S1: 20, S2: 25). **late** = service equal to that minimum. **logical extreme** = zero service, reported only as a bound. No single value is substituted silently; all four are carried through. | The prompt forbids silent single-value replacement. The rules use resource availability, queue entry, completion, and non-negative service. |
| A9 | **OPEN activities.** Elapsed time up to 14:00 counts as busy time and as a lower bound on final service. It is excluded from means of completed service. | Separates elapsed from final service and avoids inferring utilization from completed cases only. |
| A10 | **Blank = waiting.** Queue time is right-censored at 14:00. Kaplan–Meier (KM) summaries assume non-informative censoring. This is optimistic here because later entrants face longer waits, so KM figures are treated as a floor-like reference. | Censored waits cannot be dropped or treated as complete. |
| A11 | **Queue discipline is not assumed.** No reconstruction step relies on FIFO. FIFO is used only as a diagnostic and for explicitly labelled projections beyond 14:00. | Two overtakings are observed (P09 over P08 at 11:00; P17 over P16 at 13:55). |
| A12 | **Little's Law** is interpreted as a steady-state approximation only on an interval that starts empty, is pre-outage, and has constant staffing. Elsewhere only the exact finite-horizon identity is used. | The process is clearly non-stationary. |
| A13 | **C2 before the outage.** C2 does not start a ~40-min job it cannot finish before maintenance. | Explains C2 idling 10:50–10:55 while P08 waited, without assuming a data error. |

# 2. Reconstruction method and formulas

**Case/station durations**

- Waiting: \(W^k_i = s^k_i - q^k_i\). Service (active): \(S^k_i = e^k_i - s^k_i\). Station sojourn: \(R^k_i = e^k_i - q^k_i = W^k_i + S^k_i\). Case total sojourn (completed cases): \(T_i = e^2_i - q^1_i\).
- Station sojourn and total sojourn **do not depend on missing starts**. A MISSING start only moves time between waiting and service.
- Censoring: if the case is still waiting at 14:00, \(W^k_i \ge T_1 - q^k_i\). If the activity is OPEN, elapsed \(= T_1 - s^k_i\) and the final \(S^k_i \ge\) elapsed. Summaries of censored waits use KM, \(\hat S(t)=\prod_{t_j\le t}(1-d_j/n_j)\), or explicit lower bounds.

**MISSING-start bounds** (A8): \(s \in [\max(q, e^{\text{prev}}_{r}),\, e]\). Early = lower bound. Central = \(\min(\max(q, e^{\text{prev}}_r + 5),\; e - S^k_{\min})\). Late = \(e - S^k_{\min}\), clipped to the window.

**Occupancy (WIP)**, using A3's half-open intervals. Unknown leave times (blank/OPEN) are set to +∞ inside the window:

- \(Q_k(t)=\#\{i: q^k_i \le t < s^k_i\}\), \(B_k(t)=\#\{i: s^k_i \le t < e^k_i\}\), station WIP \(N_k=Q_k+B_k\), total WIP \(N(t)=N_1+N_2=\#\{i: q^1_i\le t< e^2_i\}\).
- Time average over \([a,b)\): \(\bar Q_k = \frac{1}{b-a}\int_a^b Q_k(t)\,dt\). This is evaluated on a 1-min grid, which is exact because all events lie on a 5-min grid. Peak = maximum of the right-continuous step function.

**Rates.** Arrival rate \(\lambda_k[a,b)=\#\{q^k_i\in[a,b)\}/(b-a)\). Departure rate (throughput) \(X_k[a,b)=\#\{e^k_i\in[a,b)\}/(b-a)\). Note \(X_1 = \lambda_2\).

**Busy time and utilization.** \(\text{Busy}_r=\sum_i |[s_i,\min(e_i,T_1)]\cap[T_0,T_1]|\), where OPEN activities contribute their elapsed time. \(U_r = \text{Busy}_r/\text{Avail}_r\), with Avail excluding the C2 outage. Station \(U_k=\sum_r \text{Busy}_r/\sum_r\text{Avail}_r\). Three variants are reported:

1. Whole window.
2. From the first moment work could exist at the station (S2: 08:25). This removes structural start-up starvation.
3. Hand-over-inclusive (A7), which counts the 5-min gaps as occupied.

**Effective capacity and load.** \(\mu_k = c_k\cdot 60/(\bar S_k + h)\) jobs/h, with \(c_k = 2\) and hand-over \(h=5\) min (also reported with \(h=0\)). Load ratio \(\rho_k=\lambda_k/\mu_k\).

**Little's Law.** The exact finite-horizon identity on any \([a,b)\) is

\[
\bar N_{[a,b)}=\frac{1}{b-a}\sum_i\big|[q_i,d_i)\cap[a,b)\big| \;=\; \lambda\,\bar W \;-\;\text{spill} \;+\; \text{carry-in},
\]

where \(\bar W\) is the mean full sojourn of cases entering in \([a,b)\), spill \(=\sum_{\text{entering}}(d_i-b)^+/(b-a)\), and carry-in is the in-interval time of cases present at *a*. Steady-state \(L=\lambda W\) is only accepted where carry-in = 0 and spill is small relative to \(\lambda W\).

**Lower / central / upper.** Estimates combine three independent layers:

1. Imputation scenarios (early / central / late, plus the logical extreme as a bound).
2. Rounding: ±5 min worst case per duration. For aggregates, ±2·2.04·√n min for a sum of n durations. For means, SD ≈ 2.04/√n.
3. Censoring: elapsed-time lower bounds, KM, and labelled projections.

Tables report 5-min precision for single durations and at most one decimal for averages.

# 5. Bottleneck and temporal interpretation

**Evidence (observations and derived estimates):**

| period | λ into S1 | S1 output = λ into S2 | S2 output | mean Q1 | mean Q2 | ρ_S1 = λ_S1/μ_S1 | ρ_S2 = λ_S2/μ_S2 |
|---|---|---|---|---|---|---|---|
| 08–10 | 6.5/h | 3.0/h | 1.5/h (start-up) | 3.2 | 0.6 | ≈1.8 | ≈1.07 |
| 10–12 (includes outage) | 4.0/h | 3.5/h | 2.5/h | 5.9 | 2.2 | ≈1.1 | ≈1.25–1.33 (μ_S2 ≈2.6 with outage) |
| 12–14 | 0.5/h | 3.5/h (backlog drain) | 3.0/h | 3.3 | 3.6 | ≈0.14 (backlog still being worked off) | ≈1.25 |

- **Effective capacity (derived, stable across all scenarios).** S1: μ ≈ 3.6/h (3.56–3.72; logical extreme 3.97) with 5-min hand-overs, 4.3/h without. S2: μ ≈ 2.8/h (2.78–2.80; 2.67 using observed-only services; logical extreme 3.05), 3.2/h without hand-overs. The realized S2 output of 2.8/h over 09:00–14:00 matches its estimated capacity, because S2 was never starved after 08:35.
- **Neither station was starved after start-up.** Every time a calibrator became free after 08:35, at least one case was already waiting. Every time an inspector became free, the S1 queue was non-empty, including I2's unexplained 13:45–14:00 idle period. Both stations were therefore saturated (≈80–88 % logged, ≈100 % counting hand-overs). **Utilization cannot discriminate the bottleneck; the rate and queue-growth comparison does.**
- **Queue growth matches the rate imbalance.** S1 over 08–10: (6.5 − 3.0)/h × 2 h ≈ 7, versus WIP1 rising from 0 to 7 at 10:00. S2 over 10–14: (3.5 − ~2.75)/h × 4 h ≈ 3, versus WIP2 rising from 4 to 6 (plus the outage).
- **Crossover.** Q1 > Q2 until 12:55. From 12:55 to 14:00, Q2 > Q1 continuously (WIP2 > WIP1 from 12:50). The crossover time is identical in the early, central and late scenarios.
- **Waits by cohort.** S1 waits plateau at ~95–105 for everyone arriving after 10:00, because arrivals slowed and then stopped. S2 waits climb from ~14 (08–10 entrants) to ~43 (10–12) to ≥65 (12–14), and the four waiting cases are still accumulating.

**Interpretation:**

1. **Structural (throughput) bottleneck: S2 throughout.** Its effective capacity (≈2.8/h) is about 20–25 % below S1's (≈3.6/h). This holds under every imputation, rounding, and hand-over interpretation; even the logical extreme keeps S2 below S1. Adding S1 capacity would not have raised system output after 08:35, because S2 was already never idle when work existed.
2. **Where delay accumulated: S1 until ≈12:55, then S2.** The 08:00–10:00 arrival burst (6.5/h) exceeded both stations' capacities. Because S1 is first, the excess queued in front of S1, and S1 then metered flow into S2 at ≈3.0–3.5/h. That is only slightly above S2's capacity, so S2's queue stayed short in the morning (mean 0.6). After arrivals stopped at 12:10, S1 drained its backlog into S2 faster than S2 could process it, and the visible bottleneck moved downstream. This is a *shifting bottleneck in the delay sense* with a *fixed capacity bottleneck*. The practical reading: "S1 is the bottleneck" is true for waiting time in 08:00–12:30, but it would mislead a capacity decision.
3. **Active-period view.** Uninterrupted busy periods are ≈20–30 min on S1 and ≈25–50 min on S2, with the 5-min hand-over separating jobs at both. If hand-overs count as idle, S2's longer active periods point to S2. If they count as active, both stations are continuously active and the method cannot discriminate. This supports, but does not independently prove, point 1.

**C2 maintenance (10:55–11:10):**

- *Observation:* C2 finished P06 at 10:50, did not start P08 (waiting since 10:20), and restarted at 11:15. C2 therefore lost about 25 min of potential work (10:50–11:15) against 15 min of formal outage.
- *Estimate:* without the outage, P08 would plausibly have started at ≈10:55 (hand-over rule), so its wait would be ≈35 instead of 55. Because S2 was saturated with no slack, the ≈20-min shift in C2's schedule was never recovered by 14:00. That is ≈0.45 lost calibrations (≈20/44 min), or roughly +0.45 in mean S2 queue after 11:10, and by Little's relation about +8 min of wait per later S2 case (0.45 / 3.5 h⁻¹), shared across both calibrators under pooled dispatching.
- *Hypothesis-level conclusion:* the outage is a **contributing shock, not the cause** of rising S2 waits. S2 waits keep rising after its effect should have dissipated (P12 45, P13 50, P14 65, P15 75, P16 ≥85), which is consistent with λ_S2 > μ_S2.

**Dispatching and anomalies (hypotheses, not decidable from these data):**

- Before 11:00, S1→S2 pairing was strict: I1-inspected cases went to C1 and I2-inspected cases to C2. Both overtakings favour I1→C1 (P09 over P08; P17 over P16).
- From 11:45 to 13:30, pairing alternated the other way (P10, P12, P14 from I2 went to C1; P11, P13, P15 from I1 went to C2). So strict line affinity is not a consistent rule.
- Competing explanations for P16 being overtaken: a hold on P16, priority, or affinity.
- Queue discipline changes individual waits but not the averages or queue lengths above, given work-conserving servers.
- S2 services after the outage (P12–P14: 45, 50, 45) are longer than earlier ones. Possible explanations are post-maintenance recalibration or case mix. With n=3 this is only a hypothesis; if it is real, S2's recent capacity is ≈2.3/h, which strengthens point 1.
- **Projection (labelled hypothesis):** with FIFO resuming, ~40-min services and 5-min hand-overs, P16, P18, P19 and P20 would start around 14:15–15:25, giving S2 waits of ≈90–105. That matches the S1 waits of ~100 and confirms the move downstream.

**Other sensitivity layers:**

- **Rounding (A1).** Single durations carry ±5 min worst case. A 5-min wait could be 0–10, so P01/P02 show no demonstrable queueing, and the P07→P09 0-min hand-over on C1 is not a conflict. Means move by about ±0.5 min (1 SD). Resource busy times move by ±10–13 min (2 SD), about ±3 percentage points of utilization. Capacities move by about ±0.05/h, which is negligible against the 0.8/h S1–S2 capacity gap. Peaks can change by ±1 only at coinciding stamps (for example 10:55, 11:00, 11:30). Time averages are essentially unchanged.
- **Arrival-clock offset ±5 (A2).** Shifts every S1 wait and total sojourn by ∓5. It does not affect services, S2 waits, utilization, capacities, or the bottleneck ranking.
- **Hand-over interpretation (A7).** Logged utilization is 80–88 %; occupied utilization is ≈100 %. Capacity with h=0 is 4.3 vs 3.2/h, so the ranking is unchanged.
- **Right censoring.** This is the largest effect.
  - For S2 waiting: the naive mean of started cases is 36.9, the KM median is 50, and projections for late entrants are ≈90–105. Dropping censored cases would understate S2 delay by a factor of about 2 for the current regime.
  - For total sojourn: 146 (completed only) versus ≥156 (all cases, censored at elapsed).
  - S1 is barely affected (only P22 is censored), and its KM median of 75 is stable.
  - OPEN activities contribute 35 min on S2 (P15 30, P17 5) and 30 min on S1 (P21). Omitting them would understate busy time by 5–6 % at each station.
- **P22 / I2 anomaly.** If P22 actually started at 13:50 but was not logged: P22 wait = 100, I2 busy +10 min (S1 utilization +1.4 points), Q1 = 0 from 13:50 to 14:00. No conclusion changes.
- **Dispatching.** A pooled-FIFO counterfactual at 11:00 (C1 takes P08) would give P08 ≈40 and P09 ≈40 instead of 55 and 25. Means and queue lengths stay essentially the same.

**Stable conclusions** (they survive all scenarios, rounding, and censoring treatments):

1. S2 has the lower effective capacity (≈2.8 vs ≈3.6/h) and is the structural bottleneck.
2. Both stations were saturated after start-up; neither was starved (except I2's final 15 min, which is an anomaly, not starvation).
3. The dominant queue was S1 until 12:55 and S2 afterwards.
4. S1 waits plateau at ≈95–105 for arrivals after 10:00.
5. Total WIP peaked at 13 between 11:30 and 12:00.
6. The C2 outage added delay (≈20 min to P08, a few minutes per later case) but is not the cause of S2 congestion.

**Not stable:**

- Exact utilization: I1 ranges 79–88 %, and logged versus occupied differ by up to ~20 points.
- The wait/service split for P07 and P15 (±10 min) and, to a lesser degree, P05.
- The eventual S2 waits of P16–P20 and the final service times of P15, P17 and P21 (censored).
- Whether S2 service times increased after maintenance (n=3).
- The dispatching rule behind the two overtakings.
- Any steady-state Little's-Law statement outside the S2 queue interval 08:25–10:50.

# ---------------------------------------------------------------- Kaplan-Meier for censored waits
def km_median(durations, observed):
    df_ = pd.DataFrame({"t": durations, "e": observed}).sort_values(["t", "e"], ascending=[True, False])
    s, n = 1.0, len(df_)
    for t, g in df_.groupby("t", sort=True):
        d = g.e.sum()
        if d:
            s *= 1 - d / n
            if s <= 0.5:
                return t
        n -= len(g)
    return np.nan

# ---------------------------------------------------------------- Little's law on defensible intervals
def little(d, station, part, a, b):
    q, s_, e, _ = ST[station]
    A = d[q]
    D = d[s_] if part == "queue" else d[e]
    a, b = TS(a), TS(b)
    T = MIN(b - a)
    Dc = D.fillna(pd.Timestamp.max)
    L = MIN(Dc.clip(upper=b) - A.clip(lower=a)).clip(lower=0).fillna(0).sum() / T
    inside = (A >= a) & (A < b)
    W = MIN(D[inside] - A[inside])
    spill = MIN(D[inside] - b).clip(lower=0).sum() / T           # part of those W falling after b
    return dict(station=station, part=part, interval=f"{a:%H:%M}-{b:%H:%M}", L_time_avg=round(L, 2),
                lam_per_h=round(inside.sum() / T * 60, 2), W_mean=round(W.mean(), 1), censored=int(W.isna().sum()),
                lamW=round(inside.sum() / T * W.mean(), 2), spill_after_end=round(spill, 2),
                N_at_start=int(((A < a) & (Dc > a)).sum()), N_at_end=int(((A < b) & (Dc > b)).sum()))
