import pm4py
from pm4py.objects.petri_net.obj import Marking

def fire_named(net, marking, trans_name):
    trans = next(t for t in net.transitions if t.name == trans_name)
    enabled = pm4py.get_enabled_transitions(net, marking)
    if trans not in enabled:
        raise RuntimeError(f"Transition {trans_name} not enabled in marking {marking}")
    new_marking = Marking()
    for p, tok in marking.items():
        new_marking[p] = tok
    for arc in trans.in_arcs:
        new_marking[arc.source] -= 1
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]
    for arc in trans.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + 1
    return new_marking

# 1. Executive Verdict

The net is structurally a workflow net: it has one source (`source`) and one sink (`sink`), and every node lies on a directed source-to-sink path. It should **not** be expected to be sound. The principal defect is that `t_join_waived` has only one input arc (`p_waived`) and lacks an input from `p_analysis_done`. On the waiver route, the mandatory analysis branch is therefore never synchronized and its token is stranded. Business consequence: a case can be authorized before or without completed analysis, and after `t_authorize` a token remains in `p_analysis_done`, so the exact final marking `{sink:1}` is never reached. The model can pass a workflow-net check but fails soundness.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_split` | AND-split after registration to start analysis and review in parallel | One input (`p_ready`), two output arcs to `p_analysis` and `p_review`; consumes one token, produces one in each branch | Correct parallel start; no defect |
| `t_standard_review` / `t_waive_review` | XOR choice of review outcome from `p_review` | Two transitions from `p_review`, each with one output (`p_review_done`, `p_waived`); only one can fire because `p_review` holds a single token | Correct exclusive choice; outcomes distinguishable |
| `t_join_normal` | AND-join synchronizing analysis completion with standard review completion | Two input arcs (`p_analysis_done`, `p_review_done`) and one output to `p_decision` | Works for standard path; unreachable on waiver path |
| `t_join_waived` | Should synchronize analysis completion with waiver before authorization | Only one input arc (`p_waived`) and one output to `p_decision`; missing arc from `p_analysis_done` | On waiver path, analysis token never consumed; authorize can fire without/before analysis |
| Initial / final markings | Start one case, finish with exactly one token in `sink` | `im = {source:1}`, `fm = {sink:1}`; structurally legal | `fm` unreachable on waiver route because of leftover token |
| Source-to-sink path condition | WF-net requires every node on a directed path | Every place/transition has such a path (e.g., `p_analysis_done` via `t_join_normal`), so `check_is_workflow_net` passes | Structural check passes while behavioral soundness fails; hidden dead token |

# 4. Minimal-Repair Alternatives

**Edit-cost model:** adding or removing a place, transition, or arc each costs 1 unit. Relabeling is irrelevant and costs 0.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **A. Proper two-input waiver join** | Add arc `p_analysis_done  t_join_waived` | 1 | Mandatory analysis on both paths; waiver and standard remain place-level distinct; authorize only after both complete | `t_join_waived` becomes a proper AND-join with two inputs | Two silent joins exist; minor structural redundancy, but no new behavior |
| **B. Rewire waiver into normal synchronization** | Remove arc `waive_review  p_waived`; add arc `waive_review  p_review_done`; remove place `p_waived`; remove transition `t_join_waived`; remove arcs `p_waived  t_join_waived` and `t_join_waived  p_decision` | 6 | Mandatory analysis retained; waiver still explicitly recorded by the `t_waive_review` label; authorize only after both complete | Single synchronization (`t_join_normal`); waiver no longer has a dedicated place/join | Waiver and standard are indistinguishable at marking level (only log label differs); orphan nodes removed to keep WF-net validity |

At least one repair (A and B) retains mandatory analysis. Repair B is semantically/structurally distinct: it eliminates the separate waiver join rather than merely adding an arc.

**Minimality justification:**  
Under the cost model, Repair A is the smallest possible change: the defect is precisely a missing consumption of `p_analysis_done` on the waiver path, so at least one arc must be added; no removals are required. Repair B is minimal within its family: to merge the waiver outcome into the normal synchronization, the waiver token must be redirected to `p_review_done`, and the now-orphaned `p_waived` and `t_join_waived` must be deleted to preserve the source-to-sink path condition of a workflow net. Any fewer edits would either leave dead nodes (breaking WF-net structure) or fail to synchronize analysis. The repairs do not tie in cost: A is strictly cheaper, but B is a legitimately distinct structural alternative.

import pm4py
from pm4py.objects.petri_net.obj import Marking

def fire_named(net, marking, trans_name):
    """Fire a transition by its internal name, after checking enabledness."""
    trans = None
    for t in net.transitions:
        if t.name == trans_name:
            trans = t
            break
    if trans is None:
        raise ValueError(f"Transition {trans_name} not found")
    enabled = pm4py.get_enabled_transitions(net, marking)
    if trans not in enabled:
        raise RuntimeError(f"{trans_name} not enabled in {marking}")
    new_marking = Marking()
    for p, tok in marking.items():
        new_marking[p] = tok
    for arc in trans.in_arcs:
        new_marking[arc.source] -= 1
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]
    for arc in trans.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + 1
    return new_marking

# 7. Repair Trade-Offs and Residual Risks

- **Waiver vs standard distinguishability:** With Repair A, the two review outcomes remain distinguishable both by transition label and by separate places (`p_review_done` vs `p_waived`) and joins. With Repair B, they remain distinguishable only by the `t_standard_review` / `t_waive_review` labels; the dedicated waiver place and join are removed.
- **Silent-transition confusion:** Repair A leaves two invisible transitions (`t_join_normal`, `t_join_waived`) that both produce `p_decision`. They are mutually exclusive in any case, so no duplicate tokens are created, but a process-mining algorithm may see two silent joins and require careful replay to separate them.
- **Does soundness prove business alignment?** No. Soundness only guarantees proper completion and liveness. A sound net could still violate the business rule if, for example, analysis were made optional but cleanly discarded. Soundness is necessary, not sufficient; the synchronization logic must still be inspected.
- **Regression traces:**  
  *Positive:* `Register Case, (split), Perform Analysis, Perform Standard Review, (join_normal), Authorize Case`; and `Register Case, (split), Record Review Waiver, Perform Analysis, (join_waived), Authorize Case`.  
  *Negative:* any trace where `Authorize Case` occurs without a preceding `Perform Analysis`; and any trace where both review outcomes fire.
- **Detecting accidental bypass of mandatory analysis:** Add a conformance or LTL check that `Perform Analysis` must precede `Authorize Case` on every trace, or inspect the reachability graph for any marking where `t_authorize` (or `p_decision`) is enabled while `p_analysis_done` is empty. After Repair A, such markings do not exist.

# 8. Final Recommendation

Deploy **Repair A** (add the single arc `p_analysis_done  t_join_waived`). It is the minimal edit (cost 1), preserves the existing structure, keeps the waiver outcome explicitly distinguishable at the place level, and directly enforces the business rule that authorization requires completed analysis and the selected review outcome. The repaired net passes both workflow-net and soundness checks, and the counterexample sequence is blocked at the synchronization step.

Use **Repair B** as a fallback if stakeholders prefer a single, consolidated synchronization point and do not need a dedicated `p_waived` place. Repair B is behaviorally correct and slightly simpler in terms of join logic, but it costs six edits and loses place-level distinction between waiver and standard review. It should be chosen only if the event-log label is sufficient for auditability and future model extensions will route all review outcomes through one join.
