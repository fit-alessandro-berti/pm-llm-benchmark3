# 1. Executive Verdict

- **Workflow net?** Yes. Single source `source`, single sink `sink`, every node lies on a path from `source` to `sink`.
- **Expected sound?** Yes. The intent is a clean, terminating parallel branch with a choice between standard review and waiver, so the net should be sound.
- **Principal defect.** The waiver synchronization is wired to a single-input transition `t_join_waived` that consumes only `p_waived`. As a result, the mandatory analysis (`p_analysis_done`) is not required to be complete before authorization can occur when the waiver path is taken.
- **Business consequence.** A case whose review was waived can be authorized without a token ever having entered `p_analysis_done`, i.e., without analysis having been performed. This violates "Authorization may occur only after the analysis and whichever review outcome was selected are both complete."

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source  t_register  p_ready  t_split` | Sequential registration, then parallel split | Works as a one-token AND-split producing tokens in `p_analysis` and `p_review` | None |
| `p_analysis  t_analyze  p_analysis_done` | Mandatory analysis branch | Correct | None |
| `p_review  t_standard_review  p_review_done` | Standard review branch | Correct | None |
| `p_review  t_waive_review  p_waived` | Waiver branch (mutually exclusive with standard review) | Correct as an XOR choice from `p_review` | None |
| `p_analysis_done + p_review_done  t_join_normal  p_decision` | AND-join for the standard path | Correct AND-join | None |
| `p_waived  t_join_waived  p_decision` | AND-join for the waiver path | **Incorrect**: only one input arc; this is effectively an XOR-join, not an AND-join | Authorization possible without analysis being complete |
| `p_decision  t_authorize  sink` | Final authorization | Triggers as soon as `p_decision` is marked | Inherits the upstream defect |
| `im`, `fm` | Single token in `source`; expect exactly one token in `sink` | Correct as markings | None |
| Sink token accumulation? | `t_authorize` consumes `p_decision` and produces `sink` | No token is ever put into `sink` other than via `t_authorize`, and `t_authorize` is the only consumer of `p_decision` | No accumulation; the "no leftover token" issue is not the symptom here |

# 3. Marking-Based Counterexample

### Counterexample A — waiver bypasses mandatory analysis

Starting marking: `{source=1}`. All other places hold 0 tokens.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `source=1` | `t_register` | Initial state |
| 1 | `t_register` | `p_ready=1` | `t_split` | Case registered |
| 2 | `t_split` | `p_analysis=1, p_review=1` | `t_analyze`, `t_standard_review`, `t_waive_review` | Parallel branches spawned |
| 3 | `t_waive_review` | `p_analysis=1, p_waived=1` | `t_analyze`, `t_join_waived` | Analysis still pending, but join is enabled |
| 4 | `t_join_waived` | `p_analysis=1, p_decision=1` | `t_analyze`, `t_authorize` | `t_authorize` is **enabled before analysis completes** |
| 5 | `t_authorize` | `p_analysis=1, sink=1` | `t_analyze` | `sink=1` is reached even though `p_analysis` still holds a token; the token in `p_analysis` is leaked and the final marking is `{sink=1, p_analysis=1}`, not `fm` |

The two things to distinguish:

1. *A token is in `sink`* — true.
2. *The exact final marking `fm = {sink=1}` has been reached* — false; `p_analysis` still holds a token.

The leftover token in `p_analysis` is never consumable: `t_analyze` is still enabled, but its consumption produces `p_analysis_done`, which feeds only `t_join_normal`. From `p_decision=1, sink=1, p_analysis_done=1`, no transition is enabled that reaches `fm`. Therefore the net is **not sound** for the waiver path.

### Counterexample B — standard path is fine

| Step | Fired transition | Resulting nonzero marking | Observation |
|---|---|---|---|
| 0 | — | `source=1` | |
| 1 | `t_register` | `p_ready=1` | |
| 2 | `t_split` | `p_analysis=1, p_review=1` | |
| 3 | `t_analyze` | `p_review=1, p_analysis_done=1` | |
| 4 | `t_standard_review` | `p_analysis_done=1, p_review_done=1` | |
| 5 | `t_join_normal` | `p_decision=1` | |
| 6 | `t_authorize` | `sink=1` | Reaches `fm`. |

This isolates the defect to the waiver branch.

### Counterexample C — authorization can fire even when analysis never ran

If `t_analyze` is never fired on the waiver path, the firing sequence `t_register, t_split, t_waive_review, t_join_waived, t_authorize` produces the marking `{p_analysis=1, sink=1}`. This is the cleanest expression of the business violation: authorization completed while the analysis place was never even visited.

# 4. Minimal-Repair Alternatives

**Edit-cost model.** Cost is the sum of arc insertions, arc removals, place/transition additions, and place/transition removals. Renaming is free. One "semantic" change (e.g., making analysis optional) counts as a behavior change but not as additional structural cost beyond the arcs that implement it.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1: Merge the two joins.** Remove `t_join_waived` and its arcs; instead route `p_waived` to `t_join_normal` so that the standard AND-join is reused for both paths. Concretely: remove `p_waived  t_join_waived` and `t_join_waived  p_decision`; add `p_waived  t_join_normal` and `p_review_done  t_join_normal` (already present). | Remove 2 arcs, add 1 arc, remove 1 transition | 4 | Mandatory analysis is required on every path; waiver remains distinguishable as an outcome. | The two joins become one AND-join with two "review-outcome" inputs (`p_review_done`, `p_waived`). The XOR choice from `p_review` is still preserved upstream. | None significant; behavior is the cleanest realization of the stated policy. |
| **R2: Add the missing analysis input to the waiver join.** Keep `t_join_waived` but make it a true AND-join by also requiring `p_analysis_done`. Add arc `p_analysis_done  t_join_waived`. No other changes. | Add 1 arc | 1 | Mandatory analysis on the waiver path; waiver branch remains structurally distinct. | The model now has two structurally separate join transitions, which is mildly redundant given R1. | Slight model bloat; both joins must be maintained. |
| **R3 (policy change, stated): make analysis optional under waiver.** Add a silent transition `t_skip_analysis` that consumes `p_analysis` and produces `p_analysis_done` directly (or, equivalently, short-circuit the analysis branch by allowing `t_join_waived` to fire with only `p_waived` and to put a synthetic token in `p_analysis_done`). This changes the business rule. | Add 1 transition + 2 arcs (or 1 arc + reuse) | 3 | "Waiver" path can complete without real analysis. | **Policy change**: analysis is no longer mandatory when the review is waived. | Real-world consequence: a waived case may never be analyzed. Must be explicitly accepted. |

**Minimality justification.** R2 is strictly minimal in the arc-addition metric (1 added arc, 0 removals, 0 structural additions). R1 costs 4 edits but achieves the same business semantics with a smaller, less redundant net — it is the cleanest *structural* minimality. R3 is included as a sanctioned alternative only if the policy itself is being relaxed. There is no unique optimum; R1 and R2 tie on "minimum structural change to satisfy the stated business policy" along different dimensions (R1 minimizes node count, R2 minimizes arc delta).

# 5. Corrected PM4Py Code

The selected repair is **R1** (merge the two joins). This preserves the original labels, keeps mandatory analysis on every path, and yields a structurally minimal net.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in {source, p_ready, p_analysis, p_review, p_analysis_done,
          p_review_done, p_waived, p_decision, sink}:
    repaired_net.places.add(p)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in {register, split, analyze, standard_review, waive_review,
          join_normal, authorize}:
    repaired_net.transitions.add(t)

petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

# Single AND-join: requires analysis AND (standard review OR waiver).
petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_waived, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

```python
from pm4py.objects.petri_net.obj import Marking
from pm4py.objects.petri_net.utils import petri_utils

# --- Original net diagnostics ---
print("=== ORIGINAL ===")
print("workflow net:", pm4py.check_is_workflow_net(net))
pm4py.check_soundness(net, im, fm, print_diagnostics=True)

# --- Repaired net diagnostics ---
print("=== REPAIRED ===")
print("workflow net:", pm4py.check_is_workflow_net(repaired_net))
pm4py.check_soundness(repaired_net, repaired_im, repaired_fm, print_diagnostics=True)

enabled_rep = pm4py.get_enabled_transitions(repaired_net, repaired_im)
print("enabled at im:", [t.name for t in enabled_rep])
pm4py.convert_to_reachability_graph(repaired_net, repaired_im, repaired_fm)

# --- Helper used to walk the counterexample with enabledness checks ---
def fire_one(net, marking, transition_name):
    enabled = {t.name: t for t in pm4py.get_enabled_transitions(net, marking)}
    if transition_name not in enabled:
        raise RuntimeError(
            f"Cannot fire {transition_name}; enabled are {sorted(enabled)}"
        )
    t = enabled[transition_name]
    new_marking = Marking()
    for place, count in marking.items():
        new_marking[place] = count
    for arc in t.in_arcs:
        src = arc.source
        new_marking[src] = new_marking.get(src, 0) - 1
        if new_marking[src] == 0:
            del new_marking[src]
    for arc in t.out_arcs:
        dst = arc.target
        new_marking[dst] = new_marking.get(dst, 0) + 1
    return new_marking

# Replay the original-net counterexample
m = Marking()
m.update(im)
for tr in ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize"]:
    m = fire_one(net, m, tr)
    print(f"after {tr}:", {p.name: c for p, c in m.items()})

# Replay the same idea on the repaired net to show it now refuses t_authorize early
m = Marking()
m.update(repaired_im)
for tr in ["t_register", "t_split", "t_waive_review"]:
    m = fire_one(repaired_net, m, tr)
    enabled_now = [t.name for t in pm4py.get_enabled_transitions(repaired_net, m)]
    print(f"after {tr}: marking={{ {', '.join(f'{p.name}={c}' for p,c in m.items())} }} enabled={enabled_now}")
```

**Expected qualitative difference in diagnostics.**

- The original net still passes `check_is_workflow_net` because the structure (one source, one sink, every node on a path) is fine; the defect is in the *token accounting*, not the topology.
- The original net fails soundness. WOFLAN-style diagnostics will report that a proper completion is not always possible and that the final marking is not uniquely reachable. The visible witness is exactly Counterexample A: the waiver path leaves a token stranded in `p_analysis` and produces `sink=1` prematurely.
- The repaired net passes soundness. The reachable final marking is `{sink=1}` for every legal firing sequence, and every transition lies on some path from source to sink.

# 7. Repair Trade-Offs and Residual Risks

- **Distinguishability of waiver vs. standard review.** In R1 the outcomes remain distinguishable: a completed case still carries a token through either `p_review_done` or `p_waived`, and event logs can still record `t_standard_review` vs. `t_waive_review`. The join is shared, but the *evidence* of which branch was taken is preserved upstream.
- **Silent transitions.** R1 and R2 keep the same silent transitions (`t_split`, `t_join_normal`) that the original net already used. There is no new silent transition, so no risk of accidental duplicate firings or hidden behavior. The only behavioral change is that the missing synchronization arc is now present.
- **Soundness is necessary, not sufficient.** A passing `check_soundness` call only certifies proper completion and option to complete. It does *not* prove that the business rule "waiver and standard review are mutually exclusive" is enforced; that is a structural property of the choice from `p_review`. In R1, that XOR choice is intact. R3, by contrast, would be sound but would not satisfy the original business intent.
- **Regression tests.**
  - *Positive traces.* `register, split, analyze, standard_review, join, authorize`; `register, split, analyze, waive_review, join, authorize`; `register, split, waive_review, analyze, join, authorize` (different interleavings). All must end in `{sink=1}` and no other place marked.
  - *Negative trace.* `register, split, waive_review, join, authorize` (without `analyze`) must NOT be fireable on the repaired net; on the original net it reaches a marking with a leaked token.
  - *Choice exclusivity.* `standard_review` and `waive_review` must never both be possible to fire from `p_review` (they should not, because the choice is made by consuming the single token in `p_review`).
- **Detecting accidental bypass of mandatory analysis.** Add a log-level invariant: every completed case must have an `Analyze` event before the `Authorize` event. A second structural invariant is that the repaired net contains no reachable marking from `im` that marks `sink` without `p_analysis_done` having been visited along the run. WOFLAN's "proper completion" diagnostic would surface any regression to the original defect.

# 8. Final Recommendation

**Deploy R1 (merge the two joins).** It restores the missing AND-synchronization between analysis and the review outcome with a structurally minimal change, keeps mandatory analysis on every path, and removes a redundant silent transition. The original XOR choice from `p_review` is preserved, so waiver vs. standard review remain distinguishable in event logs. Modelers reviewing the net will also find a single, unambiguous join easier to maintain than two near-duplicate join transitions.

**Fallback R2 (add `p_analysis_done  t_join_waived`).** If the team has already wired downstream tooling, dashboards, or process-mining queries to the existence of a separate `t_join_waived` transition, R2 is the lowest-risk patch: it changes exactly one arc, leaves the rest of the net (including the redundant join transition) untouched, and enforces the same business rule. It is strictly minimal under the arc-delta metric and is the safest "surgical" fix when organizational context discourages refactoring.
