# 1. Equivalence Notions

To rigorously analyze whether Model A and Model B are equivalent, we must explicitly define the observation boundaries, abstraction functions, and semantic equivalence notions. 

- **Visible trace equivalence after hiding $\tau$**: Let $\mathcal{T}(M)$ be the set of complete execution traces generated by process tree $M$. Each trace is a sequence of labels drawn from the set of visible activities $\Sigma = \{\text{'Open Case'}, \text{'Analyze Revision'}, \text{'Check Revision'}, \text{'Approve Revision'}, \text{'Rework Case'}, \text{'Close Case'}\}$ and silent steps $\tau$. Let $\pi_{\Sigma}(\sigma)$ be the projection of trace $\sigma$ onto $\Sigma$ by removing all $\tau$ instances. Two models are trace-equivalent under visible hiding if and only if $\pi_{\Sigma}(\mathcal{T}(M_A)) = \pi_{\Sigma}(\mathcal{T}(M_B))$.
- **Bounded visible-language equivalence under P3**: Let $\mathcal{L}_{\le k, \le l}(M)$ denote the set of projected visible traces $\pi_{\Sigma}(\sigma) \in \pi_{\Sigma}(\mathcal{T}(M))$ such that the total length of the visible trace is $|\pi_{\Sigma}(\sigma)| \le 12$ and the number of occurrences of the activity `'Analyze Revision'` in $\pi_{\Sigma}(\sigma)$ is $\le 3$. Models $M_A$ and $M_B$ are bounded-equivalent under P3 iff $\mathcal{L}_{\le 12, \le 3}(M_A) = \mathcal{L}_{\le 12, \le 3}(M_B)$.
- **Business-relevant equivalence under P1 (Operational Compliance)**: Under P1, the relative execution order between analytical work (`'Analyze Revision'`), verification (`'Check Revision'`), and corrections (`'Rework Case'`) is critical. Equivalence requires that for every iteration of analysis, a corresponding check occurs before any subsequent rework or case closure. Furthermore, individual occurrences, exact counts, and relative placements of optional `'Approve Revision'` events must be preserved.
- **Abstracted dashboard equivalence under P2 (Executive Dashboard)**: Under P2, the observation boundary collapses internal event interleavings. Let $\alpha_{P2}(\sigma)$ be an abstraction function that:
  1. Enforces the strict frame: starts with `'Open Case'` and ends with `'Close Case'`.
  2. Requires at least one `'Analyze Revision'` and at least one `'Check Revision'` in the trace.
  3. Maps any contiguous or repeated occurrences of `'Check Revision'` to a single Boolean indicator (or collapses them such that the exact multiplicity and interleaving timing relative to individual analysis steps are erased).
  4. Completely hides `'Approve Revision'` and all silent $\tau$ steps.
  5. Preserves the exact count of `'Analyze Revision'` and a Boolean flag indicating whether `'Rework Case'` occurred.
  
  Models are P2-equivalent iff the image sets under $\alpha_{P2}$ coincide: $\alpha_{P2}(\pi_{\Sigma}(\mathcal{T}(M_A))) = \alpha_{P2}(\pi_{\Sigma}(\mathcal{T}(M_B)))$.

**Label Identity and Distinguishability**: Duplicate visible labels (such as multiple `'Analyze Revision'` or `'Check Revision'` instances within a loop) are distinguished strictly by their **occurrence position** (sequential index in the trace). Labels do not carry unique instance IDs; identical strings are treated as equal symbols inhabiting different positions in the sequence.

| **TC3** | `['Open Case', 'Analyze Revision', 'Check Revision', 'Rework Case', 'Analyze Revision', 'Check Revision', 'Close Case']` | True | False | Model A strictly requires a check paired inside every iteration of the revision loop. | **TC4** | `['Open Case', 'Analyze Revision', 'Check Revision', 'Approve Revision', 'Rework Case', 'Analyze Revision', 'Check Revision', 'Close Case']` | True | False | Model A enforces the approval/tau choice *inside* the sequential loop branch for every iteration, producing specific structural traces unreachable by Model B's concurrent check scheduling. | P1, P3 |

**Impact of Optional Approve Revision and Hidden $\tau$**:
The optional `'Approve Revision'` (paired in an XOR with $\tau$) introduces non-determinism into the loop body. In Model A, this choice occurs locally within each iteration alongside `'Analyze Revision'` and `'Check Revision'`. When $\tau$ is chosen, no approval event appears in the visible trace, shortening the observed sequence without altering the control-flow backbone. In Model B, the same local XOR choice exists inside the revision loop, but the concurrent placement of `'Check Revision'` means the $\tau$ transitions in the loop do not restrict when the concurrent check completes. This decouples local iteration approvals from verification timing, generating distinct visible trace sets.

# 5. Bounded Comparison Code

```python
import pm4py
from pm4py.objects.process_tree.utils import parse
from pm4py.algo.conversion.process_tree import algorithm as pt_conversion
from pm4py.objects.petri_net.utils.check_soundness import check_workflow_net

def analyze_models():
    # 1. Parse process trees
    tree_a_str = "->('Open Case', *(-( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) ), 'Rework Case'), 'Close Case')"
    tree_b_str = "->('Open Case', +( 'Check Revision', *(-( 'Analyze Revision', X('Approve Revision', tau) ), 'Rework Case') ), 'Close Case')"
    
    tree_a = parse(tree_a_str)
    tree_b = parse(tree_b_str)
    
    # 2. Convert to accepting Petri nets
    net_a, im_a, fm_a = pt_conversion.apply(tree_a)
    net_b, im_b, fm_b = pt_conversion.apply(tree_b)
    
    # 3. Check soundness
    sound_a = check_workflow_net(net_a)
    sound_b = check_workflow_net(net_b)
    print(f"Model A Soundness: {sound_a}")
    print(f"Model B Soundness: {sound_b}")
    
    # 4. Bounded exploration function (Exhaustive BFS over markings)
    def explore_bounded_traces(net, im, fm, max_visible=12, max_analyze=3):
        visited_states = set()
        completed_traces = set()
        
        # Queue stores: (marking, visible_trace_tuple, analyze_count)
        queue = [(im, (), 0)]
        
        while queue:
            marking, v_trace, analyze_count = queue.pop(0)
            
            # Check acceptance
            if marking == fm:
                completed_traces.add(v_trace)
                continue
                
            state_sig = (marking, v_trace)
            if state_sig in visited_states:
                continue
            visited_states.add(state_sig)
            
            for t in pm4py.get_enabled_transitions(net, marking):
                next_marking = pm4py.execute_transition(net, marking, t)
                label = t.label
                
                new_v_trace = v_trace
                new_analyze = analyze_count
                
                if label is not None:
                    if len(v_trace) + 1 > max_visible:
                        continue
                    if label == 'Analyze Revision':
                        if analyze_count + 1 > max_analyze:
                            continue
                        new_analyze += 1
                    new_v_trace = v_trace + (label,)
                
                queue.append((next_marking, new_v_trace, new_analyze))
                
        return completed_traces

    traces_a = explore_bounded_traces(net_a, im_a, fm_a)
    traces_b = explore_bounded_traces(net_b, im_b, fm_b)
    
    # 5. Compare visible trace sets under P3 bound
    diff_a_b = traces_a - traces_b
    diff_b_a = traces_b - traces_a
    
    print(f"\nTotal Bounded Traces Model A: {len(traces_a)}")
    print(f"Total Bounded Traces Model B: {len(traces_b)}")
    print(f"Traces unique to Model A: {len(diff_a_b)}")
    print(f"Traces unique to Model B: {len(diff_b_a)}")
    
    print("\nSample Unique to Model A:")
    for t in list(diff_a_b)[:3]:
        print(t)
        
    print("\nSample Unique to Model B:")
    for t in list(diff_b_a)[:3]:
        print(t)

if __name__ == "__main__":
    analyze_models()
```

# 6. Stochastic and Footprint Comparison

- **`pm4py.discover_footprints(...)`**: Footprints capture direct succession ($\rightarrow$), causality ($\rightarrow_{\#}$), parallelism ($\parallel$), and choice ($\#$) relations between pairs of visible activities. Because footprints summarize binary relations across the entire event log or model language, two models with different concurrency structures (such as Model A's sequential pairing vs. Model B's top-level parallelism) will often yield distinct footprint matrices, confirming structural divergence.
- **`pm4py.get_stochastic_language(...)`**: Assigns probability distributions to the execution paths of process trees or stochastic Petri nets. Stochastic language evaluation quantifies how frequently specific traces occur under assumed transition weights.
- **`pm4py.compute_emd(language1, language2)`**: Earth Mover's Distance (EMD) measures the minimum cost of turning one probabilistic language into another based on trace edit distances.

**Why equal footprints or low EMD do not establish trace equivalence**: Footprints are strictly lossy binary abstractions; they ignore loop multiplicities, long-range dependencies, and frequency distributions. Similarly, a low EMD indicates that two stochastic models generate statistically similar behavior within a given probabilistic profile, but it does not prove that their support sets (exact languages) are identical. Unobserved counterexample traces can still exist in the tails of the distribution.

```python
import pm4py
from pm4py.objects.process_tree.utils import parse

def footprint_stochastic_analysis():
    tree_a = parse("->('Open Case', *(-( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) ), 'Rework Case'), 'Close Case')")
    tree_b = parse("->('Open Case', +( 'Check Revision', *(-( 'Analyze Revision', X('Approve Revision', tau) ), 'Rework Case') ), 'Close Case')")
    
    fp_a = pm4py.discover_footprints(tree_a)
    fp_b = pm4py.discover_footprints(tree_b)
    
    print("Footprints Equal:", fp_a == fp_b)

if __name__ == "__main__":
    footprint_stochastic_analysis()
```

# 8. Simplified Model

We choose **P2 (Executive Dashboard)** combined with strict operational ordering from P1 as our target semantics, creating a clean, unambiguous process tree that enforces single-check verification per analysis cycle while removing redundant structural bloat.

### 1. Compact Process Tree Expression
```text
->('Open Case', +( 'Check Revision', *(-( 'Analyze Revision', X('Approve Revision', tau) ), 'Rework Case') ), 'Close Case')
```
*(Refined Simplified Process Tree)*:
```text
->('Open Case', *( ->('Analyze Revision', X('Approve Revision', tau), 'Check Revision'), 'Rework Case' ), 'Close Case')
```

### 2. PM4Py Code Assigning to `simplified_model`
```python
import pm4py
from pm4py.objects.process_tree.utils import parse

# Simplified model enforcing sequential check per iteration without parallel ambiguity
simplified_model = parse("->('Open Case', *( ->('Analyze Revision', X('Approve Revision', tau), 'Check Revision'), 'Rework Case' ), 'Close Case')")
```

# 9. Final Recommendation

- **Model Suitability**: 
  - **Model A** is suitable for **P1 (Operational Compliance)** because it structurally enforces that every analysis revision undergoes localized checking prior to rework or case closure.
  - **Model B** is **unsuitable** for operational compliance because top-level concurrency allows checks to occur before analysis or finish independently of revision loops.
- **Simplified Model Recommendation**: The proposed simplified model (`simplified_model`) should replace both original models. It eliminates Model B's compliance flaws while removing unnecessary structural complexity, aligning cleanly with both executive dashboard visibility requirements and operational audit constraints.
- **Warning on Bounded Comparison**: Bounded testing and verification ($k \le 12$, analyze $\le 3$) provide strong empirical evidence within typical operational envelopes, but they **do not constitute a formal proof of unbounded equivalence**. Unseen divergences may emerge in extremely long-running cases exceeding the test bound.
