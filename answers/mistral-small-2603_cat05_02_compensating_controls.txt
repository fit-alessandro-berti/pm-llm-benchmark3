## 1. Control-Objective Decomposition

FEP-1’s nominal four-eyes principle is a single control objective, but it decomposes into multiple threat scenarios that require different compensating controls to address:

| **Threat Scenario** | **Preventive Controls** | **Detective Controls** | **Corrective Capacity** | **Failure Modes** |
|---------------------|------------------------|------------------------|-------------------------|-------------------|
| **Erroneous payment** (wrong vendor, amount, or bank) | AV-2 (duplicate invoice, sanctions, bank ownership, PO match), ED-1 (bank-change check, operator limit) | RA-7 (audit review), MG-4 (manager approval) | RA-7 (recall within 24h) | AV-2 override without justification; ED-1 conditions bypassed |
| **Fraudulent payment** (intentional misappropriation) | AV-2 (sanctions, bank ownership), ED-1 (bank-change check, operator limit), MG-4 (independent manager) | RA-7 (audit review), MG-4 (approval before settlement) | RA-7 (recall within 24h) | Collusion between preparer/releaser and manager; shared credentials |
| **Collusion** (two actors acting as one) | ED-1 (independent manager approval), MG-4 (independent manager) | RA-7 (audit review for pattern detection) | Limited (cannot correct collusion after the fact) | Repeated same-user pairs (u12/u13); manager in direct reporting line (m09/u23) |
| **Bank account takeover** (compromised vendor account) | AV-2 (bank ownership verification), ED-1 (bank-change check) | RA-7 (audit review), MG-4 (approval before settlement) | RA-7 (recall within 24h) | AV-2 unavailable (AP-208); late emergency token (AP-206) |
| **Process circumvention** (emergency bypass without justification) | ED-1 (strict conditions: token before Prepare_Payment, amount limit, vendor age, no bank change, AV-2 pass, manager approval before settlement, audit within 1 day) | RA-7 (audit review), MG-4 (approval before settlement) | RA-7 (recall within 24h) | Emergency token created after Prepare_Payment (AP-206); manager ratification after settlement (AP-208) |

## 2. Equivalence and Sufficiency Test

A compensating-control package is evaluated against the following structured test:

| **Criterion** | **Fully Equivalent** | **Partially Equivalent** | **Merely Mitigating** | **Ineffective** |
|---------------|----------------------|--------------------------|-----------------------|-----------------|
| **Timing** | Preventive/detective/corrective controls act *before* irrevocable bank settlement. Manager approval occurs *before* release or settlement. | Detective/corrective controls act *after* release but *before* settlement. | Detective/corrective controls act *after* settlement. | Controls act *after* recall window (>24h). |
| **Independence** | Manager is L3+, not preparer/releaser, and has no unresolved conflict of interest. | Manager is independent but approves *after* release. | Manager is in direct reporting line (e.g., m09/u23). | Shared credentials or collusion suspected. |
| **Coverage** | All AV-2 checks passed without override; ED-1 conditions fully met. | AV-2 warning overridden with justification; ED-1 conditions mostly met. | AV-2 unavailable; manager checklist unsigned. | AV-2 blocked but no manager review; or manager ratifies without review. |
| **Overrideability** | Override requires documented justification and retains evidence. | Override occurs but is later justified in audit. | Override occurs with no justification. | Override occurs with no evidence or collusion suspected. |
| **Recoverability** | Recall possible within 24h; audit detects defect before settlement. | Recall possible but delayed; audit detects defect after settlement. | Recall unlikely; audit detects defect after recall window. | No reliable bank-ownership evidence; recall impossible. |
| **Evidence Quality** | Complete audit trail (invoice, bank details, receipts, manager review). | Incomplete audit trail (e.g., missing receipts). | Audit trail shows anomalies but no clear defect. | Audit trail fabricated or missing. |
| **Collusion Resistance** | No repeated same-user pairs; no shared workstations; no manager in direct reporting line. | Repeated same-user pairs but no evidence of collusion. | Repeated same-user pairs with shared workstation; manager in direct reporting line. | Clear evidence of collusion (e.g., shared credentials, fabricated receipts). |

**Why "same expected loss" is not the only standard:**
- **Control objectives** are not solely about loss reduction but also about *preventing circumvention*, *ensuring accountability*, and *maintaining process integrity*.
- **Independence** and **collusion resistance** are qualitative objectives that cannot be reduced to a numerical loss metric.
- **Timing** matters: A control that acts *after* settlement may reduce expected loss but fails the control objective of preventing erroneous/fraudulent transfers.
- **Evidence quality** affects the ability to *detect* and *correct* defects, even if the defect itself is rare.

## 4. Preventive–Detective–Corrective Comparison

| **Control** | **Preventive** | **Detective** | **Corrective** | **Hybrid/Notes** |
|-------------|---------------|---------------|----------------|------------------|
| **AV-2** |  (blocks release if checks fail) |  (emits warnings) |  (cannot correct after release) | Hybrid: Preventive if it blocks; detective if it warns. |
| **MG-4 (Manager Approval)** |  (if before release/settlement) |  (if after release but before settlement) |  (cannot correct after settlement) | Hybrid: Preventive if before release; detective if after release but before settlement. |
| **RA-7 (Audit Review)** |  |  |  (if defect detected before recall window) | Hybrid: Detective if after release; corrective only if defect detected within 24h. |
| **ED-1 (Emergency Permission)** |  (if all conditions met) |  (audit required) |  (if defect detected within 24h) | Hybrid: Preventive if conditions met; detective/corrective via audit. |

**Semantics of MG-4 timing:**
- **Preventive**: Manager approves *before* release or settlement (e.g., AP-203, AP-206, AP-207).
- **Detective**: Manager approves *after* release but *before* settlement (e.g., AP-201, AP-207).
- **Hybrid**: If approval occurs *after* settlement, it is purely detective and lacks corrective capacity (e.g., AP-208).

## 6. Evidence and Monitoring Recommendations

### **Evidence Collection Rules**
1. **Same-User Rate**: Monitor the frequency of same-user Prepare_Payment/Release_Payment pairs. Alert if >5% of payments.
2. **Override Rate**: Track AV-2 overrides and require documented justification in audit trail.
3. **Late Manager Approval**: Flag manager approvals occurring >1 hour after release or after settlement.
4. **Audit-Before-Recall-Window**: Ensure 100% of emergency payments are audited within 1 business day.
5. **Repeated Resource Pairs**: Alert on repeated same-user pairs (e.g., u12/u13 in >10 payments).
6. **Shared Workstations**: Monitor logins from shared workstations for payment actors.
7. **Bank-Change Proximity**: Alert on bank-account changes within 7 days of payment.
8. **Control Outages**: Log AV-2 unavailability and require manager checklist for manual overrides.

### **Distinguishing Alerts from Proof of Misconduct**
- **Alert**: Repeated same-user pairs, shared workstations, or late manager approvals.
- **Proof of Misconduct**: Fabricated receipts, shared credentials, vendor linked to employee’s relative, or manager in direct reporting line approving overrides.

### **Monitoring Dashboard**
| **Metric** | **Threshold** | **Action** |
|------------|---------------|------------|
| Same-user rate | >5% | Investigate process circumvention. |
| AV-2 override rate | >2% | Require documented justification. |
| Late manager approval | >1 hour after release | Escalate to compliance. |
| Audit delay for emergency payments | >1 business day | Flag for immediate review. |
| Repeated resource pairs | >10 payments | Review organizational design. |
| Bank-change proximity | Within 7 days | Require additional approvals. |
| Control outages (AV-2 unavailable) | Any | Require manager checklist. |

- **PM4Py Behavior**: The `filter_four_eyes_principle` function identifies cases where the same resource performs both `Prepare_Payment` and `Release_Payment`. This is a nominal violation of FEP-1 but does not assess control-objective sufficiency.
- **Version Compatibility**: The code assumes PM4Py 2.7+ and pandas 1.3+. Minor adjustments may be needed for older versions (e.g., column name changes).
- **Output**: The `preliminary_flags_df` provides evidence flags for emergency eligibility, AV-2 coverage, manager timing, audit timing, bank change proximity, repeated pairs, shared workstations, and control outages. This is **not** the final compliance verdict but supports the analysis in Sections 1–6.
