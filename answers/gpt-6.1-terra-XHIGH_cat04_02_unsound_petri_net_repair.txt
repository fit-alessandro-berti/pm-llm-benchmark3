# 1. Executive Verdict

The net is a workflow net: it has one source, one sink, and every node lies on a directed path between them. It is not sound. The waiver join consumes only the waiver token, so authorization can occur before analysis finishes. Even if analysis finishes first, the waiver join leaves its completion token behind. A waiver case can therefore put a token in the sink without reaching the exact final marking. This both violates the mandatory-analysis rule and leaves the case unable to complete properly.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_register` and `t_split` | Register, then start analysis and review in parallel | `t_split` consumes `p_ready` and produces one token each in `p_analysis` and `p_review` | Both branches have outstanding work after the split |
| `t_analyze` | Complete mandatory analysis | Consumes `p_analysis` and produces `p_analysis_done` | Its result must be consumed by an appropriate join for proper completion |
| `t_standard_review`, `t_waive_review` | Select standard review or a recorded waiver | Both compete for the single `p_review` token; the former produces `p_review_done`, the latter `p_waived` | Exactly one review outcome is selected in each execution |
| `t_join_normal` | Wait for analysis and standard review | Requires and consumes both `p_analysis_done` and `p_review_done`, then produces `p_decision` | Normal path synchronizes correctly |
| `t_join_waived` | Wait for analysis and waiver | Requires only `p_waived` and produces `p_decision` | Early authorization and an unconsumed analysis token on the waiver path |
| `im`, `fm` | Start with one case and finish with no work remaining | `im = {source: 1}` and `fm = {sink: 1}`; the latter is an exact marking, not merely a requirement that `sink` contain a token | A sink token plus another token is not `fm` |
| Whole graph | Connect all nodes from start to finish | `source` is the unique source, `sink` the unique sink, and every place and transition lies on a directed source-to-sink path | The workflow-net structure passes even though execution is unsound |

# 3. Marking-Based Counterexample

The following legal sequence takes the waiver route and authorizes **before** analysis:

`t_register`, `t_split`, `t_waive_review`, `t_join_waived`, `t_authorize`, `t_analyze`.

Markings below list only nonzero places; each displayed place has one token. Enabled transitions are listed after the firing in that row.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `{source}` | `t_register` | Initial marking `im` |
| 1 | `t_register` | `{p_ready}` | `t_split` | Case registered |
| 2 | `t_split` | `{p_analysis, p_review}` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token in each parallel branch |
| 3 | `t_waive_review` | `{p_analysis, p_waived}` | `t_analyze`, `t_join_waived` | Waiver chosen; standard review is no longer enabled |
| 4 | `t_join_waived` | `{p_analysis, p_decision}` | `t_analyze`, `t_authorize` | The join did not wait for analysis |
| 5 | `t_authorize` | `{p_analysis, sink}` | `t_analyze` | A token is in `sink`, but this is not `fm`; authorization preceded analysis |
| 6 | `t_analyze` | `{p_analysis_done, sink}` | None | Dead marking, still not `fm` |

The remaining `p_analysis_done` token cannot be consumed: its only outgoing arc goes to `t_join_normal`, which also requires `p_review_done`. The waiver consumed the only `p_review` token, and nothing can now produce `p_review_done`. Before step 6, `p_analysis` can be consumed by `t_analyze`, but doing so only moves the leftover token to `p_analysis_done`.

Authorization can also occur **after** analysis and still fail proper completion: from step 4, firing `t_analyze` gives `{p_analysis_done, p_decision}`; firing `t_authorize` then gives `{p_analysis_done, sink}`, again a dead marking distinct from `fm`. More generally, after the waiver has been selected, there is no way to reach `fm`: the analysis token cannot be removed by either join. The normal review route, by contrast, can reach `fm` through `t_join_normal`.

# 4. Minimal-Repair Alternatives

Use the following edit-cost model: each added or removed arc, place, or transition costs one; a rewire costs one removal plus one addition. Initial and final markings and transition labels remain unchanged. The costs below count edits to the given net.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| A: synchronize waiver directly | Add `p_analysis_done → t_join_waived` | 1 | Analysis remains mandatory; both review outcomes remain visible and distinct | The waiver join waits for and consumes analysis completion before enabling authorization | The two separate silent joins must both be maintained if the synchronization rule changes |
| B: route waiver to the common join | Remove `t_join_waived → p_decision`; add `t_join_waived → p_review_done` | 2 | Analysis remains mandatory; standard review and waiver remain visible and distinct | After waiver, `t_join_waived` silently routes the outcome to `p_review_done`; `t_join_normal` then synchronizes either outcome with analysis | `p_review_done` now represents either outcome, and the extra silent routing step can confuse readers or trace alignment |

Repair A is globally minimal under this cost model: zero edits leave the demonstrated defect, while one added arc suffices. For repair B, the stated structural change requires removing the existing output arc and adding a different output arc, so it costs at least two and the proposed edits attain that bound. It is not globally minimum-cost: repair A is cheaper. The alternatives have the same intended visible behavior but differ structurally and in their silent-transition behavior; B is minimal for its specified rewiring, not claimed to be the unique cheapest alternative in every possible repair family.

For A, the selected review outcome and analysis each produce a token required by the corresponding join. The join consumes both and produces one decision token, which authorization consumes to produce the sole sink token. For B, either review alternative eventually places one token in `p_review_done`, and the common join consumes it together with the analysis token. In both repairs, all transitions remain usable and every reachable partial execution can be completed to the exact final marking.

# 5. Corrected PM4Py Code

The following standalone code implements repair A, adding the missing analysis input to the waiver join.

```python
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for place in {
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink,
}:
    repaired_net.places.add(place)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for transition in {
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize,
}:
    repaired_net.transitions.add(transition)

for src, dst in [
    (source, register),
    (register, p_ready),
    (p_ready, split),
    (split, p_analysis),
    (split, p_review),
    (p_analysis, analyze),
    (analyze, p_analysis_done),
    (p_review, standard_review),
    (standard_review, p_review_done),
    (p_review, waive_review),
    (waive_review, p_waived),
    (p_analysis_done, join_normal),
    (p_review_done, join_normal),
    (join_normal, p_decision),
    (p_waived, join_waived),
    (p_analysis_done, join_waived),  # Wait for analysis on the waiver path too.
    (join_waived, p_decision),
    (p_decision, authorize),
    (authorize, sink),
]:
    petri_utils.add_arc_from_to(src, dst, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

Run this block in a context where the original `net`, `im`, `fm` and the repaired variables above have been constructed. It checks each requested property and attempts the same early-authorization sequence on both nets. The helper checks enabledness before firing; on the repaired net it stops at the disabled waiver join.

```python
import pm4py
from pm4py.objects.petri_net import semantics


def format_marking(marking):
    return "{" + ", ".join(
        f"{place.name}: {count}"
        for place, count in sorted(marking.items(), key=lambda item: item[0].name)
        if count
    ) + "}"


def run_sequence(net, initial_marking, names):
    by_name = {transition.name: transition for transition in net.transitions}
    if len(by_name) != len(net.transitions):
        raise ValueError("Transition names must be unique")
    marking = initial_marking.copy()
    print("Initial:", format_marking(marking))
    for name in names:
        transition = by_name[name]
        enabled = pm4py.get_enabled_transitions(net, marking)
        if transition not in enabled:
            print(name, "is not enabled at", format_marking(marking))
            break
        marking = semantics.execute(transition, net, marking)
        print(name, "->", format_marking(marking))
    return marking


sequence = [
    "t_register", "t_split", "t_waive_review", "t_join_waived",
    "t_authorize", "t_analyze",
]

for title, current_net, initial, final in [
    ("original", net, im, fm),
    ("repaired", repaired_net, repaired_im, repaired_fm),
]:
    print("\n", title)
    print("Workflow net:", pm4py.check_is_workflow_net(current_net))
    print("Soundness result:", pm4py.check_soundness(
        current_net, initial, final, print_diagnostics=True
    ))
    print("Initially enabled:", sorted(
        transition.name
        for transition in pm4py.get_enabled_transitions(current_net, initial)
    ))
    reachability_graph = pm4py.convert_to_reachability_graph(
        current_net, initial, final
    )
    print("Reachability graph:", reachability_graph)
    end_marking = run_sequence(current_net, initial, sequence)
    print("Exact final marking reached:", end_marking == final)
```

Both nets should pass the structural workflow-net check. The original should fail soundness because the waiver route cannot complete properly, whereas repair A should pass. The original sequence reaches a dead marking with both `sink` and `p_analysis_done` marked; in the repaired net `t_join_waived` is disabled until analysis has fired. Exact diagnostic fields and presentation can vary with the PM4Py version.

# 7. Repair Trade-Offs and Residual Risks

Both repairs keep `Perform Standard Review` and `Record Review Waiver` as distinct visible transitions, so a complete visible trace records which outcome was selected. In repair B, however, the common completion place no longer identifies which outcome occurred; a marking alone loses that distinction after routing.

Repair A retains two silent joins, but they do not create duplicate choices in a single case: the exclusive review alternatives put a token in only one of `p_review_done` and `p_waived`. Silent transitions can nevertheless obscure the synchronization in a visualization or complicate trace alignment. Repair B adds a silent routing step and makes the meaning of `p_review_done` broader.

Soundness establishes behavioral completion properties for the modeled net and markings; it does not prove that the model expresses the business policy. For example, an alternative model that deliberately skips analysis on waiver could be sound while violating the stated mandatory-analysis rule. Soundness also says nothing by itself about whether the real review or waiver was valid.

Regression tests should accept both review outcomes, with analysis occurring either before or after the selected outcome, followed by authorization and the exact final marking. They should reject authorization before analysis or before a review outcome, a case with no review outcome, and a case containing both review alternatives for the same single execution. They should also check that a completed case has no tokens outside `sink`. Trace checks should account for the silent split and joins.

To detect an accidental analysis bypass, explore reachable markings and assert that `t_authorize` is never enabled until `t_analyze` has fired in that case, on both the waiver and standard routes. Also check the visible traces and exact final markings; a soundness check alone is insufficient for this rule.

# 8. Final Recommendation

Deploy repair A. Its single added arc directly expresses the missing prerequisite, preserves both visible review outcomes, and keeps each outcome's synchronization explicit. Verify soundness and the positive and negative traces before deployment.

Use repair B as the fallback if a shared synchronization point is preferred. Rename or document `p_review_done` as a generic review-outcome completion place in a subsequent maintenance change so that its broadened meaning is clear; that rename is not included in the stated two-edit cost.
