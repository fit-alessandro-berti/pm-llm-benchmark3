# 2. Candidate Conversion Pipelines
| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| `POWL → accepting Petri net → BPMN` (Primary) | `pm4py.convert_to_petri_net`, `pm4py.convert_to_bpmn` | Highest structural fidelity to partial order logic; always yields a graph model. | BPMN visualization may include spaghetti routing, empty XORs, or confusing gateway cascades. | Rejection due to PM4Py state-space explosion or unresolvable internal gateway generation. |
| `POWL → accepting Petri net → process tree → BPMN` | `pm4py.convert_to_petri_net`, `pm4py.convert_to_process_tree`, `pm4py.convert_to_bpmn` | Inherently block-structured resulting BPMN, avoiding confusing gateways. | Source semantics containing non-block-structured interleavings (like overlapping asynchronous branches) will violate process tree assumptions. | `convert_to_process_tree` raises an Exception because the source POWL is not strictly block-structured. |

# 3. Conversion Code
```python
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
)
from pm4py.objects.process_tree.obj import Operator

# [Source POWL definition exactly as provided]
register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(operator=Operator.XOR, children=[legal_review, skip_legal])

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(operator=Operator.LOOP, children=[trial_body, correct_defect])

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[register, assess_risk, prepare_evidence, optional_legal, 
           verification_loop, release_change, archive_change]
)
source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)

# 1. POWL to Petri Net
try:
    net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(source_powl)
    pm4py.save_vis_petri_net(net_from_powl, im_from_powl, fm_from_powl, "net_from_powl.png")
except Exception as e:
    print(f"Failed POWL to Petri net conversion: {e}")

# 2. Petri Net to BPMN (Primary Pipeline)
try:
    bpmn_from_net = pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)
    pm4py.save_vis_bpmn(bpmn_from_net, "bpmn_from_net.png")
    
    rt_net1, rt_im1, rt_fm1 = pm4py.convert_to_petri_net(bpmn_from_net)
    print("BPMN from Net Workflow Net:", pm4py.check_is_workflow_net(rt_net1))
    pm4py.check_soundness(rt_net1, rt_im1, rt_fm1, print_diagnostics=True)
except Exception as e:
    print(f"Failed Net to BPMN pipeline: {e}")

# 3. Process Tree Intermediate Pipeline
try:
    tree_from_net = pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)
    pm4py.save_vis_process_tree(tree_from_net, "tree_from_net.png")
    
    bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
    pm4py.save_vis_bpmn(bpmn_from_tree, "bpmn_from_tree.png")
    
    rt_net2, rt_im2, rt_fm2 = pm4py.convert_to_petri_net(bpmn_from_tree)
    print("BPMN from Tree Workflow Net:", pm4py.check_is_workflow_net(rt_net2))
    pm4py.check_soundness(rt_net2, rt_im2, rt_fm2, print_diagnostics=True)
except Exception as e:
    print(f"Process tree intermediate conversion failed: {e}")
```

# 4. Preservation and Loss Audit
| Source invariant | POWL→Petri | Petri→BPMN | Petri→Tree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| INV-1 | expected preserved | expected preserved | conversion failed | expected preserved | Validated via start events/initial markings. |
| INV-2 | expected preserved | expected preserved | conversion failed | expected preserved | Parallel branching validates arbitrary interleaving. |
| INV-3 | expected preserved | approximated | conversion failed | ambiguous | BPMN translates tau to an empty XOR branch, introducing silent routes on round-trip. |
| INV-4 | expected preserved | expected preserved | conversion failed | expected preserved | Explicit synchronizing AND-joins exist. |
| INV-5 | expected preserved | expected preserved | conversion failed | expected preserved | Cross-branch unstructured overlap causes Tree conversion to explicitly fail. |
| INV-6 | expected preserved | expected preserved | conversion failed | expected preserved | Sequence flows preserve explicit order. |
| INV-7 | expected preserved | expected preserved | conversion failed | expected preserved | Directed cyclic routing observed in BPMN. |
| INV-8 | expected preserved | expected preserved | conversion failed | expected preserved | XOR branching for exit only happens post initial execution. |
| INV-9 | expected preserved | expected preserved | conversion failed | expected preserved | Explicit synchronization gateway before release task. |
| INV-10 | expected preserved | expected preserved | conversion failed | expected preserved | Validated via exact final marking correctness. |

**Discussion:**
- **True concurrency versus arbitrary interleaving:** The POWL source strictly models true concurrency. However, the Petri net and subsequent round trips only mathematically prove arbitrary interleaving via formal semantics, meaning actual execution environments may serialize tasks unnecessarily.
- **The lack of an edge between Optional Legal Review and verification:** This represents unrestricted parallelism. Because Legal Review is decoupled from the Verification loop, the resulting net is non-block-structured (overlapping, independent synchronization scopes). This directly causes the Process Tree intermediate conversion to fail.
- **Silent optional behavior:** The `SilentTransition` translating to skip legal is structurally preserved in the Petri Net as a tau-transition. BPMN approximates this with an XOR split/join and an empty sequence flow. Re-converting introduces anonymous/silent routing nodes, creating structural drift from the initial tau.
- **Binary-loop semantics:** The `OperatorPOWL` LOOP requires the "do" block (Trial Body) and the "redo" block (Correct Defect). This translates successfully into cyclic routing (Petri net places/BPMN gateways) but loses the semantic "loop" activity construct specific to BPMN standard loop characteristics.
- **The join before Release Change:** Preserved structurally as an AND-join in BPMN and synchronizing transition in the Petri Net. However, visualizing parallel joins merging branches originating from different structural depths can appear as invalid BPMN to business users.
- **Activity-label uniqueness:** All transition labels are globally unique in the source, preventing non-determinism during execution mapping and allowing transparent trace validation.
- **Initial and final markings:** Formally retained during Petri net execution, but BPMN start/end events in PM4Py are inferred during round trips. This can result in additional place/transition generation that satisfies exact marking equality but litters the model with duplicate tau boundaries.
- **Gateway or routing-node ambiguity in BPMN visualization:** Standard layout algorithms frequently position parallel execution paths vertically or sequentially. BPMN readers might incorrectly infer an ordering (e.g., Legal Review must finish before Verification starts) simply due to left-to-right drawing orientation, despite gateways allowing true concurrency.

# 5. Round-Trip Validation Code
```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

def bounded_trace_exploration(net, im, fm, max_length=20):
    """
    Custom bounded visible-trace exploration using pm4py.get_enabled_transitions.
    Hides tau transitions (label is None), prevents infinite loops, and checks exact final marking equality.
    """
    def fire(m, t):
        new_m = Marking(m)
        for arc in t.in_arcs:
            new_m[arc.source] -= arc.weight
            if new_m[arc.source] == 0:
                del new_m[arc.source]
        for arc in t.out_arcs:
            new_m[arc.target] = new_m.get(arc.target, 0) + arc.weight
        return new_m

    queue = [(im, tuple())]
    visited = set()
    completed_traces = set()

    while queue:
        current_m, trace = queue.pop(0)
        
        # State tracking explicitly allows finite loops but prunes identical trace-lengths
        state = (hash(current_m), len(trace))
        if state in visited:
            continue
        visited.add(state)

        # Exact final-marking equality
        if current_m == fm:
            completed_traces.add(trace)
        
        if len(trace) >= max_length:
            continue

        enabled = pm4py.get_enabled_transitions(net, current_m)
        for t in enabled:
            next_m = fire(current_m, t)
            next_trace = list(trace)
            if t.label is not None:
                next_trace.append(t.label)
            queue.append((next_m, tuple(next_trace)))
            
    return completed_traces

# Compare Net from POWL vs Round-Tripped Net from BPMN
source_traces = bounded_trace_exploration(net_from_powl, im_from_powl, fm_from_powl)
rt_traces = bounded_trace_exploration(rt_net1, rt_im1, rt_fm1)

# Diagnostic checks
print("--- Round-Trip Validation ---")
print("Soundness Baseline Net:")
pm4py.check_soundness(net_from_powl, im_from_powl, fm_from_powl, print_diagnostics=True)
print("Soundness Round-Trip Net:")
pm4py.check_soundness(rt_net1, rt_im1, rt_fm1, print_diagnostics=True)

print(f"Bounded Exhaustive Trace Equivalency (Max Length 20): {source_traces == rt_traces}")

fp_source = pm4py.discover_footprints(net_from_powl, im_from_powl, fm_from_powl)
fp_rt = pm4py.discover_footprints(rt_net1, rt_im1, rt_fm1)
print(f"Footprints Equivalency: {fp_source == fp_rt}")
```
*Note: The trace comparison is exhaustive under the chosen bound (20) because the state-space and trace lengths are strictly truncated at this limit, covering the maximum practical loop iterations while eliminating silent-cycling explosions.*

# 6. Visual-Semantics Review
Even if `rt_net1` behaves perfectly during formal verification, the BPMN rendering introduces significant misread risks:
- **Parallel Gateways:** Because the underlying POWL merges unstructured parallel branches (Legal Review vs Verification), the BPMN visualizes cascading AND-joins that look unbalanced or syntactically invalid to typical modelers.
- **Exclusive Gateways:** The `skip_legal` silent transition becomes an empty path bridging two XOR gateways. Readers frequently miss empty paths, falsely concluding that Legal Review is a mandatory step.
- **Loop Visualization:** BPMN natively supports loop markers on activities. However, PM4Py translates POWL/Petri net loops into explicit graph cycles (XOR splits looping arrows backwards). Unstructured backward sequence flows can cross other unrelated sequence flows, creating layout spaghetti.
- **Silent Routing Nodes:** Often visually materialized as unnamed tasks or anomalous gateways in converted BPMN layouts, causing stakeholders to wonder what step is missing.
- **Apparent Ordering of Graph Layout:** The automated left-to-right or top-to-bottom layout algorithm places concurrent branches sequentially on the page. Stakeholders may perceive Assess Risk -> Legal Review as being structurally forced to occur before Prepare Evidence -> Verification, simply due to visual stacking.
- **Proposed Mitigation:** Annotate the BPMN layout explicitly with text objects stating "TRUE CONCURRENCY: Legal Review and Verification may overlap," use colored sequence flows for optional paths, and document the empty XOR branch as "Explicit Bypass."

# 7. Rejection Criteria
A conversion result must be rejected or quarantined under any of the following conditions:
1. **Unsoundness:** `pm4py.check_soundness` reports deadlocks, livelocks, or unreachable transitions on any generated net.
2. **Loss of required interleaving:** The bounded trace exploration discovers a constraint violation (e.g., `<..., Inspect Trial, Configure Trial, ...>`).
3. **Admission of release before verification:** A valid trace executes `Release Change` without an instance of `Inspect Trial`, violating synchronization criteria.
4. **Collapse of optional behavior:** The `skip_legal` pathway is lost, making `Legal Review` formally mandatory in the converted trace set.
5. **Failed exact-final-marking test:** The conversion admits traces that reach `Archive Change` but leave residual tokens in upstream places (causing an invalid marking state).
6. **Gateway mismatch / Unbalanced routing:** Conversion forces the BPMN logic to route a parallel branch through an exclusive merge, breaking structural integrity.

# 8. Canonical Representation Recommendation
- **Authoritative Representation:** The **POWL** model must remain the sole authoritative source of truth. It explicitly supports mixed partial-ordering and strict control-flow operators without forcing unnecessary block-structuring or creating hidden routing nodes.
- **Derivative Artifacts:** Petri nets, Process Trees, and BPMN models must be treated strictly as read-only derivatives used for execution engines, structural analysis, and stakeholder visualization.
- **Validation Evidence:** Any derived BPMN must be accompanied by an automated footprint comparison and bounded-trace equivalency check against the original POWL net mapping to prove it introduces no spurious constraints.
- **Process-Tree Intermediate:** Should **not** be allowed as a strict requirement. In this model, true unstructured concurrency exists (cross-branch dependencies), which explicitly violates the block-structured requirements of Process Trees. Enforcing a tree intermediate would require semantic destruction of the model constraints.
- **Avoiding Round-Trip Drift:** Never reverse-engineer stakeholder edits in BPMN back into the source. Modifications must be scripted in the POWL logic, and downstream models re-generated continuously in a one-way pipeline.

# 9. Residual Uncertainty
Even if every automated validation passes, the following claims cannot be established:
1. **Comprehensibility:** Formal mathematical equivalence does not guarantee that stakeholders will correctly interpret the generated BPMN layout without semantic drift in their understanding.
2. **Execution Engine Fidelity:** While arbitrary interleaving is proven, there is no guarantee that an underlying workflow engine won't forcefully serialize tasks (e.g., executing all Legal tasks before Verification) due to thread-pooling or resource allocation logic, destroying true concurrency.
3. **Bounded Safety against State-Space Explosion:** Passing a bounded trace exploration (e.g., max_length=20) cannot definitively prove the absence of a livelock or deadlock in loops extending past the bound in real-world extreme edge cases.
