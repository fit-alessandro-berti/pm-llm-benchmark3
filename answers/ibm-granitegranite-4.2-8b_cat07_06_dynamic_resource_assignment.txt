# 1. Objectives and constraints
**Hard / safetycompliance constraints (must always be satisfied)**  
1. **Security Review** – must be performed by a resource with skill3, or by a resource with skill12 *only* under explicit supervision by R7_Gita or R8_Hugo.  
2. **Final Approval** – must be performed by a resource with skill2; a skill1 resource may only prepare, not finalize.  
3. **Highpriority (urgent/high) Customer Negotiation or Rework** – cannot be assigned to a skill1 resource without supervision.  
4. **Batch fairness** – no resource receives more than4 new assignments in the current decision batch.  
5. **Overtime avoidance** – a resource whose overtimerisk = *high* must not receive a nonurgent (normal/low) assignment unless the SLA risk is urgent and no safer alternative exists.  
6. **Continuity & handover cost** – for highcomplexity cases with a high handovercost band, the current owner should keep the case unless the owner’s skill is01 and supervision is not feasible; otherwise a handover is preferred.  
7. **Training quota** – at least20% of normal/lowpriority assignments must be given to a resource whose documented training priority matches the activity type (e.g., diagnosis tasks to diagnosistrainees). This is a soft goal; violations are monitored rather than penalised.  

**Soft / preference tradeoffs (optimised, but can be traded off)**  
- **Throughput** – minimise average waiting time for urgent cases while respecting the batchfairness limit.  
- **Skill development** – favour giving normal/lowpriority tasks to trainees (skill12) whose training priority matches the activity, but avoid overloading trainees with highcomplexity or urgent work.  
- **Workload fairness** – balance the number of new assignments per resource around their current opencase load and remaining hours today.  
- **Resilience** – avoid putting all specialisttype work (e.g., security reviews) on the same two specialists; spread normal security reviews to trainees under supervision when possible.  
- **Continuity** – keep the current owner whenever the owner’s skill meets the minimum ( required skill) and the handover cost is not high; otherwise use supervision rather than a full handover if the owner’s skill is 12.

The policy never ignores any hard constraint; tradeoffs are resolved by a small scoring system (see Section2) and by explicit tiebreaking rules that favour continuity, then fairness, then training support, then urgency.

# 2. Assignment policy
*All steps are applied in order; if a hard constraint is violated the candidate is discarded immediately.*

1. **Eligibility filtering**  
   - For each pending case compute the *minimum required skill* from the activity (e.g., Securityskill3, or skill12 with supervisor{Gita, Hugo}).  
   - Build the set `Candidates(case)` of resources that either  
        *have skillrequired* **or** have skill12 **and** a supervisor (Gita/Hugo) can be attached (only for security normal tasks).  
   - Remove resources that are already at 4 new assignments in this batch.

2. **Urgency scoring** (`U(case)`)  
   - `U = 3` if SLA 4h (urgent), `U = 2` if priority = *high* and SLA 12h, `U = 1` otherwise.  
   - Used later in tiebreaking; not a hard filter.

3. **Skillmatch score** (`SM(r, case)`)  
   - `SM = 3` if `skill(r)  required` and `skill(r)  required+1`; `SM = 2` if `skill(r) = required1` (only for normal/low tasks); `SM = 1` otherwise; `SM = 0` if skill0 (never eligible after step1).  
   - Higher score favours a resource that naturally fits the skill level.

4. **Continuity / handover score** (`CT(r, case)`)  
   - If the case has a current owner `curr` and `skill(curr)  required`  `CT = 3` (keep owner).  
   - Else if `skill(curr)` is 12 **and** a supervisor (Gita/Hugo) is available  `CT = 2` (assign to `curr` with supervision).  
   - Else if the current owner is a specialist with skillrequired and the handovercost band is *medium* or *low*  `CT = 2` (prefer keep).  
   - Otherwise `CT = 1`.  
   - For security normal tasks we also allow `CT = 2` when assigning to a trainee (skill12) with supervisor Gita/Hugo.

5. **Workloadfairness score** (`WF(r, case)`)  
   - Compute `load(r) = (open_cases(r) + 1) / (hours_remaining(r) * 0.5)`. Smaller load  better fairness.  
   - Map to score: `WF = 3` if `load(r)  median_load`, `WF = 2` if within one stddev, `WF = 1` otherwise.  
   - Penalise resources with overtimerisk = *high* for normal/low tasks: subtract 1 from `WF` if `overtime = high` and `U  1` (i.e., not urgent).

6. **Trainingsupport score** (`TS(r, case)`)  
   - `TS = 2` if the resource’s documented training priority matches the activity type (e.g., diagnosistrainee for diagnosis/eligibility/rework tasks) **and** the case priority is normal/low.  
   - `TS = 1` if the priority is high/urgent but the resource’s training priority matches; otherwise `TS = 0`.  
   - This score is added only after hard constraints and urgency; it helps meet the 20% quota.

7. **Resilience / bottleneck avoidance score** (`RB(r, case)`)  
   - Detect “specialist bottlenecks” from the current snapshot: if a specialist team (securityspecialists Gita/Hugo, approvalspecialists David/Hugo) already has 3 pending specialisttype tasks (security or final approval) and the resource `r` is a specialist, give `RB = 1` (penalty), otherwise `RB = 2`.  
   - Normal trainees get `RB = 2`.

8. **Composite score** (`CS(r, case)`)  
   - `CS = 0.4·SM + 0.3·CT + 0.15·WF + 0.1·TS + 0.05·RB`.  
   - Scores are normalised to 03 after weighting. Hard constraints have already filtered out illegal candidates, so `CS` is computed only among remaining candidates.

9. **Tiebreaking & supervision handling**  
   - Choose the candidate with the highest `CS`.  
   - If the chosen resource is a trainee (skill12) for a security normal task, pair it with a supervisor (Gita or Hugo) that has the smallest current load among supervisors. Record `supervisor` in `assignment_reason`.  
   - If the chosen resource already has 4 new assignments, discard it and pick the next best candidate (fallback to the next highest `CS`).  
   - For urgent cases where the current owner’s skill is insufficient and no supervisor is available, the algorithm must pick a specialist (rule1) – this overrides the continuity score.

10. **Final decision logging**  
    - Store `assignment_reason` as a short human phrase (e.g., “keep owner – skillrequired”, “assign trainee+supervisor for normal security”, “balance workload – avoid specialist bottleneck”).  
    - Store `supports_training` = `Yes` iff `TS = 2` (matching priority + normal/low).  
    - Store `risk_to_monitor` summarising the most relevant SLA / overtime / handover risk (e.g., “urgent SLA3h – ensure Gita’s remaining hours”, “normal security with supervisor – supervisor availability”).

```python
def assign_policy(queue, resource_snapshot):
    # queue: list of cases with attributes (priority, sla_remaining, handover_band, current_owner, etc.)
    # resource_snapshot: dict {resource_id: {'open_cases': int, 'hours_remaining': float,
    #                                    'skill_matrix': dict, 'overtime_risk': str,
    #                                    'training_priority': str, 'supervisor_eligible': bool}}

    batch_new = {rid: 0 for rid in resource_snapshot}
    assignments = {}

    for case in queue:
        # 1. eligibility filter
        candidates = []
        for rid, res in resource_snapshot.items():
            if batch_new[rid] >= 4:
                continue
            req_skill = case.required_skill  # e.g., 'Security', 'Diagnosis'
            # map activity  min skill from matrix
            min_skill = get_min_skill(req_skill, case)   # helper from matrix
            if res['skill'][req_skill] >= min_skill:
                candidates.append(rid)
            elif req_skill == 'Security' and 1 <= res['skill']['Security'] <= 2:
                # normal security can be supervised
                candidates.append(rid)  # will be handled later with supervision

        # remove candidates that would violate overtime rule for nonurgent tasks
        urgency = case.priority.upper() in ('URGENT', 'HIGH') or case.sla_remaining <= 4
        for rid in list(candidates):
            if not urgency and res['overtime_risk'] == 'high':
                candidates.remove(rid)

        # 26 compute scores for remaining candidates
        best_rid = None
        best_cs = -1
        for rid in candidates:
            res = resource_snapshot[rid]
            SM = skill_match_score(res['skill'], case.required_skill)
            CT = continuity_score(case, res, resource_snapshot)
            WF = workload_fairness_score(res, case)
            TS = training_support_score(res['training_priority'], case.priority)
            RB = resilience_score(res['skill'], resource_snapshot)
            CS = 0.4*SM + 0.3*CT + 0.15*WF + 0.1*TS + 0.05*RB
            # tiebreak: if case is urgent and candidate is trainee without supervisor  discard
            if case.priority.upper() in ('URGENT', 'HIGH') and res['skill'][case.required_skill] <= 1:
                continue
            if CS > best_cs:
                best_cs = CS
                best_rid = rid

        # select best_rid; if none left due to overtime filter, fallback to smallest workload among all resources (ignoring overtime)
        if best_rid is None:
            # fallback: pick candidate with smallest WF (ignoring overtime penalty)
            for rid in candidates:
                res = resource_snapshot[rid]
                WF = workload_fairness_score(res, case)
                if best_rid is None or WF < workload_fairness_score(resource_snapshot[best_rid], case):
                    best_rid = rid

        # assign
        assignments[case.case_id] = best_rid
        batch_new[best_rid] += 1

        # decide supervisor for normal security trainee assignments
        if case.activity == 'Security Review' and case.priority.lower() != 'urgent' \
           and resource_snapshot[best_rid]['skill']['Security'] in (1,2):
            # pick smallestload supervisor among {Gita, Hugo}
            sup = pick_supervisor({'R7_Gita','R8_Hugo'}, resource_snapshot)
            assignments[case.case_id] = (best_rid, sup)  # tuple indicates supervised pair

        # set flags
        supports_training = (TS >= 2 and case.priority.lower() in ('normal','low'))
        risk = risk_summary(case, resource_snapshot[best_rid])
        assignment_reason = textual_reason(case, best_rid, assignments)

    return assignments, batch_new, supports_training flags
```

*Helper functions (`skill_match_score`, `continuity_score`, etc.) are straightforward arithmetic using the matrix and current owner info; `pick_supervisor` chooses the supervisor with the fewest new assignments already in this batch.*
