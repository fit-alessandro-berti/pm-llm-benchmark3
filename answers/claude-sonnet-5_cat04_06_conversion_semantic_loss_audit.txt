# 1. Source-Semantics Baseline

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| INV-1 | `Register Change` is the unique initial activity; nothing precedes it | `Register Change, Assess Risk, Prepare Evidence, ...` completes | Any completed trace not starting with `Register Change` | Yes |
| INV-2 | `Assess Risk` and `Prepare Evidence` are concurrent (both children of `Register Change`, no edge between them) | Both `...,Assess Risk,Prepare Evidence,...` and `...,Prepare Evidence,Assess Risk,...` complete | A model that admits only one fixed order between them | Yes |
| INV-3 | `optional_legal` depends only on `Assess Risk`, **not** on `Prepare Evidence` (no edge `prepare_evidence  optional_legal`) | `Register Change, Assess Risk, Legal Review, Prepare Evidence, ...` completes | A converted model in which every completed trace has `Prepare Evidence` before `Legal Review` | Yes |
| INV-4 | `Legal Review` is optional (`XOR` with a `SilentTransition`) | A completed trace with **zero** occurrences of `Legal Review` | A converted model where every completed trace contains `Legal Review` | Effect yes (presence/absence observable); the choice-node itself is not observable once tau is hidden |
| INV-5 | Verification cannot start until **both** `Assess Risk` and `Prepare Evidence` are done (join before loop) | Every completed trace has both predecessors before the first `Configure Trial` | A trace with `Configure Trial` before `Prepare Evidence` completes | Yes |
| INV-6 | `optional_legal` and `verification_loop` are unordered w.r.t. each other (no edge either direction) | Traces exist with `Legal Review` before **and** after `Configure Trial` | A converted model that forces the legal branch to fully resolve before any loop transition fires | Yes, but only provable from trace-set richness, not a single trace |
| INV-7 | Inside every iteration, `Configure Trial` strictly precedes `Inspect Trial` | Every iteration shows `Configure Trial, Inspect Trial` in that order | `Inspect Trial` before `Configure Trial` in the same iteration | Yes |
| INV-8 | Loop minimum iteration count = 1 (body is never skipped) | Shortest completed trace has exactly one `Configure Trial`/`Inspect Trial` pair | A completed trace with zero `Configure Trial` occurrences | Yes |
| INV-9 | Repeats are separated by `Correct Defect` (redo pattern `A (B A)*`) | `Configure Trial, Inspect Trial, Correct Defect, Configure Trial, Inspect Trial` | Two consecutive iterations without an intervening `Correct Defect` | Yes |
| INV-10 | `Release Change` waits for completion of **both** the optional-legal branch and the verification loop (join before release) | `Release Change` never fires while a redo is pending or the legal choice unresolved | `Release Change` immediately after `Register Change`/`Assess Risk` only | Yes (the join point itself is visible; "loop resolved" is only inferable behaviorally) |
| INV-11 | `Archive Change` strictly follows `Release Change` and is final | Every completed trace ends `..., Release Change, Archive Change` | `Archive Change` before `Release Change`, or trace ending elsewhere | Yes |

# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| **P1 (primary): POWL  accepting Petri net  BPMN** | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_bpmn(net, im, fm)` | Petri net construction from POWL is defined directly on the partial-order/XOR/LOOP semantics, so it is the best-supported, most literature-grounded translation; BPMN is generated from a *marked* net, not guessed | BPMN gateway synthesis from an unstructured/partially-ordered net may insert extra routing nodes or (worse) additional synchronization edges to keep the diagram "clean"; loss is structural/visual, not necessarily behavioral, but must be checked, not assumed | `convert_to_bpmn` raises, or round-trip validation (Section 5) shows a lost/added trace |
| **P2: POWL  accepting Petri net  process tree  BPMN** | `pm4py.convert_to_petri_net(...)`; `pm4py.convert_to_process_tree(net, im, fm)` (in `try/except`); `pm4py.convert_to_bpmn(tree)` | If it succeeds, gives a compact block-structured artifact that many BPM tools understand natively | Process trees can only express nested SEQ/XOR/AND/LOOP blocks with **symmetric** child dependencies. INV-3/INV-6 describe an *asymmetric* join (`optional_legal` depends on `Assess Risk` only; `verification_loop` depends on both `Assess Risk` and `Prepare Evidence`; the two branches are otherwise unordered) — this is a non-series-parallel ("rigid") fragment that a block-structured tree cannot represent without either adding a spurious dependency or dropping one | `convert_to_process_tree` raises an exception (expected/acceptable outcome), **or** it silently returns a tree that is not trace-equivalent to `net_from_powl` — a returned object is not proof of fidelity |
| **P3 (rejected as invented): POWL  BPMN directly** | *(no such public PM4Py call is documented for this task)* | N/A | N/A | Not attempted — inventing an undocumented direct conversion would violate the task constraint |

Primary pipeline: **P1**. P2 is retained only as a diagnostic probe of block-structuredness, and any output it produces is treated as provisional until validated.

# 3. Conversion Code

```python
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

# ---------------------------------------------------------------------------
# 0. Reconstruct the authoritative source POWL model exactly as specified.
# ---------------------------------------------------------------------------
register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(operator=Operator.XOR, children=[legal_review, skip_legal])

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(operator=Operator.LOOP, children=[trial_body, correct_defect])

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[register, assess_risk, prepare_evidence, optional_legal,
           verification_loop, release_change, archive_change]
)
source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)

pm4py.save_vis_powl(source_powl, "01_source_powl.png")

# ---------------------------------------------------------------------------
# 1. POWL -> accepting Petri net  (P1, step 1)
# ---------------------------------------------------------------------------
net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(source_powl)

if im_from_powl is None or fm_from_powl is None:
    raise RuntimeError("POWL -> Petri net conversion returned a null marking; "
                       "cannot proceed with soundness/round-trip analysis.")

pm4py.save_vis_petri_net(net_from_powl, im_from_powl, fm_from_powl, "02_net_from_powl.png")

# ---------------------------------------------------------------------------
# 2. Petri net -> BPMN  (P1, step 2)
# ---------------------------------------------------------------------------
try:
    bpmn_from_net = pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)
    pm4py.save_vis_bpmn(bpmn_from_net, "03_bpmn_from_net.png")
except Exception as e:
    bpmn_from_net = None
    print(f"[FAILURE] Petri net -> BPMN failed: {type(e).__name__}: {e}")

# ---------------------------------------------------------------------------
# 3. Petri net -> process tree attempt (P2, step 1) -- allowed to fail
# ---------------------------------------------------------------------------
tree_from_net = None
tree_conversion_error = None
try:
    tree_from_net = pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)
    pm4py.save_vis_process_tree(tree_from_net, "04_tree_from_net.png")
    print("[NOTE] process-tree conversion returned an object; this is NOT proof of "
          "semantic fidelity -- see Section 4/5 for required validation.")
except Exception as e:
    tree_conversion_error = e
    print(f"[EXPECTED-POSSIBLE FAILURE] Petri net -> process tree failed: "
          f"{type(e).__name__}: {e}")

# ---------------------------------------------------------------------------
# 4. Process tree -> BPMN (P2, step 2), only if step 3 produced a tree
# ---------------------------------------------------------------------------
bpmn_from_tree = None
if tree_from_net is not None:
    try:
        bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
        pm4py.save_vis_bpmn(bpmn_from_tree, "05_bpmn_from_tree.png")
    except Exception as e:
        print(f"[FAILURE] process tree -> BPMN failed: {type(e).__name__}: {e}")

# ---------------------------------------------------------------------------
# 5. BPMN -> accepting Petri net, for every BPMN artifact produced
# ---------------------------------------------------------------------------
def safe_bpmn_to_net(bpmn_model, label):
    if bpmn_model is None:
        print(f"[SKIP] {label}: no BPMN model available")
        return None, None, None
    try:
        net, im, fm = pm4py.convert_to_petri_net(bpmn_model)
        if im is None or fm is None:
            print(f"[WARNING] {label}: BPMN -> Petri net produced a null marking; "
                  f"treat as UNVALIDATED, do not assume markings exist.")
        return net, im, fm
    except Exception as e:
        print(f"[FAILURE] {label}: BPMN -> Petri net failed: {type(e).__name__}: {e}")
        return None, None, None

net_rt_from_net_bpmn, im_rt_from_net_bpmn, fm_rt_from_net_bpmn = safe_bpmn_to_net(
    bpmn_from_net, "bpmn_from_net -> net"
)
net_rt_from_tree_bpmn, im_rt_from_tree_bpmn, fm_rt_from_tree_bpmn = safe_bpmn_to_net(
    bpmn_from_tree, "bpmn_from_tree -> net"
)

if net_rt_from_net_bpmn is not None:
    pm4py.save_vis_petri_net(net_rt_from_net_bpmn, im_rt_from_net_bpmn, fm_rt_from_net_bpmn,
                              "06_net_roundtrip_from_net_bpmn.png")
if net_rt_from_tree_bpmn is not None:
    pm4py.save_vis_petri_net(net_rt_from_tree_bpmn, im_rt_from_tree_bpmn, fm_rt_from_tree_bpmn,
                              "07_net_roundtrip_from_tree_bpmn.png")

# ---------------------------------------------------------------------------
# 6. Workflow-net and soundness diagnostics on EVERY accepting net produced
# ---------------------------------------------------------------------------
all_nets = {
    "net_from_powl": (net_from_powl, im_from_powl, fm_from_powl),
    "net_rt_from_net_bpmn": (net_rt_from_net_bpmn, im_rt_from_net_bpmn, fm_rt_from_net_bpmn),
    "net_rt_from_tree_bpmn": (net_rt_from_tree_bpmn, im_rt_from_tree_bpmn, fm_rt_from_tree_bpmn),
}

diagnostics = {}
for name, (net, im, fm) in all_nets.items():
    if net is None:
        diagnostics[name] = {"status": "not available"}
        print(name, diagnostics[name])
        continue

    is_wfnet = pm4py.check_is_workflow_net(net)

    if im is None or fm is None:
        soundness_result = "skipped: null marking, soundness undefined without im/fm"
    else:
        try:
            soundness_result = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
        except Exception as e:
            soundness_result = f"soundness check raised {type(e).__name__}: {e}"

    diagnostics[name] = {"is_workflow_net": is_wfnet, "soundness": soundness_result}
    print(name, diagnostics[name])
```

# 4. Preservation and Loss Audit

| Source invariant | POWLPetri | PetriBPMN | PetriTree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| INV-1 initial activity | expected preserved | expected preserved | not tested (conversion may fail before reaching this) | expected preserved | Positive witnesses all start with `Register Change`; confirmed by trace search in Sec. 5 |
| INV-2 true concurrency (Assess Risk  Prepare Evidence) | validated preserved | expected preserved | ambiguous | ambiguous | Petri net gives genuine token-based concurrency (distinct places/arcs); BPMN AND-gateway conversion is *expected* to preserve interleaving-set equivalence, but true concurrency (independent execution) vs. arbitrary interleaving cannot be distinguished by trace-set tests alone — see Sec. 9 |
| INV-3 asymmetric join (optional_legal  Assess Risk only) | validated preserved (by construction of POWL semantics) | ambiguous | lost | ambiguous | This is the critical fragile invariant. A Petri-netBPMN gateway-matching algorithm may add a synchronization edge to keep gateways paired, which would silently turn the asymmetric dependency into a symmetric one. A process tree literally cannot express it (AND/XOR children share the same predecessor set) — expect `conversion failed` or an incorrect tree |
| INV-4 optional (silent) legal review | validated preserved | approximated | ambiguous | approximated | Silent transition survives in the Petri net; in BPMN it typically becomes an unlabeled gateway path (no visible task), which is a faithful *behavioral* encoding but a *visual* approximation (see Sec. 6) |
| INV-5 join before verification (Assess Risk  Prepare Evidence  loop) | validated preserved | expected preserved | ambiguous | not tested until round-trip check runs | Confirmed via negative witness search: no completed trace should show `Configure Trial` before both predecessors |
| INV-6 no order between optional_legal and verification_loop | validated preserved | ambiguous | lost | ambiguous | Same class of risk as INV-3; a block-structured tree would need to force an artificial AND/SEQ relation between the two branches |
| INV-7 Configure Trial before Inspect Trial | validated preserved | expected preserved | expected preserved (this sub-fragment alone is series-parallel) | expected preserved | Local sequence is trivially block-structured; low risk |
| INV-8 minimum one iteration (binary loop, non-skippable body) | validated preserved | approximated | approximated | approximated | POWL LOOP  Petri net encodes "body, then optional (redo, body)*"; BPMN visualizes this via a back-edge/gateway that can look like an arbitrary repeat-or-skip loop unless annotated — see Sec. 6 |
| INV-9 redo only via Correct Defect | validated preserved | expected preserved | approximated | expected preserved | Structurally forced by the net; BPMN back-edge should still route only through `Correct Defect`, but a generic loop icon can visually suggest a free repeat |
| INV-10 join before Release Change (legal branch  loop) | validated preserved | ambiguous | lost | ambiguous | Same asymmetric-join family as INV-3/6, mirrored on the merge side; must be checked with negative witnesses (no `Release Change` while a redo is pending) |
| INV-11 finality of Archive Change | validated preserved | expected preserved | not tested | expected preserved | End marking / end event should be single and reachable only after `Release Change` |
| Activity-label uniqueness | validated preserved | validated preserved | validated preserved (if tree exists) | validated preserved | All nine labels in `source_powl` are distinct strings; silent transitions carry label `None`. No duplicate-label collapse observed; this must still be explicitly checked after any BPMN edit tool touches the file |
| Initial/final markings | validated preserved (guarded in code) | not tested by default (BPMN has no native marking) | not tested | ambiguous | `im`/`fm` must be explicitly checked for `None` after each conversion, not assumed; BPMN start/end events are reconstructed heuristically on the way back to a Petri net |
| Gateway/routing-node ambiguity in BPMN visualization | not applicable | ambiguous | not applicable | ambiguous | Purely a rendering concern — see Sec. 6; behaviorally sound nets can still be visually misleading |

# 5. Round-Trip Validation Code

```python
import pm4py
from collections import deque
from pm4py.objects.petri_net import semantics as petri_semantics

# ---------------------------------------------------------------------------
# Footprints comparison
# ---------------------------------------------------------------------------
def safe_footprints(net, im, fm, label):
    if net is None or im is None or fm is None:
        print(f"[SKIP] footprints for {label}: missing net/markings")
        return None
    try:
        return pm4py.discover_footprints((net, im, fm))
    except Exception as e:
        print(f"[FAILURE] footprints for {label}: {type(e).__name__}: {e}")
        return None

fp_source = safe_footprints(net_from_powl, im_from_powl, fm_from_powl, "net_from_powl")
fp_rt_net_bpmn = safe_footprints(net_rt_from_net_bpmn, im_rt_from_net_bpmn,
                                  fm_rt_from_net_bpmn, "roundtrip(net->bpmn->net)")
fp_rt_tree_bpmn = safe_footprints(net_rt_from_tree_bpmn, im_rt_from_tree_bpmn,
                                   fm_rt_from_tree_bpmn, "roundtrip(tree->bpmn->net)")

def compare_footprints(fp_a, fp_b, name_a, name_b):
    if fp_a is None or fp_b is None:
        print(f"[NOT TESTED] footprint comparison {name_a} vs {name_b}: one side unavailable")
        return None
    diffs = {}
    for k in ("sequence", "parallel", "start_activities", "end_activities", "activities"):
        va, vb = fp_a.get(k), fp_b.get(k)
        if va != vb:
            diffs[k] = {
                "in_source_only": (va - vb) if isinstance(va, set) and isinstance(vb, set) else va,
                "in_target_only": (vb - va) if isinstance(va, set) and isinstance(vb, set) else vb,
            }
    print(f"Footprint diff {name_a} vs {name_b}: {diffs if diffs else 'no differences on checked keys'}")
    return diffs

compare_footprints(fp_source, fp_rt_net_bpmn, "net_from_powl", "roundtrip(net->bpmn->net)")
compare_footprints(fp_source, fp_rt_tree_bpmn, "net_from_powl", "roundtrip(tree->bpmn->net)")

# ---------------------------------------------------------------------------
# Reachability graph comparison (structural sanity, sizes only)
# ---------------------------------------------------------------------------
def safe_reachability(net, im, fm, label):
    if net is None or im is None or fm is None:
        print(f"[SKIP] reachability graph for {label}: missing net/markings")
        return None
    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        print(f"{label}: {len(rg.states)} states, {len(rg.transitions)} transitions")
        return rg
    except Exception as e:
        print(f"[FAILURE] reachability graph for {label}: {type(e).__name__}: {e}")
        return None

rg_source = safe_reachability(net_from_powl, im_from_powl, fm_from_powl, "net_from_powl")
rg_rt_net_bpmn = safe_reachability(net_rt_from_net_bpmn, im_rt_from_net_bpmn,
                                    fm_rt_from_net_bpmn, "roundtrip(net->bpmn->net)")
rg_rt_tree_bpmn = safe_reachability(net_rt_from_tree_bpmn, im_rt_from_tree_bpmn,
                                     fm_rt_from_tree_bpmn, "roundtrip(tree->bpmn->net)")

# ---------------------------------------------------------------------------
# Bounded, tau-hiding, visible-trace exploration
# ---------------------------------------------------------------------------
def bounded_visible_trace_search(net, im, fm, max_visible_steps=9, max_silent_run=3, max_states=50000):
    """
    Explores the marking graph up to explicit bounds.
    - Transitions with label None are hidden (fired but not recorded).
    - A trace is 'completed' only when the exact final marking fm is reached.
    - max_silent_run bounds consecutive silent firings (prevents infinite tau cycling).
    - max_visible_steps bounds visible trace length (bounds loop-iteration depth).
    Returns (completed_traces, states_explored, bound_exhausted).
    bound_exhausted=True means the bound was hit before the frontier was empty,
    i.e. the search is NOT a proof of exhaustive equivalence.
    """
    if net is None or im is None or fm is None:
        return set(), 0, True

    frontier = deque([(im, tuple(), 0)])
    visited = set()
    completed_traces = set()
    explored = 0
    bound_exhausted = False

    while frontier:
        marking, trace, silent_run = frontier.popleft()
        key = (marking, trace, silent_run)
        if key in visited:
            continue
        visited.add(key)
        explored += 1
        if explored > max_states:
            bound_exhausted = True
            break

        if marking == fm:
            completed_traces.add(trace)  # exact final-marking equality required

        for t in pm4py.get_enabled_transitions(net, marking):
            if t.label is None:
                if silent_run >= max_silent_run:
                    bound_exhausted = True
                    continue
                new_marking = petri_semantics.execute(t, net, marking)
                frontier.append((new_marking, trace, silent_run + 1))
            else:
                if len(trace) >= max_visible_steps:
                    bound_exhausted = True
                    continue
                new_marking = petri_semantics.execute(t, net, marking)
                frontier.append((new_marking, trace + (t.label,), 0))

    return completed_traces, explored, bound_exhausted

BOUND_VISIBLE_STEPS = 9
BOUND_SILENT_RUN = 3

traces_source, explored_source, exhausted_source = bounded_visible_trace_search(
    net_from_powl, im_from_powl, fm_from_powl, BOUND_VISIBLE_STEPS, BOUND_SILENT_RUN)
traces_rt_net_bpmn, explored_rt1, exhausted_rt1 = bounded_visible_trace_search(
    net_rt_from_net_bpmn, im_rt_from_net_bpmn, fm_rt_from_net_bpmn, BOUND_VISIBLE_STEPS, BOUND_SILENT_RUN)
traces_rt_tree_bpmn, explored_rt2, exhausted_rt2 = bounded_visible_trace_search(
    net_rt_from_tree_bpmn, im_rt_from_tree_bpmn, fm_rt_from_tree_bpmn, BOUND_VISIBLE_STEPS, BOUND_SILENT_RUN)

print(f"net_from_powl: {len(traces_source)} completed traces, bound_exhausted={exhausted_source}")
print(f"roundtrip(net->bpmn->net): {len(traces_rt_net_bpmn)} traces, bound_exhausted={exhausted_rt1}")
print(f"roundtrip(tree->bpmn->net): {len(traces_rt_tree_bpmn)} traces, bound_exhausted={exhausted_rt2}")

# ---------------------------------------------------------------------------
# Positive and negative witnesses
# ---------------------------------------------------------------------------
POSITIVE_WITNESSES = [
    ("Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Release Change", "Archive Change"),
    ("Register Change", "Prepare Evidence", "Assess Risk", "Legal Review", "Configure Trial",
     "Inspect Trial", "Release Change", "Archive Change"),
    ("Register Change", "Assess Risk", "Legal Review", "Prepare Evidence", "Configure Trial",
     "Inspect Trial", "Release Change", "Archive Change"),  # legal review before Prepare Evidence: INV-3
    ("Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Correct Defect", "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"),
]

NEGATIVE_WITNESSES = [
    ("Register Change", "Assess Risk", "Release Change", "Archive Change"),
    ("Register Change", "Assess Risk", "Prepare Evidence", "Release Change", "Archive Change"),
    ("Register Change", "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Assess Risk", "Release Change", "Archive Change"),  # verification before join: INV-5
    ("Register Change", "Assess Risk", "Prepare Evidence", "Inspect Trial", "Configure Trial",
     "Release Change", "Archive Change"),  # inspect before configure: INV-7
]

def audit_witnesses(name, traces, exhausted):
    print(f"--- witness audit: {name} (bound_exhausted={exhausted}) ---")
    for w in POSITIVE_WITNESSES:
        print(f"  POSITIVE {'FOUND' if w in traces else 'MISSING'}: {w}")
    for w in NEGATIVE_WITNESSES:
        print(f"  NEGATIVE {'ABSENT (OK)' if w not in traces else 'PRESENT (VIOLATION)'}: {w}")

audit_witnesses("net_from_powl", traces_source, exhausted_source)
audit_witnesses("roundtrip(net->bpmn->net)", traces_rt_net_bpmn, exhausted_rt1)
audit_witnesses("roundtrip(tree->bpmn->net)", traces_rt_tree_bpmn, exhausted_rt2)

print(
    "EXHAUSTIVENESS NOTE: this search is bounded (max_visible_steps, max_silent_run, max_states) "
    "and is therefore NOT an exhaustive equivalence proof between net_from_powl and any "
    "round-tripped net. A MISSING positive witness or a PRESENT negative witness inside the "
    "bound is conclusive evidence of a semantic divergence. The absence of such a finding is "
    "only evidence 'up to the bound', not a guarantee of full trace-language equivalence "
    "(in particular for iteration counts beyond the bound)."
)
```

# 6. Visual-Semantics Review

Even a Petri net that passes soundness and witness checks can be *rendered* in a way that invites a wrong reading:

- **Parallel (AND) gateways.** The BPMN converter must materialize the join of `Assess Risk` and `Prepare Evidence` before the loop, and (separately) the join before `Release Change`. If the gateway-matching algorithm reuses or merges routing nodes to keep the diagram "well-formed," it can visually — and possibly structurally — attach `Prepare Evidence` to the `optional_legal` branch as well, even though the source model has no such edge (INV-3/INV-6). A parallel gateway icon communicates "these paths must both complete here," which is correct for the loop join but **must not** be assumed correct for the legal-review branch without checking the underlying arcs.
- **Exclusive (XOR) gateways.** `optional_legal`'s XOR-with-silent-branch will typically render as an exclusive split/join pair where one outgoing branch has no task on it. A reader unfamiliar with silent transitions may interpret the empty branch as a modeling omission ("a task is missing here") rather than as "no activity occurs."
- **Loop visualization.** POWL's binary LOOP (`body, (redo, body)*`) is a specific redo pattern: repetition is *only* possible through `Correct Defect`. Many BPMN renderers depict any structural cycle with a generic loop marker or a back-pointing sequence-flow arrow, which looks identical to "repeat the whole loop body arbitrarily" or "possibly skip the body once." The **minimum-one-iteration** guarantee (INV-8) and the **mandatory Correct Defect on redo** guarantee (INV-9) are not visually distinguishable from a weaker while-loop unless the diagram is annotated.
- **Silent routing nodes.** The silent `skip_legal` transition has no natural BPMN task representation; it usually collapses into a gateway routing path with no attached activity. This is behaviorally correct but visually indistinguishable from "flow directly bypasses this section," which can be misread as a shortcut rather than a deliberate optional-skip semantics.
- **Layout-implied ordering.** Auto-layout engines commonly place nodes in a left-to-right or top-to-bottom reading order. `Assess Risk` may be drawn above/before `Prepare Evidence` purely because of graph-layout heuristics (e.g., node insertion order, id-based tie-breaking), which a stakeholder can misread as "Assess Risk happens first" even though the two are concurrent (INV-2). Layout order is **not** a semantic claim; only arcs and gateway types are.

**Mitigations:**
- Attach a machine-readable "invariant manifest" (the Section-1 table) to every BPMN export, referencing this document.
- Annotate the diagram: a text label on the loop back-edge stating "redo requires Correct Defect; minimum one Configure Trial/Inspect Trial pair required."
- Annotate the silent XOR branch explicitly as "No activity (Legal Review skipped)."
- Add a swim-lane or grouping visual cue (not a semantic gateway) to indicate "these two branches share no ordering constraint beyond their common predecessor," so viewers do not infer sequence from proximity.
- Never ship a BPMN diagram as the sole record of truth; always pair it with the soundness/witness report from Section 5.

# 7. Rejection Criteria

A conversion artifact (Petri net, BPMN, or process tree) must be **rejected or quarantined** if any of the following hold:

1. `pm4py.check_soundness(...)` returns `False`, or raises, for any round-tripped accepting net.
2. `pm4py.check_is_workflow_net(...)` returns `False` for a net that is expected to be a workflow net (single unambiguous source/sink structure required for soundness reasoning).
3. The bounded exploration (Section 5) finds a completed trace admitting `Release Change` before both `Configure Trial` and `Inspect Trial` have occurred in that run, or before the legal-review choice has resolved (violates INV-10/INV-5).
4. Any required positive witness (Section 5 list) is **MISSING** from a round-tripped net's completed-trace set within the bound (loss of concurrency, optionality, or a valid interleaving).
5. Any negative witness (Section 5 list) is **PRESENT** in a round-tripped net's completed-trace set (over-approximation / admission of forbidden behavior, e.g., release before verification).
6. Any conversion step returns a `None` initial or final marking that is then used downstream without an explicit guard/check (silent null-marking propagation).
7. Footprint comparison shows a `parallel` relation present in `net_from_powl` (e.g., `Assess Risk  Prepare Evidence`, or the absence of ordering between `optional_legal` and `verification_loop`) that has become a `sequence` relation (or vice versa) in a round-tripped net.
8. `pm4py.convert_to_process_tree(...)` raises an exception, **or** succeeds but the resulting tree's round-tripped net fails any witness/footprint/soundness check above — in either case the tree-based pipeline (P2) must not be promoted to canonical status.
9. Any conversion collapses two previously distinct labels onto the same string, or converts a distinct real activity into an unlabeled ("silent") node, making trace-based comparison ambiguous.
10. The bounded exploration cannot find **any** completed trace at all (positive or negative) within the configured bound for a supposedly sound net — this is inconclusive, not passing, and must be quarantined pending a larger bound or manual review.

# 8. Canonical Representation Recommendation

- **Authoritative/canonical model for storage:** `source_powl` (the POWL model itself). It is the only representation in this pipeline that natively expresses true concurrency, the asymmetric joins (INV-3, INV-6, INV-10), and the binary-loop redo pattern without approximation. All future business-logic edits (e.g., adding a new optional step, changing loop conditions) should be made by editing the POWL construction code, not by hand-editing a downstream artifact.
- **Model for stakeholder visualization:** the BPMN diagram produced by **P1** (`bpmn_from_net`), regenerated fresh from the current `source_powl` on every release, always accompanied by the annotations recommended in Section 6.
- **Derivative artifacts and required evidence:**
  - `net_from_powl` (Petri net): derivative of POWL, used for formal analysis. Must ship with: `check_is_workflow_net` result, `check_soundness` result, and the bounded witness/footprint report from Section 5.
  - `bpmn_from_net`: derivative of the Petri net. Must ship with: the BPMNPetri round-trip diagnostics (Section 3/4/5) and an explicit statement of which invariants were only "ambiguous" or "approximated" (Section 4), not silently dropped.
  - Process tree (if it is produced at all): must be labeled **experimental/non-canonical**, must never be used to regenerate BPMN for distribution, and must ship with the full exception log or, if it "succeeded," the complete witness comparison showing pass/fail per invariant (given the asymmetric-join structure identified above, it should generally be expected to fail Section 7's criteria for *this* source model).
- **Should a process-tree intermediate be allowed?** Not as a required or default step for this particular model. It may be attempted for diagnostic purposes (to demonstrate exactly which fragment is non-block-structured, useful for documentation/education), but its output must never be treated as authoritative and must not silently substitute for `bpmn_from_net` in pipeline P1.
- **Avoiding round-trip drift:** (a) regenerate all derivatives from `source_powl` on every change rather than patching BPMN/tree files by hand; (b) tag every derivative with a content hash/version of the exact POWL construction it came from; (c) re-run the full Section 5 validation suite on every regeneration and block promotion to "released" status on any Section 7 rejection condition; (d) if a BPMN diagram is manually edited by a stakeholder (e.g., in a BPMN editor), treat the edited file as a **new, untrusted source** requiring full re-import and re-validation against the original POWL invariants — never merge it back into `source_powl` without re-deriving the partial order explicitly.
