## 1. Normalization Assumptions

**True-time model.** For any source `clock_offset = recorded_clock - true_clock`. If `offset  [a,b]` then for any clock reading `c`, `true = c - offset  [c-b , c-a]`. Construction order:

1.  **Timestamp resolution**  clock interval `C = [c_low , c_high)` on the source's displayed time.
    * HUB UTC exact to second: `±0.5s`  `C=[t-0.5 , t+0.5]`
    * OPS-BER / VENDOR-NY / LEGACY-BER floor-to-minute `HH:MM`  `C=[HH:MM:00 , HH:MM+1:00)`
    * SENSOR round-nearest-10s `HH:MM:SS`  `C=[t-5 , t+5)`
    * MOBILE-LON round-nearest-minute `HH:MM`  `C=[HH:MM-30s , HH:MM+30s)`
2.  **Clock correction**  `True = [C_low - b , C_high - a)`.
3.  **Time-zone conversion**  to UTC after step 2. `Europe/Berlin` CEST UTC+2 (summer), `Europe/Berlin` CET UTC+1 (winter), `America/New_York` EDT UTC-4, `Europe/London` BST UTC+1. Library `zoneinfo` is used; DST rules are not re-invented.
4.  **DST fold 2025-10-26 (LEGACY-BER).** `02:00-02:59` occurs twice. No fold flag logged  each event generates **two alternative intervals**: `True_CEST = true_local -2h` and `True_CET = true_local -1h`. Ingestion order `Alert < Investigation_Start < Containment_Complete` is a causal constraint. Feasible set = union of alternatives **filtered** by existence of a tuple satisfying the order. If a whole alternative interval lies strictly before another, that combination is eliminated. Where intervals would partially overlap, the feasible set would be truncated; here combinations are disjoint, so filtering reduces to selecting the only globally consistent fold assignment.
5.  **SENSOR completion semantics.** Recorded `08:51:10` is a completion, not a start. No further adjustment; interval already represents when the completion occurred.
6.  **Inferred Investigation_Start T-404.** `Investigation_Complete - duration  [18min,25min]`. If `Complete_true  [Cc_low,Cc_high]` and `d  [1080,1500]` then `Start_true  [Cc_low -1500 , Cc_high -1080]`. Interval arithmetic preserves both sources of uncertainty.
7.  **Missing Alert_Received T-407.** `Alert_Received  Alert_Sent_true + [0,1200s]`. No acknowledgement  **weak evidence**. Optional causal assumption `Alert_Received  Investigation_Start` is *not* logged. Results are reported **without** and **with** the assumption; the former is primary.
8.  **MOBILE-LON entry delay T-406.** Up to 300s late entry *in addition* to `[-300,+300]` clock bound. Two semantic interpretations are separated:
    * **A - occurrence interpretation (primary):** user wrote time after event  occurrence = true_clock - entry_delay, `entry_delay  [0,300]`  `Occ = [True_low-300 , True_high)`. This shifts the estimate earlier.
    * **B - recording-lag interpretation:** delay is only record timestamp lag, occurrence = true_clock  `Occ = [True_low , True_high)`. Both are reported; A controls SLA S2 classification.

Midpoints are **never** substituted for intervals in primary analysis. A separate `midpoint-only` log is built in §5 purely for comparison with `pm4py.conformance_temporal_profile`.

**Evidence strength:**
* HUB: high trust, ±1s, ±0.5s resolution.
* SENSOR: medium, ±5s, ±5s resolution.
* OPS-BER with daily NTP: medium.
* VENDOR-NY external, no sync: low.
* LEGACY-BER / MOBILE-LON / OPS-BER without NTP (T-409): weak / low.
* Inferred / bounded latency (T-404,T-407): weak.

    fmt = "%Y-%m-%d %H:%M:%S" if len(local_naive_str)>16 else "%Y-%m-%d %H:%M"
    dt_naive = datetime.strptime(local_naive_str, fmt)
    tz = ZoneInfo(tz_name)
    # produce alternative aware datetimes for folds
    alternatives = []
    if is_dst_fold:
        for fold in [0,1]:  # 0=first (summer),1=second (winter)
            dt_aware = dt_naive.replace(tzinfo=tz, fold=fold)
            alternatives.append(dt_aware)
    else:
        # attach tz (no fold)
        dt_aware = dt_naive.replace(tzinfo=tz)
        # for summer dates zoneinfo resolves correctly without fold
        alternatives = [dt_aware]
    out = []
    a,b = offset_bounds
    for dt_aware in alternatives:
        c_low_local = dt_aware
        # floor vs round handled by caller; here floor: c_high = c_low + 60s or 30s etc
        # This helper assumes floor 60s; callers override for round cases
        c_high_local = dt_aware + timedelta(seconds=60) - timedelta(microseconds=1)
        # clock interval to true interval: [c_low - b , c_high - a]
        true_low_local = c_low_local - timedelta(seconds=b)
        true_high_local = c_high_local - timedelta(seconds=a) + timedelta(microseconds=1)
        # to UTC
        true_low_utc = true_low_local.astimezone(timezone.utc).replace(tzinfo=None)
        true_high_utc = true_high_local.astimezone(timezone.utc).replace(tzinfo=None)
        out.append((true_low_utc, true_high_utc))
    return out

# specific helpers
def normalize(row):
    sys=row.system; rec=row.recorded; tz=row.tz
    if sys=="HUB":
        dt = datetime.strptime(rec, "%Y-%m-%d %H:%M:%S").replace(tzinfo=timezone.utc)
        low,high = hub_interval(dt.replace(tzinfo=None))
        # make UTC naive
        return [(low, high)]
    if sys=="SENSOR": # round 10s UTC
        dt = datetime.strptime(rec, "%Y-%m-%d %H:%M:%S").replace(tzinfo=timezone.utc)
        c_low = dt - timedelta(seconds=5)
        c_high = dt + timedelta(seconds=5)
        a,b = -5,5
        low = (c_low - timedelta(seconds=b)).replace(tzinfo=None)
        high = (c_high - timedelta(seconds=a)).replace(tzinfo=None)
        return [(low,high)]
    if sys=="OPS-BER" and "weak" not in str(row.notes):
        # floor 60s, offset [-90,120], CEST UTC+2
        return floor_interval_local_to_utc(rec, "Europe/Berlin", (-90,120))
    if sys=="OPS-BER" and "weak" in str(row.notes):
        return floor_interval_local_to_utc(rec, "Europe/Berlin", (-720,720))
    if sys=="VENDOR-NY":
        return floor_interval_local_to_utc(rec, "America/New_York", (-180,180))
    if sys=="LEGACY-BER":
        return floor_interval_local_to_utc(rec, "Europe/Berlin", (-60,60), is_dst_fold=True)
    if sys=="MOBILE-LON":
        # round nearest minute -> c_low = t-30s, c_high=t+30s, offset [-300,300] plus entry delay handled separately
        dt_naive = datetime.strptime(rec, "%Y-%m-%d %H:%M")
        tz = ZoneInfo("Europe/London")
        dt_aware = dt_naive.replace(tzinfo=tz) # BST
        c_low = dt_aware - timedelta(seconds=30)
        c_high = dt_aware + timedelta(seconds=30)
        a,b = -300,300
        true_low = c_low - timedelta(seconds=b)
        true_high = c_high - timedelta(seconds=a)
        # to UTC
        tl_utc = true_low.astimezone(timezone.utc).replace(tzinfo=None)
        th_utc = true_high.astimezone(timezone.utc).replace(tzinfo=None)
        # occurrence interpretation A: subtract entry delay [0,300]
        occ_low = tl_utc - timedelta(seconds=300)
        occ_high = th_utc  # max entry 0
        # return both interpretations as tuple (record interval, occurrence interval)
        return [(tl_utc, th_utc), (occ_low, occ_high)]  # index 0=B,1=A
    return []

def classify(duration_iv, limit, two_sided=None):
    # one-sided SLA vs two-sided profile band
    lo,hi = duration_iv
    if two_sided:
        b_lo,b_hi = two_sided

        return "POSSIBLE_VIOLATION"

## 7. Governance Recommendation

**Storage & resolution**
* Store all events in UTC (`timestamptz`) and retain the raw local string + zone + fold flag + resolution metadata (`floor|round|exact|inferred`). Never overwrite raw with normalized.
* Require at least second precision for SLA-relevant activities; minute-floor sources must be labeled low-trust and not used for 15-min SLA enforcement without ±30s sync proof.
* For rounding sources, log `precision` (e.g., `10s`, `60s`) to allow correct interval reconstruction; forbid silent midpoint substitution.

**Clock & telemetry**
* Mandate continuous offset telemetry (NTP/PTP) per source with per-hour `[-a,b]` bounds persisted. Missing telemetry during an incident = automatic **INDETERMINATE**, not PASS. Retain diagnostics for audit.
* HUB/SENSOR remain high-trust reference; external VENDOR/MOBILE require out-of-band sync (e.g., HUB receipt proxy) for SLA use.
* Define entry-delay policy: capture `occurrence_time` and `recorded_time` as distinct fields; document that entry delay shifts occurrence estimate (interpretation A) for legal analysis.

**Lifecycle & semantics**
* Emit both **start** and **complete** for investigations; if only complete exists, duration attestation must be cryptographically signed and narrow (<2min) to be usable.
* DST: persist `fold` (0/1) and `offset` at event time; store UTC instantly via `zoneinfo`. On 25-26 Oct, enforce UTC storage and reject ambiguous local-only ingestion.
* Causal identifiers: `alert_id` propagated AlertInvestigationContainment; ingestion order is not a substitute for causal timestamp proof. `Alert_Sent  Alert_Received` – require ack.

**Enforcement policy**
* SLA enforcement uses **interval overlap**, but overlap is **insufficient** for violation: **POSSIBLE_VIOLATION** is not a breach; it triggers evidence uplift (request sync logs, re-query). Only **CERTAIN_VIOLATION** (feasible interval wholly outside limit) is legally enforceable. **INDETERMINATE** = pause enforcement, request evidence per §6.
* Publish SLA tolerances: strict (0) for reporting, +2min operational grace for minor clock skew, +5min only with documented approval; sensitivity matrix (§4) must accompany any enforcement report.
* Temporal-profile conformance is statistical: report =2 primary, =1/3 sensitivity, and distinguish from SLA. A profile violation does not imply SLA breach.

This regime makes timestamp uncertainty explicit, preserves disjoint DST intervals, avoids lossy midpoints in authoritative decisions, and ties escalation to evidence strength rather than point estimates.
