# 1. Assumptions and notation

**A1 – Event-order convention.** For any two rounded timestamps that could overlap within ±2.5 min, the process sequence is enforced: arrival  S1 start  S1 end  S2 start  S2 end, with a minimal inter-case gap of ~5 min observed on every resource schedule. Where rounding creates an apparent resource conflict (e.g. two cases on I1 within 5 min), the conflict is treated as a logging/rounding artifact, not as true parallel execution.

**A2 – Rounding treatment.** Every reported time *t* represents an interval [*t*2.5, *t*+2.5] min. Any derived duration (wait, service, sojourn) therefore carries an uncertainty of ±5 min on the endpoints and ±5 min on the difference if both endpoints are uncertain; when only one endpoint is uncertain the duration uncertainty is ±2.5 min.

**A3 – Capacity and assignment.** S1 has two single-task resources I1 and I2; S2 has C1 and C2. The data show strict round-robin assignment by arrival order (I1/I2/I1/I2…), so each resource carries its own ordered sub-queue. C2 is forced unavailable 10:55–11:10.

**A4 – Queue entry convention.** A case enters the S1 queue at `arrival_s1`. It enters the S2 queue immediately upon `s1_end`. Blank cells mean “not observed / not started”; they are not zeros.

**A5 – Missing-start imputation (interval logic).** For a missing S1 or S2 start we do not substitute a single value. Instead we derive a feasible start window from:
  - previous case end on the same resource,
  - next case start on the same resource,
  - the known end of the current case,
  - non-negativity of service time,
  - the observed station-specific service-time range (I1 20–35 min, I2 25–30 min, C1 25–45 min, C2 30–50 min).

The lower/upper wait estimates come from pairing the earliest/latest feasible start with the rounded arrival/end bounds.

**A6 – Open (right-censored) activities.** For an `OPEN` case the elapsed service time by 14:00 is a lower bound (`14:00  start`). Final service time is unknown; we report the lower bound and a plausible upper bound drawn from the observed service distribution at that station.

**A7 – Blank S2 start/end for completed S1.** This is interpreted as “waiting for S2 at 14:00”. Service time is zero; wait is at least `14:00  s1_end`.

**A8 – Little’s Law applicability.** We apply it only where arrivals and departures are approximately constant and there is no right-censoring inside the interval. Here the 12:00–13:00 S2 window is the closest defensible slice (arrivals  departures  3 cases, all starts/ends observed except open cases excluded).

**A9 – Censoring flags.** `COMPLETE_WITH_MISSING_START` = full path observed except one missing start timestamp. `OPEN_IN_S2` / `OPEN_IN_S1` = right-censored at 14:00. `WAITING_FOR_S2` / `WAITING_FOR_S1` = queue present at 14:00 with zero observed service.

**A10 – Data coverage.** Because all times are rounded and some starts are missing, any point estimate is a midpoint of a defensible interval; ranges are reported wherever a single value would overstate certainty.

# 2. Reconstruction method and formulas

For each case *c*:

- `S1_wait` = `s1_start`  `arrival_s1` (with bounds when `s1_start` is imputed or rounded)
- `S1_service` = `s1_end`  `s1_start`
- `S1_sojourn` = `s1_end`  `arrival_s1`
- `S2_wait` = `s2_start`  `s1_end`
- `S2_service` = `s2_end`  `s2_start`
- `S2_sojourn` = `s2_end`  `s1_end`
- `Total_sojourn_complete` = `s2_end`  `arrival_s1`

**Bounds for missing starts** (example P05, P07, P11, P15):
1. Compute resource-available window from adjacent completed cases on the same resource.
2. Compute start window = [`end_prev` + gap, `start_next`  gap] intersected with [`end_case`  max_service, `end_case`  min_service`].
3. Wait range = [`start_lower`  `arrival_upper`, `start_upper`  `arrival_lower`].
4. Service range = [`end_lower`  `start_upper`, `end_upper`  `start_lower`].

**Station-level WIP at time *t***:
- S1 WIP(*t*) = #{arrived  *t* and (`s1_end` > *t* or (`s1_start` > *t* and `s1_end` missing/open))}
- S2 WIP(*t*) = #{`s1_end`  *t* and (`s2_end` > *t* or (`s2_start` > *t* and `s2_end` missing/open))}

**Queue length** = WIP  number in service (count of cases with start  *t* < end).

**Arrival rate** (*I*) = arrivals in interval *I* / |*I*|.
**Departure rate** (*I*) = completed services in *I* / |*I*|.

**Utilization** *U* = (service durations in *I*) / (resource_count × |*I*| × availability_factor), where availability_factor = 1 for I1/I2, and (|*I*|  15 min)/|*I*| for C2 during windows that include 10:55–11:10.

**Little’s Law check** (only for defensible sub-intervals):
*L*   × *W*, where *W* is mean observed wait in that interval.

**Evidence.**

**Hypotheses vs. evidence.**
- The round-robin assignment (A4) is an inference, not a documented rule, but it is the only assignment that reproduces the observed sequential resource schedules with 5-min gaps. If assignment were random, the same queue lengths could arise, but the resource-level schedules would differ; the data do not support random assignment.
- The imputed start windows for P07, P15, P05, P11 depend on assuming observed service-time ranges hold for these cases. If P07 had an unusually short service (e.g., 15 min), its wait could shrink by ~10 min; this is captured in the ranges.

**Time-varying bottleneck.**
- 08:00–09:30: Both stations start empty; queue builds slowly. No clear bottleneck yet.
- 09:30–11:00: C2 maintenance and long C2 services cause S2 delays; P08 waits ~55 min after maintenance. S2 is the dominant bottleneck.
- 11:00–14:00: S1 also becomes severely backlogged (waits reach 100+ min for P16–P22). This is not because S1 is slower, but because the upstream arrival rate (~5/h in the morning) exceeds the system exit rate (~2.5–3/h set by S2). Thus the *system* bottleneck is S2, but S1 exhibits the symptomatic queue growth because it receives arrivals faster than the downstream station can absorb them.

# 6. Missingness, censoring, and sensitivity analysis

We compare three explicit scenarios for the missing/open cases.

| scenario | imputation / censoring rule | effect on key metrics |
|---|---|---|
| **Optimistic (O)** | Missing starts at earliest feasible time; open cases finish with minimal plausible service (P15=30, P17=30, P21=30); rounding errors reduce durations by 2.5 min. | P07 wait 35, P15 wait 85, P11 wait 50. S1 late-interval mean wait 90; S2 mean wait 45. Utilization S1 0.80, S2 0.80. |
| **Central (C)** | Midpoint of feasible windows; open cases continue with median observed service; rounding midpoint used. | Values reported in Sections 3–4. P07 wait 48, P15 wait 97, P11 wait 55. Utilization S1 0.88, S2 0.85. |
| **Pessimistic (P)** | Missing starts at latest feasible time; open cases have long service (P15=50, P17=50, P21=50); rounding extends durations by 2.5 min. | P07 wait 60, P15 wait 110, P11 wait 60. S1 late-interval mean wait 110; S2 mean wait 65. Utilization S1 0.93, S2 0.92. |

**Stable conclusions (all scenarios agree):**
1. Both stations are highly utilized (>75% in every scenario; >80% in central/pessimistic).
2. S2 has longer average service and is the tighter system constraint.
3. The C2 maintenance gap (10:55–11:10) is visibly present in the resource schedule regardless of imputation.
4. Queue lengths grow after 10:00 for both stations; by 14:00 S2 holds at least 5 cases and S1 holds at least 2.

**Unstable conclusions (scenario-sensitive):**
1. Exact wait times for P07, P11, P15 vary by ±15–20 min.
2. Peak S1 queue length varies between ~6 (optimistic) and ~8 (pessimistic) around 13:00 because P15/P21 start/service windows shift.
3. Precise utilization of I1 and C1 depends on the imputed lengths of P07 and P15; ranges span about ±0.08.
4. Any Little’s-Law point estimate is fragile because arrival/departure rates are not stationary across the 6-hour window; we therefore report it only as a consistency check in 10:00–12:00 with explicit bounds, not as a definitive value.
