Shared mechanisms include the AND-join into Assessment: both identity and document verification must finish before assessment, so any *true* reduction in the verification phase makespan (max of the two paths rather than sum) can shorten waiting before assessment and thereby cycle time. Independence of identity work from document content is plausible on both sites for purely digital files, so the partial-order idea is not site-bound.

Site-specific mechanisms dominate elsewhere. Originals receipt is a statutory and exogenous delay at B for most cases; parallel “Document Check” cannot start until originals arrive. Legal review and supplement loops exist only as a first-class path at B and couple document capacity to post-assessment rework. Role specialization and case locking at B break A’s assumption that one cross-trained reviewer (or dual ownership) can advance both checks. A’s before/after also bundled API latency reduction, +2 document FTE, mix shift, and huddles—selection and co-intervention nodes that do not travel with the control-flow change.

Effect modifiers are originals_required, digital_documents, IT_case_lock, role_specialization, legal/assessment capacity, and case_complexity. A similar-looking process tree (Register then both checks then Assessment) does not guarantee transportability because transport requires stable causal mechanisms and comparable distributions of modifiers; B’s mandatory partial order, thin specialized pools, and confounded evidence at A mean the *diagram* can match while the *effect* does not.

## 6. Candidate Site B intervention

**Eligibility rules**
- Stratum D (digital / originals not legally required): after `Register`, create `Identity Check` and `Document Check` concurrently.
- Stratum O (originals required): after `Register`, create `Identity Check` and `Originals Receipt` concurrently; create `Document Check` only when originals are received (or statutory waiver recorded).
- Stratum L flag (public-sector/high-value): no change to legal obligation; `Legal Review` still after `Assessment` when required.
- Exclude from concurrency expansion (initial pilot): cases already in supplement loop, or explicit fraud hold.

**Concurrency and statutory prerequisites**
- Mandatory: `Document Check`  start before originals when legally required; `Assessment` waits for both ID and Doc complete; `Legal Review` when policy requires; `Approve`/`Reject` then `Notify`.
- Allowed concurrency: ID  Doc on Stratum D; ID  Originals Receipt on Stratum O; never Doc  before originals on O.

**Queue and WIP controls**
- Per-role open verification caps (e.g., ID 6, Doc 6 open tasks per reviewer analog to A).
- Daily queue huddles as an explicit co-practice, instrumented separately.
- Priority: `Request Supplement` Doc rework  aged cases &gt; new first-pass.

**Resource responsibilities**
- Keep specialized roles; do not assume cross-training for go-live.
- Assignment engine offers parallel tasks only to different role pools (or dual-own subtasks).

**Legal-review and supplement loops**
- `Legal Review`  `Approve`/`Reject` or `Request Supplement`  `Document Check` (and re-`Assessment` as today).
- Supplements do not auto-create a new parallel ID unless identity is re-challenged.

**Logging**
- System-enforced task start/complete timestamps; two active owners allowed for ID and Doc on same case; flag back-entry &gt;15 min; store eligibility stratum and originals-required flag.

**POWL-style partial order (candidate)**  
```text
POWL Site B candidate:
  XOR_eligibility(
    Digital:  StrictPartialOrder({Register, ID, Doc, Assessment, XOR_dec1(Approve, Reject), Notify};
      edges: RegisterID, RegisterDoc, IDAssessment, DocAssessment,
             AssessmentXOR_dec1, XOR_dec1Notify),
    Originals: StrictPartialOrder({Register, ID, OriginalsReceipt, Doc, Assessment, XOR_dec2(Approve, Reject), Notify};
      edges: RegisterID, RegisterOriginalsReceipt, OriginalsReceiptDoc,
             IDAssessment, DocAssessment, AssessmentXOR_dec2, XOR_dec2Notify)
  )
  After Assessment (both strata): XOR(
      skip_legal to decision,
      LOOP(LegalReview, RequestSupplement  DocumentCheck  Assessment  LegalReview)
  )  # loop body simplified: supplement re-enters Doc then Assessment then Legal
```
Compact relation set (core):  
`Register  ID`; `Register  (Doc | OriginalsReceipt)`; `OriginalsReceipt  Doc` when required; `{ID, Doc}  Assessment`; `Assessment  (LegalReview | Decision)`; `LegalReview  (Decision | Supplement)`; `Supplement  Doc`; `Decision  Notify`.

| Duration | 10–14 weeks steady state + 90d appeal follow-up | Capture tail and appeals | — | cohort windows |
| Stop rules | Appeals +1.5pp or rework +3pp vs control; IT lock compliance &lt;50% true dual-start; Assessment wait +50% | Safety and futility | Auto-pause dual-create | dashboards |
| Transportability analysis | Stratum-specific CATE; mediator true_overlap; modifier interactions (complexity, legal flag); compliance-adjusted | External validity to full B | Pre-specify estimators | gated outcomes by S_ nodes |

The pilot separates **mechanism failure** from **implementation failure** by measuring compliance mediators before judging outcomes. Implementation fidelity is true dual ownership, live timestamps, and legally correct task creation (no Doc before originals). If fidelity is high but wait-before-assessment and cycle time do not improve in Stratum D, the mechanism fails under B’s capacities (bottleneck shift, specialization). If outcomes look flat while overlap remains low and lock bypass/back-entry dominate, the failure is implementation/IT—not transport of the causal idea. Factorial or staged addition of huddles prevents A-style co-intervention confounding. Stratum O tests only IDOriginals, so null results there do not condemn digital parallelization. Pre-fixed staffing and marketing freeze block A’s confounds from reappearing as false “transport success.”

## 8. PM4Py model-construction code

```python
"""
Site A before/after process trees + Site B POWL candidate.
Requires pm4py with process tree, POWL, Petri net, soundness utilities.
"""

import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

# ---------------------------------------------------------------------------
# 1) Site A before / after as process trees
# ---------------------------------------------------------------------------
# Before: strict sequence Register -> ID -> Doc -> Assessment -> (Approve XOR Reject) -> Notify
tree_a_before = pm4py.parse_process_tree(
    "->('Register', 'Identity Check', 'Document Check', 'Assessment', "
    "X('Approve', 'Reject'), 'Notify')"
)

# After: Register -> (ID || Doc) -> Assessment -> XOR -> Notify
tree_a_after = pm4py.parse_process_tree(
    "->('Register', +('Identity Check', 'Document Check'), 'Assessment', "
    "X('Approve', 'Reject'), 'Notify')"
)

# ---------------------------------------------------------------------------
# 2) Convert Site A trees to accepting Petri nets
# ---------------------------------------------------------------------------
net_a_before, im_a_before, fm_a_before = pm4py.convert_to_petri_net(tree_a_before)
net_a_after, im_a_after, fm_a_after = pm4py.convert_to_petri_net(tree_a_after)

print("Site A BEFORE workflow net:", pm4py.check_is_workflow_net(net_a_before))
print("Site A AFTER  workflow net:", pm4py.check_is_workflow_net(net_a_after))
try:
    print("Site A BEFORE soundness:", pm4py.check_soundness(net_a_before, im_a_before, fm_a_before))
    print("Site A AFTER  soundness:", pm4py.check_soundness(net_a_after, im_a_after, fm_a_after))
except Exception as e:
    print("Soundness check note (A):", e)

# ---------------------------------------------------------------------------
# 3–5) Site B candidate POWL: digital vs originals paths, legal + supplement loop
# ---------------------------------------------------------------------------
Register = Transition(label="Register")
ID = Transition(label="Identity Check")
Doc = Transition(label="Document Check")
Orig = Transition(label="Originals Receipt")
Assess = Transition(label="Assessment")
Legal = Transition(label="Legal Review")
Supp = Transition(label="Request Supplement")
Approve = Transition(label="Approve")
Reject = Transition(label="Reject")
Notify = Transition(label="Notify")
skip_legal = SilentTransition()  # non-legal path after assessment path choice

# Decision XOR after assessment/legal
xor_decision = OperatorPOWL(operator=Operator.XOR, children=[Approve, Reject])

# Supplement loop body: Request Supplement then Document Check then Assessment then Legal again
# LOOP semantics: do Legal, then optionally (Supp -> Doc -> Assess) and repeat Legal, else exit
loop_body = StrictPartialOrder(nodes=[Supp, Doc, Assess])
loop_body.order.add_edge(Supp, Doc)
loop_body.order.add_edge(Doc, Assess)
legal_loop = OperatorPOWL(operator=Operator.LOOP, children=[Legal, loop_body])

# After verification+assessment core, either skip legal or enter legal loop
post_assess_xor = OperatorPOWL(operator=Operator.XOR, children=[skip_legal, legal_loop])

# --- Digital stratum partial order: Register, ID || Doc, then Assessment ---
# Build digital block as PO with Register  ID, Register  Doc, ID  Assess, Doc  Assess
digital_core = StrictPartialOrder(nodes=[Register, ID, Doc, Assess, post_assess_xor, xor_decision, Notify])
digital_core.order.add_edge(Register, ID)
digital_core.order.add_edge(Register, Doc)
digital_core.order.add_edge(ID, Assess)
digital_core.order.add_edge(Doc, Assess)
digital_core.order.add_edge(Assess, post_assess_xor)
digital_core.order.add_edge(post_assess_xor, xor_decision)
digital_core.order.add_edge(xor_decision, Notify)

# --- Originals stratum: Register, ID || Orig, Orig  Doc, {ID, Doc}  Assess ---
Register_o = Transition(label="Register")
ID_o = Transition(label="Identity Check")
Doc_o = Transition(label="Document Check")
Orig_o = Transition(label="Originals Receipt")
Assess_o = Transition(label="Assessment")
Legal_o = Transition(label="Legal Review")
Supp_o = Transition(label="Request Supplement")
Approve_o = Transition(label="Approve")
Reject_o = Transition(label="Reject")
Notify_o = Transition(label="Notify")
skip_legal_o = SilentTransition()

xor_decision_o = OperatorPOWL(operator=Operator.XOR, children=[Approve_o, Reject_o])
loop_body_o = StrictPartialOrder(nodes=[Supp_o, Doc_o, Assess_o])
# Note: Doc_o/Assess_o nodes reused carefully — for LOOP body use dedicated transitions
Supp_o_b = Transition(label="Request Supplement")
Doc_o_b = Transition(label="Document Check")
Assess_o_b = Transition(label="Assessment")
loop_body_o = StrictPartialOrder(nodes=[Supp_o_b, Doc_o_b, Assess_o_b])
loop_body_o.order.add_edge(Supp_o_b, Doc_o_b)
loop_body_o.order.add_edge(Doc_o_b, Assess_o_b)
legal_loop_o = OperatorPOWL(operator=Operator.LOOP, children=[Legal_o, loop_body_o])
post_assess_xor_o = OperatorPOWL(operator=Operator.XOR, children=[skip_legal_o, legal_loop_o])

originals_core = StrictPartialOrder(
    nodes=[Register_o, ID_o, Orig_o, Doc_o, Assess_o, post_assess_xor_o, xor_decision_o, Notify_o]

originals_core.order.add_edge(Register_o, ID_o)
originals_core.order.add_edge(Register_o, Orig_o)
originals_core.order.add_edge(Orig_o, Doc_o)          # statutory: originals before doc check
originals_core.order.add_edge(ID_o, Assess_o)
originals_core.order.add_edge(Doc_o, Assess_o)         # Assessment waits for BOTH
originals_core.order.add_edge(Assess_o, post_assess_xor_o)
originals_core.order.add_edge(post_assess_xor_o, xor_decision_o)
originals_core.order.add_edge(xor_decision_o, Notify_o)
```

## 9. Recommendation

**conditional go**

Transfer the *structural idea* only where Site B can legally and operationally start both verification activities: concurrent `Identity Check` with `Document Check` for digital / non-originals cases, and concurrent `Identity Check` with `Originals Receipt` (not Document Check) when originals are required. Preserve the Assessment AND-join, specialized roles, and the entire Legal Review / Request Supplement loop. Do **not** copy Site A’s blanket “create Identity and Document tasks simultaneously for every case,” A’s before/after nine-hour median as a promised effect, cross-training assumptions, or unseparated co-interventions (API upgrade, extra FTE, marketing-driven mix shift). Huddles and numeric WIP caps may be adopted as explicit, instrumented companions—not silently bundled.

First entrant subgroup: **Stratum D (originals not required)**, ideally simpler non-legal cases, under dual-ownership IT or an approved live-timestamp workaround. This is where A’s mechanism (makespan = max(ID, Doc)) is most analogous. Expand to IDOriginals on Stratum O only after fidelity is proven. Leave high-value/legal-heavy cohorts until Assessment and Legal queues show slack.

Expected benefits: roughly 2 to 5h median cycle in a well-run segmented design (larger inside digital stratum), modest p90 improvement if originals delay already masks ID, and better use of ID idle time during originals wait. Risks: cosmetic parallelization under case lock; Doc/Assessment/Legal bottleneck shift with **median down but p90 up**; supplement traffic colliding with newly parallel first-pass work; slight rework/appeal creep; false KPIs from back-entry.

Expand if the pilot shows high compliance (true overlap, legal task ordering), median and wait-before-assessment gains in Stratum D without p90 or rework breaches, and stable Assessment/Legal utilization. Modify if IT lock kills true concurrency (fix dual-own) or if Assessment wait absorbs all gains (throttle or capacity). Abandon blanket parallelization if fidelity is high yet eligible-stratum effects are null and quality worsens—or if statutory interpretation forbids even digital dual-start. Re-estimate transport only with stratum-specific effects, not A’s confounded headline delta.

## 10. Assumption register

1. **Identity work does not require original-document content for most cases** — needed to justify starting ID in parallel with originals receipt or digital Doc — test via SME audit and exception rates when ID precedes originals — if false, parallel ID creates rework and the hybrid O design fails.

2. **Digital / non-originals share is large enough (~30%+) and identifiable at registration** — needed for a powered first stratum — test with flag quality and baseline volume — if false, pilot underpowered and portfolio benefit negligible.

3. **True dual task ownership (or equivalent) can be enabled for the pilot** — needed so treatment is not illusory under legacy lock — test with simultaneous active-owner events and stamp lag audits — if false, prefer IT fix before process scale-up; else no-go on full copy.

4. **Site A’s median 9h is confounded; portable effect is only a fraction via verification makespan** — needed to set realistic expectations and MDE — test with B pilot RCT/stepped-wedge under frozen staff/mix — if false (A was nearly pure treatment), B digital effects may be larger than forecast but still modifier-bound.

5. **Assessment (3) and Legal (2) capacity will not immediately erase upstream gains under segmented load** — needed for net cycle-time benefit — test Assessment/Legal queue time and utilization in pilot dashboards — if false, expect bottleneck-shift scenario (median, p90) and throttle release.

7. **Overlap and cycle metrics can be measured with reliable live timestamps** — needed for transport learning vs false success — test stamp-vs-real lag sample — if false, pause outcome-based scale decisions until instrumentation works.

8. **Statutory ordering (originals before Doc when required; Legal when flagged) remains non-negotiable** — needed for compliant intervention design — test with conformance checking on pilot log — if “false” only via legal change (out of scope), any design that violates remains no-go; if flags are wrong, eligibility misclassification biases CATE.
