# 1. Assumptions, objectives, and decision variables

**Demand and Service Assumptions**
-   **Arrival Process**: Arrivals within a 2-hour block are distributed uniformly across the block for simulation purposes, though in reality they may cluster. Total arrivals per block are fixed by the demand table.
-   **Service Time Distribution**: Ranges (Min-Max) are modeled as Triangular distributions $(min, mode, max)$ where $mode$ is the midpoint of the range. For "Complex-tail" cases (probability $p$), the range is replaced by the complex range (e.g., Intake 10-14 mins).
-   **ME/ES Branching**:
    -   **Parallel**: Selected if Case Priority is P1 AND at least 2 qualified resources are idle at the moment of Diagnostic start. Coordination penalty (8 min) applies before Validation.
    -   **Sequential**: Default for P2/P3 or if resources are constrained. No coordination penalty.
-   **Preemption**: Only P1 cases can preempt P2/P3. A case is preempted if a P1 case arrives and the resource is busy with a lower priority. The penalty is applied to the remaining service time of the interrupted case. Max 1 preemption per case.
-   **Handovers**: 7 minutes added if the resource changes between Intake, Diagnostic, and Validation. 5 minutes added if switching between Mechanical and Electrical/Software teams (unless same cross-skilled resource). 5 minutes setup if resource switches skill family between consecutive cases.

**Objective Formulations**
1.  **SLA Risk Minimization (Primary)**: Maximize the weighted percentage of cases meeting their priority-specific SLA targets.
    $$ \text{Score}_{SLA} = 0.5 \cdot \mathbb{I}(P1 \le 120m) + 0.3 \cdot \mathbb{I}(P2 \le 8h) + 0.2 \cdot \mathbb{I}(P3 \le 24h) $$
    *Rationale*: P1 cases represent critical technical incidents; failure here has the highest business impact.
2.  **Fairness and Robustness (Secondary)**: Minimize the standard deviation of resource utilization across the shift, penalizing utilization > 90%.
    $$ \text{Score}_{Fair} = - \text{StdDev}(\text{Utilization}_r) - \sum_r \max(0, \text{Util}_r - 0.9) \cdot \text{Penalty} $$
    *Rationale*: Prevents burnout on specific resources (e.g., Farah or Ada) and ensures the system remains stable under load shocks.

**Decision Variables**
-   Routing policy (Specialized vs. Pooled vs. Hybrid).
-   Parallelism trigger (P1-only vs. Always).

# 5. Robust recommendation

# 6. Secondary effects and implementation risks

-   **Gaming**: Resources may claim "Complex-tail" status to extend service time (buffer). *Mitigation*: Audit complex cases against historical baselines.
-   **Starvation**: P3 cases may be indefinitely delayed if P1 surge is continuous. *Mitigation*: Enforce a minimum P3 throughput per shift (e.g., 1 case/hour).
-   **Skill Erosion**: If Policy C uses "Core" too heavily, Flex resources (Chen/Emil) lose proficiency. *Mitigation*: Rotate Flex resources into Core tasks weekly.
-   **Preemption Overhead**: Excessive preemption leads to high restart penalties. *Mitigation*: Limit preemption to cases with >50% remaining time.

    def __init__(self, case_id, priority, case_type, arrival_time, scenario):
        self.id = case_id
        self.priority = priority # 1, 2, 3
        self.type = case_type # M, E, S, ME, ES
        self.arrival_time = arrival_time
        self.start_time = None
        self.end_time = None
        self.current_activity = "Intake"
        self.resource = None
        self.history = [] # List of (activity, resource, start, end)
        self.complex = random.random() < (SERVICE_TIMES["Intake"]["prob"] * scenario["complex_mult"])
        self.preempted = False

    def get_duration(self, activity, resource_speed):
        # Triangular approx: min, mid, max
        if activity == "ME_Diag" or activity == "ES_Diag":
            # Simplified: use avg of branches
            base_range = SERVICE_TIMES.get("Mechanical", SERVICE_TIMES.get("Electrical", SERVICE_TIMES["Intake"]))["ordinary"]
            if self.complex:
                base_range = SERVICE_TIMES.get("Mechanical", SERVICE_TIMES.get("Electrical", SERVICE_TIMES["Intake"]))["complex"]
            return (base_range[0] + base_range[1]) / 2 / resource_speed
        else:
            range_data = SERVICE_TIMES[activity]
            if self.complex:
                base_range = range_data["complex"]
            else:
                base_range = range_data["ordinary"]
            # Triangular mean approx
            mean = (base_range[0] + base_range[1]) / 2
            return mean / resource_speed

def run_simulation(scenario_name, scenario_config, policy_type="Hybrid"):
    events = []
    queue = []
    resources = {r["id"]: {"busy_until": datetime(2023,1,1,0,0), "last_skill": None, "active_case": None} for r in RESOURCES}
    if scenario_config["chen_absent"]:
        resources["Chen"]["busy_until"] = datetime(2023,12,31,23,59) # Lock out Chen
    
    # Generate Arrivals
    case_counter = 0
    day_start = datetime(2023, 1, 1, 8, 0)
    
    for block in DEMAND:
        # Apply Scenario Modifiers
        multiplier = scenario_config.get("multiplier", 1.0)
        arr_count = int(block["arr"] * multiplier)
        
        # Adjust P1
        p1_pct = block["p1"] + scenario_config.get("p1_add", 0)
        # Renormalize P2/P3 slightly if needed, simplified here
        p1_count = int(arr_count * p1_pct)
        p2_count = int(arr_count * block["p2"])
        p3_count = arr_count - p1_count - p2_count
        
        # Case Types
        types = ["M", "E", "S", "ME", "ES"]
        probs = [block["M"], block["E"], block["S"], block["ME"], block["ES"]]
        
        # IT Outage Block (U5)
        it_outage = scenario_config.get("it_outage", False)
        outage_start = datetime(2023, 1, 1, 9, 30)
        outage_end = datetime(2023, 1, 1, 10, 0)
        
        # Distribute arrivals in block
        block_start_str, block_end_str = block["block"].split("-")
        block_start = datetime.strptime(f"2023-01-01 {block_start_str}", "%Y-%m-%d %H:%M")
        block_end = datetime.strptime(f"2023-01-01 {block_end_str}", "%Y-%m-%d %H:%M")
        duration_min = (block_end - block_start).total_seconds() / 60
        
        for i in range(arr_count):
            case_counter += 1
            # Random time in block
            t_offset = (i / arr_count) * duration_min
            arrival_time = block_start + timedelta(minutes=t_offset)
            
            # Check Outage
            if it_outage and outage_start <= arrival_time <= outage_end:
                arrival_time = outage_end # Delay to end of outage
            
            # Determine Priority
            r = random.random()
            if r < p1_pct: priority = 1
            elif r < p1_pct + block["p2"]: priority = 2
            else: priority = 3
            
            # Determine Type
            t_rand = random.random()
            cum_p = 0
            case_type = "M"
            for t, p in zip(types, probs):
                cum_p += p
                if t_rand < cum_p:
                    case_type = t
                    break
            
            # U2 Surge Adjustment
            if scenario_config.get("elec_surge") and "12:00" <= block_start_str < "16:00":
                if random.random() < 0.5:
                    case_type = "E" if case_type == "M" else case_type # Simple swap for demo
            
            case = Case(case_counter, priority, case_type, arrival_time, scenario_config)
            queue.append(case)

    # Sort queue by Priority then Arrival
    queue.sort(key=lambda x: (x.priority, x.arrival_time))

    # Simulation Loop (Event Driven Simplified)
    current_time = day_start
    max_time = day_start + timedelta(hours=24)
    
    # Resource Availability Helper
    def get_available_resources(at_time):
        avail = []
        for rid, rdata in resources.items():
            if rdata["busy_until"] <= at_time:
                # Check Shift
                res_def = next(r for r in RESOURCES if r["id"] == rid)
                shift_start = datetime.strptime(f"2023-01-01 {res_def['shift_start']}", "%Y-%m-%d %H:%M")
                shift_end = datetime.strptime(f"2023-01-01 {res_def['shift_end']}", "%Y-%m-%d %H:%M")
                if shift_start <= at_time < shift_end:
                    avail.append(rid)
        return avail

    # Process Queue
    while queue:
        # Find next event (Arrival or Completion)
        # For simplicity in this scaffold, we process queue in order but check resource availability
        # This is an approximation of DES for benchmarking purposes
        
        case = queue.pop(0)
        if case.arrival_time > max_time: break
        
        current_time = max(current_time, case.arrival_time)
        
        # Find Resource
        # Policy Logic
        if policy_type == "Specialization":
            # Fixed mapping (simplified)
            # M->Ben, E->Chen/Deepa, S->Chen/Emil, Val->Ada
            preferred = []
            if case.type in ["M", "ME"]: preferred = ["Ben", "Ada", "Deepa"]
            elif case.type in ["E", "ME", "ES"]: preferred = ["Chen", "Deepa", "Emil", "Farah"]
            elif case.type in ["S", "ES"]: preferred = ["Chen", "Emil"]
            else: preferred = ["Ada", "Ben"]
            
            # Find first available in preferred
            res_id = None
            for r in preferred:
                if r in resources and resources[r]["busy_until"] <= current_time:
                    res_id = r
                    break
        else:
            # Pooling / Hybrid: Any qualified
            res_id = None
            for rid in resources:
                if resources[rid]["busy_until"] <= current_time:
                    # Check skill
                    skill_map = next(r for r in RESOURCES if r["id"] == rid)["skills"]
                    # Determine required skill
                    req_skill = "Mechanical" if case.type in ["M", "ME"] else "Electrical" if case.type in ["E", "ES"] else "Software" if case.type in ["S"] else "Validation"
                    if case.current_activity == "Intake": req_skill = "Intake"
                    if case.current_activity == "Validation": req_skill = "Validation"
                    
                    if skill_map.get(req_skill) is not None:
                        res_id = rid
                        break
        
        if res_id:
            # Assign
            resources[res_id]["busy_until"] = current_time + timedelta(minutes=1) # Placeholder duration logic
            resources[res_id]["active_case"] = case.id
            case.resource = res_id
            case.start_time = current_time
            
            # Calculate Real Duration
            speed = next(r for r in RESOURCES if r["id"] == res_id)["skills"].get(case.current_activity, 1.0)
            if speed is None: speed = 1.0
            duration = case.get_duration(case.current_activity, speed)
            
            # Add Handover/Setup
            last_res = resources[res_id]["last_skill"]
            if last_res is not None and last_res != case.current_activity:
                duration += 5 # Setup
            
            end_time = current_time + timedelta(minutes=duration)
            resources[res_id]["busy_until"] = end_time
            resources[res_id]["last_skill"] = case.current_activity
            case.end_time = end_time
            
            # Log Event
            events.append({
                "case:concept:name": str(case.id),
                "concept:name": case.current_activity,
                "start_timestamp": current_time,
                "time:timestamp": end_time,
                "org:resource": res_id,
                "priority": case.priority,
                "case_type": case.type,
                "policy_version": policy_type
            })
            
            # Next Activity
            if case.current_activity == "Intake":
                case.current_activity = "Diag"
                queue.append(case) # Re-queue for Diag
            elif case.current_activity == "Diag":
                case.current_activity = "Validation"
                queue.append(case)
            else:
                case.end_time = end_time
                # Case Done
        else:
            # Resource Busy, re-queue
            queue.append(case)
            current_time += timedelta(minutes=10) # Advance time to unblock
    
    # Convert to DataFrame for PM4Py
    df = pd.DataFrame(events)
    if not df.empty:
        df['start_timestamp'] = pd.to_datetime(df['start_timestamp'])
        df['time:timestamp'] = pd.to_datetime(df['time:timestamp'])
    return df

# 9. Limits and validation plan

**Limits of Current Analysis**
-   **Arrival Variability**: The simulation assumes uniform distribution within blocks. Real-world "burstiness" (e.g., all 7 cases arrive in 10 mins) would increase queue delays significantly more than the mean calculation suggests.
-   **Human Factors**: The model assumes resources work at constant speed multipliers. In reality, fatigue (especially after 16:00 for Deepa/Emil) reduces speed.
-   **Preemption Accuracy**: The restart penalty is an estimate. Real preemption may involve context switching costs not captured by simple time addition.
-   **Complex Tail**: The "Complex" probability is static. In reality, it may correlate with specific resource skill levels or time of day.

**Validation Plan**
1.  **Pilot Run**: Deploy Policy C on a single shift (e.g., 12:00-20:00) for 2 weeks.
2.  **Backtest**: Use historical logs (if available) to simulate Policy A/B/C against actual outcomes to validate the "U1/U2" predictions.
3.  **A/B Test**: Split incoming cases by Case Type (e.g., Mechanical -> Policy A, Electrical -> Policy B) to compare SLA performance directly.
4.  **Safety Valve**: Implement a hard limit on P1 SLA breach (e.g., if >10% breach in 1 hour, trigger "All Hands" mode).

This benchmark analysis prioritizes **robustness** (handling U1-U5) over **optimality** (Base case delay). Policy C is recommended because it explicitly manages the trade-off between P1 urgency and resource fairness, which is the primary operational tension in this scenario. The Python code provides a reproducible scaffold to validate these claims with empirical data.


# 1. Assumptions, objectives, and decision variables

**Demand and Service Assumptions**
-   **Arrival Process**: Arrivals within a 2-hour block are distributed uniformly across the block for simulation purposes. Total arrivals per block are fixed by the demand table.
-   **Service Time Distribution**: Ranges (Min-Max) are modeled as Triangular distributions $(min, mode, max)$ where $mode$ is the midpoint of the range. For "Complex-tail" cases (probability $p$), the range is replaced by the complex range (e.g., Intake 10-14 mins).
-   **ME/ES Branching**:
    -   **Parallel**: Selected if Case Priority is P1 AND at least 2 qualified resources are idle at the moment of Diagnostic start. Coordination penalty (8 min) applies before Validation.
    -   **Sequential**: Default for P2/P3 or if resources are constrained. No coordination penalty.
-   **Preemption**: Only P1 cases can preempt P2/P3. A case is preempted if a P1 case arrives and the resource is busy with a lower priority. The penalty is applied to the remaining service time of the interrupted case. Max 1 preemption per case.
-   **Handovers**: 7 minutes added if the resource changes between Intake, Diagnostic, and Validation. 5 minutes added if switching between Mechanical and Electrical/Software teams (unless same cross-skilled resource). 5 minutes setup if resource switches skill family between consecutive cases.

**Objective Formulations**
1.  **SLA Risk Minimization (Primary)**: Maximize the weighted percentage of cases meeting their priority-specific SLA targets.
    $$ \text{Score}_{SLA} = 0.5 \cdot \mathbb{I}(P1 \le 120m) + 0.3 \cdot \mathbb{I}(P2 \le 8h) + 0.2 \cdot \mathbb{I}(P3 \le 24h) $$
    *Rationale*: P1 cases represent critical technical incidents; failure here has the highest business impact.
2.  **Fairness and Robustness (Secondary)**: Minimize the standard deviation of resource utilization across the shift, penalizing utilization > 90%.
    $$ \text{Score}_{Fair} = - \text{StdDev}(\text{Utilization}_r) - \sum_r \max(0, \text{Util}_r - 0.9) \cdot \text{Penalty} $$
    *Rationale*: Prevents burnout on specific resources (e.g., Farah or Ada) and ensures the system remains stable under load shocks.

**Decision Variables**
-   Routing policy (Specialized vs. Pooled vs. Hybrid).
-   Parallelism trigger (P1-only vs. Always).
-   Preemption threshold (Always P1 vs. P1 with load check).

# 3. Candidate policies

**Policy A: Strict Specialization (Fixed Queues)**
-   **Eligibility**: Resources only take cases matching their primary skill (e.g., Ben = Intake, Mech, Val).
-   **Dispatch**: FCFS within skill queue.
-   **Handover**: Maximized. Intake $\to$ Diag $\to$ Val often requires handover (7 min each).
-   **Parallelism**: Disabled (sequential only) to avoid coordination overhead.
-   **Pros**: Low setup time (no skill switching).
-   **Cons**: High handover delays. Low resilience (Chen absent $\to$ Software stops).

**Policy B: Full Pooling (Transparent Dispatch)**
-   **Eligibility**: Any qualified resource takes the oldest eligible case.
-   **Dispatch**: Priority Queue (P1 > P2 > P3).
-   **Handover**: Minimized (resource keeps case if possible).
-   **Parallelism**: Enabled for P1 cases if 2 resources free.
-   **Pros**: High resource utilization. Fast P1 response.
-   **Cons**: High setup time (5 min per skill switch). Complex to audit.

**Policy C: Hybrid (P1 Reserve + Overflow)**
-   **Eligibility**: Ada, Ben, Deepa form "Core". Chen, Emil, Farah form "Flex".
-   **Dispatch**: P1 cases routed to Core first. If Core > 85% util, overflow to Flex.
-   **Preemption**: Enabled for P1 on Core resources.
-   **Parallelism**: Enabled for P1 on Core.
-   **Pros**: Protects P1 SLA. Balances load.
-   **Cons**: Requires monitoring of Core utilization.

# 5. Robust recommendation

**Primary Recommendation: Policy C (Hybrid with P1 Reserve)**
-   **Why**: Policy A fails under U1/U3 due to rigidity. Policy B creates excessive setup overhead and fairness issues (Farah/Ada overworked). Policy C balances P1 protection with flexibility.
-   **Trigger Thresholds**:
    -   Switch to "Full Pooling" (Policy B logic) if Core utilization > 90% for 30 mins.
    -   Switch to "Sequential Only" if Coordination overhead > 15% of total time.
-   **Fallback**: In U5 (Combined Stress), activate "Triage Mode": All P1 cases bypass Intake queue if possible (direct to Diag), P2/P3 paused.

**Why it dominates**: It explicitly addresses the "Fairness" objective by capping Core utilization, preventing the burnout seen in Policy B. It protects the "SLA" objective by reserving capacity for P1.

# 6. Secondary effects and implementation risks

-   **Gaming**: Resources may claim "Complex-tail" status to extend service time (buffer). *Mitigation*: Audit complex cases against historical baselines.
-   **Starvation**: P3 cases may be indefinitely delayed if P1 surge is continuous. *Mitigation*: Enforce a minimum P3 throughput per shift (e.g., 1 case/hour).
-   **Skill Erosion**: If Policy C uses "Core" too heavily, Flex resources (Chen/Emil) lose proficiency. *Mitigation*: Rotate Flex resources into Core tasks weekly.
-   **Preemption Overhead**: Excessive preemption leads to high restart penalties. *Mitigation*: Limit preemption to cases with >50% remaining time.
-   **Validation Bottleneck**: If Diagnostic speed increases, Validation becomes the new bottleneck. *Monitoring required*.

# --- SIMULATION ENGINE ---

class Case:
    def __init__(self, case_id, priority, case_type, arrival_time, scenario):
        self.id = case_id
        self.priority = priority # 1, 2, 3
        self.type = case_type # M, E, S, ME, ES
        self.arrival_time = arrival_time
        self.start_time = None
        self.end_time = None
        self.current_activity = "Intake"
        self.resource = None
        self.history = [] # List of (activity, resource, start, end)
        self.complex = random.random() < (SERVICE_TIMES["Intake"]["prob"] * scenario["complex_mult"])
        self.preempted = False

    def get_duration(self, activity, resource_speed):
        # Triangular approx: min, mid, max
        if activity == "ME_Diag" or activity == "ES_Diag":
            # Simplified: use avg of branches
            base_range = SERVICE_TIMES.get("Mechanical", SERVICE_TIMES.get("Electrical", SERVICE_TIMES["Intake"]))["ordinary"]
            if self.complex:
                base_range = SERVICE_TIMES.get("Mechanical", SERVICE_TIMES.get("Electrical", SERVICE_TIMES["Intake"]))["complex"]
            return (base_range[0] + base_range[1]) / 2 / resource_speed
        else:
            range_data = SERVICE_TIMES[activity]
            if self.complex:
                base_range = range_data["complex"]
            else:
                base_range = range_data["ordinary"]
            # Triangular mean approx
            mean = (base_range[0] + base_range[1]) / 2
            return mean / resource_speed

def run_simulation(scenario_name, scenario_config, policy_type="Hybrid"):
    events = []
    queue = []
    resources = {r["id"]: {"busy_until": datetime(2023,1,1,0,0), "last_skill": None, "active_case": None} for r in RESOURCES}
    if scenario_config["chen_absent"]:
        resources["Chen"]["busy_until"] = datetime(2023,12,31,23,59) # Lock out Chen
    
    # Generate Arrivals
    case_counter = 0
    day_start = datetime(2023, 1, 1, 8, 0)
    
    for block in DEMAND:
        # Apply Scenario Modifiers
        multiplier = scenario_config.get("multiplier", 1.0)
        arr_count = int(block["arr"] * multiplier)
        
        # Adjust P1
        p1_pct = block["p1"] + scenario_config.get("p1_add", 0)
        # Renormalize P2/P3 slightly if needed, simplified here
        p1_count = int(arr_count * p1_pct)
        p2_count = int(arr_count * block["p2"])
        p3_count = arr_count - p1_count - p2_count
        
        # Case Types
        types = ["M", "E", "S", "ME", "ES"]
        probs = [block["M"], block["E"], block["S"], block["ME"], block["ES"]]
        
        # IT Outage Block (U5)
        it_outage = scenario_config.get("it_outage", False)
        outage_start = datetime(2023, 1, 1, 9, 30)
        outage_end = datetime(2023, 1, 1, 10, 0)
        
        # Distribute arrivals in block
        block_start_str, block_end_str = block["block"].split("-")
        block_start = datetime.strptime(f"2023-01-01 {block_start_str}", "%Y-%m-%d %H:%M")
        block_end = datetime.strptime(f"2023-01-01 {block_end_str}", "%Y-%m-%d %H:%M")
        duration_min = (block_end - block_start).total_seconds() / 60
        
        for i in range(arr_count):
            case_counter += 1
            # Random time in block
            t_offset = (i / arr_count) * duration_min
            arrival_time = block_start + timedelta(minutes=t_offset)
            
            # Check Outage
            if it_outage and outage_start <= arrival_time <= outage_end:
                arrival_time = outage_end # Delay to end of outage
            
            # Determine Priority
            r = random.random()
            if r < p1_pct: priority = 1
            elif r < p1_pct + block["p2"]: priority = 2
            else: priority = 3
            
            # Determine Type
            t_rand = random.random()
            cum_p = 0
            case_type = "M"
            for t, p in zip(types, probs):
                cum_p += p
                if t_rand < cum_p:
                    case_type = t
                    break
            
            # U2 Surge Adjustment
            if scenario_config.get("elec_surge") and "12:00" <= block_start_str < "16:00":
                if random.random() < 0.5:
                    case_type = "E" if case_type == "M" else case_type # Simple swap for demo
            
            case = Case(case_counter, priority, case_type, arrival_time, scenario_config)
            queue.append(case)

    # Sort queue by Priority then Arrival
    queue.sort(key=lambda x: (x.priority, x.arrival_time))

    # Simulation Loop (Event Driven Simplified)
    current_time = day_start
    max_time = day_start + timedelta(hours=24)
    
    # Resource Availability Helper
    def get_available_resources(at_time):
        avail = []
        for rid, rdata in resources.items():
            if rdata["busy_until"] <= at_time:
                # Check Shift
                res_def = next(r for r in RESOURCES if r["id"] == rid)
                shift_start = datetime.strptime(f"2023-01-01 {res_def['shift_start']}", "%Y-%m-%d %H:%M")
                shift_end = datetime.strptime(f"2023-01-01 {res_def['shift_end']}", "%Y-%m-%d %H:%M")
                if shift_start <= at_time < shift_end:
                    avail.append(rid)
        return avail

    # Process Queue
    while queue:
        # Find next event (Arrival or Completion)
        # For simplicity in this scaffold, we process queue in order but check resource availability
        # This is an approximation of DES for benchmarking purposes
        
        case = queue.pop(0)
        if case.arrival_time > max_time: break
        
        current_time = max(current_time, case.arrival_time)
        
        # Find Resource
        # Policy Logic
        if policy_type == "Specialization":
            # Fixed mapping (simplified)
            # M->Ben, E->Chen/Deepa, S->Chen/Emil, Val->Ada
            preferred = []
            if case.type in ["M", "ME"]: preferred = ["Ben", "Ada", "Deepa"]
            elif case.type in ["E", "ME", "ES"]: preferred = ["Chen", "Deepa", "Emil", "Farah"]
            elif case.type in ["S", "ES"]: preferred = ["Chen", "Emil"]
            else: preferred = ["Ada", "Ben"]
            
            # Find first available in preferred
            res_id = None
            for r in preferred:
                if r in resources and resources[r]["busy_until"] <= current_time:
                    res_id = r
                    break
        else:
            # Pooling / Hybrid: Any qualified
            res_id = None
            for rid in resources:
                if resources[rid]["busy_until"] <= current_time:
                    # Check skill
                    skill_map = next(r for r in RESOURCES if r["id"] == rid)["skills"]
                    # Determine required skill
                    req_skill = "Mechanical" if case.type in ["M", "ME"] else "Electrical" if case.type in ["E", "ES"] else "Software" if case.type in ["S"] else "Validation"
                    if case.current_activity == "Intake": req_skill = "Intake"
                    if case.current_activity == "Validation": req_skill = "Validation"
                    
                    if skill_map.get(req_skill) is not None:
                        res_id = rid
                        break
        
        if res_id:
            # Assign
            resources[res_id]["busy_until"] = current_time + timedelta(minutes=1) # Placeholder duration logic
            resources[res_id]["active_case"] = case.id
            case.resource = res_id
            case.start_time = current_time
            
            # Calculate Real Duration
            speed = next(r for r in RESOURCES if r["id"] == res_id)["skills"].get(case.current_activity, 1.0)
            if speed is None: speed = 1.0
            duration = case.get_duration(case.current_activity, speed)
            
            # Add Handover/Setup
            last_res = resources[res_id]["last_skill"]
            if last_res is not None and last_res != case.current_activity:
                duration += 5 # Setup
            
            end_time = current_time + timedelta(minutes=duration)
            resources[res_id]["busy_until"] = end_time
            resources[res_id]["last_skill"] = case.current_activity
            case.end_time = end_time
            
            # Log Event
            events.append({
                "case:concept:name": str(case.id),
                "concept:name": case.current_activity,
                "start_timestamp": current_time,
                "time:timestamp": end_time,
                "org:resource": res_id,
                "priority": case.priority,
                "case_type": case.type,
                "policy_version": policy_type
            })
            
            # Next Activity
            if case.current_activity == "Intake":
                case.current_activity = "Diag"
                queue.append(case) # Re-queue for Diag
            elif case.current_activity == "Diag":
                case.current_activity = "Validation"
                queue.append(case)
            else:
                case.end_time = end_time
                # Case Done
        else:
            # Resource Busy, re-queue
            queue.append(case)
            current_time += timedelta(minutes=10) # Advance time to unblock
    
    # Convert to DataFrame for PM4Py
    df = pd.DataFrame(events)
    if not df.empty:
        df['start_timestamp'] = pd.to_datetime(df['start_timestamp'])
        df['time:timestamp'] = pd.to_datetime(df['time:timestamp'])
    return df

# 9. Limits and validation plan

**Limits of Current Analysis**
-   **Arrival Variability**: The simulation assumes uniform distribution within blocks. Real-world "burstiness" (e.g., all 7 cases arrive in 10 mins) would increase queue delays significantly more than the mean calculation suggests.
-   **Human Factors**: The model assumes resources work at constant speed multipliers. In reality, fatigue (especially after 16:00 for Deepa/Emil) reduces speed.
-   **Preemption Accuracy**: The restart penalty is an estimate. Real preemption may involve context switching costs not captured by simple time addition.
-   **Complex Tail**: The "Complex" probability is static. In reality, it may correlate with specific resource skill levels or time of day.

**Validation Plan**
1.  **Pilot Run**: Deploy Policy C on a single shift (e.g., 12:00-20:00) for 2 weeks.
2.  **Backtest**: Use historical logs (if available) to simulate Policy A/B/C against actual outcomes to validate the "U1/U2" predictions.
3.  **A/B Test**: Split incoming cases by Case Type (e.g., Mechanical -> Policy A, Electrical -> Policy B) to compare SLA performance directly.
4.  **Safety Valve**: Implement a hard limit on P1 SLA breach (e.g., if >10% breach in 1 hour, trigger "All Hands" mode).

This benchmark analysis prioritizes **robustness** (handling U1-U5) over **optimality** (Base case delay). Policy C is recommended because it explicitly manages the trade-off between P1 urgency and resource fairness, which is the primary operational tension in this scenario. The Python code provides a reproducible scaffold to validate these claims with empirical data.
