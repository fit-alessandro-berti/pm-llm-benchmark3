## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels -> alignment_moves -> measured_fitness
ETL_change -> recorded_order -> alignment_moves -> measured_fitness
policy_change -> true_process -> normative_model (obsolete) -> measured_fitness
reviewer_behavior -> true_process -> recorded_labels -> alignment_moves
true_process -> business_outcomes (invariant)
```

The sudden deterioration of conformance is a classic artifact of socio-technical interference, where operational data pipeline modifications and user-interface updates completely distort the digital shadow of an otherwise stable process. 

First, the deployment of UI Release 4.2 replaced the screen label `Classify` with `Risk Screen` without updating the normative process tree, immediately causing the conformance engine to flag every case as a mismatch. Second, IT introduced `Queue Routed` technical logging and migrated ETL timestamp generation to warehouse-ingestion time rather than source-system sequence numbers. This created artificial concurrency and sequence inversion (e.g., `Notify` preceding `Decision`), drastically inflating alignment costs. Third, process obsolescence occurred concurrently: the August policy mandate for `Supervisor Sign-off` introduced a genuine structural change to the process that the normative model did not anticipate.

Crucially, business outcomes (approval rates, cycle times, and appeal rates) remained virtually unchanged across all periods, proving that the operational reality of the claims process did not collapse. The plummeting fitness metrics were entirely a product of logging semantics, ETL timing artifacts, and an un-updated process model. However, dismissing noncompliance entirely would be premature; the persistent presence of enhanced reviews lacking compliance checks points to potential operational friction or missing log events that require targeted case-attribute auditing.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py
from pm4py.objects.process_tree.utils import generic as pt_utils
from pm4py.algo.discovery.dfg import algorithm as dfg_discovery
from pm4py.algo.conformance.alignments.petri_net import algorithm as alignments_algo
from pm4py.statistics.traces.generic.log import case_statistics

# 1. Encode normative process tree
normative_tree_str = "-> ('Receive', 'Classify', X (* ('Standard Review', 'Request Info'), -> ('Enhanced Review', 'Compliance Check')), 'Decision', 'Notify')"
process_tree = pm4py.parse_process_tree(normative_tree_str)

# 2. Convert to accepting Petri net
net, initial_marking, final_marking = pm4py.convert_to_petri_net(process_tree)

# 3. Construct synthetic event logs from variant frequencies (June-July raw)
jun_jul_raw_data = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
    ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
    ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20)
]

events = []
case_id = 1
for trace_str, count in jun_jul_raw_data:
    activities = trace_str.split(",")
    for _ in range(count):
        for act in activities:
            events.append({"case:concept:name": f"Case_{case_id}", "concept:name": act})
        case_id += 1

import pandas as pd
raw_log = pd.DataFrame(events)
raw_log = pm4py.format_dataframe(raw_log, case_id="case:concept:name", activity_key="concept:name", timestamp_key=None)

# 4. Discover DFG
dfg, start_activities, end_activities = dfg_discovery.apply(raw_log)

# 5. Compute raw alignment diagnostics
raw_alignments = alignments_algo.apply(raw_log, net, initial_marking, final_marking)
raw_fitness = pm4py.conformance_eval_alignments(raw_log, net, initial_marking, final_marking)
print(f"Raw Alignment Fitness (June-July): {raw_fitness}")

# 6. Apply transparent normalization pipeline
normalized_log_df = raw_log.copy()
normalized_log_df["concept:name"] = normalized_log_df["concept:name"].replace({"Risk Screen": "Classify"})
normalized_log_df = normalized_log_df[~normalized_log_df["concept:name"].isin(["Queue Routed"])]

norm_fitness = pm4py.conformance_eval_alignments(normalized_log_df, net, initial_marking, final_marking)
print(f"Normalized Alignment Fitness (June-July): {norm_fitness}")

# 7. Candidate process tree allowing optional Supervisor Sign-off (August-September)
candidate_tree_str = "-> ('Receive', 'Classify', X (* ('Standard Review', 'Request Info'), -> ('Enhanced Review', 'Compliance Check')), X (tau, 'Supervisor Sign-off'), 'Decision', 'Notify')"
candidate_tree = pm4py.parse_process_tree(candidate_tree_str)
cand_net, cand_init, cand_final = pm4py.convert_to_petri_net(candidate_tree)

aug_sep_data = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35)
]

aug_events = []
c_id = 1000
for trace_str, count in aug_sep_data:
    activities = trace_str.split(",")
    for _ in range(count):
        for act in activities:
            aug_events.append({"case:concept:name": f"Case_{c_id}", "concept:name": act})
        c_id += 1

aug_log = pd.DataFrame(aug_events)
aug_log = pm4py.format_dataframe(aug_log, case_id="case:concept:name", activity_key="concept:name", timestamp_key=None)
aug_log["concept:name"] = aug_log["concept:name"].replace({"Risk Screen": "Classify"})
aug_log = aug_log[~aug_log["concept:name"].isin(["Queue Routed"])]

cand_fitness = pm4py.conformance_eval_alignments(aug_log, cand_net, cand_init, cand_final)
print(f"Candidate Model Alignment Fitness (Aug-Sep): {cand_fitness}")

# 8. Print caveats
print("\n[CAVEAT] A control-flow-only optional sign-off model cannot enforce data-aware constraints (e.g., EUR > 50,000 threshold) and may overgeneralize conformance by permitting sign-offs on low-value claims.")
```

## 7. Provisional conclusion

The sudden deterioration in conformance for the regulated claims process is primarily an artifact of technical interference, interface relabeling, and data pipeline corruption rather than a collapse in operational execution. Confidence in this primary diagnosis is **high (95%)**. 

The evidence is unambiguous: when UI Release 4.2 renamed `Classify` to `Risk Screen`, when IT injected `Queue Routed` technical events, and when the ETL pipeline began using warehouse-ingestion timestamps (causing `Notify`/`Decision` inversions), the digital shadow of the process broke. Once these technical artifacts were filtered and remapped, alignment fitness jumped dramatically from 32% back to 89%. Furthermore, business outcomes—such as median cycle times (26.0h to 27.4h), approval rates (72.0% to 71.5%), and appeal rates (3.8% to 3.6%)—remained remarkably stable, confirming that the underlying business process operated normally.

However, a separate assessment is required for potential compliance drift. Confidence in a secondary compliance risk is **moderate (70%)**. The August policy change introducing mandatory `Supervisor Sign-off` for claims above EUR 50,000 represented a genuine normative model obsolescence. Moreover, the persistence of enhanced-review traces lacking a recorded compliance check (~25–30 cases per period) warrants caution. While compliance reported no material change in confirmed incidents, they warned that incident detection is incomplete. 

**Immediate Actions:**
- **IT:** Revert ETL timestamp generation to use source-system sequence numbers and establish a synchronized metadata dictionary mapping UI labels to process event classes.
- **Process Owners:** Formally update the normative process model to incorporate the EUR 50,000 `Supervisor Sign-off` rule with data-aware guards.
- **Compliance:** Conduct a targeted file audit on the subset of enhanced-review cases lacking recorded compliance checks to determine whether they represent true policy bypasses or logging omissions.

**What must not be claimed yet:** IT and compliance must not claim that employees are systematically violating policy or that the process has suffered structural operational failure. The drop in conformance was predominantly synthetic.

## 8. Model-governance recommendation

1. **Model Versioning:** Every normative process model must be formally versioned, timestamped, and linked via metadata repository to the active policy documentation and UI schema definitions.
2. **Event-Semantic Contracts:** IT and process engineering must establish a strict semantic contract governing event logs; any UI relabeling (e.g., `Classify` to `Risk Screen`) requires a mandatory mapping layer in the event extraction pipeline prior to conformance evaluation.
3. **Technical-Event Policy:** Infrastructure events (such as `Queue Routed` or system-level triggers) must be logged in separate technical namespaces or system audit tables, strictly segregated from business process event logs used for conformance checking.
4. **Timestamp Provenance:** Conformance pipelines must ingest source-system sequence numbers and atomic transaction timestamps rather than asynchronous warehouse-ingestion times to prevent artificial concurrency and ordering defects.
5. **Data-Aware Constraints:** Control-flow normative models must be supplemented with data-aware guard conditions (e.g., monetary thresholds like EUR 50,000) to prevent overgeneralization and false positives in regulatory compliance monitoring.
6. **Post-Release Validation:** Any release of user interface updates, IT infrastructure patches, or ETL pipeline modifications must trigger an automated regression test comparing pre- and post-release event log variants and alignment metrics before compliance reporting.
