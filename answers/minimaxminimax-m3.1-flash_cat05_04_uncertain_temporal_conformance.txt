def expand_local(ts: datetime, rounding: str) -> tuple[datetime, datetime]:
    if rounding == "second":       # displayed second, +/-0.5 s measurement error
        return ts - timedelta(seconds=0.5), ts + timedelta(seconds=0.5)
    if rounding == "floor_minute":
        base = ts.replace(second=0, microsecond=0)
        return base, base + timedelta(seconds=59.999)
    if rounding == "round_10s":
        return ts - timedelta(seconds=5), ts + timedelta(seconds=5)
    if rounding == "round_minute":
        return ts - timedelta(seconds=30), ts + timedelta(seconds=30)
    raise ValueError(rounding)

def _offs(dt, tz, fold):
    return dt.replace(tzinfo=tz, fold=fold).utcoffset()

def local_to_utc_alternatives(lo, hi, tz):
    """Return list of (utc_lo, utc_hi) alternatives for a local wall-clock interval."""
    # sample breakpoints every 30 s to detect DST transitions
    pts = [lo]
    t = lo
    while t < hi:
        t = t + timedelta(seconds=30)
        pts.append(min(t, hi))
    if pts[-1] != hi: pts.append(hi)
    segs = []  # (seg_lo, seg_hi, off0, off1)
    cur = None
    for p in pts:
        o0 = _offs(p, tz, 0); o1 = _offs(p, tz, 1)
        if cur and cur[2] == o0 and cur[3] == o1:
            cur = (cur[0], p, o0, o1)
        else:
            if cur: segs.append(cur)
            cur = (p, p, o0, o1)
    segs.append(cur)
    out = []
    for s_lo, s_hi, o0, o1 in segs:
        if o0 == o1:
            out.append(((s_lo - o0).astimezone(timezone.utc), (s_hi - o0).astimezone(timezone.utc)))
        else:
            # ambiguous (or nonexistent) local hour: two fold alternatives
            out.append(((s_lo - o0).astimezone(timezone.utc), (s_hi - o0).astimezone(timezone.utc)))
            out.append(((s_lo - o1).astimezone(timezone.utc), (s_hi - o1).astimezone(timezone.utc)))
    return merge(out)
```

Hmm, careful: `s_lo - o0` gives an aware datetime with tzinfo=tz; `.astimezone(timezone.utc)` converts. That works since subtracting an offset from an aware dt keeps the same tzinfo but shifts wall clock — which is wrong! Subtracting from an aware datetime in zoneinfo keeps the tzinfo and changes the wall time; converting with astimezone then applies the offset again  double counting. Better: compute UTC as naive subtraction then attach UTC:
utc = (s_lo - timedelta(seconds=o0.total_seconds())).replace(tzinfo=timezone.utc). Since we compute the offset ourselves, that's correct.

def merge(iv):
    if not iv: return []
    iv = sorted(iv)
    out = [list(iv[0])]
    for a,b in iv[1:]:
        if a <= out[-1][1]:
            out[-1][1] = max(out[-1][1], b)
        else:
            out.append([a,b])
    return [(a,b) for a,b in out]
```

def local_to_utc_alternatives(lo, hi, tz):
    step = timedelta(seconds=30)
    pts = [lo]
    t = lo
    while t < hi:
        t = min(t + step, hi)
        pts.append(t)
    segs = []
    for p in pts:
        o0 = p.replace(tzinfo=tz, fold=0).utcoffset()
        o1 = p.replace(tzinfo=tz, fold=1).utcoffset()
        if segs and segs[-1][2] == o0 and segs[-1][3] == o1:
            segs[-1] = (segs[-1][0], p, o0, o1)
        else:
            segs.append((p, p, o0, o1))
    out = []
    for s_lo, s_hi, o0, o1 in segs:

        else:

            out.append((_to_utc(s_lo, o0), _to_utc(s_hi, o0)))
            out.append((_to_utc(s_lo, o1), _to_utc(s_hi, o1)))

## 1. Normalization Assumptions

**A1 — Event representation.** Every event is represented as a *union of closed UTC intervals* `[t_lo, t_hi]`. An empty union is never collapsed to a point; where two mutually exclusive readings survive, both are kept (e.g. DST folds, unresolved receipt, offset-bound variants).

**A2 — Clock-offset direction and order of operations.** `clock_offset = recorded_clock  true_clock`, so `true = recorded  offset`. With `offset  [a,b]` and a resolution interval `[r_lo, r_hi]`:

```
true_local  [ r_lo  b ,  r_hi  a ]        (resolution FIRST, then clock correction)
```

Note the asymmetry: a clock that is *ahead* (positive offset) makes the true event **earlier**. Resolution uncertainty is applied before clock correction (as required), so the two uncertainty sources add rather than partially cancel.

**A3 — Display/rounding semantics (per source).**
- HUB: displayed second is exact ± 0.5 s  `[t0.5s, t+0.5s]`; plus offset ±1 s  **±1.5 s** total.
- OPS-BER / VENDOR-NY / LEGACY-BER: floor to minute  `[m:00, m:59.999]`.
- SENSOR: round to nearest 10 s  `[t5s, t+5s]`; plus offset ±5 s  **±10 s** total.
- MOBILE-LON: round to nearest minute  `[t30s, t+30s]`; plus offset ±300 s  **±330 s** before entry-delay treatment.

**A4 — Time zones.** 2026-06-01: Europe/Berlin = CEST (UTC+2), America/New_York = EDT (UTC4), Europe/London = BST (UTC+1). 2025-10-26 Berlin: 02:00:00–02:59:59.999 local occurs twice (CEST UTC+2, then CET UTC+1); both are enumerated as alternatives.

**A5 — Causal ordering ("eventually-following").** The SLA chain and the temporal-profile pairs assert a causal order `Alert_Received < Investigation_Start < Containment_Complete < Close_Incident`. I therefore require the feasible intervals of ordered events to be non-overlapping in the intended direction. This is the single most material structural assumption in the whole analysis: it is what collapses T-405's DST fold to one assignment, and it is why negative feasible durations are treated as **ordering anomalies**, not as SLA passes.

**A6 — Ingestion sequence is evidence of event order** (used for T-405 and T-407). It is not a logged event-time, so it is an assumption, but it is corroborated in T-405 by A5 (independent convergence).

**A7 — Derived events.**
- T-404: `Investigation_Start = Investigation_Complete  duration`, `duration  [1080, 1500] s` from a signed work record. Minkowski difference  start  `[C_lo  1500, C_hi  1080]`; the derived start inherits the HUB ±1.5 s of the completion and the record's own 7-minute width. The record's provenance (who wrote it, when, and whether "duration" means the same activity's startcomplete) is unverified.
- T-407: `Alert_Received = Alert_Sent + latency`, `latency  [0, 1200] s`. `Alert_Sent` is **not** definitionally `Alert_Received`.

**A8 — Mobile entry delay (T-406): two readings, treated separately from the clock bound.**
- **R (record-time only):** the user typed the *occurrence* time; entry lateness is a provenance/latency fact only. Occurrence  `[12:08:30, 12:19:30]`.
- **L (entry lag  earlier occurrence):** the value typed was current-at-entry, so occurrence may be up to 5 min earlier. Occurrence  `[12:03:30, 12:19:30]`.
Primary analysis uses **L (conservative envelope)**; R is reported as a labelled variant. The entry delay is *not* folded into the ±300 s clock-offset bound — it is a separate, semantic uncertainty about which instant the record denotes.

**A9 — T-409 offset bound.** Primary = the **weak hour-specific engineering estimate ±12 min** (the only evidence for that hour). The routine NTP bound [90 s, +120 s] is reported as a sensitivity variant. I explicitly do *not* assume the narrower bound is more accurate; a narrow but unvalidated estimate can be worse than a validated wide one. Both are reported in §3/§4.

**A10 — Acceptance semantics.**
- SLA: feasible duration `d` satisfies the rule iff `d  limit` (S1 900 s, S2 2700 s, S3 129 600 s). SLA tolerances are only applied in §4.
- Temporal profile: accept iff `d  [mean  ·sd, mean + ·sd]`, two-sided. Baseline ** = 1**. Wholly below/above the band  certain deviation; wholly inside  certain pass; partial overlap  possible deviation (both a conforming and a non-conforming outcome remain feasible).
- Classification vocabulary: CERTAIN_PASS / CERTAIN_VIOLATION / POSSIBLE_VIOLATION / INDETERMINATE, as prescribed.

**A11 — Independence of event uncertainties.** Interval subtraction treats the two events' feasible sets as independent. This is conservative for causally coupled pairs (T-404 especially): the true joint feasible set may be smaller, so POSSIBLE_VIOLATION findings are upper bounds on the violation probability.

**A12 — No drift/linearity modelling.** Offsets are treated as constant over each case's window; no intra-case drift, no clock-jump modelling, no rate skew.

**A13 — Semantic caveats.** SENSOR records a **completion** event; if the SLA's `Containment_Complete` meant containment *start*, all containment-based conclusions shift later/earlier correspondingly. No network-ingest lag is modelled because none was supplied (this makes containment appear *earlier* than it may be, i.e. it makes S2 look *easier*).

**A14 — Midpoints are used only as a labelled secondary comparison** (§5 and the contrast table in §4), never as a substitute for the interval analysis.

# 4. INTERVAL PRIMITIVES

def expand_resolution(ts: datetime, rounding: str) -> tuple[datetime, datetime]:
    """Step 1: display/rounding semantics -> clock-time interval (naive local)."""
    if rounding == "second":                       # exact to displayed second, +/- 0.5 s
        return ts - timedelta(seconds=0.5), ts + timedelta(seconds=0.5)
    if rounding == "floor_minute":                 # displayed m:SS means clock in [m:00, m:59.999]
        base = ts.replace(second=0, microsecond=0)
        return base, base + timedelta(seconds=59, microseconds=999000)
    if rounding == "round_10s":
        return ts - timedelta(seconds=5), ts + timedelta(seconds=5)
    if rounding == "round_minute":
        return ts - timedelta(seconds=30), ts + timedelta(seconds=30)
    raise ValueError(f"unknown rounding: {rounding}")


def correct_clock(lo: datetime, hi: datetime, off: tuple[float, float]) -> tuple[datetime, datetime]:
    """Step 2: clock_offset = recorded - true, so true = recorded - offset.
    offset in [a, b]  =>  true in [lo - b, hi - a]."""
    a, b = off
    return lo - timedelta(seconds=b), hi - timedelta(seconds=a)


def _to_utc(naive_local: datetime, off: timedelta) -> datetime:
    return (naive_local - timedelta(seconds=off.total_seconds())).replace(tzinfo=UTC)


def merge_intervals(iv: list[tuple[datetime, datetime]]) -> list[tuple[datetime, datetime]]:
    """Union of closed intervals; disjoint components are preserved."""
    if not iv:
        return []
    out = [[a, b] for a, b in sorted(iv)]
    merged = [out[0]]
    for a, b in out[1:]:
        if a <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], b)
        else:
            merged.append([a, b])
    return [(a, b) for a, b in merged]


def local_to_utc_alternatives(lo: datetime, hi: datetime, tz: ZoneInfo):
    """Step 3: naive local wall-clock interval -> list of UTC alternatives.
    Ambiguous local times (DST fold) yield TWO alternatives (fold=0 / fold=1).
    Non-existent local times (spring-forward gap) are detected and flagged."""
    step, pts = timedelta(seconds=30), [lo]
    t = lo
    while t < hi:
        t = min(t + step, hi)
        pts.append(t)
    segs = []
    for p in pts:
        o0 = p.replace(tzinfo=tz, fold=0).utcoffset()
        o1 = p.replace(tzinfo=tz, fold=1).utcoffset()
        if segs and segs[-1][2] == o0 and segs[-1][3] == o1:
            segs[-1] = (segs[-1][0], p, o0, o1)
        else:
            segs.append((p, p, o0, o1))
    out, nonexist = [], []
    for s_lo, s_hi, o0, o1 in segs:
        if o0 == o1:                                  # unique offset
            out.append((_to_utc(s_lo, o0), _to_utc(s_hi, o0)))
        else:                                         # ambiguous OR non-existent
            for off in (o0, o1):
                u_lo, u_hi = _to_utc(s_lo, off), _to_utc(s_hi, off)
                # round-trip test: a non-existent local time does not survive
                if u_lo.astimezone(tz).replace(tzinfo=None) != s_lo:
                    nonexist.append((s_lo, s_hi))
                else:
                    out.append((u_lo, u_hi))
    return merge_intervals(out), nonexist


def duration_intervals(a_list, b_list):
    """Feasible durations (a - b) as a union of intervals; unions preserved."""
    res = []
    for a_lo, a_hi in a_list:
        for b_lo, b_hi in b_list:
            res.append((a_lo - b_hi, a_hi - b_lo))
    return merge_intervals(res)

# 5. CLASSIFICATION

def classify_sla(dur_iv, limit: float, tolerance: float = 0.0) -> str:
    lim = limit + tolerance
    if all(d[1] <= lim for d in dur_iv):
        return "CERTAIN_PASS"
    if all(d[0] > lim for d in dur_iv):
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"


def classify_band(dur_iv, lo: float, hi: float) -> str:
    if all(d[0] >= lo and d[1] <= hi for d in dur_iv):
        return "CERTAIN_PASS"
    if all(d[1] < lo or d[0] > hi for d in dur_iv):
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"


def fmt(iv) -> str:
    if not iv:
        return "-"
    return " | ".join(f"[{a.isoformat()} .. {b.isoformat()}]" for a, b in iv)


def secs(iv) -> str:
    if not iv:
        return "-"
    return " | ".join(f"[{(a-b).total_seconds():.3f}, {(c-d).total_seconds():.3f}]"
                      for a, b in iv for c, d in [iv[0]][:0]) if False else \
           " | ".join(f"[{ (iv[i][1]-iv[i+1][0]).total_seconds():.3f}, "
                      f"{(iv[i][1]-iv[i+1][1]).total_seconds():.3f}]".replace("(", "") for i in range(len(iv)))


def dur_seconds(iv):
    """Human-readable feasible duration intervals in seconds."""
    out = []
    for lo, hi in iv:
        out.append(f"[{(hi - lo).total_seconds():.3f} .. {(lo - hi).total_seconds():.3f}]")
    return " | ".join(out)

        notes[("T-407", "Alert_Received")] = "DERIVED: Alert_Sent + latency[0,1200]s (Alert_Sent != Alert_Received)"

def run_analysis(variant: str = "primary", tolerance_s: float = 0.0, zeta: float = 1.0):
    ev, notes = build_events(variant)
    rows = []
    cases = sorted({c for c, *_ in RAW_EVENTS})
    for case in cases:
        for rule, (a, b, limit) in SLA.items():
            key_a, key_b = (case, a), (case, b)
            if key_a not in ev or key_b not in ev:
                rows.append(dict(case=case, test=rule, feasible="", acceptance=f"d <= {limit}",
                                 classification="INDETERMINATE", sev="", conf=""))
                continue
            d = duration_intervals(ev[key_b], ev[key_a])
            cls = classify_sla(d, limit, tolerance_s)
            anomaly = any(x[1] < 0 for x in d)
            rows.append(dict(case=case, test=rule, feasible=dur_seconds(d),
                             acceptance=f"d <= {limit}", classification=cls,
                             sev="", conf="", anomaly=anomaly))
        for (a, b), (mu, sd) in PROFILE.items():
            key_a, key_b = (case, a), (case, b)
            if key_a not in ev or key_b not in ev:
                rows.append(dict(case=case, test=f"PROFILE {a}->{b}", feasible="",
                                 acceptance="", classification="INDETERMINATE", sev="", conf=""))
                continue
            d = duration_intervals(ev[key_b], ev[key_a])
            lo, hi = mu - zeta * sd, mu + zeta * sd
            rows.append(dict(case=case, test=f"PROFILE {a}->{b} (zeta={zeta:g})",
                             feasible=dur_seconds(d), acceptance=f"[{lo:.0f}, {hi:.0f}]",
                             classification=classify_band(d, lo, hi), sev="", conf=""))
    return ev, notes, pd.DataFrame(rows)


# =====================================================================
# 7. MIDPOINT ("LOSSY") LOG + PM4PY CROSS-CHECK
# =====================================================================
def midpoint_log(ev) -> pd.DataFrame:
    """Midpoint of the FIRST feasible branch of each event. LOSSY by construction:
    it discards the width of every uncertainty interval and any disjoint
    alternatives (e.g. DST folds, unresolved receipt)."""
    recs = []
    for (case, act), iv in sorted(ev.items()):
        if not iv:
            continue
        a, b = iv[0]
        recs.append(dict(case=case, activity=act, timestamp=(a + (b - a) / 2),
                         derivation="MIDPOINT_LOSSY"))
    return pd.DataFrame(recs)


def pm4py_crosscheck(mid_df: pd.DataFrame, zetas=(1, 2, 3)):
    """Version-sensitive part is isolated here.

    ASSUMPTION: pm4py.conformance_temporal_profile(log, alpha, beta) returns a
    DataFrame whose columns are approximately
        ['attribute','event_A','event_B','count','mean','std_dev','min','max',
         'median', ... 'deviation_case']  (schema varies across PM4Py versions).
    We therefore (a) call it inside try/except, (b) normalise the column names
    defensively, and (c) ALWAYS recompute the task-specified acceptance band
    (mean +/- zeta*sd) locally, because PM4Py's alpha/beta are statistical
    significance levels and are NOT equivalent to a zeta band."""
    report = {}
    try:
        import pm4py
    except Exception as exc:                                   # pragma: no cover
        return {"status": "pm4py unavailable", "detail": str(exc), "calls": {}}

    df = mid_df.copy()
    df["timestamp"] = pd.to_datetime(df["timestamp"], utc=True)
    try:
        formatted = pm4py.format_dataframe(df, case_id="case", activity="activity",
                                            timestamp="timestamp")
        if isinstance(formatted, tuple):                        # version differences
            df_fmt, log = formatted
        else:
            df_fmt, log = formatted, None
        if log is None:
            log = pm4py.convert_to_event_log(df_fmt)
    except Exception as exc:
        return {"status": "formatting failed", "detail": str(exc), "calls": {}}

    calls = {}
    for zeta in zetas:
        try:
            with warnings.catch_warnings():
                warnings.simplefilter("ignore")
                res = pm4py.conformance_temporal_profile(log, alpha=zeta, beta=zeta)
            norm = {}
            for _, r in res.iterrows():
                keys = {str(k).lower(): k for k in res.columns}
                ea = r[keys.get("event_a", list(res.columns)[1])]
                eb = r[keys.get("event_b", list(res.columns)[2])]
                mean = r[keys["mean"]] if "mean" in keys else None
                std = r[keys["std_dev"]] if "std_dev" in keys else None
                dev = r[keys["deviation_case"]] if "deviation_case" in keys else None
                norm[f"{ea}->{eb}"] = dict(mean=mean, std=std, deviations=dev)
            calls[zeta] = norm
        except Exception as exc:
            calls[zeta] = {"error": str(exc)}
    return {"status": "ok", "calls": calls}

**Version/assumption notes for §5.** (i) `pm4py.format_dataframe` returns a DataFrame in current PM4Py but a `(df, log)` tuple in some builds; the code handles both and falls back to `pm4py.convert_to_event_log`. (ii) `pm4py.conformance_temporal_profile(log, alpha, beta)` uses **statistical significance levels**, not a zeta band, and its return schema (`event_A/event_B/mean/std_dev/deviation_case`) varies by version; the call is therefore isolated in `pm4py_crosscheck`, wrapped in `try/except`, and the task-specified `mean ± ·sd` band is always recomputed locally. (iii) PM4Py is fed the **midpoint** log, which is explicitly labelled `MIDPOINT_LOSSY`; PM4Py cannot consume interval-valued timestamps and therefore cannot adjudicate any POSSIBLE_VIOLATION or INDETERMINATE result here. (iv) The PM4Py run aggregates all 9 cases into one log (one case-id per case), so its population statistics are *not* the per-case profile parameters used in the report; the cross-check is directional only. (v) `local_to_utc_alternatives` samples local time in 30-s steps to segment DST transitions; for events whose uncertainty interval straddles a transition boundary the segmentation is approximate at the sample resolution (no event in this dataset does).

## 7. Governance Recommendation

**7.1 Timestamp storage and representation (technical).**
1. **Store UTC everywhere, losslessly.** Persist the event instant as UTC with at least millisecond precision *plus* the original raw string and its original zone. Never persist only a local wall-clock string; never persist only a floored/rounded value.
2. **Retain raw and rendered timestamps side by side.** Keep `raw_value`, `rendered_value`, `render_semantics` (`exact_second`/`floor_minute`/`round_10s`/`round_minute`/…), `rendered_zone`, and the source clock's `offset_estimate` + `offset_bounds` + `offset_evidence_id` with every event. The analyst can then reconstruct the feasible interval exactly as in §2, instead of re-deriving it from folklore.
3. **Persist the uncertainty interval, not just the point.** Store `t_lower_utc`, `t_upper_utc`, and the *components* of the width (resolution, clock offset, zone/DST branch, entry lag, ingest lag). Where the source is ambiguous (DST fold), store **both branches** with a `branch_reason`, or store the fold flag.

**7.2 Clock control.**
4. **Source offset telemetry, continuously.** Every system should publish `chrony`/`ntpd` offset, frequency, and last-sync age as a time series (already implied by "daily NTP diagnostics"), with a **per-event** lookup rather than a daily aggregate. T-409 exists only because one hour of diagnostics was missing; and a *narrow unvalidated* estimate (±12 min) proved more decision-relevant than a wide validated one — so record **how the bound was obtained** (measured vs engineering estimate) and prefer *measured* bounds even when wider. Treat a missing-diagnostics window as an explicit evidence gap that downgrades confidence automatically.
5. **Do not silently mix a wide bound with a narrow one.** When a period lacks diagnostics, the analysis bound should be the *union* of the last measured bound and the engineering estimate, flagged as unvalidated.

**7.3 Time-zone / DST.**
6. **Never infer a UTC instant from a local string without the zone rule.** Record the IANA zone id plus the offset actually used, and — for local times inside a fold — record `fold=0/1` explicitly. Since 2025-10-26 Berlin proved that a fold can invert the *causal* order of three events (a naive same-fold read makes the investigation precede the alert by 45 minutes), ingestion pipelines must detect ambiguity at write time and either store both branches or refuse to infer a single instant.
7. Add an automated **ordering-anomaly detector**: flag any event whose feasible interval lies entirely after the next lifecycle event's interval. T-405 and T-407 would have been caught automatically.

**7.4 Lifecycle semantics.**
8. **Define start/complete semantics per activity and store the role.** `SENSOR` records completion events; the SLA must state explicitly whether `Containment_Complete` means containment *start* or *end* (the same for `Investigation_Complete`). Where a device emits completion events, capture the **device-side ingest lag** as a first-class uncertainty component; it was unmodelled here and would consume T-401's 340 s S2 margin.
9. **Make the full lifecycle mandatory.** `Close_Incident` was missing in 7 of 9 cases, making S3 untestable and hiding the single largest confirmed breach (T-408). Require a close event (or an explicit "not closed / abandoned" state) for every incident.
10. **Distinguish `Alert_Sent` from `Alert_Received`.** Model delivery as an activity with its own latency distribution and, ideally, a receipt acknowledgment event keyed by a **causal identifier** (alert/ticket id) that also appears on the investigation record.

**7.5 Provenance and evidence handling.**
11. **Provenance for human-entered timestamps.** MOBILE-LON and the T-404 work record are both human artifacts. Require: who/when/where the value was produced, whether it denotes *occurrence* or *recording*, and an explicit lag field. Mobile submissions should carry a server-side receipt timestamp — the cheapest, hardest evidence available in T-406.
12. **Signed/auditable derived evidence.** A duration assertion (T-404's "18–25 min") must record its basis, author, and system of record, and must be linked to the same activity instance so that start and complete are not treated as independent measurements.

**7.13 Enforcement policy for interval overlap (the key governance decision).**
13. **Recommended policy — three tiers, no automatic penalty on interval overlap alone.**
    - **CERTAIN_VIOLATION** (all feasible durations breach): actionable now. Escalate, and — for S1/S2 — trigger automated containment or paging. Evidence-quality gates still apply: if the *uncertainty itself* is the cause (T-403: an 8-hour apparent breach that is really a vendor timezone/clock artefact), the first action is data remediation, not disciplinary process.
    - **POSSIBLE_VIOLATION**: **not** an adjudication. Route to a bounded evidence-remediation queue with a deadline (e.g. obtain the source's offset telemetry and a second-resolution record). Do not record a breach, do not automatically penalise. The remediation artefact must be an *interval-narrowing* datum (offset measurement, receipt ACK, second-resolution timestamp, joint start/complete pair), not a re-statement of the same weak evidence.
    - **INDETERMINATE**: report as a **data-quality defect** (missing lifecycle event, missing offset telemetry), not as a compliance outcome, and track it on a separate compliance-with-evidence dashboard so that evidence debt is visible.
14. **Declare SLA tolerance as policy, in advance, and separately per rule.** The sensitivity shows a 2-minute tolerance downgrades T-402's headline S1 violation from certain to possible, while 5 minutes erases six POSSIBLE findings. If the SLA is a *legal maximum*, adopt **zero tolerance for the recorded duration** and instead tighten the *measurement* (better clocks, higher resolution), because tolerance silently converts a compliance metric into a softer one. If a tolerance is genuinely needed (e.g. to absorb documented ingest lag), define it as an explicit *measurement allowance* applied to the interval's upper edge, and publish which findings it changes.
15. **Keep the SLA and the statistical profile separate in the data model.** T-408's IC is a *certain SLA violation* yet conforms to the profile at =2; T-409's AI is a *profile deviation in the fast direction* while passing the SLA. Merging them produces incoherent enforcement. Report two conformance dimensions with two independent review paths.
16. **Publish the confidence semantics.** "POSSIBLE_VIOLATION" must never be summarised as "compliant" in management dashboards; it means *undetermined*. Conversely, a CERTAIN_VIOLATION that stems from clock or timezone defect should be classified as a **data-integrity failure** in the pipeline, with the incident re-scored after remediation — the T-403, T-405 and T-409 patterns are exactly this, and automated re-scoring after a clock fix will materially change the historical compliance numbers.
17. **Re-evaluate on evidence change, not on schedule.** Every interval-based finding should be stored with the specific evidence that would narrow it, so that when the missing close event, the missing NTP hour, or the missing receipt acknowledgment arrives, the finding is automatically re-derived and the audit trail shows what changed.
