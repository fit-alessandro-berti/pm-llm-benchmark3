# Process-Aware Survival Analysis of SLA Tail Risk

## 1. SLA Estimands and Time Definitions

**Time origin**: Case submission (`Submit` event)
**Time horizon**: 72 hours (SLA deadline)
**Event**: Terminal disposition (Resolve, Withdraw, Reject, Transfer)
**Censoring**: Cases still open at cutoff (age < 72h) or with unknown terminal outcome (Transfer)

### Defined Estimands:

1. **Probability of unresolved status at 72 hours (P(U72))**
   - *Definition*: P(observed_status = open AND duration_or_age_h < 72)
   - *Contributions*:
     - S01 (resolved at 18h): contributes 0
     - S09 (open at 92h): contributes 1 (since 92 > 72)
     - S06 (withdrawn at 27h): contributes 0
     - S08 (transferred at 68h): contributes 1 (informative censoring)

2. **Cumulative incidence of resolution after 72 hours (CI_resolve>72)**
   - *Definition*: P(resolved AND duration_or_age_h > 72)
   - *Contributions*:
     - S01: 0
     - S09: 0 (open)
     - S06: 0
     - S08: 0 (transferred)

3. **Probability of SLA breach (P_breach)**
   - *Definition*: P(resolved AND duration_or_age_h > 72) + P(open AND duration_or_age_h > 72)
   - *Contributions*:
     - S01: 0
     - S09: 1 (open)
     - S06: 0
     - S08: 0 (transferred)

4. **Competing-risk hazard for transfer (_transfer)**
   - *Definition*: Cause-specific hazard for transfer events
   - *Contributions*:
     - S08: contributes to _transfer
     - S32: contributes to _transfer

**Key distinction**: Transfer cases are not censored but competing events with unknown outcomes.

## 2. Event and Censoring Encoding

| observed_status | Event Indicator | Competing Risk | Censoring Rule | Sensitivity Alternatives |
|-----------------|-----------------|----------------|----------------|---------------------------|
| resolved        | 1               | 0              | No             | None                      |
| withdrawn       | 0               | 1              | No             | Treat as censored (alt1)  |
| rejected        | 0               | 2              | No             | Treat as censored (alt2)  |
| transferred     | 0               | 3              | No             | 1) Treat as censored<br>2) Treat as event with unknown outcome<br>3) Treat as event with 50% probability of breach |
| open            | 0               | 0              | Yes (age < 72) | None                      |

**Transfer treatment alternatives**:
1. **Standard**: Competing risk (no censoring)
2. **Pessimistic**: Treat as censored at transfer time
3. **Optimistic**: Treat as resolved at transfer time
4. **Uncertainty**: Model as interval-censored (transfer time to cutoff)

## 3. Why Naive Completed-Case Analysis is Biased

**Survivor bias**: Only resolved cases (e.g., S01, S02) are analyzed, ignoring withdrawn/rejected/transferred cases (S05, S06, S08) which may have different characteristics.

**Informative censoring**: Transferred cases (S08, S32) have:
- Longer durations (68h, 96h)
- Higher priority (P1)
- Escalation before transfer
This suggests transfers are not random censoring but related to case severity.

**Competing risks**: Withdrawals (S06, S30) and rejections (S05, S14) represent different failure modes than transfers, requiring cause-specific analysis.

**Cohort imbalance**: Cohort B shows:
- Different process paths (e.g., S16 starts with AutoCheck)
- Different outcomes (S21 transferred vs S18 resolved)
- Potential policy effects (automated screening)

**Active vs. passive open cases**:
- Cases open at 72h (S09, S24) vs. cases open at cutoff (S26, S31)
- Different risk profiles due to:
  - Longer event gaps (S26: 72h gap vs S24: 4h gap)
  - Different prefix patterns (S26: Review vs S24: Review)

## 4. Statistical Analysis Plan

**Primary approach**: Cause-specific hazards (Fine-Gray model) for:
- Resolution (primary outcome)
- Transfer (key competing risk)
- Withdrawal/Rejection (secondary competing risks)

**Secondary approach**: Multi-state model with:
- States: Open, Resolved, Withdrawn, Rejected, Transferred
- Transitions: Submission  Screening  Review/Escalate  Resolution/Withdrawal/Rejection/Transfer

**Justification**:
- Handles competing risks properly
- Accounts for transfers as non-censored events
- Can incorporate process features as time-varying covariates
- Provides state-specific probabilities

**Alternative methods considered**:
- Kaplan-Meier: Ignores competing risks
- Aalen-Johansen: Good for multi-state but complex
- Landmarking: Useful for time-varying covariates but loses information
- Restricted mean time: Less interpretable for tail risk

## 5. Process-Aware Features and Stage Hazards

**Derived features from prefixes**:

1. **Baseline covariates** (time-invariant):
   - Initial priority (P1-P3)
   - Cohort (A/B)
   - First activity after Submit (Screen vs AutoCheck)

2. **Time-varying covariates** (potential leakage):
   - Current stage (Screening, Review, Escalation)
   - Number of reviews (from prefix length)
   - Escalation timing (hours from Submit)
   - Last event gap (last_event_gap_h)

3. **Post-treatment features**:
   - Rework count (rework_count)
   - Escalation flag (escalated)
   - Path pattern (e.g., "ScreenReviewEscalateTransfer")

**Leakage risks**:
- Escalation timing cannot be baseline covariate (occurs after case start)
- Rework count requires careful definition (is it before/after escalation?)
- Last event gap is post-treatment but may reflect case severity

**Proposed state-transition diagram**:
```
[Submit]  [Screening]  [Review/Escalation]  [Resolution/Withdrawal/Rejection/Transfer]
                     
                [Rework]  [Review/Escalation]
```

## 6. Sensitivity Analysis

**Three key variations**:

1. **Transfer treatment**:
   - Baseline: Competing risk
   - Alternative 1: Treat as censored
   - Alternative 2: Treat as resolved (optimistic)
   - Alternative 3: Model as interval-censored (transfer time to cutoff)

2. **Withdrawal/Rejection treatment**:
   - Baseline: Competing risks
   - Alternative: Treat as censored

3. **Informative censoring**:
   - Baseline: Standard analysis
   - Alternative: Weight cases by inverse probability of transfer

**Qualitative conclusions that could reverse**:
- The impact of cohort B's policy changes
- The relationship between priority and transfer risk
- The effectiveness of escalation in reducing SLA breaches

## 7. Operational Interpretation

**Alerts**:
- "High-risk cases": Cases in Review stage with >48h event gap (e.g., S25)
- "At-risk transfers": Cases with EscalateTransfer path (S08, S32)

**Workload actions**:
1. For cases with long Review gaps (>24h):
   - Escalate to higher priority
   - Assign to specialized reviewer
2. For cases with EscalateTransfer path:
   - Review transfer justification
   - Consider alternative resolution paths

**SLA governance**:
- Set priority-specific SLA targets:
  - P1: 95% resolution by 48h
  - P2: 90% resolution by 72h
  - P3: 80% resolution by 72h
- Monitor transfer rates by cohort and priority
- Implement process mining dashboards showing:
  - Path frequency distributions
  - Time-to-event distributions by stage
  - Escalation timing patterns

**Fairness checks**:
- Compare SLA breach rates by:
  - Priority within cohort
  - Cohort within priority
- Test for interaction effects between cohort and priority

def encode_events(df):
    df['event_time'] = df['duration_or_age_h']
    df['event'] = np.where(df['observed_status'] == 'resolved', 1,
                          np.where(df['observed_status'] == 'transferred', 0,
                                   np.where(df['observed_status'] == 'withdrawn', 2,
                                            np.where(df['observed_status'] == 'rejected', 3, 0))))
    df['censoring'] = np.where(df['observed_status'] == 'open', 1, 0)
    df['transfer_scenario'] = 0  # 0: competing risk, 1: censored, 2: resolved

    # Alternative transfer treatments
    df.loc[df['observed_status'] == 'transferred', 'transfer_scenario'] = 1  # censored
    # df.loc[df['observed_status'] == 'transferred', 'transfer_scenario'] = 2  # resolved

    return df

# 3. Create survival-ready data
def create_survival_data(df):
    # For cases with event_time > 72, we consider them as censored at 72
    df['event_time'] = np.minimum(df['duration_or_age_h'], 72)
    df['event'] = np.where(df['duration_or_age_h'] > 72, 0, df['event'])
    df['censoring'] = np.where(df['observed_status'] == 'open' & (df['duration_or_age_h'] < 72), 1, 0)
    df['censoring'] = np.where(df['observed_status'] == 'transferred', 0, df['censoring'])

    return df

df_surv = create_survival_data(df_encoded)

# 4. Cohort/priority-stratified analysis
def stratified_analysis(df):
    # Create stratified datasets
    strata = ['A_P1', 'A_P2', 'A_P3', 'B_P1', 'B_P2', 'B_P3']
    stratified = []

    for s in strata:
        subset = df[df['cohort'] + '_' + df['priority'] == s]
        kmf = KaplanMeierFitter()
        kmf.fit(subset['event_time'], event_observed=subset['event'])
        stratified.append({
            'stratum': s,
            'median_survival': kmf.median_survival_time_,
            'survival_prob_72': kmf.survival_function_(72)[0]
        })

    return pd.DataFrame(stratified)

def sensitivity_comparison(df):
    # Baseline: competing risk
    df_baseline = df.copy()
    df_baseline['event'] = np.where(df_baseline['observed_status'] == 'transferred', 0, df_baseline['event'])

    # Alternative 1: treat transfers as censored
    df_alt1 = df.copy()
    df_alt1.loc[df_alt1['observed_status'] == 'transferred', 'event'] = 0
    df_alt1.loc[df_alt1['observed_status'] == 'transferred', 'censoring'] = 1

    # Compare survival probabilities at 72h
    kmf_baseline = KaplanMeierFitter()
    kmf_baseline.fit(df_baseline['event_time'], event_observed=df_baseline['event'])
    surv_baseline = kmf_baseline.survival_function_(72)[0]

    kmf_alt1 = KaplanMeierFitter()
    kmf_alt1.fit(df_alt1['event_time'], event_observed=df_alt1['event'])
    surv_alt1 = kmf_alt1.survival_function_(72)[0]

    return {
        'baseline_survival': surv_baseline,
        'alt1_survival': surv_alt1,
        'difference': surv_baseline - surv_alt1
    }

2. **External outcomes after transfer**: Current analysis treats transfers as unknown outcomes

4. **Time-varying workload**: Could explain event gaps
5. **Assignment mechanism**: To understand cohort differences
6. **Policy rollout compliance**: To properly interpret cohort differences
