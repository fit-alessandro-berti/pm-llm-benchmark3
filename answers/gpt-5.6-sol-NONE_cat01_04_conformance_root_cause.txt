The first four hypotheses chiefly explain the **measured conformance collapse**. Employee noncompliance ranks lower as an explanation of that collapse, but remains a potentially material **operational concern** because even a small number of genuine check bypasses can be serious.

The collapse is best explained by several mechanisms superimposed on the same traces. The UI release changed the observed name of a stable function, so the checker produced a log move for `Risk Screen` and a model move for `Classify`. The gateway then inserted `Queue Routed`, increasing recording granularity without necessarily changing work. On June 15, ingestion timestamps replaced source chronology for `Decision` and `Notify`, creating apparent order violations. The staged recovery—32% raw, 58% after mapping, 81% after technical-event removal, and 89% after source ordering—is unusually strong abductive evidence for those measurement mechanisms.

A second mechanism begins in August: policy truly changes the required process for high-value claims while the normative tree remains unchanged. `Supervisor Sign-off` is therefore simultaneously a real process event and a false deviation relative to the obsolete model. An unguarded optional-sign-off model improves fitness but may accept sign-off omissions for high-value claims and unnecessary sign-offs for low-value claims.

Residual enhanced reviews without a recorded compliance check cannot yet be classified. They may reflect reviewer bypass, missing extraction, or semantic mismatch. `Manual Override` likewise may be legitimate routing correction, unauthorized behavior, or newly visible behavior after changed logging.

Stable cycle time, approval, and appeal rates favor a measurement/model explanation for the aggregate collapse, but do not prove it. Rare compliance harms may not move aggregate outcomes, appeals are an insensitive proxy, case mix can offset effects, and incident detection is acknowledged to be incomplete.

def expand_variant_frequencies(variant_freqs):
    """Return one PM4Py textual trace per case."""
    lines = []
    for activities, count in variant_freqs:
        trace = ",".join(activities)
        lines.extend([trace] * count)
    return "\n".join(lines)

def print_top_dfg(name, log, n=12):

# 5. Alignment diagnostics, alignment fitness, and precision

def alignment_diagnostics(log, net, im, fm):
    # Preferred high-level PM4Py API.
    if hasattr(pm4py, "conformance_diagnostics_alignments"):
        return pm4py.conformance_diagnostics_alignments(log, net, im, fm)

    # Compatibility fallback for PM4Py installations exposing the algorithm module.
    from pm4py.algo.conformance.alignments.petri_net import algorithm as alignments
    return alignments.apply_log(log, net, im, fm)

def evaluate_alignment_fitness(log, net, im, fm):
    # Preferred high-level API.
    if hasattr(pm4py, "fitness_alignments"):
        result = pm4py.fitness_alignments(log, net, im, fm)
        if isinstance(result, dict):
            return result
        return {"average_trace_fitness": float(result)}

    # Compatibility fallback.
    from pm4py.algo.evaluation.replay_fitness import algorithm as replay_fitness
    return replay_fitness.apply(
        log, net, im, fm,
        variant=replay_fitness.Variants.ALIGNMENT_BASED
    )

def evaluate_precision(log, net, im, fm):
    if hasattr(pm4py, "precision_alignments"):
        return float(pm4py.precision_alignments(log, net, im, fm))

    from pm4py.algo.evaluation.precision import algorithm as precision_evaluator
    return float(precision_evaluator.apply(
        log, net, im, fm,
        variant=precision_evaluator.Variants.ALIGN_ETCONFORMANCE
    ))

def is_skip(value):
    return value is None or value == ">>"

def move_counts(diagnostics):
    """
    Count visible log-only and model-only moves.
    PM4Py alignment records usually encode each move as (log_label, model_label),
    where '>>' denotes a skip. Silent model transitions are excluded.
    """
    log_moves = {}
    model_moves = {}

    for result in diagnostics:
        for move in result.get("alignment", []):
            pair = move
            # Some versions attach metadata around the move pair.
            if (
                isinstance(move, tuple)
                and len(move) >= 1
                and isinstance(move[0], tuple)
                and len(move[0]) == 2
            ):
                pair = move[0]

            if not isinstance(pair, tuple) or len(pair) != 2:
                continue

            log_label, model_label = pair

            if not is_skip(log_label) and is_skip(model_label):
                key = str(log_label)
                log_moves[key] = log_moves.get(key, 0) + 1
            elif is_skip(log_label) and not is_skip(model_label):
                # Exclude silent/tau model transitions where identifiable.
                label = str(model_label)
                if label.lower() not in {"none", "tau", "silent"}:
                    model_moves[label] = model_moves.get(label, 0) + 1

    return log_moves, model_moves

def summarize(name, log, net, im, fm, diagnostics_limit=8):
    fitness = evaluate_alignment_fitness(log, net, im, fm)
    precision = evaluate_precision(log, net, im, fm)
    diagnostics = alignment_diagnostics(log, net, im, fm)
    log_moves, model_moves = move_counts(diagnostics)

    trace_fitness = fitness.get(
        "average_trace_fitness",
        fitness.get("log_fitness", fitness.get("perc_fit_traces", None))
    )
    fit_pct = fitness.get("percentage_of_fitting_traces",
                          fitness.get("perc_fit_traces", None))

    print(f"\n=== {name} ===")
    print("fitness result:", fitness)
    print("selected trace/log fitness:", trace_fitness)
    print("fitting traces percentage if available:", fit_pct)
    print("alignment precision:", round(precision, 4))
    print("dominant visible log moves:",
          sorted(log_moves.items(), key=lambda x: -x[1])[:diagnostics_limit])
    print("dominant visible model moves:",
          sorted(model_moves.items(), key=lambda x: -x[1])[:diagnostics_limit])
    return {
        "fitness": fitness,
        "precision": precision,
        "diagnostics": diagnostics,
        "log_moves": log_moves,
        "model_moves": model_moves,
    }

# 6-7. Transparent normalization: map the alias and optionally remove queue events

def normalize_variant_frequencies(variant_freqs, remove_queue=False):
    normalized = {}
    for activities, count in variant_freqs:
        new_trace = []
        for activity in activities:
            mapped = "Classify" if activity == "Risk Screen" else activity
            if remove_queue and mapped == "Queue Routed":
                continue
            new_trace.append(mapped)
        key = tuple(new_trace)
        normalized[key] = normalized.get(key, 0) + count
    return [(list(trace), count) for trace, count in normalized.items()]

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a compound observation-and-model failure rather than a sudden workforce-wide behavioral deterioration. Confidence is **very high (95%)**. The UI renamed `Classify`; the gateway inserted `Queue Routed`; and the ETL substituted ingestion timestamps for authoritative ordering. These mechanisms are temporally aligned with the decline and, more importantly, are discriminated by the staged fitness recovery from 32% to 89%. From August, an additional policy/model version mismatch caused valid `Supervisor Sign-off` events to be penalized. Thus, “the log became less conformant” is not equivalent to “the work became broadly less compliant.”

A real compliance problem nevertheless remains possible, with **moderate confidence that some residual risk exists (45%)**, but low confidence that confirmed violations increased. The 55 enhanced-review traces without recorded checks are substantively important. They could be true bypasses, missing events, or integration failures; no reliable audit currently separates those causes. `Manual Override` is also real behavior and requires authorization and reason analysis rather than automatic deletion. Stable appeals, approval rates, and cycle times reduce the probability of severe aggregate deterioration but are weak safeguards against rare regulated failures.

**Immediate IT actions:** preserve raw records; restore source-sequence ordering; expose both source and ingestion timestamps; document aliases; tag gateway events by provenance; reconcile missing compliance events and resource fields. Do not overwrite the raw log.

**Process-owner actions:** version the model at the August policy boundary; specify the correct sign-off insertion point; classify routing and override semantics; create a data-aware rule requiring sign-off only for claims above EUR 50,000. Compare fitness and precision because an optional sign-off can overfit.

**Compliance actions:** conduct a blind, stratified source audit of every feasible missing-check case plus controls; verify notification chronology; test sign-off compliance by value; assess override authorization; and examine reviewer patterns only after technical normalization and case-mix adjustment.

It must **not** yet be claimed that employees caused the collapse, that all missing checks are extraction defects, that no compliance issue exists, or that the optional-sign-off candidate is the correct policy model.

## 8. Model-governance recommendation

1. **Version models with effective dates:** Bind each policy and process-tree version to its effective interval, owner, approval, migration record, and applicable case population; never score post-change cases solely against a superseded model.

2. **Maintain event-semantic contracts:** Define each business activity’s canonical name, aliases, trigger, lifecycle, source, actor semantics, and backward compatibility; UI renaming must not silently change conformance identities.

3. **Govern technical events explicitly:** Maintain an allowlist of business events and a separately tagged technical-event taxonomy; removal must be provenance-based and auditable, never motivated only by improved fitness.

4. **Preserve timestamp provenance:** Store source time, ingestion time, timezone, sequence number, transaction ID, and ordering rules independently; prohibit ingestion time from silently replacing business chronology.

5. **Represent data-aware constraints:** Encode value thresholds, authorizations, and policy guards outside or alongside the control-flow model; do not substitute unconditional optional branches for obligations such as the EUR 50,000 sign-off rule.

6. **Require post-release validation:** After UI, gateway, ETL, or policy releases, compare variants, DFGs, fitness, precision, attributes, and provenance against a baseline, then manually audit representative changed and residual-deviation cases before compliance reporting.
