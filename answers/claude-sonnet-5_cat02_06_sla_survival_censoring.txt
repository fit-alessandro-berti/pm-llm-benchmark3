# 1. SLA estimands and time definitions

**Time origin (t=0):** the `Submit` event. All durations (`duration_or_age_h`) are measured from this origin, which is the only anchor we have — we do not have absolute calendar timestamps for intermediate activities.

**Horizon:**  = 72h, the contractual SLA.

**Terminal absorbing states:** `Resolve`, `Withdraw`, `Reject` (internally observed), plus `Transfer` (internal observation stops; true terminal state unknown). `open` at the extract cutoff is a **transient, not-yet-terminal** state, not a fifth outcome.

Because "breach probability" is ambiguous, at least four estimands should be distinguished:

| # | Estimand | Formal target | Decision it serves |
|---|---|---|---|
| E1 | **SLA-miss probability**: P(not yet resolved by 72h) = 1  CIFResolve(72) | Cumulative-incidence-style, treats Withdraw/Reject/Transfer as competing causes that preclude internal resolution | Contractual/penalty reporting: "what fraction of the portfolio failed to resolve inside the window, for any reason" |
| E2 | **Late-success cumulative incidence**: CIFResolve(t) for t>72, i.e. resolutions that occur but after 72h | Competing-risks CIF restricted to the tail | Expectation-setting / SLA-credit negotiation for the "recoverable but late" subset |
| E3 | **Still-open probability**: P(no terminal disposition yet at 72h) = S_overall(72) (all-cause survival of "time-to-any-terminal-event") | Multistate occupancy probability of the transient state | Workforce/queue management: how many cases will still be sitting in the pipeline needing attention at the 72h mark |
| E4 | **Cause-specific risk under competing outcomes**: cause-specific hazards / subdistribution hazards for Resolve vs Withdraw vs Reject vs Transfer | Etiological decomposition | Process improvement: which failure mode dominates and when |

**How the four illustrative cases contribute:**

- **S03 (resolved at 76h):** Fully observed, not censored. E1: counts as an *observed breach* (t=76>72). E2: contributes an event to the late-CIF at t=76. E3: at t=72 the case had not yet terminated, so it contributes to the "still non-terminal at 72h" risk set as a case that *later* exits — i.e. it is at risk in the occupancy calculation, then leaves the open state at 76h.
- **S09 (open at 92h, gap 31h):** Not resolved, censored at cutoff for its *eventual* fate. E1: because age (92h) already exceeds 72h with no resolution recorded, this is a **deterministic, already-observed breach** — no censoring ambiguity here, even though we don't know if/when it will ever terminate. E2: right-censored at 92h for "will it still resolve late" — genuinely unknown. E3: certainly occupied the open state through t=72 (age>72 while still open) — deterministic "still open at 72" observation, not censored for that question.
- **S06 (withdrawn at 27h):** Fully observed exit into a competing state before 72h. E1: contributes as either a competing event (permanently "not resolved") or as censored, *depending on the assumption chosen* (see §2) — this is exactly the ambiguity the task warns about. E2: precluded — contributes 0 to late-resolution CIF from t=27 onward. E3: not open at 72h; it left the transient state at t=27.
- **S08 (transferred at 68h):** Exits internal observation just before the horizon. E1: the central ambiguity — is this a failure (never resolved internally), a censored/unknown case, or out-of-scope? Three defensible codings exist (§2, §6). E2: internal system cannot ever record a `Resolve` for this case, so under a "no fabricated resolution" rule it contributes 0 to CIFResolve from 68h on, or is censored, depending on scenario. E3: not open at 72h (it is in a `Transferred` absorbing/unknown state) — but whether that should be treated as a governance "success," "failure," or "unmeasurable" is a policy choice, not a statistical one.

# 2. Event and censoring encoding

| `observed_status` | Event indicator (E1: unresolved@72) | Competing-risk cause code | Censoring rule | Sensitivity alternatives |
|---|---|---|---|---|
| `resolved`, t  72 | 0 (SLA met) | cause = 1 (Resolve) | none — fully observed | — |
| `resolved`, t > 72 | 1 (observed breach) | cause = 1 (Resolve, late) | none — fully observed, exact time known | classify separately as "late success" (E2) rather than lumping with never-resolved failures |
| `withdrawn` | ambiguous by design | cause = 2 | (a) competing event, absorbing, not censored — "resolution structurally impossible from here"; (b) right-censor at withdrawal time — "unrelated exit, would have continued toward Resolve" | run both; report divergence |
| `rejected` | ambiguous by design | cause = 3 | same two options as withdrawn | run both; report divergence |
| `transferred` | **most ambiguous** | cause = 4 | **Scenario 1 – "competing/failure":** absorbing state that precludes ever satisfying internal SLA — counted as a permanent non-resolution. **Scenario 2 – "unknown-fate censoring":** right-censor at transfer time; case removed from risk set, contributes no information for or against resolution. **Scenario 3 – "scope exclusion":** case removed from the SLA denominator entirely (treated as no longer an internally-owned case, e.g. contractually the SLA clock stops at hand-off) | compare all three (§6) — qualitative conclusions can reverse between them |
| `open`, age  72 | not yet determinable — right-censored at cutoff | cause = 0 (censored, still at risk) | administrative right-censoring at the observed age | none needed for E1 (genuinely unresolved as of now); relevant for E2/E3 group estimators |
| `open`, age > 72 | 1 (deterministic breach for E1) | cause = 0 for the *eventual*-outcome question (right-censored at cutoff) | right-censored at cutoff for eventual disposition; **not** censored for the binary "missed 72h" fact | none needed for the breach flag itself; eventual-outcome uncertainty remains |

Two points the table intentionally keeps separate: (i) *right censoring* (we stop observing before the outcome is known — applies to all `open` rows and, under scenario 2, to `transferred`) versus (ii) *competing events* (an alternative absorbing state is reached and precludes the event of interest — applies to `withdrawn`/`rejected`/`transferred` under scenario 1) versus (iii) *already-observed breaches* (S03, S13, S20, S28, and all `open` rows with age>72) which require no assumption at all for E1.

# 3. Why naive completed-case analysis is biased

**Survivor bias from dropping opens.** Nine of 32 cases (28%) are `open` (S09,S10,S11,S15,S24,S25,S26,S29,S31). A "completed-case" analysis that keeps only resolved/withdrawn/rejected/transferred rows discards exactly the cases that, by construction, have not yet finished — which mechanically over-represents *fast* cases in the sample. S26 (age 104h, `last_event_gap_h`=72h — essentially no activity since near the start) and S11 (age 81h, gap 55h, **P1** priority) are clear latent severe-breach signals; dropping them makes the portfolio look far healthier than it is, and specifically hides that the highest-priority tier has a stalled case.

**Informative censoring.** Standard KM/AJ assumes censoring time is independent of the outcome process. Here `last_event_gap_h` varies enormously among open cases: S15 (gap 2h, apparently still being actively worked) versus S26 (gap 72h, apparently abandoned) versus S11 (gap 55h). A large gap is plausibly *itself* a symptom of the case being stuck (harder, escalation failure, resource contention) — i.e., the mechanism generating "still open at cutoff" is correlated with the mechanism generating bad outcomes. Treating all opens as identically, non-informatively censored (as naive KM does) will understate breach risk for the S26/S11-type cases and overstate it for S15/S31-type cases if pooled uncritically.

**Competing risks.** S08 and S32 are `transferred` — if these are simply dropped or treated as ordinary censoring in a plain KM-for-Resolve, the estimator implicitly assumes they remain "at risk" of eventually resolving internally, which is impossible once transferred. This is the textbook mechanism by which naive KM overestimates cumulative incidence of the event of interest under competing risks (Kalbfleisch–Prentice bias).

**Cohort imbalance and confounding.** Cohort B follows the screening/escalation policy change, but rollout compliance is incomplete: `AutoCheck` appears in 13/17 cohort-B prefixes but is *absent* in S20, S23, S26, S30 (i.e., "Cohort B" is not the same as "received the new screening step"). Any naive A-vs-B comparison of breach rates conflates the policy effect with (i) non-random assignment to cohort and (ii) within-cohort non-compliance — e.g., S26 (a severe open/stalled case) is a *non-compliant* Cohort-B case, so if it drives an apparent "B is worse" finding, that is a compliance artifact, not evidence against the policy.

**Open cases below vs. above 72h are qualitatively different.** S09 (92h) and S11 (81h) are *already* SLA breaches with certainty — the only open question is eventual disposition/duration, not SLA compliance. S15 (35h) and S31 (23h) are *not yet* determined — they might still resolve within the window. Lumping both groups into one undifferentiated "censored, unknown" category (or dropping them) erases this distinction and either double-counts uncertainty for S09/S11 or under-counts real forward risk for S15/S31.

# 4. Statistical analysis plan

| Method | What it estimates | Fit for this dataset |
|---|---|---|
| **Kaplan–Meier (single event)** | Marginal survival for one event type, treating everything else as non-informative censoring | Appropriate *only* for E3 (time-to-any-terminal-event, where "any terminal" is the single event and `open` is the censoring) — not appropriate for E1/E4 because it would silently treat competing outcomes as innocuous censoring |
| **Aalen–Johansen / non-parametric CIF** | Cumulative incidence per cause, correctly crediting competing risks with their own absorbing mass | **Primary tool for E1/E2/E4** here: assumption-lean, works with n=32, does not require proportional hazards, and directly yields E1 = 1CIF_Resolve(72) and E3 = S_overall(72) from the same fit |
| **Cause-specific hazards (Nelson–Aalen/Cox)** | Instantaneous rate of each cause among those still at risk | Diagnostic secondary tool: tells us *when* each risk (rework loops, escalation, transfer) is concentrated; hazard ratios do **not** map linearly onto CIF differences under competing risks, so should not be reported as "risk" |
| **Subdistribution hazards (Fine–Gray)** | Direct regression on the CIF scale | Conceptually the right regression tool for covariate-adjusted E1, but with n=32 and only 4 transfers/7 withdrawals+rejections, a multi-covariate Fine-Gray model will be badly underpowered/overfit — usable only as an exploratory, wide-CI supplement |
| **Restricted mean time (RMST) to 72h** | Area under the survival curve up to  — a single interpretable number ("expected hours in the pipeline before 72h") | Good executive summary statistic, robust to non-proportional hazards; recommended as a secondary scalar alongside CIF(72) |
| **Landmarking** | Conditions on being event-free (open) at an intermediate landmark s<72, then estimates risk over (s,72] using covariates known at s | The principled way to use `Escalate`/`Rework` information without immortal-time bias — recommended for any model that wants to use process state as a predictor |
| **Multi-state model (Aalen–Johansen transition probabilities over a full state graph)** | Richest representation: transition-specific hazards between Screen/AutoCheck/Review/Escalate/Rework/terminal states | Conceptually the right target model (§5), but **not estimable from this extract**: we have only total elapsed time and last-gap, not per-activity timestamps, so transition-specific sojourn times cannot be recovered without fabricating data |

**Recommendation.** Primary: **Aalen–Johansen competing-risks CIF**, computed under each of the three transfer-treatment scenarios and stratified by cohort/priority, because it (i) handles competing risks correctly, (ii) makes no proportional-hazards or parametric assumption inappropriate for n=32, (iii) directly produces both E1 and E3 from one fit, and (iv) is transparent about which observations are events vs. censored. Secondary: **cause-specific Nelson–Aalen hazards** (for diagnostic timing of failure modes) plus **RMST(72h)** as a single reportable number, with **Fine–Gray regression treated only as low-power exploratory sensitivity**, not a headline result. The full multi-state model is recommended as the *target* architecture (§5) but deferred pending activity-level timestamps (§9).

# 5. Process-aware features and stage hazards

From the `prefix` field we can derive:

- **Path length / number of activities so far** — time-varying by construction; safe as a *time-varying* covariate measured at a landmark, unsafe as a "baseline" predictor of final duration for terminal cases (it partly encodes how long the case took, i.e. it grows with the very quantity we're modeling).
- **Current stage / last activity before terminal or cutoff** (e.g., S31 sits at `Screen`, S10/S11/S25/S29 sit at `Escalate`, S15/S24 sit at `Review`) — genuinely observable in real time for open cases; this is the correct **time-varying state** for a multistate model, not a baseline covariate.
- **`escalated` flag** — occurs *after* Submit, sometimes late in a long case (e.g., S13's escalation happens only after a rework/review loop inside a 110h case). Using it as a fixed baseline covariate in a t=0 model is a textbook **immortal-time / leakage bias**: a case must already have survived long enough to be escalated, so coding it as "known at time 0" implicitly gives escalated cases credit for surviving. Correct treatment: a 01 time-varying covariate with its own (unknown, since we lack timestamps) transition time, or a landmark analysis using "escalated by landmark s" only.
- **`rework_count`** — same problem as `escalated`: it is a *running tally over the case's life*, not known at t=0. Safe only as time-varying / landmark-truncated.
- **`last_event_gap_h`** — inherently a *live* signal ("how long has this case been quiet"), well suited as a real-time monitoring feature / alert trigger, not as a static baseline predictor.
- **Presence/position of `AutoCheck`** — appears very early (2nd/3rd event) in most traces, so it is the feature closest to a legitimate baseline covariate (reflects which intake path a case entered on), *and* it doubles as a rollout-compliance indicator (present in most, not all, Cohort-B traces; occasionally present in Cohort-A, e.g. S01, S15). Still an assumption, since we have no timestamp proving it precedes any material elapsed time.
- **Priority, cohort** — assigned at/near Submit; treat as genuine baseline covariates (with the caveat, in §3/§6, that cohort assignment is non-random and compliance is incomplete).
- **Path pattern / variant** (e.g., "has a ReviewEscalate loop", "has Rework") — useful descriptive control-flow feature, but if computed on the *full, completed* trace it is post-outcome information for terminal cases; must be truncated to the prefix available at the chosen landmark when used predictively.

# 6. Sensitivity analysis

1. **Transfer treatment (Scenario 1 vs 2 vs 3, §2).** Cohort A has 1/15 transfers (S08); Cohort B has 2/17 (S21, S32) — proportionally more transfers in B. Under Scenario 1 ("transfer = failure"), Cohort B's E1 risk is pushed up relative to A; under Scenario 2/3 (censor or exclude), that gap shrinks or reverses in relative terms once denominators change. **Reversible conclusion:** "Cohort B has lower/higher SLA-miss probability than A" is fragile and can flip depending purely on this coding choice — it should never be reported as a single number without stating the scenario.
2. **Withdrawal/rejection treatment (competing vs. censor vs. scope-exclude).** Cohort A: 4/15 withdrawn+rejected (S05,S06,S12,S14); Cohort B: 3/17 (S22,S23,S30). If these are excluded from the SLA denominator entirely (treated as client-driven non-applicable cases), the effective sample sizes and hence E1 point estimates shift disproportionately between cohorts (A loses a larger share of its N). **Reversible conclusion:** relative cohort ranking on E1 can change sign depending on whether withdrawals/rejections are "in scope."
3. **Informative-censoring bracket for open cases.** Compare (i) naive AJ (treats all opens as non-informatively censored), (ii) "worst-case" bound — treat every currently open case as a permanent non-resolution (upper bound on E1), (iii) "best-case" bound — treat every open case as if it will resolve within horizon (lower bound on E1). With 9/32 (28%) open, this bracket is wide by construction. **Reversible conclusion:** whether the portfolio-level SLA-miss probability is "moderate" (~naive estimate) or "high" (near worst-case bound) is not resolvable with current data; only a bracket, not a point estimate, is defensible.
4. **Cohort-policy effect: intention-to-treat vs. compliance-adjusted.** Compare crude A-vs-B CIF(72) against a version restricting Cohort B to only the `AutoCheck`-present (compliant) cases, dropping the non-compliant B cases (S20, S23, S26, S30 — note S26 is one of the worst stalled cases). **Reversible conclusion:** an apparent "policy improved SLA performance" finding could be entirely attributable to the compliant subgroup being a healthier selection of cases, or could strengthen once non-compliant noise is removed — direction is not determinable from the table alone, which is exactly why this must be flagged as associational (§7), not causal.

# 7. Operational interpretation

- **Alerts.** Use the *live* features (elapsed age vs. 72h, current stage, `last_event_gap_h`) to flag cases whose landmark-conditional CIF (§4, §5) exceeds a threshold — e.g., any case with age>48h and gap>24h and still in `Review`/`Escalate` (S10, S11, S25, S29 are current examples) should trigger a workload/escalation alert. This is a **monitoring rule derived from an estimated risk**, not a causal claim that intervening will change the outcome.
- **Workload actions.** Convert stratified CIF/RMST outputs into expected counts (e.g., "X% of the current open book is expected to still be open past 72h") to drive staffing/triage decisions, not individual-case blame.
- **SLA governance.** The transfer/withdraw/reject coding choices in §2/§6 are **policy decisions**, not statistical ones. Recommend the organization pre-register (a) whether transferred cases count against the SLA, (b) whether withdrawn/rejected cases are in scope, and report the primary CIF plus the bracket from §6.3 rather than a single number.
- **No causal language.** Cohort B vs. A differences, or any hazard ratio from a Fine–Gray/Cox fit, must be reported as **associations under non-random, incompletely-complied assignment**, not as the causal effect of the screening/escalation policy. If a causal estimate is required, recommend (a) using AutoCheck-compliance as a stratifying/IPW-weighting variable, or (b) a difference-in-differences design once true pre/post calendar timestamps are available (§9) — neither is currently executable.
- **Calibration.** With n=32, only coarse checks are feasible: bin predicted risk (e.g., from a landmark model) into 2–3 groups and compare to observed proportions within priority tiers; do not present decile calibration plots as if they were reliable with this sample size.
- **Fairness by priority/cohort.** A concrete, worth-flagging pattern in the raw data: of the 8 `P1` cases (S04,S08,S11,S18,S21,S25,S29,S32), only 2 resolved cleanly within 72h (S04, S18); 3 were transferred (S08,S21,S32) and 2 are open with large gaps well past 72h (S11,S25). Highest-priority labeling is **not** visibly translating into faster/cleaner resolution in this sample. This should be surfaced as a fairness/consistency check on the priority-handling process — *not* asserted as a causal failure of prioritization, since P1 cases may simply be inherently harder (confounding by indication) with only 8 cases to judge from.

def build_scenario(data: pd.DataFrame, transfer_mode: str) -> pd.DataFrame:
    """Encode one of 3 transfer-treatment scenarios; never drops 'open' rows."""
    d = data.copy()
    if transfer_mode == "competing":       # transfer = its own permanent absorbing failure
        d["cause"] = d["cause_raw"]
    elif transfer_mode == "censor_unknown":  # transfer = right-censored, fate unknown
        d["cause"] = d["cause_raw"].replace({4: 0})
    elif transfer_mode == "exclude_scope":   # transfer = out of SLA scope entirely
        d = d[d["observed_status"] != "transferred"].copy()
        d["cause"] = d["cause_raw"]
    else:
        raise ValueError(transfer_mode)
    return d

# ---------------------------------------------------------------
# 3) Non-parametric Aalen-Johansen CIF / KM builder (no external survival
#    library assumed to be installed; this is a minimal, transparent
#    implementation). If `lifelines` is available, KaplanMeierFitter /
#    AalenJohansenFitter could replace this block one-for-one.
# ---------------------------------------------------------------
def aalen_johansen(times, causes):
    """Returns time grid, overall all-cause survival S(t), and CIF per cause."""
    times = np.asarray(times, dtype=float)
    causes = np.asarray(causes)
    n = len(times)
    order = np.argsort(times)
    t_sorted, c_sorted = times[order], causes[order]
    unique_causes = sorted(c for c in set(causes) if c != 0)
    at_risk = n
    S = 1.0
    cif = {c: 0.0 for c in unique_causes}
    grid = [(0.0, 1.0, dict(cif))]
    for t in sorted(set(t_sorted)):
        mask = (t_sorted == t)
        n_i = at_risk
        if n_i <= 0:
            break
        d_total = np.sum(mask & (c_sorted != 0))
        for c in unique_causes:
            d_k = np.sum(mask & (c_sorted == c))
            cif[c] += S * (d_k / n_i)
        S *= (1 - d_total / n_i)
        at_risk -= mask.sum()
        grid.append((t, S, dict(cif)))
    return grid

def at_horizon(grid, horizon):
    """Step-function lookup: value in force at time <= horizon."""
    S, cif = 1.0, {}
    for t, s, c in grid:
        if t <= horizon:
            S, cif = s, c
        else:
            break
    return S, cif

# ---------------------------------------------------------------
# 4) Estimand computation for a given sub-dataframe
#    E1 = 1 - CIF_resolve(72);  E3 = S_overall(72)
# ---------------------------------------------------------------
def estimands_at(data, horizon=72.0):
    grid = aalen_johansen(data["time"].values, data["cause"].values)
    S72, cif72 = at_horizon(grid, horizon)
    e1 = 1 - cif72.get(1, 0.0)     # not resolved by 72h
    e3 = S72                        # still non-terminal (open) at 72h
    return e1, e3, cif72

print("=== Sensitivity: transfer-treatment scenarios (whole portfolio) ===")
for mode in ["competing", "censor_unknown", "exclude_scope"]:
    d = build_scenario(df, mode)
    e1, e3, cif72 = estimands_at(d)
    print(f"{mode:16s}  N={len(d):2d}  E1(not resolved by 72h)={e1:.3f}  "
          f"E3(still open at 72h)={e3:.3f}  CIF_by_cause@72={ {k: round(v,3) for k,v in cif72.items()} }")

print("\n=== Cohort x Priority stratified analysis (scenario='competing') ===")
