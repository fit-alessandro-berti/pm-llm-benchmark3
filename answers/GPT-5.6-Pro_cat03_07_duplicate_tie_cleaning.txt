## 1. Duplicate-handling decision tree

Start with a candidate group produced from source identity, payload similarity, equal or near timestamps, harmonized activity, and overlapping E2O relations. Do not decide from timestamp and activity alone.

1. **Exact identity gate.** Are source, `source_event_key`, business payload, timestamp, source sequence, and qualified E2O relation set identical, with no correction/version semantics? **Terminal: drop** the later technical copy after attaching its raw eid and ingestion record to the canonical audit entry. If the same source key carries changed business data, it is not exact; continue as a correction/version candidate.

2. **Verified physical-identity gate.** Does reconciliation evidence or a unique business identifier prove that several records observe one physical occurrence? **Terminal: merge attributes and relations.** Keep one stable canonical eid; preserve every source row, use attribute-level authority rules, and union only compatible object–qualifier relations.

3. **Derivation gate.** Is one event generated from another?

   * One-to-one derivation, no independent lifecycle meaning, and verified message correlation: **terminal: merge attributes and relations**.
   * Independent status transition, different abstraction level, or many-to-one aggregate: **terminal: retain both with refined labels or qualifiers**, such as “WMS transaction” versus “ERP-derived status.”
   * Derivation suspected but lineage unresolved: **terminal: quarantine for review**; the conservative analytical view retains both unchanged and marks the candidate.

4. **Harmonization-collision gate.** Did distinct original source activities receive the same common label? **Terminal: retain both with refined labels or qualifiers.** The common label is evidence of taxonomy compression, not duplication.

5. **Object-instance gate.** Do events concern different discriminating objects, such as I1 versus I2 or M1 versus M2? **Terminal: retain both unchanged**; an optional object-instance qualifier may aid analysis, but relations must remain separate.

6. **Residual unresolved candidate.** No decisive evidence either way: **terminal: quarantine for review** and retain both unchanged in the minimum-change dataset. Never silently choose the first row.

## 3. Timestamp-tie ordering rules

Construct a directed graph for each **original** timestamp, then topologically sort it. The hierarchy is:

1. **Verified domain constraints — semantic:** reconciliation statements and explicit rules, for example e09 before e10 and e12 before e13.
2. **Within-source sequence — semantic within that source only:** compare `source_seq` for PSP-to-PSP or SCANNER-to-SCANNER events; never compare ERP 30 with WMS 110.
3. **Validated lifecycle constraints on shared objects — semantic:** creation before use, authorization before capture, and all required item picks before package packing. Apply only when the lifecycle rule is genuinely valid for the process.
4. **Source-specific semantics and derivation lineage — semantic:** a generated ERP status follows its triggering WMS message; an invoice-level payment summary follows the contributing payment messages.
5. **Ingestion time — merely deterministic and weak:** use only when stable source identity is unavailable, never as a business-order edge, and flag that use.
6. **Stable fallback — merely deterministic:** source, source key, then original or canonical eid. This produces reproducibility, not truth.

Detect cycles. Do not “solve” a conflict by inserting tiny time offsets; quarantine the conflicting constraints or downgrade an explicitly weak rule. Adding microseconds first lets arbitrary row order manufacture a causal-looking sequence, after which DFGs, lifecycle checks, and waiting times repeat that false story. The same warning applies to index-based millisecond offsets: they are an ordering encoding, not measured elapsed time. ([Process Intelligence Solutions][1])

Intended conservative orders are:

* **10:00:** `e03* < e05 < e06 < e07`, where `e03*` represents e03/e04. The first edge inherits SCANNER 551 < 552; both picks precede packing; the ERP status follows the WMS transaction. If e06/e07 are merged, the last two become one event.
* **10:15:** `e08 < e09 < e10`. Only `e09 < e10` is explicitly certain; if warehouse-release-before-acceptance is not validated, e08 is incomparable with that chain and its placement is only deterministic.
* **12:00:** `e11* < e12 < e13 < e14 < e15`, using invoice creation-before-use, PSP 400 < 401 < 402, M1 authorization-before-capture, and summary-after-messages. Without the creation-before-use rule, e11* and e12 are admissibly unordered; the fallback still gives a stable export order.

## 4. Conservative cleaning pipeline

First normalize UTC datatypes and freeze `original_timestamp`, `original_activity`, original eid, source, source key, payload hash, and source sequence. Generate candidate groups and relation signatures, but make no automatic deletion from those candidates. Remove truly exact technical copies only after full event-plus-qualified-relation equality is established.

Next, custom-merge the two strongly verified groups: e03/e04 into e03 and e11/e16 into e11. Retain e06/e07 at separate abstraction levels, retain e08/e09 as separate milestones, and retain e13/e14/e15 as two Payment captures plus one invoice-level summary. Refine e06, e07, e08, e09, and e15 so harmonization no longer creates misleading same-label repetition. Apply qualifier-preserving E2O cleanup, validate all references, build the semantic partial order, then materialize a separate adjusted ordering timestamp. Duration analysis uses the original timestamp view.

For the 17 listed candidates, the expected retained count is **15 events**: two verified pair merges reduce the count by two. The expected E2O count is **39**, assuming the listed relation sets and no additional exact relation-row duplicates. Any further exact technical copies found by the pre-check are reported separately rather than hidden in this count.

## 5. Aggressive alternatives

**Evidence-based semantic merging.** Apply the two verified merges and additionally merge e06/e07 only when a message or correlation identifier proves a one-to-one derivation and the chosen analysis treats both as observations of one packing transition. Retain e08/e09 and all payment events. Expected result: **14 events and 37 E2O relations**. The main damage is loss of the ERP propagation/status milestone and any interface-latency or synchronization analysis between WMS and ERP.

**Mechanically aggressive PM4Py merging.** Run `pm4py.ocel_merge_duplicates(..., have_common_object=True)` on a deep copy. The current implementation groups equal activity/timestamp records through common-object relation groups, rewrites event IDs, keeps one event row, and unions event–object links; it is not an attribute-authority merge. ([Process Intelligence Solutions][1]) On the supplied relations the expected result is **10 events and 28 E2O relations**: it collapses e03/e04/e05, e06/e07, e08/e09, e11/e16, and e13/e14/e15.

`have_common_object=True` is not protective. e13 and e14 share O1 and V1, so one common object is already enough even though M1 and M2 prove distinct partial payments. The same defect collapses the I1 and I2 picks through O1/P1. Most likely damage: erased multiplicity, false multi-object events linking I1 with I2 and M1 with M2, lost source-authoritative attributes, and disappearance of distinct logistics milestones.

An unguarded `ocel_drop_duplicates` fails differently: because it removes relation triples, it can leave e05 attached only to I2 and e14 attached only to M2 after their shared O1/P1/V1 rows were kept for an earlier event. That is why the implementation below invokes it only behind a relation-level safety wrapper. ([Process Intelligence Solutions][1])

## 6. PM4Py-oriented Python implementation

In current PM4Py, `ocel_drop_duplicates` removes E2O rows by activity, timestamp, and object identifier and then propagates the relation filtering; it is therefore wrapped below with event-specific temporary labels and qualifier checks. `ocel_sort_by_additional_column` sorts on the timestamp plus a supplied ordering column, and `ocel_add_index_based_timedelta` changes both event and relation timestamps only after that order is fixed. Because the latter uses the event index, the code also creates separate original-time views for performance analysis. ([Process Intelligence Solutions][1])

```python
from __future__ import annotations

from copy import deepcopy
import json
import warnings

import networkx as nx
import pandas as pd
import pm4py

RULE_VERSION = "ocel-cleaning-2026-08-v1"


def jdump(x):
    return json.dumps(x, sort_keys=True, default=str)


def missing(x):
    try:
        y = pd.isna(x)
        return bool(y) if not hasattr(y, "__len__") else False
    except Exception:
        return x is None


def sync_relations(ocel):
    """Synchronize denormalized activity/timestamp values in the E2O table."""
    eid = ocel.event_id_column
    act = ocel.event_activity
    ts = ocel.event_timestamp

    ev = ocel.events.set_index(eid)
    ocel.relations[act] = ocel.relations[eid].map(ev[act])
    ocel.relations[ts] = ocel.relations[eid].map(ev[ts])
    return ocel


def prepare(raw):
    """Independent copy plus immutable raw fields and initial lineage."""
    out = deepcopy(raw)
    e, r = out.events, out.relations
    eid, act, ts = out.event_id_column, out.event_activity, out.event_timestamp

    for column in [eid, act, ts, "source", "source_event_key"]:
        if column not in e:
            raise KeyError(f"Missing event column: {column}")

    e[ts] = pd.to_datetime(e[ts], utc=True)
    r[ts] = pd.to_datetime(r[ts], utc=True)

    e["original_timestamp"] = e[ts]
    e["original_activity"] = e[act]
    e["original_eid"] = e[eid].astype(str)
    e["source_event_ids"] = e[eid].map(lambda x: jdump([str(x)]))
    e["source_systems"] = e["source"].map(lambda x: jdump([x]))
    e["source_event_keys"] = e["source_event_key"].map(lambda x: jdump([x]))
    e["merge_rule"] = "none"
    e["rule_version"] = RULE_VERSION

    r["original_timestamp"] = r[ts]
    r["original_activity"] = r[act]
    r["relation_source_eids"] = r[eid].map(lambda x: jdump([str(x)]))
    return out


def candidate_report(ocel):
    """
    Pre-check only. Returns same-activity/time candidate groups and exact
    technical groups; it makes no deletion decision.
    """
    eid, act, ts = ocel.event_id_column, ocel.event_activity, ocel.event_timestamp
    qualifier = getattr(ocel, "qualifier", None)

    relation_columns = [ocel.object_type_column, ocel.object_id_column]
    if qualifier and qualifier in ocel.relations:
        relation_columns.append(qualifier)

    def relation_signature(group):
        return tuple(
            sorted(
                tuple("" if missing(v) else str(v) for v in row)
                for row in group[relation_columns].itertuples(
                    index=False, name=None
                )
            )
        )

    signatures = (
        ocel.relations.groupby(eid, sort=False)
        .apply(relation_signature)
        .to_dict()
    )

    events = ocel.events.copy()
    events["_relation_signature"] = events[eid].map(signatures)

    candidates = []
    for (timestamp, activity), group in events.groupby(
        [ts, act], dropna=False, sort=True
    ):
        if len(group) > 1:
            candidates.append(
                {
                    "timestamp": timestamp,
                    "activity": activity,
                    "eids": group[eid].astype(str).tolist(),
                    "sources": group["source"].tolist(),
                    "relation_signatures": group[
                        "_relation_signature"
                    ].tolist(),
                }
            )

    exact_columns = [
        act,
        ts,
        "source",
        "source_event_key",
        "_relation_signature",
    ]
    exact_columns += [
        c for c in ["source_seq", "payload_hash"] if c in events
    ]

    exact_groups = [
        group[eid].astype(str).tolist()
        for _, group in events.groupby(
            exact_columns, dropna=False, sort=False
        )
        if len(group) > 1
    ]
    return pd.DataFrame(candidates), exact_groups


def merge_verified(
    ocel,
    members,
    canonical,
    rule,
    confidence,
    reason,
    authority=None,
):
    """
    Attribute-aware merge for an explicitly verified group.

    Full original event rows and relation rows are stored in JSON lineage.
    E2O qualifiers are part of the relation merge key.
    """
    out = deepcopy(ocel)
    authority = authority or {}

    eid = out.event_id_column
    act = out.event_activity
    ts = out.event_timestamp
    oid = out.object_id_column
    object_type = out.object_type_column
    qualifier = getattr(out, "qualifier", None)

    members = list(map(str, members))
    canonical = str(canonical)

    rows = out.events[
        out.events[eid].astype(str).isin(members)
    ].copy()

    if set(rows[eid].astype(str)) != set(members):
        raise KeyError(f"Missing member in verified group: {members}")
    if canonical not in members:
        raise KeyError("Canonical eid must be a verified group member")
    if rows[ts].nunique(dropna=False) != 1:
        raise ValueError(
            "Timestamp mismatch requires a separate adjudication rule"
        )

    chosen = rows[
        rows[eid].astype(str) == canonical
    ].iloc[0].copy()

    event_lineage = {
        str(row[eid]): {
            column: None if missing(row[column]) else row[column]
            for column in rows.columns
        }
        for _, row in rows.iterrows()
    }

    conflicts = {}
    for column in rows.columns:
        if column in {eid, act, ts}:
            continue

        available = rows.loc[
            ~rows[column].map(missing),
            [eid, "source", column],
        ]
        if available.empty:
            continue

        preferred = (
            available[available["source"] == authority[column]]
            if column in authority
            else available.iloc[0:0]
        )

        if not preferred.empty:
            chosen[column] = preferred.iloc[0][column]
        elif missing(chosen.get(column)):
            chosen[column] = available.iloc[0][column]

        distinct_values = {
            str(row[column]) for _, row in available.iterrows()
        }
        if len(distinct_values) > 1:
            conflicts[column] = [
                {
                    "eid": str(row[eid]),
                    "source": row["source"],
                    "value": row[column],
                }
                for _, row in available.iterrows()
            ]

    source_relations = out.relations[
        out.relations[eid].astype(str).isin(members)
    ].copy()

    chosen[eid] = canonical
    chosen["source_event_ids"] = jdump(sorted(members))
    chosen["source_systems"] = jdump(
        sorted(rows["source"].astype(str).unique())
    )
    chosen["source_event_keys"] = jdump(
        sorted(rows["source_event_key"].astype(str).unique())
    )
    chosen["event_attribute_lineage"] = jdump(event_lineage)
    chosen["relation_lineage"] = jdump(
        source_relations.to_dict("records")
    )
    chosen["unselected_conflicts"] = jdump(conflicts)
    chosen["original_activity_by_eid"] = jdump(
        dict(zip(rows[eid].astype(str), rows["original_activity"]))
    )
    chosen["original_timestamp_by_eid"] = jdump(
        dict(zip(rows[eid].astype(str), rows["original_timestamp"]))
    )
    chosen["merge_rule"] = rule
    chosen["merge_confidence"] = float(confidence)
    chosen["merge_reason"] = reason
    chosen["rule_version"] = RULE_VERSION

    out.events = pd.concat(
        [
            out.events[
                ~out.events[eid].astype(str).isin(members)
            ],
            pd.DataFrame([chosen]),
        ],
        ignore_index=True,
    )

    mapping = {member: canonical for member in members}
    relations = out.relations.copy()
    relations["__source_eid"] = relations[eid].astype(str)
    relations[eid] = relations[eid].astype(str).replace(mapping)

    relation_key = [eid, oid]
    if object_type in relations:
        relation_key.append(object_type)
    if qualifier and qualifier in relations:
        relation_key.append(qualifier)

    merged_relations = []
    for _, group in relations.groupby(
        relation_key, dropna=False, sort=False
    ):
        relation = group.iloc[0].copy()
        relation["relation_source_eids"] = jdump(
            sorted(group["__source_eid"].astype(str).unique())
        )
        merged_relations.append(relation)

    out.relations = (
        pd.DataFrame(merged_relations)
        .drop(columns="__source_eid")
        .reset_index(drop=True)
    )

    # Repair event-to-event references when present.
    if hasattr(out, "e2e") and out.e2e is not None and len(out.e2e):
        eid2 = eid + "_2"
        out.e2e[eid] = out.e2e[eid].astype(str).replace(mapping)
        out.e2e[eid2] = out.e2e[eid2].astype(str).replace(mapping)

        self_loop = (
            out.e2e[eid].astype(str)
            == out.e2e[eid2].astype(str)
        )
        out.globals.setdefault(
            "removed_merge_self_loops", []
        ).extend(out.e2e[self_loop].to_dict("records"))

        out.e2e = (
            out.e2e[~self_loop]
            .drop_duplicates()
            .reset_index(drop=True)
        )

    out.globals.setdefault("cleaning_audit", []).append(
        {
            "canonical_eid": canonical,
            "source_eids": sorted(members),
            "merge_rule": rule,
            "confidence": confidence,
            "reason": reason,
            "rule_version": RULE_VERSION,
        }
    )
    return sync_relations(out)


def merge_exact_groups(ocel, exact_groups):
    out = deepcopy(ocel)
    for members in exact_groups:
        out = merge_verified(
            out,
            members,
            sorted(members)[0],
            "exact_technical_duplicate",
            1.0,
            "Same source identity, payload/signature, and E2O set",
        )
    return out


def refine_activities(ocel, mapping):
    out = deepcopy(ocel)
    eid, act = out.event_id_column, out.event_activity

    for event_id, label in mapping.items():
        mask = out.events[eid].astype(str) == str(event_id)
        out.events.loc[mask, act] = label
        out.events.loc[
            mask, "activity_refinement_rule"
        ] = "source-semantic-refinement"

    return sync_relations(out)


def guarded_drop_duplicate_relations(ocel):
    """
    Safe use of ocel_drop_duplicates as an exact E2O-row cleanup.

    Event-specific temporary activities prevent the function from collapsing
    relations belonging to different events.
    """
    out = deepcopy(ocel)
    eid = out.event_id_column
    act = out.event_activity
    ts = out.event_timestamp
    oid = out.object_id_column
    qualifier = getattr(out, "qualifier", None)

    for _, group in out.relations.groupby(
        [eid, oid, ts], dropna=False, sort=False
    ):
        if len(group) <= 1:
            continue

        if (
            qualifier
            and qualifier in group
            and group[qualifier].nunique(dropna=False) > 1
        ):
            raise ValueError(
                "Refuse to drop E2O rows with incompatible qualifiers"
            )

        comparable = [
            c
            for c in group.columns
            if c not in {act, "relation_source_eids"}
        ]
        if len(group[comparable].drop_duplicates()) > 1:
            raise ValueError(
                "Refuse to drop E2O rows with conflicting attributes"
            )

    saved_activity = out.events.set_index(eid)[act].to_dict()
    temporary_activity = {
        event_id: f"__EXACT_E2O__::{event_id}"
        for event_id in saved_activity
    }

    out.events[act] = out.events[eid].map(temporary_activity)
    out.relations[act] = out.relations[eid].map(
        temporary_activity
    )

    out = pm4py.ocel_drop_duplicates(out)

    out.events[act] = out.events[eid].map(saved_activity)
    out.relations[act] = out.relations[eid].map(saved_activity)
    return sync_relations(out)


def validate_ocel(ocel):
    eid = ocel.event_id_column
    act = ocel.event_activity
    ts = ocel.event_timestamp
    oid = ocel.object_id_column

    event_ids = set(ocel.events[eid].astype(str))
    object_ids = set(ocel.objects[oid].astype(str))

    assert ocel.events[eid].astype(str).is_unique
    assert ocel.objects[oid].astype(str).is_unique
    assert set(ocel.relations[eid].astype(str)) <= event_ids
    assert set(ocel.relations[oid].astype(str)) <= object_ids

    event_index = ocel.events.set_index(eid)
    expected_activity = ocel.relations[eid].map(event_index[act])
    expected_timestamp = ocel.relations[eid].map(event_index[ts])

    assert (
        ocel.relations[act].astype(str)
        == expected_activity.astype(str)
    ).all()

    assert (
        pd.to_datetime(ocel.relations[ts], utc=True)
        == pd.to_datetime(expected_timestamp, utc=True)
    ).all()

    if hasattr(ocel, "e2e") and ocel.e2e is not None and len(ocel.e2e):
        assert set(ocel.e2e[eid].astype(str)) <= event_ids
        assert set(ocel.e2e[eid + "_2"].astype(str)) <= event_ids

    if hasattr(ocel, "o2o") and ocel.o2o is not None and len(ocel.o2o):
        assert set(ocel.o2o[oid].astype(str)) <= object_ids
        assert set(ocel.o2o[oid + "_2"].astype(str)) <= object_ids

    for column in [
        "original_timestamp",
        "original_activity",
        "source",
        "source_event_key",
    ]:
        assert column in ocel.events

    return True


def deterministic_fallback(row, eid):
    source_key = row.get("source_event_key", None)

    if source_key not in [None, ""]:
        stable = f"{row.get('source', '')}|{source_key}"
        return 0, stable, str(row[eid])

    # Only reached when stable source identity is unavailable.
    return 1, str(row.get("ingested_at", "")), str(row[eid])


def materialize_order(ocel, semantic_edges):
    """
    Semantic DAG first, deterministic fallback second, synthetic time last.
    """
    out = deepcopy(ocel)
    eid, ts = out.event_id_column, out.event_timestamp
    ranks = {}
    ordering_bases = {}

    for timestamp, group in out.events.groupby(
        ts, dropna=False, sort=True
    ):
        rows = {
            str(row[eid]): row
            for _, row in group.iterrows()
        }

        graph = nx.DiGraph()
        graph.add_nodes_from(rows)

        for before, after, reason in semantic_edges:
            before = str(before)
            after = str(after)
            if before in rows and after in rows and before != after:
                graph.add_edge(before, after, reason=reason)

        if not nx.is_directed_acyclic_graph(graph):
            raise ValueError(
                f"Conflicting semantic order at {timestamp}"
            )

        order = list(
            nx.lexicographical_topological_sort(
                graph,
                key=lambda node: deterministic_fallback(
                    rows[node], eid
                ),
            )
        )

        for rank, node in enumerate(order):
            ranks[node] = rank
            ordering_bases[node] = jdump(
                {
                    "predecessors": [
                        {
                            "eid": predecessor,
                            "reason": graph[predecessor][node]["reason"],
                        }
                        for predecessor in graph.predecessors(node)
                    ],
                    "fallback": deterministic_fallback(
                        rows[node], eid
                    ),
                }
            )

    out.events["ordering_rank"] = (
        out.events[eid].astype(str).map(ranks)
    )
    out.events["ordering_basis"] = (
        out.events[eid].astype(str).map(ordering_bases)
    )

    out = pm4py.ocel_sort_by_additional_column(
        out,
        "ordering_rank",
        primary_column=ts,
    )

    # Only now materialize a synthetic order timestamp.
    out = pm4py.ocel_add_index_based_timedelta(out)
```

## 7. Sensitivity analysis

| Dataset                  | Expected events / E2O | Principal structural effect                                                                  |
| ------------------------ | --------------------: | -------------------------------------------------------------------------------------------- |
| Raw                      |               17 / 44 | Cross-system observations appear as repetitions; harmonized labels hide semantic differences |
| Conservative             |               15 / 39 | Verified duplicates removed; abstraction and distinct object instances preserved             |
| Evidence-based merge     |               14 / 37 | ERP packing-status observation absorbed into the WMS event                                   |
| Aggressive library merge |               10 / 28 | Item picks, logistics stages, and partial payments are collapsed through shared objects      |

**Order flattening.** Under the stated deterministic order, raw O1 contains apparent `Pick Item → Pick Item`, `Pack Package → Pack Package`, `Dispatch Package → Dispatch Package`, `Issue Invoice → Issue Invoice`, and repeated `Capture Payment → Capture Payment`. Conservative cleaning removes the duplicate I1 pick and invoice loop, but deliberately retains a legitimate I1-to-I2 repeated pick. It replaces the package and dispatch repetitions with interpretable edges: `Pack Package [WMS] → Package Packed Status Updated [ERP]` and `Release from Warehouse → Carrier Acceptance → Handover to Carrier`. Evidence-based merging removes the first of those edges. Aggressive merging reduces the order trace to one Pick, one Pack, one Dispatch, one Invoice, and one Capture, understating work and milestones.

**Item flattening.** For I1, raw data has `Pick Item → Pick Item → Pack Package` because e03/e04 duplicate the scan; conservative data has `Pick Item → Pack Package`. I2’s e05 must remain a separate pick. Aggressive merging creates one Pick event related to both I1 and I2, making the two item lifecycles look artificially synchronized and adding a false Item–Item co-occurrence specifically at the Pick activity; I1/I2 legitimately co-occur only at packing in the supplied source events.

**Payment flattening.** Conservative and evidence-based datasets preserve `Authorize Payment → Capture Payment` for M1 and a separate Capture for M2; e15 correctly remains absent from Payment flattening because it has no Payment relation. Aggressive merging makes one event serve both M1 and M2. Per-object DFGs may still look superficially plausible, while event-frequency and interaction metrics become wrong.

**OC-DFG, ET–OT, and OTG.** At least eight interpretations change: the five loop-like patterns above; `Release from Warehouse → Carrier Acceptance`; `Carrier Acceptance → Handover to Carrier`; and `Authorize Payment → Capture Payment`. Conservative label refinement splits the raw `Dispatch Package` event-type frequency into two meaningful types. Verified merges lower Pick–Item/Order/Package and Issue-Invoice–Order/Invoice observation counts without changing unique business objects. Aggressive Capture has one event but two Payment objects, so event-based and object-based OC-DFG frequencies diverge. Its relation union adds a false I1–I2 interaction occurrence at Pick and creates a genuinely new M1–M2 interaction; weighted OTG/interaction metrics therefore change rather than merely losing duplicates. Duplicate observations can inflate ET–OT weights even when the set of object-type pairs is unchanged.

**Rework, lifecycle, and performance.** Raw same-label loops can be misread as rework; conservative cleaning distinguishes true multiplicity from duplicate observation and abstraction changes. Original tie intervals are zero, not positive. Synthetic offsets can decide edge orientation but must be excluded from service, waiting, and lifecycle-duration calculations. In this sample O1’s overall start/end remain unchanged, but zero-time internal paths disappear or change label; aggressive merging also removes opportunities to measure interface propagation, partial-payment sequencing, and stage-specific conformance.

## 8. Audit trail and reversibility

Maintain an immutable raw-event table and two append-only audit tables. The event mapping table contains: `canonical_eid`, ordered `source_eids`, merge rule ID, reviewer or rule version, confidence, reason, canonical-selection rule, original activity and timestamp by source eid, refined activity, adjusted timestamp, source/source-key/hash/sequence, complete attribute lineage, selected value and authority per attribute, and every unselected or discarded conflict.

The relation audit contains canonical eid, source eid, object ID/type, original and refined qualifier, retained relation attributes, conflicts, and whether the row was kept, merged, or quarantined.

The analytical OCEL stores `original_timestamp` and `adjusted_timestamp` separately and references the audit record. Reconstruction proceeds by:

1. Exploding each canonical mapping back to its source eids.
2. Restoring each source event row from `event_attribute_lineage`.
3. Restoring qualified E2O rows from `relation_lineage`.
4. Reinstating each source’s original label and timestamp.
5. Removing the synthetic canonical row and ordering timestamp.

Exact copies that were dropped remain recoverable from the immutable raw snapshot. Reconstruction never depends on reversing a lossy aggregate or guessing which source supplied a value.

## 9. Failure modes and safeguards

1. **Collapsing e13/e14 partial payments.** Require equality of the discriminating Payment identity, not merely O1/V1 overlap.
2. **Turning abstraction updates into false rework.** Store `abstraction_level`, derivation lineage, and refined labels for e06/e07 and e15.
3. **Ordering by ingestion time.** Permit it only as a flagged fallback when stable source identity is unavailable.
4. **Treating shared objects as proof of duplication.** Require physical identity, unique business key, or verified lineage; object overlap is only candidate evidence.
5. **Unioning incompatible E2O relations.** Include qualifiers in the merge key; retain conflicting qualifiers as separate audited relations.
6. **Changing durations through synthetic microseconds or milliseconds.** Preserve original timestamps and use a restored original-time view for every performance metric.
7. **Losing source-authoritative attributes.** Apply attribute-level authority rules and retain every conflicting source value.
8. **Applying duplicate functions to the whole OCEL without inspection.** Generate candidate reports first; run library functions only on deep copies with guards and post-validation.
9. **Comparing `source_seq` across systems.** Scope sequence constraints to one source; cross-source order needs domain evidence.
10. **Presenting a total order as physical truth.** Store the ordering basis and distinguish semantic edges from deterministic fallback.
11. **Breaking E2E constraints when event IDs are rewritten.** Update and validate both E2E endpoints, quarantine self-loops created by merging, and fail on orphans.
12. **Creating new object interactions by relation union.** Compare pre/post object-pair-by-activity co-occurrences; flag the new M1–M2 pair and the false I1–I2 co-occurrence at Pick.
13. **Merging a many-to-one summary into one contributor.** Keep aggregate events separate unless their complete contributor set and semantics are modeled.
14. **Unstable canonical IDs or first-row selection.** Use a documented canonical rule and retain the raw-to-canonical mapping independently of DataFrame order.
