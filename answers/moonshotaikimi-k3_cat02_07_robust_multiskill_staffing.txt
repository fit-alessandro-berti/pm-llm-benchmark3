```python
def try_preempt(job, now):
```

```python
def build_windows(cfg):
    s,e = cfg['shift']; w=[]
    if cfg['break']: b0,b1 = cfg['break']; w += [(s,b0),(b1,e)]
    else: w=[(s,e)]
    w.append((e, e+OVERTIME_MIN))   # finish-in-progress only
    return [x for x in w if x[1]>x[0]]

def windows_minus(wins, cut):
    out=[]
    for a,b in wins:
        if b<=cut[0] or a>=cut[1]: out.append((a,b))
        else:
            if a<cut[0]: out.append((a,cut[0]))
            if b>cut[1]: out.append((cut[1],b))
    return out

def add_work(wins, t, w):
    for a,b in wins:
        if b<=t: continue
        s=max(a,t)
        if w <= b-s: return s+w
        w -= (b-s)
    return None

def work_between(wins, t0, t1):
    return sum(max(0.0, min(b,t1)-max(a,t0)) for a,b in wins)

def mean_service(stage, mult, tailp):
    S=SERVICE[stage]; p=min(tailp[stage],1.0)
    m=(1-p)*(S['ord'][0]+S['ord'][1])/2 + p*(S['tail'][0]+S['tail'][1])/2
    return m*mult

def sample_service(stage, mult, tailp, rng):
    S=SERVICE[stage]; p=min(tailp[stage],1.0)
    lo,hi = S['tail'] if rng.random()<p else S['ord']
    return rng.uniform(lo,hi)*mult
```

# 1. Assumptions, objectives, and decision variables

**Demand and service assumptions (labeled).**

- **A1 (distributions from ranges).** Each range is treated as a uniform distribution; the complex tail is a Bernoulli mixture: with probability `p` draw from the tail range, else from the ordinary range. This is an assumption — ranges alone do not identify a distribution (see §9). Resulting means (base minutes): Intake 6.9, Mechanical 26.3, Electrical 32.8, Software 38.5, Validation 15.7.
- **A2 (arrivals).** Per block, arrivals ~ Poisson(expected_arrivals), uniform within the block. Poisson adds realistic burstiness; a deterministic alternative would understate queueing.
- **A3 (multipliers).** A resource multiplier scales any draw for that resource–activity pair (1.25  25% slower).
- **A4 (handover).** 7 min when Intake/Diagnostic/Validation changes resource; +5 min when the case crosses the mechanical  electrical/software family *and* changes resource (same-resource retention waives both). Handover/setup minutes occupy the receiving resource (conservative; alternative: case dead-time only — tested as sensitivity).
- **A5 (setup).** 5 min when a resource's previous case's diagnostic family differs from the new one.
- **A6 (coordination).** 8 min case dead-time before Validation for parallel ME/ES; sequential execution on one cross-skilled resource avoids it but lengthens the critical path (branch sum instead of branch max).
- **A7 (preemption).** P1 may preempt a lower-priority *diagnostic* activity only; victim resumes with remaining × 1.10; at most once per case; completed work is retained.
- **A8 (overtime).** Finish in-progress work up to 30 min past shift; no new starts after shift end. Unfinished work is end-of-day backlog (no next-day drain modeled — A11).
- **A9 (SLA clock).** Arrival  Validation completion, elapsed minutes.
- **A10 (dispatcher knowledge).** Dispatch decisions use *expected* service times, not realized draws (realistic and auditable).
- **A11 (horizon).** Single day, no carry-in. P3 24 h SLA is therefore only partially identifiable (flagged throughout).
- **A12 (scenario mechanics).** U1: +8 pp P1 taken proportionally from P2/P3. U2: E and ES percentages doubled, then rows renormalized. U4: tail probabilities of the three diagnostic activities double.

**ME/ES parallelization decision.** Parallel iff (case is P1) OR (both branch pools currently have idle qualified capacity), i.e. parallelize(E[wait saved] > COORD_MIN + extra handover  15 min). **Decision variables.** Eligibility matrix (who may do what), dispatch priority score, reservation set and thresholds, preemption on/off, parallelization threshold, aging/anti-starvation parameter, surge-mode triggers.

**Objectives (two formulations).**

- **O1 (tail/SLA risk):** minimize `J1 = _p w_p·max(0, target_p  attained_p) + ·q95(flow)`, with w = (P1:10, P2:3, P3:1),  = 1/60 per minute. Captures tail/SLA risk directly.

Priority score: (priority class, FIFO) within each fixed queue. Reservation: none. Preemption: none (policy choice, for contrast). Parallelization: always parallel to specialist queues (+8 min coordination). Handover minimization: none (resource change is forced at stage boundaries 2.4 handovers/case  700 resource-min/day  28% of capacity). Overflow: none — this is the fragility point (e.g., U3 removes Chen  Electrical fixed queue loses its 1.0-speed resource with no fallback).

**P-B — Full pooling, transparent dispatch.** Eligibility: any qualified resource. Job priority score: (P1<P2<P3, arrival time). Resource score: `expected_service(resource) + handover_if_resource_change + setup_if_family_switch`; argmin — this is the handover-minimization rule (enables single-resource ownership, e.g., M case entirely on Ben). Preemption: P1 diagnostic jobs preempt lowest-priority running diagnostic job on the qualified resource where P1's expected service is smallest (once per case, +10% remaining). Parallelization: state-based — parallel if both branches have an idle qualified resource now; else sequential on a cross-skilled resource if one exists. Overflow triggers: none needed (fully pooled).

**P-C — Hybrid: pooling + P1 fast lane + aging (recommended).** Everything in P-B, plus: (i) *reservation*: fast-lane resources {Ben: Mechanical, Chen: Electrical, Emil: Software} accept non-P1 work only if expected service  25 min OR the job has waited > 60 min OR no non-lane candidate exists — idle lane capacity is the P1 insurance premium; (ii) *aging*: P3 jobs waiting > 240 min are dispatched as P2 (starvation guard); (iii) *parallelization*: P1 dual-branch cases always parallelize; others only when both branch queues are empty; (iv) tie-break among near-equal resource scores by lowest cumulative busy minutes (fairness). Overflow triggers and surge mode in §5.

**P-D (optional variant, not fully simulated).** SERPT/fairness-penalized dispatch: minimize expected *remaining* processing time + ·utilization-deviation; useful if estimate gaming is controlled (§6).

# 5. Robust recommendation

**Primary: P-C (hybrid pooling with P1 fast lane, preemption, aging, threshold parallelization).** It is the only policy keeping P1 SLA  0.85 across *all* U1–U5 (minimax criterion O2), at a cost of ~5–10 min base mean delay and some idle reserved capacity in quiet periods. Specialization is disqualified by U3 (no fallback); pure pooling fails U1/U5 on P1 protection.

**Fallback / surge mode.** Triggers (any): P1 waiting >20 min; Electrical or Software pool utilization >95% over two consecutive blocks; a skill's qualified-resource count drops to 1 (absence); backlog at 14:00 >120 min. Actions: open fast lane to all priorities with expected service 40 min; parallelize P1 dual-branch only; defer new P3 starts after 18:00 when backlog >90 min (aging floor protects the 24 h SLA); pre-approve overtime; escalate for call-in capacity.

**Structural caveat (must accompany any routing recommendation):** the base plan is 110–120% loaded in expectation; *no routing policy* meets P2/P3 targets under U1/U3/U5 without capacity action. Highest-value options: +0.5–1.0 FTE cross-skilled E/S cover 12:00–20:00; extend Farah past 12:00; cross-train Ben on Electrical.

**When another policy is preferable:** if true demand 85% of capacity (e.g., after the capacity fix), B dominates — simpler and lower mean delay; if governance demands fixed accountability and mix is stable, A *with added slack*; if P1 share persistently >20%, enlarge the fast lane (add Deepa as flex reserve).

# 6. Secondary effects and implementation risks

- **Gaming of estimates/priority:** dispatch uses expected times — operators may inflate priority or under-report complexity to access the fast lane. Mitigate: audit priority vs. realized service; feed realized times back into estimates; log the eligible set for every decision (§7).
- **P3 starvation:** under permanent overload P3 is systematically displaced; aging (240 min) plus a daily P3 completion budget; monitor P3 age distribution.
- **Skill erosion:** speed-based dispatch underuses Farah (1.4 multipliers) — but she is the *only* morning software backup (U5). Reserve deliberate low-stakes rotations for her; track per-resource case mix.
- **Excessive preemption:** thrash risk in U5 (6–10 preemptions/day); the once-per-case cap and 10% penalty bound the damage; alert if preemptions/day > 8 or if a resource is preempted twice within 30 min.
- **Coordination overhead:** always-parallel costs 13 cases × 8 min  106 min dead-time/day plus extra handovers; the threshold rule saves roughly half of that — measure it rather than assume it.
- **Validation bottleneck migration:** diagnostics clearing surges push work into Validation exactly when validation-qualified staff leave (16:00); hold validation-capable capacity (Deepa/Emil) in the evening.
- **Fairness:** specialization is *unfair* (Chen/Emil 100%, Farah 65%); pooling/hybrid are *uniformly overloaded* (all >90%) — fair in distribution but in breach of the 90% fragility rule; escalate as a staffing issue, not a dispatch issue.
- **Human interpretability:** the dispatch rule must fit on one slide (priority, then fastest-with-handover-preference, fast-lane exceptions); every deviation logged with policy version for audit.

# 7. Monitoring and process-mining design

**Event attributes (interval event log):** `case:concept:name`, `concept:name` (stage/branch), `start_timestamp`, `time:timestamp`, `org:resource`, plus: queue-entry time (`ready0`), assignment-decision timestamp, eligible-resource set at decision, skill used vs. case-type skill required, planned (expected) vs. actual service minutes, pause/resume (`was_preempted`, `pause_minutes`), handover minutes, setup minutes, parallel/sequential flag, priority, SLA target and breach flag, policy version, scenario/shock flag (e.g., outage window, absence day).

**PM4Py analyses:**
- *Drift:* weekly/sliding-window `pm4py.get_service_time` per (activity, resource); CUSUM or windowed comparison of means  detects service-time changes and multiplier drift.
- *Handover burden:* `pm4py.discover_handover_of_work_network` edge weights × 7 min; trend daily; stratify by policy version.
- *Bottleneck migration:* performance DFG / sojourn time per activity per 2 h window; case-level `pm4py.insert_case_service_waiting_time` for total service vs. waiting — **labeled case-level**: its "waiting" conflates queue wait + handover + coordination, so queue-specific waits must be computed separately from interval timestamps (done in §8).
- *Policy conformance:* variant analysis distinguishes parallel vs. sequential ME/ES executions; compare actual resource vs. logged eligible set.
- *Rework/preemption:* activity multiplicity per case; pause/resume attribute rates.

# 8. Reproducible Python

```python
"""
Technical-incident process: policy comparison under U1-U5.
Engine: transparent hand-rolled discrete-event simulation (seeded).
Known simplifications (scaffold): arrivals Poisson/uniform-in-block; uniform
service draws from ranges; dispatcher uses EXPECTED service; handover/setup
occupy the receiving resource; preemption resumes with remaining*1.10 and is
logged as one interval with pause attributes; no next-day drain; overtime is
finish-in-progress only. PM4Py API assumed >= 2.x.
"""
import copy, heapq, itertools
import numpy as np
import pandas as pd
import pm4py

# ---- explicit mechanism constants (NOT hidden in logic) ----
HANDOVER_MIN, CROSS_TEAM_MIN, SETUP_MIN, COORD_MIN = 7.0, 5.0, 5.0, 8.0
RESTART_PCT, MAX_PREEMPT, OVERTIME_MIN = 0.10, 1, 30.0
FAST_LANE_MAX_SERVICE, FAST_LANE_OVERFLOW_WAIT, AGING_P3_MIN = 25.0, 60.0, 240.0

SERVICE = {
 'Intake':     {'ord': (5, 8),   'tail': (10, 14), 'p': 0.08},
 'Mechanical': {'ord': (18, 28), 'tail': (35, 55), 'p': 0.15},
 'Electrical': {'ord': (22, 35), 'tail': (40, 65), 'p': 0.18},
 'Software':   {'ord': (25, 40), 'tail': (45, 80), 'p': 0.20},
 'Validation': {'ord': (10, 18), 'tail': (22, 35), 'p': 0.12}}
RESOURCES = {
 'Ada':   {'mult': {'Intake':1.00,'Mechanical':1.00,'Electrical':1.35,'Validation':1.15}, 'shift':( 480, 960), 'break':(735, 765)},
 'Ben':   {'mult': {'Intake':1.10,'Mechanical':1.00,'Validation':1.00},                   'shift':( 480, 960), 'break':(720, 750)},
 'Chen':  {'mult': {'Intake':1.10,'Electrical':1.00,'Software':1.25,'Validation':1.10},   'shift':( 480, 960), 'break':(750, 780)},
 'Deepa': {'mult': {'Intake':1.00,'Mechanical':1.25,'Electrical':1.00,'Validation':1.00}, 'shift':( 600,1080), 'break':(840, 870)},
 'Emil':  {'mult': {'Intake':1.10,'Electrical':1.30,'Software':1.00,'Validation':1.00},   'shift':( 720,1200), 'break':(960, 990)},
 'Farah': {'mult': {'Intake':1.00,'Mechanical':1.40,'Electrical':1.40,'Software':1.40,'Validation':1.20}, 'shift':(480,720), 'break':None}}
DEMAND = pd.DataFrame([
 ('08:00-10:00', 480, 7,10,55,35, 30,25,15,20,10),
 ('10:00-12:00', 600, 9,15,55,30, 25,25,15,25,10),
 ('12:00-14:00', 720, 7,12,58,30, 22,28,18,20,12),
 ('14:00-16:00', 840,10,18,52,30, 20,30,18,20,12),
 ('16:00-18:00', 960, 6,10,50,40, 20,25,25,15,15),
 ('18:00-20:00',1080, 3, 5,45,50, 25,20,30,10,15)],
 columns=['block','start','expected_arrivals','P1_pct','P2_pct','P3_pct',
          'M_pct','E_pct','S_pct','ME_pct','ES_pct'])

FAMILY   = {'Mechanical':'MECH','Electrical':'ES','Software':'ES'}
BRANCHES = {'M':['Mechanical'],'E':['Electrical'],'S':['Software'],
            'ME':['Mechanical','Electrical'],'ES':['Electrical','Software']}
DIAG = set(FAMILY); PRIO = {'P1':0,'P2':1,'P3':2}
SLA  = {'P1':120.0,'P2':480.0,'P3':1440.0}
FIXED_QUEUES = {'Intake':['Ben','Farah'],'Mechanical':['Ada','Deepa'],
                'Electrical':['Chen','Emil'],'Software':['Emil','Chen'],
                'Validation':['Ada','Ben','Deepa']}
FAST_LANE = {'Mechanical':{'Ben'},'Electrical':{'Chen'},'Software':{'Emil'}}
POLICIES = {
 'A_specialization': dict(elig='fixed', preempt=False, parallel='always', aging=False, fastlane=False, fair_tb=False),
 'B_pooling':        dict(elig='pool',  preempt=True,  parallel='state',  aging=False, fastlane=False, fair_tb=False),
 'C_hybrid':         dict(elig='pool',  preempt=True,  parallel='p1',     aging=True,  fastlane=True,  fair_tb=True)}

def get_scenario(name):
    dem, res = DEMAND.copy(), copy.deepcopy(RESOURCES)
    tailp = {a: SERVICE[a]['p'] for a in SERVICE}; outage = None
    if name in ('U1','U5'):
        m = dem['block'].isin(['08:00-10:00','10:00-12:00'])
        dem.loc[m,'expected_arrivals'] *= 1.7
        p1 = dem.loc[m,'P1_pct'] + 8.0
        f  = (100.0 - p1) / (dem.loc[m,'P2_pct'] + dem.loc[m,'P3_pct'])
        dem.loc[m,'P2_pct'] *= f; dem.loc[m,'P3_pct'] *= f; dem.loc[m,'P1_pct'] = p1
    if name == 'U2':
        m = dem['block'].isin(['12:00-14:00','14:00-16:00'])
        dem.loc[m,'E_pct'] *= 2; dem.loc[m,'ES_pct'] *= 2
        cols = ['M_pct','E_pct','S_pct','ME_pct','ES_pct']
        dem.loc[m,cols] = dem.loc[m,cols].div(dem.loc[m,cols].sum(axis=1), axis=0)*100.0
    if name in ('U3','U5'): res.pop('Chen')
    if name == 'U4':
        for a in DIAG: tailp[a] = min(1.0, 2*tailp[a])
    if name == 'U5': outage = (570, 600)          # 09:30-10:00 Intake outage
    return dem, res, tailp, outage

def build_windows(cfg):                            # incl. finish-only overtime tail
    s,e = cfg['shift']; w = [(s,e)] if not cfg['break'] else [(s,cfg['break'][0]),(cfg['break'][1],e)]
    return [x for x in w+[(e,e+OVERTIME_MIN)] if x[1] > x[0]]
def windows_minus(wins, cut):
    out = []
    for a,b in wins:
        if b <= cut[0] or a >= cut[1]: out.append((a,b))
        else:
            if a < cut[0]: out.append((a,cut[0]))
            if b > cut[1]: out.append((cut[1],b))
    return out
def add_work(wins, t, w):
    for a,b in wins:
        if b <= t: continue
        s = max(a,t)
        if w <= b-s: return s+w
        w -= b-s
    return None                                    # cannot finish today
def work_between(wins, t0, t1):
    return sum(max(0.0, min(b,t1)-max(a,t0)) for a,b in wins)
def mean_service(stage, mult, tailp):
    S = SERVICE[stage]; p = min(tailp[stage],1.0)
    return ((1-p)*np.mean(S['ord']) + p*np.mean(S['tail'])) * mult
def sample_service(stage, mult, tailp, rng):
    S = SERVICE[stage]; lo,hi = S['tail'] if rng.random() < min(tailp[stage],1.0) else S['ord']
    return rng.uniform(lo,hi) * mult

def simulate(pol_name, sc_name, seed):
    rng = np.random.default_rng(seed); pol = POLICIES[pol_name]
    dem, res, tailp, outage = get_scenario(sc_name)
    wins  = {r: build_windows(c) for r,c in res.items()}
    sh_s  = {r: c['shift'][0] for r,c in res.items()}
    sh_e  = {r: c['shift'][1] for r,c in res.items()}
    avail = {r: sum(b-a for a,b in wins[r]) - OVERTIME_MIN for r in res}
    cases, ev, Q, running = {}, [], [], {}
    rstate = {r: {'last_family':None,'busy':0.0} for r in res}
    rows, n_pre = [], 0
    seq = itertools.count(); rid = itertools.count(1)
    cid = 0
    for _, b in dem.iterrows():
        n = rng.poisson(b['expected_arrivals'])
        pp = np.array([b['P1_pct'],b['P2_pct'],b['P3_pct']]); pp /= pp.sum()
        pt = np.array([b['M_pct'],b['E_pct'],b['S_pct'],b['ME_pct'],b['ES_pct']]); pt /= pt.sum()
        for _ in range(n):
            cid += 1
            cases[cid] = dict(id=cid, arr=float(rng.uniform(b['start'],b['start']+120)),
                pri=rng.choice(['P1','P2','P3'],p=pp), typ=rng.choice(['M','E','S','ME','ES'],p=pt),
                last_res=None, last_act=None, pending=0, parallel=False, preempts=0, val_end=None)
            heapq.heappush(ev,(cases[cid]['arr'], next(seq), 'arr', cid))
    def mkjob(c, stage, now):
        return dict(cid=c['id'], stage=stage, pri=c['pri'], enq=now, ready=now, ready0=now,
                    pinned=None, work=None, pause_start=None, seq_both=None)
    def qualified(r, stage): return stage in res[r]['mult']
    def eff_prio(j, now):
        p = PRIO[j['pri']]
        if pol['aging'] and j['pri']=='P3' and now-j['enq'] > AGING_P3_MIN: p = 1
        return p
    def candidates(job, now):
        pool = ([r for r in FIXED_QUEUES[job['stage']] if r in res] if pol['elig']=='fixed'
                else list(res))
        pool = [r for r in pool if qualified(r,job['stage']) and r not in running
                and sh_s[r] <= now < sh_e[r]]
        if job['pinned']:
            r = job['pinned']                       # pin expires at shift end
            pool = [r] if (r in res and r not in running and now < sh_e[r]) else pool
        if job['seq_both']:                         # sequential dual: cross-skilled only
            pool = [r for r in pool if all(b in res[r]['mult'] for b in job['seq_both'])]
        if pol['fastlane'] and job['pri'] != 'P1':
            lane = FAST_LANE.get(job['stage'], set()) & set(pool)
            if lane:
                est = min(mean_service(job['stage'], res[r]['mult'][job['stage']], tailp) for r in lane)
                if not (est <= FAST_LANE_MAX_SERVICE or now-job['enq'] > FAST_LANE_OVERFLOW_WAIT
                        or set(pool) <= lane):
                    pool = [r for r in pool if r not in lane]
        return pool
    def assign(job, r, now):
        c = cases[job['cid']]; ho = 0.0
        if c['last_res'] is not None and r != c['last_res']:
            ho = HANDOVER_MIN
            if FAMILY.get(c['last_act']) and FAMILY.get(job['stage']) \
               and FAMILY[c['last_act']] != FAMILY[job['stage']]: ho += CROSS_TEAM_MIN
        fam = FAMILY.get(job['stage'])
        setup = SETUP_MIN if (fam and rstate[r]['last_family']
                              and rstate[r]['last_family'] != fam) else 0.0
        w = job['work'] or sample_service(job['stage'], res[r]['mult'][job['stage']], tailp, rng)
        jw = windows_minus(wins[r], outage) if (job['stage']=='Intake' and outage) else wins[r]
        start = now + ho + setup; end = add_work(jw, start, w)
        rstate[r]['busy'] += ho + setup + w
        if fam: rstate[r]['last_family'] = fam
        rec = dict(id=next(rid), job=job, r=r, start=start, work=w, wins=jw, end=end,
                   ho=ho, setup=setup)
        running[r] = rec
        if end is not None: heapq.heappush(ev,(end, next(seq), 'done', (rec['id'], r)))
    def try_preempt(job, now):
        nonlocal n_pre
        best = None
        for r, rec in running.items():
            if not qualified(r, job['stage']): continue
            v = rec['job']
            if v['stage'] not in DIAG or PRIO[v['pri']] <= 0: continue
            if cases[v['cid']]['preempts'] >= MAX_PREEMPT: continue
            rem = rec['work'] - work_between(rec['wins'], rec['start'], now)
            if rem <= 1e-9: continue
            key = mean_service(job['stage'], res[r]['mult'][job['stage']], tailp)
            if best is None or key < best[0]: best = (key, r, rec, rem)
        if best is None: return False
        _, r, rec, rem = best
        v = rec['job']; vc = cases[v['cid']]
        vc['preempts'] += 1
        v['work'] = rem * (1.0 + RESTART_PCT)       # explicit restart penalty
        v['enq'] = now; v['ready'] = now; v['pause_start'] = now
        del running[r]                              # old 'done' event becomes stale
        Q.append(v); n_pre += 1
        return True
    def decide_parallel(c, now):
        brs = BRANCHES[c['typ']]
        if pol['parallel'] == 'always': return True
        if pol['parallel'] == 'p1':
            return c['pri']=='P1' or not any(j['stage'] in brs for j in Q)
        ok = all(any(qualified(r,b) and r not in running and sh_s[r] <= now < sh_e[r]
                     for r in res) for b in brs)
        if ok: return True
        return not any(all(b in res[r]['mult'] for b in brs) for r in res)
    def dispatch(now):
        progress = True
        while progress:
            progress = False
            Q.sort(key=lambda j: (eff_prio(j, now), j['enq']))
            for job in list(Q):
                if job['ready'] > now: continue
                pool = candidates(job, now)
                if not pool:
                    if pol['preempt'] and job['pri']=='P1' and job['stage'] in DIAG:
                        if try_preempt(job, now): progress = True
                    continue
                def score(r):
                    c = cases[job['cid']]
                    ho = HANDOVER_MIN if (c['last_res'] and r != c['last_res']) else 0.0
                    fam = FAMILY.get(job['stage'])
                    su = SETUP_MIN if (fam and rstate[r]['last_family']
                                       and rstate[r]['last_family'] != fam) else 0.0
                    tb = rstate[r]['busy'] if pol['fair_tb'] else 0.0
                    return (mean_service(job['stage'], res[r]['mult'][job['stage']], tailp)
                            + ho + su, tb)
                r = min(pool, key=score)
                Q.remove(job)
                if job['seq_both']: cases[job['cid']]['pin_sibling'] = r
                assign(job, r, now); progress = True
    while ev:
        now, _, kind, payload = heapq.heappop(ev)
        if kind == 'arr':
            Q.append(mkjob(cases[payload], 'Intake', now))
        else:
            rid_ev, r = payload
            rec = running.get(r)
            if rec is None or rec['id'] != rid_ev: continue   # stale (preempted)
            del running[r]
            job, c = rec['job'], cases[rec['job']['cid']]
            pause = (rec['start'] - job['pause_start']) if job['pause_start'] else 0.0
            rows.append(dict(case=f"C{job['cid']}", activity=job['stage'],
                start=rec['start'], end=now, resource=r, priority=c['pri'],
                case_type=c['typ'], handover_min=rec['ho'], setup_min=rec['setup'],
                was_preempted=bool(job['pause_start']), pause_min=pause,
                stage_wait_min=rec['start'] - job['ready0'],
                policy=pol_name, scenario=sc_name))
```

# 9. Limits and validation plan

**What cannot be concluded from the supplied evidence:** (i) expected arrivals give no arrival-process variance — Poisson is assumed, and burstier processes worsen all tails; (ii) ranges are not distributions — uniform vs. peaked choices move p95 materially; (iii) tail events may be correlated within a day (U4 only partially covers this); (iv) multipliers are static and unvalidated; learning, fatigue, and handover *quality* (rework after handover) are unmodeled; (v) the single-day horizon cannot identify P3 24 h SLA under a persistent 116% load — simulated P3 SLA is an upper bound; (vi) no abandonment, no next-day carryover, no joint U1+U4-type shocks; (vii) because expected demand already exceeds capacity, all conclusions concern *allocation of unavoidable delay*, not full SLA compliance — precise table values will shift when §8 is executed and should be recomputed.

**Validation plan.** (1) *Backtest:* replay 20–40 historical days through the simulator; compare simulated vs. actual flow-time distributions (KS test), per-resource utilization, and handover counts; re-fit service distributions from the logs (replacing A1). (2) *Shadow mode:* hybrid policy recommends dispatches for 2 weeks while humans decide; log acceptance rate and counterfactual deltas. (3) *Stepped-wedge pilot:* alternate B vs. C by matched day-type, low-risk days first; P1 preemption always on in all arms; abort criteria — intraday projected P1 SLA <85%, 14:00 backlog >120 min, any resource planned >100%; run 2–4 weeks, then decide with matched controls. (4) *Guardrails:* cap P3 deferral via the aging floor; monitor gaming (priority vs. realized service) and Farah's skill retention; review policy version logged on every assignment before any full rollout.
