| Outcomes | decision rate, Senior Assessment rate, decision-time p90 | Jan–Feb and seasonal | Outcome shift >5pp or Senior Assessment rate doubles | Segment by complexity/supplier | Policy change, seasonality | Risk/compliance |

Seasonality should be handled with same-month prior-year baselines or seasonal exponential smoothing for October–December metrics. For nonseasonal metrics, use rolling baselines from January–February. Multiple testing should be mitigated by requiring alerts to persist for two consecutive periods, applying false-discovery-rate adjustment across monitors, and treating alerts as diagnostic triggers rather than proof of drift.

def prepare_event_log(df, case_id='case_id', activity_key='activity', timestamp_key='timestamp'):
    """
    Format a raw event dataframe with pm4py format_dataframe.
    """
    df = df.copy()
    df[timestamp_key] = pd.to_datetime(df[timestamp_key])
    formatted = pm4py.format_dataframe(
        df,
        case_id=case_id,
        activity_key=activity_key,
        timestamp_key=timestamp_key
    )
    return formatted

def slice_time_window(formatted_df, start, end, timestamp_key='time:timestamp'):
    """
    Filter a formatted pm4py dataframe to a time range.
    """
    return pm4py.filter_time_range(formatted_df, start, end, timestamp_key=timestamp_key)

def compute_monthly_dfg(formatted_df, freq='ME'):
    """
    Discover a DFG for each calendar month.
    """
    df = formatted_df.copy()
    df['month'] = df['time:timestamp'].dt.to_period(freq).astype(str)
    return {m: pm4py.discover_dfg(g) for m, g in df.groupby('month')}

def compute_variants(formatted_df):
    """
    Return process variants from a pm4py formatted dataframe.
    """
    return pm4py.get_variants(formatted_df)

def compute_temporal_profile(formatted_df):
    """
    Discover a temporal profile from a pm4py formatted dataframe.
    """
    return pm4py.discover_temporal_profile(formatted_df)

def discover_rule_models(formatted_df):
    """
    Optionally discover log skeleton and DECLARE models.
    """
    log = pm4py.convert_to_event_log(formatted_df)
    result = {}
    try:
        result['log_skeleton'] = pm4py.discover_log_skeleton(log)
    except Exception as e:
        result['log_skeleton_error'] = str(e)
    try:
        result['declare'] = pm4py.discover_declare(log)
    except Exception as e:
        result['declare_error'] = str(e)
    return result

def compare_raw_and_normalized(df, label_mapping=None, drop_technical_duplicates=False,
                               case_id='case_id', activity_key='activity', timestamp_key='timestamp'):
    """
    Compare original and normalized label mappings without overwriting the original log.

    label_mapping: dict mapping raw activity labels to normalized labels.
    drop_technical_duplicates: whether to drop repeated technical events per case.
    """
    original = prepare_event_log(df, case_id=case_id, activity_key=activity_key, timestamp_key=timestamp_key)

    normalized_df = df.copy()
    if label_mapping:
        normalized_df[activity_key] = normalized_df[activity_key].replace(label_mapping)
    if drop_technical_duplicates:
        # Simple conservative deduplication of repeated technical events.
        normalized_df = normalized_df.drop_duplicates(
            subset=[case_id, activity_key, timestamp_key], keep='first'
        )

    normalized = prepare_event_log(
        normalized_df,
        case_id=case_id,
        activity_key=activity_key,
        timestamp_key=timestamp_key
    )
    return original, normalized

## 9. Provisional attribution

The strongest conclusions are the March logging/semantic migration, the May supplier-driven rework surge, and the June–July queueing deterioration. In March, raw fitness collapsed to 0.55 while mapped fitness stayed near baseline at 0.90. Simultaneously, new labels appeared, `Open Case` duplicates emerged, and resource missingness rose. This is high-confidence measurement/logging drift. In May, Supplier Z share rose from 14.5% to 43–46%, rework variants rose from 11.5% to 24–29%, and AssessRequestInfo roughly doubled. These signatures are high-confidence control-flow/behavioral drift caused by incomplete supplier bundles. In June–July, median cycle, p90, and queue waiting increased sharply while Assess service time changed only modestly. With four assessors leaving in June, this is high-confidence performance drift from capacity shortage, though supplier rework increased demand for assessment.

The priority-rule effect is only plausible. Timing suggests July redistribution, but the aggregate monthly data cannot show that standard cases waited longer while high-complexity cases waited less. The October–November complexity increase is high-confidence seasonal population drift: volume, high-complexity share, and Senior Assessment paths all rose. December improvement is only plausibly intervention-related because it coincides with lower seasonal load, lower supplier share, and supplier recovery.

Mediation and interaction prevent clean attribution. Supplier disruption creates rework; staffing cuts slow rework resolution; priority rules redistribute waiting; seasonal complexity adds workload to depleted capacity. The October p90 of 116 hours is likely an interaction effect, not a single mechanism.

I would revise the account if event-level data showed supplier-stratified rework returning to baseline after September while cycle times remained high, which would strengthen staffing attribution. If high-complexity waiting improved after July while standard waiting worsened, priority attribution would strengthen. Prior-year seasonal data would also separate recurrence from new drift.

## 10. Monitoring decision rules

1. IF `raw_model_fitness` drops by more than 0.10 while `mapped_model_fitness` remains within 0.03 of baseline, THEN update label mapping and inspect schema changes, BECAUSE the dominant drift is logging/semantic rather than operational.

2. IF Supplier Z share exceeds 30% and AssessRequestInfo exceeds 20 per 100 cases and rework variant share exceeds 20%, THEN trigger supplier document-quality audit and integration review, BECAUSE incomplete supplier bundles are generating rework loops.

3. IF queue waiting before Assess increases by more than 25% while Assess service time changes less than 10%, THEN trigger capacity and priority-rule review, BECAUSE the delay is queueing rather than slower service.

4. IF high-complexity share exceeds the seasonal forecast by more than 5 percentage points and Senior Assessment rate doubles, THEN re-stratify capacity planning and adjust case-mix adjustment, BECAUSE population/case-mix drift changes expected processing paths and workload.

5. IF duplicate `Open Case` share exceeds 1% or missing-resource share exceeds 3% and is concentrated by activity, THEN run a log provenance audit and repair extraction, BECAUSE measurement drift can bias conformance, resource, and workload analyses.

6. IF p90 cycle time rises faster than median and rework variant share increases, THEN analyze tail variants and segment by supplier and complexity, BECAUSE rework and queueing interaction produces extreme delays.

7. IF priority-class waiting times diverge after July with one class improving and another worsening, THEN partition monitoring by priority class and use difference-in-differences before changing operational targets, BECAUSE aggregate KPIs mask redistribution of delay.
