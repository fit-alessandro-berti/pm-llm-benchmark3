# 4. Risks invisible in average cycle time

1. **Tail latency and queue aging:** Average cycle time can improve if many simple cases move faster, while p90/p95 and long-waiting legal/risk or high-complexity cases deteriorate. A central queue often creates a long tail that averages hide. Monitor p90/p95, maximum wait, queue age, and SLA misses by segment.

2. **High-complexity cases:** These are a minority and may be masked by simpler cases. Central routing may improve average throughput while making high-complexity, legal/risk/security, and difficult QC cases wait longer or receive less local context. Analyze `case_complexity`, `required_specialty`, and high-complexity variants separately.

3. **Local knowledge loss:** North/South currently retain local knowledge that prevents unnecessary referrals and rework. Early averages may look good because local work is replaced by formal central advice, but over months local staff may lose technical capability. Track local technical activity variety, high-complexity exposure, `local_expertise_flag` interaction with rework, and role discovery over time.

4. **Fairness across teams and customer segments:** Overall averages can improve while East benefits, North/South degrade, and customers needing regional or language accommodation wait longer. Use event-log filters by `team`, `customer_segment`, `priority`, and accommodation flags. Compare p90 cycle time, SLA miss, rework, and outcomes, not only means.

5. **Learning and skill development:** Routing all hard cases away may improve short-term specialization but reduce local learning. Average cycle time cannot show that local staff are no longer developing technical judgment. Monitor who participates in high-complexity cases, activity-resource variety, and junior staff exposure to Specialist Review and Quality Check.

6. **Accountability and role clarity:** Shared approval and shared queues can blur ownership. A case may appear cycle-time efficient while it silently experiences more clarification loops, reassignment, or delayed decisions. Track `reassignment_count`, handover_reason, approval loops, and working-together network centrality of the shared queue.

7. **Exception handling and resilience:** Centralization may work in normal flow but fail during absence, unusual cases, or peak demand. Average cycle time under normal conditions can hide single-points-of-failure. Simulate central resource absence, monitor cross-team handovers, and analyze rare variants with long waiting times.

import pm4py

CASE = "case:concept:name"
ACT = "concept:name"
TS = "time:timestamp"

def prepare(df):
    df = df.copy()
    df[TS] = pd.to_datetime(df[TS])
    df = pm4py.format_dataframe(
        df,
        case_id=CASE,
        activity_key=ACT,
        timestamp_key=TS
    )
    return df

def case_durations_days(df):
    g = df.groupby(CASE)[TS].agg(["min", "max"])
    g["cycle_days"] = (g["max"] - g["min"]).dt.total_seconds() / 86400
    return g

def waiting_before_key_activities(df, activities):
    d = df.sort_values([CASE, TS]).copy()
    d["prev_ts"] = d.groupby(CASE)[TS].shift(1)
    d["wait_hours"] = (d[TS] - d["prev_ts"]).dt.total_seconds() / 3600
    return d[d[ACT].isin(activities)].groupby(ACT)["wait_hours"].describe(
        percentiles=[0.5, 0.9, 0.95]
    )

    d = df.sort_values([CASE, TS]).copy()
    d["next_resource"] = d.groupby(CASE)["org:resource"].shift(-1)
    d["next_team"] = d.groupby(CASE)["team"].shift(-1)
    n_cases = d[CASE].nunique()

    transitions = d[
        d["org:resource"].notna()
        & d["next_resource"].notna()
        & (d["org:resource"] != d["next_resource"])
    ].copy()

    edge_counts = (
        transitions.groupby(["org:resource", "next_resource"])
        .size()
        .reset_index(name="count")
    )
    edge_counts["per_100_cases"] = 100 * edge_counts["count"] / n_cases

    uniq_resources = d.groupby(CASE)["org:resource"].nunique()
    return edge_counts, uniq_resources

def filter_segments(df, team=None, complexity=None, specialty=None, segment=None):
    out = df.copy()
    # Depending on PM4Py version, use filter_trace_attribute_values for case-level attrs.
    if team:
        out = pm4py.filter_event_attribute_values(out, "team", team, level="case")
    if complexity:
        out = pm4py.filter_event_attribute_values(out, "case_complexity", complexity, level="case")
    if specialty:
        out = pm4py.filter_event_attribute_values(out, "required_specialty", specialty, level="case")
    if segment:
        out = pm4py.filter_event_attribute_values(out, "customer_segment", segment, level="case")
    return out

def sla_misses(df, thresholds_by_priority=None):
    if thresholds_by_priority is None:
        thresholds_by_priority = {"High": 5, "Medium": 7, "Low": 10}

    durs = case_durations_days(df).reset_index()
    last_attrs = (
        df.sort_values(TS)
        .groupby(CASE)
        .agg(priority=("priority", "last"), outcome=("outcome", "last"))
        .reset_index()
    )
    m = durs.merge(last_attrs, on=CASE, how="left")
    m["sla_threshold_days"] = m["priority"].map(thresholds_by_priority)
    m["sla_miss"] = m["cycle_days"] > m["sla_threshold_days"]
    return m

def analyze_period(df, label, filters=None):
    df = prepare(df)
    if filters:
        df = filter_segments(df, **filters)

    n_cases = df[CASE].nunique()

    # Process discovery and performance DFG
    dfg, start_activities, end_activities = pm4py.discover_dfg(df)
    perf_dfg = pm4py.discover_performance_dfg(df)
    variants = pm4py.get_variants(df)

    # Organizational networks
    handover_network = pm4py.discover_handover_of_work_network(df)
    working_together = pm4py.discover_working_together_network(df)
    subcontracting = pm4py.discover_subcontracting_network(df)
    resource_similarity = pm4py.discover_activity_based_resource_similarity(df)
    org_roles = pm4py.discover_organizational_roles(df)

    # Waiting/service times
    df_with_times = pm4py.insert_case_service_waiting_time(df)
    key_waits = waiting_before_key_activities(
        df,
        ["Specialist Review", "Quality Check", "Supervisor Approval", "Implementation"]
    )
    try:
        service_time_specialist = pm4py.get_service_time(df, activity="Specialist Review")
    except Exception:
        service_time_specialist = None

    # Rework
    rework_per_activity = pm4py.get_rework_cases_per_activity(df)

    # Temporal features and durations
    temporal_features = pm4py.extract_temporal_features_dataframe(df)
    durations = case_durations_days(df)["cycle_days"]
    sla = sla_misses(df)

    # Handover metrics
    edge_counts, uniq_resources = handover_metrics(df)

    # Variant filtering example: inspect top variants
    top_variants = list(variants.keys())[:5]
    variant_subset_stats = {}
    for v in top_variants:
        df_v = pm4py.filter_variants(df, [v])
        variant_subset_stats[str(v)] = {
            "cases": df_v[CASE].nunique(),
            "p90_cycle_days": case_durations_days(df_v)["cycle_days"].quantile(0.9)
        }

    return {
        "label": label,
        "n_cases": n_cases,
        "dfg": dfg,
        "start_activities": start_activities,
        "end_activities": end_activities,
        "performance_dfg": perf_dfg,
        "variants": variants,
        "top_variant_stats": variant_subset_stats,
        "handover_network": handover_network,
        "working_together_network": working_together,
        "subcontracting_network": subcontracting,
        "resource_similarity": resource_similarity,
        "org_roles": org_roles,
        "key_waits": key_waits,
        "service_time_specialist": service_time_specialist,
        "rework_per_activity": rework_per_activity,
        "temporal_features": temporal_features,
        "cycle_p50_days": durations.median(),
        "cycle_p90_days": durations.quantile(0.90),
        "cycle_p95_days": durations.quantile(0.95),
        "sla_miss_rate": sla["sla_miss"].mean(),
        "handover_edges": edge_counts,
        "unique_resources_per_case": uniq_resources.describe()
    }
