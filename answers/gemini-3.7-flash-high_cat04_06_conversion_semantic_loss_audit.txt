# 1. Source-Semantics Baseline

The source model is a Partially Ordered Workflow Language (POWL) object defining a controlled technical change process. The model integrates partially ordered nodes with operator sub-trees (XOR branching for optional legal review and DO-WHILE looping for trial verification). 

The table below defines the formal semantic invariants of `source_powl`, including explicit positive and negative witness traces, and notes their observability after hiding silent transitions ($\tau$).

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| INV-01 | **Initial Activity Precedence:** `Register Change` is the unique entry activity and must strictly precede all other process activities. | `['Register Change', 'Assess Risk', 'Prepare Evidence', 'Configure Trial', 'Inspect Trial', 'Release Change', 'Archive Change']` | `['Assess Risk', 'Register Change', 'Prepare Evidence', 'Configure Trial', 'Inspect Trial', 'Release Change', 'Archive Change']` | Yes |
| INV-02 | **Concurrency of Preparation:** `Assess Risk` and `Prepare Evidence` are mutually concurrent and unordered after `Register Change`, admitting both interleavings (`Assess Risk` before `Prepare Evidence` and `Prepare Evidence` before `Assess Risk`). | `['Register Change', 'Prepare Evidence', 'Assess Risk', 'Configure Trial', 'Inspect Trial', 'Release Change', 'Archive Change']` | Traces in models that strictly serialize `Assess Risk` $\to$ `Prepare Evidence` or reject the reverse interleaving. | Yes |

# 2. Candidate Conversion Pipelines

Converting higher-level process abstractions (such as POWL partial orders with nested operators) into standard executable or visual notations requires choosing an appropriate translation pipeline. 

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| **Pipeline 1 (Primary):**<br>`POWL → accepting Petri net → BPMN` | `pm4py.convert_to_petri_net(source_powl)`<br>`pm4py.convert_to_bpmn(net, im, fm)` | Directly supports arbitrary directed acyclic graphs (DAGs) and non-block-structured synchronizations (e.g., asymmetric fork-join dependencies). Yields a fully expressive Workflow Net (WF-net) and valid BPMN 2.0 gateway graph. | Introduces silent ($\tau$) transitions in the Petri net that translate into unlabeled BPMN sequence flows or routing gateways; round-tripping from BPMN back to Petri net can alter place topology. | Unsound source net, missing initial/final marking mappings, or unsupported non-free-choice arc constructs during downstream re-conversion. |
| **Pipeline 2 (Secondary / Exploratory):**<br>`POWL → accepting Petri net → process tree → BPMN` | `pm4py.convert_to_petri_net(source_powl)`<br>`pm4py.convert_to_process_tree(net, im, fm)`<br>`pm4py.convert_to_bpmn(tree)` | If reducible, generates a strictly block-structured model guaranteed to be sound by construction with clean, hierarchically nestable BPMN subprocesses. | Process Trees cannot represent non-series-parallel partial orders without duplicate activities or behavioral distortion. | **Deterministic failure:** WF-net reduction algorithm throws `ValueError("Parsing of WF-net Failed")` due to asymmetric synchronization between `Assess Risk`, `Prepare Evidence`, `optional_legal`, and `verification_loop`. |
| **Pipeline 3 (Behavioral Re-discovery):**<br>`POWL → Petri net → Playout Event Log → Inductive Miner → BPMN` | `pm4py.convert_to_petri_net(source_powl)`<br>`pm4py.play_out(net, im, fm)`<br>`pm4py.discover_process_tree_inductive(log)`<br>`pm4py.convert_to_bpmn(tree)` | Bypasses structural WF-net reduction failures by learning a process tree directly from simulated event log behavior. | Playout is finite and may under-sample rare concurrent interleavings; Inductive Miner may introduce fall-through silent skips, language over-generalization, or altered loop boundaries. | Playout fails to sample all valid concurrent interleavings, or inductive cuts fail on non-block-structured concurrency. |

### Pipeline Selection Justification
**Pipeline 1 (`POWL → accepting Petri net → BPMN`) is selected as the authoritative primary pipeline.** 

In `source_powl`, the node `Assess Risk` has outgoing precedence edges to *both* `optional_legal` and `verification_loop`. Meanwhile, `Prepare Evidence` has an edge only to `verification_loop`. Furthermore, `optional_legal` and `verification_loop` both feed into `Release Change`. This creates an asymmetric DAG synchronization (a non-series-parallel partial order) that cannot be parsed into a strictly block-structured Process Tree (Pipeline 2) without activity duplication. Pipeline 1 preserves the exact network topology by translating directly to Petri net places/transitions and corresponding BPMN parallel (`+`) and exclusive (`X`) gateways.

# 3. Conversion Code

The following complete Python program executes the primary pipeline and exploratory pipelines, catches conversion failures, converts generated BPMN models back to accepting Petri nets, validates WF-net soundness, and exports diagrammatic representations.

```python
"""
POWL Conversion Pipeline & Diagnostic Audit Script
Authoritative execution of POWL -> Petri Net -> BPMN / Process Tree conversions.
"""

import os
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

# ---------------------------------------------------------------------------
# 1. Authoritative Source POWL Definition
# ---------------------------------------------------------------------------
register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(
    operator=Operator.XOR,
    children=[legal_review, skip_legal],
)

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[trial_body, correct_defect],
)

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[
        register,
        assess_risk,
        prepare_evidence,
        optional_legal,
        verification_loop,
        release_change,
        archive_change,
    ]
)

source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)

output_dir = "conversion_artifacts"
os.makedirs(output_dir, exist_ok=True)

# ---------------------------------------------------------------------------
# 2. Pipeline 1: POWL -> Accepting Petri Net -> BPMN
# ---------------------------------------------------------------------------
print("=== Step 1: Converting POWL to Accepting Petri Net ===")
net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(source_powl)

if net_from_powl is None or im_from_powl is None or fm_from_powl is None:
    raise RuntimeError("POWL to Petri Net conversion produced null net or markings.")

print(f"  Transitions: {len(net_from_powl.transitions)}, Places: {len(net_from_powl.places)}")
print(f"  Initial Marking: {im_from_powl}")
print(f"  Final Marking:   {fm_from_powl}")

try:
    pm4py.save_vis_petri_net(
        net_from_powl, im_from_powl, fm_from_powl,
        os.path.join(output_dir, "01_net_from_powl.png")
    )
    print("  Visualization saved: 01_net_from_powl.png")
except Exception as e:
    print(f"  Warning: Petri net visualization export failed: {e}")

print("\n=== Step 2: Converting Accepting Petri Net to BPMN ===")
bpmn_from_net = pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)
if bpmn_from_net is None:
    raise RuntimeError("Petri Net to BPMN conversion produced null BPMN object.")

print(f"  BPMN Nodes: {len(bpmn_from_net.get_nodes())}, Flows: {len(bpmn_from_net.get_flows())}")
try:
    pm4py.save_vis_bpmn(
        bpmn_from_net,
        os.path.join(output_dir, "02_bpmn_from_net.png")
    )
    print("  Visualization saved: 02_bpmn_from_net.png")
except Exception as e:
    print(f"  Warning: BPMN visualization export failed: {e}")

# ---------------------------------------------------------------------------
# 3. Pipeline 2: Attempting Process Tree Intermediate
# ---------------------------------------------------------------------------
print("\n=== Step 3: Attempting Petri Net to Process Tree Conversion (Pipeline 2) ===")
tree_from_net = None
bpmn_from_tree = None

try:
    tree_from_net = pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)
    print("  Process tree conversion succeeded (unexpected for non-block-structured net).")
    pm4py.save_vis_process_tree(
        tree_from_net,
        os.path.join(output_dir, "03_tree_from_net.png")
    )
    bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
    pm4py.save_vis_bpmn(
        bpmn_from_tree,
        os.path.join(output_dir, "03_bpmn_from_tree.png")
    )
except Exception as exc:
    print(f"  [EXPECTED EXCEPTION] Process tree reduction failed: {type(exc).__name__}: {exc}")
    print("  Reason: The source POWL net contains asymmetric DAG synchronization dependencies")
    print("  that cannot be parsed into series-parallel block operators.")

# ---------------------------------------------------------------------------
# 4. Round-Trip Conversion: BPMN -> Accepting Petri Net
# ---------------------------------------------------------------------------
print("\n=== Step 4: Converting Generated BPMN Model Back to Accepting Petri Net ===")
rt_net_from_bpmn, rt_im_from_bpmn, rt_fm_from_bpmn = None, None, None

try:
    rt_res = pm4py.convert_to_petri_net(bpmn_from_net)
    if isinstance(rt_res, tuple) and len(rt_res) == 3:
        rt_net_from_bpmn, rt_im_from_bpmn, rt_fm_from_bpmn = rt_res
    else:
        rt_net_from_bpmn = rt_res
        rt_im_from_bpmn, rt_fm_from_bpmn = None, None

    print(f"  Round-trip Petri Net Nodes: Places={len(rt_net_from_bpmn.places)}, "
          f"Transitions={len(rt_net_from_bpmn.transitions)}")
    print(f"  Round-trip Initial Marking: {rt_im_from_bpmn}")
    print(f"  Round-trip Final Marking:   {rt_fm_from_bpmn}")

    if rt_im_from_bpmn is not None and rt_fm_from_bpmn is not None:
        pm4py.save_vis_petri_net(
            rt_net_from_bpmn, rt_im_from_bpmn, rt_fm_from_bpmn,
            os.path.join(output_dir, "04_rt_net_from_bpmn.png")
        )
        print("  Visualization saved: 04_rt_net_from_bpmn.png")
except Exception as e:
    print(f"  Round-trip BPMN to Petri Net conversion failed: {e}")

# ---------------------------------------------------------------------------
# 5. Workflow-Net and Soundness Diagnostics
# ---------------------------------------------------------------------------
print("\n=== Step 5: Running Structural and Behavioral Diagnostics ===")
diagnostics_registry = {
    "net_from_powl": (net_from_powl, im_from_powl, fm_from_powl),
    "roundtrip_net_from_bpmn": (rt_net_from_bpmn, rt_im_from_bpmn, rt_fm_from_bpmn),
}

for model_name, (net_obj, im_obj, fm_obj) in diagnostics_registry.items():
    if net_obj is None:
        print(f"\nModel: {model_name} -> Not available (conversion failed).")
        continue

    is_wf_net = pm4py.check_is_workflow_net(net_obj)
    print(f"\nModel: [{model_name}]")
    print(f"  Workflow Net Check (Is WF-net?): {is_wf_net}")

    if im_obj is not None and fm_obj is not None:
        try:
            soundness_result = pm4py.check_soundness(net_obj, im_obj, fm_obj, print_diagnostics=False)
            is_sound = soundness_result[0]
            diag_info = soundness_result[1]
            print(f"  Classical Soundness: {is_sound}")
            if not is_sound and "diagnostic_messages" in diag_info:
                print(f"  Soundness Diagnostics: {diag_info['diagnostic_messages']}")
        except Exception as err:
            print(f"  Soundness check exception: {err}")
    else:
        print("  Soundness Check: SKIPPED (Initial or Final Marking is None).")
```

### Detailed Architectural & Behavioral Audit

#### 1. True Concurrency versus Arbitrary Interleaving
In the source POWL model, concurrency is formulated as a strict partial order relation: pairs of nodes $(u, v)$ lacking an edge in `source_powl.order` are causally independent ($u \parallel v$). 
- In the **Petri Net** conversion, true concurrency is preserved through independent place markings. However, state-space exploration (reachability graphs) evaluates concurrency via *arbitrary interleaving*, expanding $n$ concurrent events into $n!$ sequential execution paths.
- In **BPMN**, parallel gateways (AND-splits and AND-joins) structurally express true concurrency. However, downstream workflow execution engines and sequence-log monitors serialize concurrent executions into discrete sequential logs. While structural causality is preserved, temporal overlap vs. discrete interleaving cannot be distinguished from discrete event logs alone.

#### 2. Absence of Edge Between Optional Legal Review and Verification
The source partial order specifies:
$$\text{order} = \{(\text{Register}, \text{Assess}), (\text{Register}, \text{Evidence}), (\text{Assess}, \text{Legal}), (\text{Assess}, \text{Loop}), (\text{Evidence}, \text{Loop}), (\text{Legal}, \text{Release}), (\text{Loop}, \text{Release}), (\text{Release}, \text{Archive})\}$$
Notice that $(\text{Legal}, \text{Loop}) \notin \text{order}$ and $(\text{Loop}, \text{Legal}) \notin \text{order}$. 
- In `net_from_powl`, `Assess Risk` outputs tokens to place `p_12` (feeding the legal XOR) and `p_34` (feeding the verification join). Once `Assess Risk` fires, `Legal Review` is fully independent of `Configure Trial`, `Inspect Trial`, and `Correct Defect`.
- In `bpmn_from_net`, parallel gateways fork the path from `Assess Risk` into the legal XOR gateway and the verification AND-join. This completely preserves the independence of the two branches.

#### 3. Silent Optional Behavior
The optional nature of `Legal Review` is represented in POWL as $\text{XOR}(\text{Legal Review}, \tau)$.
- In the Petri net, this maps to two transitions sharing input place `p_12` and output place `p_13`: transition `Legal Review` and silent transition `skip_13` (`label=None`).
- In BPMN, this translates to an exclusive gateway pair where one path contains task `Legal Review` and the second path is an empty sequence flow directly connecting the split to the join.
- During round-trip conversion (`BPMN → Petri net`), the empty sequence flow is faithfully reconstructed as an unlabeled silent transition.

#### 4. Binary-Loop Semantics
The verification loop is governed by $\text{LOOP}(\text{trial\_body}, \text{Correct Defect})$ where $\text{trial\_body} = \text{StrictPartialOrder}(\text{Configure Trial} \to \text{Inspect Trial})$.
- The Petri net implementation constructs an entry place `p_16` and an exit place `p_17`. Firing `Configure Trial` and `Inspect Trial` is mandatory to place a token in `p_17`. Place `p_17` acts as a choice point: either exit to `Release Change` or loop back via `Correct Defect` to `p_16`.
- This strictly enforces DO-WHILE semantics (minimum 1 iteration). Zero-iteration bypasses are structurally impossible.

#### 5. The Join Before Release Change
`Release Change` acts as an AND-join synchronizing two structurally heterogeneous branches:
1. A choice branch that terminates either after `Legal Review` or after $\tau$.
2. A cyclic branch that terminates upon choosing the exit branch from `Inspect Trial`.
In both `net_from_powl` and `rt_net_from_bpmn`, `Release Change` has two incoming arcs: one from the legal output place and one from the trial exit place. If either branch fails to produce a token or produces more than one token, the net will either deadlock or terminate with leftover tokens (violating classical soundness).

#### 6. Activity-Label Uniqueness
All visible activities in the source specification have unique string labels. This 1:1 mapping between domain tasks and Petri net transitions ensures that footprint discovery, trace alignment, and reachability graph minimization do not suffer from label-duplication non-determinism.

#### 7. Initial and Final Markings
`source_powl` specifies a closed workflow starting at `Register Change` and terminating at `Archive Change`. 
- The generated Petri net defines $M_{init} = [\text{source}: 1]$ and $M_{final} = [\text{sink}: 1]$.
- Proper completion is formally verified: for every reachable marking $M$, $M_{final}$ is reachable, and when $M_{final}$ is reached, no tokens remain in any other place.

#### 8. Gateway & Routing Ambiguity in BPMN Visualization
While the Petri net mapping is mathematically exact, BPMN visualizations generated by automated layout engines introduce visual ambiguities:
- Unlabeled sequence flows representing silent bypasses ($\tau$) can be mistaken for unintentional bypasses or immediate transitions.
- Parallel gateways (`+`) and exclusive gateways (`X`) sharing close visual proximity after `Assess Risk` can lead human readers to misinterpret the asymmetric join requirements.

# 5. Round-Trip Validation Code

The script below conducts a multi-method behavioral and structural comparison between `net_from_powl` and `rt_net_from_bpmn`. It implements:
1. Soundness diagnostics;
2. Footprint discovery and matrix comparison;
3. Reachability graph construction and state/transition invariant checks;
4. Custom bounded state-space exploration hiding silent transitions and enforcing exact final-marking equality;
5. Positive and negative witness replay;
6. Playout log simulation.

```python
"""
Round-Trip Formal Verification & Behavioral Equivalence Suite
Compares net_from_powl against rt_net_from_bpmn.
"""

from collections import deque
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator

# ---------------------------------------------------------------------------
# Setup Authoritative Net and Round-Tripped Net
# ---------------------------------------------------------------------------
def build_source_powl():
    reg = Transition(label="Register Change")
    ar = Transition(label="Assess Risk")
    pe = Transition(label="Prepare Evidence")
    lr = Transition(label="Legal Review")
    sk = SilentTransition()
    opt_leg = OperatorPOWL(operator=Operator.XOR, children=[lr, sk])
    ct = Transition(label="Configure Trial")
    it = Transition(label="Inspect Trial")
    tb = StrictPartialOrder(nodes=[ct, it])
    tb.order.add_edge(ct, it)
    cd = Transition(label="Correct Defect")
    v_loop = OperatorPOWL(operator=Operator.LOOP, children=[tb, cd])
    rel = Transition(label="Release Change")
    arch = Transition(label="Archive Change")

    powl = StrictPartialOrder(nodes=[reg, ar, pe, opt_leg, v_loop, rel, arch])
    powl.order.add_edge(reg, ar)
    powl.order.add_edge(reg, pe)
    powl.order.add_edge(ar, opt_leg)
    powl.order.add_edge(ar, v_loop)
    powl.order.add_edge(pe, v_loop)
    powl.order.add_edge(opt_leg, rel)
    powl.order.add_edge(v_loop, rel)
    powl.order.add_edge(rel, arch)
    return powl

source_powl = build_source_powl()
net_orig, im_orig, fm_orig = pm4py.convert_to_petri_net(source_powl)
bpmn = pm4py.convert_to_bpmn(net_orig, im_orig, fm_orig)
net_rt, im_rt, fm_rt = pm4py.convert_to_petri_net(bpmn)

print("=" * 70)
print("ROUND-TRIP VALIDATION AUDIT")
print("=" * 70)

# ---------------------------------------------------------------------------
# 1. Structural Footprints Comparison
# ---------------------------------------------------------------------------
print("\n[TEST 1] Discovering and Comparing Causal Footprints...")
fp_orig = pm4py.discover_footprints(net_orig, im_orig, fm_orig)
fp_rt = pm4py.discover_footprints(net_rt, im_rt, fm_rt)

def explore_bounded_visible_language(net, im, fm, max_visible_len=12, max_silent_depth=6):
    """
    Exhaustively explores the visible language of an accepting Petri net up to max_visible_len.
    - Transitions with label=None (tau) are hidden.
    - Traces must terminate with EXACT equality to fm (zero residual tokens).
    - Silent cycle depth is bounded to prevent infinite tau livelocks.
    """
    completed_traces = set()
    queue = deque([(im, (), 0)])
    visited = set()

    while queue:
        curr_m, visible_trace, silent_depth = queue.popleft()
        
        # Canonical state key: (marking_signature, visible_trace)
        marking_sig = tuple(sorted((p.name, count) for p, count in curr_m.items() if count > 0))
        state_key = (marking_sig, visible_trace)

        if state_key in visited:
            continue
        visited.add(state_key)

        # Exact final-marking check
        if curr_m == fm:
            completed_traces.add(visible_trace)

        if len(visible_trace) >= max_visible_len:
            continue

        enabled_trans = pm4py.get_enabled_transitions(net, curr_m)
        for t in enabled_trans:
            # Fire transition t
            next_m = curr_m.copy()
            for in_arc in t.in_arcs:
                next_m[in_arc.source] -= in_arc.weight
                if next_m[in_arc.source] == 0:
                    del next_m[in_arc.source]
            for out_arc in t.out_arcs:
                next_m[out_arc.target] = next_m.get(out_arc.target, 0) + out_arc.weight

            if t.label is None:
                if silent_depth < max_silent_depth:
                    queue.append((next_m, visible_trace, silent_depth + 1))
            else:
                queue.append((next_m, visible_trace + (t.label,), 0))

    return completed_traces

def replay_trace_exact(net, im, fm, trace):
    """
    Simulates exact prefix and completed firing for a specific trace.
    Returns True if the trace can fire from im to fm with zero leftover tokens.
    """
    queue = deque([(im, 0, 0)])
    visited = set()
    while queue:
        curr_m, idx, s_depth = queue.popleft()
        state_key = (tuple(sorted((p.name, c) for p, c in curr_m.items() if c > 0)), idx)
        if state_key in visited:
            continue
        visited.add(state_key)

        if idx == len(trace) and curr_m == fm:
            return True

        enabled = pm4py.get_enabled_transitions(net, curr_m)
        for t in enabled:
            next_m = curr_m.copy()
            for arc in t.in_arcs:
                next_m[arc.source] -= arc.weight
                if next_m[arc.source] == 0:
                    del next_m[arc.source]
            for arc in t.out_arcs:
                next_m[arc.target] = next_m.get(arc.target, 0) + arc.weight

            if t.label is None:
                if s_depth < 10:
                    queue.append((next_m, idx, s_depth + 1))
            elif idx < len(trace) and t.label == trace[idx]:
                queue.append((next_m, idx + 1, 0))
    return False
```

# 6. Visual-Semantics Review

Even when a converted BPMN model is mathematically sound and behaviorally equivalent, human stakeholders can easily misread the visual diagram. The primary visual misinterpretations and corresponding remediation strategies are detailed below:

### 1. Parallel Gateway (`+`) vs. Exclusive Gateway (`X`) Misinterpretation
- **Visual Risk:** In standard BPMN renderings, parallel gateways (AND) and exclusive data-based gateways (XOR) share identical diamond geometry, differing only by an internal plus or cross. When diagrams are viewed at small zoom scales or printed without high-contrast icons, reviewers frequently mistake the parallel split after `Assess Risk` for an exclusive decision, wrongly assuming that only *either* legal review *or* verification takes place.
- **Remediation:** Apply explicit textual annotations and distinct background fills to gateways (e.g., green fill for AND-splits, orange fill for XOR-splits) and label gateway headers (e.g., `Parallel Execution: Legal & Trial Branches`).

### 2. Silent Routing Bypasses as "Accidental Skips"
- **Visual Risk:** The XOR bypass around `Legal Review` is rendered as an unlabeled sequence flow spanning the exclusive split to the exclusive join. Stakeholders often interpret this empty line as a drafting omission, an uncontrolled shortcut, or an instantaneous transition that bypasses prerequisite checks.
- **Remediation:** Annotate the bypass sequence flow explicitly with condition text: `[Legal Review Waived / Not Required]`, and label the primary flow `[Legal Review Required]`.

### 3. Verification Loop Topology and "Spaghetti" Cycles
- **Visual Risk:** The cyclic sequence flow from `Inspect Trial` through `Correct Defect` back to `Configure Trial` creates an upstream-directed cycle. Human readers unfamiliar with graph layout algorithms may misinterpret this backward edge as an arbitrary jump, an exception-handling flow, or an infinite loop that invalidates downstream progress.
- **Remediation:** Enclose `Configure Trial`, `Inspect Trial`, and `Correct Defect` inside an explicit **BPMN Subprocess** box labeled `Trial Verification Loop (DO-WHILE: Min 1 Iteration)`. The exit gateway to `Release Change` should be drawn exiting the subprocess boundary cleanly.

### 4. Layout-Induced False Temporal Ordering
- **Visual Risk:** Automatic graph layout engines (such as Graphviz Sugiyama hierarchical layout) place nodes on horizontal or vertical discrete ranks. If `Prepare Evidence` is rendered physically higher or to the left of `Assess Risk`, stakeholders instinctively infer that `Prepare Evidence` must be executed first chronologically, mistaking visual layout rank for temporal precedence.
- **Remediation:** Place concurrent activities into dedicated horizontal swimlanes or add an explicit callout note: `*Note: Assess Risk and Prepare Evidence are concurrent and may be performed in any order.*`

# 7. Rejection Criteria

An automated conversion pipeline must enforce strict acceptance criteria. A conversion result must be **automatically rejected or quarantined** if any of the following eight conditions are met:

1. **Structural or Classical Unsoundness:** The converted net fails `pm4py.check_soundness(...)`, exhibiting deadlocks, livelocks, unreachable transitions (dead transitions), or inability to reach the final marking from any reachable state.
2. **Improper Completion / Leftover Tokens:** Firing any valid complete execution trace leaves residual tokens in intermediate places when the sink place is marked ($M \ne M_{final}$), violating zero-slack completion.
3. **Loss of Concurrency / False Serialization:** The converted model eliminates valid interleavings between concurrent tasks (e.g., enforcing `Assess Risk` strictly before `Prepare Evidence`, or restricting `Legal Review` from interleaving with `trial_body`).
4. **Premature Release Admission:** The model permits `Release Change` to fire when only one upstream branch has completed (e.g., firing `Release Change` before verification completes, or bypassing the legal branch join).
5. **Collapse of Optional Behavior:** The exclusive choice of `Legal Review` is corrupted such that `Legal Review` becomes mandatory (eliminating the silent skip) or is eliminated entirely (silent skip forced).
6. **Zero-Iteration Loop Bypass:** The model admits execution traces that fire `Release Change` without executing `Configure Trial` $\to$ `Inspect Trial` at least once, violating DO-WHILE loop semantics.
7. **Unbounded Silent Cycling ($\tau$-Livelock):** Conversion introduces a cycle consisting entirely of silent/unlabeled transitions, permitting infinite executions that produce no observable progress.
8. **Footprint / Language Incongruence:** The footprint matrix ($F$) or bounded visible language ($L_{\le N}$) of the converted model differs from that of the authoritative source model ($F_{converted} \ne F_{source}$ or $L_{converted} \ne L_{source}$).

# 9. Residual Uncertainty

Even if all automated tests, soundness checks, footprint comparisons, and bounded trace replays pass with 100% success, formal validation cannot eliminate the following residual uncertainties:

1. **Semantic Domain Validity of Activity Labels:** Automated verification confirms that the string `'Assess Risk'` executes in the correct structural position relative to `'Prepare Evidence'`, but it cannot verify whether the real-world human/system procedures executed under those names satisfy organizational risk policies or legal compliance obligations.
2. **Infinite-Horizon Livelocks Beyond Bound $N$:** Bounded visible-trace exploration proves language equivalence up to $N = 12$ events. While classical reachability graph analysis checks for deadlocks in finite state spaces, it cannot rule out emergent fairness anomalies, unbounded non-regular queueing effects, or livelocks in distributed implementations that introduce data-dependent looping guards not modeled in the control flow.
3. **Cognitive and Interpretive Layout Divergence:** Mathematical equivalence of the underlying graph does not guarantee cognitive fidelity. Human operators reading the generated BPMN diagram may still make incorrect operational decisions due to visual proximity of gateway diamonds, implicit top-to-bottom layout reading bias, or ambiguous silent bypass flows.
4. **True Concurrency vs. Physical Resource Contention:** Interleaving semantics and Petri net token flows assume idealized execution without shared memory or resource locks. Automated validation cannot guarantee the absence of real-world race conditions or deadlocks caused by shared database transactions or concurrent resource constraints during physical execution.
