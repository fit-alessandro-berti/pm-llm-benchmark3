# 1. Assumptions and notation

- **A1 — Event order and simultaneity.** The event order is S1 completion  S2 queue entry, and S2 start  S2 completion. At a reported timestamp, completions and arrivals/entries are recognized before starts. Thus a completion at \(t\) frees a resource for a start at \(t\), and a case entering a queue at \(t\) may start at \(t\). Snapshots are taken **after** all events at that timestamp.
- **A2 — Rounding.** A reported timestamp \(t\) represents an actual time in approximately \([t-2.5,t+2.5]\) minutes. Consequently, a difference between two independently rounded timestamps has a conservative interval of approximately \(d-5\) to \(d+5\) minutes. No de-rounding is performed; these are envelopes, not probability intervals.
- **A3 — Capacity and outage.** S1 has I1 and I2; S2 has C1 and C2. Each resource executes at most one case at a time. C2 is unavailable from 10:55 through 11:10, leaving 350 available minutes in the six-hour window. The reported central schedules show no obvious same-resource overlap; simultaneous rounded endpoints are resolved by A1.
- **A4 — No bypass or undocumented work.** Every observed case that completed S1 entered S2. Baseline calculations assume no assistance, preemption, transport time, or off-log activity. Apparent conflicts would need additional evidence rather than silent imputation.
- **A5 — Missing starts.** `MISSING` means execution occurred, but its start was not logged. It is not treated as a zero-duration activity and is not treated like a blank, never-started activity.
- **A6 — Missing-start constraints.** The admissible start interval is bounded by queue entry, the completion of the preceding job on the same resource, the current completion, and, where tighter, the next same-resource start. The nominal and rounding-adjusted bounds are:

  | Case/station | Nominal admissible start | Rounding-adjusted possible actual start |
  |---|---|---|
  | P07 / S1 | 09:25–10:00 | 09:22:30–10:02:30 |
  | P15 / S1 | 11:40–12:15 | 11:37:30–12:17:30 |
  | P05 / S2 | 09:45–10:15 | 09:42:30–10:17:30 |
  | P11 / S2 | 12:00–12:25 | 11:57:30–12:27:30 |

  The preceding/following resource jobs are, respectively, P05P07 on I1, P13P17 on I1, P03P07 on C1, and P08P13 on C2.
- **A7 — Imputation scenarios.** The **early-start/queue-optimistic** scenario uses each nominal lower bound; the **central** scenario uses the midpoint of each nominal interval; the **late-start/queue-pessimistic** scenario uses each nominal upper bound. Early starts imply longer observed service for the same completion, so “optimistic” is explicitly about queue waiting, not utilization.
- **A8 — Open activities.** `OPEN` means started but not completed at 14:00. Its **elapsed** service is \(14{:}00-\text{start}\). Its final service time is at least that elapsed amount and is **unbounded above** from these data. Open elapsed time is counted as busy time within the observation window, but not as a completed service.
- **A9 — Blank starts.** A blank S2 row after completed S1 means the case was waiting for S2 at 14:00. A blank S1 row means it was waiting for S1 at 14:00. The corresponding wait is right-censored and is reported as a horizon wait, not as a completed waiting time.
- **A10 — Busy time.** Busy time within the window is completed service plus elapsed service for open activities. Resource utilization is busy time divided by available resource-minutes: 360 minutes for I1, I2, and C1, and 350 minutes for C2.
- **A11 — Subperiods.** The operational bins are 08:00–10:00, 10:00–12:00, and 12:00–14:00. A timestamp exactly at 10:00 or 12:00 belongs to the later bin for arrivals/entries and for completions. These bins are descriptive of the morning surge and afternoon drain, not asserted stationary periods.
- **A12 — External arrival and total sojourn.** The external-arrival timestamp was rounded like the operational timestamps. Completed-case total sojourn is therefore directly \(S2\text{ end}-S1\text{ arrival}\), with an approximate ±5-minute envelope, regardless of an internal missing start.
- **A13 — Little’s Law.** A traditional Little’s-Law inference is not used for the full window or the strongly transient two-hour bins. One local, approximately balanced interval is used only as a consistency diagnostic; it is not used to impute any quantity.
- **A14 — WIP precision.** Reported-time event integration provides the central queue and WIP paths. Rounding can change event ordering slightly, so reported peaks are accompanied by conservative, explicitly non-extremal envelopes rather than exact claims about the true continuous peak.

# 2. Reconstruction method and formulas

Let:

- \(a_i\): external arrival at S1;
- \(x_{i1},e_{i1}\): actual S1 start and completion;
- \(e_{i1}\) is also the actual S2 queue-entry time;
- \(x_{i2},e_{i2}\): actual S2 start and completion;
- \(H=14{:}00\).

For completed activities:

\[
W_{i1}=x_{i1}-a_i,\qquad
D_{i1}=e_{i1}-x_{i1}
\]

\[
W_{i2}=x_{i2}-e_{i1},\qquad
D_{i2}=e_{i2}-x_{i2}
\]

\[
R_{i1}=e_{i1}-a_i=W_{i1}+D_{i1}
\]

\[
R_{i2}=e_{i2}-e_{i1}=W_{i2}+D_{i2}
\]

\[
T_i=e_{i2}-a_i
\]

where \(W\) is queue waiting, \(D\) is active service, and \(R\) is station sojourn.

For an activity still open:

\[
D^{\text{elapsed}}=H-x
\]

and

\[
D^{\text{final}}\ge D^{\text{elapsed}},\qquad
\text{no finite upper bound on }D^{\text{final}}.
\]

For a never-started case:

\[
W^{\text{censored}}(H)=H-\text{queue-entry time}.
\]

For a completed case with total sojourn directly bounded by two rounded endpoints:

\[
T_i^{\,L}=\hat T_i-5,\qquad T_i^{\,U}=\hat T_i+5.
\]

For an observed duration or wait \(\hat d\), the same conservative ±5-minute envelope is used, truncated below at zero where appropriate.

For a missing start, the nominal interval is

\[
L=\max(\text{entry},\text{previous same-resource completion}),\qquad
U=\min(\text{current completion},\text{next same-resource start}),
\]

with any additional feasibility constraint from S1-to-S2 precedence. The central start is \((L+U)/2\). Rounding-adjusted global wait and service bounds combine the possible start interval with the possible actual queue-entry or completion times.

Station WIP and queue length are:

\[
L^{WIP}_s(t)
 = \#\{\text{entered station }s,\ \text{not completed}\}
 = L^{queue}_s(t)+L^{active}_s(t),
\]

\[
L^{queue}_s(t)
 = \#\{\text{entered but not started}\}.
\]

The time-integrated means are

\[
\overline L^{queue}_s
 = \frac{1}{T}\int L^{queue}_s(t)\,dt,
\qquad
\overline L^{WIP}_s
 = \frac{1}{T}\int L^{WIP}_s(t)\,dt.
\]

The implementation integrates the exact piecewise-constant event path rather than sampling individual cases’ total waiting as though it were continuously present.

For a subperiod \(I\):

\[
\lambda^{arrival}_s(I)=
\frac{\#\{\text{station entries in }I\}}{|I|},
\qquad
\lambda^{departure}_s(I)=
\frac{\#\{\text{station completions in }I\}}{|I|}.
\]

Resource utilization is

\[
U_r=\frac{B_r}{m_r},
\]

where \(B_r\) is busy time and \(m_r\) is available time on resource \(r\).

For the local Little’s-Law diagnostic:

\[
\overline L^{queue}\ \stackrel{?}{=}\ \lambda W.
\]

This equality is exact for a stationary system and only approximate for the selected short, approximately balanced interval.

# 5. Bottleneck and temporal interpretation

## Early window: 08:00–10:00

The evidence favors **S1 as the initial queueing bottleneck**:

- S1 receives **13 arrivals** versus only **6 S1 completions**.
- Its central waiting time for starts in the bin averages **29.1 min**, versus **8.8 min** for S2.
- S1’s reported-time WIP rises to **7**, while S2’s peaks at **4**.
- S1’s queue grows from the initial arrival burst and remains the largest waiting pool.

S2 is faster to clear in this interval because many S2 entries have not yet arrived and the initial S2 queue is short. That does not make S2 intrinsically faster: S2 service times are generally longer.

## Middle window: 10:00–12:00

This is a transition period:

- S1 continues to accumulate a large standing queue: its mean WIP is **7.58**, with a peak queue of **7**.
- S2’s queue is smaller, but its waiting times increase: **35 min** on average for starts in the bin.
- S2 has lower mean service time in the central scenario because the two imputed services are short; among the **12 fully timed completed S2 services**, the mean is **40 min**, compared with approximately **27–28 min** at S1.
- The C2 outage reduces S2 capacity during a period in which P08 and subsequent work are waiting.

Thus the middle period retains a substantial **S1 backlog**, while S2 increasingly becomes a **service-capacity constraint**.

## Afternoon: 12:00–14:00

The unresolved bottleneck is more clearly **S2**:

- S1 receives only **one** new arrival and completes **five** cases; it is draining its earlier backlog.
- S2 receives **seven** entries and completes **none** during the bin.
- S2 ends the window with **six cases of WIP**, including **four waiting for service**, and reaches WIP **7**.
- S1 ends with only **two cases of WIP**.

The defensible overall conclusion is therefore a **time-varying combination**: S1 is the main early bottleneck, its backlog persists into the middle of the window, and S2 dominates the unresolved afternoon backlog.

## Maintenance interval

The C2 outage is directly observed from 10:55 to 11:10, and no C2 operation is recorded during it. C1 is executing P09 from 11:00 to 11:40, while P08, P10, and P11 accumulate behind the available S2 capacity.

A plausible counterfactual is that P08 could have started on C2 near 10:55 and finished around 11:40, rather than its recorded 11:15–12:00 interval. That would reduce P08’s delay by roughly 15–20 minutes. This is a **hypothesis**, not an identified causal effect: priority rules, assignment behavior, and completion times of other cases are not logged.

The outage is material but does not by itself explain the whole process backlog. The morning arrival surge at S1 and the longer S2 service times are larger structural contributors.

The apparently counterintuitive busy-time direction is important: an earlier start leaves more time before the fixed completion, so it produces a longer measured service.

### Stable conclusions

Stable across all three imputations:

- Arrival, entry, and completion counts.
- Completed-case total sojourn, because it is determined by recorded arrival and completion.
- Reported-time WIP paths derived from entries and completions.
- The qualitative temporal bottleneck interpretation: S1 early, S2 later.
- The fact that S2’s fully observed completed services are materially longer than S1’s.
- The right-censored conclusion that four S2 cases and one S1 case had not started by 14:00.

Not stable or only interval-defensible:

- Exact queue-wait means and percentiles.
- Exact resource utilization: early missing starts raise busy time because they lengthen service.
- Exact S2 mean service time: the fully observed completed mean is 40 min, while imputation scenarios give 34.3–38.2 min when all completed cases are included.
- Exact peak ordering and timing of queue events under timestamp perturbation.

## Right censoring

The two open S2 services have only **elapsed** durations of 25 minutes each; their final durations are unbounded. P21 has 30 elapsed S2 minutes and an unbounded final S1 duration. Consequently:

- They contribute lower-bound busy time within the window.
- They are not included in completed-service means.
- Their process total sojourns are lower bounds, not completed totals.
- A high utilization estimate should not be interpreted as evidence that these activities were unusually long.

## Rounding

Rounding has two separate effects:

1. It broadens every two-timestamp duration by about ±5 minutes.
2. It can change near-simultaneous event ordering, especially transitions such as C1’s P07 completion and P09 start at 11:00.

It does **not** change the directly measured completed totals by more than the stated endpoint envelopes, nor does it alter the observation that P15 and P17 were still active at 14:00.

## Local Little’s-Law diagnostic

The 10:00–12:00 bins are too transient for a defensible stationary Little’s-Law estimate. The best local check is S2 during **09:45–10:50**:

- Four S2 entries and four S2 completions occur.
- The queue remains small and has the same approximate endpoint level.
- Central mean queue length is \(90/65=1.38\).
- Mean wait of the four cases completed in the interval is 21.25 min.
- Effective completion rate is \(4/(65/60)=3.69\) cases/h.
- The implied \(L_q\) is \(3.69\times21.25/60=1.31\).

The 1.31 versus 1.38 difference is small enough to be consistent with rounding and P05’s imputation, but the interval is short and nonstationary. It is a **consistency check only**, not evidence of stationary operation and not a basis for imputing other intervals.

# 7. Reproducible Python

The code below embeds the data, keeps `MISSING`, `OPEN`, and blank statuses distinct, performs all three missing-start scenarios, computes station-specific queue/service/WIP metrics with pandas, and constructs a PM4Py interval-event DataFrame. The PM4Py insertion functions are applied only to a projection containing fully observed completed cases; their outputs are explicitly **case-level**, not station-level.

```python
import pandas as pd
import numpy as np
import pm4py

DATE = "2026-05-12"
H0 = pd.Timestamp(f"{DATE} 08:00")
H1 = pd.Timestamp(f"{DATE} 14:00")
WINDOW_MIN = (H1 - H0).total_seconds() / 60.0

raw = pd.DataFrame([
    ["P01","08:00","08:05","08:25","I1","08:30","09:00","C1","COMPLETE"],
    ["P02","08:05","08:10","08:35","I2","08:40","09:20","C2","COMPLETE"],
    ["P03","08:10","08:30","08:55","I1","09:05","09:45","C1","COMPLETE"],
    ["P04","08:20","08:40","09:10","I2","09:25","10:05","C2","COMPLETE"],
    ["P05","08:25","09:00","09:25","I1","MISSING","10:15","C1","COMPLETE_WITH_MISSING_START"],
    ["P06","08:35","09:15","09:45","I2","10:10","10:50","C2","COMPLETE"],
    ["P07","08:45","MISSING","10:00","I1","10:20","11:00","C1","COMPLETE_WITH_MISSING_START"],
    ["P08","09:00","09:50","10:20","I2","11:15","12:00","C2","COMPLETE"],
    ["P09","09:05","10:05","10:35","I1","11:00","11:40","C1","COMPLETE"],
    ["P10","09:15","10:25","10:55","I2","11:45","12:10","C1","COMPLETE"],
    ["P11","09:25","10:40","11:05","I1","MISSING","12:25","C2","COMPLETE_WITH_MISSING_START"],
    ["P12","09:35","11:00","11:30","I2","12:15","13:00","C1","COMPLETE"],
    ["P13","09:50","11:10","11:40","I1","12:30","13:20","C2","COMPLETE"],
    ["P14","10:00","11:35","12:00","I2","13:05","13:50","C1","COMPLETE"],
    ["P15","10:10","MISSING","12:15","I1","13:30","OPEN","C2","OPEN_IN_S2"],
    ["P16","10:25","12:05","12:35","I2","","","","WAITING_FOR_S2"],
    ["P17","10:45","12:20","12:50","I1","13:55","OPEN","C1","OPEN_IN_S2"],
    ["P18","11:00","12:40","13:10","I2","","","","WAITING_FOR_S2"],
    ["P19","11:15","12:55","13:25","I1","","","","WAITING_FOR_S2"],
    ["P20","11:30","13:15","13:45","I2","","","","WAITING_FOR_S2"],
    ["P21","11:50","13:30","OPEN","I1","","","","OPEN_IN_S1"],
    ["P22","12:10","","","","","","","WAITING_FOR_S1"],
], columns=[
    "case","arrival_s1","s1_start","s1_end","s1_resource",
    "s2_start","s2_end","s2_resource","state_at_14_00"
])

def parse_time(value):
    if value is None:
        return pd.NaT
    value = str(value).strip()
    if value in {"", "MISSING", "OPEN"}:
        return pd.NaT
    return pd.Timestamp(f"{DATE} {value}")

def parse_start(value):
    # MISSING and blank both produce NaT here, but raw status remains distinct.
    return parse_time(value)

def parse_end(value):
    # OPEN and blank both produce NaT here, but raw status remains distinct.
    return parse_time(value)

df = raw.copy()
df["arrival_ts"] = df["arrival_s1"].map(parse_time)
df["s1_start_ts"] = df["s1_start"].map(parse_start)
df["s1_end_ts"] = df["s1_end"].map(parse_end)
df["s2_start_ts"] = df["s2_start"].map(parse_start)
df["s2_end_ts"] = df["s2_end"].map(parse_end)

df["s1_status"] = np.select(
    [df["s1_start"].eq("MISSING"), df["s1_end"].eq("OPEN"),
     df["s1_start"].eq("")],
    ["MISSING_START", "OPEN", "WAITING"], default="COMPLETE"
)
df["s2_status"] = np.select(
    [df["s2_start"].eq("MISSING"), df["s2_end"].eq("OPEN"),
     df["s2_start"].eq("")],
    ["MISSING_START", "OPEN", "WAITING"], default="NOT_ENTERED"
)

def T(hhmm):
    return pd.Timestamp(f"{DATE} {hhmm}")

# Nominal missing-start constraints, in minutes from midnight.
imputation_bounds = {
    ("P07", "S1"): (T("09:25"), T("10:00")),
    ("P15", "S1"): (T("11:40"), T("12:15")),
    ("P05", "S2"): (T("09:45"), T("10:15")),
    ("P11", "S2"): (T("12:00"), T("12:25")),
}

def choose_start(case, station, scenario):
    key = (case, station)
    if key not in imputation_bounds:
        return None
    lo, hi = imputation_bounds[key]
    if scenario == "early":
        return lo
    if scenario == "late":
        return hi
    return lo + (hi - lo) / 2

def build_long(scenario):
    records = []
    for row in df.itertuples(index=False):
        s1s = row.s1_start_ts
        if row.s1_start == "MISSING":
            s1s = choose_start(row.case, "S1", scenario)

        s2s = row.s2_start_ts
        if row.s2_start == "MISSING":
            s2s = choose_start(row.case, "S2", scenario)

        records.append({
            "case": row.case,
            "station": "S1",
            "entry": row.arrival_ts,
            "start": s1s,
            "end": row.s1_end_ts,
            "resource": row.s1_resource,
            "status": row.s1_status,
        })

        # A case enters S2 only if S1 actually completed.
        if pd.notna(row.s1_end_ts):
            records.append({
                "case": row.case,
                "station": "S2",
                "entry": row.s1_end_ts,
                "start": s2s,
                "end": row.s2_end_ts,
                "resource": row.s2_resource,
                "status": row.s2_status,
            })

    out = pd.DataFrame(records)
    out["complete"] = out["end"].notna()
    out["open"] = out["status"].eq("OPEN")
    out["waiting"] = out["status"].eq("WAITING")

    wait, service, elapsed = [], [], []
    for r in out.itertuples(index=False):
        if pd.notna(r.start):
            wait.append((r.start - r.entry).total_seconds() / 60.0)
        elif r.waiting:
            wait.append((H1 - r.entry).total_seconds() / 60.0)
        else:
            wait.append(np.nan)

        if r.complete:
            d = (r.end - r.start).total_seconds() / 60.0
            service.append(d)
            elapsed.append(d)
        elif r.open:
            d = (H1 - r.start).total_seconds() / 60.0
            service.append(np.nan)
            elapsed.append(d)
        else:
            service.append(np.nan)
            elapsed.append(np.nan)

    out["wait_min"] = wait
    out["service_min"] = service
    out["busy_min"] = elapsed
    return out

def event_trace(rec):
    """
    Piecewise-constant station trace.
    At each timestamp, entries/arrivals and starts are recognized together;
    completed cases are removed from WIP. This implements A1.
    """
    times = {H0, H1}
    for col in ["entry", "start", "end"]:
        times.update(rec.loc[rec[col].notna(), col].tolist())
    times = sorted(t for t in times if H0 <= t <= H1)

    segments = []
    for i, t in enumerate(times[:-1]):
        nxt = times[i + 1]
        entered = rec["entry"].notna() & rec["entry"].le(t)
        started = rec["start"].notna() & rec["start"].le(t)
        completed = rec["end"].notna() & rec["end"].le(t)

        q = int(entered.sum() - started.sum())
        wip = int(entered.sum() - completed.sum())
        dt = (nxt - t).total_seconds() / 60.0
        segments.append({
            "t": t, "next_t": nxt, "dt": dt, "queue": q, "wip": wip
        })

    segments.append({
        "t": times[-1], "next_t": H1, "dt": 0.0,
        "queue": int(
            rec["entry"].notna().sum() - rec["start"].notna().sum()
        ),
        "wip": int(
            rec["entry"].notna().sum() - rec["end"].notna().sum()
        ),
    })
    return pd.DataFrame(segments)

def summarize_station(rec, station):
    z = rec[rec["station"].eq(station)].copy()
    started = z[z["start"].notna()]
    completed = z[z["complete"]]

    trace = event_trace(z)
    queue_area = float((trace["queue"] * trace["dt"]).sum())
    wip_area = float((trace["wip"] * trace["dt"]).sum())

    return {
        "scenario": scenario,
        "station": station,
        "arrivals_or_entries": int(z["entry"].notna().sum()),
        "completed": int(z["complete"].sum()),
        "started": int(z["start"].notna().sum()),
        "open": int(z["open"].sum()),
        "waiting": int(z["waiting"].sum()),
        "mean_started_wait": started["wait_min"].mean(),
        "median_started_wait": started["wait_min"].median(),
        "mean_completed_service": completed["service_min"].mean(),
        "median_completed_service": completed["service_min"].median(),
        "mean_queue": queue_area / WINDOW_MIN,
        "mean_wip": wip_area / WINDOW_MIN,
        "peak_queue": int(trace["queue"].max()),
        "peak_wip": int(trace["wip"].max()),
    }

def bin_label(ts):
    minute = ts.hour * 60 + ts.minute
    if minute < 600:
        return "08-10"
    if minute < 720:
        return "10-12"
    return "12-14"

def throughput_table(rec):
    rows = []
    for station in ["S1", "S2"]:
        z = rec[rec["station"].eq(station)]
        for b in ["08-10", "10-12", "12-14"]:
            arrivals = z["entry"].dropna().map(bin_label).eq(b).sum()
            departures = z.loc[z["complete"], "end"].map(bin_label).eq(b).sum()
            rows.append({
                "station": station, "bin": b,
                "arrivals": int(arrivals),
                "departures": int(departures),
                "arrival_rate_h": arrivals / 2.0,
                "departure_rate_h": departures / 2.0,
            })
    return pd.DataFrame(rows)

def resource_utilization(rec):
    rows = []
    for station in ["S1", "S2"]:
        z = rec[rec["station"].eq(station)]
        for resource, available in [
            ("I1", 360.0), ("I2", 360.0),
            ("C1", 360.0), ("C2", 350.0),
        ]:
            x = z[z["resource"].eq(resource)]
            if x.empty:
                continue
            busy = float(x["busy_min"].sum())
            rows.append({
                "scenario": scenario, "station": station,
                "resource": resource,
                "busy_min": busy,
                "available_min": available,
                "utilization": busy / available,
            })
    return pd.DataFrame(rows)

all_long = {}
all_summaries = []
all_resources = []
all_throughput = []

for scenario in ["early", "central", "late"]:
    rec = build_long(scenario)
    all_long[scenario] = rec
    for station in ["S1", "S2"]:
        all_summaries.append(summarize_station(rec, station))
    all_resources.append(resource_utilization(rec))
    all_throughput.append(throughput_table(rec))

summary = pd.DataFrame(all_summaries)
resources = pd.concat(all_resources, ignore_index=True)
throughput = pd.concat(all_throughput, ignore_index=True)

# Hourly snapshots under the central scenario.
central = all_long["central"]
snapshots = []
for station in ["S1", "S2"]:
    z = central[central["station"].eq(station)]
    trace = event_trace(z)
    for clock in ["08:00", "09:00", "10:00", "11:00", "12:00", "13:00", "14:00"]:
        t = T(clock)
        row = trace[trace["t"].eq(t)].iloc[0]
        snapshots.append({
            "station": station, "time": clock,
            "queue": int(row["queue"]), "wip": int(row["wip"])
        })
snapshots = pd.DataFrame(snapshots)

# Completed-case total sojourn: directly from recorded arrival and S2 completion.
case_totals = []
for row in df.itertuples(index=False):
    if pd.notna(row.s2_end_ts):
        total = (row.s2_end_ts - row.arrival_ts).total_seconds() / 60.0
        case_totals.append({
            "case": row.case,
            "total_min": total,
            "total_lower_approx": max(0.0, total - 5.0),
            "total_upper_approx": total + 5.0,
        })
case_totals = pd.DataFrame(case_totals)

# Conservative rounded bounds for the four missing starts.
rounding_adjusted = {
    ("P07", "S1"): (T("09:22:30"), T("10:02:30")),
    ("P15", "S1"): (T("11:37:30"), T("12:17:30")),
    ("P05", "S2"): (T("09:42:30"), T("10:17:30")),
    ("P11", "S2"): (T("11:57:30"), T("12:27:30")),
}
missing_bounds_rows = []
for (case, station), (start_lo, start_hi) in rounding_adjusted.items():
    r = df[df["case"].eq(case)].iloc[0]
    entry = r["arrival_ts"] if station == "S1" else r["s1_end_ts"]
    end = r["s1_end_ts"] if station == "S1" else r["s2_end_ts"]
    entry_lo, entry_hi = entry - pd.Timedelta(minutes=2.5), entry + pd.Timedelta(minutes=2.5)
    end_hi = end + pd.Timedelta(minutes=2.5)
    wait_lo = (start_lo - entry_hi).total_seconds() / 60.0
    wait_hi = (start_hi - entry_lo).total_seconds() / 60.0
    service_hi = (end_hi - start_lo).total_seconds() / 60.0
    missing_bounds_rows.append({
        "case": case, "station": station,
        "wait_lower": max(0.0, wait_lo),
        "wait_upper": wait_hi,
        "service_lower": 0.0,
        "service_upper": service_hi,
    })
missing_bounds = pd.DataFrame(missing_bounds_rows)

# PM4Py-compatible interval-event DataFrame.
interval_rows = []
for row in df.itertuples(index=False):
    for station, start, end, resource in [
        ("S1", row.s1_start, row.s1_end, row.s1_resource),
        ("S2", row.s2_start, row.s2_end, row.s2_resource),
    ]:
        # Only fully observed completed activities are usable intervals.
        if start in {"", "MISSING", "OPEN"} or end in {"", "MISSING", "OPEN"}:
            continue
        interval_rows.append({
            "case:concept:name": row.case,
            "concept:name": station,
            "start_timestamp": parse_start(start),
            "time:timestamp": parse_end(end),
            "org:resource": resource,
        })

events = pd.DataFrame(interval_rows, columns=[
    "case:concept:name", "concept:name",
    "start_timestamp", "time:timestamp", "org:resource"
])

def format_interval_df(frame):
    # Current PM4Py releases accept resource_id; older releases use resource.
    try:
        return pm4py.format_dataframe(
            frame,
            case_id="case:concept:name",
            activity="concept:name",
            timestamp="time:timestamp",
            resource_id="org:resource"
        )
    except TypeError:
        return pm4py.format_dataframe(
            frame,
            case_id="case:concept:name",
            activity="concept:name",
            timestamp="time:timestamp",
            resource="org:resource"
        )

formatted = format_interval_df(events)
if isinstance(formatted, tuple):
    log = formatted[0]
else:
    log = formatted

# Direct pandas station calculations are safer than convert_log_to_time_intervals:
# interval conversion can alter activity boundaries but cannot create S2 queue-entry
# events, recover missing starts, or provide station-specific WIP semantics.

# CASE-LEVEL projection only: both station activities fully observed and complete.
complete_case_ids = []
for case in df["case"]:
    x = df[df["case"].eq(case)].iloc[0]
    if (
        x["s1_start"] not in {"", "MISSING", "OPEN"}
        and x["s1_end"] not in {"", "MISSING", "OPEN"}
        and x["s2_start"] not in {"", "MISSING", "OPEN"}
        and x["s2_end"] not in {"", "MISSING", "OPEN"}
    ):
        complete_case_ids.append(case)

case_projection = pm4py.project(log, complete_case_ids)

def apply_mutation(function, projection):
    result = function(projection)
    return projection if result is None else result

case_projection = apply_mutation(
    pm4py.insert_case_service_waiting_time, case_projection
)
case_projection = apply_mutation(
    pm4py.insert_case_arrival_finish_rate, case_projection
)

# Independent pandas check of case-level external-arrival-to-finish semantics.
cl = df[df["case"].isin(complete_case_ids)].copy()
cl["external_total_min"] = (
    cl["s2_end_ts"] - cl["arrival_ts"]
).dt.total_seconds() / 60.0
cl["sum_active_service_min"] = (
    (cl["s1_end_ts"] - cl["s1_start_ts"]).dt.total_seconds()
    + (cl["s2_end_ts"] - cl["s2_start_ts"]).dt.total_seconds()
) / 60.0
cl["external_queue_plus_other_time_min"] = (
    cl["external_total_min"] - cl["sum_active_service_min"]
)

# Local Little's-Law diagnostic: S2, 09:45-10:50, central scenario.
z = central[central["station"].eq("S2")]
tr = event_trace(z)
lo, hi = T("09:45"), T("10:50")
part = tr[tr["t"].ge(lo) & tr["next_t"].le(hi)].copy()
observed_lq = (part["queue"] * part["dt"]).sum() / ((hi - lo).total_seconds() / 60.0)
completed_in_window = z[
    z["complete"] & z["end"].ge(lo) & z["end"].le(hi)
]
effective_rate_h = len(completed_in_window) / ((hi - lo).total_seconds() / 3600.0)
implied_lq = effective_rate_h * completed_in_window["wait_min"].mean() / 60.0

print(case_totals.round(1).to_string(index=False))
print(f"Completed mean total: {case_totals['total_min'].mean():.2f} min")

print(missing_bounds.round(1).to_string(index=False))

print("\n=== SCENARIO STATION SUMMARIES ===")

print("\n=== CENTRAL HOURLY QUEUE/WIP SNAPSHOTS ===")
print(snapshots.to_string(index=False))

print(resources.round(3).to_string(index=False))

print(throughput.round(2).to_string(index=False))

print(cl[[
    "case", "external_total_min",
    "sum_active_service_min",
    "external_queue_plus_other_time_min"

    attribute_names.update(event.keys())
print(sorted(attribute_names))

})
```
