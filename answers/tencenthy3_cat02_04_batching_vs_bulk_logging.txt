    # count overlapping intervals
    sub = sub.dropna(subset=["start","complete"])
    overlaps = 0
    n = len(sub)
    for i in range(n):
        for j in range(i+1, n):
            if sub.iloc[i]["start"] < sub.iloc[j]["complete"] and sub.iloc[j]["start"] < sub.iloc[i]["complete"]:
                overlaps += 1
    return overlaps

diag = df.groupby("cluster").apply(lambda x: pd.Series({
    "n_cases": len(x),
    "start_eq": x["start"].nunique() == 1,
    "end_eq": x["complete"].nunique() == 1,
    "rec_lag_sec": (x["recorded_at"] - x["complete"]).dt.total_seconds().median(),
    "queue_to_start_min": (x["start"] - x["queue_arrival"]).dt.total_seconds().median()/60 if x["start"].notna().any() else None,
    "overlap_pairs": overlap_pairs(x),
    "precision": x["precision"].iloc[0]
})).reset_index()

# 6. Preserve clusters with missing/suspect lifecycle (G6 zero service, G7 coarse)
diag["lifecycle_suspect"] = diag["cluster"].isin(["G6","G7"])
print("\n[Cluster Diagnostic Table]")
print(diag.to_string(index=False))
print("\n[Suspect Lifecycle Flagged]:")
print(diag[["cluster","lifecycle_suspect","start_eq","end_eq","overlap_pairs"]].to_string(index=False))

# 5. Robustness and alternative explanations

**Resource ID trusted vs shared accounts**
- If `RBT-7` is trusted (automated cell), G1 is genuinely simultaneous. If wrongly treated as a shared human account, one might falsely claim impossible multitasking.
- If `analyst_pool` (G5) is trusted as a single resource, utilization exceeds 100% (4 overlaps), forcing the conclusion of a shared-account artifact. Treating it as shared reveals up to 3 concurrent workers.
- `T-B` (G2) trusted implies one inspector used a group button; if it were a shared account, overlaps might be real concurrency, but completions are too staggered for pure concurrency.

**Exact vs interval-censored timestamps**
- If timestamps are exact, G6 shows zero service time (artifact). If interval-censored by 1-min precision, it remains zero.
- G7 under exact timestamps looks like a perfect 14:00–14:15 batch. If interval-censored to 15-min precision (start  [13:45,14:00), complete  [14:15,14:30)), true waiting and service variance reappear, and the "batch" disappears.

**Three cases where same temporal pattern supports multiple physical explanations**
1. **G1 (identical start & end):** genuine simultaneous batch (fixture) vs logging batch (PLC reports fixture completion once).
2. **G2 (identical start, staggered end):** start batching/common setup (group button) vs concurrent multitasking (inspector works on all four at once, finishing sequentially).
3. **G6 (identical start & end, bulk form):** end batching/bulk submission (manual shift-end entry) vs timestamp coarsening (if 1-min precision were silently rounded to hour).

# 6. Data-collection redesign

Prioritized recommendations:
1. **Execution timestamps:** Capture true per-case `start` and `complete` at the moment of physical action, not group-button or bulk-submit times (fixes G2, G3, G6).
2. **Resource/badge identity:** Replace shared logins (`analyst_pool`) with badge-verified worker IDs to separate concurrent work from artifacts (fixes G5).
3. **Source clock synchronization:** Implement NTP or central time broker so safety system and repair queue share a clock (fixes G8 capacity-loss inference).
4. **Timestamp precision metadata & enforcement:** Disable undocumented legacy rounding; store raw microseconds and explicit precision (fixes G7).
5. **Explicit group/batch identifiers:** Add a `batch_id` field distinct from `case_id` so process miners can distinguish operational batches from log batches (helps G1, G2).
6. **Pause/resume and downtime events:** Log safety checks, breaks, and fixture loads as explicit events rather than inferred gaps (helps G8, G1).
7. **Workstation capacity & fixture load:** Emit load/unload events for automated cells to confirm parallel capacity (confirms G1).
8. **Recording vs execution separation:** Ensure `recorded_at` is never used as a proxy for `complete` in performance KPIs.
