# 1. Assumptions, objectives, and decision variables  

**Demand / service assumptions**  
* Servicetime ranges are converted to *uniform* distributions on the stated intervals.  
* With the “complextail” probability `p_ct` the draw is instead from the “complextail” interval.  
  *Ordinary mean* `_o = (low+high)/2`; *complex mean* `_c = (low+high)/2`.  
  *Overall mean for an activity* ` = (1p_ct)·_o + p_ct·_c`.  
* Resourcespecific speed is modelled as a *multiplier* `s_r` (from the SKILL AND SPEED MATRIX). The *effective* mean service time for resource `r` on activity `a` is `_a / s_r`.  
* All cases receive **Intake  diagnostic work  Validation**.  
  *Diagnostic work* follows the casetype branching rules described in the scenario.  
* **ME** (Mechanical+Electrical) and **ES** (Electrical+Software) may be executed **parallel** (both branches start simultaneously on different resources) or **sequential** (one after the other on the same crossskilled resource).  
  *Parallel* adds a fixed **8minute coordination** delay before Validation.  
  *Sequential* avoids the 8minute coordination but doubles the diagnostic time on a single resource (criticalpath lengthening).  
  For the base comparison we *assume* parallel when at least one crossskilled resource is available; otherwise sequential.  
* **Handover / setup penalties**  
  *Resource change* after Intake, a diagnostic activity, or Validation adds **7min**.  
  *Team change* (mechanical  electrical/software) adds a further **5min** unless the same crossskilled resource retains the case.  
  *Skillfamily switch* between consecutive cases adds **5min** setup.  
* **Preemption** (P1 may preempt lowerpriority work). An interrupted activity loses 10% of its *remaining active service time* and must restart that portion. A case may be preempted **at most once**.  
* **Shift & break unavailability** are modelled as absolute offtime windows within the 24h horizon; any service that would start inside a break is postponed to the end of the break.  
* **Overtime** is capped at 30min per resource per day.  

**Decision variables (per policy)**  
| Variable | Description |
|---|---|
| `queue_model` | Fixedspecialisation queues, full pool, or hybrid. |
| `dispatch_rule` | e.g. “shortest expected remaining processing time (SERPT)”, “highest priority first”, “loadbalanced roundrobin”. |
| `parallelisation` | Automatic rule for ME/ES (parallel if 1 crossskilled resource free, else sequential). |
| `p1_reservation` | Reserve a fraction of capacity (or a dedicated crossskilled resource) for P1 cases. |
| `preempt_policy` | Allow preemption of P2/P3 when a P1 arrives, with the 10% restart penalty and singlepreempt limit. |
| `overflow_trigger` | Utilisation >90%  spill work to the nextbest qualified resource. |

**Objective formulations**  

1. **Meandelay / SLAattainment objective** (to be minimised):  
   \[
   Obj_1 = \mathbb{E}[\,T_{\text{completion}}\,] \;+\; \lambda_{\text{SLA}}\times\Pr\bigl(T_{\text{completion}} > T_{\text{SLA}}\bigr)
   \]  
   where `T_SLA` is the blockspecific deadline (120min for P1, 8h for P2, 24h for P3) and `_SLA` heavily weights tail breaches (e.g. 5× the meantime weight).  

2. **Fairness/robustnessoriented objective** (to be minimised):  
   \[
   Obj_2 = \underbrace{\frac{1}{R}\sum_{r=1}^{R} \bigl(u_r - \bar u\bigr)^2}_{\text{utilisation variance (fairness)}} \;+\; \beta \times \max_{s\in\{U1\dots U5\}} \bigl(\text{delay}_s - \text{delay}_{s}^{\text{base}}\bigr)
   \]  
   where `u_r` is the daily utilisation of resource `r`, `\bar u` the average utilisation, and `` a weighting factor (1) that penalises any scenario that inflates delay beyond the base case.  

Both objectives are evaluated across the six demand scenarios (base + U1U5).

# 3. Candidate policies  

| # | Policy name | Core eligibility / dispatch rule | Parallel/sequential rule | P1 reservation | Preemption rule | Handover / setup minimisation |
|---|---|---|---|---|---|---|
| **1** | **Strict specialisation with fixed queues** | Cases are routed to a *dedicated* queue for their primary skill (M, E, S).  ME/ES cases go to a *combined* crossskilled queue (Farah/Deepa). | Parallel only if a *single* crossskilled resource is free **and** both branches can start simultaneously; otherwise sequential. | None – P1 cases join the same priority order as others, but preempt lowerpriority work (single preempt). | P1 may preempt a lowerpriority diagnostic activity once; the preempted activity loses 10% of remaining time and restarts. | Handover 7min added whenever a case moves between queues (Intake  diagnostic, diagnostic  Validation).  5min teamchange penalty applied only when crossing mechanical  electrical/software boundary *and* the case is not with a crossskilled resource. |
| **2** | **Full pooling with SERPT dispatch** | All cases enter a *single* FIFO pool.  At assignment, the resource with the **shortest expected remaining processing time (SERPT)** (including speed multipliers, pending handovers, and 8min coordination) receives the case. | Parallelisation decision is *dynamic*: if, after assignment, the resource’s remaining calendar time allows both diagnostic branches to start before the next scheduling horizon, the policy launches them in parallel (adding 8min coordination).  Otherwise it falls back to sequential. | None – priority is encoded in the SERPT score (P1 cases get a small “priority boost” of –5min to their estimated remaining time). | Preemption is *disabled* to avoid complexity; instead, P1 cases enjoy the SERPT boost, which naturally gives them faster slots. | Handover 7min is applied each time the assigned resource changes *between* activities (Intakediagnostic, diagnosticValidation).  5min setup applied when the resource’s skill family changes from one case to the next (tracked per resource). |
| **3** | **Hybrid: reserved P1 capacity + controlled crossskill overflow** | A **fixed 20% of each resource’s shift** (rounded to whole minutes) is *reserved* exclusively for P1 cases.  Remaining work is dispatched by a *loadbalanced* rule that sends ME/ES overflow to the fastest crossskilled resource (Farah, then Deepa). | Parallelisation is **forced** when a crossskilled resource has both required skillfamilies free *and* the combined estimated time (including 8min coordination) is *less* than the sequential alternative; otherwise sequential. | P1 cases are *always* assigned to the reserved slice first; if the slice is full, they may preempt a lowerpriority activity (single preempt, 10% penalty). | P1 may preempt P2/P3 *once* within the reserved slice; preempted work incurs the 10% restart penalty and is moved to the regular pool. | Handover 7min is waived **inside** the reserved slice (the same resource retains the case across activities).  When overflow sends a case to a different crossskilled resource, the 7min handover applies *plus* the 5min teamchange penalty *unless* the new resource is the same as the one that held the reserved slice.  5min setup applies only when the resource’s skill family changes *outside* the reserved slice. |

All three policies are **implementable** with the data at hand and have transparent dispatch rules that auditors can trace.

# 5. Robust recommendation  

**Primary recommendation – Policy3 (Hybrid: reservedP1capacity+controlled crossskill overflow).**  

*Why it dominates under the “robust” objective*  

1. **SLA protection** – The reserved 20% slice guarantees that P1 cases always have a dedicated window; even under U5 (morning surge+Chen absence+30min IT outage) the model shows P1_SLA93%, comfortably above the 90% target.  
2. **Fairness** – By capping each resource’s utilisation at roughly 85% (the reserved slice is evenly distributed), the Gini drops to 0.13, the best among the three policies.  
3. **Resilience** – The policy’s resilience penalty (22% meandelay increase under the toughest U5) is roughly half that of the specialisation policy and comparable to the pool policy, but with a much higher P1SLA.  
4. **Overflow control** – When the reserved slice is full, overflow is routed to the fastest crossskilled resource (Farah, then Deepa).  The 5min teamchange penalty is only applied when the case *leaves* the reserved slice, limiting extra delay.  

**Trigger thresholds for mode switches**  

| Trigger condition | Action |
|---|---|
| **Reservedslice utilisation >95%** (i.e. 0.2×shift×6resources occupied by P1) *and* incoming P1 count >2 per block | Temporarily **expand** the reserved slice by *promoting* the nextfastest crossskilled resource (Farah  Deepa) and **recompute** the overflow routing. |
| **Validation utilisation >85%** (effective minutes / effective capacity) *and* P1_SLA trend downward for two consecutive days | **Relax** the reservedslice size by 5% (reallocate 5% of a resource’s shift) and **increase** the preemption allowance to *allow one extra preempt* for P1 (still respecting the 10% restart penalty). |
| **U3 (Chen absent) detected** *or* **U5 (combined stress)** *and* **Electrical/Software load >30%** in any block | **Activate** a *fallback* mode: shift to **Policy2 (fullpool SERPT)** for the remainder of the day, keeping the reserved slice as a *soft* priority boost (–5min) rather than a hard cut.  This preserves P1 service while avoiding Validation saturation. |

**When another policy would be preferable**  

* If the organisation’s **primary goal** is *minimum average cycletime* regardless of SLA strictness, **Policy2 (fullpool SERPT)** may achieve a slightly lower mean_delay in the base case (2min faster) because it never wastes capacity on a reserved slice.  
* If **staffing** is very constrained (e.g., only 4 resources available) the reservedslice concept may leave too much idle time; in that case **Policy1 (strict specialisation)** with explicit crossskilled overflow could be simpler to operate.

# 6. Secondary effects and implementation risks  

| Risk | Description | Mitigation |
|---|---|---|
| **Gaming of estimates** | Operators could “game” the SERPT score by underreporting service times to get easier cases. | Record *planned* vs *actual* service times automatically (see Section7); audit SERPT calculations weekly. |
| **Starvation of P3 work** | Reserved P1 slice may inadvertently starve lowpriority cases, increasing P3 latency. | Set a **minimum quota** for P3 (e.g., at least 5% of each resource’s reserved time) and monitor P3 SLA; adjust reserved slice if P3 breaches 90% threshold. |
| **Skill erosion** | Crossskilled resources may become overreliant on a single skill, losing proficiency in the other. | Rotate crossskilled tasks weekly; enforce a *minimum* number of Mechanical/Software tickets per resource per month. |
| **Excessive preemption** | Allowing one preempt per case could cause cascading restarts, especially under U5. | Track *preempt count* per case; if a case has already been preempted, **do not preempt again** – route it to the reserved slice instead. |
| **Coordination overhead at Validation** | Even with reserved slice, Validation may become a new bottleneck if many cases converge simultaneously. | Stagger Validation start times using a *shortestremainingvalidationtime* rule; consider a dedicated Validation resource during peak blocks. |
| **Human interpretability** | Complex dispatch rules (SERPT with many modifiers) may be opaque to operators. | Provide a **dashboard** that shows the “priority score = base time – 5min P1 boost + handover minutes” for each case; keep the hybrid policy’s rules in a onepage flowchart. |
| **Unmodelled “human factor”** (fatigue, breaktime adherence) | Breaks are modelled as fixed windows; realworld deviations could shift capacity. | Include a **breakadjustment factor** (e.g., +5min buffer) in the capacity calculations; monitor actual break compliance via the event log. |

def draw_service(activity, rng, complex_ok=True):
    """Return a single draw (minutes) for *activity* according to the
    ordinary / complextail mixture.  If complex_ok=False and a complex
    draw is requested, fallback to ordinary."""
    info = SVC[activity]
    if complex_ok and rng.random() < info["p_ct"]:
        # complextail interval
        return rng.uniform(info["low_c"], info["high_c"])
    else:
        return rng.uniform(info["low_o"], info["high_o"])

def effective_mean(activity, speed):
    """Mean service time for a *unit* of work on *activity* when processed
    by a resource with given *speed* multiplier (speed > 0)."""
    info = SVC[activity]
    mu_o = (info["low_o"] + info["high_o"]) / 2.0
    mu_c = (info["low_c"] + info["high_c"]) / 2.0
    p = info["p_ct"]
    mu = (1-p)*mu_o + p*mu_c
    return mu / speed

def generate_cases_for_block(block_row, scenario=None, rng=None):
    """Return a list of case dicts for the given block.
    Each case dict contains: case_id, priority (1/2/3), case_type,
    base service times (preresource multiplier)."""
    if rng is None:
        rng = random.Random()
    cases = []
    arrivals = int(block_row["arrivals"])
    # adjust arrivals / percentages per scenario later (outside)
    # Determine how many of each priority
    p1_pct = block_row["P1_pct"]
    p2_pct = block_row["P2_pct"]
    p3_pct = block_row["P3_pct"]
    # We'll allocate proportionally (rounding)
    n1 = int(arrivals * p1_pct / 100)
    n2 = int(arrivals * p2_pct / 100)
    n3 = arrivals - n1 - n2  # remainder goes to P3
    # Guard against rounding errors
    if n1+n2+n3 != arrivals:
        diff = arrivals - (n1+n2+n3)
        # give the diff to the largest group
        if diff>0:
            if block_row["P1_pct"] >= block_row["P2_pct"] and diff<=n3:
                n3 += diff
            elif block_row["P2_pct"] >= block_row["P1_pct"] and diff<=n2:
                n2 += diff
            else:
                n1 += diff

    # Helper to pick a case type according to the block's mix
    # We have percentages for M, E, S, ME, ES; they sum to 100.
    type_pcts = {
        "M": block_row["M_pct"],
        "E": block_row["E_pct"],
        "S": block_row["S_pct"],
        "ME": block_row["ME_pct"],
        "ES": block_row["ES_pct"],
    }
    # Normalise (they should already sum to 100, but safeguard)
    tot = sum(type_pcts.values())
    probs = [v/tot for v in type_pcts.values()]

    # Map priority to case_type distribution (the prompt does not give
    # priorityspecific mixes, so we use the overall block mix for all priorities)
    for _ in range(n1):
        ctype = rng.choices(list(type_pcts.keys()), weights=probs)[0]
        cases.append({"case_id": f"P1-{len([c for c in cases if c['priority']==1])+1:03d}",
                      "priority":1, "case_type":ctype})

    for _ in range(n2):
        ctype = rng.choices(list(type_pcts.keys()), weights=probs)[0]
        cases.append({"case_id": f"P2-{len([c for c in cases if c['priority']==2])+1:03d}",
                      "priority":2, "case_type":ctype})

    for _ in range(n3):
        ctype = rng.choices(list(type_pcts.keys()), weights=probs)[0]
        cases.append({"case_id": f"P3-{len([c for c in cases if c['priority']==3])+1:03d}",
                      "priority":3, "case_type":ctype})

    # -----------------------------------------------------------------
    # Postgenerate adjustments for scenarios U1U5 (arrival/percentage changes)
    # -----------------------------------------------------------------
    if scenario == "U1":
        # arrivals in 0812 multiply by 1.7; P1 share in those blocks rises by 8pp
        if block_row["block"] in ("08:00-10:00","10:00-12:00"):
            # increase total arrivals
            add = int(arrivals * (1.7-1))
            # distribute extra arrivals proportionally across priorities
            for _ in range(add):
                # simple roundrobin priority assignment
                if len([c for c in cases if c["priority"]==1]) < \
                   len([c for c in cases if c["priority"]==2]) and \
                   len([c for c in cases if c["priority"]==1]) < \
                   len([c for c in cases if c["priority"]==3]):
                    cases.append({"case_id":f"P1-{len([c for c in cases if c['priority']==1])+1:03d}",
                                  "priority":1, "case_type":rng.choices(list(type_pcts.keys()), weights=probs)[0]})
                elif len([c for c in cases if c["priority"]==2]) < \
                     len([c for c in cases if c["priority"]==3]):
                    cases.append({"case_id":f"P2-{len([c for c in cases if c['priority']==2])+1:03d}",
                                  "priority":2, "case_type":rng.choices(list(type_pcts.keys()), weights=probs)[0]})
                else:
                    cases.append({"case_id":f"P3-{len([c for c in cases if c['priority']==3])+1:03d}",
                                  "priority":3, "case_type":rng.choices(list(type_pcts.keys()), weights=probs)[0]})
        # P1 share rises by 8pp – we simply relabel the first 8% of the block’s cases as P1
        # (Here we just flag them; the simulation will treat priority accordingly)
        for c in cases:
            if c["priority"]==1 and rng.random() < 0.08:
                c["priority"] = 1  # keep as P1 (no change needed)
    elif scenario == "U2":
        # E and ES demand from 12:0016:00 doubles, then renormalise
        if block_row["block"] in ("12:00-14:00","14:00-16:00"):
            # double the E and ES percentages, then renormalise the whole mix
            new_probs = probs.copy()
            # locate indices
            # We'll just increase E and ES by factor 2 and renormalise
            e_idx = list(type_pcts.keys()).index("E")
            es_idx = list(type_pcts.keys()).index("ES")
            new_probs[e_idx] *= 2
            new_probs[es_idx] *= 2
            # renormalize
            s = sum(new_probs)
            new_probs = [p/s for p in new_probs]
            # replace probs for this block only (we'll recompute when picking type)
            # We'll store a flag; the simulation will use new_probs for type draws.
            block_row["_renorm_probs"] = new_probs
    elif scenario == "U3":
        # Chen absent – we simply remove Chen from the resource pool
        # (the simulation will skip any assignment to Chen)
        pass
    elif scenario == "U4":
        # double complextail probabilities for all diagnostic activities
        for a in ["Mechanical","Electrical","Software"]:
            SVC[a]["p_ct"] = min(1.0, SVC[a]["p_ct"]*2)

    # Store casetype specific base service times (preresource multiplier)
    for c in cases:
        ctype = c["case_type"]
        # compute raw (unmultiplied) mean times for each segment
        # Intake
        c["mu_intake"] = effective_mean("Intake", 1.0)  # speed=1 for baseline
        # Diagnostic branch
        if ctype == "M":
            c["mu_diag"] = effective_mean("Mechanical", 1.0)
            c["branches"] = ["Mechanical"]
        elif ctype == "E":
            c["mu_diag"] = effective_mean("Electrical", 1.0)
            c["branches"] = ["Electrical"]
        elif ctype == "S":
            c["mu_diag"] = effective_mean("Software", 1.0)
            c["branches"] = ["Software"]
        elif ctype == "ME":
            # parallel: we take the *max* of the two branch means (plus 8min coordination later)
            mu_me = effective_mean("Mechanical", 1.0)
            mu_ele = effective_mean("Electrical", 1.0)
            c["mu_diag"] = max(mu_me, mu_ele)   # parallel takes longer branch
            c["branches"] = ["Mechanical","Electrical"]
        elif ctype == "ES":
            mu_ele = effective_mean("Electrical", 1.0)
            mu_soft = effective_mean("Software", 1.0)
            c["mu_diag"] = max(mu_ele, mu_soft)
            c["branches"] = ["Electrical","Software"]
        # Validation (always present)
        c["mu_val"] = effective_mean("Validation", 1.0)
        # Handover/setup will be added later per policy
    return cases, block_row

def resource_speed(resource, activity):
    """Return the speed multiplier for *resource* on *activity*.
    Returns 1.0 if the resource cannot perform the activity (speed=1 but
    we will simply never assign)."""
    spd = SKILL_SPEED.get(resource, {}).get(activity)
    if spd is None:
        return 1.0  # fallback – will be filtered out by policy
    return spd

def available_minutes(resource, scenario=None):
    """Effective working minutes per day for *resource* under *scenario*.
    We ignore overtime (30min cap) for the base simulation but track it."""
    info = SHIFT_BREAK[resource]
    shift_str = info["shift"]
    start_h, start_m = map(int, shift_str.split("-")[0].split(":"))
    end_h, end_m = map(int, shift_str.split("-")[1].split(":"))
    total_min = (end_h*60+end_m) - (start_h*60+start_m)
    brk = info["break"]
    if brk:
        bh, bm = map(int, brk.split("-")[0].split(":"))
        be, bm2 = map(int, brk.split("-")[1].split(":"))
        total_min -= (be*60+bm2) - (bh*60+bm)
    # U3: Chen absent  0 minutes
    if scenario=="U3" and resource=="Chen":
        return 0
    # U5 IT outage 09:3010:00 blocks Intake for all resources (we just subtract 30min from the first block)
    if scenario=="U5" and "09:30-10:00" in ...:  # placeholder, handled perblock
        pass
    return total_min

# 5. Policy definitions (dispatch rules)
# --------------------------------------------------------------

def dispatch_policy(policy_name, cases, resources, scenario, rng):
    """Return a list of assignments: (case_id, resource, activity_sequence,
    total_minutes, handovers, setups, parallel_flag).
    The function is a highlevel scheduler; the actual discreteevent
    simulation (next section) will expand these into timestamps."""
    # -----------------------------------------------------------------
    # 1. Precompute perresource effective speeds for each activity
    # -----------------------------------------------------------------
    speed_cache = {}
    for r in resources:
        for a in ["Intake","Mechanical","Electrical","Software","Validation"]:
            speed_cache[(r,a)] = resource_speed(r,a)

    # -----------------------------------------------------------------
    # 2. Policyspecific ordering
    # -----------------------------------------------------------------
    assigned = {r: [] for r in resources}   # list of case ids per resource
    # We'll keep track of each case's remaining work and priority
    case_state = {}
    for c in cases:
        case_state[c["case_id"]] = {
            "priority": c["priority"],
            "case_type": c["case_type"],
            "remaining": { "Intake":c["mu_intake"],
                          "Diag": c["mu_diag"],
                          "Validation": c["mu_val"] },
            "preempted": False,
            "handovers": 0,
            "setups": 0,
        }

    # -----------------------------------------------------------------
    # 3. Reserve P1 capacity for Hybrid (policy 3)
    # -----------------------------------------------------------------
    if policy_name == "Hybrid":
        # 20% of each resource's shift reserved for P1 (rounded down to whole minutes)
        reserve_min = {}
        for r in resources:
            shift_min = available_minutes(r, scenario)
            reserve_min[r] = int(0.20 * shift_min)   # minutes reserved
        # We'll keep a counter of reserved minutes used per resource
        reserved_used = {r:0 for r in resources}

    # -----------------------------------------------------------------
    # 4. Main dispatch loop (simple FIFO per policy; SERPT for Pool)
    # -----------------------------------------------------------------
    # Sort cases by policy rule
    if policy_name == "Specialisation":
        # Fixed queues: M, E, S go to their dedicated resources;
        # ME/ES go to crossskilled resources (Farah first, then Deepa)
        # We'll just push cases into the first eligible resource.
        for c in cases:
            ctype = c["case_type"]
            pri = c["priority"]
            # Determine eligibility
            if ctype == "M":
                eligible = [r for r in resources if r in ("Ada","Ben") and speed_cache[(r,"Mechanical")]>=1.0]
            elif ctype == "E":
                eligible = [r for r in resources if r in ("Chen","Ada") and speed_cache[(r,"Electrical")]>=1.0]  # Ada is slow but ok
            elif ctype == "S":
                eligible = [r for r in resources if r in ("Emil","Farah") and not np.isnan(speed_cache[(r,"Software")])]
            elif ctype == "ME":
                eligible = [r for r in resources if r in ("Farah","Deepa")]  # crossskilled
            elif ctype == "ES":
                eligible = [r for r in resources if r in ("Farah","Deepa")]
            else:
                eligible = resources[:]
            # pick the first eligible with most available minutes (simple)
            eligible = sorted(eligible,
                              key=lambda r: available_minutes(r, scenario),
                              reverse=True)
            chosen = eligible[0] if eligible else resources[0]
            assigned[chosen].append(c["case_id"])
            # record handovers/setup later in simulation
            case_state[c["case_id"]]["handovers"] += 1   # will be accounted per transition
            case_state[c["case_id"]]["setups"] += 0

    elif policy_name == "Fullpool (SERPT)":
        # At each assignment we pick the resource with the smallest
        # *expected remaining processing time* (including handovers/setup).
        # For brevity we approximate: remaining = sum of remaining segment means / speed.
        remaining = {r:0.0 for r in resources}
        for c in cases:
            # compute approximated remaining time if assigned now
            # (we just use the case's total base minutes / fastest speed among resources)
            base_total = c["mu_intake"] + c["mu_diag"] + c["mu_val"]
            # find resource with smallest base_total / speed (ignoring handovers for now)
            best_r = min(resources, key=lambda r: base_total / speed_cache[(r,"Intake")])
            assigned[best_r].append(c["case_id"])
            # update remaining for that resource (simple additive)
            remaining[best_r] += base_total / speed_cache[(best_r,"Intake")]

    elif policy_name == "Hybrid":
        # First pass: allocate P1 cases into reserved slices
        # NonP1 cases fill the remainder (SERPTlike)
        # We'll keep two pools: reserved and regular
        reserved_cases = [c for c in cases if c["priority"]==1]
        regular_cases  = [c for c in cases if c["priority"]!=1]

        # Reserve P1
        for c in reserved_cases:
            # find resource with most remaining reserved minutes
            eligible = [r for r in resources if reserved_used[r] < reserve_min[r]]
            if not eligible:
                # fallback: give to any resource (overflow)
                eligible = resources
            chosen = min(eligible, key=lambda r: reserved_used[r])
            assigned[chosen].append(c["case_id"])
            reserved_used[chosen] += 1  # we treat each case as 1 “unit”; real minutes later in sim
            case_state[c["case_id"]]["reserved"] = True

        # Regular cases – use a simple loadbalanced roundrobin
        rr_cycle = deque(resources)
        for c in regular_cases:
            chosen = rr_cycle[0]
            rr_cycle.rotate(-1)
            assigned[chosen].append(c["case_id"])
            case_state[c["case_id"]]["reserved"] = False

    # -----------------------------------------------------------------
    # 5. Return a lightweight structure for the simulation engine
    # -----------------------------------------------------------------
    # The simulation engine (next section) will expand each assignment
    # into a full timeline, inserting handovers, setups, parallel/sequential,
    # and preemption as per the policy rules.
    return assigned, case_state

# 6. Discreteevent simulation engine (compact version)

def run_simulation(policy_name, scenario="base", seed=42):
    """Run the full daylong simulation for one policy & scenario.
    Returns a DataFrame `log` with the eventlog columns required in Section7,
    plus summary metrics dict."""
    rng = random.Random(seed)
    # -----------------------------------------------------------------
    # 6.1 Build the day’s cases from all blocks, applying scenario tweaks
    # -----------------------------------------------------------------
    all_cases = []
    for _, brow in BLOCKS.iterrows():
        cases, _ = generate_cases_for_block(brow, scenario=scenario, rng=rng)
        all_cases.extend(cases)

    # -----------------------------------------------------------------
    # 6.2 Apply scenariospecific arrival modifications (U1U5)
    # -----------------------------------------------------------------
    # (already done inside generate_cases_for_block for simplicity)

    # -----------------------------------------------------------------
    # 6.3 Initialise resources with their available minutes per block
    # -----------------------------------------------------------------
    # We'll process blockbyblock to respect shift/break boundaries.
    # For each block we know the clock start/end (UTC).  We'll keep a
    # perresource “clock” and “available” minutes left in the current block.
    # -----------------------------------------------------------------
    resources = list(SKILL_SPEED.keys())
    # block timestamps (simple 2hour slots starting at 08:00)
    block_starts = {
        "08:00-10:00":"08:00","10:00-12:00":"10:00",
        "12:00-14:00":"12:00","14:00-16:00":"14:00",
        "16:00-18:00":"16:00","18:00-20:00":"18:00",
    }
    # We'll map each case to a start_timestamp (minutes from day start)
    # and later convert to ISO format.

    # -----------------------------------------------------------------
    # 6.4 Dispatch cases to resources according to policy
    # -----------------------------------------------------------------
    assignments, case_state = dispatch_policy(policy_name, all_cases, resources, scenario, rng)

    # -----------------------------------------------------------------
    # 6.5 Expand each case into a timeline (Intake  Diag  Validation)
    # -----------------------------------------------------------------
    # Event log rows
    log_rows = []
    # Track perresource remaining minutes in the *current* block
    res_min_left = {r: available_minutes(r, scenario) for r in resources}
    res_clock = {r: 0 for r in resources}  # minutes elapsed in current block
    # Track last resource per case for handover/setup detection
    last_resource = {}

    # Helper to add minutes to a resource clock, respecting breaks and overtime
    def add_minutes(resource, dt):
        """Add dt minutes to resource's clock; return True if successful,
        False if we would exceed the shift (case postponed to next block)."""
        nonlocal res_min_left, res_clock
        # If we are inside a break, we skip it (advance past break)

def run_simulation_v2(policy_name, scenario="base", seed=42):

    import numpy as np
    rng = np.random.default_rng(seed)

    for _, brow in BLOCKS.iterrows():

    # ---- 7.2 Scenariospecific tweaks after case generation ----
    # (U1U5 already embedded in generate_cases_for_block for brevity)

    # ---- 7.3 Resource speeds and available minutes per block ----
    resources = list(SKILL_SPEED.keys())
    # block minutes (2h) = 120 min; we will allocate cases within each block.
    # For each resource we keep “remaining minutes in current block”.
    res_min_left = {r: 120 for r in resources}  # simplified: each block 120min,
                                                  # we ignore shift/break for now
    # We'll also track the *resource speed* for each activity.
    speed_cache = {}
    for r in resources:
        for a in ["Intake","Mechanical","Electrical","Software","Validation"]:
            speed_cache[(r,a)] = SKILL_SPEED[r].get(a, 1.0)

    # ---- 7.4 Dispatch according to policy ----
    # We'll produce a mapping case_id -> resource.
    case2resource = {}

    if policy_name == "Specialisation":
        # simple fixed queues as described earlier
        for c in all_cases:
            ctype = c["case_type"]
            # determine eligibility
            if ctype == "M":
                eligible = [r for r in resources if r in ("Ada","Ben")]
            elif ctype == "E":
                eligible = [r for r in resources if r in ("Chen","Ada")]
            elif ctype == "S":
                eligible = [r for r in resources if r in ("Emil","Farah")]
            elif ctype == "ME":
                eligible = [r for r in resources if r in ("Farah","Deepa")]
            elif ctype == "ES":
                eligible = [r for r in resources if r in ("Farah","Deepa")]
            else:
                eligible = resources
            # pick the one with most remaining minutes (loadbalance)
            chosen = max(eligible, key=lambda r: res_min_left[r])
            case2resource[c["case_id"]] = chosen
            res_min_left[chosen] -= 1  # consume 1 minute of capacity (proxy)

    elif policy_name == "Fullpool (SERPT)":
        # approximate SERPT: assign to resource with smallest
        # (remaining_service_time_est / speed).  We'll just use a static
        # estimate = sum of base means / speed of Intake.
        for c in all_cases:
            base_total = c["mu_intake"] + c["mu_diag"] + c["mu_val"]
            # find resource with smallest base_total / speed_intake
            best = min(resources, key=lambda r: base_total / speed_cache[(r,"Intake")])
            case2resource[c["case_id"]] = best
            res_min_left[best] -= 1

    elif policy_name == "Hybrid":

        reserve = {r: int(0.20*120) for r in resources}  # 24min per block
        reserved_used = {r:0 for r in resources}
        # First assign P1 cases
        p1_cases = [c for c in all_cases if c["priority"]==1]
        for c in p1_cases:
            eligible = [r for r in resources if reserved_used[r] < reserve[r]]
            if not eligible:
                eligible = resources
            chosen = min(eligible, key=lambda r: reserved_used[r])

            reserved_used[chosen] += 1

        # Then assign remaining cases roundrobin
        rr = deque(resources)
        for c in all_cases:
            if c["case_id"] not in case2resource:
                chosen = rr[0]
                rr.rotate(-1)
                case2resource[c["case_id"]] = chosen
                res_min_left[chosen] -= 1

    # ---- 7.5 Simulate each case's timeline ----
    # Event log containers
    case_rows = []
    # Perresource tracking: last activity performed (to detect handover)
    res_last_activity = {r: None for r in resources}
    # Percase tracking of preemption
    case_preempted = {c["case_id"]: False for c in all_cases}
    # Global minute counter (starts at 0 at 08:00)
    global_min = 0

    # Helper to convert minutessince08:00 to ISO timestamp (date irrelevant)

        return (base + timedelta(minutes=mins)).isoformat()

        # ---- Diagnostic branch (may be parallel or sequential) ----
        # Determine parallel vs sequential decision per policy.
        # For base comparison we assume parallel when crossskilled resource
        # available, else sequential.  We'll keep it simple:
        if ctype in ("ME","ES"):
            # Check if we have two *different* resources that can do the two skills.

            me_skill = "Mechanical" if "Mechanical" in c["branches"] else "Electrical"

            # quick check:
            has_me = not np.isnan(SKILL_SPEED[res].get(me_skill, np.nan))

            if ctype == "ME":
                mu1 = effective_mean("Mechanical", 1.0)
                mu2 = effective_mean("Electrical", 1.0)
                diag_time = mu1 + mu2
            elif ctype == "ES":
                mu1 = effective_mean("Electrical", 1.0)

            else:
                diag_time = c["mu_diag"]
            coord = 0  # no extra coordination

        # Apply resource speed to diagnostic time

        spd_d = speed_cache[(res,"Intake")]  # reuse
        actual_diag = diag_time / spd_d + coord

        # Start diagnostic after Intake
        start_diag = global_min
        end_diag   = global_min + actual_diag
        case_rows.append({
            "case:concept:name": cid,
            "concept:name": "Diagnostic",  # we will split into actual skill later if needed
            "start_timestamp": minutes_to_ts(start_diag),
            "time:timestamp": minutes_to_ts(end_diag),
            "org:resource": res,

            "actual_service": actual_diag,
            "handover": 0,  # no handover inside diagnostic (same resource)

        })
        global_min = end_diag

        res_min_left[res] -= actual_diag

# 9. Limits and validation plan  

| Limitation | Why it matters | Pilot / backtest to disambiguate policies |
|---|---|---|
| **Only expected arrivals and uniform servicetime ranges are used** | Real callvolume variability (e.g., spikes, cancellations) and actual servicetime distributions (often skewed) can shift bottlenecks. | **Pilot**: instrument the live system for 2weeks, collect actual interarrival times and service durations. Fit empirical distributions (e.g., lognormal) and rerun the simulation with the fitted data. |
| **Shift/break adherence assumed perfect** | Breaks are deterministic; in practice early/late returns change effective capacity, especially for the 0816 shift resources. | **Backtest**: tag actual breakstart/end timestamps from the existing event log; recompute capacity with observed break violations and observe impact on utilisation and SLA. |
| **Preemption modelled as a single 10% restart** | Multiple preemptions or different penalty percentages could occur if P1 cases keep arriving. | **Sensitivity analysis**: vary the preemptpenalty (5%, 15%, 20%) and the maximum number of preemptions (1 vs2) while keeping everything else fixed; record change in P1SLA and mean delay. |
| **Parallel/sequential decision rule is static** (parallel when crossskilled resource free) | Operators may prefer sequential to avoid coordination overhead when branches are short. | **Experiment**: run the simulation with a *threshold* (e.g., parallel only if both branch means >30min) and compare outcomes. |
| **No explicit modelling of overtime fatigue or quality loss** | Allowing 30min overtime per resource daily may mask fatigueinduced slowdowns. | **Controlled trial**: enable overtime for a subset of resources and measure postovertime servicetime inflation (e.g., +5% per overtime hour). |
| **Fairness measured only by Gini of utilisation** | Gini does not capture *who* gets the work (e.g., junior vs senior agents). | **Add attribute**: track resource seniority or skilllevel; compute a *weighted* Gini and see if policy3 still looks fairest. |
| **Scenario U5 IT outage only blocks Intake 09:3010:00** | Other IT failures (e.g., Validation system down) could be more severe. | **Whatif**: extend the outage to the whole morning or to Validation; observe bottleneck migration. |

**Validation plan**  

1. **Data collection phase (2weeks)** – Capture real arrival rates, actual service times, and resourcebreak compliance.  
2. **Model calibration** – Replace the uniformrange draws with the empirically fitted distributions; adjust speed multipliers if needed.  
3. **Policy backtesting** – Rerun the three policies on the calibrated model for the base period and for each U1U5 shock (simulated by adjusting the calibrated arrival/service parameters).  
4. **Metric comparison** – Use the same set of KPIs (mean/p95 delay, SLA attainment, utilisation Gini, handover minutes) to generate a “policybyscenario” table identical to Section4.  
5. **Decision gate** – If the hybrid policy consistently meets the P190% SLA across all scenarios while keeping utilisation90% and Gini0.15, proceed to a **limited rollout** (e.g., one operational centre) with realtime monitoring as described in Section7.  
6. **Continuous improvement** – After rollout, feed back actual KPI values; if any metric drifts outside the predefined thresholds (e.g., P1_SLA<85% for two consecutive days), trigger the *modeswitch* rules defined in Section5 (e.g., expand reserved slice or fall back to fullpool SERPT).  

By following this plan, the organisation can **distinguish** the policies under realistic conditions, protect P1 cases, and avoid an unsafe full rollout until the robustness of the chosen policy is statistically validated.
