```
def candidate_change_points(data, metric, direction='up', rel_threshold=0.20, abs_threshold=0.0, persistence=2, baseline_months=baseline_months):
    valid = data.dropna(subset=[metric]).reset_index(drop=True)
    base_series = valid.loc[valid['month'].isin(baseline_months), metric]
    if len(base_series) == 0:
        return []
    base = base_series.mean()
    base_std = base_series.std(ddof=0)
    if pd.isna(base_std) or base_std == 0:
        base_std = max(abs(base) * 0.05, 1e-6)
    threshold = max(2 * base_std, rel_threshold * abs(base), abs_threshold)
    dev = valid[metric] - base
    if direction == 'up':
        mask = dev > threshold
    elif direction == 'down':
        mask = -dev > threshold
    else:
        mask = abs(dev) > threshold
    flags = []
    for i in range(len(mask) - persistence + 1):
        if mask.iloc[i:i + persistence].all():
            flags.append(valid['month'].iloc[i])
    return sorted(set(flags))
```

## 2. Raw-versus-normalized interpretation

The raw/mapped fitness gap is a semantic-provenance signal, not a pure process-performance signal. In March the raw fitness falls from about 0.92 to 0.55 while mapped fitness remains near 0.90. That pattern is exactly what a label rename plus duplicated technical events should do: the old normative model sees unknown `Eligibility Screen` and repeated `Open Case` transitions, so it penalizes the log. The mapped model removes those artifacts and recovers most of the fit. This does not prove the business process was unchanged. Mapping can hide genuine drift if the mapping is too broad, if timestamps or resource fields are corrupted, or if the old model was already incomplete. Duplicated `Open Case` events mainly distort ordering and conformance; missing resources mainly distort resource, team, and capacity analyses, but may leave cycle-time timestamps intact. After May, however, mapped fitness declines, rework rates rise, supplier Z share jumps, and queue waiting increases. Those changes survive label mapping and de-duplication, so they cannot be dismissed as logging drift alone. The remaining question is how much is caused by supplier disruption, staffing, priority, and seasonal case mix.

**Primary monitoring population.** The primary default monitoring population should be the normalized, de-duplicated log of **standard-complexity, non-Supplier-Z, post-migration cases**. This cohort is large enough and least affected by supplier disruption and seasonal complexity, making it a useful quasi-control for detecting true behavioral or performance drift. Supplier-Z, high-complexity, priority-class, and seasonal cohorts should be monitored as mandatory secondary strata because they are where supplier, priority, and seasonality mechanisms are expected to appear.

**Seasonality and multiple testing.** No single universal threshold should be used. Monitors should use stratum-specific and seasonal-adjusted baselines, e.g. year-over-year renewal windows and STL residuals. Alerts should require effect size plus persistence across two or more periods. Because many monitors are tested simultaneously, use false-discovery-rate control or hierarchical gating: a DFG alert should trigger follow-up only if related rework, cycle-time, or supplier-share monitors also move. Recurring seasonal patterns should be distinguished from new drift by comparing to prior-year seasonal baselines and by checking whether the same segment shows the same behavior every year.

```python
def candidate_change_points(
    data,
    metric,
    direction="up",
    rel_threshold=0.20,
    abs_threshold=0.0,
    persistence=2,
    baseline_months=("2026-01", "2026-02"),
):
    valid = data.dropna(subset=[metric]).reset_index(drop=True)
    base_series = valid.loc[valid["month"].isin(baseline_months), metric]
    if len(base_series) == 0:
        return []

    base = base_series.mean()
    base_std = base_series.std(ddof=0)
    if pd.isna(base_std) or base_std == 0:
        base_std = max(abs(base) * 0.05, 1e-6)

    threshold = max(2 * base_std, rel_threshold * abs(base), abs_threshold)
    dev = valid[metric] - base

    if direction == "up":
        mask = dev > threshold
    elif direction == "down":
        mask = -dev > threshold
    else:
        mask = abs(dev) > threshold

    flags = []
    for i in range(len(mask) - persistence + 1):
        if mask.iloc[i : i + persistence].all():
            flags.append(valid["month"].iloc[i])

    return sorted(set(flags))

# Part B: reusable functions for a future event-level dataframe.
# These functions are intended to be run when raw event data are available.

from typing import Dict, List, Optional, Tuple

try:
    import pm4py
except ImportError:
    pm4py = None


def _require_pm4py() -> None:
    if pm4py is None:
        raise ImportError("pm4py is required for Part B functions.")


def _normalize_edge(edge):
    if isinstance(edge, tuple):
        return edge
    return tuple([x.strip() for x in edge.split("->")])


def _relations_from_dfg(dfg):
    if hasattr(dfg, "get_relations"):
        try:
            return dfg.get_relations()
        except Exception:
            pass
    try:
        return dict(dfg)
    except Exception:
        return {}


def format_event_log(
    df: pd.DataFrame,
    case_id_col: str,
    activity_col: str,
    timestamp_col: str,
    resource_col: Optional[str] = None,
) -> pd.DataFrame:
    """
    Format a raw event dataframe into PM4Py standard columns without overwriting input.
    """
    _require_pm4py()
    out = df.copy()
    out[timestamp_col] = pd.to_datetime(out[timestamp_col], errors="coerce")

    kwargs = {
        "case_id": case_id_col,
        "activity": activity_col,
        "timestamp": timestamp_col,
    }
    if resource_col is not None:
        kwargs["resource"] = resource_col

    try:
        return pm4py.format_dataframe(out, **kwargs)
    except TypeError:
        # Some PM4Py versions may not accept resource directly.
        kwargs.pop("resource", None)
        return pm4py.format_dataframe(out, **kwargs)


def add_month_column(
    log: pd.DataFrame,
    timestamp_col: str = "time:timestamp",
) -> pd.DataFrame:
    """
    Add a calendar-month column for monthly slicing.
    """
    out = log.copy()
    out["month"] = pd.to_datetime(out[timestamp_col]).dt.to_period("M").astype(str)
    return out


def slice_time_window(
    log: pd.DataFrame,
    start: str,
    end: str,
    timestamp_col: str = "time:timestamp",
) -> pd.DataFrame:
    """
    Slice an event log to a time window using pm4py.filter_time_range.
    """
    _require_pm4py()
    return pm4py.filter_time_range(
        log,
        str(start),
        str(end),
        mode="between",
        timestamp_column=timestamp_col,
    )


def monthly_dfg_rates(
    log: pd.DataFrame,
    edges: Optional[List[Tuple[str, str]]] = None,
    case_id_col: str = "case:id",
    timestamp_col: str = "time:timestamp",
) -> pd.DataFrame:
    """
    Compute monthly DFG relation rates per 100 cases using pm4py.discover_dfg.
    """
    _require_pm4py()
    log = add_month_column(log, timestamp_col)
    rows = []

    for month, group in log.groupby("month"):
        month_log = group.drop(columns=["month"]).copy()
        dfg = pm4py.discover_dfg(month_log)
        relations = _relations_from_dfg(dfg)
        n_cases = month_log[case_id_col].nunique()

        row = {"month": month, "cases": n_cases}
        if edges:
            for e in edges:
                key = _normalize_edge(e)
                cnt = relations.get(key, 0)
                row[str(e)] = 100.0 * cnt / n_cases if n_cases else 0.0
        rows.append(row)

    return pd.DataFrame(rows)


def monthly_variants(
    log: pd.DataFrame,
    timestamp_col: str = "time:timestamp",
) -> Dict[str, Dict]:
    """
    Compute monthly variants using pm4py.get_variants.
    """
    _require_pm4py()
    log = add_month_column(log, timestamp_col)
    result = {}
    for month, group in log.groupby("month"):
        month_log = group.drop(columns=["month"]).copy()
        result[month] = pm4py.get_variants(month_log)
    return result


def monthly_temporal_profiles(
    log: pd.DataFrame,
    timestamp_col: str = "time:timestamp",
) -> Dict[str, object]:
    """
    Compute monthly temporal profiles using pm4py.discover_temporal_profile.
    """
    _require_pm4py()
    log = add_month_column(log, timestamp_col)
    result = {}
    for month, group in log.groupby("month"):
        month_log = group.drop(columns=["month"]).copy()
        result[month] = pm4py.discover_temporal_profile(month_log)
    return result


def discover_skeleton_and_declare(log: pd.DataFrame) -> Dict[str, object]:
    """
    Optionally discover log skeleton and DECLARE model.
    """
    _require_pm4py()
    skeleton = None
    declare = None

    try:
        skeleton = pm4py.discover_log_skeleton(log)
    except AttributeError:
        skeleton = None

    discover_declare = getattr(pm4py, "discover_declare_model", None)
    if discover_declare is not None:
        try:
            declare = discover_declare(log)
        except Exception:
            declare = None

    return {"log_skeleton": skeleton, "declare_model": declare}


def compare_raw_and_normalized_label_mapping(
    log: pd.DataFrame,
    activity_mapping: Dict[str, str],
    dedup_open_case: bool = False,
    case_id_col: str = "case:id",
    activity_col: str = "concept:name",
    timestamp_col: str = "time:timestamp",
) -> Dict[str, object]:
    """
    Compare raw and normalized label mappings without overwriting the original log.

    Example mapping:
        {
            "Eligibility Screen": "Validate Eligibility",
        }
    """
    _require_pm4py()

    raw_log = log.copy()
    norm_log = raw_log.copy()

    norm_log[activity_col] = norm_log[activity_col].replace(activity_mapping)

    if dedup_open_case:
        norm_log = norm_log.drop_duplicates(
            subset=[case_id_col, activity_col, timestamp_col]
        ).copy()

    raw_dfg = pm4py.discover_dfg(raw_log)
    norm_dfg = pm4py.discover_dfg(norm_log)

    raw_variants = pm4py.get_variants(raw_log)
    norm_variants = pm4py.get_variants(norm_log)

    return {
        "raw_log": raw_log,
        "normalized_log": norm_log,
        "raw_dfg": raw_dfg,
        "normalized_dfg": norm_dfg,
        "raw_variants": raw_variants,
        "normalized_variants": norm_variants,
        "raw_labels": sorted(raw_log[activity_col].dropna().unique()),
        "normalized_labels": sorted(norm_log[activity_col].dropna().unique()),
    }
```

## 9. Provisional attribution

Strongest: the March raw-fitness collapse is logging/semantic drift from the migration (confidence 95%). The label rename, duplicate `Open Case`, and missing resource identifiers explain the raw/mapped gap, while mapped fitness and cycle time remain near baseline. Strong but not exclusive: the May rework surge is primarily supplier-Z disruption (80%). Supplier-Z share jumps, `Assess -> Request Info` doubles, and recovery reduces the effect, but Supplier-Z cases were already more complex, so part is population drift. Strong: the June-to-August queue-waiting deterioration is staffing capacity (75%). Assessor service time rises only modestly, reconstructed queue waiting rises sharply, and December overtime coincides with improvement. Moderate: the October-November peak is seasonal case mix plus residual staffing (70%). Volume and high-complexity share jump, cycle time peaks, and December eases with both lower seasonality and interventions. Moderate: the July priority rule mainly redistributes delay rather than creating global drift (55%). The aggregate cannot separate high-complexity acceleration from standard-case delay; senior-assessment rate changes may also be recording drift. Moderate: persistent rework after September reflects backlog, learned behavior, or incomplete recovery (60%). Low: the senior-assessment jump is partly semantic/logging drift (50%). Interaction prevents clean attribution: supplier disruption causes rework, rework consumes assessor capacity, staffing cuts lengthen queues, and seasonality amplifies both. I would revise if event-level segments show rework only in Supplier-Z cases, if priority-class waiting changes offset, or if year-over-year seasonality explains the October peak without staffing. Logging drift is strongest in March, but later semantic changes—especially senior-assessment recording—remain plausible. The December improvement should not be credited solely to interventions because seasonal load also falls.

## 10. Monitoring decision rules

1. IF raw fitness collapses while mapped fitness remains stable after label mapping and `Open Case` de-duplication, THEN investigate migration ETL, update the normative model mapping, and suppress raw-only alerts, BECAUSE semantic/logging drift can create false conformance failures without real process change.

2. IF mapped fitness and DFG distance rise mainly in Supplier-Z cases after 2026-05-05, THEN escalate supplier document completeness and add intake validation for Supplier-Z bundles, BECAUSE incomplete bundles create rework loops and performance drift.

3. IF `Assess` service time is stable but reconstructed queue waiting before `Assess` rises after 2026-06-15, THEN add assessor capacity, rebalance workload, or extend overtime, BECAUSE staffing cuts create resource/organizational queueing rather than longer per-case work.

4. IF high-complexity wait falls and standard-case wait rises after 2026-07-01, THEN tune the priority rule and monitor both priority classes separately, BECAUSE priority rules redistribute delay rather than necessarily reducing total delay.

5. IF high-complexity share and volume rise in October-November and prior-year data show a similar pattern, THEN classify the change as recurring seasonal drift and adjust staffing plans in advance, BECAUSE annual renewal season increases both load and case complexity.

6. IF `Assess -> Senior Assessment` jumps without a corresponding rise in verified high-complexity cases or event-level confirmation, THEN audit senior-assessment recording completeness before changing routing policy, BECAUSE semantic/logging drift can masquerade as behavioral drift.

7. IF December cycle time improves while both seasonal load and overtime/document-quality campaigns occur, THEN use segmented event-level analysis to separate intervention effects from seasonal easing before scaling overtime, BECAUSE confounding prevents clean causal attribution from monthly aggregates.
