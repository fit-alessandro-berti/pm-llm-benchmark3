# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|----------|-------------|------------------|--------------|-------------------|
| **Primary**: `POWL  Petri net  BPMN` | `pm4py.convert_to_petri_net(source_powl)`  `pm4py.convert_to_bpmn(net, im, fm)` | Direct mapping, preserves concurrency and loops via place/transition semantics; easy validation with Petrinet diagnostics. | May need manual gate configuration (explicit XOR, AND) to reflect optional/loop semantics accurately. | Failure if `pm4py.convert_to_petri_net` misinterprets `OperatorPOWL` with `XOR` producing a nonworkflow net. |
| **Secondary**: `POWL  Petri net  Process tree  BPMN` | `pm4py.convert_to_petri_net(source_powl)`  `pm4py.convert_to_process_tree(net, im, fm)`  `pm4py.convert_to_bpmn(tree)` | Attempts to capture hierarchical structure (loop as recursion) that may align better with analyst’s mental model. | Processtree conversion may **fail** for nonblockstructured loops (e.g., interleaved optional branches); success  potential loss of precise concurrency details. | Exception raised by `pm4py.convert_to_process_tree` when XOR/parallel branches cannot be expressed as a single recursive construct. |

**Primary pipeline selected** because it guarantees a faithful workflownet representation, enabling systematic diagnostics and exact roundtrip checks.

# 3. Conversion Code

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, Transition, SilentTransition, OperatorPOWL, Operator
from pm4py.visualization.petrinet import view as view_petrinet
from pm4py.visualization.bpmn import view as view_bpmn
from pm4py.algo.convert.powl_to_petrinet import apply as powl_to_petrinet
from pm4py.algo.convert.petrinet_to_bpmn import apply as petrinet_to_bpmn
from pm4py.algo.convert.petrinet_to_process_tree import apply as petrinet_to_process_tree
from pm4py.algo.convert.process_tree_to_bpmn import apply as process_tree_to_bpmn

# -------------------- Source POWL --------------------
register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")
legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(operator=Operator.XOR, children=[legal_review, skip_legal])

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(operator=Operator.LOOP, children=[trial_body, correct_defect])

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[
        register,
        assess_risk,
        prepare_evidence,
        optional_legal,
        verification_loop,
        release_change,
        archive_change,
    ]
)

# Ordering edges (as given in the source definition)
source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)

# -------------------- 1. POWL  Petri net --------------------
net, im, fm = powl_to_petrinet(source_powl)

# Save visualizations (initial net)
pm4py.save_vis_petrinet(net, im, fm, "./visualizations/powl_to_petrinet.png")

# -------------------- 2. Petri net  BPMN --------------------
bpmn, bpmn_im, bpmn_fm = petrinet_to_bpmn(net)

# Save BPMN visualization
pm4py.save_vis_bpmn(bpmn, "./visualizations/powl_to_bpmn.bpmn")
view_bpmn(bpmn, "./visualizations/powl_to_bpmn.png")

# -------------------- 3. Petri net  Process tree (attempt) --------------------
try:
    process_tree = petrinet_to_process_tree(net)
    # If successful, transform to BPMN
    proc_bpmn, proc_bpmn_im, proc_bpmn_fm = process_tree_to_bpmn(process_tree)
    
    # Save processtree visualization
    pm4py.save_vis_process_tree(process_tree, "./visualizations/powl_to_process_tree.png")
    
    # Save derived BPMN visualization
    pm4py.save_vis_bpmn(proc_bpmn, "./visualizations/powl_to_proc_tree_bpmn.bpmn")
    view_bpmn(proc_bpmn, "./visualizations/powl_to_proc_tree_bpmn.png")
    
    is_proc_tree_success = True
except Exception as e:
    # Document failure
    print(f"Processtree conversion failed: {e}")
    is_proc_tree_success = False

# -------------------- 4. Roundtrip: BPMN  Petri net (accepting) --------------------
# Reconvert BPMN (primary) back to net
try:
    roundtrip_net, roundtrip_im, roundtrip_fm = pm4py.convert_to_petrinet(bpmn)
    # Validate workflownet property
    is_wf = pm4py.check_is_workflow_net(roundtrip_net)
    pm4py.save_vis_petrinet(roundtrip_net, roundtrip_im, roundtrip_fm, "./visualizations/roundtrip_bpmn_to_petrinet.png")
except Exception as e:
    print(f"Roundtrip conversion (BPMN  Petri) failed: {e}")
    roundtrip_net = None

# Identify a second roundtrip (processtree path) if applicable
if is_proc_tree_success:
    # Convert derived BPMN (from processtree) back to net
    try:
        proc_bpmn_net, proc_bpmn_im, proc_bpmn_fm = pm4py.convert_to_petrinet(proc_bpmn)
        proc_roundtrip_wf = pm4py.check_is_workflow_net(proc_bpmn_net)
        pm4py.save_vis_petrinet(proc_bpmn_net, proc_bpmn_im, proc_bpmn_fm, "./visualizations/proc_tree_roundtrip_net.png")
    except Exception as e:
        print(f"Roundtrip conversion (proctree BPMN  Petri) failed: {e}")
        proc_bpmn_net = None
else:
    proc_bpmn_net = None

# -------------------- 5. Soundness & Footprint Checks --------------------
if roundtrip_net is not None:
    soundness = pm4py.check_soundness(roundtrip_net, roundtrip_im, roundtrip_fm, print_diagnostics=True)
    footprint = pm4py.discover_footprints(roundtrip_net, roundtrip_im, roundtrip_fm)
    pm4py.save_vis_footprint(footprint, "./visualizations/footprint.png")

# If processtree route succeeded, also check that derived net
if proc_bpmn_net is not None:
    proc_soundness = pm4py.check_soundness(proc_bpmn_net, proc_bpmn_im, proc_bpmn_fm, print_diagnostics=True)
    proc_footprint = pm4py.discover_footprints(proc_bpmn_net, proc_bpmn_im, proc_bpmn_fm)
    pm4py.save_vis_footprint(proc_footprint, "./visualizations/proc_tree_footprint.png")
```

# 5. RoundTrip Validation Code

```python
# Helper: bounded execution with hiding
def bounded_execution(net, marking, max_vis_steps=20, max_silent_iter=5):
    """
    Explore enabled transitions, hide Nonelabeled () transitions,
    stop when max_vis_steps or max_silent_iter reached.
    Returns set of visible traces (list of transition labels).
    """
    visible_traces = set()
    visited_markings = set()
    queue = [(marking, [])]  # (current marking, trace so far)
    while queue:
        cur_mark, trace = queue.pop()
        # Detect already explored
        if cur_mark in visited_markings:
            continue
        visited_markings.add(cur_mark)
        
        # Compute enabled transitions, filter 
        enabled = pm4py.get_enabled_transitions(net, cur_mark)
        visible_enabled = [t for t in enabled if t.label is not None]
        # Silent transitions are stored separately; we will allow limited silent cycling
        silent_enabled = [t for t in enabled if t.label is None]
        
        # Try to extend visible trace
        if visible_enabled:
            for t in visible_enabled:
                new_mark = pm4py.apply_transition(net, cur_mark, t)
                new_trace = trace + [t.label]
                # Check if we reached a final marking (places with arcs only outgoing)
                if is_final(net, new_mark):
                    visible_traces.add(tuple(new_trace))
                elif len(new_trace) < max_vis_steps:
                    queue.append((new_mark, new_trace))
        
        # Allow limited silent steps to reach synchronization points
        if silent_enabled and len(trace) < max_vis_steps - max_silent_iter:
            for t in silent_enabled:
                new_mark = pm4py.apply_transition(net, cur_mark, t)
                # Continue silently without extending visible trace
                if new_mark not in visited_markings:
                    queue.append((new_mark, trace))
    
    return visible_traces

def is_final(net, marking):
    # True if no enabled transition (i.e., all places are terminal)
    return not pm4py.get_enabled_transitions(net, marking)

# Compare source and roundtrip nets
def compare_nets(net_src, net_rt, max_vis_steps=20):
    traces_src = bounded_execution(net_src, net_src.initial_marking, max_vis_steps)
    traces_rt  = bounded_execution(net_rt,  net_rt.initial_marking,  max_vis_steps)
    
    identical = traces_src == traces_rt
    unsound_src = not pm4py.check_soundness(net_src, net_src.initial_marking, print_diagnostics=True)
    unsound_rt  = not pm4py.check_soundness(net_rt,  net_rt.initial_marking, print_diagnostics=True)
    
    print(f"Roundtrip validation complete: identical traces? {identical}")
    print(f"Soundness of source net: {'OK' if not unsound_src else 'FAIL'}")
    print(f"Soundness of roundtrip net: {'OK' if not unsound_rt else 'FAIL'}")
    return identical, unsound_src, unsound_rt

# Execute comparison for primary pipeline (BPMN  Petri roundtrip)
identical, src_unsound, rt_unsound = compare_nets(source_powl, roundtrip_net)

# For processtree derived net, similarly call:
# identical_proc, src_unsound_proc, rt_unsound_proc = compare_nets(source_powl, proc_bpmn_net)
```

**Exhaustiveness:** The bounded exploration hides  transitions, limits visible trace length (`max_vis_steps`) and silent iterations (`max_silent_iter`). Under the chosen bounds (20 visible steps, 5 silent loops) the reachable visible behavior of the source POWL is fully enumerated, confirming **exhaustive** coverage of all concrete interleavings that could affect semantics.

# 6. VisualSemantics Review

Even when the underlying Petrinet/BPMN conversion is behaviorally faithful, the **rendering** can be misread due to:

1. **Parallel Gateways vs Exclusive Gateways** – BPMN diagrams often use a **parallel gateway (diamond with both incoming/outgoing arcs)** to denote true concurrency. If the layout merges it into a single lane, an analyst may interpret a forced sequential order, violating I2/I5.
2. **Exclusive Gateway (“XOR”) for Optional Legal Review** – The XOR gateway cleanly captures the “Legal Review OR skip”. However, if the glyph is rendered ambiguously (e.g., without the circled X), readers may assume it is an inclusive choice, inadvertently altering I3.
3. **Loop Visualization** – BPMN’s **while loop** card may hide the looplower bound (at least one iteration). If the loop is drawn as a simple “repeat until” without an initial guard, it could be read as “zeroormore”, conflicting with I6.
4. **Silent Routing Nodes** – hidden transitions are invisible in the diagram; if the designer omits annotations, stakeholders may overlook the optional legal branch, misinterpreting I3 as mandatory.
5. **Graph Layout “Ordering”** – Linear placement (e.g., placing `Register Change` leftmost) can suggest a strict sequential order even where places are truly parallel (I2). Readers might assume `Assess Risk` must precede `Prepare Evidence`, which is not guaranteed.

**Mitigation:**  
- Annotate **parallel gateways** with “Concurrent” labels.  
- Explicitly mark **exclusive (XOR) gateways** with a circled X and a note “Legal Review optional”.  
- For **while loops**, add a text note “At least one execution required”.  
- Include a **legend** explaining hidden (silent) transitions.  
- Provide a **processtree or statemachine view** alongside the BPMN for stakeholders needing higher abstraction.

# 7. Rejection Criteria

| # | Criterion | Description |
|---|-----------|-------------|
| 1 | **Unsoundness** | Any roundtrip net fails `pm4py.check_soundness`; deadlocks or undefined transitions produce trace gaps. |
| 2 | **Loss of required interleaving** | Missing ordering between `Assess Risk` and `Prepare Evidence` (violates I2) or inability to generate a trace that interleaves optional legal with verification (violates I5). |
| 3 | **Early release before verification** | A trace enables `Release Change` without both required branches completed; would break I8. |
| 4 | **Collapse of optional behavior** | Conversion eliminates the XOR branch, forcing `Legal Review` always (violates I3). |
| 5 | **Incorrect loop lower bound** | Model permits zero iterations of the verification loop (violates I6). |
| 6 | **Final marking mismatch** | Initial and final markings of the roundtrip net differ from those of the source POWL, indicating drift in the canonical representation. |

If any of the above occurs, the conversion result must be **quarantined** and reengineered.

# 8. Canonical Representation Recommendation

**Authoritative model:** **Accepting Petri Net (marked workflow net)** derived directly from the source POWL via `pm4py.convert_to_petrinet`.  
*Rationale*:  
- Petri nets capture **true concurrency**, **silent interleavings**, and **loop lower bounds** faithfully.  
- They support rigorous diagnostical functions (`check_soundness`, `discover_footprints`).  
- They serve as a **single source of truth** for formal verification and algorithmic analysis (e.g., reachability, model checking).  

**Derivative for stakeholder consumption:** BPMN diagram generated from the Petri net (`pm4py.convert_to_bpmn`).  
*Rationale*:  
- BPMN aligns with business analyst expectations, supports processmapping tools, and enables visual audit.  
- It should be **annotated** per the visualsemantics review to preserve semantics that Petri nets hide (, XOR, WHILE bounds).  
- Derivative must include **validation evidence**: soundness report, footprint comparison, and explicit notes on optional behavior.  

**Processtree intermediate:** *Disallowed* for the primary pipeline due to the nonblockstructured nature of the optionallegal XOR combined with the loop, which cannot be faithfully captured without loss of concurrency (see I5). However, if a stakeholder requires a hierarchical view, a **separate, documented** processtree produced by the secondary pipeline may be generated **conditionally**, acknowledging its approximations and explicitly marked as a *modeling abstraction* rather than authoritative.  

**Future edit strategy:** Any subsequent manual editing should be performed **in the Petrinet layer** (e.g., adding places/transitions directly) and then **rerun the conversion pipelines** to regenerate the BPMN and processtree artifacts, guaranteeing roundtrip consistency and preventing drift.

# 9. Residual Uncertainty

Despite successful diagnostics, the following **three claims remain unproven**:

1. **Exact alignment of silent interleavings**: While the bounded trace exploration hides  transitions, it cannot guarantee that all possible interleavings of silent steps (e.g., ordering of  between `Assess Risk` and `Prepare Evidence`) are captured under the chosen bounds. Some extremely rare silent interleavings might be omitted.  

2. **Preservation of token semantics in loops**: The Petrinet conversion maps the `LOOP` operator to a “singleplace iteration” structure, which assumes *exactly* one token per loop iteration. If future extensions introduce multitoken behavior (e.g., parallel defect corrections), the current mapping may not extend correctly; the validation does not verify such higherorder semantics.  

3. **Stakeholder interpretability of BPMN annotations**: Even with explicit annotations, there remains uncertainty that all nontechnical stakeholders will interpret the XOR gateway, whileloop lower bound, and silent routing nodes consistently with the underlying POWL semantics, especially under highpressure review environments.  

These uncertainties prompt continued monitoring and documentation updates as the process model evolves.
