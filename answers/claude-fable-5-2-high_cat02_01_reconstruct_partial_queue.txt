# 1. Assumptions and notation

**Notation.** Durations are in minutes; clock times are on 2026-05-12; T = 14:00 is the end of the window. For case *i* at station *s*: `q` = queue entry (S1: `arrival_s1`; S2: `s1_end`), `b` = service start, `e` = service completion. Evidence tags used throughout: **[O]** observation (read from the table or exact arithmetic on reported timestamps), **[E]** estimate (depends on an imputation or modelling choice), **[B]** bound, **[H]** hypothesis, **[R]** recommendation. All numbers quoted are printed by the script in Section 7.

**Assumptions.**

- **A1 – Empty start.** No case was in the system before 08:00. Needed to turn cumulative counts into WIP levels; supported by P01/P02 waiting only 5 min and by the absence of earlier cases, but not provable. If violated, every WIP figure is a lower bound by an unknown constant.
- **A2 – Extract completeness.** The 22 rows are all cases present in the window. In particular the absence of any arrival after 12:10 is taken at face value. It is suspicious (inter-arrival gaps were 5–20 min for four hours, then 110 min with nothing), so everything concerning S1 after 12:10 is conditional on A2.
- **A3 – Event-order convention for equal rounded timestamps.** At a shared timestamp events are processed in the order (1) completions, (2) queue entries (external arrivals, and the S2 queue entry created by an S1 completion), (3) service starts; the state is read after all of them. Equivalently a case is in queue on [q, b), in service on [b, e) and in station WIP on [q, e) (right-continuous step functions). Rates use half-open bins [a, b). The alternative convention (arrivals counted before departures at the same instant) is reported as a sensitivity; it changes instantaneous peaks by at most one case and no time average.
- **A4 – Rounding.** Each reported time t stands for a true time in [t−2.5, t+2.5], errors independent and roughly uniform. Hence any single duration has a worst-case error of ±5 min (SD ≈ 2 min), a mean over n durations has SD ≈ 2/√n min, and a reported 5-min duration means "between 0 and 10". Nominal values are reported; bounds are widened where it matters, and a jitter Monte Carlo quantifies the effect on aggregates.
- **A5 – Clock alignment.** The external-arrival clock and the operational clock are assumed synchronised. An offset δ would shift every S1 wait by δ and nothing else. P01/P02 (reported S1 wait 5 min) limit how far the arrival clock can run late (more than about 5–10 min would create negative waits).
- **A6 – Capacity.** I1, I2, C1, C2 are single-task resources available for the whole window, except C2 during 10:55–11:10. No breaks or shift changes are documented. Available time is therefore 360 min per resource, 345 min for C2 (S1: 720 resource-min, S2: 705).
- **A7 – Queue entry.** A case enters the S2 queue at its S1 completion (stated in the scenario); there is no transport buffer, so system WIP = S1 WIP + S2 WIP.
- **A8 – Hard feasibility of a MISSING start.** `lo = max(queue entry, previous completion on the same resource, end of an outage if lo falls inside it)`, `hi = own completion` (non-negative service). These use only single-tasking and are the interval bounds.
- **A9 – FIFO as a soft bound.** A missing start is assumed not to be later than the earliest observed start of a case that entered the same queue later. At S1 this is well supported: all 19 observed starts are in strict arrival order **[O]**. At S2 it is weaker: P09 overtook P08 and P17 overtook P16 **[O]**. The FIFO bound is therefore reported next to, not instead of, the hard bound.
- **A10 – Central imputation (justified point estimate, not a silent fill).** Central start = `lo + 5 min`. Justification: of the 29 same-resource hand-overs whose two timestamps are both observed, 26 show a reported gap of exactly 5 min (one 0, one 10, one 25 spanning the outage) **[O]**, and in all four cases other work was already waiting, so the resource had no reason to idle.
- **A11 – Right censoring.** OPEN activities contribute their elapsed time (T − b) to busy time and WIP; that elapsed time is a lower bound on final service time and is never averaged with completed services. Cases still waiting contribute a waiting-time lower bound (T − q). Anything said about what happens after 14:00 is labelled as projection **[H]**.
- **A12 – Blank means not started.** Blank S1/S2 starts are taken as "still waiting". Delayed logging is possible for P16 and P22 (see Section 5), in which case the 14:00 queue lengths are upper bounds by one case each.
- **A13 – Service time is active time.** e − b is treated as uninterrupted work by the named resource; the 5-min hand-over gap is not service.
- **A14 – Outage.** C2 could neither start nor continue work during 10:55–11:10. No C2 job overlaps it (P06 ended 10:50, P08 started 11:15) **[O]**, so no service time needs correcting.

# 2. Reconstruction method and formulas

**Case/station quantities.**

- Queue waiting time: `Wq = b − q`. Not started by T: `Wq ≥ T − q` (censored). MISSING `b`: `Wq ∈ [lo − q, hi − q]`.
- Active service time: `S = e − b`. OPEN: elapsed `T − b`, final `S ≥ T − b`. MISSING `b`: `S ∈ [0, e − lo]`.
- Station sojourn: `R = e − q = Wq + S`. It does not involve `b`, so it is exact (up to rounding) even when the start is missing; only the split between waiting and service is uncertain. In-window residence is `min(e, T) − q`.
- Case total sojourn: `e_S2 − arrival_s1` for departed cases (also independent of every missing start). For unfinished cases only the age `T − arrival_s1` is known, a lower bound.

**Counting processes and state.** With A(t), B(t), D(t) the cumulative queue entries, starts and completions of a station: queue length `Lq(t) = A − B`, in service `B − D`, station WIP `N(t) = A − D`, system WIP `N_S1 + N_S2`. Time averages over [a, b) are computed exactly as summed interval overlaps divided by (b − a), not from grid samples. Peaks are read on the 2.5-min grid under A3.

**Rates.** Arrival rate λ = queue entries in [a, b) / (b − a); departure (throughput) rate = completions in [a, b) / (b − a). The S2 arrival process is the S1 departure process. Effective capacity of a resource is estimated from its saturated cycle: completions / (last completion − first start − outage), which includes the hand-over gap and uses only observed timestamps.

**Utilisation.** `U = Σ |[b, min(e, T)) ∩ window| / available time`, over all work including OPEN jobs and imputed starts. Two readings are given: touch-time utilisation (definition above) and occupancy, which also counts the hand-over gaps as engaged time.

**Little's Law.** `L = λ·W` with L the time-average WIP, λ the arrival rate and W the mean time in the station. On a finite window the exact identity is `L = (A/T)·(Σ in-window residence / A)`; the steady-state form with completed-case W is only close if the cases still inside at the boundaries carry a small share of the area. That share is the criterion for "defensible".

**Lower / central / upper values.**

- Bound **[B]**: every MISSING start at `lo`, respectively at `hi` (scenario X, zero service; a bound, not a plausible state).
- Feasible scenarios **[E]**: E = `lo`; C = `lo + 5` (central, A10); M = midpoint of [lo, hi] (ignorance prior); L = latest FIFO-consistent start (A9).
- Stress scenario R: start = completion − mean observed service of the station, even where that violates single-tasking (models undocumented assistance or a mis-logged completion).
- Multiple imputation: 1,000 joint draws; each MISSING start uniform on its FIFO-feasible interval and every timestamp jittered by U(−2.5, +2.5) (A4); 5th/50th/95th percentiles reported.
- Ranges written "x (y–z)" are central (min–max over E, C, M, L).

Supporting detail.

- **Per-resource touch-time utilisation over the window** **[E]**: I1 0.85 (0.74–0.88; hard lower bound 0.68), I2 0.81 (no missingness, exact up to rounding), C1 0.82 (0.76–0.83; ≥ 0.75), C2 0.77 (0.74–0.78; ≥ 0.71) of its 345 available minutes. Measured from each resource's first start to its last activity: I1 0.86, I2 0.87, C1 0.89, C2 0.87 (central).
- **Occupancy** **[E]**: under the central imputation every gap between consecutive jobs is a hand-over of 5 min or less, except the 25-min C2 gap around the outage, one 10-min C2 gap (13:20–13:30) and I2 after 13:45. Counting hand-overs as engaged time, all four resources were about 100 % occupied from their first job on. The S1 queue was never empty during the window and the S2 queue never empty from 09:10 on **[O, independent of imputation]**, so neither station was ever starved after start-up. The plausible utilisation range is therefore "about 0.75–0.85 touch time, effectively 1.0 occupancy"; the difference is the hand-over, which rounding alone cannot explain (zero true gaps would round to a mixture of 0 and ±5, not to 26 fives out of 29).
- **Effective capacity** **[E]**, from saturated cycles: I1 10 jobs in 320 min, I2 10 in 335 min, giving S1 ≈ 3.6–3.7 cases/h; C1 8 jobs in 320 min, C2 6 jobs in 265–280 min (net/gross of outage), giving S2 ≈ 2.8–2.9 cases/h.
- **Little's Law, S1, 08:00–14:00 (defensible).** S1 starts empty (A1) and ends with 2 of 22 cases inside, which carry 12 % of the WIP area. L = 5.79; λ = 22/6 h = 3.67/h; in-window mean residence 94.8 min, so λW = 5.79 (identity). With the completed-case mean sojourn (92.3 min, n = 20) the steady-state form gives 5.64 (−3 %); with the departure rate instead of the arrival rate 5.12 (−12 %). Consistent within the censoring share. All of this is free of start imputation.
- **Little's Law, S1 plateau 10:00–12:00 (defensible, and not a tautology).** WIP was 7 at both ends, L = 7.58, 8 in, 7 out. L/rate predicts a station sojourn of 114 min (arrival rate) to 130 min (departure rate); the cohort arriving in that interval has an observed mean sojourn of ≥ 128 min (P21 censored). The departure cohort averages only 96 min because it joined a shorter queue earlier; the law applies to the cohort that experiences the measured L.
- **Little's Law, S1 queue only.** Lq = 4.11–4.25 depending on scenario; using the 21 started cases only gives 3.81–3.94, P22's censored wait being the difference.
- **Little's Law, S2 and whole system (not defensible as steady state).** S2 WIP rises monotonically by hour (1.1, 2.8, 3.3, 4.4, 4.9, 5.8) and 6 of 20 cases are still inside, carrying 27 % of the area. The identity holds (L = 3.72 = 3.33/h × 67.0 min), but the completed-case form gives 2.72 with the departure rate (−27 %) and 3.89 with the arrival rate (+5 %, agreement by cancellation, not evidence of stationarity). The system as a whole (mean WIP 9.5, peak 13 at 11:30, 8 cases left at 14:00) is in the same position. No steady-state W should be quoted for S2 or for the case level.

**Evidence [O/E].**

1. *Three demand regimes.* External arrivals run at 6.5/h in 08:00–10:00, 4.0/h in 10:00–12:00 and 0.5/h afterwards (one arrival at 12:10, then none).
2. *S1 output is flat* at 3.0–3.5 completions/h whatever the arrival rate, and S1 always had a queue: it worked at its capacity of ≈ 3.6–3.7/h all morning. S1 waits climb from 5 to about 100 min and then stay at 95–105 min for every case from P14 on.
3. *S2 output is flat and lower*: 2–3 completions/h, 2.8/h averaged over 09:00–14:00, against an inflow of 3.3–3.5/h. S2 was never starved after 09:10 and its waits rise almost monotonically (5, 5, 10, 15, … 65, 75, then censored values up to ≥ 85).
4. *Queue positions cross.* The S1 queue is the larger one until about 12:45 (6–7 cases against 1–4); from 13:00 the S2 queue is larger (4–5 against 3 → 1). At 14:00, six of the eight cases in the system are at S2.
5. *Delay shares.* For the 14 departed cases S1 waiting averages 49 min and S2 waiting 33 min (central), so S1 contributed about 60 % of their waiting. For later cases the S2 share is censored and already large (P16: 100 at S1, ≥ 85 at S2).

**Interpretation.** The evidence fits a time-varying combination, and the answer depends on which definition of bottleneck is used:

- *Capacity (throughput) bottleneck: S2 throughout, after the start-up half hour.* Its effective capacity (≈ 2.8–2.9/h) is below S1's (≈ 3.6–3.7/h) and below demand in every regime before 12:10, and it was continuously fed. System output over 09:00–14:00 equals S2's rate (2.8/h). This conclusion uses only completion counts and is unaffected by the missing starts.
- *Dominant queue (largest delay contributor): S1 from about 08:10 to about 12:45, S2 afterwards.* S1 holds the bigger queue in the morning because the overload it faces is far larger (6.5/h against 3.7/h, +3 cases/h) than the one S2 faces (≈ 3.5/h against ≈ 2.8/h, +0.7/h). S1 in effect meters work into S2 and hides part of S2's shortfall.
- *The S1 queue shrinks after 12:10 only because arrivals stop* (A2), not because S1 improved; the S2 queue keeps growing because S1 continues to deliver 3.5/h.

**Maintenance interval.**

- **[O]** C2 finished P06 at 10:50 and next started P08 at 11:15: 25 reported idle minutes (20–30 after rounding) around a 15-min outage. P08, in the S2 queue since 10:20, waited 55 min, about 30 min more than its neighbours P07 (20) and P09 (25), and was overtaken by P09 when C1 became free at 11:00. S2 completions drop to 2 in 11:00–12:00, the lowest hour after start-up.
- **[E]** With the usual hand-over C2 could have started P08 at about 10:55, so roughly 20 min of C2 time were lost (15 declared plus a flank too short to start a 40–45 min job). That is about half a calibration, or 3 % of S2's resource-minutes in the window. Every later C2 job (P11, P13, P15) is shifted by about the same 20 min.
- **[E]** The outage is an aggravating factor, not the cause of the S2 queue. S2 waits were already rising before 10:55 (5 → 25 min over P01–P07), S2 utilisation was already 0.88 in 09:00–10:00, and the deficit accumulated by 14:00 is four unstarted cases, of which the outage can explain at most one. Without it the S2 queue at 14:00 would plausibly be 3 rather than 4 and post-outage waits roughly 10–20 min shorter.
- **[H] Lane hypothesis.** P01–P09 follow a strict pairing I1→C1, I2→C2 (9 of 9); from P10 the pairing is reversed (P10–P15: I2→C1, I1→C2, 6 of 6). If S2 work was pre-assigned to a calibrator rather than pooled, P08 "belonged" to C2 and waited out the outage, and the reassignment from P10 on was the reaction to it. Pooling would not have recovered the lost capacity, but it would have spread the delay instead of concentrating it on P08.

**End-of-window anomalies [O], causes [H].** C2 idle 13:20–13:30 with two cases waiting; P17 started ahead of P16; I2 idle from 13:45 with P22 waiting. Candidate explanations: a break or shift change around 13:20–14:00, a hold on P16, or delayed logging of starts. If P16 and P22 had in fact started, the 14:00 queues would be 3 (S2) and 0 (S1).

**Projection [H].** At 14:00 eight cases still need calibration (2 in service, 4 queued, 2 upstream). At ≈ 2.8/h and with no new arrivals the backlog clears at roughly 16:30–17:00, and the four queued cases would wait roughly 90–100 min at S2, so the final S2 mean wait would be near 49 min rather than the 37 min seen so far.

**Recommendations [R].**

1. Treat S2 as the capacity constraint: adding or cross-training calibration capacity is the only change that raises output. Inspectors are the obvious source once the S1 queue has drained (I2 was already idle from 13:45).
2. Do not add S1 capacity alone for the 08:00–10:00 surge; it would move the queue to S2 without raising throughput. Level the arrivals, or raise both stations together.
3. Schedule C2 maintenance outside saturated periods (before 08:40, when S2 is starved anyway, or after the backlog), and pool the S2 queue across calibrators during any outage.

# 6. Missingness, censoring, and sensitivity analysis

**Scenario comparison** (whole window; waits over started cases, services over completed cases; minutes).

**Missing starts.**

- The four MISSING starts leave station sojourn, WIP, total sojourn, arrival and completion counts untouched; they only move time between "waiting" and "service" for four station visits, and therefore affect queue length versus in-service count for at most 25–35 min each, and the busy time of I1, C1 and C2 (I2 has none).
- Their aggregate effect is small: across the feasible scenarios the mean wait moves by about 2.5 min and the mean service by about 3 min at either station, and station utilisation by 0.06–0.07 (0.08–0.10 between the hard bounds).
- At S2 the usual fill, completion minus typical service (scenario R), is infeasible under single-tasking: it puts P05 on C1 10 min before C1 finished P03 and P11 on C2 15 min before C2 finished P08. Either both calibrations were genuinely short (≤ 30 and ≤ 25 min against a typical 40), or there was undocumented assistance or a mis-logged completion or resource **[H]**. The data cannot separate these; R is retained as a stress test and its S2 utilisation (0.84) includes double-counted minutes.
- At S1 the same back-dating is feasible and lands within 2 min of the central value, which supports A10 there.

**Right censoring.**

- Dropping unfinished work would remove P21's 30 min from S1 and 35 min (P15, P17) from S2 busy time, lowering utilisation from 0.83 to 0.78 and from 0.79 to 0.74; it would also remove 12 % of S1's and 27 % of S2's WIP area. They are kept.
- Completed-case S2 waiting (37 min) understates the experience of the later cases: the four censored waits are already 15–85 min and the hand projection in Section 5 lifts the S2 mean to about 49 min **[H]**. Because waits trend upward with arrival time, censoring is informative; a Kaplan–Meier style correction that assumes independent censoring would be misleading, so bounds and a labelled projection are given instead.
- OPEN services: P15's and P17's elapsed 30 and 5 min, and P21's 30 min, are lower bounds on final service and are excluded from service-time means.
- The case-level mean total sojourn (146 min) describes the first 14 arrivals only; later arrivals will exceed it (P15 > 230).

**C2 outage.** Removing the outage from the denominator gives S2 utilisation 0.79 (560/705); ignoring it gives 0.78 (560/720); also removing the flanking idle time gives 0.81 (560/695). The choice moves the figure by about 0.03 and does not change any conclusion. The outage's effect on waiting (about one case of queue, 10–20 min of post-outage wait) is an estimate resting on the 5-min hand-over assumption.

**Rounding.** Single small durations are unreliable (reported 5 = true 0–10; reported 0-min gap on C1 at 11:00 = true gap within ±5). Hard bounds for the missing starts widen by up to 2.5 min at each end, so the service upper bounds become 40, 40, 35 and 30 min in the worst case. Aggregates are robust: jitter alone moves mean waits by well under 1 min and mean WIP by about ±0.05. Instantaneous peaks depend on the tie convention: S1 WIP peak 8 or 9; the queue peaks (7 and 5) and the S2 WIP peak (7) do not change.

**Stable conclusions** (hold in every scenario and under rounding).

- Both stations ran at practical capacity all morning; S2 has the lower capacity and limits output (≈ 2.8/h against ≈ 3.6/h).
- S1 carried the larger queue until about 12:45 and S2 afterwards; system WIP peaked at about 13 around 11:30 and 8 cases remain at 14:00.
- Station sojourn, WIP, total sojourn of departed cases and all counts.
- The outage cost roughly 20–25 C2-minutes and is not the root cause of the S2 queue.
- Order of magnitude of waits: S1 about 65–68 min on average (plateau ≈ 100), S2 about 37–40 min so far and rising.

**Not stable.**

- The wait/service split for P05, P07, P11 and P15, and with it the utilisation of I1 (0.74–0.88) and, less so, of C1 and C2 (spread 0.04–0.07).
- Whether P05 and P11 were genuinely short calibrations.
- Final S2 waits and total sojourns of P15–P22, and the final services of P15, P17 and P21.
- Whether arrivals truly stopped after 12:10 (A2), and whether P16 and P22 were really still waiting (A12).
- Any steady-state reading of S2 or case-level averages.

**Data recommendations [R].** Make start timestamps mandatory and keep unrounded times; log resource availability (breaks, maintenance flanks) and hold reasons; reconcile the arrival feed after 12:10; record the assigned S2 resource at queue entry so that pooled and dedicated queueing can be told apart.

#--- 2. status-aware parsing
def parse(x):
    """-> (minutes after 08:00 or NaN, status). MISSING, OPEN and blank stay distinct."""
    if x == "":
        return np.nan, "NOT_REACHED"       # activity not started/finished and not applicable yet
    if x == "MISSING":
        return np.nan, "MISSING"           # happened, timestamp not recorded
    if x == "OPEN":
        return np.nan, "OPEN"              # started, still running at 14:00
    h, m = x.split(":")
    return (int(h) - 8) * 60.0 + int(m), "OBS"


tbl = raw[["case", "s1_resource", "s2_resource", "state_at_14_00"]].copy()
for c in TCOLS:
    tbl[c] = [parse(x)[0] for x in raw[c]]
    tbl[c + "_st"] = [parse(x)[1] for x in raw[c]]


def visits(t):
    """One row per (case, station) that the case has reached. q_in = queue-entry time."""
    s1 = pd.DataFrame({"case": t.case, "station": "S1", "res": t.s1_resource, "q_in": t.arrival_s1,
                       "start": t.s1_start, "start_st": t.s1_start_st, "end": t.s1_end, "end_st": t.s1_end_st})
    r = t[t.s1_end_st == "OBS"]            # only these cases have entered the S2 queue
    s2 = pd.DataFrame({"case": r.case, "station": "S2", "res": r.s2_resource, "q_in": r.s1_end,
                       "start": r.s2_start, "start_st": r.s2_start_st, "end": r.s2_end, "end_st": r.s2_end_st})
    return pd.concat([s1, s2], ignore_index=True)


def start_bounds(v):
    """Feasible interval of every MISSING start.
    lo      = max(queue entry, previous completion on the same resource, end of outage if inside it)
    hi      = own completion (non-negative service)
    hi_fifo = min(hi, earliest observed start of a case that entered the same queue later)  [soft]"""
    out = []
    for i, r in v[v.start_st == "MISSING"].iterrows():
        prev = v[(v.res == r.res) & (v.end_st == "OBS") & (v.end < r.end)].end.max()
        lo = np.nanmax([r.q_in, prev])
        a, b = OUTAGE.get(r.res, (np.inf, np.inf))
        lo = b if a <= lo < b else lo
        later = v[(v.station == r.station) & (v.start_st == "OBS") & (v.q_in > r.q_in)].start.min()
        obs = v[(v.station == r.station) & (v.start_st == "OBS") & (v.end_st == "OBS")]
        out.append(dict(idx=i, case=r.case, station=r.station, res=r.res, q_in=r.q_in, end=r.end, lo=lo,
                        hi=r.end, hi_fifo=np.nanmin([r.end, later]), svc_ref=(obs.end - obs.start).mean()))
    return pd.DataFrame(out)


SCEN = {  # imputation rule applied to each MISSING start
    "E_earliest":  lambda b: b.lo,                                  # longest service, shortest wait
    "C_handover":  lambda b: np.minimum(b.lo + 5, b.hi_fifo),       # usual 5-min hand-over gap
    "M_midpoint":  lambda b: (b.lo + b.hi) / 2,                     # midpoint of hard interval
    "L_fifo_late": lambda b: b.hi_fifo,                             # latest FIFO-consistent start
    # relaxed capacity: back-date by the station's mean observed service even if the resource was still
    # busy (only possible with undocumented assistance or a mis-logged completion) - a stress test
    "R_meansvc_overlap": lambda b: np.maximum(b.q_in, b.end - b.svc_ref),
}
FEASIBLE = ["E_earliest", "C_handover", "M_midpoint", "L_fifo_late"]


def impute(v, b, starts):
    x = v.copy()
    x.loc[b.idx.values, "start"] = np.asarray(starts, dtype=float)
    return x


def ov(lo, hi, a, b):
    """Minutes of [lo,hi) inside [a,b); NaN hi = still running (right-censored at 14:00)."""
    hi = np.where(np.isnan(hi), W, hi)
    return np.clip(np.minimum(hi, b) - np.maximum(lo, a), 0, None)


def station_metrics(x, a=0.0, b=W):
    """Queue / service / WIP / utilisation for an imputed visit table on window [a,b)."""
    rows = {}
    for s, g in x.groupby("station"):
        started, done = g.start.notna(), g.end.notna()
        wait = g.start - g.q_in
        wait_lb = np.where(started, wait, W - g.q_in)              # censored waits as lower bounds
        svc = (g.end - g.start)[done]
        q_area = ov(g.q_in, g.start, a, b).sum()
        wip_area = ov(g.q_in, g.end, a, b).sum()
        busy = ov(g.start[started], g.end[started], a, b).sum()
        avail = len(RES[s]) * (b - a) - sum(max(0, min(o[1], b) - max(o[0], a))
                                            for r, o in OUTAGE.items() if r in RES[s])
        rows[s] = dict(n_in=len(g), n_started=int(started.sum()), n_done=int(done.sum()),
                       wait_mean_started=wait[started].mean(), wait_mean_with_cens_LB=wait_lb.mean(),
                       svc_mean_done=svc.mean(), svc_min=svc.min(), svc_max=svc.max(),
                       Lq_mean=q_area / (b - a), WIP_mean=wip_area / (b - a),
                       busy_min=busy, util=busy / avail)
    return pd.DataFrame(rows).T


def step(lo, hi, grid):
    """Right-continuous count of intervals [lo,hi) at each grid time (completions and starts at a
    rounded instant are processed before the count is read; a case leaving at t is not counted at t)."""
    lo = np.asarray(lo, float)[:, None]
    hi = np.where(np.isnan(hi), np.inf, hi)[:, None]
    return ((lo <= grid) & (grid < hi)).sum(0)

grid = np.arange(0, W + 0.1, 2.5)

rows = []

        g = XC[XC.station == s]
