# 1. Objectives and Constraints

## Optimization Objectives
1. **SLA Compliance**: Minimize SLA misses while balancing urgency and resource constraints
2. **Throughput**: Maximize efficient processing of cases without sacrificing quality
3. **Skill Development**: Allocate 20% of normal/low-priority work to training opportunities
4. **Workload Fairness**: Distribute assignments evenly while respecting overtime risks
5. **Continuity**: Maintain case ownership where handover costs are high
6. **Resilience**: Avoid bottlenecks and single points of failure

## Hard Constraints (Safety/Compliance)
1. **Skill Requirements**:
   - Security Review: Skill 3 or 1-2 with supervision (R7_Gita or R8_Hugo)
   - Final Approval: Skill 2-3 (Skill 1 may prepare but not finalize)
   - Quality Check: Only batch when priority is normal/low and SLA >24h
2. **High-Priority Cases**: Cannot assign to skill <2 without supervision
3. **Overtime Protection**: No more than 1 high-priority assignment to high-overtime-risk resources
4. **Reassignment Limits**: No resource gets >4 new assignments in current batch
5. **Specialist Routing**: Security Review must be skill 3 or supervised

## Soft Constraints (Preference Trade-offs)
1. **Continuity vs. Skill**: Prefer current owner if handover cost is high and skill is adequate
2. **Training vs. SLA**: 20% training assignments must not risk SLA misses
3. **Fairness vs. Efficiency**: Workload distribution should be fair but not at cost of SLA
4. **Bottleneck Avoidance**: Prevent overloading of high-demand skills (Security, Approval)
5. **Risk Mitigation**: High-complexity cases with high handover cost should maintain continuity

# 2. Assignment Policy

**Pseudocode Algorithm:**

```
FUNCTION assign_case(case, queue):
    // 1. Eligibility Filtering
    eligible_resources = filter_resources_by_skill(case.required_skill, case.priority)
    eligible_resources = apply_special_constraints(eligible_resources, case)

    // 2. SLA Urgency Scoring (0-100)
    urgency_score = calculate_urgency(case.sla_remaining, case.priority, case.complexity)

    // 3. Skill-Match Scoring (0-100)
    skill_scores = calculate_skill_match(eligible_resources, case.required_skill)

    // 4. Continuity/Handover-Cost Scoring (0-100)
    continuity_scores = calculate_continuity_score(eligible_resources, case)

    // 5. Workload/Fairness Scoring (0-100)
    workload_scores = calculate_workload_score(eligible_resources, case.priority)

    // 6. Training/Development Scoring (0-100)
    training_scores = calculate_training_score(eligible_resources, case.priority)

    // 7. Resilience/Bottleneck Scoring (0-100)
    resilience_scores = calculate_resilience_score(eligible_resources, case.required_skill)

    // 8. Combine Scores with Weighting
    combined_score = (
        urgency_score * 0.3 +
        skill_scores * 0.25 +
        continuity_scores * 0.2 +
        workload_scores * 0.15 +
        training_scores * 0.05 +
        resilience_scores * 0.05
    )

    // 9. Tie-Breaking Rules
    if case.reassignment_count > 2:
        prefer_current_owner_if_adequate_skill(combined_score, case)
    if case.complexity > 0.7 and case.handover_cost == "high":
        apply_continuity_bias(combined_score, case)
    if case.priority == "urgent" and case.required_skill == "Security":
        enforce_supervision_requirement(combined_score, case)

    // 10. Final Selection
    return select_resource_with_highest_score(eligible_resources, combined_score)

FUNCTION filter_resources_by_skill(resources, required_skill, priority):
    if priority == "urgent" and required_skill in ["Security", "Approval"]:
        return resources where skill >= 2 (with supervision if skill < 3)
    if required_skill == "Security":
        return resources where skill >= 3 or (skill >= 1 and supervisor in [R7_Gita, R8_Hugo])
    if required_skill == "Approval":
        return resources where skill >= 2
    return resources where skill >= 1

FUNCTION calculate_urgency(case):
    if case.sla_remaining < 2h and case.priority == "urgent": return 100
    if case.sla_remaining < 6h and case.priority == "high": return 80
    if case.priority == "urgent": return 60
    if case.sla_remaining < 12h: return 40
    return 20
```

# 4. Comparison with Baseline Policies

| Metric | Proposed Policy | First-Available Routing | Specialist-Only Routing |
|--------|-----------------|-------------------------|--------------------------|
| **SLA Compliance** | High (prioritizes urgency) | Medium (ignores SLA in routing) | Low (specialist bottlenecks) |
| **Error/Rework Risk** | Low (balances skill and continuity) | High (skill mismatch) | Medium (specialist overload) |
| **Workload Fairness** | Balanced (respects overtime) | Unfair (overloads low-open cases) | Unfair (specialists overloaded) |
| **Skill Development** | High (20% training) | Low (no training focus) | Low (no training focus) |
| **Continuity** | High (prioritizes handover cost) | Low (ignores continuity) | Medium (specialists may change) |
| **Resilience** | High (avoids bottlenecks) | Low (creates bottlenecks) | Low (specialist overload) |
| **Throughput** | Medium (balances quality) | High (fast but error-prone) | Low (specialist delays) |
| **Overtime Risk** | Low (protects high-risk resources) | High (ignores overtime) | Medium (specialists may work overtime) |

**Key Trade-offs:**
- **First-Available**: Maximizes throughput but risks errors, reassignments, and unfairness.
- **Specialist-Only**: Minimizes errors but creates bottlenecks and delays.
- **Proposed**: Balances all factors but requires more complex logic and monitoring.

# 5. Explanation to Workers

**Why Assignments Are Made:**

1. **For Your Safety and Quality**:
   - High-priority cases (like Security Review) are assigned to specialists or supervised trainees to prevent errors.
   - Cases with high handover costs (like C007) stay with you if possible to avoid delays.

2. **For Fair Work Distribution**:
   - We avoid overloading resources with overtime risks unless absolutely necessary (e.g., urgent cases).
   - You won’t get more than 4 new assignments at once to prevent burnout.

3. **For Your Growth**:
   - Some normal/low-priority cases are assigned to you to help you develop new skills (e.g., C003, C013).
   - Training assignments are marked clearly so you know they’re for development.

4. **For Case Continuity**:
   - If a case is complex or has high handover costs (like C007), we’ll keep it with you unless you lack the right skills.
   - This reduces delays and rework caused by switching owners.

5. **For Team Resilience**:
   - We avoid overloading any single team or skill (e.g., Security Review is spread between specialists).
   - If a specialist is unavailable, we use supervised trainees to keep the process moving.

**What You Can Do:**
- If you’re assigned a training case, ask your supervisor for guidance.
- If a case is reassigned, check the notes for why it happened.
- If you’re at risk of overtime, flag it so we can redistribute work.

# 6. Process-Mining Audit Indicators

1. **Handover Frequency**:
   - `count(events where org:resource changes for same case)`
   - `avg(handover_cost_band == "high" and reassignment_count > 0)`

2. **Reassignment Risk**:
   - `count(cases where reassignment_count > 2)`
   - `avg(service_time where handover_cost_band == "high")`

3. **Skill Mismatch**:
   - `count(events where required_skill != 0 and resource_skill < 2)`
   - `avg(service_time where skill_mismatch == True)`

4. **Workload Distribution**:
   - `histogram(open_cases_per_resource by team)`
   - `avg(hours_remaining_today by overtime_risk)`

5. **Overtime Risk Exposure**:
   - `count(events where overtime_risk == "high" and priority == "urgent")`
   - `avg(service_time where overtime_risk == "high")`

6. **SLA Misses**:
   - `count(cases where sla_deadline < time:timestamp)`
   - `avg(sla_remaining at assignment vs. actual completion)`

7. **Rework/Appeal**:
   - `count(cases where reassignment_count > 2 and outcome == "rework")`
   - `avg(appeal_rate by resource)`

8. **Training Assignment Share**:
   - `count(training_priority == "yes" cases) / total_normal_low_priority_cases`
   - `avg(skill_growth_score by resource)`

9. **Specialist Bottleneck Indicators**:
   - `avg(service_time for Security/Approval cases)`
   - `histogram(open_cases by required_skill)`

10. **Policy Deviations**:
    - `count(events where assignment violates skill constraints)`
    - `count(events where workload > 4 new assignments)`

# 7. PM4Py Implementation Sketch

```python
import pm4py
import pandas as pd
from pm4py.objects.log.util import dataframe_utils

# Load and preprocess event log
log = pm4py.format_dataframe(event_df, parameters={"case_id": "case:concept:name",
                                                  "activity": "concept:name",
                                                  "timestamp": "time:timestamp",
                                                  "resource": "org:resource"})

# Discover resource networks for similarity analysis
resource_network = pm4py.discover_working_together_network(log)
pm4py.view_sna(resource_network, format="png", output="resource_network.png")

# Discover handover patterns
handover_network = pm4py.discover_handover_of_work_network(log)
pm4py.view_sna(handover_network, format="png", output="handover_network.png")

# Filter cases by priority and SLA
urgent_cases = pm4py.filter_case_performance(log, parameters={"case_attribute": "case_priority",
                                                              "case_attribute_values": ["urgent", "high"]})

# Calculate performance metrics
service_times = pm4py.get_service_time(log)
pm4py.insert_case_service_waiting_time(log, service_times)

# Discover performance DFG
dfg = pm4py.discover_performance_dfg(log)
pm4py.view_graph(dfg, format="png", output="performance_dfg.png")

# Discover organizational roles and skill similarity
roles = pm4py.discover_organizational_roles(log)
skill_similarity = pm4py.discover_activity_based_resource_similarity(log)

# Filter cases by training priority
training_cases = pm4py.filter_event_attribute_values(log,
                                                     parameters={"attributes": ["training_priority"],
                                                                "values": ["yes"]})

# Audit handover costs and reassignments
reassignment_counts = log.groupby("case:concept:name")["org:resource"].nunique().reset_index()
reassignment_counts.columns = ["case", "reassignment_count"]

# Calculate SLA compliance
sla_misses = log[log["time:timestamp"] > log["sla_deadline"]]

# Generate audit report
audit_report = pd.DataFrame({
    "handover_frequency": reassignment_counts["reassignment_count"].mean(),
    "skill_mismatch_rate": (log[log["required_skill"] != 0] &
                           log["resource_skill"] < 2).mean(),
    "training_assignment_share": len(training_cases) / len(log),
    "sla_miss_rate": len(sla_misses) / len(log),
    "overtime_risk_exposure": log[(log["overtime_risk"] == "high") &
                                 (log["case_priority"].isin(["urgent", "high"]))].shape[0] / len(log)
})

# Save visualization of workload distribution
workload_dist = log.groupby("org:resource")["case:concept:name"].nunique().reset_index()
workload_dist.columns = ["resource", "open_cases"]
pm4py.view_sna(workload_dist, format="png", output="workload_distribution.png")
```

**Key PM4Py Functions Used:**
- `discover_working_together_network`: Analyze collaboration patterns
- `discover_handover_of_work_network`: Identify handover bottlenecks
- `discover_activity_based_resource_similarity`: Match resources to activities
- `discover_organizational_roles`: Understand team structures
- `get_service_time`/`insert_case_service_waiting_time`: Measure performance
- `filter_event_attribute_values`: Isolate training cases
- `discover_performance_dfg`: Visualize process bottlenecks
- `view_sna`: Generate social network visualizations

This implementation enables continuous monitoring of the assignment policy's effectiveness and compliance with constraints.
