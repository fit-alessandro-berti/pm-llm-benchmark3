# 1. Equivalence Notions

To compare process models rigorously, equivalence must be defined relative to specific observation functions and abstraction boundaries.

- **Visible Trace Equivalence after hiding $\tau$**:
  Two process trees $M_1$ and $M_2$ are visible trace equivalent ($M_1 \equiv_{\text{vis}} M_2$) iff their sets of complete visible traces are identical. Let $\pi_{\setminus \tau}(t)$ project a sequence of execution events $t$ by removing all silent transitions ($\tau$). Then:
  $$L(M)_{\setminus \tau} = \{ \pi_{\setminus \tau}(t) \mid t \in L_{\text{complete}}(M) \}$$
  $M_1 \equiv_{\text{vis}} M_2$ holds iff $L(M_1)_{\setminus \tau} = L(M_2)_{\setminus \tau}$.

- **Bounded Visible-Language Equivalence under P3**:
  Two models are bounded visible-language equivalent under parameter bound $B = (L_{\max} = 12, A_{\max} = 3)$ iff:
  $$\{ t \in L(M_1)_{\setminus \tau} \mid |t| \le 12 \land \#_{\text{'Analyze Revision'}}(t) \le 3 \} = \{ t \in L(M_2)_{\setminus \tau} \mid |t| \le 12 \land \#_{\text{'Analyze Revision'}}(t) \le 3 \}$$

- **Business-Relevant Equivalence under P1 (Operational Compliance View)**:
  $M_1 \equiv_{\text{P1}} M_2$ iff for every trace $t$, the following compliance properties hold:
  1. Each instance of `'Analyze Revision'` is paired $1$-to-$1$ with a `'Check Revision'` within the same revision attempt prior to any subsequent `'Rework Case'` or `'Close Case'`.
  2. `'Rework Case'` strictly separates distinct analysis attempts.
  3. Optional `'Approve Revision'` occurrences do not bypass the check requirement.

- **Abstracted Dashboard Equivalence under P2 (Executive Dashboard View)**:
  Let $\alpha_{\text{dash}}(t)$ be the abstraction function mapping a visible trace $t$ to a 5-tuple:
  $$\alpha_{\text{dash}}(t) = \left( \text{head}(t) = \text{'Open Case'}, \text{last}(t) = \text{'Close Case'}, \#_{\text{'Analyze Revision'}}(t), \#_{\text{'Check Revision'}}(t) \ge 1, \#_{\text{'Rework Case'}}(t) > 0 \right)$$
  $M_1 \equiv_{\text{P2}} M_2$ iff $\{ \alpha_{\text{dash}}(t) \mid t \in L(M_1)_{\setminus \tau} \} = \{ \alpha_{\text{dash}}(t) \mid t \in L(M_2)_{\setminus \tau} \}$.

**Handling of Duplicate Visible Labels**:
In trace semantics, activity occurrences are represented by their string activity labels. Duplicate activity occurrences within a trace are distinguished by their **sequence position (order of occurrence)**, not by hidden instance identifiers.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| **Loop scope** | Encloses `+('Analyze Revision', 'Check Revision')` and `X('Approve Revision', tau)`. | Encloses `->('Analyze Revision', X('Approve Revision', tau))`. `'Check Revision'` is outside the loop. | In Model A, `'Check Revision'` executes once per loop iteration. In Model B, `'Check Revision'` executes exactly once per overall case. |
| **Check Revision count range** | Min: $1$, Max: Unbounded ($n_{\text{Check}} = n_{\text{Analyze}}$). | Min: $1$, Max: $1$ ($n_{\text{Check}} = 1$ regardless of $n_{\text{Analyze}}$). | Model A enforces repeated checking on reworks; Model B limits checking to a single global occurrence. |
| **Placement of Check Revision** | Scoped inside each iteration, concurrent with `'Analyze Revision'`, prior to approval/rework. | Fully concurrent (`+`) with the entire revision loop construct. | Model B permits `'Check Revision'` to interleave before the 1st analysis, between reworks, or after all reworks. |
| **Optional approval occurrences** | Executed 0 or 1 time per revision cycle (max $n_{\text{Analyze}}$). | Executed 0 or 1 time per revision cycle (max $n_{\text{Analyze}}$). | Both models permit skipping approval via $\tau$ on each revision iteration. |
| **Concurrency scope** | Local intra-iteration concurrency between `'Analyze Revision'` and `'Check Revision'`. | Global inter-iteration concurrency between `'Check Revision'` and the multi-step loop. | Model B introduces cross-iteration interleaving of checks relative to rework cycles. |
| **Join before Close Case** | Sequential join: loop terminates, then `'Close Case'` fires. | Concurrent join (`+`): both `'Check Revision'` and the loop must complete before `'Close Case'`. | Both guarantee all concurrent branches complete before case closure. |

### Impact of Optional `Approve Revision` and Hidden `tau`
The XOR operator `X('Approve Revision', tau)` allows `Approve Revision` to be replaced silently by `tau`. Because `tau` produces no visible label in the projected trace, traces without approvals (such as T1, T3, T4) are valid complete traces. However, choosing `tau` does not bypass the structural requirement in Model A that `+('Analyze Revision', 'Check Revision')` must complete before the loop iteration can transition to `LoopRedo` (`'Rework Case'`) or exit to `'Close Case'`.

# 5. Bounded Comparison Code

The following Python script uses PM4Py to parse both process trees, convert them to accepting Petri nets, verify soundness, and execute an exhaustive Breadth-First Search (BFS) reachability traversal over Petri net markings under the P3 bounds ($|t| \le 12$ and $\#_{\text{'Analyze Revision'}} \le 3$).

```python
import pm4py
from collections import deque

def build_models():
    tree_a_str = "->( 'Open Case', *( ->( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) ), 'Rework Case' ), 'Close Case' )"
    tree_b_str = "->( 'Open Case', +( 'Check Revision', *( ->( 'Analyze Revision', X('Approve Revision', tau) ), 'Rework Case' ) ), 'Close Case' )"
    
    tree_a = pm4py.parse_process_tree(tree_a_str)
    tree_b = pm4py.parse_process_tree(tree_b_str)
    
    net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
    net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)
    
    sound_a = pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=False)
    sound_b = pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=False)
    
    return (net_a, im_a, fm_a, sound_a), (net_b, im_b, fm_b, sound_b)

def get_bounded_complete_traces(net, im, fm, max_len=12, max_analyze=3):
    """
    Exhaustive Breadth-First Search (BFS) over Petri net reachability graph.
    Explores all complete traces up to max_len visible events and max_analyze occurrences.
    """
    complete_traces = set()
    # Queue items: (marking, visible_trace_tuple, analyze_count)
    queue = deque([(im, (), 0)])
    visited_states = set()
    visited_states.add((im, (), 0))
    
    while queue:
        curr_m, trace, analyze_cnt = queue.popleft()
        
        if curr_m == fm:
            complete_traces.add(trace)
            
        enabled_transitions = pm4py.get_enabled_transitions(net, curr_m)
        for t in enabled_transitions:
            label = t.label
            if label is None or label == 'tau':
                new_trace = trace
                new_analyze_cnt = analyze_cnt
            else:
                new_trace = trace + (label,)
                new_analyze_cnt = analyze_cnt + (1 if label == 'Analyze Revision' else 0)
            
            if len(new_trace) <= max_len and new_analyze_cnt <= max_analyze:
                # Calculate next marking
                next_m = curr_m
                for arc in t.in_arcs:
                    next_m = next_m - arc.source.multiplicity * arc.source
                for arc in t.out_arcs:
                    next_m = next_m + arc.target.multiplicity * arc.target
                
                state_key = (next_m, new_trace, new_analyze_cnt)
                if state_key not in visited_states:
                    visited_states.add(state_key)
                    queue.append((next_m, new_trace, new_analyze_cnt))
                    
    return complete_traces

if __name__ == "__main__":
    (net_a, im_a, fm_a, sound_a), (net_b, im_b, fm_b, sound_b) = build_models()
    
    print(f"Model A Soundness: {sound_a}")
    print(f"Model B Soundness: {sound_b}")
    
    traces_a = get_bounded_complete_traces(net_a, im_a, fm_a, max_len=12, max_analyze=3)
    traces_b = get_bounded_complete_traces(net_b, im_b, fm_b, max_len=12, max_analyze=3)
    
    only_a = traces_a - traces_b
    only_b = traces_b - traces_a
    
    print(f"\nTotal bounded complete traces in Model A: {len(traces_a)}")
    print(f"Total bounded complete traces in Model B: {len(traces_b)}")
    print(f"Traces unique to Model A: {len(only_a)}")
    print(f"Traces unique to Model B: {len(only_b)}")
    
    print("\nSample trace unique to Model A:")
    if only_a:
        print(list(next(iter(only_a))))
        
    print("\nSample trace unique to Model B:")
    if only_b:
        print(list(next(iter(only_b))))
```

### Note on Exhaustive BFS vs Heuristic Play-out
The BFS state exploration above guarantees **exhaustive coverage** of all reachable marking states and visible traces up to the designated depth bounds. In contrast, using `pm4py.play_out(...)` relies on stochastic or heuristic simulation, which samples traces randomly and cannot prove trace non-containment or language equivalence.

# 6. Stochastic and Footprint Comparison

- **Footprint Matrices (`pm4py.discover_footprints`)**:
  Footprint analysis captures pairwise behavioral relations between activity labels: directly-follows ($\rightarrow$), parallel ($||$), and choice ($\#$).
  - Footprint analysis abstracts away total activity occurrence counts and global loop iterations.
  - Model A and Model B generate distinct footprint matrices because in Model B, `'Check Revision'` can directly follow or precede `'Rework Case'`, whereas in Model A, `'Check Revision'` cannot follow `'Rework Case'` without an intervening `'Analyze Revision'`.

- **Stochastic Language & Earth Mover's Distance (`pm4py.get_stochastic_language`, `pm4py.compute_emd`)**:
  Stochastic language analysis assigns probabilities to complete traces under assumed transition execution probabilities (e.g., uniform branch choices). EMD quantifies the minimal transport cost to transform one trace probability distribution into another.

```python
import pm4py

def compare_footprints_and_stochastics(net_a, im_a, fm_a, net_b, im_b, fm_b):
    # 1. Discover footprints
    fp_a = pm4py.discover_footprints(net_a, im_a, fm_a)
    fp_b = pm4py.discover_footprints(net_b, im_b, fm_b)
    
    # 2. Simulate logs for stochastic language estimation
    log_a = pm4py.play_out(net_a, im_a, fm_a, no_traces=500)
    log_b = pm4py.play_out(net_b, im_b, fm_b, no_traces=500)
    
    stoch_a = pm4py.get_stochastic_language(log_a)
    stoch_b = pm4py.get_stochastic_language(log_b)
    
    emd_distance = pm4py.compute_emd(stoch_a, stoch_b)
    return fp_a, fp_b, emd_distance
```

### Why Equal Footprints or Low EMD Do Not Prove Equivalence
1. **Footprint Limitation**: Pairwise abstractions ignore higher-order loop dependencies and activity counts. Two models can have identical footprint relations while allowing completely different numbers of activity executions per trace.
2. **EMD Limitation**: EMD is a continuous distance metric over probability distributions. A low EMD value indicates statistical similarity under a specific simulation policy, but does **not** prove strict trace equivalence ($L(M_1) = L(M_2)$).
3. **Probability Distribution Sensitivity**: Stochastic equivalence depends entirely on the choice of transition weights. Without declared empirical probabilities, uniform sampling introduces artificial biases.

# 7. Complexity Comparison

```python
import pm4py

def analyze_complexity(tree_str):
    tree = pm4py.parse_process_tree(tree_str)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    
    def get_nodes(t):
        return 1 + sum(get_nodes(c) for c in t.children)
    
    def get_depth(t):
        return 1 + (max([get_depth(c) for c in t.children]) if t.children else 0)
    
    def get_leaves(t):
        if not t.children:
            return [t.label]
        res = []
        for c in t.children:
            res.extend(get_leaves(c))
        return res

    nodes = get_nodes(tree)
    depth = get_depth(tree)
    leaves = get_leaves(tree)
    vis_leaves = [l for l in leaves if l is not None and l != 'tau']
    sil_leaves = [l for l in leaves if l is None or l == 'tau']
    dup_labels = len(vis_leaves) - len(set(vis_leaves))
    simplicity = pm4py.simplicity_petri_net(net, im, fm)
    
    return nodes, depth, len(vis_leaves), len(sil_leaves), dup_labels, simplicity
```

# 8. Simplified Model

### Target Semantics Selection
We target **P1 (Operational Compliance View)**. Operational compliance requires every analysis attempt to be checked before rework or case closure, but standard business procedures require analysis to precede checking sequentially, rather than executing concurrently.

### 1. Process Tree Expression
```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

### 2. PM4Py Assignment
```python
import pm4py

simplified_model_str = "->( 'Open Case', *( ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ), 'Rework Case' ), 'Close Case' )"
simplified_model = pm4py.parse_process_tree(simplified_model_str)
simplified_net, simplified_im, simplified_fm = pm4py.convert_to_petri_net(simplified_model)
```

### 3. Preservation Table

| View / Property | Status under Simplified Model | Explanation |
|---|---|---|
| **P1 Operational Compliance** | **Exact** | Guarantees every `'Analyze Revision'` is checked before rework/close. |
| **P2 Executive Dashboard** | **Exact** | Preserves Open first, Close last, $n_{\text{Analyze}} \ge 1$, $n_{\text{Check}} \ge 1$, and rework flags. |
| **P3 Bounded Equivalence vs Model A** | **Weakened** | Retains sequential traces (`Analyze` $\rightarrow$ `Check`); eliminates trace variants where `Check` precedes `Analyze`. |
| **Interleaving Concurrency** | **Lost** | Eliminates parallel execution between `'Analyze Revision'` and `'Check Revision'`. |

# 9. Final Recommendation

1. **Operational Compliance View (P1)**: **Model A** is structurally correct; **Model B is strictly non-compliant** because it omits checks on repeated revisions and allows checks to float across rework boundaries.
2. **Executive Dashboard View (P2)**: Both Model A and Model B (as well as the Simplified Model) satisfy P2 under its Boolean abstraction. However, **Model A or the Simplified Model** should still be used at the data layer to maintain underlying process integrity.
3. **Bounded Testing View (P3)**: Models A and B are **not equivalent**. Bounded exploration ($|t| \le 12$) successfully produces counterexamples (e.g., T1, T3) that disprove equivalence.
4. **Simplification Recommendation**: Adopt the **Simplified Model**. It reduces structural complexity (node count from 12 to 11, higher Petri net simplicity score), enforces strict sequential compliance (`Analyze` followed by `Check`), eliminates unnecessary concurrency, and preserves exact compliance under P1 and P2.

> **Warning on Bounded Comparison Limits**: Passing bounded trace comparison tests demonstrates language inclusion only up to the tested bound $k$. It does **not** constitute a formal proof of unbounded equivalence for infinite-state or looping process models. Exceeding or modifying bounds can reveal latent state divergence.
