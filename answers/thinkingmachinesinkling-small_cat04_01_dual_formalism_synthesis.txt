No visible activity label is duplicated, avoiding identifier collisions in logs.
5. **Approximation policy (Process Tree).** **Conservative under-approximation** for concurrency and synchronization: the tree forces *Plan Verification* and *Design Corrective Action* and *Approvals* / *Consult Supplier* to complete before *Execute Trial* starts, and forces approvals to complete before the trial cycle begins. This excludes valid traces where approvals overlap the trial (the intended non-block-structured overlap is lost). It is conservative because it never admits an unsafe release without approvals or supplier finish.
6. **“May overlap” interpretation.** Interpreted as **true concurrency / absence of order constraint** wherever the narrative does not mandate precedence. Where the tree cannot represent true concurrency (e.g., approvals overlapping trial), overlap is sacrificed for safety.
7. **Activity-based recording.** Every node is a visible transition (except ``); no data variables control branching.
8. **Release synchronization.** Modeled as a sequence point after the trial loop: *Release Material* is placed after the loop, and approval / supplier nodes are placed in the preceding parallel block, so they finish before release.

# 3. PM4Py Process-Tree Model

## 3.1 Compact expression

Because object constructors are used, the mapping is structural rather than string-based: sequence nodes (``) enforce strict order; parallel nodes (``) allow overlap; `XOR` nodes (``) model choice; `LOOP` (`*`) models repetition; silent `` nodes model skips.

```
(
  "Register Deviation",
  (
    ("Contain Material", "Plan Verification"),
    ("Analyze Root Cause",
      ("Design Corrective Action",
        ("Supervisor Review",
          ("Quality Review","Regulatory Review")
        ),
        ("Consult Supplier", )
      )
    )
  ),
  *(("Execute Trial","Inspect Trial",
       ("Adjust Parameters", )
     )),
  "Release Material",
  "Archive Case"
)
```

*Mapping notes:* The outer `` lets *Contain Material* and *Analyze Root Cause* start together. The inner `` after *Analyze Root Cause* forces design, approvals, and optional supplier to finish together before the trial loop begins (conservative). The `*` loop repeats the trial body; `("Adjust Parameters", )` approximates “fail / pass” by non-deterministically inserting `Adjust Parameters` or a silent exit.

## 3.2 Self-contained construction code

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

def link(parent, children):
    parent.children = list(children)
    for c in children:
        c.parent = parent

# --- Leaves -------------------------------------------------
rd   = ProcessTree("Register Deviation")
cm   = ProcessTree("Contain Material")
pv   = ProcessTree("Plan Verification")
arc  = ProcessTree("Analyze Root Cause")
dca  = ProcessTree("Design Corrective Action")
sr   = ProcessTree("Supervisor Review")
qr   = ProcessTree("Quality Review")
rr   = ProcessTree("Regulatory Review")
cs   = ProcessTree("Consult Supplier")
et   = ProcessTree("Execute Trial")
it   = ProcessTree("Inspect Trial")
ap   = ProcessTree("Adjust Parameters")
rm   = ProcessTree("Release Material")
ac   = ProcessTree("Archive Case")
tau  = ProcessTree("\u03C4")  # silent skip / loop exit

# --- Approval route (XOR) ------------------------------------
low_route  = ProcessTree("Supervisor Review")
high_route = ProcessTree()
high_route.operator = Operator.PARALLEL
high_route.children = [ProcessTree("Quality Review"), ProcessTree("Regulatory Review")]
approval_route = ProcessTree()
approval_route.operator = Operator.XOR
approval_route.children = [low_route, high_route]
# Note: high_route uses PARALLEL inside XOR; the tree supports this structurally.

# --- Optional supplier (XOR) ---------------------------------
optional_cs = ProcessTree()
optional_cs.operator = Operator.XOR
optional_cs.children = [cs, tau]

# --- Post-root-cause parallel block -------------------------
post_arc = ProcessTree()
post_arc.operator = Operator.PARALLEL
post_arc.children = [dca, approval_route, optional_cs]

arc_seq = ProcessTree()
arc_seq.operator = Operator.SEQUENCE
arc_seq.children = [arc, post_arc]

# --- Containment branch --------------------------------------
cm_seq = ProcessTree()
cm_seq.operator = Operator.SEQUENCE
cm_seq.children = [cm, pv]

# --- Initial parallel streams --------------------------------
work_par = ProcessTree()
work_par.operator = Operator.PARALLEL
work_par.children = [cm_seq, arc_seq]

# --- Trial loop (approximate) -------------------------------
trial_body = ProcessTree()
trial_body.operator = Operator.SEQUENCE
trial_body.children = [
    et,
    it,
    # Approximate pass/fail: either adjust (loop back) or silent (exit)
    ProcessTree(operator=Operator.XOR, children=[ap, tau])
]
trial_loop = ProcessTree()
trial_loop.operator = Operator.LOOP
trial_loop.children = [trial_body]

# --- Root sequence -------------------------------------------
root = ProcessTree()
root.operator = Operator.SEQUENCE
root.children = [rd, work_par, trial_loop, rm, ac]

# --- Parent links --------------------------------------------
link(work_par, [cm_seq, arc_seq])
link(cm_seq, [cm, pv])
link(arc_seq, [arc, post_arc])
link(post_arc, [dca, approval_route, optional_cs])
# Internal approval / optional links handled by their parents
link(approval_route, [low_route, high_route])
link(high_route, [high_route.children[0], high_route.children[1]])  # already set
link(optional_cs, [cs, tau])
link(trial_body, [et, it, trial_body.children[-1]])
link(trial_loop, [trial_body])
link(root, [rd, work_par, trial_loop, rm, ac])

# --- Final variable ------------------------------------------
tree = root
```

## 3.3 Requirements not represented exactly

- **Cross-branch overlap of approvals and trial (D04/D08/C04).** The tree forces `work_par` (which contains approvals and optional supplier) to finish before `trial_loop` starts. Thus allowed traces where *Execute Trial* starts while *Supervisor Review* / *Quality Review* / *Regulatory Review* are still open are excluded.
- **Optional supplier overlap with trial (C05).** Because `optional_cs` is inside `work_par`, it must finish before the trial loop begins; the intended overlap with trial execution is lost.
- **Loop exit semantics (L01/D14/D13).** The `LOOP` with `XOR(ap, )` admits traces where `Adjust Parameters` occurs after a passing inspection (if `` is chosen to exit but `ap` was previously selected in another iteration? More precisely, because `` is silent and non-deterministic, the model may exit immediately after `Inspect Trial` without requiring a passing result, and may also execute `Adjust Parameters` in the final iteration before exit).
- **High-risk concurrency (C06).** Inside `XOR`, the high branch uses `PARALLEL` for `QR` and `RR`; this is structurally supported but analytically treats them as concurrently enabled, which is correct.
- **No data conditions.** The split between low/high and supplier/no-supplier is modeled structurally, so the same tree produces both traces; this is correct per instruction 11.

# 4. PM4Py POWL Model

## 4.1 Compact POWL description

One `StrictPartialOrder` holds all visible and operator nodes. Cross-branch dependencies are direct edges (`.order.add_edge`). `OperatorPOWL(XOR, ...)` models the risk-choice; `OperatorPOWL(XOR, ...)` models optional supplier; `OperatorPOWL(LOOP, ...)` models the trial cycle. Unconnected nodes (e.g., `approval_op` and `trial_op`) may remain concurrent.

```
StrictPartialOrder(
  RD, CM, ARC, PV, DCA, SR, QR, RR, CS, ET, IT, AP, RM, AC, ,
  approval_op=XOR(SR, Parallel(QR,RR)),
  opt_cs=XOR(CS, ),
  trial_op=LOOP(SEQ(ET, IT, XOR(AP, )))
)
Edges:
  RDCM, RDARC,
  CMPV, ARCDCA, ARCapproval_op, ARCopt_cs,
  PVtrial_op, DCAtrial_op,
  trial_opRM, approval_opRM, opt_csRM,
  RMAC
```

## 4.2 Self-contained construction code

```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# --- Visible transitions -------------------------------------
rd  = Transition("Register Deviation")
cm  = Transition("Contain Material")
pv  = Transition("Plan Verification")
arc = Transition("Analyze Root Cause")
dca = Transition("Design Corrective Action")
sr  = Transition("Supervisor Review")
qr  = Transition("Quality Review")
rr  = Transition("Regulatory Review")
cs  = Transition("Consult Supplier")
et  = Transition("Execute Trial")
it  = Transition("Inspect Trial")
ap  = Transition("Adjust Parameters")
rm  = Transition("Release Material")
ac  = Transition("Archive Case")

# --- Silent / operator nodes ---------------------------------
tau = SilentTransition("\u03C4")

# High-risk approval group: no edge between QR/RR -> concurrency
high_spo = StrictPartialOrder([qr, rr])

# Risk-route choice (low vs high)
approval_op = OperatorPOWL(Operator.XOR, children=[sr, high_spo])

# Optional supplier choice
opt_cs = OperatorPOWL(Operator.XOR, children=[cs, tau])

# Trial loop (approximate: loop over ET, IT, optional AP, silent exit)
trial_op = OperatorPOWL(Operator.LOOP, children=[et, it, ap, tau])

# --- Assemble strict partial order ---------------------------
nodes = [
    rd, cm, pv, arc, dca, sr, qr, rr, cs, et, it, ap, rm, ac,
    tau, approval_op, opt_cs, trial_op
]

powl = StrictPartialOrder(nodes)

# --- Cross-branch precedence edges ---------------------------
# Initial streams
powl.order.add_edge(rd, cm)
powl.order.add_edge(rd, arc)

# Containment stream
powl.order.add_edge(cm, pv)

# Root-cause stream
powl.order.add_edge(arc, dca)

# Approvals and optional supplier start only after analysis
powl.order.add_edge(arc, approval_op)
powl.order.add_edge(arc, opt_cs)

# Trial waits for BOTH planning and design (join)
powl.order.add_edge(pv, trial_op)
powl.order.add_edge(dca, trial_op)

# Release synchronizes trial completion, approval completion,
# and optional supplier completion (if selected)
powl.order.add_edge(trial_op, rm)
powl.order.add_edge(approval_op, rm)
powl.order.add_edge(opt_cs, rm)

# Archive after release
powl.order.add_edge(rm, ac)

# --- Internal concurrency preserved -------------------------
# No edge added between qr and rr => concurrent high-risk reviews.
# No edge between approval_op and trial_op => approvals may overlap trial.
# No edge between opt_cs and trial_op => supplier may overlap trial.
# No edge between pv and dca => planning and design may overlap.
# No edge between cm and arc => initial streams overlap.
```

## 4.3 Why unconnected pairs may remain concurrent

Every omitted edge is intentional:

- `approval_op`  `trial_op`: approvals may overlap the trial cycle.
- `opt_cs`  `trial_op`: supplier work may overlap trial work.
- `pv`  `dca`: verification planning and corrective design progress independently.
- `cm`  `arc`: containment and root-cause analysis start together.
- `qr`  `rr`: high-risk reviews have no order constraint.
- `et`  `it` are ordered (inside `trial_op`); `ap` is ordered inside loop body but may or may not fire.

# 7. Preferred Representation and Validation Plan

**Canonical representation:** The **POWL model** is preferred because it expresses cross-branch concurrency (approvals vs trial, supplier vs trial) through omitted partial-order edges rather than through forced serialization. It also directly encodes the synchronization at *Release Material* via multiple incoming edges, matching the intended “join of independent obligations” semantics.

**Validation plan:**

1. **Conversion to accepting Petri net.** Use `pm4py.convert_to_petri_net(powl)` (or `convert_to_petri_net(tree)` for the tree). Inspect the resulting `PetriNet` for correct initial/final markings.
2. **Soundness checking.** Call `pm4py.check_soundness(net, im, fm, print_diagnostics=True)` on both converted nets. Confirm no dead transitions and that `IM` reaches `FM` cleanly.
3. **Bounded / sampled playout.** Use `pm4py.play_out(powl, max_depth=10, variant="random")` and `play_out(tree, ...)`. Check that:
   - All five allowed witness traces are replayable (positive tests).
   - The forbidden traces are blocked (negative tests).
4. **Positive and negative trace tests (explicit).**
   - Positive: T01, T02, T03, T04 (POWL only), T05.
   - Negative: F01 (cross-branch), F02 (supplier after release), F03 (AP after pass).
5. **Silent behavior / duplicate-label check.** Inspect that `tau` (silent) nodes appear only as skips in `XOR` branches, not as visible events in logs. Verify that no visible label occurs twice in the same process-tree path (e.g., *Analyze Root Cause* is not duplicated).
6. **Limitations.** Validation relies on simulated playout and soundness of the converted net; it does not prove that *all* intended traces are admitted or that *only* intended traces are admitted, because the loop and XOR approximations admit extra behavior. Data-based conditions (risk, supplier involvement, pass/fail) are not executable in the control-flow model alone; a post-processing log filter is required.

# 8. Final Self-Critique

1. **Semantic weakness in loop approximation.** Both the process tree and POWL use a structural `LOOP` / `XOR` pattern for the trial cycle, which admits invalid traces (e.g., `Adjust Parameters` after a passing inspection, or exit without ever passing). This is a **semantic** rather than syntax limitation: the model under-constrains the hidden “fail / pass” data condition.
2. **Conservative process-tree overconstraint.** By serializing approvals and supplier consultation before the trial loop, the tree excludes valid high-flexibility traces (e.g., early trial execution while quality review is pending). The defense is explicit (safety over flexibility), but the representational loss is real and affects analytical metrics like average trial-start time.
3. **POWL constructor assumptions.** The POWL code assumes `OperatorPOWL` can contain a `StrictPartialOrder` node (`high_spo`) and that `StrictPartialOrder` nodes can be nested inside operator children. If PM4Py’s runtime validates node types strictly, the `high_spo` nesting may require an alternative representation (e.g., duplicating `qr`/`rr` inside the `XOR` branch with explicit partial-order edges from a wrapper). This is a **construction / API-risk** weakness that could be resolved by runtime inspection of the converted net.
