## 1. Conformance semantics

Classification of observed deviations relies on a strict separation between normative obligations, modeling abstractions, and data provenance. The following categories are used:

- **Forbidden behavior**: Relations explicitly disallowed by the norm (e.g., `Cancel Order -> Dispatch Package`, `Order object_cobirth Payment`, `Sensor Heartbeat -> Invoice`). The norm operates in a closed-world for these edges; any observed instance constitutes a violation regardless of business context, unless a technical exception is formally documented.
- **Missing mandatory behavior**: Expected relations absent within their stated scope (e.g., `Create Order -> Validate Order`, `Pack Package -> Dispatch Package`). Because the norm is open-world outside forbidden/mandatory columns, absence may indicate a genuine gap, an unrecorded intermediate event, or an abstraction mismatch. Classification requires scope verification.
- **Unexpected but unregulated behavior**: Observed relations not covered by the normative specification (e.g., `Manual Compliance Review -> Customer`, `Order object_interaction Customer`). These are benign by default under open-world assumptions. Escalation requires evidence of cross-policy conflict, not mere norm absence.
- **Typical-pattern absence**: Deviations from desirable but non-binding sequences (e.g., `Validate Order -> Close Order`, `Issue Invoice -> Record Payment`). The norm explicitly permits legitimate exceptions (credit notes, write-offs, open credit). Absence is expected and does not imply noncompliance.
- **Likely data-quality error**: Observations with strong technical indicators of pipeline faults rather than process deviations (e.g., `Sensor Heartbeat -> Invoice` via reused numeric ID, `Add Item` count mismatch of 1448 vs 1450). These require ETL remediation, not process intervention.
- **Abstraction mismatch**: Gaps arising from modeling choices, such as interpreting an “eventually expected” business rule as a strictly “directly-follows” constraint. The 2 Orders missing `Create Order -> Validate Order` and the 2 Packages missing `Delivery` edges exemplify this; intermediate or attribute-based evidence may satisfy the normative intent.
- **Insufficient evidence**: Cases where graph summaries cannot distinguish between legitimate business practice and norm violation (e.g., unlabeled unapplied cash, exact origin of the single `Order-Payment` cobirth event). These require transactional logs or stakeholder confirmation.

**Open-world vs. closed-world impact**: The norm is closed-world only for explicitly forbidden relations and mandatory columns within their stated scope. All other observations fall under open-world reasoning: absence from the normative graph does not imply noncompliance, and presence outside the norm does not imply violation. Severity calibration must therefore distinguish between normative breaches (closed-world) and modeling/data artifacts (open-world).

### OC-DFG

It can confirm whether expected transitions occur in the observed order but cannot capture eventual compliance, parallel branches, or attribute-based evidence. The model cannot establish whether these satisfy N1/N4 intent without scope clarification. The danger of interpreting an “eventually expected” rule as a strictly directly-follows constraint is high: it inflates false positives, misclassifies legitimate process variations as violations, and obscures the actual compliance posture. Open-world reasoning must be applied to mandatory gaps unless forbidden status is confirmed.

The OTG model captures object association structures independent of temporal order. It can verify whether required interactions exist (T1, T2) and detect forbidden cobirths (T6). import pm4py
from typing import Dict, Any

def semantic_classify(raw_results: Dict[str, Any], 
                      mandatory_edges: set, 
                      forbidden_edges: set, 
                      typical_edges: set) -> Dict[str, Any]:
    """Separate raw PM4Py diagnostics from semantic classification."""
    classified = {}
    for model_name, diag in raw_results.items():
        classified[model_name] = {
            "raw_diagnostics": diag,
            "semantic_classification": {}
        }
        for edge, count in diag.get("violations", {}).items():
            if edge in forbidden_edges:
                classified[model_name]["semantic_classification"][edge] = "forbidden_violation"
            elif edge in mandatory_edges and count < diag.get("expected_count", 0):
                classified[model_name]["semantic_classification"][edge] = "missing_mandatory"
            elif edge in typical_edges:
                classified[model_name]["semantic_classification"][edge] = "typical_absence"
            else:
                classified[model_name]["semantic_classification"][edge] = "unregulated"
    return classified

forbidden_edges = {("Cancel Order", "Dispatch Package"), ("Order", "Payment", "cobirth"),
