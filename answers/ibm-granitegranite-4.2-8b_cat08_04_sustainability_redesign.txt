### 5. Rebound and displacement risks (6; grounded in trade-offs)
1. **Batching caps (B) vs heat-treat late delivery**: If the max batch wait cap (e.g., 24h for MTO Regular) is set too low relative to typical heat-treat cycle time variability, it could force immediate CNC start for small batches (<12), reducing energy efficiency per item (since energy per item drops at size 12). *Displacement*: heat-treat batch may miss optimal thermal cycle timing, slightly  cycle time for some cases; if heat-treat queue fragments, late delivery risk could rise for borderline cases (though cap aims to prevent >38h waits). *Mitigation*: Use segment-specific caps with buffer (e.g., cap = median batch wait + 1 SD; monitor median wait vs cap weekly; adjust cap quarterly based on actual late delivery trend).
2. **Consolidated trucks (E) vs tight promised lead times**: If a Standard-stock SC order has promised lead time = 20h (slack <24h), consolidation (12–24h wait) would cause late delivery, even though E targets slack 24h. *Displacement*: Operators might default to air for such orders if unaware of consolidation wait, increasing air emissions (rebound: consolidation benefit not realized; air use rises for cases misclassified as "urgent"). *Mitigation*: Always check slack (promised  estimate) *before* suggesting consolidation; if slack <24h, default to ground (per Option A), never consolidate for <24h slack. Logging "consolidation_slot" only for slack 24h prevents this.
3. **Packaging compatibility (D) vs customer urgency perception**: If a Standard-stock SC customer perceives ground delivery as slower (e.g., due to remote site), they might request air despite ground feasibility (slack 12h). *Displacement*: Staff might override D check to use air to satisfy perceived urgency, increasing air emissions and undoing material waste reduction. *Mitigation*: Include brief customer communication at "Package" step (e.g., "Ground delivery meets your promised time; air would add speed but higher emissions. We recommend ground to protect your deadline and environment."). Track override requests via exception log (H); if >5% requests for air when slack sufficient, review communication clarity.
4. **SP1 slack check (A) vs disruption uncertainty**: During a carrier disruption (e.g., truck delay), the estimated processing time might be overestimated (e.g., CNC wait longer), causing slack to appear sufficient for ground but actual ground delivery misses promise. *Displacement*: Using ground per slack check could cause late delivery for some orders during disruption, while air might have been safer. *Mitigation*: Add a "disruption buffer" check: if "expedite_flag" = true *or* recent carrier disruption event (e.g., "truck_delay" observed in last 24h), default to air/van only if slack < threshold (even if slack  threshold normally). Log "disruption_flag" event; monitor late delivery for orders with disruption flag vs ground choice.
5. **Shared lanes (G) vs van coordination**: If shared lanes are not pre-arranged with couriers (e.g., no slot availability), Critical orders with no stock and <24h promise might default to van anyway, wasting the lane effort. *Displacement*: Reduced van usage could increase courier lane congestion if coordination fails, potentially slowing shared lane deliveries and increasing emissions compared to planned van. *Mitigation*: Only activate shared lane replacement for 30% of van usage (as stated); maintain van option for >70% cases; require courier slot confirmation (e.g., "lane_confirmed" event) before switching; if no slot, default to van with justification. Log lane confirmation status; monitor shared lane on-time rate vs van.
6. **Inspection gate (F) vs small urgent batches**: For a MTO Regular case with very tight slack (<12h), the inspection gate might require a retest within the batch, adding <2h wait if inspection misses a small defect. *Displacement*: If the gate triggers retest, cycle time could increase slightly vs rushing inspection and accepting rework later (which often causes second shipment/backorder). *Mitigation*: For cases where promised lead time  estimated processing time < 6h (very tight), allow "inspect_and_package" without gate *only if* inspection certifies "low risk" (1% defect); otherwise proceed to gate. Log "gate_waiver_reason" for tight cases; monitor cycle time for waived vs gated cases; adjust threshold quarterly based on late delivery data.
7. **Exception log (H) vs decision speed**: If managers slow approval for exceptions (e.g., due to frequent reviews), urgent Critical orders might wait longer for van justification, risking service. *Displacement*: Operators might bypass H (log exception) to speed decisions, causing unjustified air/van use and higher emissions. *Mitigation*: Set max approval time for exception log review to 4 hours for Critical; use automated "default to ground" for non-Critical overrides without log (only Critical/Service-contract need log). Log "exception_approval_time"; monitor approval latency; if >4h >10% of cases, simplify justification rules.

> *These risks directly reflect the stated trade-offs (e.g., batch size  energy vs  wait; air protects service vs  emissions; packaging mismatch causes rework). Each has a clear displacement (unintended increase in another impact) and a practical mitigation tied to monitoring (e.g., slack check + disruption buffer, logging flags). Six risks listed cover batching, transport, packaging, customer perception, coordination, and gate speed—addressing all mentioned categories (batching, transport, packaging, rework, obsolescence, customer behavior).*
