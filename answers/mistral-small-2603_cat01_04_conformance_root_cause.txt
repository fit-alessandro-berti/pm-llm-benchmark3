## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels
recorded_labels -> alignment_moves
ETL_change -> recorded_order
recorded_order -> alignment_moves
policy_change -> true_process
true_process -> recorded_labels, recorded_order
true_process -> business_outcomes
normative_model --X alignment_moves
normative_model --X measured_fitness
alignment_moves -> measured_fitness
measured_fitness -> business_outcomes
business_outcomes --> hidden_variables[high_value_status]
```

The conformance collapse arises from a **cascade of logging defects and model obsolescence**, not a real behavioral change. The UI label change (`Classify``Risk Screen`) introduced semantic drift, misaligning traces with the normative model. The addition of `Queue Routed`—a technical event with no business meaning—further distorted the DFG and alignments. The ETL switch to warehouse-ingestion time corrupted event ordering, causing `Notify`/`Decision` reversals. These defects were **amplified by an obsolete normative model** that failed to account for the new `Supervisor Sign-off` policy, leading to spurious deviations when the policy was enforced.

Employee noncompliance is plausible but **not the primary driver**: missing `Compliance Check` events could reflect either bypasses or extraction defects, and stable approval/appeal rates suggest no systemic compliance failure. The **real operational concern** is **data provenance**: inconsistent labeling, unreliable timestamps, and unmodeled technical events created a false signal of nonconformance. Better fitness after label remapping, technical-event removal, and source-sequence ordering confirms that **the process behavior did not change**—only the recording and modeling did.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py
from pm4py.objects.log.util import dataframe_utils
from pm4py.objects.conversion.log import converter as log_converter
from pm4py.objects.process_tree.utils import generic_tree
import pandas as pd

# 1. Encode normative process tree
tree = pm4py.parse_process_tree(
    """->(
        'Receive',
        'Classify',
        X(
            *('Standard Review', 'Request Info'),
            ->('Enhanced Review', 'Compliance Check')
        ),
        'Decision',
        'Notify'
    )"""
)

# 2. Convert to Petri net
net, im, fm = pm4py.convert_to_petri_net(tree)

# 3. Expand variant-frequency tables into logs
def expand_variants_to_log(variant_table):
    log = pm4py.objects.log.log.EventLog()
    for trace_str, count in variant_table.items():
        trace = pm4py.objects.log.trace.Trace()
        for event_str in trace_str.split(','):
            event = pm4py.objects.log.util.event_generator.apply(
                attributes={'concept:name': event_str.strip()}
            )
            trace.append(event)
        for _ in range(count):
            log.append(trace)
    return log

# April-May log
apr_may_variants = {
    'Receive,Classify,Standard Review,Decision,Notify': 380,
    'Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify': 180,
    'Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify': 40
}
log_apr_may = expand_variants_to_log(apr_may_variants)

# June-July log
jun_jul_variants = {
    'Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify': 270,
    'Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify': 145,
    'Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision': 70,
    'Receive,Risk Screen,Standard Review,Decision,Notify': 90,
    'Receive,Classify,Queue Routed,Standard Review,Decision,Notify': 30,
    'Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify': 25,
    'Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify': 20
}
log_jun_jul = expand_variants_to_log(jun_jul_variants)

# August-September log
aug_sep_variants = {
    'Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify': 210,
    'Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify': 150,
    'Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify': 90,
    'Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify': 60,
    'Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision': 45,
    'Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify': 30,
    'Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify': 35
}
log_aug_sep = expand_variants_to_log(aug_sep_variants)

# 4. Discover DFGs
dfg_apr_may = pm4py.discover_dfg(log_apr_may)
dfg_jun_jul = pm4py.discover_dfg(log_jun_jul)
dfg_aug_sep = pm4py.discover_dfg(log_aug_sep)

# 5. Alignment diagnostics
alignments_apr_may = pm4py.conformance_diagnostics_alignments(log_apr_may, net, im, fm)
alignments_jun_jul = pm4py.conformance_diagnostics_alignments(log_jun_jul, net, im, fm)
alignments_aug_sep = pm4py.conformance_diagnostics_alignments(log_aug_sep, net, im, fm)

print("April-May alignment fitness:", sum(a['trace_is_fit'] for a in alignments_apr_may) / len(alignments_apr_may))
print("June-July alignment fitness:", sum(a['trace_is_fit'] for a in alignments_jun_jul) / len(alignments_jun_jul))
print("August-September alignment fitness:", sum(a['trace_is_fit'] for a in alignments_aug_sep) / len(alignments_aug_sep))

# 6. Normalization pipeline: map Risk Screen to Classify and remove Queue Routed
def normalize_log(log):
    for trace in log:
        for event in trace:
            if event['concept:name'] == 'Risk Screen':
                event['concept:name'] = 'Classify'
            if event['concept:name'] == 'Queue Routed':
                trace.remove(event)
    return log

log_jun_jul_norm = normalize_log(log_jun_jul.copy())
log_aug_sep_norm = normalize_log(log_aug_sep.copy())

alignments_jun_jul_norm = pm4py.conformance_diagnostics_alignments(log_jun_jul_norm, net, im, fm)
alignments_aug_sep_norm = pm4py.conformance_diagnostics_alignments(log_aug_sep_norm, net, im, fm)

print("June-July normalized alignment fitness:", sum(a['trace_is_fit'] for a in alignments_jun_jul_norm) / len(alignments_jun_jul_norm))
print("August-September normalized alignment fitness:", sum(a['trace_is_fit'] for a in alignments_aug_sep_norm) / len(alignments_aug_sep_norm))

# 7. Candidate model with optional Supervisor Sign-off
tree_extended = pm4py.parse_process_tree(
    """->(
        'Receive',
        'Classify',
        X(
            *('Standard Review', 'Request Info'),
            ->('Enhanced Review', 'Compliance Check')
        ),
        'Decision',
        'Notify',
        ?('Supervisor Sign-off')
    )"""
)
net_extended, im_extended, fm_extended = pm4py.convert_to_petri_net(tree_extended)

alignments_aug_sep_extended = pm4py.conformance_diagnostics_alignments(log_aug_sep_norm, net_extended, im_extended, fm_extended)
print("August-September extended model alignment fitness:", sum(a['trace_is_fit'] for a in alignments_aug_sep_extended) / len(alignments_aug_sep_extended))

# Caveat: This model cannot enforce the EUR 50,000 condition and may overgeneralize.
```

## 7. Provisional conclusion

The **primary explanation** for the conformance collapse is a **cascade of data-quality defects**: the UI label change (`Classify``Risk Screen`), the introduction of the technical event `Queue Routed`, and the ETL switch to warehouse-ingestion time corrupted the recorded process traces. These defects were **amplified by an obsolete normative model** that failed to account for the new `Supervisor Sign-off` policy. The staged improvements after label mapping, technical-event removal, and source-sequence ordering confirm that **the real process behavior did not change**—only the recording and modeling did.

A **real compliance problem may remain**, but it is not the cause of the conformance drop. The missing `Compliance Check` events in some enhanced-review traces could reflect either bypasses or extraction defects, and the stable approval/appeal rates suggest no systemic failure. However, the policy requiring sign-off for high-value claims introduces a **new operational risk**: if reviewers bypass the sign-off or the model fails to enforce it, compliance could degrade silently.

**Confidence levels**:
- **Data-quality defects**: 90% (strong evidence from alignment improvements and audit).
- **Model obsolescence**: 80% (improved fitness with extended model).
- **Employee noncompliance**: 30% (no direct evidence; stable outcomes suggest otherwise).

**Immediate actions**:
- **IT**: Audit `Queue Routed` source; correct ETL timestamp logic; remap labels in all downstream systems.
- **Process owners**: Update the normative model to include optional `Supervisor Sign-off` and enforce high-value constraints.
- **Compliance**: Conduct a manual audit of cases with missing `Compliance Check` events; stratify by case value to detect policy violations.

**What must not be claimed yet**: That employees are systematically bypassing controls. The evidence does not support this, and better fitness after data repairs suggests the issue is **not behavioral**.

## 8. Model-governance recommendation

1. **Model versioning**: Maintain a versioned repository of normative process trees and Petri nets, with changelogs for every policy or UI change that affects control flow.
2. **Event-semantic contracts**: Require that every new UI label, technical event, or timestamp source is documented in a semantic contract signed by IT, process owners, and compliance before release.
3. **Technical-event policy**: Ban non-business technical events (e.g., `Queue Routed`) from conformance logs unless explicitly modeled and justified.
4. **Timestamp provenance**: Enforce that conformance jobs use source-system timestamps for event ordering; warehouse-ingestion time may only be used for SLA metrics.
5. **Data-aware constraints**: Extend conformance models to include high-value case attributes (e.g., EUR 50,000 threshold) to detect policy violations, not just control-flow deviations.
6. **Post-release validation**: Require a conformance sanity check within 48 hours of any UI, ETL, or policy change, comparing raw and normalized logs against the updated model.
