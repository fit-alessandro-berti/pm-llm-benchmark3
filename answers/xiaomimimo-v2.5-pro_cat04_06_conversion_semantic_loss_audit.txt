# 5. Round-Trip Validation Code

```python
import pm4py
from pm4py.objects.petri_net.utils import reachability_graph
from collections import deque

def bounded_visible_trace_exploration(net, im, fm, max_loop_iterations=2, max_trace_length=20):
    """
    Explore visible traces up to a bound, hiding silent transitions (label=None).
    Returns a set of visible traces (tuple of labels) that are sound.
    """
    # Initial state
    initial_state = (im, tuple())  # (marking, visible_trace_so_far)
    visited = set()
    queue = deque([initial_state])
    visited.add(im)
    visible_traces = set()
    
    while queue:
        marking, trace = queue.popleft()
        
        # Check if we are at a final marking
        if marking == fm:
            visible_traces.add(trace)
            continue
        
        # Get enabled transitions
        enabled = pm4py.get_enabled_transitions(net, marking)
        for t in enabled:
            # Enforce visible-length bound
            if len(trace) >= max_trace_length:
                continue
            
            # Enforce loop iteration bound (heuristic: if label is 'Correct Defect', count occurrences)
            if t.label == "Correct Defect" and trace.count("Correct Defect") >= max_loop_iterations:
                continue
            
            # Fire transition
            new_marking = pm4py.objects.petri_net.semantics.execute(t, net, marking)
            if new_marking is not None:
                if new_marking not in visited:
                    visited.add(new_marking)
                    new_trace = trace if t.label is None else trace + (t.label,)
                    queue.append((new_marking, new_trace))
    
    return visible_traces

# Original net
orig_traces = bounded_visible_trace_exploration(net_from_powl, im_from_powl, fm_from_powl)
print(f"Original net visible traces count: {len(orig_traces)}")

# Compare with round-tripped nets
for name, net, im, fm in nets_round_tripped:
    print(f"\nRound-trip net: {name}")
    rt_traces = bounded_visible_trace_exploration(net, im, fm)
    print(f"Round-trip visible traces count: {len(rt_traces)}")
    
    # Set equality check
    if orig_traces == rt_traces:
        print("Visible traces are exactly equal (under bound).")
    else:
        print("Visible traces differ.")
        # Show symmetric difference
        diff = orig_traces.symmetric_difference(rt_traces)
        if diff:
            print(f"Traces only in one set: {diff}")
    
    # Also check footprints and soundness
    is_wf = pm4py.check_is_workflow_net(net)
    print(f"Is workflow net: {is_wf}")
    sound = pm4py.check_soundness(net, im, fm, print_diagnostics=False)
    print(f"Soundness: {sound}")
    
    # Check if footprints match
    try:
        orig_fp = pm4py.discover_footprints(net_from_powl, im_from_powl, fm_from_powl)
        rt_fp = pm4py.discover_footprints(net, im, fm)
        if orig_fp == rt_fp:

        else:
            print("Footprints differ.")
            print(f"Original: {orig_fp}")

    # Generate reachability graphs (for comparison, but not printing full graph)
```

# 6. Visual-Semantics Review

Even when the converted Petri net is behaviorally correct, the BPMN rendering can be misread due to:

1. **Parallel Gateways**: The concurrency between Assess Risk and Prepare Evidence may be rendered with a parallel gateway, but the layout may place them sequentially, implying order. Similarly, the synchronization before Release Change may be rendered as a join gateway that could be misread as an exclusive merge.

2. **Exclusive Gateways**: The optional Legal Review is an XOR with a silent path. In BPMN, this may be rendered as an exclusive gateway with two branches, but the silent branch might be omitted visually, making it unclear that Legal Review is optional.

3. **Loop Visualization**: The loop structure may be rendered with a loop marker, but the body of the loop (Configure Trial  Inspect Trial) may be drawn in a way that obscures the fact that Correct Defect can occur between iterations. The loop marker might not indicate the minimum of one iteration.

4. **Silent Routing Nodes**: The silent transition in the optional legal branch and any silent transitions introduced by conversion may not be shown, making the control flow ambiguous. For example, the split after Assess Risk (to Optional Legal and Verification) might be rendered without an explicit gateway if silent transitions are hidden.

5. **Apparent Ordering of Graph Layout**: BPMN tools often auto-layout diagrams, which may place nodes in a way that suggests temporal order where none exists (e.g., drawing Optional Legal above Verification, implying it happens first). The lack of an explicit edge between Optional Legal and Verification might be overlooked.

**Proposed Annotations/Documentation**:
- Add labels to gateways indicating their type (e.g., "Parallel Split", "Exclusive Decision").
- Use annotations to explain that Legal Review is optional and that the loop must run at least once.
- Document that Assess Risk and Prepare Evidence can occur in any order.
- Provide a textual narrative alongside the diagram that restates the invariants.

# 7. Rejection Criteria

A conversion result should be rejected or quarantined if:

1. **Unsoundness**: The resulting Petri net or BPMN is not sound (e.g., deadlocks, livelocks, or improper termination).
2. **Loss of required interleaving**: The converted model forbids a valid trace from the source model (e.g., Assess Risk before Prepare Evidence is not allowed).
3. **Admission of invalid traces**: The converted model allows a trace that violates an invariant (e.g., Release Change occurs before Verification Loop completes).
4. **Collapse of optional behavior**: Optional Legal Review becomes mandatory or impossible.
5. **Failed exact-final-marking test**: Round-trip conversion changes the set of reachable final markings.
6. **Loop iteration collapse**: The loop allows zero iterations or forces exactly one iteration.
7. **Silent transition misinterpretation**: Silent transitions are removed or misinterpreted, changing the branching structure.
8. **Concurrency loss**: True concurrency is replaced by arbitrary interleaving that is not behaviorally equivalent.

# 8. Canonical Representation Recommendation

- **Authoritative representation**: The source POWL model should be stored as the canonical representation. It explicitly captures partial order, concurrency, optionality, and loop structure without visualization artifacts.
- **Derivative artifacts**: The Petri net (from direct conversion) and the BPMN (from Petri net) are derivatives. The process-tree intermediate (if successful) is also derivative.
- **Validation evidence**: Each derivative must be accompanied by:
  - Soundness and workflow-net checks.
  - A positive witness trace from the source model that is also valid in the derivative.
  - A negative witness trace from the source model that is invalid in the derivative.
  - A bounded visible-trace equivalence check (under chosen bounds).
- **Process-tree intermediate**: Should not be allowed as a canonical representation because the source partial order is not block-structured, and tree conversion may fail or alter behavior.
- **Future edits**: Edits should be made on the source POWL model, then reconverted to avoid round-trip drift. If edits are made on BPMN, they must be validated against the source invariants.
