## 1. Target definition
**Primary target (operational): unconditional joint incidence under observed policy.** Unit of analysis = one credit **application** (`case:concept:name`). Population = all Applications Started in observation window. Prediction time `t_pred` = time of early prefix: primary `k=3` events or first completion of Credit Review, whichever is earlier, constrained to occur before Accept/Reject/Withdraw/Transfer/Activation. Follow-up window = from `t_pred` until `t_activate+90d+35d feed lag`, with global maturity requiring `case_start + max_activation_lag +90d+35d <= as-of cutoff`.

Event of interest: `E=1` if case is Account Activated **and** Default Recorded within 90 days after activation (feed observed). Competing terminal events: Rejected, Withdrawn, Transferred without linked activation, Activated non-default within 90d. Censored: still-open at extraction, activated but 90d+feed not matured, unlinked transfers, permanently missing feed.

Estimand: cumulative incidence function:
`F_default(h | X_{<=t_pred}) = P( Activate by T_max and T_default - T_activate <=90d | prefix history X_{<=t_pred}, policy _obs )`
This is well-defined for **every** application without counterfactuals. It answers the capacity/loss-triaging question: per 100 early applications with this prefix, how many will become defaulted activated accounts under current selection? It does not label rejected/withdrawn as "non-default"; they are `E=0` for this joint event but belong to distinct competing states.

**Why defensible:** observable without imagining defaults for never-exposed cases; evaluable on full cohort with competing-risk accounting; robust to selection shifts if re-estimated per policy period; directly maps to expected exposure and review prioritization. Conditional default risk alone cannot be applied at `t_pred` because future activation is unknown.

**Credible alternative A - conditional default | eventual activation:** `P(default_90d=1 | Activated, X_{<=t_pred}, _obs)`. Answers underwriting pricing question: among those we would activate, who defaults? Statistically requires correction for selective observation (activation selection on `risk_score`, policy threshold 01-Jul-2025, channel/region). Operationally needs a second activation-probability model to be usable at `t_pred`. Suffers selection bias if trained only on 21,600 mature activated rows.

**Credible alternative B - time to default after activation with right censoring:** `T = days Activation->Default`, censored at 90d, extraction, loss to transfer, or missing feed. Answers when-monitoring/collections timing. Requires survival/competing-risk methods (cause-specific hazard, IPCW). Same selection limitation as A plus delay-censoring, but handles 3,600 immature + 7-35d feed delay correctly instead of dropping them.

Rejected-as-non-default counterfactual `P(default if all activated)` is rejected as primary: fundamentally unidentified without random activation or strong no-unmeasured-confounding + positivity, which fails because rejected cases were never exposed and policy change violates positivity/transportability.

## 2. Cohort construction
**Inclusion:** every `case:concept:name` with first `Application Started` in [2024-01-01, 2025-12-31]. One row per application identifier; linked transfer pairs kept as two linked records with flag, not merged for primary incidence.

**Exclusion:** no exclusion on outcome; exclude from *primary metric evaluation* only cases whose outcome cannot be mature as of as-of cutoff (see as-of rules). No exclusion on short prefixes except handled separately in §4. Duplicate events from migration deduplicated before counting.

**As-of rules:** (a) prefix features use only events with `time:timestamp <= t_pred` and attribute values valid at `t_pred`; (b) cohort status and labels determined as of `CUTOFF = min(data_extract_time=2026-02-15, evaluation cutoff)` requiring `case_start <= CUTOFF - max_activation_lag(assumed 60d, to be estimated) -90d -35d` for maturity-eligible evaluation; (c) `label_available_at` must be `<= CUTOFF`; future feed arrivals after CUTOFF ignored in backtest.

| Cohort flow (N=48,000 starts) | N | % | Analytic role |
|---|---|---|---|
| Mature activated, default observed | 2,700 | 5.6% | Labeled `E=1` for primary joint + conditional |
| Mature activated, non-default observed | 18,900 | 39.4% | Labeled competing `Activated non-default` (`E=0`, distinct class) |
| Activated, 90d/feed not yet matured (incl. delayed 7-35d) | 3,600 | 7.5% | **Censored / not yet mature**; excluded from primary complete-case metric, included with IPCW + landmark sensitivity |
| Rejected and closed | 9,100 | 19.0% | **Competing outcome**, selectively unobserved for conditional default; `E=0` for joint but never "non-default" |
| Withdrawn | 5,700 | 11.9% | **Competing outcome**, selectively unobserved |
| Transferred (2,900 total; ~1,740 linked, ~1,160 unlinked) | 2,900 | 6.0% | **Competing event + missing follow-up mechanism**; linked followed via new ID, unlinked censored at transfer |
| Still-open at extraction (no terminal, no activation) | 5,100 | 10.6% | **Censored**; excluded from primary metric, included in sensitivity/bounds |
| **Total** | **48,000** | **100%** | Primary evaluable mature: 21,600 conditional; ~39,300 mature-eligible for joint minus censored definition per cutoff |
Naive training on 21,600 only = 45% selective subsample; overstates activation rate and misestimates unconditional risk by factor ~2.2.

## 3. Censoring and missing-label strategy
- **Ordinary right censoring:** still-open 5,100 and extraction 2026-02-15 censoring; activated 3,600 where `T_activate+90d > CUTOFF`. Mechanism: administrative, depends on `case_start` calendar time. Handled by maturity eligibility + Inverse-Probability-of-Censoring Weighting (IPCW) and landmark survival.
- **Delayed labels:** external feed +7-35d after 90d horizon; `label_available_at` > horizon. If evaluated before `horizon+35d`, mature defaults appear as non-defaults. Handled by embargo: require `CUTOFF >= T_activate+125d` for definitive label; otherwise treat as censored. Testable: compare delay distribution by calendar, channel, partner vs direct.
- **Selection through activation:** `default_90d` undefined unless Activated under policy . Rejected 9,100 + Withdrawn 5,700 + non-activated Transfers never exposed. Not censoring, not missing at random — undefined outcome. Must not impute 0/1. Handled by primary joint target (no imputation) + secondary conditional model with Inverse-Probability-of-Activation Weighting (IPAW) using prefix + calendar + policy-era instruments.
- **Transfer as competing event or missing follow-up:** 2,900 transfers; 60% linkable to new ID on partner platform, 40% lost. If transfer is terminal diversion, it is competing risk. If case re-activates elsewhere, it is interval-missing follow-up. Primary: treat transfer as competing state at transfer time; sensitivity: link where available, IPCW for linkage probability, worst-case bounds for unlinked.
- **Permanently missing outcome feeds:** partner-originated activated have elevated never-arriving feed (MNAR likely related to default itself/partner IT). Not recoverable by waiting. Primary: flag `source_system=partner`, report stratum-specific incidence among feed-observed + missing-rate; sensitivity: Manski bounds (all-missing=default vs non-default) and pattern-mixture tipping-point.

**Primary analysis:** competing-risk cumulative incidence for joint `Activate+Default` on maturity-eligible cohort, with administrative censoring weights and calendar stratification (pre/post 01-Jul-2025). Conditional default|activation reported only within activated-mature stratum with IPAW diagnostic.

**Sensitivity analyses:** (1) IPCW + IPAW weighted estimators; (2) worst-case bounds for unlinked transfers + partner missing feed; (3) time-to-default Cox/competing-risk landmark from activation.

**Testability:** delay and censoring MAR conditional on start date/source — partially testable via observed delay vs covariates and pre/post comparison. Selection on observables — partially testable via overlap/positivity checks across policy eras, but selection on unobservables (officer soft info, applicant intent) and counterfactual default-if-rejected — fundamentally untestable from these data; requires activation experiment or strong structural assumptions to be labeled as such.

## 4. Prefix extraction
No future lookahead: prefix `P(k,)` = ordered events with `timestamp <= t_pred` where `t_pred = min(time of k-th event, case_start+)`. Primary business prefix: `k=3` fixed-length + `=72h` elapsed-time variants evaluated separately; report `k=1..5` curve to show earliness-accuracy tradeoff. Implementation filters event table on timestamp before any aggregation; nightly `documents_total` recomputed as-of `t_pred` date exclusive of same-day later uploads; `risk_score` taken as last value with timestamp `<=t_pred`.

**Short cases:** cases terminating (Reject/Withdraw/Transfer/Accept) before `k` have no `k`-prefix under that definition. Do not pad with future terminal events. Options: (a) evaluate `k`-model only on cases still active at `k` (report denominator shrinkage explicitly); (b) carry forward terminal state as separate early-exit stratum for joint target. Chosen: (a) + report coverage (% still active at each k) to avoid survivorship bias.

**Repeated document loops:** `Credit Review -> Request Documents -> Credit Review` cycles collapsed to counts: `n_review_loops`, `loop_time`, not as distinct variants for modeling; variant analysis keeps full loop-expanded variant for discovery but model uses loop-count + time features to avoid sparsity.

**Activity renaming 15-Oct-2025:** build canonical mapping (e.g., `ID Check`/`KYC Check` -> `Identity/KYC Check`) from DFG + variant diff pre/post migration; deduplicate events with same case+canonical activity+resource within 5 min (migration duplicates); add `era=pre/post-migration` and `migrated_name_flag` features; validate model separately post-migration; never use post-`t_pred` canonical info learned from future.

## 5. Process-aware features
All computed strictly from `<=t_pred` slice; historical-reference features computed from cases active at `t_pred` (as-of join), not from full-file aggregates.

**Static case attributes (known at start):** `case:channel`, `case:region`, `case:requested_amount`, weekday/hour of Application Started, policy-era at start (pre/post 01-Jul-2025), source_system direct vs partner-originated.

**Prefix-derived (control-flow/timing/rework):** prefix length actually observed, elapsed `t_pred - case_start`, last activity + prior bigram, variant-prefix id (from `get_variants` on truncated log), n_events, n_distinct activities, n_Credit Review entries, n_document loops, time in Credit Review, mean/sojourn times, time since last event, after-hours flag, `risk_score` at start + at `t_pred` + delta (only `<=t_pred` values), rework rate, handoff count.

**Resource/queue (requires as-of history):** current resource role (not future experience), number of distinct resources so far, queue length = number of other cases with started but no terminal event at `t_pred`, median waiting time of recently completed Credit Reviews at same region/channel (trailing 30d, strictly before `t_pred`), insert service/waiting split where justified.

**Cohort/calendar:** days from policy change, days from migration, monthly application volume trend, region-channel activation base rate in trailing window before `t_pred` (for IPAW diagnostics, not as naive default predictor).

Historical-reference-needed: queue length, trailing waiting times, trailing activation rates, resource experience-as-of-event (reconstructed from HR history, not extraction-time value). All else is static or prefix-local.

## 6. Leakage audit
| Feature or data element | Leakage or bias risk | Valid availability rule | Keep/repair/drop | Rationale |
|---|---|---|---|---|
| `final_limit` | High: populated only after final credit decision, encodes Accept + creditworthiness | Only if timestamp of decision `<=t_pred` (never for early prefix) | **Drop** for early model | Post-decision; conditions on selection, leaks activation |
| `decision_reason` | High: at/after Accept/Reject, perfect proxy of competing outcome | Require event time `<=t_pred` | **Drop** | Determines terminal state; unavailable early |
| `collection_status` | Critical: updated after activation, directly reveals default | Never `<=t_pred` for pre-activation prefix | **Drop** | Target leakage; defines outcome |
| Future events: Contract Signed, Account Activated, Collections Contact, Default Recorded | Critical: occur after `t_pred`, define outcome/selection | Exclude any event with `timestamp > t_pred` from features/prefixes | **Drop** | Classic temporal leakage; prediction must precede them |
| `documents_total` (nightly snapshot) | Medium: same-calendar-day later uploads included | Recompute count of uploads with `upload_time <= t_pred`, not snapshot date | **Repair** | Snapshot violates as-of; repair to event-time |
| Updated `risk_score` | Medium: later updates encode review outcome/trajectory to default | Use last value with `timestamp <= t_pred` only; delta from start to `t_pred` | **Repair** | Future updates leak selection/outcome evolution |
| Resource experience (extraction-time) | Medium: uses future tenure/promotions; biased for early events | Join HR history as-of event time; if unavailable use role/tenure bucket at `t_pred` or drop | **Repair or drop** | Lookahead bias; experience at extraction  at event |
| Label availability: `default_90d`, `label_available_at` | Critical: missing for rejected/withdrawn/open/immature; delayed 7-35d | Label may never enter features; split/evaluate only when `label_available_at <= cutoff` and mature | **Drop from X; gate for y** | Including mimics selection; premature use creates false negatives |
| `source_system`, `data_extract_time` | Low-medium: partner flag predicts permanent missingness; extract time is post-hoc | `source_system` at start keep as covariate + missingness stratifier; `data_extract_time` drop | **Keep source, drop extract time** | Partner missingness is MNAR signal to stratify, not to impute |
| `time:timestamp` derived horizons | Medium: horizon length correlates with start date maturity | Use elapsed-since-start/pred only, plus calendar era flags; never use distance to extraction | **Repair** | Prevents learning administrative censoring as risk |

Automated check: assert no feature column has max event time `> t_pred`; assert banned list absent; assert `documents_total` recomputed; fail pipeline otherwise.

## 7. Validation design
**Why not random split:** random case split mixes pre/post 01-Jul-2025 policy (different selection `P(Activate|X)` and `P(Default|X,Activate)`), mixes pre/post 15-Oct-2025 vocabulary/duplicates, and mixes mature with immature/delayed labels, leaking future policy knowledge backward and overstating calibration/AUC. It also breaks as-of queue features (future cases in reference set).

**Temporal backtesting (primary):** split by `case_start`: Train 2024-01-01–2024-12-31, Validation 2025-01-01–2025-06-30 (pre-policy, pre-migration), Test-1 2025-07-01–2025-10-14 (post-policy, pre-migration), Test-2 2025-10-15–2025-12-31 (post-policy + migration, maturity-limited). Enforce maturity embargo: evaluate Test only on cases with `start <= evaluation_cutoff -60d -90d -35d`; later starts reported as censored-coverage diagnostic. Rolling-origin update: refit quarterly; report degradation across policy/migration boundaries. Mention `pm4py.split_train_test` only as convenience baseline to demonstrate optimism gap, not for decisions.

**Label maturity handling:** backtest cutoff simulated (e.g., pretend extraction 2025-10-01 for validation) so delayed feeds after cutoff treated as censored; compare complete-case vs IPCW metrics.

**Metrics:** primary joint incidence: PR-AUC / average precision (rare joint event ~5-6% unconditional), Brier score + calibration slope/intercept + binned calibration curve, cumulative-incidence calibration by decile, multiclass log-loss/Brier over {default-activation, non-default-activation, rejected, withdrawn, transferred, censored}. Conditional default|activated secondary: ROC-AUC, AUPRC, IPCW-weighted Brier, calibration within activated. Time-to-default: IPCW C-index + calibration at 90d. Subgroups: channel, region, requested_amount band, partner vs direct, policy era, migration era; report shift in activation rate, default rate, and calibration. Distribution-shift diagnostics: PSI/KS on prefix features, DFG drift pre/post, activation-rate control chart.

## 8. Limitations and decision-use boundary
**Can claim:** under observed activation policy _obs and calendar era, applications with early prefix X had observed joint incidence F of activation-plus-90d-default; ranking and calibrated probabilities for triage/review prioritization within era; competing-outcome distributions for capacity planning. Conditional default claims only as "among activated under _obs" with selection caveat.

**Cannot claim:** causal or counterfactual individual default risk if a rejected/withdrawn case had been activated; that Reject causes lower default; that deploying the score will reduce defaults by the predicted amount; transportability to a stricter/looser policy or new partner mix without revalidation. Association  selection-adjusted risk  causal effect.

**Deployment can change DGP (3):** (1) Acting on scores (extra review, lower limits, rejection of flagged early prefixes) changes activation selection and outcome prevalence — prevention paradox and selective-label feedback making flagged group appear lower-risk. (2) Policy/threshold tuning in response to model (e.g., tightening after 2025-07-01 precedent) shifts positivity and invalidates conditional calibration. (3) Behavioural gaming/channel shift — applicants/resources reroute to partner platform or alter document timing, changing prefix distributions and transfer/missingness rates. (4) Capacity effects — prioritizing flagged cases alters queue/waiting times, which are themselves predictors, creating performative drift. Use requires monitoring, holdout non-intervened sample, and policy-versioned models with decision-use limited to triage + human review, not auto-reject, with explicit era labels.

## 9. PM4Py-oriented Python implementation skeleton
```python
import pandas
import pm4py
from datetime import timedelta

CUTOFF = pandas.Timestamp("2026-02-15")  # data_extract_time
FEED_LAG = timedelta(days=35)  # max 7-35d delay; assumption
HORIZON = timedelta(days=90)  # default_90d horizon
MAX_ACT_LAG = timedelta(days=60)  # start->activation; ASSUMPTION: estimate empirically
POLICY = pandas.Timestamp("2025-07-01")
MIGRATION = pandas.Timestamp("2025-10-15")
K = 3  # primary fixed prefix length

# 1. Load; parse timestamps (assumption: UTC, no mixed tz)
df = pandas.read_csv("applications_events.csv", parse_dates=["time:timestamp", "label_available_at", "data_extract_time"])
df = pm4py.format_dataframe(df, case_id="case:concept:name", activity_key="concept:name", timestamp_key="time:timestamp")
df = df.sort_values(["case:concept:name", "time:timestamp"])
# 2. Canonical activity map for 15-Oct-2025 migration + dedup (assumption: 5-min dup window)
canon = {"ID Check": "Identity/KYC Check", "KYC Check": "Identity/KYC Check", "KYC review": "Credit Review"}
df["concept:name"] = df["concept:name"].replace(canon)
df = df.drop_duplicates(subset=["case:concept:name", "concept:name", "time:timestamp", "org:resource"])
# 3. Case-level as-of status: start, activation, terminal, censoring, maturity
TERMINAL = {"Rejected", "Withdrawn", "Transferred", "Account Activated", "Contract Signed"}
def case_status(g):
    start = g["time:timestamp"].min()
    act = g.loc[g["concept:name"] == "Account Activated", "time:timestamp"].min()
    term_rows = g[g["concept:name"].isin(["Rejected", "Withdrawn", "Transferred", "Account Activated"])]
    term = term_rows["time:timestamp"].min() if len(term_rows) else pandas.NaT
    term_act = term_rows.loc[term_rows["time:timestamp"].idxmin(), "concept:name"] if len(term_rows) else None
    lab = g["default_90d"].dropna().iloc[-1] if g["default_90d"].notna().any() else pandas.NA
    lab_at = g["label_available_at"].max()
    mature_date = (act + HORIZON + FEED_LAG) if pandas.notna(act) else (start + MAX_ACT_LAG + HORIZON + FEED_LAG)
    mature = mature_date <= CUTOFF and pandas.notna(lab_at) and lab_at <= CUTOFF
    return pandas.Series({"start": start, "t_activate": act, "t_terminal": term, "terminal": term_act, "label": lab, "mature": mature})
cases = df.groupby("case:concept:name").apply(case_status, include_groups=False).reset_index()
print(cases["terminal"].value_counts(dropna=False))  # cohort counts; still-open = NaT terminal
print("mature rate:", cases["mature"].mean())
# 4. Temporal split by case start (primary); random split only as baseline illustration
def era(s):
    if s < "2025-01-01": return "train"
    if s < POLICY: return "valid"
    if s < MIGRATION: return "test_post_policy"
    return "test_post_migration"
cases["split"] = pandas.to_datetime(cases["start"]).apply(era)
# NOTE: pm4py.split_train_test mentioned only as convenience baseline; NOT used for decisions.
# 5. Process discovery on train only (justify: vocabulary/drift audit, not features)
log_train = pm4py.convert_to_event_log(df[df["case:concept:name"].isin(cases.query("split=='train'")["case:concept:name"])])
dfg, start_a, end_a = pm4py.discover_dfg(log_train)
variants = pm4py.get_variants(log_train)  # inspect document loops + migration renames
# 6. Fixed-length prefixes without future (demonstrate get_prefixes_from_log)
prefix_log = pm4py.get_prefixes_from_log(log_train, length=K)  # K-event prefixes, train only
pref_df = pm4py.convert_to_dataframe(prefix_log)
# Elapsed-time prefix alternative: truncate each case at start+72h
case_start = df.groupby("case:concept:name")["time:timestamp"].transform("min")
df_72h = df[(df["time:timestamp"] - case_start) <= timedelta(hours=72)].copy()
# 7. Feature table strictly <= t_pred (prevent post-prefix leakage)
t_pred = df.groupby("case:concept:name")["time:timestamp"].nth(K - 1)  # K-th event time; short cases -> NaT
feat = []
for case, g in df.groupby("case:concept:name"):
    tp = t_pred.loc[case]
    if pandas.isna(tp): continue  # short-case handling: excluded from K-model denominator; report coverage
    h = g[g["time:timestamp"] <= tp]  # as-of slice
    last_risk = h["risk_score"].dropna().iloc[-1] if h["risk_score"].notna().any() else None
    feat.append({"case": case, "t_pred": tp, "n_events": len(h), "last_act": h["concept:name"].iloc[-1],
                 "elapsed_s": (tp - h["time:timestamp"].min()).total_seconds(),
                 "n_review": (h["concept:name"] == "Credit Review").sum(), "risk_at_pred": last_risk,
                 "channel": h["case:channel"].iloc[0], "region": h["case:region"].iloc[0]})
X = pandas.DataFrame(feat).merge(cases, left_on="case", right_on="case:concept:name", how="left")
# Temporal features helper (justified: timing/waiting audit on prefix slice only)
# tfeat = pm4py.extract_temporal_features_dataframe(pref_df)  # optional timing enrichment
# 8. Leakage-audit check: banned post-decision/outcome columns must not enter X
BANNED = ["final_limit", "decision_reason", "collection_status", "default_90d", "label_available_at", "data_extract_time"]
assert not any(c in X.columns for c in BANNED), "leakage: banned column in features"
assert "documents_total" not in X.columns, "repair documents_total to upload_time<=t_pred first"
print("leakage check passed; feature rows:", len(X))
# 9. Connect survival/competing-risk modeling later (do NOT fabricate pm4py survival API):
# Merge X[mature] -> lifelines/skill-survival: joint incidence (multinomial/IPCW) + conditional Cox for T=activate->default.
```
