## 3. Causal-abductive explanation

```text
UI_release        -> recorded_labels
recorded_labels   -> alignment_moves
ETL_change        -> recorded_order
recorded_order    -> alignment_moves
recorded_labels   -> measured_fitness (-)
recorded_order    -> measured_fitness (-)
event_gateway     -> recorded_labels (Queue Routed)
recorded_labels   -> measured_fitness (-)
policy_change     -> normative_model (gap)
normative_model   -> measured_fitness (-) on Aug-Sep
true_process      -> business_outcomes
business_outcomes -> (no change observed)
reviewer_behavior -> true_process (small residual)
true_process      -> recorded_labels (mostly)
hidden: extraction_pipeline_delay, attribute_HV_available
```

Three independent mechanisms stack. The 2026-05-31 UI relabel changes the *labels* the conformance checker sees but not the underlying activity. The 2026-06-03 event-gateway addition injects a technical `Queue Routed` event between risk screening and review for most cases. The 2026-06-15 ETL switch to warehouse-ingestion time scrambles `Decision` and `Notify` for cases where ingestion lags the source sequence. Each alone degrades fitness; together they explain why raw fitness collapsed from 93% to 32%. The staged remediation—label map, technical-event removal, source ordering—recovers most of the loss (89%), confirming these as dominant causes and leaving only a small residual (11%) that contains genuine Enhanced-Review-without-Compliance-Check traces. The 2026-08-01 supervisor sign-off policy introduces a real new control step that the normative tree does not encode; an extended model with optional sign-off improves fitness for Aug-Sep. Stable approval and appeal rates argue against a system-wide behavior change, and the residual bypass signal is too small and not yet audit-validated to support a noncompliance narrative. Unchanged outcomes therefore neither confirm pure data error nor exclude a focused compliance concern: the metrics are insensitive to small sub-population effects, and the audit population for the suspected bypass is unresolved.

## 6. PM4Py reproduction and model-comparison code

```python
import pandas as pd
from pm4py.objects.log.importer.csv import pandas_utils
from pm4py.objects.process_tree import parser as pt_parser
from pm4py.objects.conversion.process_tree import converter as pt_converter
from pm4py.objects.log.importer.variants import pandas_csv_import
from pm4py.algo.discovery.dfg import algorithm as dfg_discovery
from pm4py.algo.evaluation.replay_fitness import algorithm as fitness_evaluator
from pm4py.algo.evaluation.precision import algorithm as precision_evaluator
from pm4py.objects.log.util import dataframe_utils
from pm4py.objects.log.importer.variants.pandas import importer as pandas_importer
from pm4py.objects.log.obj import EventLog, Trace

def expand_variants(variant_counts):
    log = EventLog()
    for trace_str, n in variant_counts:
        acts = [a.strip() for a in trace_str.split(",")]
        for _ in range(n):
            t = Trace()
            for a in acts:
                ev = {"concept:name": a, "time:timestamp": pd.Timestamp("2026-01-01")}
                t.append(ev)
            log.append(t)
    return log

apr_may = [
    ("Receive,Classify,Standard Review,Decision,Notify", 380),
    ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
    ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40),
]
jun_jul = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
    ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
    ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
]
aug_sep = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),
]

log_apr = expand_variants(apr_may)
log_jun = expand_variants(jun_jul)
log_aug = expand_variants(aug_sep)

# Normative tree
tree_str = "-> ( 'Receive', 'Classify', X ( * ( 'Standard Review', 'Request Info' ), -> ( 'Enhanced Review', 'Compliance Check' ) ), 'Decision', 'Notify' )"
norm_tree = pt_parser.parse_process_tree(tree_str)
norm_net, im, fm = pt_converter.apply(norm_tree)

def normalize(log, map_labels=True, drop_tech=True):
    out = EventLog()
    tech = {"Queue Routed"}
    mapping = {"Risk Screen": "Classify"}
    for tr in log:
        new = Trace()
        for ev in tr:
            name = ev["concept:name"]
            if drop_tech and name in tech:
                continue
            if map_labels and name in mapping:
                name = mapping[name]
            new.append({"concept:name": name, "time:timestamp": ev["time:timestamp"]})
        out.append(new)
    return out

def fit(log, net, im, fm):
    if len(log) == 0:
        return None
    return fitness_evaluator.apply(log, net, im, fm, variant=fitness_evaluator.Variants.TOKEN_BASED)

def prec(log, net, im, fm):
    if len(log) == 0:
        return None
    return precision_evaluator.apply(log, net, im, fm, variant=precision_evaluator.Variants.TOKEN_BASED)

def dfg(log):
    if len(log) == 0:
        return {}
    return dfg_discovery.apply(log)

print("== Apr-May (raw vs normative) ==")
print("fitness", fit(log_apr, norm_net, im, fm))
print("DFG edges:", len(dfg(log_apr)))

print("== Jun-Jul raw ==")
print("fitness", fit(log_jun, norm_net, im, fm))

print("== Jun-Jul label-mapped ==")
log_jun_lbl = normalize(log_jun, map_labels=True, drop_tech=False)
print("fitness", fit(log_jun_lbl, norm_net, im, fm))

print("== Jun-Jul label+tech ==")
log_jun_full = normalize(log_jun, map_labels=True, drop_tech=True)
print("fitness", fit(log_jun_full, norm_net, im, fm))
print("DFG edges:", len(dfg(log_jun_full)))

print("== Aug-Sep raw ==")
print("fitness", fit(log_aug, norm_net, im, fm))

print("== Aug-Sep normalized ==")
log_aug_n = normalize(log_aug, map_labels=True, drop_tech=True)
print("fitness", fit(log_aug_n, norm_net, im, fm))

# Candidate model with optional Supervisor Sign-off
candidate_str = "-> ( 'Receive', 'Classify', X ( * ( 'Standard Review', 'Request Info' ), -> ( 'Enhanced Review', 'Compliance Check' ) ), ?( 'Supervisor Sign-off' ), 'Decision', 'Notify' )"
cand_tree = pt_parser.parse_process_tree(candidate_str)
cand_net, cim, cfm = pt_converter.apply(cand_tree)

print("== Aug-Sep normalized + candidate model ==")
print("fitness", fit(log_aug_n, cand_net, cim, cfm))
print("precision", prec(log_aug_n, cand_net, cim, cfm))

print("\nCaveats:")
print("- Aggregated variants cannot reproduce exact aggregate alignment costs; ordering step is simulated.")
print("- Optional Supervisor Sign-off is control-flow only and cannot enforce EUR 50k data condition.")
print("- An overpermissive optional model can raise fitness while lowering precision; always inspect precision.")
print("- Source-sequence ordering requires the original timestamped log; not reproducible from aggregate strings.")
```

## 7. Provisional conclusion

The measured conformance collapse from 93% (Apr-May) to 32% (Jun-Jul) is primarily an artifact of three independent logging changes, not a real operational deterioration: the UI relabel of `Classify` to `Risk Screen` on 2026-05-31, the new `Queue Routed` gateway event on 2026-06-03, and the 2026-06-15 ETL switch to warehouse-ingestion time. The staged recovery to ~89% under label mapping, technical-event removal, and source-sequence ordering quantifies that contribution: roughly 60+ percentage points of the Jun-Jul fitness drop are explained without invoking reviewer behavior. Confidence in this primary explanation: high (~85%).

A real compliance concern cannot be excluded. The 25 (Jun-Jul) and 30 (Aug-Sep) Enhanced Review traces without a recorded Compliance Check are consistent with a small genuine bypass population, but the available evidence is insufficient to distinguish them from extraction gaps. Confidence in "real compliance problem exists": low-to-moderate (~25%); the bypass signal is plausible but unverified. The August-Sep drop is further explained by model obsolescence: the 2026-08-01 Supervisor Sign-off policy is real and not represented in the normative tree; adding an optional sign-off step restores Aug-Sep fitness from 66% to 86%, and this step is policy-required for cases above EUR 50,000 — a fact the control-flow-only model cannot enforce.

Immediate actions: (IT) revert the conformance job to use source-system sequence numbers and tag technical events with an `is_technical` flag; restore label-mapping in the conformance configuration. (Process owners) update the normative tree to reflect Supervisor Sign-off, scoped by the EUR 50,000 attribute; document `Manual Override` as a first-class activity. (Compliance) commission a targeted audit of the 55 Enhanced-Review-without-Compliance-Check traces, prioritized by reviewer and case value.

It must not yet be claimed that (a) reviewers are noncompliant, (b) the model is fundamentally wrong, or (c) the underlying process has deteriorated. Stable KPIs, staged remediation, and lack of audit confirmation argue against all three.

## 8. Model-governance recommendation

1. **Versioned normative models.** Every policy change (e.g., 2026-08-01 Supervisor Sign-off) must trigger a new versioned normative process tree with an effective date, owner sign-off, and diff against the prior version. Models used for conformance must be pinned by version; old models must remain queryable for historical replay.
2. **Event-semantic contracts.** Activity labels in source systems must be governed by a contract: a UI or gateway change that alters a label or inserts an event must be reviewed by process mining before conformance scoring resumes. The contract defines label synonyms, deprecation, and supersession.
3. **Technical-event policy.** Every event recorded in the event log must carry an `event_type` attribute distinguishing `business`, `technical`, and `system` events. Conformance jobs must filter or down-weight technical events by default, with explicit opt-in to include them.
4. **Timestamp provenance.** Each event must carry both source-system sequence/order information and the recorded timestamp; ETL must preserve the source ordering. Conformance checks must use the source order by default and surface any reliance on ingestion time as an explicit, reviewed configuration.
5. **Data-aware constraints.** Normative models used in regulated processes must encode data conditions where relevant (e.g., "Supervisor Sign-off required if claim_value > 50000") using declarative guards or a parallel attribute-stratified conformance job. Control-flow-only optionality must be flagged as insufficient.
6. **Post-release validation.** Any release touching the UI, event gateway, or ETL must trigger a four-phase validation pipeline (provenance check, normalized conformance, model comparison, stratified audit) before the conformance KPI is reported. The validation output, including the chosen preprocessing, must be attached to the release record.
