## 2. Process-model consistency checks

To ensure predictions respect process constraints at t0, we implement the following validation suite:

1.  **Prefix-time availability checks:**
    *   Verify that every feature has a valid timestamp  t0.
    *   Reject any feature populated at closure, extraction, or later.
    *   **Role:** Prevents future leakage.
    *   **Limitation:** Requires rigorous feature-store timestamping.

2.  **Activity-order feasibility checks:**
    *   Validate that sequence patterns respect the normative DAG (e.g., `Damage Assessment` before `Settlement Decision`).
    *   Reject patterns that imply closed cases at t0.
    *   **Role:** Causal process alignment.
    *   **Limitation:** Fails if log data has errors (e.g., missing sequence indices).

3.  **Same-timestamp ambiguity checks:**
    *   When events share a timestamp (e.g., Z: `Claim Closed` and `Damage Assessment`), enforce sequence index priority.
    *   If index missing, mark as ambiguous/unusable.
    *   **Role:** Disambiguation of parallel events.
    *   **Limitation:** Cannot recover lost ordering without re-processing logs.

4.  **Complete-trace vs. prefix-trace checks:**
    *   Detect if an aggregation (e.g., `full_trace_variant_id`) depends on post-t0 events.
    *   Force recomputation restricted to log prefix up to t0.
    *   **Role:** Temporal soundness.
    *   **Limitation:** Increases compute complexity for training.

5.  **Repeat Decision semantic checks:**
    *   Ensure `Settlement Decision Recorded` logic distinguishes first decision from reconsideration.
    *   **Role:** Corrects for appeal semantics.
    *   **Limitation:** Requires explicit flagging in event logs.

These checks ensure explanations reflect what the model *could* have known at t0, not what is known post-closure.

## 5. Recommendations for explanation validation

1.  **Feature Store Design:** Implement point-in-time correct feature tables. Every feature must have a `valid_from` and `valid_to` timestamp aligned with `t0`.
2.  **Historical Feature Timestamps:** Enforce a rule where `feature_timestamp <= t0`. Automatically flag or reject features missing timestamps.
3.  **Prefix-only Recomputation:** For training, recompute all aggregations (e.g., counts, variants) using only events preceding each training instance's `t0`.
4.  **Process-conformance Tests:** Integrate static analysis to check explanations against normative process models (e.g., BPMN or DFG).
5.  **Calibration After Feature Removal:** Retrain and recalibrate models after removing leakage features to ensure performance is not artificially inflated.
6.  **Proxy/Fairness Analysis:** Audit features like `claimant_region` for disparate impact before deployment.
7.  **Schema and Process Drift Monitoring:** Monitor changes in event sequences and timestamps to detect when process rules change (e.g., new fraud triggers).
