# 1. Assumptions and notation

Notation (all times 2026-05-12, minutes unless stated): `a_i` external arrival, `s1s_i/s1e_i` S1 start/end, `s2s_i/s2e_i` S2 start/end, `T_END` = 14:00, window length `T` = 360 min. "Queue entry" for S1 is `a_i`; for S2 it is `s1e_i` (given). I1/I2 are the S1 resources, C1/C2 the S2 resources.

- **A1 – Event-order / tie convention.** All stamps sit on a 5-minute grid, so ties are frequent. At an identical rounded instant `t`, completions/departures are processed before starts/arrivals, and any state is a half-open interval `[from, to)`: a case is "in state" at `t` iff `from <= t < to`. Consequences: (i) P07 ending on C1 at 11:00 and P09 starting on C1 at 11:00 is not a resource conflict; (ii) the WIP value at `t` is read after both the departure and the arrival at `t` have been applied; (iii) clock-hour bins are `[h:00, h+1:00)` (e.g., P08 arriving 09:00 belongs to the 09:00 hour; P01 finishing S2 at 09:00 counts as a 09:00-hour completion). This convention is needed because the alternative (start-before-end) would create apparent overlaps that the scenario says are artefacts.
- **A2 – Rounding.** A reported time `t` stands for a true time in `[t-2.5, t+2.5]`. Any duration built from two stamps therefore has an error in `(-5, +5)` min: a reported 0-min gap can be a true overlap of up to 5 min, a reported 5-min wait can be 0–10 min. Point estimates use reported values; sums of `n` durations get a worst-case band of `±5n` and, assuming independent uniform rounding errors (A2b), an approximate 2σ band of `±2·2.04·√n` min. Rounding does not change any ordering conclusion that rests on gaps ≥ 10 min.
- **A3 – Capacity.** I1, I2, C1, C2 are single-task servers. S1 capacity is 2 throughout. S2 capacity is 2 except 10:55–11:10 (C2 maintenance), when it is 1. C2 available time is 345 min, all others 360 min. No case bypasses a station.
- **A4 – Queue discipline is not assumed.** FIFO is tested, not imposed. The bounds for MISSING starts use only physical constraints (single-task resource, nonnegative service, queue entry), never FIFO.
- **A5 – MISSING start bounds.** For a MISSING start on resource `r`: `lower = max(queue entry, end of the previous recorded task on r)`, `upper = own end` (zero service). This gives P07 S1 ∈ [09:25, 10:00], P15 S1 ∈ [11:40, 12:15], P05 S2 ∈ [09:45, 10:15], P11 S2 ∈ [12:00, 12:25].
- **A6 – Central imputation = previous task end on the same resource + 5 min.** Justification: of the 28 fully observed consecutive task pairs on the four resources (excluding the maintenance pair), 26 have a gap of exactly 5 min, one has 0 min (C1 11:00) and one has 10 min (C2 13:20→13:30). A 5-min changeover after the previous task is by far the best-supported single value; the full feasible range is still carried through as lower/upper scenarios (Section 6).
- **A7 – Two utilization definitions.** "Service utilization" counts only recorded (or imputed) service; the systematic 5-min gaps are idle/changeover. "Occupied utilization" additionally counts those 5-min gaps as occupied (they are plausibly unlogged handling/changeover). Both are reported because the truth is unknown.
- **A8 – OPEN activities** (P15 S2 from 13:30, P17 S2 from 13:55, P21 S1 from 13:30) contribute *elapsed* service up to 14:00 (30, 5, 30 min) to busy time and WIP. Elapsed service is a lower bound of final service; final service is never estimated except inside the explicitly labelled projection in Section 6, which uses station-typical values (S1 30, S2 40).
- **A9 – Blanks are censored waits.** Blank S2 for P16, P18, P19, P20: waiting for S2 from `s1e_i` to at least 14:00 (lower bounds 85, 50, 35, 15). Blank S1 for P22: waiting for S1 from 12:10, ≥ 110 min. Their in-window waiting time is included in queue-length and WIP curves; they are never dropped.
- **A10 – Right censoring of case statistics.** Means over "completed cases only" are biased low because the eight unfinished cases are the latest, longest ones. Every completed-only figure is accompanied by an all-arrivals lower bound and, where useful, a labelled projection.
- **A11 – External arrival stamps** are treated as accurate to ±2.5 min like all others, and as the moment the case became available for S1. That P22 is still waiting at 14:00 while I2 has been idle since 13:45 is treated as an anomaly (Section 5), not as a reason to discard the record.
- **A12 – Analysis window.** Only 08:00–14:00 is analysed; nothing is inferred about work before 08:00 (the log shows the system empty at 08:00: first arrival 08:00, first S1 start 08:05).

# 2. Reconstruction method and formulas

Case-level quantities (per case `i`, station `k`):

- S1 wait `W1_i = s1s_i - a_i`; S1 service `S1_i = s1e_i - s1s_i`; S1 sojourn `T1_i = s1e_i - a_i = W1_i + S1_i`. Note `T1_i` does **not** depend on the missing start; only the split between wait and service does.
- S2 wait `W2_i = s2s_i - s1e_i`; S2 service `S2_i = s2e_i - s2s_i`; S2 sojourn `T2_i = s2e_i - s1e_i`.
- Case sojourn (completed cases) `TT_i = s2e_i - a_i = T1_i + T2_i`; again independent of missing starts.
- OPEN: elapsed service `E_i = 14:00 - start`; final service `≥ E_i`. Blank: censored wait `≥ 14:00 - queue entry`.
- Missing start `x`: feasible `[x_lo, x_hi]` (A5); wait range `[x_lo - entry, x_hi - entry]`, service range `[0, x_hi - x_lo]`; central per A6. Rounding widens every range by up to 5 min at each end (A2).

Station-level quantities, computed on the 5-min grid `t = 08:00, 08:05, …, 13:55` (each point represents `[t, t+5)`, so a mean over grid points is an exact time average under A1):

- Queue length `Q_k(t) = #{i : entry_k,i <= t < start_k,i}` (start = 14:05 sentinel for blanks).
- In service `N_k(t) = #{i : start_k,i <= t < end_k,i}` (end = 14:00 for OPEN).
- Station WIP `L_k(t) = Q_k + N_k`; total WIP `L(t) = L_1(t) + L_2(t) = #{arrived, not yet finished S2}`.
- Throughput/arrival rates: counts of `a_i`, `s1e_i` (= S2 arrivals), `s2e_i` per bin, divided by bin length.
- Busy time `B_r = Σ (min(end, 14:00) - start)` over tasks of resource `r` (OPEN tasks contribute elapsed time). Service utilization `ρ_r = B_r / A_r` with `A = 360` (345 for C2). Occupied utilization adds the 5-min inter-task gaps. Starvation-adjusted utilization uses available time from the first moment work could have arrived (C1: from 08:25, 335 min; C2: from 08:35, 320 min).
- Little's Law. Sample-path identity (holds for any finite window, all cases included): `mean_t L_k(t) = (1/T) Σ_i (time case i spends in station k inside the window)`. This is used as an internal-consistency check of the WIP curve against the case durations. The stationary form `L = λ·W` with `λ = arrivals/T` and `W = mean sojourn of completed cases` is only reported where start-of-window and end-of-window WIP are both small relative to mean WIP and the residual (unfinished) case-time is small; otherwise `W_completed` is biased low and the check is not meaningful.
- Lower/central/upper estimates. Three imputation scenarios for the four MISSING starts: `min_service` (start = own end → longest waits, least busy time), `central` (A6), `max_service` (start = lower bound → shortest waits, most busy time). Censored quantities are lower bounds. Rounding bands per A2.

# 5. Bottleneck and temporal interpretation

Evidence (observations and arithmetic on the supplied data):

1. Demand vs. capacity. External arrivals ran at 6.5/h in 08:00–10:00 and 4.0/h in 10:00–12:00, then stopped after 12:10. S1's effective cycle per resource is ~28 min service + 5 min gap ≈ 33–35 min, i.e. ≈ 3.4–3.6 cases/h for two resources; observed S1 throughput was 3.75/h while saturated. S2's cycle is ~40 min + 5 ≈ 45 min, i.e. ≈ 2.7 cases/h for two resources; observed 2.9/h (helped by the three short calibrations P05, P10, P11).
2. S1 queue dynamics. The S1 queue rose from 0 to 7 (peak 11:30) because arrivals (5.3–6.5/h) exceeded S1 capacity by ~2–3 cases/h for four hours; S1 waits climbed monotonically from 5 to a plateau of 95–105 min for every arrival after 10:00. Once arrivals stopped (12:10), the S1 queue drained at the S1 throughput rate to 1 case by 14:00.
3. S2 queue dynamics. S2 receives ~3.4–3.75/h from S1 but can process ~2.7/h, so its queue grew steadily and roughly linearly: mean 0.6 (08–10) → 2.2 (10–12) → 3.7 (12–14), peak 5, six cases in the station at 14:00. S2 waits rose from 5–25 min (early entries) to 45–75 min (mid-day entries) to ≥ 85 min (P16, censored). At 14:00 both calibration resources are busy and four cases are waiting, whereas S1 has one idle resource.
4. Both stations were essentially continuously occupied after start-up: occupied utilization ≈ 99 % (I1), 93 % (I2), 92 % (C1), 88 % (C2 including the outage). Pure service utilization is lower (77–85 % central) because of the systematic 5-min inter-task gaps.

Interpretation:

- **08:00–~12:30: S1 is the binding constraint in the sense of waiting time and queue length.** This is an arrival-burst (transient) bottleneck: S1 has more capacity than S2, but it faces the raw arrival stream, which exceeded its capacity by a wide margin. S1 also acted as a filter that limited the load reaching S2 to ~3.5/h.
- **From ~12:30 onward: S2 becomes the binding constraint, and it is the structural (long-run) bottleneck.** Its capacity (~2.7/h) is below both the arrival rate (5.3/h while arrivals lasted) and S1's throughput (~3.5/h). Even with zero external arrivals after 12:10, the S2 queue kept growing because S1 kept feeding it faster than it can drain. Had arrivals continued at the morning rate, both stations would have been overloaded, but S2 would have accumulated the larger backlog in the long run.
- So the evidence supports a **time-varying combination**: S1-dominated transient congestion in the morning, hand-over to S2 around 12:30–13:00, S2-dominated at the end of the window. The crossing point is visible in the queue means (S1 queue 3.3 vs S2 queue 3.7 in 12:00–14:00) and in the 13:00 hour (S1 queue 1.75 vs S2 queue 4.2).

Maintenance interval (C2, 10:55–11:10): C2 finished P06 at 10:50, was idle 10:50–10:55, under maintenance until 11:10, and restarted with P08 at 11:15 — a 25-min interruption of which 15 min is the documented outage and 10 min the usual changeover gaps. The direct victim is P08 (S2 wait 55 min instead of ~35 min if C2 had continued): at 11:00 C1 became free but took P09 (queue entry 10:35) rather than P08 (queue entry 10:20). Hypotheses (not evidence): (H1) dedicated lanes I1→C1 / I2→C2 were in force until then — every case P01–P09 follows that pattern — and P08 was locked to C2; (H2) P08 needed C2-specific equipment; (H3) a genuine dispatching lapse. After the outage the lane pattern disappears (P10 I2→C1, P11 I1→C2, P12 I2→C1, P13 I1→C2, P15 I1→C2, P17 I1→C1), consistent with H1 being relaxed once the backlog became visible. The outage removed ~15–25 min of S2 capacity (about half a case); it shifted the C2 stream by ~20 min but is not the cause of the S2 backlog, which would have reached ~3–4 waiting by 14:00 without it (it reduced completed S2 work by at most one case).

Other anomalies (evidence) with hypotheses:
- S2 FIFO violations: (P08, P09) discussed above; (P16, P17): P16 entered 12:35, P17 entered 12:50 and started 13:55 while P16 still waits. Hypotheses: priority rule, P16 on hold (paperwork/parts), or P16's start was logged late. Since both C's are occupied at 14:00, P16 cannot be in undocumented service unless a third person helped.
- I2 idle 13:45–14:00 with P22 waiting since 12:10: hypotheses — I2 break/shift end, P22 started but not yet logged (delayed logging), or P22's arrival stamp (other system) precedes physical availability. Under the first hypothesis S1's effective capacity in the last 15 min was 1.
- The three short S2 services (P05 ≤ 30, P10 25, P11 ≤ 25) versus a norm of 40–50: either a fast calibration variant or logging artefacts (late end stamps for the preceding task). If they are artefacts, true S2 capacity is even lower than 2.7/h, strengthening the S2-bottleneck conclusion.
- The 100 % regular 5-min gaps suggest that starts are logged after a fixed handling step, or a genuine 5-min changeover. In either case the *effective* cycle time, not the recorded service time, determines capacity: S1 ≈ 33–35 min, S2 ≈ 45 min per case per resource.

Hour-bin counts can move by one case when an event sits exactly on a bin edge (P08 arrival 09:00, P01/P07/P08/P12 S2 ends at 09:00/11:00/12:00/13:00), which is why two-hour blocks are preferred in Section 4.

Right-censoring sensitivity (labelled projection, hypothesis-level, assumes A8 typical services 30/40, FIFO from now on, 5-min changeovers, C2 continues): P15 finishes ≈ 14:10, P17 ≈ 14:35, P16 ≈ 14:55, P18 ≈ 15:20, P19 ≈ 15:40, P20 ≈ 16:05, P21 leaves S1 ≈ 14:00 and finishes ≈ 16:25, P22 finishes ≈ 16:50. Under this projection the mean case sojourn of all 22 arrivals is ≈ 190 min (vs 146 for completed cases and the hard lower bound 156), and the mean S2 sojourn of the 20 S2 arrivals ≈ 87 min (vs 70 completed-only; hard lower bound 67). The S2 backlog would need ~2 h beyond 14:00 to clear with no new arrivals.

Stable conclusions (survive all scenarios, rounding, and censoring treatment):
- Station sojourns, total WIP and all case sojourns of the 14 completed cases are unaffected by the missing starts (only the wait/service split moves).
- S1 waits plateau at 95–105 min for every arrival after 10:00; S1 waits exceed S2 waits for all cases up to P14, and the S1 queue peaks (7) before the S2 queue peaks (5).
- S2 queue and WIP grow monotonically through the window and S2 holds 6 cases at 14:00 while S1 holds 2; S2 is the structural bottleneck, S1 the transient morning bottleneck.
- All four resources are effectively fully occupied (≥ 88 % including changeover gaps) after start-up; I2 is the only one with an unexplained idle period (13:45–14:00).
- The C2 outage explains P08's long wait and shifted the C2 stream by ~20 min, but not the S2 backlog.
- Completed-case means (146 min sojourn, 70 min S2 sojourn) understate the experience of the full arrival cohort by at least 7 % (hard bounds) and plausibly by 25–30 %.

Unstable / not identifiable conclusions:
- Service utilization of I1 (68–88 %) and, to a lesser extent, C1/C2 (72–86 %, 68–81 %) depends on the imputation of P07/P15 and P05/P11; only the central-plus-rounding band (I1 81–88 %, C1 78–86 %, C2 73–81 %) is reasonably tight, and "occupied" utilization (88–99 %) is a different quantity.
- Whether the short calibrations (P05, P10, P11) are real or logging artefacts; this changes S2's effective capacity estimate between ~2.7/h and ~2.5/h.
- Mean S2 service (34–40 min) and the S2 wait median (35 vs 47.5) move materially between the min_service and central scenarios; the central scenario is well supported by the 5-min pattern but not proven.
- The cause of the two FIFO violations and the I2 idle period; and whether S1 capacity in 13:45–14:00 was 1 or 2.
- Final service times of P15, P17, P21 (only elapsed 30, 5, 30 are known) and the finishing times of all eight open cases (projection only).

def parse(cell):
    """Return (timestamp-or-NaT, status). MISSING / OPEN / BLANK are kept distinct."""

# Constraints: start >= queue entry (arrival for S1, s1_end for S2); start >= end of the

# Central = previous task end on the same resource + 5 min (the changeover gap seen in every
# fully observed consecutive pair of this station), clipped to [lower, upper].
def resource_prev_end(case, station, res):
    st, en = f"{station}_start", f"{station}_end"

    others = df[(df[f"{station}_resource"] == res) & (df.case != case) & df[en].notna()]

# ------------------------------------------------------------------ 9. Little's-Law checks
# Sample-path identity: area under station-WIP curve == sum of in-window station time over ALL cases.
# Stationary form L = lambda * W uses arrivals/window and the mean sojourn of completed cases only.
def little(d, w, station):
    entry = d["arrival_s1"] if station == "S1" else d["s1_end"]
    exit_ = (d["s1_end"] if station == "S1" else d["s2_end"]).fillna(T_END)
    inwin = mins(exit_.clip(upper=T_END) - entry).dropna()
    area = inwin.sum()
    L_curve = w[f"{station}_total"].mean()
    n_arr = entry.notna().sum()
    soj = (d["s1_sojourn"] if station == "S1" else d["s2_sojourn"]).dropna()
    lam = n_arr / 360
    return dict(L_from_curve=round(L_curve, 2), L_from_case_time=round(area / 360, 2),
                arrivals=int(n_arr), completed=int(len(soj)), W_completed=round(soj.mean(), 1),
                lambda_x_W_completed=round(lam * soj.mean(), 2),
                residual_case_min_at_14=int(inwin[(d["s2_end" if station == "S2" else "s1_end"].isna())].sum()))
