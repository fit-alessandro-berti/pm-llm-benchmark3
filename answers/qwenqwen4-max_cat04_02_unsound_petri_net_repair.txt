# 1. Executive Verdict

The net **is** a workflow net in the structural sense: `source` is the unique place without input arcs, `sink` the unique place without output arcs, and every place/transition lies on some `source``sink` path (including `p_waived` and `t_join_waived`). It should nevertheless **not** be expected to be sound. The principal defect is that `t_join_waived` consumes only `p_waived`; nothing on the waiver route consumes the mandatory analysis token. Consequently `t_authorize` can fire while `p_analysis` is still marked (authorization before analysis), and after the analysis is eventually performed its token in `p_analysis_done` is unconsumable, because `t_join_normal` also needs `p_review_done`, which can never be marked once `t_waive_review` took the `p_review` token. Business consequence: cases can be authorized without a completed mandatory analysis, and waived cases end in a dead marking with a leftover token instead of exactly `fm`.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source  t_register  p_ready  t_split` | Case registration, then AND-split | Correct: one token becomes two branch tokens (`p_analysis`, `p_review`) | None |
| `t_split` | Start analysis **and** review in parallel | Genuine AND-split (two output arcs, one input) | None; parallelism is real, not simulated |
| `p_review  {t_standard_review, t_waive_review}` | XOR choice of review outcome | Free-choice conflict over the single `p_review` token; exactly one outcome per case | Correct mutual exclusion; also means `p_review_done` and `p_waived` are never both marked |
| `t_standard_review  p_review_done` | Standard review completion | Correct | None |
| `t_waive_review  p_waived` | Recorded waiver as the review outcome | Produces a waiver token in a place that is **only** read by `t_join_waived` | Waiver outcome is not visible to the analysis-synchronizing join |
| `t_join_normal` (`p_analysis_done` + `p_review_done`  `p_decision`) | AND-join of analysis + standard review | Correct 2-input AND-join | Unreachable on the waiver route (`p_review_done` stays empty forever) |
| `t_join_waived` (`p_waived`  `p_decision`) | AND-join of analysis + waiver | **Degenerate 1-input "join"**: it is a pass-through, not a synchronization | Authorization enabled with analysis outstanding; no consumption of the analysis token |
| `p_analysis_done` | Analysis completion condition for authorization | Consumed only by `t_join_normal` | Leftover token on the waiver route; unconsumable  improper completion / deadlock |

| Node coverage / path condition | WF-net well-formedness | All nodes on a `source``sink` path; no orphan nodes, no dead transitions in the *structural* sense | `check_is_workflow_net` is expected to pass, which masks the behavioral defect |
| Boundedness | Safety | Safe: the two joins can never both fire (review outcomes are mutually exclusive), so no place exceeds one token | The failure is **not** unsafeness; it is missing synchronization / leftover tokens |

# 4. Minimal-Repair Alternatives

**Edit-cost model (explicit).** Unit cost per elementary edit: `+1` per arc added, `+1` per arc removed, `+1` per place added/removed, `+1` per transition added/removed, `+1` per label change. Deleting a node also charges its incident arcs (they must go). Renames of identifiers with no semantic effect are free and are not used as “repairs”. Cost of a repair = sum of elementary edits. A repair is *minimal in its family* if no cheaper edit set achieves the same behavior; it is *globally minimal* if no cheaper edit set yields a sound net at all.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1 — give the waiver path a real 2-input join** *(selected)* | add arc `p_analysis_done  t_join_waived` | **1** (1 arc added) | Analysis mandatory on both routes; parallel start; XOR review choice; waiver keeps its own place `p_waived` and its own silent join; authorization only after both completions | `t_join_waived` now waits for `p_analysis_done`; premature authorization and the orphan token both disappear | `p_analysis_done` now has two consumers (`t_join_normal`, `t_join_waived`). They are never co-enabled today (mutual exclusion via `p_review`), but future loops/multi-token usage could turn this into a token-stealing race; two silent joins remain |
| **R2 — merge the waiver outcome into the normal synchronization** | remove arc `t_waive_review  p_waived`; add arc `t_waive_review  p_review_done`; remove arc `p_waived  t_join_waived`; remove arc `t_join_waived  p_decision`; remove place `p_waived`; remove transition `t_join_waived` | **6** (3 arcs removed, 1 arc added, 1 place removed, 1 transition removed) | Analysis mandatory on both routes; parallelism; single canonical AND-join; visible label “Record Review Waiver” retained | Waiver and standard review become token-indistinguishable in `p_review_done`; only one join exists; net-level waiver state erased | Loss of structural provenance for waiver audits; misleading place name (`p_review_done` now also means “waived”); re-adding waiver-specific logic later costs more. Deleting `p_waived`/`t_join_waived` is *required*: leaving them would create dead nodes/transitions |
| **R3 — gate the waiver on completed analysis** | add arc `p_analysis_done  t_waive_review` | **1** (1 arc added) | Analysis mandatory; sound; single review token still chooses the outcome | Waiver can only be recorded **after** the analysis finishes  the waiver branch is no longer independent/parallel; strict order analysis  waiver | Violates the “analysis and review are started in parallel” clause for the waiver branch; asymmetric concurrency (standard review stays parallel); ties R1 on cost but is weaker on intent |
| **R4 — POLICY CHANGE: waiver cancels the pending analysis** | add arc `p_analysis  t_waive_review` | **1** (1 arc added) | XOR review choice; parallel start; proper completion; waiver distinguishable | **Explicit policy change: analysis is no longer mandatory under waiver.** `t_waive_review` consumes the *pending* analysis token, so waiver is only possible *before* `t_analyze`; if analysis already ran, standard review is forced | Cases authorized with no analysis at all; the waiver’s availability depends on a race with `t_analyze`; mandatory-analysis control is lost |

**Rejected one-arc “repairs” (why cost 1 is not automatically sufficient).**

- `p_waived  t_join_normal` (instead of R2’s full rewiring): makes `t_join_normal` a **3-input** AND-join; on the waiver route `p_review_done` is unmarkable  deadlock. Unsound.
- `p_analysis  t_join_waived`: works if the waiver join fires first, but if `t_analyze` fires first the marking `{p_analysis_done, p_waived}` enables nothing (`t_join_normal` lacks `p_review_done`)  deadlock. Unsound.
- `p_analysis_done  t_authorize`: fixes the waiver route but breaks the standard route, where `t_join_normal` already consumed `p_analysis_done`  `t_authorize` dead. Unsound.
- `t_join_waived  p_review_done`: enables `t_join_normal` in addition, producing two `p_decision`/`sink` tokens  unsafe, improper completion. Unsound.

**Minimality argument.** Cost 0 is impossible (the original is unsound, Section 3). No single *arc removal* can help: the defect is a *missing* consumption/precondition, and removals only delete behavior (and would additionally create dead nodes). Hence any cost-1 repair is a single arc addition. The orphan token sits in `p_analysis` or `p_analysis_done`; a fix must either (i) make some waiver-route transition consume it in *both* interleavings, or (ii) prevent the waiver route from proceeding without completed analysis. Enumerating the plausible additions gives exactly the working candidates R1 (`p_analysis_done  t_join_waived`), R3 (`p_analysis_done  t_waive_review`) and R4 (`p_analysis  t_waive_review`); the other candidates fail as listed above. Therefore **R1 is globally minimal (cost 1) and intent-preserving**. R3 and R4 tie at cost 1 but each changes stated policy (parallelism / mandatory analysis), so they are not equivalent to R1 under an intent-weighted reading of “minimal”. R2 costs 6 and is minimal only within the “single shared review-done place / one join” family: keeping `p_waived` and `t_join_waived` while merging outcomes would leave dead nodes (unsound), and keeping both joins with identical inputs would duplicate silent behavior at higher cost.

```python
from collections import deque

import pm4py
from pm4py.objects.petri_net.obj import Marking


def marking_key(m):
    """Canonical, hashable view of a marking (place names -> positive counts)."""
    return tuple(sorted((p.name, c) for p, c in m.items() if c > 0))


def enabled_names(net, m):
    return sorted(t.name for t in pm4py.get_enabled_transitions(net, m))


def fire_named(net, m, name):
    """Fire a transition by name ONLY if it is enabled; never move tokens silently."""
    enabled = pm4py.get_enabled_transitions(net, m)
    matches = [t for t in enabled if t.name == name]
    if not matches:
        raise RuntimeError(
            f"{name} is NOT enabled at {marking_key(m)}; enabled={enabled_names(net, m)}"
        )
    t = matches[0]
    out = Marking()
    for p, c in m.items():
        out[p] = c
    for a in t.in_arcs:
        out[a.source] = out.get(a.source, 0) - a.weight
        if out[a.source] == 0:
            del out[a.source]
    for a in t.out_arcs:
        out[a.target] = out.get(a.target, 0) + a.weight
    return out


def replay(net, im, sequence, title):
    print(f"\n--- {title} ---")
    m = im
    print(f"step 0 | {'(initial)':<20} | {marking_key(m)} | {enabled_names(net, m)}")
    for i, name in enumerate(sequence, start=1):
        m = fire_named(net, m, name)          # raises if the step is illegal
        print(f"step {i} | {name:<20} | {marking_key(m)} | {enabled_names(net, m)}")
    return m


def audit(net, im, fm):
    """BFS over (marking, 'analysis already fired') to test the business rule
    and proper completion. Returns diagnostics we computed ourselves."""
    fm_key = marking_key(fm)
    start = (marking_key(im), False)
    seen = {start}
    queue = deque([(im, False)])
    dead, improper, premature_authorize = set(), set(), set()
    while queue:
        m, analyzed = queue.popleft()
        enabled = pm4py.get_enabled_transitions(net, m)
        if not enabled:
            dead.add(marking_key(m))
            if marking_key(m) != fm_key:
                improper.add(marking_key(m))
        for t in enabled:
            if t.name == "t_authorize" and not analyzed:
                premature_authorize.add(marking_key(m))
            nxt = fire_named(net, m, t.name)
            state = (marking_key(nxt), analyzed or t.name == "t_analyze")
            if state not in seen:
                seen.add(state)
                queue.append((nxt, analyzed or t.name == "t_analyze"))
    return {
        "dead_markings": sorted(dead),
        "improper_dead_markings": sorted(improper),
        "authorize_without_analysis": sorted(premature_authorize),
        "audit_states_marking_x_flag": len(seen),
    }


def diagnose(net, im, fm, tag):
    print(f"\n================ {tag} ================")
    print("check_is_workflow_net:", pm4py.check_is_workflow_net(net))
    try:
        print("check_soundness:", pm4py.check_soundness(net, im, fm, print_diagnostics=True))
    except Exception as exc:                      # API/signature varies across versions
        print("check_soundness unavailable/failed:", type(exc).__name__, exc)
    print("enabled at im:", enabled_names(net, im))
    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        sources = {tr.from_state for tr in rg.transitions}
        dead_states = [s for s in rg.states if s not in sources]
        print("reachability graph: states =", len(rg.states),
              "arcs =", len(rg.transitions),
              "states without outgoing arcs =", len(dead_states))
    except Exception as exc:
        print("convert_to_reachability_graph failed:", type(exc).__name__, exc)
    print("own audit:", audit(net, im, fm))


# assumes `net`, `im`, `fm` (original) and `repaired_net`, `repaired_im`,
# `repaired_fm` (Section 5) already exist
diagnose(net, im, fm, "ORIGINAL")
diagnose(repaired_net, repaired_im, repaired_fm, "REPAIRED (R1)")

# Counterexample A on the original: authorization BEFORE analysis, then deadlock.
replay(net, im,
       ["t_register", "t_split", "t_waive_review", "t_join_waived",
        "t_authorize", "t_analyze"],
       "ORIGINAL counterexample A")

# Counterexample B on the original: analysis first, still an orphan token.
replay(net, im,
       ["t_register", "t_split", "t_analyze", "t_waive_review",
        "t_join_waived", "t_authorize"],
```

# 7. Repair Trade-Offs and Residual Risks

**Distinguishability of waiver vs standard review.** R1 keeps `p_waived`, `t_join_waived` and the visible label “Record Review Waiver”, so the waiver is distinguishable both in the event log and in the net’s state space (useful for auditing “who waived, and was analysis done first?”). R2 destroys the *net-level* distinction: after merging into `p_review_done`, the marking no longer records which review outcome occurred; only the log label does. If waiver reporting is a compliance requirement, R2 is a downgrade even though it is sound.

**Duplicate behavior / silent transitions.** R1 introduces a shared input place `p_analysis_done` for two silent joins. They are never simultaneously enabled in the current net (the single `p_review` token makes `p_review_done` and `p_waived` mutually exclusive), so no token-stealing race exists today. But this is an invariant of the *whole* net, not a local property: adding a loop, a re-marking arc, or running several cases in one net instance would break it. Both joins are silent, so trace-level alignments cannot see which join fired; that is benign here because the preceding visible review label disambiguates the route, but it does add silent-transition skipping choices to conformance checking. R2 removes that ambiguity by having a single join, at the price of provenance.

**Soundness  business alignment.** Soundness only guarantees option to complete, proper completion, and no dead transitions. R4 is sound while flatly violating “analysis is always mandatory”; R3 is sound while violating the parallel-start clause. Neither would be caught by `check_soundness`. The mandatory-analysis-before-authorization rule is an *ordering/obligation* property and must be checked separately (the `audit` BFS above, or a temporal-logic/model-checking step).

**Regression tests.** Positive traces (must reach exactly `fm`): `Register Case, Perform Analysis, Perform Standard Review, Authorize Case`; `Register Case, Perform Standard Review, Perform Analysis, Authorize Case`; `Register Case, Record Review Waiver, Perform Analysis, Authorize Case`; `Register Case, Perform Analysis, Record Review Waiver, Authorize Case` (both interleavings of each route). Negative traces (must be rejected): `Register Case, Record Review Waiver, Authorize Case` (no analysis); `Register Case, Authorize Case`; `Register Case, Perform Analysis, Authorize Case` (no review outcome); `Register Case, Perform Standard Review, Record Review Waiver, Authorize Case` (both outcomes); any trace with two authorizations; any trace ending with a leftover token, i.e. replay must end at `fm`, not merely “sink contains a token”. Also test the *prefix* property: after `Register Case, Record Review Waiver`, neither `t_join_waived` nor `t_authorize` may be enabled.

**Detecting an accidental bypass of mandatory analysis.** Do not rely on the sink token. Two cheap, permanent guards: (1) the BFS over `(marking, analysis_fired)` in Section 6 asserts that `t_authorize` is never enabled in a state where `t_analyze` has not fired — this catches R4-style policy drift and any future rewiring; (2) a reachability-graph check that every path from `im` to a final state contains `t_analyze` before `t_authorize`, plus a check that the only dead marking equals `fm`. In production, add a log-level assertion that every authorized case has exactly one analysis event and exactly one review-outcome event, both timestamped before authorization.

# 8. Final Recommendation

**Deploy R1** (add `p_analysis_done  t_join_waived`). It is globally minimal under the stated edit-cost model (one arc), it repairs both counterexamples, and it is the only cost-1 edit that preserves every clause of the business intent: analysis mandatory on both routes, genuine parallel start, exclusive review choice, waiver still recorded in its own place, authorization strictly after both completions. Its residual risk — two silent joins sharing `p_analysis_done` — is documented and testable, and is inert as long as the review choice stays exclusive.

**Fallback: R2** (merge the waiver outcome into `p_review_done`, delete `p_waived` and `t_join_waived`). Choose it if reviewers prefer a single canonical AND-join and want to eliminate the shared-input conflict structurally rather than by an invariant. It costs six edits and sacrifices net-level waiver provenance, but keeps mandatory analysis and full parallelism, and is easy to audit visually.

Reject R3 and R4 for deployment despite their cost-1 tie: R3 silently serializes the waiver behind the analysis, and R4 abolishes mandatory analysis. Both are sound, which is precisely why soundness must not be the acceptance criterion; the ordering/obligation audit and the negative-trace suite are.
