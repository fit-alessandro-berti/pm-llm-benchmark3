## 1. Interaction-graph description

The manufacturing system is modeled as a heterogeneous, typed interaction graph whose nodes represent individual instances of business objects and whose edges represent explicit relational links or event co-occurrences. 

### Important Node Types
- **Job ($J$)**: $J1, J2, J3, J4, J5, J6$
- **Component ($C$)**: $C1, C2, C3, C4, C5, C6$
- **ComponentLot ($L$)**: $L7, L8$
- **Machine ($M$)**: `CNC-2`, `OVEN-1`, `TEST-1`
- **Tool ($T$)**: `FIX-A`, `RACK-7`, `CAL-3`
- **Batch ($B$)**: $B1, B2$
- **Shipment ($S$)**: $S1, S2, S3$

### Important Edge Types and Qualifiers
- `requires`: Job $\rightarrow$ Component
- `contains`: ComponentLot $\rightarrow$ Component
- `batches`: Batch $\rightarrow$ Job
- `consolidates`: Shipment $\rightarrow$ Job
- `processed_on` (inferred from events): Job $\rightarrow$ Machine
- `held_by` (inferred from events): Job $\rightarrow$ Tool
- `cured_in` (inferred from events): Batch $\rightarrow$ Tool

### Higher-Order Motifs (Involving >2 Object Types)
1. **Batch-Tool-Job-Machine Motif**: Batch $B1$ links to Jobs $J1, J2, J3$, which require Components $C1, C2, C3$, where $C1, C3 \in L8$ and $C2 \in L7$, and $B1$ utilizes Tool `RACK-7` on Machine `OVEN-1`.
2. **Tool-Job-Machine Motif**: Tool `FIX-A` is acquired by Job $J4$, which concurrently targets Machine `CNC-2` for a `Machine Process` event involving Component $C4$.
3. **Shipment-Job-Component-Lot Motif**: Shipment $S1$ consolidates Jobs $J1$ and $J4$, where $J1$ requires $C1$ (from lot $L8$) and $J4$ requires $C4$, intersecting with upstream lot-release gates and downstream batch synchronization barriers.

### Direct Observations vs. Inferred Edges
- **Direct Observations**: Static bill-of-materials and grouping relations (`requires`, `contains`, `batches`, `consolidates`) extracted from structural master data.
- **Inferred Edges**: Dynamic resource allocations (`held_by`, `processed_on`, `cured_in`) derived by co-occurrence mapping within timestamped event logs (e.g., matching event timestamps for `FIX-A` acquisition with `J4` state transitions).

## 2. Quantitative delay decomposition

For every calculation below, counterfactual assumptions are explicitly stated. These figures do not constitute formal causal proof.

### 1. Avoidable Synchronization-Induced Waiting for $J1$ and $J2$ in $B1$
- **Observed Data**: $J1$ is ready at 08:10; $J2$ is ready at 08:25; batch $B1$ starts at 12:05.
- **Counterfactual Assumption**: If jobs were processed independently upon readiness without batching constraints on `OVEN-1` and `RACK-7`, execution would begin immediately.
- **Calculation**: 
  - $J1$ waiting time = 12:05 - 08:10 = 3 hours, 55 minutes.
  - $J2$ waiting time = 12:05 - 08:25 = 3 hours, 40 minutes.
- **Interpretation**: Synchronization forces early-ready jobs to idle, masking true downstream capacity.

### 2. Delay Plausibly Associated with `FIX-A` for $J4$
- **Observed Data**: $J3$ holds `FIX-A` from 09:00 to 11:40. $J4$ reaches `CNC-2` at 09:50. `CNC-2` is idle from 10:05 to 10:47. $J4$'s `Machine Process` starts at 11:45.
- **Counterfactual Assumption**: If `FIX-A` were available at 09:50 when $J4$ arrived at `CNC-2` (accounting for the machine idle window 10:05–10:47), $J4$ would have processed immediately after the machine became free.
- **Calculation**: $J4$ actual start (11:45) - Earliest possible start given machine availability after arrival (10:47) = 58 minutes of tool-contention-induced delay.

### 3. Delay Imposed on $J1$ by $S1$ Consolidation
- **Observed Data**: $J1$ is packed at 13:30. $J4$ is packed at 19:10. Shipment $S1$ dispatches at 19:25.
- **Counterfactual Assumption**: If $J1$ could dispatch independently without waiting for its consolidation partner ($J4$), dispatch would occur immediately after packing (adding standard 0.3 h load time from shipment DFG).
- **Calculation**: $J1$ packing completion (13:30) + 0.3 h load time = 13:50 expected dispatch. Actual dispatch = 19:25. 
- **Delay**: 19:25 - 13:50 = 5 hours, 35 minutes of consolidation holding time for $J1$.

### 4. Delay Plausibly Associated with `CAL-3` for $J6$
- **Observed Data**: $J6$ is ready for final test at 16:05. Calibration tool `CAL-3` undergoes recalibration from 16:35 to 17:20. $J6$ tests from 17:25 to 17:50 (`TEST-1` is idle 16:35–17:25).
- **Counterfactual Assumption**: If `CAL-3` did not require recalibration immediately after $J5$'s test (completed at 16:35), $J6$ could have initiated testing at 16:35.
- **Calculation**: $J6$ actual test start (17:25) - Counterfactual test start (16:35) = 50 minutes of tool-calibration blocking.

### 5. Lot-Release Gating Delay for $J5$
- **Observed Data**: $J5$ is ready for component staging prior to 10:20. Lot $L7$ (`C2`, `C5`) enters quarantine at 10:20 and is released at 13:50. $J5$ proceeds after 13:50.
- **Counterfactual Assumption**: If lot $L7$ had not been quarantined, $J5$ would have progressed through staging (0.4 h) and machine process (1.1 h) starting around 08:30 (typical early arrival).
- **Calculation**: Actual progression start (13:50) - Counterfactual start (~08:45) $\approx$ 5 hours, 5 minutes of upstream lot-quarantine blocking.

## 4. What flattening misses

### Job Viewpoint
- **Visible**: Sequence of stages from release to dispatch and total elapsed time.
- **Hidden / Duplicated**: Hides waiting times caused by batch synchronization ($B1, B2$), shared tool contention (`FIX-A`), and shipment holding ($S1$). Duplicates event logs if multi-component joins are unrolled.
- **Misleading Conclusion**: Concludes that jobs are running normally because total duration is within 1.8 standard deviations of the mean, missing that most duration is passive waiting.

### Machine Viewpoint
- **Visible**: Observed utilization percentage (e.g., `CNC-2` at 54%) and typical activity sequences.
- **Hidden / Duplicated**: Hides *why* machines are idle (e.g., `CNC-2` idle 10:05–10:47 because $J4$ is waiting for `FIX-A`, not lack of work).
- **Misleading Conclusion**: Low utilization (44–58%) leads analysts to falsely assume excess capacity, recommending more work intake when machines are actually starved by synchronization.

### Batch Viewpoint
- **Visible**: Batch cure cycles and aggregate processing on ovens.
- **Hidden / Duplicated**: Hides individual job arrival skews and pre-batch idle times.
- **Misleading Conclusion**: Treats batch processing time as efficient transformation, ignoring the severe holding penalty inflicted on early-arriving jobs ($J1, J2$).

### Tool Viewpoint
- **Visible**: Tool acquire and release timestamps.
- **Hidden / Duplicated**: Hides the connection between tool locks and downstream machine starvation.
- **Misleading Conclusion**: Treats tool usage as instantaneous or binary state rather than a critical queuing bottleneck.

### ComponentLot Viewpoint
- **Visible**: Lot quarantine and release timestamps ($L7$ at 10:20–13:50).
- **Hidden / Duplicated**: Hides differential job handling (e.g., $J2$ bypassing via supervisor override vs. $J5$ obeying quarantine).
- **Misleading Conclusion**: Assumes homogeneous lot constraints across all consumer jobs.

### Shipment Viewpoint
- **Visible**: Shipment creation, loading, and dispatch timestamps.
- **Hidden / Duplicated**: Hides the residence time of early packed jobs waiting for consolidation partners.
- **Misleading Conclusion**: Assumes shipment lead times are short (e.g., 0.8h load, 0.3h dispatch) while hiding hours of internal yard waiting.

### Why Low Utilization Coexists with Long Waiting
Traditional metrics equate utilization with congestion. In this system, low machine utilization ($\le 58\%$) coexists with cascading delays because **synchronization barriers** (`OVEN-1` batching, `S1` shipment consolidation) and **exclusive resource locks** (`FIX-A`, `CAL-3`) create artificial starvation. Machines sit idle not because work does not exist, but because prerequisite objects are physically trapped behind upstream gates or locked tools.

## 5. Object-lifecycle evidence

### Narrative 1: The Batch-Tool-Job-Machine Cascade ($J1, J2, J3, B1, RACK-7, OVEN-1$)
1. **Temporal Precedence**: $J1$ and $J2$ complete component staging early (08:10 and 08:25), whereas $J3$ completes staging at 11:55. 
2. **Resource Feasibility**: Batch $B1$ requires all three jobs to be co-staged and loaded onto shared fixture `RACK-7` before entering `OVEN-1`.
3. **Policy Constraints**: Operational rules forbid partial batch curing on `OVEN-1` to maintain thermal consistency.
4. **Causal Speculation**: $J1$ and $J2$ experience nearly 4 hours of passive waiting not due to machine wear or operator speed, but strictly due to structural batching policy coupled with $J3$'s delayed arrival.

### Narrative 2: The Tool-Contention-Starvation Loop ($J3, J4, FIX-A, CNC-2$)
1. **Temporal Precedence**: $J3$ acquires tool `FIX-A` at 09:00 and retains it until 11:40. Meanwhile, $J4$ arrives at `CNC-2` at 09:50.
2. **Resource Feasibility**: $J4$'s `Machine Process` on `CNC-2` physically requires `FIX-A`.
3. **Policy Constraints**: `FIX-A` is a singular non-shareable asset; simultaneous multi-job machining is prohibited.
4. **Causal Speculation**: Although `CNC-2` has available operational capacity (evidenced by idleness from 10:05 to 10:47), $J4$ cannot utilize the machine because $J3$ holds the required tool downstream, inducing an artificial machine idle period and delaying $J4$ by 58 minutes.

### Narrative 3: The Lot-Quarantine-Bypass Disconnect ($L7, C2, C5, J2, J5, S2$)
1. **Temporal Precedence**: Component lot $L7$ enters quarantine at 10:20 and is released at 13:50. $J2$ enters batch $B1$ at 12:05 via supervisor override; $J5$ waits until after 13:50.
2. **Resource Feasibility**: Both $J2$ (consuming $C2$) and $J5$ (consuming $C5$) depend structurally on $L7$.
3. **Policy Constraints**: Quality quarantine mandates halting downstream processing until lot clearance, but management override protocols permit discretionary bypassing.
4. **Causal Speculation**: The quarantine policy effectively gates $J5$ for over 5 hours, while $J2$ bypasses the gate, creating asynchronous state divergence within members of the same component lot.

## 8. Falsification and additional data

### Observations That Would Weaken the Top-Ranked Explanation (Batch Synchronization & Tool Contention)
1. **Post-Batch Rework Clustering**: If jobs $J1, J2, J3$ exhibited high failure and rework rates directly traceable to thermal stress during batch $B1$ curing, the long pre-batch waiting might be a necessary quality stabilization hold rather than avoidable waste.
2. **Operator Utilization Saturation**: If operators were empirically proven to be 100% occupied handling manual pre-treatments during the exact windows ovens sat idle, the waiting would be labor-constrained rather than synchronization-constrained.
3. **Alternative Tool Paths**: If discovery proved that `FIX-A` and `CAL-3` had fully functional interchangeable backups (`FIX-B`, `CAL-4`) located in the same cell that went unutilized due to operator preference, tool contention would be an operational artifact rather than a physical bottleneck.
4. **Asynchronous Batch Override Success**: If data showed that jobs bypassing batch gates via overrides experienced a 50%+ scrap rate due to improper thermal curing, the synchronization barriers would be validated as vital quality gates.
5. **Shipment Independence Proof**: If internal transit logs revealed that early-packed jobs ($J1$) were actively undergoing secondary quality inspections during the 5.5-hour consolidation window, the delay would be processing-driven rather than consolidation-driven.
6. **Lot Homogeneity Verification**: If chemical analysis of lot $L7$ confirmed that quarantined components ($C2, C5$) were entirely defective, the 5-hour lot release delay would represent a successful safety stop rather than a bureaucratic bottleneck.

### Additional Fields or Event Types to Discriminate Among Hypotheses
1. **Operator Assignment Logs (`OperatorID`)**: To test whether human resource scarcity rather than tool/batch constraints drives idle gaps.
2. **Physical Queue Length Sensors (`QueueDepth`)**: To measure real-time buffer occupancy upstream of `CNC-2` and `OVEN-1`.
3. **Detailed Tool Inspection/Calibration Logs**: To distinguish between scheduled maintenance, uncalibrated drift, and active fixture holding times for `FIX-A` and `CAL-3`.
4. **Supervisor Override Reason Codes**: To categorize why $J2$ bypassed lot $L7$ quarantine while $J5$ did not.
5. **Thermal Sensor Telemetry (`OvenTemperature`, `CurePressure`)**: To verify whether oven batching constraints are physical thermodynamics-driven or purely administrative schedule rules.
6. **Yard/Loading Dock Occupancy Timestamps**: To isolate exact staging durations for packed jobs awaiting shipment consolidation ($S1, S2, S3$).
