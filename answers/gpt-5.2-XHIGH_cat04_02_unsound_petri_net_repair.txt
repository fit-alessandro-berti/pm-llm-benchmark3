# 1. Executive Verdict

Yes, this net is a **workflow net**: it has a unique source place (`source`), a unique sink place (`sink`), and every node lies on at least one path from `source` to `sink`. However, it should **not** be expected to be **sound**. The principal defect is the waiver synchronization: `t_join_waived` consumes only `p_waived`, so it can create `p_decision` without consuming the analysis-branch token created by `t_split`. Business consequence: a case can be **authorized before analysis is performed**, and even when a token reaches `sink`, the exact final marking `fm = {sink: 1}` is **unreachable on the waiver path** because a leftover token remains stranded in the analysis branch (violating proper completion and leading to a dead marking not equal to `fm`).

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source` → `t_register` → `p_ready` | Create a single case token | Standard start; no incoming arcs to `source` | None |
| `t_split` (`p_ready` → `p_analysis` and `p_review`) | AND-split: start analysis and review in parallel | Duplicates the token into two concurrent branches | If a later join does not consume both, a leftover token remains |
| Analysis branch (`p_analysis` → `t_analyze` → `p_analysis_done`) | Mandatory analysis completion | Produces `p_analysis_done`; **only** `t_join_normal` consumes it in the original net | On waiver route, token becomes orphaned (`p_analysis`/`p_analysis_done` cannot be cleared) |
| Standard review path (`p_review` → `t_standard_review` → `p_review_done`) | Do standard review | Competes with waiver for the same input token (XOR choice) | None (choice behavior is correct) |
| Waiver path (`p_review` → `t_waive_review` → `p_waived`) | Record a waiver instead of standard review | Also competes for the same input token (XOR choice) | None by itself; the problem is downstream synchronization |
| `t_join_normal` (`p_analysis_done` + `p_review_done` → `p_decision`) | AND-join for the “standard review” outcome | Correctly enforces analysis+standard review before `p_decision` | Works only when `t_standard_review` is chosen |
| `t_join_waived` (`p_waived` → `p_decision`) | Intended: synchronize waiver with analysis | **Not a join**: ignores `p_analysis_done` entirely | `t_authorize` can happen before analysis; leftover analysis token prevents reaching `fm` |
| `p_decision` → `t_authorize` → `sink` | Authorization and completion | Completion depends only on `p_decision` | “Sink marked” does not imply “properly completed” (tokens can remain elsewhere) |
| `im` and `fm` | Proper WF-net start/stop | `im={source:1}` is fine; `fm={sink:1}` requires no other tokens | Waiver route reaches `sink` but not `fm` |
| Source-to-sink path coverage | WF-net criterion (“every node on some source→sink path”) | Satisfied: nodes are covered via standard-review path or waiver path | WF-net check can pass even when soundness fails |

# 3. Marking-Based Counterexample

## Counterexample A (authorization can occur before analysis)

Legal firing sequence (waiver route):  
\(\sigma_A = \langle\) `t_register`, `t_split`, `t_waive_review`, `t_join_waived`, `t_authorize` \(\rangle\)

Marking table (starting from `im`):

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---:|---|---|---|---|
| 0 | — | `{source:1}` | `{t_register}` | Start from `im` |
| 1 | `t_register` | `{p_ready:1}` | `{t_split}` | Case registered |
| 2 | `t_split` | `{p_analysis:1, p_review:1}` | `{t_analyze, t_standard_review, t_waive_review}` | AND-split created one token in each parallel branch |
| 3 | `t_waive_review` | `{p_analysis:1, p_waived:1}` | `{t_analyze, t_join_waived}` | Waiver chosen; **analysis not yet done** but `t_join_waived` already enabled |
| 4 | `t_join_waived` | `{p_analysis:1, p_decision:1}` | `{t_analyze, t_authorize}` | `p_decision` created **without** consuming the analysis token |
| 5 | `t_authorize` | `{p_analysis:1, sink:1}` | `{t_analyze}` | A token exists in `sink`, but **`fm` not reached** (extra token remains) |

Why the leftover token cannot be consumed to reach `fm`:

- If we now fire `t_analyze`, we get `{p_analysis_done:1, sink:1}`.
- From `{p_analysis_done:1, sink:1}`, **no transition is enabled**: `t_join_normal` additionally needs `p_review_done` (impossible after choosing waiver), and `t_join_waived` needs `p_waived` (already consumed at step 4).
- Therefore the net deadlocks in a marking \(\neq fm\). This violates both “option to complete properly” and “proper completion”.

## Counterexample B (even if analysis happens first, completion is still improper)

Legal firing sequence (waiver route, analysis before authorization):  
\(\sigma_B = \langle\) `t_register`, `t_split`, `t_waive_review`, `t_analyze`, `t_join_waived`, `t_authorize` \(\rangle\)

Key markings:

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---:|---|---|---|---|
| 3 | `t_waive_review` | `{p_analysis:1, p_waived:1}` | `{t_analyze, t_join_waived}` | Same fork as in A |
| 4 | `t_analyze` | `{p_analysis_done:1, p_waived:1}` | `{t_join_waived}` | Analysis completes |
| 5 | `t_join_waived` | `{p_analysis_done:1, p_decision:1}` | `{t_authorize}` | Analysis token is still not consumed by the waiver join |
| 6 | `t_authorize` | `{p_analysis_done:1, sink:1}` | `{}` | Dead marking \(\neq fm\) (leftover token) |

So `t_authorize` can occur **before** `t_analyze` (Counterexample A) or **after** `t_analyze` (Counterexample B); in both cases, the exact final marking `fm` is not reachable on the waiver route.

# 4. Minimal-Repair Alternatives

## Edit-cost model

Let the **edit cost** be:

\[
\text{cost} = \#(\text{arcs added}) + \#(\text{arcs removed}) + \#(\text{places added/removed}) + \#(\text{transitions added/removed})
\]

(Redirecting an arc counts as 1 removal + 1 addition.)

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| **R1: Make waiver a true synchronization (preferred)** | **Add arc** `p_analysis_done -> t_join_waived` (keep existing `p_waived -> t_join_waived` and `t_join_waived -> p_decision`) | 1 | Yes: analysis mandatory; review is standard **or** waiver; authorization only after both are complete | Waiver route must wait for analysis; waiver route can now reach `fm` | If someone *intended* waiver to bypass analysis, this blocks that policy (but matches stated intent) |
| **R2: Route waiver outcome into the normal join** | **Remove arc** `t_join_waived -> p_decision`; **add arc** `t_join_waived -> p_review_done` (so both outcomes feed `t_join_normal`) | 2 | Yes: analysis mandatory; waiver remains a distinct visible transition; authorization after analysis + “some review outcome” | Only `t_join_normal` produces `p_decision`; waiver path gains an extra silent step (“convert waived to review_done”) | `t_join_waived` becomes semantically non-obvious (a converter, not a join); may confuse maintainers unless documented |

## Minimality justification

- **R1**: To enforce mandatory analysis on the waiver route *and* eliminate the leftover analysis token, `t_join_waived` must (directly or indirectly) consume the analysis completion token. The cheapest way is to add exactly **one** missing dependency arc from `p_analysis_done` into `t_join_waived` (cost 1). Any repair with cost 0 leaves the defect unchanged.
- **R2** (under the design constraint “single join to `p_decision`”): the waiver route must produce `p_review_done` (or equivalent) so `t_join_normal` can synchronize it with `p_analysis_done`. The smallest change is a single arc redirection on `t_join_waived`, which is cost **2** in this model. With fewer than 2 arc edits, `t_join_waived` would still send a token to `p_decision` (preserving the bypass) or would not feed `p_review_done` (making the waiver route incomplete).

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking
from pm4py.objects.petri_net.semantics import execute


def _mview(marking):
    # Pretty-print: {place_name: tokens} for nonzero places
    items = [(p.name, marking[p]) for p in marking if marking[p] > 0]
    return "{" + ", ".join(f"{k}:{v}" for k, v in sorted(items)) + "}"


def _t_by_name(pn, t_name: str):
    for t in pn.transitions:
        if t.name == t_name:
            return t
    raise KeyError(f"Unknown transition name: {t_name}")


def fire_named(pn, marking, t_name: str):
    enabled = pm4py.get_enabled_transitions(pn, marking)
    t = _t_by_name(pn, t_name)
    if t not in enabled:
        raise RuntimeError(
            f"{t_name} not enabled at {_mview(marking)}; enabled={[x.name for x in enabled]}"
        )
    new_marking = execute(t, pn, marking)
    print(f"fired {t_name:>14} -> {_mview(new_marking)}")
    return new_marking


def run_checks(label, pn, pn_im, pn_fm):
    print(f"\n== {label} ==")
    print("workflow net?", pm4py.check_is_workflow_net(pn))
    print("sound?", pm4py.check_soundness(pn, pn_im, pn_fm, print_diagnostics=True))
    print("enabled@im:", [t.name for t in pm4py.get_enabled_transitions(pn, pn_im)])
    rg = pm4py.convert_to_reachability_graph(pn, pn_im, pn_fm)
    print("reachability graph computed:", type(rg))


run_checks("original", net, im, fm)
run_checks("repaired", repaired_net, repaired_im, repaired_fm)


# Reproduce waiver counterexample on the original net
m = Marking(im)
print("\n-- original waiver counterexample --")
for tn in ["t_register", "t_split", "t_waive_review", "t_join_waived", "t_authorize"]:
    m = fire_named(net, m, tn)
print("fm reached (original)?", m == fm, " current=", _mview(m))
print("enabled after authorize (original):", [t.name for t in pm4py.get_enabled_transitions(net, m)])
```

Expected qualitative diagnostic difference:

- The **workflow-net check** should be `True` for both (structure already satisfies unique source/sink and coverage).
- The **original** should be reported **unsound**, with diagnostics consistent with **improper completion** (a reachable marking marks `sink` while other places are also marked) and/or a **dead marking not equal to `fm`** on the waiver route.
- The **repaired** net should be **sound**: both the standard-review and waiver routes can reach exactly `fm`, and markings with `sink` marked should coincide with `fm` (no leftover tokens outside `sink` at completion).

# 7. Repair Trade-Offs and Residual Risks

- **Waiver vs. standard review distinguishability**: Preserved. The visible transitions `t_standard_review` (“Perform Standard Review”) and `t_waive_review` (“Record Review Waiver”) remain distinct, so logs can still separate the two outcomes even though the joins are silent.
- **Silent-transition ambiguity**: `t_split`, `t_join_normal`, and `t_join_waived` are invisible. This is normal for control-flow routing, but it can introduce multiple equivalent interleavings in alignments and make “why was this enabled?” harder to explain to non-experts. In R1, there are also two silent joins that both produce `p_decision`; they are mutually exclusive per case, but still add internal branching.
- **Soundness ≠ full business-rule compliance**: Soundness guarantees token-level completion properties, not that every domain rule is modeled. For example, it does not validate that “analysis content is adequate,” that waivers are authorized by the right actor, or that analysis and review truly started “in parallel” in real life.
- **Regression tests (positive traces)**:
  - Standard: `t_register, t_split, (t_analyze || t_standard_review in any order), t_join_normal, t_authorize`
  - Waiver: `t_register, t_split, (t_analyze || t_waive_review in any order), t_join_waived, t_authorize`
  - Also test both interleavings of analysis vs. review outcome before the join.
- **Regression tests (negative traces)**:
  - Waiver without analysis: `t_register, t_split, t_waive_review, t_join_waived, t_authorize` (must be impossible after repair)
  - Authorization without any review outcome (must be impossible)
  - Any execution that marks `sink` with extra tokens elsewhere (must be impossible).
- **Detecting accidental bypass of mandatory analysis**:
  - Structural guard: in R1, both joins that produce `p_decision` require `p_analysis_done`, so `t_analyze` becomes a causal prerequisite of `t_authorize`.
  - Verification guard: use reachability (or a simple search over the reachability graph) to check that **no path reaches `sink` without firing `t_analyze`**, and that any marking with `sink` marked equals `fm`.

# 8. Final Recommendation

Deploy **R1 (add `p_analysis_done -> t_join_waived`)**. It is the lowest-cost fix (one added arc), it matches the stated business intent exactly (analysis mandatory even under waiver), and it directly eliminates the stranded-token problem by ensuring the waiver route consumes the analysis-completion token before producing `p_decision`.

Keep **R2 (rewire `t_join_waived` to produce `p_review_done` so `t_join_normal` is the sole decision join)** as a fallback if you prefer a single synchronization point before authorization (often easier to reason about and sometimes simpler for future extensions like additional review outcomes). R2 costs one arc redirection (2 arc edits) and slightly increases the “interpretation burden” because `t_join_waived` becomes a silent converter rather than a true join.
