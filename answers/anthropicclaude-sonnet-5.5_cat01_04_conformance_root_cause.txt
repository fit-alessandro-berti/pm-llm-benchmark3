
The pattern is best explained by a conjunctive, staged mechanism rather than one cause. The UI release changed recorded_labels without changing true_process, and the gateway independently inserted Queue Routed; each creates log moves, and the renamed step also creates a model move. Because every June–July trace carries at least one of them, neither repair alone helps much, so any staged attribution (325881) depends on repair order. The ETL change altered recorded_order for Decision and Notify only, explaining a few points at most: all 70 reversals sit on the standard path and only 11 were screenshot-confirmed, so some may be real early notification. From August, the policy change altered true_process through a mandated step while normative_model stayed frozen. That is model obsolescence, not misconduct; the optional-sign-off model recovers about twenty points but overgeneralizes. A residue remains (Manual Override, enhanced review without a recorded check) whose cause is unidentified: reviewer_behavior, event loss, or routing semantics.

Unchanged outcomes are weak evidence. Approval and appeal rates are aggregate, lagging and insensitive: a 4–5% subpopulation with skipped checks would shift a 3.7% appeal rate far less than sampling noise, and compliance admits incident detection is incomplete. Stable outcomes therefore do not show the log is wrong, because label and ordering defects are demonstrated by independent provenance. They also do not show reviewers are compliant. They only bound how large any decision-changing shift could be.

```python
def build_traces(table, label_map=None, drop=(), fix_order_fraction=0.0):
    """Expand variant counts into trace strings.
    label_map: rename activities; drop: remove activities (technical events);
    fix_order_fraction: WHAT-IF share of reversed Notify,Decision traces restored to
    Decision,Notify. With real data, sort by the source sequence number instead:
        df = df.sort_values(['case:concept:name', 'source_seq'])
    """
    label_map = label_map or {}
    traces = []
    for trace, n in table:
        acts = [label_map.get(a, a) for a in trace.split(",") if a not in drop]
        if fix_order_fraction > 0 and acts[-2:] == ["Notify", "Decision"]:
            k = round(n * fix_order_fraction)
            fixed = acts[:-2] + ["Decision", "Notify"]
            traces += [",".join(fixed)] * k + [",".join(acts)] * (n - k)
        else:
            traces += [",".join(acts)] * n
    return traces

    return pm4py.parse_event_log_string(traces, sep=",")

# ---------------------------------------------------------------- diagnostics
def visible_moves(alignment):
    log_m, model_m = Counter(), Counter()
    for mv in alignment:
        if isinstance(mv[0], tuple):      # defensive: some versions nest (names),(labels)
            mv = mv[1]
        l, m = mv
        if l == ">>" and m not in (">>", None):
            model_m[m] += 1               # visible model move
        elif m == ">>" and l not in (">>", None):
            log_m[l] += 1                 # log move
    return log_m, model_m

def alignment_summary(df, model):
    net, im, fm = model
    diag = pm4py.conformance_diagnostics_alignments(df, net, im, fm)
    lm, mm, costs = Counter(), Counter(), []
    for d in diag:
        l, m = visible_moves(d["alignment"])
        lm.update(l); mm.update(m)
        costs.append(sum(l.values()) + sum(m.values()))   # unit-cost visible moves
    n = len(costs)
    fit = pm4py.fitness_alignments(df, net, im, fm)
    return {
        "n": n,
        "pct_fit": 100.0 * sum(c == 0 for c in costs) / n,
        "mean_moves": sum(costs) / n,
        "avg_fitness": fit.get("average_trace_fitness", fit.get("averageFitness")),
        "top_log": lm.most_common(3), "top_model": mm.most_common(3),
    }

def signoff_by_value(events, cases, threshold=50_000):
    """events: DataFrame with case:concept:name, concept:name; cases: DataFrame with
    case:concept:name and claim_value_eur. Returns a crosstab of sign-off presence by value band."""
    has_so = (events[events["concept:name"] == "Supervisor Sign-off"]
              .groupby("case:concept:name").size().rename("has_signoff").gt(0))
    c = cases.set_index("case:concept:name").join(has_so).fillna({"has_signoff": False})
    c["high_value"] = c["claim_value_eur"] > threshold
    return pd.crosstab(c["high_value"], c["has_signoff"])
```

## 7. Provisional conclusion

**Primary explanation (confidence about 80% that it is the dominant cause of the measured collapse).** The June–July collapse is mainly a measurement artifact. A UI relabel (Risk Screen for Classify) and a gateway technical event (Queue Routed) cannot be absorbed by the frozen model, and a smaller ordering defect comes from ingestion-time stamping of Decision and Notify. The two main causes are jointly necessary, which is why staged repairs lift fitness from 32% to 89%. The August–September drop is mainly model obsolescence: the sign-off policy changed the real process and the tree was not updated (66%86% with an optional-sign-off model, an upper bound on the gain because optionality overgeneralizes). The aggregate report cannot be reproduced from the variant tables at the raw and Aug-Sep stages, so magnitudes are provisional.

**Real compliance problem (confidence about 55% that some genuine bypass or control gap exists, about 15% that it is large).** Enhanced reviews without a recorded compliance check (25 and 30 cases), Manual Override (2035), possible sign-off gaps on claims above EUR 50,000, and a memo referring to a known rise in violations all survive every repair. Flat approval and appeal rates do not discriminate, and compliance's detection is incomplete. These residues could equally be event loss (missing resources rose from 1.2% to about 6%) or routing corrections.

**Immediate actions.**
- **IT:** reconcile the extract against source by activity, including the vanished Request Info events. Document Queue Routed and Manual Override semantics. Supply event, ingestion and sequence timestamps, and re-extract ordered by sequence number.
- **Process owners:** freeze a versioned label map. Add sign-off as a conditional step. Decide whether Manual Override and Queue Routed are business or technical events.
- **Compliance:** audit all 55 enhanced-without-check cases, the unverified reversals (59 and 45) and a sample of overrides against source systems. Stratify sign-off by claim value. Run a reviewer-level analysis.

**Do not claim yet:**
- that employees became noncompliant, or that they did not;
- that the process is "unchanged";
- that 86% fitness validates the new model;
- that stable appeal rates prove data error or compliance;
- that Risk Screen and Classify are equivalent beyond the 40-case audit.

## 8. Model-governance recommendation

1. **Model versioning.** Version every normative model with an effective-date range and link it to its policy source. Each policy or UI change ticket must name the model version that has to change, and conformance reports must state the model version and log window they used.
2. **Event-semantic contracts.** Keep a registry that maps each activity label to a business meaning and owner, including aliases and the release that introduced each. A UI or logging change that alters a label, or the logging of an action such as Manual Override, needs an approved mapping before release and a canonical activity name kept stable in the log.
3. **Technical-event policy.** Classify every event type as business or technical at creation. Technical events carry an explicit marker and a system resource, are excluded from conformance by rule rather than by ad-hoc filtering, and are retained in a separate layer. Coverage of each technical event is monitored.
4. **Timestamp provenance.** Store event time, ingestion time and source sequence number separately. The conformance ordering key is declared per activity and approved, with ingestion time never the default, and the reversal rate is monitored against ETL deployment dates.
5. **Data-aware constraints.** Express rules that depend on case attributes (the EUR 50,000 sign-off, resource authorizations) as data-conditional checks alongside the control-flow model, and always report conformance stratified by such attributes. Never approximate them with optional control-flow steps without measuring precision.
6. **Post-release validation.** After every release, patch, ETL change or policy change, run a preregistered validation. It should compare variant and DFG distributions around the change date, reconcile event counts to source, and audit a random sample of cases. Conformance drops trigger triage against the six hypotheses in this document, not automatic conclusions about employee behavior.
