## 3. Causal-abductive explanation

```text
UI_release            -> recorded_labels            (Classify rendered/logged as Risk Screen)
UI_release            -> gateway_config[hidden]     (release enabled new routing gateway)
gateway_config[hidden]-> technical_events[hidden]   (Queue Routed emitted for most cases)
technical_events[hidden] -> recorded_labels         (extra non-business events in the log)
ETL_change            -> recorded_order             (ingestion time reverses Decision/Notify)
ETL_change            -> event_completeness[hidden] (possible dropped/unlinked events, e.g. Compliance Check)
policy_change         -> true_process               (Supervisor Sign-off added for >EUR 50k)
policy_change         -> reviewer_behavior          (reviewers adopt sign-off; memo pressure)
reviewer_behavior     -> true_process               (corrective Manual Override; possible check bypass[hidden])
true_process          -> recorded_labels
true_process          -> recorded_order
true_process          -> business_outcomes
model_maintenance_lag[hidden] -> normative_model    (tree frozen despite policy change)
recorded_labels       -> alignment_moves
recorded_order        -> alignment_moves
event_completeness[hidden] -> alignment_moves
normative_model       -> alignment_moves
alignment_moves       -> measured_fitness
incident_detection_gap[hidden] -> business_outcomes (observed outcomes understate violations)
```

The measured collapse is overdetermined: four independent mechanisms injected deviations into the alignment layer at nearly the same time, and alignments cannot distinguish their origins — a renamed screen, a gateway event, an ingestion-time swap, and an unmodeled policy step all surface identically as moves on log or model. The staged repairs decompose the June-July gap almost completely (32 to 89 percent fitting), which is why systematic, date-locked artifacts dominate the explanation. But this decomposition cuts both ways. Stable approval, cycle-time, and appeal figures are exactly what artifacts predict, yet they are lagging, coarse indicators routed through an acknowledged incident-detection gap; skipped internal compliance checks would not move them for months, if ever. So unchanged outcomes cannot prove the drop was data error. Symmetrically, the same extraction pipeline that fabricated `Queue Routed` and scrambled `Decision`/`Notify` could plausibly have dropped `Compliance Check` events — meaning the residual "missing checks" signal is not yet evidence of noncompliance either. The honest position is conditional: the fitness metric collapsed for measurement and governance reasons with high confidence, while a small, genuinely open question — roughly fifty-five enhanced-review cases without a recorded check — remains unresolved in both directions and can only be closed by provenance audit, not by more conformance checking on the same log.

Phase logic: Phase 1 removes known measurement contamination so later phases measure behavior, not plumbing. Phase 2 turns "conformance dropped" into a named, quantified residual. Phase 3 decides what the model should be, using precision to guard against overpermissiveness and the value attribute to test the actual policy mechanism. Phase 4 is the only phase that can legitimately convert a log signal into a compliance finding, because it consults provenance outside the log.

Conformance root-cause reproduction: raw vs. normalized logs, normative vs.
candidate model. Data are the published variant aggregates (no timestamps),
so absolute numbers may differ slightly from the aggregate report; the
pipeline and comparisons are what matter.
"""
import pm4py

# ---------------------------------------------------------------- models ---
NORMATIVE = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "

    "X ( 'Supervisor Sign-off', tau ), "
    "'Decision', 'Notify' )"
)

norm_tree = pm4py.parse_process_tree(NORMATIVE)

def expand(variants):
    """Expand (trace_string, count) aggregates into one string per case."""
    out = []
    for trace, count in variants:
        out.extend([trace] * count)
    return out

def normalize(variants, map_label=True, drop_queue=True, fix_order=False):
    """Transparent normalization on trace strings.
    - map_label: Risk Screen -> Classify (UI release 4.2 relabel)
    - drop_queue: remove Queue Routed (gateway technical event)
    - fix_order:  emulate source-sequence ordering for the known
                  Notify/Decision ingestion-time swap
    """
    out = []
    for trace, count in variants:
        acts = trace.split(",")
        if map_label:
            acts = ["Classify" if a == "Risk Screen" else a for a in acts]
        if drop_queue:
            acts = [a for a in acts if a != "Queue Routed"]
        if fix_order:
            for i in range(len(acts) - 1):
                if acts[i] == "Notify" and acts[i + 1] == "Decision":
                    acts[i], acts[i + 1] = acts[i + 1], acts[i]
        out.append((",".join(acts), count))
    return out

def build_log(variants):
    return pm4py.parse_event_log_string(expand(variants), sep=",")

def report(name, log, net, im, fm):
    fit = pm4py.fitness_alignments(log, net, im, fm)
    prec = pm4py.precision_alignments(log, net, im, fm)
    diags = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    n_fit = sum(1 for a in diags if a["fitness"] >= 0.9999)
    print(f"[{name}] avg alignment fitness = {fit['average_trace_fitness']:.3f} | "
          f"perfectly fitting = {100.0 * n_fit / len(diags):.1f}% | "
          f"precision = {prec:.3f}")
    return fit, prec, diags

# ------------------------------------------------------------------ DFGs ---
for period, variants in [("Apr-May", APR_MAY), ("Jun-Jul", JUN_JUL), ("Aug-Sep", AUG_SEP)]:
    dfg, start_acts, end_acts = pm4py.discover_dfg(build_log(variants))
    print(f"\n=== DFG {period} (top edges) ===")
    for edge, cnt in sorted(dfg.items(), key=lambda kv: -kv[1])[:8]:
        print(f"  {edge[0]} -> {edge[1]}: {cnt}")

# ----------------------------------- staged raw-vs-normalized comparison ---
print("\n=== Jun-Jul: staged repairs vs. normative model ===")
report("raw",                       build_log(JUN_JUL), norm_net, norm_im, norm_fm)
report("label map only",            build_log(normalize(JUN_JUL, True, False, False)), norm_net, norm_im, norm_fm)
report("label map + drop QueueRtd", build_log(normalize(JUN_JUL, True, True, False)),  norm_net, norm_im, norm_fm)
report("+ source-order emulation",  build_log(normalize(JUN_JUL, True, True, True)),   norm_net, norm_im, norm_fm)

# ------------------------------ Aug-Sep: normative vs. candidate model -----
print("\n=== Aug-Sep: model comparison (fully normalized log) ===")
aug_norm = build_log(normalize(AUG_SEP, True, True, True))
report("normative model", aug_norm, norm_net, norm_im, norm_fm)
report("candidate model (optional sign-off)", aug_norm, cand_net, cand_im, cand_fm)

# ---------------------------------------------------------------- caveats ---

1. The candidate model makes Supervisor Sign-off optional for EVERY case. It

   sign-off on trivial claims, or none on large ones). Compare precision
   printed above before adopting it.
3. Inputs here are variant aggregates without timestamps or case attributes;
   the 'source-order emulation' swap is a stand-in for genuine reordering by

4. Normalization steps (label map, technical-event removal) are hypotheses

## 7. Provisional conclusion

The measured conformance collapse is primarily a measurement and governance failure, not a workforce failure. Four date-locked mechanisms account for nearly all of it: the 2026-05-31 UI release renamed `Classify` to `Risk Screen`; the 2026-06-03 gateway injected the technical event `Queue Routed` into most traces; the 2026-06-15 ETL switch to ingestion time reversed `Decision` and `Notify` in 70 June-July traces (11 of 70 already contradicted by source screenshots); and the 2026-08-01 sign-off policy changed the sanctioned process while the normative model stayed frozen. The staged repairs quantify this: June-July fitness recovers from 32% to 89% through label mapping, technical-event removal, and source-sequence ordering, and August-September recovers from 66% to 86% once sign-off is admitted. Stable cycle times, approval rates, and appeal rates corroborate that day-to-day operations did not materially change. Confidence in this primary explanation: high, roughly 85-90%.

A real compliance problem may nonetheless remain. After every repair, 25 June-July and 30 August-September enhanced-review traces still lack a recorded `Compliance Check`, and no audit has established whether these are true bypasses or events lost by the same extraction pipeline that demonstrably fabricated and reordered other events. The `Manual Override` rise is confounded by the 2026-08-12 logging patch, and the sign-off policy's EUR 50,000 condition is untested because the high-value attribute was omitted from the report. Confidence that a material, widespread compliance breakdown exists: low, perhaps 15-25%; confidence that the question is open for those ~55 cases: high.

Immediate actions. IT: restore source-sequence ordering in the conformance job, publish a label-mapping and technical-event register, and reconcile source-versus-warehouse event completeness. Process owners: version the normative model, adding a data-aware sign-off condition rather than a blanket optional step, and validate that `Risk Screen` is functionally identical to `Classify`. Compliance: commission a full provenance audit of the 55 enhanced-review-without-check cases and a stratified review of sign-off against claim value.

What must not be claimed yet: that employees became noncompliant, that all deviations were data artifacts, that the memo responded to real violations, or that the optional-sign-off model is the correct policy encoding — its fitness gain comes partly from overgeneralization.

## 8. Model-governance recommendation

1. **Model versioning:** Keep the normative model in version control with an owner; every approved policy change (like the 2026-08-01 sign-off rule) must trigger a model revision with an effective date, and conformance jobs must evaluate each case against the model version in force when the case ran.
2. **Event-semantic contracts:** Maintain a contract per event type (name, business meaning, emitting system, lifecycle stage, resource expectations); any UI or logging release that renames, adds, or re-scopes an event (e.g., `Classify` -> `Risk Screen`, the `Manual Override` patch) requires a contract update and an entry in the conformance label-mapping table before release.
3. **Technical-event policy:** Every event entering the warehouse is classified business or technical at ingestion (using emitting component and resource presence); technical events such as `Queue Routed` are retained for diagnostics but excluded from conformance by default, with the exclusion list published and auditable.
4. **Timestamp provenance:** Conformance ordering must use source-system timestamps or sequence numbers, never warehouse-ingestion time; every event carries both, plus a provenance flag, and the pipeline fails loudly rather than silently substituting ingestion time as it did on 2026-06-15.
5. **Data-aware constraints:** Encode conditional obligations (sign-off required if claim > EUR 50,000) as data-aware rules or guarded models rather than unconditioned control flow, so that conformance can distinguish a legitimately skipped optional step from a violated mandatory one — an optional-step tree cannot.
6. **Post-release validation:** After every UI, gateway, ETL, or policy release, run an automated canary: compare variant distributions, DFG edges, event-per-case counts, and fitness on a pre/post window, and block the conformance dashboard from publishing until deltas are triaged as artifact or behavior — so a 61-point fitness cliff is caught in days, not months.
