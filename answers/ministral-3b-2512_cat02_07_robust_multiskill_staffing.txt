# 1. Assumptions, objectives, and decision variables

## Demand and Service Assumptions
- **Case arrival distributions**: Two-hour blocks are treated as Poisson arrivals with given expected counts. Percentages (e.g., 30% M in 08:00-10:00) are normalized to actual counts (e.g., 7 cases × 0.30 = 2.1 M cases, rounded to 2).
- **Service-time distributions**: Ordinary and complex-tail ranges are modeled as uniform distributions with given probabilities. For example, Mechanical ordinary time is 18–28 minutes with 85% probability.
- **ME/ES parallelism**: Defaults to sequential unless a cross-skilled resource exists (e.g., Emil handles ME or ES). Parallelization adds 8 minutes of coordination unless explicitly avoided.
- **Preemption**: P1 cases may preempt lower-priority work, incurring 10% restart penalty on remaining time. Preemptions are limited to once per case.

## Decision Variables
- **Routing**: Assign each case to a resource based on skill eligibility, priority, and workload.
- **Parallelization**: Decide whether ME/ES branches execute in parallel or sequentially.

## Objectives
1. **Tail/SLA Risk Objective**:
   \[
   \text{Objective}_1 = \sum_{i \in \text{P1,P2,P3}} \lambda_i \cdot \max(0, \text{delay}_i - \text{SLA}_i)
   \]
   where \(\lambda_i\) is the priority weight (e.g., \(\lambda_{\text{P1}} = 0.5\)), and \(\text{SLA}_i\) is the target elapsed time (e.g., 120 minutes for P1).
2. **Fairness/Robustness Objective**:
   \[
   \text{Objective}_2 = \alpha \cdot \text{Max Utilization} + \beta \cdot \text{Queue Length Variance}
   \]
   where \(\alpha\) and \(\beta\) balance resource saturation and workload fairness. Fairness is penalized if any queue exceeds 90% capacity or if P3 cases wait > 24 hours.

# 3. Candidate Policies

## Policy 1: Strict Specialization (Fixed Queues)
- **Eligibility**: Cases routed to the first available resource in their skill family (e.g., M  Farah, E  Chen, S  Emil).
- **Priority**: P1 cases bypass lower-priority queues but incur handover delays if resources are idle.
- **Preemption**: P1 cases preempt lower-priority work only if the preempted case is >10% complete.
- **Parallelization**: ME/ES branches execute sequentially unless a cross-skilled resource exists (e.g., Emil handles ME/ES).
- **Overflow**: Reject P1 cases if all resources are busy for >15 minutes.

## Policy 2: Full Pooling (Transparent Dispatch)
- **Eligibility**: Any resource with the required skill is eligible. Dispatch rule: **Shortest Expected Remaining Time (SERT)**.
- **Priority**: P1 cases get priority in SERT but are assigned to the fastest available resource.
- **Preemption**: P1 cases preempt lower-priority work if the preempted case is <50% complete.
- **Parallelization**: ME/ES branches parallelized if a cross-skilled resource is available; otherwise sequential.
- **Overflow**: Reject P1 cases if all resources are busy for >10 minutes.

## Policy 3: Hybrid Policy (Reserved Capacity + Overflow)
- **Eligibility**: P1 cases reserved for a dedicated resource (e.g., Farah for ME, Chen for E). Overflow P1 cases use SERT.
- **Priority**: P1 reserved cases preempt lower-priority work if the reserved resource is idle.
- **Parallelization**: ME/ES branches parallelized if the reserved resource is unavailable; otherwise sequential.
- **Overflow**: Reject overflow P1 cases if all non-reserved resources are busy for >12 minutes.

# 5. Robust Recommendation

**Primary Policy**: Hybrid Policy (Reserved Capacity + Overflow).
- **Why**: Balances SLA attainment (P1 70–85% in base) with fairness (no resource >95% utilization). Reserved capacity prevents U3/U5 bottlenecks, while overflow uses SERT to handle spikes.
- **Trigger Thresholds**:
  - Switch to **Full Pooling** if any resource exceeds 98% utilization for >2 hours.
  - Switch to **Strict Specialization** if P1 SLA drops below 60% for 3 consecutive hours.

**Fallback**: Full Pooling if reserved resources are unavailable (e.g., Chen absent in U3).

# 6. Secondary Effects and Implementation Risks

- **Gaming**: Operators may delay P1 cases to avoid preemption penalties, but reserved capacity mitigates this.
- **Starvation**: P3 cases may wait >24 hours if P1/P2 dominate queues. Monitor queue lengths >12 hours.
- **Skill Erosion**: Full Pooling risks cross-training; hybrid policy limits this by reserving skills.
- **Preemption**: Hybrid policy’s reserved capacity reduces preemption frequency but may increase handover delays.
- **Validation Bottleneck**: Parallel ME/ES coordination adds 8 minutes; sequential execution avoids this but may lengthen critical paths.
- **Fairness**: Hybrid policy penalizes overflow P1 cases, but full pooling ensures no resource is overloaded.
