## 6. Candidate Site B intervention

**Modified intervention:** selective early-concurrency with statutory guards, not blanket Site-A copying.

- **Eligibility rules**
  - All cases: Identity Check may be released after Register.
  - Non-originals-required cases: Document Check may be released after Register, concurrently with Identity Check, if registration confirms required documents are already available.
  - Originals-required cases: only Originals Receipt, identity work, and Document Intake/Readiness may be concurrent. Substantive Document Check remains blocked until Originals Receipt and required originals are confirmed.
  - Legal-review cases: eligible for the same early verification rules, but Assessment cannot produce final decision until Legal Review is complete; supplement loops remain mandatory.

- **Concurrent tasks**
  - `Register -> Identity Check` in parallel with `Originals Receipt` where required.
  - `Identity Check || Document Check` only for digital/non-originals cases.
  - `Identity Check || Originals Receipt || Document Intake/Readiness` for originals-required cases.
  - Identity results should be reused after supplement unless the supplement affects identity.

- **Mandatory prerequisites**
  - Originals Receipt before substantive Document Check whenever legally required.
  - Identity Check and Document Check complete before Assessment.
  - Legal Review before final decision in public-sector/high-value cases.
  - Request Supplement before repeat Document Check/Assessment when supplement grounds exist.

- **Queue and WIP controls**
  - Start with strict WIP caps: identity 8 open tasks total, document 10, assessment 3, legal 2, adjustable only with measured utilization.
  - Release completed verification pairs to Assessment in controlled batches; do not flood assessment/legal queues.
  - Freeze staffing and queue-priority changes during the pilot.

- **Resource responsibilities**
  - Identity reviewers only perform Identity Check.
  - Document reviewers handle Document Intake and Document Check; substantive checks remain role-owned.
  - Assessors do not begin until both verification milestones are complete.
  - Legal reviewers own legal gate and supplement decision.

- **Legal/supplement handling**
  - After Assessment, legal-required cases route to Legal Review.
  - If Legal Review issues Request Supplement, reopen only affected document/identity milestones, then repeat Document Check and Assessment, then return to Legal Review.
  - Record supplement reason and whether early parallelism contributed.

- **Logging requirements**
  - Log assignment arm, eligibility rule, originals-required flag, legal-required flag, document channel, task creation time, actual start time, completion time, owner, lock override, and predecessor completion.
  - Log true overlap from start/end intervals, not creation timestamps.
  - Detect back-entry, owner conflicts, and illegal Document Check starts before originals receipt.

**Compact POWL-style partial order:**

```text
Register
  < {Identity Check, Document-readiness bundle}
Document-readiness bundle =
  XOR(
    Digital: Document Intake -> Document Check,
    Originals: {Originals Receipt, Document Intake} -> Document Check
  )
{Identity Check, Document-readiness bundle} < Assessment
Assessment < XOR(
  NonLegal: Approve | Reject,
  Legal: Legal Review -> XOR(
      Approve | Reject,
      Request Supplement -> Document Check repeat -> Assessment repeat -> Legal Review
    )
)
final decision < Notify
```

import pm4py

# 1. Site A process trees from the supplied process-tree strings
# ---------------------------------------------------------------------
pt_a_before = pm4py.parse_process_tree(
    "-> ( 'Register', 'Identity Check', 'Document Check', 'Assessment', "
    "X ( 'Approve', 'Reject' ), 'Notify' )"

pt_a_after = pm4py.parse_process_tree(
    "-> ( 'Register', + ( 'Identity Check', 'Document Check' ), 'Assessment', "
    "X ( 'Approve', 'Reject' ), 'Notify' )"

apn_a_before = pm4py.convert_to_petri_net(pt_a_before)

# ---------------------------------------------------------------------
# 2. Site B candidate POWL model
# ---------------------------------------------------------------------
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)

try:
    from pm4py.objects.powl.obj import Operator
except Exception:  # compatibility with versions exposing Operator elsewhere
    from pm4py.objects.process_tree.obj import Operator


def spo(nodes, edges=()):
    """Build a StrictPartialOrder and add explicit order edges."""
    obj = StrictPartialOrder(nodes=list(nodes))
    for u, v in edges:
        obj.order.add_edge(u, v)
    return obj


def xor(children):
    return OperatorPOWL(operator=Operator.XOR, children=list(children))


def loop(do_child, redo_child):
    # PM4Py LOOP operator: first child is the do-part, second the redo-part.
    return OperatorPOWL(operator=Operator.LOOP, children=[do_child, redo_child])


# Basic transitions

## 9. Recommendation

conditional go

Transfer the partial-order idea, not Site A’s package: create independent verification-related work as early as legally possible, measure genuine overlap, and prevent downstream flooding. Do not copy blanket creation of Document Check for every case; at B that would violate statutory ordering for 62% of originals cases and would be especially risky for 40% legal-review cases with supplement loops. Do not treat Site A’s nine-hour median reduction as an expected effect; it is confounded by mix, capacity, API, and huddles.

Enter first with digital-document, non-legal, low-complexity claims, where substantive Document Check can legally start at registration and where success depends mainly on task ownership and queue discipline. The legal/originals strata should remain on a guarded variant until the system can represent originals receipt as a predecessor of substantive document checking and can log supplements as repeat work; otherwise the apparent control-flow match is misleading.

Expected benefit is a modest reduction in waiting before Assessment and median cycle time, perhaps a few hours overall; p90 may improve if digital cases are currently queued late. Main risks are false overlap from back-entered events, case-lock workarounds that hide serial work, reassessment/legal congestion, and more rework or appeals if document quality falls. Freeze API, staffing, and routing changes during evaluation so the pilot can isolate the mechanism.

Expand only if the pilot shows high compliance with statutory prerequisites, true interval overlap, reduced verification waiting, stable WIP, no material increase in supplement/rework/appeal, and p90 not worsening. Modify toward document-intake parallelization and stricter WIP if assessment/legal queues absorb the gain. Abandon blanket parallelization if legal guards are breached, timestamp fidelity remains poor, or tail/rework deterioration exceeds pre-set thresholds.

## 10. Assumption register

1. B’s event logs can distinguish task creation from actual start/end — Needed to measure true overlap — Audit timestamps, owner events, and back-entry patterns — If false, apparent gains may be instrumentation artifacts.
2. Digital/non-originals cases can be reliably identified at Register — Needed for safe eligibility — Validate document-channel flag against completed cases — If false, illegal or premature checks will occur.
3. Originals Receipt completion can be recorded as a hard predecessor — Needed to enforce statutory ordering — Test guard rules in staging and pilot — If false, substantive checks may start too early.
4. Legal-required cases are known before Assessment — Needed to route to Legal Review — Validate public-sector/high-value flag — If false, legal loops will be missed and quality risk rises.
5. IT lock can be worked around without hiding serial execution — Needed for real concurrency — Test sub-task IDs and simultaneous ownership — If false, true overlap will remain low despite nominal parallelization.
6. Assessment and legal capacity remain fixed during the pilot — Needed to attribute effects — Freeze staffing and record all exceptions — If false, capacity changes will confound effects.
7. External originals-arrival delays are not simultaneously improved — Needed to isolate parallelization — Monitor receipt-delay distributions — If false, cycle-time gains may come from faster originals.
8. Rework and appeal outcomes mature within the observation window — Needed to assess quality — Use 90-day appeal follow-up and reason codes — If false, short-term speed may hide later harm.
