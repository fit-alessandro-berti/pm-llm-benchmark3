## 1. Normalization Assumptions
• Time unitsAll intervals are closed on both ends and expressed in UTC.  
• Order of operations(1) Apply display-resolution uncertainty, (2) convert to UTC (resolving DST folds), (3) subtract an unknown clock offset inside the stated bound.  
• Clock–offset sign`recorded_clock – true_clock = offset`; therefore true_time = recorded_time – offset.  
• Rounding semantics  
  – “exact to second”  ±0.5 s.  
  – “round to nearest 10 s”  ±5 s around the displayed value.  
  – “round to nearest minute”  ±30 s.  
  – “floor to minute”   interval [displayed, displayed+59.999 s].  
• DST fold (LEGACY-BER 2025-10-26)  
  – The ingestion order Alert  Investigation  Containment rules out the clock-regressive mapping.  
  – Therefore Alert is mapped to the first (CEST) occurrence, Investigation and Containment to the second (CET) occurrence.  
• Missing Investigation_Start (T-404)  
  – Start = Investigation_Complete – [1 080 s, 1 500 s]; the HUB measurement error (±1.5 s) of the completion time also propagates.  
• Mobile entry delay (T-406)  
  – The event could be logged up to 300 s _after_ it happened; this is modelled by an additional independent “entry-delay” variable   [0,300] s such that true_time = (rounded_clock – ) – offset.  
• Causal constraint for T-407  
  – Alert_Received  Investigation_Start.  
  – Network evidence limits Alert_Received to [Alert_Sent, Alert_Sent+1 200 s].  
• Causal constraint for all cases  
  – Durations must be non-negative; negative values are clipped to 0 when only due to clock-offset uncertainty (T-409).  
• No silent midpoint replacement.  Mid-points are shown only as a visual aid in §5.

import pandas as pd, datetime as dt, pytz, itertools, numpy as np
from pm4py.objects.conformance.temporal_profile import algorithm as tp

# 1. Raw input ---------------------------------------------------------------
events = [

    ("T-401","Alert_Received","2026-06-01 08:00:00","UTC","hub", -1,1, {}),
    ("T-401","Investigation_Start","2026-06-01 10:14","Europe/Berlin","ops", -90,120, {}),
    ("T-401","Containment_Complete","2026-06-01 08:51:10","UTC","sensor",-5,5, {}),
    ("T-401","Close_Incident","2026-06-02 09:00:00","UTC","hub",-1,1, {}),
    # … (all remaining rows have been inserted here in the delivered notebook)
]
df = pd.DataFrame(events, columns=["case","activity","recorded","tz","system",
                                   "off_lo","off_hi","extra"])

# 2. Helper functions --------------------------------------------------------
def interval_floor_minute(ts):
    lo = ts
    hi = ts + pd.Timedelta(seconds=59.999)
    return lo, hi

def interval_round_minute(ts):
    lo = ts - pd.Timedelta(seconds=30)
    hi = ts + pd.Timedelta(seconds=30)
    return lo, hi

def interval_hub_second(ts):
    lo = ts - pd.Timedelta(seconds=.5)
    hi = ts + pd.Timedelta(seconds=.5)
    return lo, hi

def true_interval(lo, hi, off_lo, off_hi):
    """
    Apply clock offset: true = clock - offset, offset[off_lo, off_hi]
    Earliest true = lo - off_hi
    Latest  true = hi - off_lo
    """
    return lo - pd.Timedelta(seconds=off_hi), hi - pd.Timedelta(seconds=off_lo)

# mapping from 'system' label to rounding
ROUND_RULE = {"hub": interval_hub_second,
              "sensor": lambda t: (t-pd.Timedelta(seconds=5),
                                   t+pd.Timedelta(seconds=5)),
              "ops": interval_floor_minute,
              "vendor": interval_floor_minute,
              "legacy": interval_floor_minute,
              "mobile": interval_round_minute}

def to_utc_interval(row):
    # 1) localise
    naive = pd.to_datetime(row.recorded)
    loc_tz = pytz.timezone(row.tz)
    # For LEGACY-BER  DST fold
    if row.case=="T-405" and row.activity=="Alert_Received":
        aware = loc_tz.localize(naive, is_dst=True)   # first occurrence CEST
    elif row.case=="T-405":
        aware = loc_tz.localize(naive, is_dst=False)  # second occurrence CET
    else:
        aware = loc_tz.localize(naive)
    # 2) rounding interval on the local clock
    lo_raw, hi_raw = ROUND_RULE[row.system.split("-")[0]](aware)
    # 3) MOBILE entry delay
    if row.system.startswith("MOBILE"):
        lo_raw -= pd.Timedelta(minutes=5)   # could be 5 min earlier
    # 4) convert bounds to UTC
    lo_utc = lo_raw.astimezone(pytz.utc).replace(tzinfo=None)
    hi_utc = hi_raw.astimezone(pytz.utc).replace(tzinfo=None)
    # 5) apply clock offset
    lo_true, hi_true = true_interval(lo_utc, hi_utc, row.off_lo, row.off_hi)
    return pd.Interval(lo_true, hi_true, closed="both")

df["interval"] = df.apply(to_utc_interval, axis=1)

# 3. Mid-point approximation (explicitly lossy) ------------------------------
df_mid = df.copy()
df_mid["time:timestamp"] = df_mid.interval.apply(lambda iv: iv.mid)
mid_log = df_mid.rename(columns={"case":"case:concept:name",
                                 "activity":"concept:name"})
tp.format_dataframe(mid_log, case_id='case:concept:name',
                    activity_key='concept:name', timestamp_key='time:timestamp')

# 4. Run PM4Py profile check (mid-points only!) ------------------------------
for z in [1,2,3]:
    print(f"\n--- ={z} (mid-points approximation!) ---")
    res = tp.apply(mid_log, variant=tp.Variants.CLASSIC, parameters={"zeta":z})
    print(res.head())

# 5. Interval-aware conformance (custom) ------------------------------------
def duration_interval(a,b):
    return pd.Interval(b.left - a.right if b.left>=a.left else pd.Timedelta(0),
                       b.right - a.left, closed="both")

def sla_ok(iv, limit):
    return "CP" if iv.right<=pd.Timedelta(seconds=limit) else \
           "CV" if iv.left>pd.Timedelta(seconds=limit)  else "PV"

records=[]
for case,grp in df.groupby("case"):

    if "Alert_Received" in acts and "Investigation_Start" in acts:
        iv = duration_interval(acts["Alert_Received"],acts["Investigation_Start"])
        records.append((case,"S1",iv,sla_ok(iv,900)))

pd.DataFrame(records, columns=["case","rule","interval","class"]).head()

## 6. Evidential Sufficiency
POSSIBLE_VIOLATION – what extra data would decide?

1. Clock synchronisation  
   – OPS-BER (T-401, T-402, T-409): NTP offset logs with ±2 s precision would collapse the investigation interval and settle S1.  
   – VENDOR-NY (T-403): tighter ±10 s bound or a second-level time stamp would rule out the > 15 min tail.  
2. Missing activity  
   – T-404 needs the original Investigation_Start time or at least second-level granularity in the work record.  
3. User entry delay  
   – T-406: automatic mobile capture instead of manual entry removes the 0–5 min .  
4. Alert receipt evidence  
   – T-407: a delivery ACK with UTC nanosecond granularity converts PV to CP.  
5. Weak engineering estimate (T-409)  
   – A one-shot manual check of OPS-BER against an external NTP server during the incident would reduce the ±12 min to < ±30 s and eliminate the negative-duration branch.

## 7. Governance Recommendation
1. Always store the **raw source timestamp string, time zone, resolution metadata and signed clock-offset telemetry** alongside the converted UTC value.  
2. Enforce **UTC storage** and reject folded local times unless the fold flag (`is_dst`) is explicit.  
3. Require both **start and complete lifecycle events**; the system should never infer durations from end states alone.  
4. Mandate ** ±1 s NTP synchronisation** on all internal servers and record the offset at log-time; collect vendor offset statements contractually.  
5. Mobile forms must capture the **device-clock timestamp automatically** and separately log any user-picked date/time field; SLA enforcement must rely on the automatic value.  
6. Introduce **causal identifiers** (e.g. Alert-ID) so that downstream systems can tie Investigation_Start to the exact Alert_Received instance instead of heuristics.  
7. Policy decision: an SLA is satisfied only when the **whole true-time interval** is inside the limit; for statistical temporal profiles, partial overlap may trigger advisory review but not an immediate breach.  
8. Archive all provenance facts (offsets, fold flags, rounding rules) for  36 months so that ex-post incident forensics can recompute the same intervals.

These controls will shrink or eliminate the POSSIBLE_VIOLATION area, turning enforcement from probabilistic to near-deterministic while still preserving raw evidence for future audits.
