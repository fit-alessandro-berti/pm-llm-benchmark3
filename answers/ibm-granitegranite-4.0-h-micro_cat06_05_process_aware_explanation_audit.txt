## 2. Process-model consistency checks

### Validation Suite
1. **Prefix-Time Availability Check**
   - **Alignment**: Verify that every feature used in prefix explanations is derived from events that occurred at or before `t0`.
   - **Limitation**: Historical features (e.g., `risk_score_current`) may have been updated post `t0` and should be flagged as unavailable.

2. **Activity-Order Feasibility Check**
   - **Alignment**: Ensure that event sequences in explanations respect the logical order of the claim process (e.g., `Coverage Check Completed` must precede any downstream event).
   - **Limitation**: Some sequence patterns may appear plausible but are actually impossible given the real process (e.g., `Appeal -> Settlement Decision Recorded` after `t0`).

3. **Same-Timestamp Ambiguity Resolution**
   - **Alignment**: Resolve ambiguities arising from events with identical timestamps by using reliable sequence indexes or timestamps.
   - **Limitation**: Lack of sequence index may lead to incorrect ordering; this must be addressed before interpretation.

4. **Complete-Trace Information Usage**
   - **Alignment**: Distinguish features that are derived from the complete trace from those that are strictly prefix-time features.
   - **Limitation**: Features like `full_trace_variant_id` should be clearly marked as post-t0 information and excluded from `t0` explanations.

5. **Legitimate Prefix-Derived Signals**
   - **Alignment**: Identify signals that are inherently process-derived at `t0` (e.g., `queue_length_at_t0`, `claimant_region`).
   - **Limitation**: Features that are only meaningful after certain process milestones (e.g., `final_handler_team`) should be excluded from `t0` explanations.

6. **Repetition of Settlement Decision Events**
   - **Alignment**: Confirm that explanations account for legitimate appeal-induced re-evaluations (e.g., `Appeal -> Settlement Decision Recorded`).
   - **Limitation**: Duplicate events must be properly contextualized to avoid misleading causal claims.

### Process-specific Checks
- **Claim Closed -> Damage Assessment Completed**: Verify that this transition is allowed and timely; otherwise, it should be excluded from breach risk explanations.
- **Appeal -> Settlement Decision Recorded**: Recognize that this is a legitimate feedback loop but not a causal predictor of breach risk; treat it as a process signal rather than a predictive driver.

## 5. Recommendations for explanation validation

1. **Feature-Store Design**
   - Implement a feature-store that captures feature values at `t0` and marks features as prefix-time or post-t0.
   - Ensure audit trails for all feature recomputations.

2. **Historical Feature Timestamps**
   - Store timestamps for all features, especially those derived from traces or snapshots, to resolve temporal ambiguities.

3. **Prefix-Only Recomputation**
   - Develop a pipeline that recomputes only prefix-time features using the final resolution timestamp, ensuring that no post-t0 data is included.

4. **Process-Conformance Tests**
   - Create tests that validate:
     - The chronological order of events.
     - The availability of features at `t0`.
     - The legitimacy of repeated events like `Settlement Decision Recorded`.

5. **Calibration After Feature Removal**
   - After removing or repairing features, recalibrate the model to ensure that the predictive performance remains stable.

6. **Explanation Stability**
   - Use version control for explanations and maintain a change log to track updates and ensure reproducibility.

7. **Proxy and Fairness Review**
   - Conduct regular fairness audits on features that may introduce bias (e.g., `claimant_region`).
   - Review the impact of correlated proxies on model decisions and adjust as necessary.

8. **Monitoring for Drift**
   - Implement continuous monitoring for feature drift and process drift to catch any changes in the underlying data or process that could affect model reliability.

By following these recommendations, the explanations can be made more credible, accurate, and aligned with the actual operational process, while also ensuring that any predictive insights are ethically sound and free from bias.
