# **Object-Centric Analysis of Job Coupling in Manufacturing**

## **1. Interaction-Graph Description**

### **Node Types**
The system comprises six core object types with distinct roles:
- **Jobs (J1–J6)**: Independent tasks requiring components, tools, and machines.
- **Components (C1–C6)**: Raw materials or subassemblies, often grouped in **ComponentLots (L7, L8)**.
- **Machines (CNC-2, OVEN-1, TEST-1)**: Process resources with limited capacity.
- **Tools (FIX-A, RACK-7, CAL-3)**: Fixtures, racks, and calibration devices with shared or exclusive use.
- **Batches (B1, B2)**: Groupings of jobs processed together (e.g., in OVEN-1).
- **Shipments (S1–S3)**: Consolidation points for dispatch.

### **Edge Types and Qualifiers**

### **Higher-Order Motifs**
1. **Batch Synchronization Motif**
   - **Jobs  Batch  Machine  Tool**
   - Example: J1, J2, J3  B1  OVEN-1  RACK-7
   - *Constraint*: All jobs in a batch must be ready before processing starts.

2. **Component-Lot Release Motif**
   - **ComponentLot  Job  Machine**
   - Example: L7 (C2, C5)  J2, J5  CNC-2 (if C2/C5 are blocked)
   - *Constraint*: Lot release events (e.g., 10:20 quarantine, 13:50 release) delay dependent jobs.

3. **Tool Contention Motif**
   - **Job  Tool  Job**
   - Example: J3 holds FIX-A (09:00–11:40), delaying J4’s CNC-2 use.
   - *Constraint*: Tools are not explicitly tracked in job logs, leading to hidden waits.

4. **Shipment Consolidation Motif**
   - **Job  Shipment  Job**
   - Example: J1 packed at 13:30, but S1 dispatches at 19:25 (waiting for J4).
   - *Constraint*: Early-ready jobs stall for late partners.

## **2. Quantitative Delay Decomposition**

### **1. Batch Synchronization Delay (J1, J2 in B1)**
- **Observed**: J1 ready at 08:10, batch starts at 12:05 (3h 55m wait).
- **Counterfactual**: If J1 could process immediately, delay = **3h 55m**.
- **Root cause**: Batch B1 requires all three jobs (J1, J2, J3) to be ready.
  - J3 arrives at 11:55, forcing a 10-minute delay for itself but 3h+ for J1/J2.
- **Calculation**:
  - J1’s wait = Batch start (12:05) – J1 ready (08:10) = **3h 55m**.
  - J2’s wait = 12:05 – 08:25 = **3h 40m**.

### **2. FIX-A Tool Contention Delay (J4)**
- **Observed**: J4 reaches CNC-2 at 09:50 but processes at 11:45.
- **Counterfactual**: If FIX-A were free at 09:50, J4 could start immediately.
- **Root cause**: J3 holds FIX-A until 11:40.
  - CNC-2 is idle (10:05–10:47), but FIX-A is unavailable.
- **Calculation**:
  - J4’s CNC-2 wait = 11:45 – 09:50 = **1h 55m**.
  - *Note*: Machine idle time (10:05–10:47) is misleading—tool unavailability is the true blocker.

### **3. Shipment Consolidation Delay (J1 in S1)**
- **Observed**: J1 packed at 13:30, S1 dispatches at 19:25.
- **Counterfactual**: If J1 could dispatch immediately, delay = **5h 55m**.
- **Root cause**: S1 requires J4 (packed at 19:10), which arrives late.
- **Calculation**:
  - J1’s shipment wait = 19:25 – 13:30 = **5h 55m**.

### **4. CAL-3 Calibration Delay (J6)**
- **Observed**: J6 ready for TEST-1 at 16:05, tests at 17:25.
- **Counterfactual**: If CAL-3 were pre-calibrated, J6 could test at 16:05.
- **Root cause**: CAL-3 recalibration (16:35–17:20) after J5’s test.
- **Calculation**:
  - J6’s TEST-1 wait = 17:25 – 16:05 = **1h 20m**.
  - *Note*: TEST-1 is idle (16:35–17:25), but CAL-3 is the bottleneck.

### **5. Component-Lot Release Delay (J5)**
- **Observed**: J5 cannot proceed until L7 is released at 13:50.
- **Counterfactual**: If L7 were released at 10:20 (quarantine end), J5 could start earlier.
- **Root cause**: Supervisor override for J2 (already in B1) bypassed release, but J5 was blocked.
- **Calculation**:
  - J5’s lot wait = 13:50 – (hypothetical 10:20) = **3h 30m** (if release were automatic).

## **4. What Flattening Misses**

| **Viewpoint**      | **Visible**                                                                 | **Hidden/Duplicated**                                                                 | **Misleading Conclusion**                                                                 |
|--------------------|-----------------------------------------------------------------------------|------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| **Job-flattened**  | Individual job steps (e.g., stagemachineinspect).                       | Batch synchronization, tool contention, lot release delays.                          | "No bottleneck" (all jobs are "normal").                                               |
| **Machine-flattened** | Machine utilization (54–58%), idle gaps (39–73m).                          | Tool unavailability, batch waits, shipment consolidation.                           | "Machines are underutilized" (ignores upstream delays).                                  |
| **Batch-flattened** | Batch processing times (e.g., B1 at 12:05).                                | Individual job waits within batches.                                                | "Batches are efficient" (hides J1/J2’s 3h+ waits).                                       |
| **Tool-flattened** | Tool usage (e.g., FIX-A held by J3).                                       | No explicit "wait for tool" events.                                                 | "Tools are rarely used" (misses contention).                                            |
| **ComponentLot-flattened** | Lot release events (10:20 quarantine, 13:50 release).                   | Impact on dependent jobs (e.g., J5).                                                | "Lots are released promptly" (ignores J5’s delay).                                       |
| **Shipment-flattened** | Dispatch times (e.g., S1 at 19:25).                                        | Job-level consolidation waits (e.g., J1’s 5h+ wait).                                | "Shipments are fast" (hides early job stalls).                                          |

### **Why Low Utilization Coexists with Long Waits**
- **Batch synchronization** forces jobs to wait for late arrivals (e.g., J1 waits for J3).
- **Tool contention** (e.g., FIX-A) creates hidden waits not reflected in machine logs.
- **Shipment consolidation** delays early jobs for late ones.
- **Machine-flattening** only sees machine events, not the upstream constraints that cause idle time.

## **5. Object-Lifecycle Narratives**

### **Narrative 1: Batch Synchronization  Tool Contention  Shipment Delay**
- **Temporal Precedence**:
  1. **08:10**: J1 ready for C1 (from L8).
  2. **08:25**: J2 ready for C2 (from L7).
  3. **11:55**: J3 ready for C3 (from L8).
  4. **12:05**: B1 starts on OVEN-1 (RACK-7).
- **Resource Feasibility**:
  - OVEN-1 is free at 12:05 (no machine constraint).
  - RACK-7 is available (no tool conflict here).
- **Policy Constraints**:
  - Batch policy requires all jobs to be ready.
  - J1/J2 wait 3h+ for J3.
- **Causal Speculation**:
  - If J3 arrived earlier, J1/J2 would have started sooner.
  - *But*: J3’s arrival time is exogenous (e.g., supplier delay).

### **Narrative 2: Component-Lot Quarantine  Job Blocking  Machine Idle**
- **Temporal Precedence**:
  1. **10:20**: L7 (C2, C5) quarantined.
  2. **13:50**: L7 released.
  3. **14:40**: J5 ready for C5 (but blocked until 13:50).
- **Resource Feasibility**:
  - CNC-2 is idle (10:05–10:47), but J5 cannot proceed due to lot status.
- **Policy Constraints**:
  - Lot release is manual; supervisor override for J2 bypasses rules.
- **Causal Speculation**:
  - If lot release were automatic, J5 could have started at 14:40.
  - *But*: J2’s override complicates causality (was it intentional?).

### **Narrative 3: Tool Calibration  Machine Idle  Shipment Delay**
- **Temporal Precedence**:
  1. **16:00**: J5 ready for TEST-1 (requires CAL-3).
  2. **16:10–16:35**: J5 tests (uses CAL-3).
  3. **16:35–17:20**: CAL-3 recalibrated.
  4. **17:25–17:50**: J6 tests (delayed by recalibration).
- **Resource Feasibility**:
  - TEST-1 is idle (16:35–17:25), but CAL-3 is unavailable.
- **Policy Constraints**:
  - Calibration is periodic; no alternative tool exists.
- **Causal Speculation**:
  - If CAL-3 were pre-calibrated, J6 could have tested at 16:05.
  - *But*: Calibration is a maintenance requirement, not a policy choice.

## **6. Intervention Portfolio and Spillovers**

| **Intervention**               | **Target Mechanism**       | **Expected Benefit**                          | **Helped Objects**               | **Harmed Objects**               | **New Cost/Risk**                          | **Perverse Incentive**                     | **Evaluation Design**                                                                 |
|--------------------------------|---------------------------|-----------------------------------------------|-----------------------------------|-----------------------------------|-------------------------------------------|--------------------------------------------|----------------------------------------------------------------------------------------|
| **Dynamic Batch Resizing**     | Batch synchronization     | Reduce J1/J2 waits by 3h+                     | J1, J2, B1                        | J3 (may face longer waits)        | Higher batch planning complexity         | Incentive to delay jobs to fill batches    | Track job-level batch wait times; compare to fixed batch sizes.                        |
| **Tool Reservation System**    | Tool contention (FIX-A)   | Eliminate J4’s 1h 55m wait                    | J4, J6                            | J3 (may face longer waits)        | Tool tracking overhead                | Incentive to hoard tools                    | Log tool acquisition/release times; measure CNC-2 idle time vs. tool waits.             |
| **Automated Lot Release**      | Component-lot release     | Reduce J5’s 3h 30m wait                       | J5, L7                            | None (if rules are fair)          | Integration with ERP system             | Incentive to bypass rules                    | Monitor lot release times vs. job start times.                                   |
| **Shipment Slack Reduction**   | Shipment consolidation    | Cut J1’s 5h 55m wait                           | J1, S1                            | J4 (may face longer processing)   | Higher dispatch coordination cost        | Incentive to delay jobs to meet deadlines  | Track job dispatch times vs. shipment readiness.                                  |
| **Pre-Calibration Scheduling** | CAL-3 calibration         | Reduce J6’s 1h 20m wait                       | J5, J6                            | TEST-1 (higher calibration freq)  | Maintenance downtime                 | Incentive to skip calibration               | Log calibration events vs. test delays.                                           |
| **Enhanced Logging (Tool Holds)** | Data-integration artifacts | Explicitly log tool waits                     | All jobs                          | None (better visibility)          | Data collection effort                  | None (pure observability)                 | Compare inferred vs. logged tool waits.                                           |

### **Spillover Analysis**
- **Dynamic Batch Resizing**:
  - *Helps*: J1/J2 (shorter waits).
  - *Harms*: J3 (may face longer waits if batch size increases).
  - *Risk*: Overloading OVEN-1 if batches grow too large.
- **Tool Reservation System**:
  - *Helps*: J4/J6 (no tool contention).
  - *Harms*: J3 (may face longer waits if tool is reserved).
  - *Risk*: Tool hoarding if reservations are not enforced.
- **Automated Lot Release**:
  - *Helps*: J5 (no manual delays).
  - *Harms*: None (if rules are fair).
  - *Risk*: Over-release if quality checks are bypassed.

## **8. Falsification and Additional Data**

### **Observations That Weaken Top Hypotheses**
1. **If batch delays were random**, J1/J2 would not consistently wait for J3.
   - *Falsification*: If J1/J2 sometimes start without J3, batch sync is not the primary cause.
2. **If FIX-A were never a bottleneck**, J4 would not wait 1h 55m.
   - *Falsification*: If J4 starts at 09:50 even with FIX-A held, tool contention is minor.
3. **If lot release were automatic**, J5 would not wait until 13:50.
   - *Falsification*: If J5 starts at 14:40 despite quarantine, lot release is not the issue.
4. **If shipment delays were uniform**, all jobs in S1 would wait equally.
   - *Falsification*: If J4’s delay does not affect J1, consolidation is not the main issue.
5. **If CAL-3 were redundant**, J6 would not wait for recalibration.
   - *Falsification*: If TEST-1 can test without CAL-3, calibration is not the bottleneck.
6. **If machine utilization were >80%**, capacity would be the primary constraint.
   - *Falsification*: If CNC-2/OVEN-1 hit 90% utilization, coupling is less relevant.

### **Additional Fields/Event Types Needed**
1. **Explicit "Wait for Tool" events** (instead of inferred holds).
2. **Batch readiness timestamps** (when all jobs in a batch are ready).
3. **Tool calibration schedules** (predictive, not reactive).
4. **Lot release triggers** (automatic vs. manual overrides).
5. **Shipment partner readiness** (when all jobs in a shipment are packed).
6. **Machine setup times** (distinguish from tool waits).
7. **Job priority flags** (to explain supervisor overrides).
8. **ComponentLot quality checks** (to explain quarantine delays).

### **Final Synthesis**
The system’s delays stem from **policy-induced coupling** (batches, shipments) and **hidden resource contention** (tools, lots). Traditional flattenings obscure these because:
- **Jobs** appear independent (no single bottleneck).
- **Machines** are underutilized but idle due to upstream waits.
- **Tools/Lots/Shipments** are not explicitly modeled in job logs.

**Top interventions** should target:
1. **Batch synchronization** (dynamic resizing).
2. **Tool tracking** (explicit logging).
3. **Automated lot release** (reduce manual delays).
4. **Shipment slack reduction** (prioritize early jobs).
5. **Calibration scheduling** (prevent TEST-1 idle time).

**PM4Py confirms** that object-centric analysis reveals delays invisible in traditional process mining. The key insight: **coupling is not just shared resources—it’s policy, data gaps, and hidden constraints.**
