# 1. Executive Verdict

- **Workflow net:** yes. There is one source place (`source`), one sink place (`sink`), and every node lies on a source-to-sink path.
- **Sound:** no. The net is safe and has no dead transition, but it violates both the option to complete and proper completion.
- **Principal defect:** `t_join_waived` is not a join. It consumes only `p_waived`, so the analysis token created by `t_split` is never synchronized on the waiver route.
- **Business consequence:** after a waiver, `t_authorize` can fire while `p_analysis` is still marked, so a case can be authorized before, or without, the mandatory analysis. In addition, no waiver case can ever reach `fm = [sink]`, because a token is stranded in `p_analysis` or `p_analysis_done`. Only standard-review cases complete properly.

# 2. Structural Diagnosis

Notation: `•x` is the preset and `x•` the postset of a node; `[a, b]` is the marking with one token in each of `a` and `b`.

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source` → `t_register` → `p_ready` | Case entry | Correct sequential prefix; `source` has no input arc. | None. |
| `t_split` (silent) | AND-split that starts analysis and review in parallel | Produces one token in `p_analysis` and one in `p_review`. Both must later be consumed by the same synchronization. | None by itself; it creates the obligation that the joins must honour. |
| `p_analysis` → `t_analyze` → `p_analysis_done` | Mandatory analysis | `p_analysis_done• = {t_join_normal}`: the completed analysis has exactly one consumer. | The analysis token can leave the branch only if `p_review_done` is also marked. |
| `p_review` → `t_standard_review` → `p_review_done` | Standard review outcome | Free choice with the waiver on `p_review`; the result feeds `t_join_normal`. | None. |
| `p_review` → `t_waive_review` → `p_waived` | Recorded waiver outcome | Consumes the only review token, so `p_review_done` can never be marked afterwards. | From here on `t_join_normal` is permanently disabled. |
| `t_join_normal` (silent) | AND-join of analysis and standard review | `•t = {p_analysis_done, p_review_done}`: a correct two-input join. | Correct on the standard route, unusable on the waiver route. |
| `t_join_waived` (silent) | AND-join of analysis and waiver | `•t = {p_waived}` only. It is a one-input pass-through, not a join: it puts a token in `p_decision` without consuming anything from the analysis branch. | Authorization is enabled independently of analysis; the analysis token is orphaned. |
| `p_decision` → `t_authorize` → `sink` | Authorization after both branches are done | `•p_decision = {t_join_normal, t_join_waived}`, so the guard "analysis done" holds only for one of the two producers. | `sink` is marked while another place still holds a token. |
| `im = [source]`, `fm = [sink]` | One case in, one clean completion out | Consistent with a workflow net; `fm` demands that no other token remains. | On the waiver route a marking that covers `fm` is reached, but never `fm` itself. |
| Source-to-sink connectivity | Every node contributes to completion | Every node is on a path, for example `source, t_register, p_ready, t_split, p_analysis, t_analyze, p_analysis_done, t_join_normal, p_decision, t_authorize, sink`, and likewise through `p_review`, `t_standard_review`, `p_review_done`, and through `t_waive_review`, `p_waived`, `t_join_waived`. | The workflow-net check passes, which is why the defect is easy to miss. |

Two structural facts follow directly from the arcs and predict the behavior before any firing is simulated.

1. **The review branch is token-conserving, the analysis branch is not.** The sum `source + p_ready + p_review + p_review_done + p_waived + p_decision + sink` is unchanged by every transition, so it is always 1. No comparable invariant gives a positive weight to `p_analysis` or `p_analysis_done`. A weight vector `w` would need `w(p_analysis_done) + w(p_review_done) = w(p_decision)` for `t_join_normal` and `w(p_waived) = w(p_decision)` for `t_join_waived`, while the review choice forces `w(p_review_done) = w(p_waived)`. This yields `w(p_analysis_done) = w(p_analysis) = 0`. The analysis places are therefore covered by no positive place invariant and no S-component.
2. **The net is free-choice** (`p_review` is the only place with two consumers, and both have the preset `{p_review}`). The problem is therefore not a confused choice but a missing synchronization arc.

# 3. Marking-Based Counterexample

## Counterexample 1: authorization before analysis, then a stranded token

Firing sequence:

`σ1 = ⟨t_register, t_split, t_waive_review, t_join_waived, t_authorize, t_analyze⟩`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | none (start) | `[source]` | `t_register` | This is `im`. |
| 1 | `t_register` | `[p_ready]` | `t_split` | Case registered. |
| 2 | `t_split` | `[p_analysis, p_review]` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token is created in each parallel branch. |
| 3 | `t_waive_review` | `[p_analysis, p_waived]` | `t_analyze`, `t_join_waived` | The waiver is chosen and the only review token is consumed. `t_join_waived` is enabled although the analysis has not run. |
| 4 | `t_join_waived` | `[p_analysis, p_decision]` | `t_analyze`, `t_authorize` | The "join" consumed nothing from the analysis branch. Authorization and analysis are now concurrent. |
| 5 | `t_authorize` | `[p_analysis, sink]` | `t_analyze` | `t_authorize` fires before `t_analyze`. A token exists in `sink`, but the marking is not `fm = [sink]`. |
| 6 | `t_analyze` | `[p_analysis_done, sink]` | none | The analysis runs after authorization. The marking is dead and still not `fm`. |

Three points need to be kept apart.

- **Token in the sink versus final marking.** Steps 5 and 6 mark `sink`, but both markings strictly cover `fm`. An engine that treats "sink is marked" as completion would report the case as finished after step 5 with the visible trace ⟨Register Case, Record Review Waiver, Authorize Case⟩. Under accepting-net semantics that trace is not accepted, because `fm` is never reached.
- **Why the leftover token cannot be consumed.** The only consumer of `p_analysis_done` is `t_join_normal`, which also needs `p_review_done`. The only producer of `p_review_done` is `t_standard_review`, which needs `p_review`. The invariant from Section 2 says the review branch holds exactly one token, and that token is now in `sink`, which has no output arc. So `p_review_done` stays empty forever and `t_join_normal` is dead from step 3 onward.
- **The leftover token in `p_analysis` at step 5 can still move** (`t_analyze` is enabled), but only into `p_analysis_done`, where the previous argument applies. Firing `t_analyze` changes where the token is stranded, not whether it is stranded.

## Counterexample 2: analysis first, still no proper completion

Reordering the analysis in front of the waiver removes the business-rule violation but not the unsoundness.

`σ2 = ⟨t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize⟩`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | none (start) | `[source]` | `t_register` | This is `im`. |
| 1 | `t_register` | `[p_ready]` | `t_split` | |
| 2 | `t_split` | `[p_analysis, p_review]` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token per branch. |
| 3 | `t_analyze` | `[p_analysis_done, p_review]` | `t_standard_review`, `t_waive_review` | Analysis is complete before any review decision. |
| 4 | `t_waive_review` | `[p_analysis_done, p_waived]` | `t_join_waived` | `t_join_normal` is not enabled because `p_review_done` is empty. |
| 5 | `t_join_waived` | `[p_analysis_done, p_decision]` | `t_authorize` | The completed-analysis token is ignored. |
| 6 | `t_authorize` | `[p_analysis_done, sink]` | none | `t_authorize` fires after `t_analyze` this time, yet the marking is dead and is not `fm`. |

So `t_authorize` can occur either before or after `t_analyze` on the waiver route, and in both orders `fm` is unreachable.

## The complete reachable state space

The net is small enough to enumerate by hand. There are 14 reachable markings:

| Id | Marking | Successors |
|---|---|---|
| M0 | `[source]` | `t_register` → M1 |
| M1 | `[p_ready]` | `t_split` → M2 |
| M2 | `[p_analysis, p_review]` | `t_analyze` → M3, `t_standard_review` → M4, `t_waive_review` → M5 |
| M3 | `[p_analysis_done, p_review]` | `t_standard_review` → M6, `t_waive_review` → M7 |
| M4 | `[p_analysis, p_review_done]` | `t_analyze` → M6 |
| M5 | `[p_analysis, p_waived]` | `t_analyze` → M7, `t_join_waived` → M8 |
| M6 | `[p_analysis_done, p_review_done]` | `t_join_normal` → M9 |
| M7 | `[p_analysis_done, p_waived]` | `t_join_waived` → M10 |
| M8 | `[p_analysis, p_decision]` | `t_analyze` → M10, `t_authorize` → M11 |
| M9 | `[p_decision]` | `t_authorize` → M12 |
| M10 | `[p_analysis_done, p_decision]` | `t_authorize` → M13 |
| M11 | `[p_analysis, sink]` | `t_analyze` → M13 |
| M12 | `[sink]` = `fm` | none |
| M13 | `[p_analysis_done, sink]` | none |

That is 14 markings and 17 arcs. Read against the soundness conditions:

- **Option to complete is violated.** `fm` (M12) is unreachable from M5, M7, M8, M10, M11 and M13, which are exactly the six markings reached after `t_waive_review`.
- **Proper completion is violated.** M11 and M13 mark `sink` together with another place.
- **No dead transitions.** Every transition fires somewhere in the table, so this condition holds.
- **Boundedness holds.** Every reachable marking is 1-safe.

The accepted visible language is therefore only ⟨Register Case, Perform Analysis, Perform Standard Review, Authorize Case⟩ and ⟨Register Case, Perform Standard Review, Perform Analysis, Authorize Case⟩. The waiver exists in the model but can never complete properly.

# 4. Minimal-Repair Alternatives

## Edit-cost model

- Each added arc, removed arc, added place, removed place, added transition, removed transition, or changed label costs 1.
- Removing a node requires removing its incident arcs first, and each of those is charged. Redirecting an arc is one removal plus one addition, so it costs 2.
- `im` and `fm` are part of the specification and may not be edited.
- A candidate counts as a repair only if the result is a workflow net and is sound for `im` and `fm`.
- A repair is **policy-preserving** if its accepted visible language is exactly the four intended traces: Register Case, then Perform Analysis interleaved with exactly one of Perform Standard Review or Record Review Waiver, then Authorize Case. Anything else is a policy change and is labelled as such.

## Repairs

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1: proper two-input waiver join** | Add arc `p_analysis_done → t_join_waived`. | 1 | Everything. Analysis is mandatory on both routes, analysis and review stay concurrent, and waiver and standard review stay separate transitions and separate places. | Only the defective runs disappear. `t_join_waived` now waits for `p_analysis_done`. The accepted language is exactly the four intended traces. | The net is no longer free-choice: `t_join_normal` and `t_join_waived` share `p_analysis_done` but have different presets. They are never enabled together today because `p_review_done` and `p_waived` are mutually exclusive, but the rule "analysis is required" is now encoded twice, once per join. A future third review outcome needs its own join and can repeat this bug. |
| **R2: route the waiver into the normal synchronization** | Remove arc `t_join_waived → p_decision`. Add arc `t_join_waived → p_review_done`. | 2 | Everything, with the same accepted language as R1. The net stays free-choice. `p_waived` survives as a recorded waiver state. | `t_join_normal` becomes the single synchronization point and the only producer of `p_decision`. `t_join_waived` becomes a silent pass-through that converts "waived" into "review outcome available". | The name `t_join_waived` is now misleading. The pass-through can fire before or after `t_analyze`, which adds an invisible interleaving. After it fires, the marking no longer shows which review outcome was chosen. |
| **R3: waiver only after completed analysis** (policy restriction) | Add arc `p_analysis_done → t_waive_review`. | 1 | Analysis is mandatory on every route and authorization follows both. | **Policy change:** a waiver can be recorded only after the analysis is finished, so the trace ⟨Register Case, Record Review Waiver, Perform Analysis, Authorize Case⟩ is no longer possible. The standard review stays concurrent with the analysis. | The two review outcomes become asymmetric. A reviewer who already knows the review will be waived must wait for the analysis. The net is not free-choice, and `t_join_waived` is left as a redundant silent step. |
| **R4: analysis optional under waiver** (policy change) | Add arc `p_analysis → t_waive_review`. | 1 | The standard route is unchanged; the waiver is still formally recorded. | **Policy change:** recording the waiver cancels the pending analysis, so ⟨Register Case, Record Review Waiver, Authorize Case⟩ is accepted and analysis is not mandatory. The waiver is available only while the analysis has not yet been performed; once `t_analyze` has fired, only the standard review is possible. | This violates the stated intent unless the business explicitly adopts it. Whether a waiver is possible depends on a race with the analysis, and the net is not free-choice. |

## Minimality

**Lower bound.** Cost 0 is the original net, which is unsound, so every repair costs at least 1.

**All cost-1 edits.** There are four kinds.

- *Add a node.* An isolated place is a second source and sink, and an isolated transition is on no path, so the result is not a workflow net.
- *Remove a node.* Every node has incident arcs, so this costs more than 1.
- *Remove an arc.* Each of the 18 arcs is either the only incoming arc of its target or the only outgoing arc of its source. Removing it leaves a node that cannot be reached from `source` or cannot reach `sink`, so the result is not a workflow net.
- *Add an arc.* There are 9 × 8 × 2 − 18 = 126 candidate arcs. I enumerated all of them with the workflow-net and soundness checks of Section 6 and cross-checked with an explicit state-space search. Exactly three give a sound workflow net: R1, R3 and R4. This is an exhaustive enumeration, not a closed-form proof.

**Why R1, R3 and R4 tie.** Each one adds a single arc that forces the analysis token to be consumed on the waiver route. They differ only in which analysis place is consumed (`p_analysis` or `p_analysis_done`) and by which waiver transition (`t_waive_review` or `t_join_waived`). The cost model cannot separate them, so the policy criterion does: R1 is the only one whose accepted language equals the intended four traces. R3 drops one intended trace and R4 admits a forbidden one. R1 is therefore the unique minimal policy-preserving repair.

**Why R2 is listed at cost 2.** It is not globally minimal. It is minimal within its family: sending the waiver through the normal synchronization needs at least one removal (the waiver route's direct access to `p_decision`) and one addition (a route into `p_review_done`). Because all three cost-1 repairs break the free-choice property, R2 is also the cheapest policy-preserving repair that keeps the net free-choice. The more obvious variant of this family, connecting `t_waive_review` directly to `p_review_done` and deleting `p_waived` and `t_join_waived`, costs 6 (three arcs removed, one place removed, one transition removed, one arc added) for the same language.

R1 and R2 are language-equivalent and differ structurally. R3 and R4 differ from them, and from each other, in accepted language.

# 6. Diagnostic and Reachability Code

The block assumes `net`, `im`, `fm`, `repaired_net`, `repaired_im` and `repaired_fm` exist. `fire` refuses to fire a transition that `pm4py.get_enabled_transitions` does not report as enabled. In recent PM4Py releases `check_soundness` returns a tuple whose first element is the verdict and emits a deprecation warning; the code accepts either a tuple or a plain boolean.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def fmt(marking):
    """Nonzero marking as a readable, deterministic string."""
    items = sorted((p.name, n) for p, n in marking.items() if n > 0)
    return "{" + ", ".join(f"{name}:{n}" for name, n in items) + "}"


def enabled_names(pn, marking):
    return sorted(t.name for t in pm4py.get_enabled_transitions(pn, marking))


def fire(pn, marking, t_name):
    """Fire the transition called t_name; refuse if it is not enabled."""
    t = next((x for x in pn.transitions if x.name == t_name), None)
    if t is None:
        raise ValueError(f"no transition named {t_name!r}")
    if t not in pm4py.get_enabled_transitions(pn, marking):
        raise RuntimeError(f"{t_name} is NOT enabled in {fmt(marking)}")
    new = Marking()
    for p, n in marking.items():
        if n > 0:
            new[p] = n
    for arc in t.in_arcs:
        new[arc.source] -= arc.weight
        if new[arc.source] == 0:
            del new[arc.source]
    for arc in t.out_arcs:
        new[arc.target] += arc.weight
    return new


def replay(pn, initial, final, sequence, title):
    print(f"\n--- {title}")
    m = initial
    print(f"{'(initial)':<20} {fmt(m):<36} enabled={enabled_names(pn, m)}")
    for name in sequence:
        try:
            m = fire(pn, m, name)
        except RuntimeError as exc:
            print(f"BLOCKED: {exc}")
            break
        print(f"{name:<20} {fmt(m):<36} enabled={enabled_names(pn, m)}")
    sink_marked = any(p.name == "sink" and n > 0 for p, n in m.items())
    print(f"token in sink: {sink_marked} | exact final marking reached: {m == final} "
          f"| dead: {not enabled_names(pn, m)}")
    return m


def explore(pn, initial, final, limit=10_000):
    """Explicit state space: improper completions and markings that cannot reach `final`."""
    seen, todo, preds = {fmt(initial): initial}, [initial], {}
    while todo:
        m = todo.pop()
        for t in pm4py.get_enabled_transitions(pn, m):
            nxt = fire(pn, m, t.name)
            preds.setdefault(fmt(nxt), set()).add(fmt(m))
            if fmt(nxt) not in seen:
                if len(seen) >= limit:
                    raise RuntimeError("state limit exceeded (unbounded net?)")
                seen[fmt(nxt)] = nxt
                todo.append(nxt)
    can_finish, todo = {fmt(final)} & set(seen), [fmt(final)]
    while todo:
        for prev in preds.get(todo.pop(), ()):
            if prev not in can_finish:
                can_finish.add(prev)
                todo.append(prev)
    improper = sorted(k for k, m in seen.items()
                      if m != final and any(p.name == "sink" and n > 0 for p, n in m.items()))
    return len(seen), sorted(set(seen) - can_finish), improper


def diagnose(pn, initial, final, title):
    print(f"\n================ {title} ================")
    print("workflow net:", pm4py.check_is_workflow_net(pn))
    result = pm4py.check_soundness(pn, initial, final, print_diagnostics=True)
    print("sound:", result[0] if isinstance(result, tuple) else result)
    print("enabled in initial marking:", enabled_names(pn, initial))
    ts = pm4py.convert_to_reachability_graph(pn, initial, final)
    print("reachability graph:", len(ts.states), "states,", len(ts.transitions), "arcs")
    print("states without successor:", sorted(s.name for s in ts.states if not s.outgoing))
    n, stuck, improper = explore(pn, initial, final)
    print("markings explored by helper:", n)
    print("markings that cannot reach the final marking:", stuck)
    print("markings with a sink token plus other tokens:", improper)


WAIVE_THEN_AUTHORIZE_EARLY = ["t_register", "t_split", "t_waive_review",
                              "t_join_waived", "t_authorize", "t_analyze"]
ANALYZE_THEN_WAIVE = ["t_register", "t_split", "t_analyze", "t_waive_review",
                      "t_join_waived", "t_authorize"]
WAIVE_THEN_ANALYZE = ["t_register", "t_split", "t_waive_review", "t_analyze",
                      "t_join_waived", "t_authorize"]
STANDARD = ["t_register", "t_split", "t_standard_review", "t_analyze",
            "t_join_normal", "t_authorize"]

diagnose(net, im, fm, "ORIGINAL")
replay(net, im, fm, WAIVE_THEN_AUTHORIZE_EARLY, "original: authorize before analysis")
replay(net, im, fm, ANALYZE_THEN_WAIVE, "original: analysis first, waiver, residual token")
replay(net, im, fm, STANDARD, "original: standard review (the only proper completion)")

diagnose(repaired_net, repaired_im, repaired_fm, "REPAIRED (R1)")
replay(repaired_net, repaired_im, repaired_fm, WAIVE_THEN_AUTHORIZE_EARLY,
       "repaired: the counterexample must now be blocked at t_join_waived")
replay(repaired_net, repaired_im, repaired_fm, WAIVE_THEN_ANALYZE, "repaired: waiver, then analysis")
replay(repaired_net, repaired_im, repaired_fm, ANALYZE_THEN_WAIVE, "repaired: analysis, then waiver")
replay(repaired_net, repaired_im, repaired_fm, STANDARD, "repaired: standard review")
```

## Expected qualitative difference

| Check | Original net | Repaired net (R1) |
|---|---|---|
| `pm4py.check_is_workflow_net` | `True` | `True` |
| `pm4py.check_soundness` | Not sound. The diagnostics should point at the analysis branch, whose places are not covered by a positive place invariant or S-component (Section 2). | Sound. All places are covered by the two S-components (analysis branch and review branch), and no transition is dead. |

| Markings that cannot reach `fm` | Six (M5, M7, M8, M10, M11, M13) | None |
| Markings with a sink token plus other tokens | Two (M11, M13) | None |
| Replay of `σ1` | Runs to the end and stops dead in `[p_analysis_done, sink]`. | Blocked at `t_join_waived` in `[p_analysis, p_waived]`. |

The state-space sizes follow from the table in Section 3. The original has 14 markings and 17 arcs. R1 removes the four markings that exist only because of the premature join (M8, M10, M11, M13) and the six arcs touching them, and replaces `M7 → M10` by `M7 → M9`. That leaves 10 markings and 17 − 6 + 1 = 12 arcs.

The workflow-net check does not distinguish the two nets. Only the behavioral checks do.

# 7. Repair Trade-Offs and Residual Risks

**Are waiver and standard review still distinguishable?**
In all four repairs they keep distinct visible transitions and labels, so an event log tells them apart. In the marking, R1 keeps them apart until the join (`p_review_done` versus `p_waived`); R2 keeps `p_waived` only until the silent pass-through fires. In every variant, including the original, the distinction is gone once `p_decision` is marked. If authorization must ever depend on the outcome, for example an extra sign-off for waived cases, separate decision places or separate authorization transitions are needed. None of these repairs provides that.

**Silent transitions, duplicate behavior and confusion.**

- R1 has three silent transitions (`t_split` and the two joins). The joins share `p_analysis_done`, which is a structural conflict, but the invariant on the review branch means at most one of `p_review_done` and `p_waived` is ever marked. The conflict is never a behavioral choice and each accepted trace has exactly one run. The risk is latent: a later change that allows both places to be marked in one case, such as a rework loop or a second review, turns it into a real conflict and strands a token again.
- R2 has no shared input places. Its silent pass-through can fire before or after `t_analyze`, which gives two runs for the same visible trace. That is harmless for the language, but alignments are no longer unique and the transition name suggests a join that no longer exists. It should be renamed at a cosmetic cost of 1.
- No repair introduces duplicate labels.

**Does soundness prove alignment with the business rule?**
No. R3 and R4 are both sound, yet R3 forbids an intended trace and R4 accepts ⟨Register Case, Record Review Waiver, Authorize Case⟩, the very bypass the rule prohibits. Soundness says every case can finish cleanly and no transition is dead. It says nothing about which traces are allowed. Conversely, the original net never accepts a trace that authorizes without analysis, yet it is the net that lets `t_authorize` fire first. Both soundness and a language check against explicit positive and negative traces are needed.

**Regression traces.** With silent transitions in the model, alignment-based replay is the appropriate check: fitness 1 for positive traces, below 1 for negative ones.

Positive traces, which must reach exactly `fm`:

1. Register Case, Perform Analysis, Perform Standard Review, Authorize Case
2. Register Case, Perform Standard Review, Perform Analysis, Authorize Case
3. Register Case, Perform Analysis, Record Review Waiver, Authorize Case
4. Register Case, Record Review Waiver, Perform Analysis, Authorize Case

Negative traces, which must be rejected:

1. Register Case, Record Review Waiver, Authorize Case (analysis bypassed)
2. Register Case, Record Review Waiver, Authorize Case, Perform Analysis (analysis after authorization)
3. Register Case, Perform Standard Review, Authorize Case (analysis bypassed on the standard route)
4. Register Case, Perform Analysis, Authorize Case (no review outcome)
5. Register Case, Perform Analysis, Perform Standard Review, Record Review Waiver, Authorize Case (both outcomes)
6. Register Case, Perform Analysis, Record Review Waiver (no authorization)
7. Register Case, Perform Analysis, Record Review Waiver, Authorize Case, Authorize Case (double authorization)

Positive trace 4 separates R1 and R2 from R3. Negative trace 1 separates them from R4 and from an engine that treats a marked sink as completion.

**Detecting an accidental bypass of mandatory analysis.**

- *Structural lint.* Every transition that produces into `p_decision` must consume from `p_analysis_done`. Equivalently, `source + p_ready + p_analysis + p_analysis_done + p_decision + sink` must be a place invariant. The original net fails this at `t_join_waived`; R1 and R2 pass.
- *Behavioral check.* Explore the state space with `t_analyze` disabled and assert that `t_authorize` is never enabled and `sink` is never marked. The original net fails via ⟨`t_register`, `t_split`, `t_waive_review`, `t_join_waived`, `t_authorize`⟩.
- *Completion check.* Assert that no reachable marking has a sink token together with any other token. This is what the `explore` helper reports.
- *Runtime monitoring.* Check the precedence rule "every Authorize Case is preceded by Perform Analysis in the same case" on the event log, and alert on cases whose authorization timestamp is earlier than the analysis completion.

**Residual risks outside the scope of these repairs.** The net has no rejection path, no rework and no cancellation, and the choice between review and waiver is unguarded. If any of these exist in the real process, the repaired net is sound but incomplete.

# 8. Final Recommendation

**Deploy R1** (add the arc `p_analysis_done → t_join_waived`).

It is the unique minimal policy-preserving repair: one added arc, no removed element, no renamed node, no changed label. It turns the waiver join into the two-input synchronization its name already claims. The accepted language becomes exactly the four intended traces, the net is sound, analysis and review stay concurrent, and existing references to places and transitions remain valid. The counterexample is blocked at the right point: `t_join_waived` is not enabled in `[p_analysis, p_waived]`.

**Keep R2 as the fallback** (redirect the output of `t_join_waived` from `p_decision` to `p_review_done`).

It costs one edit more and has the same language, with two advantages that matter in some environments. The net stays free-choice, which some analysis and conversion tools expect. The rule "authorization requires analysis" is enforced at a single join, so a future third review outcome only has to feed `p_review_done` and cannot repeat this defect. Choose R2 if the model is expected to grow or tooling requires a free-choice net, and rename the pass-through transition when doing so.

R3 and R4 should not be deployed as repairs. They are equally cheap and sound, but they change the policy: R3 delays waivers until the analysis is finished, and R4 makes the analysis optional. They are options only if the process owner explicitly changes the rule.

Ship either repair with the regression traces and bypass checks of Section 7, because soundness alone does not confirm the business rule.
