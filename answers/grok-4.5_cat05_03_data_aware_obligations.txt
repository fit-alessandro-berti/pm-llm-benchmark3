## 1. Temporal Data Semantics

State is reconstructed **forward-only per case** in `(time:timestamp, event_index)` order. A blank attribute cell means “no update at this event,” not nulling; the last non-blank value remains in force until a later event writes a new one. Final case attributes are never copied backward: each obligation is judged on the snapshot known at that event’s timestamp (and index).

**Time kinds distinguished**
- **Event time**: `time:timestamp` of the log row (process occurrence).
- **Effective time**: when a fact/exemption legally binds (may be stated in evidence; defaults to event time if not contradicted).
- **Record time**: when a system row was inserted (e.g., late `Record_Exemption`).
- **Evidence time**: cryptographic/signature/witness times that support or undermine claimed effective time.

Equal timestamps are ordered by `event_index` (source-system order). Consequence: an attribute write with higher `event_index` at the same timestamp is **not** visible to a sibling event with lower index (TX-311: Enhanced_Review precedes jurisdictionDE).

**Material change (R4)**  
Only an amount **increase > 20%** after the latest Standard_Review or Enhanced_Review invalidates that review for amount-dependent duties. Decreases do not. Increase from an unknown prior amount is not safely classifiable (R4/R6). Risk, jurisdiction, and customer_type changes are treated as material for the rules that depend on them (R1–R3) at the next obligation check, using the post-change snapshot.

Late database inserts may corroborate earlier approval only when independent evidence (qualified signature timestamp, outage documentation) supports it; a displayed backdated field alone is not conclusive (R5).

## 2. Normalized Rule Table

| Rule | Trigger event and condition | Required prior/subsequent event | Ordering constraint | State snapshot used | Exception | Missing-data treatment | Evidence needed |
|------|----------------------------|----------------------------------|---------------------|---------------------|-----------|------------------------|-----------------|
| R1 | `Release_Funds` where `jurisdiction  DE`  `amount  100000` | `Enhanced_Review` completed | ER after latest material data change and before release | At release (amount, jurisdiction); material-change time | Matching valid exemption (R5) waiving R1 | If amount or jurisdiction unknown  INDETERMINATE unless exemption clearly covers or other evidence resolves | ER event; or exemption scope+approval+timing |
| R2 | `Release_Funds` where `risk_level=HIGH`  `customer_type=PEP` | `Enhanced_Review` and `Compliance_Approve` | ER before CA before release; ER after relevant material change for amount-dependent parts | At release (risk, customer_type, amount) | None in policy (exemption register waives R1 only) | If risk and customer_type both unknown  INDETERMINATE | ER + CA events; CA must not be only “standard packet” if ER absent |
| R3 | `Release_Funds` where jurisdiction was added to sanctions list after latest `Sanctions_Screen` and before release | New `Sanctions_Screen` | Screen after `Sanctions_List_Update` and before release | Jurisdiction at release; list-update and screen times | None stated | If jurisdiction unknown across screen/update/release window  INDETERMINATE | Screen + list-update events with jurisdiction |
| R4 | Amount increase >20% after latest SR/ER | Invalidates that review for amount-dependent obligations | Compare pre-review amount to later amount at/before release | Amount trajectory vs review times | Decrease does not invalidate; unknownincrease not safely classifiable | Unknown baseline amount  do not assume validity or invalidity | Amount update events + review timestamps |
| R5 | Exemption cited for an obligation | Approval by Head_Compliance; scope match; unexpired | `effective_from`  obligation trigger; not expired at trigger; approval existed at trigger | Scope vs release snapshot; times vs release | — | Incomplete scope/times  cannot grant exception | Approval identity, effective/expiry, scope, signature/evidence times |
| R6 | Any decisive predicate missing | — | — | — | — | INDETERMINATE if trigger cannot be established or excluded | Downstream immutable amounts only if explicitly bound to release |
| R7 | Every obligation evaluation | — | event_index tie-break on equal timestamps | Latest known value at event, not final case state | — | Blanks = no update | Ordered log + explicit same-ts policy |

**Concise formal pseudo-logic**

```text
State(c,e) = forward-fill attributes of case c over events  e ordered by (ts, event_index)

MaterialAmountInvalidates(c, rev, rel) 
   amt events after rev before/at rel:
    known(amount_at_rev)  known(amount_at_rel) 
    amount_at_rel > amount_at_rev × 1.20

R1(c, rel) triggers 
  State(c,rel).jurisdiction  DE  State(c,rel).amount  100000
  (if either unknown  indeterminate_trigger)

R1(c, rel) satisfied 
  ¬triggers OR
  ( er: Enhanced_Review(er)  er  rel 
        ¬MaterialAmountInvalidates(c, er, rel) 
        no other material change after er that policy treats as resetting ER) OR
  ValidExemption(c, rel, waives=R1)

R2(c, rel) triggers 
  State(c,rel).risk_level = HIGH  State(c,rel).customer_type = PEP

R2(c, rel) satisfied 
  ¬triggers OR
  ( er, ca: Enhanced_Review(er)  Compliance_Approve(ca) 
        er  ca  rel 
        ca is not merely approval of a standard-only packet when ER missing)

R3(c, rel) triggers 
   u: Sanctions_List_Update(u) adding State(c,rel).jurisdiction 
  latest Sanctions_Screen before rel is  u  rel

R3(c, rel) satisfied 
  ¬triggers OR  s: Sanctions_Screen(s)  u  s  rel

ValidExemption(x, rel, waives) 
  approved_by = Head_Compliance 
  effective_from  time(rel) < expires 
  scope matches State(jurisdiction, customer_type, amount) 
  evidence_time supports approval existing at time(rel)
  (record_time may be late; displayed backdate alone  approval)

  (ts, event_index) lexicographic order
```

## 4. Ambiguities and Alternative Readings

**TX-305 (INDETERMINATE)**  
- If an immutable release payload or bank acknowledgment fixed amount 100000 at 11:30, R1 would trigger: ER exists and no known post-ER material amount change  could flip to **COMPLIANT**.  
- If release amount were shown &lt;100000, R1 off  **COMPLIANT**.  
- If policy treated next-day settlement as authoritative release amount (150000) without payload, some readers would call **COMPLIANT** (ER done); R6 and the problem’s “no immutable release payload” support staying indeterminate.

**TX-302**  
- Already **COMPLIANT** via ER. Alternative: ignore ER and rely only on EX-77  **JUSTIFIED_EXCEPTION** (strong q-sig + outage). Only if both ER were disregarded and EX-77 rejected would it become noncompliant—contrary to evidence.

**TX-310**  
- Current: **NONCOMPLIANT** (no ER; EX-88 fails R5).  
- If independent qualified evidence showed Head_Compliance approval 10:00 (e.g., cert time  release, or disinterested contemporaneous record), classification could become **JUSTIFIED_EXCEPTION**.  
- Oral approval by requester alone should not flip the result.

**TX-311**  
- **COMPLIANT** under release-time jurisdiction DE.  
- Alternative (stricter): require ER under the jurisdiction that applied when ER ran for “foreign” characterization—still, R1 text is evaluated at Release_Funds with **current** jurisdiction; DE excludes R1.  
- If event_index were ignored and jurDE were treated as before ER, still DE at release. If jur were still US at release, R1 would apply and ER before release with amount 115000 and no post-ER amount hike  COMPLIANT anyway.

**TX-307**  
- If Compliance_Approve on a “standard packet” were re-read as curing PEP/HIGH duties without ER, one could argue COMPLIANT; policy note and R2 text reject that  remains NONCOMPLIANT.

**TX-301**  
- Only if the 80000125000 change were deemed non-material or SR equated to ER would the outcome change; both contradict R1/R4 and “SR  ER”.

**TX-308**  
- Borderline amount exactly 100000: policy says “at least EUR 100,000”  R1 on; decrease-does-not-invalidate keeps COMPLIANT. If threshold were strict &gt;100000, R1 off  still COMPLIANT.

**TX-304**  
- If list update were not jurisdiction-additive for XZ or screen after update existed off-log  could change; on given log, clear NONCOMPLIANT.

        er_invalid = rel_state_amt > amt_at_er * 1.20 + 1e-9
    elif amt_at_er is None and rel_state_amt is not None:
        er_invalid = "UNKNOWN_BASELINE"
    else:
        er_invalid = False if er_ts is not None else None

    # Coarse R1–R4 flags
    unk_amt = rel_state_amt is None
    unk_jur = rel_state_jur is None
    unk_risk = rel_state_risk is None
    unk_ct = rel_state_ct is None

    r1_trigger = None
    if unk_jur or unk_amt:
        r1_trigger = "INDETERMINATE"
    else:
        r1_trigger = (rel_state_jur != "DE") and (rel_state_amt >= 100000)

    er_before_rel = er_ts is not None and (
        er_ts < rel_ts or (er_ts == rel_ts and er_idx <= rel_idx)
    )
    er_ok_r1 = er_before_rel and (er_invalid is False)

    r2_trigger = None
    if unk_risk and unk_ct:
        r2_trigger = "INDETERMINATE"
    else:
        r2_trigger = (rel_state_risk == "HIGH") or (rel_state_ct == "PEP")

    ca_after_er = (
        ca_ts is not None and er_ts is not None
        and (er_ts < ca_ts or (er_ts == ca_ts and er_idx < ca_idx))
        and (ca_ts < rel_ts or (ca_ts == rel_ts and ca_idx < rel_idx))
    )
    r2_ok = (
        er_before_rel
        and ca_ts is not None
        and (ca_ts < rel_ts or (ca_ts == rel_ts and ca_idx < rel_idx))
        and (er_ts is None or ca_after_er or (er_ts <= ca_ts))
        and not (ca_standard_only and not er_before_rel)
    )
    # stricter: need ER and CA with ER before CA before release
    r2_ok = (
        er_before_rel
        and ca_ts is not None
        and (er_ts < ca_ts or (er_ts == ca_ts and er_idx < ca_idx))
        and (ca_ts < rel_ts or (ca_ts == rel_ts and ca_idx < rel_idx))
    )

    r3_trigger = False
    r3_ok = True
    if list_ts is not None and rel_state_jur is not None:
        # list update adds jurisdiction matching current
        added = (list_jur == rel_state_jur) or (
            list_jur is None and "added" in str(
                g.loc[g["concept:name"] == "Sanctions_List_Update", "note"].astype(str).str.cat(sep=" ")
            )
        )
        # From log: jurisdiction column on list update carries XZ
        list_rows = g[g["concept:name"] == "Sanctions_List_Update"]
        if not list_rows.empty:
            lj = list_rows.iloc[0].get("jurisdiction")
            if pd.isna(lj):
                lj = list_rows.iloc[0].get("state_jurisdiction")
            added = (lj == rel_state_jur)
            list_ts = list_rows.iloc[0]["time:timestamp"]
        if added and list_ts < rel_ts:
            screens = g[
                (g["concept:name"] == "Sanctions_Screen")
                & (g["time:timestamp"] < rel_ts)
            ]
            last_sc = screens["time:timestamp"].max() if len(screens) else None
            if last_sc is None or last_sc < list_ts:
                r3_trigger = True
                post = screens[screens["time:timestamp"] > list_ts]
                r3_ok = len(post) > 0
            else:
                r3_trigger = False
                r3_ok = True

    # Exemption join
    ex_row = None
    ex_auto = None
    if cited_ex and pd.notna(cited_ex):
        m = exemptions[exemptions["exemption_id"] == cited_ex]
        if len(m):
            ex_row = m.iloc[0].to_dict()
            scope_ok = (
                ex_row["jur"] == rel_state_jur
                and ex_row["ctype"] == rel_state_ct
                and (rel_state_amt is None or rel_state_amt <= ex_row["max_amt"])
            )
            time_ok = ex_row["effective_from"] <= rel_ts < ex_row["expires"]
            evid_ok = (
                ex_row["evidence_quality"] == "STRONG"
                and ex_row["evidence_time"] <= rel_ts
            )
            # WEAK if evidence_time after release
            if ex_row["evidence_time"] > rel_ts:
                evid_ok = False
            ex_auto = {
                "scope_ok": scope_ok,
                "time_ok": bool(time_ok),
                "evid_ok": evid_ok,
                "quality": ex_row["evidence_quality"],
                "waives": ex_row["waives"],
            }

    # Coarse classification (human review for evidence edge cases)
    flags = []
    classification = "COMPLIANT"
    reasons = []

    if r1_trigger == "INDETERMINATE":
        classification = "INDETERMINATE"
        reasons.append("R1_trigger_unknown_amount_or_jur")
    elif r1_trigger is True:
        ex_waives = (
            ex_auto
            and ex_auto["waives"] == "R1"
            and ex_auto["scope_ok"]
            and ex_auto["time_ok"]
            and ex_auto["evid_ok"]
        )
        if ex_auto and ex_auto["waives"] == "R1" and ex_auto["quality"] == "WEAK":
            flags.append("EXEMPTION_REVIEW_REQUIRED")
            ex_waives = False
        if not er_ok_r1 and not ex_waives:
            if ex_auto and ex_auto["quality"] == "STRONG" and ex_auto["scope_ok"] and ex_auto["time_ok"]:
                # strong path
                if ex_auto["evid_ok"]:
                    classification = "JUSTIFIED_EXCEPTION"
                    reasons.append("R1_waived_by_strong_exemption")
                else:
                    classification = "REVIEW_REQUIRED"
                    reasons.append("R1_exemption_evidence_timing")
            elif not er_before_rel:
                classification = "NONCOMPLIANT"
                reasons.append("R1_missing_ER")
            elif er_invalid is True:
                classification = "NONCOMPLIANT"
                reasons.append("R1_ER_invalidated_by_amount_increase")
            else:
                classification = "REVIEW_REQUIRED"
                reasons.append("R1_unclear")
        else:
            reasons.append("R1_ok")

    if r2_trigger == "INDETERMINATE":
        classification = "INDETERMINATE"
        reasons.append("R2_trigger_unknown")
    elif r2_trigger is True:
        if not r2_ok:
            # special: CA on standard packet without ER
            if ca_standard_only and not er_before_rel:
                classification = "NONCOMPLIANT"
                reasons.append("R2_CA_standard_packet_without_ER")
            elif not er_before_rel:
                classification = "NONCOMPLIANT"
                reasons.append("R2_missing_ER")
            elif ca_ts is None:
                classification = "NONCOMPLIANT"
                reasons.append("R2_missing_CA")
            else:
                classification = "NONCOMPLIANT"
                reasons.append("R2_ordering")
        else:
            reasons.append("R2_ok")

    if r3_trigger and not r3_ok:
        classification = "NONCOMPLIANT"
        reasons.append("R3_missing_rescreen_after_list_update")

    # TX-305 style: settlement after release not used as release amount
    settlement = g[g["concept:name"] == "Settlement_Confirmed"]
    sett_amt = float(settlement.iloc[0]["amount"]) if len(settlement) and pd.notna(settlement.iloc[0]["amount"]) else None

    rows.append({
        "case": case_id,
        "release_ts": rel_ts,
        "state_amount": rel_state_amt,
        "state_risk": rel_state_risk,
        "state_jurisdiction": rel_state_jur,
        "state_customer_type": rel_state_ct,
        "unknown_amount": unk_amt,
        "unknown_jurisdiction": unk_jur,
        "unknown_risk": unk_risk,
        "unknown_customer_type": unk_ct,
        "r1_trigger": r1_trigger,
        "r2_trigger": r2_trigger,
        "r3_trigger": r3_trigger,
        "er_ts": er_ts,
        "sr_ts": sr_ts,
        "ca_ts": ca_ts,
        "amt_at_er": amt_at_er,
        "er_invalidated_r4": er_invalid,
        "screen_ts": screen_ts,
        "list_update_ts": list_ts,
        "cited_exemption": cited_ex if pd.notna(cited_ex) else None,
        "exemption_auto": ex_auto,
        "ca_standard_only": ca_standard_only,
        "settlement_amt_nonbinding": sett_amt,
        "coarse_classification": classification,
        "reasons": ";".join(reasons) if reasons else "none",
        "flags": ";".join(flags) if flags else "",
    })

diag = pd.DataFrame(rows)
pd.set_option("display.max_columns", None)
pd.set_option("display.width", 200)
pd.set_option("display.max_colwidth", 80)
print("=== CASE DIAGNOSTICS (coarse; evidence edge cases => REVIEW_REQUIRED) ===")
print(diag.to_string(index=False))

## 6. Why Control-Flow-Only Conformance Is Insufficient

1. **Final-state leakage** — Aligning a whole-case attribute vector (last amount/risk/jurisdiction) with the full trace makes TX-311 look like “ER under DE” or TX-309 look like a single static amount; obligations need **prefix state at each event**.

2. **Post-hoc exemptions** — `Record_Exemption` after `Release_Funds` can still be compliant (EX-77) or not (EX-88). Control-flow “exemption eventually follows release” cannot encode signature time, cert creation after release, or witness conflict (R5).

3. **Material changes after review (R4)** — Trace pattern `Enhanced_Review  Release_Funds` matches TX-306, TX-308, and TX-309 alike; only amount deltas distinguish validity. DECLARE/response constraints on activity labels miss invalidating increases.

4. **Conditional activation** — R1 needs `jurDE  amount100k`; R2 needs HIGH/PEP; R3 needs list-update relative to jurisdiction. Pure order templates fire or skip uniformly and produce false positives/negatives (e.g., DE releases, sub-threshold amounts).

5. **Missing data (R6)** — Absence of amount is not “activity missing.” CF conformance yields fit/unfit; policy requires **INDETERMINATE** (TX-305), not silent low-risk default.

6. **Same-timestamp ordering** — TX-311 ER and jurisdiction update share `16:20`; only `event_index` establishes that DE changed **after** ER. Activity sequences without a stable tie-break scramble guards.

7. **Review type mismatch** — `Standard_Review` then `Compliance_Approve` then `Release` looks orderly for TX-307 but fails R2 because SRER and CA on a standard packet does not substitute.

8. **Sanctions temporal sandwich** — R3 needs `Screen  ListUpdate  Screen  Release` **conditional on jurisdiction membership**; a global “exists Screen before Release” pattern accepts TX-304 incorrectly.

---

## 7. Recommended Logging and Control Improvements

1. **Immutable release payload** — At `Release_Funds`, persist signed snapshot: `amount`, `risk_level`, `jurisdiction`, `customer_type`, `exemption_id`, rule-version, and hash of prior material events; eliminate TX-305-style ambiguity.

2. **Triple timestamps on legal facts** — For exemptions and list updates: `effective_time`, `record_time`, `signature_time` (qualified cert not_before); store signer role (must be Head_Compliance) separately from display fields.

3. **Exemption scope as structured attributes** — `waives_rules[]`, `jurisdiction_scope`, `customer_type_scope`, `amount_min/max`, `expires_at`; validate at release in-engine, not via free-text notes.

4. **Change provenance events** — Typed `Update_Amount` / `Update_Jurisdiction` / `Risk_Reclassify` with `old_value`, `new_value`, `percent_change`, `material_flag` computed at source; link `invalidates_review_id`.

5. **Review binding** — Reviews carry `reviewed_amount`, `reviewed_risk`, `reviewed_jurisdiction`, `reviewed_customer_type`, `review_class  {STANDARD, ENHANCED}`; Compliance_Approve references `review_id` + packet class (blocks TX-307 false cure).

6. **Stable total order** — Monotonic `event_index` (or Lamport/vector clock) mandatory within case; forbid unordered same-ts writes; document tie-break in policy (as R7).

7. **Sanctions controls** — `Sanctions_List_Update` lists `jurisdictions_added[]`; gate `Release_Funds` on `last_screen_ts > last_relevant_list_ts` for current jurisdiction.

8. **Rule version & obligation evaluation record** — Emit `Obligation_Check` events at release: which rules triggered, state snapshot, evidence refs—enables audit without re-deriving forward-fill semantics.

9. **Segregation of witnesses** — Exemption oral/emergency paths require disinterested second approver; requester cannot be sole witness (TX-310).

10. **Amount feed quality** — If amount unknown, hard-block release or force `INDETERMINATE_HOLD` state rather than allowing release with empty payload.

These changes make event-time semantics executable, reduce INDETERMINATE outcomes, and allow automated checks to align with R1–R7 without narrative reconstruction.
