## 1. Duplicate-handling decision tree

1. **Exact technical duplicate?** Same source, `source_event_key`, `payload_hash`, timestamp, activity, and identical E2O relation set.
   - **Terminal:** Drop later duplicate, keep canonical, retain provenance. If source IDs differ but all technical keys match, retain both source IDs in provenance. Confidence high.

2. **Same physical event observed by multiple systems?** Different sources, compatible timestamp, overlapping object set, reconciliation or business key proves same physical occurrence, payload differences explainable by enrichment/authority.
   - **Terminal:** Merge into one canonical event; merge attributes with source-authority policy; union compatible relations; retain all source IDs, timestamps, labels, hashes. Confidence high only with evidence.

3. **Summary event derived from detailed event?** One event is aggregate/status/balance update; other is operational detail; object sets differ because summary omits item/payment objects.
   - **Terminal:** Retain both with refined labels unless a one-to-one mapping is proven and no abstraction is lost. Do not union relations blindly. Confidence medium.

4. **Harmonization collision between semantically distinct source activities?** Same harmonized label and timestamp, but source semantics differ.
   - **Terminal:** Retain both; refine to source-specific labels or qualifiers. Do not merge. Confidence high when source meaning is known.

5. **Concurrent same-label events involving different objects?** Same activity/time, different critical object, e.g. different Item or Payment.
   - **Terminal:** Retain both; qualify by critical object. Do not merge even if they share Order/Invoice. Confidence high.

6. **Unresolved candidate?** Insufficient evidence, conflicting payloads, ambiguous object roles.
   - **Terminal:** Quarantine for review or retain both unchanged in conservative mode. Mark as candidate. Confidence low.

## 3. Timestamp-tie ordering rules

Use a partial-order-to-total-order policy. The total order is an analyst artifact, not proof of physical truth.

**Semantic rules**
1. **Domain constraints:** e12 before e13 for M1; e09 before e10; e08 before e09 by release-before-acceptance; picks before pack; pack before dispatch; invoice before payment; captures before ERP payment summary; e17 is next day.
2. **Within-source sequence:** If same source and `source_seq` is meaningful, respect it. Example: scanner e04 before e05; PSP e13 before e14.
3. **Lifecycle constraints on shared objects:** For O1/P1, Pick < Pack < Dispatch < Handover < Confirm. For V1, Invoice < Authorize < Capture < Summary. For M1, Authorize < Capture.
4. **Source-specific semantics:** WMS operational events before ERP summaries; carrier acceptance before handover; Billing/ERP invoice observations are merged when evidence exists.

**Deterministic but non-semantic rules**
5. **Ingestion time:** Technical arrival only. Do not use it as primary business order. Use it only for exact technical duplicate selection or audit.
6. **Stable fallback:** Canonical `eid` lexicographic order after semantic constraints, or an explicit source-priority map if documented. This is arbitrary.

import pandas as pd
import pm4py

REL_EID = "ocel:eid"
REL_OID = "ocel:oid"
META_COLS = {
    "eid", "timestamp", "activity", "source", "source_event_key", "source_seq",
    "ingested_at", "payload_hash", "related objects", "provenance",
    "original_timestamp", "original_activity"
}

def clone_ocel(ocel):
    return copy.deepcopy(ocel)

def add_original_columns(ocel):
    ev = ocel.events
    if "original_timestamp" not in ev.columns:
        ev["original_timestamp"] = ev["timestamp"]
    if "original_activity" not in ev.columns:
        ev["original_activity"] = ev["activity"]
    if "provenance" not in ev.columns:
        ev["provenance"] = ev.apply(
            lambda r: [{
                "eid": r["eid"],
                "source": r["source"],
                "source_event_key": r["source_event_key"],
                "timestamp": r["timestamp"],
                "activity": r["activity"],
                "payload_hash": r["payload_hash"]
            }], axis=1
        )

def candidate_duplicate_groups(ocel, keys=("activity", "timestamp")):
    ev = ocel.events
    return ev.groupby(list(keys)).filter(lambda g: len(g) > 1)[
        ["eid", "activity", "timestamp", "source", "source_event_key", "payload_hash"]
    ].sort_values(list(keys) + ["eid"])

def validate_ocel(ocel):
    ev_ids = set(ocel.events["eid"])
    rel_eids = set(ocel.relations[REL_EID])
    obj_ids = set(ocel.objects["oid"])
    rel_oids = set(ocel.relations[REL_OID])
    assert ocel.events["eid"].is_unique, "duplicate canonical event ids"
    assert rel_eids <= ev_ids, f"relations reference missing events: {rel_eids - ev_ids}"
    assert rel_oids <= obj_ids, f"relations reference missing objects: {rel_oids - obj_ids}"
    return True

def merge_verified_pair(ocel, canonical_eid, dup_eid, attr_priority=None):
    """Merge one verified duplicate. Modifies the supplied deep copy."""
    ev = ocel.events
    rel = ocel.relations
    canon_mask = ev["eid"] == canonical_eid
    dup_mask = ev["eid"] == dup_eid
    assert canon_mask.any() and dup_mask.any(), "missing canonical or duplicate event"

    cidx = ev.index[canon_mask][0]
    didx = ev.index[dup_mask][0]

    prov = ev.at[cidx, "provenance"]
    if not isinstance(prov, list):
        prov = []
    prov.append({
        "eid": dup_eid,
        "source": ev.at[didx, "source"],
        "source_event_key": ev.at[didx, "source_event_key"],
        "timestamp": ev.at[didx, "timestamp"],
        "activity": ev.at[didx, "activity"],
        "payload_hash": ev.at[didx, "payload_hash"]
    })
    ev.at[cidx, "provenance"] = prov

    # Fill missing non-meta attributes from duplicate; conflicts stay in provenance.
    for col in ev.columns:
        if col in META_COLS:
            continue
        if pd.isna(ev.at[cidx, col]) and not pd.isna(ev.at[didx, col]):
            ev.at[cidx, col] = ev.at[didx, col]

    # Union compatible relations, avoiding exact duplicates.
    dup_rels = rel[rel[REL_EID] == dup_eid].copy()
    for _, r in dup_rels.iterrows():
        exists = (
            (rel[REL_EID] == canonical_eid) &
            (rel[REL_OID] == r[REL_OID]) &
            (rel.get("ocel:qualifier", "") == r.get("ocel:qualifier", ""))
        ).any()
        if not exists:
            rel.loc[len(rel)] = {
                REL_EID: canonical_eid,
                REL_OID: r[REL_OID],
                "ocel:qualifier": r.get("ocel:qualifier", "")
            }

    ocel.events = ev[ev["eid"] != dup_eid].copy()
    ocel.relations = rel[rel[REL_EID] != dup_eid].copy()
    return ocel

# Raw copy

## 7. Sensitivity analysis

| Dataset | Events | E2O | Order-flattened DFG | Item DFG | Payment DFG | Main risks |
|---|---:|---:|---|---|---|---|
| Raw | 17 | 44 | Pick appears multiple times; Invoice appears twice; Dispatch twice | I1 has e03/e04 duplicate; I2 has e05 | M1 and M2 visible; e15 summary separate | False rework, inflated frequencies |
| Conservative | 15 | 39 | Pick once for I1, once for I2; Pack detail and ERP summary; Dispatch release and carrier acceptance | I1 pick/pack; I2 pick/pack | M1 authorize/capture; M2 capture; ERP summary | Still two Pack nodes and two Dispatch nodes, intentionally |
| Evidence-based merge | 14 | 37 | Pack summary collapsed into WMS Pack | I2 pick preserved unless separately merged | Same as conservative | Loses ERP abstraction/status |
| Aggressive library merge | ~12 | ~32 | Dispatch release and carrier acceptance collapsed | e05 may be at risk unless guarded | M2 or summary may collapse | High semantic damage |

Concrete patterns whose interpretation changes:
1. Raw `e03  e04` Pick-Pick edge looks like rework; conservative removes it.
2. Conservative retains `e05` Pick(I2)  `e06` Pack(I2); aggressive common-object merging can erase it.
3. Raw `e06  e07` Pack-Pack edge is detail-to-summary; evidence merge removes ERP status latency.
4. Raw `e08  e09` Dispatch-Dispatch edge is release-to-acceptance; aggressive merge erases carrier acceptance.
5. `e09  e10` acceptance  handover is semantic; ingestion ordering can mislabel it.
6. Raw `e11/e16` duplicate Invoice inflates V1 invoice frequency; conservative merges.
7. `e12  e13` Authorize(M1)  Capture(M1) remains; aggressive `e13/e14` merge destroys M2 partial payment.
8. `e13/e14  e15` capture-to-summary relation shows aggregation; merging e15 into M1 hides M2.

ET–OT weights change when duplicated events are collapsed: fewer Pick observations, fewer Invoice observations. OTG relations change if summary events are merged into detailed events, because e15 has no Payment object but e13/e14 do. Apparent loops/rework decrease in conservative; aggressive may decrease more but by deleting legitimate concurrency. Lifecycle measurements should use original timestamps with explicit unknown concurrency, not synthetic microseconds.

## 8. Audit trail and reversibility

Provenance schema:

| Field | Meaning |
|---|---|
| canonical_event_id | Surviving eid |
| source_event_ids | All merged/deduplicated eids |
| merge_rule | e.g. `verified_physical_scan`, `invoice_authority_merge` |
| rule_version | Version of cleaning policy |
| reviewer | Analyst or automated rule owner |
| original_activity | Source labels before refinement |
| refined_activity | Analysis label |
| original_timestamp | Source UTC timestamp |
| adjusted_timestamp | PM4Py synthetic/order timestamp if any |
| attributes_retained | JSON per source |
| conflicts_discarded | JSON of conflicting attributes |
| confidence | High/medium/low |
| reason | Evidence text |

Analyst can reconstruct raw view by exploding `source_event_ids`, restoring `original_timestamp`, `original_activity`, source, source_event_key, and reattaching raw E2O relations using the original eids. Synthetic timestamps must be marked as non-business.

## 9. Failure modes and safeguards

1. Collapsing distinct partial payments e13/e14: safeguard by requiring Payment-object compatibility.
2. Converting abstraction-level updates into false rework: retain e06/e07 and e13/e15 unless one-to-one evidence exists.
3. Ordering by ingestion time: use semantic/domain rules first; ingestion only for audit.
4. Treating shared objects as proof of duplication: require critical object equality for Pick/Payment.
5. Unioning incompatible E2O relations: do not add Item relations to ERP summary e07 or Payment relations to e15.
6. Changing durations through synthetic microseconds: store original timestamps and mark synthetic deltas.
7. Losing source-authoritative attributes: use authority maps for e11/e16 and log conflicts.
8. Applying duplicate functions to whole OCEL without candidate groups: pre-check local groups and run on deep copies.
9. Merging harmonization collisions e08/e09: preserve original source semantics and refined labels.
10. Dropping e05 or e14: explicitly protect different Item/Payment objects from common-object duplicate merges.
