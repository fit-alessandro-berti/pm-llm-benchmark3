# 1. Assumptions and notation

Time is measured in minutes after 2026-05-12 08:00. The horizon is \(T=360\) (14:00). A reported timestamp \(t\) is the primary analysis clock. Symbols: \(W\) queue wait, \(S\) active service, \(J=W+S\) station sojourn, \(C\) case sojourn from external arrival to S2 completion. In-window elapsed quantities are marked “(elapsed)” and are censored at 14:00.

**A1. Event order and snapshot convention.** An activity occupies the half-open interval \([\mathrm{start},\mathrm{end})\). A case is in a station queue on \([\mathrm{entry},\mathrm{start})\). At a shared timestamp, events are applied in this order: service completions, then queue entries (external arrivals and S1 completions entering S2), then service starts. Peaks are taken from the resulting right-continuous step function, so a zero-duration spike is not a peak. A completion exactly equal to the next start on the same resource is an abutment, not an overlap.

**A2. Rounding.** Each reported \(t\) may stand for a true time in \([t-2.5,\,t+2.5]\) minutes. Primary figures use \(t\). A single duration, being a difference of two rounded timestamps, can move by up to 5 minutes. Order between timestamps at least 10 minutes apart is stable. Equal timestamps and 5-minute gaps can change length or apparent order inside that tolerance. Rounding is not folded into every cell; it is applied as a separate sensitivity layer.

**A3. Capacity and the outage.** I1, I2, C1, and C2 are single-task resources. No S1 absence is documented, so each inspector contributes 360 minutes. C2 is treated as unavailable on \([10{:}55,\,11{:}10)\), 15 minutes, and available again at 11:10. “Through 11:10” as a closed endpoint does not change the length and does not intersect any recorded C2 execution. Available S2 resource time is \(360+345=705\) minutes. Nominal time \(2\times360=720\) is reported beside it.

**A4. Flow constraints.** Every case is intended to visit S1 and then S2. S2 queue entry is the S1 completion time. A case with a completed S1 and a blank S2 is in the S2 queue at 14:00. A blank S1 means the case is in the S1 queue at 14:00. OPEN means service has started and has not completed by 14:00, so final service is strictly longer than elapsed service. A censored queue wait is at least the elapsed wait.

**A5. Hard feasible window for a missing start.** The start lies in \([\max(\text{queue entry},\,\text{previous end on that resource},\,\text{outage end}),\,\text{recorded end})\), so service is positive and the same resource is not given two overlapping executions. These hard windows are wide because a vanishingly short service is logically allowed and operationally implausible.

**A6. Central imputation (preferred point inside each window).** Fully observed handoffs show a dominant lag of 5 minutes from the moment the resource becomes free (and the case is already waiting) until the next start. That rule reproduces 19 of 19 observed S1 starts and 12 of 14 observed S2 starts. The two S2 exceptions are a 0-minute gap (P09) and a 10-minute gap (P15), both one grid step from 5 and within rounding of a true gap near 5 minutes. Central starts are therefore: P07 S1 at 09:30, P15 S1 at 11:45, P05 S2 at 09:50, P11 S2 at 12:05. This is an empirical regularity used as an estimator, not a logged policy.

**A7. Optimistic and pessimistic points.** Optimistic uses the earliest resource-feasible start (no 5-minute lag): P07 at 09:25, P15 at 11:40, P05 at 09:45, P11 at 12:00. Pessimistic-plausible uses a low service floor near the historical minimum: S1 service 20 minutes (P07 at 09:40, P15 at 11:55), P05 S2 service 20 minutes (start 09:55), P11 S2 service 15 minutes (start 12:10). A fourth, extreme, bound lets each missing service approach 0 and is used only to test whether conclusions flip.

**A8. Why P11 is special under A6.** C2 is busy with fully observed P08 until 12:00, and P11 completes at 12:25, so P11’s service cannot exceed 25 minutes. The +5 rule gives 20 minutes, which sits 5 minutes below every fully observed S2 service (minimum 25). The alternative central point C* sets P11’s start at 12:00 and service at 25, the only value inside both the hard window and the historical range \([25,50]\). Both points are retained. They differ by 5 minutes of busy time.

**A9. In-window busy time of OPEN work is identified.** P15 S2, P17 S2, and P21 S1 have known starts, so their contribution to busy time up to 14:00 is exact. Censoring affects residual service after 14:00, not the in-window integral.

**A10. Little’s law.** The identity “average WIP \(=\) total case-time in the window \(/\,T\)” is an accounting identity and is not treated as confirmation. A stationary \(L=\lambda W\) check is reported only for an interval with a stated cohort, and the mismatch for other cohorts is reported with it.

**A11. Assignment pattern used only as interpretation.** Odd-numbered cases all use I1 and even-numbered cases all use I2, consistent with two dedicated S1 servers. S2 follows the same alternation through P08 and then diverges (P10 and several later cases). S2 is not given a single forced discipline. One inversion, P17 starting while P16 is already waiting, is left as an anomaly.

# 2. Reconstruction method and formulas

Queue entry is external arrival at S1 and S1 completion at S2. For a case that starts,

\[
W = t_{\mathrm{start}}-t_{\mathrm{entry}},\qquad
S = t_{\mathrm{end}}-t_{\mathrm{start}},\qquad
J = t_{\mathrm{end}}-t_{\mathrm{entry}}.
\]

If the start is missing, \(J\) is still identified for a completed activity, and only the split \((W,S)\) moves: \(W=J-S\) with \(S\) inside the feasible window. If the case is still waiting at 14:00, \(W^{(\mathrm{elapsed})}=T-t_{\mathrm{entry}}\) and \(S\) is absent. If the activity is OPEN, \(W\) is identified from the known start, \(S^{(\mathrm{elapsed})}=T-t_{\mathrm{start}}\), and final \(S>S^{(\mathrm{elapsed})}\).

Case sojourn for a case that finishes both stations is \(C=t_{\mathrm{S2,end}}-t_{\mathrm{arrival}}\). It does not depend on missing starts.

WIP at time \(t\), imputation-free, is the count of cases with entry at or before \(t\) and exit after \(t\) (exit \(=T\) if the case is still in the station at 14:00, with the 14:00 census counting those cases). Queue length and service occupancy do depend on starts:

\[
Q(t)=\#\{\mathrm{entry}\le t<\mathrm{start}\},\qquad
B(t)=\#\{\mathrm{start}\le t<\mathrm{end}\},
\]

with OPEN service counted up to \(T\). The integrals satisfy \(\int_0^T(Q+B)=\int_0^T\mathrm{WIP}\). Time averages divide by \(T=360\). Peaks use A1.

Hourly rates use half-open hours \([08{:}00,09{:}00),\ldots,[13{:}00,14{:}00)\). Throughput is completed services per hour. S2 arrivals are S1 completions.

Resource utilization inside the window is

\[
U_r=\frac{\text{minutes \(r\) is in \([\mathrm{start},\mathrm{end})\) or \([\mathrm{start},T)\) if OPEN}}{\text{minutes \(r\) is available}}.
\]

Lower, central, and upper values are the same formulas under A7, A6, and the earliest-start endpoint. Preferred S2 figures are shown for both central (P11 service 20) and C* (P11 service 25).

Station capacity is read from the observed cycle, not from completed cases alone. S1 start-to-start gaps on a loaded server are mostly 35 minutes (about 30 minutes of service plus the 5-minute lag), so two inspectors give about \(2\times60/35\approx3.4\) cases per hour. Fully observed S2 service averages 40 minutes; with the same lag the cycle is about 45 minutes and two calibrators give about \(2\times60/45\approx2.7\) cases per hour. The outage removes about \(15/45\approx0.3\) of a case from C2.

Little’s check on an interval \(I\) of length \(\tau\) is \(\bar L=\tau^{-1}\int_I\mathrm{WIP}\), \(\lambda=N/\tau\), and \(W\) equal to the mean station sojourn of a named cohort. \(\lambda W\) is compared with \(\bar L\) only under the assumptions stated in section 4.

# 5. Bottleneck and temporal interpretation

**Observation.** S1 and S2 have the same nominal headcount, but calibration takes longer than inspection. Fully observed S1 service sits at 20–30 minutes (mean 28); fully observed S2 service sits at 25–50 minutes (mean 40, mode 40). With the systematic 5-minute handoff lag included, effective capacity is about 3.4 cases per hour at S1 and about 2.7 at S2. Measured output once both stations are loaded agrees: S1 completions from 09:00 to 14:00 are 17 in 5 hours (3.4/h); S2 completions in that same span are 14 in 5 hours (2.8/h).

**Observation.** External arrivals from 08:00 to 12:00 are 21 cases, 5.3 per hour, above S1’s 3.4. S1 inventory therefore builds. It is 7–8 cases for about 175 minutes and peaks at 8. After arrivals fall to 1 case in the 12:00 hour and 0 in the 13:00 hour, S1 completions of 4 and then 3 per hour drain the station. End-of-hour S1 WIP on the after-event hour marks runs 5, 7, 8, 7, 5, 2. The 14:00 census is P21 in service and P22 waiting.

**Observation.** S1’s output, about 3.4/h while saturated, stays above S2’s roughly 2.7–2.8/h. S2 inventory never plateaus. Hourly mean WIP climbs from 1.1 to 5.8, the queue peaks at 5, total WIP peaks at 7, and the 14:00 census is still 6 cases (2 in service, 4 waiting). Finished throughput of the line is the S2 completion count, 14 cases in 6 hours.

**Reading of the bottleneck, separated from the measurements.** Through the late morning both stations are binding, at different interfaces. S1 is the constraint relative to external demand: the arrival surge cannot enter inspection as fast as it arrives, and the S1 queue absorbs the difference (WIP near 8, waits near 100 minutes). S2 is the constraint relative to finished output: even a saturated S1 feeds S2 faster than calibration clears, so the S2 queue climbs all day. By 13:00–14:00 the picture is no longer balanced. S1 is draining (mean WIP in the last hour about 3.3, census 2) while S2 is at its highest (mean WIP 5.8, census 6). The unfinished work at the horizon sits in calibration.

The dedicated odd/even assignment at S1 does not explain the waits. Odd-case and even-case waits track each other from about 5 minutes up to about 100 minutes, and both inspectors are busy roughly 81–85% of the window. Pooling would remove only the short staggered gaps, not the gap between a 5.3/h arrival rate and a 3.4/h station.

**Maintenance interval, evidence first.** C2 has no recorded execution from 10:55 to 11:10. P06 ends on C2 at 10:50. P08, already in the S2 queue since 10:20, starts at 11:15 rather than at the 10:55 instant the handoff rule would have produced. P08’s wait is 55 minutes, against neighboring completed waits of 20–25 minutes earlier in the morning. The 11:00–12:00 hour has 2 S2 completions, while the surrounding busy hours have 3; P08 completing at 12:00 rather than near 11:40 is consistent with one completion being pushed across noon. Capacity removed by the outage is about 0.3 of a case.

**Hypothesis.** The outage is a local shock on the C2 lane, visible mainly in P08 and in the noon completion count. It is too small to be the cause of a queue that keeps rising for the next three hours. That rise matches the structural gap between an S1 feed near 3.4/h and an S2 cycle near 2.7/h (about 0.6–0.7 case per hour, several cases over the afternoon). Interpreting the 5-minute lags as pure rounding, rather than setup, raises both capacities (S1 toward about 4/h at a 30-minute service, S2 toward about 3/h at a 40-minute service). Demand still exceeds S1, and a saturated S1 still exceeds S2. The identity of the two constraints is stable under that reinterpretation.

**Hypothesis, dispatch.** S2 behavior through 13:50 is mostly consistent with “oldest waiting case takes the server that just freed, plus about 5 minutes,” including P10 moving to C1 while C2 is still tied up by the delayed P08. It is not consistent with strict alternation after P08. The rule breaks once: at 13:50 C1 frees and P16 has been waiting since 12:35, but P17, in queue only since 12:50, starts at 13:55. P16 is still waiting at 14:00. Possible explanations (a hold on P16, a skill constraint, a logging omission) cannot be separated with this table. The inversion changes who waits, not the WIP total.

**Hypothesis, P22.** I2’s idle stretch from 13:45 to 14:00 while P22 waits is the one clear S1 work-conservation miss. It is about 10 minutes beyond the usual lag. Rounding, a start at the boundary that was not logged, or the external arrival not being a physical ready time can all produce it. It does not move the day’s utilization by a material amount.

**Stable conclusions.**

- Total WIP paths, peak WIP, peak queues, completion counts, hourly arrival and completion counts, completed case sojourns, and completed station sojourns are fixed by arrivals and completions. Imputation only moves the wait-versus-service split inside those sojourns.
- Both stations are heavily occupied inside the window. Plausible utilization is about 80–84% at S1 and 78–81% at S2. The extreme “almost zero service” bounds would pull utilization down by roughly another 8–10 points and still leave both stations as the busy part of the line. They are not realistic operating cases: they require service times far below every fully observed activity.
- S1 congests and then drains; S2 congests and does not drain. Finished throughput is limited by S2. Morning intake is limited by S1. After about 13:00 the remaining WIP is an S2 problem. This ordering is the same under optimistic, central, central*, and pessimistic starts, and it survives treating the 5-minute lags as rounding rather than setup.
- The C2 outage is a real 15-minute hole with a direct footprint on P08 of about 20 minutes. It is not the main accumulation mechanism.
- P11 cannot be given a typical 40-minute calibration. Even allowing \(\pm2.5\) minutes on P08’s end and on P11’s end, the longest service consistent with “C2 does not run two cases at once” is about 30 minutes. P11 is a short job on every scenario. Only the placement inside 15–25 minutes is sensitive, and that placement does not change P11’s 80-minute station sojourn.

**Unstable or only weakly identified.**

- The exact split of P05’s 50-minute S2 sojourn and of P07’s and P15’s S1 sojourns, inside the ranges in the case table.
- Whether P11’s service is 20 or 25 minutes. That is the one central choice that leaves the historical service range.
- Residual times after 14:00. Elapsed values are solid lower bounds. Converting them into expected remaining service (for example assuming P15’s final service will look like the 40–50 minute C2 jobs, or that P21 will finish within a few minutes because 30 minutes is already the S1 maximum) is an extrapolation. P21, P15, and especially P17 could also be the long tail that the OPEN flag is selecting for.
- The cause of P17 overtaking P16, and the cause of I2 sitting free for about 15 minutes while P22 waits.
- A stationary Little’s number at S2, and any departure-based Little’s number at S1. The one S1 arrival-cohort comparison that lands near 7.5 versus 7.6 should be read as supportive but fragile: the window is short relative to the sojourn, and one cohort member is censored.

Right censoring bites the eventual waiting-time mean more than it bites utilization inside the window. In-window busy time of the three OPEN activities is known. The four cases still in the S2 queue, particularly P16 at an elapsed wait of 85 minutes, will pull the eventual S2 mean wait up by an amount the log does not determine. Clearing four waiting cases plus two partial services on a 45-minute cycle is on the order of 1–2 further hours; that clearance time is a capacity extrapolation, not an observation.

def parse_mark(value):
    """Return (status, minutes or None). Status is time, missing, open, or blank."""
    if value is None or (isinstance(value, str) and value.strip() == ""):
        return "blank", None
    text = str(value).strip()
    if text == "MISSING":
        return "missing", None
    if text == "OPEN":
        return "open", None
    hour, minute = text.split(":")
    return "time", (int(hour) - 8) * 60 + int(minute)

def case_metrics(df):
    """One row per case under a start imputation. Elapsed waits stay censored."""
    recs = []
    for r in df.itertuples(index=False):
        s1_wait = s1_svc = s2_wait = s2_svc = None
        if r.s1_start_hat is not None:
            s1_wait = r.s1_start_hat - r.arrival
            if r.s1_end_status == "time":
                s1_svc = r.s1_end - r.s1_start_hat
            elif r.s1_end_status == "open":
                s1_svc = HORIZON - r.s1_start_hat  # elapsed
        elif r.s1_start_status == "blank":
            s1_wait = HORIZON - r.arrival  # elapsed, still waiting
        if r.s1_end_status == "time":
            entry2 = r.s1_end
            if r.s2_start_hat is not None:
                s2_wait = r.s2_start_hat - entry2
                if r.s2_end_status == "time":
                    s2_svc = r.s2_end - r.s2_start_hat
                elif r.s2_end_status == "open":
                    s2_svc = HORIZON - r.s2_start_hat  # elapsed
            elif r.s2_start_status == "blank":
                s2_wait = HORIZON - entry2  # elapsed, still waiting
        recs.append(
            {
                "case": r.case,
                "S1_wait": s1_wait,
                "S1_service": s1_svc,
                "S2_wait": s2_wait,
                "S2_service": s2_svc,
                "state": r.state_at_14_00,
                "s1_open": r.s1_end_status == "open",
                "s2_open": r.s2_end_status == "open",
                "s2_waiting": r.s1_end_status == "time" and r.s2_start_status == "blank",
                "s1_waiting": r.s1_start_status == "blank",
            }
        )
    return pd.DataFrame(recs)


def sweep_wip(entries, exits):
    """Imputation-free WIP. Departures at time t are applied before arrivals at t.
    A case still present has no exit and remains until HORIZON.
    Returns segment table (t0, t1, wip) on [0, HORIZON) and the 14:00 census.
    """
    events = [(0, 0, 0)]
    for t in entries:
        events.append((t, 1, +1))
    for t in exits:
        events.append((t, 0, -1))
    events.append((HORIZON, 0, 0))
    events.sort()
    wip = 0
    segments = []
    last_t = 0
    last_wip = 0
    for t, _prio, delta in events:
        if t > last_t:
            segments.append((last_t, t, last_wip))
        wip += delta
        last_t = t
        last_wip = wip
        if t == HORIZON:
            break
    census = wip
    return pd.DataFrame(segments, columns=["t0", "t1", "wip"]), census


def time_average(segments):
    area = ((segments["t1"] - segments["t0"]) * segments["wip"]).sum()
    return area, area / HORIZON


def hourly_mean(segments):
    rows = []
    for h in range(6):
        a, b = h * 60, (h + 1) * 60
        piece = 0.0
        for t0, t1, wip in segments.itertuples(index=False):
            lo, hi = max(t0, a), min(t1, b)
            if hi > lo:
                piece += (hi - lo) * wip
        rows.append({"hour": f"{8+h:02d}:00–{9+h:02d}:00", "mean_wip": piece / 60, "case_minutes": piece})
    return pd.DataFrame(rows)


def count_in_hour(times):
    counts = []
    for h in range(6):
        a, b = h * 60, (h + 1) * 60
        counts.append(sum(a <= t < b for t in times))
    return counts
