register = Transition(label="Register_Supplier")
sanctions = Transition(label="Sanctions_Check")
quality = Transition(label="Quality_Review")
qa_clearance = Transition(label="QA_Clearance")  # Alias for Quality_Review
manual_approval = Transition(label="Manual_Procurement_Approval")
auto_approve = Transition(label="Auto_Approve")
provisional_activate = Transition(label="Provisional_Activate")
activate = Transition(label="Activate_Supplier")
reject = Transition(label="Reject_Supplier")
notify = Transition(label="Notify_Requester")
close = Transition(label="Close_Case")
request_more = Transition(label="Request_More_Info")

# --- Standard Route: Concurrent Checks -> Decision -> Approval/Reject -> Notify -> Close ---
standard_checks = StrictPartialOrder(nodes=[sanctions, quality, qa_clearance])
# Approximation: POWL lacks native REPEAT. We model Request_More_Info as a parallel 
# pre-decision gate that can loop back conceptually. True looping requires DECLARE.
request_loop = StrictPartialOrder(nodes=[request_more])
pre_decision = StrictPartialOrder(nodes=[standard_checks, request_loop])

manual_branch = StrictPartialOrder(nodes=[manual_approval, activate])
manual_branch.order.add_edge(manual_approval, activate)

auto_branch = StrictPartialOrder(nodes=[auto_approve, activate])
auto_branch.order.add_edge(auto_approve, activate)

provisional_branch = StrictPartialOrder(nodes=[provisional_activate, quality, manual_approval, activate])
provisional_branch.order.add_edge(provisional_activate, quality)
provisional_branch.order.add_edge(provisional_activate, manual_approval)
provisional_branch.order.add_edge(quality, activate)
provisional_branch.order.add_edge(manual_approval, activate)

decision = OperatorPOWL(operator=Operator.XOR, children=[manual_branch, auto_branch, provisional_branch, reject])

notify_close = StrictPartialOrder(nodes=[notify, close])
notify_close.order.add_edge(notify, close)

# --- Root Model ---
M1 = StrictPartialOrder(nodes=[register, pre_decision, decision, notify_close])
M1.order.add_edge(register, pre_decision)
M1.order.add_edge(pre_decision, decision)
M1.order.add_edge(decision, notify_close)

# --- Limitation Note ---
# POWL cannot natively enforce: amount caps, risk tiers, actor identity/alias resolution, 
# CoI rules, or strict temporal windows. These require DECLARE/log-skeleton constraints, 
# data validation pipelines, and organizational controls. The Request_More_Info loop 
# is approximated as a parallel pre-decision gate; a full loop requires a repeat operator 
# or DECLARE constraint (e.g., response_event).

**Event & Data-Collection Proposal**
- **Stable Notification IDs**: Replace mutable text fields with UUID-linked `notification_id` in onboarding log; enforce CRM-to-log mirroring 95% via API webhook.
- **Rule/Version IDs**: Attach `policy_version_id` (e.g., `CS-9-v2`, `PD-3-v1`, `FD-7-v1`) to every case at `Register_Supplier`. Validate against overlay registry before activation.
- **Eligibility Snapshots**: Capture risk tier, corporate group, location, and spend cap at registration; store as immutable JSON payload.
- **Actor Aliases & Delegation**: Resolve HR identity to canonical user ID; log `actor_canonical_id` and `delegation_evidence` (if applicable).
- **Emergency/Pilot Authority**: Require `directive_id` and `authorizing_officer_id` for provisional/auto flows. Auto-expire after window; require formal amendment for continuation.
- **Immutable Timestamps**: Use `event_timestamp` (system-generated) and `record_timestamp` (immutable); reject post-hoc edits to control-flow events.
- **Data Validation**: Pre-load pandas checks for amount caps, date windows, and actor mismatches; fail fast on policy violation before POWL conformance testing.
