def queue_stats(entries, starts, end=360):
    events=[]
    for t in entries: events.append((t,0,1)) # arrival priority 0
    for t in starts: events.append((t,1,-1)) # start priority 1
    events.sort(key=lambda x:(x[0],x[1]))
    q=0; prev=0; area=0; peak=0
    i=0
    while i<len(events):
       t=events[i][0]
       if t>prev: area += q*(t-prev); prev=t
       while i<len(events) and events[i][0]==t:
          q += events[i][2]
          peak=max(peak,q)
          i+=1
    area += q*(end-prev)
    return area/end, peak

def queue_stats(entries, starts, end=360):
    events=[]
    for t in entries:
       if not pd.isna(t): events.append((float(t),0,1))
    for t in starts:
       if not pd.isna(t): events.append((float(t),1,-1))
    events.sort(key=lambda x:(x[0],x[1]))
    q=0; prev=0.0; area=0.0; peak=0
    i=0
    while i < len(events):
       t=events[i][0]
       if t > prev:
          area += q*(t-prev)
          prev=t
       while i < len(events) and events[i][0]==t:
          q += events[i][2]
          if q > peak: peak=q
          i+=1
    area += q*(end-prev)
    return area/end, peak, area

# 1. Assumptions and notation

All times are on 2026-05-12. I use minutes from 08:00 when discussing bounds and formulas; e.g., 10:15 is minute 135 and 14:00 is minute 360.

**A1. Event-order convention for reported rounded times.**  
For the central reconstruction, reported timestamps are treated as point observations. When two reported events have the same nominal timestamp:
- on a single resource, an activity end is ordered before the next start on that resource;
- a queue entry is ordered before a service start from that queue;
- an external arrival to S1 is ordered before an S1 start at the same reported time.

This convention can add a momentary +1 to peak queue counts. Where rounding could change ordering, I note the uncertainty rather than forcing a single exact peak.

**A2. Rounding treatment.**  
Each reported timestamp is assumed to represent an actual time in approximately \([t-2.5, t+2.5]\) minutes. Therefore, a duration formed from two reported timestamps has a rounding envelope of roughly \(\pm 5\) minutes, subject to nonnegativity and precedence constraints. The explicit bounds for MISSING starts are structural bounds from precedence/resource constraints; rounding could widen them slightly.

**A3. Capacity and routing.**  
S1 has two single-task resources, I1 and I2. S2 has two single-task resources, C1 and C2. A case cannot bypass S1 or S2. A case enters the S2 queue immediately when its S1 service completes.

**A4. Missing-start imputation bounds.**  
A MISSING start is bounded by:
- queue entry time: external arrival for S1; S1 completion for S2;
- resource availability, using the observed previous and next work on that resource;
- known completion time;
- nonnegative service time.

The specific feasible start intervals used are:
- P07 S1 start: \([09:25, 10:00]\), because I1 is busy with P05 until 09:25 and P07 completes at 10:00.
- P15 S1 start: \([11:40, 12:15]\), because I1 is busy with P13 until 11:40 and P15 completes S1 at 12:15.
- P05 S2 start: \([09:45, 10:15]\), because C1 is busy with P03 until 09:45 and P05 completes S2 at 10:15.
- P11 S2 start: \([12:00, 12:25]\), because C2 is unavailable 10:55–11:10, then busy with P08 until 12:00, and P11 completes S2 at 12:25.

**A5. OPEN activities.**  
OPEN means the activity had started but not completed by 14:00. For OPEN activities, I distinguish elapsed service to 14:00 from final service time. Final service time is right-censored and bounded below by elapsed service.

**A6. Blank entries.**  
A blank S2 start/end after completed S1 means waiting for S2 at 14:00. A blank S1 start/end means waiting for S1 at 14:00. These are treated as right-censored waiting times, not missing because the case never arrived.

**A7. C2 maintenance.**  
C2 is unavailable from 10:55 through 11:10. In the central reconstruction, no C2 service is scheduled in this interval. The maintenance interval is treated as unavailable capacity, not idle-but-available capacity.

**A8. Scenario labels.**  
- **Optimistic / earliest-feasible:** MISSING starts are set as early as constraints allow. This minimizes waiting and maximizes observed service within the window.
- **Central:** MISSING starts are set at the midpoint of their feasible start intervals. This is an explicit, arbitrary central imputation, not a claim that the midpoint is most likely.
- **Pessimistic / latest-feasible:** MISSING starts are set as late as constraints allow. This maximizes waiting and minimizes observed service; in the limit it allows near-zero service, so it is a bound rather than a realistic operating point.

**A9. Utilization denominator.**  
Utilization is reported primarily against scheduled resource-time, 360 minutes per resource. For C2, I also report utilization against available time, 345 minutes, excluding the 15-minute maintenance window.

**A10. Little’s Law.**  
Steady-state Little’s Law is not assumed for the full window because arrivals, completions, and WIP are nonstationary and the window ends with substantial right-censored WIP. I use only a finite-window inventory identity as a consistency check where its arithmetic assumptions are defensible.

# 2. Reconstruction method and formulas

## Queue entry, waiting, service, and sojourn

For case \(i\):

- S1 queue entry time:  
  \[
  a_i = \text{arrival\_s1}_i
  \]

- S1 waiting time, if S1 start \(s^{S1}_i\) is known or imputed:  
  \[
  W^{S1}_i = s^{S1}_i - a_i
  \]

- S1 service time, if S1 completion \(e^{S1}_i\) is known:  
  \[
  X^{S1}_i = e^{S1}_i - s^{S1}_i
  \]

- S2 queue entry time:  
  \[
  q^{S2}_i = e^{S1}_i
  \]
  for cases that completed S1.

- S2 waiting time, if S2 start \(s^{S2}_i\) is known or imputed:  
  \[
  W^{S2}_i = s^{S2}_i - q^{S2}_i
  \]

- S2 service time, if S2 completion \(e^{S2}_i\) is known:  
  \[
  X^{S2}_i = e^{S2}_i - s^{S2}_i
  \]

- Station sojourn time:  
  \[
  T^{S1}_i = W^{S1}_i + X^{S1}_i
  \]
  \[
  T^{S2}_i = W^{S2}_i + X^{S2}_i
  \]

For completed cases, total system sojourn is:
\[
T_i = e^{S2}_i - a_i
\]

For OPEN or blank/waiting cases, I report elapsed time to 14:00 and state that the final value is greater than or equal to the elapsed value.

## Missing-start bounds

For a MISSING start with feasible start interval \([L, U]\):

- waiting time bound:
  \[
  W \in [L - q, U - q]
  \]

- service time bound:
  \[
  X \in [e - U, e - L]
  \]

where \(q\) is the queue-entry time and \(e\) is the known completion time.

## Queue length and WIP

For station \(j\), queue length is:
\[
Q_j(t) = \#\{\text{queue entries to station } j \le t\} - \#\{\text{service starts at station } j \le t\}
\]

Active station jobs:
\[
A_j(t) = \#\{\text{service starts at station } j \le t\} - \#\{\text{service completions at station } j \le t\}
\]

Station WIP:
\[
L_j(t) = Q_j(t) + A_j(t)
\]

Total system WIP:
\[
L(t) = \#\{\text{external arrivals} \le t\} - \#\{\text{completed S2 services} \le t\}
\]

This total WIP definition does not require imputing MISSING starts because it depends only on external arrivals and final S2 completions.

## Rates

For subperiod \(B\) of length \(|B|\):

- arrival rate:
  \[
  \lambda^{arr}_B = \frac{\#\text{arrivals in }B}{|B|}
  \]

- departure/completion rate:
  \[
  \lambda^{dep}_B = \frac{\#\text{completions in }B}{|B|}
  \]

I use half-open 2-hour subperiods, \([08:00,10:00)\), \([10:00,12:00)\), \([12:00,14:00)\), with boundary events assigned to the later period. Rounding can move boundary events by a few minutes, so subperiod rates are approximate.

## Busy time and utilization

For resource \(r\), busy time is the sum of overlaps between observed or imputed service intervals and the observation window:
\[
B_r = \sum_i \max(0, \min(e_i, 360) - \max(s_i, 0))
\]

Scheduled utilization:
\[
U_r = \frac{B_r}{360}
\]

For C2, available-time utilization:
\[
U^{avail}_{C2} = \frac{B_{C2}}{360 - 15}
\]

OPEN activities contribute elapsed service up to 14:00, not final service time.

## Lower / central / upper estimates

- Lower waiting / upper service for MISSING cases: earliest feasible start.
- Upper waiting / lower service for MISSING cases: latest feasible start.
- Central: midpoint of feasible start interval.
- OPEN and blank/waiting cases are not replaced by completed values; they contribute elapsed lower bounds and remain right-censored.

## Arrival and departure rates by subperiod

The subperiods are half-open: \([08:00,10:00)\), \([10:00,12:00)\), \([12:00,14:00)\). Boundary events are assigned to the later period. Rounding can shift boundary cases by a few minutes.

| subperiod | S1 arrivals | S1 arrival rate/h | S1 completions | S1 completion rate/h | S2 arrivals | S2 arrival rate/h | S2 completions | S2 completion rate/h |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 08:00–10:00 | 13 | 6.5 | 6 | 3.0 | 6 | 3.0 | 3 | 1.5 |
| 10:00–12:00 | 8 | 4.0 | 7 | 3.5 | 7 | 3.5 | 5 | 2.5 |
| 12:00–14:00 | 1 | 0.5 | 7 | 3.5 | 7 | 3.5 | 6 | 3.0 |

Interpretation:
- External arrivals are front-loaded: 13 of 22 arrivals occur before 10:00.
- S1 completion rate rises from 3.0/h to about 3.5/h.
- S2 completion rate rises from 1.5/h to 3.0/h but remains below the S2 arrival rate in the second and third subperiods.
- The window ends with S2 backlog, not S1 backlog, even though S1 waiting times are individually longer.

## Little’s-Law consistency checks

A global steady-state Little’s Law check is not defensible because the system is finite-horizon, nonstationary, and right-censored: 22 cases arrive but only 14 complete S2 by 14:00.

However, finite-window inventory identities are consistent.

Total system:
- Total observed case-minutes in system, including elapsed times for censored cases, is approximately 3425 minutes.
- Average total WIP over 360 minutes:
  \[
  \bar L = \frac{3425}{360} \approx 9.51
  \]
- Average elapsed sojourn per arrival within the window:
  \[
  \bar W = \frac{3425}{22} \approx 155.7 \text{ minutes}
  \]
- Arrival rate:
  \[
  \lambda = \frac{22}{360} \approx 0.0611 \text{ cases/min}
  \]
- Check:
  \[
  \lambda \bar W \approx 0.0611 \times 155.7 \approx 9.51
  \]

S2 subsystem:
- S2 entries: 20.
- S2 case-minutes within window: 1340.
- Average S2 WIP:
  \[
  \frac{1340}{360} \approx 3.72
  \]
- Average elapsed time in S2 per S2 entry:
  \[
  \frac{1340}{20} = 67.0 \text{ minutes}
  \]
- S2 entry rate over the full window:
  \[
  \frac{20}{360} \approx 0.0556
  \]
- Check:
  \[
  0.0556 \times 67.0 \approx 3.72
  \]

These are arithmetic finite-window checks, not evidence of steady state.

# 5. Bottleneck and temporal interpretation

## Evidence

1. **Early window, 08:00–10:00: S1 shows the stronger bottleneck signature.**
   - External arrival rate is 6.5/h.
   - S1 completion rate is only 3.0/h in this subperiod, partly because the system starts empty and partly because S1 service times are around 20–30 minutes per case with two resources.
   - S1 waiting rises from 5 minutes for P01/P02 to 35–40 minutes by P05/P06, and then to 50–75 minutes for cases arriving before 10:00.
   - S2 waiting is still modest for completed cases: mostly 5–25 minutes, with P08 later showing 55 minutes because its S1 completion occurs after the early S1 backlog has propagated.

2. **Middle window, 10:00–12:00: bottleneck becomes mixed, then increasingly S2-like.**
   - S1 arrivals fall to 4.0/h, but S1 still has a substantial queue because earlier arrivals are being processed.
   - S2 arrivals are 3.5/h, while S2 completions are only 2.5/h.
   - S2 waiting for completed cases increases: P08 55, P10 50, P12 45, P14 65.
   - The C2 maintenance outage from 10:55 to 11:10 occurs during this period. P11 completes S1 at 11:05 and cannot use C2 during maintenance; C2 is also needed by P08 after the outage. P11’s S2 start is bounded no earlier than 12:00.

3. **Late window, 12:00–14:00: S1 clears, S2 remains constrained.**
   - External arrivals collapse to 1 case, P22.
   - S1 completes 7 services and reduces its queue. At 14:00, only P21 is open in S1 and P22 is waiting for S1.
   - S2 also completes 6 services, but S2 arrivals remain 7. At 14:00, S2 has two open cases, P15 and P17, and four waiting cases, P16, P18, P19, P20.
   - Thus, the final backlog is concentrated at S2.

## Hypothesis versus evidence

**Evidence:**
- S1 queue length and S1 waiting are larger in absolute minutes than S2 queue length and S2 waiting for completed cases.
- S2 ends the window with six unfinished cases in or waiting for S2, while S1 ends with only two unfinished cases in or waiting for S1.
- S2 completion rate remains below S2 arrival rate in the 10:00–12:00 and 12:00–14:00 subperiods.
- The C2 outage directly removes 15 minutes of S2 capacity and affects P11.

**Hypothesis:**
- The bottleneck is time-varying: S1-dominated early, mixed in the middle, and S2-dominated late.
- The C2 outage amplifies S2 congestion but is not sufficient by itself to explain all S2 backlog; S2 service times around 40–50 minutes imply a capacity near 2.4–3.0 cases/h, while S2 arrivals are about 3.5/h after 10:00.

## Maintenance interval

The C2 maintenance interval is short but poorly timed relative to demand:
- P06 finishes S2 on C2 at 10:50, just before the outage.
- P11 finishes S1 at 11:05, during the outage.
- P08 starts on C2 at 11:15, after the outage.
- P11 cannot plausibly start on C2 before P08 completes at 12:00 if single-tasking and no preemption are assumed.

Thus, the outage contributes to P11’s bounded S2 wait of 55–80 minutes and reduces C2 available capacity by about 4.3%.

## Stable conclusions

The following conclusions survive all plausible imputation choices:
- S1 waiting grew substantially over the morning.
- S2 backlog grew after 10:00 and remained at 14:00.
- The final unfinished inventory is concentrated in S2.
- The C2 outage delayed P11 and reduced S2 capacity.
- Total system WIP peaked around 13 cases, near 11:30–12:00.
- Utilization is high but not saturated; exact values depend on missing-start imputation.

## Unstable conclusions

The following are sensitive to imputation or rounding:
- Exact mean S1/S2 waiting and service times for cases with MISSING starts.
- Exact I1, C1, and C2 utilization.
- Whether the middle period should be described as “S1 bottleneck”, “S2 bottleneck”, or “joint bottleneck” depends on whether one emphasizes queue length, waiting time, remaining backlog, or capacity utilization.
- Exact peak queue counts can shift by one under different simultaneous-event conventions or rounding assumptions.

# Queue/WIP step-function calculation.
# Arrival/entry events have priority 0, start/departure-from-queue events priority 1,
# so at the same nominal time entries are processed before starts for peak counting.
def queue_stats(entries, starts, end=END_MIN):
    events = []
    for t in entries:
        if not pd.isna(t):
            events.append((float(t), 0, 1))
    for t in starts:
        if not pd.isna(t):
            events.append((float(t), 1, -1))
    events.sort(key=lambda x: (x[0], x[1]))

    q = 0
    prev = 0.0
    area = 0.0
    peak = 0
    i = 0
    while i < len(events):
        t = events[i][0]
        if t > prev:
            area += q * (t - prev)
            prev = t
        while i < len(events) and events[i][0] == t:
            q += events[i][2]
            peak = max(peak, q)
            i += 1
    area += q * (end - prev)
    return area / end, peak, area

            st = scenario_value((r.case, "s1_start"), scenario)
            add_interval(records, r.case, "S1", r.s1_resource, st, r.s1_end_min)

        # S2 intervals
        if r.s2_start_status == "OBS" and r.s2_end_status == "OBS":
            add_interval(records, r.case, "S2", r.s2_resource, r.s2_start_min, r.s2_end_min)
        elif r.s2_start_status == "OBS" and r.s2_end_status == "OPEN":
            add_interval(records, r.case, "S2", r.s2_resource, r.s2_start_min, END_MIN)
        elif r.s2_start_status == "MISSING" and r.s2_end_status == "OBS":
            st = scenario_value((r.case, "s2_start"), scenario)
            add_interval(records, r.case, "S2", r.s2_resource, st, r.s2_end_min)
    return pd.DataFrame(records)

def busy_by_resource(intervals):
    if intervals.empty:
        return pd.Series(dtype=float)
    intervals = intervals.copy()
    intervals["busy"] = intervals["end_min"] - intervals["start_min"]
    return intervals.groupby("resource")["busy"].sum().sort_index()

def log_to_df(log):
    if isinstance(log, pd.DataFrame):
        return log
    conv = getattr(pm4py, "convert_to_dataframe", None)
    if callable(conv):
        try:
            return conv(log)
        except Exception:
            pass
    to_pandas = getattr(log, "to_pandas", None)
    if callable(to_pandas):
        try:
            return to_pandas()
        except Exception:
            pass
    try:
        return pd.DataFrame(log)
    except Exception:
        return pd.DataFrame()

def print_pm4py_case_table(log, label, attr_fragments):
    print("\n" + label)
    if log is None:
        print("PM4Py function did not return a usable object.")
        return
    d = log_to_df(log)
    if d.empty:
        print("Empty PM4Py output.")
        return
    frag_cols = [
        c for c in d.columns
        if any(f.lower() in str(c).lower() for f in attr_fragments)
    ]
    if "case:concept:name" in d.columns and frag_cols:
        keep = ["case:concept:name"] + frag_cols
        print(d[keep].drop_duplicates().head(15).to_string(index=False))
    else:
        print(d.head(10).to_string(index=False))

def try_insert(func, log, kw_options, pos_options):
    last_err = None
    for kwargs in kw_options:
        try:
            log_copy = copy.deepcopy(log)
            out = func(log_copy, **kwargs)
            return log_copy if out is None else out
        except Exception as e:
            last_err = e
    for args in pos_options:
        try:
            log_copy = copy.deepcopy(log)
            out = func(log_copy, *args)
            return log_copy if out is None else out
        except Exception as e:
            last_err = e
    print("PM4Py insert call failed:", last_err)
    return None
