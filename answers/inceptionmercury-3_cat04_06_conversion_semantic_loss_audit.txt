# 1. Source-Semantics Baseline

The source POWL is authoritative. In the table below, witnesses are complete visible label sequences. Abbreviations: R=Register Change, A=Assess Risk, P=Prepare Evidence, L=Legal Review, C=Configure Trial, I=Inspect Trial, D=Correct Defect, Rel=Release Change, Arc=Archive Change.  denotes a silent transition.

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| INV-ORD-1 | R occurs first. | `R,A,P,C,I,Rel,Arc` | `A,R,P,C,I,Rel,Arc` | Yes |
| INV-ORD-2 | Rel occurs before Arc; Arc is final. | `R,A,P,C,I,Rel,Arc` | `R,A,P,C,I,Arc,Rel` | Yes |
| INV-CONC-1 | A and P are unordered. | `R,A,P,C,I,Rel,Arc` and `R,P,A,C,I,Rel,Arc` | N/A; if only one order were accepted, the other-order trace would be missing. | Yes |
| INV-OPT-1 | L is optional. | `R,A,P,C,I,Rel,Arc` (no L) and `R,A,P,L,C,I,Rel,Arc` (with L) | N/A; the model must accept both. | Yes |
| INV-LOOP-1 | In every verification iteration, C occurs before I. | `R,A,P,C,I,D,C,I,Rel,Arc` | `R,A,P,I,C,Rel,Arc` | Yes |
| INV-LOOP-2 | D separates repeated iterations; D cannot occur before the first C or after the last I without another iteration. | `R,A,P,C,I,D,C,I,Rel,Arc` | `R,A,P,C,I,C,I,Rel,Arc` and `R,A,P,C,I,D,Rel,Arc` | Yes |
| INV-MIN-1 | At least one verification iteration occurs. | `R,A,P,C,I,Rel,Arc` | `R,A,P,Rel,Arc` | Yes |
| INV-SYNC-1 | Verification waits for both A and P. | `R,P,A,C,I,Rel,Arc` | `R,A,C,I,Rel,Arc`; `R,P,C,I,Rel,Arc` | Yes |
| INV-SYNC-2 | Release waits for completion of the verification loop. | `R,A,P,C,I,Rel,Arc` | `R,A,P,C,I,D,Rel,Arc` | Yes |
| INV-SYNC-3 | Release waits for completion of the legal branch, either L or silent skip. | `R,A,P,L,C,I,Rel,Arc`; `R,A,P,C,I,Rel,Arc` | Not observable after hiding : a no-L trace cannot distinguish the silent skip from an incomplete legal branch. | No/partial |
| INV-CONC-2 | The legal branch and verification loop are unordered/overlap. | `R,A,L,P,C,I,Rel,Arc` and `R,A,P,C,I,L,Rel,Arc` | N/A; if either order were forced, the other-order trace would be missing. | Yes |

# 2. Candidate Conversion Pipelines

No direct POWL-to-BPMN conversion is assumed. The primary pipeline is the direct accepting-Petri-net route.

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| P1 (primary): POWL  accepting Petri net  BPMN | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)`; `pm4py.convert_to_petri_net(bpmn_from_net)` for round trip | Directly derives from the authoritative POWL; preserves the accepting-net semantics; BPMN is used only as a visualization layer | BPMN routing can be visually misleading; silent transitions can become invisible; BPMN round trip may produce a net with different places/new silent transitions | Any conversion returns `None`; workflow-net/soundness checks fail; bounded trace/witness comparison fails; exact final-marking test fails |
| P2: POWL  accepting Petri net  process tree  BPMN | `pm4py.convert_to_petri_net(source_powl)`; `pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)`; `pm4py.convert_to_bpmn(tree_intermediate)`; `pm4py.convert_to_petri_net(bpmn_from_tree)` | Produces a clean hierarchical BPMN if the source is block-structured | The source is unlikely to be block-structured because verification is synchronized by A and P while the legal branch overlaps verification; conversion may raise or return an approximate tree | Exception from `convert_to_process_tree`; or a produced tree fails the round-trip/invariant comparison. The exception must be caught and interpreted as `conversion failed`, not suppressed |

**Primary pipeline: P1.**

# 4. Preservation and Loss Audit

Successful serialization is not treated as semantic fidelity. The audit below relies on the bounded trace oracle and diagnostics defined in Section 5.

| Source invariant | POWLPetri | PetriBPMN | PetriTree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| R occurs first | validated preserved | expected preserved | conversion failed | validated preserved | No accepted trace starts with a non-R label; round-tripped completed trace sets match. |
| Rel before Arc, Arc final | validated preserved | expected preserved | conversion failed | validated preserved | Accepted traces end with Arc; exploration stops at exact final marking; soundness check. |
| A and P unordered | validated preserved | expected preserved | conversion failed | validated preserved | Both `R,A,P,...` and `R,P,A,...` are accepted by baseline and round-trip nets. This validates absence of order, not simultaneity. |
| L optional | validated preserved | expected preserved | conversion failed | validated preserved | With-L and no-L traces survive round trip; silent skip is not visible. |
| C before I in each iteration | validated preserved | expected preserved | conversion failed | validated preserved | No accepted trace contains I before C; repeated iterations preserve CI. |
| D separates iterations | validated preserved | expected preserved | conversion failed | validated preserved | Missing-D and D-at-end traces are rejected; D-between-I-C is accepted. |
| At least one verification iteration | validated preserved | expected preserved | conversion failed | validated preserved | Release without C/I is rejected. |
| Verification waits for A and P | validated preserved | expected preserved | conversion failed | validated preserved | Configure before both A and P is rejected. |
| Release waits for verification loop | validated preserved | expected preserved | conversion failed | validated preserved | Release before verification and release after redo are rejected. |
| Release waits for legal branch | expected preserved | expected preserved | conversion failed | ambiguous | Silent skip makes a no-L trace observationally identical to an unfinished legal branch; marking-level test would be needed. |
| Legal branch and verification loop unordered | validated preserved | expected preserved | conversion failed | validated preserved | L-before-loop and L-after-loop traces are both accepted. |
| Activity labels unique | validated preserved | expected preserved | conversion failed | validated preserved | Label multiset comparison in Section 5 passes. |
| Initial/final markings | validated preserved | expected preserved | conversion failed | ambiguous | Non-null markings checked; exact final-marking equality used locally; round-trip marking objects are behaviorally compared, not place-identical. |

If a particular PM4Py version unexpectedly returns a process tree instead of raising, the `PetriTree` cells should be changed to `approximated` and the tree should be quarantined unless it passes all Section 5 round-trip checks. For this non-block-structured source, `conversion failed` is the expected and acceptable outcome.

Additional audit observations:

- **True concurrency versus arbitrary interleaving:** The trace oracle confirms both interleavings of A and P, but not simultaneous execution. A Petri net token game and BPMN parallel gateway both model concurrency as non-deterministic interleaving in trace semantics.
- **Lack of edge between optional legal review and verification:** The source has no edge between `optional_legal` and `verification_loop`. The witness set includes L before the loop and L after the loop but before release, confirming no causal order at the trace level.
- **Silent optional behavior:** `skip_legal` is invisible. Therefore the legal branch completion invariant is only partially observable.
- **Binary-loop semantics:** The loop has a body and a redo child. Correct Defect is a redo separator, not an exit activity; a trace ending with D before release is rejected.
- **Join before Release:** Release has incoming edges from both `optional_legal` and `verification_loop`. The trace oracle verifies the verification side; the legal side is hidden by the silent skip.
- **Activity-label uniqueness:** Visible labels are unique in the source. The label multiset check in Section 5 detects duplicate or renamed visible labels.
- **Initial and final markings:** `im` and `fm` are checked as non-null. A trace is completed only when the local marking equals `fm`.
- **BPMN gateway ambiguity:** The BPMN diagram is a visualization, not a formal semantics; Section 6 addresses how it can be misread.

# 5. Round-Trip Validation Code

```python
from collections import Counter, deque
from pm4py.objects.petri_net.obj import Marking


def place_token_key(p):
    name = getattr(p, "name", None)
    return name if name is not None else id(p)


def marking_key(m):
    return tuple(sorted((place_token_key(p), c) for p, c in m.items() if c > 0))


def copy_marking(m):
    new = Marking()
    for p, c in m.items():
        if c > 0:
            new[p] = c
    return new


def fire_transition(net, marking, t):
    new = copy_marking(marking)
    for arc in t.in_arcs:
        w = getattr(arc, "weight", 1)
        p = arc.source
        remaining = new.get(p, 0) - w
        if remaining == 0:
            if p in new:
                del new[p]
        else:
            new[p] = remaining
    for arc in t.out_arcs:
        w = getattr(arc, "weight", 1)
        p = arc.target
        new[p] = new.get(p, 0) + w
    return new


def bounded_visible_traces(net, im, fm, max_visible=12, max_silent_per_segment=1000):
    completed = set()
    queue = deque()
    queue.append((copy_marking(im), (), 0))
    visited = set()

    while queue:
        marking, trace, silent_steps = queue.popleft()
        key = (marking_key(marking), trace)
        if key in visited:
            continue
        visited.add(key)

        if marking == fm:
            completed.add(trace)
            continue

        enabled = pm4py.get_enabled_transitions(net, marking)
        for t in enabled:
            if t.label is None:
                if silent_steps >= max_silent_per_segment:
                    continue
                new_marking = fire_transition(net, marking, t)
                queue.append((new_marking, trace, silent_steps + 1))
            else:
                if len(trace) + 1 > max_visible:
                    continue
                new_marking = fire_transition(net, marking, t)
                queue.append((new_marking, trace + (t.label,), 0))

    return completed


def visible_label_multiset(net):
    return Counter(t.label for t in net.transitions if t.label is not None)


def directly_follows(traces):
    return {(a, b) for tr in traces for a, b in zip(tr, tr[1:])}


def report_equivalence(tag, baseline_traces, other_traces):
    missing = baseline_traces - other_traces
    extra = other_traces - baseline_traces
    print(f"{tag}: missing={len(missing)} extra={len(extra)}")
    if missing:
        print("  missing examples:", sorted(missing)[:5])
    if extra:
        print("  extra examples:", sorted(extra)[:5])
    return not missing and not extra


POSITIVE_WITNESSES = {
    "no_legal": (
        "Register Change", "Assess Risk", "Prepare Evidence",
        "Configure Trial", "Inspect Trial", "Release Change", "Archive Change",
    ),
    "with_legal": (
        "Register Change", "Assess Risk", "Prepare Evidence", "Legal Review",
        "Configure Trial", "Inspect Trial", "Release Change", "Archive Change",
    ),
    "two_iterations": (
        "Register Change", "Assess Risk", "Prepare Evidence",
        "Configure Trial", "Inspect Trial", "Correct Defect",
        "Configure Trial", "Inspect Trial", "Release Change", "Archive Change",
    ),
    "legal_before_loop": (
        "Register Change", "Assess Risk", "Legal Review", "Prepare Evidence",
        "Configure Trial", "Inspect Trial", "Release Change", "Archive Change",
    ),
    "legal_after_loop": (
        "Register Change", "Assess Risk", "Prepare Evidence",
        "Configure Trial", "Inspect Trial", "Legal Review",
        "Release Change", "Archive Change",
    ),
    "reverse_assess_prepare": (
        "Register Change", "Prepare Evidence", "Assess Risk",
        "Configure Trial", "Inspect Trial", "Release Change", "Archive Change",
    ),
}

NEGATIVE_WITNESSES = {
    "assess_before_register": (
        "Assess Risk", "Register Change", "Prepare Evidence",
        "Configure Trial", "Inspect Trial", "Release Change", "Archive Change",
    ),
    "release_before_verification": (
        "Register Change", "Assess Risk", "Prepare Evidence",
        "Release Change", "Archive Change",
    ),
    "missing_prepare": (
        "Register Change", "Assess Risk", "Configure Trial",
        "Inspect Trial", "Release Change", "Archive Change",
    ),
    "inspect_before_configure": (
        "Register Change", "Assess Risk", "Prepare Evidence",
        "Inspect Trial", "Configure Trial", "Release Change", "Archive Change",
    ),
    "redo_before_first_iteration": (
        "Register Change", "Assess Risk", "Prepare Evidence",
        "Correct Defect", "Configure Trial", "Inspect Trial",
        "Release Change", "Archive Change",
    ),
    "redo_at_end": (
        "Register Change", "Assess Risk", "Prepare Evidence",
        "Configure Trial", "Inspect Trial", "Correct Defect",
        "Release Change", "Archive Change",
    ),
}


def check_witnesses(tag, traces):
    print(tag, "witnesses:")
    for name, tr in POSITIVE_WITNESSES.items():
        print("  positive", name, tr in traces)
    for name, tr in NEGATIVE_WITNESSES.items():
        print("  negative", name, tr not in traces)


baseline_traces = bounded_visible_traces(
    net_from_powl, im_from_powl, fm_from_powl,
    max_visible=12,
)
print("baseline completed trace count:", len(baseline_traces))
check_witnesses("baseline", baseline_traces)

all_nets = [
    ("baseline", net_from_powl, im_from_powl, fm_from_powl),
]
if net_from_bpmn is not None:
    all_nets.append(("bpmn_roundtrip", net_from_bpmn, im_from_bpmn, fm_from_bpmn))
if net_from_tree_bpmn is not None:
    all_nets.append(("tree_bpmn_roundtrip", net_from_tree_bpmn, im_from_tree_bpmn, fm_from_tree_bpmn))

baseline_labels = visible_label_multiset(net_from_powl)
for tag, net, im, fm in all_nets:
    print(tag, "label multiset equal:", visible_label_multiset(net) == baseline_labels)

    try:
        fp = pm4py.discover_footprints(net, im, fm)
        print(tag, "footprints computed:", type(fp).__name__)
    except Exception as e:
        print(tag, "footprints error:", type(e).__name__, e)

    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        if hasattr(rg, "number_of_nodes"):
            print(tag, "reachability nodes/edges:", rg.number_of_nodes(), rg.number_of_edges())
        else:
            print(tag, "reachability graph type:", type(rg).__name__)
    except Exception as e:
        print(tag, "reachability error:", type(e).__name__, e)

baseline_df = directly_follows(baseline_traces)
for tag, net, im, fm in all_nets[1:]:
    other_traces = bounded_visible_traces(
        net, im, fm, max_visible=12
    )
    report_equivalence(tag, baseline_traces, other_traces)
    check_witnesses(tag, other_traces)
    print(tag, "directly-follows equal:", directly_follows(other_traces) == baseline_df)
```

With `max_visible=12`, the traversal is exhaustive for accepted visible traces of length  12. It expands each reachable `(marking, visible trace)` pair at most once, stops at the exact final marking `fm`, hides transitions with `label is None`, and uses `visited` plus a silent-step bound to avoid infinite silent cycling. It covers all positive witnesses above, including two verification iterations with legal review. It is not a proof for traces longer than 12 visible events.

# 6. Visual-Semantics Review

A BPMN rendering can be misread even when the converted net is behaviorally acceptable.

- **Parallel gateways:** An AND split/join is often drawn side-by-side, which may imply simultaneous execution. In the underlying semantics it only means that the branches are enabled without order. The actual execution is an interleaving.
- **Exclusive gateways:** The legal-review XOR may be shown as an exclusive gateway with an unlabeled default flow for the silent skip. A viewer may not understand that “skip legal review” is an explicit modeled choice.
- **Loop visualization:** A BPMN loop marker on a subprocess may suggest a standard `while` or `repeat` loop. The source loop is binary: `trial_body` is executed at least once; after it, `correct_defect` may return to the body; the loop cannot exit after `correct_defect`.
- **Silent routing nodes:** Silent transitions often become invisible sequence flows or implicit gateways in BPMN. They are semantically meaningful for optionality and loop exit, but they are not visible as labeled activities.
- **Apparent ordering of graph layout:** Left-to-right placement may make parallel branches look sequential. The legal branch may appear before or after the verification loop solely because of layout, not semantics.

Annotations and documentation should reduce this ambiguity:

- Attach invariant IDs such as `INV-CONC-1`, `INV-OPT-1`, and `INV-LOOP-2` to the corresponding BPMN elements.
- Annotate the silent skip flow as “No legal review (silent)”.
- Use a legend stating: AND gateway = interleaved concurrency, XOR gateway = exclusive choice, loop subprocess = body first, redo after body, at least one body.
- Add a note under the diagram: “Layout order is not semantic order.”
- Keep the BPMN file as a derivative artifact; do not edit it as if it were the source of truth.

# 7. Rejection Criteria

A conversion result should be rejected or quarantined if any of the following occurs:

1. Any conversion function returns `None`, raises an unhandled exception, or violates the expected API contract.
2. `pm4py.check_is_workflow_net(net)` returns `False`, or `pm4py.check_soundness(...)` reports unsoundness.
3. The visible label multiset changes, or a visible label is duplicated.
4. The bounded completed-trace set differs between the baseline accepting Petri net and any round-tripped net.
5. A required positive witness is missing, or a required negative witness is accepted.
6. Exact final-marking equality is not satisfied for a completed trace, or a non-final deadlock is found.
7. Release Change is admitted before verification has completed, or before the legal branch has observably/silently completed.
8. Optional legal behavior collapses: either the with-L trace or the no-L trace is rejected.
9. The loop semantics change: minimum iteration count is lost, Correct Defect appears before the first iteration, or Correct Defect appears immediately before Release without another iteration.
10. A process-tree conversion succeeds but the resulting tree or BPMN fails the same validation suite.

# 8. Canonical Representation Recommendation

**Authoritative model:** the source POWL definition. It is the only representation that directly expresses the intended partial order, optionality, and binary-loop semantics without conversion-induced ambiguity.

**Canonical storage model:** the source POWL, stored as versioned code or a versioned POWL serialization. It is the editable source of truth.

**Stakeholder visualization:** BPMN generated from the accepting Petri net. It is a derivative, not an authoritative model.

**Derivative artifacts:** the accepting Petri net, the BPMN model, any process tree, the reachability graph, footprint diagnostics, and visualizations. Each derivative must be regenerated from the source POWL.

**Validation evidence accompanying each derivative:**

- workflow-net and soundness diagnostics;
- label multiset comparison;
- bounded completed-trace equivalence with the source-derived accepting Petri net;
- positive and negative witness trace results;
- generation log and PM4Py version;
- visual review notes for BPMN.

**Process-tree intermediate:** it should be allowed only as a temporary experimental artifact, never as a canonical or editable representation. Because the source is not block-structured, a process-tree conversion failure is expected and acceptable. If a tree is produced, it must pass the full validation suite before it may be used even transiently.

**Avoiding round-trip drift:**

- Edit only the source POWL.
- Never hand-edit the generated Petri net, BPMN, or process tree.
- Run the invariant and round-trip suite after every source change.
- Pin the PM4Py version in the validation environment.
- Reject any derivative whose validation evidence is missing.

# 9. Residual Uncertainty

Even if every test above passes, the following cannot be established:

1. Full unbounded language equivalence: the trace comparison is exhaustive only up to 12 visible events, so loop behaviors with more iterations are not proven equivalent.
2. Silent-choice placement: because the legal skip is invisible, visible trace equivalence cannot prove that Release is never enabled before the legal branch has completed. A marking-level bisimulation or state invariant would be required.
3. PM4Py version independence: conversion functions, exception behavior, and BPMN layout can change between versions; this validation is specific to the observed environment.
4. Human interpretation of BPMN: automatic diagnostics cannot guarantee that a stakeholder will correctly read parallel gateways, silent skip flows, or loop semantics from the visual diagram.
