## 1. Normalization Assumptions

1. **Clock-offset direction**  
   For each source, `clock_offset = recorded_clock - true_clock`. Given an offset bound `[a, b]`, true time  `recorded_clock – b, recorded_clock – a`.  
   
2. **Handling of timestamp resolution**  
   Resolution/rounding uncertainty is applied **first** to obtain the internal clock-reading interval, then the clock-offset bound is applied to obtain the truetime interval.  
   - HUB: exact to the displayed second, measurement uncertainty ±0.5s  internal reading  `[recorded – 0.5s, recorded + 0.5s]`. Offset  [1,1]s  true  `[recorded – 1.5s, recorded + 1.5s]`.  
   - OPSBER / VENDORNY / LEGACYBER: floor to minute  internal local time  `[displayed_minute, displayed_minute + 60s)`. Convert to UTC using the timezone offset at that instant. Offset bound gives final expansion.  
   - SENSOR: round to nearest 10s  internal reading  `[recorded – 5s, recorded + 5s)`. Offset  [5,5]s  true  `[recorded – 10s, recorded + 10s]`.  
   - MOBILELON: round to nearest minute  internal local time  `[displayed_minute – 30s, displayed_minute + 30s)`. Offset  [300,300]s. Userentry delay : up to 5min **after** the actual occurrence; we model this by expanding the truetime interval backwards by 0–5min (shifts occurrence earlier).  

3. **Timezone conversion**  
   - CEST = UTC+2, EDT = UTC4, BST = UTC+1.  
   - For DSTfold (T405, Europe/Berlin 20251026), local times 02:00–02:59 are ambiguous (CEST UTC+2 or CET UTC+1). We enumerate both folds, compute intervals, and retain only those foldcombinations compatible with the ingestion sequence.  

4. **Causal ordering constraints**  
   Unless otherwise noted, we enforce the lifecycle: `Alert_Received  Investigation_Start  Containment_Complete  Close_Incident`. For T407, the given causal assumption is explicitly used. For T409, we apply the same principle (otherwise negative durations would occur).  

5. **Missing events**  
   - T404 (missing `Investigation_Start`): inferred from `Investigation_Complete` minus a duration of [18min,25min].  
   - T407 (missing `Alert_Received`): inferred from `Alert_Sent` + delivery latency [0,20min] and the condition `Alert_Received  Investigation_Start`.  

6. **Midpoint usage**  
   Midpoints are only used for the lossy PM4Py comparison; all primary conformance decisions are intervalbased.

# 2. Interval-based conformance classification functions
# ------------------------------------------------------------
def duration_interval(df, case, act1, act2):
    """Return (min_dur, max_dur) in seconds for act2 - act1, or None if missing."""
    row1 = df[(df["case"]==case) & (df["Activity"]==act1)]
    row2 = df[(df["case"]==case) & (df["Activity"]==act2)]
    if row1.empty or row2.empty:
        return None
    e1, l1 = row1.iloc[0]["earliest_utc"], row1.iloc[0]["latest_utc"]
    e2, l2 = row2.iloc[0]["earliest_utc"], row2.iloc[0]["latest_utc"]
    # assume ordering act1 <= act2; enforce by clipping
    min_dur = max(timedelta(0), (e2 - l1)).total_seconds()
    max_dur = max(timedelta(0), (l2 - e1)).total_seconds()
    return (min_dur, max_dur)

def classify_sla(dur, limit):
    if dur is None:
        return "INDETERMINATE"
    lo, hi = dur
    if hi <= limit:
        return "CERTAIN_PASS"
    if lo > limit:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

def classify_profile(dur, avg, std, zeta):
    if dur is None:
        return "INDETERMINATE"
    lo, hi = dur
    band_lo = avg - zeta*std
    band_hi = avg + zeta*std
    if hi < band_lo or lo > band_hi:
        return "CERTAIN_VIOLATION"
    if lo >= band_lo and hi <= band_hi:
        return "CERTAIN_PASS"
    return "POSSIBLE_VIOLATION"

## 6. Evidential Sufficiency

For each INDETERMINATE or POSSIBLE_VIOLATION result, the minimum additional evidence that would resolve it to CERTAIN:

| Result type                  | Examples                                      | Sufficient evidence                                                                                                |
|------------------------------|-----------------------------------------------|---------------------------------------------------------------------------------------------------------------------|
| INDETERMINATE – missing event| S3 in T402…T409, Pair4 missing Close        | `Close_Incident` timestamp from any source with known offset bound (or a signed work record of closure duration).  |
| POSSIBLE_VIOLATION – S1/S2   | T401 S1, T402 S2, T404 S2, T406 S1/S2, …| Tighter clockoffset bounds (e.g., subsecond NTP confirmation for OPSBER, authenticated mobile clock).           |
| POSSIBLE_VIOLATION – wide start/alert intervals | T403 S1, T409 S1                    | Direct duration measurement from a trusted system, or a secure receipt acknowledgment with a narrow UTC timestamp. |
| POSSIBLE_VIOLATION – DST fold| T405 S1                                      | Logging of the actual DST flag (fold bit) from the legacy system, or correlation with a UTCreferenced log.        |
| POSSIBLE_VIOLATION – inferred start| T404 S1, S2                             | Explicit `Investigation_Start` timestamp from a hightrust source, or a precise automated start event.             |
| POSSIBLE_VIOLATION – delivery latency | T407 S1                              | A delivery acknowledgment timestamp from the receiving system with known offset, or network packet capture.        |
| POSSIBLE_VIOLATION – temporal profiles | many Pair1, Pair2                   | Same as above – narrower intervals eliminate overlap with the acceptance band.                                    |

## 7. Governance Recommendation

1. **UTC storage** – All eventtime data must be stored as UTC `datetime` with subsecond precision; localtime displays should be derived, never stored as primary evidence.  
2. **Raw timestamp retention** – Always keep the original recorded value alongside the normalized UTC value, including the raw clock reading and its timezone label.  
3. **Source offset telemetry** – Continuously collect and attach NTPoffset statistics (min/max per hour) for each source; require authenticated synchronization (e.g., NTP with authentication, PTP) for SLAcritical systems.  
4. **Resolution metadata** – Record the timestamp’s resolution (e.g., “floor to minute”, “round to 10s”) and measurement uncertainty (e.g., “±0.5s unavoidable jitter”) as structured fields.  
5. **Start/complete semantics** – For lifecycle activities, log both start and completion events with explicit activity labels (e.g., `Investigation_Start`, `Investigation_Complete`) and enforce their causal ordering in the schema.  
6. **DST fold** – Any system that generates local timestamps in DSTtransition windows MUST log a UTC offset or a fold indicator (0/1) alongside the local time.  
7. **Causal identifiers** – For every activity pair, log a correlation ID that definitively links the `received` event to the `sent` event (e.g., a message queue ID), eliminating the need for inferred causal bounds.  
8. **Intervaloverlap policy** – Adopt a governance rule that SLA enforcement uses interval reasoning: a violation is prosecutable **only** when the entire feasible interval exceeds the limit (CERTAIN_VIOLATION); POSSIBLE_VIOLATION triggers an investigation but does not automatically penalize.  
9. **Audit logging** – Store all derivations (conversions, offset bounds, DST interpretations) immutably so that any future reinterpretation can be traced and repeated.
