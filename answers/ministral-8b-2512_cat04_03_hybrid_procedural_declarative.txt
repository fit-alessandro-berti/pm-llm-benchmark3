  1. Sanctions Escalation occurred

- **Compliance Risk:** Requires external authorization tracking which isn't logged

- Procedural model enforces opinion before activation by default
- Resource layer validates emergency cases through external check
- Temporal profile flags late opinions as warnings

def check_resource_constraints(log_df):
    """Check R9 segregation of duties and R6 emergency policy"""
    violations = []

    # R9: Verify Bank Account and approval resources differ
    for _, case in log_df.groupby('case:concept:name'):
        verify_bank = case[case['concept:name'] == 'Verify Bank Account']['resource']
        approvals = case[case['concept:name'].isin(['Manager Approval', 'Compliance Approval'])]['resource']

        if not verify_bank.empty and not approvals.empty:
            if verify_bank.iloc[0] == approvals.iloc[0]:
                violations.append({
                    'case': case.name,
                    'requirement': 'R9',
                    'message': f"Verify Bank Account and approval by same resource: {verify_bank.iloc[0]}"
                })

        # R9: Capture Master Data and Activate Vendor resources differ
        capture = case[case['concept:name'] == 'Capture Master Data']['resource']
        activate = case[case['concept:name'] == 'Activate Vendor']['resource']

        if not capture.empty and not activate.empty:
            if capture.iloc[0] == activate.iloc[0]:
                violations.append({
                    'case': case.name,
                    'requirement': 'R9',
                    'message': f"Capture Master Data and activation by same resource: {capture.iloc[0]}"
                })

    # R6: Emergency activation check (requires external data)
    # This would need integration with external authorization system
    emergency_cases = []
    for _, case in log_df.groupby('case:concept:name'):
        has_escalation = 'Sanctions Escalation' in case['concept:name'].values
        has_activation_before_opinion = (
            case[case['concept:name'] == 'Activate Vendor']['time:timestamp'].min() <
            case[case['concept:name'] == 'Obtain Legal Opinion']['time:timestamp'].min()
        )

        if has_escalation and has_activation_before_opinion:
            emergency_cases.append(case.name)

    if emergency_cases:
        violations.append({
            'case': emergency_cases,
            'requirement': 'R6',
            'message': 'Emergency activation detected - requires external authorization validation'
        })

    return violations

def check_four_eyes(log_df):
    """Check R4 four-eyes principle for critical activities"""
    critical_pairs = [
        ('Verify Bank Account', 'Manager Approval'),

            violations.append({

                'message': f"Four-eyes violation detected for {pair}"

## 9. Contradictions, Redundancies, and Blind Spots

1. **Duplicated Enforcement:**
   - R1 enforced in both Log Skeleton (`never_together`) and DECLARE (`noncoexistence`)
   - R2 enforced in both DECLARE (`exactly_one`) and Log Skeleton (`activ_freq`)
   - Redundancy is acceptable for cross-validation

2. **Constraints Under Loops:**
   - Clarification loops (R3) create temporal windows where:
     - Final outcomes can't occur until all clarifications are answered
     - DECLARE's `nonchainsuccession` prevents approvals before complete response chains
     - Log skeleton's `always_before` ensures classification happens after all responses

3. **Vacuity in Declarative Rules:**
   - Some DECLARE rules have high confidence but low support (e.g., `precedence` for escalation)
   - These represent normative expectations rather than absolute requirements

4. **Missing Case Attributes:**
   - No "emergency" flag in logs (R6)
   - No explicit risk classification (only inferred from path)
   - No explicit authorization data for emergency cases

5. **Timestamp Limitations:**
   - Can't distinguish between:
     - Intentional delays vs. processing times
     - Resource availability vs. actual work duration
   - Only relative timing can be analyzed

6. **Support/Confidence Risks:**
   - Confidence values are subjective
   - Support values may change with more data
   - Treating them as normative could lead to false positives
