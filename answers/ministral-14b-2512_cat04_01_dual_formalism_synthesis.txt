# 1. Assumptions and Interpretation

1. **Low-risk/High-risk choice**: Represented as an XOR split after `Analyze Root Cause` with two branches:
   - Low-risk branch: `Supervisor Review` only.
   - High-risk branch: Parallel composition of `Quality Review` and `Regulatory Review` (order unspecified).
   *Assumption*: The choice is deterministic but not observable in the trace (hidden condition).

2. **Optional supplier consultation**: Represented as a silent choice (-transition) after `Analyze Root Cause` with:
   - One branch: `Consult Supplier` (optional).
   - Other branch: empty (no supplier consultation).
   *Assumption*: The decision is data-driven and not encoded in the model.

3. **Passing inspection**: Abstracted as a loop where `Inspect Trial` must eventually succeed (no explicit "pass" event). The loop terminates when `Inspect Trial` is followed by `Adjust Parameters` *or* by `Release Material` (implied success).
   *Assumption*: A trace without `Adjust Parameters` after `Inspect Trial` implies a passing inspection.

4. **Duplicate visible labels**: Permitted only for `Inspect Trial`/`Execute Trial` cycles (e.g., `Inspect Trial` may appear multiple times in a trace). All other activities are unique per occurrence.

5. **Approximation policy**:
   - **Process Tree**: Conservative under-approximation for overlapping activities (e.g., `Plan Verification` and `Design Corrective Action` are forced sequential in some branches to avoid over-approximation).
   - **POWL**: Exact representation of partial-order dependencies; overlaps are modeled via silent transitions where needed.

6. **"May overlap"**: Interpreted as **true concurrency** (no order constraint) in POWL. In the process tree, overlaps are approximated by parallel operators where possible, but some interleavings are excluded due to tree structure limitations.

|----|---------------------------|--------------------------|----------|-----------|

# 3. PM4Py Process-Tree Model

### Compact Process-Tree Expression
```text
Start -> RegisterDeviation -> (ContainMaterial || AnalyzeRootCause)
    -> (PlanVerification after ContainMaterial)
    -> (DesignCorrectiveAction after AnalyzeRootCause)
    -> (XOR: SupervisorReview || (QualityReview || RegulatoryReview))
    -> (Optional: ConsultSupplier after AnalyzeRootCause)
    -> (ExecuteTrial after (DesignCorrectiveAction && PlanVerification))
    -> (InspectTrial -> (AdjustParameters -> ExecuteTrial)* -> ReleaseMaterial)
    -> ArchiveCase
```

### Python Code
```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

# Build the tree step-by-step
tree = ProcessTree()

# Start -> RegisterDeviation
start = ProcessTree()
start.label = "Start"
register = ProcessTree()
register.label = "Register Deviation"
start.children.append(register)
register.parent = start

# RegisterDeviation -> (ContainMaterial || AnalyzeRootCause)
contain = ProcessTree()
contain.label = "Contain Material"
analyze = ProcessTree()
analyze.label = "Analyze Root Cause"
parallel = ProcessTree()
parallel.operator = Operator.PARALLEL
parallel.children = [contain, analyze]
contain.parent = parallel
analyze.parent = parallel
register.children.append(parallel)
parallel.parent = register

# ContainMaterial -> PlanVerification
plan = ProcessTree()
plan.label = "Plan Verification"
sequence_contain = ProcessTree()
sequence_contain.operator = Operator.SEQUENCE
sequence_contain.children = [contain, plan]
contain.parent = sequence_contain
plan.parent = sequence_contain
# Replace contain in parallel with sequence_contain
parallel.children[0] = sequence_contain
sequence_contain.parent = parallel

# AnalyzeRootCause -> DesignCorrectiveAction
design = ProcessTree()
design.label = "Design Corrective Action"
sequence_analyze = ProcessTree()
sequence_analyze.operator = Operator.SEQUENCE
sequence_analyze.children = [analyze, design]
analyze.parent = sequence_analyze
design.parent = sequence_analyze
# Replace analyze in parallel with sequence_analyze
parallel.children[1] = sequence_analyze
sequence_analyze.parent = parallel

# Risk route (XOR)
supervisor = ProcessTree()
supervisor.label = "Supervisor Review"
quality = ProcessTree()
quality.label = "Quality Review"
regulatory = ProcessTree()
regulatory.label = "Regulatory Review"
xor = ProcessTree()
xor.operator = Operator.XOR
xor.children = [supervisor, ProcessTree(operator=Operator.PARALLEL, children=[quality, regulatory])]
xor.parent = design  # Attach to DesignCorrectiveAction (approximation: assumes design completes before risk route)
design.children.append(xor)
xor.parent = design

# Optional ConsultSupplier
consult = ProcessTree()
consult.label = "Consult Supplier"
optional = ProcessTree()
optional.operator = Operator.XOR
optional.children = [ProcessTree(), consult]  # Empty branch for "no supplier"
optional.parent = analyze
analyze.children.append(optional)
optional.parent = analyze

# Trial loop
execute = ProcessTree()
execute.label = "Execute Trial"
inspect = ProcessTree()
inspect.label = "Inspect Trial"
adjust = ProcessTree()
adjust.label = "Adjust Parameters"
loop = ProcessTree()
loop.operator = Operator.LOOP
loop.children = [inspect, ProcessTree(operator=Operator.SEQUENCE, children=[adjust, execute])]
# Attach loop to execute (approximation: assumes trial starts after design and plan)
sequence_trial = ProcessTree()
sequence_trial.operator = Operator.SEQUENCE
sequence_trial.children = [execute, loop]
execute.parent = sequence_trial
loop.parent = sequence_trial

# Synchronization for ReleaseMaterial
release = ProcessTree()
release.label = "Release Material"
# Approximation: Force sequence for design/plan -> trial -> release
# (POWL handles overlaps better)
sequence_release = ProcessTree()
sequence_release.operator = Operator.SEQUENCE
sequence_release.children = [sequence_trial, release]
sequence_trial.parent = sequence_release
release.parent = sequence_release

# ArchiveCase
archive = ProcessTree()
archive.label = "Archive Case"
sequence_final = ProcessTree()
sequence_final.operator = Operator.SEQUENCE
sequence_final.children = [release, archive]
release.parent = sequence_final
archive.parent = sequence_final
sequence_release.children.append(sequence_final)
sequence_final.parent = sequence_release

# Assign root
tree.root = start
```

### Limitations
1. **Overlap Approximation**: The process tree forces `Design Corrective Action` and `Plan Verification` to complete before the risk route (XOR) starts, violating the intended concurrency.
2. **Supplier Consultation**: The optional `Consult Supplier` is attached to `Analyze Root Cause` but cannot overlap with later activities (e.g., trial) due to tree structure.
3. **Trial Loop**: The loop is modeled as `Inspect Trial -> (Adjust Parameters -> Execute Trial)*`, but the process tree cannot enforce that `Adjust Parameters` must precede a *new* `Inspect Trial` without explicit sequencing.
4. **Release Synchronization**: The tree cannot express that `Release Material` depends on *both* the risk route *and* `Consult Supplier` (if selected) without forcing a strict order.

# 4. PM4Py POWL Model

### Compact POWL Description
```text
Nodes: Start, RD, CM, ARC, PV, DCA, SR, QR, RR, CS, ET, IT, AP, RM, AC
Edges:
  Start -> RD
  RD -> CM | RD -> ARC
  CM -> PV
  ARC -> DCA | ARC -> (QR || RR) | ARC -> (SR)
  ARC -> CS (optional)
  DCA  PV -> ET
  ET -> IT
  IT -> AP -> ET | IT -> RM (if risk route and CS complete)
  RM -> AC
  CS -> RM
  SR -> RM | QR -> RM | RR -> RM
```

### Python Code
```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)

# Nodes
nodes = [
    "Start", "RD", "CM", "ARC", "PV", "DCA", "SR", "QR", "RR", "CS", "ET", "IT", "AP", "RM", "AC"
]
powl = StrictPartialOrder(nodes)

# Transitions
transitions = {
    "Start": [Transition("Start", "RD")],
    "RD": [
        Transition("RD", "CM"),
        Transition("RD", "ARC"),
    ],
    "CM": [Transition("CM", "PV")],
    "ARC": [
        Transition("ARC", "DCA"),
        Transition("ARC", "SR"),
        Transition("ARC", "QR"),
        Transition("ARC", "RR"),
        Transition("ARC", "CS"),  # Optional
    ],
    "DCA": [Transition("DCA", "ET")],
    "PV": [Transition("PV", "ET")],
    "ET": [Transition("ET", "IT")],
    "IT": [
        Transition("IT", "AP"),
        Transition("IT", "RM"),  # Implicit: risk route and CS complete
    ],
    "AP": [Transition("AP", "ET")],
    "SR": [Transition("SR", "RM")],
    "QR": [Transition("QR", "RM")],
    "RR": [Transition("RR", "RM")],
    "CS": [Transition("CS", "RM")],
    "RM": [Transition("RM", "AC")],
}

# Add transitions
for src, trs in transitions.items():
    for tr in trs:
        powl.transitions[src].append(tr)

# Partial-order edges (precedence)
powl.order.add_edge("RD", "CM")
powl.order.add_edge("RD", "ARC")
powl.order.add_edge("CM", "PV")
powl.order.add_edge("ARC", "DCA")
powl.order.add_edge("ARC", "SR")
powl.order.add_edge("ARC", "QR")
powl.order.add_edge("ARC", "RR")
powl.order.add_edge("ARC", "CS")  # Optional
powl.order.add_edge("DCA", "ET")
powl.order.add_edge("PV", "ET")
powl.order.add_edge("ET", "IT")
powl.order.add_edge("IT", "AP")  # Only if inspection fails
powl.order.add_edge("AP", "ET")
powl.order.add_edge("SR", "RM")
powl.order.add_edge("QR", "RM")
powl.order.add_edge("RR", "RM")
powl.order.add_edge("CS", "RM")  # Must complete before RM
powl.order.add_edge("RM", "AC")

# Operators (XOR, LOOP)
xor_risk = OperatorPOWL(Operator.XOR)
xor_risk.children = ["SR", "QR", "RR"]
powl.operators["ARC"].append(xor_risk)  # Attach to ARC (approximation: assumes ARC completes before risk route)

loop_trial = OperatorPOWL(Operator.LOOP)
loop_trial.children = ["IT", "AP", "ET"]
powl.operators["ET"].append(loop_trial)  # Attach to ET

# Optional CS
optional_cs = OperatorPOWL(Operator.XOR)
optional_cs.children = ["CS", ""]  # Empty branch
powl.operators["ARC"].append(optional_cs)

# Silent transitions for overlaps (e.g., CS can overlap with trial)
powl.transitions["CS"].append(SilentTransition("CS", "ET"))  # CS can overlap with trial
powl.transitions["CS"].append(SilentTransition("CS", "RM"))  # CS must complete before RM
```

### Unconnected Nodes
- **`DCA` and `PV`**: Unconnected except via `ET` because they can proceed concurrently after `ARC`/`CM`.
- **`QR`/`RR` and `ET`**: Unconnected to allow approvals to overlap with trial.
- **`CS` and `ET`**: Unconnected to allow supplier consultation to overlap with trial (via silent transition).

# 6. Semantic Comparison

| Requirement | Intended semantics | Process tree | POWL | Overconstraint or underconstraint | Business consequence |
|-------------|--------------------|--------------|------|------------------------------------|----------------------|
| Initial work streams | `CM` and `ARC` can overlap after `RD`. | **Overconstrained**: Forces `CM` before `ARC`. | Exact | Process tree excludes valid interleavings. | Delays in containment may block root-cause analysis unnecessarily. |
| Split dependencies | `PV` depends on `CM`; `DCA` depends on `ARC`. | Exact | Exact | None | Correct. |
| Risk route | XOR between `SR` and `(QR  RR)`. | Exact | Exact | None | Correct. |
| Overlap of approval and trial | `QR`/`RR` can overlap with `ET`/`IT`. | **Overconstrained**: Forces approvals before trial. | Exact | Process tree excludes valid overlaps. | Approvals may delay trial unnecessarily. |
| Optional supplier consultation | `CS` is optional and can overlap with other activities. | **Underconstrained**: Forces `CS` before `ET`. | Exact (with silent transitions) | Process tree excludes overlaps. | Supplier feedback may be delayed. |
| Repeat-until behavior | `ET`  `IT`  (`AP`  `ET`)* until `IT` passes. | Exact | Exact | None | Correct. |
| Release synchronization | `RM` requires passing `IT`, completed risk route, and `CS` (if selected). | **Underconstrained**: Cannot express all dependencies. | Exact | Process tree cannot enforce all preconditions. | Risk of releasing material prematurely. |
| Duplicate-label risk | Only `ET`/`IT` can repeat; other labels are unique. | Exact | Exact | None | Correct. |

# 7. Preferred Representation and Validation Plan

### Canonical Representation
**POWL** is the preferred representation because:
1. It exactly models **true concurrency** (e.g., `CM`/`ARC` overlap, approvals/trial overlap).
2. It handles **optional activities** (`CS`) and **loops** without forcing artificial sequencing.
3. It supports **partial-order dependencies** (e.g., `RM` depends on `IT`, risk route, and `CS`).
4. Silent transitions can model **unobservable overlaps** (e.g., `CS` overlapping with trial).

### Validation Plan
1. **Conversion to Petri Net**:
   ```python
   net, im, fm = pm4py.convert_to_petri_net(powl)
   ```
   - Check for dead transitions or livelocks.

2. **Soundness Checking**:
   ```python
   pm4py.check_soundness(net, im, fm, print_diagnostics=True)
   ```
   - Ensure no deadlocks or invalid behavior.

3. **Bounded Playout**:
   ```python
   traces = pm4py.play_out(powl, parameters={...}, max_length=10)
   ```
   - Generate traces up to length 10 to test all branches.

4. **Positive/Negative Trace Tests**:
   - **Allowed traces**: Test all combinations (low/high risk, with/without `CS`, 1/2 trials).
   - **Forbidden traces**: Test violations (e.g., `ET` before `PV`, `RM` before `CS`).

5. **Silent Behavior Check**:
   - Use `pm4py.get_silent_transitions(powl)` to verify silent transitions are only where intended (e.g., `CS` overlapping with trial).

6. **Duplicate-Label Check**:
   - Ensure only `ET`/`IT` can repeat by inspecting the POWL structure.

### Limitations
- POWL cannot explicitly model **data conditions** (e.g., "low risk"), but this is intentional per requirements.
- Validation is bounded by the playout length; infinite loops (e.g., failing inspections) require additional checks.

---

# 8. Final Self-Critique

1. **Semantic Loss in Process Tree**:
   The process tree cannot represent **true concurrency** between `CM`/`ARC` or approvals/trial, leading to overconstrained behavior. This is a fundamental limitation of tree structures for non-block-nested workflows.

2. **Ambiguous Loop Termination**:
   The POWL model assumes `IT`  `RM` implies a passing inspection, but this is not explicitly enforced. A more precise model would require a "pass" event or a loop guard.

3. **Optional Activity Handling**:
   The optional `CS` is modeled as an XOR with an empty branch, but this does not fully capture the **overlap semantics** with other activities. Silent transitions help, but their semantics are less intuitive than explicit concurrency in Petri nets.

4. **Python Implementation**:
   The POWL code could be more modular (e.g., separate functions for building the risk route or trial loop), but this was omitted for brevity.
