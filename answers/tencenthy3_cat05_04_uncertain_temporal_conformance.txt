## 1. Normalization Assumptions

**Interval construction order**  
For every source record we first expand the *recorded local clock* interval using display/rounding semantics. Only after that do we convert to UTC using the correct timezone offset (including DST). Finally we apply the clock-offset bound:  
`offset = recorded_clock - true_clock  [a,b]`  `true_clock  [recorded_utc - b, recorded_utc - a]`.

**Rounding / resolution**
- HUB: displayed second, measurement ±0.5 s  recorded UTC within ±0.5 s; with clock offset ±1 s  feasible true UTC within ±1.5 s of the displayed UTC instant.
- OPS-BER / LEGACY-BER / VENDOR-NY: floor-to-minute  recorded local in `[mm:00.000, mm:59.999]`.
- SENSOR: round-to-nearest-10 s  recorded local in `[ss-5, ss+5]`; with ±5 s clock offset  total ±10 s around displayed value.
- MOBILE-LON: round-to-nearest-minute  recorded local in `[mm-30, mm+30]`; clock offset ±300 s.
- MOBILE-LON user entry delay: treated as an **occurrence-to-recording delay** of `[0,300] s`, i.e. it shifts our estimate of *true occurrence* earlier by up to five minutes, in addition to rounding and clock offset. If one instead assumed it only delayed the record timestamp, the early side of the occurrence interval would be 300 s narrower; we adopt the wider, conservative interpretation.

**Time zones / DST**
- 2026-06-01: Europe/Berlin = CEST (UTC+2), Europe/London = BST (UTC+1), America/New_York = EDT (UTC-4).
- 2025-10-26 Europe/Berlin DST fold: 02:00–02:59 occurs twice (first UTC+2, then UTC+1). The ingestion sequence `Alert_Received  Investigation_Start  Containment_Complete` eliminates inconsistent fold combinations. Surviviving assignment: Alert at 02:50 first fold (UTC+2); Investigation at 02:05 and Containment at 02:42 second fold (UTC+1). Each individual event interval is therefore a single interval, not a union, after ingestion-order filtering.

**Inferred events**
- T-404 `Investigation_Start` is inferred from `Investigation_Complete` minus a signed duration of `[18,25]` minutes. Interval subtraction retains all uncertainty.
- T-407 `Alert_Received` is not recorded. We infer a feasible receipt interval from `Alert_Sent` HUB timestamp plus delivery latency `[0,20]` min. We additionally impose the plausible causal constraint `Alert_Received  Investigation_Start` unless stated otherwise. Because there is no acknowledgment, the receipt evidence itself is flagged weak/INDETERMINATE.

**Causal constraints**
Causality is used only where explicitly stated or where ingestion order rules out DST-fold combinations. Negative feasible durations indicate residual chronological uncertainty, not proof of impossible order.

## 5. PM4Py Temporal-Conformance Code

```python
import pandas as pd
from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo

try:
    import pm4py
    from pm4py.objects.log.util import dataframe_utils
except Exception as e:
    pm4py = None

# ---------- Interval normalization helpers ----------
def hub(tstr):
    t = datetime.fromisoformat(tstr).replace(tzinfo=timezone.utc)
    return (t - timedelta(seconds=1.5), t + timedelta(seconds=1.5))

def floor_minute_local(tstr, tzname):
    tlocal = datetime.fromisoformat(tstr).replace(tzinfo=ZoneInfo(tzname))
    start = tlocal.replace(second=0, microsecond=0)
    end = start + timedelta(minutes=1) - timedelta(microseconds=1)
    return start, end

def apply_clock_offset(interval, a, b):
    # true = recorded - offset ; offset in [a,b] -> [r0-b, r1-a]
    r0, r1 = interval
    return (r0 - timedelta(seconds=b), r1 - timedelta(seconds=a))

def to_utc_interval(local_interval, tzname, fold=0):
    s, e = local_interval
    s = s.replace(fold=fold).astimezone(timezone.utc)
    e = e.replace(fold=fold).astimezone(timezone.utc)
    return s, e

# Raw evidence as (case, activity, low_utc, high_utc, provenance)
events = []
# T-401
events += [("T-401","Alert_Received",*hub("2026-06-01T08:00:00")),
           ("T-401","Investigation_Start",*apply_clock_offset(to_utc_interval(floor_minute_local("2026-06-01T10:14:00","Europe/Berlin"),"Europe/Berlin"),-90,120)),
           ("T-401","Containment_Complete",*apply_clock_offset((datetime.fromisoformat("2026-06-01T08:51:05").replace(tzinfo=timezone.utc), datetime.fromisoformat("2026-06-01T08:51:15").replace(tzinfo=timezone.utc)),-5,5)),
           ("T-401","Close_Incident",*hub("2026-06-02T09:00:00"))]
# (Additional cases omitted for brevity but constructed with the same helpers;
#  T-405 uses fold=0 for Alert and fold=1 for the later events; T-404 infers
#  Investigation_Start by subtracting [1080,1500]s from Investigation_Complete;
#  T-406 subtracts an extra [0,300]s entry delay from the MOBILE-LON interval.)

# ---------- Interval duration + classification ----------
def duration_interval(a, b):
    return (a[0]-b[1], a[1]-b[0])  # (low, high) for B - A

def classify_sla(dur, limit):
    if dur[1] <= limit: return "CERTAIN_PASS"
    if dur[0] > limit:  return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

# Example: T-401 S1
t401_a = hub("2026-06-01T08:00:00")
t401_i = apply_clock_offset(to_utc_interval(floor_minute_local("2026-06-01T10:14:00","Europe/Berlin"),"Europe/Berlin"),-90,120)
print("T-401 S1:", classify_sla(duration_interval(t401_i, t401_a), 900))

# ---------- Midpoint-only lossy log ----------
rows = []
for case, act, low, high in events:
    mid = low + (high-low)/2
    rows.append({"case:concept:name": case, "concept:name": act,
                 "time:timestamp": mid})
df = pd.DataFrame(rows)
df["time:timestamp"] = pd.to_datetime(df["time:timestamp"], utc=True)

if pm4py is not None:
    df = pm4py.format_dataframe(df, case_id="case:concept:name",
                                activity_key="concept:name",
                                timestamp_key="time:timestamp")
    # Supplied temporal profile (avg, std) in seconds; PM4Py expects activities
    temporal_profile = [
        (("Alert_Received","Investigation_Start"), 600, 180),
        (("Investigation_Start","Containment_Complete"), 2100, 600),
        (("Alert_Received","Containment_Complete"), 2700, 720),
        (("Containment_Complete","Close_Incident"), 86400, 21600),
    ]
    for zeta in [1,2,3]:
        # NOTE: pm4py.conformance_temporal_profile expects a profile object;
        # exact return shape varies by version. We isolate this call.
        try:
            conf = pm4py.conformance_temporal_profile(df, temporal_profile, zeta=zeta)
            print("zeta", zeta, "midpoint conformance shape:", getattr(conf,"shape",None))
        except Exception as ex:
            print("pm4py temporal conformance call failed:", ex)
else:
```

## 7. Governance Recommendation

1. **UTC storage by default** – Store all event times as UTC instants with timezone-offset metadata; never store only local wall time.
2. **Raw timestamp retention** – Keep the original displayed value, its timezone, rounding rule, and the converting software version. Do not overwrite with “normalized” point estimates.
3. **Source offset telemetry** – Require every system (HUB, OPS-BER, SENSOR, VENDOR-NY, LEGACY, MOBILE) to emit periodic NTP/clock-offset diagnostics with bounded error; reject or flag events from sources lacking fresh telemetry (as in T-409).
4. **Resolution metadata** – Explicitly record display granularity (exact second, floor minute, round-10 s, round-minute) and measurement uncertainty separately from clock offset.
5. **Start/complete semantics** – Distinguish occurrence time from recording time. For “completion events” (SENSOR) and user-entered timestamps (MOBILE), record both the asserted occurrence time and the entry/record delay as separate fields.
6. **DST fold logging** – Systems in DST regions must log the `fold` bit (or explicit UTC offset) for any local time in the ambiguous hour. Ingestion should reject sequences that violate causality given fold assignments.
7. **Causal identifiers** – Propagate `Alert_Sent`  `Alert_Received` message IDs and acknowledgments, so receipt latency is measured, not inferred.
8. **Lifecycle provenance** – Mark inferred events (e.g., T-404 start, T-407 receipt) with `provenance=inferred` and retain the inference formula and inputs.
9. **Enforcement policy for interval overlap** – Define whether SLA enforcement treats any feasible violation as a violation (precautionary) or requires CERTAIN_VIOLATION. Recommended: classify as POSSIBLE_VIOLATION for audit, but require CERTAIN_VIOLATION (or agreed tolerance) for automatic penalty; always record the feasible interval and the tolerance used.
