# 1. Equivalence Notions

Let the visible alphabet be

[
\Sigma={\text{Open Case},\text{Analyze Revision},\text{Check Revision},
\text{Approve Revision},\text{Rework Case},\text{Close Case}}.
]

A **complete execution** starts at the initial state and reaches successful termination. Concurrency is observed through its possible sequential linearizations; timing, resources, and true simultaneity are outside the observation boundary.

For compact formulas, write:

* (O=) `Open Case`
* (A=) `Analyze Revision`
* (C=) `Check Revision`
* (P=) `Approve Revision`
* (R=) `Rework Case`
* (Z=) `Close Case`

## Visible trace equivalence after hiding `tau`

Let (\operatorname{Runs}(T)) be the complete executions of model (T). Let (\pi_{\tau}) erase all silent transitions and retain the labels of visible transitions in execution order. The complete visible language is

[
L_{\mathrm{vis}}(T)
===================

{\pi_{\tau}(\rho)\mid \rho\in\operatorname{Runs}(T)}.
]

Models (T_1) and (T_2) are visibly trace equivalent exactly when

[
T_1\equiv_{\mathrm{vis}}T_2
\iff
L_{\mathrm{vis}}(T_1)=L_{\mathrm{vis}}(T_2).
]

This is language equivalence, not branching bisimulation, history-preserving equivalence, or equivalence of causal structures.

**Duplicate-label policy:** observations retain only labels, not transition identities. Two occurrences of `Check Revision` are therefore distinguished by their multiplicity and positions in the trace, but not by separate activity-instance identities. For example,

```text
<Analyze Revision, Check Revision, Check Revision>
```

contains two observable check occurrences even though both have the same label. Structurally, neither input tree contains duplicate visible leaves; repeated labels arise dynamically through loop execution.

## Bounded visible-language equivalence under P3

P3 counts all visible events, including `Open Case`, `Close Case`, approvals, checks, and rework events. Silent transitions do not count.

Define

[
L_{\mathrm{P3}}(T)
==================

\left{
\sigma\in L_{\mathrm{vis}}(T)
\ \middle|
|\sigma|\le 12
\land
#_A(\sigma)\le 3
\right}.
]

Then

[
T_1\equiv_{\mathrm{P3}}T_2
\iff
L_{\mathrm{P3}}(T_1)=L_{\mathrm{P3}}(T_2).
]

This is exhaustive equality only inside the stated bound. Equality would not prove unbounded equivalence. Conversely, finding one bounded difference is already a valid proof of unbounded non-equivalence.

## Business-relevant equivalence under P1

P1 observes complete cases and divides the part between `Open Case` and `Close Case` into attempt blocks using `Rework Case` as the separator:

[
O;b_1;R;b_2;R\cdots R;b_n;Z.
]

For every block (b_i), retain:

* (a_i): number of `Analyze Revision` occurrences;
* (c_i): number of `Check Revision` occurrences;
* (p_i): number of `Approve Revision` occurrences;
* (q_i): whether every approval in that block occurs after both its analysis and its check.

The P1 observation is

[
\operatorname{obs}_{P1}(\sigma)
===============================

\left(
\text{Open-first},
\text{Close-last},
\big((a_i,c_i,p_i,q_i)\big)_{i=1}^{n}
\right).
]

A block is P1-compliant when

[
a_i=1,\qquad c_i=1,\qquad p_i\in{0,1},\qquad q_i=\text{true}.
]

Thus each analysis attempt has its own check before the next `Rework Case` or `Close Case`, and any approval is attached to that attempt and happens after both mandatory activities.

The relative order of (A) and (C) **within a block is not distinguished by this P1 abstraction**, because P1 as written requires both before the boundary but does not explicitly say (A<C). If “check after analysis” is intended, that is an additional business rule.

Two models are P1-equivalent when their sets of these business observations are equal, including compliant and violating observations. This retains approval count and attempt placement but abstracts away the internal (A/C) order.

## Abstracted dashboard equivalence under P2

For a complete visible trace (\sigma), define

[
\operatorname{obs}_{P2}(\sigma)
===============================

\left(
\text{Open-first},
\text{Close-last},
#_A(\sigma),
\mathbf{1}[#_C(\sigma)>0],
\mathbf{1}[#_R(\sigma)>0]
\right).
]

This abstraction:

* erases all `Approve Revision` occurrences;
* erases silent behavior;
* turns any positive number of checks into one Boolean fact;
* retains the exact number of analyses;
* retains only whether rework occurred;
* ignores the exact interleaving of analyses and checks.

The abstracted dashboard languages are equal when

[
{\operatorname{obs}*{P2}(\sigma)\mid \sigma\in L*{\mathrm{vis}}(T_1)}
=====================================================================

{\operatorname{obs}*{P2}(\sigma)\mid \sigma\in L*{\mathrm{vis}}(T_2)}.
]

# 4. Counterexample Traces

The complete visible languages can be written compactly.

For Model A:

[
L_A=
\left{
O,u_1,(R,u_2)\cdots(R,u_n),Z
\ \middle|
n\ge1,;
u_i\in{AC,CA}{\epsilon,P}
\right}.
]

Thus every attempt contributes exactly one (A), exactly one (C), and optionally one trailing (P).

For Model B, first form

[
v_n=A,p_1,R,A,p_2\cdots R,A,p_n,
\qquad p_i\in{\epsilon,P}.
]

Then insert the single (C) at any position in (v_n), preserving the order of all events already in (v_n):

[
L_B=
{O,\operatorname{insert}(C,v_n),Z\mid n\ge1}.
]

| Trace ID | Trace                                                                                                                                          | Model A  | Model B  | First decisive semantic difference                                                                                                 | Relevant view          |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| A-only-1 | `<Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close Case>`                                     | admitted | rejected | The second `Check Revision` is required by A but impossible in B, which has only one check leaf.                                   | P1, P3, visible traces |
| A-only-2 | `<Open Case, Check Revision, Analyze Revision, Approve Revision, Rework Case, Analyze Revision, Check Revision, Approve Revision, Close Case>` | admitted | rejected | B cannot execute a second check in the second attempt.                                                                             | P1, P3, visible traces |
| B-only-1 | `<Open Case, Analyze Revision, Approve Revision, Check Revision, Close Case>`                                                                  | rejected | admitted | In A, the local parallel join requires the check before approval. In B, approval waits only for analysis.                          | P1, P3, visible traces |
| B-only-2 | `<Open Case, Analyze Revision, Rework Case, Check Revision, Analyze Revision, Close Case>`                                                     | rejected | admitted | A cannot execute the first `Rework Case` before completing the first attempt’s check. B’s global check may occur between attempts. | P1, P3, visible traces |
| B-only-3 | `<Open Case, Check Revision, Analyze Revision, Rework Case, Analyze Revision, Close Case>`                                                     | rejected | admitted | At closing, the second A attempt has no corresponding check.                                                                       | P1, P3, visible traces |

All five witnesses satisfy the P3 bound.

The `X('Approve Revision', tau)` choice means that each attempt may either emit a visible approval or emit nothing. Hiding `tau` therefore makes approval optional; it does **not** hide an executed `Approve Revision`.

This optionality affects the comparison in two ways:

1. In A, an observed approval is necessarily after both its analysis and its local check.
2. In B, an observed approval is necessarily after its analysis but may precede the global check, as in B-only-1.

The no-approval witnesses A-only-1, B-only-2, and B-only-3 show that non-equivalence does not depend on approval behavior.

# 5. Bounded Comparison Code

The following code performs exhaustive bounded exploration of the accepting Petri nets. It does not use random playout for the P3 verdict.

The code targets PM4Py 2.7.23.3. PM4Py’s public API converts a process tree to a Petri net together with initial and final markings. ([PyPI][1])

```python
from __future__ import annotations

from collections import deque
from typing import FrozenSet, Iterable, Tuple

import pm4py
from pm4py.objects.petri_net import semantics
from pm4py.objects.petri_net.obj import Marking, PetriNet


TREE_A_STRING = """
->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
"""

TREE_B_STRING = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)
"""

MAX_VISIBLE_EVENTS = 12
MAX_ANALYZE_OCCURRENCES = 3
ANALYZE_LABEL = "Analyze Revision"


def soundness_boolean(result: object) -> bool:
    """
    Current PM4Py check_soundness returns (bool, diagnostics).
    This helper also tolerates versions returning a plain bool.
    """
    if isinstance(result, tuple):
        return bool(result[0])
    return bool(result)


def marking_key(marking: Marking) -> FrozenSet[Tuple[PetriNet.Place, int]]:
    """
    Canonical hashable representation of a marking.
    Zero-token entries are intentionally excluded.
    """
    return frozenset(
        (place, int(tokens))
        for place, tokens in marking.items()
        if tokens
    )


def exhaustive_bounded_complete_language(
    net: PetriNet,
    initial_marking: Marking,
    final_marking: Marking,
    max_visible_events: int,
    max_analyze_occurrences: int,
) -> set[tuple[str, ...]]:
    """
    Exhaustively enumerates complete visible traces satisfying the P3 bound.

    State = (current marking, complete visible prefix).

    Including the visible prefix in the visited-state key is necessary:
    reaching the same marking through two different visible traces must
    preserve both traces.

    Silent cycles terminate because reaching the same marking with the
    same visible prefix is explored only once.
    """
    empty_trace: tuple[str, ...] = ()
    queue = deque([(initial_marking, empty_trace)])
    seen = {(marking_key(initial_marking), empty_trace)}
    accepted: set[tuple[str, ...]] = set()

    while queue:
        marking, visible_trace = queue.popleft()

        # Accept only exact equality with the declared final marking.
        if marking == final_marking:
            accepted.add(visible_trace)
            continue

        for transition in pm4py.get_enabled_transitions(net, marking):
            label = transition.label

            if label is None:
                next_trace = visible_trace
            else:
                next_trace = visible_trace + (label,)

                # Visible counts are monotone, so a state exceeding a bound
                # can never return to the bounded language.
                if len(next_trace) > max_visible_events:
                    continue
                if next_trace.count(ANALYZE_LABEL) > max_analyze_occurrences:
                    continue

            next_marking = semantics.execute(transition, net, marking)
            if next_marking is None:
                # Should not happen for a transition returned as enabled,
                # but keeps the exploration defensive.
                continue

            state_key = (marking_key(next_marking), next_trace)
            if state_key not in seen:
                seen.add(state_key)
                queue.append((next_marking, next_trace))

    return accepted


def format_trace(trace: Iterable[str]) -> str:
    return "<" + ", ".join(trace) + ">"


def print_trace_set(title: str, traces: set[tuple[str, ...]]) -> None:
    print(f"\n{title}: {len(traces)}")
    for trace in sorted(traces, key=lambda x: (len(x), x)):
        print("  " + format_trace(trace))


def main() -> None:
    tree_a = pm4py.parse_process_tree(TREE_A_STRING)
    tree_b = pm4py.parse_process_tree(TREE_B_STRING)

    net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
    net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

    for name, net, im, fm in [
        ("A", net_a, im_a, fm_a),
        ("B", net_b, im_b, fm_b),
    ]:
        result = pm4py.check_soundness(
            net,
            im,
            fm,
            print_diagnostics=True,
        )
        is_sound = soundness_boolean(result)
        print(f"Model {name} sound: {is_sound}")
        if not is_sound:
            raise RuntimeError(f"Model {name} did not convert to a sound net.")

    language_a = exhaustive_bounded_complete_language(
        net_a,
        im_a,
        fm_a,
        MAX_VISIBLE_EVENTS,
        MAX_ANALYZE_OCCURRENCES,
    )
    language_b = exhaustive_bounded_complete_language(
        net_b,
        im_b,
        fm_b,
        MAX_VISIBLE_EVENTS,
        MAX_ANALYZE_OCCURRENCES,
    )

    shared = language_a & language_b
    only_a = language_a - language_b
    only_b = language_b - language_a

    print("\nExploration mode: EXHAUSTIVE bounded BFS")
    print(f"|L_P3(A)|       = {len(language_a)}")
    print(f"|L_P3(B)|       = {len(language_b)}")
    print(f"|intersection|  = {len(shared)}")
    print(f"|A only|        = {len(only_a)}")
    print(f"|B only|        = {len(only_b)}")
    print(f"P3 equivalent   = {language_a == language_b}")

    # Expected for these exact trees and bounds.
    assert len(language_a) == 76
    assert len(language_b) == 85
    assert len(shared) == 4
    assert len(only_a) == 72
    assert len(only_b) == 81
    assert language_a != language_b

    print_trace_set("Traces admitted only by Model A", only_a)
    print_trace_set("Traces admitted only by Model B", only_b)


if __name__ == "__main__":
    main()
```

This exploration is exhaustive for the bounded accepting-net state space because it explores every enabled transition from every reachable pair of marking and visible prefix. It handles:

* silent transitions without incrementing visible length;
* silent cycles through repeated-state elimination;
* repeated markings reached through different visible prefixes;
* exact final-marking equality;
* both P3 bounds independently.

By contrast, `pm4py.play_out(...)` would generate a finite log of sampled traces. Failure to observe a trace in such a log would not establish that the model forbids it.

The count formulas independently confirm the BFS result.

For A, a trace with (n) attempts and (k) approvals has length

[
3n+1+k.
]

There are (2^n) choices for the (A/C) order and (\binom{n}{k}) approval choices. For (n=3), the all-three-approved traces have length 13 and are excluded:

[
4+16+8\left[\binom30+\binom31+\binom32\right]
=============================================

# 4+16+56

76.

]

For B, fixing (n) attempts and (k) approvals gives (2n+k) positions at which the single check can be inserted. All cases with (n\le3) satisfy the visible-length bound:

[
5+20+60=85.
]

# 6. Stochastic and Footprint Comparison

## Footprints

`pm4py.discover_footprints(...)` can provide inexpensive pairwise evidence about ordering and parallelism. PM4Py supports footprint discovery directly on process trees and also exposes footprint-based conformance operations. ([Process Intelligence Solutions][2])

```python
# Assumes tree_a and tree_b from Section 5.

footprints_a = pm4py.discover_footprints(tree_a)
footprints_b = pm4py.discover_footprints(tree_b)

for relation in ("sequence", "parallel"):
    only_a = footprints_a[relation] - footprints_b[relation]
    only_b = footprints_b[relation] - footprints_a[relation]

    print(f"\nRelation: {relation}")
    print("A only:", sorted(only_a))
    print("B only:", sorted(only_b))

for key in (
    "activities",
    "start_activities",
    "end_activities",
    "activities_always_happening",
):
    print(f"{key} equal:", footprints_a[key] == footprints_b[key])
```

For the current process-tree footprint implementation, the decisive difference is:

```text
A-only sequence:
    ('Check Revision', 'Approve Revision')

B-only parallel:
    ('Check Revision', 'Approve Revision')
    ('Approve Revision', 'Check Revision')
```

This correctly reflects that A requires the local check before approval, whereas B permits either order between the global check and an approval.

Footprints still do not establish trace equivalence because they are pairwise abstractions. They generally lose:

* occurrence counts;
* the fact that A creates a fresh check per loop iteration;
* the scope of concurrency;
* complete-trace context;
* which occurrence of a repeated label participates in a relation;
* higher-order dependencies among three or more activities.

Consequently, equal footprints would not prove language equality. Here the unequal footprints provide additional non-equivalence evidence, but the complete-trace witnesses are stronger.

## Stochastic language and EMD

A stochastic comparison requires a probability distribution, while the supplied process trees are nondeterministic models without declared business probabilities.

The following code uses PM4Py’s simulation-induced distribution. It is reproducible, but it is not a claim about real business likelihoods:

```python
import random
import pm4py

# Assumes tree_a and tree_b from Section 5.

simulation_parameters = {
    "num_traces": 20_000,
}

random.seed(20260805)
sampled_language_a = pm4py.get_stochastic_language(
    tree_a,
    parameters=simulation_parameters,
)

random.seed(20260805)
sampled_language_b = pm4py.get_stochastic_language(
    tree_b,
    parameters=simulation_parameters,
)

sampled_emd = pm4py.compute_emd(
    sampled_language_a,
    sampled_language_b,
)

print("Sample-induced EMD:", sampled_emd)
```

For process-tree playout, the current default top-down simulator randomly selects XOR branches, uses its built-in loop-continuation rule, and randomizes parallel linearizations. These are simulator choices, not supplied process probabilities.

A second experiment can use the exhaustive P3 languages but must explicitly declare an artificial distribution. The following assigns equal probability to every bounded variant:

```python
# Assumes language_a and language_b are the exhaustive sets from Section 5.

uniform_p3_a = {
    trace: 1.0 / len(language_a)
    for trace in language_a
}
uniform_p3_b = {
    trace: 1.0 / len(language_b)
    for trace in language_b
}

uniform_p3_emd = pm4py.compute_emd(
    uniform_p3_a,
    uniform_p3_b,
)

print("Uniform-over-P3-variants EMD:", uniform_p3_emd)
```

With PM4Py’s current normalized-Levenshtein ground distance, this artificial experiment gives approximately

[
\operatorname{EMD}=0.1821612465.
]

Yet the two languages share only 4 traces out of a union of 157 traces. This demonstrates why a fairly low EMD cannot be read as trace equivalence. PM4Py’s current EMD implementation transports probability mass using normalized edit distance between encoded traces.

A low EMD may coexist with major language differences because:

* many non-shared traces differ by only one check insertion or deletion;
* low-probability forbidden behavior contributes little transport cost;
* sampled languages may omit rare variants;
* the result depends on the chosen probability distribution;
* EMD compares weighted trace similarity, not equality of support;
* it does not preserve branching or concurrency semantics.

Thus footprints, stochastic language, and EMD are useful supplementary evidence, but none substitutes for the explicit bounded-language comparison or the formal counterexamples.

The following code calculates both the tree and converted-net metrics:

```python
from collections import Counter
from typing import Any

import pm4py


def process_tree_stats(root: Any) -> dict[str, Any]:
    labels: list[str] = []
    operator_nodes = 0
    visible_leaves = 0
    silent_leaves = 0
    max_depth = 0

    stack = [(root, 0)]
    while stack:
        node, depth = stack.pop()
        max_depth = max(max_depth, depth)

        if node.operator is None:
            if node.label is None:
                silent_leaves += 1
            else:
                visible_leaves += 1
                labels.append(node.label)
        else:
            operator_nodes += 1
            for child in node.children:
                stack.append((child, depth + 1))

    frequencies = Counter(labels)
    duplicate_label_count = sum(
        count - 1
        for count in frequencies.values()
        if count > 1
    )

    total_leaves = visible_leaves + silent_leaves

    return {
        "operator_nodes": operator_nodes,
        "visible_leaves": visible_leaves,
        "silent_leaves": silent_leaves,
        "total_leaves": total_leaves,
        "total_nodes": operator_nodes + total_leaves,
        "depth": max_depth,
        "distinct_visible_labels": len(frequencies),
        "duplicate_label_count": duplicate_label_count,
    }


def petri_net_stats(net, im, fm) -> dict[str, Any]:
    return {
        "places": len(net.places),
        "visible_transitions": sum(
            transition.label is not None
            for transition in net.transitions
        ),
        "silent_transitions": sum(
            transition.label is None
            for transition in net.transitions
        ),
        "total_transitions": len(net.transitions),
        "arcs": len(net.arcs),
        "arc_degree_simplicity": pm4py.simplicity_petri_net(
            net,
            im,
            fm,
            variant="arc_degree",
        ),
    }


for name, tree, net, im, fm in [
    ("A", tree_a, net_a, im_a, fm_a),
    ("B", tree_b, net_b, im_b, fm_b),
]:
    print(f"\nModel {name}")
    print("Tree:", process_tree_stats(tree))
    print("Petri net:", petri_net_stats(net, im, fm))
```

The raw node counts and the arc-degree score answer different questions. B has fewer converted nodes and arcs, but its remaining nodes have a higher mean degree, so the default PM4Py simplicity score ranks A higher.

# 8. Simplified Model

The appropriate target is **P1 operational compliance**, because an executable operational model should enforce per-revision checking. P2 should be implemented as a reporting projection rather than used as the behavioral specification.

I additionally choose a canonical operational order:

[
\text{Analyze Revision}
<
\text{Check Revision}
<
\text{optional Approve Revision}.
]

This is stricter than Model A’s internal concurrency but preserves Model A’s complete P1 observations as defined in Section 1.

The simplified process tree is:

```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

Self-contained PM4Py construction:

```python
import pm4py

SIMPLIFIED_TREE_STRING = """
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
"""

simplified_model = pm4py.parse_process_tree(
    SIMPLIFIED_TREE_STRING
)

simplified_net, simplified_im, simplified_fm = (
    pm4py.convert_to_petri_net(simplified_model)
)

soundness_result = pm4py.check_soundness(
    simplified_net,
    simplified_im,
    simplified_fm,
    print_diagnostics=True,
)

simplified_is_sound = (
    soundness_result[0]
    if isinstance(soundness_result, tuple)
    else bool(soundness_result)
)

assert simplified_is_sound
```

# 9. Final Recommendation

| Business view             | Model A                                                              | Model B                      | Recommendation                                                                                                                            |
| ------------------------- | -------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| P1 operational compliance | Suitable for per-attempt checking, but permits check-before-analysis | Unsuitable                   | Prefer A over B. Replace A with the simplified model when the intended order is specifically analyze, then check, then optional approval. |
| P2 executive dashboard    | Suitable after P2 projection                                         | Suitable after P2 projection | Treat them as equivalent only in the dashboard layer. Do not infer operational equivalence from identical dashboard records.              |
| P3 bounded testing        | Not equivalent to B                                                  | Not equivalent to A          | Use P3 as a regression test, not as a business equivalence definition. The bounded test already exposes both inclusion failures.          |

**Model A is the correct original model for P1’s per-revision compliance interpretation.** Its main weakness is that the parallel operator permits `Check Revision` before `Analyze Revision`. If that order is not meaningful operationally, the simplified sequential model is preferable.

**Model B is appropriate only for a different business rule:** exactly one case-level check that may run concurrently with all revision work. That rule is incompatible with P1 whenever more than one analysis attempt occurs. Model B should not be described as a simplification of A under operational semantics.

**Both originals, and the simplified model, are equivalent under P2’s dashboard projection.** That conclusion is intentionally weak: P2 hides check multiplicity, approval placement, and attempt-level check pairing.

The simplified model should replace Model A only after explicitly accepting the loss of (A/C) concurrency and check-first traces. It should not replace Model B when the intended requirement genuinely is one global case-level check.

Finally, bounded comparison has asymmetric evidential force:

* a bounded difference, as found here, is a proof of unbounded non-equivalence;
* bounded equality would only establish equality inside the tested horizon;
* no finite bound alone proves equality of two unbounded loop languages.
