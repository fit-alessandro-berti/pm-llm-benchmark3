## 1. Normalization Assumptions
- I treat each recorded timestamp as evidence about a true event-time interval, not as the true time itself.
- Clock-offset direction follows the prompt exactly: `clock_offset = recorded_clock - true_clock`. If offset is in `[a,b]`, then `true_time = recorded_time - offset`, so a recorded interval `[r_lo, r_hi]` maps to a true-time interval `[r_lo - b, r_hi - a]`.
- I apply display/rounding uncertainty before clock correction. I then convert the resulting interval(s) to UTC.
- Baseline enforcement semantics in Section 3 use the SLA text as written with no grace period: S1 `[0,900]` s, S2 `[0,2700]` s, S3 `[0,129600]` s. The `0` lower bound reflects the intended event order; if raw evidence admits negative durations, I keep that possibility unless there is explicit extra evidence that removes it.
- Baseline temporal-profile findings in Section 3 use `zeta = 1`. Section 4 gives `zeta = 2` and `zeta = 3` sensitivity.
- HUB: displayed second is exact only up to measurement uncertainty `+/-0.5 s`; with offset `[-1 s,+1 s]`, each HUB event becomes `[display - 1.5 s, display + 1.5 s]`.
- OPS-BER: floor-to-minute means displayed `10:14` corresponds to recorded clock time in `[10:14:00, 10:14:59.999]` local. With offset `[-90 s,+120 s]`, true UTC is `[recorded_lo - 120 s, recorded_hi + 90 s]` after local-to-UTC conversion. For T-409 I replace that with the weaker hour-specific bound `[-12 min,+12 min]`.
- SENSOR: “round to nearest 10 seconds” is treated conservatively as a recorded interval `[display - 5 s, display + 5 s]`; with offset `[-5 s,+5 s]`, true UTC is `[display - 10 s, display + 10 s]`.
- VENDOR-NY: floor-to-minute plus offset `[-180 s,+180 s]` is handled the same way as OPS-BER, then converted from EDT to UTC.
- LEGACY-BER: floor-to-minute plus offset `[-60 s,+60 s]`; for 2025-10-26 local times between 02:00 and 02:59 I preserve both DST folds unless other evidence removes one. For T-405, ingestion order is explicit evidence and eliminates all fold combinations except: `Alert_Received` in the first fold (CEST, UTC+2), `Investigation_Start` in the second fold (CET, UTC+1), and `Containment_Complete` in the second fold.
- MOBILE-LON: “round to nearest minute” is treated as `[display - 30 s, display + 30 s]` local. With offset `[-300 s,+300 s]`, the clock bound alone gives `[display - 5 m 30 s, display + 5 m 30 s]` in UTC.
- T-406 mobile entry delay: baseline assumption is substantive, not merely clerical. If the user entered the mobile timestamp up to five minutes late, the actual occurrence may be up to five minutes earlier than the displayed clock time. I therefore widen the lower bound by an additional 5 minutes. I do not shift the upper bound later. Section 4 also states the alternative “logging-only delay” interpretation because it materially changes T-406 S2/profile findings.
- T-404 inferred start: I infer `Investigation_Start = Investigation_Complete - duration`, with duration retained as `[18 min,25 min]`. No midpoint substitution is used.
- Duration intervals are derived by endpoint subtraction. For source interval(s) `A` and target interval(s) `B`, feasible duration interval(s) are all `[b_lo - a_hi, b_hi - a_lo]`, preserving unions if they remain disjoint.
- For T-407, `Alert_Sent` is not definitionally equal to `Alert_Received`. I therefore treat alert-related rules as indeterminate under strict evidential semantics, while also noting the conditional results if one assumes delivery occurred and uses the `[0,20]` minute network-latency bound.

Semantic sensitivities not captured by the requested grids:
- T-406 mobile-entry interpretation is material. If late entry is treated as a logging delay only, not uncertainty in occurrence time, `Investigation_Start` becomes `[2026-06-01T12:08:30Z, 2026-06-01T12:19:30Z]`. Then T-406 S2 becomes `CERTAIN_PASS` even at zero SLA tolerance, and the `Investigation_Start -> Containment_Complete` temporal-profile row becomes `CERTAIN_PASS` already at `zeta=1`. T-406 S1 remains `POSSIBLE_VIOLATION` at zero tolerance because the upper bound stays `1171.5 s`.
- T-407 alert-related rows are semantically, not numerically, sensitive. If one assumes an actual delivery occurred and imposes `Alert_Received <= Investigation_Start`, then T-407 S1 and the alert-to-start profile become `POSSIBLE_VIOLATION`, while the alert-to-containment profile becomes a conditional `CERTAIN_PASS`. Without that missing receipt evidence, they remain `INDETERMINATE`.

@dataclass(frozen=True)
class Interval:
    low: datetime
    high: datetime

    def midpoint(self) -> datetime:
        return self.low + (self.high - self.low) / 2


def to_utc(dt: datetime) -> datetime:
    return dt.astimezone(timezone.utc)


def parse_local(ts: str, tz_name: str, fold: int | None = None) -> datetime:
    fmt = "%Y-%m-%d %H:%M:%S" if len(ts) == 19 else "%Y-%m-%d %H:%M"
    naive = datetime.strptime(ts, fmt)
    if tz_name == "UTC":
        return naive.replace(tzinfo=timezone.utc)
    zone = ZoneInfo(tz_name)
    if fold is None:
        return naive.replace(tzinfo=zone)
    return datetime(
        naive.year, naive.month, naive.day, naive.hour, naive.minute, naive.second, naive.microsecond,
        tzinfo=zone, fold=fold
    )


def recorded_clock_intervals(row: pd.Series) -> list[Interval]:
    system = SYSTEMS[row["system"]]
    kind = system["kind"]
    tz_name = row["tz"]
    ts = row["recorded_value"]

    # LEGACY-BER ambiguous hour: keep both folds as alternatives
    folds = [0, 1] if row["system"] == "LEGACY-BER" and ts.startswith("2025-10-26 02:") else [None]
    out: list[Interval] = []

    for fold in folds:
        dt = parse_local(ts, tz_name, fold=fold)
        if kind == "exact_second":
            out.append(Interval(dt - timedelta(seconds=0.5), dt + timedelta(seconds=0.5)))
        elif kind == "floor_minute":
            out.append(Interval(dt.replace(second=0, microsecond=0), dt.replace(second=59, microsecond=999000)))
        elif kind == "round_10_seconds":
            out.append(Interval(dt - timedelta(seconds=5), dt + timedelta(seconds=5)))
        elif kind == "round_minute":
            out.append(Interval(dt - timedelta(seconds=30), dt + timedelta(seconds=30)))
        else:
            raise ValueError(f"Unsupported kind: {kind}")
    return out


def apply_clock_offset(interval: Interval, offset_low_s: float, offset_high_s: float) -> Interval:
    # true = recorded - offset, with offset in [low, high]
    low_utc = to_utc(interval.low) - timedelta(seconds=offset_high_s)
    high_utc = to_utc(interval.high) - timedelta(seconds=offset_low_s)
    return Interval(low_utc, high_utc)


def normalize_row(row: pd.Series, mobile_entry_delay_affects_occurrence: bool = True) -> list[Interval]:
    system = SYSTEMS[row["system"]]
    intervals = [
        apply_clock_offset(iv, system["offset_low_s"], system["offset_high_s"])
        for iv in recorded_clock_intervals(row)
    ]
    if row["system"] == "MOBILE-LON" and mobile_entry_delay_affects_occurrence:
        intervals = [Interval(iv.low - timedelta(minutes=5), iv.high) for iv in intervals]
    return intervals


def merge_intervals(intervals: list[Interval]) -> list[Interval]:
    if not intervals:
        return []
    ordered = sorted(intervals, key=lambda iv: (iv.low, iv.high))
    merged = [ordered[0]]
    for iv in ordered[1:]:
        last = merged[-1]
        if iv.low <= last.high:
            merged[-1] = Interval(last.low, max(last.high, iv.high))
        else:
            merged.append(iv)
    return merged


def duration_union(src_intervals: list[Interval], dst_intervals: list[Interval]) -> list[tuple[float, float]]:
    raw = []
    for src, dst in product(src_intervals, dst_intervals):
        low_s = (dst.low - src.high).total_seconds()
        high_s = (dst.high - src.low).total_seconds()
        raw.append((low_s, high_s))
    raw.sort()
    merged: list[list[float]] = []
    for low_s, high_s in raw:
        if not merged or low_s > merged[-1][1]:
            merged.append([low_s, high_s])
        else:
            merged[-1][1] = max(merged[-1][1], high_s)
    return [tuple(x) for x in merged]


def classify_union(intervals: list[tuple[float, float]], accept_low: float, accept_high: float) -> str:
    if not intervals:
        return "INDETERMINATE"
    all_inside = all(lo >= accept_low and hi <= accept_high for lo, hi in intervals)
    any_overlap = any(not (hi < accept_low or lo > accept_high) for lo, hi in intervals)
    any_outside = any(lo < accept_low or hi > accept_high for lo, hi in intervals)
    if all_inside:
        return "CERTAIN_PASS"
    if not any_overlap:
        return "CERTAIN_VIOLATION"
    if any_overlap and any_outside:
        return "POSSIBLE_VIOLATION"
    return "INDETERMINATE"


def profile_band(mu: float, sigma: float, zeta: float) -> tuple[float, float]:
    return mu - zeta * sigma, mu + zeta * sigma

def safe_pm4py_temporal_profile(log_df: pd.DataFrame, zeta: float) -> tuple[object, pd.DataFrame | None]:

    with columns like: case, source_activity, target_activity, throughput, num_st_devs.
    If a different shape is returned, preserve the raw object instead of assuming schema.

    raw = pm4py.conformance_temporal_profile(
        log_df,
        temporal_profile=TEMPORAL_PROFILE,
        zeta=zeta,
        activity_key="concept:name",
        timestamp_key="time:timestamp",
        case_id_key="case:concept:name",
        return_diagnostics_dataframe=True,
    )
    if isinstance(raw, pd.DataFrame):
        expected = {"case", "source_activity", "target_activity", "throughput", "num_st_devs"}
        if expected.issubset(raw.columns):
            return raw, raw.copy()
        return raw, None
    return raw, None

## 7. Governance Recommendation

- Store canonical timestamps in UTC, but also retain the raw local timestamp string, source time zone, and the original display semantics such as exact-second, floor-to-minute, or nearest-minute rounding.
- Preserve source clock-offset telemetry as first-class provenance. The useful artifact is not just “NTP healthy” but the actual bound used for each event or at least for the relevant hour.
- Record timestamp resolution metadata per field. A minute-floored human-entered value should never be indistinguishable from an exact machine timestamp.
- Distinguish lifecycle semantics explicitly: `start`, `complete`, `sent`, `received`, `acknowledged`, `entered_by_user`, and `record_created_at` should not share one overloaded timestamp field.
- Add an explicit DST-fold indicator, or store the UTC offset observed at capture time, so ambiguous local times like `2025-10-26 02:xx` in Europe/Berlin are reconstructible without forensic inference.
- Retain both observed events and inferred events, but mark inferred events with provenance, derivation rule, and uncertainty source. Do not overwrite missing starts with synthetic point estimates.
- Add causal identifiers and correlation edges for transmission steps such as `Alert_Sent` and `Alert_Received`, so delivery and receipt are evidentially linked rather than semantically guessed.
- For mobile or user-entered timestamps, capture both the user-entered occurrence time and the system-recorded submission time. This separates “late entry” from “late event.”
- For enforcement, adopt a policy distinction: use `CERTAIN_VIOLATION` for automatic legal/disciplinary breach findings; route `POSSIBLE_VIOLATION` and `INDETERMINATE` to manual review; do not let midpoint-only approximations trigger penalties.
- Keep interval-aware audit trails. Store the normalized UTC interval (or interval union), the assumptions used to derive it, and the exact evidence inputs, so later reviewers can rerun conformance under different tolerance or semantic policies without destroying provenance.
