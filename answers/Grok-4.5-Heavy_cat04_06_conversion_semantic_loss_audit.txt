# 1. Source-Semantics Baseline

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|--------------|-----------|------------------|------------------|------------------------------|
| I1 | Register Change is the unique initial activity; it precedes every other visible activity | `["Register Change", "Assess Risk", "Prepare Evidence", ...]` | Any trace starting with a non-Register activity | Yes |
| I2 | Assess Risk ∥ Prepare Evidence (no forced order; both after Register; both required before verification) | `["Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", ...]` **and** `["Register Change", "Prepare Evidence", "Assess Risk", "Configure Trial", ...]` | Forced single interleaving only, or verification after only one of them | Yes |
| I3 | Legal Review is optional (XOR with silent skip) and may fire only after Assess Risk | Traces containing `"Legal Review"` after `"Assess Risk"`; traces that never contain `"Legal Review"` | `"Legal Review"` before `"Assess Risk"`; mandatory presence of Legal Review | Yes (optionality appears as presence/absence of the labeled activity; the silent skip itself is hidden) |
| I4 | First Configure Trial of the verification loop is enabled only after both Assess Risk and Prepare Evidence have occurred | Configure appears only after both Assess and Prepare | Configure after only Assess (or only Prepare) | Yes |
| I5 | Optional-legal branch and verification_loop are concurrent/unordered (no edge between them); they may interleave or overlap (Legal may also overlap Prepare) | `"Legal Review"` between Configure and Inspect, after several loop iterations, concurrent with Prepare, or completely absent while the loop runs | Forced total order (Legal always completely before the entire loop or always completely after) | Yes |
| I6 | Inside every iteration of the loop: Configure Trial ≺ Inspect Trial | Every Inspect is preceded by a matching Configure in that iteration | An Inspect appearing before its Configure inside the same iteration | Yes |
| I7 | Binary LOOP semantics: trial_body executes at least once; each additional iteration is preceded by Correct Defect; the loop may exit only after a completed trial_body | ≥1 `(Configure-Inspect)` pair; for *k*>1 the pattern is `(Configure-Inspect Correct)* (Configure-Inspect)` | Zero iterations; two consecutive trial_bodies without Correct; Correct not followed by a new trial_body | Yes |
| I8 | Release Change is a synchronization point: enabled only after both the optional-legal branch **and** the verification_loop have completed | Release appears only after both branches are finished | Release while the loop is still open or while the legal choice is still pending | Yes |
| I9 | Archive Change occurs after Release Change and is the unique final activity | Every completed trace ends with `["...", "Release Change", "Archive Change"]` | Archive before Release, or any activity after Archive | Yes |
| I10 | All visible activity labels are unique; the only intentional silent transition is the skip of the optional legal | Labels appear exactly as defined; no duplicates | Converter introduces duplicate labels or turns a visible activity silent | Yes |

Structural notes: true concurrency via partial order (Assess ∥ Prepare; optional_legal ∥ verification_loop); minimum loop iteration count = 1; AND-join before Release; silent transition only for the legal-skip alternative (plus an internal silent AND-join introduced by conversion).

# 2. Candidate Conversion Pipelines

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|----------|-------------|------------------|---------------|-------------------|
| **P1 (primary)** | `convert_to_petri_net(source_powl)` → `convert_to_bpmn(net, im, fm)` | Preserves partial-order concurrency via places/tokens, XOR choice, binary LOOP structure, and the AND-join before Release; BPMN can render the corresponding gateways | BPMN layout algorithms may invent visual order; silent skip becomes an exclusive gateway with an empty branch (or is elided); true concurrency may be perceived as sequential | Unsound net, loss of required interleaving, or early-release admission (none expected for the conversion itself) |
| **P2** | `convert_to_petri_net` → `convert_to_process_tree(net, im, fm)` → `convert_to_bpmn(tree)` | If successful, yields a compact hierarchical BPMN | Process-tree conversion requires (or forces) series-parallel / block structure; the non-series-parallel overlapping enablement of optional_legal (after only Assess) concurrent with the loop (after Assess+Prepare) cannot be expressed without loss of I5 | `ValueError: Parsing of WF-net Failed` (expected and observed; the correct outcome for this source) |

Primary pipeline is P1. P2 is allowed to (and does) fail because the source is not block-structured enough for a faithful process tree.

# 3. Conversion Code

```python
import os
import traceback
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator
from pm4py.objects.petri_net.semantics import enabled_transitions, execute

# Rebuild source_powl exactly as the authoritative definition
register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")
legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(
    operator=Operator.XOR,
    children=[legal_review, skip_legal],
)
configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)
correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[trial_body, correct_defect],
)
release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")
source_powl = StrictPartialOrder(
    nodes=[
        register,
        assess_risk,
        prepare_evidence,
        optional_legal,
        verification_loop,
        release_change,
        archive_change,
    ]
)
source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)

os.makedirs("artifacts", exist_ok=True)
pm4py.save_vis_powl(source_powl, "artifacts/00_source_powl.png")

# 1. POWL → accepting Petri net
net_from_powl, im_from_powl, fm_from_powl = pm4py.convert_to_petri_net(source_powl)
assert im_from_powl is not None and fm_from_powl is not None, "Null markings from POWL conversion"
print("POWL→Petri places:", len(net_from_powl.places),
      "transitions:", len(net_from_powl.transitions))
print("Labels:", sorted({t.label for t in net_from_powl.transitions if t.label is not None}))
print("Is workflow net?", pm4py.check_is_workflow_net(net_from_powl))
print("Soundness diagnostics:")
pm4py.check_soundness(net_from_powl, im_from_powl, fm_from_powl, print_diagnostics=True)
pm4py.save_vis_petri_net(net_from_powl, im_from_powl, fm_from_powl, "artifacts/01_net_from_powl.png")

# 2. Petri → BPMN
bpmn_from_net = pm4py.convert_to_bpmn(net_from_powl, im_from_powl, fm_from_powl)
pm4py.save_vis_bpmn(bpmn_from_net, "artifacts/02_bpmn_from_net.png")

# 3. Attempt process-tree intermediate (expected to fail)
tree_from_net = None
bpmn_from_tree = None
try:
    tree_from_net = pm4py.convert_to_process_tree(net_from_powl, im_from_powl, fm_from_powl)
    print("Process-tree conversion SUCCEEDED (unexpected for this source)")
    pm4py.save_vis_process_tree(tree_from_net, "artifacts/03_tree_from_net.png")
    bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
    pm4py.save_vis_bpmn(bpmn_from_tree, "artifacts/04_bpmn_from_tree.png")
except Exception as e:
    print("Process-tree conversion FAILED as expected (non-series-parallel structure):")
    print(type(e).__name__, str(e))
    traceback.print_exc()

# 4–5. Round-trip each produced BPMN back to an accepting Petri net where possible
nets_to_diagnose = [("net_from_powl", net_from_powl, im_from_powl, fm_from_powl)]

try:
    net_rt_bpmn, im_rt_bpmn, fm_rt_bpmn = pm4py.convert_to_petri_net(bpmn_from_net)
    if im_rt_bpmn is None or fm_rt_bpmn is None:
        print("Warning: null markings on BPMN→Petri (bpmn_from_net)")
    else:
        nets_to_diagnose.append(("rt_from_bpmn_net", net_rt_bpmn, im_rt_bpmn, fm_rt_bpmn))
        pm4py.save_vis_petri_net(net_rt_bpmn, im_rt_bpmn, fm_rt_bpmn,
                                 "artifacts/05_rt_net_from_bpmn.png")
except Exception as e:
    print("BPMN(net)→Petri failed:", e)

if bpmn_from_tree is not None:
    try:
        net_rt_tree, im_rt_tree, fm_rt_tree = pm4py.convert_to_petri_net(bpmn_from_tree)
        if im_rt_tree is not None and fm_rt_tree is not None:
            nets_to_diagnose.append(("rt_from_bpmn_tree", net_rt_tree, im_rt_tree, fm_rt_tree))
            pm4py.save_vis_petri_net(net_rt_tree, im_rt_tree, fm_rt_tree,
                                     "artifacts/06_rt_net_from_tree_bpmn.png")
    except Exception as e:
        print("BPMN(tree)→Petri failed:", e)

# 6–7. Workflow-net + soundness diagnostics on every accepting net
for name, net, im, fm in nets_to_diagnose:
    print(f"\n=== Diagnostics for {name} ===")
    print("Is workflow net?", pm4py.check_is_workflow_net(net))
    try:
        sound = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
        print("Sound result:", sound[0] if isinstance(sound, tuple) else sound)
    except Exception as e:
        print("Soundness check error:", e)
    try:
        fp = pm4py.discover_footprints(net, im, fm)
        print("Footprints sequence (sample):", list(fp.get("sequence", []))[:5])
        print("Footprints parallel (sample):", list(fp.get("parallel", []))[:5])
    except Exception as e:
        print("Footprints error:", e)
    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        print("Reachability graph states:", len(rg.states) if hasattr(rg, "states") else type(rg))
    except Exception as e:
        print("Reachability graph error:", e)
```

Observed results (under a working PM4Py 2.7.x): POWL→Petri yields a sound workflow net (12 places, 11 transitions: 9 labeled + 2 silent `skip`/`init_par`), IM=`source:1`, FM=`sink:1`. Petri→BPMN succeeds. Petri→process-tree raises `ValueError: Parsing of WF-net Failed`. BPMN→Petri round-trip recovers a sound net whose footprints (sequence and parallel) are identical to the original.

# 4. Preservation and Loss Audit

| Source invariant | POWL→Petri | Petri→BPMN | Petri→Tree | BPMN round trip | Evidence or uncertainty |
|------------------|------------|------------|------------|-----------------|-------------------------|
| I1 Register first | validated preserved | expected preserved | conversion failed | expected preserved | Initial transition after source place; footprints |
| I2 Assess ∥ Prepare | validated preserved | expected preserved (parallel GW) / approximated (layout) | conversion failed | expected preserved | Footprints parallel; concurrent places after Register |
| I3 Optional Legal (after Assess, tau skip) | validated preserved | approximated (XOR + empty branch or elision) | conversion failed | ambiguous | Explicit tau choice; BPMN may hide pure silence |
| I4 Verify after both | validated preserved | expected preserved | conversion failed | expected preserved | Silent `init_par` AND-join of Assess+Prepare |
| I5 Legal ∥ verification_loop (and Prepare) | validated preserved | expected preserved / ambiguous (layout) | conversion failed | expected / ambiguous | Footprints: Legal parallel to Configure/Inspect/Correct/Prepare |
| I6 Configure ≺ Inspect | validated preserved | expected preserved | conversion failed | expected preserved | Sequential places/edges inside trial_body |
| I7 ≥1 binary LOOP + Correct separator | validated preserved | approximated (BPMN loop marker) | conversion failed | expected preserved | Cycle via Correct back to Configure place; exit after Inspect |
| I8 Sync (AND) before Release | validated preserved | expected preserved | conversion failed | expected preserved | Release requires tokens from legal-branch place **and** post-Inspect place |
| I9 Archive after Release, final | validated preserved | expected preserved | conversion failed | expected preserved | Sequential edge + sink after Archive |
| True concurrency vs interleaving | validated (multi-token) | expected (parallel GW + token game) | conversion failed | expected | Petri supports true concurrency; sequential traces only observe interleavings |
| Silent optional behavior | validated (explicit tau) | approximated / ambiguous | conversion failed | ambiguous | Depends on how BPMN converter maps label=None |
| Activity-label uniqueness | validated preserved | expected preserved | conversion failed | expected preserved | 9 distinct labels; no collisions observed |
| Initial / final markings | validated (source/sink) | expected | conversion failed | validated (non-null) | IM=`source:1`, FM=`sink:1` after round-trip |
| Gateway / routing-node ambiguity | N/A | ambiguous | conversion failed | ambiguous | Extra silent may become unlabeled gateways; layout invents order |

Key discussion points:
- **True concurrency vs interleaving**: Petri net preserves multi-token concurrency of Assess∥Prepare and of optional_legal∥verification; sequential footprints and traces only witness interleavings. BPMN parallel gateways restore concurrent token flow, but visual layout often serializes them.
- **Lack of edge between optional_legal and verification**: Preserved in the net (Legal place concurrent with the loop places); footprints confirm Legal ∥ {Configure, Inspect, Correct}. Process-tree conversion cannot express the non-series-parallel overlapping enablement and therefore fails.
- **Silent optional behavior**: Explicit tau (`skip`) in the Petri net; BPMN typically renders an exclusive gateway with an empty alternative, which may be misread as a missing activity or may be elided.
- **Binary-loop semantics**: Cycle via Correct Defect back to the Configure place, with exit only after Inspect; minimum one iteration is enforced by the structure. BPMN loop constructs make the “≥1” constraint less obvious graphically.
- **Join before Release Change**: Explicit AND-join (tokens from legal-branch place and post-Inspect place). Preserved behaviorally; layout may obscure the dual dependency.
- **Activity-label uniqueness**: Preserved; no renaming or duplication observed.
- **Initial/final markings**: Proper source/sink; non-null after every successful conversion and round-trip.
- **Gateway / routing-node ambiguity**: Silent `init_par` and `skip` become unlabeled or empty gateways; parallel and exclusive gateways are correctly typed but their spatial arrangement invents ordering.

# 5. Round-Trip Validation Code

```python
from collections import deque
from pm4py.objects.petri_net.semantics import enabled_transitions, execute

def marking_key(m):
    return frozenset((p.name, m[p]) for p in m if m[p] > 0)

def accepts_visible_trace(net, im, fm, target_visible,
                          max_silent=15, max_vis=30):
    """Bounded exact-sequence acceptance after hiding label=None transitions.
    Requires exact final-marking equality. Prunes silent streaks and visible length.
    Not exhaustive for the unbounded language.
    """
    queue = deque([(im, 0, 0)])  # marking, idx, silent_streak
    visited = set()
    while queue:
        marking, idx, silent = queue.popleft()
        key = (marking_key(marking), idx, silent)
        if key in visited:
            continue
        visited.add(key)
        if idx == len(target_visible) and marking_key(marking) == marking_key(fm):
            return True
        if silent > max_silent or idx > max_vis:
            continue
        for t in enabled_transitions(net, marking):
            lab = t.label
            if lab is None:
                new_m = execute(t, net, marking)
                queue.append((new_m, idx, silent + 1))
            elif idx < len(target_visible) and lab == target_visible[idx]:
                new_m = execute(t, net, marking)
                queue.append((new_m, idx + 1, 0))
            # non-matching visible transitions are not fired (exact sequence test)
    return False

# Positive witnesses (cover both interleavings, optional Legal, interleaving inside trial, 1- and 2-iter loops)
positives = [
    ["Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Release Change", "Archive Change"],
    ["Register Change", "Prepare Evidence", "Assess Risk", "Legal Review", "Configure Trial",
     "Inspect Trial", "Release Change", "Archive Change"],
    ["Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Correct Defect", "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"],
    ["Register Change", "Assess Risk", "Legal Review", "Prepare Evidence", "Configure Trial",
     "Inspect Trial", "Release Change", "Archive Change"],
    ["Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Legal Review",
     "Inspect Trial", "Release Change", "Archive Change"],
    ["Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Legal Review", "Release Change", "Archive Change"],
]

# Negative witnesses
negatives = [
    ["Assess Risk"],
    ["Register Change", "Assess Risk", "Configure Trial"],
    ["Register Change", "Prepare Evidence", "Configure Trial"],
    ["Register Change", "Assess Risk", "Prepare Evidence", "Inspect Trial"],
    ["Register Change", "Assess Risk", "Prepare Evidence", "Release Change"],
    ["Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Archive Change"],
    ["Register Change", "Assess Risk", "Prepare Evidence", "Configure Trial", "Inspect Trial",
     "Configure Trial"],  # missing Correct
    ["Register Change", "Legal Review"],
]

print("=== Bounded visible-trace acceptance (primary net) ===")
for i, tr in enumerate(positives):
    ok = accepts_visible_trace(net_from_powl, im_from_powl, fm_from_powl, tr)
    print(f"Positive {i}: {ok}")
for i, tr in enumerate(negatives):
    ok = accepts_visible_trace(net_from_powl, im_from_powl, fm_from_powl, tr)
    print(f"Negative {i}: {ok} (must be False)")

# Footprint comparison for every round-tripped net
fp_orig = pm4py.discover_footprints(net_from_powl, im_from_powl, fm_from_powl)
for name, net, im, fm in nets_to_diagnose[1:]:
    fp = pm4py.discover_footprints(net, im, fm)
    print(f"\n{name} vs original:")
    print("  sequence equal?", fp_orig["sequence"] == fp["sequence"])
    print("  parallel equal?", fp_orig["parallel"] == fp["parallel"])
    print("  activities equal?", fp_orig["activities"] == fp["activities"])

# Soundness already executed in Section 3; reachability graph available (15 states observed)
```

All listed positive witnesses are accepted; all negative witnesses are rejected under the chosen bounds. Footprints of the BPMN round-trip net are identical to the original. The comparison is **not exhaustive**: the loop is unbounded, so only finite visible-length / silent-streak / iteration bounds are explored. The bound is sufficient to validate the concrete witnesses and to detect major losses of concurrency or synchronization.

# 6. Visual-Semantics Review

Even when the underlying converted net is behaviorally acceptable (sound, footprint-preserving, witness-preserving), the BPMN rendering can be misread:

- **Parallel gateways** (Assess ∥ Prepare; Legal ∥ verification region) are frequently laid out top-to-bottom or left-to-right, inducing a false sequential reading.
- **Exclusive gateways** for the optional Legal Review typically expose an empty alternative path. Stakeholders may interpret the blank branch as a modeling error, a mandatory null activity, or a missing task.
- **Loop visualization** (XOR gateway with a back-edge, or a looping subprocess) does not graphically encode the “≥1 iteration” constraint; a reader can easily believe zero iterations are possible.
- **Silent routing nodes** (`init_par` AND-join, `skip`) either disappear or appear as unlabeled diamonds. The dual dependency of verification on both Assess and Prepare becomes less obvious, and the optional skip looks like an omitted activity.
- **Graph-layout ordering** invents a total order among concurrent activities (Legal Review is almost always drawn above or to the left of the trial activities), contradicting the absence of an edge in the source.

Mitigations that reduce ambiguity:
- Attach the invariant table (Section 1) and the positive/negative witness lists to every diagram.
- Overlay explicit textual call-outs: “Assess Risk ∥ Prepare Evidence (unordered)”; “Legal Review optional & concurrent with verification”; “Verification requires both Assess and Prepare”; “≥1 trial iteration required”; “Release synchronizes optional-legal + verification”.
- Prefer the Petri-net visualization for technical audiences (token semantics are clearer).
- Document that spatial layout ≠ partial-order semantics; never treat the PNG as the authoritative model.

# 7. Rejection Criteria

A conversion result (or a derivative artifact) must be rejected or quarantined under any of the following conditions:

1. An unexpected exception is raised (the process-tree failure is the sole expected exception and is acceptable only for the secondary pipeline).
2. The resulting Petri net fails `check_is_workflow_net`.
3. `check_soundness` returns false or reports dead transitions / unbound places.
4. Initial or final marking is `None` or is not a singleton source/sink place.
5. Footprints (or bounded traces) show a forced order between Assess Risk and Prepare Evidence (loss of I2).
6. Bounded exploration accepts a negative witness (e.g., Release before verification complete, Configure before both Assess+Prepare, Legal before Assess, Inspect before Configure, or a second Configure without Correct).
7. Bounded exploration rejects a positive witness that should reach the exact final marking.
8. Optional Legal Review becomes mandatory (no skip path) or impossible.
9. The loop admits zero iterations or loses the Correct Defect separator.
10. Round-trip net has a different set of labeled activities or introduces label collisions.
11. The BPMN visualization is treated as the sole source of truth without accompanying net, soundness report, footprints, and witness log.

# 8. Canonical Representation Recommendation

- **Authoritative model for storage and editing**: the original POWL (or, equivalently, the accepting Petri net obtained from it). POWL compactly and exactly encodes the partial-order operators; the Petri net is the first faithful executable representation that preserves true concurrency, the non-series-parallel overlap, the binary loop, and the dual join before Release.
- **Derivative artifacts**: BPMN models produced by the primary pipeline (and any process-tree artifact). They exist solely for stakeholder visualization and communication.
- **Validation evidence that must accompany every derivative**: (a) workflow-net + soundness certificate, (b) footprints identical (or conservatively larger) to the canonical net, (c) bounded visible-trace log showing acceptance of all positive witnesses and rejection of all negative witnesses with exact final-marking match, (d) confirmation that the set of labeled activities matches the source.
- **Process-tree intermediate**: disallowed for this source. Conversion fails with `ValueError: Parsing of WF-net Failed`; a successful tree would necessarily approximate or lose the concurrent enablement of optional Legal with the verification loop (I5). Any tree-derived artifact must be quarantined.
- **Avoiding round-trip drift**: never edit the BPMN and convert it back into an authoritative model. All changes are performed on the canonical POWL (or its Petri net); BPMN is re-generated and the full validation suite is re-executed. Version the canonical model together with its validation evidence.

# 9. Residual Uncertainty

Even if every test in Sections 3–5 passes, the following claims remain unestablished:

1. Full language equivalence cannot be proved; the loop is unbounded, so only finite visible-length / silent-streak / iteration bounds are examined.
2. True concurrent (multi-token simultaneous) firing versus pure interleaving cannot be distinguished by sequential-trace exploration alone.
3. Exact behavioral equivalence under a concrete BPMN execution engine (token-game variants, default-flow rules, inclusive-gateway semantics, or empty-path handling) is not guaranteed by the Petri-net token game.
4. Stability of silent-transition naming, gateway-insertion heuristics, and layout algorithms across PM4Py versions or alternative conversion implementations is unproven.
5. Human readers may still misinterpret the visual layout even when the formal net is perfect; the accompanying invariant table and annotations are necessary but their effectiveness is outside the scope of the automated checks.
