The observed collapse is best explained as a layered measurement problem plus a genuine policy/model change, rather than a single sudden workforce failure. First, UI release 4.2 changed the emitted label from `Classify` to `Risk Screen`; mapping it back eliminates a substantial portion of Jun-Jul deviation. Second, the gateway inserted `Queue Routed`, a likely technical routing event absent from the control-flow model. Its removal produces another large improvement. Third, the ETL changed timestamp semantics for `Decision` and `Notify`; ordering by retained source sequence removes much of the apparent `Notify -> Decision` reversal.

Those mechanisms affect what the conformance engine sees, not necessarily what employees did. In August, however, the process itself changed: high-value claims required supervisor sign-off. The old model therefore became obsolete. A candidate model improves fitness, but an unconditional optional sign-off branch may overfit because policy requires sign-off conditionally by value.

A residual concern remains: enhanced-review cases lacking recorded compliance checks persist after normalization. They could represent true bypasses, missing compliance-system events, or cross-system extraction gaps. Stable approval, appeal, cycle-time, and reported-incident rates reduce evidence for a broad harmful operational collapse, but do not prove data error. Outcomes can be insensitive, delayed, selectively detected, or offset by compensating controls. Likewise, unchanged outcomes do not rule out noncompliance in a small but high-risk subgroup.

def variants_to_event_log(variant_freqs, prefix):
    """
    Expand variant frequencies to a PM4Py EventLog using parse_event_log_string.

    parse_event_log_string is used for the requested conversion. We then assign
    explicit case IDs to make subsequent copies/filtering transparent.
    """
    trace_strings = []
    case_counter = 0

    for variant, frequency in variant_freqs.items():
        activities = [x.strip() for x in variant.split(",")]
        for _ in range(frequency):
            case_counter += 1
            # PM4Py parser accepts newline-separated traces; use commas as separators.
            trace_strings.append(",".join(activities))

    log = pm4py.parse_event_log_string("\n".join(trace_strings))

    for i, trace in enumerate(log, start=1):
        trace.attributes[CASE_ID] = f"{prefix}_{i:04d}"

    return log


apr_may_log = variants_to_event_log(apr_may_variants, "aprmay")
jun_jul_log = variants_to_event_log(jun_jul_variants, "junjul")
aug_sep_log = variants_to_event_log(aug_sep_variants, "augsep")

# 3. Transparent normalization: label mapping and optional removal
# ---------------------------------------------------------------------
def normalize_log(log, map_risk_screen=True, remove_queue_routed=False):
    """
    Copies a log, maps 'Risk Screen' -> 'Classify', and optionally removes
    'Queue Routed'. It does not infer timestamps or source ordering because
    supplied aggregate variants do not contain those fields.
    """
    normalized = EventLog()

    for old_trace in log:
        new_trace = Trace()
        new_trace.attributes = copy.deepcopy(old_trace.attributes)

        for old_event in old_trace:
            event = Event(copy.deepcopy(dict(old_event)))

            if map_risk_screen and event.get(ACTIVITY) == "Risk Screen":
                event[ACTIVITY] = "Classify"

            if remove_queue_routed and event.get(ACTIVITY) == "Queue Routed":
                continue

            new_trace.append(event)

        normalized.append(new_trace)

    return normalized


def print_top_variants(log, title, max_rows=10):
    variants = pm4py.get_variants_as_tuples(log)
    ranked = sorted(variants.items(), key=lambda x: x[1], reverse=True)

    print(f"\n--- {title}: top variants ---")
    for variant, count in ranked[:max_rows]:
        print(f"{count:4d}  {variant}")


def print_dfg(log, title):
    dfg, start_acts, end_acts = pm4py.discover_dfg(log)
    print(f"\n--- {title}: DFG ---")
    print("DFG:")
    pprint(dict(sorted(dfg.items(), key=lambda kv: (-kv[1], kv[0]))))
    print("Start activities:", dict(start_acts))
    print("End activities:", dict(end_acts))
    return dfg


def alignment_summary(log, net, im, fm, title):
    """
    Alignment diagnostics and alignment-based fitness against an accepting
    Petri net. PM4Py versions may return diagnostics with slightly different
    field names, so summary extraction is defensive.
    """
    print(f"\n--- {title}: alignment diagnostics ---")
    diagnostics = pm4py.conformance_diagnostics_alignments(log, net, im, fm)

    costs = []
    fit_flags = 0

    for d in diagnostics:
        cost = d.get("cost", 0)
        costs.append(cost)

        # Most PM4Py versions expose one of these:
        if d.get("fitness", 0) == 1 or d.get("trace_is_fit", False):
            fit_flags += 1

    print("Number of traces:", len(diagnostics))
    print("Mean raw alignment cost:", round(sum(costs) / len(costs), 4) if costs else None)
    print("Perfect-fit diagnostic share:", round(fit_flags / len(diagnostics), 4) if diagnostics else None)

    # Print representative deviations. The exact representation of "alignment"
    # may differ slightly by PM4Py release.
    print("Sample diagnostics:")
    for d in diagnostics[:3]:
        print({
            "cost": d.get("cost"),
            "fitness": d.get("fitness"),
            "trace_is_fit": d.get("trace_is_fit"),
            "alignment": d.get("alignment"),
        })

    print(f"\n--- {title}: alignment fitness ---")
    fitness = pm4py.fitness_alignments(log, net, im, fm)
    pprint(fitness)

    return diagnostics, fitness


def precision_summary(log, net, im, fm, title):
    """
    Precision is meaningful only alongside fitness and review of model scope.
    An overly permissive model can improve fitness while reducing precision.
    """
    print(f"\n--- {title}: precision ---")
    try:
        precision = pm4py.precision_alignments(log, net, im, fm)
        print("Alignment precision:", precision)
        return precision
    except Exception as exc:
        print("Precision computation failed in this PM4Py installation:", repr(exc))
        return None

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a compound observability and model-governance failure, not evidence by itself of a sudden broad deterioration in employee behavior. Confidence in that conclusion is high, approximately 85-90%. The strongest evidence is the staged recovery of Jun-Jul conformance: mapping `Risk Screen` to `Classify` removes a major semantic mismatch; removing `Queue Routed` eliminates a newly introduced technical event; and restoring source-sequence ordering addresses the artificial `Notify`-before-`Decision` pattern created after the ETL timestamp change. Those changes explain most of the apparent fall from the 93% pre-change baseline.

August-September additionally contains a real process and policy change. `Supervisor Sign-off` was introduced for high-value cases, while the normative tree remained unchanged. This is genuine model obsolescence, not merely bad logging. The candidate sign-off model’s improvement confirms that the existing model is incomplete, but it must not be accepted as the final policy model because optional sign-off for every claim would overgeneralize the actual EUR 50,000 requirement.

A separate compliance concern remains. Confidence that there is some unresolved control risk is moderate, around 60%. Enhanced-review cases without a recorded compliance check persist after the principal normalization steps. The current evidence cannot distinguish true reviewer bypasses from missing compliance-platform events, alternate event coding, or extraction defects. The supervisor memo and reviewer references to manual overrides justify investigation, but neither proves misconduct.

Immediate IT actions are to restore source-event ordering, document timestamp provenance, assign producer/type metadata, reconcile compliance-system events, and implement governed label mappings. Process owners should version the model at the August policy effective date and create an attribute-aware sign-off control outside—or alongside—the control-flow tree. Compliance should prioritize case-level audits of enhanced-review/no-check cases and high-value cases missing sign-off, then assess reviewer clustering only after data reconciliation.

It must not yet be claimed that employees caused the overall conformance collapse, that all missing compliance checks are bypasses, or that stable appeal and incident rates prove the process is compliant.

## 8. Model-governance recommendation

1. **Version normative models with effective dates and policy ownership.** Every policy, UI, workflow, or control change must trigger a documented assessment of whether the conformance model, its labels, and its acceptance criteria require a new version.

2. **Maintain an event-semantic contract.** For each activity, define business meaning, producer system, event type, lifecycle point, permitted labels, release version, and approved crosswalks such as `Risk Screen -> Classify`.

3. **Classify technical events explicitly.** Gateway, queue, retry, routing, and telemetry events must be marked as technical, business-visible, or hybrid; conformance preprocessing rules must be approved rather than inferred ad hoc.

4. **Preserve timestamp provenance and authoritative ordering.** Store source occurrence time, source sequence number, ingestion time, timezone, and ordering confidence separately; never silently substitute warehouse ingestion time for business-event order.

5. **Model data-aware controls separately from unconstrained control flow.** Controls such as “sign-off required above EUR 50,000” require case attributes, eligibility logic, and auditable rule evaluation; an optional process-tree branch is not sufficient proof of compliance.

6. **Require post-release validation before interpreting deviation trends.** After any UI, gateway, ETL, or policy release, compare variants, DFGs, alignment moves, fitness, precision, missingness, and audited cases against a pre-release baseline before escalating employee-performance conclusions.
