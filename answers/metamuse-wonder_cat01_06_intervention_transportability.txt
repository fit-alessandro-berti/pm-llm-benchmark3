Shared mechanisms are narrow: when both checks are legally startable, independent, and staffed, replacing sequential waiting with parallel execution can reduce waiting_before_assessment without changing assessment logic. Independence of external data, additive service content, and join-before-assessment plausibly hold in both sites for some cases.

Site-specific mechanisms dominate elsewhere. At A, digital documents, cross-trained reviewers, simultaneous ownership, six-task WIP limit, and no legal review allowed true_overlap to rise. At B, originals_required blocks Document Check for 62%, strict role specialization separates capacities, IT_case_lock serializes ownership or drives back-entry, and Legal Review creates a supplement loop returning to Document Check and Assessment. API_latency and queue_huddles at A are co-interventions, not part of parallelization.

Effect modifiers therefore include originals_required and digital_documents, case_complexity, role_specialization, IT_case_lock, and the four capacities, plus legal-review probability. They change either eligibility, true overlap, queueing delay, or downstream congestion.

A similar control-flow diagram does not guarantee transportability because diagrams encode allowable ordering, not startability conditions, data dependencies, resource pools, queue disciplines, durations, loop probabilities, or measurement. Selection nodes shift distributions and mechanisms; the same `+` node can be realized as genuine concurrency, blocked tasks, premature task creation, or timestamp artefacts. Transport requires invariant causal mechanisms and overlap in modifiers, not syntactic similarity.

## 6. Candidate Site B intervention

**Eligibility rules**
- Segment 1 (pilot): no originals legally required, documents digital/available at Register, not public-sector/high-value legal-review, low/moderate complexity.
- Segment 2 (later, only if Segment 1 succeeds): originals-required but non-legal — Identity Check and Originals Receipt/tracking in parallel; Document Check released immediately upon Originals Receipt.
- Segment 3 (deferred): legal-review and/or high-complexity cases until legal capacity, loop handling and tail effects are understood.

**Concurrency**
- Segment 1: create and execute Identity Check and Document Check concurrently after Register.
- Segment 2: Identity Check  Originals Receipt; Document Check after originals, then join.
- Assessment may be *prepared* but not started/decided until both checks complete.

**Statutory prerequisites that remain mandatory**
- Register first; Document Check not started before Originals Receipt where originals legally required; Assessment requires both checks; Legal Review where required; Approve/Reject then Notify.

**Queue and WIP controls**
- Per-reviewer WIP cap (adapt A's six-task rule, tuned by pool), per-pool queue thresholds, no unbounded simultaneous task creation.
- Blocked Document tasks are not counted as active WIP and are auto-released on Originals Receipt.
- Daily huddles, if used, must be applied equally across pilot arms or tested as a separate factor.

**Resource responsibilities**
- Identity pool (4), document pool (7), assessors (3), legal (2) retain specialization; named join-owner monitors both-check completion; no borrowing across pools without logging as a protocol deviation.

**Legal-review and supplement loops**
- Legal Review after Assessment for required cases; Request Supplement returns case to Document Check (and re-Assessment if needed) with reason codes; loop count capped/escalated after second supplement; legal queue protected by reserving pilot-arrival slots.

**Logging requirements**
- System-generated start/end timestamps per task, task creator/owner, blocked reason, originals receipt time, back-entry flag, WIP/queue snapshots, loop iteration, and arm assignment. Manual back-entry prohibited or explicitly flagged.

Textual POWL-style partial order:

```text
StrictPartialOrder {
  nodes: Register, IdentityCheck, OriginalsReceipt, DocumentCheck,
         Assessment, LegalOptional, DecisionXOR, Notify
  edges:
    Register -> IdentityCheck
    Register -> OriginalsReceipt        // tracking/receipt; legally required subset only
    OriginalsReceipt -> DocumentCheck   // mandatory only when originals_required
    IdentityCheck -> Assessment
    DocumentCheck -> Assessment         // Assessment waits for BOTH checks
    Assessment -> LegalOptional
    LegalOptional -> DecisionXOR
    DecisionXOR -> Notify
  LegalOptional = XOR( LOOP(LegalReview, RequestSupplement), SilentSkip )
                    // loop simplification: supplement in reality re-enters
                    // DocumentCheck/Assessment; see code comments
  DecisionXOR = XOR(Approve, Reject)
  Segment1 restriction: OriginalsReceipt branch is skipped/not required,
  allowing IdentityCheck  DocumentCheck after Register.
}
```

The pilot separates mechanism failure from implementation failure by measuring the mediator chain, not only cycle time. Implementation failure is diagnosed when assigned parallel cases show low audited true overlap, high blocked time, case-lock serialization, or back-entry: the intervention was not delivered, so a null cycle effect does not refute the mechanism. Mechanism failure is diagnosed when true overlap rises and waiting before Assessment falls as predicted, yet end-to-end cycle time, p90, or rework do not improve—typically because assessment or legal capacity becomes the binding constraint. Conversely, if overlap rises but waiting does not fall, the shared causal mechanism itself does not hold at B, for example because queues rather than ordering dominate. Holding huddles, staffing, and API conditions constant, and stratifying by originals/legal status, prevents re-labelling co-intervention or mix effects as transport success.

## 8. PM4Py model-construction code

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# ---------------- Site A: process trees ----------------
# NOTE: parse_process_tree string syntax may need spacing adjusted to your PM4Py version.
site_a_before_str = "->( 'Register', 'Identity Check', 'Document Check', 'Assessment', X( 'Approve', 'Reject' ), 'Notify' )"
site_a_after_str  = "->( 'Register', +( 'Identity Check', 'Document Check' ), 'Assessment', X( 'Approve', 'Reject' ), 'Notify' )"

pt_before = pm4py.parse_process_tree(site_a_before_str)
pt_after = pm4py.parse_process_tree(site_a_after_str)

net_before, im_before, fm_before = pm4py.convert_to_petri_net(pt_before)
net_after, im_after, fm_after = pm4py.convert_to_petri_net(pt_after)

print("A before workflow net:", pm4py.check_is_workflow_net(net_before))
print("A after workflow net:", pm4py.check_is_workflow_net(net_after))
# check_soundness expects (net, initial_marking, final_marking) in recent PM4Py versions.
try:
    print("A after soundness:", pm4py.check_soundness(net_after, im_after, fm_after))
except Exception as e:
    print("Soundness check unavailable/failed:", e)

# ---------------- Site B candidate: POWL ----------------
# What this model CANNOT encode:
# - Data-dependent rules: originals_required (62%), legal required for public-sector/
#   high-value cases (40%), complexity-based eligibility. POWL here shows the
#   maximal legal partial order; eligibility must be enforced by the case system.
# - Resource capacities (4/7/3/2 pools), role specialization, queueing/WIP caps,
#   case locks / single-owner IT constraints, durations and originals-delay
#   distributions, probabilities, and supplement-loop re-entry into Document Check
#   + Assessment with state-dependent repetition. The LOOP below is a simplification:
#   a supplement in reality repeats Document Check and possibly Assessment, which a
#   clean hierarchical POWL cannot express without duplicating those nodes.
# - Timestamp quality/back-entry and true vs measured overlap.

register   = Transition(label="Register")
identity   = Transition(label="Identity Check")
originals  = Transition(label="Originals Receipt")
document   = Transition(label="Document Check")
assessment = Transition(label="Assessment")
legal      = Transition(label="Legal Review")
supplement = Transition(label="Request Supplement")
approve    = Transition(label="Approve")
reject     = Transition(label="Reject")
notify     = Transition(label="Notify")
skip_legal = SilentTransition()

# Legal review with supplement loop: LOOP(first=Legal, then optionally Supplement and repeat Legal)
legal_loop = OperatorPOWL(operator=Operator.LOOP, children=[legal, supplement])
# Optional legal branch: either the legal loop or skip (data rule decides in reality)
legal_optional = OperatorPOWL(operator=Operator.XOR, children=[legal_loop, skip_legal])
# Final decision
decision = OperatorPOWL(operator=Operator.XOR, children=[approve, reject])

site_b = StrictPartialOrder(
    nodes=[register, identity, originals, document, assessment,
           legal_optional, decision, notify]
)

# Statutory / join dependencies. For no-originals cases OriginalsReceipt is a
# non-required branch in execution terms; the order edge only constrains cases
# where that node is actually executed/enabled by the surrounding system.
site_b.add_order(register, identity)
site_b.add_order(register, originals)
site_b.add_order(originals, document)   # mandatory prerequisite when originals required
site_b.add_order(identity, assessment)  # Assessment waits for Identity ...
site_b.add_order(document, assessment)  # ... AND for Document Check (explicit join)
site_b.add_order(assessment, legal_optional)
site_b.add_order(legal_optional, decision)
site_b.add_order(decision, notify)
# Deliberately NO identity -> document edge: for digital cases they are parallel;
# for originals cases document waits on originals, not on identity.

net_b, im_b, fm_b = pm4py.convert_to_petri_net(site_b)
print("B workflow net:", pm4py.check_is_workflow_net(net_b))
try:
    print("B soundness:", pm4py.check_soundness(net_b, im_b, fm_b))
except Exception as e:
    print("B soundness check unavailable/failed:", e)

# Optional playout (API signature varies by version)
try:
    log_b = pm4py.play_out(net_b, im_b, fm_b)
    for trace in list(log_b)[:5]:
        print([event["concept:name"] for event in trace])
except Exception as e:
    print("Playout unavailable/failed:", e)
```

## 9. Recommendation

`conditional go`

What should be transferred is the mechanism, not Site A's surface intervention: start both verifications as early as they are legally and materially startable, preserve the join before Assessment, cap WIP, and measure true overlap as a mediator. What should not be copied is simultaneous creation of Identity and Document tasks for every case immediately after Register. That is legally impossible for the 62% requiring originals, operationally dubious under single-owner case locking, and risky for the 40% entering legal review with a supplement loop. Nor should the nine-hour median gain be used as the business case: it is a confounded before/after composite reflecting simpler case mix, two added reviewers, an API upgrade, huddles, and possibly timestamp changes, with no control group. Site B resembles Site A before, not after, on complexity, and has heavier tails and lower baseline quality.

The first subgroup should be digital, no-originals, non-legal, low-to-moderate-complexity claims, and only after dual task ownership is genuinely enabled and back-entry is controlled. In that segment a plausible benefit is a 3–6 hour median reduction, with little expected quality harm if assessment capacity absorbs arrivals. The main risks are bottleneck shift to three assessors, legal congestion in later expansion, blocked-WIP clutter, and spurious fidelity from timestamps. Expansion should be triggered by audited true overlap rising, waiting before Assessment falling, and end-to-end median improving without p90, rework, supplement, or queue deterioration in adjacent strata. Modification is triggered if verification waiting falls but cycle time does not, indicating a downstream constraint. Abandonment is triggered by p90 worsening, rework rising materially, legal-queue breaches, or fidelity remaining low despite IT fixes—evidence that either the mechanism or its implementation does not transport.

## 10. Assumption register

1. Both checks are independent and additive for digital cases — why needed: parallel gain assumes no shared data dependency — how to test: dependency mapping and audited pilot overlap/service times — consequence if false: parallel work creates waiting or duplicated effort, gain vanishes.
2. Document Check genuinely cannot start before Originals Receipt where required — why needed: defines the 62% ineligible segment — how to test: legal review of statute plus conformance checking — consequence if false: eligible share is larger and segmentation should be redrawn.
3. IT dual ownership can be enabled with reliable timestamps — why needed: treatment requires true, measurable concurrency — how to test: pre-pilot IT test cases and timestamp audit — consequence if false: pilot tests task creation only; stop and fix IT first.
4. Identity (4) and document (7) pools have enough slack at pilot volumes — why needed: queueing delay could offset ordering gains — how to test: utilization/queue monitoring by arm and pool — consequence if false: bottleneck-shift scenario; add WIP caps or capacity before proceeding.
5. Assessment (3) can absorb faster verification arrivals — why needed: end-to-end cycle, not verification waiting, is the outcome — how to test: assessment queue and waiting as secondary outcomes — consequence if false: median gain stalls and tail worsens; stagger release.
