1. a recurring work package,
2. the complexity and risk of the cases touched,
3. decision or approval authority, and
4. whether participation is routine, delegated, temporary, or cross-functional.

The activity counts are event counts, not unique cases. Likewise, the case-complexity totals can overlap because one case may involve several resources.

# 5. PM4Py role-discovery and similarity code

The following is illustrative and assumes:

- the case identifier is `case:concept:name`;
- `resource_metadata.csv` contains one row per resource, including `org:resource`, `formal_title`, `home_team`, `certifications`, `contract`, and optionally `case_complexity_score`;
- PM4Py releases differ slightly in the exact keys returned by organizational-role discovery, so the role-member extraction should be checked against `print(roles[0])`.

```python
import pandas as pd
import networkx as nx
import pm4py
from sklearn.metrics.pairwise import cosine_similarity

# ------------------------------------------------------------------
# 1. Load and format the event log
# ------------------------------------------------------------------
CASE_ID = "case:concept:name"
ACTIVITY = "concept:name"
TIME = "time:timestamp"
RESOURCE = "org:resource"
COMPLEXITY = "case_complexity"
TEMP = "temporary_substitution"

events = pd.read_csv("events.csv")
events[TIME] = pd.to_datetime(events[TIME], utc=True)

# The field may be boolean or a string flag. Adjust this parser if it
# contains a different convention, such as "substitute:<resource>".
def marked_as_true(series):
    if pd.api.types.is_bool_dtype(series):
        return series.fillna(False)
    return series.astype(str).str.strip().str.lower().isin(
        {"true", "1", "yes", "y", "temporary", "substitution"}
    )

if TEMP not in events.columns:
    events[TEMP] = False

events["_temporary_event"] = marked_as_true(events[TEMP])

# Use the actual numeric score if supplied. Otherwise use a clearly
# labelled ordinal proxy; it is not the same scale as the reported
# median scores in the question.
if "case_complexity_score" in events.columns:
    events["_complexity_score"] = pd.to_numeric(
        events["case_complexity_score"], errors="coerce"
    )
else:
    complexity_map = {
        "low": 1.0,
        "medium": 2.0,
        "high": 3.0,
        "critical": 4.0,
    }
    events["_complexity_score"] = (
        events[COMPLEXITY]
        .astype(str)
        .str.strip()
        .str.lower()
        .map(complexity_map)
    )

log = pm4py.format_dataframe(
    events,
    case_id=CASE_ID,
    activity=ACTIVITY,
    timestamp=TIME,
    resource=RESOURCE,
)

# ------------------------------------------------------------------
# 2. Discover candidate organizational roles
# ------------------------------------------------------------------
# 0.65 is an illustrative cutoff, not evidence of a formal boundary.
# Run sensitivity checks at several cutoffs before accepting a role.
roles = pm4py.discover_organizational_roles(
    log,
    activity=ACTIVITY,
    resource=RESOURCE,
    similarity_threshold=0.65,
    frequency_threshold=0,
)

print("Raw PM4Py role output:")
print(pd.json_normalize(roles).head())

known_resources = set(events[RESOURCE].dropna().astype(str))

def scalar_resource(value):
    # Accommodate tuple/list-shaped collaborator values used in some
    # PM4Py versions.
    if isinstance(value, (tuple, list)):
        value = value[0]
    return None if value is None else str(value)

role_rows = []
for i, role in enumerate(roles, start=1):
    reported_label = role.get("role") or role.get("resource")
    role_id = (
        reported_label
        if str(reported_label).upper().startswith("ROLE")
        else f"ROLE_{i:03d}"
    )

    origin = scalar_resource(role.get("originating_resource"))
    collaborators = role.get("collaborators") or []

    members = []
    for candidate in [origin] + list(collaborators):
        member = scalar_resource(candidate)
        if member in known_resources and member not in members:
            members.append(member)

    for member in members:
        role_rows.append(
            {
                "role_id": role_id,
                "member": member,
                "pm4py_role_label": reported_label,
                "pm4py_originating_resource": origin,
            }
        )

assignments = pd.DataFrame(
    role_rows,
    columns=[
        "role_id",
        "member",
        "pm4py_role_label",
        "pm4py_originating_resource",
    ],
)

# Resources omitted by PM4Py should remain visibly unassigned rather
# than being forced into a nearby activity cluster.
profile = pd.DataFrame({"member": sorted(known_resources)}).merge(
    assignments[["role_id", "member"]],
    on="member",
    how="left",
)

# ------------------------------------------------------------------
# 3. Join roles to complexity and temporary-substitution indicators
# ------------------------------------------------------------------
# A resource-case-complexity row reflects a case touched by the resource;
# it is not an exclusive assignment of the whole case.
case_resource = (
    events[
        [CASE_ID, RESOURCE, COMPLEXITY, "_complexity_score"]
    ]
    .drop_duplicates()
)

complexity_counts = pd.crosstab(
    case_resource[RESOURCE],
    case_resource[COMPLEXITY],
).reset_index()

resource_complexity = (
    case_resource.groupby(RESOURCE)
    .agg(
        cases_touched=(CASE_ID, "nunique"),
        median_complexity_score=("_complexity_score", "median"),
    )
    .reset_index()
    .rename(columns={RESOURCE: "member"})
)

resource_events = (
    events.groupby(RESOURCE)
    .agg(
        event_count=(ACTIVITY, "size"),
        temporary_marked_events=("_temporary_event", "sum"),
        temporary_marked_share=("_temporary_event", "mean"),
    )
    .reset_index()
    .rename(columns={RESOURCE: "member"})
)

profile = (
    profile
    .merge(resource_complexity, on="member", how="left")
    .merge(resource_events, on="member", how="left")
    .merge(complexity_counts, on="member", how="left")
)

# Formal metadata is needed to distinguish authority from activity.
resource_metadata = pd.read_csv("resource_metadata.csv")
resource_metadata[RESOURCE] = resource_metadata[RESOURCE].astype(str)

profile = profile.merge(
    resource_metadata.rename(columns={RESOURCE: "member"}),
    on="member",
    how="left",
    validate="one_to_one",
)

# Count A9 performance, but do NOT infer final approval authority from it.
a9_mask = (
    events[ACTIVITY]
    .astype(str)
    .str.contains("Supervisor Approval", case=False, na=False)
    | events[ACTIVITY]
    .astype(str)
    .str.match(r"^\s*A9(?:[.\s:-]|$)", na=False)
)

a9_counts = (
    events.loc[a9_mask]
    .groupby(RESOURCE)
    .size()
    .rename("a9_events_performed")
    .reset_index()
    .rename(columns={RESOURCE: "member"})
)

profile = profile.merge(a9_counts, on="member", how="left")
profile["a9_events_performed"] = profile["a9_events_performed"].fillna(0)

# Final approval authority comes from an explicit certification/RACI,
# not from having executed A9.
approval_authority = set()
if "certifications" in resource_metadata.columns:
    approval_mask = (
        resource_metadata["certifications"]
        .fillna("")
        .astype(str)
        .str.contains("approval", case=False, regex=False)
    )
    approval_authority = set(
        resource_metadata.loc[approval_mask, RESOURCE].astype(str)
    )

profile["certified_approval_authority"] = profile["member"].isin(
    approval_authority
)

if "contract" in profile.columns:
    profile["temporary_contract"] = (
        profile["contract"].astype(str).str.lower() == "temporary"
    )

# ------------------------------------------------------------------
# 4. Activity-based resource similarity
# ------------------------------------------------------------------
similarity_records = pm4py.discover_activity_based_resource_similarity(
    log,
    activity=ACTIVITY,
    resource=RESOURCE,
)

def parse_similarity_item(item):
    if isinstance(item, dict):
        target = item.get("resource") or item.get("target")
        score = item.get(
            "similarity",
            item.get("score", item.get("distance")),
        )
        return target, score
    if isinstance(item, (tuple, list)) and len(item) >= 2:
        return item[0], item[1]
    return item, None

similarity_rows = []
for record in similarity_records:
    source = record.get("resource")
    for item in record.get("similar_resources", []):
        target, score = parse_similarity_item(item)
        similarity_rows.append(
            {
                "resource": source,
                "compared_resource": target,
                # The PM4Py metric/version may report similarity or distance.
                "reported_similarity_or_distance": score,
            }
        )

similarity_long = pd.DataFrame(similarity_rows)

# Optional transparent cosine calculation for comparison with the
# activity-profile similarities supplied in the question.
activity_counts = pd.crosstab(events[RESOURCE], events[ACTIVITY])
row_totals = activity_counts.sum(axis=1).replace(0, pd.NA)
normalized_profiles = (
    activity_counts.div(row_totals, axis=0).fillna(0)
)

cosine_values = cosine_similarity(normalized_profiles.to_numpy())
cosine_matrix = pd.DataFrame(
    cosine_values,
    index=normalized_profiles.index,
    columns=normalized_profiles.index,
)

cosine_long = (
    cosine_matrix.stack()
    .rename("cosine_similarity")
    .rename_axis([RESOURCE, "compared_resource"])
    .reset_index()
)

# ------------------------------------------------------------------
# 5. Handover, working-together, and subcontracting networks
# ------------------------------------------------------------------
handover_graph = pm4py.discover_handover_of_work_network(log)
working_together_graph = pm4py.discover_working_together_network(log)
subcontracting_graph = pm4py.discover_subcontracting_network(log)

def graph_to_edge_frame(graph, relation):
    rows = []
    for source, target, attributes in graph.edges(data=True):
        rows.append(
            {
                "relation": relation,
                "source": source,
                "target": target,
                "weight": attributes.get("weight", 1),
                "attributes": str(attributes),
            }
        )
    return pd.DataFrame(rows)

handover_edges = graph_to_edge_frame(
    handover_graph, "handover_of_work"
)
working_together_edges = graph_to_edge_frame(
    working_together_graph, "working_together"
)
subcontracting_edges = graph_to_edge_frame(
    subcontracting_graph, "subcontracting"
)

# ------------------------------------------------------------------
# 6. Isolate temporary-substitution events and compare networks
# ------------------------------------------------------------------
temporary_values = (
    events.loc[events["_temporary_event"], TEMP]
    .dropna()
    .unique()
    .tolist()
)

if temporary_values:
    substitution_log = pm4py.filter_event_attribute_values(
        log,
        TEMP,
        temporary_values,
    )
else:
    substitution_log = log

temporary_handover_graph = (
    pm4py.discover_handover_of_work_network(substitution_log)
)
temporary_handover_edges = graph_to_edge_frame(
    temporary_handover_graph,
    "handover_during_substitution",
)

# Weekly profiles help distinguish a stable role from behavior caused
# only by an absence or incident surge.
events["_week"] = events[TIME].dt.isocalendar().week.astype("Int64")

role_week_profile = (
    assignments[["role_id", "member"]]
    .merge(
        events[[RESOURCE, "_week", "_temporary_event"]],
        left_on="member",
        right_on=RESOURCE,
        how="left",
    )
    .groupby(
        ["role_id", "member", "_week"],
        dropna=False,
    )
    .agg(
        events=("_temporary_event", "size"),
        temporary_marked_events=("_temporary_event", "sum"),
    )
    .reset_index()
)

# ------------------------------------------------------------------
# 7. Export results for business review
# ------------------------------------------------------------------
profile.to_csv("resource_role_complexity_profile.csv", index=False)
similarity_long.to_csv("activity_resource_similarity.csv", index=False)
cosine_long.to_csv("cosine_similarity.csv", index=False)
handover_edges.to_csv("handover_edges.csv", index=False)
working_together_edges.to_csv("working_together_edges.csv", index=False)
subcontracting_edges.to_csv("subcontracting_edges.csv", index=False)
temporary_handover_edges.to_csv(
    "temporary_substitution_handover_edges.csv",
    index=False,
)
role_week_profile.to_csv("role_week_profile.csv", index=False)
```

The interpretation safeguards in this workflow are important:

- `discover_organizational_roles` is used to produce **candidate work packages**, not formal authority.
- The similarity result may be reported as distance or similarity depending on PM4Py version; it must be labeled accordingly.
- A handover edge shows a sequential dependency, while a working-together edge shows collaboration. Neither means subordination.
- Rare resources left unassigned should not be forced into a cluster; that is itself evidence of a specialist boundary.
- The event-level `temporary_substitution` field must be verified. If it identifies the substitute rather than merely marking a substituted event, the parsing and network comparison must be adjusted.
- A9 performance must remain separate from final approval authority, as shown by the explicit certification/RACI field.
- Absence-period behavior should be compared with the same actor’s pre- and post-absence behavior before inferring competence.

# 6. Operational interpretation

**Staffing**

- Build capacity plans around **case complexity and work package**, not raw event totals. Front-office capacity should be sized primarily for standard-response and closure work, while technical capacity should reflect diagnosis, configuration, and implementation effort.
- Protect scarce critical capacity for Erik, Hana, and Mateo rather than allowing routine assignments to consume it. Their lower event totals do not indicate low workload.
- Use Kai and Lina for low-complexity surge work with restricted exception permissions. Their shifts can cover demand, but a permanent-agent should remain accountable for validation-note completeness and sampled closures.
- Model Ivan and Julia jointly as a quality pool with day/late-shift continuity, while measuring whether same-case implementation and checking undermine independence.
- Use Mateo as a controlled routing capacity, with service-level targets and critical-case escalation rules rather than treating him as an unlimited queue.

**Training**

- Maintain a deliberate commercial-shadow rotation between Fatima and Giorgio, accompanied by documented thresholds, calibration reviews, and periodic assessment. A temporary absence is not a substitute for certification.
- Train front-office agents in entitlement-note completeness and give temporary agents a shorter, checklist-based validation protocol.
- Train Mateo in triage rules, escalation thresholds, and documentation. If he is authorized to make preliminary approvals, define exactly what he may decide and when Hana’s confirmation is mandatory.
- Conduct cross-training for Erik’s security role, but do not imply that a coordinator or front-office agent can provide equivalent security assurance.
- Rotate technical and quality staff carefully so that implementation expertise is not confused with independent quality approval.

**Risk control**

- Maintain a formal approval matrix. R08_Hana should remain the default final A9 authority unless an explicit delegation policy identifies others. A9 activity by Giorgio, Fatima, or Mateo should be classified as final, preliminary, or administrative in the event schema.
- Require specialist security review for critical or policy-triggered cases. Mateo’s low-risk filtering should be rule-audited because false-escalation reductions can conceal harmful delay.

- Track first-time-right quality rather than closure volume. The 17 reopened temp-agent cases show why a closure count can conceal a service failure.
- Formalize shadow decisions with the same audit trail as permanent-role decisions where risk, pricing, or approval thresholds are involved.

**Resilience**

- Create tested absence plans for each scarce function: security review, commercial exceptions, final approval, quality checking, and escalation coordination.
- Use Giorgio as a time-bounded commercial backup, not as the standing replacement for Fatima. His longer pricing-review duration during coverage should inform recovery capacity and escalation thresholds.

- Pair day and late-shift personnel where possible and require structured handoffs so that case knowledge follows the work.
- Simulate an Enterprise Security surge and a simultaneous supervisor absence; the observed two-day critical delay shows that these compound scenarios should be part of continuity testing.

**Management dashboard**

Track role-relevant outcomes such as:

- reopen rate and validation-note completeness;
- pricing-exception duration and quality by normal versus substitute handling;
- critical-case wait time;
- false escalation rate;
- supervisor-approval recheck rate;
- first-time-right quality;
- security-review bypass rate;

- KB reuse following a resolved incident.

**Cautions**

1. **Mined roles are observational, not authoritative.** A role label describes who did what in the sample; it does not establish legal accountability, certification, or decision rights.
2. **Frequency is not workload or importance.** Erik, Hana, and Mateo may appear less prominent than front-office agents while carrying much higher case risk and bottleneck potential.
3. **Temporary behavior is not permanent competence.** Giorgio’s absence cover and the temporary agents’ activity should not be converted into formal qualifications without assessment.
4. **Shadow roles can be beneficial but need governance.** Informal coverage can preserve service, while uncontrolled shadowing can reduce consistency, dilute accountability, or create self-review.
5. **Absence and incident periods are confounded.** The pricing-duration increase coincided with Fatima’s absence, and the security delay coincided with incident filtering; association alone does not establish causality. Replicated periods, case-mix controls, and outcome data are needed before changing policy.
