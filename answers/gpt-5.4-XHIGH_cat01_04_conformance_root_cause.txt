## 3. Causal-abductive explanation
```text

```

The observed collapse is best explained by several mechanisms acting on different layers. First, the 2026-05-31 UI rename changed recorded labels from `Classify` to `Risk Screen` without strong evidence that the business action itself changed. Second, the 2026-06-03 gateway inserted `Queue Routed`, inflating path length and creating new variants. Third, the 2026-06-15 ETL change degraded event ordering for `Decision` and `Notify`. Those three mechanisms act on `recorded_labels` and `recorded_order`, which directly increase alignment moves and depress measured fitness even if the underlying business process is mostly stable. The staged recovery from 32% to 89% after remapping, technical-event removal, and source ordering is exactly the pattern expected from this layered data-provenance explanation.

A different mechanism appears from 2026-08-01 onward: `Supervisor Sign-off` became a real policy-driven step for high-value claims, but the normative model remained unchanged. That is a genuine process/model mismatch, not merely noisy logging. At the same time, some enhanced-review cases still lack a recorded `Compliance Check`, so a residual mixture of true bypasses and missing events remains plausible.

Unchanged aggregate outcomes do not settle the issue. Stable approval, appeal, and cycle-time rates can coexist with severe measurement defects because those defects distort conformance more than operations. But the same stable outcomes also do not rule out noncompliance, because control failures may be rare, concentrated in high-risk tails, or simply missed by incomplete incident detection.

## 6. PM4Py reproduction and model-comparison code
```python
import pm4py
import pandas as pd
from collections import Counter

NORMATIVE_TREE = """
-> (
    'Receive',
    'Classify',
    X (
        * ( 'Standard Review', 'Request Info' ),
        -> ( 'Enhanced Review', 'Compliance Check' )
    ),
    'Decision',
    'Notify'
)
"""

# Candidate control-flow-only model for the post-2026-08-01 period.
# It allows an optional sign-off before Decision, but it cannot encode
# the EUR 50,000 data condition.
CANDIDATE_SIGNOFF_TREE = """
-> (
    'Receive',
    'Classify',
    X (
        * ( 'Standard Review', 'Request Info' ),
        -> ( 'Enhanced Review', 'Compliance Check' )
    ),
    X ( tau, 'Supervisor Sign-off' ),
    'Decision',
    'Notify'
)
"""

APR_MAY = [
    ("Receive,Classify,Standard Review,Decision,Notify", 380),
    ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
    ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40),
]

JUN_JUL = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
    ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
    ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
]

AUG_SEP = [
    ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
    ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
    ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
    ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),
]


def expand_variants(period_name, variant_counts):
    traces = []
    for trace, count in variant_counts:
        traces.extend([trace] * count)

    # PM4Py returns a DataFrame by default here.
    df = pm4py.parse_event_log_string(traces, sep=",")
    df["case:concept:name"] = df["case:concept:name"].astype(str).radd(f"{period_name}_")
    df["period"] = period_name

    # Synthetic sequence from the supplied trace order. In real raw data,
    # replace this with the preserved source-system sequence number.
    df["source_seq"] = df.groupby("case:concept:name").cumcount() + 1
    return df


def normalize_log(df, map_risk_screen=True, remove_queue_routed=False):
    out = df.copy()
    if map_risk_screen:
        out.loc[out["concept:name"] == "Risk Screen", "concept:name"] = "Classify"
    if remove_queue_routed:
        out = out[out["concept:name"] != "Queue Routed"].copy()
    return out.reset_index(drop=True)


def order_by_source_sequence_if_present(df):
    if "source_seq" not in df.columns:
        return df
    return df.sort_values(
        ["case:concept:name", "source_seq", "time:timestamp"]
    ).reset_index(drop=True)


def summarize_alignment_moves(diagnostics):
    log_moves = Counter()
    model_moves = Counter()
    for item in diagnostics:
        for left, right in item["alignment"]:
            if left == ">>" and right not in {">>", None}:
                model_moves[right] += 1
            elif right == ">>" and left not in {">>", None}:
                log_moves[left] += 1
    return log_moves, model_moves


def evaluate(label, df, net, im, fm):
    dfg, starts, ends = pm4py.discover_dfg(df)
    fitness = pm4py.fitness_alignments(df, net, im, fm)
    precision = pm4py.precision_alignments(df, net, im, fm)
    diagnostics = pm4py.conformance_diagnostics_alignments(df, net, im, fm)
    log_moves, model_moves = summarize_alignment_moves(diagnostics)

    print(f"\n=== {label} ===")
    print(
        {
            "cases": int(df["case:concept:name"].nunique()),
            "events": int(len(df)),
            "fit_traces_pct": round(fitness["percentage_of_fitting_traces"], 2),
            "avg_trace_fitness": round(fitness["average_trace_fitness"], 4),
            "log_fitness": round(fitness["log_fitness"], 4),
            "precision": round(float(precision), 4),
            "top_log_moves": log_moves.most_common(6),
            "top_model_moves": model_moves.most_common(6),
        }
    )

    interesting_edges = [
        ("Receive", "Classify"),
        ("Receive", "Risk Screen"),
        ("Risk Screen", "Queue Routed"),
        ("Standard Review", "Notify"),
        ("Notify", "Decision"),
        ("Enhanced Review", "Decision"),
        ("Enhanced Review", "Compliance Check"),
        ("Compliance Check", "Supervisor Sign-off"),
        ("Standard Review", "Supervisor Sign-off"),
    ]
    print(
        "interesting_dfg_edges",
        {edge: dfg[edge] for edge in interesting_edges if edge in dfg},
    )


# 1. Encode and convert the normative process tree.
norm_tree = pm4py.parse_process_tree(NORMATIVE_TREE)
norm_net, norm_im, norm_fm = pm4py.convert_to_petri_net(norm_tree)

# 2. Create the candidate Aug-Sep model with optional sign-off.
candidate_tree = pm4py.parse_process_tree(CANDIDATE_SIGNOFF_TREE)
candidate_net, candidate_im, candidate_fm = pm4py.convert_to_petri_net(candidate_tree)

# 3. Expand the supplied variant-frequency tables into logs.
apr_may_log = expand_variants("Apr-May", APR_MAY)
jun_jul_log = expand_variants("Jun-Jul", JUN_JUL)
aug_sep_log = expand_variants("Aug-Sep", AUG_SEP)

# 4. Compare raw and normalized conformance results.
evaluate("Apr-May raw vs normative", apr_may_log, norm_net, norm_im, norm_fm)
evaluate("Jun-Jul raw vs normative", jun_jul_log, norm_net, norm_im, norm_fm)

jun_jul_mapped = normalize_log(jun_jul_log, map_risk_screen=True, remove_queue_routed=False)
evaluate("Jun-Jul mapped label only", jun_jul_mapped, norm_net, norm_im, norm_fm)

jun_jul_normalized = normalize_log(jun_jul_log, map_risk_screen=True, remove_queue_routed=True)
evaluate(
    "Jun-Jul mapped + Queue Routed removed",
    jun_jul_normalized,
    norm_net,
    norm_im,
    norm_fm,
)

# 5. Ordering by source sequence is shown explicitly, although with these
# aggregate traces it is effectively a no-op because no alternate source
# ordering was supplied.
jun_jul_source_ordered = order_by_source_sequence_if_present(jun_jul_normalized)
evaluate(
    "Jun-Jul normalized + source-sequence ordering",
    jun_jul_source_ordered,
    norm_net,
    norm_im,
    norm_fm,
)

aug_sep_normalized = normalize_log(aug_sep_log, map_risk_screen=True, remove_queue_routed=True)
evaluate("Aug-Sep normalized vs normative", aug_sep_normalized, norm_net, norm_im, norm_fm)
evaluate(
    "Aug-Sep normalized vs candidate sign-off model",
    aug_sep_normalized,
    candidate_net,
    candidate_im,
    candidate_fm,
)

print("\nCAVEATS")
print("- These logs are synthetic expansions of aggregated variants, so they will not reproduce the dossier's exact alignment percentages or timestamp-order defects.")
print("- For the real investigation, preserve and use the original source-system sequence number and source timestamps instead of regenerated synthetic order.")
print("- The optional sign-off model is control-flow only; it cannot enforce the EUR 50,000 condition and may improve fitness by overgeneralizing.")
print("- Manual Override is intentionally left visible because the dossier says it is a real user action, even though its logging changed on 2026-08-12.")
```

## 7. Provisional conclusion
The primary explanation for the measured conformance collapse is a compounded measurement problem, not a sudden broad failure of staff discipline. The strongest evidence is the staged recovery in June-July: raw fitness falls to 32%, then rises to 58% after remapping `Risk Screen` to `Classify`, to 81% after removing `Queue Routed`, and to 89% after ordering by source sequence. That sequence is hard to reconcile with a story in which reviewers suddenly became much less compliant in early June 2026. It is easy to reconcile with three dated provenance changes: the 2026-05-31 UI rename, the 2026-06-03 technical routing event, and the 2026-06-15 ETL timestamp change. My confidence in this primary explanation is high, about 85/100.

A separate issue may still remain. From 2026-08-01, `Supervisor Sign-off` is likely a genuine policy-driven step for claims above EUR 50,000, so the normative model became stale. That explains much of the residual Aug-Sep misfit, especially because a sign-off-capable candidate model lifts normalized fitness from 66% to 86%. However, some enhanced-review cases still lack a recorded `Compliance Check` even after the benign repairs, and the 2026-07-10 memo shows the control was salient enough to remind staff about it. Because there is still no reliable audit proving whether those traces are true bypasses or missing events, my confidence that there is a material underlying compliance problem is only moderate, about 45/100.

Immediate actions are split by owner. IT should freeze event semantics, restore source-order provenance in the conformance job, and reconcile `Compliance Check` capture across source, gateway, and warehouse. Process owners should version the normative model effective 2026-08-01 and add an attribute-aware rule for high-value claims. Compliance should manually audit the enhanced-review cases lacking a recorded check and examine reviewer-level clusters of `Manual Override` and missing checks.

What must not be claimed yet: that employees broadly deteriorated; that all deviations are harmless data noise; or that optional sign-off is acceptable for all cases regardless of claim value.

## 8. Model-governance recommendation
1. Version normative models with explicit effective dates and change tickets, and never run a post-policy population against a pre-policy model without a time-based selection rule.
2. Maintain an event-semantic contract for every business label, so UI text changes such as `Classify` to `Risk Screen` require an explicit compatibility declaration or a new canonical event name.
3. Classify technical events separately from business-control events, and require every new gateway or middleware event to declare whether it is excluded, auxiliary, or normative for conformance.
4. Preserve timestamp provenance and source ordering fields end to end, and make the conformance pipeline declare which timestamp and tie-breaker it used for each analysis run.
5. Represent data-aware obligations outside a pure control-flow model when needed, so rules like `Supervisor Sign-off` only for claims above EUR 50,000 are not approximated by an overpermissive optional step.
6. After every release affecting UI labels, gateways, ETL, or policy, run a post-release validation pack on a canary sample comparing variants, DFGs, fitness, precision, and audited case provenance before publishing conformance results.
