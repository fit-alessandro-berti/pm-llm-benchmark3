## 1. Normalization Assumptions

- **Interval semantics.** Each recorded timestamp is converted to a set of feasible true UTC times. I use intervals, not point estimates, for all conformance conclusions. Midpoints are used only in the PM4Py diagnostic section and are explicitly labeled lossy.
- **Clock-offset direction.** Given `clock_offset = recorded_clock - true_clock` and offset bound `[a, b]`, true time is `recorded - offset`. For a recorded interval `[r_start, r_end]`, the true interval is `[r_start - b, r_end - a]`.
- **Resolution/rounding before clock correction.**
  - HUB: exact to displayed second plus measurement uncertainty `±0.5 s`, then HUB offset `[-1 s, +1 s]`  total HUB true interval `[t - 1.5 s, t + 1.5 s]`.
  - OPS-BER, VENDOR-NY, LEGACY-BER: floor to minute. Displayed `HH:MM` means local clock time in `[HH:MM:00, HH:MM+1:00)`.
  - SENSOR: round to nearest 10 seconds. Displayed `t` means recorded clock in `[t - 5 s, t + 5 s)`.
  - MOBILE-LON: round to nearest minute. Displayed `t` means recorded clock in `[t - 30 s, t + 30 s)`.
- **Time-zone conversion.** Local clock intervals are converted to UTC using IANA time zones. For the 2025-10-26 Europe/Berlin DST fold, local times `02:00` through `02:59` are ambiguous: `fold=0` maps to CEST/UTC+2, `fold=1` maps to CET/UTC+1.
- **DST-fold handling for T-405.** The ingestion order `Alert_Received < Investigation_Start < Containment_Complete` rules out all fold combinations except:
  - `Alert_Received` = first fold / CEST,
  - `Investigation_Start` = second fold / CET,
  - `Containment_Complete` = second fold / CET.
  The surviving timestamps remain intervals because of minute flooring and clock offset.
- **Inferred events.**
  - T-404: `Investigation_Start` is inferred from `Investigation_Complete` minus a duration in `[18 min, 25 min]`. The full uncertainty is retained.
  - T-407: `Alert_Received` is inferred from `Alert_Sent` plus delivery latency `[0, 20 min]`. `Alert_Sent` is not treated as definitionally identical to `Alert_Received`; this is a low-confidence inference. For pair feasibility, the causal assumption “receipt must not be after investigation start” is used.
- **Causal order.** For an activity pair `(X, Y)`, feasible durations are computed only for `t_Y >= t_X`. If intervals overlap, the minimum feasible duration is `0`. If no feasible order exists, the pair is indeterminate.
- **Mobile entry delay for T-406.** I treat the “up to five minutes late” entry delay as uncertainty about **occurrence time**: the entered timestamp is an upper bound on the true occurrence, so the occurrence interval is shifted earlier by `[0, 5 min]`. This is the main assumption used in the tables. The alternative “late recording only, occurrence unchanged” assumption is noted because it changes T-406 S2.
- **Headline classification basis.** Section 3 uses SLA tolerance `0` and temporal-profile `zeta = 2`. Section 4 gives sensitivity for SLA tolerance `0/2/5` minutes and `zeta = 1/2/3`.
- **Boundary convention.** Rounded upper endpoints are technically exclusive, but I treat endpoints as closed for conservative interval arithmetic. The difference is sub-second and does not change the stated classifications.
