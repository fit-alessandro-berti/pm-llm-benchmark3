Shadow and bridging roles are not necessarily policy violations; in complex service operations, they often emerge organically to absorb variance, prevent handoff friction, and preserve throughput—while introducing latency, rework, or accountability risks when left unmanaged.

# 5. PM4Py role-discovery and similarity code

```python
import pandas as pd
import numpy as np
import pm4py

# 1. Load and format the event log
raw_df = pd.read_csv("order_to_resolution_events.csv")
raw_df["time:timestamp"] = pd.to_datetime(raw_df["time:timestamp"], utc=True)

log_df = pm4py.format_dataframe(
    raw_df,
    case_id="case:concept:name",
    activity_key="concept:name",
    timestamp_key="time:timestamp",
)

# 2. Baseline vs. non-substitution / complexity-stratified views
#    Avoid treating temporary substitutions as permanent role competence.
baseline_df = pm4py.filter_event_attribute_values(
    log_df,
    attribute_key="temporary_substitution",
    values=[False, "False", 0],
    level="event",
    retain=True,
)

high_crit_df = pm4py.filter_event_attribute_values(
    baseline_df,
    attribute_key="case_complexity",
    values=["High", "Critical"],
    level="event",
    retain=True,
)

low_med_df = pm4py.filter_event_attribute_values(
    baseline_df,
    attribute_key="case_complexity",
    values=["Low", "Medium"],
    level="event",
    retain=True,
)

# 3. Discover organizational roles (overall vs. baseline vs. complexity-stratified)
roles_all = pm4py.discover_organizational_roles(log_df)
roles_baseline = pm4py.discover_organizational_roles(baseline_df)
roles_high_crit = pm4py.discover_organizational_roles(high_crit_df)
roles_low_med = pm4py.discover_organizational_roles(low_med_df)

def summarize_roles(role_list, label):
    rows = []
    for idx, role in enumerate(role_list):
        rows.append({
            "scope": label,
            "role_cluster_id": f"{label}_R{idx+1}",
            "activities": sorted(list(role.activities)),
            "resources": dict(role.originator_importance),
        })
    return pd.DataFrame(rows)

roles_summary_df = pd.concat([
    summarize_roles(roles_all, "all_events"),
    summarize_roles(roles_baseline, "no_substitution"),
    summarize_roles(roles_high_crit, "high_critical_only"),
    summarize_roles(roles_low_med, "low_medium_only"),
], ignore_index=True)

# 4. Activity-based resource similarity (full vs. non-substitution)
sim_all = pm4py.discover_activity_based_resource_similarity(log_df)
sim_baseline = pm4py.discover_activity_based_resource_similarity(baseline_df)

# Convert SNA similarity connections to DataFrame for comparison
sim_df = pd.DataFrame(
    [(r1, r2, score) for (r1, r2), score in sim_baseline.connections.items()],
    columns=["resource_a", "resource_b", "baseline_similarity"],
)

# 5. Handover-of-work, working-together, and subcontracting networks
#    Reveals bridging (R13_Mateo, R07_Giorgio) and gatekeeping (R05_Erik, R08_Hana)
how_net = pm4py.discover_handover_of_work_network(log_df, beta=0)
wt_net = pm4py.discover_working_together_network(log_df)
sub_net = pm4py.discover_subcontracting_network(log_df)

how_edges = pd.DataFrame(
    [(u, v, w) for (u, v), w in how_net.connections.items()],
    columns=["from_resource", "to_resource", "handover_weight"],
)
wt_edges = pd.DataFrame(
    [(u, v, w) for (u, v), w in wt_net.connections.items()],
    columns=["resource_a", "resource_b", "working_together_weight"],
)

# Compute out-degree / in-degree / cross-boundary spread per resource
out_how = how_edges.groupby("from_resource")["handover_weight"].sum().rename("how_out_weight")
in_how = how_edges.groupby("to_resource")["handover_weight"].sum().rename("how_in_weight")
wt_partners = wt_edges.groupby("resource_a")["resource_b"].nunique().rename("unique_collaborators")

# 6. Enrich with case_complexity, temporary_substitution, escalation, and service time
#    Assuming numeric complexity score or mapping ordinal levels to [0.15, 0.45, 0.75, 0.95]
complexity_map = {"Low": 0.15, "Medium": 0.45, "High": 0.75, "Critical": 0.95}
if "case_complexity_score" not in log_df.columns:
    log_df["case_complexity_score"] = log_df["case_complexity"].map(complexity_map)

# Optional: insert service/waiting times to detect substitution bottlenecks (e.g., 38m -> 74m)
enriched_df = pm4py.insert_case_service_waiting_time(log_df)

# Flag reopen cases (A13) to track downstream quality / rework risk
reopen_cases = set(
    log_df.loc[log_df["concept:name"] == "Reopen Request", "case:concept:name"]
)
log_df["is_reopened_case"] = log_df["case:concept:name"].isin(reopen_cases)

resource_metrics = (
    log_df.groupby("org:resource")
    .agg(
        total_events=("concept:name", "count"),
        unique_cases=("case:concept:name", "nunique"),
        median_complexity=("case_complexity_score", "median"),
        high_crit_share=("case_complexity", lambda s: s.isin(["High", "Critical"]).mean()),
        substitution_share=("temporary_substitution", lambda s: pd.Series(s).astype(bool).mean()),
        approval_events=("concept:name", lambda s: (s == "Supervisor Approval").sum()),
        reopen_case_share=("is_reopened_case", "mean"),
    )
    .join([out_how, in_how, wt_partners])
    .fillna(0)
)

# 7. Join PM4Py role clusters with resource context to prevent authority misinterpretation
#    Extract primary baseline role cluster per resource
resource_to_cluster = []
for idx, role in enumerate(roles_baseline):
    for res, imp in role.originator_importance.items():
        resource_to_cluster.append({
            "org:resource": res,
            "baseline_cluster": f"Cluster_{idx+1}",
            "cluster_importance": imp,
            "cluster_activities": ", ".join(sorted(role.activities)),
        })

cluster_df = (
    pd.DataFrame(resource_to_cluster)
    .sort_values("cluster_importance", ascending=False)
    .drop_duplicates("org:resource")
    .set_index("org:resource")
)

final_role_audit = resource_metrics.join(cluster_df, how="left")

# Flag resources where frequency-based cluster membership diverges from risk/authority:
# - High complexity or approval divergence within the same cluster (e.g., Chen vs. Dina)
# - High substitution share (e.g., Giorgio on A7/A8, Mateo on A9)
# - High reopen share on routine clusters (e.g., Kai/Lina)
cluster_complexity_spread = final_role_audit.groupby("baseline_cluster")["median_complexity"].transform("std")
final_role_audit["complexity_stratification_flag"] = cluster_complexity_spread > 0.12
final_role_audit["substitution_caution_flag"] = final_role_audit["substitution_share"] > 0.05
final_role_audit["bridge_outlier_flag"] = (
    (final_role_audit["unique_collaborators"] >= final_role_audit["unique_collaborators"].quantile(0.75))
    & (final_role_audit["high_crit_share"] >= 0.40)
)

print(final_role_audit.sort_values(["baseline_cluster", "median_complexity"], ascending=[True, False]))
```

### How this prevents over-interpreting frequency clusters as formal authority
1. **Separating baseline vs. substitution logs (`filter_event_attribute_values`)** ensures temporary coverage (R07_Giorgio on A7/A8, R13_Mateo on A9) does not permanently merge substitutes into formal authority roles.
2. **Stratifying role discovery by `case_complexity`** separates R03_Chen (0.71) from R04_Dina (0.48) and R01/R02 (0.29–0.34) from R11/R12 (0.18–0.19) despite near-identical activity vectors.
3. **Joining SNA handover/working-together metrics with reopen rates and service time** surfaces rare specialists (R05_Erik), coordination hubs (R13_Mateo), and rework-inducing gaps (R11/R12) that activity counts miss.

- **Structured complexity progression (R04_Dina  R03_Chen):** Pair Dina with Chen on high-complexity cases (`case_complexity == "High"`) and security-adjacent diagnostics before assigning critical late-shift work.

### Risk Control and Governance
- **Enforce approval separation of duties:** Flag `A9 Supervisor Approval` in the system so preliminary triage by R13_Mateo or commercial work by R07_Giorgio/R06_Fatima is logged distinctly from final `approval`-certified sign-off by R08_Hana (eliminating silent recheck loops like Week 5's 13-of-21 rechecks).

Use explicit severity criteria (`customer_segment`, `product_line`, `case_complexity`) so critical security flags route directly to R05_Erik without waiting in a human triage queue.

### Resilience
- **Codify planned substitution playbooks:** Formalize backup pairs—R07_Giorgio for R06_Fatima (bounded pricing tiers), a designated deputy approver for R08_Hana (so workshops don't trigger mass post-hoc rechecks), and a secondary security reviewer for R05_Erik—so resilience does not depend on undocumented heroics.

### Cautions Against Changing Staffing Based Only on Mined Roles
1. **Mined similarity reflects *observed execution*, not *delegated authority or risk tolerance*:** Removing or merging R01/R02 with R11/R12, or flattening R03_Chen and R04_Dina because of >0.93 cosine similarity, would destroy critical complexity capacity and trigger spikes in reopenings, SLA breaches, and compliance failures.
2. **Low event counts and broad activity scatter can hide mission-critical bottlenecks:** Volume-based clustering undervalues rare specialists (R05_Erik) and brokers (R13_Mateo). Reallocating or cutting "low-volume" or "unclustered" resources based solely on mined role purity would remove the exact connective tissue keeping cross-functional escalations from stalling.
3. **Temporary substitutions create mirage roles in historical logs:** Treating a 10-week aggregate as permanent capability rewards informal workarounds that actually degraded cycle time (Giorgio's 38  74 min) or required silent rework (Mateo's 13/21 rechecked approvals). Always separate `temporary_substitution` episodes before making permanent headcount or role-redesign decisions.
