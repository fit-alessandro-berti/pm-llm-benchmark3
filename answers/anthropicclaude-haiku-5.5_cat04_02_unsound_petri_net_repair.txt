# 1. Executive Verdict

The net is a **workflow net**: it has one source place (`source`), one sink place (`sink`), and every node lies on a path from source to sink. It should **not** be expected to be **sound**. The principal defect is that `t_join_waived` has a single input, `p_waived`, so the waiver branch can authorize a case without analysis. Authorization can occur before `t_analyze`, and the analysis token is then stranded in `p_analysis` or `p_analysis_done`. The business consequence is that a case can be authorized without the mandatory analysis, and some executions end with tokens outside the final marking. The standard-review path is correct; the defect is confined to the waiver path.

| Element or subnet | Intended role | Actual structural effect | Potential symptom |

| `t_split` (unlabeled, AND-split) | Create analysis and review tokens together | Consumes `p_ready`, produces one token in each of `p_analysis` and `p_review`. | None structurally. |

| Standard review: `t_standard_review`, `p_review_done` | One review outcome | Consumes `p_review`, feeds `t_join_normal`. | None. |
| Waiver: `t_waive_review`, `p_waived` | Alternative review outcome | Competes with `t_standard_review` for the single `p_review` token (free-choice). Places a token in `p_waived`. | None by itself. |
| `t_join_normal` (AND-join) | Wait for analysis and standard review | Needs `p_analysis_done` and `p_review_done`; correct. | None. |

| `p_decision` | Case is ready for authorization | Two input transitions. At most one token per case, because only one review token exists. | Authorization is enabled on the waiver branch before analysis. |

| `im` = {source}, `fm` = {sink} | Start and accepting markings | Correct as declared. However, `fm` is not the only terminal state: the waiver path reaches `sink` with tokens left behind. | The net appears to accept although it does not complete properly. |

**Verdict on structure:** the workflow-net check should pass. The defect is behavioral and is hidden by the structure.

# 3. Marking-Based Counterexample

Notation: `s`=source, `R`=p_ready, `A`=p_analysis, `V`=p_review, `AD`=p_analysis_done, `RD`=p_review_done, `W`=p_waived, `D`=p_decision, `K`=sink. Start marking: `im` = {s}. Final marking: `fm` = {K}.

**Counterexample 1 (authorization before analysis; policy violation).** Firing sequence: `t_register, t_split, t_waive_review, t_join_waived, t_authorize, t_analyze`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | (start) | {s} | t_register | Start from `im`. |
| 1 | t_register | {R} | t_split | Case registered. |
| 2 | t_split | {A, V} | t_analyze, t_standard_review, t_waive_review | AND-split creates one token in each parallel branch. |
| 3 | t_waive_review | {A, W} | t_analyze, t_join_waived | Waiver route taken. Analysis is still pending. |
| 4 | t_join_waived | {A, D} | t_analyze, t_authorize | `t_join_waived` fires with only `W` as input. The analysis token is untouched, so the join is not a synchronization. |
| 5 | t_authorize | {A, K} | t_analyze | Authorization occurs **before** `t_analyze`. The sink holds a token, but the marking is not `fm`, and an analysis token remains. |
| 6 | t_analyze | {AD, K} | none | Analysis completes **after** authorization. The marking is dead and is not `fm`. |

**Why the leftover token cannot be consumed:** `AD` is an input only of `t_join_normal`, which also requires `RD`. `RD` can receive a token only from `t_standard_review`, which needs `V`, and `V` was consumed in step 3. No transition can ever consume `AD`, so the case is stuck with a token outside `fm`.

**Counterexample 2 (waiver after analysis; improper completion).** Firing sequence: `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`. This is a legal sequence that follows the intended order, yet it still fails.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | (start) | {s} | t_register | Start from `im`. |
| 1 | t_register | {R} | t_split | |
| 2 | t_split | {A, V} | t_analyze, t_standard_review, t_waive_review | Parallel tokens created. |
| 3 | t_analyze | {AD, V} | t_standard_review, t_waive_review | Analysis completes first. |
| 4 | t_waive_review | {AD, W} | t_join_waived | Waiver recorded. |
| 5 | t_join_waived | {AD, D} | t_authorize | Waiver synchronized **without** a check on the analysis token, which is already present, so this step is ordinary here. |
| 6 | t_authorize | {AD, K} | none | The sink holds one token, but `AD` remains. The marking is dead and is not `fm`. |

**Distinguishing the two conditions:** a token in `sink` does not mean `fm` was reached. `fm` requires exactly {K}. In both counterexamples, `sink` is marked while another token remains, so the final marking is not reached. In Counterexample 2, `fm` is reached only on the standard-review path (`t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize`).

**Exhaustive check (derived by hand):** the original reachability set has 14 markings: {s}, {R}, {A,V}, {AD,V}, {A,RD}, {AD,RD}, {D}, {K}, {A,W}, {AD,W}, {A,D}, {AD,D}, {A,K}, {AD,K}. Two are dead non-final markings: {A,K} and {AD,K}. Both are reached only through the waiver branch.

# 4. Minimal-Repair Alternatives

**Edit-cost model:** each elementary structural edit costs 1. This includes adding or deleting a place, a transition, or an arc. Relabeling is free but is not used. A repair is admissible only if it preserves mandatory analysis (unless the policy change is stated) and yields a sound net.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R-A**: Rewire waiver into the normal join | Delete arc `p_waivedt_join_waived`, `t_join_waivedp_decision`, and `t_waive_reviewp_waived`. Delete `t_join_waived` and `p_waived`. Add arc `t_waive_reviewp_review_done`. | 6 (3 arc deletions, 1 arc addition, 2 node deletions) | Mandatory analysis (enforced by `t_join_normal`). Single decision place. Authorization after both prerequisites. | Waiver now produces the same token as the standard review. Both review outcomes synchronize through `t_join_normal`. Net is free-choice. | Waiver and standard review are indistinguishable at the place level. Future waiver-specific logic needs re-splitting. The waiver is visible only as a transition label. |
| **R-B**: Give the waiver path its own two-input synchronization | Add arc `p_analysis_donet_join_waived`. | **1** (1 arc addition) | All intent preserved. Waiver stays a distinct place until the join. Labels unchanged. | Waiver path now requires analysis completion. Authorization follows analysis on both paths. | `p_analysis_done` becomes an input of two joins, so the net is no longer free-choice. Safety depends on the invariant that at most one review token exists per case. |
| **R-C**: Make analysis optional under waiver (policy change) | Naive version: add arc `p_analysist_join_waived`. A correct version would also need a cancellation transition or place for a pending analysis token. | Naive: 1, but **unsound**. Correct version: estimated 4 (not derived in detail). | Violates "analysis is always mandatory." | Analysis becomes skippable on waiver. | Naive version deadlocks: if `t_analyze` fires first, `t_join_waived` can no longer fire (`A` is consumed) and `W` is stuck. The correct version introduces a choice on the analysis branch. |

**Minimality justification:** Under the cost model, the only zero-policy-change repair found with a single edit is R-B. The other one-arc candidates into `t_join_waived` were checked: adding `p_analysis` is R-C (unsound as stated), and adding `p_review_done` makes the waiver join depend on a token that never exists on the waiver path, so it is dead. Adding `p_analysis_done` is therefore the unique single-edit fix among admissible repairs. R-A costs 6, so it is more expensive but is not tied with R-B. R-A is kept as a structurally distinct fallback because it keeps the net free-choice.

**Tie check:** no tie on cost. R-B (1) beats R-A (6). R-C is not comparable because it changes the policy.

# 6. Diagnostic and Reachability Code

This block assumes that `net`, `im`, `fm` (original) and `repaired_net`, `repaired_im`, `repaired_fm` exist. The helper `fire` checks enabledness with `pm4py.get_enabled_transitions` and raises an error instead of moving tokens silently.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def marking_str(m):
    """Render a marking as a sorted multiset of place names."""
    return "{" + ", ".join(sorted(p.name for p, n in m.items() for _ in range(n))) + "}"


def fire(net, marking, transition_name):
    """Fire a named transition only if it is enabled; otherwise raise."""
    enabled = pm4py.get_enabled_transitions(net, marking)
    matches = [t for t in enabled if t.name == transition_name]
    if not matches:
        names = sorted(t.name for t in enabled)
        raise RuntimeError(
            f"{transition_name} NOT enabled at {marking_str(marking)}; enabled={names}"
        )
    t = matches[0]
    new = Marking(marking)
    for arc in t.in_arcs:
        new[arc.source] -= 1
        if new[arc.source] == 0:
            del new[arc.source]
    for arc in t.out_arcs:
        new[arc.target] += 1
    return new


def replay(label, petri_net, start, sequence, goal):
    print(f"\n== {label} ==")
    m = Marking(start)
    print("start:", marking_str(m))
    for name in sequence:
        try:
            m = fire(petri_net, m, name)
        except RuntimeError as err:
            print("BLOCKED:", err)
            return None
        print(f"  fired {name:<22} -> {marking_str(m)}")
    print("reached fm exactly:", m == goal, "| final:", marking_str(m))
    return m


# Label-level sequences (transition names)
STANDARD_PATH = ["t_register", "t_split", "t_analyze",
                 "t_standard_review", "t_join_normal", "t_authorize"]
WAIVER_AFTER_ANALYSIS = ["t_register", "t_split", "t_analyze",
                         "t_waive_review", "t_join_waived", "t_authorize"]
WAIVER_BEFORE_ANALYSIS = ["t_register", "t_split", "t_waive_review",
                          "t_join_waived", "t_authorize", "t_analyze"]


def diagnose(label, petri_net, i, f):
    print(f"\n### {label}")
    print("initial enabled:", sorted(t.name for t in pm4py.get_enabled_transitions(petri_net, i)))
    print("check_is_workflow_net:", pm4py.check_is_workflow_net(petri_net))
    sound = pm4py.check_soundness(petri_net, i, f, print_diagnostics=True)
    print("check_soundness returned:", sound)
    ts = pm4py.convert_to_reachability_graph(petri_net, i, f)
    print("reachability graph: states =", len(ts.states),
          "transitions =", len(ts.transitions))


if __name__ == "__main__":
    diagnose("original", net, im, fm)
    diagnose("repaired", repaired_net, repaired_im, repaired_fm)

    replay("original: standard path", net, im, STANDARD_PATH, fm)
    replay("original: waiver after analysis", net, im, WAIVER_AFTER_ANALYSIS, fm)
    replay("original: waiver before analysis", net, im, WAIVER_BEFORE_ANALYSIS, fm)

    replay("repaired: standard path", repaired_net, repaired_im, STANDARD_PATH, repaired_fm)
    replay("repaired: waiver after analysis", repaired_net, repaired_im, WAIVER_AFTER_ANALYSIS, repaired_fm)
    replay("repaired: waiver before analysis", repaired_net, repaired_im, WAIVER_BEFORE_ANALYSIS, repaired_fm)
```

**Expected qualitative difference (from hand derivation; not executed here):**

- **Original:** `check_is_workflow_net` passes. `check_soundness` fails on proper completion and the option to complete, with two dead non-final markings ({AD,K} and {A,K}). The waiver-before-analysis replay runs to completion but ends outside `fm`. The reachability graph has 14 markings.
- **Repaired:** `check_is_workflow_net` passes. `check_soundness` passes. The waiver-before-analysis replay is `BLOCKED` at `t_join_waived` (not enabled at {A,W}). The reachability graph has 10 markings, namely the original set minus the four bypass markings {A,D}, {AD,D}, {A,K}, {AD,K}.

# 7. Repair Trade-Offs and Residual Risks

- **Waiver vs. standard review distinguishability.** Under R-B, the waiver is distinct at the place level (`p_waived`) until `t_join_waived` consumes it. After the join, `p_decision` does not record which review occurred. Under R-A, the distinction is lost immediately, since both outcomes produce `p_review_done`. In either case the waiver is recorded only by the `Record Review Waiver` event. If an audit requires the waiver as a case attribute, a data attribute or a separate record is needed. Soundness does not supply this.

- **Silent transitions and duplicate behavior.** `t_split` and `t_join_waived` are unlabeled. Visible behavior does not duplicate: each case has exactly one review outcome, and the labels still show it. However, process-discovery tools may hide or misplace the silent join, and alignments may need custom mapping. A future edit that gives the join a label would change log conformance results.

- **R-B and free-choice.** `p_analysis_done` now feeds two transitions with different co-inputs, so the net is no longer free-choice. The two joins are mutually exclusive only because one review token exists per case. A later edit that adds a second review token, or lets review outcomes repeat, could create real conflict between `t_join_normal` and `t_join_waived`. Re-run soundness checks after every edit to the review subnet.

- **Soundness does not prove business alignment.** A sound net can still permit an unwanted control flow. For example, it can allow authorization without any review, or let a waiver be granted to cases that should not be eligible. Soundness checks only the control flow of the model. Eligibility rules, authority, and the recording of waivers need separate checks.

- **Regression tests.**
  - *Positive:* analysis then standard review then authorize; standard review then analysis then authorize; analysis then waiver then authorize; waiver then analysis then authorize.
  - *Negative:* authorize without analysis; authorize after waiver without analysis; two review outcomes for one case; waiver after standard review; analysis missing from the log; authorize twice for one case.

- **Detecting accidental bypass of mandatory analysis.** Run alignments or token-based replay on the production log against the model, and alert when a case contains `Authorize Case` without `Perform Analysis` (or with the analysis event after authorization). Add a model-level check: in the reachability graph, verify that no reachable marking contains a token in `sink` with any other token present, and that every marking with a token in `p_decision` has consumed `p_analysis_done`.

# 8. Final Recommendation

**Deploy R-B** (add arc `p_analysis_done  t_join_waived`). It is the unique one-edit repair among admissible options. It keeps the waiver as a separate branch, preserves all labels and the business policy, and enforces mandatory analysis on both review paths. The cost is that the net is no longer free-choice. This is acceptable because the joins are mutually exclusive under the one-review-token invariant, and the repaired net should pass the soundness check. Deployment should be gated by the regression suite in Section 7 and by a conformance monitor for authorization without analysis.

**Fallback: R-A** (rewire the waiver into `t_join_normal` via `p_review_done`). It costs 6 edits but keeps the net free-choice and removes the second join entirely. Choose it if the toolchain requires free-choice nets or if the business is willing to treat a waiver as a review outcome. The trade-off is that the waiver is no longer distinguishable in the net structure.
