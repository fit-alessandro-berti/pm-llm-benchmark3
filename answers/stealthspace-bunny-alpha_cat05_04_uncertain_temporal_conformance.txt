## 1. Normalization Assumptions

1. **Primary analysis:** SLA rules are evaluated as hard limits; temporal profiles are evaluated separately as statistical expectations. The primary temporal-profile choice is ** = 1**.

2. **Intervals are bounds, not probabilities.** I treat the stated source bounds as enclosing the true clock error. I do not assign probabilities, confidence distributions, or preferred timestamps within an interval. Unless stated otherwise, clock errors from different events are allowed to vary independently within their bounds. Consequently, interval subtraction gives **feasible outer bounds**, potentially broader than the result with known shared-clock correlations.

3. **Clock correction:**  
   `clock_offset = recorded_clock  true_clock`  
   Therefore:
   \[
   \text{true time}=\text{recorded clock time}-\text{clock offset}.
   \]
   For offset bounds \([a,b]\), the corrected interval is:
   \[
   [\text{recorded-window lower bound}-b,\ 
     \text{recorded-window upper bound}-a].
   \]

4. **Resolution is applied before clock correction.**
   - HUB exact-to-second records receive the specified ±0.5-second measurement interval.
   - Floor-to-minute records occupy the displayed minute plus 59.999 seconds.
   - SENSOR receives ±5 seconds around the nearest-10-second timestamp.
   - MOBILE-LON is conservatively treated as nearest-minute rounding with ±30 seconds.

5. **Time zones:**  
   - June 2026 Berlin time is CEST, UTC+02:00.
   - June 2026 New York time is EDT, UTC04:00.
   - June 2026 London time is BST, UTC+01:00.
   - The 2025-10-26 Berlin ambiguity has:
     - first occurrence of 02:xx at UTC+02:00;
     - second occurrence of 02:xx at UTC+01:00.

6. **Negative elapsed times:** A negative `End  Start` is not treated as a particularly fast valid process. For “after” rules and eventually-following profiles, it is evidence that the required ordering or timestamp semantics are violated. Thus T-405’s AlertInvestigation and AlertContainment results are certain violations of the **positive/following premise**, not valid SLA-compliant durations.

7. **T-404 inferred start:** The investigation start is the set:
   \[
   C_{\text{complete}}-[18\text{ min},25\text{ min}].
   \]
   I retain the signed duration’s entire range and the HUB completion-event uncertainty. It is an inferred interval, not an observed start.

8. **T-405 ordering:** I interpret the supplied ingestion sequence as a constraint on occurrence order, as the question directs. This excludes the first-fold Alert interval, but it does **not** resolve the Investigation and Containment folds. If ingestion order describes only data-arrival order, these exclusions would need to be revisited.

9. **T-406 entry delay:**
   - **Primary interpretation:** entry delay can represent a genuinely late occurrence estimate, so:
     \[
     \text{occurrence/estimate}
     =\text{clock-corrected record}-[0,300\text{ s}].
     \]
   - **Alternative interpretation:** the delay affected only when the user recorded the event, not the time being recorded. Under that reading, the clock-corrected interval is **[12:08:30, 12:19:29.999] UTC**, and the entry delay is metadata only.
   - These interpretations materially change S2 and the =1 InvestigationContainment result.

10. **T-407 receipt:** `Alert_Received` is not replaced by `Alert_Sent`. A conditional receipt proxy is calculated as:
    \[
    R=\text{AlertSent}+[0,20\text{ min}].
    \]
    That proxy does not prove delivery or receipt. The plausible causal condition \(R\leq I\) is evaluated as a sensitivity scenario, not treated as a logged fact.

11. **T-409 weak clock estimate:** The ±12-minute range is shown as an **engineering scenario**, but is not accepted as a sufficiently strong, audited bound for a primary certainty finding. Therefore its affected findings are **INDETERMINATE**, with conditional classifications shown separately.

12. **SLA tolerances:** Adding 2 or 5 minutes expands the relevant maximum by exactly 120 or 300 seconds. It does not narrow timestamp uncertainty.

13. **Missing events:** S3 is assessed only for T-401 and T-408. T-407’s AlertContainment interval is not reported as an observed temporal-profile result; using the proxy there would test a model, not the logged activity pair.

# 2. Interval representation, resolution, timezone conversion, and offsets.
# An interval is (lower_epoch_seconds, upper_epoch_seconds).
# ---------------------------------------------------------------------

Interval = tuple[float, float]
Intervals = list[Interval]
EPS = 1e-6


def clean(intervals: Intervals) -> Intervals:
    """Sort and merge overlapping/touching intervals; preserve disjoint sets."""
    if not intervals:
        return []
    ordered = sorted(intervals)
    merged = [ordered[0]]
    for lo, hi in ordered[1:]:
        last_lo, last_hi = merged[-1]
        if lo <= last_hi + EPS:
            merged[-1] = (last_lo, max(last_hi, hi))
        else:
            merged.append((lo, hi))
    return merged


def as_utc(local_naive: pd.Timestamp, zone: str, fold: int) -> pd.Timestamp:
    """Standard-library ZoneInfo localization with explicit DST fold."""
    local = local_naive.to_pydatetime().replace(tzinfo=ZoneInfo(zone), fold=fold)
    return pd.Timestamp(local).tz_convert("UTC")


def source_window(recorded: pd.Timestamp, rounding: str) -> tuple[pd.Timestamp, pd.Timestamp]:
    """Apply display-resolution uncertainty before clock correction."""
    if rounding == "exact_second":
        return (
            recorded - pd.Timedelta(seconds=0.5),
            recorded + pd.Timedelta(seconds=0.5),
        )
    if rounding == "floor_minute":
        lo = recorded.floor("min")
        hi = lo + pd.Timedelta(minutes=1) - pd.Timedelta(milliseconds=1)
        return lo, hi
    if rounding == "round_10_seconds":
        return (
            recorded - pd.Timedelta(seconds=5),
            recorded + pd.Timedelta(seconds=5),
        )
    if rounding == "round_minute":
        # Conservative closed +/-30-second interval.
        return (
            recorded - pd.Timedelta(seconds=30),
            recorded + pd.Timedelta(seconds=30),
        )
    raise ValueError(f"Unknown rounding mode: {rounding}")


def normalize_one(
    record,
    include_entry_delay: bool = True,
    force_first_fold: bool = False,
) -> Intervals:
    lo_clock, hi_clock = source_window(record["recorded"], record["rounding"])

    # UTC has no ambiguity; BER on 2025-10-26 is represented by folds 0 and 1.
    if force_first_fold or record["system"] != "LEGACY-BER":
        folds = (0,)
    else:
        folds = (0, 1)

    out = []
    for fold in folds:
        lo_utc = as_utc(lo_clock, record["zone"], fold)
        hi_utc = as_utc(hi_clock, record["zone"], fold)

        # true = recorded - offset:
        # lower uses maximum offset; upper uses minimum offset.
        true_lo = lo_utc - pd.Timedelta(seconds=record["offset_hi"])
        true_hi = hi_utc - pd.Timedelta(seconds=record["offset_lo"])

        delay = record["entry_delay_max_s"] if include_entry_delay else 0.0
        # Primary T-406 model: estimate = corrected_record - entry_delay.
        true_lo -= pd.Timedelta(seconds=delay)

        out.append((
            true_lo.timestamp(),
            true_hi.timestamp(),
        ))
    return clean(out)

def intervals_by_case_activity(frame: pd.DataFrame) -> dict:
    result = {}
    for case, group in frame.groupby("case"):
        result[case] = {}
        for activity, ag in group.groupby("activity"):
            alternatives = []
            for intervals in ag["intervals"]:
                alternatives.extend(intervals)
            result[case][activity] = clean(alternatives)
    return result


def apply_t405_occurrence_order(by_case: dict) -> dict:
    """
    Treat supplied ingestion order as occurrence order:
    Alert < Investigation < Containment.

    This removes impossible fold combinations, not all uncertainty.
    """
    alert_alts = by_case["T-405"]["Alert_Received"]
    start_alts = by_case["T-405"]["Investigation_Start"]
    complete_alts = by_case["T-405"]["Containment_Complete"]

    kept_alert, kept_start, kept_complete = set(), set(), set()
    for alert, start, complete in product(alert_alts, start_alts, complete_alts):
        if alert[1] <= start[0]:
            continue
        if start[1] > complete[0]:
            continue
        kept_alert.add(alert)
        kept_start.add(start)
        kept_complete.add(complete)

    by_case["T-405"]["Alert_Received"] = clean(list(kept_alert))
    by_case["T-405"]["Investigation_Start"] = clean(list(kept_start))
    by_case["T-405"]["Containment_Complete"] = clean(list(kept_complete))
    return by_case

def difference_intervals(left: Intervals, right: Intervals) -> Intervals:
    """Minkowski difference: preserve disjoint unions."""
    out = []
    for a in left:
        for b in right:
            out.append((a[0] - b[1], a[1] - b[0]))
    return clean(out)


def classify_sla(intervals: Intervals, maximum: float) -> str:
    # A negative "after" duration is an ordering violation, not a pass.
    valid = [iv for iv in intervals if iv[1] >= 0]
    if not valid:
        return "CERTAIN_VIOLATION"
    if any(iv[1] > maximum for iv in valid):
        return "POSSIBLE_VIOLATION"
    return "CERTAIN_PASS"


def classify_profile(intervals: Intervals, lower: float, upper: float) -> str:
    if not intervals:
        return "INDETERMINATE"
    if all(iv[1] < lower for iv in intervals) or all(iv[0] > upper for iv in intervals):
        return "CERTAIN_VIOLATION"
    if all(lower <= iv[0] and iv[1] <= upper for iv in intervals):
        return "CERTAIN_PASS"
    return "POSSIBLE_VIOLATION"


def interval_text(intervals: Intervals) -> str:
    return "  ".join(f"[{lo:.3f},{hi:.3f}]" for lo, hi in intervals)

## 6. Evidential Sufficiency

There is no universally “minimum” number of additional data points independent of the desired conclusion. The following identifies the **minimum type and scope of evidence** needed to turn the listed uncertainty into a certain pass or violation.

| Case / uncertain finding | Additional evidence needed for certainty | Evidence type |
|---|---|---|
| **T-401 S1 and =1/2 AI** | A synchronized, high-resolution Start timestamp and a narrower signed OPS-BER offset bound sufficient to place the complete duration interval wholly inside or outside the relevant limit/band. For example, at =1, certification requires the entire interval below 780 s for pass or above 780 s for violation. | Stronger synchronization and resolution |
| **T-402 S1 and AI profile** | To preserve certain zero-tolerance S1 violation, total feasible timing uncertainty relative to the 15-minute limit must be reduced by more than about 59.5 s. For a certain profile result, the resulting duration must be wholly inside or outside the selected band. | Clock-offset telemetry and high-resolution timestamps |
| **T-402 S2 and =1 IC** | A sufficiently precise synchronized Start and Completion interval that no longer straddles 2700 s, or a sufficiently narrow offset bound that puts its maximum below 2700 s. For violation, evidence must make even the earliest feasible completion occur more than 45 minutes after Start. | Synchronization |
| **T-403 =3 AC** | Better VENDOR-NY synchronization or an event-level UTC receipt record sufficient to remove the present profile-band overlap. | External-source synchronization |
| **T-404 S1, S2, AI, and IC** | Preferably a directly logged, synchronized Investigation_Start. If duration evidence remains the basis, a narrower signed duration bound tied to a specific Investigation_Complete can suffice. With current HUB uncertainty, a work-duration upper bound no greater than about **899 s** would establish the original S1 pass; an earliest-start bound later than Alert’s latest feasible time plus 900 s would establish violation. For original S2, a duration upper bound around **1499 s or less** would establish a pass. | Missing activity evidence or tighter duration evidence |
| **T-405 S2 and IC at every  shown** | A DST-fold identifier for both Investigation and Containment, with a trusted UTC offset for that hour. Same-fold surviving branches are approximately 32–42 minutes; the surviving cross-fold branch is approximately 92–102 minutes. Fold identity would therefore distinguish pass from violation. | Time-zone/fold evidence plus clock evidence |
| **T-405 ordering-related negative results** | True occurrence-order provenance, such as monotonic event identifiers or trusted transaction sequencing. Mere arrival order at an ingestion system is insufficient if ingestion can be delayed or reordered. | Semantic/transaction evidence |
| **T-406 S1 and AI profile** | Evidence about what the mobile entry timestamp represents, plus a narrower device clock bound. A trusted event-generated start time, rather than a manually entered time, would be preferable. | Semantic and synchronization evidence |
| **T-406 S2 and =1 IC** | A signed record distinguishing late entry from late occurrence. To make the primary possible violation a certain pass, one needs either proof that entry delay did not shift occurrence time and a sufficiently narrow clock bound, or evidence that actual entry delay was zero. Clock tightening alone cannot remove the five-minute semantic ambiguity. | Semantic evidence about entry delay |
| **T-407 S1 and AI profile** | An actual receipt acknowledgment or equivalent trustworthy evidence that delivery occurred, with its event timestamp and clock uncertainty. Receipt-after-Start must not be assumed. For S1 certainty, the certified receipt-to-start interval must be wholly at or below 900 s for pass or wholly above it for violation. For profile certainty, it must be wholly inside or outside the selected band. | Missing activity evidence and synchronization |
| **T-408 S2** | A sufficiently precise Start/Completion interval. The current lower bound is about 3299 s, so for a certain violation the combined uncertainty would need to be reduced by more than approximately 599 s. For a certain pass, its upper bound would need to fall below 2700 s. | Synchronization and resolution |
| **T-409 S1, S2, AI, and IC** | Audited NTP/PTP diagnostics covering the relevant hour, with signed offset bounds and uncertainty in those bounds. A weak engineering estimate is not enough for enforcement. The verified interval must then be wholly inside or outside the relevant SLA/profile region. | Stronger source-clock evidence |
| **T-409 if the ±12-minute estimate is accepted solely as a scenario** | No additional evidence is needed to calculate the conditional results: S1 and AI are possible violations; S2 is a conditional pass; IC is a conditional =1 violation. But an audit of the estimate is needed before treating those calculations as certain. | Evidence-quality validation |

A general point worth preserving: additional evidence can make a finding **certainly passing** or **certainly violating**, but cannot justify selecting whichever outcome is preferred. The certification condition is that the tightened feasible interval no longer overlaps the relevant boundary.

## 7. Governance Recommendation

1. **Store canonical UTC timestamps**
   - Persist event time as UTC with sufficient precision, ideally nanoseconds or an explicitly documented precision.
   - Retain the original displayed value, source time zone, offset/fold, and rendering rule.
   - Never overwrite the raw timestamp with a corrected or midpoint value.

2. **Retain complete timestamp provenance**
   For each timestamp, store:
   - raw source value;
   - source identifier and clock domain;
   - time zone and DST fold;
   - flooring, rounding, or quantization rule;
   - display-resolution uncertainty;
   - measured clock offset and its uncertainty;
   - correction method and software version;
   - original versus corrected value;
   - provenance and evidentiary strength.

3. **Capture source-clock telemetry continuously**
   - Record signed NTP/PTP offset estimates, uncertainty, sample age, and diagnostic quality.
   - Alert on stale or missing diagnostics.
   - Do not let a weak engineering estimate silently become an enforcement-grade bound.
   - Track whether events share a clock, allowing correlated-offset reasoning where justified.

4. **Make resolution semantics explicit**
   - Use machine-readable metadata such as `rounding=floor_minute`, `round_10_seconds`, or `precision_us=500`.
   - Distinguish measurement uncertainty from display quantization.
   - Avoid using “exact to displayed second” without retaining the ±0.5-second interpretation where applicable.

5. **Make DST handling mandatory**
   - Capture UTC offset and `fold=0/1` for ambiguous local times.
   - Reject or quarantine local timestamps lacking fold information when converted to UTC.
   - Preserve alternative UTC intervals until corroborating evidence resolves the ambiguity.

6. **Define lifecycle event semantics**
   - Explicitly distinguish request, start, completion, acknowledgment, and ingestion events.
   - SENSOR completion events should not be treated as starts.
   - For T-404-style missing starts, permit inferred starts only with a documented duration model, uncertainty, and provenance.
   - Never equate Alert_Sent with Alert_Received.

7. **Use causal and transactional identifiers**
   - Assign durable incident, alert-delivery, investigation, and containment identifiers.
   - Record causal links and monotonic transaction sequence where available.
   - Do not treat ingestion order as occurrence order unless the architecture guarantees it.

8. **Govern mobile entry separately**
   - Store both the displayed entry time and any device-generated event time.
   - Record whether entry delay represents:
     - late data entry only;
     - late occurrence;
     - or unknown semantics.
   - Flag manually entered timestamps as unsuitable for high-confidence enforcement unless corroborated.

9. **Separate SLA enforcement from process mining**
   - Treat the SLA as the operational/legal maximum.
   - Treat temporal profiles as statistical diagnostics.
   - A point in a profile band does not prove SLA compliance, and a profile deviation does not itself prove an SLA breach.
   - Do not use PM4Py point conformance as a substitute for timestamp-interval evidence.

10. **Adopt an explicit interval-overlap enforcement policy**
    A recommended policy is:
    - **CERTAIN_VIOLATION:** eligible for enforcement under the published rule.
    - **CERTAIN_PASS:** close the SLA timer.
    - **POSSIBLE_VIOLATION:** place in an evidence-review or precautionary-containment queue; do not assert a definitive breach without stronger evidence.
    - **INDETERMINATE:** escalate missing telemetry or lifecycle evidence rather than silently selecting a point timestamp.
    - Require source-quality thresholds before an interval can support disciplinary or contractual enforcement.

11. **Retain alternatives and revisions**
    - Store every normalization version and classification revision.
    - When new clock telemetry, fold information, or activity evidence arrives, recompute the interval and retain the superseded result for audit.
    - Publish both the original conclusion and the evidence change that caused reclassification.
