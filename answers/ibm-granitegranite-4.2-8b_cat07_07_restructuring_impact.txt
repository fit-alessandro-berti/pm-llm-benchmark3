5. **Diminished skill acquisition** – local caseworkers may defer all technical decisions to the shared service, slowing internal capability building; this effect is not captured by cycletime averages.  
6. **Accountability ambiguity** – when a case sits in the shared approval queue, staff may be unsure who makes the final decision, causing subtle delays and perceived unfairness that do not affect the mean cycle time.  
7. **Exceptionhandling variability** – adhoc crossteam transfers may reappear under pressure; the average may stay stable while occasional long handovers hurt specific teams and customers.

# 5. Pilot design
- **Pilot scope**: Deploy the Technical Shared Service and shared approval queue only for **Team North** (local caseworkers, intake, supervisor). Keep **Team South** unchanged as the control group; **Team East** remains observationonly (used for early signal checks).  
- **Comparison group**: South team continues the current embeddedspecialist model (local tech specialists N_Tech only, no shared queue). East is used for sanity checks on regional conventions but not as a control.  
- **Pre/post observation window**: 2weeks baseline (collect event logs under current model), followed by 8weeks pilot period (adjustment + measurement). Data collected continuously throughout.  
- **Segmentation within pilot**: Within North, split cases by (a) `case_complexity` (high vs medium), and (b) `required_specialty` (tech vs {legal, risk}). Track persegment metrics.  
- **Guardrail metrics** (must be satisfied each week to continue full rollout within North):  
  1. Median wait to Technical Shared Service 3h.  
  2. Central queue size 25 pending cases at any day start.  
  3. Specialist utilization 70%.  
  4. Rework rate 10%.  
  5. Maximum specialtycase wait 10h across teams.  
  6. Roleclarity survey score 4/5.  
  7. SLA miss rate 8%.  
- **Staff feedback collection**: short weekly pulse survey (3 questions on clarity, workload, fairness) and a brief focus group after week4. Capture qualitative notes on informal advice needs.  
- **Rollback / adjustment triggers** (if any guardrail breached for two consecutive weeks):  
  * Pause routing of highcomplexity cases to the Technical Shared Service for North; allow local tech specialist review for mediumcomplexity cases that have `local_expertise_flag=True`.  
  * Add a “localfirst” rule for cases with regional conventions (detected via `team` + `customer_segment`) to go directly to the local tech specialist unless `required_specialty` is legal/risk.  
  * If fairness metric (max specialty wait) exceeds 12h for >30% of specialty cases in North, temporarily increase the size of the legal/risk subqueue buffer (e.g., allow up to 5 extra pending cases) and monitor.  
  * If roleclarity survey score drops below 3.5/5 for two weeks, introduce a onepage “ownership guide” and retrain local caseworkers on queue status within the pilot.

# 6. Recommendation
Proceed **only with the pilot** described in Section5 for TeamNorth versus TeamSouth control. Continue monitoring the guardrail metrics weekly. If all guardrails are met for at least two consecutive weeks during the pilot, consider a phased rollout to the remaining teams (South then East) while keeping the guardrails active. If any guardrail is breached for two consecutive weeks, pause full routing to the shared service for the pilot team, apply the localfirst adjustment rule, and reassess before further expansion. **Management should not infer overall success from early average cycletime improvement alone; they must watch tail latency, specialtycase wait times, fairness gaps, roleclarity scores, and rework rates.** A stable or slightly lower average cycle time does not guarantee that the hidden risks (bottleneck queues, skill loss, fairness disparities) are absent.

def edge_freq(net):
    # net is a GraphVizlike object; count edges between local caseworker and Technical Shared Service
    count = 0
    for edge in net.edges:
        src, tgt = edge
        if "local caseworker" in src or "local caseworker" in tgt:
            if "Technical Shared Service" in src or "Technical Shared Service" in tgt:
                count += 1
    return count

freq_before = edge_freq(net_before)
freq_after  = edge_freq(net_after)

def median_wait_handover(log):
    # filter events that are handover concepts (local caseworker -> Technical Shared Service)
    handover_events = filter_event_attribute_values(log, {"concept:name": ["Local Caseworker", "Technical Shared Service"]})
    # compute waiting time between consecutive events for each case
    waits = []
    for case_id in handover_events['case']:
        case_events = handover_events[handover_events['case'] == case_id]
        case_events = case_events.sort_values('time:timestamp')
        for i in range(1, len(case_events)):
            wait = (case_events.iloc[i]['time:timestamp'] - case_events.iloc[i-1]['time:timestamp']).total_seconds() / 3600.0
            waits.append(wait)
    if waits:
        return sorted(waits)[len(waits)//2]  # approximate median
    return None

median_wait_before = median_wait_handover(log_before)

def check_guardrails(log, team):
    # queue size: count pending cases where org:resource == "Technical Shared Service" and concept:name == "pending"
    pending = filter_event_attribute_values(log, {"org:resource": "Technical Shared Service", "concept:name": "pending"})

    return {

        "specialist_util_%": util*100,
