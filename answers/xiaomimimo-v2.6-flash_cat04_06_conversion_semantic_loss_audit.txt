**Key observations:**

- **PetriTree**: Expected to fail. The cross-dependency structure (verification depends on Assess Risk *and* Prepare Evidence, while Legal Review depends only on Assess Risk) creates non-block-structured concurrency that process trees cannot represent without loss. Failure is the correct outcome.

# 5. Round-Trip Validation Code

```python
"""
Round-trip validation: compares net_from_powl with every round-tripped net
using soundness, footprints, reachability graph, bounded trace exploration,
positive/negative witness traces.
"""
from collections import deque
from pm4py.objects.petri_net.obj import PetriNet, Marking

#  Helper: fire a transition on a marking 
def fire_transition(marking, transition):
    """Return a new marking after firing `transition` from `marking`."""
    new_marking = dict(marking)
    for arc in transition.in_arcs:
        place = arc.source
        new_marking[place] = new_marking.get(place, 0) - 1
        if new_marking[place] <= 0:
            del new_marking[place]
    for arc in transition.out_arcs:
        place = arc.target
        new_marking[place] = new_marking.get(place, 0) + 1
    return new_marking

def mark_equal(m1, m2):
    """Compare two markings, ignoring zero-count entries."""
    d1 = {k: v for k, v in m1.items() if v > 0}
    d2 = {k: v for k, v in m2.items() if v > 0}
    return d1 == d2

#  Bounded visible-trace exploration 
def bounded_visible_traces(net, im, fm, max_visible=12, max_total_steps=60,
                           max_states=200000):
    """
    Exhaustively enumerate complete visible traces up to the stated bounds.

    Rules:
    - Transitions with label=None are hidden (tau).
    - A trace is complete only when the marking exactly equals fm (after
      normalizing zero-count places).
    - max_total_steps bounds every execution path (prevents infinite silent
      cycling).
    - max_visible bounds the visible-trace length.
    - max_states bounds total explored (marking, trace, step) tuples.

    Exhaustiveness: exhaustive under the combined bounds
    (max_visible, max_total_steps, max_states). If max_states is reached
    before the search space is exhausted, the result is incomplete.
    """
    results = set()
    queue = deque([(im, tuple(), 0)])
    explored = 0

    while queue:
        marking, trace, steps = queue.popleft()
        explored += 1
        if explored > max_states:
            print(f"  [bounded] State budget exhausted at {max_states} states.")
            break
        if steps >= max_total_steps:
            continue
        if len(trace) >= max_visible:
            continue

        # Exact final-marking check (normalized)
        if mark_equal(marking, fm):
            results.add(trace)
            continue

        enabled = pm4py.get_enabled_transitions(net, marking)
        for trans in enabled:
            new_marking = fire_transition(marking, trans)
            if trans.label is None:
                new_trace = trace  # hide tau
            else:
                new_trace = trace + (trans.label,)

            if len(new_trace) < max_visible and steps + 1 < max_total_steps:
                queue.append((new_marking, new_trace, steps + 1))

    return results, explored

#  Witness traces for the source model 
POSITIVE_WITNESSES = [
    # W1: Both orders of Assess Risk / Prepare Evidence; Legal Review present;
    #     1 iteration; Release; Archive
    ("Register Change", "Assess Risk", "Prepare Evidence", "Legal Review",
     "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"),
    # W2: Reversed Assess Risk / Prepare Evidence; no Legal Review (tau skip);
    #     2 iterations with Correct Defect between; Release; Archive
    ("Register Change", "Prepare Evidence", "Assess Risk",
     "Configure Trial", "Inspect Trial", "Correct Defect",
     "Configure Trial", "Inspect Trial",
     "Release Change", "Archive Change"),
    # W3: Prepare Evidence interleaves with Legal Review (unordered);
    #     single iteration
    ("Register Change", "Assess Risk", "Legal Review", "Prepare Evidence",
     "Configure Trial", "Inspect Trial", "Release Change", "Archive Change"),
]

NEGATIVE_WITNESSES = [
    # N1: Verification before Prepare Evidence (violates INV-07)
    ("Register Change", "Assess Risk",
     "Configure Trial", "Inspect Trial",
     "Prepare Evidence", "Release Change", "Archive Change"),
    # N2: Release before verification completes (violates INV-12)
    ("Register Change", "Assess Risk", "Prepare Evidence",
     "Release Change", "Archive Change"),
    # N3: No verification iteration (violates INV-10)
    ("Register Change", "Assess Risk", "Prepare Evidence",
     "Release Change", "Archive Change"),
    # N4: Archive before Release (violates INV-13)
    ("Register Change", "Assess Risk", "Prepare Evidence",
     "Archive Change", "Release Change"),
]

#  Comparison function 
def compare_nets(reference_name, reference_tuple,
                 candidate_name, candidate_tuple):
    """Compare a reference net against a candidate net on multiple criteria."""
    print(f"\n{'='*60}")
    print(f"Comparing: {reference_name}  vs  {candidate_name}")
    print(f"{'='*60}")

    ref_net, ref_im, ref_fm = reference_tuple
    cand_net, cand_im, cand_fm = candidate_tuple

    # 1. Soundness
    print("\n[1] Soundness")
    try:
        ref_is_wn = pm4py.check_is_workflow_net(ref_net)
        cand_is_wn = pm4py.check_is_workflow_net(cand_net)
        print(f"  {reference_name} workflow net: {ref_is_wn}")
        print(f"  {candidate_name} workflow net: {cand_is_wn}")
        if ref_is_wn and cand_is_wn:
            ref_sound = pm4py.check_soundness(ref_net, ref_im, ref_fm,
                                              print_diagnostics=False)
            cand_sound = pm4py.check_soundness(cand_net, cand_im, cand_fm,
                                               print_diagnostics=False)
            print(f"  {reference_name} sound: {ref_sound}")
            print(f"  {candidate_name} sound: {cand_sound}")
        else:
            print("  Soundness skipped for non-workflow net.")
    except Exception as e:
        print(f"  Soundness check raised: {e}")

    # 2. Footprints
    print("\n[2] Footprints")
    try:
        ref_fp = pm4py.discover_footprints(ref_net, ref_im, ref_fm)
        cand_fp = pm4py.discover_footprints(cand_net, cand_im, cand_fm)
        print(f"  {reference_name} footprint count: {len(ref_fp)}")
        print(f"  {candidate_name} footprint count: {len(cand_fp)}")
        if ref_fp == cand_fp:
            print("  FOOTPRINTS MATCH: exact equality.")
        else:
            missing = ref_fp - cand_fp
            extra = cand_fp - ref_fp
            print(f"  FOOTPRINTS DIFFER.")
            print(f"    Missing in candidate: {len(missing)}")
            for fp in list(missing)[:10]:
                print(f"      - {fp}")
            print(f"    Extra in candidate: {len(extra)}")
            for fp in list(extra)[:10]:
                print(f"      + {fp}")
    except Exception as e:
        print(f"  Footprint discovery raised: {e}")

    # 3. Reachability graph
    print("\n[3] Reachability graph")
    try:
        ref_rg = pm4py.convert_to_reachability_graph(ref_net, ref_im, ref_fm)
        cand_rg = pm4py.convert_to_reachability_graph(cand_net, cand_im, cand_fm)
        ref_states = len(ref_rg.transitions)
        cand_states = len(cand_rg.transitions)
        print(f"  {reference_name} reachability transitions: {ref_states}")
        print(f"  {candidate_name} reachability transitions: {cand_states}")
        if ref_states == cand_states:
            print("  Reachability graph sizes match (same # transitions).")
        else:
            print(f"  Reachability graph sizes DIFFER "
                  f"(delta: {cand_states - ref_states}).")
    except Exception as e:
        print(f"  Reachability graph conversion raised: {e}")

    # 4. Bounded visible-trace exploration
    print("\n[4] Bounded visible-trace exploration")
    print("    Bounds: max_visible=12, max_total_steps=60, max_states=200000")
    print("    Exhaustive under these bounds (state budget permitting).")
    try:
        ref_traces, ref_explored = bounded_visible_traces(
            ref_net, ref_im, ref_fm, max_visible=12, max_total_steps=60,
            max_states=200000)
        print(f"  {reference_name}: {len(ref_traces)} distinct complete "
              f"visible traces (explored {ref_explored} states)")
    except Exception as e:
        print(f"  Reference trace exploration raised: {e}")
        ref_traces = set()

    try:
        cand_traces, cand_explored = bounded_visible_traces(
            cand_net, cand_im, cand_fm, max_visible=12, max_total_steps=60,
            max_states=200000)
        print(f"  {candidate_name}: {len(cand_traces)} distinct complete "
              f"visible traces (explored {cand_explored} states)")
    except Exception as e:
        print(f"  Candidate trace exploration raised: {e}")
        cand_traces = set()

    if ref_traces and cand_traces:
        if ref_traces == cand_traces:
            print("  TRACES MATCH: exact equality within bounds.")
        else:
            missing_tr = ref_traces - cand_traces
            extra_tr = cand_traces - ref_traces
            print(f"  TRACES DIFFER: {len(missing_tr)} missing, "
                  f"{len(extra_tr)} extra in candidate.")
            for t in list(missing_tr)[:5]:
                print(f"    MISSING: {t}")
            for t in list(extra_tr)[:5]:
                print(f"    EXTRA:   {t}")

    # 5. Positive witness traces
    print("\n[5] Positive witness traces")
    try:
        ref_traces_set, _ = bounded_visible_traces(ref_net, ref_im, ref_fm,
                                                    max_visible=15,
                                                    max_total_steps=70,
                                                    max_states=200000)
        cand_traces_set, _ = bounded_visible_traces(cand_net, cand_im, cand_fm,
                                                     max_visible=15,
                                                     max_total_steps=70,
                                                     max_states=200000)
    except Exception:
        ref_traces_set = set()
        cand_traces_set = set()

    for i, witness in enumerate(POSITIVE_WITNESSES):
        in_ref = witness in ref_traces_set
        in_cand = witness in cand_traces_set
        status = "OK" if in_ref and in_cand else "FAIL"
        print(f"  W{i+1} [{status}] ref={in_ref} cand={in_cand}: {witness}")

    # 6. Negative witness traces (should NOT be present)
    print("\n[6] Negative witness traces (should be absent)")
    for i, witness in enumerate(NEGATIVE_WITNESSES):
        in_ref = witness in ref_traces_set
        in_cand = witness in cand_traces_set
        status = "OK" if not in_ref and not in_cand else "FAIL"
        print(f"  N{i+1} [{status}] ref_present={in_ref} "
              f"cand_present={in_cand}: {witness}")

    print(f"\n{'='*60}\n")

#  Run comparisons 
reference = ("net_from_powl", (net_from_powl, im_from_powl, fm_from_powl))

for rt_name, rt_tuple in roundtrip_nets.items():
    compare_nets(reference[0], reference[1], rt_name, rt_tuple)

print("Round-trip validation complete.")
print("NOTE: Bounded exploration is exhaustive only within the stated bounds "
      "(max_visible, max_total_steps, max_states).")
```

**Bounded exploration notes:**

- Hides transitions whose `label is None`.
- Requires **exact** final-marking equality (normalized: zero-count entries removed) for a trace to be recorded as complete.
- `max_total_steps` bounds every execution path, preventing infinite silent (tau) cycling.
- `max_visible` bounds visible-trace length.
- `max_states` bounds the total number of explored `(marking, trace, step)` tuples.
- **Exhaustive under the combined bounds** `(max_visible=12, max_total_steps=60, max_states=200000)`. If the state budget is reached before the queue is drained, results are **partial** and the function reports this.

# 6. Visual-Semantics Review

The BPMN rendering (`viz_bpmn_primary.png`) can be behaviorally sound at the net level while being **visually misleading** to a human reader. The following risks are distinct from actual behavioral loss:

## 6.1 Parallel gateways (concurrency)

The source has three unordered pairs: (Assess Risk  Prepare Evidence), (Prepare Evidence  Legal Review), (Legal Review  verification loop). BPMN represents AND-splits/merges with parallel gateways (diamond with a plus sign). However:

- **Layout direction**: Most graph-layout algorithms (and PM4Py's default) render flows left-to-right. If Prepare Evidence and Legal Review are placed on parallel branches, the layout may imply that Prepare Evidence is "above" or "before" Legal Review even though they are unordered. A reader could mistake layout for causality.
- **Gateway overlap**: If the AND-join before Release Change and the AND-split before the middle section are close together, the rendered graph may look like a simple sequence rather than concurrency.

## 6.2 Exclusive gateways (optionality)

The XOR of Legal Review and a silent transition maps to an exclusive gateway with two outgoing edges. Risks:

- The **skip path** (originally a `SilentTransition`) may render as a line with no visible activity, which a reader may mistake for a missing activity or a rendering error rather than an intentional skip.
- If the exclusive gateway's label (or diamond icon) is small, readers may confuse it with a parallel gateway.

## 6.3 Loop visualization

The verification loop (`LOOP(trial_body, correct_defect)`) maps to a back-edge in BPMN. Risks:

- **Placement of the decision point**: If the exclusive gateway controlling the loop-back is placed **before** the loop body (check-then-act), the rendering suggests zero iterations are possible, violating INV-10 (at least one iteration). The correct placement is **after** the body (act-then-check), but layouts do not guarantee this.
- **Back-edge visibility**: A backward arrow in a dense diagram may be hard to trace. Readers may not follow it correctly and could miss that Correct Defect feeds back into Configure Trial.
- The relationship between Correct Defect and the loop body may be misread as: Correct Defect is an alternative to Configure Trial, rather than a mandatory separator between iterations.

## 6.4 Silent routing nodes

Silent transitions (tau) in BPMN become routing nodes with no label. These are invisible in the rendered image if the renderer draws only tasks. The exclusive gateway for optional Legal Review relies on the presence of two edges from one gateway; if one edge is "empty," the rendering may show only one path, making Legal Review appear mandatory.

## 6.5 Apparent ordering of graph layout

Graph layout imposes a spatial ordering even when the model has no such order. For example:

- If Legal Review is drawn above the verification loop, a reader may infer it happens first.
- If Configure Trial and Inspect Trial are drawn left-to-right within the loop body, the apparent order is correct (INV-09), but if the layout engine places them vertically, the reading order may be ambiguous (top-to-bottom vs. left-to-right).

## 6.6 Recommended annotations and documentation

| Ambiguity | Annotation / Documentation |
|---|---|
| Concurrency vs. sequence | Add a legend: "Parallel gateway (diamond with +) means unordered — both branches may execute in any order or overlap." Add a note: "Graph layout direction does not imply causality." |
| Optional Legal Review | Label the skip path explicitly: "Skip Legal Review (default)" or annotate the XOR gateway: "Legal Review optional." |
| Loop iteration guarantee | Add a note near the loop gateway: "At least one verification iteration is required. Correct Defect separates iterations." |
| Silent nodes | Optionally replace silent routing nodes with a labeled task named "Skip" or "No Action" so the optionality is visible. |
| Final marking | Annotate the end event: "All branches must complete before Release Change." |

# 7. Rejection Criteria

A conversion result should be **rejected** or **quarantined** (excluded from downstream use pending investigation) if any of the following conditions holds:

1. **Unsoundness**: Any accepting Petri net fails `pm4py.check_soundness(net, im, fm)`. This indicates deadlocks, improper termination, or lack of proper completion — the model does not faithfully represent a well-formed process.

2. **Loss of required interleaving**: The round-trip BPMNPetri net exploration cannot produce a visible trace where Prepare Evidence and Assess Risk appear in **both** orders (INV-02 violation). If only one ordering is possible, concurrency has collapsed to sequence.

3. **Admission of Release before verification**: A negative witness trace such as `Register, Assess Risk, Prepare Evidence, Release, Archive` (without any verification activity) is found in the round-tripped net. This violates INV-10 and INV-12.

4. **Collapse of optional behavior**: The round-trip net cannot produce both a trace containing `Legal Review` and a trace omitting `Legal Review` (INV-04 violation). This means the XOR-with-silent structure was lost.

5. **Failed exact-final-marking test**: During bounded exploration, completed traces reach a marking that does **not** exactly equal the expected final marking (after normalizing zero-count places). This means some tokens are left unconsumed or extra tokens are produced — the finality invariant (INV-13) is broken.

6. **Footprint mismatch**: `pm4py.discover_footprints(net, im, fm)` for the round-tripped net differs from the reference footprint set. Missing footprints mean lost ordering relationships; extra footprints mean new (incorrect) ordering constraints were introduced.

7. **Label loss or duplication**: The set of visible labels in the round-tripped net differs from the source's 9 unique labels. Missing labels indicate activities were dropped; duplicate labels (or labels with added suffixes) indicate renaming that breaks trace-level comparison.

8. **Non-workflow net result**: The round-tripped net fails `pm4py.check_is_workflow_net(net)`, indicating the conversion produced a net without a single source/sink structure — structurally invalid for BPMN process interpretation.

9. **Loop minimum-iteration violation**: The round-tripped net allows a complete visible trace with zero occurrences of both `Configure Trial` and `Inspect Trial`, violating INV-10 (at least one verification iteration).

10. **Process-tree silent success without footprint validation**: If `convert_to_process_tree` succeeds, the resulting tree is **not** automatically accepted. It must pass footprint comparison against the source Petri net. If footprints differ, the tree introduced or removed ordering and must be quarantined.

# 8. Canonical Representation Recommendation

## 8.1 Authoritative representation

**The POWL model (`source_powl`) is the authoritative, canonical representation for storage.**

Rationale:
- POWL directly expresses partial order, optionality, and loop structure without ambiguity.
- It is machine-readable (Python object) and can be re-serialized without layout-dependent interpretation.
- It does not suffer from the visual-layout ambiguity that affects BPMN.
- All other representations (Petri net, BPMN, process tree) are **derived** from it.

## 8.2 Stakeholder visualization

**BPMN (generated via the primary pipeline: POWL  Petri net  BPMN) is the visualization model.**

Rationale:
- BPMN is the lingua franca for business stakeholders and process analysts.
- It provides familiar gateways, events, and activities.
- It must be accompanied by annotations (Section 6.6) and the invariant table (Section 1) to counter layout ambiguity.

## 8.3 Derivative artifacts and validation evidence

| Artifact | Status | Required validation evidence |
|---|---|---|
| POWL (`source_powl`) | **Canonical / authoritative** | Self-contained; source of truth. |
| Petri net from POWL | Derivative | Must pass workflow-net check and soundness check. Bounded trace exploration should confirm all positive witnesses present and all negative witnesses absent. |
| BPMN from Petri net | Derivative (visualization) | Must round-trip back to Petri net; round-tripped net must match footprints, pass soundness, and produce identical bounded traces within bounds. |
| Process tree (if obtained) | Derivative (conditional) | Must not be accepted without footprint equality against the source net. If conversion fails, record the failure as evidence of non-block-structuredness. |
| Round-tripped Petri nets | Derivative (audit artifacts) | All diagnostics from Section 5. |

## 8.4 Process-tree intermediate

**A process-tree intermediate should be allowed only as a diagnostic, not as a storage format.**

- If `convert_to_process_tree` succeeds, the tree must be footprint-compared against the source net. If footprints match, the tree may be used for visualization (it often renders more cleanly than a Petri-net-derived BPMN).
- If footprints differ or conversion fails, the tree must not be used. The failure itself is diagnostic: it confirms the source is not block-structured.
- The tree must **never** be the stored canonical model, because it may have introduced silent transitions or reordered structure to force block-structuring.

## 8.5 Avoiding round-trip drift

1. **Never edit the Petri net, BPMN, or process tree directly.** All edits originate in the POWL model, then regenerate all derivatives.
2. **Regeneration pipeline must be idempotent**: Running the conversion twice from the same POWL must produce identical derivatives (or differences explainable by nondeterministic layout only).
3. **Automated CI check**: On every POWL change, run the full Section 5 validation suite. Reject merges if any rejection criterion (Section 7) triggers.
4. **Pin PM4Py version**: Conversion behavior may change across PM4Py versions. Record the version in the validation report.

# 9. Residual Uncertainty

Even if every test in Sections 4–5 passes, the following claims **cannot** be established:

1. **Unbounded behavioral equivalence**: The bounded trace exploration is exhaustive only within `(max_visible, max_total_steps, max_states)`. For traces exceeding these bounds — for example, a loop executing more than `max_visible` iterations — equivalence is not verified. The source model allows unbounded loop iterations (the LOOP operator has no built-in iteration count), so no finite bound can cover all possible executions.

2. **Layout-semantics alignment in BPMN**: Even if the underlying converted net is behaviorally sound, the rendered BPMN image's visual layout is determined by a graph-layout algorithm (typically Sugiyama or similar). This algorithm may impose apparent ordering on unordered branches, place gateways in misleading positions, or draw back-edges in ways that obscure the loop. No Petri-net-level test can validate that a human reading the rendered image will correctly interpret the intended semantics. This is a **human-factors** claim outside the scope of automated testing.

3. **Semantic equivalence of the source's authorial intent**: The invariant table in Section 1 captures what the code *structurally encodes*. It cannot establish whether the POWL model correctly represents the real-world business process it is intended to model. For instance, the model encodes "Legal Review is optional," but it cannot verify that legal review is truly optional in the organization's policy. This is a domain-validation claim requiring external expert review.

4. **Soundness of exotic PM4Py internal conversion strategies**: PM4Py's POWLPetri net converter may use specific structural strategies (e.g., how it handles nested LOOP operators with partial-order children).
