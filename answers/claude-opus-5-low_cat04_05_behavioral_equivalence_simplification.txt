# 1. Equivalence Notions

Throughout, `L_vis(M)` denotes the set of **complete** visible traces of model `M`: sequences of labels of the visible transitions fired on a run from the initial marking to the final marking of the accepting Petri net obtained from the tree, with all `tau` (silent) steps deleted from the sequence.

**N0 — label discipline (asked explicitly).** Neither model contains duplicate labels: each of `Open Case`, `Analyze Revision`, `Check Revision`, `Approve Revision`, `Rework Case`, `Close Case` appears exactly once as a leaf in each tree. However, the loop makes *occurrences* repeat at runtime. All four notions below compare traces **by label only**; two occurrences of `Check Revision` are indistinguishable as symbols. Occurrence *position* matters only in the sense that a trace is a sequence, so position is encoded in the word, not in the identity of the symbol. No notion below uses transition identity. This matters: under a label-only reading, "the check that belongs to attempt 2" is not an observable object — it must be reconstructed from position, which is exactly what P1 does and what P2 refuses to do.

**N1 — visible trace equivalence after hiding `tau`.**
`A ≡_trace B  ⟺  L_vis(A) = L_vis(B)`.
This is *language* equivalence, not bisimulation: branching structure, moment of choice, and concurrency-vs-interleaving are invisible. It is the strictest notion used here.

**N2 — bounded visible-language equivalence (P3).**
Let `Λ(M, k, m) = { σ ∈ L_vis(M) : |σ| ≤ k and #(σ, 'Analyze Revision') ≤ m }`, with `k = 12`, `m = 3`.
`A ≡_bounded B  ⟺  Λ(A,12,3) = Λ(B,12,3)`.
Because both models can generate unboundedly long traces (unbounded loop), `≡_bounded` is a *necessary* condition for `≡_trace` but never sufficient. A bounded mismatch **disproves** N1; a bounded match only fails to disprove it.

**N3 — business-relevant equivalence (P1).**
Define, for a visible trace `σ`, the projection onto the compliance-relevant alphabet and the predicate:

`COMPLIANT_P1(σ)` holds iff, writing `σ` restricted to `{Analyze Revision, Check Revision, Rework Case, Close Case}` as a word `w`, every occurrence of `Analyze Revision` in `w` is followed by at least one `Check Revision` **before** the next `Rework Case` or, for the last attempt, before `Close Case`, and no `Check Revision` is "reused" by two attempts (i.e. the count of checks in each inter-`Rework` segment is ≥ 1, matched one-to-one against the analyses in that segment).

Define the P1 observation of a trace as
`obs_P1(σ) = ( segments(σ), per-segment (#Analyze, #Check), positions of Approve Revision )`,
where `segments` splits `σ` at `Rework Case`. P1 keeps approvals visible ("number and placement of approvals remains visible and potentially relevant"), so `obs_P1` is close to the identity on visible traces; it abstracts only from the *relative order* of `Analyze Revision` and `Check Revision` inside one segment (P1 states the requirement as "its own check before the next Rework/Close", not "after the analyze"). Under a stricter reading in which the check must *follow* its analysis, the verdict below only gets worse for B, never better.
`A ≡_P1 B  ⟺  obs_P1(L_vis(A)) = obs_P1(L_vis(B))`.

**N4 — abstracted dashboard equivalence (P2).**
Define the abstraction map
`α(σ) = ( first(σ) = 'Open Case', last(σ) = 'Close Case', n = #(σ,'Analyze Revision'), checkOccurred = [#(σ,'Check Revision') ≥ 1], reworkOccurred = [#(σ,'Rework Case') ≥ 1] )`,
with `Approve Revision` and all `tau` deleted, and repeated `Check Revision` collapsed to a Boolean.
`A ≡_P2 B  ⟺  α(L_vis(A)) = α(L_vis(B))`.
Note `α` deliberately destroys the interleaving of `Analyze Revision` and `Check Revision`, the check *multiplicity*, and every approval — i.e. exactly the three dimensions on which A and B differ.

# 2. Structural Comparison

First, the runtime shape of each model (binary-loop semantics: body once; then optionally redo + body again; repeat).

*Model A*, for `n ≥ 1` iterations, generates
`Open Case · X_1 · Rework Case · X_2 · Rework Case · … · X_n · Close Case`,
where each `X_i` is an interleaving of `Analyze Revision` and `Check Revision` (2 orders), optionally followed by `Approve Revision`. Hence **#Check = #Analyze = n** and every check sits in its own iteration, always *before* that iteration's approval.

*Model B*, for `n ≥ 1` iterations, generates any interleaving of the single symbol `Check Revision` with the word
`Analyze Revision·[Approve Revision] · Rework Case · Analyze Revision·[Approve Revision] · … `,
all between `Open Case` and `Close Case`. Hence **#Check = 1** regardless of `n`, and the check may fall anywhere strictly between `Open Case` and `Close Case`, including after an approval, after a `Rework Case`, or after the last approval.

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | Loop body = `->( +(Analyze, Check), X(Approve, tau) )`; the check is **inside** the repeated body | Loop body = `->( Analyze, X(Approve, tau) )`; the check is **outside**, in parallel with the whole loop | The repetition operator distributes over the check in A and not in B — this is the single root cause of every difference below |
| Minimum `Check Revision` occurrences | 1 (when `n = 1`) | 1 (always) | Minima agree; both satisfy "at least one check" |
| Maximum `Check Revision` occurrences | Unbounded; exactly `n` (= number of analyses) | Exactly 1, always | Check multiplicity is a *function of n* in A and a *constant* in B → languages differ for every `n ≥ 2` |
| Possible placement of `Check Revision` | Only inside iteration `i`, adjacent to `Analyze Revision` of that iteration and strictly before that iteration's optional `Approve Revision` | Anywhere strictly between `Open Case` and `Close Case`: before the first analysis, between an approval and a rework, after the last approval, etc. | B admits placements A forbids (e.g. after an `Approve Revision`) |
| Optional approval occurrences | 0..n approvals, one optional per iteration, each after that iteration's `+(Analyze, Check)` block | 0..n approvals, one optional per iteration, each after that iteration's `Analyze Revision`, but *not* synchronised with the check | Same approval *count* profile in both; different approval-vs-check ordering |
| Concurrency | `+` is local: `Analyze ∥ Check` inside one iteration only; concurrency scope = one attempt | `+` is global: `Check ∥ (whole loop)`; concurrency scope = the entire revision phase | A's parallelism yields 2 orders per iteration; B's yields `2n+1`-ish insertion points for one check |
| Join before `Close Case` | The AND-join is *inside* the loop; the loop must be exited (silent exit) before `Close Case`; no cross-iteration synchronisation | The AND-join synchronises the single check with loop termination; `Close Case` waits for **both** the check and the loop exit | In B the check may legitimately be the *last* visible event before `Close Case`, even after all analyses and approvals; impossible in A |
| Silent leaves | 1 (`tau` in the approval XOR) + loop-exit silence introduced by the Petri-net conversion | 1 (`tau` in the approval XOR) + loop-exit silence + AND-split/join silence | `tau` never appears in visible traces, but it makes "optional approval" a *branching* difference, not a language difference |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| N1 — visible trace equivalence (unrestricted) | **not equivalent** | Very high (proved) | Check multiplicity: `L_vis(A)` forces `#Check = #Analyze`; `L_vis(B)` forces `#Check = 1`. Any trace with `n ≥ 2` separates them (T1, T2). Conversely B admits a check *after* an approval, which A cannot produce (T3, T4). Both inclusions fail. | The two languages are not disjoint: they coincide exactly on the four single-attempt traces listed in §4, so a test suite that never reworks will see no difference |
| P1 — operational compliance | **not equivalent** | Very high | P1 demands "every analysis revision must have its own Check Revision before the next Rework Case or before Close Case". In B, for `n = 2`, the segment before the first `Rework Case` may contain zero checks. B *violates the P1 norm itself*, so it cannot be P1-equivalent to A, which satisfies it by construction | If one weakens P1 to "at least one check occurred in the case", the verdict flips to equivalent — but that weakened rule is precisely P2, not P1 |
| P2 — executive dashboard | **equivalent only under stated abstraction** | High | `α` records only (Open first, Close last, `n`, checkOccurred, reworkOccurred). Both models yield exactly `{ (true, true, n, true, n ≥ 2) : n ≥ 1 }`. Both force `n ≥ 1`, both force `≥ 1` check, both make rework occur iff `n ≥ 2`, both fix `Open Case` first and `Close Case` last. Interleaving, check multiplicity and approvals — the only differences — are all destroyed by `α` | The equivalence is an artefact of the abstraction. Any dashboard change that un-collapses check counts (e.g. "checks per case", "check-to-analysis ratio") breaks it immediately. Also, `α` is not a bisimulation-compatible abstraction: it is a per-trace projection, so it says nothing about the models' behaviour under composition |
| P3 — bounded testing (≤ 12 visible events, ≤ 3 analyses) | **not equivalent** | Very high | All four counterexamples in §4 have length ≤ 8 and ≤ 2 analyses, so they sit strictly inside the P3 window. A single witness inside the bound refutes bounded equivalence, and refutation inside a bound *is* conclusive for N1 as well | The converse never holds: had the bounded sets matched, that would have been evidence only. Here the bound is generous enough that the difference is unmissable — a much tighter bound (≤ 5 events, ≤ 1 analysis) would have shown A ⊆ B and missed the multiplicity difference entirely |

**Summary of the inclusion structure.** Neither `L_vis(A) ⊆ L_vis(B)` nor `L_vis(B) ⊆ L_vis(A)` holds. Their intersection is exactly the single-attempt language

`L_vis(A) ∩ L_vis(B) = { Open·A·C·Close, Open·C·A·Close, Open·A·C·Ap·Close, Open·C·A·Ap·Close }`

(writing `A = Analyze Revision`, `C = Check Revision`, `Ap = Approve Revision`).
*Proof.* Any `σ` in the intersection has `#C = #A` (from A) and `#C = 1` (from B), hence `#A = #C = 1`, hence `n = 1` and no `Rework Case`. For `n = 1`, A's traces are `Open · {AC, CA} · [Ap] · Close`, all four of which B admits (insert its single check before or after `A`, both being valid interleavings of `C` with `A·[Ap]`). B's `n = 1` traces additionally include `Open·A·Ap·C·Close`, which A excludes. ∎

# 4. Counterexample Traces

Abbreviations: `O = Open Case`, `A = Analyze Revision`, `C = Check Revision`, `Ap = Approve Revision`, `R = Rework Case`, `Cl = Close Case`.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| T1 | `O, A, C, R, A, C, Cl` (7 events, 2 analyses) | **accepted** (2 iterations, each `A·C`, no approvals) | **rejected** | At the 6th event, the second `C`: B's single `Check Revision` transition already fired at position 3 and cannot fire again — the check is outside the loop | N1, P1, P3 |
| T2 | `O, C, A, Ap, R, A, C, Ap, Cl` (9 events, 2 analyses) | **accepted** (iter 1 = `C·A·Ap`, iter 2 = `A·C·Ap`) | **rejected** | At the 7th event, the second `C`: same token exhaustion as T1; also shows A can vary the intra-iteration order per iteration | N1, P1, P3 |
| T3 | `O, A, Ap, C, Cl` (5 events, 1 analysis) | **rejected** | **accepted** (check delayed past the whole loop) | At the 4th event, `C` after `Ap`: in A the AND-join `+(A,C)` must complete *before* the approval XOR is reached, so no check can follow an approval within an iteration, and the loop has already exited | N1, P3 (invisible to P1's norm-check but visible to `obs_P1`) |
| T4 | `O, A, Ap, R, A, Ap, C, Cl` (8 events, 2 analyses) | **rejected** | **accepted** (one check, fired last) | At the 3rd event, `Ap` with no preceding `C`: A cannot reach the approval XOR of iteration 1 without having fired that iteration's `Check Revision`. The first attempt is approved and reworked with **no check at all** | N1, **P1 (the compliance breach)**, P3 |
| T5 (shared, for calibration) | `O, A, C, Ap, Cl` | accepted | accepted | none — inside the intersection | shows why a 1-attempt test suite is blind |

**Two analysis attempts.** T1, T2 and T4 each contain two `Analyze Revision` occurrences, satisfying the requirement; T1/T2 are the A-only witnesses and T4 is the B-only witness at `n = 2`.

**Why A-only witnesses need two attempts.** As proved in §3, `L_vis(A)` restricted to `n = 1` is a *subset* of `L_vis(B)`. So no single-attempt trace can be an A-only witness; the weakest A-only witnesses are exactly the `n = 2` traces, of which T1 is the shortest (7 events). This is the sharpest possible statement of the asymmetry: A ⊆ B fails only via check multiplicity, and multiplicity only becomes observable once the loop repeats.

**Effect of the optional `Approve Revision`.** Optionality *widens* both languages symmetrically (each iteration independently emits `Ap` or nothing) and therefore does **not** by itself create any difference: deleting `Ap` from T1–T4 leaves T1 and T3' = `O,A,C,Cl` — and T3' is in *both* languages. So the approval is not the source of the mismatch; it is an *amplifier*. Its real role is in T3/T4, where it acts as a **positional marker** that exposes B's late check: without an approval, a trailing check in B is indistinguishable from an in-iteration check, because `O,A,C,Cl` is ambiguous. The optional approval is what makes "the check came after the approval" an observable event, and hence what turns a branching difference into a language difference.

**Effect of hidden `tau`.** The `tau` in `X(Approve Revision, tau)` and the silent loop-exit / AND-routing transitions never appear in a visible trace, so they cannot themselves distinguish the models. What they do is (i) make the two models fail to be *branching/weak-bisimilar* even where their languages coincide — e.g. on the shared trace `O,A,C,Cl`, A has already committed to skipping approval when the loop exits, while B may still owe a check — and (ii) make the bounded exploration in §5 non-trivial: a naive BFS that counts silent steps against the length bound, or that dedupes markings without accounting for the visible prefix, will produce wrong answers. Hiding `tau` is therefore an assumption about the *logging* system, not a neutral simplification: if the log recorded an "auto-approval" event, T3 vs `O,A,tau,C,Cl` would separate the models even more sharply.

# 5. Bounded Comparison Code

The script below is exhaustive within the P3 bound (it enumerates every complete visible trace with ≤ 12 visible events and ≤ 3 `Analyze Revision` occurrences), and it separately runs a random playout to make the contrast between the two methods explicit.

```python
"""
Bounded behavioural comparison of Model A and Model B.

EXHAUSTIVE part : breadth-first exploration over Petri-net markings with an
                  explicit visible-length bound. Complete for the P3 window.
HEURISTIC part  : pm4py.play_out sampling. NOT exhaustive - shown only to
                  demonstrate that sampling can silently miss the witnesses.
"""

from collections import Counter, deque
import pm4py

MODEL_A = """
->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
"""

MODEL_B = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)
"""

MAX_VISIBLE = 3          # P3: at most 12 visible events
MAX_ANALYZE = 3           # P3: at most 3 'Analyze Revision'
ANALYZE = 'Analyze Revision'
MAX_VISIBLE = 12          # (re-stated; the line above is intentionally overwritten)


# ---------------------------------------------------------------- 1. parsing
def build(tree_string, name):
    tree = pm4py.parse_process_tree(tree_string)
    net, im, fm = pm4py.convert_to_petri_net(tree)          # 2. accepting net
    print(f"--- {name}: soundness ---")
    pm4py.check_soundness(net, im, fm, print_diagnostics=True)  # 3. soundness
    return tree, net, im, fm


# ------------------------------------------- marking helpers (hashable form)
def marking_key(marking):
    """Marking -> canonical hashable tuple (place name, token count)."""
    return tuple(sorted((p.name, c) for p, c in marking.items() if c > 0))


def fire(marking, t):
    """Return the marking obtained by firing t. Arc weights honoured."""
    new = Counter(marking)
    for arc in t.in_arcs:
        new[arc.source] -= arc.weight
        if new[arc.source] <= 0:
            del new[arc.source]
    for arc in t.out_arcs:
        new[arc.target] += arc.weight
    return new


def enabled(net, marking):
    """Wrapper around the pm4py API; falls back to a manual check."""
    try:
        from pm4py.objects.petri_net.obj import Marking
        m = Marking()
        for p, c in marking.items():
            m[p] = c
        return list(pm4py.get_enabled_transitions(net, m))
    except Exception:
        out = []
        for t in net.transitions:
            if all(marking.get(a.source, 0) >= a.weight for a in t.in_arcs):
                out.append(t)
        return out


# --------------------------------------- 4./5. EXHAUSTIVE bounded exploration
def bounded_language(net, im, fm, max_visible=MAX_VISIBLE, max_analyze=MAX_ANALYZE,
                     max_silent_run=40):
    """
    Every complete visible trace sigma with |sigma| <= max_visible and
    #(sigma, ANALYZE) <= max_analyze.

    Explicit handling of the four traps:
      * silent transitions   -> fired but NOT appended to the trace and NOT
                                counted against the visible bound;
      * repeated markings    -> the visited set is keyed on the PAIR
                                (marking, visible trace), never on the marking
                                alone, because the same marking is reachable
                                with different visible histories (the loop!);
      * visible-length bound -> pruned at generation time, so the search space
                                stays finite despite the unbounded loop;
      * final-marking equality -> a trace is emitted only when the marking is
                                EXACTLY fm (not >= fm), i.e. proper completion.
    The extra `max_silent_run` guard bounds runs of consecutive tau steps so a
    silent cycle (none exists here, but conversions can create one) cannot
    diverge.
    """
    fm_key = marking_key(fm)
    start = Counter({p: c for p, c in im.items() if c > 0})

    language = set()
    seen = {(marking_key(start), (), 0)}
    queue = deque([(start, (), 0)])          # (marking, visible trace, silent run)

    while queue:
        marking, trace, srun = queue.popleft()

        if marking_key(marking) == fm_key:
            language.add(trace)
            # do not `continue`: in general a final marking may be left again;
            # here it cannot, but the code stays correct for other nets.

        for t in enabled(net, marking):
            nxt = fire(marking, t)
            if t.label is None:                        # silent transition
                if srun >= max_silent_run:
                    continue
                new_trace, new_srun = trace, srun + 1
            else:                                      # visible transition
                if len(trace) + 1 > max_visible:
                    continue
                if t.label == ANALYZE and trace.count(ANALYZE) + 1 > max_analyze:
                    continue
                new_trace, new_srun = trace + (t.label,), 0
            key = (marking_key(nxt), new_trace, new_srun)
            if key not in seen:
                seen.add(key)
                queue.append((nxt, new_trace, new_srun))

    return language


# --------------------------------------------------------- 6. report + 7. contrast
def main():
    tree_a, net_a, im_a, fm_a = build(MODEL_A, "Model A")
    tree_b, net_b, im_b, fm_b = build(MODEL_B, "Model B")

    print("\n=== EXHAUSTIVE bounded exploration (complete for the P3 window) ===")
    la = bounded_language(net_a, im_a, fm_a)
    lb = bounded_language(net_b, im_b, fm_b)
    print(f"|L_A| within bound = {len(la)}")
    print(f"|L_B| within bound = {len(lb)}")
    print(f"shared             = {len(la & lb)}")

    only_a = sorted(la - lb, key=lambda s: (len(s), s))
    only_b = sorted(lb - la, key=lambda s: (len(s), s))

    print(f"\n--- {len(only_a)} traces in A but NOT in B (showing 10 shortest) ---")
    for s in only_a[:10]:
        print("  ", " -> ".join(s))
    print(f"\n--- {len(only_b)} traces in B but NOT in A (showing 10 shortest) ---")
    for s in only_b[:10]:
        print("  ", " -> ".join(s))

    verdict = "EQUIVALENT within the P3 bound" if la == lb else "NOT equivalent (bounded witness found)"
    print(f"\nP3 verdict: {verdict}")
    print("A bounded MISMATCH disproves unbounded trace equivalence.")
    print("A bounded MATCH would prove nothing about traces outside the bound.")

    # explicit check of the four hand-derived counterexamples
    T = {
        "T1": ('Open Case', 'Analyze Revision', 'Check Revision', 'Rework Case',
               'Analyze Revision', 'Check Revision', 'Close Case'),
        "T2": ('Open Case', 'Check Revision', 'Analyze Revision', 'Approve Revision',
               'Rework Case', 'Analyze Revision', 'Check Revision',
               'Approve Revision', 'Close Case'),
        "T3": ('Open Case', 'Analyze Revision', 'Approve Revision',
               'Check Revision', 'Close Case'),
        "T4": ('Open Case', 'Analyze Revision', 'Approve Revision', 'Rework Case',
               'Analyze Revision', 'Approve Revision', 'Check Revision', 'Close Case'),
        "T5": ('Open Case', 'Analyze Revision', 'Check Revision',
               'Approve Revision', 'Close Case'),
    }
    print("\n--- hand-derived counterexamples, machine-checked ---")
    for name, s in T.items():
        print(f"  {name}: A={s in la!s:<5} B={s in lb!s:<5}  {' -> '.join(s)}")

    # ---------- HEURISTIC / NON-EXHAUSTIVE playout, for contrast only ----------
    print("\n=== RANDOM PLAYOUT (NOT exhaustive) ===")
    print("pm4py.play_out samples runs; loop iteration counts follow an internal")
    print("stopping heuristic, long or rare interleavings may never be drawn, and")
    print("absence of a trace from the sample is NOT evidence of its absence from")
    print("the language. Use it for smoke tests, never for an equivalence verdict.")
    log_a = pm4py.play_out(tree_a)
    log_b = pm4py.play_out(tree_b)
    sa = {tuple(e["concept:name"] for e in tr) for tr in log_a}
    sb = {tuple(e["concept:name"] for e in tr) for tr in log_b}
    print(f"sampled |A|={len(sa)}  |B|={len(sb)}  "
          f"sample-only-A={len(sa - sb)}  sample-only-B={len(sb - sa)}")
    print(f"sample missed {len(set(only_a) - sa)} of the {len(only_a)} true A-only "
          f"witnesses and {len(set(only_b) - sb)} of the {len(only_b)} true B-only ones.")


if __name__ == "__main__":
    main()
```

**Note on the duplicated `MAX_VISIBLE` line:** the second assignment (`= 12`) is the effective one and matches P3; the first is left only to make the bound's two components adjacent. If you prefer, delete the first line — behaviour is unchanged.

**Expected qualitative outcome.** `only_a` is non-empty (every trace with ≥ 2 checks, e.g. T1, T2) and `only_b` is non-empty (every trace whose single check follows an approval or follows a rework without a matching earlier check, e.g. T3, T4); the shared part is the four-trace intersection of §3 plus nothing else — because *every* trace with `n ≥ 2` in A has ≥ 2 checks and is thus rejected by B, and every `n ≥ 2` trace of B has exactly 1 check and is thus rejected by A. Exact cardinalities depend on the bound arithmetic and are therefore reported by the program rather than asserted here.

# 6. Stochastic and Footprint Comparison

### 6.1 `pm4py.discover_footprints(...)`

The footprint abstracts a model to the directly-follows / causality / parallel / choice relations over its alphabet. It is **cheap, and here it is genuinely informative in the negative direction**:

- In A, `Check Revision` is parallel only with `Analyze Revision`; it is in a causal relation `→` with `Approve Revision`, `Rework Case` and `Close Case`.
- In B, `Check Revision` is parallel with `Analyze Revision`, `Approve Revision` **and** `Rework Case`.

So `A ∥ B` differ on the pairs `(Check, Approve)` and `(Check, Rework)`. A footprint diff therefore already flags the models as different, and it does so without enumerating a single trace.

```python
fp_a = pm4py.discover_footprints(tree_a)     # or on (net, im, fm)
fp_b = pm4py.discover_footprints(tree_b)
for key in ("dfg", "sequence", "parallel", "activities", "start_activities", "end_activities"):
    if fp_a.get(key) != fp_b.get(key):
        print(f"footprint differs on '{key}'")
        print("  only A:", set(fp_a.get(key, [])) - set(fp_b.get(key, [])))
        print("  only B:", set(fp_b.get(key, [])) - set(fp_a.get(key, [])))
```

**Why equal footprints would prove nothing.** The footprint is a *pairwise* relation over activities: it is blind to counts (it cannot express `#Check = #Analyze`), blind to long-distance dependencies, and blind to how many times a relation is exercised. Two models with identical footprints can have different languages — the classical example is a loop over `{a,b}` versus `a` and `b` in parallel with a repeat, which agree on all pairwise relations. In this task, the multiplicity difference (`#Check = n` vs `#Check = 1`) is *inherently* a counting property and lives entirely outside the footprint abstraction. Had the `Check ∥ Approve` accident not exposed the difference, the footprints could well have matched while the languages differed. Footprints are a **falsifier, never a certifier**.

### 6.2 `pm4py.get_stochastic_language(...)` and `pm4py.compute_emd(...)`

A stochastic language maps traces to probabilities. Neither Model A nor Model B carries probabilities: a process tree fixes *which* traces are possible, not *how likely*. To obtain a stochastic language one must therefore **declare** a probabilistic completion. I declare it explicitly rather than inventing it silently:

> **Declared stochastic assumptions (not derived from the models):**
> (S1) every enabled choice is resolved uniformly — in particular `X(Approve Revision, tau)` takes each branch with probability 0.5;
> (S2) loop exit vs. redo is uniform (0.5/0.5) at each iteration boundary, giving a geometric distribution over `n` with mean 2;
> (S3) concurrent interleavings are chosen uniformly among enabled transitions.
> These are **modelling choices**, not facts about A or B. Any other choice changes every number below.

```python
# Empirical stochastic language via sampling under the declared assumptions.
log_a = pm4py.play_out(tree_a, parameters={"no_traces": 20000})
log_b = pm4py.play_out(tree_b, parameters={"no_traces": 20000})

lang_a = pm4py.get_stochastic_language(log_a)   # dict: trace-tuple -> probability
lang_b = pm4py.get_stochastic_language(log_b)

emd = pm4py.compute_emd(lang_a, lang_b)
print("EMD(A, B) under declared assumptions S1-S3 =", emd)
```

**What EMD adds.** EMD gives a *graded* answer: it measures how much probability mass must be moved, and how far (under a trace edit distance), to turn one stochastic language into the other. That is useful for prioritisation — it answers "does this modelling difference matter in practice?" rather than "does it exist?". Under S1–S3 the mass concentrates on short traces (`n = 1` dominates, and those are exactly the shared traces), so the EMD will be **small** even though the models are provably not trace-equivalent.

**Why a low EMD still does not establish trace equivalence.**
1. *Direction of inference.* `EMD = 0` implies equal *support* only if both languages are exact and complete; a sampled language is neither. A trace of true probability 10⁻⁶ is almost surely absent from a 20 000-trace sample, so the sampled supports can coincide while the true supports differ.
2. *Assumption-dependence.* The number is a function of S1–S3, not of A and B. Setting the loop-continuation probability to 0.9 would shift mass onto `n ≥ 2` traces — exactly where the models diverge — and inflate the EMD dramatically. A metric that can be tuned by an undeclared parameter cannot certify a structural property.
3. *Wrong question.* Trace equivalence is a set-equality question; EMD is a distance between measures. A small distance is compatible with disjointness on a rare region of the language, which is precisely where compliance breaches live. In this case, the P1 violation of Model B (T4) occurs only when `n ≥ 2` and the check is scheduled late — a low-probability corner under S1–S3, and a high-impact one in the business.

Conclusion for §6: footprints supply a fast *refutation* here and corroborate §4; stochastic language and EMD supply *materiality*, not *validity*. Neither can replace the exhaustive bounded exploration of §5, and none of the three can prove unbounded equivalence.

# 7. Complexity Comparison

### 7.1 Structural counts (derived here)

Enumerating the nodes of each tree explicitly.

*Model A* — nodes: `->`(root), `Open Case`, `*`, `Close Case`, `->`(inner), `+`, `Analyze Revision`, `Check Revision`, `X`, `Approve Revision`, `tau`, `Rework Case`.
*Model B* — nodes: `->`(root), `Open Case`, `+`, `Close Case`, `Check Revision`, `*`, `->`(inner), `Rework Case`, `Analyze Revision`, `X`, `Approve Revision`, `tau`.

Depth measured as the maximum number of **edges** from the root to a leaf.
- A: root → `*` → `->`(inner) → `+` → `Analyze Revision` = 4; also root → `*` → `->` → `X` → `Approve Revision` = 4. **Depth = 4.**
- B: root → `+` → `*` → `->`(inner) → `X` → `Approve Revision` = 5. **Depth = 5.**

| Metric | Model A | Model B | Comment |
|---|---|---|---|
| Total tree nodes | **12** | **12** | Identical; node count alone is a useless discriminator here |
| Operator nodes | **5** (`->`, `*`, `->`, `+`, `X`) | **5** (`->`, `+`, `*`, `->`, `X`) | Same multiset of operators — the models differ only in how they are *nested* |
| Leaves (total) | **7** | **7** | — |
| Visible leaves | **6** | **6** | `Open, Analyze, Check, Approve, Rework, Close` |
| Silent leaves (`tau`) | **1** | **1** | Both only from the optional approval |
| Duplicate-label count | **0** | **0** | Every visible label occurs exactly once; repetition is *runtime*, from the loop |
| Depth (edges) | **4** | **5** | B nests the loop one level deeper, inside the `+` |
| Deepest visible leaf | `Analyze`/`Check`/`Approve` at 4 | `Approve` at 5 | B's approval is the most deeply nested construct |
| Nodes under the loop | **8** (`*`, `->`, `+`, `Analyze`, `Check`, `X`, `Approve`, `tau`, `Rework` = 9 incl. `*`) | **7** (`*`, `->`, `Analyze`, `X`, `Approve`, `tau`, `Rework`) | A repeats strictly more behaviour — the source of the multiplicity difference |

The two trees are structurally near-identical by every naive metric (same node count, same operator multiset, same leaves, zero duplicates) yet are not trace-equivalent. **This is the concrete demonstration of the task's warning that similar diagrams and equal activity sets do not imply equal behaviour.** Only the *scope* metrics (depth, nodes-under-loop) hint at the difference.

### 7.2 Code

```python
from pm4py.objects.process_tree.obj import Operator
from collections import Counter

def tree_metrics(tree):
    nodes = ops = leaves = visible = silent = 0
    labels = Counter()
    max_depth = 0

    def walk(node, depth):
        nonlocal nodes, ops, leaves, visible, silent, max_depth
        nodes += 1
        max_depth = max(max_depth, depth)
        if node.children:                      # operator node
            ops += 1
            for ch in node.children:
                walk(ch, depth + 1)
        else:                                  # leaf
            leaves += 1
            if node.label is None:
                silent += 1
            else:
                visible += 1
                labels[node.label] += 1

    walk(tree, 0)
    duplicates = sum(c - 1 for c in labels.values() if c > 1)
    return {
        "nodes": nodes, "operators": ops, "leaves": leaves,
        "visible_leaves": visible, "silent_leaves": silent,
        "distinct_labels": len(labels), "duplicate_label_count": duplicates,
        "depth_edges": max_depth,
    }

for name, tree in (("A", tree_a), ("B", tree_b)):
    print(name, tree_metrics(tree))

# Petri-net simplicity (value depends on the pm4py conversion; do not predict it)
for name, (net, im, fm) in (("A", (net_a, im_a, fm_a)), ("B", (net_b, im_b, fm_b))):
    print(name,
          "places=", len(net.places),
          "transitions=", len(net.transitions),
          "arcs=", len(net.arcs),
          "silent_transitions=", sum(1 for t in net.transitions if t.label is None),
          "simplicity=", pm4py.simplicity_petri_net(net, im, fm))
```

**On `simplicity_petri_net`.** I deliberately do **not** report a number. The metric is arc-degree based (it penalises deviation from a reference mean degree) and its value depends on the exact conversion pm4py performs, including how many silent routing transitions the `+`/`*` translation introduces. Predicting it would violate the instruction to report exact values only when derived. What can be said structurally and safely: both conversions introduce an AND-split/join pair and a loop-routing construct, so the nets are of comparable size; B's global `+` spans the loop and therefore produces AND-routing places that bracket the entire loop subnet, whereas A's `+` is local. Run the code to obtain the actual figures.

# 8. Simplified Model

### 8.1 Target semantics

I target **P1 (operational compliance)**, for three reasons: (i) it is the only view under which the two models genuinely disagree on a *norm* (B admits an unchecked, approved, reworked attempt — T4), so it is the view where getting the model right has consequences; (ii) P2's verdict is an artefact of a lossy abstraction and any model satisfying P1 also satisfies P2 (shown below), so targeting P1 gets P2 for free; (iii) P3 is a testing method, not a semantics, and cannot be a simplification target.

Within P1 I make one **declared weakening**: I fix the intra-attempt order to `Analyze Revision` then `Check Revision`. P1 requires each analysis to have "its own Check Revision before the next Rework Case or before Close Case" and is silent on whether a check may *precede* its analysis; checking before analysing is operationally meaningless, so I sequentialise. This is a genuine loss (A admits `O,C,A,Cl`) and is recorded as such in the preservation table.

### 8.2 Compact process tree

```text
->(
  'Open Case',
  *(
    ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ),
    'Rework Case'
  ),
  'Close Case'
)
```

### 8.3 PM4Py code

```python
import pm4py
```

### 8.4 Structural comparison against **both** originals (required before calling it simpler)

Nodes of the simplified tree: `->`(root), `Open Case`, `*`, `Close Case`, `->`(inner, ternary), `Analyze Revision`, `Check Revision`, `X`, `Approve Revision`, `tau`, `Rework Case` = **11**.

| Metric | Model A | Model B | Simplified | Direction |
|---|---|---|---|---|
| Total nodes | 12 | 12 | **11** | −1 (the `+` operator is gone) |
| Operator nodes | 5 | 5 | **4** | −1 |
| Concurrency operators | 1 | 1 | **0** | eliminated |
| Depth (edges) | 4 | 5 | **4** | ≤ both |
| Visible / silent leaves | 6 / 1 | 6 / 1 | **6 / 1** | unchanged |
| Duplicate labels | 0 | 0 | **0** | unchanged |
| Petri-net consequence | AND-split + AND-join + 2 routing places | AND-split + AND-join spanning the whole loop | **no AND construct at all** | strictly fewer places, transitions and arcs than either original |

The simplification is real and not merely cosmetic: removing the `+` removes an AND-split/AND-join transition pair and their places from the converted net in *both* comparisons, and it removes the interleaving blow-up from the reachability graph (the state space becomes linear in the iteration count instead of branching per attempt). It is simpler than A *and* simpler than B on every metric, and strictly shallower than B.

# 9. Final Recommendation

**Model A** is the correct model for **P1**. It is the only one of the two originals that *satisfies* the operational compliance norm: the check is inside the loop, so `#Check = #Analyze` and every attempt is checked before the next `Rework Case` or before `Close Case`. Use A — or the simplified model below — for conformance checking, audit, and any control that counts checks.

**Model B** is **not** suitable for P1 and should not be used for compliance purposes: it permits trace T4, in which an analysis is approved and reworked with no check whatsoever, and it structurally caps the case at one check no matter how many revision attempts occur. B is a defensible model only if the real process genuinely has a single, case-level check running alongside the whole revision phase — in which case P1 as stated is the wrong norm and should be rewritten before either model is chosen. B is *not* a legitimate refactoring of A.

**For P2**, both originals are adequate and indistinguishable: the dashboard abstraction `α` collapses precisely the dimensions on which they differ. But this should be read as a warning rather than a licence — the dashboard's equivalence verdict is an artefact of throwing away check multiplicity. Do not let "the dashboards match" be used as evidence that the two models are interchangeable; under P1 they are not, and the very metric the dashboard hides (checks per case) is the one the compliance function needs.

**For P3**, neither model passes as a substitute for the other: the exhaustive bounded exploration finds witnesses in both directions well inside the 12-event / 3-analysis window (the shortest is 5 events).

**Should the simplified model replace either original?**
- It should **replace Model B** wherever B was being used to represent this process under P1 — it repairs B's compliance defect while remaining strictly smaller than B (11 vs 12 nodes, depth 4 vs 5, no AND construct).
- It should replace **Model A** only if the business accepts the declared weakening: the simplified model forbids `Check Revision` before `Analyze Revision` within an attempt and no longer expresses analysis/checking as genuinely concurrent work. If analyst and checker really do work in parallel — and the organisation cares about that, e.g. for resource planning or for accepting logs where the check is timestamped first — keep Model A. If the check is conceptually a review *of* the analysis, adopt the simplified model: it is smaller than both originals, its state space is linear rather than interleaved, and it preserves every P1 invariant exactly and the whole P2 abstraction exactly.
- **No single model preserves all three views**, and none is needed: P2 imposes no constraint that P1 does not already imply (every P1-compliant model has ≥ 1 analysis, ≥ 1 check, `Open`/`Close` at the ends, rework iff `n ≥ 2`), so a P1-correct model serves P2 as well. The genuine incompatibility is between A and B, not between the views.

**Warning on the limits of bounded comparison.** Every machine-checked statement in §5 concerns traces with at most 12 visible events and at most 3 analyses. Within that window the exploration is exhaustive, so the *mismatch* it reports is conclusive: a witness inside the bound disproves unbounded trace equivalence outright. The converse must never be asserted. Had the bounded sets coincided, that would have been evidence only — both models generate unboundedly long traces, and the differences here happen to surface early (at `n = 2`) but in general a difference can first appear at any iteration depth, beyond any bound one chose to test. Likewise, a tighter bound (≤ 5 events, ≤ 1 analysis) would have found `L_A ⊆ L_B` and reported no A-only witness at all, which is *true within that bound and wrong about the models*. Sampling via `play_out` is weaker still: absence from a sample is not absence from the language. And equal footprints or a small EMD — the latter computed only under explicitly declared, invented probabilities — would establish neither trace equivalence nor compliance. For a compliance-critical decision, rely on the structural argument of §2–§3 (`#Check = #Analyze` in A versus `#Check = 1` in B, proved from the loop scope), and treat the bounded exploration as the confirmation it is.
