## 2. Equivalence and Sufficiency Test

**Test ladder.** Classify the *package* (not individual activities) against the case's actual risk drivers:

- **Fully equivalent (A):** (i) an independent, non-conflicted human (L3+, own credentials, no rating/kinship conflict) performs a substantive review of invoice, bank details, and receipt **before economic finality** (release, or settlement if later and stoppable); (ii) AV-2 fully operational, clean pass, no override, and its covered checks match the case's risk drivers; (iii) audit scheduled within the recall window; (iv) if an ED-1 exception is claimed, all seven conditions are evidenced, including token-before-prepare. AP-203, AP-207 conform to this shape.
- **Partially equivalent (B):** substantive independent verification before finality exists, but with formal condition breaches that added no exposure (AP-206 token timing), or with coverage gaps offset by low intrinsic case risk (AP-201), or formal SoD whose substantive independence is unverified but no defect found (AP-209).
- **Merely mitigating (C):** checks occur but after finality (post-settlement ratification), or warnings are overridden, or independence is impaired, or audit falls outside the recall window. Expected loss is reduced; single-actor exposure is not eliminated.
- **Ineffective (D):** no independent check before finality **and** no timely detection, or controls were affirmatively defeated (self-override, fail-open during outage). AP-202, AP-208.

**Criteria applied at each level:**
- **Timing** — measured against two reference points: Release_Payment and irrevocable settlement/recall expiry. The second dominates for loss prevention.
- **Independence** — organizational (no reporting/rating line), credential (no shared or borrowed override rights), physical (no shared workstation), and temporal (reviewer not pre-committed).
- **Coverage** — do the checks that passed actually address this case's risk drivers? A clean AV-2 pass is strong evidence only for duplicates, sanctions, ownership, recent bank change, limits, PO match — never for receipt or collusion.
- **Overrideability** — who can override, with whose credential, logged how? A warning self-overridden by the operator is not a control event; it is a control failure with extra logging.
- **Recoverability** — is detection early enough that recall is still feasible? Detective value decays to near zero after ~24h.
- **Evidence quality** — contemporaneous, signed, attributable, tamper-evident artifacts (AP-208's unsigned checklist fails this).
- **Collusion resistance** — pair rotation, affinity limits, no shared devices; formal two-person sign-off by a dominated pair is one eye, not two.

**Why "same expected loss" is not the only admissible standard:** (1) EL ignores tail shape — a package that usually works but fails catastrophically at EUR 900k is not interchangeable with a consistently adequate one under any risk-averse appetite; (2) some harms are not commensurable in EUR (sanctions exposure, regulatory SoD mandates); (3) ex-ante EL for rare fraud is not measurable from sparse internal data — the estimate is model output, not fact; (4) controls carry governance value EL omits: attribution, deterrence, auditability, precedent-setting (a tolerated convenience bypass lowers the cost of the next one); (5) prevention and correction have different option value — correction depends on bank cooperation and counterparty solvency; (6) failure modes are correlated (outage + emergency + bank change cluster), which EL averaging hides. A sufficiency judgment may therefore legitimately demand prevention even where EL arithmetic favors detection.

## 4. Preventive–Detective–Corrective Comparison

**Chosen semantics.** I classify controls by capability relative to **economic finality** (bank settlement plus recall expiry), not relative to the Release_Payment event. Justification: FEP-1's stated purpose targets the *transfer*, and the harm materializes only when value leaves irrevocably; a released instruction that has not settled is still reversible. Under this semantics, a manager action after Release_Payment but before settlement is **hybrid**: detective with respect to the release event, preventive with respect to the loss event — and I operationally count it as preventive-of-loss (AP-201, AP-207). The process-event view should still be reported alongside, because post-release approval compresses review time, creates ratification pressure, and correlates with rubber-stamping; it is a weaker mode of prevention and should be monitored as such.

# ---------- 2. PM4Py formatting ----------
import pm4py
log = pm4py.format_dataframe(df, case_id="case:concept:name",
                             activity_key="concept:name",
                             timestamp_key="time:timestamp")

# ---------- 3. Nominal four-eyes violations among COMPLETED payments ----------
def _case_ids(obj):
    # pm4py 2.x returns a DataFrame; older versions may return an EventLog
    if isinstance(obj, pd.DataFrame):
        return set(obj["case:concept:name"].unique())
    return {t.attributes.get("concept:name") for t in obj}

def manual_violations(frame):
    p = frame[frame["concept:name"] == "Prepare_Payment"][["case:concept:name", "org:resource"]]
    r = frame[frame["concept:name"] == "Release_Payment"][["case:concept:name", "org:resource"]]
    j = p.merge(r, on="case:concept:name", suffixes=("_prep", "_rel"))
    return set(j.loc[j["org:resource_prep"] == j["org:resource_rel"], "case:concept:name"])

try:
    fep_log = pm4py.filter_four_eyes_principle(log, "Prepare_Payment", "Release_Payment")
    pm4py_viol = _case_ids(fep_log)          # keeps traces where ONE resource did BOTH -> violations
except Exception as exc:
    pm4py_viol = None
    print("filter_four_eyes_principle unavailable, using manual definition:", exc)

man_viol = manual_violations(df)
if pm4py_viol is not None and pm4py_viol != man_viol:
    print("NOTE: pm4py result differs from manual definition:",
          sorted(pm4py_viol), "vs", sorted(man_viol))
nominal_violations = man_viol if pm4py_viol is None else pm4py_viol
print("Nominal FEP-1 violations (completed payments):", sorted(nominal_violations))

# ---------- 4. Attempted but BLOCKED releases (no completed Release_Payment) ----------

                          if "Attempt_Release" in a and "Release_Payment" not in a)

# Settlement times stated in the narrative but absent from the log
NARRATIVE_SETTLEMENT = {"AP-201": "2026-05-04T10:00:00Z", "AP-203": "2026-05-04T12:00:00Z"}

# ---------- 6. Evidence flags ----------
def t(case, activity):
    s = df[(df["case:concept:name"] == case) & (df["concept:name"] == activity)]["time:timestamp"]
    return s.min() if len(s) else pd.NaT

prep_res = df[df["concept:name"] == "Prepare_Payment"].set_index("case:concept:name")["org:resource"]
rel_res  = df[df["concept:name"] == "Release_Payment"].set_index("case:concept:name")["org:resource"]

pair_counts = pairs.value_counts()

rows = []
for _, f in facts.iterrows():
    c = f["case"]
    prep_t, rel_t, aud_t = t(c, "Prepare_Payment"), t(c, "Release_Payment"), t(c, "Audit_Review")
    set_t = t(c, "Bank_Settlement")
    if pd.isna(set_t) and c in NARRATIVE_SETTLEMENT:
        set_t = pd.Timestamp(NARRATIVE_SETTLEMENT[c])
    mgr_t = min([x for x in (t(c, "Manager_Approve"), t(c, "Manager_Ratify")) if pd.notna(x)] or [pd.NaT])

    # manager timing relative to release and economic finality
    if pd.isna(mgr_t):

    elif pd.notna(rel_t) and mgr_t < rel_t:

    elif pd.notna(set_t) and mgr_t < set_t:

    elif pd.notna(set_t):
        mgr_timing = "POST_SETTLEMENT"
    else:

                     and aud_t.date() <= (rel_t + pd.offsets.BDay(1)).date())   # next-business-day approx.
    audit_24h = bool(pd.notna(aud_t) and pd.notna(rel_t)
                     and (aud_t - rel_t) <= pd.Timedelta(hours=24))             # recall window

    # ED-1 conditions 1-7 (None = unknown)
    tok = f["token_active_at"]
    c1 = None if pd.isna(tok) else bool(pd.notna(prep_t) and tok <= prep_t)
    conds = {
        "c1_token_before_prepare": c1,
        "c2_amount_lt_100k": bool(f["amount_eur"] < 100_000),
        "c3_vendor_ge_180d": bool(f["vendor_age_days"] >= 180),

                                               and pd.notna(set_t) and mgr_t < set_t),
        "c7_audit_within_1bd": audit_1bd,
    }
    ed1_failed = [k for k, v in conds.items() if v is False]

    pair = (pairs.loc[c, "preparer"], pairs.loc[c, "releaser"]) if c in pairs.index else None
    rows.append({
        "case": c,
        "same_user_fep1_violation": c in nominal_violations,
        "blocked_before_completion": c in blocked_attempts,
        "av_result": f["av_result"],
        "mgr_timing": mgr_timing,
        "audit_within_1bd": audit_1bd,
        "audit_within_24h_recall": audit_24h,
        "bank_change_7d": f["bank_change_7d"],
        "pair": pair,
        "pair_count_30d": int(pair_counts.get(pair, 0)) if pair else 0,
        "ed1_failed_conditions": ed1_failed,
        "loss_or_invalid_outcome": f["loss_or_invalid_outcome"],
    })

evidence = pd.DataFrame(rows)
pd.set_option("display.width", 200)

**Version caveats I cannot guarantee:** (a) `pm4py.format_dataframe(df, case_id=, activity_key=, timestamp_key=)` is stable across pm4py 2.x, but the returned object type (DataFrame vs EventLog) has varied — `_case_ids` handles both; (b) `pm4py.filter_four_eyes_principle` is assumed to *retain* traces where one resource performs both activities (i.e., nominal violations) and to require both activities present; if a version's semantics differ, the code prints the discrepancy and the manual definition is the authoritative cross-check; (c) the one-business-day audit SLA is approximated by next-business-day calendar date, and the 24h recall flag is computed separately because the two diverge (AP-201: 25h); (d) settlement times for AP-201/AP-203 come from the narrative, not the log, and are marked as such. All output is evidence for the classifications argued in Sections 3–5, not a substitute for them.
