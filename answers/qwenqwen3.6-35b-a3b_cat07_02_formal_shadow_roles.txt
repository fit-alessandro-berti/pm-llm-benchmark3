```python
from pm4py.objects.log.importer.xes import importer as xes_importer
from pm4py.algo.discovery.organizational_roles import algorithm as org_roles
from pm4py.algo.discovery.activity_based_resource_similarity import algorithm as activity_similarity
from pm4py.algo.discovery.handover_of_work import algorithm as handover_algo
from pm4py.algo.discovery.working_together import algorithm as working_together_algo

# 1. Load and Format Dataframe
# Assuming 'log_df' is a pandas DataFrame with standard PM4Py columns
# concept:name, activity, time, resource, case_complexity, customer_segment, product_line, temporary_substitution, escalation_level

log_df = pd.read_csv("event_log.csv") # Example load

# Format for PM4Py
log = pm4py.format_dataframe(
    log_df,
    concept_name_attribute='concept:name',
    activity_attribute='activity', # or 'concept:name' if activity is in that column
    timestamp_attribute='time:timestamp',
    resource_attribute='org:resource'
)

# Ensure case_complexity is available as a case attribute
# PM4Py usually stores case attributes in the log's dictionary
log = pm4py.add_case_attributes(log, case_attributes=['case_complexity', 'customer_segment', 'product_line'])

# 2. Discover Organizational Roles
# This uses frequency-based clustering by default, which is the "naïve" baseline.
# We run it to compare against our inferred structure.
roles = org_roles.apply(log)
print("Naïve Role Clustering:")
print(roles)

# 3. Discover Activity-Based Resource Similarity
# This helps identify shadow roles (high similarity but different complexity/authority).
similarity_matrix = activity_similarity.apply(log)
print("\nActivity Similarity Matrix (Top Pairs):")
# Filter for high similarity
high_sim = similarity_matrix[similarity_matrix['similarity'] > 0.8]
print(high_sim)

# 4. Compute Networks
# Handover of Work: Shows who hands off to whom. Critical for identifying brokers.
hwo_network = handover_algo.apply(log)
print("\nHandover of Work Network (Edges):")
print(hwo_network)

# Working Together: Shows resources active in same cases.
wt_network = working_together_algo.apply(log)
print("\nWorking Together Network (Edges):")
print(wt_network)

# 5. Join Role Discovery with Case Complexity and Temporary Substitution
# Analyze complexity per resource to distinguish seniority vs routine.
complexity_by_resource = log_df.groupby('org:resource')['case_complexity'].median()
print("\nMedian Case Complexity by Resource:")
print(complexity_by_resource)

# Identify temporary substitutions
# Filter for cases where temporary_substitution is True
temp_cases = log_df[log_df['temporary_substitution'] == True]
temp_resources = temp_cases['org:resource'].unique()
print("\nResources involved in Temporary Substitutions:")
print(temp_resources)

# 6. Avoid Over-interpreting Frequency Clusters
# Strategy: Combine similarity, complexity, and network analysis.
# Example: If Giorgio is clustered with Amira/Ben by frequency, check:
# - Is Giorgio's similarity to Fatima > 0.7? (Shadow detection)
# - Is Giorgio's complexity distribution different from Amira?
# - Does Giorgio appear in Handover network as a bridge to Commercial nodes?

giorgio_complexity = complexity_by_resource.get('R07_Giorgio')
fatima_similarity = similarity_matrix.loc['R07_Giorgio', 'R06_Fatima']
giorgio_in_hwo = hwo_network[(hwo_network['source'] == 'R07_Giorgio') | (hwo_network['target'] == 'R07_Giorgio')]

# Decision Logic (Illustrative)
if fatima_similarity > 0.7 and giorgio_complexity > complexity_by_resource.get('R01_Amira'):
    print("Giorgio is likely a Commercial Shadow Role, not just a Front-Office Agent.")
    print("Recommendation: Formalize shadow role; train backup.")
else:
    print("Giorgio is likely a standard Front-Office Agent.")

# 7. Inspect Mateo's Brokerage
# Mateo should have high degree in HWO network connecting multiple clusters.
mateo_degree = len(hwo_network[(hwo_network['source'] == 'R13_Mateo') | (hwo_network['target'] == 'R13_Mateo')])
mateo_complexity = complexity_by_resource.get('R13_Mateo')

if mateo_degree > 5 and mateo_complexity > 0.7:
    print("Mateo is a Cross-Functional Broker. High connectivity and complexity.")
    print("Recommendation: Protect Mateo's capacity; audit approval rechecks.")
```

# 6. Operational interpretation

**Staffing and Capacity Planning**
*   **Resilience via Shadows:** The structure reveals that R07_Giorgio and R03_Chen provide critical shadow coverage. Management should retain Giorgio in a hybrid role rather than promoting him to pure Commercial, as his FO volume is high and his commercial substitution is inefficient (2x duration). For security, R03's shadow capability is a buffer, but R05_Erik remains a single point of failure. Consider cross-training a second specialist or formalizing R03's shadow role with certification.
*   **Temp Management:** R11_Kai and R12_Lina are effective for low-complexity volume but introduce quality risk (Sequence 6). Staffing should pair them with R01/R02 for validation checks, or invest in training to improve their A2 note quality.

**Training and Development**
*   **Complexity-Based Training:** R04_Dina and R02_Ben handle lower complexity but have similar activity profiles to seniors. Training should focus on escalation triggers and validation rigor. R01_Amira and R03_Chen should receive advanced training in complexity handling and shadow roles (e.g., Chen in security, Amira in mentorship).
*   **Broker Training:** R13_Mateo's role requires high contextual awareness. Training should focus on decision frameworks for preliminary approvals and security triage to reduce the recheck burden on R08_Hana.

**Risk Control and Governance**
*   **Shadow Role Risks:** Shadow roles improve resilience but can blur accountability. Giorgio's pricing decisions during substitutions may lack the depth of Fatima's, leading to suboptimal negotiations. Mateo's preliminary approvals require strict audit trails. Management should monitor error rates and approval rejection rates for shadow activities.
*   **Automation Boundary:** R14_Nora handles A1/A2. If Nora fails, intake stops. A fallback process for manual registration must exist. Also, Sequence 6 shows reopens due to incomplete validation by temps; this may indicate Nora's A2 is too simplistic, and humans must catch errors.

**Cautions for Management**
1.  **Do not restructure based solely on activity frequency:** Clustering would group Giorgio with Amira/Ben and Mateo with generalists. This would hide Giorgio's commercial risk and Mateo's coordination value. Use complexity and network analysis to guide decisions.
2.  **Do not assume temporary substitution proves permanent competence:** Giorgio's substitution showed reduced efficiency. R13_Mateo's approvals required recheck. Substitutions reveal backup capability but also performance gaps. Formalizing these roles without addressing efficiency gaps may degrade overall process performance.
3.  **Monitor the "Reopen" Loop:** Sequence 6 and data show reopens are driven by validation errors (temps) and complex escalations (Mateo). Staffing and training must address the root causes of reopens, not just the resolution. Reducing reopens is key to throughput.
