## 1. Equivalence design space

**1. Activity-sequence equivalence AS**
Definition: Two executions e, e' are equivalent iff the sequence of activity labels
`[a1,...,an]` and `[a'1,...,a'm]` are identical with n=m and ai = a'i for all i. Timestamp order is used as total order; ties are broken lexicographically.
Invariants preserved: order of activity types.
Information discarded: all object types, object identifiers, multiplicities, external flags, E2O incidence, O2O relations, qualifiers, repeated events.
Reflexive, symmetric, transitive. Concurrency is lost; same-time events are forced to an arbitrary order.

**2. Typed structural equivalence under identifier renaming TS**
Definition: There is a bijection  on local object identifiers that preserves object type and external flag, such that for each event i the activity label is equal, the multiset of object types with multiplicities per type is equal, the E2O incidence pattern is equal up to , and the O2O type graph is isomorphic up to . Event order is preserved.
Invariants preserved: activity order, object types, multiplicities per type per event, external flag per object, E2O incidence, O2O type topology.
Information discarded: concrete local identifiers, O2O qualifier labels, attribute values.
Reflexive, symmetric, transitive. Concurrency is treated as total order; partial order would require a different definition.

**3. Business-semantic equivalence BS**
Preferred relation.
Definition: Canonical signature `sig(e)` is invariant to local renaming and consists of:
* event i: activity a_i, for each object type t the number of local objects |t| and number of external objects |t_ext| participating, and the multiset of object types involved;
* global phase counts: #packages, #deliveries, #invoices, #payments;
* external participation flags: logistics_shared, financial_shared;
* O2O qualifier presence set Q(e).
Two executions are equivalent iff `sig(e)=sig(e')`. 
Invariants preserved: activity order, multiplicities, external participation, qualified relations, lifecycle motifs.
Information discarded: concrete local identifiers, exact identity of which item maps to which package when only cardinalities matter.
Reflexive, symmetric, transitive. Same-time events are kept as a multiset per timestamp.

A fourth relation, partial-order typed equivalence, can be added where PackDispatch is a precedence only, not interleaving order.

## 2. Canonical signatures

Preferred relation is BS.

```python
def canonical_signature(exec):
    events = sorted(exec.events, key=lambda e:e.timestamp)
    sig_events = []
    for e in events:
        obj_counts = {}
        ext_counts = {}
        for ot, ids in e.e2o.items():
            local = [i for i in ids if not str(i).startswith('EXT')]
            ext   = [i for i in ids if str(i).startswith('EXT')]
            obj_counts[ot] = len(local)
            ext_counts[ot] = len(ext)
        sig_events.append((
            e.activity,
            tuple(sorted(obj_counts.items())),
            tuple(sorted(ext_counts.items()))
        ))
    # global motif counts
    pkgs = sum(1 for e in events if e.activity=='Pack Package')
    dels = sum(1 for e in events if e.activity=='Dispatch')
    pays = sum(1 for e in events if e.activity=='Record Payment')
    # external flags
    logistics_shared = any('EXT' in str(v) for e in events if e.activity in ['Pack Package','Dispatch'] for v in e.e2o.values())
    financial_shared = any('EXT' in str(v) for e in events if e.activity in ['Issue Invoice','Record Payment'] for v in e.e2o.values())
    # O2O qualifiers
    qualifiers = tuple(sorted({q for rel in exec.o2o for q in rel.qualifiers}))
    return (
        tuple(sig_events),
        pkgs, dels, pays,
        logistics_shared, financial_shared,
        qualifiers
    )
```

The signature is invariant to local renaming, preserves types, multiplicities, external flags, event order and O2O qualifiers.

## 6. Relation to `pm4py.cluster_equivalent_ocel`

`pm4py.cluster_equivalent_ocel` builds a key per execution from activity, timestamp, object identifiers and relations. It preserves exact object identifiers, E2O incidence and O2O links, thus it is finer than TS and BS. Raw identifiers make clusters too fine: X1 vs X2 would be different under exact identifiers.

Canonicalization / post-processing:
1. Cluster with pm4py.
2. For each cluster compute BS signature by renaming local ids to canonical counters per type and discarding concrete ids.
3. Merge clusters with identical BS signatures.

Exact equivalence is preferable for compliance monitoring where audit trail identity matters. Coarser business clustering is preferable for operational segmentation.

`max_objs` limits the size of connected object graph; large executions are dropped or truncated, biasing clusters toward small orders. Practical use requires sampling or hierarchical clustering.

Python outline:
```python
import pm4py
from pm4py.objects.ocel.obj import OCEL

lead_type = "Order"
clusters = pm4py.cluster_equivalent_ocel(ocel, parameters={"lead_object_type": lead_type})

def bs_key(exec_events):
    return canonical_signature(exec_events)

merged = {}
for cid, execs in clusters.items():
    key = bs_key(execs)
    merged.setdefault(key, []).extend(execs)
```

## 7. Robustness analysis

*Ignore O2O qualifiers*: X7 merges into SEM-BASELINE under AS, and into TS-1 if Dispatch Item is also ignored. Substitution risk disappears.

*Ignore external objects*: X5 and X6 collapse into SEM-BASELINE. Logistics and financial sharing become invisible.

*Collapse repeated same-label events*: Add Item twice collapses to one. X1,X2,X3,X4 lose item count distinction; split vs single package becomes ambiguous.

*Treat Pack and Dispatch as partial order*: X3 and X4 both have two packs and two dispatches with precedence Pack<iDispatch<i. Interleaving disappears, they may merge under TS if delivery consolidation is ignored.

*Payment multiplicity as amount attribute*: X4 with two Record Payment events becomes one payment with amount split. It would merge with SEM-SPLIT-SPLIT under BS if only delivery structure matters.

## 8. Limitations and recommendation

No single equivalence is best.

* Compliance monitoring: TS with exact identifiers and qualifiers. Need provable identity and external sharing flags.

* Operational segmentation: BS preferred. Multiplicities, external flags and lifecycle motifs drive capacity planning.

* Root-cause analysis: Partial-order TS with qualifiers. Order of independent Add Item matters less than PackDispatch causality.

* Descriptive reporting: AS is sufficient for KPI dashboards, but must be accompanied by object metrics to avoid masking sharing and returns.

The finest partition is not the best. Business meaning emerges from intentional discarding of identifier noise while retaining externality, multiplicity and qualified relations.
