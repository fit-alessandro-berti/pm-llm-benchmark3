## 5. Diagnostic program

| phase | analyses | PM4Py artifact or method | data required | decision produced | risk of misleading result |
|---|---|---|---|---|---|
| **Phase 1 — Semantic provenance: labels and technical events** (isolates H3 and H6, the two largest shares) | Weekly variant tables and **frequency DFGs** either side of 2026-05-31 and 2026-06-03; label census (`concept:name` frequency by client/app version); three-way A/B: raw vs label-remapped vs label-remapped + `Queue Routed` removed; start/end activity and per-relation DFG deltas | `pm4py.discover_dfg` and frequency DFG view; `pm4py.get_variants` / `pm4py.filter_variants`; `pm4py.filter_event_attribute_values` for the technical activity; `pm4py.conformance_diagnostics_alignments` + `pm4py.fitness_alignments` on each arm | Raw log with case, activity, client version, gateway topic/lifecycle flag; release calendar with deployment cohorts | The exact share of the 61-point drop attributable to label semantics versus technical-event emission; whether a contract-preserving alias restores period comparability | Applying both repairs simultaneously confounds attribution; removing `Queue Routed` could conceal genuinely unrouted cases; naive remapping may merge two activities that are *not* in fact identical |
| **Phase 2 — Temporal provenance and completeness** (isolates H4 and extraction defects) | Per-activity comparison of warehouse-ingestion time against the source-system sequence number; `Decision`/`Notify` swap rate; **ordering by source sequence** and re-running the same alignments; reconciliation of reported mean events/case against variant-derived means; resource-field completeness by activity and period | `pm4py.format_dataframe` with each ordering; `pm4py.conformance_diagnostics_alignments` with per-move counters; `pm4py.fitness_alignments` delta; `pm4py.discover_dfg` under both orderings | Source-system sequence number, both timestamps per event, resource fields, ETL job logs | Whether ordering alone explains the reversed-`Notify` moves; whether resource loss makes reviewer-level analysis impossible right now | The sequence number may reset per queue; reordering can mask genuinely late notifications; only 11/70 reversals have been source-verified |
| **Phase 3 — Model relevance and data-aware conformance** (isolates H2 and tests over-permissiveness) | Compare normative vs extended (optional sign-off) vs conditional (sign-off iff amount > EUR 50,000) on the identical normalized Aug–Sep log; report **fitness and precision together** plus model size; **case-attribute stratification** of alignments by high-value; inductive discovery on the fully normalized log as a descriptive (not normative) reference | `pm4py.parse_process_tree`, `pm4py.convert_to_petri_net`, `pm4py.fitness_alignments`, `pm4py.precision_token_based` / `precision_etconformance_pt`, `pm4py.fitness_tbr`, `pm4py.discover_process_tree_inductive`, `pm4py.filter_event_attribute_values(..., level='case')` for stratification | Case attributes (claim amount), policy text, model versions and effective dates | Whether the Aug–Sep drop is model obsolescence, and whether any extension buys fitness *without* destroying precision | An optional-sign-off tree raises fitness mechanically; without stratification it simultaneously permits sign-off where policy forbids it and omits it where policy mandates it; control-flow alone cannot express EUR 50,000 |
| **Phase 4 — Residual behavioral audit** (isolates H5 versus H6 for the residual, and H1) | Extract residual non-fitting case IDs from **alignment diagnostics**; manual audit of the 55 enhanced-review-without-check traces and the 59 unverified reversed traces against source screenshots; reviewer-level deviation rates after resource repair; daily series around 2026-08-12 for `Manual Override`; triangulation with appeal/incident data under an explicitly stated detection-sensitivity bound | `pm4py.conformance_diagnostics_alignments` per case, residual case IDs selected via `pm4py.filter_event_attribute_values(..., level='case')`, alignment visualisation for the audit sample; `pm4py.discover_dfg` restricted to the residual subset | Source-system screenshots, complete resource fields, reviewer IDs, a pre-registered audit protocol and sample size | Bypass versus missing event; whether noncompliance is real and material — the only remaining open question | A 40-case audit cannot bound a ~4.8% rate with useful confidence; resource loss biases reviewer attribution toward whoever logs cleanly; absence of an appeal signal is not evidence of absence of nonconformance |

Each phase isolates one mechanism against a controlled counterfactual (Phase 1: semantics; Phase 2: ordering and completeness; Phase 3: model relevance; Phase 4: behaviour). None of them is "rerun conformance" — re-running on the same raw log with the same stale tree would reproduce 32% and prove nothing.

## 6. PM4Py reproduction and model-comparison code

```python
# -*- coding: utf-8 -*-
"""
Conformance-collapse reproduction scaffold (PM4Py >= 2.7, API as documented in
the PM4Py manual: parse_process_tree, convert_to_petri_net,
parse_event_log_string, discover_dfg, conformance_diagnostics_alignments,
fitness_alignments, precision_*).

What this script does
  1. encodes the normative process tree
  2. converts it to an accepting Petri net
  3. expands the published variant-frequency tables into logs
  4. discovers DFGs
  5. computes alignment diagnostics and alignment fitness
  6. applies a transparent normalisation pipeline
        (a) map 'Risk Screen' -> 'Classify'
        (b) optionally drop the technical event 'Queue Routed'
        (c) optionally order by the source-system sequence number
  7. compares raw vs normalised results
  8. builds a candidate tree with an OPTIONAL 'Supervisor Sign-off',
     converts it, and compares fitness AND precision for Aug-Sep
  9. prints caveats about what a control-flow-only model cannot enforce

NOTE ON PROVENANCE: the input is variant AGGREGATES, not a timestamped log.
Timestamps below are synthetic and preserve only within-trace activity order
exactly as published.  The source-system sequence repair is ILLUSTRATIVE by
default and must be replaced by the real column before any number is quoted.
"""

from collections import Counter

import pandas as pd
import pm4py

CASE = "case:concept:name"
ACT = "concept:name"
TS = "time:timestamp"


# --------------------------------------------------------------------------
# 1-2.  NORMATIVE MODEL  ->  ACCEPTING PETRI NET
# --------------------------------------------------------------------------
NORMATIVE_TREE = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "'Decision', 'Notify' )"
)

# Candidate: same structure, plus an OPTIONAL Supervisor Sign-off before Decision.
CANDIDATE_TREE = (
    "-> ( 'Receive', 'Classify', "
    "X ( * ( 'Standard Review', 'Request Info' ), "
    "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
    "X ( 'Supervisor Sign-off', {silent} ), "
    "'Decision', 'Notify' )"
)


def _tree_candidates(kind):
    """PM4Py releases differ on xor token ('X'/'XOR') and silent token
    ('tau'/'epsilon'/'silent'); try every documented spelling."""
    if kind == "normative":
        yield NORMATIVE_TREE
        yield NORMATIVE_TREE.replace(" X (", " XOR (")
    else:
        for silent in ("tau", "epsilon", "silent"):
            text = CANDIDATE_TREE.format(silent=silent)
            yield text
            yield text.replace(" X (", " XOR (")


def parse_tree(kind):
    last = None
    for text in _tree_candidates(kind):
        try:
            return pm4py.parse_process_tree(text)
        except Exception as exc:                      # pragma: no cover
            last = exc
    raise RuntimeError("pm4py.parse_process_tree could not parse %s tree: %s"
                       % (kind, last))


norm_tree = parse_tree("normative")
norm_net, norm_im, norm_fm = pm4py.convert_to_petri_net(norm_tree)

cand_tree = parse_tree("candidate")
cand_net, cand_im, cand_fm = pm4py.convert_to_petri_net(cand_tree)

print("[model] normative transitions:", len(norm_tree.children),
      " | candidate transitions:", len(cand_tree.children))


# --------------------------------------------------------------------------
# 3.  VARIANT-FREQUENCY TABLES -> EVENT LOGS
# --------------------------------------------------------------------------
APR_MAY = [
    (["Receive", "Classify", "Standard Review", "Decision", "Notify"], 380),
    (["Receive", "Classify", "Enhanced Review", "Compliance Check",
      "Decision", "Notify"], 180),
    (["Receive", "Classify", "Standard Review", "Request Info",
      "Standard Review", "Decision", "Notify"], 40),
]

JUN_JUL = [
    (["Receive", "Risk Screen", "Queue Routed", "Standard Review",
      "Decision", "Notify"], 270),
    (["Receive", "Risk Screen", "Queue Routed", "Enhanced Review",
      "Compliance Check", "Decision", "Notify"], 145),
    (["Receive", "Risk Screen", "Queue Routed", "Standard Review",
      "Notify", "Decision"], 70),
    (["Receive", "Risk Screen", "Standard Review", "Decision", "Notify"], 90),
    (["Receive", "Classify", "Queue Routed", "Standard Review",
      "Decision", "Notify"], 30),
    (["Receive", "Risk Screen", "Queue Routed", "Enhanced Review",
      "Decision", "Notify"], 25),
    (["Receive", "Risk Screen", "Queue Routed", "Manual Override",
      "Standard Review", "Decision", "Notify"], 20),
]

AUG_SEP = [
    (["Receive", "Risk Screen", "Queue Routed", "Standard Review",
      "Decision", "Notify"], 210),
    (["Receive", "Risk Screen", "Queue Routed", "Enhanced Review",
      "Compliance Check", "Supervisor Sign-off", "Decision", "Notify"], 150),
    (["Receive", "Risk Screen", "Queue Routed", "Enhanced Review",
      "Compliance Check", "Decision", "Notify"], 90),
    (["Receive", "Risk Screen", "Queue Routed", "Standard Review",
      "Supervisor Sign-off", "Decision", "Notify"], 60),
    (["Receive", "Risk Screen", "Queue Routed", "Standard Review",
      "Notify", "Decision"], 45),
    (["Receive", "Risk Screen", "Queue Routed", "Enhanced Review",
      "Decision", "Notify"], 30),
    (["Receive", "Risk Screen", "Queue Routed", "Manual Override",
      "Standard Review", "Decision", "Notify"], 35),
]

PERIODS = {"Apr-May 2026": APR_MAY,
           "Jun-Jul 2026": JUN_JUL,
           "Aug-Sep 2026": AUG_SEP}


def expand(rows):
    """Counter-encoded variants -> list of traces (counts preserved)."""
    return [list(trace) for trace, count in rows for _ in range(count)]


def _shape_ok(log, rows):
    """Shape validation: guards against a silent signature mismatch."""
    traces = [list(t) for t in log]
    if len(traces) != sum(c for _, c in rows):
        return False
    lens = [len(t) for t in traces]
    return (max(lens) == max(len(t) for t, _ in rows)
            and min(lens) == min(len(t) for t, _ in rows))


def build_log(rows):
    """pm4py.parse_event_log_string: some releases take space-separated
    strings, others take list[list[str]].  Try both and validate the shape."""
    traces = expand(rows)
    for payload in ([" ".join(t) for t in traces], traces):
        try:
            log = pm4py.parse_event_log_string(payload)
        except Exception:
            continue
        if log is not None and _shape_ok(log, rows):
            return log
    raise RuntimeError("pm4py.parse_event_log_string signature mismatch")


raw_logs = {name: build_log(rows) for name, rows in PERIODS.items()}
for name, log in raw_logs.items():
    print("[log] %-14s traces=%d" % (name, len(log)))


# --------------------------------------------------------------------------
#    LOG -> FRAME  (adds synthetic timestamps and an extraction sequence)
# --------------------------------------------------------------------------
def log_to_frame(log):
    df = pm4py.convert_to_dataframe(log).reset_index(drop=True)
    # SYNTHETIC: the aggregates publish activity ORDER only.  These stamps make
    # the frame well-formed; they carry no information about real clock time.
    df[TS] = pd.Timestamp("2026-06-01 00:00:00") + pd.to_timedelta(
        range(len(df)), unit="s")
    df[TS] = pd.to_datetime(df[TS])
    # what warehouse-ingestion-time ordering effectively yields
    df["extract_seq"] = df.groupby(CASE).cumcount()
    return df


frames = {name: log_to_frame(log) for name, log in raw_logs.items()}


# --------------------------------------------------------------------------
# 6.  TRANSPARENT NORMALISATION PIPELINE
# --------------------------------------------------------------------------
def normalize(df, label_map=True, drop_technical=True):
    """(a) label alias, (b) technical-event removal. Fully explicit."""
    out = df.copy()
    if label_map:
        out[ACT] = out[ACT].replace({"Risk Screen": "Classify"})
    if drop_technical:
        out = out[out[ACT] != "Queue Routed"]
    return out.reset_index(drop=True)


def with_source_order(df, illustrative=True):
    """(c) order by the source-system sequence number.

    The supplied aggregates contain NO such column.  With illustrative=True we
    synthesise one for the known reversed Notify->Decision pair (consistent
    with the 11/70 screenshot checks) ONLY to demonstrate the direction of the
    repair.  This is NOT evidence.  Set illustrative=False once the real
    sequence column has been joined in.
    """
    out = df.copy()
    if "source_seq" not in out.columns:
        if not illustrative:
            print("!! no source-system sequence column: ordering repair skipped")
            return out
        print("!! ILLUSTRATIVE ordering: source_seq is synthesised, not observed")
        seq = pd.Series(index=out.index, dtype="int64")
        for _, g in out.groupby(CASE, sort=False):
            acts = list(g[ACT])
            s = list(range(len(acts)))
            if "Notify" in acts and "Decision" in acts:
                i, j = acts.index("Notify"), acts.index("Decision")
                if i < j:                       # source recorded Decision first
                    s[i], s[j] = s[j], s[i]
            seq.loc[g.index] = s
        out["source_seq"] = seq

    out = out.sort_values([CASE, "source_seq"], kind="stable").reset_index(drop=True)
    # re-stamp so that any timestamp-based sorter agrees with the new order
    out[TS] = pd.Timestamp("2026-06-01 00:00:00") + pd.to_timedelta(
        range(len(out)), unit="s")
    out[TS] = pd.to_datetime(out[TS])
    return out.drop(columns=["source_seq"])


# --------------------------------------------------------------------------
# 4-5.  DFG + ALIGNMENT HELPERS
# --------------------------------------------------------------------------
def discover_dfg(log):
    try:
        return pm4py.discover_dfg(log)
    except Exception:                                   # pragma: no cover
        from pm4py.algorithms.discovery.dfg.algorithm import apply as _dfg
        return _dfg(log)


def count_moves(diagnostics):
    """Dominant moves on log / on model from alignment diagnostics."""
    on_log, on_model = Counter(), Counter()
    for diag in diagnostics:
        for alignment in diag.get("alignments", []):
            steps = alignment[0] if isinstance(alignment, tuple) else alignment
            for step in steps:
                if not isinstance(step, (tuple, list)) or len(step) != 2:
                    continue
                lm, mm = step
                if lm == ">>" and mm != ">>":
                    on_model[mm] += 1
                elif mm == ">>" and lm != ">>":
                    on_log[lm] += 1
    return on_log, on_model


def _pct(value):
    """PM4Py returns some fitness measures as 0-1, others as 0-100."""
    return value if value > 1.0 else 100.0 * value


def precision_of(log, net, im, fm):
    for name in ("precision_token_based", "precision_etconformance_pt",
                 "precision_tbr"):
        fn = getattr(pm4py, name, None)
        if fn is None:
            continue
        try:
            return round(float(fn(log, net, im, fm)), 3)
        except Exception:                               # pragma: no cover
            continue
    return float("nan")


def evaluate(label, df, net, im, fm):
    fit = pm4py.fitness_alignments(df, net, im, fm)
    diags = pm4py.conformance_diagnostics_alignments(df, net, im, fm)
    on_log, on_model = count_moves(diags)
    return {
        "condition": label,
        "fit_traces_%": round(_pct(fit.get("percFitTraces", 0.0)), 1),
        "mean_fitness": round(_pct(fit.get("averageFitness", 0.0)), 1),
        "top_moves_on_log": ", ".join("%s x%d" % (k, v)
                                      for k, v in on_log.most_common(3)) or "-",
        "top_moves_on_model": ", ".join("%s x%d" % (k, v)
                                        for k, v in on_model.most_common(3)) or "-",
    }


# --------------------------------------------------------------------------
# 7-8.  COMPARISON
# --------------------------------------------------------------------------
def main():
    apr = frames["Apr-May 2026"]
    jj = frames["Jun-Jul 2026"]
    asf = frames["Aug-Sep 2026"]

    as_norm = with_source_order(normalize(asf, label_map=True,
                                          drop_technical=True),
                                illustrative=False)

    results = [
        # ---- baseline -----------------------------------------------------
        evaluate("Apr-May | raw log, normative model",
                 apr, norm_net, norm_im, norm_fm),
        # ---- staged normalisation on Jun-Jul ------------------------------
        evaluate("Jun-Jul | raw log, normative model",
                 jj, norm_net, norm_im, norm_fm),
        evaluate("Jun-Jul | + label map Risk Screen->Classify",
                 normalize(jj, label_map=True, drop_technical=False),
                 norm_net, norm_im, norm_fm),
        evaluate("Jun-Jul | + label map + remove Queue Routed",
                 normalize(jj, label_map=True, drop_technical=True),
                 norm_net, norm_im, norm_fm),
        evaluate("Jun-Jul | + label + remove + source ordering",
                 with_source_order(normalize(jj, True, True)),
                 norm_net, norm_im, norm_fm),
        # ---- model comparison on Aug-Sep ----------------------------------
        evaluate("Aug-Sep | normalised, NORMATIVE model",
                 as_norm, norm_net, norm_im, norm_fm),
        evaluate("Aug-Sep | normalised, CANDIDATE (optional sign-off)",
                 as_norm, cand_net, cand_im, cand_fm),
    ]
    print("\n=== RAW vs NORMALISED, and NORMATIVE vs CANDIDATE ===")
    print(pd.DataFrame(results).to_string(index=False))

    # ---- fitness must always be read together with precision -------------
    print("\n=== FITNESS + PRECISION (over-permissiveness check) ===")
    prec_rows = []
    for lbl, frame, net, im, fm in [
        ("Apr-May / normative", apr, norm_net, norm_im, norm_fm),
        ("Aug-Sep / normative", as_norm, norm_net, norm_im, norm_fm),
        ("Aug-Sep / candidate", as_norm, cand_net, cand_im, cand_fm),
    ]:
        fit = pm4py.fitness_alignments(frame, net, im, fm)
        prec_rows.append({
            "condition": lbl,
            "fitness_%": round(_pct(fit.get("log_fitness",
                                             fit.get("averageFitness", 0.0))), 1),
            "precision": precision_of(frame, net, im, fm),
        })
    print(pd.DataFrame(prec_rows).to_string(index=False))
    print("Interpretation rule: fitness up + precision down = fitness bought "
          "by permissiveness, not by conformance.")

    # ---- 4. DFG evidence --------------------------------------------------
    print("\n=== SELECTED DFG RELATIONS (Aug-Sep, fully normalised) ===")
    dfg, start_act, end_act = discover_dfg(as_norm)
    for src, dst in [
        ("Receive", "Classify"),
        ("Classify", "Standard Review"),
        ("Classify", "Enhanced Review"),
        ("Enhanced Review", "Compliance Check"),
        ("Enhanced Review", "Decision"),           # missing check
        ("Compliance Check", "Supervisor Sign-off"),
        ("Standard Review", "Supervisor Sign-off"),
        ("Supervisor Sign-off", "Decision"),
        ("Notify", "Decision"),                    # should be 0 after ordering
    ]:
        print("  %-20s -> %-20s : %d" % (src, dst, dfg.get((src, dst), 0)))
    print("  start activities:", start_act)
    print("  end   activities:", end_act)

    # ---- contamination audit ---------------------------------------------
    print("\n=== CONTAMINATION AUDIT (before -> after normalisation) ===")
    for name, raw in frames.items():
        norm = normalize(raw, True, True)
        print("  %-14s Risk Screen %4d -> %4d | Queue Routed %4d -> %4d"
              % (name,
                 int((raw[ACT] == "Risk Screen").sum()),
                 int((norm[ACT] == "Risk Screen").sum()),
                 int((raw[ACT] == "Queue Routed").sum()),
                 int((norm[ACT] == "Queue Routed").sum())))

    print(CAVEATS)
```

## 7. Provisional conclusion

**Primary explanation for the measured collapse — confidence  90/100.** The conformance deterioration is predominantly a measurement-pipeline failure, not a process failure. Between April–May (93% fitting) and June–July (32%), roughly 57 of the ~61 lost fitness points are recovered by three data-side repairs that map cleanly onto dated technical changes: remapping `Risk Screen` to `Classify` (+26, after the 31 May UI release), removing the gateway's `Queue Routed` (+23, after 3 June), and ordering by source sequence rather than warehouse-ingestion time (+8, after 15 June). Each repair is monotone, isolated and reversible, none touches business outcomes, and a 40-case audit independently confirms the rename. The August–September deterioration is a separate and legitimate mechanism: a 1 August sign-off requirement that a control-flow-only tree never absorbed costs ~23 points (66% under preprocessing identical to Jun–Jul's 89%) and is recovered to 86% by a candidate model.

**A real compliance concern may remain — confidence  45/100.** After full preprocessing and model extension, about 7 points of residual deviation persist, concentrated in enhanced reviews with no recorded `Compliance Check` (25 then 30 traces) and `Manual Override` (20 then 35). Because April–May recorded the check in 180 of 180 cases, the regression is genuine *in the log*; but no audit yet separates a bypassed step from an unlogged one, and resource-attribution loss rising 1.2%  6.4% blocks reviewer-level analysis. Flat appeal and approval rates neither convict nor exonerate, given compliance's own admission of incomplete detection.

**Immediate actions.** *IT:* version the label and gateway event contract; dual-write source sequence alongside ingestion time; demote `Queue Routed` to a technical lifecycle; repair resource capture. *Process owners:* release a versioned tree containing conditional sign-off and register the EUR 50,000 attribute as a mandatory stratifier. *Compliance:* commission the 55-case audit, and once resources are complete, a reviewer-level deviation study.

**What must not be claimed yet:** that reviewers are noncompliant; that the extended model is correct (precision is unmeasured); that stable appeal rates demonstrate conformance; or that post-repair fitness equals regulatory compliance.

## 8. Model-governance recommendation

1. **Model versioning.** Every normative process tree carries a version identifier, effective date, named owner and change log. A policy or regulation that changes the process without a corresponding model release is a blocking defect tracked like a schema migration; conformance jobs declare the model version they used, and results from two versions are never placed in the same trend line.

2. **Event-semantic contracts.** Each activity label in the model is bound to a documented, versioned contract naming the source system, field, transformation and business function it represents. A UI relabel is permitted only if ingestion emits a declared, tested, reversible alias (or the model is released in the same change window); undeclared label changes fail the pipeline rather than silently entering conformance.

3. **Technical-event policy.** Gateway and infrastructure events are published in a separate lifecycle/technical namespace and are excluded from application-activity analysis by an explicit whitelist. Emitting any new technical event requires a conformance-impact assessment; partial coverage of a technical event must be explained by sampling rules, never discovered as a fitness drop.

4. **Timestamp provenance.** Every event stores source-system time *and* source-system sequence number *and* warehouse-ingestion time, with the conformance job ordering by source sequence by default. Ingestion-only ordering is flagged as a data-quality incident, and any conformance report without provenance columns is void.

5. **Data-aware constraints.** Control-flow models are paired with declarative or conditional constraints (here: `Supervisor Sign-off` required iff amount > EUR 50,000); key case attributes are mandatory inputs to conformance reporting and every fitness figure is published alongside precision and attribute-stratified breakdowns, so that a more permissive model can never be mistaken for a more conformant one.

6. **Post-release validation.** Every UI, gateway or ETL release triggers an automated pre/post conformance diff — weekly variant and frequency-DFG series, fitness and precision deltas, label and technical-event counts — with a threshold that blocks promotion until the movement is attributed to *process*, *model*, or *measurement*. No release closes without that attribution.
