## 1. Normalization Assumptions

- **Clock-offset direction:** `clock_offset = recorded_clock - true_clock`. Therefore `true_time = recorded_time - offset`, with `offset in [a,b]`; so a recorded interval `[Rlo,Rhi]` becomes `[Rlo - b, Rhi - a]`.
- **Resolution first:** timestamp rounding/flooring is applied to the recorded clock time before clock-offset correction.
- **HUB:** displayed second plus ±0.5 s measurement uncertainty, then offset [-1,+1] s, gives ±1.5 s around the displayed time.
- **OPS-BER:** displayed minute is a floor interval `[MM:SS, MM:SS+60)`; CEST = UTC+2. Normal offset is [-90,+120] s; T-409 uses weak offset [-720,+720] s because NTP diagnostics are missing.
- **SENSOR:** rounded to nearest 10 s, so the clock time is within ±5 s; offset [-5,+5] s gives combined ±10 s around the displayed second.
- **VENDOR-NY:** floored minute, EDT = UTC-4, offset [-180,+180] s.
- **LEGACY-BER:** floored minute, ambiguous DST fold on `2025-10-26 02:00..02:59`. Two alternative UTC intervals are retained: fold 0 = CEST (UTC+2) and fold 1 = CET (UTC+1), each with offset [-60,+60] s.
- **T-405 order constraint:** ingestion sequence says Investigation_Start is after Alert_Received and Containment_Complete is after Investigation_Start. Among the DST alternatives, only **Alert=CEST, Investigation=CET, Containment=CET** survives that ordered sequence.
- **T-404 inferred start:** Investigation_Start = Investigation_Complete  investigation duration, with duration uncertainty [1080,1500] s. No midpoint is used as a substitute for the interval.
- **T-407 inferred receipt:** Alert_Received = Alert_Sent + delivery latency, with latency [0,1200] s. I do **not** impose “receipt must be before Investigation_Start” as a hard constraint because the prompt labels it plausible but not directly logged.
- **MOBILE-LON entry delay:** I treat late entry as an additional delay between true occurrence and the entered/displayed time; it shifts the estimate of occurrence time **earlier** by up to 300 s, not merely the record-keeping time. This is material for T-406.
- **Default temporal-profile zeta:** Section 3 uses **zeta = 1** for the baseline classifications; Section 4 reports zeta = 1, 2, 3 sensitivity.

from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo
import pandas as pd
import pm4py


def merge_intervals(intervals):
    """Merge overlapping/touching timedelta intervals."""
    intervals = sorted(intervals)
    merged = []
    for lo, hi in intervals:
        if not merged or lo > merged[-1][1]:
            merged.append([lo, hi])
        else:
            merged[-1][1] = max(merged[-1][1], hi)
    return [(lo, hi) for lo, hi in merged]


def apply_clock_offset(rec_start, rec_end, offset_low, offset_high):
    """
    true_time = recorded_time - offset.
    offset in [offset_low, offset_high].
    """
    return (
        rec_start - timedelta(seconds=offset_high),
        rec_end - timedelta(seconds=offset_low),
    )


def hub_interval(iso):
    dt = datetime.fromisoformat(iso)
    rec_start = dt - timedelta(seconds=0.5)
    rec_end = dt + timedelta(seconds=0.5)
    return apply_clock_offset(rec_start, rec_end, -1, 1)


def floor_minute_utc(iso, tz):
    dt = datetime.fromisoformat(iso).replace(tzinfo=ZoneInfo(tz))
    start_local = dt
    end_local = dt + timedelta(seconds=60)
    return (
        start_local.astimezone(timezone.utc),
        end_local.astimezone(timezone.utc),
    )


def round_interval_utc(iso, seconds, tz=None):
    dt = datetime.fromisoformat(iso)
    if tz is not None:
        dt = dt.replace(tzinfo=ZoneInfo(tz))
    half = timedelta(seconds=seconds / 2)
    start = (dt - half).astimezone(timezone.utc)
    end = (dt + half).astimezone(timezone.utc)
    return start, end


def ops_ber(iso, offset_low=-90, offset_high=120):
    start, end = floor_minute_utc(iso, "Europe/Berlin")
    return apply_clock_offset(start, end, offset_low, offset_high)


def sensor(iso):
    start, end = round_interval_utc(iso, 10)
    return apply_clock_offset(start, end, -5, 5)


def vendor_ny(iso):
    start, end = floor_minute_utc(iso, "America/New_York")
    return apply_clock_offset(start, end, -180, 180)


def legacy_ber(iso):
    """DST-fold ambiguous intervals: fold 0 = CEST, fold 1 = CET."""
    dt = datetime.fromisoformat(iso)
    out = []
    for fold in (0, 1):
        start_local = dt.replace(tzinfo=ZoneInfo("Europe/Berlin"), fold=fold)
        end_local = start_local + timedelta(seconds=60)
        start_utc = start_local.astimezone(timezone.utc)
        end_utc = end_local.astimezone(timezone.utc)
        out.append(apply_clock_offset(start_utc, end_utc, -60, 60))
    return out


def mobile_lon(iso):
    """
    Round to nearest minute, mobile clock offset [-300,300] s,
    plus user-entry delay [0,300] s shifting occurrence earlier.
    """
    start, end = round_interval_utc(iso, 60, "Europe/London")
    clock_corrected = apply_clock_offset(start, end, -300, 300)
    return (
        clock_corrected[0] - timedelta(seconds=300),
        clock_corrected[1],
    )


def duration_intervals(a_intervals, b_intervals):
    """Feasible B - A durations over all interval combinations."""
    out = []
    for a_start, a_end in a_intervals:
        for b_start, b_end in b_intervals:
            out.append((b_start - a_end, b_end - a_start))
    return merge_intervals(out)


def classify_interval(lo, hi, alow, ahigh):
    if alow is not None and hi < alow:
        return "CERTAIN_VIOLATION"
    if ahigh is not None and lo > ahigh:
        return "CERTAIN_VIOLATION"
    if alow is not None and lo < alow:
        return "POSSIBLE_VIOLATION"
    if ahigh is not None and hi > ahigh:
        return "POSSIBLE_VIOLATION"
    return "CERTAIN_PASS"


def overall_classification(intervals, alow, ahigh, tol_seconds=0):
    classes = set()
    for lo, hi in intervals:
        alow_adj = alow + timedelta(seconds=tol_seconds) if alow is not None else None
        ahigh_adj = ahigh + timedelta(seconds=tol_seconds) if ahigh is not None else None
        classes.add(classify_interval(lo, hi, alow_adj, ahigh_adj))
    if "CERTAIN_VIOLATION" in classes and "CERTAIN_PASS" in classes:
        return "POSSIBLE_VIOLATION"
    if "POSSIBLE_VIOLATION" in classes:
        return "POSSIBLE_VIOLATION"
    if "CERTAIN_VIOLATION" in classes:
        return "CERTAIN_VIOLATION"
    return "CERTAIN_PASS"

print("The interval-based classifications above are authoritative for uncertainty analysis.")

## 6. Evidential Sufficiency

The following table identifies the minimum additional evidence that would make a currently **POSSIBLE_VIOLATION** result certain. The same evidence generally tightens the interval enough to place it wholly inside or wholly outside the relevant SLA threshold / temporal band.

| Case / rule(s) | Cause of possible violation | Minimum additional evidence needed |
|---|---|---|
| T-401 S1 / ARI | OPS-BER floored minute and clock offset | Exact OPS-BER seconds and tighter NTP offset bound; or a HUB timestamp for Investigation_Start |
| T-402 S2 / ISCC | OPS-BER floor/offset makes the end of investigation uncertain | Exact Investigation_Start and Containment_Complete timestamps, or tighter OPS-BER offset |
| T-403 S1 / ARI, ARCC | VENDOR-NY floored minute and wide offset | Exact VENDOR-NY time or a HUB-confirmed Alert_Received timestamp; tighter vendor clock sync |
| T-404 S1 / ARI, S2 / ISCC | Investigation_Start is inferred from completion minus duration | Direct Investigation_Start timestamp, or exact duration from the signed work record |
| T-405 S1 / ARI | DST fold not logged; floor/offset ambiguity | Explicit DST fold log, or primary UTC timestamp; exact seconds/tighter clock offset |
| T-406 S1 / ARI, S2 / ISCC | Mobile user entry delay and wide clock offset | App-generated Investigation_Start timestamp; separate log of user-entry delay; tighter mobile clock offset |
| T-407 S1 / ARI | Alert_Received missing; no receipt acknowledgment | Receipt acknowledgment or delivery-log evidence for the actual Alert_Received time |
| T-409 S1 / ARI, ISCC | OPS-BER NTP diagnostics missing; only ±12 min estimate | OPS-BER NTP diagnostics for that hour; non-floored exact second timestamp |

If the mobile entry delay in T-406 were treated as only a record-time shift rather than an occurrence-time shift, T-406 S2 would become a certain pass, but T-406 S1 would remain possible. This shows that the semantics of user-entry delay are decision-relevant and should be recorded explicitly.

## 7. Governance Recommendation

- **Store UTC as the primary timestamp** for every event, but **retain the original raw local timestamp** exactly as received. Never discard source-native values.
- **Require per-source clock-offset telemetry** with every event or at least per hour. The current cases show that offset bounds are decision-relevant.
- **Record timestamp resolution/rounding semantics** in metadata: exact, floor-to-minute, round-to-nearest-10s, etc. Do not infer rounding semantics after the fact.
- **Record lifecycle semantics explicitly:** Alert_Sent, Alert_Received, Investigation_Start, Investigation_Complete, Containment_Complete, and Close_Incident should be separate named events with clear definitions. Avoid using `Investigation_Complete` as a proxy for `Investigation_Start`.
- **Log DST fold** for local-time sources in time zones with daylight-saving transitions. Even better, send an authoritative UTC timestamp from the device, with local time as display-only.
- **Add causal identifiers** so activity pairs can be logically linked: `alert_id`, `investigation_id`, `containment_id`, `incident_id`. This would eliminate missing-receipt and missing-start inference problems.
- **Require receipt acknowledgments** for alerts that trigger SLA clocks. Do not use `Alert_Sent` as if it were `Alert_Received`.
- **For user-entered timestamps, log entry delay separately** and define whether the delay is part of occurrence-time uncertainty or only record-creation latency.
- **Set an enforcement policy for interval overlap:** if a feasible duration interval overlaps the SLA threshold, treat it as **possible non-compliance** requiring manual review, not as a pass. Conversely, do not declare a certain violation unless every feasible duration violates the rule.
- **For temporal-profile conformance**, use interval-based conformance for operational decisions. Midpoint-only PM4Py conformance is acceptable only as an exploratory diagnostic, never as proof of compliance or breach.
