Section 2: Equivalence and sufficiency test. Dimensions: timing (T), independence (I), coverage (C), overrideability (O), recoverability (R), evidence quality (E), collusion resistance (K). Define scoring  FULLY EQUIVALENT / PARTIALLY EQUIVALENT / MERELY MITIGATING / INEFFECTIVE. Rules:
- Full equivalence: all seven dimensions at target level: at least one preventive control with decision rights before the point of no return covering the same threat, by an independent actor with evidence of substantive review, non-defeatable by the preparer (override requires independent credential + logged rationale), recall path open at decision time (audit before settlement+24h), coverage  the checks AV-2 lacks for the specific threat (e.g., receipt verification), and collusion resistance adequate (pair analytics clear, no shared credential/workstation red flags).
- Partially equivalent: timing met, independence met, but coverage short on 1 threat dimension, or evidence quality weak (rubber stamp).
- Merely mitigating: control exists and reduces expected severity/frequency but cannot block the loss chain (post-release only, or after recall window, or conflicted approver, or overrideable by preparer).
- Ineffective: control absent, outaged, conflicted, post-recall, or overridden by the controlled party.

Also add "monotonicity/conjunctive rule": the package is only as strong as the weakest objective-critical dimension for the specific threat scenario — i.e., equivalence is assessed per threat scenario then aggregated by the maximum residual exposure, not by average. Because losses are not fungible (a €900k unrecoverable diversion isn't offset by a perfectly executed duplicate check).

Why "same expected loss" isn't the only standard:
1. Distributional/tail considerations: expected loss hides variance and tail; a 900k possible loss with 1% probability (9k EV) may be unacceptable vs. the risk appetite and capital.
2. Option value and irreversibility: settlement is irreversible  asymmetric payoffs; controls that preserve optionality (can stop/recall) have value beyond EV.
3. Non-quantifiable harms: regulatory breach, sanctions, criminal liability, reputation, license — not reducible to EUR.
4. Information/agency effects: a control that can be overridden by the controlled party corrupts the evidence base; the loss includes loss of assurance/information, and incentives (moral hazard).
5. Correlation: losses across cases share root causes (same pair, same credential)  EV understates portfolio risk; tail dependence.
6. Auditability/assurance: absence of evidence has value/cost independent of expected loss (assurance standard, ISA/ SOC).
7. Legal/regulatory safe harbors: conforming to the designed control may be an obligation regardless of EV (a control objective is deontological, not just consequentialist).
8. Cost of control is not the only comparator; also feasibility of detection.

```python
def case_ids(obj):
    if obj is None: return set()
    if isinstance(obj, pd.DataFrame):
        for c in ("case:concept:name", "case_id", "case:concept:name".strip()):
            if c in obj.columns: return set(obj[c].dropna().unique())
        return set()
    # pm4py EventLog / list of traces
    try:
        ids = []
        for tr in obj:
            attrs = getattr(tr, "attributes", {}) or {}
            cid = attrs.get("case:concept:name") or attrs.get("case_id") or attrs.get("concept:name")
            if cid is not None: ids.append(cid)
        return set(ids)
    except Exception:
        return set()
```

### 2. Equivalence and Sufficiency Test

Define T-I-C-O-R-E-K dimensions with pass criteria, then a decision rule producing4 grades, plus per-threat aggregation rule (max-residual, not average). Then why not only "same expected loss".

Let me formalize:

For each threat scenario s in {O1..O8} and case c, the compensating package P = {AV-2, MG-4, RA-7, ED-1} evaluated on:
- T Timing: does at least one control in P have a decision point before the point of no return (settlement) for the loss associated with s? Grade: T2 = pre-release; T1 = pre-settlement; T0 = post-settlement.
- I Independence: is the deciding actor independent from preparer AND releaser, non-conflicted, on own credentials? I2/I1(conflicted or credential shared)/I0.
- C Coverage: does some control in P actually examine the attributes relevant to s? C2 (covers the attribute), C1 (adjacent proxy — e.g., PO match for receipt), C0 (no coverage).
- O Overrideability: can the party being constrained defeat the control? O0 non-defeatable (hard block, independent override credential), O1 defeatable only with independent credential + logged reason, O2 defeatable by preparer (self-override)  O2 is disqualifying.
- R Recoverability: at the moment of detection, is a stop/recall/recovery path still open? R2 (pre-release, can cancel), R1 (within settlement+24h, recall plausible), R0 (after, uncertain).
- E Evidence quality: is there contemporaneous, attributable evidence that the reviewer examined invoice, bank details, and receipt? E2 documented & substantive, E1 present but shallow (ratify/rubber stamp), E0 absent/unsigned.
- K Collusion resistance: are the actors demonstrably separate (distinct credentials, distinct devices, no repeated pairing concentration, no conflict graph edge)? K2/K1/K0-unknown.

Grade rules (conjunctive, weakest-link per threat):
- FULLY EQUIVALENT for threat s:  control chain covering s with TT1, I=I2, C=C2, OO1, RR1, E=E2, KK1 — and no disqualifier (O=O2 by the controlled party, I=I0, R=O0...).
- PARTIALLY EQUIVALENT: TT1 and I=I2 and (C=C1 or E=E1 or K=K0) — objective substantially addressed, one or more soft gaps.
- MERELY MITIGATING: only detective controls with RR1 and no preventive gate (i.e., reduces severity/frequency but does not break the causal chain), or preventive control exists but C=C0 for that threat.
- INEFFECTIVE: control absent, outaged, self-overridden, conflicted, or R=0 for the relevant threat.

Case-level grade = the grade of the worst-covered *material* threat (material = plausible given amount/vendor/bank facts), i.e., a max-residual rule; a package cannot be "fully equivalent" overall if any material threat is merely mitigating or ineffective — because threats are not additive and not fungible. Formally: grade_overall = min over material threats of grade(s), with ties broken by exposure magnitude, not by counting controls.

Also: monotonicity requirement — adding a late detective control cannot upgrade a package past "merely mitigating" for a threat already past the point of no return; timing has lexicographic priority over count.

Why not only same expected loss: (list ~7 reasons as above). Also: EV equality across cases is not observable (we don't have calibrated probabilities; the evidence is qualitative), and the standard must be auditable by a third party  a rule-based, dimension-based test is reproducible; EV-based requires calibration the firm does not have. Also asymmetric consequences (unrecoverable > recoverable), and control-design obligations are often non-consequentialist (regulatory). Also the "same EV" standard would license replacing a strong preventive control with cheap post-hoc monitoring — which changes incentives and the evidence base (moral hazard), a cost not in EV.

```python
    """Extract case identifiers from whatever PM4Py returned (df / EventLog / list)."""

        return set()
    if isinstance(obj, pd.DataFrame):

            cid = attrs.get("case:concept:name") or attrs.get("case_id") or attrs.get("concept:name")
```

## 1. Control-Objective Decomposition

FEP-1 is written as a single sentence ("prepare  release"), but it encodes several *different* objectives protecting against *different* loss mechanisms. Grading a package by whether two activity names were executed by two account names collapses all of them.

Legend used below: **P** = can *prevent* the threat; **D** = can *detect* it; **C** = can *correct* it (stop, recall or recover, within an open window); **X** = fails to address it; **P\*** = conditional (only under stated preconditions).

| # | Objective / threat scenario | AV-2 | MG-4 | RA-7 | ED-1 |
|---|---|---|---|---|---|
| **O1** | **Separation of initiation from authorization** — one human both initiates and authorizes an erroneous or fraudulent transfer (single-actor control takeover) | **X** for the human dimension (it validates *data*, not *actors*); **P** only incidentally when it hard-blocks the payment regardless of actor (AP-205) | **P\*** independent L3+ before release  full prevention of *content* authorization; **hybrid P** if before settlement (cannot restore two-person release); **D** if post-settlement; **X** if conflicted or on a shared credential (m09) | **D** (identifies same-user completion); **C** only if still inside the recall window *and* recall is actually initiated | **X** as a rule — it *permits* an exception rather than restoring two-human separation; its seven conditions only re-distribute O2–O7 coverage |
| **O2** | **Authenticity of the underlying obligation** — goods/services received, invoice genuine, commercial reasonableness | **X** by design (basic PO match  receipt evidence) | **P\*** only if the reviewer actually inspects invoice, bank details and receipt; **X** if rubber-stamped | **D** (AP-204 found a fabricated receipt); **C** only if recall still open | **X** — condition 5 explicitly does not establish receipt |

1. **AV-2 is strong on O3/O4 and structurally silent on O1, O2, O6.** A clean AV-2 pass is evidence about duplicate/sanction/ownership/limit/PO attributes only; it says nothing about receipt, collusion, or who controlled an account. Treating it as general assurance is the most common over-credit.

## 2. Equivalence and Sufficiency Test

### 2.1 The test

For a case *c* and a threat *s* (O1–O8), the package is *P* = {AV-2, MG-4, RA-7, ED-1}. I score seven dimensions; each grade is objective-relative, because **"preventive" is not a property of an activity — it is a property of an (activity, objective) pair**.

| Dim | Question | Grade 2 (target) | Grade 1 | Grade 0 (disqualifying) |
|---|---|---|---|---|
| **T — Timing** | Does some control have decision rights *before the point of no return for loss s*? | T2: before Release_Payment | T1: after release but strictly before settlement | T0: after settlement |
| **I — Independence** | Is the deciding actor independent of preparer *and* releaser, non-conflicted, on own credentials? | I2: independent, no conflict edge, own credential | I1: independence asserted but unverified | I0: conflict (ratings line), or credential shared/used by another |
| **C — Coverage** | Does a control actually examine the attributes relevant to *s*? | C2: the attribute itself (e.g., receipt for O2, ownership for O3) | C1: adjacent proxy (PO match for receipt) | C0: no coverage |
| **O — Overrideability** | Can the party being constrained defeat the control? | O0: hard block, or override only by an independent credential with logged reason | O1: override possible with independent credential + rationale | **O2: self-override by preparer** (disqualifying) |
| **R — Recoverability** | At the moment of detection, is a stop/recall/recovery path still open? | R2: pre-release, can cancel | R1: within settlement + 24 h, recall plausible | R0: after, recovery uncertain |
| **E — Evidence quality** | Contemporaneous, attributable proof that invoice, bank details and receipt were examined? | E2: documented and substantive | E1: present but shallow ("Ratify", < seconds dwell, unsigned checklist) | E0: absent |
| **K — Collusion resistance** | Are the actors demonstrably separate? | K2: distinct credentials + distinct devices + no conflict edge | K1: distinct accounts, device/design evidence missing | K0: shared device, repeated pairing concentration, or unknown |

**Grading rule (conjunctive / weakest-link, per threat):**

- **FULLY EQUIVALENT** for *s*:  a control chain with **TT1, I=I2, C=C2, OO1, RR1, E=E2, KK1**, and no disqualifier.
- **PARTIALLY EQUIVALENT**: TT1 and I=I2, but (C=C1 **or** E=E1 **or** K=K1) — substantially addressed, soft gaps remain.
- **MERELY MITIGATING**: only detective controls for *s* (RR1) with no gate that can stop the transition — the package reduces frequency or severity but does **not** break the causal chain; or a preventive control exists with C=C0 for *s*.
- **INEFFECTIVE**: control absent, outaged, self-overridden, conflicted, or R=0 for *s*.

**Case-level rule (aggregation):**

> **Overall grade = the grade of the worst-covered *material* threat**, where "material" = plausible given that case's amount, vendor age, bank-change proximity and control availability. Ties broken by *exposure magnitude*, never by counting activities.

Two corollaries:

- **Timing has lexicographic priority over count.** Adding a late detective control can never upgrade a package past *merely mitigating* for a threat that already crossed the point of no return. Ten activities after settlement = one grade, not ten.
- **The package cannot be "fully equivalent" overall** if any material threat is merely mitigating or ineffective. Threats are not additive: a perfect duplicate check does not offset an unverified beneficiary on a €900 k transfer.

Applying this mechanically to the extract: AP-203 and AP-207 clear all seven dimensions for every material threat (T1/T2, I2, C2 on their threat set, O1, R1, E2, K2)  fully equivalent; AP-201 fails T1T1 *and* O7/ED-1 condition 1 (no token) with E1 on the manager review  partially equivalent; AP-202 hits **O2 + I0 + R0**  ineffective; AP-208 hits **T0 + C0 + O0 + R0**  ineffective.

### 2.2 Why "same expected loss" is not the only possible standard

1. **Expected value hides distribution.** €480 k at an unquantified probability and €900 k with no bank-ownership evidence can have modest EV while carrying unacceptable variance and tail. Risk appetite is stated in tails (single-loss limits), not in EV.
2. **Irreversibility has option value not in EV.** A pre-settlement gate preserves the *option* to stop; a post-settlement audit does not. Two packages with equal EV differ sharply in retained optionality.
3. **Some harms are not denominated in euros** — sanctions breach, criminal liability, licence, regulatory findings, restatement. These are non-fungible with control cost and cannot be netted into one number.
4. **EV equality requires calibration the firm does not have.** No defensible probabilities exist for collusion or credential sharing here; any EV comparison would be an invented number dressed as analysis. A dimension-based, rule-referenced test is *reproducible by a third party*, which an EV test is not.
5. **Defeatability corrupts the evidence base (moral hazard).** A control the controlled party can override (AP-202) degrades assurance itself — a cost that never appears in a loss EV but destroys the reliability of every downstream metric.
6. **Losses are correlated, not independent.** Repeated pairing (u12/u13), a shared override credential, or an unmonitored control outage are *common causes*; summing per-case EVs understates portfolio risk badly.
7. **Control objectives are partly deontological.** FEP-1 exists as a designed obligation with an exception procedure (ED-1); conformance is judged against the design, not against a posterior cost–benefit. A firm may not waive an authorization control because the expected loss looks small.

## 4. Preventive–Detective–Corrective Comparison

### 4.1 Semantics I adopt

Grades are assigned against the **point of no return for the loss**, which is **bank settlement** (irrevocable for internal-control purposes) — not against the release event.

- **Preventive**: has *decision authority* over a transition into the harmful state **and exercises it before that transition**. Preventiveness is graded against the state the control can actually stop, and is **objective-relative**.
- **Detective**: observes a defect after the transition it could have controlled has already occurred, with no authority or mechanism to reverse it.
- **Corrective**: after detection, an available, timely **and exercised** mechanism stops, recalls or recovers. Corrective capacity is a **window**, roughly `[settlement, settlement + 24 h]`, not an event.

**Manager action after Release_Payment but before settlement  HYBRID.** It is *detective with respect to the release act* (the release already happened with one actor; no ratification can restore two-person release, so it is never preventive for **O1**) and *preventive with respect to the loss* (settlement has not occurred; a hold or cancel prevents irrevocable diversion, so it is preventive for **O3/O5**). I credit the preventive half only when all four hold: (i) timestamp strictly before settlement; (ii) documented authority **and a working mechanism** to hold/cancel settlement; (iii) substantive independent review (E2, not a rubber stamp); (iv) no conflict edge and no shared credential. Failing any  detective-only; post-settlement  detective with the corrective window already expired.

Two generalisations worth stating:

1. **A pre-release MG-4 is strictly dominant over a post-release ratification for every objective** — it converts detective value into preventive value at zero extra cost in timing. Cases AP-203/AP-206 vs. AP-201/AP-207 show the same dollar-scale control doing different work purely because of *when* it fired.
2. **RA-7 is only "partly corrective" while the window is open *and* someone acts.** In this extract, three audits started after the window (202, 204, 208) — those are pure detection. Two started inside it (201 with ~1 h margin, 207 with ~4 h) — genuine but *fragile* correction, because detection time alone leaves little room to decide and instruct a recall.

## 5. Counterfactual and Residual-Risk Analysis

*(Qualitative ranges: negligible–low / low / low–moderate / moderate / high / very high. Any figure below is explicitly **illustrative**, not an estimate.)*

### AP-202 — bank-diversion to a related party
- **Loss mechanism:** new vendor + bank account changed 2 h before release + no receipt confirmation  €480 k transferred to an account controlled by an employee's relative; preparer raises and clears the AV-2 warning himself.
- **Chain-breaking control that *should* have fired:** AV-2's bank-change/ownership block, made non-self-overridable, or an independent pre-release MG-4 with conflict screening.
- **What remains exposed:** everything after release. MG-4 was conflicted and 2 days late; audit at 8 days is detection with no remedy. Residual: **very high — realized and unrecovered**.
- **Counterfactual with a truly independent second releaser:** a separate actor without m09's override credential would have faced the bank-change warning with no ability to clear it, and would have seen a new vendor with no receipt. Most likely outcome: release delayed pending ownership re-verification  loss prevented or reduced to a delay cost. Residual would drop to **low–moderate** (residual = the credential-sharing question: if m09's credential was in circulation, independence of *accounts* is not independence of *people*, and the counterfactual weakens sharply).

### AP-208 — €900 k release with no validation and no bank evidence
- **Loss mechanism:** validation service down; recent (3-day) bank change; unsigned manual checklist  transfer to a possibly-unverified account at the highest amount in the extract, settled before anyone independent looked.
- **Chain-breaking control that *should* have fired:** a hard stop on release while AV-2 is unavailable (control-outage rule), independent of amount.
- **What remains exposed:** no bank-ownership evidence *for the release moment*; recall window closed at exactly settlement + 24 h; audit on a Saturday, 115 h later. Residual: **critical/unbounded at release**, and now permanently unverifiable even though the payment was later judged legitimate.
- **Counterfactual with a truly independent second releaser:** near-certain intervention — a second person would have to release a €900 k payment to a 3-day-old bank account with *no automated validation and no signed checklist*. Even a modestly diligent second releaser stops or holds this. Residual would fall to **low–moderate** (the remaining exposure being that both actors share the same information vacuum if AV-2 remains down — which is why the outage rule, not the second person, is the primary fix).

### AP-204 — fabricated service receipt behind a formally valid two-person sequence
- **Loss mechanism:** payment for services never delivered; the invoice is internally consistent enough that duplicate/sanction/PO checks pass, and no human verifies the deliverable.
- **Chain-breaking control that *should* have fired:** MG-4 with receipt/deliverable inspection (the only control covering O2), pre-release.
- **What remains exposed:** O2 had **zero** preventive coverage; detection came at +94 h, roughly 3 days past recall; recovery undocumented. Residual: **high** — the realized defect plus unresolved independence.
- **Counterfactual with a truly independent second releaser:** *if* genuinely independent and reviewing deliverables, this is stopped pre-release — the single highest-value change for this case. *If* the second releaser is the same pair pattern (shared workstation, 37 co-approvals), the counterfactual adds almost nothing: AP-209 shows the identical pair clearing with no defect found, i.e. the pair's detection rate for fabrication is empirically unproven. Residual: **low** vs. **high** — the entire spread is a function of *independence quality*, not of activity count.

### AP-201 — €1.8 k same-user convenience payment
- **Loss mechanism:** low-probability human error or a low-value test of the same-user path (probe for control tolerance), rather than a headline fraud.
- **Chain-breaking control:** AV-2 clean pass plus an independent pre-settlement manager review; audit opened 1 h before recall expiry.
- **What remains exposed:** governance, not money — an unauthorized use of the exception path with no token, and E1-quality review evidence. Residual: **low** (financial), **low–moderate** (control-tolerance: if undetected/unflagged, it teaches the operator the rule is soft).
- **Counterfactual with a truly independent second releaser:** almost no change to the *loss* (the amount and vendor risk make a loss unlikely either way); a large change to *assurance*, because the two-person path would have been exercised rather than waived. This case is the clearest example where nominal violation and objective attainment diverge *in the tolerable direction* — still not conforming to ED-1, but not a material risk event.

### AP-206 — token minted after Prepare_Payment
- **Loss mechanism:** primarily a *governance* mechanism — an emergency exception whose precondition cannot be evidenced; secondary, an outage-driven release with a manager who approved before the validation result existed.
- **Chain-breaking control:** AV-2 full pass pre-release (13:05 < 13:08) and independent pre-release MG-4; audit at +18.9 h with ~7 h of recall margin.
- **What remains exposed:** the ambiguity itself. If the token timestamp is a logging delay  evidence failure (low economic risk, moderate assurance risk). If genuinely minted post-hoc  an unauthorized same-user release (moderate). Residual: **low economically, moderate on governance**.
- **Counterfactual with a truly independent second releaser:** minimal change to outcome — this package was already strong. The change would be *epistemic*: no reliance on a disputed token timestamp at all. Residual would become **low** with high confidence instead of low with medium confidence.

### AP-209 — same pair as AP-204, no defect found
- **Loss mechanism:** if u12/u13 are not genuinely independent (shared credentials/device, one queue operator), then any of O1/O2/O6 — including another fabricated receipt — passes unchallenged; "no defect found" would be a sampling artifact of a cooperative pair.
- **Chain-breaking control:** currently only AV-2 (O3/O4) and a timely audit (recall margin ~8 h) that *itself* depends on an auditor outside the pair.
- **What remains exposed:** O1 substance (is u13 a second actor?), O2 (nothing checks deliverables), O6 (pair concentration invisible to case-level controls). Residual: **low–moderate, indeterminate**.
- **Counterfactual with a truly independent second releaser:** if independence is already real, essentially no change (case is close to MET); if it is not, a *different, independently assigned* second releaser — not a third account in the same cell — converts this from indeterminate to **low**. Note the counterfactual is about *who*, not *how many*.

*(AP-203 and AP-207 are the positive controls: with a pre-release / pre-settlement independent approval and a same- or next-business-day audit inside the recall window, the counterfactual "remove ED-1" would leave only AV-2 — which cannot cover O2 or O6 — so ED-1 is doing real work there, not merely documenting an exception.)*

## 6. Evidence and Monitoring Recommendations

**Standing principle:** *an alert establishes that a control-relevant condition exists and triggers evidence collection; it does not establish intent, causation, knowledge, or misconduct.* Escalation tiers: **T1 signal** (metric breach  collect evidence)  **T2 control exception** (breach + missing evidence  hold/escalate to control owner)  **T3 suspected defect** (breach + corroborating artifact, e.g. fabricated receipt  investigation). Only T3 plus corroboration supports any statement about wrongdoing.

| Metric | Definition (from the log + bank feed) | Trigger | Tier | Alert vs. proof |
|---|---|---|---|---|
| **Same-user completion rate** | cases with `Prepare_Payment` resource = `Release_Payment` resource ÷ completed payments, per operator and per month | > 0 outside an **ED-1-eligible** case; operator rate > 5 % | T1; T2 if ED-1 conditions not all met | **Alert.** A violation of FEP-1 form; not evidence of error or fraud — AP-203/207 are legitimate |
| **ED-1 condition dashboard** | per same-user case, count of conditions 1–7 evidenced | any case with < 7/7 | T2 | **Alert**; missing evidence  breach occurred, but it is a reportable assurance gap |
| **Override rate** | `Override_Warning` ÷ `Automated_Validate_Warning` | > 10 % monthly; **any self-override** (preparer clears own warning) | **T2 immediately**; AP-202 pattern  T3 with credential evidence | Self-override is strong evidence the preventive control is defeatable — **not** proof the payment was wrong |
| **Credential-usage vs. assignment** | authenticated principal  entitlement owner for any override/approval (AP-202 override credential assigned to m09, used at 09:05) | any mismatch | **T3** | **Near-proof of credential sharing** (an access-control breach in itself) — still not proof the payment was fraudulent |
| **Late manager approval** | `Manager_Approve/Ratify` timestamp vs. release and settlement | post-release (hybrid, flag hold-authority evidence); **post-settlement**  T2; approval at/after settlement + 24 h  T2 | T1/T2 | **Alert** on timing only; independence and evidence quality must be assessed separately (m04 vs. m09) |
| **Manager independence graph** | reporting/ratings/conflict edges between approver and preparer/releaser | any edge (m09  u23) | **T2** (invalidates MG-4 credit) | **Structural proof that MG-4 cannot be credited** — not proof of collusion |
| **Audit-before-recall-window** | `audit_start  settlement + 24 h`, with **margin in hours**; plus `audit  release + 1 business day` | margin < 6 h (AP-201 = 1 h)  T1; window missed  T2 | T1/T2 | **Alert**; a missed window is a *recoverability* failure even when the payment is fine |
| **Audit coverage of same-user payments** | 100 % within 1 business day for **all** same-user completions, emergency or not (closes the RA-7 design gap exposed by AP-201/202) | < 100 % | T2 | **Alert** on coverage, not on outcome |
| **Repeated resource pairs** | (prepare, release) pair co-occurrence over rolling 30/90 d; concentration index; **in-extract count is a lower bound** on a sampled log |  5 co-approvals/30 d with no documented cell design (u12/u13 = 37/30 d) | T1  T2 if unexplained | **Alert.** A dedicated two-person cell is a legitimate design; without the design document the signal cannot be resolved |
| **Shared workstations / devices** | device-ID, SSO session, or IP shared by the preparer and the releaser **of the same payment** (or systematically across the pair) | any same-payment shared device | **T2  T3** if combined with a defect | Shared device on the same payment is close to **proof of non-independence** for that pair — *not* proof of fraud or even of error |
| **Bank-change proximity** | hours between bank-account change and release/settlement; ownership re-verification timestamp |  7 days  mandatory hard block unless independent ownership re-verification + L4 approval (AP-202 = 2 h; AP-208 = 3 d) | T2, release held | **Alert at release**; the *absence* of ownership evidence at release (AP-208) is an assurance failure regardless of later legitimacy |
| **Control outages** | `Validation_Service_Unavailable` / AV-2 downtime windows | **any release attempted or completed during outage**  hard stop by policy; reconcile release volume against outage windows | **T2 minimum**, T3 if amount > limit or bank changed | Outage + release is proof the compensating design was not enforced — not proof the payment is wrong |
| **Post-block release attempts** | `Attempt_Release` after `Automated_Validate_Block` (AP-205) | any occurrence | T1  T2 on repetition or on re-keyed invoice | **Alert** on behaviour; the block itself is proof prevention worked |
| **Emergency token discipline** | token activation vs. prepare time (AP-206: 13:02 > 13:00); tokens without a corroborating outage ticket; tokens without pre-settlement approval | token  prepare required; token without outage  T2 | T1/T2 | **Alert**; discrepancy may be logging latency — resolve with the source clock before asserting a breach |
| **Rubber-stamp detection** | dwell time between manager open and approve; attachments opened; checklist fields populated | review < 60 s or empty artifact set | T1  T2 | **Alert** on evidence quality (E1), not on the decision's correctness |
| **Log completeness** | `Bank_Settlement` present for every completed payment (missing for AP-201/202/203/204/205 in this extract); settlement reconciled to bank statement | any completed payment without settlement record | **T2** | Missing events make recall-window math impossible  an unmeasurable corrective capacity is itself a reportable gap |

**Additional recommendations**

1. **Collect, before any conclusion on u12/u13:** the payment-cell organizational design document, device/SSO binding for both accounts, credential-sharing test, preparerelease dwell times over 90 days, and deliverable evidence for the AP-204 invoice. Until then AP-209 stays INDETERMINATE by design, not by oversight.
2. **Hard-wire the outage rule:** release must be impossible while AV-2 is unavailable (AP-208), rather than relying on an unsigned manual checklist.
3. **Move MG-4 pre-release** for all same-user completions and for any payment above a threshold — this is the cheapest conversion of detective value into preventive value visible in this extract.
4. **Separate "override" from "override by an independent party":** an override credential must never be usable by the preparer of the same payment (AP-202), and override reasons must be structured, not free-text.
5. **Re-perform independently** on a rotating sample (re-execute the checks in §7 and re-inspect source documents) so that control-effectiveness metrics are not self-reported by the same population being measured.
6. **State explicitly in reporting** that a metric breach is an *alert*, a missing artifact is an *assurance gap*, and only a corroborating artifact (fabricated receipt, mismatched authenticating principal) supports a statement about an actual defect — and even then, knowledge or intent requires separate evidence.

```python
def to_bool(series, default=False):
    return series.apply(lambda v: default if (v is None or pd.isna(v)) else bool(v))

def hours(t0, t1):
    if t0 is None or t1 is None or pd.isna(t0) or pd.isna(t1):
        return np.nan
    return round((pd.Timestamp(t1) - pd.Timestamp(t0)).total_seconds() / 3600.0, 2)

    if t0 is None or t1 is None or pd.isna(t0) or pd.isna(t1) or pd.Timestamp(t1) < pd.Timestamp(t0):

    return bool(np.busday_count(np.datetime64(str(pd.Timestamp(t0).date())),
                                np.datetime64(str(pd.Timestamp(t1).date()))) <= 1)
```

### 7.1 PM4Py behaviour I cannot guarantee across versions

1. **Existence and signature.** I have called `pm4py.filter_four_eyes_principle(log, "Prepare_Payment", "Release_Payment")` exactly as specified, but I cannot guarantee that this function exists in every PM4Py release, nor that the 3-argument form is accepted (some builds may take a *list* of activities, a list of pairs, or additional keyword arguments such as a `resource_key`). The code therefore tries three call shapes and reports which one succeeded.
2. **Direction of the returned set.** I cannot guarantee whether it returns the cases that **violate** the principle or the cases that **conform** to it. The code empirically determines direction by comparing the returned set against an independently computed partition (violations vs. conforming completed cases) and prints the diagnostic. This is essential: silently assuming one direction would invert every downstream conclusion.
3. **What counts as a "case" for the filter.** I cannot guarantee whether the function requires *both* activities to occur in a trace, compares only the *first* prepare with the *last* release, or compares *all* combinations of prepare/release events; nor whether a case containing only one of the two activities is dropped, kept, or treated as conforming. In this extract every completed case has exactly one prepare and one release, so the three interpretations coincide — but that will not hold in a general log with retries or partial traces.
4. **Resource handling.** I cannot guarantee how it treats a blank/`SYSTEM` resource: whether `SYSTEM == SYSTEM` is treated as a violation (it should not be, for human four-eyes purposes) or whether missing resources are treated as distinct. The manual path explicitly excludes `SYSTEM == SYSTEM` pairs and is used as the authoritative reference.
5. **Return type.** I cannot guarantee that it returns a `DataFrame`, a PM4Py `EventLog` of traces, or an object with a different case-id column (`case_id` vs `case:concept:name`). The `_case_ids` helper probes `DataFrame` columns first, then trace `attributes`.
6. **Input type requirements.** Some builds require an `EventLog` rather than a formatted `DataFrame`; the third attempt converts with `pm4py.convert_to_event_log`. Also, `pm4py.format_dataframe` may fail if the timestamp column is already parsed, if `org:resource` is missing, or if timestamps are timezone-aware in builds that expect tz-naive — all handled by falling back to the manually formatted log (UTC tz-aware is retained for consistent hour arithmetic).
7. **`pm4py.format_dataframe` side effects.** It may sort the log, add or rename index columns, or coerce dtypes; I therefore keep an untouched `df` for all manual computations and use `log` only for PM4Py-facing calls, so version-specific formatting cannot contaminate the evidence flags.
8. **Warnings/version drift.** Deprecation warnings or renamed top-level helpers are possible; the import and every PM4Py call are wrapped, so the script degrades to a fully manual (pandas-only) computation and clearly states which path ran.

Finally, the code deliberately emits **no** classification column: the flags it prints are inputs to the judgment recorded in §3, never a substitute for it.
