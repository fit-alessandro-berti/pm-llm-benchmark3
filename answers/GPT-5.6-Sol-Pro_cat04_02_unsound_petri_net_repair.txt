# 1. Executive Verdict

Structurally, the net is a workflow net: it has one source, one sink, and every node lies on a directed source-to-sink path. It should not be expected to be sound. The standard-review branch synchronizes correctly, but `t_join_waived` consumes only `p_waived`; it neither requires nor consumes the analysis branch. Consequently, the waiver route can enable `t_authorize` before `t_analyze`. Authorization can place a token in `sink`, yet the parallel analysis token remains in `p_analysis` or later `p_analysis_done`, so the exact final marking `fm = {sink: 1}` is never reached on that route. The leftover token cannot be cleared because `t_join_normal` also requires `p_review_done`, which a waiver case never produces. The business consequence is both semantic and operational: a case can be visibly authorized without mandatory analysis, while the Petri-net instance remains improperly completed.

# 2. Structural Diagnosis

| Element or subnet                                | Intended role                                                 | Actual structural effect                                                                                                           | Potential symptom                                                                         |
| ------------------------------------------------ | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `source -> t_register -> p_ready`                | Create one process instance and prepare it for parallel work  | Moves the unique initial token from `source` to `p_ready`                                                                          | No defect in this subnet                                                                  |
| `t_split`                                        | Start analysis and review concurrently                        | An AND-split: consumes one token from `p_ready` and creates one token in each of `p_analysis` and `p_review`                       | Correctly creates two obligations that must eventually be accounted for                   |
| `p_analysis -> t_analyze -> p_analysis_done`     | Represent mandatory analysis                                  | The analysis token can be consumed only by `t_analyze`, after which it remains in `p_analysis_done` until a transition consumes it | On the waiver route, neither `t_join_waived` nor any later transition consumes this token |
| `p_review -> t_standard_review -> p_review_done` | Select and complete standard review                           | Competes with `t_waive_review` for the single token in `p_review`; therefore the two review outcomes are exclusive                 | Correct XOR-like selection between standard review and waiver                             |
| `p_review -> t_waive_review -> p_waived`         | Record the alternative formal waiver outcome                  | Consumes the review-branch token and records the waiver in a distinct place                                                        | Correctly distinguishes the waiver, but does not discharge the analysis obligation        |
| `t_join_normal`                                  | Synchronize completed analysis with completed standard review | Proper two-input AND-join over `p_analysis_done` and `p_review_done`                                                               | Standard-review cases can complete cleanly                                                |
| `t_join_waived`                                  | Synchronize completed analysis with a recorded waiver         | Has only one input, `p_waived`; it is therefore not a synchronization with analysis                                                | Enables `p_decision` while `p_analysis` or `p_analysis_done` still contains a token       |
| `p_decision -> t_authorize -> sink`              | Authorize only after both parallel obligations are discharged | Tests only for a token in `p_decision`; it has no direct awareness of outstanding branch tokens                                    | Authorization may occur while analysis remains pending                                    |
| `im = {source: 1}`                               | Mark the unique process entry                                 | Correct single-token initial marking                                                                                               | No marking defect                                                                         |
| `fm = {sink: 1}`                                 | Require clean completion with no residual tokens              | Correctly makes `sink` plus any other token different from the accepted final marking                                              | Exposes the waiver-path defect rather than hiding it                                      |
| Whole directed graph                             | Satisfy the workflow-net source, sink, and path conditions    | There is one source, one sink, and every place and transition lies on at least one structural source-to-sink path                  | `check_is_workflow_net` should succeed even though behavioral soundness fails             |

The source-to-sink path condition is structural. It does not account for the fact that `t_join_normal` needs two tokens simultaneously or that `t_join_waived` fails to consume the analysis token. Therefore, workflow-net status does not imply soundness here.

# 3. Marking-Based Counterexample

Consider the legal sequence

```text
<t_register, t_split, t_waive_review, t_join_waived,
 t_authorize, t_analyze>
```

Each marking below lists only places with nonzero tokens.

| Step | Fired transition | Resulting nonzero marking        | Enabled transitions                                | Observation                                                                                    |
| ---: | ---------------- | -------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
|    0 | —                | `{source: 1}`                    | `t_register`                                       | This is exactly `im`                                                                           |
|    1 | `t_register`     | `{p_ready: 1}`                   | `t_split`                                          | Registration completes                                                                         |
|    2 | `t_split`        | `{p_analysis: 1, p_review: 1}`   | `t_analyze`, `t_standard_review`, `t_waive_review` | One token has been created in each parallel branch                                             |
|    3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}`   | `t_analyze`, `t_join_waived`                       | The review obligation is discharged by waiver, but analysis remains pending                    |
|    4 | `t_join_waived`  | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, `t_authorize`                         | The faulty join creates the decision token without consuming the analysis token                |
|    5 | `t_authorize`    | `{p_analysis: 1, sink: 1}`       | `t_analyze`                                        | A token exists in `sink`, but this marking is not `fm`; authorization occurred before analysis |
|    6 | `t_analyze`      | `{p_analysis_done: 1, sink: 1}`  | none                                               | The marking is dead and still differs from `fm`                                                |

At step 5, the presence of a token in `sink` is not equivalent to reaching the exact final marking. Proper completion requires:

```text
{sink: 1}
```

but the actual marking is:

```text
{p_analysis: 1, sink: 1}
```

Firing `t_analyze` after authorization merely moves the residual token to `p_analysis_done`. It cannot then be consumed:

* `t_join_normal` additionally requires `p_review_done`;
* a waiver case produced `p_waived`, not `p_review_done`;
* `t_join_waived` already consumed the only `p_waived` token;
* no other transition consumes `p_analysis_done`.

Authorization can also occur **after** analysis:

```text
<t_register, t_split, t_analyze, t_waive_review,
 t_join_waived, t_authorize>
```

That sequence ends in `{p_analysis_done: 1, sink: 1}`. Thus changing the interleaving does not repair the token-accounting defect.

For comparison, the standard route is valid:

```text
<t_register, t_split, t_analyze, t_standard_review,
 t_join_normal, t_authorize>
```

It reaches exactly `{sink: 1}`.

# 4. Minimal-Repair Alternatives

The edit-cost model used here is:

* add or remove one ordinary arc: cost 1;
* add or remove one place: cost 1;
* add or remove one transition: cost 1;
* change an arc endpoint: cost 2, because it is one removal plus one addition;
* incident arc edits are counted separately from node edits;
* label, name, and marking changes would each cost 1, although none is needed below.

| Repair                                                        | Exact edits                                                                        | Edit cost | Preserved intent                                                                                                                                            | Changed behavior                                                                                                                                                                   | New risk                                                                                                                                             |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------- | --------: | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. Complete the waiver AND-join**                           | Add arc `p_analysis_done -> t_join_waived`                                         |     **1** | Analysis remains mandatory; standard review and waiver remain exclusive and distinguishable; each route has its own synchronization                         | `t_join_waived` is enabled only when both the waiver and completed analysis are present                                                                                            | `p_analysis_done` now feeds two alternative silent joins; maintainers must understand that the review-route token determines which join can fire     |
| **B. Early waiver cancels analysis — explicit policy change** | Add arc `p_analysis -> t_waive_review`                                             |     **1** | Formal waiver remains visible; completed cases have no residual tokens                                                                                      | A waiver can occur only before `t_analyze`; it consumes both branch tokens and skips analysis. If analysis fires first, waiver becomes unavailable and standard review is required | Contradicts the original mandatory-analysis policy; outcome becomes sensitive to which concurrent transition fires first                             |
| **C. Normalize both review outcomes before one shared join**  | Remove arc `t_join_waived -> p_decision`; add arc `t_join_waived -> p_review_done` |     **2** | Analysis remains mandatory; visible standard-review and waiver activities remain distinct; `t_join_normal` becomes the sole analysis/review synchronization | The waiver route passes through `t_join_waived`, then waits in `p_review_done` for analysis and uses `t_join_normal`                                                               | After the silent normalization, the marking no longer distinguishes a standard review from a waiver; the extra silent step may confuse model readers |

Repairs A and B are globally minimal under this cost model. Zero edits cannot change the defective reachable markings, so every repair has a lower bound of one edit. Each reaches that bound.

They tie in edit cost but not in policy:

* Repair A consumes the **completed** analysis token at the waiver join and preserves the stated rule.
* Repair B consumes the **pending** analysis token when waiver is recorded and deliberately changes the rule.

Repair C is not globally minimum because it costs two edits. It is, however, minimal under the additional design constraint that `t_join_normal` must be the single common synchronization and all existing places and transitions must be retained. The bypass arc must be removed, and a replacement arc into the common review-completion place must be added; either edit alone is insufficient.

# 5. Corrected PM4Py Code

The following complete model implements Repair A.

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking


def copy_marking(marking):
    copied = Marking()
    for place, count in marking.items():
        if count:
            copied[place] = count
    return copied


def format_marking(marking):
    entries = sorted(
        (
            (place.name, count)
            for place, count in marking.items()
            if count
        ),
        key=lambda item: item[0],
    )
    if not entries:
        return "{}"
    return "{" + ", ".join(
        f"{name}: {count}" for name, count in entries
    ) + "}"


def enabled_names(petri_net, marking):
    return sorted(
        transition.name
        for transition in pm4py.get_enabled_transitions(
            petri_net, marking
        )
    )


def find_transition(petri_net, transition_name):
    matches = [
        transition
        for transition in petri_net.transitions
        if transition.name == transition_name
    ]
    if len(matches) != 1:
        raise ValueError(
            f"Expected exactly one transition named "
            f"{transition_name!r}; found {len(matches)}."
        )
    return matches[0]


def fire_named(petri_net, marking, transition_name):
    transition = find_transition(petri_net, transition_name)
    enabled = pm4py.get_enabled_transitions(petri_net, marking)

    if transition not in enabled:
        raise RuntimeError(
            f"Transition {transition_name!r} is not enabled at "
            f"{format_marking(marking)}. "
            f"Enabled transitions: {enabled_names(petri_net, marking)}"
        )

    result = copy_marking(marking)

    for arc in transition.in_arcs:
        weight = getattr(arc, "weight", 1) or 1
        input_place = arc.source
        result[input_place] -= weight
        if result[input_place] == 0:
            del result[input_place]

    for arc in transition.out_arcs:
        weight = getattr(arc, "weight", 1) or 1
        output_place = arc.target
        result[output_place] += weight

    print(
        f"{transition_name} -> {format_marking(result)}; "
        f"enabled next: {enabled_names(petri_net, result)}"
    )
    return result


print("=== ORIGINAL NET ===")
original_is_wf_net = pm4py.check_is_workflow_net(net)
print("Workflow net:", original_is_wf_net)

original_soundness = pm4py.check_soundness(
    net, im, fm, print_diagnostics=True
)
print("Soundness result:", original_soundness)

original_initial_enabled = pm4py.get_enabled_transitions(net, im)
print(
    "Enabled at original initial marking:",
    sorted(t.name for t in original_initial_enabled),
)

original_reachability_graph = pm4py.convert_to_reachability_graph(
    net, im, fm
)
print(
    "Original reachability graph constructed:",
    original_reachability_graph is not None,
)


print("\n=== REPAIRED NET ===")
repaired_is_wf_net = pm4py.check_is_workflow_net(repaired_net)
print("Workflow net:", repaired_is_wf_net)

repaired_soundness = pm4py.check_soundness(
    repaired_net,
    repaired_im,
    repaired_fm,
    print_diagnostics=True,
)
print("Soundness result:", repaired_soundness)

repaired_initial_enabled = pm4py.get_enabled_transitions(
    repaired_net, repaired_im
)
print(
    "Enabled at repaired initial marking:",
    sorted(t.name for t in repaired_initial_enabled),
)

repaired_reachability_graph = pm4py.convert_to_reachability_graph(
    repaired_net, repaired_im, repaired_fm
)
print(
    "Repaired reachability graph constructed:",
    repaired_reachability_graph is not None,
)


print("\n=== ORIGINAL WAIVER COUNTEREXAMPLE ===")
original_marking = copy_marking(im)
print(
    "Start:",
    format_marking(original_marking),
    "enabled:",
    enabled_names(net, original_marking),
)

for transition_name in (
    "t_register",
    "t_split",
    "t_waive_review",
    "t_join_waived",
    "t_authorize",
    "t_analyze",
):
    original_marking = fire_named(
        net, original_marking, transition_name
    )

print("Exact original final marking reached:", original_marking == fm)


print("\n=== REPAIRED WAIVER ROUTE ===")
repaired_marking = copy_marking(repaired_im)
print(
    "Start:",
    format_marking(repaired_marking),
    "enabled:",
    enabled_names(repaired_net, repaired_marking),
)

for transition_name in (
    "t_register",
    "t_split",
    "t_waive_review",
):
    repaired_marking = fire_named(
        repaired_net, repaired_marking, transition_name
    )

# Under Repair A, the waiver join must still be blocked here.
if "t_join_waived" in enabled_names(repaired_net, repaired_marking):
    raise AssertionError(
        "Mandatory-analysis bypass detected: "
        "t_join_waived is enabled before t_analyze."
    )

for transition_name in (
    "t_analyze",
    "t_join_waived",
    "t_authorize",
):
    repaired_marking = fire_named(
        repaired_net, repaired_marking, transition_name
    )

print(
    "Exact repaired final marking reached:",
    repaired_marking == repaired_fm,
)
```

The expected qualitative result is:

* both nets satisfy the structural workflow-net check;
* the original net fails soundness because the waiver route reaches improper and non-completable markings;
* the repaired net should satisfy ordinary workflow-net soundness;
* after `t_waive_review`, the original enables both `t_analyze` and `t_join_waived`;
* after `t_waive_review`, the repaired net enables `t_analyze` but not `t_join_waived`;
* the original reachability graph contains a marking with `sink` plus an outstanding analysis token, whereas the repaired graph does not.

The exact diagnostic wording and internal keys may vary across PM4Py versions, so the code prints the implementation’s actual diagnostics rather than assuming particular WOFLAN fields.

# 7. Repair Trade-Offs and Residual Risks

**Outcome distinguishability.** Under Repair A, standard review and waiver remain distinguishable both by their visible transitions and by their intermediate places:

* standard review produces `p_review_done`;
* waiver produces `p_waived`;
* the corresponding join consumes the appropriate outcome.

After synchronization, both routes converge in `p_decision`, which is appropriate because the authorization stage no longer needs to distinguish how the review obligation was fulfilled. The event history still preserves that distinction.

**Silent-transition structure.** The repaired model has two silent synchronization transitions leading to the same decision place. They do not create duplicate behavior in the current net because the single token in `p_review` permits only one review outcome:

* `p_review_done` enables only `t_join_normal`;
* `p_waived` enables only `t_join_waived`.

Nevertheless, two similar silent joins can confuse maintainers. An incorrect future modification that produced both review-outcome tokens could create a conflict over `p_analysis_done` and leave another residual token. Repair C avoids duplicate synchronization logic, at the cost of an extra silent normalization step and loss of marking-level outcome distinction after normalization.

**Soundness versus business alignment.** Soundness proves properties such as clean completion, completion availability, and absence of dead transitions under the selected formal semantics. It does not prove that labels have the intended business meaning. Repair B illustrates this directly: it can be sound while violating the rule that analysis is mandatory.

Representative regression tests are:

| Class    | Transition sequence or prefix                                                   | Expected result                                          |
| -------- | ------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Positive | `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize` | Reach exactly `repaired_fm`                              |
| Positive | `t_register, t_split, t_standard_review, t_analyze, t_join_normal, t_authorize` | Reach exactly `repaired_fm`                              |
| Positive | `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize`    | Reach exactly `repaired_fm`                              |
| Positive | `t_register, t_split, t_waive_review, t_analyze, t_join_waived, t_authorize`    | Reach exactly `repaired_fm`                              |
| Negative | `t_register, t_split, t_waive_review, t_join_waived`                            | Reject at `t_join_waived` because analysis is incomplete |
| Negative | Any sequence enabling `t_authorize` without an earlier `t_analyze`              | Must be unreachable                                      |
| Negative | A sequence containing both `t_standard_review` and `t_waive_review`             | Must be unreachable because they compete for `p_review`  |
| Negative | `t_register, t_split, t_analyze, t_join_normal`                                 | Reject because no review outcome exists                  |
| Negative | Any complete run ending with tokens outside `sink`                              | Must fail exact-final-marking assertion                  |

An accidental analysis bypass should be detected with a precedence property over all reachable executions:

```text
Every occurrence of t_authorize must be preceded by t_analyze.
```

Because a reachability-state marking alone does not always encode history, a rigorous automated check can explore product states of the form:

```text
(marking, analysis_seen)
```

where `analysis_seen` becomes true after `t_analyze`. The test must fail if `t_authorize` is enabled or fired while `analysis_seen` is false. The shorter negative-prefix test in the diagnostic code catches the specific original defect directly.

# 8. Final Recommendation

Deploy **Repair A: add `p_analysis_done -> t_join_waived`**. It is a one-arc, globally minimal repair that directly supplies the missing synchronization condition. It preserves every stated business rule: analysis remains mandatory, standard review and waiver remain exclusive, the waiver remains formally recorded, and authorization follows completion of both obligations. Its marking interpretation is also straightforward: each review outcome has its own two-input join.

Use **Repair C** as the fallback when maintainability standards strongly prefer a single shared synchronization transition. Redirecting `t_join_waived` to `p_review_done` centralizes the analysis/review join in `t_join_normal` and remains faithful to the business intent. Its disadvantages are the extra silent transition and the loss of marking-level distinction between review and waiver after normalization, although the visible trace still preserves the distinction.

Repair B should not be deployed without explicit policy approval. Although it is also a one-arc soundness repair, it makes waiver timing cancel mandatory analysis and therefore solves the formal defect by changing the business rule rather than implementing it.
