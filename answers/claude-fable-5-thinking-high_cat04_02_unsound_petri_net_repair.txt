# 1. Executive Verdict

The net is a workflow net: it has a unique source place (`source`, no input arcs), a unique sink place (`sink`, no output arcs), and every place and transition lies on some directed path from `source` to `sink` (the waiver route reaches `sink` via `t_join_waived` and `t_authorize`; `p_review_done` reaches it via `t_join_normal`). It should nevertheless **not** be expected to be sound. The principal defect is an asymmetric synchronization: the XOR choice at `p_review` has two outcomes, but only the standard outcome is joined with the analysis branch. `t_join_waived` consumes only `p_waived`, so on the waiver route (a) `t_authorize` can fire before — or entirely without waiting for — `t_analyze`, and (b) the token in the analysis branch is stranded forever, so the exact final marking `fm` is unreachable. Business consequence: waived cases can be authorized without a completed mandatory analysis, and such cases never terminate cleanly.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `source` → `t_register` → `p_ready` | Case intake | Correct: one token enters the process | None |
| `t_split` (`p_ready` → `p_analysis`, `p_review`) | AND-split opening two parallel branches | Correct: produces exactly one token in each branch | None by itself; it creates the two tokens that must later be re-synchronized |
| `p_review` → `t_standard_review` / `t_waive_review` | XOR choice between standard review and waiver | Correct free choice: both transitions have `p_review` as their only input, so exactly one fires | None by itself; the problem is downstream |
| `t_join_normal` (inputs `p_analysis_done`, `p_review_done`) | AND-join for the standard route | Correct two-input synchronization; only enabled if both analysis and standard review completed | Never enabled on the waiver route, because `p_review_done` is then never marked |
| `t_join_waived` (input `p_waived` only) | AND-join for the waiver route | **Defective:** single-input transition; it forwards the waiver token to `p_decision` without consuming anything from the analysis branch | Authorization without (or before) analysis; the analysis-branch token (`p_analysis` or `p_analysis_done`) is left behind |
| `p_decision` → `t_authorize` → `sink` | Gate authorization on the completed join | Correct locally, but it trusts whichever join produced the `p_decision` token; via `t_join_waived` the guarantee "analysis done" does not hold | `t_authorize` fires while the analysis branch still holds a token |
| `im = {source:1}`, `fm = {sink:1}` | Standard WF-net markings | Correctly defined; the defect is that `fm` is unreachable on the waiver route (only `sink:1` **plus** a leftover token is reachable) | Soundness check fails on proper completion / option to complete |
| Source-to-sink paths | WF-net structural condition | Satisfied for every node: e.g. `p_waived` → `t_join_waived` → `p_decision` → `t_authorize` → `sink`; `p_review_done` → `t_join_normal` → `p_decision` → `sink` | `check_is_workflow_net` returns `True`, which can lull the modeler into assuming soundness |

The structural pattern is the classic XOR-split/AND-join mismatch, but only half of it: one XOR branch is synchronized with the parallel analysis branch, the other is not. The informal statement is not sufficient, so Section 3 derives it through markings.

# 3. Marking-Based Counterexample

**Counterexample 1 — waiver chosen, authorization occurs before analysis:**

Firing sequence: `t_register`, `t_split`, `t_waive_review`, `t_join_waived`, `t_authorize`, `t_analyze`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (initial `im`) | `source:1` | `t_register` | Start |
| 1 | `t_register` | `p_ready:1` | `t_split` | |
| 2 | `t_split` | `p_analysis:1, p_review:1` | `t_analyze`, `t_standard_review`, `t_waive_review` | One token created in each parallel branch |
| 3 | `t_waive_review` | `p_analysis:1, p_waived:1` | `t_analyze`, `t_join_waived` | Waiver route taken; analysis not yet performed |
| 4 | `t_join_waived` | `p_analysis:1, p_decision:1` | `t_analyze`, `t_authorize` | The "join" fired while the analysis branch still holds its token: it consumed only `p_waived` |
| 5 | `t_authorize` | `p_analysis:1, sink:1` | `t_analyze` | **`t_authorize` fired before `t_analyze`** — direct violation of the business rule. A token exists in the sink, but the marking is `{sink:1, p_analysis:1}` ≠ `fm = {sink:1}` |
| 6 | `t_analyze` | `p_analysis_done:1, sink:1` | (none — dead marking) | The case is "finished" yet a token remains outside `fm` |

Why the leftover token can never be consumed: the only consumer of `p_analysis_done` is `t_join_normal`, which also requires a token in `p_review_done`. The only producer of `p_review_done` is `t_standard_review`, whose only input `p_review` was already consumed by `t_waive_review` at step 3 and is never re-marked (no cycles exist). Hence from step 4 onward the exact final marking `fm` is unreachable: every continuation ends in `{sink:1}` plus one residual token in `p_analysis` or `p_analysis_done`. This violates both the option-to-complete and proper-completion conditions of soundness. (There are no dead transitions: every transition, including `t_join_normal`, fires in the standard-review run `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize`, which does reach `fm` exactly. The net is unsound but not trivially broken on every path.)

**Counterexample 2 — the defect is not a race; it persists even when analysis finishes first:**

Firing sequence: `t_register`, `t_split`, `t_analyze`, `t_waive_review`, `t_join_waived`, `t_authorize`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (initial `im`) | `source:1` | `t_register` | |
| 1 | `t_register` | `p_ready:1` | `t_split` | |
| 2 | `t_split` | `p_analysis:1, p_review:1` | `t_analyze`, `t_standard_review`, `t_waive_review` | |
| 3 | `t_analyze` | `p_analysis_done:1, p_review:1` | `t_standard_review`, `t_waive_review` | Analysis completed first this time |
| 4 | `t_waive_review` | `p_analysis_done:1, p_waived:1` | `t_join_waived` | `t_join_normal` is **not** enabled: it needs `p_review_done`, not `p_waived` |
| 5 | `t_join_waived` | `p_analysis_done:1, p_decision:1` | `t_authorize` | The join ignores `p_analysis_done` even though it is available |
| 6 | `t_authorize` | `p_analysis_done:1, sink:1` | (none — dead marking) | Sink marked, but marking ≠ `fm`; the `p_analysis_done` token is permanently stranded for the reason given above |

So the waiver route **always** ends improperly, regardless of interleaving: the defect is structural, not a scheduling race. The two counterexamples together show the two distinct symptoms: premature authorization (ordering violation, Counterexample 1) and guaranteed improper completion (Counterexamples 1 and 2).

# 4. Minimal-Repair Alternatives

**Edit-cost model:** cost = (number of arcs added) + (number of arcs removed) + 2 × (number of places or transitions added or removed). Renaming or relabeling is cost 0 but does not count as a repair. Lower is more minimal.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1: complete the waiver join** | Add one arc: `p_analysis_done` → `t_join_waived` | **1** (1 arc added) | Analysis remains mandatory on both routes; waiver remains a structurally distinct outcome (`p_waived`, `t_join_waived` kept) | `t_join_waived` now waits for analysis; `t_authorize` can no longer precede `t_analyze`; `fm` reached exactly on both routes | Two silent joins now coexist; a reader must notice they synchronize different review outcomes. No behavioral duplication: their input sets differ (`p_review_done` vs `p_waived`) |
| **R2: fold the waiver into the normal synchronization** | Remove arc `t_waive_review` → `p_waived`; add arc `t_waive_review` → `p_review_done`; remove arc `p_waived` → `t_join_waived`; remove arc `t_join_waived` → `p_decision`; remove place `p_waived`; remove transition `t_join_waived` | **8** (1 added + 3 removed arcs + 2 nodes removed) | Analysis mandatory on both routes; visible labels unchanged, so the event-log-level language is the same as R1's | Waiver and standard review now converge into the same place `p_review_done` and the same join `t_join_normal`; the net is smaller (one join, one review-done place) | The waiver outcome is no longer distinguishable in the *state space* (only via the label of the firing transition); future state-based rules "if waived then X" need re-engineering |
| **R3 (explicit policy change): analysis optional under waiver** | Add arc `p_analysis` → `t_join_waived` (waiver cancels a not-yet-started analysis); add transition `t_join_waived_late` (silent) with arcs `p_analysis_done` → `t_join_waived_late`, `p_waived` → `t_join_waived_late`, `t_join_waived_late` → `p_decision` (absorbs an already-finished analysis) | **6** (4 arcs added + 1 transition added) | Waiver remains distinct; proper completion restored on all routes | **Business policy changed and stated explicitly:** on the waiver route, analysis is skipped if it has not started yet, and merely absorbed if it already finished — analysis is no longer mandatory when the review is waived | Nondeterministic race between `t_analyze` and `t_join_waived` for the `p_analysis` token: whether analysis happens on a waived case depends on interleaving. This is usually *not* what a business wants and must be governed by an explicit rule |

**Minimality justification.** The original net is unsound, so no zero-cost repair exists; the cheapest possible nonzero edit under the model is a single arc, cost 1. R1 achieves exactly that, so R1 is globally minimal — no repair can be cheaper, and one can argue no *other* single-arc repair works: to fix the waiver route while keeping analysis mandatory, the waiver-side synchronization must consume the analysis branch's token after `t_analyze`, i.e., some transition on the waiver route must gain `p_analysis_done` as an input; adding `p_analysis_done` → `t_join_waived` is the unique single arc that does this without breaking the standard route. R2 and R3 are not cost-minimal (8 and 6) but are behaviorally/structurally distinct alternatives: R2 simplifies the structure at the price of state-level distinguishability; R3 changes the policy itself. There is no tie.

# 5. Corrected PM4Py Code

Selected repair: **R1** (add the single arc `p_analysis_done` → `t_join_waived`).

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

r_source = PetriNet.Place("source")
r_p_ready = PetriNet.Place("p_ready")
r_p_analysis = PetriNet.Place("p_analysis")
r_p_review = PetriNet.Place("p_review")
r_p_analysis_done = PetriNet.Place("p_analysis_done")
r_p_review_done = PetriNet.Place("p_review_done")
r_p_waived = PetriNet.Place("p_waived")
r_p_decision = PetriNet.Place("p_decision")
r_sink = PetriNet.Place("sink")

for p in [
    r_source, r_p_ready, r_p_analysis, r_p_review, r_p_analysis_done,
    r_p_review_done, r_p_waived, r_p_decision, r_sink
]:
    repaired_net.places.add(p)

r_register = PetriNet.Transition("t_register", "Register Case")
r_split = PetriNet.Transition("t_split", None)
r_analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
r_standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
r_waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
r_join_normal = PetriNet.Transition("t_join_normal", None)
r_join_waived = PetriNet.Transition("t_join_waived", None)
r_authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in [
    r_register, r_split, r_analyze, r_standard_review, r_waive_review,
    r_join_normal, r_join_waived, r_authorize
]:
    repaired_net.transitions.add(t)

petri_utils.add_arc_from_to(r_source, r_register, repaired_net)
petri_utils.add_arc_from_to(r_register, r_p_ready, repaired_net)
petri_utils.add_arc_from_to(r_p_ready, r_split, repaired_net)
petri_utils.add_arc_from_to(r_split, r_p_analysis, repaired_net)
petri_utils.add_arc_from_to(r_split, r_p_review, repaired_net)

petri_utils.add_arc_from_to(r_p_analysis, r_analyze, repaired_net)
petri_utils.add_arc_from_to(r_analyze, r_p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(r_p_review, r_standard_review, repaired_net)
petri_utils.add_arc_from_to(r_standard_review, r_p_review_done, repaired_net)

petri_utils.add_arc_from_to(r_p_review, r_waive_review, repaired_net)
petri_utils.add_arc_from_to(r_waive_review, r_p_waived, repaired_net)

petri_utils.add_arc_from_to(r_p_analysis_done, r_join_normal, repaired_net)
petri_utils.add_arc_from_to(r_p_review_done, r_join_normal, repaired_net)
petri_utils.add_arc_from_to(r_join_normal, r_p_decision, repaired_net)

petri_utils.add_arc_from_to(r_p_waived, r_join_waived, repaired_net)
# REPAIR (the single added arc): the waiver join must also consume the
# completed-analysis token, so authorization on the waiver route waits for
# t_analyze and no token is left behind.
petri_utils.add_arc_from_to(r_p_analysis_done, r_join_waived, repaired_net)
petri_utils.add_arc_from_to(r_join_waived, r_p_decision, repaired_net)

petri_utils.add_arc_from_to(r_p_decision, r_authorize, repaired_net)
petri_utils.add_arc_from_to(r_authorize, r_sink, repaired_net)

repaired_im = Marking()
repaired_im[r_source] = 1
repaired_fm = Marking()
repaired_fm[r_sink] = 1
```

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

def fire_by_name(a_net, marking, transition_name):
    """Fire the transition with the given .name, checking enabledness first."""
    trans = next((t for t in a_net.transitions if t.name == transition_name), None)
    if trans is None:
        raise ValueError(f"transition {transition_name!r} not found in {a_net.name}")
    if trans not in pm4py.get_enabled_transitions(a_net, marking):
        raise RuntimeError(
            f"{transition_name!r} is NOT enabled at marking "
            f"{ {p.name: n for p, n in marking.items()} }"
        )
    new_marking = Marking()
    for p, n in marking.items():
        new_marking[p] = n
    for arc in trans.in_arcs:
        new_marking[arc.source] -= arc.weight
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]
    for arc in trans.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + arc.weight
    print(f"fired {transition_name}: "
          f"{ {p.name: n for p, n in new_marking.items()} } | enabled next: "
          f"{sorted(t.name for t in pm4py.get_enabled_transitions(a_net, new_marking))}")
    return new_marking

for tag, (a_net, a_im, a_fm) in {
    "ORIGINAL": (net, im, fm),
    "REPAIRED": (repaired_net, repaired_im, repaired_fm),
}.items():
    print(f"\n===== {tag} =====")
    print("is workflow net:", pm4py.check_is_workflow_net(a_net))
    print("soundness:", pm4py.check_soundness(a_net, a_im, a_fm, print_diagnostics=True))
    print("enabled at im:", sorted(t.name for t in pm4py.get_enabled_transitions(a_net, a_im)))
    rg = pm4py.convert_to_reachability_graph(a_net, a_im, a_fm)
    print("reachability graph states:", len(rg.states),
          "| transitions:", len(rg.transitions))

    # Replay the waiver-route counterexample from Section 3.
    m = a_im
    for name in ["t_register", "t_split", "t_waive_review"]:
        m = fire_by_name(a_net, m, name)
    if tag == "ORIGINAL":
        # Defect: join fires and authorization happens with analysis pending.
        for name in ["t_join_waived", "t_authorize", "t_analyze"]:
            m = fire_by_name(a_net, m, name)
    else:
        # Repaired: t_join_waived must NOT be enabled before t_analyze.
        assert "t_join_waived" not in {
            t.name for t in pm4py.get_enabled_transitions(a_net, m)
        }, "repair failed: waiver join enabled before analysis"
        for name in ["t_analyze", "t_join_waived", "t_authorize"]:
            m = fire_by_name(a_net, m, name)
    reached_fm_exactly = (dict(m) == dict(a_fm))
    print("final marking:", {p.name: n for p, n in m.items()},
          "| equals fm exactly:", reached_fm_exactly)
```

**Expected qualitative difference.** Both nets return `True` for `check_is_workflow_net`. For the original, `check_soundness` reports unsoundness (proper completion / option to complete violated: from any marking after `t_waive_review`, `fm` is unreachable and a token is left in `p_analysis` or `p_analysis_done`); the replay ends in `{sink:1, p_analysis_done:1}` with `equals fm exactly: False`, and after `t_join_waived` both `t_analyze` and `t_authorize` are enabled, exhibiting the premature authorization. For the repaired net, `check_soundness` reports sound; `t_join_waived` is not enabled until `t_analyze` has fired; the replay ends exactly in `fm`. The original's reachability graph contains dead end states carrying a `sink` token plus a residual token; the repaired graph's only dead end state is `fm` itself. I do not claim exact state counts here; the code prints the actual sizes.

# 7. Repair Trade-Offs and Residual Risks

- **Distinguishability of waiver vs standard review.** Under R1, fully preserved at both the label level (`Record Review Waiver` vs `Perform Standard Review`) and the state level (`p_waived` vs `p_review_done`, separate joins). Under R2, preserved only at the label level: once `t_waive_review` fires into `p_review_done`, the state no longer records which outcome occurred. If downstream rules or conformance queries condition on the waived *state*, R1 is safer.
- **Duplicate behavior through silent transitions.** R1 keeps two silent joins (`t_join_normal`, `t_join_waived`). They are not duplicates — their presets differ (`{p_analysis_done, p_review_done}` vs `{p_analysis_done, p_waived}`) and at most one can ever be enabled in a case, since `p_review_done` and `p_waived` are mutually exclusive outputs of an XOR choice. The residual risk is cosmetic: in discovered/visualized models, two taus into the same place can confuse readers, and alignment-based conformance may route through either tau at zero cost, which is harmless for fitness but can blur diagnostics.
- **Soundness is not business alignment.** A sound net guarantees only option to complete, proper completion, and no dead transitions. R3 is also sound, yet deliberately violates "analysis is always mandatory." Conversely, a sound net could still order activities in a business-invalid way. Soundness is necessary hygiene, not proof of policy compliance; the ordering property "no `t_authorize` before `t_analyze`" must be checked separately (e.g., on the reachability graph or via replay assertions as in Section 6).
- **Regression traces.** Positive (must replay to exactly `fm`): `⟨Register Case, Perform Analysis, Perform Standard Review, Authorize Case⟩`; `⟨Register Case, Perform Standard Review, Perform Analysis, Authorize Case⟩` (interleaving); `⟨Register Case, Perform Analysis, Record Review Waiver, Authorize Case⟩`; `⟨Register Case, Record Review Waiver, Perform Analysis, Authorize Case⟩`. Negative (must not be replayable / must not reach `fm`): `⟨Register Case, Record Review Waiver, Authorize Case⟩` (no analysis); `⟨Register Case, Perform Analysis, Authorize Case⟩` (no review outcome); any trace with both `Perform Standard Review` and `Record Review Waiver`; any trace where `Authorize Case` precedes `Perform Analysis`.
- **Detecting an accidental bypass of mandatory analysis.** Three complementary checks: (1) structural — assert every transition whose output reaches `p_decision` has `p_analysis_done` in its preset (true for both joins under R1); (2) state-space — enumerate the reachability graph and assert no path fires `t_authorize` before `t_analyze` (an LTL-style precedence check); (3) log-based — alignments of production logs against the repaired net, alerting on any case where `Authorize Case` aligns without a preceding `Perform Analysis`, which would indicate reality (or a future model edit) has reintroduced the bypass.

# 8. Final Recommendation

Deploy **R1** (add the single arc `p_analysis_done` → `t_join_waived`). It is the globally minimal repair under the stated cost model (cost 1, and no cheaper repair can exist since the net must change), it restores soundness, it enforces the exact business rule — authorization only after analysis *and* the selected review outcome — on both routes, and it preserves the waiver as a distinguishable state (`p_waived`) and a distinguishable synchronization (`t_join_waived`). That state-level distinguishability matters: audit queries, conformance diagnostics, and any future rule of the form "waived cases require X" keep a structural anchor. The change is also the easiest to review: a one-line diff whose correctness follows directly from the marking argument in Section 3.

Keep **R2** (retarget `t_waive_review` to `p_review_done`; delete `p_waived` and `t_join_waived`) as the fallback. It is costlier (8) but yields a strictly simpler net — one join, one review-done place, fewer silent transitions — with the same visible-label language as R1 and the same guarantee that analysis is mandatory. It is preferable if the organization decides the waiver needs no distinct state and wants the leanest model for discovery, visualization, and maintenance.

**R3** is explicitly not recommended: it silently converts "analysis is always mandatory" into "analysis happens on waived cases only if it wins a race," which is a policy change that should come from the business owner, not from a model repair.

Regardless of choice, add the Section 7 regression traces and the `t_analyze`-precedes-`t_authorize` reachability assertion to CI so the bypass cannot be reintroduced unnoticed.
