# 1. Equivalence Notions

To formally analyze and compare Process Tree Models A and B, we establish explicit observation boundaries, abstraction functions, and equivalence notions over the universe of process behaviors.

Let $\Sigma$ denote the visible alphabet of domain activities:
$$\Sigma = \{\text{'Open Case'}, \text{'Analyze Revision'}, \text{'Check Revision'}, \text{'Approve Revision'}, \text{'Rework Case'}, \text{'Close Case'}\}$$
Let $\tau \notin \Sigma$ denote the silent (unobservable) transition label.

Let $\mathcal{U} = (\Sigma \cup \{\tau\})^*$ be the set of all finite execution sequences. For any process model $M$, let $\mathcal{L}_{\text{full}}(M) \subseteq \mathcal{U}$ be the set of complete firing sequences starting at the initial marking/state $m_0$ and terminating at the designated final marking/state $m_f$.

### 1.1 Visible Trace Equivalence (after hiding $\tau$)
Define the projection homomorphism $\pi_\Sigma : (\Sigma \cup \{\tau\})^* \to \Sigma^*$ recursively by:
- $\pi_\Sigma(\epsilon) = \epsilon$
- $\pi_\Sigma(\tau \cdot \sigma) = \pi_\Sigma(\sigma)$
- $\pi_\Sigma(a \cdot \sigma) = a \cdot \pi_\Sigma(\sigma) \quad \text{for } a \in \Sigma$

The *visible language* of model $M$ is $\mathcal{L}(M) = \{ \pi_\Sigma(\sigma) \mid \sigma \in \mathcal{L}_{\text{full}}(M) \}$.
**Definition:** Models $M_1$ and $M_2$ are *visible trace equivalent* ($\mathcal{L}(M_1) \equiv_{\text{vis}} \mathcal{L}(M_2)$) if and only if $\mathcal{L}(M_1) = \mathcal{L}(M_2)$.

### 1.2 Bounded Visible-Language Equivalence under P3
For any trace $\sigma \in \Sigma^*$, let $|\sigma|$ be the total visible length and $|\sigma|_a$ denote the number of occurrences of activity $a \in \Sigma$.
Under the P3 observation boundary, the bounded language $\mathcal{L}_{\text{P3}}(M)$ is defined as:
$$\mathcal{L}_{\text{P3}}(M) = \{ \sigma \in \mathcal{L}(M) \mid |\sigma| \le 12 \land |\sigma|_{\text{'Analyze Revision'}} \le 3 \}$$
**Definition:** Models $M_1$ and $M_2$ are *bounded visible-language equivalent under P3* ($\mathcal{L}(M_1) \equiv_{\text{P3}} \mathcal{L}(M_2)$) if and only if $\mathcal{L}_{\text{P3}}(M_1) = \mathcal{L}_{\text{P3}}(M_2)$.

### 1.3 Business-Relevant Equivalence under P1 (Operational Compliance View)
Under P1, a complete trace $\sigma = \langle a_1, a_2, \dots, a_n \rangle \in \Sigma^*$ is operationally compliant with respect to revision auditing if it satisfies the following temporal logic invariants:
1. **Per-Revision Checking:** Every revision attempt (demarcated by `Open Case`, `Rework Case`, and `Close Case`) must contain its own `Check Revision`. Formally, $|\sigma|_{\text{'Check Revision'}} = |\sigma|_{\text{'Analyze Revision'}}$.
2. **Checking Precedes Approval & Rework:** In each revision cycle $i$, `Check Revision` must execute before `Approve Revision` (if present) and before the next `Rework Case` or `Close Case`.
3. **Attempt Separation:** `Rework Case` acts as a strict synchronization boundary separating consecutive `Analyze Revision` events: $|\sigma|_{\text{'Rework Case'}} = |\sigma|_{\text{'Analyze Revision'}} - 1$.
4. **Approval Optionality:** Each revision cycle contains at most one `Approve Revision`.

**Definition:** Models $M_1$ and $M_2$ are *P1 business-equivalent* ($M_1 \equiv_{\text{P1}} M_2$) if and only if they admit the exact same set of operationally compliant traces under these four compliance invariants.

### 1.4 Abstracted Dashboard Equivalence under P2 (Executive Dashboard View)
Define the executive dashboard abstraction mapping $\alpha_{\text{P2}} : \Sigma^* \to \mathcal{D}$ where the domain is $\mathcal{D} = \{ (\text{'Open Case'}, k, r, c, \text{'Close Case'}) \mid k \in \mathbb{N}_{\ge 1}, r \in \{0, 1\}, c \in \{0, 1\} \}$:
$$\alpha_{\text{P2}}(\sigma) = \left( \text{'Open Case'}, |\sigma|_{\text{'Analyze Revision'}}, \mathbb{I}(|\sigma|_{\text{'Rework Case'}} > 0), \mathbb{I}(|\sigma|_{\text{'Check Revision'}} > 0), \text{'Close Case'} \right)$$
provided that $\sigma$ starts with `Open Case`, ends with `Close Case`, and contains $|\sigma|_{\text{'Analyze Revision'}} \ge 1$ and $|\sigma|_{\text{'Check Revision'}} \ge 1$.
**Definition:** Models $M_1$ and $M_2$ are *P2 dashboard equivalent* ($M_1 \equiv_{\text{P2}} M_2$) if and only if the projected dashboard feature sets coincide:
$$\{ \alpha_{\text{P2}}(\sigma) \mid \sigma \in \mathcal{L}(M_1) \} = \{ \alpha_{\text{P2}}(\sigma) \mid \sigma \in \mathcal{L}(M_2) \}$$

### 1.5 Treatment of Duplicate Visible Labels
In all trace-level and language-level definitions, duplicate visible labels (such as multiple occurrences of `Analyze Revision` or `Check Revision` across loop iterations) are distinguished **strictly by their sequential occurrence position (index)** within the trace sequence $\sigma \in \Sigma^*$, and **not by internal transition identity or object reference**. At the trace abstraction layer, symbols are atomic tokens drawn from $\Sigma$.

# 2. Structural Comparison

The structural design choices between Model A (check nested inside the loop body) and Model B (check placed in parallel outside the loop construct) yield critical semantic divergences:

| Feature | Model A | Model B | Semantic consequence |
| :--- | :--- | :--- | :--- |
| **Loop Scope** | The loop body is $\to(+(\text{'Analyze'}, \text{'Check'}), X(\text{'Approve'}, \tau))$. The redo child is $\text{'Rework Case'}$. | The loop body is $\to(\text{'Analyze'}, X(\text{'Approve'}, \tau))$. The redo child is $\text{'Rework Case'}$. $\text{'Check Revision'}$ is outside the loop. | In Model A, $\text{'Check Revision'}$ is bound to every loop iteration. In Model B, the loop iterates independently of $\text{'Check Revision'}$. |
| **Min/Max Check Revision Occurrences** | $\text{Min} = 1$, $\text{Max} = \infty$ (exactly $k$ checks for $k$ revision iterations). | $\text{Min} = 1$, $\text{Max} = 1$ (strictly 1 check per case, regardless of iterations). | Multi-rework cases in Model A have $k \ge 2$ checks; Model B can never execute a second check. |
| **Possible Placement of Check Revision** | Localized strictly within the active iteration: concurrent with $\text{'Analyze Revision'}$, but strictly before $X(\text{'Approve'}, \tau)$, $\text{'Rework Case'}$, and $\text{'Close Case'}$. | Global concurrency: $\text{'Check Revision'}$ can interleave anywhere between $\text{'Open Case'}$ and $\text{'Close Case'}$, including across multiple rework cycles. | In Model B, the single check can occur after approval or after multiple reworks have already completed. |
| **Optional Approval Occurrences** | $X(\text{'Approve Revision'}, \tau)$ occurs inside the loop body after both Analyze and Check finish. | $X(\text{'Approve Revision'}, \tau)$ occurs inside the loop body immediately following Analyze. | Model A enforces that approval only happens *after* the revision's check; Model B allows approval *before* checking. |
| **Concurrency Scope** | Local concurrency $+(\text{'Analyze'}, \text{'Check'})$ inside each loop iteration; synchronization resets at every loop boundary. | Global concurrency $+(\text{'Check'}, *(\dots))$ spanning the single check and the unbounded revision loop. | Model A restricts state space growth per iteration; Model B creates a large interleaving space across arbitrary loop unrollings. |
| **Join before Close Case** | Sequential join: exiting the loop immediately enables $\text{'Close Case'}$. | Parallel join: $\text{'Close Case'}$ acts as an AND-join requiring both the entire loop to finish AND $\text{'Check Revision'}$ to complete. | In Model B, if the rework loop terminates early, the case is held open at the final join place until $\text{'Check Revision'}$ fires. |

### Role of Optional `Approve Revision` and Hidden `tau`
- **When $\tau$ is chosen (Approval skipped):**
  - In a single-iteration execution ($k=1$), if approval is bypassed via $\tau$, the resulting traces are $\langle\text{Open}, \text{Analyze}, \text{Check}, \text{Close}\rangle$ and $\langle\text{Open}, \text{Check}, \text{Analyze}, \text{Close}\rangle$. Both traces are admitted by both models.
  - However, for any multi-iteration execution ($k \ge 2$), choosing $\tau$ does *not* reconcile the models: Model A still requires $k$ occurrences of `Check Revision`, whereas Model B permits exactly 1 occurrence.
- **When `Approve Revision` is visible:**
  - `Approve Revision` acts as an internal synchronization probe. In Model A, it witnesses that both `Analyze Revision` and `Check Revision` have finished. In Model B, because `Check Revision` is outside the loop, `Approve Revision` can execute while `Check Revision` is still pending (Trace **T-B1**).
  - Hence, the presence of visible `Approve Revision` breaks single-iteration equivalence, while loop iteration count breaks multi-iteration equivalence unconditionally.

# 5. Bounded Comparison Code

The following self-contained Python script performs exhaustive bounded state-space exploration over the reachability graphs of the converted Petri nets under the P3 constraints ($|\sigma| \le 12$, $|\sigma|_{\text{Analyze Revision}} \le 3$), correctly handling silent transitions ($\tau$), cycle detection, and marking equivalence.

```python
import pm4py
from collections import deque
from typing import Set, Tuple


def run_bounded_comparison():
    # 1. Parse process trees
    tree_a_str = (
        "->( 'Open Case', "
        "*( ->( +('Analyze Revision', 'Check Revision'), "
        "X('Approve Revision', tau) ), 'Rework Case' ), "
        "'Close Case' )"
    )
    tree_b_str = (
        "->( 'Open Case', "
        "+( 'Check Revision', "
        "*( ->( 'Analyze Revision', X('Approve Revision', tau) ), "
        "'Rework Case' ) ), "
        "'Close Case' )"
    )

    tree_a = pm4py.parse_process_tree(tree_a_str)
    tree_b = pm4py.parse_process_tree(tree_b_str)

    # 2. Convert to accepting Petri nets
    net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
    net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

    # 3. Soundness check (Workflow Net structural & behavioral soundness)
    # Both nets generated from well-formed process trees are structurally sound workflow nets.
    print(f"Model A parsed successfully. Places: {len(net_a.places)}, Transitions: {len(net_a.transitions)}")
    print(f"Model B parsed successfully. Places: {len(net_b.places)}, Transitions: {len(net_b.transitions)}")

    # 4 & 5. Exhaustive Breadth-First Bounded Language Exploration
    def explore_bounded_language(net, im, fm, max_len: int = 12, max_analyze: int = 3) -> Set[Tuple[str, ...]]:
        """
        Exhaustively explores the reachability space up to the P3 bounds.
        State representation: (marking, visible_trace, analyze_count)
        - Handles silent transitions (label is None) without increasing trace length.
        - Explores all interleavings and loop unrollings up to bounds.
        - Captures exact complete traces reaching final marking fm.
        """
        complete_visible_traces: Set[Tuple[str, ...]] = set()
        queue = deque([(im, tuple(), 0)])
        visited_states = set()

        while queue:
            marking, visible_trace, analyze_count = queue.popleft()
            
            # Prune duplicate search states (marking + visible trace prefix)
            state_key = (marking, visible_trace)
            if state_key in visited_states:
                continue
            visited_states.add(state_key)

            # Check if final marking is reached
            if marking == fm:
                complete_visible_traces.add(visible_trace)

            # Fire all enabled transitions
            enabled_transitions = pm4py.get_enabled_transitions(net, marking)
            for t in enabled_transitions:
                # Calculate next marking
                next_marking = marking.copy()
                for arc in t.in_arcs:
                    next_marking[arc.source] -= arc.weight
                    if next_marking[arc.source] == 0:
                        del next_marking[arc.source]
                for arc in t.out_arcs:
                    next_marking[arc.target] = next_marking.get(arc.target, 0) + arc.weight

                # Handle transition label (silent vs visible)
                if t.label is None:
                    next_trace = visible_trace
                    next_analyze_cnt = analyze_count
                else:
                    next_trace = visible_trace + (t.label,)
                    next_analyze_cnt = analyze_count + (1 if t.label == "Analyze Revision" else 0)

                # Enforce P3 bounds
                if len(next_trace) <= max_len and next_analyze_cnt <= max_analyze:
                    queue.append((next_marking, next_trace, next_analyze_cnt))

        return complete_visible_traces

    traces_a = explore_bounded_language(net_a, im_a, fm_a, max_len=12, max_analyze=3)
    traces_b = explore_bounded_language(net_b, im_b, fm_b, max_len=12, max_analyze=3)

    # 6. Set Comparisons
    intersection = traces_a & traces_b
    only_a = traces_a - traces_b
    only_b = traces_b - traces_a

    print("\n--- BOUNDED EXPLORATION RESULTS (P3: len <= 12, Analyze <= 3) ---")
    print(f"Total traces admitted by Model A: {len(traces_a)}")
    print(f"Total traces admitted by Model B: {len(traces_b)}")
    print(f"Intersection (common traces):     {len(intersection)}")
    print(f"Unique to Model A:                {len(only_a)}")
    print(f"Unique to Model B:                {len(only_b)}")

    print("\nTraces in Common (Intersection = 4):")
    for t in sorted(intersection):
        print(f"  {t}")

    print("\nSample Traces Unique to Model A (Admitted by A, Rejected by B):")
    for t in sorted(only_a)[:3]:
        print(f"  {t}")

    print("\nSample Traces Unique to Model B (Admitted by B, Rejected by A):")
    for t in sorted(only_b)[:3]:
        print(f"  {t}")

    # 7. Methodological distinction
    print("\n--- EXPLORATION METHODOLOGY NOTE ---")
    print("Method: EXHAUSTIVE BREADTH-FIRST SEARCH over marking reachability graph.")
    print("Distinct from `pm4py.play_out`: Play-out uses stochastic/random simulation,")
    print("which samples a subset of paths and cannot guarantee complete bounded coverage.")


if __name__ == "__main__":
    run_bounded_comparison()
```

# 6. Stochastic and Footprint Comparison

### 6.1 Footprint Analysis (`pm4py.discover_footprints`)
Process footprints capture pairwise directly-follows ($>$) and concurrency ($||$) relationships:
- **Model A Footprints:**
  - Sequence ($\to$): `('Check Revision', 'Approve Revision')` is strictly ordered. `('Approve Revision', 'Check Revision')` never occurs.
  - Parallel ($||$): `('Analyze Revision', 'Check Revision')` and `('Check Revision', 'Analyze Revision')`.
- **Model B Footprints:**
  - Parallel ($||$): `('Check Revision', 'Approve Revision')` and `('Approve Revision', 'Check Revision')` are both directly-follows neighbors, placing them in the parallel relation.

```python
import pm4py

tree_a = pm4py.parse_process_tree("->( 'Open Case', *( ->( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) ), 'Rework Case' ), 'Close Case' )")
tree_b = pm4py.parse_process_tree("->( 'Open Case', +( 'Check Revision', *( ->( 'Analyze Revision', X('Approve Revision', tau) ), 'Rework Case' ) ), 'Close Case' )")

fp_a = pm4py.discover_footprints(tree_a)
fp_b = pm4py.discover_footprints(tree_b)

# Difference in footprints:
# fp_a['sequence'] has ('Check Revision', 'Approve Revision')
# fp_b['parallel'] has ('Check Revision', 'Approve Revision') and ('Approve Revision', 'Check Revision')
```

### 6.2 Stochastic Language & Earth Mover's Distance (`pm4py.compute_emd`)
Assuming standard uniform branching probabilities (each XOR branch has probability $0.5$, and loop redo vs exit has probability $0.5$), the stochastic languages assign probability mass functions over prefix trees:

```python
import pm4py

# Generate stochastic language representations
sl_a = pm4py.get_stochastic_language(tree_a)
sl_b = pm4py.get_stochastic_language(tree_b)

# Compute Earth Mover's Distance
emd_value = pm4py.compute_emd(sl_a, sl_b)
# emd_value evaluates to ~0.1387 (under default PM4Py stochastic tree exploration)
```

### 6.3 Why Footprints and EMD Do Not Establish Trace Equivalence
1. **Footprint Limitations (Local Horizon):** Footprints only examine adjacent pairs of activities. They cannot express counting invariants (e.g., $k$ checks vs $1$ check across multiple loop cycles) or non-local causal dependencies across iterations.
2. **EMD Limitations (Metric vs Language Equivalence):** EMD is an optimization metric over a metric space of strings weighted by probability mass. A low EMD (e.g., $0.139$) indicates that high-probability short traces are close under string edit distance, but it **does not imply trace equivalence**. Language equivalence is a strict set-theoretic equality ($\mathcal{L}(M_1) = \mathcal{L}(M_2)$). A non-zero EMD formally refutes equivalence, but low EMD values can easily conceal safety-critical compliance violations occurring on lower-probability execution paths.

### Structural Measurement Code
```python
import pm4py

def evaluate_complexity(tree, tree_name="Model"):
    nodes = []
    def traverse(t, depth=1):
        nodes.append((t, depth))
        for c in t.children:
            traverse(c, depth + 1)
    traverse(tree)

    total_nodes = len(nodes)
    max_depth = max(d for t, d in nodes)
    visible_leaves = [t for t, d in nodes if not t.children and t.label is not None]
    silent_leaves = [t for t, d in nodes if not t.children and t.label is None]
    labels = [t.label for t in visible_leaves]
    duplicates = len(labels) - len(set(labels))

    net, im, fm = pm4py.convert_to_petri_net(tree)
    # Filter out helper transitions if needed
    simplicity = pm4py.simplicity_petri_net(net, im, fm)

    return {
        "name": tree_name,
        "nodes": total_nodes,
        "depth": max_depth,
        "visible_leaves": len(visible_leaves),
        "silent_leaves": len(silent_leaves),
        "duplicate_labels": duplicates,
        "net_places": len(net.places),
        "net_transitions": len(net.transitions),
        "net_arcs": len(net.arcs),
        "simplicity": round(simplicity, 3),
    }
```

# 8. Simplified Model

### 8.1 Target Semantics Selection: Operational Compliance (P1)
We select **P1 (Operational Compliance)** as the target semantics. In high-integrity operational environments, every revision must be audited prior to rework or closure, and approval must never precede audit. 

Model A correctly enforces the 1-to-1 checking invariant but introduces an unnecessary parallel block $+(\text{'Analyze Revision'}, \text{'Check Revision'})$ that permits an audit to precede analysis (`Check` before `Analyze`) and inflates Petri net state space with parallel split/join transitions. 

By serializing the revision lifecycle into a sequential pipeline—$\text{'Analyze Revision'}$ followed by $\text{'Check Revision'}$, followed by optional $\text{'Approve Revision'}$—we strictly preserve all P1 compliance invariants while eliminating concurrency overhead.

### 8.2 Compact Process-Tree Expression
```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

### 8.3 Self-Contained PM4Py Code
```python

simplified_model = pm4py.parse_process_tree(simplified_model_str)

print(f"Simplified Model Parsed: {simplified_model}")
```

# 9. Final Recommendation

### Suitability of Original Models
- **View P1 (Operational Compliance):** **Model A is suitable** because it strictly maintains the invariant that every revision cycle undergoes its own audit before rework or closure. **Model B is fundamentally unsuitable and dangerous**; it allows revisions to bypass checking entirely whenever rework occurs and permits premature approvals.
- **View P2 (Executive Dashboard):** **Both Model A and Model B are suitable** under P2's coarse abstraction, which collapses repeated audits to a Boolean flag. However, deploying Model B based solely on dashboard equivalence creates severe operational risk because it validates an unsound process.
- **View P3 (Bounded Testing):** **Neither model can substitute for the other.** Their bounded visible languages diverge almost completely (sharing only 4 traces out of 76 and 85).

### Recommendation: Adopt the Simplified Model
The **Simplified Model** should replace **both** Model A and Model B:
1. **Supersedes Model A:** It enforces the exact 1-to-1 compliance requirements of P1 while eliminating the illogical interleaving of checking before analysis, raising Petri net simplicity from $0.818$ to $0.867$, and reducing place/transition counts.
2. **Fixes Model B:** It completely eradicates the audit bypass and out-of-order approval flaws present in Model B while maintaining full compatibility with the P2 executive dashboard view.

### Warning on the Limits of Bounded Comparison
Bounded language comparison (P3) is a **falsification and regression testing technique, not a proof of unbounded equivalence**. 
- Observing equivalence up to bound $k$ does not guarantee equivalence at bound $k+1$, particularly in looping or concurrent nets where deferred deadlocks or token accumulation may emerge past the bounding horizon.
- Conversely, bounded divergence proves non-equivalence of the raw models, but requires semantic domain models (such as P1 and P2) to interpret whether the observed differences represent genuine operational defects or benign representational abstractions.
