# 1. SLA Estimands and Time Definitions

**Time origin**: `Submit` (case start).
**Horizon**: 72 hours after `Submit`.
**Event(s)**:
- **Terminal events**: `Resolve`, `Reject`, `Withdraw` (all mark successful/failed resolution).
- **Censoring**: `Transfer` (external exit) and `open` cases (cutoff at `duration_or_age_h`).
- **Competing risks**: `Reject`, `Withdraw`, `Transfer` (each competes for survival analysis).

**Estimands**:
1. **Probability of not being resolved by 72 hours (P)**:
   - *Definition*: Survival probability at 72h for all cases, including those transferred/censored.
   - *Contributions*:
     - Resolved at 76h  breach (100% risk of not resolved by 72h).
     - Open at 92h  censored (risk = 0.5 at 72h, but censored after 72h).
     - Withdrawn at 27h  breach (0% risk of not resolved by 72h).
     - Transferred at 68h  censored (risk = 0.96 at 72h, but transfer event is informative).

2. **Cumulative incidence of resolution after 72 hours (C)**:
   - *Definition*: Proportion of cases resolved *after* 72h, accounting for competing risks.
   - *Contributions*:
     - Resolved at 76h  contributes to C (1 case out of 1 total).
     - Open at 92h  censored (no contribution).
     - Withdrawn at 27h  no contribution.
     - Transferred at 68h  censored (no contribution, but transfer may bias incidence).

# 2. Event and Censoring Encoding

|-----------------|-----------------|---------------------|-----------------------------------------|---------------------------------------------------|
| Resolved        | 1               | None                | None                                    | -                                                 |

# 3. Why Naive Completed-Case Analysis is Biased

**Survivor bias**: Cases resolved *after* 72h (e.g., S03 at 76h) are excluded, skewing estimates toward early breaches.
**Informative censoring**:
- **Transfers (S08, S21, S32)**: Cases transferred early (e.g., S08 at 68h) are censored *before* 72h, but transfers may signal high risk. Treating them as non-informative ignores this.
- **Open cases**: Age at cutoff (e.g., S26 at 92h) is not random; longer gaps may correlate with unresolved issues.
**Competing risks**: Withdrawals/rejections (e.g., S05 at 9h) compete with resolution, requiring cause-specific modeling.
**Cohort imbalance**: Cohort B began after policy changes but was not randomized; priority assignment may differ between cohorts.

---
# 4. Statistical Analysis Plan

**Primary approach**: **Cause-specific hazards (CSH)** with competing risks.
- *Why?* Handles transfers/rejections as competing events while estimating resolution-specific risk.
- *Justification*: Avoids immortal-time bias (e.g., `Escalate` cannot be baseline) and leakage (e.g., `last_event_gap_h` is time-varying).

**Secondary approach**: **Multi-state model** with:
- States: `Submit  Screen  Review  Escalate  Resolve/Reject/Withdraw/Transfer`.
- Transitions: Time-dependent hazards for each stage (e.g., `Escalate`  `Resolve`).
- *Why?* Captures process-aware covariates (e.g., rework count, path length).

**Avoid**:
- Kaplan-Meier (ignores competing risks).
- Landmarking (assumes stability post-72h, which is violated by transfers).

---
# 5. Process-Aware Features and Stage Hazards

**Features from prefixes**:
- **Baseline**: `priority`, `escalated` (binary).
- **Time-varying**: `last_event_gap_h`, `rework_count`.
- **Post-treatment**: `prefix` (e.g., `Screen>Review>Escalate` vs. `Screen>AutoCheck`).
- **Leakage risks**:
  - `Escalate` cannot be baseline (occurs after `Submit`).
  - `duration_or_age_h` is informative (long gaps may indicate unresolved issues).

**State-transition diagram (Mermaid)**:

# 6. Sensitivity Analysis

**Variations**:
1. **Transfers**:
   - *Scenario 1*: Right-censored at 72h (non-informative).
   - *Scenario 2*: Cause-specific hazard (transfer as competing risk).
   - *Scenario 3*: Transfer = "high-risk" flag (binary covariate).
   - *Impact*: Scenario 2 may underestimate resolution risk; Scenario 3 introduces bias if transfers  high-risk.

2. **Informative censoring**:
   - *Assumption*: `last_event_gap_h` correlates with unresolved cases (e.g., S26 at 72h).
   - *Impact*: May inflate survival estimates if gap is proxy for risk.

3. **Cohort-policy effects**:
   - *Assumption*: Cohort B has higher escalation rates (e.g., S18 vs. S04).
   - *Impact*: May reverse if cohort B’s policy change improves outcomes.

# 7. Operational Interpretation

**Alerts**:
- **SLA breaches**: Flag cases where `duration_or_age_h > 72h` and `observed_status  resolved` (e.g., S26 at 92h).
- **High-risk paths**: Escalate cases with `prefix` containing `Escalate` + `Rework` (e.g., S13).

**Workload actions**:
- **Priority P1**: Monitor `Escalate`  `Resolve` transitions (e.g., S04 at 29h).
- **Cohort B**: Check if policy changes reduced transfers (e.g., S32 vs. S08).

**Governance**:
- **Calibration**: Compare P by priority (e.g., P1 vs. P3) to ensure fairness.
- **Fairness check**: Ensure cohort B’s SLA breaches align with policy intent.

# 8. Python Code

```python
import pandas as pd
import numpy as np
from lifelines import KaplanMeierFitter, CoxPHFitter
from lifelines.utils import survival_function
from lifelines.datasets import load_poisson_clinic_data
import pm4py
from pm4py.objects.log.importer.xes import importer as xes_importer

# --- Data construction ---
data = pd.DataFrame({
    'case': [S01, S02, ..., S32],  # Replace with actual list
    'cohort': ['A', 'A', ..., 'B'],
    'priority': ['P2', 'P3', ..., 'P1'],
    'duration_or_age_h': [18, 41, ..., 96],
    'observed_status': ['resolved', 'resolved', ..., 'open'],
    'prefix': ['Submit>Screen>AutoCheck>Resolve', ...],
    'escalated': [False, False, ..., True],
    'rework_count': [0, 0, ..., 1],
    'last_event_gap_h': [0, 0, ..., 55]
})

# --- Estimand 1: P (Survival probability at 72h) ---
kmf = KaplanMeierFitter()
kmf.fit(data['duration_or_age_h'], event_observed=data['observed_status'].map({'resolved': True, 'open': False}))
print("P (KM):", kmf.survival_function_[72])

# --- Estimand 2: Cause-specific hazards (CSH) ---
csf = CoxPHFitter()
csf.fit(
    data,
    duration_col='duration_or_age_h',
    event_col='observed_status',
    event_labels={
        'resolved': 'Resolve',
        'rejected': 'Reject',
        'withdrawn': 'Withdraw',
        'transfer': 'Transfer'
    },
    censoring_col='observed_status',
    censoring_labels={'open': 'Censor'}
)
print("CSH coefficients:", csf.summary())

# --- Process-aware features (PM4Py) ---
log = xes_importer.apply(
    "".join([f"{case}>".join(prefix.split('>')[1:]) for case, prefix in zip(data['case'], data['prefix'])])
)
prefixes = pm4py.get_prefixes_from_log(log)
print("Unique prefixes:", prefixes)

# --- Sensitivity: Transfer treatment ---
data['transfer_treatment'] = np.where(data['observed_status'] == 'transfer', 0, 1)  # 0=informative, 1=censor
csf_sensitivity = CoxPHFitter()
csf_sensitivity.fit(data, duration_col='duration_or_age_h', event_col='observed_status', event_labels=csf.event_labels, censoring_col='transfer_treatment')
print("Sensitivity (Transfer as covariate):", csf_sensitivity.summary())
```

# 9. Limitations and Additional Data

**Missing data needed**:
1. **Exact timestamps**: Replace `duration_or_age_h` with precise event times for hazard modeling.
2. **External outcomes**: Post-transfer resolution status (e.g., S08’s fate).
3. **Cutoff/start dates**: Cohort B’s policy rollout window.
4. **Time-varying workload**: Staffing changes affecting `Review`/`Escalate` rates.
5. **Assignment mechanism**: Why cases were assigned to P1/P2/P3 (e.g., severity vs. policy).

**Assumptions**:
- `Escalate` is not baseline (time-aware design required).
- `last_event_gap_h` is informative but not perfectly correlated with risk.
- Cohort B’s policy change is causal (no confounding by unmeasured factors).
