def build_csv(variants, period_prefix, start_time):
    rows = ["case:concept:name,concept:name,time:timestamp,source_seq,period"]
    case_no = 0

    for trace, count in variants:
        acts = trace.split(",")

        for _ in range(count):
            case_no += 1
            case_id = f"{period_prefix}-{case_no:05d}"

            # Extracted order is the order of the supplied trace string.
            # source_seq is the authoritative source-system order when available.
            source_positions = list(range(1, len(acts) + 1))

            if len(acts) >= 2 and acts[-2] == "Notify" and acts[-1] == "Decision":
                # Demonstration assumption: source sequence says Decision happened first.
                source_positions[-2], source_positions[-1] = (
                    source_positions[-1],
                    source_positions[-2],
                )

            for i, act in enumerate(acts):
                ts = start_time + timedelta(minutes=case_no * 19 + i * 17)
                ts_string = ts.strftime("%Y-%m-%d %H:%M:%S")
                rows.append(
                    f"{case_id},{act},{ts_string},{source_positions[i]},{period_prefix}"
                )

    return "\n".join(rows)

def get_dfg(log):
    try:
        result = pm4py.discover_dfg(log)
    except TypeError:
        result = pm4py.discover_dfg(
            log,
            variant="frequency",

    except Exception as e:

    if isinstance(result, tuple) and len(result) == 3:

    return result, {}, {}


def call_metric(func_name, log, model):
    func = getattr(pm4py, func_name, None)
    if func is None:
        print(f"{func_name} is not available in this PM4Py installation.")
        return None

    net, im, fm = model
    attempts = [
        (log, net, im, fm),
        (log, model),
    ]

    last_error = None
    for args in attempts:
        for kwargs in ({}, {"variant": "alignments"}):
            try:
                return func(*args, **kwargs)
            except TypeError as e:
                last_error = e
            except Exception as e:
                last_error = e

    print(f"{func_name} could not be called with standard signatures: {last_error}")
    return None


def summarize(label, log, model):

    print("DFG edges:", len(dfg))
    print("start activities:", sorted(start_activities)[:5])
    print("end activities:", sorted(end_activities)[:5])

    fitness = call_metric("fitness_alignments", log, model)
    print("fitness_alignments:", fitness)

    diagnostics = call_metric("conformance_diagnostics", log, model)
    if diagnostics is not None:
        print("diagnostic cases:", len(diagnostics))

    print()
    return fitness

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a measurement and model-maintenance failure, not a sudden collapse of operational discipline. The June drop is best explained by the UI relabeling of `Classify` as `Risk Screen`, the injection of the technical `Queue Routed` event, and ETL ordering that used ingestion time for `Decision` and `Notify`. The staged recovery of fitness—32% raw, 58% after label mapping, 81% after technical-event removal, and 89% after source-sequence ordering—shows that most June-July deviations were artifacts of log semantics and extraction. The August residual is substantially explained by the new `Supervisor Sign-off` requirement not being reflected in the normative tree; allowing optional sign-off raises cleaned August-September fitness from 66% to 86%, although that fix can overgeneralize. Confidence: high (about 85%) that measurement/model issues are the dominant cause of the reported conformance decline.

A real compliance concern may remain, but it is narrower and unproven. The 25 June-July and 30 August-September enhanced-review traces without a recorded `Compliance Check`, plus the supervisor memo and `Manual Override` usage, justify a targeted audit. However, stable approval rates, cycle times, and appeal rates, together with incomplete incident detection and missing high-value attributes, prevent concluding that employees became systematically noncompliant. Confidence: moderate-low (about 35%) that there is material deliberate noncompliance; moderate (about 55%) that at least some missing checks or overrides represent real control gaps.

Immediate actions: IT should restore source-sequence/business timestamps in conformance preprocessing, publish event-semantic contracts for `Risk Screen`, `Queue Routed`, and `Manual Override`, and join claim amount to the log. Process owners should version the normative model for the August policy and define data-aware sign-off rules. Compliance should audit enhanced-review cases without checks and overrides, stratified by value and reviewer.

Do not claim employee wrongdoing, process breakdown, or improved compliance solely from aggregate fitness changes until source-verified audits are complete.

## 8. Model-governance recommendation

1. Version every normative model with effective dates, owners, and change-control approval; when a policy such as high-value `Supervisor Sign-off` is introduced, update the conformance model before using it for compliance reporting.

2. Maintain an event-semantic contract that maps every emitted UI, gateway, ETL, and warehouse label to a canonical process-mining activity; require process-mining impact review before UI releases that rename screens or buttons.

3. Separate technical events from business events at ingestion by tagging provenance, event class, and source system; exclude technical events from conformance checking by default unless explicitly modeled.

4. Preserve authoritative source timestamps and source sequence numbers; conformance checking should use business-order evidence, while warehouse ingestion time should be retained only for debugging and audit trails.

5. Encode data-aware constraints, such as claim amount thresholds and resource authorizations, alongside control-flow models; do not rely on a control-flow-only tree to enforce conditional policies.

6. Perform post-release validation after any UI, ETL, gateway, or policy change: compare baseline and post-change variants, DFGs, alignment diagnostics, fitness, and precision, and require a manual audit sample before escalating conformance deviations as compliance findings.
