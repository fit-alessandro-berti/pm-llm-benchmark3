# 1. Assumptions and notation

- **A1 (window and time base)**: Observation window is \(T=[08{:}00,14{:}00]\) on 2026-05-12. I treat it as half-open \([08{:}00,14{:}00)\) for step-function computations; “state at 14:00” means **just before** 14:00.
- **A2 (rounding uncertainty)**: Every reported timestamp \(t\) was rounded to the nearest 5 minutes, so the true time lies in \([t-2.5\text{ min},\, t+2.5\text{ min}]\). For any difference of two rounded timestamps (e.g., wait \(=t_2-t_1\)), the **rounding-only** bound is approximately \([\,\max(0,d-5),\, d+5\,]\) minutes where \(d\) is the difference of the reported times.
- **A3 (simultaneous rounded events convention)**: For queue/WIP step functions, I use **half-open intervals** \([start,end)\) and order same-timestamp events as: **ends (departures) first**, then **starts**, then **arrivals**. This avoids double-counting at boundaries. Because of A2, any same-timestamp ordering is itself uncertain within \(\pm 2.5\) minutes; I treat resulting queue-length spikes of \(\pm 1\) around ties as uncertainty, not as physical truth.
- **A4 (capacity/servers)**: S1 has two single-task resources \(I1, I2\). S2 has two single-task resources \(C1, C2\).
- **A5 (C2 outage)**: \(C2\) is unavailable on \([10{:}55,11{:}10]\). A valid \(C2\) service interval must not intersect this outage. When computing S2 utilization denominators, I subtract 15 minutes of capacity (one server down for 15 minutes).
- **A6 (no bypass)**: No case intentionally bypasses S1 or S2; a case enters the S2 queue at its S1 completion time.
- **A7 (MISSING/OPEN/blank semantics)**:
  - **MISSING start**: activity completed and resource is known, but start is unobserved.
  - **OPEN**: started but not completed by 14:00 (right-censored end).
  - **Blank S2 start/end with completed S1**: waiting for S2 at 14:00 (right-censored waiting time).
  - **Blank S1 start/end**: waiting for S1 at 14:00 (right-censored waiting time).
- **A8 (feasible window for a missing start)**: For a missing start \(s\) with known end \(e\) on resource \(r\),
  \[
  s \in [L,U],\quad
  L=\max(\text{queue entry time},\,\text{previous known end on }r,\,\text{availability constraints}),\quad
  U=\min(e,\,\text{next known start on }r).
  \]
- **A9 (three scenarios for missing starts)**:
  - **Optimistic (O)**: \(s=L\) (min waiting, max service) for missing starts.
  - **Central (C)**: S1 missing starts chosen near “typical” 30 min service when feasible (\(s\approx e-30\) clipped to \([L,U]\)); S2 missing starts set to \(L\) because otherwise calibration service would become implausibly short given observed 40–50 min calibrations.
  - **Pessimistic (P)**: \(s=U\) (max waiting, min service). This is an extreme bound; for some cases it implies unrealistically short service and should be treated as a **worst-case envelope**, not the most likely reality.
- **A10 (queue/WIP membership)**:
  - In S1 queue if \(arrival\_s1 \le t < s1\_start\).
  - In S1 service if \(s1\_start \le t < s1\_end\) (or \(<14{:}00\) if OPEN).
  - In S2 queue if \(s1\_end \le t < s2\_start\) (or \(<14{:}00\) if waiting at 14:00).
  - In S2 service if \(s2\_start \le t < s2\_end\) (or \(<14{:}00\) if OPEN).

# 2. Reconstruction method and formulas

## 2.1 Per-case quantities

For case \(i\):
- \(a_i\): external arrival to S1 (`arrival_s1`)
- \(s_{1i}, e_{1i}\): S1 start/end (end may be right-censored at 14:00 if OPEN)
- \(s_{2i}, e_{2i}\): S2 start/end (start may be missing; end may be right-censored if OPEN)

Station-specific times (minutes):
- **S1 waiting**: \(W_{q1,i}=s_{1i}-a_i\) (range if \(s_{1i}\) missing/blank)
- **S1 service**: \(S_{1,i}=e_{1i}-s_{1i}\) (range if \(s_{1i}\) missing; right-censored if \(e_{1i}\) OPEN)
- **S1 sojourn**: \(T_{1,i}=W_{q1,i}+S_{1,i}=e_{1i}-a_i\) (for completed S1, this is fixed even if \(s_{1i}\) missing)

- **S2 waiting**: \(W_{q2,i}=s_{2i}-e_{1i}\) (range if \(s_{2i}\) missing; right-censored if waiting at 14:00)
- **S2 service**: \(S_{2,i}=e_{2i}-s_{2i}\) (range if \(s_{2i}\) missing; right-censored if \(e_{2i}\) OPEN)
- **S2 sojourn**: \(T_{2,i}=W_{q2,i}+S_{2,i}=e_{2i}-e_{1i}\) (for completed S2, fixed even if \(s_{2i}\) missing)

Total case sojourn (completed cases only):
- \(T_i=e_{2i}-a_i\). With rounded endpoints, rounding-only uncertainty is about \(\pm 5\) minutes (A2).

## 2.2 Queue length and WIP over time

Define (using A10):
- **Queue length** \(Q_1(t)\), \(Q_2(t)\)
- **In service** \(B_1(t)\), \(B_2(t)\)
- **Station WIP** \(L_1(t)=Q_1(t)+B_1(t)\), \(L_2(t)=Q_2(t)+B_2(t)\)
- **Total WIP** \(L(t)=L_1(t)+L_2(t)\)

Time-average WIP on \([t_0,t_1)\):
\[
\bar{L}=\frac{1}{t_1-t_0}\int_{t_0}^{t_1} L(t)\,dt,
\]
computed exactly for step functions by sweeping event boundaries (A3). Peak WIP is the maximum step value.

## 2.3 Rates

For an interval \([t_0,t_1)\), with \(\Delta=t_1-t_0\):
- **External arrival rate to S1**: \(\lambda_1 = N(\text{arrival\_s1}\in[t_0,t_1))/\Delta\)
- **S1 completion rate**: \(\mu_1 = N(s1\_end\in[t_0,t_1))/\Delta\)
- **S2 completion rate**: \(\mu_2 = N(s2\_end\in[t_0,t_1))/\Delta\)

Arrivals to S2 queue equal S1 completions by design (A6).

## 2.4 Busy time and utilization

For resource \(r\), busy time is the sum of overlaps between its service intervals and the window (right-censoring OPEN at 14:00 for elapsed busy).

For station utilization over an interval:
- S1 capacity (server-minutes): \(2\cdot \Delta\)
- S2 capacity: \(2\cdot \Delta - \text{overlap}([10{:}55,11{:}10], [t_0,t_1))\) (A5)

Utilization \(u = \text{busy server-minutes}/\text{available server-minutes}\). Rounding (A2) can create artificial 5-minute “gaps”, so utilization reported from rounded times is best treated as a **range** rather than exact.

## 2.5 Little’s Law check (only where defensible)

Classic Little’s Law \(L \approx \lambda W\) assumes a stable regime. Here the system is strongly transient (arrival burst early; multiple right-censored cases late). I therefore use Little-style checks only as **sanity checks**, expecting mismatch when WIP is trending.

# 5. Bottleneck and temporal interpretation

## 5.1 Evidence-driven interpretation

- **Early (08:00–10:00)**:
  - External arrivals to S1 are very high (6.5/h) vs S1 completions (3.0/h), so **S1 queue builds rapidly** (e.g., \(Q_1\) already ~3 by 09:00 and ~6 by 10:00).
  - S2 queue remains relatively small early (median S2 waits 5–20 minutes; \(L_2\) mean ~1.9 in 08–10), consistent with **S1 being the effective bottleneck** in this transient regime (S2 cannot be busier than the flow arriving from S1).

- **Middle (10:00–12:00)**:
  - Both stations run at high utilization in the rounded logs (S1 ~0.8–0.9; S2 ~0.82–0.89 with reduced capacity).
  - S2 waiting times increase (e.g., P08 waits ~55; P10 waits ~50; P11 waits at least ~55), and S2 WIP rises (mean ~3.9 in 10–12).
  - Interpretation: **bottleneck becomes shared/time-varying**, with S2 beginning to constrain flow.

- **Late (12:00–14:00)**:
  - External arrivals nearly stop (0.5/h), while S1 completes 7 cases (3.5/h), so **S1 drains**.
  - Meanwhile S2 still has **6 cases in station at the end** (4 waiting + 2 in service) and higher mean WIP than S1 (S2 mean WIP ~5.4 in 12–14 vs S1 ~4.9). This indicates **S2 is the operational bottleneck in the later period**.

Overall: the evidence best supports a **time-varying bottleneck**: S1 dominates early due to the arrival surge; S2 dominates later due to longer calibrations and residual backlog.

## 5.2 Maintenance interval (C2 outage) impact

The outage is observed on \([10{:}55,11{:}10]\), when \(C2\) had just completed P06 at 10:50 and does not start P08 until 11:15. In the rounded data, the outage:
- **does not visibly preempt** a running C2 calibration (no logged interval crosses the outage), but
- likely **removes up to ~15 minutes of potential capacity** during a time when the S2 queue already contains waiting work (e.g., P08 is waiting from 10:20 to 11:15).

However, late-window S2 waits of 65–85+ minutes and the presence of four cases still waiting at 14:00 cannot be explained by a 15-minute outage alone; they are more consistent with **systematic S2 capacity shortfall** (relative to S1 output) plus transient congestion.

# 6. Missingness, censoring, and sensitivity analysis

## 6.1 Missing-start feasible windows (tight constraints from resource calendars)

From resource non-overlap + known neighbors:
- **P07 S1 start** on I1: \(s_{1}\in[09{:}25,10{:}00]\) (after P05 ends 09:25, before its own end 10:00, and before I1’s next logged start 10:05).
- **P15 S1 start** on I1: \(s_{1}\in[11{:}40,12{:}15]\) (after P13 ends 11:40, before its own end 12:15, before next start 12:20).
- **P05 S2 start** on C1: \(s_{2}\in[09{:}45,10{:}15]\) (after P03 ends 09:45, before its own end 10:15, before next start 10:20).
- **P11 S2 start** on C2: \(s_{2}\in[12{:}00,12{:}25]\) (after P08 ends 12:00, before its own end 12:25, before next start 12:30; also avoids the earlier outage).

These windows imply **fixed station sojourns** but uncertain wait/service splits:
- P07 S1 sojourn \(=10{:}00-08{:}45=75\) min (fixed), but split \(W_{q1}\in[40,75]\), \(S_1\in[0,35]\).
- P05 S2 sojourn \(=10{:}15-09{:}25=50\) min (fixed), but split \(W_{q2}\in[20,50]\), \(S_2\in[0,30]\).
- P11 S2 sojourn \(=12{:}25-11{:}05=80\) min (fixed), but split \(W_{q2}\in[55,80]\), \(S_2\in[0,25]\).
- P15 S1 sojourn \(=12{:}15-10{:}10=125\) min (fixed), but split \(W_{q1}\in[90,125]\), \(S_1\in[0,35]\).

## 6.2 Three-scenario comparison (O/C/P)

- **Waiting vs service for missing-start cases**: the largest sensitivity is the **allocation** of fixed station sojourn into waiting vs service for P05/P07/P11/P15. Central choices (C) are guided by the observed typical service durations (S1 mostly 25–30; S2 mostly 40–50), making the “service≈0” edges of (P) unlikely.
- **Queue length / WIP**:
  - **Station WIP** (arrival-to-end at each station) is largely **insensitive** to missing-start imputations because it does not depend on the internal split between queue and service.
  - **Queue length** near tie times can vary by about \(\pm 1\) because of A2/A3, but the qualitative trajectory (S1 high early; S2 high late) is stable.
- **Utilization**:
  - Station utilizations remain high in all plausible scenarios; the pessimistic extreme (service→0 for missing starts) provides a lower bound but conflicts with the otherwise stable service durations in the data.
  - Rounding produces apparent 5-minute gaps between many tasks; true utilization may be slightly higher than “point-estimated” from rounded intervals.
- **Right censoring sensitivity**:
  - The largest unquantified uncertainty is from **censored waiting** (P22 at S1; P16/P18/P19/P20 at S2) and **OPEN service** (P21 at S1; P15/P17 at S2). Any estimate of mean waiting time that treats these as complete will be biased low.

## 6.3 Little’s-Law-style sanity check (illustrative, not definitive)

Example: S2 on 10:00–12:00 is not steady (arrivals exceed departures), so mismatch is expected.
- Departures in 10–12: 5 \(\Rightarrow \hat{\lambda}_{dep}=5/120\approx 0.0417\) per minute
- Mean S2 sojourn of those departures: \(\bar{W}\approx 59\) minutes
- \(\hat{\lambda}_{dep}\bar{W}\approx 2.46\) vs measured mean S2 WIP in 10–12 of \(\bar{L}_2\approx 3.88\)

The gap is consistent with **WIP increasing** during the interval (transient growth), violating steady-state assumptions rather than indicating a calculation error.

def parse_status_time(x):
    if x is None:
        return "BLANK", pd.NaT
    x = str(x).strip()
    if x == "":

    if x == "MISSING":

def predecessor_end(d, idx, act_prefix, res_col):
    res = d.loc[idx, res_col]
    if not isinstance(res, str) or res.strip() == "":
        return pd.NaT
    target_end = d.loc[idx, act_prefix + "_end_ts"]
    cand = d[(d[res_col] == res) & d[act_prefix + "_end_ts"].notna() & (d.index != idx) & (d[act_prefix + "_end_ts"] <= target_end)]
    return cand[act_prefix + "_end_ts"].max() if not cand.empty else pd.NaT

def successor_start(d, idx, act_prefix, res_col):
    res = d.loc[idx, res_col]
    if not isinstance(res, str) or res.strip() == "":
        return pd.NaT
    target_end = d.loc[idx, act_prefix + "_end_ts"]
    cand = d[(d[res_col] == res) & d[act_prefix + "_start_ts"].notna() & (d.index != idx) & (d[act_prefix + "_start_ts"] >= target_end)]
    return cand[act_prefix + "_start_ts"].min() if not cand.empty else pd.NaT
