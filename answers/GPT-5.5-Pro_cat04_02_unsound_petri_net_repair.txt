# 1. Executive Verdict

The net is structurally a workflow net: it has a unique source place, a unique sink place, and every place and transition lies on at least one source-to-sink path. It should **not** be expected to be sound. The principal defect is that the waiver branch is not synchronized with the mandatory analysis branch: `t_join_waived` consumes only `p_waived` and can produce `p_decision` while the analysis token is still in `p_analysis` or later stranded in `p_analysis_done`. Business consequence: a waived case can be authorized before analysis is complete, and even if a token reaches `sink`, the exact final marking `fm = {sink: 1}` is not reached because an analysis-branch token remains.

# 2. Structural Diagnosis

| Element or subnet                                               | Intended role                                                                           | Actual structural effect                                                                                                    | Potential symptom                                                                         |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `source`, `t_register`, `p_ready`                               | Start one case and make it ready for parallel work.                                     | `im = {source: 1}` enables only `t_register`; after registration one token reaches `p_ready`.                               | No defect here.                                                                           |
| `t_split` with outputs to `p_analysis` and `p_review`           | AND-split: start mandatory analysis and one review decision branch in parallel.         | Firing `t_split` creates one token in `p_analysis` and one token in `p_review`.                                             | Correct parallel start; later joins must consume both branches.                           |
| Analysis subnet: `p_analysis → t_analyze → p_analysis_done`     | Mandatory analysis must complete before authorization.                                  | Analysis completion creates `p_analysis_done`, but this place is only an input to `t_join_normal`, not to `t_join_waived`.  | On the waiver path, the analysis token can be ignored or stranded.                        |
| Standard review: `p_review → t_standard_review → p_review_done` | One possible review outcome.                                                            | Shares input `p_review` with `t_waive_review`, so standard review and waiver are in XOR conflict.                           | Correct: both review outcomes cannot occur in the same run.                               |
| Waiver review: `p_review → t_waive_review → p_waived`           | Alternative review outcome: formally record that review was waived.                     | Also consumes `p_review`, so it excludes standard review. It produces a distinct waiver token in `p_waived`.                | Correct distinction of the waiver outcome, but the token is routed to an incomplete join. |
| `t_join_normal`                                                 | Synchronize completed analysis with completed standard review.                          | Requires both `p_analysis_done` and `p_review_done`, then produces `p_decision`.                                            | Correct for standard-review cases.                                                        |
| `t_join_waived`                                                 | Intended to synchronize completed analysis with recorded waiver.                        | Has only one input, `p_waived`, and produces `p_decision`. It is not a real synchronization with analysis.                  | `p_decision` can be produced while analysis is incomplete or unconsumed.                  |
| `p_decision → t_authorize → sink`                               | Authorization after all prerequisites, then clean completion.                           | `t_authorize` only checks for `p_decision`. It does not know whether `p_decision` was produced by a proper synchronization. | Authorization can occur too early on the waiver path.                                     |
| Initial marking `im` and final marking `fm`                     | Accept exactly one token at `source` initially and exactly one token at `sink` finally. | `fm = {sink: 1}` means **no other tokens** may remain. A marking such as `{sink: 1, p_analysis_done: 1}` is not final.      | A run may put a token in `sink` but still fail proper completion.                         |
| Source-to-sink path condition                                   | Every node should be structurally relevant to the process.                              | Every place and transition lies on some source-to-sink path, including `p_waived` and `t_join_waived`.                      | The workflow-net check can pass even though the behavior is unsound.                      |

The structural issue is therefore not that the net is disconnected. The issue is that the waiver path reaches `p_decision` through a one-input silent transition, while the mandatory analysis branch created by `t_split` remains alive.

# 3. Marking-Based Counterexample

A legal firing sequence exposing the defect is:

```text
t_register, t_split, t_waive_review, t_join_waived, t_authorize
```

Using `{place: count}` notation and omitting zero-token places:

| Step | Fired transition | Resulting nonzero marking        | Enabled transitions                                | Observation                                                                                 |
| ---: | ---------------- | -------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------- |
|    0 | —                | `{source: 1}`                    | `t_register`                                       | Initial marking `im`.                                                                       |
|    1 | `t_register`     | `{p_ready: 1}`                   | `t_split`                                          | Case is registered.                                                                         |
|    2 | `t_split`        | `{p_analysis: 1, p_review: 1}`   | `t_analyze`, `t_standard_review`, `t_waive_review` | The split has created one token in each parallel branch.                                    |
|    3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}`   | `t_analyze`, `t_join_waived`                       | Waiver is recorded, but the analysis token still exists in `p_analysis`.                    |
|    4 | `t_join_waived`  | `{p_analysis: 1, p_decision: 1}` | `t_analyze`, `t_authorize`                         | Defect: `t_authorize` is enabled before `t_analyze`.                                        |
|   5A | `t_authorize`    | `{p_analysis: 1, sink: 1}`       | `t_analyze`                                        | A token exists in `sink`, but this is **not** `fm`, because `p_analysis` still has a token. |
|   6A | `t_analyze`      | `{p_analysis_done: 1, sink: 1}`  | none                                               | Dead marking, still not `fm`. The leftover `p_analysis_done` cannot be consumed.            |

The leftover token cannot be consumed because:

```text
t_join_normal requires both p_analysis_done and p_review_done
```

but the waiver route consumed the review token into `p_waived`, and `p_waived` was already consumed by `t_join_waived`. There is no remaining way to produce `p_review_done`. Also, the original `t_join_waived` has no input arc from `p_analysis_done`.

Authorization can also occur **after** `t_analyze`, but still without proper final completion. From Step 4 above:

| Step | Fired transition | Resulting nonzero marking             | Enabled transitions | Observation                                                                                    |
| ---: | ---------------- | ------------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------- |
|   5B | `t_analyze`      | `{p_analysis_done: 1, p_decision: 1}` | `t_authorize`       | Here `t_authorize` occurs after analysis, but analysis was not synchronized into the decision. |
|   6B | `t_authorize`    | `{p_analysis_done: 1, sink: 1}`       | none                | Again, a token exists in `sink`, but the exact final marking `fm = {sink: 1}` is not reached.  |

Equivalently, this full sequence is legal:

```text
t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize
```

It also ends in:

```text
{p_analysis_done: 1, sink: 1}
```

not in:

```text
{sink: 1}
```

So the waiver branch has two related symptoms: early authorization is possible, and every waived completion leaves an analysis-branch token behind.

# 4. Minimal-Repair Alternatives

Edit-cost model used here:

```text
add arc = 1
remove arc = 1
add place = 1
remove place = 1
add transition = 1
remove transition = 1
rewiring an arc = remove old arc + add new arc
pure comments = 0
renaming only = not counted as a behavioral repair
```

| Repair                                                          | Exact edits                                                                                                                                                                                                          | Edit cost | Preserved intent                                                                                                                                                                                | Changed behavior                                                                                                                                                                                                    | New risk                                                                                                                                                                                  |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. Add the missing analysis input to the waiver join**        | Add arc `p_analysis_done → t_join_waived`.                                                                                                                                                                           |       `1` | Preserves the original policy exactly: analysis is mandatory on both standard and waiver paths; waiver remains visibly distinct via `t_waive_review`; `p_waived` remains structurally distinct. | `t_join_waived` now requires both `p_waived` and `p_analysis_done`, so `p_decision` cannot be produced on the waiver path until analysis is complete.                                                               | There are two silent joins into `p_decision`, which is correct but may look like duplicated gateway logic in diagrams.                                                                    |
| **B. Route the waiver outcome into the normal synchronization** | Remove arc `t_join_waived → p_decision`.<br>Add arc `t_join_waived → p_review_done`.                                                                                                                                 |       `2` | Preserves mandatory analysis. Keeps visible waiver activity and keeps `p_waived` as a distinct intermediate waiver state.                                                                       | `t_join_waived` no longer authorizes the waiver branch directly. It silently converts `p_waived` into the generic completed-review place `p_review_done`; then `t_join_normal` synchronizes with `p_analysis_done`. | The name `t_join_waived` becomes slightly misleading: it is no longer the final synchronization, but a silent routing/normalization transition.                                           |
| **C. Explicit policy change: waiver may cancel/skip analysis**  | Add arc `p_analysis_done → t_join_waived`.<br>Add new silent transition `t_join_waived_skip`.<br>Add arcs `p_waived → t_join_waived_skip`, `p_analysis → t_join_waived_skip`, and `t_join_waived_skip → p_decision`. |       `5` | Preserves clean completion and preserves standard-review behavior. Handles both cases where analysis already happened and where waiver skips it.                                                | Changes the business rule: on the waiver path, analysis is no longer mandatory. If `t_join_waived_skip` fires, it consumes the unperformed analysis token from `p_analysis`.                                        | This violates the stated business intent unless the organization explicitly agrees that a waiver also waives analysis. It also introduces a silent choice between analyzing and skipping. |

Repair A is globally minimal for the stated business intent: zero edits cannot change the erroneous behavior, and one added arc is sufficient to make the waiver path consume the completed analysis token before producing `p_decision`.

Repair B is not globally cheaper than Repair A, but it is minimal under the additional design constraint that **all authorization decisions must pass through the existing normal synchronization `t_join_normal`**. One edit is insufficient for that design: the old direct arc to `p_decision` must be removed, and a new route into the normal review-complete place must be added.

Repair C is minimal for the stated optional-analysis policy under ordinary place/transition-net semantics because two different reachable waiver markings must be handled:

```text
{p_analysis: 1, p_waived: 1}
{p_analysis_done: 1, p_waived: 1}
```

A single ordinary transition cannot consume “either `p_analysis` or `p_analysis_done`”; it would require all its input places. Therefore one route must handle the analyzed waiver case and another must handle the skipped-analysis waiver case.

# 5. Corrected PM4Py Code

Selected repair: **Repair A**, adding `p_analysis_done → t_join_waived`.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

# Places
r_source = PetriNet.Place("source")
r_p_ready = PetriNet.Place("p_ready")
r_p_analysis = PetriNet.Place("p_analysis")
r_p_review = PetriNet.Place("p_review")
r_p_analysis_done = PetriNet.Place("p_analysis_done")
r_p_review_done = PetriNet.Place("p_review_done")
r_p_waived = PetriNet.Place("p_waived")
r_p_decision = PetriNet.Place("p_decision")
r_sink = PetriNet.Place("sink")

for place in [
    r_source,
    r_p_ready,
    r_p_analysis,
    r_p_review,
    r_p_analysis_done,
    r_p_review_done,
    r_p_waived,
    r_p_decision,
    r_sink,
]:
    repaired_net.places.add(place)

# Transitions
r_register = PetriNet.Transition("t_register", "Register Case")
r_split = PetriNet.Transition("t_split", None)
r_analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
r_standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
r_waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
r_join_normal = PetriNet.Transition("t_join_normal", None)
r_join_waived = PetriNet.Transition("t_join_waived", None)
r_authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for transition in [
    r_register,
    r_split,
    r_analyze,
    r_standard_review,
    r_waive_review,
    r_join_normal,
    r_join_waived,
    r_authorize,
]:
    repaired_net.transitions.add(transition)

# Registration and parallel split
petri_utils.add_arc_from_to(r_source, r_register, repaired_net)
petri_utils.add_arc_from_to(r_register, r_p_ready, repaired_net)
petri_utils.add_arc_from_to(r_p_ready, r_split, repaired_net)
petri_utils.add_arc_from_to(r_split, r_p_analysis, repaired_net)
petri_utils.add_arc_from_to(r_split, r_p_review, repaired_net)

# Mandatory analysis branch
petri_utils.add_arc_from_to(r_p_analysis, r_analyze, repaired_net)
petri_utils.add_arc_from_to(r_analyze, r_p_analysis_done, repaired_net)

# Standard review branch
petri_utils.add_arc_from_to(r_p_review, r_standard_review, repaired_net)
petri_utils.add_arc_from_to(r_standard_review, r_p_review_done, repaired_net)

# Waiver branch
petri_utils.add_arc_from_to(r_p_review, r_waive_review, repaired_net)
petri_utils.add_arc_from_to(r_waive_review, r_p_waived, repaired_net)

# Standard synchronization
petri_utils.add_arc_from_to(r_p_analysis_done, r_join_normal, repaired_net)
petri_utils.add_arc_from_to(r_p_review_done, r_join_normal, repaired_net)
petri_utils.add_arc_from_to(r_join_normal, r_p_decision, repaired_net)

# Repaired waiver synchronization:
# waiver authorization now requires both completed analysis and recorded waiver.
petri_utils.add_arc_from_to(r_p_analysis_done, r_join_waived, repaired_net)
petri_utils.add_arc_from_to(r_p_waived, r_join_waived, repaired_net)
petri_utils.add_arc_from_to(r_join_waived, r_p_decision, repaired_net)

# Authorization and completion
petri_utils.add_arc_from_to(r_p_decision, r_authorize, repaired_net)
petri_utils.add_arc_from_to(r_authorize, r_sink, repaired_net)

# Initial and final markings
repaired_im = Marking()
repaired_im[r_source] = 1

repaired_fm = Marking()
repaired_fm[r_sink] = 1
```

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

def marking_to_str(marking):
    nonzero = [
        (place.name, count)
        for place, count in marking.items()
        if count
    ]
    if not nonzero:
        return "{}"
    return "{" + ", ".join(
        f"{name}: {count}" for name, count in sorted(nonzero)
    ) + "}"

def copy_marking(marking):
    copied = Marking()
    for place, count in marking.items():
        if count:
            copied[place] = count
    return copied

def transition_by_name(petri_net, transition_name):
    matches = [t for t in petri_net.transitions if t.name == transition_name]
    if len(matches) != 1:
        raise ValueError(
            f"Expected exactly one transition named {transition_name!r}, "
            f"found {len(matches)}."
        )
    return matches[0]

def enabled_transition_names(petri_net, marking):
    enabled = pm4py.get_enabled_transitions(petri_net, marking)
    return sorted(t.name for t in enabled)

def arc_weight(arc):
    return getattr(arc, "weight", 1) or 1

def fire_named_transition(petri_net, marking, transition_name):
    transition = transition_by_name(petri_net, transition_name)
    enabled = set(pm4py.get_enabled_transitions(petri_net, marking))

    if transition not in enabled:
        raise RuntimeError(
            f"Transition {transition_name!r} is not enabled at "
            f"{marking_to_str(marking)}. Enabled transitions: "
            f"{enabled_transition_names(petri_net, marking)}"
        )

    new_marking = copy_marking(marking)

    for arc in transition.in_arcs:
        place = arc.source
        weight = arc_weight(arc)
        new_marking[place] = new_marking.get(place, 0) - weight
        if new_marking[place] == 0:
            del new_marking[place]
        elif new_marking[place] < 0:
            raise RuntimeError(
                f"Negative token count while firing {transition_name!r}."
            )

    for arc in transition.out_arcs:
        place = arc.target
        weight = arc_weight(arc)
        new_marking[place] = new_marking.get(place, 0) + weight

    return new_marking

def replay_sequence(title, petri_net, initial_marking, final_marking, sequence):
    print(f"\n=== Replay: {title} ===")
    marking = copy_marking(initial_marking)
    print(f"Start: {marking_to_str(marking)}")
    print(f"Enabled: {enabled_transition_names(petri_net, marking)}")

    for transition_name in sequence:
        marking = fire_named_transition(petri_net, marking, transition_name)
        print(f"After {transition_name}: {marking_to_str(marking)}")
        print(f"Enabled: {enabled_transition_names(petri_net, marking)}")

    print(f"Equals final marking? {marking == final_marking}")
    return marking

def run_pm4py_diagnostics(title, petri_net, initial_marking, final_marking):
    print(f"\n=== PM4Py diagnostics: {title} ===")

    print("Workflow net?")
    print(pm4py.check_is_workflow_net(petri_net))

    print("Enabled transitions at initial marking:")
    print(enabled_transition_names(petri_net, initial_marking))

    print("Soundness:")
    print(pm4py.check_soundness(
        petri_net,
        initial_marking,
        final_marking,
        print_diagnostics=True,
    ))

    print("Reachability graph:")
    rg = pm4py.convert_to_reachability_graph(
        petri_net,
        initial_marking,
        final_marking,
    )
    print(rg)
    return rg

# Required PM4Py calls on both nets
original_rg = run_pm4py_diagnostics("original", net, im, fm)
repaired_rg = run_pm4py_diagnostics(
    "repaired",
    repaired_net,
    repaired_im,
    repaired_fm,
)

# Counterexample on the original net:
# this reaches a sink token while leaving the analysis branch unfinished/stranded.
original_bad_sequence = [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_join_waived",
    "t_authorize",
    "t_analyze",
]

replay_sequence(
    "original waiver counterexample",
    net,
    im,
    fm,
    original_bad_sequence,
)

# Positive waiver path on the repaired net:
# t_join_waived is no longer enabled until t_analyze has completed.
repaired_good_waiver_sequence = [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_analyze",
    "t_join_waived",
    "t_authorize",
]

replay_sequence(
    "repaired waiver path",
    repaired_net,
    repaired_im,
    repaired_fm,
    repaired_good_waiver_sequence,
)
```

Expected qualitative difference:

The original net should pass the workflow-net check but fail soundness because the waiver route can create a sink token together with a leftover analysis token, and some reachable markings cannot complete properly. The repaired net should still pass the workflow-net check, and the waiver route should no longer enable `t_authorize` before `t_analyze`; the repaired waiver sequence should end exactly in `repaired_fm`.

No exact diagnostic keys, state-space sizes, or numeric reachability counts are assumed here.

# 7. Repair Trade-Offs and Residual Risks

With the selected repair, waiver and standard review remain distinguishable. The visible transitions are still different:

```text
t_standard_review  label = "Perform Standard Review"
t_waive_review     label = "Record Review Waiver"
```

The token states also remain different before synchronization:

```text
standard path: p_review_done
waiver path:   p_waived
```

So the waiver remains auditable.

The selected repair does introduce two silent joins leading to `p_decision`:

```text
t_join_normal
t_join_waived
```

That is not duplicate behavior in the harmful sense, because the two joins are enabled after mutually exclusive review outcomes. However, model readers may still confuse the two silent transitions unless the diagram or code comments clarify that `t_join_waived` is the waiver-specific AND-join.

Soundness alone does not prove alignment with the business rule. For example, Repair C could be sound while deliberately allowing waiver to skip analysis. Soundness checks proper completion and absence of behavioral dead ends; they do not know that “analysis is mandatory” is a business obligation unless the model structure enforces it.

Positive regression traces should include at least these visible behaviors, allowing analysis and review/waiver to occur in either parallel order before authorization:

```text
Register Case,
Perform Analysis,
Perform Standard Review,
Authorize Case
```

```text
Register Case,
Perform Standard Review,
Perform Analysis,
Authorize Case
```

```text
Register Case,
Perform Analysis,
Record Review Waiver,
Authorize Case
```

```text
Register Case,
Record Review Waiver,
Perform Analysis,
Authorize Case
```

Negative regression traces should reject or fail replay for:

```text
Register Case,
Record Review Waiver,
Authorize Case
```

```text
Register Case,
Perform Standard Review,
Authorize Case
```

```text
Register Case,
Perform Analysis,
Authorize Case
```

```text
Register Case,
Perform Standard Review,
Record Review Waiver,
Authorize Case
```

The first negative trace detects the original waiver bypass. The second detects bypass of mandatory analysis on the standard-review path. The third detects authorization without any review outcome. The fourth detects accidental loss of XOR behavior between standard review and waiver.

To detect an accidental bypass of mandatory analysis structurally, inspect every transition that produces `p_decision`. Under the selected repair, both are required to consume `p_analysis_done`:

```text
p_analysis_done → t_join_normal → p_decision
p_analysis_done → t_join_waived → p_decision
```

A simple structural assertion can check that every transition with an output arc to `p_decision` has an input arc from `p_analysis_done`. For trace-level testing, every complete trace containing `Authorize Case` should contain a preceding `Perform Analysis`.

# 8. Final Recommendation

Deploy **Repair A**: add `p_analysis_done → t_join_waived`. It is the smallest possible behavioral repair under the stated edit-cost model, preserves the original business rule that analysis is always mandatory, keeps standard review and waiver distinguishable, and directly fixes the missing synchronization.

Use **Repair B** as the fallback if the modeling team strongly prefers a single authorization synchronization point. Repair B is slightly more expensive but conceptually attractive: waiver is first converted into a completed-review outcome, and then the existing normal join handles both standard review and waiver cases.

Do not deploy Repair C unless the business explicitly changes the policy so that a recorded waiver can also waive analysis. It can be made behaviorally clean, but it contradicts the stated intent that analysis is always mandatory.
