# 1. Executive Verdict

Structurally the model *is* a workflow net: `source` is the unique place with no input arc, `sink` the unique place with no output arc, and every place and transition lies on a directed `source`→`sink` path. So `check_is_workflow_net` should pass, and soundness is a fair expectation for it.

Behaviorally it is **not sound**. The principal defect is that `t_join_waived` is a *one-input* transition: it consumes only `p_waived` and produces `p_decision`, so the waiver branch never synchronizes with the analysis branch. The AND-split at `t_split` is therefore closed by an unmatched join on the waiver route.

Business consequence: on any waiver case, `t_authorize` can fire before (or without) `Perform Analysis`, and a token is stranded in `p_analysis`/`p_analysis_done` after the sink is marked. Authorization escapes the mandatory-analysis control and cases never terminate properly.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_split` (silent) | AND-split: open analysis branch and review branch concurrently | Correct AND-split: one input `p_ready`, two outputs `p_analysis`, `p_review` — two concurrent tokens | None in isolation; but every AND-split needs a matching AND-join on *every* completion route |
| `p_review` → `{t_standard_review, t_waive_review}` | XOR-choice between standard review and waiver | Correct free-choice conflict: both transitions have preset exactly `{p_review}`; exactly one fires, consuming the single review token | None; the choice itself is well modelled |
| `t_analyze` / `p_analysis_done` | Mandatory analysis, always executed | Structurally reachable, but nothing *forces* its completion before `t_authorize` on the waiver route | Authorization without analysis; residual token |
| `t_join_normal` (silent) | AND-join of analysis + standard review | Correct 2-input join: preset `{p_analysis_done, p_review_done}` → `p_decision`. The standard-review route is sound | None on the standard route |
| `t_join_waived` (silent) | AND-join of analysis + waiver | **Defect.** Preset is only `{p_waived}`; it is a pass-through relabeller, not a join. The analysis token is never consumed on this route | Improper completion: extra token left; `t_authorize` enabled too early |
| `p_analysis_done` (waiver route) | Feed the join | Has exactly one output arc, to `t_join_normal`, which additionally requires `p_review_done`. Under a waiver `p_review_done` can never be marked | Dead token: a marked `p_analysis_done` with no way to be consumed |
| `p_decision` → `t_authorize` → `sink` | Single authorization then completion | Correct, but `p_decision` can be marked from an unsynchronized route | Sink marked while other places still hold tokens |
| `im = [source]`, `fm = [sink]` | Standard WF-net accepting markings | Correct and well formed | `fm` is *exactly* `{sink:1}`; any co-existing token means `fm` is not reached |
| Global connectivity | Every node on a source-to-sink path | Holds: `source→t_register→p_ready→t_split→{p_analysis→t_analyze→p_analysis_done→t_join_normal, p_review→t_waive_review→p_waived→t_join_waived}→p_decision→t_authorize→sink` covers all nine places and eight transitions | WF-net check passes and can mislead a reviewer into assuming soundness |

The key asymmetry: `t_split` creates two tokens; `t_join_normal` destroys two; `t_join_waived` destroys one. Token count on the waiver route is therefore not conserved back to one.

# 3. Marking-Based Counterexample

## Counterexample A — waiver taken before analysis

Firing sequence from `im`:

`t_register`, `t_split`, `t_waive_review`, `t_join_waived`, `t_authorize`, `t_analyze`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (`im`) | `source:1` | `t_register` | Initial marking |
| 1 | `t_register` | `p_ready:1` | `t_split` | Case registered |
| 2 | `t_split` | `p_analysis:1`, `p_review:1` | `t_analyze`, `t_standard_review`, `t_waive_review` | **Two tokens created**, one per parallel branch |
| 3 | `t_waive_review` | `p_analysis:1`, `p_waived:1` | `t_analyze`, `t_join_waived` | Waiver route chosen; analysis branch still pending |
| 4 | `t_join_waived` | `p_analysis:1`, `p_decision:1` | `t_analyze`, `t_authorize` | The "join" fired with **one** input token; it never waited for the analysis branch |
| 5 | `t_authorize` | `p_analysis:1`, `sink:1` | `t_analyze` | **`t_authorize` occurs before `t_analyze`** — authorization without any analysis |
| 6 | `t_analyze` | `p_analysis_done:1`, `sink:1` | *(none)* | Dead marking ≠ `fm` |

Interpretation:

- At step 5 a token **exists in `sink`**, but the reached marking is `{p_analysis:1, sink:1}`, which is **not** the final marking `fm = {sink:1}`. Marking equality is required; sink-occupancy is not sufficient.
- At step 6 the leftover token moves to `p_analysis_done` but **cannot be consumed**: the only output arc of `p_analysis_done` goes to `t_join_normal`, whose preset also contains `p_review_done`. Since the review token was consumed by `t_waive_review` and `t_standard_review` can no longer fire (`p_review` is empty), `p_review_done` is unreachable from here. Hence `t_join_normal` is permanently disabled and the token is dead.
- This violates *proper completion* (tokens remain outside the final marking) and, at step 6, the *option to complete* (a dead marking that is not `fm`).

## Counterexample B — analysis completed first, waiver afterwards

Firing sequence: `t_register`, `t_split`, `t_analyze`, `t_waive_review`, `t_join_waived`, `t_authorize`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (`im`) | `source:1` | `t_register` | Initial marking |
| 1 | `t_register` | `p_ready:1` | `t_split` | — |
| 2 | `t_split` | `p_analysis:1`, `p_review:1` | `t_analyze`, `t_standard_review`, `t_waive_review` | Both branches live |
| 3 | `t_analyze` | `p_analysis_done:1`, `p_review:1` | `t_standard_review`, `t_waive_review` | Analysis genuinely performed |
| 4 | `t_waive_review` | `p_analysis_done:1`, `p_waived:1` | `t_join_waived` | `t_join_normal` is *not* enabled: `p_review_done` empty |
| 5 | `t_join_waived` | `p_analysis_done:1`, `p_decision:1` | `t_authorize` | Analysis token ignored again |
| 6 | `t_authorize` | `p_analysis_done:1`, `sink:1` | *(none)* | Deadlock with residual token; `fm` not reached |

So even the "well-behaved" ordering, where analysis is really done, cannot terminate properly. Counterexample B isolates the *token-conservation* defect (improper completion) from the *ordering* defect (unforced authorization) exposed by A. Both stem from the same missing input arc, but they are distinct observable failures: A also permits authorization of a completely un-analysed case.

By contrast, the standard-review route is fine: `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize` yields exactly `{sink:1}` with no leftovers. The unsoundness is confined to the waiver branch.

# 4. Minimal-Repair Alternatives

**Edit-cost model.** Cost = 1 per arc added or removed, 2 per place added or removed, 3 per transition added or removed. Rationale: arcs are pure wiring; places carry state and appear in markings/final-marking definitions; transitions carry labels, semantics, event-log alignment and documentation, so they are the most expensive artifact to add or delete. Renaming is free but also behaviorally void, so it never counts as a repair. All repairs must preserve the WF-net property (no orphaned nodes).

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1 — Funnel the waiver into the normal synchronization** | Remove arc `t_join_waived → p_decision`; add arc `t_join_waived → p_review_done`. (`t_join_waived` becomes a silent "waiver counts as a completed review outcome" converter.) | 2 arcs removed/added = **2** | Mandatory analysis on both routes; XOR between standard review and waiver; single authorization point | Waiver route now flows `p_waived → t_join_waived → p_review_done`, and `t_join_normal` performs the one and only AND-join with `p_analysis_done`. Authorization is impossible before `t_analyze`. | `p_review_done` becomes an overloaded state ("reviewed *or* waived"); a reader of the marking alone can no longer tell which outcome occurred — the distinction survives only in the firing of `t_standard_review` vs `t_waive_review`. Adds one silent step to every waiver trace. |
| **R1b — R1 consolidated** (variant, for comparison) | Remove arcs `t_waive_review→p_waived`, `p_waived→t_join_waived`, `t_join_waived→p_decision`; add arc `t_waive_review→p_review_done`; remove place `p_waived`; remove transition `t_join_waived` | 4 arcs (4) + 1 place (2) + 1 transition (3) = **9** | Same as R1 | Same reachable *visible* language as R1, one fewer silent step | Destroys the explicit `p_waived` state, which may be referenced by dashboards/queries; largest edit |
| **R2 — Give the waiver route a real two-input join** | Add arc `p_analysis_done → t_join_waived` | 1 arc = **1** | Mandatory analysis on both routes; waiver stays a first-class, separately observable state (`p_waived`) and a separate join | `t_join_waived` now requires `p_analysis_done` **and** `p_waived`, so it can only fire after `t_analyze`; token count is conserved (2 in, 1 out), mirroring `t_join_normal` | The net loses the free-choice property: `p_analysis_done` now has two output transitions with different presets (`t_join_normal` also needs `p_review_done`). Still sound, but some free-choice-dependent analyses/discovery round-trips no longer apply. Two structurally similar silent joins invite modelling confusion. |
| **R3 — Policy change: analysis optional *only* under waiver** | Add arc `p_analysis_done → t_join_waived` (as R2); add transition `t_join_waived_skip` (silent) with arcs `p_analysis → t_join_waived_skip`, `p_waived → t_join_waived_skip`, `t_join_waived_skip → p_decision` | 4 arcs (4) + 1 transition (3) = **7** | XOR review choice; single authorization; token conservation | **Stated policy change:** when a waiver is recorded, the case may proceed to authorization with the analysis branch abandoned (unstarted analysis is silently absorbed). If analysis already finished, the R2 join is used instead. | Weakens a control that the business stated as invariant ("analysis is always mandatory") — requires explicit sign-off. Also introduces a race: whether the skip or the proper join fires depends only on whether `t_analyze` happened to fire first, which is non-deterministic in the model and hard to audit. |

## Minimality justification

Under the stated cost model, **R2 (cost 1) is the unique minimum**. It is also minimal in a stronger sense: no zero-cost edit can fix the net (soundness fails behaviorally, and renaming is cost-0 but behavior-preserving), and any single-arc edit other than `p_analysis_done → t_join_waived` either leaves `t_join_waived` unsynchronized or breaks the standard route — so R2 is the only cost-1 repair that restores soundness.

**R1 (cost 2) is the minimum within the "one join only" family.** It cannot be done for cost 1: simply redirecting `t_waive_review` to `p_review_done` without touching `p_waived`/`t_join_waived` would orphan those nodes off any source-to-sink path and break the WF-net property, so at least one removal plus one addition (or a remove+add pair on `t_join_waived`'s output) is required.

**No ties occur** among R1 (2), R2 (1), R3 (7), R1b (9). R1 and R1b are behaviorally equivalent at the level of visible labels but not cost-equivalent; R1 dominates R1b, so R1b is dropped from consideration. R3 is not comparable on cost alone because it changes the policy — a cheaper repair that preserves the stated policy always dominates it unless the business explicitly requests optional analysis.

Note that R2 is cheapest but R1 is structurally cleaner (free-choice, one join). The cost model deliberately does not price "free-choiceness"; that trade-off is resolved in §8.

# 5. Corrected PM4Py Code

Selected repair: **R1** — the waiver outcome is funnelled into the single normal synchronization.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in [
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
]:
    repaired_net.places.add(p)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
# t_join_waived is retained but demoted: it is no longer a (pseudo) join.
# It is a silent converter meaning "a recorded waiver counts as a settled review outcome".
join_waived = PetriNet.Transition("t_join_waived", None)
# t_join_normal is now the single AND-join that closes the split created by t_split.
join_normal = PetriNet.Transition("t_join_normal", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in [
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
]:
    repaired_net.transitions.add(t)

petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

# --- REPAIR (R1) -----------------------------------------------------------
# Original: t_join_waived -> p_decision  (single-input pass-through, unsound)
# Repaired: t_join_waived -> p_review_done
# The waiver token now re-enters the review branch, so the only way to reach
# p_decision is through the genuine two-input AND-join t_join_normal.
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_review_done, repaired_net)
# ---------------------------------------------------------------------------

petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

Sanity trace of the waiver route in the repaired net:
`{source:1}` →`t_register`→ `{p_ready:1}` →`t_split`→ `{p_analysis:1, p_review:1}` →`t_waive_review`→ `{p_analysis:1, p_waived:1}` →`t_join_waived`→ `{p_analysis:1, p_review_done:1}` →`t_analyze`→ `{p_analysis_done:1, p_review_done:1}` →`t_join_normal`→ `{p_decision:1}` →`t_authorize`→ `{sink:1}` = `repaired_fm`. `t_authorize` is unreachable before `t_analyze`, and no token is left behind.

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking
from pm4py.objects.petri_net.semantics import ClassicSemantics

# Assumes `net`, `im`, `fm` (original) and
# `repaired_net`, `repaired_im`, `repaired_fm` (repaired) already exist.

def show_marking(marking, prefix=""):
    """Print only the nonzero places of a marking, sorted for stable output."""
    items = sorted((p.name, n) for p, n in marking.items() if n > 0)
    print(prefix + "{" + ", ".join(f"{name}:{n}" for name, n in items) + "}")


def enabled_names(a_net, marking):
    return sorted(t.name for t in pm4py.get_enabled_transitions(a_net, marking))


def fire(a_net, marking, transition_name):
    """Fire a transition BY NAME, refusing to move tokens if it is not enabled."""
    candidates = [t for t in a_net.transitions if t.name == transition_name]
    if not candidates:
        raise KeyError(f"no transition named {transition_name!r}")
    t = candidates[0]
    enabled = pm4py.get_enabled_transitions(a_net, marking)
    if t not in enabled:
        raise RuntimeError(
            f"{transition_name} is NOT enabled in "
            f"{ {p.name: n for p, n in marking.items() if n > 0} }"
        )
    return ClassicSemantics().execute(t, a_net, marking)


def replay(a_net, marking, sequence, target_fm, title):
    print(f"\n=== {title} ===")
    show_marking(marking, "step 0            : ")
    print("   enabled:", enabled_names(a_net, marking))
    for i, name in enumerate(sequence, start=1):
        try:
            marking = fire(a_net, marking, name)
        except RuntimeError as exc:
            print(f"step {i} BLOCKED   : {exc}")
            break
        show_marking(marking, f"step {i} {name:<17}: ")
        print("   enabled:", enabled_names(a_net, marking))
    print("token in sink?      ",
          any(p.name == "sink" and n > 0 for p, n in marking.items()))
    print("marking == fm?      ", marking == target_fm)
    return marking


for label, n_, i_, f_ in [("ORIGINAL", net, im, fm),
                          ("REPAIRED", repaired_net, repaired_im, repaired_fm)]:
    print(f"\n########## {label} ##########")
    print("is workflow net:", pm4py.check_is_workflow_net(n_))
    print("enabled at im  :", enabled_names(n_, i_))
    print("soundness:")
    print(pm4py.check_soundness(n_, i_, f_, print_diagnostics=True))
    rg = pm4py.convert_to_reachability_graph(n_, i_, f_)
    print("reachability graph:", len(rg.states), "states,",
          len(rg.transitions), "edges")

# Counterexample A on the original net (waiver before analysis)
replay(net, im,
       ["t_register", "t_split", "t_waive_review",
        "t_join_waived", "t_authorize", "t_analyze"],
       fm, "ORIGINAL / counterexample A")

# The same visible order on the repaired net: t_authorize must now be blocked
replay(repaired_net, repaired_im,
       ["t_register", "t_split", "t_waive_review",
        "t_join_waived", "t_authorize"],
       repaired_fm, "REPAIRED / A is blocked")

# Repaired happy path over the waiver route
replay(repaired_net, repaired_im,
       ["t_register", "t_split", "t_waive_review", "t_join_waived",
        "t_analyze", "t_join_normal", "t_authorize"],
       repaired_fm, "REPAIRED / waiver route completes properly")

# Repaired happy path over the standard route
replay(repaired_net, repaired_im,
       ["t_register", "t_split", "t_analyze", "t_standard_review",
        "t_join_normal", "t_authorize"],
       repaired_fm, "REPAIRED / standard route completes properly")
```

**Expected qualitative differences** (no fabricated numbers; the printed state/edge counts come from the actual run, and I do not claim their values here):

- `check_is_workflow_net` returns **True for both** nets. This is the trap: the structural check cannot see the defect.
- `check_soundness` returns **False for the original** and **True for the repaired** net. The original's diagnostics should point at improper termination / a dead or unbounded-in-spirit residue on the waiver branch and at silent transitions that never participate in a proper synchronization; I deliberately do not quote specific WOFLAN diagnostic keys or values.
- `get_enabled_transitions` at `im` is `{t_register}` for both. The discriminating call is later: in the original, after `t_register, t_split, t_waive_review, t_join_waived`, the enabled set contains **`t_authorize`** alongside `t_analyze`; in the repaired net the corresponding marking enables only `t_analyze`, and the `replay` helper raises `RuntimeError` when asked to fire `t_authorize` — that raised error *is* the regression assertion.
- `convert_to_reachability_graph` on the original contains at least one **dead state that is not `fm`** (the marking `{p_analysis_done:1, sink:1}`) plus a state where `sink` is marked while `p_analysis` still holds a token. The repaired graph's only terminal state is `fm`. The repaired graph is expected to be somewhat larger in states than a purely sequential model because the analysis and review branches interleave, but I have not enumerated it.

# 7. Repair Trade-Offs and Residual Risks

**Are waiver and standard review still distinguishable?** Yes, but the locus of the distinction shifts. Under R1 both outcomes deposit a token in the shared place `p_review_done`, so the *marking* no longer records which outcome happened; only the firing of the visible transition `t_standard_review` vs `t_waive_review` does. Every event log and alignment still separates them, since both carry distinct visible labels, and the state `p_waived` is still visited on the waiver route. Anything that queries the state space rather than the log (e.g. "how many cases are currently waived?") must be rewritten to look at `p_waived` before `t_join_waived` fires, which is a transient state. R2 preserves the distinction all the way to the join and is preferable if downstream tooling depends on marking-level state.

**Duplicate behavior or confusion through silent transitions?** R1 leaves `t_join_waived` as a silent transition whose only purpose is to relabel a token. It adds an invisible step to every waiver trace and could be inlined (R1b) at higher edit cost. It does not create duplicate *visible* behavior: no visible label occurs on two transitions, and there is no silent loop, so alignment costs and replay remain unambiguous. R2's risk is different: two silent joins with overlapping presets over `p_analysis_done`, which is harder for a human reader to check and breaks free-choice, and free-choice violations are a classic source of surprising discovery/repair-tool behavior later. R3 is the worst here — its skip transition is a silent bypass of a mandatory control, exactly the thing an auditor would want to be visible.

**Does soundness prove alignment with the business rule?** No. Soundness is a property of the model in isolation: option to complete, proper completion, no dead transitions. It says nothing about whether "analysis is mandatory" or "authorization only after both branches" is what the model encodes. R3, for example, would very likely pass `check_soundness` while explicitly violating the stated policy. Soundness is necessary, not sufficient; the ordering constraint must be verified separately, by the reachability/enabledness assertions in §6 or by conformance checking against curated traces.

**Regression tests.** Positive traces that must fit with zero deviations:
1. `Register Case, Perform Analysis, Perform Standard Review, Authorize Case`
2. `Register Case, Perform Standard Review, Perform Analysis, Authorize Case` (interleaving order of the parallel branches)
3. `Register Case, Perform Analysis, Record Review Waiver, Authorize Case`
4. `Register Case, Record Review Waiver, Perform Analysis, Authorize Case`

Negative traces that must *not* fit (nonzero alignment cost / blocked replay):
5. `Register Case, Record Review Waiver, Authorize Case` — the exact bug: authorization without analysis
6. `Register Case, Perform Analysis, Authorize Case` — no review outcome at all
7. `Register Case, Perform Standard Review, Record Review Waiver, Perform Analysis, Authorize Case` — both review outcomes (XOR violated)
8. `Register Case, Perform Analysis, Perform Standard Review, Authorize Case, Authorize Case` — double authorization
9. `Perform Analysis, ...` without `Register Case` first

Trace 5 is the primary regression test; it is accepted by the original net and must be rejected after repair.

**Detecting an accidental bypass of mandatory analysis.** Three complementary checks, all cheap enough for CI: (a) a *structural invariant* — assert that every transition on a path into `p_decision` has `p_analysis_done` in its preset, i.e. `all("p_analysis_done" in {a.source.name for a in t.in_arcs} for t in p_decision.in_arcs_sources)`; under R1 that is just `t_join_normal`, under R2 it is both joins, and under R3 it deliberately fails; (b) a *reachability assertion* — enumerate the reachability graph and assert no state marking `p_decision` (or `sink`) is reachable without `t_analyze` having fired, which the `replay` helper approximates by asserting that firing `t_authorize` early raises; (c) a *log-level monitor* in production — a rule that flags any case whose `Authorize Case` event has no preceding `Perform Analysis` event for the same case id, which catches bypasses introduced by the executing system even when the model is correct.

# 8. Final Recommendation

**Deploy R1** (redirect `t_join_waived` to `p_review_done`); **keep R2** (add `p_analysis_done → t_join_waived`) **as the fallback.**

R2 is strictly cheaper under the edit-cost model — one added arc against R1's remove-plus-add — and if the sole criterion were edit distance it would win. I still prefer R1 for deployment for reasons the cost model intentionally does not price. R1 leaves the net **free-choice**: the only place with multiple output transitions is `p_review`, whose successors share an identical preset. R2 makes `p_analysis_done` a non-free-choice conflict point between two silent joins with different presets. Both nets are sound, but the free-choice one is far easier to reason about, admits stronger structural soundness results, survives round-trips through discovery and reduction tooling more predictably, and — most practically — leaves exactly **one** AND-join closing the one AND-split, which is the invariant a future maintainer will actually check. R2 leaves two similar silent joins whose difference is a single easily-deleted arc; the defect just repaired is precisely a missing arc on such a join, so R2 keeps the model one careless edit away from the original bug.

The cost of R1 is that `p_review_done` becomes an overloaded state and waiver traces gain a silent step. Neither affects the visible language, log-level distinguishability, or conformance checking.

If marking-level observability of the waiver is a hard requirement — a dashboard or downstream system that reads `p_waived` versus `p_review_done` as distinct case states — switch to R2. It is cheaper, equally sound, and preserves that distinction end to end; accept the free-choice loss and compensate with the structural invariant check from §7.

R3 is **not** recommended in either slot: it silently relaxes the stated mandatory-analysis policy and should only be revisited if the business explicitly changes that rule in writing.
