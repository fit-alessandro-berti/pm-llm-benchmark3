| D4 | S (when it happens) before Approve | Whether S is always required (S3 vs S4 conflict) | Medium | S constrained to midblock, optional |

| S7 (Logging) | Only completion stamps; ties broken by ingest index | Start/finish overlap | Technical, high | Defines observational ceiling: all models live in completionsequence space |

**Why reciprocal DFG edges do not prove concurrency.** Both `CE` (17) and `EC` (11) exist. Three mechanisms generate this pattern: (i) true parallel execution with random completion order; (ii) a **casemix of two sequential templates** (some cases routed financefirst, others engineeringfirst — exactly the disagreement between S1 and S2); (iii) measurement artifacts under S7 (ties resolved by ingestion). A directlyfollows pair count cannot separate (i) from (ii): a 58/42 split of two sequential routings produces the *identical* DFG. Discriminating requires start/finish lifecycle timestamps (overlap of intervals), not completion order. Likewise, the small backedge `SE` (2) is fully explained by V5's "S slips between the checks"; a naive miner could misread it as rework/looping — it is a positional artifact, not evidence of repetition. Finally, the unequal counts (12 vs 7 vs…) mean the sample is not exchangeable across orders; we therefore treat frequencies as descriptive, not as a fitted distribution.

# 2. Shared Assumptions

1. **Completionevent semantics (S7, D7).** Every activity is one atomic completion event; log order = completion order. True overlap is unobservable. All three models reason over completion sequences only; nobody claims concurrency is *proven*, only that it is or is not *represented*.
2. **Head/tail invariants.** `Register Order` is the sole start; `Approve Configuration  Release Production  Archive Case` closes every case (D1, D2, EVTAIL) in all models.
3. **Singleoccurrence baseline.** Each of C, E occurs once, S at most once, X at most once — *except* the permissive model, which lifts multiplicities with explicit bounds (disclosed there).
4. **Optional S = XOR controlflow abstraction.** Absence of Supplier Confirmation is represented as an XOR skip branch. This deliberately **conflates** (a) legitimate skip for stocked components (S3/S4), and (b) event loss from the integration fault (S5). Control flow cannot distinguish them without the missing attribute; this is an disclosed abstraction, revisited in §9.
5. **No data/resource attributes.** The external/stocked flag, approver identities, case values are not modeled; conditioning approval or supplier behavior on them is future work pending data collection.
6. **Frequencies are descriptive.** Variant counts inform prior plausibility judgments in prose but are not baked in as stochastic weights (PM4Py ProcessTrees/POWL are qualitative here).
7. **No loops by default.** Observed behavior contains no repeats; the `SE` backedge is treated as positional (V5), not rework. Only the permissive model introduces bounded repetition, explicitly flagged as speculative.
8. **Duplicate labels.** Where orderings are enumerated (conservative) or mirrored (balanced/permissive), activity labels may appear on several transitions. This is semantically benign (same observable action), but costs state space, blurs diagnostic provenance, and scales poorly if enumeration grows combinatorially — discussed per model.

# 3. Conservative Candidate

**Inductive bias.** *Closedworld, memoryless:* the model's language is asserted to be exactly what was observed, nothing more. Every generalization — however plausible — is refused until evidenced; uncertainty is offloaded from the model onto the analyst, who must manually remine whenever reality drifts. This maximizes fidelity to the sample and refuses all causal claims (compatible with D7): the model is a descriptively perfect filter and a predictively brittle hypothesis.

**Compact formal expression.**

```
MODEL C := ( R , _{  }  , A , P , Arch )
 = { (C,E,S), (E,C,S), (C,E), (E,C), (C,S,E), (C,E,S,X), (E,C,X,S) }
L(C) = exactly the 7 observed variant strings.
```

**Code (PM4Py ProcessTree).**

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

        c.parent = t
        t.children.append(c)
    return t


CORE_ORDERS = [
    ("Credit Check", "Engineering Review", "Supplier Confirmation"),        # 12x
    ("Engineering Review", "Credit Check", "Supplier Confirmation"),        # 7x

     "Expedite Review", "Supplier Confirmation"),                           # 1x

    _inner,
    _leaf("Approve Configuration"),
    _leaf("Release Production"),
    _leaf("Archive Case"),
```

*Duplicate labels & scalability.* Labels `C`, `E` appear in all 7 arms, `S` in 5, `X` in 2  ~24 activity transitions for a 8activity alphabet. Consequences: (a) Petrinet and statespace grow linearly here but **quadratically/exponentially in general** when arms are enumerated combinatorially (k alternatives at n positions  k arms); (b) alignment diagnostics can no longer tell *which arm* matched a trace without extra bookkeeping; (c) perfectfitness/precision on the sample is achieved by memorization, which is why §8 demonstrates language equality directly. Factoring the shared tail (done here) already halves duplication versus naively XORing seven full traces.

**Deliberately excluded behavior.**
- Any *new ordering* of C, E, S, X (e.g., E, S, C; C, E, X, S; E, C, S, X).
- X **without** Supplier Confirmation (never observed togetherwithskip).
- Multiple executions of any activity; any activity after `Archive Case`; any skipped head/tail step.

**Known underfitting risks.**
1. **Missingevent brittleness (S5):** a real trace `C,E,S,X` logged as `C,E,X` (S lost) finds no arm  false rejection. Same for double corruption.
2. **Casemix drift:** one new legitimate ordering (even a probable mirror like E,S,C) = immediate conformance failure; maintenance is manual.
3. **Compliance blind spot:** the model cannot express *why* a noS trace is fine, so auditors cannot reuse it for rule checking beyond rote matching.
4. **Rareclass poverty:** with only 2 X observations, the model freezes an almost certainly incomplete picture of the expedite path.

# 4. Balanced Candidate

**Inductive bias.** *Structured generalization under explicit uncertainty:* encode only orderings that the joint evidence (rules + symmetries) supports; leave genuinely open questions (true parallelism vs routing, per D7) as a *disclosed abstraction* (completion order = XOR choice) instead of either banning behavior or asserting unverifiable causality. Optionality is separated positionally (gates) from existential uncertainty (skiparm semantics declared conflated, §2).

**Compact formal expression.**

```
MODEL B := ( R , B_C  B_E , A , P , Arch )
B_C = ( C ,  ) where  is a partial order over {E, S?, X?} with edges:
        E    X                       (X after both checks: D6/S6)
        S    E                       (S may precede or follow the other check: D5, EVV5)
        S    X                       (S before or after X: S6)
B_E  = mirror (roles of C and E swapped)
Language predicate on the midblock: exactly one C and one E; 0#S1 with
pos(S) > pos(first completed check); 0#X1 with pos(X) > pos(second completed check);
no constraint between S and X.
```

**Code (POWL).**

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator


def _optional(label: str) -> OperatorPOWL:
    """XOR(activity, tau): 0..1 occurrences."""
    return OperatorPOWL(
        operator=Operator.XOR,
        children=[Transition(label=label), SilentTransition()],
    )


def _family(first_lbl: str, second_lbl: str) -> StrictPartialOrder:
    """first check runs (dispatch choice), then a partial order containing
    the second check, optional S, optional X."""
    first = Transition(label=first_lbl)
    second = Transition(label=second_lbl)
    s_opt = _optional("Supplier Confirmation")
    x_opt = _optional("Expedite Review")

    po = StrictPartialOrder(children=[second, s_opt, x_opt])
    po.order.add_edge(second, x_opt)      # X only after the SECOND check (D6/S6)
    # 'second' vs 's_opt': intentionally UNORDERED -> S may precede or follow the
    # other check (D5, EV-V5).  's_opt' vs 'x_opt': UNORDERED (S6: before or after).

    stage = StrictPartialOrder(children=[first, po])
    stage.order.add_edge(first, po)       # sequence: first check -> stage2 block
    return stage


model_balanced = StrictPartialOrder(
    children=[
        Transition(label="Register Order"),
        OperatorPOWL(
            operator=Operator.XOR,
            children=[
                _family("Credit Check", "Engineering Review"),
                _family("Engineering Review", "Credit Check"),
            ],

        Transition(label="Approve Configuration"),
        Transition(label="Release Production"),
        Transition(label="Archive Case"),

_root_order = model_balanced.order
_root_order.add_edge(model_balanced.children[0], model_balanced.children[1])
_root_order.add_edge(model_balanced.children[1], model_balanced.children[2])
_root_order.add_edge(model_balanced.children[2], model_balanced.children[3])
_root_order.add_edge(model_balanced.children[3], model_balanced.children[4])
```

**How sequence / concurrency / partial order were decided for each activity.**

| Pair | Decision | Why |
|---|---|---|
| C  E | **Unordered (partialorder "concurrency" with completion order abstracted as XOR dispatch)** | Reciprocal DFG (17/11) + V2/V4/V7 refute fixed sequence; S2 supports parallel reading; D7 forbids asserting physical concurrency. Modeling completion order as a choice reproduces the exact observable constraints without claiming mechanism. |
| S vs C/E | **Sequenced after the first check; unordered w.r.t. the second** (strictly a partial order, neither pure sequence nor free concurrency) | V5 proves S can slip *between* the checks  not a plain sequence. S never observed (nor ruled, D5) before any check  not free concurrency. Mingate is the sharp middle. |
| X vs C/E | **Hard sequenced gate:** X after both checks | Never violated in log; D6 + S6 agree; 2 observations both conform. Kept strict (see permissive boundary). |
| S  X | **Unordered** | V6 (S then X) and V7 (X then S) realize both directions; S6 permits both. |

**Deliberately excluded behavior.** S before *any* check; X before the second check completes; S/X after Approve Configuration; repeats; skipped tail; missing C or E.

**Known underfitting risks.** (1) If a *dominant sequentialrouting* story (S1) were true, the model still fits the log but overstates parallelism in documentation; risk is interpretive, not behavioral. (2) Genuine repeat visits (reconfirmation, recheck) are impossible  residual false alarms. (3) The E,S,C mirror is predicted but unobserved: if systematic asymmetry exists (e.g., S practically always triggered by engineering), a minority family is dead weight — monitorable in §9.

# 5. Permissive Candidate

**Inductive bias.** *Explorationgrade openness:* keep every *compliance gate* that has converging evidence (head/tail, both checks, gates on S and X), but lift every assumption whose contrary has never been tested — chiefly single occurrences. Bounded multiplicity (`2`) is admitted for the checks and Supplier Confirmation, hypothesizing mundane operational phenomena (configchange reconfirmation, rerun checks) that the short log cannot refute and that integration faults (S5) could have masked. Everything still runs through the same gates as balanced, so the language strictly contains B's.

**Compact formal expression.**

```
MODEL P := same scaffold as MODEL B, with multiplicity lifting inside the family:
  first check c1  {C,E}#:    1 or 2 executions (duplicated label allowed)
  second check c2 (complement): 1 or 2 executions
  S  {0,1,2}, X  {0,1}
Gates unchanged: S only after the first check's first instance has completed;
X only after both check types have completed; all before A; head/tail fixed.
Forbidden (boundary): S before any check; X before both check types;
S/X after Approve; >2 executions of any check/S; any missing mandatory step;
repeats of R, A, P, Arch.
```

**Code (POWL).**

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator


def _optional(label):
    return OperatorPOWL(operator=Operator.XOR,
                        children=[Transition(label=label), SilentTransition()])


def _once_or_twice(label):
    """XOR(label, label->label): 1 or 2 occurrences. NOTE: duplicate labels —
    occurrences are indistinguishable in the log by design (exploration tier)."""
    once = Transition(label=label)
    rep1, rep2 = Transition(label=label), Transition(label=label)
    seq2 = StrictPartialOrder(children=[rep1, rep2])
    seq2.order.add_edge(rep1, rep2)
    return OperatorPOWL(operator=Operator.XOR, children=[once, seq2])


def _loose_family(first_lbl, second_lbl):
    first = _once_or_twice(first_lbl)
    second = _once_or_twice(second_lbl)
    s_opt = OperatorPOWL(  # 0, 1 or 2 confirmations
        operator=Operator.XOR,
        children=[SilentTransition(),
                  Transition(label="Supplier Confirmation"),
                  *(lambda r1, r2: (  # inline 2nd-occurrence branch
                      None,))(None, None)] if False else None
    )
    # Build the 0/1/2 supplier branch explicitly (clarity over cleverness):
    s_once = Transition(label="Supplier Confirmation")
    sr1, sr2 = Transition(label="Supplier Confirmation"), Transition(label="Supplier Confirmation")
    s_twice = StrictPartialOrder(children=[sr1, sr2])
    s_twice.order.add_edge(sr1, sr2)
    s_opt = OperatorPOWL(operator=Operator.XOR,
                         children=[SilentTransition(), s_once, s_twice])

    x_opt = _optional("Expedite Review")

    po = StrictPartialOrder(children=[second, s_opt, x_opt])
    po.order.add_edge(second, x_opt)   # X after the second check (D6/S6, retained!)
    stage = StrictPartialOrder(children=[first, po])
    stage.order.add_edge(first, po)
    return stage


model_permissive = StrictPartialOrder(
    children=[
        Transition(label="Register Order"),
        OperatorPOWL(operator=Operator.XOR,
                     children=[_loose_family("Credit Check", "Engineering Review"),
                               _loose_family("Engineering Review", "Credit Check")]),
        Transition(label="Approve Configuration"),
        Transition(label="Release Production"),
        Transition(label="Archive Case"),
    ]
)
_o = model_permissive.order
for a, b in zip(model_permissive.children, model_permissive.children[1:]):
    _o.add_edge(a, b)
```

**Boundary between "reasonable generalization" and forbidden.**

*Admitted (reasonablebutunobserved):* mirrored orderings (already in B) **plus** second executions of a check, second Supplier Confirmation, and all interleavings thereof within the existing gates — bounded at 2 to keep precision finite and the audit tractable.

*Still forbidden, and why:*
1. **S before any check** — contradicts even the weak D5; no stakeholder claims supplier contact precedes registration outputs.
2. **X before the second check** — D6 (medium) *and* S6 (compliance) converge; relaxing this would create a live compliance violation channel.
3. **S or X after Approve Configuration** — D4/D6 gate closure; approval is the commitment point.
4. **Missing R / C / E / A / P / Arch**, repeats of R/A/P/Arch, >2 repetitions anywhere — destroys traceability guarantees (D1, D2, EVTAIL).
5. **Unbounded loops** — POWL loops (`*`) are deliberately avoided; unbounded repetition would swallow precision and make conformance alarms meaningless.

**Known underfitting risks (yes, even this model can underfit).** (1) The bound `2` is arbitrary; a real triple reconfirmation would fail. (2) X is capped at 1 by D6 — if operations ever batchexpedites, the gate is wrong. (3) If missingness (S5) also strikes *other* events (e.g., lost Approve), no model tier here tolerates it.

```python
# 6) Manual positive/negative suite via EXACT bounded language enumeration
#    (BFS over markings up to a stated length bound; NOT an inclusion proof)
# ----------------------------------------------------------------------------
def enumerate_language(net, im, fm, max_len=14, cap=40000):
    """All accepted visible traces with length <= max_len (acyclic nets)."""
    def enabled(mark):
        out = []
        for t in net.transitions:
            ok = True
            for a in t.in_arcs:
                if mark.get(a.source, 0) < a.weight: ok = False; break
            if ok: out.append(t)
        return out
    def fire(mark, t):
        m = dict(mark)
        for a in t.in_arcs:
            m[a.source] -= a.weight
            if m[a.source] == 0: del m[a.source]
        for a in t.out_arcs:
            m[a.target] = m.get(a.target, 0) + a.weight
        return frozenset(m.items()), m

    start_mark = frozenset(im.items())
    results, frontier, seen_at = set(), [((), dict(start_mark.items()))], set()
    while frontier:
        seq, mark = frontier.pop()
        if len(seq) >= max_len or len(results) > cap: continue
        for t in enabled(mark):
            nf, nm = fire(mark, t)
            label = t.label
            ns = seq if label is None else seq + (label,)
            key = (nf, len(ns))
            if key in seen_at: continue
            seen_at.add(key)
            if nf == frozenset(fm.items()):
                results.add(ns)
                continue                              # acyclic: no extension past final
            frontier.append((ns, nm))
    return results
```

# 9. Recommendation and DataCollection Plan

**Recommendation.** Deploy **`model_balanced`** for immediate operational use (conformance monitoring, gatealigned alerts, stakeholder legible). Run **`model_permissive` only as a sandbox sensitivity model**: replay live traffic daily through both models and measure the deltaalarm stream (traces P accepts, B rejects). Those deltas are precisely the empirical price of the multiplicity hypotheses; if after a quarter the reconfirmation/recheck families materialize repeatedly, promote them into the balanced model as *evidenced* optional repeats; if not, retire the speculation. `model_conservative` remains useful as the zerodrift sentinel: any B/P verdict disagreement with C points at drift or data loss and should page the analyst.

**Ambiguity resolution plan (priority order).**

1. **Lifecycle timestamps (kills D7 uncertainty).** Export `start`/`complete` (ideally `schedule`, `suspend/resume`) for Credit Check and Engineering Review. Also instrument the recorder to flag sametimestamp ties (S7) and reemit with server receive time.
2. **External/stocked attribute + PO linkage (dissolves S3/S4/S5).** Join Supplier Confirmation events to purchaseorder records; carry the component sourcing class on the case. | X afterboth gate, 1 | ~80% | D6+S6 converge; n=2 limits tails |
| Baseline single occurrences (C, E, S) | ~70% | No repeats in 30 cases; short log weakens absence evidence |
| Permissive's multiplicity hypotheses reflect reality | ~35% | Explicitly speculative; sandboxonly until §9 items land |

**Material alternative interpretation #1 (mixtureoftemplates).** Suppose S1 is right about mechanism: two hidden sequential routes (financefirst vs engineeringfirst) selected by a case attribute, with no parallelism anywhere. The balanced model's *language* is unchanged (the XOR dispatch already reproduces both orders), but its *explanation layer* is wrong, and the correct target model becomes an attributeconditioned XOR of two templates — better precision messaging, cleaner audits, and different automation targets. The §9 lifecycletimestamp item resolves this cheaply; until then, all concurrency language in docs should say "unordered/undetermined," not "parallel."

**Material alternative interpretation #2 (lossdominated skip).** If S5's integration fault is worse than estimated (say, most noS cases are actually lost events rather than stocked skips), then Supplier Confirmation is effectively mandatory, the skiparm in B (and P) should shrink toward a rareexception, and compliance policy should treat Sabsence as an alarm rather than a variant — flipping the operational tuning of the recommended model's thresholds.

If either alternative is confirmed, the recommendation shifts from "balanced as-is" to "balanced with attributeconditional gates" (alt #1) or "balanced with tightened skip policy + upstream logging fixes" (alt #2). Permissive would remain sandboxonly in every scenario; conservative would remain the drift sentinel.
