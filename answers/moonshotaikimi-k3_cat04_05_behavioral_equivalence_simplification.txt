# 1. Equivalence Notions

Use the abbreviations:

- \(O=\) Open Case
- \(A=\) Analyze Revision
- \(C=\) Check Revision
- \(P=\) Approve Revision
- \(R=\) Rework Case
- \(Z=\) Close Case

A *complete trace* reaches the final marking of the accepting Petri net, rather than merely being an executable prefix. Since both models can execute their loops arbitrarily often, their unbounded languages contain arbitrarily long finite complete traces.

For a trace \(w\), let \(h_\tau(w)\) be the projection that removes silent `tau` transitions.

**Visible trace equivalence after hiding `tau`.**

\[
L_{\mathrm{vis}}(M)=
\{h_\tau(w)\mid w\text{ is a complete firing sequence of }M\}.
\]

Models are visibly trace equivalent iff:

\[
L_{\mathrm{vis}}(M_A)=L_{\mathrm{vis}}(M_B).
\]

This is set equality over ordered words. If two internal paths produce the same visible word, that word appears once in the language. Stochastic path multiplicity is considered separately in Section 6.

**Duplicate visible labels.**

For raw and bounded trace equivalence, duplicate labels are retained as ordered occurrences: `A,C,A` differs from `A,A,C`, and two occurrences of `Check Revision` differ from one occurrence. They do not have persistent event identities; “first” and “second” refer to positions in the trace.

For P1, occurrences receive a derived analysis-attempt index, described below. For P2, `Analyze Revision` occurrences are reduced to a count, while repeated checks and reworks are reduced to Booleans.

**Business-relevant equivalence under P1.**

Delimit analysis attempts by `Rework Case` and the end of the case:

- attempt 1 starts after `Open Case`;
- each `Rework Case` closes an attempt and starts another;
- the final attempt ends before `Close Case`.

For P1:

1. Every attempt containing an `Analyze Revision` must have a distinct `Check Revision` in the same attempt before the next `Rework Case` or `Close Case`.
2. `Rework Case` occurrence positions remain relevant because they delimit attempts.
3. Each optional `Approve Revision`, including its position relative to the check and attempt boundary, remains visible.
4. P1 does not explicitly state whether the check must precede or follow the analysis. I therefore quotient only adjacent `Check Revision, Analyze Revision` versus `Analyze Revision, Check Revision` orderings inside the same attempt. All other ordering remains relevant.

Let \(\kappa_{P1}\) canonicalize the local pair `C,A` to `A,C` inside an attempt and retain all other visible events and attempt indices. Then:

\[
L_{P1}(M)=\{\kappa_{P1}(h_\tau(w))\mid w\in L(M)\}.
\]

P1 equivalence requires both models to generate only P1-compliant traces and to have equal canonical P1 languages.

If the business additionally requires `Check Revision` to occur strictly after `Analyze Revision`, Model A itself permits nonconforming `C,A` executions; the simplified model in Section 8 eliminates that ambiguity.

**Abstracted dashboard equivalence under P2.**

Define:

\[
\pi_{P2}(w)=
\bigl(
\operatorname{first}(w)=O,\;
\operatorname{last}(w)=Z,\;
\#A(w),\;
\#C(w)>0,\;
\#R(w)>0
\bigr).
\]

Thus P2 records:

- whether Open is first;
- whether Close is last;
- the exact number of analyses;
- whether at least one check occurred;
- whether at least one rework occurred.

It erases:

- `Approve Revision`;
- `tau`;
- the multiplicity of `Check Revision`;
- the number of reworks beyond the Boolean;
- the exact interleaving of analyses and checks.

P2 equivalence means equality of the sets of these dashboard observations.

**Bounded visible-language equivalence under P3.**

For visible length bound \(L=12\) and analysis bound \(N=3\), define:

\[
L_{P3}(M)=
\{w\in L_{\mathrm{vis}}(M)
\mid |w|\leq 12\text{ and }\#A(w)\leq 3\}.
\]

Both bounds apply conjunctively. P3 equivalence means:

\[
L_{P3}(M_A)=L_{P3}(M_B).
\]

This is an exact statement about the bounded languages. If the bounded languages were equal, that would still not prove equality of the unbounded languages.

# 2. Structural Comparison

For Model A, let a revision block be:

\[
B_A=(AC\mid CA)(\varepsilon\mid P).
\]

Its complete visible language is:

\[
L_A=
\{O\,B_1(RB_2)\cdots(RB_n)Z
\mid n\geq1,\;B_i\in B_A\}.
\]

Thus every loop iteration contains exactly one analysis and one check.

For Model B, the sequential revision-loop core containing exactly \(n\) analyses is:

\[
K_n=A(\varepsilon\mid P)
\bigl(RA(\varepsilon\mid P)\bigr)^{n-1}.
\]

The complete language is:

\[
L_B=
\{O\,u\,Z\mid n\geq1,\;u\in K_n\mathrel{\shuffle} C\},
\]

where \(\shuffle\) is the interleaving or shuffle operation. Consequently, the single `Check Revision` can be inserted at any point of the loop-core word.

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The loop repeats the parallel pair `Analyze Revision + Check Revision`, followed by optional approval. | The loop repeats only `Analyze Revision`, optional approval, and `Rework Case`; `Check Revision` is outside the loop. | A creates one check per revision attempt. B creates one check for the entire loop. |
| Analysis occurrences | Minimum 1; no finite maximum. | Minimum 1; no finite maximum. | This property alone does not distinguish the models. |
| Check occurrences | Minimum 1; no finite maximum. For \(n\) analyses, exactly \(n\) checks. | Minimum 1 and maximum 1. | For two or more analyses, A has multiple checks while B still has only one. |
| Possible placement of Check Revision | Within each iteration, either before or after `Analyze Revision`, but always before that iteration’s optional approval, next rework, or Close. | Anywhere after Open and before Close: before the first analysis, after an approval, between reworks, or after the final loop iteration. | B permits checks that are temporally detached from later analyses. |
| Optional approval occurrences | For \(n\) analyses, 0 through \(n\) approvals. Each approval occurs only after both the analysis and check of that iteration complete. | For \(n\) analyses, 0 through \(n\) approvals. Each approval follows its analysis, but the global check may occur later. | B admits `O,A,P,C,Z`; A does not. |
| Concurrency | Local concurrency only: `Analyze Revision` and `Check Revision` are concurrent within one revision block. | One `Check Revision` is concurrent with the entire potentially unbounded revision loop. | B permits a check to cross approvals, reworks, and subsequent attempts. |
| Rework relation | For \(n\) analysis attempts, exactly \(n-1` reworks. A rework can occur only after the preceding analysis, check, and approval choice complete. | For \(n\) analysis attempts, exactly \(n-1\) reworks. A rework can occur before the global check has occurred. | A enforces a check before each attempt boundary; B does not. |
| Join before Close Case | The parallel `A/C` branch joins before the optional approval, and the completed loop reaches Close. | The outer parallel join requires both the completed loop and the one check branch before Close. | B must eventually execute its check, but not once per revision. |
| Minimum complete visible traces | `O,A,C,Z` and `O,C,A,Z`. | `O,A,C,Z` and `O,C,A,Z`. | Their minimum traces coincide. |
| Maximum length | Unbounded because of the loop. | Unbounded because of the loop. | Finite testing requires an explicit bound such as P3. |
| Open and Close | Each occurs exactly once, first and last respectively. | Each occurs exactly once, first and last respectively. | Both satisfy the P2 boundary condition. |
| Raw language inclusion | Not a subset of B because A generates multiple checks. | Not a subset of A because B can approve before checking and has only one check across attempts. | There is no inclusion in either direction. |

For exactly one analysis, every raw trace of A is also a trace of B: B can place its single check before or between `A` and `P`. However, B additionally admits `O,A,P,C,Z`. For two or more analyses, A and B are disjoint because their check cardinalities differ.

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| Raw visible trace equivalence | not equivalent | High | A admits two checks for two analyses; B admits approval before its only check. | This uses interleaving trace semantics, not bisimulation. Bisimulation would also not rescue equality. |
| P1 — operational compliance | not equivalent | High | For two analyses, A has two attempt-local checks, whereas B has only one global check. B also permits `A,P,C`. | If “check” must strictly follow its analysis, A itself needs strengthening because A permits `C,A`. |
| P2 — executive dashboard | equivalent only under stated abstraction | High | Both generate exactly the dashboard observations \((n,\mathit{checked}=\mathrm{true},\mathit{reworked}=n>1)\) for every \(n\geq1\). | Equality disappears if the dashboard records check multiplicity, approval placement, or late-check position. |
| P3 — bounded visible language | not equivalent | High | Both bounded differences already occur within the limits; see `A-only-1` and `B-only-1`. | Bounded equality would only be evidence, not proof. Here bounded inequality is decisive. |

Formally, the P2 image of both models is:

\[
\{(true,true,n,true,n>1)\mid n\in\mathbb{N},\;n\geq1\}.
\]

# 4. Counterexample Traces

All traces below are complete visible traces in the models marked “Yes”; `tau` has already been hidden. Every trace has at most 12 visible events and at most three analyses, so all are also P3 witnesses.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| A-only-1 | \(O,A,C,R,A,C,Z\) | Yes | No | The sixth event is a second `Check Revision`; B’s check branch can execute only once. | Raw, P1, P3 |
| A-only-2 | \(O,C,A,P,R,C,A,Z\) | Yes | No | The first check is consumed in the first attempt, so B cannot execute the check after `Rework Case`. | Raw, P1, P3 |
| A-only-3 | \(O,A,C,R,A,C,R,A,C,Z\) | Yes | No | A produces three checks for three analyses; B can produce only one. | Raw, P1, P3 |
| B-only-1 | \(O,A,P,C,Z\) | No | Yes | `Approve Revision` occurs before `Check Revision`; in A, the parallel analysis/check join must complete before approval. | Raw, P1, P3 |
| B-only-2 | \(O,A,R,A,C,Z\) | No | Yes | The first `Rework Case` occurs before any check, whereas A requires the first analysis/check block to complete before rework. | Raw, P1, P3 |
| B-only-3 | \(O,C,A,P,R,A,Z\) | No | Yes | The single check was consumed before the first analysis; the post-rework analysis has no check. | Raw, P1, P3 |

No language inclusion holds:

- \(L_A\not\subseteq L_B\), witnessed by `A-only-1`.
- \(L_B\not\subseteq L_A\), witnessed by `B-only-1`.

The `X(Approve Revision, tau)` operator creates an optional visible approval:

- choosing `Approve Revision` emits \(P\);
- choosing `tau` emits no visible event but still resolves the choice and allows the loop to continue or exit.

Thus each model permits between zero and \(n\) approvals for \(n\) analyses. Hiding `tau` does not erase the consequential differences:

1. A has one check per loop iteration, while B has one check overall.
2. In A, an approval can occur only after the paired analysis and check.
3. In B, an approval can occur while the global check remains pending.

P2 hides approvals and collapses check multiplicity, which is why these counterexamples disappear under that abstraction.

# 5. Bounded Comparison Code

The following is self-contained and performs exhaustive bounded exploration over Petri-net markings. It does not use random playout.

```python
from collections import deque
from dataclasses import dataclass

import pm4py
from pm4py.objects.petri_net.obj import Marking


MODEL_A_TEXT = """
->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
""".strip()

MODEL_B_TEXT = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->(
        'Analyze Revision',
        X('Approve Revision', tau)
      ),
      'Rework Case'
    )
  ),
  'Close Case'
)
""".strip()


OPEN = "Open Case"
ANALYZE = "Analyze Revision"
CHECK = "Check Revision"
APPROVE = "Approve Revision"
REWORK = "Rework Case"
CLOSE = "Close Case"

MAX_VISIBLE_EVENTS = 12
MAX_ANALYZE_EVENTS = 3


tree_a = pm4py.parse_process_tree(MODEL_A_TEXT)
tree_b = pm4py.parse_process_tree(MODEL_B_TEXT)


@dataclass
class BoundedResult:
    language: set
    explored_states: int
    seen_states: int
    fired_transitions: int
    places: int
    transitions: int


def checked_conversion(tree, model_name):
    """
    Convert to an accepting Petri net and verify soundness.
    The accepting net consists of (net, initial marking, final marking).
    """
    net, im, fm = pm4py.convert_to_petri_net(tree)

    soundness = pm4py.check_soundness(
        net, im, fm,
        print_diagnostics=True
    )

    print(f"{model_name} soundness result: {soundness}")

    if not soundness:
        raise RuntimeError(f"{model_name} is not sound")

    return net, im, fm


def clone_marking(marking):
    return Marking(
        {place: int(tokens)
         for place, tokens in marking.items()
         if tokens > 0}
    )


def marking_key(marking):
    """
    A hashable representation of the exact marking.

    Place object identities are used because generated place names are
    implementation-dependent. Zero-token places are omitted.
    """
    return tuple(
        sorted(
            (id(place), int(tokens))
            for place, tokens in marking.items()
            if tokens > 0
        )
    )


def is_silent(transition):
    # Standard PM4Py conversion represents tau as label=None.
    # The string check is defensive for custom nets that retain "tau".
    return (
        transition.label is None
        or str(transition.label).lower() == "tau"
    )


def fire_transition(transition, marking):
    """
    Fire an enabled transition, respecting arc weights.
    """
    result = clone_marking(marking)

    for arc in transition.in_arcs:
        place = arc.source
        weight = arc.weight

        if result.get(place, 0) < weight:
            raise RuntimeError(
                f"Transition {transition.name} was reported enabled "
                f"but input place {place.name} is insufficiently marked"
            )

        result[place] -= weight
        if result[place] == 0:
            del result[place]

    for arc in transition.out_arcs:
        place = arc.target
        result[place] = result.get(place, 0) + arc.weight

    return result


def bounded_complete_language(
        tree,
        model_name,
        max_visible=MAX_VISIBLE_EVENTS,
        max_analyze=MAX_ANALYZE_EVENTS):
    """
    Exhaustively enumerate complete visible traces satisfying both bounds.

    BFS state = (exact Petri-net marking, visible trace prefix).

    Keeping the visible prefix in the state is necessary because two paths
    to the same marking may have produced different visible words.  If both
    the marking and visible prefix are identical, hidden-history differences
    cannot affect future Petri-net behavior, so the duplicate state is safe
    to discard.
    """
    net, im, fm = checked_conversion(tree, model_name)

    initial = clone_marking(im)
    initial_key = marking_key(initial)
    final_key = marking_key(fm)

    queue = deque([(initial, tuple())])
    seen = {(initial_key, tuple())}

    complete_traces = set()
    explored_states = 0
    fired_transitions = 0

    if initial_key == final_key:
        complete_traces.add(tuple())

    while queue:
        marking, visible_trace = queue.popleft()
        explored_states += 1

        enabled = sorted(
            pm4py.get_enabled_transitions(net, marking),
            key=lambda t: (str(t.name), str(t.label))
        )

        for transition in enabled:
            fired_transitions += 1
            next_marking = fire_transition(transition, marking)

            if is_silent(transition):
                next_trace = visible_trace
            else:
                next_trace = visible_trace + (transition.label,)

            # Both P3 bounds are monotone: once exceeded, no continuation
            # can return to the bounded region.
            if len(next_trace) > max_visible:
                continue
            if next_trace.count(ANALYZE) > max_analyze:
                continue

            next_key = marking_key(next_marking)
            state = (next_key, next_trace)
            reaches_final = next_key == final_key

            if reaches_final:
                complete_traces.add(next_trace)

            if state in seen:
                continue

            seen.add(state)

            # In a sound workflow net, the final marking has no required
            # continuation.  We therefore only record complete traces there
            # and do not extend them.
            if not reaches_final:
                queue.append((next_marking, next_trace))

    return BoundedResult(
        language=complete_traces,
        explored_states=explored_states,
        seen_states=len(seen),
        fired_transitions=fired_transitions,
        places=len(net.places),
        transitions=len(net.transitions)
    )


result_a = bounded_complete_language(tree_a, "Model A")
result_b = bounded_complete_language(tree_b, "Model B")

language_a = result_a.language
language_b = result_b.language

only_a = language_a - language_b
only_b = language_b - language_a


def print_words(title, words):
    print(f"\n{title}: {len(words)} trace(s)")
    for word in sorted(words, key=lambda w: (len(w), w)):
        print("  " + " -> ".join(word))


print("\n=== Exhaustive bounded exploration summary ===")
print("Bounds: at most 12 visible events and at most 3 analyses")
print(f"Model A: {len(language_a)} bounded complete visible traces")
print(f"Model B: {len(language_b)} bounded complete visible traces")

print(f"Model A explored states: {result_a.explored_states}")
print(f"Model B explored states: {result_b.explored_states}")
print(f"Model A seen marking/trace states: {result_a.seen_states}")
print(f"Model B seen marking/trace states: {result_b.seen_states}")

print_words("Traces unique to Model A", only_a)
print_words("Traces unique to Model B", only_b)

witness_a = (
    OPEN, ANALYZE, CHECK, REWORK, ANALYZE, CHECK, CLOSE
)
witness_b = (
    OPEN, ANALYZE, APPROVE, CHECK, CLOSE
)

assert witness_a in language_a
assert witness_a not in language_b
assert witness_b in language_b
assert witness_b not in language_a

for word in language_a | language_b:
    assert word[0] == OPEN
    assert word[-1] == CLOSE
    assert len(word) <= MAX_VISIBLE_EVENTS
    assert word.count(ANALYZE) <= MAX_ANALYZE_EVENTS

print("\nBoth bounded-language inclusions fail.")
print("Method: EXHAUSTIVE bounded BFS; no random/heuristic playout was used.")
```

This exploration is exhaustive for the stated bound because:

1. Every reachable pair of marking and visible prefix is explored.
2. Silent transitions are fired normally but do not increase the visible length.
3. Visible length and analysis count are monotone, so prefixes exceeding either bound cannot later become bounded again.
4. A trace is accepted only when the entire marking is exactly equal to the final marking, not merely when the final place is marked.
5. Revisiting an identical `(marking, visible-prefix)` state cannot produce a new continuation because Petri-net future behavior is determined by the marking.

By contrast, `pm4py.play_out(...)` would generate sampled executions. Failure of playout to produce a counterexample would not prove its absence.

# 6. Stochastic and Footprint Comparison

**Footprints.**

Footprints aggregate activity-level relations such as directly-follows, eventual-follows, choice, parallelism, start, and end. They can provide evidence of structural difference. In particular, B can place `Approve Revision` immediately before `Check Revision`, whereas A cannot, so a footprint implementation may expose that relation.

```python
# Continuing the session from Section 5.

footprints_a = pm4py.discover_footprints(tree_a)
footprints_b = pm4py.discover_footprints(tree_b)

print("Model A footprints:")
for key, value in footprints_a.items():
    print(f"  {key}: {value}")

print("Model B footprints:")
for key, value in footprints_b.items():
    print(f"  {key}: {value}")

all_footprint_keys = set(footprints_a) | set(footprints_b)

print("\nFootprint differences:")
for key in sorted(all_footprint_keys, key=str):
    value_a = footprints_a.get(key)
    value_b = footprints_b.get(key)
    if value_a != value_b:
        print(f"  {key}:")
        print(f"    A: {value_a}")
        print(f"    B: {value_b}")
```

Footprints are not sufficient for trace equivalence because they are pairwise and existential. They discard or aggregate:

- occurrence cardinality, such as one versus three checks;
- correlations among three or more events;
- loop scope;
- the reason a relation occurs;
- probability and path multiplicity;
- higher-order constraints such as “every attempt must contain a check.”

Both models already have the same activity set and many of the same local `A/C` relations, despite having different languages. Conversely, if footprints are discovered by sampling rather than exact derivation, rare relations may also be missed.

**Stochastic languages.**

A stochastic language assigns probabilities to trace variants. It is meaningful only after declaring where probabilities come from. For these models, one would need, for example:

- an approval probability versus an auto-approval probability for each `X(P,tau)`;
- a loop-exit versus loop-repeat probability;
- an interleaving or duration policy for parallel branches;
- a normalization policy if language generation is truncated at a bound.

The following creates a deliberately declared, artificial distribution: one empirical case for each distinct bounded trace variant, hence a uniform distribution over bounded variants—not a uniform distribution over branches.

```python
from pm4py.objects.log.obj import EventLog, Trace, Event


def event_log_from_language(words):
    log = EventLog()

    for case_number, word in enumerate(sorted(words)):
        trace = Trace(
            attributes={"concept:name": f"bounded-variant-{case_number}"}
        )
        for activity in word:
            trace.append(Event({"concept:name": activity}))
        log.append(trace)

    return log


# One case per bounded trace variant.  This is a declared uniform
# variant distribution, not an inferred operational probability model.
bounded_log_a = event_log_from_language(language_a)
bounded_log_b = event_log_from_language(language_b)

stochastic_language_a = pm4py.get_stochastic_language(bounded_log_a)
stochastic_language_b = pm4py.get_stochastic_language(bounded_log_b)

print("Stochastic language A:")
for trace, probability in stochastic_language_a.items():
    print(f"  {probability:.6f}: {trace}")

print("Stochastic language B:")
for trace, probability in stochastic_language_b.items():
    print(f"  {probability:.6f}: {trace}")

emd = pm4py.compute_emd(
    stochastic_language_a,
    stochastic_language_b
)

print(f"EMD under the declared uniform bounded distribution: {emd}")
```

For a PM4Py version supporting weighted stochastic Petri nets, `pm4py.get_stochastic_language(...)` could instead consume a properly weighted net. Calling it on an unweighted net without documenting the library’s default weights would not constitute a business probability model.

A low EMD means that two selected distributions can be transported to one another cheaply under the configured trace-distance metric. It does not establish trace equivalence because:

- support and probabilities may be truncated;
- duplicate internal paths may be collapsed;
- the metric may regard different traces as close;
- equal supports can have unequal probabilities;
- different supports can still have low distance;
- a result under one branch-probability assignment need not hold under another.

If EMD is exactly zero under an identity-of-indiscernibles trace metric, that supports equality of those two declared stochastic languages, but still not unbounded raw trace equivalence unless the full, correctly weighted languages were compared.

Counting the displayed abstract-syntax tree, including each operator node and each leaf:

| Metric | Model A | Model B | Comparison |
|---|---:|---:|---|
| Total process-tree nodes | 12 | 12 | Equal |
| Operator nodes | 5 | 5 | Equal: two sequences, one loop, one parallel, one XOR |
| Total leaves | 7 | 7 | Equal |

| Silent leaves | 1 | 1 | Both contain one `tau` leaf |
| Maximum depth, root depth 0 | 4 | 5 | B is one level deeper |

| Runtime duplicate checks | Unbounded | At most 1 | Important semantic difference not visible in static duplicate count |

The depth difference is:

- A: outer sequence  loop  inner sequence  parallel/XOR  leaf.
- B: outer sequence  parallel  loop  inner sequence  XOR  approval or `tau`.

The following code computes the parser-specific counts and converted-net simplicity metrics:

```python
from collections import Counter


def process_tree_stats(root):
    nodes = []

    def visit(node, depth):
        nodes.append((node, depth))
        for child in node.children:
            visit(child, depth + 1)

    visit(root, 0)

    operator_nodes = 0
    total_leaves = 0
    visible_labels = []
    silent_leaves = 0
    operator_counts = Counter()

    for node, _ in nodes:
        children = list(node.children)

        if children:
            operator_nodes += 1
            operator_counts[str(node.operator)] += 1
        else:
            total_leaves += 1
            label = getattr(node, "label", None)

            if label is None or str(label).lower() == "tau":
                silent_leaves += 1
            else:
                visible_labels.append(label)

    label_counts = Counter(visible_labels)

    return {
        "nodes": len(nodes),
        "operator_nodes": operator_nodes,
        "leaves": total_leaves,
        "visible_leaves": len(visible_labels),
        "silent_leaves": silent_leaves,
        "max_depth_edges": max(depth for _, depth in nodes),
        "duplicate_label_names": sum(
            1 for count in label_counts.values() if count > 1
        ),
        "extra_duplicate_label_occurrences": sum(
            count - 1 for count in label_counts.values()
            if count > 1
        ),
        "operator_counts": dict(operator_counts),
    }


stats_a = process_tree_stats(tree_a)
stats_b = process_tree_stats(tree_b)

print("Model A process-tree statistics:", stats_a)
print("Model B process-tree statistics:", stats_b)


def petri_net_stats(tree, name):
    net, im, fm = pm4py.convert_to_petri_net(tree)

    visible_transitions = sum(
        1 for transition in net.transitions
        if transition.label is not None
        and str(transition.label).lower() != "tau"
    )
    silent_transitions = sum(
        1 for transition in net.transitions
        if transition.label is None
        or str(transition.label).lower() == "tau"
    )

    simplicity = pm4py.simplicity_petri_net(net, im, fm)

    print(f"{name} Petri-net statistics:")
    print(f"  places: {len(net.places)}")
    print(f"  transitions: {len(net.transitions)}")
    print(f"  visible transitions: {visible_transitions}")
    print(f"  silent transitions: {silent_transitions}")
    print(f"  arcs: {len(net.arcs)}")
    print(f"  PM4Py simplicity: {simplicity}")


petri_net_stats(tree_a, "Model A")
petri_net_stats(tree_b, "Model B")
```

No exact `simplicity_petri_net(...)` value is asserted here because conversion details and the returned metric can depend on the installed PM4Py version. The important complexity conclusion is that equal tree size and equal static activity leaves do not imply equal behavior: the placement of the parallel and loop operators changes the semantics.

# 8. Simplified Model

I select a **P1-core compromise** as the target:

1. Preserve one analysis and one dedicated check per attempt.
2. Preserve `Rework Case` as the separator between attempts.
3. Preserve optional approval for every attempt.
4. Preserve approval count and its placement after the paired analysis/check.
5. Abstract away the local concurrency between `Analyze Revision` and `Check Revision`, using `Analyze -> Check`.
6. Preserve P2 as a consequence.

This removes the parallel operator from Model A. If the business requires a check to follow its analysis, the resulting sequence is not merely an abstraction but a useful strengthening.

The simplified process tree is:

```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

Its canonical P1 language is:

\[
O\,\bigl(AC(\varepsilon\mid P)\bigr)
\bigl(R\,AC(\varepsilon\mid P)\bigr)^*Z.
\]

After canonicalizing `C,A` to `A,C` inside an attempt, this is exactly Model A’s P1 language. It is not equal to Model B’s P1 language because B has only one check overall.

```python
import pm4py

def p1_canonical(word):
    """
    P1 does not prescribe whether A or C occurs first inside an attempt.
    Canonicalize adjacent C,A to A,C.  All other order, including approval
    placement and rework boundaries, remains unchanged.
    """
    result = list(word)

    for index in range(len(result) - 1):
        if result[index] == CHECK and result[index + 1] == ANALYZE:
            result[index], result[index + 1] = (
                result[index + 1],
                result[index]
            )

    return tuple(result)


def p2_projection(word):
    return (
        bool(word) and word[0] == OPEN,
        bool(word) and word[-1] == CLOSE,
        word.count(ANALYZE),
        CHECK in word,
        REWORK in word
    )
```

| ID | Trace | Expected result | Violation tested |
|---|---|---|---|
| S-neg-1 | \(O,A,R,A,C,Z\) | Rejected | First analysis reaches rework without a check |
| S-neg-2 | \(O,A,C,P,R,A,Z\) | Rejected | Second analysis reaches Close without a check |
| S-neg-3 | \(O,A,P,C,Z\) | Rejected | Approval precedes the paired check |

A still smaller dashboard-only model, such as `->(O,C,*(A,R),Z)`, could preserve P2 but would discard approval and per-attempt checking. It is therefore unsuitable for the selected P1-core target.

# 9. Final Recommendation

**P1 — operational compliance**

- Model A is the closer original model because it creates a check inside every revision iteration.
- Model B is unsuitable because one check can cover—or simply precede—an arbitrary number of later analyses.
- Model A has an important ambiguity: it permits `Check Revision` before `Analyze Revision`. If a check must follow the analysis, A should be replaced by the simplified sequence model.
- Under the stated P1 abstraction, the simplified model preserves A’s compliance semantics and may replace A for operational P1 purposes.

**P2 — executive dashboard**

- Models A and B are equivalent under the explicitly defined dashboard projection.
- Either can drive the dashboard.
- The simplified model also preserves P2 and may replace either original for dashboard-only use.
- It should not be treated as an operational compliance model merely because its dashboard projection matches.

**P3 — bounded testing**

- Models A and B are not bounded-trace equivalent.
- Test suites should retain the counterexamples in Section 4, especially:
  - two analyses with two checks for A;
  - approval before check for B;
  - a check delayed until after a rework for B.
- The simplified model is not a P3 substitute for A because it loses the raw `C,A` interleaving.

**Overall recommendation**

Use the simplified model when P1’s compliance facts—not the local check/analysis execution order—are the authoritative semantics. Keep or derive richer operational details from Model A only if concurrent check/analysis order is genuinely relevant. Do not adopt Model B unless the business intentionally changes its policy from “one check per revision” to “one check per case.”

Finally, bounded comparison is not a general proof technique. Here it is decisive because explicit counterexamples already fit inside the P3 bounds. If the bounded languages had agreed, that agreement would have remained evidence only; unbounded equivalence would still require a formal language, bisimulation, or model-checking argument.
