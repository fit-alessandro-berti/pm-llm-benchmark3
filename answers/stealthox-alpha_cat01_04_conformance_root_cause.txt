## 3. Causal-abductive explanation

```text
UI_release            -> recorded_labels        # Classify renamed Risk Screen (audit-confirmed)
UI_release            -> gateway_telemetry      # same release window; Queue Routed on ~86% of traces
UI_release            -> reviewer_behavior      # new routing friction provokes Manual Override workarounds
gateway_telemetry     -> alignment_moves        # inserted technical log moves
gateway_telemetry     -> reviewer_behavior      # routing mistakes trigger corrections
ETL_change            -> recorded_order         # ingestion time replaces source time for Decision/Notify
recorded_labels       -> alignment_moves        # Risk Screen scored as log move vs Classify
recorded_order        -> alignment_moves        # Notify-before-Decision inversions (70, then 45)
policy_change         -> true_process           # Supervisor Sign-off mandatory for >EUR 50k
policy_change         -> model_currency         # normative tree NOT updated -> obsolescence (hidden)
model_currency        -> alignment_moves        # legitimate sign-off scored as log move
normative_model       -> alignment_moves        # reference: Classify model moves; no sign-off transition
reviewer_behavior     -> true_process           # overrides are real, rare adaptive behavior
extraction_completeness -> alignment_moves      # possibly missing Compliance Check events (hidden)
true_bypass_rate      -> true_process           # hidden: genuinely skipped checks
true_bypass_rate      -> extraction_completeness  # confound: not yet separable
high_value_mix        -> true_process           # hidden: which cases require sign-off
true_process          -> business_outcomes      # approval / appeal / cycle time
detection_coverage    -> business_outcomes      # hidden: confirmed-incident counts are censored
alignment_moves       -> measured_fitness
```

The collapse decomposes almost perfectly along three independent, dated measurement mechanisms. The 2026-05-31 UI release renamed `Classify` to `Risk Screen`, moving every post-release case's second activity off-model (audit-confirmed). The 2026-06-03 gateway change injected `Queue Routed` into roughly 86% of traces. The 2026-06-15 ETL switch to warehouse-ingestion time inverted `Decision`/`Notify`, producing exactly the 70 (later 45) reversed traces seen in both variants and DFG. Each mechanism maps to a distinct alignment-cost component, and the staged lifts — 3258 (label map), 5881 (technical-event removal), 8189 (source ordering) — recover the 93% April baseline almost exactly. That monotone, mechanism-tied recovery is the strongest abductive signal in the file: the June collapse is predominantly a measurement artifact, not a behavioral rupture. The August residual is categorically different: a real, mandated step (`Supervisor Sign-off`) exists in the process but not in the normative tree, so conformance now measures model currency. Here "the process changed" and "the model became obsolete" are one fact viewed from two sides, and the policy change — not reviewers — drives the deviation. Unchanged approval, appeal, and cycle-time figures are consistent with this account but are weak instruments: a skipped compliance check on a minority of enhanced reviews need not move 30-day appeals, and incident detection is admittedly incomplete, so stable outcomes neither prove the data are wrong nor exonerate the workforce. Meanwhile extraction quality degraded in the same window (missing-resource events rose from 1.2% to 6.4%), so the 55 enhanced reviews without a recorded check are precisely where a logging defect and a true bypass are observationally equivalent. `Manual Override` is plausibly a small, real adaptation to routing friction, simultaneously inflated by the 2026-08-12 logging patch.

## 6. PM4Py reproduction and model-comparison code

```python
# =====================================================================
# Conformance-collapse reproduction (investigation "ox-alpha")
# ---------------------------------------------------------------------
# The supplied data are VARIANT-FREQUENCY AGGREGATES, not the original
# timestamped log, so absolute fitness/precision values will differ from
# the report. The staged pattern (collapse -> partial recovery) is what
# this pipeline demonstrates. Fully self-contained and executable.
# =====================================================================

import pm4py
import pandas as pd
from datetime import datetime, timedelta
from collections import Counter

SKIP = {None, ">>"}   # alignment skip symbol differs across pm4py versions

# ---------------------------------------------------------------------
# 1) Normative process tree -> accepting Petri net
# ---------------------------------------------------------------------
NORMATIVE = ("-> ( 'Receive', 'Classify', "
             "X ( * ( 'Standard Review', 'Request Info' ), "
             "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
             "'Decision', 'Notify' )")

# Candidate: same tree, but an OPTIONAL Supervisor Sign-off before Decision.
CANDIDATE = ("-> ( 'Receive', 'Classify', "
             "X ( * ( 'Standard Review', 'Request Info' ), "
             "-> ( 'Enhanced Review', 'Compliance Check' ) ), "
             "X ( tau, 'Supervisor Sign-off' ), "
             "'Decision', 'Notify' )")

norm_tree = pm4py.parse_process_tree(NORMATIVE)
net, im, fm = pm4py.convert_to_petri_net(norm_tree)

cand_tree = pm4py.parse_process_tree(CANDIDATE)
cnet, cim, cfm = pm4py.convert_to_petri_net(cand_tree)

# ---------------------------------------------------------------------
# 2) Variant-frequency tables from the investigation report
# ---------------------------------------------------------------------
APR_MAY = {
    "Receive,Classify,Standard Review,Decision,Notify": 380,
    "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,
    "Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify": 40,
}
JUN_JUL = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 270,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 145,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,   # reversed order
    "Receive,Risk Screen,Standard Review,Decision,Notify": 90,                # no Queue Routed
    "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,      # old label persists
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,   # missing check
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 20,
}
AUG_SEP = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 210,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify": 150,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 90,
    "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify": 60,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 45,   # reversed order
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 30,   # missing check
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 35,
}

# ---------------------------------------------------------------------
# 3) Expansion of variant tables into an event log
#    (parse_event_log_string expects lines: case,activity,timestamp)
# ---------------------------------------------------------------------
def variants_to_log(variants, start):
    lines, cid = [], 0
    for trace, count in variants.items():
        acts = trace.split(",")
        for _ in range(count):
            cid += 1
            ts = start
            for act in acts:
                lines.append(f"{cid},{act},{ts.strftime('%Y-%m-%d %H:%M:%S')}")
                ts += timedelta(hours=1)   # synthetic; recorded order preserved
    return pm4py.parse_event_log_string(
        "\n".join(lines), sep=",",
        activity_key="concept:name", timestamp_key="time:timestamp",
        case_id_key="case:concept:name")

def to_df(log):
    return log if isinstance(log, pd.DataFrame) else pm4py.convert_to_dataframe(log)

def add_source_seq(df):
    """Recorded order follows warehouse ingestion time (2026-06-15 defect).
    'source:seq' repairs the Decision/Notify inversion, simulating the
    source-system sequence number that the initial conformance job ignored."""
    df = df.sort_values(["case:concept:name", "time:timestamp"], kind="mergesort").copy()
    df["source:seq"] = df.groupby("case:concept:name").cumcount()
    for _, idx in df.groupby("case:concept:name").groups.items():
        n = [i for i in idx if df.at[i, "concept:name"] == "Notify"]
        d = [i for i in idx if df.at[i, "concept:name"] == "Decision"]
        if len(n) == 1 and len(d) == 1 and n[0] < d[0]:
            df.at[n[0], "source:seq"], df.at[d[0], "source:seq"] = \
                df.at[d[0], "source:seq"], df.at[n[0], "source:seq"]
    return df

# ---------------------------------------------------------------------
# 4) Transparent normalization pipeline (all steps switchable)
# ---------------------------------------------------------------------
def normalize_df(df, map_labels=True, drop_queue_routed=True, order_by_source=True):
    out = df.copy()
    if map_labels:                       # Step A: label semantics repair
        out["concept:name"] = out["concept:name"].replace({"Risk Screen": "Classify"})
    if drop_queue_routed:                # Step B: technical-event removal
        out = out[out["concept:name"] != "Queue Routed"]
        # equivalent pm4py API, gated on gateway-config confirmation:
        # out = pm4py.filter_event_attribute_values(
        #     out, "concept:name", ["Queue Routed"], level="event", retain=False)
    if order_by_source and "source:seq" in out.columns:   # Step C: ordering repair
        out = out.sort_values(["case:concept:name", "source:seq"], kind="mergesort")
    return out

# ---------------------------------------------------------------------
# 5) Diagnostics: DFG, variants, alignments, fitness, precision
# ---------------------------------------------------------------------
def conformance_summary(log, net_, im_, fm_, tag):
    diag = pm4py.conformance_diagnostics_alignments(log, net_, im_, fm_)
    fit = pm4py.fitness_alignments(log, net_, im_, fm_)
    prec = pm4py.precision_alignments(log, net_, im_, fm_)
    moves = Counter()
    for tr in diag:
        for lm, mm in tr["alignment"]:
            if lm not in SKIP and mm in SKIP:
                moves[("log move ", str(lm))] += 1
            elif lm in SKIP and mm not in SKIP:
                moves[("model move", str(mm))] += 1
    pct = fit.get("percentage_of_fitting_traces", fit.get("percFitTraces", float("nan")))
    print(f"\n=== {tag} ===")
    print(f"  fitting traces : {pct:.1f}%")
    print(f"  log fitness    : {fit.get('log_fitness', float('nan')):.3f}")
    print(f"  avg trace fit  : {fit.get('average_trace_fitness', float('nan')):.3f}")
    print(f"  precision      : {prec:.3f}")
    print("  dominant deviations:")
    for (kind, act), n in moves.most_common(6):
        print(f"    {kind}: {act} (x{n})")

def dfg_top(log_or_df, tag, k=8):
    dfg, sa, ea = pm4py.discover_dfg(log_or_df)
    print(f"\n--- DFG {tag}: top {k} edges ---")
    for (a, b), n in sorted(dfg.items(), key=lambda kv: -kv[1])[:k]:
        print(f"    {a}  ->  {b} : {n}")

def variant_profile(df, tag, k=6):
    vc = (df.groupby("case:concept:name")["concept:name"]
            .apply(lambda s: ",".join(s)).value_counts())
    print(f"\n--- Variants {tag} (top {k}) ---")
    for v, n in vc.head(k).items():
        print(f"    {n:4d}  {v}")

# ---------------------------------------------------------------------
# 6) Run the staged comparison
# ---------------------------------------------------------------------
apr_log = variants_to_log(APR_MAY, datetime(2026, 4, 1))
jun_log = variants_to_log(JUN_JUL, datetime(2026, 6, 1))
aug_log = variants_to_log(AUG_SEP, datetime(2026, 8, 1))

conformance_summary(apr_log, net, im, fm, "Apr-May raw vs normative (baseline)")
conformance_summary(jun_log, net, im, fm, "Jun-Jul raw vs normative (collapse)")
dfg_top(to_df(jun_log), "Jun-Jul raw")

jun_df = add_source_seq(to_df(jun_log))
conformance_summary(pm4py.convert_to_event_log(normalize_df(jun_df, True, False, False)),
                    net, im, fm, "Jun-Jul + label map only")
conformance_summary(pm4py.convert_to_event_log(normalize_df(jun_df, True, True, False)),
                    net, im, fm, "Jun-Jul + label map + Queue Routed removed")
jun_norm_df = normalize_df(jun_df, True, True, True)
variant_profile(to_df(jun_log), "Jun-Jul raw")
variant_profile(jun_norm_df, "Jun-Jul normalized")
conformance_summary(pm4py.convert_to_event_log(jun_norm_df), net, im, fm,
                    "Jun-Jul fully normalized (map + removal + source ordering)")
dfg_top(jun_norm_df, "Jun-Jul normalized")

aug_df = add_source_seq(to_df(aug_log))
aug_norm = pm4py.convert_to_event_log(normalize_df(aug_df, True, True, True))
conformance_summary(aug_norm, net, im, fm, "Aug-Sep normalized vs NORMATIVE model")
conformance_summary(aug_norm, cnet, cim, cfm,
                    "Aug-Sep normalized vs CANDIDATE (optional sign-off)")

# ---------------------------------------------------------------------
# 7) Caveats
# ---------------------------------------------------------------------
print("""
============================ CAVEATS ============================
1. Inputs are VARIANT-FREQUENCY AGGREGATES, not the original
   timestamped log; absolute fitness/precision values will not match
   the investigation report. The staged recovery pattern is the point.
2. Timestamps are synthetic. The Notify/Decision inversion is
   simulated so the source-sequence repair has a real defect to fix;
   in production, ALWAYS order by the source-system sequence number,
   never by warehouse ingestion time.
3. The candidate model's X ( tau, 'Supervisor Sign-off' ) is
   CONTROL-FLOW ONLY: it cannot enforce the EUR 50,000 condition,
   accepts sign-off on any case, and therefore OVERGENERALIZES.
   Its fitness gain must be read jointly with precision, and the real
   control should be a data-aware Petri net guard or an attribute-
   level rule check on claim value and authorization.
4. Removing 'Queue Routed' assumes it is purely technical; this must
   be confirmed against gateway configuration before adoption.
5. 'Manual Override' is deliberately kept: IT assesses it as a real
   user action, so its residual deviation cost is a finding, not noise.
=================================================================
""")
```

## 7. Provisional conclusion

The measured conformance collapse has a primary explanation with high confidence (~90%): a measurement-stack failure, not a behavioral rupture. Three independent, dated mechanisms — the `Risk Screen` label rename, the `Queue Routed` technical event, and the ingestion-time ordering defect — account for the June collapse; removing them in sequence restores fitness from 32% to 89% against a 93% baseline. A second, categorically distinct mechanism explains the August residual with high confidence (~85%): model obsolescence. ## 8. Model-governance recommendation

1. **Model versioning.** Normative models live in version control with effective-dated validity windows; every policy change opens a model-change ticket before its effective date; every conformance report pins the model version and validity period it was scored against; silent model edits are prohibited.
2. **Event-semantic contracts.** Every activity label carries a registered definition — source screen, business meaning, owner, technical/business flag. UI renames must register an alias mapping before deployment; mappings are versioned configuration data consumed by the pipeline, never ad hoc transformations inside analysis code.
3. **Technical-event policy.** System-generated events are flagged at emission (e.g., `event_type=technical`); conformance jobs exclude them by contract, not by hand-picked filtering; any new gateway or middleware event requires process-mining sign-off before it enters the analytical log.
4. **Timestamp provenance.** Every event carries its source timestamp, a monotonic source-system sequence number, and ingestion metadata; ordering always uses the source sequence; any ETL change affecting time semantics must pass automated sequence-vs-timestamp consistency gates before conformance results may be published.
5. **Data-aware constraints.** Conditions such as value thresholds and resource authorizations are encoded as data-aware guards (guarded Petri nets or attribute-level rule checks) or explicitly declared out of scope; every control-flow-only model ships with a written list of conditions it does not enforce, attached to every fitness figure it produces.
6. **Post-release validation.** After any UI, ETL, or gateway release, run automated drift checks — new activities, novel DFG edges, fitness-drop decomposition, resource-completeness, label-alias coverage — plus a small manual provenance audit; conformance KPIs are quarantined until validation passes; maintain a golden sample log for regression testing of the entire measurement stack.
