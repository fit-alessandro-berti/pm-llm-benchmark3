```
effort(a, c, skill) = base_service_time(a) * (0.6 + 0.8*c) * k_skill
   k_skill: 3  1.00, 2  1.15, 1(supervised)  1.35
supervisor_overhead = 0.30 * base_service_time(a)      # counted as 0.5 assignment
handover_wait(band) = low 0.4h | medium 1.2h | high 2.7h   # medians from evidence
weak_skill_penalty  = +3.3h service if owner kept at skill 1 without coaching
slack(c,r) = sla_remaining - (queue_wait(r) + effort + handover_wait(if owner change))
```

## 2.3 Pseudocode

```python
def assign_batch(cases, resources, state, weights, version="v1"):
    # ---------- PASS 0: order ----------
    urgent_high = sort([c for c in cases if c.priority in ("urgent","high")],
                       key=lambda c: c.sla_remaining)          # earliest deadline first
    normal_low  = sort([c for c in cases if c.priority in ("normal","low")],
                       key=lambda c: (c.sla_remaining, -c.complexity))
    plan = {}

    for c in urgent_high + normal_low:
        # ---------- PASS 1: HARD ELIGIBILITY FILTER ----------
        cand = []
        for r in resources:
            s = r.skill[c.required_skill]
            if s == 0:                       continue   # H1
            sup = None
            if c.required_skill == "Security" and s < 3:
                sup = pick_supervisor(["R7_Gita","R8_Hugo"], state, c)   # H2
                if sup is None:              continue
            if c.required_skill == "Approval" and s < 2:
                signer = pick_signer(skill_ge=2, activity="Approval", state=state)
                if signer is None:           continue   # H3 (prepare-only pair)
                sup = signer
            if c.priority in ("urgent","high") and s < 2 and sup is None: continue  # H4
            if s == 1 and sup is None and (c.complexity >= 0.35 or c.priority != "low"):
                continue                                # trainee needs a coach
            if state.load_units[r] + role_units(sup) > 4: continue        # H5
            if effort(c, r, sup) > r.hours_left_today and not deferrable(c): continue  # H6
            if r.ot_risk == "high" and not h8_exception(c, r, state):     # H8
                if not (deferrable(c) or offsetting_release(r, state)):   continue
            if r != c.owner and c.reassignment_count >= 2 \
               and not threshold_justification(c, r, sup): continue       # H9
            cand.append((r, sup))

        if not cand:
            plan[c] = escalate(c, options=["supervised pair", "defer + renegotiate SLA",
                                           "controlled handover", "cross-team loan"])
            log_exception(c, "NO_FEASIBLE_RESOURCE"); continue

        # ---------- PASS 2: SOFT SCORING ----------
        w = weights[c.priority]
        if training_share(plan) < 0.20 and c.priority in ("normal","low"):
            w = boost(w, "T", 1.5)                     # quota controller, soft only

        def score(r, sup):
            U = urgency_fit(slack(c, r))               # 1 if slack>>0, 0 as slack0, reject if <0
            S = {3:1.0, 2:0.75, 1:0.45}[r.skill[c.required_skill]] + (0.10 if sup else 0)
            C = 1.0 if r == c.owner else -handover_penalty(c)   # band × (1+complexity) × (1+0.3*reassign)
            F = 1 - normalised_load(r, state) - ot_penalty(r)   # high .6 / medium .2 / low 0
            T = training_credit(c, r, sup)             # 1.0 documented priority + coach + slackbuffer
                                                       # 0.5 stretch at skill 2; 0 otherwise
            B = -bottleneck_tax(r, c) + bus_factor_bonus(c, r)  # protect scarce specialists,
                                                               # reward creating a 2nd competent performer
            return w.U*U + w.S*S + w.C*C + w.F*F + w.T*T + w.B*B

        ranked = sorted(cand, key=lambda rs: (
            -score(*rs),
            -slack(c, rs[0]),                          # tie 1: SLA margin
            0 if rs[0] == c.owner else 1,              # tie 2: continuity
            normalised_load(rs[0], state),             # tie 3: fairness
            ot_rank(rs[0]),                            # tie 4: overtime risk
            stable_hash(c.id, rs[0].id)))              # tie 5: deterministic, reproducible
        plan[c] = commit(ranked[0], c, reason=explain(ranked, c), scores=score_breakdown)

    # ---------- PASS 3: REPAIR / BATCH / FREEZE ----------
    plan = form_quality_batches(plan)      # H7: normal|low and SLA>24h, same activity, similar complexity
    plan = repair_cap_and_fairness(plan)   # move lowest-priority, lowest-complexity, low-handover cases first
    plan = add_escalation_triggers(plan)   # e.g. "if not resolved in 2h  specialist consult (no owner change)"
    assert hard_constraints_hold(plan)     # fail closed: never publish a non-compliant plan
    write_log(plan, version, score_breakdown, assignment_reason, exception_codes)
    return plan
```

**Tie-breaking & exceptions.** Deterministic order above; a stable hash makes the last tie reproducible for auditors instead of discretionary. Any human override must supply an `assignment_reason` and is diffed against the computed recommendation (indicator I10). Infeasible cases are *escalated with options*, never forced. Re-planning triggers: new urgent case, absence, slack < 0.5h, or a supervisor becoming unavailable — but H10 prevents churn.

# 5. Explanation to workers

> **How today's work was shared out**
>
> We look at four things, in this order: **what the rules allow**, **how much time the customer has left**, **who already knows the case**, and **how loaded and tired you already are**. Learning is built in, not squeezed in at the end.
>
> - **Rules come first.** Security reviews are done by a Risk specialist, or by someone learning it *with* Gita or Hugo signed on. Approvals are finalised only by someone qualified to finalise. If a note in the system asks for something the rules don't allow, we follow the rules and fix the note — that's what happened with C015: Eva and Jonas aren't certified for Security yet, so they can observe, and we'll book the certification first. Nobody is being held back; the record was wrong.
> - **Urgency is about the customer's clock, not about who asks loudest.** C002 and C011 go first because they expire in 2–4 hours.
> - **We try not to pass cases around.** C001, C007 and C016 stay with the person who already owns them, because handing over a complicated case costs hours of re-explanation and, after three handovers, cases come back as rework much more often. Where the owner isn't the deepest expert, we add a specialist alongside them instead of moving the case.
> - **We protect people who are already stretched.** Bruno, David and Iris get **no extra hours today**. Bruno hands off an approval and picks up a coached quality check next shift instead. David keeps his diagnosis case but starts it fresh next shift, with a short consult — the repeated loop is a process problem, not a "David problem". Iris's quality check moves into a batch so her queue gets lighter.
> - **Learning slots are real assignments, with a coach and time budget.** Amal practices diagnosis on C009 with Celine reviewing; Bruno practices quality checking on C012 with Jonas co-signing. Both have plenty of SLA room, so learning isn't happening under time pressure.
> - **When we can't offer someone their learning slot, we say so and say why.** Iris's negotiation development is deferred: the only negotiation cases today are a waiting customer and a VIP with 4 hours left. It's logged, and the next low-risk negotiation case is reserved for her.
> - **Nobody is expected to be a machine.** Jonas is capped at four assignments; Farid and Gita keep free time on purpose so that an urgent arrival or an absence doesn't collapse the queue.
>
> **What the numbers are used for.** We track handovers, rework, SLA misses and who gets development opportunities — to fix the *system* (bottlenecks, bad routing hints, unfair distribution), not to rank individuals. Every assignment carries a reason you can read. If a reason looks wrong, you can challenge it; a team lead can override it, and the override and its reason are recorded so we can learn from it and adjust the rules together.
