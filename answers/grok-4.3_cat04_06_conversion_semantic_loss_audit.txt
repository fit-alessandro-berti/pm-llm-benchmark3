# 1. Source-Semantics Baseline

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|--------------|-----------|------------------|------------------|------------------------------|
| I1 | Register Change is the unique initial activity | trace starting with Register | any trace omitting Register or placing it after another activity | yes |
| I2 | Assess Risk and Prepare Evidence are concurrent (no order) after Register | traces with Assess then Prepare and Prepare then Assess | any trace enforcing strict order between them | yes |
| I3 | Legal Review is optional after Assess Risk | traces that contain Legal Review and traces that skip it | traces that execute Legal Review before Assess Risk | yes |
| I4 | Verification loop cannot start until both Assess Risk and Prepare Evidence complete | no trace enters Configure Trial before both predecessors finish | any trace allowing Configure Trial while either predecessor is pending | yes |
| I5 | Optional Legal and verification loop are unordered (may interleave) | traces interleaving Legal Review with Configure/Inspect | any model forcing strict precedence between the two branches | yes |
| I6 | Each verification iteration executes Configure Trial before Inspect Trial | every iteration contains Configure  Inspect | any iteration containing Inspect before Configure | yes |
| I7 | At least one verification iteration occurs; Correct Defect enables repetition | traces with one or more (Configure, Inspect, Correct Defect) cycles | empty verification or zero iterations | yes |
| I8 | Release Change is synchronized after both optional-legal branch and verification loop | Release only after both branches complete | Release appearing before either branch finishes | yes |
| I9 | Archive Change occurs after Release Change and is final | every complete trace ends with Archive | Archive appearing before Release or non-final | yes |

# 6. Visual-Semantics Review

BPMN parallel gateways may be read as enforcing a specific interleaving order because of layout position even though the underlying net permits any interleaving. Exclusive gateways introduced for the silent skip may appear mandatory when the visual omits the skip path. Loop visualization often collapses the binary LOOP structure into a single “loop” marker, hiding the mandatory Configure-before-Inspect ordering inside each iteration. Silent routing nodes disappear, removing evidence of optionality. Graph layout can suggest a total order between Legal Review and verification that the model does not enforce. Annotations listing the original invariant IDs next to each gateway and a separate “behavioral note” document listing allowed interleavings reduce ambiguity.

# 7. Rejection Criteria

- Resulting net fails `check_soundness`.
- Reachability graph admits a trace that reaches Release before verification completes.
- Footprints show loss of an allowed interleaving between Assess Risk and Prepare Evidence.
- Optional Legal Review becomes mandatory after conversion.
- Round-trip net fails exact-final-marking test on any positive witness.
- Process-tree conversion succeeds but the resulting tree forces an ordering absent in the source POWL.
- Any conversion produces a non-workflow net.
- Visible-trace set under bound differs between source and round-tripped net.

# 8. Canonical Representation Recommendation

The accepting Petri net obtained directly from `convert_to_petri_net(source_powl)` is the authoritative canonical model for storage. All BPMN and process-tree artifacts are derivative. Every derivative must be accompanied by soundness diagnostics, footprint comparison, and a bounded witness-trace report. A process-tree intermediate must not be allowed because the source is not block-structured. Future edits must be performed on the canonical Petri net; any new visualization is regenerated from that net without round-tripping through BPMN or trees.

# 9. Residual Uncertainty

- Whether every possible interleaving permitted by the net is also accepted by the BPMN gateway semantics under all layout engines.
- Whether silent-transition removal in BPMN preserves the exact set of visible traces when the optional branch is skipped.
- Long-term behavioral drift if a stakeholder edits the BPMN diagram and the edit is later re-imported.
