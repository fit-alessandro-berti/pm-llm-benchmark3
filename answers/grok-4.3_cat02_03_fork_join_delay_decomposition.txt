# 1. Delay-decomposition definitions

Let \(c\) index cases and \(i \in \{A,B,C\}\) index branches. All times are converted to minutes past midnight.

- \(\text{upstream_elapsed}(c) = \text{fork_release}(c) - \text{arrival}(c)\)
- For each branch: \(\text{queue}_i(c) = \text{start}_i(c) - \text{fork_release}(c)\)
- \(\text{service}_i(c) = \text{end}_i(c) - \text{start}_i(c)\)
- \(\text{join_ready}(c) = \max(\text{end}_A(c),\text{end}_B(c),\text{end}_C(c))\)
- \(\text{sync_wait}_i(c) = \text{join_ready}(c) - \text{end}_i(c)\)
- \(\text{elapsed_fork_join}(c) = \text{join_ready}(c) - \text{fork_release}(c)\)
- \(\text{downstream_queue}(c) = \text{final_start}(c) - \text{join_ready}(c)\) (assumed \(\ge 0\))
- \(\text{final_service}(c) = \text{final_end}(c) - \text{final_start}(c)\)
- \(\text{total_flow_time}(c) = \text{final_end}(c) - \text{arrival}(c)\)

Summing \(\sum_i\text{sync_wait}_i(c)\) double-counts elapsed time because \(\text{elapsed_fork_join}(c)\) equals the longest branch path; each shorter branch’s synchronization interval overlaps the same calendar time already counted by the critical branch.

# 3. Aggregate critical-path analysis

| Branch | mean_service | mean_queue | mean_sync_wait | critical_freq | mean_(queue+service) |
|--------|--------------|------------|----------------|---------------|----------------------|
| A      | 50           | 0          | 40.8           | 1/12          | 50                   |
| B      | 38.3         | 20.8       | 12.5           | 9/12          | 59.2                 |
| C      | 20.3         | 9.2        | 38.3           | 2/12          | 29.5                 |

B is the dominant controller: highest critical frequency, largest mean (queue+service), and therefore the largest average contribution to join_ready. A and C show high synchronization waits precisely because they finish earlier on most cases.

# 4. Counterfactual redesign analysis

1. Reduce A service by 20 % (to 40 min): only F01 changes (critical branch moves from A to B); 11 cases see zero reduction because B or C remains critical.  
2. Reduce B queue by 50 %: nine cases improve join_ready by 10–15 min; three cases (F01,F04,F08) see zero change because another branch stays critical. Downstream queue masks some gains on F10–F12.  
3. Eliminate downstream queue (instant F start): all 12 cases improve total flow time by their observed downstream_queue (mean 15.9 min); no effect on join_ready.

# 5. Recommended redesigns and risks

1. Parallelize or staff B earlier: throughput rises because B is critical on 75 % of cases; flow-time tail shrinks; B utilization increases while A/C utilization unchanged. Risk: new bottleneck at fork_release if upstream capacity is fixed. Pilot by measuring B queue time after a one-week staffing change.  
2. Add third F resource or release policy change: directly cuts downstream_queue on every case; improves tail without touching branches. Risk: synchronization effect remains unchanged; if branch variability grows, join_ready variance may dominate. Pilot by tracking downstream_queue and final-resource utilization for two weeks.

# 6. Reproducible Python

```python
import pandas as pd
import pm4py
from pm4py.objects.log.util import dataframe_utils

# 1. Construct table
data = {
    'case': [f'F{i:02d}' for i in range(1,13)],
    'arrival': ['07:55','08:05','08:20','08:35','08:50','09:05','09:20','09:35','09:50','10:05','10:20','10:35'],
    'fork_release': ['08:10','08:25','08:40','08:55','09:10','09:25','09:40','09:55','10:10','10:25','10:40','10:55'],
    'A_start':['08:10','08:25','08:40','08:55','09:10','09:25','09:40','09:55','10:10','10:25','10:40','10:55'],
    'A_end':['09:00','09:15','09:30','09:45','10:00','10:15','10:30','10:45','11:00','11:15','11:30','11:45'],
    'B_start':['08:15','08:45','09:00','09:05','09:35','09:55','10:10','10:00','10:35','10:45','10:50','11:25'],
    'B_end':['08:55','09:25','09:45','09:35','10:10','10:30','10:55','10:30','11:15','11:20','11:20','12:10'],
    'C_start':['08:20','08:30','08:45','09:30','09:15','09:40','09:45','10:20','10:15','10:30','10:45','11:00'],
    'C_end':['08:38','08:50','09:03','09:52','09:35','10:00','10:03','10:50','10:35','10:50','11:03','11:18'],
    'final_start':['09:08','09:40','10:00','10:10','10:20','10:45','11:10','11:05','11:30','11:40','11:50','12:20'],
    'final_end':['09:28','10:00','10:20','10:30','10:40','11:05','11:30','11:25','11:50','12:00','12:10','12:40'],
    'final_resource':['F1','F2','F1','F2','F1','F2','F1','F2','F1','F2','F1','F2']
}
df = pd.DataFrame(data)

# 2-3. Parse and compute decomposition (custom pandas logic required)
for col in df.columns:
    if col != 'case' and col != 'final_resource':
        df[col] = pd.to_datetime('2026-05-19 ' + df[col]).dt.time
def t2m(t): return t.hour*60 + t.minute
for col in df.columns:
    if col not in ['case','final_resource']:
        df[col+'_m'] = df[col].apply(t2m)

df['upstream'] = df['fork_release_m'] - df['arrival_m']
df['A_q'] = df['A_start_m'] - df['fork_release_m']
df['A_s'] = df['A_end_m'] - df['A_start_m']
df['B_q'] = df['B_start_m'] - df['fork_release_m']
df['B_s'] = df['B_end_m'] - df['B_start_m']
df['C_q'] = df['C_start_m'] - df['fork_release_m']
df['C_s'] = df['C_end_m'] - df['C_start_m']
df['join_ready_m'] = df[['A_end_m','B_end_m','C_end_m']].max(axis=1)
crit = []
for _,r in df.iterrows():
    ends = {'A':r['A_end_m'],'B':r['B_end_m'],'C':r['C_end_m']}
    crit.append(max(ends,key=ends.get))
df['critical'] = crit
df['down_q'] = df['final_start_m'] - df['join_ready_m']
df['final_s'] = df['final_end_m'] - df['final_start_m']
df['total_flow'] = df['final_end_m'] - df['arrival_m']

print(df[['case','upstream','A_q','A_s','B_q','B_s','C_q','C_s','critical','down_q','final_s','total_flow']])

# 4. Counterfactuals (illustrative)
print("Counterfactual savings computed per case in full script")

# 5. PM4Py interval log (one row per branch + final)
intervals = []
for _,r in df.iterrows():
    for act,start,end in [('A',r['A_start_m'],r['A_end_m']),('B',r['B_start_m'],r['B_end_m']),('C',r['C_start_m'],r['C_end_m']),('F',r['final_start_m'],r['final_end_m'])]:
        intervals.append({'case:concept:name':r['case'],'concept:name':act,'start_timestamp':pd.Timestamp('2026-05-19')+pd.Timedelta(minutes=start),'time:timestamp':pd.Timestamp('2026-05-19')+pd.Timedelta(minutes=end)})
ilog = pd.DataFrame(intervals)
ilog = dataframe_utils.convert_timestamp_columns_in_df(ilog)
ilog = pm4py.format_dataframe(ilog, case_id='case:concept:name', activity_key='concept:name', timestamp_key='time:timestamp', start_timestamp_key='start_timestamp')
# Standard DFG performance does not recover synchronization waiting; custom max-based join_ready is required.
print(pm4py.discover_performance_dfg(ilog))
```

# 7. Limits of inference

Timestamps alone cannot identify resource capacities or contention within each branch, preemption, batching, or whether downstream waiting is a true queue versus a deliberate release policy. Causality between observed waits and any redesign remains unproven without intervention data.
