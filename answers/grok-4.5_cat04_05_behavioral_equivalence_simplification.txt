# 1. Equivalence Notions

**Observation alphabet.**  
Visible labels  
\(\Sigma = \{\)Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, Close Case\(\}\).  
The silent leaf `tau` is always hidden. Duplicate visible labels are distinguished by **occurrence position in the trace** (i.e., traces are words in \(\Sigma^*\), not multisets), unless a view explicitly collapses them.

**Visible trace equivalence after hiding `tau`.**  
Let \(L(M)\) be the set of finite complete firing sequences of the accepting Petri-net semantics of process tree \(M\), projected onto \(\Sigma\) (every `tau` deleted, order of visible labels preserved).  
\(M_A \equiv_{\mathrm{tr}} M_B \iff L(M_A)=L(M_B)\).  
This is the finest language equivalence used below; it is sensitive to cardinality, order, and optionality of every visible label.

**Bounded visible-language equivalence under P3.**  
\[
L_{\le 12,\le 3}(M) = \{\, w\in L(M) \mid |w|\le 12 \land \#(w,\text{Analyze Revision})\le 3 \,\}.
\]  
\(M_A \equiv_{\mathrm{P3}} M_B \iff L_{\le 12,\le 3}(M_A)=L_{\le 12,\le 3}(M_B)\).  
Equality is only **evidence**, never a proof of \(L(M_A)=L(M_B)\).

**Business-relevant equivalence under P1 (operational compliance).**  
A complete visible trace is P1-legal iff  
1. it starts with Open Case and ends with Close Case;  
2. the projection onto \(\{\)Analyze Revision, Check Revision, Rework Case\(\}\) belongs to the regular language  
   \((\text{Analyze Revision}\mid\text{Check Revision})^*\text{Analyze Revision}(\text{Analyze Revision}\mid\text{Check Revision})^*\text{Check Revision}(\text{Rework Case}(\text{Analyze Revision}\mid\text{Check Revision})^*\text{Analyze Revision}(\text{Analyze Revision}\mid\text{Check Revision})^*\text{Check Revision})^*\);  
   i.e., every Analyze is “covered” by its own Check before the next Rework or before Close, and Rework strictly separates successive analysis attempts;  
3. Approve Revision may appear zero or one time after each parallel Analyze/Check pair and nowhere else.  

\(M_A \equiv_{\mathrm{P1}} M_B\) iff the sets of P1-legal traces they generate coincide.  
(P1 therefore **rejects** any model that can emit two Analyzes under a single Check.)

**Abstracted dashboard equivalence under P2.**  
Define the abstraction map \(\alpha:\Sigma^*\to Obs_{P2}\) that  
- keeps the mandatory endpoints Open Case … Close Case,  
- replaces every non-empty sequence of Check Revision by the Boolean flag `check=true`,  
- deletes every Approve Revision and every `tau`,  
- records the integer \(n=\#(\text{Analyze Revision})\) and the Boolean `rework=(\#(\text{Rework Case})>0)`,  
- discards all interleaving information among Analyze and Check.  

Then \(M_A \equiv_{\mathrm{P2}} M_B \iff \alpha(L(M_A))=\alpha(L(M_B))\).  
Under \(\alpha\), cardinality of Check and the precise schedule of Approve become invisible.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|--------|---------|---------|----------------------|
| Loop scope | Loop body = (Analyze  Check) · (Approve  ); redo via Rework | Loop body = Analyze · (Approve  ) only; Check lies **outside** the loop | A ties a fresh Check to every Analyze; B performs Check once for the whole case |
| Min / max Check occurrences | min = 1, max =  (one per iteration) | min = max = 1 | Cardinality of Check distinguishes the languages |
| Placement of Check | Concurrent with its matching Analyze, before the optional Approve of that iteration | Anywhere concurrent with the entire revision loop (before, between, or after any Analyze/Rework) | B admits schedules impossible in A (Check after several Analyzes) and forbids schedules required by A (two Checks) |
| Optional approval | One Approve-or- per loop iteration | One Approve-or- per loop iteration (Analyze only) | Same per-iteration optionality, but A’s Approve is sequenced after both Analyze and Check of that round |
| Concurrency | Binary parallel inside each iteration | Top-level parallel between a single Check and the whole loop | Different partial-order envelopes; different weak-orderings of Check vs. Rework |
| Join before Close | Loop exit, then Close | Parallel join (Check finished  loop finished), then Close | Both are sequential before Close; the difference is only what must be finished (multiple Checks vs. one) |
| Silent leaves | One  per iteration (the skip-Approve branch) | One  per iteration | Identical silent structure per iteration; hiding  does not restore trace equivalence |

Standard binary-loop reading used throughout: `*(P,Q)` executes P; then either exits or executes Q·P again.

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|------|---------|------------|-----------------|--------|
| Visible trace equiv. (hide ) | not equivalent | high | Different cardinalities and positions of Check Revision | — |

| P2 executive dashboard | equivalent only under stated abstraction | high | \(\alpha\) collapses Check cardinality to a Boolean and forgets Approve/interleaving; both models then yield exactly the observations \(\{(n,\mathrm{rework}=(n\ge 2),\mathrm{check}=\top)\mid n\ge 1\}\) | Abstraction is lossy; restoring any Check count breaks equivalence |
| P3 bounded (12 events, 3 Analyzes) | not equivalent | high | Concrete counter-examples of length  7 already separate the bounded languages (see §4) | Boundedness is only evidence for the unbounded case |

# 4. Counterexample Traces

All traces below are complete and -projected (Approve is shown only when chosen).  
Loop semantics guarantee that after every Rework the body runs again, so “two analysis attempts” always means two Analyzes separated by Rework.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|----------|-------|---------|---------|------------------------------------|---------------|
| A1 | Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close Case | yes | no | Second Check Revision — B contains only one Check leaf | tr, P1, P3 |
| A2 | Open Case, Check Revision, Analyze Revision, Approve Revision, Rework Case, Analyze Revision, Check Revision, Approve Revision, Close Case | yes | no | Two Checks and two Approves; B cannot emit a second Check | tr, P1, P3 |
| B1 | Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case | no | yes | Single Check after two Analyzes — A demands a Check inside the first iteration before Rework | tr, P1, P3 |
| B2 | Open Case, Analyze Revision, Approve Revision, Analyze Revision, Check Revision, Close Case | no | yes | Missing Rework between two Analyzes **and** only one Check; A’s loop forces Rework to re-enter and forces a Check per entry | tr, P1, P3 |
| B3 (extra) | Open Case, Check Revision, Analyze Revision, Close Case | yes | yes | (common short word — not a separator) | — |

**Effect of optional Approve and hidden .**  
Choosing the -branch simply deletes Approve from the visible word; it does **not** create or remove Check events. Consequently every separator above remains a separator after arbitrary insertion/deletion of Approve (provided each Approve stays inside its own iteration for A, or after its Analyze for B). Hiding  therefore never restores trace equivalence; it only adds the silent variants of the same distinguishing skeletons.

**Inclusion.**  
Neither language includes the other: A1L(A)\L(B) and B1L(B)\L(A).  
Under the P2 map \(\alpha\), both A1 and B1 collapse to the same observation \((n=2,\mathrm{rework}=\top,\mathrm{check}=\top)\), which is why P2 still equates the models.

# 5. Bounded Comparison Code

```python
"""
Bounded visible-language comparison of Model A vs Model B (P3).
Exhaustive BFS over markings; silent transitions are taken freely
but do not increase the visible-length counter.
"""

import pm4py
from pm4py.algo.analysis.woflan import algorithm as woflan
from collections import deque
from copy import copy

# ---------------------------------------------------------------------------
# 1. Parse
# ---------------------------------------------------------------------------
A_STR = ("->('Open Case',*(->(+('Analyze Revision','Check Revision'),"
         "X('Approve Revision',tau)),'Rework Case'),'Close Case')")
B_STR = ("->('Open Case',+('Check Revision',*(->('Analyze Revision',"
         "X('Approve Revision',tau)),'Rework Case')),'Close Case')")

tree_a = pm4py.parse_process_tree(A_STR)
tree_b = pm4py.parse_process_tree(B_STR)

# ---------------------------------------------------------------------------
# 2. Convert to accepting Petri nets
# ---------------------------------------------------------------------------
net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

# ---------------------------------------------------------------------------
# 3. Soundness
# ---------------------------------------------------------------------------
def soundness_report(label, net, im, fm):
    try:
        ok = pm4py.check_soundness(net, im, fm, print_diagnostics=False)
    except TypeError:
        # older pm4py signature
        ok = pm4py.check_soundness(net, im, fm)
    print(f"[{label}] soundness = {ok}")

soundness_report("A", net_a, im_a, fm_a)
soundness_report("B", net_b, im_b, fm_b)

# ---------------------------------------------------------------------------
# 4–5. Exhaustive bounded BFS for visible traces
# ---------------------------------------------------------------------------
def visible_label(t):
    if t.label is None or t.label == "tau":
        return None
    return t.label

def bounded_language(net, im, fm, max_vis=12, max_analyze=3):
    """
    Exhaustive exploration.
    State key = (frozen marking, visible_trace_tuple, analyze_count)
    Silent steps do not increase visible length.
    Final traces are those that reach fm with no bound violation.
    """
    vis_traces = set()
    # queue elements: (marking, vis_tuple, analyze_count)
    q = deque([(im, tuple(), 0)])
    seen = {(frozenset(im.items()), tuple(), 0)}

    while q:
        marking, vis, n_an = q.popleft()

        if marking == fm:
            vis_traces.add(vis)
            # continue: other silent paths may still leave fm? normally stop,
            # but we still explore enabled transitions from fm only if any
            # (sound nets have none). Fall through.

        if len(vis) > max_vis or n_an > max_analyze:
            continue

        enabled = pm4py.get_enabled_transitions(net, marking)
        for t in enabled:
            # fire copy
            new_marking = copy(marking)
            for a in t.in_arcs:
                new_marking[a.source] -= a.weight
                if new_marking[a.source] == 0:
                    del new_marking[a.source]
            for a in t.out_arcs:
                new_marking[a.target] = new_marking.get(a.target, 0) + a.weight

            lab = visible_label(t)
            if lab is None:
                new_vis = vis
                new_an = n_an
            else:
                if len(vis) + 1 > max_vis:
                    continue
                new_vis = vis + (lab,)
                new_an = n_an + (1 if lab == "Analyze Revision" else 0)
                if new_an > max_analyze:
                    continue

            key = (frozenset(new_marking.items()), new_vis, new_an)
            if key not in seen:
                seen.add(key)
                q.append((new_marking, new_vis, new_an))

    return vis_traces

print("\nExhaustive BFS under P3 bounds (max_vis=12, max_analyze=3)...")
lang_a = bounded_language(net_a, im_a, fm_a)
lang_b = bounded_language(net_b, im_b, fm_b)

only_a = sorted(lang_a - lang_b, key=lambda t: (len(t), t))
only_b = sorted(lang_b - lang_a, key=lambda t: (len(t), t))
common = lang_a & lang_b

print(f"|L_A|={len(lang_a)}  |L_B|={len(lang_b)}  |common|={len(common)}")
print(f"|only A|={len(only_a)}  |only B|={len(only_b)}")

print("\n--- sample traces unique to A (up to 8) ---")
for tr in only_a[:8]:
    print(" A:", " -> ".join(tr))

print("\n--- sample traces unique to B (up to 8) ---")
for tr in only_b[:8]:
    print(" B:", " -> ".join(tr))

print("\n[Method note] Exploration is exhaustive BFS over "
      "(marking × visible-trace × analyze-count) with explicit "
      "silent handling and final-marking equality. "
      "It is NOT random playout.")
```

# 6. Stochastic and Footprint Comparison

**Footprints.**  
`pm4py.discover_footprints` builds the directly-follows / parallelism / choice matrix of the **eventually-visible** relations. Because both trees contain the pairs (Analyze, Check) in a parallel or interleavable context, and both contain the loop-carried pair (Analyze, Rework), the footprint matrices are often identical or differ only in the Check–Rework cell. Equal footprints are a **necessary** condition for trace equivalence of a restricted class of models; they are far from sufficient once cardinality of loops or the scope of a parallel branch differs (exactly our situation).

**Stochastic language & EMD.**  
`get_stochastic_language` / `compute_emd` require a probability measure on traces. Process trees do not carry probabilities unless we impose them (e.g., uniform choice at every XOR and a geometric exit probability \(p\) at every loop). Even under a declared distribution, a low Earth-Mover’s Distance only says the two distributions are close in total variation on the examined support; it does not prove support equality. In particular the distinguishing words A1 and B1 each receive positive mass under any faithful distribution, so EMD > 0 as soon as the support is large enough to contain them.

```python
# Footprint evidence (not a proof)
fp_a = pm4py.discover_footprints(tree_a)
fp_b = pm4py.discover_footprints(tree_b)
print("footprints equal?", fp_a == fp_b)

# Stochastic comparison requires an explicit distribution.
# Illustration only: play_out frequencies as an empirical measure.
# (Declared assumption: each XOR/loop exit resolved by the playout engine defaults.)
from pm4py.algo.simulation.playout.petri_net import algorithm as pn_playout

def empirical_language(net, im, fm, n=2000, max_trace_length=20):
    log = pn_playout.apply(
        net, im, fm,
        variant=pn_playout.Variants.BASIC_PLAYOUT,
        parameters={
            pn_playout.Variants.BASIC_PLAYOUT.value.Parameters.NO_TRACES: n,
            pn_playout.Variants.BASIC_PLAYOUT.value.Parameters.MAX_TRACE_LENGTH: max_trace_length,
        },
    )
    from collections import Counter
    c = Counter()
    for case in log:
        tr = tuple(e["concept:name"] for e in case
                   if e["concept:name"] and e["concept:name"] != "tau")
        c[tr] += 1
    total = sum(c.values()) or 1
    return {k: v / total for k, v in c.items()}

# lang_sa = empirical_language(net_a, im_a, fm_a)
# lang_sb = empirical_language(net_b, im_b, fm_b)
# emd = pm4py.compute_emd(lang_sa, lang_sb)
# print("empirical EMD (heuristic, not exhaustive):", emd)
```

**Why this cannot establish trace equivalence.**  
Footprints ignore count; EMD can be made arbitrarily small by putting tiny mass on distinguishing traces while the supports remain different. Only an exhaustive language comparison (bounded or symbolic) decides \(\equiv_{\mathrm{tr}}\).

# 7. Complexity Comparison

Structural counts (derived by walking the process-tree AST):

| Metric | Model A | Model B |
|--------|---------|---------|
| Process-tree nodes (all operators + leaves) | 11 | 11 |
| Depth (root  deepest leaf) | 5 | 5 |
| Visible leaves | 6 | 6 |
| Silent leaves (`tau`) | 1 | 1 |
| Duplicate visible labels | 0 (each label appears once as a leaf; multiplicity arises only from the loop) | 0 (same) |
| Parallel operators | 1 (inside loop) | 1 (outside loop) |
| Loop operators | 1 | 1 |
| XOR operators | 1 | 1 |

The trees are isomorphic in size; they differ only in **where** the parallel subtree is attached relative to the loop. Consequently any complexity advantage must come from a later simplification, not from choosing A over B.

```python
def tree_metrics(tree):
    """Precise structural counts for a pm4py process tree."""
    nodes = 0
    depth = 0
    vis_leaves = 0
    silent_leaves = 0
    labels = []

    def rec(n, d):
        nonlocal nodes, depth, vis_leaves, silent_leaves
        nodes += 1
        depth = max(depth, d)
        kids = list(n.children) if hasattr(n, "children") and n.children else []
        if not kids:
            lab = n.label
            if lab is None or str(lab).lower() == "tau":
                silent_leaves += 1
            else:
                vis_leaves += 1
                labels.append(lab)
        for c in kids:
            rec(c, d + 1)

    rec(tree, 1)
    dup = len(labels) - len(set(labels))
    return dict(nodes=nodes, depth=depth, vis_leaves=vis_leaves,
                silent_leaves=silent_leaves, duplicate_label_count=dup)

print("A metrics:", tree_metrics(tree_a))
print("B metrics:", tree_metrics(tree_b))

sim_a = pm4py.simplicity_petri_net(net_a, im_a, fm_a)
sim_b = pm4py.simplicity_petri_net(net_b, im_b, fm_b)
print("simplicity Petri net A/B:", sim_a, sim_b)
```

(Exact numeric simplicity scores depend on the installed pm4py version; they are expected to be nearly equal because the nets differ mainly in arc placement around one parallel construct.)

# 8. Simplified Model

**Target chosen: P1 (operational compliance).**  
P1 is the strongest business view that still matches a natural process-tree pattern; P2 is recoverable from it by further abstraction, while the converse is false. A single tree cannot be faithful to P1 and simultaneously identical to B’s concurrent-check schedules, so the simplification **deliberately drops B’s exotic interleavings**.

**Compact process tree (strict per-revision check, optional approve, redo via rework):**

```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

Rationale versus originals:  
- vs A — replaces the inner parallel AnalyzeCheck by the sequential order AnalyzeCheck (still P1-legal; loses only the Analyze/Check race inside one iteration); removes one operator node;  
- vs B — moves Check inside the loop, restoring the “one Check per Analyze” rule required by P1;  
- node count 10 (down from 11), depth 4 (down from 5), still one silent leaf.

```python
import pm4py

simplified_model = pm4py.parse_process_tree(
    "->('Open Case',"
    "*(->('Analyze Revision','Check Revision',X('Approve Revision',tau)),"
    "'Rework Case'),"
    "'Close Case')"
)
# optional: net_s, im_s, fm_s = pm4py.convert_to_petri_net(simplified_model)
```

**Preservation table**

| Property | Status in simplified model |
|----------|----------------------------|
| Open first / Close last | exact |
| Every Analyze covered by its own Check before Rework/Close | exact (P1) |
| Rework separates analysis attempts | exact |
| Optional Approve per iteration | exact |
| Analyze  Check race inside one iteration (from A) | lost (serialized) |
| Check concurrent with whole loop (from B) | lost (rejected as P1-illegal) |
| Check cardinality collapsed to Boolean (P2) | abstracted (P2 still holds because 1 Check is guaranteed) |
| Unbounded loop | exact |
| Silent  skip-Approve | exact |

**Regression traces (must be accepted)**

1. `Open Case  Analyze Revision  Check Revision  Close Case`  
2. `Open Case  Analyze Revision  Check Revision  Approve Revision  Rework Case  Analyze Revision  Check Revision  Close Case`  
3. `Open Case  Analyze Revision  Check Revision  Rework Case  Analyze Revision  Check Revision  Approve Revision  Close Case`

**Negative traces (must be rejected)**

1. `Open Case  Analyze Revision  Rework Case  Analyze Revision  Check Revision  Close Case`  
   (Check missing for the first Analyze — the classic B-only word)  
2. `Open Case  Analyze Revision  Check Revision  Analyze Revision  Check Revision  Close Case`  
   (second Analyze without intervening Rework — violates loop discipline)

Structural comparison to originals: 10 nodes / depth 4 vs 11 nodes / depth 5 for both A and B; parallel operator removed; therefore strictly simpler by node count, depth, and operator diversity.

# 9. Final Recommendation

| Business view | Suitable original | Role of the simplified model |
|---------------|-------------------|------------------------------|
| P1 operational compliance | **Model A only** (B systematically violates per-revision checking) | Preferred replacement for A: preserves P1, is smaller, and eliminates the non-essential AnalyzeCheck race |
| P2 executive dashboard | **Either A or B** (they are \(\equiv_{\mathrm{P2}}\)) | Also fine for P2; reports the same \((n,\mathrm{rework},\mathrm{check})\) observations |
| P3 bounded testing | Neither is interchangeable; tests must fix one reference model | Use the simplified model as the single oracle for bounded regression suites |

**Warnings.**  
- Bounded equality (P3) with 12 events and 3 Analyzes already fails for A vs B; success of a bounded test on the simplified model against A is still only evidence, never a proof of unbounded trace equivalence (the loop is unbounded).  
- Do not substitute B for A (or for the simplified model) in any compliance or audit setting: the missing per-revision Check is observationally real and P1-illegal.  
- If a future stakeholder insists on the “one Check concurrent with the whole case” reading, that is Model B, and it must be kept under a **different** purpose label—never under P1.
