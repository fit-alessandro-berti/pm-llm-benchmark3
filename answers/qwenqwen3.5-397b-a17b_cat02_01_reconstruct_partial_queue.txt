# 1. Assumptions and notation

To reconstruct the process dynamics from the rounded and incomplete data, the following assumptions and conventions are applied:

*   **A1 (Timestamp Rounding):** All reported timestamps $T_{rep}$ represent an actual time $t_{actual} \in [T_{rep} - 2.5\text{min}, T_{rep} + 2.5\text{min}]$. Consequently, a duration calculated from two reported timestamps has an uncertainty of $\pm 5$ minutes.
*   **A2 (MISSING Start Imputation):** For an activity with a `MISSING` start timestamp, the actual start time $t_{start}$ is bounded by:
    1.  The completion of the previous activity for that case (process order).
    2.  The completion of the previous case on the same resource (resource capacity).
    3.  The reported completion time of the current activity (causality).
    4.  Specific availability windows (e.g., C2 maintenance).
*   **A3 (OPEN/Censored Cases):** For activities marked `OPEN` or blank at 14:00, the service time is at least the elapsed time from the recorded start to 14:00. The final duration is unknown (right-censored).
*   **A4 (Resource Capacity):** Resources I1, I2, C1, C2 process one case at a time. Overlaps in reported times are attributed to rounding error unless they exceed the 5-minute uncertainty band, in which they are treated as logging anomalies.
*   **A5 (C2 Maintenance):** C2 is strictly unavailable between 10:55 and 11:10. No S2 activity on C2 can overlap this interval.
*   **A6 (Queue Discipline):** First-In-First-Out (FIFO) is assumed within each station queue unless resource assignment data suggests otherwise (e.g., a later arrival starting earlier on a different parallel resource).
*   **A7 (Notation):**
    *   $W$: Waiting time (Queue time).
    *   $S$: Service time (Active processing).
    *   $T$: Sojourn time ($W + S$).
    *   $L$: Queue length / WIP.
    *   $\lambda$: Arrival rate.
    *   $\mu$: Service rate.

*   **WIP (Work In Progress):** Count of cases present at the station (Waiting + In Service) at specific time slices.
*   **Throughput:** Count of completions per hour.

**Estimation Strategy:**
*   **Lower Bound:** Assumes minimal service times and earliest possible starts consistent with constraints.
*   **Upper Bound:** Assumes maximal service times and latest possible starts consistent with constraints.
*   **Central Estimate:** Midpoint of the feasible interval for MISSING timestamps; reported values for complete timestamps (acknowledging $\pm 2.5$ min noise).

**Little's Law Check:**
$L = \lambda W$. Checked only for stable intervals where arrival and departure rates are roughly constant and the system is not in a transient startup/shutdown phase.
