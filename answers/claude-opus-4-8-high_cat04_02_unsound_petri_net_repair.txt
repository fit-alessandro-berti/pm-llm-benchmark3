# 1. Executive Verdict

Structurally, this **is** a workflow net: there is a unique source (`source`, no input arcs), a unique sink (`sink`, no output arcs), and every node lies on a `source`→`sink` path (the waiver branch reaches the sink via `waive_review → p_waived → join_waived → p_decision → authorize → sink`). So `check_is_workflow_net` should return `True`.

It should **not** be expected to be sound. The business intent requires authorization only after analysis **and** the selected review outcome are both complete, but the waiver join does not synchronize with analysis.

**Principal defect:** `t_join_waived` has a single input (`p_waived`) and ignores `p_analysis_done`. On any waiver run, it drives `p_decision` while the mandatory-analysis token is stranded.

**Business consequence:** a case can be authorized without analysis being consumed, and the run ends with a leftover token — completion is improper (unsound). Authorization effectively bypasses mandatory analysis.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|---|---|---|---|
| `t_split` | AND-split after `p_ready`: start analysis and review in parallel | Correct AND-split: consumes `p_ready`, marks both `p_analysis` and `p_review` | None on its own; it faithfully creates two concurrent tokens that must later be re-merged |
| `p_analysis → t_analyze → p_analysis_done` | Mandatory analysis branch | Correct sequential branch producing exactly one token in `p_analysis_done` | Token in `p_analysis_done` is only consumed by `t_join_normal`; if the run does not reach `t_join_normal`, it is stranded |
| Review choice at `p_review` (`t_standard_review` vs `t_waive_review`) | XOR-choice between standard review and recorded waiver | Correct free choice: `p_review` enables both; firing one disables the other | The two outcomes feed different, non-symmetric joins, so downstream behavior depends on which was chosen |
| `t_standard_review → p_review_done` | Standard-review completion | Correct: single token in `p_review_done` | Consumed only by `t_join_normal` (two-input), so the normal path re-synchronizes with analysis |
| `t_waive_review → p_waived` | Waiver completion | Correct: single token in `p_waived` | Consumed only by `t_join_waived` (one-input), which does **not** re-synchronize with analysis |
| `t_join_normal` (inputs `p_analysis_done`, `p_review_done` → `p_decision`) | AND-join re-merging analysis with standard review | Correct two-input synchronization; only enabled when analysis **and** standard review are both done | On the normal path the net behaves as intended |
| `t_join_waived` (input `p_waived` → `p_decision`) | Intended AND-join re-merging analysis with waiver | **Defective**: one-input transition. It merges nothing with analysis; it moves the waiver token to `p_decision` regardless of analysis | Enables `t_authorize` while `p_analysis_done` still holds a token → leftover token / bypass of analysis |
| `p_decision → t_authorize → sink` | Authorize only after full synchronization | Correct locally, but it trusts `p_decision`, which the waiver join can mark prematurely | Authorization occurs without the analysis token having been consumed |
| Initial/final markings `im=[source:1]`, `fm=[sink:1]` | Single-token entry and exit | Well-formed for a workflow net | On the waiver route, reaching a token in `sink` does not coincide with `fm`, because `p_analysis_done` remains marked |

Source-to-sink coverage: every place and transition is reachable from `source` and can reach `sink`, so the workflow-net path condition holds. Soundness, a behavioral property, is where it fails.

# 3. Marking-Based Counterexample

I denote a marking as the set of places holding one token (all tokens are 1 here). I start from `im`.

**Legal firing sequence exposing the defect (waiver route, authorize before analyze):**

`t_register`, `t_split`, `t_waive_review`, `t_join_waived`, `t_authorize` — reaching a marking with a token in `sink` **and** a leftover token in `p_analysis_done`-region (in fact still in `p_analysis`, since `t_analyze` never fired).

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — (initial `im`) | `source` | `t_register` | Start |
| 1 | `t_register` | `p_ready` | `t_split` | Case registered |
| 2 | `t_split` | `p_analysis`, `p_review` | `t_analyze`, `t_standard_review`, `t_waive_review` | AND-split creates the analysis token and the review token — the mandatory-analysis token now exists in the analysis branch |
| 3 | `t_waive_review` | `p_analysis`, `p_waived` | `t_analyze`, `t_join_waived` | Waiver route chosen; analysis token still sits untouched in `p_analysis` |
| 4 | `t_join_waived` | `p_analysis`, `p_decision` | `t_analyze`, `t_authorize` | **Defect:** `t_join_waived` needed only `p_waived`; it did not wait for analysis. `p_decision` is now marked while analysis has not even started |
| 5 | `t_authorize` | `p_analysis`, `sink` | `t_analyze` | **`t_authorize` fires before (indeed without) `t_analyze`.** A token is in `sink`, but the marking is `{p_analysis, sink}`, not `fm = {sink}` |

**Distinguishing "token in sink" from "`fm` reached":** After step 5, `sink` holds a token, but the marking is `{p_analysis: 1, sink: 1}` ≠ `fm = {sink: 1}`. So a run can *deposit* a token in the sink while the exact final marking is never reached.

**Why the leftover token cannot be consumed to repair the marking:** The only consumer of `p_analysis` is `t_analyze`, whose product `p_analysis_done` is only consumed by `t_join_normal`, which additionally requires `p_review_done`. But on the waiver route `p_review_done` is never produced (the token went to `p_waived` and was already consumed). Hence firing `t_analyze` next yields `{p_analysis_done: 1, sink: 1}`, and `t_join_normal` can never become enabled (its second input `p_review_done` is unreachable now). The residual token is permanently stuck. This violates *proper completion* (no tokens left besides `fm`) and *option to complete* from this reachable state — the net is **unsound**.

**Second counterexample (same defect, analyze first) — confirming order-independence:**

`t_register`, `t_split`, `t_analyze`, `t_waive_review`, `t_join_waived`, `t_authorize`.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | — | `source` | `t_register` | Start |
| 1 | `t_register` | `p_ready` | `t_split` | — |
| 2 | `t_split` | `p_analysis`, `p_review` | `t_analyze`, `t_standard_review`, `t_waive_review` | Two concurrent tokens |
| 3 | `t_analyze` | `p_analysis_done`, `p_review` | `t_standard_review`, `t_waive_review` | Analysis actually completes this time |
| 4 | `t_waive_review` | `p_analysis_done`, `p_waived` | `t_join_waived` | Note `t_join_normal` is **not** enabled: it needs `p_review_done`, which was never produced |
| 5 | `t_join_waived` | `p_analysis_done`, `p_decision` | `t_authorize` | Waiver join again ignores the completed-analysis token |
| 6 | `t_authorize` | `p_analysis_done`, `sink` | — (dead) | End marking `{p_analysis_done: 1, sink: 1}` ≠ `fm`. A token in `sink` coexists with a stranded `p_analysis_done`; no transition is enabled, so the leftover can never be cleared |

Both orderings show the same structural cause: the waiver join is a one-input transition, so the analysis token from the AND-split is never re-synchronized on the waiver path and is orphaned after authorization. This is the marking-level statement of the informal "the waiver join forgets analysis" observation.

(No livelock or unbounded behavior is present; the net is 1-safe, so the defect is purely improper completion / dead residual token, not token explosion.)

# 4. Minimal-Repair Alternatives

**Edit-cost model.** Cost = (arcs added) + (arcs removed) + 2·(places added) + 2·(transitions added), i.e. each arc edit costs 1 and each new node costs 2 (nodes are structurally heavier and demand naming/labeling decisions). Removing a node also costs 2. Lower total is "more minimal"; among ties, prefer fewer new *nodes* (less cognitive/model surface) and fewer changes to visible labels.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| **R1 — Give the waiver its own proper two-input synchronization** | Add arc `p_analysis_done → t_join_waived`. (Now `t_join_waived` consumes `p_analysis_done` **and** `p_waived` → `p_decision`.) No node changes. | +1 arc = **1** | Mandatory analysis retained on the waiver path; waiver stays a distinct outcome with its own join | On the waiver route, `t_authorize` can no longer fire until `t_analyze` has produced `p_analysis_done`; no residual token | `t_join_normal` and `t_join_waived` now both consume `p_analysis_done` (as a free choice after analysis+review), which is fine, but a reader must notice `p_analysis_done` feeds two joins |
| **R2 — Route the waiver into the normal synchronization** | Remove arc `t_waive_review → p_waived`; add arc `t_waive_review → p_review_done`. Then remove the now-dead waiver join: remove arcs `p_waived → t_join_waived` and `t_join_waived → p_decision`, remove transition `t_join_waived` and place `p_waived`. | remove 4 arcs? Net: −arc(`t_waive_review→p_waived`) +arc(`t_waive_review→p_review_done`) −arc(`p_waived→t_join_waived`) −arc(`t_join_waived→p_decision`) −place `p_waived` −transition `t_join_waived` = 4 arc edits + 2·2 node removals = **8** | Analysis remains mandatory (still synchronized at `t_join_normal`); one single AND-join for both outcomes | Both review outcomes converge on `p_review_done`; `t_join_normal` synchronizes analysis with *whichever* review completed | Waiver and standard review become indistinguishable at the token level *after* their transitions fire (they merge into `p_review_done`); the distinction survives only in the transition/log, not the marking |
| **R3 (policy change) — Make analysis optional under waiver** | Add a silent transition `t_skip_analysis` with input `p_analysis`, output `p_analysis_done`; **or** simply add arc `p_analysis → t_join_waived` and arc so waiver consumes the *pre-analysis* analysis token. Concretely: add arc `p_analysis → t_join_waived` (consuming the raw analysis token) so the waiver join clears both parallel tokens without requiring `t_analyze`. | +1 arc (variant) = **1**, or +1 transition +2 arcs = **4** for the explicit silent-skip variant | Proper completion restored (no leftover token) | **Business policy changes:** under a waiver, analysis is *not* performed — it is skipped/short-circuited. This must be stated explicitly and approved | Silently bypasses mandatory analysis; only acceptable if the business truly allows "waiver ⇒ no analysis". High governance risk |

**Distinctness.** R1 keeps analysis mandatory and keeps two joins (behaviorally: waiver route now blocks until analysis done). R2 keeps analysis mandatory but collapses to a single join and merges the two review outcomes into one place (behaviorally different: fewer nodes, marking-level indistinguishable outcomes). R3 is semantically opposite — it *removes* the mandatory-analysis obligation on the waiver path and is only admissible as a stated policy change.

**Minimality justification.** Under the cost model, **R1 (cost 1)** and the arc-only variant of **R3 (cost 1)** are the cheapest. They tie on raw cost but are **not** interchangeable: R1 preserves the business rule (analysis mandatory) while R3 changes it. When two repairs tie on cost, I break the tie by *intent preservation first*, so R1 is preferred; R3 remains the cheapest way to *intentionally* drop the obligation if the business wants that. R2 costs 8 because it deletes a transition and a place and rewires four arcs; it is more invasive but yields the "cleanest" single-join topology, which can be worth the cost for long-term model simplicity. So R1 is minimal-and-intent-preserving; R2 is a heavier structural simplification; R3 is minimal-but-policy-changing.

# 5. Corrected PM4Py Code

Selected repair: **R1** — add `p_analysis_done → t_join_waived` so the waiver path has a proper two-input synchronization and mandatory analysis is retained.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

# Places
source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in {
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
}:
    repaired_net.places.add(p)

# Transitions (visible labels preserved)
register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in {
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
}:
    repaired_net.transitions.add(t)

# Arcs
petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

# Normal join: analysis AND standard review
petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

# REPAIR (R1): waiver join is now a proper two-input synchronization.
# It consumes the waiver token AND the mandatory-analysis token.
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)  # <-- added arc
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

After R1, on the waiver route `t_join_waived` requires both `p_analysis_done` and `p_waived`, so authorization cannot occur before analysis, and no analysis token is orphaned.

# 6. Diagnostic and Reachability Code

```python
import pm4py

def fire(net, marking, transition_name):
    """Fire a named transition if enabled; otherwise report and do nothing.
    Checks enabledness rather than silently moving tokens."""
    enabled = pm4py.get_enabled_transitions(net, marking)
    target = next((t for t in enabled if t.name == transition_name), None)
    if target is None:
        names = sorted(t.name for t in enabled)
        print(f"  [BLOCKED] {transition_name} is NOT enabled. Enabled now: {names}")
        return marking
    new_marking = marking.copy()
    for a in target.in_arcs:
        new_marking[a.source] -= 1
        if new_marking[a.source] <= 0:
            del new_marking[a.source]
    for a in target.out_arcs:
        new_marking[a.target] += 1
    fired = sorted(f"{p.name}:{new_marking[p]}" for p in new_marking)
    print(f"  [FIRED]   {transition_name} -> {fired}")
    return new_marking

def run_sequence(net, im, seq, label):
    print(f"\n=== Firing sequence on {label} ===")
    m = im
    print("  start:", sorted(f"{p.name}:{m[p]}" for p in m))
    for tname in seq:
        m = fire(net, m, tname)
    return m

# --- Assumes original: net, im, fm ; repaired: repaired_net, repaired_im, repaired_fm ---

for label, (n, i, f) in {
    "ORIGINAL": (net, im, fm),
    "REPAIRED": (repaired_net, repaired_im, repaired_fm),
}.items():
    print(f"\n########## {label} ##########")
    print("is_workflow_net:", pm4py.check_is_workflow_net(n))
    print("soundness:")
    pm4py.check_soundness(n, i, f, print_diagnostics=True)
    print("enabled at initial marking:",
          sorted(t.name for t in pm4py.get_enabled_transitions(n, i)))
    rg = pm4py.convert_to_reachability_graph(n, i, f)
    print("reachability graph:",
          len(rg.states), "states,", len(rg.transitions), "transitions")

# Counterexample sequence that breaks the ORIGINAL net (waiver, authorize before analyze):
run_sequence(net, im,
             ["t_register", "t_split", "t_waive_review",
              "t_join_waived", "t_authorize"],
             "ORIGINAL (defect trace)")

# Same intent on the REPAIRED net: t_join_waived should now block until analysis is done.
run_sequence(repaired_net, repaired_im,
             ["t_register", "t_split", "t_waive_review",
              "t_join_waived"],  # expected [BLOCKED] here
             "REPAIRED (waiver join must wait for analysis)")

# A full, valid waiver trace on the REPAIRED net:
run_sequence(repaired_net, repaired_im,
             ["t_register", "t_split", "t_analyze", "t_waive_review",
              "t_join_waived", "t_authorize"],
             "REPAIRED (valid waiver trace)")
```

**Expected qualitative difference.** Both nets pass `check_is_workflow_net` (`True`). `check_soundness` should report the **original** as **not sound** (its diagnostics should flag improper completion / tokens remaining outside the final marking, reachable via the waiver route), while the **repaired** net should report **sound**. On the original, the defect sequence runs to completion and leaves `sink` marked together with a stranded `p_analysis`/`p_analysis_done` token; on the repaired net, `t_join_waived` is `[BLOCKED]` until `t_analyze` has fired, and the valid trace ends exactly at `fm`. I do not claim specific reachability-graph sizes; the printed `len(rg.states)`/`len(rg.transitions)` are whatever PM4Py derives at runtime, and I only assert the repaired graph should contain no reachable "token-in-sink-with-leftover" deadlock state that the original contains.

# 7. Repair Trade-Offs and Residual Risks

- **Waiver vs. standard review distinguishability.** Under **R1** they remain fully distinguishable: waiver flows through `t_waive_review → p_waived → t_join_waived`, standard review through `t_standard_review → p_review_done → t_join_normal`. The two joins and the two intermediate places are preserved, so both the marking and the event log distinguish the outcomes. (Under the alternative R2 the outcomes would merge into `p_review_done` and become marking-indistinguishable, distinguishable only by which transition fired in the log.)

- **Duplicate behavior / silent transitions.** R1 adds no silent transition, only one arc, so it introduces no duplicate or hidden behavior. The two silent joins (`t_join_normal`, `t_join_waived`) already existed; R1 does not increase the number of τ-transitions, so it cannot introduce new "invisible" confusion. (R3's silent-skip variant would introduce exactly such a risk and must be scrutinized.)

- **Soundness is necessary, not sufficient.** A `sound` verdict only guarantees option-to-complete, proper completion, and no dead transitions. It does **not** prove the model matches the business rule. For instance, R3 can also be made sound while *violating* the mandatory-analysis policy. So passing `check_soundness` must be paired with policy conformance checks.

- **Regression traces to test.**
  - *Positive (should complete at `fm`):* `t_register, t_split, t_analyze, t_standard_review, t_join_normal, t_authorize`; and `t_register, t_split, t_analyze, t_waive_review, t_join_waived, t_authorize` (plus the interleaving where analysis and review fire in the opposite order).
  - *Negative (should NOT be able to authorize / should block):* on the repaired net, `... t_waive_review, t_join_waived` before any `t_analyze` must be blocked; authorizing without analysis must be impossible.

- **Detecting accidental bypass of mandatory analysis.** Assert that every join transition producing `p_decision` has `p_analysis_done` in its preset (a static check on `t.in_arcs`). Behaviorally, verify no reachable marking has `p_decision` or `sink` marked while `p_analysis`/`p_analysis_done` is also marked — i.e., check the reachability graph for any state where `sink` is marked and total token count > 1. Any such state signals a bypass.

# 8. Final Recommendation

**Deploy R1** (add the single arc `p_analysis_done → t_join_waived`). It is the minimal intent-preserving repair (edit cost 1), it keeps analysis mandatory on both review outcomes, it keeps waiver and standard review clearly distinct, it introduces no new nodes or silent transitions, and it leaves all visible labels untouched. The behavioral change is exactly the intended one: the waiver path now blocks until analysis is complete and then synchronizes both tokens, so no residual token can remain and the net becomes sound. Its only "cost" is that a reader must notice `p_analysis_done` now feeds two joins — a small, documentable point.

**Fallback: R2** (route the waiver into `p_review_done` and delete `t_join_waived`/`p_waived`, cost 8). Choose it when the team prefers a single, uniform AND-join and is willing to accept that the two review outcomes become marking-indistinguishable (still separable in the log). R2 yields a simpler topology at the price of more edits and reduced token-level distinguishability, which is why it is the fallback rather than the primary choice.

I would **not** deploy R3 unless the business explicitly decides that a waiver removes the analysis obligation; despite its low edit cost, it changes policy and risks silently bypassing mandatory analysis, so it is out of scope for a behavior-preserving fix.
