April-May is a baseline, not proof that the later operating process failed. The 4.2 release creates a deterministic label mismatch: the same business action is emitted as `Risk Screen`, so the old model requires a visible `Classify` move. The gateway then inserts `Queue Routed`, an event outside the business control flow. These mechanisms explain the large staged recovery from 32% to 81% without requiring any person to have skipped work. The ETL change can independently place `Notify` before `Decision`; source-order recovery and screenshots make this a likely additional source of moves.

From August, a real policy and process change creates a different model-governance problem. Sign-off is observed in 210 traces, and the old model has no place for it. An optional control-flow extension improves fitness, but it is only an approximation: it permits sign-off for every case and omission for high-value cases. Finally, missing `Compliance Check` events may be capture loss or genuine bypass. `Manual Override` is similarly a real action whose business meaning is not yet modeled.

Stable cycle time, approval rate, and appeal rate make a broad operational collapse less likely, but they do not identify event semantics. They neither prove data error nor exonerate reviewers: a small, high-value, or remediated bypass may not alter coarse, lagged outcomes, and appeals are not a complete incident detector. Measured fitness is therefore a joint function of process, model, labels, capture, and ordering—not a direct compliance rate.

# 2. Expand variant counts into XES strings, then parse with PM4Py

def xes_from_variants(period_name, variant_counts):
    """
    Build a minimal XES document and parse it through pm4py.parse_event_log_string.

    source_seq is only the listed event ordinal because the real source sequence
    is absent from the supplied aggregate tables. In production, hydrate this
    attribute from the source system rather than constructing it here.
    """
    lines = [
        '<?xml version="1.0" encoding="UTF-8" ?>',
        '<log xes.version="1.0" xes.features="nested-attributes" '
        'xmlns="http://www.xes-standard.org/">',
    ]

    case_no = 0
    for trace_string, frequency in variant_counts:
        activities = [x.strip() for x in trace_string.split(",")]
        for _ in range(frequency):
            case_no += 1
            case_id = f"{period_name}-{case_no:05d}"
            lines.append("<trace>")
            lines.append(
                f'<string key="concept:name" value="{html.escape(case_id, quote=True)}"/>'
            )
            for position, activity in enumerate(activities, start=1):
                lines.append("<event>")
                lines.append(
                    f'<string key="concept:name" value="{html.escape(activity, quote=True)}"/>'
                )
                # Placeholder only. Replace with actual source-system sequence.
                lines.append(f'<int key="source_seq" value="{position}"/>')
                lines.append("</event>")
            lines.append("</trace>")

    lines.append("</log>")
    return pm4py.parse_event_log_string("\n".join(lines))

def normalize_log(
    log,
    map_risk_screen=True,
    remove_queue_routed=False,
    order_by_source_sequence=False,
):
    """
    Copy an EventLog while applying explicit, auditable transformations.
    Do not remove Manual Override: its business semantics are unresolved.
    """
    normalized = EventLog()
    normalized.attributes.update(dict(getattr(log, "attributes", {})))

    for old_trace in log:
        new_trace = Trace()
        new_trace.attributes.update(dict(getattr(old_trace, "attributes", {})))
        events = []

        for old_event in old_trace:
            event = Event(dict(old_event))
            activity = event.get("concept:name")

            if map_risk_screen and activity == "Risk Screen":
                event["concept:name"] = "Classify"

            if remove_queue_routed and event.get("concept:name") == "Queue Routed":
                continue

            events.append(event)

        if order_by_source_sequence:
            # Valid only when source_seq was truly supplied by the source system.
            events.sort(key=lambda e: int(e.get("source_seq", 10**12)))

        for event in events:
            new_trace.append(event)
        normalized.append(new_trace)

    return normalized

def show_dfg(name, log, top_n=12):
    dfg = pm4py.discover_dfg(log)
    print(f"\n{name}: {len(log)} cases; top frequency DFG edges")
    for edge, count in sorted(dfg.items(), key=lambda kv: (-kv[1], kv[0]))[:top_n]:
        print(f"  {edge}: {count}")
    return dfg


def is_skip(move):
    """Robustly identify PM4Py's >> skip marker in common alignment formats."""
    if move is None or move == ">>":
        return True
    if isinstance(move, tuple):
        return all(x is None or x == ">>" for x in move)
    return False


def printable_move(move):
    if isinstance(move, tuple):
        visible = [str(x) for x in move if x is not None and x != ">>"]
        return visible[-1] if visible else "tau"
    return str(move)


def fitness_percentage(fitness_result, alignments):
    # PM4Py versions use slightly different key names.
    for key in ("percentage_of_fitting_traces", "percFitTraces"):
        if key in fitness_result:
            return fitness_result[key]
    if not alignments:
        return 0.0
    return 100.0 * sum(a.get("cost", 1) == 0 for a in alignments) / len(alignments)


def alignment_report(name, log, net, initial_marking, final_marking):
    alignments = pm4py.conformance_diagnostics_alignments(
        log, net, initial_marking, final_marking
    )
    fitness = pm4py.fitness_alignments(log, net, initial_marking, final_marking)

    costs = [float(a.get("cost", 0.0)) for a in alignments]
    log_moves = Counter()
    model_moves = Counter()

    for result in alignments:
        for pair in result.get("alignment", []):
            if len(pair) != 2:
                continue
            log_move, model_move = pair
            if not is_skip(log_move) and is_skip(model_move):
                log_moves[printable_move(log_move)] += 1
            elif is_skip(log_move) and not is_skip(model_move):
                model_moves[printable_move(model_move)] += 1

    print(f"\n{name}")
    print(f"  fitting traces %: {fitness_percentage(fitness, alignments):.2f}")
    print(f"  mean alignment cost: {mean(costs):.4f}")
    print(f"  PM4Py fitness dictionary: {fitness}")
    print(f"  dominant moves on log: {log_moves.most_common(6)}")
    print(f"  dominant visible moves on model: {model_moves.most_common(6)}")

    return {
        "alignments": alignments,
        "fitness": fitness,
        "mean_cost": mean(costs),
        "log_moves": log_moves,
        "model_moves": model_moves,
    }

## 7. Provisional conclusion

**Primary explanation for the measured conformance collapse — high confidence (about 90%).** The June-July collapse is predominantly a measurement and model-interface problem, not demonstrated operational deterioration. Three staged interventions explain most of it: mapping `Risk Screen` to `Classify`, removing the gateway-produced `Queue Routed` event, and using source sequence rather than warehouse-ingestion order. The observed recovery from 32% fitting to 89% after these steps is strong abductive evidence because each intervention removes a distinct, date-aligned source of artificial alignment moves. The initial raw fitness should therefore not be presented as a compliance rate or evidence that employees broadly stopped following the process.

**Residual real compliance concern — moderate confidence (about 45%).** There are two legitimate issues that remain after normalization. First, the August policy introduced a real sign-off requirement that the normative model lacks. Sign-off-related deviations are expected model obsolescence, but an optional-sign-off model is not policy-complete because it ignores the EUR 50,000 condition. Second, enhanced-review cases without a recorded `Compliance Check` remain unresolved. They could be genuine bypasses, omitted upstream events, or alternate documented controls. The current record cannot distinguish these explanations.

Immediate actions should be split by owner. **IT** should freeze and version the event contract, identify technical producers, retain source event time and source sequence, reconcile extraction populations, and repair missing resource capture. **Process owners** should version the policy model effective 2026-08-01 and define an auditable exception/override path. **Compliance** should conduct a blinded, source-complete audit of missing-check cases and test sign-off compliance using the high-value attribute.

It must not yet be claimed that employees caused the conformance collapse, that all `Compliance Check` omissions are violations, that sign-off was correctly applied only to high-value cases, or that stable appeals prove the process is compliant. Nor should the optional-sign-off model be adopted as the final policy model without a data-aware control.

## 8. Model-governance recommendation

1. Version every normative model with an owner, policy source, effective date, retirement date, and explicit linkage to the software and event-schema versions against which it was validated.

2. Maintain an event-semantic contract for every activity label: business meaning, producer system, lifecycle state, resource semantics, case-correlation rule, whether it is human or automated, and approved predecessor/successor interpretation.

3. Classify technical events separately from business-control events, require producer metadata for them, and prohibit automatic deletion from conformance logs unless an approved technical-event policy documents the rationale.

4. Preserve source event time, source sequence, gateway receipt time, and warehouse ingestion time as distinct attributes; define one ordering rule for each analytic purpose and continuously test for reorder rates.

5. Use data-aware compliance controls for conditions such as EUR 50,000 thresholds, authorization, channel, and jurisdiction; do not rely on a control-flow-only model to represent attribute-dependent policy obligations.

6. Require post-release validation after UI, gateway, ETL, or policy changes: compare variants, frequency DFGs, alignment moves, fitness, precision, attribute-stratified results, and a targeted provenance audit before publishing conformance trends.
