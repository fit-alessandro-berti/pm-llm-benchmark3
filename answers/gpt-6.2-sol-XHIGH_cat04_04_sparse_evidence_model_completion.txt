# 1. Evidence Ledger

For compact traces, **R** = Register Order, **C** = Credit Check, **E** = Engineering Review, **S** = Supplier Confirmation, **X** = Expedite Review, **A** = Approve Configuration, **P** = Release Production, and **Z** = Archive Case. Each row shows a complete case in recorded completion order.

A DFG pools adjacent pairs across cases. Opposite arcs can arise from different sequential routes, actual overlap with different finish orders, or the tie-breaking rule. Even adjacency in a particular case only identifies successive log entries. Reading reciprocal arcs as concurrency, or traversing arbitrary paths through the DFG as if they were valid cases, would introduce unsupported behavior.

# 2. Shared Assumptions

- Each supplied trace represents the recorded completions of one production order. The log order, including the ingestion tie-break, is the order modeled. Ordering and interleaving claims refer to that representation.
- The models assume one occurrence each of R, C, E, A, P, and Z. R starts the trace, both checks finish before A, and A → P → Z is a fixed tail. Each model allows at most one recorded S and at most one recorded X, both before A. Retries, repeated component-level confirmations, and post-approval amendments are outside these candidates.
- Seven cases lack a recorded S. An absent S could be a legitimate stock skip, integration loss, or a process deviation. S5's estimated event-loss percentage cannot classify the seven cases or separate those causes. The missing external/stocked attribute prevents enforcement of S3's per-case requirement from this log alone.
- Optionality models the **observable** projection. The conservative model gives distinct XOR variants for recorded absence. The balanced and permissive models use XOR choices that select a branch without the event or take a silent transition `τ`. None of these choices assigns a cause to an absent event.
- In the expressions, `·` denotes sequence, `XOR` chooses one alternative, `∥` permits interleavings while preserving internal order, `?` abbreviates `XOR(τ, activity)`, and `≺` denotes required completion precedence in a partial order.

# 3. Conservative Candidate

Treat each of the seven observed variants as a supported route and share the common start and tail. The model is an exact baseline for recorded behavior. It preserves rare observations without extrapolating new combinations from them, and it deliberately leaves the check scheduling and the reason for each skip unidentified.

`R · XOR(C·E·S, E·C·S, C·E, E·C, C·S·E, C·E·S·X, E·C·X·S) · A · P · Z`

```python
import pm4py

labels = {
    "C": "Credit Check",
    "E": "Engineering Review",
    "S": "Supplier Confirmation",
    "X": "Expedite Review",
}
cores = ("C E S", "E C S", "C E", "E C", "C S E", "C E S X", "E C X S")
branches = ", ".join(
    "->(" + ", ".join(repr(labels[symbol]) for symbol in core.split()) + ")"
    for core in cores
)
model_conservative = pm4py.parse_process_tree(
    f"->('Register Order', X({branches}), "
    "'Approve Configuration', 'Release Production', 'Archive Case')"
)
```

**Deliberately excluded**

- All unseen complete traces, including reversing the X/S order within either observed expedite check order and adding X to the early-S variant.
- Missing required core activities, repeated events, and deviations from the fixed start or tail.

**Known underfitting risks**

- A policy-compliant order that is absent from a 30-case sample is rejected. Losing S from either recorded expedite trace also creates a rejected trace.
- Each branch has its own leaves. The same label therefore occurs on different transitions in the converted net, which can make prefix-level replay and diagnosis ambiguous. Branch count grows with variant count, potentially combinatorially when several activities can be interleaved. The model overfits the sample and consequently under-represents plausible process behavior.

# 4. Balanced Candidate

Make C and E incomparable in both branches because both orders occur and lifecycle data cannot adjudicate S1 and S2. A total sequence would discard supported behavior. With S present, use a partial order: C precedes S because all 23 recorded S events follow C, and E remains unordered relative to S because both E/S orders are observed. Treat C ≺ S as a provisional constraint on completions. Sequence optional X after both checks, per D6 and S6, and leave X unordered relative to S because both relative orders are observed. Keep X within the S-present branch because its two observations both include S. This last choice limits extrapolation from rare cases and is a weak empirical assumption about the recorded trace. Conversely, admitting both C/E orders across both branches may overgeneralize if a missing case attribute determines a fixed order.

`R · XOR(PO({C,E}, ∅), PO({C,E,S,X?}, {C≺S, C≺X?, E≺X?})) · A · P · Z`

Here `PO(nodes, edges)` specifies a strict partial order over the listed nodes. When X is present, it must follow both checks. The silent X alternative emits no event. The entire selected branch completes before A.

```python
from itertools import combinations

from pm4py.objects.powl.obj import (
    OperatorPOWL,
    SilentTransition,
    StrictPartialOrder,
    Transition,
)
from pm4py.objects.process_tree.obj import Operator

no_supplier = StrictPartialOrder([
    Transition("Credit Check"),
    Transition("Engineering Review"),
])
credit = Transition("Credit Check")
engineering = Transition("Engineering Review")
supplier = Transition("Supplier Confirmation")
expedite = OperatorPOWL(Operator.XOR, [
    SilentTransition(),
    Transition("Expedite Review"),
])
with_supplier = StrictPartialOrder([credit, engineering, supplier, expedite])
for source, target in [(credit, supplier), (credit, expedite), (engineering, expedite)]:
    with_supplier.order.add_edge(source, target)

routing = OperatorPOWL(Operator.XOR, [no_supplier, with_supplier])
stages = [
    Transition("Register Order"),
    routing,
    Transition("Approve Configuration"),
    Transition("Release Production"),
    Transition("Archive Case"),
]
model_balanced = StrictPartialOrder(stages)
for source, target in combinations(stages, 2):
    model_balanced.order.add_edge(source, target)
```

**Deliberately excluded**

- S before C even when E has already completed.
- X in a trace with no recorded S, X before both checks complete, and X after A.
- Omission or repetition of core activities and repetition of S or X.

**Known underfitting risks**

- Some cases may legitimately use E alone to make S ready while C is outstanding. The observed absence of that ordering provides limited coverage of a potentially rare route.
- Legitimate expedites for stocked orders and expedites with a lost S record would be rejected. Two co-occurrences offer weak evidence for imposing this restriction.

# 5. Permissive Candidate

Treat either principal check as a possible precursor for S, using the first recorded check completion as a proxy for the readiness in D5. Allow S and X to be independently optional in the recorded trace. This makes room for X on a legitimate stock skip or after losing an S record. After the first check, S can interleave with the second check and its optional X successor. The two branches partition traces by first check completion. The added paths can overgeneralize if engineering alone cannot supply the relevant information or stocked orders are ineligible for X. Case-level authorization for an external order to skip S remains a separate business question.

`R · XOR(C · (S? ∥ (E · X?)), E · (S? ∥ (C · X?))) · A · P · Z`

```python
import pm4py

def after_first_check(first, second):
    supplier = "X(tau, 'Supplier Confirmation')"
    expedite = "X(tau, 'Expedite Review')"
    return f"->({first!r}, +({supplier}, ->({second!r}, {expedite})))"

credit_first = after_first_check("Credit Check", "Engineering Review")
engineering_first = after_first_check("Engineering Review", "Credit Check")
model_permissive = pm4py.parse_process_tree(
    f"->('Register Order', X({credit_first}, {engineering_first}), "
    "'Approve Configuration', 'Release Production', 'Archive Case')"
)
```

**Deliberately excluded**

- S before any check completes. This is the chosen observable boundary for relaxing the supplier prerequisite.
- X before the second check completes, any S or X after A, approval with a principal check outstanding, and release before approval.
- Missing core activities, repeated activities, and changes to the fixed endpoints and tail.

**Known underfitting risks**

- D5 speaks of sufficient information, which could be available before either check completes. Genuine early S completions of this kind would be rejected by the readiness proxy.
- Real work may include rechecks, component-level repeats, or approvals amended before release. The shared single-occurrence assumption excludes such behavior.

# 8. Validation Code

This script reconstructs the three models so it can be run independently. Bounded playout enumerates visible traces reaching the exact final marking, following silent firings without adding events. Eight visible completions suffice for these loop-free candidates, each with six required and at most two optional completions. The enumeration is exhaustive here because the converted nets have finite reachable markings and the visible cap covers their full languages. For a model with unbounded visible behavior, this procedure can only compare the explored slice if the exploration terminates. A sampled playout would provide examples and would not prove language inclusion. The trace suite gives expected membership in conservative, balanced, and permissive order. In a local run, all three nets passed the soundness check, accepted all 30 recorded cases, and passed all 17 trace checks. Their complete visible languages contained 7, 10, and 14 traces, respectively.

```python
from collections import deque
from itertools import combinations

import pm4py
from pm4py.objects.petri_net import semantics
from pm4py.objects.powl.obj import (
    OperatorPOWL,
    SilentTransition,
    StrictPartialOrder,
    Transition,
)
from pm4py.objects.process_tree.obj import Operator

labels = dict(
    R="Register Order",
    C="Credit Check",
    E="Engineering Review",
    S="Supplier Confirmation",
    X="Expedite Review",
    A="Approve Configuration",
    P="Release Production",
    Z="Archive Case",
)
variants = [
    (12, "C E S"),
    (7, "E C S"),
    (4, "C E"),
    (3, "E C"),
    (2, "C S E"),
    (1, "C E S X"),
    (1, "E C X S"),
]

def expand(trace):
    return tuple(labels[symbol] for symbol in trace.split())

recorded_strings = [
    ",".join(expand(f"R {middle} A P Z"))
    for count, middle in variants
    for _ in range(count)
]
log = pm4py.convert_to_event_log(pm4py.parse_event_log_string(recorded_strings))
assert len(log) == 30
observed = {tuple(event["concept:name"] for event in case) for case in log}
assert len(observed) == 7

def wrapped_tree(middle):
    return pm4py.parse_process_tree(
        f"->({labels['R']!r}, {middle}, {labels['A']!r}, "
        f"{labels['P']!r}, {labels['Z']!r})"
    )

branches = ", ".join(
    "->(" + ", ".join(map(repr, expand(middle))) + ")"
    for _, middle in variants
)
model_conservative = wrapped_tree(f"X({branches})")

no_supplier = StrictPartialOrder([Transition(labels["C"]), Transition(labels["E"])])
credit = Transition(labels["C"])
engineering = Transition(labels["E"])
supplier = Transition(labels["S"])
expedite = OperatorPOWL(Operator.XOR, [SilentTransition(), Transition(labels["X"])])
with_supplier = StrictPartialOrder([credit, engineering, supplier, expedite])
for source, target in [(credit, supplier), (credit, expedite), (engineering, expedite)]:
    with_supplier.order.add_edge(source, target)
routing = OperatorPOWL(Operator.XOR, [no_supplier, with_supplier])
stages = [
    Transition(labels["R"]),
    routing,
    Transition(labels["A"]),
    Transition(labels["P"]),
    Transition(labels["Z"]),
]
model_balanced = StrictPartialOrder(stages)
for source, target in combinations(stages, 2):
    model_balanced.order.add_edge(source, target)

def after_first_check(first, second):
    supplier = f"X(tau, {labels['S']!r})"
    expedite = f"X(tau, {labels['X']!r})"
    return f"->({labels[first]!r}, +({supplier}, ->({labels[second]!r}, {expedite})))"

credit_first = after_first_check("C", "E")
engineering_first = after_first_check("E", "C")
model_permissive = wrapped_tree(f"X({credit_first}, {engineering_first})")

models = {
    "conservative": model_conservative,
    "balanced": model_balanced,
    "permissive": model_permissive,
}

def bounded_playout(net, initial, final, max_visible):
    start = (initial, ())
    pending = deque([start])
    visited = {start}
    accepted = set()
    while pending:
        marking, trace = pending.popleft()
        if marking == final:
            accepted.add(trace)
        for transition in semantics.enabled_transitions(net, marking):
            if transition.label is None:
                extension = trace
            elif len(trace) < max_visible:
                extension = trace + (transition.label,)
            else:
                continue
            next_marking = semantics.execute(transition, net, marking)
            state = (next_marking, extension)
            if state not in visited:
                visited.add(state)
                pending.append(state)
    return accepted

languages = {}
for name, model in models.items():
    net, initial, final = pm4py.convert_to_petri_net(model)
    sound, diagnostics = pm4py.check_soundness(net, initial, final, print_diagnostics=False)
    print(name, "soundness", sound)
    assert sound, (name, diagnostics)

    reports = {
        "fitness": pm4py.fitness_alignments(log, net, initial, final),
        "precision": pm4py.precision_alignments(log, net, initial, final),
        "generalization": pm4py.generalization_tbr(log, net, initial, final),
        "simplicity": pm4py.simplicity_petri_net(net, initial, final),
    }
    print(name, reports)
    languages[name] = bounded_playout(net, initial, final, max_visible=8)
    assert observed <= languages[name], (name, observed - languages[name])
    print(name, "accepted traces", len(languages[name]))
    print(name, "unobserved traces", sorted(languages[name] - observed))

suite = [
    ("R C E S A P Z",   (True, True, True)),
    ("R C S E A P Z",   (True, True, True)),
    ("R E C A P Z",     (True, True, True)),
    ("R E C X S A P Z", (True, True, True)),
    ("R C E X S A P Z", (False, True, True)),
    ("R C S E X A P Z", (False, True, True)),
    ("R E C S X A P Z", (False, True, True)),
    ("R E S C A P Z",   (False, False, True)),
    ("R E S C X A P Z", (False, False, True)),
    ("R C E X A P Z",   (False, False, True)),
    ("R E C X A P Z",   (False, False, True)),
    ("R S C E A P Z",   (False, False, False)),
    ("R C X E S A P Z", (False, False, False)),
    ("R C S A P Z",     (False, False, False)),
    ("R C E S P A Z",   (False, False, False)),
    ("R C S E S A P Z", (False, False, False)),
    ("R C E X X A P Z", (False, False, False)),
]
for trace, expected in suite:
    actual = tuple(expand(trace) in language for language in languages.values())
    assert actual == expected, (trace, expected, actual)

assert languages["conservative"] == observed
assert languages["conservative"] < languages["balanced"] < languages["permissive"]
assert tuple(map(len, languages.values())) == (7, 10, 14)
print(f"Passed all {len(suite)} trace checks.")
```

# 9. Recommendation and Data-Collection Plan

Use **`model_balanced`** for immediate conformance monitoring. Send deviations involving S before C or X without S for case review because those restrictions are provisional. Use **`model_permissive`** for sensitivity analysis and track which rejected traces become explainable when either check can enable S and X can occur without a recorded S. Treat the conservative model as a historical coverage baseline.

1. **Capture lifecycle and ordering evidence.** Record activity-instance IDs, order IDs, start and completion timestamps for C, E, S, and X, the source system, timestamp precision and timezone, and ingestion timestamps and sequence IDs. Record the event or status that made supplier work eligible. Compare lifecycle intervals on synchronized clocks. Overlap requires the later start to precede the earlier finish. An E start before C finishes directly challenges universal S1 for an in-scope case. Stratify by policy version, team, and routing rule to distinguish parallel work from an XOR choice of sequential routes. Documented routing with nonoverlapping opposite orders across cohorts supports sequential alternatives. Overlap within a cohort discriminates against both strict sequences. Since all 30 cases contain both checks, an XOR that performs only one check already conflicts with the recorded variants.
2. **Recover component attributes and ground truth for S.** Join each order and component ID to its external/stocked status, confirmation-required flag and reason, and supplier-system event ID and lifecycle record. Reconcile source events with exported events, including retries and late arrivals. A stocked order with a documented no-S disposition supports a legitimate skip. An external order with a source confirmation missing from the export identifies event loss. An external order with approval and no corroborating confirmation calls for investigation against S3. Estimate loss among source confirmations and stratify by integration and period.
3. **Prioritize traces that distinguish the candidates.** A verified `R C E X S A P Z` distinguishes the fixed variant enumeration from both generalizing models. A verified `R E S C A P Z` with an engineering readiness signal distinguishes the either-check prerequisite from the balanced C gate. A genuinely stocked `R C E X A P Z` with documented expedite authorization distinguishes independent optionality from the balanced co-occurrence restriction. The same trace with a source S event would diagnose logging loss instead. For check order, seek matched cases under the same routing policy with C-first and E-first completions and reliable start times. Their intervals can separate physical overlap from different realized sequential orders.
4. **Validate prospectively.** Hold out subsequent cases by time and report conformance separately by sourcing type, routing, and data quality. Review discrepancies with Finance, Engineering, Procurement, and Compliance before promoting a provisional restriction to an enforcement rule. Reassess the two balanced restrictions using the adjudicated exceptions and eligible case counts.

# 10. Uncertainty Statement

| Modeling decision | Confidence and basis |
|---|---|
| Fixed R start, Z end, and A before P | High. Domain intent and every observed trace agree. The fixed tail also assumes no intervening modeled activity. |
| Both C and E before A | Medium to high. D3 and all 30 traces support it. Confidence in precisely one completion each is lower because the sample does not characterize rework. |
| Both C/E completion orders and their relation to execution | High that both orders occur in the log. Moderate that both are permissible for a single case type. Physical overlap remains undetermined. |
| S before A when S occurs | Medium to high for the modeled completions, given D4 and all 23 S records. |
