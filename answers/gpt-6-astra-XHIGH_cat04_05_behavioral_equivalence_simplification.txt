# 1. Equivalence Notions

Use the following abbreviations for visible, atomic events:

| Symbol | Label |
|---|---|
| `o` | Open Case |
| `a` | Analyze Revision |
| `c` | Check Revision |
| `p` | Approve Revision |
| `r` | Rework Case |
| `f` | Close Case |

Let (L(M)) be the set of finite, complete visible traces of model (M). A complete execution reaches the accepting final marking; a prefix that can still execute is not automatically a complete trace. Every `tau` occurrence is erased, contributing the empty word ε. Concurrency permits all interleavings consistent with the tree's ordering constraints. No event durations, resource assignments, or probabilities are assumed.

A trace is a tuple of **labels in occurrence order**. Repeated labels occupy separate positions and retain their multiplicity. Transition identities and persistent event identities are not observed. Thus two executions differing only in the identities of equally labeled transitions can yield the same trace, but `a c r a c` and `a c r a` are different traces.

- **Visible trace equivalence:** (M \equiv_{\mathrm{vis}} N) exactly when (L(M)=L(N)), after hiding `tau` and retaining every visible label, including `p`.
- **P3 bounded visible-language equivalence:** define
  \[
  L_{12,3}(M)=\{t\in L(M): |t|\leq12\ \land\ \#_a(t)\leq3\}.
  \]
  The models are equivalent under P3 exactly when these sets are equal. Bounds count visible occurrences, including approvals; silent transitions consume neither bound. This compares sets, not execution frequencies.
- **P1 business-relevant equivalence:** split the interior of each complete trace at `r`, obtaining one revision segment per analysis attempt. The operational observation retains the ordered visible word in every segment, including approval positions, and the opening, revision boundaries, and closing. Two models are equivalent when their sets of these observations coincide. This is a deliberately detailed operational observation, equivalent to visible trace observation for these trees. Compliance additionally requires each segment containing an analysis to contain its own check before the segment ends. A check may precede its analysis within that segment: P1 does not require analysis-before-check, and A explicitly allows both orders. Checks cannot cover analyses in other segments. Merely sharing a compliance verdict would be weaker than behavioral equivalence.
- **P2 abstracted dashboard equivalence:** for a complete trace with exactly one opening first and one closing last, define
  \[
  \Phi(t)=(o,\ \#_a(t),\ \mathbf1_{\#_c(t)>0},\ \mathbf1_{\#_r(t)>0},\ f).
  \]
  Traces violating the boundary requirement receive a separate invalid-boundary observation. All traces considered below satisfy it. The dashboard hides approvals and silent behavior, replaces check multiplicity by a Boolean, and retains no internal event positions beyond the stated fields. In particular, it does not identify which revision received a check. P2 equivalence means equality of the sets of dashboard records, (\Phi(L(M))=\Phi(L(N))), not equality of distributions over those records.

# 2. Structural Comparison

Let (n\geq1) be the number of analysis attempts and (0\leq k\leq n) the number of approvals.

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | Repeats `(a parallel c)` followed by optional `p`; redo child is `r` | Repeats `a` followed by optional `p`; redo child is `r`; `c` is outside the loop | Only A creates a fresh check obligation for every attempt |
| Minimum and maximum Check Revision occurrences | Exactly (n); minimum 1, no finite maximum | Exactly 1 in every complete trace | Check multiplicities differ whenever (n\geq2) |
| Possible placement of Check Revision | Before or after its local `a`, but before local `p`, if present, and before the next `r` or `f` | Anywhere among the loop's visible events, including before its first `a`, between attempts, or after its last `p` | B can rework or approve while its single check is still pending |
| Optional approval occurrences | Zero or one per attempt, after both local `a` and `c` | Zero or one per attempt, after local `a`; no ordering constraint against the global `c` | Both allow (0\ldots n) approvals, but their possible positions differ |
| Concurrency | A separate `a`/`c` parallel block in each iteration | One `c` branch concurrent with the entire loop, including analyses, approvals, and reworks | Equal activity sets conceal different synchronization constraints |
| Join before Close Case | Each local parallel block joins before its optional approval; the loop then exits before `f` | The outer parallel block joins only after both the loop and the single check finish | Both require a check before closing, but only A requires one in every revision segment |

The complete languages can be characterized exactly. Concatenation is implicit, `?` means optional, and `shuffle` denotes all order-preserving interleavings:

\[
L(A)=o\,((ac\mid ca)p?)\,(r((ac\mid ca)p?))^*\,f,
\]
\[
L(B)=\{o\,w\,f:w\in\operatorname{shuffle}(c,\ ap?(rap?)^*)\}.
\]

Both have exactly (n-1) reworks. Their visible lengths are

\[
|t_A|=3n+1+k,\qquad |t_B|=2n+2+k.
\]

Both converted nets are sound. Soundness concerns proper completion and absence of dead tasks; it does not establish equivalence or require every possible infinite loop execution to terminate. The comparison here concerns finite complete executions.

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 operational compliance | not equivalent | High: direct language and revision-segment arguments | A supplies one check in every segment. B has only one check and therefore misses at least (n-1) segments when (n\geq2). Approval ordering also differs | Even B's single-attempt traces can differ from A while satisfying the check-before-close requirement |
| P2 executive dashboard | equivalent only under stated abstraction | High: proof for every finite (n\geq1) | Both produce exactly the records ((o,n,\mathrm{true},[n>1],f)) | This discards check-to-revision association, approval behavior, and internal timing; it claims no probability equivalence |
| P3 bounded testing | not equivalent | High: exhaustive bounded exploration, corroborated by exact counting | A has 76 bounded traces, B has 85, and only 4 are common | Disagreement already disproves unbounded visible equivalence; bounded agreement would not prove it |

For the P2 proof, every complete execution of either model has (n\geq1), at least one check, and exactly (n-1) reworks. Conversely, each integer (n\geq1) is realizable by taking exactly (n-1) redo branches. Hence

\[
\Phi(L(A))=\Phi(L(B))
=\{(o,n,\mathrm{true},[n>1],f):n\geq1\}.
\]

# 4. Counterexample Traces

Every row below is a complete visible trace, using the label abbreviations from Section 1. All four satisfy the P3 bounds.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| A1 | `o a c r a c f` | Admitted | Rejected | The second `c` is required by A's second iteration, but B has already consumed its only check | P1 and P3; erased by P2 |
| A2 | `o c a p r c a p f` | Admitted | Rejected | The second `c` has no available occurrence in B; A permits `c a p` in both iterations | P1 and P3; erased by P2 |
| B1 | `o a r a c f` | Rejected | Admitted | The first `r` occurs before the first segment has received any check; A cannot leave that segment yet | P1 and P3; erased by P2 |
| B2 | `o a p c f` | Rejected | Admitted | `p` occurs while the check is still pending; A's local parallel join must complete before `p` | P1 approval observation and P3; erased by P2 |

A1 and A2 have two analyses and two checks. B1 has two analyses but only one check, placed in its second segment. B2 has one analysis; it satisfies P1's check-before-close predicate but exhibits a different visible approval position. This illustrates why compliance alone is not the chosen operational equivalence test.

In fact, the unbounded language intersection is exactly

\[
L(A)\cap L(B)=\{oacf,\ ocaf,\ oacpf,\ ocapf\}.
\]

A common trace must have one check, forcing A to have (n=1). A then has precisely the four words listed, all admitted by B. B has one further single-attempt word, `o a p c f`. For (n\geq2), check counts make the languages disjoint. Thus neither unbounded language includes the other.

Optional approval means each iteration independently chooses `p` or `tau`. Hiding `tau` permits the no-approval witnesses A1 and B1; it never hides a check or makes multiple checks into one. Even additionally hiding all approvals would leave the multi-attempt counterexamples intact. P2 succeeds because it applies the additional Boolean and case-summary abstraction, not merely because it hides approvals.

# 5. Bounded Comparison Code

The following is self-contained Python for the requested PM4Py comparison. It performs **exhaustive bounded exploration**, not random or heuristic playout. It was executed with PM4Py 2.7.23.8 and produced the counts below.

```python
from collections import deque
import pm4py
from pm4py.objects.petri_net import semantics

A_TEXT = """
->(
  'Open Case',
  *(
    ->(
      +('Analyze Revision', 'Check Revision'),
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
"""

B_TEXT = """
->(
  'Open Case',
  +(
    'Check Revision',
    *(
      ->('Analyze Revision', X('Approve Revision', tau)),
      'Rework Case'
    )
  ),
  'Close Case'
)
"""

MAX_VISIBLE = 12
MAX_ANALYSES = 3
ANALYZE = "Analyze Revision"


def bounded_visible_language(net, im, fm,
                             max_visible=12, max_analyses=3):
    # Fix one coordinate per place. Explicit zero entries and absent
    # entries represent the same token multiset.
    places = tuple(net.places)

    def marking_key(marking):
        return tuple(marking.get(place, 0) for place in places)

    final_key = marking_key(fm)
    queue = deque([(im, ())])
    seen = {(marking_key(im), ())}
    accepted = set()

    while queue:
        marking, word = queue.popleft()

        # Exact final-marking equality: extra tokens are not accepted.
        if marking_key(marking) == final_key:
            accepted.add(word)

        for transition in pm4py.get_enabled_transitions(net, marking):
            label = transition.label
            if label is None:
                # Silent steps remain explorable even at the visible cap.
                next_word = word
            else:
                if len(word) >= max_visible:
                    continue
                if (label == ANALYZE
                        and word.count(ANALYZE) >= max_analyses):
                    continue
                next_word = word + (label,)

            next_marking = semantics.execute(transition, net, marking)
            if next_marking is None:
                raise RuntimeError("Enabled transition failed to fire")

            # Marking alone is insufficient: different visible prefixes
            # reaching it must retain their different complete traces.
            key = (marking_key(next_marking), next_word)
            if key not in seen:
                seen.add(key)
                queue.append((next_marking, next_word))

    return accepted


trees = {
    "A": pm4py.parse_process_tree(A_TEXT),
    "B": pm4py.parse_process_tree(B_TEXT),
}
nets = {}
languages = {}

for name, tree in trees.items():
    net, im, fm = pm4py.convert_to_petri_net(tree)
    nets[name] = (net, im, fm)
    result = pm4py.check_soundness(
        net, im, fm, print_diagnostics=True
    )
    # Accommodate a Boolean or a (Boolean, diagnostics) result.
    sound = result[0] if isinstance(result, tuple) else result
    print(name, "sound:", bool(sound))
    if not sound:
        raise RuntimeError("Soundness check failed for " + name)
    languages[name] = bounded_visible_language(
        net, im, fm, MAX_VISIBLE, MAX_ANALYSES
    )

la, lb = languages["A"], languages["B"]
print("Exploration: exhaustive within the two visible bounds")
print("A:", len(la), "B:", len(lb))
print("Intersection:", len(la & lb))
print("A-only:", len(la - lb), "B-only:", len(lb - la))
print("P3 equivalent:", la == lb)

symbols = {
    "Open Case": "o", "Analyze Revision": "a",
    "Check Revision": "c", "Approve Revision": "p",
    "Rework Case": "r", "Close Case": "f",
}
for title, unique in (("A-only", la - lb), ("B-only", lb - la)):
    print(title, "complete traces:")
    for word in sorted(unique, key=lambda t: (len(t), t)):
        print(" ".join(symbols[label] for label in word))

assert (len(la), len(lb), len(la & lb)) == (76, 85, 4)
assert (len(la - lb), len(lb - la)) == (72, 81)
```

The visited key includes both the marking and the full visible prefix. This preserves different labeled histories while merging redundant silent paths and silent cycles that reach the same state with the same prefix. Different transition identities remain distinguishable whenever they produce different markings or words. The analysis count is determined by the prefix, so it need not be a separate key component.

The standard nets converted from these trees have finitely many reachable markings. Together with the finite alphabet and the visible-length bound, this makes the explored state space finite. There is no silent-step limit, firing-depth cutoff, or sample-size cutoff. Bounds cannot discard a qualifying completion because visible length and analysis count never decrease. Acceptance requires equality with the entire final marking, including the absence of tokens elsewhere.

The exact counts also follow independently from the language formulas:

| Analysis count (n) | A bounded traces | B bounded traces | Common traces |
|---|---:|---:|---:|
| 1 | 4 | 5 | 4 |
| 2 | 16 | 20 | 0 |
| 3 | 56 | 60 | 0 |
| Total | 76 | 85 | 4 |

For A, each iteration has two `a`/`c` orders. With (k) approvals there are (2^n\binom{n}{k}) traces. All approval choices fit for (n=1,2); at (n=3), the all-approved traces have length 13 and are excluded. This gives (8(1+3+3)=56).

For B, fix the (k) approved attempts. The loop word has (2n-1+k) events, hence (2n+k) distinct insertion positions for its unique check. All choices for (n\leq3) fit the bound, giving

\[
\sum_{k=0}^{n}\binom{n}{k}(2n+k)=5n2^{n-1},
\]

or 5, 20, and 60 traces. Random `pm4py.play_out(...)` could discover witnesses, but failure to sample a trace would not establish its absence; it would not justify these exhaustive counts.

# 6. Stochastic and Footprint Comparison

**Footprints provide useful structural evidence.** For example, A requires the check before an approval in that revision, whereas B permits both relative orders. The following code continues from Section 5:

```python
for name, tree in trees.items():
    fp = pm4py.discover_footprints(tree)
    print(name, "sequence:", sorted(fp.get("sequence", set())))
    print(name, "parallel:", sorted(fp.get("parallel", set())))
```

For these trees, PM4Py 2.7.23.8 reports `(Check Revision, Approve Revision)` as a sequence relation for A and both directions of that pair as parallel relations for B. This corroborates the approval-order witness. Footprints summarize relations rather than retaining complete words and their iteration-specific obligations. Equal footprints can therefore conceal differences in multiplicity, loop scope, and longer-range dependencies; equality would not prove trace equivalence.

**Stochastic languages and Earth Mover's Distance require a probability interpretation.** The trees do not specify loop-exit probabilities, approval probabilities, or probabilities for concurrent interleavings. No operational stochastic language is uniquely determined by the question.

One reproducible diagnostic is to give every distinct P3 trace equal weight. This is an explicitly chosen distribution over the finite trace catalog, not a transition-probability model or an estimate of actual business frequencies:

```python
from pm4py.objects.log.obj import EventLog, Trace, Event


def catalog_log(language):
    # One case per distinct bounded trace: uniform trace-catalog weighting.
    return EventLog([
        Trace([Event({"concept:name": label}) for label in word])
        for word in sorted(language)
    ])


stochastic = {
    name: pm4py.get_stochastic_language(catalog_log(languages[name]))
    for name in ("A", "B")
}
for name, distribution in stochastic.items():
    assert abs(sum(distribution.values()) - 1.0) < 1e-12
    print(name, "stochastic support size:", len(distribution))

emd = pm4py.compute_emd(stochastic["A"], stochastic["B"])
print("EMD for uniform P3 trace catalogs:", emd)
```

Under this declared weighting, the tested version returned approximately **0.1821612465** using its default distance. This value depends on the trace bound, weighting, and ground distance. Empirical logs could instead supply observed frequencies, but their coverage and sampling assumptions would need to be stated.

A low EMD measures distributional proximity, not trace-set equality. Even zero distance between sampled or bounded distributions would not establish unbounded visible equivalence. Equal P2 record sets also do not imply equal record probabilities: uniform weighting over the original visible traces can induce different weights on their shared dashboard records.

# 7. Complexity Comparison

Count the parsed trees as written, without binarizing their sequence operators. Depth is the maximum number of edges from root to leaf; levels equal depth plus one. Duplicate-label excess means \(\sum_\ell\max(\mathrm{leafCount}(\ell)-1,0)\), over visible labels.

| Tree metric | Model A | Model B |
|---|---:|---:|
| Total nodes | 12 | 12 |
| Operator nodes | 5 | 5 |
| Depth in edges | 4 | 5 |
| Levels | 5 | 6 |
| Visible leaves | 6 | 6 |
| Silent leaves | 1 | 1 |
| Distinct visible labels | 6 | 6 |
| Duplicate-label excess | 0 | 0 |

Each original has five operators and seven leaves. A's longest paths are `sequence → loop → sequence → parallel/XOR → leaf`. B's longest path is `sequence → parallel → loop → sequence → XOR → leaf`. Repeated execution of a leaf by a loop does not create duplicate leaves in the tree.

This code derives the counts and evaluates the converted nets, continuing from Section 5:

```python
from collections import Counter


def tree_statistics(tree):
    labels = []
    counts = {
        "nodes": 0, "operators": 0,
        "silent_leaves": 0, "depth_edges": 0,
    }

    def visit(node, depth):
        counts["nodes"] += 1
        counts["depth_edges"] = max(counts["depth_edges"], depth)
        if node.operator is None:
            if node.label is None:
                counts["silent_leaves"] += 1
            else:
                labels.append(node.label)
        else:
            counts["operators"] += 1
            for child in node.children:
                visit(child, depth + 1)

    visit(tree, 0)
    frequency = Counter(labels)
    counts["visible_leaves"] = len(labels)
    counts["distinct_visible_labels"] = len(frequency)
    counts["duplicate_label_excess"] = sum(
        max(n - 1, 0) for n in frequency.values()
    )
    counts["depth_levels"] = counts["depth_edges"] + 1
    return counts


for name, tree in trees.items():
    net, im, fm = nets[name]
    print(name, tree_statistics(tree))
    print(name, "places:", len(net.places),
          "transitions:", len(net.transitions), "arcs:", len(net.arcs))
    print(name, "simplicity:", pm4py.simplicity_petri_net(net, im, fm))
```

The default conversion and simplicity function in the tested PM4Py version produced:

| Converted-net metric | Model A | Model B |
|---|---:|---:|
| Places | 9 | 7 |
| Transitions | 9 | 7 |
| Arcs | 20 | 16 |
| Simplicity score, approximately | 0.818182 | 0.777778 |

These net results are derived by the code and are conversion/version dependent. B uses fewer net nodes yet receives a lower simplicity score, illustrating that the score measures more than size. Neither the score nor tree size certifies behavioral preservation.

# 8. Simplified Model

I target **P2**, treating the simplified model as a generator of dashboard-equivalent cases. Operational compliance remains represented by A.

A compact process tree is:

```text
->(
  'Open Case',
  'Check Revision',
  *('Analyze Revision', 'Rework Case'),
  'Close Case'
)
```

This chooses a single check before all analyses, retains the analysis/rework loop, and removes visible approvals. The following construction is self-contained:

```python
import pm4py

simplified_model = pm4py.parse_process_tree("""
->(
  'Open Case',
  'Check Revision',
  *('Analyze Revision', 'Rework Case'),
  'Close Case'
)
""")

simplified_net, simplified_im, simplified_fm = (
    pm4py.convert_to_petri_net(simplified_model)
)
result = pm4py.check_soundness(
    simplified_net, simplified_im, simplified_fm,
    print_diagnostics=True,
)
sound = result[0] if isinstance(result, tuple) else result
assert sound
print("Simplified-net simplicity:", pm4py.simplicity_petri_net(
    simplified_net, simplified_im, simplified_fm
))
```

Its exact language is

\[
L(S)=\{o\,c\,a(ra)^{n-1}f:n\geq1\}.
\]

Consequently,

\[
\Phi(L(S))=\{(o,n,\mathrm{true},[n>1],f):n\geq1\}
=\Phi(L(A))=\Phi(L(B)).
\]

This proves unbounded P2 preservation. More concretely, map any source trace with (n) analyses to `o c a (r a)^(n-1) f`. Conversely, that representative has a B execution with every approval skipped and an A counterpart `o c a (r c a)^(n-1) f`, with the same dashboard record. Both directions are necessary: preservation includes every original record and introduces no new record.

The size reduction is explicit:

| Metric | Model A | Model B | Simplified S |
|---|---:|---:|---:|
| Tree nodes | 12 | 12 | 7 |
| Operator nodes | 5 | 5 | 2 |
| Depth in edges | 4 | 5 | 2 |
| Visible / silent leaves | 6 / 1 | 6 / 1 | 5 / 0 |
| Duplicate-label excess | 0 | 0 | 0 |
| Converted places / transitions / arcs | 9 / 9 / 20 | 7 / 7 / 16 | 5 / 5 / 10 |
| Converted-net simplicity, approximately | 0.818182 | 0.777778 | 1.000000 |

S has one sequence operator, one loop operator, and five visible leaves: seven nodes in total. Its longest path is `sequence → loop → leaf`. Its net values were derived using the same conversion and metric as the originals. Thus it is smaller than both originals under the stated measures.

| Property | Status | Preservation statement |
|---|---|---|
| One opening first and one closing last | Exact | Preserved from both originals |
| At least one analysis; arbitrary finite analysis count | Exact | Every integer (n\geq1) remains possible |
| Rework separates successive attempts, with exactly (n-1) reworks | Exact | Retained even though P2 records only whether any rework occurred |
| At least one check | Exact | S always performs its single check |
| Dashboard record language | Exact under P2 | Equal to both originals for every (n\geq1) |
| Check multiplicity | Abstracted | A's (n) checks become one; B's count of one is retained; the Boolean is preserved |
| Check order and concurrency | Lost as visible behavior | S fixes the check before the loop; P2 ignores these positions and interleavings |
| Visible approval choices and positions | Abstracted for P2; lost for P1/P3 | All source approval variants map to representatives with no approval event |
| A's check coverage for every revision | Weakened | Only case-level coverage remains; for (n\geq2), S leaves later revision segments unchecked. B already lacks the per-revision guarantee |
| Full visible language and P3 language | Lost | S has only three P3 traces, versus A's 76 and B's 85 |

Regression traces, all accepted by S:

| ID | Complete trace | Expected dashboard fields `(analyses, check occurred, rework occurred)` |
|---|---|---|
| R1 | `o c a f` | `(1, true, false)` |
| R2 | `o c a r a f` | `(2, true, true)` |
| R3 | `o c a r a r a f` | `(3, true, true)` |

Negative traces:

| ID | Complete candidate | Expected result and reason |
|---|---|---|
| N1 | `o a f` | Reject: the mandatory check is missing; its dashboard record is absent from both originals |
| N2 | `o c a a f` | Reject: two analyses require a separating rework; `(2, true, false)` is absent from both originals |
| N3 | `o a c f` | Reject as an S execution: S places its check first. Both originals admit it, and its dashboard record is already represented by R1 |

N3 makes the abstraction boundary explicit. S preserves dashboard records without retaining every concrete source trace. Indeed, (L(S)\subsetneq L(B)), while S's multi-attempt traces are absent from A because they lack repeated checks.

The following regression check uses the exhaustive helper from Section 5:

```python
s_language = bounded_visible_language(
    simplified_net, simplified_im, simplified_fm, 12, 3
)
expand = {symbol: label for label, symbol in symbols.items()}


def trace(text):
    return tuple(expand[symbol] for symbol in text.split())


for text in ("o c a f", "o c a r a f", "o c a r a r a f"):
    assert trace(text) in s_language
for text in ("o a f", "o c a a f", "o a c f"):
    assert trace(text) not in s_language
assert len(s_language) == 3


def dashboard(word):
    assert word[0] == "Open Case" and word[-1] == "Close Case"
    assert word.count("Open Case") == word.count("Close Case") == 1
    return (word.count("Analyze Revision"),
            "Check Revision" in word, "Rework Case" in word)


assert ({dashboard(t) for t in la}
        == {dashboard(t) for t in lb}
        == {dashboard(t) for t in s_language})
```

# 9. Final Recommendation

- **P1:** Use Model A. Its loop scope enforces a separate check in each revision segment. Model B and S are unsuitable as operational replacements because their single check cannot cover multiple attempts under P1.
- **P2:** Either original yields the required dashboard record set. S can replace either in a dashboard abstraction, reporting specification, or representative-case generator. It should not replace A as the executable compliance process merely because their dashboard records agree.
- **P3:** Both originals are valid subjects for bounded testing, but they are not interchangeable reference models. Use A as the reference when testing P1 compliance semantics. S does not preserve either original's bounded visible language and should not replace either for that comparison.

No single model can be visibly equivalent to both originals, even within P3: equality with both would imply equality between A and B, contradicting the witnesses. The simplification therefore deliberately preserves P2 only.

Bounded agreement is evidence, not an unbounded proof. Here the bounded counterexamples already prove visible inequivalence, while the separate dashboard-language argument establishes P2 equivalence for every finite number of revisions.
