### Burden-of-proof approach

## 6. Revised Normative Architecture

**Layer 0 — Vocabulary and scope (organizational/governance).**
Canonical activity dictionary with versioned synonym map (Quality_Review  QA_Clearance, effective-dated, board-approved). A case-type scope matrix assigning every lifecycle entry to an owning model: NEW_ONBOARDING  M1; INTAKE_REJECTED (sanctions-failed leads)  M1-reject-branch with abbreviated pre-screen codified; REACTIVATION  M-reactivation (fresh sanctions mandatory; quality satisfied by documented, validity-checked certification, else recycled through full checks); WITHDRAWN/ABANDONED  terminal path closing with reason codes. Ends the SUP-709/710/711 battles by legislation rather than litigation.

**Layer 1 — Control flow (POWL, Section 7).**
Feasible orders and exclusive routes only: shared sanctions prefix; XOR over standard-manual / low-risk-auto (quality deferred but mandatory) / emergency-provisional (activation first, remediation after) / reject; notification precedes closure; Request_More_Info as a repeatable loop concurrent with screening. POWL deliberately carries *no* predicates.

**Layer 2 — Data-aware declarative constraints (DECLARE/log-skeleton style).**
Response/precedence: `Activate_*` responds-to `Sanctions_Check`. Branched eligibility constraints: whenever `Auto_Approve_LowRisk` occurs  same-case snapshot shows risk=LOW  country=DE  group_approved  instrument-window covers occurred-time. Impossibility: never `Manual_Procurement_Approver == Requester` after alias resolution. Attested existence: for each `Request_More_Info`, a response/attachment event exists before the next gate. Timeliness: emergency quality within 2 business days; spend-ledger sums vs caps.

**Layer 3 — Quantitative/referential checks (pandas batch jobs).**
Dedup on `(source_system, source_transaction_id)` (SUP-711); referential join of `notification_id` into an immutable CRM export with pre/post-close assertions and a >15%-missing circuit-breaker alert (SUP-702/706); eligibility-snapshot completeness for every auto-route case with 9-open-case aging; alias-graph resolution against HR master with delegation-table join (SUP-712); COI-graph scan (kinship, reporting-line) with disclosure-flag verification (SUP-715); per-case emergency cap computation joined to the transaction ledger; append-only audit asserting `recorded_at  occurred_at` and mutation alarms on "old" links.

**Layer 4 — Instrument governance (organizational).**
Instrument registry: every pilot/waiver/emergency gets an ID, named owner, signature(s) including the standard's custodian (answers the observer-dispute), effective/expiry timestamps driving automated 7-day pre-expiry alarms and hard deactivation, and a mandatory retirement decision (ratify | renew formally | wind down). "Graduation" checklist converting validated pilots into CS-9 amendments. Delegation-of-authority matrix feeding Layer 2. COI disclosure workflow.

**Allocation rationale:** POWL owns *what sequences are possible*; DECLARE owns *cross-activity predicates and resource pairings*; pandas owns *arithmetic, referential integrity, and identity/graph reasoning*; organizations own *the creation, amendment, expiry, and accountability of authority itself* — the one thing no execution engine can legitimately invent.

## 7. PM4Py Model and Data Proposal

```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

def t(label):
    return Transition(label=label)

# ------------------------------------------------------------------
# Canonical vocabulary. Synonyms (e.g., QA_Clearance) are mapped to
# these labels upstream by a VERSIONED dictionary; POWL sees only
# canonical labels.
# ------------------------------------------------------------------
REGISTER          = t("Register_Supplier")
SANCTIONS         = t("Sanctions_Check")          # mandatory before EVERY activation (CS-9; PD-3; FD-7)
REQUEST_MORE_INFO = t("Request_More_Info")
AUTO_APPROVE      = t("Auto_Approve_LowRisk")     # eligibility gated OUTSIDE POWL (overlay R-PD3-* / future R-AMEND-*)
MANUAL_APPROVAL   = t("Manual_Procurement_Approval")
REJECT            = t("Reject_Supplier")
NOTIFY            = t("Notify_Requester")
CLOSE             = t("Close_Case")

# ------------------------------------------------------------------
# Repeatable information requests:  tau (RMI tau)*  <=> zero or more
# RMI occurrences. Uses PM4Py loop semantics *(A,B) = A (B A)* with
# A = silent. Cannot express "RMI only between specific activities";
# declared approximation: free interleaving with the screening block.
# Gating rule "evidence arrives before decision" => DECLARE + org control.
# ------------------------------------------------------------------
_tau = SilentTransition()
info_loop = OperatorPOWL(operator=Operator.LOOP,
                         children=[_tau, REQUEST_MORE_INFO])

# Screening concurrency: sanctions may run while info requests cycle.
# No internal edges => arbitrary interleaving. SANCTIONS < every
# activation is guaranteed structurally because each activation lives
# in a route placed AFTER this block.
screening = StrictPartialOrder(nodes=[SANCTIONS, info_loop])

# ------------------------- Route: STANDARD -------------------------
# Quality Review AND Manual Approval both before activation;
# mutually unordered between themselves (CS-9 asks both beforehand).
act_std = t("Activate_Supplier")
route_standard = StrictPartialOrder(nodes=[t("Quality_Review"),
                                           MANUAL_APPROVAL,
                                           act_std])
route_standard.order.add_edge(t("Quality_Review"), act_std)
route_standard.order.add_edge(MANUAL_APPROVAL, act_std)

# -------- Route: LOW-RISK PROVISIONAL AUTO (PD-3 style) ------------
# Deliberately encodes DEFERRED-and-mandatory quality AFTER
# activation (pilot semantics observed in SUP-702/714). Limitation:
# POWL cannot switch this order on data (a future amended permanent
# policy wanting pre-checks should add a FOURTH route and let the
# overlay select it per governing instrument). Conservative choice.
act_auto = t("Activate_Supplier")
route_auto = StrictPartialOrder(nodes=[AUTO_APPROVE,
                                       act_auto,
                                       t("Quality_Review")])
route_auto.order.add_edge(AUTO_APPROVE, act_auto)
route_auto.order.add_edge(act_auto, t("Quality_Review"))

# ------------- Route: EMERGENCY / PROVISIONAL (FD-7) ---------------
# Only sanctions constrain the prefix (screening block precedes);
# activation first, then BOTH remediation duties (unordered).
prov_act = t("Provisional_Activate_Emergency")
_q_late = t("Quality_Review")
_retro  = t("Retrospective_Procurement_Approval")
route_emergency = StrictPartialOrder(nodes=[prov_act, _q_late, _retro])
route_emergency.order.add_edge(prov_act, _q_late)
route_emergency.order.add_edge(prov_act, _retro)

# ---------------------------- Routing -----------------------------
routes = OperatorPOWL(operator=Operator.XOR,
                      children=[route_standard,
                                route_auto,
                                route_emergency,
                                REJECT])

# --------------------------- Assembly ------------------------------
# Notification always precedes closure on ALL routes (one convergence),
# repairing the capture ambiguity flagged in SUP-702/706 at the
# modeling level; proof-of-delivery remains a data-layer duty.
M1 = StrictPartialOrder(nodes=[REGISTER, screening, routes, NOTIFY, CLOSE])
M1.order.add_edge(REGISTER, screening)
M1.order.add_edge(screening, routes)
M1.order.add_edge(routes, NOTIFY)
M1.order.add_edge(NOTIFY, CLOSE)
```

**Honest limitations of the single-POWL approach (stated, not hidden):** (1) POWL cannot carry predicates — eligibility, amounts, dates, identities are unencodable, hence the overlay below; (2) the info-loop position permits RMI interleaving only before route entry, whereas SUP-707 interleaved with the checks — tolerated as a superset approximation, tightened by Layer-2 constraints; (3) fixed post-activation quality on the auto route encodes the pilot shape and would need a fourth route (plus instrument-based selection) if the permanent amendment dictates pre-checks; (4) "reactivation" is intentionally excluded — it belongs to the Layer-0 scope matrix and a companion model, not to a conditional hack inside onboarding.

- **Immutable event store** `EVENTS`: `event_id` (UUID, assigned at write), `case_id`, `activity_code` (canonical, FK to dictionary version), `occurred_at` (source clock) and `recorded_at` (store receipt) both immutable and append-only; `actor_canonical_id`; `alias_set_hash`; `delegation_id` nullable (FK to approved delegations); `instrument_id` nullable (FK to pilot/emergency authority registry); `rule_version_id` (which overlay evaluation applied); `route_declared`.

- **DELEGATIONS**: `delegation_id`, `delegate_from`, `delegate_to`, `scope`, `approver_signature`, `valid_interval` — turns SUP-712 disputes into lookups.
- **ELIGIBILITY_SNAPSHOTS**: `snapshot_id`, `case_id`, `captured_at`, `risk_rating`, `country`, `group_membership_ref`, `criteria_hash`, `rule_version_id` — frozen at decision instant; missing snapshot = route may not fire (retires the 9 indeterminates).

- Pandas checks (batch + streaming): dedup/unique assertion; CRM reconciliation join with >15%-missing circuit breaker; per-case emergency cap recomputation from the transaction ledger; SoD/COI graph scans; snapshot-completeness gate feeding the route validator; append-only tamper audit comparing stored hashes.
