# 1. Equivalence Notions

Let `L_vis(M)` be the set of complete visible traces of model `M` after deleting `tau`.

- `Visible trace equivalence after hiding tau`: `M1 ≡vis M2` iff `L_vis(M1) = L_vis(M2)`. Repeated visible labels are distinguished only by occurrence position in the trace, not by transition identity.
- `Bounded visible-language equivalence under P3`: `M1 ≡P3 M2` iff `{σ in L_vis(M1) | len(σ) <= 12 and count_Analyze(σ) <= 3} = {σ in L_vis(M2) | len(σ) <= 12 and count_Analyze(σ) <= 3}`. This is exact for the stated bound only.
- `Business-relevant equivalence under P1`: split each complete visible trace into revision attempts separated by `Rework Case`, with `Open Case` first and `Close Case` last. The observation keeps the full visible sequence, so approval occurrences and their positions remain visible. A trace is P1-compliant only if every `Analyze Revision` occurrence has a `Check Revision` in the same attempt before the next `Rework Case` or `Close Case`. Two models are equivalent under P1 iff they admit the same complete visible behaviors under that compliance interpretation.
- `Abstracted dashboard equivalence under P2`: define
  `α_P2(σ) = (open_first, close_last, nA, anyCheck, anyRework)`
  after deleting `Approve Revision` and `tau`, where `nA` is the number of `Analyze Revision` occurrences, `anyCheck` is whether any `Check Revision` occurred, and `anyRework` is whether any `Rework Case` occurred. Here duplicate `Analyze Revision` occurrences are retained only by count; duplicate `Check Revision` and `Rework Case` occurrences are collapsed to presence/absence. Exact interleaving is not observed.

Under these notions, duplicate visible labels are never tracked by transition identity. They are tracked by sequence position for `≡vis`, `≡P3`, and P1; under P2 they are intentionally coarsened as above.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
| --- | --- | --- | --- |
| Loop scope | The loop body contains `Analyze Revision`, `Check Revision`, and optional `Approve Revision`. | The loop body contains `Analyze Revision` and optional `Approve Revision`; `Check Revision` is outside the loop in parallel with the whole loop. | A ties checking to every iteration; B does not. |
| Minimum and maximum `Check Revision` occurrences in complete traces | Exactly one per iteration; overall minimum `1`, maximum unbounded. For `n` analyses, there are exactly `n` checks. | Exactly one total per complete trace; minimum `1`, maximum `1`, regardless of the number of analyses. | This is the main source of non-equivalence. |
| Possible placement of `Check Revision` | Within each revision attempt, `Check Revision` may occur before or after `Analyze Revision` because of `+`, but it must occur before any `Approve Revision`, before `Rework Case`, and before `Close Case`. | The single `Check Revision` may appear anywhere in the interleaving with the whole revision loop, including after an `Approve Revision` or between two attempts, but still before `Close Case` because of the join. | B allows late or globally misplaced checks that A forbids. |
| Optional approval occurrences | Optional once per iteration via `X('Approve Revision', tau)`. For `n` analyses, there may be `0..n` approvals. | Optional once per iteration via the same `X('Approve Revision', tau)`. For `n` analyses, there may be `0..n` approvals. | Approval counts can match, but approval timing relative to checking differs. |
| Concurrency | Local concurrency inside each attempt: `Analyze Revision` and `Check Revision` interleave only with each other. | One global concurrency block: the single `Check Revision` interleaves with the entire loop, including approvals and reworks. | B introduces cross-attempt interleavings that A cannot express. |
| Join before `Close Case` | `Close Case` is reached only after the loop has completed; because the check is inside the loop, loop completion implies all per-attempt checks are done. | `Close Case` is reached only after both the loop branch and the separate `Check Revision` branch finish. | B guarantees only “some check before close”, not “one check per analysis attempt”. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
| --- | --- | --- | --- | --- |
| P1 | not equivalent | high | Model A embeds one visible check inside every revision attempt; Model B has only one global check and admits traces where an analysis is followed by `Rework Case` or `Close Case` without its own check. | If the business rule were weakened to “at least one check somewhere before close”, B could fit, but that is not the stated compliance view. |
| P2 | equivalent only under stated abstraction | high | After removing `Approve Revision` and `tau`, collapsing repeated checks to the Boolean fact “a check occurred”, and keeping only analyze count plus whether any rework occurred, both models induce the same observations: one or more analyses, a check present, and rework iff there was more than one analysis. | The equivalence disappears immediately if the dashboard counts checks or records when the check happened. |
| P3 | not equivalent | high | Exhaustive bounded exploration under the P3 bound yields `76` complete visible traces for A and `85` for B, with only `4` common traces. | Bounded non-equivalence is conclusive because an actual bounded counterexample is enough; only bounded equivalence would remain inconclusive. |

# 4. Counterexample Traces

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
| --- | --- | --- | --- | --- | --- |
| A1 | `[Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close Case]` | yes | no | A performs one check in each of the two analysis attempts; B has only one `Check Revision` total. | P1, P3 |
| A2 | `[Open Case, Check Revision, Analyze Revision, Rework Case, Check Revision, Analyze Revision, Approve Revision, Close Case]` | yes | no | A can place a distinct check at the start of each attempt; B cannot produce a second check. | P1, P3 |
| B1 | `[Open Case, Analyze Revision, Approve Revision, Check Revision, Close Case]` | no | yes | In B, the single global check may happen after approval; in A, approval is reachable only after both analyze and check have completed. | `≡vis`, P3 |
| B2 | `[Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case]` | no | yes | B allows the first analysis attempt to end in `Rework Case` before any check; A never exits an attempt before both analyze and check are done. | P1, P3 |

At least one witness contains two analysis attempts: `A1`, `A2`, and `B2` all do.

Effect of optional approval and hidden `tau`:

- `X('Approve Revision', tau)` makes `Approve Revision` optional in both models, so some traces differ only by the presence or absence of approval.
- Hiding `tau` does not hide missing checks, because `Check Revision` is visible.
- Optional approval creates extra B-only witnesses such as `B1`, because B can interleave the single check after an approval, while A cannot.

# 5. Bounded Comparison Code

```python
import pm4py
from collections import deque
from pm4py.objects.petri_net import semantics as pn_semantics

MODEL_A = "->('Open Case', * ( ->( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) ), 'Rework Case' ), 'Close Case')"
MODEL_B = "->('Open Case', +( 'Check Revision', *( ->('Analyze Revision', X('Approve Revision', tau)), 'Rework Case' ) ), 'Close Case')"

MAX_VISIBLE = 12
MAX_ANALYZE = 3


def marking_signature(marking):
    return tuple(sorted((place.name, count) for place, count in marking.items() if count))


def exhaustive_bounded_language(net, im, fm, max_visible=MAX_VISIBLE, max_analyze=MAX_ANALYZE):
    """
    Exhaustive BFS over markings and visible prefixes.
    This is exhaustive for the stated P3 bound.
    """
    queue = deque([(im, tuple(), 0)])
    seen = set()
    complete = set()

    while queue:
        marking, trace, analyze_count = queue.popleft()
        state = (marking_signature(marking), trace, analyze_count)
        if state in seen:
            continue
        seen.add(state)

        if marking == fm:
            complete.add(trace)
            continue

        if len(trace) >= max_visible:
            continue

        for transition in pm4py.get_enabled_transitions(net, marking):
            next_marking = pn_semantics.execute(transition, net, marking)

            if transition.label is None:
                queue.append((next_marking, trace, analyze_count))
                continue

            next_trace = trace + (transition.label,)
            next_analyze = analyze_count + int(transition.label == "Analyze Revision")

            if len(next_trace) <= max_visible and next_analyze <= max_analyze:
                queue.append((next_marking, next_trace, next_analyze))

    return complete


def analyze_model(name, tree_string):
    tree = pm4py.parse_process_tree(tree_string)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    sound = pm4py.check_soundness(net, im, fm, print_diagnostics=False)[0]
    language = exhaustive_bounded_language(net, im, fm)
    print(f"{name}: sound={sound}, bounded_complete_traces={len(language)}")
    return tree, net, im, fm, language


_, net_a, im_a, fm_a, lang_a = analyze_model("A", MODEL_A)
_, net_b, im_b, fm_b, lang_b = analyze_model("B", MODEL_B)

only_a = sorted(lang_a - lang_b, key=lambda t: (len(t), t))
only_b = sorted(lang_b - lang_a, key=lambda t: (len(t), t))
both = sorted(lang_a & lang_b, key=lambda t: (len(t), t))

print("\nExhaustive bounded comparison under P3")
print(f"common={len(both)}, A_only={len(only_a)}, B_only={len(only_b)}")

print("\nA-only traces:")
for trace in only_a:
    print(trace)

print("\nB-only traces:")
for trace in only_b:
    print(trace)

# Non-exhaustive evidence only:
# sampled_log_a = pm4py.play_out(net_a, im_a, fm_a, parameters={"noTraces": 2000, "maxTraceLength": 12})
# sampled_log_b = pm4py.play_out(net_b, im_b, fm_b, parameters={"noTraces": 2000, "maxTraceLength": 12})
# print(len(sampled_log_a), len(sampled_log_b))
# The playout logs above are heuristic samples; they are not a proof of equivalence.
```

The exhaustive part is the BFS over markings and visible prefixes. A plain `pm4py.play_out(...)` call is only a sample generator unless one explicitly chooses an exhaustive variant and proves the bound coverage.

# 6. Stochastic and Footprint Comparison

These techniques can add evidence, but they do not settle trace equivalence.

- `pm4py.discover_footprints(...)` compares local relations such as start activities, end activities, sequencing, and parallelism. It can expose a meaningful difference here: Model B makes `Check Revision` concurrent with the whole loop, so relations involving `Check Revision` and `Approve Revision` differ from A. But equal footprints would still be too coarse, because footprints do not encode long-range counting constraints such as “one check per analysis attempt”.
- `pm4py.get_stochastic_language(...)` can produce an empirical or model-derived probability distribution over traces. Without declared transition probabilities, it reflects playout defaults or sampled frequencies, not business-validated likelihoods.
- `pm4py.compute_emd(...)` can compare two stochastic languages as distributions. A low Earth Mover’s Distance would only mean the sampled distributions are similar, not that the supports are identical. Rare but valid counterexample traces could still exist.

```python
import pm4py

# Assume tree_a/tree_b or net_a/im_a/fm_a and net_b/im_b/fm_b already exist.

footprints_a = pm4py.discover_footprints(tree_a)
footprints_b = pm4py.discover_footprints(tree_b)

print("A parallel pairs:", footprints_a["parallel"])
print("B parallel pairs:", footprints_b["parallel"])
print("A sequence pairs:", footprints_a["sequence"])
print("B sequence pairs:", footprints_b["sequence"])

# Sample-based stochastic evidence only. No transition probabilities are declared here.
sample_params = {"noTraces": 5000, "maxTraceLength": 12}
lang_a = pm4py.get_stochastic_language(net_a, im_a, fm_a, parameters=sample_params)
lang_b = pm4py.get_stochastic_language(net_b, im_b, fm_b, parameters=sample_params)

emd = pm4py.compute_emd(lang_a, lang_b)
print("Sample-based EMD:", emd)
```

Even if the footprints matched exactly or the sampled EMD were very small, that would still not establish visible trace equivalence, because language equality is a support question, not merely a local-relation or distributional-similarity question.

# 7. Complexity Comparison

A precise recursive count over the process tree is enough for the structural metrics:

```python
from collections import Counter


def tree_stats(node, depth=1):
    is_leaf = len(node.children) == 0
    stats = {
        "nodes": 1,
        "depth": depth,
        "visible_leaves": int(is_leaf and node.label is not None),
        "silent_leaves": int(is_leaf and node.label is None),
    }
    labels = [node.label] if is_leaf and node.label is not None else []

    for child in node.children:
        child_stats, child_labels = tree_stats(child, depth + 1)
        stats["nodes"] += child_stats["nodes"]
        stats["depth"] = max(stats["depth"], child_stats["depth"])
        stats["visible_leaves"] += child_stats["visible_leaves"]
        stats["silent_leaves"] += child_stats["silent_leaves"]
        labels.extend(child_labels)

    return stats, labels


stats_a, labels_a = tree_stats(tree_a)
stats_b, labels_b = tree_stats(tree_b)

duplicate_leaf_labels_a = sum(c - 1 for c in Counter(labels_a).values() if c > 1)
duplicate_leaf_labels_b = sum(c - 1 for c in Counter(labels_b).values() if c > 1)

simplicity_a = pm4py.simplicity_petri_net(net_a, im_a, fm_a)
simplicity_b = pm4py.simplicity_petri_net(net_b, im_b, fm_b)
```

Derived values for the two original models:

| Metric | Model A | Model B |
| --- | --- | --- |
| Process-tree node count | 12 | 12 |
| Depth (`root = 1`) | 5 | 6 |
| Visible leaves | 6 | 6 |
| Silent leaves | 1 | 1 |
| Duplicate visible-label count across leaves | 0 | 0 |
| Petri-net simplicity `pm4py.simplicity_petri_net(...)` | 0.8181818182 | 0.7777777778 |

Notes:

- The duplicate-label count is `0` in both trees because each visible activity label appears on only one leaf. Repetition in traces comes from loop execution, not from duplicated leaves.
- In this conversion, A yields a larger net than B, but the reported simplicity score is still slightly better for A. So “fewer Petri-net elements” and “higher simplicity score” do not coincide automatically.

# 8. Simplified Model

I choose P2 as the target semantics. It is the only view under which A and B intentionally collapse to the same business observation, so a single simplification can preserve that view exactly while becoming much smaller.

A compact process tree for P2 is:

```text
->(
  'Open Case',
  *('Analyze Revision', 'Rework Case'),
  'Check Revision',
  'Close Case'
)
```

This fixes the check at one position, which is acceptable because P2 does not record the exact interleaving of `Analyze Revision` and `Check Revision`; it only records whether any check occurred.

Self-contained PM4Py code:

```python
import pm4py

simplified_model = pm4py.parse_process_tree(
    "->('Open Case', *('Analyze Revision', 'Rework Case'), 'Check Revision', 'Close Case')"
)
```

Compared with the originals, this really is simpler: it has `7` process-tree nodes instead of `12`, depth `3` instead of `5` or `6`, no silent leaf, and converted-Petri-net simplicity `1.0` instead of `0.8181818182` or `0.7777777778`.

Preservation table relative to the chosen P2 semantics:

| Property | Status | Note |
| --- | --- | --- |
| `Open Case` first | exact | Preserved by the outer sequence. |
| `Close Case` last | exact | Preserved by the outer sequence. |
| At least one `Analyze Revision` | exact | The loop first child executes once. |
| Number of `Analyze Revision` occurrences | exact | Each loop iteration contributes one analysis. |
| At least one `Check Revision` occurred | exact | The model has one mandatory visible check. |
| Whether any `Rework Case` occurred | exact | `Rework Case` appears iff the loop repeats. |
| `Approve Revision` visibility | lost intentionally | P2 hides approvals. |
| Multiple `Check Revision` occurrences beyond “a check occurred” | abstracted | P2 collapses all checks to a Boolean fact. |
| Exact `Analyze`/`Check` interleaving | abstracted | P2 does not observe it. |
| P1 compliance evidence “one check per analysis attempt” | lost | This model is not suitable for compliance auditing. |

Regression traces for the simplified model:

| Kind | Trace | Expected |
| --- | --- | --- |
| regression | `[Open Case, Analyze Revision, Check Revision, Close Case]` | accepted |
| regression | `[Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case]` | accepted |
| regression | `[Open Case, Analyze Revision, Rework Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case]` | accepted |
| negative | `[Open Case, Analyze Revision, Close Case]` | rejected |
| negative | `[Open Case, Check Revision, Close Case]` | rejected |

This simplified model should be understood as a derived dashboard model, not as a replacement for the operational semantics required by P1.

# 9. Final Recommendation

- For P1, Model A is the suitable original model; Model B is not. A places checking inside every revision attempt, which matches the compliance rule far better. If the intended business rule is actually “analyze first, then check”, A should be tightened further, because it still allows `Check Revision` before `Analyze Revision` within an attempt.
- For P2, Models A and B are equivalent only under the stated abstraction. A dedicated simplified dashboard model is preferable to either original, because it preserves exactly what the dashboard observes and discards the rest.
- For P3, the models are not equivalent. The bounded comparison already finds real complete counterexamples in both directions, so B should not be substituted for A as a semantics-preserving simplification.
- A single simplification does not preserve all three views simultaneously. The P2 simplification above is exact for the dashboard view, but it intentionally loses the compliance distinctions that matter under P1.
- Bounded comparison has a strict limit: finding a bounded counterexample proves non-equivalence, but failing to find one within `12` visible events and `3` analyses would still not prove unbounded equivalence.
