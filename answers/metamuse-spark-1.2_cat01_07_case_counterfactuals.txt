## 1. Feasibility model

```text
Partial-Order Relations ( -> = must precede, || = may be concurrent):

1. Register -> Triage
2. Triage -> Identity Check
3. Triage -> Originals Receipt [if originals_required = true]
4. Originals Receipt -> Document Check [if originals_required = true]
5. Triage -> Document Check [if originals_required = false]
6. {Identity Check, Document Check} -> Assessment   // both must complete before Assessment
7. Identity Check || Document Check [if originals_required = false OR after Originals Receipt]
8. Identity Check || Originals Receipt [may overlap]
9. Assessment -> Decision   [if no Compliance required and no Request More Info]
10. Assessment -> Compliance Review -> Decision [if high_risk OR high_value]
11. Assessment -> Request More Info -> Document Check -> Assessment [rework loop]
12. Compliance Review -> Request More Info -> Document Check -> Assessment -> (Compliance Review reaffirmed/new) -> Decision [if rework after compliance]
13. Preliminary Compliance Screen || {Identity Check, Document Check, Originals Receipt} [non-binding, does not satisfy 10]
14. Escalation Advice || {Identity Check, Document Check} [advisory, S1 may overlap]
15. Decision -> Notify
16. For any rework: latest Assessment -> (latest) Compliance Review -> Decision [compliance must be after latest evidence]
```

```text
Conditional and Declarative Constraints:

C1. IF originals_required = true THEN Document Check requires Originals Receipt complete.
C2. IF high_risk = true OR high_value = true THEN Compliance Review required after latest Assessment and before Decision.
C3. Four-eyes: resource(final Assessment) != resource(final Compliance Review).
C4. Resource capacity: For any resource r, no two service intervals may overlap; queue wait = sum of remaining service times of cases ahead + uncertainty.
C5. Service time ranges are stochastic forecasts, not deterministic guarantees.
C6. Request More Info triggers mandatory rework: Document Check + Assessment required; if high-risk/value then Compliance Review must be new or explicitly reaffirmed (preliminary screen insufficient).
C7. Escalation Advice is optional and non-decisive; does not replace Compliance Review.
C8. Decision is only allowed if all evidence required by C1-C2-C6 is marked complete and four-eyes holds.
C9. Queue estimates at snapshots are forecasts with ~ +-30-50% error; earlier readiness does not guarantee earlier final completion if downstream queue is saturated.
C10. Logging constraint: Concurrent work must be logged with real-time timestamps; batch entry can create false precedence.
```

Interventions by type:

* **Timing-only (preserves path structure): K-104.** Adds parallel preliminary Escalation/Compliance preparation but does not remove or reorder mandatory checks; final Compliance Review must still occur after final Assessment. Changes waiting time and service time for final Compliance, not routing. Provisional slot reservation changes queue priority timing.
* **Routing/resource substitution: K-219 and K-411.** K-219 substitutes D2 for D1 at same process position; K-411 removes sequential lock to enable concurrency (Identity || Document). Both alter resource assignment and concurrency, not decision policy.
* **Decision-policy altering: K-337.** Prohibits a legitimate `Request More Info -> Document Check -> Assessment` loop and forces a decision under unresolved discrepancy. This is not a time compression but a truncation of the allowed evidence set and changes the approval conditions, risk exposure, and defensibility.

## 3. Counterfactual derivations

### K-104
Factual mechanism: Triage noticed sanctions ambiguity but did not escalate. Identity (I1) and Document (D1-complex 8h, queue 13h) proceeded without compliance context. When Assessment (A1) rediscovered ambiguity Tue 19:10, it triggered sequential Escalation (S1 2h) and then a cold Compliance Review (C1 Wed 13:10, 4.5h) after waiting 16h in C1 queue. The critical path was D1 queue + Assessment queue + C1 queue + full C1 service.

Minimal intervention: At Triage completion Mon 08:50 add non-blocking send to S1 (packet) and request provisional hold on C1 calendar. S1 advisory and C1 preliminary reading become parallel branches to Identity/Document. No mandatory activity is removed; final Compliance Review after Assessment is retained.

Temporal propagation: Identity completes Mon 12:50 regardless. Document completes Tue 05:40. In factual, Assessment could not start until Tue 15:10 due to A1 queue (12h at Mon 16:00, 9h at Tue 08:00). Counterfactual does not shorten those queues. However S1 can work Mon 09:00- Tue 05:40, and C1 can use idle time Tue 06:00-15:10 for 2-4h preliminary screen of already-available corporate documents. This saves 1-3h of final C1 service (from 4.5h to ~2-3h) and, if reservation is honored, reduces C1 waiting from Wed 13:10 to Wed 08:00-10:00 arrival. Saving propagates as: preliminary work -> shorter final Compliance -> Decision earlier same day; if reservation fails, only service-time saving remains. Four-eyes still holds because final Assessment stays A1, final Compliance stays C1.

Process-feasibility check: Register->Triage->Identity||Document satisfied. Preliminary compliance screen is explicitly allowed before Assessment and does not replace final review (satisfies rule 5 and 10). Final order Assessment -> Compliance -> Decision preserved. S1 overlap allowed per resource notes. No resource does two intervals at once: C1 preliminary is spread across idle gaps, not overlapping its other cases except via reservation displacement.

Best/base/worst case: Best: packet complete, C1 holds slot, preliminary saves 3h and queue saves 6h  finish Wed 08:30-11:00 (-7 to -10h). Base: packet partially complete, saves 1.5-2h service + 3-4h queue  finish Wed 11:00-14:00 (-5 to -7h). Worst: packet incomplete, C1 cannot honor hold due to two urgent cases added Mon 16:00  no queue save, only ~0.5h savings from notes  ~Wed 17:00 (-1 to -2h), and displaced case adds spillover with no net benefit.

Evidence that would reverse the conclusion: C1 time-stamped logs showing no preliminary time was actually available (C1 fully occupied Tue), or S1 notes showing preliminary packet contained no usable sanctions evidence, or compliance queue data showing urgent cases had SLA priority making reservation infeasible, or audit finding that provisional holds violate compliance SLA policy.

### K-219
Factual mechanism: Originals required, so Document Check blocked until Mon 17:30. Case routed to D1 (expert on handwriting) despite 11h queue; D1 started Tue 09:30, finished quickly and accurately in 4h, enabling Assessment Tue 20:00 after A2 queue.

Minimal intervention: Change resource assignment only after Originals Receipt; keep all other rules and decision policy. D2 is instructed to start as soon as originals arrive plus its queue wait, rather than holding for D1.

Temporal propagation: At Mon 16:00 D1 queue 11h, D2 queue 5h; at Tue 08:00 D1 8h, D2 4h. Intervention start for D2 is Mon evening: earliest start ~Mon 20:30-23:00, service 6-10h for handwritten standard (vs D1 3-6h). So D2 finishes ~Tue 04:30-08:00, ~5-8h before D1's factual completion Tue 13:30. Assessment readiness moves earlier, but A2 queue (7h at Mon 16:00, 6h at Tue 08:00) means earlier arrival Tuesday morning may still wait until Tue 14:00-18:00 for Assessment start vs factual 20:00. Net cycle-time gain in no-rework world is start-time saving minus slower service, minus queue absorption: ~8-12h. If D2 requests clarification, the rework branch adds external collection 8-36h plus second Document Check (4-8h) plus second Assessment (2-5h), pushing completion beyond factual by 12-36h.

Process-feasibility check: Originals Receipt -> Document Check ordering satisfied regardless of resource. Four-eyes irrelevant (no compliance needed). No overlap violation: D2 interval does not conflict with I2 (already complete Mon 16:20). Path still obeys {Identity, Document} -> Assessment -> Decision -> Notify. Higher rework probability is not a feasibility violation but a quality loop allowed by rule 6-7.

Best/base/worst case: Best (no rework, D2 fast 4-5h): cycle -12h, finish Tue evening, decision unchanged. Base (mixture, 30% rework): expected -2 to -4h off calendar but variance high. Worst (rework with slow supplier): +24 to +36h vs factual, plus second D1 involvement, customer experience degraded.

Evidence that would reverse the conclusion: Handwriting difficulty scoring showing D2 historical rework rate >50% on similar samples, or D2 actually had 8h+ queue Mon night (negating start advantage), or external supplier response logs showing D2 clarifications are routinely resolved in <4h (reducing worst case), or assessment logs showing A2 was unavailable Tue afternoon (eliminating early-readiness benefit).

### K-337
Factual mechanism: High-risk/high-value with originals; each Document Check revealed inconsistency, each Assessment requested correction; external supplier slow/inconsistent amplified waiting, including a weekend gap (Fri 10:30 to Mon 09:00, 70.5h). Factual path required 3 Document Checks, 3 Assessments, then Compliance.

Minimal intervention: Policy intervention after Assessment 2: forbid second Request More Info. This is not a timing tweak but a truncation of the normative rework loop. The decision must now be made with one inconsistency remaining, using an explicitly risk-adjusted decision (conditional approval with mitigants or rejection). The path must retain a final Compliance Review after Assessment 2 before Decision (rule 5).

Temporal propagation: Factual spent Fri 10:30-Mon 09:00 waiting + Mon 13:00-16:30 Document 3 + Tue 08:00-10:30 Assessment 3 + Tue 15:30-19:30 Compliance. Intervention replaces that entire block with Compliance Review Friday afternoon (Fri 11:00-16:00, C1 queue ~5h at Thu 08:00) then Decision. Weekend delay disappears because no external Request is sent. Saving propagates one-to-one: eliminating external wait plus two service intervals. Assessment 3 and Document 3 queues are also avoided.

Process-feasibility check: Truncated path Register->Triage->Identity->Originals->Document1->Assessment1->Request1->Document2->Assessment2->Compliance->Decision satisfies all prerequisites: Document before Assessment, latest Assessment before Compliance, Compliance before Decision, four-eyes (A1 != C1). The prohibition is feasible only if decision explicitly addresses the unresolved discrepancy (approve with conditions/reject); silently issuing a clean approve would violate defensibility and rule 5.

Best/base/worst case: Best: conditional approve with heightened monitoring on Fri 16:30 (-4.3 days), acceptable residual risk, no appeal. Base: conditional approve or borderline reject Fri evening (-4 days), elevated appeal and monitoring cost, audit flag but defensible because documented. Worst: forced clean approve without conditions to meet speed metric  compliance breach, downstream loss, reversal on appeal; or forced reject  customer loss and potential overturn due to insufficient evidence gathering.

Evidence that would reverse the conclusion: Supplier confirmation data showing inconsistency was material to credit risk (second loop avoided would have revealed default), or compliance policy stating provisional approval with known inconsistency is prohibited, or loss data showing conditional approvals without second confirmation have 3x default, or legal review that rejecting without second request violates procedural fairness.

### K-411
Factual mechanism: System lock created only Identity task at Triage; Document task creation blocked until Identity completed Tue 13:20 + 1h40 creation lag until 15:00. Sequential execution plus Assessment queue (A2 6h) produced Wed afternoon finish.

Minimal intervention: At Triage create both tasks and apply controlled workaround for case ownership, enabling concurrent execution with real-time timestamp logging. No resource or decision rule changed.

Temporal propagation: At Tue 08:00 queues I2 2h, D2 4h, A2 6h. With concurrency, I2 runs Tue 11:30-13:20 (1h50 actual), D2 runs ~13:30-18:00 (4.5h factual duration, but start 1.5h earlier due to earlier creation). Both done by ~18:00-18:30 vs factual 19:30, so readiness gain ~1-1.5h. However Assessment queue is the binding constraint: earlier readiness Tuesday evening does not translate to earlier Assessment start because A2 queue shows next slot Wed 09:30 factual. Counterfactual Assessment could start Wed 08:00-09:00 at best (1-1.5h earlier) if it jumps queue by earlier arrival timestamp, otherwise same slot. Final Decision/Notify shift similarly limited to 0-4h. Workaround overhead (15-30 min logging) slightly offsets.

Process-feasibility check: Concurrency allowed by rule 3 because originals not required; both checks before Assessment satisfied. Real-time timestamps required to avoid false concurrency violation of rule 10/12; if batch entry were used, apparent overlap would be audit-invalid. No resource overlap: I2 and D2 are distinct pools. Path Register->Triage->[Identity||Document]->Assessment->Decision->Notify holds.

Best/base/worst case: Best: workaround logged cleanly, Assessment starts Wed 08:00, finish Wed 10:30 (-4h). Base: Assessment still Wed 09:30 due to queue priority by arrival time within same day batch, finish Wed 12:00-13:00 (-1 to -2h). Worst: gain fully absorbed by queue (+0h), plus added logging overhead and concurrent load increases D2/I2 queue for others, with audit risk if workaround not documented.

Evidence that would reverse the conclusion: Assessment dispatch logs showing strict FIFO by readiness timestamp (then concurrency does help), vs batch dispatch daily at 08:00 (then it does not), or D2 service logs showing D2 was actually saturated Tue afternoon (queue forecast understated), or timestamp audit showing workaround entries were batch-entered post hoc, invalidating concurrency claim.

| K-219 D2 substitution | Shifts 4-8h demand from D1 to D2 per case; +30% expected rework adds +6-12h D2/D1 and +2-5h A2 per rework case | D1 queue (13h -> clearing) | D2 queue, Assessment queue (via rework loops), external supplier inbound | Standard document cases waiting for D2, cases needing D1 expertise | Mixed: relieves D1 bottleneck but congests D2 and adds volatile rework | Rework is heavy-tailed (8-36h external) creating bimodal cycle time; small increase in D2 error rate multiplies queue |

**100-case weekly rollout analysis (302 words)**

Analyzing each intervention in isolation holds other arrivals fixed. Rolling the same policy to 100 similar cases in one week breaks that ceteris paribus and reveals interference and bottleneck migration.

Reserving C1 capacity for K-104 is the scarcest resource intervention. C1 is the only fully certified reviewer; the snapshot shows 16-20h queues Monday-Tuesday. One provisional hold is absorbable; one hundred holds is infeasible. Compliance queue would explode from 5-8h to 30-40h, displacing the two urgent cases added Mon 16:00 and violating SLA. Preliminary work that saved 1-3h per case would be negated by 15-20h extra waiting for non-target cases, with system-wide cycle time increasing despite local savings. Benefit is also fragile because early packets are incomplete ~40% of the time, wasting C1 time.

Substituting D2 for D1 (K-219) at scale inverts the bottleneck. Factual D1 is 13h congested, D2 2h idle Monday, so reassignment initially balances load. At 100 cases, D2 queue migrates from 2-4h to 12-16h, while D1 is underutilized. More importantly, D2's higher handwriting error rate means 25-40 rework cases vs 5-10 with D1, each adding a volatile 8-36h external wait and second Document/Assessment cycles. That rework variance dominates throughput and creates heavy-tailed delays that swamp the initial 8-12h start advantage. Assessment queue also grows from the extra loops.

Suppressing the second loop (K-337) at scale frees D1/A1/C1 capacity and avoids weekend external waits – the largest single-case time saving. However it systematically lowers the evidence bar. With 100 high-risk/value cases, even a 2-3% increase in loss given default or appeal rate creates large portfolio exposure that dwarfs throughput gains.

Parallelizing verification (K-411) under a workaround shows timestamp vs true concurrency effects. Hundred concurrent I2+D2 starts earlier shift completions to late Tuesday, bunching arrivals into the Assessment queue which at Wed 08:00 is already 5-7h. The Document creation gain (1-2h) is clipped by Assessment capacity, so system finish time barely moves but Assessment queue grows 30-40%. If workaround logging is batch-entered rather than real-time, the apparent concurrency gain is audit-invalid and masks the real bottleneck, leading to misattributed improvement.

### 7. Final synthesis

The most robust intervention is K-411 parallelization. It is the only one that changes timing without changing resource skill mismatch or decision policy. Its gain is modest (0-4h) because earlier verification readiness is clipped by the Assessment queue, but it preserves compliance, four-eyes, and quality, is fully reversible, and carries negligible risk spillover. It also delivers the clearest learning about bottleneck migration and timestamp integrity versus true concurrency.

The most dangerous despite apparent speed is K-337 suppression of the second rework loop. It offers the largest local counterfactual saving (~4 days, largely the weekend external wait) but does so by truncating the evidence gathering process. The intervention does not merely compress time; it forces a risk-adjusted decision (conditional approve or reject) on incomplete evidence. At single-case level this may be defensible if the remaining inconsistency is immaterial, but as a policy it systematically raises portfolio loss exposure, appeal risk, and audit defensibility. Its irreversibility after Decision makes it the least forgiving, and its benefit is a step-function tied to weekend timing that does not transport to a uniform time saving.

Local counterfactuals are least transportable to system-wide policy for K-104 and K-219. K-104's provisional C1 reservation works for one case by displacing one slot, but at 100 cases the singleton C1 queue explodes and urgent cases are starved – a classic interference violation. K-219's one-case substitution exploits idle D2 capacity, but at scale it migrates congestion to D2 and multiplies heavy-tailed rework, erasing expected gains. Both illustrate that earlier readiness does not equal earlier final completion when downstream capacity is the binding constraint.

Most valuable additional data are fine-grained event timestamps with resource overlap validation, true queue waiting time distributions (not forecasts) per pool at hourly granularity, D1/D2 rework and accuracy stratified by handwriting/complexity, and outcome data linking conditional approvals to loss/appeal rates. External response time distribution for suppliers (including weekend effects) is also critical to calibrate rework tradeoffs.

### 8. Assumption audit

1. Preliminary compliance work can save 1-3h of final review without replacing it – `temporal`
2. Queue forecast error is +-30-50% and earlier readiness may not advance final completion if downstream queue saturated – `temporal`
3. C1 is singleton and reservations displace other urgent compliance cases – `resource`
4. D2 has higher handwriting rework probability (25-40%) than D1 (5-10%) and slower service (4-8h vs 3-6h) – `quality`
5. Four-eyes rule strictly enforced: final Assessment and final Compliance must be different persons – `structural`
6. Workaround concurrency is only valid if logged with real-time timestamps; batch entry creates false concurrency – `behavioral`
7. Suppressing Request More Info changes decision policy to require conditional approve/reject, not silent clean approve – `structural`
8. Scaling to 100 cases creates interference (queue displacement and bottleneck migration) violating the single-case ceteris paribus assumption – `interference`
