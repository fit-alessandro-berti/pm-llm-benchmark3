## 1. Normalization Assumptions

- **Clock-offset direction**: `clock_offset = recorded_clock − true_clock` with offset ∈ [a, b] from source metadata. Therefore true time ∈ [recorded − b, recorded − a].
- **Uncertainty order**: Resolution/rounding/display/measurement uncertainty is applied first, producing a source-clock interval consistent with the displayed value. The clock-offset bound is then applied to that interval. The resulting true local times are converted to UTC via `zoneinfo` IANA rules.
- **HUB (UTC, high-trust)**: Recorded second \(t\) has measurement uncertainty [ \(t\)−0.5 s, \(t\)+0.5 s ]; offset [−1 s, +1 s] yields true UTC interval [ \(t\)−1.5 s, \(t\)+1.5 s ].
- **OPS-BER / LEGACY-BER (Europe/Berlin)**: Floor-to-minute semantics: displayed HH:MM means source clock ∈ [HH:MM:00, HH:MM:59.999…]. Offset then applied. June 2026 dates use CEST (UTC+2). On 2025-10-26 the DST fold (CEST → CET) makes local 02:00–02:59 ambiguous; unions of the two folds are formed and then reduced by ingestion-order constraints.
- **SENSOR (UTC)**: Round-to-nearest-10 s: displayed \(R\) implies source clock ∈ [ \(R\)−5 s, \(R\)+5 s ). Offset [−5 s, +5 s] expands the true interval to [ \(R\)−10 s, \(R\)+10 s ). Timestamps are completion events.
- **VENDOR-NY (America/New_York, EDT = UTC−4 in June)**: Floor-to-minute + offset [−180 s, +180 s ].
- **MOBILE-LON (Europe/London, BST = UTC+1)**: Round-to-nearest-minute → source clock ∈ [displayed−30 s, displayed+30 s ); offset [−300 s, +300 s ]. Additional user-entry delay ≤ 5 min is treated as late recording: the occurrence-time interval is extended earlier by up to 300 s (substantive assumption that recorded time ≥ occurrence time). This is the primary analysis (conservative for start-time SLAs). The alternative of pure recording lag that does not shift occurrence is noted but not used as primary.
- **T-404**: Investigation_Start is missing. It is inferred as Investigation_Complete minus a duration ∈ [18 min, 25 min]. All HUB uncertainties are propagated; the full resulting interval is retained.
- **T-405**: Only the fold combination Alert (CEST) + Investigation_Start (CET) + Containment_Complete (CET) satisfies the ingestion order Alert_Received < Investigation_Start < Containment_Complete. All other fold combinations are eliminated; the surviving intervals are single (non-union).
- **T-407**: Alert_Received is missing. It is bounded by Alert_Sent + latency ∈ [0, 20] min and further constrained by the plausible (but unlogged) causal assumption Receipt ≤ Investigation_Start. Alert_Sent is not definitionally identical to Alert_Received.
- **T-409**: Standard OPS-BER offset is replaced by the weak engineering estimate [−12 min, +12 min] because NTP diagnostics are missing for that hour.
- **Causal / ordering constraints**: Duration intervals are computed only over pairs satisfying end ≥ start when the activity order is definitional or supported by ingestion/causal evidence. When the evidence permits reverse order, negative durations are possible and the result is classified INDETERMINATE.
- **Evidence strength**: High (HUB), Medium (OPS-BER with standard NTP, SENSOR, order-constrained LEGACY-BER), Low (VENDOR-NY, MOBILE-LON, inferred events, weak-offset OPS).
- **Mid-points**: Used only for a secondary, explicitly lossy PM4Py comparison; never as a primary replacement for interval evidence.
- All source bounds are finite; no unbounded intervals appear. SLA limits are hard operational maxima; temporal-profile bands are statistical (mean ± ζ·sd). A case may satisfy one while violating the other.

# 2–3. Interval normalization helpers (resolution first, then offset, then TZ)
# ---------------------------------------------------------------------------
UTC = timezone.utc
BERLIN = ZoneInfo("Europe/Berlin")
NY = ZoneInfo("America/New_York")
LONDON = ZoneInfo("Europe/London")

def hub_interval(rec: str) -> Tuple[datetime, datetime]:
    R = datetime.fromisoformat(rec).replace(tzinfo=UTC)
    return R - timedelta(seconds=1.5), R + timedelta(seconds=1.5)

def ops_ber_interval(rec: str, a: float = -90, b: float = 120) -> Tuple[datetime, datetime]:
    # floor-to-minute
    if len(rec.split()[1].split(":")) == 2:
        rec = rec + ":00"
    local_start = datetime.fromisoformat(rec).replace(tzinfo=BERLIN)
    local_end = local_start + timedelta(seconds=59.999)
    true_lo = (local_start - timedelta(seconds=b)).astimezone(UTC)
    true_hi = (local_end - timedelta(seconds=a)).astimezone(UTC)
    return true_lo, true_hi

def sensor_interval(rec: str) -> Tuple[datetime, datetime]:
    R = datetime.fromisoformat(rec).replace(tzinfo=UTC)
    return R - timedelta(seconds=10), R + timedelta(seconds=10)

def vendor_ny_interval(rec: str) -> Tuple[datetime, datetime]:
    if len(rec.split()[1].split(":")) == 2:

    local_end = local_start + timedelta(seconds=59.999)
    true_lo = (local_start - timedelta(seconds=180)).astimezone(UTC)
    true_hi = (local_end - timedelta(seconds=-180)).astimezone(UTC)
    return true_lo, true_hi

    if len(rec.split()[1].split(":")) == 2:
        rec = rec + ":00"
    center = datetime.fromisoformat(rec).replace(tzinfo=LONDON)
    clock_lo = center - timedelta(seconds=30)
    clock_hi = center + timedelta(seconds=29.999)
    true_lo = (clock_lo - timedelta(seconds=300)).astimezone(UTC)
    true_hi = (clock_hi + timedelta(seconds=300)).astimezone(UTC)
    # occurrence shifted earlier by entry delay
    return true_lo - timedelta(seconds=entry_delay), true_hi

def legacy_fold_intervals(rec: str) -> List[Tuple[datetime, datetime, int]]:
    """Return list of (lo, hi, fold) for both folds."""
    if len(rec.split()[1].split(":")) == 2:
        rec = rec + ":00"
    naive = datetime.fromisoformat(rec)
    local_start = naive
    local_end = naive + timedelta(seconds=59.999)
    true_lo_n = local_start - timedelta(seconds=60)
    true_hi_n = local_end - timedelta(seconds=-60)
    out = []
    for fold in (0, 1):
        lo = true_lo_n.replace(tzinfo=BERLIN, fold=fold).astimezone(UTC)
        hi = true_hi_n.replace(tzinfo=BERLIN, fold=fold).astimezone(UTC)
        out.append((lo, hi, fold))
    return out

def duration_interval(start: Tuple[datetime, datetime], end: Tuple[datetime, datetime]):
    s_lo, s_hi = start
    e_lo, e_hi = end
    return (e_lo - s_hi).total_seconds(), (e_hi - s_lo).total_seconds()

def classify(dur_lo: float, dur_hi: float, acc_lo: float, acc_hi: float, is_upper_limit: bool = False):
    """For SLA (is_upper_limit=True) acceptance is (-inf, limit]; for profile a closed band."""
    if is_upper_limit:
        limit = acc_hi
        if dur_hi <= limit:
            return "CERTAIN_PASS"
        if dur_lo > limit:
            return "CERTAIN_VIOLATION"
        return "POSSIBLE_VIOLATION"
    # two-sided band

        return "CERTAIN_VIOLATION"
    if dur_lo >= acc_lo and dur_hi <= acc_hi:
        return "CERTAIN_PASS"
    return "POSSIBLE_VIOLATION"

## 6. Evidential Sufficiency

For every POSSIBLE_VIOLATION or INDETERMINATE result the minimum additional evidence that would render the classification CERTAIN (PASS or VIOLATION) is listed below. Categories: stronger synchronization evidence, missing-activity evidence, duration evidence, semantic evidence.

- **T-401 S1 / AR-IS**: Stronger synchronization (tighter OPS-BER NTP bound or second-resolution timestamp for Investigation_Start) sufficient to shrink the interval entirely below or above 900 s.
- **T-402 S2 / IS-CC**: Higher-resolution Containment_Complete or modestly tighter clock offset on either endpoint; the present 61.5 s overage is already near the limit.
- **T-403 S1 / AR-IS / AR-CC**: Stronger synchronization of the external VENDOR-NY source (reduce ±180 s) or an independent HUB-grade receipt timestamp; semantic confirmation that the VENDOR time is the true Alert_Received.
- **T-404 S1 / S2 / profiles**: Missing-activity evidence – an explicit Investigation_Start log (or a far tighter duration record than [18, 25] min). Current inference keeps a multi-minute window.
- **T-405 S1 / AR-IS**: Semantic evidence – logged DST-fold indicator (which occurrence of 02:xx) together with second-resolution timestamps; alternatively, native UTC storage that eliminates the fold ambiguity.
- **T-406 (all POSSIBLE)**: Stronger synchronization of the mobile device (reduce ±300 s clock bound) plus semantic clarification of the entry-delay (exact lag or confirmation that none occurred); an independent non-mobile timestamp for Investigation_Start would also suffice.
- **T-407 S1 / AR-IS / AR-CC**: Missing-activity evidence – a receipt acknowledgment that supplies an exact Alert_Received; alternatively a tighter network-latency bound or a logged causal identifier linking Sent → Received → Investigation_Start.

- **General pattern**: Retention of the original unrounded source timestamp together with continuous offset telemetry and resolution metadata would convert the majority of POSSIBLE results into CERTAIN results.

## 7. Governance Recommendation

1. **Canonical storage**: Persist every event in UTC (or with an explicit UTC offset) at the highest available resolution; never store only a rounded local display value.
2. **Raw timestamp retention**: Keep the original displayed string, the source clock resolution, the rounding mode (floor / nearest / exact), and the measurement uncertainty alongside the normalized UTC value.
3. **Source offset telemetry**: Continuously record NTP (or equivalent) offset bounds per system and per hour; surface missing diagnostics (as in T-409) as first-class quality flags.
4. **Resolution & lifecycle metadata**: Attach to every event: resolution (seconds / minutes / 10 s), lifecycle transition (start / complete / other), and whether the timestamp is a user entry.
5. **DST-fold handling**: On transition days log the fold indicator (or the underlying UTC instant) explicitly; never rely solely on a local wall-clock time.
6. **Causal / provenance identifiers**: Emit correlation identifiers that link Alert_Sent → Alert_Received → Investigation_Start, and record ingestion order when absolute clocks are unreliable.
7. **Start / complete semantics**: Distinguish activity start from activity completion in the event schema; treat completion timestamps as upper bounds on activity duration.
8. **Policy for interval overlap**: Treat POSSIBLE_VIOLATION (interval overlap with an SLA limit or profile band) as a review trigger, not automatic enforcement. Legal / contractual SLA enforcement should require CERTAIN_VIOLATION (or CERTAIN_VIOLATION after a documented tolerance). Statistical profile deviations remain advisory.
9. **Mobile / external sources**: Apply elevated scrutiny and larger uncertainty budgets; require secondary corroboration for any SLA decision that rests solely on a mobile or third-party timestamp.
10. **Auditability**: All normalization assumptions (offset direction, entry-delay treatment, fold selection, causal constraints) must be versioned and recorded so that later recomputation under revised assumptions remains possible.
