```
def role_clusters_to_df(clusters):
    rows=[]
    if isinstance(clusters, dict):
        for cluster_id, resources in clusters.items():
            if isinstance(resources, dict): # maybe resource: score
                for r, score in resources.items(): rows.append({"resource": r, "cluster_id": cluster_id, "score": score})
            else:
                for r in resources: rows.append({"resource": r, "cluster_id": cluster_id})
    elif isinstance(clusters, list):
        for i, cluster in enumerate(clusters, start=1):
            if isinstance(cluster, dict):
                for r, score in cluster.items(): rows.append({"resource": r, "cluster_id": f"C{i}", "score": score})

                for r in cluster: rows.append({"resource": r, "cluster_id": f"C{i}"})
```

```
def network_to_df(net, source="source", target="target", weight="weight"):
    if isinstance(net, pd.DataFrame): return net
    if hasattr(net, "edges"):
       return pd.DataFrame([(u,v,d.get(weight,1)) for u,v,d in net.edges(data=True)], columns=[source,target,weight])
    if isinstance(net, dict):
       return pd.DataFrame([(k, v.get("target"), v.get("weight",1)) for k,v in net.items()], columns=[source,target,weight])
    return pd.DataFrame(net, columns=[source,target,weight])
```

```
def role_clusters_to_df(clusters):
    rows = []
    if isinstance(clusters, dict):
        for cluster_id, resources in clusters.items():
            if isinstance(resources, dict):
                for r, score in resources.items():
                    rows.append({"resource": r, "cluster_id": cluster_id, "score": score})
            else:
                for r in resources:
                    rows.append({"resource": r, "cluster_id": cluster_id, "score": np.nan})
    elif isinstance(clusters, list):
        for i, cluster in enumerate(clusters, start=1):
            cid = f"C{i}"
            if isinstance(cluster, dict):
                for r, score in cluster.items():
                    rows.append({"resource": r, "cluster_id": cid, "score": score})
            else:
                for r in cluster:
                    rows.append({"resource": r, "cluster_id": cid, "score": np.nan})
    return pd.DataFrame(rows, columns=["resource", "cluster_id", "score"])
```

```
def network_to_df(net, source="source", target="target", weight="weight"):
    if isinstance(net, pd.DataFrame):
        return net
    if hasattr(net, "edges"):
        return pd.DataFrame(
            [(u, v, d.get(weight, 1)) for u, v, d in net.edges(data=True)],
            columns=[source, target, weight],
        )
    if isinstance(net, dict):
        return pd.DataFrame(
            [(k, v.get("target"), v.get("weight", 1)) for k, v in net.items()],
            columns=[source, target, weight],
        )
    return pd.DataFrame(net, columns=[source, target, weight])
```

# 3. Shadow and bridging roles

- **R07_Giorgio as a commercial shadow role**  
  Giorgio is the clearest commercial shadow. He is formally a Senior Service Agent, but his activity profile includes substantial A7 Pricing Exception Review and A8 Customer Negotiation. The similarity to Fatima is 0.71, and during Fatima’s absence he performed 31 A7 and 18 A8 events.

If not explicitly governed, this can create ambiguity about who owns pricing decisions and who is accountable for exceptions.

- **R13_Mateo as a cross-functional escalation broker**  
  Mateo touches many activities: A13 Reopen, A9 Approval, A6 Security Review, A7 Pricing, A8 Negotiation, A3 Diagnose, A5 Configure, A10 Implement, and A11 Quality Check. His complexity profile is high/critical, and he appears in sequences involving security, commercial, and rework.

His filtering of security referrals reduced false escalation complaints but caused two critical cases to wait more than 2 days. This makes him a valuable broker but also a potential bottleneck or risk point if triage rules are weak.

- **R05_Erik as a rare but critical specialist**

# 5. PM4Py role-discovery and similarity code

The code below is illustrative but uses PM4Py-style function names and parameters. It shows how to format the log, discover behavioral roles, inspect similarity and handover networks, join complexity and substitution indicators, and avoid treating activity-frequency clusters as formal authority.

```python
import pandas as pd
import numpy as np
import pm4py

# =====================================================================
# 1. Load and format the event log
# =====================================================================

df = pd.read_csv("event_log.csv", parse_dates=["time:timestamp"])

required_cols = [
    "case:concept:name",
    "concept:name",
    "time:timestamp",
    "org:resource",
    "case_complexity",
    "customer_segment",
    "product_line",
    "temporary_substitution",
    "escalation_level",
]

df = df[required_cols].dropna(
    subset=["case:concept:name", "concept:name", "time:timestamp", "org:resource"]
)

# Format as a PM4Py event log.
# The try/except is included because extra attribute support may vary by PM4Py version.
try:
    log = pm4py.format_dataframe(
        df,
        case_id="case:concept:name",
        activity_key="concept:name",
        timestamp_key="time:timestamp",
        resource_key="org:resource",
        event_attribute_keys=[
            "case_complexity",
            "customer_segment",
            "product_line",
            "temporary_substitution",
            "escalation_level",
        ],
    )
except TypeError:
    log = pm4py.format_dataframe(
        df,
        case_id="case:concept:name",
        activity_key="concept:name",
        timestamp_key="time:timestamp",
        resource_key="org:resource",
    )

# 2. Discover organizational roles / behavioral clusters
# =====================================================================

    "min_cluster_size": 2,
    "max_cluster_size": 8,
    "similarity_threshold": 0.75,
    "distance": "cosine",
    "case_id_key": "case:concept:name",
    "activity_key": "concept:name",
    "resource_key": "org:resource",
}

role_clusters = pm4py.discover_organizational_roles(log, parameter=role_params)


def role_clusters_to_df(clusters):
    """
    Convert role-discovery output into a DataFrame with resource and cluster_id.
    The exact return type may vary, so this function is intentionally defensive.
    """
    rows = []

    if isinstance(clusters, dict):
        for cluster_id, resources in clusters.items():
            if isinstance(resources, dict):
                for resource, score in resources.items():
                    rows.append(
                        {
                            "resource": resource,
                            "cluster_id": cluster_id,
                            "score": score,
                        }
                    )
            else:
                for resource in resources:
                    rows.append(
                        {
                            "resource": resource,
                            "cluster_id": cluster_id,
                            "score": np.nan,
                        }
                    )

    elif isinstance(clusters, list):
        for i, cluster in enumerate(clusters, start=1):
            cluster_id = f"C{i}"
            if isinstance(cluster, dict):
                for resource, score in cluster.items():
                    rows.append(
                        {
                            "resource": resource,
                            "cluster_id": cluster_id,
                            "score": score,
                        }
                    )
            else:
                for resource in cluster:
                    rows.append(
                        {
                            "resource": resource,
                            "cluster_id": cluster_id,
                            "score": np.nan,
                        }
                    )

    return pd.DataFrame(rows, columns=["resource", "cluster_id", "score"])


role_df = role_clusters_to_df(role_clusters)
role_map = dict(zip(role_df["resource"], role_df["cluster_id"]))

df["role"] = df["org:resource"].map(role_map)

# =====================================================================
# 3. Activity-based resource similarity
# =====================================================================

    log,
    parameter={
        "metric": "cosine",
        "min_similarity": 0.65,
        "case_id_key": "case:concept:name",
        "activity_key": "concept:name",
        "resource_key": "org:resource",
    },
)

if hasattr(similarity, "to_pandas"):
    similarity_df = similarity.to_pandas()
elif isinstance(similarity, dict):
    similarity_df = pd.DataFrame(similarity)
else:
    similarity_df = pd.DataFrame(similarity)

# Inspect high-similarity pairs, but do not merge roles automatically.
# Example pairs to review manually:
# - R03_Chen / R04_Dina: similar activity, different complexity
# - R01_Amira / R02_Ben: similar front-office, different seniority
# - R06_Fatima / R07_Giorgio: commercial shadow, not identical authority
# - R08_Hana / R13_Mateo: both touch escalations, different authority

# =====================================================================
# 4. Handover-of-work, working-together, and subcontracting networks
# =====================================================================

handover = pm4py.discover_handover_of_work_network(
    log,
    parameter={
        "min_frequency": 3,
        "case_id_key": "case:concept:name",
        "activity_key": "concept:name",
        "resource_key": "org:resource",
    },
)

working_together = pm4py.discover_working_together_network(
    log,
    parameter={
        "min_frequency": 3,
        "case_id_key": "case:concept:name",
        "activity_key": "concept:name",
        "resource_key": "org:resource",
    },

subcontracting = pm4py.discover_subcontracting_network(
    log,
    parameter={
        "min_frequency": 2,
        "case_id_key": "case:concept:name",
        "activity_key": "concept:name",
        "resource_key": "org:resource",
    },

def network_to_df(net, source="source", target="target", weight="weight"):
    """
    Convert network output to a simple edge DataFrame.
    The exact network object type may vary by PM4Py version.
    """
    if isinstance(net, pd.DataFrame):
        return net

    if hasattr(net, "edges"):
        return pd.DataFrame(
            [(u, v, d.get(weight, 1)) for u, v, d in net.edges(data=True)],
            columns=[source, target, weight],
        )

    if isinstance(net, dict):
        return pd.DataFrame(
            [
                (k, v.get("target"), v.get("weight", 1))
                for k, v in net.items()
            ],
            columns=[source, target, weight],
        )

    return pd.DataFrame(net, columns=[source, target, weight])


handover_df = network_to_df(handover)
working_df = network_to_df(working_together)
subcontract_df = network_to_df(subcontracting)

# Useful manual checks:
# - R13_Mateo -> R08_Hana on A9: provisional approval followed by recheck
# - R13_Mateo -> R05_Erik on A6: security referral filtering
# - R07_Giorgio -> R06_Fatima or R08_Hana on A7/A8: commercial shadow boundary
# - R11_Kai / R12_Lina -> R01_Amira / R02_Ben / R13_Mateo on rework

# =====================================================================
# 5. Case clustering, variants, and service time
# =====================================================================

cluster_result = pm4py.cluster_log(

    variant_df = pd.DataFrame(variants).T
else:
    variant_df = pd.DataFrame(variants)

    log,
    parameter={
        "case_id_key": "case:concept:name",
        "timestamp_key": "time:timestamp",
        "activity_key": "concept:name",
    },

service_time = pm4py.get_service_time(
    log,
    parameter={
        "case_id_key": "case:concept:name",
        "timestamp_key": "time:timestamp",
        "activity_key": "concept:name",
    },
)

if isinstance(service_time, dict):
    service_time_df = pd.DataFrame(service_time).T
else:
    service_time_df = service_time

# =====================================================================
# 6. Join role-discovery output with case complexity and substitution
# =====================================================================

case_meta = df.groupby("case:concept:name").agg(
    case_complexity=("case_complexity", "max"),
    customer_segment=("customer_segment", "first"),
    product_line=("product_line", "first"),
    temporary_substitution=("temporary_substitution", "max"),
    escalation_level=("escalation_level", "max"),
).reset_index()

df = df.merge(case_meta, on="case:concept:name", how="left")


def bool_share(series):
    return series.astype(str).str.lower().isin(["true", "1", "yes"]).mean()


role_profile = df.groupby("role").agg(
    events=("case:concept:name", "size"),
    cases=("case:concept:name", "nunique"),
    median_complexity=("case_complexity", "median"),
    high_critical_share=(
        "case_complexity",
        lambda s: (pd.to_numeric(s, errors="coerce") >= 0.7).mean(),
    ),
    substitution_share=("temporary_substitution", bool_share),
    escalation_share=(
        "escalation_level",
        lambda s: (pd.to_numeric(s, errors="coerce") >= 2).mean(),
    ),
).reset_index()

activity_mix = df.pivot_table(
    index="role",
    columns="concept:name",
    values="case:concept:name",
    aggfunc="count",
    fill_value=0,
)

activity_mix_norm = activity_mix.div(activity_mix.sum(axis=1), axis=0)

resource_profile = df.groupby("org:resource").agg(
    events=("case:concept:name", "size"),
    cases=("case:concept:name", "nunique"),
    median_complexity=("case_complexity", "median"),
    high_critical_share=(
        "case_complexity",
        lambda s: (pd.to_numeric(s, errors="coerce") >= 0.7).mean(),
    ),
    substitution_share=("temporary_substitution", bool_share),
    escalation_share=(
        "escalation_level",
        lambda s: (pd.to_numeric(s, errors="coerce") >= 2).mean(),
    ),
).reset_index()

resource_profile["role"] = resource_profile["org:resource"].map(role_map)

# =====================================================================
# 7. Authority and recheck indicators
# =====================================================================

# Example: identify provisional approvals by R13_Mateo that are later

a9 = df[df["concept:name"] == "A9 Approval"].sort_values(

a9["is_prelim_recheck"] = (
    (a9["org:resource"] == "R13_Mateo")
    & (a9["next_resource"] == "R08_Hana")
)

prelim_recheck = a9.groupby("org:resource").agg(
    a9_events=("org:resource", "size"),
    prelim_rechecks=("is_prelim_recheck", "sum"),
).reset_index()

# =====================================================================
# 8. Security critical-wait indicator
# =====================================================================

case_start = (
    df.groupby("case:concept:name")["time:timestamp"]
    .min()
    .reset_index(name="case_start")
)

sec = df[df["concept:name"] == "A6 Security Review"].merge(
    case_start, on="case:concept:name"
)

sec["wait_hours"] = (

sec = sec.merge(

sec_critical = sec[sec["case_complexity_num"] >= 0.75]

sec_wait = (

# =====================================================================

reopen = df[df["concept:name"] == "A13 Reopen Request"].merge(

reopen_by_substitution = (

sub_variants = pm4py.get_variants(log_sub)
```

# 6. Operational interpretation

Management should use the discovered structure as a **map of behavioral roles, dependencies, and risk boundaries**, not as an automatic org chart. The goal is to improve staffing, training, risk control, and resilience while preserving formal accountability.

- **Staffing**
  - Keep R01_Amira and R02_Ben as the permanent front-office core for routine validation, standard response, and closure.
  - Use R11_Kai and R12_Lina for low-complexity peak load, but constrain them to simple cases and monitor Validate Entitlement note quality.
  - Balance R03_Chen and R04_Dina so that Chen is not overloaded with critical/security-adjacent cases while Dina handles routine technical work.
  - Protect R05_Erik’s capacity for critical security reviews. Low volume should not be interpreted as low importance.
  - Use R07_Giorgio as a trained backup for R06_Fatima, but with explicit delegation limits and monitoring of pricing exception duration.
  - Ensure R08_Hana has sufficient approval capacity, and define when R13_Mateo may perform preliminary approvals.
  - Use R09_Ivan and R10_Julia as quality gates and knowledge-base owners, not as general technical implementers.
  - Use R13_Mateo for escalations, reopens, and cross-functional routing, not as a permanent substitute for specialist authority.

- **Training**
  - Train temporary agents specifically on entitlement validation quality, because the reopen episode was traced to incomplete Validate Entitlement notes.
  - Develop R04_Dina toward more complex technical cases, but do not assume equivalence with R03_Chen until complexity and risk metrics support it.
  - Formalize R07_Giorgio’s commercial support through pricing training, negotiation guidance, and clear escalation rules to Fatima or Hana.
  - Train R13_Mateo in escalation management, security triage criteria, and the limits of provisional approval.
  - Cross-train a secondary security reviewer for R05_Erik to reduce single-point-of-failure risk.
  - Train R01_Amira in commercial basics if she continues to handle A7/A8 events, or clarify when she should hand those cases to Fatima or Giorgio.

- **Risk control**
  - Define an explicit authority matrix:
    - A6 Security Review: final authority with R05_Erik or formally approved delegate.
    - A7 Pricing Exception Review: final authority with R06_Fatima or formally delegated approver.
    - A9 Supervisor Approval: formal authority with R08_Hana; R13_Mateo may perform only preliminary or delegated approval with recheck.
    - A11 Quality Check: gate authority with R09_Ivan/R10_Julia.
  - Monitor critical security wait times, especially for product_line="Enterprise Security" and high/critical cases.
  - Monitor pricing exception duration during substitutions, because Giorgio’s coverage increased duration from 38 to 74 minutes.
  - Monitor provisional approval recheck rates, because 13 of 21 Mateo approvals were rechecked by Hana.
  - Monitor temporary-agent reopen rates and Validate Entitlement note completeness.
  - Use escalation_level and case_complexity to route cases, not only activity history.

- **Resilience**
  - Create substitution plans that distinguish between **temporary coverage**, **trained backup**, and **formal delegation**.
  - Use R14_Nora for routine intake automation, but keep human validation for exceptions and complex entitlement cases.
  - Use R13_Mateo as an escalation broker to reduce false escalations, but add rules to prevent critical cases from waiting too long during triage.
  - Use R09_Ivan/R10_Julia to convert reopens and quality failures into KB updates, reducing repeat work.
  - Maintain cross-functional visibility through handover and working-together networks so that bottlenecks are visible before they become customer complaints.

- **Cautions about changing staffing based only on mined roles**
  1. **Behavioral clusters are not formal authority.** R13_Mateo performs A9 events, but the data show that many are provisional and later rechecked by R08_Hana. Promoting Mateo based only on A9 frequency could weaken approval accountability.
  2. **Low-frequency critical roles can be misclassified as outliers.** R05_Erik has relatively few events compared with front-office agents, but his work is concentrated in high/critical security cases. Reducing security capacity based on raw activity volume would increase critical risk.
  3. **Temporary substitution is not proof of permanent competence.** R07_Giorgio covered pricing work during Fatima’s absence, but pricing exception duration increased. This shows useful continuity, not full equivalence.
  4. **Similar activity profiles do not imply similar risk exposure.** R03_Chen and R04_Dina have similar activity mixes, but Chen handles more high/critical and security-adjacent cases. Staffing decisions based only on activity similarity could overload junior staff or underuse senior expertise.
