| Element | Definition |
|---|---|
| **Unit of analysis** | One application case (`case:concept:name`), one landmark prefix per case (independence across cases; cluster-robust inference by `org:resource` / branch). |
| **Prediction time (landmark)** | The timestamp of the **K-th pre-outcome event** (K = 5 primary; K  {3, 8} sensitivity), where "pre-outcome" means strictly before the first `Accept / Reject / Withdrawn / Transferred / Contract Signed / Account Activated / Collections Contact / Default Recorded`. A prediction is only ever issued **before a credit decision exists**. |
| **Prediction horizon** | Follow-up from prediction time to `min(activation + 90 days + feed latency, 2026-02-15)`. Reported cumulative incidence at 90 / 180 / 365 days post-prediction, because activation itself may occur weeks after the prediction. |
| **Population** | **All** applications started in the observation window that reach K pre-outcome events — i.e. all four terminal routes, not a convenient subset. Cases terminating before K events are retained in the cohort table as "unscoreable" and reported as a coverage metric. |
| **Outcome variable** | A **cause vector** J over mutually exclusive terminal states: (1) *activated + 90-day default* (event of interest), (2) *activated + no 90-day default*, (3) *rejected*, (4) *withdrawn*, (5) *transferred*, (6) *still open* (censored). |
| **Estimand** | The cause-specific **cumulative incidence function** under the policy actually in force: F(t \| x, regime) = P(T  t, J = 1 \| prefix features x, policy regime), estimated with administrative right-censoring at 2026-02-15. Secondary estimands: F…F and cause-specific hazards. |
| **Label semantics** | `default_90d = 1` contributes to cause 1. `default_90d = 0` contributes to cause 2. **Rejected, withdrawn, transferred, and open cases are assigned competing/censored states — never `default_90d = 0`.** |

**Why this is operationally and statistically defensible.**

1. **It is defined for every application.** "Default" requires credit exposure; rejected and withdrawn applicants never had exposure, so `default_90d = 0` for them is a *category error*, not a negative label. The composite outcome ("did this application end in an activated account that defaulted early?") is a single, observable, well-posed statement about each of the 48,000 cases.
2. **It respects the process.** Activation becomes an explicit intermediate state rather than a silent inclusion filter, so selection-through-activation is modelled rather than assumed away.
3. **It matches the operational use case.** An early-warning model is issued before the decision; the lender's cost function (early defaults on booked accounts) is exactly cause 1's incidence, weighted by `case:requested_amount`.
4. **It is identified under weak assumptions.** Identification requires only independent *administrative* censoring conditional on case start time (deterministic by construction), not ignorability of approval, not positivity, and not a structural credit model.
5. **It is policy-labeled.** F is explicitly indexed by the decision policy in force; it is honest about the fact that changing the policy changes the estimand.

### Credible alternative targets (different questions)

- **(A) P(default | activated, prefix).** Answers *"given this applicant is approved and booked, what is their credit risk?"* — the classic underwriting question. **Different denominator**: it is a conditional distribution over a post-baseline-selected subpopulation. It cannot be issued from the first few events (activation hasn't happened), and naively estimating it requires `activation  future default | observed prefix` plus positivity, both of which fail near the decision boundary (near-certain rejections have no activated analogues, and latent creditworthiness is unobserved). Kept as a **secondary target**, reported alongside the activation CIF and with inverse-probability-of-activation weighting as sensitivity.
- **(B) Time-to-default after activation, right-censored (survival).** Answers *"how fast after booking does default occur?"* Time origin = activation, so the landmark differs per case and is only available **after** the decision — it is a post-booking collections model, not an early warning. Retained as the natural extension for causes 1 vs 2 (discrete-time hazard), and it is the right tool for the 3,600 immature activations.
- **(C) Policy-specific counterfactual: P(default within 90 days if this application were activated | prefix).** Answers *"what would happen under approve-all?"* Requires consistency, no unmeasured confounding of approval, and **positivity** — all violated for rejected/withdrawn prefixes. Explicitly labeled **not identified from these data**; would require a randomized approval experiment among marginal applicants or a validated structural credit model.
- **(D) "Default for every application, rejected = non-default."** **Rejected.** It conflates "no exposure" with "no default," manufactures an easy majority class, inflates accuracy, and produces a number that means nothing under any deployment policy.

## 2. Cohort construction

### As-of rules

| Rule | Statement |
|---|---|
| **A1 – observation window** | Only events with `time:timestamp`  [2024-01-01, 2025-12-31 23:59:59]. |
| **A2 – extract cutoff** | No event with `time:timestamp > 2026-02-15` is ever read. All case-level terminal/censoring status computed as of 2026-02-15. |
| **A3 – feature as-of** | A feature may use only events with `time:timestamp  t_pred` **and** only values whose recorded availability time  `t_pred`. Snapshot fields with unknown provenance are rebuilt from the event stream. |
| **A4 – label as-of** | A label is "known" only if `label_available_at  2026-02-15`, or, when absent, if `activation + 90 + 35 days  2026-02-15` (worst-case feed latency). |
| **A5 – prediction-before-outcome** | Prediction landmarks precede the first decision/terminal activity; cases that decide in fewer than K events are **not scored** by the K-event model. |
| **A6 – canonicalization** | Activity names normalized via an expert-reviewed rename map (2025-10-15 migration) **before** any split; duplicate events (same case, canonical activity, 60 s bin) collapsed with counts logged. |
| **A7 – linkage** | Transferred cases keep their original id as the analysis unit; partner-platform ids are joined through `linked_parent_case` for outcome retrieval only (60%), and are **grouped** so a linked parent never straddles train/test. |

### Inclusion / exclusion

- **Include in the cohort (risk set):** all 48,000 applications. Nothing is excluded from *accounting*.
- **Include in the primary feature table:** cases with  K pre-outcome events and a valid start timestamp.
- **Exclude from the feature table (reported, not hidden):** (i) cases whose outcome occurs before K events ("early terminators" — outcome already decided, no early warning is possible); (ii) rows removed by migration dedup; (iii) partner-platform duplicate ids for linked transfers.
- **Never exclude** because a label is inconvenient, missing, or negative.

## 3. Censoring and missing-label strategy

### The five distinct mechanisms (must not be pooled)

| # | Mechanism | Cases | Nature | Handling |
|---|---|---|---|---|
| 1 | **Ordinary right censoring** | 5,100 open; plus activated cases whose 90-day window has not closed | Event time > censoring time; censoring time = 2026-02-15 | Administrative right-censoring; IPCW / Aalen–Johansen |
| 2 | **Delayed labels** | part of the 3,600 | Horizon closed (or event known) but the external feed arrives 7–35 days later  label *coarsened*, event not censored | Maturity rule using `label_available_at`, else `activation + 125 d`; do not treat as negative |
| 3 | **Selection through activation** | affects the *secondary* target only | `default_90d` exists only after a post-baseline decision  truncation, collider if conditioned naively | Disappears for the primary composite; for the secondary target: report activation CIF, IPAW, explicit positivity caveat |
| 4 | **Transfer** | 2,900 | Dual role: **competing state** for the primary target *and* a **missing-follow-up** mechanism (60% linked) | Cause `transferred` in primary; outcome re-attachment for the 1,740 linked; bounds for the 1,160 unlinked |
| 5 | **Permanently missing outcome feed** | partner-originated activated, TBD count | Missingness depends on `source_system`/channel  **MNAR candidate** | Identified, excluded from complete-case training, handled by pattern-mixture sensitivity; never backfilled to 0 |

### Primary analysis strategy

**Landmark competing-risks analysis on the composite target.**
1. Build person-period (discrete-time) records from `t_pred` to `min(outcome, 2026-02-15)`.
2. Fit a **cause-specific discrete-time hazard model** (gradient boosting or penalized logit on time bins) with causes {1…5} and an indicator for administrative censoring; entry time = prediction time, exit = terminal/censoring time.
3. Report **Aalen–Johansen cumulative incidence** for calibration curves (predicted CIF vs. nonparametric observed CIF), plus IPCW Brier score and time-dependent AUC.
4. Stratify by policy regime (pre/post 2025-07-01) and include regime as a covariate; migration period flagged.

### Sensitivity analyses (all pre-registered)

| SA | Question probed | Method |
|---|---|---|
| S1 | Permanently missing feeds (MNAR) | Pattern-mixture / tipping point: assign a fraction of missing activated labels to default at  × observed rate,   {0.5, 1, 2, 4}; report how cause-1 CIF and top-decile PPV move |
| S2 | Unlinked transfers (40%) | Best/worst-case bounds: all-unlinked-transfer applicants default vs. none; report the width of the identification interval |
| S3 | Linked transfers (60%) | Re-attach partner outcomes and re-estimate  measures how much of S2's width is real information |
| S4 | Selection through activation (secondary target) | Unweighted vs. inverse-probability-of-activation weighted P(default\|activated); report propensity overlap/positivity diagnostics |
| S5 | Regime pooling | Pooled vs. regime-stratified models; pre-policy-only training evaluated post-policy |
| S6 | Migration artifacts | With/without dedup and with/without post-2025-10-15 cases |
| S7 | Delayed labels | Strict maturity (125 d) vs. `label_available_at`-based maturity |

### Assumption status

- **Testable:** administrative censoring time is deterministic given case start (by construction); label-latency distribution by `source_system` (Kaplan–Meier of `label_available_at  (activation+90d)`, testable for equality across feeds); whether null labels were backfilled as 0 (cross-tab with `Default Recorded` events); duplicate/migration defects (row-level counts); whether feature availability  `t_pred` (assertable).
- **Partially testable:** independence of censoring from the event given entry time — can be *refuted* by showing that still-open cases have systematically different prefixes than terminated ones (stall features, queue times), but not proven; missing-at-random of activation given observed covariates — assessable only through balance and overlap diagnostics.
- **Fundamentally untestable from these data:** counterfactual default under forced activation (positivity + no unmeasured confounding); MNAR mechanisms for unlinked transfers and permanently missing feeds; whether a deployed score changes the approval filter or suppresses defaults through intervention (observable only *after* deployment, ideally via a randomized holdout).

## 4. Prefix extraction

**Canonicalization first.** Apply the expert rename map (2025-10-15 migration) to canonical activity names; collapse duplicate events within a 60-second bin per case/activity/source, logging the number removed. Never infer renames from labels. Order by `(case, time:timestamp, source_system)` for deterministic ties.

**Boundary construction (look-ahead proof).**
1. Mark each event `stop  PREFIX_STOP`; compute `first_stop_pos` per case.
2. `pre_outcome = pos < first_stop_pos`; `pre_rank = cumulative count within pre_outcome`.
3. **Prefix events = `pre_outcome & pre_rank < K`.** By construction `max(timestamp in prefix)  t_pred`, so *no* post-prefix event can enter a feature. A runtime assertion enforces this (`post_events == 0`).

**Fixed event-count prefixes (primary).** K  {3, 5, 8}; one landmark per case (the first qualifying prefix) so cases remain independent. Features are aggregated over exactly those K events.

**Elapsed-time prefixes (co-primary / sensitivity).**
- *Credit-review landmark:* all events with `timestamp  (first entry into Credit Review + )`,   {24 h, 72 h}, truncated at the first stop event. Operationally natural: the model fires once the case sits in review.
- *Calendar landmark:* all events within the first 7 days of the case, truncated at the first stop event.
- A time-based prefix naturally includes very short cases that a K=5 rule would drop; report coverage for both.

**Short cases.** Cases whose outcome occurs before K pre-outcome events cannot be scored by the K-event model: they are (i) counted as *unscoreable early terminators* and reported as a coverage metric, (ii) kept in the cohort/censoring bookkeeping, (iii) optionally handled in a variable-length variant (pad + boolean mask + `prefix_length` feature) whose results are reported separately. Their outcomes are **not** used to create "easy negatives."

**Repeated document loops.** Loops are preserved in the event log (they are the signal: rework). Features capture loop count, number of `Request Documents  Credit Review` round trips, oscillation index, distinct activities per loop, total and current-loop sojourn time, and whether the loop is still open at `t_pred`. Counts are `log1p`-transformed and winsorized at the training 99th percentile so a single pathological case cannot dominate. Loop-collapsed variants of the log are used only for descriptive DFG/variant statistics.

**Activity renaming.** Canonicalized before splitting; the frequency of *unmapped* names post-migration is a monitored data-quality metric (unmapped  quarantined, not silently passed).

**Multi-landmark caveat.** If several landmarks per case are used (rolling prediction), cases are no longer independent: use cluster-robust standard errors by case and group all landmarks of a case in the same split.

## 5. Process-aware features

### (a) Static case attributes — known at registration, no look-ahead risk
`case:channel`, `case:region`, `log(case:requested_amount)` + banded amount, `source_system`, partner-origin flag, start day-of-week/month, calendar cohort, **policy regime at start** (pre/post 2025-07-01), **migration regime**.

### (b) Prefix-derived features — computed strictly from events with `timestamp  t_pred`

*Control flow:* prefix length; distinct activities; last (current) activity = current process state; whether Credit Review has been entered; whether a decision was attempted; loop/rework counts and oscillation index; top-N training-set **prefix variant id** (computed on the *prefix*, matched to a variant dictionary built from training data only, with an `unseen_variant` bucket); progress against the training DFG (position in the discovered model, longest-path completion fraction, expected-vs-observed edge deviations).

*Timing:* elapsed hours since start; time since first Credit Review entry; current-state sojourn; inter-arrival mean/sd/p90/max; time since last event (stall indicator); business-hours vs. overnight flag; hour-of-day and weekday of the prediction event; prefix-bounded waiting time (`insert_case_service_waiting_time` on prefix events only).

*Resource / queue:* distinct resources; reassignment count; resource's **open-case workload at `t_pred`** (must be recomputed from events as-of `t_pred`, *not* an extraction-time aggregate); resource tenure = `t_pred  first-seen date` (or hire date from an **effective-dated** HR table); overnight/weekend handling. **Extraction-time "experience" is excluded unless re-derived as-of.**

*Decision-support signals:* `risk_score` **as-of `t_pred`** (last value  `t_pred`), number of updates, delta from first to last value, direction of travel; missingness indicator.

*Derived-as-of repair:* `n_documents_asof` = count of document-upload events  `t_pred` (replaces the nightly snapshot `documents_total`, which may include same-day later uploads).

### (c) Features requiring historical reference data (must be rolling, prior-cases-only)
Resource's historical approval rate and default rate over an **expanding/rolling window ending before the case's start** (computed in group-time folds to prevent same-period leakage); variant frequency in the prior 90 days; monthly portfolio default base rate; policy-version-specific expected default rate; queue-length baselines per region/channel. All reference tables are versioned by "information available at case start."

**Explicitly excluded from all groups:** `final_limit`, `decision_reason`, `collection_status`, future events (`Contract Signed`, `Account Activated`, `Collections Contact`, `Default Recorded`), `documents_total`, extraction-time resource experience, `default_90d`, `label_available_at`, `data_extract_time`.

## 6. Leakage audit

| Feature or data element | Leakage or bias risk | Valid availability rule | Keep/repair/drop | Rationale |
|---|---|---|---|---|
| `final_limit` | Populated only after the final credit decision  encodes the outcome of the process being predicted; near-perfect proxy for Accept/Reject | Value available only at/after decision | **Drop** | Post-decision; using it would make the model a decision classifier, not an early warning |
| `decision_reason` | Written at or after Accept/Reject; textual proxy for the decision and often for risk grade | Same as above | **Drop** | Only exists after the decision that ends the prediction window |
| `collections_status` | Updated after activation and "may directly reveal default"  direct label proxy | Any value after activation | **Drop** | Post-outcome; would leak the target |
| Future events (`Contract Signed`, `Account Activated`, `Collections Contact`, `Default Recorded`) | Events after `t_pred`; `Account Activated` also silently conditions on selection | `timestamp  t_pred` and `pos < first_stop_pos` | **Drop (structural)** | Enforced by the `pre_outcome & pre_rank < K` boundary + runtime assertion `post_events == 0` |
| `documents_total` (nightly snapshot) | May include documents uploaded *later on the same calendar day* than `t_pred`  future information in a same-day prefix | Only values with recorded availability  `t_pred` | **Repair**: recompute as event-derived count of document uploads  `t_pred` | Snapshot granularity exceeds prediction granularity; event log is the authoritative as-of source |
| `risk_score` (updated at several events) | Using the extraction-time/latest value injects post-decision re-score; using the first value discards signal | Last value with `timestamp  t_pred` | **Repair**: as-of join; keep `risk_score_at_pred`, `n_risk_updates`, delta | Legitimate as a *prefix* trajectory; illegitimate as a final snapshot |
| Resource experience (stored at extraction time) | Future information (experience accrued after `t_pred`); also correlates with period  period proxy | Experience as-of `t_pred` from effective-dated data | **Repair** to `tenure = t_pred  hire/first-seen`; otherwise **drop** | Extraction-time values are systematically larger for older cases and confound regime with resource effects |
| `label_available_at`, `default_90d` | The label itself plus its availability timestamp reveals period/maturity; used naively it acts as a period proxy that predicts "is this case labeled" | Target + censoring bookkeeping only | **Keep as target/censoring vars; never as features** | Would let the model learn label availability rather than risk |
| `data_extract_time` | Constant per file, but paired with `start` it encodes label maturity  period proxy | Cutoff bookkeeping only | **Drop** | Non-predictive in deployment; leaks the snapshot structure |
| Full-case aggregates (total events, final variant, "did loop again") | Computed over the whole case, including after `t_pred` | Aggregates over prefix events only | **Repair**: recompute on `pref_ev` | Classic PM leakage: aggregate features silently span the whole trace |
| Activity names (pre-normalization) | Post-migration names identify the period; model learns "2025-10+" instead of behavior; duplicates double-count rework | Canonical name map applied before splitting | **Repair**: rename map + 60 s dedup, counts logged | Migration artifacts are pure period proxies |
| `linked_parent_case` / partner ids | Same real case appears under two ids  can straddle splits (train on one id, test on the twin) | Group split by linked parent | **Repair**: group assignment | Direct train/test contamination for the 60% linked transfers |
| `case:channel` / `source_system` | Not leakage, but correlate with *label availability* (partner feed missingness)  model may predict missingness, and calibration differs by feed | Keep, but stratify calibration and monitor | **Keep with subgroup calibration** | Feature is legitimate; the risk is conflating feed completeness with credit risk |

## 7. Validation design

### Why a random case split is misleading here

1. **Policy change (2025-07-01).** `P(activation | prefix)` and `P(default | activation, prefix)` both changed. A random split puts both regimes in train and test, so the model is *tested on the same selection mechanism it was fit on* and scores well, while the real question is generalization to the new regime.
2. **Migration (2025-10-15).** Renamed activities and duplicates are period artifacts; a random split lets the model exploit them as period fingerprints that happen to correlate with labels in-sample.
3. **Label maturity is a function of case start time.** Early cases are almost always matured; late cases are mostly censored. A random split mixes them, so "label available"  "started early"  "old policy." The model can reach high apparent accuracy by learning **calendar time**, not credit risk — a silent label-availability leak.
4. **Dependence.** Resource behavior, queue conditions, and channel campaigns are autocorrelated across adjacent cases; a random split violates iid and understates variance. Linked transferred cases can literally appear on both sides.
5. **Calibration drift.** Random validation measures interpolation, whereas deployment is extrapolation forward in time under a new policy.

### Primary scheme: temporal splits by case start + rolling-origin backtesting

| Split | Case start window | Role | Maturity status at 2026-02-15 |
|---|---|---|---|
| **Train** | 2024-01-01  2025-03-31 | Fit feature reference tables, variant dictionary, DFG, model | Fully mature |
| **Validation** | 2025-04-01  2025-06-30 | Model selection, thresholding, calibration fit | Mature |
| **Test A** | 2025-07-01  2025-09-30 | Post-policy, pre-migration, forward test | **Partially censored**  evaluate with IPCW only; report maturity fraction |
| **Test B** | 2025-10-01  2025-12-31 | Post-migration | **Heavily censored**  process/DGF drift monitoring + matured-subset analysis only; **calibration deferred to the next snapshot (re-run after 2026-04-30)** |

- Splits are assigned by **case start**, grouped by `linked_parent_case`.
- **Backtesting:** rolling origins at 2024-07-01, 2025-01-01, 2025-07-01. At each origin *o*, only cases with `label_available_at  o` may be used for training — this simulates exactly what would have been known then and prevents hindsight maturity from inflating backtest scores.
- **Baseline only:** `pm4py.split_train_test` may be reported for reference, explicitly labeled as an optimistic, regime-mixing baseline.

### Handling known changes

- **Policy change:** regime indicator as a feature; metrics reported pre/post 2025-07-01; pooled vs. stratified model comparison; Test A is the honest estimate for the regime a new deployment would face.
- **Migration:** canonicalization + dedup *before* splitting; assert no case id in two splits; report the share of unmapped activities post-2025-10-15.
- **Label maturity:** training uses maturity-aware as-of labels; evaluation on immature cases uses censoring-aware metrics only — **never** treat an immature case as a negative.

### Metrics (matched to the competing-risks + censoring design)

- **Discrimination:** IPCW time-dependent AUC / cumulative-dynamic AUC at 90, 180, 365 days for cause 1; cause-specific concordance.
- **Calibration:** calibration-in-the-large, calibration slope, ICI/E50/E90, and reliability plots of predicted CIF vs. **Aalen–Johansen** observed CIF, computed with IPCW weights on censored cases.
- **Overall accuracy:** right-censored/competing-risk **Brier score** with IPCW; multiclass log score over the cause vector.
- **Operational:** precision@k / lift at the collections-review capacity constraint, PPV/NPV at the chosen threshold, expected loss =  `requested_amount` × PD × LGD, and **prediction coverage** (% of applications where a pre-decision prediction is issued).
- **Uncertainty:** case-level bootstrap CIs, clustered by resource/branch; report counts alongside every subgroup metric.
- **Subgroups:** `case:channel` (partner vs. direct), region, amount bands, policy regime, migration period, prefix length, resource tenure, and — critically — **label-availability subgroup** (mature vs. censored), since calibration on censored cohorts is the main hidden failure mode.
- **Distribution shift:** PSI/KS on prefix features traintest; variant-frequency divergence and novel-variant rate; DFG edge-frequency drift; label-latency shift by feed; unmapped-activity rate. Thresholds trigger re-fit or abstention, not silent acceptance.

## 8. Limitations and decision-use boundary

**What the study can claim.**
- A *predictive association* between early process behavior (rework loops, stalls, queue times, resource patterns, risk-score trajectory) and the **policy-conditional composite outcome** "activated + 90-day default," calibrated for matured cohorts within the observed regimes.
- Relative, policy-indexed incidence: under the decision policy in force during 2024–2025, applications with prefix characteristics *x* ended in early defaults at rate F.
- Honest uncertainty: identification intervals for unlinked transfers and missing partner feeds; coverage and censoring fractions reported alongside every metric.

**What it cannot claim.**
- **Not counterfactual default risk.** It cannot say what a rejected or withdrawn applicant's default rate would have been — that quantity is undefined without an activation policy and unidentifiable without positivity and no unmeasured confounding. The informal "rejected = non-default" reading is explicitly rejected.
- **Not a causal effect.** The model estimates association; it does not establish that acting on the score reduces defaults.
- **Not transportable across policies.** F changes if the approval policy changes; results from pre-2025-07-01 do not certify post-change performance.
- **Not calibrated for late-2025 cohorts** until the next maturity snapshot.
- **Not complete for partner platforms** — 40% of transfers and possibly partner-originated activations have no outcome.
- **Not a fairness certificate:** channel/region features may proxy protected attributes; subgroup calibration must be reviewed against local regulation before use in any adverse decision.

**Distinguishing the three layers.**
1. **Predictive association** — supported by the design (as-of prefixes, temporal validation, censoring-aware metrics).
2. **Selection effects** — acknowledged and quantified: activation is a post-baseline filter; the 21,600 labeled cases are a policy-selected 45% of applications; partner feeds are differentially missing.
3. **Counterfactual default risk** — **not identified**; would require randomized approval among marginal applicants or a validated structural model, and must never be presented as a model output.

**At least three ways deployment changes the data-generating process.**
1. **Score-guided approval changes the selection filter.** Who gets activated becomes a function of the score, so `P(default | activated, features)` shifts, the training distribution no longer describes the deployment population, and calibration drifts immediately (performative prediction). The model's own rejections also shrink the labeled denominator.
2. **Early-warning interventions suppress the label.** Collections outreach, extra document requests, or manual review triggered by a high score can *prevent* the default it predicted, so the outcome becomes endogenous to the model — observed performance degrades even while the model "works." Requires shadow mode, champion/challenger, or a randomized holdout to measure true impact.
3. **Process behavior changes.** Model-driven extra document requests create new rework loops and longer prefixes, shifting the feature distribution the model was trained on; resource workload patterns change as staff anticipate scoring; channel mix may migrate toward partner origins with worse feed completeness, changing the *missingness* mechanism as well as the covariate shift.
4. *(Additional)* **Threshold gaming and portfolio drift:** teams may route borderline cases to different channels to influence the score, and marketing may expand into segments with no historical support — both require abstention/OOD rules.

**Boundary statement for the lender:** this model is a *prioritization* tool for review and monitoring capacity under the current policy, with reported coverage, calibration, and identification intervals. It is not an approval engine, not a counterfactual risk engine, and not valid for decisions about applicants whose credit outcome was never observed.

```python
# ------------------------------------------------------------------- configuration
CSV = "applications_events.csv"
EXTRACT = pd.Timestamp("2026-02-15")                     # data extraction date: every as-of rule keys here
WIN = (pd.Timestamp("2024-01-01"), pd.Timestamp("2025-12-31 23:59:59"))
POLICY_CHANGE, MIGRATION = pd.Timestamp("2025-07-01"), pd.Timestamp("2025-10-15")
PRED_K, OUT_H, FEED_MAX = 5, 90, 35                      # prefix length | 90d horizon | feed lag (days)
ACT = "Account Activated"
PREFIX_STOP = {"Accept", "Reject", "Withdrawn by applicant", "Transferred to partner",
               "Contract Signed", ACT, "Collections Contact", "Default Recorded"}   # prediction must precede these
TERMINAL2STRATUM = {"Reject": "rejected", "Withdrawn by applicant": "withdrawn",
                    "Transferred to partner": "transferred", ACT: "activated"}
# ASSUMPTION: expert-reviewed rename map for the 2025-10-15 migration; never inferred from labels
RENAME = {"Identity Check": "Identity/KYC Check", "KYC Review": "Identity/KYC Check",
          "Doc Request": "Request Documents", "Reject (new)": "Reject"}
FORBIDDEN = {"final_limit", "decision_reason", "collection_status", "default_90d",
             "label_available_at", "data_extract_time", "documents_total"}

# ------------------------------------------------------------------- 1. read + as-of filter
df = pd.read_csv(CSV, parse_dates=["time:timestamp", "label_available_at", "data_extract_time"])
df = df[df["time:timestamp"].between(*WIN) & (df["time:timestamp"] <= EXTRACT)]     # A1 / A2
df["concept:name"] = df["concept:name"].replace(RENAME).str.strip()                # A6 canonicalize
df = df.sort_values(["case:concept:name", "time:timestamp", "source_system"], kind="mergesort")
df["_s"] = df["time:timestamp"].values.astype("datetime64[s]")                     # migration duplicates
dup = df.groupby(["case:concept:name", "concept:name", pd.Grouper(key="_s", freq="60s")]).cumcount() > 0
print("duplicate rows dropped (migration dedup):", int(dup.sum()))
df = df[~dup].drop(columns="_s")

log = pm4py.format_dataframe(df, case_id="case:concept:name", activity_key="concept:name",
                             timestamp_key="time:timestamp")
if "case:concept:name" not in log.columns:            # PM4Py versions differ: id may live in the index
    log["case:concept:name"] = log.index.get_level_values(0)
log = log.reset_index(drop=True)
log["pos"] = log.groupby("case:concept:name").cumcount()                            # deterministic ties
log["stop"] = log["concept:name"].isin(PREFIX_STOP)

# ------------------------------------------------------------------- 2. prefix boundary (no look-ahead)
first_stop = log[log["stop"]].groupby("case:concept:name")["pos"].min()
log["first_stop_pos"] = log["case:concept:name"].map(first_stop)
log["pre_outcome"] = log["pos"] < log["first_stop_pos"].fillna(np.inf)              # A5
log["pre_rank"] = log.loc[log["pre_outcome"]].groupby("case:concept:name").cumcount()
# invariant: any event used later satisfies pre_outcome & pre_rank < PRED_K  =>  ts <= t_pred
pref_ev = log[log["pre_outcome"] & (log["pre_rank"] < PRED_K)]

# ------------------------------------------------------------------- 3. case-level as-of view
case = log.groupby("case:concept:name").agg(start=("time:timestamp", "min"),
                                            last_event=("time:timestamp", "max"),
                                            n_events=("time:timestamp", "size"))
fst = (log[log["stop"]].groupby("case:concept:name").first()[["concept:name", "time:timestamp"]]
       .rename(columns={"concept:name": "outcome_activity", "time:timestamp": "outcome_time"}))
case = case.join(fst)
case = case.join(log[log["concept:name"] == ACT].groupby("case:concept:name")["time:timestamp"]
                 .min().rename("activation_time"))
case["terminal"] = case["outcome_activity"].map(TERMINAL2STRATUM).fillna("open")
case["label_ready_at"] = log.groupby("case:concept:name")["label_available_at"].max()
# A4 maturity: activated -> 90d horizon + up to 35d feed lag; other terminals known at the terminal event
case["mature"] = np.where(case["terminal"] == "activated",
                          (case["activation_time"] + pd.Timedelta(days=OUT_H + FEED_MAX)).le(EXTRACT)
                          | case["label_ready_at"].le(EXTRACT),
                          case["outcome_time"].le(EXTRACT))
case["censored"] = ~case["mature"]                                                 # right-censor flag
# SURVIVAL-HOOK: attach (entry=start, exit=min(outcome_time, EXTRACT), cause, censor) here to feed an
# Aalen-Johansen CIF / cause-specific discrete-time hazard. PM4Py has no survival API: use lifelines/sksurv.
case["is_default"] = (log[log["concept:name"] == "Default Recorded"].groupby("case:concept:name").size()
                      .gt(0).reindex(case.index).fillna(False))
case["stratum"] = np.select(            # rejected/withdrawn/transferred/open are NEVER coded as non-default
    [case["terminal"].eq("open"), case["terminal"].eq("activated") & case["censored"], case["is_default"],
     case["terminal"].eq("activated"), case["terminal"].eq("rejected"), case["terminal"].eq("withdrawn")],
    ["open_right_censored", "activated_label_not_mature", "activated_default_90d",
     "activated_no_default", "rejected", "withdrawn"], default="transferred")
flow = case["stratum"].value_counts().rename_axis("stratum").reset_index(name="n")
print("\nCOHORT FLOW as of", EXTRACT.date()); print(flow.to_string(index=False))
print("total =", int(flow["n"].sum()), "(must equal 48,000 on the full export)\n")
# audit: partner feeds backfilled as 0? -> cross-tab label vs channel among matured activations
print(case[(case["terminal"] == "activated") & case["mature"]]
      .groupby("case:channel")["is_default"].agg(["size", "mean"]).round(4).to_string())

# ------------------------------------------------------------------- 4. prefix feature table (as-of t_pred)
feat = pref_ev.groupby("case:concept:name").agg(
    n_events=("pos", "size"), n_distinct_act=("concept:name", "nunique"), last_act=("concept:name", "last"),
    n_doc_loops=("concept:name", lambda s: int((s == "Request Documents").sum())),
    first_ts=("time:timestamp", "min"), last_ts=("time:timestamp", "max"))
feat["t_pred"] = feat["last_ts"]                                                  # landmark = K-th pre-outcome event
feat = feat.join(case[["start", "terminal", "stratum", "censored", "outcome_time", "label_ready_at"]])
# as-of joins: only values recorded at/before t_pred (never the extraction-time snapshot)
feat = feat.join(pref_ev.sort_values("time:timestamp", kind="mergesort").groupby("case:concept:name")
                 ["risk_score"].last().rename("risk_score_at_pred"))
feat = feat.join(pref_ev.groupby("case:concept:name")["risk_score"].count().rename("n_risk_updates"))
feat["elapsed_h"] = (feat["t_pred"] - feat["start"]).dt.total_seconds() / 3600
# repairs nightly-snapshot `documents_total` with a prefix-bounded event count (A3)
feat["n_documents_asof"] = (pref_ev[pref_ev["concept:name"].str.contains("Document", case=False)]
                            .groupby("case:concept:name").size().reindex(feat.index).fillna(0).astype(int))
# context known at prediction time only; regime is a *feature*, never a label proxy
feat["policy_regime"] = np.where(feat["t_pred"] >= POLICY_CHANGE, "post_2025_07", "pre_2025_07")
feat["migration_regime"] = np.where(feat["t_pred"] >= MIGRATION, "post_2025_10", "pre_2025_10")
# PRIMARY validation: temporal split by case START. ASSUMPTION: group on linked_parent_case first so a
# transferred case never straddles splits. pm4py.split_train_test is a random, regime-mixing BASELINE only.
feat["split"] = np.select([feat["start"] <= pd.Timestamp("2025-03-31"),
                           feat["start"] <= pd.Timestamp("2025-06-30"),
                           feat["start"] <= pd.Timestamp("2025-09-30")],
                          ["train", "valid", "test_pre_migration"], default="test_post_migration")

# ------------------------------------------------------------------- 5. leakage audit
leaked = sorted(set(feat.columns) & FORBIDDEN)
chk = pref_ev.merge(feat["t_pred"], left_on="case:concept:name", right_index=True, how="left")
post_events = int((chk["time:timestamp"] > chk["t_pred"]).sum())                  # must be 0
coverage = 100.0 * len(feat) / log["case:concept:name"].nunique()                 # early terminators unscoreable
print("\nLEAKAGE AUDIT | forbidden cols:", leaked or "none",
      "| events used after t_pred:", post_events, "| K=%d prefix coverage: %.1f%%" % (PRED_K, coverage))
assert not leaked and post_events == 0, "post-prefix data entered the feature table"
print(feat["split"].value_counts().to_string())
print(pd.crosstab(feat["split"], feat["stratum"]).to_string())                    # censoring mix per split

# ------------------------------------------------------------------- 6. PM4Py tooling, prefixes only
prefixes = pm4py.get_prefixes_from_log(pref_ev, case_id="case:concept:name", activity_key="concept:name",
                                       timestamp_key="time:timestamp", max_len=PRED_K)   # fixed-length benchmark
dfg, s, e = pm4py.discover_dfg(pref_ev, case_id="case:concept:name", activity_key="concept:name",
                               timestamp_key="time:timestamp")                    # control-flow reference (descriptive)
variants = pm4py.get_variants(pref_ev, activity_key="concept:name", case_id="case:concept:name",
                              timestamp_key="time:timestamp")                     # variant drift: train vs test
tf = pm4py.extract_temporal_features_dataframe(pref_ev.copy(), case_id_key="case:concept:name",
        activity_key="concept:name", timestamp_key="time:timestamp")              # calendar features, prefix only
wt = pm4py.insert_case_service_waiting_time(pref_ev.copy(), case_id_key="case:concept:name",
        activity_key="concept:name", timestamp_key="time:timestamp")              # prefix-bounded sojourn/queue proxy
# NEXT: fit a cause-specific discrete-time hazard on `feat` + (exit, cause, censor) from case; calibrate the
# CIF against Aalen-Johansen on the train split; report IPCW Brier / time-dependent AUC on the temporal test.
```

**Notes on the skeleton.** It (i) reads and time-filters the CSV, (ii) canonicalizes and de-duplicates migration artifacts, (iii) calls `pm4py.format_dataframe`, (iv) builds case-level start / activation / terminal / censoring / label-maturity fields as of a configurable `EXTRACT`, (v) enforces the prefix boundary before any feature is computed, (vi) splits temporally by case start, (vii) demonstrates `pm4py.get_prefixes_from_log` for fixed-length prefixes plus `discover_dfg`, `get_variants`, `extract_temporal_features_dataframe`, and `insert_case_service_waiting_time` — all applied to **prefix events only**, with interpretations limited to control-flow description, variant drift, calendar features, and prefix-bounded waiting time, (viii) prints cohort counts and a leakage audit with a hard assertion, and (ix) marks the assumptions and the point at which external survival/competing-risk tooling (not PM4Py) must attach.
