### Section 1: Modeling assumptions

- Object types (exact capitalization): `Order`, `Item`, `Package`, `Delivery`, `Invoice`, `Payment`. OIDs: O100, O200; I1–I3; P1, P2; D1, D2; V1; M1, M2. Object IDs are globally unique across types (OCEL 2.0 best practice since oid is the key).
- E2O qualifier vocabulary (event  object):
  - `creates`: Create Order  Order
  - `adds_to` / `adds`: Add Item  Order (`adds_to`), Add Item  Item (`adds`)
  - `reserves`: Reserve Stock  Item
  - `shared_by`: Reserve Stock  Order (event operationally shared)
  - `packs`: Pack Package  Package; `includes`: Pack Package  Item; `involves`: Pack Package  Order (only where narrative asserts it, i.e., P1)
  - `dispatches`: Dispatch Package  Package; `loads`: Dispatch Package  Delivery
  - `issues`: Issue Invoice  Invoice; `bills`: Issue Invoice  Order
  - `records`: Record Payment  Payment; `partially_settles` / `completes_settlement`: Record Payment  Invoice
  - `confirms`: Confirm Delivery  Delivery
  - `closes`: Close Order  Order
- O2O direction: `ocel:oid` is subject/container/upstream; `ocel:oid_2` is object/contained/downstream; qualifier reads left-to-right: Order `contains` Item; Package `packs` Item; Delivery `carries` Package; Invoice `bills` Order; Payment `partially_settles`/`completes_settlement` Invoice.
- Logistics/financial events  Orders/Items: policy = source-minimal with explicit co-involvements. Dispatch/Confirm/Payment events relate only to their directly named operands (Package+Delivery; Delivery; Payment+Invoice). Order involvement of those events is derived analytically from O2O and kept in a separate, clearly-marked table. Exception: Reserve Stock `shared_by` both orders and Pack P1 `involves` both orders are asserted as source facts because the narrative states them explicitly. Payment settlement assumption: M1 = `partially_settles` (100 of, assumed, 250 total); M2 = `completes_settlement` (assumption: 100+150 fully settles V1; if the invoice were known to remain open, M2 would also be `partially_settles`). Amounts live in `events.amount` as event attributes; no `Amount` object type.
- Prevention of confusion: separate DataFrame names (`relations` = source; `relations_derived` = analytical), qualifier prefix `derived:`, provenance column, derived table never passed to OCEL, and validators that assert the source table contains no `derived:` qualifiers.
- Version assumptions: pm4py  2.7 (has `discover_otg`, `discover_etot`, `discover_ocdfg`, `discover_oc_petri_net`, `ocel_flattening`, `ocel_object_type_activities`, `ocel_objects_interactions_summary`, and the DataFrame-based `OCEL` constructor in `pm4py.objects.ocel.obj`). The OCEL construction is isolated to one line; if the version's constructor requires e.g. `parameters` with column names or a different import path, only that line changes — data semantics untouched. Timestamps are pandas tz-aware UTC; if a pm4py release drops tz info internally, comparisons still use our DataFrames.

Validation function:

```python
def run_validation(events, objects, relations, o2o) -> None:
    """Structural + referential checks. Raises AssertionError on any violation."""
    checks = []

    def check(name, condition):
        assert condition, f"VALIDATION FAILED: {name}"
        checks.append(name)

    check("event ids unique", events["ocel:eid"].is_unique)
    check("object ids unique", objects["ocel:oid"].is_unique)
    check("every event has >=1 relation",
          set(events["ocel:eid"]) == set(relations["ocel:eid"]))
    check("no orphan event ids in relations",
          set(relations["ocel:eid"]).issubset(set(events["ocel:eid"])))
    known_oids = set(objects["ocel:oid"])
    check("no orphan object ids in relations",
          set(relations["ocel:oid"]).issubset(known_oids))
    check("no orphan object ids in o2o (column 1)",
          set(o2o["ocel:oid"]).issubset(known_oids))
    check("no orphan object ids in o2o (column 2)",
          set(o2o["ocel:oid_2"]).issubset(known_oids))

    # activity/timestamp consistency between events and relations
    m = relations.merge(events, on="ocel:eid", how="left", suffixes=("", ":ev"))
    check("activity consistent between events and relations",
          (m["ocel:activity"] == m["ocel:activity:ev"]).all())
    check("timestamp consistent between events and relations",
          (m["ocel:timestamp"] == m["ocel:timestamp:ev"]).all())
```

```python
    check("object IDs unique", objects["ocel:oid"].is_unique)

          set(relations["ocel:eid"]).issubset(ev_ids))
    check("every event participates in >= 1 relation",
          set(relations["ocel:eid"]) == ev_ids)
    check("relations reference only known object IDs",

          set(o2o["ocel:oid_2"]).issubset(obj_ids))

                        suffixes=("", ":from_events"), validate="many_to_one")

          (j["ocel:activity"] == j["ocel:activity:from_events"]).all())
    check("relation timestamps equal event timestamps",
          (j["ocel:timestamp"] == j["ocel:timestamp:from_events"]).all())

    check("at most one qualifier per (event, object) pair",
          not relations.duplicated(subset=["ocel:eid", "ocel:oid"]).any())
```

```python
def derive_order_involvement(events, relations, o2o):
    """
    Walk the O2O graph to derive, for every event that touches a Package, a
    Delivery or an Invoice, the Orders that are operationally affected:

        Delivery -carries-> Package -packs-> Item <-contains- Order
        Invoice  -bills------------------------------>  Order

    This answers questions like "which Orders does confirming D1 affect?".
    The result is an ANALYTICAL artefact:
      * qualifier prefix 'derived:' marks it as non-source,
      * it is never merged into `relations`,
      * it is never passed to the OCEL constructor.
    """
    orders_of_item = {}     # Item      -> {Order}
    items_of_pkg = {}       # Package   -> {Item}
    pkgs_of_dlv = {}        # Delivery  -> {Package}
    orders_of_inv = {}      # Invoice   -> {Order}
    for s, t, q in zip(o2o["ocel:oid"], o2o["ocel:oid_2"], o2o["ocel:qualifier"]):
        if q == "contains":
            orders_of_item.setdefault(t, set()).add(s)
        elif q == "packs":
            items_of_pkg.setdefault(s, set()).add(t)
        elif q == "carries":
            pkgs_of_dlv.setdefault(s, set()).add(t)
        elif q == "bills":
            orders_of_inv.setdefault(s, set()).add(t)

    rel_by_event = relations.groupby("ocel:eid")["ocel:oid"].agg(set).to_dict()

    rows = []
    for eid in events["ocel:eid"]:
        touched = rel_by_event.get(eid, set())
        derived_orders = set()
        for oid in touched:
            if oid in items_of_pkg:                       # event touches a Package
                for item in items_of_pkg[oid]:
                    derived_orders |= orders_of_item.get(item, set())
            if oid in pkgs_of_dlv:                        # event touches a Delivery
                for pkg in pkgs_of_dlv[oid]:
                    for item in items_of_pkg.get(pkg, set()):
                        derived_orders |= orders_of_item.get(item, set())
            if oid in orders_of_inv:                      # event touches an Invoice
                derived_orders |= orders_of_inv[oid]
        for order in sorted(derived_orders - touched):
            rows.append((eid, order, "Order", "derived:order_involvement"))

    derived = pd.DataFrame(rows, columns=["ocel:eid", "ocel:oid", "ocel:type", "ocel:qualifier"])
    if derived.empty:
        return derived
    return (derived
            .merge(events[["ocel:eid", "ocel:activity", "ocel:timestamp"]],
                   on="ocel:eid", how="left", validate="many_to_one")
            [REL_COLS]
            .reset_index(drop=True))

print("\nDerived order involvement (qualifier 'derived:order_involvement'):")
if relations_derived.empty:
    print("  (none)")
else:
    print(relations_derived.to_string(index=False))
```

```python
# --------------------------------------------------------------------------- #
# 5) VALIDATION -- structural and referential integrity                       #
# --------------------------------------------------------------------------- #
def validate(events, objects, relations, o2o) -> None:
    """Assert the mandatory OCEL invariants; raise AssertionError on violation."""
    passed = []

    def check(name: str, condition) -> None:
        assert condition, f"VALIDATION FAILED: {name}"
        passed.append(name)

    check("event IDs are unique", events["ocel:eid"].is_unique)
    check("object IDs are unique", objects["ocel:oid"].is_unique)

    event_ids = set(events["ocel:eid"])
    object_ids = set(objects["ocel:oid"])

    check("no orphan event IDs in relations",
          set(relations["ocel:eid"]).issubset(event_ids))
    check("every event participates in at least one relation",
          set(relations["ocel:eid"]) == event_ids)
    check("no orphan object IDs in relations",
          set(relations["ocel:oid"]).issubset(object_ids))
    check("no orphan object IDs in o2o (ocel:oid)",
          set(o2o["ocel:oid"]).issubset(object_ids))
    check("no orphan object IDs in o2o (ocel:oid_2)",
          set(o2o["ocel:oid_2"]).issubset(object_ids))

    # activity / timestamp consistency between events and relations
    joined = relations.merge(
        events, on="ocel:eid", how="left",
        suffixes=("", ":event"), validate="many_to_one",
    )
    check("relation activities match the events table",
          (joined["ocel:activity"] == joined["ocel:activity:event"]).all())
    check("relation timestamps match the events table",
          (joined["ocel:timestamp"] == joined["ocel:timestamp:event"]).all())

    check("no duplicate relation rows", not relations.duplicated().any())
    check("at most one qualifier per (event, object) pair",
          not relations.duplicated(subset=["ocel:eid", "ocel:oid"]).any())
    check("no duplicate o2o rows", not o2o.duplicated().any())

    type_of = dict(zip(objects["ocel:oid"], objects["ocel:type"]))
    check("relation object types agree with the objects table",
          all(type_of[oid] == otype
              for oid, otype in zip(relations["ocel:oid"], relations["ocel:type"])))

    check("all event timestamps are timezone-aware",
          events["ocel:timestamp"].dt.tz is not None)

    check("no 'derived:' qualifiers leaked into the source relations",
          not relations["ocel:qualifier"].str.startswith("derived:").any())

    print(f"Validation: {len(passed)}/{len(passed)} checks passed")
    for name in passed:
        print(f"  [ok] {name}")


section("Validation of the four source tables")
validate(events, objects, relations, o2o)
```

```python
# --------------------------------------------------------------------------- #
# 9) ANALYTICAL (NON-SOURCE) DERIVATION -- kept strictly separate              #
#                                                                             #
#    Walks the O2O graph to answer: "which Orders are operationally affected  #
#    by an event that touches a Package, a Delivery or an Invoice?"           #
#                                                                             #
#        Delivery -carries-> Package -packs-> Item <-contains- Order          #
#        Invoice  -bills--------------------------->  Order                   #
#                                                                             #
#    The result is an ANALYTICAL artefact:                                    #
#      * every row carries the qualifier prefix 'derived:';                   #
#      * it is never merged into `relations`;                                 #
#      * it is never passed to the OCEL constructor.                          #
# --------------------------------------------------------------------------- #
def derive_order_involvement(events, relations, o2o) -> pd.DataFrame:
    orders_of_item = {}   # Item     -> {Order}   via 'contains'
    items_of_pkg = {}     # Package  -> {Item}    via 'packs'
    pkgs_of_dlv = {}      # Delivery -> {Package} via 'carries'
    orders_of_inv = {}    # Invoice  -> {Order}   via 'bills'
    for subj, obj, qual in zip(o2o["ocel:oid"], o2o["ocel:oid_2"], o2o["ocel:qualifier"]):
        if qual == "contains":
            orders_of_item.setdefault(obj, set()).add(subj)
        elif qual == "packs":
            items_of_pkg.setdefault(subj, set()).add(obj)
        elif qual == "carries":
            pkgs_of_dlv.setdefault(subj, set()).add(obj)
        elif qual == "bills":
            orders_of_inv.setdefault(subj, set()).add(obj)

    objects_of_event = relations.groupby("ocel:eid")["ocel:oid"].agg(set).to_dict()

    rows = []
    for eid in events["ocel:eid"]:
        touched = objects_of_event.get(eid, set())
        derived_orders = set()
        for oid in touched:
            if oid in items_of_pkg:                      # event touches a Package
                for item in items_of_pkg[oid]:
                    derived_orders |= orders_of_item.get(item, set())
            if oid in pkgs_of_dlv:                       # event touches a Delivery
                for pkg in pkgs_of_dlv[oid]:
                    for item in items_of_pkg.get(pkg, set()):
                        derived_orders |= orders_of_item.get(item, set())
            if oid in orders_of_inv:                     # event touches an Invoice
                derived_orders |= orders_of_inv[oid]
        for order in sorted(derived_orders - touched):
            rows.append((eid, order, "Order", "derived:order_involvement"))

    derived = pd.DataFrame(
        rows, columns=["ocel:eid", "ocel:oid", "ocel:type", "ocel:qualifier"]
    )
    if derived.empty:
        return derived
    return (
        derived
        .merge(events[["ocel:eid", "ocel:activity", "ocel:timestamp"]],
               on="ocel:eid", how="left", validate="many_to_one")[REL_COLS]
        .sort_values(["ocel:timestamp", "ocel:eid", "ocel:oid"], kind="stable")
        .reset_index(drop=True)
    )


section("Analytical derivation (O2O walk; NOT source facts)")

print(f"source E2O relations      : {len(relations)} rows (what was recorded)")
print(f"analytically derived rows : {len(relations_derived)} rows (qualifier "
```

## 1. Modeling assumptions

**Object types and capitalization** (exact strings used as `ocel:type`): `Order` (O100, O200), `Item` (I1, I2, I3), `Package` (P1, P2), `Delivery` (D1, D2), `Invoice` (V1), `Payment` (M1, M2). **E2O qualifier vocabulary** (chosen to read as a verb phrase, event  object):

| Qualifier | Used on | Meaning |
|---|---|---|
| `creates` | Create Order  Order | event creates the order |
| `adds_to` / `adds` | Add Item  Order / Item | event adds the item to the order / registers the item |
| `reserves` | Reserve Stock  Item | event reserves stock of that item |
| `shared_by` | Reserve Stock  Order | the single event is operationally shared by that order |
| `packs` / `includes` | Pack Package  Package / Item | event fills the package / item goes into it |
| `involves` | Pack Package  Order | order is an explicit co-participant (asserted only for P1's packing) |
| `dispatches` / `loads` | Dispatch Package  Package / Delivery | event dispatches the package / loads it into the delivery |
| `issues` / `bills` | Issue Invoice  Invoice / Order | event issues the invoice / bills that order |
| `records` | Record Payment  Payment | event records that payment |
| `partially_settles` / `completes_settlement` | Record Payment  Invoice | the payment's effect on the invoice |
| `confirms` | Confirm Delivery  Delivery | event confirms the delivery |
| `closes` | Close Order  Order | event closes the order |

**O2O direction convention:** `ocel:oid` is the subject (container/upstream), `ocel:oid_2` is the object (contained/downstream); the qualifier reads left to right: Order `contains` Item, Package `packs` Item, Delivery `carries` Package, Invoice `bills` Order, Payment `partially_settles`/`completes_settlement` Invoice.

**Do logistics and financial events relate directly to Orders and Items?** Policy: *source-minimal plus explicit co-involvements*. A relation row exists iff the narrative names that object as a participant of the event. The narrative explicitly asserts order co-involvement for exactly two events — Reserve Stock (shared by O100 and O200) and Pack Package P1 (relates to both Orders) — so those are source facts. Dispatch, Confirm Delivery, and Record Payment relate only to their directly named operands (Package+Delivery, Delivery, Payment+Invoice). Trade-off: the source-minimal choice keeps frequency-based discovery honest (each event counted once, on its true operands) and keeps provenance clean, at the price that Order-flattened views under-report fulfilment; the pipeline therefore contains an explicit O2O-walk that recovers the operational view analytically.

**Preventing propagation from masquerading as observation:** four mechanisms — separate variable names (`relations` vs. `relations_derived`), a mandatory `derived:` qualifier prefix on every derived row, a validator asserting that no `derived:` qualifier ever appears in `relations`, and the fact that the derived table is computed after OCEL construction and never passed to it.

**Settlement assumption:** the narrative gives no invoice total. I assume 100 + 150 = 250 fully settles V1, hence M1  `partially_settles` and M2  `completes_settlement`. If V1 were known to remain open, both would be `partially_settles`. Amounts are event attributes (`amount` in `events`), never objects.

**Version-dependent PM4Py assumption:** pm4py  2.7 with `from pm4py.objects.ocel.obj import OCEL` and the four-DataFrame constructor; `pm4py.discover_otg` / `pm4py.discover_etot` likewise require a recent release. All other calls used here (`ocel_flattening`, `discover_ocdfg`, `discover_oc_petri_net`, `ocel_object_type_activities`, `ocel_objects_interactions_summary`, `discover_dfg`, `discover_log_skeleton`) are stable across recent versions. The constructor call is isolated on one marked line: if a release needs extra arguments (e.g., a `parameters` dict for column names, or `e2e`/`object_changes`), only that line changes — never the DataFrames or the semantics.

```python
# --------------------------------------------------------------------------- #
# 5) VALIDATION -- structural and referential integrity                       #
# --------------------------------------------------------------------------- #
def validate(events, objects, relations, o2o) -> None:
    """Assert the mandatory OCEL invariants; raise AssertionError on violation."""
    passed = []

    def check(name: str, condition) -> None:
        assert condition, f"VALIDATION FAILED: {name}"
        passed.append(name)

    check("event IDs are unique", events["ocel:eid"].is_unique)
    check("object IDs are unique", objects["ocel:oid"].is_unique)

    event_ids = set(events["ocel:eid"])
    object_ids = set(objects["ocel:oid"])

    check("no orphan event IDs in relations",
          set(relations["ocel:eid"]).issubset(event_ids))
    check("every event participates in at least one relation",
          set(relations["ocel:eid"]) == event_ids)
    check("no orphan object IDs in relations",
          set(relations["ocel:oid"]).issubset(object_ids))
    check("no orphan object IDs in o2o (ocel:oid)",
          set(o2o["ocel:oid"]).issubset(object_ids))
    check("no orphan object IDs in o2o (ocel:oid_2)",
          set(o2o["ocel:oid_2"]).issubset(object_ids))

    # activity / timestamp consistency between events and relations
    joined = relations.merge(
        events, on="ocel:eid", how="left",
        suffixes=("", ":event"), validate="many_to_one",
    )
    check("relation activities match the events table",
          (joined["ocel:activity"] == joined["ocel:activity:event"]).all())
    check("relation timestamps match the events table",
          (joined["ocel:timestamp"] == joined["ocel:timestamp:event"]).all())

    check("no duplicate relation rows", not relations.duplicated().any())
    check("at most one qualifier per (event, object) pair",
          not relations.duplicated(subset=["ocel:eid", "ocel:oid"]).any())
    check("no duplicate o2o rows", not o2o.duplicated().any())

    type_of = dict(zip(objects["ocel:oid"], objects["ocel:type"]))
    check("relation object types agree with the objects table",
          all(type_of[oid] == otype
              for oid, otype in zip(relations["ocel:oid"], relations["ocel:type"])))

    check("all event timestamps are timezone-aware",
          events["ocel:timestamp"].dt.tz is not None)

    check("no 'derived:' qualifiers leaked into the source relations",
          not relations["ocel:qualifier"].str.startswith("derived:").any())

    print(f"Validation: {len(passed)} checks passed")
    for name in passed:
        print(f"  [ok] {name}")


section("Validation of the four source tables")
validate(events, objects, relations, o2o)

# --------------------------------------------------------------------------- #
# 9) ANALYTICAL (NON-SOURCE) DERIVATION -- kept strictly separate              #
#                                                                             #
#    Walks the O2O graph to answer: "which Orders are operationally affected  #
#    by an event that touches a Package, a Delivery or an Invoice?"           #
#                                                                             #
#        Delivery -carries-> Package -packs-> Item <-contains- Order          #
#        Invoice  -bills--------------------------->  Order                   #
#                                                                             #
#    The result is an ANALYTICAL artefact:                                    #
#      * every row carries the qualifier prefix 'derived:';                   #
#      * it is never merged into `relations`;                                 #
#      * it is never passed to the OCEL constructor.                          #
# --------------------------------------------------------------------------- #
def derive_order_involvement(events, relations, o2o) -> pd.DataFrame:
    orders_of_item = {}   # Item     -> {Order}   via 'contains'
    items_of_pkg = {}     # Package  -> {Item}    via 'packs'
    pkgs_of_dlv = {}      # Delivery -> {Package} via 'carries'
    orders_of_inv = {}    # Invoice  -> {Order}   via 'bills'
    for subj, obj, qual in zip(o2o["ocel:oid"], o2o["ocel:oid_2"], o2o["ocel:qualifier"]):
        if qual == "contains":
            orders_of_item.setdefault(obj, set()).add(subj)
        elif qual == "packs":
            items_of_pkg.setdefault(subj, set()).add(obj)
        elif qual == "carries":
            pkgs_of_dlv.setdefault(subj, set()).add(obj)
        elif qual == "bills":
            orders_of_inv.setdefault(subj, set()).add(obj)

    objects_of_event = relations.groupby("ocel:eid")["ocel:oid"].agg(set).to_dict()

    rows = []
    for eid in events["ocel:eid"]:
        touched = objects_of_event.get(eid, set())
        derived_orders = set()
        for oid in touched:
            if oid in items_of_pkg:                      # event touches a Package
                for item in items_of_pkg[oid]:
                    derived_orders |= orders_of_item.get(item, set())
            if oid in pkgs_of_dlv:                       # event touches a Delivery
                for pkg in pkgs_of_dlv[oid]:
                    for item in items_of_pkg.get(pkg, set()):
                        derived_orders |= orders_of_item.get(item, set())
            if oid in orders_of_inv:                     # event touches an Invoice
                derived_orders |= orders_of_inv[oid]
        for order in sorted(derived_orders - touched):
            rows.append((eid, order, "Order", "derived:order_involvement"))

    derived = pd.DataFrame(
        rows, columns=["ocel:eid", "ocel:oid", "ocel:type", "ocel:qualifier"]
    )
    if derived.empty:
        return derived
    return (
        derived
        .merge(events[["ocel:eid", "ocel:activity", "ocel:timestamp"]],
               on="ocel:eid", how="left", validate="many_to_one")[REL_COLS]
        .sort_values(["ocel:timestamp", "ocel:eid", "ocel:oid"], kind="stable")
        .reset_index(drop=True)
    )


section("Analytical derivation (O2O walk; NOT source facts)")
relations_derived = derive_order_involvement(events, relations, o2o)
print(f"source E2O relations      : {len(relations)} rows (recorded facts)")
print(f"analytically derived rows : {len(relations_derived)} rows "
      f"(qualifier 'derived:order_involvement'; never merged into `relations`, "
      f"never passed to the OCEL)")
if not relations_derived.empty:
    print()
    print(relations_derived.to_string(index=False))

# --------------------------------------------------------------------------- #
# 10) Final eyeball checks against the narrative                              #
# --------------------------------------------------------------------------- #
section("Highlights to eyeball against the narrative")
p1_items = sorted(o2o.loc[(o2o["ocel:oid"] == "P1")
                          & (o2o["ocel:qualifier"] == "packs"), "ocel:oid_2"])
v1_orders = sorted(o2o.loc[(o2o["ocel:oid"] == "V1")
                           & (o2o["ocel:qualifier"] == "bills"), "ocel:oid_2"])
print(f"P1 packs items            : {p1_items}  (I1 belongs to O100, I3 to O200)")
print(f"V1 bills orders           : {v1_orders}")
print(f"total recorded on V1      : {events['amount'].sum():.0f} "
      f"(M1: 100 @ 2026-04-06 11:30 UTC, M2: 150 @ 2026-04-07 10:00 UTC)")
print("shared cross-order events : e06 Reserve Stock, e07 Pack Package, "
      "e11 Issue Invoice (each related to both O100 and O200)")
if not relations_derived.empty:
    for eid in ("e13", "e14"):
        affected = sorted(relations_derived.loc[
            relations_derived["ocel:eid"] == eid, "ocel:oid"])
        print(f"derived orders affected by {eid} : {affected}  (analytical, not source)")
```

- **e06 Reserve Stock** — first convergence point: one event touches two Orders and two Items; after Order flattening it is copied into both order traces, destroying their independence.
- **e07 Pack Package** — the widest event (5 relations, 4 object types). P1 crosses the order boundary (I1 of O100 + I3 of O200); this single relation set is the only reason cross-order fulfilment is visible in any object-centric view, and simultaneously the largest relation-inflation risk.
- **e08 Pack Package** — consequential by *absence*: no Order relations, so O100's flattened trace cannot see its own item I2 being packed. The divergence between the Order view and reality is encoded here.
- **e11 Issue Invoice** — converges both Orders onto V1; guarantees the Invoice flattening has exactly one trace; couples the financial branch to the commerce branch.
- **e12 / e15 Record Payment** — converge M1 and M2 into V1; their qualifier pair carries the settlement semantics that flattening destroys.

## 4. Expected flattened behavior

**Flattening on Order (2 traces).**
- *Trace shape:* O100  Create Order, Add Item, Add Item, Reserve Stock, Pack Package, Issue Invoice, Close Order (7 events); O200  Create Order, Add Item, Reserve Stock, Pack Package, Issue Invoice, Close Order (6 events).
- *Copied shared events:* e06, e07, e11 each appear in both traces — 3 physical events produce 6 flattened occurrences.
- *Omitted lifecycle aspects:* all dispatch, delivery confirmation, and payment events; and Pack P2 (e08), even though P2 ships O100's item I2. The view also cannot show that P1 mixes items of both orders — each order trace shows "its own" pack event.
- *Likely DFG edges:* (Create OrderAdd Item):2, (Add ItemAdd Item):1, (Add ItemReserve Stock):2, (Reserve StockPack Package):2, (Pack PackageIssue Invoice):2, (Issue InvoiceClose Order):2. Start: Create Order:2; End: Close Order:2.
- *Misleading interpretations:* shared events are double-counted (both "Pack Package" occurrences come from the single event e07, while e08 never appears at all); the view implies orders close after invoicing with no payment or delivery gating; the per-order DFG suggests two independent reserve–pack chains, hiding the cross-order synchronization at e06/e07; O100 looks fully served by P1 while its I2 path vanishes.

**Flattening on Package (2 traces).**
- *Trace shape:* Pack Package, Dispatch Package for both P1 and P2.
- *Copied shared events:* none within this view (each event belongs to one package), though e07 is shared with the Order/Item views.
- *Omitted lifecycle aspects:* item/order composition (P1 cross-order vs P2 single-order is indistinguishable), delivery confirmation, invoicing, payment.
- *Likely DFG edges:* (Pack PackageDispatch Package):2.
- *Misleading interpretations:* looks like a complete, closed two-step lifecycle; cannot say whether a package was ever delivered or paid; identical traces hide that P1 concentrates the risk of two orders.

**Flattening on Delivery (2 traces).**
- *Trace shape:* Dispatch Package, Confirm Delivery for D1 (3 h) and D2 (~23 h).
- *Copied shared events:* none within this view; e09/e10 are shared with the Package view.
- *Omitted lifecycle aspects:* contents, orders, invoice/payment; everything before dispatch.
- *Likely DFG edges:* (Dispatch PackageConfirm Delivery):2.
- *Misleading interpretations:* deliveries appear to exist only from dispatch onward; identical structure hides the day-long difference in confirmation latency (timestamps only); D1's confirmation cannot be tied to O100/O200 without the object-centric model.

**Flattening on Invoice (1 trace).**
- *Trace shape:* Issue Invoice, Record Payment, Record Payment (V1).
- *Copied shared events:* none within this view; e11 is shared with both order traces.
- *Omitted lifecycle aspects:* the two billed orders; allocation of the 250 across O100/O200; fulfilment status. The two Record Payment events are distinguishable only via the `amount` attribute (100 vs 150), not structurally.
- *Likely DFG edges:* (Issue InvoiceRecord Payment):1, (Record PaymentRecord Payment):1.
- *Misleading interpretations:* the Record PaymentRecord Payment edge reads like a causal chain or installment plan, but M1 and M2 are independent partial payments; with one trace, the DFG/skeleton say almost nothing generalizable; "V1 is settled" cannot be concluded structurally — it rests on the `completes_settlement` qualifier and the stated assumption.

**Why flattening on Payment is particularly weak:** M1 and M2 each participate in exactly one event, so the flattened Payment log is two one-event traces Record Payment.
