## 2. Raw-versus-normalized interpretation

The fitness gap between raw and mapped models (ranging from 0.49 to 0.92) primarily indicates semantic drift rather than purely technical issues. The mapping consolidates `Register -> Validate Eligibility` events, removing duplicated technical `Open Case` events. This change addresses conformance without asserting that the underlying process remained unchanged; the mapping captures business intent but may not fully account for technical nuances introduced by the system migration. The duplication of technical events (e.g., duplicate `Open Case` events) and missing resources introduce noise that affects both analyses. In the post-May period, the DFG and performance metrics show a marked deterioration, suggesting that these changes are not solely due to logging drift. The normalization process highlights the impact of the system migration and staffing cuts on both the raw and mapped conformance metrics, reinforcing the notion that process changes are intertwined with technical ones.

## 8. Reproducible Python and PM4Py plan

### Part A: Monthly summary and drift analysis

```python
import pandas as pd
from pm4py.objects.log_factory import factory as log_factory
from pm4py.stats.dfg import discover_dfg
from pm4py.stats.dfg import distance
from pm4py.metrics.basic import compute_fitness

# Load data
log = log_factory.from_event_stream(pd.read_csv('monthly_summary.csv'))

# Validate data
assert log is not None, "Invalid log data"

# Calculate baseline-relative changes
baseline = log_factory.from_event_stream(pd.read_csv('baseline.csv'))
changes = compute_fitness(log, baseline)

# Compute normalized DFG rates
dfg_pre = discover_dfg.discover_dfg(log)
dfg_post = discover_dfg.discover_dfg(log_factory.from_event_stream(pd.read_csv('post_migration.csv')))
distance_jaccard = distance.jaccard_distance(dfg_pre, dfg_post)

# Calculate raw-to-mapped fitness recovery
mapped_log = log_factory.from_event_stream(pd.read_csv('mapped_model_fitness.csv'))
fitness_recovery = compute_fitness(log, mapped_log)

# Flag candidate change points
def flag_change_points(data):
    change_points = []
    for i in range(1, len(data)):
        if data[i] < 0.7 * data[i-1]:
            change_points.append(data[i-1])
    return change_points

change_points = flag_change_points(changes['mapped_model_fitness'])

# Print results
print("Monthly Summary:", pd.read_csv('monthly_summary.csv'))
print("Normalized DFG Distance:", distance_jaccard)
print("Fitness Recovery:", fitness_recovery)
print("Candidate Change Points:", change_points)
```

### Part B: PM4Py functions

```python
def format_dataframe(log):
    return log_factory.from_event_stream(log)

def filter_time_range(log, start, end):
    return log_factory.from_event_stream(log.loc[(log['timestamp'] >= start) & (log['timestamp'] <= end)])

def discover_monthly_dfgs(log):
    monthly_dfgs = {}
    for month in pd.Grouper(key='timestamp', freq='M'):
        monthly_log = filter_time_range(log, month.start_time, month.end_time)
        monthly_dfgs[month.strftime('%Y-%m')] = discover_dfg.discover_dfg(monthly_log)
    return monthly_dfgs

def compute_temporal_profile(log):
    temporal_profile = discover_temporal_profile.discover_temporal_profile(log)
    return temporal_profile
```

## 9. Provisional attribution

The observed drift is attributed to a combination of mechanisms with varying degrees of confidence. The most convincing attribution is to the system migration (logging/semantic drift) and supplier disruption (behavioral drift), both with high confidence (90-95%). The gradual increase in case mix and staffing cuts explain the performance deterioration (performance drift) with moderate confidence (65-75%). The priority rule implementation also contributes to the performance drift, but with lower confidence (45-55%) due to its potential to mask underlying delays. Seasonal case mix surge and supplier recovery explain the observed increases in complexity and supplier-related variants, respectively, with moderate confidence (55-70%). The presence of duplicate technical events and missing resources introduces logging drift, with lower confidence (40-60%). The interaction among mechanisms, such as the priority rule amplifying the impact of supplier disruption, prevents clean attribution. Future revisions would consider more detailed process mining analyses to isolate the effects of individual mechanisms and interactions.

## 10. Monitoring decision rules

1. **IF** logging schema deviation exceeds 5%, **THEN** investigate event mapping consistency, **BECAUSE** semantic drift was identified as a primary drift dimension.
2. **IF** variant distribution for Supplier Z cases increases by >20%, **THEN** assess supplier operational status, **BECAUSE** supplier-driven rework was a significant drift mechanism.
3. **IF** high-complexity case cycle time increases by >15% and queue waiting time by >10%, **THEN** evaluate staffing levels and resource allocation, **BECAUSE** staffing cuts and queueing were identified as performance drift contributors.
4. **IF** priority rule implementation leads to a redistribution of delay to high-complexity cases, **THEN** review priority rule logic, **BECAUSE** priority-induced redistribution was observed as a behavioral drift mechanism.
5. **IF** case mix distribution shifts by >10% in post-migration months, **THEN** analyze seasonal patterns and volume changes, **BECAUSE** seasonal case mix drift was noted.
6. **IF** resource completeness drops below 90% for >2 weeks, **THEN** investigate resource availability, **BECAUSE** resource/organizational drift was identified.
7. **IF** conformance rate drops below 90% for two consecutive months, **THEN** conduct root cause analysis, **BECAUSE** performance drift and potential process inefficiencies are indicated.
