# 1. Assumptions and Interpretation

1. Risk is an exclusive control-flow choice: the low-risk branch contains Supervisor Review; the high-risk branch contains both Quality Review and Regulatory Review without an order between them. The case-data guard selecting the branch is outside both models.
2. Supplier involvement is represented by an exclusive choice between Consult Supplier and a silent activity. The consultation branch occurs at most once. Its case-data guard is likewise outside the models.
3. Each completed Execute Trial is followed by a completed Inspect Trial. An Inspect Trial followed by Adjust Parameters is interpreted as failed; the final Inspect Trial, after which the loop exits, is interpreted as passed. The models cannot check an actual inspection result stored in data.
4. Distinct nodes with the same visible label are not used. Repetition of Execute Trial and Inspect Trial comes from one loop, not duplicated visible nodes.
5. The process tree uses a conservative under-approximation: it joins containment/planning with root-cause/design/approval/consultation before beginning the trial loop. It therefore excludes some valid overlap but does not relax a release prerequisite.
6. “May overlap” is modeled as causal concurrency: unordered activities may complete in either order, including orders compatible with overlapping execution. A linear trace alone cannot establish that their time intervals actually overlapped.
7. Because events are recorded at completion, every stated start-after-completion rule is approximated by a precedence rule between completion events. This is necessary but insufficient to verify actual start times.

# 2. Intended Dependency Specification

| ID | Source activity or submodel | Target activity or submodel | Relation | Rationale |
|---|---|---|---|---|
| D1 | Register Deviation | Contain Material; Analyze Root Cause | Precedes both | Registration starts every case. |
| D2 | Contain Material | Analyze Root Cause | No order | The initial streams can progress independently. |
| D3 | Contain Material | Plan Verification | Precedes | Planning may start only after containment. |
| D4 | Analyze Root Cause | Design Corrective Action | Precedes | Design requires the analysis. |
| D5 | Analyze Root Cause | Selected risk route | Precedes | Risk review is selected after analysis. |
| D6 | Supervisor Review | Quality Review plus Regulatory Review | Exclusive alternatives | One low-risk review or both high-risk reviews are required. |
| D7 | Quality Review | Regulatory Review | No order | Both are required on the high-risk route; either may finish first. |
| D8 | Analyze Root Cause | Optional Consult Supplier | Precedes if selected | Consultation cannot start before analysis. |
| D9 | Consult Supplier | Silent skip | Exclusive alternatives | Consultation is optional and occurs at most once. |
| D10 | Plan Verification; Design Corrective Action | First Execute Trial | Both precede | The first trial needs both work products. |
| D11 | Execute Trial | Inspect Trial | Precedes in each cycle | Every execution is inspected. |
| D12 | Failed Inspect Trial | Adjust Parameters; next Execute Trial | Sequence and repetition | Failure leads to adjustment and another full cycle. |
| D13 | Final, passing Inspect Trial | Release Material | Precedes; no subsequent adjustment | Release requires a passed inspection. |
| D14 | Selected risk route; optional consultation; trial loop | Release Material | Three-way synchronization | All selected obligations must finish before release. |
| D15 | Selected risk route; optional consultation | Trial loop | No order after their own prerequisites | Reviews and consultation can overlap trial work. |
| D16 | Release Material | Archive Case | Precedes | Archiving closes the case. |

# 3. PM4Py Process-Tree Model

`SEQ` means `Operator.SEQUENCE`, `AND` means `Operator.PARALLEL`, `XOR` means `Operator.XOR`, `LOOP(do, redo)` performs `do` once and then zero or more `redo, do` repetitions, and `τ` is silent. The two sides of the outer `AND` model the initial work streams; the inner `AND` allows design, review, and optional consultation to proceed independently after analysis.

```text
SEQ(
  Register Deviation,
  AND(
    SEQ(Contain Material, Plan Verification),
    SEQ(Analyze Root Cause,
        AND(Design Corrective Action,
            XOR(Supervisor Review, AND(Quality Review, Regulatory Review)),
            XOR(Consult Supplier, τ)))
  ),
  LOOP(SEQ(Execute Trial, Inspect Trial), Adjust Parameters),
  Release Material,
  Archive Case
)
```

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator


def activity(label):
    return ProcessTree(label=label)


def compose(operator, *children):
    parent = ProcessTree(operator=operator)
    for child in children:
        child.parent = parent
        parent.children.append(child)
    return parent


risk_route = compose(
    Operator.XOR,
    activity("Supervisor Review"),
    compose(
        Operator.PARALLEL,
        activity("Quality Review"),
        activity("Regulatory Review"),
    ),
)
supplier_option = compose(
    Operator.XOR, activity("Consult Supplier"), ProcessTree()
)
containment_stream = compose(
    Operator.SEQUENCE,
    activity("Contain Material"),
    activity("Plan Verification"),
)
analysis_stream = compose(
    Operator.SEQUENCE,
    activity("Analyze Root Cause"),
    compose(
        Operator.PARALLEL,
        activity("Design Corrective Action"),
        risk_route,
        supplier_option,
    ),
)
trial_loop = compose(
    Operator.LOOP,
    compose(
        Operator.SEQUENCE,
        activity("Execute Trial"),
        activity("Inspect Trial"),
    ),
    activity("Adjust Parameters"),
)
tree = compose(
    Operator.SEQUENCE,
    activity("Register Deviation"),
    compose(Operator.PARALLEL, containment_stream, analysis_stream),
    trial_loop,
    activity("Release Material"),
    activity("Archive Case"),
)
```

The tree cannot express the intended cross-branch join compactly while leaving review and consultation independent of trial work. Its outer `AND` must complete before the loop starts, so it wrongly requires the selected approval route and selected consultation to finish before the first Execute Trial. It consequently excludes approvals or consultation during any trial cycle, even though the intended behavior permits them. The tree retains the intended independence among containment/planning and analysis-side work until that join, including concurrency of the two high-risk reviews. As with the POWL model, its XOR branches do not enforce data-based route selection, and its loop exit does not inspect a recorded pass/fail value. Completion-only traces also cannot establish the stated start-time conditions.

# 4. PM4Py POWL Model

`PO{...}` is a strict partial order. The listed edges, together with transitivity, are its only precedence constraints. The risk and supplier alternatives are single nested nodes in the root order; completion of either node means completion of its selected branch.

```text
Risk     = XOR(Supervisor Review, PO{Quality Review, Regulatory Review})
Supplier = XOR(Consult Supplier, τ)
Cycle    = PO{Execute Trial < Inspect Trial}
Trial    = LOOP(Cycle, Adjust Parameters)

Root nodes = {Register Deviation, Contain Material, Analyze Root Cause,
              Plan Verification, Design Corrective Action, Risk, Supplier,
              Trial, Release Material, Archive Case}
Root edges = {Register Deviation < Contain Material,
              Register Deviation < Analyze Root Cause,
              Contain Material < Plan Verification,
              Analyze Root Cause < Design Corrective Action,
              Analyze Root Cause < Risk,
              Analyze Root Cause < Supplier,
              Plan Verification < Trial,
              Design Corrective Action < Trial,
              Risk < Release Material,
              Supplier < Release Material,
              Trial < Release Material,
              Release Material < Archive Case}
```

```python
from pm4py.objects.process_tree.obj import Operator
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)

register = Transition("Register Deviation")
contain = Transition("Contain Material")
analyze = Transition("Analyze Root Cause")
plan = Transition("Plan Verification")
design = Transition("Design Corrective Action")
supervisor = Transition("Supervisor Review")
quality = Transition("Quality Review")
regulatory = Transition("Regulatory Review")
consult = Transition("Consult Supplier")
execute = Transition("Execute Trial")
inspect = Transition("Inspect Trial")
adjust = Transition("Adjust Parameters")
release = Transition("Release Material")
archive = Transition("Archive Case")

high_risk = StrictPartialOrder(nodes=[quality, regulatory])
risk_route = OperatorPOWL(
    operator=Operator.XOR, children=[supervisor, high_risk]
)
supplier_option = OperatorPOWL(
    operator=Operator.XOR, children=[consult, SilentTransition()]
)
cycle = StrictPartialOrder(nodes=[execute, inspect])
cycle.order.add_edge(execute, inspect)
trial_loop = OperatorPOWL(
    operator=Operator.LOOP, children=[cycle, adjust]
)

powl = StrictPartialOrder(nodes=[
    register, contain, analyze, plan, design,
    risk_route, supplier_option, trial_loop, release, archive,
])
powl.order.add_edge(register, contain)
powl.order.add_edge(register, analyze)
powl.order.add_edge(contain, plan)
powl.order.add_edge(analyze, design)
powl.order.add_edge(analyze, risk_route)
powl.order.add_edge(analyze, supplier_option)
powl.order.add_edge(plan, trial_loop)
powl.order.add_edge(design, trial_loop)
powl.order.add_edge(risk_route, release)
powl.order.add_edge(supplier_option, release)
powl.order.add_edge(trial_loop, release)
powl.order.add_edge(release, archive)
```

Unconnected nodes remain unordered for a reason: Contain Material and Analyze Root Cause are independent; containment/planning can interleave with analysis-side design, review, and consultation wherever their own edges permit; design, review, and consultation can interleave after analysis; review and consultation can continue during the trial; and the two high-risk reviews have no mutual prerequisite. The trial still waits for both planning and design, and release still waits for the entire selected review branch, the selected supplier branch, and the complete trial loop. There is no meaningful concurrency between XOR alternatives, and the loop fixes order within each trial cycle.

# 6. Semantic Comparison

| Requirement | Intended semantics | Process tree | POWL | Overconstraint or underconstraint | Business consequence |
|---|---|---|---|---|---|
| Two initial work streams | Containment and analysis can proceed independently after registration. | Outer `AND` permits their completion interleavings. | Separate nodes with no edge between them. | Neither, at completion-trace level. | Parallel case preparation is represented. |
| Split dependencies into planning/design | Plan follows containment; design follows analysis; trial waits for both. | Two stream sequences join before the loop. | Four direct prerequisite edges and a two-input join at the trial. | Tree's join also pulls in review and consultation. | The tree can flag valid early trials as violations. |
| Risk route | Exactly one route: Supervisor, or both Quality and Regulatory without mutual order. | XOR with a parallel high-risk branch. | XOR with an unordered high-risk partial order. | Both omit case-data guards. | A trace can select a route inconsistent with recorded risk data. |
| Approval and trial overlap | Review may finish before, during, or after trial work, but before release. | Review must finish before the trial loop. | Review and trial are unordered after their own prerequisites. | Tree overconstrains. | Legitimate fast-start trials are excluded by the tree. |
| Optional supplier consultation | Selected at most once after analysis; may overlap design, planning, review, or trial; must finish before release. | XOR with `τ`, but consultation must finish before trial. | XOR with `SilentTransition`; only analysis and release constrain it. | Tree overconstrains; both omit selection data. | Tree rejects valid supplier contact during trial work. |
| Repeat until passing inspection | Each cycle is Execute then Inspect; failure requires Adjust then another cycle; final inspection passes. | Two-child loop enforces the visible pattern. | Loop over an ordered Execute–Inspect cycle enforces the visible pattern. | Both underconstrain actual pass/fail data. | A mislabeled inspection result could appear control-flow conformant. |
| Release synchronization | Passed trial, selected reviews, and selected consultation must all finish first. | Sequence places release after the early join and loop. | Three incoming obligations to release. | Tree enforces a stronger, earlier join; POWL matches the label-level dependencies. | POWL permits valid overlap while still protecting release. |
| Duplicate-label risk | Each named task has one model node, except repeated executions of loop nodes. | No distinct duplicate visible leaves. | No distinct duplicate visible transitions. | Neither in this construction. | Repeated trial events retain an unambiguous loop explanation. |
| Completion-time observation | Successor starts only after predecessor finishes where specified. | Enforces completion order only. | Enforces completion order only. | Both underconstrain actual start times. | A task started too early but finished later may evade detection. |

# 7. Preferred Representation and Validation Plan

The POWL model is canonical because its edges directly express the asymmetric dependencies and the release join. It admits A2 and A3 while preserving the required prerequisites. The process tree remains a useful conservative baseline when a tree-only tool is required.

1. Convert each model with `pm4py.convert_to_petri_net(model)` and retain `(net, initial_marking, final_marking)`. Inspect the converted structures, especially XOR, loop, and silent transitions; successful conversion alone is not a fidelity claim.
2. Run `pm4py.check_soundness(net, initial_marking, final_marking, print_diagnostics=True)` on both nets. Investigate dead transitions, deadlocks, and improper completion if reported.
3. Use bounded or sampled `pm4py.play_out(...)`, covering both risk routes, both supplier choices, both high-risk review orders, zero and one adjustment, and review/consultation completion on either side of trial events. Cap sampling at a practical number of events or loop iterations; retain traces reaching the final marking.
4. Build exact visible-trace acceptance tests against each accepting net, using replay or alignments with positive cost for inserting or deleting a visible activity and zero cost for silent model moves. Assert that POWL accepts A1–A5 and rejects F1–F3; assert that the tree accepts A1, A4, A5 and rejects A2, A3, F1–F3. Also test a trial before Plan Verification, a high-risk release missing either review, and consultation after release.
5. Inspect model nodes to confirm each visible label occurs once; separately confirm that the two-cycle trace repeats the same Execute Trial and Inspect Trial transitions. Verify that the no-supplier branch emits no visible event, that `τ` cannot bypass a required review or trial, and that a completed run contains exactly one Release Material and Archive Case.

Soundness and finite playout do not prove equality with an unbounded language. Exact trace tests cover only chosen witnesses. Neither model or its accepting net verifies risk, supplier-selection, or inspection-result data, nor can completion-only traces prove actual start times or interval overlap. PM4Py version-specific conversion behavior should be checked against these expected traces.

# 8. Final Self-Critique

1. The final inspection is called “passing” by control-flow position; neither model checks a real pass/fail attribute, so data-inconsistent cases can pass a control-flow test.
2. Completion-event precedence cannot verify that a successor actually started after its prerequisite finished, or that purportedly concurrent activities overlapped in time.
3. The process tree intentionally loses valid review/trial and consultation/trial overlap; a different approximation policy might be preferable if coverage of valid traces matters more than conservative conformance.
