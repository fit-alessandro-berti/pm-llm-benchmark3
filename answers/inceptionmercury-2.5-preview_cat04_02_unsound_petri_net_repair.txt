

# 1. Executive Verdict
The net is structurally a workflow net (unique source/sink, all nodes on source-to-sink paths), but it is not sound. The principal defect lies in the waiver path, which bypasses the mandatory synchronization with analysis. Consequently, authorization can be reached with a stranded analysis token still in the system, violating the requirement that authorization depends on both analysis and review completion. This allows business-critical approvals without completed mandatory analysis.

# 2. Structural Diagnosis
| Element or subnet | Intended role | Actual structural effect | Potential symptom |
| :--- | :--- | :--- | :--- |
| `split` | AND-split to parallel branches | Creates tokens in both `p_analysis` and `p_review` | Both tracks start together |
| `standard_review` | Review completion | Consumes `p_review`, produces `p_review_done` | Standard review ready to sync |
| `waive_review` | Waiver completion | Consumes `p_review`, produces `p_waived` | Waiver track ready to sync |
| `join_normal` | Synchronize Analysis & Standard | Requires `p_analysis_done` and `p_review_done` | Waits for both parallel paths |
| `join_waived` | Synchronize Waiver | Requires **only** `p_waived` | Waiver path skips analysis join |
| Initial/Final marking | Source/Sink | Unique single token in source/sink | Standard workflow net properties |
| All nodes | Reachability | All places lie on path sourcesink | Workflow net structural check passes |

# 3. Marking-Based Counterexample
**Sequence:** `t_register`  `t_split`  `t_analyze`  `t_waive_review`  `t_join_waived`  `t_authorize`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| :--- | :--- | :--- | :--- | :--- |
| 0 | (initial) | `source`=1 | `t_register` | Initial marking |
| 1 | `t_register` | `p_ready`=1 | `t_split` | Case registered |
| 2 | `t_split` | `p_analysis`=1, `p_review`=1 | `t_analyze`, `t_standard_review`, `t_waive_review` | Parallel branches start |
| 3 | `t_analyze` | `p_analysis_done`=1, `p_review`=1 | `t_standard_review`, `t_waive_review` | Analysis complete |
| 4 | `t_waive_review` | `p_analysis_done`=1, `p_waived`=1 | `t_join_waived` | Waiver complete, Analysis token remains |
| 5 | `t_join_waived` | `p_analysis_done`=1, `p_decision`=1 | `t_authorize` | Join Waived consumes waiver token only |
| 6 | `t_authorize` | `sink`=1, **`p_analysis_done`=1** | None | **Dead token in `p_analysis_done`** |

*Observation:* The transition `t_authorize` fires when `t_analyze` is complete, but the analysis token is not consumed by `join_waived`. The final marking `fm` (`sink`=1) is reached, but the marking `p_analysis_done`=1 persists. This violates soundness (proper completion requires exact `fm`).

# 4. Minimal-Repair Alternatives
| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1: Add Sync Arc | Add arc `p_analysis_done`  `join_waived` | 1 arc | Analysis remains mandatory | Waiver path now blocks until analysis done | Synchronization delay if analysis lags |
| 2: Merge Joins | Remove `join_waived`; add arc `p_waived`  `join_normal` (requires `join_normal` accept `p_waived`) | 1 transition + 3 arcs | Analysis mandatory | Both reviews synchronize with analysis identically | Loss of distinction between review types |

**Minimality Justification:** Under a cost model where arc addition = 1 and transition removal = 1, Repair 1 costs 1 (minimal). Repair 2 costs 4. Repair 2 is distinct because it changes the topology (merging join transitions) whereas Repair 1 is a behavioral correction without structural merge. Both preserve the mandatory analysis constraint.

# 5. Corrected PM4Py Code

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

def create_repaired_net():
    net = PetriNet("parallel_review_with_waiver_fixed")
    source = PetriNet.Place("source")
    p_ready = PetriNet.Place("p_ready")
    p_analysis = PetriNet.Place("p_analysis")
    p_review = PetriNet.Place("p_review")
    p_analysis_done = PetriNet.Place("p_analysis_done")
    p_review_done = PetriNet.Place("p_review_done")
    p_waived = PetriNet.Place("p_waived")
    p_decision = PetriNet.Place("p_decision")
    sink = PetriNet.Place("sink")

    for p in [source, p_ready, p_analysis, p_review, p_analysis_done,
              p_review_done, p_waived, p_decision, sink]:
        net.places.add(p)

    register = PetriNet.Transition("t_register", "Register Case")
    split = PetriNet.Transition("t_split", None)
    analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
    standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
    waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
    join_normal = PetriNet.Transition("t_join_normal", None)
    join_waived = PetriNet.Transition("t_join_waived", None)
    authorize = PetriNet.Transition("t_authorize", "Authorize Case")

    for t in [register, split, analyze, standard_review, waive_review,
              join_normal, join_waived, authorize]:
        net.transitions.add(t)

    # Standard flows
    petri_utils.add_arc_from_to(source, register, net)
    petri_utils.add_arc_from_to(register, p_ready, net)
    petri_utils.add_arc_from_to(p_ready, split, net)
    petri_utils.add_arc_from_to(split, p_analysis, net)
    petri_utils.add_arc_from_to(split, p_review, net)

    petri_utils.add_arc_from_to(p_analysis, analyze, net)
    petri_utils.add_arc_from_to(analyze, p_analysis_done, net)

    petri_utils.add_arc_from_to(p_review, standard_review, net)
    petri_utils.add_arc_from_to(standard_review, p_review_done, net)

    petri_utils.add_arc_from_to(p_review, waive_review, net)
    petri_utils.add_arc_from_to(waive_review, p_waived, net)

    # Normal Sync (Analysis + Review)
    petri_utils.add_arc_from_to(p_analysis_done, join_normal, net)
    petri_utils.add_arc_from_to(p_review_done, join_normal, net)
    petri_utils.add_arc_from_to(join_normal, p_decision, net)

    # Waiver Sync (Analysis + Waiver) [REPAIRED]
    petri_utils.add_arc_from_to(p_analysis_done, join_waived, net) 
    petri_utils.add_arc_from_to(p_waived, join_waived, net)
    petri_utils.add_arc_from_to(join_waived, p_decision, net)

    petri_utils.add_arc_from_to(p_decision, authorize, net)
    petri_utils.add_arc_from_to(authorize, sink, net)

    im = Marking()
    im[source] = 1
    fm = Marking()
    fm[sink] = 1
    return net, im, fm

repaired_net, repaired_im, repaired_fm = create_repaired_net()
```

# 7. Repair Trade-Offs and Residual Risks
- **Waiver vs Standard:** In both repairs, the distinction remains visible via transition labels (`t_standard_review` vs `t_waive_review`).
- **Silent Transitions:** Neither repair introduces silent transitions; all are labeled.
- **Soundness vs Alignment:** Soundness ensures the net can terminate cleanly (no leftover tokens) but does not guarantee the business rule (e.g., analysis was made optional, soundness could still hold).
- **Regression Testing:** Positive traces include Waiver path with Analysis complete. Negative traces should include Waiver path with Analysis incomplete (should be blocked).
- **Detection of Bypass:** To detect accidental bypass, monitor if `authorize` fires without a preceding `analyze` event timestamp on the same case instance.

# 8. Final Recommendation
Recommend **Repair 1** (Adding `p_analysis_done`  `join_waived`) for deployment. It is minimal (1 arc edit), maintains distinct synchronization points for each review path, and preserves explicit structural separation that aids future auditing. The added arc forces the waiver path to synchronize with analysis, directly fixing the business rule violation without collapsing the join logic.

Use **Repair 2** (Merging joins) as a fallback if process analytics team wants to reduce transition count for state-space simplification. Repair 2 introduces more structural changes (transition removal and re-routing) but standardizes the join behavior to a single gate, potentially simplifying long-term maintenance at the cost of slightly higher initial edit complexity.
