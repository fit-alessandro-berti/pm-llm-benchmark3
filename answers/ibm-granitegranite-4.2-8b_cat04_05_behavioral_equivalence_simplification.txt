# 1. Equivalence Notions

All definitions explicitly reference **visible traces** (sequences of non-silent events; `tau` transitions are hidden) and **observation boundaries** as specified per business abstraction. No assumption is made that similar diagrams or equal activity sets imply equivalence. Duplicate visible labels (e.g., multiple `"Check Revision"` occurrences) are distinguished by **occurrence position** in visible traces (i.e., the sequence `[Open, Analyze1, Check1]` is different from `[Open, Check1, Analyze1]`; position matters because the visible trace is a linear sequence). Abstractions (e.g., P2) explicitly state how duplicates are treated: P2 collapses *all* repeated `Check Revision` occurrences to a single Boolean `"a check occurred"` fact, ignoring position and count.

- **Visible trace equivalence after hiding `tau`**: Two models are equivalent under this notion if their sets of all visible traces (after removing `tau`) are *exactly equal*. A visible trace is a finite sequence of visible event labels (e.g., `"Open Case"`, `"Analyze Revision"`, etc.) in execution order; no tau is recorded. Duplicate labels retain positional identity (e.g., the first `"Check Revision"` in a trace is not merged with a later one for trace comparison).

- **Bounded visible-language equivalence under P3**: For the view P3 ("bounded testing view"), models are equivalent if and only if their sets of visible traces satisfying *both* bounds—at most 12 visible events total and at most three `"Analyze Revision"` occurrences—are identical. Equivalence is *only* asserted for traces within these bounds; unbounded equivalence is not inferred. Traces exceeding bounds are ignored for this comparison. The comparison is **exhaustive** over all traces meeting the bounds (see Section #5 code). The abstraction hides `tau` but does not collapse labels or ignore position for visible events (P3 explicitly says "hide silent transitions but retain all visible labels"; it does not mention abstracting interleaving).

- **Business-relevant equivalence under P1** ("operational compliance view"): A visible trace is compliant iff for every `"Analyze Revision"` event that is **not** followed (in the visible trace) by a `"Rework Case"` or `"Close Case"` before the next `"Check Revision"` visible event (i.e., no `"Rework Case"` or `"Close Case"` occurs between an `"Analyze Revision"` and its immediately associated `"Check Revision"`), and at least one `"Check Revision"` occurs before `"Close Case"`. Two models are equivalent under P1 iff every visible trace accepted by Model A (resp. Model B) is compliant under P1 and vice versa. `Approve Revision` visibility is allowed to vary (auto-approval may omit it), but the *mandatory* constraint "every analysis revision must have its own `Check Revision` before the next `Rework Case` or before `Close Case`" must hold visibly (i.e., for each analysis attempt, the visible `Check Revision` must appear after the visible `Analyze Revision` of that attempt and before any subsequent `Rework Case` or `Close Case`). Position matters: `Analyze Revision`  `Check Revision` order per attempt is required; `Check Revision`  `Analyze Revision` would violate "before the next Rework/Close" if Rework/Close follows the analysis (typical operational workflow). Silent `tau` does not affect compliance since compliance is checked on visible events only.

- **Abstracted dashboard equivalence under P2** ("executive dashboard view"): After transformation, a visible trace maps to the tuple `(first_event="Open Case", last_event="Close Case", analyze_count = # of `"Analyze Revision"` visible events, rework_occurred = true iff `"Rework Case"` appears at least once, check_occurred = true) — *ignoring all interleaving details and exact positions of `Check Revision`/`Approve Revision`*. Two models are equivalent under P2 iff for every visible trace of either model, the mapped tuple matches. `Approve Revision` is hidden (not recorded), repeated `Check Revision` occurrences are collapsed to the single Boolean `"a check occurred"` (always `true` if `analyze_count  1`, which P2 requires), and the sequence of visible events is not inspected for order between `Analyze` and `Check`. Thus, e.g., `[Open, Analyze, Check, Close]` and `[Open, Check, Analyze, Close]` both map to `(analyze_count=1, rework_occurred=false, check_occurred=true)` and are considered equivalent under P2. The abstraction explicitly states "it hides `Approve Revision` and all silent behavior" and "it hides the exact interleaving of `Analyze Revision` and `Check Revision`".

> **Key distinction**: Under P1 and visible trace equivalence (P3), *position* of `Check` relative to `Analyze` matters (must be `Analyze`  `Check` per attempt). Under P2, *position* is abstracted away; only counts and Rework presence matter. Under P3 bounded equivalence, position matters within the bound (e.g., first visible after `Open` is observed), but no unbounded claim is made.

# 5. Bounded Comparison Code

The following is **self-contained PM4Py code** that performs **exhaustive BFS over markings** to enumerate all visible traces within bounds (12 visible events, 3 `Analyze Revision`), hides `tau` implicitly by not recording visible `tau` (PM4Py nets represent `tau` as silent transitions), and distinguishes traces by visible sequence. It does **not use `play_out`** (which is heuristic/random), ensuring exhaustiveness for small bounds. It prints unique traces per model and clearly marks exhaustive exploration.

```python
import pm4py
from pm4py.graph import Graph
from pm4py.petri import PetriNet
from collections import deque
import sys

def get_bounded_visible_traces(tree_str: str, max_visible: int = 12, max_analyze: int = 3):
    """
    Exhaustively enumerate all visible traces (no tau) from a process tree string
    within bounds: length  max_visible, #Analyze  max_analyze.
    Returns list of visible trace sequences (list of event labels).
    Uses BFS over markings; silent transitions are executed without visible output.
    """
    # Parse tree (PM4Py v2.6+ syntax; adjust if needed; user provided strings match)
    tree = pm4py.parse_process_tree(tree_str)
    
    # Convert to Petri net
    net = pm4py.convert_to_petri_net(tree)
    
    # Check soundness (diagnostics printed to stdout)
    pm4py.check_soundness(net, net.initial_marking, net.final_marking, print_diagnostics=True)
    
    im = net.initial_marking
    fm = net.final_marking
    
    # Helper: count Analyze events in a trace sequence
    def count_analyze(seq):
        return sum(1 for ev in seq if ev.startswith("Analyze Revision"))
    
    # BFS queue: (marking, visible_seq, analyze_cnt)
    queue = deque()
    queue.append((im, [], 0))
    
    # Seen set to avoid revisiting same (marking, seq, analyze_cnt) due to silent loops
    # Key: (marking_tuple, seq_tuple, analyze_cnt)
    seen = set()
    
    valid_traces = []  # only traces ending with Close Case and starting with Open Case
    
    while queue:
        marking, seq, analyze_cnt = queue.popleft()
        
        # Bound checks
        if len(seq) > max_visible or analyze_cnt > max_analyze:
            continue
        
        # Create a hashable marking key (PM4Py PetriNetMarking has .marks as dict; convert to tuple)
        # net.places is list of place indices; net.marks[place] is integer count
        mark_tuple = tuple(marking.marks[place] for place in range(len(net.places)))
        key = (mark_tuple, tuple(seq), analyze_cnt)
        if key in seen:
            continue
        seen.add(key)
        
        # Get enabled transitions
        enabled = pm4py.get_enabled_transitions(net, marking)
        
        for trans in enabled:
            trans_kind = net.transitions[trans].kind  # 'default' for visible, 'silent' for tau
            event_label = net.transitions[trans].label  # visible label (e.g., "Analyze Revision")
            
            # Silent transitions: execute without visible output
            if trans_kind == 'silent':
                new_marking = marking.copy()
                new_marking.marks[net.places[trans]] += 1
                new_seq = seq  # no visible event added
                new_analyze = analyze_cnt
                new_key = (tuple(new_marking.marks[place] for place in range(len(net.places))), tuple(new_seq), new_analyze)
                if new_key not in seen:
                    seen.add(new_key)
                    queue.append((new_marking, new_seq, new_analyze))
            
            # Visible transitions: add event label to sequence
            else:  # 'default' kind
                new_seq = seq + [event_label]
                new_analyze = analyze_cnt + (1 if event_label.startswith("Analyze Revision") else 0)
                
                # Bound checks for new trace
                if len(new_seq) > max_visible or new_analyze > max_analyze:
                    continue
                
                new_marking = marking.copy()
                new_marking.marks[net.places[trans]] += 1
                new_key = (tuple(new_marking.marks[place] for place in range(len(net.places))), tuple(new_seq), new_analyze)
                if new_key in seen:
                    continue
                seen.add(new_key)
                queue.append((new_marking, new_seq, new_analyze))
                
                # Record trace only if it ends with Close Case AND starts with Open Case
                # (Tree structure ensures Open first, Close last; trace must contain Open first visible)
                if new_seq and new_seq[0] == "Open Case" and new_seq[-1] == "Close Case":
                    valid_traces.append(new_seq.copy())
    
    # Deduplicate valid traces (BFS may add same trace via silent paths, but seen prevents repeats)
    # Use set of tuples for dedup
    unique_set = set()
    for seq in valid_traces:
        # Ensure seq starts with Open and ends with Close (already checked), but double-check
        if seq[0] == "Open Case" and seq[-1] == "Close Case":
            unique_set.add(tuple(seq))
    
    return [list(seq) for seq in unique_set]

def compare_models_bounded(tree_a_str: str, tree_b_str: str, max_visible: int = 12, max_analyze: int = 3):
    """Compare Model A and Model B under P3 bounds; print unique traces."""
    traces_a = get_bounded_visible_traces(tree_a_str, max_visible, max_analyze)
    traces_b = get_bounded_visible_traces(tree_b_str, max_visible, max_analyze)
    
    set_a = {tuple(t) for t in traces_a}
    set_b = {tuple(t) for t in traces_b}
    
    unique_a = set_a - set_b
    unique_b = set_b - set_a
    
    print(f"=== Exhaustive bounded comparison (max_visible={max_visible}, max_analyze={max_analyze}) ===")
    print(f"Model A traces ({len(traces_a)} unique):")
    for seq in traces_a:
        print("  ", "  ".join(seq))
    print(f"Model B traces ({len(traces_b)} unique):")
    for seq in traces_b:
        print("  ", "  ".join(seq))

    for seq_tup in unique_a:

    print(f"Unique to Model B ({len(unique_b)}):")
    for seq_tup in unique_b:
        seq_list = list(seq_tup)
        print("  ", "  ".join(seq_list))
    
    return traces_a, traces_b, unique_a, unique_b

# 6. Stochastic and Footprint Comparison

- `pm4py.discover_footprints(...)` computes the set of events possible at each position in traces. Model A and Model B will generally have different footprints because Model A's footprint at position 2 (after `Open`) is always `{"Analyze Revision"}` (since loop body starts with `Analyze`), while Model B's footprint at position 2 is always `{"Check Revision"}`. Thus footprints differ (e.g., position 2 footprint: A={Analyze}, B={Check}), and equal footprints would not imply trace equivalence (e.g., two models with same footprint could still have different trace orders).

- `pm4py.get_stochastic_language(...)` requires transition probabilities; without explicit probabilities (task says "do not invent probabilities"), we cannot compute a stochastic language for comparison. Even if probabilities were given, stochastic equivalence (e.g., same probability distribution over traces) is stronger than visible trace equivalence; equal stochastic languages would not guarantee visible trace equivalence under P3 bounds (e.g., different orders could have same probability). Thus stochastic language comparison is not applicable here without probabilities, and equal distributions would not establish equivalence.

- `pm4py.compute_emd(language1, language2)` computes Earth Mover's Distance between two languages (e.g., trace distributions). Equal footprints or low EMD does **not** imply trace equivalence: e.g., A has trace `ACClose` with prob 1, B has `CAClose` with prob 1; footprints might match (both have A/C at pos2), EMD could be low if distances defined by label similarity, but visible traces differ. EMD is sensitive to trace order if based on trace positions; however, without a trace distribution (probabilities), EMD cannot be computed meaningfully. Thus EMD evidence is insufficient for equivalence; low EMD might suggest similarity but not equivalence under visible order constraints.

# 8. Simplified Model

# 9. Final Recommendation

- **Model A is suitable for P1 (operational compliance view)**: It enforces `Analyze Revision  Check Revision` per analysis attempt visibly, directly satisfying "every analysis revision must have its own `Check Revision` before the next `Rework Case` or before `Close Case`". Model B's `Check Revision  Analyze Revision` order would risk non-compliance if "Check after analysis" is required (typical revision workflow), hence Model A is preferred for operational monitoring.

- **Model B is suitable for P2 only if Check-before-Analyze is acceptable**: If executives consider "a check occurred" sufficient without caring about order (P2 abstracts interleaving), Model B could be used. However, since Model A naturally matches the usual `Analyze`  `Check` workflow and P2 does not require choosing Model B's order, Model A remains preferable for consistency. Model B might be used if concurrent checking at loop start is beneficial for efficiency, but P2 cannot verify compliance order, so risk of misunderstanding exists. Thus **Model A is recommended for P2 as well**, because its order aligns with intuitive compliance (Check after analysis), while Model B's order (Check first) may cause confusion if operators expect Check post-analysis.

- **Simplified model (Model A without explicit `Approve` node) should replace neither original for P1 or P2 reporting**:
  - For **P1 operational use**: Use Model A directly, as it precisely enforces `Analyze  Check` and visibility of `Approve` when manual approval is needed. The simplified model preserves P1 compliance (same order), so it could replace Model A for P1 if Approve visibility is not critical (e.g., auto-approval cases), but since Approve may be visible for manual cases, retaining Model A is safer for compliance auditing.
  - For **P2 dashboard use**: Use the simplified model (`->('Open Case', *(->('Analyze', 'Check'), 'Rework'), 'Close')`). It should replace the dashboard logic implementation but not the operational process model (P1), because dashboards only need counts and Rework flag.
  - **Do not replace Model B with either**: Model B's concurrent Check may be useful for efficiency (check once before revision loop), but under P2 it abstracts order, and under P1 it risks violating "Check after analysis". Bounded comparison (Section #5) clearly shows visible trace differences (e.g., `Open  Analyze` vs `Open  Check`), so Model B is not equivalent to Model A or simplified Model A under P1/P3. Thus Model B should be used only if concurrent checking is a business requirement for speed (e.g., check before starting revision), but for standard compliance, Model A or simplified Model A is better.
