## 1. Materiality Framework
Severity is scored 1–5 by combining: (a) control-objective breach (approval sequence, fraud screening, notification), (b) exposure (claim amount and risk level), (c) reversibility (paid vs. unpaid), (d) timing (pre-approval payment, delayed notification), (e) customer/regulatory harm potential, (f) recurrence, (g) evidence reliability (core log + external document vs. single mutable field), and (h) model-scope fit (payable claims only).  
Severity 5 = irreversible high-value control failure or clear P2/P3 breach; 4 = policy violation with material exposure; 3 = evidence gap on high-value or repeated pattern; 2 = label/scope mismatch with low exposure; 1 = harmless telemetry or silent-move noise.  
Confidence (High/Med/Low) measures evidential reliability and source corroboration, independent of severity; a severity-5 event with only a mutable CRM field receives Low confidence, while a severity-3 event backed by external adjuster report and core log receives High confidence.

## 6. Why Alignment Cost Is Not Business Risk
Raw cost sums uniform move penalties and ignores business semantics. CL-610 (cost 0) fully violates P1 via bank change yet incurs no penalty because the model lacks data conditions. CL-604 (cost 3) records a severe irreversible P3 breach (payment before approval) whose cost is modest because the alignment can insert cheap moves. CL-602 (cost 1) hides a EUR 480k control failure by omitting only one activity. CL-608 (cost 1) masks evidence weakness because the model cannot see that the CRM link is mutable. CL-605 (cost 0) correctly signals fit, while CL-607 (cost 4) inflates cost solely because the model scope excludes denials. Hidden tau moves, duplicated telemetry, external evidence, and irreversibility are invisible to the cost function; therefore cost and risk must remain separate columns.

## 7. PM4Py Reproduction and Aggregation Code
```python
import pm4py
import pandas as pd
from pm4py.objects.log.obj import EventLog, Trace, Event

pt_str = "->('Register Claim','Validate Coverage','Assess Loss',X(->('Fraud Screen','Manual Approve'),'Auto Approve'),'Pay Claim','Notify Claimant')"
process_tree = pm4py.parse_process_tree(pt_str)
net, im, fm = pm4py.convert_to_petri_net(process_tree)

# Representative traces (authoritative alignments supplied separately)
log = EventLog()
for case_id, activities in [
    ("CL-601", ["Register Claim","Validate Coverage","Assess Loss","Auto Approve","Pay Claim","Notify Claimant"]),
    ("CL-610", ["Register Claim","Validate Coverage","Assess Loss","Auto Approve","Pay Claim","Notify Claimant"]),
    ("CL-604", ["Register Claim","Validate Coverage","Assess Loss","Pay Claim","Manual Approve","Notify Claimant"]),
]:
    trace = Trace()
    for act in activities:
        trace.append(Event({"concept:name": act, "case:concept:name": case_id}))
    log.append(trace)

alignments = pm4py.conformance_diagnostics_alignments(log, net, im, fm)

# Move summary dataframe (populated from supplied authoritative alignments)
moves = pd.DataFrame([
    {"case":"CL-601","move":"L(Open Workbench)","raw_cost":1,"amount":1200,"risk":"LOW","policy_flag":"none"},
    {"case":"CL-610","move":"S(Auto Approve)","raw_cost":0,"amount":4500,"risk":"LOW","policy_flag":"bank_change"},
    {"case":"CL-604","move":"L(Pay Claim)","raw_cost":1,"amount":90000,"risk":"MEDIUM","policy_flag":"pre_approval"},
    # ... remaining cases
])
moves["business_severity"] = [1,4,5]  # illustrative; narrative judgment separate
print(moves.groupby(["policy_flag","risk"]).agg({"raw_cost":"sum","business_severity":"mean"}))
```
