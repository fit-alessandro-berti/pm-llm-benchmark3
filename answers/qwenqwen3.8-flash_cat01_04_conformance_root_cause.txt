def make_log_string(variants, base_time, swap_notify_decision=False):
    lines = ["case,activity,timestamp,resource,sequence"]
    case_id = 1
    for trace_str, count in variants:
        trace = [a.strip() for a in trace_str.split(",")]
        seqs = list(range(1, len(trace)+1))
        if swap_notify_decision and "Notify" in trace and "Decision" in trace:
            n = trace.index("Notify"); d = trace.index("Decision")
            if n < d:
                seqs[n], seqs[d] = seqs[d], seqs[n]
        for _ in range(count):
            for pos, act in enumerate(trace):
                ts = base_time + timedelta(seconds=case_id*1000 + pos)
                lines.append(f"{case_id},{act},{ts.isoformat()},,{seqs[pos]}")
            case_id += 1
    return "\n".join(lines)

The observed collapse is best explained as a chain of representation failures layered on top of a genuine policy change. The UI release changed the recorded label for the same business activity, so the normative model saw `Risk Screen` as an unexpected move. The gateway then inserted `Queue Routed`, and the ETL change replaced source-system ordering for `Decision` and `Notify` with ingestion time, producing reversed traces. Each fix—label mapping, technical-event removal, source-sequence ordering—improves fitness, which is the signature of logging artifacts rather than a wholesale behavioral break. The August policy change then made the normative model obsolete for high-value cases because `Supervisor Sign-off` is a real new activity that the control-flow model does not contain. At the same time, enhanced reviews without a recorded compliance check and manual overrides may reflect real routing corrections or true bypasses. Stable approval, appeal, and cycle-time outcomes are reassuring but not decisive: they can remain flat when noncompliance is rare, when appeals lag, or when incident detection is incomplete. Conversely, stable outcomes do not prove all deviations are data errors, because a process can be operationally successful while still violating control requirements. The right inference is therefore pluralistic: most measured conformance loss is artifact/model mismatch, but a smaller residual risk of real noncompliance must be tested by provenance, high-value stratification, and manual audit.

def make_log_string(variants, base_time, swap_notify_decision=False):
    """
    Build a CSV-like event log string.

    Raw order is represented by timestamp order.
    A 'sequence' column represents the source-system sequence number.
    For demonstration, when swap_notify_decision=True, source sequence corrects
    traces where raw timestamp order has Notify before Decision.
    """
    lines = ["case,activity,timestamp,resource,sequence"]
    case_id = 1

    for trace_str, count in variants:
        trace = [a.strip() for a in trace_str.split(",")]
        seqs = list(range(1, len(trace) + 1))

        if swap_notify_decision and "Notify" in trace and "Decision" in trace:
            n = trace.index("Notify")
            d = trace.index("Decision")
            if n < d:
                seqs[n], seqs[d] = seqs[d], seqs[n]

        for _ in range(count):
            for pos, act in enumerate(trace):
                ts = base_time + timedelta(seconds=case_id * 1000 + pos)
                # resource intentionally empty
                lines.append(f"{case_id},{act},{ts.isoformat()},,{seqs[pos]}")
            case_id += 1

    return "\n".join(lines)

def parse_event_log_string_compat(event_log_string):
    try:
        log = pm4py.parse_event_log_string(event_log_string)
    except Exception:
        # Fallback for PM4Py versions that do not accept the extra column.
        reader = csv.DictReader(io.StringIO(event_log_string))
        log = [dict(row) for row in reader]

    if hasattr(log, "to_dict"):
        log = log.to_dict("records")
    if not isinstance(log, list):
        log = list(log)
    return log

def normalize_log(log):
    out = []
    for e in log:
        case = e.get("case", e.get("case_id", e.get("Case")))
        activity = e.get("activity", e.get("concept:name", e.get("Activity")))
        timestamp = e.get("time:timestamp", e.get("timestamp", e.get("Timestamp")))
        resource = e.get("org:resource", e.get("resource", e.get("Resource")))
        sequence = e.get("sequence", e.get("source_sequence", e.get("Sequence")))

        try:
            case = int(case)
        except Exception:
            pass

        if isinstance(timestamp, str):
            try:
                timestamp = datetime.fromisoformat(timestamp)
            except Exception:
                timestamp = None

        try:
            sequence = int(sequence)
        except Exception:
            sequence = None

        out.append({
            "case": case,
            "activity": activity,
            "time:timestamp": timestamp,
            "org:resource": resource,
            "sequence": sequence,
        })
    return out

def sort_by_timestamp(log):
    return sorted(log, key=lambda e: (e["case"], e["time:timestamp"] or datetime.min))

def sort_by_sequence(log):
    return sorted(log, key=lambda e: (
        e["case"],
        e["sequence"] if e["sequence"] is not None else 10**9
    ))

    return sort_by_timestamp(log)

def normalize_for_conformance(log, map_label=True, remove_queue=True, source_order=True):

def alignment_metrics(event_log, net, initial_marking, final_marking):
    metrics = {}

    fn = getattr(pm4py, "align_conformance_checking", None)
    if fn is None:
        fn = getattr(pm4py, "conformance_checking", None)

    if fn is not None:
        try:
            res = call_pm4py(fn, event_log, net, initial_marking, final_marking)
            if isinstance(res, dict):
                metrics.update(res)
            else:
                metrics["alignments"] = res
        except Exception as exc:
            metrics["error"] = str(exc)

    if metrics.get("fitness") is None:
        try:
            metrics["fitness"] = call_pm4py(
                pm4py.fitness_alignment_based,
                event_log, net, initial_marking, final_marking
            )
        except Exception:
            pass

    if metrics.get("precision") is None:
        try:
            metrics["precision"] = call_pm4py(
                pm4py.precision_alignment_based,
                event_log, net, initial_marking, final_marking
            )
        except Exception:
            pass

    aligns = metrics.get("alignments") or []
    if aligns:
        fit_count = 0
        cost_sum = 0.0
        cost_count = 0

        for a in aligns:
            cost = None
            if isinstance(a, dict):
                cost = a.get("cost", a.get("alignment_cost"))
                if cost is None and "moves" in a:
                    # Crude fallback: count non-silent moves.
                    cost = sum(1 for mv in a["moves"] if mv not in (">>", ">> "))

            if cost is not None:
                try:
                    cost = float(cost)
                    cost_sum += cost
                    cost_count += 1
                    if cost == 0.0:
                        fit_count += 1
                except Exception:
                    pass

        metrics["fitting_percent"] = 100.0 * fit_count / len(aligns)
        metrics["mean_cost"] = cost_sum / cost_count if cost_count else None

    return metrics

## 7. Provisional conclusion

The primary explanation for the measured conformance collapse is a combination of logging-semantics drift, technical-event inflation, and timestamp/order corruption, followed by a real model-obsolescence effect after the August policy change. The staged fitness recovery after mapping Risk Screen to Classify, removing Queue Routed, and ordering by source sequence is strong evidence that much of the June-July drop was not a behavioral break but a mismatch between the recorded event stream and the normative model. The August drop is better explained by the unmodeled Supervisor Sign-off requirement, especially because adding an optional sign-off branch raises fitness substantially. A real compliance problem may remain, but it is narrower and less certain. Enhanced reviews without a recorded Compliance Check, Manual Override use, and possible high-value sign-off gaps are credible residual risks. The audit is incomplete, incident detection is known to be imperfect, and stable appeal and approval rates do not prove compliance because violations may be rare, delayed, or undetected. Confidence in the artifact/model explanation is high; confidence in widespread employee noncompliance is low to moderate; confidence in the existence of some real bypasses is moderate pending targeted audit. Immediate actions: IT should freeze and document event-name and timestamp provenance, expose source sequence numbers, and classify Queue Routed as technical unless business value is proven. Process owners should update the normative model to include Supervisor Sign-off and, preferably, a data-aware constraint for claims above EUR 50,000. Compliance should stratify by high-value status and review a random sample of enhanced-review traces missing Compliance Check and manual overrides. What must not be claimed yet: that employees are noncompliant, that the process is materially unchanged, that all deviations are logging defects, or that the optional-sign-off model is policy-compliant merely because it improves fitness.

## 8. Model-governance recommendation

1. Maintain versioned normative models with effective dates, model IDs, policy citations, and change history, and never run conformance against a model whose version does not match the period being analyzed.
2. Require an event-semantic contract for every activity label: source system, owning team, business meaning, trigger point, and whether it is a user action, system action, gateway event, or derived event.
3. Define a technical-event policy that explicitly identifies events such as `Queue Routed` as non-conformance-relevant unless they are modeled as real control-flow steps, and require approval before adding or removing them from conformance inputs.
4. Preserve timestamp provenance by storing source-system sequence numbers, ingestion timestamps, and event-generation timestamps separately, and make conformance jobs declare which ordering source is authoritative.
5. Encode data-aware constraints for policy-relevant conditions, such as `Supervisor Sign-off` required only for claims above EUR 50,000, rather than relying on overpermissive control-flow models that can hide violations.
6. Perform post-release validation after UI, gateway, ETL, or policy changes: compare variants, DFGs, label dictionaries, timestamp distributions, and alignment diagnostics before and after the change, and require sign-off from IT, process owners, and compliance.
