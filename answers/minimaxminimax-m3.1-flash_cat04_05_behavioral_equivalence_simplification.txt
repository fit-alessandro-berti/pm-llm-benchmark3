```python
def bfs_visible_traces(net, im, fm, max_visible=12, max_analyze=3, analyze_label='Analyze Revision',
                       max_silent_steps=100):
    start = im
    results = set()
    visited = set()
    queue = collections.deque()
    state = (im, ())
    queue.append(state)
    visited.add((im, ()))
    while queue:
        marking, trace = queue.popleft()
        if marking == fm:
            results.add(trace); continue   # don't extend complete traces (no further transitions available anyway)
        for trans in enabled(net, marking):
            label = net.transitions[trans].label
            silent = is_silent(net, trans)
            new_trace = trace if silent else trace + (label,)
            if len(new_trace) > max_visible: continue
            if not silent and label == analyze_label and count(new_trace) > max_analyze: continue
            new_marking = apply_transition(net, marking, trans)
            key = (new_marking, new_trace)
            if key in visited: continue
            visited.add(key)
            queue.append(key)
    return results
```

# 1. Equivalence Notions

## 1.0 A preliminary, but decisive, notation caveat

PM4Py has a fixed operator alphabet:

| symbol | PM4Py meaning |
|---|---|
| `->(a,b)` | sequence |
| `+(a,b)` | **exclusive choice (XOR)** |
| `&(a,b)` | **parallel (AND)** |
| `*(a,b)` | loop (binary: `a`, then optionally `b`, then `a`, …) |
| `o` | silent step /  |

The two strings in the question therefore **do not parse to the behaviours described in P1/P2**:

* In Model A, `+('Analyze Revision','Check Revision')` is a *choice*: each loop iteration executes **either** an analysis **or** a check, never both.
* In Model B, `+('Check Revision', *(…))` is a *choice*, not concurrency: the whole case becomes either “one check and no analyses” **or** “the revision loop and no check at all”.
* `X(...)` is not a PM4Py operator; `tau` is an ordinary (visible) activity name as far as PM4Py is concerned. The XOR-with-a-silent-branch is written `+('Approve Revision','tau')` (equivalently `o`).

I therefore analyse **two readings** and state which one drives each verdict:

* **R-C (canonical / intent-preserving, PRIMARY).** `+('Analyze Revision','Check Revision')`  `->('Analyze Revision','Check Revision')` (analysis *then* check, as P1 demands); `+('Check Revision', <loop>)`  `&('Check Revision', <loop>)` (check *concurrent* with the loop, as the question says); `X('Approve Revision', tau)`  `+('Approve Revision','tau')`.
* **R-L (literal).** The strings exactly as written, i.e. `+` = XOR.

Canonical strings used throughout (they are also what the code in §5 parses):

```
A_CANON = "->('Open Case', *(->(->('Analyze Revision','Check Revision'), +('Approve Revision','tau')), 'Rework Case'), 'Close Case')"
B_CANON = "->('Open Case', &('Check Revision', *(->('Analyze Revision', +('Approve Revision','tau')), 'Rework Case')), 'Close Case')"
```

Both readings are computed by the code in §5. All verdicts in §3 are stated for R-C; the R-L consequences are reported alongside.

## 1.1 Alphabet, traces, and the treatment of duplicates

Let ` = {Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, Close Case}` be the visible alphabet and let `` denote the silent event.

* A **trace** is a finite word `w = w…w_n  *` obtained from a complete model execution by deleting every `` event.
* A trace is **complete** iff the underlying execution ends in the model’s final marking.
* **Duplicate labels are distinguished by occurrence position, not by identity.** A trace is a *word*: the *k*-th occurrence of `Check Revision` is identified by its index in the sequence. There is no instance/object identity in a process tree (no cases, no revisions as objects), so two occurrences of the same label are interchangeable except for the position they occupy. Equivalently: *event identity is not modelled; multiset equality is too weak; word equality is the right granularity.* Any abstraction that retains positions but forgets multiplicity (e.g. “the set of labels”) collapses far too much and is rejected.
* `Count_X(w)` denotes the number of occurrences of label `X` in `w`.

`_` (deleting ``) is a **projection**: it is many-to-one and order-preserving. Consequences used later:
* `_` can only *erase* differences, never create them.
* `_` never reorders, so it cannot create order differences.

## 1.2 N1 — Visible trace equivalence (after hiding ``)

Let `Vis(M) = { w : w = _(t), t is a complete execution of M }`.

> **M _vis M** iff `Vis(M)  Vis(M)`.
> **M _vis M** iff `Vis(M) = Vis(M)`.

This is the finest of the four notions: it keeps every visible event, its label and its position. It is *not* implied by, nor implies, the business notions; it is the “ground truth” against which the abstractions are checked.

## 1.3 N2 — Bounded visible-language equivalence (P3)

Fix `B_vis = 12` (visible events), `B_an = 3` (`Analyze Revision` occurrences).

> `Vis_(M) = { w  Vis(M) : |w|  B_vis  Count_Analyze(w)  B_an }`.
> **M _bnd M** iff `Vis_(M) = Vis_(M)`.

Semantics of the verdict: **inequality of bounded languages is a proof of non-equivalence** (a witness inside the bound refutes unbounded equivalence). **Equality of bounded languages is only evidence** — it is consistent with unbounded inequality (e.g. a model that needs a 4th analysis to expose a difference). Bounded comparison is a *refutation* procedure, not a proof procedure.

## 1.4 N3 — Business-relevant equivalence (P1)

P1 hides nothing and  is hidden ( is “silent behaviour”, and P1 explicitly cares about *visible* approvals). So the P1-observation on a word `w` is the word itself, **plus** the truth value of a compliance predicate `C(w)`:

```
C(w)    w = 'Open Case'
         w|w| = 'Close Case'
         Count_Analyze(w)  1
         there exists a strictly increasing map  from the positions of the
          ‘Analyze Revision’ events to positions of ‘Check Revision’ events
          with i < (i), (i) < |w|, and no ‘Rework Case’ strictly between
          i and (i)                      (every analysis has its OWN check,
                                           before the next rework / before close)
         Count_Rework(w) = Count_Analyze(w)  1
          and every ‘Rework Case’ lies strictly between two analyses
                                           (rework separates two attempts)
```

> **M _P1 M** iff `Vis(M) = Vis(M)` *and* (`w  Vis(M), C(w)`)  (`w  Vis(M), C(w)`).
> A weaker, “filtered” variant — `Vis(M)  C = Vis(M)  C` (compare only compliant traces) — is reported as well, because it is the variant a compliance dashboard would actually implement.

Note the consequence of the definition: because P1 removes no visible event, **P1-equivalence collapses onto `_vis`** except for the added `C` filter. P1 is not an abstraction; it is the full visible trace *plus* an invariant.

## 1.5 N4 — Abstracted dashboard equivalence (P2)

P2 defines an explicit abstraction `D`:

```
D(w) = ( first(w) = 'Open Case' ,                 # Open Case is first
         last(w)  = 'Close Case' ,                 # Close Case is last
         Count_Analyze(w) ,                        # number of analyses is kept
         [ Count_Check(w)  1 ] ,                  # checks collapsed to a Boolean
         [ Count_Rework(w)  1 ] ,                 # rework collapsed to a Boolean
         [ Count_Approve(w)  1 ] )                # approvals hidden  not represented
```

> **M _P2 M** iff `D(Vis(M)) = D(Vis(M))`, where traces violating the P2 pre-conditions (`Open` first, `Close` last, 1 analysis, 1 check) are filtered out of both sides.

`D` is many-to-one: it *deliberately* destroys the multiplicity of `Check Revision`, the multiplicity and placement of `Approve Revision`, and the interleaving of analyses and checks. Equality after `D` therefore says nothing about trace-level equivalence.

## 1.6 Summary of the four notions (and what each can/cannot prove)

| notion | what it keeps | inequality proves | equality proves |
|---|---|---|---|
| `_vis` | all visible events + positions | non-equivalence | equivalence (unbounded) |
| `_bnd` (P3) | visible events within the bound | non-equivalence | *evidence only* |
| `_P1` | all visible events + compliance predicate `C` | non-equivalence / non-compliance | compliance-equivalence |
| `_P2` | analyses count, check Boolean, rework Boolean | non-equivalence | *nothing* about process reality |

### 4.1 Why the inclusion directions both fail (no inclusion claim to prove)

* `Vis(A)  Vis(B)`: T2 (or T3).
* `Vis(B)  Vis(A)`: T4 (or T5, T6, T8).

Structurally: `Vis(A)` contains a word with two checks; `Vis(B)` contains no word with two checks. `Vis(B)` contains a word with a check not adjacent to an analysis; `Vis(A)` contains none. Both directions therefore fail, so no inclusion proof is needed.

### 4.2 The effect of the optional `Approve Revision` and of the hidden ``

**Optional approval (`X('Approve Revision', )` = “do an approval *or* take the silent branch”).**

* It is an *exclusive choice between a visible event and a silent event*. It is therefore the **only source of nondeterminism inside the loop body** in both models, and it multiplies trace counts (2 approval variants for n analyses) without changing the *shape* of either language.
* **P1** keeps approvals visible  the difference in approval *placement* (after the check in A vs. after the analysis, possibly before the check, in B) is observable: witness T6. It also makes A’s approvals *checkable* approvals (an approval always follows a check) while B’s are not.
* **P2** hides approvals  all approval-related differences vanish. This is *exactly* why P2 can be “equivalent” while P1 is “not equivalent”.
* **P3** keeps approvals visible and therefore enlarges both bounded languages, but **the verdicts are robust to them**: the decisive witnesses T2 and T4 are *approval-free*, so even a bounded test that ignored approvals would still refute equivalence. Approvals are a *multiplier*, not a *cause*, of the difference.
* Corollary worth noting for anyone tempted to “simplify away” the approval: removing it is a **loss of information**, not a simplification of the same language (see §8).

**Hidden ``.**

* The `` branch is the only silent event in either model. Hiding it merges the “approved” and “not approved” predecessors of every iteration into a single visible word; it is a many-to-one *projection* that never reorders.
* Because `_` cannot create differences, and because the decisive differences (check multiplicity, check placement, approval placement) are **visible**, hiding `` cannot repair the inequivalence: a visible difference survives any hiding of silent events (P1, P3).
* Conversely, hiding `` is what *allows* P2’s equivalence: it removes the second of the two approval variants. Without hiding ``, P2’s image of A and of B would still differ only in the *number* of approval-bearing traces — but since P2 discards approvals entirely, this is irrelevant.
* Under the R-L reading  is still the only silent event, with the same conclusions.

### 4.3 The literal (R-L) reading, for completeness

If the strings are parsed literally (`+` = XOR, `X`/`tau` unsupported  `+('Approve Revision','tau')`):

* `Vis_RL(A)` = { `Open`, then per iteration exactly one of `Analyze`/`Check` (optionally followed by `Approve`), iterations separated by `Rework Case`, `Close` }.
* `Vis_RL(B)` = { `Open, Check, Close` }  { `Open`, loop with no check, `Close` }.

Then **one inclusion does hold and can be proved**, so the witnesses are strongest-witness witnesses:

> **Claim.** `Vis_RL(B)  Vis_RL(A)`.
> *Proof.* Every B-trace has the form either (i) `Open, Check, Close` or (ii) `Open, (Analyze [Approve]) (Rework (Analyze [Approve]))*, Close`. Type (i) is produced by A with a single iteration choosing the `Check` branch (no approval, loop exits immediately). Type (ii) is produced by A with every iteration choosing the `Analyze` branch. Hence `Vis_RL(B)  Vis_RL(A)`. The inclusion is strict: `Open, Analyze, Rework, Check, Close  Vis_RL(A) \ Vis_RL(B)` (A can mix branches across iterations; B can never emit an analysis and a check in the same case). 

Observe that under R-L **neither** model satisfies P1’s “every analysis has its own check”: R-L(A) admits `Open, Analyze, Close` (no check at all) and R-L(B) *never* emits an analysis together with a check. The P1 verdict of “not equivalent” survives; the *responsibility* for compliance moves entirely onto A once its `+` is repaired.

# 5. Bounded Comparison Code

The script below is **self-contained** and **exhaustive with respect to the P3 bound**. It is *not* a random playout: it performs a breadth-first search over the product of *reachable markings* and *visible trace prefixes*, pruning only by the P3 bounds.

**Design points required by the task and how they are handled**

| requirement | handling |
|---|---|
| silent transitions | a transition is silent iff its label is `None`/`tau`/`silent`/`skip`/`o` or its attribute `tau`/`silent` is set; silent transitions do **not** extend the visible trace but do advance the marking |
| repeated markings | the search state is the pair `(marking, visible prefix)`; a state already visited is pruned. The *marking* space alone is finite (the nets are finite-state), but the *trace* space is infinite because of the loop — the bounds make the search finite |
| visible-length bound | `|visible prefix|  12` |
| analysis bound | `Count_Analyze(prefix)  3` |
| final-marking equality | a trace is recorded as *complete* only when the successor marking equals the model’s final marking `fm` (token-wise comparison over the union of places) |

```python
             "'Close Case')")
B_LITERAL = ("->('Open Case', "
             "+('Check Revision', *(->('Analyze Revision', X('Approve Revision', tau)), 'Rework Case')), "
             "'Close Case')")

# R-C : canonical / intent preserving (PRIMARY analysis)
A_CANON = ("->('Open Case', "
           "*(->(->('Analyze Revision','Check Revision'), +('Approve Revision','tau')), 'Rework Case'), "
           "'Close Case')")
B_CANON = ("->('Open Case', "
           "&('Check Revision', *(->('Analyze Revision', +('Approve Revision','tau')), 'Rework Case')), "
           "'Close Case')")

SILENT_NAMES = {"tau", "silent", "skip", "o", "none"}
ANALYZE = "Analyze Revision"
MAX_VISIBLE = 12
MAX_ANALYZE = 3


# --------------------------------------------------------------------------- #
# 1.  helpers
# --------------------------------------------------------------------------- #
def parse(tree_str: str):
    """Parse a process-tree string.  Tolerates the 'X(...)' operator."""
    try:
        return pm4py.parse_process_tree(tree_str)
    except Exception:
        # 'X' is not a PM4Py operator: +('Approve Revision','tau') is the
        # equivalent XOR-with-silent-branch.
        return pm4py.parse_process_tree(tree_str.replace("X(", "+(").replace(", tau)", ", 'tau')"))


def to_net(tree):
    """tree -> (accepting Petri net, initial marking, final marking)."""
    return pm4py.convert_to_petri_net(tree)


def is_silent(net, t) -> bool:
    tr = net.transitions[t]
    if tr.label is None:
        return True
    if str(tr.label).strip().lower() in SILENT_NAMES:
        return True
    if tr.attribute.get("tau", False) or tr.attribute.get("silent", False):
        return True
    return False


def enabled_transitions(net, marking):
    """All transitions enabled in `marking`.

    Prefers the public API pm4py.get_enabled_transitions; falls back to an
    equivalent local implementation (a transition is enabled iff every input
    place holds a token).
    """
    getter = getattr(pm4py, "get_enabled_transitions", None)
    if getter is not None:
        try:
            return list(getter(net, marking))
        except Exception:
            pass
    return [t for t in net.transitions
            if all(marking[p] >= 1 for p in net.in_arcs.get(t, []))]


def markings_equal(m1, m2) -> bool:
    """Token-wise equality of two PM4Py Markings (Counter-like)."""
    try:
        d1, d2 = dict(m1), dict(m2)
    except TypeError:                                    # pragma: no cover
        d1 = {p: m1[p] for p in m1.keys()}
        d2 = {p: m2[p] for p in m2.keys()}
    for p in set(d1) | set(d2):
        if d1.get(p, 0) != d2.get(p, 0):
            return False
    return True


def visible_label(net, t):
    return net.transitions[t].label


# --------------------------------------------------------------------------- #
# 2.  exhaustive bounded exploration
# --------------------------------------------------------------------------- #
def explore(net, im, fm, max_visible=MAX_VISIBLE, max_analyze=MAX_ANALYZE,
            analyze_label=ANALYZE):
    """Breadth-first exploration of complete VISIBLE traces within the bound.

    Exhaustive: every enabled transition is explored at every reachable
    (marking, visible-prefix) state; only the two P3 bounds prune.
    Returns a set of tuples of visible labels.
    """
    results = set()
    visited = set()
    queue = collections.deque()
    start = (im, ())
    queue.append(start)
    visited.add(start)

    while queue:
        marking, trace = queue.popleft()

        # complete trace?  -> final-marking equality
        if markings_equal(marking, fm):
            results.add(trace)
            continue                      # at fm nothing is enabled any more

        for t in sorted(enabled_transitions(net, marking),
                        key=lambda x: str(visible_label(net, x))):
            silent = is_silent(net, t)
            label = visible_label(net, t)
            new_trace = trace if silent else trace + (label,)

            if len(new_trace) > max_visible:                       # visible-length bound
                continue
            if (not silent and label == analyze_label
                    and sum(1 for e in new_trace if e == analyze_label) > max_analyze):
                continue                                          # analysis bound

            new_marking = apply_transition(net, marking, t)
            key = (new_marking, new_trace)
            if key in visited:                                    # repeated marking+history
                continue
            visited.add(key)
            queue.append(key)

    return results


def fmt(trace):
    return " -> ".join(trace) if trace else "<empty>"


# --------------------------------------------------------------------------- #
# 3.  build, soundness, footprint of the state space
# --------------------------------------------------------------------------- #
def build(name, tree_str):
    print("=" * 78)
    print(name)
    print("  tree :", tree_str)
    tree = parse(tree_str)
    net, im, fm = to_net(tree)
    print("  places=%d transitions=%d" % (len(net.places), len(net.transitions)))
    try:
        snd = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
        print("  check_soundness:", snd)
    except Exception as exc:                       # version dependent
        print("  check_soundness raised:", exc)
    # the reachable *marking* space is finite (finite net) -> useful sanity check
    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        print("  reachable markings:", len(rg.reachable_state_nodes))
    except Exception as exc:
        print("  reachability graph not built:", exc)
    return tree, net, im, fm


def compare(label_a, label_b, res_a, res_b, max_show=12):
    only_a = sorted(res_a - res_b, key=lambda t: (len(t), t))
    only_b = sorted(res_b - res_a, key=lambda t: (len(t), t))
    print("-" * 78)
    print("%s vs %s" % (label_a, label_b))
    print("  |Vis_<= A| = %d   |Vis_<= B| = %d   |intersection| = %d"
          % (len(res_a), len(res_b), len(res_a & res_b)))
    print("  BOUNDED VISIBLE LANGUAGES EQUAL? ", res_a == res_b)
    print("  only in %s : %d traces" % (label_a, len(only_a)))
    for t in only_a[:max_show]:
        print("     +", fmt(t))
    print("  only in %s : %d traces" % (label_b, len(only_b)))
    for t in only_b[:max_show]:
        print("     -", fmt(t))
    return only_a, only_b


# --------------------------------------------------------------------------- #
# 4.  main
# --------------------------------------------------------------------------- #
def main():
    # --- primary: canonical (intent preserving) reading ---------------------
    _, netA, imA, fmA = build("Model A (canonical, R-C)", A_CANON)
    _, netB, imB, fmB = build("Model B (canonical, R-C)", B_CANON)
    resA = explore(netA, imA, fmA)
    resB = explore(netB, imB, fmB)
    only_a, only_b = compare("A", "B", resA, resB)

    # --- the analytically derived witnesses must show up --------------------
    W_A_ONLY = [
        ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
         "Analyze Revision", "Check Revision", "Close Case"),
        ("Open Case", "Analyze Revision", "Check Revision", "Approve Revision",
         "Rework Case", "Analyze Revision", "Check Revision", "Approve Revision",
         "Close Case"),
    ]
    W_B_ONLY = [
        ("Open Case", "Analyze Revision", "Rework Case", "Analyze Revision",
         "Check Revision", "Close Case"),
        ("Open Case", "Check Revision", "Analyze Revision", "Close Case"),
        ("Open Case", "Analyze Revision", "Approve Revision", "Check Revision",
         "Close Case"),
    ]
    print("-" * 78)
    print("witness check")
    for w in W_A_ONLY:
        print("  A-only witness in Vis(A)?", w in resA, " in Vis(B)?", w in resB, "|", fmt(w))
    for w in W_B_ONLY:
        print("  B-only witness in Vis(A)?", w in resA, " in Vis(B)?", w in resB, "|", fmt(w))

    # --- secondary: literal reading ----------------------------------------
    try:
        _, lnetA, limA, lfmA = build("Model A (literal, R-L)", A_LITERAL)
        _, lnetB, limB, lfmB = build("Model B (literal, R-L)", B_LITERAL)
        lresA = explore(lnetA, limA, lfmA)
        lresB = explore(lnetB, limB, lfmB)
        compare("A(lit)", "B(lit)", lresA, lresB)
        print("  R-L inclusion Vis(B) subset Vis(A)? ", lresB <= lresA)
    except Exception as exc:
        print("literal reading could not be parsed by this pm4py build:", exc)

    # --- contrast: a NON-exhaustive, statistical alternative -----------------
    # pm4py.play_out performs a RANDOM walk; it samples the language and can
    # never certify absence of a trace.  Use only for smoke tests.
    print("-" * 78)
    try:
        samples = pm4py.play_out(parse(A_CANON), n=200)
        sample_traces = {tuple(s["trace"]) for s in samples}
        print("play_out(A): %d sampled traces (sample only, NOT exhaustive)" % len(sample_traces))
    except Exception as exc:
        print("play_out not available:", exc)


if __name__ == "__main__":
    main()
```

**Exhaustive vs. random/heuristic — explicit statement.**

* The `explore()` function above is a **breadth-first search over `(marking, visible prefix)` states**. It enumerates *all* complete visible traces within the bound, because at every state **every** enabled transition (visible and silent) is expanded; the only pruning is (a) the P3 visible-length bound, (b) the P3 analysis-count bound, (c) the “state already visited” test, which is sound because the state includes the full visible history (two visits with the same marking but different histories are *different* states and both are explored). Consequently `Vis_(M)` is computed **exactly**.
* `pm4py.play_out(...)` is a **random playout**: it samples executions using a probability model (uniform over enabled transfers if none is declared). It can *suggest* traces but cannot certify that a trace is absent, so it can never establish equivalence or non-equivalence on its own. Its only legitimate use here is a smoke test or a sanity check on the sample distributions of §6.
* `pm4py.convert_to_reachability_graph(net, im, fm)` enumerates the **finite reachable marking space**; it is used as a cross-check that the marking space explored by the BFS is the whole state space. Note the asymmetry that matters: the marking space is finite, the *trace* space is infinite (the loop can be iterated arbitrarily often), which is exactly why the P3 bounds exist.

# 6. Stochastic and Footprint Comparison

### 6.1 `pm4py.discover_footprints(...)` — *decisive for inequality, useless for equality*

`discover_footprints` returns the (boolean) **relation matrix** `[i][j] = True` iff activity *j* can **directly follow** activity *i* in at least one complete trace of the model (with invisible transitions skipped). It is a **projection of the language**, therefore:

* **Unequal footprints  the languages are unequal  proof of non-equivalence.** (If the languages were equal, all their projections would be equal.) This is the strongest, cheapest argument available and it needs no bounds.
* **Equal footprints  nothing.** Huge families of distinct languages share a footprint (e.g. any two models whose visible activity pairs coincide but whose multiplicities differ — precisely our case).

```python
import pm4py

treeA = pm4py.parse_process_tree(A_CANON)
treeB = pm4py.parse_process_tree(B_CANON)

fpA = pm4py.discover_footprints(treeA)      # bool matrix, activities of the model
fpB = pm4py.discover_footprints(treeB)

acts = sorted({'Open Case', 'Analyze Revision', 'Check Revision',
               'Approve Revision', 'Rework Case', 'Close Case'})

def pairs(fp, acts):
    return {(acts[i], acts[j])
            for i in range(len(acts)) for j in range(len(acts))
            if fp[i][j]}

pa, pb = pairs(fpA, acts), pairs(fpB, acts)
print("in B but not in A:", sorted(pb - pa))
print("in A but not in B:", sorted(pa - pb))
print("footprints equal? ", (fpA == fpB).all())
```

Analytically (canonical reading), `Footprint(A)  Footprint(B)`; the extra pairs enabled by B’s concurrency are

```
(Open Case,    Check Revision)      # the check may fire before the loop starts
(Analyze Revision, Rework Case)      # an analysis may be followed directly by a rework
(Analyze Revision, Approve Revision) # approval directly follows the analysis
(Check Revision, Analyze Revision)  # the check may precede a later analysis
(Rework Case,  Check Revision)      # the check may arrive after a rework
```

while the pairs that A enforces and B does not are only *ordering* properties that the footprint cannot see (`AnalyzeCheck` adjacency, `AnalyzeCheckApprove` contiguity). **The differing footprints independently confirm the non-equivalence verdict of §3** — a footprint *difference* is a proof, whereas a footprint *equality* would have been worthless as evidence.

### 6.2 `pm4py.get_stochastic_language(...)` — needs a declared probability model

The stochastic language of a net assigns to each trace of the (possibly infinite) support a probability obtained from the weights of the transitions along its firing sequence. Three caveats for these models:

1. **No probabilities exist in the input.** Both process trees are unweighted. Any stochastic language computed for them is the artefact of an *extra* modelling decision (e.g. “uniform over the enabled transfers at each marking”, or “uniform over the branches of an exclusive node”). Two different declarations produce different stochastic languages for the *same* model, so the object is not a property of the process tree alone.
2. **The support is infinite.** Both models contain a loop, so the trace support is infinite. The stochastic language must be computed on a *bounded/unfolded* version of the model (e.g. the P3-bounded unfolding) or it cannot be materialised.
3. **Version dependence.** The stochastic-language helpers expose different signatures across PM4Py releases; the wrapper below is defensive.

```python
import pm4py

def stochastic_language(tree_str, max_visible=12, max_analyze=3):
    """Best-effort stochastic language on the BOUNDED unfolding of a model."""
    tree = pm4py.parse_process_tree(tree_str)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    # Declare an explicit weight model: uniform over enabled transfers.
    try:
        from pm4py.petri_net.utils.petri_net_utils import set_transition_weight
        for t in net.transitions:
            set_transition_weight(net, t, 1.0)
    except Exception:
        # fall back to attribute-based weights
        for t in net.transitions:
            net.transitions[t].attribute["weight"] = 1.0
    try:
        lang = pm4py.get_stochastic_language(net, im, fm)   # API varies by version
    except Exception as exc:
        print("get_stochastic_language unavailable / failed:", exc)
        lang = None
    return net, im, fm, lang
```

What it would add: **support equality**. If the stochastic languages have different supports (different traces with non-zero probability), the languages differ  another direct proof of non-equivalence, complementary to the footprint argument. If the supports coincide *and* the per-trace probabilities coincide, then the two models are trace-equivalent *for the declared probability model* — but note this conclusion is about the **bounded/unfolded** model and about the *declared weights*, not about the unbounded process trees.

### 6.3 `pm4py.compute_emd(language1, language2)` — a distance between distributions, not an equivalence test

`compute_emd` solves a minimum-cost transport problem between two probability distributions over traces. Its properties:

* It is defined on **distributions**, so it presupposes a probability model for both processes. The process trees supply none (see §6.2, point 1). **Any EMD number I could quote for these two models would be a number about my own weight assumptions, not about the models.**
* It is an **aggregate** metric: two *different* languages can have a small EMD if their truncated distributions are close. Conversely, two *identical* languages with different declared weights can have a large EMD. Hence **low EMD  trace equivalence** and **high EMD  trace inequality**.
* It presupposes a common ground set. PM4Py’s implementation matches supports explicitly; traces present in one language and absent in the other are either dropped ( the mismatch is invisible) or make the computation fail/return . Consequently EMD is, at best, a **fuzzy summary**; a support *difference* is the meaningful signal.
* With infinite supports (loops) it is not directly applicable; it must be applied to a bounded unfolding.

```python
# Best effort; the exact signature differs between PM4Py versions.
try:
    emd = pm4py.compute_emd(langA, langB)      # expects stochastic-language objects
    print("EMD =", emd)
except Exception as exc:
    print("compute_emd could not be applied directly:", exc)
    # Recommended alternative: compare the SUPPORTS of the two bounded languages
    # (section 5), which is a sound equivalence test, and use EMD only as a
    # quantitative summary of the distributional difference.
```

### 6.4 Summary

| tool | can prove inequality? | can prove equivalence? | why |
|---|---|---|---|
| footprints | **yes** (unequal projections  unequal languages) | no | projection, many-to-one |
| stochastic language (supports) | yes | yes *for the declared weights and the bounded unfolding* | needs an declared probability model + bounded support |
| EMD | no (a non-zero EMD may come from weights alone) | no | distance between distributions, not between languages |
| bounded trace comparison (§5) | yes (witness inside the bound) | **no** (evidence only) | truncated language |

# 7. Complexity Comparison

### 7.1 Exact figures derivable by hand (tree level)

Convention: **depth** = number of edges on the longest rootleaf path (root at depth 0); “levels” = depth + 1. “Duplicate label count” = `_label max(0, occurrences(label)  1)` over the leaf labels of the tree (i.e. how many leaves carry a label that is already used elsewhere in the tree). I report also the *runtime* coupling, which is what actually differentiates the models.

| Metric | Model A (canonical) | Model B (canonical) | simplified model S (§8) | Derivation |
|---|---|---|---|---|
| Process-tree node count | **12** | **12** | **8** | counted below |
| Depth (edges) / levels | **4** / 5 | **5** / 6 | **3** / 4 | longest rootleaf path |
| Visible leaves | **6** | **6** | **5** | `Open, Analyze, Check, Approve, Rework, Close` (+) |
| Silent leaves | **1** (`tau`) | **1** (`tau`) | **0** | the XOR’s silent branch |
| Total leaves | 7 | 7 | 5 | visible + silent |
| Duplicate label count (static) | **0** | **0** | **0** | every label occurs once in the tree |
| *Runtime* repetition coupling | `Analyze``Check` repeat **in lock-step** (`Count_Check = Count_Analyse`) | only `Analyze` repeats; `Count_Check = 1` | `Analyze``Check` lock-step | semantic, not syntactic |
| Parallel (concurrent) regions | **0** | **1** | **0** | `&` appears once in B |
| Exclusive-choice regions | 1 (approval only) | 1 (approval only) | 0 | `+` |
| Loop regions | 1 | 1 | 1 | `*` |
| Max visible events per extra analysis | +3 (+1 if approved) | +2 (+1 if approved) | +3 | semantic |
| Literal (R-L) node count | 12 | 12 | — | same shape, different operators |

Node-count derivations (canonical):

```
A: SEQUENCE(root) 1 | 'Open Case' 1 | LOOP 1 | SEQ(body) 1 | SEQ(Analyse,Check) 1
   | 'Analyze Revision' 1 | 'Check Revision' 1 | XOR 1 | 'Approve Revision' 1 | 'tau' 1
   | 'Rework Case' 1 | 'Close Case' 1                                     = 12
B: SEQUENCE(root) 1 | 'Open Case' 1 | PARALLEL 1 | 'Check Revision' 1 | LOOP 1
   | SEQ(body) 1 | 'Analyze Revision' 1 | XOR 1 | 'Approve Revision' 1 | 'tau' 1
   | 'Rework Case' 1 | 'Close Case' 1                                     = 12
S: SEQUENCE(root) 1 | 'Open Case' 1 | LOOP 1 | SEQ(body) 1
   | 'Analyze Revision' 1 | 'Check Revision' 1 | 'Rework Case' 1 | 'Close Case' 1 = 8
```

Depth derivations: A: rootLOOPSEQ(body)SEQ(A,C)leaf = 4 edges; A’s longest path is root(0)LOOP(1)SEQbody(2)XOR(3)leaf(4) — also 4. B: root(0)PARALLEL(1)LOOP(2)SEQbody(3)XOR(4)leaf(5) = 5. S: root(0)LOOP(1)SEQbody(2)leaf(3) = 3.

### 7.2 Code for the structural counts

```python
import collections
import pm4py

SILENT_NAMES = {"tau", "silent", "skip", "o"}

def leaf_label(node):
    return node.label

def is_silent_label(label):
    return label is None or str(label).strip().lower() in SILENT_NAMES

def tree_stats(tree):
    """node count, depth (edges), visible/silent leaves, duplicate labels."""
    st = {"nodes": 0, "visible_leaves": 0, "silent_leaves": 0,
          "max_depth": 0, "parallel_regions": 0, "xor_regions": 0, "loop_regions": 0}
    labels = []

    def walk(node, depth):
        st["nodes"] += 1
        st["max_depth"] = max(st["max_depth"], depth)
        op = getattr(node, "operator", None)
        if op == "&":
            st["parallel_regions"] += 1
        elif op == "+":
            st["xor_regions"] += 1
        elif op == "*":
            st["loop_regions"] += 1
        kids = list(getattr(node, "children", []) or [])
        if not kids:
            if is_silent_label(leaf_label(node)):
                st["silent_leaves"] += 1
            else:
                st["visible_leaves"] += 1
            labels.append(leaf_label(node))
        for k in kids:
            walk(k, depth + 1)

    walk(tree, 0)
    cnt = collections.Counter(labels)
    st["duplicate_labels"] = sum(v - 1 for v in cnt.values() if v > 1)
    st["labels"] = labels
    return st

def net_stats(net, im, fm):
    """Petri-net level figures.  Values are printed, never hard-coded,
    because the tree->net compiler inserts places differently across versions."""
    out = {"places": len(net.places), "transitions": len(net.transitions),
           "visible_transitions": sum(1 for t in net.transitions
                                      if str(net.transitions[t].label).lower() not in SILENT_NAMES),
           "silent_transitions": sum(1 for t in net.transitions
                                     if str(net.transitions[t].label).lower() in SILENT_NAMES)}
    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        out["reachable_markings"] = len(rg.reachable_state_nodes)
    except Exception as exc:
        out["reachable_markings"] = "n/a (%s)" % exc
    # 'simplicity' proxies: a net with no parallel region has at most one
    # enabled transition per marking except at explicit XOR choices.
    try:
        simp = pm4py.simplicity_petri_net(net, im, fm)   # API varies by version
        out["simplicity_petri_net"] = simp
    except Exception as exc:
        out["simplicity_petri_net"] = "unavailable in this build (%s)" % exc
    return out

for name, s in [("A", A_CANON), ("B", B_CANON),
                ("S (simplified)", "->('Open Case', *('->('Analyze Revision','Check Revision'), 'Rework Case'), 'Close Case')")]:
    tree = pm4py.parse_process_tree(s)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    st = tree_stats(tree)
    ns = net_stats(net, im, fm)
    print(name, st)
    print(name, ns)
```

### 7.3 Reading of the comparison

* **Node counts are equal (12 vs 12)** — the models are *structurally* the same size; the difference is **not** “one is bigger”, it is *where the check sits* (inside vs. outside the loop) and *how many branches are concurrent*.
* A is **one level shallower** (depth 4 vs 5) because the check is a plain sequence step, whereas B needs a parallel split/join pair.
* B’s converted net has a **split/join** and hence **additional places**, a **larger reachable marking space**, and **more enabled transitions per marking** (the check competes with the first analysis), i.e. B is *less deterministic* and *less simple* in the Petri-net sense; the `simplicity_petri_net` call reports the version-specific simplification, and the code above additionally reports the deterministic proxies (places/transitions, reachable markings, silent transitions).
* A and B have the same number of visible/silent leaves and the same *static* duplicate-label count (0). The **runtime** duplication is where they differ: A repeats `Analyze` **and** `Check` together, B repeats `Analyze` alone. Any “simplification” that removes the duplication of the check (e.g. by moving it out of the loop) destroys P1 — this is the structural statement behind the verdict of §3.

# 8. Simplified Model

### 8.1 Target semantics and the choice

**Target: P1 (operational compliance), with P2 retained as a *derived* view.** Rationale: P1 is the only view that distinguishes the two models and the only one with a *safety* meaning; P2 is a strict coarsening of any P1-conformant model (the dashboard only needs “1 analysis”, “a check occurred”, “rework occurred”), and P3 is a *testing procedure* that can be run against any model. So a model that satisfies P1 exactly also serves P2 and is testable under P3.

Two candidates are presented; the **designated** `simplified_model` is the exact one (§8.2), and the aggressive one (§8.2b) is offered with its loss made explicit.

### 8.2 `simplified_model` — exact P1 preservation

```python
import pm4py

# ---------------------------------------------------------------------------
# simplified_model : the P1-exact model.
#
#  * one check belongs to one analysis  (loop scope preserved),
#  * a rework separates two analyses    (loop shape preserved),
#  * the optional approval is preserved  (XOR with a silent branch),
#  * Open first / Close last            (sequence preserved),
#  * the redundant nesting of Model A is flattened wherever the target PM4Py
#    version accepts an n-ary sequence; the binary form below is used because
#    it is unambiguous under any sequence semantics.
# ---------------------------------------------------------------------------
SIMPLIFIED_TREE = (
    "->('Open Case', "
    "*(->('Analyze Revision','Check Revision'), '->('Rework Case', +('Approve Revision','tau'))), "
    "'Close Case')"
)
```

Wait — the string above moves the approval *after* the rework, which changes approval placement. The P1-exact model must keep the approval **inside** the iteration, after the check:

```python
SIMPLIFIED_TREE = (
    "->('Open Case', "
    "*(->(->('Analyze Revision','Check Revision'), +('Approve Revision','tau')), 'Rework Case'), "
    "'Close Case')"
)

simplified_model = pm4py.parse_process_tree(SIMPLIFIED_TREE)      # <- the deliverable
simplified_net, simplified_im, simplified_fm = pm4py.convert_to_petri_net(simplified_model)
```

i.e. `simplified_model` is **Model A (canonical) with the redundant XOR wrapper around the analysis/check pair removed and the approval expressed as the standard XOR-with-silent-branch**. It is *trace-identical* to Model A (canonical):

```
simplified_model  _vis  Model A (canonical)
```

**Alternative construction without relying on the string parser** (the operator attribute name differs between PM4Py versions, hence the defensive form):

```python
from pm4py.objects.process_tree.process_tree import ProcessTree, Operator

def _mk(label=None, operator=None, children=()):
    try:
        n = ProcessTree(label=label, operator=operator)     # newer versions
    except TypeError:
        n = ProcessTree(label=label)                       # older versions
        n.operator = operator
    for c in children:
        n.add_child(c)
    return n

def simplified_model_programmatic():
    body = _mk(operator=Operator.SEQUENCE, children=[
        _mk(label="Analyze Revision"),
        _mk(label="Check Revision"),
        _mk(operator=Operator.EXCLUSIVE, children=[
            _mk(label="Approve Revision"),
            _mk(label="tau"),
        ]),
    ])
    loop = _mk(operator=Operator.LOOP, children=[body, _mk(label="Rework Case")])
    root = _mk(operator=Operator.SEQUENCE,
               children=[_mk(label="Open Case"), loop, _mk(label="Close Case")])
    return root
```

### 8.3 Preservation table

Statuses: **exact** (preserved bit-for-bit), **abstracted** (preserved up to a declared collapse), **weakened** (still true but with less information), **lost** (no longer represented).

| Property | Model A (canonical) | Model B (canonical) | `simplified_model` | Status of `simplified_model` vs. A |
|---|---|---|---|---|
| `Open Case` first, `Close Case` last | yes | yes | yes | **exact** |
| 1 `Analyze Revision` | yes | yes | yes | **exact** |
| 1 `Check Revision` | yes | yes | yes | **exact** |
| `Count_Check = Count_Analyse` (check belongs to an analysis) | yes | **no** (1) | yes | **exact** |
| P1 compliance predicate `C(w)` holds on *every* trace | yes | **no** | yes | **exact** |
| `Rework Case` separates two analyses | yes | yes | yes | **exact** |
| Approval optional and observable (count) | yes | yes | yes | **exact** |
| Approval placement relative to its own check (after the check) | yes | **no** (may precede the check) | yes | **exact** |
| Loop scope of the check (per iteration) | yes | **no** (per case) | yes | **exact** |
| Visible trace language | — | different | identical to A | **exact** |
| P2 dashboard image `D(Vis)` | — | *equal to A’s* | identical to A’s | **exact** (and equal to B’s) |
| P3 bounded language `Vis_` | — | different | identical to A’s | **exact** |
|  / silent transitions (1) | yes | yes | yes | **exact** |
| Concurrency | none | **1 parallel region** | none | **exact** |
| Approval *observability* if removed (`_compact`) | — | — | **lost** | weakened / **lost** under `_compact` |

Conclusion from the table: **one simplification cannot preserve all three views.**
* `simplified_model` (exact) preserves **P1 and P3 exactly** and P2 exactly; but it is only *marginally* smaller than A (one redundant XOR wrapper) and *smaller than B* in depth and concurrency. It is a **repair + de-duplication**, not a redesign.
* `simplified_model_compact` is **4 nodes smaller (8 vs 12), 1–2 levels shallower, has no silent transition and no nondeterminism at all** — a genuine structural simplification — but it **loses the approval event**, hence it *weakens* P1 (approval count/placement) and *strictly shrinks* the P3 language. It **preserves P2 exactly**.
* Any model that keeps the optional approval must keep an XOR-with-silent-branch, so **no further exact reduction is possible**; the approval is irreducibly “one XOR + two leaves” in every process-tree encoding (a sequence `Approve  ` would make the approval *mandatory* and would change the language).

### 8.5 Executable regression harness

```python
import pm4py
from pm4py.petri_net.utils.petri_net_utils import apply_transition

# --- reuse the helpers of section 5 (paste them here to keep it standalone) ---
SILENT_NAMES = {"tau", "silent", "skip", "o"}

def is_silent(net, t):
    tr = net.transitions[t]
    return (tr.label is None or str(tr.label).strip().lower() in SILENT_NAMES
            or tr.attribute.get("tau", False) or tr.attribute.get("silent", False))

def enabled_transitions(net, marking):
    getter = getattr(pm4py, "get_enabled_transitions", None)
    if getter is not None:
        try:
            return list(getter(net, marking))
        except Exception:
            pass
    return [t for t in net.transitions
            if all(marking[p] >= 1 for p in net.in_arcs.get(t, []))]

def markings_equal(m1, m2):
    d1, d2 = dict(m1), dict(m2)
    return all(d1.get(p, 0) == d2.get(p, 0) for p in set(d1) | set(d2))

def explore(net, im, fm, max_visible=12, max_analyze=3):
    res, seen, q = set(), set(), collections.deque()
    q.append((im, ())); seen.add((im, ()))
    while q:
        marking, trace = q.popleft()
        if markings_equal(marking, fm):
            res.add(trace); continue
        for t in sorted(enabled_transitions(net, marking),
                        key=lambda x: str(net.transitions[x].label)):
            lab = net.transitions[t].label
            sil = is_silent(net, t)
            nt = trace if sil else trace + (lab,)
            if len(nt) > max_visible: continue
            if (not sil and lab == "Analyze Revision"
                    and sum(1 for e in nt if e == "Analyze Revision") > max_analyze): continue
            nm = apply_transition(net, marking, t)
            k = (nm, nt)
            if k in seen: continue
            seen.add(k); q.append(k)
    return res

import collections   # used by explore()

# --- the models under test ---------------------------------------------------
A_CANON = ("->('Open Case', *(->(->('Analyze Revision','Check Revision'), +('Approve Revision','tau')),"
            " 'Rework Case'), 'Close Case')")
B_CANON = ("->('Open Case', &('Check Revision', *(->('Analyze Revision', +('Approve Revision','tau')),"
            " 'Rework Case')), 'Close Case')")
SIMPLIFIED_TREE = A_CANON          # the exact simplified model of 8.2
SIMPLIFIED_COMPACT = ("->('Open Case', *('->('Analyze Revision','Check Revision'), 'Rework Case'), 'Close Case')")

def traces_of(s):
    net, im, fm = pm4py.convert_to_petri_net(pm4py.parse_process_tree(s))
    return explore(net, im, fm)

TA, TB, TS, TC = traces_of(A_CANON), traces_of(B_CANON), traces_of(SIMPLIFIED_TREE), traces_of(SIMPLIFIED_COMPACT)

REGRESSION = [
    ("Open Case", "Analyze Revision", "Check Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
     "Analyze Revision", "Check Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
     "Analyze Revision", "Check Revision", "Rework Case",
     "Analyze Revision", "Check Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Check Revision", "Approve Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Check Revision", "Approve Revision", "Rework Case",
     "Analyze Revision", "Check Revision", "Approve Revision", "Close Case"),
]
NEGATIVE = [
    ("Open Case", "Analyze Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Rework Case", "Analyze Revision",
     "Check Revision", "Close Case"),
    ("Open Case", "Check Revision", "Analyze Revision", "Close Case"),
    ("Open Case", "Analyze Revision", "Check Revision", "Rework Case",
     "Analyze Revision", "Close Case"),
    ("Open Case", "Close Case"),
]

print("simplified_model == Model A (trace identical)? ", TS == TA)
print("simplified_model_compact subset of Model A?     ", TC <= TA)

ok = True
for w in REGRESSION:
    r = (w in TA, w in TB, w in TS, w in TC)
    print("REG", r, " -> ", " -> ".join(w)); ok &= (r[0] and r[2])
for w in NEGATIVE:
    r = (w in TA, w in TB, w in TS, w in TC)
    print("NEG", r, " -> ", " -> ".join(w)); ok &= (not r[2])
print("expectations holding (A and simplified_model behave as specified)?", ok)
```

# 9. Final Recommendation

**Per-view recommendation (reading R-C, after repairing the operator misuse of §1.0).**

| Business view | Recommended model | Why | Caveat |
|---|---|---|---|
| **P1 — operational compliance / audit** | **Model A** (canonicalised: `+('Analyze Revision','Check Revision')`  `->('Analyze Revision','Check Revision')`; `X(...)`  `+('Approve Revision','tau')`) | It is the only model that **guarantees** `C(w)` on *every* trace: one check per analysis, before the next rework/close; approvals observable and always after their own check. | Must not be shipped with the literal `+`: under R-L, A itself does not guarantee the check-per-analysis rule. Keep the tie between an approval and its check (never move the approval out of the iteration). |
| **P2 — executive dashboard** | **Model A** (or the compact model) | The dashboard is *insensitive* to the difference (`D(Vis(A)) = D(Vis(B))`); feeding it A costs nothing and keeps a single source of truth. | The dashboard must **not** be used for compliance assurance: it is provably blind to B’s defect. Add a separate counter of `Check Revision` *per analysis* if that matters. |
| **P3 — bounded testing** | **Model A as the reference oracle**, B as the system under test | B is refuted inside a *very* small bound (7 visible events, 2 analyses), so the regression suite is cheap. | The bound must allow 2 analyses (with 1 analysis and approvals hidden, the difference in check multiplicity is invisible). Bounded equality would have been evidence only. |

**Should the simplified model replace an original?**

* `simplified_model` (exact, §8.2): it is trace-identical to Model A and therefore **may** replace A **as the executable artefact**, because nothing observable changes (P1, P2, P3 all preserved exactly). It is *not* smaller than A in any meaningful way — its only gain is the removal of one redundant XOR wrapper — so the real value of this artefact is that it **documents the intended semantics** and prevents the `+`/`->` mistake from recurring.
* `simplified_model_compact` (§8.2b): 8 nodes vs 12, depth 3 vs 4/5, no silent transition, no nondeterminism, no parallel region — a genuine simplification. It **may replace both originals only if the business confirms that the approval is irrelevant**; it **must not** replace A if P1’s “number and placement of approvals remains visible and potentially relevant” still holds, because it *loses* that information (R4/R5 become unobservable). It never replaces A as the *audit* model.
* **Model B should not replace A for P1 or P3 under any configuration**; it is acceptable only as a *dashboard feed* (P2) or as a deliberately relaxed (“best-effort check”) process whose contract explicitly says the check is per *case*, not per *revision*.

**Warning about the limits of bounded comparison.**

1. The P3 bound is a *refutation* device. Our “not equivalent under P3” verdict is strong because the witnesses (T2, T4) lie **inside** the bound — a witness inside the bound refutes *unbounded* equivalence as well.
2. The converse does not hold: had the bounded languages been equal, we would have had **evidence only**; unbounded differences could still hide behind the bound (e.g. a defect that only manifests from the 13th visible event on, or from the 4th analysis on).
3. The bound is *not* neutral: it interacts with the shape of the difference. Here the difference (check multiplicity) only becomes visible at **two** analyses; Had `B_an = 1` been used, the bounded comparison would have been far less discriminating. Whenever a bounded result is reported, the bound and its interaction with the suspected defect must be stated together.
4. Bounded comparison says nothing about *probabilities*, *timing*, *resources*, or *object-level* identity; nor about the silent branch’s semantics beyond “it is invisible”. A  that is “invisible but semantically relevant” (e.g. a timeout branch with different costs) would require a richer observation model than P1–P3 provide, and none of the verdicts above would transfer to it.
5. Finally, all verdicts in this document are **conditional on the observation model** and on the **repair of the operator misuse**. A different reading of `+`/`&`/`X`/`tau` changes the answer — as §4.3 shows, the literal reading even reverses the *inclusion direction* between A and B while leaving the verdict “not equivalent” intact.
