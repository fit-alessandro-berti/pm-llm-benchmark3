```python
import pm4py
from pm4py.objects.petri_net.obj import Marking
from collections import deque

MODEL_A = "->('Open Case', *(->(+('Analyze Revision', 'Check Revision'), X('Approve Revision', tau)), 'Rework Case'), 'Close Case')"
MODEL_B = "->('Open Case', +('Check Revision', *(->('Analyze Revision', X('Approve Revision', tau)), 'Rework Case')), 'Close Case')"

def parse_and_convert(s):
    tree = pm4py.parse_process_tree(s)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    return tree, net, im, fm

def fire(net, marking, t):
    m = dict(marking)
    for arc in t.in_arcs:
        p = arc.source
        weight = getattr(arc, "weight", 1)
        m[p] = m.get(p, 0) - weight
        if m[p] == 0:
            del m[p]
    for arc in t.out_arcs:
        p = arc.target
        weight = getattr(arc, "weight", 1)
        m[p] = m.get(p, 0) + weight
    return Marking(m)

def marking_key(m):
    return tuple(sorted((p.name, c) for p, c in m.items()))

def bounded_visible_language(net, im, fm, max_visible=12, max_analyze=3):
    traces = set()
    queue = deque()
    start_mark = Marking(dict(im))
    queue.append((start_mark, ()))
    visited = set()
    visited.add((marking_key(start_mark), ()))
    while queue:
        m, trace = queue.popleft()
        if m == fm:
            traces.add(trace)
            continue
        for t in pm4py.get_enabled_transitions(net, m):
            nm = fire(net, m, t)
            label = t.label
            ntrace = trace
            if label is not None:
                ntrace = trace + (label,)
                if len(ntrace) > max_visible:
                    continue
                if label == "Analyze Revision" and ntrace.count("Analyze Revision") > max_analyze:
                    continue
            key = (marking_key(nm), ntrace)
            if key in visited:
                continue
            visited.add(key)
            queue.append((nm, ntrace))
    return traces

def main():
    tree_a, net_a, im_a, fm_a = parse_and_convert(MODEL_A)
    tree_b, net_b, im_b, fm_b = parse_and_convert(MODEL_B)
    print("Soundness A:", pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=True))
    print("Soundness B:", pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=True))

    la = bounded_visible_language(net_a, im_a, fm_a)
    lb = bounded_visible_language(net_b, im_b, fm_b)

    print("A traces under bound:", len(la))
    print("B traces under bound:", len(lb))
    print("A-only traces:")
    for t in sorted(la - lb):
        print("  ", t)
    print("B-only traces:")
    for t in sorted(lb - la):
        print("  ", t)
    print("Bounded language equal?", la == lb)

if __name__ == "__main__":
    main()
```

def process_tree_stats(tree):
    operator_count = 0
    visible_leaves = 0
    silent_leaves = 0
    labels = []
    max_depth = 0

    def walk(node, depth):
        nonlocal operator_count, visible_leaves, silent_leaves, max_depth
        max_depth = max(max_depth, depth)
        if node.children:
            operator_count += 1
            for child in node.children:

        else:

            else:

        "depth_edges": max_depth,
        "visible_leaves": visible_leaves,

# 1. Equivalence Notions

I use PM4Py process-tree notation: `->` is sequence, `+` is parallel, `X` is exclusive choice, `*` is binary loop, and `tau` is silent. The binary-loop semantics is:

`* ( first, second )` = execute `first`; then either stop, or execute `second` and then execute `first` again; repeat as desired.

So the visible language of `*(first, second)` is:

`first ( second first )*`

For this answer, a **visible trace** is the sequence of visible labels obtained from a complete run after deleting every `tau`/silent transition. Duplicate visible labels are distinguished by **occurrence position in the trace word**, not by hidden event identity. Thus:

- `(Analyze, Check, Analyze, Check)` is a trace with two Analyze occurrences at positions 1 and 3;
- `(Check, Analyze, Analyze, Check)` is a different trace even though the same labels occur;
- we do not attach arbitrary event IDs to the two Check occurrences.

The equivalence notions are:

1. **Visible trace equivalence after hiding `tau`**  
   Let `v(M)` be the set of all complete visible traces of model `M`.  
   `M1  M2` iff `v(M1) = v(M2)`.

2. **Bounded visible-language equivalence under P3**  
   Let `v_{12,3A}(M)` be:

   `{ w  v(M) | |w|  12 and count_Analyze(w)  3 }`.

   `M1 _bounded M2` iff these finite sets are equal.  
   This is evidence when sets match, not a proof of unbounded equivalence; if they differ, the differing finite trace is a real counterexample.

3. **Business-relevant equivalence under P1**  
   P1 does not authorize collapsing Check or Approve occurrences; Approve remains visible, and exact visible traces matter. Define a visible trace `w` as **P1-valid** if:

   - `w[0] = Open Case` and `w[-1] = Close Case`;
   - after removing Open and Close, splitting on `Rework Case` gives blocks;
   - each block contains exactly one `Analyze Revision`;
   - each block contains at least one `Check Revision`.

   This encodes “Rework separates two analysis attempts” and “every analysis attempt has its own Check before the next Rework/Close.”  
   `M1 _P1 M2` means their complete visible trace languages after hiding `tau` are equal and every trace is P1-valid. The verdict is robust even under a weaker “same valid visible language” comparison, because A has valid traces with two analyses, while B has no valid trace with two analyses.

4. **Abstracted dashboard equivalence under P2**  
   Define an abstraction from a visible trace `w` to:

   ```text
   abs_P2(w) = (
       w starts with Open Case,
       w ends with Close Case,
       count(w, "Analyze Revision"),
       has(w, "Check Revision"),
       has(w, "Rework Case")
   )
   ```

   This hides `Approve Revision`, hides all silent behavior, collapses repeated Check occurrences to a Boolean, keeps the number of Analyze occurrences, and records only whether any Rework occurred.  
   `M1 _P2 M2` iff `{ abs_P2(w) | w  v(M1) } = { abs_P2(w) | w  v(M2) }`.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The `*` loop contains `->(+(Analyze Revision, Check Revision), X(Approve Revision, tau))` as its first child and `Rework Case` as its second child. Check is inside the loop. | The `*` loop contains `->(Analyze Revision, X(Approve Revision, tau))` as its first child and `Rework Case` as its second child. Check is outside the loop, as a sibling of the loop under the top-level `+`. | In A, each Analyze iteration also has a Check. In B, Check is one global concurrent activity. |
| Minimum Check Revision occurrences | 1 | 1 | Both have at least one check. |
| Maximum Check Revision occurrences | Unbounded, exactly one per Analyze Revision | Exactly 1 | For two Analyze occurrences, A has two Checks; B has only one. |
| Possible placement of Check Revision | Inside each loop iteration, in parallel with Analyze Revision, before the optional Approve and before the next Rework/Close. It may appear before or after the Analyze Revision of that iteration. | One Check can appear anywhere between Open and Close because it is concurrent with the entire revision loop. It may appear before the first Analyze, between Analyze and Rework, after Rework, or even after all Analyze occurrences but before Close. | This is the main structural reason P1 fails for B. |
| Optional Approve occurrences | One optional Approve per loop iteration, placed after the parallel `+(Analyze, Check)` block. | One optional Approve per loop iteration, placed after Analyze in the inner sequence. | If Approve is visible under P1, both have optional Approve traces; the decisive difference is still the Check count. |
| Concurrency | The inner `+` is between Analyze Revision and Check Revision inside the loop body. | The top-level `+` is between Check Revision and the whole revision loop. | B permits the single Check to overlap Rework and later analyses; A requires each Check to complete before the following Rework/Close. |
| Join before Close Case | Close Case is sequenced after the whole `*` loop. | Close Case is sequenced after the top-level parallel join, so both the single Check and the loop must finish before Close. | In both models Close Case is always last, and all required branches are complete before Close. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 operational compliance | `not equivalent` | High | Model A forces `#Check = #Analyze`; Model B forces `#Check = 1`. For two Analyze occurrences, A admits a trace with two Checks, B cannot. Also B can admit a trace whose second analysis block has no Check, violating P1. | This assumes the strict reading that each analysis attempt needs its own Check. If “Check” were reinterpreted as one continuous monitoring activity covering the whole loop, B might pass a weaker compliance check, but that is not the stated P1 abstraction. |
| P2 executive dashboard | `equivalent only under stated abstraction` | High | After hiding Approve, collapsing repeated Check to a Boolean, keeping only the number of Analyze occurrences and the Boolean Rework flag, both models produce exactly the same abstracted tuples. | If Check count or exact A/C interleaving is later made observable, the equivalence disappears. P2 is an abstraction, not exact trace equivalence. |
| P3 bounded testing | `not equivalent` | High | There are complete visible traces with fewer than 12 visible events and exactly two Analyze occurrences that are accepted by one model but not the other. Exhaustive bounded BFS will find these. | The counterexamples prove non-equivalence under the bound and also prove unbounded non-equivalence, because the finite witness is itself a complete trace. If the bounded sets had matched, that would only be evidence, not proof. |

**Why P2 equivalence holds:**  
For any `n  1` Analyze occurrences:

- Model A produces `n` Check occurrences, `n-1` Rework occurrences, and optional Approve occurrences.
- Model B produces `1` Check occurrence, `n-1` Rework occurrences, and optional Approve occurrences.

After P2 abstraction:

- Check multiplicity collapses to `true`;
- Approve is hidden;
- Rework is recorded as a Boolean;
- Analyze count is `n`.

Both models can produce such a trace for every `n  1`, so their P2-abstracted languages are equal.

# 4. Counterexample Traces

All traces below are complete visible traces after hiding `tau`. All contain two Analyze Revision occurrences.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| A1 | `Open Case, Analyze Revision, Check Revision, Rework Case, Check Revision, Analyze Revision, Close Case` | Yes | No | Model B has exactly one Check Revision. After its single Check branch fires, there is no second Check transition left to produce the second Check in this trace. | P1, P3 |
| A2 | `Open Case, Check Revision, Analyze Revision, Approve Revision, Rework Case, Analyze Revision, Check Revision, Close Case` | Yes | No | Model B can never produce two Check Revision occurrences in one trace. Model A can because each loop iteration contains a Check. | P1, P3 |
| B1 | `Open Case, Check Revision, Analyze Revision, Approve Revision, Rework Case, Analyze Revision, Close Case` | No | Yes | Model A requires one Check in the second analysis segment before Close. This trace has no Check after the Rework Case. | P1, P3 |
| B2 | `Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case` | No | Yes | Model A requires a Check in the first analysis segment before the first Rework Case. This trace has no Check before that Rework Case. | P1, P3 |

Optional Approve Revision and hidden `tau` affect the comparison as follows:

- The `tau` in `X(Approve Revision, tau)` allows “auto-approval” traces with no Approve label.
- Approve Revision adds extra visible variants in both models, but it is not the source of non-equivalence.
- The decisive mismatch is the loop scope of Check Revision: A repeats a Check with each Analyze; B has a single Check for the whole case.
- Under P2, all four counterexample traces map to the same dashboard tuple:

  ```text
  open = true, close = true, n_Analyze = 2, check_occurred = true, rework_occurred = true
  ```

  So these traces are not counterexamples under P2.

# 5. Bounded Comparison Code

The code below is an **exhaustive bounded exploration** over markings, not a random playout. It explicitly handles:

- silent transitions;
- repeated markings;
- visible-length bound;
- Analyze-count bound;
- final-marking equality.

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking
from collections import deque

MODEL_A = "->( 'Open Case', *( ->( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) ), 'Rework Case' ), 'Close Case' )"
MODEL_B = "->( 'Open Case', +('Check Revision', *( ->('Analyze Revision', X('Approve Revision', tau)), 'Rework Case')), 'Close Case' )"


def parse_and_convert(tree_string):
    tree = pm4py.parse_process_tree(tree_string)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    return tree, net, im, fm


def fire_transition(net, marking, transition):
    """Return a new marking after firing transition."""
    m = dict(marking)

    for arc in transition.in_arcs:
        p = arc.source
        weight = getattr(arc, "weight", 1)
        m[p] = m.get(p, 0) - weight
        if m[p] == 0:
            del m[p]

    for arc in transition.out_arcs:
        p = arc.target
        weight = getattr(arc, "weight", 1)
        m[p] = m.get(p, 0) + weight

    return Marking(m)


def marking_key(marking):
    return tuple(sorted((p.name, c) for p, c in marking.items()))


def bounded_visible_language(net, im, fm, max_visible=12, max_analyze=3):
    """
    Exhaustive BFS up to P3 bounds.
    This is NOT pm4py.play_out; it explores all reachable markings,
    not random samples.
    """
    traces = set()
    queue = deque()
    start_marking = Marking(dict(im))

    # State is (marking, visible trace prefix).
    # Same marking with same visible prefix is not expanded again.
    visited = set()
    visited.add((marking_key(start_marking), ()))
    queue.append((start_marking, ()))

    while queue:
        marking, trace = queue.popleft()

        # A complete trace in a sound accepting Petri net ends at the final marking.
        if marking == fm:
            traces.add(trace)
            continue

        for transition in pm4py.get_enabled_transitions(net, marking):
            new_marking = fire_transition(net, marking, transition)
            label = transition.label
            new_trace = trace

            # Silent transitions do not extend the visible trace.
            if label is not None and label != "tau":
                new_trace = trace + (label,)

                if len(new_trace) > max_visible:
                    continue

                if label == "Analyze Revision" and new_trace.count("Analyze Revision") > max_analyze:
                    continue

            key = (marking_key(new_marking), new_trace)
            if key in visited:
                continue

            visited.add(key)
            queue.append((new_marking, new_trace))

    return traces


def main():
    tree_a, net_a, im_a, fm_a = parse_and_convert(MODEL_A)
    tree_b, net_b, im_b, fm_b = parse_and_convert(MODEL_B)

    print("Soundness A:", pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=True))
    print("Soundness B:", pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=True))

    lang_a = bounded_visible_language(net_a, im_a, fm_a)
    lang_b = bounded_visible_language(net_b, im_b, fm_b)

    print("A traces under bound:", len(lang_a))
    print("B traces under bound:", len(lang_b))

    only_a = sorted(lang_a - lang_b)
    only_b = sorted(lang_b - lang_a)

    print("Unique to A:")
    for trace in only_a:
        print("  ", trace)

    print("Unique to B:")
    for trace in only_b:
        print("  ", trace)

    print("Bounded language equal?", lang_a == lang_b)


if __name__ == "__main__":
    main()
```

This code will find, among others, the A-only and B-only counterexample traces from Section 4. Because it is exhaustive for the stated bound, it does not rely on random playout.

# 6. Stochastic and Footprint Comparison

### Footprints

`pm4py.discover_footprints(...)` can add model-level evidence about start activities, end activities, directly-follows relations, and parallel relations.

```python
# If the installed PM4Py version supports footprint discovery for accepting Petri nets:
footprints_a = pm4py.discover_footprints(net_a, im_a, fm_a)
footprints_b = pm4py.discover_footprints(net_b, im_b, fm_b)

print("Footprints equal?", footprints_a == footprints_b)
```

Equal footprints would **not** prove trace equivalence. Footprints are an abstraction. Two models can have the same directly-follows and parallel relation sets but different loop-body counts or different exact interleavings.

### Stochastic language and EMD

The original process trees carry no transition probabilities. Therefore `pm4py.get_stochastic_language(...)` and `pm4py.compute_emd(...)` require an additional modeling assumption, such as “uniform choice among enabled transitions at each marking.” That assumption is not part of the process-tree semantics.

If probabilities were declared, a low Earth Mover’s Distance could show that the stochastic languages are similar, but it still would not establish trace equivalence. EMD measures probability mass distance; traces with very low probability can contribute little to EMD even if one support contains traces the other support does not.

Code for structural counts:

```python
def process_tree_stats(tree):
    operator_count = 0
    visible_leaves = 0
    silent_leaves = 0
    labels = []
    max_depth = 0

    def walk(node, depth):
        nonlocal operator_count, visible_leaves, silent_leaves, max_depth

        max_depth = max(max_depth, depth)

        if node.children:
            operator_count += 1
            for child in node.children:
                walk(child, depth + 1)
        else:
            if node.label is None:
                silent_leaves += 1
            else:
                visible_leaves += 1
                labels.append(node.label)

    walk(tree, 0)

    return {
        "node_count": operator_count + visible_leaves + silent_leaves,
        "depth_edges": max_depth,
        "visible_leaves": visible_leaves,
        "silent_leaves": silent_leaves,
        "duplicate_label_count": len(labels) - len(set(labels)),
    }


# Example:

```

# 8. Simplified Model

I choose the **P2 executive dashboard** as the target semantics because it is the view under which the two original models are already equivalent, and because a simpler model can preserve that abstracted semantics while removing compliance-irrelevant detail.

### 8.1 Compact process-tree expression

```text
->(
    'Open Case',
    'Check Revision',
    *(
        'Analyze Revision',
        'Rework Case'
    ),
    'Close Case'
)
```

In one line:

```text
->('Open Case', 'Check Revision', *('Analyze Revision', 'Rework Case'), 'Close Case')
```

### 8.2 PM4Py code for simplified model

```python
simplified_model = pm4py.parse_process_tree(
    "->('Open Case', 'Check Revision', *('Analyze Revision', 'Rework Case'), 'Close Case')"
)

simplified_net, simplified_im, simplified_fm = pm4py.convert_to_petri_net(simplified_model)

print("Simplified model:", simplified_model)
print("Simplified sound:", pm4py.check_soundness(
    simplified_net, simplified_im, simplified_fm, print_diagnostics=True
))
```

### 8.3 Preservation table

| Property | Preservation | Explanation |
|---|---|---|
| Open Case first, Close Case last | Exact | The root sequence enforces this. |
| At least one Analyze Revision | Exact | The loop `*(Analyze Revision, Rework Case)` executes Analyze Revision at least once. |
| Number of Analyze Revision occurrences | Exact | The loop emits `n  1` Analyze occurrences. |
| Rework count = Analyze count  1 | Exact | The loop structure emits one Rework between consecutive Analyze occurrences. This is stronger than P2’s Boolean Rework requirement. |
| At least one Check Revision | Abstracted | The simplified model has exactly one Check Revision. P2 collapses repeated Check occurrences to a Boolean, so this is enough. |
| Approve Revision and silent behavior | Lost/Abstracted | P2 explicitly hides Approve Revision and silent behavior; the simplified model omits them. |
| Exact interleaving of Analyze and Check | Weakened/Lost | The simplified model places Check before the loop; P2 explicitly says the dashboard does not record the exact interleaving of Analyze and Check. |
| P1 compliance | Lost | With only one Check Revision, the simplified model cannot satisfy “every analysis revision must have its own Check Revision.” |
| P3 bounded visible-language equivalence | Lost | P3 retains all visible labels, including Approve and repeated Checks; the simplified model is not equivalent to either original at that exact visible-label level. |

### 8.4 Regression and negative traces

Regression traces are accepted by the simplified model.

| Kind | Trace | Why |
|---|---|---|
| Regression | `Open Case, Check Revision, Analyze Revision, Close Case` | One Analysis Revision, no Rework. Dashboard tuple: `n_Analyze=1, check=true, rework=false`. |
| Regression | `Open Case, Check Revision, Analyze Revision, Rework Case, Analyze Revision, Close Case` | Two Analysis Revisions separated by one Rework. Dashboard tuple: `n_Analyze=2, check=true, rework=true`. |
| Regression | `Open Case, Check Revision, Analyze Revision, Rework Case, Analyze Revision, Rework Case, Analyze Revision, Close Case` | Three Analysis Revisions separated by two Rework cases. Dashboard tuple: `n_Analyze=3, check=true, rework=true`. |

Negative traces are rejected by the simplified model.

| Kind | Trace | Why |
|---|---|---|
| Negative | `Open Case, Check Revision, Analyze Revision, Rework Case, Close Case` | After a Rework Case, the loop requires another Analyze Revision before Close. |
| Negative | `Open Case, Check Revision, Analyze Revision, Analyze Revision, Close Case` | Two consecutive Analyze Revisions without an intervening Rework Case are impossible in the loop. |

# 9. Final Recommendation

- **P1 operational compliance:** Use **Model A**. Model B should not be used because it has only one Check Revision for the whole case and cannot satisfy the requirement that every analysis attempt has its own Check before the next Rework or Close.

- **P2 executive dashboard:** Either Model A or Model B can be used, and the simplified P2 model from Section 8 can replace either one **only when the P2 abstraction is applied before comparison**. The simplified model is structurally smaller and preserves the dashboard-relevant facts: Open first, Close last, Analyze count, Check occurred, Rework occurred.

- **P3 bounded testing:** Neither original model is equivalent under the stated bound. The counterexamples are small and exhaustive; any future bounded comparison should use exhaustive BFS rather than random playout.

**Warning about bounded comparison:**  
Bounded language equivalence is evidence, not proof of unbounded equivalence. However, a bounded comparison that finds a counterexample is conclusive for non-equivalence of the full languages, because the bounded counterexample is itself a complete trace. If a bounded comparison finds no differences, that does **not** prove unbounded equivalence.
