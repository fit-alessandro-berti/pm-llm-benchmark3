## 1. Executive causal assessment

**Provisional verdict: mainly confounded. Confidence: 72/100.** The crude association says Orion cases are slower: Orion mean cycle time is 21.96h versus Nova 15.24h, a +6.71h gap. But the strongest counter-evidence is a clear aggregate-versus-stratified reversal: within every observed complexity stratum, Orion is faster than Nova on mean cycle time: Low 7.50h versus 9.64h, Medium 17.17h versus 19.38h, and High 31.57h versus 35.00h. Using the overall complexity mix as common weights, Orion’s standardized mean is about 17.14h versus Nova’s 19.65h, a −2.51h Orion contrast. This does not prove Orion is causally faster, because complexity is coarse, overlap is weak, and Orion is heavily entangled with night work, high arrival load, compliance-required cases, and difficult-case routing. This assessment uses only the supplied prompt data. 

A **total effect** of “assigning to Orion” as currently implemented would include the routing bundle: queue exposure, night coverage, reviewer skill mix, compliance-related waiting, and rework loops. A **direct effect** would compare Orion versus Nova holding case risk, shift, load, compliance requirement, and queue state fixed. A **mediated effect** would operate through queue wait, review service time, rework, or quality. Blindly moving 50% of Orion work to Nova may succeed only if Orion’s queues or operating practices are truly harmful. It may fail or backfire if Orion is absorbing harder, night, compliance-heavy cases more efficiently than Nova would, or if Nova’s day-oriented capacity becomes congested.

A static DAG suppresses feedback: tonight’s Orion WIP can change later queue load, routing decisions, reviewer availability, and rework congestion.

Final recommendation: **do not reassign 50% of Orion’s future cases to Nova based on the crude mean.** The evidence is more consistent with Orion being assigned harder, night, high-load, compliance-heavy work than with a simple harmful Orion effect. The within-complexity reversal is strategically important, but it is not sufficient causal identification because overlap is sparse and hidden risk remains plausible. Management should first stabilize measurement and reconstruct queue states, then run two targeted interventions: a queue/compliance-capacity test for Orion-heavy periods, and a small randomized or quasi-random routing pilot only in cells with real overlap. Scaling should be stratum-specific, not blanket. If Nova truly improves matched cases without quality or spillover damage, expand gradually. If delays fall after queue/compliance capacity changes while group effects vanish, invest in bottleneck capacity rather than moving the label. If Orion proves beneficial for complex/night cases, protect Orion capacity and route simpler supported cases elsewhere only when Nova load allows.

        print(f"WARNING: trace variant has weak group support: {trace} -> {row.to_dict()}")

def manual_dfg_counts(subframe):
    """Fallback directly-follows counts from trace strings; no timestamps are fabricated."""
    counts = Counter()
    for trace in subframe["trace"]:
        activities = trace.split(">")
        for a, b in zip(activities, activities[1:]):
            counts[(a, b)] += 1
    return dict(sorted(counts.items()))

def pm4py_or_manual_dfg(subframe):
    """
    Use PM4Py when available, consistently with trace-string parsing.
    If PM4Py is unavailable in the runtime, fall back to manual directly-follows counts
    so the diagnostic still runs without fabricating timestamps.
    """
    try:
        import pm4py
        trace_string = "\n".join(subframe["trace"].str.replace(">", ",", regex=False))
        log = pm4py.parse_event_log_string(trace_string, sep=",")
        discovered = pm4py.discover_dfg(log)
        # PM4Py commonly returns (dfg, start_activities, end_activities).
        dfg = discovered[0] if isinstance(discovered, tuple) else discovered
        return dict(sorted(dfg.items()))
    except Exception as exc:
        print(f"WARNING: PM4Py DFG discovery unavailable or failed ({exc!r}); using manual DFG counts.")
        return manual_dfg_counts(subframe)

print("\n=== 6) Group-specific directly-follows graphs ===")
dfg_by_group = {}
for group, sub in df.groupby("resource_group"):
    dfg_by_group[group] = pm4py_or_manual_dfg(sub)
    print(f"\nDFG for {group}:")
    for edge, count in dfg_by_group[group].items():
        print(f"  {edge}: {count}")

print("\nDirectly-follows edge comparison:")
all_edges = sorted(set().union(*[set(dfg.keys()) for dfg in dfg_by_group.values()]))
for edge in all_edges:
    counts = {group: dfg_by_group[group].get(edge, 0) for group in sorted(dfg_by_group)}
    print(f"{edge}: {counts}")

## 8. Residual uncertainty

1. **Hidden case difficulty within `complexity`.** Most valuable addition: the routing engine’s numeric risk score and routing reason captured at assignment time.

2. **True queue state at classification and compliance.** Most valuable addition: timestamped WIP, queue length, and available reviewer/compliance capacity at each routing decision.

3. **Reviewer-level capability and workload.** Most valuable addition: assigned reviewer ID with certification level, active workload, and shift roster at the time of review.

4. **Selection from observing only completed cases.** Most valuable design change: include open, abandoned, and censored cases with extraction date so survival or censoring-aware analysis is possible.

5. **Quality interpretation of the 30-day outcome.** Most valuable addition: detailed appeal/reopen reason codes distinguishing review error, customer behavior, external evidence arrival, and post-process events.
