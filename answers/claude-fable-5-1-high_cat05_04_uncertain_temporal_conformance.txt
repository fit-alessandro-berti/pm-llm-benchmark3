## 1. Normalization Assumptions

**A1. Interval construction (two-stage, in the prescribed order).**
Recorded value → (stage 1: resolution) → clock-time interval [c_lo, c_hi] on the source's own clock → (stage 2: clock correction) → true-time interval. With `clock_offset = recorded − true ∈ [a, b]`, the true time is `recorded − offset`, so

  true ∈ [c_lo − b, c_hi − a].

Note the direction: the *upper* offset bound shifts the *lower* end of the true-time interval and vice versa. Every endpoint is treated as attainable (closed interval); the "…:59.999" endpoint of a floored minute is written as such and treated as closed for classification (the 1 ms difference never crosses any threshold used here).

**A2. Resolution semantics per source.**
- HUB: displayed second is exact but has ±0.5 s measurement uncertainty → clock ∈ [T−0.5 s, T+0.5 s]; with offset [−1,+1] s the true interval is [T−1.5 s, T+1.5 s] (half-width 1.5 s).
- OPS-BER: floor to minute → clock ∈ [M:00.000, M:59.999]; offset [−90,+120] s → true ∈ [M − 120 s, M + 59.999 s + 90 s] = [M − 2:00, M + 2:29.999].
- SENSOR: round to nearest 10 s → clock ∈ [X−5, X+5]; offset ±5 s → true ∈ [X−10 s, X+10 s]. The event is a *completion* event, so it is the correct anchor for `Containment_Complete`.
- VENDOR-NY: floor to minute; offset ±180 s → true ∈ [M − 3:00, M + 3:59.999].
- LEGACY-BER: floor to minute; offset ±60 s → true ∈ [M − 1:00, M + 1:59.999], per fold.
- MOBILE-LON: round to nearest minute → clock ∈ [M−30 s, M+30 s]; offset ±300 s → true ∈ [M − 5:30, M + 5:30] before any entry-delay treatment.

**A3. Time-zone conversion.** Local wall time is converted to UTC *before* offset correction using IANA rules: Europe/Berlin CEST = UTC+2 (T-401, T-402, T-409), America/New_York EDT = UTC−4 (T-403), Europe/London BST = UTC+1 (T-406). Endpoints of a sub-minute interval always lie in the same fold, so endpoints are converted with the same UTC offset.

**A4. DST fold (T-405).** On 2025-10-26 Europe/Berlin leaves CEST at 03:00 CEST → 02:00 CET, so wall times 02:00–02:59 occur twice: first fold (CEST, UTC+2) maps 02:xx → 00:xx UTC, second fold (CET, UTC+1) maps 02:xx → 01:xx UTC. Each LEGACY-BER event is therefore initially a *union of two disjoint intervals*, one per fold. The three events give 2³ = 8 fold combinations. Ingestion order (Alert_Received < Investigation_Start < Containment_Complete) is assumed to reflect true occurrence order (a substantive assumption: ingestion is a proxy for occurrence). A combination is kept only if each consecutive pair can be ordered (lower bound of the earlier event < upper bound of the later event). The same pruning result is obtained from process causality alone (an alert must be received before investigation starts, which precedes containment), so the pruning is robust to either justification. Surviving timestamps keep their full 3-minute width; pruning removes folds, not uncertainty.

**A5. Inferred start (T-404).** `Investigation_Start = Investigation_Complete − duration` with duration ∈ [18, 25] min from the signed work record, interpreted as elapsed time between start and completion, bounds inclusive, and the work record itself treated as exact-to-the-minute (no additional rounding is stated). All HUB uncertainty on `Investigation_Complete` is propagated: IS ∈ [IC_lo − 25 min, IC_hi − 18 min].

**A6. Missing Alert_Received (T-407).** `Alert_Received = Alert_Sent + latency`, latency ∈ [0, 20] min. The causal constraint "receipt ≤ investigation start" is applied as the primary semantics because the process definition requires it; it clips AR's upper bound to IS's upper bound (14:17:01.5Z). Without it, AR could lie after IS and the pair AR→IS would not exist as an ordered pair (negative durations), which I classify INDETERMINATE for semantic reasons rather than as a pass. Because there is no acknowledgement, receipt itself is not proven; conclusions for T-407 are conditional on receipt having occurred and carry low confidence.

**A7. Mobile entry delay (T-406).** Two interpretations are carried through the whole analysis:
- Interpretation A (recording delay only): the user entered the correct occurrence time late; the delay shifts the log-write time, not the occurrence. Occurrence ∈ [12:08:30Z, 12:19:30Z].
- Interpretation B (occurrence uncertainty): the user entered the time *displayed at entry*, up to 5 min after the actual start; the occurrence may be up to 300 s earlier than the recorded value. Occurrence ∈ [12:03:30Z, 12:19:30Z].
Interpretation A is used as primary (the metadata literally says the user entered "the displayed time … late"; the recorded time is what the user saw), but B is reported everywhere it changes a classification, and it does change S2 for T-406.

**A8. Weak offset evidence (T-409).** NTP diagnostics for OPS-BER are missing for this hour. The engineering estimate ±12 min is *not* a diagnostic bound. Primary treatment: any test whose outcome depends on the OPS-BER offset is INDETERMINATE, with conditional results reported under (i) the weak ±720 s estimate and (ii) the nominal OPS-BER bound [−90,+120] s (not justified for this hour, shown only for sensitivity). Tests whose outcome is the same under both, or that do not involve the OPS-BER event, are classified normally.

**A9. Duration intervals.** For events A (earlier) and B (later), the feasible duration is [B_lo − A_hi, B_hi − A_lo]. Offsets of different events are treated as independent even when they come from the same source (conservative). A common-mode remark: when two events come from the same clock within minutes of each other, the offset largely cancels and only resolution uncertainty remains; this tightens T-405 and HUB–HUB pairs. It is reported as a secondary variant where it changes a class (T-405 AR→IS under ζ = 1), never as the primary result.

**A10. Classification semantics.** SLA acceptance region is [0, limit + tolerance] (a negative duration is not an S-rule violation but signals that the ordering is not established → INDETERMINATE unless a causal constraint is applied). Temporal-profile acceptance is the closed two-sided band [μ − ζσ, μ + ζσ]. Interval wholly inside → CERTAIN_PASS; wholly outside → CERTAIN_VIOLATION; partial overlap → POSSIBLE_VIOLATION; missing event, ordering not established, or class dependent on an untrusted bound → INDETERMINATE. Unions of disjoint intervals are tested piecewise and combined (any pass + any violation → POSSIBLE).

**A11. Severity and confidence scales.** Severity: Low (worst-case exceedance < 1 min or a razor-thin overlap of a few seconds), Medium (1–10 min), High (> 10 min, or > 1 h for S3). Confidence: High (only HUB events, bounds from diagnostics), Medium (bounded non-HUB sources such as OPS-BER/SENSOR/VENDOR-NY/LEGACY-BER with fold resolved), Low (inferred events, mobile entry, or offset without diagnostics).

def parse_naive(s):
    for fmt in ("%Y-%m-%d %H:%M:%S", "%Y-%m-%d %H:%M"):
        try:
            return datetime.strptime(s, fmt)
        except ValueError:
            pass
    raise ValueError(s)

def clock_interval(naive, rounding, meas):
    """Resolution uncertainty on the source's own clock (still local, naive)."""
    if rounding == "exact_second":
        return naive - timedelta(seconds=meas), naive + timedelta(seconds=meas)
    if rounding == "floor_minute":          # displayed 10:14 -> [10:14:00, 10:14:59.999]
        return naive, naive + timedelta(seconds=59.999)
    if rounding == "round_10s":
        return naive - timedelta(seconds=5), naive + timedelta(seconds=5)
    if rounding == "round_minute":
        return naive - timedelta(seconds=30), naive + timedelta(seconds=30)
    raise ValueError(rounding)

def localize_alternatives(naive, tzname):
    """[(label, fold)] - two entries when the wall time is DST-ambiguous."""
    tz = ZoneInfo(tzname)
    offs = [naive.replace(tzinfo=tz, fold=f).utcoffset() for f in (0, 1)]
    if offs[0] == offs[1]:
        return [("unique", 0)]
    return [(f"fold{f}(utc{offs[f]})", f) for f in (0, 1)]

def normalize_event(recorded, system, extra):
    """-> list of (label, lo_utc, hi_utc) feasible true-time intervals (a union when ambiguous)."""
    meta = SOURCES[system]
    a, b = extra.get("offset_override", meta["offset"])
    naive = parse_naive(recorded)
    c_lo, c_hi = clock_interval(naive, meta["rounding"], meta["meas"])
    tz = ZoneInfo(meta["tz"])
    out = []
    for label, fold in localize_alternatives(naive, meta["tz"]):
        # endpoints of a sub-minute interval share the same fold
        lo_utc = c_lo.replace(tzinfo=tz, fold=fold).astimezone(timezone.utc)
        hi_utc = c_hi.replace(tzinfo=tz, fold=fold).astimezone(timezone.utc)
        # true = recorded - offset, offset in [a,b]  ->  [lo - b, hi - a]
        out.append((label, lo_utc - timedelta(seconds=b), hi_utc - timedelta(seconds=a)))
    return out

# 3. Duration intervals and interval classification

def merge(ivs):
    ivs, out = sorted(ivs), []
    for lo, hi in ivs:
        if out and lo <= out[-1][1]:
            out[-1] = (out[-1][0], max(out[-1][1], hi))
        else:
            out.append((lo, hi))
    return out

def duration_intervals(case, a, b, causal=False):
    """Union of feasible [lo,hi] durations (seconds) between activity a and b."""
    A = iv[(iv.case == case) & (iv.activity == a)]
    B = iv[(iv.case == case) & (iv.activity == b)]
    if A.empty or B.empty:
        return None
    out = []
    for ra in A.itertuples():
        for rb in B.itertuples():
            lo = (rb.lo - ra.hi).total_seconds()
            hi = (rb.hi - ra.lo).total_seconds()
            if causal:
                lo = max(lo, 0.0)
            if hi >= lo:
                out.append((lo, hi))
    return merge(out)

def classify(ivs, lo_ok, hi_ok, allow_negative=False):
    if ivs is None:
        return "INDETERMINATE"
    if not allow_negative and any(lo < 0 for lo, _ in ivs):
        return "INDETERMINATE"          # ordering itself not established by the evidence
    any_pass = any(max(lo, lo_ok) <= min(hi, hi_ok) for lo, hi in ivs)
    any_viol = any(lo < lo_ok or hi > hi_ok for lo, hi in ivs)
    if any_pass and not any_viol:
        return "CERTAIN_PASS"
    if any_viol and not any_pass:
        return "CERTAIN_VIOLATION"
    if any_pass and any_viol:
        return "POSSIBLE_VIOLATION"
    return "INDETERMINATE"

def fmt(ivs):
    return " U ".join(f"[{lo:.1f}, {hi:.1f}]" for lo, hi in ivs) if ivs else "n/a"

    """Isolated because the diagnostic shape differs across PM4Py versions.
    Assumed shapes: (a) diagnostics dataframe with columns
    case/source_activity/target_activity/throughput/num_st_devs (pm4py >= 2.7);
    (b) list with one entry per case, each a list of tuples

                                                  return_diagnostics_dataframe=True)

                         r["target_activity"], r.get("throughput", r.get("time_passed")), r["num_st_devs"]))
    except TypeError:                                   # older signature without the dataframe option
        diag = pm4py.conformance_temporal_profile(log_df, TEMPORAL_PROFILE, zeta=zeta)
        case_ids = list(log_df["case:concept:name"].drop_duplicates())
        for cid, devs in zip(case_ids, diag):
            for dev in devs:
                flat.append((str(cid).replace("INC-", ""), dev[0], dev[1], dev[2], dev[3]))
    return pd.DataFrame(flat, columns=["case", "source", "target", "midpoint_duration_s", "num_std_devs"])

## 6. Evidential Sufficiency

Evidence types: SYNC = stronger synchronization evidence (per-event or per-hour clock offset, higher resolution); ACT = missing activity evidence; DUR = duration evidence; SEM = semantic evidence (meaning of a timestamp or ordering).

- T-401 S1 / AR→IS profile (POSSIBLE): SYNC — an OPS-BER offset measurement for 08:14 UTC with error ≤ ±30 s, or a seconds-resolution Investigation_Start record (e.g., the ticketing system's raw event time). A pass would be certain if OPS-BER is shown to be at most ~30 s fast; a violation would be certain if it is shown to be ≥ 90 s slow in the late part of the minute. Alternatively, the HUB-side record of the same start action (a correlated event on a trusted clock).
- T-402 S2 / IS→CC ζ=1 (POSSIBLE): SYNC on the same OPS-BER event (offset known to ±30 s resolves whether IS was before or after 09:17:00Z). T-402 S1 is already certain; at +2/+5 min tolerance it needs the same SYNC evidence. T-402 S3 (INDETERMINATE): ACT — the Close_Incident event.

## 7. Governance Recommendation

1. Timestamp storage: store every event in UTC with explicit offset (RFC 3339 with `Z`), at millisecond resolution or the native resolution of the source, never re-rounded downstream. Store the local wall time and IANA zone name alongside for audit, not as the primary key.
2. Raw timestamp retention: retain the verbatim recorded string, the source system identifier, and the source's clock reading as received; derive normalized values in a separate column with a documented transformation version. Never overwrite the raw value with a "corrected" one.
3. Source offset telemetry: log the clock offset of every non-authoritative source against the HUB reference at least hourly (NTP diagnostics, peer measurement), with the bound and the measurement method, and attach the applicable offset bound to each event at ingestion. Flag events whose hour lacks a measurement (the T-409 situation) as `offset_bound=UNKNOWN` so they cannot silently inherit the nominal bound.
4. Resolution metadata: record the resolution semantics per source as machine-readable metadata (`exact_second`, `floor_minute`, `round_10s`, `round_minute`) and the resulting half-width so interval construction is automatic and reproducible; forbid minute-floored timestamps for SLA-relevant activities where the SLA is measured in minutes (S1 needs ≤ 15 s resolution to be certifiable).
5. Start/complete semantics: every event carries a lifecycle transition (`start`, `complete`, `sent`, `received`, `assign`) in a dedicated attribute; SLA rules reference the transition explicitly (Alert_Received:complete → Investigation_Start:start). Sensor completion events, `Alert_Sent` and `Investigation_Complete` must not be relabelled as the SLA anchor activity.
6. DST fold: for any local-time source, log the UTC offset or the `fold` flag with every event; run a scheduled check on transition nights that rejects ambiguous wall times without a fold marker. Prefer UTC at source; if impossible, capture the monotonic device clock as a tiebreaker.
7. Causal identifiers: propagate an alert identifier from Alert_Sent through Alert_Received, Investigation_Start and Containment_Complete, and record delivery acknowledgements as first-class events so that receipt is observed, not assumed. Store ingestion sequence numbers separately from occurrence time and never use them as a substitute for it except as an explicit ordering constraint (as done for T-405).
8. Mobile and user-entered timestamps: capture the device's automatic entry timestamp, the user-declared occurrence time and the device offset separately; mark the record as `entry_mode=manual`, so the analyst can choose between interpretations A and B with evidence rather than assumption.
9. Interval-based enforcement policy: define three enforcement tiers. (a) Breach is asserted, with financial or contractual consequence, only on CERTAIN_VIOLATION (the entire feasible interval outside the limit), with the source bounds cited. (b) POSSIBLE_VIOLATION triggers an evidence-collection action (Section 6) and a review flag, not a breach; if evidence cannot be obtained within a defined window, the case is reported as "unverifiable" against the party responsible for the weaker evidence, not as a breach. (c) INDETERMINATE (missing activity, unbounded clock, unresolved ordering) is a data-quality incident against the logging owner. Publish the tolerance actually used (0 / 2 / 5 min) and the ζ for statistical monitoring, and report conformance as three counts (certain pass / possible / certain violation) rather than one rate. Overlap of the feasible interval with the acceptance region is therefore sufficient to avoid a breach finding but never sufficient to assert compliance.
10. Analytics practice: keep interval conformance as the system of record; midpoint or point-based tools (including PM4Py temporal-profile conformance) may be used for exploratory monitoring only, labelled as lossy approximations, and any point-based alert must be re-evaluated against the interval before it is acted on.
