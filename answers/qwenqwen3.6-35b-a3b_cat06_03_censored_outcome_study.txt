## 3. Censoring and missing-label strategy
**Distinctions:**
- *Ordinary right censoring:* Open cases and activated cases where <90 days have elapsed since activation.
- *Delayed labels:* External feed arriving 7–35 days post-horizon. Creates asymmetric information availability.
- *Selection through activation:* Labels only exist for activated accounts. This induces informative censoring; the labeled cohort is a selected subpopulation.
- *Transfer:* Competing event that may sever observation. Partial linkage (60%) creates differential missingness.
- *Permanently missing feeds:* Partner-originated accounts with unobserved outcomes. Represents structural missingness.

**Primary analysis strategy:** Inverse Probability of Treatment Weighting (IPTW) applied to the conditional default model. Weights estimate the probability of activation given pre-activation features $X$, then weight each labeled case by $1/\hat{P}(\text{Activated}\mid X)$ to recover an unbiased estimator of the population-level expected loss among approved portfolios. Alternatively, a joint semiparametric model (e.g., parametric activation hazard + conditional default hazard) can be fit.

**Sensitivity analysis:** Cause-specific Cox model with competing risks (Fine-Gray subdistribution hazards) treating rejection/withdrawal/transfer as competing events. Bounds analysis assuming worst-case default rates for permanently missing partner feeds.

**Assumption testability:**
- *Ignorability of censoring given $X$:* Partially testable via standardized mean differences across activation groups; residual confounding possible if unmeasured underwriter discretion drives both approval and risk.
- *Monotonic policy shift:* Testable by comparing activation rates and default distributions before/after 1 July 2025.
- *Transfer linkage completeness:* Fundamentally untestable for the 40% unlinkable subset; can only assess stability of linkage rate over time.

- **Activity renaming:** A canonical mapping layer resolves pre-Oct 2025 renamed activities to current labels before prefix generation. Duplicate events are resolved by keeping the earliest timestamp per `(case, activity)` pair.
- **Strict temporal guard:** All prefix extraction enforces `time:timestamp  prediction_point`. No future events or post-prefix attribute updates are permitted to influence the feature matrix.

## 8. Limitations and decision-use boundary
**What the study can claim:** Robust association between early process traces and activation probability, plus calibrated conditional default risk among approved applications. Quantifies how rework intensity, review timing, and channel characteristics predict 90-day loss given activation.

**What the study cannot claim:** True default risk for rejected, withdrawn, or open applications. The model does not establish causal efficacy of process interventions without randomized trials.

**Deployment-induced DGP changes:**
1. *Adaptive thresholding:* Deploying the model to flag high-risk applicants may trigger additional scrutiny or manual overrides, altering the activation rate and shifting the composition of the labeled cohort.
2. *Human-in-the-loop feedback:* Underwriters may defer to model scores, creating a confirmation bias that suppresses variation in `decision_reason` and compresses feature diversity.
3. *Operational optimization:* Knowing which cases drive defaults may lead to process redesign (e.g., automated KYC for low-risk channels), fundamentally changing event frequencies, cycle times, and the underlying control flow.

## 9. PM4Py-oriented Python implementation skeleton
```python
import pandas as pd
import pm4py
from datetime import datetime

# 1. Load & parse timestamps
events = pd.read_csv("applications_events.csv", parse_dates=["time:timestamp"])
events["data_extract_time"] = pd.to_datetime(events["data_extract_time"])

# 2. Canonicalize activities & deduplicate (addresses migration renaming)
rename_map = {"KYC_CHECK": "Identity/KYC Check", "DOC_REQUEST": "Request Documents"}
events["concept:name"] = events["concept:name"].map(rename_map).fillna(events["concept:name"])
events = events.sort_values("time:timestamp").drop_duplicates(
    subset=["case:concept:name", "concept:name", "time:timestamp"], keep="first"
)

# 3. Format for PM4Py
log = pm4py.format_dataframe(
    events, case_id="case:concept:name", activity_key="concept:name", timestamp_key="time:timestamp"
)

# Configuration
PREDICTION_CUTOFF = pd.Timestamp("2025-09-30")
LABEL_MATURITY_DAYS = 120  # 90d horizon + buffer for delayed feed

# 4. Prefix extraction (fixed-length, strictly before cutoff)
prefixes_df = pm4py.get_prefixes_from_log(log, length=3)
prefixes_df["prediction_time"] = PREDICTION_CUTOFF

# 5. Case-level temporal features & censoring indicators
# Filter events strictly before prediction cutoff to prevent leakage
prefix_events = events[events["time:timestamp"] <= PREDICTION_CUTOFF]
temporal_feats = pm4py.extract_temporal_features_dataframe(
    prefix_events, case_id="case:concept:name", timestamp_key="time:timestamp"
)
service_wait = pm4py.insert_case_service_waiting_time(
    prefix_events.copy(), case_id="case:concept:name", timestamp_key="time:timestamp"
)

# 6. Cohort labeling & censoring as-of cutoff
case_labels = events.groupby("case:concept:name").agg(
    start_time=("time:timestamp", "min"),
    activation_time=("time:timestamp", lambda x: x[events.loc[x.index, "concept:name"]=="Account Activated"].iloc[0] if "Account Activated" in events.loc[x.index, "concept:name"].values else pd.NaT),
    terminal_event=("concept:name", "last"),
    label_value=("default_90d", "first"),
    label_avail=("label_available_at", "max")
).reset_index()

case_labels["matured_for_label"] = (
    case_labels["activation_time"].notna() &
    ((PREDICTION_CUTOFF - case_labels["activation_time"]).dt.days >= 90) &
    (case_labels["label_avail"].notna())
)

# 7. Temporal train/val/test split (avoids random-split leakage across policy/migration)
case_labels["train"] = case_labels["start_time"] < pd.Timestamp("2025-06-30")
case_labels["val"]   = (case_labels["start_time"] >= pd.Timestamp("2025-06-30")) & \
                       (case_labels["start_time"] < pd.Timestamp("2025-09-30"))
case_labels["test"]  = case_labels["start_time"] >= pd.Timestamp("2025-09-30")

# 8. Leakage audit & cohort summary
prohibited_cols = ["final_limit", "decision_reason", "collection_status", "default_90d"]
assert not any(col in prefix_events.columns for col in prohibited_cols), "Leakage detected!"
print(f"Cohort sizes - Train: {case_labels['train'].sum()}, Val: {case_labels['val'].sum()}, Test: {case_labels['test'].sum()}")
print(f"Matured labeled cases: {case_labels['matured_for_label'].sum()}")
```
