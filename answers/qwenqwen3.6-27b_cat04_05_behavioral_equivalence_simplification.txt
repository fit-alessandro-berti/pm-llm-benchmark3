# 1. Equivalence Notions

Equivalence is not absolute; it is defined relative to an observation boundary and abstraction function. Below are the formal notions required for this comparison.

- **Visible trace equivalence after hiding `tau`**: Two models are equivalent if their sets of complete visible traces (sequences of activity labels excluding `tau`) are identical. Duplicate visible labels are distinguished by **position** in the trace (standard linear trace semantics). Interleaving order matters.
- **Bounded visible-language equivalence under P3**: Equivalence restricted to the subset of complete visible traces satisfying: (1) total visible events  12, and (2) count of `'Analyze Revision'`  3. `tau` is hidden. This is a finite-language equivalence; it provides evidence but not a proof of unbounded equivalence.
- **Business-relevant equivalence under P1**: Defined by the compliance constraint: for every occurrence of `'Analyze Revision'`, there must exist a corresponding `'Check Revision'` that occurs in the same logical iteration, strictly before the next `'Rework Case'` or `'Close Case'`. This implies a strict 1:1 pairing and ordering invariant. Duplicate labels are distinguished by **iteration identity**.
- **Abstracted dashboard equivalence under P2**: Defined by a projection function $\pi$ mapping any trace $t$ to a tuple $(\exists \text{Analyze}, \exists \text{Check}, \#\text{Analyze}, \exists \text{Rework})$. The projection collapses repeated `'Check Revision'` to a Boolean, hides `'Approve Revision'` and `tau`, and ignores interleaving. Two models are equivalent if $\pi(L_A) = \pi(L_B)$.

| **Optional approval occurrences** | One optional `Approve Revision` (or `tau`) after each `Analyze`/`Check` pair. | One optional `Approve Revision` (or `tau`) after each `Analyze Revision`. | Identical optional structure, but attached to different loop scopes. |
| **Concurrency** | Local parallelism: `Analyze` \|\| `Check` inside each iteration. | Global parallelism: `Check` \|\| `(Analyze  Rework)*` loop. | A's concurrency is bounded per iteration; B's concurrency spans the entire process. |
| **Join before Close Case** | Sequential join after loop exits. | Parallel join after both branches complete. | A guarantees loop termination before close; B requires explicit synchronization of parallel branches. |

from collections import deque

def parse_and_validate(tree_str, name):
    tree = pm4py.parse_process_tree(tree_str)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    sound = pm4py.check_soundness(net, im, fm, print_diagnostics=False)

    return net, im, fm

def bounded_trace_explorer(net, im, fm, max_visible=12, max_analyze=3):
    """Exhaustive BFS over reachability graph respecting P3 bounds."""
    graph, im_node, fm_node = pm4py.convert_to_reachability_graph(net, im, fm)
    traces = set()
    
    # BFS state: (current_node, visible_trace_tuple, analyze_count)
    queue = deque([(im_node, (), 0)])
    visited = set()
    
    while queue:
        node, trace, a_count = queue.popleft()
        
        # Bound checks
        if len(trace) > max_visible or a_count > max_analyze:
            continue
            
        # Final marking reached
        if node == fm_node:
            traces.add(trace)
            continue
            
        state_key = (node, a_count)
        if state_key in visited:
            continue
        visited.add(state_key)
        
        for edge in graph.out_edges(node, data=True):
            _, target, label = edge
            if label == 'tau':
                # Silent transition: advance without updating trace or bounds
                queue.append((target, trace, a_count))
            else:
                new_a = a_count + (1 if label == 'Analyze Revision' else 0)
                queue.append((target, trace + (label,), new_a))
                
    return traces

# 6. Stochastic and Footprint Comparison

- **`pm4py.discover_footprints(...)`**: Computes a partial-order abstraction capturing causal, parallel, choice, and exclusion relations. Model A and B will yield different footprints because A enforces strict causal pairing between `Analyze` and `Check` per iteration, while B allows global parallelism. **Limitation**: Equal footprints do not imply trace equivalence. Footprints collapse trace multiplicity and interleaving details; distinct trace languages can project to identical footprints.
- **`pm4py.get_stochastic_language(...)`**: Requires explicit transition probabilities. Without domain-assigned probabilities, this is undefined. If uniform probabilities were assigned, the resulting distributions would differ due to structural path counts. **Limitation**: Stochastic equivalence is distributional, not structural. Two models can have identical distributions under specific probabilities but different trace sets.
- **`pm4py.compute_emd(...)`**: Earth Mover’s Distance measures the cost of transforming one trace probability distribution into another. A low EMD indicates statistical similarity, not set equality. **Limitation**: EMD ignores trace support boundaries; a model that forbids a trace entirely can still have low EMD if the forbidden trace has near-zero probability under the assigned distribution.

```python
# Plausible footprint comparison
fp_a = pm4py.discover_footprints(net_a, im_a, fm_a)
fp_b = pm4py.discover_footprints(net_b, im_b, fm_b)
print("Footprints equal?", fp_a == fp_b) # Expected: False
```

# 8. Simplified Model

**Target Semantics**: P2 (Executive dashboard view). It abstracts away interleaving, collapses Check multiplicity, and hides approval noise, making it ideal for high-level reporting.

# 9. Final Recommendation

- **Model A** is suitable for **P1 (operational compliance)**. Its loop-scoped pairing of `Analyze` and `Check` enforces the required audit trail per revision attempt.
- **Model B** is unsuitable for P1 due to its single global check. It is structurally valid for P2 but unnecessarily complex due to parallel interleaving that the dashboard discards.
- **The Simplified Model** should replace both for **P2 (executive dashboard)**. It preserves all dashboard-relevant metrics exactly while eliminating concurrency, optional approval noise, and silent transitions, reducing cognitive and computational overhead.

 **Warning on Bounded Comparison**: P3 bounded equivalence (12 events, 3 Analyzes) only examines a finite prefix of the language. It cannot prove unbounded equivalence, nor can it detect divergence in longer traces or infinite behaviors. Bounded results are evidence of difference, not proof of equivalence. Always validate compliance-critical models (P1) against their full structural invariants, not just sampled traces.
