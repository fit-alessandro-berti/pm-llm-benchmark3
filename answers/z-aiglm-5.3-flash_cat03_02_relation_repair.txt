## 1. Consistency rules and evidence model

**Hard invariants (violating repairs are discarded outright)**

- **H1 Referential integrity:** only existing event/object IDs may be used; no invented events or objects to close lifecycles.
- **H2 Uniqueness:** no duplicate `(eid, oid, qualifier)` or `(oid, oid_2, qualifier)` rows; no conflicting qualifiers for the same pair.
- **H3 Directionality/type compatibility:** qualifiers keep the observed orientation (e.g., `carries`: DeliveryPackage; reversing per rule 8 is forbidden). Each qualifier implies compatible endpoint types.
- **H4 Temporal non-inversion:** an added edge must not imply Create < Add < Pack  Dispatch  Confirm  Issue  Pay inversions stronger than logging latency excuses.

**Strong defaults (violations need explicit licensed exceptions)**

- **S1 Event arities** per domain rules 1–7: Pack = 1 Item + 1 Package *unless* the sanctioned scanner-outage pattern applies; Dispatch = 1 Package + 1 Delivery *unless* licensed bulk dispatch; Payment events touch exactly one Payment and *normally* one Invoice.
- **S2 Structural closure:** after adding an E2O edge, the mirrored O2O edge (`packs`, `carries`, `bills`, `settles`) is expected for object-graph coherence — added at **reduced confidence**, because it is *derived from* the E2O hypothesis, not independent evidence for it.
- **S3 Scope filters:** any proposal must survive customer (C17), route (NORTH), and object-hint agreement.
- **S4 Precedence sanity:** added edges must fit observed timestamps (identification uses payloads, time only vetoes absurd orderings).

**Weak heuristics (tie-breakers only, never sufficient alone)**

- **W1 Identifier similarity:** exact string > normalized prefix (`PK8-2`PK-8 after hyphen-stripping) > wildcard (`N-42*`) > arithmetic residue.
- **W2 Timestamp coincidence:** ev09/ev10 both 10:00 suggests a batching session.
- **W3 Numeric-sum consistency:** 230 = 130 + 100; 100 + 130 = 230. Treated strictly as evidence, not proof — taxes, fees, and round numbers can mimic equality.
- **W4 Attribute plausibility:** weights/routes (largely non-discriminative here: PK-8 is NORTH-consistent with *either* delivery).

**Evidence against repairs (negative evidence caps confidence)**

- **A1 Uncertainty markers:** the literal `N-421?` and wildcard `N-42*` are in-band declarations of unreliable identification; any edge derived from them is capped at "provisional".
- **A2 Licensed exceptions:** scanner-outage rows and unapplied cash are legitimate per rules 3 and 7, so an absence can be *meaningful* rather than defective.
