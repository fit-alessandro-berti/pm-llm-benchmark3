def build_site_b_powl(originals_required=True, bounded_supplement=True):
    powl = POWL()
    def add_node(label):
        node = POWLNode(label=label)
        try:
            powl.add_node(node)
        except Exception:
            # Some PM4Py versions may accept a label directly.
            powl.add_node(label)
        return node
    def add_edge(src, dst):
        try:
            edge = POWLEdge(src, dst)
        except TypeError:
            edge = POWLEdge(source=src, target=dst)
        try:
            powl.add_edge(edge)
        except Exception:
            powl.add_edge(src, dst)
    reg = add_node('Register')
    idc = add_node('Identity Check')
    doc = add_node('Document Check')
    assess = add_node('Assessment')
    decision = add_node('Decision')  # collapsed Approve/Reject because POWL cannot encode XOR
    notify = add_node('Notify')
    if originals_required:
        orig = add_node('Originals Receipt')
        add_edge(reg, orig)
        add_edge(orig, doc)
    else:
        add_edge(reg, doc)
    add_edge(reg, idc)
    # Explicit partial-order edges: Assessment waits for both identity and document verification.
    add_edge(idc, assess)
    add_edge(doc, assess)
    # Main decision path. In a full process tree this would be X(Approve, Reject).
    add_edge(assess, decision)
    # Legal-review branch (precedence constraints only; choice/data dependence not encoded).
    legal = add_node('Legal Review')
    add_edge(assess, legal)
    add_edge(legal, decision)
    supp = add_node('Request Supplement')
    add_edge(legal, supp)
    if bounded_supplement:
        doc2 = add_node('Document Check (Supplement)')
        assess2 = add_node('Assessment (Supplement)')
        legal2 = add_node('Legal Review (Supplement)')
        add_edge(supp, doc2)
        add_edge(doc2, assess2)
        add_edge(assess2, legal2)
        add_edge(legal2, decision)
    else:
        # Unbounded loop would add supp -> doc, creating a cycle and violating strict partial order.
        add_edge(supp, doc)
    add_edge(decision, notify)
    return powl

## 6. Candidate Site B intervention

Modified intervention: do not copy Site A’s all-case simultaneous Document Check creation. Instead, implement a statutory-aware partial-order change.

- Eligibility rules:
  - Phase 1: digital claims where originals are not legally required, no active supplement, low-to-medium complexity, and the case system can support two active task owners.
  - Phase 2: originals-required cases where Identity Check can be assigned while Originals Receipt is pending.
  - Exclude cases with missing registration data, fraud hold, statutory hold, or any rule requiring a different ordering.

- Which tasks may be created or executed concurrently:
  - All eligible cases: Identity Check and Originals Receipt may be created and executed concurrently after Register.
  - Digital claims: Document Check may be created and executed concurrently with Identity Check after Register.
  - Originals-required claims: Document Check may be created in a blocked state, but it cannot start until Originals Receipt is complete.

- Statutory prerequisites that remain mandatory:
  - Register occurs first.
  - Originals Receipt must precede Document Check when originals are legally required.
  - Assessment requires both Identity Check and Document Check complete.
  - Legal Review is required after Assessment for public-sector or high-value cases.
  - Approve/Reject follows Assessment or Legal Review as required.
  - Notify follows final decision.

- Queue and WIP controls:
  - Identity Check WIP limit: 4 open cases per identity reviewer.
  - Document Check WIP limit: 6 open cases per document reviewer.
  - Assessment WIP limit: 3 open cases per assessor.
  - Legal Review WIP limit: 2 open cases per legal reviewer.
  - Supplement loop limit: 2 iterations before escalation.
  - Daily queue huddle with aging alerts: identity >24h, document >48h, assessment >72h, legal >48h.

- Resource responsibilities:
  - Intake owns Register and Originals Receipt.
  - Identity reviewers own Identity Check.
  - Document reviewers own Document Check and supplement document checks.
  - Assessors own Assessment and supplement assessments.
  - Legal reviewers own Legal Review and Request Supplement decisions.
  - Supervisors monitor WIP, true overlap, and back-entry.

- Handling of legal-review and supplement loops:
  - Legal Review may Approve, Reject, or Request Supplement.
  - Request Supplement creates a new versioned Document Check and Assessment.
  - Original tasks are closed as superseded; supplement tasks carry a loop counter.
  - If loop counter exceeds 2, escalate to legal lead and pause automatic parallelization for that case.

- Logging requirements:
  - Log task creation, start, end, owner, blocker reason, and dependency satisfied.
  - Log Originals Receipt time separately from Document Check start.
  - Log supplement iteration number.
  - Flag any back-entered event.
  - Retain enough event data to compute true overlap, not only recorded overlap.

Compact POWL-style partial-order relation set:

The pilot separates mechanism failure from implementation failure by measuring both intended process structure and actual execution. The causal mechanism is true concurrency: identity and document/originals tasks must have overlapping execution intervals and both complete before Assessment. Implementation failure occurs if the system creates parallel tasks but the case lock, role separation, or manual back-entry prevents simultaneous ownership, so recorded overlap rises while true overlap stays low. The design therefore requires event-level timestamps, task-owner fields, and a fidelity metric: the share of treated cases with at least 50% overlapping verification intervals and no back-entry gap above threshold. If cycle time improves but true overlap is low, the effect is likely due to co-occurring queue management or capacity, not parallelization. If true overlap is high but cycle time does not improve, the mechanism is real but offset by downstream bottlenecks, legal loops, or capacity constraints. Stratification by digital/originals and legal/non-legal lets us test whether the structural precondition is the boundary condition. Randomization controls for case-mix drift; WIP caps and capacity monitoring control interference. A pre-specified transportability analysis compares Site B stratum effects with Site A’s eligible digital stratum, adjusting for originals delay, legal share, and capacity. This distinguishes "the idea does not work here" from "the change was not implemented as intended."

def build_site_b_powl(originals_required=True, bounded_supplement=True):
    """
    Build a POWL candidate for Site B.

    Notes:
    - POWL encodes precedence constraints, not full XOR choice.
    - The legal branch is represented as a precedence branch.
    - The supplement loop is bounded to one iteration to preserve a strict
      partial order. An unbounded loop would create a cycle and is not a
      strict partial order.
    - Data-dependent requirements, such as whether originals are legally
      required or whether legal review is required, are not fully encodable
      in a static POWL; this model is a conservative structural candidate.
    """
    powl = POWL()

    def add_node(label):
        node = POWLNode(label=label)
        try:
            powl.add_node(node)
        except Exception:
            # Some versions may accept a label directly.
            powl.add_node(label)
        return node

    def add_edge(src, dst):
        try:
            edge = POWLEdge(src, dst)
        except TypeError:
            edge = POWLEdge(source=src, target=dst)
        try:
            powl.add_edge(edge)
        except Exception:
            powl.add_edge(src, dst)

    reg = add_node('Register')
    idc = add_node('Identity Check')
    doc = add_node('Document Check')
    assess = add_node('Assessment')
    decision = add_node('Decision')  # collapsed Approve/Reject because POWL cannot encode XOR
    notify = add_node('Notify')

    # Register first.
    add_edge(reg, idc)

    if originals_required:
        orig = add_node('Originals Receipt')
        add_edge(reg, orig)
        # Statutory prerequisite: Document Check after Originals Receipt.
        add_edge(orig, doc)
    else:
        # Digital-only variant: Document Check can start after Register.
        add_edge(reg, doc)

    # Explicit partial-order edges: Assessment waits for both identity and document verification.
    add_edge(idc, assess)
    add_edge(doc, assess)

    # Main decision path. In a full process tree this would be X(Approve, Reject).
    add_edge(assess, decision)

    # Legal-review branch.
    legal = add_node('Legal Review')
    add_edge(assess, legal)
    add_edge(legal, decision)

    supp = add_node('Request Supplement')
    add_edge(legal, supp)

    if bounded_supplement:
        doc2 = add_node('Document Check (Supplement)')
        assess2 = add_node('Assessment (Supplement)')
        legal2 = add_node('Legal Review (Supplement)')
        add_edge(supp, doc2)
        add_edge(doc2, assess2)
        add_edge(assess2, legal2)
        add_edge(legal2, decision)
    else:
        # Unbounded loop would add supp -> doc, creating a cycle and violating strict partial order.
        add_edge(supp, doc)

    add_edge(decision, notify)

    return powl

powl_b = build_site_b_powl(originals_required=True, bounded_supplement=True)
net_b = to_accepting_net(powl_b, 'Site B candidate')
report_net('Site B candidate', net_b)

## 9. Recommendation

`conditional go`

Transfer the structural idea, not the Site A rollout. The transportable component is the partial-order change that allows identity verification to proceed while document verification is being prepared, provided statutory prerequisites are respected. For digital claims, Site B may start Identity Check and Document Check concurrently after Register. For originals-required claims, Site B should start Identity Check concurrently with Originals Receipt, but Document Check must remain blocked until originals are received. Do not copy Site A’s all-case simultaneous Document Check creation, its cross-trained reviewer assumption, its added FTE, API upgrade, marketing mix shift, or queue huddles as if they were part of the treatment. Those co-occurring changes likely contributed to Site A’s nine-hour median reduction and are not identified effects.

The first subgroup should be digital, non-legal, low-to-medium complexity cases where the system can support two active task owners. This stratum has the cleanest structural precondition and avoids the legal/supplement loop. If the pilot shows true overlap above 50%, waiting before Assessment reduced by at least 2 hours, p90 stable or improved, and rework/appeals stable, expand to digital legal cases. If assessment or legal queues grow, add WIP limits, capacity alerts, or legal review triage before expanding. If the legacy case lock prevents simultaneous ownership, or recorded overlap rises without true overlap, fix IT/logging before further rollout. If p90 worsens by more than 20%, rework increases by 5 percentage points, appeals increase by 2 percentage points, or any statutory ordering violation occurs, stop and redesign. The expected benefit is a modest cycle-time reduction, likely 2-5 hours for eligible cases, with the main risk being bottleneck shift and rework congestion. The decision should be driven by stratum-specific transport effects, not by Site A’s aggregate before/after difference.

## 10. Assumption register

1. Site A’s increase in overlapping verification intervals reflects true concurrent execution, not merely better timestamp recording — why needed: transport depends on the mechanism actually occurring — how to test: compare task start/end timestamps, owner fields, and system logs — consequence if false: Site A’s effect may be a measurement artifact and Site B should not expect the same benefit.
2. Site B’s statutory rule that Document Check cannot start before originals receipt is enforceable in the case system — why needed: prevents illegal parallelization — how to test: configure task dependencies and audit traces for violations — consequence if false: early document checks may be invalid, increasing rework and legal risk.
3. Digital claims, about 38% of volume, can start Document Check immediately after Register without missing required data — why needed: defines the cleanest eligible stratum — how to test: process-mine digital cases and check registration completeness — consequence if false: the digital stratum is smaller than assumed and the overall effect is diluted.
4. Identity Check can be executed while Originals Receipt is pending for originals-required cases — why needed: this is the main transportable saving for the 62% originals-required stratum — how to test: pilot true overlap and originals-delay distribution — consequence if false: originals-required cases receive little or no benefit.
5. The legacy case lock can be disabled or worked around reliably for pilot cases — why needed: simultaneous task ownership is required for true overlap — how to test: IT configuration, task-owner logs, and back-entry audit — consequence if false: recorded parallelism may occur without true concurrency.
6. Resource pools for identity, document, assessment, and legal have enough spare capacity to absorb shifted WIP — why needed: avoids bottleneck shift from verification to assessment/legal — how to test: monitor queue lengths, utilization, and p90 — consequence if false: upstream gains become downstream delays and tail performance worsens.
7. Legal-review supplement loops remain bounded and do not increase materially under earlier document checking — why needed: legal/rework loops can dominate tail behavior — how to test: track supplement count, loop duration, and rework by stratum — consequence if false: tail cycle time and rework may worsen.
8. Quality outcomes, especially rework and appeals, are not materially harmed by parallel verification — why needed: protects decision quality and stakeholder trust — how to test: compare rework and appeal rates by stratum against control — consequence if false: the intervention must be modified or abandoned.
