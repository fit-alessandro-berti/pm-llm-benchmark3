def normalize_footprints(fp):
   if fp is None: return None
   out=set()
   def add(item): out.add(repr(item))
   if isinstance(fp, dict):
      for k,v in fp.items(): out.add(repr((k,v)))
   elif isinstance(fp, (list, tuple, set, frozenset)):
      for item in fp:
         if isinstance(item, dict):
            for k,v in item.items(): out.add(repr((k,v)))
         else: add(item)
   else: add(fp)

    """
    Do not assume markings are non-null.
    """
    if m is None:
        return False
    try:
        return len(m) > 0
    except Exception:
        try:
            return any(True for _ in m)
        except Exception:
            return False


def usable_accepting_net(net, im, fm) -> bool:
    return net is not None and non_empty_marking(im) and non_empty_marking(fm)


def save_artifact(saver, *args) -> Dict[str, Any]:
    """
    Wrap visualization saving so that missing optional dependencies
    or unsupported objects are reported instead of crashing the audit.
    """
    if saver is None:
        return {"saved": False, "error": "PM4Py save function is unavailable"}
    try:
        saver(*args)
        return {"saved": True, "file": args[-1] if args else None}
    except Exception as exc:
        return {"saved": False, "error": repr(exc)}


def convert_to_bpmn_flexible(obj, im=None, fm=None):
    """
    PM4Py's BPMN conversion is documented here as accepting either
    a marked Petri net or a process tree. This helper tries supported
    call forms without inventing a direct POWL-to-BPMN API.
    """
    attempts = []
    arg_sets = []

    if im is not None and fm is not None:
        arg_sets.append(("obj, im, fm", (obj, im, fm)))

    arg_sets.append(("obj", (obj,)))
    arg_sets.append(("obj, None, None", (obj, None, None)))

    last_exc = None
    for desc, args in arg_sets:
        try:
            bpmn_obj = pm4py.convert_to_bpmn(*args)
            return bpmn_obj, desc, attempts
        except Exception as exc:
            last_exc = exc
            attempts.append({"call_form": desc, "error": repr(exc)})

    raise RuntimeError(f"BPMN conversion failed after attempts: {attempts}") from last_exc


def transition_label_report(net) -> Dict[str, Any]:
    """
    Activity-label uniqueness matters for trace-based validation.
    """
    labels = []
    try:
        for t in net.transitions:
            label = getattr(t, "label", None)
            if label is not None:
                labels.append(label)
    except Exception as exc:
        return {"error": repr(exc)}

    duplicates = sorted({label for label in labels if labels.count(label) > 1})
    return {
        "visible_labels": sorted(set(labels)),
        "duplicate_visible_labels": duplicates,
        "visible_transition_count": len(labels),
    }

# 4. Preservation and Loss Audit

The `PetriTree` column is audited for the expected outcome of this source model: process-tree conversion is expected to fail because the source contains overlapping, non-block-structured dependencies. The code in Section 3 still handles unexpected success by continuing to BPMN and validation.

Additional audit discussion:

**True concurrency versus arbitrary interleaving.**  
The POWL source is explicitly partial-order. The accepting Petri net is the strongest generated representation for preserving concurrency because independent transitions can be simultaneously enabled. BPMN can represent parallelism with parallel gateways, but many BPMN engines and visual readers interpret branches as interleaved execution paths. The round-trip validation in Section 5 compares visible interleaving traces and footprints, which is necessary but not sufficient for full partial-order equivalence.

**Lack of an edge between Optional Legal Review and verification.**  
This is one of the highest-risk semantic features. The source does not order `optional_legal` and `verification_loop`. Therefore, legal review may occur before verification, during verification, or after verification but before release. A converter that forces legal review to complete before verification starts, or that prevents legal review from occurring after verification has started, loses source behavior. The positive witnesses in Section 5 explicitly test these interleavings.

**Silent optional behavior.**  
The silent transition `skip_legal` makes legal review optional. After hiding tau, the source language contains completed traces both with and without visible `Legal Review`. A BPMN diagram may hide the silent path inside an exclusive gateway or an unnamed sequence flow. This is behaviorally acceptable only if the skip path remains executable and does not become a visible task, a mandatory manual decision, or a blocked branch.

**Binary-loop semantics.**  
The loop is not an arbitrary repeat marker. It is a binary loop with a body and a redo branch: execute `trial_body`, then either exit or execute `Correct Defect` and repeat `trial_body`. Therefore:

- At least one iteration occurs.
- `Configure Trial` precedes `Inspect Trial` in every iteration.
- `Correct Defect` appears only between iterations.
- `Correct Defect` after the final `Inspect Trial` without another iteration is invalid.

BPMN loop markers can easily under-specify this. A standard loop task may be read as “repeat the same task” rather than “repeat a structured body after a separate correction activity.”

**Join before Release Change.**  
Release must wait for both the optional legal branch and the verification loop. If legal is skipped silently, the join still receives the silent branch completion token. If legal is performed visibly, release must wait for `Legal Review`. A converter that turns the join into an inclusive or event-based gateway without validation may change blocking behavior.

**Activity-label uniqueness.**  
The source uses unique visible labels. BPMN conversion and reimport can introduce duplicate labels, split labels, or unnamed gateway tasks. Duplicate labels are especially dangerous for label-based trace comparison because two distinct nodes may become indistinguishable in the visible language.

**Initial and final markings.**  
A BPMN object can serialize successfully while its reimported Petri net has no usable initial marking, no proper final marking, or extra tokens at completion. Section 3 checks non-null markings, and Section 5 requires exact final-marking equality for completed traces.

**Gateway or routing-node ambiguity in BPMN visualization.**  
A BPMN diagram generated from a Petri net may contain gateways that are structural routing artifacts rather than source-model decisions. For example, an exclusive gateway may represent the optional legal XOR, while parallel gateways may represent token synchronization. Stakeholders may incorrectly infer business decisions, priorities, or ordering from gateway shapes and layout.

def non_empty_marking(m) -> bool:
    if m is None:
        return False
    try:
        return len(m) > 0
    except Exception:
        try:
            return any(True for _ in m)
        except Exception:
            return False


def usable_accepting_net(net, im, fm) -> bool:
    return net is not None and non_empty_marking(im) and non_empty_marking(fm)


def marking_key(m):
    """
    Hashable representation of a marking for state exploration.
    """
    try:
        return frozenset(m.items())
    except Exception:
        return frozenset()


def markings_equal(m1, m2) -> bool:
    """
    Exact final-marking equality is required for completed traces.
    """
    try:
        if m1 is m2:
            return True
    except Exception:
        pass
    return marking_key(m1) == marking_key(m2)


def fire_transition(net, marking, trans):
    """
    Minimal token-game firing.

    This is intentionally conservative and assumes ordinary Petri net
    arcs with positive integer weights. It does not invent inhibitor or
    reset arc semantics.
    """
    new_marking = Marking()
    for place, tokens in marking.items():
        new_marking[place] = tokens

    for arc in trans.in_arcs:
        place = arc.source
        weight = getattr(arc, "weight", 1)
        if new_marking.get(place, 0) < weight:
            raise ValueError("Transition is not enabled under manual firing.")
        if new_marking[place] == weight:
            del new_marking[place]
        else:
            new_marking[place] = new_marking[place] - weight

    for arc in trans.out_arcs:
        place = arc.target
        weight = getattr(arc, "weight", 1)
        new_marking[place] = new_marking.get(place, 0) + weight

    return new_marking


def safe_soundness(net, im, fm):
    try:
        return pm4py.check_soundness(net, im, fm, print_diagnostics=True), None
    except Exception as exc:
        return None, repr(exc)


def safe_footprints(net, im, fm):
    try:
        return pm4py.discover_footprints(net, im, fm), None
    except Exception as exc:
        return None, repr(exc)


def safe_reachability_state_count(net, im, fm):
    try:
        rg = pm4py.convert_to_reachability_graph(net, im, fm)
        state_count = len(getattr(rg, "states", getattr(rg, "nodes", [])))
        return state_count, None
    except Exception as exc:
        return None, repr(exc)


def normalize_footprints(fp):
    """
    Normalize footprint output to a comparable set of strings.
    PM4Py footprint representations can vary by version.
    """
    if fp is None:
        return None

    normalized = set()

    def add(item):
        normalized.add(repr(item))

    if isinstance(fp, dict):
        for k, v in fp.items():
            normalized.add(repr((k, v)))
    elif isinstance(fp, (list, tuple, set, frozenset)):
        for item in fp:
            if isinstance(item, dict):
                for k, v in item.items():
                    normalized.add(repr((k, v)))
            else:
                add(item)
    else:
        add(fp)

    return normalized

def bounded_completed_visible_traces(
    net,
    im,
    fm,
    max_visible=MAX_VISIBLE,
    max_total_firings=MAX_TOTAL_FIRINGS,
    max_silent_streak=MAX_SILENT_STREAK,
    max_silent_total=MAX_SILENT_TOTAL,
    max_loop_iterations=MAX_LOOP_ITERATIONS,
    max_states=MAX_STATES,
):
    """
    Explore completed visible traces under explicit bounds.

    - Transitions with label None are hidden.
    - A completed trace must reach the final marking exactly.
    - Silent cycling is bounded by silent streak and total silent firings.
    - Loop iteration is bounded by number of visible Configure Trial events.
    """
    completed = set()
    seen = set()
    truncated = False

    if not usable_accepting_net(net, im, fm):
        return completed, True

    stack = [
        (
            im,                # current marking
            tuple(),           # visible trace
            0,                 # total firings
            0,                 # silent streak
            0,                 # total silent firings
            {},                # visible label counts
        )
    ]

    while stack:
        if len(seen) >= max_states:
            truncated = True
            break

        marking, visible, total, silent_streak, silent_total, label_counts = stack.pop()

        if (
            total > max_total_firings
            or len(visible) > max_visible
            or silent_total > max_silent_total
        ):
            continue

        if label_counts.get("Configure Trial", 0) > max_loop_iterations:
            continue

        if label_counts.get("Correct Defect", 0) > max(0, max_loop_iterations - 1):
            continue

        state = (
            marking_key(marking),
            visible,
            total,
            silent_streak,
            silent_total,
            tuple(sorted(label_counts.items())),
        )

        if state in seen:
            continue
        seen.add(state)

        if markings_equal(marking, fm):
            completed.add(visible)
            continue

        try:
            enabled = pm4py.get_enabled_transitions(net, marking)
        except Exception:
            enabled = set()

        if enabled is None:
            enabled = set()

        for trans in enabled:
            label = getattr(trans, "label", None)

            if label is None:
                # Hide silent transitions.
                if silent_streak >= max_silent_streak:
                    continue
                if silent_total >= max_silent_total:
                    continue

                next_visible = visible
                next_silent_streak = silent_streak + 1
                next_silent_total = silent_total + 1
                next_counts = label_counts
            else:
                if len(visible) >= max_visible:
                    continue

                next_visible = visible + (label,)
                next_silent_streak = 0
                next_silent_total = silent_total
                next_counts = dict(label_counts)
                next_counts[label] = next_counts.get(label, 0) + 1

                if label == "Configure Trial" and next_counts[label] > max_loop_iterations:
                    continue

                if (
                    label == "Correct Defect"
                    and next_counts[label] > max(0, max_loop_iterations - 1)
                ):
                    continue

            try:
                next_marking = fire_transition(net, marking, trans)
            except Exception:
                continue

            stack.append(
                (
                    next_marking,
                    next_visible,
                    total + 1,
                    next_silent_streak,
                    next_silent_total,
                    next_counts,
                )
            )

    return completed, truncated


def witness_presence(completed_traces, witnesses):
    return {
        ", ".join(witness): (tuple(witness) in completed_traces)
        for witness in witnesses
    }


def witness_absence(completed_traces, witnesses):
    return {
        ", ".join(witness): (tuple(witness) not in completed_traces)
        for witness in witnesses
    }

        entry["footprint_symmetric_difference_count"] = len(footprint_diff)
        entry["footprint_difference_examples"] = sorted(list(footprint_diff))[:20]
    else:
        entry["footprint_symmetric_difference_count"] = None
        entry["footprint_difference_examples"] = []

    rg_states, rg_error = safe_reachability_state_count(net, im, fm)
    entry["reachability_states"] = rg_states
    entry["reachability_error"] = rg_error

    validation_report[name] = entry

print(json.dumps(validation_report, indent=2, default=str))

**Exhaustiveness statement.**  
The bounded exploration is exhaustive only for completed visible traces that can be produced by firing sequences satisfying all of the following bounds:

- visible length  `MAX_VISIBLE`;
- total transition firings  `MAX_TOTAL_FIRINGS`;
- consecutive silent firings  `MAX_SILENT_STREAK`;
- total silent firings  `MAX_SILENT_TOTAL`;
- at most `MAX_LOOP_ITERATIONS` visible occurrences of `Configure Trial`;
- exploration state count  `MAX_STATES`.

It is **not** exhaustive for unbounded loop iterations, unbounded silent cycles, or traces exceeding the visible-length bound. If `truncated` is `True`, the result is a partial check.

# 6. Visual-Semantics Review

A BPMN rendering can be behaviorally acceptable and still be semantically misleading.

**Parallel gateways.**  
BPMN parallel gateways may be drawn with branches stacked vertically or ordered left-to-right. Readers often infer that the top branch executes first or that the lower branch waits. In the source model, `Assess Risk` and `Prepare Evidence` are unordered, and optional legal review is unordered with verification. The visual order of gateway outgoing flows must be documented as non-semantic.

**Exclusive gateways for optional legal review.**  
The optional legal branch is an XOR between visible `Legal Review` and silent skip. In BPMN, the skip may appear as an empty sequence flow, a default flow, or an unnamed gateway path. Stakeholders may miss that the process can legally proceed without `Legal Review`. Annotate the gateway with text such as:

> “Optional legal review: automatic silent skip is allowed unless legal review is required.”

**Loop visualization.**  
A BPMN loop marker on a task or subprocess can be read as “repeat this activity” or “repeat until condition.” The source loop is more specific:

1. Execute `Configure Trial`.
2. Execute `Inspect Trial`.
3. Either exit, or execute `Correct Defect` and repeat from `Configure Trial`.

A plain loop marker does not communicate that `Correct Defect` is mandatory between iterations and forbidden after the final iteration. Add a note such as:

> “Verification loop: at least one iteration. `Correct Defect` occurs only between iterations.”

**Silent routing nodes.**  
Petri-to-BPMN conversion may create unnamed routing nodes or gateway constructs for silent transitions. These are not business activities. If they appear as tasks, they should be stereotyped as automatic or hidden. Otherwise, stakeholders may invent manual work that does not exist in the source model.

**Apparent ordering from graph layout.**  
If the BPMN diagram places legal review above the verification loop, readers may assume it must happen first. If it places legal review after the loop, readers may assume it must happen last. The source explicitly allows overlap. The diagram should include a concurrency note:

> “Legal Review and Verification are unordered except that both must complete before Release Change.”

**Recommended annotations.**

- Label AND joins with their synchronization purpose, e.g. “Wait for Assess Risk and Prepare Evidence.”
- Label the release join as “Wait for optional legal branch and verification loop.”
- Use color or dashed boundaries to show unordered regions.
- Include a small witness-trace appendix showing valid interleavings.
- Keep the source POWL diagram available alongside the BPMN diagram.
- Mark silent paths explicitly as “automatic skip” in documentation, even if BPMN does not render tau transitions visibly.

# 7. Rejection Criteria

A conversion result should be rejected or quarantined if any of the following holds:

1. **Unsound accepting net.**  
   `pm4py.check_soundness(...)` returns false, raises an unrecoverable error, or diagnostics show deadlock, improper completion, or residual tokens at termination.

2. **Missing or empty initial/final marking.**  
   Any conversion step returns `None` for the net, initial marking, or final marking, or returns an empty marking where a non-empty accepting marking is required.

3. **Loss of required positive behavior.**  
   A positive witness trace from the source semantics is absent in the round-tripped net within the validation bound. Examples include:
   - legal review occurring during verification;
   - `Prepare Evidence` before `Assess Risk`;
   - two verification iterations separated by `Correct Defect`.

4. **Admission of forbidden behavior.**  
   A negative witness trace becomes completable to the final marking. Critical examples include:
   - `Release Change` before `Inspect Trial`;
   - `Release Change` before visible `Legal Review` when legal review was chosen;
   - `Correct Defect` after final inspection without another iteration;
   - verification starting before both `Assess Risk` and `Prepare Evidence`.

5. **Collapse of optional legal behavior.**  
   The silent skip is lost, making `Legal Review` mandatory, or the silent skip becomes a visible activity, changing the visible language.

6. **Concurrency collapse.**  
   The converter introduces an ordering between optional legal review and verification, or between `Assess Risk` and `Prepare Evidence`, that is not present in the source POWL.

7. **Process-tree route fails or changes semantics.**  
   If the process-tree conversion raises an exception, the tree route must not be used as canonical. If it succeeds but validation shows missing or extra traces, it must be rejected even if the BPMN diagram looks cleaner.

8. **Label ambiguity or duplicate visible labels.**  
   BPMN round-trip introduces duplicate activity labels, unnamed visible tasks, or relabeling that prevents reliable mapping back to source activities.

9. **Exact final-marking failure.**  
   A visible trace reaches a marking that looks terminal but is not exactly the declared final marking, or leaves extra tokens in routing places.

10. **Unbounded silent cycling.**  
   The round-tripped net permits silent cycles that prevent bounded validation from being meaningful, or that indicate tau-explosion from gateway conversion.

# 8. Canonical Representation Recommendation

**Authoritative canonical representation for storage: source POWL.**

The POWL model should be the authoritative stored representation because it directly encodes the intended semantic invariants:

- partial order between activities;
- absence of order between legal review and verification;
- explicit silent optional branch;
- explicit binary loop with body and redo branch;
- synchronization before release.

BPMN should be treated as a **stakeholder visualization derivative**, not as the editable source of truth.

**Derivative artifacts.**

The following artifacts are derivative:

1. `net_from_powl`, `im_from_powl`, `fm_from_powl`  
   Use this accepting Petri net as the executable/validation canonical when a tool cannot store POWL directly. It should be regenerated from the POWL, not edited manually.

2. `bpmn_from_net`  
   Use this BPMN model for stakeholder communication. It must be regenerated from the Petri net or POWL pipeline and accompanied by validation evidence.

3. `tree_from_net` and `bpmn_from_tree`  
   These should be optional exploratory artifacts only. Because the source behavior is not cleanly block-structured, the process-tree route should not be allowed as a canonical intermediate unless it succeeds and passes the same validation suite as the primary pipeline.

4. Round-tripped Petri nets from BPMN  
   These are validation artifacts, not authoritative models. They are used to detect semantic loss during BPMN export/import.

**Validation evidence required for each derivative.**

Each generated BPMN or Petri net derivative should be stored with:

- PM4Py version and conversion command;
- hash or identifier of the source POWL;
- workflow-net check result;
- soundness check result;
- label inventory and duplicate-label report;
- positive/negative witness results;
- bounded trace comparison report;
- footprint comparison summary;
- known truncation bounds if trace exploration was bounded;
- visual annotations explaining unordered regions and silent paths.

**Should a process-tree intermediate be allowed?**

Not by default.

The process-tree intermediate is attractive because it may produce cleaner BPMN, but it imposes block-structured nesting. The source model contains overlapping dependencies that are likely not block-structured. Therefore:

- allow process-tree conversion only as an optional audit path;
- if it raises an exception, record the failure as semantically meaningful;
- if it succeeds, require full round-trip validation before using its BPMN output;
- never prefer a process-tree derivative over the primary POWLPetriBPMN derivative unless validation proves it is at least as faithful.

**Avoiding round-trip drift.**

Future edits should follow this rule:

> Edit the POWL. Regenerate the Petri net. Regenerate the BPMN. Re-run validation.

Do not edit BPMN and reimport it as the new source. If BPMN annotations are needed for stakeholders, store them as separate documentation or diagram overlays, not as structural changes to the canonical process model.

# 9. Residual Uncertainty

Even if every test in Sections 3 and 5 passes, the following claims remain unproven:

1. **Unbounded loop equivalence is not proven.**  
   The bounded trace exploration checks only up to the configured number of visible events and loop iterations. It cannot prove that the converted BPMN round-trip preserves the source behavior for arbitrarily many verification iterations.

2. **Full partial-order concurrency equivalence is not proven.**  
   Visible-trace comparison and footprint checks can detect many ordering losses, but they do not fully establish true concurrency equivalence. Two models can have the same visible interleavings while differing in subtle branching, synchronization, or partial-order structure.

3. **BPMN human interpretation is not validated.**  
   A BPMN diagram can be behaviorally sound and still be misread because of layout, gateway shapes, silent paths, or loop markers. Automated validation does not prove that stakeholders will interpret the diagram according to the source semantics.

4. **Converter implementation assumptions may change.**  
   The audit assumes current PM4Py conversion semantics. Future PM4Py versions could change POWL-to-Petri, Petri-to-BPMN, BPMN-to-Petri, or process-tree reduction behavior. Validation must be rerun after any tool upgrade.

5. **Label-based validation may hide identity ambiguity.**  
   If duplicate labels are introduced, visible trace comparison may still pass while distinct source activities or routing nodes have been conflated. Label inventory helps, but it does not fully prove identity preservation.
