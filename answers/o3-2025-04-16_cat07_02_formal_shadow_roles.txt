# 5. PM4Py role-discovery and similarity code  

```python
import pandas as pd
import pm4py

# 1. Load and format
df = pd.read_csv("order2resolution_10weeks.csv", parse_dates=['time:timestamp'])
df = pm4py.format_dataframe(df,
                            case_id='case:concept:name',
                            activity_key='concept:name',
                            timestamp_key='time:timestamp',
                            resource_key='org:resource')

# 2. Discover activity-based similarity (frequency only – first approximation)
sim_matrix = pm4py.discover_activity_based_resource_similarity(df,
                               resource_key='org:resource',
                               activity_key='concept:name',
                               measure='cosine')

# 3. Simple role clustering (will be refined)
roles_freq = pm4py.discover_organizational_roles(df,
                               resource_key='org:resource',
                               activity_key='concept:name',
                               algorithm='agm',   # aggregated activity graph
                               similarity_threshold=0.7)

# 4. Overlay hand-over networks to find bridging roles
handover = pm4py.discover_handover_of_work_network(df,
                               case_id_key='case:concept:name',
                               resource_key='org:resource',
                               activity_key='concept:name')

working_together = pm4py.discover_working_together_network(df,
                               case_id_key='case:concept:name',
                               resource_key='org:resource')

# 5. Add case complexity & substitution info
complexity = df.groupby('org:resource')['case_complexity'].median()
roles_enriched = (roles_freq
                  .merge(complexity, left_on='resource', right_index=True)
                  .merge(df[['org:resource','temporary_substitution']].groupby('org:resource')
                         .max(), on='org:resource'))

# 6. Prevent over-interpretation
# Flag resources that (a) appear in >3 distinct clusters depending on the algorithm
# or (b) have high betweenness in hand-over network

import networkx as nx
G = nx.from_pandas_edgelist(handover, 'source', 'target', ['count'])
betweenness = nx.betweenness_centrality(G, normalized=True)
roles_enriched['handover_betw'] = roles_enriched['org:resource'].map(betweenness)

# 7. Analyst manually reviews resources with high betweenness or high substitution flag
ambiguous = roles_enriched[(roles_enriched.handover_betw > 0.15) |
                           (roles_enriched.temporary_substitution)]
print("Resources needing manual review:", ambiguous.org_resource.tolist())
```

Key points in the code  
• We run similarity first but treat it as “baseline signal”.  
• We enrich with complexity and substitution flags because frequency alone hides seniority and authority.  
• Betweenness in hand-over network highlights Matteo, Giorgio, Erik – typical bridging or shadow roles.  
• Final role assignment therefore mixes algorithmic hints with domain judgement, preventing over-fitting.

3. Risk control  
   • Quality gate keeps catching entitlement omissions from temp agents – improve their checklist, otherwise temp surge erodes NPS through reopens.  
   • Security reviews delayed in weeks 7–8 show need for an on-call back-up or documented triage rules.

4. Resilience & substitution planning  
   • Map which roles can legitimately substitute others and document authority thresholds (pricing, security, approvals).  
   • Use PM4Py monitoring to trigger alerts when a shadow role’s share of a critical activity exceeds a safe threshold (e.g., Giorgio doing >25 % of A7 in a week).

Cautions  
a) Mined roles are descriptive, not prescriptive. Forcing staff into the discovered clusters could freeze healthy flexibility.  
b) Activity frequency does not equate to competence or authority – especially for bots, temps, and shadow actors. Always confirm with HR records and compliance policies before reorganising.
