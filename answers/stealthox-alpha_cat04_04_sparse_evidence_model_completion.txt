**Why bidirectional DFG edges do not prove concurrency.** The DFG shows CCER (17) and ERCC (11). Three mechanisms generate exactly this pattern: (i) genuine concurrency observed through completion timestamps (S2); (ii) a case-level routing choice — an XOR of two strict sequences, e.g., some order types check credit first; (iii) arbitrary tie-breaking of near-simultaneous completions by ingestion index (S7). When each activity occurs once, all three produce *identical* directly-follows counts and *identical complete-trace languages*. A DFG is a frequency projection over complete traces and carries no start/overlap information. Bidirectionality therefore falsifies "one globally mandatory sequence" (S1) but does not distinguish concurrency from routing-XOR; D7 concedes precisely this. (I also verified every DFG weight is exactly reproducible from the variant counts — the DFG adds no information beyond the variants.)

# 2. Shared Assumptions

1. **Completion semantics (S7).** Every event is a *completion*. A trace is one linear extension of the true (possibly concurrent) execution; same-timestamp ties are broken by ingestion index and may misrepresent causal order. All three models therefore assert constraints over completion orders only, never over starts.
2. **Observational equivalence.** For once-per-case activities, "XOR of the two serializations" and "concurrency" yield identical complete-trace languages. The candidates differ in the *claim* they encode, not necessarily in trace-level fit.
3. **Single occurrence, no loops.** Every activity occurs 1 time per case (30/30 observed). All three models forbid repetition; rework, if any, is invisible in this log and out of scope.
4. **Missing SC vs. true skip (disclosed abstraction).** SC optionality is encoded as the control-flow alternative XOR(SC, ). This deliberately *conflates* legitimate skip for stocked components (S4) with integration loss (S5), because the external/stocked attribute is absent from the log and conditioning is impossible. This is a representation of missingness/optionality, not a mechanism claim.
5. **Optionality encoding.** Silent transition `tau` inside an XOR (ProcessTree) or `SilentTransition` inside an XOR block (POWL).
6. **Boundaries.** RO is the unique start and AR the unique end (D1); AC  RP  AR is a strict tail (D2 + 30/30). Enforced in all three models.
7. **Expedite Review.** Optional, at most once, only after both CC and ER complete, before AC (D6/S6). Enforced in *all three* models; permissiveness is spent on SC placement and interleaving, not on XR.
8. **Stakeholder statements are priors, not constraints.** S1 is treated as falsified as a universal rule (11 counterexamples) but kept as a case-type hypothesis.
9. **Judgement basis.** Candidates are compared on complete-trace languages plus structural interpretability; partial-trace enabling behavior is discussed only where it differs (concurrency vs. XOR-of-sequences).

# 3. Conservative Candidate

**Inductive bias.** The conservative model assumes the observed variant set *is* the process: every observed completion order becomes a hard alternative and nothing else is reachable. Its bias is maximal specificity with zero smoothing — precision on the observed support is protected at the cost of all recall on future legitimate variation. It treats n=1 variants (V6, V7) as exactly as legitimate as the dominant path, makes no commitments about causality, concurrency, or missingness, and uses duplicate labels across branches rather than inventing shared structure the data cannot confirm.

**Formal expression.**

`RO · ( CC·ER·(  SC  SC·XR)  ER·CC·(  SC  XR·SC)  CC·SC·ER ) · AC · RP · AR`

**Code (ProcessTree — this is the required ProcessTree candidate).**

```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

RO, CC, ER, SC, XR = ("Register Order", "Credit Check", "Engineering Review",
                      "Supplier Confirmation", "Expedite Review")
AC, RP, AR = "Approve Configuration", "Release Production", "Archive Case"

def _leaf(label): return ProcessTree(operator=None, label=label)
def _tau():       return ProcessTree(operator=None, label=None)
def _node(op, children):
    t = ProcessTree(operator=op)
    for c in children:
        c.parent = t; t.children.append(c)
    return t

branch_cc_first = _node(Operator.SEQUENCE, [
    _leaf(CC), _leaf(ER),
    _node(Operator.XOR, [_tau(), _leaf(SC), _node(Operator.SEQUENCE, [_leaf(SC), _leaf(XR)])]),
])
branch_er_first = _node(Operator.SEQUENCE, [
    _leaf(ER), _leaf(CC),
    _node(Operator.XOR, [_tau(), _leaf(SC), _node(Operator.SEQUENCE, [_leaf(XR), _leaf(SC)])]),
])
branch_sc_between = _node(Operator.SEQUENCE, [_leaf(CC), _leaf(SC), _leaf(ER)])

model_conservative = _node(Operator.SEQUENCE, [
    _leaf(RO),
    _node(Operator.XOR, [branch_cc_first, branch_er_first, branch_sc_between]),
    _leaf(AC), _leaf(RP), _leaf(AR),
])
```

*On XOR enumeration, duplicate labels, scalability:* this compact tree admits **exactly** the 7 observed variants. A naive XOR over the 7 full sequences would need 7×8 = 56 labeled transitions vs. 17 labeled leaves (+3 ) here; in general enumeration scales O(variants × length) and becomes unusable for real logs with thousands of variants. Duplicate labels ("Supplier Confirmation" ×5, "Credit Check" ×3, …) are structurally fine in PM4Py and do not affect alignment fitness, but they split per-transition statistics (hurting generalization-style metrics), complicate diagnostics about *which copy* fired, and can interact badly with label-unique simplification heuristics.

**Deliberately excluded behavior.**
- Any reordering outside the 7 variants: e.g., CC,ER,XR,SC; ER,SC,CC; SC before CC; SC before both checks.
- XR without SC; XR before either check; a second XR.
- Skipping CC or ER; SC after AC; RP before AC; any repetition; anything before RO or after AR.

**Known underfitting risks.**
1. S5 data loss: an SC event dropped from a V6-type case yields CC,ER,XR — rejected although the case was conformant (the degraded trace matches no variant).
2. Any legitimate new variant (new XR position, SC skip for a new product line, a new interleaving) produces a false non-conformance alarm.
3. Cannot express attribute-dependence (external vs. stocked): the skip is a free choice, not a conditioned one.
4. Zero tolerance turns every data-quality glitch into a compliance flag (alarm fatigue).

# 4. Balanced Candidate

**Inductive bias.** The balanced model assumes ordering freedom exactly where the data shows instability (CC/ER), stability where the data is unanimous (CC before SC; ACRPAR), explicit optionality where absence is observed but the mechanism is unknown (SC, XR), and *no constraint* where the evidence is silent (SC vs. ER, SC vs. XR). Rules with medium confidence (D1–D4, D6) are hard constraints; low-confidence aspects (D5's exact anchor, D7) are left unordered. It uses the smallest set of asymmetric, falsifiable edges that fit all 30 traces.

**Formal expression.** `L = { RO · w · AC · RP · AR : w  Lin(P) }` over tasks {CC, ER, SC?, XR?} with SC?  {SC, }, XR?  {XR, }, and precedence `CC  SC?`, `CC  XR?`, `ER  XR?`; all other pairs unordered (CC  ER, ER  SC?, SC?  XR?).

**How sequence / concurrency / partial order were decided.**

| Pair | Decision | Deciding evidence | Rejected alternative and why |
|---|---|---|---|
| CC–ER | **Concurrency** (no edge) | Both serializations frequent (17/11); S2; S1 contradicted by 11 traces; D7 forbids a sharper claim | Strict sequence (S1) is falsified; XOR of two sequences is trace-equivalent but encodes an untestable routing claim |
| CC–SC | **Sequence** CC  SC | 23/23 SC traces have CC before SC; D5 needs *some* anchor | "SC after both" underfits V5; "SC anywhere" admits SC-first, contradicting D5 |
| ER–SC | **Partial order: no edge** (unordered) | V5 shows SC completing between the checks | Edge ER  SC would exclude V5 |
| SC–XR | **Unordered** | V6 and V7 show both orders | Any fixed sequence excludes one variant |
| {CC,ER}–XR | **Sequence**: both  XR | D6/S6 (medium), 2/2 support | XR before a check contradicts S6 and is unobserved |
| SC, XR presence | **XOR with ** | V3/V4 (no SC, 7 traces); XR in 2/30 | Mandatory SC contradicted by V3/V4 *or* explained by S5 loss (disclosed abstraction) |

**Code (POWL — this is the required POWL candidate).**

```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

RO, CC, ER, SC, XR = ("Register Order", "Credit Check", "Engineering Review",
                      "Supplier Confirmation", "Expedite Review")
AC, RP, AR = "Approve Configuration", "Release Production", "Archive Case"

def _opt(label):  # optionality as control-flow alternative (disclosed abstraction)
    return OperatorPOWL(Operator.XOR, [Transition(label=label), SilentTransition()])

ro, cc, er = Transition(label=RO), Transition(label=CC), Transition(label=ER)
sc_opt, xr_opt = _opt(SC), _opt(XR)
ac, rp, ar = Transition(label=AC), Transition(label=RP), Transition(label=AR)

model_balanced = StrictPartialOrder(nodes=[ro, cc, er, sc_opt, xr_opt, ac, rp, ar])
for a, b in [(ro, cc), (ro, er),
             (cc, sc_opt), (cc, xr_opt), (er, xr_opt),      # SC anchored to CC only; XR after both
             (cc, ac), (er, ac), (sc_opt, ac), (xr_opt, ac),# D3 + D4
             (ac, rp), (rp, ar)]:                            # D2 + D1
    model_balanced.order.add_edge(a, b)
```

**Deliberately excluded behavior.**
- SC completing before CC (RO,SC,…; ER,SC,CC,…).
- XR before CC or ER completes; a second XR.
- AC before both checks; RP before AC; activity after AR; repetitions.

**Known underfitting risks.**
1. If D5's "either" includes ER-only anchoring (SC legitimately before CC in some flow), balanced raises false alarms on ER,SC,CC traces.
2. If XR can precede the checks in urgent cases (S6 wrong), such traces are rejected.
3. If SC is mandatory for external cases (S3), the  branch over-admits skips there (attribute blindness — a precision, not fitness, problem).
4. As a completion-order model it cannot represent start-time concurrency claims (D7) — an interpretive limitation, not a fitness one.

# 5. Permissive Candidate

**Inductive bias.** The permissive model assumes only *milestone* constraints: the four "checking" activities (CC, ER, SC, XR) may interleave arbitrarily subject to RO first, XR after both checks, and everything before AC, followed by the fixed tail ACRPAR. It treats D5 as untestable under completion-only semantics (S7) and therefore refuses to anchor SC to any check; any interleaving is epistemically admissible. Its bias is maximal recall inside the milestone envelope: ordering violations are the only alarms.

**Formal expression.** `L = { RO · w · AC · RP · AR : w  Lin(P) }` over {CC, ER, SC?, XR?} with only `CC  XR?` and `ER  XR?`; CC, ER, SC? are pairwise unordered (CC  ER  SC?), and SC?  XR?.

**Code (POWL).**

```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

RO, CC, ER, SC, XR = ("Register Order", "Credit Check", "Engineering Review",
                      "Supplier Confirmation", "Expedite Review")
AC, RP, AR = "Approve Configuration", "Release Production", "Archive Case"

def _opt(label):
    return OperatorPOWL(Operator.XOR, [Transition(label=label), SilentTransition()])

ro, cc, er = Transition(label=RO), Transition(label=CC), Transition(label=ER)
sc_opt, xr_opt = _opt(SC), _opt(XR)
ac, rp, ar = Transition(label=AC), Transition(label=RP), Transition(label=AR)

model_permissive = StrictPartialOrder(nodes=[ro, cc, er, sc_opt, xr_opt, ac, rp, ar])
for a, b in [(ro, cc), (ro, er), (ro, sc_opt),        # RO first; SC fully concurrent with checks
             (cc, xr_opt), (er, xr_opt),              # D6 kept even here
             (cc, ac), (er, ac), (sc_opt, ac), (xr_opt, ac),
             (ac, rp), (rp, ar)]:
    model_permissive.order.add_edge(a, b)
```

**Boundary: reasonable generalization vs. forbidden.** *Admitted (reasonable generalization):* any interleaving or omission inside the milestone envelope that no observed trace contradicts and no medium rule forbids — including SC-first traces, which are **disclosed as an abstraction artifact**: D5 constrains when SC may *start*, but with completion-only data (S7) start-order constraints are unencodable, so the permissive model deliberately refuses to pretend otherwise. *Remains forbidden:* anything before RO or after AR; RP before AC (D2); AC before CC or ER completes (D3); SC after AC (D4); XR before both checks, or twice (D6/S6); any repetition.

**Deliberately excluded behavior.** As in the boundary list: pre-RO/post-AR activity, D2/D3/D4/D6 violations, repetitions.

**Known underfitting risks.**
1. It cannot detect drift that manifests as *new orderings* — precision is low enough that alarms are near-meaningless (the mirror image of the conservative model's problem).
2. If compliance requires "SC only after a check", permissive silently admits D5-violations.
3. If SC-first traces are actually ingestion-order artifacts (S7 tie-breaking), permissive admits corrupted traces as conformant.
4. It cannot express attribute-conditional structure (external vs. stocked) without case stratification.

# 7. Comparative Model Matrix

# 8. Validation Code

```python
# =====================================================================
# Self-contained validation for the three candidates.
# Requires pm4py >= 2.7. Limitations:
#  * All three languages are FINITE (loop-free, each activity <= once),
#    so the DFS below is an EXHAUSTIVE language enumeration here.
#    For models with loops this would only be a bounded approximation.
#  * Sampled playout is a sanity check only; it NEVER proves language
#    inclusion. Membership of single traces is decided by zero-cost
#    alignments (valid because the nets are sound).
#  * Exact metric values can vary slightly across pm4py versions.
# =====================================================================
import pm4py
from pm4py.objects.process_tree.obj import ProcessTree, Operator
from pm4py.objects.powl.obj import (StrictPartialOrder, OperatorPOWL,
                                    Transition, SilentTransition)

# ---------- 1. Reconstruct the 30-case log ----------
VARIANT_COUNTS = {
    "Register Order,Credit Check,Engineering Review,Supplier Confirmation,Approve Configuration,Release Production,Archive Case": 12,
    "Register Order,Engineering Review,Credit Check,Supplier Confirmation,Approve Configuration,Release Production,Archive Case": 7,
    "Register Order,Credit Check,Engineering Review,Approve Configuration,Release Production,Archive Case": 4,
    "Register Order,Engineering Review,Credit Check,Approve Configuration,Release Production,Archive Case": 3,
    "Register Order,Credit Check,Supplier Confirmation,Engineering Review,Approve Configuration,Release Production,Archive Case": 2,
    "Register Order,Credit Check,Engineering Review,Supplier Confirmation,Expedite Review,Approve Configuration,Release Production,Archive Case": 1,
    "Register Order,Engineering Review,Credit Check,Expedite Review,Supplier Confirmation,Approve Configuration,Release Production,Archive Case": 1,
}
trace_strings = [v for v, n in VARIANT_COUNTS.items() for _ in range(n)]
try:
    log = pm4py.parse_event_log_string(trace_strings)
except Exception:
    log = pm4py.parse_event_log_string("\n".join(trace_strings))
assert len(log) == 30, f"expected 30 traces, got {len(log)}"

# ---------- 2. Candidate models (same builders as Sections 3-5) ----------
RO, CC, ER, SC, XR = ("Register Order", "Credit Check", "Engineering Review",
                      "Supplier Confirmation", "Expedite Review")
AC, RP, AR = "Approve Configuration", "Release Production", "Archive Case"

def _leaf(l): return ProcessTree(operator=None, label=l)
def _tau():   return ProcessTree(operator=None, label=None)
def _node(op, ch):
    t = ProcessTree(operator=op)
    for c in ch: c.parent = t; t.children.append(c)
    return t

def make_conservative():
    b1 = _node(Operator.SEQUENCE, [_leaf(CC), _leaf(ER),
        _node(Operator.XOR, [_tau(), _leaf(SC), _node(Operator.SEQUENCE, [_leaf(SC), _leaf(XR)])])])
    b2 = _node(Operator.SEQUENCE, [_leaf(ER), _leaf(CC),
        _node(Operator.XOR, [_tau(), _leaf(SC), _node(Operator.SEQUENCE, [_leaf(XR), _leaf(SC)])])])
    b3 = _node(Operator.SEQUENCE, [_leaf(CC), _leaf(SC), _leaf(ER)])
    return _node(Operator.SEQUENCE, [_leaf(RO), _node(Operator.XOR, [b1, b2, b3]),
                                     _leaf(AC), _leaf(RP), _leaf(AR)])

def _opt(label):
    return OperatorPOWL(Operator.XOR, [Transition(label=label), SilentTransition()])

def _base_nodes():
    return (Transition(label=RO), Transition(label=CC), Transition(label=ER),
            _opt(SC), _opt(XR),
            Transition(label=AC), Transition(label=RP), Transition(label=AR))

def make_balanced():
    ro, cc, er, sc_opt, xr_opt, ac, rp, ar = _base_nodes()
    po = StrictPartialOrder(nodes=[ro, cc, er, sc_opt, xr_opt, ac, rp, ar])
    for a, b in [(ro, cc), (ro, er), (cc, sc_opt), (cc, xr_opt), (er, xr_opt),
                 (cc, ac), (er, ac), (sc_opt, ac), (xr_opt, ac), (ac, rp), (rp, ar)]:
        po.order.add_edge(a, b)
    return po

def make_permissive():
    ro, cc, er, sc_opt, xr_opt, ac, rp, ar = _base_nodes()
    po = StrictPartialOrder(nodes=[ro, cc, er, sc_opt, xr_opt, ac, rp, ar])
    for a, b in [(ro, cc), (ro, er), (ro, sc_opt), (cc, xr_opt), (er, xr_opt),
                 (cc, ac), (er, ac), (sc_opt, ac), (xr_opt, ac), (ac, rp), (rp, ar)]:
        po.order.add_edge(a, b)
    return po

model_conservative = make_conservative()
model_balanced     = make_balanced()
model_permissive   = make_permissive()
CANDIDATES = {"conservative": model_conservative,
              "balanced": model_balanced,
              "permissive": model_permissive}

# ---------- 3. Convert to accepting Petri nets + soundness ----------
nets = {}
for name, m in CANDIDATES.items():
    net, im, fm = pm4py.convert_to_petri_net(m)
    nets[name] = (net, im, fm)
    try:
        res = pm4py.check_soundness(net, im, fm)
        is_sound = res[0] if isinstance(res, tuple) else res
        print(f"[soundness] {name}: sound={is_sound}")
    except Exception as exc:
        print(f"[soundness] {name}: checker unavailable/failed ({exc}); "
              f"process trees and acyclic POWL partial orders are sound by construction.")

# ---------- 4. Fitness / precision / generalization / simplicity ----------
for name, (net, im, fm) in nets.items():
    row = {"model": name}
    for metric, fn in [
        ("fitness",       lambda: pm4py.fitness_alignments(log, net, im, fm)),
        ("precision",     lambda: pm4py.precision_alignments(log, net, im, fm)),
        ("generalization",lambda: pm4py.generalization_tbr(log, net, im, fm)),
        ("simplicity",    lambda: pm4py.simplicity_petri_net(net, im, fm)),
    ]:
        try:
            v = fn()
            if isinstance(v, dict):
                v = v.get("log_fitness", v.get("averageFitness", v))
            row[metric] = round(float(v), 3)
        except Exception as exc:
            row[metric] = f"n/a ({exc})"
    print("[metrics]", row)
# Expected pattern: fitness 1.0 for all three; precision conservative ~1.0,
# balanced < permissive; generalization conservative lowest.

# ---------- 5. Exhaustive language enumeration (finite languages) ----------
def enumerate_language(net, im, fm, max_firings=40):
    """DFS over the reachability graph. Exhaustive HERE because the models are
    loop-free and fire each activity at most once. NOT exhaustive for looper models."""
    def norm(m): return tuple(sorted((p, c) for p, c in m.items() if c > 0))
    target, out = norm(fm), set()

    def dfs(m, trace, depth):
        if depth > max_firings: return
        if norm(m) == target: out.add(tuple(trace))
        for t in net.transitions:
            if all(m.get(a.source, 0) >= a.weight for a in t.in_arcs):
                m2 = dict(m)
                for a in t.in_arcs:  m2[a.source] = m2.get(a.source, 0) - a.weight
                for a in t.out_arcs: m2[a.target] = m2.get(a.target, 0) + a.weight
                dfs(m2, trace + ([t.label] if t.label is not None else []), depth + 1)

    dfs(dict(im), [], 0)
    return out
```

# 9. Recommendation and Data-Collection Plan

**Immediate use: `model_balanced`.** It fits all 30 cases at zero cost, encodes every medium-confidence rule, generalizes only along locally evidenced directions (|L| = 12), and every edge is falsifiable and traceable to evidence — suitable for operational conformance checking and KPI computation now.

**Sensitivity analysis: `model_conservative`.** Run it in parallel on live cases as a zero-generalization baseline: the rate at which new, *legitimately caused* cases fall outside the 7-variant set directly measures the balanced model's underfitting risk and tells us which extra branch to add next. (`model_permissive` is reserved for exploration only; its alarm output is not actionable.)

**Data-collection plan (prioritized).**
1. **Case attributes at Register Order:** `component_mix` (external / stocked / mixed), `order_type`, `expedite_flag`. This resolves S3/S4/S5 and turns XOR(SC, ) into an attribute-conditioned choice.
2. **Full lifecycle timestamps** (schedule/start/complete, not just completion) for CC, ER, SC, XR. This is the *only* way to resolve D7/S1-vs-S2: overlapping execution intervals  concurrency; disjoint intervals with order correlated to `order_type`  routing XOR.
3. **SC reconciliation:** for a sample of ~100 closed cases, compare procurement-system confirmation records against log events to measure the true missing-event rate (tests S5's 5–10% claim; 7/30 = 23% no-SC already suggests most are true skips).
4. **XR metadata:** trigger reason, requester, whether SC was pending (tests an XR–SC dependency hypothesis).
5. **Maximally informative future traces:**
   - an *external-component* case with no SC in the log  distinguishes true skip vs. missing event vs. attribute error (optionality hypothesis);
   - any case where SC completes **before CC**  falsifies the balanced model's CC  SC anchor and sharpens D5 (sequence-anchor hypothesis);
   - cases with **overlapping CC/ER execution intervals**, and same-`order_type` cases exhibiting both serializations  distinguishes concurrency from routing-XOR (XOR-vs-concurrency hypothesis);
   - an XR case **without SC**, and any case where XR precedes a check  tests XR's precondition and independence (optionality/precedence hypothesis);
   - any case with **two XR events** or AC before a check  falsifies D6/D3.

# 10. Uncertainty Statement

| Modeling decision | Confidence | Basis |
|---|---|---|
| Enforce D1 (RO start, AR end) in all models | 0.98 | D1 + 30/30 |
| Enforce AC  RP  AR | 0.98 | D2 + 30/30 |
| Enforce AC after both CC and ER | 0.90 | 30/30 + D3 |
| SC genuinely optional for some cases | 0.75 | 7/30 no-SC exceeds S5's 5–10% loss bound; S4 plausible |
| XR optional, 1, after both checks | 0.80 | D6/S6 medium; only n=2 observations |
| CC, ER unordered (concurrency claim) | 0.55 | Underdetermined (D7); trace-equivalent to routing-XOR, so low stakes for complete-trace fit, high stakes for interpretation |
| CC  SC anchor (balanced) | 0.60 | 23/23 support, mechanism unverified; the alternative "after both" costs V5 |
| Conservative model = the true process | 0.30 | Brittle to S5 loss and to any future legitimate variant |
| Balanced as best default | 0.65 | Fits all data; modest, falsifiable structure |

**Plausible alternative interpretations that would materially change the recommendation:**
1. **Attribute-guarded SC (S3+S4 both true).** If the collected `component_mix` shows every no-SC case is stocked, SC optionality is attribute-dependent: the balanced  branch then over-admits skips in the external segment, and the right model is a stratified/guarded variant, not a free XOR.
2. **S1 vindicated at case-type level.** If start-timestamps show strictly sequential checks *within* cases and the ER-first traces belong to a distinct order type, the balanced concurrency claim becomes misleading (though complete-trace fit is unchanged) and should be replaced by an attribute-keyed XOR of sequences.
3. **Much higher SC missingness.** If reconciliation shows ~25% event loss (far above S5's claim), variants V3–V5 counts are unreliable, the conservative model collapses entirely, and even the balanced CC  SC anchor needs re-estimation.
4. **XR–SC dependency.** If XR is always a reaction to supplier failure, XR-without-SC (admitted by balanced and permissive) is impossible in reality; a dependency constraint should be added, shifting precision assessments upward for a *tighter* balanced variant.

Under interpretation 1 or 3 the recommendation would move from "balanced as-is" to "balanced with attribute guards / re-estimated edges"; under no plausible interpretation does the conservative exact-enumeration model become the recommended operational model, because its correctness depends on the log containing zero data loss — which S5 explicitly denies.
