The shared mechanism is an AND-join: Assessment cannot start until identity and document verification are complete. Where both checks are executable and sufficiently independent, parallelization can replace the sum of their elapsed paths with approximately their maximum, reducing synchronization delay and pre-Assessment waiting. That mechanism could operate at both sites.

Its prevalence and magnitude are site-specific. At B, originals block document execution for 62% of cases, legal review adds a scarce downstream stage and supplement loop, specialized pools limit dynamic balancing, and the case lock can prevent true simultaneous ownership. At A, an API upgrade, added document capacity, queue huddles, easier case mix, and improved event recording accompanied treatment. These mechanisms therefore cannot be attributed to parallelization or transported automatically.

Key effect modifiers are digital availability, originals requirements, complexity, role specialization, lock behavior, capacities at all downstream pools, legal-review eligibility, and rework propensity. Queue huddles and API latency may be co-interventions or mediators depending on what is transferred.

A similar control-flow diagram establishes only logical permission and precedence. It does not establish that tasks have independent inputs, can be executed under the software lock, receive timely capacity, or avoid creating queues at Assessment and Legal Review. Nor does it encode durations, statutory case attributes, resource contention, loops, or timestamp validity. Transportability therefore depends on matching operative causal mechanisms and modifier distributions, not diagram shape alone.

## 6. Candidate Site B intervention

**Modified intervention: readiness-aware parallel verification with pull control**

- **Eligibility rules**
  - Wave 1: no-original, non-mandatory-legal cases, separately randomized within low/high complexity.
  - Wave 2, if safe: originals-required cases may receive early Identity Check while awaiting originals; Document Check remains dormant.
  - Mandatory-legal cases enter only after legal queue and supplement safeguards pass.
- **Concurrent creation/execution**
  - After Register, create Identity Check and an `Originals Receipt/Document Readiness` item concurrently.
  - Create an executable Document Check immediately only when digital evidence is legally sufficient.
  - Otherwise create a non-owning readiness marker; activate Document Check only after Originals Receipt.
  - Identity and activated Document Check may execute concurrently in separate lock-safe work items.
- **Mandatory prerequisites**
  - Registration precedes all verification.
  - Required originals precede executable Document Check.
  - Both checks precede Assessment.
  - Mandatory Legal Review follows Assessment and precedes final decision.
  - Notify follows Approve or Reject.
- **Queue/WIP controls**
  - Pool caps, initially: identity 16 open tasks, document 28, assessment 12, legal 8; revise using observed utilization.
  - Pull release when downstream aged-WIP thresholds are exceeded.
  - Daily huddles review aged work but are logged as a distinct component.
- **Responsibilities**
  - Specialized pools retain accountability; no reviewer performs another regulated role without authorization.
  - A flow coordinator manages readiness and exceptions, not substantive decisions.
- **Loops**
  - `Request Supplement` returns the case to receipt/readiness, then Document Check and Assessment repeat.
  - Identity repeats only if the supplement affects identity or the result has expired.
  - Version all evidence and cancel obsolete work items.
- **Logging**
  - Immutable enabled, assigned, started, suspended, completed, input-ready, lock, API, supplement, and version events.
  - Record worker/pool, statutory flags, complexity, channel, WIP at release, and reason codes.

```text
Register < Identity Check
Register < Originals Receipt / Document Readiness

if originals_required:
    Originals Receipt < Document Check
else:
    Register < Document Check

Identity Check < Assessment
Document Check < Assessment

if legal_required:
    Assessment < Legal Review
    Legal Review < (Approve XOR Reject XOR Request Supplement)
    Request Supplement < Originals Receipt / Document Readiness
    Originals Receipt / Document Readiness < repeated Document Check
    repeated Document Check < repeated Assessment
else:
    Assessment < (Approve XOR Reject)

Approve < Notify
Reject < Notify

No order is imposed between Identity Check and Document Check when both are enabled.
```

The pilot separates **mechanism failure** from **implementation failure** by measuring the causal chain. First, assignment must produce executable concurrent work: activation times, immutable starts, lock conflicts, and validated true overlap test fidelity. If T1 fails to increase true overlap, or only back-entry rises, implementation failed and cycle-time results do not test the structural mechanism.

If true overlap rises but the maximum completion time of the two checks does not fall, the shared critical-path mechanism is weak—for example, one check was not actually independent or originals still dominated. If verification completion improves but total cycle time does not, downstream Assessment or Legal Review congestion displaced the bottleneck. Pool occupancy and stage-specific waiting identify that case. If time improves but rework, supplements, or appeals worsen, the mechanism operates but is unsafe for that stratum.

T1 versus T2 distinguishes parallelization from queue huddles/WIP controls, avoiding Site A’s bundled-change ambiguity. An IT-enabled version versus a legacy-lock version estimates whether software support is a necessary implementation condition. Randomized stratum effects then show whether failure is concentrated among originals-required, legal, or complex cases rather than being intrinsic to parallel verification.

## 8. PM4Py model-construction code

```python
"""
Illustrative PM4Py construction.

The exact POWL constructor keyword names have varied across PM4Py releases.
This example uses the common OperatorPOWL / StrictPartialOrder interface in
pm4py.objects.powl.obj and keeps parent-child relationships explicit.
"""

import pm4py
from pm4py.objects.powl.obj import (
    Transition,
    SilentTransition,
    OperatorPOWL,
    StrictPartialOrder,
    Operator
)

# ---------------------------------------------------------------------
# 1-2. Site A process trees and accepting Petri nets
# ---------------------------------------------------------------------
a_before = pm4py.parse_process_tree(
    "->('Register','Identity Check','Document Check','Assessment',"
    "X('Approve','Reject'),'Notify')"
)

a_after = pm4py.parse_process_tree(
    "->('Register',+('Identity Check','Document Check'),'Assessment',"
    "X('Approve','Reject'),'Notify')"
)

a_before_net, a_before_im, a_before_fm = pm4py.convert_to_petri_net(a_before)
a_after_net, a_after_im, a_after_fm = pm4py.convert_to_petri_net(a_after)

# ---------------------------------------------------------------------
# POWL helpers
# ---------------------------------------------------------------------
def xor(*children):
    """Exclusive choice over the supplied POWL children."""
    return OperatorPOWL(operator=Operator.XOR, children=list(children))

def loop(do_part, redo_part):
    """
    LOOP means: execute do_part once; optionally execute redo_part and then
    do_part again, repeatedly. Here it captures supplement-driven repetition.
    """
    return OperatorPOWL(
        operator=Operator.LOOP,
        children=[do_part, redo_part]
    )

def spo(children, edges):
    """
    Build a strict partial order and explicitly add order edges.
    Each edge is a tuple (predecessor_node, successor_node).
    """
    model = StrictPartialOrder(nodes=list(children))
    for source, target in edges:
        model.order.add_edge(source, target)
    return model

# ---------------------------------------------------------------------
# 3-4. Site B candidate:
# - Registration enables identity and a document-readiness path.
# - Identity and document verification are unordered relative to each other.
# - Explicit edges force Assessment to wait for BOTH.
# - Optional legal branch contains a supplement loop.
#
# Data-specific originals routing is represented structurally as a choice:
#   digital-ready: Register -> Document Check
#   originals path: Register -> Originals Receipt -> Document Check
# In production, a case attribute/rule must resolve this choice.
# ---------------------------------------------------------------------
register = Transition(label="Register")
identity = Transition(label="Identity Check")

doc_digital = Transition(label="Document Check [digital-ready]")

originals = Transition(label="Originals Receipt")
doc_after_originals = Transition(label="Document Check [after originals]")
originals_path = spo(
    [originals, doc_after_originals],
    [(originals, doc_after_originals)]
)

# A silent branch-selection structure can represent lawful alternatives,
# but cannot itself evaluate "originals_required".
document_route = xor(doc_digital, originals_path)

assessment = Transition(label="Assessment")

# Direct decision for cases not requiring legal review
approve_direct = Transition(label="Approve [direct]")
reject_direct = Transition(label="Reject [direct]")
direct_decision = xor(approve_direct, reject_direct)

# Legal path, including zero-or-more supplement cycles before final decision.
legal_review_initial = Transition(label="Legal Review")

supplement_request = Transition(label="Request Supplement")
supplement_receipt = Transition(label="Supplement Receipt")
repeat_document = Transition(label="Document Check [repeat]")
repeat_assessment = Transition(label="Assessment [repeat]")
repeat_legal = Transition(label="Legal Review [repeat]")

supplement_body = spo(
    [
        supplement_request,
        supplement_receipt,
        repeat_document,
        repeat_assessment,
        repeat_legal
    ],
    [
        (supplement_request, supplement_receipt),
        (supplement_receipt, repeat_document),
        (repeat_document, repeat_assessment),
        (repeat_assessment, repeat_legal)
    ]
)

# LOOP do-part is silent: the legal path may have no supplement, or may
# execute one/more supplement bodies before the final legal decision.
no_supplement = SilentTransition(label=None)
supplement_loop = loop(no_supplement, supplement_body)

approve_legal = Transition(label="Approve [legal]")
reject_legal = Transition(label="Reject [legal]")
legal_decision = xor(approve_legal, reject_legal)

legal_path = spo(
    [legal_review_initial, supplement_loop, legal_decision],
    [
        (legal_review_initial, supplement_loop),
        (supplement_loop, legal_decision)
    ]
)

# Optional legal review is represented as XOR between direct and legal paths.
post_assessment = xor(direct_decision, legal_path)

notify = Transition(label="Notify")

# Root strict partial order.
# Crucially, there is NO edge identity -> document_route or reverse.
# Both can therefore proceed concurrently once Register completes.
# The two explicit incoming edges to Assessment implement the AND-join.
site_b_candidate = spo(
    [
        register,
        identity,
        document_route,
        assessment,
        post_assessment,
        notify
    ],
    [
        (register, identity),
        (register, document_route),
        (identity, assessment),          # Assessment waits for identity
        (document_route, assessment),    # Assessment waits for documents
        (assessment, post_assessment),
        (post_assessment, notify)
    ]
)

# ---------------------------------------------------------------------
# 5. Convert the POWL model to an accepting Petri net
# ---------------------------------------------------------------------
b_net, b_im, b_fm = pm4py.convert_to_petri_net(site_b_candidate)

# ---------------------------------------------------------------------
# 6. Workflow-net / soundness checks
# ---------------------------------------------------------------------
for name, net, im, fm in [
    ("Site A before", a_before_net, a_before_im, a_before_fm),
    ("Site A after", a_after_net, a_after_im, a_after_fm),
    ("Site B candidate", b_net, b_im, b_fm),
]:
    is_wf = pm4py.check_is_workflow_net(net)
    print(f"{name}: workflow net = {is_wf}")
    try:
        sound = pm4py.check_soundness(net, im, fm)
        print(f"{name}: soundness = {sound}")
    except TypeError:
        # Some PM4Py versions infer markings or expose a different signature.
        print(f"{name}: soundness check signature differs in this PM4Py version")

# ---------------------------------------------------------------------
# 7. Optional playout and sample traces
# ---------------------------------------------------------------------
try:
    simulated_log = pm4py.play_out(
        b_net,
        b_im,
        b_fm,
        parameters={"noTraces": 5}
    )
    for i, trace in enumerate(simulated_log[:5], start=1):
        labels = [event.get("concept:name") for event in trace]
        print(f"Sample {i}: {labels}")
except Exception as exc:
    print("Playout unavailable or API differs:", exc)

# ---------------------------------------------------------------------
# 8. Model limitations
# ---------------------------------------------------------------------
# This control-flow model cannot itself enforce data-dependent legislation:
# whether originals or legal review are required must be resolved by case
# attributes, guards, or an external rules engine. It also does not encode:
# - reviewer counts, skills, calendars, utilization, or WIP limits;
# - legacy case ownership locks or unsafe workarounds;
# - stochastic service, receipt, API, or queue durations;
# - immutable versus back-entered timestamps;
# - identity-result expiry or substantive dependencies between checks.
# Those require organizational/resource models, data-aware guards,
# simulation parameters, and execution-system controls.
```

## 9. Recommendation

**conditional go**

Transfer the **partial-order principle**, not Site A’s literal rollout or its claimed nine-hour effect. Site B should permit Identity Check and Document Check to execute concurrently only when each task’s legal and informational prerequisites are satisfied, while retaining the AND-join before Assessment. For originals-required cases, the transferable idea is narrower: perform Identity Check while originals are in transit, but do not create an active, ownership-consuming Document Check until receipt. Also transfer disciplined WIP management and reliable event logging, but evaluate them as separate components because queue huddles were a co-intervention at Site A.

Do not copy universal simultaneous task creation. It would conflict with the 62% originals requirement, interact badly with the legacy lock, and could shift congestion to three assessors or two legal reviewers. Nor should Site A’s nine-hour median reduction or 18-hour p90 reduction be used as B’s forecast: A added document capacity, upgraded its API, simplified its mix, introduced huddles, and changed timestamp recording without a concurrent control.

The first subgroup should be no-original, non-mandatory-legal claims—approximately 23% if the two characteristics are independent—randomized within complexity and team/day blocks. A realistic initial target is a 4–6 hour median reduction within that subgroup, with stable p90, rework, and appeals. Originals-required cases can follow if early identity completion reduces post-receipt elapsed time without stale-result rework. Mandatory-legal and highly complex cases should enter last.

Expand when immutable logs show materially higher true overlap, median time to Assessment and total cycle time improve, and p90, rework, supplements, and appeals remain within pre-specified non-inferiority limits. Modify the intervention if verification improves but assessment or legal queues grow: reduce release rates, tighten WIP, or add downstream capacity. Repair or abandon the legacy implementation if task creation increases but true overlap does not, ownership conflicts occur, or timestamp back-entry dominates. Abandon expansion if repeated randomized evidence shows no proximal waiting benefit, or if rework rises by at least two percentage points, appeals by one point, or p90 by 15 hours despite adequate implementation fidelity.

## 10. Assumption register

1. **Identity and document checks are substantively independent for the first-wave subgroup** — needed for safe concurrent execution — test dependency reason codes and reviewer audit samples — if false, use ordered or milestone-based checking.

2. **About 38% of cases can legally use documents available without originals** — needed to size immediate eligibility — validate statutory flags against legal determinations — if false, revise subgroup size and forecasts.

3. **Originals and mandatory-legal status are sufficiently independent for the 23% planning estimate** — needed for initial volume planning — cross-tabulate six months of cases — if false, use the observed joint share.

4. **The case system can support lock-safe independent work items during the pilot** — needed to deliver true parallelization — run technical concurrency and audit tests — if false, restrict treatment to an IT-enabled sandbox or postpone.

5. **Assessment and legal utilization leave enough headroom for controlled pilot releases** — needed to avoid induced downstream congestion — estimate arrival/service distributions and monitor occupancy — if false, use pull gates or add capacity before expansion.

6. **Site B’s complexity classification is measured before treatment and consistently applied** — needed for stratification and standardization — audit labels against blinded case reviews — if false, replace it with observable pre-treatment predictors.

7. **Immutable task events approximate actual work intervals better than current back-entry timestamps** — needed to measure fidelity and overlap — compare logs with lock/API records and work sampling — if false, do not use overlap as a mediator until instrumentation improves.

8. **Rework and 90-day appeal rates are sensitive enough to detect material quality harm** — needed for safety decisions — validate linkage, denominators, and adjudication lag — if false, add blinded error audits and first-pass-quality endpoints.
