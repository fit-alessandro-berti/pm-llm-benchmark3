For live scoring, do not trust global calibration; use variant/source-stratified conservative thresholds or manual review for V3 and Partner Z where business risk is high.

**Short-term recalibration.** After activity-label normalization, duplicate cleaning, and cached-feature backfill, recalibrate on mature, clean labels. Use segment-specific calibration for V1/V2/V3 and possibly Partner Z/non-Z. Recalibration should use fixed-vintage labels or censor-aware weights, not raw current labels from Sep–Oct.

**Feature repair.** Add and backfill supplier/parts-wait features, rurality, device age, Partner Z/source, routing policy, and current backlog indicators. Repair the cached “number of events before diagnosis” feature. Validate that duplicate-event handling is consistent across old and new sources.

**Full retraining.** Retrain only when: Apr/May features are repaired; Sep/Oct labels have matured sufficiently, e.g. 120–180 days depending on label delay; and pipeline/label-quality alarms are clear. Use time-based validation and evaluate by variant, source, and month. A global model with variant/source interactions and hierarchical partial pooling is safer initially than fully separate models. A separate V3 model or V3/Partner-Z calibration head is justified if data volume is sufficient and stratified evidence shows persistent conditional deterioration.

**Safe/unsafe training months.** Jan–Mar are safe baseline. Apr is unsafe due to corrupted prefixes and features. May is unsafe until recomputed. Jun–Jul are usable with caution if routing-policy/variant features are included; July is 98% mature but supplier stress begins. Aug is borderline: mostly mature, but it reflects the new supplier regime. Sep is unsafe until maturity increases. Oct is unsafe and should not be used for training or final performance claims.

## 5. Monitoring architecture

| Monitor | Key signals | Alert dependency/action |
|---|---|---|
| Predictive | AUROC, PR-AUC, Brier, log loss, prediction distribution, by month/variant/source | If alert fires, require mature labels and clean pipeline before retraining. |
| Calibration | ECE, calibration slope/intercept, reliability curves by segment | Segment-specific recalibration if mature and pipeline-clean. |
| Label maturity | Maturity curves, median label delay, % matured at 30/60/90 days, fixed-vintage estimates | Label-delay alarm marks current performance provisional; do not automatically retrain. |
| Data quality | Unknown activity share, missing queue/features, duplicate rate, schema/label mapping, source lag | Block retraining/calibration until pipeline repairs and recomputation pass. |
| Process variant | Variant distribution, unmapped/other share, transition counts | If shift exceeds threshold, trigger stratified analysis and feature review. |
| Performance-DFG | `Order Part -> Part Received`, diagnosis-to-`Remote Fix`, dispatch-to-repair median/P90 | Parts-edge alert triggers operational/supplier investigation and feature coverage check. |
| Population | Partner Z share, rural/device-age coverage, source mix | Population alarm triggers reweighting/transport checks before declaring concept drift. |
| Intervention/deployment | Routing policy, supplier alerts, model version, thresholds, overrides | Annotate all metric changes with known interventions; require segment evidence before model action. |

Alert dependencies: a label-delay alarm should pause performance comparisons and force fixed-vintage reporting, not retraining. A data-quality alarm should block retraining and calibration. A population-shift alarm should trigger stratified/reweighted evaluation before any unfairness conclusion. A concept-drift alarm should require mature labels, clean pipeline, and within-stratum degradation. A process/performance-DFG alarm should first investigate operational causes and feature coverage.

```python
import pandas as pd
import pm4py

# Read raw events; keep a source column for duplicate/lineage auditing.
df = pd.read_csv("field_service_events.csv", parse_dates=["timestamp"])
if "source" not in df.columns:
    df["source"] = "unknown"

# Normalize renamed diagnosis labels before any feature extraction.
df["activity"] = df["activity"].replace({
    "Initial Diagnosis Completed": "Diagnostic_Assessment_Completed",
    "Diagnostic Assessment Completed": "Diagnostic_Assessment_Completed",
})
df["is_unknown"] = df["activity"].eq("UNKNOWN_ACTIVITY")

# Conservative duplicate handling: remove exact duplicates only where policy applied.
df["exact_dup"] = df.duplicated(["case_id", "activity", "timestamp", "source"], keep="first")
df["remove_dup"] = df["exact_dup"] & df["source"].eq("new") & (df["timestamp"] >= pd.Timestamp("2026-04-20"))
df_clean = df.loc[~df["remove_dup"]].copy()

# PM4Py standardized columns.
df_fmt = pm4py.format_dataframe(
    df_clean, case_id="case_id", activity_key="activity", timestamp_key="timestamp"
)
C, A, T = "case:concept:name", "concept:name", "time:timestamp"

# Event-calendar cohort = events occurring in a calendar month.
# Case-start cohort = all events for cases created in that month; use for outcome/label maturity.
first_event = df_fmt.groupby(C)[T].min().dt.to_period("M").rename("case_start_month")
df_fmt = df_fmt.merge(first_event, on=C, how="left")
df_fmt["event_month"] = df_fmt[T].dt.to_period("M").astype(str)

def edge_median_hours(events, a, b):
    events = events.sort_values([C, T])
    events["next_activity"] = events.groupby(C)[A].shift(-1)
    events["next_ts"] = events.groupby(C)[T].shift(-1)
    mask = events[A].eq(a) & events["next_activity"].eq(b)
    return ((events.loc[mask, "next_ts"] - events.loc[mask, T])
            .dt.total_seconds().div(3600).median())

rows = []
for m in sorted(df_fmt["event_month"].unique()):
    start = pd.Timestamp(m + "-01")
    end = start + pd.offsets.MonthEnd(1) + pd.Timedelta(days=1)

    ev_cal = pm4py.filter_time_range(df_fmt, start, end)          # operational/event view
    cs = df_fmt[df_fmt["case_start_month"].astype(str).eq(m)]     # training/outcome cohort view

    dfg, sa, ea = pm4py.discover_dfg(ev_cal) if len(ev_cal) else ({}, set(), set())
    perf_dfg, psa, pea = pm4py.discover_performance_dfg(ev_cal) if len(ev_cal) else ({}, set(), set())
    variants = pm4py.get_variants(cs) if len(cs) else {}
    try:
        temporal = pm4py.extract_temporal_features_dataframe(cs)
    except Exception:
        temporal = None

    rows.append({
        "month": m,
        "case_start_cases": cs[C].nunique(),
        "event_calendar_events": len(ev_cal),
        "unknown_share_case_start": cs["is_unknown"].mean() if len(cs) else None,
        "variant_counts_case_start": variants,
        "order_part_to_received_median_h": edge_median_hours(cs, "Order Part", "Part Received"),
        "diagnostic_to_remote_fix_median_h": edge_median_hours(
            cs, "Diagnostic_Assessment_Completed", "Remote Fix"
        ),
        "event_calendar_dfg_edges": len(dfg),
        "event_calendar_perf_dfg_edges": len(perf_dfg),
        "temporal_feature_rows": None if temporal is None else len(temporal),
    })

monthly_summary = pd.DataFrame(rows).sort_values("month")
print(monthly_summary.to_string(index=False))
```

## 6. Risks of acting on the wrong diagnosis

1. **Retraining on immature labels.** Sep–Oct labels are censored, especially for long V3/Partner Z paths. Retraining would learn that breaches are rare in October when they are merely unmatured. Mitigation: fixed-vintage backtesting, censor-aware training, and a maturity gate before using a month for training.

2. **Calibrating around a pipeline bug.** April’s AUROC/ECE deterioration is caused by renamed diagnosis labels, duplicates, and missing cached features. Recalibrating on corrupted features would bake in the bug. Mitigation: freeze April, recompute features from raw events, run lineage checks, and require pipeline-clean gates before calibration.

3. **Ignoring genuine supplier-driven concept drift.** Aug–Sep V3 breach rises sharply as `Order Part -> Part Received` worsens. Treating this only as label delay or population shift could understate real operational risk. Mitigation: add supplier/parts-delay features, test within-V3 month effects, and retrain once labels mature enough to represent the supplier regime.

4. **Attributing Partner Z’s population shift to unfair model behavior without stratified evidence.** Partner Z has more rural cases, higher V3 share, and slower labels. A raw source gap does not prove bias. Mitigation: stratify by variant, adjust for rurality/device age, run reweighting/transport tests, and separate population shift from model discrimination/calibration.

5. **Treating June routing change as model decay.** June’s lower breach is largely a V2 mix increase, not a broken model. Retraining immediately could erase useful stable relationships. Mitigation: variant-stratified calibration, policy features, and conditional breach-rate checks before retraining.

6. **Misreading October’s lower observed breach as improvement.** October observed 0.16 is not comparable because maturity is 55% and the outcome API backlog affects longer paths. Mitigation: suppress month-over-month conclusions on immature cohorts, display maturity-adjusted estimates, and trigger label-delay alarms rather than retraining.

7. **Overreacting to April by retraining.** April’s AUROC drop is an incident, not a stable drift signal. Retraining on April data would introduce corrupted labels/features. Mitigation: classify April as a data-pipeline incident, repair and recompute, then compare against Jan–Mar before deciding whether any model change is needed.
