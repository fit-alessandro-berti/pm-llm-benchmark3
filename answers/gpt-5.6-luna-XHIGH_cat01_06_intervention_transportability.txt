The shared causal mechanism is a critical-path change: if identity and document work have no true precedence relation, overlap can reduce the maximum of their completion times toward the time that was previously their sum, especially by reducing waiting before Assessment. Queue huddles and lower query latency can reinforce that mechanism. The site-specific mechanisms are the statutory originals gate, separate role pools, the one-owner case lock, the Legal Review branch, supplement/reassessment loops, and B's heavier complexity tail. These can determine whether a nominally parallel task is executable, whether it consumes scarce capacity, and whether it creates rework.

The effect modifiers are digital-document availability, originals delay, complexity, legal status, role specialization, identity/document/assessment/legal capacity, lock fidelity, queue load, and timestamp fidelity. They modify both treatment adherence (true overlap) and the outcome response once overlap occurs. The S-nodes represent different site distributions or mechanisms, rather than extra treatment effects. A similar control-flow diagram therefore does not establish transportability: the estimand is conditional on prerequisites, resources, data-dependent branches, and implementation fidelity. At A, the intervention is also entangled with an API upgrade, added reviewers, simpler mix, huddles, and improved recording. Those variables make the observed association compatible with several causal stories, so A supplies a mechanism hypothesis and plausible bounds, not a transported nine-hour effect.

## 6. Candidate Site B intervention

Eligibility should be determined at registration from document channel, statutory status, complexity, and package completeness. For a digitally complete, non-blocked case, create Identity Check and Document Check after Register and allow their separate pools to execute concurrently. For an originals-required case, create Identity Check and Originals Receipt after Register. A Document Check task may be pre-created as `blocked-awaiting-originals` for routing, but its execution, work timestamp, and completion are prohibited until Originals Receipt is complete and the received package is linked. Any other statutory prerequisite remains mandatory.

Assessment starts only after the current-version Identity Check and Document Check both complete. Non-legal cases then take the Approve/Reject branch and Notify. Public-sector or high-value cases take Legal Review after Assessment. Legal Review may approve or reject, or issue Request Supplement. A supplement creates a new document version, invalidates affected downstream work, performs the required document recheck and Assessment recheck, and returns the case to Legal Review before final decision. No stale Assessment may be used for a legal decision.

Identity, document, assessment, and legal pools retain separate ownership. Each pool has an explicit WIP cap, with admission control tied to the next pool's ready queue. Use aged-case priority within a fair queue, reserve legal capacity for supplement returns, and keep blocked tasks out of active-worker WIP counts while tracking their age. Preserve the six-open-task principle as a starting guardrail, but calibrate it separately for B's pools. Treatment assignment and version are immutable.

Log server-side task creation, eligibility, ready time, start, completion, owner, handoff, lock acquisition/release, override, blocked reason, document version, supplement cause, cancellation, recheck, and final outcome. Flag late or back-entered events and record both event time and entry time.

POWL-style partial-order relations (with `||` denoting no required order) are:

```text
Register < Identity Check
Register < Originals Receipt
DigitalDocument => Register < Document Check
OriginalsRequired => Originals Receipt < Document Check
DigitalDocument => Identity Check || Document Check
{Identity Check, Document Check} < Assessment
NonLegal => Assessment < (Approve xor Reject) < Notify
Legal => Assessment < Legal Review < (Legal Approve xor Legal Reject xor Request Supplement)
Request Supplement < Document Check(recheck) < Assessment(recheck) < Legal Review(recheck)
Final Approve/Reject < Notify
```

The pilot separates implementation failure from mechanism failure by measuring the mediator rather than inferring it from assignment. If T1 or T2 does not produce true overlap because of the lock, blocked-state, or staffing controls, the result is a fidelity failure; improve the workflow and rerun the technical cell. If auditable overlap is achieved with complete prerequisites and capacity within limits but waiting does not fall, the parallelization mechanism is weak in that stratum. If waiting falls but p90, rework, or appeals worsen, the mechanism helps the central path while causing a downstream bottleneck or stale-work loop. Blocked time, lock exceptions, queue load, and timestamp provenance make those explanations distinguishable, while randomized assignment and standardized huddles limit confounding. The 90-day follow-up prevents a fast-cycle result from being declared successful before quality is observable.

## 8. PM4Py model-construction code

```python
"""Illustrative PM4Py construction for the two Site A trees and a Site B POWL.

This requires a PM4Py release with the public POWL classes. POWL captures
control-flow order, choice, and loops here; it does not encode case data,
statutory predicates, resource capacity, case locks, or task durations.
"""

import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator


# 1) Site A process trees, using the supplied process-tree notation.
a_before = pm4py.parse_process_tree(
    "->('Register', 'Identity Check', 'Document Check', "
    "'Assessment', X('Approve', 'Reject'), 'Notify')"
)
a_after = pm4py.parse_process_tree(
    "->('Register', +('Identity Check', 'Document Check'), "
    "'Assessment', X('Approve', 'Reject'), 'Notify')"
)

# 2) Convert both trees to accepting Petri nets.
a_before_net, a_before_im, a_before_fm = pm4py.convert_to_petri_net(a_before)
a_after_net, a_after_im, a_after_fm = pm4py.convert_to_petri_net(a_after)


def t(label):
    return Transition(label=label)


def xor(*children):
    return OperatorPOWL(operator=Operator.XOR, children=list(children))


def spo(nodes, edges):
    """Make an SPO and explicitly add every precedence edge."""
    p = StrictPartialOrder(nodes=list(nodes))
    for source, target in edges:
        p.order.add_edge(source, target)
    return p


# 3) A Site B candidate. The document-track XOR represents a case-data branch:
# digital documents permit immediate Document Check; originals require receipt.
register = t("Register")
identity = t("Identity Check")
digital_doc = t("Document Check [digital]")
receipt = t("Originals Receipt")
original_doc = t("Document Check [originals]")
assessment = t("Assessment")

original_track = spo(
    [receipt, original_doc],
    [(receipt, original_doc)],
)
document_track = xor(digital_doc, original_track)

# The root SPO explicitly gives both identity and the selected document track
# Register as a predecessor, and gives Assessment both predecessors. Thus the
# model cannot complete Assessment after only one verification has finished.
direct_decision = xor(t("Approve"), t("Reject"))

legal_review = t("Legal Review")
request_supplement = t("Request Supplement")
doc_recheck = t("Document Check [supplement]")
assessment_recheck = t("Assessment [supplement]")
legal_recheck = t("Legal Review [supplement]")

supplement_cycle = spo(
    [request_supplement, doc_recheck, assessment_recheck, legal_recheck],
    [
        (request_supplement, doc_recheck),
        (doc_recheck, assessment_recheck),
        (assessment_recheck, legal_recheck),
    ],
)

# In POWL, LOOP has a body and a redo/continuation component. The XOR with a
# silent transition makes the supplement cycle optional; its body returns to
# legal review and can be repeated by the LOOP semantics.
supplement_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[supplement_cycle, SilentTransition()],
)
optional_supplement = xor(SilentTransition(), supplement_loop)
legal_outcome = xor(t("Legal Approve"), t("Legal Reject"))
legal_branch = spo(
    [legal_review, optional_supplement, legal_outcome],
    [
        (legal_review, optional_supplement),
        (optional_supplement, legal_outcome),
    ],
)

# The data-dependent choice Legal versus non-Legal is represented as XOR for
# control-flow purposes; a case attribute must select the statutory branch.
post_assessment = xor(direct_decision, legal_branch)
notify = t("Notify")
b_powl = spo(
    [register, identity, document_track, assessment, post_assessment, notify],
    [
        (register, identity),
        (register, document_track),
        (identity, assessment),
        (document_track, assessment),
        (assessment, post_assessment),
        (post_assessment, notify),
    ],
)

# 4) Convert POWL to an accepting Petri net. Some PM4Py releases dispatch this
# through the top-level function; the fallback is the POWL converter module.
try:
    b_net, b_im, b_fm = pm4py.convert_to_petri_net(b_powl)
except (AttributeError, TypeError, NotImplementedError):
    from pm4py.objects.powl.to_petri_net import apply as powl_to_petri_net
    b_net, b_im, b_fm = powl_to_petri_net(b_powl)


def report_properties(name, net, initial_marking, final_marking):
    if hasattr(pm4py, "check_is_workflow_net"):
        print(name, "workflow-net:",
              pm4py.check_is_workflow_net(net))
    if hasattr(pm4py, "check_soundness"):
        print(name, "soundness:",
              pm4py.check_soundness(net, initial_marking, final_marking))


report_properties("A before", a_before_net, a_before_im, a_before_fm)
report_properties("A after", a_after_net, a_after_im, a_after_fm)
report_properties("B candidate", b_net, b_im, b_fm)

# 5) Optional playout of sample traces.
if hasattr(pm4py, "play_out"):
    sample_log = pm4py.play_out(
        b_net, b_im, b_fm, parameters={"no_traces": 3}
    )
    for i, trace in enumerate(sample_log):
```

## 9. Recommendation

conditional go

Transfer the operational principle—remove an unnecessary precedence relation and expose independent work early—but do not transfer Site A's aggregate nine-hour estimate or its exact task graph. Site B should first use a digital-safe variant: after Register, release Identity Check and Document Check concurrently only when the digital package is complete and no statutory prerequisite is outstanding. For originals-required cases, release Identity Check alongside Originals Receipt, keep Document Check blocked until receipt, and let Assessment wait for both current-version checks. Legal Review remains a downstream, mandatory branch for public-sector and high-value cases.

The first entering subgroup should be lower-complexity, digitally complete, non-legal cases. This subgroup has the clearest shared partial-order mechanism, the least risk from supplement loops, and a plausible 4–8 hour subgroup median improvement if true overlap is achieved. Originals cases should enter through a separate gated arm, not by copying the digital arm. Legal cases should be included in a later capacity-controlled arm so that legal queue and supplement effects are observed rather than hidden.

Expected benefits are reduced waiting before Assessment, better alignment of identity completion with document readiness, and possibly a lower median cycle time. Risks are a false overlap signal from back-entered timestamps, lock workarounds, saturation of the seven-person document or three-person Assessment pool, legal-tail congestion, duplicate work, and higher rework. A modest median gain is not sufficient if B's 110-hour p90 worsens or appeals rise.

Expand only when the relevant arm has auditable true overlap, statutory conformance, stable or improved p90, non-inferior rework and quality, and adequate support in channel, legal-status, and complexity strata. Modify when overlap is low but the technical remedy is clear, or when the median improves while a specific queue or subgroup deteriorates. Abandon that arm when fidelity is adequate yet waiting does not improve, or when tail, rework, appeal, or legal-safety guardrails breach their prespecified limits.

## 10. Assumption register

1. Digital claims are legally eligible for concurrent Identity Check and Document Check after Register — needed to define the cleanest shared mechanism — test by statutory rule review and case-level eligibility audit — if false, exclude the claim type and use only the safe originals path.
2. Originals Receipt is the controlling prerequisite for every originals-required Document Check — needed to preserve Site B's stated legal ordering — test by legal audit and conformance checking of event logs — if false, revise the graph and eligibility gate before randomization.
3. Identity and document pools can accept separate work without lowering review quality — needed for true concurrency to create capacity rather than merely shift work — test with blinded quality sampling, error rates, and handoff audits — if false, require paired review or abandon that treatment version.
4. A lock adapter or an auditable blocked-task state can be deployed without bypassing statutory controls — needed to distinguish real overlap from timestamp back-entry — test in a canary with lock telemetry and duplicate-case reconciliation — if false, do not interpret overlap or run the parallel arm.
5. Assessment capacity can absorb earlier verification completions under capped admission — needed for waiting reduction to reach cycle time — test with a load simulation and pilot ready-queue age/utilization — if false, pace releases or treat the intervention as a bottleneck-shift failure.
6.
