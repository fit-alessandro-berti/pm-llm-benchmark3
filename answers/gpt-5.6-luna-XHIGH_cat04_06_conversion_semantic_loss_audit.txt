# 1. Source-Semantics Baseline

Use the abbreviations `R=Register Change`, `A=Assess Risk`, `P=Prepare Evidence`, `L=Legal Review`, `C=Configure Trial`, `I=Inspect Trial`, `D=Correct Defect`, `X=Release Change`, and `Z=Archive Change`. A trace shown in the tables omits the silent `tau` choice that skips legal review. `C I` is one verification iteration; `C I D C I` is two iterations.

| Invariant ID | Invariant | Positive witness | Negative witness | Observable after hiding tau? |
|---|---|---|---|---|
| S1 | `R` is first. | `R A P C I X Z` | `A R P C I X Z` | Yes. |
| S2 | `A` and `P` both follow `R`, but neither is ordered before the other. | `R A P C I X Z` and `R P A C I X Z` | `P R A C I X Z` | The two orders are visible; true concurrency is only partially observable in linear traces. |
| S3 | Legal review is optional and, when present, follows `A`. | `R A P C I X Z` and `R A P L C I X Z` | `R P L A C I X Z` | Yes: `L` is visible when selected, while the skip branch is not. |
| S4 | Verification cannot start until both `A` and `P` finish. | `R A P C I X Z` and `R P A C I X Z` | `R A C I P X Z` | Yes. |
| S5 | There is no source order between the optional-legal branch and verification after their prerequisites. | `R A P L C I X Z` and `R A P C I L X Z` | There is no forbidden source trace for this invariant; rejecting either positive witness is a negative conversion result. | Both interleavings are visible; independence itself is not proved by a trace alone. |
| S6 | Within every iteration, `C` precedes `I`; `D` is the repeat separator, not part of the trial body. | `R A P C I D C I X Z` | `R A P C D I X Z` | Yes. |
| S7 | At least one verification iteration occurs. | `R A P C I X Z` | `R A P X Z` | Yes. |
| S8 | `X` waits for both the completed verification loop and completion of the legal branch, including its silent skip. | `R A P C I X Z` and `R A P L C I X Z` | `R A P L X Z` | Yes, provided the silent branch is treated as a completed branch. |
| S9 | `Z` follows `X` and is final; no source activity follows it. | `R A P C I X Z` | `R A P C I X Z A` or `R A P C I Z X` | Yes. |
| S10 | Visible activity labels identify activities uniquely; only the optional skip is silent. | The two S3 witnesses differ by the presence of `L`, not by an invented visible tau label. | A conversion that duplicates labels or exposes tau as a visible activity changes the observable alphabet. | Labels are observable; tau visibility is not. |

# 2. Candidate Conversion Pipelines

The primary pipeline is the accepting-net route because an accepting Petri net can represent partial-order concurrency, silent routing, explicit joins, and a binary loop without requiring the model to be block structured.

| Pipeline | PM4Py calls | Expected benefit | Expected risk | Failure condition |
|---|---|---|---|---|
| **Primary: POWL → accepting Petri net → BPMN** | `pm4py.convert_to_petri_net(source_powl)` followed by `pm4py.convert_to_bpmn(net, im, fm)` | Keeps an explicit executable semantics between the source and the stakeholder diagram. Markings and tau transitions make joins, optionality, and loop repetition auditable. | BPMN may introduce gateways, routing nodes, and layout choices whose visual appearance is ambiguous. A successful object conversion does not prove behavioral equivalence. | Any exception, null marking, non-workflow net, unsoundness, missing witness, forbidden witness, changed visible footprints, or failed exact-final-marking round trip. |
| POWL → accepting Petri net → process tree → BPMN | `pm4py.convert_to_petri_net(source_powl)`, `pm4py.convert_to_process_tree(net, im, fm)`, then `pm4py.convert_to_bpmn(tree)` | Can yield a compact, block-structured diagram with familiar sequence, choice, parallel, and loop constructs. | A process tree has a single-hierarchy/block-structure bias. Shared prerequisites and the unordered legal/verification branches can be forced into a sequence, duplicated, or otherwise misrepresented. | `convert_to_process_tree` raises; tree-to-BPMN raises; or the tree/BPMN accepts a different bounded trace set, changes optionality, loses the join, changes loop scope, or fails soundness. The exception is evidence that this route is unavailable, not a reason to silently substitute a different model. |

# 3. Conversion Code

The following is a self-contained script. It reconstructs `source_powl` exactly from the authoritative definition, checks returned markings before treating a result as accepting, reports process-tree exceptions, saves each available visualization, and diagnoses every accepting net that it obtains.

```python
from pathlib import Path

import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition,
    SilentTransition,
)
from pm4py.objects.process_tree.obj import Operator


# Authoritative source model.
register = Transition(label="Register Change")
assess_risk = Transition(label="Assess Risk")
prepare_evidence = Transition(label="Prepare Evidence")

legal_review = Transition(label="Legal Review")
skip_legal = SilentTransition()
optional_legal = OperatorPOWL(
    operator=Operator.XOR,
    children=[legal_review, skip_legal],
)

configure_trial = Transition(label="Configure Trial")
inspect_trial = Transition(label="Inspect Trial")
trial_body = StrictPartialOrder(nodes=[configure_trial, inspect_trial])
trial_body.order.add_edge(configure_trial, inspect_trial)

correct_defect = Transition(label="Correct Defect")
verification_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[trial_body, correct_defect],
)

release_change = Transition(label="Release Change")
archive_change = Transition(label="Archive Change")

source_powl = StrictPartialOrder(
    nodes=[
        register,
        assess_risk,
        prepare_evidence,
        optional_legal,
        verification_loop,
        release_change,
        archive_change,
    ]
)

source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)
source_powl.order.add_edge(release_change, archive_change)


def require_accepting(result, description):
    """Return (net, im, fm), or raise with an explicit interpretation."""
    if not isinstance(result, (tuple, list)) or len(result) != 3:
        raise RuntimeError(
            f"{description} did not return (net, initial_marking, final_marking): "
            f"{type(result).__name__}"
        )
    net, im, fm = result
    if net is None or im is None or fm is None:
        raise RuntimeError(
            f"{description} returned a non-accepting result: "
            f"net={net is not None}, im={im is not None}, fm={fm is not None}"
        )
    return net, im, fm


# Required primary conversion.
net_from_powl, im_from_powl, fm_from_powl = require_accepting(
    pm4py.convert_to_petri_net(source_powl),
    "POWL-to-Petri conversion",
)
bpmn_from_net = pm4py.convert_to_bpmn(
    net_from_powl,
    im_from_powl,
    fm_from_powl,
)


# Optional process-tree route. Failure is retained and interpreted, not hidden.
tree_from_net = None
bpmn_from_tree = None
process_tree_error = None
try:
    tree_from_net = pm4py.convert_to_process_tree(
        net_from_powl,
        im_from_powl,
        fm_from_powl,
    )
except Exception as exc:
    process_tree_error = f"{type(exc).__name__}: {exc}"
    print("PROCESS-TREE ROUTE FAILED")
    print(process_tree_error)
    print(
        "Interpretation: the Petri net is retained as the authoritative executable "
        "derivative; no tree semantics are inferred from the failed conversion."
    )
else:
    print(
        "PROCESS-TREE ROUTE PRODUCED A TREE; this is not evidence of semantic "
        "equivalence, so the round-trip audit is still required."
    )
    try:
        bpmn_from_tree = pm4py.convert_to_bpmn(tree_from_net)
    except Exception as exc:
        process_tree_error = f"tree-to-BPMN {type(exc).__name__}: {exc}"
        print("TREE-TO-BPMN ROUTE FAILED")
        print(process_tree_error)


# Convert every produced BPMN model back where PM4Py can do so.
roundtripped_nets = {}


def add_bpmn_round_trip(name, bpmn):
    if bpmn is None:
        return
    try:
        result = pm4py.convert_to_petri_net(bpmn)
        net, im, fm = require_accepting(result, f"BPMN-to-Petri conversion for {name}")
    except Exception as exc:
        print(f"BPMN ROUND TRIP FAILED [{name}]: {type(exc).__name__}: {exc}")
        return
    roundtripped_nets[name] = (net, im, fm)
    print(f"BPMN ROUND TRIP PRODUCED ACCEPTING NET [{name}]")


add_bpmn_round_trip("bpmn_from_net", bpmn_from_net)
add_bpmn_round_trip("bpmn_from_tree", bpmn_from_tree)


# All accepting nets, including the direct POWL conversion and available
# round-tripped nets, receive the same diagnostics.
accepting_nets = {
    "net_from_powl": (net_from_powl, im_from_powl, fm_from_powl),
    **roundtripped_nets,
}


def diagnose_accepting_net(name, net, im, fm):
    print(f"\nDIAGNOSTICS [{name}]")
    print(f"initial_marking={im}")
    print(f"final_marking={fm}")
    try:
        print(f"workflow_net={pm4py.check_is_workflow_net(net)}")
    except Exception as exc:
        print(f"workflow-net diagnostic failed: {type(exc).__name__}: {exc}")
    try:
        print(
            "soundness=",
            pm4py.check_soundness(net, im, fm, print_diagnostics=True),
        )
    except Exception as exc:
        print(f"soundness diagnostic failed: {type(exc).__name__}: {exc}")


for net_name, (net, im, fm) in accepting_nets.items():
    diagnose_accepting_net(net_name, net, im, fm)


# Visualization artifacts are derivative and have deliberately explicit names.
artifact_dir = Path("conversion_audit_artifacts")
artifact_dir.mkdir(parents=True, exist_ok=True)


def save_visualization(filename, save_call):
    path = artifact_dir / filename
    try:
        save_call(str(path))
        print(f"saved visualization: {path}")
    except Exception as exc:
        print(
            f"visualization failed [{path}]: {type(exc).__name__}: {exc}"
        )


save_visualization(
    "01_source_powl.png",
    lambda path: pm4py.save_vis_powl(source_powl, path),
)
save_visualization(
    "02_net_from_powl.png",
    lambda path: pm4py.save_vis_petri_net(
        net_from_powl, im_from_powl, fm_from_powl, path
    ),
)
save_visualization(
    "03_bpmn_from_net.png",
    lambda path: pm4py.save_vis_bpmn(bpmn_from_net, path),
)

if tree_from_net is not None:
    save_visualization(
        "04_tree_from_net.png",
        lambda path: pm4py.save_vis_process_tree(tree_from_net, path),
    )
if bpmn_from_tree is not None:
    save_visualization(
        "05_bpmn_from_tree.png",
        lambda path: pm4py.save_vis_bpmn(bpmn_from_tree, path),
    )

for net_name, (net, im, fm) in roundtripped_nets.items():
    safe_name = net_name.replace(" ", "_")
    save_visualization(
        f"06_{safe_name}.png",
        lambda path, net=net, im=im, fm=fm: pm4py.save_vis_petri_net(
            net, im, fm, path
        ),
    )
```

# 4. Preservation and Loss Audit

The first conversion is expected to preserve the POWL semantics in the accepting net. BPMN is treated as an intermediate/visual stakeholder model, so claims about it are conditional on the round-trip tests. For the tree column, `conversion failed` is the correct recorded result when PM4Py rejects the non-block-structured net; if it succeeds, it is not accepted until the same tests pass.

| Source invariant | POWL→Petri | Petri→BPMN | Petri→Tree | BPMN round trip | Evidence or uncertainty |
|---|---|---|---|---|---|
| `R` is first and the source has a single start | expected preserved | expected preserved | conversion failed | validated preserved | Check initial marking and the positive/negative witness traces. A layout placing another node higher on the page is irrelevant. |
| `A` and `P` are both after `R` and unordered with respect to each other | expected preserved | approximated | conversion failed | validated preserved | The net can retain independent enabled transitions. BPMN needs parallel routing, while a tree may have to choose a block decomposition. |
| `L` is optional and follows `A` | expected preserved | approximated | conversion failed | validated preserved | The skip branch must remain silent and must still complete the release join. Test both the no-`L` and `L` witnesses. |
| No edge orders optional legal review before verification, or verification before optional legal review | expected preserved | ambiguous | conversion failed | validated preserved | Require both `L`-before-`C` and `C`-before-`L` traces. A topological drawing or a sequence-shaped tree is not evidence that either order is required. |
| `C` precedes `I` inside each iteration | expected preserved | expected preserved | conversion failed | validated preserved | Use the wrong-loop-order negative witness and inspect visible labels, not transition object names. |
| `D` is the binary-loop redo separator | expected preserved | ambiguous | conversion failed | validated preserved | A BPMN loop marker may not show that `D` occurs only after a completed body and before a repeated body. |
| At least one `C I` iteration occurs | expected preserved | approximated | conversion failed | validated preserved | Reject a representation that admits `R A P X Z` or makes the body a zero-or-more loop. |
| `X` joins the legal branch and verification loop | expected preserved | approximated | conversion failed | validated preserved | The optional branch's tau path must count as completed, but `X` must not be enabled while verification is incomplete. |
| Initial and final markings define acceptance, not merely a visible sink | expected preserved | ambiguous | conversion failed | validated preserved | The round-trip test uses exact equality `marking == fm`; an apparently completed trace with extra tokens is not accepted. |
| `Z` is after `X` and final | expected preserved | expected preserved | conversion failed | validated preserved | Test a trace with activity after `Z` and inspect the final marking. |
| Visible labels remain unique and tau remains hidden | expected preserved | ambiguous | conversion failed | validated preserved | Duplicate labels can collapse distinct traces and footprints. An unlabeled BPMN routing node should not become a visible activity. |

The main semantic traps are these:

- True concurrency is stronger than accepting both linear interleavings. The Petri net should have independent enabled transitions where the POWL partial order has no edge. A bounded trace set can show both interleavings, but it cannot by itself prove independence; footprints and net inspection provide supporting evidence.
- The absent edge between optional legal review and verification is material. The source permits legal review before verification and verification before legal review once their prerequisites are met. A converter that happens to draw one branch above the other may have imposed no semantic order, or it may have encoded one; only enabled-transition and round-trip tests distinguish those cases.
- The XOR with `skip_legal` is not the same as a mandatory legal task and not the same as deleting the legal branch. The tau branch must be silent in visible traces and must satisfy the join before `X`.
- The loop is binary: the first child is the trial body and the second child is the redo action. The body runs at least once; after a body, `D` may separate it from another body. `D` is not an unconstrained activity and is not a third body step.
- `X` is a join point. It must wait for either completion of `L` or completion of its silent skip, as well as for a completed verification loop. A BPMN join that visually resembles a merge but does not synchronize both branches is a semantic loss.
- Labels, not transition identities, are used for visible-trace comparison. Every source visible label is unique. If a conversion creates duplicate labels, a trace comparison can become unsoundly permissive because distinct activities have collapsed into one alphabet symbol.
- Initial and final markings are part of the model. A returned object, a sink place, or a rendered end event is insufficient without checking the actual marking and exact final-token condition.
- BPMN gateways and routing nodes can make the model look more sequential or more concurrent than it is. The visual artifact is therefore evidence to review, not the canonical behavioral specification.

# 5. Round-Trip Validation Code

This block is intended to run after the conversion block. It compares `net_from_powl` with every accepting BPMN round-trip net in `roundtripped_nets`. The custom explorer records a trace only when the current marking is exactly equal to that net's final marking. It hides precisely transitions whose label is `None`, bounds visible length and the number of `Configure Trial` occurrences, and caps silent-only progress so a tau cycle cannot run forever.

```python
from collections import deque

from pm4py.objects.petri_net import semantics


CONFIGURE_LABEL = "Configure Trial"
MAX_VISIBLE_LENGTH = 12
MAX_LOOP_ITERATIONS = 3


def marking_key(marking, places):
    # Place objects are net-local. A fixed place order makes the exploration
    # state hashable without weakening the exact equality test below.
    return tuple(marking.get(place, 0) for place in places)


def bounded_visible_traces(
    net,
    initial_marking,
    final_marking,
    max_visible_length=MAX_VISIBLE_LENGTH,
    max_loop_iterations=MAX_LOOP_ITERATIONS,
):
    places = sorted(
        net.places,
        key=lambda place: (str(getattr(place, "name", "")), id(place)),
    )
    max_tau_steps = max(8, 4 * len(net.transitions) + 4)

    # tau_steps is reset after a visible transition. For a given marking and
    # visible trace, a path with fewer tau steps dominates one with more.
    queue = deque([(initial_marking, tuple(), 0)])
    best_tau_for_state = {}
    completed = set()
    silent_cutoffs = 0
    visible_cutoffs = 0
    loop_cutoffs = 0

    while queue:
        marking, trace, tau_steps = queue.popleft()
        state_key = (marking_key(marking, places), trace)
        previous_tau_steps = best_tau_for_state.get(state_key)
        if previous_tau_steps is not None and previous_tau_steps <= tau_steps:
            continue
        best_tau_for_state[state_key] = tau_steps

        # This is deliberately exact equality, including all token counts.
        if marking == final_marking:
            completed.add(trace)

        enabled = pm4py.get_enabled_transitions(net, marking)
        ordered_enabled = sorted(
            enabled,
            key=lambda transition: (
                str(getattr(transition, "label", None)),
                str(getattr(transition, "name", "")),
            ),
        )
        for transition in ordered_enabled:
            label = getattr(transition, "label", None)

            if label is None:
                if tau_steps >= max_tau_steps:
                    silent_cutoffs += 1
                    continue
                next_trace = trace
                next_tau_steps = tau_steps + 1
            else:
                if len(trace) >= max_visible_length:
                    visible_cutoffs += 1
                    continue
                next_trace = trace + (label,)
                if (
                    label == CONFIGURE_LABEL
                    and next_trace.count(CONFIGURE_LABEL) > max_loop_iterations
                ):
                    loop_cutoffs += 1
                    continue
                next_tau_steps = 0

            next_marking = semantics.execute(transition, net, marking)
            if next_marking is None:
                # This should not happen for an enabled transition, but it is
                # safer to record the anomaly than to treat it as completion.
                print("transition execution returned None:", transition)
                continue
            queue.append((next_marking, next_trace, next_tau_steps))

    return {
        "traces": frozenset(completed),
        "explored_states": len(best_tau_for_state),
        "silent_cutoffs": silent_cutoffs,
        "visible_cutoffs": visible_cutoffs,
        "loop_cutoffs": loop_cutoffs,
        # The trace set is exhaustive for the requested visible and loop
        # bounds. A silent cutoff means even that bounded set may be incomplete.
        "exhaustive_under_bound": silent_cutoffs == 0,
        "max_visible_length": max_visible_length,
        "max_loop_iterations": max_loop_iterations,
        "max_tau_steps_per_visible_segment": max_tau_steps,
    }


POSITIVE_WITNESSES = {
    "skip legal, one iteration": (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
    "legal before verification": (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Legal Review",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
    "verification before legal": (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Legal Review",
        "Release Change",
        "Archive Change",
    ),
    "two iterations": (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Correct Defect",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
}

NEGATIVE_WITNESSES = {
    "release without verification": (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Release Change",
        "Archive Change",
    ),
    "verification before evidence": (
        "Register Change",
        "Assess Risk",
        "Configure Trial",
        "Inspect Trial",
        "Prepare Evidence",
        "Release Change",
        "Archive Change",
    ),
    "correct defect inside first body": (
        "Register Change",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Correct Defect",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
    "legal before assessment": (
        "Register Change",
        "Legal Review",
        "Assess Risk",
        "Prepare Evidence",
        "Configure Trial",
        "Inspect Trial",
        "Release Change",
        "Archive Change",
    ),
}


def report_witnesses(name, exploration):
    traces = exploration["traces"]
    for witness_name, trace in POSITIVE_WITNESSES.items():
        print(
            name,
            "positive",
            witness_name,
            "PASS" if trace in traces else "MISMATCH",
        )
    for witness_name, trace in NEGATIVE_WITNESSES.items():
        print(
            name,
            "negative",
            witness_name,
            "PASS" if trace not in traces else "MISMATCH",
        )


def reachability_summary(net, im, fm):
    try:
        graph = pm4py.convert_to_reachability_graph(net, im, fm)
        states = getattr(graph, "states", None)
        transitions = getattr(graph, "transitions", None)
        return {
            "state_count": len(states) if states is not None else None,
            "transition_count": (
                len(transitions) if transitions is not None else None
            ),
        }
    except Exception as exc:
        return f"reachability conversion failed: {type(exc).__name__}: {exc}"


def optional_model_playout(name, net, im, fm):
    # play_out is version-dependent. Use it only when the installed PM4Py
    # exposes it, and report an exception instead of treating it as proof.
    play_out = getattr(pm4py, "play_out", None)
    if not callable(play_out):
        print(name, "play_out not available in this PM4Py version")
        return
    try:
        log = play_out(net, im, fm)
        print(name, "play_out trace count=", len(log))
    except Exception as exc:
        print(name, "play_out failed:", type(exc).__name__, exc)


baseline = bounded_visible_traces(
    net_from_powl,
    im_from_powl,
    fm_from_powl,
)
print("baseline exploration:", baseline)
report_witnesses("net_from_powl", baseline)

baseline_footprints = None
try:
    baseline_footprints = pm4py.discover_footprints(
        net_from_powl, im_from_powl, fm_from_powl
    )
except Exception as exc:
    print("baseline footprints failed:", type(exc).__name__, exc)

baseline_reachability = reachability_summary(
    net_from_powl, im_from_powl, fm_from_powl
)
print("baseline reachability:", baseline_reachability)
optional_model_playout("net_from_powl", net_from_powl, im_from_powl, fm_from_powl)


def soundness_result(net, im, fm):
    try:
        return pm4py.check_soundness(
            net, im, fm, print_diagnostics=False
        )
    except Exception as exc:
        return f"soundness failed: {type(exc).__name__}: {exc}"


for name, (net, im, fm) in roundtripped_nets.items():
    candidate = bounded_visible_traces(net, im, fm)
    print("\nROUND-TRIP COMPARISON:", name)
    print("candidate exploration:", candidate)
    report_witnesses(name, candidate)
    print("bounded trace sets equal:", candidate["traces"] == baseline["traces"])
    print(
        "soundness baseline/candidate:",
        soundness_result(net_from_powl, im_from_powl, fm_from_powl),
        soundness_result(net, im, fm),
    )

    try:
        candidate_footprints = pm4py.discover_footprints(net, im, fm)
        print(
            "footprints equal:",
            candidate_footprints == baseline_footprints,
        )
    except Exception as exc:
        print("candidate footprints failed:", type(exc).__name__, exc)

    candidate_reachability = reachability_summary(net, im, fm)
    print("baseline/candidate reachability:", baseline_reachability, candidate_reachability)
    optional_model_playout(name, net, im, fm)

    if candidate["traces"] != baseline["traces"]:
        print("REJECT: bounded visible behavior differs")
    elif not candidate["exhaustive_under_bound"] or not baseline["exhaustive_under_bound"]:
        print("QUARANTINE: silent cutoff prevents an exhaustive bounded comparison")
    else:
        print(
            "bounded comparison passes; it is exhaustive only for visible length "
            f"<={MAX_VISIBLE_LENGTH}, Configure Trial iterations "
            f"<={MAX_LOOP_ITERATIONS}, and the chosen silent-step cap"
        )
```

The trace-set comparison is exhaustive under the chosen visible-length and loop-iteration bounds when no silent cutoff occurs. It is not an exhaustive proof for arbitrary trace lengths or arbitrary loop counts. Reachability-state counts are useful diagnostics but are not a graph-isomorphism proof because conversion may rename or insert internal places. Footprints provide a coarser independent check. Soundness is necessary, not sufficient, for source-semantic equivalence.

# 6. Visual-Semantics Review

A BPMN rendering can be behaviorally acceptable while being visually misleading. A parallel gateway should communicate that the branches are enabled independently and that the downstream join waits for both; however, a crowded drawing may make one branch appear to follow the other. The `A`/`P` split and the optional-legal/verification relationship are especially vulnerable to this misreading.

An exclusive gateway can correctly represent the `Legal Review`/silent-skip XOR, but a diagram may show only the labeled branch and hide the skip route in a way that looks mandatory. The silent route is semantically real even though it has no visible activity. It should be labeled, for example, `skip legal review (tau)`, or documented in a legend as the branch that completes the legal gate without a visible task.

The loop can be drawn with a BPMN loop marker, an explicit gateway, or a back edge. These renderings do not necessarily make clear that the first child is `Configure Trial → Inspect Trial`, that `Correct Defect` is the redo action, and that at least one body execution is required. An annotation such as `one or more: Configure Trial → Inspect Trial; repeat only via Correct Defect` prevents the loop from being read as zero-or-more or as an unconstrained cycle.

Gateway shapes and unlabeled routing nodes may also be mistaken for business activities. Every routing-only node should be marked as a gateway or explicitly labeled `routing only`; every visible task should retain its source label. The diagram should state that gateway labels and positions are explanatory, not additional source activities.

Finally, graph layout is not execution order. A node drawn higher, farther left, or on a visually dominant horizontal path is not thereby a predecessor. The diagram documentation should include the source invariant table, identify parallel splits and joins, state that both legal/verification interleavings are permitted, and link the BPMN artifact to its accepting-net validation report. A legend should distinguish visible activities, tau routes, parallel gateways, exclusive gateways, joins, and loop-back edges.

# 7. Rejection Criteria

Reject or quarantine a conversion result if any of the following occurs:

1. A conversion raises an exception, returns no model, or returns a net without a non-null initial or final marking.
2. `pm4py.check_is_workflow_net` fails, or `pm4py.check_soundness` reports unsoundness, deadlock, improper completion, or an unreachable required completion.
3. A required negative witness is accepted, especially release before verification, verification before `Prepare Evidence`, `Correct Defect` inside the first trial body, or legal review before `Assess Risk`.
4. A required positive witness is rejected, including either legal-before-verification or verification-before-legal interleaving.
5. The result admits `Release Change` before both the verification loop and the optional-legal branch have completed, including completion through the silent skip.
6. The optional legal branch is collapsed into a mandatory visible `Legal Review`, removed entirely, or exposed as an unintended visible tau activity.
7. The binary loop admits zero trial iterations, allows `Inspect Trial` before `Configure Trial`, or permits `Correct Defect` outside the boundary between completed and repeated trial bodies.
8. Exact final-marking comparison fails for a purported completed trace, even if the trace ends at a visually plausible BPMN end event.
9. Activity labels are duplicated, changed, or mapped inconsistently enough that visible-trace or footprint comparison cannot identify source activities unambiguously.
10. Footprints or bounded visible traces differ from the POWL-derived net, or a silent cutoff makes the claimed bounded comparison incomplete.
11. A process-tree conversion succeeds syntactically but its generated BPMN changes any source invariant; a successful tree object is not a waiver of the audit.
12. The only evidence of fidelity is object serialization, a successful save call, or a visually attractive diagram without behavioral diagnostics.

# 8. Canonical Representation Recommendation

Store the source POWL as the authoritative canonical model. It states the partial-order intent directly: the absence of an edge is meaningful, tau optionality is explicit, and the loop body and redo action are named separately. Store the accepting Petri net as a generated, versioned execution artifact with its initial and final markings. Generate BPMN from that net for stakeholder visualization.

The direct `POWL → accepting Petri net → BPMN` artifact should be the primary visualization route. A process tree may be cached as a derivative only when conversion succeeds and its tree-to-BPMN result passes the same soundness, footprint, witness, bounded-trace, and exact-final-marking checks. If process-tree conversion fails, retain the exception and do not use an invented tree as a canonical substitute.

Each derivative should carry the source model version or hash, PM4Py version, conversion route, initial and final markings, workflow-net and soundness results, visible-label inventory, witness results, footprint comparison, bounded exploration parameters, and any silent-cutoff or visualization warnings. A BPMN file without this evidence is a presentation artifact, not an authority.

Future edits should be made to POWL and then regenerate the net and BPMN artifacts. Do not edit the generated BPMN and round-trip it back as the source. If a stakeholder requires a BPMN change, translate the requested semantic change into a POWL edit, rerun conversion and validation, and retain old derivatives for comparison. This prevents gateway placement, layout, or serialization details from introducing round-trip drift.

# 9. Residual Uncertainty

- Passing the bounded trace exploration does not prove equivalence for unbounded visible traces, more than three verification iterations, or silent paths longer than the selected cap.
- A set of accepted interleavings does not by itself prove true concurrency or independence. Two models can admit the same finite traces while imposing different causal/resource structure.
- Soundness and matching footprints do not prove that every source invariant is preserved; they are necessary diagnostics with limited resolution.
- A BPMN image can still be misread because of layout, gateway placement, hidden routing nodes, or an ambiguous loop marker even when its converted net passes the behavioral tests.
- Exact final-marking equality validates the tested accepting-net semantics, but it does not establish that every BPMN end event was rendered or documented with the intended stakeholder meaning.
- A process-tree conversion that happens to succeed may rely on PM4Py-version-specific decomposition choices; without a stable conversion and regression corpus, future versions can introduce semantic or naming drift.
