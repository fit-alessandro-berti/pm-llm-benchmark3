# 1. Executive Verdict

The given Petri net is structurally a workflow net: it possesses a unique source place (`source`), a unique sink place (`sink`), and every place and transition lies on a directed path from `source` to `sink`.

However, the net is **unsound**. The principal defect is an asymmetric synchronization flaw: while `t_split` initiates concurrent execution across two branches (`p_analysis` and `p_review`), the silent transition `t_join_waived` consumes only from `p_waived`, omitting synchronization with the mandatory analysis branch (`p_analysis_done`).

This defect causes two critical business failures:
1. **Premature Authorization**: When a review waiver is recorded, `t_authorize` can fire and mark `sink` before `t_analyze` is performed (or even started), violating the mandatory analysis business policy.
2. **Improper Completion / Dead Tokens**: Stranded tokens remain indefinitely in `p_analysis` or `p_analysis_done` after authorization, violating proper completion.

### Detailed Structural Discussion
The net satisfies all structural criteria of a classical Workflow Net (WF-net):
1. There is a single source place `source` with $in(source) = \emptyset$.
2. There is a single sink place `sink` with $out(sink) = \emptyset$.
3. Every node $x \in P \cup T$ is on a directed path from `source` to `sink`.

The structural failure arises from an **AND-split / XOR-join balance violation**. The AND-split transition `t_split` increments the total token count to 2 (one in `p_analysis`, one in `p_review`). The standard path uses a balanced 2-input AND-join (`t_join_normal`), reducing the token count from 2 to 1 at `p_decision`. However, the waiver path uses a 1-input transition (`t_join_waived`), consuming only the token in `p_waived` while leaving the concurrent token in the analysis branch unconsumed. In the coverability analysis of S-components, places `p_analysis` and `p_analysis_done` are not covered by any valid S-component containing `t_join_waived`, leading to unsoundness.

# 3. Marking-Based Counterexample

### Primary Counterexample: Premature Authorization & Improper Completion
**Firing Sequence**: $\sigma_1 = \langle \text{t\_register}, \text{t\_split}, \text{t\_waive_review}, \text{t\_join\_waived}, \text{t\_authorize}, \text{t\_analyze} \rangle$

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| :---: | :--- | :--- | :--- | :--- |
| 0 | *(Initial state)* | `[source: 1]` | `{t_register}` | Initial marking $im$ established. |
| 1 | `t_register` | `[p_ready: 1]` | `{t_split}` | Case registered. |
| 2 | `t_split` | `[p_analysis: 1, p_review: 1]` | `{t_analyze, t_standard_review, t_waive_review}` | Tokens created in both parallel branches. |
| 3 | `t_waive_review` | `[p_analysis: 1, p_waived: 1]` | `{t_analyze, t_join_waived}` | Waiver path selected; `p_review` consumed. |
| 4 | `t_join_waived` | `[p_analysis: 1, p_decision: 1]` | `{t_analyze, t_authorize}` | `t_join_waived` fires without waiting for `t_analyze`. |
| 5 | `t_authorize` | `[p_analysis: 1, sink: 1]` | `{t_analyze}` | **Critical Symptom 1 (Premature Authorization)**: A token exists in `sink`, but $M_5 \neq fm$. Authorization occurred before analysis even executed! |
| 6 | `t_analyze` | `[p_analysis_done: 1, sink: 1]` | $\emptyset$ | **Critical Symptom 2 (Deadlock / Dead Token)**: Analysis executes post-authorization. Terminal state reached with an unconsumable leftover token. |

### Secondary Counterexample: Analysis Completed, Stranded Dead Token
**Firing Sequence**: $\sigma_2 = \langle \text{t\_register}, \text{t\_split}, \text{t\_analyze}, \text{t\_waive_review}, \text{t\_join\_waived}, \text{t\_authorize} \rangle$

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| :---: | :--- | :--- | :--- | :--- |
| 0 | *(Initial state)* | `[source: 1]` | `{t_register}` | Initial marking $im$. |
| 1 | `t_register` | `[p_ready: 1]` | `{t_split}` | Case registered. |
| 2 | `t_split` | `[p_analysis: 1, p_review: 1]` | `{t_analyze, t_standard_review, t_waive_review}` | Tokens spawned in both concurrent branches. |
| 3 | `t_analyze` | `[p_analysis_done: 1, p_review: 1]` | `{t_standard_review, t_waive_review}` | Mandatory analysis completed. |
| 4 | `t_waive_review` | `[p_analysis_done: 1, p_waived: 1]` | `{t_join_waived}` | Waiver recorded. |
| 5 | `t_join_waived` | `[p_analysis_done: 1, p_decision: 1]` | `{t_authorize}` | `t_join_waived` fires, ignoring `p_analysis_done`. |
| 6 | `t_authorize` | `[p_analysis_done: 1, sink: 1]` | $\emptyset$ | **Terminal Deadlock**: Token reaches `sink`, but leftover token in `p_analysis_done` cannot be consumed. |

### Distinction Between "Token in Sink" vs. "Proper Final Marking $fm$"
Classical soundness requires two conditions upon process completion:
1. **Option to complete**: From any reachable marking $M$, the final marking $fm = [\text{sink}: 1]$ is reachable ($M \xrightarrow{*} fm$).
2. **Proper completion**: For any reachable marking $M$, if $M(\text{sink}) \ge 1$, then $M = fm$.

In both sequences $\sigma_1$ and $\sigma_2$, the net reaches a marking containing a token in `sink`, but $M \neq fm$ because of the extra token in $p\_analysis$ ($M_5$ in $\sigma_1$) or $p\_analysis\_done$ ($M_6$ in $\sigma_1$ and $\sigma_2$).

### Why Leftover Tokens Cannot Be Consumed
- The token in `p_analysis_done` requires `t_join_normal` for consumption.
- `t_join_normal` requires an input token from `p_review_done`.
- Because `p_review` was already consumed by `t_waive_review`, `p_review_done` will never receive a token.
- Therefore, `t_join_normal` is permanently dead at marking `[p_analysis_done: 1, sink: 1]`, leaving the token stranded forever.

# 4. Minimal-Repair Alternatives

### Edit-Cost Model Definition
We define an elementary Graph Edit Distance (GED) cost model:
$$\text{Cost} = \Delta P + \Delta T + \Delta F$$
where $\Delta P$ is the number of added/removed places, $\Delta T$ is the number of added/removed transitions, and $\Delta F$ is the number of added/removed directed arcs (each elementary insertion or deletion costs 1 unit).

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Repair 1: Synchronized Dual Join** *(Arc-minimal)* | Add 1 arc:<br>• `petri_utils.add_arc_from_to(p_analysis_done, join_waived, net)` | **1 edit**<br>($0\,\Delta P + 0\,\Delta T + 1\,\Delta F$) | Fully preserves business policy: analysis is strictly mandatory on both standard and waiver paths; authorization requires both analysis and review/waiver completion. | Forces `t_join_waived` to wait for `p_analysis_done`. Prevents premature authorization and eliminates dead tokens on the waiver route. | Introduces structural redundancy: `t_join_normal` and `t_join_waived` are duplicate silent joins with identical post-conditions and isomorphic synchronization logic. |
| **Repair 2: Unified Review Synchronization** *(State-minimal)* | 1. Add arc `(t_waive_review, p_review_done)`<br>2. Remove arcs: `(t_waive_review, p_waived)`, `(p_waived, t_join_waived)`, `(t_join_waived, p_decision)`<br>3. Remove place `p_waived`<br>4. Remove transition `t_join_waived` | **6 edits**<br>($1\,\Delta P + 1\,\Delta T + 4\,\Delta F$) | Fully preserves business policy: analysis is strictly mandatory; both review outcomes merge into a single review-completed place before joint synchronization. | Unifies synchronization into single join transition `t_join_normal`; eliminates `p_waived` and `t_join_waived`; produces a smaller, canonical state space. | Collapses distinct review outcomes into a single place (`p_review_done`), requiring process mining to rely on transition labels (`Record Review Waiver` vs. `Perform Standard Review`) rather than place marking. |
| **Repair 3: Policy Change: Fast-Track Waiver Bypasses Analysis** *(Policy-altering)* | 1. Rewire `t_waive_review` input from `p_ready` instead of `p_review`<br>2. Rewire `t_waive_review` output to `p_decision`<br>3. Remove `p_waived`, `t_join_waived`, and their 3 connecting arcs | **7 edits**<br>($1\,\Delta P + 1\,\Delta T + 5\,\Delta F$) | **Alters policy**: Analysis is no longer mandatory; recording a waiver acts as an emergency fast-track that bypasses analysis and review altogether. | Cases with a review waiver never execute `t_analyze`; authorization can occur immediately after case registration. | High business/regulatory compliance risk: cases are authorized without any analysis, violating the original policy mandate. |

### Minimality Justification
- Under the Graph Edit Distance metric, **Repair 1 is strictly minimal with an edit cost of 1**. No sound repair that retains mandatory analysis can have a cost of 0. Adding the single arc `(p_analysis_done, join_waived)` turns `t_join_waived` into a proper 2-input AND-join, immediately resolving the AND/XOR mismatch with zero node modifications.
- **Repair 2 has an edit cost of 6**, but achieves **structural minimality** in the final artifact: it reduces the net by 1 place and 1 transition, and reduces the reachability graph from 10 states to 8 states without any loss of business intent.

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils


def fire_transition_safely(target_net, current_marking, transition_name):
    """Helper to safely fire a named transition along a sequence, checking enabledness."""
    t_obj = next((t for t in target_net.transitions if t.name == transition_name), None)
    if t_obj is None:
        raise ValueError(f"Transition '{transition_name}' does not exist in net.")
    
    enabled_transitions = pm4py.get_enabled_transitions(target_net, current_marking)
    if t_obj not in enabled_transitions:
        enabled_names = [t.name for t in enabled_transitions]
        raise RuntimeError(
            f"Cannot fire '{transition_name}': not enabled in marking {dict(current_marking)}. "
            f"Enabled transitions: {enabled_names}"
        )
    
    new_marking = Marking(current_marking)
    for in_arc in t_obj.in_arcs:
        new_marking[in_arc.source] -= in_arc.weight
        if new_marking[in_arc.source] == 0:
            del new_marking[in_arc.source]
    for out_arc in t_obj.out_arcs:
        new_marking[out_arc.target] = new_marking.get(out_arc.target, 0) + out_arc.weight
    
    marking_str = ", ".join(f"{p.name}: {c}" for p, c in sorted(new_marking.items(), key=lambda x: x[0].name))
    print(f"  Fired {t_obj.name} ({t_obj.label}) -> Marking: {{{marking_str}}}")
    return new_marking
```

# 7. Repair Trade-Offs and Residual Risks

### 1. Distinguishability of Waiver vs. Standard Review
In Petri net workflow modeling, execution events are recorded with their transition labels in the event log (`t_standard_review: "Perform Standard Review"` vs. `t_waive_review: "Record Review Waiver"`). Even though both branches synchronize with mandatory analysis:
- In **Repair 1**, the two outcomes remain topologically separate through distinct places (`p_review_done` vs. `p_waived`) and distinct join transitions (`t_join_normal` vs. `t_join_waived`).
- In **Repair 2**, the places merge into `p_review_done`, but full distinguishability is preserved in process mining audit logs via transition activity labels.

### 2. Duplicate Behavior and Silent Transitions
- In **Repair 1**, `t_join_normal` and `t_join_waived` are two silent transitions with identical post-conditions (`p_decision`) and identical pre-condition structures (both consume `p_analysis_done` alongside their respective review outcome). While behaviorally correct, this introduces minor tau-transition redundancy.
- In **Repair 2**, this redundancy is removed by routing both review transitions directly into `p_review_done`, eliminating `t_join_waived` completely.

### 3. Soundness vs. Business Rule Alignment
Mathematical soundness proves absence of deadlocks, absence of dead transitions, and proper completion to $fm$. However, **soundness alone does not prove business rule compliance**. For example, Repair 3 (bypassing analysis under waiver) is mathematically sound, but directly violates the business policy requiring mandatory analysis. Soundness must always be paired with declarative conformance verification.

### 4. Regression Testing Suite
A robust regression test suite should validate the following test vectors:

- **Positive Conforming Traces (Must Replay Successfully to $fm$)**:
  1. $\langle \text{Register Case}, \text{Perform Analysis}, \text{Perform Standard Review}, \text{Authorize Case} \rangle$
  2. $\langle \text{Register Case}, \text{Perform Standard Review}, \text{Perform Analysis}, \text{Authorize Case} \rangle$
  3. $\langle \text{Register Case}, \text{Perform Analysis}, \text{Record Review Waiver}, \text{Authorize Case} \rangle$
  4. $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Perform Analysis}, \text{Authorize Case} \rangle$

- **Negative Non-Conforming Traces (Must Fail Replay / Rejection Required)**:
  1. $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Authorize Case} \rangle$ *(Analysis bypassed)*
  2. $\langle \text{Register Case}, \text{Perform Standard Review}, \text{Authorize Case} \rangle$ *(Analysis bypassed)*
  3. $\langle \text{Register Case}, \text{Perform Analysis}, \text{Authorize Case} \rangle$ *(Review/Waiver bypassed)*
  4. $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Perform Standard Review}, \text{Perform Analysis}, \text{Authorize Case} \rangle$ *(Duplicate review)*

### 5. Detecting Accidental Bypass of Mandatory Analysis
In production logs, compliance can be continuously monitored using:
- **Declarative LTL Constraints**:
  - $\text{Response}(\text{"Register Case"}, \text{"Perform Analysis"})$
  - $\text{Precedence}(\text{"Perform Analysis"}, \text{"Authorize Case"})$
- **Alignment-Based Conformance Checking**: Replaying non-compliant traces against the repaired net will immediately flag missing tokens on `p_analysis_done` or unconsumed tokens on `p_analysis`.

# 8. Final Recommendation

### Primary Deployment Choice: Repair 1 (Synchronized Dual Join)
For immediate operational deployment, **Repair 1** is the recommended solution. Under the graph edit distance model, it achieves the absolute minimal edit cost ($\text{Cost} = 1$) by adding a single synchronization arc `(p_analysis_done, t_join_waived)`. This hotfix carries the lowest change risk and zero schema churn: it preserves all existing places (`p_waived`, `p_review_done`) and transitions, guaranteeing backward compatibility with external audit monitors or sub-process state observers that query marking topology. It strictly enforces mandatory analysis on all execution paths and restores full classical soundness.

### Fallback Choice: Repair 2 (Unified Review Synchronization)
If the workflow net is undergoing structural refactoring or model clean-up, **Repair 2** is the recommended fallback. While requiring an edit cost of 6, it eliminates structural redundancy by merging `p_waived` and `t_join_waived` into the canonical `p_review_done` place and single `t_join_normal` transition. This produces a compact reachability graph (8 states vs. 10) and avoids duplicate silent joins, while preserving full audit-trail distinguishability through transition activity labels.
