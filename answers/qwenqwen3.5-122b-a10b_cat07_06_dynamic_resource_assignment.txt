# 1. Objectives and constraints

This policy prioritizes sustainable performance over raw speed. It distinguishes between non-negotiable safety/compliance rules and flexible optimization goals that require trade-off management.

### Hard Constraints (Safety & Compliance)
These constraints cannot be violated without triggering an exception workflow.
1.  **Skill Thresholds:**
    *   **Security Review:** Requires Skill Level 3, OR Skill Level 1–2 with explicit supervision by R7_Gita or R8_Hugo.
    *   **Final Approval:** Requires Skill Level 2–3. Skill Level 1 may prepare documentation but cannot finalize.
    *   **High Priority Cases:** Must be assigned to Skill Level  2 unless direct supervision is confirmed.
2.  **Workload Caps:** No resource receives more than 4 new assignments in the current batch.
3.  **Overtime Protection:** Do not assign new work to resources with `overtime_risk="high"` (R2, R4, R9) unless the case is Urgent AND no other qualified resource is available.
4.  **Batching Rules:** Quality Check activities may only be batched if Priority is Normal/Low AND SLA Time Remaining > 24 hours.

### Soft Constraints (Optimization Trade-offs)
These objectives are scored; conflicts are resolved by weighted priority.
1.  **SLA Adherence:** Minimize risk of missing deadlines (higher weight for shorter SLA time remaining).
2.  **Continuity:** Prefer the current owner to minimize handover costs, unless the current owner lacks necessary skill or poses an overtime risk.
3.  **Fairness:** Distribute workload evenly across teams and individuals to prevent burnout.
4.  **Skill Development:** At least 20% of Normal/Low priority assignments must align with a resource’s `training_priority`, provided SLA risk is acceptable.
5.  **Resilience:** Avoid creating single points of failure (bottlenecks) by balancing assignments among specialists.

# 2. Assignment policy

The policy uses a **Multi-Criteria Decision Analysis (MCDA)** approach. For each case, eligible resources are filtered, scored, and ranked.

### Algorithm Pseudocode

```text
FOR EACH Case C in Queue:
    1. FILTER ELIGIBILITY:
       - Identify resources with Skill >= Required_Skill.
       - IF Activity == 'Security Review':
           - Require Skill 3 OR (Skill 1-2 AND Supervisor in {R7, R8}).
       - IF Activity == 'Final Approval':
           - Require Skill >= 2.
       - IF Case Priority == 'Urgent' OR 'High':
           - Remove resources with Skill < 2 (unless supervised).
       - IF Resource.ot_risk == 'High':
           - Remove resource UNLESS Case.Priority == 'Urgent' AND No other option.
       - IF Resource.new_assignments_in_batch >= 4:
           - Remove resource.

    2. SCORE CANDIDATES (Weighted Sum):
       - SLA_Urgency_Score: Inverse of (SLA_Time_Remaining / Avg_Service_Time).
         (Higher score = Closer to deadline).
       - Skill_Match_Score: (Resource_Skill - Required_Skill). 
         (Bonus for exact match, penalty for over-skilling if bottleneck).
       - Continuity_Score: +10 if Resource == Current_Owner.
         (-5 penalty if Resource != Current_Owner AND Handover_Cost == 'High').
       - Workload_Fairness_Score: Inverse of (Current_Open_Cases + New_Assignments).
       - Training_Score: +5 if Resource.Training_Priority == Required_Activity AND Case.Priority != 'Urgent'.
       - Resilience_Score: Penalty if assigning to a unique specialist (e.g., only R7/R8 for Security).

       Total_Score = (w1*SLA) + (w2*Skill) + (w3*Cont) + (w4*Load) + (w5*Train) + (w6*Res)

    3. SELECT BEST:
       - Pick Resource with Highest Total_Score.
       - TIE-BREAKER: Lowest Current_Open_Cases.

    4. UPDATE STATE:
       - Increment Resource.new_assignments_in_batch.
       - Record Assignment Reason.

    5. TRAINING QUOTA CHECK:
       - After processing all Normal/Low cases, ensure >= 20% selected Training_Score > 0.
       - If not met, swap lowest SLA-risk Normal/Low assignments to Training-aligned resources.
```

### Exception Handling
*   **Bottleneck Detected:** If a specialist (e.g., R7/R8 for Security) reaches capacity, force-supervise a junior (Skill 1-2) if available.
*   **SLA Breach Imminent:** Override Workload and Training scores; assign to any available skilled resource immediately.

**Reasoning:**
First-available maximizes short-term speed but degrades quality and employee well-being. Specialist-only ensures quality but starves the system of flow. The proposed policy accepts slightly longer assignment times to secure sustainability, compliance, and workforce development.

# 6. Process-mining audit indicators

To verify the policy is working as intended, we track the following indicators using the event log:

1.  **Handover Frequency:**
    *   *Metric:* Count of `reassignment_count` increments per case.
    *   *Target:* < 2 for Normal cases; < 1 for High Priority.
    *   *PM4Py:* `pm4py.discover_handover_of_work_network(log)` to visualize flows.
2.  **Skill Mismatch Rate:**
    *   *Metric:* % of events where `org:resource` skill < `required_skill` (without supervision flag).
    *   *Target:* 0%.
    *   *PM4Py:* Join log with resource matrix; filter violations.
3.  **Workload Distribution Variance:**
    *   *Metric:* Standard deviation of `current_open_cases` across resources post-assignment.
    *   *Target:* Minimized variance compared to previous batches.
    *   *PM4Py:* `pm4py.get_variants()` grouped by `org:resource`.
4.  **Overtime Risk Exposure:**
    *   *Metric:* % of total case volume assigned to resources flagged `overtime_risk="high"`.
    *   *Target:* < 5% (only for Urgent exceptions).
5.  **SLA Miss Rate:**
    *   *Metric:* % of cases where `time:timestamp` completion > `sla_deadline`.
    *   *Target:* < 5%.
    *   *PM4Py:* `pm4py.filter_case_performance(log, min_time=...)`.
6.  **Training Assignment Share:**
    *   *Metric:* % of Normal/Low priority cases assigned to resources where `assignment_reason` == 'training'.
    *   *Target:*  20%.
    *   *PM4Py:* Filter by `case_priority` and `assignment_reason`.
7.  **Specialist Bottleneck Indicator:**
    *   *Metric:* Average waiting time for Security/Approval activities compared to average process time.
    *   *Target:* Waiting time < 20% of total cycle time.
    *   *PM4Py:* `pm4py.discover_performance_dfg(log)`.
8.  **Deviation from Policy:**
    *   *Metric:* Count of manual overrides recorded in `assignment_reason` field.
    *   *Target:* Track frequency to tune policy weights.
