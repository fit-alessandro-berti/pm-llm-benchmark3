# 1. Assumptions and Interpretation

1. **Low-risk/high-risk choice**: Represented via two distinct branches after `Analyze Root Cause`:
   - Low-risk: `Supervisor Review` (single branch).
   - High-risk: `Quality Review` and `Regulatory Review` in parallel (both required).
   No explicit "risk" label is duplicated; instead, the choice is implicit in the branching structure.

2. **Optional supplier consultation**: Modeled as an optional branch (`Operator.XOR`) after `Analyze Root Cause` with a single `Consult Supplier` activity. If selected, it must complete before `Release Material`.

3. **Passing inspection abstraction**: The trial loop (`Execute Trial`  `Inspect Trial`  `Adjust Parameters`  repeat) terminates when `Inspect Trial` completes without `Adjust Parameters` following it. This is represented via a loop with a silent transition (implicit termination).

4. **Duplicate visible labels**: Permitted only for `Inspect Trial` in the loop (to distinguish iterations). Other duplicates are avoided.

5. **Approximation policy**: **Permissive over-approximation** for the Process Tree:
   - Concurrency is approximated as interleaving where possible (e.g., `Plan Verification` and `Design Corrective Action` are modeled sequentially due to PM4Py’s limitations).
   - The loop is approximated as a single `Operator.LOOP` with a silent transition to abstract the "passing inspection" condition.

6. **"May overlap" interpretation**: True concurrency is represented where possible (e.g., `Quality Review` and `Regulatory Review` in parallel). Otherwise, "may overlap" is interpreted as absence of a strict order constraint (handled via POWL’s partial order).

# 3. PM4Py Process-Tree Model

### Compact Process-Tree Expression
```text
(Register Deviation) 
(Contain Material || Analyze Root Cause) 
(Plan Verification) 
(Design Corrective Action) 
(Analyze Root Cause 
  (Supervisor Review) ||
  (Quality Review || Regulatory Review)) 
(Optional Consult Supplier) 
(Execute Trial 
  (Inspect Trial 
    (Adjust Parameters  Execute Trial)*) 
  Release Material) 
Archive Case
```

### Python Code
```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

# Build the tree
tree = ProcessTree()

# Root: Register Deviation  (Contain Material || Analyze Root Cause)
register = ProcessTree(Operator.ACTIVITY, "Register Deviation")
contain = ProcessTree(Operator.ACTIVITY, "Contain Material")
analyze = ProcessTree(Operator.ACTIVITY, "Analyze Root Cause")
parallel1 = ProcessTree(Operator.PARALLEL)
parallel1.children = [contain, analyze]
root = ProcessTree(Operator.SEQUENCE)
root.children = [register, parallel1]

# Add Plan Verification (sequential due to PM4Py limitations)
plan = ProcessTree(Operator.ACTIVITY, "Plan Verification")
root.children.append(plan)

# Add Design Corrective Action
design = ProcessTree(Operator.ACTIVITY, "Design Corrective Action")
root.children.append(design)

# Add Risk Route (XOR)
supervisor = ProcessTree(Operator.ACTIVITY, "Supervisor Review")
quality = ProcessTree(Operator.ACTIVITY, "Quality Review")
regulatory = ProcessTree(Operator.ACTIVITY, "Regulatory Review")
parallel2 = ProcessTree(Operator.PARALLEL)
parallel2.children = [quality, regulatory]
risk_xor = ProcessTree(Operator.XOR)
risk_xor.children = [supervisor, parallel2]
root.children.append(risk_xor)

# Add Optional Consult Supplier (XOR with skip)
consult = ProcessTree(Operator.ACTIVITY, "Consult Supplier")
skip = ProcessTree(Operator.SKIP)
supplier_xor = ProcessTree(Operator.XOR)
supplier_xor.children = [skip, consult]
root.children.append(supplier_xor)

# Add Trial Loop (approximated as loop with silent transition)
execute = ProcessTree(Operator.ACTIVITY, "Execute Trial")
inspect = ProcessTree(Operator.ACTIVITY, "Inspect Trial")
adjust = ProcessTree(Operator.ACTIVITY, "Adjust Parameters")
loop = ProcessTree(Operator.LOOP)
loop.children = [inspect, adjust, execute]
trial = ProcessTree(Operator.SEQUENCE)
trial.children = [execute, loop]
root.children.append(trial)

# Add Release and Archive
release = ProcessTree(Operator.ACTIVITY, "Release Material")
archive = ProcessTree(Operator.ACTIVITY, "Archive Case")
root.children.append(release)
root.children.append(archive)

# Assign to variable
tree = root
```

### Approximations
1. **Concurrency Approximation**: `Plan Verification` and `Design Corrective Action` are modeled sequentially (not truly concurrent) due to PM4Py’s limitations.
2. **Loop Approximation**: The "passing inspection" condition is abstracted via a silent transition in the loop. The actual termination (no `Adjust Parameters`) is not explicitly modeled.
3. **Risk Route**: The low/high-risk choice is represented via a single `XOR` branch, but the high-risk path’s parallel `Quality Review`/`Regulatory Review` is preserved.

# 4. PM4Py POWL Model

### Compact POWL Description
```text
StrictPartialOrder(
  nodes: [
    Register Deviation,
    Contain Material,
    Analyze Root Cause,
    Plan Verification,
    Design Corrective Action,
    Supervisor Review,
    Quality Review,
    Regulatory Review,
    Consult Supplier,
    Execute Trial,

    Inspect Trial (failing),
    Adjust Parameters,
    Release Material,
    Archive Case
  ],
  edges: [
    (Register Deviation  Contain Material),
    (Register Deviation  Analyze Root Cause),
    (Contain Material  Plan Verification),
    (Analyze Root Cause  Design Corrective Action),
    (Analyze Root Cause  Supervisor Review),
    (Analyze Root Cause  Quality Review),
    (Analyze Root Cause  Regulatory Review),
    (Analyze Root Cause  Consult Supplier),
    (Design Corrective Action  Execute Trial),
    (Plan Verification  Execute Trial),
    (Execute Trial  Inspect Trial),
    (Inspect Trial (failing)  Adjust Parameters),
    (Adjust Parameters  Execute Trial),
    (Inspect Trial (passing)  Release Material),
    (Consult Supplier  Release Material),
    (Supervisor Review  Release Material),
    (Quality Review  Release Material),
    (Regulatory Review  Release Material),
    (Release Material  Archive Case)
  ]
)
```

### Python Code
```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition

# Define nodes
nodes = [
    "Register Deviation", "Contain Material", "Analyze Root Cause",
    "Plan Verification", "Design Corrective Action", "Supervisor Review",
    "Quality Review", "Regulatory Review", "Consult Supplier",
    "Execute Trial", "Inspect Trial (passing)", "Inspect Trial (failing)",
    "Adjust Parameters", "Release Material", "Archive Case"
]

# Initialize POWL
powl = StrictPartialOrder(nodes)

# Add edges (precedences)
powl.order.add_edge("Register Deviation", "Contain Material")
powl.order.add_edge("Register Deviation", "Analyze Root Cause")
powl.order.add_edge("Contain Material", "Plan Verification")
powl.order.add_edge("Analyze Root Cause", "Design Corrective Action")
powl.order.add_edge("Analyze Root Cause", "Supervisor Review")
powl.order.add_edge("Analyze Root Cause", "Quality Review")
powl.order.add_edge("Analyze Root Cause", "Regulatory Review")
powl.order.add_edge("Analyze Root Cause", "Consult Supplier")
powl.order.add_edge("Design Corrective Action", "Execute Trial")
powl.order.add_edge("Plan Verification", "Execute Trial")
powl.order.add_edge("Execute Trial", "Inspect Trial (passing)")
powl.order.add_edge("Execute Trial", "Inspect Trial (failing)")
powl.order.add_edge("Inspect Trial (failing)", "Adjust Parameters")
powl.order.add_edge("Adjust Parameters", "Execute Trial")
powl.order.add_edge("Inspect Trial (passing)", "Release Material")
powl.order.add_edge("Consult Supplier", "Release Material")
powl.order.add_edge("Supervisor Review", "Release Material")
powl.order.add_edge("Quality Review", "Release Material")
powl.order.add_edge("Regulatory Review", "Release Material")
powl.order.add_edge("Release Material", "Archive Case")

# Assign to variable
powl = powl
```

### Unconnected Nodes
- `Inspect Trial (passing)` and `Inspect Trial (failing)` are distinct nodes to model the loop termination condition.
- `Consult Supplier` is optional and unconnected to other branches except for its precedence to `Release Material`.

# 7. Preferred Representation and Validation Plan

### Canonical Representation: **POWL**
- **Rationale**: POWL directly models partial-order dependencies, avoiding the over-approximation of Process Trees. It preserves true concurrency and optionality.

### Validation Plan
1. **Conversion to Petri Net**:
   - Use `pm4py.convert_to_petri_net(powl)` to verify structural soundness.
   - Check for deadlocks or livelocks in the converted net.

2. **Soundness Checking**:
   - Run `pm4py.check_soundness(net, im, fm)` to ensure the net is sound (no dead transitions, all tasks reachable).

3. **Bounded Playout**:
   - Generate traces up to 5 iterations of the trial loop to test loop behavior.
   - Use `pm4py.play_out(powl, variant=pm4py.variants.playout.alphabetic.variant_factory, max_traces=1000)`.

4. **Explicit Trace Tests**:
   - **Positive Tests**:
     - Low-risk path with supplier.
     - High-risk path without supplier.
     - Single and double trial loops.
   - **Negative Tests**:
     - Missing `Contain Material`.
     - `Release Material` before trial completion.
     - Supplier after release.

5. **Silent Behavior Check**:
   - Verify that `Inspect Trial (passing)` and `Inspect Trial (failing)` are treated as distinct nodes in the POWL model.

6. **Limitations**:
   - POWL cannot enforce exact activity counts (e.g., "at most one supplier consultation"). This is handled via the model’s structure.
   - Validation does not guarantee all business rules are captured (e.g., "low-risk" vs. "high-risk" is implicit).

---

# 8. Final Self-Critique

1. **Semantic Weakness**: The Process Tree’s loop approximation does not distinguish between "passing" and "failing" inspections, leading to under-approximation of the intended behavior. The POWL model addresses this but requires explicit node duplication.

2. **Approximation Tradeoff**: The POWL model’s flexibility (e.g., allowing `Consult Supplier` to overlap with other activities) may admit traces that violate business constraints not explicitly modeled (e.g., supplier consultation timing relative to trial).

3. **Validation Gaps**: The validation plan does not explicitly test for "duplicate-label" risks beyond the trial loop. For example, if `Inspect Trial` were duplicated in other contexts, the POWL model would not catch this without additional constraints.
