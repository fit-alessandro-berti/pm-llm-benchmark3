The digital twin is an activity-level discrete-event model of the municipal permit process from portal submission through issue or rejection. It is used to compare policies under shared calendars, seasonal and day-of-week demand, and coupling between cases. It becomes decision-grade only after the baseline reproduces the 18-month log closely enough to pass the validation gates in section 6. Until then, rankings are diagnostic.

## 1. Model scope and state variables

**Boundary.** Inside the twin: case arrival and attributes; completeness and applicant document delay; planning, fire, and environmental review; statutory public notice; inspection scheduling and site visits; decision drafting; legal check; issue or rejection; rework and appeal-like repeats; staff calendars; and cross-case coupling through architects, districts, and latent objections.

Outside the boundary: political content of decisions, clause-level code checking, fee payment, post-permit construction, court proceedings after rejection, and consultant work other than a response-time distribution. Pre-submission effort is outside the municipal clock and is switched on only in D1, where it is reported as a separate applicant-time metric.

**Grain.** One case is one entity. Activities are the log labels, not checklist steps inside them. Documents, objections, and violations are attributes or latent flags. Resources are capacitated servers that work one case at a time and accumulate service in their own working hours. Public notice and applicant document return are timers, not staffed queues.

The simplified process tree is a control-flow sketch. The executable lifecycle is a guarded token model because the tree has no data conditions, no calendars, no join rule beyond its syntax, and no cross-case state. `Decision drafting` becomes enabled only when every branch that applies to that case has completed.

**Entities.** Case, architect, resource server, resource pool, district, inspection bundle, latent objection shock, calendar, queue, policy.

**Case state.**

- Identity and covariates: `case_id`, `case_type`, `district`, `architect_id`, `application_value`, `requires_fire`, `requires_environment`, `requires_public_notice`, `prior_violations` (often missing), `building_area` and `env_sensitive` (incomplete).
- Control state: current phase, attempt index per activity, which optional branches apply, set of branches still required before decision drafting, rework counts, skip-inspection flag, urgent flag.
- Latent state: objection shock id, no-show flag, rework cause class when the text is uncoded. These stay latent and are never written back into the historical log as if they had been observed.
- Time state: arrival timestamp, enablement time, start time, completion time per activity attempt, sampled working-time service, sampled external delay, travel component, censoring flag.
- Dependency state: `bundle_id`, architect workload key, district-week shock key.

**Resource and queue state.** Each pool has a headcount, a skill set, a weekly calendar, holiday dates, blackout weeks, and an effective-availability fraction. Each server has idle or busy status, the case it holds, and remaining working hours. Queues are per pool. Priority is FIFO in the baseline, with an aging lane only in D6. Queue state stores length, oldest arrival, and working-hour backlog.

Pools and provisional calendars, to be confirmed with HR:

| Pool | Capacity | When they work | Constraint the twin must keep |
| --- | --- | --- | --- |
| Clerks | 5 FTE | Mon–Fri 08:00–16:00 | On Monday one clerk is on portal support, so completeness capacity is 4 |
| Planners | 8 FTE | Mon–Fri 09:00–17:00 | Two planners accept only Simple renovation |
| Fire | 2 FTE | Tue–Thu, provisional 09:00–17:00 | No Monday or Friday fire capacity |
| Environment | 3 FTE | Mon–Fri | 40% of time is reserved, so offered permit capacity is 1.8 FTE |
| Inspectors | 4 FTE | Field Tue–Fri | Travel consumes inspector hours and depends on district; batching can cut travel and add wait |
| Legal | 2 FTE | Weekdays, except council weeks | Council weeks accept urgent cases only |
| System | Unlimited | Business release cycle | Used for portal receipt, public-notice start, and issue |
| Applicant / third party | Unlimited servers | Calendar time | Delay distributions, separate from staff service |

**Cross-case state.**

- Architects, especially the top 20 who account for 31% of cases, generate clustered arrivals and can have overlapping document-response delays.
- Inspection bundles group ready cases by district. A bundle reduces marginal travel and holds the earliest case until the bundle rule fires.
- A district-week objection shock lengthens public notice for cases whose notice windows overlap. The shock is inferred from duration clustering, because objection events are absent.
- Council weeks and holidays are shared calendars, so many cases stall together even when their other attributes are independent.
- Decision drafting waits for the case’s own applicable branches. Parallel reviews interact only by sharing planners, fire reviewers, environmental reviewers, and the later legal pool.

**Clocks.** Service is in working hours of the assigned pool. Waiting, statutory notice, applicant delay, and cycle time are in calendar time. A 14-hour planning review occupies a planner across more than one day because nights and weekends do not consume service. Inter-completion time from the log is a result of those clocks, not a substitute for them.

## 2. Parameter-estimation plan

Use the full 18-month log for estimation. The two-case excerpt is only a schema check. PM4Py handles log I/O, variant and DFG discovery, and the process-tree sketch. A separate estimation module turns those outputs into simulation parameters. PM4Py playout is not the twin: it has no resource calendars and no cross-case state.

**Log handling.**

- Read the extract with `pandas.read_csv` or build the excerpt with `pandas`. There is no `pm4py.read_csv`.
- Convert timestamps with `pandas.to_datetime`, then call `pm4py.format_dataframe` on `case:concept:name`, `concept:name`, and `time:timestamp`.
- Discover variants with `pm4py.get_variants`, the directly-follows graph with `pm4py.discover_dfg`, and the performance DFG with `pm4py.discover_performance_dfg`.
- Compute `pm4py.get_case_arrival_average` only as a scalar reference. That average hides the 1.7× seasonal peaks and the Monday 2.2× peak, so it is not the arrival generator.
- Parse the tree with `pm4py.parse_process_tree`. Shield spaces inside quoted labels before parsing, because some PM4Py versions strip whitespace globally and would turn `Submit application` into a different label. Restore labels afterward.
- Optionally convert the tree with `pm4py.convert_to_petri_net` and compute token-replay fitness. Low fitness is expected: the log repeats `Completeness check` and `Site inspection`, while the tree invents `Completeness rework` and `Inspection rework`, and appeal or planning rework is absent from the tree. Fitness is a sketch diagnostic, not a validation gate for the twin.

**What the performance DFG actually measures.** Arc values are times between successive completion timestamps on a flattened case, usually in seconds. On a parallel fragment that total order is an artifact. The time from `Planning review` to `Fire-safety review` mixes any real overlap, queueing, calendar closure, and recording delay. Those arc times calibrate sojourn. They are not service-time parameters.

**Arrivals.** Take the first timestamp of each case as the arrival. Keep incomplete cases in the arrival series. Bin starts by month, ISO week, weekday, and hour. Estimate a multiplicative calendar: season index, weekday index, and a residual weekly rate. Compare weekly counts with a Poisson variance; overdispersion motivates the architect cluster process below. Fit the weekday profile from the log rather than imposing 2.2× on Monday alone. Include holiday dummies so a Monday holiday is not absorbed into the Monday effect. The stated 1.7× for March–May and September–November versus January–February is a check on the seasonal index, not a complete calendar: June–August and December need their own estimated indices.

**Case attributes.** Estimate the joint distribution of `case_type`, `district`, architect class, value band, and the three requirement flags. Preserve dependence. Simple renovation is 45%, new residential 28%, commercial 17%, and complex variance 10%, and the flags move with type. Within an architect burst, draw district and type from the empirical within-architect distribution so related applications stay related.

**Branching.** Estimate probabilities from the log conditional on attributes and history, not from the unweighted tree. Examples: probability of a missing-document loop given case type; probability that fire, environment, or public notice occurs given the observed flags and case type. Where `requires_fire` is no and a fire review still occurs, treat the residual as the unobserved area-threshold rule and keep that residual rate in the sensitivity set. Do the same for environmental review when the sensitive-district flag is missing. Tree `tau` branches receive these empirical probabilities; the parser does not store them.

**Service, waiting, and sojourn.** Split each activity’s elapsed time into enablement, queue wait, calendar suspension, working-time service, travel, and external delay.

- Enablement of the first activity is the arrival time. Enablement of an AND successor is the maximum completion time of the predecessors that actually ran. Enablement is not “the previous row in the case.”
- Where a start timestamp exists, service is the assigned calendar’s working time from start to completion, and waiting is calendar time from enablement to start.
- Where only a completion timestamp exists, the log identifies the inter-completion sojourn only. Use the published median and p90 service and waiting figures as provisional priors. Choose the split so simulated sojourn, after calendars and queues, matches observed inter-event times. Keep at least two identifiable extremes in the uncertainty set: short service with long wait, and long service with short wait, both pinned to the same sojourn.
- Fit service distributions on working-time quantiles by activity and case type. Match median and p90, then check the mean. Prefer lognormal or gamma bodies. A single exponential understates the p90 gaps in the activity table, such as planning review at 3.5 h versus 14 h.
- `Receive missing documents` has zero municipal service. Its time is an external delay. `Public-notice period` is a minimum 14-day timer plus a latent extension. `Issue permit` has about five minutes of system work and a median half-day wait, which is a release delay on an unlimited server, not a capacity queue.

**Rework.** Count repeated occurrences of the same log activity inside a case. Map the tree’s redo labels onto those repeats: a second `Completeness check` is completeness rework; a second `Site inspection` is inspection rework. Estimate repeat probabilities by case type and upstream path. The 9% inspection-rework variants and the 8% complex appeal/rework variants are calibration targets. Rework reasons are unstructured, so cause-specific rates stay unidentified; use an aggregate repeat probability and a sensitivity multiplier of 0.5×, 1×, and 1.5× on rework service time. Rare emergency paths were removed from the log, so the estimated model is slightly shifted away from those short paths. Record that bias; do not invent the removed cases.

**Calendars.** Encode the HR calendars as offered working hours, then check them against the timestamps that do exist: fire completions should concentrate on Tuesday–Thursday, inspector activity on Tuesday–Friday, and legal activity should thin in council weeks. Completions recorded on a closed day are a recording convention to resolve with staff, because many human activities have no start stamp. Holidays come from the municipal calendar. Council blackout weeks come from the council calendar where available, and otherwise from weeks in which legal completions collapse. Environmental reservation is applied as 60% offered time, not as three full-time permit reviewers.

**Dependencies.**

- Architect clustering: distribution of weekly case counts per `architect_id`, with a separate model for the top 20. Estimate co-occurrence of district within an architect-week.
- Shared applicant delay: correlation of `Receive missing documents` delays across open cases of the same architect. Strong correlation supports a per-architect response queue. Weak correlation supports independent heavy-tailed draws.
- Inspection geography: travel increment by district, with D3 and D5 longer. If the historical log already contains same-day same-district visits, estimate the travel saving from those episodes. Otherwise the saving used in D3 is a scenario parameter.
- Objections: do not impute objection events. Model a district-week shock whose presence lengthens notice. Calibrate the marginal duration mixture to the observed public-notice times: a point mass at the 14-day floor and a long component reaching the reported 60-day objection regime. Estimate extra-Poisson correlation of long notices among overlapping cases in the same district. That correlation identifies the shock only weakly, so it stays in the outer uncertainty loop.

**Censoring and windowing.** Cases open at the extract’s end are censored for duration fitting and fully counted as arrivals. Use a temporal split for validation: refit on the earlier part of the log and score the later part, choosing the cut so the holdout still contains a peak season. An 18-month extract can support that split once. It cannot identify year-to-year change in seasonality; the stress scenarios carry that uncertainty.

## 3. Assumptions

### Arrivals

Background applications follow a non-homogeneous Poisson process with a seasonal index, a weekday index, and an hour-of-day profile estimated from case starts. The top 20 architects follow a cluster process: each week a probability of a burst, then a burst size from the empirical weekly count, with attributes drawn from that architect’s own history. Background and burst processes are additive. Portal arrivals outside clerk hours wait until the next clerk opening. The scalar PM4Py case-arrival average is only a checksum.

### Service times

Municipal service is sampled in working hours and executed only inside the activity’s calendar. Distributions are activity-specific and case-type-specific, matched to median and p90. System activities have short service and unlimited servers. Site inspection service includes an on-site component plus a district travel component; travel uses inspector working hours. When start stamps are missing, the numerical split between service and wait is an assumption constrained by the observed sojourn and by the published summaries. Review work is non-preemptive across cases and preemptive across calendar closures: a planner keeps the case overnight but does not work overnight.

### Routing

Fire is required when `requires_fire` is yes, plus a residual probability standing in for the unobserved area threshold. Environmental review is required when `requires_environment` is yes, plus a residual probability standing in for incomplete sensitivity data. Public notice is required for complex variance and for the share of new residential cases indicated by `requires_public_notice` and the variant table. Planning always runs. Decision drafting waits for every branch that was actually required, including inspection unless a policy skips it. Legal check follows the historical conditional rate, concentrated in commercial and complex cases. The final XOR is issue versus reject at the historical type-specific rate. D2, D5, D8, and D9 change these rules only inside their own experiment arms.

### Resources and calendars

Headcounts and weekly patterns are the HR figures in section 1. Fire hours and inspector field hours were not fully specified; the prototype uses Tuesday–Thursday 09:00–17:00 for fire and Tuesday–Friday 08:30–16:30 for inspectors, pending face validation. One Monday clerk is removed from the completeness queue. Two planners form a Simple-renovation-only subpool; the other six form the generalist pool. Environment offers 60% of weekday time to permits. Legal offers no ordinary capacity in council weeks; a small urgent bypass exists. Servers do not multitask. Holidays close every municipal pool. These calendars are shared by all open cases.

### Rework

Completeness rework returns the case to `Completeness check` after another document cycle when the repeat occurs. Inspection rework returns the case to scheduling. The inspection-rework mixture combines no-shows, applicant unreadiness, and failed visits; those causes are not coded, so policies cannot be credited with fixing only one cause. Planning, legal, and appeal-like repeats are extra loops whose probabilities are set to reproduce the complex and “other” variant shares. Each case draws rework from its attributes and history, independent of other cases except through the shared objection shock and shared congestion. Rework service uses the same family as first-pass service, with a multiplier that sensitivity analysis varies because the log does not separate the two reliably.

### Applicant and third-party response

`Receive missing documents` is an infinite-server delay, provisionally heavy-tailed and anchored on a median of about five days from the request, then calibrated so the missing-document variant median of 22 days and p90 of 45 days are recovered. Environmental consultant delay, where it sits inside the environmental sojourn, is a separate external delay with median and p90 chosen during calibration against the environmental waiting summary. Applicant time and municipal service stay in different accumulators. D1’s pre-submission effort is applicant time before the municipal clock starts.

### Cross-case dependencies

Cases are dependent in four places. Architect bursts couple arrivals and may couple document-response delays. Inspection bundles couple waiting and travel for cases in the same district. District-week objection shocks couple public-notice extensions; the shock is latent. Shared pools and shared blackout weeks couple delays for everyone in queue. No other case-to-case influence is assumed. Neighborhood objections are not read from a missing event type.

### Non-stationary demand

The arrival rate in March–May and September–November is about 1.7 times the January–February rate, and Monday submissions are about 2.2 times Wednesday submissions, subject to the estimated indices and holiday adjustments. Service-time laws, routing probabilities, and FTE counts are constant across seasons in the baseline. Seasonality of outcomes comes from the arrival rate, the weekly calendars, council blackouts, and queue feedback. A policy that looks neutral in a flat-demand run can still fail in the peak because fire, environment, inspectors, and legal are small pools. Each experiment is scored on a window that contains both peak seasons.

### Missing data

Start stamps are missing for many human activities, so the wait/service split is only partially identified and is carried as an outer uncertainty factor. Objection events are absent; only the duration proxy and its cross-case correlation are used. Rework reasons remain aggregated. `prior_violations`, building area, and environmental sensitivity are incomplete, so D2 and D8 include explicit prevalence and misclassification levels. Emergency cases removed from the log are acknowledged as a small downward bias in very short-cycle volume. Calendars come from HR reconstruction and are checked against timestamp support. The flattened case log under-represents dependency; architect, district, and overlapping-notice statistics are the repair, with a high-coupling sensitivity.

## 4. Experiment matrix

Primary levels, used when an arm says “primary”: D1 cuts the missing-document probability by half and adds two days of pre-submission applicant time; D2 uses a 5% prior-violation prevalence; D3 waits up to two days to form a district bundle of at least two cases and applies a 0.6 travel multiplier inside the bundle; D4 adds one inspector on the field calendar in March–May and September–November; D5 starts legal work when planning starts for commercial and complex cases; D6 reserves one generalist planner for cases older than 45 days; D7 shifts half of Monday’s excess volume to Tuesday–Thursday; D8 uses a 10% environmental misclassification rate; D9 shortens latent notice extensions by 25% and does not increase their incidence.

All arms share the calibrated baseline parameters, the same calendars, the same seeds, and the same arrival window. D10 and the factorial slice exist because D1–D4 are not additive: D2 and D4 both relieve inspectors, and D3 changes how inspector hours convert into throughput.

## 5. Warm-up, replications, and uncertainty treatment

The system is seasonal and many complex cases run for 140 days at the median and about 260 days at the p90. A steady-state batch-means analysis on one long run would mix different seasons and would treat a transient calendar as if it were stationary. The design is a fixed-horizon simulation aligned to the calendar.

**Initial condition and warm-up.** Primary setting: load a work-in-progress snapshot stratified by phase, case type, and age, built from cases open on a 1 January-like date in the log, then run 90 days of warm-up before scoring. Alternative check: start empty and warm up for 12 months, long enough for a complex-case cohort to arrive and finish, and compare scores with the snapshot method. Warm-up length is confirmed with a Welch plot on weekly WIP, weekly throughput, and inspector queue, computed across replications and aligned by calendar week. Scored cases are those that arrive in the observation window. Warm-up arrivals are discarded from metrics even if they finish during the window.

**Run length.** The observation window is 24 months, so it contains two spring peaks and two autumn peaks. Each scored case is followed until it finishes or until 365 days after its arrival. The simulation drains for up to 12 months after the last scored arrival. Every metric is reported with its censoring rate. A horizon that cuts complex cases at 180 days would understate the tail the council actually feels.

**Replications and seeds.** Screening uses 40 replications per arm. Shortlisted arms and S1–S4 use 60 replications because p90 and district ratios are noisier than means. One master seed, `20260102`, feeds a `numpy.random.SeedSequence`. Replication `r` spawns independent streams for background arrivals, architect bursts, covariates, routing and rework, service, applicant delay, objection shocks, and no-shows. The same replication index is used for every policy. Random draws are keyed by `(case_id, activity, attempt)` so a skipped inspection in D2 does not reshuffle later draws for unrelated activities. That keeps common-random-number comparisons meaningful when paths diverge.

**Intervals.** For each replication, compute the cohort median, p90, SLA rate, utilization, and fairness ratio. Across replications, report the mean of those replication statistics and a 95% t-interval. Also report a percentile interval of the replication statistics so a skewed tail metric is visible. Paired policy differences use the same replication index and a 95% interval on the paired difference. A difference whose interval covers zero is treated as unresolved at this sample size.

**Outer parameter uncertainty.** For shortlisted policies, add a second loop: 30 weekly block-bootstrap resamples of the log, stratified by season so a peak is not dropped, re-estimate arrival, routing, and duration parameters, and run 20 inner replications. HR headcounts and calendars are not bootstrapped; they are varied on a small grid (±1 clerk, ±1 planner, environment availability 50–70%, council-week count ±2). The reported interval for a decision metric is the spread across bootstrap fits and inner noise. Stochastic intervals alone would understate uncertainty from the missing start stamps and the missing objections.

**Heavy tails.** Applicant delay, notice extension, environmental sojourn, and complex-case cycle time are heavy-tailed. Fit median and p90, and use a lognormal or a two-component mixture for the long component. The mean is a diagnostic because censoring and a few very long cases dominate it. Decision metrics are medians, p90, and SLA rates. Winsorizing is allowed on a diagnostic plot and is not used in the selection rule. If the p90 interval for complex variance is still too wide at 60 replications, increase that arm rather than replacing the p90 with the mean.

**Sensitivity, in order.** Wait/service identification split; objection incidence and district-week correlation; D2 violation prevalence; D8 misclassification; architect-delay correlation on versus off; travel-time prior for D3 and D5; rework service multiplier; fire and inspector clock hours; environmental availability fraction. One-factor sweeps cover the list. The E11 factorial covers the inspection interactions. A policy recommendation requires the sign of the primary paired difference to agree on both identification splits and on S1–S3.

## 6. Validation strategy

Validation is sequential. Face and replay checks come first. Distributional, utilization, and bottleneck checks decide whether E0 is close enough to use as a baseline. Out-of-sample checks come before any recommendation. Failure sends the model back to calibration. It does not produce a qualified ranking.

**Face validation.** Walk the lifecycle, calendars, and bundle rule with clerks, planners, a fire reviewer, an inspector, and legal. Confirm Monday portal-support staffing, the two simple-only planners, fire days, the 40% environmental reservation, council blackout rules, the urgent bypass, and the provisional fire and inspector hours. Confirm the decision-drafting join: which branches a case type actually waits for. Confirm that rejection work sits with the decision planner plus a system record. Record every change as a versioned assumption.

**Event-log replay validation.** Compare discovered variants and the DFG with the executable lifecycle. Alignment is judged on log vocabulary: repeated `Completeness check` and `Site inspection`, presence of the three optional reviews, and the issue/reject ending. The process-tree labels `Completeness rework` and `Inspection rework` are expected to misfire on token replay; that misfire is documented and then removed from the executable model by using the log labels. Replay also checks that parallel fire and environment reviews are not forced into a false sequence by the flattened trace. Conformance of the sketch tree is not a pass/fail gate for the twin.

**Distributional validation.** On the estimation window, compare simulated and observed: monthly and weekday arrival counts; case-mix and flag rates; variant-group shares from the summary table; calendar-day cycle-time median and p90 by case type and by the seven variant groups; and activity sojourn medians. Use Wasserstein distance and a two-sample KS statistic as diagnostics, with the numeric gates below as the decision rules. Compare the mixture of public-notice durations to the log without requiring the simulator’s latent shocks to match events that were never recorded. Gates for a usable baseline: variant-group shares within 3 percentage points; monthly arrival totals within 10%; case-type median cycle time within 10% relative; case-type p90 within 15% relative; censoring pattern of open cases within 5 points of the log.

**Resource-utilization validation.** Compare simulated busy hours, by pool and month, with busy time inferred only from intervals that have start and completion stamps. For completion-only activities, compare timestamp density by weekday and hour with the calendar, and treat absolute utilization as provisional. Inspector utilization is reported both with and without travel so a travel-heavy month is not mistaken for an on-site service backlog. Environmental busy time is compared with 1.8 FTE of offered hours, not with 3 FTE.

**Bottleneck validation.** Rank activities by median wait and by peak-month queue. The empirical pattern to recover is completeness spikes after Mondays, long planning and environmental waits, fire delay on a three-day calendar, inspection waits around a median of 8 days, and legal waits sensitive to council weeks. Staff should recognize the same top three constraints the model ranks. A model that makes system issue the bottleneck, or that leaves inspectors idle while inspection wait stays at its historical median, fails this gate.

**Out-of-sample validation.** Refit all estimated quantities on the earlier portion of the 18-month log and simulate the later portion with its actual calendar, holidays, and council weeks. The holdout must include one peak season. Loosen the distributional gates by 5 percentage points. Also check a structural slice: hide one mid-size district’s durations during fitting and test them after, so district travel and mix are not only in-sample. Random case holdout is a weak test here because it leaks the same season and the same architect bursts into both sides. Year-to-year stability cannot be validated from 18 months; S1 carries that exposure instead.

**Calibration stop rule.** Adjust only parameters that the missing data leave free: the wait/service split within the two bounds, residual routing rates, objection-shock variance, and travel priors. Do not tune routing probabilities that are directly counted in the log, and do not add a latent objection event column to the historical extract.

## 7. Decision criteria

Thresholds below are policy choices anchored to today’s variant table, for the municipality to ratify before the runs. They are not estimates, and they are not an optimality claim. No arm is selected unless E0 has passed the section 6 gates. After that, the result is a shortlist with paired intervals, not a proven optimum.

**Metrics, all on the arrival cohort, with censoring reported.**

- Duration: median and p90 calendar days from `Submit application` to `Issue permit` or `Reject application`, overall and by case type.
- Two clocks for D1: municipal cycle time, and municipal time plus pre-submission delay plus applicant document delay.
- SLA attainment by case type, using the ratified calendar-day targets: Simple renovation 30 days, New residential 90 days, Commercial 120 days, Complex variance 200 days. Today’s p90 values sit near 24, 95, 130, and 260 days for the dominant variant groups, so the residential, commercial, and complex targets are intentionally close to the current tail and should be confirmed.
- Fairness: ratio of median cycle time in D3–D5 to the other districts; the same ratio for SLA attainment; ratio of median cycle time for the top 20 architects to everyone else.
- Utilization: peak-month busy hours over offered hours, by pool, with inspector travel split out.
- Rework: share of cases with a repeated completeness check, a repeated site inspection, or any other repeat.
- Backlog: mean weekly WIP, and the count of open cases older than their type’s SLA, measured at the end of each peak season.
- Robustness: paired difference versus E0 under S1–S4, plus agreement across the two wait/service splits.

**Screen, applied in order.**

1. Paired 95% interval for the targeted case type’s median shows a reduction, and the p90 interval shows a reduction or no increase.
2. No other case type’s p90 interval lies entirely above a 5% worsening.
3. District median ratio does not rise by more than 0.05 relative to E0, and the architect-size ratio does not rise by more than 0.05.
4. Peak-month utilization for clerks, planners, and inspectors stays at or below 85% of offered hours in the median replication. Fire may print short spikes up to 90% because it is open only three days. Environment is judged against 1.8 FTE.
5. Completeness and inspection rework shares do not increase. For D2, a rise in inspection rework among the cases that still require a visit is a rejection signal, because the skipped visits’ failure risk is invisible in the log.
6. End-of-peak overdue WIP is at or below E0.
7. The sign of the primary p90 benefit agrees on both identification splits and remains favorable to E0 under S1 and S2. S3 is mandatory for any shortlist that includes D9 or that claims a public-notice benefit. S4 is mandatory for any shortlist that includes D7.

**How to read the arms.** D1 is adopted on the municipal clock only if the combined applicant-plus-municipal clock also improves at the +2-day and +5-day levels the municipality believes. D2 is a capacity policy with an unquantified compliance risk; it can pass the operational screen and still be declined on legal grounds. D3 is preferred when the D3/D5 tail falls and low-volume districts do not absorb a large wait increase. D4 is preferred when its peak benefit survives S2, otherwise it is a temporary patch for absenteeism. D5 and D6 are tail policies and fail the screen if fresh-case or non-target p90 worsens past the bound. D8 fails closed when the 30% misclassification level reverses the environmental tail. D9 can be recommended only as a pilot: the objection mechanism is unobserved, so a simulated gain that appears only inside the assumed extension model is labeled exploratory. D10 is preferred to the best single arm only when E10’s own paired interval beats that arm on the primary p90 and E11 shows the combination is not double-counting the same inspector hours.

If several arms pass, prefer the one with the smaller worst-case p90 regret across S1–S4 and across the two identification splits. If none pass, keep the baseline and collect the missing start stamps, a coded objection or notice-extension flag, and a violation flag before the next round. The simulation does not establish an exact optimum.

def shield_quoted_spaces(tree_string: str) -> Tuple[str, Dict[str, str]]:
    """Keep spaces inside quotes stable if the parser strips whitespace."""
    import re

    mapping: Dict[str, str] = {}

    def repl(match: "re.Match[str]") -> str:
        label = match.group(1)
        token = label.replace(" ", "·")
        mapping[token] = label
        return "'" + token + "'"

    return re.sub(r"'([^']*)'", repl, tree_string), mapping


def restore_labels(tree, mapping: Mapping[str, str]) -> None:
    if tree is None:
        return
    label = getattr(tree, "label", None)
    if label in mapping:
        tree.label = mapping[label]
    for child in getattr(tree, "children", []) or []:
        restore_labels(child, mapping)


def collect_labels(tree) -> set:
    found = set()
    if tree is None:
        return found
    if getattr(tree, "label", None):
        found.add(tree.label)
    for child in getattr(tree, "children", []) or []:
        found |= collect_labels(child)
    return found


def parse_control_flow_sketch(tree_string: str = PROCESS_TREE_STRING):
    """Parse the sketch and report why it is not the executable model.

    pm4py.parse_process_tree stores operators and labels only. It does not
    store branching probabilities, durations, calendars, guards, or
    cross-case state. Some PM4Py versions delete every space before parsing,
    which would corrupt labels such as 'Site inspection'.
    """
    shielded, mapping = shield_quoted_spaces(tree_string)
    tree = pm4py.parse_process_tree(shielded)
    restore_labels(tree, mapping)
    labels = collect_labels(tree)
    unknown = sorted(labels - LOG_ACTIVITIES - {"tau"} - set(mapping.values()))
    missing_from_tree = sorted(LOG_ACTIVITIES - labels)
    # 'Environmental review' is in the tree. Repeated log activities are not
    # the same symbols as 'Completeness rework' and 'Inspection rework'.
    report = {
        "parsed_type": type(tree).__name__,
        "labels": sorted(labels),
        "labels_absent_from_log": sorted(set(labels) - LOG_ACTIVITIES - {None}),
        "log_labels_absent_from_tree": missing_from_tree,
        "whitespace_tokens_restored": sorted(mapping.values()),
        "unknown_after_restore": unknown,
        "limitations": [
            "Tree redo labels do not match repeated activities in the log.",
            "Appeal and planning/legal rework from the variant notes are absent.",
            "XOR and loop probabilities are not in the string.",
            "The AND/XOR sketch has no data guards and no decision-drafting join state.",
            "Resources, calendars, travel, and cross-case bundles cannot be encoded.",
        ],
    }
    return tree, report

def add_elapsed_columns(frame: pd.DataFrame) -> pd.DataFrame:
    """Separate service and waiting only when start stamps exist.

    elapsed_since_prev_completion mixes queue time, nights and weekends,
    applicant delay, travel, and service. It is retained as a sojourn proxy.
    """
    timed = frame.sort_values(["case:concept:name", "time:timestamp"]).copy()
    previous = timed.groupby("case:concept:name")["time:timestamp"].shift(1)
    elapsed = timed["time:timestamp"] - previous
    timed["elapsed_since_prev_completion_h"] = elapsed.dt.total_seconds() / 3600.0
    start_col = "start_timestamp" if "start_timestamp" in timed.columns else None
    if start_col is None:
        timed["service_time_h"] = pd.NA
        timed["waiting_time_h"] = pd.NA
        timed["time_split_status"] = "completion_only_sojourn"
        return timed
    service = timed["time:timestamp"] - timed[start_col]
    waiting = timed[start_col] - previous
    timed["service_time_h"] = service.dt.total_seconds() / 3600.0
    timed["waiting_time_h"] = waiting.dt.total_seconds() / 3600.0
    timed["time_split_status"] = "start_and_completion"
    return timed

@dataclass
class WeeklyCalendar:
    """Working-time calendar for one pool. Capacity changes are separate."""

    open_weekdays: Tuple[int, ...]
    start_hour: float
    end_hour: float
    holidays: Tuple[pd.Timestamp, ...] = ()
    blackout_weeks: Tuple[Tuple[int, int], ...] = ()

    def is_open(self, ts: pd.Timestamp) -> bool:
        stamp = pd.Timestamp(ts)
        if stamp.weekday() not in self.open_weekdays:
            return False
        if stamp.normalize() in {pd.Timestamp(day).normalize() for day in self.holidays}:
            return False
        if (int(stamp.isocalendar().year), int(stamp.isocalendar().week)) in set(self.blackout_weeks):
            return False
        hour = stamp.hour + stamp.minute / 60.0
        return self.start_hour <= hour < self.end_hour

    def add_working_hours(self, start: pd.Timestamp, hours: float) -> pd.Timestamp:
        """Advance a clock by working hours. Calendar closures do not count."""
        if hours < 0:
            raise ValueError("service hours must be non-negative")
        cursor = pd.Timestamp(start)
        remaining = float(hours)
        guard = 0
        while remaining > 1e-9:
            guard += 1
            if guard > 100000:
                raise RuntimeError("calendar advance did not terminate")
            if not self.is_open(cursor):
                cursor = self._next_open(cursor)
                continue
            hour = cursor.hour + cursor.minute / 60.0 + cursor.second / 3600.0
            available = self.end_hour - hour
            step = min(remaining, available)
            cursor += pd.Timedelta(hours=step)
            remaining -= step
            if remaining > 1e-9:
                cursor = self._next_open(cursor)
        return cursor

    def _next_open(self, ts: pd.Timestamp) -> pd.Timestamp:
        cursor = pd.Timestamp(ts) + pd.Timedelta(minutes=1)
        for _ in range(366 * 24 * 60):
            if self.is_open(cursor):
                return cursor.replace(second=0, microsecond=0)
            if cursor.weekday() not in self.open_weekdays or cursor.normalize() in {
                pd.Timestamp(day).normalize() for day in self.holidays
            }:
                cursor = (cursor.normalize() + pd.Timedelta(days=1)).replace(
                    hour=int(self.start_hour),
                    minute=int(round((self.start_hour % 1) * 60)),
                )
                continue
            hour = cursor.hour + cursor.minute / 60.0
            if hour < self.start_hour:
                return cursor.normalize() + pd.Timedelta(hours=self.start_hour)
            cursor = (cursor.normalize() + pd.Timedelta(days=1)).replace(
                hour=int(self.start_hour),
                minute=int(round((self.start_hour % 1) * 60)),
            )
        raise RuntimeError("no open instant found")


@dataclass
class ResourcePool:
    name: str
    headcount: int
    calendar: WeeklyCalendar
    skills: Tuple[str, ...] = ("all",)
    availability: float = 1.0  # environment uses 0.6

    def offered_servers(self, ts: pd.Timestamp, monday_portal_support: bool = False) -> int:
        if not self.calendar.is_open(ts):
            return 0
        count = self.headcount
        if self.name == "clerk" and monday_portal_support and ts.weekday() == 0:
            count = max(0, count - 1)
        if self.availability < 1.0:
            # Fractional FTE: expected servers, at least the fractional capacity.
            return max(1, int(round(count * self.availability))) if count else 0
        return count

@dataclass
class ArrivalProcess:
    """Non-stationary, architect-clustered arrivals. Not a homogeneous Poisson."""

    season_index: Mapping[int, float]
    weekday_index: Mapping[int, float]
    base_daily_rate: float
    top_architects: Tuple[str, ...]
    burst_probability: float
    rng: np.random.Generator

    def rate_on(self, day: pd.Timestamp, policy: Policy) -> float:
        season = float(self.season_index.get(int(day.month), 1.0))
        weekday = float(self.weekday_index.get(int(day.weekday()), 1.0))
        if policy.monday_multiplier_override is not None and day.weekday() == 0:
            wednesday = float(self.weekday_index.get(2, 1.0))
            weekday = policy.monday_multiplier_override * wednesday
        rate = self.base_daily_rate * season * weekday * policy.demand_multiplier
        if day.weekday() == 0 and policy.monday_shift_fraction > 0:
            rate *= 1.0 - policy.monday_shift_fraction * (1.0 - min(1.0, 1.0 / max(weekday, 1e-6)))
        return max(rate, 0.0)

    def generate_case_arrivals(self, start: pd.Timestamp, end: pd.Timestamp, policy: Policy) -> List[pd.Timestamp]:
        """Thinning-ready daily counts, plus same-week architect bursts.

        A full implementation would draw attributes and burst membership here
        and would shift a fraction of Monday arrivals when D7 is on.
        """
        arrivals: List[pd.Timestamp] = []
        day = pd.Timestamp(start).normalize()
        last = pd.Timestamp(end).normalize()
        while day < last:
            lam = self.rate_on(day, policy)
            count = int(self.rng.poisson(lam))
            if count:
                offsets = self.rng.uniform(8, 18, size=count)
                arrivals.extend(day + pd.to_timedelta(offsets, unit="h"))
            if self.rng.random() < self.burst_probability:
                burst = max(1, int(self.rng.geometric(0.45) * policy.burst_size_multiplier))
                offsets = self.rng.uniform(8, 18, size=burst)
                arrivals.extend(day + pd.to_timedelta(offsets, unit="h"))
            day += pd.Timedelta(days=1)
        return sorted(arrivals)


@dataclass
class RoutingModel:
    """Data-dependent routing. Probabilities are estimated outside PM4Py."""

    p_missing_docs: Mapping[str, float]
    p_fire_residual: float
    p_env_residual: float
    p_legal: Mapping[str, float]
    p_reject: Mapping[str, float]
    p_completeness_rework: Mapping[str, float]
    p_inspection_rework: Mapping[str, float]
    p_objection: Mapping[str, float]

    def apply_static_flags(self, case: Case, policy: Policy, rng: np.random.Generator) -> None:
        if case.case_type == "Simple renovation" and policy.skip_simple_inspection:
            low_value = case.application_value < policy.simple_value_limit
            # prior_violations is often unobserved; prevalence is a scenario input.
            if case.prior_violations is None:
                case.prior_violations = bool(rng.random() < policy.violation_prevalence)
            case.requires_inspection = not (low_value and not case.prior_violations)
        if rng.random() < self.p_fire_residual:
            case.requires_fire = True
        if rng.random() < self.p_env_residual:
            case.requires_environment = True
        incidence = self.p_objection.get(case.case_type, 0.0) * policy.notice_incidence_multiplier
        case.objection_shock = bool(rng.random() < min(1.0, incidence))

    def missing_documents(self, case: Case, policy: Policy, rng: np.random.Generator) -> bool:
        base = self.p_missing_docs.get(case.case_type, 0.0) * policy.missing_doc_multiplier
        return bool(rng.random() < min(1.0, base))


@dataclass
class DurationModel:
    """Working-hour service and calendar-time external delays.

    Quantile pairs are provisional until estimation replaces them.
    Public notice is a 14-day floor plus a latent extension. The extension
    is not an observed objection event.
    """

    service_quantiles_h: Mapping[str, Tuple[float, float]]
    applicant_delay_quantiles_d: Tuple[float, float] = (5.0, 30.0)
    notice_floor_d: float = 14.0
    notice_extension_quantiles_d: Tuple[float, float] = (20.0, 46.0)
    travel_hours: Mapping[str, float] = field(default_factory=dict)

    def sample_service_hours(self, activity: str, rng: np.random.Generator) -> float:
        median, p90 = self.service_quantiles_h[activity]
        # Lognormal matched roughly to median and p90; replace with a fitted law.
        sigma = max(0.05, (np.log(p90) - np.log(median)) / 1.2816)
        return float(rng.lognormal(np.log(median), sigma))

    def sample_applicant_delay_days(self, rng: np.random.Generator) -> float:
        median, p90 = self.applicant_delay_quantiles_d
        sigma = max(0.05, (np.log(p90) - np.log(median)) / 1.2816)
        return float(rng.lognormal(np.log(median), sigma))

    def public_notice_days(self, case: Case, policy: Policy, rng: np.random.Generator) -> float:
        if not case.objection_shock:
            return self.notice_floor_d
        median, p90 = self.notice_extension_quantiles_d
        sigma = max(0.05, (np.log(max(p90, median)) - np.log(median)) / 1.2816)
        extension = float(rng.lognormal(np.log(median), sigma))
        extension *= policy.notice_extension_multiplier
        return self.notice_floor_d + extension


@dataclass
class InspectionBatcher:
    """District bundles: lower travel, extra wait for the earliest case."""

    wait_cap: pd.Timedelta
    min_size: int
    buffers: Dict[str, List[Case]] = field(default_factory=dict)

    def offer(self, case: Case, now: pd.Timestamp) -> List[Case]:
        bucket = self.buffers.setdefault(case.district, [])
        bucket.append(case)
        oldest = min(item.timestamps.get("inspection_ready", now) for item in bucket)
        if len(bucket) >= self.min_size or now - oldest >= self.wait_cap:
            released = bucket[:]
            bucket.clear()
            return released
        return []

class SimulationEngine:
    """Activity-level DES shell.

    The run method is intentionally a scaffold: it wires arrivals, routing,
    calendars, the decision join, and batching, and it leaves the event loop
    for a SimPy or custom calendar-queue implementation. Scoring cases are
    those that arrive inside the observation window.
    """

    def __init__(
        self,
        arrivals: ArrivalProcess,
        routing: RoutingModel,
        durations: DurationModel,
        pools: Mapping[str, ResourcePool],
        master_seed: int = 20260102,
    ) -> None:
        self.arrivals = arrivals
        self.routing = routing
        self.durations = durations
        self.pools = pools
        self.master_seed = master_seed

    def replication_rng(self, replication: int, stream: str) -> np.random.Generator:
        entropy = np.random.SeedSequence([self.master_seed, replication, abs(hash(stream)) % (2**32)])
        return np.random.default_rng(entropy)

    def run(
        self,
        policy: Policy,
        replication: int,
        window_start: pd.Timestamp,
        window_end: pd.Timestamp,
    ) -> ExperimentResult:
        rng = self.replication_rng(replication, "master")
        arrivals = self.arrivals.generate_case_arrivals(window_start, window_end, policy)
        batcher = InspectionBatcher(
            wait_cap=pd.Timedelta(days=policy.bundle_wait_days),
            min_size=policy.bundle_min_size,
        )
        completed: List[Case] = []
        for index, arrival in enumerate(arrivals):
            case_rng = np.random.default_rng(rng.integers(0, 2**31 - 1))
            case = self._synthetic_case(index, pd.Timestamp(arrival), policy, case_rng)
            self.routing.apply_static_flags(case, policy, case_rng)
            completed.append(self._execute_lifecycle(case, policy, case_rng, batcher))
        metrics = summarize_cohort(completed, window_start, window_end)
        return ExperimentResult(policy.name, replication, metrics)

    def _synthetic_case(self, index: int, arrival: pd.Timestamp, policy: Policy, rng: np.random.Generator) -> Case:
        # Attribute draws are placeholders. Replace with the empirical joint distribution.
        case_type = str(rng.choice(
            ["Simple renovation", "New residential", "Commercial", "Complex variance"],
            p=[0.45, 0.28, 0.17, 0.10],
        ))
        return Case(
            case_id=f"SIM-{index:06d}",
            case_type=case_type,
            district=str(rng.choice(["D1", "D2", "D3", "D4", "D5"])),
            architect_id=str(rng.choice(["A17", "A02", "other"])),
            application_value=float(rng.choice([32000, 480000, 900000])),
            requires_fire=case_type != "Simple renovation",
            requires_environment=case_type in {"Commercial", "Complex variance"},
            requires_public_notice=case_type in {"New residential", "Complex variance"},
            prior_violations=bool(rng.random() < policy.violation_prevalence),
            arrival=arrival,
        )

    def _execute_lifecycle(
        self,
        case: Case,
        policy: Policy,
        rng: np.random.Generator,
        batcher: InspectionBatcher,
    ) -> Case:
        """Semantic scaffold, not a clock-correct event loop.

        A complete engine would schedule enablement, queue, and calendar
        completion events. This method shows the state transitions the loop
        must preserve, including the AND-join and the external delays.
        """
        case.timestamps["Submit application"] = case.arrival + pd.Timedelta(days=policy.pre_submission_delay_days)
        if self.routing.missing_documents(case, policy, rng):
            delay = self.durations.sample_applicant_delay_days(rng)
            case.timestamps["Receive missing documents"] = case.arrival + pd.Timedelta(days=delay)
            case.attempt["Completeness check"] = 2
        else:
            case.attempt["Completeness check"] = 1
        case.finished_branches.add("Planning review")
        if case.requires_fire:
            case.finished_branches.add("Fire-safety review")
        if case.requires_environment:
            case.finished_branches.add("Environmental review")
        if case.requires_public_notice:
            notice_days = self.durations.public_notice_days(case, policy, rng)
            case.timestamps["Public-notice period"] = case.arrival + pd.Timedelta(days=notice_days)
            case.finished_branches.add("Public-notice period")
        if case.requires_inspection:
            case.timestamps["inspection_ready"] = case.arrival
            if policy.batch_inspections:
                batcher.offer(case, case.arrival)
            case.finished_branches.add("Site inspection")
        if not case.decision_enabled():
            case.timestamps["status"] = pd.NaT
        case.timestamps["end"] = case.arrival + pd.Timedelta(days=1)  # replaced by the real event loop
        return case


def summarize_cohort(cases: Sequence[Case], window_start: pd.Timestamp, window_end: pd.Timestamp) -> Dict[str, float]:
    """Median, tail, SLA, fairness, rework, and backlog placeholders.

    Cycle time uses calendar days from submission to the terminal event.
    A real run replaces the scaffold end timestamp with Issue or Reject.
    """
    scored = [case for case in cases if window_start <= case.arrival < window_end]
    if not scored:
        return {"n": 0}
    durations = []
    for case in scored:
        end = case.timestamps.get("end", pd.NaT)
        start = case.timestamps.get("Submit application", case.arrival)
        if pd.isna(end):
            continue
        durations.append((end - start).total_seconds() / 86400.0)
    array = np.asarray(durations) if durations else np.asarray([np.nan])
    return {
        "n": float(len(scored)),
        "median_days": float(np.nanmedian(array)),
        "p90_days": float(np.nanpercentile(array, 90)),
        "censoring_rate": float(np.mean([1.0 if pd.isna(case.timestamps.get("end", pd.NaT)) else 0.0 for case in scored])),
    }


def run_experiment_matrix(engine: SimulationEngine, policies: Sequence[Policy], replications: int = 40) -> pd.DataFrame:
    """Paired replications: replication r is shared across policies."""
    rows = []
    window_start = pd.Timestamp("2026-01-01")
    window_end = pd.Timestamp("2028-01-01")
    for policy in policies:
        for replication in range(replications):
            result = engine.run(policy, replication, window_start, window_end)
            row = {"policy": result.policy, "replication": result.replication}
            row.update(result.metrics)
            rows.append(row)
    return pd.DataFrame(rows)
