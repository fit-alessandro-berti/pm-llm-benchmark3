# 1. Cluster diagnoses

**Working assumptions** (labelled so they can be challenged)

- **A1 (display resolution).** Every lifecycle field (`queue_arrival`, `start`, `complete`) is shown as HH:MM, including the 1-second PLC and scanner sources. Only `recorded_at` carries seconds. I treat lifecycle equality as equality at the displayed minute, so the effective tolerance is about ±30 s. The sub-minute "precision" claims apply, if at all, to the stored or recorded values, not to the exported lifecycle fields.
- **A2 (capacities).** RBT-7 = 4 and analyst_pool = 3 are given. T-B, T-C, T-D, T-G and T-H are assumed to be single-operator or single-station resources (capacity 1). T-F is unknown.
- **A3 (semantics).** `complete` is the item's end of work when the item was processed alone. `start` may instead mean "item opened", "group begun", or "batch cycle started".
- **A4 (queue arrivals).** `queue_arrival` comes from an independent upstream clock and is treated as reliable.
- **A5 (MES rounding).** The legacy MES rounds start down and complete up to quarter-hour boundaries, as the scenario states. The exact rule is undocumented, so this is a working hypothesis.
- **A6 (safety clock).** The offset between the T-H safety-check clock and the repair-queue clock is unknown. The 15:00–15:35 window is used only as a hypothesis.

# 3. Consequences for performance analysis

**Waiting time** is `start  queue_arrival`. It is inflated when start marks a batch cycle, group begin, or shift boundary, and understated when start is copied or floored. **Service time** is `complete  start`. It is inflated when complete is a bulk submission or a session end, and zero when both fields are the same administrative value. **Utilization** is summed busy time divided by capacity times window. It is overstated when overlapping intervals are summed without capacity capping. **Bottleneck detection** depends on whether the artefact inflates waits, service, or utilization at a given resource.

**Why G6-like data can create both inflated waiting and near-zero service.** The single administrative value 17:00 is used as both `start` and `complete`. Waiting is measured from `queue_arrival` to that value, so the entire open period (35–175 min) is labelled as queue wait. Service is measured from `start` to `complete`, so it is zero by construction. The two fields are not independent observations of the same process: they are the same record. The consequence is that queue analysis reports a severe bottleneck at T-F while service and utilization report no work at all. Any model that ranks activities by wait/service ratio will return an infinite ratio. Throughput also looks like zero until 17:00 and then seven completions in one instant, which creates a false burst. Conformance checks are unreliable too: with identical timestamps, ordering depends on `sequence_no`, which here records entry order, not occurrence order.

# ---- 3. Pandas fallback batch classifier (independent of PM4Py) ----
def classify_group(sub, tol_s=0):
    S = sub["start_timestamp"].tolist()
    C = sub["time:timestamp"].tolist()
    pairs = list(itertools.combinations(range(len(sub)), 2))
    if not pairs:
        return "singleton"
    d = lambda a, b: abs((a - b).total_seconds())
    same_s = any(d(S[i], S[j]) <= tol_s for i, j in pairs)
    same_c = any(d(C[i], C[j]) <= tol_s for i, j in pairs)
    overl = any(S[i] < C[j] and S[j] < C[i] for i, j in pairs)
    adj = any(d(S[i], C[j]) <= tol_s or d(S[j], C[i]) <= tol_s for i, j in pairs)
    if same_s and same_c:
        return "simultaneous"
    if same_s:
        return "start_batching"
    if same_c:
        return "end_batching"
    if overl:
        return "concurrent"
    if adj:
        return "sequential"
    return "loose_link_only"

def pandas_batches(ev, merge_s, min_size):
    rows = []
    for (cl, res, act), g in ev.groupby(["cluster", "org:resource", "concept:name"], sort=False):
        g = g.sort_values(["start_timestamp", "time:timestamp"]).reset_index(drop=True)
        n = len(g)
        parent = list(range(n))

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        S = g["start_timestamp"].tolist()
        C = g["time:timestamp"].tolist()
        # Link members whose starts OR completes lie within merge_distance
        for i, j in itertools.combinations(range(n), 2):
            if (abs((S[i] - S[j]).total_seconds()) <= merge_s
                    or abs((C[i] - C[j]).total_seconds()) <= merge_s):
                parent[find(i)] = find(j)
        comps = {}
        for k in range(n):
            comps.setdefault(find(k), []).append(k)
        for mem in comps.values():
            if len(mem) >= min_size:
                rows.append({"cluster": cl, "resource": res, "size": len(mem),
                             "label": classify_group(g.iloc[mem])})
    return pd.DataFrame(rows, columns=["cluster", "resource", "size", "label"])

def parse_pm4py(res):
    """Best-effort mapping of PM4Py output to clusters via case IDs; inspect the object shape per version."""
    items = res.to_dict("records") if isinstance(res, pd.DataFrame) else list(res or [])
    out = []
    for item in items:
        text = str(item).lower()
        label = next((lab for ph, lab in PM_PHRASES if ph in text), "unparsed")
        hits = [cl for cl, cases in case_map.items() if any(c.lower() in text for c in cases)]
        for cl in hits or ["unmapped"]:
            out.append((cl, label))
    return out
