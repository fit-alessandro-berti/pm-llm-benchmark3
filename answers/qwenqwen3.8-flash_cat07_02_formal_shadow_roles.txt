def to_network_df(net):
    if isinstance(net, pd.DataFrame):
        out = net.copy()
    elif hasattr(net, "nodes") and hasattr(net, "edges"):
        out = pd.DataFrame(
            [
                {"source": e[0], "target": e[1], "weight": e[2] if len(e) > 2 else 1}
                for e in net.edges
            ]
        )
    else:
        out = pd.DataFrame(net)

    rename = {}
    if "source" not in out.columns:
        for old in ["org:resource_source", "from", "resource_1"]:
            if old in out.columns:
                rename[old] = "source"
                break
    if "target" not in out.columns:
        for old in ["org:resource_target", "to", "resource_2"]:
            if old in out.columns:
                rename[old] = "target"
                break
    if rename:
        out = out.rename(columns=rename)
    if "weight" not in out.columns:
        out["weight"] = 1
    return out

for old, new in {

    "source": "resource_a",
    "resource_2": "resource_b",
    "org:resource_2": "resource_b",

}.items():
    if old in sim.columns and new not in sim.columns:

# ----------------------------------------------------------------------
# 5. Organizational networks

def to_network_df(net):
    """
    Convert PM4Py network output to a DataFrame with columns:
    source, target, weight.
    """
    if isinstance(net, pd.DataFrame):
        out = net.copy()
    elif hasattr(net, "nodes") and hasattr(net, "edges"):
        out = pd.DataFrame(
            [
                {
                    "source": edge[0],
                    "target": edge[1],
                    "weight": edge[2] if len(edge) > 2 else 1,
                }
                for edge in net.edges
            ]
        )
    else:
        out = pd.DataFrame(net)

    # Normalize source/target names.
    rename = {}
    if "source" not in out.columns:
        for old in ["org:resource_source", "from", "resource_1"]:
            if old in out.columns:
                rename[old] = "source"
                break

    if "target" not in out.columns:
        for old in ["org:resource_target", "to", "resource_2"]:
            if old in out.columns:
                rename[old] = "target"
                break

    if rename:
        out = out.rename(columns=rename)

    if "weight" not in out.columns:
        out["weight"] = 1

    return out

# 6. Operational interpretation

The mined structure should be used as a decision-support map, not as a simple org chart. The process owner needs to distinguish three things:

1. **Formal authority:** supervisor approval, security review, pricing exception ownership, quality gate.  
2. **Routine specialization:** front-office work, technical resolution, quality and knowledge work.  
3. **Shadow or bridging capacity:** Giorgio’s commercial support, Mateo’s coordination and preliminary approvals, Erik’s rare security gate, Nora’s automation boundary, and temporary surge agents.

## Staffing

Staffing decisions should not be based only on event counts.

- **Permanent front-office agents** should be separated from **temporary surge agents**. Kai and Lina close many cases, but their work is low-complexity and associated with reopened cases. They should not be promoted or treated as equivalent to Amira or Ben without validation depth and quality metrics.
- **Erik should not be understaffed because his volume is low.** His security work is rare but critical. Capacity planning should use critical-case arrival rates, security SLA, and risk exposure, not total events.
- **Fatima’s commercial role should have a named backup with formal delegation.** Giorgio provides useful resilience, but the duration increase during substitution shows that backup coverage is not equivalent.
- **Mateo should not be used as a standing supervisor substitute.** His preliminary approvals were frequently rechecked. He is better modeled as a coordination buffer, not as approval authority.
- **Chen and Dina may need different workloads.** Chen’s complexity and security-adjacent exposure suggest senior technical capacity. Dina’s similar activity mix but lower complexity may indicate a standard technical role or a development path.

## Training

- **Temporary agents** need targeted training on Validate Entitlement completeness, not just standard response throughput.
- **Giorgio** should either receive formal commercial training and delegated pricing authority, or his commercial work should be bounded and supervised.
- **Mateo** needs clear rules for escalation triage, security filtering, and preliminary approval. He should not make decisions that require formal supervisor or security authority unless explicitly delegated.
- **Dina** may benefit from exposure to higher-complexity cases under Chen’s mentorship if the organization wants to create a second senior technical specialist.
- **Quality analysts** should be trained as knowledge owners, not merely as checkers. Their KB activity is strategically important for reducing repeat work.

## Risk control

- Monitor **pricing exception duration and quality** when Giorgio covers Fatima.
- Monitor **approval rework rate** when Mateo performs preliminary approvals.
- Monitor **security referral filtering** to ensure low-risk filtering does not delay critical cases.
- Monitor **reopen rate by resource**, especially temporary agents, because high closure volume can hide validation failures.
- Monitor **automation handover quality**, because Nora’s high Validate counts may create false confidence in entitlement completeness.

## Resilience

The organization has useful resilience mechanisms:

- Giorgio can absorb commercial work.
- Mateo can coordinate escalations and filter referrals.
- Quality analysts convert incidents into knowledge.
- Temporary agents absorb low-complexity surge.
- Nora automates routine intake.

But resilience can become risk if informal roles are not governed. A resilient design should formalize backup roles with clear authority, training, and audit trails.

## Cautions

- **Do not change staffing based only on mined activity clusters.** Similar activity profiles can hide different authority, complexity, and risk. Chen and Dina are similar, but not identical in exposure. Kai and Lina are similar to permanent agents in activity mix, but not in competence or authority.
- **Do not treat temporary substitution as proof of permanent competence.** Giorgio’s pricing work and Mateo’s approvals show that the organization can survive absences, but duration increases and rework reveal that substitution is not equivalent to formal capability.
- **Do not reduce rare specialist capacity because of low volume.** Erik’s low event count is a warning sign of concentration risk, not evidence of surplus capacity.
- **Do not overload the escalation broker.** Mateo’s broad involvement is operationally valuable, but it can create a hidden single point of failure if coordination, security triage, and preliminary approvals all depend on him.
