## Why two DFG directions do not prove concurrency

The DFG is a **first-order (bigram) projection**: it marginalises away trace context, case attributes and lifecycle. Observing `CCER = 17` *and* `ERCC = 11` is compatible with at least six distinct generators:

1. **H1 – true concurrency** with variable durations (S2): both completion orders arise from one AND-block.
2. **H2 – XOR of two sequential routes**: a finance-first route (19) and an engineering-first route (11), possibly correlated with an unexported attribute.
3. **H3 – overlap**: ER *starts* before CC finishes but *completes* earlier/later; with completion-only logging, start order and completion order can invert.
4. **H4 – resource queueing**: one shared clerk alternates, producing both orders without any parallelism.
5. **H5 – ingestion artifacts** (S7): equal completion timestamps ordered by ingestion index.
6. **H6 – case mix**: external vs. stocked, or priority classes, correlated with routing.

Logically, concurrency *implies* both orders are observable; inferring concurrency *from* both orders is affirming the consequent. Worse, for **two atomic activities the hypotheses are formally indistinguishable**: `XOR(SEQ(CC,ER), SEQ(ER,CC))` and `AND(CC,ER)` have the *identical* trace language `{CC ER, ER CC}`. No amount of completion-order data — 30 traces or 30 million — can separate them. The same caution applies to `ERSC = 13` vs `SCER = 2`.

Note the asymmetry of evidential strength: **negative evidence is decisive here, positive evidence is not.** V5 (2 cases) *refutes* the universal claim "SC waits for both checks", and V2/V4/V7 (11 cases) *refute* S1 as a hard control. But no number of both-direction observations *establishes* parallelism. The choice between XOR, sequence and partial order must therefore be made on domain rules, structural extensibility and explicit uncertainty — and it becomes empirically decidable only with start timestamps, resources and case attributes (§9).

# 2. Shared Assumptions

* **A1 – Event semantics.** Every logged event is a *completion*. Activities are modelled as atomic, instantaneous transitions. Consequently "concurrent" in any candidate means **unordered completion**, never proven simultaneous execution; genuine overlap is *not representable* in any of the three models (D7, S7).
* **A2 – Case notion.** One trace = one custom production order. No cross-case interleaving, no batching, no resource contention modelled.
* **A3 – Cardinality.** Each activity occurs at most once per case (E4). No loops, no rework, no cancellation. All three languages are therefore **finite** (max 8 events).
* **A4 – Hard skeleton.** `R` is the unique start; `ACRPAR` is a strict suffix; `AR` the unique end (D1, D2, 30/30). `CC` and `ER` are mandatory and both precede `AC` (D3, 30/30).
* **A5 – Optionality = XOR with a silent branch.** `SC` and `EX` are represented as `XOR(activity, )`. The silent branch means **"no event observed for this activity"**, *not* "the activity was not required".
* **A6 – Missingness abstraction (disclosed).** The `SC` skip branch conflates two ontologically different phenomena: (a) legitimate stocked-component skip (S4) and (b) integration loss of an executed SC (S5). Control flow alone cannot separate them; all three candidates are therefore *equally blind* to this data defect, and none may be used to certify "SC was correctly skipped". Arithmetically (E1) 4–6 of the 7 SC-free cases are probably real skips and 1–3 are losses.
* **A7 – Absent external/stocked attribute.** The real process is data-conditional (S3/S4). All three models are **control-flow projections** of that data-conditional process; the projection turns a deterministic data-driven choice into apparent non-determinism. This is a deliberate, disclosed abstraction, not a claim about the business.
* **A8 – No frequency-based filtering.** All 7 variants are retained, including the two singletons; frequency is used only as *weak* prior information, never as a pruning threshold.
* **A9 – Soundness target.** Every candidate must be a sound WF-net (option to complete, proper completion, no dead transitions).
* **A10 – Fitness by construction.** All three languages contain all 7 observed variants, so alignment fitness = 1.0 is a *deductive* property, not a measured estimate.
* **A11 – Ties.** Where S7 could apply we treat order as unordered; we never convert an ingestion-index ordering into a precedence edge.

# 3. Conservative Candidate

**Inductive bias.** Minimal-language / closed-world memorisation: the model asserts that the language *is* the observed variant set, with the high-confidence skeleton factored out. It prefers precision over recall to the maximal degree, treats every unwitnessed interleaving as forbidden, and treats low-frequency variants as fully legal (no pruning). Structurally it is a trace automaton (prefix acceptor restricted to complete observed traces) written as a block-structured ProcessTree. Its bias is "the sample is the population" — demonstrably false with 30 cases and two singleton variants, which is exactly why it is offered as a *lower bound* hypothesis rather than a recommendation.

**Formal expression.**

```
L_cons = {R} · M · {AC, RP, AR}          (concatenation, |L_cons| = 7)
M = { CC·ER·SC,  ER·CC·SC,  CC·ER,  ER·CC,  CC·SC·ER,  CC·ER·SC·EX,  ER·CC·EX·SC }
model_conservative = SEQ(R, XOR(SEQ(m) for m in M), AC, RP, AR)
```

**Code.**

from pm4py.objects.process_tree.obj import ProcessTree, Operator

    for c in n.children:
        c.parent = n
    return n

def leaf(k): return ProcessTree(label=A[k])
def seq(*c): return _node(Operator.SEQUENCE, c)
def xor(*c): return _node(Operator.XOR, c)

MIDDLES = [("CC", "ER", "SC"),        # V1  12

           ("CC", "ER"),              # V3   4
           ("ER", "CC"),              # V4   3

           ("CC", "ER", "SC", "EX"),  # V6   1
           ("ER", "CC", "EX", "SC")]  # V7   1

                         xor(*[seq(*[leaf(k) for k in m]) for m in MIDDLES]),
                         leaf("AC"), leaf("RP"), leaf("AR"))

**Duplicate labels and scalability (discussion).** The 7 branches duplicate `CC`/`ER`/`SC`/`EX`, so the Petri net has 25 labelled transitions for 8 activities. Consequences: (i) activity-level analytics become ambiguous (which `CC` place/transition fired?); (ii) alignments have many cost-tied optima, so reported "model moves" are arbitrary among duplicates; (iii) simplicity metrics degrade for reasons unrelated to real complexity; (iv) maintenance is brittle — one new interleaving requires a new branch. Scalability: enumerating *k* mutually unordered activities needs *k!* branches; adding a third unordered check and two optional activities would push this model from 7 to dozens/hundreds of branches. Factoring `R` and `ACRPAR` out of the XOR (done above) is the only compression that preserves the language exactly.

**Behavior deliberately excluded.**
* Every unwitnessed interleaving, e.g. `R ER CC SC EX AC RP AR` (mirror of V6) and `R CC ER EX SC AC RP AR` (mirror of V7).
* `EX` in an SC-free case (`R CC ER EX AC RP AR`).
* `EX` after `CC SC ER`.
* `SC` before `CC` (any position).
* Any repetition/rework, any skipping of CC or ER, any deviation from `ACRPAR`.

**Known underfitting risks.**
* **Coverage:** 30 cases / 7 variants with 2 singletons almost certainly under-samples a language of 12 traces; balanced/permissive enumerate 12/14. Expected generalisation is the worst of the three.
* **Missing-data legitimisation (compliance hazard):** because V3/V4 are admitted verbatim, the model *certifies* traces whose SC was lost by the integration (S5) as perfectly conforming — it hides the defect instead of flagging it.
* **False alarms:** a legitimate mirror interleaving (highly likely under S2) is reported as a violation; with ~37% ER-first cases, mirrored EX placements are near-certain in future data.
* **No abstraction of the data condition:** the model cannot express "SC required iff external", so it also cannot support the audit question stakeholders actually care about.

# 4. Balanced Candidate

**Inductive bias.** Weakest-commitment generalisation: keep every precedence that is either high-confidence (D1–D3) or witnessed in 100% of relevant cases *and* domain-motivated; drop every precedence that a single counterexample refutes; leave everything else **unordered** rather than choosing a direction. Uncertainty is managed structurally (absence of an edge = "we do not know") rather than by probabilistic annotation, and the two unwitnessed-but-rule-consistent enabler disjuncts of D5 are deliberately *not* both instantiated. Bias: prefer a small, falsifiable partial order over both memorisation and speculative freedom.

**Formal expression (POWL).**

```
nodes = { R, CC, ER, X_SC = XOR(SC, ), X_EX = XOR(EX, ), AC, RP, AR }
order = { RCC, RER,
          CCX_SC,                      # single witnessed enabler (E2, V5)
          CCX_EX, ERX_EX,             # AND-join (D6, S6, V6, V7)
          CCAC, ERAC, X_SCAC, X_EXAC,
          ACRP, RPAR }
no edge between CC and ER;  no edge between X_SC and X_EX
|L_bal| = 12 complete traces  (7 observed + 5 unobserved)
```

# 5. Permissive Candidate

**Inductive bias.** Maximal rule-consistent generalisation: treat the *permissions* in the domain rules as permissions to be exercised (D5 literally: **either** check may enable SC), keep only the high/medium-confidence *prohibitions* as hard constraints, and accept label duplication as the price of expressing an OR-join.                                     Transition, SilentTransition)

     "SC": "Supplier Confirmation", "EX": "Expedite Review",
     "AC": "Approve Configuration", "RP": "Release Production", "AR": "Archive Case"}

def tr(k):  return Transition(label=L[k])
def opt(k): return OperatorPOWL(Operator.XOR, [tr(k), SilentTransition()])

def branch(enabler):

    cc, er = tr("CC"), tr("ER")
    x_sc, x_ex = opt("SC"), opt("EX")

    po.order.add_edge(er, x_ex)
    return po                                                # CC/ER and SC/EX unordered

    model_permissive.order.add_edge(s, t)

* **Precision loss / compliance hazard:** it admits `SC` before `CC`, contradicting a 23/23 empirical regularity. If CC is a genuine financial gate, permissive silently authorises credit-unchecked procurement.
* Admits `EX` without `SC` (untestable today, H4).
* The XOR-of-two-partial-orders is a **modelling device** for an OR-join, not evidence that two organisational routes exist; readers may over-interpret it as H2.
* Still underfits reality if rework, cancellation, multi-supplier loops or partial approvals exist (A3).

# 7. Comparative Model Matrix

| Criterion | Conservative (ProcessTree, XOR enumeration) | Balanced (POWL partial order) | Permissive (POWL, OR-join via XOR) |
|---|---|---|---|
| Language size (deductive, complete traces) | **7** (= observed set) | **12** (7 + 5 new) | **14** (7 + 7 new); strict superset chain |
| Expected fitness on the 30 cases | **1.0 by construction** (all variants  L) | **1.0 by construction** | **1.0 by construction** |
| Expected precision risk | Lowest; 1.0 expected (no escaping edges: every enabled continuation is witnessed) | Low; one systematic escaping edge (`EX` enabled right after `CC ER`, never witnessed there) | Highest of the three; extra escaping (`SC` enabled after `ER` alone, never witnessed) |
| Generalization potential | Very low (closed world; two singleton variants memorised) | Medium-high (mirrors + optional-activity combinations) | High (also covers the unwitnessed D5 disjunct) |
| Structural simplicity | Worst: 25 labelled transitions for 8 activities; 7-branch XOR; duplicated CC/ER/SC/EX | **Best**: 8 labelled + 2 silent transitions, 11 precedence edges | Middle: 12 labelled + silent; labels duplicated ×2 by the OR-join device |
| Explainability | High as a *list* ("these 7 paths"), low as a *process* (no causal statement, duplicate-label ambiguity) | **High**: each edge traceable to a rule or a 100% regularity; each missing edge is an explicit "unknown" | Medium: must explain that the XOR is an OR-join encoding, not two real routes |
| Robustness to missing SC events | Poor: accepts only the two witnessed SC-free shapes; a lost SC in an EX case  false violation; and it *certifies* V3/V4 losses as conforming | Good: any SC-free shape accepted (but cannot flag the loss — A6) | Good: same as balanced, plus more shapes; also cannot flag the loss |
| Handling of unseen interleavings | None (every new interleaving = deviation) | Covers mirrors and optional-activity combinations; rejects SC-before-CC | Covers all rule-consistent interleavings incl. SC-before-CC |
| Commitments that could be wrong | "the sample is the population" | `CCSC` as a hard gate; EX  SC | that D5's ER-disjunct is real; that SC-before-CC is acceptable |
| Suitability for compliance | **Not recommended** for enforcement (hides missingness, flags legitimate variation); useful as an audit *lower bound* / regression baseline | **Recommended** for monitoring with two-tier deviation severity | Not for enforcement; use as a *sandbox* / upper envelope for triage |
| Suitability for exploration | Low | Medium | **High** |
| Maintenance / scalability | Poor (k! branch growth) | Good (add an edge) | Fair (OR-join duplication grows with #disjuncts) |

# 8. Validation Code

Limitations stated up front: (i) sampled playout **does not prove language inclusion** — it only samples; (ii) in general an infinite (loop) language cannot be exhaustively compared. **Here, however, all three candidates are loop-free with at most 8 visible events, so bounded enumeration is *provably exhaustive* provided the caps are not hit** — the harness reports the cap flag, and inclusion claims are made only when `capped == False`. (iii) Metric availability varies by pm4Py version; every call is wrapped and failures are reported as `UNAVAILABLE`, never fabricated.

Validation harness for the three candidate models (pm4py 2.7.x).
Self-contained: log reconstruction, model construction, conversion, soundness,
metrics, bounded exhaustive enumeration, sampled playout, positive/negative suite.
"""

def _pt(op, children):
    n = ProcessTree(operator=op, children=list(children))
    for c in n.children: c.parent = n
    return n

def xor(*c): return _pt(Operator.XOR, c)

def to_net(model):
    try:
        return pm4py.convert_to_petri_net(model)
    except Exception as e1:
        print(f"[convert] direct failed ({type(e1).__name__}); trying POWL->tree->net")
        pt = pm4py.convert_to_process_tree(model)
        return pm4py.convert_to_petri_net(pt)

# ------------------------------------------- 2. version-independent net semantics
def enabled(net, m):
    out = []
    for t in net.transitions:
        if all(m.get(a.source, 0) >= getattr(a, "weight", 1) for a in t.in_arcs):
            out.append(t)
    return out

def fire(t, m):
    m2 = dict(m)
    for a in t.in_arcs:
        w = getattr(a, "weight", 1); m2[a.source] = m2.get(a.source, 0) - w
        if m2[a.source] <= 0: m2.pop(a.source, None)
    for a in t.out_arcs:
        w = getattr(a, "weight", 1); m2[a.target] = m2.get(a.target, 0) + w
    return m2

def keyer(net):
    pid = {p: i for i, p in enumerate(net.places)}
    return lambda m: tuple(sorted((pid[p], c) for p, c in m.items()))

def enumerate_language(net, im, fm, max_visible=10, max_steps=40, max_states=300000):
    """Exhaustive for loop-free models IF capped == False."""
    k = keyer(net); fmk = k(dict(fm))
    q = deque([(dict(im), (), 0)]); seen = {(k(dict(im)), ())}
    lang, deadlocks, capped = set(), [], False
    while q:
        m, trace, steps = q.popleft()
        if len(seen) > max_states: capped = True; break
        if k(m) == fmk:
            lang.add(trace); continue
        en = enabled(net, m)
        if not en:
            deadlocks.append(trace); continue
        for t in en:
            tr2 = trace + ((t.label,) if t.label else ())
            if len(tr2) > max_visible or steps + 1 > max_steps:
                capped = True; continue
            m2 = fire(t, m); s2 = (k(m2), tr2)
            if s2 not in seen:
                seen.add(s2); q.append((m2, tr2, steps + 1))
    return {"language": lang, "capped": capped, "deadlocks": deadlocks, "states": len(seen)}

def soundness_by_reachability(net, im, fm, max_steps=60, max_states=100000):
    k = keyer(net); imk, fmk = k(dict(im)), k(dict(fm))
    q = deque([(dict(im), 0)]); reach = {imk: dict(im)}; edges = []; capped = False
    while q:
        m, k_ = k(m), None  # noqa  (placeholder removed below)
        break
    # explicit BFS (kept simple / readable)
    q = deque([(dict(im), 0)]); reach = {imk: dict(im)}; edges = []; capped = False
    while q:
        m, steps = q.popleft(); mk = k(m)
        if len(reach) > max_states: capped = True; break
        for t in enabled(net, m):
            m2 = fire(t, m); m2k = k(m2)
            edges.append((mk, m2k))
            if m2k not in reach:
                if steps + 1 > max_steps: capped = True; continue
                reach[m2k] = m2; q.append((m2, steps + 1))
    deadlocks = [mk for mk, m in reach.items() if mk != fmk and not enabled(net, m)]
    rev = {}
    for a, b in edges: rev.setdefault(b, set()).add(a)
    can = {fmk}; q = deque([fmk])
    while q:
        b = q.popleft()
        for a in rev.get(b, ()):
            if a not in can: can.add(a); q.append(a)
    stuck = [mk for mk in reach if mk not in can]
    fmd = dict(fm)
    improper = [mk for mk, m in reach.items()
                if mk != fmk and all(m.get(p, 0) >= c for p, c in fmd.items())]
    safe = all(c <= 1 for m in reach.values() for c in m.values())
    return {"reachable_markings": len(reach), "safe_1bounded": safe,
            "deadlocks": len(deadlocks), "cannot_reach_final": len(stuck),
            "improper_completion_markings": len(improper), "capped": capped}

def sampled_playout(net, im, fm, n=200, max_steps=60, seed=7):
    """Sampling only: proves NOTHING about language inclusion."""
    rng = random.Random(seed); k = keyer(net); fmk = k(dict(fm))
    traces, aborted = [], 0
    for _ in range(n):
        m, trace, steps = dict(im), [], 0
        while k(m) != fmk and steps < max_steps:
            en = enabled(net, m)
            if not en: aborted += 1; break
            t = rng.choice(en)
            if t.label: trace.append(t.label)
            m = fire(t, m); steps += 1
        else:
            if k(m) == fmk: traces.append(tuple(trace))
    return traces, aborted

# 9. Recommendation and Data-Collection Plan

**Immediate use: `model_balanced`.** It is the only candidate whose every edge is justified by a high-confidence rule or a 100% regularity, whose every *missing* edge is an explicit statement of ignorance, and which is small enough to explain to Finance, Engineering and Compliance in one picture. Deploy it for **monitoring with two-tier severity**, not for hard enforcement:

* **Tier 1 (hard violation):** any trace outside `L_perm` (e.g. AC before a check, EX before a check, SC after AC, repeats)  investigate immediately.
* **Tier 2 (ambiguous):** inside `L_perm` but outside `L_bal` (i.e. SC completed before CC)  route to a data-quality/ownership queue, **not** to a compliance case.
* **Tier 3 (silent risk):** any SC-free case  cannot be classified by control flow at all (A6); flag for attribute-based reconciliation.

**Sensitivity analysis: `model_permissive`** as the upper envelope; the difference `L_perm \ L_bal` (exactly 2 traces) *is* the operational definition of our uncertainty about D5. **`model_conservative` is retained only as a regression lower bound**, never for conformance decisions, because it simultaneously hides lost SC events and criminalises legitimate mirrors.

## Data-collection plan (designed to falsify, not to confirm)

**Attributes / fields to add**

| Field | Purpose | Ambiguity resolved |

| `lifecycle:transition` with **start** and **complete** (ideally also *enable/queue*) timestamps for CC, ER, SC, EX | interval overlap test | H1/H3 (concurrency/overlap) vs H2/H4 (sequential routes) — the *only* way to break the formal indistinguishability |

**Maximally informative future traces (targeted sampling, not random)**

1. `R ER SC CC … AC RP AR` — SC completing before CC. **Separates balanced from permissive** (refutes `CCX_SC`). Highest value per case.
2. Any case with `start_SC  complete_ER` **and** `start_SC < complete_CC` — proves the ER-enabler disjunct even if completion order looks CC-first.
3. `R CC ER EX AC RP AR` (EX on a stocked order) — tests EX  SC (H4) and the riskiest balanced/permissive admission.
4. CC/ER interval pairs: (a) overlapping intervals, (b) disjoint with ER first, (c) equal completion timestamps with different ingestion indices. (a)  concurrency; only (b) with a routing attribute  XOR of sequences; (c)  S7 artifact.
5. A case with `sc_required = true` and no SC event — a *confirmed* missingness case; used to calibrate a detector and to prove that V3/V4-shaped traces can be defective.
6. Any rework case (second ER / second SC) — falsifies A3 and would force a loop model, invalidating all three languages.
7. `R CC SC ER EX AC RP AR` — confirms the V5+EX combination (cheap, expected).

**Decision gates with pre-registered thresholds**

* **Concurrency vs XOR:** if 10% of cases show overlapping CC/ER intervals  adopt concurrency semantics (keep the edgeless partial order, document parallelism). If **zero** overlap in 60 cases *and* both orders persist with a routing attribute  replace the edgeless block by `XOR(SEQ(CC,ER), SEQ(ER,CC))` conditioned on that attribute (behaviourally identical today, but explanatory and extendible).
* **D5 disjunct:** if zero SC-before-CC in ~60 additional cases, the rule of three gives an upper bound of 5%  keep balanced's `CCSC` and demote permissive. If 2 such cases  promote permissive's OR-join.
* **Optionality vs missingness:** reconcile 100 cases; if measured loss rate 5–10% and `sc_required=false` explains ~15–20% of cases, split the skip into a *data-conditioned* skip (legitimate) and an *anomaly* branch (flagged).
* **EX cardinality/independence:** ~30–40 stocked cases and ~15 expedite cases suffice to detect an EXexternal dependency; if confirmed, nest EX inside the SC-present branch (a new balanced variant B).
* **Sample-size note:** more *completion-only* traces cannot resolve H1 vs H2 at all — priority is lifecycle/attribute enrichment, not volume.

**Plausible alternative interpretations that would materially change the recommendation**

* **ALT-1 — Missingness-dominated, data-conditional reality.** If reconciliation shows the SC loss rate is far above S5's estimate (say 20%+) *and* Finance's CC-gate is enforced for a high-value subpopulation, then the correct model is a **data-conditional XOR** (`external  SC mandatory`, `stocked  no SC`) with a CCER sequence in one branch. Balanced's skip branch would then be systematically wrong, and conservative would be actively harmful (it certifies losses). Recommendation would shift to "no conformance deployment; build the attribute-conditional model first".
* **ALT-2 — Expedite implies external (H4).** If `EX  sc_required`, then both balanced and permissive authorise a non-compliant path (`EX` without `SC`). The fix is to nest EX inside the SC-present branch (B), which *reduces* the language from 12 to 10 and would make balanced — not permissive — the correct upper envelope for expedite cases.
* **ALT-3 — Batch-ingestion artifact.** If many CC/ER pairs share completion timestamps and the 19/11 split is driven by ingestion index (S7), the underlying process may in fact be the *sequence* S1 describes, with the log misrepresenting order. Then a `CCER` sequence model plus a data-quality flag beats all three candidates, and my strongest structural claim ("S1 is refuted") would need to be re-scoped to "S1 is refuted *as recorded*", not "as executed".
* **ALT-4 — Filtered happy path.** If the export excluded rework, re-checks and cancellations, all three languages are severe underfits and the finite-language verification in §8 — while correct — is verifying the wrong scope. Recommendation would become: collect an unfiltered export before any conformance use.

None of these alternatives is excluded by the current 30 traces; each is decidable by a specific, cheap measurement listed in §9. That is the main argument for shipping **balanced as a hypothesis with two-tier severity**, and **permissive as its explicit uncertainty envelope**, rather than shipping any single model as "the process".
