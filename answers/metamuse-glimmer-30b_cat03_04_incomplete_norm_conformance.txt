## 1. Conformance semantics

Forbidden behavior is closed-world: status = forbidden and scope applies => any occurrence is a violation. Frequency does not excuse it.

Missing mandatory behavior is closed-world only for the mandatory columns inside the stated scope. Absence is a deviation unless scope does not apply, abstraction is too strict, or evidence is insufficient. For OC-DFG, the norm is often *eventually* expected, not directly-follows. A directly-follows summary can miss an intermediate event and therefore produce a false missing-mandatory signal. For ET–OT, mandatory means the event type must be linked to the object type in every instance of that event type unless the norm explicitly carves out an exception.

Unexpected but unregulated behavior is any relation whose norm status is unspecified. The norm is open-world here; presence is not a violation and absence is not a finding.

Typical-pattern absence is status = typical. The norm is open-world: exceptions are legitimate. Absence therefore warrants monitoring, not escalation, and must be interpreted with counts and business context.

Likely data-quality error is inferred when a relation is structurally implausible, e.g. Sensor Heartbeat linked to Invoice, object_cobirth Order-Payment, or a join on a reused numeric identifier. It is a deviation class separate from business non-compliance.

Abstraction mismatch occurs when the model family cannot express the normative intent. Directly-follows vs eventually, object_interaction vs object_codeath/cobirth, and missing attribute scoping are classic examples.

Insufficient evidence means the summary aggregates lose ordering, timestamps, or object identity. The graph shows a count but cannot prove conformance or violation for individual cases.

Open-world vs closed-world: forbidden and mandatory columns within scope are closed-world. All other relations are open-world: the norm deliberately does not cover them.

## 3. Detailed reasoning by model family

### OC-DFG
The OC-DFG can establish directly-follows frequencies between event types per object type. It cannot establish eventual reachability, timing, or causality. N1 is mandatory *eventually* but is measured as directly-follows; the 2 missing Create->Validate cases may be an abstraction mismatch with an unrecorded review in between. N3 forbidden is observable directly-follows: Cancel->Dispatch in 2 orders is a direct violation. N4 mandatory Pack->Dispatch is measured directly-follows; the 2 missing cases may be scope: packages not intended for external shipment. Typical N2 Validate->Close is observed 83 times, Validate->Issue Invoice 72 times, both are plausible intermediates and not violations. Interpreting an eventually expected rule as directly-follows inflates false positives.

### OTG
OTG can establish existence and weight of object relationships and lifecycles. It cannot establish temporal order or event-level linking. T1 mandatory Order-Item interaction is present 1450, T2 mandatory Package-Delivery interaction is present 200. T6 forbidden object_cobirth Order-Payment is present weight 1, a closed-world violation. T3 typical Invoice-Payment interaction is present 92, consistent with typical. T4 and T5 unspecified interactions are present and therefore unregulated. Package object_codeath Delivery 7 is unregulated; the norm says nothing about codeath. Conformance can be conforming in OTG but suspicious in ET-OT if the event level link is missing.

### ET-OT
ET-OT can establish which object types are linked to each event type. It cannot establish multiplicity, order, or whether a link is required for all instances. E1,E2,E3,E4,E5,E6,E7 are mandatory and are satisfied in counts except Dispatch Package Delivery 198 vs 200 and Add Item Order 1448 vs 1450. E8 mandatory Record Payment Invoice is missing for 1 payment; finance says unapplied cash is possible but not labelled, so evidence is insufficient. E10 forbidden Sensor Heartbeat Invoice is present weight 1, likely data-quality. A relation can be conforming at ET-OT level and still be suspicious at OC-DFG level, e.g. Dispatch Package links Package but not Delivery.
