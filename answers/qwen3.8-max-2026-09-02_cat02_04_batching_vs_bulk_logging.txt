# 3. Consequences for performance analysis

The following bias assessments are estimates. They assume the usual definitions: waiting time is measured from `queue_arrival` to `start`, service time from `start` to `complete`, and utilization from the summed busy intervals attributed to a resource.

Why G6-like data can create both inflated waiting and near-zero service:

- The waiting calculation uses `queue_arrival` to the recorded `start`. If all cases are stamped at 17:00, every arrival from 14:05 onward accumulates a long apparent wait.
- The service-time calculation uses `start` to `complete`. If both are 17:00, service time becomes zero.
- Therefore, the same logging behavior can make the resource look like a severe queue bottleneck while also making the actual work look instantaneous.
- This is a classic logging-batch artifact: the batch stamp records the moment of bulk entry or bulk submission, not the physical execution interval.

## At least three cases where the same temporal pattern supports multiple physical explanations

1. **G1: identical start and end times.**  
   This can mean a genuine simultaneous four-item machine batch. It can also mean a PLC batch cycle where the system writes all item events at cycle completion, or a fixture-fill process where items queue until the batch can start.

2. **G2: identical starts but staggered ends.**  
   This can mean a common group start followed by serial work. It can also mean a single inspector multitasking across items, or minute-level rounding hiding slightly different starts.

3. **G3: staggered starts but identical ends.**  
   This can mean folder-level bulk submission, actual simultaneous completion, or open forms left active while the reviewer multitasks. The supplied context favors bulk submission, but the temporal pattern alone does not prove it.

4. **G5: overlapping intervals under one resource.**  
   This can mean one analyst multitasking, several analysts using a shared login, or timestamp imprecision exaggerating overlap. The shared-account context makes the shared-login explanation strongest, but not certain.

5. **G6: identical zero-duration stamps for many cases.**  
   This can mean a genuine bulk system action, retrospective end-of-shift data entry, or a system default timestamp. All three produce the same observed equality but have different operational meanings.
