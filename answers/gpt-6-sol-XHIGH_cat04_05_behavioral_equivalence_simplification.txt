# 1. Equivalence Notions

Let `O`, `A`, `C`, `P`, `R`, and `F` abbreviate Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, and Close Case. A trace is **complete** when execution reaches the final marking. Hiding `tau` deletes silent transitions from the execution sequence; it does not delete a visible `C` or `P`.

- **Visible trace equivalence:** the two models have the same set of complete sequences over `{O,A,C,P,R,F}` after hiding `tau`.
- **P3 bounded visible-language equivalence:** those sets are equal after restricting each complete trace to at most 12 visible events and at most three `A` occurrences. This says nothing, by itself, about longer traces.
- **P1 business-relevant equivalence:** retain the complete visible sequence, partition its interior at each `R`, and retain the position and number of `C` and `P` events in each resulting analysis attempt. Two models are equivalent only if these observations agree for every complete trace. In particular, a compliant attempt has its own `C` before the following `R` or `F`; the optional `P` remains observable.
- **P2 dashboard equivalence:** map a complete trace to `(O first, F last, number of A, whether any R, whether any C)`, after discarding `P`, `tau`, extra `C` occurrences, and the interleaving of `A` with `C`. Compare the sets of these tuples. Here both models always have `C = true` and `number of A >= 1`.

Repeated visible labels are distinguished by **occurrence position and count in a sequence**, not by persistent event identity. Neither tree supplies revision identifiers. For P1, `R` boundaries associate occurrences with attempts; if a real case requires an identifier to establish which revision a check examined, that extra fact is outside both models.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
| --- | --- | --- | --- |
| Loop scope | The parallel `A`/`C` block and optional `P` are in the first loop child. | Only `A` and optional `P` are in the loop; `C` is a sibling of the entire loop. | A repeats `C` with every analysis attempt; B does not. |
| Minimum and maximum `C` occurrences | For `n >= 1` attempts, exactly `n`; minimum one, unbounded maximum. | Exactly one, regardless of `n`; minimum and maximum one. | Counts differ whenever `n >= 2`. |
| Possible `C` placement | Before or after its attempt's `A`, but before that attempt's `P` (if present) and before its following `R` or `F`. | Anywhere in the loop's visible execution: before the first `A`, within or between attempts, or after the last `P`; always before `F`. | B can leave an attempt without a check and can put `C` after `P`. |
| Optional approvals | Zero or one `P` after the parallel join in each attempt. | Zero or one `P` after `A` in each attempt. | Both allow `0..n` approvals, but their order relative to `C` differs. |
| Concurrency | `A` and `C` are concurrent in every iteration. | The single `C` is concurrent with the whole loop. | Similar labels do not imply the same interleavings. |
| Join before `F` | The final iteration's parallel block and approval choice must finish. | Both the loop and the single `C` must finish. | Neither model can close before its outstanding parallel branch finishes. |

More formally, put `Q = (AC | CA)P?`, where `P?` is either `P` or the empty word. Then

`L_A = { O Q (R Q)^(n-1) F : n >= 1 }`, with an independent choice of `Q` on each attempt.

For B, choose `n >= 1` and independently choose each optional approval in `D = AP? (R AP?)^(n-1)`. Its language consists of `O`, then `D` with exactly one `C` inserted at any position, then `F`. This insertion description expresses the parallel interleaving, including insertion before the first or after the last event of `D`.

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
| --- | --- | --- | --- | --- |
| Full visible traces after `tau` hiding | not equivalent | Proof from the language forms above | A has one `C` per attempt; B has one per case. B also admits `O A P C F`. | This compares labels and order, not event identities. |
| P1 operational compliance | not equivalent | Proof | With two attempts, B can close with one attempt unchecked; A gives each `R`-delimited attempt a `C`. | A allows `C` before its `A`. If compliance means checking the *completed* analysis, A also needs a stricter ordering. |
| P2 dashboard | equivalent only under stated abstraction | Proof | Both yield exactly the tuples for `n >= 1` analyses, `R` present iff `n > 1`, and `C = true`, with `O` first and `F` last. | The abstraction deliberately discards check counts, approval, and check placement. |
| P3 bounded visible language | not equivalent | Exhaustive bounded argument and short witnesses | Unequal traces already occur with one or two attempts and well under 12 events. | Bounded inequality is decisive here; bounded *equality* would not prove unbounded equality. |

# 4. Counterexample Traces

The abbreviations from Section 1 are used in this table. Every row is a complete visible trace: `O` begins it and `F` ends it.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
| --- | --- | --- | --- | --- | --- |
| A1 | `O A C R A C F` | Yes | No | The second `C`: B has only one check in the entire case. | P1, P3, full visible language |
| A2 | `O C A P R C A P F` | Yes | No | The second `C`: A checks both attempts. | P1, P3, full visible language |
| B1 | `O A P C F` | No | Yes | A requires its `C` before that attempt's optional `P`; B can check afterward. | P1, P3, full visible language |
| B2 | `O A R A C F` | No | Yes | The first `R` occurs before any `C`, leaving A's first attempt unchecked. | P1, P3, full visible language |

There is no inclusion in either direction. With one attempt and no approval, both allow `O A C F` and `O C A F`; with one approval, both allow `O A C P F` and `O C A P F`. Those four are their entire visible-language intersection: with two or more attempts the `C` counts differ. The `tau` choice merely omits an approval in a particular attempt. It cannot supply or remove a `C`, and it does not erase B's additional placement `P C`.

# 5. Bounded Comparison Code

This program **exhaustively explores the bounded marking/visible-prefix state space**; it is not random playout. A state is revisited only if both its marking and visible prefix match. Silent firings keep the prefix unchanged, final-marking equality records a complete trace, and the two P3 limits prune successors. Soundness is checked before exploration.

```python
from collections import deque
import pm4py
from pm4py.objects.petri_net import semantics

model_a = "->('Open Case',*(->(+('Analyze Revision','Check Revision'),X('Approve Revision',tau)),'Rework Case'),'Close Case')"
model_b = "->('Open Case',+('Check Revision',*(->('Analyze Revision',X('Approve Revision',tau)),'Rework Case')),'Close Case')"

tree_a = pm4py.parse_process_tree(model_a)
tree_b = pm4py.parse_process_tree(model_b)

def accepting_net(tree):
    net, initial, final = pm4py.convert_to_petri_net(tree)
    result = pm4py.check_soundness(net, initial, final,
                                    print_diagnostics=True)
    sound = result[0] if isinstance(result, tuple) else result
    if not sound:
        raise ValueError("Unsound accepting net")
    return net, initial, final

def marking_key(marking):
    # Place objects stay fixed during this traversal; token counts matter.
    return tuple(sorted((id(place), count)
                        for place, count in marking.items() if count))

def bounded_language(net, initial, final):
    queue = deque([(initial, ())])
    visited = set()
    accepted = set()
    while queue:
        marking, visible = queue.popleft()
        state = (marking_key(marking), visible)
        if state in visited:
            continue
        visited.add(state)

        if marking == final:  # complete accepting run, not just a deadlock
            accepted.add(visible)
            continue

        for transition in pm4py.get_enabled_transitions(net, marking):
            next_visible = (visible if transition.label is None else
                            visible + (transition.label,))
            if (len(next_visible) > 12 or
                    next_visible.count("Analyze Revision") > 3):
                continue
            next_marking = semantics.execute(transition, net, marking)
            if next_marking is not None:
                queue.append((next_marking, next_visible))
    return accepted

la = bounded_language(*accepting_net(tree_a))
lb = bounded_language(*accepting_net(tree_b))
print("bounded equivalent:", la == lb)
print("A / B / shared:", len(la), len(lb), len(la & lb))
print("unique to A:")
for trace in sorted(la - lb):
    print(trace)
print("unique to B:")
for trace in sorted(lb - la):
    print(trace)
```

The expected set sizes are `|la| = 76`, `|lb| = 85`, `|la ∩ lb| = 4`, hence 72 A-only and 81 B-only traces. These counts can also be derived directly. A trace with `n` attempts and `k` approvals has `3n + 1 + k` visible events; B's has `2n + 2 + k`. The bound permits `n <= 3`; for A at `n = 3`, only `k <= 2` fits. Thus A contributes `4 + 16 + (4^3 - 2^3) = 76` traces. For B, inserting its unique `C` into each approval choice contributes `5` at `n = 1`, `20` at `n = 2`, and `60` at `n = 3`, totaling `85`. The four shared traces are listed in Section 4. The exploration terminates because the sound converted nets are bounded and there are finitely many markings paired with prefixes inside the stated limits.

# 6. Stochastic and Footprint Comparison

`pm4py.discover_footprints(...)` summarizes local relations. It can highlight structural differences here: A has a `C`-then-`P` relation inside an attempt, while B can place `C` on either side of `P` because the check branch runs in parallel with the loop. Footprints discard enough history that equal footprints would still not establish equal complete trace languages, attempt-level check counts, or P1 compliance.

`pm4py.get_stochastic_language(...)` estimates a distribution from an event log. `pm4py.compute_emd(...)` compares two such distributions under its trace-distance cost. The following uses **declared illustrative samples**, each with two traces of equal empirical weight; the resulting probabilities are properties of these samples, not probabilities supplied by either process tree.

```python
import pm4py
from pm4py.objects.log.obj import Event, EventLog, Trace

tree_a = pm4py.parse_process_tree(
    "->('Open Case',*(->(+('Analyze Revision','Check Revision'),X('Approve Revision',tau)),'Rework Case'),'Close Case')")
tree_b = pm4py.parse_process_tree(
    "->('Open Case',+('Check Revision',*(->('Analyze Revision',X('Approve Revision',tau)),'Rework Case')),'Close Case')")
foot_a = pm4py.discover_footprints(tree_a)
foot_b = pm4py.discover_footprints(tree_b)
print("footprints equal:", foot_a == foot_b)

def example_log(rows):
    return EventLog([Trace([Event({"concept:name": label})
                            for label in row]) for row in rows])

a_log = example_log([
    ["Open Case", "Analyze Revision", "Check Revision", "Close Case"],
    ["Open Case", "Analyze Revision", "Check Revision", "Rework Case",
     "Analyze Revision", "Check Revision", "Close Case"],
])
b_log = example_log([
    ["Open Case", "Analyze Revision", "Check Revision", "Close Case"],
    ["Open Case", "Analyze Revision", "Rework Case", "Analyze Revision",
     "Check Revision", "Close Case"],
])
dist_a = pm4py.get_stochastic_language(a_log)
dist_b = pm4py.get_stochastic_language(b_log)
print("sample EMD:", pm4py.compute_emd(dist_a, dist_b))
```

In PM4Py 2.7.23.4 these footprints differ, and this toy sample has EMD about `0.07143`; neither number is an equivalence test. A low EMD can coexist with a rare but critical unchecked revision. To use stochastic evidence operationally, estimate probabilities from real case logs or declare a branch/loop distribution, use comparable sampling for both models, and still check the P1 invariant separately. Random `pm4py.play_out(...)` samples would likewise be non-exhaustive.

# 7. Complexity Comparison

Counting the root as depth level 1 and counting duplicate labels as occurrences beyond the first of each **visible leaf label** gives:

| Measure | Model A | Model B | Interpretation |
| --- | ---: | ---: | --- |
| Process-tree nodes | 12 | 12 | Equal size by node count. |
| Depth, in node levels | 5 | 6 | B nests its approval choice one level deeper. |
| Operator nodes | 5 | 5 | Each has sequence, loop, parallel, and exclusive-choice structure. |
| Visible leaves | 6 | 6 | Same activity labels. |
| Silent leaves | 1 | 1 | Each has one `tau` option. |
| Duplicate visible-label count | 0 | 0 | Looping creates repeated *events*, not duplicate tree leaves. |
| Converted net: places / transitions / arcs | 9 / 9 / 20 | 7 / 7 / 16 | B converts to a smaller net in PM4Py 2.7.23.4. |
| `simplicity_petri_net` | about 0.81818 | about 0.77778 | This metric ranks A slightly higher despite B's smaller net; it is not a language-equivalence measure. |

The structural counts and implementation-specific net measurements can be reproduced as follows:

```python
from collections import Counter
import pm4py

def tree_stats(root):
    labels = []
    silent = 0
    operators = 0
    def visit(node, depth):
        nonlocal silent, operators
        if not node.children:
            if node.label is None:
                silent += 1
            else:
                labels.append(node.label)
            return 1, depth
        operators += 1
        child_stats = [visit(child, depth + 1) for child in node.children]
        return 1 + sum(n for n, _ in child_stats), max(d for _, d in child_stats)
    nodes, depth = visit(root, 1)
    duplicates = sum(count - 1 for count in Counter(labels).values())
    return dict(nodes=nodes, depth=depth, operators=operators,
                visible=len(labels), silent=silent, duplicates=duplicates)

sources = {
    "A": "->('Open Case',*(->(+('Analyze Revision','Check Revision'),X('Approve Revision',tau)),'Rework Case'),'Close Case')",
    "B": "->('Open Case',+('Check Revision',*(->('Analyze Revision',X('Approve Revision',tau)),'Rework Case')),'Close Case')",
}
for name, source in sources.items():
    tree = pm4py.parse_process_tree(source)
    net, initial, final = pm4py.convert_to_petri_net(tree)
    print(name, tree_stats(tree),
          (len(net.places), len(net.transitions), len(net.arcs)),
          pm4py.simplicity_petri_net(net, initial, final))
```

# 8. Simplified Model

I target **P2 exactly**, since an executive dashboard only needs the case endpoints, analysis count, whether rework occurred, and the Boolean fact that a check occurred. A compact tree is:

```text
->('Open Case',+('Check Revision',*('Analyze Revision','Rework Case')),'Close Case')
```

Its single `C` runs in parallel with the analysis/rework loop. The loop's first child executes at least once, so an analysis always occurs; `F` waits for both branches. The tree has **8 nodes, depth 4, 3 operators, 5 visible leaves, and no silent leaves**, versus 12 nodes and depth 5 or 6 in the originals. Its PM4Py 2.7.23.4 conversion has 6 places, 5 transitions, 12 arcs, and `simplicity_petri_net` about `0.84615`.

```python
import pm4py

simplified_model = pm4py.parse_process_tree(
    "->('Open Case',+('Check Revision',*('Analyze Revision','Rework Case')),'Close Case')"
)
simple_net, simple_initial, simple_final = pm4py.convert_to_petri_net(
    simplified_model
)
result = pm4py.check_soundness(simple_net, simple_initial, simple_final,
                                print_diagnostics=True)
assert result[0] if isinstance(result, tuple) else result
```

| Property | Preservation in simplified model | Reason |
| --- | --- | --- |
| `O` first and `F` last | Exact | Root sequence and final parallel join. |
| At least one `A`; count of `A` | Exact under P2 | Same binary-loop iteration count `n >= 1`. |
| `R` count and whether any `R` | Exact under P2 | Exactly `n - 1` reworks. |
| At least one `C` | Exact under P2 | Exactly one check is mandatory. |
| Multiple checks and their attempt placement | Abstracted for P2; lost for P1 | P2 records only `C = true`; A's per-attempt checks are absent. |
| Optional approvals | Abstracted for P2; lost for P1/P3 | P2 hides `P`; the simplified raw language has no `P`. |
| Full or P3 visible language | Not preserved | Approval traces disappear, and A's repeated-check traces disappear. |

Regression **positive** complete traces for the simplified tree are `O C A F`, `O A C F`, `O A R A C F`, and `O A C R A F`. The first two cover both orders of the parallel branches; the latter two cover two attempts and different check placements. Regression **negative** traces are `O A F` (missing mandatory check) and `O C R A F` (rework before the loop's mandatory first analysis). Under P2, every trace of either original maps to a dashboard observation produced by this tree, and vice versa: choose the same `n`; approvals and extra checks are ignored by the projection.

# 9. Final Recommendation

For **P1**, use A if a check may occur anywhere within its `R`-delimited attempt; use a stricter `A`-then-`C` ordering if the check must examine a completed analysis. B is unsuitable because it permits unchecked attempts. For **P2**, either original is suitable, and the eight-node simplified tree can replace either as the dashboard model because their P2 observation sets are identical. For **P3**, the originals are not interchangeable, and the simplified tree is not a replacement for their full visible languages. Choose the model against the intended operational requirement rather than a structural or metric score. The P3 test proves inequality through short counterexamples here; in general, equality within a finite bound cannot establish unbounded equivalence.
