## 1. Consistency rules and evidence model

In evaluating this incomplete OCEL 2.0 dataset, I use the following rules and evidence models:

- **Hard invariant**: Every E2O relation must reference an existing event ID and object ID. O2O relations must reference existing objects and respect directional qualifiers (e.g., `DEL-X carries PK-7` is valid, but `PK-7 carries DEL-X` is not). No object can be related to an event outside its valid temporal lifecycle.
- **Strong default**: Lifecycle ordering must be preserved. An Order is created before Items are added; Items are added before they are packed; Packages are packed before they are dispatched; Deliveries are dispatched before they are confirmed; Invoices are issued before Payments are recorded. Items should correspond to their `order_hint` and Orders should correspond to the invoice's customer.
- **Weak heuristic**: Identifier similarity provides evidence. The event attribute `scanner_ref=PK8-2` strongly suggests a relation to `PK-8`. `external_ref=N-421?` suggests `DEL-Y` (carrier_ref=N-421). Arithmetic matching (e.g., `INV-44 total=230` = `130` + `100`) is informative but not conclusive due to potential fees, taxes, or split payments.
- **Evidence against a repair**: A proposed relation is contradicted if it violates a hard invariant, reverses lifecycle ordering, or creates a biologically impossible cardinality (e.g., a Package dispatched before any Item is packed into it). 

To combine these, I prioritize lifecycle ordering and existing O2O structure. Identifier matching is used as a strong hint, while arithmetic matching is treated with caution, serving only to increase confidence rather than confirm a relation. I explicitly avoid circular reasoning by not inferring an O2O edge solely from an E2O edge and then using the O2O edge as independent proof.

2. **Assuming mixed-order packaging is standard**: Adding `PK-8` to `ev08` without flagging the cross-order contamination might lead process miners to incorrectly optimize package consolidation rules that are actually data entry errors.
