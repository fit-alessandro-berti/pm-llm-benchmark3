## 1. Normalization Assumptions

1. **Clock-offset direction** is interpreted as `offset = recorded_clock - true_clock`; therefore `true_time = recorded_clock - offset`. For an offset bound `[a,b]`, a clock-time interval `[L,U]` becomes true time `[L-b, U-a]`.
2. **Timestamp-resolution uncertainty is applied before clock-offset correction.** For example, HUB “exact second” with measurement `±0.5 s` and offset `[-1 s, +1 s]` gives a true-time interval of `[recorded - 1.5 s, recorded + 1.5 s]`.
3. **Rounding semantics:**
   - Floor-to-minute local time means local clock time in `[displayed, displayed + 60 s)`.
   - Round-to-nearest-10-seconds means clock time in `[recorded - 5 s, recorded + 5 s)`.
   - Round-to-nearest-minute means clock time in `[displayed - 30 s, displayed + 30 s)`.
4. **Time-zone conversion** uses fixed IANA conversions for the stated dates: CEST = UTC+2, EDT = UTC-4, BST = UTC+1, CET = UTC+1.
5. **DST fold for T-405** treats `2025-10-26 02:xx` in Europe/Berlin as two possible UTC intervals: first fold CEST (UTC+2) and second fold CET (UTC+1). Ingestion order then removes impossible combinations.
6. **T-404 missing start** is inferred as `start = completion - duration`, with duration `[18,25]` minutes. The uncertainty in completion and duration is preserved.
7. **T-407 missing Alert_Received** is inferred as `Alert_Received = Alert_Sent + delivery_latency`, with delivery latency `[0,20]` minutes. I do **not** hard-enforce the unlogged causal “receipt before investigation start” constraint in the main table, but I note it as an alternative.
8. **Mobile entry delay for T-406** is treated as uncertainty about occurrence time, not just recording time: the user may have entered a time up to 5 minutes later than actual occurrence. This shifts the feasible occurrence interval earlier.
9. **Half-open vs closed intervals:** I use `[start, end]` for readability; small endpoint inclusivity differences do not materially affect the classifications.
10. **Main temporal-profile classification uses zeta = 2** unless otherwise stated; Section 4 shows zeta 1, 2, and 3.
11. **SLA pass regions** are `[0,900] s` for S1, `[0,2700] s` for S2, and `[0,129600] s` for S3. Negative durations imply a sequence/causality violation and are not accepted.

import pandas as pd
from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo

# ------------------------------------------------------------------
# Interval construction helpers
# ------------------------------------------------------------------

HUB_OFFSET = (-1, 1)        # (a,b)
OPS_BER_OFF = (-90, 120)
SENSOR_OFF = (-5, 5)
VENDOR_OFF = (-180, 180)
LEGACY_OFF = (-60, 60)
MOBILE_OFF = (-300, 300)
WEAK_OPS_OFF = (-720, 720)

def parse_utc(s):
    return datetime.fromisoformat(s.replace('Z', '+00:00'))

def hub_interval(ts):
    t = parse_utc(ts)
    return [(t - timedelta(seconds=1.5), t + timedelta(seconds=1.5))]

def floor_minute_interval(local_ts, tz_name, offset_bounds):
    tz = ZoneInfo(tz_name)
    naive = datetime.strptime(local_ts, '%Y-%m-%d %H:%M')
    local_start = naive.replace(tzinfo=tz)
    local_end = local_start + timedelta(minutes=1)
    utc_start = local_start.astimezone(timezone.utc)
    utc_end = local_end.astimezone(timezone.utc)
    a, b = offset_bounds
    return [(utc_start - timedelta(seconds=b), utc_end - timedelta(seconds=a))]

def sensor_round10_interval(ts):
    t = parse_utc(ts)
    # round to nearest 10: +/-5 s, plus clock offset [-5,+5]
    return [(t - timedelta(seconds=10), t + timedelta(seconds=10))]

def mobile_round_minute_interval(local_ts, tz_name, offset_bounds, entry_delay_minutes=5):
    tz = ZoneInfo(tz_name)
    naive = datetime.strptime(local_ts, '%Y-%m-%d %H:%M')
    local_round_start = naive.replace(tzinfo=tz) - timedelta(seconds=30)
    local_round_end = naive.replace(tzinfo=tz) + timedelta(seconds=30)
    occ_start = local_round_start - timedelta(minutes=entry_delay_minutes)
    occ_end = local_round_end
    utc_start = occ_start.astimezone(timezone.utc)
    utc_end = occ_end.astimezone(timezone.utc)
    a, b = offset_bounds
    return [(utc_start - timedelta(seconds=b), utc_end - timedelta(seconds=a))]

def berlin_fold_floor_minute_interval(local_ts, offset_bounds=LEGACY_OFF):
    """Return CEST and CET alternatives for ambiguous Berlin local time."""
    naive = datetime.strptime(local_ts, '%Y-%m-%d %H:%M')
    a, b = offset_bounds

    # First fold: CEST, UTC+2
    cest = timezone(timedelta(hours=2))
    local_start = naive.replace(tzinfo=cest)
    local_end = local_start + timedelta(minutes=1)
    utc_start = local_start.astimezone(timezone.utc)
    utc_end = local_end.astimezone(timezone.utc)
    cest_interval = (utc_start - timedelta(seconds=b), utc_end - timedelta(seconds=a))

    # Second fold: CET, UTC+1
    cet = timezone(timedelta(hours=1))
    local_start = naive.replace(tzinfo=cet)
    local_end = local_start + timedelta(minutes=1)
    utc_start = local_start.astimezone(timezone.utc)
    utc_end = local_end.astimezone(timezone.utc)
    cet_interval = (utc_start - timedelta(seconds=b), utc_end - timedelta(seconds=a))

    return cest_interval, cet_interval

sla_rules = {
    'S1': ('Alert_Received', 'Investigation_Start', 900),

temporal_profiles = {
    ('Alert_Received', 'Investigation_Start'): (600.0, 180.0),
    ('Investigation_Start', 'Containment_Complete'): (2100.0, 600.0),
    ('Alert_Received', 'Containment_Complete'): (2700.0, 720.0),

def get_duration_interval(case, start_act, end_act):
    s = interval_df[(interval_df['Case'] == case) & (interval_df['Activity'] == start_act)].iloc[0]
    e = interval_df[(interval_df['Case'] == case) & (interval_df['Activity'] == end_act)].iloc[0]
    lo = (e['Start'] - s['End']).total_seconds()
    hi = (e['End'] - s['Start']).total_seconds()
    return (lo, hi)

def classify_for_band(dur, lo, hi):
    d_lo, d_hi = dur
    if d_lo >= lo and d_hi <= hi:
        return 'CERTAIN_PASS'
    if d_hi < lo or d_lo > hi:
        return 'CERTAIN_VIOLATION'
    return 'POSSIBLE_VIOLATION'

print('--- Interval-based SLA classification ---')
for case in interval_df['Case'].unique():
    for rule, (start_act, end_act, threshold) in sla_rules.items():
        if not ((interval_df['Case'] == case) & (interval_df['Activity'] == start_act)).any():
            continue
        if not ((interval_df['Case'] == case) & (interval_df['Activity'] == end_act)).any():
            continue
        dur = get_duration_interval(case, start_act, end_act)
        cls = classify_for_band(dur, 0, threshold)
        print(f'{case} {rule} {dur}={cls}')

print('\n--- Interval-based temporal profile classification for zeta 1,2,3 ---')
for zeta in (1.0, 2.0, 3.0):

## 7. Governance Recommendation

1. **UTC storage:** Store all event timestamps in UTC. Retain the raw local timestamp, raw offset, time zone, and IANA time-zone identifier.
2. **Clock-offset telemetry:** Record source clock-offset bounds per event, not just daily averages. Include NTP diagnostic stamps, stratum, and whether the offset is measured, estimated, or missing.
3. **Resolution metadata:** Persist timestamp resolution and rounding semantics, such as exact, floor-to-minute, round-to-nearest-second, round-to-nearest-10-seconds, and user-entered rounding.
4. **DST fold logging:** For ambiguous local times, store UTC first and, when local time is needed, store the IANA time-zone **and** DST fold or UTC offset.
5. **Start/complete semantics:** Log lifecycle semantics separately: `Alert_Received`, `Investigation_Start`, `Investigation_Complete`, `Containment_Start`, `Containment_Complete`, `Closed_Incident`. Do not use `Investigation_Complete` as a substitute for `Investigation_Start`.
6. **Provenance and causality:** Assign each event a correlated incident ID, source-system ID, ingestion sequence, and causal parent-child identifiers where known. Log delivery latency separately from semantic receipt time.
7. **User-entered timestamps:** Distinguish entry time from actual occurrence time. For mobile/user-entered evidence, record both the entry timestamp and any known or estimated occurrence delay.
8. **Enforcement policy:** Interval overlap is **not sufficient for automatic legal/SLA enforcement**. Use:
   - `CERTAIN_PASS` / `CERTAIN_VIOLATION` for automated decisions when evidence is strong.
   - `POSSIBLE_VIOLATION` as a trigger for manual review.
   - `INDETERMINATE` as a request for additional evidence, not as a silent pass or violation.
9. **Analytics policy:** Keep midpoint-based PM4Py conformance as a lossy diagnostic only. Operational conclusions should use interval-based analysis and sensitivity tests.
