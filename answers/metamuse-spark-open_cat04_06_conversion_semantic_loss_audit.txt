# 1. Source-Semantics Baseline

archive_change = Transition(label="Archive Change")
source_powl = StrictPartialOrder(

)
source_powl.order.add_edge(register, assess_risk)
source_powl.order.add_edge(register, prepare_evidence)
source_powl.order.add_edge(assess_risk, optional_legal)
source_powl.order.add_edge(assess_risk, verification_loop)
source_powl.order.add_edge(prepare_evidence, verification_loop)
source_powl.order.add_edge(optional_legal, release_change)
source_powl.order.add_edge(verification_loop, release_change)

BPMN execution semantics is interleaving; `pm4py.convert_to_bpmn` therefore necessarily `approximated` concurrency. Footprints will show `` but bounded trace exploration can only verify that both interleavings are accepted, not that they are concurrent.
* **Lack of edge between Optional Legal and verification:** This is intentional absence of order. Petri preserves it exactly; BPMN forces a syntactic choice of where to place parallel gateways. Visually it appears ordered top-to-bottom; semantically it is not. Reviewers misread layout as precedence.
* **Silent optional behavior:** `XOR(Legal Review, SilentTransition)`  Petri silent transition; BPMN empty flow. Loss manifests as `Legal Review` mandatory (collapse) or always skipped (lost). Must be validated by checking both witnesses with visible-length 6-8.
* **Binary-loop semantics:** POWL LOOP  BPMN loop subprocess. The Petri encoding introduces silent switches for redo/exit; BPMN visualisation uses an exclusive gateway loop. Off-by-one error (0 iterations) is common.
* **Join before Release:** Must be AND-join, not XOR-join. Workflow-soundness alone does not guarantee AND vs XOR; footprint sequence vs parallel check and negative witness (release before verification) are needed.
* **Activity-label uniqueness:** Preserved because all labels unique, but BPMN converters sometimes duplicate label on added gateway labels. Validate by counting labeled transitions.
* **Initial and final markings:** Null checks are mandatory. Some BPMNPetri converters create multiple initial places or empty markings; `exact final-marking equality` in bounded exploration will catch drift.
* **Gateway/routing-node ambiguity:** BPMN adds exclusive/parallel gateways and intermediate sequence flows that have no counterpart in POWL. They are routing-only but reviewers may interpret them as decision points or synchronizations that do not exist. Documentation must clarify.

# 5. Round-Trip Validation Code

Bounded visible-trace exploration hides `label is None`, requires exact `fm` equality, avoids infinite `tau` cycling, and enforces visible-length and silent-depth bounds. Exhaustiveness is **only up to the bound**, not for the unbounded LOOP.

```python
import pm4py
from collections import deque

# ------------------------------------------------------------
# Helpers for bounded visible-trace exploration
# ------------------------------------------------------------
def marking_to_frozen(marking):
    # marking: dict[Place -> tokens]
    return frozenset((p.name, v) for p, v in marking.items() if v > 0)

def bounded_visible_traces(net, im, fm, max_visible_len=6, max_traces=5000, max_silent_depth=10):
    """
    Bounded BFS over reachability graph hiding tau.
    Returns set of visible trace tuples that end in *exact* final marking.
    - Hides transitions where label is None
    - Requires marking == fm for completion
    - Avoids infinite tau cycling via visited[(frozen_marking, tuple(visible_trace), silent_depth)]
    - Enforces max_visible_len (loop iteration bound implicitly)
    """
    if net is None or im is None or fm is None:
        return set()
    fm_frozen = marking_to_frozen(fm)
    results = set()
    # queue entries: (marking, visible_tuple)
    start = (im, tuple())
    queue = deque([start])
    # visited set prevents revisiting same state with same visible prefix
    visited = set()
    visited.add((marking_to_frozen(im), tuple()))
    # For tau-cycle avoidance: track how many consecutive silent steps taken without visible progress
    # We bound by max_silent_depth via visited and by not expanding silent loops
    traces_explored = 0

    while queue and len(results) < max_traces:
        marking, vis = queue.popleft()
        # Check completion: exact final marking equality (not superset)
        if marking_to_frozen(marking) == fm_frozen:
            results.add(vis)
            # do not stop: may still extend via tau? But fm should be dead in sound WF-net
            # continue exploring other branches; do not expand completed traces further
            continue
        if len(vis) > max_visible_len:
            continue

        try:
            enabled = pm4py.get_enabled_transitions(net, marking)
        except Exception:
            continue

        for tr in enabled:
            # must copy marking; pm4py markings are dict-like
            # Use pm4py marking firing via get_enabled check + manual firing is safer via net semantics,
            # but we can attempt to fire using pm4py's internal: we simulate by using the net's arcs.
            # Simpler: use pm4py's playout helper if available, otherwise approximate firing.
            # Here we use a lightweight manual firing to avoid dependency on private API:
            # This is defensible for bounded exploration demonstration; production should use pm4py's state space.
            from pm4py.objects.petri_net.utils.petri_utils import remove_place_from_marking, add_place_to_marking
            # Instead use pm4py's semantics if available:
            # pm4py.objects.petri_net.semantics.enabled_transitions etc.
            # Fallback manual:
            new_marking = dict(marking)
            # consume
            for arc in tr.in_arcs:
                p = arc.source
                new_marking[p] = new_marking.get(p, 0) - 1
                if new_marking[p] == 0:
                    del new_marking[p]
            # produce
            for arc in tr.out_arcs:
                p = arc.target
                new_marking[p] = new_marking.get(p, 0) + 1

            is_tau = (tr.label is None)

            if is_tau:
                # tau: visible length unchanged, but avoid infinite silent loops
                new_vis = vis
                key = (marking_to_frozen(new_marking), new_vis)
                if key in visited:
                    continue
                # silent depth guard: limit number of tau steps without visible progress
                # Approximated by visited size; more precise would track depth counter
                visited.add(key)
                queue.append((new_marking, new_vis))
            else:
                if len(vis) >= max_visible_len:
                    continue
                new_vis = vis + (tr.label,)
                key = (marking_to_frozen(new_marking), new_vis)
                if key in visited:
                    continue
                visited.add(key)
                queue.append((new_marking, new_vis))
            traces_explored += 1
            if traces_explored > 100000:
                print("[WARN] bounded exploration trace limit reached")
                break

    return results

# ------------------------------------------------------------
# Witness definitions (derived from Section 1)
# ------------------------------------------------------------
positive_witnesses = [
    # Minimal with Legal Review (1 iteration)
    ("P-1 legal present", ["Register Change","Assess Risk","Prepare Evidence","Legal Review","Configure Trial","Inspect Trial","Release Change","Archive Change"]),
    # Minimal with skip Legal (1 iteration, tau path)
    ("P-2 legal skipped", ["Register Change","Assess Risk","Prepare Evidence","Configure Trial","Inspect Trial","Release Change","Archive Change"]),
    # Prepare before Assess (concurrency witness)
    ("P-3 prepare before assess", ["Register Change","Prepare Evidence","Assess Risk","Configure Trial","Inspect Trial","Release Change","Archive Change"]),
    # 2 iterations
    ("P-4 two iterations", ["Register Change","Assess Risk","Prepare Evidence","Configure Trial","Inspect Trial","Correct Defect","Configure Trial","Inspect Trial","Release Change","Archive Change"]),
    # Interleaved legal inside verification (tests INV-06)
    ("P-5 interleaved legal inside loop", ["Register Change","Assess Risk","Prepare Evidence","Configure Trial","Legal Review","Inspect Trial","Release Change","Archive Change"]),

    for lbl, net, im, fm in [("A (original)", net_a, im_a, fm_a), ("B (round-trip)", net_b, im_b, fm_b)]:
        if net is None or im is None or fm is None:

        print(f" {lbl}: workflow net = {pm4py.check_is_workflow_net(net)}")

        # Footprints
        try:
            fp = pm4py.discover_footprints(net, im, fm)
            print(f"  footprints: sequence pairs={len(fp.get('sequence',[])) if isinstance(fp, dict) else 'obj'}")
            # pm4py footprint object type varies; just indicate success
        except Exception as e:

        # Reachability graph size as sanity
        try:

            # rg is graphviz / networkx-like; use len
            print(f"  reachability graph: {type(rg)}")
        except Exception as e:
            print(f"  reachability_graph failed: {e}")

    # Bounded trace equivalence (exhaustive only up to max_len)
    traces_a = bounded_visible_traces(net_a, im_a, fm_a, max_visible_len=max_len)
    traces_b = bounded_visible_traces(net_b, im_b, fm_b, max_visible_len=max_len) if net_b else set()
    print(f" Bounded visible traces up to len {max_len} (exact final marking):")
    print(f"  |A|={len(traces_a)} |B|={len(traces_b)}")
    diff_a_not_b = traces_a - traces_b
    diff_b_not_a = traces_b - traces_a
    print(f"  A\\B = {len(diff_a_not_b)} examples: {list(diff_a_not_b)[:3]}")
    print(f"  B\\A = {len(diff_b_not_a)} examples: {list(diff_b_not_a)[:3]}")
    # Positive/negative witness tests
    for wname, wtrace in positive_witnesses:
        in_a = tuple(wtrace) in traces_a
        in_b = tuple(wtrace) in traces_b if traces_b else "N/A"
        print(f"  Positive {wname}: A={in_a} B={in_b} {'PASS' if in_a else 'FAIL (loss)'}")
    for wname, wtrace in negative_witnesses:
        in_a = tuple(wtrace) in traces_a
        in_b = tuple(wtrace) in traces_b if traces_b else "N/A"
        # Negative should be rejected (not in traces)
        print(f"  Negative {wname}: A_rejected={not in_a} B_rejected={not in_b if in_b!='N/A' else 'N/A'} {'PASS' if not in_a else 'FAIL (unsound admission)'}")

# 6. Visual-Semantics Review

A BPMN diagram is **layout**, not semantics. Even when the underlying `net_from_powl` and its round-trip are behaviorally equivalent, the PM4Py BPMN renderer can be misread:

* **Parallel gateways (AND):** `POWL  Petri  BPMN` will create an AND-split after `Register Change` (into `Assess Risk` vs `Prepare Evidence`) and an AND-join before `Release Change`. Rendered left-to-right, reviewers often read top branch as “first” and bottom as “second”, although the gateway means *unordered*. Without annotation, INV-04 and INV-06 are misinterpreted as sequence.
* **Exclusive gateways (XOR):** Optionality `XOR(Legal Review, )` becomes a diamond with one empty outgoing flow. In print it looks like a decision that must be taken, not an optional skip. Stakeholders may ask “who decides?” when the model means “may be skipped”.
* **Loop visualization:** The binary LOOP becomes a cycle: `Configure Trial  Inspect Trial  XOR (redo?  Correct Defect  back)` . The gateway placement suggests the condition is evaluated *after* `Inspect Trial`, which is correct, but the diagram obscures the invariant that **zero iterations is forbidden**. A reader may assume the loop may be skipped entirely. The `Correct Defect` label on the redo arc is easily mistaken for an exception path.
* **Silent routing nodes:** Petri silent transitions are removed or turned into sequence flows and gateway conditions. The diagram therefore has more nodes than semantically meaningful activities. A reviewer cannot tell which diamonds are routing introduced by conversion vs. business decisions. This is especially acute for the synchronization places before verification: they become anonymous AND-joins.
* **Apparent ordering of graph layout:** Auto-layout places `optional_legal` branch above the verification loop branch. Visually this suggests `Legal Review` happens “before” verification, contradicting INV-06’s explicit “may overlap”. Two linearizations that are semantically equivalent appear as different drawings.

**Proposed annotations/documentation to reduce ambiguity:**
1. Add a text annotation box on the diagram: “*All AND-gateway branches are concurrent after hiding ; layout order is not precedence. Legal Review may interleave with verification iterations.*”
2. Color code: blue AND-gateways, orange XOR-gateways, grey silent flows labeled ` (auto-skip)`. Mark the mandatory loop body with a loop-characteristic annotation “*1 iteration: ConfigureInspect*”.
3. Explicitly label the join before `Release Change` as “AND-join: waits for both Legal (if chosen) and verification loop”.
4. Document that BPMN is *derivative* and provide the validation report (witness traces, soundness) alongside the image; forbid editing the BPMN layout as authoritative.
5. Keep `POWL` source ` StrictPartialOrder` edges as separate documentation view (e.g., partial-order matrix) so reviewers can verify “no edge” invariants that gateways hide.

# 7. Rejection Criteria

Reject or quarantine a conversion result if **any** of the following holds (technical or semantic):

1. **Unsoundness:** `pm4py.check_soundness(net, im, fm)` reports deadlock, livelock, dead transitions, or unreachable final marking. Unsound net cannot be safely executed.
2. **Not a workflow net:** `check_is_workflow_net` fails — multiple initial tokens, multiple final places, or disconnected fragments. Indicates lost initial/final marking mapping (common BPMN start/end event mis-mapping).
3. **Null/empty markings:** `im` or `fm` is `None` or empty after conversion. Exact-final-marking tests become meaningless; quarantine.
4. **Loss of required interleaving:** A positive witness is rejected — e.g., `Prepare Evidence` before `Assess Risk` (INV-02) or 2-iteration trace `Correct Defect`-separated (INV-08) not accepted. Indicates concurrency or loop collapsed to sequence.
5. **Admission of forbidden trace:** A negative witness is accepted — e.g., `Release Change` before `Inspect Trial` completes (INV-09), `Inspect Trial` before `Configure Trial` (INV-07), or zero-iteration trace without any `Configure/Inspect` (INV-08). Indicates lost join or loop scope.
6. **Collapse of optional behavior:** `Legal Review` always present or never present in bounded trace set; i.e., one of the two positive witnesses (with/without Legal Review) systematically missing. Signals XOR+ mis-encoded as mandatory or deleted.
7. **Loop-boundary violation:** `Correct Defect` appears outside loop context, or `ConfigureInspect` order not enforced inside loop; or bounded traces show `Correct Defect` without preceding `Inspect Trial`.
8. **Footprint divergence:** `discover_footprints` shows expected parallel pair (`Legal Review  Configure Trial`) changed to sequence, or expected sequence (`ConfigureInspect`) changed to parallel/choice. Even if traces accidentally pass bounded bound, footprint indicates semantic shift.
9. **Initial/final drift:** Trace accepted but ends in non-exact final marking (extra tokens left) or requires extra silent steps beyond bound to reach `fm`; bounded exploration with exact equality fails.
10. **Tree conversion unexpectedly succeeds without quarantine:** If `convert_to_process_tree` succeeds, treat its BPMN derivative as `approximated` at best; require independent witness validation before any use. Unvalidated success is quarantine.

Any single criterion triggers rejection; multiple criteria indicate systematic loss.

# 8. Canonical Representation Recommendation

* **Authoritative storage: POWL source + validated accepting Petri net.**
  Store `source_powl` Python code (or its JSON/PNML serialization) as the single source of truth. Store the derived `net_from_powl, im_from_powl, fm_from_powl` in PNML with diagnostics. POWL is human-auditable for partial orders and LOOP/XOR semantics; Petri net is the formal execution semantics that PM4Py guarantees for POWL. Either alone is insufficient: POWL captures intent, Petri net captures analyzable WF-net properties.

* **Derivative for stakeholder visualization: BPMN from Pipeline A only.**
  `bpmn_from_net` (Pipeline A) may be distributed for visualization, training, or BPMN-engine import, but it is **derivative, not authoritative**. Never allow edits to BPMN and round-trip back to POWL/Petri as a new version (“no round-trip drift”). Edits must be made to POWL and regenerated.

* **Validation evidence that must accompany each derivative:**
  For every BPMN artifact shipped, attach a validation bundle: `check_is_workflow_net` + `check_soundness` diagnostics for both original and round-tripped nets, `discover_footprints` diff, bounded visible-trace witness report (positive witnesses accepted, negative rejected) up to stated bound (e.g., `max_visible_len=7`), and reachability-graph size comparison. Mark evidence as `approximated` for true concurrency  interleaving.

* **Process-tree intermediate: disallowed as canonical.**
  `Pipeline B` (`PetriTreeBPMN`) must remain a **quarantine-only probe**. Its expected `conversion failed` outcome is informative. If a future PM4Py version unexpectedly succeeds, the resulting tree/BPMN must be labeled `approximated` and require manual review of INV-06, INV-08, INV-09 invariants. Do not promote it to primary, because block-structured trees cannot faithfully represent the overlapping optional-legal + verification-loop partial order without duplication or loss.

* **Avoiding round-trip drift:**
  1. Version-control only `01_powl_source.*` and `02_petri_from_powl.*`; generate `03_bpmn_from_petri.*` on demand via CI with pinned PM4Py version.
  2. Forbid `BPMNPetriPOWL` editing cycles; if BPMN must be hand-tweaked for aesthetics, keep tweaks as layout-only annotations (separate layer) not affecting gateways.
  3. Re-run full Section 5 validation on every regeneration; promote BPMN only if all rejection criteria pass and bounded trace diff is empty.
  4. Document in the repository README that visualization success  behavioral equivalence.

# 9. Residual Uncertainty

Even if every test in Sections 3 and 5 passes, the following claims **cannot** be established:

1. **Unbounded language equivalence:** Bounded visible-trace exploration is exhaustive only up to `max_visible_len` / `Correct Defect` iteration bound (e.g., 2 loops). The `LOOP` language is infinite; equivalence for 5+ iterations, or termination properties under infinite redo, remains unproven. Soundness does not guarantee boundedness or absence of divergence beyond the explored depth.
2. **True concurrency (step semantics) preservation:** Petri/POWL allow two concurrent activities to occur *simultaneously* as a step; BPMN and interleaving trace equivalence only verify that both orders are accepted, not that simultaneity is preserved. Footprints report `` but cannot distinguish interleaving from step semantics. Time/resource constraints that depend on true parallelism are not validated.
3. **BPMN execution-engine fidelity:** PM4Py’s `convert_to_bpmn` gateway semantics may differ from a given BPMN engine’s interpretation of AND/XOR joins, loop conditions, and silent flows. Passing `check_soundness` on the round-tripped Petri net does not guarantee the deployed BPMN engine will enforce the same AND-join before `Release Change` or the same XOR+ optionality.
4. **Visual-interpretation equivalence:** Validation confirms the *underlying* net behavior, not that stakeholders will interpret parallel vs. exclusive gateways, loop cycles, or layout order correctly. Silent routing nodes remain ambiguous to humans; no automated test proves absence of misreading.
5. **Future-converter stability:** Results are pinned to the tested PM4Py version and conversion implementation details (e.g., silent-transition handling, gateway mapping). Upgrading PM4Py, BPMN layout algorithms, or PNML import/export may change gateway structure while still passing superficial soundness, reintroducing loss undetected without re-running the full witness suite.
