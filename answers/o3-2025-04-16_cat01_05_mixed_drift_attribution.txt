## 2. Raw-versus-normalized interpretation (210 words)
The 0.40 collapse in raw conformance during March–April simply shows that the reference Petri net did not recognise the renamed activity “Eligibility Screen” and the duplicated technical “Open Case”. After mapping the new label and deleting the spurious duplicates, mapped fitness rebounds to 0.90—virtually the pre-migration level. Therefore the gap flags a logging/semantic drift, not necessarily a behavioural one.

However, recovering conformance by relabelling does **not** prove that business execution stayed identical. It only shows that, once we speak the same vocabulary, the normative ordering of tasks is still largely followed; timing, repetition, and frequency can still drift.

Duplicated “Open Case” events inflate variant counts and may create false rework arcs, whereas missing `resource` values undermine any staffing or RACI analysis but leave control-flow metrics almost intact. Both artefacts must therefore be filtered or imputed before performance or organisational mining.

From May onward the mapped fitness remains flat while rework, queueing, and cycle time deteriorate, and DFG arc frequencies change markedly (e.g., AssessRequest Info from 12  29 per 100 cases). Hence these later shifts cannot be dismissed as mere logging drift: they persist after semantic repair, affect waiting times, and coincide with external supplier and staffing events. In short, March was mostly a visibility problem; May-onwards reflects substantive process stress.

# ---------------- Part A – work with monthly aggregates -----------------
import pandas as pd, numpy as np

# 1. embed data
monthly = pd.read_csv('monthly_summary.csv')  # assume csv text pasted or available
dfg_rates = pd.read_csv('dfg_rates.csv')

# 2. validate
assert monthly.isnull().sum().sum() == 0, "Nulls present"
assert (dfg_rates.groupby('month').size() == 7).all(), "DFG fragment incomplete"

# 3. baseline-relative changes
baseline = monthly.loc[monthly['month']=='2026-02']
cols = ['cases','high_complexity_pct','supplier_z_pct',
        'rework_variant_pct','p90_cycle_h','mapped_model_fitness',
        'missing_resource_pct']
for c in cols:
    monthly[c+'_'] = monthly[c] - float(baseline[c])
print(monthly[['month']+[c+'_' for c in cols]].head())

# 4. simple DFG distance (Euclidean on provided edges)
edges = ['Register->Eligibility','Eligibility->CollectDocs',
         'CollectDocs->Assess','Assess->RequestInfo',
         'RequestInfo->CollectDocs','Assess->SeniorAssessment',
         'Assess/SeniorAssessment->Decision']
def dfg_dist(m1,m2):
    a = dfg_rates.loc[dfg_rates.month==m1,edges].values.flatten()
    b = dfg_rates.loc[dfg_rates.month==m2,edges].values.flatten()
    return np.linalg.norm(a-b)
baseline_month = '2026-01'
monthly['dfg_dist'] = monthly['month'].apply(lambda m: dfg_dist(m,baseline_month))

# 5. raw-to-mapped fitness recovery
monthly['fitness_gap'] = monthly['mapped_model_fitness'] - monthly['raw_model_fitness']

# 6. simple change-point flag
monthly['possible_change'] = ((monthly['dfg_dist']>0.05) |
                              (monthly['p90_cycle_h_']>25) |
                              (monthly['fitness_gap']<-0.3))
print(monthly[['month','dfg_dist','p90_cycle_h','fitness_gap','possible_change']])

print("Note: DFG distances ignore omitted edges; fitness gap confounds logging and behaviour.")

## 9. Provisional attribution (320 words)
The most certain attribution concerns the March collapse in raw fitness: 90 % confidence that it is almost entirely a semantic/logging drift triggered by the system migration. The quick recovery after very simple label remapping, plus the absence of any contemporaneous performance change, rules out a major behavioural shock.

Second-strongest conclusion: the surge in rework (AssessRequest Info loop) during May–July is dominantly generated by Supplier Z’s partial document deliveries. Supplier cases rose from 16 % to 46 % exactly at the disruption date and the rework incidence doubled in virtual lock-step. Because supplier Z already handled somewhat more complex customers, part of the increase is compositional, yet the within-supplier rework rate also rose—indicating a behavioural reactance by assessors. Confidence  80 %.

Queueing deterioration between June and August is best explained by the loss of four assessors (20 % of that role). Median Assess service time changed little, while waiting time and p90 cycle soared; Little’s-law style calculations show the imbalance between arrivals and capacity. Confidence 75 %.

The July priority rule evidently altered control flow: AssessSenior Assessment arcs tripled and preliminary analyses hint that high-complexity cases exited the queue faster. Confidence 70 %, limited by poor historic tagging of “complexity”.

October–November delays arise from the annual renewal season, which historically lifts both volume and complexity. The seasonal pulse overlaps with still-constrained capacity, so attribution is mixed: 60 % seasonal, 40 % persisting backlog.

December improvements stem from both reduced seasonal load and explicit overtime plus a “document-quality” outreach. Because rework and p90 cycle descended together while staffing stayed constant, the intervention plausibly helped, though causal certainty is moderate (60 %).

Interactions complicate the picture: supplier backlog and staff loss jointly lengthened queues; the priority rule partly shielded complex cases, redistributing delay to standard ones. Missing resource logs neither cause nor fully mask the performance issues but do hamper granular staffing diagnostics.

Future revisions would be required if: (a) event-level logs reveal large un-mapped semantic changes in May, or (b) a rigorous queueing model shows that capacity loss alone could produce the May rework spike without supplier influence.

## 10. Monitoring decision rules
1. IF new activity labels exceed 1 % of events over any 14-day window, THEN trigger a schema review and mapping update, BECAUSE label drift undermines all downstream conformance metrics.

2. IF duplicate “Open Case” events exceed 3 % of cases, THEN run the de-duplication script and inspect connector logs, BECAUSE a technical emitter may be looping after deployment.

3. IF AssessRequest Info loops rise above 25 per 100 cases AND >50 % of those cases involve Supplier Z, THEN contact Supplier Z account manager and schedule an API test, BECAUSE supplier disruption likely causes missing documents.

4. IF median waiting time before Assess increases by >30 % for two consecutive weeks while service time is stable, THEN escalate to workforce planning for temporary capacity, BECAUSE queue build-up indicates a staffing shortfall rather than task difficulty.

5. IF high-complexity cases experience lower waiting time than standard cases AND standard-case p90 delay exceeds SLA, THEN evaluate the priority rule for unintended inequity, BECAUSE preferential scheduling can redistribute, not remove, delay.

6. IF high-complexity share rises >10 pp compared with same period last year, THEN pre-allocate overtime budget, BECAUSE seasonal population drift predicts workload beyond normal capacity.

7. IF mapped fitness falls below 0.85 without a corresponding rise in new labels, THEN investigate potential behavioural non-conformance (e.g., skipped validation), BECAUSE conformance degradation absent logging drift signals real process change.
