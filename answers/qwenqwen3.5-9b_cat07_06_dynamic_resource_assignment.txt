# 1. Objectives and constraints

**Optimization Objectives**
1.  **SLA Compliance:** Prioritize urgent cases and minimize waiting time to prevent breaches.
2.  **Quality & Rework Reduction:** Assign cases to resources with matching or higher skill levels to minimize errors and rework loops.
3.  **Workload Fairness:** Distribute new assignments evenly to prevent burnout and overtime risk.
4.  **Skill Development:** Allocate 20% of normal/low-priority work to resources with documented training priorities.
5.  **Continuity:** Minimize handover costs for high-complexity cases with high reassignment history.

**Hard Constraints (Safety & Compliance)**
1.  **Skill Requirements:**
    *   Security Review: Skill Level 3 OR Skill 1–2 with explicit supervision (R7/R8).
    *   Final Approval: Skill Level 2–3. Skill 1 may prepare but not finalize.
    *   High-Priority Cases: Skill Level < 2 is forbidden unless supervised.
2.  **Workload Limits:** No resource receives more than 4 new assignments in a single decision batch.
3.  **Overtime Risk:** Avoid assigning work to "high" overtime risk resources unless SLA risk is urgent and no safer alternative exists.
4.  **Continuity:** For high-complexity cases with high handover cost, prefer current owner unless owner has Skill 0–1 and no supervision is feasible.

**Soft Constraints (Preference Trade-offs)**
1.  **Specialist vs. Generalist:** Specialist-only routing can create bottlenecks; generalist routing can increase rework. Balance based on urgency.
2.  **Training vs. Throughput:** Training assignments must not critically delay urgent SLA deadlines.
3.  **Resilience:** Avoid overloading single points of failure (e.g., R4_David has 14 open cases).

# 2. Assignment policy

**Algorithm: Dynamic Weighted Scoring with Hard Filtering**

1.  **Eligibility Filtering:**
    *   Filter resources by `required_skill` (Skill Level 0 = Disqualified).
    *   Apply Hard Constraints (e.g., Security Level 3, Approval Level 2+).
    *   Apply Overtime Risk Constraint (Exclude "high" risk unless urgent).
2.  **Scoring Function:**
    For each eligible resource `r` and case `c`:
    $$ Score = w_1 \cdot SLA\_Urgency + w_2 \cdot SkillMatch + w_3 \cdot Continuity + w_4 \cdot Fairness + w_5 \cdot Training $$
    *   **SLA Urgency:** Inverse of remaining time (weighted by Priority).
    *   **Skill Match:** Difference between `r.skill` and `required_skill` (prefer expert match).
    *   **Continuity:** Inverse of `reassignment_count` and `handover_cost_band` if `current_owner == r`.
    *   **Fairness:** Inverse of `current_open_cases` and `hours_remaining`.
    *   **Training:** Binary flag if `r.training_priority == activity` (boosted for normal/low priority).
3.  **Batching & Constraints:**
    *   Sort all cases by SLA Urgency.
    *   Assign top cases to resources with highest scores.
    *   Enforce "Max 4 new assignments per resource" constraint iteratively.
    *   Resolve ties using `workload_snapshot` (fewer open cases wins).
4.  **Exception Handling:**
    *   If no resource meets skill constraints, trigger escalation or supervisor override.
    *   If workload limit reached, defer case to next batch.

**Pseudocode:**
```python
def assign_case(case, resources):
    eligible = []
    for r in resources:
        if r.skill[case.activity] < 1: continue # Hard constraint
        if r.overtime_risk == "high" and case.priority != "urgent": continue
        score = calculate_score(case, r)
        eligible.append((score, r))
    
    eligible.sort(key=lambda x: x[0], reverse=True)
    for score, r in eligible:
        if r.current_open_cases < 4: # Constraint 1
            assign(case, r)
            break
```
