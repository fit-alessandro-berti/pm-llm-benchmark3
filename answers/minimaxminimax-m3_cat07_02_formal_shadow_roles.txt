# 5. PM4Py role-discovery and similarity code

The snippet below is illustrative but coherent with PM4Py's structure. It uses the dataframe columns described in the prompt and avoids treating activity-frequency clusters as formal authority.

```python
import pandas as pd
import pm4py
from pm4py.objects.log.util import dataframe_utils

# ---------- 1. Load and format the event log ----------
df = pd.read_csv("event_log.csv")
df = pm4py.format_dataframe(
    df,
    case_id="case:concept:name",
    activity_key="concept:name",
    timestamp_key="time:timestamp"
)
# keep attribute columns accessible
df["case_complexity"] = df["case_complexity"].astype(str)
df["temporary_substitution"] = df["temporary_substitution"].astype(bool)

# ---------- 2. Discover organizational roles ----------
# By default this uses activity->resource frequency; we treat it as a hypothesis
roles = pm4py.discover_organizational_roles(df)

# ---------- 3. Resource similarity (activity profile) ----------
sim_matrix = pm4py.discover_activity_based_resource_similarity(df)

# ---------- 4. Networks: handover and working-together ----------
handover_net = pm4py.discover_handover_of_work_network(df)   # who passes work to whom
working_net  = pm4py.discover_working_together_network(df)   # co-occurrence of resources

# ---------- 5. Filter by case complexity and substitution flag ----------
high_critical_df = pm4py.filter_event_attribute_values(
    df, attribute_name="case_complexity",
    values=["high", "critical"], level="case", retain_activities=True
)
sub_df = df[df["temporary_substitution"] == True]

# ---------- 6. Per-resource complexity profile (to avoid mis-clustering) ----------
def resource_complexity_profile(log_df):
    grouped = (log_df
               .groupby("org:resource")["case_complexity"]
               .value_counts(normalize=True)
               .unstack(fill_value=0))
    return grouped

complexity_by_resource = resource_complexity_profile(df)

# ---------- 7. Join role discovery with complexity and substitution indicators ----------
role_records = []
for role_name, role_info in roles.items():
    members = role_info.get("members", [])
    activities = role_info.get("activities", [])
    avg_complexity = complexity_by_resource.loc[members].mean().to_dict()
    sub_share = (sub_df["org:resource"].isin(members).mean())
    role_records.append({
        "role": role_name,
        "members": members,
        "activities": activities,
        "complexity_share": avg_complexity,
        "substitution_share": sub_share,
    })
roles_df = pd.DataFrame(role_records)

# ---------- 8. Cross-check with handover network: distinguish execution vs broker ----------
# Resources whose outgoing handovers dominate and whose incoming handovers are diverse
# are broker-like; resources with strong mutual handover pairs are execution-like.
out_deg = {n: d for n, d in handover_net.out_degree()}
in_deg  = {n: d for n, d in handover_net.in_degree()}
broker_score = {n: out_deg.get(n, 0) / max(1, in_deg.get(n, 0))
                for n in set(out_deg) | set(in_deg)}

# ---------- 9. Sensitivity check: re-discover after filtering substitution events ----------
roles_no_sub = pm4py.discover_organizational_roles(df[df["temporary_substitution"] == False])
# Compare roles vs roles_no_sub — disagreement tells you which roles are
# partly filled by shadow execution (e.g., Giorgio in commercial coverage).

# ---------- 10. Guardrails when interpreting ----------
# Do not promote a role to "specialist" on the basis of a single A6 count.
# Compare both frequency-weighted AND complexity-weighted activity shares.
# Compare both discovery_organizational_roles AND similarity to detect
# shadow roles that have high similarity to two clusters (Giorgio case).
```

Two practical rules embedded in the code:

1. **Re-discover roles after excluding `temporary_substitution=True` events.** If a role's membership changes materially (e.g., Giorgio moves out of "Front Office" into "Commercial"), the role was inflated by substitution and must be flagged.
2. **Always join discovered roles with `case_complexity` and substitution share before drawing conclusions.** A role that is "Kim" in the activity-frequency output but has 0% critical cases and 100% low-complexity work is functionally a different role than the name suggests.
