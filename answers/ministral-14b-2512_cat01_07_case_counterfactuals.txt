## 1. Feasibility model

### Partial-order relations ( = must precede)
```
Register  Triage
Identity Check  Assessment
Document Check  Assessment
Originals Receipt  Document Check (if originals required)
Assessment  Compliance Review (if high-risk/value)
Compliance Review  Decision
Decision  Notify
Request More Info  Document Check  Assessment
```

### Conditional/declarative constraints
1. If `Originals Required`:
   - `Originals Receipt` must precede `Document Check`
   - `Identity Check` may precede or follow `Originals Receipt`
2. If `High Risk/Value`:
   - `Compliance Review` must follow latest `Assessment` and precede `Decision`
   - Four-eyes: same person cannot perform final `Assessment` and final `Compliance Review`
3. If `Request More Info`:
   - New `Document Check` and `Assessment` required
   - High-risk cases need new/reaffirmed `Compliance Review`
4. Resource constraints:
   - No two service intervals for same resource simultaneously
   - Queue estimates are probabilistic (e.g., "D1: 13h" means 13h forecasted, not guaranteed)

### Intervention classification
- **K-104**: Alters *routing* (preliminary compliance work) and *timing* (C1 reservation)
- **K-219**: Alters *routing* (D1D2) and *risk* (rework probability)
- **K-337**: Alters *decision policy* (suppresses rework loop) and *timing*
- **K-411**: Alters *routing* (parallelizes verification) and *logging discipline*
