However, it **should not be expected to be sound**.

### Distinction Between Marking `sink` and Reaching `fm`, and Why Leftover Tokens Are Unconsumable

* **Token in `sink` vs. exact final marking `fm`:** At Step 5 of $\sigma_1$ (`[p_analysis: 1, sink: 1]`) and Step 6 of both $\sigma_1$ and $\sigma_2$ (`[p_analysis_done: 1, sink: 1]`), `marking[sink] == 1` holds, so `sink` contains a token. However, the exact final marking `fm = [sink: 1]` requires zero tokens in every place other than `sink`. Because marking `[p_analysis: 1, sink: 1]` strictly covers `fm` (`m > fm`), the net violates proper completion; at Step 6, `fm` becomes completely unreachable (violating the option to complete).
* **Why leftover tokens can or cannot be consumed:** At `[p_analysis: 1, sink: 1]`, the leftover token in `p_analysis` can advance *once* by firing `t_analyze`, moving to `p_analysis_done`. Once in `p_analysis_done`, the token **cannot be consumed**: the unique transition in `p_analysis_done•` is `t_join_normal`, whose preset is `{p_analysis_done, p_review_done}`. Placing a token in `p_review_done` requires firing `t_standard_review`, which requires a token in `p_review`. Because the sole token produced into `p_review` by `t_split` was consumed by `t_waive_review` and the net is acyclic with `sink• = `, `p_review_done` remains `0` forever.

### Justification of Minimality and Ties

1. **Global minimality of Repair A (Cost = 1):** Cost $0$ leaves the net unsound. Any cost-$1$ edit can only add or delete a single element:
   * Deleting any single place or transition with incident arcs is invalid without also deleting its arcs (cost $> 1$).
   * Deleting any single arc either disconnects a node from `source`-to-`sink` paths—violating the workflow-net condition (e.g., removing `(p_review, t_waive_review)` leaves `t_waive_review` with an empty preset, and removing `(t_split, p_analysis)` strands `p_analysis`)—or breaks normal synchronization.
   * Adding a single arc must preserve bipartiteness and consume the stranded analysis token on the waiver path. The only other candidate of cost $1$ is adding `(p_analysis, t_join_waived)`. However, `(p_analysis, t_join_waived)` **deadlocks** on the firing sequence $\langle \texttt{t\_register}, \texttt{t\_split}, \texttt{t\_analyze}, \texttt{t\_waive\_review} \rangle$, which reaches `[p_analysis_done: 1, p_waived: 1]` where neither `t_join_normal` nor `t_join_waived` is enabled.
   * Hence, **Repair A is the unique globally minimal sound workflow-net repair at Cost = 1.**
2. **Family-level minimality and tie between Repairs B and C (Cost = 2):** Because Repair A is the sole valid edit at cost $1$, any structurally consolidated single-join repair (Repair B) or policy-modifying analysis-bypass repair (Repair C) requires at least cost $2$. Both Repairs B and C redirect exactly one arc endpoint (`-1` arc, `+1` arc = cost $2$) without stranding any node off `source`-to-`sink` paths. Thus, Repairs B and C **tie at Cost = 2** because each achieves the minimum possible single-arc rewiring within its respective design family: single-AND-join funneling versus pre-split fast-track routing. (By contrast, deleting `p_waived` and `t_join_waived` outright to wire `t_waive_review -> p_review_done` directly would cost $6$ edits.)

```python
def format_marking(marking):
    items = sorted((p.name, count) for p, count in marking.items() if count > 0)
    return "{" + ", ".join(f"{name}: {count}" for name, count in items) + "}"


def fire_named_transition(petri_net, marking, transition_name):
    transitions_by_name = {t.name: t for t in petri_net.transitions}
    if transition_name not in transitions_by_name:
        raise ValueError(f"Transition '{transition_name}' does not exist in net '{petri_net.name}'.")

    target = transitions_by_name[transition_name]
    enabled = pm4py.get_enabled_transitions(petri_net, marking)
    if target not in enabled:
        enabled_names = sorted(t.name for t in enabled)
        raise RuntimeError(
            f"Cannot fire '{transition_name}' at {format_marking(marking)}; "
            f"enabled transitions: {enabled_names}"
        )

    next_marking = Marking()
    for place, count in marking.items():
        if count > 0:
            next_marking[place] = count

    for arc in target.in_arcs:
        next_marking[arc.source] -= arc.weight
        if next_marking[arc.source] <= 0:
            del next_marking[arc.source]

    for arc in target.out_arcs:
        next_marking[arc.target] = next_marking.get(arc.target, 0) + arc.weight

    return next_marking


def replay_sequence(label, petri_net, initial_marking, final_marking, seq):
    print(f"\n--- Replay on {label}: {seq} ---")
    current = initial_marking
    enabled_now = sorted(t.name for t in pm4py.get_enabled_transitions(petri_net, current))
    print(f"Step 0 (initial): marking={format_marking(current)}, enabled={enabled_now}")

    for idx, t_name in enumerate(seq, start=1):
        try:
            current = fire_named_transition(petri_net, current, t_name)
        except RuntimeError as exc:
            print(f"Step {idx}: BLOCKED -> {exc}")
            return
        enabled_now = sorted(t.name for t in pm4py.get_enabled_transitions(petri_net, current))
        has_sink_token = any(p.name == "sink" and cnt > 0 for p, cnt in current.items())
        print(
            f"Step {idx} ({t_name}): marking={format_marking(current)}, "
            f"enabled={enabled_now}, sink_marked={has_sink_token}, exact_fm={current == final_marking}"
        )
```

### Expected Qualitative Diagnostic Differences (and Exact State-Space Derivation)

1. **`check_is_workflow_net`:** Returns `True` for **both** the original and repaired nets, confirming that structural graph connectivity is unaffected and was never the failure mode.
2. **`check_soundness(..., print_diagnostics=True)`:**
   * **Original net:** Evaluates to **unsound** (`False`). Diagnostics report improper completion / inability to reach the exact final marking `fm` from reachable states on the waiver branch because markings strictly covering `fm` (`[p_analysis: 1, sink: 1]` and the dead non-final marking `[p_analysis_done: 1, sink: 1]`) are reached.
   * **Repaired net:** Evaluates to **sound** (`True`). Every reachable marking retains the option to complete cleanly at `repaired_fm = [sink: 1]`, no residual tokens remain when `sink` is marked, and every transition is live (executable from `repaired_im`).
3. **`get_enabled_transitions` & helper replay:** After `t_register -> t_split -> t_waive_review` (`[p_analysis: 1, p_waived: 1]`), the original net enables `{t_analyze, t_join_waived}` and permits premature `t_authorize`, whereas the repaired net enables **only** `{t_analyze}`, raising a `RuntimeError` if `t_join_waived` is attempted before `t_analyze`.
4. **`convert_to_reachability_graph`:** We can derive the exact reachable markings directly from the net structure:
   * Common markings to both nets ($10$ states): `[source: 1]`, `[p_ready: 1]`, `[p_analysis: 1, p_review: 1]`, `[p_analysis_done: 1, p_review: 1]`, `[p_analysis: 1, p_review_done: 1]`, `[p_analysis_done: 1, p_review_done: 1]`, `[p_analysis: 1, p_waived: 1]`, `[p_analysis_done: 1, p_waived: 1]`, `[p_decision: 1]`, and `[sink: 1]`.

# 7. Repair Trade-Offs and Residual Risks

* **Distinguishability of waiver vs. standard review:** In **Repair A**, standard review and waiver remain distinguishable both externally in event logs (`"Perform Standard Review"` vs. `"Record Review Waiver"`) and internally in net markings (`p_review_done` + `t_join_normal` vs. `p_waived` + `t_join_waived`). By contrast, **Repair B** preserves log-level distinguishability but erases state-level distinguishability once `t_join_waived` moves the waiver token into `p_review_done`.
* **Silent transitions and duplicate behavior:** Repair A retains three silent ($\tau$) transitions (`t_split`, `t_join_normal`, `t_join_waived`), with `t_join_normal` and `t_join_waived` sharing `p_analysis_done` as an input and `p_decision` as an output. Behaviorally, this introduces **no nondeterministic ambiguity or duplicate visible traces** because `p_review_done` and `p_waived` are mutually exclusive for a single case; at `[p_analysis_done: 1, ...]`, at most one join can be enabled. However, multiple $\tau$-joins converging on `p_decision` slightly increase alignment search branching in conformance checking and cannot be rediscovered faithfully by basic process-discovery algorithms (such as the Alpha miner) that do not infer silent transitions.
* **Why soundness alone does not prove business-rule alignment:** Soundness is purely a control-flow consistency property (option to complete, proper completion, no dead transitions). **Repair C** is a workflow net and is $100\%$ WOFLAN-sound, yet it completely omits mandatory analysis whenever review is waived. Similarly, serializing analysis and review or swapping transition labels would remain sound while violating concurrency or ordering requirements.
* **Regression test suite (visible activity traces):**
  * *Positive traces (must be accepted and reach exact `fm`):*
    1. $\langle \text{Register Case}, \text{Perform Analysis}, \text{Perform Standard Review}, \text{Authorize Case} \rangle$
    2. $\langle \text{Register Case}, \text{Perform Standard Review}, \text{Perform Analysis}, \text{Authorize Case} \rangle$
    3. $\langle \text{Register Case}, \text{Perform Analysis}, \text{Record Review Waiver}, \text{Authorize Case} \rangle$
    4. $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Perform Analysis}, \text{Authorize Case} \rangle$
  * *Negative traces (must be rejected or flagged as non-conformant):*
    1. $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Authorize Case}, \text{Perform Analysis} \rangle$ *(premature authorization before analysis)*
    2. $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Authorize Case} \rangle$ *(mandatory analysis bypassed altogether)*
    3. $\langle \text{Register Case}, \text{Perform Analysis}, \text{Authorize Case} \rangle$ *(both review and waiver bypassed)*
    4. $\langle \text{Register Case}, \text{Perform Analysis}, \text{Perform Standard Review}, \text{Record Review Waiver}, \text{Authorize Case} \rangle$ *(XOR violation executing both review options)*
* **Detecting an accidental bypass of mandatory analysis:**
  * *Design-time (model verification):* Traverse `convert_to_reachability_graph(net, im, fm)` (or check the LTL formula $\mathbf{G}(\texttt{Authorize Case} \rightarrow \mathbf{O}\,\texttt{Perform Analysis})$ / $\neg (\neg \texttt{Perform Analysis}\;\mathbf{U}\;\texttt{Authorize Case})$) to verify that every path from the initial state to any edge labeled `"Authorize Case"` traverses `"Perform Analysis"` first. Alternatively, remove `t_analyze` temporarily and verify that `t_authorize` becomes dead (non-live).
  * *Run-time / audit-time (log conformance):* Run alignment-based conformance (`pm4py.conformance_diagnostics_alignments`) alongside a temporal trace assertion checking that every completed case has `count("Perform Analysis") == 1` and `index("Perform Analysis") < index("Authorize Case")`.

# 8. Final Recommendation

Deploy **Repair A (Two-Input Waiver Synchronization)**—adding the single arc `(p_analysis_done, t_join_waived)`—and retain **Repair B (Funnel Waiver into Normal AND-Join)** as the technical fallback.

Repair A is the optimal primary deployment choice for three reasons:
1. **Strict policy fidelity:** It enforces mandatory parallel analysis on both standard-review and waiver paths, blocking `t_authorize` until both `p_analysis_done` and the selected review outcome (`p_review_done` or `p_waived`) are marked.
2. **Global minimality:** At an edit cost of $1$ (`+1` arc), it is provably the smallest structural change capable of restoring soundness without altering any existing place, transition, or label.
3. **Audit clarity:** Unlike Repair B, it keeps `p_waived` and `p_review_done` semantically distinct right up to synchronization, making runtime token inspection unambiguous for compliance auditing.

**Fallback strategy:** Choose **Repair B** (cost $2$) if a target execution or analytics engine restricts parallel blocks to a single symmetric AND-join (`t_join_normal`), since it preserves identical visible trace behavior while centralizing synchronization. (**Repair C** should not be used as a technical fallback; it is admissible only if business governance formally revises policy to exempt waived cases from analysis.) Before go-live, pair WOFLAN soundness verification with reachability-graph temporal checks confirming `"Perform Analysis"` precedes `"Authorize Case"` on every path.
