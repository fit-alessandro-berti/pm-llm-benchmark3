# 1. Equivalence Notions

### Visible Trace Equivalence after Hiding `tau`
- **Definition**: Two models are equivalent if their sets of visible traces (after removing `tau`) are identical.
- **Label Handling**: Duplicate visible labels are distinguished by their **position in the trace** (e.g., two `Check Revision` events are distinct if they occur at different steps).
- **Formal Basis**: Standard trace semantics where `tau` is invisible, and visible actions are recorded in order.

### Bounded Visible-Language Equivalence under P3
- **Definition**: Two models are equivalent if their visible traces of length  12 (with  3 `Analyze Revision` occurrences) are identical.
- **Label Handling**: Labels are distinguished by identity (e.g., `Check Revision` is treated as a single observable event regardless of position).
- **Formal Basis**: Exhaustive enumeration of all traces up to the bound, comparing sets.

### Business-Relevant Equivalence under P1 (Operational Compliance)
- **Definition**: Two models are equivalent if:
  1. Every `Analyze Revision` is immediately followed by its own `Check Revision` before the next `Rework Case` or `Close Case`.
  2. `Approve Revision` (and `tau`) may occur but do not affect compliance.
- **Label Handling**: Labels are distinguished by **identity and causal ordering** (e.g., `Check Revision` must follow its corresponding `Analyze Revision`).

### Abstracted Dashboard Equivalence under P2 (Executive View)
- **Definition**: Two models are equivalent if:
  1. All traces start with `Open Case` and end with `Close Case`.
  2. At least one `Analyze Revision` and one `Check Revision` occur.
  3. The dashboard collapses all `Check Revision` into a Boolean flag ("a check occurred").
  4. `Approve Revision` and `tau` are hidden; only the count of `Analyze Revision` and presence of `Rework Case` are recorded.
- **Label Handling**: `Check Revision` is treated as a single Boolean; `Analyze Revision` counts are preserved.

# 5. Bounded Comparison Code

```python
import pm4py
from pm4py.objects.process_tree import parse as parse_tree
from pm4py.objects.petri_net.utils import check_soundness
from pm4py.objects.log.util import project_on_event_classes
from collections import deque

def get_visible_traces(tree, max_visible=12, max_analyze=3):
    """Exhaustively enumerate visible traces up to bounds."""
    net, im, fm = pm4py.convert_to_petri_net(tree)
    check_soundness(net, im, fm)
    visible_traces = set()
    queue = deque([(im, [])])
    visited = set()

    while queue:
        marking, trace = queue.popleft()
        if marking == fm:
            visible_trace = [t for t in trace if t != 'tau']
            if (len(visible_trace) <= max_visible and
                visible_trace.count('Analyze Revision') <= max_analyze):
                visible_traces.add(tuple(visible_trace))
            continue
        if marking in visited:
            continue
        visited.add(marking)
        enabled = pm4py.get_enabled_transitions(net, marking)
        for t in enabled:
            if t.label is not None:
                new_trace = trace + [t.label]
            else:
                new_trace = trace + ['tau']
            new_marking = pm4py.objects.petri_net.utils.marking.add(
                marking, pm4py.objects.petri_net.utils.marking.create(t.name)
            )
            queue.append((new_marking, new_trace))
    return visible_traces

# Parse models
model_a = parse_tree("->('Open Case', *(+('Analyze Revision', 'Check Revision'), X('Approve Revision', tau)), 'Rework Case'), 'Close Case')")
model_b = parse_tree("->('Open Case', +('Check Revision', *(->('Analyze Revision', X('Approve Revision', tau)), 'Rework Case')), 'Close Case')")

# Get bounded visible traces
traces_a = get_visible_traces(model_a)
traces_b = get_visible_traces(model_b)

# Compare
unique_to_a = traces_a - traces_b
unique_to_b = traces_b - traces_a

print("Traces unique to Model A:", unique_to_a)
print("Traces unique to Model B:", unique_to_b)
```

**Explanation**:
- The code exhaustively explores all possible traces up to the bounds (12 visible events, 3 `Analyze Revision`).
- Silent transitions (`tau`) are included in the exploration but excluded from the final visible traces.
- The comparison is **exhaustive** for the given bounds.

# 6. Stochastic and Footprint Comparison

### Footprint Analysis
```python
footprint_a = pm4py.discover_footprints(model_a)
footprint_b = pm4py.discover_footprints(model_b)
print("Footprint A:", footprint_a)
print("Footprint B:", footprint_b)
```
- **Why Equal Footprints Don’t Imply Trace Equivalence**:
  Footprints capture causal dependencies (e.g., `A > B` means `A` must precede `B`), but they abstract away the exact number of occurrences or concurrency. Two models can have identical footprints but different trace sets (e.g., Model A enforces per-iteration checks, while Model B does not).

def count_tree_nodes(tree):
    if isinstance(tree, pm4py.objects.process_tree.obj.ProcessTree):
        count = 1
        for child in tree.children:
            count += count_tree_nodes(child)
        return count
    return 1

# 8. Simplified Model

### Target: P2 (Executive Dashboard)
**Rationale**: P2 abstracts away the exact interleaving of `Check Revision` and `Analyze Revision`, so we can collapse the loop and `Check Revision` into a simpler structure.

#### Simplified Process Tree:
```text
->(
  'Open Case',
  +(
    ->('Analyze Revision', 'Check Revision'),
    'Rework Case'
  ),
  'Close Case'
)
```
- **Intuition**: The loop is replaced with a choice between `(Analyze Revision, Check Revision)` and `Rework Case`, as the dashboard only cares about counts and presence, not ordering.

#### PM4Py Code:
```python
simplified_model = parse_tree("->('Open Case', +(->('Analyze Revision', 'Check Revision'), 'Rework Case'), 'Close Case')")
```

#### Preservation Table:

| Property                          | Original Models | Simplified Model | Status          |
|-----------------------------------|------------------|------------------|-----------------|
| Starts with `Open Case`           |                |                | Exact           |
| Ends with `Close Case`            |                |                | Exact           |
| At least one `Analyze Revision`   |                |                | Exact           |
| At least one `Check Revision`     |                |                | Exact           |
| Count of `Analyze Revision`       |                |                | Exact           |
| Presence of `Rework Case`         |                |                | Exact           |
| Per-iteration `Check Revision`    |  (A),  (B)    |                | Lost            |
| Exact interleaving of events      |                |                | Abstracted      |

#### Regression Traces:
- **Positive (admitted by all)**:
  1. `Open Case, Analyze Revision, Check Revision, Close Case`
  2. `Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close Case`
  3. `Open Case, Rework Case, Analyze Revision, Check Revision, Close Case`
- **Negative (admitted by originals but not simplified)**:
  1. `Open Case, Analyze Revision, Rework Case, Analyze Revision, Check Revision, Close Case` (valid in A, invalid in simplified)
  2. `Open Case, Check Revision, Analyze Revision, Close Case` (valid in B, invalid in simplified)
