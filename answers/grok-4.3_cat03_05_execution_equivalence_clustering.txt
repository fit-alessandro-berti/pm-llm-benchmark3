## 1. Equivalence design space

Activity-sequence equivalence is defined as identity of the ordered list of activity labels, ignoring all object references, timestamps, and multiplicities. Invariants preserved: exact activity order and repetition counts. Information discarded: all object participation, external flags, and O2O relations. It is reflexive, symmetric, and transitive. Concurrency is collapsed to the observed total order; simultaneous events appear in the recorded sequence.

Typed structural equivalence under identifier renaming normalizes every local object identifier to a fresh canonical name per type while preserving type incidence, E2O links, and O2O cardinalities. Two executions are equivalent when their normalized typed graphs are isomorphic. Invariants preserved: object-type multiplicities, participation patterns, and external-object flags. Information discarded: concrete identifiers and qualifier semantics. It is reflexive, symmetric, and transitive. Concurrent or same-time events are treated as an unordered set within each timestamp bucket before isomorphism testing.

Business-semantic equivalence augments the typed graph with external-object flags, O2O qualifiers (e.g., “replaces”, “partial_settles”), and lifecycle motifs (return-repack, item substitution). Equivalence holds when the multisets of (activity, type-multiplicity, qualifier) tuples match after identifier normalization. Invariants preserved: external sharing, payment multiplicity semantics, and replacement/return motifs. Information discarded: absolute timestamps and local identifier values. It is reflexive and symmetric; transitivity holds only within the same motif family. Concurrent events are ordered by the partial order induced by shared objects.

A fourth relation, payment-settlement equivalence, collapses all Record Payment events attached to the same invoice into a single “settlement” node annotated with cardinality. It is useful only for financial segmentation and is not transitive with the other three.

## 2. Canonical signatures

The preferred relation is business-semantic equivalence. Its canonical signature is the sorted tuple:

```python
sig = (
    tuple(sorted(activities)),                 # activity labels with multiplicity
    frozenset((t, mult) for t, mult in type_counts.items()),
    frozenset(ext_flags),                      # (activity, EXT flag) pairs
    frozenset(qualifiers),                     # normalized (rel, qualifier) pairs
    payment_cardinality                        # 1 or >1
)
```

Normalization replaces every local Order, Item, Package, etc. identifier by its type plus an occurrence counter within the lead object; external objects remain flagged as EXT. The signature is computed after sorting events by timestamp and breaking ties by activity label.

## 4. Cluster interpretations

SEM-A (X1,X2): standard isolated single-package order. Business behavior is linear fulfillment with one invoice and one payment. Operational risk is low; opportunity is straightforward throughput measurement. Traditional flattening loses object cardinalities but still yields a readable trace. Stable under identifier repair.

SEM-B (X3): multi-package consolidated delivery. Behavior splits physical handling while keeping financial settlement atomic. Risk is misallocation of delivery cost; opportunity is packaging optimization. Flattening merges the two Pack events and hides the consolidation. Stable.

SEM-C (X4): multi-delivery with partial payments. Behavior decouples physical and financial completion. Risk is cash-flow fragmentation; opportunity is installment handling. Flattening collapses payments into one event and loses partial-settlement semantics. Moderately stable.

SEM-D (X5) and SEM-E (X6): cross-order sharing in logistics versus finance. Behavior indicates shared fulfillment or billing agreements. Risk is attribution error; opportunity is volume consolidation. Flattening either drops external objects or fabricates phantom links. Stable only when external flags are reliably recorded.

SEM-F (X7): item replacement. Behavior hides substitution inside an otherwise normal sequence. Risk is inventory distortion; opportunity is quality-root-cause detection. Flattening loses the qualifier and appears identical to SEM-A. Unstable if qualifiers are missing.

SEM-G (X8): return and repack. Behavior extends the lifecycle with reverse logistics. Risk is return fraud; opportunity is circular-economy tracking. Flattening truncates the trace after first Dispatch. Stable when return events are present.

## 5. Borderline cases

X1 versus X2: activity-sequence and typed-structural relations equate them; business-semantic also equates them because no qualifiers differ. Only raw-identifier equivalence would separate them.

X1 versus X5: activity-sequence equates them; typed-structural separates them on external flags; business-semantic keeps them apart because logistics sharing changes attribution semantics.

X1 versus X6: same pattern as X5, but financial sharing instead of logistics sharing; the two relations again disagree on whether external flags matter.

X1 versus X7: activity-sequence and typed-structural equate them; business-semantic separates them because the replacement qualifier alters meaning.

X3 versus X4: activity-sequence separates them by event counts; typed-structural also separates them by delivery cardinality; business-semantic keeps them apart because payment multiplicity and delivery splitting carry different operational meanings.

X4 versus X8: activity-sequence separates them by return events; business-semantic separates them because return-repack is a distinct lifecycle motif even though both contain multiple Pack/Dispatch pairs.

## 6. Relation to `pm4py.cluster_equivalent_ocel`

`pm4py.cluster_equivalent_ocel` returns clusters based on exact isomorphism of the object-centric event log graph using raw object identifiers, preserving full E2O incidence and O2O links but treating every local identifier as distinct. Raw identifiers therefore produce singleton clusters for every execution that uses different surrogate keys. Post-processing replaces each local identifier by a type-plus-occurrence counter and recomputes a hash of the normalized graph. Exact equivalence is preferable when regulatory traceability demands identical object histories; coarser business clustering is preferable for segmentation. Large connected executions or high `max_objs` cause memory blow-up; the outline below first filters to the lead object type.

```python
import pm4py
from pm4py.objects.ocel.obj import OCEL
clusters = pm4py.cluster_equivalent_ocel(ocel, lead_object_type="Order")
canonical = {}
for cid, sub_ocel in clusters.items():
    norm = normalize_identifiers(sub_ocel, lead="Order")
    sig = compute_semantic_signature(norm)
    canonical[cid] = sig
```

## 7. Robustness analysis

Ignoring all O2O qualifiers merges SEM-F into SEM-A and makes X7 indistinguishable from X1. Ignoring external objects merges SEM-D and SEM-E into SEM-A. Collapsing repeated same-label events merges X3 and X4 into a single “multi-pack” cluster, losing delivery-splitting semantics. Treating Pack/Dispatch order as partial merges X3 and X4 because the relative order of the second Pack and first Dispatch becomes irrelevant. Treating payment multiplicity as an amount attribute rather than structure collapses SEM-C and SEM-A when total amounts match, losing the partial-payment motif.

## 8. Limitations and recommendation

For compliance monitoring use typed-structural equivalence: it retains object participation without requiring domain-specific qualifiers. For operational segmentation use business-semantic equivalence: it surfaces sharing and lifecycle motifs that drive cost and risk. For root-cause analysis use activity-sequence equivalence augmented with qualifiers: it keeps traces readable while still highlighting anomalies. For descriptive reporting use payment-settlement equivalence: it produces compact financial cohorts. No single notion is best for all four purposes because compliance requires structural fidelity, operations require semantic aggregation, root-cause analysis needs both detail and motif detection, and reporting needs maximal summarization; each purpose optimizes a different trade-off between precision and interpretability.
