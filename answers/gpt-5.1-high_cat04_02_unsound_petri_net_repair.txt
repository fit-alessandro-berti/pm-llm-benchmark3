## 1. Executive Verdict

The given model **is** a workflow net: it has a unique source place `source`, a unique sink place `sink`, and every place and transition lies on a path from `source` to `sink`. It should **not** be expected to be sound. The principal defect is that the waiver join `t_join_waived` synchronizes only on `p_waived` and ignores `p_analysis_done`, so authorization can proceed without completed analysis. As a result, there are reachable markings where `t_authorize` fires before `t_analyze`, and reachable deadlock markings in which `sink` holds a token together with leftover tokens in analysis places. The business consequence is that cases may be authorized without mandatory analysis and the process can terminate in internally inconsistent states, threatening compliance, auditability, and reliable throughput statistics.

## 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
| --- | --- | --- | --- |
| `t_split` with `p_ready`, `p_analysis`, `p_review` | AND-split after registration, starting analysis and some form of review in parallel | One token in `p_ready` becomes one token in both `p_analysis` and `p_review` | Both branches must be joined correctly; any incorrect join will leave residual tokens in one branch |
| `p_review → t_standard_review → p_review_done` | Perform a standard review and signal its completion | Consumes the review token from `p_review` and places a token in `p_review_done` | Without synchronization with analysis, authorization could ignore the analysis branch or deadlock waiting for it |
| `p_review → t_waive_review → p_waived` | Record a formal waiver instead of performing standard review | Consumes the token from `p_review` and moves it to `p_waived` | Chooses the waiver route; if subsequent synchronization ignores `p_analysis_done`, analysis can be skipped or left incomplete |
| `t_join_normal` with `p_analysis_done`, `p_review_done` | Synchronize completion of analysis and standard review | Enabled only when both `p_analysis_done` and `p_review_done` carry a token; produces `p_decision` | Correctly enforces mandatory analysis for standard-review cases; no structural defect here |
| `t_join_waived` with `p_waived` | Synchronize completion of analysis and waived review | Enabled solely by a token in `p_waived` and produces `p_decision` without consulting `p_analysis_done` | Allows authorization without completed analysis and can strand tokens in `p_analysis` or `p_analysis_done`, creating unsound final states |
| Initial marking `im` and final marking `fm` | Model a single active case that should fully terminate | `im` has one token in `source`; `fm` has one token in `sink` | While `fm` is reachable via the standard-review path, there are also reachable deadlocks with a token in `sink` and additional tokens elsewhere, so proper completion is not guaranteed |
| All nodes on source–sink paths | Ensure workflow-net structure | Every place and transition lies on some directed path from `source` to `sink` | Structural workflow-net condition holds, so the defect is purely behavioral (soundness), not a missing-path problem |

## 3. Marking-Based Counterexample

One firing sequence along the waiver route that exposes the defect is:

`t_register, t_split, t_waive_review, t_join_waived, t_authorize, t_analyze`.

This sequence shows both the token creation in parallel branches and that `t_authorize` can fire before `t_analyze`, leading to a deadlock with residual tokens.

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| --- | --- | --- | --- | --- |
| M0 | (initial) | `{source: 1}` | `{t_register}` | Initial marking `im` |
| 1 | `t_register` | `{p_ready: 1}` | `{t_split}` | Case is registered and ready for parallel work |
| 2 | `t_split` | `{p_analysis: 1, p_review: 1}` | `{t_analyze, t_standard_review, t_waive_review}` | AND-split: one token in analysis branch and one in review branch |
| 3 | `t_waive_review` | `{p_analysis: 1, p_waived: 1}` | `{t_analyze, t_join_waived}` | Waiver chosen; analysis token still waiting in `p_analysis` |
| 4 | `t_join_waived` | `{p_analysis: 1, p_decision: 1}` | `{t_analyze, t_authorize}` | Waiver join ignores `p_analysis`; decision place is marked while analysis is still pending |
| 5 | `t_authorize` | `{p_analysis: 1, sink: 1}` | `{t_analyze}` | Authorization fires **before** `t_analyze`; a token exists in `sink` but the marking is not equal to `fm` because `p_analysis` still has a token |
| 6 | `t_analyze` | `{p_analysis_done: 1, sink: 1}` | `∅` | Analysis is performed after authorization; `t_join_normal` is disabled (no token in `p_review_done`), so `p_analysis_done` can never be consumed, leaving a deadlock with extra tokens outside `sink` |

Thus the model reaches a marking where the business goal (“case authorized”) is met while analysis was not completed beforehand, and even if analysis is eventually performed, the exact final marking `fm` is unreachable from that state because the remaining token in `p_analysis_done` cannot be synchronized with any review completion.

## 4. Minimal-Repair Alternatives

| Repair | Exact edits | Edit cost (arcs + places + transitions) | Preserved intent | Changed behavior | New risk |
| --- | --- | --- | --- | --- | --- |
| **R1: Add analysis input to waiver join** | Add one arc from place `p_analysis_done` to transition `t_join_waived`, so `t_join_waived` now requires tokens in both `p_waived` and `p_analysis_done` to fire; keep all other places and transitions unchanged | 1 (add 1 arc) | Analysis remains mandatory for both standard-review and waiver cases; parallel start via `t_split` and standard-review synchronization via `t_join_normal` are preserved | `t_authorize` can no longer occur before `t_analyze` on the waiver path; any waiver completion must wait for analysis completion, and no marking with a token in `sink` can contain leftover tokens in analysis places | If logs contain traces where waiver is recorded but analysis never happens, those traces will now deadlock before authorization, which may reveal data-quality or organizational issues |
| **R2: Rewire waiver outcome into the normal synchronization** | Redirect the output of `t_waive_review` from `p_waived` to `p_review_done`; remove place `p_waived`; remove transition `t_join_waived`; remove arcs `t_waive_review → p_waived`, `p_waived → t_join_waived`, and `t_join_waived → p_decision` | 6 (remove 3 arcs, 1 place, 1 transition; add 1 arc) | Analysis stays mandatory for all cases; both standard review and waiver still exist as distinct visible transitions, but they share the same “review completed” place `p_review_done` and the same AND-join `t_join_normal` with `p_analysis_done` | The separate waiver join disappears; after either standard review or waiver, the process waits for `p_analysis_done` and then uses the common join `t_join_normal`. The internal marking no longer distinguishes between “review completed” and “waiver recorded” at the place level | Structural distinction between waived and standard reviews is reduced to the transition label; model-based diagnostics that relied on `p_waived` or `t_join_waived` (e.g., token-based KPIs per waiver) will no longer be possible without log analysis |

Under the edit-cost model “1 per added or removed arc, place, or transition,” R1 is minimal for preserving the original business rule. The defect is that the waiver join ignores the analysis completion place; this cannot be corrected without at least one structural change connecting `p_analysis_done` to the waiver synchronization. Adding exactly one input arc to `t_join_waived` is the cheapest way to enforce that every waived case also completes analysis before authorization. R2 deliberately changes the internal structure more aggressively (higher cost) to simplify the model by collapsing both review outcomes into a single completion place and join; it is minimal within that family because any alternative that keeps `p_waived` or `t_join_waived` would require additional arcs to avoid residual tokens.

## 5. Corrected PM4Py Code

The following code implements Repair R1 (adding `p_analysis_done` as an additional input to `t_join_waived`), producing `repaired_net`, `repaired_im`, and `repaired_fm` without assuming that the original code has been run:

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

# Places
source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in {
    source,
    p_ready,
    p_analysis,
    p_review,
    p_analysis_done,
    p_review_done,
    p_waived,
    p_decision,
    sink,
}:
    repaired_net.places.add(p)

# Transitions
register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in {
    register,
    split,
    analyze,
    standard_review,
    waive_review,
    join_normal,
    join_waived,
    authorize,
}:
    repaired_net.transitions.add(t)

# Arcs: registration and parallel split
petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

# Arcs: analysis branch
petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

# Arcs: standard review branch
petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

# Arcs: waiver branch
petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

# Arcs: joins and authorization
petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

# Corrected waiver synchronization: require completed analysis as well
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

repaired_im = Marking()
repaired_im[source] = 1

repaired_fm = Marking()
repaired_fm[sink] = 1
```

## 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

def fire_transition_by_name(net, marking, transition_name):
    """
    Fire a transition by name if it is enabled; otherwise raise an error.
    """
    enabled = {t.name: t for t in pm4py.get_enabled_transitions(net, marking)}
    if transition_name not in enabled:
        raise RuntimeError(f"Transition {transition_name} is not enabled in marking {marking}")

    t = enabled[transition_name]
    new_marking = Marking(marking)

    # Consume tokens from input places
    for arc in t.in_arcs:
        place = arc.source
        new_marking[place] = new_marking.get(place, 0) - arc.weight
        if new_marking[place] == 0:
            del new_marking[place]

    # Produce tokens in output places
    for arc in t.out_arcs:
        place = arc.target
        new_marking[place] = new_marking.get(place, 0) + arc.weight

    return new_marking


def replay_sequence(net, im, sequence):
    """
    Replay a transition-name sequence from an initial marking,
    printing markings and enabled transitions along the way.
    """
    marking = Marking(im)
    print(f"Initial marking: {marking}")
    for i, t_name in enumerate(sequence, start=1):
        print(f"\nStep {i}: firing {t_name}")
        marking = fire_transition_by_name(net, marking, t_name)
        enabled = pm4py.get_enabled_transitions(net, marking)
        enabled_names = sorted(t.name for t in enabled)
        print(f"  Marking: {marking}")
        print(f"  Enabled transitions: {enabled_names}")
    return marking


# 1. Workflow-net and soundness checks
print("Original net is workflow net:", pm4py.check_is_workflow_net(net))
print("Repaired net is workflow net:", pm4py.check_is_workflow_net(repaired_net))

print("\nOriginal net soundness diagnostics:")
pm4py.check_soundness(net, im, fm, print_diagnostics=True)

print("\nRepaired net soundness diagnostics:")
pm4py.check_soundness(repaired_net, repaired_im, repaired_fm, print_diagnostics=True)

# 2. Enabled transitions at the initial markings
print("\nEnabled transitions at im (original):",
      sorted(t.name for t in pm4py.get_enabled_transitions(net, im)))
print("Enabled transitions at repaired_im:",
      sorted(t.name for t in pm4py.get_enabled_transitions(repaired_net, repaired_im)))

# 3. Reachability graphs
rg_original = pm4py.convert_to_reachability_graph(net, im, fm)
rg_repaired = pm4py.convert_to_reachability_graph(repaired_net, repaired_im, repaired_fm)
print("\nReachability graphs constructed for original and repaired nets.")

# 4. Replay the waiver counterexample on both nets
waiver_sequence = [
    "t_register",
    "t_split",
    "t_waive_review",
    "t_join_waived",
    "t_authorize",
    "t_analyze",
]

print("\nCounterexample sequence on original net:")
final_marking_original = replay_sequence(net, im, waiver_sequence)
print(f"\nFinal marking reached on original net: {final_marking_original}")

print("\nSame sequence on repaired net (t_join_waived should be disabled until analysis is done):")
try:
    final_marking_repaired = replay_sequence(repaired_net, repaired_im, waiver_sequence)
    print(f"\nFinal marking reached on repaired net: {final_marking_repaired}")
except RuntimeError as e:
    print("As expected, replay fails due to disabled transition:", e)
```

Qualitatively, `pm4py.check_is_workflow_net` should report that both the original and repaired nets satisfy the workflow-net structural conditions (unique source, unique sink, and all nodes on a source–sink path). For the original net, `pm4py.check_soundness` should flag behavioral problems, in particular reachable markings where `sink` is marked together with tokens remaining in `p_analysis` or `p_analysis_done`, and the counterexample replay should succeed, demonstrating that `t_authorize` can fire before `t_analyze` on the waiver path. For the repaired net, the soundness check should succeed (option to complete, proper completion, and no dead tasks), and attempting to replay the same counterexample should raise an error when `t_join_waived` is requested before `t_analyze`, confirming that authorization after waiver now depends on completed analysis and leaves no residual tokens outside the final marking.

## 7. Repair Trade-Offs and Residual Risks

Under Repair R1, waiver and standard review remain clearly distinguishable: they are separate visible transitions (`t_standard_review` versus `t_waive_review`) and they still feed into different internal joins (`t_join_normal` and `t_join_waived`), while both require `p_analysis_done`. Under Repair R2, the distinction is partly blurred structurally because both outcomes share the same place `p_review_done` and join `t_join_normal`; they remain distinguishable only at the transition level, which is sufficient for event-log analysis but weaker for purely structural diagnostics. R1 does not introduce new silent transitions, but the presence of two silent joins means that care is needed when interpreting model-based diagnostics; R2 simplifies the silent structure by removing `t_join_waived`. Soundness alone does not prove alignment with the business rule: a perfectly sound net could still omit mandatory analysis or misrepresent waiver semantics. Regression tests should include positive traces such as “register → split → analyze → standard review → join → authorize” and “register → split → standard review → analyze → join → authorize”, as well as “register → split → analyze → waive review → (waiver join) → authorize” under R1, and negative traces like “register → split → waive review → (direct) authorize” which should be impossible. To detect accidental bypass of mandatory analysis, one should perform conformance checking on event logs, explicitly searching for any trace where `t_authorize` occurs without a preceding `t_analyze` (or, under an intentional policy change, without either `t_analyze` or an explicitly modeled analysis-waiver transition).

## 8. Final Recommendation

I recommend **Repair R1 (add analysis input to the waiver join)** for deployment. It has minimal edit cost (one new arc), leaves the overall structure and concurrency pattern intact, and directly enforces the original business rule that analysis is mandatory regardless of whether the review is standard or waived. The explicit `p_waived` place and separate silent join `t_join_waived` preserve a clear structural distinction between standard and waived cases, which is valuable for diagnostics, KPI definition, and compliance audits, while guaranteeing that authorization can occur only after analysis completion and that no residual tokens remain at completion. As a fallback, **Repair R2 (rewire the waiver outcome into the normal synchronization)** is attractive when model simplicity is prioritized over structural expressiveness: it removes the dedicated waiver place and join, reducing the number of silent elements and making the net easier to visualize, while still ensuring soundness and mandatory analysis. However, R2 slightly weakens the structural observability of waivers, so it should be chosen only if this trade-off is acceptable to stakeholders.
