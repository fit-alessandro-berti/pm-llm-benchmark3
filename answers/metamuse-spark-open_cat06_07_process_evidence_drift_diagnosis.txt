## 5. Monitoring architecture

**Layers and alert dependencies (DAG):**

1. **Data-quality monitor (upstream gate):** Unknown activity %, missing queue %, duplicate event rate, diagnosis label coverage.  If breached, *suppress downstream* calibration/drift alerts, trigger pipeline incident, not retraining.
2. **Label-maturity monitor:** Maturity % by month/variant/source, median label delay, Kaplan-Meier maturity curve, censoring bias estimate (V3 vs V2 maturity gap).  If maturity <80% or median delay >45d, mark predictive metrics **provisional**, block retraining.
3. **Predictive monitor:** AUROC, Brier, log-loss on maturity-gated vintage cohorts (60d,90d locks), not cutoff. Stratified by variant/source.
4. **Calibration monitor:** ECE, reliability slope, per-variant calibration-in-the-large. Depends on maturity gate.
5. **Process-variant monitor:** Monthly variant prevalence, DFG fitness/conformance drift, new variant emergence (Unmapped).
6. **Performance-DFG monitor:** Edge median/p90 delay for `Order Part->Part Received`, `Remote Fix`, etc., with supplier SLA breach flag.
7. **Population monitor:** PSI/KS for source mix, rural distance, device age, Partner Z share, propensity shift index.
8. **Intervention/Deployment monitor:** Log of workflow migration (1 Apr), mapping patch (6 May), routing policy (1 Jun), supplier event (10 Jul), Partner Z onboarding (1 Sep), outcome API state. Used to annotate and attribute, not alert alone.

**Dependency logic:** Data-quality alarm OR maturity < threshold  pause predictive/calibration retraining alarms (show as “data/maturity incident, not model incident”). Process-variant + performance-DFG alarm  route to ops/supply chain, not immediate retraining. Population shift + calibration alarm  trigger reweighting check before retraining.

```python
import pandas as pd
import pm4py
from pm4py.objects.log.util import dataframe_utils

# --- 1. Read & format ---
df = pd.read_csv("field_service_events.csv", parse_dates=["timestamp","case_start_time"])
df = pm4py.format_dataframe(df, case_id="case_id", activity_key="activity", timestamp_key="timestamp")

# --- 2. Normalize renamed diagnosis label BEFORE feature extraction ---
# Pipeline bug fix: Apr 1 rename Diagnostic Assessment Completed -> Initial Diagnosis Completed
df["activity"] = df["activity"].replace({"Diagnostic Assessment Completed": "Initial Diagnosis Completed"})
# Collapse generic pipeline artifact
df.loc[df["activity"] == "UNKNOWN_ACTIVITY", "activity"] = pd.NA

# --- 3. Duplicate handling strategy (auditable) ---
# Keep first of exact (case_id, activity, timestamp) duplicates within 60s; flag rate
df = df.sort_values(["case_id","timestamp"])
df["dup_flag"] = df.duplicated(subset=["case_id","activity","timestamp"], keep="first")
# For near-duplicates from duplication bug (same activity +1 sec)
df = df.drop_duplicates(subset=["case_id","activity","timestamp"], keep="first")
print(f"duplicate_rate: {df['dup_flag'].mean():.3%}")

# --- 4. Create two cohort definitions (different interpretation) ---
# Case-start cohort: cases STARTED in month -> outcome eventually observed (needs maturity)
# Event-calendar cohort: events OCCURRING in month -> system load / DFG snapshot
monthly_summaries = []
for month in pd.period_range("2026-01","2026-10", freq="M"):
    start, end = month.start_time, month.end_time
    # Case-start cohort (for variant/outcome prevalence)
    cases_month = df[df["case_start_time"].between(start, end)]["case_id"].unique()
    df_case_cohort = df[df["case_id"].isin(cases_month)]
    # Event-calendar cohort (for DFG performance in month)
    df_event_cohort = pm4py.filter_time_range(df, start.tz_localize("UTC").isoformat(), end.tz_localize("UTC").isoformat())

    # --- 5. Process evidence ---
    variants = pm4py.get_variants(df_case_cohort)  # variant prevalence
    dfg, start_act, end_act = pm4py.discover_dfg(df_event_cohort)
    perf_dfg = pm4py.discover_performance_dfg(df_event_cohort)  # median/mean delays per edge
    # Temporal features audit (missingness lineage)
    tmp = pm4py.extract_temporal_features_dataframe(df_case_cohort)
    # Note: extract_temporal_features does NOT fix label maturity; join with outcome maturity table externally

    # --- 6. Auditable monthly summary (return, do not fit model) ---
    summary = {
        "month": str(month),
        "cases_started": len(cases_month),
        "variant_dist": {k: len(v)/len(cases_month) for k,v in variants.items()},
        "dfg_edges": dfg,
        "perf_edge_OrderPart_PartReceived_median_h": perf_dfg.get(("Order Part","Part Received"), {}).get("median", None),
        "perf_edge_Diagnosis_RemoteFix_median_h": perf_dfg.get(("Initial Diagnosis Completed","Remote Fix"), {}).get("median", None),
        "unknown_share": df_event_cohort["activity"].isna().mean(),
        "missing_queue_proxy": tmp.isna().mean().to_dict() if not tmp.empty else {}
    }
    monthly_summaries.append(summary)
# monthly_summaries -> feed to dashboards with maturity overlay; never used for direct retraining trigger without gate
```

*Note:* No invented `pm4py.detect_drift` used. Maturity, calibration, and population PSI computed outside PM4Py on joined outcome table with `label_available_at_cutoff` flag.

## 6. Risks of acting on the wrong diagnosis

**1. Retraining on immature labels (Oct/Sep bias).**
*Failure:* Using cutoff labels (55% mature, V3 censored) trains model to predict “short-case breach” survivor bias, down-weighting V3 risk and rural Z features. Observed 0.16 would teach model October is low-risk, causing severe under-prediction when labels mature to ~0.30.
*Mitigation:* Enforce vintage-locked training eligibility (90d or maturity >85% per variant). Show maturity-adjusted Kaplan-Meier estimate on training UI; block pipelines if V3 maturity gap >15% vs V2.

**2. Calibrating around a pipeline bug (April).**
*Failure:* Applying Platt scaling to fix April mean predicted 0.280.19 would bake in wrong-prefix features (stale event count, unknown activity). Post-patch backfill would then make model *mis*calibrated and AUROC remains 0.67 because discrimination lost.
*Mitigation:* Data-quality gate precedes calibration. Require Unknown <1% and lineage replay success before calibration. Treat April as incident hold-out, not calibration set; fix feature derivation first, then recalibrate if needed.

**3. Ignoring genuine supplier-driven concept drift (Aug-Sep).**
*Failure:* Dismissing V3 breach 0.64 as “temporary covariate shift, will revert” and only reweighting leads to persistent under-triage: high-risk parts cases not prioritized, SLA breaches continue. Performance-DFG edge 130-155h signals outcome definition unchanged but P(breach|wait) truly increased (stockout vs delay).
*Mitigation:* Run conditional test (breach vs waitHours by month). If lift persists after delay stratification, escalate to ops (supplier) + model (add wait threshold, segment-specific V3 model) + process (expedite flag). Monitor per-variant ECE.

**4. Attributing Partner Z population shift to unfair model behavior.**
*Failure:* Seeing Z observed 0.45 vs non-Z 0.27 and retraining with fairness penalty or down-sampling Z would mask true missing features (rural distance/device age not in model) and V3 concentration, leading to over-correction and worse transport.
*Mitigation:* Stratify by variant/source, reweight to baseline mix, test if error explained by added covariates. Audit fairness only after delay-adjusted, maturity-gated evaluation. Add geography/device features rather than blind debiasing; evaluate Z hold-out separately.

**5. Treating June routing shift as concept drift requiring global retrain.**
*Failure:* Global retrain on V2-heavy June would overweight remote cases, reduce V3 capacity, and lose Jan-Mar stable baseline. AUROC stable proves model generalizes; unnecessary retrain wastes capacity and introduces variance.
*Mitigation:* Use population PSI + per-variant metrics to classify as benign process mix drift. Apply per-variant threshold tuning / reweighting, keep global model until concept drift proven. Log intervention (routing policy) to annotate shift.
