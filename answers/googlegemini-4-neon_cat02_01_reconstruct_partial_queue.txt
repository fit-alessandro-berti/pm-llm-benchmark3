- $W_{q,i,k}$: queue waiting time; $S_{i,k}$: active service time; $W_{i,k} = W_{q,i,k} + S_{i,k}$: station sojourn time; $W_i^{\text{tot}} = e_{i,2} - a_{i,1}$: case-level total sojourn time.
- $L_k(t) = L_{q,k}(t) + L_{s,k}(t)$: station WIP decomposed into queue length and active-in-service count at time $t$.
- $B_r, B_k$: active busy-time of resource $r$ or station $k$; $C_k^{\text{gross}}, C_k^{\text{avail}}$: gross and maintenance-adjusted resource-minute capacity.

## Explicit assumptions
- **A1 (Rounding model):** Every reported timestamp $t$ represents an underlying true time $t^* \in [t - 2.5,\; t + 2.5]\text{ min}$. Consequently, any single nominal duration $\Delta = t_2 - t_1$ between two independently rounded timestamps has an actual value in $[\max(0, \Delta - 5),\; \Delta + 5]\text{ min}$ (assuming physical precedence $t_2^* \ge t_1^*$). For the right-censoring cutoff `14:00`, we treat `14:00` as an exact observation boundary ($t = 360.0$), so elapsed durations of `OPEN`/`WAITING` activities carry $\pm 2.5\text{ min}$ endpoint uncertainty from their start/arrival timestamp alone.
- **A2 (Simultaneous-event convention):** For time-series WIP and queue curves, we adopt a **right-continuous step-function convention** ($L(t) = \lim_{\epsilon \downarrow 0} L(t+\epsilon)$), where all events sharing a rounded timestamp $t$ take effect simultaneously (equivalently: completions before starts before arrivals at the same timestamp, preventing artificial single-resource overlap at `11:00` on C1 where P07 ends and P09 starts). Under rounding, an arrival timestamped $t$ could physically precede a departure timestamped $t$ by up to $5\text{ min}$; therefore, we also report **transient arrival-before-departure peak bounds** wherever simultaneous ties occur. Time-averaged WIP $\bar{L}$ is invariant to tie-breaking order (a measure-zero effect).
- **A3 (Subperiod boundary convention):** Subperiods are partitioned into half-open intervals `[08:00, 10:00)`, `[10:00, 12:00)`, and closed final interval `[12:00, 14:00]`. Events exactly at `10:00` (P14 arrival, P07 S1 completion) and `12:00` (P14 S1 completion, P08 S2 completion) belong to the interval starting at that timestamp; boundary sensitivity is negligible and noted where relevant.
- **A4 (Capacity, single-tasking, and maintenance):** Resources I1, I2, C1, and C2 are single-task resources (no concurrent execution on the same resource). C2's maintenance window `10:55–11:10` removes $15\text{ min}$ of nominal capacity ($C_{\text{S2}}^{\text{gross}} = 720\text{ res-min}$, $C_{\text{S2}}^{\text{avail}} = 705\text{ res-min}$; if maintenance endpoints are also rounded, true unavailable time lies in $[10, 20]\text{ min}$). Observed 5-minute gaps between consecutive jobs on the same resource (present in 19 of 21 observed consecutive same-resource transitions) are treated as **non-active changeover/handling or idle time** in primary utilization figures, while acknowledging that rounding plus short changeovers mean effective (active + setup) utilization is higher.
- **A5 (Status semantics and right-censoring):** `MISSING` denotes an occurred activity with known resource and completion but unrecorded start; `OPEN` denotes an activity in progress at `14:00` (elapsed service is observed; final service is right-censored); blank S2 fields after completed S1 denote `WAITING_FOR_S2` at `14:00` (elapsed S2 wait is observed; final wait is right-censored); blank S1 fields denote `WAITING_FOR_S1` at `14:00`. Open and waiting cases are **never discarded** from WIP, queue, or utilization calculations.
- **A6 (Missing-start constraint and scenario assumptions):** For each `MISSING` start $s_{i,k}$, hard structural bounds enforce precedence, single-task resource non-overlap, and nonnegative service time:
  $$s_{i,k}^{\min} = \max(a_{i,k},\; e_{\text{prev}(r_{i,k})}), \qquad s_{i,k}^{\max} = e_{i,k}.$$
  Because hard bounds allow implausible 0-minute service times, we also define a **central gap-consistent imputation** assuming the empirically dominant $5\text{ min}$ inter-job gap ($s_{i,k}^{\text{central}} = s_{i,k}^{\min} + 5$, verified $\le e_{i,k}$ for all four missing starts), alongside optimistic, midpoint, and plausible-minimum-service scenarios in Section 6. No undocumented extra servers are assumed in baseline reconstruction, though P11's short feasible S2 window is flagged as a possible anomaly.
- **A7 (Initial system state):** The system is assumed empty just prior to `08:00` (no carryover WIP from before `08:00`, consistent with I1 starting P01 at `08:05` and I2 starting P02 at `08:10`).

# 2. Reconstruction method and formulas

## 2.1 Case-level time quantities
For each case $i$ and station $k \in \{1, 2\}$:
- **Fully observed completed visit:**
  $$W_{q,i,k} = s_{i,k} - a_{i,k}, \qquad S_{i,k} = e_{i,k} - s_{i,k}, \qquad W_{i,k} = e_{i,k} - a_{i,k}.$$
- **Completed visit with `MISSING` start (P07, P15 at S1; P05, P11 at S2):**
  Station sojourn time $W_{i,k} = e_{i,k} - a_{i,k}$ is **exact (nominal)** and unaffected by the missing start. Waiting and active service are bounded on the nominal grid by:
  $$W_{q,i,k} \in \bigl[s_{i,k}^{\min} - a_{i,k},\; e_{i,k} - a_{i,k}\bigr], \qquad S_{i,k} \in \bigl[0,\; e_{i,k} - s_{i,k}^{\min}\bigr], \qquad W_{q,i,k} + S_{i,k} = W_{i,k}.$$
  Incorporating A1 rounding widens each interval by $\pm 5\text{ min}$ (truncated below at $0$). Central estimates use $s_{i,k}^{\text{central}} = s_{i,k}^{\min} + 5\text{ min}$.
- **`OPEN` visit at `14:00` (P21 at S1; P15, P17 at S2):**
  Queue waiting time $W_{q,i,k} = s_{i,k} - a_{i,k}$ is **fully observed**. Active service is right-censored:
  $$S_{i,k}^{\text{elapsed}} = 360 - s_{i,k}, \qquad S_{i,k}^{\text{final}} \ge S_{i,k}^{\text{elapsed}}, \qquad W_{i,k}^{\text{final}} \ge 360 - a_{i,k}.$$
- **`WAITING` case at `14:00` (P22 at S1; P16, P18, P19, P20 at S2):**
  Queue wait is right-censored: $W_{q,i,k}^{\text{elapsed}} = 360 - a_{i,k}$, $W_{q,i,k}^{\text{final}} \ge W_{q,i,k}^{\text{elapsed}}$; active service is unobserved ($0$ in-window).
- **Case-level total sojourn time:**
  For the 14 completed cases (P01–P14), $W_i^{\text{tot}} = e_{i,2} - a_{i,1}$ is exact (nominal) even for P05, P07, and P11. For incomplete cases (P15–P22), $W_i^{\text{tot,final}} \ge 360 - a_{i,1}$.

## 2.2 Station WIP, queue length, throughput, and utilization
For any analysis window $[t_0, t_1]$ of length $\Delta T = t_1 - t_0$:
- **Station WIP (invariant to missing starts!):** Because every $a_{i,k}$ and every $\min(e_{i,k}, 360)$ is observed, total station WIP $L_k(t)$ is **nominally exact**:
  $$L_k(t) = \sum_i \mathbf{1}\bigl\{a_{i,k} \le t < \tilde{e}_{i,k}\bigr\}, \qquad \tilde{e}_{i,k} = \begin{cases} e_{i,k} & \text{if completed}, \\ 360 & \text{if OPEN/WAITING at 14:00}. \end{cases}$$
  Time-averaged WIP is $\bar{L}_k = \frac{1}{\Delta T}\int_{t_0}^{t_1} L_k(t)\,dt = \frac{1}{\Delta T}\sum_i \max\bigl(0,\, \min(\tilde{e}_{i,k}, t_1) - \max(a_{i,k}, t_0)\bigr)$.
- **Active busy-time and utilization:** For resource $r$ and station $k$:
  $$B_r[t_0, t_1] = \sum_{i:\, r_{i,k}=r} \max\bigl(0,\, \min(\tilde{e}_{i,k}, t_1) - \max(s_{i,k}, t_0)\bigr), \qquad U_k^{\text{avail}} = \frac{\sum_{r \in k} B_r[t_0, t_1]}{C_k^{\text{avail}}[t_0, t_1]}.$$
  Note that `OPEN` activities contribute their elapsed active time within $[t_0, t_1]$. Missing-start activities contribute lower/central/upper busy-times according to $s_{i,k} \in \{s_{i,k}^{\max},\; s_{i,k}^{\text{central}},\; s_{i,k}^{\min}\}$.
- **Decomposed in-service and queue averages:**
  $$\bar{L}_{s,k} = \frac{B_k[t_0, t_1]}{\Delta T}, \qquad \bar{L}_{q,k} = \bar{L}_k - \bar{L}_{s,k}.$$
- **Arrival and departure rates:** $\lambda_k = N_k^{\text{arr}}[t_0, t_1] / (\Delta T/60)$ and $\theta_k = N_k^{\text{dep}}[t_0, t_1] / (\Delta T/60)$ in cases/hr.

## 2.3 Little's Law consistency check
- **Exact finite-horizon identity (always holds, not a steady-state test):** $\bar{L}_k = \frac{1}{\Delta T}\sum_i w_{i,k}^{\text{in-window}}$.
- **Steady-state Little's Law ($\bar{L}_k \approx \lambda_k \bar{W}_k$):** Requires approximate stationarity (no strong WIP drift, stable arrival/service rates, and minimal censoring). Over the full `08:00–14:00` window this assumption is **violated** (empty start, arrival surge then cutoff, 8 censored cases). We therefore restrict steady-state Little's Law checks to two locally quasi-stationary subintervals: **S1 on `[10:00, 12:00]`** (WIP plateau at 7–8) and **S2 on `[09:00, 10:55]`** (post-warm-up, pre-maintenance WIP of 2–4).

# 5. Bottleneck and temporal interpretation

## Evidence vs. hypotheses
**Direct evidence from the log:**
1. **Service-time asymmetry (structural capacity):** Observed S2 active service times average **40 min** (median 40, range 25–50; ~38 min central incl. P05/P11), which is **~35–43% longer** than S1's **28 min** (median 30, range 20–30). Including the pervasive ~5-minute inter-job changeover gaps, effective two-server capacity is **~3.5–3.6 cases/hr at S1** versus **~2.7–2.8 cases/hr at S2**.
2. **Three-phase temporal shift:**
   - *Phase 1 (`08:00–10:10`, arrival surge):* External arrivals hit **6.5 cases/hr**, nearly double S1's capacity. S1 WIP climbs from 0 to **8**, while S1 meters inflow to S2 at only **3.0 cases/hr**. S2 starts starved (70 res-min idle before `08:40`) and holds just 2–3 cases.
   - *Phase 2 (`10:10–12:15`, high plateau + C2 outage):* Arrivals moderate to **4.0 cases/hr**, stabilizing S1 at 7–8 WIP. Meanwhile, S1 feeds S2 at **3.5 cases/hr** — consistently above S2's ~2.7–2.8 cases/hr capacity. C2's maintenance (`10:55–11:10`) halves S2 capacity temporarily and pushes S2 WIP from 3–4 up to **5**, lifting S2 waiting times from 20–25 min to **45–80 min**.
   - *Phase 3 (`12:15–14:00`, upstream drain, downstream accumulation):* External arrivals stop after `12:10` (P22). S1 drains rapidly from **8 down to 2** cases, whereas S2 climbs to its peak WIP of **7** at `13:45` and ends at **6** (75% of all remaining system WIP).
3. **Post-warm-up utilization:** Once S2 is no longer starved (`09:00–14:00`), S2 available utilization (**87%** central, up to **89%** in `10:00–12:00`) exceeds S1's (**84%**).
4. **Operational anomalies observed in timestamps:**
   - *Two non-FIFO overtakes at S2:* P09 (S1 end `10:35`) starts C1 at `11:00` ahead of P08 (S1 end `10:20`, starts C2 at `11:15`); P17 (S1 end `12:50`) starts C1 at `13:55` ahead of P16 (S1 end `12:35`, still waiting at `14:00`).
   - *Unexplained end-of-window idle time on I2:* I2 finishes P20 at `13:45` and sits idle for 15 minutes while P22 has been waiting since `12:10`.
   - *S2 service-time lengthening on C2:* C2 runs 40, 40, 40 min pre-maintenance and 45, [$\le 25$], 50 min post-maintenance (plus a 10-min gap `13:20–13:30` before P15).

**Synthesis — Which station is the bottleneck?**
The evidence strongly supports **S2 as the long-run structural (capacity) bottleneck**, combined with a **time-varying short-run congestion shift**: S1 acts as the *front-end surge absorber* during `08:00–12:15` because the morning arrival burst exceeds S1's capacity first (and S1 physically shields S2 from seeing the 6.5/hr burst). Once arrivals subside after `12:10`, S1 clears quickly while S2's structural deficit (~3.5/hr inflow vs. ~2.7–2.8/hr outflow) leaves a growing calibration backlog.

**Role of the C2 maintenance interval (`10:55–11:10`):**
The 15-minute nominal outage (25-minute total gap between P06 ending at `10:50` and P08 starting at `11:15`) removed roughly **0.4–0.6 cases** of S2 throughput capacity. It directly triggered the sharp jump in waiting time for P08 (55 min) and propagated delay through P10–P20. However, it **amplified rather than solely caused** S2 congestion: even without maintenance, S1's 3.5/hr feed into S2's ~2.8/hr capacity would still have grown S2 WIP by ~0.7 cases/hr (~3.5 cases over 5 hours).

**Defensible hypotheses (not directly proven by the log):**
- *H1 (Non-FIFO dispatching):* P08 may have required C2-specific tooling/calibration (or been pre-assigned to C2 before maintenance), while P17 bypassing P16 could reflect priority expediting, a parts/documentation hold on P16, or non-FIFO queue discipline.
- *H2 (I2 idle at `13:45–14:00`):* Inspectors may avoid starting a ~30-minute inspection 15 minutes before a `14:00` shift break/cutoff, or P22's start was logged late / placed on hold.
- *H3 (Short S2 window for P11):* P11's max nominal C2 duration of 25 min (vs. C2's observed 40–50 min) could reflect a simpler component variant (like P10's 25 min on C1), rounding at both ends (up to 30 min actual), or undocumented assistance/reassignment.

# 6. Missingness, censoring, and sensitivity analysis

We compare four missing-start imputation scenarios over `[08:00, 14:00]` (nominal timestamps), followed by rounding and censoring sensitivity:
1. **Optimistic-Wait / Max-Service (0-min gap):** Missing starts at $s_{i,k}^{\min}$ (P07=`09:25`, P15=`11:40`, P05=`09:45`, P11=`12:00`).
2. **Central / Gap-Consistent (5-min gap):** Missing starts at $s_{i,k}^{\min} + 5$ (P07=`09:30`, P15=`11:45`, P05=`09:50`, P11=`12:05`).
3. **Plausible-Pessimistic (observed-min service floor):** S1 missing services floored at S1 obs min 20 min (P07=`09:40`, P15=`11:55`); S2 missing services at 25 min for P05 (`09:50`, obs min) and 15 min for P11 (`12:10`).
4. **Hard-Structural Pessimistic (0-min service):** Missing starts at $e_{i,k}$ (mathematical worst-case bound; operationally implausible).

| Scenario | S1 mean wait (21 started, min) | S1 mean svc (20 comp, min) | S1 util (% of 720) | S1 mean queue (cases) | S2 mean wait (16 started, min) | S2 mean svc (14 comp, min) | S2 util (% of 705 avail) | S2 mean queue (cases) |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 1. Optimistic-Wait / Max-Svc | 65.2 | 28.8 | 84.0% | 4.11 | 36.6 | 38.2 | 80.9% | 2.14 |
| **2. Central (5-min gap)** | **65.7** | **28.3** | **82.6%** | **4.14** | **37.2** | **37.5** | **79.4%** | **2.17** |
| 3. Plausible-Pessimistic | 66.7 | 27.3 | 79.9% | 4.19 | 37.5 | 37.1 | 78.7% | 2.18 |
| 4. Hard-Structural Pessimistic | 68.6 | 25.3 | 74.3% | 4.31 | 40.0 | 34.3 | 73.0% | 2.29 |

**Timestamp rounding sensitivity ($\pm 2.5\text{ min}$ per timestamp):**
- Individual waits and service times carry $\pm 5\text{ min}$ uncertainty (e.g., P11's max S2 service extends from 25 to 30 min; C2 maintenance could be 10–20 min).
- Because consecutive same-resource jobs cannot physically overlap, rounding errors partially cancel across a chain of jobs, EXCEPT that the 5-minute inter-job gaps could hide 1–3 min of extra active service per job if actual changeovers are shorter than 5 min. Under an extreme rounding bound where half of the 5-min gaps are active service, full-window active utilization rises by ~3–5 percentage points (and post-warm-up utilization approaches ~90–93% at both stations).
- Instantaneous peak WIP could transiently increase by +1 at tied timestamps (S1 peak 8 $\to$ 9 at `11:30`; system peak remains 13, potentially reached at `12:10` as well as `11:50`).

**Right-censoring sensitivity (P15–P22):**
- Discarding the 8 open/waiting cases would **underestimate S2 busy-time by 35 min** (-5.0 pp utilization) and **S1 busy-time by 30 min** (-4.2 pp utilization), hide the `12:15–14:00` S2 backlog buildup entirely, and understate mean S2 waiting time (completed-only central mean = 32 min vs. all-started 37 min vs. true 20-case cohort $\ge 45\text{–}55\text{ min}$ once P16, P18–P20 finish waiting).

**Stability assessment:**
- **Robust conclusions (invariant across all plausible scenarios):** Exact nominal station WIP curves ($\bar{L}_{\text{S1}} = 5.79$, $\bar{L}_{\text{S2}} = 3.72$); completed-case sojourn times (mean 146 min); S2 as the structural bottleneck (service time ~38–40 min vs. S1 ~28 min; post-warm-up S2 utilization > S1); the 3-phase shift from S1 arrival-surge congestion to S2 structural backlog; non-FIFO episodes (P08/P09, P16/P17); and severe downward bias if censored cases are omitted.
- **Sensitive quantities:** Exact active-vs-changeover utilization (~4–5 pp across plausible imputations, ~10 pp across hard bounds); exact waiting-vs-service splits for P05, P07, P11, and P15; and final post-14:00 sojourn times for P15–P22.

def parse_status_time(val: str):
    v = val.strip()

def interval_overlap(a: float, b: float, t0: float, t1: float) -> float:
    if np.isnan(a) or np.isnan(b):
        return 0.0
    return max(0.0, min(b, t1) - max(a, t0))

def exact_peak_wip_and_queue(frame: pd.DataFrame, station: str, start_map: dict, t0: float, t1: float):
    # Right-continuous sweep over all distinct event times in [t0, t1)
    if station == "S1":
        arrs = frame["arrival_s1_m"].values
        ends = frame["s1_eff_end_m"].values
        starts = [
            start_map[(r["case"], "S1")] if r["s1_start_status"] == "MISSING" else r["s1_start_m"]
            for _, r in frame.iterrows()
        ]
    else:
        sub = frame[frame["s2_arr_m"].notna()]
        arrs = sub["s2_arr_m"].values
        ends = sub["s2_eff_end_m"].values
        starts = [
            start_map[(r["case"], "S2")] if r["s2_start_status"] == "MISSING" else r["s2_start_m"]
            for _, r in sub.iterrows()
        ]
    pts = sorted({t for t in list(arrs) + list(ends) + [s for s in starts if not np.isnan(s)] + [t0, t1] if t0 <= t < t1})
    peak_wip, peak_q = 0, 0
    for t in pts:
        wip = sum(1 for a, e in zip(arrs, ends) if a <= t < e)
        svc = sum(1 for s, e in zip(starts, ends) if not np.isnan(s) and s <= t < e)
        peak_wip = max(peak_wip, wip)
        peak_q = max(peak_q, wip - svc)
    return peak_wip, peak_q

def eval_station_window(frame: pd.DataFrame, station: str, start_map: dict, t0: float, t1: float, label: str):
    dt = t1 - t0
    maint_loss = interval_overlap(175.0, 190.0, t0, t1) if station == "S2" else 0.0
    avail_cap = 2.0 * dt - maint_loss

    wip_min, busy_min = 0.0, 0.0
    arr_cnt, comp_cnt = 0, 0
    for _, r in frame.iterrows():
        if station == "S1":
            a, e_eff, e_stat = r["arrival_s1_m"], r["s1_eff_end_m"], r["s1_end_status"]
            s = start_map[(r["case"], "S1")] if r["s1_start_status"] == "MISSING" else r["s1_start_m"]
            e_obs = r["s1_end_m"]
        else:
            if pd.isna(r["s2_arr_m"]):
                continue
            a, e_eff, e_stat = r["s2_arr_m"], r["s2_eff_end_m"], r["s2_end_status"]
            s = start_map[(r["case"], "S2")] if r["s2_start_status"] == "MISSING" else r["s2_start_m"]
            e_obs = r["s2_end_m"]

        wip_min += interval_overlap(a, e_eff, t0, t1)
        busy_min += interval_overlap(s, e_eff, t0, t1)
        in_arr = (t0 <= a <= t1) if t1 == 360.0 else (t0 <= a < t1)
        in_comp = (e_stat == "OBSERVED") and ((t0 <= e_obs <= t1) if t1 == 360.0 else (t0 <= e_obs < t1))
        arr_cnt += int(in_arr)
        comp_cnt += int(in_comp)

    peak_wip, peak_q = exact_peak_wip_and_queue(frame, station, start_map, t0, t1)
    return {
        "station": station,
        "window": label,
        "arr": arr_cnt,
        "comp": comp_cnt,
        "arr_rate_hr": round(arr_cnt / (dt / 60.0), 2),
        "dep_rate_hr": round(comp_cnt / (dt / 60.0), 2),
        "mean_wip": round(wip_min / dt, 2),
        "mean_q": round((wip_min - busy_min) / dt, 2),
        "peak_wip": peak_wip,
        "peak_q": peak_q,
        "busy_min": round(busy_min, 1),
        "avail_cap": round(avail_cap, 1),
        "util_avail_pct": round(100.0 * busy_min / avail_cap, 1),
    }
