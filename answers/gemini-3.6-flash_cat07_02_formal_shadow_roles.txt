# 5. PM4Py role-discovery and similarity code

```python
import pandas as pd
import numpy as np
import pm4py
from pm4py.objects.log.util import dataframe_utils

def analyze_organizational_roles_and_networks(file_path_or_df):
    """
    Loads event log, formats dataframe, discovers organizational roles and resource similarities,
    builds handover/working-together networks, and joins attributes (case complexity, temporary substitutions)
    to prevent over-interpreting activity-frequency clusters as formal authority.
    """
    # 1. Load Dataframe and Format using PM4Py
    if isinstance(file_path_or_df, str):
        df = pd.read_csv(file_path_or_df)
    else:
        df = file_path_or_df.copy()

    # Ensure PM4Py format compliance
    df = dataframe_utils.convert_timestamp_columns_in_df(df)
    df = pm4py.format_dataframe(
        df,
        case_id='case:concept:name',
        activity_key='concept:name',
        timestamp_key='time:timestamp',
        resource_key='org:resource'
    )

    # 2. Naive Activity-Based Organizational Role Discovery
    # This uses PM4Py's built-in role discovery based on activity profiles
    discovered_roles = pm4py.discover_organizational_roles(df)
    print("=== DISCOVERED ORGANIZATIONAL ROLES (PM4Py Default) ===")
    for role in discovered_roles:
        print(f"Role Name: {role.name}")
        print(f"  Activities: {role.activities}")
        print(f"  Members: {[r.name for r in role.resources]}\n")

    # 3. Discover Activity-Based Resource Similarity Matrix
    similarity_matrix = pm4py.discover_activity_based_resource_similarity(df)
    
    # 4. Discover Handover of Work and Working-Together Networks
    how_network = pm4py.discover_handover_of_work_network(df)
    wt_network = pm4py.discover_working_together_network(df)

    # 5. Integrate Contextual Metadata: Case Complexity & Temporary Substitution
    # Calculate resource-level complexity profiles
    resource_complexity = df.groupby('org:resource').agg(
        total_events=('case:concept:name', 'count'),
        unique_cases=('case:concept:name', 'nunique'),
        median_complexity=('case_complexity', 'median'),
        high_critical_cases=('case_complexity', lambda x: (x >= 0.7).sum()),
        temp_substitution_events=('temporary_substitution', lambda x: (x == True).sum()),
        reopen_touches=('concept:name', lambda x: (x == 'Reopen Request').sum())
    ).reset_index()

    # Calculate activity counts per resource
    activity_pivot = pd.crosstab(df['org:resource'], df['concept:name'])

    # Join activity profiles with complexity metrics
    enriched_resource_profile = pd.merge(
        resource_complexity,
        activity_pivot,
        on='org:resource',
        how='inner'
    )

    # 6. Advanced Role Clustering Guardrails (Preventing Over-interpretation)
    # Filter out temporary substitutions to assess baseline vs. substituted authority
    baseline_df = df[df['temporary_substitution'] == False]
    baseline_roles = pm4py.discover_organizational_roles(baseline_df)

    print("=== ENRICHED RESOURCE PROFILE (Sample View) ===")
    print(enriched_resource_profile[['org:resource', 'total_events', 'median_complexity', 'high_critical_cases', 'temp_substitution_events']])

    # Return structured results for downstream auditing
    return {
        'formatted_df': df,
        'discovered_roles': discovered_roles,
        'baseline_roles': baseline_roles,
        'similarity_matrix': similarity_matrix,
        'handover_network': how_network,
        'working_together_network': wt_network,
        'enriched_profile': enriched_resource_profile
    }

# Example Usage Pseudocode Execution:
# results = analyze_organizational_roles_and_networks('order_resolution_log.csv')
```

### Explanation of Code Logic & Guardrails:
1. **`pm4py.format_dataframe`**: Standardizes case IDs, timestamps, activities, and resources to prepare the log for process mining.
2. **`pm4py.discover_organizational_roles` & `discover_activity_based_resource_similarity`**: Extracts naive activity vectors to identify resources performing similar tasks.
3. **Handover & Working Together Networks**: Uncovers structural communication topology (e.g., revealing that R13_Mateo interacts with all units, whereas R05_Erik receives handovers primarily from R13 or R03).
4. **Contextual Metadata Join**: Joins `case_complexity` and `temporary_substitution` flags directly to resource activity summaries. This ensures that resources with high activity similarity (e.g., R03 vs. R04 or R01 vs. R11) are distinguished based on median case complexity score and temporary assignment spikes.
5. **Baseline Filtering**: Discovers roles on `temporary_substitution == False` subset to prevent temporary coverage (e.g., Giorgio covering Fatima's pricing reviews or Mateo covering Hana's approvals) from polluting formal role definitions.

### Two Essential Cautions Against Restructuring Based Solely on Process-Mined Roles

#### Caution 1: Naïve Cluster Analysis Conflates Temporary Emergency Coverage with Formal Competence and Authority
Process mining algorithms detect execution patterns, not organizational authority or regulatory compliance. If management restructures formal role definitions based purely on mined clusters:
* They risk formalizing temporary, emergency, or informal substitutions (such as R07_Giorgio filling in for R06_Fatima, or R13_Mateo covering R08_Hana's approvals) as permanent operational rights.
* *Consequence:* This leads to governance breaches, loss of separation-of-duties (SoD) controls, legal compliance exposure, and elevated error rates (e.g., Mateo’s 62% recheck rate on acting approvals).

#### Caution 2: Frequency-Based Role Discovery Disregards Criticality and Risk Exposure
Frequency-based clustering naturally privileges high-volume, repetitive transactions (e.g., intake, standard responses, quality checks) while marginalizing low-frequency, high-impact specialized interventions:
* Specialists like R05_Erik (Security Review) or R08_Hana (Supervisor Approval) execute low event counts relative to front-office or automation bots. A frequency-driven restructuring might conclude these roles are underutilized or redundant, leading to downsizing or merging them into generalist roles.
* *Consequence:* Disbanding specialized expert roles severely impairs organizational capability during high-complexity incidents, causing severe SLA breaches, unmitigated enterprise risk, and systemic operational bottlenecks.
