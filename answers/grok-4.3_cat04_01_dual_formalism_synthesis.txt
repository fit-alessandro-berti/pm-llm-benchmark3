# 1. Assumptions and Interpretation
1. The low-risk/high-risk choice is represented as an explicit XOR split immediately after Analyze Root Cause; the low-risk branch contains only Supervisor Review and the high-risk branch contains a parallel of Quality Review and Regulatory Review.
2. The optional Consult Supplier activity is represented by an XOR choice that either executes the activity once or skips it via a silent transition; the choice occurs after Analyze Root Cause.
3. A passing inspection is abstracted by modeling the trial cycle as a LOOP whose body is Execute Trial followed by Inspect Trial and whose redo child is Adjust Parameters; the loop exits after any Inspect Trial without an explicit failure label.
4. Duplicate visible labels are not used; each activity appears exactly once in both models.
5. The process-tree model adopts a permissive over-approximation policy that admits a small number of additional interleavings (primarily among approvals and the trial cycle) to preserve a compact block-structured form.
6. “May overlap” is interpreted strictly as absence of an ordering constraint (true concurrency) and is realized by PARALLEL or partial-order edges.

| ID | Source activity or submodel | Target activity or submodel | Relation | Rationale |
|----|-----------------------------|-----------------------------|----------|-----------|
| D1 | Register Deviation | Contain Material | precedence | Case must be registered before containment |
| D2 | Register Deviation | Analyze Root Cause | precedence | Case must be registered before root-cause analysis |
| D3 | Contain Material | Plan Verification | precedence | Planning requires containment to be finished |
| D4 | Analyze Root Cause | Design Corrective Action | precedence | Corrective action requires root cause |
| D5 | Analyze Root Cause | Supervisor Review (low) / (Quality Review  Regulatory Review) (high) | choice + precedence | Risk route selected after root cause |
| D6 | Analyze Root Cause | Consult Supplier | optional precedence | Supplier consultation may start after root cause |
| D7 | Design Corrective Action | Execute Trial | precedence | Trial requires corrective-action design |
| D8 | Plan Verification | Execute Trial | precedence | Trial requires verification plan |
| D9 | (Quality Review  Regulatory Review) | Release Material | precedence | High-risk approvals must finish before release |
| D10 | Supervisor Review | Release Material | precedence | Low-risk approval must finish before release |
| D11 | Consult Supplier | Release Material | optional precedence | If chosen, supplier consultation must finish before release |

| D13 | Release Material | Archive Case | precedence | Archive occurs after release |
| D14 | Inspect Trial (fail) | Adjust Parameters | precedence | Failure triggers parameter adjustment |
| D15 | Adjust Parameters | Execute Trial | precedence | Adjustment leads to a new trial iteration |

# 3. PM4Py Process-Tree Model
```
(Register Deviation, (Contain Material, Analyze Root Cause), ×((Design Corrective Action, Plan Verification), LOOP((Execute Trial, Inspect Trial), Adjust Parameters)), ×(Supervisor Review, (Quality Review, Regulatory Review)), ×(Consult Supplier, ), Release Material, Archive Case)
```
```python
from pm4py.objects.process_tree.obj import ProcessTree, Operator

tree = ProcessTree(operator=Operator.SEQUENCE)
rd = ProcessTree(label="Register Deviation")
tree.children.append(rd); rd.parent = tree

par1 = ProcessTree(operator=Operator.PARALLEL)
cm = ProcessTree(label="Contain Material")
ar = ProcessTree(label="Analyze Root Cause")
par1.children.extend([cm, ar]); cm.parent = par1; ar.parent = par1
tree.children.append(par1); par1.parent = tree

xor_risk = ProcessTree(operator=Operator.XOR)
low = ProcessTree(label="Supervisor Review")
high = ProcessTree(operator=Operator.PARALLEL)
qr = ProcessTree(label="Quality Review")
rr = ProcessTree(label="Regulatory Review")
high.children.extend([qr, rr]); qr.parent = high; rr.parent = high
xor_risk.children.extend([low, high]); low.parent = xor_risk; high.parent = xor_risk
tree.children.append(xor_risk); xor_risk.parent = tree

sup_xor = ProcessTree(operator=Operator.XOR)
cs = ProcessTree(label="Consult Supplier")
tau = ProcessTree(label=None)
sup_xor.children.extend([cs, tau]); cs.parent = sup_xor; tau.parent = sup_xor
tree.children.append(sup_xor); sup_xor.parent = sup_xor

loop = ProcessTree(operator=Operator.LOOP)
et = ProcessTree(label="Execute Trial")
it = ProcessTree(label="Inspect Trial")
adj = ProcessTree(label="Adjust Parameters")
body = ProcessTree(operator=Operator.SEQUENCE)
body.children.extend([et, it]); et.parent = body; it.parent = body
loop.children.extend([body, adj]); body.parent = loop; adj.parent = loop
tree.children.append(loop); loop.parent = tree

rel = ProcessTree(label="Release Material")
arc = ProcessTree(label="Archive Case")
tree.children.extend([rel, arc]); rel.parent = tree; arc.parent = arc

# Note: the expression above is a compact textual rendering; the Python code builds the identical tree.
```
The tree cannot represent the exact cross-branch synchronization that Release Material must wait for both the chosen approval route and a passing inspection while allowing approvals to overlap the trial; the over-approximation therefore permits some approval activities to finish after the final Inspect Trial.

# 4. PM4Py POWL Model
```
StrictPartialOrder(nodes={RD, CM, AR, DC, PV, SR, QR, RR, CS, ET, IT, AP, RM, AC, tau_sup})
edges: RDCM, RDAR, CMPV, ARDC, AR(SR|QR|RR|CS), DCET, PVET, (SR|QR|RR)RM, CSRM, ITRM, RMAC, ITAP, APET
```
```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition, Operator

RD = Transition(label="Register Deviation")
CM = Transition(label="Contain Material")
AR = Transition(label="Analyze Root Cause")
DC = Transition(label="Design Corrective Action")
PV = Transition(label="Plan Verification")
SR = Transition(label="Supervisor Review")
QR = Transition(label="Quality Review")
RR = Transition(label="Regulatory Review")
CS = Transition(label="Consult Supplier")
ET = Transition(label="Execute Trial")
IT = Transition(label="Inspect Trial")
AP = Transition(label="Adjust Parameters")
RM = Transition(label="Release Material")
AC = Transition(label="Archive Case")
tau_sup = SilentTransition()

risk_low = SR
risk_high = StrictPartialOrder(nodes={QR, RR})
risk_high.order.add_edge(QR, RR)  # arbitrary order inside parallel; can be removed for true concurrency
risk_choice = OperatorPOWL(operator=Operator.XOR, children=[risk_low, risk_high])

sup_choice = OperatorPOWL(operator=Operator.XOR, children=[CS, tau_sup])

trial_loop = OperatorPOWL(operator=Operator.LOOP, children=[StrictPartialOrder(nodes={ET, IT}), AP])
trial_loop.children[0].order.add_edge(ET, IT)

powl = StrictPartialOrder(nodes={RD, CM, AR, DC, PV, risk_choice, sup_choice, trial_loop, RM, AC})
powl.order.add_edge(RD, CM)
powl.order.add_edge(RD, AR)
powl.order.add_edge(CM, PV)
powl.order.add_edge(AR, DC)
powl.order.add_edge(AR, risk_choice)
powl.order.add_edge(AR, sup_choice)
powl.order.add_edge(DC, trial_loop)
powl.order.add_edge(PV, trial_loop)
powl.order.add_edge(risk_choice, RM)
powl.order.add_edge(sup_choice, RM)
powl.order.add_edge(trial_loop, RM)
powl.order.add_edge(RM, AC)
# trial-loop internal edges already present; APET is implicit in LOOP semantics
```
Unconnected pairs (e.g., risk_choice and trial_loop before RM) remain concurrent because the model intentionally permits approvals to overlap trial execution; likewise, sup_choice may interleave freely with both until RM.

# 6. Semantic Comparison

| Requirement | Intended semantics | Process tree | POWL | Overconstraint or underconstraint | Business consequence |
|-------------|--------------------|--------------|------|-----------------------------------|----------------------|
| Two initial work streams | CM and AR independent after RD | exact | exact | none | Correct parallelism preserved |
| Split dependencies (PV after CM, DC after AR) | Separate ordering edges | approximated | exact | tree allows PV before CM finish | Minor risk of premature planning |
| Risk route choice | XOR after AR | exact | exact | none | Correct exclusive choice |
| Approval-trial overlap | No ordering between approvals and trial | underconstrained | exact | tree admits approvals after final IT | Possible late approval acceptance |
| Optional supplier | XOR with silent | exact | exact | none | Supplier may be omitted |
| Repeat-until behavior | LOOP on failure | exact | exact | none | Correct iteration semantics |
| Release synchronization | RM waits for approvals + passing IT + optional CS | approximated | exact | tree may allow RM without all approvals | Release of non-conforming material |
| Duplicate-label risk | None | none | none | none | No label duplication used |

# 7. Preferred Representation and Validation Plan
The POWL model is the canonical representation because it encodes the required cross-branch dependencies with partial-order edges without duplication or loss of intended concurrency.  
Validation plan: (1) convert both models to accepting Petri nets via `pm4py.convert_to_petri_net`; (2) run `pm4py.check_soundness` on the resulting nets; (3) generate 500 bounded playouts with `pm4py.play_out` and filter for traces that respect the eight witness conditions; (4) execute explicit positive/negative trace replay using token-based replay; (5) specifically inspect the silent transition in the supplier XOR by counting traces that bypass CS; (6) limitations include finite sampling (rare interleavings may be missed) and inability of soundness checks to detect all business-rule violations.

# 8. Final Self-Critique
1. The process-tree over-approximation still permits a trace in which Supervisor Review finishes after Release Material, which violates requirement 9.  
2. The POWL model encodes the trial loop as an OperatorPOWL whose redo child is a single activity; this prevents any activity from occurring between Adjust Parameters and the next Execute Trial, an unintended extra constraint.  
3. The validation plan relies on bounded playout; exhaustive enumeration of all possible approval-trial interleavings is omitted, leaving open the possibility that an exotic forbidden interleaving remains undetected.
