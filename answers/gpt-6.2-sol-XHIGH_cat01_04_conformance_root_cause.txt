A single June claim can acquire several penalties while passing each business control. A renamed screening event produces a move on log for `Risk Screen` and a visible move on model for `Classify`. Gateway telemetry adds another move on log. Ingestion delays can make a later notification appear earlier than the decision, forcing an optimal alignment to leave one of the observed activities unmatched and insert a modeled activity. Depending on ties and costs, the returned alignment may choose different moves to represent the same reversal. The June-July report shows successive fitness recovery after each repair. A case may require several repairs to fit, so the increments depend on repair order.

In August the true process and the comparator can diverge for a different reason. A policy-driven sign-off can be performed correctly and appear as an extra event against the frozen model. The optional branch absorbs it while allowing an above-threshold claim to pass without sign-off. Enhanced reviews without recorded checks remain explainable by either a missing compliance action or a break in event capture and extraction. Those explanations predict different evidence in the source compliance records.

Stable approval and appeal rates are compatible with measurement artifacts, lawful workflow changes and real violations confined to a subgroup. Appeals capture only some consequences of missed controls, incident detection is incomplete, and pooled rates depend on case mix and follow-up. The outcome series therefore offers weak evidence about the frequency of specific breaches. Source records and targeted audits can test those mechanisms more directly.

```python
from collections import Counter
from datetime import datetime, timedelta, timezone

import pm4py


VARIANTS = {
    "Apr-May": {
        "Receive,Classify,Standard Review,Decision,Notify": 380,
        "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,

    },
}

normative_tree = pm4py.parse_process_tree(
    "->('Receive','Classify',"
    "X(*('Standard Review','Request Info'),"
    "->('Enhanced Review','Compliance Check')),"
    "'Decision','Notify')"
)
normative_net = pm4py.convert_to_petri_net(normative_tree)

candidate_tree = pm4py.parse_process_tree(
    "->('Receive','Classify',"
    "X(*('Standard Review','Request Info'),"
    "->('Enhanced Review','Compliance Check')),"
    "X(tau,'Supervisor Sign-off'),'Decision','Notify')"
)
candidate_net = pm4py.convert_to_petri_net(candidate_tree)


def expand_log(period, variants, *, map_screening=False, remove_gateway=False):
    """Replay the supplied within-case order under the selected projection."""
    trace_strings = []
    for variant, frequency in variants.items():
        activities = variant.split(",")
        if map_screening:
            activities = [
                "Classify" if activity == "Risk Screen" else activity
                for activity in activities
            ]
        if remove_gateway:
            activities = [activity for activity in activities if activity != "Queue Routed"]
        trace_strings.extend([",".join(activities)] * frequency)

    parsed_log = pm4py.parse_event_log_string(trace_strings, sep=",")
    log = pm4py.convert_to_event_log(parsed_log)
    epoch = datetime(2026, 1, 1, tzinfo=timezone.utc)
    for case_index, trace in enumerate(log, start=1):
        trace.attributes["concept:name"] = f"{period}-{case_index}"
        for position, event in enumerate(trace):
            # Synthetic timestamps encode the supplied order only.
            event["time:timestamp"] = epoch + timedelta(seconds=position)
    return log


def report(period, condition, log, model, *, measure_precision=False):
    net, initial_marking, final_marking = model
    dfg, starts, ends = pm4py.discover_dfg(log)
    diagnostics = pm4py.conformance_diagnostics_alignments(
        log, net, initial_marking, final_marking
    )
    fitness = pm4py.fitness_alignments(log, net, initial_marking, final_marking)

    moves_on_log = Counter()
    visible_moves_on_model = Counter()
    exactly_fitting_cases = 0
    for diagnostic in diagnostics:
        moves = diagnostic["alignment"]
        has_visible_deviation = False
        for log_label, model_label in moves:
            if model_label == ">>" and log_label != ">>":
                moves_on_log[log_label] += 1
                has_visible_deviation = True
            elif log_label == ">>" and model_label not in (">>", None):
                visible_moves_on_model[model_label] += 1
                has_visible_deviation = True
        if not has_visible_deviation:
            exactly_fitting_cases += 1

    print(f"\n{period} | {condition} | {len(log)} cases")
    print("DFG frequencies:", dict(sorted(dfg.items())))
    print("Starts:", starts, "Ends:", ends)
    print("Cases replaying without visible deviations:", exactly_fitting_cases)
    print("Alignment fitness:", fitness)
    print("Moves on log:", moves_on_log.most_common())
    print("Visible moves on model:", visible_moves_on_model.most_common())
    if measure_precision:
        precision = pm4py.precision_alignments(log, net, initial_marking, final_marking)
        print("Alignment precision:", precision)


if __name__ == "__main__":
    for period, variants in VARIANTS.items():
        raw = expand_log(period, variants)
        mapped = expand_log(period, variants, map_screening=True)
        normalized = expand_log(
            period, variants, map_screening=True, remove_gateway=True
        )
        report(period, "raw / normative", raw, normative_net)
        report(period, "label mapped / normative", mapped, normative_net)
        report(
            period,
            "label mapped and gateway removed / normative",
            normalized,
            normative_net,
            measure_precision=(period == "Aug-Sep"),
        )
        if period == "Aug-Sep":
            report(
                period,
                "same normalized log / optional sign-off",
                normalized,
                candidate_net,
                measure_precision=True,
            )

    print("\nVariant replay preserves extracted order. Source sequences, original")
    print("timestamps and case amounts are absent from the supplied variant tables.")
    print("Move counts reflect one returned optimal alignment per trace.")
    print("The optional control-flow model allows sign-off at any claim value.")
    print("It also allows claims above EUR 50,000 to omit sign-off, so it may")
    print("overgeneralize. Checking that obligation requires validated case attributes.")
```

## 7. Provisional conclusion

With high confidence, measurement changes account for most of the reported June-July conformance deterioration. The label substitution explains the new screening event paired with a missing classification. Gateway telemetry adds an extra log move, and ingestion-time ordering can put notification ahead of the effective decision. The reported repairs raise fitness from 32% to 89% and lower mean alignment cost from 0.74 to 0.12. Those figures describe the report's staged comparisons. Exact visible replay of the supplied variants gives 0/650 raw, 90/650 after mapping alone and 535/650 after also removing gateway events. These calculations retain the extracted order. The baseline variants also all fit. Reconcile case membership, preprocessing and metric definitions before assigning precise shares of the production decline to each mechanism.

For August onward, the effective sign-off policy creates a separate model-governance failure with high confidence. Both review routes contain sign-off. On the normalized variants in extracted order, the candidate raises exact fits from 300 to 510 out of 620 and alignment precision from about 0.920 to 0.936. Precision measures the behavior available at replayed prefixes. The policy test must establish whether eligible cases above EUR 50,000 received timely, authorized sign-off. A fit under the optional tree gives no assurance on that point.

A residual compliance problem remains plausible, with low confidence in employee bypass as the explanation and high confidence that the recorded omissions warrant audit. The absent checks affect 25 of 170 recorded enhanced reviews in June-July and 30 of 270 in August-September. The count rises while the fraction falls. Stable appeals, incomplete incident surveillance and the July reminder provide limited leverage for deciding between actual bypass, an authorized exception and lost evidence.

IT should preserve raw records, reconcile the production job with the variant extract, validate the screening crosswalk, separate gateway telemetry in the analysis projection and recover source precedence where supported. Process owners should version the sign-off requirement and verify override actions, authorizations and logging across the August patch. Compliance should audit the 55 flagged reviews and matched controls, then check eligible high-value cases for missing, late or unauthorized sign-offs. Claims of employee misconduct, universal reversal repair, unchanged business semantics in every channel or full compliance under the optional model should await case-level evidence.

## 8. Model-governance recommendation

1. Version normative models with the approved policy text, effective dates, applicability rules for in-flight cases and replay configurations. Record the model and log snapshot used for every published metric.
2. Maintain a versioned event contract with stable activity IDs, display labels, source producers, lifecycle definitions and case correlation keys. Verify semantic equivalence before registering a label alias.
3. Classify technical telemetry by producer and purpose. Preserve it in the raw event record and apply documented, versioned exclusions in the conformance projection.
4. Store business event time, ingestion time and source sequence separately, with scope and timezone metadata. Validate ordering across sources and report cases with unresolved precedence.
5. Encode conditional obligations with effective-dated case attributes and explicit timing and authorization checks. Test both review branches and the EUR 50,000 boundary before approval.
6. After each release, validate event counts, variant and DFG shifts, paired alignment moves, fitness and precision on matched cohorts. Reconcile unexpected changes against source samples and record the disposition before publishing trend comparisons.
