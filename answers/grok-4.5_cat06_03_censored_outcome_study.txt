## 1. Target definition

**Primary target.**  
- **Unit of analysis:** one credit application (`case:concept:name`).  
- **Population:** applications that reach `Account Activated` and whose 90-day outcome feed has matured by a chosen as-of cutoff.  
- **Prediction time:** end of an early prefix—either the first \(k\) events (e.g., \(k \in \{2,3,4\}\)) or a fixed elapsed-time window from `Application Started` (e.g., 24h / 72h), always strictly before Accept / Contract Signed / Account Activated.  
- **Horizon:** calendar 90 days after the `Account Activated` timestamp.  
- **Label:** \(Y = \ co{default\_90d} \in \{0,1\}\), observed only when the external outcome feed has arrived.  
- **Estimand:**  
  \[
  \theta(x_{\le t}) = P(Y=1 \mid X_{\le t}=x_{\le t},\ \text{activated},\ \text{label matured}).
  \]
  This is an **associational, selection-conditional** risk: early-warning rank-ordering among applications that historically entered the book, not the probability that “any application will default.”

**Why this is defensible.** Default under the lender’s legal and operational definition is exposure after activation. Rejected, withdrawn, and never-activated cases have **no defined 90-day post-activation default** under the observed policy. Conditioning on activation and label maturity matches how loss is actually realized and audited, keeps the target semantically honest, and supports early triage of applications that are on a path toward booking—without fabricating non-default labels for never-exposed cases.

**Credible alternative.**  
A **competing-outcome / multi-state target** on all started applications, with absorbing (or censored) states such as:  
`{Rejected, Withdrawn, Transferred, Activated–NoDefault90, Activated–Default90, Open/Immature}`.  
Prediction is multinomial (or cause-specific / subdistribution hazards). This answers a different question: “What will happen next to this application?” and is closer to portfolio intake steering. It does **not** identify counterfactual default had a rejected case been activated; that would require a policy-specific causal estimand and stronger assumptions (overlap, no unmeasured confounding of underwriting) and is out of scope as a primary claim.

**Not used as primary:** labeling rejects/withdrawals/open cases as \(Y=0\) “for convenience.” That conflates selection with credit performance and biases default rates downward.

---

## 2. Cohort construction

**Inclusion (universe):** all applications with `Application Started` in the event observation window 2024-01-01 through 2025-12-31 (\(N=48{,}000\)).

**As-of / cutoff rules (configurable, example operational cutoff \(T_{\text{asof}} =\) data extract 2026-02-15):**  
1. Case start time \(t_0 =\) timestamp of first `Application Started`.  
2. Activation time \(t_{\text{act}} =\) first `Account Activated` if any.  
3. Label maturity time \(t_{\text{mat}} = t_{\text{act}} + 90\text{d} + \text{feed delay}\) (use `label_available_at` when present; otherwise a conservative upper bound, e.g., +35d).  
4. A case is **label-eligible** only if \(t_{\text{act}}\) exists and \(t_{\text{mat}} \le T_{\text{asof}}\).  
5. Prefixes for modeling use only events with `time:timestamp` \(\le t_{\text{pred}}\) and \(\le T_{\text{asof}}\).  
6. Policy regime flag: \(t_0 <\) 2025-07-01 vs \(\ge\) 2025-07-01. Migration flag: events around 2025-10-15 normalized (see §4).

**Exclusion from the primary labeled training set:**  
- Never activated (rejected / withdrawn / transferred without activation / still open).  
- Activated but \(t_{\text{mat}} > T_{\text{asof}}\) (immature).  
- Activated with evidence of **permanently missing** partner outcome feed (sensitivity: exclude or IPW; see §3).  
- Cases whose only identity after transfer cannot be linked when linkage is required for outcome (treat as competing exit / missing follow-up).

**Cohort-flow table (accounts for all 48,000)**

| Stage | n | Role in primary analysis |
|------:|--:|--|
| Applications started (2024-01-01 .. 2025-12-31) | 48,000 | Universe |
|  Rejected (terminal, never activated) | 9,100 | Competing outcome; **not** \(Y=0\) |
|  Withdrawn | 5,700 | Competing outcome; **not** \(Y=0\) |
|  Transferred (no activation on this ID) | 2,900 | Competing exit / partial linkage (~60%); not primary \(Y\) |
|  Still open at extract (no activation) | 5,100 | Right-censored pathway; unlabeled for default |
| = Reached Account Activated | 25,200 | Activation-selected subpopulation |
|  Activated, label/feed not mature at \(T_{\text{asof}}\) | 3,600 | Delayed/immature labels; censored for classification; usable in survival sensitivity |
| = Activated + matured label (export) | 21,600 | **Primary labeled cohort** |
|    of which non-default | 18,900 | \(Y=0\) |
|    of which default | 2,700 | \(Y=1\) |
| Partner-originated with elevated permanent feed loss | (subset of above) | Flag for sensitivity / missing-not-at-random risk |

Primary model training and calibration use the 21,600 with explicit reporting that they are **activation- and maturity-selected**. The 26,400 never-activated or immature cases are retained for process mining, competing-risk models, and selection diagnostics—not dumped into \(Y=0\).

## 3. Censoring and missing-label strategy

**Mechanisms (kept distinct):**

| Mechanism | Description | Primary handling |
|--|--|--|
| Ordinary right censoring | Open applications or activated accounts with \(t_{\text{act}}+90\text{d}\) not reached by \(T_{\text{asof}}\) | Not in primary binary cohort; eligible for survival analysis |
| Delayed labels | Feed arrives 7–35d after horizon (`label_available_at`) | Maturity rule: include only if `label_available_at` \(\le T_{\text{asof}}\); as-of joins only |
| Selection through activation | Default defined only post-activation; underwriting selects on risk | Primary estimand **conditional on activation**; report selection rates by score/prefix |
| Transfer | Exit to partner; 60% linkage; possible re-ID | Competing event in multi-state view; linked subset for outcome sensitivity; unlinked  non-default |
| Permanently missing feeds | Partner-originated activations often never receive `default_90d` | Separate missingness indicator; do not impute 0; sensitivity analyses |

**Primary analysis strategy.**  
Binary supervised model for \(\theta(x_{\le t})\) on matured activated cases only, with:  
- temporal train/val/test by \(t_0\);  
- sample weights or stratified reporting by channel/partner to reduce dominance of complete-feed segments;  
- explicit **selection model** side analysis: \(P(\text{activate} \mid x_{\le t})\) estimated on all applications (competing terminals as non-activate), used for diagnostics and optional **inverse-probability-of-activation weighting (IPAW)** as a robustness check—not as proof of counterfactual default.

**Sensitivity analyses.**  
1. **Competing-risk / multi-state** model on all 48k pathways (Fine–Gray or cause-specific hazards / multinomial PPM).  
2. **Time-to-default after activation** with right censoring at \(\min(T_{\text{asof}}-t_{\text{act}}, 90\text{d})\) for the 25,200 activated (includes 3,600 immature).  
3. Exclude vs. doubly-weight partner channels with high permanent feed loss.  
4. Split pre/post 2025-07-01 policy; refit and transport checks.  
5. Linked-transfer-only vs. treat all transfers as censored competing exits.

**Assumption testability.**  
- Label delay distribution: **testable** from `label_available_at`.  
- Activity rename/duplicate rates post-migration: **testable**.  
- Differential activation by prefix/risk_score: **testable**.  
- MAR missingness of partner feeds given observables: **partially testable** (observed predictors of missingness; not the outcome among missing).  
- “Rejects would not have defaulted” or counterfactual default under forced activation: **fundamentally untestable** without randomized underwriting or credible instruments.  
- MNAR permanent feed loss tied to default itself: **fundamentally untestable**; bound it.

## 4. Prefix extraction

**No future leakage rule:** for prediction time \(t_{\text{pred}}\), retain only events with `time:timestamp` \(\le t_{\text{pred}}\). Drop or mask any attribute not knowable at \(t_{\text{pred}}\) (see §6).

**Fixed event-count prefixes.**  
- Use `pm4py.get_prefixes_from_log` (or equivalent groupby-head) for \(k=2,3,4\) after normalizing activity names.  
- Require that the \(k\)-th event occurs **before** any of `{Accepted, Rejected, Withdrawn, Transferred, Contract Signed, Account Activated}` when the business asks for “pre-decision” warning; if a short case terminates earlier, emit a **terminal-short** prefix and either (a) exclude from pre-decision models or (b) model separately as early-exit prediction.  
- Document-request loops: repeated `Document Requested` / return to `Credit Review` count as distinct events; optional **loop-collapsed** variant (max 1 consecutive duplicate activity) as sensitivity, not as silent default.

**Elapsed-time prefixes.**  
- \(t_{\text{pred}} = t_0 + \Delta\), \(\Delta \in \{24\text{h}, 72\text{h}, 7\text{d}\}\).  
- Include all events \(\le t_{\text{pred}}\); if the case already terminal before \(\Delta\), mark `early_terminal=1` and do not pretend a full open prefix exists.  
- Same-calendar-day snapshot features (e.g., `documents_total`) must use a snapshot **as-of \(t_{\text{pred}}\)**, not the nightly end-of-day total (see leakage table).

**Short cases.** Keep with feature `prefix_len`, `duration_to_pred`, `early_terminal_type`; do not pad with future activities.

**Activity renaming (2025-10-15 migration).**  
- Maintain a versioned **activity synonym map** (oldcanonical).  
- Deduplicate exact duplicate events (same case, canonical activity, timestamp, resource) created by migration.  
- Flag `post_migration=1` on cases with \(t_0\) near the cut; never mix raw unmapped names in DFG features.

**Risk_score updates:** only the last `risk_score` value with event timestamp \(\le t_{\text{pred}}\).

## 5. Process-aware features

**Static case attributes (at start / known pre-prefix):** `case:channel`, `case:region`, `case:requested_amount`, start calendar (month, dow, business-day), policy_regime (`t_0` pre/post 2025-07-01).

**Prefix-derived control-flow:** activity counts; presence of KYC, Credit Review, Document Request; number of Credit Review visits; rework count (re-entry to Credit Review); unique activity set size; canonical variant hash (from historical train log only); distance-in-DFG sense only if DFG built on **train** periods.

**Timing:** time from start to \(t_{\text{pred}}\); inter-event mean/std; time since last event; service vs waiting times **if** computed only from events \(\le t_{\text{pred}}\) (e.g., careful use of `insert_case_service_waiting_time` on prefix logs, not full logs).

**Resource/queue:** number of distinct resources so far; whether resource changed; queue proxy = concurrent open cases at same resource/region at \(t_{\text{pred}}\) from **historical reference**, not future; **do not** use employee experience-at-extract.

**Rework / documents:** document request count; time in document loop; **as-of** document count at \(t_{\text{pred}}\) (repaired snapshot), not `documents_total` end-of-day.

**Cohort/calendar / reference:** application volume in prior 7d in same channel (train-history lookup); pre vs post policy and migration flags; empirical activation rate in same score bucket from **prior** period only.

**Explicitly excluded from features at \(t_{\text{pred}}\):** `final_limit`, `decision_reason`, post-decision events, `collection_status`, `default_90d`, `label_available_at`, any Collections/Default activities, experience-at-extract, future risk_score.

## 6. Leakage audit

| Feature or data element | Leakage or bias risk | Valid availability rule | Keep/repair/drop | Rationale |
|--|--|--|--|--|
| `final_limit` | Post-decision; encodes accept/amount policy | Only after final credit decision | **Drop** at early prefix | Not known at pre-decision \(t_{\text{pred}}\) |
| `decision_reason` | Reveals Accept/Reject and underwriting outcome | At/after decision event | **Drop** | Direct label/selection leak |
| `collection_status` | Updated after activation; can reveal default | Post-activation collections only | **Drop** | Near-direct target leak |
| Future events (Contract Signed, Activated, Collections, Default Recorded) | Path and outcome leakage | Event time \(\le t_{\text{pred}}\) | **Drop** from prefix log | Standard temporal leakage |
| `documents_total` (nightly snapshot) | Can include uploads later same day than \(t_{\text{pred}}\) | Recompute as-of \(t_{\text{pred}}\) from events | **Repair** | Nightly batch violates as-of |
| `risk_score` (updates) | Future scores after \(t_{\text{pred}}\) | Last value with timestamp \(\le t_{\text{pred}}\) | **Repair** | Keep causal score path only |
| Resource experience at extract | Uses future career progress | Experience as-of event time (if historized); else omit | **Drop** if only extract-time | Look-ahead bias |
| `default_90d` on event rows | Target repeated on events | Label join only at training outcome stage | **Drop** from features | Direct target leak |
| `label_available_at` | Maturity proxy; correlated with delay process | Cohort filter only, not a feature | **Drop** from features | Outcome-observability leak |
| `data_extract_time` / `source_system` | Extract artifacts; partner feed patterns | System OK as static if set at start; extract time not a feature | **Repair** | Avoid extract-date shortcuts |
| Partner / transfer linkage | Differential missing outcomes | Missingness flag + sensitivity | **Keep flag**, not imputed \(Y\) | Selection / MNAR risk |
| Pre-migration activity names | Inconsistent control-flow features | Canonical name map + dedupe | **Repair** | Otherwise spurious shift |
| Policy thresholds from 2025-07-01 | Same prefix, different P(activate) and P(Y\|activate) | Regime feature + temporal split | **Keep** regime flag | Concept/selection shift |
| Treating reject as non-default | Semantic false negative bias | Never auto-label | **Drop** practice | Undefined outcome under policy |

## 7. Validation design

**Why random case splits mislead.**  
They mix pre/post policy (2025-07-01) and pre/post migration (2025-10-15), allow near-duplicate process variants across folds, and ignore label maturity (future feed status leaking via who appears in the 21.6k). They also break the activation selection distribution over time.

**Primary scheme: temporal, maturity-aware backtesting.**  
1. Define case start folds, example:  
   - **Train:** \(t_0\) in 2024-01-01 .. 2025-03-31, labels matured under a train-as-of (e.g., 2025-08-15).  
   - **Validation:** \(t_0\) in 2025-04-01 .. 2025-06-30 (pre-policy) with val-as-of ensuring maturity.  
   - **Test A (policy shift):** \(t_0\) in 2025-07-01 .. 2025-09-30.  
   - **Test B (migration + policy):** \(t_0\) in 2025-10-15 .. 2025-12-31, evaluation only when \(t_{\text{mat}} \le\) 2026-02-15.  
2. For each fold, rebuild prefixes and features using **only information available inside that fold’s as-of**.  
3. DFG/variant reference statistics computed on train only.  
4. Optional rolling origin monthly backtests on activated-matured cohorts.

**Metrics (primary binary target on activated-matured).**  
- Discrimination: ROC-AUC, PR-AUC (default ~12.5% prevalence in export—PR-AUC mandatory).  
- Calibration: reliability diagrams, ECE, stratified by channel/partner/regime.  
- Decision-centric: recall@top-q% of score, expected precision at capacity constraints.  
- Stability: PSI/JS on score and key features traintest; subgroup AUC (region, channel, requested_amount bins, policy regime).  
- Selection diagnostics: AUC for \(P(\text{activate}\mid x)\); default rate among activated vs model score; report coverage (% apps with score usable pre-decision).

**If competing-risk sensitivity:** cause-specific hazards / CIF at horizon; time-dependent AUC; calibration of CIF; never collapse competing exits to non-default.

**Label maturity gate:** a case enters a fold’s evaluation set only if `label_available_at` \(\le\) fold_asof. No “partial default” from incomplete horizon.

## 8. Limitations and decision-use boundary

**Can claim.**  
- Among applications that historically activated and received matured feeds, early prefixes contain predictive signal for 90-day default association.  
- Relative ranking and calibration **within** the activated-matured population under similar policy/feed regimes.  
- Process bottlenecks and rework patterns associated with later default **conditional on booking**.

**Cannot claim.**  
- Unconditional “P(default) for every application” including rejects/withdrawals.  
- Counterfactual default had underwriting accepted a rejected case.  
- Causal effect of interventions (requesting documents, changing resources) without a causal design.  
- Stable performance across unmodeled partner feed loss or further policy shifts.

**Selection vs prediction vs counterfactual.**  
Activation is a collider/selection path: models fit on booked accounts estimate \(\theta\) above, not population default risk. IPAW/multi-state analyses probe sensitivity; they do not create ground-truth defaults for never-activated cases.

**Deployment can change the DGP (at least three ways).**  
1. **Underwriting feedback:** using scores to accept/reject shifts the activation population  label distribution drifts (performativity).  
2. **Operational reaction:** early intervention (extra KYC, manual review) alters prefix distributions and time-to-activate, breaking stationary prefixY maps.  
3. **Collections / reporting changes:** faster default recording or partner feed SLAs change apparent `default_90d` and maturity delay.  
4. *(Bonus)* Policy threshold updates like July 2025 again decouple historical \(\theta\) from future booked risk.

**Decision-use boundary.** Use as an **early risk signal on the path to booking** and for capacity prioritization—not as an automated reject reason that treats the score as causal default probability for never-activated applicants, and not without regime monitoring and recalibration after policy/system changes.

## 9. PM4Py-oriented Python implementation skeleton

```python
"""
Uncertainty-aware PPM skeleton: cohort, as-of labels, prefixes, leakage guards.
Assumptions are marked ASSUMPTION; survival/competing-risk hooks marked LATER.
"""
from __future__ import annotations
import pandas as pd
import numpy as np
import pm4py
from pm4py.objects.log.util import dataframe_utils

EVENTS_PATH = "applications_events.csv"
ASOF = pd.Timestamp("2026-02-15")
PRED_K = 3  # fixed-count prefix length
POLICY_CHANGE = pd.Timestamp("2025-07-01")
MIGRATION = pd.Timestamp("2025-10-15")
MAX_FEED_DELAY = pd.Timedelta(days=35)  # ASSUMPTION if label_available_at missing

ACTIVITY_MAP = {  # post-migration synonyms -> canonical
    "KYC_Check": "Identity/KYC Check",
    "CreditReview": "Credit Review",
    # ... extend from data profiling
}
TERMINAL = {"Rejected", "Withdrawn", "Transferred"}
POST_DECISION = {
    "Accepted", "Contract Signed", "Account Activated",
    "Collections Contact", "Default Recorded",
}
LEAKY_COLS = {
    "final_limit", "decision_reason", "collection_status",
    "default_90d", "label_available_at", "data_extract_time",
}

def read_events(path: str) -> pd.DataFrame:
    df = pd.read_csv(path)
    df = pm4py.format_dataframe(
        df,
        case_id="case:concept:name",
        activity_key="concept:name",
        timestamp_key="time:timestamp",
    )
    df = dataframe_utils.convert_timestamp_columns_in_df(df)
    df["concept:name"] = df["concept:name"].replace(ACTIVITY_MAP)
    # migration duplicate collapse
    df = (
        df.sort_values(["case:concept:name", "time:timestamp"])
        .drop_duplicates(
            subset=["case:concept:name", "concept:name", "time:timestamp", "org:resource"],
            keep="first",
        )
    )
    return df

def case_timeline(df: pd.DataFrame, asof: pd.Timestamp) -> pd.DataFrame:
    """Case-level start, activation, terminals, maturity — all as-of `asof`."""
    e = df[df["time:timestamp"] <= asof].copy()
    g = e.groupby("case:concept:name", sort=False)
    t0 = g["time:timestamp"].min().rename("t0")
    def first_ts(act):
        m = e["concept:name"] == act
        return e.loc[m].groupby("case:concept:name")["time:timestamp"].min()
    t_act = first_ts("Account Activated").rename("t_act")
    # competing terminals (first among reject/withdraw/transfer)
    term = e[e["concept:name"].isin(TERMINAL)]
    t_term = term.groupby("case:concept:name")["time:timestamp"].min().rename("t_term")
    term_name = (
        term.sort_values("time:timestamp")
        .groupby("case:concept:name")["concept:name"].first()
        .rename("terminal_type")
    )
    # label from case-level known rows (not as a feature later)
    lab = (
        e.dropna(subset=["default_90d"])
        .groupby("case:concept:name")["default_90d"].max()
        .rename("default_90d")
    )
    lab_at = (
        e.dropna(subset=["label_available_at"])
        .assign(label_available_at=lambda x: pd.to_datetime(x["label_available_at"]))
        .groupby("case:concept:name")["label_available_at"].min()
        .rename("label_available_at")
    )
    cases = pd.concat([t0, t_act, t_term, term_name, lab, lab_at], axis=1)
    cases["policy_regime"] = np.where(cases["t0"] >= POLICY_CHANGE, "post_2025_07", "pre_2025_07")
    # maturity: ASSUMPTION — prefer label_available_at else t_act+90d+max delay
    horizon_end = cases["t_act"] + pd.Timedelta(days=90)
    est_ready = horizon_end + MAX_FEED_DELAY
    cases["t_mat"] = cases["label_available_at"].fillna(est_ready)
    cases["activated"] = cases["t_act"].notna()
    cases["label_mature"] = cases["activated"] & cases["t_mat"].notna() & (cases["t_mat"] <= asof)
    cases["primary_labeled"] = cases["label_mature"] & cases["default_90d"].isin([0, 1])
    # still open: no activation, no terminal as-of
    cases["still_open"] = (~cases["activated"]) & cases["t_term"].isna()
    cases["competing_exit"] = (~cases["activated"]) & cases["t_term"].notna()
    return cases.reset_index()

def cohort_flow_report(cases: pd.DataFrame) -> pd.DataFrame:
    n = len(cases)
    rows = [
        ("universe_started", n),
        ("competing_exit_not_activated", int(cases["competing_exit"].sum())),
        ("still_open", int(cases["still_open"].sum())),
        ("activated", int(cases["activated"].sum())),
        ("activated_immature_or_missing_label",
         int((cases["activated"] & ~cases["primary_labeled"]).sum())),
        ("primary_labeled", int(cases["primary_labeled"].sum())),
        ("primary_default", int(((cases["primary_labeled"]) & (cases["default_90d"] == 1)).sum())),
        ("primary_non_default", int(((cases["primary_labeled"]) & (cases["default_90d"] == 0)).sum())),
    ]
    out = pd.DataFrame(rows, columns=["stage", "n"])
    print(out.to_string(index=False))
    return out

def temporal_case_split(cases: pd.DataFrame):
    """Primary validation: by case start time — not random split."""
    # ASSUMPTION: illustrative dates; align to maturity in real runs
    train = cases[(cases["t0"] >= "2024-01-01") & (cases["t0"] <= "2025-03-31")]
    val = cases[(cases["t0"] >= "2025-04-01") & (cases["t0"] <= "2025-06-30")]
    test_policy = cases[(cases["t0"] >= "2025-07-01") & (cases["t0"] <= "2025-09-30")]
    test_migr = cases[(cases["t0"] >= "2025-10-15") & (cases["t0"] <= "2025-12-31")]
    return {"train": train, "val": val, "test_policy": test_policy, "test_migr": test_migr}

def prefix_log_fixed_k(df: pd.DataFrame, k: int):
    """Fixed-count prefixes without post-prefix events."""
    log = pm4py.convert_to_event_log(df)
    # pm4py helper for prefixes; each trace truncated to first k events
    prefixes = pm4py.get_prefixes_from_log(log, k)
    return prefixes

def prefixes_as_dataframe(df: pd.DataFrame, k: int, case_ids: set) -> pd.DataFrame:
    d = df[df["case:concept:name"].isin(case_ids)].sort_values(
        ["case:concept:name", "time:timestamp"]
    )
    d["ev_idx"] = d.groupby("case:concept:name").cumcount() + 1
    pref = d[d["ev_idx"] <= k].copy()
    # hard drop leaky columns before any feature build
    pref = pref.drop(columns=[c for c in LEAKY_COLS if c in pref.columns], errors="ignore")
    # last risk_score within prefix only (already true by event filter)
    return pref

def leakage_audit_check(pref_df: pd.DataFrame) -> pd.DataFrame:
    rows = []
    for col in sorted(set(LEAKY_COLS) | {"final_limit", "collection_status"}):
        present = col in pref_df.columns
        rows.append({
            "feature": col,
            "present_in_prefix_table": present,
            "action": "FAIL_DROP" if present else "OK_ABSENT",
        })
    # future activity names should not appear if k is pre-decision — diagnostic
    bad_acts = set(pref_df["concept:name"].unique()) & POST_DECISION
    rows.append({
        "feature": "post_decision_activities_in_prefix",
        "present_in_prefix_table": bool(bad_acts),
        "action": f"REVIEW:{bad_acts}" if bad_acts else "OK",
    })
    audit = pd.DataFrame(rows)
    print(audit.to_string(index=False))
    return audit

def process_diagnostics_train_only(train_pref_df: pd.DataFrame):
    """DFG/variants on train prefixes only — reference distribution, not labels."""
    log = pm4py.convert_to_event_log(train_pref_df)
    dfg, sa, ea = pm4py.discover_dfg(log)
    variants = pm4py.get_variants(log)
    # Temporal features on prefix df only (justified: times <= t_pred)
    # tf = pm4py.extract_temporal_features_dataframe(train_pref_df)
    return {"dfg_edges": len(dfg), "n_variants": len(variants)}

def build_prefix_features(pref_df: pd.DataFrame) -> pd.DataFrame:
    """Minimal process-aware features; all from prefix rows only."""
    g = pref_df.groupby("case:concept:name")
    feats = pd.DataFrame({
        "prefix_len": g.size(),
        "n_unique_acts": g["concept:name"].nunique(),
        "n_credit_review": g["concept:name"].apply(lambda s: (s == "Credit Review").sum()),
        "n_doc_loops": g["concept:name"].apply(lambda s: s.astype(str).str.contains("Document").sum()),
        "duration_sec": (g["time:timestamp"].max() - g["time:timestamp"].min()).dt.total_seconds(),
        "n_resources": g["org:resource"].nunique(),
        "risk_score_last": g["risk_score"].last(),
        "channel": g["case:channel"].first(),
        "region": g["case:region"].first(),
        "requested_amount": g["case:requested_amount"].first(),
    })
    # ASSUMPTION: resource experience-at-extract intentionally omitted
    return feats.reset_index()

def main():
    df = read_events(EVENTS_PATH)
    cases = case_timeline(df, ASOF)
    cohort_flow_report(cases)

    splits = temporal_case_split(cases)
    # Primary labeled subpopulation only for supervised default model
    train_cases = splits["train"][splits["train"]["primary_labeled"]]
    val_cases = splits["val"][splits["val"]["primary_labeled"]]

    train_pref = prefixes_as_dataframe(df, PRED_K, set(train_cases["case:concept:name"]))
    val_pref = prefixes_as_dataframe(df, PRED_K, set(val_cases["case:concept:name"]))

    leakage_audit_check(train_pref)
```
