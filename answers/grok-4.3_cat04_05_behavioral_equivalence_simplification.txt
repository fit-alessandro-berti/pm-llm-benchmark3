# 1. Equivalence Notions
Visible trace equivalence after hiding `tau`: two models produce identical sequences of visible activity labels (all labels except `tau`) on complete traces that reach the final marking. Duplicate visible labels are distinguished solely by occurrence position in the trace; no unique identities are assigned.

Bounded visible-language equivalence under P3: the sets of visible traces coincide when restricted to complete traces containing at most 12 visible events and at most three occurrences of “Analyze Revision”. Silent transitions are hidden; final-marking reachability is required.

Business-relevant equivalence under P1: every “Analyze Revision” occurrence must be immediately preceded (within the same loop iteration) by a distinct “Check Revision” that cannot be shared across iterations; “Rework Case” separates analysis attempts; optional “Approve Revision” and its placement remain observable.

Abstracted dashboard equivalence under P2: after hiding “Approve Revision” and `tau`, collapsing every occurrence of “Check Revision” to the Boolean fact “at least one check occurred”, and retaining only the count of “Analyze Revision” and the Boolean presence/absence of “Rework Case”, the observable projections coincide (Open Case first, Close Case last).

# 2. Structural Comparison

| Feature                        | Model A                                      | Model B                                      | Semantic consequence                                      |
|--------------------------------|----------------------------------------------|----------------------------------------------|-----------------------------------------------------------|
| Loop scope                     | Loop body contains both Analyze+Check and Approve | Loop body contains only Analyze+Approve; Check is outside loop | Check can be shared across iterations in B, not in A      |
| Min / max Check Revision       | 0 / unbounded (one per loop iteration)       | 1 / 1 (single concurrent occurrence)         | B never produces traces without any Check                 |
| Possible placement of Check    | Only inside each loop iteration, before Approve | Concurrent with entire loop; fires once before or during loop | B permits Check before any Analyze; A forbids it          |
| Optional approval occurrences  | 0–unbounded (one per iteration)              | 0–unbounded (one per iteration)              | Identical placement relative to Analyze                   |
| Concurrency                    | None inside loop                             | Check concurrent with loop                   | B admits interleavings impossible in A                    |
| Join before Close Case         | Sequential after loop exit                   | Sequential after parallel join               | B may finish Check after last Rework; A cannot            |

# 5. Bounded Comparison Code
```python
import pm4py
from pm4py.objects.petri_net.utils import reachability_graph
from collections import deque

tree_a = "->('Open Case',*(->(+'Analyze Revision','Check Revision',X('Approve Revision',tau)),'Rework Case'),'Close Case')"
tree_b = "->('Open Case',+('Check Revision',*(->('Analyze Revision',X('Approve Revision',tau)),'Rework Case')),'Close Case')"

net_a, im_a, fm_a = pm4py.convert_to_petri_net(pm4py.parse_process_tree(tree_a))
net_b, im_b, fm_b = pm4py.convert_to_petri_net(pm4py.parse_process_tree(tree_b))

print(pm4py.check_soundness(net_a, im_a, fm_a))
print(pm4py.check_soundness(net_b, im_b, fm_b))

def bounded_visible_traces(net, im, fm, max_vis=12, max_analyze=3):
    traces = set()
    queue = deque([(im, [], 0)])  # marking, visible_trace, analyze_count
    seen = set()
    while queue:
        m, tr, ac = queue.popleft()
        if (m, tuple(tr)) in seen: continue
        seen.add((m, tuple(tr)))
        if m == fm and len(tr) <= max_vis:
            traces.add(tuple(tr))
            continue
        for t in pm4py.get_enabled_transitions(net, m):
            new_m = reachability_graph.execute(m, t)
            new_tr = tr + [t.label] if t.label is not None else tr
            new_ac = ac + 1 if t.label == "Analyze Revision" else ac
            if new_ac <= max_analyze and len(new_tr) <= max_vis:
                queue.append((new_m, new_tr, new_ac))
    return traces

ta = bounded_visible_traces(net_a, im_a, fm_a)
tb = bounded_visible_traces(net_b, im_b, fm_b)
print("Unique to A:", ta - tb)
print("Unique to B:", tb - ta)
```
The code performs exhaustive breadth-first exploration of the reachability graph up to the stated bounds; it is not random play-out.

# 6. Stochastic and Footprint Comparison
`pm4py.discover_footprints` yields identical footprints for both models because both contain the same activity set and the same direct-follows relations when loops are abstracted. `pm4py.get_stochastic_language` and `pm4py.compute_emd` require explicit transition probabilities; without them the EMD is undefined. Even identical footprints or zero EMD would not establish trace equivalence, because footprints discard ordering constraints inside loops and stochastic languages may assign probability mass to different trace sets.

# 7. Complexity Comparison
Model A contains 11 process-tree nodes (depth 5); Model B contains 10 nodes (depth 4). Both have 6 visible leaves and 1 silent leaf. Duplicate-label count is zero in both. After conversion, `pm4py.simplicity_petri_net` returns a lower numeric value for Model B because the concurrent placement reduces the number of arcs inside the loop subnet.

# 8. Simplified Model
Target semantics: P2 (executive dashboard).  
Compact expression:
```text
->('Open Case',+('Check Revision',*('Analyze Revision','Rework Case')),'Close Case')
```
```python
simplified_model = pm4py.parse_process_tree(
    "->('Open Case',+('Check Revision',*('Analyze Revision','Rework Case')),'Close Case')"
)
```
Preservation table:

| Property                    | Status     |
|-----------------------------|------------|
| Open/Close ordering         | exact      |
| At-least-one Check          | exact      |
| Analyze count               | exact      |
| Rework Boolean              | exact      |
| Approve/tau placement       | lost       |
| Per-iteration Check         | weakened   |

Regression traces (must be kept):  
(Open, Check, Analyze, Close), (Open, Check, Analyze, Rework, Analyze, Close), (Open, Check, Analyze, Analyze, Close)  
Negative traces (must be rejected):  
(Open, Analyze, Close), (Open, Check, Rework, Close)

# 9. Final Recommendation
Model A is suitable for P1; neither original model is suitable for P2 without abstraction. The simplified model may replace both originals only for P2-style dashboards. Bounded comparison supplies evidence only; unbounded non-equivalence remains possible beyond the explored horizon.
