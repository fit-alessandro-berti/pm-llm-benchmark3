## 6. Intervention and learning plan

| phase | intervention | target mechanism | assignment unit | safeguards | process-mining measurements | causal learning value | stop or rollback rule |
|---|---|---|---|---|---|---|---|
| 1. Instrumentation and retrospective diagnostics | Add event-level timestamps, queue length, reviewer IDs, compliance start/end, request-info loops, and case status including open/abandoned; do not change routing. | Measurement, selection, queueing vs service | Case and time-slot | No operational change; data governance and privacy review | Activity timestamps, DFG variants, directly-follows counts, rework loops, queue_wait decomposition, open/abandoned survival curves | Establishes overlap, positivity, and whether wait/service/rework can be separated; reduces collider/selection ambiguity. | Pause if event logging is incomplete or trace conformance falls below an agreed threshold. |
| 2. Queue/compliance capacity pilot | Increase night compliance capacity or create a triage queue during high-load periods while keeping routing rules unchanged. | queue_wait and compliance_performed, not resource_group label | Time-slot or shift with staggered rollout | Maintain compliance policy; monitor SLA, appeals, rework, and reviewer overload | Compliance duration, queue depth, wait_before_review, cycle_time, DFG conformance, rework loop frequency | Tests whether the mechanism is queue/compliance waiting rather than Orion itself; supports front-door/mediation analysis. | Roll back if cycle_time worsens, appeals increase, or compliance SLA breaches exceed predefined limits. |
| 3. Small randomized routing pilot | Randomize 10–20% of overlapping cases—low/medium, non-compliance, similar shift and load—to Orion vs Nova; do not move 50% of all Orion cases. | Total causal effect of routing policy under overlap | Case | Exclude high-risk or no-overlap cases; verify Nova certification; cap Nova volume; Orion fallback for escalation | Cycle_time, wait_before_review, review_service, rework, appeals, trace variants, DFG, within-reviewer performance | Produces a causal estimate where positivity exists; distinguishes harmful, beneficial, or null group effects. | Stop if Nova mean cycle_time exceeds Orion by >10% on matched cases, appeals increase, or SLA breaches rise. |

Do not implement the 50% reassignment as a blanket action. The crude Orion delay is mainly a routing-mix signal, not proof of inefficiency. First instrument event timestamps, queue state, compliance duration, reviewer IDs, and open/abandoned status. Then run a staggered night/compliance capacity pilot to test whether queue_wait drives the gap. Only after that, randomize a small, overlapping subset—low/medium, non-compliance, similar shift and load—to Nova or Orion, with Nova certification and capacity safeguards. Monitor cycle, wait, service, rework, appeals, and conformance, stopping if Nova worsens comparable cases or quality declines. The current evidence favors a diagnostic, mechanism-targeted approach over a label-based reassignment. If the pilot shows Nova is slower on matched cases, keep Orion and address queues; if Orion is genuinely slower under overlap, move capacity gradually.

def warn_small(n, context):
    try:
        n_int = int(n)
    except Exception:
        n_int = n
    if n_int < 3:
        print(f"WARNING: {context}: n={n_int} (<3); comparison has poor support.")

def manual_dfg(events):
    edges = {}
    for _, g in events.groupby("case_id", sort=False):
        acts = g["activity"].tolist()
        for a, b in zip(acts, acts[1:]):
            edges[(a, b)] = edges.get((a, b), 0) + 1
    return edges

def get_dfg(events):
    try:
        import pm4py
    except ImportError:
        print("WARNING: PM4Py not installed; using manual directly-follows counts.")
        return manual_dfg(events)

    events = events[["case_id", "activity"]].copy()
    event_csv = events.to_csv(index=False)
    log = None

    try:
        log = pm4py.parse_event_log_string(
            event_csv,
            case_id_attr="case_id",
            activity_attr="activity",
            timestamp_attr=None
        )
    except TypeError:
        try:
            log = pm4py.parse_event_log_string(
                event_csv,
                case_id_attr="case_id",
                activity_attr="activity"
            )
        except Exception as e:
            print(f"WARNING: PM4Py parse failed ({e}); using manual DFG.")
            return manual_dfg(events)
    except Exception as e:
        print(f"WARNING: PM4Py parse failed ({e}); using manual DFG.")
        return manual_dfg(events)

    try:
        result = pm4py.discover_dfg(
            log,
            case_id_attr="case_id",
            activity_attr="activity"
        )
        edges = result[0] if isinstance(result, tuple) else result
        return edges
    except Exception as e:
        print(f"WARNING: PM4Py discover_dfg failed ({e}); using manual DFG.")
        return manual_dfg(events)

print("\n=== Group-specific directly-follows relations ===")

    warn_small(n_cases, f"process-mining {group}")

    print(f"\n{group} DFG edges:")

for edge in all_edges:
    print(f"{edge}: Orion={dfgs['Orion'].get(edge, 0)}, Nova={dfgs['Nova'].get(edge, 0)}")

## 8. Residual uncertainty

1. Unobserved case risk beyond recorded complexity. Most valuable addition: a validated case-risk score captured at Classify before routing.

2. Actual reviewer skill, capacity, and reviewer-to-case assignment. Most valuable addition: reviewer_id plus time-stamped queue length and staffing level for each review activity.

3. Selection bias from analyzing only completed cases. Most valuable addition: case status and timestamps for open, abandoned, and completed cases to enable survival analysis.

4. Separation of compliance waiting from review queueing and service. Most valuable addition: start/end timestamps for Compliance Check and Request Info loops.

5. Causal role of shift and arrival load. Most valuable addition: randomized or staggered shift-coverage/queue-capacity design with time-stamped arrival_load and queue state.
