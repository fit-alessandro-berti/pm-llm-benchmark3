```
def exhaustive_bounded_visible_language(net, im, fm):
    start = dict(im)
    q = deque()
    q.append((start, (), 0))
    visited = {(mkey(start), (), 0)}
    accepted = set()
    stats = {'expanded':0,'generated':0,'pruned_by_bound':0,'visited':1}
    while q:
       marking, trace, nac = q.popleft()
       stats['expanded'] += 1
       if mkey(marking) == mkey(fm):
          accepted.add(trace); continue
       for trans in pm4py.get_enabled_transitions(net, marking):
          lab = visible_label(trans)
          if lab is not None:
             if len(trace)+1 > MAX_VISIBLE or (lab==ANALYZE and nac+1>MAX_ANALYZE):
                stats['pruned_by_bound'] += 1
                continue
          new_marking = dict(marking)
          pm4py.execute_transition(net, trans, new_marking)
          new_trace = trace if lab is None else trace+(lab,)
          new_nac = nac + (1 if lab==ANALYZE else 0)
          state = (mkey(new_marking), new_trace, new_nac)
```

# 1. Equivalence Notions

I use the PM4Py process-tree reading: `+` is parallel/AND, `X` is XOR/choice, `*` is the binary loop, and `tau` is silent. A complete trace is a trace from the initial marking to the final marking.

- **Visible trace equivalence after hiding `tau`**: let \(L_{vis}(M)\) be the set of complete traces obtained from model \(M\) by deleting all silent transitions. Models \(M_1,M_2\) are visibly trace equivalent iff  
  \[
  L_{vis}(M_1)=L_{vis}(M_2).
  \]
  Different control paths yielding the same visible label sequence are not distinguished.

- **Bounded visible-language equivalence under P3**: define  
  \[
  L_{P3}(M)=\{w\in L_{vis}(M)\mid |w|\le 12 \land \#_w(\text{Analyze Revision})\le 3\}.
  \]
  Models are P3-equivalent iff \(L_{P3}(M_1)=L_{P3}(M_2)\). A bounded counterexample proves non-equivalence; bounded equality is evidence, not an unbounded proof.

- **Business-relevant equivalence under P1**: define abstraction \(\alpha_{P1}\) as follows: hide `tau`; require `Open Case` first and `Close Case` last; segment the middle by `Rework Case`; every segment containing `Analyze Revision` must contain a corresponding `Check Revision` in the same segment before the next `Rework Case` or `Close Case`; keep `Approve Revision` occurrences and their placement relative to the revision attempt. Two models are P1-equivalent iff the sets of \(\alpha_{P1}\)-outputs, including violation markers, are equal.

- **Abstracted dashboard equivalence under P2**: define  
  \[
  \alpha_{P2}(w)=
  (\text{Open-first/Close-last ok?},\ 
   \#\text{Analyze Revision},\ 
   \text{any Check Revision?},\ 
   \text{any Rework Case?})
  \]
  while hiding `Approve Revision` and silent behavior, collapsing repeated `Check Revision` to a Boolean, and ignoring Analyze/Check interleaving.

**Duplicate visible labels:** trace equality uses labels and their positions, not transition identities. Two repeated `Analyze Revision` labels are distinguished by position in the word, but not named as “first analysis token” versus “second analysis token.” P1 derives “own check” from segment membership/counting; P2 collapses checks to a Boolean; P3 compares exact visible label sequences.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | Loop contains `+(Analyze Revision, Check Revision)` followed by optional approval; `Rework Case` is the redo child. | Loop contains `Analyze Revision` followed by optional approval; `Check Revision` is outside and parallel with the whole loop. | A checks every revision attempt. B performs one global check for an arbitrary number of analysis attempts. |
| Minimum `Check Revision` occurrences | 1, because the loop body executes at least once. | 1, because the parallel `Check Revision` branch executes once. | Both guarantee at least one check. |
| Maximum `Check Revision` occurrences | Unbounded: one per loop iteration. | Exactly 1. | Any trace with two or more analyses and one check per analysis separates the models. |
| Possible placement of `Check Revision` | In each iteration, parallel with `Analyze Revision`, before that iteration’s approval choice and before the next `Rework Case`/`Close Case`. | Anywhere between `Open Case` and `Close Case`: before/after Analyze, approvals, rework steps, or after the whole loop. | B allows a check after approval or after all rework; A does not. |
| Optional approval occurrences | One optional `Approve Revision`/`tau` choice per iteration, after Analyze and Check of that iteration. | One optional `Approve Revision`/`tau` choice per analysis iteration, after Analyze. | Counts can coincide, but approval/check relative placement differs. |
| Concurrency | Local concurrency inside each revision attempt: Analyze  Check. | Global concurrency: one Check  entire loop. | A’s concurrency is attempt-local; B’s concurrency spans rework boundaries. |
| Join before `Close Case` | Each local Analyze/Check join occurs before the approval choice; the loop exits before `Close Case`. | The parallel join waits for both the single Check branch and the whole loop before `Close Case`. | B can place `Check Revision` immediately before `Close Case`, even after final approval; A cannot. |

```python
            (getattr(place, "name", str(place)), int(n))
            for place, n in marking.items()
            if int(n) > 0
        )
    )


def exhaustive_bounded_visible_language(net, im, fm):
    start = dict(im)

    # State includes the visible prefix. We must not memoize by marking alone:
    # two different prefixes can reach the same marking and yield different traces.
    queue = deque([(start, tuple(), 0)])
    visited = {(marking_key(start), tuple(), 0)}
    accepted = set()

    stats = {
        "expanded_states": 0,
        "visited_states": 1,
        "generated_states": 0,
        "pruned_by_bound": 0,
    }

    while queue:
        marking, trace, n_analyze = queue.popleft()
        stats["expanded_states"] += 1

        # Explicit final-marking acceptance.
        if marking_key(marking) == marking_key(fm):
            accepted.add(trace)
            continue

        for trans in pm4py.get_enabled_transitions(net, marking):
            label = visible_label(trans)

            if label is not None:
                new_len = len(trace) + 1
                new_n_analyze = n_analyze + (1 if label == ANALYZE else 0)

                if new_len > MAX_VISIBLE:
                    stats["pruned_by_bound"] += 1
                    continue
                if new_n_analyze > MAX_ANALYZE:
                    stats["pruned_by_bound"] += 1
                    continue
            else:
                new_n_analyze = n_analyze

            new_marking = dict(marking)
            pm4py.execute_transition(net, trans, new_marking)

            new_trace = trace if label is None else trace + (label,)
            state = (marking_key(new_marking), new_trace, new_n_analyze)

            if state not in visited:
                visited.add(state)
                stats["visited_states"] += 1
                stats["generated_states"] += 1
                queue.append((new_marking, new_trace, new_n_analyze))

    return accepted, stats


def fmt(trace):
    return "  ".join(trace)


tree_A, net_A, im_A, fm_A = parse_convert_check("Model A", TREE_A)
tree_B, net_B, im_B, fm_B = parse_convert_check("Model B", TREE_B)

L_A, stats_A = exhaustive_bounded_visible_language(net_A, im_A, fm_A)
L_B, stats_B = exhaustive_bounded_visible_language(net_B, im_B, fm_B)

print("\nMODE: EXHAUSTIVE bounded BFS over the finite bounded state space.")
print("No random or heuristic playout was used.")
print(f"P3 bound: <= {MAX_VISIBLE} visible events, <= {MAX_ANALYZE} Analyze Revision events")
print(f"|L_P3(A)| = {len(L_A)}")
print(f"|L_P3(B)| = {len(L_B)}")
print(f"Stats A: {stats_A}")
print(f"Stats B: {stats_B}")
print(f"Bounded equivalent under P3? {L_A == L_B}")

print("\nTraces in A but not B:")
for tr in sorted(L_A - L_B):
    print(fmt(tr))

print("\nTraces in B but not A:")
for tr in sorted(L_B - L_A):
    print(fmt(tr))
```

# 6. Stochastic and Footprint Comparison

`pm4py.discover_footprints(...)` can add structural evidence. For these models, one would expect A to relate `Check Revision` mainly in parallel with `Analyze Revision`, while B relates the single `Check Revision` in parallel with the whole revision loop, including rework and approval behavior. That supports a structural diagnosis, but footprints are pairwise relations, not complete trace languages. Equal footprints would not prove trace equivalence because footprints do not preserve full ordering, multiplicity, loop cardinality, or all silent-transition effects.

```python
fp_A = pm4py.discover_footprints(tree_A)
fp_B = pm4py.discover_footprints(tree_B)

print("Footprint A:", fp_A)
print("Footprint B:", fp_B)

# Typical fields, depending on PM4Py version:
# print(fp_A["sequence"], fp_A["parallel"], fp_A["choice"], fp_A["loop"])
```

`pm4py.get_stochastic_language(...)` and `pm4py.compute_emd(...)` can compare probability distributions over traces, but only after probabilities are declared or learned. The process trees themselves do not provide probabilities. The following uses a deliberately artificial uniform scheduler weight only as an illustration; it is not a business fact.

```python
def add_declared_uniform_weights(net):
    """
    Declaration: every transition receives weight 1.0.
    This imposes a uniform stochastic scheduler assumption. It is not derived
    from data and should not be used as operational truth.
    """
    for trans in net.transitions:
        trans.properties["weight"] = 1.0
        try:
            trans.weight = 1.0
        except Exception:
            pass


add_declared_uniform_weights(net_A)
add_declared_uniform_weights(net_B)

try:
    stochastic_language_A = pm4py.get_stochastic_language(net_A, im_A, fm_A)
    stochastic_language_B = pm4py.get_stochastic_language(net_B, im_B, fm_B)

    # With unbounded loops, stochastic languages can be infinite; in practice
    # apply the same bound/cutoff used for trace comparison.
    emd_value = pm4py.compute_emd(stochastic_language_A, stochastic_language_B)
    print("EMD under declared uniform weights:", emd_value)
except Exception as e:
    print("Stochastic language/EMD not available for this net/version:", e)
```

A low Earth Mover’s Distance would not establish trace equivalence: it depends on the chosen probabilities, may underweight decisive but rare traces, and can be small under smoothing or truncation. EMD zero under one probability model still does not imply equal support unless that is separately checked. Stochastic evidence is therefore complementary to, not a substitute for, exact language comparison.

# 7. Complexity Comparison

Node counts below include operators and leaves. Depth uses root depth 0. “Duplicate labels” counts repeated leaf labels in the process-tree structure; runtime duplicate occurrences caused by loops are unbounded.

| Metric | Model A | Model B | Comment |
|---|---:|---:|---|
| Process-tree node count | 12 | 12 | Same raw node count. |
| Depth | 4 | 5 | B is deeper because the loop is nested under the global parallel operator. |
| Leaves | 7 | 7 | Same number of leaves. |
| Visible leaves | 6 | 6 | Open, Analyze, Check, Approve, Rework, Close. |
| Silent leaves | 1 | 1 | One `tau` per model. |
| Duplicate-tree-label count | 0 | 0 | No leaf label repeats structurally. |
| Converted-Petri-net simplicity | compute below | compute below | Exact value is version/conversion dependent, so report it from code rather than hard-code it. |

```python
from collections import Counter

def is_leaf(node):
    return not node.children


def is_silent_leaf(node):
    return is_leaf(node) and (
        node.label is None or str(node.label) in ("", "tau", "")
    )


def process_tree_stats(node, depth=0):
    nodes = 1
    leaves = 0
    visible_leaves = 0
    silent_leaves = 0
    max_depth = depth
    labels = []

    if is_leaf(node):
        leaves = 1
        if is_silent_leaf(node):
            silent_leaves += 1
        else:
            visible_leaves += 1
            labels.append(str(node.label))
    else:
        for child in node.children:
            child_stats = process_tree_stats(child, depth + 1)
            nodes += child_stats["nodes"]
            leaves += child_stats["leaves"]
            visible_leaves += child_stats["visible_leaves"]
            silent_leaves += child_stats["silent_leaves"]
            labels.extend(child_stats["labels"])
            max_depth = max(max_depth, child_stats["max_depth"])

    label_counts = Counter(labels)
    duplicate_labels = sum(c - 1 for c in label_counts.values() if c > 1)

    return {
        "nodes": nodes,
        "leaves": leaves,
        "visible_leaves": visible_leaves,
        "silent_leaves": silent_leaves,
        "max_depth": max_depth,
        "duplicate_labels": duplicate_labels,
    }


print("A structural stats:", process_tree_stats(tree_A))
print("B structural stats:", process_tree_stats(tree_B))

simplicity_A = pm4py.simplicity_petri_net(net_A, im_A, fm_A)
simplicity_B = pm4py.simplicity_petri_net(net_B, im_B, fm_B)

print("A Petri-net simplicity:", simplicity_A)
print("B Petri-net simplicity:", simplicity_B)
```

# 8. Simplified Model

Target semantics chosen: **P1 operational compliance**, with the explicit abstraction that the relative order of `Analyze Revision` and `Check Revision` inside one attempt is not business-relevant; what matters is that each attempt has one Check before the next `Rework Case`/`Close Case`, and that approval placement relative to the attempt remains visible.

Simplified process tree:

```text
->(
  'Open Case',
  *(
    ->(
      'Analyze Revision',
      'Check Revision',
      X('Approve Revision', tau)
    ),
    'Rework Case'
  ),
  'Close Case'
)
```

Compared with both originals, this removes the parallel operator. Structurally, it has 11 nodes instead of 12, depth 4, the same 7 leaves, 6 visible leaves, 1 silent leaf, and 0 duplicate tree labels. Behaviorally, it is simpler because it allows only `Analyze Revision  Check Revision`, not both interleavings.

```python
SIMPLIFIED_MODEL = (
    "->('Open Case', "
    "*(->('Analyze Revision', 'Check Revision', "
    "X('Approve Revision', tau)), "
    "'Rework Case'), "
    "'Close Case')"
)

simplified_model = pm4py.parse_process_tree(SIMPLIFIED_MODEL)

simplified_net, simplified_im, simplified_fm = pm4py.convert_to_petri_net(
    simplified_model
)

try:
    simplified_sound = pm4py.check_soundness(
        simplified_net, simplified_im, simplified_fm, print_diagnostics=True
    )
except TypeError:
    simplified_sound = pm4py.check_soundness(
        simplified_net, simplified_im, simplified_fm
    )

print("simplified_model soundness =", simplified_sound)
print("simplified_model =", simplified_model)
```

| Property | Model A | Simplified model | Status | Note |
|---|---|---|---|---|
| `Open Case` first, `Close Case` last | yes | yes | exact | Preserved. |
| At least one revision attempt | yes | yes | exact | Binary loop still executes body once. |
| One Check per analysis attempt before rework/close | yes | yes | exact | Preserved under P1. |
| `Rework Case` separates attempts | yes | yes | exact | Same loop redo child. |
| Optional approval after the revision attempt | yes | yes | exact | Approval count and placement relative to attempt preserved. |
| Analyze/Check interleaving | both orders | only Analyze then Check | weakened / abstracted away | Lost at raw P3 level; intentionally irrelevant under the chosen P1 abstraction. |
| P2 dashboard abstraction | equivalent | equivalent | exact at P2 abstraction | Both map to same dashboard facts as A and B. |
| Raw P3 visible-trace language | A-specific | subset of A | lost | The simplified model is not a raw trace-preserving replacement for A. |
| B’s single global Check behavior | absent | absent | lost intentionally | B violates the chosen P1 compliance view. |

Regression traces admitted by the simplified model:

| Kind | Trace | Expected result |
|---|---|---|
| regression | `Open Case  Analyze Revision  Check Revision  Close Case` | admitted; one compliant attempt |
| regression | `Open Case  Analyze Revision  Check Revision  Approve Revision  Rework Case  Analyze Revision  Check Revision  Close Case` | admitted; approval placement preserved |
| regression | `Open Case  Analyze Revision  Check Revision  Rework Case  Analyze Revision  Check Revision  Approve Revision  Rework Case  Analyze Revision  Check Revision  Approve Revision  Close Case` | admitted; within P3 bounds: 12 visible events, 3 Analyze events |
| negative | `Open Case  Check Revision  Analyze Revision  Close Case` | rejected; admitted by A but removed by simplified Analyze-before-Check choice |
| negative | `Open Case  Analyze Revision  Rework Case  Analyze Revision  Check Revision  Close Case` | rejected; first analysis lacks its own Check, so P1 violated |
| negative | `Open Case  Analyze Revision  Approve Revision  Check Revision  Close Case` | rejected; Check after approval is not allowed by the simplified P1 model |

# 9. Final Recommendation

- For **P1 operational compliance**, prefer **Model A** if the raw possibility of Check-before-Analyze must remain. Use the **simplified model** only if Analyze/Check interleaving is explicitly irrelevant and the organization wants a stricter, easier-to-read compliance model. **Model B is not suitable**.
- For **P2 executive dashboard**, **A and B are equivalent under the stated abstraction**. Either can feed the dashboard, but neither should be interpreted operationally from that dashboard view. The simplified model also preserves the P2 abstraction.
- For **P3 bounded testing**, **A and B are not equivalent**. Keep them distinct if visible approval placement, Check multiplicity, or Check placement relative to rework matters.

A single simplification cannot preserve all three views simultaneously. Any raw P3-preserving replacement for A must retain A’s multiple checks and check-before-approval constraint; any raw P3-preserving replacement for B must retain one global, freely interleaved Check. Bounded comparison is useful evidence and can prove non-equivalence when it finds a witness, but bounded equality must never be reported as unbounded trace equivalence.
