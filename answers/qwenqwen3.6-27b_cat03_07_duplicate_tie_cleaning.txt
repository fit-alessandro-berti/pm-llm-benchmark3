    ACTION: RETAIN BOTH unchanged; enforce parallel lifecycle tracking

     Criteria: Conflicting metadata, ambiguous object mapping, no reconciliation evidence
     ACTION: QUARANTINE for review; exclude from analytical OCEL until resolved

## 3. Timestamp-tie ordering rules

**Policy: Semantic-first, deterministic-fallback partial-to-total ordering**

1. **Domain constraints** (Semantic): Business rules dictate precedence (e.g., `Validate Order`  `Pick Item`; `Authorize Payment`  `Capture Payment`).
2. **Lifecycle constraints on shared objects** (Semantic): Object state machines enforce order (e.g., Item picked  Package packed; Carrier accepted  Handover).
3. **Source-specific semantics** (Semantic): WMS detailed transactions precede ERP summaries; Carrier acceptance precedes handover.
4. **Within-source sequence** (Deterministic/Operational): `source_seq` ascending reflects system commit order; reliable for intra-source ties.
5. **Ingestion time** (Deterministic fallback): Only applied when all semantic and sequence rules are exhausted. Not a business timestamp.
6. **Stable fallback** (Deterministic): Lexicographic sort on `eid` guarantees reproducibility across runs.

**Semantic vs Deterministic:** Rules 1, 2, 3 are semantic. Rules 4, 5, 6 are deterministic. Rule 4 bridges both but is treated as deterministic for tie-breaking.

**Why synthetic microseconds before semantic ordering encode a false story:** Injecting microsecond offsets to force a total order before evaluating semantic constraints arbitrarily assigns physical causality. If `ingested_at` or random jitter places an ERP summary before a WMS detail, the pipeline will infer a reverse causality loop, distort performance metrics, and create phantom rework in the DFG. Deterministic ordering must only resolve ties *after* semantic equivalence is established, and the original timestamp must remain untouched.

**Intended orders (post-duplicate decisions):**
- **10:00:00 block (e03–e07):** `e03` (Pick I1)  `e05` (Pick I2)  `e06` (Pack Detail)  `e07` (Pack Summary). Rationale: Items must be picked before packing; detailed WMS precedes ERP summary.
- **10:15:00 block (e08–e10):** `e08` (Dispatch/Release)  `e09` (Carrier Accept)  `e10` (Handover). Rationale: Warehouse release precedes carrier acceptance; handover follows acceptance per carrier lifecycle.
- **12:00:00 block (e11–e16):** `e11` (Invoice ERP)  `e12` (Auth M1)  `e13` (Capture M1)  `e14` (Capture M2)  `e15` (Payment Summary). Rationale: Invoice precedes payment; authorization precedes capture; captures are concurrent but ordered by payment ID; ERP summary follows PSP messages.

## 4. Conservative cleaning pipeline

The conservative pipeline applies minimum necessary changes to preserve analytical fidelity while removing only strongly supported duplicates.

1. **Fingerprint & Group:** Hash `(activity, timestamp, related_objects)` to form candidate groups. Exclude groups with disjoint objects.
2. **Apply Decision Tree:** Route each group through the tree. Only exact technical duplicates and verified same-physical observations (e03/e04, e11/e16) trigger merges.
3. **Merge Verified Pairs:** Union attributes and relations. Partition conflicting fields by source authority. Attach secondary `source_event_key` and `source` to the canonical event as provenance metadata.
4. **Refine Harmonized Labels:** Where collisions occur (e08/e09), append qualifiers (`Dispatch.Package.Release`, `Dispatch.Package.Accept`) while preserving `original_activity`.
5. **Preserve Abstraction Levels:** Retain summary/detail pairs (e06/e07, e13/e15, e14/e15) unchanged. Do not merge across abstraction boundaries.
6. **Deterministic Ordering:** Apply semantic rules first, then `source_seq`, then `eid`. Store result in a separate `order_rank` column. Never overwrite `timestamp`.
7. **Validation & Export:** Verify referential integrity (all E2O references exist in objects table). Export cleaned OCEL.

```python
import copy
import pandas as pd
import pm4py
from pm4py.objects.ocel.obj import ObjectCentricEventLog as OCEL

def merge_verified_pair(ocel, secondary_eid, canonical_eid, attr_policy='union', rel_policy='union'):
    """Custom merge for verified same-physical events."""
    sec = ocel.events.loc[ocel.events['eid'] == secondary_eid]
    can = ocel.events.loc[ocel.events['eid'] == canonical_eid]
    
    # Preserve original fields
    ocel.events.loc[ocel.events['eid'] == canonical_eid, 'original_timestamp'] = can['timestamp'].values[0]
    ocel.events.loc[ocel.events['eid'] == canonical_eid, 'original_activity'] = can['activity'].values[0]
    
    # Merge attributes (simplified union)
    merged_attrs = pd.concat([can['payload_hash'], sec['payload_hash']], ignore_index=True).unique()
    ocel.events.loc[ocel.events['eid'] == canonical_eid, 'payload_hash'] = '|'.join(merged_attrs)
    
    # Merge relations: union E2O rows
    can_e2o = ocel.e2o[ocel.e2o['event_id'] == canonical_eid]
    sec_e2o = ocel.e2o[ocel.e2o['event_id'] == secondary_eid]
    ocel.e2o = pd.concat([ocel.e2o, sec_e2o], ignore_index=True)
    
    # Attach provenance
    ocel.events.loc[ocel.events['eid'] == canonical_eid, 'merged_from'] = secondary_eid
    ocel.events.loc[ocel.events['eid'] == canonical_eid, 'source_provenance'] = sec['source'].values[0]
    
    # Drop secondary
    ocel.events = ocel.events[ocel.events['eid'] != secondary_eid]
    ocel.e2o = ocel.e2o[ocel.e2o['event_id'] != secondary_eid]
    return ocel

def validate_referential_integrity(ocel):
    """Check E2O references exist in events and objects tables."""
    invalid_eids = ocel.e2o['event_id'].difference(ocel.events['eid'])
    invalid_objs = ocel.e2o['object_id'].difference(ocel.objects['object_id'])
    assert len(invalid_eids) == 0, f"Orphaned events: {invalid_eids}"
    assert len(invalid_objs) == 0, f"Orphaned objects: {invalid_objs}"
    return True

# Assume ocel_raw exists
ocel_conservative = copy.deepcopy(ocel_raw)
ocel_aggressive = copy.deepcopy(ocel_raw)

# --- CONSERVATIVE SCENARIO ---
# Pre-check candidate groups
candidates = ocel_conservative.events.groupby(['timestamp', 'activity'])['eid'].apply(list)
candidate_groups = {k: v for k, v in candidates.items() if len(v) > 1}

# Custom verified-pair merge for e03/e04 and e11/e16
verified_pairs = [('e04', 'e03'), ('e16', 'e11')]
for sec, can in verified_pairs:
    ocel_conservative = merge_verified_pair(ocel_conservative, sec, can)

# Deterministic ordering without deleting concurrency
ocel_conservative.events['order_key'] = (
    ocel_conservative.events['timestamp'].astype(str) + '_' + 
    ocel_conservative.events['source_seq'].astype(str) + '_' + 
    ocel_conservative.events['eid']
)
pm4py.ocel_sort_by_additional_column(ocel_conservative, 'order_key')
pm4py.ocel_add_index_based_timedelta(ocel_conservative)

validate_referential_integrity(ocel_conservative)

# --- AGGRESSIVE SCENARIO (WITH WARNING) ---
print("WARNING: Aggressive merging applied. Semantic granularity will be reduced.")
# Justified drop of exact technical duplicates only
pm4py.ocel_drop_duplicates(ocel_aggressive, columns=['source_event_key', 'timestamp', 'activity'])
# Mechanically merge remaining ties on activity+timestamp+objects
pm4py.ocel_merge_duplicates(ocel_aggressive, 
                            group_by=['activity', 'timestamp', 'related_objects'],
                            merge_strategy='union')
pm4py.ocel_sort_by_additional_column(ocel_aggressive, 'timestamp')
pm4py.ocel_add_index_based_timedelta(ocel_aggressive)
validate_referential_integrity(ocel_aggressive)
```

**Six concrete edges/patterns with interpretation changes:**
1. `(Pick Item, Pack Package)`: Raw shows potential reverse edge due to tie; conservative fixes it; aggressive keeps it but loses item granularity.
2. `(Dispatch Package, Handover to Carrier)`: Raw conflates release/accept/handover; conservative separates them; aggressive merges into single edge.
3. `(Authorize Payment, Capture Payment)`: Raw may show parallelism; conservative enforces authcapture; aggressive preserves but loses M1/M2 distinction.
4. `(Issue Invoice, Authorize Payment)`: Raw shows concurrent invoice events; conservative merges e11/e16, clarifies start point; aggressive drops billing source entirely.
5. `(Pick Item I1, Pick Item I2)`: Raw appears sequential; conservative reveals parallelism; aggressive collapses to one pick.
6. `(Capture Payment M1, Capture Payment M2)`: Raw concurrent; conservative retains both; evidence-based retains both; aggressive merges, destroying partial payment tracking.

**Reconstruction:** An analyst reconstructs the raw view by joining the audit trail with the cleaned OCEL. For each canonical event, the `source_event_ids` array is expanded back into separate rows. Original timestamps, activities, and source attributes are restored from the audit columns. The `order_key` and `timedelta` columns are dropped. E2O relations are split according to the original `source_event_key` mapping. Because all merges are logged with deterministic keys and no original data is overwritten, the transformation is fully reversible and auditable.

## 9. Failure modes and safeguards

1. **Collapsing distinct partial payments:** Merging e13/e14 due to shared O1/V1 destroys M1/M2 tracking. *Safeguard:* Require object intersection == object union for duplication; payment ID must match exactly.
2. **Converting abstraction-level updates into false rework:** Merging e06/e07 or e13/e15 creates artificial state reversals. *Safeguard:* Preserve summary/detail pairs; use refined labels; never merge across abstraction boundaries.
3. **Ordering by ingestion time:** Using `ingested_at` as primary order reverses causality when network latency varies. *Safeguard:* Restrict ingestion time to final deterministic tie-break; prioritize domain/lifecycle rules.
4. **Treating shared objects as proof of duplication:** Assuming e13/e14 are duplicates because they share O1/V1. *Safeguard:* Validate object-level specificity; shared objects indicate concurrency, not duplication.
5. **Unioning incompatible E2O relations:** Merging WMS item-level picks with ERP order-level summaries creates orphaned object references. *Safeguard:* Validate object type compatibility before union; reject cross-type merges without explicit mapping rules.
6. **Changing durations through synthetic microseconds:** Injecting offsets to break ties alters performance metrics and SLA calculations. *Safeguard:* Store synthetic order in a separate column; never overwrite `original_timestamp`; document offset as analytical artifact.
7. **Losing source-authoritative attributes:** Overwriting ERP financial fields with billing tax fields during merge. *Safeguard:* Partition attributes by source authority; use explicit conflict resolution policy; log discarded conflicts in audit trail.
8. **Applying duplicate functions to whole OCEL without inspecting candidates:** Running `ocel_drop_duplicates` globally collapses legitimate concurrency. *Safeguard:* Pre-filter candidate groups using activity+timestamp+object overlap; only apply deduplication to verified groups; quarantine unresolved candidates.
