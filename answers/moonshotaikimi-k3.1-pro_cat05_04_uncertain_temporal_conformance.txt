## 1. Normalization Assumptions

**Interval and clock model.** I first construct the source-clock interval implied by rounding, then correct for clock offset. If the recorded clock value is \(R\in[r_l,r_h)\) and

\[
\text{clock\_offset}=R-T\in[a,b],
\]

where \(T\) is true time, then

\[
T\in[r_l-b,\;r_h-a).
\]

Thus, subtracting an offset interval is not the same as adding it. Closed HUB endpoints are retained below where useful; minute/10-second rounding windows are treated as half-open. Endpoint openness does not change any classification here.

- **HUB:** apply ±0.5 s measurement uncertainty, then the \([-1,+1]\) s offset bound. The resulting true-time interval is the displayed UTC second ±1.5 s.
- **OPS-BER:** the displayed minute first becomes a 60-second source-clock window. CEST is UTC+2 on the supplied dates.
- **SENSOR:** nearest-10-second rounding gives a ±5 s source-clock window before offset correction. No extra completion-time allowance is added.
- **VENDOR-NY:** EDT is UTC4. Its offset bound is used, but evidence strength remains lower because there is no event-level synchronization.
- **MOBILE-LON:** nearest-minute rounding gives a ±30 s source-clock window before offset correction; BST is UTC+1.

**Duration arithmetic.** For independent event intervals \(X\) and \(Y\), the duration hull is

\[
D_{X\rightarrow Y}=[Y_l-X_h,\;Y_h-X_l].
\]

Where events are jointly constrained—especially T-405, inferred starts, and conditional causal models—I apply those constraints rather than treating every marginal interval as independently combinable. Disjoint alternatives are not collapsed merely to make a wider hull.

**T-404 inferred start.** I accept the signed 18–25 minute investigation-duration record as a hard bound for the conditional analysis:

\[
\text{Investigation\_Start}
=\text{Investigation\_Complete}-D,\qquad D\in[1080,1500]\text{ s}.
\]

The start remains inferred, not observed. For containment duration, the equivalent correlated calculation is \((C-IC)+D\); its hull is the same as the interval reported below. If the signed record is only an informal estimate, the start-dependent findings become INDETERMINATE rather than enforcement-grade.

**T-405 DST and ordering.** Both DST folds are constructed. I conditionally interpret the ingestion statements as occurrence/causal order

\[
A<I<C,
\]

not merely database arrival order. Only the following fold combination survives:

- Alert: first fold, CEST;
- Investigation_Start: second fold, CET;
- Containment_Complete: second fold, CET.

The remaining timestamp intervals are still uncertain. If ingestion order is only arrival order and carries no occurrence-order semantics, this pruning is not justified and the start-dependent T-405 results must be weakened.

**T-406 mobile entry delay.** Two substantive interpretations are reported:

1. **Primary occurrence-time model:** the displayed value reflects the time of entry/current mobile clock, and entry occurred \(d\in[0,5]\) minutes after the event. Occurrence is therefore the indicated true time minus \(d\). This shifts the earliest possible occurrence five minutes earlier and widens the interval.
2. **Late-recording-only alternative:** the delay affects only when the record was saved, while the entered value was already intended as the occurrence time. It does not shift the occurrence-time estimate.

This distinction materially changes T-406 S2 and one temporal-profile result.

**T-407 missing receipt.** Alert_Sent is not substituted for Alert_Received. Unconditionally, the sent interval plus delivery latency gives only a receipt envelope. **T-409 weak clock evidence.** The ±12 minute engineering estimate is used only as a clearly labelled conditional bound. **Classification and severity.** CP, CV, PV, and I below mean CERTAIN_PASS, CERTAIN_VIOLATION, POSSIBLE_VIOLATION, and INDETERMINATE. “Certain” is always conditional on the stated evidence model. def source_clock_window(naive, resolution):
    """Rounding/measurement uncertainty, before clock correction."""
    if resolution == "hub":
        return naive - timedelta(seconds=0.5), naive + timedelta(seconds=0.5)
    if resolution == "floor_minute":
        return naive, naive + timedelta(minutes=1)
    if resolution == "round_10s":
        return naive - timedelta(seconds=5), naive + timedelta(seconds=5)
    if resolution == "round_minute":
        return naive - timedelta(seconds=30), naive + timedelta(seconds=30)
    raise ValueError(resolution)


def local_to_utc(naive, tz_name, fold):
    if tz_name == "UTC":
        aware = naive.replace(tzinfo=UTC)
    else:
        # Python fold=0/1 distinguishes the two ambiguous DST occurrences.
        aware = naive.replace(tzinfo=ZoneInfo(tz_name), fold=fold)
    return pd.Timestamp(aware).tz_convert("UTC")


def normalize_row(case_id, value, system, shift_mobile_delay=True):
    """Return alternative true-time intervals; do not average DST alternatives."""
    meta = META[system]
    naive = datetime.fromisoformat(value)
    clock_lo, clock_hi = source_clock_window(naive, meta["resolution"])

    offset_lo, offset_hi = meta["offset"]
    if case_id == "T-409":
        # Conditional weak engineering estimate, not the normal OPS bound.
        offset_lo, offset_hi = -720, 720

    folds = (0, 1) if system == "LEGACY-BER" else (0,)
    answer = []
    for fold in folds:
        # Time-zone conversion precedes subtraction of the source offset.
        recorded_utc_lo = local_to_utc(clock_lo, meta["tz"], fold)
        recorded_utc_hi = local_to_utc(clock_hi, meta["tz"], fold)

        # true = recorded - offset, offset in [offset_lo, offset_hi]
        true_lo = recorded_utc_lo - pd.Timedelta(seconds=offset_hi)
        true_hi = recorded_utc_hi - pd.Timedelta(seconds=offset_lo)
        iv = Iv(true_lo, true_hi)

        if system == "MOBILE-LON" and shift_mobile_delay:
            # Primary model: displayed/entry time = occurrence + entry delay.
            # occurrence = indicated true time - d, d in [0, 5] minutes.
            iv = Iv(iv.lo - pd.Timedelta(minutes=5), iv.hi)

        if iv not in answer:
            answer.append(iv)
    return answer

# 4. Duration intervals and interval classifications.
def merge_duration_intervals(intervals):
    """Merge overlap only; disjoint feasible components remain disjoint."""
    result = []
    for lo, hi in sorted(intervals):
        if result and lo <= result[-1][1]:
            result[-1] = (result[-1][0], max(result[-1][1], hi))
        else:
            result.append((lo, hi))
    return result


def duration_intervals(case_id, activity_a, activity_b, causal_clip=False):
    key_a, key_b = (case_id, activity_a), (case_id, activity_b)
    if key_a not in ALTS or key_b not in ALTS:
        return []

    answer = []
    for a in ALTS[key_a]:
        for b in ALTS[key_b]:
            lo = (b.lo - a.hi).total_seconds()
            hi = (b.hi - a.lo).total_seconds()
            if causal_clip:
                # Explicit conditional model only: discard negative-duration traces.
                if hi < 0:
                    continue
                lo = max(0.0, lo)
            answer.append((lo, hi))
    return merge_duration_intervals(answer)


def classify(duration_set, acceptance):
    """Acceptance is an inclusive (lower, upper) band."""
    lower, upper = acceptance
    all_inside = all(
        lo >= lower and hi <= upper for lo, hi in duration_set
    )
    any_inside = any(
        max(lo, lower) <= min(hi, upper) for lo, hi in duration_set
    )
    if all_inside:
        return "CERTAIN_PASS"
    if not any_inside:
        return "CERTAIN_VIOLATION"
    return "POSSIBLE_VIOLATION"

## 6. Evidential Sufficiency

For any remaining PV result, additional evidence must do more than move a midpoint. It must tighten or constrain the feasible duration set so that:

- **Certain SLA pass:** every feasible duration is at most the applicable deadline;
- **Certain SLA violation:** every feasible duration exceeds that deadline;
- **Certain profile pass:** the whole feasible set lies inside the band;
- **Certain profile violation:** the whole feasible set lies wholly below or wholly above it.

The same rule applies to tolerance- and zeta-induced PV results using the adjusted deadline or band.

| Case | PV or I results covered | Minimum additional evidence needed |
|---|---|---|
| T-401 | S1; AI at zeta 1–2 | **Stronger synchronization/resolution evidence:** an event-level OPS offset measurement plus the unrounded start second, or an independent HUB-quality start timestamp. It must separate the duration interval from 900 s or from the relevant profile band. |
| T-402 | S2; AI at zeta 2–3; IC at zeta 1; tolerance-induced S1 PV | The same kind of **OPS start synchronization and resolution evidence**. Alert and containment HUB refinements alone cannot remove most of the width. |

## 7. Governance Recommendation

1. **Retain UTC and raw source time.** Store the best estimate of occurrence time in UTC at high resolution, while immutably retaining the raw displayed timestamp, source time zone, UTC offset, source clock reading, and ingestion time. Never replace the raw value with a midpoint or corrected timestamp.

2. **Make uncertainty first-class metadata.** Record resolution and rounding semantics—exact, floor, nearest—and their numeric uncertainty. Store clock-offset bounds, measurement error, entry-delay bounds, and evidence strength alongside each event. Preserve interval unions and joint constraints in the evidence record.

3. **Continuously monitor clocks.** Collect NTP/PTP offset and error-bound telemetry at sufficient frequency to cover every event, including vendor and mobile sources where feasible. Missing diagnostics should automatically reduce evidence strength; a weak engineering estimate should not silently inherit the trust level of monitored clock evidence.

4. **Control time-zone and DST handling.** Store the IANA zone and tz-database version, the UTC offset in effect, and an explicit `fold`/DST-ambiguity indicator. Ambiguous or nonexistent local times should require review. Ingestion sequence must remain distinct from occurrence order and should not silently select a fold.

5. **Complete lifecycle instrumentation.** Capture Alert_Sent and Alert_Received as different activities, preferably with a correlated delivery acknowledgment. Require explicit Investigation_Start, Investigation_Complete, Containment_Complete, and Close_Incident events. Completion events should not be relabelled as starts. Inferred starts must carry the duration evidence and derivation provenance.

6. **Separate occurrence, entry, and ingestion.** For manual/mobile records, automatically capture device entry time and ingestion time, and separately solicit or capture the asserted occurrence time. Late entry should not be assumed either to shift occurrence time or to be harmless without a documented semantic policy.

7. **Add causal provenance.** Use incident identifiers, event identifiers, causal-parent/correlation identifiers, and receipt acknowledgments. Network latency should be labelled as a validated hard bound, statistical estimate, or mere expectation; these are not interchangeable.

8. **Use different enforcement policies for SLAs and profiles.** For automatic legal or operational SLA penalties, I recommend requiring **CERTAIN_VIOLATION** under an approved evidence model and tolerance. CP can be reported as assured compliance within that model. PV should trigger targeted evidence collection or manual review, and I should be reported as insufficient evidence—not as a pass. If an organization chooses to enforce on mere overlap, that policy should be explicit, legally approved, and distinguished from proof of breach.

9. **Treat temporal profiles as anomaly detection.** Version the profile, zeta, and training population. A profile deviation should prompt investigation, not override SLA arithmetic, and widening zeta should not be used to excuse a legal deadline breach.

10. **Audit borderline calculations.** Retain the normalization code, assumptions, feasible trace constraints, and sensitivity results. The 1.5–3 second tails in several cases demonstrate why midpoint-only conformance, silent rounding, and unsupported causal pruning are unsuitable for enforcement.
