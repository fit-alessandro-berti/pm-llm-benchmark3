| `p_review`  `t_standard_review` / `t_waive_review` | XOR choice standard review vs waiver | One token from `p_review` can go to either `p_review_done` or `p_waived` | Choice is exclusive as intended |
| `t_join_normal` | AND-join analysis + standard review | Requires `p_analysis_done` and `p_review_done`  `p_decision` | Works for standard path |
| `t_join_waived` | Should synchronise analysis + waiver | Requires only `p_waived`  `p_decision`, no link to analysis | Premature authorisation, dead tokens |
| Initial marking `im[source]=1` / Final marking `fm[sink]=1` | Proper start/end | Start is correct, end requires all tokens removed | Final marking unreachable on waiver |
| Node reachability | Every node on source-sink path | All places/transitions are reachable from source and can reach sink | Workflow-net condition holds structurally |

# 3. Marking-Based Counterexample
Legal firing exposing the defect, waiver route:

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|---|---|---|---|---|
| 0 | - | source=1 | t_register | start |
| 1 | t_register | p_ready=1 | t_split | |
| 2 | t_split | p_analysis=1, p_review=1 | t_analyze, t_standard_review, t_waive_review | parallel tokens created |
| 3 | t_waive_review | p_analysis=1, p_waived=1 | t_analyze, t_join_waived | review chosen, analysis still pending |
| 4 | t_join_waived | p_analysis=1, p_decision=1 | t_analyze, t_authorize | decision reachable without analysis |
| 5 | t_authorize | p_analysis=1, sink=1 | t_analyze | sink token exists but `fm` not reached |
| 6 | t_analyze | p_analysis_done=1, sink=1 | - | token in `p_analysis_done` is dead, `t_join_normal` needs `p_review_done` which never appears |

`t_authorize` can fire before `t_analyze`. `sink=1` is present at step 5 but the exact final marking `fm` with only `sink=1` is never reached because `p_analysis_done` remains. The leftover token cannot be consumed: `t_join_normal` needs both `p_analysis_done` and `p_review_done`; `t_join_waived` has already fired and `p_waived` is empty.

# 4. Minimal-Repair Alternatives
Edit cost = added arcs + removed arcs + added places + removed places + added transitions + removed transitions.

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---|---|---|---|
| A. Synchronise waiver with analysis | Add arc `p_analysis_done  t_join_waived`. Keep all existing nodes. | +1 arc | Mandatory analysis on both paths, parallel start, choice preserved | `t_authorize` now waits for analysis also on waiver | Two joins remain, silent `t_join_waived` still present |
| B. Merge review outcomes | Remove place `p_waived`, remove transition `t_join_waived`, remove arcs `p_waivedt_join_waived`, `t_join_waivedp_decision`, `t_waive_reviewp_waived`; add arc `t_waive_reviewp_review_done`. | -1 place, -1 transition, -3 arcs, +1 arc | Mandatory analysis preserved, single AND-join | Waiver and standard review become indistinguishable in marking | Loss of audit distinction between waiver and standard review |

Minimality: Repair A is one arc addition, the smallest possible change that forces analysis completion on the waiver path. Repair B is structurally different and removes the duplicate join; it is minimal among merges that keep a single synchronisation point.

# 6. Diagnostic and Reachability Code
```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

def fire(net, marking, transition):
    enabled = pm4py.get_enabled_transitions(net, marking)
    if transition not in enabled:
        raise ValueError(f"{transition} not enabled in {marking}")
    new_marking = Marking()
    for p in net.places:
        new_marking[p] = marking.get(p, 0)
    for p in net.in_arcs[transition]:
        new_marking[p] -= 1
    for p in net.out_arcs[transition]:
        new_marking[p] = new_marking.get(p, 0) + 1
    return new_marking

print("Original workflow net:", pm4py.check_is_workflow_net(net))
print("Repaired workflow net:", pm4py.check_is_workflow_net(repaired_net))

pm4py.check_soundness(net, im, fm, print_diagnostics=True)
pm4py.check_soundness(repaired_net, repaired_im, repaired_fm, print_diagnostics=True)

print("Original enabled from im:", pm4py.get_enabled_transitions(net, im))
print("Repaired enabled from im:", pm4py.get_enabled_transitions(repaired_net, repaired_im))

rg_orig = pm4py.convert_to_reachability_graph(net, im, fm)
rg_rep = pm4py.convert_to_reachability_graph(repaired_net, repaired_im, repaired_fm)
```

Expected qualitative difference: `check_is_workflow_net` is True for both. Original `check_soundness` reports unsoundness, e.g., improper completion / dead tokens on the waiver path. Repaired net is sound; enabled transition sets evolve consistently and the reachability graph contains a path from `im` to `fm` with no dead markings.

# 7. Repair Trade-Offs and Residual Risks
Waiver vs standard review remain distinguishable with Repair A because `p_waived` and `p_review_done` are separate. Silent transitions `t_split`, `t_join_normal`, `t_join_waived` remain; they can cause confusion but do not change behaviour. Soundness alone does not prove business alignment: the net could still allow analysis after authorisation in a different interleaving, which is avoided here by the added synchronisation. Regression tests should include positive traces `Register  Split  Analyze  StandardReview  Authorize` and `Register  Split  Analyze  Waive  Authorize`, and negative traces where Authorize precedes Analyze or where Analyze is skipped. An accidental bypass of mandatory analysis would be detected by a marking check that `p_analysis_done` is present before `t_join_waived` fires, or by a property test that every `t_authorize` firing is preceded by `t_analyze`.

# 8. Final Recommendation
Deploy Repair A – add `p_analysis_done  t_join_waived`. It is a one-arc change, preserves auditability of waiver vs standard review, and retains mandatory analysis on both paths. Fallback is Repair B merging review outcomes into a single `p_review_done`; it simplifies the model to one AND-join at the cost of losing explicit waiver traceability.
