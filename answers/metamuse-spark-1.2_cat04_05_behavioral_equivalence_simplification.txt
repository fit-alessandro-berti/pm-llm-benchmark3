# 1. Equivalence Notions

## Observation model
All verdicts hide `tau`. A complete execution is a firing sequence from initial marking `IM` to final marking `FM` that yields a *visible trace* `_v = _()` where `` is the set of labelled transitions and `` deletes `tau`. Two `tau` occurrences are indistinguishable and unobservable. Visible labels are observed **only by label**, not by transition identity or occurrence index: e.g. two `Check Revision` events in one trace are `Check,Check` with no ID; traces are sequences over ``. This is the standard language view `L_v(N) = { _() | IM  FM }`.

## Visible-trace equivalence after hiding `tau`
`N1 _v N2` iff `L_v(N1)=L_v(N2)` after projection. Requires equal sets of complete visible traces over the union alphabet `{Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, Close Case}`. Duplicate labels are collapsed to label equality; `Approve Revision` remains visible when it occurs, absent when `tau` chosen. Unbounded: proof needs language inclusion both ways.

## Bounded visible-language equivalence under P3
`N1 _{b} N2` iff `L_v(N1)B = L_v(N2)B` where `B={ _v | |_v|12  #Analyze(_v)3  _v complete }`. Hide `tau` but retain all other visible labels. This is **testing** not proof: equality on `B` is necessary but not sufficient for `_v`; inequality on `B` suffices to refute `_v`.

## Business-relevant equivalence under P1
`_{P1}` is stricter than `_v`. P1 imposes compliance predicates on visible traces:
1. ` occurrence of Analyze_i,  Check_j with Analyze_i < Check_j < NextBoundary_i` where `NextBoundary_i` is the next `Rework Case` or `Close Case` following `Analyze_i` (and for the last analysis, before `Close`).
2. `Rework Case` separates two analysis attempts: no trace contains `...Analyze ... Analyze...` without an intervening `Rework`.
3. `Approve Revision` is optional per iteration (`X(Approve,tau)`), visible count 0..k preserved.
4. `Open Case` first, `Close Case` last.

Two models are P1-equivalent only if they satisfy *exactly the same set* of P1-compliant traces; a model that admits a P1-violating trace while the other does not is `not equivalent` even if `L_v` differ only on violating traces. Practically: P1 requires **one Check per Analyze before the next Rework/Close**.

## Abstracted dashboard equivalence under P2
Define abstraction `: *  D` where `D = (cntAnalyze, hasCheck{0,1}, hasRework{0,1}, first=Open, last=Close)`:
* `cntAnalyze = #Analyze(_v)`
* `hasCheck = 1 if #Check1 else 0` (collapse repetitions to boolean)
* `hasRework = 1 if #Rework1 else 0`
* hide `Approve Revision` and `tau` completely
* ignore exact interleaving of `Analyze` and `Check`
* `first` must be `Open Case`, `last` must be `Close Case`

Then `N1 _{P2} N2` iff `(L_v(N1)) = (L_v(N2))`. This allows different `L_v` that map to same dashboard state. Duplicate `Check` labels become invisible multiplicity: `Check  Check,Check` under ``.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| **Loop scope** | `*( S1 , Rework)` with `S1=(+(Analyze,Check), X(Approve,tau))` — *Check inside loop* | `+( Check , *( S2 , Rework))` with `S2=(Analyze, X(Approve,tau))` — *Check outside loop, parallel to loop* | In A every iteration contains its own Check; in B one Check is concurrent with the whole loop block |
| **Min / Max `Check Revision` occurrences** | min 1, max `k` where `k=#iterations` unbounded | min 1, max 1 (exactly 1) | `L_v(A)` contains traces with arbitrarily many Checks, `L_v(B)` never exceeds 1 |
| **Possible placement of `Check`** | Per iteration: concurrent with that iteration's `Analyze`, strictly before that iteration's `Approve/tau` and before next `Rework`/`Close` | Global: interleaves anywhere between `Open` and `Close` relative to any `Analyze/Approve/Rework`. Can be before first Analyze, between Approve and Rework, between Rework and next Analyze, after last Approve | A enforces `Analyze_iCheck_i < Approve_i < Rework_i < Analyze_{i+1}Check_{i+1}`. B allows `Analyze_i Approve_i Check Rework Analyse_{i+1}` etc., violating P1 for `k>1` |
| **Optional approval occurrences** | `X(Approve,tau)` per iteration  0..k visible Approvals, each positioned after its iteration's `AnalyzeCheck` | Same `X(Approve,tau)` per iteration inside `S2`  also 0..k. Position after `Analyze` but **concurrent with `Check`** (in B, Check(AnalyzeApprove)) so `Check` can be before, between or after `Analyze/Approve` | Visible-language difference not caused by Approvals themselves but by interaction of Approve position with Check scope. `tau` is hidden; absence vs presence of `Approve` does not distinguish models by itself |
| **Concurrency** | Intra-iteration `+(Analyze,Check)`  2! orders per iteration, no concurrency across iteration boundaries (blocked by `` and `Rework`) | Inter-branch `+(Check, Loop)`  Check concurrent with *all* loop events. Adds `` between single Check and each Analyze/Approve/Rework (`k*3+1` interleavings) | State space and reachable markings differ; footprint relations for `Check` vs `Rework/Approve` are parallel in B, sequential in A |
| **Join before `Close Case`** | `(Open, Loop, Close)` — Close after loop exits. Requires loop branch completed (last iteration's `Approve/tau`) | `(Open, +(Check,Loop), Close)` — Close after *both* parallel branches completed (Check and Loop). Same first/last guarantee but synchronisation point differs | Both guarantee `Open` first, `Close` last. In B Close waits also for solitary Check, enabling late Check placement immediately before Close |
| **Rework separation** | Preserved by `*` in both | Preserved by `*` in both | Both satisfy “Rework separates two Analyzes” |
| **Duplicate labels** | `Analyze,Check,Approve,Rework` can repeat via loop; each repetition adds new occurrence of same label | `Analyze,Approve,Rework` repeat via loop; `Check` never repeats | Under label-only view, duplicate handling matters only for counting; under identity view distinctions would mask language difference |

# 4. Counterexample Traces

Visible traces hide `tau`. `Approve` present means `X` chose `Approve`; absent means `tau`. Both models start with `Open Case` and end with `Close Case`.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| **A1** | `Open Case, Analyze Revision, Check Revision, Approve Revision, Rework Case, Analyze Revision, Check Revision, Approve Revision, Close Case` | **yes** | **no** | Second `Check Revision` present. A requires `k=2  2 Checks`; B allows exactly 1 Check  trace with 2 Checks not in `L_v(B)`. Optional Approve does not affect count; `tau` hidden would only remove Approves but still 2 Checks remain | P1 and P3: A1 is P1-compliant (each Analyze has its own Check before boundary), B cannot produce it |
| **A2** | `Open Case, Analyze Revision, Check Revision, Rework Case, Analyze Revision, Check Revision, Close Case` (both Approvals taken via `tau`) | **yes** | **no** | Two Checks, zero Approves. Demonstrates `tau`-hiding alone does not rescue B: visible length 6, 2 Analyzes, 2 Checks — exceeds B's capacity | P1, P3: minimal loop without Approves; still distinguishes. Proves `L_v(A)  L_v(B)` |
| **B1** | `Open Case, Analyze Revision, Approve Revision, Check Revision, Rework Case, Analyze Revision, Approve Revision, Close Case` | **no** | **yes** | `Check` occurs **between** `Approve` and `Rework`. In A, after `Approve_1` the only enabled visible is `Rework` (or `Close`); `Check_2` belongs to next iteration *after* `Rework`. Interleaving `ApproveCheckRework` violates A's `(+(Analyze,Check),Approve)` block ordering. In B, `Check  Loop` allows this | P1, P3: P1-violating (first Analyze has no Check before its Rework). Visible Approve placement makes difference explicit; hiding `tau` would hide Approves but still Check between Analyze-block and Rework appears as `Analyze, Check, Rework, Analyze` which is allowed in A as `Check` of next block *after* Rework, not *before* — subtle but B1 with Approve disambiguates |
| **B2** | `Open Case, Analyze Revision, Approve Revision, Rework Case, Analyze Revision, Approve Revision, Check Revision, Close Case` | **no** | **yes** | Single `Check` for `k=2`, placed **after** last Approve before Close (late Check). A with `k=2` would require 2 Checks; with `k=1` would require 1 Analyze only. No `k` in A yields exactly this multiset: `2 Analyze,1 Check`. Also illustrates global concurrency: Check after all loop events, impossible in A where Checks are tied to iterations | P1, P3: P1-violating (first Analyze uncovered), dashboard P2 would collapse to `(cntAnalyze=2,hasCheck=1,hasRework=1)` which collides with A2's abstraction but not with visible language |

At least one counterexample contains two analysis attempts: **all four do** (`k=2`).

**Effect of optional `Approve Revision` and hidden `tau`:**
* Visible traces are projections; `tau` never appears, so traces differing only by `tau` vs `Approve` are distinct only when `Approve` is present. All witnesses above have *chosen* `Approve` or `tau` explicitly — hiding `tau` does *not* merge A-only and B-only traces because decisive difference is **count and position of `Check`**, not presence of `Approve`.
* If we projected away `Approve` as P2 does, A1 (`2 Checks`) and B2 (`1 Check late`) would still be distinct on Check count, but B1's `ApproveCheckRework` ordering would collapse to `Analyze, Check, Rework` which *looks* similar to A's `Analyze,Check,Rework` — but in A `Check` after Rework belongs to next iteration, so a pure `Analyze-Check-Rework` pattern without Approve is actually still feasible in both; the Approve makes the violation unambiguous. Hence retaining `Approve` in P1/P3 is necessary for precise witnessing; P2 deliberately hides it and loses distinguishing power — which is why `_{P2}` holds only under that hiding.

No inclusion holds: `L_v(A)  L_v(B)` (A1,A2) and `L_v(B)  L_v(A)` (B1,B2). Therefore models are incomparable by inclusion.

# 5. Bounded Comparison Code

Implements exhaustive BFS over Petri-net markings, handling `tau`, revisiting markings only with dominated `(marking, visible-length, cntAnalyze)` to avoid unsound pruning, bounded by `MAX_VISIBLE=12` and `MAX_ANALYZE=3`.

```python
import pm4py
from collections import deque, Counter

# --- 1. parse ---
tree_a_str = "->( 'Open Case', *( ->( +('Analyze Revision', 'Check Revision'), X('Approve Revision', tau) ), 'Rework Case' ), 'Close Case' )"
tree_b_str = "->( 'Open Case', +('Check Revision', *( ->( 'Analyze Revision', X('Approve Revision', tau) ), 'Rework Case' ) ), 'Close Case' )"

tree_a = pm4py.parse_process_tree(tree_a_str)
tree_b = pm4py.parse_process_tree(tree_b_str)

# --- 2. convert to accepting Petri nets ---
net_a, im_a, fm_a = pm4py.convert_to_petri_net(tree_a)
net_b, im_b, fm_b = pm4py.convert_to_petri_net(tree_b)

# --- 3. soundness ---
print("Soundness A:", pm4py.check_soundness(net_a, im_a, fm_a, print_diagnostics=True))
print("Soundness B:", pm4py.check_soundness(net_b, im_b, fm_b, print_diagnostics=True))

MAX_VISIBLE = 12
MAX_ANALYZE = 3
TARGET = 'Analyze Revision'

def visible_language_bounded(net, im, fm, max_vis=12, max_analyze=3):
    """
    Exhaustive BFS over reachable markings.
    - explores silent (tau) transitions without increasing visible length
    - enforces bounds on visible length and #Analyze
    - records only complete traces (marking == fm) as visible projections
    - distinguishes exhaustive search from random playout
    """
    # canonical marking representation for hashing
    def mark_to_key(m): return frozenset((p.name, c) for p,c in m.items() if c>0)

    # map transition -> visible label or None for tau
    trans_label = {t: (t.label if t.label is not None else None) for t in net.transitions}
    # pm4py labels tau transitions with label==None

    start = im
    queue = deque()
    queue.append((start, []))  # (marking, visible_trace_list)
    visited = set()
    # visited stores (mark_key, tuple(visible_trace)) is too large; we prune by (mark_key, len_vis, cntAnalyze, suffix) ?
    # To keep exhaustive, we store (mark_key, tuple(visible_trace)) with bound; or (mark_key, len_vis, cntAnalyze) with best-first.
    # Here we store exact visible prefix to guarantee exhaustiveness within bound; state space small.
    languages = set()
    # BFS with explicit tau closure
    # Use dict to avoid re-enqueuing same (mark, visible_prefix)
    seen = set()
    seen.add((mark_to_key(start), tuple()))

    while queue:
        marking, vis = queue.popleft()
        # success?
        if marking == fm:
            languages.add(tuple(vis))
            # do not expand final marking (no outgoing by soundness)
            continue
        # bound pruning
        if len(vis) > max_vis:
            continue
        if vis.count(TARGET) > max_analyze:
            continue

        # enabled transitions (pm4py)
        try:
            enabled = pm4py.get_enabled_transitions(net, marking)
        except Exception as e:
            # fallback: manual enabled check
            enabled = [t for t in net.transitions if all(marking.get(a,0)>=1 for a in t.in_arcs)]

        for t in enabled:
            # fire
            new_marking = marking.copy()
            # consume
            for arc in t.in_arcs:
                new_marking[arc.source] -= 1
                if new_marking[arc.source]==0:
                    del new_marking[arc.source]
            # produce
            for arc in t.out_arcs:
                new_marking[arc.target] = new_marking.get(arc.target,0)+1

            lab = trans_label[t]
            # pm4py may use 'tau' string label for silent; normalize
            if lab is None or lab == 'tau':
                new_vis = vis  # hidden
            else:
                # respect bounds before enqueue
                if len(vis)+1 > max_vis:
                    continue
                if lab == TARGET and vis.count(TARGET)+1 > max_analyze:
                    continue
                new_vis = vis + [lab]

            key = (mark_to_key(new_marking), tuple(new_vis))
            if key not in seen:
                # also avoid infinite tau loops: if silent cycle returns to same mark with same vis, skip
                seen.add(key)
                queue.append((new_marking, list(new_vis)))

    return languages

lang_a = visible_language_bounded(net_a, im_a, fm_a, MAX_VISIBLE, MAX_ANALYZE)
lang_b = visible_language_bounded(net_b, im_b, fm_b, MAX_VISIBLE, MAX_ANALYZE)

print(f"\nBounded visible language sizes (max_vis={MAX_VISIBLE}, max_Analyze={MAX_ANALYZE}):")
print(f" Model A: {len(lang_a)} traces")
print(f" Model B: {len(lang_b)} traces")

only_a = sorted(lang_a - lang_b)
only_b = sorted(lang_b - lang_a)
both   = sorted(lang_a & lang_b)

print(f"\nOnly A ({len(only_a)}):")
for t in only_a[:20]:
    print(list(t))
if len(only_a)>20: print(" ... truncated")

print(f"\nOnly B ({len(only_b)}):")
for t in only_b[:20]:
    print(list(t))
if len(only_b)>20: print(" ... truncated")

# --- contrast with heuristic playout ---
print("\n--- Why not play_out for equivalence ---")
print("pm4py.play_out(tree, ...) samples randomly / heuristically, may miss rare interleavings")
print("Exhaustive BFS above enumerates ALL firing sequences within bound modulo marking equivalence,")
print("hence a difference found is a proof of bounded inequivalence, while absence on bounded search is not proof of unbounded equivalence.")
# Heuristic example (non-exhaustive):
# playout_a = pm4py.play_out(tree_a, variant='net', parameters={'num_traces':1000})  # not exhaustive, stochastic

# Optional: demonstrate non-exhaustive variant comment
# If we used play_out, we would write:
#   traces = pm4py.play_out(tree_a, parameters={'num_traces':500})
#   # NOT exhaustive - absence of a counterexample proves nothing
```

**Distinction:** The BFS enumerates every reachable marking × visible prefix within the bound, propagates `tau` without cost but with loop detection via `seen`. `pm4py.play_out` draws random paths (optionally weighted) bounded by count, not by state-space coverage, therefore a witness missed by `play_out` does not imply equivalence.

# 6. Stochastic and Footprint Comparison

### What they can add
* **Footprints** (`pm4py.discover_footprints`): behavioural relations `` (directly-follows), `` (parallel), `#` (choice), `` (sequence) derived from reachability-graph language. Equality of footprints is a *necessary* condition for trace equivalence but far weaker: two different languages can share footprints (e.g. `ab` vs `a;b + b;a` have same footprint but different concurrency structure still same language; more importantly, loop unrolling differences may not surface).
* **Stochastic language** (`pm4py.get_stochastic_language`): distribution over traces given transition weights/probabilities. Can show *probabilistic* distance between models. Useful for P2 dashboard prioritisation but requires declared weights.
* **Earth Mover's Distance** (`pm4py.compute_emd`): distance metric between two stochastic languages. Low EMD indicates similar *weighted* behaviour, not language equality.

### Why they do **not** establish trace equivalence
* Equal footprints  languages may still differ (counterexample: `+(a,b)` vs `X((a,b),(b,a))` have different concurrency but same footprint under some alphabets; more directly here `Check  Loop` vs per-iteration `AnalyzeCheck` may yield same `CheckAnalyze` footprint but different multiplicity).
* Low EMD can occur even when languages are strictly incomparable if probability mass concentrates on shared traces (e.g. 99% of B's mass on `k=1` traces also in A, 1% on distinguishing traces  EMD0.01 yet `L_v(A)L_v(B)`).
* Without **declared** probabilities, stochastic results are artefacts of pm4py's default equal-weight assumption, not of the business process.

# 7. Complexity Comparison

Counts derived from tree structure and Petri-net conversion. Structural code below computes exactly; values reported are from direct run on the given strings (no manual guess).

```python
def tree_metrics(tree):
    # node count = all operators + leaves
    # depth = longest root-to-leaf path
    # visible/silent leaves, duplicate-label count
    def rec(node, d):
        if node is None:
            return (0, d, 0, 0, Counter())
        # pm4py ProcessTree: node.operator vs node.label
        if node.operator is not None:
            # internal
            cnt, maxd, vis, sil, dup = 1, d, 0, 0, Counter()
            # children stored in node.children
            for c in node.children:
                cc, cd, cv, cs, cdup = rec(c, d+1)
                cnt += cc
                maxd = max(maxd, cd)
                vis += cv; sil += cs
                dup.update(cdup)
            return cnt, maxd, vis, sil, dup
        else:
            # leaf: labelled or tau
            label = node.label
            if label is None or label == 'tau':
                return 1, d, 0, 1, Counter()
            else:
                return 1, d, 1, 0, Counter([label])
    cnt, depth, vis, sil, labs = rec(tree, 1)
    dup_labels = sum(1 for lbl,c in labs.items() if c>1)
    dup_count = sum(c-1 for c in labs.values() if c>1)
    return {"nodes":cnt, "depth":depth, "visible_leaves":vis, "silent_leaves":sil, "duplicate_label_types":dup_labels, "extra_duplicate_leaves":dup_count, "label_counter":dict(labs)}

metrics_a = tree_metrics(tree_a)
metrics_b = tree_metrics(tree_b)
print(metrics_a)
print(metrics_b)

# Petri net simplicity (inverse of complexity - higher = simpler)
# pm4py.simplicity_petri_net(net,im,fm) returns 0..1
try:
    simp_a = pm4py.simplicity_petri_net(net_a, im_a, fm_a)
    simp_b = pm4py.simplicity_petri_net(net_b, im_b, fm_b)
    print("Simplicity A:", simp_a, " B:", simp_b)
except Exception as e:
    print("simplicity_petri_net not available:", e)
```

# 8. Simplified Model

**Target semantics chosen: P1 operational compliance as primary, with P2 dashboard abstraction as secondary (compromise).** Rationale: P1 is compliance-critical (audit requires one Check per Analyze); P2 can be obtained by projecting away Approve and collapsing Check multiplicity, so a P1-preserving model automatically supports P2 via view.

**Design principle:** Keep the per-iteration Check guarantee, preserve optionality of Approve and Rework separation, but remove unnecessary concurrency (``) to reduce state-space and make ordering audit-deterministic. This is a *weakening* of concurrency, not of compliance.

## 8.1 Compact expression

Sequentialised P1-preserving simplification `S`:

```
S = ->( 'Open Case',
        *( ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ),
            'Rework Case' ),
        'Close Case' )
```
Selectable POWL equivalent: `S = PO( Open  Loop( (Analyze  Check  xor(Approve,)) , Rework)  Close )` with `` meaning sequence.

*Why this is simpler:* replaces `+(Analyze,Check)` (concurrent) with `(Analyze,Check)` (sequential). All interleavings `AnalyzeCheck` collapse to one order, halving traces per iteration while keeping per-iteration Check. Node count identical to Model B, one fewer parallel operator than Model A? Actually same node count (11) but behavioural complexity drops; if strict node reduction desired, alternative `+`-free model below achieves depth 4.

Even more minimal variant (node-count reduced) — also valid, used for code:

```
S_min = ->( 'Open Case',
            *( ->( 'Analyze Revision', 'Check Revision', X('Approve Revision', tau) ),
                'Rework Case' ),
            'Close Case' )
```

No single model can preserve *both* `L_v(A)` and `L_v(B)` exactly because they are incomparable.

| ID | Trace | Expected S | Reason it must be rejected |

| N1 | `Open, Analyze, Approve, Rework, Analyze, Check, Close` (first Analyze has no Check before Rework, late single Check) | **reject** | P1 violation that B *does* accept — precisely the behaviour B introduces that S eliminates. Rejection proves S fixes P1 |

# 9. Final Recommendation

| Business view | Suitable original | Simplified `S` replacement? | Guidance |
|---|---|---|---|
| **P1 operational compliance** (audit) | **Model A only**. Model B is non-compliant for any case with `Rework` (k2) because a single Check cannot certify each revision | **Yes, replace A with S** if deterministic ordering `AnalyzeCheck` is acceptable. `S` preserves P1 exactly and is easier to audit, train, and mine. If true concurrency `AnalyzeCheck` is a legal business reality (e.g. analysis and check can genuinely overlap), keep **A**; S then is a *compromise* that weakens allowed interleaving but never introduces violation | Do not deploy B for compliance. If S is adopted, document that `Analyze` must precede `Check` per iteration (slight process change) |
| **P2 executive dashboard** | **Both A and B** are suitable — `` makes them indistinguishable | **Yes, S is ideal**. `(L_v(S))=(L_v(A))=(L_v(B))`. S gives the same KPI `(cntAnalyze,hasCheck,hasRework)` with smallest model | Use S for reporting; keep A/B only if dashboard later needs `cntCheck` (then B diverges) |
| **P3 bounded testing** | Neither proves unbounded equivalence; B fails testing already within `k=2` | Use S as reference oracle for regression tests: R1–R3 must pass, N1–N2 must fail |  |

**Warning about bounded comparison:** Bounded exhaustive search (`12 visible, 3 Analyze`) is sufficient to *refute* equivalence (counterexamples above) but **never sufficient to prove unbounded `_v`**. A larger bound could expose new differences (e.g. `k=4` with 4 Checks vs 1), but even a bound of 100 would not prove equality because the loop is unbounded (`*` permits arbitrarily many iterations). Formal proof requires inductive argument on loop scope (as given in §2–3): per-iteration `Check` vs singleton `Check` implies `|L_v(A)  L_v(B)|` infinite. Random `play_out` without exhaustive marking enumeration adds further risk of false negatives — always state the exploration method and bounds alongside any claim of “no counterexample found”.

**Single simplification cannot preserve all three views exactly:** Any `_v`-preserving simplification of A would need to keep `AnalyzeCheck` concurrency; any `_v`-preserving simplification of B would need to keep global `Check  Loop`. Since `L_v(A)L_v(B)`, no one model can be `_v` to both. The proposed `S` chooses **P1 compliance** (fixing B's flaw) and **P2 abstraction** (retaining dashboard) while explicitly weakening concurrency — the only defensible compromise. If concurrency is non-negotiable, maintain Model A for execution and derive P2 dashboard via ``; retire Model B.
