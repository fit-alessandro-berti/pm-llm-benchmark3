# 1. Executive Verdict

The given Petri net is a structurally valid workflow net: it possesses a unique source place (`source`), a unique sink place (`sink`), and every node lies on a directed path from source to sink. However, the net is not sound.

The principal defect is an asymmetric synchronization failure on the waiver branch. While the silent split `t_split` forks execution concurrently into an analysis branch and a review branch, the silent transition `t_join_waived` consumes only `p_waived`, completely bypassing synchronization with the mandatory analysis branch (`p_analysis_done`).

Consequently, whenever a review waiver is recorded, `t_authorize` can fire prematurely before mandatory analysis executes. Once the sink place is marked, the unconsumed token in `p_analysis` or `p_analysis_done` remains permanently deadlocked. This violates proper completion and creates severe operational risk by allowing cases to be authorized without mandatory analysis.

# 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
| :--- | :--- | :--- | :--- |
| **Initial Marking & Source** (`source`, `im = [source: 1]`) | Initializes a single case instance with one token. | Dedicated source place ($\bullet \text{source} = \emptyset$). Properly holds 1 token initially. | None. Correctly initializes the workflow net. |
| **Registration Subnet** (`t_register`, `p_ready`) | Executes initial case registration and gates progress. | Sequential pipeline step ($\text{source} \to \text{register} \to \text{p\_ready}$). | None. Sequential control is well-formed. |
| **Parallel Split** (`t_split`, `p_ready \to t_split \to \{p\_analysis, p\_review\}`) | Concurrently forks control into mandatory analysis and review evaluation. | AND-split generating two concurrent tokens in parallel places. | Multi-token state requiring symmetric downstream synchronization. |
| **Analysis Branch** (`p_analysis \to t_analyze \to p_analysis_done`) | Performs mandatory case analysis. | Linear subnet operating concurrently with the review branch. | Unconsumed token if synchronization fails downstream. |
| **Review Choice Split** (`p_review \to \{t_standard_review, t_waive_review\}`) | Mutually exclusive XOR-choice between standard review and waiver. | Free-choice conflict at `p_review` resolving into either `p_review_done` or `p_waived`. | Correct mutually exclusive split. |
| **Standard Review Outcome** (`t_standard_review \to p_review_done`) | Records standard review completion. | Produces a token in `p_review_done`. | Proper token flow under normal review. |
| **Waiver Review Outcome** (`t_waive_review \to p_waived`) | Records formal waiver of review. | Produces a token in `p_waived`. | Leads to unsynchronized branch termination. |
| **Normal Join** (`t_join_normal`, preset $\{\text{p\_analysis\_done}, \text{p\_review\_done}\}$) | Synchronizes completed analysis with completed standard review. | 2-input AND-join depositing 1 token into `p_decision`. | Functions correctly when standard review is selected. |
| **Waived Join** (`t_join_waived`, preset $\{\text{p\_waived}\}$) | Modeler intended to route waiver outcome into decision. | 1-input transition depositing 1 token into `p_decision` without consuming `p_analysis_done`. | Asymmetric synchronization; bypass of analysis; orphaned token in analysis branch. |
| **Authorization & Sink** (`p_decision \to t_authorize \to sink`, `fm = [sink: 1]`) | Final case authorization and workflow termination. | Gated authorization transition producing a token in the sink place ($\text{sink} \bullet = \emptyset$). | Premature case authorization; terminal deadlock with leftover tokens. |

### Structural Path and Component Analysis

1. **Workflow Net Verification**:
   - **Source place condition**: The net has exactly one place with in-degree 0: $\bullet p = \emptyset \iff p = \text{source}$.
   - **Sink place condition**: The net has exactly one place with out-degree 0: $p \bullet = \emptyset \iff p = \text{sink}$.
   - **Path condition**: Every node $x \in P \cup T$ lies on a directed path from `source` to `sink`. For example:
     - Analysis subnet: $\text{source} \to \text{register} \to \text{p\_ready} \to \text{split} \to \text{p\_analysis} \to \text{analyze} \to \text{p\_analysis\_done} \to \text{join\_normal} \to \text{p\_decision} \to \text{authorize} \to \text{sink}$.
     - Standard review subnet: $\text{p\_ready} \to \text{split} \to \text{p\_review} \to \text{standard\_review} \to \text{p\_review\_done} \to \text{join\_normal} \to \text{p\_decision} \dots$
     - Waiver subnet: $\text{p\_ready} \to \text{split} \to \text{p\_review} \to \text{waive\_review} \to \text{p\_waived} \to \text{join\_waived} \to \text{p\_decision} \dots$
   - Therefore, the model structurally qualifies as a Workflow Net (WF-net).

2. **Structural Cause of Unsoundness (S-Component Defect)**:
   - For a workflow net to be sound, every place must be covered by at least one S-component (a strongly connected state-machine subnet in the short-circuited net where `sink` is connected back to `source`).
   - In this net, places `p_analysis` and `p_analysis_done` are **not covered by any S-component**. When execution traverses `t_waive_review` and `t_join_waived`, a token reaches `sink` by consuming only 1 token from the concurrent pair generated by `t_split`. The token in `p_analysis` / `p_analysis_done` cannot be routed into the short-circuit cycle, causing an irrecoverable structural token leak.

# 3. Marking-Based Counterexample

### Counterexample 1: Race Condition and Premature Authorization
This sequence proves that `t_authorize` can fire before `t_analyze` executes, leaving a dead token permanently stranded.

**Firing sequence $\sigma_1$**:
`t_register` $\to$ `t_split` $\to$ `t_waive_review` $\to$ `t_join_waived` $\to$ `t_authorize` $\to$ `t_analyze`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| :--- | :--- | :--- | :--- | :--- |
| **0** | *(initial)* | `[source: 1]` | `{'t_register'}` | Process instance initialized at `im`. |
| **1** | `t_register` | `[p_ready: 1]` | `{'t_split'}` | Case registered; ready for concurrent execution. |
| **2** | `t_split` | `[p_analysis: 1, p_review: 1]` | `{'t_analyze', 't_standard_review', 't_waive_review'}` | Concurrent fork: one token in `p_analysis`, one token in `p_review`. |
| **3** | `t_waive_review` | `[p_analysis: 1, p_waived: 1]` | `{'t_analyze', 't_join_waived'}` | Review waiver recorded. Because $\bullet t\_join\_waived = \{p\_waived\}$, `t_join_waived` is enabled without waiting for analysis. |
| **4** | `t_join_waived` | `[p_analysis: 1, p_decision: 1]` | `{'t_analyze', 't_authorize'}` | Token deposited in `p_decision`. `t_authorize` is now concurrently enabled before `t_analyze` has run. |
| **5** | `t_authorize` | `[p_analysis: 1, sink: 1]` | `{'t_analyze'}` | **Premature authorization.** Case is authorized before analysis even starts. A token exists in `sink`, but this is **not** the final marking `fm = [sink: 1]` because `p_analysis` holds 1 token. |
| **6** | `t_analyze` | `[p_analysis_done: 1, sink: 1]` | $\emptyset$ | Analysis executes after authorization. The net reaches a terminal deadlock with 2 tokens. |

### Counterexample 2: Analysis Executed Prior to Waiver Authorization
Even if `t_analyze` finishes before `t_authorize`, proper completion fails because the token in `p_analysis_done` is permanently orphaned.

**Firing sequence $\sigma_2$**:
`t_register` $\to$ `t_split` $\to$ `t_analyze` $\to$ `t_waive_review` $\to$ `t_join_waived` $\to$ `t_authorize`

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
| :--- | :--- | :--- | :--- | :--- |
| **0–2** | `t_register`, `t_split` | `[p_analysis: 1, p_review: 1]` | `{'t_analyze', 't_standard_review', 't_waive_review'}` | Parallel branches active. |
| **3** | `t_analyze` | `[p_analysis_done: 1, p_review: 1]` | `{'t_standard_review', 't_waive_review'}` | Analysis completes first; token resides in `p_analysis_done`. |
| **4** | `t_waive_review` | `[p_analysis_done: 1, p_waived: 1]` | `{'t_join_waived'}` | Waiver recorded. `t_join_normal` cannot fire because `p_review_done` is empty. |
| **5** | `t_join_waived` | `[p_analysis_done: 1, p_decision: 1]` | `{'t_authorize'}` | `p_decision` marked; token in `p_analysis_done` is ignored. |
| **6** | `t_authorize` | `[p_analysis_done: 1, sink: 1]` | $\emptyset$ | Case authorized. Marking contains `sink`, but $M_6 \neq fm$. Deadlock reached with leftover token in `p_analysis_done`. |

### Why Leftover Tokens Cannot Be Consumed
In the original net:
- The only output transition of `p_analysis_done` is `t_join_normal`.
- Its preset is $\bullet t\_join\_normal = \{\text{p\_analysis\_done}, \text{p\_review\_done}\}$.
- Because `t_waive_review` consumed `p_review`, no token can ever enter `p_review_done`.
- Consequently, `t_join_normal` can never be enabled.
- No other transition in the net has `p_analysis` or `p_analysis_done` in its preset.
- Therefore, any token entering the analysis branch during a waived review is permanently deadlocked. The marking `fm = [sink: 1]` is mathematically unreachable on the waiver path.

# 4. Minimal-Repair Alternatives

### Explicit Edit-Cost Model
Let a Petri net be $N = (P, T, F)$. The structural edit distance between original net $N_0 = (P_0, T_0, F_0)$ and repaired net $N_1 = (P_1, T_1, F_1)$ is defined as:
$$\text{Cost}(N_0 \to N_1) = |\Delta P_{\text{add}}| + |\Delta P_{\text{del}}| + |\Delta T_{\text{add}}| + |\Delta T_{\text{del}}| + |\Delta F_{\text{add}}| + |\Delta F_{\text{del}}|$$
where each structural element added or deleted incurs unit cost ($1$).

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Repair 1: Dual Two-Input Synchronization (Modeler Arc Completion)** | Add arc: `(p_analysis_done, t_join_waived)` | **1** (1 arc added, 0 deleted, 0 nodes modified) | Analysis remains strictly mandatory on all paths; authorization occurs only after analysis and waiver complete; exact `fm` reached cleanly. | `t_join_waived` cannot fire until `t_analyze` finishes, preventing premature authorization and token stranding. | Introduces asymmetric non-free-choice structure at `p_analysis_done` (two joins sharing an input). Safe here, but requires care during future extensions. |
| **Repair 2: Unified Synchronization via Outcome Rewiring (Free-Choice Refactoring)** | 1. Add arc: `(t_waive_review, p_review_done)`<br>2. Del arc: `(t_waive_review, p_waived)`<br>3. Del arc: `(p_waived, t_join_waived)`<br>4. Del arc: `(t_join_waived, p_decision)`<br>5. Del place: `p_waived`<br>6. Del trans: `t_join_waived` | **6** (1 arc added, 3 arcs deleted, 1 place deleted, 1 trans deleted) | Analysis remains strictly mandatory; authorization occurs only after analysis and review/waiver complete; exact `fm` reached cleanly. | Both review outcomes funnel into `p_review_done` (semantically "review evaluated"); eliminates redundant silent transition `t_join_waived`. | `p_review_done` does not structurally segregate waiver tokens, but visible labels (`Record Review Waiver` vs `Perform Standard Review`) fully preserve auditability in event logs. |
| **Repair 3: Policy Change – Sequential Waiver Bypass (Optional Analysis)** | 1. Del trans: `t_split`<br>2. Del places: `p_analysis`, `p_review`, `p_analysis_done`, `p_review_done`, `p_waived`<br>3. Del trans: `t_join_normal`, `t_join_waived`<br>4. Rewire registration to review choice; standard review leads to analysis; waiver connects directly to `p_decision`. | **$\ge 12$** (Multiple node and arc additions/deletions) | Sound workflow net reaching `fm` without leftover tokens. | **Violates business policy.** Analysis is no longer mandatory; waived cases skip analysis completely. | High governance/compliance risk: cases are authorized without mandatory analysis. |

### Justification of Minimality
- Under the explicit edit-cost model, repairing an unsound net requires at least one structural change ($\text{Cost} \ge 1$). 
- **Repair 1** requires adding exactly one directed arc from `p_analysis_done` to `t_join_waived` ($\text{Cost} = 1$). Because no non-zero integer is less than 1, Repair 1 is **provably the global minimal structural repair**. It directly restores the missing synchronization arc that the original modeler omitted when creating `t_join_waived`.
- **Repair 2** has an edit cost of 6, but is minimal with respect to structural complexity: it eliminates redundant silent transitions and produces a strictly Free-Choice Workflow Net.

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

# Places
source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in {
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
}:
    repaired_net.places.add(p)

# Transitions
register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
join_waived = PetriNet.Transition("t_join_waived", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in {
    register, split, analyze, standard_review, waive_review,
    join_normal, join_waived, authorize
}:
    repaired_net.transitions.add(t)

# Arcs: Registration and parallel fork
petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

# Arcs: Mandatory analysis branch
petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

# Arcs: Mutually exclusive review outcomes
petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)
petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

# Arcs: Standard review synchronization
petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)

# Arcs: Waiver synchronization (REPAIR: synchronize mandatory analysis with waiver)
petri_utils.add_arc_from_to(p_waived, join_waived, repaired_net)
petri_utils.add_arc_from_to(p_analysis_done, join_waived, repaired_net)
petri_utils.add_arc_from_to(join_waived, p_decision, repaired_net)

# Arcs: Case authorization to sink
petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

# Markings
repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

# 6. Diagnostic and Reachability Code

```python
import pm4py
from pm4py.objects.petri_net.obj import Marking

# Helper to fire a named transition with strict enabledness checking
def fire_transition_traced(curr_net, curr_marking, transition_name):
    t = next((tr for tr in curr_net.transitions if tr.name == transition_name), None)
    if t is None:
        raise ValueError(f"Transition '{transition_name}' does not exist in net.")
    enabled_transitions = pm4py.get_enabled_transitions(curr_net, curr_marking)
    if t not in enabled_transitions:
        enabled_names = sorted([tr.name for tr in enabled_transitions])
        marking_str = {p.name: v for p, v in curr_marking.items()}
        raise ValueError(
            f"Cannot fire '{transition_name}': not enabled at marking {marking_str}. "
            f"Currently enabled: {enabled_names}"
        )
    new_marking = Marking(curr_marking)
    for arc in t.in_arcs:
        new_marking[arc.source] -= arc.weight
        if new_marking[arc.source] == 0:
            del new_marking[arc.source]
    for arc in t.out_arcs:
        new_marking[arc.target] = new_marking.get(arc.target, 0) + arc.weight
    return new_marking

def fmt_m(m):
    return "{" + ", ".join(f"{p.name}: {v}" for p, v in sorted(m.items(), key=lambda x: x[0].name)) + "}"

# 1. Structural workflow net checks
```

# 7. Repair Trade-Offs and Residual Risks

### 1. Distinguishability of Waiver and Standard Review
In both proposed repairs, waivers and standard reviews remain fully distinguishable:
- In **Repair 1**, distinguishability exists both in state markings (`p_waived` vs `p_review_done`) and in the observable transition labels (`Record Review Waiver` vs `Perform Standard Review`).
- In **Repair 2**, the places merge into `p_review_done`, but distinguishability is completely preserved in the event log because the visible activity labels remain distinct. Process mining and audit logging rely on activity labels, ensuring full traceability.

### 2. Silent Transitions and Potential Confusion
- In **Repair 1**, `t_join_normal` and `t_join_waived` are silent transitions sharing an input place (`p_analysis_done`). This creates an asymmetric non-free-choice structure. However, it introduces **no runtime confusion or race condition** because their other input places (`p_review_done` and `p_waived`) are mutually exclusive by virtue of the upstream XOR-split at `p_review`. At most one join transition is ever enabled in any single execution.
- In **Repair 2**, `t_join_waived` is deleted entirely. The net becomes an ordinary Free-Choice Workflow Net with zero structural confusion.

### 3. Soundness Alone vs Business Rule Alignment
Soundness is strictly a structural and behavioral liveness property of Petri nets (absence of deadlocks, absence of token leaks, reachability of `fm`). **Soundness alone does not prove alignment with domain business rules.** For instance:
- A model where `Record Review Waiver` skips `Perform Analysis` (Repair 3) is structurally sound, yet directly violates the business rule that analysis is mandatory.
- A model that authorized a case immediately upon registration would be sound, yet commercially catastrophic.
Conformance checking against declarative business rules (e.g., LTL/Declare constraints: `Mandatory(Perform Analysis)` and `Precedence(Perform Analysis, Authorize Case)`) is required in addition to soundness.

### 4. Regression Test Suites (Positive and Negative Traces)
The following execution traces must be verified:

**Positive Traces (Must complete cleanly at `fm` with zero residual tokens)**:
1. Standard review with analysis first:  
   $\langle \text{Register Case}, \text{Perform Analysis}, \text{Perform Standard Review}, \text{Authorize Case} \rangle$
2. Standard review with review first:  
   $\langle \text{Register Case}, \text{Perform Standard Review}, \text{Perform Analysis}, \text{Authorize Case} \rangle$
3. Waived review with analysis first:  
   $\langle \text{Register Case}, \text{Perform Analysis}, \text{Record Review Waiver}, \text{Authorize Case} \rangle$
4. Waived review with waiver first:  
   $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Perform Analysis}, \text{Authorize Case} \rangle$

**Negative Traces (Must be rejected, unreplayable, or blocked prior to `Authorize Case`)**:
1. Premature authorization bypassing analysis under waiver:  
   $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Authorize Case} \rangle$
2. Out-of-order analysis following authorization:  
   $\langle \text{Register Case}, \text{Record Review Waiver}, \text{Authorize Case}, \text{Perform Analysis} \rangle$
3. Complete bypass of review/waiver branch:  
   $\langle \text{Register Case}, \text{Perform Analysis}, \text{Authorize Case} \rangle$
4. Duplicate review evaluations:  
   $\langle \text{Register Case}, \text{Perform Standard Review}, \text{Record Review Waiver}, \dots \rangle$

### 5. Detecting Accidental Bypass of Mandatory Analysis in Production
To guarantee compliance in production:
1. **Declare / LTL Temporal Logic Monitoring**: Enforce the rule `Precedence(Perform Analysis, Authorize Case)` on streaming event logs. Any case where `Authorize Case` occurs without a prior `Perform Analysis` event triggers an immediate alert.
2. **Alignment-Based Conformance Checking**: Replay logs against the repaired net using PM4Py token-based replay or alignment algorithms. Traces attempting to skip analysis will produce model moves on `Perform Analysis` and trace fitness $< 1.0$.
3. **Database Guard Constraints**: At the application layer, make the case authorization API transactional, asserting that `case.analysis_id IS NOT NULL` before committing authorization.

# 8. Final Recommendation

For production deployment, I recommend **Repair 2 (Unified Synchronization via Outcome Rewiring)**. Although its graph edit cost (6) exceeds that of Repair 1, it represents superior architectural design. By routing `Record Review Waiver` directly into `p_review_done` and removing the redundant silent transition `t_join_waived` and place `p_waived`, Repair 2 transforms the model into an Ordinary Free-Choice Workflow Net.
