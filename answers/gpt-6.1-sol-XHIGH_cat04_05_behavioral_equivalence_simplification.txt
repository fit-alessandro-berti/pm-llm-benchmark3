# 1. Equivalence Notions

Let `O` = Open Case, `A` = Analyze Revision, `C` = Check Revision, `P` = Approve Revision, `R` = Rework Case, and `Z` = Close Case. These abbreviations denote visible labels, not transition identities. A trace is complete only when execution reaches the accepting final marking.

For a model `M`, let `L(M)` be its complete visible language after deleting every silent `tau` event. Parallel composition permits all order-preserving interleavings of its children. The binary loop executes its first child at least once, with its second child between successive executions of the first.

Repeated visible labels are distinguished by their positions in the trace: `A C R A C` contains two analyses and two checks. Transition or event identities are not observed. Thus different execution paths producing the same label word contribute one trace to a language set. There are no duplicated visible labels among the syntactic leaves of either tree; repetition arises from the loop.

- **Visible trace equivalence:** `M1 ≡vis M2` iff `L(M1) = L(M2)`. Hiding `tau` removes silent events; it does not remove approvals or merge repeated checks.
- **P3 bounded visible-language equivalence:** define `L12,3(M) = {t ∈ L(M) : |t| ≤ 12 and count_A(t) ≤ 3}`. The models are bounded equivalent iff these sets are equal. Both endpoint events and every approval count toward the visible-length bound.
- **P1 business-relevant equivalence:** split each complete trace at `R` into ordered revision blocks, retaining the event order within each block, the boundaries, and every approval. Call this observation `β1(t)`. Require equality of the resulting observation sets. This conservative operational observation is lossless for these traces, so it coincides with visible trace equivalence here. Separately, compliance requires a distinct check in each analysis block before its ending `R` or `Z`. A check may precede its analysis within a block under the stated parallel semantics; it cannot serve two blocks. Approval omission is permitted, but approval count and placement remain observable. Even a coarser operational comparison retaining only per-attempt check coverage would distinguish the models.
- **P2 dashboard equivalence:** for these complete case traces, define `α2(t) = (first(t), last(t), count_A(t), count_C(t) > 0, count_R(t) > 0)`. Interior analysis/check ordering, check multiplicity, approval events, and silent behavior are discarded. Equivalence means equality of the images `{α2(t) : t ∈ L(M)}`, together with the required first/last and existence conditions. This compares possible dashboard records, not their probabilities.

A useful exact characterization is:

```text
L(A) = { O u1 R u2 ... R un Z : n >= 1,
         each ui is one of AC, CA, ACP, CAP }

L(B) = { O w Z : n >= 1,
         w is an interleaving of the single C with
         v1 R v2 ... R vn,
         each vi is A or AP }
```

In both models there are `n` analyses and `n−1` reworks. Model A has `n` checks; Model B has exactly one. These characterizations follow directly from the mandatory first loop execution, the optional approval choice, and the scope of the parallel operator.

# 2. Structural Comparison

| Feature | Model A | Model B | Semantic consequence |
|---|---|---|---|
| Loop scope | The repeated body contains parallel analysis/check and then optional approval. | The repeated body contains analysis and optional approval; the check is outside the loop. | A repeats a check for every attempt; B repeats only analysis/approval. |
| Minimum Check Revision occurrences | One. | One. | Neither complete language permits a case without a check. |
| Maximum Check Revision occurrences | Unbounded; exactly `n` for `n` analyses. | Exactly one, regardless of `n`. | Every A trace with two or more attempts is excluded by B. |
| Possible placement of Check Revision | Before or after its paired analysis, within the same revision block; before that block's approval and before its next rework or final close. | At any insertion point in the entire analysis/approval/rework sequence, including before all attempts, after all attempts, or between an analysis and its approval. | B allows rework before the case's check and allows approval before the check. |
| Optional approval occurrences | Zero through `n`; at most one per attempt, after both its analysis and its check. | Zero through `n`; at most one per attempt, after its analysis, with no requirement to wait for the global check. | Equal approval-count ranges do not imply equal approval placement. |
| Concurrency | Analysis and check run concurrently within each attempt. Their join precedes the approval choice. | One check runs concurrently with the entire revision loop. | The synchronization boundary moves from each attempt to the whole case. |
| Rework boundaries | Exactly `n−1`; each occurs after the preceding attempt's check and approval choice. | Exactly `n−1`; each occurs after the preceding analysis and approval choice, possibly before the global check. | R separates attempts in both models, but B provides no per-attempt check barrier. |
| Join before Close Case | Each iteration has already joined analysis/check; close follows loop exit. | The outer parallel join waits for both loop exit and the single check. | Both require a check before closing; only A requires checks before every rework boundary. |

# 3. Verdicts

| View | Verdict | Confidence | Decisive reason | Caveat |
|---|---|---|---|---|
| P1 operational compliance | not equivalent | High; explicit witnesses and an unbounded counting argument. | A checks every revision block. For `n ≥ 2`, B has only one check for `n` blocks and necessarily leaves at least one unchecked. B also permits approval before its check. | The approval-order difference matters under the declared operational observation; P1's explicit check-coverage condition alone already establishes the failure. |
| P2 executive dashboard | equivalent only under stated abstraction | High; exact equality of abstract language images. | Both produce precisely `(O, Z, n, True, n > 1)` for every integer `n ≥ 1`. | Check multiplicity, approval behavior, and interleaving must actually be discarded. Dashboard-record probabilities are not compared. |
| P3 bounded testing | not equivalent | High; bounded witnesses and exhaustive exploration. | There are bounded traces unique to each model, including traces with two attempts. The sets contain 76 and 85 traces, respectively, with only four shared. | These counts concern the specified bounds. A positive bounded result would not prove unbounded equivalence. |

For P2, necessity follows from the mandatory analysis body, the mandatory check, and the identity `count_R = count_A − 1`. Sufficiency follows by choosing any desired iteration count `n` and omitting every approval. Therefore the dashboard equivalence holds for all iteration counts, independently of bounded testing.

# 4. Counterexample Traces

All words below include opening and closing. Their abbreviations expand to the full labels defined in Section 1. Every witness has at most 12 visible events and at most three analyses.

| Trace ID | Trace | Model A | Model B | First decisive semantic difference | Relevant view |
|---|---|---|---|---|---|
| A1 | `O A C R A C Z` | Admitted. | Rejected. | The second `C` requires B's single check to execute again. | P1, P3; P2 maps this to the same two-attempt record as B2/B3. |
| A2 | `O C A P R C A P Z` | Admitted. | Rejected. | The second `C` is impossible in B. Both approvals correctly follow their local analysis/check joins in A. | P1, P3; approvals and repeated checks are hidden by P2. |
| B1 | `O A P C Z` | Rejected. | Admitted. | At `P`, A's first analysis/check join has not completed because no `C` has occurred. | P1's retained approval placement, P3; P2 hides this distinction. |
| B2 | `O C A R A Z` | Rejected. | Admitted. | At `Z`, A's second revision block lacks its required check. B's global check has already completed. | P1 check coverage, P3; P2 retains only two analyses and the presence of rework/check. |
| B3 | `O A R A C Z` | Rejected. | Admitted. | The first `R` arrives before A's first attempt has received its check. | P1 check coverage, P3; P2 hides the late check placement. |

The shortest A-only words have two attempts and length seven. B1 is a shortest B-only word, of length five. Neither visible-language inclusion holds.

Approvals are optional through `X(P, tau)`. Choosing `tau` omits an approval without adding a visible event. It neither supplies a check nor relaxes a synchronization barrier. Thus A1, B2, and B3 remain counterexamples even if approvals are hidden entirely. Retaining approvals exposes the additional ordering witness B1. For one analysis and no approval, both models allow `O A C Z` and `O C A Z`; with approval, both allow `O A C P Z` and `O C A P Z`, but only B allows `O A P C Z`.

# 5. Bounded Comparison Code

The following is a self-contained PM4Py program. It exhaustively explores the accepting nets within P3's bounds; it performs no random playout. A silent transition is identified by `transition.label is None`.

```python
from collections import deque
import pm4py
from pm4py.objects.petri_net import semantics

TREE_STRINGS = {
    "A": """->(
        'Open Case',
        *(
            ->(
                +('Analyze Revision', 'Check Revision'),
                X('Approve Revision', tau)
            ),
            'Rework Case'
        ),
        'Close Case'
    )""",
    "B": """->(
        'Open Case',
        +(
            'Check Revision',
            *(
                ->(
                    'Analyze Revision',
                    X('Approve Revision', tau)
                ),
                'Rework Case'
            )
        ),
        'Close Case'
    )""",
}


def bounded_visible_language(net, im, fm, max_visible=12, max_analyzes=3):
    # Fix an order once; place object identities are internal to this net.
    places = tuple(net.places)

    def marking_key(marking):
        # Include ALL places and their token counts. Missing keys mean zero.
        return tuple(marking.get(place, 0) for place in places)

    final_key = marking_key(fm)
    queue = deque([(im, (), 0)])
    seen = {(marking_key(im), ())}
    accepted = set()

    while queue:
        marking, word, analyzes = queue.popleft()

        # Exact final-token vector, not merely a token in the sink place.
        if marking_key(marking) == final_key:
            accepted.add(word)
            continue

        for transition in pm4py.get_enabled_transitions(net, marking):
            label = transition.label
            if label is None:
                next_word = word
                next_analyzes = analyzes
            else:
                if len(word) >= max_visible:
                    continue
                next_analyzes = analyzes + int(label == "Analyze Revision")
                if next_analyzes > max_analyzes:
                    continue
                next_word = word + (label,)

            next_marking = semantics.execute(transition, net, marking)
            if next_marking is None:
                raise RuntimeError("An enabled transition could not fire")

            # A marking alone is insufficient: different visible histories
            # reaching it can yield different complete words.
            state = (marking_key(next_marking), next_word)
            if state not in seen:
                seen.add(state)
                queue.append((next_marking, next_word, next_analyzes))

    return accepted


def print_words(title, words):
    print(title, len(words))
    for word in sorted(words, key=lambda w: (len(w), w)):
        print("  " + " -> ".join(word))


trees = {}
nets = {}
bounded_languages = {}
for name, source in TREE_STRINGS.items():
    tree = pm4py.parse_process_tree(source)
    net, im, fm = pm4py.convert_to_petri_net(tree)
    result = pm4py.check_soundness(net, im, fm, print_diagnostics=True)
    sound = result[0] if isinstance(result, tuple) else result
    print(name, "sound:", sound)
    if not sound:
        raise RuntimeError(f"{name} failed soundness checking")
    trees[name] = tree
    nets[name] = (net, im, fm)
    bounded_languages[name] = bounded_visible_language(net, im, fm)

LA = bounded_languages["A"]
LB = bounded_languages["B"]
print("EXHAUSTIVE bounded exploration: <=12 visible events, <=3 analyses")
print("A:", len(LA), "B:", len(LB), "shared:", len(LA & LB))
print("Bounded equivalent:", LA == LB)
print_words("Unique to A:", LA - LB)
print_words("Unique to B:", LB - LA)
```

The exploration retains silent moves even after reaching the visible-length limit, so silent completion at length 12 remains possible. Repeated `(marking, visible word)` states are merged, including silent cycles; the analysis counter need not appear in the key because it is determined by the word. Different histories at the same marking are preserved. Exact final-marking equality excludes incomplete prefixes and markings with residual tokens.

These sound workflow nets are bounded and have finitely many reachable markings. Combined with the finite visible-word bound, this gives a finite search. The same algorithm need not terminate on an arbitrary net with unbounded silent token production. Within this setting, induction over firing sequences establishes completeness: every allowed visible extension and every silent extension is explored unless an identical state has already been explored. Conversely, every accepted word has a firing sequence to the exact final marking.

Both converted nets pass the soundness check. The bounded counts can also be derived independently:

- A trace with `n` analyses and `k` approvals has length `3n + 1 + k`. There are `2^n × binomial(n, k)` such words: choose the analysis/check order in each attempt and choose which attempts have approvals. For `n = 1, 2, 3`, the bounded counts are `4, 16, 56`; the last excludes the eight length-13 words with three approvals.
- B has length `2n + 2 + k`. For each of the `binomial(n, k)` approval selections, its analysis/rework/approval skeleton has `2n − 1 + k` events. The single check has `2n + k` insertion positions. All words for `n ≤ 3` fit the length bound, giving `5, 20, 60` words.
- Shared words must have `n = 1`, because equality of check counts requires `n = 1`. The four shared words are the one-attempt A words listed in Section 4.

Therefore `|LA| = 76`, `|LB| = 85`, `|LA ∩ LB| = 4`, `|LA − LB| = 72`, and `|LB − LA| = 81`.

Random or heuristic `pm4py.play_out(...)` could find witnesses but would not enumerate the bounded language: it can omit possible interleavings, approval choices, or loop counts. Failure to find a counterexample by sampling is not an equivalence result.

# 6. Stochastic and Footprint Comparison

Footprints summarize activities and ordering relations. They can expose an ordering change without preserving the complete language. The following extends the program in Section 5:

```python
footprints = {
    name: pm4py.discover_footprints(tree)
    for name, tree in trees.items()
}
for name, footprint in footprints.items():
    print(name, "activities:", sorted(footprint.get("activities", set())))
    print(name, "sequence:", sorted(footprint.get("sequence", set())))
    print(name, "parallel:", sorted(footprint.get("parallel", set())))
print("Identical footprint dictionaries:", footprints["A"] == footprints["B"])
```

For these trees, PM4Py 2.7.23.4 reports different footprints: A includes `(Check Revision, Approve Revision)` in its sequence relation, whereas B includes the two directional check/approval pairs in its parallel relation. This supports the ordering difference witnessed by B1. Both have the same activity set. A footprint's bidirectional relation can also arise from loop ordering; it should not automatically be interpreted as physical simultaneous execution.

Even equal footprints would not establish trace equivalence. They discard important information about multiplicity, the synchronization of each iteration, and correlations across longer words.

A stochastic language maps complete label words to probabilities. These nondeterministic process trees do not specify business probabilities for loop continuation, approval choice, or scheduling. Probabilities must come from observations or an explicitly declared stochastic policy.

For a reproducible comparison that introduces no transition probabilities, the next code deliberately assigns equal mass to every distinct P3 trace by creating a synthetic log with one occurrence of each word. This is a **uniform distribution over the bounded language**, not an estimate of actual case frequencies. It also extends Section 5.

```python
from pm4py.objects.log.obj import EventLog, Trace, Event


def one_case_per_word(words):
    log = EventLog()
    for word in sorted(words):
        trace = Trace()
        for label in word:
            trace.append(Event({"concept:name": label}))
        log.append(trace)
    return log


stochastic_languages = {
    name: pm4py.get_stochastic_language(one_case_per_word(words))
    for name, words in bounded_languages.items()
}
for name, language in stochastic_languages.items():
    print(name, "support:", len(language), "total mass:", sum(language.values()))

emd = pm4py.compute_emd(
    stochastic_languages["A"], stochastic_languages["B"]
)
print("EMD under the declared uniform bounded distributions:", emd)
```

With PM4Py 2.7.23.4 and its default distance, this calculation gives approximately `0.182161`. Its meaning depends on both the synthetic weighting and the distance between traces. Empirical logs could instead supply observed frequencies, but rare allowed behaviors might never occur in a sample.

A low Earth Mover's Distance measures similarity of weighted distributions under a chosen transport cost; it does not require equality of trace supports. A single rare counterexample can disprove equivalence while contributing little distance. Even zero distance for sampled or bounded distributions would say nothing about unobserved unbounded behavior. Zero distance under a separating metric for exact full distributions would establish equality of those distributions, but such full distributions have not been specified or computed here.

# 7. Complexity Comparison

Count every operator and leaf as one process-tree node. Depth is the longest root-to-leaf path in **edges**; a single leaf has depth zero. A duplicate-label count is the number of visible leaf occurrences beyond the first syntactic occurrence of each label.

| Structural measure | Model A | Model B |
|---|---:|---:|
| Operator nodes | 5 | 5 |
| Visible leaves | 6 | 6 |
| Silent leaves | 1 | 1 |
| Total process-tree nodes | 12 | 12 |
| Depth in edges | 4 | 5 |
| Duplicate visible leaf occurrences | 0 | 0 |

Both trees contain two sequence operators, one parallel operator, one exclusive-choice operator, and one loop operator: five operators plus seven leaves gives twelve nodes. A's deepest path is root sequence → loop → body sequence → parallel/choice → leaf, giving four edges. B's is root sequence → parallel → loop → body sequence → choice → leaf, giving five.

The following extends Section 5 and computes the counts rather than estimating them from a picture:

```python
from collections import Counter


def structural_counts(tree):
    label_counts = Counter()

    def visit(node):
        children = list(node.children)
        if not children:
            if node.label is None:
                return 1, 0, 1  # nodes, depth, silent leaves
            label_counts[node.label] += 1
            return 1, 0, 0
        child_stats = [visit(child) for child in children]
        return (
            1 + sum(s[0] for s in child_stats),
            1 + max(s[1] for s in child_stats),
            sum(s[2] for s in child_stats),
        )

    nodes, depth, silent = visit(tree)
    visible = sum(label_counts.values())
    return {
        "nodes": nodes,
        "depth_edges": depth,
        "visible_leaves": visible,
        "silent_leaves": silent,
        "operator_nodes": nodes - visible - silent,
        "duplicate_visible_leaves": sum(n - 1 for n in label_counts.values()),
    }


for name, tree in trees.items():
    print(name, structural_counts(tree))
    net, im, fm = nets[name]
    print(name, "places:", len(net.places),
          "transitions:", len(net.transitions), "arcs:", len(net.arcs))
    print(name, "simplicity:", pm4py.simplicity_petri_net(net, im, fm))
```

The local PM4Py 2.7.23.4 conversion and default simplicity metric produce:

| Converted-net measure | Model A | Model B |
|---|---:|---:|
| Places | 9 | 7 |
| Transitions, including silent transitions | 9 | 7 |
| Arcs | 20 | 16 |
| Default simplicity, higher is simpler | `9/11 ≈ 0.818182` | `7/9 ≈ 0.777778` |

For the default arc-degree measure with baseline two, `d = 2 × arcs / (places + transitions)` and `simplicity = 1 / (1 + max(d − 2, 0))`. A has `d = 40/18 = 20/9`, yielding `9/11`; B has `d = 32/14 = 16/7`, yielding `7/9`. Thus B's converted net has fewer nodes, yet a lower score under this metric because its mean degree is higher. Conversion details and metric defaults can vary by version, so these scores should be recomputed with the supplied code. Neither a smaller tree nor a simpler net establishes behavioral equivalence.

# 8. Simplified Model

Choose **P2's dashboard observation** as the simplification target. It permits a substantial reduction and has an exact abstraction-level preservation proof. Operational execution should continue to use A when P1 is required.

Use the following model S, with a single check after the analysis/rework loop and approvals omitted:

```text
->(
  'Open Case',
  *('Analyze Revision', 'Rework Case'),
  'Check Revision',
  'Close Case'
)
```

Self-contained construction and soundness checking:

```python
import pm4py

simplified_model = pm4py.parse_process_tree("""->(
    'Open Case',
    *('Analyze Revision', 'Rework Case'),
    'Check Revision',
    'Close Case'
)""")

simplified_net, simplified_im, simplified_fm = pm4py.convert_to_petri_net(
    simplified_model
)
result = pm4py.check_soundness(
    simplified_net, simplified_im, simplified_fm, print_diagnostics=True
)
sound = result[0] if isinstance(result, tuple) else result
if not sound:
    raise RuntimeError("Simplified model failed soundness checking")
print("Simplified-net simplicity:", pm4py.simplicity_petri_net(
    simplified_net, simplified_im, simplified_fm
))
```

Its exact visible language is `L(S) = {O A (R A)^(n−1) C Z : n ≥ 1}`. For every `n`, S yields the dashboard record `(O, Z, n, True, n > 1)`. Conversely, every dashboard record of A or B has this form and has an S representative. Hence `α2(L(S)) = α2(L(A)) = α2(L(B))` without any iteration bound.

S has two operators, five visible leaves, no silent leaves, seven nodes, depth two, and no duplicated visible leaves. The operators are the root sequence and the loop; `2 + 5 = 7` nodes, and root sequence → loop → leaf gives depth two. Compared with both originals, it removes five nodes and two leaves, and lowers depth from four/five to two. It also removes parallel composition and the approval choice.

With the same local conversion used in Section 7, S produces five places, five transitions, and ten arcs. Its mean degree is `20/10 = 2`, giving default simplicity `1`. Thus it is smaller than both originals in tree size and converted-net size, and higher under the tested simplicity metric.

| Property | Preservation status in S | Explanation |
|---|---|---|
| Open first; Close last | Exact for A and B. | Both remain mandatory endpoint events. |
| At least one analysis | Exact for A and B. | The loop's first child executes once before any exit. |
| Possible analysis counts | Exact for A and B. | Every positive integer `n` remains possible. |
| Rework count and dashboard flag | Exact for A and B. | Still `n−1` reworks; the flag is true exactly when `n > 1`. |
| Presence of a check | Exact for A and B. | A check occurs in every complete S trace. |
| Check multiplicity | Abstracted relative to A; exact relative to B. | S has one check; P2 retains only its existence. |
| Approval counts and placement | Abstracted under P2; lost as visible behavior. | S generates no approvals, whereas both originals can. |
| Analysis/check interleavings | Abstracted under P2; restricted in the visible language. | S selects the representative with the check after all attempts. |
| Per-attempt check coverage under P1 | Weakened relative to A; lost for `n ≥ 2`. | Earlier attempts reach rework before S's sole check. B already lacks this guarantee. |
| P3 visible language | Lost relative to both originals. | S has only three P3 traces; A and B have 76 and 85. |
| Workflow soundness | Exact property for all three. | S still permits proper completion and passes the soundness check. |

The following are regression traces for S. They also represent the complete set of its P3 traces, because S has one word for each of the three permitted analysis counts.

| Test | Complete trace | Expected result | Property exercised |
|---|---|---|---|
| Regression 1 | `O A C Z` | Accept. | Mandatory first attempt and a final check. |
| Regression 2 | `O A R A C Z` | Accept. | Two attempts and the true rework flag. |
| Regression 3 | `O A R A R A C Z` | Accept. | Three attempts with exactly two reworks. |
| Negative 1 | `O A R C Z` | Reject. | Rework must be followed by another analysis before loop exit. |
| Negative 2 | `O A R A Z` | Reject. | A case cannot close without a check. |
| Negative 3 | `O C Z` | Reject. | At least one analysis is mandatory. |

For abstraction-level regression, A's `O C A P R C A P Z` and B's `O C A R A Z` both map to the same dashboard record as Regression 2. S need not admit either original word to preserve that record. Indeed, `L(S) ⊆ L(B)` because B can omit approvals and schedule its check last; S is a strict visible-language restriction of B. S and A are not related by that inclusion for multiple attempts, since their check counts differ.

# 9. Final Recommendation

Use Model A for P1 operational compliance. Its loop contains the per-attempt check barrier, and its approvals retain the declared operational placement. Model B is unsuitable for P1 whenever rework is possible.

For P2, either original is suitable as a generator of dashboard records, and S can replace either as a dashboard-level model. Its seven-node structure preserves exactly the specified abstract records. Keep S scoped to that purpose: it cannot replace A for operational compliance or preserve either original's visible approval behavior.

For P3, both originals are legitimate subjects of testing, but they are demonstrably different specifications. If tests are intended to validate the P1 workflow, use A as the reference; B and S fail that reference. S cannot replace either original while preserving P3's complete visible-language observations.

A single model cannot be visibly equivalent to both A and B under P3, because equality of languages is transitive and their bounded languages differ. The same obstruction applies to their declared P1 observations. Agreement after dashboard abstraction is therefore the appropriate scope of this simplification.

Exhaustive bounded exploration is conclusive about the stated finite bound, and a bounded counterexample disproves unbounded equivalence. Passing all bounded comparisons would still not prove unbounded equivalence. Here the P2 preservation claim is supported by the all-`n` language argument, while the P1/P3 failures have explicit complete witnesses.
