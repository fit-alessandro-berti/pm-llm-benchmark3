## 6. Segmentation plan

| segment level | variables | purpose | minimum support rule | comparisons enabled | risk of conditioning bias |
|---|---|---|---|---|---|
| L0 — global monthly cohort | registration month (all cases entering `Register`) | headline KPIs, change-point screening, seasonality | 300 cases/month (actual 605–790) | any month vs baseline; YoY | overaggregation: mix shifts masquerade as behavior |
| L1 — mechanism strata (**primary analytic layer**) | supplier Z / non-Z × complexity high / standard (4 cells) | separate supplier and mix mechanisms from behavior; standardization weights | 50 cases/cell/month; else pool to quarter or merge complexity bands; report cell sizes with every KPI | Z vs non-Z within complexity; AprMaySep DiD; mix-standardized totals | complexity measured post-registration; supplier non-random by region (residual confounding) |
| L2 — scheduling layer | priority class × complexity, post-2026-07 only | detect redistribution of delay hidden by aggregates | 40 cases/class/month and 100 pre-`Assess` waiting observations | pre/post 07-01 at matched load and supplier | class derived from complexity  post-treatment w.r.t. mix; do not compare class *shares* as outcomes |

| L6 — calendar layer | renewal vs non-renewal month; year | recurrence vs new drift | 2 years for seasonal identification; until then flag seasonality as *assumed* | YoY same-month; seasonal residual drift | season/trend not identifiable in a single 12-month cycle |

**Primary monitoring population:** the **L0 registration-month cohort of all cases**, reported jointly with **L1 mix-standardized rates** (baseline complexity×supplier weights). Reason: it is defined entirely by pre-treatment information (arrival date, supplier, recorded complexity), so it avoids conditioning on mediators (rework, senior assessment, priority handling) and on completion (censoring collider). Every mechanism claim is then made *within* L1 cells; the standardized L0 series answers "did the process change?", the raw L0 series answers "did the burden change?" — and the two must never be conflated.

**Seasonality.** Never compare October to July. Use (a) same-calendar-month prior-year references once 24 months exist, (b) a seasonal adjustment (STL or harmonic regression on log volume/waiting) and monitor the *residual*, and (c) mix-standardization to baseline complexity×supplier weights so that expected seasonal composition does not fire behavioral alarms. Until history exists, October–November thresholds are widened and explicitly labelled "season-expected"; an alert is only raised if the *seasonally adjusted, mix-standardized* residual moves.

**Multiple testing.** Group monitors into families (schema, control-flow, temporal, resource, mix/outcome) and apply Benjamini–Hochberg at q = 0.10 *within* family, with a hierarchical gate: a global L0 alert must fire before cell-level alerts page anyone; otherwise cell findings are queued as diagnostics. Require persistence (2 of 3 consecutive windows) and minimum support before any alert; use EWMA/CUSUM tuned to a target in-control ARL (e.g. 6 months) rather than repeated independent tests; cap paging alerts per week and route the rest to a review backlog. Chronic known issues (post-migration missingness) get a re-baselined monitor plus an open remediation ticket, not a permanent alarm.

def dfg_distances(d):

        row = {"month": r["month"], "L1_per100": round(l1, 2), "TV_norm": round(tv, 4),

        for g, cols in GROUPS.items():
            idx = [EDGE_COLS.index(c) for c in cols]
            row[f"{g}_share_of_L1"] = round(float(np.abs(diff[idx]).sum()) / l1, 3) if l1 else np.nan
        row["L1_excl_senior"] = round(l1 - abs(diff[EDGE_COLS.index("assess_senior")]), 2)
        rows.append(row)
    res = pd.DataFrame(rows)
    print("\nDFG fragment distances vs 2026-01 (L1 in relations/100 cases; TV on sum-1 fragment):")

    # pairwise contrast between the two worst-looking snapshots

def _robust_sigma(x):
    x = np.asarray(x, float)
    med = np.median(x)
    mad = np.median(np.abs(x - med))
    return 1.4826 * mad if mad > 0 else (np.std(x) if np.std(x) > 0 else np.nan)


def change_points(m):
    flags = []
    for metric, (floor, rel, direction) in CP_CFG.items():
        x = m[metric].to_numpy(float)
        base = float(np.mean(x[:2]))
        diffs = np.diff(x)
        sigma = _robust_sigma(diffs)
        # Rule A: single-month step, robust-z >= 2.5 AND practically material
        for i, dv in enumerate(diffs, start=1):
            z = abs(dv) / sigma if sigma and sigma > 0 else 0.0
            sign_ok = (direction == "both" or (direction == "up" and dv > 0)
                       or (direction == "down" and dv < 0))
            if sign_ok and abs(dv) >= floor and z >= 2.5:
                flags.append((metric, m["month"][i], "A_step", round(dv, 3), round(z, 2)))
        # Rule B: sustained level shift, 2 consecutive months beyond a relative threshold
        if base != 0:
            dev = (x - base) / abs(base)
            ok = ((dev >= rel) if direction == "up" else
                  (dev <= -rel) if direction == "down" else (np.abs(dev) >= rel))
            for i in range(len(x) - 1):
                if ok[i] and ok[i + 1]:
                    flags.append((metric, m["month"][i], "B_sustained",
                                  round(dev[i], 3), round(base, 3)))
                    break
    f = pd.DataFrame(flags, columns=["metric", "onset_month", "rule", "magnitude", "scale_or_base"])
    print("\nCANDIDATE CHANGE POINTS (heuristic; no formal estimator on 12 aggregates):")
    print(f.sort_values(["metric", "onset_month"]).to_string(index=False))

def format_log(df, case_col="case_id", activity_col="activity", ts_col="timestamp",
               ts_format=None):
    """Copy + type-cast + pm4py.format_dataframe (never overwrites the input)."""
    _require_pm4py()
    local = df.copy()
    local[ts_col] = pd.to_datetime(local[ts_col], utc=True, format=ts_format, errors="coerce")
    if local[ts_col].isna().any():

    return pm4py.format_dataframe(local, case_id=case_col,

def normalize_log(formatted, alias_map=None, technical_activities=None, keep="first"):
    """Return a NEW mapped/de-duplicated log plus provenance; original stays raw."""
    _require_pm4py()
    alias_map = ALIAS_MAP if alias_map is None else alias_map
    technical_activities = TECHNICAL_ACTIVITIES if technical_activities is None else technical_activities
    norm = formatted.copy()
    before = norm[ACT_KEY].value_counts().to_dict()
    norm[ACT_KEY] = norm[ACT_KEY].replace(alias_map)
    tech = norm[ACT_KEY].isin(technical_activities)
    dup_mask = tech & norm.duplicated(subset=[CASE_KEY, ACT_KEY], keep=keep)
    removed = int(dup_mask.sum())
    norm = norm.loc[~dup_mask].sort_values([CASE_KEY, TS_KEY]).reset_index(drop=True)
    provenance = {"alias_map": dict(alias_map), "events_before": len(formatted),
                  "events_after": len(norm), "technical_events_removed": removed,
                  "label_counts_before": before,
                  "label_counts_after": norm[ACT_KEY].value_counts().to_dict()}
    return norm, provenance


def slice_window(log, start, end, mode="traces_contained"):
    """mode in {'events','traces_contained','traces_intersecting'}; cohort analyses should
    use traces_contained on registration month to limit censoring artifacts."""
    _require_pm4py()
    return pm4py.filter_time_range(log, str(start), str(end), mode=mode)


def monthly_dfgs(log, mode="traces_contained"):
    """Per-calendar-month DFG + start/end activities, on case-cohort windows."""
    _require_pm4py()
    ts = pd.to_datetime(log[TS_KEY], utc=True)
    out = {}
    for period in sorted(ts.dt.to_period("M").unique()):
        w = slice_window(log, period.start_time, period.end_time, mode=mode)
        if len(w) == 0:
            continue
        dfg, sa, ea = pm4py.discover_dfg(w)
        n_cases = w[CASE_KEY].nunique()
        out[str(period)] = {"n_cases": int(n_cases), "dfg": dfg,
                            "start_activities": sa, "end_activities": ea,
                            "rates_per_100_cases": {k: 100.0 * v / max(n_cases, 1)
                                                    for k, v in dfg.items()}}
    return out


def dfg_fragment_distance(rates_a, rates_b, edges=None):
    """Same transparent measure as Part A: L1 per 100 cases + TV on the shared fragment.
    Edges absent from one snapshot are reported separately, never silently zero-filled."""
    keys_a, keys_b = set(rates_a), set(rates_b)
    shared = sorted(keys_a & keys_b) if edges is None else [e for e in edges if e in keys_a & keys_b]
    a = np.array([rates_a[e] for e in shared], float)
    b = np.array([rates_b[e] for e in shared], float)
    return {"edges_used": shared, "only_in_a": sorted(keys_a - keys_b),
            "only_in_b": sorted(keys_b - keys_a),
            "L1_per100": float(np.abs(a - b).sum()),
            "TV_norm": float(0.5 * np.abs(a / a.sum() - b / b.sum()).sum()) if a.sum() and b.sum() else np.nan}


def variant_spectrum(log, as_tuples=False):
    _require_pm4py()
    variants = (pm4py.get_variants_as_tuples(log) if as_tuples else pm4py.get_variants(log))
    n = log[CASE_KEY].nunique()
    counts = {v: (len(c) if isinstance(c, (list, set, tuple)) else int(c))
              for v, c in variants.items()}
    return {"n_cases": n, "counts": counts,
            "shares": {v: c / max(n, 1) for v, c in counts.items()}}


def variant_distance(spec_a, spec_b):
    keys = sorted(set(spec_a["shares"]) | set(spec_b["shares"]), key=str)
    p = np.array([spec_a["shares"].get(k, 0.0) for k in keys])
    q = np.array([spec_b["shares"].get(k, 0.0) for k in keys])
    m_ = 0.5 * (p + q)
    def _kl(x, y):
        mask = (x > 0) & (y > 0)
        return float(np.sum(x[mask] * np.log(x[mask] / y[mask])))
    return {"TV": float(0.5 * np.abs(p - q).sum()),
            "JS": float(0.5 * _kl(p, m_) + 0.5 * _kl(q, m_)),
            "new_variant_mass": float(q[p == 0].sum())}


def temporal_profile(log, reference_log=None, deviation_z=2.0):
    """Mean/SD seconds per activity pair; optionally score deviations on a later window."""
    _require_pm4py()
    profile = pm4py.discover_temporal_profile(reference_log if reference_log is not None else log)
    out = {"profile": profile}
    if reference_log is not None:
        out["deviations"] = pm4py.conformance_temporal_profile(
            log, profile, parameters={"deviation_threshold": deviation_z})
    return out


def structural_models(log, noise_threshold=0.0, min_support=0.05, min_confidence=0.8):
    """Optional log skeleton + DECLARE; API names vary slightly across pm4py versions."""
    _require_pm4py()
    out = {}
    try:
        sk = pm4py.discover_log_skeleton(log, noise_threshold=noise_threshold)
        out["log_skeleton"] = {"always_after": sk.get_always_after_relations(),
                               "always_before": sk.get_always_before_relations(),
                               "never_together": sk.get_never_together_relations(),
                               "eventually_follows": sk.get_eventually_follows_relations()}
    except Exception as exc:                      # pragma: no cover
        out["log_skeleton_error"] = repr(exc)
    try:
        dec = pm4py.discover_declare(log, min_support_ratio=min_support,
                                     min_confidence_ratio=min_confidence)
        out["declare"] = dec
        out["declare_conformance"] = pm4py.conformance_declare(log, dec)
    except Exception as exc:                      # pragma: no cover
        out["declare_error"] = repr(exc)
    return out


def conformance_compare(raw_log, normalized_log, reference_log, noise_threshold=0.0):
    """Fitness of raw vs normalized against ONE frozen reference model.
    Reports mean fitness AND the alignment-cost distribution (means hide drift)."""
    _require_pm4py()
    ref = reference_log if isinstance(reference_log, object) else reference_log
    net, im, fm = pm4py.discover_petri_net_inductive(ref, noise_threshold=noise_threshold)
    res = {}
    for name, lg in [("raw", raw_log), ("normalized", normalized_log)]:
        diags = pm4py.conformance_diagnostics_alignments(lg, net, im, fm)
        fit = np.array([d.get("fitness", np.nan) for d in diags], float)
        cost = np.array([d.get("cost", np.nan) for d in diags], float)
        res[name] = {"mean_fitness": float(np.nanmean(fit)),
                     "p10_fitness": float(np.nanpercentile(fit, 10)),
                     "median_cost": float(np.nanmedian(cost)),
                     "p90_cost": float(np.nanpercentile(cost, 90)),
                     "n_traces": int(len(diags))}
    res["recovered_fitness"] = res["normalized"]["mean_fitness"] - res["raw"]["mean_fitness"]
    return res


def stratified_report(log, strata_cols=("supplier_z", "complexity_band"), min_cases=50):
    """L1 segmentation with an explicit minimum-support rule; small cells are pooled,
    never dropped silently. strata_cols must live on the CASE-level attribute table."""
    _require_pm4py()
    cases = log.groupby(CASE_KEY).first().reset_index()
    out = {}
    for keys, grp in cases.groupby(list(strata_cols), dropna=False):
        ids = set(grp[CASE_KEY])
        if len(ids) < min_cases:
            out[("POOLED",) + tuple(map(str, keys))] = {"n_cases": len(ids), "status": "below_support"}
            continue
        sub = log[log[CASE_KEY].isin(ids)]
        dfg, sa, ea = pm4py.discover_dfg(sub)
        out[tuple(map(str, keys))] = {"n_cases": len(ids),
                                      "variants": variant_spectrum(sub)["shares"],
                                      "rates_per_100_cases": {k: 100.0 * v / len(ids)
                                                              for k, v in dfg.items()}}
    return out

## 9. Provisional attribution

**Strongest conclusions (high confidence, 85–95).** The March fitness collapse is a measurement event, not a process break: raw fitness fell 0.38 while mapped fitness fell 0.03, label cardinality rose by exactly the two introduced labels, duplicate `Open Case` appeared at 4%, and both eligibility labels continue to `Collect Documents` at 96–98%. Normalized DFG distance in March is 0.004 versus 0.06–0.10 later. Equally strong: real behavioral and performance drift exists after April. The rework edge doubles in raw *and* normalized views and is corroborated by an independent operational-table metric; median cycle time rises 57% and p90 78% while `Assess` service rises only 0.6 h. No relabeling can produce waiting.

**Plausible, not established (moderate, 55–75).** Supplier Z is the dominant trigger of the May rework step: the 25 pp share jump plus an implied within-Z rework rise from ~30% to ~45% fits incomplete bundles, and the September reversal is directionally consistent. Staffing loss is the most plausible main driver of the queueing residual (45–65% of the median shift), because the median — not just the tail — moved at flat service time, and the workload index rose ~46% against reduced capacity. Seasonal population drift plausibly dominates October–November mix (complexity 2645%), but with one cycle observed, season is not statistically separable from trend.

**Where attribution breaks down.** Priority (July) is only weakly identified: the flattening median with rising p90 and p90/median is *consistent* with starvation of standard cases, but censoring and supplier backlog produce the same aggregate. Mediation is pervasive: mix  rework  load  waiting, so additive shares double-count. October's DFG distance is ~28% senior-edge, and senior-per-complexity jumping 0.320.54 with unchanged label inventory suggests recording completeness rather than escalation — this also deflates `fast_variant_pct`. December cannot separate seasonal exit, overtime and the document campaign, and is right-censored.

**Persistent residue (moderate).** December rework at 21% versus 11.5% baseline, at complexity 34% versus 21%, is partly composition and partly institutionalized rework.

**What would revise this account.** Case-level timestamps split into service vs waiting; priority-class waiting CDFs; within-complexity supplier strata; prior-year seasonal data; resource-complete team logs; and duration/outcome equivalence tests for senior-labeled cases. If within-stratum rework did *not* rise in May, supplier attribution collapses to pure mix; if standard-class waiting did not rise after July, the priority hypothesis should be dropped.

## 10. Monitoring decision rules

1. IF raw fitness drops >0.10 in one month while mapped fitness moves <0.03 and the label inventory gains exactly the renamed/technical labels, THEN classify the event as logging-semantic drift, freeze raw fitness as a schema KPI, and re-baseline all behavioral monitors on the mapped log, BECAUSE a rename plus technical-event injection changes conformance measurement without changing control flow.
2. IF a supplier's share jumps >10 pp and the normalized `AssessRequest Info` rate rises >8 pp in the same month while complexity rises <3 pp, THEN run within-complexity supplier vs non-supplier rework DFGs and open a supplier document-quality incident, BECAUSE a composition shock plus a within-stratum rate increase is the signature of incomplete bundles rather than case mix alone.
3. IF mix-standardized median cycle time rises >15% for two consecutive months while trimmed `Assess` service rises <10% and the fast-variant share falls, THEN reconstruct pre-`Assess` waiting and WIP and escalate a capacity review, BECAUSE delay accumulating in front of an activity with stable service time is queueing, not slower work.
4. IF aggregate p90 and p90/median widen >10% while high-complexity waiting improves and standard-case waiting deteriorates at comparable load, THEN audit the priority rule and introduce a fairness/aging guardrail for standard cases, BECAUSE work-conserving priority redistributes (and can raise the unweighted mean of) delay rather than creating capacity.
5. IF `AssessSenior Assessment` per high-complexity case rises >50% relative with unchanged label inventory and no difference in senior-case durations or outcomes, THEN treat it as recording-completeness drift, version the label semantics, and recompute variant and DFG distances on a senior-collapsed alphabet, BECAUSE historically inconsistent escalation labels inflate behavioral distance and deflate fast-variant share without any process change.
6. IF missing-resource share exceeds 8% on any activity or differs >5 pp between teams, THEN suspend per-team resource alerts, publish bounded/imputed resource KPIs, and fix capture at the source, BECAUSE missingness concentrated in migrated activities and non-random by team makes resource-based drift undetectable and biased.
7. IF an October–November deterioration disappears after seasonal adjustment and mix standardization and reproduces in prior-year same-month windows, THEN label it recurring seasonal load, suppress behavioral alerts, and pre-schedule capacity for the next renewal window; only the seasonally adjusted residual may trigger a drift investigation, BECAUSE recurring population drift is expected burden, not a changed process, and must be distinguished from new mechanism-specific drift.
