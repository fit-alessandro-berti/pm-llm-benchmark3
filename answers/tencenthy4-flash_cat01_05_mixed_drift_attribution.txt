## 2. Raw-versus-normalized interpretation

The raw/mapped fitness gap is strongest evidence of provenance drift, not evidence that every later difference is cosmetic. In March, raw fitness collapses from about 0.925 to 0.55 while mapped fitness returns to 0.90; labels increase from 9 to 11 and duplicated `Open Case` events appear. Mapping `Eligibility Screen` to `Validate Eligibility` and removing technical duplicates can therefore recover conformance to the old model. This implies that the old model and raw event vocabulary were no longer aligned. It does not imply that all activities, roles, timings, or decision paths were unchanged, because conformance is evaluated on a simplified normative model and can hide timing and resource changes.

A label mapping is a semantic repair. It can recover the intended activity name after migration, but it may also collapse genuinely new work into an old label. Thus March should be diagnosed as logging/semantic drift with little evidence of business-process change, while later months require separate tests.

Duplicated `Open Case` events distort edge counts, variants, and fitness; removing them is necessary for structural comparison. Missing resource identifiers have different effects: they bias resource/workload/handoff analysis and may make staffing effects look like behavioral change, but they do not by themselves create additional document loops or longer queues.

After May the mapped DFG still changes: `Assess->RequestInfo` roughly doubles by May and reaches 29 per 100 cases in July, `CollectDocs->Assess` falls, decision flow drops, and cycle time/p90 rise while `Assess` service time changes modestly. Supplier disruption, queueing, and case mix therefore remain plausible real drift even if labels are imperfect.

## 6. Segmentation plan

| segment level | variables | purpose | minimum support rule | comparisons enabled | risk of conditioning bias |
|---|---|---|---|---|---|
| Cleaned base population | case ID, timestamp, mapped activity, removed duplicate `Open Case` | Common reference log for structural drift | all cases with valid case ID, timestamp, and at least Register/Eligibility event | raw vs mapped fitness, DFG, variants | Over-cleaning can hide genuine semantic drift if mapping is wrong |
| Time / season | week and month, renewal-season flag | Locate mechanism-specific change points | 30 cases per week or 100 per month; else pool adjacent weeks | baseline vs May, Jun, Jul, Oct, Dec; same-season if historical data available | Conditioning on post-change periods can absorb the effect being estimated |
| Case mix | complexity tier from fields recorded before Assess | Separate population drift from behavior | 50 cases per tier per comparison window | high vs standard DFG, waiting, senior routing | Complexity label may itself drift or be updated mid-case |
| Supplier | Supplier Z vs other, region/customer coarse strata | Test supplier-driven rework | 30 cases per supplier cell per month; pool small regions | rework rate, first-pass acceptance, loop duration | Supplier is non-random; customer/region confounding |
| Priority exposure | complexity tier × pre/post 2026-07-01 priority rule | Test delay redistribution | 40 cases per tier-period cell | waiting quantiles, Assess queue time, decision time | Priority is assigned using complexity, which also affects service and senior routing |
| Resource / team | team or role where available, migrated-activity flag | Diagnose staffing and missingness | 20 events per resource-month or aggregate to team if below threshold | workload, handoffs, service time, resource completeness | Missing resource IDs are non-random; resource conditioning can create collider bias |
| Rework path | cases with/without `Assess->RequestInfo` | Quantify loop contribution to cycle time | 50 cases per path per window | loop duration, p90 impact, variants | Rework is a mediator, not a baseline covariate; do not use for total-effect estimates |
| Senior assessment | high-complexity flag × senior-assessment recorded | Separate routing behavior from logging inconsistency | 30 cases per cell; otherwise pool months | conditional DFG, decision outcomes, service time | Historical recording inconsistency can mimic behavioral change |

Primary monitoring population: the cleaned, mapped event log with duplicated technical `Open Case` events removed, monitored by week/month and stratified first by complexity tier and renewal-season flag, with supplier Z as an overlay. This avoids letting March logging artifacts dominate and prevents aggregate case-mix shifts from being mistaken for behavioral drift. Resource, rework, and senior-assessment strata should be used as diagnostics, not as the primary population, because they can be mediators or suffer non-random missingness.

Do not use one universal threshold. Each monitor should have its own empirical control limits, activity-specific variability, and seasonally matched reference window. For renewal-season monitors, use prior same-season data if available; otherwise mark alerts as provisional until a seasonal baseline exists. Multiple testing should be handled by controlling false discovery rate across monitor families, requiring persistence across at least two windows, and requiring corroboration from a second artifact family before operational escalation.

import copy
import pm4py

DEFAULT_CASE = "case:concept:name"
DEFAULT_ACT = "concept:name"
DEFAULT_TIME = "time:timestamp"


def format_event_dataframe(
    event_df,
    case_id_key=DEFAULT_CASE,
    activity_key=DEFAULT_ACT,
    timestamp_key=DEFAULT_TIME,
):
    """
    Format a raw event dataframe with pm4py.format_dataframe(...) and convert
    it to an event log. The input dataframe is copied, not modified.
    """
    df = event_df.copy()
    df = pm4py.format_dataframe(
        df,
        case_id=case_id_key,
        activity_key=activity_key,
        timestamp_key=timestamp_key,
    )
    log = pm4py.convert_to_event_log(df)
    return df, log


def slice_time_window(
    event_log,
    start,
    end,
    mode="events",
    case_id_key=DEFAULT_CASE,
    timestamp_key=DEFAULT_TIME,
):
    """
    Slice an event log with pm4py.filter_time_range(...).
    mode='events' keeps events in range; mode='traces' keeps cases with events in range.
    """
    return pm4py.filter_time_range(
        event_log,
        pd.to_datetime(start),
        pd.to_datetime(end),
        mode=mode,
        case_id_key=case_id_key,
        timestamp_key=timestamp_key,
    )


def monthly_dfg_artifacts(
    event_df,
    case_id_key=DEFAULT_CASE,
    activity_key=DEFAULT_ACT,
    timestamp_key=DEFAULT_TIME,
):
    """
    Compute monthly DFGs with pm4py.discover_dfg(...).
    Returns dict[month] = {dfg, start_activities, end_activities}.
    """
    df, _ = format_event_dataframe(event_df, case_id_key, activity_key, timestamp_key)
    df = df.copy()
    df["_month"] = df[timestamp_key].dt.to_period("M").dt.to_timestamp()

    result = {}
    for month, sub in df.groupby("_month"):
        sub = sub.drop(columns=["_month"])
        log = pm4py.convert_to_event_log(sub)
        dfg, start_activities, end_activities = pm4py.discover_dfg(
            log,
            activity_key=activity_key,
            case_id_key=case_id_key,
            timestamp_key=timestamp_key,
        )
        result[month] = {
            "dfg": dfg,
            "start_activities": start_activities,
            "end_activities": end_activities,
        }
    return result


def compute_variants(
    event_df,
    case_id_key=DEFAULT_CASE,
    activity_key=DEFAULT_ACT,
    timestamp_key=DEFAULT_TIME,
):
    """
    Compute trace variants with pm4py.get_variants(...).
    """
    _, log = format_event_dataframe(event_df, case_id_key, activity_key, timestamp_key)
    return pm4py.get_variants(log)


def compute_temporal_profile(
    event_df,
    case_id_key=DEFAULT_CASE,
    activity_key=DEFAULT_ACT,
    timestamp_key=DEFAULT_TIME,
):
    """
    Compute activity-to-activity temporal profiles with
    pm4py.discover_temporal_profile(...).
    """
    _, log = format_event_dataframe(event_df, case_id_key, activity_key, timestamp_key)
    return pm4py.discover_temporal_profile(
        log,
        activity_key=activity_key,
        timestamp_key=timestamp_key,
        case_id_key=case_id_key,
    )


def discover_constraint_models(
    event_df,
    noise_threshold=0.1,
    case_id_key=DEFAULT_CASE,
    activity_key=DEFAULT_ACT,
    timestamp_key=DEFAULT_TIME,
):
    """
    Optionally discover a log skeleton and DECLARE model.
    DECLARE availability may vary by PM4Py version, so failures are reported
    rather than silently changing the log.
    """
    _, log = format_event_dataframe(event_df, case_id_key, activity_key, timestamp_key)

    skeleton = pm4py.discover_log_skeleton(
        log,
        noise_threshold=noise_threshold,
        activity_key=activity_key,
        case_id_key=case_id_key,
        timestamp_key=timestamp_key,
    )

    declare_model = None
    declare_error = None
    try:
        declare_model = pm4py.discover_declare(
            log,
            activity_key=activity_key,
            case_id_key=case_id_key,
            timestamp_key=timestamp_key,
        )
    except Exception as exc:
        declare_error = repr(exc)

    return {
        "log_skeleton": skeleton,
        "declare_model": declare_model,
        "declare_error": declare_error,
    }


def compare_raw_vs_mapped(
    event_df,
    label_map=None,
    remove_duplicate_open_case=True,
    case_id_key=DEFAULT_CASE,
    activity_key=DEFAULT_ACT,
    timestamp_key=DEFAULT_TIME,
):
    """
    Compare raw and normalized label mappings without overwriting the original
    event dataframe or event log.

    Example label_map:
        {"Eligibility Screen": "Validate Eligibility"}
    """
    if label_map is None:
        label_map = {"Eligibility Screen": "Validate Eligibility"}

    raw_df = event_df.copy()
    mapped_df = event_df.copy()

    mapped_df[activity_key] = mapped_df[activity_key].replace(label_map)

    # Remove repeated technical Open Case events per case, keeping the first.
    if remove_duplicate_open_case:
        mapped_df = mapped_df.sort_values(timestamp_key).copy()
        open_mask = mapped_df[activity_key].eq("Open Case")
        mapped_df["_open_seq"] = open_mask.groupby(mapped_df[case_id_key]).cumsum()
        mapped_df = mapped_df.loc[
            ~(open_mask & mapped_df["_open_seq"].gt(1))
        ].drop(columns=["_open_seq"])

    raw_df_formatted, raw_log = format_event_dataframe(
        raw_df, case_id_key, activity_key, timestamp_key
    )
    mapped_df_formatted, mapped_log = format_event_dataframe(
        mapped_df, case_id_key, activity_key, timestamp_key
    )

    raw_dfg, raw_start, raw_end = pm4py.discover_dfg(
        raw_log,
        activity_key=activity_key,
        case_id_key=case_id_key,
        timestamp_key=timestamp_key,
    )
    mapped_dfg, mapped_start, mapped_end = pm4py.discover_dfg(
        mapped_log,
        activity_key=activity_key,
        case_id_key=case_id_key,
        timestamp_key=timestamp_key,
    )

    return {
        "raw_log": raw_log,
        "mapped_log": mapped_log,
        "raw_dataframe": raw_df_formatted,
        "mapped_dataframe": mapped_df_formatted,
        "raw_variants": pm4py.get_variants(raw_log),
        "mapped_variants": pm4py.get_variants(mapped_log),
        "raw_dfg": raw_dfg,
        "mapped_dfg": mapped_dfg,
        "raw_start_activities": raw_start,
        "mapped_start_activities": mapped_start,
        "raw_end_activities": raw_end,
        "mapped_end_activities": mapped_end,
    }

## 9. Provisional attribution

Strongest conclusion: March is logging/semantic provenance drift. The raw-to-mapped fitness recovery is large, the raw DFG splits one activity into two labels, technical duplicates start at migration, and resource missingness jumps while mapped DFG and cycle time remain near baseline. It is unlikely that the old business process materially changed in March.

Also strong: post-May drift is real. Supplier Z rises from roughly 15% to 43-46%, rework variants double, request-info loops rise from 12 to 24-29 per 100, fast variants fall, and cycle time/p90 worsen while Assess service time changes only modestly. Given the dated supplier disruption and incomplete bundles, supplier-driven rework is high confidence, though Supplier Z is non-random and already more complex.

Staffing-driven queueing is plausible-to-likely but not cleanly separable. The assessor exit aligns with worsening p90 and reconstructed waiting, but supplier backlog, rising complexity, and later priority changes overlap. The small Assess service-time change argues against pure service degradation and toward queueing/workload.

The priority rule is plausible but weakly identified in aggregates. It should redistribute waiting by complexity; monthly medians cannot show that. If event-level data show high-complexity waits falling while standard waits rise after 7/1, confidence increases; if not, revise.

October-November is high-confidence seasonal population drift: renewal season, volume up about 25-29%, high-complexity share from 20.5% to 41-45%, and senior assessment jumps. Because Senior Assessment was inconsistently recorded, the jump may combine real routing, case mix, and semantic visibility. December improvement is medium-confidence interaction: lower seasonal load plus overtime/quality campaign; effects cannot be separated.

Revise if segmented DFGs show no supplier-specific rework elevation, if mapped structural rates remain stable despite raw-label changes after May, if queue waiting does not rise more than service, if high/standard priority trajectories do not diverge, or if senior assessment changes vanish after conditioning on complexity.

## 10. Monitoring decision rules

1. IF raw fitness falls by at least 0.10 while mapped fitness returns within 0.05 of baseline and label/duplicate flags fire, THEN classify the episode as logging-semantic drift and repair mappings before process escalation, BECAUSE provenance artifacts can collapse conformance without changing the underlying process.

2. IF supplier-specific rework rises by more than 10 percentage points within two consecutive windows, THEN inspect document bundles and trigger supplier-quality review, BECAUSE incomplete bundles should first appear as repeated document collection and request-info loops.

3. IF waiting before Assess rises while Assess service time remains near baseline, THEN treat the issue as queueing/capacity rather than assessor slowness, BECAUSE cycle-time drift concentrated in waiting points to resource or priority effects.

4. IF high-complexity waiting improves after the priority rule while standard-case waiting worsens, THEN report redistribution rather than aggregate improvement, BECAUSE priority policies can change equity and tail delay without reducing total workload.

5. IF volume and high-complexity share exceed the same-season envelope together, THEN switch case-mix-adjusted baselines and postpone attribution to behavior, BECAUSE renewal-season population drift can mimic structural and performance drift.

6. IF `Assess->SeniorAssessment` rises in aggregate but not within complexity strata, THEN attribute it mainly to case mix or recording visibility, BECAUSE conditional stability indicates population composition rather than changed routing behavior.

7. IF rework, p90 cycle time, and mapped fitness all improve after the December interventions while complexity remains elevated, THEN mark the improvement as intervention-consistent but not causally identified, BECAUSE seasonal load decline and active operational changes occurred simultaneously.
