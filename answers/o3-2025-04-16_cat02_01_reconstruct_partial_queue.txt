# 1. Assumptions and notation
A1 – Time rounding: Every reported timestamp **t** stands for an unknown true time in  
[t-2.5 min, t+2.5 min].  
Central estimate = reported value,  
Lower bound = t–2.5 min,  
Upper bound = t+2.5 min.

A2 – Eventorder convention at equal rounded times: if an S1_end and an S2_start (or any departure and arrival) share the same rounded value, the departure is treated as having happened infinitesimally earlier. This avoids negative waiting times and keeps the queue FIFO whenever the data permit.

A3 – Single-task resources: I1, I2, C1, C2 can work on at most one case at a time. Any overlap is interpreted as rounding noise 5 min.

A4 – Resource availability: All resources are available for the whole window except C2, which is down from 10:55 to 11:10.

A5 – Imputation of **MISSING** start times  
• Earliest start = previous end on the same resource (upper-bound overlap tolerance 2.5 min)  
• Latest start = recorded end – 5 min (minimum plausible service)  
• Central start = midpoint of earliest and latest.  
The induced service-time and waiting-time ranges are propagated.

A6 – **OPEN** activities: elapsed service = 14:00 – start (lower), final service left open. Two scenarios are kept:  
• optimistic (“short”) – activity completes 5 min after 14:00,  
• pessimistic (“long”) – activity lasts 35 min more (90-percentile of observed services).

A7 – Blank S1/S2 start-end pairs mean the case is waiting for that station at 14:00; elapsed waiting time is measured up to 14:00 only.

A8 – Throughout, minutes are used; hr references are for readability only.

Notation  
arr = external arrival to S1 queue  
Ws1, Ss1 = waiting and service at S1  
Ws2, Ss2 = waiting and service at S2  
Soj = station sojourn (W+S),Tot = case total sojourn (S1 + S2)  
,  = arrival and departure rates; L = WIP;  = utilisation.  
Angle brackets low, central, high denote ranges.

# 2. Reconstruction method and formulas
1. Waiting time  
Ws1 = S1_start – arr,Ws2 = S2_start – S1_end  
Bounded by A1–A5.  
2. Service time  
Ss = end – start; bounds come from A1, A5, A6.  
3. Station sojourn = W+S; Case total sojourn =  station sojourns (censored when OPEN).  
4. Queue length L(t): for any time t, count cases that have entered the queue but have not yet started service.  
Departures are ordered before arrivals per A2.  
5. WIP(t): number of cases that have entered the system (arrived at S1) but have not yet left S2.  
6. Arrival and departure rates: simple counts divided by width of the analysis sub-period (2-hour blocks: 08-10, 10-12, 12-14).  
7. Resource busy time:  central service minutes on that resource (OPEN adds elapsed only);  
low = busy_low/(availability),high = busy_high/(availability). Availability for C2 is 345 min (360–15).  
8. Little’s Law check (L   × W) only in 10-12 interval, where flow is roughly steady and censoring is limited to one case.

# 5. Bottleneck and temporal interpretation
Evidence  
08-10: S1 receives 14 arrivals but completes only 7; S2 is starved (  0.2).  
10-12: S1 still busy (  0.76) but S2 catches up, now at comparable   0.8.  
12-14: No new arrivals. S1 works off the tail of its queue; S2 still busy with long Ws2 and two OPEN cases,  possibly exceeding 0.85.

Interpretation  
• Early morning bottleneck = S1 (inspection).  
• After 10:30 the backlog created at S1 shifts the instantaneous bottleneck to S2; the brief 15-min C2 outage intensifies this.  
• From ~12:15 onwards the system is constrained by S2, as S1 has no new inflow yet S2 still hosts eight waiting/processing cases.  
Thus the bottleneck is time-varying: S1  mixed  S2.

# 6. Missingness, censoring, and sensitivity analysis
Scenario 1 (optimistic) – all OPEN activities finish 5 min after 14:00, MISSING starts take earliest possible value.  
Scenario 2 (central) – midpoint imputation, OPEN ignored after 14:00.  
Scenario 3 (pessimistic) – OPEN continue 35 min, MISSING starts take latest possible value.

Findings that change little  
• Order of bottlenecks (S1 early, S2 late) – same in all scenarios.  
• Mean service times (25-30 min S1, 35-45 min S2).  
• Peak queue sizes (8 at S1 by 09:30, 9 at S2 by 12:30).

Findings that are sensitive  
• Exact utilisation range: _S2 varies from 0.71 to 0.93 across scenarios.  
• Little’s-Law consistency: in 10-12 interval, L  5.5,   3.5 cph, W  1.5 h fits in scenario 2, but not in scenario 3 where longer service extends W and violates LW by ~20 %.

Missing start times therefore matter mainly for utilisation estimates, not for the qualitative flow picture.

# 7. Reproducible Python
```python
import pandas as pd
from datetime import datetime, timedelta
import pm4py

# ----------------------------------------------------------
# 1. Build the supplied table, keeping status semantics
# ----------------------------------------------------------
raw = [
    ("P01","08:00","08:05","08:25","I1","08:30","09:00","C1","COMPLETE"),
    ("P02","08:05","08:10","08:35","I2","08:40","09:20","C2","COMPLETE"),
    ("P03","08:10","08:30","08:55","I1","09:05","09:45","C1","COMPLETE"),
    ("P04","08:20","08:40","09:10","I2","09:25","10:05","C2","COMPLETE"),
    ("P05","08:25","09:00","09:25","I1","MISSING","10:15","C1","COMPLETE_WITH_MISSING_START"),
    ("P06","08:35","09:15","09:45","I2","10:10","10:50","C2","COMPLETE"),
    ("P07","08:45","MISSING","10:00","I1","10:20","11:00","C1","COMPLETE_WITH_MISSING_START"),
    ("P08","09:00","09:50","10:20","I2","11:15","12:00","C2","COMPLETE"),
    ("P09","09:05","10:05","10:35","I1","11:00","11:40","C1","COMPLETE"),
    ("P10","09:15","10:25","10:55","I2","11:45","12:10","C1","COMPLETE"),
    ("P11","09:25","10:40","11:05","I1","MISSING","12:25","C2","COMPLETE_WITH_MISSING_START"),
    ("P12","09:35","11:00","11:30","I2","12:15","13:00","C1","COMPLETE"),
    ("P13","09:50","11:10","11:40","I1","12:30","13:20","C2","COMPLETE"),
    ("P14","10:00","11:35","12:00","I2","13:05","13:50","C1","COMPLETE"),
    ("P15","10:10","MISSING","12:15","I1","13:30","OPEN","C2","OPEN_IN_S2"),
    ("P16","10:25","12:05","12:35","I2","","","","WAITING_FOR_S2"),
    ("P17","10:45","12:20","12:50","I1","13:55","OPEN","C1","OPEN_IN_S2"),
    ("P18","11:00","12:40","13:10","I2","","","","WAITING_FOR_S2"),
    ("P19","11:15","12:55","13:25","I1","","","","WAITING_FOR_S2"),
    ("P20","11:30","13:15","13:45","I2","","","","WAITING_FOR_S2"),
    ("P21","11:50","13:30","OPEN","I1","","","","OPEN_IN_S1"),
    ("P22","12:10","","","","","","","WAITING_FOR_S1")
]
cols = ["case","arrival_s1","s1_start","s1_end","s1_res","s2_start","s2_end","s2_res","state"]
df = pd.DataFrame(raw, columns=cols)

# helper to build a timestamp or keep marker strings
def mk(ts):
    if ts in ["MISSING","OPEN",""]:
        return ts
    return datetime.strptime("2026-05-12 "+ts, "%Y-%m-%d %H:%M")

for c in ["arrival_s1","s1_start","s1_end","s2_start","s2_end"]:
    df[c] = df[c].apply(mk)

print("Original data with semantic markers")
print(df.head(3),"\n")

# ----------------------------------------------------------
# 2. Build PM4Py-compatible interval event log for fully observed activities
#    (others kept out to avoid misleading process mining results)
# ----------------------------------------------------------
def rows_for_station(row, station):
    if station=="S1":
        st, et, res = row["s1_start"], row["s1_end"], row["s1_res"]
        act  = "S1_IncomingInspection"
    else:
        st, et, res = row["s2_start"], row["s2_end"], row["s2_res"]
        act  = "S2_Calibration"
    if isinstance(st, datetime) and isinstance(et, datetime):
        return {
            "case:concept:name": row["case"],
            "concept:name": act,
            "start_timestamp": st,
            "time:timestamp": et,
            "org:resource": res
        }
    return None

interval_rows = []
for _,r in df.iterrows():
    for st in ["S1","S2"]:
        rec = rows_for_station(r, st)
        if rec: interval_rows.append(rec)

elog = pd.DataFrame(interval_rows)
elog = pm4py.format_dataframe(elog, case_id='case:concept:name',
                              timestamp_key='time:timestamp',
                              activity_key='concept:name')

print("Interval event log (fully observed parts)")
print(elog.head(),"\n")

# ----------------------------------------------------------
# 3. Station-specific queue / service / WIP demo (central scenario)
# ----------------------------------------------------------
def duration(mins):
    return timedelta(minutes=mins)

# central imputation for a small subset to illustrate
central = []
for _,r in df.iterrows():
    # skip cases still waiting for S1
    if r.s1_end in ["OPEN",""] or r.s1_end=="":
        continue
    ws1 = (r["s1_start"] - r["arrival_s1"]).total_seconds()/60 if isinstance(r["s1_start"], datetime) else None
    ss1 = (r["s1_end"] - r["s1_start"]).total_seconds()/60 if isinstance(r["s1_start"], datetime) else None
    if r["s1_start"]=="MISSING":
        # midpoint imputation per A5
        prev_end = df[(df.s1_res==r.s1_res) &
                      (df.s1_end.apply(lambda x: isinstance(x, datetime))) &
                      (df.s1_end < r.s1_end)].s1_end.max()
        earliest = prev_end + duration(0) if pd.notnull(prev_end) else r.arrival_s1
        latest   = r.s1_end - duration(5)
        r["s1_start_central"] = earliest + (latest-earliest)/2
        ws1 = (r["s1_start_central"] - r.arrival_s1).total_seconds()/60
        ss1 = (r.s1_end - r["s1_start_central"]).total_seconds()/60
    central.append({"case":r.case,"Ws1":ws1,"Ss1":ss1})

print("Central scenario S1 waiting & service (excerpt)")
print(pd.DataFrame(central).head(),"\n")

# ----------------------------------------------------------
# 4. Demonstration of pm4py helper functions on observed part
# ----------------------------------------------------------
elog_int = pm4py.convert_log_to_time_intervals(elog)
elog_int = pm4py.insert_case_service_waiting_time(elog_int)
elog_int = pm4py.insert_case_arrival_finish_rate(elog_int)

print("pm4py per-case service & waiting time (observed only)")
print(elog_int[['case:concept:name','service_time','waiting_time']].head())
```

Code comments  
• For S1/S2 activities that have either **MISSING** or **OPEN** timestamps, direct pandas computations are safer than relying on PM4Py, because pm4py ignores incomplete intervals.  
• The demo therefore first shows how a clean interval log is produced, then keeps separate pandas logic for uncertainty scenarios.
