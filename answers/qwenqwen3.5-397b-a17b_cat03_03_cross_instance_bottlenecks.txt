## 1. Interaction-graph description

The manufacturing system is best represented as a typed heterogeneous interaction graph where nodes represent physical or logical entities and edges represent relationships or events. Traditional process mining often collapses this into a single "Case" type (Job), obscuring the multi-dimensional dependencies evident here.

**Node Types:**
*   **Job (J1–J6):** The primary unit of work.
*   **Component (C1–C6):** Physical inputs required by Jobs.
*   **ComponentLot (L7, L8):** Logical groupings of Components sharing quality status.
*   **Machine (CNC-2, OVEN-1, TEST-1):** Processing resources.
*   **Tool (FIX-A, RACK-7, CAL-3):** Auxiliary resources required for processing.
*   **Batch (B1, B2):** Logical groupings for simultaneous processing.
*   **Shipment (S1–S3):** Logical groupings for logistics.

**Edge Types and Qualifiers:**
*   `requires` (Job  Component): Static bill of materials.
*   `contains` (ComponentLot  Component): Static lineage.
*   `batches` (Batch  Job): Dynamic grouping for processing.
*   `consolidates` (Shipment  Job): Dynamic grouping for logistics.
*   `uses` (Job  Machine/Tool): Inferred from event logs (e.g., `Machine Process`).
*   `blocks` (Tool  Job): Inferred from timing gaps (e.g., Tool held while Job waits).

**Higher-Order Motifs:**
1.  **Synchronization Triangle (Job–Batch–Machine):** Multiple Jobs (J1, J2, J3) converge on a Batch (B1), which then competes for a Machine (OVEN-1). This creates a barrier where the slowest job dictates the start time for all.
2.  **Hidden Contention Chain (Job–Tool–Machine):** A Job (J4) requires a Machine (CNC-2) and a Tool (FIX-A). The Machine may be idle, but the Tool is held by another Job (J3), creating invisible waiting time not captured in Machine utilization logs.

## 4. What flattening misses

Flattening object-centric data into a single case notion (e.g., Job-ID) inevitably projects multi-dimensional interactions onto a single timeline, creating artifacts that mask the true sources of delay.

*   **Job Flattening:**
    *   *Visible:* Sequence of activities per job (Release -> Process -> Pack).
    *   *Hidden:* Waiting caused by other jobs (Batching), tools (FIX-A), or lots (L7). The `Quarantine Lot` event is missing because the extraction pipeline only pulled events directly linked to the Job ID at source.
    *   *Misleading Conclusion:* The DFG shows `Inspect -> Pack` taking 1.0h median. This likely includes waiting for shipment consolidation (S1), misclassifying logistics wait as processing time.

*   **Machine Flattening:**
    *   *Visible:* Machine state (Idle, Processing, Setup).
    *   *Hidden:* *Why* the machine is idle. CNC-2 shows 54% utilization with 48min gaps. It hides that the machine was ready but blocked by FIX-A (Tool).
    *   *Misleading Conclusion:* Managers see low utilization (54-58%) and assume capacity is available, leading to overloading recommendations that would worsen tool contention.

*   **Batch Flattening:**
    *   *Visible:* Batch start and end times.
    *   *Hidden:* Individual job readiness variance. It hides that J1 was ready 4 hours before B1 started.
    *   *Misleading Conclusion:* Batch cycle time looks normal, masking the massive waiting time incurred by early-ready jobs.

*   **Tool Flattening:**
    *   *Visible:* Tool usage events (if logged).
    *   *Hidden:* Often tools are not treated as first-class objects in ERP. Here, FIX-A holding is inferred from Job acquire/release, not a dedicated Tool log.
    *   *Misleading Conclusion:* Tool contention is invisible in standard OEE reports.

*   **ComponentLot Flattening:**
    *   *Visible:* Lot movement and status changes.
    *   *Hidden:* Impact on specific Jobs. The link between L7 Quarantine and J5 delay is broken in the Job log.
    *   *Misleading Conclusion:* Quality delays appear as isolated incidents rather than systemic coupling risks.

*   **Shipment Flattening:**
    *   *Visible:* Shipment creation to dispatch.
    *   *Hidden:* Waiting time of individual jobs within the shipment.
    *   *Misleading Conclusion:* Shipment cycle time looks efficient (0.8h + 0.3h), but J1 sat packed for 6 hours.

**Coexistence of Low Utilization and Long Waiting:**
This phenomenon is the hallmark of **resource coupling**. A Machine (CNC-2) can be idle (low utilization) because it is waiting for a Tool (FIX-A) held by another Job (J3). The Job (J4) waits, but the Machine log records "Idle," not "Blocked." Traditional flattenings attribute this to lack of work, whereas object-centric analysis reveals it as a synchronization failure between complementary resources.

## 5. Object-lifecycle evidence

**Narrative 1: The Batch Penalty (Job–Component–Batch–Machine)**
*   **Temporal Precedence:** J1 requires C1 (08:00). C1 belongs to L8. J1 becomes ready for batch at 08:10.
*   **Resource Feasibility:** OVEN-1 is available. However, B1 requires J2 and J3 to be ready.
*   **Policy Constraints:** B1 cannot start until all constituent jobs are present (Batching Policy).
*   **Causal Speculation:** J1 incurs 3h 55m waiting not because OVEN-1 is busy, but because J3 was not ready until 11:55. The dependency on L8 (shared with J3) suggests component availability might have influenced J3's readiness, coupling J1's delay to J3's supply chain.

**Narrative 2: The Hidden Tool Block (Job–Machine–Tool–Shipment)**
*   **Temporal Precedence:** J4 arrives at CNC-2 (09:50). J3 holds FIX-A (09:00–11:40).
*   **Resource Feasibility:** CNC-2 is idle (10:05–10:47), yet J4 cannot start.
*   **Policy Constraints:** FIX-A is exclusive; no parallel fixation allowed.
*   **Causal Speculation:** J4's delay pushes its completion to 19:10. Because S1 consolidates J1 and J4, J4's tool-induced delay directly causes J1's shipment delay (dispatch 19:25). A tool bottleneck cascades into a logistics bottleneck.

**Narrative 3: The Quality Coupling (Job–ComponentLot–Batch–Shipment)**
*   **Temporal Precedence:** L7 Quarantine event (10:20). J5 requires C5 (from L7).
*   **Resource Feasibility:** J5 is ready for B2, but C5 is quarantined.

*   **Causal Speculation:** J5 waits until L7 Release (13:50). This delays B2 start to 14:50. Consequently, S3 (containing J5) is delayed. The quality status of a passive object (Lot) dictates the flow of active objects (Jobs), creating non-linear delays.

3.  **Job Ready Flag:** Explicit event `Job Ready for Next Stage` to distinguish processing time from waiting time.
4.  **Override Reason Code:** Log why J2 bypassed L7 quarantine (e.g., "Customer Expedite") to understand policy flexibility.
5.  **Shipment Split Permission:** Boolean field indicating if a Shipment can be partially dispatched.
6.  **Calendar/Shift Data:** To distinguish between idle time due to breaks vs. idle time due to blocking.

By integrating these fields, the object-centric model transitions from inferring delays (e.g., "CNC idle implies Tool wait") to observing them directly (e.g., "CNC idle AND Tool Status = Busy"), thereby validating the ranked bottleneck hypotheses.
