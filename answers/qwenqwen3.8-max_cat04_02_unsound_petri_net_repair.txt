```
import copy
import pm4py

def place_names(marking):
    return ", ".join(f"{p.name}:{marking[p]}" for p in sorted(marking, key=lambda x: x.name)) or "empty"

def transition_by_name(net, name):
    return next((t for t in net.transitions if t.name == name), None)

def fire_named_transition(net, marking, name):
    enabled = pm4py.get_enabled_transitions(net, marking)
    if not any(t.name == name for t in enabled):
        print(f"  {name} NOT enabled; marking = {place_names(marking)}")
        return marking, False
    t = transition_by_name(net, name)
    if t is None: ...
    for arc in t.in_arcs:
       p=arc.source
       if marking.get(p,0) <= 0: ... return False
       marking[p] -= 1
       if marking[p] == 0: del marking[p]
    for arc in t.out_arcs:
       p=arc.target
       marking[p] = marking.get(p,0)+1
    print(f"  fired {name}; marking = {place_names(marking)}")
    return marking, True

def run_sequence(net, im, sequence, title):
    print(f"\nSequence: {title}")
    m = copy.deepcopy(im)
    print(f"  initial; marking = {place_names(m)}")
    for name in sequence:
       m, ok = fire_named_transition(net, m, name)
       if not ok: break
    return m

def exact_final(m, fm):
    places = set(m.keys()) | set(fm.keys())
    return all(m.get(p,0) == fm.get(p,0) for p in places)
```

# 1. Executive Verdict

The net is structurally a workflow net: it has a unique source, a unique sink, and every node lies on some source-to-sink path. It should **not** be expected to be sound. The principal defect is that `t_join_waived` has only `p_waived` as an input, so the waiver join ignores the mandatory analysis branch. After `t_waive_review`, `t_join_waived` and then `t_authorize` can fire while `p_analysis` still contains a token; if `t_analyze` fires earlier or later, `p_analysis_done` remains unconsumed. Thus waiver cases either authorize without analysis or cannot reach the exact final marking `{sink:1}`. Business consequence: cases can be authorized without mandatory analysis, and waiver cases leave residual state, so the process cannot reliably close.

# 4. Minimal-Repair Alternatives

Edit-cost model used below:

- add or remove one arc: cost `1`
- add or remove one place: cost `2`
- add or remove one transition: cost `3`
- rewiring an arc is counted as remove + add
- label or variable-name changes cost `0`
- marking changes are not used as repairs here

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|---|---|---:|---|---|---|
| R1: make waiver join wait for analysis | Add one arc: `p_analysis_done -> t_join_waived` | `1` | Mandatory analysis retained; standard and waiver remain distinct; original visible labels unchanged | On waiver path, `t_join_waived` now requires both `p_waived` and `p_analysis_done`; authorization cannot occur before analysis completion | Very low. If future edits allow both `p_review_done` and `p_waived` simultaneously, two joins could conflict, but current XOR over `p_review` prevents that |
| R2: policy change — waiver may bypass analysis | Add arc `p_analysis -> t_join_waived`; add silent transition `t_join_waived_done`; add arcs `p_waived -> t_join_waived_done`, `p_analysis_done -> t_join_waived_done`, `t_join_waived_done -> p_decision` | `1 + 3 + 3 = 7` | Standard review still requires analysis; waiver path becomes sound | Policy changed: after a waiver, the case may authorize without analysis by firing the modified `t_join_waived`, which consumes `p_analysis` and `p_waived`. If analysis was already performed, `t_join_waived_done` consumes `p_analysis_done` and `p_waived` | Accidental business-policy bypass of mandatory analysis; silent joins can make it harder to audit whether analysis was skipped or performed |
| R3: single normal join for both review outcomes | Remove arc `t_waive_review -> p_waived`; add arc `t_waive_review -> p_review_done`; remove arcs `p_waived -> t_join_waived` and `t_join_waived -> p_decision`; remove transition `t_join_waived`; remove place `p_waived` | `1 + 1 + 1 + 1 + 3 + 2 = 9` | Mandatory analysis retained; both review outcomes synchronize through `t_join_normal` | Waiver no longer has a separate `p_waived` state or separate waiver join; waiver and standard review converge earlier | Loss of explicit waiver marker after the review transition; distinguishability relies on the visible label of `t_waive_review` |

## Minimality justification

Under the stated cost model, **R1 is globally minimal** for preserving the original business policy.

- Zero edits cannot work because the original net is unsound.
- To preserve the policy that analysis is mandatory on the waiver path, the waiver path must consume `p_analysis_done` before producing `p_decision`.
- The existing waiver-path transition that produces `p_decision` is `t_join_waived`.
- Adding the missing input arc `p_analysis_done -> t_join_waived` costs `1`.
- Any alternative that adds a new place or transition costs at least `2` or `3` before arcs are added, so it cannot beat cost `1`.

Therefore R1 is the unique cost-1 intent-preserving repair.

R2 is not globally minimal because it changes the business policy. However, it is a minimal cheap repair for the explicitly changed policy “a waiver may bypass analysis.” After waiver, the net must be able to complete from two mutually exclusive analysis states:

- analysis not yet performed: token in `p_analysis`
- analysis performed: token in `p_analysis_done`

With ordinary Petri-net arcs, one transition cannot have alternative input places. Therefore at least one additional synchronization transition, or an equivalent skip transition, is required. R2 uses the existing `t_join_waived` as the “skip analysis” join by adding `p_analysis -> t_join_waived`, and adds one new transition for the “analysis already done” case. This costs `7`. A skip-transition variant conditioned on waiver would require at least one new transition plus self-loop or conditioning arcs for `p_waived`, and is not cheaper under this cost model.

R3 is not globally minimal either, but it is minimal for the constrained design choice “use one common review-done place and one common join.” To make waiver feed `t_join_normal`, `t_waive_review` must produce `p_review_done`. To keep the net a clean workflow net, the now-disconnected waiver place and waiver join should be removed. Under the explicit cost model, that costs `9`. There is no tie under this model: R1 is strictly cheaper than R2 and R3.

# 6. Diagnostic and Reachability Code

```python
import copy
import pm4py


def place_names(marking):
    """Return a stable printable representation of a marking."""
    if not marking:
        return "empty"
    return ", ".join(
        f"{p.name}:{marking[p]}"
        for p in sorted(marking, key=lambda x: x.name)
    )


def transition_by_name(net, name):
    """Return the transition with the given name, or None."""
    return next((t for t in net.transitions if t.name == name), None)


def exact_final(marking, final_marking):
    """True iff marking equals final_marking exactly."""
    places = set(marking.keys()) | set(final_marking.keys())
    return all(marking.get(p, 0) == final_marking.get(p, 0) for p in places)


def fire_named_transition(net, marking, name):
    """
    Fire a transition by name if it is enabled.

    This helper checks enabledness using pm4py.get_enabled_transitions
    and then manually moves tokens. It does not silently move tokens.
    """
    enabled = pm4py.get_enabled_transitions(net, marking)

    if not any(t.name == name for t in enabled):
        print(f"  {name} NOT enabled; marking = {place_names(marking)}")
        return marking, False

    t = transition_by_name(net, name)
    if t is None:
        print(f"  Transition {name} not found in net.")
        return marking, False

    # Consume input tokens.
    for arc in t.in_arcs:
        place = arc.source
        if marking.get(place, 0) <= 0:
            print(f"  Internal error: {name} enabled but no token in {place.name}.")
            return marking, False
        marking[place] -= 1
        if marking[place] == 0:
            del marking[place]

    # Produce output tokens.
    for arc in t.out_arcs:
        place = arc.target
        marking[place] = marking.get(place, 0) + 1

    print(f"  fired {name}; marking = {place_names(marking)}")
    return marking, True


def run_sequence(net, initial_marking, final_marking, sequence, title):
    """Fire a named-transition sequence and print the final comparison."""
    print(f"\nSequence: {title}")
    print(f"  requested sequence = {sequence}")

    marking = copy.deepcopy(initial_marking)
    print(f"  initial; marking = {place_names(marking)}")

    for name in sequence:
        marking, ok = fire_named_transition(net, marking, name)
        if not ok:
            break

    print(f"  exact final marking reached? {exact_final(marking, final_marking)}")
    return marking


def diagnose(net, initial_marking, final_marking, label):
    """Run the required PM4Py diagnostics on one net."""
    print(f"\n=== Diagnostics: {label} ===")

    try:
        is_wf = pm4py.check_is_workflow_net(net)
        print(f"check_is_workflow_net: {is_wf}")
    except Exception as exc:
        print(f"check_is_workflow_net raised: {exc}")

    try:
        sound_result = pm4py.check_soundness(
            net,
            initial_marking,
            final_marking,
            print_diagnostics=True
        )
        print(f"check_soundness result: {sound_result}")
    except Exception as exc:
        print(f"check_soundness raised: {exc}")

    try:
        enabled = pm4py.get_enabled_transitions(net, initial_marking)
        enabled_names = sorted(t.name for t in enabled)
        print(f"enabled transitions at initial marking: {enabled_names}")
    except Exception as exc:
        print(f"get_enabled_transitions raised: {exc}")

    try:
        rg = pm4py.convert_to_reachability_graph(net, initial_marking, final_marking)
        print(f"convert_to_reachability_graph returned: {type(rg).__name__}")
    except Exception as exc:
        print(f"convert_to_reachability_graph raised: {exc}")


# Diagnostics on original and repaired nets.
diagnose(net, im, fm, "original net")
diagnose(repaired_net, repaired_im, repaired_fm, "repaired net")

# Original counterexample: authorization before analysis on waiver path.

        "t_register",
        "t_split",
        "t_waive_review",
        "t_join_waived",
        "t_authorize",
        "t_analyze",
    ],
    "original waiver path, authorize before analyze"

# Original counterexample: analysis before authorization still leaves a token.
run_sequence(

        "t_join_waived",
        "t_authorize",
    ],
    "original waiver path, analyze before authorize"
)

# Repaired behavior: waiver path requires analysis before join/authorize.
run_sequence(
```

# 7. Repair Trade-Offs and Residual Risks

## Waiver and standard review distinguishability

With the selected repair, R1, waiver and standard review remain distinguishable:

- Standard review path uses `t_standard_review` and produces `p_review_done`.
- Waiver path uses `t_waive_review` and produces `p_waived`.
- The visible labels remain different: `Perform Standard Review` versus `Record Review Waiver`.

However, both joins are silent transitions. If an event log records only visible labels, the join itself will not appear. That is acceptable here because the preceding visible review transition already distinguishes the two alternatives.

Repair R3 reduces explicit distinguishability because it removes `p_waived` and makes waiver produce `p_review_done`. The visible transition label still distinguishes waiver from standard review, but the net no longer contains a separate waiver state after the review transition.

## Duplicate behavior and silent-transition confusion

R1 does not add new silent transitions. It only strengthens the existing silent `t_join_waived`. There is no duplicate visible behavior between standard review and waiver because the visible review transitions differ.

R2 adds another silent transition, `t_join_waived_done`. That creates a larger silent subnet and can make auditing harder: from visible labels alone, a waiver case with analysis and a waiver case without analysis may differ by the presence or absence of `Perform Analysis`, but the net’s internal choice between skip and analyzed synchronization is hidden. If the business needs an explicit audit of “analysis skipped under waiver,” R2 should use a visible skip transition or an explicit waiver-skip place.

## Soundness is not sufficient for business alignment

Soundness only proves that the net can complete properly, does not leave leftover tokens when it completes, and has no dead parts in the usual Petri-net sense. It does **not** prove that the net implements the intended business rule.

This is clearest with R2: R2 can be made sound, but it changes the policy by allowing waiver cases to bypass analysis. A sound model can still be legally wrong.

Therefore, conformance to the business rule should be checked separately, for example by:

- trace assertions,
- process-mining conformance checking,
- temporal rules such as “`Perform Analysis` must precede `Authorize Case`”,
- reachability checks that no path to `t_authorize` exists without a prior firing of `t_analyze`.

## Regression traces

Positive traces that should be accepted under the original mandatory-analysis policy:

```text
Register Case, Perform Analysis, Perform Standard Review, Authorize Case
Register Case, Perform Analysis, Record Review Waiver, Authorize Case
Register Case, Record Review Waiver, Perform Analysis, Authorize Case
```

The last one is allowed because analysis and review are started in parallel; the important rule is that authorization occurs only after both are complete.

Negative traces that should be rejected under the original mandatory-analysis policy:

```text
Register Case, Record Review Waiver, Authorize Case
Register Case, Perform Standard Review, Authorize Case
Register Case, Perform Analysis, Authorize Case
Register Case, Perform Analysis, Perform Standard Review, Record Review Waiver, Authorize Case
```

The first negative trace is the exact defect in the original net. The second misses analysis. The third misses a review outcome. The fourth attempts both review outcomes, which should be impossible because standard review and waiver are alternatives.

If R2 is adopted, the first trace becomes positive by policy change, but that policy change must be explicit.

## Detecting accidental bypass of mandatory analysis

For the selected repair R1, accidental bypass can be detected in several ways:

1. **Reachability check**: verify that no reachable marking enables `t_authorize` unless `t_analyze` has occurred earlier in that run.
2. **Trace constraint**: enforce that every case containing `Authorize Case` also contains `Perform Analysis` before it.
3. **Model invariant**: in R1, `t_join_waived` and `t_join_normal` both require `p_analysis_done`; therefore `p_decision` cannot be produced without prior analysis completion.
4. **Unit tests**: fire the original counterexample sequence against the repaired net and assert that `t_join_waived` is not enabled before `t_analyze`.
5. **Conformance checking**: align real event logs with the repaired model and flag cases where `Authorize Case` occurs without `Perform Analysis`.

# 8. Final Recommendation

Deploy **Repair R1**: add the missing arc `p_analysis_done -> t_join_waived`. It is the only cost-1 repair that preserves the stated business policy. Analysis remains mandatory, the waiver remains a separate review outcome, and the existing visible labels are unchanged. It fixes the precise defect by making the waiver join consume the analysis-completion token, so authorization on the waiver path cannot occur before analysis completion and no analysis token remains.

Use **Repair R3** as the fallback if architects prefer a single synchronization point rather than separate standard and waiver joins. R3 redirects the waiver outcome into `p_review_done` and removes the waiver-specific join. It is more invasive and loses the explicit `p_waived` state, but it retains mandatory analysis and is easy to explain: both review outcomes feed the same analysis-and-review join.

Repair R2 should not be the fallback unless the business explicitly changes the rule to allow waivers to bypass analysis. It is sound, but it implements a different policy. Therefore: R1 for production; R3 as a no-policy-change fallback; R2 only after explicit policy approval.
