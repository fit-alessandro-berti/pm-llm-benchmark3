The numerical inconsistency is substantive. For the listed variants and ordinary exact-fit semantics, April–May is **100% fitting**, June–July raw is **0%**, label mapping alone is **90/650 = 13.85%**, and mapping plus queue removal is **535/650 = 82.31%**. The June–July variants also imply **3,975/650 = 6.12 events per case**, versus the reported 6.3. Aggregation can remove timestamps and attributes, but cannot by itself explain these label-based exact-fit contradictions when counts exhaust the stated cohort. The staged summaries remain qualitative evidence pending reconciliation; their percentage-point changes are not established causal effect sizes.

A move on log is an unmatched recorded event; a visible move on model is a modeled action unmatched in the log. Thus a missing recorded `Compliance Check` normally requires a model move, despite the summary informally grouping “missing checks” under log moves. A model move for `Decision` can repair an ordering mismatch and does not prove that no decision occurred. Alternative optimal alignments may locate order-repair moves differently. Exact-fitting case percentage, average alignment fitness, native alignment cost, and precision must be reported separately.

The June collapse is best explained by several observation-layer interventions superimposed on a largely recognizable process. A renamed classification action produces a log move for `Risk Screen` and a model move for `Classify`. Gateway routing adds further log moves. Ingestion timestamps can place notification before decision, requiring an alignment to skip and reinsert an activity even when execution was correct. The reported staged improvements are directionally consistent with these mechanisms, although inconsistent aggregate populations or metric definitions prevent treating their numerical increments as causal estimates.

August adds a different mechanism: a policy-directed change in actual work without a corresponding normative-model revision. A correctly performed sign-off can therefore lower fitness. Allowing it improves replay, but an unconditional optional activity also accepts high-value cases without sign-off. Better fitness would then conceal a policy violation.

Residual missing compliance events have at least two explanations: a real bypass or an incomplete observation of a performed check. A visible model move identifies an unmet model obligation in the log; it does not establish employee intent. Overrides likewise require investigation because they are reported human actions, potentially legitimate routing corrections, whose recording changed later.

Stable appeals, approvals, and detected incidents provide only weak negative evidence about harmful process change. Rare violations can be consequential without moving aggregate rates; case mix, delayed appeals, immature follow-up, and incomplete detection can hide effects. Conversely, stable outcomes do not prove logging error, because legitimate sign-offs or harmless routing changes may leave outcomes similar. Source-level evidence and policy-aware case audits must separate these possibilities.

## 6. PM4Py reproduction and model-comparison code

This reconstruction uses every supplied variant and its frequency. Synthetic timestamps preserve the supplied string order and carry no timing evidence. There are no actual source sequence numbers, amounts, resources, or original event IDs in these tables, so the code does not fabricate their effects. The optional source-order path fails unless validation is explicitly asserted and complete unique sequence values are supplied. Precision comparisons use exactly the same normalized August–September cases.

```python
from collections import Counter
from copy import deepcopy
from datetime import datetime, timedelta, timezone
from numbers import Integral
import pm4py
from pm4py.objects.log.obj import EventLog, Trace

# Requires an installed PM4Py version exposing the named public APIs.
VARIANTS = {
    "Apr-May": [
        ("Receive,Classify,Standard Review,Decision,Notify", 380),
        ("Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify", 180),
        ("Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify", 40),
    ],
    "Jun-Jul": [
        ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 270),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 145),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 70),
        ("Receive,Risk Screen,Standard Review,Decision,Notify", 90),
        ("Receive,Classify,Queue Routed,Standard Review,Decision,Notify", 30),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 25),
        ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 20),
    ],
    "Aug-Sep": [
        ("Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify", 210),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify", 150),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify", 90),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify", 60),
        ("Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision", 45),
        ("Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify", 30),
        ("Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify", 35),
    ],
}

NORMATIVE_TEXT = """->(
    'Receive', 'Classify',
    X( *('Standard Review', 'Request Info'),
       ->('Enhanced Review', 'Compliance Check') ),
    'Decision', 'Notify'
)"""
CANDIDATE_TEXT = """->(
    'Receive', 'Classify',
    X( *('Standard Review', 'Request Info'),
       ->('Enhanced Review', 'Compliance Check') ),
    X(tau, 'Supervisor Sign-off'),
    'Decision', 'Notify'
)"""

normative_tree = pm4py.parse_process_tree(NORMATIVE_TEXT)
normative_net = pm4py.convert_to_petri_net(normative_tree)  # net, im, fm
candidate_tree = pm4py.parse_process_tree(CANDIDATE_TEXT)
candidate_net = pm4py.convert_to_petri_net(candidate_tree)
BASE = datetime(2000, 1, 1, tzinfo=timezone.utc)


def expand_variants(period, rows):
    strings = [text for text, count in rows for _ in range(count)]
    parsed = pm4py.parse_event_log_string(strings)
    log = pm4py.convert_to_event_log(parsed)
    assert len(log) == sum(count for _, count in rows)
    for case_index, trace in enumerate(log):
        trace.attributes["concept:name"] = f"{period}-{case_index + 1:04d}"
        trace.attributes["period"] = period
        for position, event in enumerate(trace):
            # Preserve the trace strings; these dates are analysis placeholders.
            event["time:timestamp"] = BASE + timedelta(
                days=case_index, seconds=position
            )
            event["timestamp:provenance"] = "synthetic_variant_position"
            event["variant:original_position"] = position
            event["label:original"] = event["concept:name"]
            # Deliberately do not invent source:sequence, case value, or resource.
    return log


def normalize(log, map_risk=True, remove_queue=False,
              order_by_source=False, source_sequence_validated=False):
    """Return a new business-event view; preserve input logs and event metadata.

    A validated source sequence must order all events within each case across
    relevant producers. Uniqueness alone does not establish that property.
    Source sequences in this optional path must be integer-valued.
    """
    if order_by_source and not source_sequence_validated:
        raise ValueError("Validate sequence scope, resets, and semantics first.")
    out = EventLog(attributes=deepcopy(log.attributes))
    for case_index, original in enumerate(log):
        events = [deepcopy(event) for event in original]
        if order_by_source:
            seq = [event.get("source:sequence") for event in events]
            if (any(not isinstance(value, Integral) or isinstance(value, bool)
                    for value in seq) or len(set(seq)) != len(seq)):
                raise ValueError("Need complete, unique integer source sequences.")
            events.sort(key=lambda event: event["source:sequence"])
        trace = Trace(attributes=deepcopy(original.attributes))
        removed = 0
        for event in events:
            if remove_queue and event["concept:name"] == "Queue Routed":
                removed += 1
                continue
            if map_risk and event["concept:name"] == "Risk Screen":
                event["label:before_mapping"] = "Risk Screen"
                event["concept:name"] = "Classify"
            # Manual Override and Supervisor Sign-off are intentionally retained.
            if order_by_source:
                # Preserve the incoming timestamp; make analysis time reflect
                # verified order so subsequent conversions cannot undo sorting.
                event["timestamp:before_source_sort"] = event["time:timestamp"]
                event["timestamp:prior_provenance"] = event.get(
                    "timestamp:provenance", "unspecified"
                )
                event["time:timestamp"] = BASE + timedelta(
                    days=case_index, seconds=len(trace)
                )
                event["timestamp:provenance"] = "synthetic_validated_source_order"
            trace.append(event)
        trace.attributes["normalization:queue_events_removed"] = removed
        out.append(trace)
    return out


def variant_counts(log):
    return Counter(tuple(event["concept:name"] for event in trace)
                   for trace in log)


def report(title, log, accepting_net):
    net, initial_marking, final_marking = accepting_net
    dfg, starts, ends = pm4py.discover_dfg(log)
    diagnostics = pm4py.conformance_diagnostics_alignments(
        log, net, initial_marking, final_marking
    )
    if any(item is None for item in diagnostics):
        raise RuntimeError("Alignment failed; do not silently drop cases.")
    fitness = pm4py.fitness_alignments(
        log, net, initial_marking, final_marking
    )
    log_moves, visible_model_moves = Counter(), Counter()
    for item in diagnostics:
        # Default public alignment representation: (log label, model label).
        # '>>' means no move on that side; None denotes a silent model label.
        for log_label, model_label in item["alignment"]:
            if model_label == ">>" and log_label not in (">>", None):
                log_moves[log_label] += 1
            elif log_label == ">>" and model_label not in (">>", None):
                visible_model_moves[model_label] += 1
    print("\n" + title)
    print("cases:", len(log), "events:", sum(map(len, log)))
    print("variants:", variant_counts(log).most_common())
    print("frequency DFG:", sorted(dfg.items()))
    print("start/end frequencies:", dict(starts), dict(ends))
    print("alignment fitness:", fitness)
    print("mean native alignment cost:",
          sum(item["cost"] for item in diagnostics) / len(diagnostics))
    print("moves on log:", log_moves.most_common())
    print("visible moves on model:", visible_model_moves.most_common())
    return {"fitness": fitness, "diagnostics": diagnostics, "dfg": dfg}


print("PM4Py version:", pm4py.__version__)
print("Synthetic trace-position timestamps only; no timing or release-date inference.")
print("Default alignment costs are held fixed across comparisons.")
print("Native costs need not equal the question's unspecified mean-cost scale.")

logs = {period: expand_variants(period, rows)
        for period, rows in VARIANTS.items()}
normalized_logs, results = {}, {}
for period, log in logs.items():
    results[(period, "raw")] = report(
        f"{period}: raw / normative", log, normative_net

    if period != "Apr-May":
        mapped = normalize(log, map_risk=True, remove_queue=False)
        results[(period, "mapped")] = report(
```

## 7. Provisional conclusion

The primary explanation for the measured collapse is a combination of changed event representation, added technical events, and unreliable ordering, followed by an outdated model after the August policy change. The classification rename and queue insertion explain widespread mismatches without requiring widespread changes in employees' work. The ETL change supplies a credible mechanism for false notification-order violations. New sign-offs are plausibly legitimate process changes that the original model penalizes.

Confidence is high that these mechanisms materially distort conformance, and high that the August model lacks a required policy dimension. Confidence is only moderate in their relative contribution to the reported percentage decline: the supplied variant tables and alignment summaries cannot all describe the same exact-fit evaluation. Report reconciliation is necessary before assigning quantitative responsibility to teams or releases.

A real compliance problem may remain. There are 55 enhanced-review cases without recorded checks, unexplained overrides, and an unknown number of policy-applicable high-value cases lacking sign-off. Confidence that some residual deviations merit urgent investigation is high; confidence that the missing checks establish actual employee bypass is low to moderate, approximately 35% as a provisional judgment. The enhanced-review missing-check rate decreases between periods, so the counts do not establish worsening behavior. Stable outcomes provide limited reassurance because detection and follow-up are incomplete.

IT should reconcile extract/report lineage, preserve source identifiers and timestamp provenance, validate the label mapping, exclude proven technical events from the business view, and verify source ordering. Process owners should version the policy model, establish sign-off applicability and timing, and define the authorized meaning of overrides. Compliance should audit all 55 missing-check cases where feasible, test high-value sign-off coverage and actor permissions, and classify findings as confirmed violations, confirmed recording defects, or unresolved.

We must not yet claim that employees caused the collapse, that all reversals are timestamp errors, that all overrides are harmless, or that improved optional-model fitness proves policy compliance. Nor should the old model be relaxed to permit missing compliance checks simply because those omissions occur in the log.

## 8. Model-governance recommendation

1. **Version policy and models together.** Store effective dates, applicability rules, approvals, model hashes, and migration rules for in-flight cases; retain prior versions so each case is evaluated against the appropriate obligation.
2. **Contract event semantics.** Maintain stable business activity identifiers independently of UI text, with documented lifecycle meaning, producer, actor identity, schema version, and tested label mappings; require semantic review when releases alter emissions.
3. **Define a technical-event policy.** Classify events by provenance and business obligation, retain an immutable raw view, and version filters for the business conformance view; never remove human actions such as overrides merely to improve fitness.
4. **Preserve timestamp and order provenance.** Keep occurrence, ingestion, and processing times distinct, retain sequence scope and source IDs, validate clock/sequence behavior, and represent unresolved ordering explicitly instead of sorting toward the normative model.
5. **Enforce data-aware constraints.** Couple control-flow conformance with policy-effective claim values, mandatory sign-off above EUR 50,000, and applicable resource authorizations; quarantine missing attributes and treat an optional sign-off model as an exploratory comparison.
6. **Validate after every relevant release.** Run paired checks on fixed representative cohorts and audited cases, reconciling variants, frequency DFGs, alignment moves, fitness, precision, event completeness, and mature outcomes; investigate deviations before changing the policy model or attributing fault.
