# 1. Assumptions and notation

A1. I use the reported five-minute-rounded timestamps as the central reconstruction. Any duration computed from two reported timestamps has an additional rounding envelope of roughly ±5 minutes, because each endpoint may have moved by up to ±2.5 minutes. I do not repeat that rounding band in every table cell; the tabulated values are reported-minute estimates or reported-minute feasibility ranges.

A2. Time intervals are treated as half-open intervals: queue or service occupancy over [start, end). A completion at a reported time releases the resource before another activity starting at the same reported time is counted as active. This avoids treating C1’s P07 end at 11:00 and P09 start at 11:00 as a physical overlap. For snapshots “at 14:00,” I mean just before 14:00, because open and waiting cases are still present at the observation boundary.

A3. Queue entry for S1 is `arrival_s1`. Queue entry for S2 is `s1_end`. A blank S2 start/end after completed S1 means waiting in the S2 queue at 14:00. A blank S1 start/end means waiting in the S1 queue at 14:00.

A4. S1 has two available resources, I1 and I2, throughout 08:00–14:00, so the nominal available S1 capacity is 720 resource-minutes. S2 has C1 available for 360 minutes and C2 available for 345 minutes because of the 10:55–11:10 outage, so the nominal available S2 capacity is 705 resource-minutes.

A5. I impose no FIFO assumption. Several observations, especially in S2, are compatible with non-FIFO assignment, resource specialization, priority, or rounded-time artifacts.

A6. Missing starts are not replaced by one value. The reported-time no-overlap feasible intervals are:

| missing start | feasible reported-time interval | main constraints                                                                                 |
| ------------- | ------------------------------: | ------------------------------------------------------------------------------------------------ |
| P05 S2 start  |                     09:45–10:15 | after P05 enters S2 at 09:25 and after C1 finishes P03 at 09:45; no later than P05 S2 completion |
| P07 S1 start  |                     09:25–10:00 | after P07 arrival and after I1 finishes P05 at 09:25; no later than P07 S1 completion            |
| P11 S2 start  |                     12:00–12:25 | after P11 enters S2 at 11:05, after C2 finishes P08 at 12:00, and before P11 S2 completion       |
| P15 S1 start  |                     11:40–12:15 | after P15 arrival and after I1 finishes P13 at 11:40; no later than P15 S1 completion            |

A7. Because no positive minimum service time is supplied, a mathematical lower bound of zero service time is possible for a missing-start activity if its start is placed at its completion time. That is not operationally likely, but it is the strict lower bound under the supplied information. Sensitivity scenarios below show how conclusions change when starts are placed early, service-consistently, or late.

A8. OPEN activities are right-censored. For P21 in S1, P15 in S2, and P17 in S2, I count only elapsed active service through 14:00. Their final service times and final station sojourns are unknown and at least as large as the elapsed values.

# 2. Reconstruction method and formulas

For case i at station k:

| quantity                     | definition                                                                                                                            |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| queue entry                  | Eᵢ₁ = `arrival_s1`; Eᵢ₂ = `s1_end`                                                                                                    |
| active start                 | Bᵢₖ = station start timestamp, if known or imputed within a feasible interval                                                         |
| completion                   | Dᵢₖ = station end timestamp, if completed                                                                                             |
| queue waiting time           | Wᵢₖ = Bᵢₖ − Eᵢₖ if the start is known; if still waiting at 14:00, Wᵢₖ ≥ 14:00 − Eᵢₖ                                                   |
| active service time          | Sᵢₖ = Dᵢₖ − Bᵢₖ if completed; for OPEN, elapsed service = 14:00 − Bᵢₖ and final service is larger or equal                            |
| station sojourn              | Tᵢₖ = Dᵢₖ − Eᵢₖ if completed; if not completed, observed/truncated station sojourn = 14:00 − Eᵢₖ and final sojourn is larger or equal |
| completed-case total sojourn | `s2_end − arrival_s1`, only for completed cases                                                                                       |

For missing starts, if a feasible start interval is [L, U], then queue waiting is in [L − E, U − E] and service time is in [D − U, D − L]. These are reported-time bounds before adding the separate ±5-minute endpoint-rounding envelope.

For WIP, I calculate interval areas directly:

| quantity                           | definition                                                                         |
| ---------------------------------- | ---------------------------------------------------------------------------------- |
| station queue length Qₖ(t)         | number of cases with Eᵢₖ ≤ t < Bᵢₖ, or Eᵢₖ ≤ t < 14:00 for cases still waiting     |
| station active-service count Aₖ(t) | number of cases with Bᵢₖ ≤ t < min(Dᵢₖ, 14:00)                                     |
| station WIP Nₖ(t)                  | Qₖ(t) + Aₖ(t)                                                                      |
| mean queue/WIP                     | time integral over 08:00–14:00 divided by 360 minutes                              |
| peak queue/WIP                     | maximum over intervals between event times under the simultaneous-event convention |

Throughput and arrival rates are simple counts per subperiod divided by subperiod length. I use half-open hourly bins, except the final bin ends at 14:00.

Utilization is active busy time divided by available resource-minutes. For S2, the C2 outage is removed from the denominator. Utilization is based on observed and elapsed active service, not only completed services.

The Little’s-Law check is used only as a finite-window accounting check, not as a steady-state claim. Because there is no initial WIP at either station in the supplied window, the identity

L̄ = entry rate × mean truncated station sojourn

holds when censored cases are included through 14:00. Using only completed cases is not defensible here because both stations have positive WIP at 14:00.

# 5. Bottleneck and temporal interpretation

The evidence is most consistent with a time-varying bottleneck, not a single stationary bottleneck.

Early in the window, S1 is the visible bottleneck because external arrivals are concentrated. Thirteen cases arrive before 10:00, while only six S1 services complete in the same two hours. S1 queue length reaches six by 10:00 and its total WIP reaches eight around 11:00. With two inspectors and typical reported S1 service times around 25–30 minutes, S1’s practical output capacity is roughly four to five cases per hour under ideal continuous loading, but the early arrival pulse is about 6.5 cases per hour. That mismatch explains the early S1 queue buildup.

Structurally, S2 has the longer active service times. Completed S2 services cluster around 40–50 minutes, while S1 services cluster around 25–30 minutes. With the same nominal number of resources, that makes S2 the lower-capacity station once S1 begins feeding it steadily. This shows up later: by 13:00, S2 WIP is comparable to S1 WIP; just before 14:00, S2 has four waiting cases and two open services, while S1 has one waiting case and one open service.

The C2 outage from 10:55 to 11:10 matters, but it is not sufficient by itself to explain the entire late S2 backlog. It removes 15 resource-minutes, roughly a fraction of one normal calibration. It occurs at a bad time, when S2 already has queued work, and it likely delays a C2 start that otherwise might have happened soon after P06 ended at 10:50. However, the late S2 backlog also reflects longer calibration service times and the wave of S1 completions after 12:00.

There is one notable late S1 ambiguity: P22 is still waiting for S1 at 14:00 even though I2 appears to finish P20 at 13:45. Without inventing an explanation, this weakens any claim that S1 remains fully capacity-constrained at the very end. It could be due to unlogged non-case work, a policy not to start a new inspection near the observation boundary, a case-specific eligibility constraint, delayed logging, or simple rounding/data extraction artifacts.

# 6. Missingness, censoring, and sensitivity analysis

The three scenarios below alter only the four missing starts. They do not alter known station entries, completions, open-service starts, or waiting-at-14:00 statuses.

| P11’s S2 service split is especially fragile                       | Sensitive; a normal 40-minute C2 service would overlap P08 unless there is logging error, assistance, or another unrecorded mechanism |

Rounding adds a second layer of uncertainty. A five-minute apparent gap may be a true gap, a near-continuous handoff, or a small overlap in actual time. This mainly affects fine-grained resource-conflict interpretation and exact peak timing. It does not change the larger picture: S1 absorbs the early arrival surge, and S2 becomes the main late-window accumulation point.

Right censoring is more consequential than timestamp rounding for end-of-window conclusions. P15, P17, P21, P16, P18, P19, P20, and P22 all have unfinished station sojourns. Any completed-case-only estimate of mean waiting, service, throughput, or total sojourn is therefore biased toward cases that finished within the window.

                        "case": r["case"], "station": station, "kind": "queue",
                        "start": entry, "end": start, "resource": None,
                        "status": "queue_observed_or_imputed"
                    })
                if not pd.isna(end) and end > start:
                    rows.append({
                        "case": r["case"], "station": station, "kind": "service",
                        "start": start, "end": end, "resource": r[f"{station.lower()}_resource"],
                        "status": end_kind
                    })
    out = pd.DataFrame(rows)
    out["duration_min"] = out.apply(lambda x: minutes_between(x["start"], x["end"]), axis=1)
    return out

def summarize_station_intervals(intervals, station):
    x = intervals[intervals["station"] == station].copy()
    area_queue = x.loc[x["kind"] == "queue", "duration_min"].sum()
    area_service = x.loc[x["kind"] == "service", "duration_min"].sum()
    area_wip = area_queue + area_service

    points = sorted(set([OBS_START, OBS_END]) | set(x["start"]) | set(x["end"]))
    peak_q = peak_s = peak_w = 0
    for a, b in zip(points[:-1], points[1:]):
        if b <= a:
            continue
        mid = a + (b - a) / 2
        q = ((x["kind"] == "queue") & (x["start"] <= mid) & (mid < x["end"])).sum()
        s = ((x["kind"] == "service") & (x["start"] <= mid) & (mid < x["end"])).sum()
        peak_q = max(peak_q, int(q))
        peak_s = max(peak_s, int(s))
        peak_w = max(peak_w, int(q + s))

    available = 720 if station == "S1" else 705
    return {
        "station": station,
        "queue_area_min": area_queue,
        "busy_service_min": area_service,
        "wip_area_min": area_wip,
        "avg_queue": area_queue / WINDOW_MIN,
        "avg_service": area_service / WINDOW_MIN,
        "avg_wip": area_wip / WINDOW_MIN,
        "peak_queue": peak_q,
        "peak_service": peak_s,
        "peak_wip": peak_w,
        "utilization": area_service / available,
    }

summary_rows = []
for scen in scenario_starts:
    intervals = station_intervals(scen)
    for st in ["S1", "S2"]:
        row = summarize_station_intervals(intervals, st)
        row["scenario"] = scen
        summary_rows.append(row)

station_summary = pd.DataFrame(summary_rows)

    station_summary[

         "avg_wip", "peak_queue", "peak_wip", "utilization"]
    ].round(3).to_string(index=False)
)

def count_times(series, a, b, include_right=False):
    vals = series.dropna()
    if include_right:
        return int(((a <= vals) & (vals <= b)).sum())
    return int(((a <= vals) & (vals < b)).sum())
