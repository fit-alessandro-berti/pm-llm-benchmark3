## 6. Revised Normative Architecture

**Layered design**
1. **Control-flow (POWL)** – primary ordering: Register  Sanctions  (optional RMI loop)  XOR{standard manual, low-risk auto, emergency provisional, reject}  Notify  Close. Concurrent checks represented per branch where lawful.

5. **Explicit scope rules** – (a) Rejected leads: separate intake partial order (RegisterSanctionsRejectNotifyClose) not requiring Quality; (b) Reactivation: submodel with silent Register/Quality if prior cert valid; (c) Withdrawals: silent closure.

**Placement**
- POWL: activity order, XOR branches, loop approximation, concurrency.

- Pandas/data checks: eligibility snapshot, amount cap, date windows, label mapping.

## 7. PM4Py Model and Data Proposal

```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition
from pm4py.objects.process_tree.obj import Operator

# Atomic transitions
register = Transition(label="Register_Supplier")
sanctions = Transition(label="Sanctions_Check")
quality = Transition(label="Quality_Review")
manual = Transition(label="Manual_Procurement_Approval")
auto = Transition(label="Auto_Approve")
activate = Transition(label="Activate_Supplier")
reject = Transition(label="Reject_Supplier")
notify = Transition(label="Notify_Requester")
close = Transition(label="Close_Case")
rmi = Transition(label="Request_More_Info")
silent = Transition(label="", silent=True)

# RMI repeatable approximation via LOOP (limitation: exit condition is silent, not data-guided)
rmi_loop = OperatorPOWL(operator=Operator.LOOP, children=[rmi, silent])

# Standard manual branch: quality -> manual -> activate (sanctions already before branch)
std_branch = StrictPartialOrder(nodes=[quality, manual, activate])
std_branch.order.add_edge(quality, manual)
std_branch.order.add_edge(manual, activate)

# Low-risk auto branch (PD-3 style): auto -> activate -> quality (quality after activate)
auto_branch = StrictPartialOrder(nodes=[auto, activate, quality])
auto_branch.order.add_edge(auto, activate)
auto_branch.order.add_edge(activate, quality)

# Emergency provisional branch (FD-7 style): activate -> manual & quality retrospective
emg_branch = StrictPartialOrder(nodes=[activate, manual, quality])
emg_branch.order.add_edge(activate, manual)
emg_branch.order.add_edge(activate, quality)

# Reject branch (no quality)
decision = OperatorPOWL(operator=Operator.XOR,
                        children=[std_branch, auto_branch, emg_branch, reject])

# Root partial order
root = StrictPartialOrder(nodes=[register, sanctions, rmi_loop, decision, notify, close])
root.order.add_edge(register, sanctions)
root.order.add_edge(sanctions, rmi_loop)
root.order.add_edge(rmi_loop, decision)
root.order.add_edge(decision, notify)
root.order.add_edge(notify, close)

M_rev = root
```

Concurrency of sanctions and quality for the standard route is partially represented (sanctions before all branches; quality ordered inside each branch). A separate rejected-lead intake model and reactivation submodel are omitted from `M_rev` and handled via scope rules.
