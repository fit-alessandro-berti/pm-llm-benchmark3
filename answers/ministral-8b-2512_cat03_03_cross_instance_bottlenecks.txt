## **1. Interaction-Graph Description**

### **Node Types and Edges**
The system’s dependencies emerge from **shared resources, synchronization constraints, and policy-driven couplings** rather than individual job bottlenecks. Key node types and edges include:

- **Jobs (J1–J6)**: Primary work items with discrete processing steps.
- **Components (C1–C6)**: Input materials, often grouped into **ComponentLots (L7, L8)**.
- **Machines (CNC-2, OVEN-1, TEST-1)**: Process components but may share tools or batches.
- **Tools (FIX-A, RACK-7, CAL-3)**: Critical for machine operations; some are batch-specific (e.g., RACK-7).
- **Batches (B1, B2)**: Group jobs for simultaneous processing (e.g., OVEN-1 cures multiple jobs at once).
- **Shipments (S1–S3)**: Consolidate jobs for dispatch, creating artificial waiting.

### **Edge Types and Qualifiers**
| **Source**       | **Qualifier**       | **Target**          | **Observation Type**          | **Inferred?** |
|------------------|---------------------|---------------------|--------------------------------|---------------|
| Job  Component  | `requires`          | Component           | Direct (OCEL event)            | No            |
| ComponentLot  Job | `affects` (via release) | Job               | Indirect (lot release delays) | Yes           |
| Job  Batch      | `batches`           | Batch              | Direct (OCEL event)            | No            |
| Batch  Machine  | `uses`              | Machine            | Direct (OCEL event)            | No            |
| Job  Tool       | `acquires`          | Tool               | Inferred (gap analysis)        | Yes           |
| Shipment  Job   | `consolidates`      | Job               | Direct (OCEL event)            | No            |
| Tool  Machine   | `required_for`      | Machine            | Policy constraint             | Yes           |

### **Higher-Order Motifs**
1. **Batch Synchronization Chain (Job  Batch  Machine  Tool)**
   - *Example*: J1, J2, J3 all wait for **B1** on **OVEN-1** using **RACK-7**, even though J3 is ready 10 minutes earlier. The **3h+ delay** for J1/J2 is not due to machine capacity but **batch synchronization**.
   - *Graph*: `J1  B1  OVEN-1  RACK-7` and `J2  B1  OVEN-1  RACK-7`.

2. **Tool Contention with Machine Idle Gaps**
   - *Example*: **FIX-A** is held by J3 (09:00–11:40), forcing J4 to wait despite CNC-2 being idle (10:05–10:47). The **47-minute gap** is misleading because it doesn’t account for **tool acquisition delays**.
   - *Graph*: `J3  FIX-A  CNC-2` (inferred) and `J4  CNC-2` (blocked by FIX-A).

3. **Lot Release Coupling (ComponentLot  Job  Shipment)**
   - *Example*: **L7** (containing C2 and C5) is quarantined (10:20) and released (13:50). J2 proceeds via supervisor override, but **J5 waits until release**, delaying shipment **S3**.
   - *Graph*: `L7  J2 (override)  S2` vs. `L7  J5  S3` (delayed).

4. **Shipment Consolidation Bottleneck**
   - *Example*: **S1** (J1 + J4) dispatches at 19:25, even though J1 was packed at 13:30. The **5.5-hour wait** is due to **consolidation policy**, not machine delays.
   - *Graph*: `J1  S1  Dispatch` (with hidden `J4  S1` delay).

5. **Calibration Tool as a Serial Constraint**
   - *Example*: **CAL-3** recalibration (16:35–17:20) forces **J6** to wait despite TEST-1 being idle (16:35–17:25). The **1-hour gap** is not machine-related but **tool-dependent**.
   - *Graph*: `J5  TEST-1  CAL-3  J6`.

### **Compact Edge-List Representation**
```
# Direct OCEL edges (observed)
J1  requires  C1
J2  requires  C2
J3  requires  C3
L7  contains  C2
L7  contains  C5
B1  batches  J1, J2, J3
OVEN-1  uses  B1 (via RACK-7)
TEST-1  uses  CAL-3 (for J5, J6)
S1  consolidates  J1, J4

# Inferred edges (policy/resource constraints)
J3  acquires  FIX-A (09:00–11:40)
J4  blocked_by  FIX-A (due to J3’s hold)
L7  delays  J5 (until 13:50 release)
J6  blocked_by  CAL-3 (due to J5’s test)
```

## **2. Quantitative Delay Decomposition**

### **1. Batch Synchronization Delay (J1/J2 in B1)**
- **Observed**: J1 ready at 08:10, batch starts at 12:05  **3h55m wait**.
- **Counterfactual**: If jobs processed individually, J1 could start at 08:10 + machine setup (assume 15m)  **15m delay**.
- **Avoidable delay**: **3h40m** (synchronization overhead).

### **2. FIX-A Contention Delay (J4)**
- **Observed**: J4 arrives at CNC-2 at 09:50, but starts at 11:45  **1h55m wait**.
- **Counterfactual**: If FIX-A were available immediately, J4 could start at 09:50 + setup (15m)  **15m delay**.
- **Avoidable delay**: **1h40m** (tool hold by J3).

### **3. Shipment Consolidation Delay (J1 in S1)**
- **Observed**: J1 packed at 13:30, S1 dispatches at 19:25  **5h55m wait**.
- **Counterfactual**: If J1 shipped immediately, dispatch would be at 13:30 + dispatch time (30m)  **30m delay**.
- **Avoidable delay**: **5h25m** (consolidation policy).

### **4. CAL-3 Recalibration Delay (J6)**
- **Observed**: J6 ready at 16:05, tests at 17:25  **1h20m wait**.
- **Counterfactual**: If CAL-3 were ready immediately, J6 could test at 16:05 + test time (25m)  **25m delay**.
- **Avoidable delay**: **1h55m** (tool recalibration after J5).

### **5. ComponentLot Release Delay (J5)**
- **Observed**: J5 ready at 14:40, but waits until 14:50 (batch start) + lot release (13:50)  **0m direct wait, but 1h10m indirect delay**.
- **Counterfactual**: If lot release were immediate, J5 could start at 14:40 + setup (15m)  **15m delay**.
- **Avoidable delay**: **1h10m** (lot quarantine policy).

## **4. What Flattening Misses**

| **Flattening View** | **Makes Visible**                          | **Hides/Duplicates**                          | **Misleading Conclusion**                     |
|---------------------|--------------------------------------------|-----------------------------------------------|---------------------------------------------|
| **Job-flattened**   | Direct job-machine steps.                 | Batch synchronization, tool contention.      | "No bottleneck" (ignores hidden waits).     |
| **Machine-flattened** | Machine utilization.                     | Tool-dependent delays, batch effects.         | "Low utilization = no issue" (misleading).  |
| **Batch-flattened** | Batch start/end times.                    | Individual job readiness.                    | "Batch is efficient" (hides J1/J2 delays).   |
| **Tool-flattened**  | Tool acquisition/release.                  | Indirect tool blocking (e.g., FIX-A for J4). | "Tools are available" (if not tracked).      |
| **ComponentLot**    | Lot quarantine/release.                   | Job-specific impact (J5 vs. J2).             | "Lots are processed in time" (if not linked to jobs). |
| **Shipment-flattened** | Dispatch times.                          | Consolidation delays (J1 waits for J4).      | "Shipments are fast" (ignores intra-shipment waits). |

### **Why Low Machine Utilization Coexists with Long Waits**
- **Tools and batches** act as **serial constraints** (e.g., RACK-7 forces batch synchronization).
- **Shipment consolidation** creates **artificial waiting** even if machines are idle.
- **Data gaps** (e.g., missing lot-job links) obscure true dependencies.

## **5. Object-Lifecycle Evidence (Causal Narratives)**

### **Narrative 1: Batch Synchronization + Tool Contention**
- **Temporal Precedence**:
  - J3 acquires **FIX-A at 09:00**, holding it until 11:40.
  - J4 arrives at CNC-2 at 09:50 but cannot start until 11:45 (after FIX-A release).
- **Resource Feasibility**:
  - CNC-2 is idle (10:05–10:47), but **tool unavailability** blocks J4.
- **Policy Constraints**:
  - No explicit "wait for tool" event; tool holds are inferred.
- **Causal Speculation**:
  - If FIX-A were pre-positioned or shared differently, J4 could start sooner.

### **Narrative 2: Lot Release + Shipment Delay**
- **Temporal Precedence**:
  - **L7 quarantined at 10:20**, released at 13:50.
  - J5 is ready at 14:40 but waits until 14:50 (batch start) + lot release.
- **Resource Feasibility**:
  - OVEN-1 is idle (12:55–14:50), but **lot policy** delays J5.
- **Policy Constraints**:
  - Supervisor override for J2 bypasses lot release, but **J5 is not overridden**.
- **Causal Speculation**:
  - If lot release were automated or decoupled from batch start, J5 could proceed faster.

### **Narrative 3: Calibration Tool + Shipment Consolidation**
- **Temporal Precedence**:
  - J5 tests at 16:10–16:35, requiring **CAL-3 recalibration at 16:35–17:20**.
  - J6 is ready at 16:05 but must wait until 17:25.
- **Resource Feasibility**:
  - TEST-1 is idle (16:35–17:25), but **tool recalibration** blocks J6.
- **Policy Constraints**:
  - No explicit "calibration queue"; recalibration is implicit.
- **Causal Speculation**:
  - If CAL-3 were pre-calibrated or shared across shifts, J6 could test sooner.

## **7. PM4Py Analysis Outline**

```python
import pm4py

# Load OCEL data
ocel = pm4py.read_xes("manufacturing_process.xes")  # or OCEL format

# --- Object-Centric Interaction Summary ---
interactions = pm4py.ocel_objects_interactions_summary(ocel)
print("Top interactions by frequency:")
for obj_type, interactions_df in interactions.items():
    print(f"\n{obj_type}:")
    print(interactions_df.sort_values("frequency", ascending=False).head(3))

# --- Discover Object-Centric Graph ---
oc_graph = pm4py.discover_objects_graph(ocel)
pm4py.view_graph(oc_graph, format="png", layout="dot")

# --- Compare Batch vs. Job Flattening ---
job_flattened = pm4py.ocel_flattening(ocel, flattening_type="job")
batch_flattened = pm4py.ocel_flattening(ocel, flattening_type="batch")

# Extract performance metrics
job_dfg = pm4py.discover_performance_dfg(job_flattened)
batch_dfg = pm4py.discover_performance_dfg(batch_flattened)

print("\nJob-flattened median times (first 3 edges):")
for edge, meta in job_dfg.edges(data=True):
    print(f"{edge[0]} -> {edge[1]}: {meta['median']}h")

print("\nBatch-flattened median times (first 3 edges):")
for edge, meta in batch_dfg.edges(data=True):
    print(f"{edge[0]} -> {edge[1]}: {meta['median']}h")

# --- Object-Temporal Graph (OTG) for Batch Synchronization ---
otg = pm4py.discover_otg(ocel, parameters={"object_types": ["Job", "Batch"]})
pm4py.view_graph(otg, format="png", layout="dot")

# --- Extract Features for Tool Contention ---
features = pm4py.extract_ocel_features(ocel, parameters={"object_types": ["Job", "Tool"]})
print("\nTool acquisition delays (top 3):")
for job, tool_delay in features["job_tool_delays"].items():
    if tool_delay > 3600:  # >1 hour
        print(f"{job}: {tool_delay/3600:.1f} hours")

# --- Compare Frequency Metrics ---
job_machine_freq = pm4py.ocel_objects_interactions_summary(ocel)["Job"]["Machine"]["frequency"]
tool_machine_freq = pm4py.ocel_objects_interactions_summary(ocel)["Tool"]["Machine"]["frequency"]
print(f"\nJob-Machine interactions: {job_machine_freq}")
print(f"Tool-Machine interactions: {tool_machine_freq} (hidden delays)")
```

## **8. Falsification and Additional Data**

### **Observations That Weaken Top-Ranked Explanations**
1. **Batch synchronization is not the primary issue**:
   - If splitting batches reduces J1/J2 wait by <20%, batch synchronization is less critical.
2. **Tools are not the bottleneck**:
   - If J4’s delay is due to machine failure (not FIX-A), tool contention is overstated.
3. **Lot release is policy-driven, not resource-bound**:
   - If J5’s delay is due to manual inspection (not lot quarantine), the mechanism shifts.
4. **Shipment consolidation is not the main delay**:
   - If J1’s wait is due to downstream supplier (not S1), consolidation is irrelevant.
5. **Machine capacity is actually limiting**:
   - If OVEN-1 fails during B2, batch synchronization is secondary.
6. **Data gaps are not the issue**:
   - If explicit tool-hold events exist, inferred delays are validated.

### **Additional Data Fields to Discriminate**
1. **Tool acquisition timestamps** (not just release).
2. **Lot inspection reasons** (quarantine vs. manual hold).
3. **Shipment partner readiness times** (not just dispatch).
4. **Machine setup times per batch** (to separate setup vs. synchronization).
5. **Supervisor override logs** (to distinguish policy vs. resource delays).
6. **Tool calibration schedules** (to predict recalibration events).

---
**Conclusion**: The system’s unpredictability stems from **hidden synchronization (batches, lots, shipments) and implicit tool constraints**, not individual machine bottlenecks. Flattening obscures these dependencies, requiring object-centric analysis to uncover true coupling mechanisms.
