# Analysis of the Parallel Review with Waiver Petri Net

## # 1. Executive Verdict

The net is a workflow net (has unique source/sink and all nodes are on source-to-sink paths). It should not be expected to be sound due to a synchronization defect in the waiver path. The principal defect is that the waiver path (`p_waived  join_waived  p_decision`) bypasses the mandatory analysis synchronization (`join_normal`), allowing authorization before analysis completes. The business consequence is that cases could be authorized without completing the mandatory analysis when using the waiver path.

## # 2. Structural Diagnosis

| Element or subnet | Intended role | Actual structural effect | Potential symptom |
|-------------------|---------------|---------------------------|-------------------|
| Split (t_split) | Parallelize analysis and review | Correctly splits tokens to both branches | No issue |
| Standard review path | Parallel review option | Correctly synchronizes with analysis at join_normal | No issue |
| Waiver path | Alternative review option | Bypasses analysis synchronization entirely | Tokens can reach authorization without analysis completion |
| join_normal | Synchronize analysis and standard review | Only handles standard review path | Cannot handle waiver case |
| join_waived | Synchronize waiver path | Only handles waiver path | Cannot synchronize with analysis |
| Initial marking (im) | Start case registration | Correct single token in source | No issue |
| Final marking (fm) | Case completion | Correct single token in sink | No issue when path is correct |
| Source-to-sink paths | All nodes should be reachable | Waiver path nodes are reachable but defective | Potential unsound behavior |

## # 3. Marking-Based Counterexample

**Firing sequence exposing the defect:**
`t_register  t_split  t_analyze  t_waive_review  t_join_waived  t_authorize`

**Marking progression:**

| Step | Fired transition | Resulting nonzero marking | Enabled transitions | Observation |
|------|------------------|---------------------------|----------------------|-------------|
| 0 | - | {source:1} | {t_register} | Initial state |
| 1 | t_register | {p_ready:1} | {t_split} | Case registered |
| 2 | t_split | {p_analysis:1, p_review:1} | {t_analyze, t_standard_review, t_waive_review} | Parallel branches started |
| 3 | t_analyze | {p_analysis_done:1, p_review:1} | {t_standard_review, t_waive_review} | Analysis complete |
| 4 | t_waive_review | {p_analysis_done:1, p_waived:1} | {t_join_waived} | Waiver recorded |
| 5 | t_join_waived | {p_decision:1} | {t_authorize} | Bypassed analysis sync! |
| 6 | t_authorize | {sink:1} | {} | Case authorized without proper synchronization |

**Key observation:** The waiver path allows authorization to occur after analysis completes but without waiting for the standard review path to complete. More critically, it bypasses the synchronization requirement that both analysis and review must complete before authorization.

## # 4. Minimal-Repair Alternatives

| Repair | Exact edits | Edit cost | Preserved intent | Changed behavior | New risk |
|--------|-------------|-----------|------------------|------------------|----------|
| **Repair A: Waiver Synchronization** | Remove `p_waived  join_waived` and `join_waived  p_decision` arcs. Add `p_analysis_done  join_normal` and `p_waived  join_normal` arcs. Remove `join_waived` transition. | 4 arc changes (2 removed, 2 added) | Mandatory analysis preserved on all paths. Maintains parallel review options. | Waiver path now properly synchronizes with analysis at join_normal. | None identified |
| **Repair B: Dedicated Waiver Join** | Add new transition `join_all` and place `p_all_done`. Modify arcs: `p_analysis_done  join_all`, `p_review_done  join_all`, `p_waived  join_all`. Remove `join_normal` and `join_waived`. | 4 arc changes (2 removed, 4 added) + 1 new transition + 1 new place | Maintains all original paths but with proper synchronization | More complex structure with silent transitions | Potential confusion from additional silent transition |

**Justification of minimality:**
Both repairs require exactly 4 arc modifications (counting additions and removals equally). Repair A is more minimal as it preserves more of the original structure while achieving the same behavioral correction. Repair B introduces new elements which increases structural complexity without providing additional business value.

## # 5. Corrected PM4Py Code (Repair A)

```python
import pm4py
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

repaired_net = PetriNet("parallel_review_with_waiver_repaired")

source = PetriNet.Place("source")
p_ready = PetriNet.Place("p_ready")
p_analysis = PetriNet.Place("p_analysis")
p_review = PetriNet.Place("p_review")
p_analysis_done = PetriNet.Place("p_analysis_done")
p_review_done = PetriNet.Place("p_review_done")
p_waived = PetriNet.Place("p_waived")
p_decision = PetriNet.Place("p_decision")
sink = PetriNet.Place("sink")

for p in {
    source, p_ready, p_analysis, p_review, p_analysis_done,
    p_review_done, p_waived, p_decision, sink
}:
    repaired_net.places.add(p)

register = PetriNet.Transition("t_register", "Register Case")
split = PetriNet.Transition("t_split", None)
analyze = PetriNet.Transition("t_analyze", "Perform Analysis")
standard_review = PetriNet.Transition("t_standard_review", "Perform Standard Review")
waive_review = PetriNet.Transition("t_waive_review", "Record Review Waiver")
join_normal = PetriNet.Transition("t_join_normal", None)
authorize = PetriNet.Transition("t_authorize", "Authorize Case")

for t in {
    register, split, analyze, standard_review, waive_review,
    join_normal, authorize
}:
    repaired_net.transitions.add(t)

# Original arcs
petri_utils.add_arc_from_to(source, register, repaired_net)
petri_utils.add_arc_from_to(register, p_ready, repaired_net)
petri_utils.add_arc_from_to(p_ready, split, repaired_net)
petri_utils.add_arc_from_to(split, p_analysis, repaired_net)
petri_utils.add_arc_from_to(split, p_review, repaired_net)

petri_utils.add_arc_from_to(p_analysis, analyze, repaired_net)
petri_utils.add_arc_from_to(analyze, p_analysis_done, repaired_net)

petri_utils.add_arc_from_to(p_review, standard_review, repaired_net)
petri_utils.add_arc_from_to(standard_review, p_review_done, repaired_net)

petri_utils.add_arc_from_to(p_review, waive_review, repaired_net)
petri_utils.add_arc_from_to(waive_review, p_waived, repaired_net)

# Modified synchronization for waiver path
petri_utils.add_arc_from_to(p_analysis_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_review_done, join_normal, repaired_net)
petri_utils.add_arc_from_to(p_waived, join_normal, repaired_net)  # New arc for waiver path

petri_utils.add_arc_from_to(join_normal, p_decision, repaired_net)
petri_utils.add_arc_from_to(p_decision, authorize, repaired_net)
petri_utils.add_arc_from_to(authorize, sink, repaired_net)

# Remove the problematic waiver synchronization arcs
waiver_arcs = [
    (p_waived, join_waived),
    (join_waived, p_decision)
]
for fr, to in waiver_arcs:
    if petri_utils.remove_arc_from_to(fr, to, repaired_net) is None:
        pass  # Arc didn't exist in our construction

repaired_im = Marking()
repaired_im[source] = 1
repaired_fm = Marking()
repaired_fm[sink] = 1
```

## # 6. Diagnostic and Reachability Code

```python
def fire_transition(net, marking, transition_name):
    """Helper to fire a named transition and print the resulting marking"""
    from pm4py.objects.petri_net.utils import reachability_graph
    enabled = pm4py.get_enabled_transitions(net, marking)
    trans = next((t for t in net.transitions if t.name == transition_name), None)
    if trans not in enabled:
        print(f"Cannot fire {transition_name} - not enabled")
        return None
    new_marking = reachability_graph.construct_reachability_graph(net).get_marking(transition_name)
    print(f"Fired {transition_name}: {dict(new_marking)}")
    return new_marking

# Original net diagnostics
print("=== ORIGINAL NET DIAGNOSTICS ===")
print("Is workflow net:", pm4py.check_is_workflow_net(net))
print("\nSoundness check:")
pm4py.check_soundness(net, im, fm, print_diagnostics=True)

print("\nOriginal net counterexample sequence:")
m = im.copy()
m = fire_transition(net, m, "t_register")
m = fire_transition(net, m, "t_split")
m = fire_transition(net, m, "t_analyze")
m = fire_transition(net, m, "t_waive_review")
m = fire_transition(net, m, "t_join_waived")
print("Final marking after waiver path:", dict(m))
print("Can authorize?", "t_authorize" in [t.name for t in pm4py.get_enabled_transitions(net, m)])
print("Final marking reached?", m == fm)

# Repaired net diagnostics
print("\n=== REPAIRED NET DIAGNOSTICS ===")
print("Is workflow net:", pm4py.check_is_workflow_net(repaired_net))
print("\nSoundness check:")
pm4py.check_soundness(repaired_net, repaired_im, repaired_fm, print_diagnostics=True)

print("\nRepaired net waiver path sequence:")
m = repaired_im.copy()
m = fire_transition(repaired_net, m, "t_register")
m = fire_transition(repaired_net, m, "t_split")
m = fire_transition(repaired_net, m, "t_analyze")
m = fire_transition(repaired_net, m, "t_waiver_review")
m = fire_transition(repaired_net, m, "t_join_normal")
m = fire_transition(repaired_net, m, "t_authorize")
print("Final marking after waiver path:", dict(m))
print("Final marking reached?", m == repaired_fm)
```

**Expected qualitative differences:**
1. Original net will fail soundness checks with diagnostics showing improper completion
2. Repaired net will pass soundness checks
3. The counterexample sequence will show that authorization can occur prematurely in the original net
4. The repaired net will properly synchronize all paths before authorization

## # 7. Repair Trade-Offs and Residual Risks

**Waiver and standard review distinguishability:**
- Both remain clearly distinguishable in Repair A as they follow different paths to the same synchronization point
- The business logic of choosing waiver vs standard review is preserved

**Silent transitions:**
- Repair A eliminates the silent `join_waived` transition, reducing potential confusion
- The remaining `join_normal` transition is necessary for synchronization

**Soundness vs business alignment:**
- Soundness alone doesn't guarantee business rule alignment - we must verify that:
  - Analysis is always mandatory
  - Both review types properly synchronize
  - No paths bypass required steps

**Regression testing requirements:**
Positive traces to test:
1. Standard path: register  analyze  standard_review  authorize
2. Waiver path: register  analyze  waive_review  authorize
3. Both paths with tokens in different orders

Negative traces to test:
1. Attempt to authorize without analysis
2. Attempt to waive without analysis
3. Any path that reaches sink with tokens remaining elsewhere

**Detecting bypass of mandatory analysis:**
- Add monitoring for:
  - Tokens in `p_analysis` place that never progress to `p_analysis_done`
  - Transitions `t_standard_review` or `t_waive_review` firing before `t_analyze`
  - Any path to `p_decision` that didn't come through `p_analysis_done`

## # 8. Final Recommendation

**Deployment choice:** Repair A (waiver synchronization) is recommended for deployment as the primary solution because:
1. It achieves the minimal edit cost (4 arc changes) while preserving all business requirements
2. It maintains the simplest possible structure with no additional silent transitions
3. It clearly distinguishes between waiver and standard review paths while ensuring proper synchronization
4. The behavioral change is precisely targeted at the defect without introducing new complexity

**Fallback option:** Repair B (dedicated waiver join) serves as a good fallback because:
1. It provides an alternative synchronization approach that might be preferred if future requirements change
2. It maintains the same edit cost while being structurally different
3. It offers a more explicit synchronization point for the waiver path

Both repairs satisfy the business intent of mandatory analysis while properly synchronizing all paths before authorization. The choice between them should be based on which structure better fits the organization's modeling conventions and potential future extensions.
