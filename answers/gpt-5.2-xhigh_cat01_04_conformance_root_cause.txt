## 3. Causal-abductive explanation

```text
UI_release -> recorded_labels, rollout_fraction, logging_contract
policy_change -> true_process, normative_model_obsolescence, recorded_labels
ETL_change -> recorded_order, timestamp_provenance, events_missing_resource

true_process -> recorded_labels, recorded_order, business_outcomes
normative_model -> alignment_moves, measured_fitness
recorded_labels -> alignment_moves
recorded_order -> alignment_moves
event_missingness -> recorded_labels, alignment_moves
rollout_fraction -> recorded_labels, event_missingness
high_value_attribute -> policy_change_effect_size, signoff_frequency
policy_change_effect_size -> true_process
incident_detection_gap -> business_outcomes_observed, noncompliance_visibility
alignment_moves -> measured_fitness
measured_fitness -> governance_reactions, (weakly) business_outcomes_observed
```

The pattern is best explained by **stacked measurement and governance shocks**. In June–July, the log ceased to match the normative control‑flow mainly because instrumentation changed: `Classify` was relabeled to `Risk Screen`, a new gateway emitted `Queue Routed`, and (critically) the ETL began ordering `Decision`/`Notify` by warehouse ingestion time. Those three mechanisms create exactly the observed alignment signatures: many “moves on log” for unseen activities, plus apparent `Notify`‑before‑`Decision`. The staged recovery of fitness (32%→58%→81%→89%) after label mapping, technical‑event filtering, and source‑sequence ordering is strong abductive evidence that the **conformance collapse is largely an artifact of label/semantic drift and timestamp provenance**, not a sudden behavioral breakdown.

In August–September, a **real policy change** adds `Supervisor Sign-off` for high‑value claims, but the normative model remained unchanged; the candidate model that permits optional sign‑off explains much of the remaining drop. After these corrections, the residual deviations concentrate on `Manual Override` and a small set of enhanced reviews without recorded `Compliance Check`, which could be true bypasses or missing events. Stable aggregate outcomes (appeals/approval) neither prove “only data issues” nor rule out noncompliance: outcomes are coarse, detection is incomplete, and localized control failures can exist without moving top‑line rates—especially if they affect a narrow stratum (e.g., high‑value claims) or are offset by compensating behaviors.

## 6. PM4Py reproduction and model-comparison code

```python
import pm4py

# NOTE: This script uses variant aggregates (no timestamps), so it cannot reproduce
# ordering defects caused by ingestion timestamps. It demonstrates the logic of
# conformance/model comparison on the supplied variant-frequency tables.

# 1) Encode the normative process tree
norm_tree_str = "->( 'Receive', 'Classify', X( *( 'Standard Review', 'Request Info' ), ->( 'Enhanced Review', 'Compliance Check' ) ), 'Decision', 'Notify' )"
norm_tree = pm4py.parse_process_tree(norm_tree_str)

# 2) Convert to an accepting Petri net
norm_net, norm_im, norm_fm = pm4py.convert_to_petri_net(norm_tree)

# 3) Expand variant-frequency tables into logs using parse_event_log_string
apr_may_variants = {
    "Receive,Classify,Standard Review,Decision,Notify": 380,
    "Receive,Classify,Enhanced Review,Compliance Check,Decision,Notify": 180,
    "Receive,Classify,Standard Review,Request Info,Standard Review,Decision,Notify": 40,
}

jun_jul_variants = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 270,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 145,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 70,
    "Receive,Risk Screen,Standard Review,Decision,Notify": 90,
    "Receive,Classify,Queue Routed,Standard Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 25,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 20,
}

aug_sep_variants = {
    "Receive,Risk Screen,Queue Routed,Standard Review,Decision,Notify": 210,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Supervisor Sign-off,Decision,Notify": 150,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Compliance Check,Decision,Notify": 90,
    "Receive,Risk Screen,Queue Routed,Standard Review,Supervisor Sign-off,Decision,Notify": 60,
    "Receive,Risk Screen,Queue Routed,Standard Review,Notify,Decision": 45,
    "Receive,Risk Screen,Queue Routed,Enhanced Review,Decision,Notify": 30,
    "Receive,Risk Screen,Queue Routed,Manual Override,Standard Review,Decision,Notify": 35,
}

def expand_variants_to_string(variant_counts: dict) -> str:
    lines = []
    for trace, n in variant_counts.items():
        lines.extend([trace] * int(n))
    return "\n".join(lines)

def parse_variants_as_log(variant_counts: dict):
    s = expand_variants_to_string(variant_counts)
    return pm4py.parse_event_log_string(s)

apr_log_raw = parse_variants_as_log(apr_may_variants)
jun_log_raw = parse_variants_as_log(jun_jul_variants)
aug_log_raw = parse_variants_as_log(aug_sep_variants)

# 4) Discover DFGs with pm4py.discover_dfg
def top_dfg_edges(log, k=8):
    dfg_res = pm4py.discover_dfg(log)
    dfg = dfg_res[0] if isinstance(dfg_res, tuple) else dfg_res
    return sorted(dfg.items(), key=lambda x: -x[1])[:k]

# 5) Compute alignment diagnostics and fitness
def alignment_report(log, net, im, fm, label):
    aligns = pm4py.conformance_diagnostics_alignments(log, net, im, fm)
    costs = [a.get("cost", 0) for a in aligns]
    mean_cost = sum(costs) / max(1, len(costs))
    fitting_pct = 100.0 * sum(1 for c in costs if c == 0) / max(1, len(costs))
    fit = pm4py.fitness_alignments(log, net, im, fm)
    log_fitness = fit.get("log_fitness", None)
    print(f"\n[{label}] traces={len(log)}  mean_alignment_cost={mean_cost:.3f}  perfect_cost0%={fitting_pct:.1f}  log_fitness={log_fitness}")

def precision_report(log, net, im, fm, label):
    try:
        prec = pm4py.precision_alignments(log, net, im, fm)
        print(f"[{label}] precision_alignments={prec}")
    except Exception as e:
        print(f"[{label}] precision_alignments unavailable ({e})")

# 6) Normalization pipeline: map Risk Screen -> Classify, optionally remove Queue Routed
LABEL_MAP = {"Risk Screen": "Classify"}

def normalize_log(log, map_risk=True, drop_queue=False):
    # Works with PM4Py EventLog objects (list-like of list-like traces of dict-like events).
    new_log = []
    for trace in log:
        new_trace = []
        for ev in trace:
            ev2 = dict(ev)
            name = ev2.get("concept:name")
            if map_risk and name in LABEL_MAP:
                name = LABEL_MAP[name]
            if drop_queue and name == "Queue Routed":
                continue
            ev2["concept:name"] = name
            new_trace.append(ev2)
        new_log.append(new_trace)
    return new_log

def run_suite(period_label, log_raw):
    print(f"\n=== {period_label} ===")
    print("Top DFG edges (raw):", top_dfg_edges(log_raw))
    alignment_report(log_raw, norm_net, norm_im, norm_fm, f"{period_label} raw vs normative")

    log_norm = normalize_log(log_raw, map_risk=True, drop_queue=False)
    print("Top DFG edges (label-mapped):", top_dfg_edges(log_norm))
    alignment_report(log_norm, norm_net, norm_im, norm_fm, f"{period_label} label-mapped vs normative")

    log_norm2 = normalize_log(log_raw, map_risk=True, drop_queue=True)
    print("Top DFG edges (label-mapped + no Queue Routed):", top_dfg_edges(log_norm2))
    alignment_report(log_norm2, norm_net, norm_im, norm_fm, f"{period_label} mapped+no-queue vs normative")
    return log_norm2

_ = run_suite("Apr-May", apr_log_raw)
jun_norm = run_suite("Jun-Jul", jun_log_raw)
aug_norm = run_suite("Aug-Sep", aug_log_raw)

# 8) Candidate process tree permitting an optional Supervisor Sign-off
cand_tree_str = "->( 'Receive', 'Classify', X( *( 'Standard Review', 'Request Info' ), ->( 'Enhanced Review', 'Compliance Check' ) ), X( tau, 'Supervisor Sign-off' ), 'Decision', 'Notify' )"
cand_tree = pm4py.parse_process_tree(cand_tree_str)
cand_net, cand_im, cand_fm = pm4py.convert_to_petri_net(cand_tree)

print("\n=== Aug-Sep model comparison (using mapped+no-queue log) ===")
alignment_report(aug_norm, norm_net, norm_im, norm_fm, "Aug-Sep vs normative")
precision_report(aug_norm, norm_net, norm_im, norm_fm, "Aug-Sep vs normative")
alignment_report(aug_norm, cand_net, cand_im, cand_fm, "Aug-Sep vs candidate (optional sign-off)")
precision_report(aug_norm, cand_net, cand_im, cand_fm, "Aug-Sep vs candidate (optional sign-off)")

# 9) Caveats
print("\nCAVEATS:")
print("- The optional-sign-off candidate is control-flow only; it cannot enforce the EUR 50,000 condition without using case attributes.")
print("- Improving alignment fitness by adding optional behavior can reduce precision (the model may overgeneralize).")
print("- Variant aggregates omit timestamps; ordering defects (e.g., ingestion-time inversions) require the original timestamped/sequence-attributed log.")
```

## 7. Provisional conclusion

The **primary explanation for the measured conformance collapse** is a compounded instrumentation/provenance shift beginning in early June: (i) `Classify` was relabeled as `Risk Screen`, (ii) the gateway inserted a technical `Queue Routed` event, and (iii) the ETL began ordering `Decision` and `Notify` using warehouse ingestion time, producing apparent `Notify`‑before‑`Decision`. The alignment summaries show a classic “measurement artifact” signature: fitness is extremely low on the raw log (32%) but recovers stepwise when each suspected defect is corrected (58% after label mapping, 81% after technical-event removal, 89% after ordering by source sequence). This staged recovery is hard to reconcile with a sudden, large behavioral breakdown and strongly indicates that most of the “drop” is **not a real operational regression**. Confidence in this explanation: **high (≈0.8)**.

Separately, there is credible evidence that the **normative model became obsolete** in August because a real policy introduced `Supervisor Sign-off` for high‑value claims (>€50k) while the conformance model remained unchanged. The appearance of sign-off in frequent Aug-Sep variants/DFG edges and the improvement under a candidate sign-off‑permitting model support this. However, allowing sign-off as purely optional risks inflating fitness by overgeneralizing; the correct representation is likely **data-aware** (conditioned on claim amount). Confidence that model obsolescence contributes materially in Aug-Sep: **moderate-high (≈0.65)**.

Whether a **real compliance problem** remains is unresolved. The enhanced-review traces without a recorded `Compliance Check` could be true bypasses (noncompliance) or missing events due to extraction defects. Aggregate stability in appeals/approval does not exonerate the process (signals are coarse and detection incomplete), but it also argues against widespread noncompliance as the main driver. Confidence that there is a nontrivial residual compliance risk requiring investigation: **medium (≈0.4)**.

Immediate actions: **IT** should reinstate source-proven ordering (timestamps/sequence), publish an event-semantic contract, and segregate technical events; **process owners** should version and update the normative model (including sign-off with attribute logic) and run post-release conformance regression checks; **compliance** should run a targeted audit of “missing check” cases using cross-system evidence before attributing blame. What must not be claimed yet: that employees broadly became noncompliant, that improved fitness proves compliance, or that sign-off is “optional for everyone” rather than value-conditioned.

## 8. Model-governance recommendation

1. Maintain **versioned normative models** tied to policy effective dates, with an explicit change calendar and deprecation rules; never reuse a model version across policy regimes without a documented migration.
2. Establish an **event-semantic contract** (activity taxonomy + stable identifiers) so UI label changes map via a controlled crosswalk; require release notes to declare semantic vs cosmetic changes and provide mapping tables.
3. Define a **technical-event policy**: classify events as business vs technical at capture time, keep technical events in a separate stream or flagged dimension, and prevent them from entering control-flow conformance unless explicitly justified.
4. Enforce **timestamp provenance rules**: store and prefer source-system timestamps/sequence numbers; prohibit ordering by ingestion time for conformance; implement automated checks for inversions and missing monotonicity per case.
5. Use **data-aware constraints** when policy depends on attributes (e.g., >€50k sign-off): capture required attributes, validate them, and represent constraints in conformance (not as unconditional optional control-flow).
6. Run **post-release validation** on canary logs: regression tests on variants/DFGs, alignment move distributions, fitness *and* precision, plus a small manual audit/provenance check before declaring operational noncompliance or process drift.
