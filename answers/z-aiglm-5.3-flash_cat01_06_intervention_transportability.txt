## 6. Candidate Site B intervention

**Modified intervention: "conditional trigger-based parallelism" (two treatment modes).**

- **Eligibility rules.** Mode T1 (true dual ownership) only where: (i) all required documents are digital and validated at registration, and (ii) the case-management twin-ticket mode is certified (see below). Mode T2 everywhere else: create Identity Check immediately; create the Document Check task automatically within minutes of Originals Receipt completion — never at registration for the 62% originals cases. Exclusions during Phase 1: supplemented/remediation cases re-entering the loop (handled by loop rules, not fresh parallelism).
- **Concurrency permissions.** Identity Check  (waiting-for-or-receiving Originals); Identity Check  Document Check where eligible; "assessment-readiness" checklist preparation may run in parallel under document-reviewer responsibility (not assessment duties).
- **Statutory prerequisites (untouched).** Document Check execution strictly after Originals Receipt when originals required; Assessment strictly after both verifications complete (v-current versions); Legal Review after Assessment for all mandated classes; Request Supplement restarts document checking with a *new versioned* ticket.
- **Queue and WIP controls.** Per-pool caps before anything changes: identity 6, document 6, assessor 4 concurrently; daily treated-case release cap to smooth Assessment arrivals; fast lane reserved for the pilot stratum so treated cases cannot starve control cases.
- **Resource responsibilities.** Existing specialist pools retain ownership; a small cross-trained float (2 FTE max) balances spikes; document reviewers own the "release-on-arrival" trigger; legal queue monitored independently.
- **Legal/supplement handling.** Supplement creates Document-Check(v+1)  Assessment(v+1)  Legal Review chain; prior artifacts auto-locked read-only and old tickets invalidated; identity re-checked only when identity facts implicated.
- **Logging requirements.** Server-side immutable timestamps; late/back-filled entries flagged `backfilled=true`; store scheduled-vs-actual DC release time, lock-conflict events, task-creation source (auto/manual), and version lineage.

Compact partial-order specification (dependencies preserved):

```text
Register  IdentityCheck                                  # always
IF ¬originalsRequired:  Register  DocumentCheck          # concurrent with IdentityCheck
IF originalsRequired:   Register  OriginalsReceipt  DocumentCheck   # statute; IC  OR
IdentityCheck  AssessmentGate ;  DocumentCheck_v  AssessmentGate
AssessmentGate  Assessment
Assessment  ROUTE (data-dependent XOR)
ROUTE ordinary:        Assessment  XOR(Approve, Reject)
ROUTE legal-mandatory: Assessment  LegalReview  LOOP(
        do:   LegalReview  XOR(Approve, Reject),          # exit branch
        redo: RequestSupplement  DocumentCheck(v+1)  Assessment(v+1) )  # returns to do
(Approve | Reject)  Notify
```

The pilot separates mechanism failure from implementation failure by triangulating three evidence layers. First, fidelity indicators — share of eligible randomized cases receiving a second ticket within 15 minutes, proportion achieving verified concurrent intervals after stripping back-entered events, lock-conflict counts — establish whether the intervention was actually administered. Second, mediation indicators trace the causal chain: creation  true overlap  time-to-assessment-ready  cycle time. If fidelity is high (70%) yet endpoints do not move, the theory, not operations, failed for that stratum: freed hours are absorbed by assessment/legal queues or were never on the critical path; the correct response is rescoping eligibility or adding downstream capacity, not pushing harder. Third, the T2 arm arbitrates design: if T2 captures most of T1's benefit, B adopts cheap trigger-based handoff and abandons ownership-complication ambitions; if only T1 moves endpoints, true simultaneity matters and the IT investment is justified. Low fidelity flips the diagnosis: tickets late, dual work impossible, caps breached — implementation failed, effects are simply not estimable; fix tooling, staffing, or training and re-run. Pre-registering these rules prevents back-dated, fabricated overlap percentages from being read as success.

## 8. PM4Py model-construction code

```python
"""
Site A before/after process trees + Site B candidate POWL model.
Self-contained. Requires pm4py >= 2.7.x.
What the models deliberately CANNOT encode (see final printout):
data-dependent legal requirements, resource pools/capacities, WIP caps,
single-owner case locks, timestamps/back-entry, durations & queueing.
"""
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition
from pm4py.objects.process_tree.obj import Operator
from pm4py.algo.simulation.playout.petri_net import algorithm as playout_alg

# ----------------------------------------------------------------------
# 1) Site A BEFORE: strict sequence
# ----------------------------------------------------------------------
tree_a_before = pm4py.parse_process_tree(
    "-> ('Register', 'Identity Check', 'Document Check', "
    "'Assessment', X ('Approve', 'Reject'), 'Notify')")

# 2) Site A AFTER: parallel verification block
tree_a_after = pm4py.parse_process_tree(
    "-> ('Register', + ('Identity Check', 'Document Check'), "
    "'Assessment', X ('Approve', 'Reject'), 'Notify')")

net_a0, im_a0, fm_a0 = pm4py.convert_to_petri_net(tree_a_before)
net_a1, im_a1, fm_a1 = pm4py.convert_to_petri_net(tree_a_after)

for name, net, im, fm in [("A before", net_a0, im_a0, fm_a0),
                          ("A after ", net_a1, im_a1, fm_a1)]:
    wf = pm4py.check_is_workflow_net(net)
    snd = pm4py.check_soundness(net, im, fm)
    print(f"[Site {name}] places={len(net.places)} trans={len(net.transitions)} "
          f"arcs={len(net.arcs)} workflow-net={wf} sound={snd[0]}")

# ----------------------------------------------------------------------
# Helper constructors
# ----------------------------------------------------------------------
def T(label):
    return Transition(label=label)

def xor_decision():
    """Fresh Approve|Reject XOR (fresh instances per container)."""
    return OperatorPOWL(operator=Operator.XOR,
                        children=[T("Approve"), T("Reject")])

# ----------------------------------------------------------------------
# 3) Site B candidate built from POWL classes
#
# Structure:
#   top StrictPartialOrder:
#     Register; Identity Check; ROUTE-XOR -> {originals-path, digital-path};
#     Assessment; POST-ASSESS-XOR -> {legal-loop, ordinary-decision}; Notify
#   Explicit order edges make Assessment wait for BOTH identity and
#   document verification (AND-join semantics: all POWL predecessors of
#   Assessment must complete before Assessment runs).
#   originals-path  = SPO(Originals Receipt -> Document Check)   (statute)
#   digital-path    = single Document Check, concurrent with IC  (no edge to IC)
#   legal-loop      = LOOP(do = LegalReview -> Approve/Reject,
#                          redo = RequestSupplement -> DocCheck -> Assessment)
# ----------------------------------------------------------------------
t_register = T("Register")
t_ident    = T("Identity Check")
t_orec     = T("Originals Receipt")
t_docA     = T("Document Check")      # copies: single XOR route realizes
t_docB     = T("Document Check")      # data-dependent statute at language level
t_assess   = T("Assessment")
t_legal    = T("Legal Review")
t_suppl    = T("Request Supplement")
t_doc_rd   = T("Document Check")
t_ass_rd   = T("Assessment")
t_notify   = T("Notify")

# originals-required branch: statutory precedence encoded
orig_path = StrictPartialOrder(nodes=[t_orec, t_docA])
orig_path.add_edge(t_orec, t_docA)

# fully-digital branch: single document task; CONCURRENT with Identity Check
digital_path = StrictPartialOrder(nodes=[t_docB])

# Route is a language-level XOR standing in for the data-dependent rule;
# it CANNOT itself know whether originals are required (limitation).
route = OperatorPOWL(operator=Operator.XOR, children=[orig_path, digital_path])

# legal loop: do = legal review + verdict (exit), redo = supplement loop
verdict      = StrictPartialOrder(nodes=[t_legal, *(  # order: legal -> decision
                   []))]
verdict = StrictPartialOrder(nodes=[t_legal])
dec_in_legal = xor_decision()
verdict.add_edge(t_legal, dec_in_legal)

redo_chain = StrictPartialOrder(nodes=[t_suppl, t_doc_rd, t_ass_rd])
redo_chain.add_edge(t_suppl, t_doc_rd)
redo_chain.add_edge(t_doc_rd, t_ass_rd)

legal_loop = OperatorPOWL(operator=Operator.LOOP,
                          children=[verdict, redo_chain])

ordinary_decision = xor_decision()
post_assess = OperatorPOWL(operator=Operator.XOR,
                           children=[legal_loop, ordinary_decision])

# ---------------- top-level strict partial order ----------------
site_b = StrictPartialOrder(
    nodes=[t_register, t_ident, route, t_assess, post_assess, t_notify])

site_b.add_edge(t_register, t_ident)      # Rule 2
site_b.add_edge(t_register, route)        # route is concurrent with Identity Check
site_b.add_edge(t_ident, t_assess)        # ASSESSMENT WAITS FOR IDENTITY CHECK
site_b.add_edge(route, t_assess)          # ASSESSMENT WAITS FOR DOCUMENT CHECK
                                          # (whichever route fired completed it)
site_b.add_edge(t_assess, post_assess)    # Rules 6-7
site_b.add_edge(post_assess, t_notify)    # Rule 8

net_b, im_b, fm_b = pm4py.convert_to_petri_net(site_b)
wf_b = pm4py.check_is_workflow_net(net_b)
snd_b = pm4py.check_soundness(net_b, im_b, fm_b)
print(f"[Site B PO ] places={len(net_b.places)} trans={len(net_b.transitions)} "
      f"arcs={len(net_b.arcs)} workflow-net={wf_b} sound={snd_b[0]}")

# ----------------------------------------------------------------------
# Optional playout: print sample traces
# ----------------------------------------------------------------------
log_a1 = playout_alg.apply(net=net_a1, im=im_a1, fm=fm_a1, no_traces=4)
print("\nSample Site A-after traces:")
for tr in log_a1:
    print("  " + " | ".join(e["concept:name"] for e in tr))

log_b = playout_alg.apply(net=net_b, im=im_b, fm=fm_b, no_traces=8)
print("\nSample Site B candidate traces:")
for tr in log_b:
    print("  " + " | ".join(e["concept:name"] for e in tr))

# ----------------------------------------------------------------------
# Encoding limitations (explicit)
# ----------------------------------------------------------------------
print("""
NOT ENCODED BY THIS MODEL:
 1. Data-dependent legal requirement: the ROUTE/POST-ASSESS XOR abstracts
    'public-sector or high-value' as nondeterministic choice; real execution
    must bind it to case attributes (40% share, statutorily forced).
 2. Originals-required fraction (62%) likewise lives in data, not structure.
 3. Resource pools (4/7/3/2), WIP caps, and queue discipline: silent models
    have infinite servers and unlimited concurrency.
 4. The single-owner IT case lock and its back-entry workarounds: the model
    grants free simultaneous ownership of Identity/Document tasks.
 5. Durations, Originals Receipt delay variability, loop repetition counts,
    and rework probabilities: playout traces are untimed and unweighted.
""")
```

Note on structure: `route` nests two partial orders so that in the originals path `Originals Receipt  Document Check` is preserved (Rule 4), while in the digital path Document Check runs concurrently with Identity Check; because the block must complete before `Assessment` (order edges), Assessment always waits for both verifications — Rule 5 holds in both worlds.

## 9. Recommendation

**Decision: `conditional go`**

Transfer the *mechanism class*, not the intervention: eliminate avoidable serialization wherever verification inputs already exist, implemented at B as trigger-based release — instant dual-ticket only for fully digital cases, and Document Check released automatically within minutes of Originals Receipt everywhere else. Transfer also Site A's protective apparatus (per-reviewer WIP caps, disciplined queue hygiene) and its hard-won experimental lesson: randomize, freeze intake, distrust before/after deltas. Do **not** copy the blanket "create both tasks immediately after Register," which is illegal for 62% of B's cases and physically obstructed by the single-owner lock; do not import the expectation of a 9h median (roughly half of A's raw gain is attributable to the API upgrade, added reviewers, simpler incoming mix, and huddles); do not assume cross-trained flexibility that B's 4/7/3/2 silos lack; and do not bundle adjacent initiatives into the pilot window. The first subgroup should be fully digital, non-public-sector, low-to-medium-complexity claims (~15–23% of volume), where statutes add no gate and the lock can be legitimately sidestepped by a sanctioned two-ticket mode or the T2 automated-handoff design. Expected benefits: within-stratum median time-to-assessment-ready 2 to 3.4h; population median 0.6 to 1.3h initially; p90 neutral to mildly positive. Principal risks are bottleneck shifting into Assessment/Legal (mean improves, p90 degrades by +5–12h), WIP inflation from premature tickets, compliance exposure around the lock, rework drifting toward 19.5%, and dashboards misled by back-dated events. Expand when the pilot demonstrates 70% fidelity on eligible cases, a significant time-to-ready gain that survives exclusion of back-entered events, and p90/rework within stop thresholds with legal SLAs intact. Modify if T2 matches T1's benefit — adopt the cheaper sequential-trigger design org-wide. Pause or abandon on sustained p90 deterioration, rework above the stop-rule, weekly lock-conflict rates exceeding 3%, or adverse audit findings, reopening only after IT and logging remediation. In short: transport the operating discipline and the eligibility logic; earn the architecture.

## 10. Assumption register

1. **Statutory gate blocks the *start* of Document Check until originals arrive** — defines the hard eligibility boundary for all parallelization claims — obtain formal legal opinion and audit historical early starts for compliance objections — if false, eligible share expands sharply, but only after written compliance sign-off.
2. **Serially executed verification stages have additive durations, so removing a boundary saves  the shorter stage's residual time (~3.4h ceiling)** — bounds the transportable effect and prevents over-promising — reconstruct B's inter-stage elapsed gaps from the event log (performance annotation on DFG edges) — if hidden hand-off slack exceeds ~1h, upside is larger than modeled and S1 gains credibility.
3. **Verification service times are exogenous to WIP within pilot load ranges** — translating pool arithmetic into queue outcomes requires stable service laws — regress per-reviewer service time on concurrent caseload quartiles — if diseconomies exist, projected savings shrink and WIP caps must be tightened.
4. **Assessment and Legal stages respond smoothly to arrival shifts (no batch cliffs)** — sizes the mean-better/tail-worse (S3) risk — fit waiting time against hourly arrival rate historically — if cliffs exist, daily arrival caps become mandatory design elements.
5. **Dual-ownership IT support is deliverable within the pilot window, or T2 fully substitutes** — T1's fidelity and the whole parallel thesis depend on it — vendor certification plus sandbox integration test before Phase 1 — if false, restrict the trial to T2 and withdraw parallel-ownership claims.
6. **Case-level randomization is ignorable with negligible interference** — unbiased per-stratum effect estimates — covariate balance tests plus spillover regression on control-case waits during treated surges — if violated, fall back to stratified cluster-phased rollout with matched-period analysis.
7. **Timestamp integrity reaches 95% fresh server-side entries for verification events after safeguards** — every endpoint and the overlap KPI depend on it — quarterly audit against independent sources (registry receipts, courier scans) — if false, demote event-log endpoints to operational counters and remediate logging before continuing.
8. **Quality (rework/appeals) reacts slowly to moderate cycle-time compression** — legitimizes a fast-moving pilot without early harm — 30-day rework surveillance compared across arms — if false, narrow eligibility, add re-verification-of-changed-documents, and halt expansion pending root-cause review.
