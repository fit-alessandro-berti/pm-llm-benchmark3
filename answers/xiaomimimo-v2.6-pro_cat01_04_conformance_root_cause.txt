
The deterioration is produced by three measurement mechanisms stacked on one genuine change. (1) UI release 4.2 renamed the token of an unchanged step; the event stream — not the screen — is what alignments read, so 95% of cases lost their `Classify` sync move at once (raw 32% fitting). (2) The gateway inserted `Queue Routed`, an activity no model can match, giving every case a log move (5881 after removal). (3) From 15 June `Decision`/`Notify` were ordered by ingestion time, converting a subset of conformant cases into apparent reversals (8189 after source ordering). Because each mechanism is independent, their effects add up in alignment cost and read as one behavioural collapse. A second, real change began on 1 August: policy added `Supervisor Sign-off` to about a third of cases while the tree was never versioned, so the residual is now model obsolescence (6686 with an optional-sign-off candidate).

Stable appeal and approval rates vindicate no one. Outcomes are coarse, lagged and partly censored (30-day appeal window; "detection is incomplete"), so they have little power against a small bypass rate: skipping compliance checks on 3% of cases would move appeal rates by well under 0.1 pp. Equally, unchanged outcomes do not prove a data defect: reviewers could be noncompliant with damage that is delayed, invisible to appeals, or undetected. The measured collapse is instrumentation plus model obsolescence; the 55 cases lacking a recorded compliance check remain an open, unquantified exposure until source-level provenance resolves them.

```python
def parse_log_string(text):
    try:
        return pm4py.parse_event_log_string(text)           # 3) string -> event log
    except AttributeError:                                  # fallback for other builds
        rows = []
        for cid, line in enumerate(text.splitlines()):

def _stable_pct(key) -> int:
    return (sum(map(ord, str(key))) * 31) % 100            # process-stable pseudo hash


def _source_ranks(acts):
    """Source-sequence rank for each *recorded* position of one case.

    Stand-in for the source-system sequence number that the first conformance job did
    not use: the only documented ordering defect is the Decision/Notify pair (ETL change
    2026-06-15), and 11/70 audited screenshots put 'Decision' first.

    ranks = list(range(len(acts)))
    if "Decision" in acts and "Notify" in acts:
        i, j = acts.index("Decision"), acts.index("Notify")
        if j < i:                    # recorded reversal -> source order restores Decision first
            ranks[i], ranks[j] = ranks[j], ranks[i]
    return ranks


def expand(period, rows, base="2026-05-01"):
    text = "\n".join(DELIM.join(a.strip() for a in t.split(","))
                     for t, c in rows for _ in range(c))
    df = pm4py.convert_to_dataframe(parse_log_string(text))   # frequencies -> full log
    df[ACT] = df[ACT].astype(str).str.strip()
    df[CASE] = df[CASE].astype(str)
    df = df.sort_values([CASE], kind="mergesort").reset_index(drop=True)
    df[ING] = df.groupby(CASE, sort=False).cumcount()         # ingestion order (as extracted)

    ranks = {}
    for cid, g in df.groupby(CASE, sort=False):
        for idx, r in zip(g.index, _source_ranks(list(g[ACT]))):
            ranks[idx] = r
    df[SRC] = pd.Series(ranks).reindex(df.index)

    start = {cid: k for k, cid in enumerate(pd.unique(df[CASE]))}
    df[TS] = pd.Timestamp(base) + pd.to_timedelta(
        df[CASE].map(start) * 60 + df[ING], unit="m")         # synthetic ingestion clock
    df[HIGH] = df[CASE].map(lambda c: _stable_pct(f"{period}:{c}") < 20)   # ~20% > EUR 50k
    df[RES] = df[CASE].map(lambda c: f"Rev-{_stable_pct(str(c)) % 12:02d}")
    df["period"] = period
    df["trace_str"] = df.groupby(CASE, sort=False)[ACT].transform(lambda s: " > ".join(s))
    return df

def normalize(df, map_labels=True, drop_technical=True, order="src"):
    """Transparent, reversible preprocessing. `order` in {"src", "ing"}."""
    out = df.copy()
    if map_labels:
        out[ACT] = out[ACT].replace(LABEL_MAP)               # 6a) 'Risk Screen' -> 'Classify'
    if drop_technical:
        out = out[~out[ACT].isin(TECHNICAL)]                 # 6b) drop 'Queue Routed'
    key = SRC if order == "src" else ING                     # 6c) source-sequence ordering
    out = out.sort_values([CASE, key], kind="mergesort")
    # re-stamp timestamps so convert_to_event_log keeps this order within each case
    out[TS] = out.groupby(CASE)[TS].transform("min") + pd.to_timedelta(
        out.groupby(CASE).cumcount(), unit="m")
    return out.reset_index(drop=True)


def stratified_subsample(df, n_target):
    """Keep rare variants alive while shrinking the alignment workload."""
    total = df[CASE].nunique()
    if not n_target or n_target >= total:
        return df
    keep, frac = [], n_target / total
    for _, g in df.groupby("trace_str"):
        cases = list(pd.unique(g[CASE]))
        keep.extend(cases[:max(1, int(round(len(cases) * frac)))])
    return df[df[CASE].isin(keep)].copy()

def evaluate(df, net, im, fm, tag, with_precision=False):
    log = pm4py.convert_to_event_log(df)
    dfg_res = pm4py.discover_dfg(log)                        # 4) frequency DFG
    dfg, sa, ea = dfg_res[0], dfg_res[1], (dfg_res[2] if len(dfg_res) > 2 else {})
    diag = pm4py.conformance_diagnostics_alignments(log, net, im, fm)   # 5) diagnostics
    fit = pm4py.fitness_alignments(log, net, im, fm)                    # 5) alignment fitness
    prec = pm4py.precision_alignments(log, net, im, fm) if with_precision else float("nan")

    moves_log, moves_model = Counter(), Counter()
    costs = []
    for d in diag:
        costs.append(d["cost"])
        for lm, mm in d.get("alignment", []):
            if mm == ">>":
                moves_log[lm] += 1                            # move on log
            elif lm == ">>":
                if mm not in ("tau", ">>"):
                    moves_model[mm] += 1                      # visible move on model
    n = len(costs)
    return {
```

## 7. Provisional conclusion

**Primary explanation of the measured conformance collapse (confidence: high, ~90%).** The June drop is overwhelmingly an instrumentation artifact, not a behavioural one. Three stacked measurement defects explain essentially all of it: (i) UI 4.2 renamed the activity token of an unchanged step, so ~95% of cases lost their `Classify` synchronous move (32%  58% fitting on remapping alone); (ii) the gateway injected the technical event `Queue Routed`, which no model can match (58%  81% on removal); (iii) from 15 June `Decision`/`Notify` were ordered by warehouse-ingestion time, manufacturing apparent reversals (81%  89% on source-sequence ordering). That staged, monotone recovery under measurement-only repairs is the strongest single argument. The August window adds a distinct cause: the 2026-08-01 policy created `Supervisor Sign-off` in 210/620 cases while the normative tree was never versioned — model obsolescence, which a candidate model recovers (66%  86%) with no change to the data.

**Could a real compliance problem remain? (confidence in "material, widespread noncompliance": low, ~20–30%; confidence that *some* unexplained exposure exists: moderate, ~50–60%).** The 55 enhanced-review cases without a recorded `Compliance Check` and the 55 `Manual Override` cases are unexplained. Missing events and true bypasses produce identical traces, and no audit has yet separated them. Unchanged appeal and approval rates cannot decide this: the metrics are coarse, lagged, right-censored at 30 days, and compliance itself reports incomplete detection.

**Immediate actions.** *IT:* restore source-system sequence numbers and source timestamps in the ETL, fix the missing 6% `org:resource`, publish an activity-name/event-semantic contract, and reconcile gateway vs warehouse event counts per case. *Process owners:* re-issue a versioned normative model encoding `Supervisor Sign-off` conditioned on claim value (and decide the status of `Manual Override`), with fitness **and** precision validation. *Compliance:* run a double-blind source-journal audit of the 55 suspect enhanced-review cases and the overrides, and quantify incident-detection sensitivity.

**What must not be claimed yet:** that employees are or are not noncompliant; that `Queue Routed` or `Manual Override` are technical artifacts; that the 2026-08-12 patch was cosmetic; that improved fitness after adding optional sign-off shows the process is compliant; that stable appeal rates prove the data were wrong.

## 8. Model-governance recommendation

1. **Model versioning with change triggers.** Every normative model carries an owner, a version, a validity interval and a change ticket; any policy release (e.g. the EUR 50,000 sign-off rule) blocks deployment until a matching model version is published. Conformance results are always reported *against a dated model version*, never against "the model".
2. **Event-semantic contracts.** The activity alphabet is a governed contract between UI, event gateway and warehouse: renaming a screen or an event key is a breaking change requiring a mapping table (old key  new key  semantic definition) and an automatic conformance regression run. Labels are identifiers, and identifiers are versioned.
3. **Technical-event policy.** Every event type is classified at design time as *business*, *technical* or *compensating* and stored in a registry; technical events are tagged in the log and excluded by explicit, documented filters — never by ad-hoc deletions. Any event whose classification is disputed (`Queue Routed`, `Manual Override`) is treated as business until proven otherwise.
4. **Timestamp provenance.** Logs retain source-system occurrence time, source sequence number, and ingestion time as separate columns; conformance jobs must use source order, with ingestion order only as a tie-break. Ordering defects are detected by a standing monitor on symmetric DFG pairs (AB and BA) for mandatory sequences.
5. **Data-aware constraints.** Obligations conditioned on case attributes (sign-off above EUR 50,000) are specified declaratively alongside the control-flow model and checked separately; attribute availability, completeness and omission from reports are logged. Control-flow-only fitness must never be reported as policy conformance.
6. **Post-release validation.** Every UI, gateway, ETL and policy release triggers a validation pack within one week: label/DFG diff vs baseline, variant-distribution test, alignment with move decomposition, fitness **and** precision on a hold-out window, stratified results by key attributes, and a small provenance audit. Conformance scores are published with their preprocessing recipe so that "raw" and "normalized" results are never compared across pipelines.
