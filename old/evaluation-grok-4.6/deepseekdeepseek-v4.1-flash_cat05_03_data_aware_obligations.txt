**7.4**

The final write-up is structured correctly, reconstructs event-time state rather than final-case state, and gets the determinate cases right. That is the core of the task, and it is done well. It is not nearly flawless.

**What is solid.** TX-301, TX-303, TX-304, TX-306, TX-307, TX-308, TX-309, and TX-311 are classified from the right snapshots: blanks are non-updates, `event_index` orders TX-311, a decrease does not kill TX-308’s review, the 22.9% rise after TX-309’s Enhanced_Review does, DE turns R1 off, and a Standard_Review / standard-packet approval does not satisfy R2. TX-305 is correctly left INDETERMINATE because settlement is not an immutable release payload. EX-77 vs EX-88 is distinguished on evidence time, not on the late insert alone. Sections 6–7 hit the required failure modes and logging fixes. The pandas reconstruction (StringIO, `format_dataframe`, intra-case ffill, release snapshot, review/screen/list/material-change tracking, coarse R1–R4 flags) matches the spec and does not bake a classification lookup table.

**Formalization is incomplete, not just informal.** R1–R3 are written as two-valued predicates on `StateAt(...)`. Missing amount/jurisdiction therefore silently fail the trigger (`None >= 100000` is false), and R6 is a side remark instead of a three-valued composition. That is exactly the failure mode the policy forbids. R3’s `let s = latest Sanctions_Screen` is undefined if no screen exists. `ValidReview` treats “material data change” as R4’s >20% amount increase only; R1’s wording is broader (jurisdiction / customer / risk). The data do not punish that collapse, but the rule table never justifies it.

**Code undercuts the evidential design.** EX-88 is hardcoded `evidence_strength = "INSUFFICIENT"`, so the exemption is auto-failed rather than `REVIEW_REQUIRED`. The prompt allowed machine flags to stop where human evidence judgment starts; this encodes the judgment. `unknown_amount_increase` is computed and then dropped from diagnostics. There is no real DECLARE model, only a presence-before-release check — optional, but it does not show the gap as sharply as a DECLARE encoding would.

**TX-310 is over-decided.** Certificate-after-release plus a requester-witness is enough to *refuse* the exemption; it is not enough to make NONCOMPLIANT the unique label when the prompt says contradictory evidence has no canonical answer. Medium confidence and a Section 4 fork do not fully fix giving it the same hard label as TX-301/TX-304.

**Presentation and table hygiene.** Amount paths are written as `80k125k`, `118k145k`, etc., so the findings table is harder to audit than it should be. TX-305’s confidence cell (“High that indeterminate”) is a different quantity from every other confidence cell. Severity is undefined and used inconsistently (TX-305 “Medium” for a possibly EUR 150k foreign release).

Net: strong case reasoning and usable checking code, with real gaps in missing-data formalization, exemption-evidence handling, and a few clarity defects. That is clearly above a middling answer and clearly below a near-flawless one.
