Asha’s leave ends 14 Aug; 15 Aug is an ordinary weekend with no absence record. The matrix correctly calls the condition unverified, then §3 still awards a valid substitution. The honest primary label is `INDETERMINATE`. Calling it valid treats an unsatisfied mandatory conjunct as a footnote.

**CHG-505 as primary `UNAUTHORIZED` is defensible but compressed.** Farid’s approval is a clean RR4 substitution (D-IC-03 in force, in scope, registered before use). The failures sit on the retrospective review: D-QM-01 is production-equipment only, the review is after two business days (Tue 11 → due Thu 13; Fri 14 is late), and the actor is on certified sick leave. Bundling the whole case as unauthorized is acceptable only because RR4 is an exception that requires the review. The secondary “valid substitution” should have been attached more clearly to the *approval step*, not left as a case-level hedge.

**CHG-501 is close to right, slightly overconfident.** The signed PDF (9 Aug 18:00) can support the 11 Aug approval; a 12 Aug migration row cannot. `VALID_SUBSTITUTION` is fair. “MediumHigh” overstates it: the SoR did not contain the delegation at event time, and PDF authenticity is untested. Smaller issues: CHG-508’s secondary `DATA_OR_IDENTITY_PROBLEM` muddles a real RR1 breach that aliasing merely hid. ## Rule interpretation

§2 is the strongest part. RR1–RR3 are formalized as identity/interval/scope/absence/no-subdelegation checks at event time. Later DB rows are correctly refused as proof of earlier authority. Leave is correctly treated as contested identity, not automatic incapacitation. RR6 is respected throughout: repeated pairs are not proof.

Business-day counting is internally consistent (exclude the start date, skip weekends, no holidays). The CHG-505 lateness call follows that rule. The only gap is that RR4’s clock start (implement vs approve vs emergency flag) is assumed rather than justified.

## PM4Py / pandas (material)

The skeleton matches the spec: `StringIO` rebuild, `format_dataframe`, alias collapse before SoD, two `filter_four_eyes_principle` calls, interval table, handover and working-together networks, optional `filter_activity_done_different_resources`, no auto-collusion bit. Service-account handling via `SVC_ATTRIBUTION` with low-confidence CHG-503 left unresolved is the right design.

The four-eyes usage is still wrong. `pm4py.filter_four_eyes_principle` **keeps cases that satisfy** the principle (different resources). Labeling that output “candidate violations” inverts RR1/RR2: CHG-502, CHG-508, and CHG-510 would drop out of the printed “violations,” and conforming cases would be printed instead. There is no `positive=False` and no complement. For a section whose job is executable checks, that is a serious defect.

Other code gaps: `evaluate_authority` ignores the emergency flag and the principal-absence predicate, so it cannot implement RR3/RR4 as written. D-IC-04 is stored with `subdelegation_ok=True` and only rescued by a side-channel `voided_by`. `filter_activity_done_different_resources` is applied to a one-Approve-per-case slice, so it cannot show anything useful. `emergency` stays a string from CSV and is unused.
