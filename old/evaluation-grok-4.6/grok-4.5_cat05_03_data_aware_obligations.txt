## Subtle reasoning errors, not just style

**TX-305 alternative is too optimistic.** If a later payload fixed the release amount at ≥100000, the answer says the case “could flip to COMPLIANT” because an ER exists and no post-ER increase is known. R4 says the opposite: an increase from an *unknown* baseline is not safely classifiable. Amount at ER is unknown. Known release amount plus unknown review amount is still INDETERMINATE, not COMPLIANT. The author almost sees this and then gives the wrong counterfactual anyway.

**Material-change inconsistency is operational, not verbal.** If jurisdiction or risk changes after ER, R1’s wording requires a new ER when the release snapshot still triggers R1. The checker never tests that. No case fully punishes the gap (TX-311 turns R1 *off*), but the implementation does not match the policy the author claims to have formalized.

**TX-310 handling in code vs. prose.** The write-up treats EX-88 as an evidential judgment. The code sets `EXEMPTION_REVIEW_REQUIRED` and then still emits NONCOMPLIANT. The prompt explicitly allowed `REVIEW_REQUIRED` for exactly this situation. The narrative and the program disagree about how uncertain the exemption is.

Minor table rot: `08:20125000`, `100000100k`. Small, but this is the findings table a judge is told to read.

## The code is useful and not a lookup table — it is also not clean enough

It does the required mechanical things: `StringIO`, timestamp parse, `event_index` retained, `format_dataframe` when present, per-case ffill only, release snapshot, exemption join, unknown flags, coarse R1–R4, a trace-order demo with an explicit caveat. It is still not a high-quality artifact:

- `er_invalid` is assigned three different ways in succession. The surviving rule happens to be the right one for these rows, not because the function is clear.

- The DECLARE demonstration is `list.index`. Acceptable as optional, but it does not show that the author can express even a coarse data-aware check in PM4Py.

The code would likely run and would likely label these eleven cases in a way that matches the table. That is necessary. It is not sufficient for a high score on “usefulness.”

The checker implements a weaker policy than the memo describes, and it is padded with dead branches. On a rubric that scores formalization and code as first-class criteria, and under an instruction to treat even minor flaws as expensive, this is a strong but clearly defective answer.
