## Material flaws

**1. “Validated preserved” is unearned.**  
Section 4 marks almost every POWL→Petri and BPMN-round-trip cell `validated preserved` even though no converter was run, no witness suite was executed, and the evidence column is still a *plan* (“Validate by…”). The prompt is explicit that returning an object does not prove fidelity. Using `validated preserved` for a paper design is the central methodological error this task is built to catch. Those cells should have been `expected preserved` or `not tested`.

**2. Petri→Tree is pre-judged as `conversion failed` for every invariant.**  
That is an observation, not a prediction. PM4Py’s net→tree path often *succeeds* by approximation (e.g. inductive-style block structuring) rather than raising. The interesting failure mode for this source is success-with-INV-05-loss (optional legal nested before/after the loop), not an exception. The code would handle success; the audit table would then be false.

**3. Category error on INV-02 and INV-05.**  
Those invariants are *language* facts: both Assess/Prepare orders exist; Legal Review may appear before, inside, or after the verification body. Linear traces can decide that. Marking Petri→BPMN as `ambiguous` conflates (a) checkable interleaving with (b) true concurrency and diagram layout. Ambiguity belongs on visualization and on concurrency-vs-interleaving, not on the invariants as written.

**4. Missing source invariant.**  
There is no edge `prepare_evidence → optional_legal`. After Assess Risk, Legal Review may run *concurrently with Prepare Evidence*, not only with the loop. INV-05 only covers legal vs verification. A converter that inserts “Prepare Evidence before Legal Review” would violate the POWL order and would not be caught by the table or by `w_legal_interleaved`.

**5. Negative witnesses are only tested as complete, accepting traces.**  
`accepts_witness` asks whether a full sequence ending in Archive Change is in the set of traces that hit `fm`. If Release is enabled before verification but the run then deadlocks (never reaches `fm`), the negative test stays green while INV-09 is already broken. Forbidden *prefixes* need enabling/firing checks, not only exact completed-trace membership.

**6. Checker gaps that the prompt required care about.**  
Primary `convert_to_petri_net` / `convert_to_bpmn` unpack `im`/`fm` and pass them on with no null check, despite the explicit instruction. Baseline `net_from_powl` is never run through the witness suite—only round-trips are. Tau-hiding follows `label is None` as specified, but the `else: lab is None` branch is dead. Footprints are compared by `repr`, which is not a defensible footprint audit. `play_out(..., variant="stochastic")` is speculative and silently ignored.

**7. Canonical-storage advice reintroduces dual-source drift.**  
Choosing the accepting net + `(im, fm)` for storage and BPMN for stakeholders is reasonable, and keeping POWL as provenance is fine. Then the text allows future edits in “Petri net *or* upstream POWL.” That is two writeable sources. If they diverge, there is no stated winner. The right rule is: one editable authority (POWL *or* the net), regenerate everything else, never edit BPMN back.

## Smaller issues (still charged)

- INV-07’s negative set omits `Correct Defect` between Configure and Inspect; LOOP forbids that as surely as “Correct then Release.”
- INV-12’s “observable after hiding tau? partially” is muddy: the visible language is observable; exact marking equality is extra-linguistic. Mixing them in one row blurs the table’s own contract.
