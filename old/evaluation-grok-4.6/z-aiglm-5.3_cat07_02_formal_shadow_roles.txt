## Material problems

**1. “Exception path” for human A2 is inverted.** Nora has 610 validations; humans have ~1,641. Fragment 2 (Nora register → human validate → technical path) is a standard path, not an exception. Humans are the primary validators. Calling 1,640 human A2 events an “exception path” is a structural misread of the automation boundary.

**2. `cluster_log` is misused.** That function clusters *cases/variants*, not resources. Printing resources per case-cluster and expecting “Chen+Dina collapse, temps merge into front office, Erik/Hana become noise” confuses trace clustering with activity-profile role mining. That is a real PM4Py conceptual error in a section whose job is to show correct method.

**3. Duration analysis uses the wrong quantity.** The 38→74 minute figure is activity-level pricing-exception duration. The code proxies it with `case:service-time` after `insert_case_service_waiting_time`. Case elapsed/touch time is not the same metric, and the log is not shown to have start timestamps. The comment admitting `get_service_time` would be better does not fix the analysis that is actually run.

**4. Substitution effects are over-attributed.** Process-wide median duration doubling is treated as Giorgio’s “half throughput.” The 13/21 week-5 rechecks become “Mateo’s 62% recheck rate” in section 6. Giorgio’s remaining ~41 A7 events are called “genuinely occasional”; that is still a substantial secondary load (~5/week), which underplays interpretation B (de facto co-holder) even though section 4 lists it.
