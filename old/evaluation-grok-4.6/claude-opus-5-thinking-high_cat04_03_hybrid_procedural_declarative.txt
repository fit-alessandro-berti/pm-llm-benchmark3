## Material errors

**1. The reject branch and `directly_follows` contradict each other.**  
`REJB := ∧(ESC, Reject Vendor)` then `Close Onboarding` allows `Reject Vendor` to be interleaved with `Sanctions Escalation` / `Obtain Legal Opinion`. Legal traces include `Reject Vendor → Obtain Legal Opinion → Close Onboarding`. The skeleton nevertheless has `directly_follows: (Reject Vendor, Close Onboarding)`, and §5.2 asserts this is “consistent with the tree, where nothing may occur between them.” That sentence is false. This is exactly the kind of cross-layer disagreement the author is careful to disclose elsewhere and then misses on their own model.

**2. T8’s resource/data cell is inconsistent with §7.**  
`check_outcome_consistency` is defined to `fail` when both terminal outcomes occur, and §7 explicitly says T8 fails that check. The matrix marks the same layer `pass` and explains only that R9 holds. Required cell values were available (`fail`). This is a grading-critical slip: the matrix is the executable claim of the paper.

**3. R10 vs R11 is not a “genuine inconsistency.”**  
“Any later `Release First Payment`” is naturally “any payment after the bank change,” which is compatible with a single first payment (`Activate → Change Bank Details → Suspend → Verify Bank Account → Release First Payment`). The author’s own `check_post_activation_bank_change` implements that reading. Calling A12 a textual contradiction, then writing code that does not need the contradiction, is sloppy semantics.

**4. A9 is violated by the tree and not disclosed.**  
A9 says an opinion need not be caused by escalation, and DECLARE/skeleton correctly omit the converse. The tree only places `Obtain Legal Opinion` inside `→(Sanctions Escalation, Obtain Legal Opinion)`. An unsolicited opinion is procedurally impossible. That is a real over-constraint; it is not listed with the other approximations.

**5. R10 is already global in this tree.**  
XOR plus one `Activate Vendor` / `Release First Payment` per accept branch already yields at-most-once in the language. Claiming the tree “bounds occurrences per branch, not globally” and therefore that `activ_freq` is the authoritative R10 layer is technically wrong for this model.

True B is a data-conditioned exception, which an activity-only tree can only over-approximate. The code comment “Resolution B / C shape” admits the mash-up; §1 still sells the variant as B.

T8’s DECLARE fail is over-determined by R1, so the practical damage is limited, but the softness is documentation-only.
