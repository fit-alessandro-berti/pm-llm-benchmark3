**Classification and control-objective errors**

CHG-509 as primary **VALID_SUBSTITUTION** is too generous. D-QM-02 *requires* principal absence. Asha’s leave ends 14 Aug; 15 Aug is only a weekend. Weekend ≠ evidenced formal unavailability for a QM. The answer itself calls absence “plausible but not directly evidenced,” then still promotes substitution to the primary label. The better primary label is **INDETERMINATE** (or **UNAUTHORIZED** if the absence condition is enforced strictly). Secondary **SUSPICIOUS_PATTERN** does not repair the missing condition.

CHG-504 as primary **AUTHORIZED** is defensible on standing QM role, but identity is not settled: overlapping VPN plus self-report, with security unable to exclude credential sharing. Given the same identity-ambiguity rule applied well on CHG-506, primary **INDETERMINATE** with a standing-role caveat would have been more consistent. The secondary identity label and medium confidence only partly offset this.

CHG-501 as **VALID_SUBSTITUTION** is a fair reading of the signed PDF, but the QMS record is created *after* the approval. Treating this as substitution rather than **INDETERMINATE** depends entirely on trusting an off-system artifact. That is argued, not proven; confidence is appropriately medium, but the primary label still overstates what the system of record can support.

Severity is internally inconsistent: CHG-502 (LOW, RR1) is Medium while CHG-508 (LOW, RR1 after aliasing) is Low.

**PM4Py / pandas check quality**

The script hits the required *shape*: StringIO, `format_dataframe`, alias map, two four-eyes calls, interval tables, handover and working-together discovery, optional `filter_activity_done_different_resources`, and no automatic collusion verdict. That is not the same as a correct check.

The serious defect is that aliases are normalized onto a *side* column `human_resource`, while `org:resource` still holds `b.koch` vs `u_bk`. High-level `pm4py.filter_four_eyes_principle` typically keys off `org:resource` and often does not take `resource_key`. If that keyword is rejected, the `except` path sets passing-case sets to empty and reports **every** case as a four-eyes failure. If the call succeeds but ignores `human_resource`, CHG-508 **passes** four-eyes because the raw IDs differ. Either way, the mandated PM4Py SoD check does not reliably implement alias-normalized segregation. The custom pandas flags do; the required PM4Py path does not.

Further code flaws:

- Emergency HIGH approvals are coded as IC-only (`required_role = "IC" if emergency else "QM"`). RR4 *allows* IC substitution; it does not strip standing QM. The bug is latent on this log but is a wrong formalization.
- Retrospective coverage is gated by `"review" in manual_note`, a string hack, not a real activity/scope interval.
- `scope_matches(..., "cooling_system_ci44")` treats any `cooling_system` as in-scope and defers CI-44 identity to a note. That is not interval logic; it is a silent over-match.
- Networks are not executed. Section 4 *guesses* edges (“Clara Ben, Clara Diego…”) with dropped arrows. Indicator interpretation without output is incomplete.
- Broad `try/except` around discovery/filters can hide total failure and still print “indicator” tables.

Service-account representation in code *is* clearly documented (strong map vs `UNATTRIBUTED_SERVICE_ACCOUNT`), and residual manual judgments are listed. That part meets the spec.

**Other nits**

The actor–role matrix and rule section are long but usable; a few standing-role rows strain the “delegated role / principal-absence” columns. Network prose is qualitative rather than tied to discovered weights. Control recommendations and the executive ranking (CHG-510; 503/506 identity; D-QM-01 plus emergency review) follow from the case work and are appropriately uncertain.

**Net**

This is a high-quality investigative write-up with the right headings and mostly right case law, undermined by an optimistic CHG-509 (and to a lesser extent CHG-504/501), plus PM4Py checks that do not robustly apply alias-normalized four-eyes on the actual resource field. Under a strict bar, that is clearly below excellent.
