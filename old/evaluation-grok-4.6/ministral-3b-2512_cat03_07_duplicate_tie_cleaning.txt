## Section 1 — decision tree is not a tree and misclassifies the data

The root example is self-contradictory: “exact match → drop (e.g., e03/e04 if `payload_hash` differs).” An exact technical duplicate is same payload / same source key / same technical record. Fact 1 says e03/e04 are the *same physical scan* with *different* payloads because WMS enriched location. That is the multi-system observation case, not an exact duplicate.

The next branch is also inverted: “same payload → quarantine (e03/e04).” Those hashes are `h-pick-i1` vs `h-pick-i1-alt`. The tree then auto-merges “summary vs detail,” which the prompt treats as an *open* abstraction question, not a merge rule.

Worst factual error: “No shared objects → unresolved (e.g., e13/e14).” e13 and e14 share **O1 and V1**. That is exactly why `have_common_object=True` is unsafe. The tree proves the author did not understand the central trap.

Terminal actions are not stably mapped to the six required categories. Harmonization collisions, concurrent same-label/different-object events, and unresolved candidates are not cleanly separated.
