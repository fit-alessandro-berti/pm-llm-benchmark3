## Architecture is a sketch; the POWL fails the spec

Section 6 names the right layers in the abstract and then gives a garbled rule soup (`Rejected_Lead NOT(Register_Supplier Quality_Review)`). It never pins EUR 20,000, two-business-day quality, daily monitoring, or versioned effective windows to a check language.

Section 7 is the largest technical failure.

1. **`Request_More_Info` is not in `M_REVISED`.** The loop object is dead code.
2. **`info_loop.order.add_edge(request_info, request_info)` is not a POWL loop.** A strict partial order is irreflexive. The LOOP operator is `OperatorPOWL(Operator.LOOP, [body, redo])`. Importing `SilentTransition` and not using it is not an approximation; it is an unused import.
3. **Pilot branch is `Auto_Approve` only** — no `Activate_Supplier`, no post-activation `Quality_Review`.
4. **Emergency branch is `Provisional_Activate` only** — no mandatory prior `Sanctions_Check` distinct from the forced full `checks` block, no retrospective quality/manual approval, no spend/monitoring hooks.
5. **`checks` (sanctions **and** quality) precedes every route.** That makes the required emergency/provisional path **inexpressible**: quality cannot follow activation.
6. The same `reject` node is reused under three XORs. Route choice is `XOR(XOR(standard, reject), XOR(pilot, reject), XOR(emergency, reject))`, which is not a coherent decision semantics.
7. Observed emergency events are labeled `Activate_Supplier`, not `Provisional_Activate`. Unmapped relabeling means the new model still will not fit SUP-704 even when authorized.
8. Required **normalized policy-overlay table** is missing. The pandas fragments are not executable as written (`pd` never imported; series-wide `==` is not a case-level SoD check).

So the one artifact that had to demonstrate model competence fails concurrency-by-route, LOOP, rejection, and notification-as-the-only-solid sequencing constraint it actually implements.
