## What is actually strong

The core interval construction is largely correct: resolution before clock correction, `true = recorded - offset` with offset in `[a, b]`, Minkowski duration bounds, CEST/EDT/BST conversions, and two-sided temporal-profile bands. Several hard cases are handled well:

- **T-405 DST pruning** is the best part of the answer. Ingestion order really does force Alert into the first pass (UTC+2) and Investigation/Containment into the second (UTC+1). The surviving windows `[00:49, 00:52]`, `[01:04, 01:07]`, `[01:41, 01:44]` UTC are right, and the answer correctly refuses to treat them as exact.
- **T-402 S1** is a genuine `CERTAIN_VIOLATION` (min 958.5 s > 900 s). **T-408 S2/S3** are genuine hard violations and stay violations under +5 minutes.
- Mobile delay is split into occurrence-shift vs record-latency, and midpoints are quarantined as a lossy comparator.
- Sensitivity is mostly computed on intervals, not collapsed point estimates. Several razor edges are real: T-401 S1 vs +2 min, T-402 Alert→Inv vs ζ=2 (958.5 vs 960), T-403 Alert→Inv vs ζ=3 (1141.5 vs 1140), T-408 Inv→Cont vs ζ=2 (3297–3303 vs 3300).

That is a competent analysis. It is not enough for a high score.

## Required code section is not what was asked

Section 5 is the clearest miss. The prompt required executable normalization **from the recorded values** using pandas and stdlib time zones, and DST as **alternative intervals**. What was delivered:

1. `df_raw` is built and then ignored.
2. `ZoneInfo` is imported and never used.
3. `compute_normalized_intervals()` is a handwritten lookup table of already-computed UTC bounds. That is not interval normalization.
4. DST fold unions are not represented in code; only the prose-pruned singles are stored.
5. The code classifies temporal-profile pairs only. It does not implement S1–S3.
6. It never emits `INDETERMINATE`. T-407 and T-409 are forced into proxy intervals, so the program’s verdicts contradict Section 3.

The PM4Py midpoint half is closer to the spec (`format_dataframe`, ζ = 1/2/3, explicit “lossy” label, no claim that PM4Py solves uncertainty). Diagnostic column names are still assumed. Because items 2 and 3 of the required code list are simply not implemented, Section 5 cannot be counted as done.

## Logical inconsistencies

**Missing `Alert_Received` is treated two ways at once.** For T-407, S1 is `INDETERMINATE` because send ≠ receive. The same inferred receipt window is then used to call Alert→Containment a `CERTAIN_PASS`, including the sentence “even with full 20 m latency.” If the receipt event is not testable, that pair is not testable either. If latency bounds make it testable, S1 should be `POSSIBLE_VIOLATION` under the proxy, not indeterminate. Section 4 then scores T-407/T-409 S1 as possible/certain with asterisks, which quietly abandons the Section 3 primary label.

**The “full 20 m” duration is the wrong interval.** Uncapped receipt `[13:59:58.5, 14:20:01.5]` against containment gives about `[2097, 3303]` s, not `[2277, 3303]` s. Both still sit inside `[1980, 3420]`, so the class happens to survive, but the table and the rationale do not match.

**T-404 S2 “3-second breach” is an interval-dependence artifact.** Start is `Investigation_Complete − [18, 25] min`, and containment is another HUB timestamp. Writing `D = t_cont − t_start` with independent HUB envelopes double-counts the completion-clock error. The prompt asked for retained uncertainty, not for wrapping a derived interval as if it were an independent measurement. A same-clock reading is `D ≈ 20 min + duration`, i.e. `[2280, 2700]` s plus sub-second display error — which is a pass or a much thinner overlap, not a clean 2703 s possible violation. The answer never discusses shared clocks on one system, which also matters for T-405 (same LEGACY-BER box, minutes apart). Independent envelopes are conservative; presenting the 3 s S2 miss as a real operational finding is overstated.

**Negative durations.** T-407/T-409 S1 include −3 s and −481.5 s from independent Minkowski bounds after a causal cap was already claimed. If receipt cannot follow investigation, those lower bounds should be truncated at 0 and the joint constraint stated. Leaving negatives while calling the receipt interval “causally bounded” is internally sloppy.

## Prose that does not match the math

OPS-BER algebra is wrong even though the table is right:

`t_max = hh:mm:60 − 2 h − (−90 s)` is **+2 min 30 s** from `hh:mm` UTC, not “+1 min 30 s”. The intervals actually used (`08:16:30`, width 270 s) follow the +2.5 min figure. A reader who trusts the formula gets a different window than Section 2.

Floor-to-minute is modeled as `[mm:00, mm:60]` rather than the specified `[mm:00, mm:59.999]`. That does not flip these verdicts, but it is not what the source metadata says.

## Smaller but real gaps

- Section 6 never says what additional evidence would lock **T-405** (fold bit / UTC offset on the wire). After pruning, the remaining S1/profile overlap is entirely resolution-plus-offset; that should have been listed.
- T-409 S2 is `CERTAIN_PASS` on a bound the same section calls too weak to test S1. That can be justified (the weak envelope still sits under 2700 s) but it needed one explicit sentence; instead it looks like a changing standard of proof.
- Same-system offset cancellation is never mentioned. For HUB–HUB pairs the ±1 s clock bound largely cancels and only the ±0.5 s display term remains. Classifications here mostly survive, but T-408 at ζ=2 is a 3-second straddle driven by that conservative stacking.
- Evidence-strength labels (“High” NTP on OPS-BER, “Medium-High” on T-405 after a purely logical fold argument) are asserted, not earned.
