## 1. Source-Semantics Baseline — incomplete and partly inverted

The table shape is correct. The contents are not.

- **INV-04’s negative witness is a positive witness.** `[..., Ass, skip, ...]` is allowed optional behavior. A negative witness would be Legal Review before Assess Risk, Legal Review required on every visible trace, or Legal Review enabled from Prepare Evidence without Assess Risk.
- **INV-02’s negative witness is abdicated** (`N/A (Concurrent)`). Absence of order is an invariant: a converter that imposes a fixed Assess→Prepare (or Prepare→Assess) sequence violates it. That is exactly the kind of witness this task needs.
- **The unordered Legal Review / verification pair is missing.** The source has no edge between `optional_legal` and `verification_loop`. That is one of the load-bearing facts of the model and is listed in the intended semantics. Omitting it collapses the audit.
- **Binary-loop scope is underspecified.** “At least one Configure/Inspect” is necessary but not sufficient. The LOOP is `do trial_body redo correct_defect`: Correct Defect is the redo child, it separates iterations, and it must not be treated as an optional prefix or as a free-choice sibling of Configure. That never appears as its own invariant.
- Witnesses are schematic (`[Register, ...]`) rather than actual visible traces, so they cannot later be used as oracles.

“Observable after hiding tau? Yes (as skip)” for INV-04 is also confused: after hiding `None` labels, skip is not observed as a skip; optionality is observed only as the presence or absence of Legal Review.

## 2. Pipelines — acceptable outline, overconfident failure analysis

The failure column is not. “None if net is workflow sound” for Pipeline A is false. ## 3. Conversion Code — would not execute as specified

This is the largest failure. The prompt already told the author how these APIs work and forbade invented converters and unchecked markings.

**`convert_to_petri_net` returns `(net, im, fm)`, not a net object with marking attributes.** The code does:

```python
net_from_powl = pm4py.convert_to_petri_net(source_powl)
im_from_powl = None
fm_from_powl = None
if hasattr(net_from_powl, 'initial_marking'):
    ...
```

A tuple has no `initial_marking`. Markings stay `None`, and `net_from_powl` is not a net. Every subsequent call (`convert_to_bpmn`, `convert_to_process_tree`, `check_is_workflow_net`, `save_vis_petri_net`) is then ill-typed. The “check markings if available” comment does not satisfy “creates `net_from_powl`, `im_from_powl`, and `fm_from_powl` using `pm4py.convert_to_petri_net(...)`.”

Further defects:

- `convert_to_bpmn(tree_from_net, im_from_powl, fm_from_powl)` passes Petri markings from another object into a tree conversion. The reminder is that BPMN conversion accepts a **process tree or a marked Petri net**, not a tree plus a foreign marking. The inline comments admit the author does not know which call is defined.
- BPMN→Petri is again not unpacked; `im_from_bpmn` / `fm_from_bpmn` are guessed with `hasattr`.
- Diagnostics are not run on every accepting net (no tree→net net, no second BPMN).
- `save_vis_bpmn(..., "pipeline_a.bpmn")` and `save_vis_process_tree(..., "tree_intermediate.xml")` are visualization dumps, not serializations; the extensions are wrong. `save_vis_powl` is missing. Filenames are not a clear artifact set.
- `check_soundness` is called with possibly null markings, against the prompt’s explicit warning.

A conversion object being returned is then treated as success. That is the exact failure mode the task forbids.

## 4. Preservation Audit — labels are inflated; required topics are thin

Allowed assessment terms are used, but **`validated preserved` is unjustified**. Nothing was executed. Per the task, a converter returning an object is not fidelity. Those cells should be `expected preserved` or `not tested`.

Other problems:

- Petri→Tree “lost” for concurrency vs. “conversion failed” for the Release join is inconsistent. If the tree conversion fails, the column is `conversion failed` for every invariant, not a mix of lost/approximated/expected.
- Silent optional behavior is declared `lost` on Petri→BPMN without evidence. A silent XOR often becomes an XOR gateway with an empty branch; that can be `approximated` or `ambiguous`, not a demonstrated loss.
- Activity-label uniqueness and the missing Legal–verification edge are not rows. The discussion of “true concurrency vs. interleaving” is slogan-level: Petri tokens vs. BPMN AND-gateways vs. trees. It never says that **visible-trace comparison can only see interleavings**, so concurrency of Legal Review with the trial loop is not proven by language equality.

## 5. Round-Trip Validation Code — not a validator

Required tools were: soundness, footprints, reachability graph, bounded visible exploration, positive/negative witnesses, playout where supported.

What was delivered:

- Variables are not in scope (`net_from_powl` is local to `run_conversion`).
- Footprints are computed and **never compared**.
- `convert_to_reachability_graph` is unused.
- Positive/negative witnesses are unused.
- Playout is unused.
- Exhaustiveness under the bound is not stated. With an unbounded LOOP and `max_visible=50`, the comparison is **not** exhaustive.

The explorer itself is incorrect:

- `net.input_places[t]` / `net.output_places[t]` are not PM4Py Petri APIs. Firing must go through net semantics (arcs/weights or `execute` / `weak_execute`). This is an invented conversion-adjacent API.
- `visited` on markings only **drops alternate traces** through the same marking (Assess∥Prepare reconvergence, skip vs. Legal). That is the opposite of an invariant audit.
- `len(history) > max_visible` counts silent firings, so it is not a visible-length / loop-iteration bound.
- Reaching `fm` `continue`s without recording whether extra enabled moves remain; that is a soundness question, not a language question.

The function would crash before producing a comparison, and if patched with the imaginary firing rule it would still under-approximate the language.

## 6. Visual-Semantics Review — directionally right, technically loose

The section correctly warns that layout and gateway glyphs can be misread. That is the one part of the quality bar that is partly met.

It is still sloppy. Petri→BPMN conversion typically yields XOR split/join with a back-edge, not BPMN activity loop markers. Silent routing nodes are not “omitted from display” by default; they often appear as unlabeled gateways or dummy tasks, which is a different misreading. ## 7. Rejection Criteria — meets the count, misses the hard cases

Six bullets exist. Unsoundness, release-before-verification, and Config-after-Inspect are legitimate.

Gaps relative to the prompt’s own examples:

- Loss of a **required interleaving** (Assess∥Prepare, or Legal overlapping verification) is not a criterion.
- Admission of **zero verification iterations** is not a criterion (binary LOOP do-part).
- Successful process-tree conversion that **sequentializes** a partial order is not a quarantine rule.
- Criterion 6 (“multiple distinct token patterns at end”) restates unsoundness rather than the required **exact final-marking equality on completed traces**.
- “Skip Legal removed” is not operational: after tau-hiding, skip has no visible name to look for.

## 8. Canonical Recommendation — strongest section, still overclaims evidence

POWL as authoritative, Petri/BPMN as derivatives, no process tree as store of record, edits only at POWL: that is the right recommendation.

“Each derivative must include soundness checks and footprint logs matching the source invariant set” overstates footprints. Footprints do not encode min-one LOOP, silent XOR vs. absent activity, or token join before Release. The validation packet needed is: unpacked markings, workflow-net + soundness, bounded visible traces with exact `fm`, witness traces, and an explicit statement of non-exhaustiveness.

## 9. Residual Uncertainty — generic, not about this conversion

Timing, data payloads, and “humans may misread BPMN” are true of almost any process model. They are not the residual of **this** pipeline.

What the validation still cannot establish even if every test passed:

1. Language equality for unbounded loop unrollings beyond the bound.
2. True concurrency (token independence) as opposed to recorded interleaving.
3. That BPMN gateways implement the same silent XOR / join as the net, rather than a visually similar routing graph.
4. Identity of tau transitions across round-trip (visible-trace equality can hide extra silent structure).

Under the task’s own bar — semantic invariants, real PM4Py calls, failure as a first-class outcome, and refusal to treat serialization as fidelity — it fails at the points the prompt marked as important: markings, defined converters, negative witnesses, bounded exploration, and honest `not tested` vs. `validated` labels. Conceptual sections 6 and 8 prevent a still lower score; they do not offset an unusable conversion path.
