**7.0**

## Verdict
Sections 1–6 and 8 are strong on honest target semantics, selection, leakage, and cohort accounting. The grade is held down by internal inconsistencies in the validation design, a train-split rule that contradicts the stated survival/propensity strategy, and a Section 9 skeleton that would not run cleanly and misuses several APIs. Under a hypercritical bar this is clearly not near-flawless.

### Section-by-section critique

**1. Target definition — strong, not perfect**  
Primary activation-conditional risk plus propensity decomposition is the right operational frame; alternatives A/B/C are well separated; rejected/withdrawn/open are not falsely labeled 0.  
Nits: \(Y(c)=1\{A=1\}\times 1\{T\le 90\}\) is then immediately replaced by a conditional estimand \(P(T\le 90\mid A=1)\) — the product score is a *decision artifact*, not the primary estimand, and that should be sharper. “Each case once per \(k\)” vs. survival-on-activated is slightly underspecified for how prefixes enter the hazard model (time-fixed covariates only? landmarking?). Still among the best parts of the answer.

**2. Cohort construction — strong**  
Full 48,000 flow, two clocks, maturity cutoffs, migration dedupe, linkage collapse — all good.  
Nits: “downstream re-entry collapsed” is stated but never operationalized later; stratum 2 lumps “not mature” with “permanently missing feed,” which Section 3 correctly separates — the flow table should already split those. Conservative boundary 13 Oct 2025 is arithmetically fine.

**3. Censoring / missing labels — strong**  
Taxonomy (admin censoring vs lag vs activation selection vs transfer vs permanent non-feed), primary discrete-time survival + IPW, and S1–S5 are appropriate; testable vs untestable ledger is excellent.  
Nit: primary analysis still needs a clearer stand on whether partner `feed_at_risk` cases are IPW-weighted, bounded, or both in the *headline* number — “primary + bounding sensitivity” is implied but not locked.

**4. Prefix extraction — strong**  
Event-count + elapsed-time, short cases, loops kept, rename map + DFG stability check — good.  
Nit: “null post-prefix columns on retained prefix rows” is correct and important; elapsed-time \(\Delta\) vs event-count population shift could use one sentence on which population the headline claim uses when they disagree.

**5. Process-aware features — strong**  
Control-flow, timing, as-of workload, rework, rolling cohort stats with backward-only windows — good discipline.  
Nit: “directly-follows edges scored against a training-period DFG” and conformance-on-prefix need an explicit rule that the reference model is frozen inside the training fold only (stated generally later, not here). Experience recompute is described, not specified.

**6. Leakage audit — strong**  
Required rows present; drop/repair decisions for `final_limit`, `decision_reason`, `collection_status`, future events, `documents_total`, `risk_score`, experience, label availability are correct; detector-for-`label_present` is a good audit idea.  
Nit: single-feature AUC > 0.80 quarantine is a heuristic, not a principle; OK as engineering check.

**7. Validation design — material flaws**  
Why random splits fail is excellent; metrics (IPCW C-index/AUC, IPCW-Brier, decile calibration, capacity-aware precision) match the target.  
**Serious issues:**
- Embargo is motivated as 125 days, but the fold table **violates it**. F2: train through 2024-12  test from 2025-04 (~90d gap). F3: train through 2025-03  test from 2025-07 (~92d gap). Only F1/F4 are roughly compatible. The worked example in code uses F3 dates and will trip the skeleton’s own `assert test_start - train_end >= embargo`.
- “Split on case start” is right; train filter in code (see §9) only keeps `label_mature`, which **discards censored activated exposure** the survival story depends on and **drops all non-activated cases** needed for the propensity stage. Design and validation mechanics disagree.
- F4 as “90-day evaluation” while mostly immature is acknowledged, but then mixing in a shortened 30-day horizon “as a different quantity” needed a cleaner protocol (pre-specified secondary endpoint, not a silent substitute).

**8. Limitations — strong**  
Can/cannot claim, association vs selection vs counterfactual, and deployment feedback (policy freeze, gaming, operational reallocation, transfer composition) are exactly what the business boundary needs. Minor: four bullets after promising three.

**9. PM4Py skeleton — weakest section; several concrete defects**

| Issue | Why it matters |
|---|---|
| `temporal_split(..., 2025-03-31, 2025-07-01, ...)` fails the 125d embargo assert | Example main path is inconsistent with §7 and will crash |
| `train = idx.index[(start  train_end) & label_mature]` | Contradicts survival (needs censored activated rows) and propensity (needs all applications) |
| `f["prefix_variant"] = pm4py.get_variants(pref).keys().__class__ and g[...].apply(...)` | Broken/nonsensical; `get_variants` result unused; not a real variant encoding |
| `extract_temporal_features_dataframe(pref)` then `.groupby(pref["case:concept:name"]).mean()` | API is already case-level in normal PM4Py usage; this join/groupby is wrong or fragile |

| Transfer linkage / collapse | In inclusion rules, absent from code |

The skeleton shows the right *intent* (format_dataframe, prefixes, temporal split disclaimer, DFG migration check, null post-decision cols, no `fillna(0)` on labels, parquet handoff) but is not “concrete enough to implement” without rework. Line count is in range.

### Summary judgment
This is a **good-to-very-good study design writeup** with an **unreliable implementation appendix** and a **self-inconsistent backtesting schedule**. At full strictness — where minor logical cracks and non-runnable skeleton code block high marks — **7.0/10**. Fix the embargo-aligned folds, align `temporal_split` with censored activated + full propensity populations, and repair prefix-variant/temporal-feature/experience code, and the same narrative would sit in the high 8s to low 9s.
