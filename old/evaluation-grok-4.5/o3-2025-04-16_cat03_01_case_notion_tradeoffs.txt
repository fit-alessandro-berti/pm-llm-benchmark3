### Critical flaws (score drivers)

**1. Convergence/divergence are inconsistent.**  
§1 defines convergence as several entities merged into one trace and divergence as one entity split across traces. The Order row then rates “Medium divergence” because O1 has two packs/deliveries *inside one order trace* — that is classic within-case repeated activity, not split traces. The Item row rates “High divergence” because items of one order land in different item traces — that is order fragmentation under an item case notion, not item-lifecycle divergence. Definitions and matrix ratings do not implement the same theory. For a question that asks you to reason about flattening semantics, that is a core defect.

**2. False claims about what Item flattening contains.**  
Invoice/payment events (e18–e22, e25–e26) relate to Order/Invoice/Payment only. They are **not** E2O-related to items, so they are not “copied without context” into item cases; they are absent unless an explicit propagation transform is applied. The matrix’s “preserved / lost / duplication” story for Item is therefore wrong on the financial slice. Stating item lifecycles as “6 events” is also off: e.g. I11 is essentially Add → Pack → Dispatch → Confirm (four directly related events).

**3. Invented Package distortion (required cross-order example).**  
Distortion 2 claims a Package/P4 variant “Pack Package (for O3) → Close Order (O4)”. Close Order events e28–e31 relate only to orders, not packages. Under the problem’s own rule (no silent O2O propagation), those events **do not enter** package traces. Presenting that path as a flattening artifact is a direct factual error on a required “cross-order package” example and undermines trust in the rest of §3.

**4. Factual error in the lead-object argument.**  
“Order appears in 25/31 events” is false: every listed event includes at least one Order in “Related objects” (31/31). “Only 4 events (e11–e14) omit some orders when packages are split” is vague and not a clean reading of the log. Supporting evidence should not miscount the snapshot.
